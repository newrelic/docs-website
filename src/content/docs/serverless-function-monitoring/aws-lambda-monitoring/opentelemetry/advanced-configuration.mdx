These environment variables aren't required to get telemetry flowing — see [Install and configure](/docs/serverless-function-monitoring/aws-lambda-monitoring/opentelemetry/install-configure) for the minimum setup. Use the variables on this page to tune sampling, attribute handling, and runtime-specific behavior once your function is already reporting data.

| Variable | Value | What it does |
|---|---|---|
| `OTEL_TRACES_SAMPLER` | `always_on` | Controls trace sampling. `always_on` is already the default and captures every invocation. |
| `OTEL_ATTRIBUTE_VALUE_LENGTH_LIMIT` | `4095` | Prevents truncation of large span attribute values. |
| `OTEL_EXPORTER_OTLP_TIMEOUT` | `5000` | Sets the export timeout in milliseconds. The default may be too long for Lambda. |
| `OTEL_RESOURCE_ATTRIBUTES` | `key=value,key=value` | Adds custom resource attributes. `service.name`, `faas.name`, `cloud.region`, and `cloud.account.id` are auto-injected, so you don't need to set them here. |
| `OTEL_DOTNET_AUTO_TRACES_ENABLED` | `true` | Explicitly enables trace auto-instrumentation. .NET only. |
| `OTEL_DOTNET_AUTO_LOGS_ENABLED` | `true` | Explicitly enables log auto-instrumentation. .NET only. |
| `OTEL_DOTNET_AUTO_LOGS_INCLUDE_FORMATTED_MESSAGE` | `true` | Includes the formatted message body in exported logs. .NET only. |
| `OTEL_PYTHON_LOGGING_AUTO_INSTRUMENTATION_ENABLED` | `true` | Exports application `logging` calls, not just auto-injected trace correlation text. Required for Python (ADOT) — without it, `OTEL_LOGS_EXPORTER=otlp` alone isn't enough. |
