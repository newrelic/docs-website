OpenTelemetry (OTel) monitoring for AWS Lambda sends traces, metrics, and logs from your function to New Relic through an OTel Lambda layer, with no application code changes required. Each invocation appears as an entity you can trace, correlate with the rest of your application, and query alongside your other OpenTelemetry data. If you need custom spans or attributes beyond what auto-instrumentation captures, you can also instrument a function directly with the OpenTelemetry SDK.

## Capabilities [#capabilities]

- **Traces** — one span per invocation, with duration, status, cold-start information, and any child spans (for example, a `CONSUMER` span for SQS-triggered functions)
- **Metrics** — invocation count, duration, and error rate, groupable across functions by their auto-assigned ARN tag
- **Logs** — structured application logs, correlated to the trace
- **Entities** — an auto-synthesized OTel entity per function, linked to its underlying AWS Lambda infrastructure entity

## Choose your install path [#choose]

- **OTel Lambda layer (recommended)** — attach a layer and set environment variables, with no code changes. Works across runtimes.
- **Manual OpenTelemetry SDK instrumentation** — add the OTel SDK to your function's code. Use this when you need custom spans, attributes, or behavior beyond what the layer's auto-instrumentation provides. Guides exist for [Java](/docs/serverless-function-monitoring/aws-lambda-monitoring/opentelemetry/lambda-opentelemetry-java) and [.NET](/docs/serverless-function-monitoring/aws-lambda-monitoring/opentelemetry/lambda-opentelemetry-dotnet).
