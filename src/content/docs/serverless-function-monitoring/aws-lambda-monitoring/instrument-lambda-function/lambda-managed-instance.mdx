New Relic Lambda layers support **Lambda Managed Instance (LMI)** — AWS's managed compute model for Lambda functions backed by dedicated EC2 infrastructure. LMI functions are automatically detected and monitored in APM mode with no extra configuration.

## How it works

When you attach a New Relic Lambda layer to an LMI function, the layer auto-detects the LMI environment and configures itself as APM mode. You do not need to set `NEW_RELIC_APM_LAMBDA_MODE = true` — it is applied automatically.

The monitoring experience for LMI functions is the same as any other APM-mode Lambda function: you get the same entity in New Relic APM, the same Summary, Transactions, Distributed tracing, Errors, and Logs tabs, and the same data quality.

## Supported layer types

Both layer types are supported for LMI functions:

- **New Relic Lambda layers** (APM mode)
- **OpenTelemetry (ADOT) layers**

## Configuration

Attach the New Relic Lambda layer to your LMI function as you would for any Lambda function. Use the same environment variables you already use. No LMI-specific configuration is required.

<Callout variant="important">
  **Serverless mode is not supported for LMI.** Only APM mode is available. Even if `NEW_RELIC_APM_LAMBDA_MODE` is not set, LMI functions always run in APM mode.
</Callout>

## Lambda metrics tab differences

In the New Relic APM entity for a Lambda function, the **Lambda metrics** tab includes a **Costs** section. For standard Lambda functions, this section contains a **Billed duration** chart.

For LMI functions, the **Billed duration** chart is **not shown**. LMI billing is based on EC2 instance cost, management fee, and vCPU usage — not Lambda execution duration — so the metric is not applicable.

The rest of the Costs and Performance charts (Invocations, Memory, cold starts, time outs, iterator age, concurrent executions) are available as usual.
