Diagnose Kubernetes problems without leaving Autopilot. Autopilot K8s agent is a specialized subagent within [New Relic Autopilot](/docs/agentic-ai/autopilot/overview/). New Relic Autopilot is an AI-powered operations interface and core capability within New Relic autonomous operations. It analyzes telemetry and recommends remediation. Autopilot K8s Agent runs as a specialized subagent within [New Relic Autopilot](/docs/agentic-ai/autopilot/overview/). You interact with a single unified Autopilot, which automatically routes Kubernetes-related queries to Autopilot K8s Agent.

Instead of manually running `kubectl` commands and correlating metrics across multiple dashboards, the agent analyzes your cluster state, identifies root causes, and provides actionable remediation steps in real time.


<Callout variant="important">

Autopilot K8s Agent is only accessible through New Relic Autopilot. <DNT>Autopilot</DNT> is available to organizations on a [Pro or Enterprise](https://newrelic.com/pricing) edition with either:

* The [Advanced Compute](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#advance-compute-capacity-unit) add-on, or
* A Legacy Compute (CCU) plan.

## Key benefits [#benefits]

- **Root cause analysis for common Kubernetes failures**: `CrashLoopBackOff`, `OOMKilled`, pending and unschedulable pods, `ImagePullBackOff`, replica mismatches, high restart counts, node pressure, stuck rollouts, DNS, service and ingress problems, HPA behavior, and storage and PVC issues
- **Deep context**: Analyzes manifests, events, resource metrics, logs, and deployment history together
- **Beyond the cluster**: Correlates Kubernetes issues with your APM services and with cloud infrastructure on AWS and Azure, such as an impaired instance or an unhealthy load balancer target
- **Remediation guidance**: Provides specific fix steps, not just detection
- **One click from Kubernetes views**: <DNT>**Investigate**</DNT> buttons across the Kubernetes UI start an investigation with the context of what you're looking at
- **Works with OpenTelemetry**: Runs the same diagnosis on clusters monitored with the New Relic Kubernetes integration or with [OpenTelemetry for Kubernetes](/docs/kubernetes-pixie/k8s-otel/intro/)
- **No additional instrumentation required**: Works with the Kubernetes data you already send to New Relic

## How Autopilot K8s Agent works [#how]

You access it through Autopilot in the New Relic AI chat sidebar, or from an <DNT>**Investigate**</DNT> button in a Kubernetes view. You can describe an issue or enter a prompt (for example, `"Why are pods in namespace X crashing?"`) to trigger an autonomous investigation by the agent. The agent analyzes your cluster state, correlates metrics, and inspects manifests and events to identify root causes. It then provides actionable remediation steps in real time.


## Prerequisites [#prerequisites]

* Kubernetes data reporting to New Relic, from either the [Kubernetes integration](/install/kubernetes/) or [OpenTelemetry for Kubernetes](/docs/kubernetes-pixie/k8s-otel/intro/). The more complete the observability setup (application performance monitoring (APM), infrastructure monitoring, cloud integrations, and Kubernetes data), the richer the agent's analysis.
* New Relic [Autopilot enabled and set up](/docs/agentic-ai/autopilot/setup) on your account.


## How to use Autopilot K8s Agent [#usage]

After Autopilot is enabled on your account, you can start using Autopilot K8s Agent to analyze your Kubernetes environment and investigate incidents. There are three ways to reach it:

* **Ask Autopilot directly** in the New Relic AI chat sidebar.
* **Start from an Investigate button** in a Kubernetes view. See [Start from a Kubernetes view](#investigate).
* **From alerts:** when an alert workflow sends an issue to Autopilot and the investigation involves Kubernetes resources, Autopilot calls Autopilot K8s Agent automatically as part of its analysis. No extra setup is needed beyond your existing [Autopilot alert configuration](/docs/agentic-ai/autopilot/setup).

### Start from a Kubernetes view [#investigate]

Kubernetes pages in New Relic include buttons that open Autopilot with a ready-made prompt. The prompt already includes the cluster, namespace, entity, and status you're looking at, so you don't have to type them.

| Where | Button | What it asks Autopilot to do |
| :--- | :--- | :--- |
| K8s landing page | <DNT>**Investigate**</DNT> in the hover layer that appears when you hover over an entity name or a metric value | Diagnose an unhealthy entity or an anomalous metric, or confirm that a healthy entity has no issues |
| Kubernetes navigator | **Investigate cluster** | Analyze the entities shown, starting with critical alerts and failing entities |
| Kubernetes navigator |  <DNT>**Investigate**</DNT> in the tooltip when you hover over a critical entity's hexagon, or the action icon when you hover over a table row | Diagnose that entity's health status |
| Kubernetes events | <DNT>**Investigate**</DNT> in the popover that appears when you hover over a warning event's reason. The popover shows the event description with the button | Find the root cause of the warning event |
| Kubernetes APM summary page | <DNT>**Investigate pods in application**</DNT> | Check the pods behind the application's workload for issues |
| K8s entity dashboards | <DNT>**Explain this chart**</DNT> or <DNT>**Find anomalies**</DNT> in the chart menu | Explain what a chart shows for the entity, or find anomalies in it |

### Usage tips [#tips]

Autopilot routes prompts to the specialized Kubernetes diagnostic engine based on keywords and context embedded in your query.

To ensure your question reaches Autopilot K8s Agent:

* **Use "K8s" or "Kubernetes" in your prompt:** Including either of these words is the most reliable signal for routing your question to Autopilot K8s Agent.

* **Be specific with Kubernetes terminology:** Include Kubernetes-specific terms such as `pod`, `node`, `namespace`, `deployment`, `replica`, `container`, `cluster`, `workload`, `CrashLoopBackOff`, `OOMKilled`, `PVC`, `HPA`, and others.

  For example:

  | Less effective | More effective |
  | :--- | :--- |
  | `Why is my app slow?` | `Why are pods in namespace payments restarting?` |
  | `Something is broken` | `Pod checkout-service in cluster prod-east is in CrashLoopBackOff` |
  | `Fix my deployment` | `Deployment api-gateway has replica mismatch in namespace frontend` |
  | `Check my cluster` | `What's the health of my Kubernetes cluster prod-east-1?` |

* **Add context when possible**
  - Mention the cluster name, namespace, pod/deployment name, or node.
  - Describe symptoms using precise status terms, such as, `"Pending"`, `"Evicted"`, `"ImagePullBackOff"`.
  - Define explicit time windows when relevant. For example, `"since last rollout"`, `"in the last hour"`.

* **Paste your own evidence:** You can paste `kubectl describe` output, logs, or error messages into the prompt. The agent reasons over them together with your New Relic data.

* **Leverage automatic UI routing:** When you open Autopilot from a Kubernetes page in New Relic, including the [Investigate buttons](#investigate), it automatically routes queries to Autopilot K8s Agent without requiring explicit keywords. The agent receives contextual metadata directly from the active UI view.

  <Callout variant="tip" title="Verify agent routing">
  You can confirm your query was handled by Autopilot K8s Agent by expanding **Show reasoning** in the agent's response. If routed correctly, you'll see references to the Autopilot K8s Agent assistant alongside invoked Kubernetes diagnostic tools (such as cluster analysis, manifest inspection, or event correlation). If you don't see Kubernetes-specific reasoning, try rephrasing with more explicit Kubernetes keywords.
  </Callout>


## Privacy and security [#privacy]

The agent analyzes only telemetry data already ingested into your New Relic account. It doesn't access your cluster directly, execute commands, or read Kubernetes secrets. Remediation steps are suggestions that you review and run yourself, and any suggested command that changes resources includes `--dry-run=client` so you can check its effect first.

All interactions are subject to your existing New Relic account permissions and data access controls.
