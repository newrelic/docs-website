<DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitors your service after each deployment that you set up for monitoring. <DNT>Autopilot</DNT> checks the health of the service at scheduled checkpoints, comments on the pull request, and reports the results in <DNT>Slack</DNT> if you've connected it. If it detects a regression, it also opens a <DNT>GitHub</DNT> issue assigned to <DNT>GitHub Copilot</DNT>, which can propose a fix as a pull request if your organization has <DNT>GitHub Copilot Enterprise</DNT>.

<Callout variant="important">
  <DNT>New Relic Change Tracking for GitHub Copilot</DNT> requires a <DNT>GitHub</DNT> token with write access in addition to the read access that [Connect Autopilot to GitHub](/docs/agentic-ai/autopilot/connect-to-github) describes. Add the write permissions to the token you already connected, or connect a new token that has all of them.
</Callout>

Each deployment set up for monitoring goes through these stages:

1. You merge the pull request and your pipeline deploys it. The deployment sends an event to Change Tracking that includes the release tag URL, the merge commit SHA, and the `watchpoint_monitoring` attribute.
2. <DNT>Autopilot</DNT> validates the event. If it passes, <DNT>Autopilot</DNT> comments on the merged pull request and, if you connected <DNT>Slack</DNT>, posts a "monitoring started" message.
3. At each checkpoint, <DNT>Autopilot</DNT> compares the service's metrics after the deployment with the metrics before it. It reports one of three results (no regression, inconclusive, or regression detected) as a comment on the pull request and, if you connected <DNT>Slack</DNT>, as a reply in the same thread. The checkpoints run at 10 minutes, 30 minutes, 1 hour, 2 hours, 24 hours, and 72 hours after the deployment.

When a checkpoint detects a regression, <DNT>Autopilot</DNT> does three things:

* Posts a reply in the <DNT>Slack</DNT> thread (if you connected <DNT>Slack</DNT>) with the relevant metrics and the evidence behind the finding.
* Comments on the pull request with the relevant metrics, the checkpoint that detected the regression, and the reason.
* Opens a <DNT>GitHub</DNT> issue that describes what regressed, the supporting evidence, where to look, and acceptance criteria, then assigns the issue to <DNT>GitHub Copilot</DNT>.

If <DNT>Copilot</DNT> proposes a fix, review it as you would any other pull request before you merge it.

## Prerequisites [#prerequisites]

Before you set up <DNT>New Relic Change Tracking for GitHub Copilot</DNT>, confirm the following:

* You've configured <DNT>Autopilot</DNT>. Refer to [Set up Autopilot](/docs/agentic-ai/autopilot/setup).
* You're a <DNT>**New Relic Organization Manager**</DNT>, and you've opted in to <DNT>**New Relic Change Tracking for GitHub Copilot**</DNT> at <DNT>**[one.newrelic.com > Administration](https://one.newrelic.com/admin-portal) > Preview & Trials**</DNT>.
* You have a <DNT>GitHub</DNT> account and token with write access to the repositories you want to monitor.
* Your deployments send events to [Change Tracking](/docs/change-tracking/overview) with the [`changeTrackingCreateEvent` mutation](/docs/change-tracking/config/nerdgraph). <DNT>New Relic Change Tracking for GitHub Copilot</DNT> doesn't support the legacy endpoint.
* Each event includes the following:
  * The release tag URL in the `changelog` field.
  * The merge commit SHA in the `commit` field.
  * The custom attribute `watchpoint_monitoring` set to `"true"`, for each deployment you want monitored.
* The service reports to New Relic and has at least 3 days of history. With less data, every checkpoint returns an inconclusive result.

Optionally, [connect Autopilot to Slack](/docs/agentic-ai/autopilot/connect-to-slack) to receive notifications. For <DNT>Copilot</DNT> to start work on the issue automatically, your organization needs <DNT>GitHub Copilot Enterprise</DNT>.

## Set up New Relic Change Tracking for GitHub Copilot [#setup]

<Steps>

<Step>

### Create a GitHub token [#create-token]

Create a personal access token in <DNT>GitHub</DNT>. A fine-grained token is recommended, but a classic token also works. For instructions, refer to [Creating a fine-grained personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token) in the <DNT>GitHub</DNT> documentation. Make sure the token has the following:

* Your <DNT>GitHub</DNT> organization as its resource owner.
* Access to the repositories you want <DNT>New Relic Change Tracking for GitHub Copilot</DNT> to monitor.
* <DNT>**Read and write**</DNT> access to <DNT>**Pull requests**</DNT>, <DNT>**Issues**</DNT>, and <DNT>**Contents**</DNT>.

If you already connected <DNT>GitHub</DNT> to <DNT>Autopilot</DNT> and have a token already, you can add these permissions to that token instead.

If your organization enforces SAML SSO, authorize the token for SSO. <DNT>GitHub</DNT> shows the token only once, so when generating it, copy it and paste it into New Relic right away.

</Step>

<Step>

### Connect GitHub and enable monitoring [#enable]

To open the <DNT>Autopilot</DNT> configuration, click <DNT>**Ask AI**</DNT>, click **...**, and then click <DNT>**Configure**</DNT>.

<img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp"/>

In <DNT>**External MCP connections**</DNT>, connect <DNT>**GitHub**</DNT> (<DNT>**Public GitHub**</DNT> or <DNT>**GitHub Enterprise Cloud**</DNT>) with your token and organization name, and then turn on <DNT>**Enable deployment monitoring**</DNT>. To receive notifications, also select a <DNT>Slack</DNT> channel in <DNT>**Post alerts to**</DNT>. This option appears only after you connect <DNT>Slack</DNT> to <DNT>Autopilot</DNT>.

Click <DNT>**Update agent**</DNT> to save your changes.

</Step>

<Step>

### Confirm that monitoring started [#verify]

Deploy a change with the `watchpoint_monitoring` attribute set to `"true"`.

<CollapserGroup>
<Collapser id="example-event" title="Example deployment event">

```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "MERGE_COMMIT"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```

</Collapser>
</CollapserGroup>

After <DNT>Autopilot</DNT> validates the deployment event, you see:

* A comment from <DNT>Autopilot</DNT> on the merged pull request.
* If you connected <DNT>Slack</DNT>, a "monitoring started" message in the channel you selected. The results of later checkpoints appear as replies in that thread.

If neither appears, check that the deployment event meets the [prerequisites](#prerequisites).

</Step>

</Steps>
