<DNT>Autopilot</DNT> can connect to the <DNT>AWS DevOps Agent</DNT> so both agents investigate an incident in parallel. <DNT>Autopilot</DNT> covers the application layer, and the <DNT>AWS DevOps Agent</DNT> covers the <DNT>AWS</DNT> infrastructure layer. <DNT>Autopilot</DNT> then merges both sets of findings into a single answer in the <DNT>**Ask AI**</DNT> panel.

If your team already uses the <DNT>AWS DevOps Agent</DNT> alongside New Relic, this integration gives you a merged investigation in <DNT>Autopilot</DNT> instead of requiring you to combine results from two tools.

<SideBySide>
<Side>

**What <DNT>Autopilot</DNT> investigates:**

* Application error rates, latency spikes, service maps, and distributed traces
* Deployment and configuration change correlation
* User impact across affected services
* Kubernetes pod status, restart counts, and container metrics through the New Relic Kubernetes integration

</Side>

<Side>

**What the <DNT>AWS DevOps Agent</DNT> investigates:**

* <DNT>AWS</DNT> control plane and configuration state, such as IAM policy chains, Aurora and RDS maintenance windows and cluster configuration, and Lambda concurrency settings
* <DNT>AWS</DNT> Health events, such as EBS migrations, Availability Zone capacity events, and regional disruptions
* Layers below the Kubernetes API, such as host-level kubelet logs, VPC subnet exhaustion, and node `dmesg` output
* CloudTrail activity, which shows who changed what, when, and from where
* <DNT>AWS</DNT> data stores, including DynamoDB, S3, ElastiCache, EFS, DocumentDB, and Redshift state

</Side>
</SideBySide>

<DNT>Autopilot</DNT> and the <DNT>AWS DevOps Agent</DNT> investigate in parallel when an alert triggers or you ask a question in the <DNT>**Ask AI**</DNT> panel:

1. <DNT>Autopilot</DNT> starts its own application-layer investigation.
2. If <DNT>Autopilot</DNT> detects an <DNT>AWS</DNT> infrastructure signal, or its confidence in the root cause is below a threshold, it calls the <DNT>AWS DevOps Agent</DNT> in parallel.
3. Both agents investigate at the same time. <DNT>Autopilot</DNT> shows its own findings as soon as they're ready and labels them <DNT>**New Relic Findings**</DNT>. A progress indicator shows that the <DNT>AWS DevOps Agent</DNT> is still running, which can take some time.
4. When the <DNT>AWS DevOps Agent</DNT> finishes its investigation, <DNT>Autopilot</DNT> merges both sets of findings into one answer with one of these outcomes:

   <table>
     <thead>
       <tr>
         <th>Outcome</th>
         <th>Meaning</th>
       </tr>
     </thead>
     <tbody>
       <tr>
         <td>Corroborated</td>
         <td>Both agents reached the same conclusion, so two sources back the merged answer.</td>
       </tr>
       <tr>
         <td>Conflicting</td>
         <td>The agents reached different conclusions. <DNT>Autopilot</DNT> shows both positions and doesn't pick one.</td>
       </tr>
       <tr>
         <td>Connected</td>
         <td>The agents found different parts of a causal chain. For example, <DNT>Autopilot</DNT> identified a deployment, and the <DNT>AWS DevOps Agent</DNT> found that the deployment exhausted memory, which caused pod evictions, which caused the error spike.</td>
       </tr>
     </tbody>
   </table>

Each finding is attributed, so you can see which ones came from <DNT>Autopilot</DNT> and which came from the <DNT>AWS DevOps Agent</DNT>.

Follow-up questions in the same thread reach the same in-progress <DNT>AWS DevOps Agent</DNT> task.

## Prerequisites [#prerequisites]

### In AWS [#prerequisites-aws]

Make sure you have:

* **<DNT>AWS DevOps Agent</DNT>**: Enabled in your <DNT>AWS</DNT> account.
* **Agent space**: Created for the <DNT>AWS</DNT> accounts you want <DNT>Autopilot</DNT> to investigate. Note down the ID and <DNT>AWS</DNT> region that you enter during setup.
* **Service credential**: Created in <DNT>AWS IAM Identity Center</DNT>, <DNT>Amazon Cognito</DNT>, or an IAM service account with these permissions:
  * `devops:ListAgentSpaces`
  * `devops:RunAgent`
  * `devops:GetAgentExecutionStatus`
  * `devops:GetAgentSpace`
* **Bearer token**: Generated at the Operator scope (read-only causes silent investigation failures). Tokens expire after up to 60 days.
* **New Relic MCP server connection**: Added to the <DNT>AWS DevOps Agent</DNT> as a connected tool using your New Relic MCP server endpoint and credentials.

<Callout title="Note">
  If your team has already connected the New Relic MCP server to the <DNT>AWS DevOps Agent</DNT>, you don't need to connect it again. For instructions, refer to [Connecting MCP Servers](https://docs.aws.amazon.com/devopsagent/latest/userguide/configuring-integrations-and-knowledge-connecting-mcp-servers.html) in the <DNT>AWS DevOps Agent</DNT> documentation.
</Callout>

### In New Relic [#prerequisites-new-relic]

Make sure you have:

* **<DNT>Autopilot</DNT> set up in your organization**: Refer to [Set up Autopilot](/docs/agentic-ai/autopilot/setup).
* **Organization manager role**: Required to be able to configure agent connections. Refer to [role scopes](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts/#role-scopes).

## Configure the integration in New Relic [#configure]

The connection is account-scoped, so you don't need to set it up for each engineer.

<Steps>

<Step>

### Open the Autopilot configuration [#open-configuration]

To open the <DNT>Autopilot</DNT> configuration, click <DNT>**Ask AI**</DNT>, click <DNT>**...**</DNT>, and then click <DNT>**Configure**</DNT>.

Enable agent connectors and join the preview for your account. This lets <DNT>Autopilot</DNT> delegate to external agents like the <DNT>AWS DevOps Agent</DNT>.

<Callout title="Note">
  If you don't see this section, contact your New Relic account team to confirm the integration is enabled for your account.
</Callout>

</Step>

<Step>

### Connect the AWS DevOps Agent [#connect-agent]

Connect the <DNT>**AWS DevOps Agent**</DNT> to <DNT>Autopilot</DNT>, and then enter your bearer token, the <DNT>AWS</DNT> region, and the agent space ID. The token must have the Operator scope. New Relic stores it in an encrypted format and doesn't show it again.

</Step>

<Step>

### Test and save the connection [#test-save]

Test and save the connection to confirm that New Relic can reach the agent space with your credential. The connection is live for all <DNT>Autopilot</DNT> runs in that account.

</Step>

</Steps>

## Manage the connection [#manage]

### Update the bearer token [#update-token]

Update the bearer token when it expires or <DNT>AWS</DNT> revokes it.

1. In <DNT>AWS</DNT>, generate a new bearer token at the Operator scope and copy it.
2. Open the <DNT>Autopilot</DNT> configuration, and then reconnect the <DNT>AWS DevOps Agent</DNT> from its card. The <DNT>AWS</DNT> region and agent space ID are already filled in.
3. Replace the token, and then test and save the connection.

### Disconnect the agent [#disconnect]

To stop <DNT>Autopilot</DNT> from using the <DNT>AWS DevOps Agent</DNT>, disconnect it from its card in the <DNT>Autopilot</DNT> configuration. To use the agent again, enter the bearer token, <DNT>AWS</DNT> region, and agent space ID again.

## Security and data handling [#security]

Here's how the integration handles data, credentials, and recommendations:

* **Data that leaves New Relic**: <DNT>Autopilot</DNT> sends the <DNT>AWS</DNT> account ID, region, entity type, and a description of the symptom to the <DNT>AWS DevOps Agent</DNT>. It doesn't send raw log data, metric time series, trace data, or customer PII.
* **Authentication**: New Relic stores the bearer token encrypted at rest. It resolves the token once per request and discards it immediately after use.
* **Partner response handling**: Only structured evidence records and the investigation summary from the <DNT>AWS DevOps Agent</DNT> reach the <DNT>Autopilot</DNT> merged answer. The internal reasoning and tool output of the <DNT>AWS DevOps Agent</DNT> don't, and New Relic blocks unknown content types by default.
* **Manual execution of recommendations**: <DNT>Autopilot</DNT> doesn't run any action that the <DNT>AWS DevOps Agent</DNT> suggests, including mitigation plans. Recommendations appear for you to review, and you run them yourself.

## Limitations [#limitations]

These are the limitations that apply:

<table>
  <thead>
    <tr>
      <th>Area</th>
      <th>Limitation</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Supported partner agent</td>
      <td>The <DNT>AWS DevOps Agent</DNT> is the only supported partner agent.</td>
    </tr>
    <tr>
      <td>Authentication method</td>
      <td><DNT>Autopilot</DNT> supports only bearer token authentication, not OAuth or <DNT>AWS SigV4</DNT>.</td>
    </tr>
    <tr>
      <td>Token lifetime</td>
      <td><DNT>AWS</DNT> bearer tokens expire after up to 60 days.</td>
    </tr>
    <tr>
      <td>Agent spaces</td>
      <td>One New Relic account maps to one <DNT>AWS</DNT> agent space. <DNT>Autopilot</DNT> doesn't support mapping to multiple agent spaces.</td>
    </tr>
    <tr>
      <td>Entity types</td>
      <td><DNT>Autopilot</DNT> routes only <DNT>AWS</DNT> entities to the <DNT>AWS DevOps Agent</DNT>. Entities without a `cloud.account.id` metadata attribute, such as browser monitors, synthetic monitors, and front-end services, <DNT>Autopilot</DNT> investigates on its own.</td>
    </tr>
    <tr>
      <td><DNT>AWS</DNT> account scope</td>
      <td>The <DNT>AWS</DNT> account of the alerted entity must be in the connected agent space. If it isn't, <DNT>Autopilot</DNT> investigates without the <DNT>AWS DevOps Agent</DNT>.</td>
    </tr>
    <tr>
      <td>Investigations per thread</td>
      <td>You can't start a second investigation in a thread until the first one finishes.</td>
    </tr>
    <tr>
      <td>Required role</td>
      <td>Only users with the [Organization manager](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts/#role-scopes) role can configure agent connections.</td>
    </tr>
  </tbody>
</table>

## Troubleshoot the connection [#troubleshoot]

For setup errors (401, 403, 404, and 429) and bearer token expiry, refer to [Troubleshoot the <DNT>AWS DevOps Agent</DNT> connection](/docs/agentic-ai/autopilot/troubleshoot-aws-devops-agent-connection).
