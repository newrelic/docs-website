<Callout variant="important">
  The <DNT>Autopilot</DNT> integration with the <DNT>AWS DevOps Agent</DNT> is currently in public preview. The public preview feature is provided pursuant to our [pre-release policies](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

<DNT>Autopilot</DNT> can connect to the <DNT>AWS DevOps Agent</DNT> so both agents investigate an incident in parallel. <DNT>Autopilot</DNT> covers the application layer, and the <DNT>AWS DevOps Agent</DNT> covers the AWS infrastructure layer. <DNT>Autopilot</DNT> then merges both sets of findings into a single answer in the <DNT>**Ask AI**</DNT> panel.

If your team already uses the <DNT>AWS DevOps Agent</DNT> alongside New Relic, this integration gives you a merged investigation in <DNT>Autopilot</DNT> instead of requiring you to combine results from two tools.

## What each agent investigates [#what-each-agent-investigates]

When an alert fires, <DNT>Autopilot</DNT> investigates the application layer and the <DNT>AWS DevOps Agent</DNT> investigates the infrastructure layer at the same time.

<DNT>Autopilot</DNT> investigates:

* Application error rates, latency spikes, service maps, and distributed traces
* Deployment and configuration change correlation
* User impact across affected services
* Kubernetes pod status, restart counts, and container metrics through the New Relic Kubernetes integration

The <DNT>AWS DevOps Agent</DNT> investigates:

* AWS control plane and configuration state, such as IAM policy chains, Aurora and RDS maintenance windows and cluster configuration, and Lambda concurrency settings
* AWS Health events, such as EBS migrations, Availability Zone capacity events, and regional disruptions
* Layers below the Kubernetes API, such as host-level kubelet logs, VPC subnet exhaustion, and node `dmesg` output
* CloudTrail activity, which shows who changed what, when, and from where
* AWS data stores, including DynamoDB, S3, ElastiCache, EFS, DocumentDB, and Redshift state

## Prerequisites [#prerequisites]

Complete these steps before you configure the integration in New Relic.

### In AWS [#prerequisites-aws]

1. Enable the <DNT>AWS DevOps Agent</DNT> in your AWS account.
2. Create an agent space that includes the AWS accounts you want <DNT>Autopilot</DNT> to investigate.
3. Create a service credential in <DNT>AWS IAM Identity Center</DNT>, <DNT>Amazon Cognito</DNT>, or an IAM service account, with these permissions:
   * `devops:ListAgentSpaces`
   * `devops:RunAgent`
   * `devops:GetAgentExecutionStatus`
   * `devops:GetAgentSpace`
4. Generate a bearer token at the Operator scope. The read-only scope isn't sufficient and causes silent failures during an investigation. AWS limits bearer token expiry to a maximum of 60 days.

### In the AWS DevOps Agent [#prerequisites-devops-agent]

Add the New Relic MCP server to the <DNT>AWS DevOps Agent</DNT> as a connected tool. This lets the <DNT>AWS DevOps Agent</DNT> query your New Relic data when it needs application context during an investigation. For instructions on connecting an external MCP server, refer to the <DNT>AWS DevOps Agent</DNT> documentation. When prompted, use your New Relic MCP server endpoint and credentials.

If your team has already connected the New Relic MCP server to the <DNT>AWS DevOps Agent</DNT>, that connection satisfies this step.

### In New Relic [#prerequisites-new-relic]

* **<DNT>Autopilot</DNT> set up in your organization**: Refer to [Set up Autopilot](/docs/agentic-ai/autopilot/setup).
* **Organization manager role**: Only organization managers can configure agent connections.

## Configure the integration in New Relic [#configure]

The connection is account-scoped, so you don't need to set it up for each engineer.

1. Go to <DNT>**[one.newrelic.com](https://one.newrelic.com)**</DNT>.
2. In the upper right, select <DNT>**Ask AI**</DNT>, then select the <DNT>**Configure**</DNT> tab.
3. Under <DNT>**Agents**</DNT>, select your <DNT>Autopilot</DNT>, then select the <DNT>**Integrations**</DNT> tab.
4. In the <DNT>**A2A Connected Agents**</DNT> section, select <DNT>**AWS DevOps Agent**</DNT> from the partner catalog. If you don't see this section, contact your New Relic account team to confirm the integration is enabled for your account.
5. For authentication, select <DNT>**Bearer Token**</DNT>, then enter your token. New Relic masks the token after you save it and never logs it.
6. Enter the token expiry date. This is optional, but New Relic uses it to warn you 24 hours before the token expires.
7. Select <DNT>**Auto-discover agent spaces**</DNT>. New Relic calls the <DNT>AWS DevOps Agent</DNT> discovery endpoint and returns your available agent spaces.
8. Select your target agent space.
9. Optionally, configure a connection label and routing scope.
10. Select <DNT>**Test Connection**</DNT> to confirm that New Relic can reach the credential and agent space.
11. Select <DNT>**Save**</DNT>. The connection is live for all <DNT>Autopilot</DNT> runs in that account.

## How the investigation works [#how-it-works]

When an alert fires or you ask a question in the <DNT>**Ask AI**</DNT> panel:

1. <DNT>Autopilot</DNT> starts its own application-layer investigation.
2. If <DNT>Autopilot</DNT> detects an AWS infrastructure signal, or its confidence in the root cause is below a threshold, it calls the <DNT>AWS DevOps Agent</DNT> in parallel.
3. Both agents investigate at the same time. <DNT>Autopilot</DNT> shows its own findings as soon as they're ready, labeled <DNT>**New Relic Findings**</DNT>, and a progress indicator shows that the <DNT>AWS DevOps Agent</DNT> is still running.
4. When the <DNT>AWS DevOps Agent</DNT> finishes, <DNT>Autopilot</DNT> merges both sets of findings into one answer.

Each finding is attributed, so you can see which ones came from <DNT>Autopilot</DNT> and which came from the <DNT>AWS DevOps Agent</DNT>.

After both agents finish, <DNT>Autopilot</DNT> produces one of these outcomes:

### Long-running investigations [#long-running]

The deep infrastructure investigation by the <DNT>AWS DevOps Agent</DNT> can take 8 to 15 minutes. During that time:

* <DNT>Autopilot</DNT> shows its own findings immediately while the <DNT>AWS DevOps Agent</DNT> continues in the background.
* When the <DNT>AWS DevOps Agent</DNT> finishes, the merged answer posts in the same thread automatically. You don't need to send a new prompt.
* Follow-up questions in the same thread reach the same in-progress <DNT>AWS DevOps Agent</DNT> task.
* One investigation runs per thread at a time. You can't start a new investigation in a thread until the current one finishes.

## Security and data handling [#security]

* **Data that leaves New Relic**: <DNT>Autopilot</DNT> sends the AWS account ID, region, entity type, and a description of the symptom to the <DNT>AWS DevOps Agent</DNT>. It doesn't send raw log data, metric time series, trace data, or customer PII.
* **Authentication**: New Relic stores the bearer token encrypted at rest. It resolves the token once per request and discards it immediately after use.
* **Partner response handling**: Only structured evidence records and the investigation summary from the <DNT>AWS DevOps Agent</DNT> reach the <DNT>Autopilot</DNT> merged answer. The internal reasoning and tool output of the <DNT>AWS DevOps Agent</DNT> don't, and New Relic blocks unknown content types by default.
* **Manual execution of mitigation plans**: <DNT>Autopilot</DNT> doesn't run any action that the <DNT>AWS DevOps Agent</DNT> suggests. Recommendations appear for you to review, and you run them yourself.

### Token expiry [#token-expiry]

Bearer tokens expire at most 60 days after you generate them. These are the points where you see the expiry:

<table>
  <thead>
    <tr>
      <th>When</th>
      <th>Where it appears</th>
      <th>Action</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>24 hours before expiry</td>
      <td>A warning banner on the <DNT>AWS DevOps Agent</DNT> connection card</td>
      <td>Select <DNT>**Update Token**</DNT>.</td>
    </tr>
    <tr>
      <td>The token expires during an investigation</td>
      <td>In the active investigation thread: "AWS investigation paused — bearer token expired. Update token in Integrations to resume."</td>
      <td>Select <DNT>**Update Token**</DNT>, then start the investigation again.</td>
    </tr>
    <tr>
      <td>The token has already expired when an investigation starts</td>
      <td>The connection shows "Token expired" in the <DNT>**Integrations**</DNT> panel, and routing to the <DNT>AWS DevOps Agent</DNT> is disabled</td>
      <td>Select <DNT>**Update Token**</DNT>.</td>
    </tr>
  </tbody>
</table>

To rotate a token:

1. Generate the new token in AWS.
2. In <DNT>Autopilot</DNT>, go to <DNT>**Configure**</DNT> > <DNT>**Integrations**</DNT> > <DNT>**AWS DevOps Agent**</DNT> and select <DNT>**Update Token**</DNT>.
3. Enter the new token. New Relic preserves all other settings.

An investigation paused by an expired token doesn't resume automatically, so start it again. The <DNT>AWS DevOps Agent</DNT> treats a rotated credential as a new identity, so any in-progress investigation tied to the previous token is lost on the AWS side.

## Limitations [#limitations]

These limitations apply to the public preview:

<table>
  <thead>
    <tr>
      <th>Limitation</th>
      <th>Detail</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Supported partner agent</td>
      <td>The <DNT>AWS DevOps Agent</DNT> is the only supported partner agent.</td>
    </tr>
    <tr>
      <td>Authentication method</td>
      <td>Only bearer token authentication is supported. OAuth and AWS SigV4 aren't supported.</td>
    </tr>
    <tr>
      <td>Token lifetime</td>
      <td>AWS limits bearer token expiry to 60 days. <DNT>Autopilot</DNT> warns you 24 hours before expiry.</td>
    </tr>
    <tr>
      <td>Agent spaces</td>
      <td>One New Relic account maps to one AWS agent space. Mapping to multiple agent spaces isn't supported.</td>
    </tr>
    <tr>
      <td>Entity types</td>
      <td>Only AWS entities are routed to the <DNT>AWS DevOps Agent</DNT>. Entities without a `cloud.account.id` metadata attribute, such as browser monitors, synthetic monitors, and front-end services, are investigated by <DNT>Autopilot</DNT> only.</td>
    </tr>
    <tr>
      <td>AWS account scope</td>
      <td>The AWS account of the alerted entity must be in the connected agent space. If it isn't, <DNT>Autopilot</DNT> investigates without the <DNT>AWS DevOps Agent</DNT>.</td>
    </tr>
    <tr>
      <td>Investigations per thread</td>
      <td>You can't start a second investigation in a thread until the first one finishes.</td>
    </tr>
    <tr>
      <td>Required role</td>
      <td>Only organization managers can configure agent connections.</td>
    </tr>
  </tbody>
</table>
