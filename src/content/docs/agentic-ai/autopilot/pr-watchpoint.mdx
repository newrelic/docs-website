PR watchpoint monitors your service around each pull request. When you open a pull request in a monitored GitHub repository, <DNT>Autopilot</DNT> reads the changes and posts a monitoring plan as a comment. After the change is deployed, <DNT>Autopilot</DNT> checks the health of the service at scheduled checkpoints over the next 72 hours. If it detects a regression, it reports the evidence in Slack and on the pull request, and opens a GitHub issue with the full context.

<Callout variant="important">
  PR watchpoint needs a GitHub token with write access to pull requests, issues, and repository contents. This is different from the read-only token that [Connect Autopilot to GitHub](/docs/agentic-ai/autopilot/connect-to-github) describes for incident investigations.
</Callout>

## What PR watchpoint does [#capabilities]

PR watchpoint does the following:

* **Posts a monitoring plan before you merge.** When a pull request opens in a monitored repository, <DNT>Autopilot</DNT> reads the changes and comments with a risk assessment, the effect the change is meant to have, and the signals to watch. The plan doesn't block the merge.
* **Starts monitoring after a deployment.** When a deployment event for a monitored repository arrives through Change Tracking, <DNT>Autopilot</DNT> validates it and begins monitoring. It posts an acknowledgment comment on the merged pull request and, if you configured Slack, a message in your channel.
* **Checks service health at scheduled checkpoints.** <DNT>Autopilot</DNT> compares the service's metrics after the deployment with the metrics before it at 10 minutes, 30 minutes, 1 hour, 2 hours, 24 hours, and 72 hours.
* **Reports each result in one Slack thread.** Every checkpoint for a deployment is a reply in the same thread.
* **Reports regressions where you work.** <DNT>Autopilot</DNT> posts a regression to Slack and as a comment on the pull request, with the before and after metrics and the reason it flagged the regression.
* **Opens a GitHub issue for the fix.** The issue includes what regressed, the evidence, where to look, and acceptance criteria. <DNT>Autopilot</DNT> assigns the issue to GitHub Copilot.

## Before you begin [#prerequisites]

Before you set up PR watchpoint, make sure you have:

* **A configured <DNT>Autopilot</DNT>.** Refer to [Set up Autopilot](/docs/agentic-ai/autopilot/setup).
* **New Relic org manager access.** Only an organization manager can configure PR watchpoint.
* **Repositories on github.com.** PR watchpoint supports repositories hosted on github.com.
* **Preview access to the GitHub connection.** If <DNT>**External MCP connections**</DNT> shows that connecting GitHub isn't available for your account, ask your administrator to request access.
* **GitHub admin access** to the organization that owns the repositories. Only an admin can create a fine-grained personal access token for organization resources.
* **Deployment events in Change Tracking.** Services must send deployment events to [Change Tracking](/docs/change-tracking/overview). PR watchpoint starts from these events.

* **APM data for the service.** The service must report to New Relic and have at least 3 days of history so <DNT>Autopilot</DNT> has a baseline to compare. With less data, every checkpoint returns an inconclusive result.
* **A Slack connection (optional).** To receive notifications, [connect Autopilot to Slack](/docs/agentic-ai/autopilot/connect-to-slack).
* **GitHub Copilot Enterprise (optional).** Copilot can start work on the issue automatically only if your organization has GitHub Copilot Enterprise.

## Set up PR watchpoint [#setup]

### Step 1: Create a GitHub token [#create-token]

Create a fine-grained personal access token in GitHub:

1. Sign in to GitHub as an organization administrator.

2. Go to <DNT>**Settings > Developer settings > Personal access tokens > Fine-grained tokens**</DNT>, then click <DNT>**Generate new token**</DNT>.

3. Set <DNT>**Resource owner**</DNT> to your GitHub organization.

4. Under <DNT>**Repository access**</DNT>, select <DNT>**Only select repositories**</DNT>, then select the repositories you want PR watchpoint to monitor.

5. Under <DNT>**Repository permissions**</DNT>, set these three permissions to <DNT>**Read and write**</DNT>:
   * **Pull requests**
   * **Issues**
   * **Contents**

   GitHub adds **Metadata: Read** automatically.

6. Click <DNT>**Generate token**</DNT> and copy the value. GitHub shows it only once.

If your organization enforces SAML SSO, authorize the token for SSO before you continue.

### Step 2: Connect GitHub and turn on PR watchpoint [#enable]

Connect GitHub from the <DNT>Autopilot</DNT> configuration, then turn on PR watchpoint:

1. In <DNT>[one.newrelic.com](https://one.newrelic.com)</DNT>, open the agent tray in the header and select <DNT>**Configure**</DNT>.
2. Under <DNT>**Agents**</DNT>, click <DNT>**Autopilot**</DNT>.
3. In <DNT>**External MCP connections**</DNT>, expand <DNT>**GitHub**</DNT> and select <DNT>**Public GitHub**</DNT>.
4. Paste the token into <DNT>**GitHub personal access token**</DNT>.
5. Enter your GitHub organization name in <DNT>**GitHub organization name**</DNT>. A fine-grained token belongs to a single organization, so this field is required.
6. Click <DNT>**Create connection**</DNT>. New Relic validates the token and connects GitHub.
7. Under <DNT>**PR watchpoint**</DNT>, turn on <DNT>**Enable deployment monitoring**</DNT>.
8. To receive notifications, select a Slack channel in <DNT>**Post alerts to**</DNT>.
9. Click <DNT>**Update agent**</DNT>.

## How PR watchpoint monitors a deployment [#how-it-works]

PR watchpoint monitors each deployment in these stages:

1. **Open a pull request.** <DNT>Autopilot</DNT> reads the changes and posts the monitoring plan as a comment. Reply to the comment to refine the plan until the pull request merges. After the merge, the plan is locked.
2. **Merge and deploy.** You merge a pull request and your pipeline deploys it. The deployment sends an event to Change Tracking with the service name.
3. **Validation and acknowledgment.** <DNT>Autopilot</DNT> validates the event. If it passes, <DNT>Autopilot</DNT> comments on the merged pull request and posts a "monitoring started" message in Slack with the service, release, repository, and commit.
4. **Checkpoints.** <DNT>Autopilot</DNT> evaluates the service at each checkpoint and replies in the Slack thread with one of three results: no regression, inconclusive, or regression detected.

## What you get when a regression is detected [#regression-output]

When a checkpoint detects a regression, <DNT>Autopilot</DNT> does three things:

* **Posts to Slack.** The thread reply shows the affected service, the before and after values for error rate, p95 latency, and request count, and the evidence behind the finding.
* **Comments on the pull request.** The comment shows the same before and after table, the checkpoint that detected the regression, and the reason.
* **Opens a GitHub issue.** The issue title names the service and the commit, and the body describes what regressed, the supporting evidence, where to look, and acceptance criteria. <DNT>Autopilot</DNT> assigns the issue to GitHub Copilot.

If your organization has GitHub Copilot Enterprise, Copilot starts working on the issue and can open a pull request with a proposed fix. Review the fix as you would any other pull request before you merge it.

## Limitations [#limitations]

PR watchpoint has the following limitation:

* **GitHub.com only.** PR watchpoint supports repositories hosted on github.com. GitHub Enterprise Cloud (GHE.com) and self-hosted GitHub aren't supported.
