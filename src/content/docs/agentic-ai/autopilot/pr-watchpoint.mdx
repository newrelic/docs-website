PR watchpoint monitors your service around each pull request in a monitored <DNT>GitHub</DNT> repository. <DNT>Autopilot</DNT> posts a monitoring plan on the pull request, checks the health of the service after the change is deployed, and reports the results in <DNT>Slack</DNT> if you've connected it. If it detects a regression, it also comments on the pull request and opens a <DNT>GitHub</DNT> issue assigned to <DNT>GitHub Copilot</DNT>.

<Callout variant="important">
  * PR watchpoint needs a <DNT>GitHub</DNT> token with write access, which is different from the read-only token that [Connect Autopilot to GitHub](/docs/agentic-ai/autopilot/connect-to-github) describes for incident investigations.
  * PR watchpoint supports repositories hosted on github.com only. <DNT>GitHub</DNT> Enterprise Cloud (GHE.com) and self-hosted <DNT>GitHub</DNT> aren't supported.
</Callout>

## How PR watchpoint monitors a deployment [#how-it-works]

PR watchpoint monitors each deployment in these stages:

1. When you open a pull request, <DNT>Autopilot</DNT> reads the changes and posts a monitoring plan as a comment, with a risk assessment, the effect the change is meant to have, and the signals to watch. The plan doesn't block the merge. Reply to the comment to refine the plan until the pull request merges. After the merge, <DNT>Autopilot</DNT> locks the plan.
2. You merge the pull request and your pipeline deploys it. The deployment sends an event to Change Tracking with the service name.
3. <DNT>Autopilot</DNT> validates the event. If it passes, <DNT>Autopilot</DNT> comments on the merged pull request and, if you connected <DNT>Slack</DNT>, posts a "monitoring started" message with the service, release, repository, and commit.
4. At each checkpoint, <DNT>Autopilot</DNT> compares the service's metrics after the deployment with the metrics before it and replies in the same <DNT>Slack</DNT> thread with one of three results: no regression, inconclusive, or regression detected. The checkpoints run at 10 minutes, 30 minutes, 1 hour, 2 hours, 24 hours, and 72 hours after the deployment.

## What you get when a regression is detected [#regression-output]

When a checkpoint detects a regression, <DNT>Autopilot</DNT> does three things:

* Posts a reply in the <DNT>Slack</DNT> thread with the affected service, the before and after values for error rate, p95 latency, and request count, and the evidence behind the finding.
* Comments on the pull request with the same before and after table, the checkpoint that detected the regression, and the reason.
* Opens a <DNT>GitHub</DNT> issue that names the service and the commit and describes what regressed, the supporting evidence, where to look, and acceptance criteria, then assigns the issue to <DNT>GitHub Copilot</DNT>.

If your organization has <DNT>GitHub Copilot Enterprise</DNT>, <DNT>Copilot</DNT> can start work on the issue and propose a fix as a pull request. Review the fix as you would any other pull request before you merge it.

## Prerequisites [#prerequisites]

Before you set up PR watchpoint, confirm the following:

* You've configured <DNT>Autopilot</DNT>. Refer to [Set up Autopilot](/docs/agentic-ai/autopilot/setup).
* A <DNT>**New Relic Organization Manager**</DNT> configures PR watchpoint, and a <DNT>GitHub</DNT> user with write access to the repositories creates the access token.
* Connecting <DNT>GitHub</DNT> is available for your account. If it isn't, ask your administrator to request preview access.
* Your services send deployment events to [Change Tracking](/docs/change-tracking/overview).
{/* OPEN: does the Change Tracking event need a commit SHA? PRD says SHA is optional with a lower-confidence fallback; the existing GitHub page says SHA is required. */}
* The service reports to New Relic and has at least 3 days of history. With less data, every checkpoint returns an inconclusive result.

Optionally, [connect Autopilot to Slack](/docs/agentic-ai/autopilot/connect-to-slack) to receive notifications. For <DNT>Copilot</DNT> to start work on the issue automatically, your organization needs <DNT>GitHub Copilot Enterprise</DNT>.

## Set up PR watchpoint [#setup]

### Step 1: Create a GitHub token [#create-token]

Create a fine-grained personal access token in <DNT>GitHub</DNT>:

1. Sign in to <DNT>GitHub</DNT> with an account that has write access to the repositories you want to monitor.
2. Go to <DNT>**Settings > Developer settings > Personal access tokens > Fine-grained tokens**</DNT>, then click <DNT>**Generate new token**</DNT>.
3. Set <DNT>**Resource owner**</DNT> to your <DNT>GitHub</DNT> organization.
4. Under <DNT>**Repository access**</DNT>, give the token access to the repositories you want PR watchpoint to monitor.
5. Under <DNT>**Permissions**</DNT>, set these three permissions to <DNT>**Read and write**</DNT>:
   * <DNT>**Pull requests**</DNT>
   * <DNT>**Issues**</DNT>
   * <DNT>**Contents**</DNT>

   <DNT>GitHub</DNT> adds <DNT>**Metadata: Read**</DNT> automatically.
6. Click <DNT>**Generate token**</DNT> and copy the value. <DNT>GitHub</DNT> shows it only once.

If your organization enforces SAML SSO, authorize the token for SSO before you continue.

### Step 2: Connect GitHub and turn on PR watchpoint [#enable]

Connect <DNT>GitHub</DNT> from the <DNT>Autopilot</DNT> configuration, then turn on PR watchpoint:

1. Go to <DNT>[**one.newrelic.com**](https://one.newrelic.com)</DNT>. In the upper right, click <DNT>**Ask AI**</DNT>, click **...**, then click <DNT>**Configure**</DNT>.
   <img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp"/>
2. Click <DNT>**Autopilot**</DNT>. In <DNT>**External MCP connections**</DNT>, expand <DNT>**GitHub**</DNT> and select <DNT>**Public GitHub**</DNT>.
3. Paste the token into <DNT>**GitHub personal access token**</DNT>, then enter your <DNT>GitHub</DNT> organization name.
4. Click <DNT>**Create connection**</DNT>.
5. Under <DNT>**PR watchpoint**</DNT>, turn on <DNT>**Enable deployment monitoring**</DNT>.
6. To receive notifications, select a <DNT>Slack</DNT> channel in <DNT>**Post alerts to**</DNT>, then click <DNT>**Update agent**</DNT>.
