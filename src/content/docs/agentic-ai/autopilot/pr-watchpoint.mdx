<DNT>PR Watchpoint</DNT> monitors your service after each deployment that you flag for monitoring. <DNT>Autopilot</DNT> checks the health of the service at scheduled checkpoints, comments on the pull request, and reports the results in <DNT>Slack</DNT> if you've connected it. If it detects a regression, it also opens a <DNT>GitHub</DNT> issue assigned to <DNT>GitHub Copilot</DNT>.

<Callout variant="important">
  <DNT>PR Watchpoint</DNT> needs a <DNT>GitHub</DNT> token with write access, in addition to the read access that [Connect Autopilot to GitHub](/docs/agentic-ai/autopilot/connect-to-github) describes. Add the permissions to the token you already connected, or connect a new token that has all of them.
</Callout>

## How PR Watchpoint monitors a deployment [#how-it-works]

<DNT>PR Watchpoint</DNT> monitors each deployment in these stages:

1. You merge the pull request and your pipeline deploys it. The deployment sends an event to Change Tracking that includes the release tag URL, the commit SHA, and the `watchpoint_monitoring` attribute.
2. <DNT>Autopilot</DNT> validates the event. If it passes, <DNT>Autopilot</DNT> comments on the merged pull request and, if you connected <DNT>Slack</DNT>, posts a "monitoring started" message with the service, release, repository, and commit.
3. At each checkpoint, <DNT>Autopilot</DNT> compares the service's metrics after the deployment with the metrics before it. It reports one of three results (no regression, inconclusive, or regression detected) as a comment on the pull request and, if you connected <DNT>Slack</DNT>, as a reply in the same thread. The checkpoints run at 10 minutes, 30 minutes, 1 hour, 2 hours, 24 hours, and 72 hours after the deployment.

## What you get when a regression is detected [#regression-output]

When a checkpoint detects a regression, <DNT>Autopilot</DNT> does three things:

* Posts a reply in the <DNT>Slack</DNT> thread (if you connected <DNT>Slack</DNT>) with the affected service, the before and after values for error rate, p95 latency, and request count, and the evidence behind the finding.
* Comments on the pull request with the same before and after table, the checkpoint that detected the regression, and the reason.
* Opens a <DNT>GitHub</DNT> issue that names the service and the commit and describes what regressed, the supporting evidence, where to look, and acceptance criteria, then assigns the issue to <DNT>GitHub Copilot</DNT>.

If your organization has <DNT>GitHub Copilot Enterprise</DNT>, <DNT>Copilot</DNT> can start work on the issue and propose a fix as a pull request. Review the fix as you would any other pull request before you merge it.

## Prerequisites [#prerequisites]

Before you set up <DNT>PR Watchpoint</DNT>, confirm the following:

* You've configured <DNT>Autopilot</DNT>. Refer to [Set up Autopilot](/docs/agentic-ai/autopilot/setup).
* You're a <DNT>**New Relic Organization Manager**</DNT>. Only an Organization Manager can open <DNT>**Preview & Trials**</DNT> and configure <DNT>PR Watchpoint</DNT>.
* You have a <DNT>GitHub</DNT> account with write access to the repositories you want to monitor.
* Your deployments send events to [Change Tracking](/docs/change-tracking/overview) with the [`changeTrackingCreateEvent` mutation](/docs/change-tracking/config/nerdgraph). <DNT>PR Watchpoint</DNT> doesn't support the legacy endpoint.
* Each event includes the following:
  * The release tag URL in the `changelog` field.
  * The commit SHA in the `commit` field.
  * The custom attribute `watchpoint_monitoring` set to `"true"`, for each deployment you want monitored.
* The service reports to New Relic and has at least 3 days of history. With less data, every checkpoint returns an inconclusive result.

The following example shows an event that meets these requirements:

```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "COMMIT_SHA"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```

Optionally, [connect Autopilot to Slack](/docs/agentic-ai/autopilot/connect-to-slack) to receive notifications. For <DNT>Copilot</DNT> to start work on the issue automatically, your organization needs <DNT>GitHub Copilot Enterprise</DNT>.

## Set up PR Watchpoint [#setup]

<Steps>

<Step>

### Opt in to PR Watchpoint [#opt-in]

Only an Organization Manager can open <DNT>**Preview & Trials**</DNT>. Go to <DNT>**[one.newrelic.com > Administration](https://one.newrelic.com/admin-portal) > Preview & Trials**</DNT>, and enable <DNT>**PR Watchpoint**</DNT>.

</Step>

<Step>

### Create a GitHub token [#create-token]

A <DNT>GitHub</DNT> user with write access to the repositories creates the token. <DNT>PR Watchpoint</DNT> needs permissions in addition to the read permissions that <DNT>Autopilot</DNT> requires.

If you already connected <DNT>GitHub</DNT> to <DNT>Autopilot</DNT>, your token has <DNT>**Pull requests: Read**</DNT> and <DNT>**Contents: Read**</DNT>. <DNT>PR Watchpoint</DNT> changes both to <DNT>**Read and write**</DNT> and adds <DNT>**Issues: Read and write**</DNT>. Add these permissions to that token, or create a new token that has all of them.

Create a fine-grained personal access token in <DNT>GitHub</DNT>:

1. Sign in to <DNT>GitHub</DNT> with an account that has write access to the repositories you want to monitor.
2. Go to <DNT>**Settings > Developer settings > Personal access tokens > Fine-grained tokens**</DNT>, then click <DNT>**Generate new token**</DNT>.
3. Set <DNT>**Resource owner**</DNT> to your <DNT>GitHub</DNT> organization.
4. Under <DNT>**Repository access**</DNT>, give the token access to the repositories you want <DNT>PR Watchpoint</DNT> to monitor.
5. Under <DNT>**Permissions**</DNT>, set these three permissions to <DNT>**Read and write**</DNT>:
   * <DNT>**Pull requests**</DNT>
   * <DNT>**Issues**</DNT>
   * <DNT>**Contents**</DNT>

   <DNT>GitHub</DNT> adds <DNT>**Metadata: Read**</DNT> automatically.
6. Click <DNT>**Generate token**</DNT>. <DNT>GitHub</DNT> shows the token only once, so copy it and paste it into New Relic right away.

If your organization enforces SAML SSO, authorize the token for SSO before you continue.

</Step>

<Step>

### Connect GitHub and turn on PR Watchpoint [#enable]

An Organization Manager connects <DNT>GitHub</DNT> from the <DNT>Autopilot</DNT> configuration, then turns on <DNT>PR Watchpoint</DNT>:

1. Go to <DNT>[**one.newrelic.com**](https://one.newrelic.com)</DNT>. In the upper right, click <DNT>**Ask AI**</DNT>, click **...**, then click <DNT>**Configure**</DNT>.
   <img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp"/>
2. Click <DNT>**Autopilot**</DNT>. In <DNT>**External MCP connections**</DNT>, expand <DNT>**GitHub**</DNT> and select <DNT>**Public GitHub**</DNT> or <DNT>**GitHub Enterprise Cloud**</DNT>.
3. Paste the token into <DNT>**GitHub personal access token**</DNT>, enter your <DNT>GitHub</DNT> organization name, then click <DNT>**Create connection**</DNT>.
4. Under <DNT>**PR watchpoint**</DNT>, turn on <DNT>**Enable deployment monitoring**</DNT>.
5. To receive notifications, select a <DNT>Slack</DNT> channel in <DNT>**Post alerts to**</DNT>, then click <DNT>**Update agent**</DNT>. This option appears only after you connect <DNT>Slack</DNT> to <DNT>Autopilot</DNT>.

</Step>

<Step>

### Confirm that monitoring started [#verify]

Deploy a change with the `watchpoint_monitoring` attribute set to `"true"`. After <DNT>Autopilot</DNT> validates the deployment event, you see:

* A comment from <DNT>Autopilot</DNT> on the merged pull request.
* If you connected <DNT>Slack</DNT>, a "monitoring started" message in the channel you selected, with the service, release, repository, and commit. The results of later checkpoints appear as replies in that thread.

If neither appears, check that the deployment event meets the [prerequisites](#prerequisites).

</Step>

</Steps>
