 As an Authentication Domain Manager, perform the following steps to grant access to a user for managing account and metrics cardinality. Check with the user about their specific needs and accordingly do the configuration. To learn more about user management, refer to [User management tutorial](/docs/accounts/accounts-billing/new-relic-one-user-management/account-user-mgmt-tutorial/).

<Callout variant="important">
  If the user will change cardinality budgets through NerdGraph or Terraform, they need different permissions than in the UI. See [Permissions for NerdGraph and Terraform](#nerdgraph-terraform-permissions).
</Callout>

<Steps>

  <Step>
    ### Add permissions to a custom role [#permissions-to-custom-role]
    [Create a new custom role](/docs/accounts/accounts-billing/new-relic-one-user-management/account-user-mgmt-tutorial/#roles) with the following permissions, or add them to an existing role. Check with the user to understand the level of access required. 
       * `Manage account cardinality`: Adjust the cardinality budget of the account.
           * `View`: Can see the cardinality budget of the account.
           * `Modify`: Can update the cardinality budget of the account.
       * `Manage metric cardinality`: Adjust the cardinality budget of metrics.
           * `View`: Can see the cardinality budget of the metrics.
           * `Modify`: Can update the cardinality budget of the metrics.
       * `Manage pruning rules`: Manage pruning rules for metrics.
           * `View`: Can see the pruning rules of the metrics.
           * `Modify`: Can create and delete pruning rules for the metrics.
       * `Customer limits management`: Adjust limits of different capabilities in the account including cardinality.
           * `View`: Can see the limits available for the capabilities.
           * `Modify`: Can adjust the limits of the capabilities. Required to change account or per-metric cardinality budgets through NerdGraph or Terraform.
  </Step>

  <Step>
    ### Add user, role, and account to a group [#group-access]
    For the cardinality management, [create a new group](/docs/accounts/accounts-billing/new-relic-one-user-management/account-user-mgmt-tutorial/#group-access) or manage an existing group as follows:
        1. Navigate to **[New Relic Administration](https://one.newrelic.com/admin-portal) > Access Management > Groups**.
        2. Click <DNT>**Create a new group**</DNT>, or select <DNT>**Manage group access**</DNT> from the <Icon name="fe-more-horizontal"/> menu of an existing group.
        3. For a new group, provide a name and click <DNT>**Create group**</DNT>. The <DNT>**Admin**</DNT> pane for the group opens.
        4. Under <DNT>**Members**</DNT>, add the user.
        5. Under <DNT>**Account access**</DNT>, associate the custom role with the desired account for cardinality management.
        6. If cardinality management involves multiple accounts, under <DNT>**Account access**</DNT>, include the custom role for each relevant account within the group.
  </Step>

</Steps>

## Permissions for NerdGraph and Terraform [#nerdgraph-terraform-permissions]

You can change account and per-metric cardinality budgets in the Cardinality Management UI, through [NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph), or with the [New Relic Terraform provider](/docs/more-integrations/terraform/terraform-intro). NerdGraph and Terraform check a different permission than the UI. To change a cardinality budget through NerdGraph or Terraform, the user needs the `Customer limits management: modify` permission on each account they change. The `Manage account cardinality` and `Manage metric cardinality` permissions alone are not enough.

| Action | Permissions in the Cardinality Management UI | Permissions through NerdGraph or Terraform |
| --- | --- | --- |
| Adjust the account cardinality budget | `Manage account cardinality: modify` and `Customer limits management: modify` | `Customer limits management: modify` |
| Adjust a per-metric cardinality budget | `Manage metric cardinality: modify` | `Customer limits management: modify` |

NerdGraph and Terraform requests use a [user key](/docs/apis/intro-apis/new-relic-api-keys/#user-key), so the request has the permissions of the user who owns the key. Add the permissions to that user's role, and add the role to the group for every account the key will change.

<Callout variant="tip">
  If the same user manages cardinality in the UI and through NerdGraph or Terraform, add both sets of permissions from the table to their custom role.
</Callout>

<Callout variant="important">
  If NerdGraph or Terraform returns a `Not authorized` error when changing a cardinality budget, check that the user who owns the key has the `Customer limits management: modify` permission on that account. This applies even if the user can change the same budget in the UI. In NerdGraph, cardinality budgets are changed with the `dataManagementCreateAccountLimit` mutation, using the limits named `Dimensional Metric account cardinality ingested per day` and `Dimensional Metric per-metric cardinality ingested per day`.
</Callout>
