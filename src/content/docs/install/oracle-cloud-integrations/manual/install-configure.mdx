This page walks you through connecting your OCI account to New Relic by configuring OCI resources yourself in the OCI console. Use this path if you can't use the Oracle Resource Manager template and don't want to use Terraform.

<Callout variant="tip" title="Looking for a different install path?">

## Compatibility and requirements [#requirements]

### Supported
- OCI tenancies with an Identity and Access Management (IAM) domain

### Not supported
- _None._

### You need
- A New Relic account with [infrastructure monitoring permissions](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions/#infrastructure)
- A valid New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) and [user key](/docs/apis/intro-apis/new-relic-api-keys/#user-api-key)
- Your OCI `IAM_DOMAIN_URL` and the client credential for `newrelic-token-exchange-app`, obtained by completing [Set up Workload Identity Federation](/install/oracle-cloud-integrations/workload-identity-federation)

## Set up your OCI account access [#oci-account-setup]

### Create a compartment
Create a dedicated compartment to organize New Relic integration resources and implement proper access controls.

1. Create a compartment.
2. Add name as `newrelic-compartment`.

For more information, see Oracle's [create compartment documentation](https://docs.oracle.com/en-us/iaas/compute-cloud-at-customer/topics/compute/create-a-compartment.htm).

### Create a dynamic group
Dynamic groups let you securely access your OCI resources and their metrics without requiring static user credentials.

1. Create a dynamic group.
2. Add a matching rule.
3. Add these rules to dynamically include resources for New Relic to monitor:
   ```
   resource.type = 'serviceconnector'
   resource.type = 'fnfunc'
   ```

For more information, see Oracle's [create dynamic group documentation](https://docs.oracle.com/en-us/iaas/Content/Identity/dynamicgroups/To_create_a_dynamic_group.htm).

### Create a policy
This policy grants the permissions needed to collect metrics, logs, or both from your OCI resources and forward them to New Relic, based on the data type you select on the New Relic UI.

1. Create a policy. For more information, see the [OCI policies documentation](https://docs.oracle.com/iaas/Content/Identity/policiesgs/get-started-with-policies.htm).
2. Use the manual editor to enter the required policy statements, then save the policy configuration.

```
# Metrics policy statement

Allow dynamic-group your_dynamic_group_name to use fn-function in tenancy
Allow dynamic-group your_dynamic_group_name to use fn-invocation in tenancy
Allow dynamic-group your_dynamic_group_name to read secret-bundles in tenancy
Allow dynamic-group your_dynamic_group_name to read metrics in tenancy
```
```
# Logs policy statement

Allow dynamic-group your_dynamic_group_name to use fn-function in tenancy
Allow dynamic-group your_dynamic_group_name to use fn-invocation in tenancy
Allow dynamic-group your_dynamic_group_name to read secret-bundles in tenancy
Allow dynamic-group your_dynamic_group_name to read log-content in tenancy
```
```
# Metrics and logs policy statement

Allow dynamic-group your_dynamic_group_name to use fn-function in tenancy
Allow dynamic-group your_dynamic_group_name to use fn-invocation in tenancy
Allow dynamic-group your_dynamic_group_name to read secret-bundles in tenancy
Allow dynamic-group your_dynamic_group_name to read metrics in tenancy
Allow dynamic-group your_dynamic_group_name to read log-content in tenancy
```

## Set up a Key Vault secret [#key-vault]

Create a key vault to securely store your New Relic license key and user key for authentication. See [Key Vault setup procedure](#key-vault-procedure) below for the detailed steps.

## Set up a network [#network]

Create the network infrastructure that supports the deployment of functions and service connector hubs, with secure connectivity.

1. Navigate to the networking service and locate the Virtual Cloud Networks option.
2. Use the VCN creation wizard to create a VCN with internet connectivity.
3. Name the VCN using the pattern `newrelic-{region}-vcn`, where `{region}` is your deployment region.
4. Select the `newrelic-compartment` you created earlier.
5. Choose a CIDR block for the VCN, for example `10.0.0.0/16`.
6. Configure CIDR blocks for public and private subnets, for example `10.0.0.0/24` for private and `10.0.1.0/24` for public subnets.
7. Verify all configuration details and create the VCN.

For more information, see Oracle's [Create VCN](https://docs.oracle.com/en-us/iaas/Content/Network/Tasks/create_vcn.htm) and [Create Subnet](https://docs.oracle.com/en-us/iaas/Content/Network/Tasks/create_subnet.htm) documentation.

## Set up functions [#functions]

Create the serverless applications and functions that process metrics and logs before forwarding them to New Relic. See [Function setup for metrics](#fun-setup-proc-met) and [Function setup for logs](#fun-setup-proc-log) below for the detailed steps.

## Set up service connectors [#service-connectors]

### Set up a metrics service connector
Forwards OCI metrics to New Relic for monitoring and analysis.

1. Create a Service Connector Hub with appropriate naming conventions.
2. Configure monitoring as the source to collect metrics from specified compartments and namespaces.
3. Set the target as the New Relic function you created earlier.
4. Apply region-specific settings for multi-region deployments if required.

For more information, see Oracle's [Connector Hub documentation](https://docs.oracle.com/en-us/iaas/Content/service-connector-hub/overview.htm).

### Set up a logs service connector
Forwards OCI logs to New Relic for monitoring and analysis.

1. Create a Service Connector with an appropriate name and description.
2. Configure the source to specify the origin of data.
3. Configure the target to route data to the New Relic platform.

For more information, see Oracle's [Connector Hub documentation](https://docs.oracle.com/en-us/iaas/Content/service-connector-hub/overview.htm).

## Set up Workload Identity Federation [#wif]

**At a glance:**
- New Relic authenticates to OCI using Workload Identity Federation (WIF) — a trust relationship between New Relic and your OCI IAM domain.
- Requires creating two OCI Identity Domain applications, a dedicated service user and group, IAM policies, and an identity propagation trust.

For the full setup, see [Set up Workload Identity Federation](/install/oracle-cloud-integrations/workload-identity-federation).

## Install [#install]

1. [#install-step-1] Return to New Relic and click **Continue** to finalize the integration.
2. [#install-step-2] Click **See your data** to view the integration dashboard.
3. [#install-step-3] Click **Add instrumentation** to access the containers in your tenancy. This displays all available namespaces and log groups within the container that are currently uninstrumented.
4. [#install-step-4] Select the specific logs, metrics, and monitoring region based on your requirements.
5. [#install-step-5] Click **Deploy to OCI** to apply the monitoring configuration, then wait for the deployment to complete.

   *To instrument additional log groups or namespaces later, return to the OCI page in New Relic and repeat this step.*

## Verify your install [#verify]

Within a few minutes of completing the deployment, you should see:

- Your OCI account listed at <DNT>**one.newrelic.com → Infrastructure → OCI**</DNT>
- Metrics and/or log data flowing in for the namespaces and log groups you selected

If you don't see data after a few minutes, see [Troubleshooting](/install/oracle-cloud-integrations/workload-identity-federation#troubleshooting).

## Detailed procedures [#detailed-procedures]

The following sections provide step-by-step instructions for the manual configuration tasks referenced above.

### Key Vault setup procedure [#key-vault-procedure]

Complete these steps to create a key vault and store your New Relic API keys securely.

#### Create a key vault

1. In the OCI console, locate and access the **Key Management and Vault services**.
2. Create a new vault with the following configuration:
   * **Compartment**: Select the `newrelic-compartment`
   * **Name**: Enter a descriptive name for your vault (for example, `newrelic-vault`)
   * **Vault type**: Choose standard vault or virtual private vault based on your security requirements
3. Save the vault configuration.

#### Create a master encryption key

1. Access the newly created vault and navigate to the **encryption keys** section.
2. Create a new master key with these specifications:
   * **Name**: Enter a descriptive name (for example, `newrelic-encryption-key`)
   * **Algorithm**: Select **AES**
   * **Key length**: Set to **256 bits**
3. Save the key configuration.

#### Create secrets for API keys [#secapikeys]

1. Within your vault, navigate to the **secrets management** section.
2. Create a secret for your New Relic ingest license key:
   * **Compartment**: Select your designated compartment
   * **Name**: Use a descriptive name (for example, `newrelic-ingest-key`)
   * **Description**: Add a brief description of the secret's purpose
   * **Encryption key**: Select the master key created in the previous step
   * **Secret content**: Choose manual generation and paste your New Relic ingest license key
   * **Optional settings**: Configure cross-region replication and rotation as needed
3. Save the secret configuration.
4. Repeat the process to create a second secret for your New Relic user key:
   * Use a different name (for example, `newrelic-user-key`)
   * Paste your New Relic user key as the secret content

For detailed procedures, see Oracle's [OCI Key Management documentation](https://docs.oracle.com/en-us/iaas/Content/KeyManagement/Concepts/keyoverview.htm).

### Function setup for metrics [#fun-setup-proc-met]

Complete these steps to create a serverless application and deploy the New Relic function for data processing.

**Create a serverless application**

1. Access the **Functions** service under **Developer Services** in the OCI console.
2. Create a new application with the following configuration:
   * **Name**: Enter a descriptive name (for example, `NewRelicMetricsApp`)
   * **Compartment**: Select your designated New Relic compartment
   * **VCN**: Choose the VCN created for New Relic integration
   * **Subnet**: Select the private subnet for secure connectivity
   * **Shape**: Choose the appropriate compute shape based on your Docker image architecture (ARM or x86)

**Configure environment variables**

1. Within your application settings, add the following configuration variables:
   * **FORWARD_TO_NR**: Set to `True` to enable data forwarding to New Relic
   * **LOGGING_ENABLED**: Set to `False` to disable verbose logging (optional)
   * **NR_METRIC_ENDPOINT**: Specify the New Relic endpoint:
     * Use `newrelic-metric-api` for US accounts
     * Use `newrelic-eu-metric-api` for EU accounts
     * Use `newrelic-jp-metric-api` for JP accounts
   * **VAULT_REGION**: Set to the region where your Key Vault was created
   * **SECRET_OCID**: Provide the OCID of your New Relic ingest secret from Key Vault
   * **TENANCY_OCID**: Enter your OCI tenancy OCID
2. Save the configuration variables.

**Create and deploy the function**

1. Within your application, create a new function with these specifications:
   * **Function name**: Use a descriptive name (for example, `newrelic-metrics-function`)
   * **Image source**: Use the New Relic Docker image from Container Registry
   * **Memory allocation**: Configure appropriate memory (for example, 256 MB)
2. For Docker image deployment, use Container Registry authentication:
   * Authenticate with your regional Container Registry endpoint
   * Pull the New Relic Docker image: `{region}.ocir.io/axcvnhglb9ao/public-newrelic-repo:latest`
   * Tag and push the image to your namespace if required
   * Reference the image in your function configuration
3. Complete the function creation and deployment process.

For detailed procedure, see Oracle's [OCI Functions documentation](https://docs.oracle.com/en-us/iaas/Content/Functions/Concepts/functionsoverview.htm).

### Function setup for logs [#fun-setup-proc-log]

Complete these steps to create a serverless application and deploy the New Relic function for log processing.

**Create a serverless application for logging**

1. Access the **Functions** service under **Developer Services** in the OCI console.
2. Create a new application with the following configuration:
   * **Name**: Enter a descriptive name (for example, `newrelic-logging-function-app`)
   * **Compartment**: Select your designated New Relic compartment
   * **VCN**: Choose the VCN created for New Relic integration
   * **Shape**: Select `GENERIC_X86` for the application shape
3. Save the application configuration.

**Configure environment variables for logging**

1. Within your application settings, navigate to the configuration section and add the following variables:
   * **VAULT_REGION**: Set to the region where your Key Vault was created
   * **DEBUG_ENABLED**: Set to `false` for production use (or `true` for debugging)
   * **NEW_RELIC_REGION**: Specify your New Relic region (`US`, `EU`, or `JP`)
   * **SECRET_OCID**: Provide the OCID of your New Relic license key secret from Key Vault
   * **CLIENT_TTL**: Set to `30` seconds for license key refresh interval
2. Save the configuration variables.

**Deploy the logging function**

1. Prepare the New Relic logging Docker image:
   * Authenticate with your regional Container Registry endpoint
   * Pull the New Relic logging image from the public repository
   * Tag and push the image to your namespace if required
2. Create a new function within your application:
   * **Function name**: Use a descriptive name (for example, `newrelic-logging-function`)
   * **Image source**: Use the New Relic logging Docker image from Container Registry
   * **Memory allocation**: Configure at least 128 MB
   * **Timeout**: Set to 300 seconds for adequate processing time
3. Complete the function creation and deployment process.

**(Optional) Enable function logging**

1. Access the monitoring settings for your function application.
2. Enable function invocation logs by:
   * Selecting or creating an appropriate log group
   * Configuring log retention and access policies
   * Activating log collection for the function

For detailed procedure, see Oracle's [OCI Functions documentation](https://docs.oracle.com/en-us/iaas/Content/Functions/Concepts/functionsoverview.htm).
