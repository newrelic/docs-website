Failed AJAX and fetch calls, like a broken third-party integration or a backend API returning a 500, often cause broken pages and confusing user experiences. The <DNT>**Request errors**</DNT> page groups these failed requests so you can find the API calls behind broken pages, see how often they're failing, and know where to start debugging.

Request errors is built on the [`AjaxRequest`](/attribute-dictionary/?event=AjaxRequest) events your Browser agent already collects, so there's nothing to install or turn on to start using it.

## View the request errors page [#request-errors-page]

To view the request errors page, go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Browser > (select an app) > Request errors**</DNT>.

## Recommended workflow [#suggested-workflow]

We recommend the following approach to investigate request errors, so you can understand the error, identify contributing factors, and start debugging:

1. **See overall trends**: Start with the <DNT>**Error count**</DNT> and <DNT>**Errors by page**</DNT> charts to see at a glance whether there are any unexpected spikes, dips, or patterns.
2. **Group and filter**: Use the <DNT>**Group by**</DNT> and filter options to focus on specific request domains, request paths, response codes, or code ranges.
3. **Drill down into a single error**: Select a row in the request error table to view the full request details, including the request URL, response code, response body, and more.
4. **Review session replays and the event trail**: From a specific error, review the [event trail](#event-trail) and, where available, the [session replay](#session-replay) recorded during that occurrence.
5. **Query and share the data**: On any chart, select the <DNT>**…**</DNT> menu and then <DNT>**View query**</DNT> to explore the underlying `AjaxRequest` data in the query builder, or add it to a dashboard.
6. **Change the time window**: Select a new time period from the time picker dropdown.

## Group request errors tab [#group-errors]

On the <DNT>**Request errors**</DNT> tab you can:

* **Assess overall trends**: The <DNT>**Error count**</DNT> chart shows your top request errors over time, by request URL, response code, and response body. The <DNT>**Errors by page**</DNT> chart shows which pages are most affected.
* **Group and filter for deeper analysis**: By default, errors are grouped by request URL and response code. You can change the grouping, and filter by error type, response code, or a response code range (for example, `httpResponseCode >= 400`).
* **Identify patterns**: The request error table lists each group's request URL, response code, response body, occurrence count, and when it was first and last seen.

## Request error details [#error-details]

Select a row in the request error table to open the request details as a stacked panel, showing the full request information, request attributes, and response body for that error.

### Profiles [#error-profiles]

From the request error table, select <DNT>**View profiles**</DNT> to see which attributes most distinguish this group of request errors from your other traffic. Use profiles to quickly spot what the affected requests have in common.

### Event trail [#event-trail]

When you select a specific error, the event trail shows the browser interactions and AJAX calls that led up to it. This helps you understand what the user was doing when the request failed, and whether other calls around the same time were also affected.

### Session replay [#session-replay]

Where a session replay was recorded for the occurrence you're viewing, you can open it from the error details to see exactly what the user experienced when the request failed.

## Query and visualize request error data [#insights]

New Relic saves request error data as `AjaxRequest` events. Query the `AjaxRequest` event type in the [query builder](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder) to run NRQL queries and build dashboards from your request error data.
