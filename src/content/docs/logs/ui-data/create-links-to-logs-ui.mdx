You can build a URL that opens the [logs UI](/docs/logs/ui-data/use-logs-ui/) with an account, a search query, and a time range already set. Use these links in places where someone needs to jump straight to the right logs, such as:

* CI/CD pipeline output that links to the logs from a specific test run or deployment
* Runbooks and alert annotations that link to the logs for a failing service
* Internal tools and dashboards that link out to New Relic

You write the URL yourself or generate it in code. The URL doesn't need an encoded JSON payload.

## URL format [#format]

Use one of these formats. The first uses a time range relative to now. The second uses a fixed start and end time:

```
https://one.newrelic.com/logger/search?account=<ACCOUNT_ID>&duration=<MILLISECONDS>&luceneQuery=<URL_ENCODED_QUERY>
https://one.newrelic.com/logger/search?account=<ACCOUNT_ID>&begin=<EPOCH_MILLISECONDS>&end=<EPOCH_MILLISECONDS>&luceneQuery=<URL_ENCODED_QUERY>
```

If your account is in the EU region data center, use `one.eu.newrelic.com`. If it's in the JP region data center, use `one.jp.newrelic.com`. For more information, see [our EU and US region data centers](/docs/using-new-relic/welcome-new-relic/get-started/our-eu-us-region-data-centers/).

The `account` parameter is required. Include `luceneQuery` in every link too.

<Callout variant="important">
  If a link doesn't include `luceneQuery`, the logs UI might open with the search from a recent logs session in the same browser instead of an empty search. To open with an empty search, include an empty value: `luceneQuery=`.
</Callout>

## Examples [#examples]

Errors for the `checkout` service in the last hour:

```
https://one.newrelic.com/logger/search?account=1234567&duration=3600000&luceneQuery=service.name%3Acheckout%20level%3AERROR
```

The logs from a CI run, between two timestamps:

```
https://one.newrelic.com/logger/search?account=1234567&begin=1792519160000&end=1792520960000&luceneQuery=test_run%3A%22deeplink-test-1790962028%22
```

## Encode the query [#encode]

Always URL-encode the `luceneQuery` value. Lucene queries contain characters that have a special meaning in a URL, so an unencoded query can open the wrong search without any error.

<table>
  <thead>
    <tr>
      <th style={{ width: "200px" }}>
        If you don't encode...
      </th>

      <th>
        What happens
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        `&`
      </td>

      <td>
        The `&` ends the parameter. `message:"a & b"` arrives as `message:"a ` and the rest becomes a separate parameter.
      </td>
    </tr>

    <tr>
      <td>
        `#`
      </td>

      <td>
        The `#` starts the URL fragment, and everything after it is dropped. `message:"ticket #42"` arrives as `message:"ticket `.
      </td>
    </tr>

    <tr>
      <td>
        `+`
      </td>

      <td>
        The `+` is read as a space. `+level:ERROR` arrives as ` level:ERROR`, so the `+` is lost.
      </td>
    </tr>

    <tr>
      <td>
        `%`
      </td>

      <td>
        The `%` starts an escape sequence. Encode a literal percent sign as `%25`.
      </td>
    </tr>
  </tbody>
</table>

Two more mistakes to avoid:

* Don't use JavaScript's `encodeURI()`. It leaves `&`, `#`, and `+` unencoded. Use `encodeURIComponent()` or a URL builder instead.
* Don't encode the query twice. If you encode a value and then pass it to a URL builder that also encodes, the search bar shows `level%3AERROR` instead of `level:ERROR`.

The simplest approach is to use your language's URL builder, and to pass it the query exactly as you'd type it in the logs search bar. You can encode a space as either `+` or `%20`.

The following examples all produce a correctly encoded link for this query, which includes quotes, a backslash, and non-ASCII characters:

```
+level:ERROR message:"a \"quoted\" b & c #1 100%" url:"https://x.io/?a=1&b=2" path:C\\Windows naïve 日本語
```

    ```js
    const url = new URL('https://one.newrelic.com/logger/search');

    console.log(url.toString());
    ```

    Or, in a template string, encode only the query value:

    ```js
    const link = `https://one.newrelic.com/logger/search?account=1234567&duration=3600000&luceneQuery=${encodeURIComponent(query)}`;
    ```


## What happens when someone opens a link [#behavior]

* The logs UI opens on the **All logs** view with the account, time range, and query from the link. It starts a new session, so it doesn't reuse partitions, parsing rules, or columns from another logs tab.
* The logs UI searches the default `Log` partition.
* The query from the link is applied once. After it loads, the logs UI adds a `state` parameter to the URL, and any changes you make to the search are kept if you reload the page or copy the URL. If you change the `luceneQuery` value in the URL itself, the logs UI applies the new value.
* If the query isn't valid, the search bar shows it exactly as written, with a message that the query isn't valid, as if you had typed it.

## Limits [#limits]

Keep these limits in mind when you build links:

* Links accept a Lucene query. They don't accept an NRQL query.
* Links set the account, time range, and search query only. They can't select a view, attributes, or facets.
* The parameter for the query is `luceneQuery`. A parameter named `query` is ignored.
