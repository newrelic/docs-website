Use the `workflowAutomationCreateSchedule` mutation to create a schedule for a workflow definition.

<Callout variant="tip">
The number of schedules and the minimum duration for a given schedule are defined at [Workflow System Limits](/docs/workflow-automation/limitations-and-faq/workflow-limits).
</Callout>

## Input parameters [#input-parameters]

The following parameters are available for this API.

<table>
  <thead>
    <tr>
      <th style={{ width: "200px" }}>Parameter</th>
      <th>Data type</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`scope`</td>
      <td>Object</td>
      <td>(Required) The account scope. Contains `id` (your account ID) and `type` (ACCOUNT).</td>
    </tr>
    <tr>
      <td>`definition`</td>
      <td>Object</td>
      <td>(Required) The workflow definition to schedule. Contains `name` (workflow name) and `version` (workflow version).</td>
    </tr>
    <tr>
      <td>`cronExpression`</td>
      <td>String</td>
      <td>(Required) Cron expression defining the schedule frequency (e.g., `"0 0 * * *"` for daily at midnight).</td>
    </tr>
    <tr>
      <td>`timezone`</td>
      <td>String</td>
      <td>(Required) Timezone for the schedule (e.g., `"Asia/Kolkata"`, `"America/New_York"`).</td>
    </tr>
    <tr>
      <td>`options`</td>
      <td>Object</td>
      <td>(Optional) Optional configuration. Contains `logLevel` for controlling execution logging.</td>
    </tr>
    <tr>
      <td>`tags`</td>
      <td>[EntityTagInput]</td>
      <td>(Optional) Tags to apply to the schedule. Each tag requires a `key` (String) and `values` ([String]).</td>
    </tr>
  </tbody>
</table>

### logLevel option [#loglevel-option]

The `logLevel` option controls the amount of logging information generated during workflow execution.

- `NONE` (default): Generates no log output.
- `INFO`: Outputs step-level information.
- `DEBUG`: Adds an attribute to the step started logs with all the action step inputs, using the format `workflowAutomation.inputs.<inputName>: <inputValue>`.
- `TRACE`: In addition to `DEBUG` output, adds an attribute to the step started logs with all the action step outputs, using the format `workflowAutomation.outputs.<outputName>: <outputValue>`.

## Sample request [#sample-request]

Use the [Query Builder](https://one.newrelic.com/nerdgraph-graphiql?state=b8f3b3a9-8d3e-c03e-5da4-34b98a57ff8f) to create and edit a workflow. See [NerdGraph API explorer](/docs/apis/nerdgraph/get-started/nerdgraph-explorer).

```graphql
  mutation {
    workflowAutomationCreateSchedule(
      scope: {id: "12345678", type: ACCOUNT}
      definition: {name: "healthyHeartbeat", version: 1}
      cronExpression: "0 0 * * *"
      timezone: "Asia/Kolkata"
      options: {logLevel: DEBUG}
      tags: [{key: "environment", values: ["production"]}]
    ) {
      scheduleId
    }
  }
```
