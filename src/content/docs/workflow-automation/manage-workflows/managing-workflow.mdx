The [Workflow Automation dashboard](https://onenr.io/0gR7XE8LXjo) provides a central location to view, manage, and monitor all workflows in your account. Use the dashboard to edit configurations, track version history, manage execution schedules, and troubleshoot failures. To manage workflows, you need at least one workflow in your account and edit and delete permissions.

<Callout variant="important">
  **Disabling Workflow Automation?** If you plan to turn off Workflow Automation through Feature Control Management (FCM), ensure all scheduled workflows are removed first. See [Disabling Workflow Automation](/docs/workflow-automation/troubleshooting#disabling-workflow-automation-fcm) for detailed steps.
</Callout>

**New to workflows?** Start with [Use a template](/docs/workflow-automation/create-a-workflow-automation/use-a-template) or [Create your own workflow](/docs/workflow-automation/create-a-workflow-automation/create-your-own) to build your first workflow.

## View workflows [#view-workflows]

Go to <DNT>**All Capabilities > Workflow Automation**</DNT>. If your account has no workflows, the dashboard displays an empty state with options to create your first workflow.

### Dashboard tabs

Once you create workflows, the dashboard displays two tabs:

<DNT>**Summary tab**</DNT> (default):
Displays account-level metrics and visualizations:

<DNT>**Top metrics**</DNT>:
  - <DNT>**Total workflows**</DNT>: Count of all workflows in your account
  - <DNT>**Total number of steps executed**</DNT>: Cumulative step count across all workflow runs
  - <DNT>**Currently running workflows**</DNT>: Number of active executions

<DNT>**Performance charts**</DNT>:
  - <DNT>**Total run count of all workflows**</DNT>: Line chart showing workflow execution trends over time
  - <DNT>**Top 5 most frequently run workflows**</DNT>: Bar chart displaying the workflows with the highest execution counts
  - <DNT>**Ratio of completed to failed workflows**</DNT>: Pie chart showing success vs. failure percentages and counts

<DNT>**Recently failed runs table**</DNT>:
Displays failed workflow executions with these columns:
  - <DNT>**Workflow**</DNT>: Name of the failed workflow
  - <DNT>**Version**</DNT>: Workflow version that failed
  - <DNT>**Failed on**</DNT>: Timestamp of the failure
  - <DNT>**Run ID**</DNT>: Unique identifier for the failed run
  - <DNT>**Failed step**</DNT>: Step where the failure occurred
  - <DNT>**Error message**</DNT>: Description of the error

Each chart widget includes a context menu (three dots) to view query, get image, or create alert condition.

<DNT>**Workflows tab**</DNT>:

<DNT>**Search**</DNT>: Use the <DNT>**Search in all fields**</DNT> bar to find workflows by any column value.

<DNT>**All workflows table**</DNT> displays these columns:

  - <DNT>**Favorite**</DNT> (star icon): Mark workflows as favorites
  - <DNT>**Name**</DNT>: Workflow identifier
  - <DNT>**Description**</DNT>: Purpose or function of the workflow
  - <DNT>**Last run on**</DNT>: Timestamp of most recent execution
  - <DNT>**Last run status**</DNT>: Execution result (displayed as colored badges: green for Completed, red for Failed)
  - <DNT>**Latest version**</DNT>: Current version number
  - <DNT>**Created on**</DNT>: Date when workflow was created
  - <DNT>**Actions menu**</DNT> (three dots): Access workflow operations

Empty values in the table display as `—`

<DNT>**Row actions menu**</DNT> (click three dots next to workflow):
  - <DNT>**Run**</DNT>: Execute the workflow immediately
  - <DNT>**Schedule**</DNT>: Create a scheduled run
  - <DNT>**Open in editor**</DNT>: Modify workflow configuration
  - <DNT>**Duplicate**</DNT>: Create a copy of the workflow
  - <DNT>**Delete**</DNT>: Remove the workflow permanently

Click a workflow name to view its [Entity Overview page](/docs/workflow-automation/manage-workflows/workflow-entity-overview) with detailed metrics, run history, schedules, and logs.

## Edit a workflow [#edit-a-workflow]

Update workflow name, description, or configuration.

1. Locate the workflow you want to edit
2. Click the ellipsis (three vertical dots) next to the workflow name
3. Select <DNT>**Open in editor**</DNT>
4. Update any of these:
   - <DNT>**Name**</DNT> — The workflow identifier
   - <DNT>**Description**</DNT> — Workflow purpose or function
   - <DNT>**Configuration**</DNT> — Input parameters, actions, or logic
5. Click <DNT>**Save**</DNT>

You can also access the editor from the [Entity Overview page](/docs/workflow-automation/manage-workflows/workflow-entity-overview) by clicking the <DNT>**Edit**</DNT> button.

## Manage versions [#manage-versions]

Workflow automation automatically creates a new version every time you update a workflow definition. All previous versions remain available for reference and can be viewed or run directly from the editor.

### View version history in the editor [#view-version-history]

You can browse all previous versions of a workflow without leaving the editor.

1. Open a workflow in the editor
2. Click the <DNT>**version dropdown**</DNT> in the editor toolbar
3. Select any previous version from the list

The selected version opens in a <DNT>**read-only preview**</DNT> within the editor. You can review the configuration and run it, but you can't edit it directly.

### Create a new version from a previous version [#edit-as-new-version]

If you want to use a previous version as the basis for a new edit:

1. Open the workflow in the editor and select a previous version from the version dropdown
2. Click <DNT>**Edit as new version**</DNT>
3. Make your changes
4. Click <DNT>**Save**</DNT>

The system creates a new version numbered as the current highest version + 1. For example, if v5 is the latest and you edit v2, the result is v6. The previous version is not overwritten.

If you change your mind, click <DNT>**Cancel**</DNT> to discard the in-progress edit. No new version is saved, and you return to the workflow list.

### Compare versions [#compare-versions]

A version comparison view is available in the editor. Use it to inspect differences between any two versions of a workflow before deciding which one to run or build from.

### Version pinning for scheduling

When you schedule a workflow, you must pin it to a specific version. That pinned version runs even if you later update the workflow definition.

**Start and schedule workflows support version pinning:**
  - When scheduling a workflow, specify which version to run
  - When manually starting a workflow run, select which version to execute
  - When you update a schedule, specify the new version to use

This allows you to:
  - Update workflows without affecting running schedules
  - Test new versions manually before updating schedules
  - Maintain stability for production workflows

## Duplicate a workflow [#duplicate-a-workflow]

Duplicate workflows when you need to adapt a template or existing workflow for a different purpose while keeping the original intact.

1. Locate the workflow you want to duplicate
2. Click the ellipsis (three vertical dots)
3. Select <DNT>**Duplicate**</DNT>
4. The system creates a copy with **(Copy)** appended to the name
5. Rename and customize the duplicated workflow for your needs

**Common duplication scenarios:**
  - Adapting a workflow template for your specific use case
  - Creating a workflow for a different team with similar requirements
  - Experimenting with significant changes while preserving the original

<Callout variant="important">
  **Don't duplicate workflows for version control** — the system does this automatically. Duplicating workflows only for version control or rollback purposes can cause you to hit workflow limits. See [Manage versions](#manage-versions) for information about automatic versioning.
</Callout>

## Delete a workflow [#delete-a-workflow]

Remove workflows you no longer need.

1. Locate the workflow you want to delete
2. Click the more options menu (three vertical dots)
3. Select <DNT>**Delete**</DNT>
4. Confirm the deletion in the dialog box

<Callout variant="caution">
  Deleting a workflow is permanent. You can't undo it. We remove all versions and execution history. If you might need the workflow later, consider deactivating it instead of deleting it.
</Callout>

**What gets deleted:**
  - All versions of the workflow
  - All execution history and logs
  - All scheduled runs associated with the workflow

**Before deleting, verify:**
  - No critical automations depend on this workflow
  - You have a backup copy if you might need it later
  - Identify and account for all scheduled runs
