This page provides a reference for New Relic Synthetics actions available in the workflow automation actions catalog. These actions let you trigger on-demand test runs for existing monitors, manage maintenance window downtimes, and read monitor details directly from a workflow definition.

## Prerequisites

Before using New Relic Synthetics actions in workflow automation, ensure you have:

* A New Relic account with appropriate permissions to access Synthetics monitors.
* The entity GUID of each monitor you want to target. You can find a monitor's GUID in New Relic under **Synthetics > [monitor name] > Settings**.

## Start an automated test [#start-automated-test]

The action identifier is `newrelic.synthetics.startAutomatedTest`.

Triggers an on-demand Synthetics automated test run for one or more monitors and returns a `batchId` to poll for results using `newrelic.synthetics.getAutomatedTestResult`.

<Callout variant="important">
  Only scripted API, scripted browser, step, and simple browser monitor types are supported. SIMPLE (ping) monitors are rejected by the API with an incompatible monitor type error.
</Callout>

## Create a monitor downtime [#create-monitor-downtime]

The action identifier is `newrelic.synthetics.createMonitorDowntime`.

Schedules a one-time Synthetics monitor downtime (maintenance window) for one or more specific monitors. The API echoes back a resolved timezone label (such as `Pacific Standard Time`) rather than the submitted IANA name.

<Callout variant="important">
  `monitorGuids` is nullable in the GraphQL schema but required in practice — omitting it throws a server error. There is no account-wide downtime mode; downtimes always target specific monitors.
</Callout>

## Edit a monitor downtime [#edit-monitor-downtime]
