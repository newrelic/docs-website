This page provides a comprehensive reference for New Relic notification actions available in the Workflow Automation actions catalog. These actions enable you to send notifications through New Relic.

## Prerequisites

Before using New Relic actions in workflow automation, ensure you have:

  * A New Relic account with appropriate permissions.
  * A New Relic license key (if sending data to a different account).
  * The necessary permissions for the specific New Relic services you plan to use.

See [License Key](/docs/apis/intro-apis/new-relic-api-keys#license-key) for information on how to create and manage your New Relic Account License Key.

    <Collapser
        id="newrelic.notification.createSignalUrl"
        title="Create a signal URL"
    >
  Generates a URL that can be sent to a user's <DNT>Microsoft Teams</DNT>, <DNT>Slack</DNT>, or <DNT>email</DNT> so they can send a signal to a running workflow. This action powers the [human-in-the-loop pattern](/docs/workflow-automation/workflow-examples/advanced/human-in-the-loop), where a workflow pauses at a wait step until a person clicks the URL to approve, deny, or otherwise route the run.

  <Callout variant="important">
    This action provides no benefit on its own. It must always be paired with:

      * A **notification action** (`newrelic.notification.*` or `slack.chat.postMessage`) that delivers the generated URL to a person.
      * A **wait step** that defines at least one signal for the workflow run to wait on.

    The `waitStepName` you provide as input must match the name of a valid wait step in the same workflow definition, and that wait step must contain at least one signal. Otherwise the workflow definition fails validation when you create it.
  </Callout>
