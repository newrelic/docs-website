Updates an existing issue in a GitHub repository (title, body, state, assignees, labels, and milestone).

For authentication setup, see [GitHub issue actions](/docs/workflow-automation/setup-and-configure/actions-catalog/github/github-issue).

  The following inputs are available for this action.

  <table>
      <thead>
          <tr>
            <th>Input Field</th>
            <th>Optionality</th>
            <th>Type</th>
            <th>Description</th>
            <th>Example</th>
          </tr>
      </thead>
      <tbody>
          <tr>
              <td>**token**</td>
              <td>Required</td>
              <td>String</td>
              <td>GitHub Personal Access Token (fine-grained or classic) stored as a secret. Fine-grained PATs require Issues: Read and write permission. Classic PATs require repo scope.</td>
              <td>`"${{ :secrets:github-PAT-token }}"`</td>
          </tr>
          <tr>
              <td>**owner**</td>
              <td>Required</td>
              <td>String</td>
              <td>The account owner of the repository (user or organization login). Case-insensitive.</td>
              <td>`"octocat"`</td>
          </tr>
          <tr>
              <td>**repo**</td>
              <td>Required</td>
              <td>String</td>
              <td>Repository name without the .git suffix. Case-insensitive.</td>
              <td>`"Hello-World"`</td>
          </tr>
          <tr>
              <td>**issueNumber**</td>
              <td>Required</td>
              <td>Int</td>
              <td>The number that identifies the issue.</td>
              <td>`1347`</td>
          </tr>
          <tr>
              <td>**title**</td>
              <td>Optional</td>
              <td>String</td>
              <td>The title of the issue.</td>
              <td>`"Updated issue title"`</td>
          </tr>
          <tr>
              <td>**body**</td>
              <td>Optional</td>
              <td>String</td>
              <td>Issue body in GitHub-flavored Markdown. Omitted from the request if empty.</td>
              <td>`"Updated description."`</td>
          </tr>
          <tr>
              <td>**state**</td>
              <td>Optional</td>
              <td>String</td>
              <td>Issue state. Use to close or reopen an issue. Allowed values: `open`, `closed`.</td>
              <td>`"closed"`</td>
          </tr>
          <tr>
              <td>**state_reason**</td>
              <td>Optional</td>
              <td>String</td>
              <td>The reason for the state change. The API ignores this field unless you change `state`. Allowed values: `completed`, `not_planned`, `duplicate`, `reopened`, `null`.</td>
              <td>`"completed"`</td>
          </tr>
          <tr>
              <td>**duplicate_issue_id**</td>
              <td>Optional</td>
              <td>Int</td>
              <td>The ID of the issue to mark as the canonical duplicate. Only used when `state_reason` is `duplicate`. The issue must exist and be accessible to the authenticated user.</td>
              <td>`1200`</td>
          </tr>
          <tr>
              <td>**assignees**</td>
              <td>Optional</td>
              <td>List</td>
              <td>GitHub usernames to assign. Requires push access on the token. The GitHub API silently drops users without push access.</td>
              <td>`["octocat"]`</td>
          </tr>
          <tr>
              <td>**labels**</td>
              <td>Optional</td>
              <td>List</td>
              <td>Labels to attach. Requires push access on the token. The API auto-creates unknown labels if you have permission. Otherwise, the API rejects them.</td>
              <td>`["resolved", "p1"]`</td>
          </tr>
          <tr>
              <td>**milestone**</td>
              <td>Optional</td>
              <td>Int</td>
              <td>The milestone number (integer ID, not the title). Requires push access on the token. The milestone must already exist in the repository.</td>
              <td>`3`</td>
          </tr>
          <tr>
              <td>**type**</td>
              <td>Optional</td>
              <td>String</td>
              <td>The name of the issue type to associate with this issue (for example, Bug, Task, Feature). Requires push access. Issue types must be configured at the repository or organization level before use.</td>
              <td>`"Bug"`</td>
          </tr>
          <tr>
              <td>**issueFieldValues**</td>
              <td>Optional</td>
              <td>List</td>
              <td>Issue field values for GitHub Projects v2 custom fields. Each object must include `field_id` (integer) and `value` (string, number, or array for multi-select fields). Only available for organization-owned repositories with GitHub Projects v2 custom fields enabled.</td>
              <td>`[{"field_id": 1, "value": "high"}]`</td>
          </tr>
          <tr>
              <td>**selectors**</td>
              <td>Optional</td>
              <td>List</td>
              <td>JQ selectors to extract values from the response.</td>
              <td>`[{"name": "issueState", "expression": ".state"}]`</td>
          </tr>
      </tbody>
  </table>

    </thead>
    <tbody>
        <tr>
            <td>
```yaml
name: github_update_issue_workflow
description: Update a GitHub issue
steps:
  - name: update_issue
    type: action
    action: gitHub.issue.update
    version: 1
    inputs:
      token: ${{ :secrets:github-PAT-token }}
      owner: your_user_name
      repo: test-workflow
      issueNumber: 7
      title: Issue has been resolved
      body: Investigation complete. Closing this issue.
      state: closed
      state_reason: completed
      labels:
        - resolved
    next: end
```
