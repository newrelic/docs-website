This page provides a reference for GitHub workflow run actions available in the workflow automation actions catalog. These actions let you trigger, retrieve, and list GitHub Actions workflow runs directly from a workflow definition, enabling automated CI/CD orchestration, deployment pipelines, and release automation without custom code or external tooling.

## Prerequisites

Before using GitHub workflow run actions in workflow automation, ensure you have:

* A GitHub account with access to the target repository.
* A GitHub Personal Access Token (PAT) with the required permissions.
* The PAT stored in the New Relic Secrets Service.
* The target workflow configured with a `workflow_dispatch` trigger (required for `gitHub.workflowRun.trigger`).

## Set up PAT authentication

GitHub workflow run actions authenticate using a Personal Access Token (PAT) passed as a Bearer credential. This action supports two token types:

* **Fine-grained PAT** — requires **Actions: write** permission for `gitHub.workflowRun.trigger`; **Actions: read** for `gitHub.workflowRun.get`, `gitHub.workflowRun.getLatest`, and `gitHub.workflowRun.list`.
* **Classic PAT** — requires the **repo** scope for all four actions.

<Steps>
  <Step>
    ### Create a GitHub Personal Access Token

    1. In GitHub, go to **Settings > Developer settings > Personal access tokens**.
    2. Choose **Fine-grained tokens** or **Tokens (classic)** and click **Generate new token**.
    3. Set the required permissions: **Actions: write** (or **Actions: read** for read-only actions) for fine-grained tokens, or **repo** scope for classic tokens.
    4. Copy the generated token — GitHub shows it only once.
  </Step>

  <Step>
    ### Store the token as a secret

    Store the token in the New Relic Secrets Service and reference it in your workflow YAML using the `${{ :secrets:keyName }}` syntax:

    ```yaml
    token: ${{ :secrets:github-PAT-token }}
    ```
  </Step>
</Steps>
