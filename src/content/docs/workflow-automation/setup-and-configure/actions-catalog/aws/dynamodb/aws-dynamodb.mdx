This page provides a reference for AWS DynamoDB actions available in the workflow automation actions catalog. Use these actions to read, write, update, and delete items in DynamoDB tables, and to inspect or modify table configuration directly from a workflow definition.

## Prerequisites

For prerequisites and credentials setup, see [Set up AWS credentials](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials).

All DynamoDB actions accept the same auth inputs. Use `awsRoleArn` (recommended) or the access key pair.

## Put an item [#put-item]

The action identifier is `aws.dynamodb.putItem`.

Creates a new item, or replaces an existing item, in a DynamoDB table. Uses the DynamoDB low-level [AttributeValue](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_AttributeValue.html) format for the `item` map.

**Example**

```yaml
name: put-dynamodb-item
description: Write an order item to DynamoDB
steps:
  - name: putOrderItem
    type: action
    action: aws.dynamodb.putItem
    version: '1'
    inputs:
      awsRoleArn: ${{ :secrets:awsRoleArn }}
      region: us-east-2
      tableName: Orders
      item:
        orderId: { "S": "123" }
        status: { "S": "PLACED" }
    next: end
```

## Scan a table [#scan]

The action identifier is `aws.dynamodb.scan`.

Returns items from a DynamoDB table or index by scanning the entire table, with optional filtering. A single scan response is limited to 100 KB by Workflow Automation (DynamoDB's own limit is 1 MB). Use `limit` and `exclusiveStartKey` to paginate through large tables.

<Callout variant="important">
  Workflow Automation enforces a 100 KB output size limit per action. `aws.dynamodb.scan` throws an output size limit exceeded exception when the response exceeds this limit, even though it may be within DynamoDB's own 1 MB per-response cap. Use `limit` and `exclusiveStartKey` to paginate results and stay within this limit.
</Callout>
