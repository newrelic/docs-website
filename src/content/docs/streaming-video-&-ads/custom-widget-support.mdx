Custom widgets let you extend the Media Streaming dashboard with bespoke chart visualizations built from your own NRQL queries. You can add custom widgets to both the <DNT>**Video quality metrics**</DNT> and <DNT>**Ad quality metrics**</DNT> dashboards. Custom widgets appear at the top of the quality metrics grid and are listed under a <DNT>**Custom Metrics**</DNT> category in the metric selector dropdown. They persist across sessions and scale within the existing dashboard layout.

<Callout variant="important">
  Each account supports a soft limit of **50 custom widgets per dashboard context** — 50 for Video quality metrics and 50 for Ad quality metrics, counted separately. If you reach the limit, delete an existing custom widget before adding a new one.
</Callout>

## Before you begin [#prereqs]

- You need access to a New Relic account with the Streaming Video & Ads agent installed. See [Install the Streaming Video & Ads agent](/docs/streaming-video-&-ads/installation/install-the-streaming-video-&-ads-agent) if you haven't set it up yet.
- Custom widgets require the `MEDIA_STREAMING_CUSTOM_WIDGETS` feature flag to be enabled on your account. If the <DNT>**+ Add Custom Widget**</DNT> button isn't visible in the Quality Metrics section, contact your New Relic account team.

## Create a custom widget [#create]

1. Open the Media Streaming dashboard and navigate to the <DNT>**Quality Metrics**</DNT> section.
2. Click <DNT>**+ Add Custom Widget**</DNT> in the top-right of the section header.
3. Enter a unique title for the widget. Duplicate titles within the same dashboard context are not allowed.
4. Select a chart type: Billboard, Line, Area, Bar, Table, or Pie. Chart type is a personal preference — it applies only to your view and is not shared with other users on the account.
5. Write your NRQL query in the NRQL editor. See [Write your NRQL query](#writing-queries) for guidance on syntax, filter placeholders, and examples.
6. Click <DNT>**Run Query**</DNT> to preview results before saving.
7. Click <DNT>**Save**</DNT>. The widget is added to the <DNT>**Custom Metrics**</DNT> section of the metric selector dropdown and rendered at the top of the quality metrics grid.

<Callout variant="tip">
  Widget configurations — title and NRQL query — are scoped based on context:
  - **All-platform view:** Widgets are account-scoped and shared with all users on the same account.
  - **Single-application view:** Widgets are entity-scoped and specific to that application.

  Chart type preference is always user-scoped and applies only to your own view.
</Callout>

## Write your NRQL query [#writing-queries]

The NRQL editor accepts any valid NRQL `SELECT` or `FROM` query. Syntax highlighting, autocomplete, and real-time validation are provided.

### Query requirements [#query-requirements]

- Queries must contain both `SELECT` and `FROM` clauses.
- Do not include a hardcoded `SINCE` or `UNTIL` clause. The dashboard time picker injects the time range automatically at execution time.
- To respond to dashboard-level filter bar selections, include a [filter placeholder](#placeholders) in your query.

### Filter placeholders [#placeholders]

The dashboard applies global filters at runtime. If you hardcode a plain `WHERE` clause, the dashboard can't inject user-selected filter conditions into it. Filter placeholders are NRQL comment tokens that get replaced at runtime with the active filter conditions.

| Placeholder | Replaced with | When to use |
|-------------|---------------|-------------|
| `/* {whereClause} */` | `WHERE [filters]` | Query has no existing `WHERE` clause |
| `/* {andWhereClause} */` | `AND [filters]` | Query already has a `WHERE` clause — appends filters to it |
| `/* {aggregatorWhereClause} */` | `, WHERE [filters]` | Inside a `filter()` aggregator with no existing inner `WHERE` clause; the `filter()` wrapper is removed when no filter is active |

**Example — no existing WHERE clause:**

```sql
SELECT count(*) FROM VideoAction /* {whereClause} */
```

With filter `City = Ashburn` applied:

```sql
SELECT count(*) FROM VideoAction WHERE city = 'Ashburn' SINCE 30 minutes ago UNTIL now
```

**Example — existing WHERE clause:**

```sql
SELECT count(*) FROM VideoAction
WHERE actionName = 'QOE_AGGREGATE' /* {andWhereClause} */
```

With filter `City = Ashburn` applied:

```sql
SELECT count(*) FROM VideoAction
WHERE actionName = 'QOE_AGGREGATE' AND city = 'Ashburn' SINCE 30 minutes ago UNTIL now
```

**Example — ratio query with mixed aggregators:**

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' /* {andWhereClause} */)
     / filter(uniqueCount(viewId) /* {aggregatorWhereClause} */)
  AS 'avgWatchTime'
TIMESERIES
```

With filter `City = Ashburn` applied:

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' AND city = 'Ashburn')
     / filter(uniqueCount(viewId), WHERE city = 'Ashburn')
  AS 'avgWatchTime'
TIMESERIES SINCE 30 minutes ago UNTIL now
```

Without any active filter:

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT')
     / uniqueCount(viewId)
  AS 'avgWatchTime'
TIMESERIES SINCE 30 minutes ago UNTIL now
```

<Callout variant="tip">
  Placeholders are valid SQL comments — clicking <DNT>**Run Query**</DNT> works even when no filters are active in the dashboard.
</Callout>

### Blocked keywords and characters [#blocked]

To prevent accidental data modification, the following are blocked in the NRQL editor:

**Blocked keywords:** `DROP`, `DELETE`, `INSERT`, `UPDATE`, `CREATE`, `ALTER`

**Blocked characters:** Semicolons (`;`) — blocked to prevent query chaining.

Queries containing any of these fail validation and cannot be saved or previewed.

### Query examples [#examples]

**Basic timeseries — total video starts:**

```sql
SELECT count(*) AS 'Video Starts'
FROM VideoAction
WHERE actionName = 'CONTENT_START' /* {andWhereClause} */
TIMESERIES
```

**Unique viewer count with filter integration:**

```sql
SELECT uniqueCount(viewId) AS 'Unique Viewers'
FROM VideoAction /* {whereClause} */
TIMESERIES
```

**Error rate across event types:**

```sql
SELECT count(*) AS 'Error Count'
FROM VideoErrorAction, VideoAction
WHERE actionName = 'CONTENT_ERROR' /* {andWhereClause} */
TIMESERIES
```

**Average watch time (ratio with nested aggregators):**

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' /* {andWhereClause} */)
     / filter(uniqueCount(viewId) /* {aggregatorWhereClause} */)
  AS 'avgWatchTime'
TIMESERIES
```

### Known V1 limitations [#v1-limitations]

The filter injection mechanism works well for common query patterns. The following NRQL patterns have limited or untested support in V1 and may produce unexpected results when global filters are active:

- **OR conditions in `WHERE`** — filter injection can produce incorrect operator precedence when the existing `WHERE` clause contains `OR` logic.
- **`COMPARE WITH`** — time-comparison queries are not compatible with the dashboard time picker integration.
- **Subqueries** — nested `FROM (SELECT …)` patterns may not behave as expected when global filters are applied.
- **Complex nested aggregators** — advanced `filter()` constructs beyond the documented examples may not correctly handle the no-filter state.
- **`PREDICT` clause** — ML prediction queries have not been tested with the time injection pipeline.

If you encounter a query pattern that doesn't work as expected, contact your New Relic account team with the query details.

## Preview a widget [#preview]

Click <DNT>**Run Query**</DNT> before saving to execute the query against live data and see a rendered chart. This does not save the widget.

Use the preview to:

- Confirm the chart renders the data you expect.
- Verify that filter placeholders resolve correctly when a filter is active.
- Catch syntax or logic errors before the widget is committed to the dashboard.

## Edit a custom widget [#edit]

1. In the <DNT>**Quality Metrics**</DNT> section, locate the custom widget you want to change.
2. Click the pencil <Icon name="fe-edit-2"/> icon on the widget card.
3. The editor opens in edit mode with all fields pre-populated — title and existing NRQL query.
4. Make your changes, click <DNT>**Run Query**</DNT> to verify, then click <DNT>**Save**</DNT>.

When saved:
- The `updatedAt` timestamp is updated; the original `createdAt` and widget `id` are preserved.
- The widget immediately re-renders with the updated query.
- If you changed the title, it updates in the metric selector dropdown.

## Delete a custom widget [#delete]

1. In the <DNT>**Quality Metrics**</DNT> section, click the <Icon name="fe-more-horizontal"/> icon on the widget card.
2. Select <DNT>**Delete**</DNT>.
3. Confirm in the prompt: *"Are you sure you want to delete '[Widget Title]'? This action cannot be undone."*

When deleted:
- The widget is removed from NerdStorage and is permanently gone.
- The widget card is immediately removed from the dashboard.
- The title is removed from the metric selector dropdown.
- If the widget was selected, it is automatically deselected.

<Callout variant="caution">
  Deletion is permanent. Copy your NRQL query before deleting a widget if you may need it later.
</Callout>

## Widget limit [#limit]

The soft limit of **50 widgets per dashboard context** is based on NerdStorage document capacity. Limits for Video quality metrics and Ad quality metrics are counted separately.

If you reach the limit, widget creation is blocked until an existing custom widget is deleted. Existing widgets continue to function normally.

## Troubleshooting [#troubleshoot]

<CollapserGroup>
  <Collapser
    id="button-not-visible"
    title="+ Add Custom Widget button is not visible"
  >
    The button is hidden when the `MEDIA_STREAMING_CUSTOM_WIDGETS` feature flag is not enabled on your account. Contact your New Relic account team to request access.
  </Collapser>

  <Collapser
    id="widget-not-responding-to-filters"
    title="Widget doesn't update when I apply a dashboard filter"
  >
    Your query is missing a filter placeholder. Without `/* {whereClause} */`, `/* {andWhereClause} */`, or `/* {aggregatorWhereClause} */`, the widget always runs the query as written and ignores dashboard filter bar selections. See [Filter placeholders](#placeholders) to choose the right one for your query structure.
  </Collapser>

  <Collapser
    id="wrong-placeholder"
    title="Filters apply but the query returns an error or no data"
  >
    You may have used the wrong placeholder type. Check:

    - If your query has no `WHERE` clause, use `/* {whereClause} */`.
    - If your query already has a `WHERE` clause at the query level, use `/* {andWhereClause} */`.
    - If the placeholder is inside a `filter()` aggregator with no existing inner `WHERE`, use `/* {aggregatorWhereClause} */`.

    The wrong placeholder produces invalid NRQL at runtime, causing the query to fail.
  </Collapser>

  <Collapser
    id="query-blocked"
    title="My query fails validation or won't save"
  >
    Check whether your query contains a [blocked keyword or character](#blocked), such as `DROP`, `DELETE`, or a semicolon. Also verify:

    - The query contains both `SELECT` and `FROM` clauses.
    - There are no syntax errors flagged by the editor's inline validation.
  </Collapser>

  <Collapser
    id="duplicate-title"
    title="Widget won't save — title already exists"
  >
    Each custom widget within the same dashboard context (Video or Ad quality metrics) must have a unique title. Choose a different title for the new widget, or rename the existing one first.
  </Collapser>

  <Collapser
    id="limit-reached"
    title="I can't add a new widget — limit reached"
  >
    You've reached the 50-widget soft limit for this dashboard context. Delete at least one existing custom widget, then try adding a new one. See [Widget limit](#limit).
  </Collapser>

  <Collapser
    id="widget-not-saving"
    title="Widget saves but disappears after a page refresh"
  >
    This may indicate a NerdStorage write failure. Check for a toast notification that appeared at save time — it will indicate whether the save failed due to a network error or insufficient account permissions. Retry saving, or contact your New Relic account team if the issue persists.
  </Collapser>
</CollapserGroup>
