New Relic's OCI integration connects your Oracle Cloud Infrastructure environment to New Relic, so you can monitor OCI resources and applications from the same observability platform you use for the rest of your stack. New Relic collects OCI metrics and logs using specialized infrastructure agents, on-host integrations, and cloud integrations built specifically for OCI. Once connected, your OCI resources appear as entities in New Relic, alongside the applications and hosts running on them.

## Capabilities [#capabilities]

- **Metrics** — OCI namespace- and compartment-level performance and usage metrics
- **Logs** — OCI service and audit logs
- **Entities** — OCI containers, namespaces, and log groups visible in New Relic Infrastructure

## Guided installation [#ui-install]

Guided installation is available at <DNT>**[one.newrelic.com](https://one.newrelic.com) > Integrations & Agents > Integrate your Oracle Cloud Infrastructure**</DNT>. The UI provides a guided end-to-end workflow, with three supported setup methods:

<CollapserGroup>
  <Collapser title="Automate with Oracle Resource Manager (ORM) (recommended)">
    Deploys the required OCI policies, instrumented namespaces, and log groups for you through an Oracle Resource Manager stack. Use this unless you have a specific reason to configure OCI manually or through Terraform.
  </Collapser>
  <Collapser title="Automate with Terraform">
    If you already manage your OCI accounts and services with Terraform, use New Relic's OCI Cloud Integrations module instead. See the [Terraform provider documentation](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs).
  </Collapser>
  <Collapser title="Manually integrate your OCI account">
    Configure OCI resources yourself in the OCI console. Use this if you can't use ORM templates and don't want to use Terraform.

    1. **Create a compartment** — In OCI, create a dedicated compartment for new resources that are created as part of the New Relic integration. Name the compartment `newrelic_compartment_DO_NOT_REMOVE`.
    2. **Create a dynamic group** — Create the dynamic group in the root compartment, under the default domain. Add two rules, `resource.type = 'serviceconnector'` and `resource.type = 'fnfunc'`, and select **Match any rules defined below**.
    3. **Create a policy** — In the root compartment, use the manual editor to create the policy that allows your dynamic group to use functions and read the metrics, logs, or secrets it needs.
    4. **Set up a Key Vault secret** — Select the compartment you created earlier. Create a key in the vault, or use an existing one. Copy your New Relic ingest key and user key into OCI — using an existing key or creating a new one for each — then create a secret in the vault for both.
    5. **Set up a network** — Start the VCN wizard to create a VCN with internet connectivity, named `newrelic-{region}-vcn`, in the compartment you created earlier. Choose a CIDR block for the VCN (for example `10.0.0.0/16`) and CIDR blocks for its private and public subnets (for example `10.0.0.0/24` and `10.0.1.0/24`), then verify and create it.
    6. **Set up a metrics function** — Select the compartment you created earlier, then create an application using the default network and subnet, adding the required configuration variables. Create the function under that application using the New Relic container image for your region.
    7. **Set up a logs function** — Select the compartment you created earlier, then create an application using the default network and subnet, adding the required configuration variables. Create the function under that application using the New Relic container image for your region.
    8. **Set up a metrics service connector** — In the Service Connector Hub, select the compartment you created earlier and create a connector with **Monitoring** as the source and **Functions** as the target. Configure the source with the compartment and namespaces to forward, and the target with the metrics function you created earlier.
    9. **Set up a logs service connector** — In the Service Connector Hub, select the compartment you created earlier and create a connector with the log source you want to forward and the logs function you created earlier as the target.
    10. **Set up Workload Identity Federation (WIF)** — Establish the trust relationship New Relic uses to authenticate to your tenancy; see [Set up Workload Identity Federation](/infrastructure/oracle-cloud/workload-identity-federation).
    11. **Create the connection** — Return to New Relic and provide the WIF client ID and secret, OCI domain URL, a name for the linked account, your tenancy ID, the ingest and user secret OCIDs, the compartment ID, and your home region, then test the connection.
  </Collapser>
</CollapserGroup>
