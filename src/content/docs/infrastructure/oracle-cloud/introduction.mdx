New Relic's OCI integration connects your Oracle Cloud Infrastructure environment to New Relic, so you can monitor OCI resources and applications from the same observability platform you use for the rest of your stack. New Relic collects OCI metrics and logs using specialized infrastructure agents, on-host integrations, and cloud integrations built specifically for OCI. Once connected, your OCI resources appear as entities in New Relic, alongside the applications and hosts running on them.

## Capabilities [#capabilities]

- **Metrics** — OCI namespace and compartment-level performance and usage metrics
- **Logs** — OCI service and audit logs

## Compatibility and requirements [#requirements]

### You need
- A New Relic account with [infrastructure monitoring permissions](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions/#infrastructure), in a supported region (US, EU, or JP)
- A valid New Relic [ingest license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) and [user key](/docs/apis/intro-apis/new-relic-api-keys/#user-api-key)
- An OCI tenancy with an Identity and Access Management (IAM) domain, and administrative access to that domain and the root compartment
- Your OCI tenancy OCID and home region (for example, `us-ashburn-1`)
- An OCI API signing key (only if you're deploying with Terraform)
- Temporary Identity Domain Administrator access, to complete Workload Identity Federation (WIF) setup — the mechanism New Relic uses to authenticate without storing long-lived credentials. You can revoke this access once setup is complete.
- A WIF trust-type decision — **UPST** (default) or **RPST** — see [Guided installation](#ui-install) for when to use each

## Guided installation [#ui-install]

Guided installation is available at <DNT>**[one.newrelic.com](https://one.newrelic.com) > Integrations & Agents > Integrate your Oracle Cloud Infrastructure**</DNT>. The UI provides a guided end-to-end workflow.

<Steps>

<Step>

### Connect your OCI account

Choose the data type to ingest — metrics, logs, or both — then choose a setup method:

<CollapserGroup>
  <Collapser title="Automate with Oracle Resource Manager (ORM) (recommended)">
    Deploys a pre-built Oracle Resource Manager stack that provisions everything the integration needs — the compartment, IAM policies, service connectors, and (if not already configured) your Workload Identity Federation trust — in one guided run, instead of you creating each piece by hand in the OCI console.<br />
    In New Relic, provide your license and user key, then click **Deploy to OCI**. This redirects you to the OCI console with the stack pre-loaded for you to review and apply. Once the stack finishes, return to New Relic to finalize the connection.<br />
    Use this unless you have a specific reason to configure OCI manually or through Terraform — it takes the least manual work.
  </Collapser>
  <Collapser title="Automate with Terraform">
    Declares the compartment, policies, service connectors, and WIF trust as code, using New Relic's OCI Cloud Integrations module — instead of creating each piece by hand in the OCI console or through an OCI-side ORM stack.<br />
    Use this if you already manage your OCI tenancy with Terraform: it keeps the integration in the same version-controlled, repeatable workflow as the rest of your infrastructure, rather than introducing a manual, out-of-band step.<br />
    Apply the module with your license key, user key, and WIF details as inputs, then verify the integration in New Relic. See the [Terraform provider documentation](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs) for the resource reference.
  </Collapser>
  <Collapser title="Manually integrate your OCI account">
    Step through creating the required policies and service connectors in the OCI console yourself.

    1. **Create a compartment** — In OCI, create a dedicated compartment for new resources that are created as part of the New Relic integration. Name the compartment `newrelic_compartment_DO_NOT_REMOVE`.
    2. **Create a dynamic group** — Create the dynamic group in the root compartment, under the default domain.<br />
       Add two rules, `resource.type = 'serviceconnector'` and `resource.type = 'fnfunc'`.<br />
       Ensure that you select the **Match any rules defined below** checkbox.
    3. **Create a policy** — In the root compartment, use the manual editor to create the policies shown here.<br />
       `Allow dynamic-group your_dynamic_group_name to use fn-function in tenancy`<br />
       `Allow dynamic-group your_dynamic_group_name to use fn-invocation in tenancy`<br />
       `Allow dynamic-group your_dynamic_group_name to read secret-bundles in tenancy`<br />
       `Allow dynamic-group your_dynamic_group_name to read metrics in tenancy`<br />
       `Allow dynamic-group your_dynamic_group_name to read log-content in tenancy`
    4. **Set up a Key Vault secret** — Select the compartment you created earlier.<br />
       Create a key in the vault, or use an existing one.<br />
       Copy your New Relic ingest key and user key into OCI — using an existing key or creating a new one for each — then create a secret in the vault for both.
    5. **Set up a network** — Start the VCN wizard to create a VCN with internet connectivity, named `newrelic-{region}-vcn`, in the compartment you created earlier.<br />
       Choose a CIDR block for the VCN (for example `10.0.0.0/16`) and CIDR blocks for its private and public subnets (for example `10.0.0.0/24` and `10.0.1.0/24`), then verify and create it.
    6. **Set up a metrics function** — Select the compartment you created earlier, then create an application using the default network and subnet, adding the required configuration variables.<br />
       Create the function under that application using the New Relic container image for your region.
    7. **Set up a logs function** — Select the compartment you created earlier, then create an application using the default network and subnet, adding the required configuration variables.<br />
       Create the function under that application using the New Relic container image for your region.
    8. **Set up a metrics service connector** — In the Service Connector Hub, select the compartment you created earlier and create a connector with **Monitoring** as the source and **Functions** as the target.<br />
       Configure the source with the compartment and namespaces to forward, and the target with the metrics function you created earlier.
    9. **Set up an audit logs connector (optional)** — In the Connector Hub, create a connector with **Logging** as the source and **Functions** as the target, using the `_Audit` log group and the logs function you created earlier. Skip this step if you don't need audit log ingestion.
    10. **Set up a logs service connector** — In the Service Connector Hub, select the compartment you created earlier.<br />
        Create a connector with the log source you want to forward and the logs function you created earlier as the target.
    11. **Set up Workload Identity Federation (WIF)** — Create the two OCI Identity Domain applications (a temporary admin app for setup, and a no-privilege app for routine token exchange), the service user and group (for UPST) or claim-based principal (for RPST), and the identity propagation trust linking your domain to New Relic's JWT issuer. See your trust-type choice below.
    12. **Create the connection** — Return to New Relic and provide the WIF client ID and secret, OCI domain URL, a name for the linked account, your tenancy ID, the ingest and user secret OCIDs, the compartment ID, and your home region.
    13. **Test the connection** — Confirm New Relic can reach your OCI tenancy before moving on to instrumentation.
  </Collapser>
</CollapserGroup>

All three setup methods also require Workload Identity Federation (WIF) — the trust relationship New Relic uses to authenticate to your tenancy without storing long-lived credentials:

- Choose a trust type: **UPST** impersonates a dedicated service user — recommended for most accounts. **RPST** uses claim-based, ephemeral access instead — pick this if one tenancy is monitored by multiple New Relic accounts, or if you hit OCI's IAM policy-statement limit.
- Reuse an existing WIF configuration if you already have one (client ID, client secret, and domain URL), or set one up. Oracle Resource Manager can automate WIF setup regardless of which method you chose for the rest of the integration.

</Step>

<Step>

### Instrument your metric namespaces and log groups

Once the connection is created, an **Add instrumentation** button appears on the OCI page in New Relic. Clicking it opens a list of uninstrumented metric namespaces or log groups, based on the data type you selected earlier:

1. Click **Add instrumentation**, filtered to **Not instrumented** by default.
2. Expand a compartment to see its individual metric namespaces (or log groups), and select the ones you want to monitor. For logs, you can also turn on **Enable audit logs** to include OCI audit logs.
3. Confirm your selection — New Relic shows a summary of how many compartments and namespaces (or log groups) you're about to instrument — then click **Deploy to OCI**.
4. After the deployment finishes in OCI, the compartment moves to the **Instrumented** filter, and its data appears at <DNT>**one.newrelic.com > Infrastructure > OCI**</DNT>.
5. If you selected both metrics and logs, repeat the same process from the logs view.

Data can take up to 30 minutes to appear. If you don't see it after that, check the deployment status in the OCI console.

To instrument additional namespaces or log groups later, return to the OCI page in New Relic and repeat these steps.

</Step>
