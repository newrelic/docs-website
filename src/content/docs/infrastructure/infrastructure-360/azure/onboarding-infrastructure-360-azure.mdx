## Prerequisites [#prerequisites]

Before enabling [<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360) for <DNT>Azure</DNT>, ensure you have:

* An <DNT>Azure</DNT> account with a subscription ID.
* An <DNT>Azure</DNT> app registration with the Monitoring Reader role.
* A New Relic account enrolled in the <DNT>Infrastructure 360</DNT> preview.
* Permissions to manage cloud integrations in New Relic.

To enroll in the preview, go to <DNT>**one.newrelic.com > Administration > Preview & Trials**</DNT> and enroll for <DNT>**Infrastructure 360**</DNT>.

There are three ways to enable <DNT>Infrastructure 360</DNT> for <DNT>Azure</DNT>:

## Enable during Azure onboarding [#onboarding-enable]

If you're connecting <DNT>Azure</DNT> to New Relic for the first time, follow these steps:

1. Navigate to <DNT>**Infrastructure > Azure**</DNT>.
2. Select an account and click <DNT>**Set up integration**</DNT>.
3. Follow the prompts to create your <DNT>Azure</DNT> app registration. For detailed setup instructions, see [Connect <DNT>Azure</DNT> integrations](/docs/infrastructure/microsoft-azure-integrations/get-started/activate-azure-integrations).
4. During integration setup, enable the <DNT>**Infrastructure 360**</DNT> option when prompted.
5. Configure the scan frequency. By default, <DNT>Infrastructure 360</DNT> scans three times per day. To change this, see [Adjust scan frequency](#adjust-frequency).

## Enable for an existing Azure integration [#existing-enable]

If you already have <DNT>Azure</DNT> integrated with New Relic, follow these steps:

1. Go to <DNT>**Infrastructure > Azure**</DNT> and click <DNT>**Manage Infrastructure 360**</DNT>.
2. From the account list, find your <DNT>Azure</DNT> subscription and click <DNT>**Install**</DNT> (at the provider account level).
3. Configure the scan frequency as described above.
4. Click <DNT>**Save**</DNT> to enable <DNT>Infrastructure 360</DNT> for your <DNT>Azure</DNT> account.

## Enable from the Infrastructure 360 page [#landing-page-enable]

To enable <DNT>Infrastructure 360</DNT> from this page:

1. Go to <DNT>**[one.newrelic.com](https://one.newrelic.com) > Infrastructure > Infrastructure 360**</DNT>.
2. Enable the functionality for your <DNT>Azure</DNT> (and <DNT>AWS</DNT>) provider accounts under this New Relic account.

If this page is blank (you haven't enabled <DNT>Infrastructure 360</DNT> for any provider yet), click <DNT>**Setup Infrastructure 360**</DNT> and then enable the functionality.

## Enable through Terraform [#terraform-enable]

You can also enable <DNT>Infrastructure 360</DNT> for <DNT>Azure</DNT> through <DNT>Terraform</DNT> instead of the New Relic UI. This is a step-by-step walkthrough for enabling auto-discovery for <DNT>Azure</DNT> integrations using <DNT>Terraform</DNT>.

### Prerequisites [#terraform-prerequisites]

Before starting, ensure you have the following:

* **<DNT>Terraform</DNT> installed**: <DNT>Terraform</DNT> installed on your local machine.
* **New Relic account ID**: Your New Relic account ID (`newrelic_account_id`).
* **New Relic user API key**: A user key to authenticate with New Relic (`newrelic_api_key`).
* **Linked provider account ID**: The ID of the <DNT>Azure</DNT> account as recognized by New Relic (`provider_account_id`). This is often found in the New Relic UI under <DNT>**Infrastructure > Azure**</DNT>.
* **Region**: Your New Relic data region (US or EU).

<Steps>
<Step>

### Set up your workspace [#setup-workspace]

Set up a local folder for your <DNT>Terraform</DNT> configuration:

1. Open your terminal or command prompt.
2. Create a new folder for your project:

   ```bash
   mkdir terraform-integrate
   cd terraform-integrate
   ```

</Step>
<Step>

### Create configuration files [#create-config-files]

Create the following three files inside your `terraform-integrate` folder. You can use any text editor.

#### providers.tf

This file tells <DNT>Terraform</DNT> which plugins to download.

```hcl
terraform {
  required_providers {
    newrelic = {
      source = "newrelic/newrelic"
    }
  }
}
```

#### variables.tf

This file defines the inputs required to run the script.

```hcl
variable "provider_account_id" {
  description = "The Azure Subscription ID Equivalent in Newrelic (Linked Account ID)."
  type        = number
}

variable "new_relic_region" {
  description = "The New Relic region (e.g., 'US', 'EU', or 'JP')."
  type        = string
  default     = "US"
}

variable "newrelic_account_id" {
  description = "The New Relic account ID."
  type        = number
}

variable "newrelic_api_key" {
  description = "The New Relic API key."
  type        = string
}
```

#### main.tf

This is the core script that enables the auto-discovery feature.

```hcl
provider "newrelic" {
  account_id = var.newrelic_account_id
  region     = var.new_relic_region
  api_key    = var.newrelic_api_key
}

resource "newrelic_cloud_azure_integrations" "auto_discovery_integrations" {
  linked_account_id = var.provider_account_id

  # This block enables auto-discovery for the account
  auto_discovery {}
}
```

</Step>
<Step>

### Run Terraform [#run-terraform]

Now that your files are ready, run these commands in your terminal from within the `terraform-integrate` folder.

1. **Initialize**: Downloads the necessary New Relic provider plugins.

   ```bash
   terraform init
   ```

2. **Plan**: Checks the configuration and shows you what will happen. <DNT>Terraform</DNT> prompts you to enter your IDs and keys here.

   ```bash
   terraform plan
   ```

   Enter the values when prompted for `newrelic_account_id`, `newrelic_api_key`, and the other variables.

3. **Apply**: Executes the plan and enables the integration.

   ```bash
   terraform apply
   ```

   Type `yes` when asked to confirm.

</Step>
</Steps>

For more information, see the [New Relic <DNT>Terraform</DNT> provider documentation](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#azure).

## Use Infrastructure 360 [#using-infrastructure-360]

Once enabled, <DNT>Infrastructure 360</DNT> lets you check the relationships among all your <DNT>Azure</DNT> entities, including infrastructure, APM, and databases.

<Callout title="Note">
  <DNT>Infrastructure 360</DNT> supports entity relationships through native New Relic APM agents (<DNT>Java</DNT>, <DNT>.NET</DNT>, <DNT>Python</DNT>) and <DNT>OpenTelemetry</DNT> (<DNT>.NET</DNT>).

  For <DNT>Azure Kubernetes Service</DNT> (<DNT>AKS</DNT>) clusters specifically, connecting your application to its <DNT>AKS</DNT> cluster requires the New Relic <DNT>Kubernetes</DNT> agent or <DNT>OpenTelemetry</DNT>. <DNT>Infrastructure 360</DNT> doesn't establish that connection on its own, but once it exists, it completes the chain by mapping the relationship from your application through the <DNT>AKS</DNT> cluster to the other <DNT>Azure</DNT> infrastructure it depends on.
</Callout>

### View discovered entities and relationships [#view-entities]

To view discovered entities and their relationships:

1. Go to <DNT>**All entities**</DNT> and filter for `collector.name = auto discovery`.
2. Select any <DNT>Azure</DNT> entity to see its infrastructure map, which shows relationships between:
   * <DNT>Azure</DNT> entities (virtual machines, databases, storage accounts).
   * APM entities (applications, services).
   * Cross-platform connections (<DNT>Azure</DNT> resources connected to APM services).

### Cross-subscription relationships [#cross-subscription]

If a discovered resource connects to a resource in a different <DNT>Azure</DNT> subscription, <DNT>Infrastructure 360</DNT> resolves the relationship automatically:

* If the target subscription is also integrated with <DNT>Infrastructure 360</DNT>, the map shows the real target entity and its details.
* If you haven't integrated or monitored the target subscription, the map shows an unknown or uninstrumented entity in its place — the connection is still visible, but entity details aren't available.

### Correlate configuration changes with alerts [#correlate-config-changes]

<DNT>Infrastructure 360</DNT> tracks configuration changes on your <DNT>Azure</DNT> resources so you can quickly tell whether a recent change caused an alert or incident, instead of investigating infrastructure and application data separately.

1. Go to <DNT>**All capabilities**</DNT> and select <DNT>**Azure Services**</DNT>.
2. Select any entity from the list and click <DNT>**Configuration explorer**</DNT> to see its current settings, tags, and properties.
3. Compare the timestamps in the configuration changes timeline against your alerts or incidents. A configuration change around the same time as an alert is a strong signal of root cause, letting you correlate configuration changes with your alerts and incidents.

## Manage Infrastructure 360 settings [#manage-settings]

### Adjust scan frequency [#adjust-frequency]

You can customize how often <DNT>Infrastructure 360</DNT> scans your <DNT>Azure</DNT> environment:

1. Go to <DNT>**Infrastructure > Azure**</DNT> and click <DNT>**Manage Infrastructure 360**</DNT>.
2. Find your <DNT>Azure</DNT> account and click <DNT>**Edit**</DNT>.
3. Select your preferred scan frequency from the dropdown menu.
4. Click <DNT>**Save**</DNT> to apply the changes.

Consider increasing scan frequency if you make frequent changes to your <DNT>Azure</DNT> environment, or decreasing it if your infrastructure is stable and you want to reduce API calls.

### Disable Infrastructure 360 [#disable]

<Callout variant="important">
  When you disable <DNT>Infrastructure 360</DNT>, you lose access to:

  * Automatically discovered entities and their configurations.
  * Relationship mapping between <DNT>Azure</DNT> resources and APM services.
  * Real-time infrastructure topology updates.
</Callout>

If you re-enable <DNT>Infrastructure 360</DNT> later, it recreates any entities and relationships that no longer exist, during its next scheduled scan.

To disable <DNT>Infrastructure 360</DNT>, follow these steps:

1. Go to <DNT>**Infrastructure > Azure**</DNT> and click <DNT>**Manage Infrastructure 360**</DNT>.
2. Find the account where you want to disable <DNT>Infrastructure 360</DNT>.
3. Click <DNT>**Edit**</DNT> and turn off the scan toggle.
4. Click <DNT>**Save**</DNT> to confirm the change.
