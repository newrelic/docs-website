[New Relic integrations](/docs/infrastructure/introduction-infra-monitoring) with the [Google Cloud Platform (GCP)](https://cloud.google.com/) include one that reports [Gemini Enterprise](https://cloud.google.com/gemini-enterprise) data to New Relic. This document explains how to activate the <DNT>GCP Gemini Enterprise</DNT> integration and describes the data it reports.

## Features

<DNT>Gemini Enterprise</DNT> is <DNT>Google Cloud</DNT>'s platform for building and running enterprise search and AI agent applications, built on <DNT>Discovery Engine</DNT>. New Relic's <DNT>Gemini Enterprise</DNT> integration collects request, latency, and session metrics for apps (engines), agents, the tools those agents invoke, and data connectors, along with resource counts and quota consumption per location and per user.

## Activate integration [#activate]

<Callout variant="important">
  This integration is available only when you connect your <DNT>GCP</DNT> project with <DNT>**Workload Identity Federation**</DNT>. It isn't available for service account or user account connections.
</Callout>

To enable the integration, follow standard procedures to [connect your GCP service to New Relic](/docs/connect-google-cloud-platform-services-infrastructure) with <DNT>**Workload Identity Federation**</DNT>.

## Polling frequency [#polling]

New Relic integrations query your <DNT>GCP</DNT> services according to a polling interval that varies by integration. The polling frequency for <DNT>Gemini Enterprise</DNT> is 5 minutes. The resolution is 1 data point every minute.

## Workload Identity Federation [#wif]

### Find and use data [#find-data-wif]

After you enable the integration, your <DNT>Gemini Enterprise</DNT> resources appear as entities in the New Relic entity explorer. To see dashboards and manage services, go to <DNT>[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Infrastructure > GCP</DNT>.

New Relic collects <DNT>Gemini Enterprise</DNT> metrics available in <DNT>GCP Cloud Monitoring</DNT> as dimensional metrics in the `Metric` event type, for example:

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.discoveryengine.%' FACET metricName
```

The same counts are also reported as quota metrics, for example `gcp.discoveryengine.quota.engines_regional.usage` and `gcp.discoveryengine.quota.documents_regional.usage`.

#### Location quota metrics

Each quota is reported as up to three metrics, named by adding a suffix to the metric name below:

* `usage`: current usage of the quota.
* `limit`: current limit of the quota.
* `exceeded`: number of attempts to exceed the quota limit.

For example, the business-tier agents quota is reported as `gcp.discoveryengine.quota.agents_tier_business_regional.usage`, `.limit`, and `.exceeded`. Quota metrics carry the `metric.limit_name` and `metric.regional_location` labels.
