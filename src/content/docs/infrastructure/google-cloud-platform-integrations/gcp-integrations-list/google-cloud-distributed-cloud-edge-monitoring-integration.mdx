[New Relic integrations](/docs/infrastructure/introduction-infra-monitoring) with the [Google Cloud Platform (GCP)](https://cloud.google.com/) include one that reports [Google Distributed Cloud Edge](https://cloud.google.com/distributed-cloud/edge/latest/docs) data to New Relic. This document explains how to activate the GCP Distributed Cloud Edge integration and describes the data it reports.

## Features

Distributed Cloud Edge (formerly Distributed Cloud connected) extends GKE to on-premises edge hardware. New Relic Distributed Cloud Edge integration collects hardware health metrics for each machine (CPU, memory, disk, network, and connectivity) and software version metrics for each edge cluster.

This integration is scoped to `Machine` and `EdgeCluster` resources. Distributed Cloud Edge metrics published on `EdgeZone`, `Node`, and `Rack` resources aren't collected by this integration.

## Activate integration [#activate]

<Callout variant="important">
  This integration is available only when you connect your GCP project with Workload Identity Federation. It isn't available for service account or user account connections.
</Callout>

To enable the integration, follow standard procedures to [connect your GCP service to New Relic](/docs/connect-google-cloud-platform-services-infrastructure) with Workload Identity Federation.

## Polling frequency [#polling]

New Relic integrations query your GCP services according to a polling interval that varies by integration. The polling frequency for Distributed Cloud Edge is 5 minutes. The resolution is 1 data point every minute.

## Workload Identity Federation [#wif]

### Find and use data [#find-data-wif]

All Distributed Cloud Edge machine and cluster metrics available in GCP Cloud Monitoring are collected as dimensional metrics in the `Metric` event type.

This integration doesn't create entities in the New Relic entity explorer. Query its metrics directly on the `Metric` event type, for example:

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.edgecontainer.%' FACET metricName
```

Metrics carry the `machine_id` and `location` labels for `Machine` metrics, and the `cluster_name` and `location` labels for `EdgeCluster` metrics, so you can facet by machine or cluster without an entity.
