To read the relevant data from your Google Cloud Platform (GCP) account, New Relic uses the Google Stackdriver API and other service-specific APIs. To access these APIs in your Google Cloud project, the New Relic authorized account needs a certain set of permissions, which GCP grants through roles.

The exact APIs, roles, and permissions you need depend on how you connect GCP to New Relic. Review the requirements for your connection method below.

## APIs to enable [#apis-to-enable]

Before you connect, enable the required Google Cloud APIs in each project you want to monitor, using the <DNT>**API & Services**</DNT> library.

## Roles for the New Relic authorized account [#roles]

We recommend the GCP primitive role `Viewer` (`roles/viewer`), which grants [read-only permissions that don't affect your cloud infrastructure state, such as viewing (but not modifying) existing resources or data](https://cloud.google.com/iam/docs/understanding-roles). Google automatically manages this role and updates it as Google Cloud services change. If you need tighter control, use a [custom role](#custom-role) instead.

The roles you grant depend on your connection method.

### Workload Identity Federation [#roles-wif]

Grant the service account you create these roles on the project:

* `Viewer` (`roles/viewer`): read access to resources
* `Service Usage Consumer` (`roles/serviceusage.serviceUsageConsumer`): access to enabled APIs
* `Cloud Asset Viewer` (`roles/cloudasset.viewer`): view cloud asset metadata
* `Folder Viewer` (`roles/resourcemanager.folderViewer`): view folder metadata

The service account must also allow impersonation from the identity pool. During setup, you grant the `Workload Identity User` role (`roles/iam.workloadIdentityUser`) to the pool principal.

### Domain restriction constraints [#domain-restrictions]

If your organization enforces a [domain restriction constraint](https://cloud.google.com/resource-manager/docs/organization-policy/restricting-domains), update the policy to allow the following New Relic identifiers, depending on which constraint you use:

* `iam.allowedPolicyMemberDomains`: allow New Relic <DNT>domain ID `C02x1gp26`</DNT>
* `iam.managed.allowedPolicyMembers`: allow <DNT>Organization ID `740422149647`</DNT> or <DNT>Project Number `397727728820`</DNT>

## Use a custom role [#custom-role]

To control permissions more precisely than the `Viewer` role allows, create a custom role based on the [list of permissions](#list-permissions), which specifies the minimum set required to fetch data from each GCP integration.

<Callout variant="important">
  New Relic has no way of identifying problems related to custom permissions. If you choose to create a custom role, it is your responsibility to maintain it and ensure proper data is being collected.
</Callout>

To customize your role:

1. Create a Google Cloud IAM Custom Role in each one of the GCP projects you want to monitor with New Relic.
2. Add the permissions required for the cloud services you want to monitor to each custom role, according to the following list.
3. Assign the custom role(s) to the New Relic authorized account.

      * `resourcemanager.projects.get`

      * `monitoring.monitoredResourceDescriptors.list`

        If you do not want to grant the New Relic authorized account the permissions needed for the linking process through the UI, you have the following options:

      * Assign the `Role Viewer` or `Monitoring Viewer` role initially to the authorized account to link Google Cloud projects to New Relic through the UI. After the projects are linked, assign a Google Cloud custom role to the authorized account.

      * Use [New Relic NerdGraph](/docs/apis/graphql-api/get-started/introduction-new-relic-nerdgraph) to link Google Cloud projects to New Relic. This does not involve listing the viewable projects. However, you must know the `id` of the project you want to monitor. For more information, see the [NerdGraph GraphiQL cloud integrations API tutorial](/docs/apis/graphql-api/tutorials/nerdgraph-graphiql-cloud-integrations-api-tutorial).
