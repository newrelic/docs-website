If you authorize New Relic to fetch data through a service account, New Relic calls your GCP project APIs using a service account ID and its associated public/private key pair.

New Relic manages a specific Google service account for your New Relic account; you do not need to create it or manage the associated private key. Just add the service account ID as a member with viewing permissions in your project.

This authorization method is recommended, especially if your GCP project is managed by a team. It also guarantees that New Relic collects tags and other attributes whenever possible.

<Callout variant="tip">
  You can use Terraform to automate the process of enabling cloud integrations. Read how in the [Terraform official documentation site](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide).
</Callout>

If your organization uses a [domain restriction constraint](https://cloud.google.com/resource-manager/docs/organization-policy/restricting-domains), you will have to update the policy to allow New Relic, depending on which constraint your organization enforces:

* **`iam.allowedPolicyMemberDomains`**: Allow the New Relic domain ID `C02x1gp26`.
* **`iam.managed.allowedPolicyMembers`**: Allow the New Relic GCP Organization ID `740422149647` or GCP Project Number `397727728820`.

## Connect GCP to New Relic infrastructure monitoring [#connect]

<Callout variant="important">
  If this is your first time setting up GCP with New Relic, ensure that you've enabled Cloud Monitoring API for your project. You can do this in the [Google Cloud console](https://console.cloud.google.com/apis/api/monitoring.googleapis.com/).
</Callout>

To connect your Google account to New Relic with service account authorization:

1. Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Infrastructure > GCP**</DNT>. On the <DNT>**Google Cloud Services**</DNT> integrations page, select <DNT>**Add a GCP account**</DNT>.
2. <DNT>**Choose Authorization Method**</DNT>: Select <DNT>**Authorize a Service Account**</DNT>, and follow the instructions in the UI to authorize New Relic.
3. <DNT>**Add projects:**</DNT> Select the projects that you want New Relic to receive data from.
4. <DNT>**Select services:**</DNT> From the list of available services for your GCP account, select the individual services you want New Relic to receive data from, or select all of the services.

   <Callout variant="tip">
     These services will be enabled for <DNT>**all**</DNT> of the projects that you selected in the previous step. Once the setup process is finished, you can fine-tune the services that you want monitored for each project individually.
   </Callout>
5. To complete the setup process, select <DNT>**Finish**</DNT>.

If you see API authentication errors, follow the [troubleshooting procedures](/docs/infrastructure/google-cloud-platform-integrations/troubleshooting/troubleshooting-gcp-integrations).

It may take a few minutes for new resources to be detected and synthesized as entities. For more information, see Cloud integrations [system limits](/docs/data-apis/manage-data/view-system-limits).

## Explore app data in New Relic [#find-data]

After you connect, New Relic starts monitoring your GCP data at regular polling intervals, and your data appears in the New Relic UI after a few minutes. To learn how to view, query, and explore it — including dashboards, alerts, and entities — see [Understand your GCP data](/docs/infrastructure/google-cloud-platform-integrations/get-started/understand-your-gcp-data).

## Link multiple Google projects [#connect-multiple]

The setup process lets you select more than one project at a time.

After the first setup, to monitor additional GCP projects with New Relic, repeat the procedure to [connect your GCP services](#connect) as many times as you need.

## Unlink your GCP integrations [#disconnect]

You can [disable any of your GCP integrations](/docs/infrastructure/new-relic-infrastructure/installation/uninstall-infrastructure-agent) any time and still keep your Google project connected to New Relic.

### Disable one or more GCP services [#disable-services]

To disable services while keeping your GCP account linked to New Relic:

1. Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Infrastructure > GCP > Manage services**</DNT>.
2. From your <DNT>**Edit GCP account**</DNT> page, clear the checkbox for each active service you want to disable.
3. Save your changes.

### Disconnect and unlink your account [#unlink-account]

To completely disconnect from New Relic, unlink your GCP account. This disables all New Relic integrations associated with it. If you delete a custom role, note that the role might serve purposes beyond New Relic access.

For a <DNT>**custom user role**</DNT>:

1. Sign in to New Relic and go to <DNT>**Infrastructure > Integrations > Google Cloud Platform**</DNT>.
2. Go to <DNT>**IAM > admin > Roles**</DNT>, search for the role, select it, and select <DNT>**DELETE**</DNT>.

For a <DNT>**standard (non-custom) user role**</DNT>:

1. Sign in to New Relic and go to <DNT>**Infrastructure > Integrations > Google Cloud Platform**</DNT>.
2. Select <DNT>**Manage services**</DNT> for the account you want to remove. Copy the value of <DNT>**User**</DNT> and save it.
3. Sign in to [Google Cloud](https://console.cloud.google.com/) and select the correct project in the <DNT>**Select a project**</DNT> box.
4. From the navigation menu, select <DNT>**IAM & admin > IAM**</DNT>.
5. Search for and select the user value you saved, then select <DNT>**REMOVE**</DNT>.

### Clean up GCP after unlinking [#clean-up]

To clean your GCP project after unlinking:

1. Open the GCP IAM Console.
2. Select the project you want to unlink from New Relic and select <DNT>**Open**</DNT>.
3. Select the service account used by New Relic.
4. Select the <DNT>**Remove**</DNT> icon.
