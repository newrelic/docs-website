Use this guide to send both OCI metrics and logs to New Relic. Choosing both sends metrics and logs together, so you can correlate them for the same OCI resources. To send only one data type, see [Monitor OCI metrics](/docs/infrastructure/oci/install-metrics) or [Forward OCI logs](/docs/logs/forward-logs/oci-log-forwarding).

## Compatibility and requirements [#requirements]

Before you begin, make sure you have:

- A New Relic account with infrastructure monitoring permissions in a supported region (US, EU, or JP)
- A valid New Relic [ingest license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) and [user key](/docs/apis/intro-apis/new-relic-api-keys/#user-api-key)
- An OCI tenancy with an Identity and Access Management (IAM) domain, and temporary administrative access to that domain and the root compartment, enough to complete Workload Identity Federation (WIF) setup, the mechanism New Relic uses to authenticate without storing long-lived credentials. You can revoke this access once setup is complete.
- Your OCI tenancy OCID and home region (for example, `us-ashburn-1`)
- An OCI API signing key (only if you're deploying with Terraform)

## Guided installation [#ui-install]

Guided installation is available at <DNT>**[one.newrelic.com](https://one.newrelic.com) > Integrations & Agents > Oracle Cloud Infrastructure**</DNT>. The UI walks you through connecting your OCI account, then instrumenting the metric namespaces and log groups you want to monitor.

<Steps>

<Step>

### Choose both data types

Follow these steps:

1. Select both <DNT>**Metrics**</DNT> (for performance and usage statistics) and <DNT>**Logs**</DNT> (for detailed event and audit records).
2. Click <DNT>**Continue**</DNT>.

</Step>

<Step>

### Choose your integration method and configure the integration

Select your preferred integration method to ingest OCI data into New Relic based on your organizational needs:

<CollapserGroup>
  <Collapser id="orm" title="Monitor OCI with Oracle Resource Manager">
    Runs Oracle Resource Manager stacks to provision what the integration needs, instead of you creating each piece by hand in the OCI console.
    Follow the on-screen instructions to establish the connection.
  </Collapser>
  <Collapser id="manual" title="Manually integrate your OCI account">
    In the OCI console create the required policies and service connectors. The guided installation walks you through these steps in order: create a compartment, create a dynamic group, set up a key vault secret, create a policy, set up a network, set up the metrics function, set up the logs function, set up the metrics connector, set up an audit logs connector (optional), set up the logs connector, set up WIF, and create the connection.

    You will need the following information to complete the process:

    - Name the dedicated compartment as `newrelic_compartment_DO_NOT_REMOVE`. Create it in your OCI home region.
    - While creating the dynamic group in the root compartment under the default domain, add the rules `resource.type = 'serviceconnector'` and `resource.type = 'fnfunc'`.
    - Create a key vault to securely store your New Relic license key and user key for authentication.<br />
       1. **Create a key vault**. In the OCI console, locate and access the **Key Management and Vault services** and create a vault in the compartment you created earlier, naming it (for example, `newrelic-vault`) and choosing a standard or virtual private vault based on your security requirements.<br />
       2. **Create a master encryption key**. In the vault, create a master key named (for example) `newrelic-encryption-key`, using the `AES` algorithm and a `256`-bit key length.<br />
       3. **Create secrets for your API keys**. Create a secret for your New Relic ingest license key, named (for example) `newrelic-ingest-key`, selecting the master key you just created and pasting your ingest license key as the secret content (Plain Text). Repeat to create a second secret for your New Relic user key, named (for example) `newrelic-user-key`, pasting your user key as the secret content (Plain Text).
    - Create a serverless application and deploy the New Relic function that processes and forwards your OCI metrics.<br />
       1. **Create a serverless application**
          - Access the <DNT>**Functions**</DNT> service under <DNT>**Developer Services**</DNT> in the OCI console.
          - Create a new application with this configuration:
            - **Name**: a descriptive name (for example, `NewRelicMetricsApp`)
            - **Compartment**: your designated New Relic compartment
            - **VCN**: the VCN created for the New Relic integration
            - **Subnet**: the private subnet, for secure connectivity
            - **Shape**: `GENERIC_X86`, for the application shape
       2. **Configure environment variables**
          - Within the application settings, add these configuration variables:
            - `FORWARD_TO_NR`: set to `True` to enable data forwarding to New Relic
            - `LOGGING_ENABLED`: set to `False` to disable verbose logging (optional)
            - `NR_METRIC_ENDPOINT`: the New Relic endpoint, using `newrelic-metric-api` for US accounts, `newrelic-eu-metric-api` for EU accounts, or `newrelic-jp-metric-api` for JP accounts
            - `VAULT_REGION`: the region where you created your key vault
            - `SECRET_OCID`: the OCID of your New Relic ingest secret from the key vault
            - `TENANCY_OCID`: your OCI tenancy OCID
          - Save the configuration variables.
       3. **Create and deploy the function**
          - Within the application, create a new function with these specifications:
            - **Function name**: a descriptive name (for example, `newrelic-metrics-function`)
            - **Image source**: the New Relic Docker image, which you copy into a private repository in your Container Registry
            - **Memory allocation**: appropriate memory (for example, 256 MB)
          - For the Docker image, pull the New Relic image from Docker Hub (`docker.io/newrelic/beyond-oci-metric-function:latest`, platform `linux/amd64`). Then authenticate with your regional Container Registry endpoint (`{region}.ocir.io`) using an auth token.
          - Tag and push the image to a private repository in your namespace in the same region as the function, and reference it in your function configuration.
          - Complete the function creation and deployment process.
          - To upgrade later, push the new image again and update the function to use it.
    - Create a serverless application and deploy the New Relic function that processes and forwards your OCI logs.<br />
       1. **Create a serverless application for logging**
          - Access the <DNT>**Functions**</DNT> service under <DNT>**Developer Services**</DNT> in the OCI console.
          - Create a new application with this configuration:
            - **Name**: a descriptive name (for example, `newrelic-logging-function-app`)
            - **Compartment**: your designated New Relic compartment
            - **VCN**: the VCN created for the New Relic integration
            - **Subnet**: the private subnet, for secure connectivity
            - **Shape**: `GENERIC_X86`, for the application shape
          - Save the application configuration.
       2. **Configure environment variables for logging**
          - Within the application settings, go to the configuration section and add these variables:
            - `VAULT_REGION`: the region where you created your key vault
            - `DEBUG_ENABLED`: `false` for production use (or `true` for debugging)
            - `NEW_RELIC_REGION`: your New Relic region (`US`, `EU`, or `JP`)
            - `SECRET_OCID`: the OCID of your New Relic license key secret from the key vault
            - `CLIENT_TTL`: `30` seconds, for the license key refresh interval
          - Optionally, to enable [self-observability metrics on the log forwarder](/docs/logs/forward-logs/oci-log-forwarder-observability), also add
            - `FORWARDER_METRICS_TIER`: Controls which self-observability metrics the forwarder emits. Defaults to `basic`. Refer to the [metric tiers](/docs/logs/forward-logs/oci-log-forwarder-observability/#metric-tiers) for what each setting collects.
            - `TENANCY_NAME`: Identifies your OCI tenancy by its display name, tagging the forwarder's metrics so you can tell tenancies apart if you monitor more than one.
            - `COMPARTMENT_NAME`: Identifies, by display name, the compartment where you deployed the logs function, tagging metrics for per-compartment breakdowns. If you deployed into the tenancy's root compartment, use the same value as `TENANCY_NAME`.
          - Once you enable forwarder metrics, [import the observability dashboard](/docs/logs/forward-logs/oci-log-forwarder-observability/#observability-dashboard) to visualize them.
          - Save the configuration variables.
       3. **Deploy the logging function**
          - Create a new function within the application with these specifications:
            - **Function name**: a descriptive name (for example, `newrelic-logging-function`)
            - **Image source**: the New Relic logging Docker image, which you copy into a private repository in your Container Registry
            - **Memory allocation**: at least 128 MB
            - **Timeout**: 300 seconds, for adequate processing time
          - For the Docker image, pull the New Relic logging image from Docker Hub (`docker.io/newrelic/oci-log-forwarder:latest`, platform `linux/amd64`). Then authenticate with your regional Container Registry endpoint (`{region}.ocir.io`) using an auth token.
          - Tag and push the image to a private repository in your namespace in the same region as the function, and reference it in your function configuration.
          - Complete the function creation and deployment process.
          - To upgrade later, push the new image again and update the function to use it.
       4. **(Optional) Enable function logging**
          - Access the monitoring settings for your function application.
          - Enable function invocation logs by selecting or creating an appropriate log group, configuring log retention and access policies, and activating log collection for the function.
          - For more information, see the Oracle documentation on [exporting function log files](https://docs.oracle.com/en-us/iaas/Content/Functions/Tasks/functionsexportingfunctionlogfiles.htm).
  </Collapser>
  <Collapser id="terraform" title="Automate with Terraform">
    Because you selected logs, Terraform is the recommended setup method.<br />
    For the detailed integration steps, refer to the [OCI cloud integration guide](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#oci).<br />
  </Collapser>
</CollapserGroup>

<Step>

### Instrument your metric namespaces and log groups

Once you create the connection, the OCI page in New Relic shows separate views for metrics and logs, each with its own **Add instrumentation** control:

1. Click **Add instrumentation**, filtered to **Not instrumented** tab by default.
2. Expand a compartment to see its individual metric namespaces (or log groups), and select the ones you want to monitor. For logs, you can also turn on **Enable audit logs** to include OCI audit logs.
3. Confirm your selection. New Relic shows a summary of how many compartments and namespaces (or log groups) you're about to instrument. Then click **Deploy to OCI**.
4. After the deployment finishes in OCI, the compartment moves to the **Instrumented** tab, and its data appears at <DNT>**[one.newrelic.com](https://one.newrelic.com) > Infrastructure > OCI**</DNT>.
5. Switch to the **Logs** view and repeat steps 1–4 there.

Data can take up to 30 minutes to appear. If you don't see it after that, check the deployment status in the OCI console.

To instrument additional namespaces or log groups later, return to the OCI page in New Relic and repeat these steps.

</Step>

<Step>

### Find and use your data

Once your data starts appearing at <DNT>**[one.newrelic.com](https://one.newrelic.com) > Infrastructure > OCI**</DNT>, confirm the integration is working and put it to use:

1. Verify that your OCI account appears in the integrations list.
2. Confirm that you're receiving data (metrics and logs). To confirm logs, check either of these places:

   * The [logs UI](https://one.newrelic.com/launcher/logger.log-launcher): go to <DNT>**[one.newrelic.com](https://one.newrelic.com) > Logs**</DNT> and confirm that your OCI logs appear.
   * The [NRQL query tools](/docs/chart-builder/use-chart-builder/choose-data/use-advanced-nrql-mode-specify-data): run a NRQL query like this:

     ```sql
     SELECT * FROM Log
     ```
3. [Create alert conditions](/docs/alerts/create-alert/create-alert-condition/alert-conditions) for key OCI metrics to get proactive notifications about performance issues.
4. [Build custom dashboards](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) to visualize your OCI infrastructure data and monitor performance trends.

If you don't see data after 30 minutes, see [Troubleshooting](/docs/infrastructure/oci/troubleshoot).

</Step>
