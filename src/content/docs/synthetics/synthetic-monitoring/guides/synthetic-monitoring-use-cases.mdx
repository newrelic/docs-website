New Relic synthetic monitoring spans a spectrum: from lightweight uptime pings that cover availability broadly, to fully scripted API and browser journeys that exercise your most complex flows. On scripted monitors you can go further still, extending the runtime with your own npm modules to check almost anything reachable from your network. This guide maps **what each monitor type is good for**, with representative use cases and sample templates, so you can pick the right check for the job.

## Simple ping [#simple-ping]

Lightweight HTTP checks — the cheapest way to cover availability broadly. Send a request on a schedule and confirm the endpoint responds.

* **Endpoint reachable** — confirm a healthy status code, with no auth or scripting. *Templates:* URL returns 200; any 2xx or 3xx treated as healthy. *For example:* "Ping `https://api.acme.ai/health` every minute and alert if it isn't 200."
* **Response-time threshold** — alert when the endpoint responds slower than your budget. *Templates:* responds under 1s; responds under 3s.
* **Body string-match** — pass only when the response body contains an expected string. *Templates:* body contains "OK"; contains `"status":"healthy"`.

## Advanced ping [#advanced-ping]

Deeper network and TLS checks that localize where availability or latency breaks down.

* **SSL certificate validity** — verify the TLS certificate is valid and not expiring soon. *Templates:* certificate valid; not expiring within 30 days; validate expiry against a day offset.
* **Traceroute** — trace the network path and per-hop latency to the endpoint. *Templates:* path with per-hop latency; ICMP reachability.

## No-code API [#nocode-api]

Build API checks without writing code — point, click, and assert on status, latency, headers, and JSON.

* **Reliability and availability** — uptime, health, and rate-limit behavior. *Templates:* endpoint health and uptime; rate-limit and content-type headers; multi-step workflow.
* **Security and compliance** — authentication, TLS, and browser access controls. *Templates:* API key and auth validity (catch key rotation or expiry); TLS certificate validity; CORS headers.
* **Performance and SLAs** — latency budgets and usage telemetry. *Templates:* latency SLA budget; usage and cost telemetry to NRDB.
* **Contract and schema** — validate the response shape. *Templates:* response contract (fields and types); tool or function-call shape; schema validation.

## Scripted API [#scripted-api]

Full JavaScript control with the `$http` API — chain requests, parse responses, write custom assertions, and pull in your own npm modules. This is where scripted monitors reach well beyond plain HTTP.

* **Network and protocol** — non-HTTP connectivity. *Templates:* DNS lookups; TCP and TLS port checks; TCP request and response; WebSocket; MQTT; LDAP; FTP and SFTP; SMTP. *For example:* "Check that TCP port 5432 on `db.acme.internal` is open every minute."
* **Certificates and security** — client certificates and identity. *Templates:* mutual-TLS (client certificate) API call; SAML metadata certificate validation; email blocklist check.
* **Cloud and SaaS integration** — reach into cloud providers with native auth. *Templates:* check an S3 object's size or metadata; read an Azure Key Vault secret; call GCP APIs via a service-account signed JWT.
* **Performance and SEO** — external quality signals. *Templates:* Lighthouse audit via the PageSpeed API; Google Search Console analytics.
* **New Relic data (NRDB/NRQL)** — run a NRQL query from the monitor and assert or alert on the result. *Templates:* NRQL with `COMPARE WITH` deviation alerting; NRQL value validation.

## No-code browser [#nocode-browser]

Record real user journeys with no code. New Relic replays them from global locations and flags broken paths, slow pages, and missing elements.

* **Page availability** — confirm a page loads successfully. *Templates:* page loads (200 plus render); title contains expected text.
* **Content and element checks** — assert that specific elements or text are present. *Templates:* element is visible; text present. *For example:* "Check the 'Add to cart' button is visible on the product page."
* **Core Web Vitals** — track load time and key performance signals. *Templates:* load under 3s.

## Scripted browser [#scripted-browser]

Selenium-powered scripted journeys with the `$browser` API — full control over complex, conditional, or authenticated flows the recorder can't capture, extendable with npm modules.

* **Browser UX and content** — crawl, time, and verify on-page or document content. *Templates:* broken-link checker; file-download timing; PDF content verification. *For example:* "Crawl the homepage and fail if any link is broken."
* **Cloud and SaaS integration** — push browser artifacts to cloud storage. *Templates:* capture screenshots and upload to S3.

<Callout variant="tip" title="Where custom code fits">
  **Scripted API** and **scripted browser** monitors run your JavaScript, so you can `require()` your own npm modules — the WebSocket, MQTT, LDAP, SFTP, cloud-SDK, and PDF checks above are all powered that way. On **private locations**, those modules install from your own registry and run inside your network. Store any keys or tokens as [secure credentials](/docs/synthetics/synthetic-monitoring/using-monitors/store-secure-credentials-scripted-browsers-api-tests/).
</Callout>
