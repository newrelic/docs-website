New Relic synthetic monitoring spans a spectrum: from lightweight uptime pings that cover availability broadly, to fully scripted API and browser journeys that exercise your most complex flows. On scripted monitors you can go further still, extending the runtime with your own npm modules to check almost anything reachable from your network.

## Sample use cases [#sample-use-cases]

What you can monitor, organized by monitor type. Each monitor type lists its common use-case buckets with a short description.

### Simple ping [#simple-ping]

Lightweight HTTP checks — the cheapest way to cover availability broadly.

* **Endpoint reachable** — confirm the endpoint answers with a healthy status code, no auth or scripting required.
* **Response-time threshold** — alert when the endpoint responds slower than your budget.
* **Body string-match** — pass only when the response body contains an expected string.

### Advanced ping [#advanced-ping]

Deeper network and TLS checks that localize where availability or latency breaks down.

* **SSL certificate validity** — verify the TLS certificate is valid and not expiring soon.
* **Traceroute** — trace the network path and per-hop latency to the endpoint.

### No-code API [#nocode-api]

Build API checks without writing code — point, click, and assert on status, latency, headers, and JSON.

* **Reliability and availability** — uptime, health, and rate-limit behavior of your API.
* **Security and compliance** — authentication and key validity, TLS certificates, and CORS.
* **Performance and SLAs** — latency budgets and usage telemetry.
* **Contract and schema** — validate that the response shape stays well-formed.

### Scripted API [#scripted-api]

Full JavaScript control with the `$http` API — chain requests, parse responses, write custom assertions, and pull in your own npm modules.

* **Network and protocol** — non-HTTP connectivity: DNS, TCP, mail, file transfer, and messaging.
* **Certificates and security** — client certificates, mutual TLS, SAML metadata, and blocklist checks.
* **Cloud and SaaS integration** — reach into AWS, Azure, and GCP with native auth.
* **Performance and SEO** — Lighthouse, Core Web Vitals, and Search Console signals.
* **New Relic data (NRDB/NRQL)** — run NRQL from a monitor and assert or alert on the result.

### No-code browser [#nocode-browser]

Record real user journeys with no code, replayed from global locations.

* **Page availability** — confirm a page loads successfully from global locations.
* **Content and element checks** — assert that specific elements or text are present.
* **Core Web Vitals** — track load time and key performance signals.

### Scripted browser [#scripted-browser]

Selenium-powered scripted journeys with the `$browser` API — full control over complex, conditional, or authenticated flows, extendable with npm modules.

* **Browser UX and content** — crawl links, time downloads, and verify on-page or document content.
* **Cloud and SaaS integration** — push browser artifacts, such as screenshots, to cloud storage.

<Callout variant="tip" title="Where custom code fits">
  **Scripted API** and **scripted browser** monitors run your JavaScript, so you can `require()` your own npm modules — the protocol, cloud-SDK, and document checks above are all powered that way. On **private locations**, those modules install from your own registry and run inside your network. Store any keys or tokens as [secure credentials](/docs/synthetics/synthetic-monitoring/using-monitors/store-secure-credentials-scripted-browsers-api-tests/).
</Callout>
