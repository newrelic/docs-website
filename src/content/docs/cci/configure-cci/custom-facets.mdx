Custom facets let you create virtual dimensions that group cloud costs based on rules you define. Once created, a facet appears as a new dimension across <DNT>**Cost Overview**</DNT>, budgets, alerts, recommendations, and unit economics — without needing to re-apply filters each time.

Custom facets work the same way as the built-in <DNT>**Custom Dimensions**</DNT> already visible in <DNT>**Cost Overview**</DNT> (for example, account name, cell type, environment). The difference is that custom facets are dimensions you define yourself by combining tags and conditions from your cloud accounts.

## How custom facets work

When you define a facet, you specify a set of conditions. The system evaluates each cost row against those conditions and assigns the facet value to matching rows. That value then becomes available as a dimension throughout CCI.

For example, you could create a facet named `platform-team` with conditions that match specific AWS tags, account names, and regions. Every cost row matching those conditions is grouped under `platform-team`, which you can then use to build budgets, set alert conditions, or analyze costs in unit economics.

## Create a custom facet

1. In CCI, go to <DNT>**Configuration**</DNT> and select <DNT>**Custom Facets**</DNT>.
2. Click <DNT>**Create facet**</DNT>.
3. Enter a name for the facet value.
4. Add one or more conditions. Each condition specifies:
   - A **dimension** (for example, account, cloud provider, AI model)
   - An **operator** (for example, `in`, `not in`)
   - One or more **values**
5. Save the facet.

The system processes the rules and assigns the facet value to all matching cost rows. The facet appears as a new dimension in <DNT>**Cost Overview**</DNT> and other CCI features.

## Import facets using YAML

To define multiple facets at once or migrate rules from another system, upload a YAML configuration file.

1. In <DNT>**Custom Facets**</DNT>, click <DNT>**Upload YAML**</DNT>.
2. Select your configuration file.
3. The system validates the file and applies the rules.

To see the required file structure, click <DNT>**Download sample YAML**</DNT>. Use the sample as a template for your own configuration.

## Backfill historical data

By default, a new facet applies to cost data from the date it was created. To apply the same rules to historical data, use backfill.

1. After creating or uploading your facet rules, select the <DNT>**Backfill**</DNT> option.
2. Specify the start date for the historical period you want to include.
3. The system reprocesses the matching cost rows for that period and populates the facet dimension retroactively.

## Limits and exclusions

| Item | Detail |
|------|--------|
| Maximum facets per user | 12 |
| Resources excluded | Deleted or inactive resources are not evaluated against facet rules and do not appear in facet results |

## Use facets across CCI

Once created, a facet is available as a dimension in:

- <DNT>**Cost Overview**</DNT>: Filter and group costs by the facet dimension
- <DNT>**Budgets**</DNT>: Create a budget scoped to a specific facet value
- <DNT>**Alert conditions**</DNT>: Set alerts triggered by spend on a facet group
- <DNT>**Unit economics**</DNT>: Use a facet as the denominator or numerator dimension for cost-per-unit calculations
- <DNT>**Recommendations**</DNT>: Get optimization recommendations scoped to the facet group

## Use cases

### Multi-cloud cost grouping

If the same workload runs across AWS, Azure, and GCP, you can combine all three into a single facet group. Define conditions that match the relevant accounts, services, or tags from each provider. The resulting facet lets you view and act on the combined cost without managing separate filters for each cloud.

### Cost per transaction across clouds

To calculate cost per transaction for a service that spans multiple cloud providers:

1. Create a facet that groups the relevant AWS and Azure resources for that service.
2. In <DNT>**Unit economics**</DNT>, select the facet as the cost dimension.
3. Divide by your transaction metric to get cost per transaction.

This gives you a unified view of the cost regardless of which cloud the traffic is processed on.

### Dimensional budgets for teams or projects

Create a facet that matches the tags or accounts belonging to a specific team or project. Then build a budget directly on that facet so the team can track their cloud spend without needing a separate cloud account per team.
