Custom facets let you create virtual dimensions that group cloud costs based on rules you define. After you create a facet, it's available as a dimension across CCI features without needing to reapply filters each time.

Custom facets work the same way as the built-in <DNT>**Custom Dimensions**</DNT> visible in <DNT>**Cost Overview**</DNT> (for example, account name, team name, and environment). The difference is that custom facets are dimensions you define yourself by combining tags, cloud dimensions, and conditions from your cloud accounts.

Use custom facets when your cloud tags have gaps in coverage, or when you need to combine conditions across dimensions. For example, you can match costs where a service belongs to a group, a team name matches a pattern, or you exclude an environment. Because custom facets are part of the data model rather than a filter applied per session, you can use them to build budgets, set alert conditions, and calculate unit economics.

## How custom facets work

A custom facet is a dimension made up of one or more named values. For each value, you define a set of conditions. The system evaluates each cost row against those conditions and assigns matching rows to the corresponding value. Rows that match no conditions receive the default value you specify. The facet appears as a dimension throughout CCI.

For example, you could create a facet named `platform-team` with conditions that match AWS tags, account names, and regions. The system assigns every cost row matching those conditions to `platform-team`, which you can use to build budgets, set alert conditions, or analyze costs in unit economics.

## Use cases

### Multi-cloud cost grouping

If the same workload runs across AWS, Azure, and GCP, you can combine all three into a facet group. Define conditions that match the accounts, services, or tags from each provider. The facet lets you view and act on the combined cost without managing filters for each cloud.

### Cost per transaction across clouds

To calculate cost per transaction for a service that spans cloud providers:

1. Create a facet that groups the AWS and Azure resources for that service.
2. In <DNT>**Unit economics**</DNT>, select the facet as the cost dimension.
3. Divide by your transaction metric to get cost per transaction.

This gives you a view of the cost regardless of which cloud processes the traffic.

### Dimensional budgets for teams or projects

Create a facet that matches the tags or accounts belonging to a team or project. Build a budget on that facet so the team can track their cloud spend without needing a cloud account per team.

## Limits and exclusions

The following limits apply to custom facets.

| Item | Detail |
|------|--------|
| Maximum facets | The limit is 90 per connection, counting raw tags, Kubernetes labels, and custom facets combined. |
| Resources excluded | The system doesn't evaluate deleted or inactive resources against facet rules, and they don't appear in facet results. |

## Create a custom facet

You can create facets through the UI or by uploading a YAML file.

### Create using the UI

1. Go to <DNT>[**one.newrelic.com**](https://one.newrelic.com)</DNT> > <DNT>**All Capabilities**</DNT> > <DNT>**Cloud Cost Intelligence**</DNT> > <DNT>**Custom Facets**</DNT>.
2. Click <DNT>**Create facet**</DNT>.
3. Enter a <DNT>**Name**</DNT>, <DNT>**Description**</DNT>, and <DNT>**Default value**</DNT> for the facet.
4. Click <DNT>**+ Add facet value**</DNT>.
5. Add one or more conditions. Each condition specifies:
   - **Dimension** (for example, account, cloud provider, and AI model)
   - **Operator** (for example, `in`, `not in`, `equals`, and `regex`)
   - **Values** (one or more)
6. Save the facet.
   - Run the generated NRQL in the query editor to verify correctness and expected facet values.

The facet appears as a dimension in <DNT>**Cost Overview**</DNT> and other CCI features, after the next billing export file processing (4-8 hours).

### Import using YAML

To define multiple facets at once or migrate rules from another system, upload a YAML configuration file.

1. In <DNT>**Custom Facets**</DNT>, click <DNT>**Upload YAML**</DNT>.
2. Select your configuration file.

The system validates the file and applies the rules. To see the required file structure, click <DNT>**Download sample YAML**</DNT> and use the sample as a template.

### Backfill historical data

By default, a facet applies to cost data from the date you created it. To apply the same rules to historical data, use backfill.

1. After creating or uploading your facet rules, select the <DNT>**Backfill**</DNT> option.
2. Specify the start date for the historical period you want to include.

The system reprocesses the matching cost rows for that period and populates the facet dimension. Backfill processing begins after the facet reaches active status and completes within 8 hours. To monitor progress, go to the <DNT>**Audit**</DNT> tab on the <DNT>**Custom Facets**</DNT> page.

## Use facets across CCI

After you create a facet, it's available as a dimension in the following CCI features:

- <DNT>**Cost Overview**</DNT>: Filter and group costs by the facet dimension
- <DNT>**Budgets**</DNT>: Create a budget scoped to a facet value
- <DNT>**Query your data and Alert conditions**</DNT>: Set alerts triggered by spend on a facet group
- <DNT>**Unit economics**</DNT>: Use a facet as the denominator or numerator dimension for cost-per-unit calculations
- <DNT>**Recommendations**</DNT>: Get optimization recommendations scoped to the facet group
