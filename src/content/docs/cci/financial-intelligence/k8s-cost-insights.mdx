The <DNT>**Kubernetes Costs**</DNT> page shows how much each of your Kubernetes clusters costs, broken down by CPU, memory, unused, and unallocated resources. It uses our telemetry data to correlate cloud billing with cluster-level usage, so you can see exactly where your spending goes and where you can reduce waste.

## Prerequisites [#prerequisites]

Before the <DNT>**Kubernetes Costs**</DNT> page can show data, you need to tell Cloud Cost Intelligence (CCI) which New Relic accounts hold your Kubernetes telemetry. If you skip this step, you may see AWS costs in CCI but no Kubernetes costs.

### Add telemetry accounts [#add-telemetry-accounts]

CCI allocates Kubernetes costs using `K8sContainerSample` data. It joins that data with your cloud billing data on the instance ID. CCI can only read `K8sContainerSample` data from accounts you've added as telemetry accounts.

To add these accounts, complete the following steps:

1. Go to <DNT>**Cloud Cost Intelligence > Settings**</DNT>, then select the <DNT>**Telemetry data**</DNT> tab.
2. From the <DNT>**Accounts**</DNT> dropdown, select every New Relic account that has `K8sContainerSample` data. To check an account, run this query in it: `SELECT count(*) FROM K8sContainerSample SINCE 1 day ago`.
3. Click <DNT>**Apply**</DNT>.

Once you add the accounts, CCI pulls the `K8sContainerSample` data and starts allocating Kubernetes costs.

<Callout variant="important">
If your Kubernetes clusters report to more than one New Relic account, add each one. Costs from clusters in accounts that aren't added won't appear on the <DNT>**Kubernetes Costs**</DNT> page.
</Callout>

If you've added the right accounts and still see no Kubernetes costs, see [Troubleshoot](#troubleshoot).

## Filters and customization

### Cloud provider filters

To filter your cost data by cloud provider, select an option from the dropdown menu at the top left of the page:
- <DNT>**All**</DNT>: All cloud providers
- <DNT>**AWS**</DNT>: Amazon Web Services only
- <DNT>**Azure**</DNT>: Microsoft Azure only

### Date range selector

At the top right of the page, use the date range selector to do any of the following:
- Choose a predefined time period
- Set custom start and end dates
- View costs in your preferred timezone (UTC displayed by default)

### Engineering costs filter

If your organization uses cost allocation tags, you can filter by the <DNT>**Engineering costs**</DNT> tag to narrow analysis to specific teams, projects, or cost centers tagged in your cloud environment.


## Summary

The Summary section displays four cost metrics for your selected time period:

| Metric | Description |
|---|---|
| Total cost | Aggregate spending for all Kubernetes clusters, with percentage change compared to the previous period |
| Average cost (Daily) | Daily average spending, with percentage change |
| Unused cost | Cost of resources your cluster has allocated but that aren't receiving requests, with percentage change |
| Unallocated cost | Cost of cluster resources not allocated to any source, with percentage change |

## Insights

The Insights section provides two visualization widgets to help you analyze your Kubernetes costs.

### Cost Trends

The <DNT>**Cost Trends**</DNT> widget displays a line chart showing how your Kubernetes costs change over time. Use the view options to switch between <DNT>**Hourly**</DNT>, <DNT>**Daily**</DNT>, <DNT>**Weekly**</DNT>, or <DNT>**Monthly**</DNT> views.

### Top 20

The <DNT>**Top 20**</DNT> widget displays your highest cost areas using a tree chart visualization. By default, it shows the top 20 clusters by cost. You can customize the view with the following options:

- <DNT>**Dropdown filter**</DNT>: Select what to display (<DNT>**Cluster name, by cost**</DNT>)
- <DNT>**Group by**</DNT>: Choose dimensions to group cost data
- <DNT>**View by**</DNT>: Switch between <DNT>**Tree chart**</DNT> and other visualization formats

## Cost & Usage Analysis

The <DNT>**Cost & Usage Analysis**</DNT> section presents a table with a breakdown of resource usage and costs by cluster name:

| Column | Description |
|---|---|
| Cluster name | Name of your Kubernetes cluster |
| CPU cost | Cost attributed to CPU usage for each cluster |
| CPU usage | Percentage of CPU resources consumed by each cluster |
| Memory cost | Cost associated with memory usage for each cluster |
| Memory usage | Percentage of memory resources used by each cluster |
| Unused cost | Cost of resources your cluster has allocated but that aren't receiving requests |
| Unallocated cost | Cost of cluster resources not allocated to any source |
| Total cost | Combined cost for each cluster across all resource usage (sortable) |

If unused or unallocated costs are consistently high for a cluster, it may be over-provisioned. See [Cost optimization recommendations](/docs/cci/financial-intelligence/cci-recommendations) for right-sizing guidance.

## Unused vs. unallocated costs

These cost dimensions help you measure cluster efficiency:

| Cost type | Definition | Example |
|---|---|---|
| Unused cost | Resources your cluster has allocated but that aren't receiving requests. | Total cost: $5.60; used: $4.64; unused cost: $0.96 |
| Unallocated cost | Cluster resources not allocated to any source. | Node cost: $10.00; allocated to workloads: $7.50; unallocated cost: $2.50 |

<Callout variant="tip">
Select any cluster to view its <DNT>**Cost Trends**</DNT>, <DNT>**Cost Breakdown (Total vs Used)**</DNT>, and information about unused and unallocated costs.
</Callout>

## Troubleshoot [#troubleshoot]

### AWS costs appear but no Kubernetes costs show up

You haven't added your telemetry accounts yet, or not all accounts are added. See [Add telemetry accounts](#add-telemetry-accounts).

### Some clusters are missing from the page

Your Kubernetes clusters may report to more than one New Relic account. Make sure you've added every reporting account under <DNT>**Settings > Telemetry data**</DNT>.

### You've added the right accounts but costs still don't appear

Contact New Relic customer care.

For issues with CCI setup, integrations, or permissions, see [Troubleshoot Cloud Cost Intelligence setup](/docs/cci/troubleshooting/troubleshooting).
