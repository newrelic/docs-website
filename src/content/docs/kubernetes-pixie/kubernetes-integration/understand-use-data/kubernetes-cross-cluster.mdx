Modern Kubernetes environments have evolved into complex, **multi-cluster fleets**, but traditional observability tools often provide only a fractured, siloed view of individual clusters. This Kubernetes cross-cluster UI provides a unified command center that transforms this multi-cluster complexity into fleet-wide clarity.

This unified view helps Platform Engineers and SREs to:
* **Unify fleet-wide observability** on a single dashboard that's compatible with clusters monitored by New Relic agents or OpenTelemetry.
* **Accelerate root cause analysis** with a guided triage workflow.
* **Reduce costs** by identifying wasted resources across the entire fleet.
* **Empower developers** with an application-centric view for self-service.

## Access the new UI [#access]

You can access the new Kubernetes cross-cluster UI from the Kubernetes option in the left navigation in the New Relic platform.

To access the Kubernetes cross-cluster UI:

1. Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Kubernetes**</DNT>
2. Click the **Try it out** button at the top right corner of the page.

To share feedback on your experience with the UI, click **Send us feedback** in the banner at the top of the page. To see other Kubernetes entity types, such as CronJobs and PVCs, click **See all Kubernetes entities**.

By default, the UI shows data for the last 5 minutes. The scorecards, line chart, and table all use the time range you select in the time picker.

The Kubernetes cross-cluster UI is structured to provide both a high-level overview and deep-dive capabilities into your entire Kubernetes fleet. The main components of the UI include:

* **Account picker and filter bar**: Choose the accounts, clusters, and nodes to include. For more information, see [Choose accounts and filter entities](#filter).
* **Colored scorecards**: Display relevant high-level metrics to surface the most important issues that need attention across the entire fleet. For more information, see [Scorecards and line chart](#scorecards).
* **Line chart**: Provides the **evolution of the metric** over the selected time range for trend analysis.
* **Table**: Lists the clusters, nodes, or workloads in your fleet with **detailed metric data** for each one under the five main tabs. For more information, see [Table](#table).
* **Popovers**: Show details and links for an entity or a metric value when you hover over it in the table. For more information, see [Popovers](#popovers).

## Choose accounts and filter entities [#filter]

Use the account picker and the filter bar at the top of the page to choose which part of your fleet the UI shows:

* **Accounts**: To view clusters from more than one account, select **All accounts** in the account picker. An **Accounts** pill appears in the filter bar. Click it to select up to 30 accounts. The UI remembers your selection. If your selected accounts contain more than 500 clusters, a **Cluster limit exceeded** warning appears and the data is limited to the first 500 clusters.
* **Entity filters**: Filter using **tags and values** of your Kubernetes cluster and host (node) entities. To isolate a single cluster, hover over its name in the table and click the filter icon next to it.
  * Node filters don't apply to the **Workloads** tab. When you filter by node, the **Workloads** tab shows the message **Node filters are not applied to workloads**.

Your filters are saved in the URL, so you can share a filtered view with others.

## Scorecards and line chart [#scorecards]

Scorecards summarize each metric across all the clusters that match your filters. They're grouped by category, such as **Nodes**, **Pods**, or **Events**.

* **Values**: Ratios such as `2/436` show the number of affected entities out of the total. Large counts are abbreviated, for example `3.5K` or `1.2M`.
* **Color-coding**: A scorecard turns orange or red when its value meets a severity threshold. Otherwise, it isn't colored. Ratio scorecards are colored based on their percentage. For example, `2/436` unhealthy nodes is about 0.5%. For the thresholds of each metric, see [Tab-specific metrics](#tab).
* **Ordering the table**: Clicking a scorecard **orders the table** in the context of that metric, surfacing the entities with the most critical values at the top. It also shows the metric in the line chart. Sorting a table column selects the matching scorecard.
* **Aggregation**: Some scorecard groups have an **avg**, **p95**, **p99**, and **max** toggle, which switches the scorecard between the average, 95th percentile, 99th percentile, and maximum values. The toggle is available for the **Performance** group on the **Overview** tab, and for the **CPU** and **Memory** groups on the **Performance**, **Resources**, and **Workloads** tabs. It changes the scorecards and the line chart. The table always shows average values.

The line chart shows the selected metric over the time range, with one line for each of the top 10 entities in the table, in the table's current order. Hover over a table row to highlight its line. For **Unhealthy workloads**, **Pods unavailable**, and **Pods missing**, the line chart is split into separate charts for deployments, daemonsets, and statefulsets.

## Table [#table]

The table lists the entities in your fleet and their metric values for the selected tab:

* **Overview**: One row for each cluster.
* **Health**, **Performance**, and **Resources**: One row for each cluster or node. Use the **Group by** dropdown to switch between **Cluster** and **Node**.
* **Workloads**: One row for each deployment, daemonset, or statefulset. Use the **Show** dropdown to choose which workload types to list.

Like the scorecards, table cells are color-coded orange or red to draw attention to entities with values that meet a **severity threshold**. Table thresholds can be different from scorecard thresholds. For details, see [Tab-specific metrics](#tab).

Use these controls to focus the table:

* **Include healthy entities**: Turn off this toggle to list only the entities that have at least one orange or red value, including values in hidden columns. Alerts don't affect this toggle.
* **Search**: Filter the table rows by entering **free text** that matches a cluster, node, workload, namespace, or workload type name. On the **Workloads** tab, the search looks for workloads whose name, namespace, or cluster name matches the text.
* **Sorting**: Click a column header to sort the table by that column.
* **Columns**: Click the columns icon to show or hide columns. Columns that identify the entity, such as **Cluster**, can't be hidden. On the **Workloads** tab, the **Account**, **CPU usage (requests)**, **Memory usage (limits)**, **Pod evictions**, and **Container image restarts** columns are hidden by default. The other tabs show all columns by default. To restore the default columns, click **Reset**, then click **Apply**. Your column choices are saved for each tab.

Along with the metric columns, the table includes these columns:

* **Account**: The account the entity reports to.
* **Alerts**: The number of open critical and high-priority issues for the entity. Hover over the count to see up to five of the issues, or click **See all** to view all of them. This column always shows the issues that are currently open, regardless of the selected time range. It isn't available on the **Overview** tab.
* **Services**: On the **Workloads** tab, the services and integrations related to the workload, such as APM services, Prometheus, NGINX Ingress, Argo CD, Istio, Envoy, CoreDNS, KEDA, or Calico. Hover over a logo to see its entity popover.
* **Logs**: Opens the logs for the entity.
* **Warning events**: Click the count to see the Kubernetes warning events for the entity.

Clusters, nodes, and workloads that have stopped reporting still appear in the table with their data for the selected time range. Clusters and workloads that stopped reporting appear only when no filters are applied, and nodes only when no node filters are applied. Their names aren't links, and they don't have popovers or logs.

## Popovers [#popovers]

Hover over the table to see more details about an entity or a metric value without leaving the page.

### Entity popover [#entity-popover]

Hover over a cluster, node, workload, or namespace name in the table, or over a logo in the **Services** column, to open the entity popover. It includes:

* **Header**: The entity name, which links to the entity, and its type and account. Click **See in map** to open the entity's relationship map. For deployments, daemonsets, namespaces, and nodes monitored by the New Relic Kubernetes integration, click **Kubernetes Description** to view the Kubernetes description of the resource.
* **Tags**: The entity's team (`nr.team`) and environment (`environment`) tags, if they're set.
* **Golden metrics**: Key metrics for the entity, each with a sparkline and its percentage change. For namespaces, these are the total, unavailable, and missing pods.
* **Related entities**: The infrastructure resources related to the entity, sorted by their alert status.

To open an entity's overview page, click its name in the table.

### Metric popover [#metric-popover]

Hover over a metric value with a dotted underline to open the metric popover. It includes:

* **Header**: The entity name, type, and account, and the **See in map** button.
* **Chart**: The metric for that entity over the selected time range, with its value and its percentage change compared to the previous period of the same length. For **Unhealthy workloads**, the popover shows separate charts for deployments, daemonsets, and statefulsets. For **Pods ready/total**, it shows separate charts for ready pods and total pods.
* **View in navigator**: Opens the [Kubernetes navigator](/docs/kubernetes-pixie/kubernetes-integration/understand-use-data/kubernetes-cluster-explorer/#navigator-preview), filtered to that entity and metric.

Metric popovers aren't available for **Warning events**.

## Drill-down capabilities for triage [#drill-down]

The cross-cluster UI is specifically designed to accelerate root cause analysis with a **guided triage workflow**. The primary mechanism for this deep investigation is the ability to drill down from a fleet-wide metric to a single entity:

* **From scorecard to entity ranking:** When you click a **colored scorecard** (for example, **Unhealthy nodes**), the table immediately re-sorts. This places the entities with the worst values for that specific metric at the top, enabling you to identify where the issue is most critical across your entire fleet.
* **From table metric to Kubernetes navigator:** Hover over a metric value for a cluster, node, or workload, and click **View in navigator** in the popover. The **Kubernetes navigator** opens filtered to that entity and metric, allowing you to continue your investigation with a deep dive. For example, from **Unhealthy nodes**, the navigator opens with the **Node Health** metric for that cluster.
* **From table row to entity details:** Click an entity name to open its overview page, or hover over it to see its golden metrics and related entities.
* **From warning count to events:** Click a **Warning events** count to see the Kubernetes warning events for that entity.

## Tab-specific metrics [#tab]

The UI is organized into five main tabs:

* [Overview](#overview)
* [Health](#health)
* [Performance](#performance)
* [Resources](#resources)
* [Workloads](#workloads)


Each tab provides specific metrics both at the aggregate (Scorecard) and the cluster, node, or workload (Table) level, along with their associated color-coded thresholds for quick triage. Thresholds labeled `Scorecard:` apply to the fleet-wide scorecard, and thresholds labeled `Table:` apply to each table row. When the scorecard and the table use the same thresholds, only one set is listed. Values that don't meet a threshold aren't colored.
