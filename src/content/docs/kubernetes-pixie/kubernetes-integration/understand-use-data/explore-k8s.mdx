Modern Kubernetes environments have evolved into complex, **multi-cluster fleets**, but traditional observability tools often provide only a fractured, siloed view of individual clusters. Kubernetes monitoring in New Relic opens on a fleet-wide view that turns that complexity into clarity. 

This unified view helps platform engineers and SREs to:
* **Unify fleet-wide observability** on a single dashboard that's compatible with clusters monitored by New Relic agents or OpenTelemetry.
* **Accelerate root cause analysis** with a guided triage workflow.
* **Reduce costs** by identifying wasted resources across the entire fleet.
* **Empower developers** with an application-centric view for self-service.

## Access the UI [#access]

This is the default Kubernetes experience in New Relic. To open it:

Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Kubernetes**</DNT>


## Main components of the UI [#components]

The UI is structured to provide both a high-level overview and deep-dive capabilities into your entire Kubernetes fleet. 
The main components include:

* **Entity filters**: Filter and triage issues using **tags and values** at the **cluster or node level**.
    * **Cluster filter**: Filter to isolate the UI to a single or smaller set of Kubernetes clusters.
* **Colored scorecards**: Display relevant high-level metrics to surface the most important issues that need attention across the entire fleet.
    * Click a scorecard to **order the table** in the context of that metric, surfacing the clusters and nodes with the most critical issues at the top.
    * It also enables a **line chart** to visualize the metric's evolution over the selected time range.
    * Select  <DNT>**`avg`**</DNT>, <DNT>**`p95`**</DNT>, <DNT>**`p99`**</DNT>, or <DNT>**`max`**</DNT> to update the scorecards and line chart. The breakdown table always displays average values.
* **Line chart**: Provides the **evolution of the metric** over the selected time frame for trend analysis.
* **Table**: Lists all entities in the fleet and provides **detailed metric data** for each cluster under the five main [tabs](#tab).
    * **Health focus**: The table provides a filter to only list "unhealthy" entities to focus your attention where it is really needed.
    * **Search**: A text search bar allows you to filter table rows based on **free text** entered.
    * **Color-coding**: Like the scorecards, table cells are color-coded (Yellow, Red) to quickly draw attention to entities with issues that meet a specific [severity threshold](#tab).
    * **Column chooser**: The Workloads tab ships a lean default column set and lets you add or remove columns. Your column selection persists across sessions.
* **Workload type selector**: Narrow the Workloads tab to a specific workload type, such as Deployments, DaemonSets, or StatefulSets.
* **Feedback button**: Lets you easily share feedback on your experience with the UI.


## Multi-account fleet visibility [#multi-account]

Clusters from the New Relic accounts you have access to appear together in the same fleet view, so monitoring a fleet that spans multiple accounts doesn't require switching account context.

To see clusters from more than one account:

1. In the account picker, select <DNT>**All accounts**</DNT>.
2. Use the account filter in the entity filter bar to narrow the view to the specific accounts you need.

## Entity popovers [#popover]

Selecting an entity in the table opens a popover that gives you context on that entity without leaving the fleet view:

* **Golden metrics**, a snapshot of the entity's key performance metrics.
* **Related entities**, grouped and sorted by type, which you can open in a stacked view alongside your current context.
* **Links to related applications**, marked with an external link icon where they open the APM experience rather than a stacked view.
* **Object description**, which opens the manifest for the selected Kubernetes object.
* **Team**, if one is set for the entity.
* **Dashboard**, a link to the entity's corresponding dashboard.

## Correlate with APM, events, logs, and alerts [#correlate]

The fleet view is designed so you don't have to abandon it to correlate signals and reduce MTTR:

* **APM insights**: The Workloads view surfaces application performance data for the applications running in a workload, so you can move between infrastructure health and application performance in one place.
* **Alerts**: Open alerts are surfaced against clusters, nodes, and workloads, including alert indicators in the Workloads tab, and open in a stacked view for immediate context. Open alerts appear regardless of the time range you have selected, so an active alert is never hidden by a narrow time picker.
* **Events and logs**: Kubernetes events and logs for an entity open in a stacked view alongside your current context, so you can correlate signals without losing your place in the triage flow.

`Scorecard:` thresholds apply to the scorecards and `Table:` thresholds apply to table rows.
When they're the same, only one set is listed. Counts cover the selected time range.
