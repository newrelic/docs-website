Mobile supportability metrics are a specialized set of metrics that help you understand the health and performance of your New Relic mobile agents. They're distinct from [APM supportability metrics](/docs/apm/supportability-metrics/introduction): mobile supportability metrics are specific to mobile applications, providing insight into how your New Relic agents operate within your mobile environment.

These metrics are automatically collected by the mobile agents about their own operation, offering insight into agent behavior, feature adoption, and the effectiveness of your monitoring configuration across your mobile applications.

<Callout variant="important">
  You're charged for supportability metric ingest as part of your New Relic data consumption. These metrics provide valuable troubleshooting and optimization information that can help you resolve issues faster and improve mobile app performance.
</Callout>

## What are mobile supportability metrics used for? [#what-are-mobile-supportability-metrics]

Mobile supportability metrics provide essential data for maintaining optimal monitoring of your mobile applications. They help you:

* **Troubleshoot monitoring issues**: Identify why certain data might not be appearing in your New Relic dashboards for your mobile apps
* **Validate configuration**: Confirm that features like crash reporting, network instrumentation, or handled exceptions are working correctly on your mobile devices
* **Monitor agent performance**: Track the resource usage of the agent itself and identify potential bottlenecks it might cause
* **Optimize feature usage**: Understand which agent features your mobile application is utilizing most effectively
* **Track agent health**: Monitor connection status to New Relic's data collection services and the success rates of data transmission from your mobile agents

## Identifying mobile supportability metrics [#identifying-metrics]

All mobile supportability metrics can be identified and queried using [NRQL](/docs/nrql/get-started/introduction-nrql-new-relics-query-language/) because they consistently use the `Supportability/` prefix in their metric names. A related set of supportability metrics for crash ingest instead begins with `Custom/Mobile/Crash/`.

## Common categories and examples of mobile supportability metrics [#metric-categories]

Each mobile agent (Android, iOS, and hybrid frameworks like Flutter and React Native) may generate unique supportability metrics based on its platform and specific features, but they share these common categories.

<Callout variant="tip">
  iOS-specific metrics can also apply to tvOS or watchOS (for example, `Supportability/Mobile/tvOS/Native/Collector/data/Output/Bytes`), or to hybrid platforms like Flutter or React Native (for example, `Supportability/Mobile/iOS/ReactNative/Collector/data/Output/Bytes`).
</Callout>

### Agent health metrics

Track the overall health of the agent's tracing, error handling, and connection to New Relic's collector.

**Example metrics:**
* `Supportability/AgentHealth/HealthyActivityTraces`: Tracks healthy activity traces (Android)
* `Supportability/AgentHealth/UnhealthyActivityTraces`: Tracks unhealthy activity traces (Android)
* `Supportability/AgentHealth/ErrorsDropped`: Indicates errors dropped by the agent (Android)
* `Supportability/AgentHealth/TransactionsDropped`: Number of transactions dropped (Android, iOS)
* `Supportability/AgentHealth/IgnoredTraces`: Number of ignored traces (Android)
* `Supportability/AgentHealth/Collector/connection/errors`: Records connection errors to the collector (Android)
* `Supportability/AgentHealth/Collector/Connect/{time}`: Sampled time for collector connections (Android)
* `Supportability/AgentHealth/Collector/Harvest/{response time}`: Sampled time for data harvests (Android)
* `Supportability/AgentHealth/Payload/Removed/Stale`: Counter for stale payloads removed (Android)
* `Supportability/AgentHealth/Session/InvalidDuration`: Sampled time for sessions with invalid durations (Android)
* `Supportability/AgentHealth/Network/Request/ResponseTime/InvalidDuration`: Sampled time for network requests with invalid response durations (Android)

### Crash and Hex upload metrics

Monitor the upload success and timing of crash reports and Hex (handled exception) data.

**Example metrics:**
* `Supportability/AgentHealth/Crash/UploadTime`: Sampled time for crash uploads (Android)
* `Supportability/AgentHealth/Crash/FailedUpload`: Counter for failed crash uploads (Android)
* `Supportability/AgentHealth/Crash/Removed/Stale`: Counter for stale crashes removed (Android)
* `Supportability/AgentHealth/Crash/Removed/Rejected`: Counter for rejected crashes removed (Android)
* `Supportability/AgentHealth/Hex/UploadTime`: Sampled time or counter for Hex uploads (Android)
* `Supportability/AgentHealth/Hex/FailedUpload`: Counter for failed Hex uploads (Android)
* `Supportability/AgentHealth/Hex/UploadThrottled`: Counter for throttled Hex uploads (Android)

### NDK metrics (Android specific)

Track the Native Development Kit (NDK) layer that captures native crashes and ANRs (Application Not Responding events).

**Example metrics:**
* `Supportability/AgentHealth/NDK/Init`, `Supportability/AgentHealth/NDK/Start`, `Supportability/AgentHealth/NDK/Stop`: Track NDK initialization, start, and stop events
* `Supportability/AgentHealth/NDK/Reports/NativeCrash`, `Supportability/AgentHealth/NDK/Reports/ANR`, `Supportability/AgentHealth/NDK/Reports/NativeException`: Counters for native crash, ANR, and native exception reports

### API usage metrics

Track which SDK APIs and agent features your mobile application is enabling or calling.

**Example metrics:**
* `Supportability/AgentHealth/API/RecordHandledException`: Counter for `recordHandledException` API calls (Android)
* `Supportability/Mobile/Android/API/<framework>/<frameworkVersion>/<name>`: General API usage metrics for Android
* `Supportability/Mobile/iOS/Native/API/enableFeature/*`: Tracks enabled features for iOS, where `*` is a feature name like `InteractionTracing`, `CrashReporting`, or `DistributedTracing`
* `Supportability/Mobile/iOS/Native/API/disableFeature/*`: Tracks disabled features for iOS

### Platform and OS specific metrics

Track platform version and data output for a specific mobile platform or hybrid framework.

**Example metrics:**
* `Supportability/Mobile/PlatformVersion/ReactNative/{android agent version}`: Tracks the React Native platform version for Android

### Crash ingest supportability metrics

Unlike the metrics above, these use the `Custom/Mobile/Crash/` prefix and track crash data as it's rate-limited and processed after ingest.

**Example metrics:**
* `Custom/Mobile/Crash/RateLimit/{accountId}`: Tracks the number of crashes rejected due to rate-limiting, by account
* `Custom/Mobile/Crash/Delay`: Measures the average delay (lag) in seconds between crash ingest and consumption

## Querying mobile supportability metrics [#querying-metrics]

Use NRQL to analyze your mobile supportability metrics. The `Supportability/` prefix makes these metrics easy to identify in your queries.

<CollapserGroup>
  <Collapser
    id="query-crash-metrics"
    title="Count crash-related supportability metrics"
  >
    ```sql
    SELECT count(*) FROM Metric WHERE metricName LIKE 'Supportability/AgentHealth/Crash/%'
    ```
  </Collapser>

  <Collapser
    id="query-crash-delay"
    title="Check average crash ingest delay"
  >
    ```sql
    SELECT average(Custom/Mobile/Crash/Delay) FROM Metric
    ```
  </Collapser>

  <Collapser
    id="query-all-mobile-supportability"
    title="List all supportability metrics for your account"
  >
    ```sql
    SELECT uniques(metricName)
    FROM Metric
    WHERE metricName LIKE 'Supportability/%'
    SINCE 1 day ago
    LIMIT MAX
    ```
  </Collapser>
</CollapserGroup>

## Troubleshooting with mobile supportability metrics [#troubleshooting]

These metrics are invaluable for diagnosing issues with your mobile monitoring.

| Problem | What to check | Key metrics to monitor |
|---------|---------------|------------------------|
| **Connection problems** | Agent connectivity to New Relic's data collection service | `Supportability/AgentHealth/Collector/connection/errors` |
| **Data transmission failures** | Data being sent from the agent | `Supportability/AgentHealth/Hex/FailedUpload`, `Supportability/AgentHealth/Crash/FailedUpload` |
| **Crash data processing delays** | Lag between crash ingest and consumption | `Custom/Mobile/Crash/Delay` |
| **Feature configuration issues** | Whether expected features are enabled | `Supportability/Mobile/iOS/Native/API/enableFeature/*` |

### Creating effective dashboards and alerts

To proactively manage your mobile application monitoring:

* **Build custom dashboards**: Visualize critical mobile agent health metrics such as connection success rates, data transmission volumes, and agent resource usage
* **Set up [NRQL alert conditions](/docs/alerts/create-alert/create-alert-condition/create-nrql-alert-conditions/)** for critical supportability metrics, for example:
  * Repeated collector connection failures
  * High agent timing values indicating performance degradation
  * Spikes in crash data rejection rates
  * Configuration drift, where expected metrics stop reporting

## Data retention and costs [#retention-costs]

Mobile supportability metrics follow the same [data retention rules](/docs/data-apis/manage-data/manage-data-retention) as other metric data in your New Relic account, and you're charged for their ingest as part of your New Relic data consumption. When planning your monitoring strategy, consider:

* **Volume**: Each mobile agent reports a significant number of supportability metrics
* **Frequency**: Most metrics report frequently, often every harvest cycle (typically 60 seconds)
* **Cost optimization**: Use targeted querying and alerting to focus on the most valuable metrics for your specific needs
