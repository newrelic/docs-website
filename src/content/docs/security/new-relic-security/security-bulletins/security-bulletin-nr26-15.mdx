<DNT>**Vulnerability Identifier:**</DNT> NR26-15

<DNT>**Priority:**</DNT> High

## Summary

Between October 17 and October 20, 2026, researchers disclosed that the private keys for eight intermediate certificate authority (CA) certificates issued by eMudhra can be recovered (CVE-2026-111943). Anyone with those keys can create certificates that software would accept as genuine if it still trusts them. Browsers and operating systems have blocked the certificates, but software that carries its own list of trusted CAs, including some container images, needs to be updated.

New Relic has updated the infrastructure agent, its container images, and the on-host integrations below so they no longer accept certificates issued by these CAs. The updated versions are not picked up automatically. Customers need to upgrade to the versions listed below.

**\*Upgrade note.**

Infrastructure agent 2.0 is a major version. It turns on `safe_dir_check_enabled` by default, so the agent no longer reuses a working directory that is a symlink, is not owned by the agent's user or group, or is writable by group or others. It recreates the directory instead. Set `safe_dir_check_enabled` to `false` to keep the previous behavior. See the release notes in the [Resources](#resources) section before upgrading.

On Windows, 2.0 removes the legacy Fluent Bit 1.9 from the installer. Log forwarding uses Fluent Bit 5.1.5.

## Technical vulnerability information

[CVE-2026-111943](https://www.cve.org/CVERecord?id=CVE-2026-111943)

Eight intermediate CAs that chain to the emSign ECC Root CA - G3 and, through cross-signing, to AAA Certificate Services, are affected.

- The infrastructure agent and the on-host integrations are built with Go 1.27.3 or Go 1.26.10. Both include the Go fix for CVE-2026-111943: `crypto/x509` refuses certificate chains that contain the eight affected intermediates, even if the root is still trusted.
- The `newrelic/infrastructure` 2.0.1 and `newrelic/infrastructure-bundle` 3.6.1 images are built on Alpine 3.24.3 with ca-certificates 20261020-r0, which removes emSign ECC Root CA - G3 and AAA Certificate Services from the CA bundle.
- The Java trust store in `newrelic/infrastructure-bundle` 3.6.1, used by the JMX-based integrations, does not contain either root.
- On hosts, the agent and integrations use the operating system's trust store. Apply your OS vendor's ca-certificates update as well.
- nri-jmx, nri-kafka, and nri-cassandra collect JMX metrics through nr-jmx, which runs on your Java runtime and uses its trust store, or the trust store set in the integration configuration. Apply your Java vendor's update as well.
- The exposure is limited to connections that use the public root store: the agent's connections to New Relic endpoints and to any configured proxy, and the integration's TLS connections to the services it monitors.

## Frequently asked questions

1. **Is it safe to remove the affected certificates from the CA bundle in my agent images?**

   Yes. New Relic endpoints do not use certificates issued by the affected CAs, so removing them does not affect the agent's connection to New Relic. If an integration connects over TLS to one of your services whose certificate chains to emSign ECC Root CA - G3 or AAA Certificate Services, that connection fails after the removal. Check those certificates first.

2. **Which agent versions are safe to use in my images?**

   Infrastructure agent 2.0.1 or newer, `newrelic/infrastructure-bundle` 3.6.1 or newer, and the on-host integration versions listed above.

3. **Who can I contact as I still have some questions?**

   If additional assistance is needed, open a case with our Support team through the help section in the New Relic platform.
