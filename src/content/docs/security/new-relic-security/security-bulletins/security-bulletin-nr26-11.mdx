<DNT>**Priority:**</DNT> High

## Summary

We are issuing this bulletin to inform you of critical security vulnerabilities in [Node.js](https://nodejs.org/) versions (22.x, 24.x, 26.x) that may require customer action for New Relic Synthetic monitoring customers using Public and Private locations.

**Fixed versions:** The fixed Node.js versions are 22.23.4, 24.22.1, and 26.12.1.

**End-of-life (EOL) versions:** Node.js 20 and older, including Node.js 16.x, are end-of-life and will not receive patches from the Node.js project. The only remediation for EOL versions of Node.js is migration to a supported release.

## Action required

These vulnerabilities impact Synthetic monitoring customers using both Public and Private locations. Customer action for each is as follows.

Customer action depends on whether your monitors are on the latest runtime.

### Private locations

**Action required:** For Private locations, you must pull the latest runtime images to remediate these CVEs. Action is required for monitors deployed in Private locations if you don't use the `latest` tag.

The `node-api-runtime` and `node-browser-runtime` container images bundle Node.js and are directly impacted by this vulnerability. Although security scanners may detect the CVE within the Synthetics Job Manager (SJM) and ping-runtime images, these runtimes are not exploitable. To eliminate the same, these CVE's will be addressed in the next releases of SJM v642 and ping-runtime 1.87.0.

If you're running Private locations, take the following steps:

1. Pull the latest versions of the affected runtime images:

   ```shell
   # Node API runtime
   docker pull newrelic/synthetics-node-api-runtime:latest

   # Node browser runtime
   docker pull newrelic/synthetics-node-browser-runtime:latest
   ```

2. Restart your containers after pulling the updated images to apply the fix.

For more information, see the [runtime transition guide](/docs/synthetics/synthetic-monitoring/private-locations/runtime-transition-guide/).

### Important notice: Node.js 16.x scripted API monitors

If you have scripted API monitors configured to run on Node.js 16.x, be aware that:

* Node.js 16.x will not receive a security patch for these CVEs from the Node.js project, because it has already reached [end-of-life](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/).
* New Relic has not automatically force-upgraded Node.js 16.x monitors to Node 22.x, because script compatibility can't be guaranteed. Some monitor scripts may require code changes to run correctly on Node 22.x.

We strongly recommend that you review and migrate your Node 16.x monitors to Node 22.23.4 as soon as possible, and not wait until November 18, 2026. For detailed migration instructions, see [Upgrade scripted API monitors to Node.js 22](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/).

## Frequently asked questions


1. **Do I need to update the Synthetics job manager (SJM) & ping-runtime?**

   No immediate update is required for remediation. While vulnerability scanners may flag the CVE in SJM and ping-runtime, these components are not susceptible to exploitation. However, upcoming releases (SJM v642 and ping-runtime 1.87.0) will address this CVE. Updating to these releases is recommended if you wish to maintain zero-finding compliance reports.


2. **Will updating the runtime images affect my running monitors?**

   Monitors continue to run normally after the runtime image update. There is no behavioral change for monitors running on Node 22.x.

3. **Can CVE-2026-111497 be exploited remotely?**

   Yes. This is a remote code execution vulnerability. It can be triggered when a Node.js process receives a Brotli-compressed HTTP response from a server an attacker controls. No local access is required.

4. **I'm running Node 16.x monitors. Am I at risk?**

   Yes. Node 16.x is end-of-life and won't be patched. Your monitors remain vulnerable until you migrate them to Node 22.23.4. You can do this yourself using the runtime upgrade tool. For more information, see [Manage monitor runtimes](/docs/synthetics/synthetic-monitoring/using-monitors/manage-monitor-runtimes/).

5. **Why wasn't my Node 16.x monitor automatically upgraded?**

   Node 22.x includes breaking changes from Node 16.x, which New Relic [communicated earlier](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/). Scripted API monitors still on Node 16.x are those that couldn't be automatically upgraded without failing. New Relic therefore made this a customer-initiated upgrade to avoid unintended monitor breakage. We'll follow the EOL timelines [communicated earlier](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/) and will force-upgrade Node 16.x monitors on November 18, 2026.

6. **Do I need to reboot or restart anything after updating Private location runtimes?**

   Only a container restart is required. No host reboot is needed.

7. **Who can I contact if I still have questions?**

   Open a case with our Support team through the help section in the New Relic platform.
