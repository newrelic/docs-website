<DNT>**Priority:**</DNT> Critical

## Summary

A critical vulnerability (CVSS 4.0 score 9.2) was disclosed in the session extension of the PHP runtime. It affects applications that use PHP's default files session handler. The PHP project released fixes on November 19, 2026.

The October 2026 fix releases for CVE-2026-109618 and CVE-2026-109619 ([NR26-10](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-10)) do not include this fix. Applications that keep sessions in a database or Redis instead of the native files handler are outside this vulnerability.

**New Relic-distributed software and services are not impacted.** New Relic does not ship a PHP runtime in any customer-distributed software. The New Relic PHP agent runs inside the customer's own PHP environment and is not the vulnerable component. The PHP agent runs as an extension inside the customer's existing PHP interpreter, meaning remediation is handled by upgrading PHP itself. New Relic has not identified evidence of exploitation in its environment.

## Action Recommended

No action is required with respect to your New Relic software and services. Nonetheless, New Relic strongly encourages customers who run PHP applications, with or without New Relic instrumentation, to upgrade to the fixed release for their branch and restart all PHP workers. The same releases fix 17 advisories, so one upgrade covers all of them.

### Recommendations

- **Distribution packages:**
  - A distribution may carry the fix without changing the PHP version string. Check your vendor's security advisory instead of relying on the version number.
- **End-of-life versions (PHP 8.1 and older):**
  - These versions are not listed in the CVE record and receive no official fixes. Treat unpatched builds as affected, check whether your distribution has backported the fix, and plan an upgrade to a supported branch.
- **Managed hosting:**
  - Confirm with your provider that every environment, including development, test and preview, runs a fixed version.

## Temporary Mitigation

Only an upgrade to your PHP runtimes fully fixes this vulnerability. If you cannot upgrade immediately, as a temporary measure, disable `session.upload_progress.enabled` administratively if the feature is not needed and limit the amount of untrusted data stored in sessions. Disabling upload progress removes that input path but does not fix applications that independently store attacker-controlled session data. A session storage backend that replaces records atomically can avoid this file-write defect. The PHP update for the runtime remains the recommended fix for applications using the built-in files handler. See Supporting Documents below for more details.

## Frequently asked questions

1. **How can I find out which PHP version and session settings I'm using?**

   Run `php -v` on the host or in the container. Check session.save_handler and `session.upload_progress.enabled` in `phpinfo()` or `php.ini`. For the PHP version New Relic sees, check the host or application details in the New Relic UI.

2. **Does the New Relic PHP agent need to be updated?**

   No. The vulnerability is in the PHP runtime, not the agent. Please update your PHP runtime to the fixed versions to remediate this vulnerability.

3. **How can I tell if my systems have been targeted?**

   No public indicators of compromise have been reported so far. Customers should review their web logs from November 19, 2026 onward for unexplained PHP worker crashes or out-of-memory kills and for unauthenticated multipart POST requests to PHP endpoints. Also look for new or modified PHP files in web directories.

4. **I have questions or concerns about this vulnerability. Who should I contact?**
