<DNT>**Vulnerability Identifier:**</DNT> NR26-13

<DNT>**Priority:**</DNT> High

## Summary

Between October 17 and October 20, 2026, researchers disclosed that the private keys for eight intermediate certificate authority (CA) certificates issued by eMudhra can be recovered (CVE-2026-111943). Anyone with those keys can create certificates that software would accept as genuine if it still trusts them. Browsers and operating systems have blocked the certificates, but software that carries its own list of trusted CAs, including some container images, needs to be updated.

New Relic has updated the Logs components below so they no longer accept certificates issued by these CAs. The updated versions are not picked up automatically. Customers need to upgrade to the versions listed below.

**Note for FireLens users:** The plugin itself now rejects certificates issued by the affected CAs. The base image provided by AWS (`aws-for-fluent-bit`) may still list the affected root CAs in its own CA bundle until AWS publishes a rebuilt image. We will update this bulletin when it is available.

## Technical vulnerability information

[CVE-2026-111943](https://www.cve.org/CVERecord?id=CVE-2026-111943)

Eight intermediate CAs that chain to the emSign ECC Root CA - G3 and, through cross-signing, to AAA Certificate Services, are affected.

- The plugin is built with Go 1.27.3, whose TLS library refuses certificate chains that contain the eight affected keys, even if the root is still trusted.
- The Fluent Bit 5.1.5 base images have removed the affected roots from their CA bundle.
