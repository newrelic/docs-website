## v1.324.0

**[View this release on GitHub →](https://github.com/newrelic/newrelic-browser-agent/releases/tag/v1.324.0)** for the full technical changelog and build size information.

### Features

#### Improve script matching in manifest
Micro frontends registered with a manifest now have every resource a manifest matcher matches counted toward their MicroFrontEndTiming data. Previously each manifest asset was consumed by its first matching resource, so a broad matcher such as a RegExp for hashed chunks (e.g. /catalog-chunk-[a-f0-9]+\.js/) only contributed one chunk to totalWeight, renderBlocking and the fetch/execute timing window. All matching chunks, whether already loaded or loaded shortly after register(), now contribute. Separately, when the same script URL is referenced more than once (for example a duplicated `<script>` tag, typically re-served from the browser cache), the agent now keeps the timing from the first load instead of overwriting it, so a cached duplicate can no longer make fetch and execution timing look shorter than the real load.

#### Enable distributed tracing for registered Micro Frontends
Enables distributed tracing (DT) for registered Micro Frontends (MFEs): an AJAX call made by a registered MFE now correctly roots its trace at that MFE's own entity, giving visibility into an MFE's own backend calls for the first time.


### Bug fixes

#### prevent runaway log harvests from inflated attribute size
Fixed a bug where a page that repeatedly overwrites a custom attribute could cause the agent to send a separate logs request for every logged message, flooding the network and exhausting browser resources. The agent now tracks custom attribute size accurately when values are overwritten, limits how often each feature can harvest early, and still sends large batches promptly so that no logs are dropped while doing so.

#### fix(jserrors): reset stack hash memory on session reset
see https://new-relic.atlassian.net/browse/NR-626097 for details
Resend the full stack trace once after a session reset, instead of a hash the backend may no longer be able to resolve due to cache TTLs.

#### find iframe entity script timings at registration
Registered iframe entities now identify the script that called register() when they are created, instead of after the parent agent responds. Previously the lookup ran after the registration round trip, when the calling script was no longer on the call stack, so the entity's asset, type and fetch timings could be missing or attributed to the agent's own script.

## Support statement

New Relic recommends that you upgrade the agent regularly to ensure that you're getting the latest features and performance benefits. Older releases will no longer be supported when they reach [end-of-life](https://docs.newrelic.com/docs/browser/browser-monitoring/getting-started/browser-agent-eol-policy/). Release dates are reflective of the original publish date of the agent version.

The following features are currently in limited preview and will not receive standard support:
- [Micro frontend (MFE) monitoring](https://docs-preview.newrelic.com/docs/browser/micro-frontend-monitoring/) via the [register() API](https://docs-preview.newrelic.com/docs/browser/register)
- [BrowserPerformance "resource"](https://docs.newrelic.com/docs/browser/new-relic-browser/browser-pro-features/page-resources/) type events

New browser agent releases are rolled out to customers in small stages over a period of time. Because of this, the date the release becomes accessible to your account may not match the original publish date. Please see this [status dashboard](https://newrelic.github.io/newrelic-browser-agent-release/) for more information.

Consistent with our [browser support policy](https://docs.newrelic.com/docs/browser/new-relic-browser/getting-started/compatibility-requirements-browser-monitoring/#browser-types), v1.324.0 of the Browser agent was built for and tested against these browsers and version ranges: Chrome 144-154, Edge 144-154, Safari 18-27, and Firefox 146-156. For mobile devices, v1.324.0 was built and tested for Android OS 17 and iOS Safari 18-26.2.
