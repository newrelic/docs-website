### New docs

* Added [Triage vulnerability remediation with the Security RX Agent](/docs/vulnerability-management/agent/overview) to provide guidance on using the Security RX Agent to analyze CVEs, generate remediation plans, and trigger coding agents to open pull requests.
* Added [Security RX Jira workflow](/docs/vulnerability-management/workflows/jira) to provide step-by-step instructions for automatically creating and syncing Jira tickets for security vulnerabilities detected by Security RX.
* Added [Troubleshoot New Relic MCP](/docs/agentic-ai/mcp/troubleshoot) to provide common troubleshooting steps and solutions for resolving MCP server setup and configuration issues.

### Major changes

* Restructured [Microsoft SQL Server monitoring with NRDOT](/docs/opentelemetry/database/mssql/introduction) with a new comprehensive configuration reference, a new CNCF collector setup guide, and overhauled installation docs for Windows-hosted, Windows RDS, Linux-hosted, and Linux RDS environments.
* Updated [Agent types](/docs/new-relic-control/agent-control/agent-types) with documentation for configuring Fluent Bit log forwarding under Agent Control, including configuration file placement, binary paths by OS, and update behavior.
* Updated [Manage fleets](/docs/new-relic-control/fleet-control/manage-fleets) with comprehensive documentation for the new configuration approval workflow in Fleet Control. Config approvals require at least one reviewer other than the author before a configuration version can be deployed, with enforcement beginning September 22, 2026.
* Updated [Workflow Automation definition schema](/docs/workflow-automation/workflow-automation-apis/definition-schema) with the new State Step action for persisting key/value pairs across workflow steps via `.workflowState`, and updated [workflow limits](/docs/workflow-automation/limitations-and-faq/workflow-limits) and [execution monitoring](/docs/workflow-automation/manage-workflows/monitor-workflow-execution) to cover the new step type and `WorkflowAutomationEvent` data.
* Added VMware vSphere Kubernetes Service (VKS) 3.x support to [Kubernetes integration compatibility requirements](/docs/kubernetes-pixie/kubernetes-integration/get-started/kubernetes-integration-compatibility-requirements), covering VKS running on vSphere Supervisor 9.0 to 9.1 (vSphere 8.x and 9.x).
* Updated [.NET agent compatibility requirements](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) with the latest verified compatible library versions.
* Updated [Catalogs](/docs/service-architecture-intelligence/catalogs/catalogs) to document tag-based column value filtering via interactive pills and column reordering by drag and drop in the Personalize view table.
* Added a caution to [Response intelligence with AI](/docs/alerts/alert-event-management/response-intelligence-ai) stating that AI-generated insights are suggestions to guide investigation, not confirmed root causes, and should be verified against your data before acting on them.
* Added the `snapdom` open-source library to [New Relic browser agent licenses](/docs/licenses/product-or-service-licenses/new-relic-browser/new-relic-browser-licenses).
* Updated [Errors inbox OpenTelemetry tab](/docs/errors-inbox/otel-tab) to correct the span attribute name from `otel.status` to `otel.status_code` and expand the supported span kinds to include `producer`, `client`, and `internal` in addition to `server` and `consumer`.
* Updated [Choose your data center](/docs/accounts/accounts-billing/account-setup/choose-your-data-center) to reflect that the Japan (JP) data region is now generally available.

### Minor changes

* Updated [Set up New Relic MCP](/docs/agentic-ai/mcp/setup) with corrected Claude Code CLI commands for OAuth authentication, a minimum version requirement (Claude Code v2.1.186+), and a simplified JSON configuration format.
* Added `nrExporterEndpoints` to [Gateway YAML configuration reference](/docs/new-relic-control/pipeline-control/gateway/yaml-overview) for overriding default New Relic ingest endpoints per pipeline, including a new `otlpEndpoint` field, under a dedicated Optional overrides section.
* Updated [Trace API troubleshooting](/docs/apm/distributed-tracing/trace-api/troubleshooting-missing-trace-api-data) and [missing trace data](/docs/distributed-tracing/troubleshooting/missing-trace-data) with corrected oldest span timestamp limits for OTLP and Trace API.
* Added a cardinality warnings section to [Manage cardinality](/docs/data-apis/ingest-apis/metric-api/cardinality-management) explaining what happens when a cardinality budget is hit, how to identify affected metrics via warning indicators in charts and dashboards, and how to query raw data while remediating.
* Added the Direct to Live Archive namespace as a third partition option to [Data partitions](/docs/logs/ui-data/data-partitions) and added guidance to [Live archives](/docs/logs/get-started/live-archives) explaining that this namespace bypasses standard retention for compliance and audit logs that go directly to long-term storage.
* Corrected the `403 Forbidden` error description in [React Native JavaScript error reporting](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting) to state that the API key must belong to a user with mobile entity view permissions.
* Updated [Alert RCA with Autopilot and Slack](/docs/workflow-automation/workflow-examples/integrations/autopilot-slack-rca) with a tip on using the `{{ issueId }}` variable to automatically pass the triggering alert's issue ID when integrating with Alert Workflows.
* Updated [Downgrade or cancel account](/docs/accounts/accounts-billing/account-setup/downgradecancel-account) to add a callout clarifying that the last active account in an organization cannot be cancelled independently and must be removed by deleting the organization, and improved the organization deletion steps for clarity.
