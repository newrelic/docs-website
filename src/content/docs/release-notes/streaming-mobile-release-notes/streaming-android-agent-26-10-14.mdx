### Bug fixes

- **ExoPlayer / HLS:** `contentBitrate` always reported `0` for HLS streams. media3 internally classifies mixed audio+video HLS segment loads as `TRACK_TYPE_DEFAULT` rather than `TRACK_TYPE_VIDEO` (unlike DASH and progressive streams, which were unaffected). The tracker's bitrate-capture logic only fired for `TRACK_TYPE_VIDEO`, so HLS loads never populated the field. `contentBitrate` now correctly reflects the actual stream bitrate for HLS content.
