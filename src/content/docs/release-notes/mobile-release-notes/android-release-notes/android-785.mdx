## Improvements and enhancements

- The agent now starts only in your app's default process, so apps that declare extra processes with `android:process` no longer report empty sessions from them. ([#648](https://github.com/newrelic/newrelic-android-agent/pull/648))

## Bug fixes

- Fixed events recorded while the app was in the foreground being reported with `background = true` when they were sent in a batch harvested after the app moved to the background. With Background Reporting enabled, every event now carries `background = true` or `background = false` for the app's state at the moment it was recorded; foreground events previously had no `background` attribute. ([#655](https://github.com/newrelic/newrelic-android-agent/pull/655))
- Fixed ANRs and other app exits reported on the next launch missing the `background` attribute when they happened while the app was in the background; the attribute is now `true` or `false` based on the app's state when the process exited. ([#653](https://github.com/newrelic/newrelic-android-agent/pull/653))
- Fixed a `StackOverflowError` crash on page load in apps whose `WebView` subclass overrides `setWebViewClient` to store the client and forward to it from its own internal client; the agent no longer installs its WebView client wrapper on such WebViews. ([#660](https://github.com/newrelic/newrelic-android-agent/pull/660))
- Fixed an ANR at app startup where the agent read its saved events from disk on the main thread; they are now loaded in the background. ([#661](https://github.com/newrelic/newrelic-android-agent/pull/661))

## Support statement

We recommend updating the agent at least every three months. Find specific policies and dates for Android agent support in the [Mobile Monitoring Agents EOL Policy](/docs/mobile-monitoring/new-relic-mobile/get-started/mobile-agents-eol-policy/#android-eol).
