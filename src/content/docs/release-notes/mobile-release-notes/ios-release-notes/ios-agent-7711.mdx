Every instrumented `NSURLSession` request read the agent's harvester configuration and its cross-process ID without a lock. At the same time, the harvest thread replaced that configuration and cleared the ID at the start of the session, so a request could use an object that had just been freed. - Fixed network requests going unrecorded after the agent received a `/connect` response it could not parse. The agent stored an empty configuration until the next harvest, and requests recorded in that window were dropped. The agent now keeps its existing configuration. - Fixed handled exceptions saved on the device being dropped after an app update, with the server error "Failed to resolve data: MobileAppVersion". Saved handled exceptions were uploaded at the start of the next session, before the agent had connected for the app's new version. They are now uploaded after the connection completes. - Fixed handled exceptions recorded before an app update being reported under the new app version. A saved handled exception is now uploaded under the app version it was recorded in. This issue was present in 7.7.10 and earlier.
- Fixed `recordCustomEvent:` accepting reserved event types (`Mobile`, `MobileCrash`, `MobileRequest`, `MobileRequestError`, `MobileSession`, `MobileBreadcrumb`) when the new event system (`NRFeatureFlag_NewEventSystem`) was enabled. ### New in this release

* Session replay now captures text in React Native apps that use the legacy architecture. Text drawn by `RCTTextView` used to be recorded as an empty view. It is now captured and masked the same way as `RCTParagraphComponentView` text in the New Architecture.
