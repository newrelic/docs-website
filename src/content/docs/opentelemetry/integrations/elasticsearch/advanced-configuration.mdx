You can configure the following options to get deeper insights into your self-hosted Elasticsearch monitoring setup:

- [Secured Elasticsearch with authentication and SSL](#secured)
- [Collect host metrics](#host-metrics)
- [Collect Elasticsearch logs](#logs)
- [Add custom metadata tags](#custom-tags)
- [Restart the collector](#restart)
- [Verify your changes](#verify)

Each option modifies the same `receivers`/`processors`/`service` blocks you set up in [Install and configure NRDOT on Elasticsearch self-hosted](/docs/opentelemetry/integrations/elasticsearch/install-configure/self-hosted/nrdot), [Install and configure the OTel Collector Contrib for Elasticsearch monitoring](/docs/opentelemetry/integrations/elasticsearch/install-configure/self-hosted/otel-collector-contrib), or the Kubernetes install pages. Pick the tab for your environment and collector below, and add the snippet to your existing config.

## Secured Elasticsearch with authentication and SSL [#secured]

For secured Elasticsearch with authentication and SSL, modify the receiver configuration:

<CollapserGroup>
<Collapser
  id="secured-nrdot"
  title="NRDOT"
>

```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      ca_file: "/etc/elasticsearch/certs/http_ca.crt"
      insecure_skip_verify: false
    collection_interval: 15s
```

</Collapser>
<Collapser
  id="secured-otel"
  title="OTel Collector Contrib"
>

```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      ca_file: "/etc/elasticsearch/certs/http_ca.crt"
      insecure_skip_verify: false
    collection_interval: 15s
```

</Collapser>
<Collapser
  id="secured-k8s-nrdot"
  title="Kubernetes — NRDOT (manifest or Helm)"
>

```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```

</Collapser>
<Collapser
  id="secured-k8s-otel"
  title="Kubernetes — OTel Collector Contrib"
>

```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```

</Collapser>
</CollapserGroup>

### Configuration parameters [#secured-configuration-parameters]

The following table describes the key configuration parameters used in the snippets above:

| Parameter | Description |
| --- | --- |
| `endpoint` | Your Elasticsearch cluster's URL. Use `https://` for a secured cluster. |
| `username` | An Elasticsearch user with the `monitor` or `manage` cluster privilege. |
| `password` | The password for that user. |
| `tls.ca_file` | Path to the CA certificate used to verify Elasticsearch's TLS certificate (self-hosted only; omit if your certificate is signed by a public CA). |
| `tls.insecure_skip_verify` | Set to `false` to verify Elasticsearch's TLS certificate. |
| `collection_interval` | The interval between metric scrapes. Default: `15s`. |
| `rule` (Kubernetes only) | The pod-matching rule used for auto-discovery. |

## Collect host metrics [#host-metrics]

To collect host metrics, add the `hostmetrics` receiver:

<CollapserGroup>
<Collapser
  id="host-metrics-nrdot"
  title="NRDOT"
>

```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization: { enabled: true }
          system.cpu.time: { enabled: true }
      load:
        metrics:
          system.cpu.load_average.1m: { enabled: true }
          system.cpu.load_average.5m: { enabled: true }
          system.cpu.load_average.15m: { enabled: true }
      memory:
        metrics:
          system.memory.usage: { enabled: true }
          system.memory.utilization: { enabled: true }
      disk:
        metrics:
          system.disk.io: { enabled: true }
          system.disk.operations: { enabled: true }
      filesystem:
        metrics:
          system.filesystem.usage: { enabled: true }
          system.filesystem.utilization: { enabled: true }
      network:
        metrics:
          system.network.io: { enabled: true }
          system.network.packets: { enabled: true }
      process:
        metrics:
          process.cpu.utilization:
            enabled: true
```

And add to the service pipelines:

```yaml
service:
  pipelines:
    metrics/host:
      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```

</Collapser>
<Collapser
  id="host-metrics-otel"
  title="OTel Collector Contrib"
>

```yaml

  hostmetrics:

      network:

And add to the service pipelines:

      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```

</Collapser>
</CollapserGroup>

### Configuration parameters [#host-metrics-configuration-parameters]

The following table describes the key configuration parameters used in the snippets above:

| Parameter | Description |
| --- | --- |
| `collection_interval` | The interval between host metric scrapes. Default: `60s`. |
| `scrapers` | Which host-level metric categories to collect (`cpu`, `load`, `memory`, `disk`, `filesystem`, `network`, `process`). Set `enabled: false` on any metric you don't need. |

## Collect Elasticsearch logs [#logs]

### Requirements [#logs-requirements]

- Read access to your Elasticsearch log files, for whichever account runs the collector service:
  - Linux host: read permission on `/var/log/elasticsearch/`
  - Docker: read permission on `/var/lib/docker/containers/` (root, or Docker group membership)

To collect Elasticsearch logs, add the `filelog` receiver.

<CollapserGroup>
<Collapser
  id="logs-nrdot"
  title="NRDOT"
>

Ensure the account running the collector service (`nrdot-collector`) has read access to your Elasticsearch log files.

**If running Elasticsearch on Linux (host):**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**If running Elasticsearch in Docker:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

And add to the service pipelines:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```

</Collapser>
<Collapser
  id="logs-otel"
  title="OTel Collector Contrib"
>

Ensure the account running the collector service (`otelcol-contrib`) has read access to your Elasticsearch log files.

**If running Elasticsearch on Linux (host):**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**If running Elasticsearch in Docker:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

And add to the service pipelines:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```

</Collapser>
</CollapserGroup>

### Configuration parameters [#logs-configuration-parameters]

The following table describes the key configuration parameters used in the snippets above:

| Parameter | Description |
| --- | --- |
| `include` | Log file paths to tail (Linux host) or container log paths (Docker). |
| `operators` (Docker only) | Moves the log line from `attributes.log` to `body` so it displays correctly. |

## Add custom metadata tags [#custom-tags]

To add custom metadata tags to your metrics, use the `resource/static_override` processor:

<CollapserGroup>
<Collapser
  id="custom-tags-nrdot"
  title="NRDOT"
>

```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```

</Collapser>
<Collapser
  id="custom-tags-otel"
  title="OTel Collector Contrib"
>

```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```

</Collapser>
</CollapserGroup>

### Configuration parameters [#custom-tags-configuration-parameters]

The following table describes the key configuration parameters used in the snippets above:

| Parameter | Description |
| --- | --- |
| `key` | The attribute name to add, e.g. `env`. |
| `value` | The attribute value, e.g. `production`. |
| `action` | Set to `upsert` to add the attribute or overwrite it if it already exists. |

## Restart the collector [#restart]

After updating your configuration, restart the collector to apply the changes.

<CollapserGroup>
<Collapser
  id="restart-nrdot"
  title="NRDOT (self-hosted)"
>

```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```

</Collapser>
<Collapser
  id="restart-otel"
  title="OTel Collector Contrib (self-hosted)"
>

```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```

</Collapser>
<Collapser
  id="restart-k8s"
  title="Kubernetes (NRDOT or OTel Collector Contrib)"
>

For a manifest install, restart the deployment:

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```

For a Helm install, re-run the same `helm upgrade --install ... -f values.yaml` command from your install step to roll out the updated config.

</Collapser>
</CollapserGroup>

## Verify your changes [#verify]

After restarting the collector, confirm your change took effect:

- **Secured cluster**: rerun your install page's data collection query. If metrics are flowing with no TLS or authentication errors in the collector logs, the secured connection is working.
- **Host metrics**:

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'system.%' SINCE 10 minutes ago
  ```

- **Elasticsearch logs**:

  ```sql
  FROM Log SELECT count(*) SINCE 10 minutes ago
  ```

  Adjust the `WHERE` clause to filter to your own log attributes.

- **Custom tags**:

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'elasticsearch.%' AND env = 'production' SINCE 10 minutes ago
  ```

  Using the example tag from [Add custom metadata tags](#custom-tags).

If you don't see data within ~5 minutes, see [Elasticsearch troubleshooting](/docs/opentelemetry/integrations/elasticsearch/troubleshooting).
