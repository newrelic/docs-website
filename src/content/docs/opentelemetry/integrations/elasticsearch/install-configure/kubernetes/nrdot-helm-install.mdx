This guide shows how to deploy NRDOT on Kubernetes using Helm to automatically discover your Elasticsearch pods, collect cluster, node, and JVM metrics, and stream them to New Relic to monitor your cluster's health and performance.

## Compatibility and requirements [#requirements]

### Supported
- Elasticsearch 7.16 or later, running as pods in a Kubernetes cluster
- Helm install method

### You need
- A New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
- `kubectl` access to your Kubernetes cluster
- Helm 3.x installed
- An Elasticsearch user with the `monitor` or `manage` cluster privilege (see [Elasticsearch security privileges](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html))
- Outbound HTTPS (port 443) connectivity to New Relic's [OTLP endpoint](/docs/opentelemetry/best-practices/opentelemetry-otlp)
- An Elasticsearch username and password (if your cluster requires authentication)

## Set up pod labels [#pod-labels]

Each Elasticsearch pod must have the label `app: elasticsearch` for automatic discovery to work. Without this label, the collector won't detect or monitor your pods.

If you're using a StatefulSet or Deployment for Elasticsearch, add the label in the pod template:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: elasticsearch
spec:
  template:
    metadata:
      labels:
        app: elasticsearch  # Required for auto-discovery
    spec:
      containers:
      - name: elasticsearch
        image: docker.elastic.co/elasticsearch/elasticsearch:8.x.x
```

For existing pods without the label, update your StatefulSet/Deployment and restart the pods:

```bash
kubectl label pods -l <your-existing-selector> app=elasticsearch -n <namespace>
```

You can verify labels are set correctly:

```bash
kubectl get pods -n <namespace> --show-labels
```

</Step>

## Configure the NRDOT Collector [#configure]

Create the credentials the collector needs, then define its Elasticsearch monitoring configuration.

1. Create the namespace and a secret for your New Relic credentials:

    ```bash
    kubectl create namespace newrelic
    kubectl create secret generic newrelic-licenses \
      --from-literal=NEWRELIC_LICENSE_KEY=YOUR_LICENSE_KEY_HERE \
      --from-literal=NEWRELIC_OTLP_ENDPOINT=YOUR_NEWRELIC_OTLP_ENDPOINT \
      --from-literal=NEW_RELIC_MEMORY_LIMIT_MIB=100 \
      -n newrelic
    ```

    Replace the memory limit with what fits your environment.

2. Create a `values.yaml` file for the NRDOT Collector: set `rule` to match your pod label, and set `K8S_CLUSTER_NAME` to a unique name for this cluster:

        cpu: 200m
        memory: 256Mi

    ports: {}

    extraEnvs:
      - name: NEWRELIC_LICENSE_KEY
        valueFrom:
          secretKeyRef:
            name: newrelic-licenses
            key: NEWRELIC_LICENSE_KEY
      - name: NEWRELIC_OTLP_ENDPOINT
        valueFrom:
          secretKeyRef:
            name: newrelic-licenses
            key: NEWRELIC_OTLP_ENDPOINT
      - name: NEW_RELIC_MEMORY_LIMIT_MIB
        valueFrom:
          secretKeyRef:
            name: newrelic-licenses
            key: NEW_RELIC_MEMORY_LIMIT_MIB
      - name: K8S_CLUSTER_NAME
        value: "elasticsearch-cluster"

    clusterRole:
      create: true
      rules:
        - apiGroups: [""]
          resources: ["pods", "nodes", "nodes/stats", "nodes/proxy"]
          verbs: ["get", "list", "watch"]
        - apiGroups: ["apps"]

          endpoint: 0.0.0.0:13133

        zipkin: null
        prometheus: null
        otlp: null

          watch_observers: [k8s_observer]
          receivers:
            elasticsearch:
              rule: type == "pod" && labels["app"] == "elasticsearch"

                endpoint: 'http://`endpoint`:9200'

### Configuration parameters [#configuration-parameters]

The following table describes the key configuration parameters used in the `values.yaml` above:

| Parameter | Description |
| --- | --- |
| `rule` | The pod-matching rule used for auto-discovery. Update `labels["app"] == "elasticsearch"` to match your pod labels. |
| `endpoint` | The Elasticsearch endpoint scraped on each discovered pod. Update port `9200` if Elasticsearch runs on a different port, and use `https` for a secured cluster. |
| `collection_interval` | The interval between metric scrapes. The default is 15s. |
| `elasticsearch-cluster` (in `K8S_CLUSTER_NAME`) | A unique name identifying this cluster in New Relic. Replace with a name that's unique across your account. |
| `NEW_RELIC_MEMORY_LIMIT_MIB` | The memory limit, in MiB, for the collector's `memory_limiter` processor. Set to fit your environment. |
| `NEWRELIC_LICENSE_KEY` | Your New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key). |
| `NEWRELIC_OTLP_ENDPOINT` | The New Relic OTLP endpoint for your account's region. See [New Relic OTLP endpoints](/docs/opentelemetry/best-practices/opentelemetry-otlp). |

## Install via Helm [#install-helm]

Deploy the NRDOT Collector to your cluster using the `values.yaml` file you just created.

1. Add and update the OpenTelemetry Helm chart repository:

    ```bash
    helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
    helm repo update
    ```

2. Deploy the NRDOT Collector:

    ```bash
    helm upgrade --install elasticsearch-nrdot-collector open-telemetry/opentelemetry-collector \
      --namespace newrelic \
      --create-namespace \
      -f values.yaml
    ```

</Step>

## Verify your install [#verify]

Within ~5 minutes of installing, run this query in New Relic to confirm data is flowing (replace `elasticsearch-cluster` with your cluster's name):

```sql
FROM Metric
SELECT *
WHERE metricName LIKE 'elasticsearch.%'
  AND instrumentation.provider = 'opentelemetry'
  AND k8s.cluster.name = 'elasticsearch-cluster'
SINCE 10 minutes ago
```

<Callout variant="tip">
You can also check the collector itself: the pod should be in a `Running` state (`kubectl get pods -n newrelic --watch`), name like `elasticsearch-nrdot-collector-<hash>`, with no connection errors in the pod logs (`kubectl logs -n newrelic -l app.kubernetes.io/name=opentelemetry-collector -f`).
</Callout>

If you don't see data within ~5 minutes, see [Kubernetes troubleshooting](/docs/opentelemetry/integrations/elasticsearch/troubleshooting#kubernetes-troubleshooting).

</Step>

## Find and use your data [#find-and-use]

Once New Relic collects your data, you can access Elasticsearch monitoring through the New Relic UI.

To find your Elasticsearch dashboard in New Relic:

1. Go to <DNT>**one.newrelic.com > Integrations & Agents**</DNT>.
2. Under the <DNT>**All**</DNT> tab, click <DNT>**Dashboards**</DNT>, then search for <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> to view the dashboard.

Or, from the left navigation:

1. From the left panel, click <DNT>**Dashboards**</DNT>.
2. Search for the <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> dashboard to view it.

   After setting up Elasticsearch monitoring with NRDOT, you can:

   - [Create custom dashboards](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) to visualize your Elasticsearch metrics
   - [Set up alerts](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) for critical cluster health and performance thresholds
   - [Explore your data](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) using New Relic query capabilities

</Step>
