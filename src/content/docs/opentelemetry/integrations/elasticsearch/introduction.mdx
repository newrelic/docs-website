The New Relic Elasticsearch integration monitors the health and performance of your Elasticsearch clusters using the OpenTelemetry Collector — collecting cluster, node, and JVM metrics alongside Elasticsearch logs through a single, vendor-neutral pipeline. You get visibility into cluster health, search and indexing performance, and resource utilization without instrumenting your application code.

## Capabilities [#capabilities]

- **Metrics** — cluster health, shard distribution, node and JVM performance, and host resource utilization (CPU, memory, disk, network)
- **Logs** — Elasticsearch server logs, correlated with the same cluster and node metadata as your metrics

## Choose your install path [#choose]

**Self-hosted** — for Elasticsearch running directly on servers or VMs.
- **NRDOT** (recommended) — New Relic's distribution of the OpenTelemetry Collector; the most direct path if you have no existing collector.
- **OTel Collector Contrib** — the community OpenTelemetry Collector distribution; pick this if your environment already standardizes on it.
- **Prometheus Receiver** — pick this only if you already run a [Prometheus Elasticsearch exporter](https://github.com/prometheus-community/elasticsearch_exporter) and want to reuse it rather than connect a collector directly to Elasticsearch.

**Kubernetes** — for Elasticsearch running in a Kubernetes cluster, with automatic pod discovery.
- **NRDOT** (recommended) — New Relic's distribution of the OpenTelemetry Collector; the most direct path if you have no existing collector.
- **OTel Collector Contrib** — the community OpenTelemetry Collector distribution; pick this if your environment already standardizes on it.
- **Prometheus Receiver** — same condition as above: only if you're already running the exporter in-cluster.
