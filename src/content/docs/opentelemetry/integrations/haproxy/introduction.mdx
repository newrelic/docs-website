Monitor your HAProxy load balancers using New Relic Distribution of OpenTelemetry (NRDOT) or the OpenTelemetry Collector Contrib to get insights into backend server health, session and request rates, and connection errors.

Either collector can collect HAProxy metrics in one of two ways:

- The [haproxyreceiver](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/haproxyreceiver), which reads the HAProxy stats endpoint.
- The Prometheus receiver, which reads HAProxy's built-in Prometheus endpoint (HAProxy 2.0 or later).

With HAProxy 3.4 or later, you can also turn on the [OpenTelemetry filter](https://www.haproxy.com/documentation/haproxy-configuration-tutorials/alerts-and-monitoring/opentelemetry/overview/) to add distributed tracing and [service relationships](/docs/new-relic-solutions/new-relic-one/ui-data/service-maps/service-maps/) between your applications and HAProxy. See [HAProxy distributed tracing](/docs/opentelemetry/integrations/haproxy/distributed-tracing).

## Capabilities [#capabilities]

The HAProxy integration provides:

- **Metrics**: Sessions, requests, connections, throughput, and backend health, with `haproxy.proxy_name` and `haproxy.service_name` attributes for per-frontend, per-backend, and per-server visibility.
- **Entities**: One `HAPROXYINSTANCE` entity per HAProxy instance, with golden metrics.
- **Traces**: Distributed traces from HAProxy 3.4 or later. For more information, see [HAProxy distributed tracing](/docs/opentelemetry/integrations/haproxy/distributed-tracing).

## Choose your install path [#choose]

Select the option that matches your environment: HAProxy running on a Linux server or VM (self-hosted), or HAProxy running in a Kubernetes cluster. Then select the collector you want to use.

**Self-hosted**: For HAProxy running directly on Linux servers or VMs.

- **NRDOT** (recommended): New Relic's distribution of the OpenTelemetry Collector with the haproxyreceiver. Use this if you don't already run a collector.
- **OTel Collector Contrib**: The community OpenTelemetry Collector with the haproxyreceiver. Use this if your environment already standardizes on it.
- **Prometheus receiver**: Works with NRDOT or OTel Collector Contrib. Use this only if you already expose HAProxy's built-in Prometheus endpoint, or you're migrating from a Prometheus-based stack.

**Kubernetes**: For HAProxy running in a Kubernetes cluster, with automatic pod discovery.

- **NRDOT** (recommended): New Relic's distribution of the OpenTelemetry Collector. Use the [manifest install](/docs/opentelemetry/integrations/haproxy/install-configure/kubernetes/nrdot-manifest-install) if you've already completed the base Kubernetes OpenTelemetry manifest installation, or the [Helm install](/docs/opentelemetry/integrations/haproxy/install-configure/kubernetes/nrdot-helm-install) for the Helm chart.
- **OTel Collector Contrib**: The community OpenTelemetry Collector. Install it with Helm or manifests.
- **Prometheus receiver**: Works with NRDOT or OTel Collector Contrib. Use this only if your HAProxy pods already expose a Prometheus endpoint.

## Guided install [#ui-install]

To install this through the New Relic UI instead, go to <DNT>**one.newrelic.com > Integrations & Agents > [HAProxy (OpenTelemetry Collector)](https://onenr.io/0yw4lk5A0w3)**</DNT>. Follow the on-screen instructions to set up the integration.

## Installation at a glance [#at-a-glance]

Setting up HAProxy monitoring involves these tasks:

1. Check compatibility and gather prerequisites
2. Set up the collector
3. Apply the minimum configuration
4. Restart the collector
5. Verify data is flowing to New Relic
