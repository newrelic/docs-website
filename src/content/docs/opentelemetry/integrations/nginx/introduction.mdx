The New Relic NGINX integration uses the OpenTelemetry Collector to monitor your NGINX web servers through a single, vendor-neutral pipeline. Once connected, you can see how your servers handle connections and requests, spot saturation before it affects users, and follow requests from your applications through NGINX to your backends.

## Capabilities [#capabilities]

- **Metrics**: Active, accepted, and handled connections, and request counts, collected from the NGINX stub status endpoint.
- **Logs**: NGINX access and error logs, forwarded through the collector (optional). See [Forward NGINX logs](/docs/opentelemetry/integrations/nginx/advanced-configuration#logs).
- **Distributed tracing**: With NGINX 1.25.3 or later and `ngx_otel_module`, NGINX spans join your application traces and create service relationships. See [NGINX distributed tracing with OpenTelemetry](/docs/opentelemetry/integrations/nginx/nginx-otel-distributed-tracing).
- **Entities**: Each NGINX server appears as an `NGINXSERVER` entity.

## Choose your install path [#choose]

**Self-hosted**: For NGINX running directly on servers or VMs.
- **NRDOT** (recommended): New Relic's distribution of the OpenTelemetry Collector; the most direct path if you have no existing collector.
- **OTel Collector Contrib**: The community OpenTelemetry Collector distribution; pick this if your environment already standardizes on it.
- **Prometheus receiver**: Pick this only if you already run the [NGINX Prometheus exporter](https://github.com/nginxinc/nginx-prometheus-exporter) and want to reuse it.

**Kubernetes**: For NGINX running in a Kubernetes cluster, with automatic pod discovery.
- **NRDOT** (recommended): Choose [manifest install](/docs/opentelemetry/integrations/nginx/install-configure/kubernetes/nrdot-manifest-install) if you've already completed the base Kubernetes OpenTelemetry manifest installation, or [Helm install](/docs/opentelemetry/integrations/nginx/install-configure/kubernetes/nrdot-helm-install) if you've completed the base Helm installation.
- **OTel Collector Contrib**: Pick this if your environment already standardizes on the community collector.
- **Prometheus receiver**: Pick this only if you already run the NGINX Prometheus exporter as a sidecar.

Using NGINX Plus? It has its own integration. See [Monitor self-hosted NGINX Plus with OpenTelemetry](/docs/opentelemetry/integrations/nginx-plus/nginx-plus-otel).

## Guided installation [#ui-install]

Guided installation is available at <DNT>**[one.newrelic.com](https://one.newrelic.com) > Integrations & Agents > NGINX (OpenTelemetry Collector)**</DNT>. The UI provides a guided end-to-end workflow.

## Installation at a glance [#at-a-glance]

1. Check compatibility and gather prerequisites, including enabling the NGINX stub status module
2. Set up the collector
3. Configure the collector to scrape NGINX and send data to New Relic
4. Start or restart the collector
5. Verify data is flowing to New Relic
