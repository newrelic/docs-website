Monitor your PostgreSQL database performance using New Relic Distribution of OpenTelemetry (NRDOT) with comprehensive insights into database metrics, query performance, and system health.

This NRDOT-based approach complements our existing On-Host Integration (OHI) by leveraging OpenTelemetry standards for database monitoring, making it easier to integrate with your existing observability stack.


## Choose your installation method [#install]

You can install NRDOT Collector for PostgreSQL monitoring in following ways:

* **Manual install**: Set up the collector yourself on your own infrastructure
  * [Self-hosted setup](/docs/opentelemetry/db360/postgresql/hosted)
  * [AWS RDS or Aurora setup](/docs/opentelemetry/db360/postgresql/rds)
* **[New Relic CLI](/docs/opentelemetry/db360/postgresql/cli)**: Install and configure the collector with a single command
* **[Ansible](/docs/opentelemetry/db360/postgresql/ansible)**: Install and configure the collector at scale using the `newrelic.newrelic_install` Ansible role
* **[Chef](/docs/opentelemetry/db360/postgresql/chef)**: Install and configure the collector at scale using the `newrelic-install` Chef cookbook
* **[Helm chart](/docs/opentelemetry/db360/postgresql/helm)**: Install and configure PostgreSQL monitoring on Kubernetes using the `postgresql-otel` Helm chart
* **[Docker](/docs/opentelemetry/db360/postgresql/docker)**: Run the collector as a sibling container to a PostgreSQL instance already running in Docker


## Installation at a glance [#glance]

The high-level tasks for installing NRDOT Collector for PostgreSQL monitoring are:

<Steps>

<Step>

### Prerequisites [#prerequisites]

Before you install, make sure you have:

* PostgreSQL `14` and above
* A New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key).
* Network connectivity between the host where you install the NRDOT Collector and your PostgreSQL database.
* Network connectivity to [New Relic OTLP endpoints documentation](/docs/opentelemetry/best-practices/opentelemetry-otlp/)

For supported detailed prerequisites, refer to [Compatibility](/docs/opentelemetry/db360/postgresql/compatibility) document.


</Step>


<Step>

### Install NRDOT Collector [#install]

Choose your installation path based on your infrastructure:

- **[Self-hosted PostgreSQL](/docs/opentelemetry/db360/postgresql/hosted)**
- **[RDS PostgreSQL monitoring](/docs/opentelemetry/db360/postgresql/rds)** 

To automate the install instead, use the [New Relic CLI](/docs/opentelemetry/db360/postgresql/cli), [Ansible](/docs/opentelemetry/db360/postgresql/ansible), or [Chef](/docs/opentelemetry/db360/postgresql/chef). To monitor PostgreSQL from Kubernetes, use the [Helm chart](/docs/opentelemetry/db360/postgresql/helm). If PostgreSQL runs in Docker, use the [Docker install](/docs/opentelemetry/db360/postgresql/docker).


</Step>

<Step>

### Configure PostgreSQL monitoring user [#user]

Create and provides necessary permissions to the monitoring user for NRDOT Collector to collect metrics and query samples.

</Step>

<Step>

### Configure NRDOT Collector [#configure]

Configure the NRDOT Collector to connect to your PostgreSQL database and New Relic account. This includes setting up the connection details, authentication, and any additional configuration options. 

</Step>

<Step>

### Find and use your data [#find]

Once your data is being collected, you can access comprehensive PostgreSQL database monitoring through New Relic's UI.

To find your PostgreSQL database entity in New Relic:

1. Go to <DNT>**[https://one.newrelic.com](https://one.newrelic.com) > All Capabilities > Databases**</DNT>.
2. From the **<DNT>Entity type</DNT>** dropdown, select <DNT>**PostgreSQL instance**</DNT>, then click <DNT>**Apply**</DNT>.
3. Select your PostgreSQL database from the list of entities.

</Step>

</Steps>
