The `sqlqueryreceiver` is an OpenTelemetry Collector receiver that lets you run any custom SQL query against your database and ingest the results as metrics, logs, or custom events into New Relic.

Use this when you want to monitor data not covered by the built-in `nroracledbreceiver` / `nrsqlserverreceiver` / `nrmysqlreceiver` / `nrpostgresqlreceiver` metrics. Custom metrics, logs, and events collected via `sqlqueryreceiver` appear under the same Oracle, SQL Server, MySQL, or PostgreSQL entity in New Relic as the built-in receiver data, provided the entity-linking attributes are configured correctly.

## Prerequisites [#prerequisites]

* The database user configured in the datasource must have `SELECT` privilege on any view or table you intend to query.
* The collector binary must include the `sqlqueryreceiver` component.

Add the `sqlqueryreceiver` block inside the `receivers:` section of your existing `oracle-config.yaml`, alongside the existing `nroracledb` block:

```yaml
receivers:
  nroracledb:

  ...

  sql_query/oracle:
    driver: oracle

    # Approach 1: Use the `host`, `port`, `database`, `username`, and `password` fields to connect to your database. The receiver will construct the datasource URL for you.
    # host: <YOUR_DB_HOST>
    # port: <YOUR_DB_PORT>
    # database: <YOUR_DATABASE_NAME>
    # username: <YOUR_DB_USERNAME>
    # password: <YOUR_DB_PASSWORD>


    # Approach 2: Use the `datasource` field to provide a full connection string. 
    datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"

    collection_interval: 60s
    queries:
      - sql: "<YOUR_CUSTOM_SQL>"
        metrics:
          - metric_name: oracledb.<YOUR_METRIC_NAME>
            value_column: <RESULT_COLUMN>
            attribute_columns: [<DIMENSION_COLUMN_1>, <DIMENSION_COLUMN_2>]
            value_type: double
```

### Custom logs and custom events

Add separate receivers for custom logs and custom events, using a `logs:` block instead of `metrics:`.

Custom logs and custom events need two things to link to the database entity:

* **`db.system.name`** as a constant column in the query, included in `attribute_columns`, set to `oracle`. The metric name prefix rule under **Naming convention** applies to metrics only; for logs and events, `db.system.name` is what links the data instead.
* **`server.address`** and **`server.port`** on the resource, set to the same values the database receiver uses. This is the same requirement as for custom metrics, so reuse the processors from this tab's `metrics/custom` pipeline.

For custom events specifically, also add **`newrelic.event.type`** as a constant column included in `attribute_columns`. Its value becomes the event type name in the New Relic Database (NRDB).

<Callout variant="important">

Without `db.system.name`, or without matching `server.address`/`server.port` values, the data still lands in New Relic but isn't linked to the database entity.

</Callout>

```yaml
receivers:
  # Custom logs
  sql_query/oracle_logs:
    driver: oracle
    datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"
    collection_interval: 60s
    queries:
      - sql: "SELECT <YOUR_COLUMNS>, 'oracle' AS \"db.system.name\" FROM <YOUR_TABLE>"
        logs:
          - body_column: <SOME_TEXT_COLUMN>
            attribute_columns: [<COLUMN_1>, <COLUMN_2>, "db.system.name"]

  # Custom events
  sql_query/oracle_events:
    driver: oracle
    datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"
    collection_interval: 60s
    queries:
      - sql: "SELECT <YOUR_COLUMNS>, '<YOUR_EVENT_NAME>' AS \"newrelic.event.type\", 'oracle' AS \"db.system.name\" FROM <YOUR_TABLE>"
        logs:
          - body_column: <SOME_TEXT_COLUMN>
            attribute_columns: [<COLUMN_1>, "newrelic.event.type", "db.system.name"]
```

### Naming convention

Metric names must start with `oracledb.` to be associated with the correct entity in New Relic. New Relic still ingests metrics with a different prefix, but they won't appear under the database entity.

### Entity synthesis

Add `resource/add_event_name` and `resource/add_host` processors to set `server.address` and `server.port` to the same values used by the database receiver. Without this, custom metrics won't link to the database entity.

Add the processors in the `processors:` section:

```yaml
processors:
  batch:
  resource/add_event_name:
    attributes:
      - key: server.address
        value: "<YOUR_DB_HOST>"
        action: upsert
  resource/add_host:
    attributes:
      - key: server.port
        value: "<YOUR_DB_PORT>"
        action: upsert
```

### Pipeline configuration

Add a `metrics/custom` pipeline in the `service.pipelines:` section of the config, alongside the existing pipelines:

```yaml
service:
  pipelines:
    metrics/oracledb:
      receivers: [nroracledb]
      processors: [batch]
      exporters: [otlp/newrelic]
    logs/oracledb:
      receivers: [nroracledb]
      processors: [batch]
      exporters: [otlp/newrelic]

    metrics/custom:
      receivers: [sql_query/oracle]
      processors: [resource/add_event_name, resource/add_host, batch]
      exporters: [otlp/newrelic]

    logs/custom:
      receivers: [sql_query/oracle_logs, sql_query/oracle_events]
      processors: [resource/add_event_name, resource/add_host, batch]
      exporters: [otlp/newrelic]
```

<Callout variant="important">

Add both `resource/add_event_name` and `resource/add_host` before `batch` in the processor list.

</Callout>

### NRQL to validate data

* After restarting the collector, run the following to confirm custom metrics are arriving:

  ```sql
  SELECT uniques(metricName) FROM Metric
  WHERE otel.library.name LIKE '%sqlqueryreceiver%'
  AND metricName LIKE 'oracledb.%'
  SINCE 1 hour ago
  ```

* Run the following to confirm custom logs and custom events are arriving:

  ```sql
  -- Custom events
  SELECT count(*) FROM <YOUR_EVENT_NAME> SINCE 1 hour ago
  -- Custom logs
  SELECT count(*) FROM Log WHERE db.system.name = 'oracle' SINCE 1 hour ago
  ```


## Troubleshooting [#troubleshooting]

| Issue | Cause | Fix |
|-------|-------|-----|
| `ORA-00942: table or view does not exist` | Database user missing SELECT privilege | Grant `SELECT ON <VIEW_NAME>` to the user |
| `missing port in address` | `#` in username/password not URL-encoded | Replace `#` with `%23` in the datasource URL |
| No data in New Relic | `server.address`/`server.port` not set or mismatched | Add `resource/add_event_name` and `resource/add_host` processors with the correct values |
| Metrics not under database entity | Metric name missing required prefix | Ensure metric names start with `oracledb.` |
| Logs or events in NRDB but not under the database entity | `db.system.name` missing from the query or from `attribute_columns` | Add the `db.system.name` column with the value from the table above |
| Logs or events in NRDB but not under the database entity | `server.address`/`server.port` not set or mismatched | Add the processors shown in the `logs/custom` pipeline, with the same values the database receiver uses |
| Custom event shows up under `Log` instead of its own type | The `newrelic.event.type` alias isn't quoted correctly for your DB, or isn't listed in `attribute_columns` | Match the quoting and casing shown in the snippet for your DB |

If none of the above resolves the issue, check the collector's own logs for errors:

```bash
sudo journalctl -u nrdot-collector -f
```
