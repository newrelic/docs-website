Database 360 (DB360) gives you a unified view across your applications, databases, and infrastructure so you can find the root cause of database bottlenecks faster. Instead of jumping between separate application, database, and infrastructure tools to figure out why a query is slow, DB360 models each database as a first-class entity and connects it directly to your APM services and host metrics.

DB360 is built on an OpenTelemetry-first foundation. You collect telemetry using the New Relic Distribution of OpenTelemetry (NRDOT) Collector or a CNCF OpenTelemetry Collector Contrib distribution.

## What you get [#capabilities]

- **Query execution plans**: See the exact execution path a query takes, including wait events and locks, so you can spot missing indexes and other inefficiencies.
- **Wait states and lock tracking**: Identify long-running sessions, blocking queries, and resource-heavy workloads before they affect other workloads on the same database.
- **APM-to-database correlation**: Link application traces directly to the database queries, sessions, and wait events they generate. For more information, see [APM-database correlation](/docs/opentelemetry/db360/capabilities/db-apm).
- **Infrastructure context**: View database metrics side by side with host-level CPU, memory, and I/O metrics.
- **Node and logical database visibility**: Monitor both the database server (node) and the individual logical databases running on it, so you can right-size capacity and spot idle or underused instances.

## Things to know before you start [#considerations]

- **APM correlation**: Linking database entities to APM traces currently works with the Java agent and .NET agent. 
- **Cloud provider coverage**: 
  - **AWS**: RDS, Aurora, and self-hosted on EC2 are supported across all four database engines.
  - **Oracle Cloud Infrastructure (OCI)**: Oracle Database is supported through Autonomous Database.
- **Metric volume**: Self-hosted databases generally expose more metrics than their cloud-managed equivalents, since cloud providers restrict access to some database internals.
- **Ingest controls**: You can enable or disable categories of metrics in your NRDOT configuration file to manage the volume of data you collect.
