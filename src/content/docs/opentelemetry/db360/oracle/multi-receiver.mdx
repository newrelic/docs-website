You can configure the NRDOT Collector to monitor multiple Oracle Database instances from one collector. This is useful if you have multiple Oracle databases running on different hosts and want to collect metrics from all of them using a single NRDOT Collector instance.

<Steps>

<Step>

## Prerequisites [#prerequisites]

- NRDOT is installed and configured for your Oracle Database instances:
    - [CDB](/docs/opentelemetry/db360/oracle/host-cdb)
    - [PDB](/docs/opentelemetry/db360/oracle/host-pdb)
    - [RDS](/docs/opentelemetry/db360/oracle/rds)
    - [ADB](/docs/opentelemetry/db360/oracle/adb)

</Step>

<Step>

## Add multi-receiver configuration [#multi]

The following examples show how to configure the NRDOT Collector to monitor multiple Oracle Database instances using a multi-receiver configuration. Select the deployment type that matches your environment. You can add more receivers as needed for additional instances.

<CollapserGroup>

<Collapser
  id="cdb"
  title="For on-host Container Database (CDB)">

The `oracle-config.yaml` below demonstrates how to set up multiple receivers for different on-host (multitenant) CDB instances while sharing common exporters.

```yaml
receivers:
  # First CDB configuration (anchor cd1; cdb2 inherit via merge key)
  nroracledb/cdb1: &nroracledb-common
    endpoint: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
    username: "C##<YOUR_DB_USERNAME>"
    password: "<YOUR_DB_PASSWORD>"
    service: "<YOUR_CDB1_SERVICE_NAME>"
    collection_interval: 15s

    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
      db.server.session.wait_sample:
        enabled: true
      db.server.top_procedure:
        enabled: true
      db.server.query_plan:
        enabled: true

    top_query_collection:
      max_query_sample_count: 1000
      top_query_count: 200
      collection_interval: 60s
      allowed_comment_keys:
        - nr_service_guid

    query_sample_collection:
      max_rows_per_query: 100
      allowed_comment_keys:
        - nr_service_guid

    session_wait_event_collection:
      max_rows_per_query: 100

    top_procedure_collection:
      max_procedure_sample_count: 1000

    <<: *nroracledb-common
    endpoint: "<YOUR_DB2_HOST>:<YOUR_DB2_PORT>"
    service: "<YOUR_CDB2_SERVICE_NAME>"

  otlp/newrelic:
    endpoint: "<otlp_endpoint>"
    headers:
      api-key: "<license_key>"
    compression: gzip
    retry_on_failure:
      enabled: true
      initial_interval: 5s
      max_interval: 30s
      max_elapsed_time: 300s
    sending_queue:
        enabled: true
        sizer: bytes
        queue_size: 100_000_000
        num_consumers: 10
        batch:
          sizer: bytes
          max_size: 1_000_000
          min_size: 0
          flush_timeout: 5s  

service:
  pipelines:
    metrics/oracledb:
      receivers: [nroracledb/cdb1,nroracledb/cdb2]
      exporters: [otlp/newrelic]
    logs/oracledb:
      receivers: [nroracledb/cdb1, nroracledb/cdb2]
      exporters: [otlp/newrelic]
```

## Restart NRDOT Collector [#restart]

Restart the <DNT>NRDOT Collector</DNT> service for configuration changes to take effect. The collector loads configuration parameters once at startup and doesn't support hot-reloading. Any changes made to the configuration while the collector is running remain inactive until the process restarts.

```bash
sudo systemctl restart nrdot-collector.service
```
