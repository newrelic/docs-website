Get comprehensive insights into your Oracle Database performance with database monitoring, query analysis, and system health metrics using the New Relic Distribution of OpenTelemetry (NRDOT) Collector, running as a sibling container to an Oracle Database instance that's already running in Docker.

<Callout variant="tip" title="Guided installation">
  To install through the New Relic UI instead, go to <DNT>**[one.newrelic.com > Integrations & Agents > Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>. This page covers the Docker install path only.
  </Callout>

<Callout variant="tip">
  Looking to automate this at scale instead? Refer to [Ansible install](/docs/opentelemetry/db360/oracle/ansible), [Chef install](/docs/opentelemetry/db360/oracle/chef), or [Helm chart install](/docs/opentelemetry/db360/oracle/helm) for Kubernetes.
</Callout>

## Prerequisites [#prerequisites]

Before you begin, ensure you have the following:

* Docker installed on the host.
* An Oracle Database container already running (Oracle Database `19c` or later), with `sqlplus` available inside it.
* The `sys` password for that container.
* A valid New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key).
* Network connectivity from the collector container to [New Relic OTLP endpoint](/docs/opentelemetry/best-practices/opentelemetry-otlp).

## Configure database user and grant privileges [#database-user]

Create a monitoring user and grant it the views needed for metrics, query, and event collection by running SQL against your Oracle container with `docker exec`. Choose the tab that matches your deployment, either a multitenant Container Database (CDB) or a single Pluggable Database (PDB):

<CollapserGroup>

<Collapser
  id="docker-cdb"
  title="Container Database (CDB)"
>

This creates a common user (required to use the `C##` prefix) and grants it visibility across every PDB under the CDB. Replace `<YOUR_ORACLE_CONTAINER_NAME>`, `<YOUR_SYS_PASSWORD>`, `<YOUR_DB_USERNAME>`, and `<YOUR_DB_PASSWORD>` with your own values:

```bash
docker exec -i <YOUR_ORACLE_CONTAINER_NAME> sqlplus sys/'<YOUR_SYS_PASSWORD>' as sysdba << 'EOF'
ALTER SESSION SET CONTAINER = CDB$ROOT;

-- Create the common user and set container-data visibility
CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>" CONTAINER=ALL;
GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;

-- Grant system and dynamic performance views
GRANT SELECT ON V_$INSTANCE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$DATABASE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$CONTAINERS                 TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$DATAFILE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SYSSTAT                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$CON_SYSSTAT                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SYSMETRIC                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$CON_SYSMETRIC              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SESSION                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$RESOURCE_LIMIT             TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$OSSTAT                     TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SGAINFO                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$ROWCACHE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$PARAMETER                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON CDB_TABLESPACES               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON DBA_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON DBA_FREE_SPACE                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON DBA_RECYCLEBIN                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SQL                        TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$LOCK                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$SESSION_EVENT              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON DBA_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON DBA_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$PDBS                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON CDB_SERVICES                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON CDB_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON CDB_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON CDB_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$ASM_DISKGROUP_STAT          TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
GRANT SELECT ON V_$ASM_DISK_STAT               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

EXIT;
EOF
```

<Callout variant="tip">
  The `C##` prefix is required by Oracle for common users. The last two grants (`V_$ASM_DISKGROUP_STAT` and `V_$ASM_DISK_STAT`) are only required if you want to collect [ASM diskgroup and disk metrics](/docs/opentelemetry/db360/oracle/metrics-reference/#asm). Skip them if you don't use ASM.
</Callout>

## Ensure Docker network connectivity [#network]

Create a shared user-defined network (if you don't already have one) and connect your Oracle container to it, so the collector container can resolve it by name:

```bash
docker network create <YOUR_DOCKER_NETWORK> 2>/dev/null || true
docker network connect <YOUR_DOCKER_NETWORK> <YOUR_ORACLE_CONTAINER_NAME> 2>/dev/null || true
```

<Callout variant="tip">
  Both commands are safe to re-run: `|| true` swallows the "already exists" or "already connected" errors from a prior run.
</Callout>

</Step>

### Configuration parameters [#configuration-parameters]

| Parameter | Description |
| --- | --- |
| `<YOUR_ORACLE_CONTAINER_NAME>` | The name (or Docker DNS-resolvable hostname) of your running Oracle Database container. |
| `<YOUR_DB_USERNAME>` | The monitoring user you created in [Configure database user and grant privileges](#database-user) (the `C##` prefix is added automatically for CDB). |
| `<YOUR_DB_PASSWORD>` | The password of the monitoring user you created in [Configure database user and grant privileges](#database-user). |
| `<YOUR_CDB_SERVICE_NAME>` / `<YOUR_PDB_SERVICE_NAME>` | The Oracle service name for your CDB or PDB. |
| `<YOUR_NEWRELIC_OTLP_ENDPOINT>` | Your New Relic OTLP endpoint. For more information, see [New Relic OTLP endpoints](/docs/opentelemetry/best-practices/opentelemetry-otlp/). |
| `<YOUR_NEWRELIC_LICENSE_KEY>` | Your New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key). |

</Step>

<Step>

## Start the NRDOT Collector container [#start]

Run the collector on the same Docker network as your Oracle container:

```bash
docker run -d \
  --name nrdot-collector \
  --network <YOUR_DOCKER_NETWORK> \
  --platform linux/amd64 \
  -v "$PWD/oracle-config.yaml:/etc/nrdot-collector/oracle-config.yaml" \
  newrelic/nrdot-collector:latest \
  --config /etc/nrdot-collector/oracle-config.yaml
```

<Callout variant="tip">
  `--platform linux/amd64` avoids architecture mismatches on Apple Silicon and other ARM64 hosts where the Oracle image itself typically only ships for AMD64. Drop it if your host and images are already AMD64-native.
</Callout>

Confirm the collector container is running:

```bash
docker ps --filter name=nrdot-collector
```

If it's not running, check its logs for errors. The most common causes are YAML indentation issues in `oracle-config.yaml` or an unreachable Oracle container:

```bash
docker logs nrdot-collector
```

<Callout variant="tip">
  After changing `oracle-config.yaml`, restart the container to apply your changes:

  ```bash
  docker restart nrdot-collector
  ```
</Callout>

</Step>

## Find and use your data [#find-use-data]

Once your data is being collected, you can access comprehensive Oracle Database monitoring through the New Relic UI.

To find your Oracle Database entity in New Relic:

1. Go to <DNT>**[https://one.newrelic.com](https://one.newrelic.com) > All Capabilities > Databases**</DNT>.
2. Set the search criteria as <DNT>`instrumentation.provider = opentelemetry`</DNT>.
