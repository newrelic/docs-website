Troubleshoot common issues you may encounter when monitoring your Oracle Database with the NRDOT Collector.

## Common issues [#common-issues]

<CollapserGroup>

  <Collapser
    id="test-connection"
    title="Test network connectivity"
  >

Run the following command to verify the Oracle Database port is reachable from this host.

```bash
(timeout 3 bash -c '</dev/tcp/<YOUR_ENDPOINT>/<YOUR_PORT>' && echo "PORT OPEN - Network connection successful!") || echo "CONNECTION FAILED - Port closed or firewall blocking"
```

**Expected output:** `PORT OPEN - Network connection successful!`

</Collapser>

<Collapser
  id="otlp-endpoint-connection"
  title="Test OTLP endpoint connectivity"
>

Run the following command to verify your host can reach the selected New Relic OTLP endpoint.

```bash
ENDPOINT="<YOUR_OTLP_ENDPOINT>"
HOST=$(echo "$ENDPOINT" | sed 's|https://||' | cut -d: -f1)
PORT=$(echo "$ENDPOINT" | awk -F: '{print $NF}')
(timeout 2 bash -c "</dev/tcp/$HOST/$PORT" && echo "SUCCESS") || echo "FAILED"
```

**Expected output:** `SUCCESS`

</Collapser>

</CollapserGroup>

## Data not appearing in New Relic [#data-not-flowing]

* To check for rate-limit related issues, run:

  ```sql
  SELECT * FROM NrIntegrationError
  ```

* If data still isn't flowing, check whether there are any drop rules set on your Metric and Log events. See [Drop log data with drop filter rules](/docs/logs/ui-data/drop-data-drop-filter-rules/) and [Pipeline control](/docs/new-relic-control/pipeline-control/overview/).

* Check the NRDOT Collector logs:

  ```bash
  journalctl -u nrdot-collector -f
  ```
