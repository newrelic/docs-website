Monitor your SQL Server database performance with comprehensive metrics collected by the NRDOT Collector. By default, New Relic collects the metrics and query-level events referenced in the [Default metrics and events](#default) section. You can enhance your monitoring by enabling your desired metrics listed in the [Full-feature metrics](#full-feature) section.

## Default metrics and events [#default]

The following metrics are enabled by default. They are collected on any platform when the receiver is configured with a direct SQL Server connection.

### Log events [#log-events]

The following events are collected as OpenTelemetry log records and are enabled by default, except for `db.server.procedure_definition` which is opt-in. They provide query-level visibility: active query samples, top queries, execution plans, top stored procedures, and stored procedure definitions.

    >

    Aggregated performance metrics for the top stored procedures by elapsed time, computed as deltas over the collection interval. Correlates with `db.server.top_query` and `db.server.query_sample` via `sqlserver.procedure_id`. This event is enabled by default.

    <Callout variant="tip">

    </Callout>

    Use the `top_procedure_collection` block to tune its behavior:

    ```yaml
    top_procedure_collection:
      max_procedure_sample_count: 1000
      top_procedure_count: 250
      collection_interval: 60s
    ```

  <Collapser
    id="db-server-procedure-definition"
    title="Procedure definitions"
    >

    The SQL source text of stored procedures observed in `db.server.top_procedure`. Correlates with `db.server.top_procedure` via `sqlserver.procedure_id` and `db.namespace`. This event collects nothing unless `db.server.top_procedure` is also enabled.

## Azure SQL Database limitations [#azure-sql-database-limitations]

When monitoring Azure SQL Database, some metrics aren't available because the collector connects to a single database and doesn't have access to instance-level or operating system data.

<Callout variant="important">
  The following limitations apply only to Azure SQL Database. Azure SQL Managed Instance and self-hosted SQL Server support these metrics.
</Callout>

<CollapserGroup>
  <Collapser
    id="azure-sql-database-limitations-table"
    title="Azure SQL Database metric limitations reference"
  >

<table>
  <thead>
    <tr>
      <th>Metric</th>
      <th>Limitation</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`sqlserver.database.count`, `sqlserver.cpu.count`, `sqlserver.computer.uptime`</td>
      <td>Not supported on Azure SQL Database. These metrics require instance-level server properties.</td>
    </tr>
    <tr>
      <td>`sqlserver.os.memory.usage`, `sqlserver.os.memory.utilization`, `sqlserver.os.disk.size`, `sqlserver.os.scheduler.runnable_tasks.count`</td>
      <td>Not supported on Azure SQL Database. These metrics require operating system views that the service doesn't expose.</td>
    </tr>
    <tr>
      <td>`sqlserver.thread_pool.tasks.count`, `sqlserver.thread_pool.workers.count`, `sqlserver.thread_pool.workers.max`, `sqlserver.thread_pool.workers.utilization`</td>
      <td>Not supported on Azure SQL Database.</td>
    </tr>
    <tr>
      <td>`sqlserver.tempdb.allocation.wait_time.total`, `sqlserver.tempdb.contention.waiters.count`, `sqlserver.tempdb.data_files.count`, `sqlserver.tempdb.file.size`, `sqlserver.tempdb.space.usage`</td>
      <td>Not supported on Azure SQL Database. Instance-level tempdb views aren't available.</td>
    </tr>
    <tr>
      <td>`sqlserver.transaction.longest_running_time`</td>
      <td>Not supported on Azure SQL Database.</td>
    </tr>
    <tr>
      <td>`sqlserver.failover_cluster.ag.cluster_type`, `sqlserver.failover_cluster.ag.failure_condition_level`, `sqlserver.failover_cluster.ag.health_check_timeout`, `sqlserver.failover_cluster.ag.required_sync_secondaries`, `sqlserver.failover_cluster.replica.role`, `sqlserver.failover_cluster.replica.synchronization_health`, `sqlserver.failover_cluster.replica.database.queue_size`, `sqlserver.failover_cluster.replica.database.redo.rate`</td>
      <td>Not supported on Azure SQL Database. Always On Availability Groups aren't exposed by the service.</td>
