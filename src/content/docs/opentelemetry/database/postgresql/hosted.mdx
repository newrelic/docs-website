Set up PostgreSQL monitoring using the NRDOT Collector on self-hosted environments including physical servers, virtual machines, and standalone installations.

<Steps>

<Step>

### Setup the NRDOT Collector [#setup]

Install the NRDOT Collector on your system:

<Step>

### Configure PostgreSQL server settings [#server-settings]

1. Open `postgresql.conf`:
   
   ```bash
   sudo nano /var/lib/pgsql/data/postgresql.conf
   ```

2. Add `pg_stat_statements` to `shared_preload_libraries`, and optionally configure other recommended settings:
   
   ```ini
   shared_preload_libraries = 'pg_stat_statements'
   pg_stat_statements.max = 10000 # optional: normalized queries tracked
   pg_stat_statements.track = all # optional: track statements inside functions
   pg_stat_statements.save = on # optional: persist stats across restarts
   track_activity_query_size = 4096 # optional: improves query sample text fidelity
   track_functions = all # optional: required for function call metrics
   ```

3. Restart PostgreSQL server:
   
   ```bash
   sudo systemctl restart postgresql-*
   ```

</Step>

<Step>

### Configure database user and grants [#database-user]

#### 1. Connect as a superuser (once)

```bash
sudo -u postgres psql --dbname=postgres --port=5432
```

#### 2. Create the monitoring role (once, cluster-wide)

```sql
CREATE USER otelu WITH LOGIN PASSWORD '<USER_PASSWORD>';
```

#### 3. Grant cluster-wide monitoring privileges (once, cluster-wide)

```sql
GRANT SELECT ON pg_stat_database TO otelu;
GRANT pg_monitor TO otelu;
```

#### 4. Connect to each database you want to monitor (repeat per database)

```bash
psql --username=postgres --dbname=<YOUR_DATABASE_NAME>
```

#### 5. Grant table access and create `pg_stat_statements` (per database)

```sql
GRANT USAGE ON SCHEMA public TO otelu;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO otelu;
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
-- Repeat the GRANT lines for any additional schema you want metrics from:
-- GRANT USAGE ON SCHEMA <schema> TO otelu;
-- GRANT SELECT ON ALL TABLES IN SCHEMA <schema> TO otelu;
```

#### 6. (Optional) Create `pgvector` extension (per database — required only for vector metrics)

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

Requires PostgreSQL 13+. The `l1`, `hamming`, and `jaccard` distance functions require pgvector 0.7.0+.

#### 7. (Optional) Create the EXPLAIN helper function (per database)

For EXPLAIN plans on write statements without granting write access to the monitoring user:

```sql
CREATE OR REPLACE FUNCTION otel.explain_statement(l_query text)
RETURNS json
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
v_plan json;
v_param_count int;
v_nulls text := '';
i int;
BEGIN
SET TRANSACTION READ ONLY;
SET plan_cache_mode = force_generic_plan;
EXECUTE 'PREPARE otel_explain_stmt AS ' || l_query;
SELECT COALESCE(array_length(parameter_types, 1), 0) INTO v_param_count
FROM pg_prepared_statements WHERE name = 'otel_explain_stmt';
IF v_param_count > 0 THEN
FOR i IN 1..v_param_count LOOP
v_nulls := v_nulls || CASE WHEN i > 1 THEN ', ' ELSE '' END || 'null';
END LOOP;
v_nulls := '(' || v_nulls || ')';
END IF;
EXECUTE 'EXPLAIN (FORMAT JSON) EXECUTE otel_explain_stmt' || v_nulls INTO v_plan;
DEALLOCATE otel_explain_stmt;
RETURN v_plan;
EXCEPTION WHEN OTHERS THEN
IF EXISTS (SELECT 1 FROM pg_prepared_statements WHERE name = 'otel_explain_stmt') THEN
DEALLOCATE otel_explain_stmt;
END IF;
RAISE;
END;
$$;
GRANT EXECUTE ON FUNCTION otel.explain_statement(text) TO otelu;
```

#### 8. Verify the connection and grants

```bash
psql --username=otelu --host=localhost --port=5432 --dbname=<YOUR_DATABASE_NAME> --command '\conninfo'
psql --username=otelu --host=localhost --port=5432 --dbname=<YOUR_DATABASE_NAME> \
-c "SELECT * FROM pg_stat_database LIMIT 1;" && echo "pg_stat_database OK"
psql --username=otelu --host=localhost --port=5432 --dbname=<YOUR_DATABASE_NAME> \
-c "SELECT * FROM pg_stat_activity LIMIT 1;" && echo "pg_stat_activity OK"
psql --username=otelu --host=localhost --port=5432 --dbname=<YOUR_DATABASE_NAME> \
-c "SELECT * FROM pg_stat_statements LIMIT 1;" && echo "pg_stat_statements OK"
```

### Configure NRDOT Collector [#configure-collector]

Configure the NRDOT Collector with your PostgreSQL-specific settings. Create a configuration file (e.g., `postgresql-config.yaml`) with the following content:

```yaml
receivers:
  nrpostgresql:
    endpoint: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
    transport: tcp
    username: "<YOUR_DB_USERNAME>"
    password: "<YOUR_DB_PASSWORD>"
    databases:
      - "<YOUR_DATABASE_NAME>"
    collection_interval: 10s
    initial_delay: 1s
    tls:
      insecure: false
      insecure_skip_verify: false
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
    query_sample_collection:
      max_rows_per_query: 1000
    top_query_collection:
      max_rows_per_query: 1000
      top_n_query: 200
      collection_interval: 60s
      max_explain_each_interval: 1000
      query_plan_cache_size: 1000
      query_plan_cache_ttl: 1h
      explain_function_name: otel.explain_statement
      allowed_comment_keys: [nr_service_guid]
    # Metrics needed for the out-of-the-box dashboard but disabled by default
    metrics:
      postgresql.database.locks:
        enabled: true
      postgresql.deadlocks:
        enabled: true
      postgresql.function.calls:
        enabled: true
      postgresql.query.conflicts:
        enabled: true
      postgresql.sequential_scans:
        enabled: true
      postgresql.temp.io:
        enabled: true
      postgresql.temp_files:
        enabled: true

processors:
  batch:
  # Transform processor to add server.address and server.port for entity synthesis
  transform/postgresql_server_attrs:
    metric_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], Split(resource.attributes["service.instance.id"], ":")[0])
          - set(resource.attributes["server.port"], Int(Split(resource.attributes["service.instance.id"], ":")[1]))
    log_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], Split(resource.attributes["service.instance.id"], ":")[0])
          - set(resource.attributes["server.port"], Int(Split(resource.attributes["service.instance.id"], ":")[1]))

exporters:
  otlphttp/newrelic:
    endpoint: "<YOUR_NEWRELIC_OTLP_ENDPOINT>"
    headers:
      api-key: "<YOUR_NEWRELIC_LICENSE_KEY>"
    compression: gzip
    retry_on_failure:
      enabled: true
      initial_interval: 5s
      max_interval: 30s
      max_elapsed_time: 300s

service:
  telemetry:
    metrics:
      level: none
  pipelines:
    metrics:
      receivers: [nrpostgresql]
      processors: [transform/postgresql_server_attrs, batch]
      exporters: [otlphttp/newrelic]
    logs:
      receivers: [nrpostgresql]
      processors: [transform/postgresql_server_attrs, batch]
      exporters: [otlphttp/newrelic]
```

<Callout variant="important">
**Entity synthesis requirements**: The transform processor adds `server.address` and `server.port` attributes that are **required** for APM correlation and entity synthesis in New Relic. Without these attributes, the PostgreSQL entity won't populate correctly and APM-database relationships won't resolve.
</Callout>

<Step>

### Restart NRDOT Collector [#restart-collector]

After configuring the collector, restart the NRDOT Collector service to apply the changes:

```bash
sudo systemctl restart nrdot-collector
```

To verify that the collector is running properly, check the service status:

```bash
sudo systemctl status nrdot-collector
```

<Callout variant="tip">
  Always restart the NRDOT Collector after making configuration changes to ensure the new settings take effect.
</Callout>

</Step>

<Step>

### (Optional) Multi-receiver configuration [#multi-receiver]

To monitor multiple PostgreSQL instances from one collector, add multiple named instances of the receiver:

```yaml
receivers:
  nrpostgresql/instance1: &nrpostgresql-common
    endpoint: "<INSTANCE_1_HOST>:<PORT>"
    username: "<YOUR_DB_USERNAME>"
    password: "<YOUR_DB_PASSWORD>"
    databases:
      - "<INSTANCE_1_DATABASE_NAME>"
    collection_interval: 10s
  nrpostgresql/instance2:
    <<: *nrpostgresql-common
    endpoint: "<INSTANCE_2_HOST>:<PORT>"
    databases:
      - "<INSTANCE_2_DATABASE_NAME>"

service:
  pipelines:
    metrics:
      receivers: [nrpostgresql/instance1, nrpostgresql/instance2]
      processors: [transform/postgresql_server_attrs, batch]
      exporters: [otlphttp/newrelic]
    logs:
      receivers: [nrpostgresql/instance1, nrpostgresql/instance2]
      processors: [transform/postgresql_server_attrs, batch]
      exporters: [otlphttp/newrelic]
```

</Step>

### (Optional) Set up APM-database correlation [#optional-service-id]

To correlate your application performance with database operations, you can set up database service identification. This feature allows you to see exactly which applications are generating specific database workloads. For more information, refer to [set up database service identification](/docs/opentelemetry/database/capabilities/db-apm/) to get APM-database correlation in New Relic.

<Callout variant="important">
  To view database performance data in APM, both entities must be in the same New Relic account. If the entities are in different New Relic accounts, you must have access to both accounts to view the data.
</Callout>

### Find and use your data [#find-use-data]

Once your data is being collected, you can access comprehensive PostgreSQL database monitoring through New Relic's UI.

To find your PostgreSQL database entity in New Relic:

1. Go to <DNT>**[https://one.newrelic.com](https://one.newrelic.com) > All Capabilities > Databases**</DNT>.
2. From the **<DNT>Entity type</DNT>** dropdown, select <DNT>**PostgreSQL instance**</DNT>, then click <DNT>**Apply**</DNT>.
3. Select your PostgreSQL database from the list of entities.
    
    After setting up PostgreSQL database monitoring with NRDOT:

      * [Create custom dashboards](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) to visualize your database metrics
      * [Set up alerts](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) for critical database performance thresholds
