Set up PostgreSQL monitoring using the NRDOT Collector for AWS RDS PostgreSQL instances. RDS environments have specific considerations for extensions and parameter groups.

<Steps>

<Step>

### Prerequisites [#prerequisites]

Ensure your environment meets our [compatibility and prerequisites](/docs/opentelemetry/database/postgresql/compatibility).

**Additional RDS requirements:**
* RDS PostgreSQL instance with network accessibility from your NRDOT Collector host
* RDS parameter group with `shared_preload_libraries = 'pg_stat_statements'` enabled
* Master user credentials or a user with sufficient privileges

</Step>

<Step>

### Setup the NRDOT Collector [#setup]

Install the NRDOT Collector on a system that can connect to your RDS instance:

<Step>

### Configure RDS parameter group [#parameter-group]

1. In the AWS RDS console, modify your parameter group to include:
   
   ```
   shared_preload_libraries = pg_stat_statements
   track_activity_query_size = 4096
   track_functions = all
   ```

2. Apply the parameter group to your RDS instance and restart the instance for changes to take effect.

<Callout variant="important">
**RDS restart required**: Changes to `shared_preload_libraries` require a full RDS instance restart, not just a parameter reload.
</Callout>

</Step>

<Step>

### Configure database user [#database-user]

Create a monitoring user with the necessary privileges for your RDS PostgreSQL instance.
Connect to your RDS instance as the master user and run:

#### 1. Create the monitoring role (once, cluster-wide)

```sql
CREATE USER otelu WITH LOGIN PASSWORD '<USER_PASSWORD>';
```

#### 2. Grant cluster-wide monitoring privileges (once, cluster-wide)

```sql
GRANT SELECT ON pg_stat_database TO otelu;
GRANT pg_monitor TO otelu;
```

</Step>

<Step>

### Grant monitoring privileges for RDS [#database-grants]

Connect to each database you want to monitor and run:

#### 1. Grant table access and create extensions (per database)

```sql
GRANT USAGE ON SCHEMA public TO otelu;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO otelu;
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

#### 2. (Optional) Create pgvector extension for vector metrics

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

#### 3. (Optional) Create EXPLAIN helper function for write statement plans

```sql
CREATE OR REPLACE FUNCTION otel.explain_statement(l_query text)
RETURNS json
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
v_plan json;
v_param_count int;
v_nulls text := '';
i int;
BEGIN
SET TRANSACTION READ ONLY;
SET plan_cache_mode = force_generic_plan;
EXECUTE 'PREPARE otel_explain_stmt AS ' || l_query;
SELECT COALESCE(array_length(parameter_types, 1), 0) INTO v_param_count
FROM pg_prepared_statements WHERE name = 'otel_explain_stmt';
IF v_param_count > 0 THEN
FOR i IN 1..v_param_count LOOP
v_nulls := v_nulls || CASE WHEN i > 1 THEN ', ' ELSE '' END || 'null';
END LOOP;
v_nulls := '(' || v_nulls || ')';
END IF;
EXECUTE 'EXPLAIN (FORMAT JSON) EXECUTE otel_explain_stmt' || v_nulls INTO v_plan;
DEALLOCATE otel_explain_stmt;
RETURN v_plan;
EXCEPTION WHEN OTHERS THEN
IF EXISTS (SELECT 1 FROM pg_prepared_statements WHERE name = 'otel_explain_stmt') THEN
DEALLOCATE otel_explain_stmt;
END IF;
RAISE;
END;
$$;
GRANT EXECUTE ON FUNCTION otel.explain_statement(text) TO otelu;
```

</Step>

<Step>

### Configure NRDOT Collector [#configure-collector]

Configure the NRDOT Collector with your RDS PostgreSQL-specific settings. Create a configuration file (e.g., `rds-postgresql-config.yaml`) with the following content:

```yaml
receivers:
  nrpostgresql:
    endpoint: "<YOUR_RDS_ENDPOINT>:<YOUR_DB_PORT>"
    transport: tcp
    username: "<YOUR_DB_USERNAME>"
    password: "<YOUR_DB_PASSWORD>"
    databases:
      - "<YOUR_DATABASE_NAME>"
    collection_interval: 10s
    initial_delay: 1s
    tls:
      insecure: false
      insecure_skip_verify: false
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
    query_sample_collection:
      max_rows_per_query: 1000
      allowed_comment_keys: [nr_service_guid]
    top_query_collection:
      max_rows_per_query: 1000
      top_n_query: 200
      collection_interval: 60s
      max_explain_each_interval: 1000
      query_plan_cache_size: 1000
      query_plan_cache_ttl: 1h
      explain_function_name: otel.explain_statement
      allowed_comment_keys: [nr_service_guid]
    # Metrics needed for the out-of-the-box dashboard but disabled by default
    metrics:
      postgresql.database.locks:
        enabled: true
      postgresql.deadlocks:
        enabled: true
      postgresql.function.calls:
        enabled: true
      postgresql.query.conflicts:
        enabled: true
      postgresql.sequential_scans:
        enabled: true
      postgresql.temp.io:
        enabled: true
      postgresql.temp_files:
        enabled: true

processors:
  batch:
  transform/postgresql_server_attrs:
    metric_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], "<YOUR_RDS_ENDPOINT>")
          - set(resource.attributes["server.port"], <YOUR_DB_PORT>)
          - set(resource.attributes["cloud.provider"], "aws")
          - set(resource.attributes["cloud.platform"], "aws_rds")
    log_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], "<YOUR_RDS_ENDPOINT>")
          - set(resource.attributes["server.port"], <YOUR_DB_PORT>)
          - set(resource.attributes["cloud.provider"], "aws")
          - set(resource.attributes["cloud.platform"], "aws_rds")

exporters:
  otlphttp/newrelic:
    endpoint: "<YOUR_NEWRELIC_OTLP_ENDPOINT>"
    headers:
      api-key: "<YOUR_NEWRELIC_LICENSE_KEY>"
    compression: gzip
    retry_on_failure:
      enabled: true
      initial_interval: 5s
      max_interval: 30s
      max_elapsed_time: 300s

service:
  telemetry:
    metrics:
      level: none
  pipelines:
    metrics:
      receivers: [nrpostgresql]
      processors: [transform/postgresql_server_attrs, batch]
      exporters: [otlphttp/newrelic]
    logs:
      receivers: [nrpostgresql]
      processors: [transform/postgresql_server_attrs, batch]
      exporters: [otlphttp/newrelic]
```

<Callout variant="tip">
**RDS endpoint format**: Use your RDS endpoint hostname (e.g., `mydb.cluster-abcd1234.us-east-1.rds.amazonaws.com`) as the server address. The standard PostgreSQL port is 5432 unless you've configured a custom port.
</Callout>

</Step>

### Restart NRDOT Collector [#restart-collector]

After configuring the collector, restart the NRDOT Collector service to apply the changes:

```bash
sudo systemctl restart nrdot-collector
```

To verify that the collector is running properly, check the service status:

```bash
sudo systemctl status nrdot-collector
```

### (Optional) Multi-RDS configuration [#multi-rds]

To monitor multiple RDS PostgreSQL instances from one collector:

```yaml
receivers:
  nrpostgresql/rds1: &nrpostgresql-rds-common
    endpoint: "<RDS_INSTANCE_1_ENDPOINT>:<PORT>"
    username: "<YOUR_DB_USERNAME>"
    password: "<YOUR_DB_PASSWORD>"
    databases:
      - "<RDS_INSTANCE_1_DATABASE>"
    collection_interval: 10s
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
  nrpostgresql/rds2:
    <<: *nrpostgresql-rds-common
    endpoint: "<RDS_INSTANCE_2_ENDPOINT>:<PORT>"
    databases:
      - "<RDS_INSTANCE_2_DATABASE>"

processors:
  batch:
  transform/postgresql_rds1:
    metric_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], "<RDS_INSTANCE_1_ENDPOINT>")
          - set(resource.attributes["server.port"], <PORT>)
          - set(resource.attributes["cloud.provider"], "aws")
    log_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], "<RDS_INSTANCE_1_ENDPOINT>")
          - set(resource.attributes["server.port"], <PORT>)
          - set(resource.attributes["cloud.provider"], "aws")
  transform/postgresql_rds2:
    metric_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], "<RDS_INSTANCE_2_ENDPOINT>")
          - set(resource.attributes["server.port"], <PORT>)
          - set(resource.attributes["cloud.provider"], "aws")
    log_statements:
      - context: resource
        statements:
          - set(resource.attributes["server.address"], "<RDS_INSTANCE_2_ENDPOINT>")
          - set(resource.attributes["server.port"], <PORT>)
          - set(resource.attributes["cloud.provider"], "aws")

service:
  pipelines:
    metrics/rds1:
      receivers: [nrpostgresql/rds1]
      processors: [transform/postgresql_rds1, batch]
      exporters: [otlphttp/newrelic]
    metrics/rds2:
      receivers: [nrpostgresql/rds2]
      processors: [transform/postgresql_rds2, batch]
      exporters: [otlphttp/newrelic]
```

</Step>

## RDS-specific considerations

### Extensions and parameter groups

On AWS RDS, extensions like `pg_stat_statements` and `pgvector` must be created in each database individually. Parameter changes requiring restarts (like `shared_preload_libraries`) need to be configured in the RDS parameter group.

### Network security

Ensure your RDS security groups allow inbound connections on the PostgreSQL port (default 5432) from the system running the NRDOT Collector.

### Parameter group settings

Verify that your RDS parameter group has the following settings:
- `shared_preload_libraries = 'pg_stat_statements'`
- `track_activity_query_size = 4096` (optional)
- `track_functions = all` (optional, for function metrics)

Changes to these parameters require a restart of the RDS instance.
