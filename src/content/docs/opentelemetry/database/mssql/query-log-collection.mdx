You can configure the NRDOT Collector to collect query-level telemetry from your MSSQL instance: the queries actually running, their execution plans, and their resource usage. This gives you query-level observability on top of the standard metrics collection.

<Callout variant="important">
The logs pipeline isn't a stream of collector debug or internal logs. It carries SQL Server query telemetry, such as query text, execution plans, and sample data, captured by the `nrsqlserver` receiver's `db.server.query_sample` and `db.server.top_query` events and emitted as OpenTelemetry log records. It's query-level observability data for the SQL Server instance you're monitoring.
</Callout>

## Enable top query collection [#top-query]

`db.server.top_query` reports aggregated per-query execution stats from the SQL Server plan cache (`sys.dm_exec_query_stats`), as incremental (delta) values since the last collection cycle. It's disabled by default. Add the following to your receiver configuration to enable it:

```yaml
receivers:
  nrsqlserver:
    events:
      db.server.top_query:
        enabled: true
    top_query_collection:
      lookback_time: 60s
      max_query_sample_count: 1000
      top_query_count: 250
      collection_interval: 60s
```

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `top_query_collection.collection_interval` | duration | `60s` | Minimum time between top query collections. Must be greater than `collection_interval` to have an effect. |
| `top_query_collection.lookback_time` | duration | `0` | Time window to look back for completed queries. Defaults to 2 × `top_query_collection.collection_interval` at runtime. |
| `top_query_collection.max_query_sample_count` | uint | `1000` | Maximum rows fetched from the DMV before trimming to `top_query_count`. Maximum: `10000`. |
| `top_query_collection.top_query_count` | uint | `250` | Maximum number of top queries reported per run. Must be less than or equal to `max_query_sample_count`. |

For the output record format, see the [`db.server.top_query` reference](https://github.com/newrelic-forks/opentelemetry-collector-contrib/blob/pre-release/receiver/nrsqlserverreceiver/documentation.md#dbservertop_query).

</Step>

<Step>

## Enable query sample collection [#query-sample]

`db.server.query_sample` reports a point-in-time snapshot of currently executing queries and sessions from `sys.dm_exec_requests` and `sys.dm_exec_sessions`. It's disabled by default. Add the following to your receiver configuration to enable it:

```yaml
receivers:
  nrsqlserver:
    events:
      db.server.query_sample:
        enabled: true
    query_sample_collection:
      max_rows_per_query: 100
```

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `query_sample_collection.max_rows_per_query` | uint | `100` | Maximum number of in-flight queries returned per scrape cycle. |

For the output record format, see the [`db.server.query_sample` reference](https://github.com/newrelic-forks/opentelemetry-collector-contrib/blob/pre-release/receiver/nrsqlserverreceiver/documentation.md#dbserverquery_sample).

</Step>

<Step>

## Configure common log fields [#common-fields]

These fields apply to both `db.server.top_query` and `db.server.query_sample` collection:

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `collection_interval` | duration | `10s` | How often the receiver scrapes metrics and active query samples. |
| `collect_full_query_text` | bool | `false` | When `true`, includes the full SQL text in log records instead of a truncated version. |
| `allowed_comment_keys` | list | `[]` | SQL comment keys to extract from query text (for example, `nr_service_guid`). |

Each log record also carries a set of resource attributes that identify the SQL Server instance the telemetry came from. See the [resource attributes reference](https://github.com/newrelic-forks/opentelemetry-collector-contrib/blob/pre-release/receiver/nrsqlserverreceiver/documentation.md#resource-attributes) for the full list.

</Step>

<Step>

## Restart NRDOT Collector [#restart]

Restarting is required, not optional — the collector loads its configuration once at startup and doesn't hot-reload. Any configuration change has no effect until you restart the process.

```bash
sudo systemctl restart nrdot-collector
```
