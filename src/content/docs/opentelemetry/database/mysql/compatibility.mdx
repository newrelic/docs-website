Before you begin monitoring your MySQL with NRDOT, ensure your environment meets these requirements.

## Prerequisites

Before you begin, ensure you have the following:

* Valid New Relic [license key](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* Administrative access to your MySQL database instance
* Network connectivity between the NRDOT Collector and your database
* MySQL client tools (`mysql` CLI or MySQL Workbench)
* This integration is available as a part of New Relic public preview program. Check with your Organization Manager to opt in from the [Previews & Trials](https://one.newrelic.com/admin-portal/promotion-management/home) page.

## Required grants

The monitoring user needs access to the Performance Schema for query samples, top queries, and blocking-session detection:

```sql
GRANT SELECT ON performance_schema.* TO '<your-user>'@'%';
```

Most metrics only need `SHOW GLOBAL STATUS`. The grant above is required for query samples, top queries, and blocking-session detection.

### Optional grants for enhanced monitoring

Required only for `mysql.events_waits_current.timer_wait` (lock-wait duration on `db.server.query_sample`) — this Performance Schema consumer is **disabled by default** everywhere, including AWS RDS:

```sql
GRANT UPDATE ON performance_schema.setup_consumers TO '<your-user>'@'%';
```

## Recommended server parameters

For optimal monitoring experience, configure these MySQL server parameters:

<table>
  <thead>
    <tr>
      <th>Parameter</th>
      <th>Recommended value</th>
      <th>Why</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`performance_schema`</td>
      <td>Enabled (**required**)</td>
      <td>Query samples, top queries, and blocking detection all depend on it</td>
    </tr>
    <tr>
      <td>`max_digest_length`</td>
      <td>`4096`</td>
      <td>Longer digest text before MySQL truncates it</td>
    </tr>
    <tr>
      <td>`performance_schema_max_digest_length`</td>
      <td>`4096`</td>
      <td>Same, at the Performance Schema layer</td>
    </tr>
    <tr>
      <td>`performance_schema_max_sql_text_length`</td>
      <td>`4096`</td>
      <td>If a captured statement is truncated (ends in `...`), the receiver **skips** `EXPLAIN` for it entirely — query plans silently disappear for long statements at the 1024-byte default</td>
    </tr>
  </tbody>
</table>

## Performance Schema consumer configuration

The `events_waits_current` consumer provides lock-wait duration information but requires platform-specific configuration:

<table>
  <thead>
    <tr>
      <th>Platform</th>
      <th>Method</th>
      <th>Persistent across restarts?</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Self-managed MySQL</td>
      <td>`performance-schema-consumer-events-waits-current=ON` in `[mysqld]` (`my.cnf`/`my.ini`)</td>
      <td>Yes</td>
    </tr>
    <tr>
      <td>AWS RDS</td>
      <td>`UPDATE performance_schema.setup_consumers SET ENABLED='YES' WHERE NAME='events_waits_current';`</td>
      <td>**No** — resets on restart/failover. Re-run after each restart, or grant the receiver user this `UPDATE` so it can re-enable the consumer automatically on reconnect.</td>
    </tr>
  </tbody>
</table>

## System requirements

* System to run the NRDOT Collector (Linux, Windows, or macOS)
* Network connectivity to New Relic's OTLP endpoint
* At least 512MB RAM and 1 CPU core for the collector
