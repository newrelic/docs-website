<DNT>Fleet Control</DNT> provides centralized, remote management for your New Relic agents, helping you manage the entire instrumentation lifecycle at scale. It manages agents on Kubernetes clusters, Linux hosts, and Windows hosts, and all three share the same consistent <DNT>Fleet Control</DNT> experience. For a complete list of supported agents and their environments, see our [agent type compatibility documentation](/docs/new-relic-control/agent-control/agent-types).

With <DNT>Fleet Control</DNT>, you can:
* **Centralize agent operations and reduce manual toil:** Install, monitor, configure, and update all agents and integrations in one place.
* **Customize fleets for bulk management:** Group agents by instrumentation needs and easily upgrade agent versions for entire fleets with a few clicks. No scripts needed.
* **Eliminate telemetry gaps:** Manage agents on Kubernetes clusters with one lightweight supervisor—Agent Control—that scales across your environment.

To navigate to <DNT>Fleet Control</DNT>, go to <DNT>**All capabilities → New Relic Control → Fleets**</DNT>. You can use the pin to add New Relic Control to the left side navigation bar for easy access.

## Why use <DNT>Fleet Control</DNT>?
Managing instrumentation across a large environment can lead to significant challenges. <DNT>Fleet Control</DNT> is designed to solve these problems by giving you a centralized control plane to:
* **Prevent outdated agents:** Keep agents up-to-date to avoid security risks, incompatibilities, and to ensure you can capitalize on the latest New Relic innovations.
* **Avoid configuration drift:** Eliminate hidden observability gaps and compliance issues by ensuring consistent configurations across all your entities.
* **Fix broken instrumentation:** Quickly identify and resolve issues with your instrumentation to maintain trust in your observability data.
* **Reduce manual effort:** Stop relying on one-off scripts and manual updates to manage your agents and integrations.

## What is a fleet?
In <DNT>Fleet Control</DNT>, a fleet is a homogeneous collection of managed entities (such as Kubernetes clusters or hosts) that share identical instrumentation configurations. Fleets serve as logical groupings of managed entities, allowing for streamlined management and consistent observability configuration at scale.

A fleet is made up of three main components:
* **Active deployment:** A summary of the latest set of actions applied to the fleet. A deployment can include one or more actions, such as installing, deleting, or updating an agent's configuration, and reflects the end result of those changes.
* **Agents & Configurations:** The agents and configurations that are being instrumented on the managed entities in the fleet.
* **Managed Entities:** All the assigned managed entities that are joined to the fleet.

### Understanding managed entities
In the context of <DNT>Fleet Control</DNT>, a managed entity is a Kubernetes cluster, Linux host, or Windows host running New Relic instrumentation managed by <DNT>Agent Control</DNT>. Each fleet is associated with a specific managed entity type (Kubernetes Cluster, Linux Host, or Windows Host), and all entities within a fleet must match that type. Agent configuration is specified at the fleet level, and every managed entity in the fleet shares the same configuration.

* **Managed entity:** A Kubernetes cluster or host that has Agent Control installed. This means the entity is capable of being managed by <DNT>Fleet Control</DNT>, but it is not necessarily joined to a fleet yet.
* **Assigned managed entity:** A managed entity that has been joined to a fleet. This entity is now actively managed by <DNT>Fleet Control</DNT>, and its configuration is dictated by the fleet it belongs to.
* **Unassigned managed entity:** A managed entity that is not currently joined to any fleet. While it has Agent Control installed and can be managed, it is currently operating using its own local configuration.

<Callout title="Important" variant="important">
  You cannot add a Kubernetes cluster or host to a fleet before installing Agent Control to make it a managed entity.
</Callout>

## Key features
* **Centralized management:** Offers a unified platform for administering agents running on fleets of Kubernetes clusters and hosts, allowing you to manage instrumentation across your infrastructure at scale.
* **Real-time visibility:** Manage the health of your instrumentation with a clear view into fleet health, agent status, deployment progress, and configuration errors.
* **Flexible fleet organization:** Create distinct fleets to represent different instrumentation standards, application environments, or team-specific needs. This structure supports both centralized observability teams managing all configurations, and decentralized models where individual teams own and manage their specific fleets using fine-grained permissions.
* **Remote configuration:** Supports remote configuration of the New Relic agents and integrations responsible for monitoring various aspects of your environment and reporting key data points, including metrics, events, logs, and traces (MELT).

## Prerequisites
Before setting up <DNT>Fleet Control</DNT>, ensure that your system meets the following prerequisites:

* **Agent Control:** You must have [Agent Control](/docs/new-relic-control/agent-control/setup) installed on any Kubernetes cluster or host you plan to manage. This is a required component for all <DNT>Fleet Control</DNT> functionality.

## Required permissions
Creating and editing fleets and configurations requires the <DNT>**Organization product admin**</DNT> role, which users in the default <DNT>**User**</DNT> group already have. Running deployments requires more: either <DNT>**Organization manager**</DNT> across the organization, or the <DNT>**Fleet manager**</DNT> role granted on specific fleets.

Every <DNT>Fleet Control</DNT> permission also requires the full platform [user type](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type).

For the full breakdown, including how to scope access to individual fleets and delegate it to teams, see [manage <DNT>Fleet Control</DNT> access](/docs/new-relic-control/fleet-control/access-management).
