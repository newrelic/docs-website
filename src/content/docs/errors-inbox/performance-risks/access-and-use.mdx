You can access and use <DNT>Performance Risks inbox</DNT> to proactively identify and resolve application performance issues before they impact your end users. This guide will walk you through how to access the <DNT>Performance Risks inbox</DNT>, update the detection thresholds, and utilize the tool effectively within New Relic MCP server. For more information about what <DNT>Performance Risks inbox</DNT> is and its key benefits, refer to [introduction to <DNT>Performance Risks inbox</DNT>](/docs/errors-inbox/performance-risks/introduction).


## Access the Performance Risks inbox [#access]

You can access <DNT>Performance Risks inbox</DNT> in two ways: at the entity level, scoped to a single entity or workload, or at the account level, covering every entity in your account.

* [Access at entity level](#access-entity)
* [Access at account level](#access-account)

### Access at entity level [#access-entity]

At the entity level, <DNT>Performance Risks inbox</DNT> shows performance issues for a single entity's or workload's telemetry data. This is available for:

* APM services
* Browser applications
* Workloads

**To access <DNT>Performance Risks inbox</DNT> for an entity:**

1. Go to <DNT>[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities)</DNT>, then select <DNT>**APM & Services**</DNT>, <DNT>**Browser**</DNT>, or <DNT>**Workloads**</DNT>.
2. Select the required entity or workload.
3. In the navigation pane, under the <DNT>**Triage**</DNT> section, click <DNT>**Performance Risks**</DNT>.


### Access at account level [#access-account]

At the account level, <DNT>Performance Risks inbox</DNT> shows performance risk groups scoped to a workload or entity that you choose, so you can review problems without having to open each entity individually.

**To access <DNT>Performance Risks inbox</DNT> for an account:**

1. Go to <DNT>[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Errors Inbox</DNT>.
2. In the entity navigation pane, click <DNT>**Performance Risks**</DNT>.
3. Use the scope selector to choose <DNT>**Workload**</DNT> or <DNT>**Entities**</DNT>, then select the specific [workload](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview) or entity you want to review, or use the search box to find it by name or description.
4. Optionally, add more filters, such as by <DNT>**Performance risk group metadata state**</DNT> (for example, <DNT>Unresolved</DNT>), and use <DNT>**Sort by**</DNT> to change the order of results.

## View the Performance Risks overview [#overview]

<DNT>Performance Risks overview</DNT> is a dashboard that summarizes performance risks across your account. It shows every performance risk detected across your entities, so you don't have to check each entity individually to find where problems exist.

### Summary tiles [#summary-tiles]

Four tiles summarize the account's current state, each compared against the previous time window:

* **Entities with risks**: the number of entities that currently have at least one performance risk
* **% of entities affected**: the share of monitored entities with at least one risk, out of the total monitored
* **Total risks detected**: the number of risk occurrences detected during the selected time window
* **New this period**: the number of entities that newly crossed into "at risk" during the selected window

### Risk composition [#risk-composition]

The <DNT>**Risk composition**</DNT> chart breaks down occurrences by risk type, so you can see which kinds of performance risks are most common across the account.

### Risk trend [#risk-trend]

The <DNT>**Risk trend**</DNT> chart shows how risk occurrences change over time, stacked by risk type. You can toggle between viewing occurrences and entities affected.

### Top affected entities [#top-affected-entities]

The <DNT>**Top affected entities**</DNT> table lists the entities with the most performance risks, along with severity, the risk types detected, total risks, and a trend sparkline for the selected time window.

Click <DNT>**Investigate**</DNT> next to an entity to open the [Triage](#triage) view for that entity.

### Risk concentration [#risk-concentration]

The <DNT>**Risk concentration**</DNT> table shows how risks cluster across entities and risk types. Each cell shows the occurrence count for that entity and risk type, with color intensity indicating concentration.

## View and analyze performance risks [#view-analyze]

Once you access <DNT>Performance Risks inbox</DNT>, you can view detected issues in two ways: the <DNT>**Triage**</DNT> view and the <DNT>**Group performance risks**</DNT> view. Both views display the same underlying data but offer different ways to analyze it.

### Triage [#triage]

The <DNT>**Triage**</DNT> view processes and groups similar performance risks together automatically. Similar queries are computed, stored, and merged into a single performance risk group. For example, multiple queries that share the same pattern — such as variations of an `IN` clause — are grouped into one entry rather than appearing as separate items. This makes it easier to identify and prioritize the most impactful problems without reviewing each occurrence individually.

Use the <DNT>**Triage**</DNT> view when you want a pre-grouped summary of performance issues to quickly identify patterns across your application.

### Group performance risks [#group]

The <DNT>**Group performance risks**</DNT> view displays the raw performance risk data without pre-computed groupings. Normalized query representations (such as comma and question mark placeholders) are shown, and you can filter and group the data based on different attributes, such as:

* The user affected by the performance risk
* The service generating the calls
* The API triggering the queries

Use the <DNT>**Group performance risks**</DNT> view when you need to analyze performance risks based on specific attributes that are relevant to your investigation.

## Set the thresholds [#set-thresholds]

<DNT>Performance Risks inbox</DNT> uses configurable thresholds to automatically detect performance anomalies. You can update these thresholds at both the account and entity levels to ensure that the detection criteria align with your specific performance monitoring needs and priorities. These thresholds determine what constitutes a performance risk and help to ensure that you are alerted to the most relevant and actionable performance issues in your applications.

You can set the Performance Risks thresholds at an account or entity level:

* [Account-level thresholds](#account-thresholds)
* [Entity-level thresholds](#entity-thresholds)


### Set the account-level thresholds [#account-thresholds]

Setting thresholds at the account level allows you to establish default performance risk detection criteria that apply across all entities within the account. This is useful for maintaining consistent monitoring standards and ensuring that all applications are evaluated against the same performance benchmarks.

**To set the thresholds at an account level:**

<CollapserGroup>
    <Collapser
        id="new-account-thresholds"
        title="New account-level thresholds"
    >

1. Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Errors Inbox > Performance Thresholds**.</DNT>.
2. In the **Accounts** tab, click <DNT>**+ New**</DNT>.
3. From the <DNT>**Account**</DNT> dropdown, select the account you want to create a new threshold for.
4. Set the required limits for each analyzer.
5. Click <DNT>**Submit**</DNT> to save.

</Collapser>

### Set the entity-level thresholds [#entity-thresholds]

Setting thresholds at the entity level allows you to customize performance risk detection criteria for specific applications or services that may have unique performance characteristics or requirements. This is particularly useful for tailoring monitoring to different types of applications, environments, or business priorities.

**To set the thresholds at an entity level:**

You can set the thresholds for a specific entity in one of the following ways:

<CollapserGroup>
    <Collapser
        id="entity-triage"
        title="From the Performance Risks page"
    >

1. Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > APM & Services**.</DNT>.
2. Select the required entity.
3. In the entity navigation pane, click <DNT>**Performance Risks**</DNT> in the <DNT>**Triage**</DNT> section.
3. Click <DNT>**Adjust performance thresholds**</DNT> in the top right corner.
4. Set the required limits for each analyzer.
4. Click <DNT>**Submit**</DNT> to save.

<Callout variant="tip">
    When you modify thresholds, your username will be displayed to track who made the changes.
</Callout>

</Collapser>

<Collapser

2. In the <DNT>**Entities**</DNT> tab:
  1. From the <DNT>**Account**</DNT> dropdown, select the account of your entity.
  2. From the <DNT>**Entity**</DNT> dropdown, select the entity you want to update.
3. Set the required limits for each analyzer.

## View threshold guidelines on charts [#threshold-guidelines]

Performance risk charts display reference lines to help you interpret whether a value is within an expected range:

* **Minimum and maximum guidelines**: Calculated automatically from the historical data collected for that chart, showing the typical range of values over time.
* **Current threshold**: Reflects the threshold that's currently active for that analyzer, based on your [account-level or entity-level threshold settings](#set-thresholds). If both are set, the entity-level threshold takes precedence.

Use these lines to quickly see how close a metric is to its configured threshold, without needing to open the threshold settings.

## Generate an AI summary [#ai-summary]

For a performance risk group with multiple occurrences, you can generate an AI-powered summary instead of reviewing each occurrence individually.

**To generate an AI summary:**

1. Open a performance risk group that has multiple occurrences.
2. Click <DNT>**Generate insights**</DNT>.

<DNT>Performance Risks inbox</DNT> analyzes the occurrences for that group and returns a summary that includes a hypothesis about the root cause and suggested next steps.

New Relic enables AI features by default for all accounts. If you don't see this option, your account may not have it enabled. Contact your organization admin to request access.

## Use the Performance Risks inbox tool in New Relic MCP server [#using]

You can also access the <DNT>Performance Risks inbox</DNT> tool ([`list_entity_performance_risk_groups`](/docs/agentic-ai/mcp/tool-reference/#performance)) in [New Relic MCP server](/docs/agentic-ai/mcp/overview/). This tool lists all the Performance Risks detected for a given entity, along with their details such as risk type, severity, and occurrence count. You can use this tool to programmatically retrieve performance risk data.
