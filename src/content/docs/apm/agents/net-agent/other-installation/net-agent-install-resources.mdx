<Callout variant="important">
  This page covers manual and ZIP-based installation methods. For the recommended guided installation, see [Install the .NET agent](/install/dotnet).
</Callout>

## Manual install via ZIP file (Windows) [#install-zip-file]

Use this method when the guided installer is not an option. The .NET agent [download library](https://download.newrelic.com/dot_net_agent/latest_release/) contains all install packages.

<Steps>
  <Step>
    ## Download and unzip the agent [#download]

    Go to the [.NET agent download site](https://download.newrelic.com/dot_net_agent/latest_release/) and download the ZIP file that matches your application's architecture:

    * .NET Framework or .NET Core/.NET 5+ (64-bit): `NewRelicDotNetAgent_VERSION_x64.zip`
    * .NET Framework or .NET Core/.NET 5+ (32-bit): `NewRelicDotNetAgent_VERSION_x86.zip`

    Unzip the agent folder to your desired install location.
  </Step>

  <Step>
    ## Set environment variables [#env-vars]

    Set the required environment variables for the process you want to monitor.

    <Callout variant="caution">
      Do not set these environment variables globally — that will cause all .NET processes on the system to be instrumented. Set them only for the specific process you want to monitor.
    </Callout>

    <CollapserGroup>
      <Collapser
        id="net-framework-env-variables"
        title=".NET Framework environment variables"
      >
        ```ini
        COR_ENABLE_PROFILING=1
        COR_PROFILER={71DA0A04-7777-4EC6-9643-7D28B46A8A41}
        NEWRELIC_HOME=path\to\agent\directory\netframework
        COR_PROFILER_PATH=path\to\agent\directory\netframework\NewRelic.Profiler.dll
        ```
      </Collapser>

      <Collapser
        id="net-core-env-variables"
        title=".NET Core/.NET 5+ environment variables"
      >
        ```ini
        CORECLR_ENABLE_PROFILING=1
        CORECLR_PROFILER={36032161-FFC0-4B61-B559-F6C5D41BAE5A}
        CORECLR_NEWRELIC_HOME=path\to\agent\directory\netcore
        CORECLR_PROFILER_PATH=path\to\agent\directory\netcore\NewRelic.Profiler.dll
        ```
      </Collapser>
    </CollapserGroup>

    The two settings you **must** also configure are your license key and app name:

    ```ini
    NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY
    NEW_RELIC_APP_NAME=YOUR_APP_NAME
    ```

    You can also set these in the [newrelic.config file](/docs/agents/net-agent/configuration/net-agent-configuration#service) instead of environment variables.
  </Step>

  <Step>
    ## Restart your application [#restart]

    Restart your application. If using IIS, restart IIS:

    ```bash
    iisreset
    ```

    Send a few requests to your application, then wait 2–3 minutes and open [one.newrelic.com > APM](https://one.newrelic.com/apm) to look for your app by name.

    <Callout variant="tip">
      App not appearing? See [No data appears (.NET)](/docs/agents/net-agent/troubleshooting/no-data-appears-net).
    </Callout>
  </Step>
</Steps>

<Callout variant="caution">
  The .NET agent relies on the [Microsoft profiling API](https://docs.microsoft.com/en-us/dotnet/framework/unmanaged-api/profiling/profiling-overview). Only one service can use this profiler at a time. If another .NET monitoring tool is installed and not fully removed, the profiler may already be in use, causing [profiler conflicts](/docs/agents/net-agent/troubleshooting/profiler-conflicts).
</Callout>

## Custom instrumentation [#custom-instrumentation]

After installing the agent, most .NET application frameworks report data automatically. See [.NET agent compatibility and requirements](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) for the list of auto-instrumented frameworks.

If your application uses a framework that is not automatically instrumented (such as a console app), you will need to [custom instrument](/docs/agents/net-agent/custom-instrumentation/introduction-net-custom-instrumentation) your application.
