When you create a New Relic organization, it gets one [authentication domain](/docs/accounts/accounts-billing/new-relic-one-user-management/authentication-domains-saml-sso-scim-more) that uses username and password login, usually named <DNT>**Default**</DNT>. Adding a SAML SSO domain doesn't change that domain: its users can still sign in with a password.

To require every user to sign in through your identity provider, move your administrators to the SSO domain, then delete the users in the password domain and the domain itself. This doc explains how to do that safely.

<Callout variant="important">
  New Relic doesn't protect the <DNT>**Default**</DNT> domain or your last administrator. A user with the <DNT>**Authentication domain manager**</DNT> role can delete any manually provisioned user and any empty authentication domain in your organization, including the users who created it. Follow the steps in order so you don't lock yourself out.
</Callout>

## Requirements [#requirements]

* A user in a group with the <DNT>**Authentication domain manager**</DNT> role. The <DNT>**Organization manager**</DNT> role alone can't delete users or authentication domains.
* A [SAML SSO authentication domain](/docs/accounts/accounts-billing/new-relic-one-user-management/authentication-domains-saml-sso-scim-more/#saml) that's already working. Your users can be provisioned manually or with [SCIM](/docs/accounts/accounts/automated-user-management/automated-user-provisioning-single-sign/).

## Remove password login [#steps]

<Steps>
  <Step>
    ### Confirm that SSO works [#confirm-sso]

    Sign in through your identity provider as a user in the SAML domain. If you have users in more than one authentication domain, [choose the SAML domain](/docs/accounts/accounts-billing/account-setup/multiple-user-records/) when you sign in.
  </Step>

  <Step>
    ### Set up at least two SSO administrators [#sso-admins]

    In the SAML domain, add at least two users to a group that has:

    * The <DNT>**Authentication domain manager**</DNT> role, so they can manage users and domains.
    * A role on at least one account. Organization-scoped roles alone don't give access to any account, and those users will see <DNT>**You don't have access to an account in this organization**</DNT> after they sign in.

    Sign in as one of these users and do the remaining steps from that session.

    <Callout variant="caution">
      Nothing stops you from deleting your last administrator. Two SSO administrators keep you from depending on one person or one identity provider account.
    </Callout>
  </Step>

  <Step>
    ### Replace user keys owned by password users [#replace-keys]

    Deleting a user [disables all the user keys](/docs/apis/intro-apis/new-relic-api-keys) associated with that user. Before you continue, go to the [API keys UI](https://one.newrelic.com/admin-portal/api-keys/home) and find user keys owned by users in the password domain. Create replacement keys owned by SSO users or [system identities](/docs/accounts/accounts-billing/new-relic-one-user-management/system-identities) and update anything that uses the old keys.

    [License keys](/docs/apis/intro-apis/new-relic-api-keys/#license-key) and browser keys belong to accounts, not users, so you don't need to replace them.
  </Step>

  <Step>
    ### Delete the users in the password domain [#delete-users]

    Go to <DNT>**[one.newrelic.com > Administration](https://one.newrelic.com/admin-portal) > User management**</DNT>, select the users in the password domain, and click <DNT>**Delete users**</DNT>. You can't delete yourself, so sign in as an SSO user, not a password user. You can also [delete users with NerdGraph](/docs/apis/nerdgraph/examples/nerdgraph-manage-users/#delete-users).

    Delete the users; don't just deactivate them. A domain can only be deleted when it has no active users, and deactivated users aren't removed when you delete their domain.

    Deleting a user is permanent. See [what's deleted with a user](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-ui-and-tasks/#delete-users).
  </Step>

  <Step>
    ### Delete the password authentication domain [#delete-domain]

    Go to <DNT>**[one.newrelic.com > Administration](https://one.newrelic.com/admin-portal) > Authentication domains**</DNT>, open the menu for the password domain, and delete it.

    To use NerdGraph instead, pass the domain's ID:

    ```graphql
    mutation {
      authenticationDomainDelete(id: "YOUR_AUTHENTICATION_DOMAIN_ID") {
        id
      }
    }
    ```

    If the domain still has active users, the request fails with `Cannot delete an authentication domain with active users.`
  </Step>
</Steps>

## After you remove password login [#after]

* **Identity provider outages:** with no password domain, your users can only sign in through your identity provider. If an administrator can't sign in because of an SSO problem, use [recovery access](/docs/accounts/accounts-billing/account-setup/troubleshoot-new-relics-password-email-address-login-problems/) or contact [New Relic support](https://support.newrelic.com).
* **New users:** add them to the SAML domain, or provision them with SCIM. Don't create a new password domain unless you need one.
* **Who holds Authentication domain manager:** anyone with this role can delete users and authentication domains across your organization. Assign it only to administrators you trust, and review the group's members regularly.
* **Audit trail:** user and authentication domain deletions are recorded as `user.delete` and `authentication_domain.delete` events. To review them, [query `NrAuditEvent`](/docs/insights/insights-data-sources/default-data/nrauditevent-event-data-query-examples).
