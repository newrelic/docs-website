## Overview

Compute User Limits allow you to set monthly budgets for individual users in your organization and manage their access to New Relic resources based on compute consumption. When a user reaches their allocated budget, you can block their access to dashboards, query builder, and API calls until the end of the month or until you increase their budget.

User limits extend the existing compute budgets UI in New Relic.

It simplifies budget management at scale by introducing a global user budget that applies to all users, eliminating the need to set up thousands of individual budgets. For users with specific needs, you can create custom override budgets.

This feature helps you:

**Cost control:**
- Control compute costs at the user level
- Reduce budget overruns by individual users

**Visibility and management:**
- Track and monitor user-level compute consumption
- Maintain visibility into usage patterns across your organization
- Manage budgets efficiently across large organization

## Prerequisites

To use Compute User Limits, you must:

- Be a single-tenant customer (single organization) or a multi-tenant customer (multiple organizations)
- Have access to Compute Budgets
- Have either Core or Legacy Compute plan 

## Key capabilities

### Budget types

**Global user budget**: Set a default budget that applies to all users in your organization. You can configure this as:
- **Percentage of organization budget**: Allocate a percentage of your organization-level compute budget (based on your minimum commitments) to each user
- **Actual compute value**: Specify an exact number of CCUs (Compute Capacity Units) for each user

**Custom override budgets**: Assign specific budgets to individual users who need higher or lower limits than the global budget.

### Multi-select users

When creating custom override budgets, you can select multiple users at once and apply the same budget configuration to all of them in a single workflow. This is useful when onboarding a team or applying a standard limit to a group of users without repeating the setup for each individual.

<Callout variant="important">
Even when you create a budget for multiple users at once, the budget is individual. For example, if you set 40,000 CCUs and select five users, each user individually receives a 40,000 CCU budget — it is not shared or split among them.
</Callout>

After creation, each user's budget appears as a separate line item in the budget table. You can update budgets individually, or use the group view to update the budget for all users in the group at once.

### Multi-tenant support

If your organization spans multiple New Relic organizations, you can manage user limits across each of them separately. Log into any organization in your account and create user limits that apply to users in that organization.

### Supported compute types

In the initial phase, user limits support:
- Core compute
- Legacy compute

<Callout variant="important">
Advanced compute is not included in the first phase of this feature.
</Callout>

## How user limits work

User limits track compute consumption associated with each user's activity. When a user is assigned a budget, all of their compute activity counts toward that budget.

For example, if a user has a 1,000 CCU monthly budget, all compute consumption attributed to their user ID or API key counts toward that limit.

Once a user reaches their allocated budget, the configured blocking or monitoring rules take effect.

### Budget notifications

Users receive in-app banner notifications at the following thresholds:
- **50% of budget consumed**: Yellow informational banner
- **75% of budget consumed**: Yellow warning banner
- **95% of budget consumed**: Red critical banner
- **100% of budget consumed**: Informational banner indicating the user is over budget

These notifications appear as banners within the New Relic platform to keep users informed of their consumption status.

<Callout variant="tip">
Email notifications will be available as a fast follow-up to the limited preview.
</Callout>

### Budget enforcement

Administrators can choose what happens when a user reaches 100% of their allocated budget:

**Block the user**: The user will be blocked from:
- Accessing dashboards
- Using the query builder
- Making API calls associated with their user ID or API key

When blocked, users see error messages depending on which feature they're trying to access:
- **Query builder**: A message stating they've been blocked due to exceeding their budget, with options to view their budget

  <Callout variant="tip">
  You may also contact your admin for an increase in budget.
  </Callout>
  
- **Dashboards**: A similar message preventing access to dashboard views
- **API calls**: An error response stating: "Your account has exceeded the allowed consumption budget"

**Monitor only**: Continue to notify the user about their budget consumption without blocking access.

Blocks remain in effect until the end of the calendar month or until an administrator increases the user's budget.

<Callout variant="important">
Consumption data updates within a few hours (typically 2-4 hours). Due to this delay, blocking will not happen exactly at 100%—users may exceed their budget slightly before the block takes effect.
</Callout>

## User roles and permissions

### Organization managers
Organization managers have full control over user limits:
- Set up global user budgets
- Create custom override budgets for specific users
- Edit existing budgets
- Delete budgets
- View all users' budget consumption

### Read-only users
Read-only users have limited visibility:
- View only their own individual budget line item in the budget table
- See their own budget consumption and trends
- Access only the **View** option from the three-dot menu for their budget
- Receive notifications about their budget status at 50%, 75%, 95%, and 100% thresholds

Read-only users cannot:
- Modify any budget settings
- View other users' budgets or budget line items
- Access edit or delete options
- Set up new budgets

## Set up user limits

### Set up a global user budget

<Steps>

  <Step>
    ### Access Compute Budgets

    From the [user menu](/docs/accounts/accounts-billing/general-account-settings/intro-account-settings), select **Administration > Compute Budgets > User Limits**.
  </Step>

  <Step>
    ### Add a global budget

    Click <DoNotTranslate>**Add a global budget**</DoNotTranslate> to create a budget that applies to all users in the organization you are logged into.
  </Step>

  <Step>
    ### Configure your budget

    Choose how to allocate budgets:
    - **Percentage of organization budget**: Allocate a percentage of your organization-level compute budget (based on your minimum commitments) to each user. For example, if your organization has 800,000 core CCUs and you set 1% per user, each user receives 8,000 core CCUs.
    - **Actual value**: Specify an exact number of CCUs for each user.

    Enter the budget amount and click **Next**.
  </Step>

  <Step>
    ### Review notifications

    This informational page shows what notifications users will receive. Users will automatically receive in-app banner notifications at 50%, 75%, 95%, and 100% of their budget.

    No configuration is needed on this page. Click **Next** to continue.
  </Step>

  <Step>
    ### Configure blocking

    Choose whether to block users when they reach 100% of their budget:
    - **Enable blocking**: Users will be blocked from dashboards, query builder, and API calls when they reach their budget limit.
    - **Disable blocking**: Users will receive notifications but maintain full access to all features.

    Click **Finish** to create the global user budget.
  </Step>

</Steps>

### Set up custom override budgets

For users who need different budget limits than the global budget:

<Steps>

  <Step>
    ### Add a user budget

    From the User Limits page, click **Add a user budget**.
  </Step>

  <Step>
    ### Select users

    From the dropdown menu, select one or more users for whom you want to create a custom override budget. When you select multiple users, the same budget configuration is applied to all of them.
  </Step>

  <Step>
    ### Configure the custom budget

    Set a specific percentage or actual value. This amount is applied individually to each selected user — it is not shared among them.

    Click **Next**.
  </Step>

  <Step>
    ### Review notifications

    Review the notification thresholds that will apply to this user. Click **Next** to continue.
  </Step>

  <Step>
    ### Configure blocking

    Choose the blocking preference for this specific user, which can differ from the global budget settings.

    Click **Finish** to create the custom override budget.
  </Step>

</Steps>

Multiple custom override budgets can be created and will appear in the budget table. The global budget is displayed as a card at the top of the page.

## Managing user limits

### Viewing budget consumption

The global budget appears as a card at the top of the main user limits page. Custom override budgets appear in a budget table below.

**For organization managers:**
- View the global budget card and all custom override budgets in the table with full details
- Access a three-dot menu (**⋯**) next to each budget with options to:
  - **View**: See detailed budget information, consumption, and trends
  - **Edit**: Modify budget settings
  - **Delete**: Remove the budget

**For read-only users:**
- If you have a custom override budget: See only your own budget line item in the table
- If you only have the global budget: See the global budget card at the top
- Access only the **View** option from the three-dot menu
- Cannot see other users' budgets or access **Edit** or **Delete** options

### Budget details view

When viewing a budget (available to all users for their own budget), you can see:
- Current budget consumption
- Percentage of budget used
- Consumption trends for the month
- Whether the user will be blocked at 100%
- Notification status

### Adjusting budgets

Organization managers can modify budgets at any time:
- **Edit existing budgets**: Update budget amounts or blocking preferences for a single user, or use the group view to update the budget for all users in a group at once
- **Increase a user's budget**: Restore access to blocked users or provide additional capacity
- **Decrease budgets**: Adjust takes effect immediately for the current and future billing periods
- **Delete budgets**: Both global and custom override budgets can be deleted. When a custom override budget is deleted, the user will automatically fall back to the global user budget (if configured).

Changes to budgets take effect immediately.

<Callout variant="important">
Deleting a custom budget doesn't remove budget tracking. The user continues to be tracked under the global budget (if configured).
</Callout>

### Handling blocked users

If a user is blocked due to budget consumption:
1. The user will see a blocking message when trying to access dashboards or query builder
2. The user can view their budget details to see consumption information
3. The user should contact their administrator to request a budget increase
4. An administrator can increase the budget to immediately restore access, or
5. The user's access will automatically restore at the end of the month when budgets reset

## Common scenarios

**What happens if no budgets are configured?**
Users can access all features without restrictions. Budget tracking only applies when you configure a global budget or custom override budgets.

**What happens if a user has no budget assigned?**
If you've configured a global budget, all users automatically receive that budget. If you've only created custom override budgets without a global budget, users without custom budgets have unrestricted access.

**When do budgets reset?**
Budgets reset at the start of each calendar month based on UTC timezone.

**What happens to in-progress queries when a user reaches 100% of their budget?**
Queries already running will complete. The block only prevents new queries, dashboard loads, and API calls from starting.

**Are consumption metrics real-time?**
No. Consumption data updates within a few hours (typically 2-4 hours). This delay means that blocking will not happen exactly at 100% of the budget—users may exceed their budget slightly before the block takes effect. Budget notifications and consumption tracking are also subject to this delay.

## What's next?

After setting up user limits, you can:
- Monitor user consumption in the budget table
- Adjust budgets as needed to accommodate changing usage patterns
- Review blocking notifications and user feedback
- Refine your budget strategy based on actual consumption data
