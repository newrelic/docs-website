With Compute User Limits, you can set daily or monthly budgets for individual users in your organization and manage their access to New Relic resources based on compute consumption. Each budget tracks core compute (core CCUs) and advanced compute (advanced CCUs) as separate meters. When a user reaches their allocated budget for a meter, you can block their access to the associated resources until the end of the budget period or until you increase their budget.

It also simplifies budget management at scale with a global user budget that applies to all users, so you don't need to configure a budget for every user individually. For users with specific needs, you can create custom override budgets.

Use Compute User Limits to do the following:
  - Control compute costs by limiting per-user consumption
  - Monitor user-level compute consumption
  - Maintain visibility into user compute usage patterns across your organization
  - Manage user compute budgets across a large organization

## Key capabilities

Two budget types are available:

- **Global user budget**: Set a default budget that applies to all users in your organization.
- **Custom override budgets**: Assign specific budgets to individual users who need higher or lower limits than the global budget.

For both budget types, configure the following per meter:
  - **Core CCU limit**: Set as a percentage of your organization-level compute budget, with the equivalent CCU value calculated automatically. Choose **Block CCU usage** or **Do not block CCU usage** as the limit type for this meter.
  - **Advanced CCU limit**: Set as a percentage of your organization-level compute budget, with the equivalent CCU value calculated automatically. Choose **Block CCU usage** or **Do not block CCU usage** as the limit type for this meter.

Budget tracking only applies when you configure a global budget or custom override budgets.

If you've configured a global budget, all users automatically receive that budget. If you've only created custom override budgets without a global budget, users without custom budgets have unrestricted access.

If you need to manage usage by New Relic Autopilot, please use our [Autopilot compute limits](/docs/agentic-ai/autopilot/autopilot-compute-limits/) feature instead.

## How user limits work

User limits track each user's compute consumption across two independent meters: core compute (core CCUs) and advanced compute (advanced CCUs). When you assign a budget to a user, their compute activity counts toward the appropriate meter. Each meter has its own budget value and limit type.

For example, if a user has a 10,000 core CCU budget and a 5,000 advanced CCU budget, standard compute activity such as running queries and refreshing dashboards counts toward the core CCU limit, and advanced compute activity such as Ask AI, Live Archives, and MCP counts toward the advanced CCU limit.

When a user reaches their allocated budget for a meter, the configured limit type for that meter takes effect.

### Core and advanced compute meters

Core compute (core CCUs) covers dashboards, query builder, and API calls. Advanced compute (advanced CCUs) covers features like Live Archives and AI-powered features.

When a user's core CCU budget is exhausted and the limit type is set to **Block CCU usage**, they lose access to the following:
- [Dashboards](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards)
- [Query builder](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder)
- API calls

When a user's advanced CCU budget is exhausted and the limit type is set to **Block CCU usage**, they lose access to the following:
- [Ask AI](/docs/agentic-ai/new-relic-ai) (V1 and V2)
- [Live Archives](/docs/logs/get-started/live-archives) (the Query Live Archives button and the Use live archives toggle in query builder)
- [MCP](/docs/agentic-ai/mcp/overview)
- [Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui) (Explain Error and Generate Insights)

The following advanced CCU-consuming products are not supported by this Compute User Limits feature and remain accessible even when a user's advanced CCU budget reaches 100%:
- Pipeline Control
- Unlimited Cardinality
- Transaction 360
- Security RX
- New Relic AI Knowledge
- Autopilot

<Callout variant="tip">
  The list of advanced CCU products subject to enforcement may grow as more products reach general availability. Check back here for updates on supported advanced CCU products.
</Callout>

### Budget frequency

When you create a budget, you choose whether it resets daily or monthly. The right choice depends on your users' work patterns and how tightly you need to control costs.

The following table compares monthly and daily budgets:

| Behavior | Monthly | Daily |
|---|---|---|
| **Resets** | Start of each calendar month (UTC) | Start of each calendar day (UTC) |
| **Block lifts** | Start of next calendar month (UTC) | Start of next calendar day (UTC) |

Choose a monthly budget if any of the following apply:
- Your users have variable day-to-day usage that averages out over a billing period — for example, developers who run intensive queries at the end of a sprint but have light usage otherwise
- You want the budget period to align with your billing cycle
- You want only one reset per month

Choose a daily budget if any of the following apply:
- You want to limit how much a runaway query or script can consume in a single day
- Your users have consistent day-to-day usage and you want a fixed daily limit
- You want a shorter recovery window: A user blocked under a daily budget regains access the next day, rather than waiting until the end of the month

<Callout variant="tip">
  Daily caps can block users on high-usage days even when their total usage would have stayed within a monthly budget. Review your users' typical usage patterns before applying daily limits broadly.
</Callout>

### Budget notifications

Notifications fire independently for each compute meter. In-app notifications fire at all four thresholds; email notifications fire at 75% and 100% only.

| Threshold | Urgency | In-app notification | Email |
|---|---|---|---|
| **50%** | Info | ✓ | — |
| **75%** | Warning | ✓ | ✓ |
| **95%** | Critical | ✓ | — |
| **100%** | Critical | ✓ | ✓ |

For example, a user with a 100,000 core CCU budget and a 200,000 advanced CCU budget receives core CCU notifications at 50,000; 75,000; 95,000; and 100,000 core CCUs, and separate advanced CCU notifications at 100,000; 150,000; 190,000; and 200,000 advanced CCUs. Email notifications are sent at the 75% and 100% thresholds for each meter.

### Budget enforcement

As an organization manager, you configure limit types independently for each compute meter. This means you can, for example, apply **Block CCU usage** to a user's core compute while setting **Do not block CCU usage** for their advanced compute, or apply the same limit type to both.

**For core compute, choose one of the following:**
- **Block CCU usage**: When a user exhausts their budget, notify them and block access to Query Builder, Dashboards and API calls: running queries, refreshing dashboards, and making API calls.
- **Do not block CCU usage**: When a user exhausts their budget, notify them but don't block access to any CCU-consuming products. This option maintains full platform access but doesn't prevent overages.

**For advanced compute, choose one of the following:**
- **Block CCU usage**: When a user exhausts their budget, notify them and block access such as: [Ask AI](/docs/agentic-ai/new-relic-ai), [Live Archives](/docs/logs/get-started/live-archives), [MCP](/docs/agentic-ai/mcp/overview), and [Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui).
- **Do not block CCU usage**: When a user exhausts their budget, notify them but don't block access to CCU-consuming actions. This option maintains full platform access but doesn't prevent overages.

When blocked, users see a screen that says they've used their budget for the period and that they can contact an organization manager with any questions.

<Callout variant="tip">
  If you're rolling out budget limits for the first time, start with **Do not block CCU usage** for both meters. This lets you observe actual usage patterns before enabling blocking, reducing the chance of unexpected access disruptions.
</Callout>

<Callout variant="important">
  For monthly budgets, blocks remain in effect until the end of the calendar month (UTC). For daily budgets, blocks remain in effect until the end of the calendar day (UTC). In both cases, you can restore access sooner by increasing the user's budget. Consumption data updates within a few hours (typically 2 to 4 hours), so blocking doesn't happen exactly at 100%. Users might exceed their budget before the block takes effect.
</Callout>

## Before you begin

When you create any budget, you configure four settings. Reviewing these before you start helps you make the right choices in the setup wizard.

| Setting | Options | What to consider |
|---|---|---|
| **Budget type** | Global or custom override | Start with a global budget as your baseline. Add custom overrides for users who need different limits. |
| **Frequency** | Monthly or daily | See [Budget frequency](#budget-frequency) for guidance on choosing between them. |
| **Core CCU allocation** | Percentage of organization budget; Block CCU usage or Do not block CCU usage | Enter a percentage; the wizard calculates the equivalent CCU value. For this meter, also choose a limit type: start with **Do not block CCU usage** to observe actual usage patterns before enabling blocking. |
| **Advanced CCU allocation** | Percentage of organization budget; Block CCU usage or Do not block CCU usage | Enter a percentage; the wizard calculates the equivalent CCU value. For this meter, also choose a limit type: start with **Do not block CCU usage** to observe actual usage patterns before enabling blocking. |

## Set up a global user budget

If your organization spans multiple New Relic organizations, sign in to each one separately to create and manage user limits for its users.

<Steps>

  <Step>
    ### Access Compute Budgets

    1. Go to <DNT>**[one.newrelic.com](https://one.newrelic.com) > [user menu](/docs/accounts/accounts-billing/general-account-settings/intro-account-settings)**</DNT>.
    2. Select <DNT>**Administration > Compute Budgets**</DNT>.
  </Step>

  <Step>
    ### Open the global budget wizard

    In the <DNT>**Global user budget**</DNT> card, click <DNT>**Manage budget**</DNT>. The <DNT>**Manage global budget**</DNT> wizard opens.
  </Step>

  <Step>
    ### Set the budget frequency

    Under <DNT>**Set the frequency**</DNT>, select how often the budget resets:
    - <DNT>**Monthly**</DNT>: Tracks usage across the calendar month and resets at the start of each month (UTC).
    - <DNT>**Daily**</DNT>: Tracks usage across each calendar day and resets at the start of each day (UTC).

    Click <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Define core CCU budget

    1. Under <DNT>**Budget allocation**</DNT>, enter the percentage of your organization's core CCU budget to allocate to each user. The wizard shows the equivalent advanced CCU value as you type. For example, if your organization has 800,000 core CCUs and you set 5%, each user receives 40,000 core CCUs. User budgets can exceed your total organization budget.

    2. Under <DNT>**Limit type**</DNT>, choose what happens when a user reaches 100% of their core CCU budget:
       - <DNT>**Block CCU usage**</DNT>: Notify the user and block access to CCU-consuming actions: running queries, refreshing dashboards, and making API calls.
       - <DNT>**Do not block CCU usage**</DNT>: Notify the user but maintain full platform access. This doesn't prevent overages.

    Click <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Define advanced CCU budget

    1. Under <DNT>**Budget allocation**</DNT>, enter the percentage of your organization's advanced CCU budget to allocate to each user. The wizard shows the equivalent CCU value as you type. User budgets can exceed your total organization budget.

    2. Under <DNT>**Limit type**</DNT>, choose what happens when a user reaches 100% of their advanced CCU budget:
       - <DNT>**Block CCU usage**</DNT>: Notify the user and block access to [Ask AI](/docs/agentic-ai/new-relic-ai), [Live Archives](/docs/logs/get-started/live-archives), [MCP](/docs/agentic-ai/mcp/overview), and [Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui).
       - <DNT>**Do not block CCU usage**</DNT>: Notify the user but maintain full platform access. This doesn't prevent overages.

    Click <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Review notifications

    This page confirms the notification thresholds users receive for each compute meter. No configuration is needed. Click <DNT>**Finish**</DNT> to create the global user budget.
  </Step>

</Steps>

## Set up custom override budgets

Create custom override budgets for users who need different limits than the global budget. Use this approach when onboarding a team or applying a uniform limit to a group without configuring each user individually.

<Steps>

  <Step>
    ### Create a user budget

    From the <DNT>**User Limits**</DNT> page, click <DNT>**Create a user budget**</DNT>. The <DNT>**Create custom user budget**</DNT> wizard opens.
  </Step>

  <Step>
    ### Set the frequency and select users

    1. Under <DNT>**Set the frequency**</DNT>, select how often the budget resets:
       - <DNT>**Monthly**</DNT>: Tracks usage across the calendar month and resets at the start of each month (UTC).
       - <DNT>**Daily**</DNT>: Tracks usage across each calendar day and resets at the start of each day (UTC).

    2. Under <DNT>**Select users**</DNT>, choose one or more users from the dropdown to assign this custom override budget. When you select multiple users, the same budget applies to each user individually — they don't share a single budget.

    Click <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Define core CCU budget

    1. Under <DNT>**Budget allocation**</DNT>, enter the percentage of your organization's core CCU budget to allocate to this user. The wizard shows the equivalent CCU value as you type. User budgets can exceed your total organization budget.

    2. Under <DNT>**Limit type**</DNT>, choose what happens when the user reaches 100% of their core CCU budget. This can differ from the global budget settings.
       - <DNT>**Block CCU usage**</DNT>: Notify the user and block access to CCU-consuming actions: running queries, refreshing dashboards, and making API calls.
       - <DNT>**Do not block CCU usage**</DNT>: Notify the user but maintain full platform access. This doesn't prevent overages.

    Click <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Define advanced CCU budget

    1. Under <DNT>**Budget allocation**</DNT>, enter the percentage of your organization's advanced CCU budget to allocate to this user. The wizard shows the equivalent CCU value as you type. User budgets can exceed your total organization budget.

    2. Under <DNT>**Limit type**</DNT>, choose what happens when the user reaches 100% of their advanced CCU budget. This can differ from the global budget settings.
       - <DNT>**Block CCU usage**</DNT>: Notify the user and block access to [Ask AI](/docs/agentic-ai/new-relic-ai), [Live Archives](/docs/logs/get-started/live-archives), [MCP](/docs/agentic-ai/mcp/overview), and [Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui).
       - <DNT>**Do not block CCU usage**</DNT>: Notify the user but maintain full platform access. This doesn't prevent overages.

    Click <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Review notifications

    Review the notification thresholds that apply to this user for each compute meter. Click <DNT>**Finish**</DNT> to create the custom override budget.
  </Step>

</Steps>

After you create them, custom override budgets appear in the user budgets table as separate line items. You can update them individually or use the <DNT>**Group by**</DNT> dropdown to view and manage users who share the same allocation, limit type, and frequency.

## Manage user limits

### View budget consumption

Organization managers see the <DNT>**Global user budget**</DNT> card at the top of the <DNT>**Compute Budgets**</DNT> page. The card shows the configured core CCU and advanced CCU amounts, the percentage allocated per user, and the limit type for each meter.

Below the card, the <DNT>**User budgets**</DNT> table shows custom override budgets with the following columns:

| Column | Description |
|---|---|
| **User** | The user's email address |
| **Frequency** | Whether the budget resets daily or monthly |
| **Core usage** | Current core CCU consumption as a percentage of the allocation, or **Blocked** if the user is over budget with Block CCU usage enabled |
| **Core allocation** | The core CCU budget amount and the configured limit type (Block or Do not block) |
| **Advanced usage** | Current advanced CCU consumption as a percentage of the allocation, or **Close to limit** when approaching the threshold |
| **Advanced allocation** | The advanced CCU budget amount and the configured limit type (Block or Do not block) |

Use <DNT>**Group by > Allocation, limit, and frequency**</DNT> to cluster users who share the same budget configuration. Each group header summarizes the configuration, for example: `Core CCU 45,000 CCU · Block | Advanced CCU 100,000 CCU · Do not block | Monthly`.

**Organization managers** can do the following:
  - View all custom override budgets in the table with full details
  - Access a three-dot menu (**⋯**) next to each budget. The menu includes the following options:
    - <DNT>**View**</DNT>: See detailed budget information, consumption, and trends
    - <DNT>**Edit**</DNT>: Modify budget settings
    - <DNT>**Delete**</DNT>: Remove the budget

**Read-only users** can do the following:
  - See their own budget as a line item in the table, whether it's a custom override or global budget
  - Access only the <DNT>**View**</DNT> option from the three-dot menu

Read-only users can't see other users' budgets or use <DNT>**Edit**</DNT> or <DNT>**Delete**</DNT>.

### Budget details view [#budget-details]

When you view a budget (available to all users for their own budget), you can see:
  - Current core CCU and advanced CCU consumption
  - Percentage of each budget used
  - Consumption trends for the period
  - Blocking status at 100% for each meter
  - Notification status

### Adjust budgets [#adjust-budgets]

As an organization manager, you can modify budgets at any time:
  - <DNT>**Edit existing budgets**</DNT>: Update budget amounts, frequency, or limit types for a single user, or use the group view to update the budget for all users in a group at once
  - <DNT>**Increase a user's budget**</DNT>: Restore access to blocked users or provide additional capacity
  - <DNT>**Decrease budgets**</DNT>: Adjust budget amounts for the current and future budget periods
  - <DNT>**Delete budgets**</DNT>: Delete both global and custom override budgets. When you delete a custom override budget, the user automatically falls back to the global user budget (if you've configured one).

Changes to budgets take effect within approximately 15 minutes.

<Callout variant="important">
  Deleting a custom budget doesn't remove budget tracking. Budget tracking continues under the global budget (if you've configured one).
</Callout>

### Handle blocked users

When a user is blocked due to budget consumption, they can do the following:
  - See a message that says they've used their budget for the period
  - View their budget details to check consumption
  - Contact you to request a budget increase

To restore a blocked user's access, choose one of the following options:
  - Increase their budget. See [Adjust budgets](#adjust-budgets).
  - Wait until the budget resets at the start of the next budget period. See [Budget frequency](#budget-frequency).

<Callout variant="tip">
  Publish an internal list of organization managers so users know who to contact for limit increases, and ensure at least one is available to approve increases quickly during a service incident.
</Callout>

## Common scenarios

**When do budgets reset?**
It depends on the frequency you selected when setting up the budget:
- **Monthly**: Budgets reset at the start of each calendar month (UTC).
- **Daily**: Budgets reset at the start of each calendar day (UTC).

**What happens to in-progress queries when a user reaches 100% of their core CCU budget?**
Running queries complete. The block only prevents new queries, dashboard loads, and API calls from starting after blocking enforcement. See note above about consumption data reporting delays.

**What happens when a user reaches 100% of their advanced CCU budget?**
If the advanced CCU limit type is set to **Block CCU usage**, users lose access to [Ask AI](/docs/agentic-ai/new-relic-ai), [Live Archives](/docs/logs/get-started/live-archives), [MCP](/docs/agentic-ai/mcp/overview), and [Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui). If the limit type is **Do not block CCU usage**, users continue to have full access but receive notifications.

**What happens to a user when I delete their custom override budget?**
The user automatically falls back to the global user budget if you've configured one. If no global budget exists, the user has unrestricted access.

**What happens to users who don't have a budget assigned?**
Users without a budget assigned have unrestricted access to dashboards, query builder, API calls, and AI features.

**How quickly do budget changes take effect?**
Budget changes take effect within approximately 15 minutes.
