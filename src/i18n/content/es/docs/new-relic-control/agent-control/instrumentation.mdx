## Instrumente un sistema limpio

<Callout variant="tip">
  Agent Control es un servicio supervisor, no recopila ni envía telemetría por sí mismo. Para ver datos en New Relic, debe desplegar agentes (como el agente de infraestructura o NRDOT) a través de control de flota después de instalar Agent Control.
</Callout>

### Kubernetes

1. **Cree una flota** de tipo **clúster de Kubernetes** en el control de flota. Consulte [Crear su primera flota](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet) para obtener pasos detallados.

2. **Instale Agent Control.** Siga la [guía de instalación de Kubernetes](/docs/new-relic-control/agent-control/setup/) y seleccione la flota que creó en el Paso 1.

3. **Cree la configuración en el control de flota para cada uno de los agentes.** Después de que Agent Control se conecte al control de flota, [cree la configuración](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration) para cada uno de sus agentes. El control de flota es la fuente autorizada para toda la configuración del agente; no agregue valores específicos del agente al `values.yaml` local.

Ejemplo de cómo agregar el agente de infraestructura, Fluent Bit, Prometheus y NRDOT con ajustes personalizados, cada configuración debe crearse como una configuración remota independiente en el control de flota:

<CollapserGroup>
  <Collapser id="k8s-clean-infra" title="Agente de infraestructura">
    Habilita el agente de infraestructura de New Relic con tolerancias personalizadas y un intervalo de recopilación de 30 segundos.

    ```yaml
    chart_values:
      newrelic-infrastructure:
        kubelet:
          tolerations:
            - operator: "Exists"
              effect: "NoSchedule"
            - operator: "Exists"
              effect: "NoExecute"
        common:
          config:
            interval: 30s
    ```
  </Collapser>

  <Collapser id="k8s-clean-logs" title="Fluent Bit (reenvío de logs)">
    Despliega el reenviador de logs de Fluent Bit con recursos de CPU limitados.

    ```yaml
    chart_values:
      newrelic-logging:
        resources:
          limits:
            cpu: 200m
          requests:
            cpu: 200m
    ```
  </Collapser>

  <Collapser id="k8s-clean-prometheus" title="Prometeo">
    Despliega el agente de Prometheus en modo de datos bajos para reducir el volumen de telemetría.

    ```yaml
    chart_values:
      newrelic-prometheus-agent:
        lowDataMode: true
        config:
          kubernetes:
            integrations_filter:
              enabled: false
    ```
  </Collapser>

  <Collapser id="k8s-clean-nrdot" title="NRDOT (recolector de OpenTelemetry)">
    Despliega la distribución de New Relic del recolector de OpenTelemetry. El receptor `filelog` está desactivado aquí —habilítelo si desea la recolección de logs.

    ```yaml
    chart_values:
      nr-k8s-otel-collector:
        receivers:
          filelog:
            enabled: false
    ```
  </Collapser>
</CollapserGroup>

4. **Cree un nuevo despliegue** agregando las configuraciones remotas recién creadas a su flota. Agent Control aplicará automáticamente la nueva configuración a su clúster. Siga estos pasos en [crear y ejecutar su primer despliegue](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment).

5. **Verifique que los datos estén fluyendo.** Vaya a **Infrastructure &gt; Kubernetes** en la UI de New Relic. El clúster debería aparecer en 1-2 minutos después de aplicar la configuración remota. Si no aparece, consulte la [resolución de problemas de Agent Control](/docs/new-relic-control/agent-control/troubleshooting).

### Linux

1. **Cree una flota** de tipo **Linux Host** en el control de flota. Consulte [Crear su primera flota](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet) para obtener pasos detallados.

2. **Instale Agent Control.** Siga la [guía de instalación de Linux](/docs/new-relic-control/agent-control/setup/) y seleccione la flota que creó en el Paso 1.

3. **Cree la configuración en el control de flota para cada uno de los agentes.** Después de que Agent Control se conecte al control de flota, [cree la configuración](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration) para cada uno de los agentes.

Ejemplo que agrega el agente de infraestructura, nri-MySQL, nri-flex, fluentbit y nrdot, cada una de estas configuraciones debe crearse como una configuración remota independiente en el control de flota:

<CollapserGroup>
  <Collapser id="linux-clean-infra" title="Agente de infraestructura (línea de base)">
    `config_agent` contiene la configuración mínima requerida. `license_key` se resuelve en tiempo de ejecución a partir de la variable de entorno `NEW_RELIC_LICENSE_KEY` mediante el proveedor de valores `nr-env`; `custom_attributes` es opcional, pero se recomienda para el filtrado. `config_logging` envía el syslog del sistema a New Relic Logs.

    ```yaml
    config_agent:
      license_key: '${nr-env:NEW_RELIC_LICENSE_KEY}'
      custom_attributes:
        env: production
    config_logging:
      logging.yml:
        logs:
          - name: syslog
            file: /var/log/syslog
            attributes:
              logtype: linux_syslog
    ```
  </Collapser>

  <Collapser id="linux-clean-mysql" title="nri-mysql (integración en el host)">
    Monitorea una instancia de MySQL que se ejecuta en localhost. La contraseña se resuelve en tiempo de ejecución a partir de la variable de entorno `MYSQL_PASSWORD` utilizando el proveedor de valores `nr-env` —nunca codifique las credenciales de forma rígida.

    ```yaml
    config:
      integrations:
        - name: nri-mysql
          env:
            HOSTNAME: localhost
            PORT: 3306
            USERNAME: newrelic
            PASSWORD: ${nr-env:MYSQL_PASSWORD}
            REMOTE_MONITORING: true
          interval: 30s
    ```
  </Collapser>

  <Collapser id="linux-clean-flex" title="nri-flex con comando de shell (integración en el host)">
    Recopila estadísticas de uso de disco del sistema de archivos raíz mediante `df`. Este ejemplo demuestra cómo ejecutar cualquier comando de shell y analizar su salida como eventos de New Relic.

    ```yaml
    config:
      integrations:
        - name: nri-flex
          config:
            name: diskUsage
            apis:
              - event_type: DiskUsageSample
                commands:
                  - run: df -kP /
                    split: horizontal
                    split_by: \s+
                    set_header: [filesystem, blocks, used, available, usePercent, mountpoint]
                    row_start: 1
    ```
  </Collapser>

  <Collapser id="linux-clean-nrdot" title="NRDOT (recolector de OpenTelemetry)">
    Recopila métricas del host y logs del sistema, y abre un receptor OTLP para los servicios de APM. La clave de licencia y el extremo OTLP son inyectados automáticamente por Agent Control.

    ```yaml
    config:
      # Variables set automatically by Agent Control:
      # - NEW_RELIC_LICENSE_KEY: New Relic ingest license key.
      # - OTEL_EXPORTER_OTLP_ENDPOINT: OTLP endpoint (see: https://docs.newrelic.com/docs/opentelemetry/best-practices/opentelemetry-otlp/).

      extensions:
        health_check:

      receivers:
        otlp:
          protocols:
            grpc:
            http:

        hostmetrics:
          collection_interval: 60s
          scrapers:
            cpu:
              metrics:
                system.cpu.time:
                  enabled: false
                system.cpu.utilization:
                  enabled: true
            load:
            memory:
              metrics:
                system.memory.utilization:
                  enabled: true
            paging:
              metrics:
                system.paging.utilization:
                  enabled: false
                system.paging.faults:
                  enabled: false
            filesystem:
              metrics:
                system.filesystem.utilization:
                  enabled: true
            disk:
              metrics:
                system.disk.merged:
                  enabled: false
                system.disk.pending_operations:
                  enabled: false
                system.disk.weighted_io_time:
                  enabled: false
            network:
              metrics:
                system.network.connections:
                  enabled: false
            # Uncomment to enable process metrics, which can be noisy but valuable.
            # processes:
            # process:
            #  metrics:
            #    process.cpu.utilization:
            #      enabled: true
            #    process.cpu.time:
            #      enabled: false

        filelog:
          include:
            - /var/log/alternatives.log
            - /var/log/cloud-init.log
            - /var/log/auth.log
            - /var/log/dpkg.log
            - /var/log/syslog
            - /var/log/messages
            - /var/log/secure
            - /var/log/yum.log

      processors:
        metricstransform:
          transforms:
            - include: system.cpu.utilization
              action: update
              operations:
                - action: aggregate_labels
                  label_set: [state]
                  aggregation_type: mean
            - include: system.paging.operations
              action: update
              operations:
                - action: aggregate_labels
                  label_set: [direction]
                  aggregation_type: sum
        filter/exclude_cpu_utilization:
          metrics:
            datapoint:
              - 'metric.name == "system.cpu.utilization" and attributes["state"] == "interrupt"'
              - 'metric.name == "system.cpu.utilization" and attributes["state"] == "nice"'
              - 'metric.name == "system.cpu.utilization" and attributes["state"] == "softirq"'
        filter/exclude_memory_utilization:
          metrics:
            datapoint:
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "slab_unreclaimable"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "inactive"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "cached"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "buffered"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "slab_reclaimable"'
        filter/exclude_memory_usage:
          metrics:
            datapoint:
              - 'metric.name == "system.memory.usage" and attributes["state"] == "slab_unreclaimable"'
              - 'metric.name == "system.memory.usage" and attributes["state"] == "inactive"'
        filter/exclude_filesystem_utilization:
          metrics:
            datapoint:
              - 'metric.name == "system.filesystem.utilization" and attributes["type"] == "squashfs"'
        filter/exclude_filesystem_usage:
          metrics:
            datapoint:
              - 'metric.name == "system.filesystem.usage" and attributes["type"] == "squashfs"'
              - 'metric.name == "system.filesystem.usage" and attributes["state"] == "reserved"'
        filter/exclude_filesystem_inodes_usage:
          metrics:
            datapoint:
              - 'metric.name == "system.filesystem.inodes.usage" and attributes["type"] == "squashfs"'
              - 'metric.name == "system.filesystem.inodes.usage" and attributes["state"] == "reserved"'
        filter/exclude_system_disk:
          metrics:
            datapoint:
              - 'metric.name == "system.disk.operations" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.merged" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.io" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.io_time" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.operation_time" and IsMatch(attributes["device"], "^loop.*") == true'
        filter/exclude_system_paging:
          metrics:
            datapoint:
              - 'metric.name == "system.paging.usage" and attributes["state"] == "cached"'
              - 'metric.name == "system.paging.operations" and attributes["type"] == "cached"'
        filter/exclude_network:
          metrics:
            datapoint:
              - 'IsMatch(metric.name, "^system.network.*") == true and attributes["device"] == "lo"'
        attributes/exclude_system_paging:
          include:
            match_type: strict
            metric_names:
              - system.paging.operations
          actions:
            - key: type
              action: delete
        cumulativetodelta:
        transform/host:
          metric_statements:
            - context: metric
              statements:
                - set(description, "")
                - set(unit, "")
        transform:
          trace_statements:
            - context: span
              statements:
                - truncate_all(attributes, 4095)
                - truncate_all(resource.attributes, 4095)
          log_statements:
            - context: log
              statements:
                - truncate_all(attributes, 4095)
                - truncate_all(resource.attributes, 4095)
        memory_limiter:
          check_interval: 1s
          limit_mib: 100
        batch:
        resourcedetection:
          detectors: ["system"]
          system:
            hostname_sources: ["os"]
            resource_attributes:
              host.id:
                enabled: true
        resourcedetection/cloud:
          detectors: ["gcp", "ec2", "azure"]
          timeout: 2s
          ec2:
            resource_attributes:
              host.name:
                enabled: false
        resourcedetection/env:
          detectors: ["env"]
          timeout: 2s
          override: true

      exporters:
        otlphttp:
          endpoint: ${nr-env:OTEL_EXPORTER_OTLP_ENDPOINT}
          headers:
            api-key: ${nr-env:NEW_RELIC_LICENSE_KEY}

      service:
        pipelines:
          metrics/host:
            receivers: [hostmetrics]
            processors:
              - memory_limiter
              - metricstransform
              - filter/exclude_cpu_utilization
              - filter/exclude_memory_utilization
              - filter/exclude_memory_usage
              - filter/exclude_filesystem_utilization
              - filter/exclude_filesystem_usage
              - filter/exclude_filesystem_inodes_usage
              - filter/exclude_system_disk
              - filter/exclude_network
              - attributes/exclude_system_paging
              - transform/host
              - resourcedetection
              - resourcedetection/cloud
              - resourcedetection/env
              - cumulativetodelta
              - batch
            exporters: [otlphttp]
          logs/host:
            receivers: [filelog]
            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]
            exporters: [otlphttp]
          traces:
            receivers: [otlp]
            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]
            exporters: [otlphttp]
          metrics:
            receivers: [otlp]
            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]
            exporters: [otlphttp]
          logs:
            receivers: [otlp]
            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]
            exporters: [otlphttp]
        extensions: [health_check]
    ```
  </Collapser>
</CollapserGroup>

4. **Cree un nuevo despliegue** para agregar la configuración remota recién creada a la flota. El control del agente aplicará automáticamente la nueva configuración al host, descargará e instalará los paquetes de OCI para cada agente. Siga estos pasos en [Crear y ejecutar el primer despliegue](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment).

5. **Verifique que los datos estén fluyendo.** Vaya a **Infrastructure &gt; Hosts** en la UI de New Relic. Su host debería aparecer en 1-2 minutos. Si no aparece, consulte la [resolución de problemas de Agent Control](/docs/new-relic-control/agent-control/troubleshooting).

### Windows

1. **Cree una flota** de tipo **Windows Host** en el control de flota. Consulte [Crear su primera flota](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet) para obtener pasos detallados.

    Recopila métricas de rendimiento del disco lógico usando `Get-CimInstance` a través de PowerShell. Este ejemplo demuestra cómo nri-flex puede ejecutar cualquier comando de PowerShell y analizar su salida JSON como eventos de New Relic. Requiere PowerShell v3+.

    ```yaml
    config:
      integrations:
        - name: nri-flex
          config:
            name: winDiskPerf
            apis:
              - event_type: WinDiskPerfSample
                shell: powershell
                commands:
                  - run: >
                      Get-CimInstance -ClassName Win32_PerfFormattedData_PerfDisk_LogicalDisk |
                      Select-Object -Property Name, PercentFreeSpace, FreeMegabytes |
                      ConvertTo-Json
    ```

## Migrar un sistema previamente instrumentado

<Callout variant="important">
  Agent Control no admite la migración automática de agentes existentes. La migración siempre es un proceso manual: desinstale el agente existente, instale Agent Control y, a continuación, vuelva a crear la configuración como una configuración remota de control de flota.
</Callout>

### Proceso general de migración

Independientemente de la plataforma, la migración sigue estos cuatro pasos:

1. **Tome nota de su configuración existente.** Guarde una copia de todos los archivos de configuración del agente y las configuraciones de integración antes de desinstalar nada. Las recreará como configuraciones remotas de Fleet Control.
2. **Desinstale el agente existente.** Agent Control no puede coexistir con una instalación de agente independiente del mismo tipo.
3. **Instale Agent Control y conéctese a una flota.** Siga la guía de instalación específica de la plataforma y seleccione una flota existente o cree una nueva.
4. **Vuelva a crear la configuración en Fleet Control.** Cree una configuración remota para la flota con los ajustes anteriores. Agent Control lo aplicará automáticamente.

<Callout variant="important" title="La configuración remota siempre gana">
  Fleet Control es la fuente autorizada para la configuración del agente. Cualquier configuración del agente, versiones, valores de charts y límites de recursos, debe definirse en la configuración remota de Fleet Control, no en el archivo de instalación local. Si ambos existen, la configuración remota tiene prioridad y sobrescribirá cualquier valor local.
</Callout>

<Callout variant="tip" title="Mejores practicas">
  Para garantizar la continuidad de los datos, use el mismo nombre de entidad (nombre de clúster o nombre de host) y la misma cuenta de New Relic durante la instalación de Agent Control. Puede dejar en su lugar cualquier agente o componente que aún no sea compatible con Agent Control hasta que el soporte esté disponible.
</Callout>

### Kubernetes

Si su clúster de Kubernetes ya está instrumentado con New Relic, puede realizar la transición de sus agentes para que sean administrados por Agent Control. El proceso de migración elimina las instalaciones de agentes existentes y las reemplaza con instalaciones gestionadas por Agent Control, configuradas centralmente a través de control de flota.

Agent Control puede desplegar y administrar los siguientes agentes del chart de Helm `nri-bundle`:

* `newrelic-infrastructure`, `nri-kube-events` y `kube-state-metrics`: administrados como el tipo **agente de infraestructura**
* `newrelic-prometheus-configurator`: administrado como el tipo de agente **Prometheus**
* `newrelic-logging`: gestionado como el tipo de agente **Fluent Bit**
* `nr-k8s-otel-collector`: administrado como el tipo de agente **OpenTelemetry Collector**

1. **Recupere su configuración existente.** Si instaló agentes usando Helm, recupere la configuración de instalación del clúster:

```sh
# Find releases in the namespace
helm list --namespace <namespace-name>

# Get the values for a specific release
helm get values <release-name> --namespace <namespace-name>
```

Si tiene el archivo de configuración original guardado de la instalación, utilícelo directamente. Si instrumentó el clúster mediante manifiestos de Kubernetes (kubectl o Kustomize), tome nota de las opciones establecidas para cada agente —las recreará como configuraciones remotas de Fleet Control.

2. **Desinstale sus agentes antiguos.** Antes de instalar Agent Control, elimine los agentes antiguos de su clúster. Para una instalación de Helm:

```shell
helm uninstall <release-name> -n <namespace>
```

Por ejemplo, para desinstalar el `nri-bundle`:

```shell
helm uninstall nri-bundle -n newrelic
```

3. **Instale Agent Control.** Inicie la [instalación guiada de Agent Control](/docs/new-relic-control/agent-control/setup/) y descargue el `values.yaml` generado. Este archivo contiene solo la configuración del supervisor de Agent Control (credenciales, ID de flota y qué tipos de agentes administrar) — **no agregue valores de chart específicos del agente aquí**. Esos pertenecen a la configuración remota de control de flota.

```shell
helm upgrade --install agent-control-bootstrap -n newrelic newrelic/agent-control-bootstrap --create-namespace --values my_values.yaml
```

4. **Vuelva a crear la configuración de su agente en Fleet Control.** Después de que Agent Control se conecte a Fleet Control, [cree la configuración](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration) para cada uno de los agentes antiguos con los ajustes anteriores.

5. **Cree un nuevo despliegue** agregando las configuraciones remotas recién creadas a su flota. Agent Control aplicará automáticamente la nueva configuración a su clúster. Siga estos pasos en [crear y ejecutar su primer despliegue](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment).

6. **Verifique que los datos estén fluyendo.** Vaya a **Infrastructure &gt; Kubernetes** en la UI de New Relic. El clúster debería aparecer en 1-2 minutos después de aplicar la configuración remota. Si no aparece, consulte la [resolución de problemas de Agent Control](/docs/new-relic-control/agent-control/troubleshooting).

### Linux

<Callout variant="important">

Si ya tiene el New Relic Infrastructure Agent instalado en su host Linux, debe desinstalarlo manualmente antes de instalar Agent Control. 3. **Instale Agent Control.** Siga la [guía de instalación de Linux](/docs/new-relic-control/agent-control/setup/). Asegúrese de seleccionar o crear una flota de tipo **Host - Linux**.

4. **Vuelva a crear la configuración de su agente en Fleet Control.** Después de que Agent Control se conecte al control de flota, [cree la configuración](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration) para cada uno de los agentes antiguos con los ajustes anteriores. Siga estos pasos en [Crear y ejecutar el primer despliegue](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment).
