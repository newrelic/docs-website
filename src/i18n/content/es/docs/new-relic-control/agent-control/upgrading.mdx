## Descripción general

Agent Control proporciona una forma fluida y centralizada de gestionar todo el ciclo de vida de sus agentes, incluidas las actualizaciones. En lugar de actualizar manualmente los agentes en cada host o clúster, define el estado deseado en Fleet Control y Agent Control se encarga automáticamente del resto.

Control de agentes puede actualizarse por sí solo como parte de sus despliegues de control de flota, por lo que se mantiene actualizado sin una campaña de actualización independiente. Actualiza los agentes que gestiona cambiando su versión en la configuración de su flota.

### Beneficios clave del proceso de actualización con New Relic Control

* Control centralizado: gestione todas las versiones de agentes para toda su flota desde una única ubicación.
* Automatizado: una vez que defina una nueva versión, el proceso de despliegue y conciliación se maneja automáticamente.
* Instalaciones protegidas: en los hosts, Control de agentes verifica una nueva versión antes de reemplazar la que se está ejecutando. En Kubernetes, una actualización continua mantiene los pods antiguos en ejecución hasta que los nuevos estén en buen estado. Consulte [Si falla una actualización de Control de agentes](#upgrade-failure).

<Callout variant="important">
  Control de agentes no revierte una actualización automáticamente una vez que la nueva versión está en ejecución. Para saber qué está protegido y qué no, consulte [Si falla una actualización de Control de agentes](#upgrade-failure).
</Callout>

## Actualización de sus agentes administrados

Puede actualizar cualquier agente gestionado por Agent Control simplemente cambiando su versión en la configuración remota dentro de Fleet Control. Este enfoque declarativo garantiza la consistencia y la confiabilidad en toda su flota.

* **Edite la configuración:** Navegue a la configuración de su flota en Fleet Control.
* **Actualizar la versión:** Localice el agente que desea actualizar (por ejemplo, `infrastructure`) y cambie el valor de `chart_version` al nuevo número de versión.
* **Desplegar los cambios:** Almacene y despliegue la configuración actualizada.

Agent Control detectará automáticamente el cambio y realizará una actualización gradual sin interrupciones, asegurando que sus nuevos agentes estén en ejecución y en buen estado antes de reemplazar a los antiguos.

### Ejemplo: Actualización del agente de infraestructura de New Relic

Este ejemplo muestra cómo actualizar el agente de infraestructura a una nueva versión.

```yaml
# Remote configuration for a single agent
chart_version: "5.0.109"  # Change this value
chart_values:
  newrelic-infrastructure:
    enableProcessMetrics: true
```

## Cómo se actualiza Control de agentes con control de flota [#ac-auto-upgrade]

Cuando aplica un despliegue en el control de flota, el control de flota verifica si hay una versión más reciente de Control de agentes disponible para las entidades administradas en esa flota. Si la hay, la actualización se incluye en el despliegue.

1. El equipo de Control de agentes lanza una nueva versión en el [canal de lanzamiento](#release-channels).
2. Envía un despliegue en el control de flota. La actualización del Control de agentes se incluye con este.
3. Control de agentes se actualiza a sí mismo y los agentes administrados reciben solo los cambios de configuración que solicitó.

Control de agentes se actualiza como parte de un despliegue y no entre despliegues. Para la parte del despliegue de este proceso, consulte [Actualizaciones automáticas de Control de agentes](/docs/new-relic-control/fleet-control/manage-fleets#automatic-agent-control-upgrades) en la documentación de control de flota.

<Callout variant="important">
  Si instaló Control de agentes durante la versión preliminar limitada o pública, antes de la disponibilidad general, es posible que su versión no admita actualizaciones a través de control de flota. En ese caso, actualice Control de agentes manualmente a la última versión una vez, por ejemplo, ejecutando la instalación guiada nuevamente. Después de eso, control de flota puede incluir futuras actualizaciones en sus despliegues.
</Callout>

En un host, una actualización reinicia Control de agentes. Primero detiene los agentes que administra y los vuelve a iniciar una vez que la nueva versión está en ejecución, por lo que debe esperar una breve interrupción en los datos de esos agentes. En Kubernetes, Flux reemplaza los pods de Control de agentes con una actualización continua, y los agentes administrados siguen ejecutándose.

### Canales de versión [#release-channels]

Un canal de versión es una línea de versiones de Control de agentes a la que se suscribe. Cada canal tiene su propia política sobre cuándo llega una nueva versión, basada en factores como el tiempo que ha estado disponible una versión y qué tan probada está.

Control de flota ofrece un canal, **Rapid**. Contiene la última versión de Control de agentes lista para producción. Una nueva versión llega con su próximo despliegue en control de flota, que también es la forma en que funcionan las actualizaciones para Control de agentes en Kubernetes. No puede seleccionar un canal diferente ni elegir la versión a la que actualiza control de flota.

## Actualización del Control del Agente

Actualice Control de agentes a través de control de flota en cada plataforma. La actualización es parte de su despliegue, como se describe en [Cómo se actualiza Control de agentes con control de flota](#ac-auto-upgrade).

### Kubernetes

Las siguientes instrucciones se aplican a Agent Control ejecutándose en un clúster de Kubernetes.

El control de flota incluye la actualización del Control de agentes en el despliegue, como se describe en [Cómo se actualiza el Control de agentes con el control de flota](#ac-auto-upgrade). Cuando hay una versión más reciente disponible, la página de despliegue muestra un aviso de que el Control de agentes se actualizará. No necesita cambiar la versión del Control de agentes en su configuración. Esto mantiene el Control de agentes que se ejecuta en el clúster actualizado con las últimas características, correcciones y parches de seguridad.

La actualización desencadena una actualización gradual de los pods de Control de agentes en su clúster. Las verificaciones de estado integradas de Kubernetes aseguran que la nueva versión esté en buen estado antes de que la anterior sea terminada para una actualización sin interrupciones.

### Hosts de Linux y Windows

En los hosts de Linux y Windows, control de flota también incluye la actualización de Control de agentes en su despliegue. No necesita cambiar la versión de Control de agentes en la configuración de su flota.

<Callout variant="caution">
  El control de flota es la forma de actualizar Control de agentes en un host. No se recomienda actualizarlo con el administrador de paquetes (`apt-get`, `zypper` o `yum`) o volviendo a ejecutar el script de instalación.
</Callout>

Los agentes administrados (agente de infraestructura, NRDOT) se actualizan de la misma manera que en Kubernetes. Actualice la versión deseada del agente en la configuración de la flota y despliegue los cambios.

### Si una actualización del Control de agentes falla [#upgrade-failure]

La forma en que Control de agentes maneja una actualización fallida depende de la plataforma:

* **Hosts de Linux y Windows:** antes de que Control de agentes se reemplace a sí mismo, ejecuta la nueva versión una vez para confirmar que puede iniciarse, cargar la configuración y conectarse al control de flota. Si esa verificación falla, o si falla la descarga o la verificación de la firma, la versión actual sigue ejecutándose y el despliegue se muestra como **FAILED**. Desplegar una versión deseada diferente inicia un nuevo intento de inmediato. Si la causa es permanente, como un paquete que falla en la verificación de la firma, la actualización sigue fallando y el despliegue permanece como **FAILED** hasta que solucione la causa o despliegue una versión diferente. La verificación se ejecuta antes del intercambio, por lo que no puede detectar una versión que la apruebe y luego se rompa más tarde.
* **Kubernetes:** la actualización continua mantiene los pods antiguos de Control de agentes en ejecución hasta que los nuevos pods estén listos.

Una vez que se ejecuta una nueva versión, Control de agentes no vuelve a la versión anterior por sí solo. Para recuperarse de una versión defectuosa, avance a una versión corregida, que control de flota incluye en su próximo despliegue. Para ver qué falló, revise los detalles del despliegue en control de flota. Consulte también [Actualizaciones automáticas de Control de agentes](/docs/new-relic-control/fleet-control/manage-fleets#automatic-agent-control-upgrades).

### Iniciar, detener y reiniciar Agent Control [#start-stop-restart]

Agent Control se inicia automáticamente después de ejecutar el script de instalación.

#### Linux

Para Linux, asegúrese de utilizar el comando correcto para su sistema de inicio. Seleccione `start`, `stop`, `restart` o `status` según corresponda.

Este es un ejemplo para `systemd`:

```shell
sudo systemctl <start|stop|restart|status> newrelic-agent-control
```

#### Windows

Ejecute estos comandos en PowerShell con privilegios de administrador:

```powershell
Start-Service -Name newrelic-agent-control
Stop-Service -Name newrelic-agent-control
Restart-Service -Name newrelic-agent-control
Get-Service -Name newrelic-agent-control
```
