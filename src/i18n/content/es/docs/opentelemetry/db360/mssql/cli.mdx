Puede instalar y configurar el Collector de NRDOT para el monitoreo de SQL Server mediante la CLI de New Relic. La CLI instala el recolector, crea o autoriza la identidad de monitoreo y configura el recolector en un solo comando.

<Callout variant="tip" title="Instalación guiada">
  Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.

    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.

    * Microsoft SQL Server 2017 o posterior.

    * **SQL Server autohospedado:**

      * **Autenticación de SQL Server:** un host de recolector de Linux o Windows, y un inicio de sesión en el rol de servidor `sysadmin` (o equivalente) con su contraseña.
      * **Autenticación de Windows o gMSA:** un host recolector de Windows, una sesión de PowerShell de administrador y una cuenta de Windows o gMSA con los permisos requeridos.

    * **SQL Server en AWS RDS:**

      * Un host recolector de Linux o Windows con conectividad de red al extremo de RDS (acceso de entrada concedido en el puerto de SQL Server dentro del grupo de seguridad de RDS), junto con el nombre de usuario y la contraseña maestros de RDS.
      * **Autenticación de dominio de Windows o gMSA:** un host recolector de Windows y una instancia de RDS ya unidos a un dominio de Microsoft Active Directory administrado por AWS.

    * **Host del recolector de Linux:** la utilidad `curl`, `systemd` y la utilidad `sqlcmd` instaladas y disponibles en `PATH` (o ubicadas en `/opt/mssql-tools18/bin` o `/opt/mssql-tools/bin`).

    * **Host de recolector de Windows:** la utilidad `sqlcmd.exe` instalada y disponible en `PATH`.

    * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondiente a la región objetivo.
  </Step>

  <Step>
    ## Instalar y configurar el NRDOT Collector [#cli-install]

    <CollapserGroup>
      <Collapser id="cli-host-sql" title="Autohospedado - autenticación de SQL Server">
        Esta receta monitorea una o más instancia de SQL Server desde un solo recolector. En lugar de solicitar un único conjunto de host/puerto/credenciales, lee dos archivos que debe crear con anticipación: un **archivo de instancia** (YAML) que enumera cada instancia a monitorear, y un **archivo de secretos** (`KEY=VALUE`) con un inicio de sesión de administrador y una contraseña para cada una, indexados para que coincidan.

        1. Cree el archivo de instancias. Agregue una entrada por cada instancia de SQL Server que desee que este recolector supervise, o solo una entrada si solo ejecuta una única instancia:

           ```bash
           cat > ~/mssql-instances.yml << 'EOF'
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
           EOF
           ```

        2. Cree el archivo de secretos con un inicio de sesión y contraseña de administrador para cada instancia, indexado para que coincida con el orden del archivo de instancias. El inicio de sesión de administrador debe ser miembro del rol `sysadmin` (o equivalente):

           ```bash
           umask 077
           cat > ~/mssql-secrets.env << 'EOF'
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
           EOF
           chmod 600 ~/mssql-secrets.env
           ```

        **Linux:**

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-mssql
        ```

        **Windows** (ejecutar en una sesión de PowerShell de administrador):

        ```powershell
        [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql
        ```

      <Collapser id="cli-host-winauth" title="Autohospedado - Autenticación de Windows o gMSA">
        Este método solo es compatible con un host de recolector de Windows. Utiliza la autenticación de Windows (`integrated security=true`) en lugar de los inicios de sesión de SQL, y monitorea una o más instancias de SQL Server desde un solo recolector. El recolector es un servicio de Windows con una cuenta de inicio de sesión, y se conecta a **cada** instancia como esa cuenta, por lo que una instalación de múltiples instancias siempre utiliza un modo de autenticación y una identidad de Windows, otorgada en cada instancia que enumere.

        1. Cree el archivo de instancias. Agregue una entrada por instancia de SQL Server que desee que este recolector supervise, o solo una entrada si solo ejecuta una única instancia. Solo se necesitan `host` y `port` (sin `login_name`, sin archivo de secretos):

           ```yaml
           instances:
             - host: sql01.contoso.com
               port: 1433
             - host: sql02.contoso.com
               port: 1433
           ```

           Guarde esto en cualquier lugar del host del recolector, por ejemplo, `C:\mssql-instances.yml`. Para una instancia con nombre, use `host` más su puerto TCP estático en lugar de `host\INSTANCE`.

        Antes de ejecutar este comando, tenga preparado:

        * El archivo de instancias del paso 1
        * Ya sea que utilice una cuenta de Windows o una cuenta gMSA
        * Para la autenticación de Windows: ya sea que el recolector se ejecute en el mismo host que SQL Server o en un host diferente
        * La cuenta de Windows (o cuenta gMSA) a la que se le otorgarán permisos (no es necesario si el recolector se ejecuta en el mismo host que SQL Server)
        * Si desea métricas básicas o avanzadas

        Ejecute esto en una sesión de PowerShell de administrador:

        ```powershell
        [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql-winauth
        ```

      <Collapser id="cli-rds-winauth" title="AWS RDS - Autenticación de dominio de Windows o gMSA">
        Este método solo es compatible con un host recolector de Windows y requiere que las instancias de RDS ya estén unidas a un dominio de AWS Managed Microsoft AD. Supervisa uno o más extremos de RDS SQL Server desde un único recolector. A diferencia del método autohospedado anterior, aquí no hay una opción de &quot;mismo host&quot;: siempre se requiere una cuenta de dominio (o gMSA).

           ```yaml
               port: 1433
             - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
               port: 1433
           ```

           Guárdelo en cualquier lugar del host del recolector, por ejemplo, `C:\mssql-instances.yml`.

        Antes de ejecutar este comando, tenga preparado:

        * El archivo de instancias del paso 1

        * La cuenta de dominio (o cuenta gMSA) a la que se le otorgarán permisos

    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

    Para encontrar su entidad de base de datos SQL Server en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.

    3. Seleccione su base de datos SQL Server de la lista de entidades.

       Después de configurar el monitoreo de SQL Server con NRDOT, puede:

       * [Crea dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de tu base de datos
       * [Configura alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de rendimiento de la base de datos
       * [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
  </Step>
