Monitoree el rendimiento de la base de datos SQL Server con métricas exhaustivas recopiladas por el NRDOT Collector. De forma predeterminada, New Relic recopila las métricas y los eventos a nivel de consulta a los que se hace referencia en la sección [Métricas y eventos predeterminados](#default). Puede mejorar el monitoreo habilitando las métricas deseadas que se enumeran en la sección [Métricas de características completas](#full-feature).

## Métricas y eventos predeterminados [#default]

Las siguientes métricas están habilitadas de forma predeterminada. Se recopilan en cualquier plataforma cuando el receptor está configurado con una conexión directa a SQL Server.

### Log de eventos [#log-events]

Los siguientes eventos se recopilan como registros de logs de OpenTelemetry y están habilitados de forma predeterminada, excepto `db.server.procedure_definition`, que es opcional. Proporcionan visibilidad a nivel de consulta: muestras de consultas activas, consultas principales, planes de ejecución, procedimientos almacenados principales y definiciones de procedimientos almacenados.

<CollapserGroup>

<Collapser id="db-server-top-query" title="Consultas principales">
Recopilación de métricas de eventos para las N consultas principales, filtradas en función del mayor tiempo transcurrido consumido en el intervalo de recopilación. Este evento está habilitado de forma predeterminada.

Utilice el bloque `top_query_collection` para ajustar su comportamiento:

```yaml
top_query_collection:
  lookback_time: 60s
  max_query_sample_count: 1000
  top_query_count: 250
  collection_interval: 60s
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="db-server-top-procedure" title="Procedimientos principales">
Métricas de rendimiento agregadas para los procedimientos almacenados principales por tiempo transcurrido, calculadas como deltas durante el intervalo de recolección. Se correlaciona con `db.server.top_query` y `db.server.query_sample` a través de `sqlserver.procedure_id`. Este evento está habilitado de forma predeterminada.

<Callout variant="tip">
Requiere SQL Server 2017 CU3 o posterior, que introdujo el soporte para `sys.dm_exec_procedure_stats.total_spills`. En versiones anteriores, este evento no emite datos y registra un error. Otros eventos no se ven afectados.
</Callout>

Utilice el bloque `top_procedure_collection` para ajustar su comportamiento:

```yaml
top_procedure_collection:
  max_procedure_sample_count: 1000
  top_procedure_count: 250
  collection_interval: 60s
```

## Limitaciones de Amazon RDS [#rds-limitations]

Al monitorear una instancia de Amazon RDS para SQL Server, ciertas métricas pueden informar `0` o no recopilarse debido a restricciones del servicio RDS y limitaciones de la edición de SQL Server.

<Callout variant="important">
Las siguientes limitaciones se aplican específicamente a las instancias de SQL Server que se ejecutan en Amazon RDS. Los despliegues de SQL Server autohospedados no se ven afectados por estas restricciones.
</Callout>

<CollapserGroup>
<Collapser id="rds-limitations-table" title="Referencia de limitaciones de métricas de RDS">
<table>
<thead>
<tr>
<th>

</th>

<th>
Limitación
</th>

<th>
Ediciones afectadas
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
`sqlserver.database.execution.errors`
</td>

<td>
Siempre reporta `0`. SQL Server ML Services (Extensibility framework) no está aprovisionado en ninguna edición de Amazon RDS SQL Server.
</td>

<td>
Todas las ediciones
</td>
</tr>

<tr>
<td>
`sqlserver.failover_cluster.ag.cluster_type`, `sqlserver.failover_cluster.ag.failure_condition_level`, `sqlserver.failover_cluster.ag.health_check_timeout`, `sqlserver.failover_cluster.ag.required_sync_secondaries`, `sqlserver.failover_cluster.replica.database.queue_size`, `sqlserver.failover_cluster.replica.database.redo.rate`, `sqlserver.failover_cluster.replica.role`, `sqlserver.failover_cluster.replica.synchronization_health`
</td>

<td>
No se recopila. Los grupos de disponibilidad Always On requieren un despliegue Multi-AZ, no disponible en las ediciones Web y Express.

</td>
</tr>

<td>
`sqlserver.failover_cluster.replica.flow_control_time`, `sqlserver.replica.data.rate`, `sqlserver.transaction.delay`, `sqlserver.transaction.mirror_write.rate`

Emitido pero siempre informa `0`. Estas miden la actividad de la réplica de AG no disponible sin Multi-AZ.
</td>

<td>
Web, Express
</td>

<Callout variant="important">
Las siguientes limitaciones solo se aplican a la base de datos de Azure SQL. La instancia administrada de Azure SQL y SQL Server autohospedado admiten estas métricas.
