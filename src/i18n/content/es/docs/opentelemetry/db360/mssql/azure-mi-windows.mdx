Configure el monitoreo de Microsoft SQL Server mediante el Collector de NRDOT en entornos Windows para monitorear la instancia administrada de Azure SQL, con la autenticación de SQL Server. Para ejecutar el recolector en Linux, consulte [Instancia administrada de Azure SQL en Linux](/docs/opentelemetry/db360/mssql/azure-mi-linux).

<Callout variant="tip" title="Instalación guiada">
Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página solo cubre la instalación manual.
</Callout>

Esta página trata sobre la autenticación de SQL Server. La autenticación de dominio de Windows y gMSA no están cubiertas para la instancia administrada de Azure SQL.

<Steps>
<Step>
## Requisitos previos [#prerequisites]

Antes de monitorear Microsoft SQL Server con NRDOT, asegúrese de que el entorno cumpla con estos requisitos:

* Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) válida.

* Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para su región.

* Requisitos de Azure SQL Managed Instance:

  * Autenticación de SQL habilitada en la instancia administrada.
  * El inicio de sesión y la contraseña de administrador de la instancia administrada, o un inicio de sesión de SQL Server con el rol de servidor `sysadmin`.
  * Acceso de red desde el host del recolector a la instancia administrada en el puerto `1433` (extremo privado) o `3342` (extremo público). El grupo de seguridad de red (NSG) en la subred de la instancia administrada debe permitir la conexión.
  * SQL Server Management Studio (SSMS) o la utilidad `sqlcmd`.

* El nombre de host de la instancia administrada, que se muestra en la página **Overview** de la instancia administrada en el portal de Azure (el campo **Host**).
</Step>

<Step>
## Instalar NRDOT Collector [#install-sql]

Instale el Collector de NRDOT en una máquina virtual (VM) o máquina con Windows que pueda conectarse a la instancia administrada.

<Callout variant="important">
Instale el Collector de NRDOT en una máquina virtual (VM) en la misma red virtual que la instancia administrada (o una red emparejada). Una instancia administrada es privada de forma predeterminada, por lo que una máquina fuera de la red virtual no puede acceder a ella a menos que habilite el extremo público.
</Callout>

Descarga e instala el NRDOT Collector usando PowerShell:

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
$NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
$WebClient = New-Object System.Net.WebClient
$WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
$WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
Get-Service nrdot-collector -ErrorAction SilentlyContinue
```
</Step>

<Step>
## Crear usuario de monitoreo [#user-sql]

Ejecute este script como usuario administrador para crear el usuario de monitoreo `newrelic` y otorgar los permisos necesarios para recopilar métricas de SQL Server.

<Callout variant="tip">
Ejecute este script con el inicio de sesión de administrador de la instancia administrada o un inicio de sesión con el rol de servidor `sysadmin`. El script omite las bases de datos del sistema (`master`, `msdb`, `tempdb`, `model`) y cualquier base de datos que no esté en línea.
</Callout>

En su SQL Server Management Studio (SSMS), ejecute el siguiente script para crear el usuario de monitoreo `newrelic`. Reemplace `<YOUR_PASSWORD>` con su contraseña deseada:

```sql
USE [master];
GO
CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
GO

GRANT VIEW SERVER STATE TO [newrelic];
GRANT VIEW ANY DEFINITION TO [newrelic];
GRANT VIEW ANY DATABASE TO [newrelic];
GO

DECLARE @name SYSNAME;
DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
SELECT [name]
FROM [master].[sys].[databases]
WHERE [name] NOT IN ('master', 'msdb', 'tempdb', 'model', 'distribution')
AND [state] = 0;
OPEN db_cursor;
FETCH NEXT FROM db_cursor INTO @name;
WHILE @@FETCH_STATUS = 0
BEGIN
  BEGIN TRY
    EXEC('USE [' + @name + '];
    IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
    BEGIN
      CREATE USER [newrelic] FOR LOGIN [newrelic];
    END;
    GRANT VIEW DATABASE STATE TO [newrelic];');
  END TRY
  BEGIN CATCH
    PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
  END CATCH
  FETCH NEXT FROM db_cursor INTO @name;
END
CLOSE db_cursor;
DEALLOCATE db_cursor;
GO
```

<Callout variant="tip">
Para administrar información confidencial de forma segura, como las credenciales de la base de datos, almacénelas en herramientas de [administración de secretos](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
</Callout>
</Step>

<Callout variant="tip">
* El pipeline `logs` no transporta registros de depuración del recolector ni logs internos del agente. Transmite telemetría de consultas de SQL Server, incluido el texto de la consulta, los planes de ejecución y los datos de muestra. El receptor `nrsqlserver` captura esta telemetría a través de los eventos `db.server.query_sample`, `db.server.top_query`, `db.server.query_plan` y `db.server.top_procedure` emitidos como registros de log de OpenTelemetry.

* El evento `db.server.top_procedure` requiere SQL Server 2017 CU3 o posterior, que introdujo la compatibilidad con `sys.dm_exec_procedure_stats.total_spills`. En versiones anteriores, este evento no emite datos y registra un error. Otros eventos no se ven afectados. El acceso a `sys.dm_exec_procedure_stats` requiere `VIEW SERVER STATE` (o `VIEW SERVER PERFORMANCE STATE`, según la versión de SQL Server). Además, se requiere `VIEW ANY DEFINITION` para que `OBJECT_NAME` y `OBJECT_SCHEMA_NAME` se resuelvan correctamente en todas las bases de datos de usuario, y se necesita `CONNECT SQL` para configurar las sesiones iniciales. El usuario de monitoreo creado en [Crear usuario de monitoreo](#user-sql) ya tiene los 3 permisos.
</Callout>

<Step>
## Actualizar el registro del servicio de Windows [#registry-sql]

1. Actualice el registro de servicios de Windows para usar el nuevo archivo `mssql-config.yaml` mediante uno de los siguientes métodos:

   * **Para PowerShell:** ejecute el siguiente comando como administrador:

     ```powershell
     Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
     ```

   * **Para el símbolo del sistema:** si PowerShell no está disponible, use el símbolo del sistema en su lugar y ejecute el siguiente comando como administrador:

   ```bash
   sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
   ```

2. Valide la configuración del NRDOT Collector para asegurarse de que tenga el formato correcto y funcione correctamente.

```bash
& "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
```

<Callout variant="tip">
Para correlacionar el rendimiento de su aplicación con las operaciones de la base de datos, puede configurar la identificación del servicio de base de datos. Para obtener más información, consulte [configurar la identificación del servicio de base de datos](/docs/opentelemetry/db360/capabilities/db-apm/).
</Callout>
</Step>

<Step>
## Reiniciar NRDOT Collector [#restart-sql]

Después de actualizar su configuración, reinicie el servicio NRDOT Collector:

```bash
net stop nrdot-collector
net start nrdot-collector
```

<Callout variant="tip">
Siempre reinicie el servicio NRDOT Collector después de realizar cambios de configuración para garantizar que los nuevos ajustes surtan efecto.
</Callout>
</Step>

<Step>
## Encuentra y utiliza tus datos [#find-sql]

Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

Para encontrar su entidad de base de datos SQL Server en New Relic:

1. Vaya a <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.

2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.

3. Seleccione su base de datos SQL Server de la lista de entidades.

   Después de configurar el monitoreo de SQL Server con NRDOT, puede:

   * [Crea dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de tu base de datos
   * [Configura alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de rendimiento de la base de datos
   * [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
</Step>
</Steps>
