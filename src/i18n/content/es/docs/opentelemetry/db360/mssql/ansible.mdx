Puede instalar y configurar el Collector de NRDOT para el monitoreo de SQL Server mediante el rol de Ansible `newrelic.newrelic_install`. El rol instala el recolector, crea o autoriza la identidad de monitoreo y configura el recolector en una sola ejecución.

<Callout variant="tip" title="Instalación guiada">
  Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.

    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.

    * Microsoft SQL Server 2017 o posterior.

    * Ansible Core 2.13 o 2.14, Python 3.10 y las colecciones `ansible.windows` y `ansible.utils`.

    * SQL Server autohospedado:

      * Autenticación de SQL Server: un host recolector de Linux o Windows, y un inicio de sesión en el rol de servidor `sysadmin` (o equivalente) con su contraseña.
      * Autenticación de Windows o gMSA: un host recolector de Windows, una sesión de PowerShell de administrador y una cuenta de Windows o cuenta de servicio administrada de grupo (`gMSA`) con los permisos requeridos.

    * SQL Server en AWS RDS:

      * Un host recolector de Linux o Windows con conectividad de red al extremo de la base de datos (acceso de entrada concedido en el puerto de SQL Server dentro del grupo de seguridad), junto con el nombre de usuario y la contraseña maestros de la base de datos.
      * Autenticación de dominio de Windows o gMSA: un host recolector de Windows y una instancia unida a un dominio de AWS Managed Microsoft Active Directory.

    * Host recolector de Linux: la utilidad `curl`, `systemd` y la utilidad `sqlcmd` instaladas y disponibles en `PATH` (o ubicadas en `/opt/mssql-tools18/bin` o `/opt/mssql-tools/bin`).

    * Host del recolector de Windows: la utilidad `sqlcmd.exe` instalada y disponible en `PATH`.

    * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondiente a la región objetivo.
  </Step>

  <Step>
    ## Instale el rol [#ansible-install-role]

```bash
    ansible-galaxy install newrelic.newrelic_install
```

    Asegúrese de que las colecciones requeridas también estén instaladas:

```bash
    ansible-galaxy collection install ansible.windows ansible.utils
```
  </Step>

  <Step>
    ## Configure el playbook [#ansible-configure]

    <CollapserGroup>
      <Collapser id="ansible-host-sql" title="Autohospedado - autenticación de SQL Server">
        Este rol monitorea una o más instancias de SQL Server desde un solo recolector. En lugar de un solo conjunto de host/puerto/credenciales, lee dos archivos que ya deben existir en el host objetivo: un archivo de instancias (YAML) que enumera cada instancia a monitorear y un archivo de secretos (`KEY=VALUE`) con un inicio de sesión y contraseña de administrador para cada una, indexados para que coincidan.

        1. Cree el archivo de instancias en el host objetivo. Agregue una entrada por cada instancia de SQL Server que desee que este recolector monitoree, o solo una entrada si solo está ejecutando una única instancia:

```yaml
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
```

        2. Cree el archivo de secretos en el host objetivo con un inicio de sesión de administrador y una contraseña para cada instancia, indexado para que coincida con el orden del archivo de instancia. El inicio de sesión de administrador debe ser miembro del rol `sysadmin` (o equivalente):

```bash
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
```

        Luego, cree un archivo denominado `playbook.yml` y copie el siguiente contenido en él. Establezca `targets` en `mssql-otel` y reemplace los valores del marcador de posición por los suyos:

```yaml
        - name: Install New Relic NRDOT for SQL Server
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_MSSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

        <Callout variant="tip">
          Para habilitar el logging de depuración, agregue `verbosity: "debug"` debajo de `vars` en el playbook.

      <Collapser id="ansible-host-winauth" title="Autohospedado - Autenticación de Windows o gMSA">
        Este objetivo solo es compatible con un host del recolector de Windows. Utiliza la autenticación de Windows (`integrated security=true`) en lugar de los inicios de sesión de SQL y monitorea una o más instancias de SQL Server desde un único recolector mediante un **archivo de instancias** (YAML, `host`/`port` por instancia, sin archivo de secretos: una identidad de Windows monitorea cada instancia).

        Cree el archivo de instancia en el host objetivo, con solo una entrada si solo ejecuta una única instancia. Solo se necesitan `host` y `port` (no `login_name`):

```yaml
        instances:
          - host: sql01.contoso.com
            port: 1433
          - host: sql02.contoso.com
            port: 1433
```

        Para una instancia con nombre, utilice `host` más su puerto TCP estático en lugar de `host\INSTANCE`.

        Luego, cree un archivo denominado `playbook.yml` y copie el siguiente contenido en él. Establezca `targets` en `mssql-otel-winauth` y reemplace los valores del marcador de posición por los suyos:

```yaml
        - name: Install New Relic NRDOT for SQL Server (Windows Auth)
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel-winauth
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_AUTH_MODE: <1 for Windows Domain Auth, 2 for gMSA, default 1>
            NR_CLI_MSSQL_WINAUTH_LOCATION: <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_MSSQL_WIN_ACCOUNT: <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
            NR_CLI_MSSQL_WIN_PASSWORD: <password for that account; required only for Windows Domain Auth on a different host>
            NR_CLI_MSSQL_GMSA_ACCOUNT: <gMSA account, DOMAIN\gMSAName$; gMSA only>
```

        <Callout variant="tip">
          Para habilitar el logging de depuración, agregue `verbosity: "debug"` debajo de `vars` en el playbook.
        </Callout>

      <Collapser id="ansible-rds-sql" title="AWS RDS - Autenticación de SQL Server">
        Este rol monitorea uno o más extremos de RDS SQL Server desde un solo recolector, utilizando el mismo patrón de archivo de instancias/archivo de secretos que el autohospedado (ambos archivos ya deben existir en el host objetivo).

        1. Cree el archivo de instancias en el host objetivo, utilizando el extremo de RDS como `host`, con solo una entrada si solo monitorea una única instancia de RDS:

```yaml
           instances:
             - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
               port: 1433
               login_name: newrelic
```

        2. Cree el archivo de secretos en el host objetivo con el nombre de usuario y la contraseña maestros de RDS para cada instancia, indexado para que coincida con el orden del archivo de instancia:

```bash
           NR_CLI_MSSQL_ADMIN_USER_1=admin
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=YourMasterPassword1
```

        Luego, cree un archivo denominado `playbook.yml` y copie el siguiente contenido en él. Establezca `targets` en `mssql-otel-rds` y reemplace los valores del marcador de posición por los suyos:

```yaml
        - name: Install New Relic NRDOT for SQL Server on RDS
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel-rds
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
            NR_CLI_MSSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

      <Collapser id="ansible-rds-winauth" title="AWS RDS - Autenticación de dominio de Windows o gMSA">
        Este objetivo solo es compatible con un host del recolector de Windows y requiere que las instancias de RDS ya estén unidas a un dominio de AWS Managed Microsoft AD. Monitorea uno o más extremos de RDS SQL Server desde un único recolector mediante un **archivo de instancias** (YAML, `host`/`port` por instancia, utilizando los extremos de RDS como `host`). A diferencia del objetivo autohospedado anterior, aquí no hay una opción de &quot;mismo host&quot;: siempre se requiere una cuenta de dominio (o gMSA).

        Cree el archivo de instancias en el host objetivo, usando cada extremo de RDS como `host`, con solo una entrada si solo está monitoreando una única instancia de RDS:

```yaml
        instances:
          - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
          - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
```

        Luego, cree un archivo denominado `playbook.yml` y copie el siguiente contenido en él. Establezca `targets` en `mssql-otel-rds-winauth` y reemplace los valores del marcador de posición por los suyos:

```yaml
        - name: Install New Relic NRDOT for SQL Server on RDS (Windows Auth)
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel-rds-winauth
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_AUTH_MODE: <1 for Windows Domain Auth, 2 for gMSA, default 1>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
            NR_CLI_MSSQL_WIN_ACCOUNT: <Windows domain account, DOMAIN\username; Windows Domain Auth only>
            NR_CLI_MSSQL_WIN_PASSWORD: <password for that account; Windows Domain Auth only>
            NR_CLI_MSSQL_GMSA_ACCOUNT: <gMSA account, DOMAIN\gMSAName$; gMSA only>
```

          Para habilitar el logging de depuración, agregue `verbosity: "debug"` debajo de `vars` en el playbook.

    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

    Para encontrar su entidad de base de datos SQL Server en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.

    3. Seleccione su base de datos SQL Server de la lista de entidades.

       Después de configurar el monitoreo de SQL Server con NRDOT, puede:

       * [Crea dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de tu base de datos
       * [Configura alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de rendimiento de la base de datos
       * [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
  </Step>
