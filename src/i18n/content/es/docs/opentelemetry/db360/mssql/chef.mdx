Puede instalar y configurar el Collector de NRDOT para el monitoreo de SQL Server mediante el libro de recetas de Chef `newrelic-install`. El libro de recetas instala el recolector, crea o autoriza la identidad de monitoreo y configura el recolector cuando ejecuta la receta `newrelic-install::default`.

<Callout variant="tip" title="Instalación guiada">
  Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.

    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.

    * Microsoft SQL Server 2017 o posterior.

    * Chef 15 o posterior.

    * **SQL Server autohospedado:**

      * **Autenticación de SQL Server:** un host recolector de Windows, Ubuntu o RHEL/CentOS, y un inicio de sesión en el rol de servidor `sysadmin` (o equivalente) con la contraseña.
      * **Autenticación de Windows o gMSA:** un host recolector de Windows y la cuenta de dominio de Windows (o gMSA) a los que otorgar permisos.

    * **SQL Server en AWS RDS:**

      * Un host recolector de Windows, Ubuntu o RHEL/CentOS con conectividad de red al extremo de RDS (acceso entrante otorgado en el puerto de SQL Server dentro del grupo de seguridad de RDS), junto con el nombre de usuario y la contraseña maestros de RDS.
      * **Autenticación de dominio de Windows o gMSA:** un host recolector de Windows y una instancia de RDS ya unidos a un dominio de Microsoft Active Directory administrado por AWS.

    * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondiente a la región objetivo.
  </Step>

  <Step>
    ## Descargar el cookbook de Chef [#chef-download-cookbook]

    Descargue el [cookbook de Chef](https://supermarket.chef.io/cookbooks/newrelic-install) `newrelic-install` desde Chef Supermarket al directorio del repositorio de Chef:

    ```bash
    knife supermarket install newrelic-install
    ```
  </Step>

  <Step>
    ## Reemplace los atributos predeterminados [#chef-configure]

    Reemplace los atributos predeterminados en `attributes/default.rb` con los detalles de la cuenta:

    <CollapserGroup>
      <Collapser id="chef-host-sql" title="Autohospedado - autenticación de SQL Server">
        Este libro de recetas monitorea una o más instancias de SQL Server desde un solo recolector. En lugar de un solo conjunto de host/puerto/credenciales, lee dos archivos que ya deben existir en el nodo: un **archivo de instancias** (YAML) que enumera cada instancia a monitorear y un **archivo de secretos** (`KEY=VALUE`) con un inicio de sesión de administrador y una contraseña para cada una, indexados para que coincidan.

        1. Cree el archivo de instancias en el nodo. Agregue una entrada por cada instancia de SQL Server que desee que este recolector monitoree, o solo una entrada si solo ejecuta una única instancia:

           ```yaml
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
           ```

        2. Cree el archivo de secretos en el nodo con un inicio de sesión y contraseña de administrador para cada instancia, indexado para que coincida con el orden del archivo de instancia. El inicio de sesión de administrador debe ser miembro del rol `sysadmin` (o equivalente):

           ```bash
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
           ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']    = <path to the secrets file (KEY=VALUE per instance) on the node>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

      <Collapser id="chef-host-winauth" title="Autohospedado - Autenticación de Windows o gMSA">
        Este objetivo solo es compatible con un host del recolector de Windows. Utiliza la autenticación de Windows (`integrated security=true`) en lugar de los inicios de sesión de SQL y monitorea una o más instancias de SQL Server desde un único recolector mediante un **archivo de instancias** (YAML, `host`/`port` por instancia, sin archivo de secretos: una identidad de Windows monitorea cada instancia).

        Este archivo ya debe existir en el nodo, con solo una entrada si solo ejecuta una sola instancia. Solo se necesitan `host` y `port` (no `login_name`):

        ```yaml
        instances:
          - host: sql01.contoso.com
            port: 1433
          - host: sql02.contoso.com
            port: 1433
        ```

        Para una instancia con nombre, utilice `host` más su puerto TCP estático en lugar de `host\INSTANCE`.

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-winauth'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']    = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']        = <1 for Windows Domain Auth, 2 for gMSA, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WINAUTH_LOCATION'] = <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']   = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']      = <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']     = <password for that account; required only for Windows Domain Auth on a different host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']     = <gMSA account, DOMAIN\gMSAName$; gMSA only>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

      <Collapser id="chef-rds-sql" title="AWS RDS - Autenticación de SQL Server">
        Este libro de recetas monitorea uno o más extremos de RDS SQL Server desde un solo recolector, utilizando el mismo patrón de archivo de instancias/archivo de secretos que el autohospedado (ambos archivos ya deben existir en el nodo).

        1. Cree el archivo de instancia en el nodo, usando el extremo de RDS como `host`, con solo una entrada si solo realiza el monitoreo de una única instancia de RDS:

           ```yaml
           instances:
             - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
               port: 1433
               login_name: newrelic
           ```

        2. Cree el archivo de secretos en el nodo con el nombre de usuario maestro y la contraseña de RDS para cada instancia, indexado para coincidir con el orden del archivo de instancia:

           ```bash
           NR_CLI_MSSQL_ADMIN_USER_1=admin
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=YourMasterPassword1
           ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>

          'nrdot-collector-mssql-rds'

        default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']   = <path to the secrets file (KEY=VALUE per instance) on the node>
        ```

      <Collapser id="chef-rds-winauth" title="AWS RDS - Autenticación de dominio de Windows o gMSA">
        Este objetivo solo es compatible con un host del recolector de Windows y requiere que las instancias de RDS ya estén unidas a un dominio de AWS Managed Microsoft AD. Monitorea uno o más extremos de RDS SQL Server desde un único recolector mediante un **archivo de instancias** (YAML, `host`/`port` por instancia, utilizando los extremos de RDS como `host`). A diferencia del objetivo autohospedado anterior, aquí no hay una opción de &quot;mismo host&quot;: siempre se requiere una cuenta de dominio (o gMSA).

        Este archivo ya debe existir en el nodo, usando cada extremo de RDS como `host`, con solo una entrada si solo realiza el monitoreo de una única instancia de RDS:

        ```yaml
        instances:
          - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
          - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
        ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-rds-winauth'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']       = <1 for Windows Domain Auth, 2 for gMSA, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node, using RDS endpoints as host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']     = <Windows domain account, DOMAIN\username; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']    = <password for that account; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']    = <gMSA account, DOMAIN\gMSAName$; gMSA only>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

  <Step>
    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

    Para encontrar su entidad de base de datos SQL Server en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.

    3. Seleccione su base de datos SQL Server de la lista de entidades.

       Después de configurar el monitoreo de SQL Server con NRDOT, puede:

       * [Crea dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de tu base de datos
       * [Configura alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de rendimiento de la base de datos
       * [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
  </Step>
