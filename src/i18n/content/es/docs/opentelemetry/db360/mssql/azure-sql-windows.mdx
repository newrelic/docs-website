Monitoree el rendimiento de la base de datos de Azure SQL con métricas de la base de datos, análisis de consultas y datos de estado del sistema mediante el recolector de la distribución de OpenTelemetry de New Relic (NRDOT) en Windows.

<Callout variant="tip">
Para ejecutar el recolector en Linux, consulte [Base de datos SQL de Azure en Linux](/docs/opentelemetry/db360/mssql/azure-sql-linux).
</Callout>

<Steps>
<Step>
## Requisitos previos [#prerequisites]

* Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) válida.

* Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para su región.

* Requisitos de Azure SQL Database:

  * Un servidor lógico y una base de datos de Azure SQL.
  * El inicio de sesión y la contraseña del administrador del servidor (u otra cuenta que pueda crear inicios de sesión y administrar roles de servidor en `master`).
  * Acceso a la red desde el host del recolector al servidor en el puerto `1433`, a través de una regla de firewall del servidor, una regla de red virtual o un extremo privado. Si el servidor usa un extremo privado, el nombre del servidor debe resolverse a la dirección IP privada desde el host del recolector.

* Requisitos del host del Collector: un host (por ejemplo, una máquina virtual (VM) de Azure) con PowerShell, acceso de administrador y `sqlcmd` o SQL Server Management Studio (SSMS).
</Step>

<Step>
## Instalar NRDOT Collector [#setup]

Instale el Collector de NRDOT en un host que pueda acceder al servidor de Azure SQL.

Ejecute PowerShell como administrador:

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
$NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
$WebClient = New-Object System.Net.WebClient
$WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
$WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
Get-Service nrdot-collector -ErrorAction SilentlyContinue
```
</Step>

<Step>
## Crear usuario de monitoreo y otorgar permisos [#user]

La base de datos SQL de Azure no permite `GRANT VIEW SERVER STATE` ni permisos similares a nivel de instancia. En su lugar, agregue el inicio de sesión a los roles de servidor integrados en `master` y, luego, cree un usuario en cada base de datos que desee monitorear.

1. Cree un archivo llamado `nr-grant-permission-master.sql` y reemplace `<YOUR_PASSWORD>` con la contraseña deseada:

   ```sql
   CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
   GO
   ALTER SERVER ROLE [##MS_ServerStateReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DefinitionReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DatabaseConnector##] ADD MEMBER [newrelic];
   GO
   ```

2. Ejecútelo en la base de datos `master` como administrador del servidor. Reemplace `<YOUR-SERVER>` con el nombre del servidor (por ejemplo, `myserver.database.windows.net`):

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-master.sql
   ```

3. Cree un archivo llamado `nr-grant-permission-db.sql`:

   ```sql
   CREATE USER [newrelic] FOR LOGIN [newrelic];
   GO
   GRANT VIEW DATABASE STATE TO [newrelic];
   GO
   ```

4. Ejecútelo en **cada** base de datos que desee monitorear. Reemplace `<YOUR_DATABASE>` con el nombre de la base de datos:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-db.sql
   ```

   La siguiente tabla muestra por qué es necesario cada rol:

   | Rol o permiso              | Usado para                                                                                                            |
   | -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
   | `##MS_ServerStateReader##` | Vistas de administración dinámica a nivel de servidor, como `sys.dm_exec_query_stats` y `sys.dm_exec_procedure_stats` |
   | `##MS_DefinitionReader##`  | Resolución de nombres de objetos y esquemas para los principales procedimientos y estadísticas de índices             |
   | `##MS_DatabaseConnector##` | Conexión a bases de datos para recopilar estadísticas físicas de índices                                              |
   | `VIEW DATABASE STATE`      | Vistas de administración dinámica a nivel de base de datos, como `sys.dm_db_resource_stats`                           |

5. (Opcional) Verifique los roles del servidor de la base de datos `master`:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -Q "SELECT r.name AS [Role], l.name AS [Login] FROM sys.server_role_members rm JOIN sys.server_principals r ON rm.role_principal_id = r.principal_id JOIN sys.sql_logins l ON rm.member_principal_id = l.principal_id WHERE l.name = 'newrelic';"
   ```

   La salida enumera los tres roles.

6. (Opcional) Verifique los permisos de la base de datos conectándose como el usuario de monitoreo:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U newrelic -P '<YOUR_PASSWORD>' -C -Q "SELECT TOP 1 * FROM sys.dm_db_resource_stats; SELECT TOP 1 * FROM sys.dm_exec_query_stats;"
   ```

   Un error de permiso significa que falta una concesión.

<Callout variant="tip">
Para administrar información confidencial de forma segura, como las credenciales de la base de datos, almacénelas en herramientas de [administración de secretos](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
</Callout>
</Step>

<Step>
## Configurar el Colector NRDOT [#configure-collector]

1. Cree el archivo de configuración en PowerShell como administrador:

   ```powershell
   New-Item -Path "C:\Program Files\nrdot-collector\mssql-config.yaml" -ItemType File
   ```

2. Agregue la siguiente configuración. Reemplace `<YOUR_PASSWORD>`, `<YOUR-SERVER>`, `<YOUR_DATABASE>`, `<YOUR_LICENSE_KEY>` y el extremo de OTLP con sus valores:

   ```yaml
   receivers:
     nrsqlserver:
       collection_interval: 15s
       # datasource replaces username, password, server, and port.
       datasource: "sqlserver://newrelic:<YOUR_PASSWORD>@<YOUR-SERVER>:1433?database=<YOUR_DATABASE>"

       metrics:
         sqlserver.database.io:
           enabled: true
         sqlserver.database.latency:
           enabled: true
         sqlserver.database.operations:
           enabled: true
         sqlserver.database.tempdb.space:
           enabled: true
         sqlserver.database.tempdb.version_store.size:
           enabled: true
         sqlserver.deadlock.rate:
           enabled: true
         sqlserver.os.wait.duration:
           enabled: true
         sqlserver.processes.blocked:
           enabled: true
         sqlserver.memory.grants.pending.count:
           enabled: true
         sqlserver.database.file.size:
           enabled: true
         sqlserver.memory.area:
           enabled: true

       events:
         db.server.query_sample:
           enabled: true
         db.server.top_query:
           enabled: true
         db.server.query_plan:
           enabled: true
         db.server.top_procedure:
           enabled: true

       top_query_collection:
         lookback_time: 60s
         max_query_sample_count: 1000
         top_query_count: 250
         collection_interval: 60s
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       query_sample_collection:
         max_rows_per_query: 100
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       top_procedure_collection:
         max_procedure_sample_count: 1000
         top_procedure_count: 250
         collection_interval: 60s

       resource_attributes:
         db.system.version:
           enabled: true
         sqlserver.db.edition:
           enabled: true

   processors:
     memory_limiter:
       check_interval: ${env:NR_MEM_LIMITER_CHECK_INTERVAL:-1s}
       limit_mib:       ${env:NR_MEM_LIMITER_LIMIT_MIB:-200}
       spike_limit_mib: ${env:NR_MEM_LIMITER_SPIKE_MIB:-50}

   exporters:
     otlp:
       endpoint: https://otlp.nr-data.net:4318
       headers:
         api-key: <YOUR_LICENSE_KEY>
       tls:
         insecure: false
       compression: gzip
       sending_queue:
         enabled: true
         sizer: bytes
         queue_size: 100_000_000
         num_consumers: 10
         batch:
           sizer: bytes
           max_size: 1_000_000
           min_size: 0
           flush_timeout: 5s

   service:
     telemetry:
       metrics:
         level: none
     pipelines:
       metrics:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
       logs:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
   ```

<Callout variant="tip">
* El valor `datasource` es una URL de conexión. Si la contraseña contiene caracteres distintos de letras, dígitos y `- . _ ~ ! $ * + ,`, codifíquelos en formato URL.
* El recolector se conecta a la única base de datos nombrada en `database=`. Para monitorear varias bases de datos en el mismo servidor, use un receptor independiente para cada una, como se describe en [Configuración de múltiples receptores](/docs/opentelemetry/db360/mssql/multi-receiver#multi).
* Las métricas de Always-On, de clúster de conmutación por error y algunas métricas de latch y tempdb no están disponibles en la base de datos SQL de Azure y no devuelven datos.
* La canalización `logs` transporta telemetría de consultas de SQL Server (texto de la consulta, planes de ejecución y muestras), no logs de depuración del recolector.
</Callout>
</Step>

<Step>
## Actualizar la configuración de NRDOT Collector [#update]

1. Apunte el servicio de Windows al nuevo archivo de configuración. Ejecute en PowerShell como administrador:

   ```powershell
   Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
   ```

2. (Opcional) Valide la configuración:

   ```powershell
   & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
   ```
</Step>

<Step>
## Reiniciar NRDOT Collector [#restart]

```powershell
net stop nrdot-collector
net start nrdot-collector
```

Revise el log de eventos de la aplicación de Windows en busca de errores de permisos o de conexión:

```powershell
Get-EventLog -LogName Application -Source nrdot-collector -Newest 20
```
</Step>

<Step>
## Encuentra y utiliza tus datos [#find]

1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.
3. Seleccione su base de datos Azure SQL de la lista de entidades.
</Step>
