Configure el monitoreo de Microsoft SQL Server mediante el NRDOT Collector en entornos de Windows para monitorear instancias de AWS RDS for SQL Server, mediante la autenticación de dominio de Windows. Para monitorear en un entorno autohospedado, consulte la [instrumentación autohospedada de Windows](/docs/opentelemetry/db360/mssql/windows-hosted-domain).

<Callout variant="tip" title="Instalación guiada">
Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página solo cubre la instalación manual.
</Callout>

Esta página cubre la autenticación de dominio de Windows. Si el entorno usa un método de autenticación diferente, consulte [Autenticación de SQL Server](/docs/opentelemetry/db360/mssql/windows-rds-sql) o [gMSA](/docs/opentelemetry/db360/mssql/windows-rds-gmsa).

<Steps>
<Step>
## Requisitos previos [#prerequisites-domain]

Antes de monitorear Microsoft SQL Server con NRDOT mediante la autenticación de dominio de Windows, asegúrese de que el entorno cumpla con estos requisitos:

* Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) válida.

* Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para su región.

* Requisitos de SQL Server:

  * SQL Server 2017 o posterior en Amazon RDS.
  * Credenciales de usuario maestro de RDS o credenciales para un inicio de sesión de SQL Server con el rol `rds_superuser`.
  * Grupo de seguridad de RDS configurado para permitir conexiones en el puerto `1433` o en un puerto personalizado.
  * SQL Server Management Studio (SSMS) o la utilidad `sqlcmd`.
  * Instancia de RDS asociada al servicio AWS Active Directory.

* Requisitos de autenticación de dominio de Windows:

  * Un entorno de dominio de Windows con Active Directory.
  * Una instancia EC2 de Windows unida a un dominio.
  * RDS SQL Server configurado para aceptar la autenticación de Windows.
  * Una cuenta de usuario de dominio para que la utilice el NRDOT Collector.

* La URL del extremo de su servidor SQL de RDS, que se puede encontrar en su consola de AWS RDS en Conectividad y seguridad. Para obtener más información, consulte la [documentación de AWS RDS](https://docs.aws.amazon.com/AmazonRDS/latest/gettingstartedguide/connecting-console.html).
</Step>

<Step>
## Instalar NRDOT Collector [#setup-domain]

Instale el Collector de NRDOT en una instancia EC2 de Windows unida al dominio o en una máquina local de Windows que sea parte del mismo dominio y pueda conectarse a su instancia de RDS SQL Server.

<Callout variant="important">
Para el monitoreo de RDS, instale el Collector NRDOT en una instancia EC2 en la misma VPC que su instancia de RDS para obtener una conectividad de red óptima y una menor latencia.
</Callout>

1. Descarga e instala el NRDOT Collector usando PowerShell:

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
$NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
$WebClient = New-Object System.Net.WebClient
$WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
$WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
Get-Service nrdot-collector -ErrorAction SilentlyContinue
```
</Step>

<Step>
## Crear inicio de sesión de dominio de Windows [#create-domain]

Conéctese a la instancia de RDS SQL Server mediante SQL Server Management Studio (SSMS) o `sqlcmd` con privilegios administrativos.

En SQL Server Management Studio (SSMS), ejecute el siguiente script para crear un inicio de sesión para la cuenta gMSA y otorgar los permisos necesarios. Reemplace todas las apariciones de `<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>` con el nombre de dominio y cuenta real.

```sql
USE [master];
GO

CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FROM WINDOWS;
GO

GRANT VIEW ANY DATABASE   TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
GO

-- Grant access to all databases (required for query monitoring and tempdb metrics)
DECLARE @name SYSNAME;
DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
  SELECT [name] FROM [master].[sys].[databases]
  WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
    AND [state] = 0;
OPEN db_cursor;
FETCH NEXT FROM db_cursor INTO @name;
WHILE @@FETCH_STATUS = 0
BEGIN
  BEGIN TRY
    EXEC('USE [' + @name + '];
    IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>'')
    BEGIN
      CREATE USER [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
    END;
    GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];');
  END TRY
  BEGIN CATCH
    PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
  END CATCH
  FETCH NEXT FROM db_cursor INTO @name;
END
CLOSE db_cursor;
DEALLOCATE db_cursor;
GO
```

<Callout variant="tip">
Para administrar información confidencial de forma segura, como las credenciales de la base de datos, almacénelas en herramientas de [administración de secretos](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
</Callout>
</Step>

<Step>
## Ejecutar como usuario de dominio [#run-domain]

1. Configure el servicio NRDOT Collector para que se ejecute como su usuario de dominio usando PowerShell. Reemplace `YOUR_DOMAIN\YOUR_USER_ACCOUNT` con el nombre de su dominio y cuenta:

   ```powershell
   # Configure service to use domain account
   # The space after obj= and password= is required syntax for sc.exe
   sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

   # Restart the service
   Restart-Service nrdot-collector
   ```

2. Valide la identidad del servicio:

   ```powershell
   Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
   # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
   ```
</Step>

<Step>
## Configurar el Colector NRDOT [#configure-domain]

1. Cree un archivo de configuración llamado `mssql-config.yaml` en PowerShell como administrador:

   ```powershell
   New-Item -Path "C:\Program Files\nrdot-collector\mssql-config.yaml" -ItemType File
   ```

2. Agregue la siguiente configuración al archivo `mssql-config.yaml` creado en el paso anterior:

<Callout variant="important">
La autenticación de dominio de Windows utiliza seguridad integrada, que usa el mismo enfoque de configuración que la autenticación gMSA. Actualice el valor del servidor `datasource` a su extremo de RDS. El servicio NRDOT se autenticará mediante la cuenta de dominio que configuró en [Crear inicio de sesión de dominio de Windows](#create-domain).
</Callout>

<Callout variant="tip" title="configuración completa">
Esta configuración se centra en el monitoreo esencial de la base de datos para el entorno RDS. Para habilitar un monitoreo integral con todas las métricas disponibles, consulte la [referencia de configuración](/docs/opentelemetry/db360/mssql/config-reference/#rds-domain).
</Callout>

<Callout variant="tip">
* El pipeline `logs` no transporta registros de depuración del recolector ni logs internos del agente. Transmite telemetría de consultas de SQL Server, incluido el texto de la consulta, los planes de ejecución y los datos de muestra. El receptor `nrsqlserver` captura esta telemetría a través de los eventos `db.server.query_sample`, `db.server.top_query`, `db.server.query_plan` y `db.server.top_procedure` emitidos como registros de log de OpenTelemetry.

* El evento `db.server.top_procedure` requiere SQL Server 2017 CU3 o posterior, que introdujo la compatibilidad con `sys.dm_exec_procedure_stats.total_spills`. En versiones anteriores, este evento no emite datos y registra un error. Otros eventos no se ven afectados. El acceso a `sys.dm_exec_procedure_stats` requiere `VIEW SERVER STATE` (o `VIEW SERVER PERFORMANCE STATE`, según la versión de SQL Server). Además, se requiere `VIEW ANY DEFINITION` para que `OBJECT_NAME` y `OBJECT_SCHEMA_NAME` se resuelvan correctamente en todas las bases de datos de usuario, y se necesita `CONNECT SQL` para configurar las sesiones iniciales. La cuenta que configuró en [Crear inicio de sesión de dominio de Windows](#create-domain) ya tiene los 3 permisos.

<Step>
## Actualizar el registro del servicio de Windows [#update-registry-domain]

1. Actualice el registro de servicios de Windows para usar el nuevo archivo `mssql-config.yaml` mediante uno de los siguientes métodos:

   * **Para PowerShell:** ejecute el siguiente comando como administrador:

     ```powershell
     Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
     ```

   * **Para el símbolo del sistema:** si PowerShell no está disponible, use el símbolo del sistema en su lugar y ejecute el siguiente comando como administrador:

   ```bash
   sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
   ```

2. Valide la configuración del NRDOT Collector para asegurarse de que tenga el formato correcto y funcione correctamente:

   ```bash
   & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
   ```

<Callout variant="tip">
Para correlacionar el rendimiento de su aplicación con las operaciones de la base de datos, puede configurar la identificación del servicio de base de datos. Para obtener más información, consulte la [guía de configuración de identificación del servicio de base de datos](/docs/opentelemetry/db360/capabilities/db-apm).
</Callout>
</Step>

<Step>
## Reiniciar NRDOT Collector [#restart-domain]

Después de actualizar su configuración, reinicie el servicio NRDOT Collector:

```bash
net stop nrdot-collector
net start nrdot-collector
```

Verifique que el servicio se esté ejecutando bajo la cuenta de dominio comprobando los servicios de Windows (`services.msc`). La columna `Log On As` debería mostrar su cuenta de dominio. Por ejemplo, `CORP\SQLMonitor`.
</Step>

<Step>
## Encuentra y utiliza tus datos [#find-domain]

Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

Para encontrar su entidad de base de datos SQL Server en New Relic:

1. Vaya a <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.

2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.

3. Seleccione su base de datos SQL Server de la lista de entidades.

   Después de configurar el monitoreo de SQL Server con NRDOT, puede:

   * [Crea dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de tu base de datos
   * [Configura alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de rendimiento de la base de datos
   * [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
</Step>
</Steps>
