Database 360 (DB360) le ofrece una vista unificada de las aplicaciones, bases de datos e infraestructura para que pueda encontrar la causa raíz de los cuellos de botella de la base de datos más rápido. En lugar de alternar entre herramientas independientes de aplicación, base de datos e infraestructura para averiguar por qué una consulta es lenta, DB360 modela cada base de datos como una entidad de primera clase y la conecta directamente a los servicios de APM y las métricas de host.

DB360 está desarrollado sobre una base centrada en OpenTelemetry. Recopila telemetría mediante el Collector de New Relic Distribution of OpenTelemetry (NRDOT) o una distribución de CNCF OpenTelemetry Collector Contrib.

## Lo que obtienes [#capabilities]

* **Planes de ejecución de consultas**: vea la ruta de ejecución exacta que sigue una consulta, incluidos los eventos de espera y los bloqueos, para que pueda detectar los índices faltantes y otras ineficiencias.
* **Estados de espera y seguimiento de bloqueos**: identifique las sesiones de larga duración, las consultas que generan bloqueos y las cargas de trabajo que consumen muchos recursos antes de que afecten a otras cargas de trabajo en la misma base de datos.
* **Correlación de APM con la base de datos**: vincule las trazas de la aplicación directamente con las consultas de la base de datos, las sesiones y los eventos de espera que generan. Para obtener más información, consulte [Correlación de APM con la base de datos](/docs/opentelemetry/db360/capabilities/db-apm).
* **Contexto de infraestructura**: vea las métricas de la base de datos junto con las métricas de CPU, memoria e I/O a nivel de host.
* **Visibilidad de nodos y bases de datos lógicas**: supervise tanto el servidor de la base de datos (nodo) como las bases de datos lógicas individuales que se ejecutan en él, para que pueda dimensionar correctamente la capacidad y detectar instancias inactivas o infrautilizadas.

## Cosas que debe saber antes de comenzar [#considerations]

* **Correlación de APM**: la vinculación de entidades de base de datos a trazas de APM actualmente funciona con el agente de Java y el agente de .NET.

* **Cobertura del proveedor de cloud**:

  * **AWS**: RDS, Aurora y el autohospedaje en EC2 se admiten en los cuatro motores de base de datos.
  * **Infraestructura de la nube de Oracle (OCI)**: la base de datos de Oracle es compatible a través de Autonomous Database.

* **Volumen de métricas**: las bases de datos autohospedadas generalmente exponen más métricas que sus equivalentes administradas en el cloud, ya que los proveedores de cloud restringen el acceso a algunos componentes internos de la base de datos.

* **Controles de ingesta**: puede habilitar o deshabilitar categorías de métricas en el archivo de configuración de NRDOT para administrar el volumen de datos que recopila.
