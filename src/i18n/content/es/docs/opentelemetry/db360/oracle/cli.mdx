Puede instalar y configurar el NRDOT Collector para el monitoreo de Oracle Database mediante la CLI de New Relic. La CLI instala el recolector, crea el usuario de base de datos de monitoreo y configura el recolector en un solo comando.

<Callout variant="tip" title="Instalación guiada">
  Para instalar a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)** </DNT>. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.
    * Oracle Database 19c o posterior.
    * Para Oracle autohospedado: Oracle Linux 7, 8 o 9, con `curl` y `systemd` instalados, y acceso SSH (con reenvío de agente) al host de la base de datos de Oracle donde el usuario de SSH pueda ejecutar `sudo su - oracle` sin un símbolo de contraseña.
    * Para Oracle en AWS RDS: un host recolector que ejecute Debian/Ubuntu o CentOS/RHEL/OEL, con `curl` y `systemd` instalados, y conectividad de red desde el host recolector hasta el extremo de RDS Oracle.
    * Para Oracle Autonomous Database (ADB): un host del recolector que ejecute Debian/Ubuntu o CentOS/RHEL/OEL, con `curl`, `systemd` y Oracle Instant Client (`sqlplus`) instalados y en `PATH`; la IP de salida de cada instancia permitida en su lista de control de acceso de ADB; y la Oracle Wallet de cada instancia descargada y descomprimida en su propio directorio en el host del recolector.
  </Step>

  <Step>
    ## Instalar y configurar el NRDOT Collector [#install]

    <CollapserGroup>
      <Collapser id="cli-host" title="Base de datos Oracle autohospedada">
        Esta receta monitorea una o más instancias de Oracle Database (cada una accesible a través de SSH) desde un solo recolector. En lugar de solicitar un solo conjunto de host/contenedor/credenciales, lee un archivo de instancias (YAML) que enumera cada instancia a monitorear y, opcionalmente, un archivo de secretos para fijar contraseñas específicas del usuario de monitoreo en lugar de generarlas automáticamente.

        Antes de ejecutar este comando, tenga preparado:

        * Acceso SSH (con reenvío de agente) a cada host de la base de datos de Oracle enumerado, donde cada `ssh_user` pueda ejecutar `sudo su - oracle` sin un símbolo de contraseña
        * Tipo de contenedor por instancia (CDB para todas las PDB o un único nombre de PDB)
        * Nombre del servicio de CDB o PDB por instancia
        * Si desea métricas básicas o avanzadas

        1. Cree el archivo de instancias. Agregue una entrada por cada instancia de base de datos de Oracle que desee que este recolector monitoree; solo una entrada si únicamente realiza el monitoreo de una sola instancia:

           ```bash
           cat > ~/oracle-instances.yml << 'EOF'
           instances:
             - host: dbhost1.example.com
               port: 1521
               ssh_user: opc
               container_type: 1
               pdb_name:
               service: ORCLCDB
               login_name: newrelic
           EOF
           ```

           `container_type` es `1` para CDB (monitorea todas las PDB, crea un usuario `c##<login_name>` común) o `2` para una única PDB (solo entonces se requiere `pdb_name`). Ingrese `login_name` sin el prefijo `c##`: la receta lo agrega en el modo CDB.

        2. (Opcional) Cree un archivo de secretos para establecer una contraseña de usuario de monitoreo fija por instancia en lugar de dejar que la receta genere una automáticamente. Oracle autohospedado no necesita credenciales de administrador aquí. El usuario de monitoreo se crea a través de SSH y acceso SYSDBA autenticado por el sistema operativo:

           ```bash
           umask 077
           cat > ~/oracle-secrets.env << 'EOF'
           NR_CLI_ORACLE_LOGIN_PASSWORD_1=SomeFixedPassword1
           EOF
           chmod 600 ~/oracle-secrets.env
           ```

           Deje en blanco la ruta del archivo de secretos (o apúntela a un archivo que no exista) para generar automáticamente una contraseña aleatoria para cada instancia en su lugar.

        Ejecute esto desde un host con acceso SSH (con reenvío de agente) a cada host de Oracle Database enumerado en el archivo de instancias:

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle
        ```

      <Collapser id="cli-rds" title="Oracle Database en AWS RDS">
        Esta receta monitorea uno o más extremos de RDS Oracle desde un solo recolector, usando un archivo de instancias y un archivo de secretos.

        Antes de ejecutar este comando, tenga preparado:

        * Extremo de Oracle RDS, puerto de escucha y nombre del servicio de base de datos para cada instancia
        * Nombre de usuario maestro y contraseña de RDS para cada instancia
        * Si desea métricas básicas o avanzadas

        1. Cree el archivo de instancia (una entrada por cada extremo de RDS Oracle que desee que este recolector monitoree, sigue siendo solo una entrada si solo monitorea una única instancia):

           ```bash
           cat > ~/oracle-instances.yml << 'EOF'
           instances:
             - host: rds-orders.abcdef123.us-east-1.rds.amazonaws.com
               port: 1521
               service: ORDERSDB
               login_name: newrelic
           EOF
           ```

        2. Cree el archivo de secretos con el nombre de usuario y la contraseña maestros de RDS para cada instancia, indexado para que coincida con el orden del archivo de instancias. También puede establecer opcionalmente una contraseña fija de usuario de monitoreo por instancia. Omítalo para generar una automáticamente:

           ```bash
           umask 077
           cat > ~/oracle-secrets.env << 'EOF'
           NR_CLI_ORACLE_ADMIN_USER_1=admin
           NR_CLI_ORACLE_ADMIN_PASSWORD_1=YourMasterPassword1
           EOF
           chmod 600 ~/oracle-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle-rds
        ```

      <Collapser id="cli-adb" title="Base de datos autónoma de Oracle (ADB)">
        Esta receta monitorea una o más instancias de Oracle Autonomous Database (ADB) desde un único recolector, utilizando un archivo de instancias y un archivo de secretos. Cada instancia se conecta a través de TLS mutuo (el valor predeterminado de ADB) utilizando su propia wallet descargada. No comparta un directorio de wallet entre instancias.

        Antes de ejecutar este comando, tenga preparado:

        * Para cada instancia: la cadena de conexión (`host`, `port`, `service`, desde **Database connection &gt; Connection strings** de la consola de ADB)
        * Para cada instancia: la Oracle Wallet descargada (**Database connection &gt; Download wallet** de la consola de ADB), descomprimida en su propio directorio en el host del recolector
        * Nombre de usuario y contraseña del administrador de ADB (`ADMIN`) para cada instancia

        1. Cree el archivo de instancias. Agregue una entrada por cada instancia de ADB que desee que este recolector monitoree; solo una entrada si solo está monitoreando una sola instancia:

           ```bash
           cat > ~/adb-instances.yml << 'EOF'
           instances:
             - host: adb1.adb.us-ashburn-1.oraclecloud.com
               port: 1522
               service: myadb1_high
               login_name: newrelic
               wallet_dir: /home/opc/wallet1
           EOF
           ```

           `wallet_dir` es el directorio donde se descomprimió la billetera de esa instancia (debe contener `cwallet.sso` y `sqlnet.ora`); una instancia con un directorio de billetera faltante o no válido se omite en lugar de hacer que falle toda la instalación.

        2. Cree el archivo de secretos con el nombre de usuario y la contraseña de administrador de ADB para cada instancia, indexado para que coincida con el orden del archivo de instancias. Opcionalmente, también puede fijar una contraseña fija para el usuario de monitoreo por instancia. Omítalo para generar una automáticamente:

           ```bash
           umask 077
           cat > ~/adb-secrets.env << 'EOF'
           NR_CLI_ORACLE_ADMIN_USER_1=ADMIN
           NR_CLI_ORACLE_ADMIN_PASSWORD_1=YourAdminPassword1
           EOF
           chmod 600 ~/adb-secrets.env
           ```

        Ejecute esto desde un host que tenga `sqlplus` (Oracle Instant Client) en `PATH` y conectividad de red (mTLS) a cada instancia de ADB enumerada:

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle-adb
        ```
