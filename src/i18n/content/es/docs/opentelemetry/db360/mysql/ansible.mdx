Puede instalar y configurar el Collector de NRDOT para el monitoreo de MySQL mediante el rol de Ansible `newrelic.newrelic_install`. El rol instala el recolector, crea el usuario de monitoreo y configura el recolector en una sola ejecución.

<Callout variant="tip" title="Instalación guiada">
  Para instalar a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.
    * MySQL 5.7 o posterior.
    * Ansible Core 2.13 o 2.14, Python 3.10 y las colecciones `ansible.windows` y `ansible.utils`.
    * Un host recolector de Linux que ejecuta Debian/Ubuntu o RHEL/CentOS.
    * Para MySQL autohospedado: acceso administrativo al servidor de MySQL (la cuenta `root` o equivalente), mediante autenticación basada en contraseña.
    * Para MySQL o Aurora en AWS RDS: conectividad de red desde el host del recolector hasta el extremo de RDS, y el nombre de usuario y la contraseña maestros de RDS.
    * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para su región.

    Para obtener información detallada sobre los requisitos, consulte [Compatibilidad y requisitos previos](/docs/opentelemetry/db360/mysql/compatibility).
  </Step>

  <Step>
    ## Instale el rol [#ansible-install-role]

    ```bash
    ansible-galaxy install newrelic.newrelic_install
    ```

    Asegúrese de que las colecciones requeridas también estén instaladas:

    ```bash
    ansible-galaxy collection install ansible.windows ansible.utils
    ```
  </Step>

  <Step>
    ## Configure el playbook [#ansible-configure]

    <CollapserGroup>
      <Collapser id="ansible-host" title="MySQL autohospedado">
        Este rol monitorea una o más instancias de MySQL desde un solo recolector. En lugar de un solo conjunto de host/puerto/credenciales, lee dos archivos que ya deben existir en el host objetivo: un archivo de instancias (YAML) que enumera cada instancia a monitorear y un archivo de secretos (`KEY=VALUE`) con un inicio de sesión y contraseña de administrador para cada una, indexados para que coincidan. Consulte la página de [instalación de la CLI](/docs/opentelemetry/db360/mysql/cli/#cli-install) para conocer los formatos de archivo exactos.

        Cree un archivo denominado `playbook.yml` y copie el siguiente contenido en él. Establezca `targets` en `mysql-otel` y reemplace los valores del marcador de posición por los suyos:

        ```yaml
        - name: Install New Relic NRDOT for MySQL
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mysql-otel
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MYSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MYSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_MYSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
        ```

        <Callout variant="important">
          El rol se conecta a MySQL a través de TCP mediante una contraseña, por lo que la cuenta de administrador en el archivo de secretos debe usar autenticación basada en contraseña. En algunas instalaciones de Debian/Ubuntu, `root`@`localhost` usa por defecto el plug-in `auth_socket` (sin contraseña, solo socket local), lo cual no funcionará aquí. Cámbielo antes de ejecutar el playbook:

          ```bash
          mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '<password>';"
          ```
        </Callout>

        <Callout variant="tip">
          Para habilitar el logging de depuración, agregue `verbosity: "debug"` debajo de `vars` en el playbook.
        </Callout>

      <Collapser id="ansible-rds" title="MySQL o Aurora en AWS RDS">
        Este rol monitorea uno o más extremos de RDS MySQL o Aurora desde un único recolector, utilizando el mismo patrón de archivo de instancias/archivo de secretos que el autohospedado (ambos archivos ya deben existir en el host objetivo). Cree un archivo denominado `playbook.yml` y copie el siguiente contenido en él. Establezca `targets` en `mysql-otel-rds` y reemplace los valores del marcador de posición por los suyos:

        ```yaml
        - name: Install New Relic NRDOT for MySQL on RDS
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mysql-otel-rds
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MYSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MYSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
            NR_CLI_MYSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
        ```

        <Callout variant="tip">
          Para habilitar el logging de depuración, agregue `verbosity: "debug"` debajo de `vars` en el playbook.

  <Step>
    ## Ejecute el playbook [#ansible-run]

    ```bash
    ansible-playbook -i <inventory_file> <playbook_file>.yml
    ```
  </Step>

  <Step>
    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos MySQL a través de la UI de New Relic.

    Para encontrar su entidad de base de datos MySQL en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MySQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.
    3. Seleccione su base de datos MySQL de la lista de entidades.
  </Step>
