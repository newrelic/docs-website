Puede usar el OpenTelemetry Collector Contrib para MySQL para monitorear la instancia. El OpenTelemetry Collector Contrib es un proyecto respaldado por la comunidad que recopila telemetry data de MySQL y lo envía a New Relic.

De forma predeterminada, el OpenTelemetry Collector Contrib recopila métricas limitadas de MySQL. Para enviar las métricas de rendimiento de consultas, eventos de espera, sesiones y clientes, deberá configurar el OpenTelemetry Collector Contrib. Esta guía le muestra cómo configurarlo para recopilar métricas avanzadas de MySQL y enviarlas a New Relic.

<Callout variant="tip" title="Nota">
Esta página abarca el `mysqlreceiver` de la comunidad incluido en el binario `otelcol-contrib` estándar. Si utiliza la distribución de New Relic (NRDOT), consulte [MySQL autohospedado](/docs/opentelemetry/db360/mysql/introduction) en su lugar.
</Callout>

<Steps>
<Step>
## Requisitos previos [#prerequisites]

* OpenTelemetry Collector Contrib (`otelcol-contrib`) instalado y configurado en su sistema. Puede descargar la versión más reciente desde la página de [lanzamientos de OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).
* `performance_schema` habilitado en la instancia de MySQL/MariaDB monitoreada (activado de forma predeterminada desde MySQL 5.6.6).
</Step>

<Step>
## Habilite las métricas de la UI [#enable]

Puede enriquecer la experiencia en la plataforma de New Relic al agregar y habilitar métricas en el archivo de configuración `otelcol-contrib`. Con la configuración proporcionada en esta sección, puede completar datos para las siguientes páginas en la plataforma de New Relic:

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Habilitar métricas de la página Overview">
La página <DNT>Overview</DNT> muestra una vista general de la instancia de MySQL, incluidas métricas clave como conexiones, estado del grupo de búferes, I/O, bloqueos, tamaño de tabla y tasa de consultas lentas. `mysql.commands` y `mysql.innodb.data_file.io` además potencian el enlace APM-DB, la navegación cruzada entre la traza de un servicio de APM y su actividad de consulta de MySQL.

Para poblar los datos de la página <DNT>Overview</DNT> en la plataforma de New Relic, agregue la siguiente configuración al archivo de configuración `otelcol-contrib`:

```yaml
receivers:
  mysql:
    metrics:
      mysql.query.count:
        enabled: true
      mysql.query.slow.count:
        enabled: true
      mysql.table.size:
        enabled: true
      mysql.commands:
        enabled: true
      mysql.innodb.data_file.io:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="Habilitar métricas de rendimiento de consulta, sesión, espera y cliente">
Para completar los datos de las páginas <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT> y <DNT>Clients</DNT>:

* Rendimiento de consultas: muestra información detallada sobre las consultas que se ejecutan en la instancia de MySQL en las siguientes pestañas:

  * Consultas normalizadas: muestra la cantidad de ejecuciones y la duración promedio por consulta.
  * Muestras de consultas: muestra ejecuciones individuales de consultas, incluida la duración, el tipo de espera, la base de datos, el usuario de BD y el host del cliente.

* Eventos de espera: muestra el tipo de espera y el tiempo de espera de las sentencias que estaban en espera al momento del muestreo.

* Sesiones: muestra información sobre las sesiones conectadas a la instancia de MySQL, incluidos los recuentos de sesiones, el estado de las sesiones y los detalles de las sesiones individuales.

* Clientes: muestra información sobre los clientes conectados a la instancia de MySQL, incluidos los usuarios de BD conectados y los detalles del host del cliente.

Agregue la siguiente configuración al archivo de configuración de `otelcol-contrib`:

```yaml
receivers:
  mysql:
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      lookback_time: 60
      max_query_sample_count: 1000
      top_query_count: 250
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 100
```

<Callout variant="important">
`db.server.query_plan` requiere que al menos `db.server.top_query` o `db.server.query_sample` también esté habilitado. Habilitarlo por sí solo es un error de validación de configuración.
</Callout>

<Callout variant="tip" title="Nota">
El receptor de MySQL de la comunidad no admite la recopilación de procedimientos almacenados ni la detección de sesiones bloqueadas. Sesiones y Clientes se completan, pero no se muestra el bloqueador de una sesión bloqueada.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## Reiniciar el OpenTelemetry Collector [#restart]

Reinicie el OpenTelemetry Collector para aplicar los cambios de configuración ejecutando el siguiente comando:

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
