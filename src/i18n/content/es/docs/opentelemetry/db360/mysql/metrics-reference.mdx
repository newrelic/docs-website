Monitoree el rendimiento de la base de datos MySQL con métricas exhaustivas recopiladas por el Collector NRDOT. De forma predeterminada, New Relic recopila las métricas y los eventos a nivel de consulta a los que se hace referencia en la sección [Métricas y eventos predeterminados](#default). Puede mejorar el monitoreo habilitando las métricas deseadas que se enumeran en la sección [Métricas de características completas](#full-feature).

### Consulta evento [#query-events]

Los siguientes eventos se recopilan como registros de log de OpenTelemetry y están habilitados de forma predeterminada. Proporcionan visibilidad a nivel de consulta.

<CollapserGroup>
<Collapser id="query-sample" title="Muestras de consulta">
Visibilidad en tiempo real de las sentencias de la base de datos actualmente en ejecución: una instantánea de un momento dado tomada en cada recopilación, no un log de ejecución completo. Este evento está habilitado de forma predeterminada.

Utilice el bloque `query_sample_collection` para ajustar su comportamiento:

```yaml
query_sample_collection:
  max_rows_per_query: 100
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="top-query" title="Consultas principales">
Las consultas que consumen más tiempo de ejecución, agregadas del lado del servidor por el propio `performance_schema.events_statements_summary_by_digest` de MySQL: un verdadero contador de ejecución por resumen, no un recuento de muestras. Este evento está habilitado de forma predeterminada.

Utilice el bloque `top_query_collection` para ajustar su comportamiento:

```yaml
top_query_collection:
  lookback_time: 60
  max_query_sample_count: 5000
  top_query_count: 200
  collection_interval: 60s
  query_plan_cache_size: 1000
  query_plan_cache_ttl: 1h
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="query-plan" title="Planes de consulta">
Plan de ejecución para una sentencia, reportado como su propio evento para que el plan pueda ser filtrado, enrutado o descartado independientemente de las estadísticas propias de `top_query`/`query_sample`. Requiere que al menos uno de `db.server.top_query` o `db.server.query_sample` también esté habilitado. Una vez habilitado, `mysql.query_plan` ya no se incluye en los registros de `db.server.top_query`/`db.server.query_sample`. Consulte [Recopilación del plan de ejecución](#explain) para conocer la mecánica de `EXPLAIN`. Este evento está habilitado de forma predeterminada.

<Collapser id="explain" title="Recopilación del plan de ejecución">

`mysql.query_plan` es la salida `EXPLAIN FORMAT=json` sin procesar, envuelta en una matriz JSON de un elemento antes del almacenamiento en caché, para que la ingesta de logs de New Relic no la aplane automáticamente y la destruya. Analice el índice `[0]` para recuperar el objeto del plan.
