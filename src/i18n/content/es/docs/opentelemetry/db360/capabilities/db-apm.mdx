Obtenga una correlación perfecta entre sus aplicaciones y el rendimiento de la base de datos con los comentarios de consultas SQL. Este mecanismo permite que el receptor de base de datos de la Distribución de OpenTelemetry de New Relic (NRDOT) identifique exactamente qué servicio es responsable de la carga específica de la base de datos, las consultas lentas o los eventos de bloqueo.

<Callout variant="important">
  New Relic vincula el monitoreo del rendimiento de aplicaciones (APM) de New Relic (New Relic APM) y las entidades de base de datos al hacer coincidir la dirección y el puerto de conexión de base de datos de la aplicación con la dirección y el puerto de conexión del agente de monitoreo de base de datos. Esta vinculación funciona de manera confiable cuando ambos lados reportan exactamente la misma dirección y puerto. Sin embargo, la vinculación automática puede fallar si la aplicación enruta el tráfico a través de un balanceador de carga o proxy, o si los dos componentes usan formatos de dirección diferentes (como una dirección IP frente a un nombre de dominio).
</Callout>

## Requisitos previos [#prerequisites]

* Agente de Java: versión `9.1.0` o posterior.
* Agente .NET: versión `10.52.0` o posterior.

### Habilitar la correlación APM-DB para el agente Java [#enable-correlation-java]

Para habilitar esta correlación, agregue la propiedad `sql_metadata_comments` a la sección `transaction_tracer` de su archivo de configuración del agente de Java (`newrelic.yml`). Para obtener más información, consulte la [documentación de configuración del agente de Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/).

```yaml
transaction_tracer:
  sql_metadata_comments: nr_service_guid
```

### Habilitar la correlación APM-DB para el agente .NET [#enable-correlation-dotnet]

Para habilitar esta correlación, agregue la propiedad `sqlMetadataComments` a la sección `transactionTracer` de su archivo de configuración del agente .NET (`newrelic.config`). Para obtener más información, consulte la [documentación de configuración del agente .NET](/docs/apm/agents/net-agent/configuration/net-agent-configuration/).

<CollapserGroup>
  <Collapser id="option1" title="Opción 1: mediante variables de entorno (script)">
    Si utiliza un script de inicio o contenedor para el lanzamiento del ejecutable, establezca la variable `NEW_RELIC_TRANSACTION_TRACER_SQL_METADATA_COMMENTS_ENABLED` en `1`.

    ```powershell
    # Add this environment variable alongside your other CoreCLR / New Relic variables
    $env:NEW_RELIC_TRANSACTION_TRACER_SQL_METADATA_COMMENTS_ENABLED = "1"
    ```
  </Collapser>

  <Collapser id="option2" title="Opción 2: vía newrelic.config">
    Como alternativa, puede habilitarlo directamente dentro del bloque `<transactionTracer>` del archivo `newrelic.config`:

    ```xml
    <transactionTracer enabled="true" sqlMetadataCommentsEnabled="true" />
    ```
  </Collapser>
</CollapserGroup>

## Cómo funciona [#how-it-works]

Cuando su aplicación envía una consulta a la base de datos, el agente de APM antepone automáticamente un GUID de entidad de APM en el texto SQL como un comentario. Esta práctica común de la industria no afecta la lógica de ejecución de sus sentencias SQL.

1. **Anteposición de comentarios**: El agente de APM antepone una cadena de comentarios al SQL saliente (por ejemplo, `/* nr_service_guid="MTE2MDAzMTl8QVBNfEFQUExJ" */ SELECT * FROM orders...`).
2. **Ejecución**: La base de datos ejecuta la consulta como de costumbre. El comentario se almacena en los esquemas de rendimiento internos de la base de datos (como `sys.dm_exec_requests` o `v$session`).
3. **Extracción**: El receptor de la base de datos recupera estas consultas (activas, lentas o de bloqueo).
4. **Enriquecimiento**: El receptor analiza el comentario, extrae el `nr_service_guid` y lo adjunta como una dimensión a sus métricas de base de datos.

## Beneficios del etiquetado de servicios [#benefits]

Anteponer metadatos del servicio le brinda visibilidad de alta fidelidad en su ecosistema de bases de datos:

* **Atribución a nivel de servicio**: Vea al instante qué microservicio es responsable de un pico en la CPU o la memoria de la base de datos
* **Análisis refinado de consultas lentas**: filtre los logs de consultas lentas por `client_name` para entender si un cuello de botella en la base de datos se limita a una versión específica de la aplicación
* **Resolución de bloqueos e interbloqueos**: Identifique rápidamente al &quot;propietario&quot; de una consulta de bloqueo para agilizar la solución de problemas entre equipos

## Gestión de secretos [#secret-management]

Puede utilizar dos métodos seguros para gestionar credenciales confidenciales (como contraseñas de bases de datos) en la configuración de NRDOT Collector. Elija el método que mejor se alinee con su infraestructura y políticas de seguridad.

<CollapserGroup>
  <Collapser id="aes" title="Cifrado AES (agnóstico de plataforma)">
    ### Cifrado AES (agnóstico de plataforma) [#aes-encryption]

    Este método le permite almacenar credenciales cifradas directamente en sus archivos de configuración, admitiendo flujos de trabajo de control de versiones (GitOps).

    * **Cómo funciona**: Las cadenas confidenciales se cifran mediante AES-256 (modo GCM) fuera de línea. El colector los descifra en tiempo de ejecución usando una clave maestra almacenada en las variables de entorno del servidor
    * **Beneficio de seguridad**: Los archivos de configuración se pueden compartir de forma segura o confirmar en repositorios sin exponer contraseñas en texto plano
    * **Ideal para**: Entornos híbridos/multinube, desarrollo local o servidores Windows donde la integración con OCI Vault no es factible

    #### Configuración de ejemplo

    ```yaml
    receivers:
      newrelicoracledb/cdb:
        endpoint: "10.x.x.36:1521"
        # Credentials are encrypted using the offline helper tool
        username: "${aes:YOUR_ENCRYPTED_USERNAME_STRING}"
        password: "${aes:YOUR_ENCRYPTED_PASSWORD_STRING}"
        service: "DB1104.privatesubnet.oracledb.oraclevcn.com"
        collection_interval: 15s
    ```
  </Collapser>

  <Collapser id="aws" title="Administrador de secretos de AWS">
    ### Administrador de secretos de AWS [#aws-secrets-manager]

    Este método le permite recuperar credenciales de forma segura directamente desde AWS Secrets Manager en tiempo de ejecución, eliminando por completo la necesidad de almacenar contraseñas en sus archivos de configuración.

    * **Cómo funciona**: El NRDOT Collector utiliza un rol de AWS IAM para autenticarse automáticamente y obtener los secretos necesarios de AWS Secrets Manager durante el inicio
    * **Beneficio de seguridad**: No se almacenan datos sensibles en el disco ni en el control de versiones. El acceso se rige estrictamente por las políticas de AWS IAM y las credenciales de la base de datos se pueden rotar de forma centralizada sin necesidad de actualizar o desplegar nuevos archivos de configuración.
    * **Ideal para**: Entornos de producción que se ejecutan de forma nativa en AWS donde se requiere gestión centralizada de secretos, auditoría de cumplimiento y rotación automatizada

    #### Configuración de ejemplo

    ```yaml
    receivers:
      newrelicoracledb/pdb:
        endpoint: "10.x.x.36:1521"
        # Syntax: ${secretsmanager:SecretName#JSONKey}
        username: "${secretsmanager:oracle/credentials#username}"
        password: "${secretsmanager:oracle/credentials#password}"
        service: "PDBTEST"
    ```

    **Nota**: Establezca la Región de AWS:

    ```bash
    export AWS_REGION=your-aws-region
    ```
  </Collapser>
</CollapserGroup>
