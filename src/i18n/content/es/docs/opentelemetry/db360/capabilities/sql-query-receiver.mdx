El `sqlqueryreceiver` es un receptor de OpenTelemetry Collector que permite ejecutar cualquier consulta SQL personalizada en la base de datos e ingerir los resultados como métricas en New Relic.

Úselo cuando desee monitorear datos que no estén cubiertos por las métricas integradas de `nroracledbreceiver` / `nrsqlserverreceiver` / `nrmysqlreceiver` / `nrpostgresqlreceiver`. Las métricas personalizadas recopiladas mediante `sqlqueryreceiver` aparecen bajo la misma entidad de Oracle, SQL Server, MySQL o PostgreSQL en New Relic que los datos del receptor integrado, siempre que los atributos de vinculación de entidades estén configurados correctamente.

## Requisitos previos [#prerequisites]

* El usuario de la base de datos configurado en la fuente de datos debe tener el privilegio `SELECT` en cualquier vista o tabla que pretenda consultar.
* El binario del recolector debe incluir el componente `sqlqueryreceiver`.

      Agregue el bloque `sqlqueryreceiver` dentro de la sección `receivers:` de `oracle-config.yaml` existente, junto al bloque `nroracledb` existente:

      ```yaml
      receivers:
        nroracledb:

        ...

        sqlquery/oracle:
          driver: oracle

          # Approach 1: Use the `host`, `port`, `database`, `username`, and `password` fields to connect to your database. The receiver will construct the datasource URL for you.
          # host: <YOUR_DB_HOST>
          # port: <YOUR_DB_PORT>
          # database: <YOUR_DATABASE_NAME>
          # username: <YOUR_DB_USERNAME>
          # password: <YOUR_DB_PASSWORD>


          # Approach 2: Use the `datasource` field to provide a full connection string. 
          datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"

          collection_interval: 60s
          queries:
            - sql: "<YOUR_CUSTOM_SQL>"
              metrics:
                - metric_name: oracledb.<YOUR_METRIC_NAME>

                  attribute_columns: [<DIMENSION_COLUMN_1>, <DIMENSION_COLUMN_2>]
      ```

      ### Convención de nomenclatura

      Los nombres de las métricas deben comenzar con `oracledb.` para asociarse con la entidad correcta en New Relic. Las métricas con un prefijo diferente se ingerirán, pero no aparecerán bajo la entidad de la base de datos.

      ### Síntesis de entidad

      Agregue los procesadores `resource/add_event_name` y `resource/add_host` para establecer `server.address` y `server.port` en los mismos valores utilizados por el receptor de la base de datos. Sin esto, las métricas personalizadas no se vincularán a la entidad de la base de datos.

      Agregue los procesadores en la sección `processors:`:

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Configuración del Pipeline

      Agregue un pipeline `metrics/custom` en la sección `service.pipelines:` de la configuración, junto a los pipelines existentes:

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_event_name, resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        Agregue tanto `resource/add_event_name` como `resource/add_host` antes de `batch` en la lista de procesadores.
      </Callout>

      ### NRQL para validar datos

      Después de reiniciar el recolector, ejecute lo siguiente para confirmar que están llegando las métricas personalizadas:

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      ## Resolución de problemas [#troubleshooting]

      | Problema                                               | Causa                                                        | Arreglar                                                                                           |
      | ------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
      | `ORA-00942: table or view does not exist`              | Al usuario de la base de datos le falta el privilegio SELECT | Otorgue `SELECT ON <VIEW_NAME>` al usuario                                                         |
      | `missing port in address`                              | `#` en nombre de usuario/contraseña no codificados en URL    | Reemplace `#` con `%23` en la URL de la fuente de datos                                            |
      | No hay datos en New Relic                              | `server.address`/`server.port` no establecido o no coincide  | Agregue los procesadores `resource/add_event_name` y `resource/add_host` con los valores correctos |
      | Métricas que no están bajo la entidad de base de datos | Nombre de la métrica sin el prefijo requerido                | Asegúrese de que los nombres de las métricas comiencen con `oracledb.`                             |

      Si nada de lo anterior resuelve el problema, revise los logs del propio recolector en busca de errores:

      ```bash
      sudo journalctl -u nrdot-collector -f
      ```

      ### Convención de nomenclatura

      Los nombres de las métricas deben comenzar con `postgresql.` para asociarse con la entidad correcta en New Relic. Las métricas con un prefijo diferente se ingerirán, pero no aparecerán bajo la entidad de la base de datos.

      ### Síntesis de entidad

      `nrpostgresql` sintetiza su entidad de base de datos a partir de `server.address` y `server.port`. Agregue un procesador `resource/add_host` para marcar los mismos valores `server.address`/`server.port` que usa el receptor de la base de datos. Sin esto, las métricas personalizadas no se vincularán a la entidad de base de datos.

      Agregue el procesador en la sección `processors:`:

      ```yaml
      processors:
        batch:
        resource/add_host:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      <Callout variant="important">
        Si su pipeline `nrpostgresql` ya tiene un procesador `resource/*` que establece `server.address`/`server.port` (por ejemplo, `resource/postgresql`), reutilice ese mismo procesador en el pipeline `metrics/custom` a continuación en lugar de duplicarlo —ambos receptores deben asignar valores idénticos para asociarse a la misma entidad.
      </Callout>

      ### Configuración del Pipeline

      Agregue un pipeline `metrics/custom` en la sección `service.pipelines:` de la configuración, junto a los pipelines existentes:

      ```yaml
      service:
        pipelines:
          metrics/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          logs/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          metrics/custom:
            receivers: [sql_query/postgres]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        Agregue `resource/add_host` antes de `batch` en la lista de procesadores.
      </Callout>

      ### NRQL para validar datos

      Después de reiniciar el recolector, ejecute lo siguiente para confirmar que están llegando las métricas personalizadas:

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'postgresql.%'
      SINCE 1 hour ago
      ```

      ## Resolución de problemas [#troubleshooting-postgresql]

      | Problema                                               | Causa                                                                                                                                      | Arreglar                                                                                                                                                                                                         |
      | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
      | `pq: SSL is not enabled on the server`                 | `sslmode` no establecido, el controlador usó de forma predeterminada la negociación de SSL                                                 | Establezca `sslmode: disable` (o el modo que admita su servidor) en `additional_params` o en la cadena `datasource`                                                                                              |
      | `pq: password authentication failed for user`          | Nombre de usuario/contraseña incorrectos, o caracteres especiales no escapados en una cadena `datasource` sin procesar                     | Use el Enfoque 1 (campos individuales) —el receptor escapa `username`/`password` para URL automáticamente— o escape manualmente los caracteres especiales en `datasource`                                        |
      | Métricas que no están bajo la entidad de base de datos | Falta el prefijo `postgresql.` requerido en el nombre de la métrica, o `server.address`/`server.port` no están configurados o no coinciden | Asegúrese de que los nombres de las métricas comiencen con `postgresql.` y agregue `resource/add_host` (o reutilice el procesador de recursos `nrpostgresql` existente) con los valores correctos de host/puerto |
