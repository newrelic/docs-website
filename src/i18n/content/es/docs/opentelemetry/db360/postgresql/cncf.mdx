Puede usar el OpenTelemetry Collector Contrib para PostgreSQL para monitorear la instancia. El OpenTelemetry Collector Contrib es un proyecto respaldado por la comunidad que recopila telemetry data de PostgreSQL y lo envía a New Relic.

Por defecto, el OpenTelemetry Collector Contrib recopila métricas limitadas de PostgreSQL. Para enviar las métricas de rendimiento de consultas, eventos de espera, sesiones y clientes, deberá configurar el OpenTelemetry Collector Contrib. Esta guía le muestra cómo configurarlo para recopilar métricas avanzadas de PostgreSQL y enviarlas a New Relic.

<Callout variant="tip" title="Nota">
Esta página trata sobre el receptor `postgresql` de la comunidad incluido en el binario `otelcol-contrib` estándar. Si utiliza la distribución de New Relic (NRDOT), consulte [Introducción al monitoreo de PostgreSQL](/docs/opentelemetry/db360/postgresql/introduction) en su lugar.
</Callout>

<Steps>
<Step>
## Requisitos previos [#prerequisites]

* OpenTelemetry Collector Contrib (`otelcol-contrib`) instalado y configurado en su sistema. Puede descargar la versión más reciente desde la página de [lanzamientos de OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).

* `pg_stat_statements` habilitado a través de `shared_preload_libraries` en la instancia de PostgreSQL monitoreada. Esto es necesario para los datos de rendimiento de consultas, eventos de espera, sesiones y clientes. Consulte [Parámetros de servidor recomendados](/docs/opentelemetry/db360/postgresql/compatibility#params).

* El recolector se inició en modo de convención semántica utilizando la puerta de característica `receiver.postgresql.useOTelSemconv`.

  Si ejecuta `otelcol-contrib` como paquete RPM/Debian (servicio de systemd), el archivo de servicio importa las variables de entorno a través de `EnvironmentFile=/etc/otelcol-contrib/otelcol-contrib.conf`. En ese archivo, agregue el indicador a `OTELCOL_OPTIONS`:

  ```bash
  OTELCOL_OPTIONS="--config=/etc/otelcol-contrib/config.yaml --feature-gates=receiver.postgresql.useOTelSemconv"
  ```

  Después de guardar el archivo, reinicie el servicio para aplicar la puerta:

  ```bash
  sudo systemctl restart otelcol-contrib
  ```
</Step>

<Step>
## Habilite las métricas de la UI [#enable]

Puede enriquecer la experiencia en la plataforma de New Relic al agregar y habilitar métricas en el archivo de configuración `otelcol-contrib`. Con la configuración proporcionada en esta sección, puede completar datos para las siguientes páginas en la plataforma de New Relic:

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Habilitar métricas de la página Overview">
La página <DNT>Overview</DNT> muestra una vista de alto nivel de la instancia de PostgreSQL, incluidas métricas clave como bloqueos de base de datos, interbloqueos, llamadas a funciones, conflictos de consultas, escaneos secuenciales y uso de archivos temporales/E/S.

Para poblar los datos de la página <DNT>Overview</DNT> en la plataforma de New Relic, agregue la siguiente configuración al archivo de configuración `otelcol-contrib`:

```yaml
receivers:
  postgresql:
    metrics:
      postgresql.database.locks:
        enabled: true
      postgresql.deadlocks:
        enabled: true
      postgresql.function.calls:
        enabled: true
      postgresql.query.conflicts:
        enabled: true
      postgresql.sequential_scans:
        enabled: true
      postgresql.temp.io:
        enabled: true
      postgresql.temp_files:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="Habilitar métricas de rendimiento de consulta, sesión, espera y cliente">
Para completar los datos de las páginas <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT> y <DNT>Clients</DNT>:

* Rendimiento de consultas: muestra información detallada sobre las consultas que se ejecutan en la instancia de PostgreSQL en las siguientes pestañas:

  * Consultas normalizadas: muestra gráficos de ejecución y de tiempo promedio de CPU.
  * Muestras de consultas: muestra ejecuciones individuales de consultas, incluidas la hora de inicio, la duración, el tipo de espera, el tiempo de espera, la base de datos, el usuario de base de datos y el host del cliente.

* Eventos de espera: muestra información sobre los eventos de espera que ocurren en la instancia de PostgreSQL. La vista de muestras de consultas muestra las consultas que están en espera actualmente, junto con su tipo de espera y tiempo de espera.

* Sesiones: visualiza las tendencias de las conexiones de base de datos activas frente a las inactivas, la duración promedio de las sesiones, las sesiones bloqueadas y el uso por aplicación y proceso, para rastrear los picos de carga y los cuellos de botella de las conexiones.

* Clientes: muestra información sobre los clientes conectados a la instancia de PostgreSQL, incluidas las sesiones activas, las sesiones bloqueadas, los usuarios de base de datos conectados y los detalles del host del cliente.

Agregue la siguiente configuración al archivo de configuración de `otelcol-contrib`:

```yaml
receivers:
  postgresql:
    events:
      db.server.top_query:
        enabled: true
      db.server.query_sample:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      max_rows_per_query: 1000
      top_n_query: 200
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 1000
```

<Callout variant="important">
`db.server.query_plan` requiere que al menos `db.server.top_query` o `db.server.query_sample` también esté habilitado. Habilitarlo por sí solo es un error de validación de configuración.
</Callout>

<Callout variant="tip" title="Nota">
`postgresql.session.duration` no está disponible en el receptor `postgresql` de la comunidad, por lo que la tabla de Sesiones no se muestra en la página de Sesiones.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## Reiniciar el OpenTelemetry Collector [#restart]

Reinicie el OpenTelemetry Collector para aplicar los cambios de configuración:

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
