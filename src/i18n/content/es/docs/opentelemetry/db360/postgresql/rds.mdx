Configure el monitoreo de PostgreSQL mediante el NRDOT Collector para instancias de AWS RDS PostgreSQL. Los entornos de RDS tienen consideraciones específicas para las extensiones y los grupos de parámetros.

<Callout variant="tip" title="Instalación guiada">
  Para instalar a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    Antes de instalar, asegúrese de tener:

    * PostgreSQL `14` y superior
    * Una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) de New Relic.
    * Conectividad de red entre el host donde instala NRDOT Collector y su instancia de RDS PostgreSQL.
    * Conectividad de red a la [documentación de los extremos OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/)
    * Credenciales del usuario maestro de RDS.

    Para conocer las versiones de PostgreSQL compatibles, los permisos requeridos y los parámetros de servidor recomendados, consulte [Compatibilidad y requisitos previos](/docs/opentelemetry/db360/postgresql/compatibility).
  </Step>

  <Step>
    ## Configurar NRDOT Collector [#setup]

    Instale el NRDOT Collector en un sistema que pueda conectarse a su instancia de RDS:

    <CollapserGroup>
      <Collapser title="Para la arquitectura AMD64" id="amd">
        * Para sistemas Debian/Ubuntu, ejecute:

```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
```

        * Para sistemas RHEL/CentOS/OEL, ejecute:

```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_x86_64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
```
      </Collapser>

      <Collapser title="Para la arquitectura ARM64" id="arm">
        * Para sistemas Debian/Ubuntu, ejecute:

```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
```

        * Para sistemas RHEL/CentOS/OEL, ejecute:

```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_aarch64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
```
      </Collapser>

  <Step>
    ## Configurar el usuario y los permisos de la base de datos [#database-user]

    Cree un usuario de monitoreo con los privilegios necesarios para su instancia de PostgreSQL RDS.

    **Para crear el usuario de monitoreo y los permisos:**

    1. Conéctese a su instancia de RDS como usuario maestro:

```shell
    psql --host=<YOUR_RDS_ENDPOINT> --dbname=postgres --port=5432 --username=<YOUR_MASTER_USERNAME>
```

    2. Cree el usuario de monitoreo:

```sql
    CREATE USER <YOUR_DB_USERNAME> WITH LOGIN PASSWORD '<YOUR_DB_PASSWORD>';
```

    3. Otorgar la membresía del rol de usuario de monitoreo según sea necesario:

    * Si usa PostgreSQL 15 o superior, asigne el rol para heredar privilegios:

```sql
      ALTER ROLE <YOUR_DB_USERNAME> INHERIT;
```

      <Callout variant="tip">
        Si usa PostgreSQL 14, el usuario de monitoreo hereda los privilegios por defecto, por lo que puede omitir este paso.
      </Callout>

    * Cree el siguiente esquema y permisos en cada base de datos que desee monitorear:

```sql
      CREATE SCHEMA IF NOT EXISTS otel;
      GRANT USAGE ON SCHEMA otel TO <YOUR_DB_USERNAME>;
      GRANT USAGE ON SCHEMA public TO <YOUR_DB_USERNAME>;
      GRANT SELECT ON ALL TABLES IN SCHEMA public TO <YOUR_DB_USERNAME>;
      GRANT pg_monitor TO <YOUR_DB_USERNAME>;
      CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

    * (Opcional) Para recopilar métricas de vectores, cree la extensión `pgvector` en cada base de datos:

```sql
      CREATE EXTENSION IF NOT EXISTS vector;
```

      Las funciones de distancia `l1`, `hamming` y `jaccard` requieren la versión `0.7.0` o superior de `pgvector`.

    * (Opcional) Para verificar la conexión y los permisos, ejecute:

```shell
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> --command '\conninfo'
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_database LIMIT 1;" && echo "pg_stat_database OK"
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_activity LIMIT 1;" && echo "pg_stat_activity OK"
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_statements LIMIT 1;" && echo "pg_stat_statements OK"
```

      Si cada comando se completa sin errores, el usuario de monitoreo, el host y el puerto son correctos.
  </Step>

    ## Configurar el Colector NRDOT [#configure-collector]

    Configure el NRDOT Collector con los ajustes específicos de RDS PostgreSQL.

    Esta configuración se centra en el monitoreo esencial de PostgreSQL solo con el receptor `nrpostgresql`.

    </Callout>

```bash
      sudo nano /etc/nrdot-collector/postgresql-config.yaml
```

    ### Parámetro de configuración

    La siguiente tabla describe los parámetros de configuración clave para el receptor `nrpostgresql`:

    | Parámetro                       | Descripción                                                                                                                                                                                                                                                                                     |
    | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_RDS_ENDPOINT>`           | Ingrese el nombre de host del extremo de su instancia RDS.                                                                                                                                                                                                                                      |
    | `<YOUR_DB_PORT>`                | Ingrese el puerto de su base de datos PostgreSQL.                                                                                                                                                                                                                                               |
    | `<YOUR_DB_USERNAME>`            | Ingrese su nombre de usuario de la base de datos.                                                                                                                                                                                                                                               |
    | `<YOUR_DB_PASSWORD>`            | Ingrese la contraseña de su base de datos.                                                                                                                                                                                                                                                      |
    | `<YOUR_DATABASE_NAME>`          | Ingrese el nombre de la base de datos que desea monitorear.                                                                                                                                                                                                                                     |
    | `databases`                     | Lista de bases de datos para las que se recopilan estadísticas. Predeterminado: `[]` (todas las bases de datos que no son plantillas). Solo se aplica a las métricas. Las muestras de consultas y las consultas principales ignoran esta lista y se filtran únicamente por `exclude_databases`. |
    | `exclude_databases`             | Bases de datos excluidas de las estadísticas, muestras de consultas y consultas principales. Predeterminado: `[]`. Utilice esto para las bases de datos internas de servicios administrados (como `rdsadmin`) a las que su usuario de monitoreo no puede acceder.                               |
    | `<YOUR_NEWRELIC_OTLP_ENDPOINT>` | Ingrese el extremo OTLP de New Relic. Para obtener más información, consulte [Extremos OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/).                                                                                                                              |
    | `<YOUR_NEWRELIC_LICENSE_KEY>`   | Ingrese su [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) de New Relic.                                                                                                                                                                                      |
    | `collection_interval`           | Ingrese el intervalo entre los raspados de métricas. Predeterminado: `15s`.                                                                                                                                                                                                                     |

    <Callout variant="tip">
      Tú también puedes:

      [Configurar múltiples receptores](/docs/opentelemetry/db360/postgresql/multi-receiver): para monitorear múltiples instancias de PostgreSQL desde un recolector.
      [Vincule su base de datos PostgreSQL con APM](/docs/opentelemetry/db360/capabilities/db-apm): para correlacionar el rendimiento de la aplicación con las operaciones de la base de datos. Esto le permite ver exactamente qué aplicaciones están generando cargas de trabajo de base de datos específicas.
      [Planes de consulta para sentencias de escritura](/docs/opentelemetry/db360/postgresql/optional#query): para recopilar planes de consulta para sentencias de bloqueo o escritura sin otorgar acceso de escritura al usuario de monitoreo.
      [Configurar la gestión de secretos](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management): para administrar de forma segura información confidencial, como las credenciales de bases de datos. Esto ayuda a mejorar la seguridad de su configuración de monitoreo al evitar la codificación rígida de datos sensibles en los archivos de configuración.
    </Callout>
  </Step>

  <Step>
    ## Valide la configuración de NRDOT Collector [#validate]

    1. Actualice la ruta de configuración para que apunte a su nuevo archivo `postgresql-config.yaml`:

```bash
      sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/postgresql-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
```

    2. Valide la configuración del NRDOT Collector para asegurarse de que tenga el formato correcto y funcione correctamente:

```bash
      sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/postgresql-config.yaml
```
  </Step>

  <Step>
    ## Reiniciar NRDOT Collector [#restart-collector]

    Después de configurar el recolector, reinicie el servicio NRDOT Collector para aplicar los cambios:

```bash
    sudo systemctl restart nrdot-collector
```

    Para verificar que el recolector se esté ejecutando correctamente, verifique el estado del servicio:

```bash
    sudo systemctl status nrdot-collector
```

    <Callout variant="tip">
      Reinicie siempre el NRDOT Collector después de realizar cambios de configuración para garantizar que los nuevos ajustes surtan efecto.
    </Callout>
  </Step>

  <Step>
    ## Encuentra y utiliza tus datos [#find-use-data]

    Las muestras de consulta y las consultas principales llegan como log de evento (`event.name = 'db.server.query_sample'` / `'db.server.top_query'`, `db.system.name = 'postgresql'`). Las métricas llegan bajo el namespace `postgresql.*`.

    Para encontrar su entidad de base de datos RDS PostgreSQL en New Relic:

    1. Vaya a <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.
    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**PostgreSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.
    3. Seleccione su base de datos RDS PostgreSQL de la lista de entidades.
  </Step>
