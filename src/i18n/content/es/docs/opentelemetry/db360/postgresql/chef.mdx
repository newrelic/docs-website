Puede instalar y configurar el NRDOT Collector para el monitoreo de PostgreSQL usando el cookbook de Chef `newrelic-install`. El cookbook instala el recolector, crea el rol de monitoreo y sus permisos, y configura el recolector cuando ejecuta la receta `newrelic-install::default`.

<Callout variant="tip" title="Instalación guiada">
  Para instalar a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.
    * PostgreSQL 14 o posterior.
    * Chef 15 o posterior.
    * Un host recolector de Linux que ejecuta Debian/Ubuntu o RHEL/CentOS.
    * `pg_stat_statements` debe cargarse a través de `shared_preload_libraries`, lo que requiere un reinicio de la base de datos. Cumpla con los [requisitos previos a nivel de servidor](/docs/opentelemetry/db360/postgresql/cli/#server-prereqs) antes de ejecutar la receta.
    * Para PostgreSQL autohospedado: acceso administrativo al servidor de PostgreSQL (el superusuario `postgres` o equivalente), con una contraseña configurada y `pg_hba.conf` que permita la autenticación de host basada en contraseña.
    * Para PostgreSQL o Aurora en AWS RDS: conectividad de red desde el host del recolector hasta el extremo de RDS, y el nombre de usuario y la contraseña maestros de RDS.
    * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para su región.

    Para conocer los requisitos detallados, consulte [Compatibilidad](/docs/opentelemetry/db360/postgresql/compatibility).
  </Step>

  <Step>
    ## Descargar el cookbook de Chef [#chef-download-cookbook]

    Descargue el [cookbook de Chef](https://supermarket.chef.io/cookbooks/newrelic-install) `newrelic-install` desde Chef Supermarket al directorio del repositorio de Chef:

    ```bash
    knife supermarket install newrelic-install
    ```
  </Step>

  <Step>
    ## Reemplace los atributos predeterminados [#chef-configure]

    Reemplace los atributos predeterminados en `attributes/default.rb` con los detalles de la cuenta:

    <CollapserGroup>
      <Collapser id="chef-host" title="PostgreSQL autohospedado">
        Este cookbook monitorea una o más instancias de PostgreSQL desde un solo recolector. En lugar de un solo conjunto de host/puerto/credencial, lee dos archivos que ya deben existir en el nodo: un archivo de instancias (YAML) que enumera cada instancia que se va a monitorear y las bases de datos que se van a monitorear en cada una, y un archivo de secretos (`KEY=VALUE`) con un inicio de sesión y contraseña de superusuario para cada una, indexados para que coincidan. Consulte la página de [instalación de la CLI](/docs/opentelemetry/db360/postgresql/cli/#cli-install) para conocer los formatos de archivo exactos.

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-postgresql'
        ]
        default['newrelic_install']['env']['NR_CLI_POSTGRES_CONFIG_PRESET']         = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_INSTANCES_FILE']        = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_SECRETS_FILE']          = <path to the secrets file (KEY=VALUE per instance) on the node>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_ENABLE_EXPLAIN_HELPER'] = <y or N, default N; PREVIEW feature, see table below>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

        <Callout variant="important">
          El cookbook se conecta a PostgreSQL a través de TCP mediante una contraseña, por lo que el superusuario de cada instancia debe tener una contraseña configurada y `pg_hba.conf` debe permitir la autenticación de host basada en contraseña (`md5` o `scram-sha-256`) para las conexiones TCP:

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```
        </Callout>

  <Step>
    ## Cargue el cookbook de Chef [#chef-upload-cookbook]

    Cargue el cookbook de Chef `newrelic-install` en su servidor de Chef:

    ```bash
    knife cookbook upload newrelic-install
    ```
  </Step>

  <Step>
    ## Actualice la lista de ejecución [#chef-run-list]

    Agregue la receta `newrelic-install` a la lista de ejecución de un nodo:

    ```json
    "run_list": [
      "recipe[newrelic-install]"
    ]
    ```
  </Step>

  <Step>
    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos PostgreSQL a través de la UI de New Relic.

    Para encontrar su entidad de base de datos PostgreSQL en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**PostgreSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.
    3. Seleccione su base de datos PostgreSQL de la lista de entidades.
  </Step>
</Steps>
