El Collector de NRDOT reporta una amplia gama de métricas de PostgreSQL. New Relic recopila las métricas y los eventos a nivel de consulta en [Métricas y eventos predeterminados](#default) automáticamente. Para obtener información valiosa más detallada sobre el rendimiento y el estado, active cualquiera de las métricas enumeradas en [Métricas de características completas](#full-feature).

## Métricas y eventos predeterminados [#default]

<Callout variant="tip">
Cada métrica tiene como alcance una base de datos, tabla, esquema o índice específico. Este contexto se establece en el recurso, no como un atributo de métrica.
</Callout>

### Consulta evento [#query-events]

<Collapser id="query-sample" title="Muestras de consulta">

#### Mecánica de recopilación del plan de ejecución (EXPLAIN)

* **Limitación de velocidad:** `top_query_collection.max_explain_each_interval` (predeterminado 1000) limita los EXPLAIN por extracción.
* **Almacenamiento en caché:** `query_plan_cache_size` / `query_plan_cache_ttl` (predeterminado 1000 entradas/1h) almacena en caché un plan una vez obtenido, identificado por ID de consulta.
* **Requisito de PostgreSQL 12+:** el EXPLAIN de consulta parametrizada necesita `plan_cache_mode = force_generic_plan` antes de `PREPARE`/`EXPLAIN EXECUTE`, solo disponible en PostgreSQL 12+. En servidores más antiguos, el receptor detecta la versión y omite EXPLAIN para esa consulta en lugar de enviar un `SET` que fallaría.
* **Límite de privilegios:** por defecto, EXPLAIN se ejecuta directamente como el usuario de monitoreo, y Postgres comprueba los privilegios de tabla en el momento del *plan*, por lo que las sentencias de bloqueo de filas o de escritura fallan con `permission denied` a menos que se conceda acceso de escritura, algo que el usuario de monitoreo nunca debería tener. Utilice `explain_function_name` (consulte [Planes de consulta para sentencias de escritura](/docs/opentelemetry/db360/postgresql/optional#query)) para solucionar esto sin conceder acceso de escritura.
* Si no se puede obtener un plan por cualquier motivo, `postgresql.query_plan` simplemente está vacío para esa fila. No se muestra ningún error.
