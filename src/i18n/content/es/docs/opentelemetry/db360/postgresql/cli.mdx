Puede instalar y configurar el Collector de NRDOT para el monitoreo de PostgreSQL mediante la CLI de New Relic. La CLI instala el recolector, crea el rol de monitoreo y sus permisos, y configura el recolector en un solo comando.

<Callout variant="tip" title="Instalación guiada">
  Para instalar a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>. Esta página solo cubre la instalación manual.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Una cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Un [ID de cuenta](/docs/accounts/accounts-billing/account-structure/account-id) de New Relic.
    * PostgreSQL 14 o posterior.
    * Un host recolector de Linux que ejecuta Debian/Ubuntu o RHEL/CentOS, con `curl` y `systemd` instalados, y el cliente `psql` disponible.
    * `pg_stat_statements` debe cargarse a través de `shared_preload_libraries`. El instalador verifica esto y falla si no es así. Consulte [Requisitos previos a nivel de servidor](#server-prereqs) a continuación.
    * Para PostgreSQL autohospedado: acceso administrativo al servidor de PostgreSQL (el superusuario `postgres` o equivalente).
    * Para AWS RDS/Aurora PostgreSQL: conectividad de red desde el host del recolector al extremo de RDS (acceso de entrada en el puerto de PostgreSQL en el grupo de seguridad de RDS), y el nombre de usuario y la contraseña maestros de RDS.
    * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para su región.

    Para conocer los requisitos detallados, consulte [Compatibilidad](/docs/opentelemetry/db360/postgresql/compatibility).
  </Step>

    * **Autohospedado**: configure estos valores en `postgresql.conf` y luego reinicie PostgreSQL. Algunas distribuciones necesitan que el paquete `postgresql-contrib` esté instalado para que `pg_stat_statements` esté disponible.
    * **AWS RDS o Aurora**: configúrelos en el **grupo de parámetros** de la base de datos, no en un archivo de configuración. `track_activity_query_size` y `pg_stat_statements.max` son parámetros estáticos: aplíquelos con `apply_method: pending-reboot` y, luego, reinicie la instancia. Para Aurora, el nombre de la familia del grupo de parámetros debe coincidir exactamente con la versión principal del motor, por ejemplo, `aurora-postgresql16`.
  </Step>

  <Step>
    ## Instalar y configurar el NRDOT Collector [#cli-install]

    <CollapserGroup>
      <Collapser id="cli-host" title="PostgreSQL autohospedado">
        Esta receta monitorea una o más instancias de PostgreSQL desde un solo recolector. En lugar de solicitar un solo conjunto de host/puerto/credenciales, lee dos archivos que debe crear con anticipación: un archivo de instancias (YAML) que enumera cada instancia a monitorear y las bases de datos a monitorear en cada una, y un archivo de secretos (`KEY=VALUE`) con un inicio de sesión y contraseña de superusuario para cada una, indexados para que coincidan.

        1. Cree el archivo de instancias. Agregue una entrada por instancia de PostgreSQL que desee que este recolector monitoree; sigue siendo solo una entrada si solo ejecuta una única instancia. Cada instancia requiere al menos una base de datos: PostgreSQL no tiene un modo para monitorear todas las bases de datos:

           ```bash
           cat > ~/postgresql-instances.yml << 'EOF'
           instances:
             - host: localhost
               port: 5432
               login_name: newrelic
               databases: [app1, app2]
           EOF
           ```

        2. Cree el archivo de secretos con un rol de superusuario (cualquier rol de superusuario funciona; no tiene que ser `postgres`) y una contraseña para cada instancia, indexado para que coincida con el orden del archivo de instancias:

           ```bash
           umask 077
           cat > ~/postgresql-secrets.env << 'EOF'
           NR_CLI_POSTGRES_SUPERUSER_USER_1=postgres
           NR_CLI_POSTGRES_SUPERUSER_PASSWORD_1=YourSuperuserPassword1
           EOF
           chmod 600 ~/postgresql-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-postgresql
        ```

        <Callout variant="important">
          Este instalador se conecta a PostgreSQL a través de TCP mediante una contraseña, por lo que el superusuario de cada instancia debe tener una contraseña configurada y `pg_hba.conf` debe permitir la autenticación de host basada en contraseña (`md5` o `scram-sha-256`) para las conexiones TCP. Una instalación nueva no tiene una contraseña configurada en `postgres` de forma predeterminada. Configure una primero:

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```

          En RHEL/CentOS, el `pg_hba.conf` predeterminado a menudo no permite la autenticación de host basada en contraseña en absoluto. Verifíquelo y actualícelo, luego recargue PostgreSQL antes de ejecutar la instalación.
        </Callout>

           NR_CLI_POSTGRES_ADMIN_USER_1=postgres

  <Step>
    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos PostgreSQL a través de la UI de New Relic.

    Para encontrar su entidad de base de datos PostgreSQL en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**PostgreSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.
    3. Seleccione su base de datos PostgreSQL de la lista de entidades.

    Para confirmar que los datos están llegando, ejecute esta consulta en el [generador de consultas](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/):

    ```sql
    SELECT count(*) FROM Metric
    WHERE metricName LIKE 'postgresql.%'
    AND instrumentation.provider = 'opentelemetry'
    SINCE 10 minutes ago
    ```
