<Callout title="Avance">
  Todavía estamos trabajando en esta característica, ¡pero nos encantaría que la probaras!

  Esta función se proporciona actualmente como parte de una vista previa de conformidad con nuestras [políticas de prelanzamiento](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy/).
</Callout>

El Collector de NRDOT reporta una amplia gama de métricas de PostgreSQL. New Relic recopila las métricas en [Métricas predeterminadas](#default) automáticamente. Para obtener información valiosa más profunda sobre el rendimiento y el estado, habilite cualquiera de las métricas enumeradas en [Métricas adicionales](#additional).

<Callout variant="tip">
  Cada métrica tiene como alcance una base de datos, tabla, esquema o índice específico. Este contexto se establece en el recurso, no como un atributo de métrica.
</Callout>

    #### Mecánica de recopilación del plan de ejecución (EXPLAIN)

    * **Limitación de velocidad:** `top_query_collection.max_explain_each_interval` (predeterminado 1000) limita los EXPLAIN por extracción.
    * **Almacenamiento en caché:** `query_plan_cache_size` / `query_plan_cache_ttl` (predeterminado 1000 entradas/1h) almacena en caché un plan una vez obtenido, identificado por ID de consulta.
    * **Requisito de PostgreSQL 12+:** el EXPLAIN de consulta parametrizada necesita `plan_cache_mode = force_generic_plan` antes de `PREPARE`/`EXPLAIN EXECUTE` —solo disponible en PostgreSQL 12+. En servidores más antiguos, el receptor detecta la versión y omite EXPLAIN para esa consulta en lugar de enviar un `SET` que fallaría.
    * **Límite de privilegios:** de forma predeterminada, EXPLAIN se ejecuta directamente como el usuario de monitoreo, y Postgres verifica los privilegios de la tabla en el momento de la *planificación* — por lo que las declaraciones de bloqueo de filas o de escritura fallan con `permission denied` a menos que se otorgue acceso de escritura, lo cual el usuario de monitoreo nunca debería tener. Use `explain_function_name` (consulte los [permisos del plan EXPLAIN](/docs/opentelemetry/database/postgresql/explain-permissions)) para solucionar esto sin otorgar acceso de escritura.
    * Si no se puede obtener un plan por algún motivo, `postgresql.query_plan` simplemente está vacío para esa fila — no aparece ningún error.
