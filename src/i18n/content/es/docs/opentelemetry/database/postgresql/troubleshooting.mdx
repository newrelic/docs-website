Solucione los problemas comunes que puede encontrar durante el monitoreo de su PostgreSQL con el NRDOT Collector.

## Probar conectividad

### Probar la conectividad de red a PostgreSQL

```bash
psql --host=<YOUR_DB_HOST> --port=<YOUR_DB_PORT> --username=<YOUR_DB_USERNAME> --dbname=<YOUR_DATABASE_NAME> --command 'SELECT 1;'
```

Una conexión y un resultado exitosos confirman que el usuario de monitoreo, el host y el puerto son accesibles antes de la resolución de problemas del recolector en sí.

### Probar la conectividad del extremo OTLP

Verifique que el NRDOT Collector pueda alcanzar el extremo OTLP de New Relic:

```bash
curl -v <YOUR_NEWRELIC_OTLP_ENDPOINT>
```

## Síntomas comunes

| Síntoma                                                                                                        | Causa probable                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No hay eventos `db.server.query_sample` / `db.server.top_query`                                                | El bloque `events` no está habilitado en la configuración del receptor (ambos están desactivados por defecto)                                                                     |
| `db.server.top_query` Eventos faltantes por completo                                                           | `pg_stat_statements` extensión no creada en esa base de datos                                                                                                                     |
| `db.server.query_sample` falta el detalle de la sesión de bloqueo                                              | El usuario de monitoreo carece de `pg_monitor`                                                                                                                                    |
| Consultas largas truncadas en `db.server.query_sample`                                                         | `track_activity_query_size` predeterminado (1024 bytes) — auméntelo, consulte [Compatibilidad y requisitos previos](/docs/opentelemetry/database/postgresql/compatibility#params) |
| `postgresql.function.calls` siempre vacío, o el widget &quot;Function Calls/min&quot; del dashboard está vacío | `track_functions` no establecido en `pl` o `all` en `postgresql.conf`                                                                                                             |
| Varios widgets del dashboard vacíos a pesar del flujo de métricas                                              | Esas métricas están deshabilitadas por defecto — consulte la [Referencia de métricas](/docs/opentelemetry/database/postgresql/metrics-reference#dashboard)                        |
| `db.query.comment_tags.nr_service_guid` siempre vacío                                                          | `allowed_comment_keys: [nr_service_guid]` No establecido en `query_sample_collection` / `top_query_collection` — vacío por defecto                                                |
| Faltan métricas de tabla/índice/función para algunas tablas                                                    | El usuario de monitoreo carece de `SELECT` en esas tablas/esquemas — `pg_monitor` otorga visibilidad de estadísticas, no a nivel de objeto `SELECT`                               |
| `postgresql.wal.lag` / falta `.wal.age`                                                                        | Requiere WAL habilitado con al menos una réplica conectada — se omite silenciosamente en instancias independientes/solo de origen, no se pone a cero                              |
| La entidad de PostgreSQL no aparece, o la relación app→PostgreSQL no se resuelve en el explorador de entidades | `server.address`/`server.port` no está presente en el recurso; el receptor por sí solo no los emite bajo el modelo de recursos predeterminado (legacy)                            |
