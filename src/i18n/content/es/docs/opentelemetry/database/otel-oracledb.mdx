New Relic ahora permite a su equipo monitorear el rendimiento de su base de datos Oracle usando New Relic Distribution of OpenTelemetry (NRDOT) con las capacidades de monitoreo de bases de datos de New Relic. Esta integración proporciona información valiosa detallada sobre las métricas de la base de datos, el rendimiento de las consultas y el estado del sistema mediante el recolector NRDOT.

Este enfoque basado en NRDOT complementa nuestra actual On-Host Integration (OHI) al aprovechar los estándares de OpenTelemetry para el monitoreo de bases de datos, lo que facilita la integración con su stack de observabilidad existente.

## Requisitos previos [#prerequisites]

Antes de comenzar, cerciorar de tener lo siguiente:

* [Clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)de New Relic válida
* Arquitectura compatible: Linux con AMD64 y ARM64
* Conectividad de red al extremo OTLP de New Relic
* Oracle Database 19c o posterior
* Esta integración está disponible como parte del programa de vista previa pública (public preview) de New Relic. Consulte con el Gerente de su organización para activarla desde la página de [Previsualizaciones y pruebas (Previews &amp; Trials)](https://one.newrelic.com/admin-portal/promotion-management/home).

## Configurar el NRDOT Collector para el monitoreo de Oracle Database [#install-collector]

Puede configurar el monitoreo de Oracle Database utilizando el NRDOT Collector en entornos on-host (multitenant) o RDS. Puede configurar el NRDOT Collector utilizando los siguientes métodos:

* [Instalación guiada](/docs/opentelemetry/database/otel-oracledb/#guided): el método de instalación guiada proporciona instrucciones paso a paso en la plataforma de New Relic para ayudarle a instalar y configurar el NRDOT Collector para el monitoreo de Oracle Database.

* **Instalación manual**: el método de instalación manual le permite configurar el NRDOT Collector por su cuenta siguiendo las instrucciones de esta documentación. Puede configurar manualmente en los siguientes entornos:

  * [Entorno on-host (multitenant)](/docs/opentelemetry/database/otel-oracledb/#host): instale el NRDOT Collector en el mismo host que la instancia de Oracle Database para recopilar telemetry data de la infraestructura y de la base de datos.
  * [Entorno RDS](/docs/opentelemetry/database/otel-oracledb/#rds): instale el Collector NRDOT en un entorno RDS para monitorear las instancias de base de datos de Oracle que se ejecutan en Amazon RDS.

<Callout variant="tip">
  El NRDOT Collector recopila telemetry data relacionados tanto con la infraestructura como con la base de datos, para que pueda tener una solución de observabilidad unificada para su entorno de Oracle Database en New Relic.
</Callout>

              <Step>
                ### Configurar el usuario de la base de datos [#mdatabase-user]

                Cree un usuario de monitoreo con los privilegios necesarios para su base de datos Oracle multitenant. Esto requiere crear un usuario común con el prefijo `C##`.

                1. Antes de crear el usuario de la base de datos o ejecutar cualquier concesión de asignación, debe ejecutar la siguiente declaración como usuario `SYS` para establecer su contexto de contenedor activo actual en `CDB$ROOT`:

                   ```sql
                   ALTER SESSION SET CONTAINER = CDB$ROOT;
                   ```

                2. Para bases de datos multiinquilino, inicie sesión en la base de datos raíz como administrador. Use CREATE USER para agregar un nuevo usuario a la base de datos. El nombre de usuario especificado será un “usuario común” y debe tener el prefijo `c##` como recomienda Oracle.

                   ```sql
                   CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<USER_PASSWORD>" CONTAINER=ALL;
                   GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
                   ```

                3. Ejecute la siguiente sentencia como SYSDBA en la raíz de la CDB. Esto permite al usuario de monitoreo ver las filas de cada PDB en las vistas de datos del contenedor, lo cual es necesario para las métricas y eventos por PDB.

                   ```sql
                   ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;
                   ```

                   <Callout variant="tip">
                     Asegúrese de que su `USER_PASSWORD` cumpla con los requisitos de [contraseña de nuevo usuario](https://docs.oracle.com/en/database/oracle/oracle-database/12.2/dbseg/keeping-your-oracle-database-secure.html#GUID-451679EB-8676-47E6-82A6-DF025FD65156) de Oracle.
                   </Callout>
              </Step>

## Comandos admitidos del colector NRDOT [#commands]

Esta sección proporciona una lista de comandos comunes para administrar el servicio NRDOT Collector en su sistema.

<CollapserGroup>
  <Collapser title="Comandos del colector NRDOT" id="command">
    * Para validar el estado de la instalación:

      * Para distribuciones basadas en Debian/Ubuntu:

        ```bash
        dpkg -l | grep nrdot-collector
        ```

      * Para distribuciones basadas en RHEL/CentOS:

        ```bash
        rpm -q nrdot-collector || ls /etc/nrdot-collector
        ```

    * Para reiniciar NRDOT Collector:

    ```bash
    sudo systemctl restart nrdot-collector.service
    ```

    * Para verificar el estado de NRDOT Collector:

    ```bash
    sudo systemctl status nrdot-collector.service
    ```

    * Para ver los logs de NRDOT Collector:

    ```bash
    sudo journalctl -u nrdot-collector -n 50 --no-pager
    ```

    * Para eliminar el servicio NRDOT Collector:

      * Para distribuciones basadas en Debian/Ubuntu:

        ```bash
        sudo apt purge nrdot-collector
        ```

      * Para distribuciones basadas en RHEL/CentOS:

        ```bash
        sudo yum erase nrdot-collector
        ```

    * Para limpiar los archivos de configuración:

    ```bash
    # Clean up configuration and reload systemd
    ```

## Resolución de problemas [#troubleshoot]

Si encuentra problemas durante la configuración, utilice esta guía de solución de problemas para diagnosticar y resolver los problemas comunes.

<CollapserGroup>
  <Collapser id="test-connection" title="Probar la conectividad de red">
    Ejecute el siguiente comando para verificar que el puerto de la base de datos de Oracle sea accesible desde este host.

    ```bash
    (timeout 3 bash -c '</dev/tcp/<YOUR_ENDPOINT>/<YOUR_PORT>' && echo "PORT OPEN - Network connection successful!") || echo "CONNECTION FAILED - Port closed or firewall blocking"
    ```

    **Resultado esperado:** `PORT OPEN - Network connection successful!`
  </Collapser>

  <Collapser id="otlp-endpoint-connection" title="Probar la conectividad del extremo OTLP">
    Ejecute el siguiente comando para verificar que su host pueda alcanzar el extremo OTLP de New Relic seleccionado.

    ```bash
    ENDPOINT="<YOUR_OTLP_ENDPOINT>"
    HOST=$(echo "$ENDPOINT" | sed 's|https://||' | cut -d: -f1)
    PORT=$(echo "$ENDPOINT" | awk -F: '{print $NF}')
    (timeout 2 bash -c "</dev/tcp/$HOST/$PORT" && echo "✅ SUCCESS") || echo "❌ FAILED"
    ```

    **Resultado esperado:** `✅ SUCCESS`
  </Collapser>
</CollapserGroup>
