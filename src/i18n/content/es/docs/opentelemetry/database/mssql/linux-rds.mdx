<Callout title="Avance">
  Todavía estamos trabajando en esta característica, ¡pero nos encantaría que la probaras!

  Esta función se proporciona actualmente como parte de una vista previa de conformidad con nuestras [políticas de prelanzamiento](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy/).
</Callout>

Obtenga información valiosa completa sobre el rendimiento de su AWS RDS SQL Server con el monitoreo de base de datos, el análisis de consultas y las métricas de estado del sistema mediante el recolector de New Relic Distribution of OpenTelemetry (NRDOT).

Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página cubre únicamente la ruta de instalación de la CLI.

<Callout variant="tip">
  Si utiliza SQL Server en un entorno autohospedado de Linux, consulte la [instrumentación de Linux para RDS](/docs/opentelemetry/database/mssql/linux-hosted).
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * Cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)válida

    * [Extremo OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) de New Relic para su región

    * Requisitos de AWS RDS SQL Server:

      * AWS RDS SQL Server 2017 o posterior
      * Nombre de usuario y contraseña maestros de RDS
      * Grupo de seguridad que permite conexiones entrantes en el puerto `1433` o en un puerto personalizado

    * Requisitos del sistema de Linux:

      * `sqlcmd` utilidad instalada en el sistema Linux
      * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp)
  </Step>

  <Step>
    ## Instalar NRDOT Collector [#setup]

    Descargue e instale el paquete NRDOT para su distribución de Linux. Reemplace `<NRDOT_VERSION>` con la última etiqueta de versión de la página [nrdot-collector-releases](https://github.com/newrelic/nrdot-collector-releases/releases).

    <Callout variant="important">
      Instale el NRDOT Collector en una instancia EC2 o máquina local con conectividad de red a la instancia de RDS SQL Server. Asegúrese de que el grupo de seguridad permita conexiones entrantes en el puerto 1433 (o puerto personalizado).
    </Callout>

    <CollapserGroup>
      <Collapser id="deb" title="Para Debian/Ubuntu">
        * Para la arquitectura AMD64:

          ```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
          ```

  <Step>
    ## Crear usuario de monitoreo [#user]

    Ejecute este script como usuario root para crear el usuario de monitoreo `newrelic` y otorgar los permisos necesarios para recopilar las métricas de RDS SQL Server.

    1. Cree un archivo llamado `nr-grant-permission-rds.sql`.

    2. Pegue el siguiente script de SQL para crear el usuario de monitoreo de `newrelic` y reemplace `<YOUR_PASSWORD>` con la contraseña deseada:

       ```sql
       USE [master];
       GO
       CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
       GO
       -- Instance-level permissions
       GRANT VIEW SERVER STATE TO [newrelic];
       GRANT VIEW ANY DEFINITION TO [newrelic];
       GRANT VIEW ANY DATABASE TO [newrelic];
       GO
       -- Grant read access privileges to all user databases
       DECLARE @name SYSNAME;
       DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
       SELECT [name]
       FROM [master].[sys].[databases]
       WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
       AND [state] = 0; -- Only online databases
       OPEN db_cursor;
       FETCH NEXT FROM db_cursor INTO @name;
       WHILE @@FETCH_STATUS = 0
       BEGIN
         BEGIN TRY
           EXEC('USE [' + @name + '];
             IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
             BEGIN
               CREATE USER [newrelic] FOR LOGIN [newrelic];
             END;
             GRANT VIEW DATABASE STATE TO [newrelic];');
         END TRY
         BEGIN CATCH
           PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
         END CATCH
         FETCH NEXT FROM db_cursor INTO @name;
       END
       CLOSE db_cursor;
       DEALLOCATE db_cursor;
       GO
       ```

    3. Ejecute el script usando `sqlcmd`. Reemplace `<YOUR-RDS-ENDPOINT>` con su extremo de RDS y `<YOUR_MASTER_PASSWORD>` con su contraseña maestra:

    ```bash
    sqlcmd -S <YOUR-RDS-ENDPOINT> -U <YOUR_MASTER_USER> -P '<YOUR_MASTER_PASSWORD>' -C -i nr-grant-permission-rds.sql
    ```

    3. *(Opcional)* Verifique que el usuario se haya creado correctamente con los permisos correctos:

    ```bash
    sqlcmd -S <YOUR-RDS-ENDPOINT> -U <YOUR_MASTER_USER> -P '<YOUR_MASTER_PASSWORD>' -C -Q "SELECT sp.name AS [User], p.permission_name AS [Permission_Granted] FROM sys.server_permissions p JOIN sys.server_principals sp ON p.grantee_principal_id = sp.principal_id WHERE sp.name = 'newrelic';"
    ```

    <Callout variant="tip">
      Use el nombre de usuario y la contraseña maestros de RDS para ejecutar estos comandos. El script excluye automáticamente la base de datos `rdsadmin`, que está reservada por AWS.
      Para administrar de forma segura la información confidencial, como las credenciales de la base de datos, almacénelas en herramientas de [gestión de secretos](/docs/opentelemetry/database/capabilities/db-apm/#secret-management).
    </Callout>
  </Step>

  <Step>
    ## Actualizar la configuración de NRDOT Collector [#update]

    Después de configurar su archivo YAML con las entradas interactivas anteriores, complete la configuración de NRDOT Collector:

    1. Edite el archivo de configuración del servicio usando el siguiente comando:

       ```bash
       sudo nano /etc/nrdot-collector/nrdot-collector.conf
       ```

    2. Actualice la ruta de configuración para que apunte a su nuevo archivo `mssql-config.yaml`:

       ```bash
       OTELCOL_CONFIG="/etc/nrdot-collector/mssql-config.yaml"
       ```

    3. (Opcional) Valide la configuración del Collector de NRDOT:

       ```bash
       sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mssql-config.yaml
       ```

       <Callout variant="tip">
         Para correlacionar el rendimiento de su aplicación con las operaciones de la base de datos, puede configurar la identificación del servicio de base de datos. Para obtener más información, consulte la [guía de configuración de identificación del servicio de base de datos](/docs/opentelemetry/database/capabilities/db-apm).
       </Callout>
  </Step>

  <Step>
    ## Reiniciar NRDOT Collector [#restart]

    Después de actualizar su configuración, reinicie el servicio NRDOT Collector:

    ```bash
    sudo systemctl restart nrdot-collector
    ```

    <Callout variant="tip">
      Siempre reinicie el servicio NRDOT Collector después de realizar cambios de configuración para garantizar que los nuevos ajustes surtan efecto.
    </Callout>
  </Step>

  <Step>
    ## Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

    Para encontrar su entidad de base de datos SQL Server en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.

    3. Seleccione su base de datos SQL Server de la lista de entidades.

       Después de configurar el monitoreo de SQL Server con NRDOT, puede:

       * [Crea dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de tu base de datos
       * [Configura alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de rendimiento de la base de datos
       * [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
  </Step>
</Steps>
