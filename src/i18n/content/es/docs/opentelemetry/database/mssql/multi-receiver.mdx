Puede configurar el Collector NRDOT para monitorear múltiples instancias de MSSQL desde un recolector. Esto es útil si tiene múltiples MSSQL ejecutándose en diferentes hosts y desea recopilar métricas de todos ellos utilizando una sola instancia del Collector NRDOT.

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    * NRDOT está instalado y configurado para las instancias de MSSQL:

      * [Linux RDS](/docs/opentelemetry/database/mssql/linux-rds)
      * [Linux alojado](/docs/opentelemetry/database/mssql/linux-hosted)
      * [Windows alojado](/docs/opentelemetry/database/mssql/windows-hosted)
      * [Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
  </Step>

  <Step>
    ## Agregar configuración de múltiples receptores [#multi]

    Los siguientes ejemplos muestran cómo configurar el Collector NRDOT para monitorear múltiples instancias de MSSQL utilizando una configuración de múltiples receptores. Seleccione el tipo de despliegue que coincida con su entorno. Puede agregar más receptores según sea necesario para instancias adicionales.

    ```yaml
    receivers:
      nrsqlserver/1: &nrsqlserver-common
        username: "<YOUR_DB_USERNAME>"
        password: "<YOUR_DB_PASSWORD>"
        server: "<YOUR_SERVER_1>"
        port: <YOUR_PORT_1>
        collection_interval: 30s
        # Add any additional configuration here (metrics, events, query collection, etc.)
        # All settings are automatically inherited by additional receiver instances.
      nrsqlserver/2:
        <<: *nrsqlserver-common
        username: "<YOUR_DB2_USERNAME>"
        password: "<YOUR_DB2_PASSWORD>"
        server: "<YOUR_SERVER_2>"
        port: <YOUR_PORT_2>
      # Add more instances as needed:
      # nrsqlserver/3:
      #   <<: *nrsqlserver-common
      #   username: "<YOUR_DB3_USERNAME>"
      #   password: "<YOUR_DB3_PASSWORD>"
      #   server: "<YOUR_SERVER_3>"
      #   port: <YOUR_PORT_3>

    service:
      pipelines:
        metrics:
          receivers: [nrsqlserver/1, nrsqlserver/2]  # Add nrsqlserver/3, nrsqlserver/4, ... as needed
          processors: [<YOUR_PROCESSORS>]
          exporters: [otlp]
        logs:
          receivers: [nrsqlserver/1, nrsqlserver/2]  # Add nrsqlserver/3, nrsqlserver/4, ... as needed
          processors: [<YOUR_PROCESSORS>]
          exporters: [otlp]
    ```

    La clave de combinación `<<: *nrsqlserver-common` hereda todas las configuraciones de `nrsqlserver/1`. Cualquier campo que establezca explícitamente después de ella, como `username`, `password`, `server` y `port`, sobrescribe el valor heredado para esa instancia de receptor específica.

    <Callout variant="important">
      Cada vez que agregue una nueva instancia de receptor (por ejemplo, `nrsqlserver/3`), agréguela también a la lista `receivers` en los pipelines `metrics` y `logs` bajo `service.pipelines`. Un receptor definido en el bloque `receivers` pero que no está en `service.pipelines` no recopilará ningún dato.
    </Callout>
  </Step>

  <Step>
    ## Reiniciar NRDOT Collector [#restart]

    Es necesario reiniciar, no es opcional — el recolector carga su configuración una vez al inicio y no se recarga en caliente. Cualquier cambio de configuración no tiene efecto hasta que reinicie el proceso.

    ```bash
    sudo systemctl restart nrdot-collector
    ```
  </Step>
</Steps>
