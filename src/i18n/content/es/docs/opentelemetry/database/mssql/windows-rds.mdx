Configure el monitoreo de Microsoft SQL Server mediante el Collector NRDOT en entornos Windows para monitorear instancias de AWS RDS para SQL Server. Para monitorear en un entorno autohospedado, consulte la [instrumentación autohospedada de Windows](/docs/opentelemetry/database/mssql/windows-hosted).

Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página cubre únicamente la ruta de instalación de la CLI.

Según la configuración de seguridad de su RDS SQL Server, elija los métodos de autenticación para conectar el Collector de NRDOT a su instancia de RDS:

        <Step>
          ## Requisitos previos [#prerequisites]

          Antes de monitorear Microsoft SQL Server con NRDOT, asegúrese de que el entorno cumpla con estos requisitos:

          * Cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)válida

          * [Extremo OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) de New Relic para su región

          * Requisitos de AWS RDS SQL Server:

            * Autenticación de SQL Server habilitada en la instancia de RDS
            * Credenciales de usuario maestro de RDS o credenciales para un inicio de sesión de SQL Server con el rol `rds_superuser`
            * Grupo de seguridad de RDS configurado para permitir conexiones en el puerto `1433` o en un puerto personalizado
            * SQL Server Management Studio (SSMS) o la utilidad `sqlcmd`

          * Conectividad de red al [extremo OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp)

          * La URL del extremo de su servidor SQL de RDS, que se puede encontrar en su consola de AWS RDS en Conectividad y seguridad. Para obtener más información, consulte la [documentación de AWS RDS](https://docs.aws.amazon.com/AmazonRDS/latest/gettingstartedguide/connecting-console.html).
        </Step>

        <Step>
          ## Instalar NRDOT Collector [#install-sql]

          Instale el Collector NRDOT en una instancia EC2 de Windows o en una máquina local de Windows que pueda conectarse a su instancia de RDS SQL Server.

          <Callout variant="important">
            Para el monitoreo de RDS, instale el Collector NRDOT en una instancia EC2 en la misma VPC que su instancia de RDS para obtener una conectividad de red óptima y una menor latencia.
          </Callout>

          Descarga e instala el NRDOT Collector usando PowerShell:

          ```bash
          [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name; $WebClient = New-Object System.Net.WebClient; $WebClient.Headers.Add("User-Agent", "Mozilla/5.0"); $WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi"); Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait; Get-Service nrdot-collector -ErrorAction SilentlyContinue
          ```
        </Step>

        <Step>
          ## Crear usuario de monitoreo [#user-sql]

          Ejecute este script como usuario administrador para crear el usuario de monitoreo `newrelic` y otorgar los permisos necesarios para recopilar métricas de SQL Server.

          <Callout variant="tip">
            Ejecute este script utilizando el nombre de usuario maestro de RDS o un usuario con el rol `rds_superuser`. El script excluye automáticamente la base de datos `rdsadmin` que está reservada por AWS.
          </Callout>

          En su SQL Server Management Studio (SSMS), ejecute el siguiente script para crear el usuario de monitoreo `newrelic`. Reemplace `<YOUR_PASSWORD>` con su contraseña deseada:

          ```sql
          USE [master];
          GO
          CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
          GO

          GRANT VIEW SERVER STATE TO [newrelic];
          GRANT VIEW ANY DEFINITION TO [newrelic];
          GRANT VIEW ANY DATABASE TO [newrelic];
          GO

          DECLARE @name SYSNAME;
          DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
          SELECT [name]
          FROM [master].[sys].[databases]
          WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
          AND [state] = 0;
          OPEN db_cursor;
          FETCH NEXT FROM db_cursor INTO @name;
          WHILE @@FETCH_STATUS = 0
          BEGIN
            BEGIN TRY
              EXEC('USE [' + @name + '];
              IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
              BEGIN
                CREATE USER [newrelic] FOR LOGIN [newrelic];
              END;
              GRANT VIEW DATABASE STATE TO [newrelic];');
            END TRY
            BEGIN CATCH
              PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
            END CATCH
            FETCH NEXT FROM db_cursor INTO @name;
          END
          CLOSE db_cursor;
          DEALLOCATE db_cursor;
          GO
          ```

          <Callout variant="tip">
            Para administrar de forma segura la información confidencial, como las credenciales de la base de datos, guárdelas en herramientas de [gestión de secretos](/docs/opentelemetry/database/capabilities/db-apm/#secret-management).
          </Callout>
        </Step>

        <Step>
          ## Actualizar el registro del servicio de Windows [#registry-sql]

          1. Actualice el registro de servicios de Windows para usar el nuevo archivo `mssql-config.yaml` mediante uno de los siguientes métodos:

             * **Para PowerShell:** ejecute el siguiente comando como administrador:

               ```bash
               Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
               ```

             * **Para el símbolo del sistema:** si PowerShell no está disponible, use el símbolo del sistema en su lugar y ejecute el siguiente comando como administrador:

             ```bash
             sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
             ```

          2. Valide la configuración del NRDOT Collector para asegurarse de que tenga el formato correcto y funcione correctamente.

          ```bash
          & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
          ```

          <Callout variant="tip">
            Para correlacionar el rendimiento de su aplicación con las operaciones de la base de datos, puede configurar la identificación del servicio de base de datos. Para obtener más información, consulte [configurar la identificación del servicio de base de datos](/docs/opentelemetry/database/capabilities/db-apm/).
          </Callout>

          ## Crear inicio de sesión de dominio de Windows [#create-domain]

          ## Ejecutar como usuario de dominio [#run-domain]

          1. Configure el servicio NRDOT Collector para que se ejecute como su usuario de dominio usando PowerShell. Reemplace `YOUR_DOMAIN\YOUR_USER_ACCOUNT` con el nombre de su dominio y cuenta:

             ```bash
             # Configure service to use domain account
             # The space after obj= and password= is required syntax for sc.exe
             sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

             # Restart the service
             Restart-Service nrdot-collector
             ```

          2. Valide la identidad del servicio:

             ```bash
             Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
             # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
             ```

        <Step>
          ## Crear usuario de monitoreo [#create-user]

          Conéctese a la instancia de RDS SQL Server mediante SQL Server Management Studio (SSMS) o `sqlcmd` con privilegios administrativos.

          En SQL Server Management Studio (SSMS), ejecute el siguiente script para crear un inicio de sesión para la cuenta gMSA y otorgar los permisos necesarios. Reemplace todas las apariciones de `<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>` con el nombre de dominio y cuenta real.

          ```sql
          USE [master];
          GO

          CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$] FROM WINDOWS;
          GO

          GRANT VIEW ANY DATABASE TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
          GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
          GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
          GO
          -- Grant access to all databases 
          DECLARE @name SYSNAME;
          DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
            SELECT [name] FROM [master].[sys].[databases]
            WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
            AND [state] = 0;
          OPEN db_cursor;
          FETCH NEXT FROM db_cursor INTO @name;
          WHILE @@FETCH_STATUS = 0
          BEGIN
            BEGIN TRY
              EXEC('USE [' + @name + '];
              IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$'')
              BEGIN
                CREATE USER [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
              END;
              GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];');
            END TRY
            BEGIN CATCH
              PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
            END CATCH
            FETCH NEXT FROM db_cursor INTO @name;
          END
          CLOSE db_cursor;
          DEALLOCATE db_cursor;
          GO
          ```

          <Callout variant="tip">
            Para administrar de forma segura la información confidencial, como las credenciales de la base de datos, almacénelas en herramientas de [gestión de secretos](/docs/opentelemetry/database/capabilities/db-apm/#secret-management).
          </Callout>
        </Step>

          ## Ejecutar como cuenta gMSA [#run-gmsa]

          Configure el servicio NRDOT Collector para que se ejecute como la cuenta gMSA mediante PowerShell. Reemplace `<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$` con su dominio y nombre de cuenta gMSA. Debe incluir el `$` al final, ya que es necesario para las cuentas gMSA:

          ```bash
          # Verify the configuration
          Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, StartName

          # Start the NRDOT Collector service 
          Start-Service nrdot-collector
          ```
