<Callout title="Avance">
  Todavía estamos trabajando en esta característica, ¡pero nos encantaría que la probaras!

  Esta función se proporciona actualmente como parte de una vista previa de conformidad con nuestras [políticas de prelanzamiento](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy/).
</Callout>

Obtenga información valiosa y detallada sobre el rendimiento de su SQL Server con nuestra solución de monitoreo basada en OpenTelemetry. Realice un seguimiento de las métricas de la base de datos, analice las consultas lentas, monitoree el uso de recursos y correlacione el rendimiento de la base de datos con sus aplicaciones.

Este enfoque basado en NRDOT complementa nuestra actual On-Host Integration (OHI) al aprovechar los estándares de OpenTelemetry para el monitoreo de bases de datos, lo que facilita la integración con su stack de observabilidad existente.

Características principales:

* **Estándares de OpenTelemetry**: se integra a la perfección con las herramientas de observabilidad existentes
* **Métricas exhaustivas**: más de 50 indicadores de rendimiento de la base de datos
* **Información valiosa a nivel de consulta**: identifique y optimice las consultas de rendimiento lento
* **Despliegue flexible**: funciona con entornos autohospedados y cloud
* **Correlación de APM**: conecte el rendimiento de la base de datos a las trazas de la aplicación

## Elige tu método de instalación [#install]

Puede instalar NRDOT Collector para el monitoreo de SQL Server de las siguientes maneras:

* Entornos autohospedados: instalación manual en su propia infraestructura

  * [Windows autoalojado](/docs/opentelemetry/database/mssql/windows-hosted)
  * [Linux autoalojado](/docs/opentelemetry/database/mssql/linux-hosted)

* Entornos de AWS RDS: monitoreo de SQL Server administrado en la nube:

  * [Monitoreo de Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
  * [Monitoreo de Linux RDS](/docs/opentelemetry/database/mssql/linux-rds)

## Instalación [#ui-install]

Para instalar esto a través de la UI de New Relic en su lugar, vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Siga las instrucciones en pantalla para configurar la integración.

## Instalación de un vistazo [#at-a-glance]

<Steps>
  <Step>
    ### Requisitos previos [#prerequisites]

    * Cuenta de New Relic con una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)válida

    * Conectividad de red entre el host donde instala el Collector NRDOT y su Microsoft SQL Server.

    * Conectividad de red a la [documentación de los extremos OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/)

    * Requisitos de SQL Server, necesitará:

      * SQL Server 2017 o posterior
      * Acceso administrativo a SQL Server (rol `sysadmin` o equivalente)
      * Conectividad de red entre el recolector y SQL Server en el puerto `1433` o en un puerto personalizado

    * Esta integración está disponible como parte del programa de vista previa pública (public preview) de New Relic. Consulte con el Gerente de su organización para activarla desde la página de [Previsualizaciones y pruebas (Previews &amp; Trials)](https://one.newrelic.com/admin-portal/promotion-management/home).

    Para conocer los requisitos previos detallados compatibles, consulte la sección específica de requisitos previos del documento de instalación.
  </Step>

  <Step>
    ### Instalar NRDOT Collector [#install]

    Elija su ruta de instalación según su infraestructura:

    * **Instalación guiada**: para instalar a través de la UI de New Relic, vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Siga las instrucciones en pantalla para configurar la integración. Esta página solo cubre la ruta de instalación de la CLI.

    * **Entornos autohospedados**: instalación manual en su propia infraestructura

      * [Windows autoalojado](/docs/opentelemetry/database/mssql/windows-hosted)
      * [Linux autoalojado](/docs/opentelemetry/database/mssql/linux-hosted)

    * **Entornos de AWS RDS**: monitoreo de SQL Server administrado en la nube

      * [Monitoreo de Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
      * [Monitoreo de Linux RDS](/docs/opentelemetry/database/mssql/linux-rds)
  </Step>

  <Step>
    ### Configurar usuarios de monitoreo [#user]

    Cree un usuario dedicado de Microsoft SQL Server con los permisos necesarios para permitir que el Collector de NRDOT recopile métricas y consulte datos de rendimiento. El usuario debe tener acceso de solo lectura a lo requerido.
  </Step>

  <Step>
    ### Configurar el Colector NRDOT [#configure]

    Configure el NRDOT Collector para conectarse a la instancia de Microsoft SQL Server. Esto implica especificar los detalles de conexión, el método de autenticación y cualquier opción de configuración adicional requerida para el entorno.
  </Step>

  <Step>
    ### Reiniciar NRDOT Collector [#restart]

    Después de configurar el Collector de NRDOT, reinicie el servicio para aplicar los cambios y comenzar a recopilar datos de la instancia de Microsoft SQL Server.
  </Step>

  <Step>
    ### Encuentra y utiliza tus datos [#find]

    Una vez que sus datos se estén recopilando, puede acceder al monitoreo integral de bases de datos SQL Server a través de la UI de New Relic.

    Para encontrar su entidad de base de datos SQL Server en New Relic:

    1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. En el menú desplegable **<DNT>Entity type</DNT>**, seleccione <DNT>**MSSQL instance**</DNT> y luego haga clic en <DNT>**Apply**</DNT>.
    3. Seleccione la base de datos SQL Server de la lista de entidades para ver su dashboard, métricas y datos de rendimiento de consultas.
  </Step>
</Steps>
