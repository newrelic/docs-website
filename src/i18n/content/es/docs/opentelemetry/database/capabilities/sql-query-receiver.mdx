</Callout>

El `sqlqueryreceiver` es un receptor de OpenTelemetry Collector que permite ejecutar cualquier consulta SQL personalizada en la base de datos e ingerir los resultados como métricas en New Relic.

Úselo cuando desee monitorear datos que no están cubiertos por las métricas integradas de `nroracledbreceiver` / `nrsqlserverreceiver`. Las métricas personalizadas recopiladas a través de `sqlqueryreceiver` aparecen bajo la misma entidad de Oracle o SQL Server en New Relic que los datos del receptor integrado, siempre que `host.name` esté configurado correctamente.

## Requisitos previos [#prerequisites]

* El usuario de la base de datos configurado en la fuente de datos debe tener el privilegio `SELECT` en cualquier vista o tabla que pretenda consultar.
* El binario del recolector debe incluir el componente `sqlqueryreceiver`.

      Agregue el bloque `sqlqueryreceiver` dentro de la sección `receivers:` de `oracle-config.yaml` existente, junto al bloque `nroracledb` existente:

      ```yaml
      receivers:
        nroracledb:

        ...

        sqlquery/oracle:
          driver: oracle

          # Approach 1: Use the `endpoint`, `username`, `password`, and `service` fields to connect to your database. The receiver will construct the datasource URL for you.
          # host: <YOUR_DB_HOST>
          # port: <YOUR_DB_PORT>
          # database: <YOUR_DATABASE_NAME>
          # username: <YOUR_DB_USERNAME>
          # password: <YOUR_DB_PASSWORD>


          # Approach 2: Use the `datasource` field to provide a full connection string. 
          datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"

          collection_interval: 60s
          queries:
            - sql: "<YOUR_CUSTOM_SQL>"
              metrics:
                - metric_name: oracledb.<YOUR_METRIC_NAME>
                  value_column: <RESULT_COLUMN>
                  attribute_columns: [<DIMENSION_COLUMN_1>, <DIMENSION_COLUMN_2>]
                  value_type: double
      ```

      ### Convención de nomenclatura

      Los nombres de las métricas deben comenzar con `oracledb.` para asociarse con la entidad correcta en New Relic. Las métricas con un prefijo diferente se ingerirán, pero no aparecerán bajo la entidad de la base de datos.

      ### Síntesis de entidad

      Agregue un procesador `resource/add_host` para establecer `host.name` en el mismo valor utilizado por el receptor de la base de datos. Sin esto, las métricas personalizadas no se vincularán a la entidad de la base de datos.

      Agregue el procesador en la sección `processors:`:

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: host.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: host.name
              value: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Configuración del Pipeline

      Agregue un pipeline `metrics/custom` en la sección `service.pipelines:` de la configuración, junto a los pipelines existentes:

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [resource/add_event_name, batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [resource/add_event_name, batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_host, resource/add_event_name, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        Agregue `resource/add_host` antes de `batch` en la lista de procesadores.
      </Callout>

      ### NRQL para validar datos

      Después de reiniciar el recolector, ejecute lo siguiente para confirmar que están llegando las métricas personalizadas:

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      ## Resolución de problemas [#troubleshooting]

      | Problema                                               | Causa                                                        | Arreglar                                                                                                                                |
      | ------------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
      | `ORA-00942: table or view does not exist`              | Al usuario de la base de datos le falta el privilegio SELECT | Otorgue `SELECT ON <VIEW_NAME>` al usuario                                                                                              |
      | `missing port in address`                              | `#` en nombre de usuario/contraseña no codificados en URL    | Reemplace `#` con `%23` en la URL de la fuente de datos                                                                                 |
      | No hay datos en New Relic                              | `host.name` no establecido o no coincide                     | Agregue el procesador `resource/add_host` con el valor de host correcto                                                                 |
      | Métricas que no están bajo la entidad de base de datos | Nombre de la métrica sin el prefijo requerido                | Asegúrese de que los nombres de las métricas comiencen con `oracledb.` para la base de datos Oracle o con `sqlserver.` para SQL Server. |
