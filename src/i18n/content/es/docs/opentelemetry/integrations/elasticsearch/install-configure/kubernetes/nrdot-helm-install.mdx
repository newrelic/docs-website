Esta guía muestra cómo desplegar NRDOT en Kubernetes mediante Helm para descubrir automáticamente los pods de Elasticsearch, recopilar métricas de clúster, nodo y JVM, y transmitirlas a New Relic para monitorear el estado y el rendimiento del clúster.

## Compatibilidad y requisitos [#requirements]

### Soportado

* Elasticsearch 7.16 o posterior, ejecutándose como pod en un clúster de Kubernetes
* Método de instalación con Helm

### Necesita

* Una [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) de New Relic
* `kubectl` acceso al clúster de Kubernetes
* Helm 3.x instalado
* Un usuario de Elasticsearch con el privilegio de clúster `monitor` o `manage` (consulte los [privilegios de seguridad de Elasticsearch](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html))
* Conectividad HTTPS saliente (puerto 443) al [extremo OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) de New Relic
* Un nombre de usuario y contraseña de Elasticsearch (si el clúster requiere autenticación)

<Steps>
<Step>
## Configure las etiquetas de pod [#pod-labels]

Cada pod de Elasticsearch debe tener la etiqueta `app: elasticsearch` para que funcione el descubrimiento automático. Sin esta etiqueta, el recolector no detectará ni monitoreará los pods.

Si utiliza un StatefulSet o un Deployment para Elasticsearch, agregue la etiqueta en la plantilla del pod:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: elasticsearch
spec:
  template:
    metadata:
      labels:
        app: elasticsearch  # Required for auto-discovery
    spec:
      containers:
      - name: elasticsearch
        image: docker.elastic.co/elasticsearch/elasticsearch:8.x.x
```

Para los pods existentes sin la etiqueta, actualice el StatefulSet/despliegue y reinicie los pods:

```bash
kubectl label pods -l <your-existing-selector> app=elasticsearch -n <namespace>
```

Puede verificar que las etiquetas estén configuradas correctamente:

```bash
kubectl get pods -n <namespace> --show-labels
```
</Step>

<Step>
## Prepare las credenciales y la configuración del recolector [#prepare]

Cree las credenciales que necesita el recolector y, luego, defina la configuración de monitoreo de Elasticsearch en un archivo `values.yaml`. Instalará el recolector con esta configuración en el siguiente paso.

1. Cree el namespace y un secreto para sus credenciales de New Relic:

   ```bash
   kubectl create namespace newrelic
   kubectl create secret generic newrelic-licenses \
     --from-literal=NEWRELIC_LICENSE_KEY=YOUR_LICENSE_KEY_HERE \
     --from-literal=NEWRELIC_OTLP_ENDPOINT=YOUR_NEWRELIC_OTLP_ENDPOINT \
     --from-literal=NEW_RELIC_MEMORY_LIMIT_MIB=100 \
     -n newrelic
   ```

   Reemplace el límite de memoria con un valor que se adapte al entorno.

### Parámetro de configuración [#configuration-parameters]

La siguiente tabla describe los parámetros de configuración clave utilizados en el `values.yaml` anterior:

| Parámetro                                       | Descripción                                                                                                                                                                            |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rule`                                          | La regla de coincidencia de pod utilizada para el descubrimiento automático. Actualice `labels["app"] == "elasticsearch"` para que coincida con las etiquetas de pod.                  |
| `endpoint`                                      | El extremo de Elasticsearch recopilado en cada pod descubierto. Actualice el puerto `9200` si Elasticsearch se ejecuta en un puerto diferente y use `https` para un clúster protegido. |
| `collection_interval`                           | El intervalo entre las extracciones de métricas. El valor predeterminado es 15s.                                                                                                       |
| `elasticsearch-cluster` (en `K8S_CLUSTER_NAME`) | Un nombre único que identifica este clúster en New Relic. Reemplace con un nombre que sea único en su cuenta.                                                                          |
| `NEW_RELIC_MEMORY_LIMIT_MIB`                    | El límite de memoria, en MiB, para el procesador `memory_limiter` del recolector. Configure un valor que se adapte al entorno.                                                         |
| `NEWRELIC_LICENSE_KEY`                          | Su [clave de licencia](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) de New Relic.                                                                                     |
| `NEWRELIC_OTLP_ENDPOINT`                        | El extremo OTLP de New Relic para la región de la cuenta. Consulte los [extremos OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp).                            |
</Step>

<Step>
## Instale y configure el recolector NRDOT mediante Helm [#install-helm]

Despliegue el recolector NRDOT en su clúster. Helm aplica la configuración del archivo `values.yaml` que acaba de crear.

1. Agregue y actualice el repositorio de charts de Helm de OpenTelemetry:

   ```bash
   helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
   helm repo update
   ```

2. Despliegue el recolector NRDOT:

   ```bash
   helm upgrade --install elasticsearch-nrdot-collector open-telemetry/opentelemetry-collector \
     --namespace newrelic \
     --create-namespace \
     -f values.yaml
   ```
</Step>

<Step>
## Verifique la instalación [#verify]

En un plazo de -5 minutos tras la instalación, ejecute esta consulta en New Relic para confirmar que los datos están fluyendo (reemplace `elasticsearch-cluster` por el nombre del clúster):

```sql
FROM Metric
SELECT *
WHERE metricName LIKE 'elasticsearch.%'
  AND instrumentation.provider = 'opentelemetry'
  AND k8s.cluster.name = 'elasticsearch-cluster'
SINCE 10 minutes ago
```

<Callout variant="tip">
También puede revisar el recolector en sí: el pod debe estar en estado `Running` (`kubectl get pods -n newrelic --watch`), con un nombre como `elasticsearch-nrdot-collector-<hash>`, sin errores de conexión en los logs del pod (`kubectl logs -n newrelic -l app.kubernetes.io/name=opentelemetry-collector -f`).
</Callout>

Si no ve datos en -5 minutos, consulte la [resolución de problemas de Kubernetes](/docs/opentelemetry/integrations/elasticsearch/troubleshooting#kubernetes-troubleshooting).
</Step>

<Step>
## Encuentra y utiliza tus datos [#find-and-use]

Una vez que New Relic recopile los datos, puede acceder al monitoreo de Elasticsearch a través de la UI de New Relic.

Para buscar el dashboard de Elasticsearch en New Relic:

1. Vaya a <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT>.
2. En la pestaña <DNT>**All**</DNT>, haga clic en <DNT>**Dashboards**</DNT>, luego busque <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> para ver el dashboard.

O, desde la navegación de la izquierda:

1. Haga clic en <DNT>**Dashboards**</DNT>.
2. Busque el dashboard <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> para verlo.

Después de configurar el monitoreo de Elasticsearch con NRDOT, puede:

* [Cree un dashboard personalizado](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar las métricas de Elasticsearch
* [Configure alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para umbrales críticos de estado y rendimiento del clúster
* [Explore los datos](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) con las capacidades de consulta de New Relic
</Step>
</Steps>

<Callout variant="tip">
**Correlacione APM con Elasticsearch**: para conectar la aplicación APM y el clúster de Elasticsearch, incluya el atributo de recurso `es.cluster.name="your-cluster-name"` en las métricas de APM. Esto le permite ver los datos de APM y Elasticsearch juntos en New Relic.
</Callout>
