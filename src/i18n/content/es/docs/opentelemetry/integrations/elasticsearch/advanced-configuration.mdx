Esta página cubre la configuración opcional para el monitoreo de Elasticsearch más allá de la configuración mínima: clústeres protegidos, métricas de host, recopilación de logs y etiquetas de metadatos personalizadas.

## Elasticsearch seguro con autenticación y SSL [#secured]

Agregue autenticación y TLS a la conexión de Elasticsearch cuando el clúster los requiera.

### Requisitos [#secured-requirements]

* Un usuario de Elasticsearch con el privilegio de clúster `monitor` o `manage`, y credenciales válidas para ese usuario.

Para Elasticsearch seguro con autenticación y SSL, modifique la configuración del receptor:

<CollapserGroup>
<Collapser id="secured-nrdot" title="NRDOT">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-otel" title="OTel Collector Contrib">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-k8s-nrdot" title="Kubernetes: NRDOT (manifiesto o Helm)">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>

<Collapser id="secured-k8s-otel" title="Kubernetes: OTel Collector Contrib">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>
</CollapserGroup>

### Parámetro de configuración [#secured-configuration-parameters]

La siguiente tabla describe los parámetros de configuración clave utilizados en los fragmentos anteriores:

| Parámetro                  | Descripción                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `endpoint`                 | La URL del clúster de Elasticsearch. Use `https://` para un clúster protegido.                                  |
| `username`                 | Un usuario de Elasticsearch con el privilegio de clúster `monitor` o `manage`.                                  |
| `password`                 | La contraseña para ese usuario.                                                                                 |
| `tls.insecure_skip_verify` | Si se debe verificar el certificado TLS de Elasticsearch. Establezca en `false` para habilitar la verificación. |
| `collection_interval`      | El intervalo entre las recopilaciones de métricas. Predeterminado: `15s`.                                       |
| `rule` (Solo Kubernetes)   | La regla de coincidencia de pods utilizada para el autodescubrimiento.                                          |

## Recopilar métricas del host [#host-metrics]

Para recopilar métricas del host, agregue el receptor `hostmetrics`:

<CollapserGroup>
<Collapser id="host-metrics-nrdot" title="NRDOT">
```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization: { enabled: true }
          system.cpu.time: { enabled: true }
      load:
        metrics:
          system.cpu.load_average.1m: { enabled: true }
          system.cpu.load_average.5m: { enabled: true }
          system.cpu.load_average.15m: { enabled: true }
      memory:
        metrics:
          system.memory.usage: { enabled: true }
          system.memory.utilization: { enabled: true }
      disk:
        metrics:
          system.disk.io: { enabled: true }
          system.disk.operations: { enabled: true }
      filesystem:
        metrics:
          system.filesystem.usage: { enabled: true }
          system.filesystem.utilization: { enabled: true }
      network:
        metrics:
          system.network.io: { enabled: true }
          system.network.packets: { enabled: true }
      process:
        metrics:
          process.cpu.utilization:
            enabled: true
```

Y agregue a los pipelines de servicio:

```yaml
service:
  pipelines:
    metrics/host:
      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="host-metrics-otel" title="OTel Collector Contrib">

### Parámetro de configuración [#host-metrics-configuration-parameters]

La siguiente tabla describe los parámetros de configuración clave utilizados en los fragmentos anteriores:

| Parámetro             | Descripción                                                                                                                                                                                                |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `collection_interval` | El intervalo entre las recopilaciones de métricas del host. Predeterminado: `60s`.                                                                                                                         |
| `scrapers`            | Las categorías de métricas a nivel de host a recopilar (`cpu`, `load`, `memory`, `disk`, `filesystem`, `network`, `process`). Deshabilite cualquier métrica que no necesite configurando `enabled: false`. |

## Recopilar logs de Elasticsearch [#logs]

### Requisitos [#logs-requirements]

* Acceso de lectura al archivo de log de Elasticsearch, para cualquier cuenta que ejecute el servicio del recolector:

  * Host de Linux: permiso de lectura en `/var/log/elasticsearch/`
  * Docker: permiso de lectura en `/var/lib/docker/containers/` (root o membresía en el grupo Docker)

Para recopilar logs de Elasticsearch, agregue el receptor `filelog`.

<CollapserGroup>
<Collapser id="logs-nrdot" title="NRDOT">
Asegúrese de que la cuenta que ejecuta el servicio del recolector (`nrdot-collector`) tenga acceso de lectura a los archivos de log de Elasticsearch.

**Si Elasticsearch se ejecuta en un host de Linux, use esta configuración:**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Si Elasticsearch se ejecuta en Docker, use esta configuración:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

Y agregue a los pipelines de servicio:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="logs-otel" title="OTel Collector Contrib">
Asegúrese de que la cuenta que ejecuta el servicio del recolector (`otelcol-contrib`) tenga acceso de lectura a los archivos de log de Elasticsearch.

**Si Elasticsearch se ejecuta en un host de Linux, use esta configuración:**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Si Elasticsearch se ejecuta en Docker, use esta configuración:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

Y agregue a los pipelines de servicio:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### Parámetro de configuración [#logs-configuration-parameters]

La siguiente tabla describe los parámetros de configuración clave utilizados en los fragmentos anteriores:

| Parámetro                 | Descripción                                                                                           |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| `include`                 | Rutas de archivo de log a seguir (host de Linux) o rutas de log de contenedor (Docker).               |
| `operators` (Solo Docker) | El operador que mueve la línea de log de `attributes.log` a `body` para que se muestre correctamente. |

## Agregar etiquetas de metadatos personalizadas [#custom-tags]

Para agregar etiquetas de metadatos personalizadas a las métricas, utilice el procesador `resource/static_override`:

<CollapserGroup>
<Collapser id="custom-tags-nrdot" title="NRDOT">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="custom-tags-otel" title="OTel Collector Contrib">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### Parámetro de configuración [#custom-tags-configuration-parameters]

La siguiente tabla describe los parámetros de configuración clave utilizados en los fragmentos anteriores:

| Parámetro | Descripción                                                                                         |
| --------- | --------------------------------------------------------------------------------------------------- |
| `key`     | El nombre del atributo a agregar, p. ej., `env`.                                                    |
| `value`   | El valor del atributo, p. ej., `production`.                                                        |
| `action`  | La acción a aplicar. Establezca en `upsert` para agregar el atributo o sobrescribirlo si ya existe. |

## Reinicie el recopilador [#restart]

Después de actualizar la configuración, reinicie el recolector para aplicar los cambios.

<CollapserGroup>
<Collapser id="restart-nrdot" title="NRDOT (autoalojado)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Collapser>

<Collapser id="restart-otel" title="OTel Collector Contrib (autohospedado)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```
</Collapser>

<Collapser id="restart-k8s" title="Kubernetes (NRDOT u OTel Collector Contrib)">
Para una instalación de manifiesto, reinicie el despliegue:

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```

Para una instalación de Helm, vuelva a ejecutar el mismo comando `helm upgrade --install ... -f values.yaml` del paso de instalación para implementar la configuración actualizada.
</Collapser>
</CollapserGroup>

## Verifique sus cambios [#verify]

Después de reiniciar el recolector, confirme que el cambio surtió efecto:

* **Clúster protegido**: vuelva a ejecutar la consulta de recolección de datos de la página de instalación. Si las métricas fluyen sin errores de TLS o de autenticación en los logs del recolector, la conexión protegida está funcionando.

* **Métricas del host**: ejecute esta consulta:

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'system.%' SINCE 10 minutes ago
  ```

* **Logs de Elasticsearch**: ejecute esta consulta:

  ```sql
  FROM Log SELECT count(*) SINCE 10 minutes ago
  ```

  Ajuste la cláusula `WHERE` para que coincida con sus propios atributos de log.

* **Etiquetas personalizadas**: ejecute esta consulta, utilizando la etiqueta de ejemplo de [Agregar etiquetas de metadatos personalizadas](#custom-tags):

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'elasticsearch.%' AND env = 'production' SINCE 10 minutes ago
  ```

Si no ve datos en -5 minutos, consulte la [resolución de problemas de Elasticsearch](/docs/opentelemetry/integrations/elasticsearch/troubleshooting).
