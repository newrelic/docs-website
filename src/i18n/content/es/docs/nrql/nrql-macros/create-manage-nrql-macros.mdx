Antes de crear una macro, revise los [permisos de macro](/docs/nrql/nrql-macros/nrql-macros-overview/#macro-permissions) y las reglas de nomenclatura y expresión a continuación. Una macro que no sigue estas reglas no supera la validación al intentar guardarla.

## Reglas y limitaciones de las macros [#macro-rules]

<Callout variant="important">
Las macros son visibles para todos los usuarios de la organización. No incluya información confidencial o específica de la cuenta al crear o actualizar una macro.
</Callout>

<CollapserGroup>
<Collapser id="macro-naming-rules" title="Reglas de nomenclatura">
Los nombres de las macros deben seguir estas reglas:

* Debe ser único dentro de la organización
* Debe ser un número entero no negativo, como `3`
* No debe contener el carácter `.`
* Debe tener 500 caracteres o menos
* No debe comenzar con el carácter `$`
* No debe encerrarse entre comillas invertidas al momento de la creación.
* Si el nombre de una macro contiene caracteres especiales, debe encerrarse entre comillas invertidas. Por ejemplo, `` $`my#Macro` ``.
</Collapser>

<Collapser id="macro-expression-rules" title="Reglas de expresión">
Las expresiones de macro deben seguir estas reglas:

* Debe ser una expresión NRQL válida o una lista de expresiones
* Debe tener 3000 caracteres o menos
* Debe ser una expresión, no una cláusula. Por ejemplo, `count(*)` es válido, pero `SELECT count(*)` no es válido.
* Debe ser una subconsulta entre paréntesis, no una consulta independiente. Por ejemplo, `(FROM Transaction SELECT uniques(userId))` es válido, pero `FROM Transaction SELECT uniques(userId)` no.
* Debe devolver atributos específicos, no una lista de atributos que contenga `*`

Ejemplos de expresiones válidas:

* `count(*)`
* `(1, 2, 3)`
* `(FROM Transaction SELECT uniques(userId))`
</Collapser>

<Collapser id="macro-limitations" title="Limitaciones">
Las macros de NRQL tienen las siguientes limitaciones:

* **Alertas**: las macros no son compatibles en las condiciones de alerta.
* **Autocompletar**: el generador de consultas no sugiere macros ni usa expresiones de macros para refinar las sugerencias.
* **Variables de plantilla**: no se pueden usar variables de plantilla dentro de las macros.
* **Macros anidadas**: las macros no se pueden anidar. La expresión de una macro no puede contener una referencia a otra macro.
* **Específicas de la región**: las macros son específicas de la región y solo se pueden usar dentro de la región principal de la organización.
* **Cláusulas de tiempo**: las cláusulas relacionadas con el tiempo, incluidas `TIMESERIES`, `PREDICT`, `BY`, `USING`, `SINCE`, `UNTIL` y `COMPARE WITH`, no admiten macros.
</Collapser>
</CollapserGroup>

## Acceso a macros [#macros-access]

En la plataforma de New Relic, vaya a <DNT>**Administration &gt; NRQL Macros**</DNT>. Desde esta página, puede ver, crear, editar y eliminar macros.

## Crear una macro [#create-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="create-ui">UI</TabsBarItem> <TabsBarItem id="create-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="create-ui">
Desde la página <DNT>**NRQL Macros**</DNT>, cree una macro proporcionando un nombre único y una expresión. Siga las reglas de [nomenclatura](#macro-naming-rules) y de [expresión](#macro-expression-rules). No anteponga el carácter `$` al nombre. Por ejemplo, para guardar una condición de cláusula `WHERE`, ingrese `appName = 'ProductionApp' AND environment = 'prod'` sin la palabra clave `WHERE`.

Después de crear una macro, esta aparece en la lista <DNT>**NRQL Macros**</DNT>. Puede usarla en cualquier consulta NRQL en todo New Relic.
</TabsPageItem>

<TabsPageItem id="create-nerdgraph">
También puede crear, actualizar y consultar macros de forma programática mediante la [API de NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/). Antes de crear o actualizar macros, revise las [reglas de nomenclatura](#macro-naming-rules), las [reglas de expresión](#macro-expression-rules) y las [limitaciones](#macro-limitations).

Para comenzar, vaya al [explorador de la API de NerdGraph](https://one.newrelic.com/nerdgraph-graphiql). Si necesita ayuda para usar el explorador de la API de NerdGraph, consulte el [tutorial del explorador de la API de NerdGraph](/docs/apis/nerdgraph/get-started/nerdgraph-explorer/).

Use la mutación `entityManagementCreateNrqlMacro`:

```graphql
mutation CreateMacro($name: String!, $expression: String!, $orgId: ID!) {
  entityManagementCreateNrqlMacro(
    nrqlMacroEntity: {
      expression: $expression
      name: $name
      scope: { type: ORGANIZATION, id: $orgId }
    }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

Variables de ejemplo:

```json
{
  "name": "prod_filter",
  "expression": "(appName = 'ProductionApp' AND environment = 'prod')",
  "orgId": "your-organization-id"
}
```

Para encontrar el ID de la organización, consulte [Buscar el ID de la organización o de la macro](#find-ids).
</TabsPageItem>
</TabsPages>
</Tabs>

## Usar una macro en una consulta [#use-macro]

Para usar una macro en las consultas NRQL, escriba `$` seguido del nombre de la macro en el generador de consultas. Por ejemplo, suponga que tiene una macro llamada `prod_filter` con la expresión `appName = 'ProductionApp' AND environment = 'prod'`. Puede usarla en una consulta como esta:

```sql
SELECT count(*) FROM Transaction WHERE $prod_filter SINCE 1 hour ago
```

Cuando se ejecuta la consulta, New Relic reemplaza la macro por su expresión:

```sql
SELECT count(*) FROM Transaction WHERE appName = 'ProductionApp' AND environment = 'prod' SINCE 1 hour ago
```

<Callout variant="tip">
Encierre los nombres de macro que contienen caracteres especiales entre acentos graves en el momento de la consulta. Por ejemplo: `` $`my#Macro` ``.
</Callout>

<Callout variant="important">
Las macros se insertan en línea antes de la ejecución, lo que afecta la precedencia de los operadores binarios. Por ejemplo, una macro llamada `five` definida como `1 + 4` y utilizada como `$five * 3` se evalúa como `13`, no como `15`, porque la expresión se convierte en `1 + 4 * 3`. Para evitar esto, encierre la expresión entre paréntesis al definir la macro, como en `(1 + 4)`, o encierre la macro entre paréntesis al usarla, como en `($five) * 3`. Cualquiera de los enfoques se evalúa correctamente como `15`.
</Callout>

Los siguientes ejemplos muestran macros que resuelven problemas de consulta comunes:

<CollapserGroup>
<Collapser id="macro-example-simplify" title="Ejemplo: simplificar una consulta">
Una consulta con múltiples condiciones, como esta, puede ser difícil de leer y mantener:

```sql
SELECT * FROM Log WHERE entityGuid = '...' AND appId NOT IN (...) AND ...
```

Guarde las condiciones después de `WHERE` como una macro llamada `macro1`, y la consulta se simplifica a:

```sql
SELECT * FROM Log WHERE $macro1
```
</Collapser>

<Collapser id="macro-example-single-edit" title="Ejemplo: actualizar múltiples widgets de dashboard desde un solo lugar">
Los dashboards con muchos widgets a menudo comparten una lógica de consulta repetida. Por ejemplo, la mayoría de los widgets en un dashboard podrían usar:

```sql
SELECT count(*) FROM Transaction WHERE http.statusCode NOT IN (400, 404)
```

Si guarda la condición `WHERE` como una macro llamada `macro2`, la consulta de cada widget se ve así:

```sql
SELECT count(*) FROM Transaction WHERE $macro2
```

Para excluir una aplicación de prueba de cada widget, actualice la expresión `macro2` una vez, de `http.statusCode NOT IN (400, 404)` a `http.statusCode NOT IN (400, 404) AND appId NOT IN (12345)`. Cada widget que usa `$macro2` refleja el cambio y no tiene que editar cada widget individualmente.
</Collapser>

<Collapser id="macro-example-alias" title="Ejemplo: resolver el problema de alias de atributo">
Los datos de diferentes agentes no siempre usan el mismo nombre de atributo para el mismo concepto. Un nombre de host, por ejemplo, se puede ingerir como `host.name`, `hostName` o `host_name` según la fuente.

Guarde una macro llamada `host_alias` con la expresión:

```sql
(host.name OR hostName OR host_name)
```

Luego, haga referencia a ella en las consultas:

```sql
FROM Log SELECT $host_alias
```

Si surge otro alias más adelante, como `host-name`, actualice la macro `host_alias` una vez y cada consulta que la use aplicará el cambio.
</Collapser>
</CollapserGroup>

## Administrar macros [#manage-macros]

### Editar una macro [#edit-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="edit-ui">UI</TabsBarItem> <TabsBarItem id="edit-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="edit-ui">
Desde la página <DNT>**NRQL Macros**</DNT>, seleccione la macro y actualice la expresión, siguiendo las [reglas de expresión](#macro-expression-rules).
</TabsPageItem>

<TabsPageItem id="edit-nerdgraph">
También puede actualizar la expresión de una macro de forma programática mediante [NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/). Revise las [reglas de expresión](#macro-expression-rules) antes de actualizarla.

Utilice la mutación `entityManagementUpdateNrqlMacro` .

```graphql
mutation UpdateMacro($expression: String!, $macroId: ID!) {
  entityManagementUpdateNrqlMacro(
    id: $macroId
    nrqlMacroEntity: { expression: $expression }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

Variables de ejemplo:

```json
{
  "expression": "(appName = 'ProductionApp' AND environment = 'prod' AND region = 'us-east-1')",
  "macroId": "your-macro-id"
}
```

Para encontrar el ID de una macro, consulte [Encontrar el ID de la organización o de la macro](#find-ids).
</TabsPageItem>
</TabsPages>
</Tabs>

<Callout variant="important">
Cuando edita una macro, todas las consultas que usan esa macro utilizan automáticamente la versión actualizada. Revise los cambios para asegurarse de que no rompan las consultas existentes. Debido al almacenamiento en caché, puede haber un ligero retraso antes de que la actualización surta efecto. No puede actualizar el nombre de una macro después de crearla. Si necesita cambiar el nombre, elimine la macro y cree una nueva.
</Callout>

## Encontrar el ID de la organización o de la macro [#find-ids]

<CollapserGroup>
<Collapser id="macro-find-org-id" title="Buscar el ID de la organización">
```graphql
query MyOrganizationId {
  actor {
    organization {
      id
    }
  }
}
```
</Collapser>

<Collapser id="macro-find-macro-id" title="Listar todas las macros y sus ID">
```graphql
query GetMacros($cursor: String) {
  actor {
    entityManagement {
      entitySearch(query: "type = 'NRQL_MACRO'", cursor: $cursor) {
        entities {
          ... on EntityManagementNrqlMacroEntity {
            id
            name
            expression
          }
        }
        nextCursor
      }
    }
  }
}
```
</Collapser>
</CollapserGroup>
