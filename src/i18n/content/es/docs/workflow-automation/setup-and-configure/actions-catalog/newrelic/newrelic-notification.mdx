Esta página proporciona una referencia de las acciones de notificación de New Relic disponibles en el catálogo de acciones de automatización de flujos de trabajo. Estas acciones le permiten enviar notificaciones a través de New Relic.

## Requisitos previos

Antes de usar las acciones de New Relic en la automatización del flujo de trabajo, asegúrese de tener lo siguiente:

* Una cuenta de New Relic con las licencias adecuadas.
* Una clave de licencia de New Relic (si se envían datos a una cuenta diferente).
* Las licencias necesarias para los servicios específicos de New Relic que planea emplear.

Consulta [Clave de licencia](/docs/apis/intro-apis/new-relic-api-keys#license-key) para obtener información sobre cómo crear y administrar tu clave de licencia de la cuenta de New Relic.

## Enviar mensaje

Envía mensajes o correos electrónicos a destinos New Relic. Primero debe crear el destino adecuado en New Relic y luego usar su ID en esta acción. El identificador de la acción es `newrelic.notification.send`.

      * **Slack**

      ```yaml
      name: slack_notification_workflow
      description: This is a test workflow to test slack notification send action
      steps:
        - name: SendMessageUsingSlackChannel
          type: action
          action: newrelic.notification.send
          version: 1
          inputs:
            type: slack
            destinationId: ccd0d926-ed6f-4ddd-bc7d-b7eb9822908d
            parameters:
              text: Hi , Testing notifcation api using slack channel name
              channel: test-channel-workflow
      ```

      * **Correo electrónico**

      ```yaml
      name: emailer-workflow
      description: send email using workflow
      steps:
        - name: emailReport1
          type: action
          action: newrelic.notification.email
          version: 1
          inputs:
            type: email
            destinationId: "e7a5a004-424d-44db-a3df-266980a90242"
            parameters:
              subject: "workflow notification"
              message: "this is a message."
            attachments:
              - type: QUERY
                query: "SELECT * FROM Log"
                format: CSV
                filename: "log_count.csv"
            selectors:
              - name: success
                expression: '.success'
              - name: sessionId
                expression: '.response.sessionId'
              - name: attachments
                expression: '.response.attachments'
      ```

## Crear una URL de señal

Genera una URL para enviar a un usuario a través de <DNT>Microsoft Teams</DNT>, <DNT>Slack</DNT> o <DNT>email</DNT> para que pueda enviar una señal a un flujo de trabajo en ejecución. Esta acción impulsa el [patrón human-in-the-loop](/docs/workflow-automation/workflow-examples/advanced/human-in-the-loop), donde un flujo de trabajo se pausa en un paso de espera hasta que una persona hace clic en la URL para aprobar, rechazar o enrutar la ejecución de otro modo.

<Callout variant="important">
  Esta acción no proporciona ningún beneficio por sí sola. Utilice siempre esta acción con:

  * Una **acción de notificación** (`newrelic.notification.*` o `slack.chat.postMessage`) que entrega la URL generada a una persona.
  * Un **paso de espera** que define al menos una señal para que la ejecución del flujo de trabajo espere.

  El `waitStepName` que proporcione como entrada debe coincidir con el nombre de un paso de espera válido en la misma definición del flujo de trabajo, y ese paso de espera debe contener al menos una señal. De lo contrario, la definición del flujo de trabajo falla la validación cuando la crea.
</Callout>
