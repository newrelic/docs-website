Esta página proporciona una referencia de las acciones de Azure App Service disponibles en el catálogo de acciones de automatización del flujo de trabajo. Estas acciones le permiten obtener, enumerar, iniciar, detener y reiniciar aplicaciones web de Azure App Service directamente desde una definición de flujo de trabajo, lo que habilita flujos de trabajo operativos, como los apagados programados para el control de costos, los reinicios desencadenados por un incidente y las comprobaciones previas antes de un paso para desplegar.

## Requisitos previos

Antes de usar las acciones de Azure App Service en la automatización del flujo de trabajo, asegúrese de tener:

* Una suscripción de Azure con uno o más App Services.
* Un registro de aplicación (entidad de servicio) de Entra (Azure AD) con los permisos necesarios.
* Las credenciales de registro de la aplicación almacenadas en New Relic Secrets Service.

## Configure la autenticación de Entra

Las acciones de Azure App Service se autentican mediante un flujo de OAuth2 de credenciales de cliente de entidad de servicio de Entra (Azure AD). Los permisos necesarios dependen de la acción:

* Rol de **Reader** (Lector) —necesario para `azure.appService.get` y `azure.appService.list`.
* **Contributor** (Colaborador) (o **Website Contributor** (Colaborador de sitio web) para el privilegio mínimo) —requerido para `azure.appService.start`, `azure.appService.stop` y `azure.appService.restart`.

<Steps>
<Step>
### Crear un registro de aplicación de Entra

1. En el portal de Azure, vaya a **Microsoft Entra ID &gt; App registrations** y haga clic en **New registration**.
2. Asigne un nombre al registro y haga clic en **Register**.
3. Tome nota del **ID de la aplicación (cliente)** y del **ID del directorio (inquilino)** —los necesitará como entradas.
4. En **Certificates &amp; secrets**, cree un nuevo secreto de cliente y copie el valor de inmediato.

Para obtener instrucciones completas, consulte [Registrar una aplicación para obtener token de autenticación](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/api/register-app-for-token).
</Step>

<Step>
### Asignar el rol requerido

Asigne al registro de la aplicación el rol **Reader** (para obtener/listar) o el rol **Contributor** / **Website Contributor** (para iniciar/detener/reiniciar) en el ámbito del App Service o grupo de recursos objetivo.

1. En el portal de Azure, navegue hasta el grupo de recursos objetivo o App Service.
2. Vaya a **Access control (IAM) &gt; Add role assignment**.
3. Seleccione el rol adecuado y asígnelo al registro de aplicación.
</Step>

<Step>
### Almacenar credenciales como secretos

Almacene `clientId`, `clientSecret` y `tenantId` en el servicio de secretos de New Relic y haga referencia a ellos en el YAML del flujo de trabajo usando la sintaxis de `${{ :secrets:keyName }}`:

```yaml
clientId: ${{ :secrets:azure-client-id }}
clientSecret: ${{ :secrets:azure-client-secret }}
tenantId: ${{ :secrets:azure-client-tenant }}
```
</Step>
</Steps>
