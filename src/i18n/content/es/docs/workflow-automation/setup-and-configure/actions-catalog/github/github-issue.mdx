Esta página proporciona una referencia de las acciones de incidencias de GitHub disponibles en el catálogo de acciones de automatización de flujo de trabajo. Estas acciones le permiten crear, actualizar, listar y administrar incidencias en un respositorio de GitHub directamente desde una definición de flujo de trabajo.

## Requisitos previos

Antes de usar las acciones de problemas de GitHub en la automatización del flujo de trabajo, asegúrese de tener:

* Una cuenta de GitHub con acceso al respositorio objetivo.
* Un token de acceso personal (PAT) de GitHub con los permisos requeridos.
* El PAT almacenado en el servicio de secretos de New Relic.

## Configurar la autenticación PAT

Las acciones de incidencias de GitHub se autentican mediante un token de acceso personal (PAT) que se pasa como credencial Bearer. Esta acción admite dos tipos de token:

* **Fine-grained PAT** — requiere el permiso de respositorio **Issues: Read and write**.
* **Classic PAT** —requiere el ámbito **repositorio**.

<Steps>
  <Step>
    ### Cree un token de acceso personal de GitHub

    1. En GitHub, vaya a **Settings &gt; Developer settings &gt; Personal access tokens**.
    2. Elija **Fine-grained tokens** o **Token (classic)** y haga clic en **Generate new token**.
    3. Establezca los permisos requeridos: **Issues: Read and write** para token de grano fino, o el alcance de **repositorio** para token clásicos.
    4. Copie el token generado —GitHub lo muestra solo una vez.
  </Step>

  <Step>
    ### Almacenar el token como un secreto

    Almacene el token en New Relic Secrets Service y haga referencia a él en el YAML del flujo de trabajo utilizando la sintaxis `${{ :secrets:keyName }}`:

    ```yaml
    token: ${{ :secrets:github-PAT-token }}
    ```
  </Step>
</Steps>
