Esta página proporciona una referencia de las acciones de ejecución de flujo de trabajo de GitHub disponibles en el catálogo de acciones de automatización de flujo de trabajo. Estas acciones le permiten desencadenar, recuperar y enumerar las ejecuciones de flujo de trabajo de GitHub Actions directamente desde una definición de flujo de trabajo, lo que permite la orquestación automatizada de CI/CD, las canalizaciones de despliegue y la automatización de versiones sin código personalizado ni herramientas externas.

## Requisitos previos

Antes de usar las acciones de ejecución de flujo de trabajo de GitHub en la automatización de flujo de trabajo, asegúrese de tener:

* Una cuenta de GitHub con acceso al respositorio objetivo.
* Un token de acceso personal (PAT) de GitHub con los permisos requeridos.
* El PAT almacenado en el servicio de secretos de New Relic.
* El flujo de trabajo objetivo configurado con un desencadenador `workflow_dispatch` (necesario para `gitHub.workflowRun.trigger`).

## Configurar la autenticación PAT

Las acciones de ejecución de flujo de trabajo de GitHub se autentican mediante un token de acceso personal (PAT) que se pasa como credencial Bearer. Esta acción admite dos tipos de token:

* **Fine-grained PAT** —requiere el permiso **Actions: write** para `gitHub.workflowRun.trigger`; **Actions: read** para `gitHub.workflowRun.get`, `gitHub.workflowRun.getLatest` y `gitHub.workflowRun.list`.
* **Classic PAT** —requiere el alcance **repositorio** para las cuatro acciones.

<Steps>
<Step>
### Cree un token de acceso personal de GitHub

1. En GitHub, vaya a **Settings &gt; Developer settings &gt; Personal access tokens**.
2. Elija **Fine-grained tokens** o **Token (classic)** y haga clic en **Generate new token**.
3. Establezca los permisos requeridos: **Actions: write** (o **Actions: read** para acciones de solo lectura) para token de grano fino, o el alcance **repositorio** para token clásicos.
4. Copie el token generado —GitHub lo muestra solo una vez.
</Step>

<Step>
### Almacenar el token como un secreto

Almacene el token en New Relic Secrets Service y haga referencia a él en el YAML del flujo de trabajo utilizando la sintaxis `${{ :secrets:keyName }}`:

```yaml
token: ${{ :secrets:github-PAT-token }}
```
</Step>
</Steps>
