El identificador de la acción es `newrelic.notification.createSignalUrl`.

Genera una URL para enviar a un usuario a través de <DNT>Microsoft Teams</DNT>, <DNT>Slack</DNT> o <DNT>email</DNT> para que pueda enviar una señal a un flujo de trabajo en ejecución. Esta acción impulsa el [patrón human-in-the-loop](/docs/workflow-automation/workflow-examples/advanced/human-in-the-loop), donde un flujo de trabajo se pausa en un paso de espera hasta que una persona hace clic en la URL para aprobar, rechazar o enrutar la ejecución de otro modo.

<Callout variant="important">
  Esta acción no proporciona ningún beneficio por sí sola. Utilice siempre esta acción con:

  * Una **acción de notificación** (`newrelic.notification.*` o `slack.chat.postMessage`) que entrega la URL generada a una persona.
  * Un **paso de espera** que define al menos una señal para que la ejecución del flujo de trabajo espere.

  El `waitStepName` que proporcione como entrada debe coincidir con el nombre de un paso de espera válido en la misma definición del flujo de trabajo, y ese paso de espera debe contener al menos una señal. De lo contrario, la definición del flujo de trabajo falla la validación cuando la crea.
</Callout>

                - name: createApprovalUrls
                  type: action
                  action: newrelic.notification.createSignalUrl
                  version: 1
                  inputs:
                    waitStepName: waitForApproval
                - name: newrelicNotificationMsTeam
                  type: action
                  action: newrelic.notification.sendMicrosoftTeams
                  version: 1
                  inputs:
                    destinationId: acc24dc2-d4fc-4eba-a7b4-b3ad0170f8aa
                    channel: "dev-channel"
                    teamName: "dev-team"
                    message: "To approve continue at: ${{ .steps.createApprovalUrls.outputs.url }}"
                - name: waitForApproval
                  type: wait
                  seconds: 3900 # 1 hour 5 minutes
                  signals:
                    - name: "approve"
                      next: logApproval
                    - name: "deny"
                      next: logDenial
                  next: handleTimeout
