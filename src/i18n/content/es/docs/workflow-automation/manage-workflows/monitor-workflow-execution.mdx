Este artículo describe cómo usar los datos de observabilidad para monitorear la ejecución del flujo de trabajo y la ejecución de la programación.

## Auditorías

Todas las llamadas de mutación de NerdGraph producen registros de auditoría que puede consultar en `NrAuditEvent` en la cuenta de clientes.

### WorkflowRun

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_run'
SINCE 1 hour ago
```

### WorkflowSchedule

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_schedule'
SINCE 1 hour ago
```

## Evento

Todas las ejecuciones del flujo de trabajo emiten datos de `WorkflowAutomationEvent` en NRDB en la cuenta de clientes que inició o programó el flujo de trabajo.

Las ejecuciones del flujo de trabajo almacenan datos de eventos en el namespace `WorkflowAutomation`.

El atributo `stepType` tiene los siguientes valores:

* `ACTION`: ejecuta una acción del catálogo
* `LOOP`: itera sobre una colección
* `SWITCH`: evalúa condiciones
* `STATE`: almacena pares de valor principal en el estado compartido del flujo de trabajo

### Consulta de ejemplo

La siguiente consulta devuelve todos los eventos para una ejecución específica del flujo de trabajo:

```sql
SELECT *
FROM WorkflowAutomationEvent
where definitionName = 'json-parsing' and runId = '31c973d2-c669-4bd7-9b15-7e3a70a4a074'
SINCE 1 month ago
```

## Logs

Opcionalmente, puede iniciar o programar un flujo de trabajo con una opción de verbosidad `logLevel`. Los registros van a la cuenta que inició o programó el flujo de trabajo.

Los logs incluyen los siguientes atributos:

* `workflowAutomation.name` es el nombre de WorkflowDefinition
* `workflowAutomation.version` es la versión de WorkflowDefinition
* `workflowAutomation.runId` es el runId del flujo de trabajo
* `entityGuid` es el ID de WorkflowDefinition

Si una ocurrencia de programación inició el flujo de trabajo, las entradas del log también incluyen `workflowAutomation.scheduleId`.

Para el tipo de paso de acción, al usar `DEBUG`, cada entrada de acción agrega un atributo adicional a la entrada de registro con el formato `workflowAutomation.inputs.<inputName>: <inputValue>`.

Para el tipo de paso de acción, al usar `TRACE`, cada salida de acción agrega un atributo adicional a la entrada de registro con el formato `workflowAutomation.outputs.<outputName>: <outputValue>`.

### Ejemplo de consulta NRQL

Puede consultar su log con la siguiente consulta NRQL:

```sql
SELECT message FROM Log WHERE workflowAutomation.runId = '{run_id}' SINCE 3 hours ago
```

<img title="Diagram of log attributes for workflow runs" alt="Diagram of log attributes for workflow runs" src="/images/log_attributes.webp" />

Además de `workflowAutomation.runId`, algunos otros atributos de log que pueden ayudar con la consulta de datos log son:

* `workflowAutomation.name`
* `workflowAutomation.version`

Para las ejecuciones programadas, las entradas del log también incluyen el atributo `workflowAutomation.scheduleId`.
