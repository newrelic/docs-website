<Callout title="avance">
Todavía estamos trabajando en esta característica, ¡pero nos encantaría que la probaras!

Esta característica se proporciona actualmente como parte de un programa de vista previa de conformidad con nuestras [políticas de prelanzamiento](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

<DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitorea el servicio después de cada despliegue que configure para el monitoreo. <DNT>Autopilot</DNT> comprueba el estado del servicio en los puntos de control programados, comenta en el pull request y reporta los resultados en <DNT>Slack</DNT> si lo ha conectado. Si detecta una regresión, también abre una incidencia de <DNT>GitHub</DNT> asignada a <DNT>GitHub Copilot</DNT>, que puede proponer una corrección como pull request si la organización tiene <DNT>GitHub Copilot Enterprise</DNT>.

<Callout variant="important">
<DNT>New Relic Change Tracking for GitHub Copilot</DNT> requiere un token <DNT>GitHub</DNT> con acceso de escritura además del acceso de lectura que describe [Conectar Autopilot a GitHub](/docs/agentic-ai/autopilot/connect-to-github). Agregue los permisos de escritura al token que ya conectó, o conecte un nuevo token que los tenga todos.
</Callout>

Cada despliegue configurado para monitoreo pasa por estas etapas:

1. Fusiona el pull request y su pipeline lo despliega. El despliegue envía un evento al seguimiento de cambios que incluye la URL de la etiqueta de lanzamiento, el SHA del commit de fusión y el atributo `watchpoint_monitoring`.
2. <DNT>Autopilot</DNT> valida el evento. Si pasa, <DNT>Autopilot</DNT> comenta en el pull request fusionado y, si conectó <DNT>Slack</DNT>, publica un mensaje de &quot;monitoreo iniciado&quot;.
3. En cada punto de control, <DNT>Autopilot</DNT> compara las métricas del servicio después del despliegue con las métricas anteriores a este. Informa uno de tres resultados (sin regresión, no concluyente o regresión detectada) como comentario en el pull request y, si conectó <DNT>Slack</DNT>, como respuesta en el mismo hilo. Los puntos de control se ejecutan a los 10 minutos, 30 minutos, 1 hora, 2 horas, 24 horas y 72 horas después del despliegue.

Cuando un punto de control detecta una regresión, <DNT>Autopilot</DNT> hace tres cosas:

* Publica una respuesta en el hilo de <DNT>Slack</DNT> (si conectó <DNT>Slack</DNT>) con las métricas relevantes y la evidencia detrás del hallazgo.
* Comenta en el pull request con las métricas relevantes, el punto de control que detectó la regresión y el motivo.
* Abre una incidencia de <DNT>GitHub</DNT> que describe qué sufrió una regresión, la evidencia de respaldo, dónde buscar y los criterios de aceptación, y luego asigna la incidencia a <DNT>GitHub Copilot</DNT>.

Si <DNT>Copilot</DNT> propone una corrección, revísela como lo haría con cualquier otro pull request antes de fusionarlo.

## Requisitos previos [#prerequisites]

Antes de configurar <DNT>New Relic Change Tracking for GitHub Copilot</DNT>, confirme lo siguiente:

* Ha configurado <DNT>Autopilot</DNT>. Consulte [Configurar Autopilot](/docs/agentic-ai/autopilot/setup).

* Es un <DNT>**New Relic Organization Manager**</DNT> y ha optado por <DNT>**New Relic Change Tracking for GitHub Copilot**</DNT> en <DNT>**[one.newrelic.com &gt; Administration](https://one.newrelic.com/admin-portal) &gt; Preview &amp; Trials**</DNT>.

* Tiene una cuenta de <DNT>GitHub</DNT> y un token con acceso de escritura a los respositorios que desea monitorear.

* Los despliegues envían eventos al [seguimiento de cambios](/docs/change-tracking/overview) con la [mutación `changeTrackingCreateEvent` ](/docs/change-tracking/config/nerdgraph). <DNT>New Relic Change Tracking for GitHub Copilot</DNT> no admite el extremo legacy.

* Cada evento incluye lo siguiente:

  * La URL de la etiqueta de versión en el campo `changelog`.
  * El SHA del commit de fusión en el campo `commit`.
  * El atributo personalizado `watchpoint_monitoring` establecido en `"true"`, para cada despliegue que desee monitorear.

* El servicio reporta a New Relic y tiene al menos 3 días de historial. Con menos datos, cada punto de control devuelve un resultado no concluyente.

De manera opcional, [conecte Autopilot a Slack](/docs/agentic-ai/autopilot/connect-to-slack) para recibir notificaciones. Para que <DNT>Copilot</DNT> comience a trabajar en el problema automáticamente, la organización necesita <DNT>GitHub Copilot Enterprise</DNT>.

## Configurar el seguimiento de cambios de New Relic para GitHub Copilot [#setup]

<Steps>
<Step>
### Crear un token de GitHub [#create-token]

Cree un token de acceso personal en <DNT>GitHub</DNT>. Se recomienda un token de grano fino, pero un token clásico también funciona. Para obtener instrucciones, consulte [Creación de un token de acceso personal de grano fino](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token) en la documentación de <DNT>GitHub</DNT>. Asegúrese de que el token tenga lo siguiente:

* La organización de <DNT>GitHub</DNT> como propietaria del recurso.
* Acceso a los respositorios que desea que <DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitoree.
* <DNT>**Read and write**</DNT> acceso a <DNT>**Pull requests**</DNT>, <DNT>**Issues**</DNT> y <DNT>**Contents**</DNT>.

Si ya conectó <DNT>GitHub</DNT> a <DNT>Autopilot</DNT> y ya tiene un token, puede agregar estos permisos a ese token en su lugar.

Si su organización exige el SSO de SAML, autorice el token para el SSO. <DNT>GitHub</DNT> muestra el token solo una vez, por lo que, al generarlo, cópielo y péguelo en New Relic de inmediato.
</Step>

<Step>
### Conectar GitHub y habilitar el monitoreo [#enable]

Para abrir la configuración de <DNT>Autopilot</DNT>, haga clic en <DNT>**Ask AI**</DNT>, haga clic en **...** y luego haga clic en <DNT>**Configure**</DNT>.

<img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp" />

En <DNT>**External MCP connections**</DNT>, conecte <DNT>**GitHub**</DNT> (<DNT>**Public GitHub**</DNT> o <DNT>**GitHub Enterprise Cloud**</DNT>) con el token y el nombre de la organización, y luego active <DNT>**Enable deployment monitoring**</DNT>. Para recibir notificaciones, seleccione también un canal de <DNT>Slack</DNT> en <DNT>**Post alerts to**</DNT>. Esta opción aparece solo después de conectar <DNT>Slack</DNT> a <DNT>Autopilot</DNT>.

Haga clic en <DNT>**Update agent**</DNT> para guardar los cambios.
</Step>

<Step>
### Confirme que se inició el monitoreo [#verify]

Despliegue un cambio con el atributo `watchpoint_monitoring` establecido en `"true"`.

<CollapserGroup>
<Collapser id="example-event" title="Evento de despliegue de ejemplo">
```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "MERGE_COMMIT"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```
</Collapser>
</CollapserGroup>

Después de que <DNT>Autopilot</DNT> valide el evento de despliegue, verá:

* Un comentario de <DNT>Autopilot</DNT> en el pull request fusionado.
* Si conectó <DNT>Slack</DNT>, un mensaje de &quot;monitoreo iniciado&quot; en el canal que seleccionó. Los resultados de los puntos de control posteriores aparecen como respuestas en ese hilo.

Si no aparece ninguno, verifique que el evento de despliegue cumpla los [requisitos previos](#prerequisites).
</Step>
</Steps>
