Las llamadas AJAX y fetch fallidas, como una integración de terceros defectuosa o una API de backend que devuelve un error 500, suelen causar páginas dañadas y experiencias del usuario confusas. La página <DNT>**Request errors**</DNT> agrupa estas requests fallidas para que pueda encontrar las llamadas API detrás de las páginas dañadas, ver con qué frecuencia fallan y saber por dónde empezar a depurar.

Errores de solicitud se basa en los eventos [`AjaxRequest`](/attribute-dictionary/?event=AjaxRequest) que el agente del browser ya recopila, por lo que no hay nada que instalar ni activar para comenzar a usarlo.

## Ver la página de errores de solicitud [#request-errors-page]

Para ver la página de errores de solicitudes, vaya a <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Request errors**</DNT>.

## Flujo de trabajo recomendado [#suggested-workflow]

Recomendamos el siguiente enfoque para investigar los errores de solicitud, de modo que pueda comprender el error, identificar los factores contribuyentes y comenzar a depurar:

1. **Vea las tendencias generales**: comience con los gráficos <DNT>**Error count**</DNT> y <DNT>**Errors by page**</DNT> para ver de un vistazo si hay picos, caídas o patrones inesperados.
2. **Agrupar y filtrar**: utilice las opciones de <DNT>**Group by**</DNT> y filtro para centrarse en dominios de solicitud, rutas de solicitud, códigos de respuesta o rangos de códigos específicos.
3. **Profundizar en un solo error**: seleccione una fila en la tabla de errores de solicitud para ver los detalles completos de la solicitud, incluidos la URL de la solicitud, el código de respuesta, el cuerpo de la respuesta y más.
4. **Revisar Session Replay y la traza de evento**: a partir de un error específico, revise la [traza de evento](#event-trail) y, cuando esté disponible, el [Session Replay](#session-replay) grabado durante esa ocurrencia.
5. **Consulte y comparta los datos**: en cualquier gráfico, seleccione el menú <DNT>**…**</DNT> y luego <DNT>**View query**</DNT> para explorar los datos de `AjaxRequest` subyacentes en el generador de consultas, o agregarlo a un dashboard.
6. **Cambiar la ventana de tiempo**: seleccione un nuevo periodo de tiempo en el menú desplegable del selector de tiempo.

## Aplicar detalles del error [#error-details]

Seleccione una fila en la tabla de errores de solicitudes para abrir los detalles de la solicitud como un panel apilado, que muestra la información completa de la solicitud, los atributos de la solicitud y el cuerpo de la respuesta para ese error.

### Perfiles [#error-profiles]

Desde la tabla de errores de request, seleccione <DNT>**View profiles**</DNT> para ver qué atributos distinguen más a este grupo de errores de request del resto del tráfico. Utilice los perfiles para identificar rápidamente qué tienen en común los requests afectados.

### Traza de evento [#event-trail]

Cuando selecciona un error específico, la traza de evento muestra las interacciones del navegador y las llamadas AJAX que lo provocaron. Esto le ayuda a comprender qué estaba haciendo el usuario cuando la request falló y si otras llamadas aproximadamente al mismo tiempo también se vieron afectadas.

### Session Replay [#session-replay]

Si se registró un Session Replay para la ocurrencia que está viendo, puede abrirlo desde los detalles del error para ver exactamente qué experimentó el usuario cuando falló la solicitud.

## Consultar y visualizar datos de error de solicitud [#insights]

New Relic guarda los datos de errores de solicitud como eventos `AjaxRequest`. Consulte el tipo de evento `AjaxRequest` en el [generador de consultas](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder) para ejecutar consultas de NRQL y crear dashboards a partir de los datos de errores de solicitud.
