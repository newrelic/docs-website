## Nuevas características y mejoras

* Se agregó soporte para Webflux 6 [1181](https://github.com/newrelic/newrelic-java-agent/pull/1181)

* Se agregó soporte para Spring JMS 6 [1088](https://github.com/newrelic/newrelic-java-agent/issues/1088)

* Se agregó soporte para Mongodb Reactive Streams [1164](https://github.com/newrelic/newrelic-java-agent/pull/1164)

* Se agregó soporte para Kafka Streams [1170](https://github.com/newrelic/newrelic-java-agent/pull/1170)

  El soporte para Kafka Streams se presenta en dos variantes: métricas y spans. Las métricas están habilitadas de forma predeterminada, mientras que los spans están deshabilitados de forma predeterminada. Para habilitar los spans, agregue lo siguiente a su configuración de *newrelic.yml* en la sección common:

```
common:
  class_transformer:
    kafka-streams-spans:
      enabled: true
```

* Huella de error: proporcione sus propios nombres de grupo de la bandeja de entrada de errores [1195](https://github.com/newrelic/newrelic-java-agent/pull/1195)

  ¿Sus ocurrencias de errores están mal agrupadas? Configure su propia huella de error mediante una función de devolución de llamada. Se ha agregado un nuevo método de API pública que aceptará un proc definido por el usuario. El procedimiento se invocará para cada error detectado y, siempre que devuelva una cadena, esa cadena se utilizará como el nombre del grupo de errores para el error y tendrá prioridad sobre cualquier agrupación del lado del servidor que se realice con Errors Inbox de New Relic. Esto brinda a los usuarios un control mucho mayor sobre la agrupación de sus errores. Para obtener más información, consulte nuestras páginas [API: agrupación de errores](/docs/apm/agents/java-agent/api-guides/java-agent-api-register-error-group-callback-to-set-fingerprint/) y [APM: pestaña de grupos de errores](/docs/triage-inbox/apm-tab/).

* Seguimiento de usuarios - asociar errores con un ID de usuario [1188](https://github.com/newrelic/newrelic-java-agent/pull/1188)

  Ahora puede ver la cantidad de usuarios afectados por un grupo de errores. Identifique al usuario final con un nuevo método de API pública que aceptará una representación de cadena de un ID de usuario y asociará ese ID de usuario con la transacción actual. Las transacciones y los errores tendrán entonces un nuevo atributo de agente `enduser.id` asociado a ellos. Esto permitirá a los usuarios del agente etiquetar transacciones y errores como pertenecientes a ID de usuario determinados para admitir mayores capacidades de filtrado y alerta. Para más información, consulte la documentación de \[Newrelic.setUserId ]\([https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName(java.lang.String)](https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName\(java.lang.String\)) y la página [Rastrear usuarios afectados con Errors Inbox](/docs/triage-inbox/error-users-impacted/).

* Invocar `token.link()` fuera de una transacción instrumentará ese método para iniciar una transacción asíncrona [1140](https://github.com/newrelic/newrelic-java-agent/pull/1140)

* La instrumentación de clientes Kafka tiene nuevas métricas para listar los nodos: `MessageBroker/Kafka/Nodes/&lt;node>` [1130](https://github.com/newrelic/newrelic-java-agent/pull/1130)

## Actualizar a la última versión [#procedures]

Para identificar qué versión del agente de Java estás usando actualmente, ejecuta `java -jar newrelic.jar -v`. Su versión de agente de Java se imprimirá en su consola.

Luego, para actualizar a la última versión del agente de Java:

1. Haga una copia de seguridad **de todo** el [directorio raíz del agente de Java ](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent)en otra ubicación. Cambie el nombre de ese directorio a `NewRelic_Agent#.#.#`, donde `#.#.#` es el número de versión del agente.
2. [Descarga el agente.](/docs/release-notes/agent-release-notes/java-release-notes)
3. Descomprima el archivo de descarga del nuevo agente y luego copie `newrelic-api.jar` y `newrelic.jar` en el [directorio raíz del agente de Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) original.
4. Compare su `newrelic.yml` antiguo con el `newrelic.yml` recién descargado del zip y [actualice el archivo si es necesario](#diff).
5. Reinicie su despachador de Java.

Si tiene problemas después de la actualización del agente de Java, restaure desde el directorio del agente New Relic respaldado.

## Actualizar diferencias de configuración del agente [#diff]

Agregamos nuevas configuraciones a `newrelic.yml` a medida que lanzamos nuevas versiones del agente. Puede usar `diff` u otra utilidad de diferenciación para ver qué ha cambiado y agregar la nueva configuración a su archivo anterior. Asegúrese de no sobrescribir ninguna personalización que haya realizado en el archivo, como su clave de licencia, el nombre de la aplicación o los cambios en la configuración predeterminada.

Por ejemplo, si `diff` los archivos `newrelic.yml` predeterminados para las versiones 7.10.0 y 7.11.0 del agente de Java , los resultados impresos en la consola serán como:

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

En este ejemplo, estas líneas se agregaron al `newrelic.yml` predeterminado en la versión 7.11.0 del agente Java. Si actualiza a la versión 7.11.0 o superior, debe agregar estas nuevas líneas a su `newrelic.yml` original.
