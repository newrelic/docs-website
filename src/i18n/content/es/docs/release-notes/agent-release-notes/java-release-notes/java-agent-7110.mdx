## Nuevas características y mejoras

* Soporte para Java 19 [1022](https://github.com/newrelic/newrelic-java-agent/pull/1022)

* Soporte para Play 2.8.16+ [981](https://github.com/newrelic/newrelic-java-agent/pull/981)

* Soporte para ojdbc8 v21.1.0.0+ [1042](https://github.com/newrelic/newrelic-java-agent/pull/1042)

* Soporte para JVMs Semeru/OpenJ9 [993](https://github.com/newrelic/newrelic-java-agent/pull/993)

* Soporte para el reenvío de logs para java.util.logging (JUL) [1049](https://github.com/newrelic/newrelic-java-agent/pull/1049)

* Soporte para el reenvío de datos de contexto de logs [866](https://github.com/newrelic/newrelic-java-agent/pull/866)

  El agente ahora puede reenviar datos en Mapped Diagnostic Context (MDC, logback/slf4j) y ThreadContext (log4j2) como atributos al reenviar registros de log. Cuando la funcionalidad está habilitada, estos atributos se agregarán a los registros de log con un prefijo `context.`. Para obtener detalles sobre cómo habilitar esta función, consulte la documentación de [context\_data](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#logging-context-data).

* Aumento del límite de eventos personalizados [1036](https://github.com/newrelic/newrelic-java-agent/pull/1036)

  Esta versión aumenta el límite predeterminado de eventos personalizados de 10 000 eventos por minuto a 30 000 eventos por minuto. En el caso de que se estuvieran limitando los eventos personalizados, este cambio permitirá enviar más eventos personalizados a New Relic. También hay un nuevo límite máximo configurable de 100 000 eventos por minuto. Para cambiar los límites, consulte la documentación de [max\_samples\_stored](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Custom_Events). Para obtener más información sobre el cambio y cómo determinar si se están descartando eventos personalizados, consulte nuestra [publicación](https://support.newrelic.com/s/hubtopic/aAX8W0000008dby/send-more-custom-events-with-the-latest-apm-agents) en el Explorers Hub.

* Métricas a nivel de código activadas por defecto [1037](https://github.com/newrelic/newrelic-java-agent/pull/1037)

  La funcionalidad de métricas a nivel de código introducida con el agente 7.10 ahora está habilitada de forma predeterminada. Esta función causará un aumento en el consumo de datos. La cantidad depende de la aplicación. Para desactivar las métricas a nivel de código, consulta las instrucciones en nuestra [documentación de métricas a nivel de código](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#code-level-metrics).

Los siguientes módulos de instrumentación se están marcando como obsoletos para su eliminación:

* cassandra-datastax-2.1.2
* httpclient-3.0
* jdbc-integrado-derby-10.10.1.1
* jetty-7
* jetty-7.6
* jetty-9
* jetty-9.0.4
* jetty-9.1
* mongodb-2.12
* mongodb-2.14
* mongodb-3.0
* okhttp-3.0.0
* okhttp-3.4.0
* okhttp-3.5.0

Los atributos de transacción/span `httpResponseCode`, `response.status` y `response.statusMessage` están obsoletos y se eliminarán en una versión futura. Estos han sido reemplazados por `http.statusCode` y `http.statusText`.

## Declaración de apoyo

New Relic recomienda actualizar el agente regularmente para asegurarse de obtener las últimas funciones y beneficios de rendimiento. Además, las versiones anteriores dejarán de tener soporte cuando lleguen al [fin de su vida útil](/docs/using-new-relic/cross-product-functions/install-configure/notification-changes-new-relic-saas-features-distributed-software/).

## Actualizar a la última versión [#procedures]

Para identificar qué versión del agente de Java estás usando actualmente, ejecuta `java -jar newrelic.jar -v`. Su versión de agente de Java se imprimirá en su consola.

Luego, para actualizar a la última versión del agente de Java:

1. Haga una copia de seguridad **de todo** el [directorio raíz del agente de Java ](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent)en otra ubicación. Cambie el nombre de ese directorio a `NewRelic_Agent#.#.#`, donde `#.#.#` es el número de versión del agente.
2. [Descarga el agente.](/docs/release-notes/agent-release-notes/java-release-notes)
3. Descomprima el archivo de descarga del nuevo agente y luego copie `newrelic-api.jar` y `newrelic.jar` en el [directorio raíz del agente de Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) original.
4. Compare su `newrelic.yml` antiguo con el `newrelic.yml` recién descargado del zip y [actualice el archivo si es necesario](#diff).
5. Reinicie su despachador de Java.

Si tiene problemas después de la actualización del agente de Java, restaure desde el directorio del agente New Relic respaldado.

## Actualizar diferencias de configuración del agente [#diff]

Agregamos nuevas configuraciones a `newrelic.yml` a medida que lanzamos nuevas versiones del agente. Puede usar `diff` u otra utilidad de diferenciación para ver qué ha cambiado y agregar la nueva configuración a su archivo anterior. Asegúrese de no sobrescribir ninguna personalización que haya realizado en el archivo, como su clave de licencia, el nombre de la aplicación o los cambios en la configuración predeterminada.

Por ejemplo, si `diff` los archivos `newrelic.yml` predeterminados para las versiones 7.10.0 y 7.11.0 del agente de Java , los resultados impresos en la consola serán como:

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

En este ejemplo, estas líneas se agregaron al `newrelic.yml` predeterminado en la versión 7.11.0 del agente Java. Si actualiza a la versión 7.11.0 o superior, debe agregar estas nuevas líneas a su `newrelic.yml` original.
