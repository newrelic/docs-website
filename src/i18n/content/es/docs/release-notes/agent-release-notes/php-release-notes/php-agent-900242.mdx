### Nuevas características en 9.0

**Las trazas de la transacción detalladas ahora están disponibles cuando el rastreo distribuido está habilitado.**

Esta versión incluye una refactorización del almacenamiento de segmentos para permitir que el agente ordene y aplique diferentes priorizaciones de segmentos que se utilizan para las trazas de la transacción en lugar del rastreo distribuido. La versión 8.4 del agente PHP incluyó soporte limitado para el rastreo distribuido, lo que resultó en la pérdida de trazas de la transacción detalladas para servicios PHP individuales cuando el rastreo distribuido estaba habilitado.

La refactorización en esta nueva versión permite al agente enviar los segmentos (spans) que desea ver para un rastreo distribuido que incluye servicios PHP. También proporciona por separado el mayor detalle posible de los segmentos al explorar las trazas de la transacción para un servicio PHP individual.

Notas:

* Las [instrucciones para habilitar el rastreo distribuido](https://docs.newrelic.com/docs/agents/php-agent/features/distributed-tracing-php-agent#enable-distributed) no han cambiado con esta versión.
* El comportamiento de `newrelic.transaction_tracer.detail` ha cambiado cuando el rastreo distribuido está activado. En las versiones 8.4 - 8.7 del agente PHP, `newrelic.transaction_tracer.detail` estaba desactivado cuando el rastreo distribuido estaba activado. Esto ya no es así. Para obtener más información, consulte la documentación sobre [cómo configurar el nivel de detalle de la traza al usar el rastreo distribuido](https://docs.newrelic.com/docs/agents/php-agent/features/distributed-tracing-php-agent#performance).
* Para habilitar el soporte mejorado para el rastreo distribuido, la estrategia de asignación de memoria del agente PHP ha cambiado en la versión 9.0. El agente PHP asignará memoria de manera más agresiva cuando se inicie una transacción, y el asignador del sistema puede optar por no liberar esa memoria al sistema operativo de inmediato, dependiendo de la configuración del kernel del sistema operativo y la biblioteca de C. Como resultado, el uso de memoria de los procesos PHP ahora puede ser mayor que con versiones anteriores del agente PHP.

### Avisos de actualización para 9.0

**Con estas mejoras del rastreo distribuido, verifique los valores de los umbrales**.

* En las versiones 8.4-8.7 del agente PHP, recomendamos que los clientes configuraran `newrelic.transaction_tracer.threshold = 0` para que el agente reportara el rastreo distribuido completo incluso cuando un servicio PHP ligero fuera parte de la traza. Esto ya no es necesario.
* Al actualizar a la versión 9.0, le recomendamos que revise la configuración de `newrelic.transaction_tracer.threshold` y restablezca este valor a su valor por defecto o a un valor superior que sea adecuado para la aplicación.

**El daemon ahora emitirá una advertencia si no puede encontrar un paquete de certificados raíz durante el inicio.**

* El daemon incluye sus propios certificados y seguirá funcionando, pero una versión futura del agente PHP eliminará los certificados integrados. En ese momento, el agente PHP no podrá comunicarse con los servidores de New Relic.
* **Recomendación:** asegúrese de que haya un paquete de certificados raíz instalado en el host o en el contenedor antes de usar el agente PHP. Esto generalmente está disponible en la mayoría de las distribuciones de Linux como un paquete `ca-certificates`. En FreeBSD, hay un paquete disponible a través del paquete `security/ca_root_nss` en ports.

**El daemon ya no se puede invocar con la bandera `--tls`.**

* A partir de la versión 8.0.0 del agente PHP, la configuración ini newrelic.daemon.ssl se había eliminado para aumentar la seguridad, pero aún se podía invocar el daemon desde la línea de comando con `--tls true`. Las invocaciones de línea de comando del daemon con la bandera `--tls` harán que la invocación falle.
* Al igual que con todas las versiones del agente PHP desde la 8.0.0, TLS siempre se utiliza para la comunicación con los servidores de New Relic.

### Corrección de errores

* Se ha solucionado un posible segfault al usar `drupal_http_request` en PHP 7.3.
* En algunos casos, iniciar una nueva transacción durante una solicitud (a través de `newrelic_start_transaction` o `newrelic_set_appname`) podría resultar en un estado incompleto del framework y de la instrumentación de la función del usuario.
* Al ofuscar SQL, los comentarios se eliminan sin ninguna pérdida del SQL en sí.
* Los comandos de Predis 0.8 que utilizaban la ruta de código `executeCommand()` síncrona (por ejemplo, `HSET`) en una conexión en clúster no generaban métricas. Esto se ha solucionado.

### Problemas conocidos y soluciones alternativas

**Posible agotamiento de memoria en transacciones de larga duración**

El agente PHP 9.x usa más memoria que las versiones anteriores, ya que es menos agresivo a la hora de liberar la memoria utilizada para rastrear llamadas a funciones y segmentos durante las transacciones: en el caso normal, la memoria solo se libera al final de cada transacción.

Esto tiende a manifestarse principalmente en los usuarios con transacciones de larga duración, como trabajos en segundo plano para procesar colas de mensajes, transformar o generar informes sobre datos, o enviar correos electrónicos.

Pedimos disculpas por los inconvenientes que este problema ha causado y estamos trabajando activamente para solucionarlo. A corto plazo, tenemos cuatro posibles soluciones alternativas para mitigar este problema.

Soluciones alternativas:

* **1. Inicie/detenga las transacciones manualmente.** Si la transacción afectada es una que realiza una serie de procesos repetitivos, como un consumidor de cola de mensajes, puede instrumentar manualmente cada iteración como una transacción independiente. Esto le proporciona datos más detallados sobre cómo opera el proceso. Al hacer esto, la memoria utilizada se liberará después de cada transacción. Para implementar esto, debería ignorar la transacción automática inicial con `newrelic_end_transaction(true)`, y luego usar `newrelic_start_transaction()`y `newrelic_end_transaction()` para instrumentar cada transacción a su vez.
* **2. Reduzca el detalle de la traza de la transacción.** Si necesita PHP 7.4 de inmediato, o cualquiera de las funcionalidades agregadas en las versiones 9.x del agente PHP, y le basta con trazas que solo incluyan información sobre el almacenamiento de datos y llamadas externas, entonces puede reducir el nivel de detalle que captura el agente PHP cambiando esta configuración: `newrelic.transaction_tracer.detail = 0`. Con esta configuración, las trazas ya no contendrán llamadas a funciones de PHP. **NOTA: las transacciones que realizan cientos de miles de llamadas al almacenamiento de datos o externas aún pueden verse afectadas por problemas de memoria.**
* **3. Desactualice al agente PHP 8.7.** Si no tiene la intención de usar PHP 7.4 de inmediato, es probable que esta sea la solución más simple y rápida. Para desactualizar, puede instalar desde los tarballs en [https://download.newrelic.com/php\_agent/archive/8.7.0.242/](https://download.newrelic.com/php_agent/archive/8.7.0.242/), o desactualizar a la versión 8.7.0.242 en el administrador de paquetes y fijar esa versión. Tenga en cuenta que si el rastreo distribuido está habilitado en el agente PHP 8.7, el detalle del rastreador de transacciones se reduce automáticamente (según la siguiente opción).
* **4. Limite el número de segmentos de función que se crean** (permanezca en el agente PHP 9.x). Esto es similar a la opción “reducir el detalle de la traza de la transacción”, pero también permite la traza de un número limitado de llamadas a funciones PHP, a costa de un aumento en el uso de memoria proporcional al número de funciones que se capturan. (Como regla general, cada segmento requiere unos 320-400 bytes del montón). Para capturar las primeras 5000 llamadas a funciones, agregaría esta configuración: `newrelic.transaction_tracer.max_segments = 5000`. Con esta configuración, se ignorará cualquier función PHP posterior al número de llamadas a funciones configuradas. **NOTA: las transacciones que realizan cientos de miles de llamadas externas o al almacenamiento de datos aún pueden verse afectadas por problemas de memoria.**

\*\**NOTA: una explicación más detallada de estas opciones se puede encontrar en nuestra [publicación de Explorer’s Hub](https://support.newrelic.com/s/hubtopic/aAX8W0000008aaT/potential-memory-exhaustion-for-long-running-transactions-with-php-agent-9x).*
