## v10.9.0

* **Característica: perfilado continuo (versión preliminar)**

  El perfilado continuo es una nueva característica que aún no está disponible para uso general. El código del componente del lado del agente ya está presente en el agente, pero para usarlo realmente antes del lanzamiento de disponibilidad general, deberá comunicarse con el representante de ventas de New Relic para unirse a la versión preliminar de forma anticipada.

  Continuous Profiling toma muestras repetidamente de los stack de llamadas de Ruby de la aplicación en ejecución y los reporta a New Relic, para que pueda ver qué métodos consumen más tiempo de CPU (o asignan más objetos) en producción, sin agregar código a la aplicación.

  Para activarlo, agregue las gemas [`stackprof`](https://rubygems.org/gems/stackprof) y [`google-protobuf`](https://rubygems.org/gems/google-protobuf) al `Gemfile` de la aplicación, y luego establezca `profiling.enabled` en `true`:

  ```yaml
    profiling.enabled: true
  ```

  Con solo `profiling.enabled` configurado, el agente toma muestras del tiempo de CPU cada 10 milisegundos durante la vida del proceso. Estas opciones le permiten ajustar ese comportamiento:

  | Nombre de la configuración             | Por defecto | Comportamiento                                                                                                                        |
  | -------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------- |
  | profiling.enabled                      | `false`     | Si `true`, el agente recopila y reporta datos de perfilado continuo.                                                                  |
  | profiling.include                      | `cpu`       | Qué muestrear: `cpu` para el tiempo de CPU o `object` para las asignaciones de objetos.                                               |
  | profiling.sample\_period               | `0.01`      | Segundos entre muestras de stack. Solo se utiliza cuando `profiling.include` es `cpu`. Debe estar entre 0.000001 y 0.999999.          |
  | profiling.object\_allocation\_interval | `10000`     | Asignaciones de objetos entre muestras de stack. Solo se usa cuando `profiling.include` es `object`. Debe estar entre 1000 y 999 999. |
  | profiling.delay                        | `0`         | Milisegundos de espera antes de que comience el perfilado. `0` comienza de inmediato.                                                 |
  | profiling.duration                     | `0`         | Milisegundos de perfilado antes de detenerse automáticamente. `0` perfila hasta que el proceso finaliza.                              |

  [PR#3617](https://github.com/newrelic/newrelic-ruby-agent/pull/3617)

* **Característica: agregar soporte para Dalli 5.1.1**

  Dalli 5.1.1 agregó argumentos a algunos de los métodos instrumentados por el agente, lo que podría generar un `ArgumentError` en operaciones de múltiples claves o hacer que las opciones de solicitud se descarten silenciosamente. Ahora, el agente acepta y reenvía un número variable de argumentos posicionales y de palabras clave para estos métodos. [PR#3683](https://github.com/newrelic/newrelic-ruby-agent/pull/3683)
