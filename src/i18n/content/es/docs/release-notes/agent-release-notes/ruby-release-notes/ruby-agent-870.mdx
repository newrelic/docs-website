## v8.7.0

* **Reenvío de logs de logs en el contexto APM habilitado de forma predeterminada**

  El reenvío automático de logs de aplicación ahora está habilitado por defecto. Esta versión del agente enviará automáticamente el log de aplicación enriquecido a New Relic. Para obtener más información sobre esta característica, consulte [aquí](https://docs.newrelic.com/docs/apm/new-relic-apm/getting-started/get-started-logs-context/), y las opciones de configuración adicionales están disponibles [aquí](https://docs.newrelic.com/docs/logs/logs-context/configure-logs-context-ruby). Para obtener información sobre cómo activar o desactivar la ingesta de logs por cuenta, consulte [aquí](https://docs.newrelic.com/docs/logs/logs-context/disable-automatic-logging).

* **Soporte asíncrono mejorado e instrumentación de Thread**

  Anteriormente, el agente no podía registrar eventos y métricas dentro de los Hilos creados dentro de una transacción ya en ejecución. Esta versión incluye 2 nuevas opciones de configuración para permitir que las aplicaciones multihilo puedan instrumentar hilos automáticamente. Se ha introducido una nueva opción de configuración,`instrumentation.thread.tracing` (desactivada por defecto), que, cuando está habilitada, permitirá que el agente inserte el rastreo de New Relic dentro de todos los Hilos creados por una aplicación. Para admitir las aplicaciones que solo desean que algunos hilos estén instrumentados por New Relic, hay una nueva clase disponible, `NewRelic::TracedThread`, que creará un hilo que incluye la instrumentación de New Relic; consulte nuestra [documentación de la API](https://www.rubydoc.info/gems/newrelic_rpm/NewRelic) para obtener más detalles.

* **Descontinuar la compatibilidad con Ruby 2.2**

  Ruby 2.2 llegó al final de su vida útil el 31 de marzo de 2018. El agente ha descontinuado el soporte para Ruby 2.2 y realizará cambios incompatibles para esta versión en su próxima versión principal.

  Para las gemas con versiones descontinuadas, ya no probaremos esas versiones en la suite multiverse. Sin embargo, es posible que sigan siendo compatibles con el agente. Ya no solucionaremos los informes de errores para los problemas con estas versiones de la gema.

* **Aprovechar internamente `Object.const_get` y `Object.const_defined?`**

  Al verificar u obtener dinámicamente una referencia a una constante de clase a partir de una cadena, aproveche los métodos integrados de la clase `Object` siempre que sea posible para lograr operaciones más sencillas y eficientes. Todos los JRubies y CRubies v2.5 y anteriores necesitan un poco de ayuda más allá de lo que `Object` puede proporcionar, dado que esos Rubies pueden generar una constante no deseada de un namespace diferente al que se especificó. Pero para todos los demás Rubies, e incluso para aquellos Rubies en contextos donde podemos confiar al 100 % en el valor de la cadena entrante, aproveche los métodos de la clase `Object` y disfrute de los beneficios.

* **Aclarar la documentación para la configuración de `rake.tasks`**

  La descripción de `rake.tasks` en el archivo `newrelic.yml` predeterminado y la [documentación de configuración del agente de Ruby de New Relic](https://docs.newrelic.com/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration#rake-tasks) se han actualizado para aclarar su comportamiento y uso. La documentación ahora indica:

  > Especifique una matriz de tareas de Rake a las que aplicar el instrumento automáticamente. Esta opción de configuración convierte la matriz en una lista de expresiones regulares. Si desea permitir todas las tareas de forma predeterminada, use `rake.tasks: [.+]`. Las tareas de Rake no tendrán un estado instrumentado a menos que se agreguen a esta lista. Para obtener más información, visite la (documentación de instrumentación de Rake de New Relic para el agente APM)\[/docs/apm/agents/ruby-agent/background-jobs/rake-instrumentation].

  Agradecemos a @robotfelix por sugerir estos cambios.

* **Habilitar variables de entorno que establecen la configuración de matriz para que se conviertan en matriz**

  Antes de este cambio, cuando se pasaban listas separadas por comas como variables de entorno, se emitía un error a `newrelic_agent.log` y se establecía un String como valor. Ahora, la matriz se convertirá con precisión.

* **Corrección de errores: permitir que TransactionEvents se muestree a la tasa esperada**

  El valor de capacidad `transaction_events.max_samples_stored` dentro de TransactionEventAggregator no coincidía con el intervalo de su ciclo de recolección esperado, lo que provocaba un sobremuestreo de TransactionEvents. Esta corrección de errores se basa en las actualizaciones realizadas en [#952](https://github.com/newrelic/newrelic-ruby-agent/pull/952) para que el intervalo y la capacidad se comporten según lo esperado para las opciones de configuración `transaction_events*` renombradas.

* **Corrección de error: faltan atributos en los eventos de error cuando se crean fuera de una transacción**

  Anteriormente, el agente no asignaba una prioridad a los eventos de error que se creaban al llamar a notice\_error fuera del alcance de una transacción. Esto provocó problemas con el muestreo cuando el búfer de eventos de error estaba lleno, lo que resultó en un `NoMethodError: undefined method '<' for nil:NilClass` en el newrelic\_agent.log. Esta corrección de errores garantiza que siempre se asigne una prioridad a los eventos de error para que el agente pueda muestrear estos eventos de error correctamente. Gracias a @olleolleolle por informarnos sobre este problema.

## Declaración de apoyo

New Relic recomienda que actualice el agente regularmente y, como mínimo, cada 3 meses. A partir de este lanzamiento, la versión compatible más antigua es la [5.7.0.350](https://docs.newrelic.com/docs/release-notes/agent-release-notes/ruby-release-notes/ruby-agent-570350).
