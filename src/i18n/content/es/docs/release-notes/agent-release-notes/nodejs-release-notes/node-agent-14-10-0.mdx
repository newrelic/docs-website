### Característica

* Se agregó soporte para `@opentelemetry/api@1.10.0` ([#4392](https://github.com/newrelic/node-newrelic/pull/4392)) ([504490d](https://github.com/newrelic/node-newrelic/commit/504490dd9540e6d5312441d9feec29b47bfe959a))

  * Los clientes que utilizan directamente `@opentelemetry/api-logs` deben eliminarlo y actualizar para usar `@opentelemetry/api` 1.10.0+. Consulte [el changelog de la API de OpenTelemetry](https://github.com/open-telemetry/opentelemetry-js/blob/main/api/CHANGELOG.md#1100) para obtener más información.
  * Los clientes que registran instrumentación de terceros para bibliotecas de logging deben actualizar a lo siguiente: `@opentelemetry/instrumentation-pino` a 0.70.0+, `@opentelemetry/instrumentation-bunyan` a 0.69.0+, `@opentelemetry/instrumentation-console` a 0.6.0+, o `@opentelemetry/instrumentation-winston` a 0.69.0+

### Corrección de errores

* Se contrajeron las métricas de matriz de argumentos de Apollo Server ([#4350](https://github.com/newrelic/node-newrelic/pull/4350)) ([baf35fd](https://github.com/newrelic/node-newrelic/commit/baf35fd6b906dd4d733f0a2f13d600cb42fec246))
  * Para aprovechar esta característica, debe configurar tanto `config.apollo_server.field_metrics` como `config.apollo_server.collapse_field_metrics` en `true`. ¡Gracias a @cpruijsen por la contribución!

### Declaración de apoyo

Recomendamos actualizar a la última versión del agente tan pronto como esté disponible. Si no puede actualizar a la última versión, actualice su agente a una versión que no tenga más de 90 días de antigüedad. Obtenga más información sobre [cómo mantener al agente actualizado](/docs/new-relic-solutions/new-relic-one/install-configure/update-new-relic-agent/).

Consulta la [política de EOL](/docs/apm/agents/nodejs-agent/getting-started/nodejs-agent-eol-policy/) del agente de Node.js de New Relic para obtener información sobre las versiones del agente y las fechas de soporte.
