### Nueva característica

* Se agregó el filtrado de atributos del agente mediante reglas de inclusión y exclusión.

  Los [atributos del agente](/docs/agents/nodejs-agent/attributes/nodejs-agent-attributes) ahora se pueden controlar mediante reglas de inclusión y exclusión detalladas. Estas reglas, que se describen a continuación, reemplazan a `capture_params` y `ignored_params`. Cualquier atributo enumerado en `ignored_params` se migrará a `attributes.exclude` internamente, a menos que `attributes.exclude` se establezca de forma explícita.

  Hay tres nuevas propiedades de configuración agregadas a la configuración raíz y a cada destino (más sobre los destinos más adelante). Estas nuevas opciones de configuración son:

  * `attributes.enabled` - Habilita la recopilación de atributos para el destino.
  * `attributes.include` - Una lista de atributos o reglas de comodines para incluir.
  * `attributes.exclude` - Una lista de atributos o reglas de comodín para excluir.

  Las reglas de inclusión y exclusión pueden ser reglas exactas (por ejemplo, `request.headers.contentLength`) o reglas de comodín que coinciden solo con el principio de las claves de atributo (por ejemplo, `request.headers.*` coincidiría con cualquier encabezado de solicitud).

  Estas reglas se pueden especificar globalmente en la raíz de la configuración o para destinos específicos. Estos destinos son:

  * `transaction_tracer` - Controla los atributos de la traza de la transacción.
  * `transaction_events` - Controla los atributos del evento de transacción.
  * `error_collector` - Controla los atributos de evento de error.
  * `browser_monitoring` - Controla los atributos de transacción de navegador/RUM.

* Se cambió el nombre de `addCustomParameter` a `addCustomAttribute`.

  El método `addCustomParameter` ahora está obsoleto y se eliminará en una versión futura del agente. El método `addCustomAttribute` es un reemplazo directo para este.

* Se agregó caché al filtrado de atributos del agente.

  Para minimizar la sobrecarga de aplicar reglas de atributo, el agente almacena en caché los resultados de filtrar claves de atributo y destinos específicos. La caché está limitada a 1000 pares de destino-clave por defecto, pero se puede configurar con `attributes.filter_cache_limit`. Esta caché ofrece una mejora de 10x al aplicar reglas de filtro para aciertos de caché.

* Se agregó `allow_all_headers` a las opciones de configuración y se actualizó la instrumentación de `http`.

  Cuando se establece en `true`, el agente recopilará todos los encabezados de solicitud. Esta recopilación respeta las reglas de inclusión y exclusión del atributo del agente. Se proporciona un conjunto predeterminado de reglas de exclusión en `newrelic.js`. Estas reglas excluyen todas las cookies y los encabezados de autenticación.

* Ahora los segmentos pueden marcarse como opacos, lo que hace que los segmentos internos se omitan de la traza de la transacción.

### Mejoras

* Se agregaron límites para los atributos del agente para mantener baja la sobrecarga de monitoreo.

  Las claves y los valores de los atributos están limitados a 255 bytes cada uno. Las claves que superan los 255 bytes se descartan y se registra un mensaje de advertencia. Los valores que superan los 255 bytes se truncan a 255 bytes, respetando la codificación UTF-8 de varios bytes. Los atributos personalizados están limitados a 64 por transacción. Los atributos posteriores al 64.º se ignoran de forma silenciosa.

* Se agregó el error al mensaje de log de falla de conexión del recolector.

* Se cambió el nombre del atributo `request_uri` a `request.uri`.

  Esto alinea el nombre del atributo con todos los demás atributos de solicitud.

* Se actualizó la dependencia `https-proxy-agent` de `^0.3.5` a `^0.3.6`.

* Se actualizaron las pruebas versionadas donde corresponde para garantizar que la mayoría de las versiones menores de los módulos instrumentados funcionen como se espera.

* Se corrigió la prueba bloqueada para la línea v1 del controlador de Mongo.

* Se agregaron pruebas que verifican que las transacciones 404 de Hapi resulten en métricas con nombres correctos.

  La instrumentación de Hapi estaba haciendo lo correcto, pero no teníamos pruebas para este caso específico.

### Corrección de errores

* El agente ya no fallará cuando se haya cambiado `crypto.DEFAULT_ENCODING`.

  Anteriormente, el agente asumía que el resultado de `hash.digest()` era una instancia de un Buffer. Si se cambia `crypto.DEFAULT_ENCODING`, `hash.digest()` devolverá una cadena y el agente se bloqueará. El agente ahora se asegura de que el valor sea una instancia de Buffer antes de continuar.

* Se corrigió el error si falta `process.config.variables.node_prefix`.

  Si `process.config.variables.node_prefix` es falso (lo que puede ocurrir si se usa electron, lo que lleva a este problema [https://support.newrelic.com/s/hubtopic/aAX8W0000008ZMO/new-relic-on-electron-nodejs](https://support.newrelic.com/s/hubtopic/aAX8W0000008ZMO/new-relic-on-electron-nodejs)) la función `getGlobalPackages` en `lib/environment.js` dará un error cuando no debería.

  ¡Gracias a Jarred Filmer (@BrighTide) por la corrección!
