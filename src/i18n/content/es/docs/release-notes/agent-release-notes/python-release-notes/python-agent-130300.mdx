## Notas

Esta versión del agente de Python agrega soporte para la configuración del lado del servidor de monitoreo de IA, agrega propagación del contexto para las invocaciones de Bedrock realizadas a través de [Microsoft Agent Framework](https://pypi.org/project/agent-framework/), corrige las entidades de herramientas duplicadas para las herramientas de [LangChain](https://pypi.org/project/langchain) respaldadas por un servidor MCP remoto, reduce el riesgo de condición de carrera en el muestreador de datos de recolección de basura, corrige los nombres de transacción inconsistentes al usar [Wagtail](https://pypi.org/project/wagtail) y elimina la codificación de bytes de los encabezados de rastreo distribuido de [Kombu](https://pypi.org/project/kombu) salientes.

Instale el agente usando `easy_install/pip/distribute` a través del [Índice de paquetes de Python](https://pypi.python.org/pypi/newrelic), usando `conda` a través del [Índice de paquetes de Conda-Forge](https://anaconda.org/conda-forge/newrelic), o descárguelo directamente desde el [sitio de descargas de New Relic](https://download.newrelic.com/python_agent/release).

## Nueva característica

* Agregar soporte para la configuración del lado del servidor de monitoreo de IA

  * El agente de Python ahora admite la [configuración del lado del servidor](https://docs.newrelic.com/docs/apm/agents/python-agent/configuration/python-agent-configuration/#ai-monitoring) de monitoreo de IA. Cuando se configuran, los valores `ai_monitoring.enabled`, `ai_monitoring.record_content.enabled` y `ai_monitoring.streaming.enabled` del lado del servidor tienen prioridad sobre la configuración local.

* Agregar propagación del contexto para las invocaciones de Bedrock a través de Agent Framework

  * Propaga el contexto de traza a través de los límites de subprocesos creados por la integración de Bedrock de [Microsoft Agent Framework](https://pypi.org/project/agent-framework/). Esto permite que la instrumentación de [botocore](https://pypi.org/project/botocore) existente del agente capture eventos de LLM para las invocaciones de Bedrock realizadas a través de Agent Framework. Esto no agrega la instrumentación completa de Agent Framework en sí.

## Errores

* Se corrigieron los nombres de transacción inconsistentes al usar Wagtail

  * Anteriormente, los nombres de transacción para las aplicaciones creadas en [Wagtail](https://pypi.org/project/wagtail) eran inconsistentes y podían ser los mismos para diferentes vistas de página. Esto ya fue solucionado.

* Corregir entidades de herramientas duplicadas para las herramientas de LangChain respaldadas por un servidor MCP remoto

  * Anteriormente, cuando una herramienta de [LangChain](https://pypi.org/project/langchain) estaba respaldada por un servidor MCP remoto que también estaba instrumentado por separado, aparecían entidades de herramientas duplicadas en la UI. Esto se ha solucionado al bloquear los atributos de subcomponentes de las herramientas de LangChain cuando se detecta una herramienta remota conocida.

* Corregir el campo de entrada de usuario faltante para las llamadas a herramientas MCP de LangChain y LangGraph

  * Anteriormente, cuando [LangChain](https://pypi.org/project/langchain) o LangGraph usaban herramientas de un servidor MCP, el campo de entrada del usuario podía faltar en los datos de monitoreo de IA si el mensaje de entrada no era el último mensaje en la secuencia transmitida. Esto se ha solucionado y el agente ahora extrae correctamente el mensaje de entrada en estos casos.

* Reduce el riesgo de condición de carrera en el muestreador de datos de recolección de basura

  * Anteriormente, el agente siempre llamaba a `gc.get_objects()` para muestrear los recuentos de objetos del recolector de basura, independientemente de la configuración. Esto se ha cambiado para que `gc.get_objects()` solo se llame cuando `top_object_count_limit` esté configurado por encima de `0`, lo que evita la iteración innecesaria del montón para los clientes que no rastrean los tipos de objetos recopilados por el recolector de basura.

* Eliminar la codificación de bytes de los encabezados de rastreo distribuido de Kombu salientes

  * Anteriormente, los encabezados de rastreo distribuido agregados por la instrumentación de [Kombu](https://pypi.org/project/kombu) estaban codificados en bytes, lo que interrumpía los transportes que serializan las cargas con el módulo `json` de la biblioteca estándar (por ejemplo, transportes respaldados por SQLAlchemy). Se ha eliminado la codificación de bytes para que estos transportes funcionen correctamente.
