## Log de cambios

Lanzamos una versión con cambios importantes para marcar la eliminación de `jmxreceiver` de los manifiestos de componentes tanto de `nrdot-collector` como de `nrdot-collector-experimental` tras su eliminación de `opentelemetry-collector-contrib` en `0.157.0` (consulte la [incidencia 45 740](https://github.com/open-telemetry/opentelemetry-collector-contrib/issues/45740) como referencia). El componente era utilizado exclusivamente por el caso de uso de [monitoreo de Kafka](/docs/opentelemetry/integrations/kafka/overview/), el cual se ha adaptado para ya no depender de este receptor. Si despliega `nrdot-collector` con una configuración personalizada usando `jmxreceiver`, migre siguiendo las instrucciones del [aviso de obsolescencia del receptor](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/v0.156.0/receiver/jmxreceiver#deprecation-notice).

### Característica

* Se actualizaron las versiones de los componentes otel de v0.156.0 a v0.157.0 (#643)
* Se actualizaron `nroracledbreceiver` y `nrsqlserverreceiver` a la versión v0.157.2 (#643)
  * Para obtener la lista de cambios en estos componentes, consulte [su registro de cambios](https://github.com/newrelic-forks/opentelemetry-collector-contrib/blob/receiver/nrsqlserverreceiver/v0.157.2/NR_CHANGELOG.md).
* Se añadió `sqlqueryreceiver` a la distribución de `nrdot-collector-experimental`. (#632)

### Corrección de errores

* Se eliminó `receiver/jmxreceiver` de `nrdot-collector` y `nrdot-collector-experimental`. (#635)
  * Este componente se eliminó en la fase inicial en `v0.157.0` tras su obsolescencia en `v0.145.0`.
* Se cambió el nombre de los nodos de configuración `cumulativetodelta` a `cumulative_to_delta` tras el cambio de nombre del componente en `v0.157.0`. (#644)
  * El nombre original `cumulativetodelta` sigue estando disponible como un alias obsoleto.
* Se deshabilitó `system.cpu.logical.count` en la configuración del host. (#647)
  * La actualización de `v0.157.0` a `receiver/host_metrics` habilitó esta métrica de forma predeterminada. Este cambio restaura el comportamiento anterior.
* Se eliminó la regla de agregación de media de `system.cpu.utilization` de la configuración del host. (#646)
  * La actualización de `v0.157.0` a `receiver/host_metrics` cambió su comportamiento predeterminado para agregar `system.cpu.utilization` por media, lo que hace que la regla eliminada sea redundante.
* CVE-2026-56852 (#634)
