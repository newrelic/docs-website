### Nueva característica

* En el host y Kubernetes: cuando el tipo de un agente se actualiza mediante una actualización de configuración remota en vivo, Agent Control ahora concilia los sistemas de archivos compartidos y por agente, eliminando las rutas declaradas por el tipo antiguo que ya no aparecen en las declaraciones de ningún agente activo. Las rutas compartidas en copropiedad que aún reclama otro agente activo se conservan. En Kubernetes, los objetos de k8s anotados con el tipo antiguo se recolectan como basura, mientras que los recursos del nuevo tipo se dejan intactos.
* Agrega la CLI de `oci-utils` a `test/crates/oci-test-utils` para enviar paquetes de agente y definiciones de tipo de agente a los registros de OCI desde la línea de comando (herramientas de desarrollo/prueba; no publicadas).
* El análisis del tipo de agente en el host ahora valida `reported_version_package`: debe hacer referencia a un paquete declarado y es obligatorio cuando se define más de un paquete. Las configuraciones no válidas se rechazan en el momento del análisis con un error descriptivo. Este `reported_version_package` determina qué versión se reporta como `agent.version`.
* Agrega soporte para `copy_from_file` para el sistema de archivos &quot;in-agent&quot; en el host.
* Agrega soporte para `shared_filesystem` en los tipos de agente en el host. Incluye una regla de propietario único: dos agentes que reclaman la misma ruta en el sistema de archivos compartido no son válidos y se notifican como Failed.
* Actualización automática en el host: omitir la conciliación del subagente cuando hay una actualización automática en curso. Cuando una única configuración remota incrementa la versión del control del agente y cambia el `agent_type` de un subagente, el subagente modificado ya no se vuelve a crear momentos antes de que se reinicie el proceso; la nueva configuración se almacena y el proceso reiniciado la vuelve a aplicar de forma limpia, lo que evita un reinicio redundante del subagente y un vacío de telemetría.
* En el host: se agregó compatibilidad con el agentType nri-redis tanto para Linux como para Windows.
* Configuración de estado en el host: se reemplazaron los campos planos `health.http:` / `health.file:` por una lista `checks:` explícita. Cada entrada está discriminada por `kind:` (`Process`, `Http` o `File`). La comprobación de estado del proceso supervisado, anteriormente implícita, ahora se declara como `kind: Process`. Una lista `checks:` omitida o vacía deshabilita por completo los informes de estado.
* Las entradas del sistema de archivos en el host (`file`/`dir`) ahora siempre sobreviven a la detención, el reinicio y la aplicación de configuración del subagente. Una clave `persistent:` suelta en el YAML de tipo de agente existente se ignora en lugar de rechazarse.

### Corrección de errores

* Se agregaron atributos de identificación para cada paquete especificado en el agentType como `package.version.<id>`.
* Los paquetes RPM ahora restauran `local_config.yaml` desde la copia de seguridad de `.rpmsave` que dejó una desinstalación anterior.
