### Nueva característica

* Se renombró la clave de configuración `secrets_providers` a `value_providers`, la clave antigua se conserva por compatibilidad con versiones anteriores.
* OnHost: se agregó compatibilidad con RedHat 10
* K8s: agregar un nuevo proveedor de valores `nr-kubecm` para resolver variables de los ConfigMaps de Kubernetes.
* `chart_values.global` todavía es compatible en agentTypes, pero está obsoleto. Aún puede configurar los parámetros globales a través de `chart_values.[chart-name].global`
* Linux: se agregó el script `uninstall.sh` incluido en el paquete que detecta automáticamente el administrador de paquetes (apt, yum, zypper) y elimina `newrelic-agent-control`.

### Corrección de errores

* On-host: el agente eBPF ahora escribe su log de estado en el directorio del sistema de archivos administrado por AC en lugar de `/etc/newrelic-ebpf-agent`.
* On-host: se corrigió el falso error de inicio &quot;already running&quot; cuando un archivo PID obsoleto retenía un PID reutilizado por un proceso no relacionado.
* Suprimir el reporte de `Health` (OpAMP y servidor de estado) para los subagentes cuyo tipo de agente no define ningún bloque `health:`, incluso en caso de fallo inicial de inicio del supervisor.
* On-host: cuando un tipo de agente se actualiza a una nueva versión, las entradas obsoletas del sistema de archivos declaradas por la versión anterior ahora se eliminan mediante un diff en lugar de un borrado completo del directorio del agente; el ID de la instancia de OpAMP del subagente se conserva en los cambios de versión.
* K8s: cuando un tipo de subagente se actualiza a una nueva versión, el ID de la instancia de OpAMP ahora se conserva durante la actualización; anteriormente, el ConfigMap de fleet-data se eliminaba en cada cambio de tipo, independientemente de si el nombre del agente cambiaba, lo que provocaba que se generara un nuevo ID de la instancia en el siguiente inicio.
* Linux: el script `postremove` ahora elimina correctamente los directorios `newrelic-agent-control` en cualquier desinstalación (no solo en `apt purge`) y tiene como objetivo las rutas correctas (`/etc/newrelic-agent-control`, `/var/lib/newrelic-agent-control`, `/var/run/newrelic-infra`) en lugar de las antiguas de infra-agent.
* On-host: el servicio ahora vuelve a intentarlo indefinidamente en caso de error (retraso de 20 s) en lugar de detenerse después de 5 reinicios rápidos; se aplica tanto a la unidad systemd de Linux como a las acciones de error de SCM de Windows.
