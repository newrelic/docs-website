### Nueva característica

* Linux: se agregó Debian 13 (trixie) como plataforma compatible/publicada.
* Linux: se eliminó la migración de carpetas on-host legacy anterior a v1.2.0 de `newrelic-agent-control-cli`
* Se eliminó el soporte para variantes a favor del flujo de &quot;gobernanza&quot; del lado del servidor
* Se eliminó la validación de configuración remota basada en expresiones regulares a favor del flujo de &quot;gobernanza&quot; del lado del servidor.

### Corrección de errores

* On-host: se corrigió un log de nivel `error`espurio `"cannot forward agent control event"` emitido en cada apagado limpio; el puente del servidor de estado ahora sale solo mediante una señal de detención explícita, los canales cerrados se deshabilitan de forma silenciosa en lugar de provocar una salida y la vida útil de los publicadores se extiende para mantener los canales abiertos hasta que se active la señal de detención.
* Linux: `uninstall.sh` ahora usa `apt-get purge` en lugar de `apt-get remove`, lo que evita una inconsistencia de estado de dpkg que provocaba que la reinstalación fallara; el servicio no podía iniciarse porque el administrador de paquetes no volvía a crear el archivo de configuración `systemd-env.conf`.
* Windows: el script de desinstalación ahora advierte en lugar de completarse silenciosamente cuando no se puede eliminar el directorio de instalación o de datos de tiempo de ejecución (por ejemplo, el Explorador de Windows lo tiene abierto), y conserva el propio script para que se pueda volver a ejecutar una vez que se libere el bloqueo.
* En el host: las entradas del sistema de archivos bajo `filesystem:`/`shared_filesystem:` ahora se escriben en el disco en orden alfabético y se sincronizan con fsync después de cada escritura, lo que hace que el orden de escritura sea determinista.
* On-host: la actualización automática ya no elimina el binario del paquete descargado al reemplazar el binario en ejecución, lo que soluciona la reversión y la reinstalación de la misma versión después de una actualización automática.
* On-host: se corrigió un mensaje `Error reading the log directory/files: No such file or directory` espurio impreso en stderr la primera vez que se crea el directorio de log del control del agente o de un subagente.
* On-host: la salida del ejecutable y los logs del ciclo de vida ya no se etiquetan de forma engañosa con el span `start_agent` durante toda la vida útil de los procesos del agente y los supervisores, en su lugar, llevan los campos explícitos.
* Al salir, la línea de log de proceso terminado (éxito o error) ya no se descarta del archivo de log: solía emitirse después de que el logger de archivos ya se hubiera cerrado, por lo que solo llegaba a `journalctl`/stderr.
