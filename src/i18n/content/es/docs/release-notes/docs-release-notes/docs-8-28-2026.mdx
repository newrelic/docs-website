### Nuevos documentos

* Se agregó [Envíe las trazas de GenAI a New Relic con OpenTelemetry](/docs/ai-monitoring/opentelemetry-ai-monitoring), que explica cómo enviar trazas de GenAI de OTel, incluidas las llamadas a LLM, las llamadas a herramientas y los pasos del agente, al monitoreo de IA de New Relic sin un agente de New Relic.

* Se agregó el [monitoreo de IA de eBPF](/docs/ebpf/ai-monitoring), que cubre cómo el agente de eBPF detecta y monitorea automáticamente las workloads de GenAI y LLM en hosts de Linux y clústeres de Kubernetes sin cambios en el código.

* Se agregó [Monitorear automáticamente sus websockets](/docs/browser/new-relic-browser/browser-pro-features/websockets), que cubre el seguimiento del estado de la conexión de WebSocket, incluidos los mensajes enviados y recibidos, la duración de la conexión y los eventos de cierre, utilizando el agente del browser.

* Se agregó [Casos de uso de monitoreo sintético](/docs/synthetics/synthetic-monitoring/guides/synthetic-monitoring-use-cases), que le ayuda a elegir el tipo de monitor adecuado, desde comprobaciones de ping ligeras hasta recorridos de API y navegadores completamente programados.

* Se agregó [Tipos de agente](/docs/new-relic-control/agent-control/agent-types), que cubre las definiciones de tipos de agente de Agent Control, cómo funcionan y qué agentes son compatibles.

* Se agregaron [Introducción a Amazon Fire TV](/docs/streaming-video-&-ads/installation/amazon-fire-tv/get-started-with-amazon-fire-tv) y las guías de instalación para [Shaka Player](/docs/streaming-video-&-ads/installation/amazon-fire-tv/install-shaka-player), [Dash.js](/docs/streaming-video-&-ads/installation/amazon-fire-tv/install-dashjs) y [HTML5](/docs/streaming-video-&-ads/installation/amazon-fire-tv/install-html5), que explican cómo monitorear la reproducción de video en Amazon Fire TV mediante VegaTracker.

* Se agregó [Agrupar funciones Lambda bajo una sola entidad OTel](/docs/serverless-function-monitoring/aws-lambda-monitoring/opentelemetry/otel-service-name-lambda), que cubre el uso de `OTEL_SERVICE_NAME` para consolidar múltiples funciones Lambda instrumentadas con OTel bajo una sola entidad de New Relic.

* Se agregaron [Informes de errores de JavaScript de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting), [Listar y eliminar mapas de origen de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/list-delete-react-native-source-maps) y [Solucionar problemas de mapas de origen de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/troubleshoot-react-native-source-maps) para guiar la migración al tipo de evento `MobileJSError` introducido en el agente de React Native v1.9.0.

* Se agregaron los siguientes documentos del catálogo de acciones de automatización de flujos de trabajo:

  * [Acciones de New Relic Issue](/docs/workflow-automation/setup-and-configure/actions-catalog/newrelic/newrelic-issue): crear, actualizar y administrar problemas de New Relic desde un flujo de trabajo.

### Notas de la versión

* Mantener actualizado con nuestros últimos lanzamientos:

  * [Agente de React Native v1.9.0](/docs/release-notes/mobile-release-notes/react-native-release-notes/react-native-agent-190):

    * **Cambio importante:** el agente ahora reporta los errores de JavaScript como `MobileJSError` en lugar de `MobileHandledException`. Actualice las condiciones de alerta, las consultas del dashboard y los scripts de carga de mapas de origen. Consulte [Reporte de errores de JavaScript de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting) para conocer los pasos de migración.

  * [Agente Android v7.8.2](/docs/release-notes/mobile-release-notes/android-release-notes/android-782):

    * Se corrigió el extremo del host de la API de mapa de origen regional y predeterminado para las cargas de mapas de origen de React Native.

  * [Aplicación móvil para Android v5.43.6](/docs/release-notes/mobile-apps-release-notes/new-relic-android-release-notes/new-relic-android-5436):

    * Correcciones de errores y mejoras.

  * [Integración de Kubernetes v4.7.0](/docs/release-notes/infrastructure-release-notes/kubernetes-integration-release-notes/kubernetes-integration-4-7-0):

    * Incluido en las versiones de gráficos `newrelic-infrastructure-4.6.0` y `nri-bundle-8.0.20`.

  * [Agente de Node.js v14.3.9](/docs/release-notes/agent-release-notes/nodejs-release-notes/node-agent-14-3-9):

    * Se corrigió la instrumentación de `@google/adk` para v2.0.0.

  * [Agente .NET v10.54.0](/docs/release-notes/agent-release-notes/net-release-notes/net-agent-10-54-0):

    * Se agregó una caché sin bloqueos para las búsquedas del agente en el código inyectado por el generador de perfiles, lo que reduce la sobrecarga del agente para las aplicaciones de .NET.
    * Se corrigió la contaminación cruzada de transacciones en `HybridHttpContextStorage`.
    * Se corrigió una transacción de cliente WCF retenida cuando un resultado asincrónico se completa antes de un intercambio de devolución de llamada.
    * Se corrigió la inyección incorrecta de comentarios de metadatos de SQL para `CommandType.StoredProcedure`.

  * [NRDOT Collector v2.4.0](/docs/release-notes/nrdot-release-notes/nrdot-2026-08-25):

    * Se actualizaron `nrmysqlreceiver`, `nroracledbreceiver`, `nrpostgresqlreceiver` y `nrsqlserverreceiver` a v0.158.3.

  * [Agente de medios para Roku v4.2.3](/docs/release-notes/streaming-others-release-notes/streaming-others-agent-26-08-27):

    * Se agregó el atributo `contentIsLive` a los eventos `VideoAction` y `VideoAdAction`, lo que alinea a Roku con el modelo de datos de video estándar entre agentes.
    * Se corrigieron los eventos `CONTENT_BUFFER_END` retrasados hasta que se reanudó la reproducción después de un rebuffer en estado de pausa.
    * Se corrigió la aparición de `errorCode`, `errorMessage` y `backtrace` en todos los eventos, incluidos los heartbeats. Estos atributos ahora solo aparecen en los eventos de error.
    * Se corrigió la supresión silenciosa del logging de depuración de MediaTailor SSAI (`nrActivateLogging`) desde v4.2.0.

  * [Job Manager v618](/docs/release-notes/synthetics-release-notes/job-manager-release-notes/job-manager-release-618):

    * Se corrigieron las vulnerabilidades del SO CVE-2026-11856 y CVE-2026-8932, y las vulnerabilidades de la biblioteca CVE-2026-54399, CVE-2026-54428 y CVE-2026-64607.

  * [Entorno de ejecución de la API de Node v1.2.262](/docs/release-notes/synthetics-release-notes/node-api-runtime-release-notes/node-api-runtime-1.2.262):

    * Se corrigieron las vulnerabilidades del sistema operativo CVE-2026-53224, CVE-2026-64531, CVE-2026-11856, CVE-2026-53246, CVE-2026-62289, CVE-2026-53247 y CVE-2026-8932, y la vulnerabilidad de la biblioteca CVE-2026-55553.

  * [Tiempo de ejecución del navegador de Node v3.0.211](/docs/release-notes/synthetics-release-notes/node-browser-runtime-release-notes/node-browser-runtime-3.0.211):

    * Se actualizó Chrome de la versión 151.0.7922.137-1 a la 151.0.7922.173-1.
    * Se corrigieron las mismas vulnerabilidades del sistema operativo y de la biblioteca que en el runtime de la API de Node v1.2.262.

  * [Ping runtime v1.80.0](/docs/release-notes/synthetics-release-notes/ping-runtime-release-notes/ping-runtime-1.80.0):

    * Se corrigieron las vulnerabilidades del sistema operativo CVE-2026-11856 y CVE-2026-8932.
