### Nuevos documentos

* Se agregó [Instalar New Relic con un agente de codificación de IA](/docs/new-relic-solutions/get-started/install-with-ai) con un símbolo de copiar y pegar para que cualquier agente de codificación de IA, como Claude Code, Cursor, GitHub Copilot y Codex, pueda encontrar los documentos de instalación correctos, verificar la instalación y mantener la clave de licencia fuera de su contexto.
* Se agregaron las [Preguntas frecuentes sobre la observabilidad del Collector](/docs/opentelemetry/collector-observability/collector-observability-faq), que abarcan las versiones compatibles del recolector, los formatos de exportación, la detección automática, la clasificación automática y los recolectores adjuntos, para que las respuestas detalladas se encuentren en un solo lugar en vez de en las páginas de descripción general y configuración.
* Se agregó la [referencia de configuración de Control de agentes](/docs/new-relic-control/agent-control/configuration-reference), que enumera las configuraciones de Control de agentes que puede modificar, como el logging, el proxy, el servidor de estado, las comprobaciones de estado, la autoinstrumentación y las opciones de registro de OCI, con sus valores predeterminados.
* Se agregó [Instalar y configurar NRDOT para el monitoreo de MySQL con el servidor flexible de Azure](/docs/opentelemetry/db360/mysql/azure) e [Instalar y configurar NRDOT para el monitoreo de PostgreSQL con el servidor flexible de Azure](/docs/opentelemetry/db360/postgresql/azure) para que los equipos que ejecutan MySQL o PostgreSQL en Azure puedan configurar la observabilidad de la base de datos con el NRDOT Collector.
* Se agregó el [boletín de seguridad NR26-13](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-13) con el impacto del compromiso de la autoridad de certificación eMudhra en la integración de logs (plug-in de salida de Fluent Bit, reenvío de logs del agente de infraestructura y chart de Helm).
* Se agregó el [Boletín de seguridad NR26-14](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-14) con el impacto de la vulneración de la autoridad de certificación de eMudhra en la integración de Kubernetes, lo que incluye el nri-bundle y los charts de Helm relacionados.
* Se agregó el [boletín de seguridad NR26-15](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-15) con el impacto del compromiso de la autoridad de certificación eMudhra en el agente de infraestructura y la integración en el host.
* Se agregó el [boletín de seguridad NR26-16](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-16) para la vulnerabilidad de ejecución remota de código de OpenJDK Java4Shell (CVE-2026-114938), con elementos de acción para los componentes de New Relic afectados.
* Se agregó el [boletín de seguridad NR26-17](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-17) para la vulnerabilidad de corrupción de memoria de Ruby2Shell (CVE-2026-132825) y su impacto en las imágenes de contenedor `newrelic-fluentd-docker`, `newrelic/fluentd` y `k8s-golang-apm-linkage-demo`, donde se indica que no se requiere ninguna acción para los clientes que usan agentes de Ruby.

### Cambios importantes

* [Observabilidad del Collector](/docs/opentelemetry/collector-observability/collector-observability) ya está disponible de forma general. Se actualizaron las páginas de descripción general y [configuración](/docs/opentelemetry/collector-observability/collector-observability-setup) con nuevas capturas de pantalla y un enlace a las nuevas [Preguntas frecuentes sobre la observabilidad del Collector](/docs/opentelemetry/collector-observability/collector-observability-faq) para obtener explicaciones detalladas.
* Se reescribieron [Agente de iOS de New Relic y rastreo distribuido](/docs/mobile-monitoring/new-relic-mobile-ios/get-started/new-relic-ios-and-dt) y [Agente de Android de New Relic y rastreo distribuido](/docs/mobile-monitoring/new-relic-mobile-android/get-started/new-relic-android-and-dt) para explicar para qué requests se genera una traza automáticamente, qué necesita habilitar para la correlación de trazas y cómo desactivar el rastreo. Se eliminó el video desactualizado de ambas páginas.
* Se actualizó el documento [Conceptos importantes sobre la gestión de usuarios y accesos](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts) con tablas de los roles estándar para los alcances de organización, cuenta y entidad, lo que incluye roles de flota, secreto, conector Lens, agente de IA, macro de NRQL, notebook, política de alertas y dashboard, para que los administradores puedan ver qué otorga cada rol predeterminado.
* Se actualizó la [Comprobación de exposición](/docs/vulnerability-management/exposure-check) para cubrir el aviso de Java4Shell (CVE-2026-114938) junto con los avisos de PHP y Node.js, y para describir las nuevas tarjetas de resumen <DNT>Exposure</DNT> y <DNT>How to fix</DNT>, para que los usuarios puedan encontrar qué entidades de APM ejecutan una versión de Java afectada.
* Se actualizó [Configurar ajustes de privacidad](/docs/mobile-monitoring/mobile-monitoring-ui/mobile-session-replay/configure-privacy-settings) para Session Replay móvil para corregir ejemplos que no compilaban y reglas de etiquetas que no coincidían con el comportamiento del agente en iOS, Android y React Native, y para aclarar que los campos de contraseña se mantienen enmascarados.
* Se actualizó [Configuración de MCP](/docs/agentic-ai/mcp/setup) y [Descripción general de MCP](/docs/agentic-ai/mcp/overview) con Cursor como cliente de MCP compatible, incluidos los requisitos, el acceso y la configuración de `mcp.json` para la autenticación con una clave de API de usuario.
* Se actualizó [Conectar Autopilot a Slack](/docs/agentic-ai/autopilot/connect-to-slack) con el botón <DNT>**Investigate with AI**</DNT> en las notificaciones de alerta, para que los equipos puedan iniciar una investigación desde un hilo de alerta de Slack sin escribir un símbolo.
* Se actualizaron [Logs de eBPF](/docs/ebpf/logs), [Instalación de Kubernetes](/docs/ebpf/k8s-installation) e [Instalación de Linux](/docs/ebpf/linux-installation) para reflejar que `reportLogs` ahora tiene como valor predeterminado `"auto"` en lugar de `"false"` y que el `fileRegex` predeterminado ahora es `".*\\.log$"`.
* Se actualizó [Configuración de rastreo distribuido del agente de Ruby](/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration-distributed-tracing-settings) y [Muestreo de trazas de rastreo distribuido](/docs/apm/distributed-tracing/distributed-trace-sampling) con la configuración del muestreador `trace_id_ratio_based` para el agente de Ruby, para que el usuario pueda configurar el muestreo basado en proporciones.
* Se eliminaron las métricas que New Relic no recopila de las páginas de integración de [Google BigQuery](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-bigquery-monitoring-integration), [Google Cloud Pub/Sub](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-pubsub-monitoring-integration) y [Google Cloud Storage](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-storage-monitoring-integration) porque Google no las define o las clasifica como alfa u obsoletas.

### Cambios menores

* Se actualizó [Buscar ayuda y obtener soporte](/docs/new-relic-solutions/solve-common-issues/find-help-get-support) con una tabla de definición de estado de casos para explicar qué significa cada estado de caso de soporte.
* Se actualizó [Referencia de herramientas de MCP](/docs/agentic-ai/mcp/tool-reference) con las herramientas de solo lectura `get_retention_policy_and_namespaces`, `get_user_id` y `list_support_cases` y la habilidad Kafka Autopilot.
* Se actualizó la [descripción general de MCP](/docs/agentic-ai/mcp/overview) para explicar que eliminar a un usuario de todos los grupos con permisos de servidor MCP es una forma de menor impacto para revocar el acceso de un usuario que eliminar al usuario.
* Se actualizó [Tipos de agentes](/docs/new-relic-control/agent-control/agent-types) para explicar por qué el Control de agentes informa un estado de salud `unknown` para las integraciones en el host y que los archivos de salida `enable_file_logging` no se rotan.
* Se actualizó [Identificación del servicio de base de datos con NRDOT](/docs/opentelemetry/db360/capabilities/db-apm) para requerir el agente de Java v9.4.0 o superior y para mostrar la configuración `sql_metadata_comments.enabled`.
* Se actualizó [Configuración de conectores](/docs/new-relic-lens/set-up-connectors) con las versiones compatibles de MongoDB y Azure Cosmos DB for MongoDB (4.2 o posterior).
* Se actualizó [Gestión de cardinalidad](/docs/data-apis/ingest-apis/metric-api/cardinality-management) para aclarar que se puede aumentar el límite de cardinalidad por métrica hasta el límite de la cuenta.
* Se actualizaron los [KPI de workload inteligente](/docs/new-relic-solutions/new-relic-one/workloads/intelligent-workload-kpis) para aclarar que los datos de los KPI comienzan desde el momento en que se crea el KPI y que New Relic no los rellena de forma retroactiva.
* Se actualizó [Reenvío de logs desde Google Cloud Platform](/docs/logs/forward-logs/google-cloud-platform-log-forwarding) para indicar que la plantilla de Dataflow requiere Java 11 o posterior.
* Se actualizaron las páginas de compatibilidad y requisitos del [agente Node.js](/docs/apm/agents/nodejs-agent/getting-started/compatibility-requirements-nodejs-agent) y el [agente .NET](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) con las últimas versiones de biblioteca verificadas.

### Notas de la versión

* Mantener actualizado con nuestros últimos lanzamientos:

  * [Agente de Python v14.3.0](/docs/release-notes/agent-release-notes/python-release-notes/python-agent-14-03-00):

    * Se habilitó el monitoreo de IA de forma predeterminada. Ahora la instrumentación de LLM envía `Llm*` eventos, spans y métricas sin el contenido del mensaje, a menos que lo desactive.
    * Se marcó como obsoleta la configuración `ai_monitoring.enabled` a favor de `ai_monitoring.basic_telemetry.enabled`.
    * Se corrigió un bloqueo en la instrumentación de LangChain `StructuredTool` cuando no se pasa ninguna configuración.

  * [Agente de Node.js v14.13.0](/docs/release-notes/agent-release-notes/nodejs-release-notes/node-agent-14-13-0):

    * Se agregó `event.name` a los logs cuando `eventName` existe en un registro de log de OpenTelemetry.
    * Se corrigieron el protocolo y el puerto de los requests salientes de `http` y `https`.
    * Se corrigió la captura de los encabezados de respuesta para `writeHead`.
    * Se devolvió la promesa del controlador de la aplicación desde el wrapper `eachMessage` de kafkajs.

  * [Agente .NET v10.58.0](/docs/release-notes/agent-release-notes/net-release-notes/net-agent-10-58-0):

    * Se habilitó la telemetría básica de IA de forma predeterminada.
    * Se aplicó la ofuscación de SQL conforme a las especificaciones a MySQL, Oracle, SQL Server, Postgres y otros almacenes de datos.
    * Se capturaron los encabezados de request en las transacciones del desencadenador HTTP de Azure Function.
    * Se corrigió la captura del explain plan para MySQL y SQL Server.

  * [Agente PHP v12.13.0.43](/docs/release-notes/agent-release-notes/php-release-notes/php-agent-12-13-0-43):

    * Se agregó instrumentación para `mysqli_execute_query` y `mysqli::execute_query`.
    * Se verificó la compatibilidad con Ubuntu 26.04 y Alpine 3.24.
    * Se agregaron datos de lanzamiento para los hashes de tarball, los resúmenes de imágenes y las huellas digitales de claves de firma.
    * Se actualizó Go a 1.27.4 y `golang.org/x/net` a 0.62.0 en el daemon.

  * [Agente de infraestructura v2.1.1](/docs/release-notes/infrastructure-release-notes/infrastructure-agent-release-notes/new-relic-infrastructure-agent-211):

    * Se agregó soporte para SUSE 16.
    * Se expusieron los scripts del wrapper de nrjmx en el paquete de Control de agentes.
    * Se actualizó Go a 1.27.4 y la integración en el host incorporada.

  * [Pipeline Control Gateway v3.2.1](/docs/release-notes/pipeline-control-gateway-release-notes/pipeline-control-gateway-3-2-1):

    * Se corrigieron errores de decodificación JSON en el agente APM para Python al enviar datos a través del gateway.
    * Se corrigió el registro de los eventos de span de APM con su hora de llegada en lugar de su hora de inicio.
    * Se actualizó `golang.org/x/net` para resolver vulnerabilidades de gravedad alta y media.

  * [Observabilidad de Collector v1.1.0](/docs/release-notes/nrdot-release-notes/collector-o11y-1-1-0):
    * Se verificó la compatibilidad con `nrdot-collector:2.9.0` y `opentelemetry-collector-contrib:0.164.0`.

  * [Observabilidad de Collector v1.0.0](/docs/release-notes/nrdot-release-notes/collector-o11y-1-0-0):

    * Se verificó la compatibilidad con `nrdot-collector:2.8.1` y `opentelemetry-collector-contrib:0.163.2`.
    * Se eliminó el atributo de recurso `newrelic.service.type`, que ya no es necesario para la detección automática.

    * Se agregó el umbral de capacidad del búfer de log de evento y el evento descartado.
