bugs:
  - 'Fixed a crash (`SIGSEGV` or `SIGBUS` in `SessionAttributeManager::generateJSONObject`) on the harvest thread, which could also corrupt the heap and cause crashes elsewhere. The agent copied its internal session attributes, such as `memUsageMb` and `lastInteraction`, during a harvest without holding the lock that guards them, so it could read them while another thread was updating them. This issue was present in 7.7.8 and earlier.'
  - 'Fixed the main thread blocking, and apps being terminated by the iOS watchdog (`0x8BADF00D`), once the event buffer was full and the app kept making network requests. The agent held a lock while it rewrote its on-disk copy of buffered events, and threads recording events, including the main thread, waited on that lock. Events dropped from a full buffer were also never removed from that copy, so it grew and was rewritten in full for every new event. Writes now happen without holding the lock, are batched, and dropped events are removed. This issue was present in 7.7.8 and earlier.'
  - 'Fixed events occasionally going unreported when they were recorded, for example by a network request finishing, at the same moment the agent collected buffered events for a harvest. The agent cleared the buffer a second time after releasing its lock, which discarded any event added in between before it was sent. This issue was present in 7.7.8 and earlier.'
  - 'Fixed the agent''s own JSON work being recorded as app activity. `NSJSONSerialization` is instrumented for interaction traces, and the agent called it directly for every log message as well as for session attributes and handled exceptions. That added the agent''s internal work to interaction traces and, when the app logged heavily, could overwhelm tracing. The agent now calls the original, uninstrumented implementation. This issue was present in 7.7.8 and earlier.'
  - 'Fixed Session Replay accessibility identifier masking rules set in Application Settings being ignored on iOS. New Relic sends these rules to iOS apps with the identifier `accessibilityIdentifier`, but the agent only recognized `tag`, so every such rule was dropped. Both values are now accepted. A malformed rule is now skipped with a warning instead of discarding every rule or crashing the agent.'
  - 'Fixed possible crashes in Session Replay masking. Masking lists could be updated by a reconnect, or by `addSessionReplayMaskedAccessibilityIdentifier:` and related APIs, while a frame was being captured, without holding the lock that capture uses. Custom masking rules containing values that can''t be saved to `NSUserDefaults`, such as `null`, could also stop the app when the agent saved its configuration. Rules are now cleaned before they are stored, and every update to the masking lists is locked.'
  - 'Fixed `WKWebView` navigations being reported without a URL in apps built with the iOS 27 SDK. With that SDK, `WKWebView.URL` can still be `nil` when a navigation starts. The agent now falls back to the main-frame request URL from `decidePolicyForNavigationAction`.'
  - Fixed possible EXC_BAD_ACCESS crash when using `addHTTPHeaderTrackingFor`.

### Corrección de errores

* Se solucionó un cierre inesperado (`SIGSEGV` o `SIGBUS` en `SessionAttributeManager::generateJSONObject`) en el hilo de recolección, que también podía corromper el montón y causar cierres inesperados en otros lugares. El agente copió sus atributos de sesión internos, como `memUsageMb` y `lastInteraction`, durante una recolección sin mantener el bloqueo que los protege, por lo que podía leerlos mientras otro hilo los estaba actualizando. Este problema estaba presente en la versión 7.7.8 y anteriores.
* Se solucionó el bloqueo del hilo principal y la finalización de las aplicaciones por parte del guardián de iOS (`0x8BADF00D`), una vez que el búfer de eventos estaba lleno y la aplicación seguía realizando requests de red. El agente mantenía un bloqueo mientras reescribía su copia en disco de los eventos almacenados en el búfer, y los hilos que registraban eventos, incluido el hilo principal, esperaban ese bloqueo. Los eventos descartados de un búfer lleno tampoco se eliminaban nunca de esa copia, por lo que crecía y se reescribía por completo para cada nuevo evento. Las escrituras ahora se realizan sin mantener el bloqueo, se procesan por lotes y se eliminan los eventos descartados. Este problema estaba presente en la versión 7.7.8 y anteriores.
* Se solucionó un problema por el cual los eventos ocasionalmente no se reportaban cuando se registraban, por ejemplo, al finalizar una solicitud de red, en el mismo momento en que el agente recopilaba los eventos almacenados en el búfer para una recolección. El agente vaciaba el búfer por segunda vez después de liberar su bloqueo, lo que descartaba cualquier evento agregado en ese lapso antes de que se enviara. Este problema estaba presente en la versión 7.7.8 y anteriores.
* Se solucionó que el propio trabajo JSON del agente se registrara como actividad de la aplicación. `NSJSONSerialization` está instrumentado para trazas de interacción, y el agente lo llamaba directamente para cada mensaje de log, así como para los atributos de sesión y las excepciones controladas. Eso añadía el trabajo interno del agente a las trazas de interacción y, cuando la aplicación registraba muchos logs, podía sobrecargar el rastreo. El agente ahora llama a la implementación original no instrumentada. Este problema estaba presente en la versión 7.7.8 y anteriores.
* Se solucionó que las reglas de enmascaramiento del identificador de accesibilidad de Session Replay establecidas en la configuración de la aplicación se ignoraran en iOS. New Relic envía estas reglas a las aplicaciones de iOS con el identificador `accessibilityIdentifier`, pero el agente solo reconocía `tag`, por lo que se descartaban todas esas reglas. Ahora se aceptan ambos valores. Ahora se omite una regla mal formada con una advertencia en lugar de descartar todas las reglas o provocar el cierre inesperado del agente.
* Se solucionaron posibles cierres inesperados en el enmascaramiento de Session Replay. Las listas de enmascaramiento podían actualizarse mediante una reconexión, o mediante `addSessionReplayMaskedAccessibilityIdentifier:` y las API relacionadas, mientras se capturaba un fotograma, sin mantener el bloqueo que utiliza la captura. Las reglas de enmascaramiento personalizadas que contenían valores que no se pueden guardar en `NSUserDefaults`, como `null`, también podían detener la aplicación cuando el agente guardaba su configuración. Las reglas ahora se limpian antes de almacenarse, y cada actualización de las listas de enmascaramiento se bloquea.
* Se solucionó que las navegaciones de `WKWebView` se reportaran sin una URL en las aplicaciones compiladas con el SDK de iOS 27. Con ese SDK, `WKWebView.URL` aún puede ser `nil` cuando se inicia una navegación. El agente ahora recurre a la URL de solicitud del marco principal de `decidePolicyForNavigationAction`.
* Se solucionó un posible fallo de EXC\_BAD\_ACCESS al usar `addHTTPHeaderTrackingFor`.
