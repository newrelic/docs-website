## Nuevas características y mejoras

* Se agregó almacenamiento sin conexión para Session Replay: las cargas de repetición que no se pueden enviar de inmediato —debido a la falta de conexión de red, el cierre forzado de la aplicación, la salida del proceso o la eliminación por falta de memoria— ahora se guardan en el disco y se entregan en la siguiente recolección exitosa, en lugar de perderse.
* Se agregó soporte subyacente para el reporte de errores híbridos desde aplicaciones de React Native, que se habilitará junto con un próximo lanzamiento del agente de React Native. Los errores de JavaScript no controlados se capturarán como eventos del agente, se correlacionarán con Session Replay y se etiquetarán con la versión de la aplicación para una simbolización precisa.
* Se agregó soporte subyacente para la carga automática de mapas de origen de JavaScript de React Native durante la compilación de Gradle, que se habilitará junto con un próximo lanzamiento del agente de React Native.
* Se agregó la carga de archivos de mapeo de ProGuard/DexGuard por objetivo de compilación, de modo que las aplicaciones con múltiples objetivos de empaquetado de DexGuard obtengan una desofuscación de fallas correctamente coincidente para cada objetivo.
* Se agregó un almacén de atributos con alcance de sesión para que los eventos de información de salida de la aplicación (AEI) lleven los atributos de sesión de la sesión que realmente falló, en lugar de la sesión creada después del lanzamiento.
* La persistencia de eventos ahora está habilitada de forma predeterminada, por lo que los eventos almacenados en búfer y los datos de análisis sobreviven a la finalización de la aplicación y se recuperan en el próximo lanzamiento.
* Se agregó soporte para el plug-in de Gradle para Android (AGP) 9.x, lo que eleva el límite admitido a 9.3.0.

## Corrección de errores

* Se corrigió el tiempo de inicio en frío para medir el tiempo hasta la visualización inicial (TTID) desde el lanzamiento hasta el primer fotograma renderizado, en lugar de desde la reanudación de la actividad.
* Se solucionó un problema de recuperación de fallos en el que un archivo de copia de seguridad obsoleto podía impedir que el almacén de fallos se recuperara después de un fallo anterior.
* Se corrigieron las excepciones controladas para que persistan fuera del subproceso de llamada, lo que evita posibles ralentizaciones cuando se escribe en el almacén de excepciones.
* Se corrigió la invalidación de la caché de compilación de Gradle causada por la incrustación del ID de compilación por compilación y los valores de métricas directamente en el código fuente compilado — estos ahora se generan como recursos de Android en su lugar, lo que reduce las recompilaciones innecesarias y el tiempo de recompilación, con los recursos protegidos para que no se eliminen cuando shrinkResources está habilitado.

## Declaración de apoyo

Recomendamos actualizar el agente al menos cada tres meses. Encuentre políticas y fechas específicas para el soporte de agentes Android en la [Política de EOL de agentes de monitoreo de celulares](/docs/mobile-monitoring/new-relic-mobile/get-started/mobile-agents-eol-policy/#android-eol).
