[La integración de New Relic](/docs/infrastructure/introduction-infra-monitoring) con [Google Cloud Platform (GCP)](https://cloud.google.com/) incluye una que informa datos de [Google Cloud Service Mesh](https://cloud.google.com/service-mesh/docs) (Istio) a New Relic. Este documento explica cómo activar la integración de GCP Cloud Service Mesh y describe los datos que reporta.

## Característica

Cloud Service Mesh es la malla de servicios administrada de Google Cloud, basada en Istio. La integración de New Relic Cloud Service Mesh recopila la telemetría del servicio de Istio emitida por sus workloads en malla: recuentos de solicitudes entrantes y salientes, tamaños de solicitudes y respuestas, y distribuciones de latencia del lado del servidor y del cliente.

Esta integración está limitada a las workloads de Cloud Run inscritas en Cloud Service Mesh. Esta integración no recopila la telemetría de Istio de las workloads de sidecar de GKE (el recurso monitoreado `istio_canonical_service`).

## Activar la integración [#activate]

<Callout variant="important">
  Esta integración está disponible solo cuando conecta su proyecto de GCP con la Workload Identity Federation. No está disponible para conexiones de cuentas de servicio o cuentas de usuario.
</Callout>

Para habilitar la integración, siga los procedimientos estándar para [conectar su servicio de GCP a New Relic](/docs/connect-google-cloud-platform-services-infrastructure) con la Workload Identity Federation.

## Frecuencia de sondeo [#polling]

La integración de New Relic consulta sus servicios de GCP de acuerdo con un intervalo de sondeo que varía según la integración. La frecuencia de sondeo para Google Cloud Service Mesh es de 5 minutos. La resolución es 1 punto de datos cada minuto.

## Federación de identidades de workload (Workload Identity Federation) [#wif]

### Buscar y utilizar datos [#find-data-wif]

Todas las métricas de Cloud Service Mesh disponibles en el monitoreo de la nube de GCP se recopilan como métricas dimensionales en el tipo de evento `Metric`.

Esta integración no crea entidades en el explorador de entidades de New Relic. Consulte sus métricas directamente en el tipo de evento `Metric`, por ejemplo:

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.istio.io.%' FACET metricName
```

Las métricas llevan las etiquetas de recursos de la revisión subyacente de Cloud Run, por lo que puede clasificar por nombre de servicio, nombre de revisión y ubicación sin una entidad.

Las métricas de distribución anteriores (`request_bytes`, `response_bytes`, `response_latencies`, `roundtrip_latencies`) también están disponibles como métricas de percentil `.p50`, `.p95` y `.p99`. Por ejemplo, `gcp.istio.io.service.server.response_latencies.p99`.

Para más información sobre la telemetría del servicio de Istio, consulte la [documentación de observabilidad de Cloud Service Mesh de Google](https://cloud.google.com/service-mesh/docs/observability).
