## Requisitos previos [#prerequisites]

Antes de habilitar [<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360) para <DNT>Azure</DNT>, asegúrese de tener:

* Una cuenta de <DNT>Azure</DNT> con un ID de suscripción.
* Un registro de aplicación de <DNT>Azure</DNT> con el rol Lector de monitoreo.
* Una cuenta de New Relic inscrita en la versión preliminar de <DNT>Infrastructure 360</DNT>.
* Permisos para administrar integraciones en la nube en New Relic.

Para inscribirse en la versión preliminar, vaya a <DNT>**one.newrelic.com &gt; Administration &gt; Preview &amp; Trials**</DNT> e inscríbase en <DNT>**Infrastructure 360**</DNT>.

Existen tres formas de habilitar <DNT>Infrastructure 360</DNT> para <DNT>Azure</DNT>:

## Habilitar durante la incorporación a Azure [#onboarding-enable]

Si está conectando <DNT>Azure</DNT> a New Relic por primera vez, siga estos pasos:

1. Navegue hasta <DNT>**Infrastructure &gt; Azure**</DNT>.
2. Seleccione una cuenta y haga clic en <DNT>**Set up integration**</DNT>.
3. Siga los símbolos para crear el registro de la aplicación <DNT>Azure</DNT>. Para obtener instrucciones de configuración detalladas, consulte [Conectar integraciones de <DNT>Azure</DNT> ](/docs/infrastructure/microsoft-azure-integrations/get-started/activate-azure-integrations).
4. Durante la configuración de la integración, habilite la opción <DNT>**Infrastructure 360**</DNT> cuando aparezca el símbolo.
5. Configure la frecuencia de escaneo. De forma predeterminada, <DNT>Infrastructure 360</DNT> escanea tres veces al día. Para cambiar esto, consulte [Ajustar la frecuencia de escaneo](#adjust-frequency).

## Habilitar para una integración de Azure existente [#existing-enable]

Si ya tiene <DNT>Azure</DNT> integrado con New Relic, siga estos pasos:

1. Vaya a <DNT>**Infrastructure &gt; Azure**</DNT> y haga clic en <DNT>**Manage Infrastructure 360**</DNT>.
2. En la lista de cuentas, busque la suscripción de <DNT>Azure</DNT> y haga clic en <DNT>**Install**</DNT> (a nivel de cuenta de proveedor).
3. Configure la frecuencia de escaneo como se describe anteriormente.
4. Haga clic en <DNT>**Save**</DNT> para habilitar <DNT>Infrastructure 360</DNT> en la cuenta de <DNT>Azure</DNT>.

## Habilitar desde la página de infraestructura 360 [#landing-page-enable]

Para habilitar <DNT>Infrastructure 360</DNT> desde esta página:

1. Vaya a <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; Infrastructure 360**</DNT>.
2. Habilite la funcionalidad para las cuentas de proveedor de <DNT>Azure</DNT> (y <DNT>AWS</DNT>) en esta cuenta de New Relic.

Si esta página está en blanco (aún no ha habilitado <DNT>Infrastructure 360</DNT> para ningún proveedor), haga clic en <DNT>**Setup Infrastructure 360**</DNT> y luego habilite la funcionalidad.

## Habilite mediante Terraform [#terraform-enable]

También puede habilitar <DNT>Infrastructure 360</DNT> para <DNT>Azure</DNT> a través de <DNT>Terraform</DNT> en lugar de la UI de New Relic. Esta es una guía paso a paso para habilitar el descubrimiento automático para las integraciones de <DNT>Azure</DNT> mediante <DNT>Terraform</DNT>.

### Requisitos previos [#terraform-prerequisites]

Antes de comenzar, asegúrese de tener lo siguiente:

* **<DNT>Terraform</DNT> instalado**: <DNT>Terraform</DNT> instalado en su máquina local.
* **ID de cuenta de New Relic**: el ID de cuenta de New Relic (`newrelic_account_id`).
* **Clave de API de usuario de New Relic**: una clave de usuario para autenticarse en New Relic (`newrelic_api_key`).
* **ID de la cuenta de proveedor vinculada**: el ID de la cuenta de <DNT>Azure</DNT> tal como lo reconoce New Relic (`provider_account_id`). Esto suele encontrarse en la UI de New Relic en <DNT>**Infrastructure &gt; Azure**</DNT>.
* **Región**: su región de datos de New Relic (EE. UU. o UE).

<Steps>
<Step>
### Configure el espacio de trabajo [#setup-workspace]

Configure una carpeta local para la configuración de <DNT>Terraform</DNT>:

1. Abra la terminal o el símbolo del sistema.

2. Cree una nueva carpeta para el proyecto:

   ```bash
   mkdir terraform-integrate
   cd terraform-integrate
   ```
</Step>

<Step>
### Cree archivos de configuración [#create-config-files]

Cree los siguientes tres archivos dentro de la carpeta `terraform-integrate`. Puede usar cualquier editor de texto.

#### providers.tf

Este archivo le indica a <DNT>Terraform</DNT> qué plug-ins descargar.

```hcl
terraform {
  required_providers {
    newrelic = {
      source = "newrelic/newrelic"
    }
  }
}
```

#### variables.tf

Este archivo define las entradas necesarias para ejecutar el script.

```hcl
variable "provider_account_id" {
  description = "The Azure Subscription ID Equivalent in Newrelic (Linked Account ID)."
  type        = number
}

variable "new_relic_region" {
  description = "The New Relic region (e.g., 'US', 'EU', or 'JP')."
  type        = string
  default     = "US"
}

variable "newrelic_account_id" {
  description = "The New Relic account ID."
  type        = number
}

variable "newrelic_api_key" {
  description = "The New Relic API key."
  type        = string
}
```

#### main.tf

Este es el script principal que habilita la característica de autodescubrimiento.

```hcl
provider "newrelic" {
  account_id = var.newrelic_account_id
  region     = var.new_relic_region
  api_key    = var.newrelic_api_key
}

resource "newrelic_cloud_azure_integrations" "auto_discovery_integrations" {
  linked_account_id = var.provider_account_id

  # This block enables auto-discovery for the account
  auto_discovery {}
}
```
</Step>

<Step>
### Ejecute Terraform [#run-terraform]

Ahora que los archivos están listos, ejecute estos comandos en la terminal desde la carpeta `terraform-integrate`.

1. **Inicializar**: descarga los plug-in necesarios del proveedor de New Relic.

   ```bash
   terraform init
   ```

2. **Plan**: comprueba la configuración y le muestra lo que sucederá. <DNT>Terraform</DNT> le solicita que ingrese sus ID y claves aquí.

   ```bash
   terraform plan
   ```

   Ingrese los valores cuando se le solicite en el símbolo para `newrelic_account_id`, `newrelic_api_key` y las otras variables.

3. **Aplicar**: ejecuta el plan y habilita la integración.

   ```bash
   terraform apply
   ```

   Escriba `yes` cuando se le solicite confirmar.
</Step>
</Steps>

Para obtener más información, consulte la [documentación del proveedor <DNT>Terraform</DNT> de New Relic](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#azure).

## Utilice infraestructura 360 [#using-infrastructure-360]

Una vez habilitado, <DNT>Infrastructure 360</DNT> le permite comprobar las relaciones entre todas las entidades de <DNT>Azure</DNT>, incluida la infraestructura, APM y las bases de datos.

<Callout title="Nota">
<DNT>Infrastructure 360</DNT> admite relaciones de entidades a través de agentes APM nativos de New Relic (<DNT>Java</DNT>, <DNT>.NET</DNT>, <DNT>Python</DNT>) y <DNT>OpenTelemetry</DNT> (<DNT>.NET</DNT>).

Para los clúster <DNT>Azure Kubernetes Service</DNT> (<DNT>AKS</DNT>) específicamente, conectar la aplicación al clúster <DNT>AKS</DNT> requiere el agente <DNT>Kubernetes</DNT> de New Relic o <DNT>OpenTelemetry</DNT>. <DNT>Infrastructure 360</DNT> no establece esa conexión por sí solo, pero una vez que existe, completa la cadena mediante el mapeo de la relación desde la aplicación a través del clúster <DNT>AKS</DNT> hacia la otra infraestructura <DNT>Azure</DNT> de la que depende.
</Callout>

### Ver entidades y relaciones descubiertas [#view-entities]

Para ver las entidades descubiertas y sus relaciones:

1. Vaya a <DNT>**All entities**</DNT> y filtre por `collector.name = auto discovery`.

2. Seleccione cualquier entidad <DNT>Azure</DNT> para ver su mapa de infraestructura, que muestra las relaciones entre:

   * <DNT>Azure</DNT> entidades (máquinas virtuales, bases de datos, cuentas de almacenamiento).
   * Entidades de APM (aplicaciones, servicios).
   * Conexiones multiplataforma (<DNT>Azure</DNT> recursos conectados a servicios de APM).

### Relaciones entre suscripciones [#cross-subscription]

Si un recurso descubierto se conecta a un recurso en una suscripción de <DNT>Azure</DNT> diferente, <DNT>Infrastructure 360</DNT> resuelve la relación automáticamente:

* Si la suscripción objetivo también está integrada con <DNT>Infrastructure 360</DNT>, el mapa muestra la entidad objetivo real y sus detalles.
* Si no ha integrado o monitoreado la suscripción objetivo, el mapa muestra una entidad desconocida o no instrumentada en su lugar —la conexión sigue siendo visible, pero los detalles de la entidad no están disponibles.

### Correlacionar los cambios de configuración con las alertas [#correlate-config-changes]

<DNT>Infrastructure 360</DNT> realiza un seguimiento de los cambios de configuración en los recursos de <DNT>Azure</DNT> para que pueda determinar rápidamente si un cambio reciente provocó una alerta o un incidente, en lugar de investigar los datos de la infraestructura y de la aplicación por separado.

1. Vaya a <DNT>**All capabilities**</DNT> y seleccione <DNT>**Azure Services**</DNT>.
2. Seleccione cualquier entidad de la lista y haga clic en <DNT>**Configuration explorer**</DNT> para ver sus ajustes, etiquetas y propiedades actuales.
3. Compare los timestamp en la línea de tiempo de cambios de configuración con sus alertas o incidentes. Un cambio de configuración casi al mismo tiempo que una alerta es un claro indicio de la causa raíz, lo que le permite correlacionar los cambios de configuración con sus alertas e incidentes.

## Administrar la configuración de infraestructura 360 [#manage-settings]

### Ajustar la frecuencia de escaneo [#adjust-frequency]

Puede personalizar con qué frecuencia <DNT>Infrastructure 360</DNT> escanea su entorno <DNT>Azure</DNT>:

1. Vaya a <DNT>**Infrastructure &gt; Azure**</DNT> y haga clic en <DNT>**Manage Infrastructure 360**</DNT>.
2. Busque la cuenta de <DNT>Azure</DNT> y haga clic en <DNT>**Edit**</DNT>.
3. Seleccione la frecuencia de escaneo preferida del menú desplegable.
4. Haga clic en <DNT>**Save**</DNT> para aplicar los cambios.

Considere aumentar la frecuencia de escaneo si realiza cambios frecuentes en el entorno de <DNT>Azure</DNT>, o disminuirla si la infraestructura es estable y desea reducir las llamadas API.

### Desactivar Infraestructura 360 [#disable]

<Callout variant="important">
Cuando deshabilita <DNT>Infrastructure 360</DNT>, pierde el acceso a:

* Entidades descubiertas automáticamente y su configuración.
* Mapeo de relaciones entre los recursos de <DNT>Azure</DNT> y los servicios de APM.
* Actualizaciones en tiempo real de la topología de la infraestructura.
</Callout>

Si vuelve a habilitar <DNT>Infrastructure 360</DNT> más adelante, recrea las entidades y relaciones que ya no existen durante el próximo escaneo programado.

Para deshabilitar <DNT>Infrastructure 360</DNT>, siga estos pasos:

1. Vaya a <DNT>**Infrastructure &gt; Azure**</DNT> y haga clic en <DNT>**Manage Infrastructure 360**</DNT>.
2. Busque la cuenta donde desea desactivar <DNT>Infrastructure 360</DNT>.
3. Haga clic en <DNT>**Edit**</DNT> y desactive el interruptor de escaneo.
4. Haga clic en <DNT>**Save**</DNT> para confirmar el cambio.
