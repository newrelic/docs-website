For a seamless integration of your AWS account with New Relic, [integration via CloudFormation and CloudWatch metric stream](/docs/infrastructure/amazon-integrations/aws-integration-for-metrics/via-cloudformation) is the recommended approach. If you can&apos;t use CloudFormation templates and don&apos;t want to use Terraform, follow this procedure to integrate manually from the AWS console.

<Callout variant="tip">
  * If you manage multiple AWS accounts, [connect each account to a single New Relic account](/docs/infrastructure/amazon-integrations/manage-aws-data/aws-multi-account).
  * If you manage multiple regions within those accounts, create a separate [Kinesis Data Firehose](#create-firehose) for each region.
</Callout>

<Steps>
  <Step>
    ## Requisitos previos [#prerequisites]

    Antes de comenzar a integrar su cuenta de AWS con New Relic, cerciorar de cumplir con los siguientes requisitos previos:

    * **Una [clave de licencia de New Relic Ingest y una clave de usuario](https://one.newrelic.com/api-keys)**: necesitará estas claves para conectar sus servicios de AWS a su cuenta de New Relic.
    * **[Permissions](https://docs.aws.amazon.com/ARG/latest/userguide/gettingstarted-prereqs-permissions.html)** to deploy new AWS resources and **[IAM roles](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)**: You&apos;ll need this permission for your AWS account.
    * **[Licencias](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions/#infrastructure)** para la integración en la nube: necesitarás estas licencias para tu cuenta New Relic.
  </Step>

  <Step>
    ## Create a Kinesis Data Firehose delivery stream [#create-firehose]

    In the AWS console, set the following destination parameters for the delivery stream:

    * Fuente: <DNT>Direct PUT</DNT> u otras fuentes

    * Destino: New Relic

    * Data transformation: <DNT>Disabled</DNT>

    * Record format conversion: <DNT>Disabled</DNT>

    * Asegúrese de que estén definidas las siguientes configuraciones:

      * Configuración de New Relic (ajustes de destino):

        * URL del extremo HTTP:

          * Centro de datos de EE. UU.: `https://aws-api.newrelic.com/cloudwatch-metrics/v1`
          * Centro de datos de la UE: `https://aws-api.eu01.nr-data.net/cloudwatch-metrics/v1`
          * Centro de datos de JP: `https://aws-api.jp.nr-data.net/cloudwatch-metrics/v1`

        * Clave de API: Introduce tu<InlinePopover type="licenseKey" />

        * Codificación de contenido: `GZIP`

        * Duración del reintento: `60`

        * Condiciones de búfer de New Relic:

          * Tamaño del búfer: `1 MB`
          * Intervalo de buffer: `60 (seconds)`

      * S3 backup mode: <DNT>Failed data only</DNT>

      * Bucket de respaldo de S3: seleccione un bucket o cree uno nuevo para almacenar las métricas que no se pudieron enviar.

      * Configuración avanzada:
        * Acceso al servicio: proporcione permisos para el rol de IAM:
          * <DNT>Create or update IAM role</DNT>
  </Step>

  <Step>
    ## Crear un CloudWatch Metric Streams [#create-metric-stream]

    1. In the AWS console, go to <DNT>**CloudWatch service**</DNT>, select <DNT>**Streams**</DNT> under the <DNT>**Metrics**</DNT> menu, and click <DNT>**Create metric stream**</DNT>.
    2. To control which AWS services send metrics to New Relic, configure inclusion and exclusion filters.
    3. From the Firehose delivery stream list, select the stream you created, then enter a meaningful name for the metric stream, for example, `newrelic-metric-stream`.
    4. En el campo de formato de salida, seleccione `Open Telemetry 0.7` o `Open Telemetry 1.0`. No se admite JSON.
  </Step>

  <Step>
    ## Connect your AWS account to New Relic [#connect-aws-account]

    1. En New Relic, vaya a [<DNT>**Infrastructure &gt; AWS**</DNT>](https://one.newrelic.com/infra/infrastructure/cloud-aws).

    2. Seleccione la cuenta correcta.

    3. Haga clic en <DNT>**Set up integration**</DNT>.

    4. En cada pantalla, complete los campos que correspondan. Para esta integración, seleccione las siguientes opciones:

       * <DNT>**Choose Data type(s)**</DNT>: <DNT>Metrics</DNT>
       * <DNT>**Choose a setup method**</DNT>: <DNT>Manually integrate your AWS account</DNT>

    5. En la pantalla <DNT>**Select services**</DNT>, active <DNT>**Show resources not supported by CloudWatch Metric Streams**</DNT> si es necesario, seleccione los servicios que desea monitorear y continúe.

    6. En la pantalla <DNT>**Choose data integration type**</DNT>, elija entre las siguientes opciones:

       * **Real-time AWS monitoring (Recommended)**: This option is for services that support CloudWatch Metric Streams.
       * **Sondeo de API**: esta opción es para los servicios que no son compatibles con CloudWatch Metric Streams.

    7. From the <DNT>**Create role**</DNT> page to the <DNT>**Configure budgets policy**</DNT> page, follow the on-screen instructions and complete the steps in the AWS console.
  </Step>

  <Step>
    ## Valida tus datos [#validate]

    Para confirmar que está recibiendo datos de los Streams de métricas:

    1. In New Relic, go to <DNT>**[one.newrelic.com &gt; All capabilities &gt; Infrastructure &gt; AWS](https://one.newrelic.com/infra/infrastructure/cloud-aws)**</DNT>, search for your connected AWS account, and look for **Stream** accounts.
    2. En el dashboard de estado de la cuenta, confirme que New Relic está recibiendo datos métricos, incluidos los errores y el número de namespace y métrica ingeridos.
    3. Para explorar métricas específicas, escriba consultas para los conjuntos de métricas que desea analizar.

    Es posible que New Relic tarde unos minutos en detectar nuevos recursos y sintetizarlos como entidad.

    <Callout variant="tip">
      AWS CloudWatch metrics for global services, such as AWS Billing, are only available in the <DNT>**us-east-1**</DNT> region. Make sure there&apos;s an active CloudWatch metric stream configured in that region.
    </Callout>
  </Step>
</Steps>
