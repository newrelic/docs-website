El [Control de agentes de New Relic](/docs/new-relic-control/agent-control/overview) con Terraform proporciona una solución potente y declarativa para gestionar flotas de agentes a escala. Al usar Terraform y el Control de agentes de forma conjunta, puede garantizar un enfoque coherente, repetible y escalable para desplegar la instrumentación de New Relic en toda la infraestructura, especialmente al tratar con múltiples clústeres de Kubernetes.

## Requisitos previos [#prereqs]

Antes de comenzar, cerciorar de tener lo siguiente:

* **Herramientas necesarias:**

  * **[Terraform](https://developer.hashicorp.com/terraform/tutorials/aws-get-started/install-cli)** instalado en su máquina.
  * **Helm 3** instalado en su máquina. Para obtener instrucciones de instalación, consulte [Instalación de Helm](https://helm.sh/docs/intro/install).
  * **[Proveedor Terraform Helm](https://registry.terraform.io/providers/hashicorp/helm/latest/docs)** incluido en el script de configuración de Terraform para que la instalación funcione.

* **Credenciales de New Relic:**

  * **Clave de licencia New Relic :** Necesitará una clave de licencia New Relic para informar la telemetría a su cuenta New Relic .
  * **Clave de usuario de New Relic:** Necesitarás tu [clave de usuario de New Relic](/docs/apis/intro-apis/new-relic-api-keys/) si aún no extrajiste tu clave `clientID` y tu secreto.

* **Detalles de configuración:**

  * **ID de organización New Relic :** New Relic `OrgId` identificará de qué organización obtiene su clave de identificación de cliente y secreto.
  * **Permisos de usuario:** el usuario necesita los permisos correctos para crear una [identidad del sistema](/docs/accounts/accounts-billing/new-relic-one-user-management/system-identities). Esto normalmente requiere el rol de administrador de dominio de autenticación o de New Relic Control.
  * **Nombre del clúster de Kubernetes:** tenga listo el nombre de su clúster de Kubernetes, ya que se hará referencia a él durante el proceso de instalación.

<Callout variant="tip">
Al configurar un nuevo clúster con Terraform, asegúrese de usar el mismo nombre de clúster durante la instalación del Control de agentes.
</Callout>

### Compatibilidad con Kubernetes [#compatibility]

Para saber qué versiones de Kubernetes son compatibles con esta solución, consulte la sección [de compatibilidad](/docs/new-relic-control/agent-control/overview/#compatibility) en la descripción general.

## Instalar [#installation]

Si no tiene `clientId` y `clientSecret`, emplee la siguiente llamada API [de NerdGraph](https://docs.newrelic.com/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/) para generarlos. Esto requiere su clave de usuario administrador de New Relic y el ID de la organización.

```sh
curl -X POST \
     https://api.newrelic.com/graphql \
     -H 'Content-Type: application/json' \
     -H 'x-api-key: [INSERT_USER_API_KEY]' \
     --data-raw '{"query": "mutation SICreate { systemIdentityCreate(name: \"User Key for Agent Control\" organizationId: \"[INSERT_YOUR_ORG_ID]\") { clientId clientSecret } }"}' \
     --compressed
```

En el comando, reemplace los valores de marcador de posición con su `organizationId` y su clave de usuario. Esto devuelve las credenciales requeridas que empleará en su archivo de configuración.

### Paso 1: Crea tu directorio de proyectos

Crea un directorio para tu proyecto y coloca tu archivo `main.tf` dentro de él. Aquí es donde definirás tus recursos de Terraform. Confirme que agregó el [proveedor Helm](https://registry.terraform.io/providers/hashicorp/helm/latest/docs) a su archivo Terraform.

### Paso 2: Configurar Terraform con la versión Helm

Configure su script de Terraform con una versión de Helm que emplee los gráficos de New Relic para el control del agente. El siguiente ejemplo muestra una configuración básica:

```hcl
provider "helm" {
  kubernetes {
    config_paths = [
      "~/.kube/config"
    ]
  }
}

resource "helm_release" "newrelic" {
  name = "agent-control"
  repository = "https://newrelic.github.io/helm-charts/"
  chart = "agent-control"
  namespace = "newrelic"
  create_namespace = "true"

  values = [
    file("./values-newrelic.yaml")
  ]
}
```

Tenga en cuenta que el script de Terraform hace referencia a un archivo `values-newrelic.yaml` . Este es el archivo de configuración de Agent Control de New Relic que se empleará para configurar el Agent Control. No es necesario que esté en el mismo directorio que el script de Terraform. Puede hacer referencia a él desde cualquier ubicación proporcionando la ruta correcta en la función `file()` dentro del atributo de valores del recurso `helm_release` .

O bien, si coloca el archivo `values-newrelic.yaml` directamente en el directorio del proyecto Terraform, el script `main.tf` hará referencia a él automáticamente.

A continuación se muestra un ejemplo de un archivo `values-newrelic.yaml` básico sin configuración adicional incluida:

```yaml
global:
  cluster: [YOUR_CLUSTER_NAME]
  licenseKey: [YOUR_INGEST_LICENSE_KEY]


agentControlDeployment:
  chartValues:
    systemIdentity:
      organizationId: [ORG_ID]
      parentIdentity:
        clientId: [YOUR_IDENTITY_CLIENT_ID]
        clientSecret: [YOUR_IDENTITY_CLIENT_SECRET]
    config:
      fleet_control:
      # optional
        fleet_id: [YOUR_FLEET_ENTITY_GUID]
      log:
        level: trace
```

Para explorar todas las configuraciones disponibles, consulte [`values-newrelic.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/agent-control/values.yaml).

### Paso 3: Ejecutar comandos de Terraform

Inicialice Terraform, revise el plan y aplique los cambios.

```shell
# Initialize Terraform
terraform init
```

```shell
# Review the changes before applying
terraform plan
```

```shell
# Apply the changes to your cluster
terraform apply
```

### Paso 5: Verificar la instalación

Verifique que el pod de control del agente y cualquier agente configurado se estén ejecutando correctamente en sus respectivos espacios de nombres.

```shell
# Check Agent Control pods
kubectl get pods -n newrelic
```

```shell
# Check pods in the agent namespace, e.g., 'newrelic-agents'
kubectl get pods -n newrelic-agents
```

## Configuración [#configuration]

En el archivo `values-newrelic.yaml` , puede configurar el agente Control para desplegar múltiples agentes de monitoreo. A continuación se muestra un ejemplo que muestra la implementación de varios agentes, incluidos:

* **Infrastructure:** agente de infraestructura de New Relic
* **Logs:** Agente de registros de Fluent Bit
* **OpenTelemetry:** La distribución New Relic del Collector OpenTelemetry
* **Gateway:** Agente de puerta de enlace [de New Relic Pipeline Control](/docs/new-relic-control/pipeline-control/overview)

```yaml
agentControlDeployment:
  chartValues:
    systemIdentity:
      organizationId: "****"
      parentIdentity:
        clientId: [YOUR_IDENTITY_CLIENT_ID]
        clientSecret: [YOUR_IDENTITY_CLIENT_SECRET]
    config:
      agents:
        infrastructure:
          agent_type: newrelic/com.newrelic.infrastructure:0.1.0
        logs:
          agent_type: newrelic/io.fluentbit:0.1.0
        agent-operator:
          agent_type: com.newrelic.k8s_agent_operator:0.1.0
        open-telemetry:
          agent_type: newrelic/com.newrelic.opentelemetry.collector:0.1.0
        gateway:
          agent_type: newrelic/com.newrelic.pipeline_control_gateway:0.1.0
    agentsConfig:
      infrastructure:
        chart_version: "*"
        chart_values:
          newrelic-infrastructure:
            enableProcessMetrics: true
      logs:
        # Ref: `https://github.com/newrelic/helm-charts/tree/master/charts/newrelic-logging`
        # Recommended: check and define an explicit chart version (latest stable)
        chart_version: "*"
          chart_values:
            newrelic-logging:
              sendMetrics: true
      agent-operator:
        chart_version: "*"
      open-telemetry:
        # Ref: `https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/values.yaml`
        # Recommended: check and define an explicit chart version (latest stable)
        chart_version: "*"
          chart_values:
            nr-k8s-otel-collector:
              receivers.filelog.enabled: false
      gateway:
        chart_version: "*"
        chart_values:
          gateway:
            autoscaling:
              minReplicas: 2
              maxReplicas: 10
              targetCPUUtilizationPercentage: 70
```

<Callout variant="important">
**Importante:** Para el entorno de producción, recomendamos encarecidamente emplear un `chart_version` específico fijado en lugar de un comodín (`*`). Esto garantiza actualizaciones consistentes y previsibles, evitando comportamientos inesperados o cambios radicales.
</Callout>

## Desinstalar [#uninstall]

<Callout variant="important">
Eliminar un recurso de lanzamiento de Helm de su configuración de Terraform es una **acción destructiva**. Cuando ejecute `terraform apply` luego de este cambio, Terraform desinstalará el gráfico y destruirá **todos** los recursos relacionados, lo que podría provocar la pérdida de datos. Antes de continuar, cerciorar de comprender completamente el impacto potencial en su entorno:

* Revisar todas las dependencias y servicios que pudieran ver afectados.
* Considere realizar una copia de seguridad de cualquier dato persistente o configuración vinculada a la versión.
* Confirme que eliminar esta versión es necesario y se ajusta a su estrategia de gestión de infraestructura. Tenga siempre cuidado al realizar cambios significativos en su infraestructura y cerciorar de tener procedimientos de reversión adecuados en caso de que algo salga mal.
</Callout>

### Para desinstalar Agente Control:

1. **Elimine el bloque de recursos `helm_release` **para `newrelic_agent_control` de su archivo `main.tf` .
2. **Ejecute `terraform plan`** para revisar los cambios. Examine cuidadosamente el resultado del plan para cerciorar de que solo los recursos previstos estén marcados para su eliminación.
3. **Ejecute `terraform apply`** y confirme la ejecución para desinstalar la versión. Esto implementará los cambios planeados y eliminará efectivamente la versión de Helm especificada de su entorno.

Confirme la ejecución cuando aparezca el símbolo para completar el proceso de desinstalación.
