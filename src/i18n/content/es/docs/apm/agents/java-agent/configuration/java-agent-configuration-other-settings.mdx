Estos ajustes cubren opciones adicionales de configuración del agente de Java, que incluyen la detección de la plataforma cloud, los controles de rendimiento y la configuración del ciclo de vida del agente.

<Callout variant="tip">
Volver al índice completo de ajustes: [configuración del agente de Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## Interruptor

Estas configuraciones personalizan el comportamiento del [interruptor Java](/docs/agents/java-agent/custom-instrumentation/circuit-breaker-java-custom-instrumentation). Estas configuraciones no están incluidas en `newrelic.yml` de forma predeterminada. No es necesario reiniciar su JVM después de cambiarlos.

Si desea personalizar el interruptor, agréguelo en la sección `common` :

```yml
common: &default_settings​
  OTHER_CONFIG_SETTINGS
  circuitbreaker:
    enabled: true
    memory_threshold: 20
    gc_cpu_threshold: 10
```

Personaliza el porcentaje de memoria de montón libre por debajo del cual debe disparar el interruptor. Cuando el porcentaje de memoria del montón libre es menor que `memory_threshold` y el tiempo de CPU empleado en la recolección de basura es mayor que `gc_cpu_threshold`, el interruptor se dispara. Para que sea menos probable que se dispare el interruptor, disminuya `memory_threshold` y/o aumente `gc_cpu_threshold`. Ajuste estos valores según sea necesario, en función del comportamiento y el rendimiento operativo de su aplicación.
</Collapser>

## Configuración de la nube

Establezca las opciones relacionadas con cloud , en la sección `cloud` del YAML del agente. Puede anular estas configuraciones con una [propiedad del sistema](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#System_Properties) con prefijo `newrelic.config.cloud` o una [variable de entorno](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Environment_Variables) con prefijo `NEW_RELIC_CLOUD_` .

Un ejemplo de configuración:

```yml
cloud:
  aws:
    account_id: 123456789012
  metadata_bypass_proxy: false
```

## Evento personalizado [#Custom_Events]

Establezca la configuración de evento personalizado en la sección `custom_insights_events`. Puede [anular](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) esta configuración con una propiedad del sistema con el prefijo `newrelic.config.custom_insights_events`.

APM le permite [registrar datos de eventos personalizados](/docs/insights/insights-data-sources/custom-data/insert-custom-events-new-relic-apm-agents) a través del agente de lenguaje de API de New Relic, que [luego puede consultar](/docs/query-your-data/explore-query-data/explore-data/introduction-querying-new-relic-data).

<Callout variant="important">
Para versiones de agente de Java anteriores a 4.1.0, Se reconoce la siguiente configuración YAML:

```yml
custom_insights_events.enabled: true
  custom_insights_events.max_samples_stored: 5000
```

Para las versiones del agente 4.1.0 y superiores, la configuración YAML utiliza el formato de sección anidada:

```yml
custom_insights_events:
  enabled: false
  max_samples_stored: 5000
```
</Callout>

## Propiedades de JVM de uso

El agente de Java envía propiedades JVM a New Relic para mostrarlas en la UI. A partir de la versión `8.16.0` del agente de Java , los valores de la mayoría de las propiedades se ofuscarán. Por ejemplo: `-Dprop=12345` ahora se enviará como `-Dprop=obfuscated`.

Establezca las opciones relacionadas con la ofuscación en la sección `obfuscate_jvm_props` del YAML del agente. Puede anular estas configuraciones con una [propiedad del sistema](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#System_Properties) con prefijo `newrelic.config.obfuscate_jvm_props` o una [variable de entorno](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Environment_Variables) con prefijo `NEW_RELIC_OBFUSCATE_JVM_PROPS_` .

De forma predeterminada, los valores de las propiedades que comienzan con `-X` no se ofuscarán.

## Saltar aplicación [#skip-applications]

El agente se puede habilitar o deshabilitar selectivamente en función de la clase principal de inicio o el archivo jar ejecutable que se extrae de la línea de comandos. Esto es útil en situaciones en las que la variable de entorno &quot;JAVA\_TOOL\_OPTIONS&quot; está presente y contiene la bandera -javaagent, pero no queremos aplicar la instrumentación a todas las aplicaciones java en el entorno, por ejemplo, en un contenedor de Kubernetes.

<Callout variant="important">
La configuración de omisión solo es compatible a través de una propiedad del sistema y una variable de entorno debido a lo temprano en el ciclo de vida del agente que se debe verificar la configuración de omisión.
</Callout>

Para fines de diagnóstico, si se define alguna de las variables de configuración de exclusión o inclusión, el agente imprimirá la línea de comandos extraída y los tokens de omisión analizados en stdout:

```
New Relic Agent: New Relic Agent: Configured startup Java artifacts [include|skip] string: keytool,Main
New Relic Agent: Retrieved current startup command line / main artifact name: /Users/bob/.sdkman/candidates/java/11.0.17-amzn/bin/keytool
```

Si el agente está deshabilitado en función de una variable de configuración de inclusión u omisión, lo siguiente se volcará en stdout:

```
----------
New Relic Agent is disabled by startup class/jar skip or include configuration.
----------
```

## Eliminación temporal del archivo Jar [#temporary-jar-file-removal]

En algunos entornos de clientes, los archivos jar temporales del agente no se limpian correctamente, aunque estos archivos jar están marcados para ser eliminados al finalizar la JVM. Esto se debe probablemente a la terminación anormal de la JVM. Esta configuración indica al agente que elimine cualquier archivo jar temporal del agente anterior al valor especificado al inicio.

<Callout variant="important">
Esta configuración solo es compatible a través de una propiedad del sistema o una variable de entorno debido a lo temprano que debe ocurrir la eliminación del archivo en el ciclo de vida del agente.
</Callout>

Para fines de diagnóstico, si esta función está habilitada, se escribirá lo siguiente en la consola:

```
New Relic Agent: Removing stale temporary agent file jars from [temporaryFolder] older than [X] hour(s)
```

Si se elimina algún archivo, lo siguiente se escribirá en la consola:

```
New Relic Agent: Deleted [count] stale temporary jar files freeing up [totalBytes] bytes
```
