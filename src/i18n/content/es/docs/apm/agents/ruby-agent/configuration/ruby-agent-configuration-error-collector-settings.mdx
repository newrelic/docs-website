Configure el recolector de errores del agente de Ruby para personalizar cómo se capturan los errores, qué errores ignorar o tratar como esperados y cómo se muestrean los eventos de error.

## Recolector de errores [#error-collector]

El agente recopila e informa todas las excepciones no detectadas de forma predeterminada. Estas opciones de configuración le permiten personalizar la recopilación de errores.

Para obtener información sobre errores ignorados y esperados, [consulte esta página sobre Análisis de errores en APM](/docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected/). Para establecer el error esperado a través del `NewRelic::Agent.notice_error` Ruby método, [consulte la Ruby API del](/docs/agents/ruby-agent/api-guides/sending-handled-errors-new-relic/) agente.

## Configuración Errors Inbox [#errors-inbox-configuration]

Configurar una de las siguientes variables de entorno le ayudará a identificar qué versiones de su software produjeron los errores.

* `NEW_RELIC_METADATA_SERVICE_VERSION` crea `tags.service.version` en los datos del evento que contienen la versión de su código que está desplegada, en muchos casos una versión semántica como `1.2.3`, pero no siempre.
* `NEW_RELIC_METADATA_RELEASE_TAG` crea `tags.releaseTag` en los datos del evento que contienen la etiqueta de lanzamiento (como `v0.1.209` o `release-209`).
* `NEW_RELIC_METADATA_COMMIT` crea `tags.commit` en los datos del evento que contienen el SHA del commit. Se puede utilizar el SHA completo o solo los primeros siete caracteres (por ejemplo, `734713b`).

[Errors Inbox](/docs/errors-inbox/version-tracking/) rastreará automáticamente qué versiones de su software están produciendo errores.
