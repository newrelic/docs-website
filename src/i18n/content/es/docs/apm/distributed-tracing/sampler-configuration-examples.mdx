Si bien la configuración de muestreo predeterminada funciona para todos los servicios, puede que no sea óptima. Los agentes de APM proporcionan opciones de configuración de muestreo para que pueda personalizar el muestreo y ajustarlo a las necesidades de su servicio. Esta página presenta algunos ejemplos reales de diferentes tipos de servicios y cómo puede modificar la configuración de muestreo para adaptarse a esas necesidades.

Los ejemplos de configuración de esta página utilizan el formato YAML (agente de Java). Para ver la sintaxis equivalente en su lenguaje y la referencia completa de los parámetros, consulte la documentación del agente:

* [Configuración de rastreo distribuido del agente de Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
* [Configuración de rastreo distribuido del agente de Node.js](/docs/apm/agents/nodejs-agent/installation-configuration/nodejs-agent-configuration)
* [Configuración de rastreo distribuido del agente Python](/docs/apm/agents/python-agent/configuration/python-agent-configuration)

## Requisitos previos

Esta guía asume familiaridad con los contextos y tipos de muestreadores. Visite la página [Configurar muestreo](/docs/apm/distributed-tracing/distributed-trace-sampling) para obtener una descripción general completa de los conceptos de los muestreadores.

## Ejemplo 1: distribución deficiente de extremos capturados debido a extremos que se llaman raramente

El muestreador predeterminado, el muestreador adaptativo, muestrea alrededor de 10 trazas por minuto para la mayoría de los agentes de lenguaje de APM. Dado que el muestreador adaptativo elige las trazas al azar, es más probable que muestree los extremos llamados con frecuencia que los extremos llamados con poca frecuencia.

### Solución: aumentar el objetivo de muestreo adaptativo

Al aumentar el `adaptive_sampling_target` se muestrean más trazas cada minuto, lo que aumenta la probabilidad de capturar trazas para extremos poco frecuentes.

```yaml
distributed_tracing:
  sampler:
    adaptive_sampling_target: 20  # Increase from default 10 to 20
```

## Ejemplo 2: distribución deficiente de extremos capturados debido al muestreo ascendente

Con el muestreador adaptativo predeterminado, el servicio actual también muestrea cualquier traza entrante que un servicio ascendente ya haya muestreado. A veces, esto genera demasiadas trazas de extremos con un padre ascendente y muy pocas trazas de otros extremos.

### Solución: reducir la tasa de muestreo para las trazas muestreadas por un servicio upstream

El muestreador basado en la proporción de ID de traza se puede utilizar para muestrear las trazas muestreadas por un servicio upstream solo el 10 % del tiempo. Esto reduce la probabilidad de llenar el depósito de spans con trazas que fueron muestreadas por un servicio upstream.

```yaml
distributed_tracing:
  sampler:
    remote_parent_sampled:
      trace_id_ratio_based:
        ratio: 0.1
```

## Ejemplo 3: cambiar la distribución de trazas para todos los contextos

[Ejemplo 2](#example-2-poor-distribution-of-endpoints-captured-due-to-upstream-sampling) —demasiadas trazas muestreadas por un servicio upstream— es un caso específico de un problema más general: desea tener más control sobre la distribución de las trazas que ve en todos los contextos de traza.

### Solución: superponer múltiples muestreadores de proporción

Podemos basarnos en el ejemplo anterior superponiendo múltiples muestreadores de proporción de trazas. La tasa de muestreo de cada contexto de traza es independiente, por lo que cada proporción se puede ajustar para lograr la distribución deseada de trazas.

En este ejemplo, cada contexto de traza utiliza un muestreo basado en proporciones. Las proporciones se configuran para muestrear `25%` de `root` trazas (en lugar de un número fijo), `50%` de las trazas muestreadas por un servicio ascendente (en lugar de todas) y `5%` de las trazas no muestreadas por un servicio ascendente (en lugar de ninguna).

```yaml
distributed_tracing:
  sampler:
    root:
      trace_id_ratio_based:
        ratio: 0.25
    remote_parent_sampled:
      trace_id_ratio_based:
        ratio: 0.5
    remote_parent_not_sampled:
      trace_id_ratio_based:
        ratio: 0.05
```
