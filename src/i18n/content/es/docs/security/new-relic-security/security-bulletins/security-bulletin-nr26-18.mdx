## Resumen

Se reveló una vulnerabilidad crítica (puntuación CVSS 4.0 de 9.2) en la extensión de sesión del entorno de ejecución de PHP. Afecta a las aplicaciones que utilizan el controlador de sesión de archivos predeterminado de PHP. El proyecto PHP publicó correcciones el 19 de noviembre de 2026.

Las versiones de corrección de octubre de 2026 para CVE-2026-109618 y CVE-2026-109619 ([NR26-10](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-10)) no incluyen esta corrección. Las aplicaciones que mantienen sesiones en una base de datos o Redis en lugar del manejador de archivos nativo están fuera de esta vulnerabilidad.

**El software y los servicios distribuidos por New Relic no se ven afectados.** New Relic no incluye un entorno de ejecución de PHP en ningún software distribuido a los clientes. El agente PHP de New Relic se ejecuta dentro del propio entorno PHP de los clientes y no es el componente vulnerable. El agente PHP se ejecuta como una extensión dentro del intérprete de PHP existente de los clientes, lo que significa que la corrección se maneja actualizando el propio PHP. New Relic no ha identificado evidencia de explotación en su entorno.

## Acción recomendada

No se requiere ninguna acción con respecto a su software y sus servicios de New Relic. Sin embargo, New Relic recomienda enfáticamente a los clientes que ejecutan aplicaciones PHP, con o sin instrumentación de New Relic, que actualicen a la versión corregida para su rama y reinicien todos los workers de PHP. Las mismas versiones corrigen 17 avisos, por lo que una actualización los cubre todos.

### Recomendaciones

* **Paquetes de distribución:**
  * Una distribución puede incluir la corrección sin cambiar la cadena de versión de PHP. Consulte el aviso de seguridad del proveedor en lugar de depender del número de versión.
* **Versiones al final de su vida útil (PHP 8.1 y anteriores):**
  * Estas versiones no figuran en el registro CVE y no reciben correcciones oficiales. Trate las compilaciones sin parches como afectadas, compruebe si la distribución ha aplicado un backport de la corrección y planifique una actualización a una rama con soporte.
* **Alojamiento administrado:**
  * Confirme con su proveedor que todos los entornos, incluidos los de desarrollo, prueba y vista previa, ejecuten una versión corregida.

## Mitigación temporal

Solo una actualización de los entornos de ejecución de PHP soluciona completamente esta vulnerabilidad. Si no puede actualizar de inmediato, como medida temporal, deshabilite `session.upload_progress.enabled` administrativamente si no se necesita la característica y limite la cantidad de datos no confiables almacenados en las sesiones. Deshabilitar el progreso de carga elimina esa ruta de entrada, pero no soluciona las aplicaciones que almacenan de forma independiente datos de sesión controlados por atacantes. Un backend de almacenamiento de sesiones que reemplaza registros de forma atómica puede evitar este defecto de escritura de archivos. La actualización de PHP para el entorno de ejecución sigue siendo la corrección recomendada para las aplicaciones que utilizan el manejador de archivos incorporado. Consulte los Documentos de respaldo a continuación para obtener más detalles.

## Preguntas frecuentes

1. **¿Cómo puedo averiguar qué versión de PHP y configuración de sesión estoy usando?**

   Ejecute `php -v` en el host o en el contenedor. Verifique session.save\_handler y `session.upload_progress.enabled` en `phpinfo()` o `php.ini`. Para la versión de PHP que ve New Relic, verifique los detalles del host o de la aplicación en la UI de New Relic.

2. **¿Es necesario actualizar el agente PHP de New Relic?**

   No. La vulnerabilidad está en el entorno de ejecución de PHP, no en el agente. Actualice el entorno de ejecución de PHP a las versiones corregidas para remediar esta vulnerabilidad.

3. **¿Cómo puedo saber si mis sistemas han sido objetivo?**

   No se han reportado indicadores públicos de compromiso hasta el momento. Los clientes deben revisar sus logs web del 19 de noviembre de 2026 en adelante en busca de fallos inexplicables de los workers de PHP o finalizaciones por falta de memoria, así como de requests POST multiparte sin autenticar dirigidos a extremos de PHP. También busque archivos PHP nuevos o modificados en los directorios web.

4. **Tengo preguntas o inquietudes sobre esta vulnerabilidad. ¿A quién debo contactar?**

   Si tiene alguna pregunta sobre esta vulnerabilidad en relación con los servicios de New Relic, abra un [caso de soporte](/docs/new-relic-solutions/solve-common-issues/find-help-get-support/#file-ticket) a través del soporte en la aplicación o comuníquese con el representante de cuenta de New Relic.
