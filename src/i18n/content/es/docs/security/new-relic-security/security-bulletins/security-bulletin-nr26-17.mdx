<DNT>**Priority:**</DNT> Crítico

## Resumen

El 19 de noviembre de 2026, el Equipo de respuesta a incidentes de seguridad de New Relic comenzó una evaluación exhaustiva de nuestros servicios e infraestructura empresarial frente a la vulnerabilidad de Ruby divulgada recientemente &quot;Ruby2Shell&quot; (CVE-2026-132825). Se trata de un desbordamiento de búfer basado en el montón de un byte en la conversión de mayúsculas y minúsculas de strings del intérprete de Ruby que podría permitir la ejecución remota de código (RCE) o la denegación de servicio (DoS).

## Elementos de acción

### No se requiere ninguna acción para los clientes que usan agentes de Ruby

Los agentes de Ruby distribuidos de New Relic no se ven afectados. Los clientes de New Relic que usan los agentes de Ruby no necesitan tomar ninguna medida para esta vulnerabilidad.

## Preguntas frecuentes

1. **¿Esto afecta al agente de New Relic?**

   Los agentes de lenguaje de Ruby de New Relic no se ven afectados. Otros agentes de lenguaje de New Relic tampoco se ven afectados. Las imágenes de Fluentd no se usan en los agentes de New Relic.

2. **¿Qué sistemas se ven afectados?**

   Cualquier entorno de ejecución de contenedor (Kubernetes, Docker, etc.) que ejecute las siguientes imágenes:

   * `newrelic/newrelic-fluentd-docker`
   * `newrelic/fluentd`
   * `newrelic/k8s-golang-apm-linkage-demo`

3. **¿Cómo soluciono la vulnerabilidad?**

   Si usa la imagen `newrelic/newrelic-fluentd-docker`:

   1. Extraiga la imagen corregida:

      ```shell
      docker pull newrelic/newrelic-fluentd-docker:1.20.1
      ```

   2. Vuelva a crear los contenedores con la nueva imagen. Extraer una imagen no actualiza los contenedores que ya están en ejecución. En Kubernetes, Docker u otro entorno de ejecución de contenedor, cambie la etiqueta de la imagen a 1.20.1 y vuelva a implementar.

   3. Si compila imágenes propias a partir de `newrelic/newrelic-fluentd-docker`, vuelva a compilarlas con `docker build --pull`.

   4. Revise la versión en ejecución:

      ```shell
      docker exec <container> fluentd --version
      ```

   5. La salida debería mostrar `fluentd 1.20.1` o una versión más reciente.

   Si no usa la imagen `newrelic/newrelic-fluentd-docker`, considere usar [Fluentd](https://www.fluentd.org/) con el [plug-in de Fluentd](/docs/logs/forward-logs/fluentd-plugin-log-forwarding/) de New Relic.

4. **¿Se actualiza el contenedor cuando extraigo una imagen nueva?**

   No. Los contenedores en ejecución mantienen la imagen antigua hasta que los vuelva a crear.

5. **¿Se ve afectado el reenvío de logs del agente de infraestructura?**

   No. El reenvío de logs en el agente de infraestructura y la integración de Kubernetes usa [Fluent Bit](/docs/logs/forward-logs/fluent-bit-plugin-log-forwarding/), no Fluentd.

6. **¿Qué ocurre si tengo preguntas?**

   Para cualquier necesidad de soporte técnico relacionada con esta comunicación, abra un caso de soporte a través del soporte integrado en la aplicación.
