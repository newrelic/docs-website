<DNT>**Vulnerability Identifier:**</DNT> NR26-12

<DNT>**Priority:**</DNT> Alto

## Resumen

Entre el 17 de octubre y el 20 de octubre de 2026, los investigadores revelaron que las claves privadas de ocho certificados de autoridad de certificación (CA) intermedia emitidos por eMudhra se podían recuperar. Cualquiera con esas claves podría crear certificados que el software aceptaría como genuinos si aún confía en ellos. Aunque los principales sistemas operativos y navegadores web ya han revocado la confianza en estos certificados, las aplicaciones que administran almacenes de confianza de CA independientes, incluidas algunas imágenes de contenedor, deben actualizarse.

New Relic ha reconstruido las imágenes de contenedor que proporciona para las ubicaciones privadas de Sintéticos para que ya no utilicen estos certificados. Los clientes que ejecutan ubicaciones privadas de Sintéticos deben extraer las nuevas imágenes y reiniciar sus contenedores, ya que las imágenes no se actualizan automáticamente.

Para identificar los monitores que aún se ejecutan en el entorno de ejecución legacy, ejecute la siguiente consulta NRQL en el generador de consultas de su cuenta:

```sql
SELECT uniques(monitorName) FROM SyntheticCheck WHERE runtimeType = 'NODE_API' AND runtimeTypeVersion = '16.10' SINCE 1 day ago
```

También puede identificar los monitores afectados en la [pantalla de fin de vida útil de Sintéticos](https://onenr.io/0gR77nzxaRo) en la UI de New Relic. Filtre por **Monitor Type: Script API** para ver todos los monitores que aún se ejecutan en Node.js 16.10.

### Aviso importante: se requiere la migración a Node.js 16.x (ubicaciones públicas y privadas) [#node-16-migration]

Los monitores de API programados que se ejecutan en Node.js 16.10 llegarán al [fin de su vida útil](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/) el 18 de noviembre de 2026. Estos monitores están expuestos a las vulnerabilidades de eMudhra, y los monitores que aún se ejecutan en estas versiones anteriores deben migrarse a Node.js 22.23.0. Esto se aplica independientemente de si los monitores se ejecutan en ubicaciones públicas o en una ubicación privada.

**Acción recomendada:** a partir del 18 de noviembre de 2026, New Relic actualizará automáticamente los monitores de ubicación pública que sigan ejecutándose en Node.js 16.x al entorno de ejecución actual. Le recomendamos encarecidamente que migre lo antes posible, antes de esa fecha, para que pueda comprobar que los monitores siguen funcionando según lo previsto en el nuevo entorno de ejecución y abandonar la versión vulnerable. Para obtener instrucciones, consulte [Actualizar los monitores de API programados a Node.js 22](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/).

## Preguntas frecuentes

1. **¿Se vio afectada la infraestructura de ubicación pública de New Relic?**

   New Relic ha parcheado la infraestructura de ubicación pública que se ejecuta en el entorno de ejecución más reciente. Sin embargo, los monitores fijados explícitamente a Node.js 16.x continuarán ejecutándose en esa versión hasta que el propietario de la cuenta los actualice.

2. **¿Se alteró algún resultado del monitor?**

   New Relic no tiene evidencia de manipulación en nuestras imágenes de Sintético.

3. **¿Necesito rotar las credenciales almacenadas en las credenciales seguras de Sintéticos?**

   No es necesario realizar ninguna acción, a menos que tenga un motivo específico para creer que la red y la infraestructura se vieron comprometidas.

4. **¿Con quién puedo comunicarme si aún tengo preguntas?**

   Abra un caso con nuestro equipo de Soporte a través de la sección de ayuda en la plataforma de New Relic.
