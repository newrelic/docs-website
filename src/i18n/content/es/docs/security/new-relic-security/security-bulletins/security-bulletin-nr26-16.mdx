<DNT>**Vulnerability Identifier:**</DNT> NR26-16

<DNT>**Priority:**</DNT> Crítico

## Resumen

Se ha revelado una vulnerabilidad (CVE-2026-114938) crítica de corrupción de memoria en el decodificador Base64 acelerado por hardware de la máquina virtual de Java (JVM) OpenJDK HotSpot. Cuando una aplicación de Java afectada procesa una entrada codificada en Base64 especialmente diseñada (como encabezados de autorización HTTP, JWT, token SAML o cargas de archivos), un desbordamiento inferior de enteros puede desencadenar una escritura del montón fuera de los límites. La explotación exitosa puede causar bloqueos de la aplicación (denegación de servicio), exponer memoria confidencial del montón o permitir la ejecución remota de código (RCE) no autenticada.

## Elementos de acción

### No se requieren acciones

New Relic no incluye un entorno de ejecución de Java con el agente de Java de New Relic. No se requiere ninguna acción por parte de los clientes para los servicios alojados en New Relic, lo que incluye las ubicaciones públicas de Sintéticos.

Se requiere la acción de los clientes en los siguientes casos.

### Ubicaciones privadas de Sintéticos (Synthetics Job Manager y ping runtime)

El Job Manager de Sintéticos (SJM) y el entorno de ejecución de ping para la ubicación privada incluyen un entorno de ejecución de Java. Las imágenes actualizadas que contienen un entorno de ejecución de Java parcheado se publicaron el 19 de noviembre de 2026.

* Actualice el Job Manager de Sintéticos a la versión [release-659](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-659/images/sha256-11fa4a7b78d7a7d708b1f5efec790dc066ab6c02d3b3f02c7a59a8b885913828) o una posterior y el entorno de ejecución de ping a la versión [1.89.0](https://hub.docker.com/layers/newrelic/synthetics-ping-runtime/1.89.0/images/sha256-33da2eb67b404b09f19e1ea232e80be22d403e97abbeaf2b0f26bc95d2eae646) o una posterior.
* Si la configuración fija el entorno de ejecución de ping a una versión específica, actualícelo a la 1.89.0 o posterior. Si utiliza la etiqueta `latest`, reinicie el Job Manager de Sintéticos para extraer el entorno de ejecución actualizado.
* Si ejecuta alguna versión del Job Manager de Sintéticos anterior a la [release-655](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-655/images/sha256-c587a634136aeed4179ebd216d993c9aea4b50a6a88f977fc5099fb164b42c57), no hay una ruta de actualización in situ a la versión actual. Planifique una migración a la versión más reciente y valídela primero en un entorno de no producción. Para obtener instrucciones de instalación, consulte [Instalar el Job Manager de Sintéticos](/docs/synthetics/synthetic-monitoring/private-locations/install-job-manager).
* Si no puede actualizar el Job Manager de Sintéticos de inmediato, configure la opción de JVM `JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"` en el contenedor del Job Manager de Sintéticos. Solo en hosts x86-64, puede utilizar `-XX:UseAVX=2` en su lugar. Las JVM en ARM no reconocen esta opción y no se iniciarán. Esta opción no se aplica al contenedor del entorno de ejecución de ping cuyo lanzamiento realiza el Job Manager de Sintéticos, por lo que aún debe actualizar la imagen del entorno de ejecución de ping para solucionar el problema por completo.

### Las aplicaciones de Java, incluidas las supervisadas por el agente de Java de New Relic

La aplicación de Java solo se ve afectada cuando se cumplen todas las siguientes condiciones:

* La aplicación se ejecuta en una distribución de OpenJDK basada en HotSpot, versión 17.0.6 o posterior (pero anterior a la actualización de parches críticos de noviembre de 2026). Algunos ejemplos incluyen Oracle Java SE, Amazon Corretto, Eclipse Temurin, Azul Zulu, Red Hat OpenJDK y Microsoft Build of OpenJDK.
* El host tiene un procesador x86-64 compatible con AVX-512 VBMI (Intel Xeon Ice Lake o más reciente, o AMD Zen 4 o más reciente). Los procesadores ARM64, incluido AWS Graviton, no se ven afectados.
* La aplicación procesa entradas no confiables que pueden llegar al decodificador Base64 de Java.

**Solución:** actualice el entorno de ejecución de Java a la versión de seguridad del proveedor de noviembre de 2026, comenzando por los sistemas orientados a Internet. Para obtener más detalles, consulte la [Actualización crítica de parches de seguridad](https://www.oracle.com/security-alerts/cspunov2026.html) de Oracle (noviembre de 2026), el [Aviso de vulnerabilidades](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) de OpenJDK (17/11/2026) o el aviso del proveedor de JDK.

## Preguntas frecuentes

1. **¿Esto afecta al agente de New Relic?**

   El agente de Java de New Relic no incluye ni distribuye un entorno de ejecución de Java (JDK/JVM). Instrumenta las aplicaciones de Java mediante el entorno de ejecución de Java disponible en el entorno de la aplicación.

2. **¿Debo actualizar el agente de Java de New Relic?**

   No. El agente de Java de New Relic no incluye un entorno de ejecución de Java y no se requiere ninguna actualización del agente de Java para estas vulnerabilidades.

3. **¿Qué sistemas se ven afectados?**

   Solo los procesadores x86-64 que admiten AVX-512 VBMI. Los procesadores ARM64 no se ven afectados. OpenJDK y Oracle han publicado correcciones.

4. **¿Cómo sé si los entornos de ejecución de Java para la aplicación se ven afectados?**

   Compruebe la versión de Java y la CPU. Para la aplicación supervisada por New Relic APM, la versión de JVM se muestra en la página de entorno del servicio. Consulte [Obtener datos del entorno sobre la aplicación de APM](/docs/apm/agents/manage-apm-agents/troubleshooting/get-environment-data-about-your-apm-app) para obtener más detalles y asegúrese de seleccionar los hosts. Como alternativa, en un host, ejecute `java -version`.

   En Linux, compruebe la CPU con:

   ```bash
   grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(avx512f|avx512bw|avx512vbmi|bmi2)$'
   ```

   La CPU solo se ve afectada si aparecen los cuatro indicadores.

5. **¿Cómo soluciono la vulnerabilidad?**

   Actualice el entorno de ejecución de Java a la versión de seguridad del proveedor de noviembre de 2026, comenzando por los sistemas orientados a Internet. Para obtener más detalles, consulte la [Actualización crítica de parches de seguridad](https://www.oracle.com/security-alerts/cspunov2026.html) de Oracle (noviembre de 2026), el [Aviso de vulnerabilidades](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) de OpenJDK (17/11/2026) o el aviso del proveedor de JDK.

6. **¿Qué puedo hacer si no puedo aplicar el parche de inmediato?**

   Inicie la JVM con `JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"` como mitigación temporal. Solo en hosts x86-64, puede utilizar `-XX:UseAVX=2` en su lugar. Las JVM en ARM no reconocen esta opción y no se iniciarán. Ambas opciones son temporales y no reemplazan la aplicación de parches.

7. **¿Ha visto New Relic evidencia de explotación?**

   No hemos identificado indicadores de explotación de esta vulnerabilidad en nuestro entorno.

8. **¿Qué ocurre si tengo preguntas?**

   Para cualquier necesidad de soporte técnico relacionada con esta comunicación, abra un caso de soporte a través del soporte integrado en la aplicación.
