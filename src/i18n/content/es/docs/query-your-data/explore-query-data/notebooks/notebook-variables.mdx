Con las variables de notebook, puedes configurar parámetros dinámicos que se extienden en cascada a través de múltiples consultas en los bloques de consulta. A diferencia de las [variables de plantilla de dashboard](/docs/query-your-data/explore-query-data/dashboards/dashboard-template-variables), que filtran una vista estática, las variables de notebook actúan como parámetros inyectados que impulsan la lógica subyacente de todo tu documento.

Vaya a **[one.newrelic.com](https://one.newrelic.com) &gt; <DNT>All capabilities</DNT> &gt; <DNT>Notebooks</DNT>**.

## ¿Por qué usar variables en los cuadernos? [#why-use-variables]

Las variables de cuaderno te permiten crear experiencias interactivas como:

* **Runbooks parametrizados** donde un ingeniero ingresa un `hostName` o `transactionId` específico para generar al instante un informe de estado del sistema objetivo.
* **Plantillas post-mortem** que se pueden actualizar con timestamps, regiones o nombres de aplicación específicos para analizar un incidente.
* **Umbrales interactivos** donde los usuarios pueden ajustar variables como `errorThreshold` o `latencyTarget` para ver cómo los diferentes parámetros afectan los datos visualizados.

Los beneficios clave incluyen:

* **Creación de runbooks ejecutables**: las variables convierten sus notebooks de páginas estáticas en herramientas interactivas. Puede crear flujos de trabajo adaptables para investigaciones de eventos de alerta, análisis de rendimiento y colaboración en equipo.
* **Estandarización del intercambio de conocimientos**: como documento guardado, puede compartir flujos de trabajo analíticos con colegas. Los usuarios no necesitan reescribir consultas complejas de <DNT>NRQL</DNT> — simplemente cambian a un nuevo valor de variable de sus variables predefinidas y ejecutan el flujo de trabajo.

## Define una variable de notebook [#define-variable]

Defina una variable que inyectará en sus bloques de consulta de <DNT>NRQL</DNT> para parametrizar la recuperación de datos y las visualizaciones.

Para definir una variable:

1. Desde un notebook abierto, localiza la barra de variables en la parte superior de la interfaz.
2. Haga clic en <DNT>**+ Add variable**</DNT>.
3. Configure su tipo de variable (por ejemplo, entrada de texto, desplegable o numérico) y proporcione un valor predeterminado.

### Reglas de nomenclatura de variables [#naming-rules]

Al nombrar su variable, tenga en cuenta lo siguiente:

* El nombre es la cadena exacta que usará en los bloques de su notebook, rodeada por `{{...}}`. Por ejemplo, si nombra la variable `targetApp`, la referencia en sus bloques de consulta como `{{targetApp}}`.
* Los nombres de las variables distinguen entre mayúsculas y minúsculas y deben ser únicos dentro de un notebook.
* Elija nombres descriptivos que hagan que su runbook sea autoexplicativo para otros usuarios (por ejemplo, `failingHost` en lugar de `var1`).

## Usar una variable en un bloque de consulta [#use-variable]

Una vez definida, haz referencia a tu variable en cualquier lugar de una consulta <DNT>NRQL</DNT> usando la sintaxis `{{variableName}}`:

```sql
SELECT average(cpuPercent) FROM SystemSample WHERE hostname = {{failingHost}} TIMESERIES
```

```sql
SELECT latest(cpuPercent) FROM ProcessSample WHERE hostname = {{failingHost}} FACET processDisplayName
```

Cuando ejecutas la consulta, el valor de la variable que configuraste en la barra de variables se sustituye en la consulta en tiempo de ejecución. Cambiar el valor de la variable y volver a ejecutar la consulta actualiza al instante todos los bloques que hacen referencia a esa variable.

## Automatiza la respuesta a incidentes con runbooks [#runbook-use-case]

La aplicación más potente para las variables de notebook es la creación de runbooks ejecutables para la respuesta a incidentes. Al combinar las variables de notebook con [<DNT>New Relic</DNT> flujos de trabajo](/docs/alerts/get-notified/incident-workflows), puedes automatizar el traspaso entre la activación de una alerta y el inicio de la investigación.
