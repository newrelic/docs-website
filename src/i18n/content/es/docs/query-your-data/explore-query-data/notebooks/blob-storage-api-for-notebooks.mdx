La API <DNT>Notebooks</DNT> de New Relic te permite crear, leer, actualizar y eliminar cuadernos de forma programática, incluido el contenido completo de sus bloques (<DNT>NRQL</DNT> consultas, texto). Los cuadernos se almacenan como blobs versionados, lo que significa que cada guardado produce una nueva revisión inmutable que puedes recuperar más tarde.

Utilice esta API para:

* Automatizar la creación de notebooks a partir de plantillas de incidentes, runbooks o pipelines de CI/CD
* Sincronizar el contenido del notebook desde el control de versiones o herramientas de creación externas
* Cree integraciones que completen los notebooks de forma programática durante las investigaciones

<Callout variant="important">
  **<DNT>Notebooks</DNT> usar múltiples API**

  La superficie de la API de <DNT>Notebooks</DNT> se divide entre dos sistemas:

  * **<DNT>Blob Storage API</DNT>** maneja el contenido del cuaderno (bloques, historial de versiones)
  * **<DNT>NerdGraph</DNT>** maneja operaciones a nivel de entidad (lista, cambio de nombre, etiquetas, metadatos de organización)

  Esta separación es por diseño. El <DNT>Blob Storage API</DNT> está optimizado para la transferencia de contenido de archivos y el control de versiones; <DNT>NerdGraph</DNT> está optimizado para consultas y mutaciones de entidades estructuradas.
</Callout>

## Requisitos previos [#prerequisites]

* Una [cuenta de<DNT>New Relic</DNT> ](https://newrelic.com/signup)con una clave de API de usuario
* Tu ID de organización de <DNT>New Relic</DNT>
* Los [permisos](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions/) adecuados para administrar notebooks

## Autenticación [#authentication]

Todas las solicitudes a la API de <DNT>Notebooks</DNT> requieren autenticación mediante una clave de API de usuario de <DNT>New Relic</DNT>.

**Generar una clave de API:**

1. Vaya a [one.newrelic.com](https://one.newrelic.com)
2. Haga clic en su nombre en la esquina superior derecha
3. Seleccionar <DNT>**API Keys**</DNT>
4. Crea una clave de <DNT>**User**</DNT> (no una clave de Browser o clave de licencia)

**Incluir en los encabezados de la solicitud:**

```shell
Api-Key: NRAK-YOUR-USER-API-KEY
```

<Callout variant="tip">
  El <DNT>Blob Storage API</DNT> también admite el contexto de inicio de sesión, por lo que al llamar a la API desde una UI autenticada como usuario de <DNT>New Relic</DNT>, no se requiere el encabezado `Api-Key`.
</Callout>

## Endpoint base [#base-endpoint]

```plaintext
https://blob-api.service.newrelic.com/v1/e
```

Para las cuentas de la región de la UE, use:

```plaintext
https://blob-api.service.eu.newrelic.com/v1/e
```

  <Collapser id="retrieve-versions" title="Recuperar versiones anteriores">
    <DNT>Notebook</DNT> las versiones se retienen durante **1 día**. Para recuperar una revisión anterior, primero liste las versiones recientes a través de <DNT>NRQL</DNT>, luego recupere el blob específico.

    ### Paso 1 — listar las últimas 5 versiones [#retrieve-list-versions]

    Ejecute esta consulta <DNT>NRQL</DNT> en el generador de consultas para recopilar los ID de blob y los timestamp de los últimos 5 cambios:

    ```sql
    FROM Entity
    SELECT uniques(tuple(updatedAt, content.id))
    WHERE id = '<entity guid>'
    SINCE 1 day ago
    LIMIT 5
    ```

    ### Paso 2 — recuperar una versión específica [#retrieve-specific-version]

    Usa el `content.id` del resultado de <DNT>NRQL</DNT> para obtener el contenido de esa versión:

    ```bash
    curl -X GET \
      https://blob-api.service.newrelic.com/v1/blobs/<content.id> \
      -H 'Api-Key: NRAK-YOUR-API-KEY'
    ```
  </Collapser>

## Operaciones de entidad (NerdGraph) [#entity-operations]

Las operaciones a nivel de entidad, como listar, renombrar y asignar etiquetas, usan <DNT>NerdGraph</DNT> en lugar de <DNT>Blob Storage API</DNT>.

### Listar todos los notebooks [#list-notebooks]

```graphql
query listAllNotebooks {
  actor {
    entityManagement {
      entitySearch(query: "type='NOTEBOOK'") {
        entities {
          id
          name
        }
      }
    }
  }
}
```

<Callout variant="tip">
  La creación de la entidad es completamente transaccional, por lo que un notebook está disponible de inmediato a través de la API. Sin embargo, si enumera los notebooks a través de la consulta legacy `actor.entitySearch`, puede haber un breve retraso de propagación entre la creación y la aparición del notebook en los resultados de la lista.
</Callout>

### Renombrar un notebook [#rename-notebook]

```graphql
mutation changeNotebookName {
  entityManagementUpdateNotebook(
    id: "<entity guid>"
    notebookEntity: { name: "<new name>" }
  ) {
    entity {
      name
    }
  }
}
```

### Actualizar las etiquetas del notebook [#update-tags]

<Callout variant="important">
  Las actualizaciones de etiquetas son una operación de **reemplazo**. Debes incluir el conjunto completo de etiquetas, incluso las que no cambian — cualquier etiqueta omitida de la mutación será eliminada.
</Callout>

```graphql
mutation updateNotebookTags {
  entityManagementUpdateNotebook(
    id: "<entity guid>"
    notebookEntity: {
      tags: [
        { key: "<key>", values: "<value>" }
        { key: "<key>", values: "<value>" }
      ]
    }
  ) {
    entity {
      name
      tags {
        key
        values
      }
    }
  }
}
```

## Mejores practicas [#best-practices]

* **Almacena los GUID de la entidad:** guarda el `entityGuid` devuelto por las operaciones de creación. Lo necesitarás para leer, actualizar y eliminar cuadernos.
* **Validar JSON antes de cargarlo:** asegúrese de que la carga de su notebook sea un JSON válido y cumpla con el esquema `version` antes de enviarlo.
* **Use nombres descriptivos:** los nombres de los notebooks deben ser únicos dentro de una organización, así que elija nombres que indiquen claramente su propósito (por ejemplo, `prod-checkout-investigation` en lugar de `notebook-1`).
* **Incluye todas las etiquetas en la actualización:** las actualizaciones de etiquetas reemplazan el conjunto completo de etiquetas. Lee siempre las etiquetas existentes antes de mutar.
* **Recuperación rápida:** el historial de versiones se conserva durante solo 1 día. Si necesita un historial a largo plazo, archive el contenido del notebook en su propio almacenamiento en cada actualización.
* **Proteja su clave de API:** Nunca exponga su clave de API de usuario en el código del lado del cliente ni en repositorios públicos.
* **Verifique los códigos de estado HTTP:** La API devuelve 2xx para operaciones exitosas, 404 para no encontrado y otros códigos de estado para errores.
