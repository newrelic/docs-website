New Relic Android <InlinePopover type="mobile" />agente soporte rastreo distribuido. Esto le permite ver cómo la actividad de su aplicación móvil se conecta con los servicios relacionados.

## Requisitos [#requirements]

Para utilizar rastreo distribuido, necesitas al menos la versión 6.0.0 del agente Android. Le recomendamos utilizar el agente más reciente.

## Cómo configurar rastreo distribuido [#setup]

El rastreo distribuido está habilitado de forma predeterminada —no necesita hacer nada para activarlo. Los encabezados de rastreo distribuido se envían en cada request autoinstrumentada independientemente de otras configuraciones.

Si prefiere desactivarlo, consulte [Deshabilitar el rastreo distribuido](#disable) a continuación.

Para ver la traza correlacionada con la actividad de red de la aplicación en New Relic (el evento `MobileRequest` o `MobileRequestError` reportado), necesita tener [AnalyticsEvents](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#android-analytics-settings) habilitado —esto está activado de forma predeterminada y es un requisito previo para enviar cualquiera de los eventos de analítica de la aplicación, no algo específico del rastreo distribuido.

## Encabezados de rastreo distribuido [#headers]

A partir de la versión 7.8.3 del agente de Android, el agente solo agrega los encabezados de [W3C Trace Context](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers), `traceparent` y `tracestate`, a las requests de red salientes. Ya no envía el encabezado propietario `newrelic`. Las versiones anteriores del agente envían los tres encabezados.

Los agentes de New Relic APM que admiten W3C Trace Context usan estos encabezados para continuar la traza, de modo que los requests de la aplicación se mantengan conectados a los servicios backend a los que llaman. W3C Trace Context es compatible con estas versiones del agente APM y superiores:

Si un servicio, proxy o gateway entre la aplicación y el backend requiere el encabezado `newrelic`, actualícelo para que acepte `traceparent` y `tracestate` en su lugar. ## Qué requests obtienen rastreo distribuido automáticamente [#automatic-instrumentation]

El código de bytes de la aplicación es instrumentado en el momento de la compilación por el plug-in de Gradle del agente de Android, por lo que los encabezados del rastreo distribuido se agregan automáticamente a los requests realizados a través de:

* `OkHttp` (versiones 2 y 3)
* Apache `HttpClient`
* `HttpURLConnection`
* Retrofit

Debido a que esta instrumentación entrelaza los sitios de llamada de esas bibliotecas directamente, el código que las envuelve —incluidas las corrutinas de Kotlin y las funciones de suspensión— también debería estar cubierto, ya que los sitios de llamada subyacentes se entrelazan independientemente de qué los llame.

El agente no agrega automáticamente encabezados de rastreo distribuido a:

* Volley. El agente no es compatible con Volley en absoluto, por lo que los requests de Volley necesitan una [propagación manual](#manual) si desea obtener su traza.
* `WebView`. La instrumentación `WebView` del agente cubre el tiempo de carga de la página, no los encabezados de requests de red, por lo que las requests realizadas desde contenido web cargado en un `WebView` no se trazan automáticamente.
* Cualquier otra biblioteca de red de terceros o transporte personalizado que no se enrute a través de las bibliotecas mencionadas anteriormente.

Para cualquiera de estos, use la propagación manual.

## Deshabilitar el rastreo distribuido [#disable]

```java
NewRelic.disableFeature(FeatureFlag.DistributedTracing)
```

## Habilitar seguimiento infinito [#infinite-tracing]

Si sus aplicaciones móviles tienen algunos servicios posteriores que utilizan nuestro rastreo distribuido tail-based llamado [Infinite Tracing](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing), debe habilitar esta característica para sus aplicaciones móviles. Esto garantiza que su tramo raíz (la aplicación móvil de inicio) esté incluido en el resto de los tramos rastreados por Infinite Tracing.

Para configurar esto, consulte los [pasos de Infinite Tracing](/docs/distributed-tracing/infinite-tracing/set-trace-observer) para crear un observador de traza y seleccionar qué aplicaciones móviles (fuentes de datos) deben informar intervalos.

## Encontrar datos [#find-data]

Los tramos móviles aparecen en cualquier [UI de rastreo distribuida de New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) donde esos tramos son parte de una traza.

A continuación se ofrecen algunos consejos para buscar y consultar datos:

* Puede encontrar la traza originada por el usuario final en cualquier [UI del rastreo distribuido de New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one).

* En la UI del rastreo distribuido, los intervalos finales del usuario se indican con el<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}} />icono.

* Para ver el atributo de un intervalo, seleccione [un intervalo en la UI](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details).

* Los tramos se informan como [datos de tramos](/attribute-dictionary/?event=Span) y se pueden [consultar en New Relic](/docs/using-new-relic/data/understand-data/query-new-relic-data).

* Consejos de consulta:

  * Consulta por nombre configurando `mobileApp.name` en el nombre de la aplicación móvil.
  * Consulta para traza que contiene al menos una aplicación móvil con `mobileApp.name is not null`.
  * Consulta de traza que contiene al menos una aplicación backend con `appName is not null`.
  * Consulta para traza que contiene tramos móviles y backend combinando las dos condiciones anteriores.

Por ejemplo, para encontrar spans móviles para una aplicación específica:

```sql
SELECT count(*) FROM Span WHERE mobileApp.name = 'YOUR_APP_NAME' SINCE 1 day ago
```

Para encontrar trazas que conecten un span móvil con un span de APM del backend:

```sql
SELECT * FROM Span WHERE mobileApp.name IS NOT NULL AND appName IS NOT NULL SINCE 1 day ago
```

## Resolución de problemas [#troubleshooting]

Si no ve spans móviles donde los espera, revise estas posibles causas:

* **El rastreo distribuido está deshabilitado.** Confirme que no ha llamado a `disableFeature` con `FeatureFlag.DistributedTracing`. Consulte [Cómo configurar el rastreo distribuido](#setup).
* **AnalyticsEvents está deshabilitado.** Los encabezados aún se envían, pero el evento `MobileRequest`/`MobileRequestError` relacionado no se enviará. Consulte [Cómo configurar el rastreo distribuido](#setup).
* **La request no está autoinstrumentada.** Las requests realizadas a través de Volley, un `WebView` o cualquier biblioteca que no sea `OkHttp`, Apache `HttpClient`, `HttpURLConnection` o Retrofit necesitan [propagación manual](#manual). Consulte [Qué requests obtienen rastreo distribuido automáticamente](#automatic-instrumentation).
* **El agente APM del backend es demasiado antiguo.** Si el agente APM del servicio receptor aún no es compatible con W3C Trace Context, inicia una nueva traza en lugar de vincularla a la de la aplicación. Consulte las [versiones mínimas del agente APM](#headers).
* **Un proxy o gateway elimina los encabezados.** Cualquier elemento que se encuentre entre la aplicación y el backend debe dejar pasar `traceparent` y `tracestate` sin modificaciones.
* **Se descarta `tracestate` porque la clave de la cuenta de confianza no coincide.** Si un servicio backend pertenece a una cuenta de New Relic diferente a la de la aplicación móvil, confirme que la cuenta esté en la misma relación de confianza, o la entrada `tracestate` podría ignorarse.

Para problemas más generales de rastreo distribuido, consulte [Resolución de problemas](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data).
