Utilice esta página para solucionar problemas de carga de mapas de origen de React Native y de simbolización de `MobileJSError`. Para saber cómo cargar mapas de origen, consulte [Informes de errores de JavaScript de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting).

## Resolución de problemas [#troubleshooting]

### Errores de source map en la UI [#sourcescontent]

Si ve alguno de los siguientes errores en la UI, al archivo de mapa de origen le falta el atributo `sourcesContent` o los metadatos enviados con la carga (`sourcemapName`, `jsBundleId` o `appVersion`) no coinciden con los valores que la aplicación informa para esa compilación:

* `Source map not found.`
* `Source map missing.`
* `Incorrect map detected.`
* `Incorrect and missing maps detected.`

Primero, confirme que `sourcemapName`, `jsBundleId` y `appVersion` utilizados para la carga coincidan con los valores que la aplicación reporta para esa compilación (consulte [¿Por qué no coinciden mis números de línea?](#faq-line-numbers)). Si los metadatos coinciden, el mapa de origen debe incluir el atributo `sourcesContent` para que New Relic desminifique el rastreo del stack. Regenere el mapa de origen para que incluya este atributo y luego vuelva a cargarlo. La mayoría de los empaquetadores incluyen el contenido de origen original cuando habilita una opción como `includeSources` (o el equivalente para la herramienta de compilación).

### Tiene una aplicación de React Native pero no ve el elemento del menú [#no-menu-item]

Si tiene una aplicación de React Native pero no ve el elemento de menú de React Native en la UI, verifique que tiene una versión actualizada del agente y que la aplicación está enviando datos. El elemento de menú no aparece hasta que la aplicación envía datos con la etiqueta de la plataforma React Native.

### No ve tanto MobileJSError como los eventos de excepción controlada [#mobilejserror-events]

Con la nueva versión del agente, no verá tanto los eventos `MobileJSError` como los eventos de excepciones controladas para los mismos errores de JavaScript. En su lugar, los errores de JavaScript se registran como eventos `MobileJSError`.

New Relic actualmente admite `MobileJSError` solo para React Native. No se admiten Capacitor ni Cordova.

## Preguntas frecuentes [#faq]

<CollapserGroup>
  <Collapser id="faq-zip" title="¿Acepta New Relic archivos comprimidos?">
    Sí. Puede cargar un mapa de origen comprimido en gzip o zip (`.zip`). Los scripts de compilación comprimen automáticamente en zip los archivos `.map` grandes antes de la carga.
  </Collapser>

  <Collapser id="faq-size" title="¿Cuál es el tamaño máximo de la carga de subida?">
    200 MB sin comprimir. New Relic no almacena mapas de origen de más de 200 MB sin comprimir para la simbolización. En su lugar, envía telemetría de compilación. Para obtener más detalles, consulte [Limitaciones de tamaño de archivo](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting#file-size-limitations).
  </Collapser>

  <Collapser id="faq-code-snippets" title="¿Por qué no veo fragmentos de código en mi rastreo del stack?">
    Los fragmentos de código requieren el atributo `sourcesContent` en el mapa de origen. Si el mapa de origen no incluye el contenido de origen original, New Relic aún puede desminificar el rastreo del stack usando el mapeo de líneas y columnas, pero no puede mostrar el código fuente circundante. Vuelva a generar el mapa de origen con una opción como `includeSources` habilitada (o el equivalente para la herramienta de compilación) y, luego, cárguelo nuevamente.
  </Collapser>

  <Collapser id="faq-line-numbers" title="¿Por qué no coinciden mis números de línea?">
    Los números de línea no coinciden cuando el mapa de origen cargado no corresponde exactamente al paquete de JavaScript que produjo el error. Asegúrese de que `jsBundleId` y `appVersion` utilizados para la carga coincidan con los valores que la aplicación reporta para esa compilación —esto es especialmente importante después de una actualización de CodePush u otra actualización inalámbrica (OTA), cuando el paquete de JavaScript difiere de la versión binaria nativa. También confirme que el mapa de origen sea la versión 3.
  </Collapser>

  <Collapser id="faq-not-symbolicated" title="¿Por qué mis archivos no están simbolizados?">
    Las causas comunes incluyen:

    * Al mapa de origen le falta el atributo `sourcesContent` (consulte [Errores de mapa de origen en la UI](#sourcescontent)).
    * El `jsBundleId` o el `appVersion` no coinciden entre la carga y la aplicación en ejecución (consulte [¿Por qué no coinciden mis números de línea?](#faq-line-numbers)).
    * El mapa de origen superó el [límite de 200 MB](#faq-size), por lo que New Relic solo envió telemetría de compilación.
    * Los datos aún no han terminado de sincronizarse. Después de una carga, puede tomar unos minutos para que los datos estén disponibles.
    * La clave de API del mapa de origen y el token de la aplicación pertenecen a cuentas de New Relic diferentes.
  </Collapser>

  <Collapser id="faq-list" title="¿Cómo puedo ver lo que subí a New Relic?">
    Use el comando de lista en NerdGraph o NRQL. Consulte [Enumerar y eliminar mapas de origen de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/list-delete-react-native-source-maps).
  </Collapser>

  <Collapser id="faq-multi-bundle" title="¿Puedo cargar varios mapas de origen para una aplicación multipaquete?">
    No. La simbolización de React Native de New Relic admite solo un único archivo source map, lo que coincide con el simbolizador predeterminado (no multibundle) de Metro. Si su aplicación divide su JavaScript en múltiples paquetes y genera múltiples source maps, New Relic no admite la simbolización para esa configuración.

    Si esto le afecta, [comuníquese con el soporte de New Relic o envíe una solicitud de característica](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting#request-support) para solicitar compatibilidad con múltiples paquetes.
  </Collapser>
</CollapserGroup>
