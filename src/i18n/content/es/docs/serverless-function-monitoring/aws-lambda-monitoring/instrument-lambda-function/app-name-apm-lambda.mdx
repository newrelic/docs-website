`NEW_RELIC_APP_NAME` es una variable de entorno Lambda que controla a qué entidad APM se le asigna como atributo la telemetría de su función en New Relic. Cuando se configura, la telemetría de su función Lambda aparece bajo una entidad APM con nombre de su elección en lugar de usar de forma predeterminada el nombre de la función Lambda.

## Cómo funciona

Cuando `NEW_RELIC_APM_LAMBDA_MODE` es `true`, New Relic Lambda Extension realiza una llamada de APM `connect` en cada inicio en frío. Utiliza `NEW_RELIC_APP_NAME` (o recurre a `AWS_LAMBDA_FUNCTION_NAME` si no está configurado) como `app_name` en esa llamada. El recolector de APM resuelve o crea una entidad para ese nombre y devuelve su GUID. Toda la telemetría producida durante esa invocación se etiqueta con ese GUID y aparece bajo la entidad nombrada en New Relic.

## Configuración

Establezca `NEW_RELIC_APP_NAME` como una variable de entorno Lambda. No se requieren cambios en el código —la extensión lo maneja automáticamente en el inicio en frío.

```
NEW_RELIC_APP_NAME = my-entity-name
```

## Comportamiento de la entidad

Las funciones que comparten el mismo valor `NEW_RELIC_APP_NAME` y cuenta de New Relic se agrupan bajo una sola entidad de APM en la UI de New Relic.

Si el nombre que define coincide con una entidad de APM existente —por ejemplo, una ya creada por un servicio que no es de Lambda—, la telemetría de su función Lambda se fusiona con esa entidad automáticamente. No se crea ninguna entidad separada.

<Callout variant="important">
  Cambiar `NEW_RELIC_APP_NAME` crea una nueva entidad de APM. Los datos históricos asociados al nombre anterior no se migran a la nueva entidad.
</Callout>

## Reportes multirregión

Múltiples funciones Lambda desplegadas en diferentes regiones de AWS pueden compartir el mismo `NEW_RELIC_APP_NAME`. Todas estas funciones reportan a una sola entidad de APM, independientemente de la región en la que estén desplegadas.

Para distinguir funciones individuales o despliegues específicos de la región dentro de la entidad agrupada, filtre por el atributo `tags.aws.arn` en NRQL o use la barra de filtro de etiquetas en la vista de la entidad.

## Reportes entre entornos de ejecución

Las funciones Lambda que utilizan diferentes tiempos de ejecución (por ejemplo, una función de Python y una función de Node.js) que comparten el mismo `NEW_RELIC_APP_NAME` crean entidades de APM separadas —una por tiempo de ejecución. La agrupación no cruza los límites del tiempo de ejecución.

## Mismo nombre de aplicación en servicios Lambda y no Lambda

Si una función Lambda y un servicio de APM no Lambda (por ejemplo, una aplicación web tradicional o un microservicio) están configurados con el mismo `NEW_RELIC_APP_NAME`, reportan a la **misma** entidad de APM.

Esto puede ser intencional: si desea una vista unificada de un servicio que se ejecuta tanto en Lambda como en infraestructura basada en servidores, compartir el nombre permite que toda la telemetría —transacciones, errores, rendimiento— aparezca en un solo lugar.

Sin embargo, si se hace involuntariamente, puede causar confusión. Las métricas, las tasas de errores y el rendimiento de la función Lambda y del servicio no Lambda se combinan, lo que puede dificultar el diagnóstico de problemas o la comprensión del rendimiento de forma independiente.

## Ciclo de vida de la entidad y expiración de etiquetas

Cuando una función Lambda deja de reportar, su entidad de APM no se elimina de inmediato. Las etiquetas de la entidad (incluido `aws.arn`) expiran después de aproximadamente 1–2 días sin telemetría entrante. La entidad en sí puede persistir más tiempo dependiendo de la configuración de retención de la cuenta.

## Solucionar problemas

**La telemetría aún aparece bajo el nombre de la función después de la configuración `NEW_RELIC_APP_NAME`**

* Confirme que la variable esté configurada a nivel del entorno de Lambda, no solo en el código de la aplicación.
* Revise los logs de CloudWatch para ver las entradas de conexión de APM de `[NR_EXT]` —el campo `app_name` debe reflejar el valor personalizado.
* Asegúrese de que la versión de New Relic Lambda Extension en la capa admita esta característica.

**Existen dos entidades separadas para la misma función**

Esto es lo esperado cuando `NEW_RELIC_APP_NAME` se agrega o cambia después de que la función ya estaba reportando. La entidad antigua conserva sus datos históricos; toda la telemetría nueva va a la nueva entidad.

**Dos funciones Lambda con el mismo nombre de aplicación se muestran como entidades separadas**

Este es el comportamiento esperado cuando los tiempos de ejecución difieren (por ejemplo, Python frente a Node.js). Las funciones que comparten el mismo tiempo de ejecución y el mismo `NEW_RELIC_APP_NAME` reportarán en una sola entidad.
