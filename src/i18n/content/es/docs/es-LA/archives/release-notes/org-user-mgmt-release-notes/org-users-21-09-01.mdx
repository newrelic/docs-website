Nuestra API del Sistema de gestión de identidades entre dominios (SCIM) ahora admite la gestión del [tipo de usuario](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type) de los usuarios. Esto permite a los clientes Enterprise con usuarios en nuestro modelo de usuario más reciente gestionar el tipo de usuario a través de su proveedor de identidad (IdP) o cualquier integración personalizada que admita SCIM. Esto es particularmente útil para aprovisionar usuarios como básicos o completos (en lugar de aprovisionar siempre a los usuarios como completos), junto con la actualización y degradación automáticas dentro de la [política de facturación](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#user-count) de New Relic de dos degradaciones por usuario por cada doce meses consecutivos.

La versión incluye [un tutorial de SCIM](/docs/accounts/accounts/automated-user-management/tutorial-manage-users-groups-scim) y la capacidad para que los administradores agreguen un mensaje personalizado y/o una URL a la página de actualización automática que comunique el proceso de solicitud de actualización específico del cliente para los clientes que administran el tipo de usuario a través de la API.

Tenemos instrucciones para habilitar esto con nuestra [integración de Okta](/docs/accounts/accounts/automated-user-management/okta-scimsso-application-configuration/) prediseñada. Actualmente no tenemos instrucciones paso a paso para nuestras integraciones de OneLogin o Azure AD. Si utiliza uno de estos, deberá configurar su proveedor de identidad para enviar un nuevo atributo, [`nrUserType`](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type).

* Nuestras [instrucciones de la API de SCIM sobre el tipo de usuario](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type).
