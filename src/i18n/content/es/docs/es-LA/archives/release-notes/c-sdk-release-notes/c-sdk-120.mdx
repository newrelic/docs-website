### Nueva característica

***Más flexibilidad para los despliegues de contenedores***

* El daemon y la aplicación instrumentada ya no tienen que residir en el mismo host y ahora pueden comunicarse a través de un socket TCP IPv4 o IPv6. Para la aplicación instrumentada, esto se puede configurar a través del argumento `daemon_socket` de la función `newrelic_init`. Para el daemon, esto se puede configurar a través de la opción de línea de comando `--address`.
* Al terminar el daemon mediante la señal `SIGTERM` (y/o la señal `SIGINT` si se inició con el indicador `-f`, `--foreground`), el daemon ahora enviará todos los datos almacenados en búfer a New Relic antes de salir.
* El daemon ha introducido una nueva configuración `--watchdog-foreground`. Esto mantiene el proceso watchdog del daemon en primer plano, mientras que la configuración `--foreground` mantiene el proceso worker del daemon en primer plano. La nueva configuración hace posible usar el daemon de forma bloqueante, sin perder la estabilidad adicional proporcionada por el proceso watchdog.
* El SDK de C ahora ofrece `newrelic_set_transaction_name` con lo que los usuarios pueden cambiar el nombre de una transacción ya iniciada.

### Corrección de errores

* El daemon ahora maneja de forma sincrónica las rutas de código críticas relacionadas con la recolección y fusión de datos de transacción. Esto evita bloqueos causados por condiciones de carrera.

### Avisos de actualización

* El daemon ha introducido una nueva configuración `--address` que sirve como alias para `--port`. Los clientes pueden usar cualquiera de los dos para especificar la ubicación del daemon. Si se establecen ambos valores, `--address` tiene prioridad.

* Al iniciar el daemon, ahora esperará hasta tres segundos para que el puerto de escucha esté listo para recibir conexiones antes de bifurcarse en segundo plano. Esto generalmente ocurre en (mucho) menos de un segundo, y la mayoría de los usuarios con esta configuración no notarán ninguna diferencia en la práctica.

  El tiempo que esperará el daemon se puede controlar estableciendo la configuración `--wait-for-port` con una duración. Esta duración puede ser 0 para evitar cualquier bloqueo. Si se omite la opción, el valor predeterminado es `3s`.

  Los daemon iniciados en modo de primer plano (con el indicador `--foreground`) no se ven afectados y se comportarán como antes.
