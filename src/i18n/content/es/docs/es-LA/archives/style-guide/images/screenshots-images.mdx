Las imágenes son una parte fundamental de nuestra documentación. Muestran al usuario lo que obtendrá al seguir un procedimiento. Pueden ayudar a orientar al usuario a través de una ruta de UI complicada, ilustrar conceptos complejos como [anulaciones de archivos de configuración](/docs/agents/python-agent/installation-configuration/python-agent-configuration#options) o, a veces, simplemente agregar interés visual.

Este documento describe las mejores prácticas para crear y mantener imágenes. Si necesita ayuda para incrustarlas en nuestro sitio, consulte [Incrustar imágenes](/docs/style-guide/processes-procedures/embed-images). Si desea agregar anotaciones de imágenes, consulte [Mejores prácticas para usar anotaciones de imágenes](/docs/style-guide/images/image-annotations).

## Pautas para los tipos de imágenes [#types]

Tenemos cuatro categorías principales de imágenes en nuestro sitio.

<CollapserGroup>
  <Collapser id="screenshots" title="Capturas de pantalla">
    Las capturas de pantalla son un recurso clave para los usuarios —en las encuestas de usuarios nos dicen constantemente que les gustaría ver más capturas de pantalla, y de mayor calidad, en la documentación.

    Utilizamos dos tipos de capturas de pantalla: capturas de pantalla completas que muestran toda la UI y capturas de pantalla recortadas que muestran solo una sección. Por lo general, preferimos las capturas de pantalla completas porque ayudan al usuario a orientarse dentro de la UI. A veces, una captura de pantalla recortada puede ser mejor cuando solo intenta mostrar algo muy específico, y el marco de la UI circundante es una distracción.

## Pautas para explicar imágenes [#identify-images]

El texto de apoyo puede proporcionar contexto y explicaciones útiles, especialmente para capturas de pantalla complicadas y otras imágenes que pueden ser difíciles de entender por sí solas. Aunque siempre debe incluir texto alternativo para accesibilidad, los otros tipos de texto de apoyo son opcionales.

* Texto alternativo (obligatorio)
* Título (obligatorio)
* Leyenda
* Texto adyacente

<Callout variant="important">
  Evite el uso de texto dentro de una captura de pantalla, use [leyendas](/docs/style-guide/images/screenshots-images/#captions) en su lugar. Vea las [Mejores prácticas para usar anotaciones de imágenes](/docs/style-guide/images/image-annotations)
</Callout>

### Texto alternativo (obligatorio) [#alt-text]

Incluya siempre texto alternativo en las etiquetas de sus imágenes para que los lectores con discapacidad visual puedan usar sus lectores de pantalla para obtener información útil de las imágenes. Esto solo se aplica a las imágenes que contienen contenido o comandos (por ejemplo, botones).

<Callout variant="tip">
  El texto alternativo no se aplica a los iconos Feather en línea.
</Callout>

Al usar texto alternativo:

* Utilice descripciones de imágenes concisas.

* No repita el texto circundante — los lectores de pantalla ya lo leen.

* Busque la claridad. No se requieren oraciones completas.

* Identifique el tipo de imagen de alguna manera:

  * `alt="Diagram showing the flow of data from client to server."`
  * `alt="Screenshot showing how to select a server."`
  * `alt="Photo of garden hose that serves as a metaphor for electrical amperage."`

### Leyenda [#captions]

Las leyendas aparecen debajo de las imágenes y brindan contexto de apoyo a los lectores.

Tenga en cuenta lo siguiente:

* Mantenga las leyendas cortas y no inserte procedimientos.
* Solo inserte [rutas de navegación](/docs/style-guide/formatting/ui-paths/) en las leyendas si la navegación es una parte clave del mensaje.
* Inserte información complementaria que no sea idéntica al texto circundante.
* Cree leyendas que sean fáciles de leer por encima.
* Anime a los lectores a mirar el texto circundante.
* No ponga información requerida en leyendas que no esté disponible en otro lugar.
* Las leyendas no son necesarias en las capturas de pantalla del procedimiento porque el texto del procedimiento debería aclarar las cosas.

### Texto adyacente [#surrounding-text]

Si no utiliza subtítulos o anotaciones, asegúrese de agregar texto antes o después de la imagen para brindar un contexto útil.

Si depende del texto circundante para explicar su imagen:

* Use imágenes intuitivas.
* Mantenga el texto circundante conciso para que sea más fácil entender la imagen.

## Eliminar o cambiar el nombre de un archivo de imagen [#delete-rename-image]

Nuestros .mdx traducidos de i18n archivos deben coincidir con los .mdx en inglés correspondientes archivos. Cuando elimina o cambia el nombre de los archivos de imagen en inglés, puede causar un error de compilación porque ahora hay una discrepancia entre los archivos en inglés y los traducidos. A continuación, se ofrecen algunos consejos al eliminar o cambiar el nombre de un archivo de imagen:

* Para reemplazar una imagen: si está reemplazando una imagen existente, debe darle al archivo de imagen el mismo nombre. Elimine el archivo que desea reemplazar y agregue el archivo nuevo. Hacer esto significa que no necesitará cambiar ninguna referencia a ese archivo de imagen.
* Para eliminar una imagen: si simplemente desea eliminar una imagen sin reemplazarla, no elimine el archivo de imagen. En su lugar, simplemente elimine la declaración de importación para ese archivo de imagen. El equipo de documentación ocasionalmente ejecuta un script que elimina los archivos de imagen que no están referenciados por archivos mdx. Esto significa que no tenemos que eliminar archivos de imagen y, por lo tanto, no hay necesidad de tocar los archivos mdx en el directorio i18n, ya que se actualizarán automáticamente con nuestro flujo de trabajo de traducción.
* Para cambiar el nombre de un archivo de imagen: primero, pregúntese si es necesario hacerlo. El nombre del archivo de imagen es generalmente poco importante y trivial. Si decide cambiar el nombre de un archivo de imagen, debe ir a cualquier archivo mdx que haga referencia al archivo de imagen (incluidos los archivos del directorio i18n) y actualizar ese nombre de archivo.
