Esta es una referencia para los componentes que conforman nuestro componente de instalación ramificada.

Para comenzar con la instalación ramificada, consulte [Comenzar con la instalación ramificada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc).

Los documentos de instalación ramificados están controlados por un archivo YAML de configuración que traza las relaciones entre las diferentes opciones. El YAML describe cuándo y cómo las piezas de contenido (ubicadas en archivos .mdx ) completan el documento. A medida que los usuarios seleccionan opciones, el YAML intercambia esos fragmentos.

## Componentes [#new-components]

Para ver el componente de instalación ramificada en acción, consulte [nuestras implementaciones de instalación ramificada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#uses). Los componentes principales son:

* Cuadros de selección de opciones (a veces denominados &quot;desplegables de mosaico&quot;) donde las elecciones que hace un usuario dictan qué contenido se muestra
* Pasos numerados
* Opción de archivo de configuración integrado en el que los usuarios pueden ingresar valores
* Formulario de comentarios de instalación (`<InstallFeedback />`)

## Cómo funciona [#how]

Los documentos de instalación se encuentran en el directorio `install`. Hay un solo archivo `.yaml` que define cómo y cuándo se intercambia contenido específico dentro y fuera del documento. Las piezas específicas de contenido se representan como archivos `.mdx`.

## Descripción general del directorio [#install-directory]

El contenido del framework de instalación se encuentra en `src/install`.

Para crear un nuevo documento de instalación, agregue un directorio a `install`.

La estructura de directorios debe verse así:

```
install
|--assets (used for install images)
|--config (used for the install yaml files)
   |--agent-config (used for the agent config yml files)
|--specific-install (used for a specific install doc)
   |--sub-directory1 (used for .mdx files that will be swapped in)
   |--sub-directory2 (used for .mdx files that will be swapped in)
   |--sub-directoryx (you can have as many sub-directories as you need)
```

Cuando inicie un nuevo documento de ramificación, cree un directorio principal en el directorio `install`. Aquí es donde se encuentran todos los archivos de su documento de ramificación.

## El archivo YAML de ramificación [#yaml-overview]

El archivo YAML del documento de ramificación es una forma muy personalizable de generar una amplia variedad de contenido personalizado e interactivo. Al ser un archivo YAML, es sumamente importante prestar atención a las sangrías y asegurarse de que cada parte del archivo YAML sea correcta.

Cuando intercambia contenido MDX en su archivo YAML, el archivo MDX específico debe ser local a su directorio de documentos de instalación (por ejemplo, Java). Aunque puede ser tentador enlazar a contenido en cualquier parte del sitio de documentos con fines de reutilización, esto hará que su documento se rompa.

### Verificar el script YAML [#verify-yaml]

Dado lo fácil que es dañar cualquier archivo YAML, nuestro servicial equipo de ingeniería ha creado un script útil para comprobar los problemas comunes que podría ver en su archivo YAML.

En su terminal, vaya al directorio del repositorio `docs-website` y ejecute este comando:

`yarn verify-install-page YOUR_BRANCHING_DOC_DIRECTORY_NAME`

Por ejemplo, para el documento de ramificación de Java, usaría:

`yarn verify-install-page java`

porque el documento de ramificación de Java se encuentra en `src/install/java`.

Este script verifica lo siguiente en su archivo YAML:

* El valor `agentName` coincide con el nombre de la carpeta en `src/install/YOUR_DIRECTORY_NAME`.
* Los campos `agentName`, `agentType`, `title` y `appInfo` no están en blanco.
* El campo `appInfo` `placeholder` no está en blanco.
* Las rutas de los archivos de pasos y anulaciones son rutas válidas y apuntan a archivos reales.
* Todos los `overrides` tienen un valor `selectedOptions`.
* Problemas generales de sintaxis de YAML, como una comilla adicional o una sangría no válida.

## Detalles del nombre del campo YAML [#yaml-fields]

* agentName: el nombre del directorio donde reside todo, también vinculado a la URL (/install/java)

* title: el nombre del documento (igual que otros .mdx archivos).

* introFilePath: el archivo que contiene el contenido de introducción para el documento.

* agentConfigFilePath: (opcional, si se usa un archivo de configuración) donde se encuentra el archivo de configuración del agente. Si no funciona, pregunte a ingeniería si es un tipo de archivo compatible.

* appInfo: la sección donde se definen sus opciones. Componentes:

  * optionType: el nombre que le da a un conjunto de opciones. Este nombre se referenciará en la sección `steps` para dictar a qué opciones hace referencia, y también en el .mdx asociado archivo.
  * label: nombre para el desplegable, que se muestra encima de ese cuadro de opciones. Puede dejar esto en blanco, con comillas vacías, si no lo desea.
  * marcador de posición: más texto que puede colocar sobre el cuadro de opciones. Puede dejar esto en blanco, con comillas vacías, si no lo desea.

* opciones

  * value: la variable para el nombre del mosaico. Se hace referencia a esto en la sección `steps` cuando proporciona los valores que rigen qué archivos se muestran.
  * displayName: la etiqueta mostrada del mosaico de opciones.
  * logo: opcional. Una ruta a una imagen utilizada para el mosaico de opciones.
  * icon: opcional. Use esto si desea usar un ícono en lugar de una imagen (icon name=&quot;fe-server”)
  * recommendedGuided: booleano. Esto determina si el contenido en el archivo .mdx del tipo de componente `appInfoConfigOption` se mostrará. Esto se utiliza principalmente para el contenido de instalación guiada, pero podría usarse para cualquier contenido que desee activar para que se muestre en ese archivo. [Lea más sobre las opciones de instalación guiada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#guided-install-decision).

* steps: esta es la sección que determina qué contenido se muestra. El orden en que se enumeran determina el orden de todo el contenido.

  * filePath: esta es la ruta al .mdx archivo (o ruta teórica dependiendo de si se activará).

  * overrides: hay tres tipos de anulación:

    * **Reemplazar**. Si hay otro `filePath` en la lista bajo una anulación, significa: reemplace la ruta del archivo principal con esta ruta de archivo según las opciones seleccionadas.
    * **Mostrar si...** Esto utiliza el `isConditionalStep`, que toma un valor booleano. Esto no es una &quot;anulación&quot;, sino que significa: mostrar este archivo según las opciones seleccionadas. Para obtener información sobre el uso de una lógica AND/OR más compleja, consulte el [ejemplo de yaml de .NET](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example).
    * **Omitir.** Esto usa `skip`, que toma un booleano. Esto esencialmente dice: muestre este archivo pero omítalo si se seleccionan estas opciones.

  * selectedOptions: la sección donde coloca las selecciones de opciones relevantes. Los componentes incluyen:

    * optionType: esto se conecta al `optionType` utilizado en la sección `appInfo`.
    * opciones
      * valor: se conecta al `value` utilizado en el `optionType`.

## Ramificación de archivos MDX [#mdx-overview]

Al trabajar con este framework de instalación, hay archivos MDX específicos que se deben tener en cuenta. Los diferentes tipos de contenido MDX se especifican a través del campo frontmatter `componentType`.

Los diferentes .mdx tipos de componentes son:

* `intro`

  * Referenciado en el YAML por `introFilePath`.
  * Este es el contenido de introducción en la parte superior del documento.

* `default`

  * Un archivo MDX de formato libre.
  * Use esto para la mayor parte de su contenido.

* `appInfoConfigOption`
  * Esto se utiliza para hacer referencia al contenido de la opción.

* `agentConfig`
  * Esto se utiliza para el archivo de configuración de un agente.

Para ver ejemplos de archivos MDX en uso, consulte nuestro [archivo yaml de ejemplo](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example).

### El archivo MDX agentConfig [#sample-agentconfig]

El archivo MDX `agentConfig` opcional apunta al archivo de configuración apropiado en el directorio de instalación y controla qué líneas en el archivo de configuración son editables.

```md
---
componentType: agentConfig
headingText: Set your app name and license key
descriptionText: Set your app name and license key. Then download your custom config file.
fileName: newrelic.yml
inputOptions:
  - label: 'Name your app'
    name: appName
    codeLine: 21
    defaultValue: 'My app name'
    toolTip: 'New Relic connects metrics to individual applications using your license key and the primary application name.' 
  - label: 'Enter your license key'
    name: licenseKey
    codeLine: 28
    defaultValue: '12345'
---
```

Al usar el archivo de configuración, le recomendamos:

* cambie los permisos predeterminados de `newrelic.yml` a lectura/escritura solo para el propietario del proceso del servidor de la aplicación.
* asegúrese de que `newrelic.yml` sea parte de su rutina de copia de seguridad.
* utilice la [CLI de diagnósticos de New Relic](https://docs.newrelic.com/docs/new-relic-solutions/solve-common-issues/diagnostics-cli-nrdiag/run-diagnostics-cli-nrdiag/) para validar su configuración, ya sea antes o después de desplegar.

### Campos de frontmatter de MDX [#mdx-frontmatter]

* `componentType`: (use una de estas cuatro opciones) si falta, el valor predeterminado es el tipo &quot;default&quot;

  * `default`: archivo mdx gratuito
  * `appInfoConfigOption`: esto es para desplegables, úselo siempre que desee desplegables
  * `agentConfig`: esto es para el archivo yaml
  * `appInfoConfig`: este paso es en el que se muestra el contenido (incluye contenido `recommendedGuided`)

* `descriptionText`: el primer texto en el contenido del paso (texto gris más pequeño que actúa como un segundo encabezado)

* `optionType`: solo agregado para `appInfoConfigOption`
