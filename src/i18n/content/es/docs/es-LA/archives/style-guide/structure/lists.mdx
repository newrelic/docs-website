Las listas son una forma poderosa de organizar la información, pero no siempre ofrecen una experiencia de lectura agradable. Tenga en cuenta estos puntos cuando escriba una lista:

* Escriba siempre en mayúscula la primera letra de la primera palabra de cada elemento de la lista.
* Use listas ordenadas (numeradas) para procedimientos paso a paso, donde el orden importa.
* Use listas desordenadas (con viñetas) para facilitar al usuario la lectura rápida de información relacionada.
* Use OR en una línea separada cuando haya más de una opción para un paso numerado o una viñeta.
* Use tablas cuando su lista ordenada o desordenada se beneficie de algún detalle adicional.

<Callout variant="tip">
  Para conocer las pautas de puntuación, siga la **[Guía de estilo de escritura de Microsoft](https://docs.microsoft.com/en-us/style-guide/scannable-content/lists),** que incluye consideraciones para la localización.
</Callout>

## Listas en línea [#inline-lists]

Como alternativa al uso de listas con viñetas, puede hacer una lista en línea, como esta: [C SDK](/docs/agents/c-sdk/instrumentation/enable-distributed-tracing-your-c-applications) | [Go](/docs/agents/go-agent/features/distributed-tracing-go#create-manually) | [Java](/docs/agents/java-agent/api-guides/guide-using-java-agent-api#trace-calls).

Es posible que desee utilizar una lista en línea cuando:

* Está enlazando a más documentación.
* Es probable que los clientes seleccionen una sola opción.
* El elemento de la lista se puede mostrar con una palabra o frase corta (como Java o infraestructura).
* Cree que una lista de viñetas ocupa mucho espacio vertical. Esto puede suceder en circunstancias en las que un procedimiento debe incluir varias listas. Este es [un ejemplo de esto](/docs/understand-dependencies/distributed-tracing/enable-configure/enable-distributed-tracing#enable).
* Solo hay dos o tres opciones posibles entre las que elegirán y una lista de viñetas parece innecesaria. Este es [un ejemplo](/install/dotnet#requiremnts).
