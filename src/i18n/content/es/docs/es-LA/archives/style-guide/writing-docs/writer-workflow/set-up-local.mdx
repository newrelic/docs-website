Ejecutar el sitio localmente hace que probar y previsualizar cambios grandes sea mucho más fácil. Hay varias cosas que debe hacer para que esto funcione. Afortunadamente, solo necesita hacer esto una vez.

## Uso de la terminal y la línea de comando [#terminal]

En macOS, puede usar la aplicación Terminal para acceder a la línea de comando de su sistema. (También puede acceder a la terminal a través de VS Code). La línea de comando es una alternativa a la interfaz de usuario gráfica.

Estos son algunos comandos básicos de terminal que pueden ser útiles:

* `pwd` (print working directory): use esto para ver la ruta de su directorio.
* `ls` (list): muestra los archivos en su directorio actual.
* `cd YOUR_DIRECTORY_PATH` (change directory): se mueve a otro directorio.
* `cd ..`: Suba un directorio en su ruta.

## Habilite VS Code en su terminal [#code-terminal]

Es útil poder abrir archivos desde su terminal directamente en VS Code. Puede que solo use esto un par de veces, pero es mucho mejor que intentar editar archivos en la propia terminal.

1. Abra Visual Studio Code.
2. Presione **Command + Shift + P** para abrir la paleta de comandos, luego escriba `install code` y luego haga clic en **Shell command: Install &apos;code&apos; command in PATH**.
3. En su terminal, escriba `code` YOUR\_FILENAME\` para abrir ese archivo en VS Code.

## 1. Use GitHub Desktop para configurar su repositorio local [#repo-setup]

GitHub Desktop es una herramienta gráfica para administrar sus ramas, confirmaciones y PR. Probablemente sea la forma más sencilla de trabajar con Git y GitHub.

1. Instale GitHub Desktop.
2. Inicie sesión en GitHub Desktop a través de su cuenta de GitHub. En Mac, haga clic en **GitHub Desktop** en la esquina superior izquierda de su pantalla y seleccione **Preferences**. Seleccione el botón azul **Sign In** y siga los símbolos en la ventana del navegador.
3. Navegue hasta el [respositorio del sitio de documentación](https://github.com/newrelic/docs-website).
4. Haga clic en el botón verde **Code** y seleccione **Open with [GitHub Desktop](https://desktop.github.com/)**.
5. Elija la ubicación donde desea el repositorio. La ubicación predeterminada para esta carpeta es `~/Documents/github`.
6. Clone todo el respositorio a su máquina local.

## 2. Habilite el acceso total al disco [#disk-access]

De forma predeterminada, parece que macOS impide que la terminal acceda a ciertas carpetas del sistema, como `Documents`. Cambie esta configuración para que sea más fácil navegar por su sistema de archivos a través de la terminal.

1. Abra **Preferencias del sistema**.
2. Haga clic en **Security &amp; Privacy**.
3. En el panel izquierdo, desplácese hacia abajo hasta encontrar **Acceso total al disco** y luego selecciónelo.
4. Haga clic en el candado en la esquina inferior izquierda y luego ingrese la contraseña que usa para iniciar sesión en su computadora.
5. En la lista de aplicaciones, marque la casilla junto a **Terminal** (o cualquiera que sea su aplicación de terminal predeterminada).
6. Haga clic en el candado para bloquearlo.

## 3. Instale Homebrew [#homebrew]

Homebrew es una herramienta de línea de comando para instalar otras aplicaciones. También es una forma fácil de mantener actualizado el software de línea de comando.

1. Abra su terminal.

2. Copie y pegue este comando en su terminal:

   ```shell
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

## 4. Instale npm (administrador de paquetes de Node.js) [#npm]

Necesita instalar `npm` para que también pueda instalar `nvm` (administrador de versiones de Node.js). En su terminal, escriba `brew install npm`.

## 5. Instale nvm (administrador de versiones de Node) [#nvm]

El administrador de versiones de Node (`nvm`) es lo que se utiliza para administrar la versión de Node.js instalada en su computadora. En su terminal, escriba `npm i -g nvm`.

## 6. Agregar nvm a su perfil de shell [#add-nvm]

Para ejecutar los comandos necesarios para su compilación local, debe agregar la ruta a `nvm` en su perfil de shell.

En macOS, su shell es lo que interpreta lo que ingresa en la línea de comando. El shell predeterminado de macOS es Zsh. Necesita indicarle a su shell el directorio donde se encuentra `nvm` en su máquina para que pueda ejecutar estos comandos desde cualquier lugar.

Para hacerlo, agregue el siguiente texto a su archivo `.zshrc`, que es un archivo de configuración para su shell.

1. En su terminal, escriba `code ~/.zshrc` para abrir este archivo en VS Code.

2. En el archivo `.zshrc`, copie y pegue este texto:

   ```shell
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
   ```

3. Guarda el archivo.

## 7. Instale Node.js [#node]

Una vez que haya instalado `nvm`, puede instalar la versión correcta de Node. Node, o Node.js, es el motor de JavaScript que impulsa nuestro sitio de Gatsby y sus dependencias. Escriba `nvm use 18` para instalar la versión 16 de Node.js.

## 8. Instalar Yarn [#yarn]

Yarn es otro administrador de paquetes que se usa para compilar todos los archivos en el repositorio **docs-website** para construir el sitio localmente. Use npm para instalar Yarn. En su terminal, escriba `npm i -g yarn`.

## Compilar el sitio local [#local-site]

Una vez que haya instalado todas estas cosas en su terminal, puede ejecutar el sitio localmente en su máquina.

1. En su terminal, escriba `pwd` para asegurarse de que está en el directorio del respositorio **docs-website**.
2. Escriba `yarn` para asegurarse de que todas sus dependencias de Gatsby estén actualizadas.
3. Escriba `yarn start` para compilar el sitio localmente.
4. Cuando termine el proceso, en su navegador web, vaya a `http://localhost:8000`.

Cuando ejecuta `yarn start`, su terminal genera muchas líneas de texto. Si su compilación local falla, la salida del terminal a menudo proporciona una pista de lo que salió mal.

De forma predeterminada, el sitio se compilará sin ninguna página traducida (jp, kr). Si también desea compilar esas páginas, puede ejecutar `yarn start:full`.

## Compile parte del sitio local (más rápido) [#local-site-speed]

Si desea compilar el sitio aún más rápido, puede optar por compilar una sola carpeta (o tantas como desee) en lugar de cada documento del sitio. Esto puede ser útil si sabe que está trabajando en un documento de cuenta, por ejemplo, puede compilar solo la carpeta de la cuenta. Sin embargo, esto significa que si intenta visitar un documento en una carpeta fuera de lo que especificó, verá un `404`.

Para compilar una o más carpetas específicas, agregue esta variable a su comando `yarn start`:

`BUILD_FOLDERS=mlops yarn start` o `BUILD_FOLDERS=apm,logs,errors-inbox yarn start`

Consejos:

* La(s) carpeta(s) que especifique debe(n) estar en el nivel raíz del directorio `/src/content/docs/`. Esto no incluye ningún subdirectorio. Por ejemplo, `browser` es una carpeta válida, pero `browser-monitoring` no lo es porque es un subdirectorio de `browser`.
* Asegúrese de que no haya espacios después de las comas en su lista de carpetas. Por ejemplo, escriba `BUILD_FOLDERS=apis,infrastructure` no `BUILD_FOLDERS=apis, infrastructure`.
