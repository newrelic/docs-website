Este documento explica los estilos requeridos y las expresiones recomendadas para la documentación relacionada con los roles de usuario/permisos.

## Nota sobre los modelos de usuario

Esta guía de estilo se aplica principalmente a la redacción sobre los usuarios en nuestro modelo de usuario más reciente, no en nuestro modelo de usuario original. Aunque ambos modelos de usuario comparten ciertos términos (como **Admin**), este es un modelo de usuario completamente diferente con una estructura, frases recomendadas y estilo completamente distintos. Para comprender las diferencias de los modelos de usuario, consulte la [Descripción general de los modelos de usuario](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models).

El modelo de usuario original quedará cada vez más obsoleto, por lo que no deberíamos tener que pensar mucho en ese modelo de usuario ni actualizar esos documentos con mucha frecuencia.

## Pautas para documentar permisos/roles de usuario [#user-language-philosophy]

Hay dos factores principales que afectan la capacidad de un usuario de New Relic para acceder a una característica de New Relic:

* Tipo de usuario: limitamos casi por completo la información sobre el tipo de usuario al [documento de tipo de usuario](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type).

* Roles y capacidades: limitamos casi por completo la información sobre esto a los documentos dedicados a la gestión de usuarios:

  * [Documentos originales del modelo de usuario](/docs/accounts/original-accounts-billing/original-users-roles/users-roles-original-user-model)
  * [Documentos más recientes del modelo de usuario](/docs/accounts/accounts-billing/new-relic-one-user-management/introduction-managing-users)

En otras palabras, **no colocamos información sobre el tipo de usuario y los roles/capacidades en los documentos relacionados con las características del producto**, con las siguientes excepciones:

* Para el tipo de usuario: para la mayoría de las características del producto, es obvio para un usuario si algo está fuera de los límites debido al tipo de usuario (por ejemplo, ve un mensaje de la UI sobre el tipo de usuario). Si no es obvio que algo está fuera de los límites debido al tipo de usuario, puede documentarlo en la sección de requisitos de un documento de la característica. Por ejemplo, no será inmediatamente obvio para un usuario de NerdGraph por qué no puede hacer ciertos requests, por lo que esa es una situación en la que documentaríamos el tipo de usuario en el documento principal de NerdGraph.
* Para roles y permisos: si hay una razón específica para incluir el tipo de usuario o los roles/permisos en la sección de requisitos de un documento de característica, puede incluirlo. Por ejemplo: si un [permiso](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions) que controla el acceso a una característica no es obvio por el nombre de los permisos (como los [permisos de administración a nivel de servicio](/docs/service-level-management/faqs-slm#permissions)), debemos documentarlo.
* Para los permisos de administración de la organización y de usuarios, documentamos los roles requeridos. Esto se debe a que no hay muchos de estos, y también a que los permisos que los rigen no están expuestos en la UI de roles y permisos y, por lo tanto, son menos obvios para los clientes.

## Consideraciones para documentar tanto el modelo de usuario original como el nuevo [#user-model-requirements]

Si necesita incluir requisitos sobre roles o permisos de modelos de usuario más nuevos, probablemente también deba incluir detalles sobre el modelo de usuario original (suponiendo que esa característica esté disponible para esa audiencia). A continuación se muestra un ejemplo de cómo hacerlo:

```md
Permissions requirements differ depending on your user model:

* For users on the [original user model](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models): the [**Data retention manager** role](/docs/accounts/original-accounts-billing/original-users-roles/users-roles-original-user-model/#roles).
* For users on [our newer user model](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models): the [**Billing** administration setting](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts#admin-settings).
```
