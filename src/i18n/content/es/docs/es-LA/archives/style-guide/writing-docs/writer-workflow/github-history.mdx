Las características de control de versiones de GitHub nos permiten ver el historial completo de un documento, acceder a un documento en cualquier momento y encontrar documentos eliminados sin copias de seguridad manuales.

## Revise el historial de edición de un documento o archivo [#doc-history]

Use cualquiera de estas opciones para verificar o hacer un &quot;diff&quot; del historial de un archivo.

**Opción 1: pestaña de historial de GitHub**

1. Navegue hasta el documento en el sitio de documentación y haga clic en **Edit page** en la navegación derecha.
2. Haga clic en **History** en la esquina superior derecha del documento.

**Opción 2: githistory.xy**

1. Navegue a su archivo específico en GitHub.com:

   ```
   https://github.com/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

2. En la URL, reemplace `github.com` con `github.githistory.xyz`:

   ```
   https://github.githistory.xyz/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

3. Lo llevará a un sitio que presenta el historial visual de ese archivo específico. Puede ver los cambios haciendo clic en el historial de confirmaciones en la parte superior de su página.

**Opción 3: Git blame**

Siga la [documentación de GitHub](https://docs.github.com/en/github/managing-files-in-a-repository/managing-files-on-github/tracking-changes-in-a-file).

Alternativamente, puede usar el siguiente comando en su terminal:

```bash
git log --follow "**/file_name_here.mdx"
```

Esto mostrará el historial de commits de ese archivo. Por defecto, solo muestra los primeros commits. Puede desplazarse presionando `Return` varias veces.

Por ejemplo, para encontrar el historial de commits de `vmware-vsphere-monitoring-integration.mdx`, ejecute:

```bash
git log --follow "**/vmware-vsphere-monitoring-integration.mdx"
```

## Historial del sitio de documentación antes de octubre de 2021 [#archived-version]

Tuvimos una gran reestructuración del sitio en octubre de 2021 en la que se perdió la mayor parte del historial de archivos de nuestros documentos. Puede encontrar una versión archivada de nuestro sitio antes de la reelaboración en la rama [pre-IA-2021](https://github.com/newrelic/docs-website/tree/pre-IA-2021). Al navegar por la versión anterior a la reelaboración de nuestro repositorio, puede encontrar el historial de archivos y más.

## Cómo encontrar archivos eliminados [#deleted-files]

Hay varias formas de encontrar archivos eliminados. Estos están ordenados aproximadamente por complejidad:

<CollapserGroup>
  <Collapser className="freq-link" id="pr" title="Encontrar el PR de eliminación">
    La forma más fácil de encontrar un archivo borrado es encontrar el pull request que lo borró. Hay múltiples formas de lograr esto; aquí hay algunas ideas:

    1. Use la característica de búsqueda de GitHub para buscar palabras clave relevantes. Puede filtrar los resultados de búsqueda para incluir solo los PR.
    2. Si tiene una idea aproximada de cuándo se eliminó el documento, podría intentar buscar el pull request en la pestaña de pull request. Esta lista tiene miles de PR, por lo que esto puede llevar algún tiempo.
    3. Muchos documentos se eliminan debido a un ticket de Jira. Busque el ticket en Jira, donde encontrará la hora aproximada en que se eliminó el documento y, con suerte, un enlace al propio PR.
    4. ¡Pregunte en #doc\_talk!
  </Collapser>

  <Collapser className="freq-link" id="releases" title="Buscar en los PR de la versión">
    Al buscar a través de los pull requests de lanzamiento, eventualmente puede encontrar una rama creada antes de que se eliminara el documento. Puede encontrar una lista de pull requests de lanzamiento en la [pestaña de pull requests de GitHub](https://github.com/newrelic/docs-we.bsite/pulls?q=is%3Apr+release+is%3Aclosed).

    Algunos consejos:

    * Busque primero por intervalos de un mes. Una vez que encuentre una rama que contenga el documento, puede reducir el alcance a una semana y luego a un día. Al disminuir el alcance, eventualmente encontrará el documento eliminado en su estado exacto antes de la eliminación.
    * Para acceder a la rama de la que proviene un PR, vaya a la página de ese pull request y haga clic en el nombre de la rama debajo del título y el número de PR.
  </Collapser>

  <Collapser className="freq-link" id="git-log" title="Utilice git log">
    La forma más potente y confiable de encontrar archivos eliminados es usar `git log`. Consulte [StackOverflow](https://stackoverflow.com/questions/7203515/how-to-find-a-deleted-file-in-the-project-commit-history/7203551#7203551) para obtener más detalles.
  </Collapser>
</CollapserGroup>
