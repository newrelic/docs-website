## Formato de código en línea [#inline-code]

Para dar formato al código en línea (como `maxSampleTimes` o `TransactionError`), encierre el texto entre caracteres de acento grave `` ` ``.

## Bloques de código de varias líneas [#code-block]

Para dar formato a una o más líneas de código, inserte tres comillas invertidas ( ` ``` ` ) arriba y abajo de su código. Esto actúa esencialmente como la etiqueta HTML `<pre>`.

Cuando encierra sus fragmentos de código entre tres acentos graves, debe tener en cuenta tanto la sangría del código como el resaltado de sintaxis.

### Sangría estricta [#strict]

Como redactor técnico, se le proporcionarán fragmentos de código de una variedad de lenguajes. Para que a sus lectores les resulte más fácil entender los fragmentos de código, asegúrese de que las líneas estén sangradas y agrupadas de manera útil.

Algunos lenguajes de programación y marcado requieren una sangría específica (por ejemplo, Python y YAML). Consulte con su experto en la materia si no está seguro de si el fragmento que se le ha proporcionado necesita tener una sangría específica para funcionar. Siempre puede pasar el fragmento por un embellecedor de código en línea si se desordena al transferirlo desde otra herramienta de edición.

Aquí hay un ejemplo de código de Python que fallará si cambia la sangría:

```python
import newrelic.agent
newrelic.agent.initialize('newrelic.ini') #This is required!

def greet(name):
    """
    This function says hello to
    the person who is passed in as
    a parameter
    """
    print("Hello, " + name + " and the world!")


def execute_task(application, task_name):
    with newrelic.agent.BackgroundTask(application, name=task_name, group='Task'):
        greet("Robert")

application = newrelic.agent.register_application(timeout=10)
execute_task(application, "bar")
newrelic.agent.shutdown_agent(timeout=10)

```

### Sangría no estricta [#casual]

Para los lenguajes de formato libre, que son flexibles con la sangría, le recomendamos que busque ejemplos similares y siga esos patrones. Java y SQL son ejemplos de lenguajes de formato libre.

### Cómo dar formato a NRQL [#NRQL]

NRQL es un lenguaje de consulta de formato libre, lo que significa que no tiene reglas estrictas de sangría. Recomendamos que siga algunas pautas simples para que sea más fácil de leer. Nuestras sugerencias se basan libremente en algunas pautas de formato de SQL.

Puede usar su criterio para decidir si estas pautas se aplican a su fragmento:

* Ponga en mayúscula las palabras clave de la cláusula, como `FROM`, `SELECT`, `FACET`, `WHERE`, `AND`, `OR`, `AS`, `SINCE`, `ORDER BY`, `TIMESERIES`, `EXTRAPOLATE` y `AUTO`.

* No ponga en mayúscula las funciones, como `min()`, `max()`, `average()`, `percentile()`, `sum()` y `stddev()`, ya que el generador de consultas no pone en mayúscula automáticamente estos nombres. Si no está seguro de si una palabra clave es una función, consulte la [referencia de NRQL](/docs/query-your-data/nrql-new-relic-query-language/get-started/nrql-syntax-clauses-functions/#functions).

* La primera línea debe comenzar con una cláusula `FROM`, aunque las consultas se ejecutan bien cuando comienza con `SELECT`.

* Justifique a la izquierda las palabras clave de la cláusula excepto en los siguientes casos:

  * Si una palabra clave de cláusula está estrechamente vinculada a una palabra clave anterior (por ejemplo, `AGO` está estrechamente vinculada a `SINCE`), pertenece a la misma línea.
  * Si una palabra clave de cláusula no tiene ningún modificador (es independiente), puede agregarla al final de una línea que ya tiene palabras clave (por ejemplo, `TIMESERIES`, `AUTO` y `EXTRAPOLATE`).
    ```sql
    FROM Transaction
    SELECT count(*)
    WHERE appName='interestingApplication'
    SINCE 60 minutes AGO EXTRAPOLATE
    ```

* Para las palabras clave dentro de paréntesis que abarcan varias líneas, aplique una sangría de dos espacios. Por ejemplo, a la palabra clave `WHERE` se le aplica una sangría de dos espacios de la siguiente manera:
  ```sql
  FROM PageView
  SELECT count(*)
  FACET CASES
  (
    WHERE duration < 1,
    WHERE duration > 1 AND duration < 10,
    WHERE duration > 10
  )
  ```

Puede agregar codificación de colores para una variedad de lenguajes de programación agregando el nombre del lenguaje inmediatamente después de las primeras tres comillas invertidas de su fragmento. ## Resaltado de líneas de código [#highlight-code]

Para resaltar líneas enteras de código en un bloque de código, puede usar `lineHighlight=` para indicar las líneas específicas que desea resaltar. Esto lo hace en el mismo lugar donde anota la sintaxis. Aquí hay un ejemplo de un bloque de código con la primera línea y de la tercera a la quinta resaltadas:

```js lineHighlight=1,3-5
const coolThing = {
  key: 'HI',
  tada: 'hello'
}
// this is an important object
// other notes...
```

## Marcadores de posición para variables específicas de clientes [#value-placeholders]

A veces queremos usar marcadores de posición para variables cuyo valor dependerá de los clientes o de la situación. Por ejemplo, es posible que deba usar `YOUR_ACCOUNT_ID` para indicar un marcador de posición donde los clientes deben ingresar su ID de cuenta de New Relic.

Algunos requisitos y consejos para crear marcadores de posición de valor específicos para clientes:

* Use mayúsculas y guiones bajos `_` para separar palabras (también conocido como [SCREAMING\_SNAKE\_CASE](https://github.com/rubocop-hq/ruby-style-guide#screaming-snake-case)).
* No use otros elementos, como `<` o `>`, o `$`, a menos que los SME presenten un argumento convincente de por qué se necesitan otros elementos para un idioma o situación específicos.
* Diríjase al lector directamente usando `YOUR`. Por ejemplo, use `YOUR_ACCOUNT_ID` y no `ACCOUNT_ID`.
* Si cree que puede no estar claro si un componente es nuestro o de un tercero, puede agregar `NEW_RELIC` al marcador de posición. Por ejemplo, al escribir sobre la conexión de AWS a New Relic, es posible que desee especificar que una cuenta es nuestra y no de AWS, de esta manera: `YOUR_NEW_RELIC_ACCOUNT_ID`.
* No las combine con otros signos de puntuación para indicar variables (como encerrar el texto entre corchetes angulares o llaves).

### Cuándo no usar marcadores de posición [#placeholders]

Los marcadores de posición se utilizan principalmente cuando hay un procedimiento por hacer, como clientes que ejecutarán algún código. Si no hay un procedimiento involucrado y se usa un fragmento de código para demostrar cómo se ve o debería verse algo, no debe usar marcadores de posición. A continuación se muestran algunos ejemplos de dónde **no** debe usar marcadores de posición:

* Código o archivos de ejemplo: si muestra un archivo de configuración de ejemplo u otro ejemplo que no esté directamente relacionado con el procedimiento, use valores de ejemplo y no marcadores de posición.
* Respuestas de llamadas API: si incluye la respuesta de una llamada API que tiene como objetivo mostrar cómo se verá la respuesta y no está relacionada con un procedimiento, no use marcadores de posición.

### Claves de API

Si es necesario hacer referencia a una clave de API como ejemplo en un bloque de código o configuración, deberemos usar texto de marcador de posición con asteriscos en lugar de ceros.

Ejemplo:

```
...
-e NEW_RELIC_API_KEY=********************************FFFFNRAL \
...
```

o

```
...
NEW_RELIC_LICENSE_KEY=****************************************
...
```
