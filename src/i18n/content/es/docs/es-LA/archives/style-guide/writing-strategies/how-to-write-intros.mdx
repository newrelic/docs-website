Las introducciones son muy parecidas a los aperitivos de una cena — preparan el escenario para el plato principal. Si dedica un poco de trabajo adicional a la introducción, sus lectores estarán listos para el plato principal.

Cuando redacta introducciones, por lo general, incluye estos tres ingredientes:

* Información que define el tema
* Ideas que captan el interés del usuario
* Textos introductorios que indican al lector qué esperar del documento

Los dos primeros ingredientes parecen sencillos, pero cuando se trata de decirles a los lectores lo que pueden esperar, a menudo dependemos de frases repetitivas y rígidas. La forma en que manejamos esto plantea algunas preguntas: ¿quién está hablando? ¿Es autoritario? ¿Es colaborativo? ¿Es esta la mejor manera de ayudar a los usuarios a aprender y resolver sus problemas?

Analizaremos algunos consejos generales sobre las introducciones, pero nos centraremos en cómo indicar a los lectores qué esperar del documento. Si prefiere omitir la discusión de fondo, puede saltar a los [Ejemplos de frases iniciales](#example-lead-ins) que muestran introducciones que evitan las frases hechas y van al grano del tema de la página.

## Consejos para introducciones más activas [#tips]

Tenemos varias páginas en nuestro sitio que tienen un encabezado seguido de una oración introductoria `This document is about`. Esta oración a menudo reafirma el encabezado. Al leer más, generalmente hay un párrafo que proporciona una mejor introducción. Le recomendamos que evite usar el `this document is about` y vaya directamente a la información que busca el usuario.

Analizaremos varias alternativas a este tipo de construcción a lo largo del documento. Antes de explorar esas alternativas, considere estas formas de redactar introducciones más sólidas:

* Concéntrese en el usuario de inmediato. En lugar de comenzar hablando sobre de qué trata el documento, hable sobre lo que el usuario podría querer saber o hacer (piense en [Cinco preguntas](/docs/style-guide/writing-strategies/five-questions-help-write-docs)).
* Pregúntese qué información falta o está implícita: es posible que deba definir un término o un concepto. Por ejemplo, tenemos una página de documentación que se centra en el uso de Gradle, pero nunca dice qué es Gradle. O, en la página de Observability for Good, comenzamos haciendo referencia a OfG, pero no decimos qué es.
* Descubra cuál es el verdadero objetivo de la página y asegúrese de incluirlo en la introducción. Esa información suele encontrarse poco después de la frase introductoria plana “Esta página trata sobre esto”. Pero es posible que deba observar bien la página para encontrar el énfasis.

Para encontrar nuevas formas de llegar a su lector, explore algunos enfoques alternativos para las introducciones.

## Considere algunos enfoques diferentes [#what-about]

¿De qué trata su documento? La forma en que responda a esta pregunta afecta a sus lectores y su posibilidad de atraerlos. Si utiliza la misma construcción en todos sus documentos, pueden ser predecibles, pero también podrían ser repetitivos hasta el punto de que los usuarios dejen de ver esas oraciones.

La frase hecha tiende a ser una barrera para un buen detalle, y tiende a repetir la información que ya se proporcionó en el título de la página. A menudo, al mover la información pertinente a la introducción, puede informar al lector de manera más específica e interesante de qué trata la página.

Este es un ejemplo de introducción que resume un problema y capta la atención de los lectores:

```
Clogged drains account for 60 percent of calls to professional plumbers. You may be able to solve this problem yourself and avoid the expense.
```

¿Qué tipo de tercera oración podría agregar a este párrafo para decirles a los lectores de qué trata el resto de este documento? Las secciones a continuación tienen tablas con varias opciones para su tercera y última oración de conexión.

### Enfoque 3: use la primera persona [#first-person]

Cuando utiliza la primera persona `we` en un documento de procedimiento, el `we` se refiere a usted como redactor junto con el lector. Ambos están siguiendo los pasos juntos.

<Callout variant="tip">
  Este es un uso diferente de `we` del uso más general en el que `we` puede referirse a New Relic. Puede usar `we` como sustituto de New Relic cuando no se refiere al escritor y al lector juntos. Por ejemplo, “NerdGraph es la API que **nosotros** recomendamos para consultar datos de New Relic y para realizar alguna configuración específica (obtenga más información sobre la característica)”.
</Callout>

La primera persona probablemente se usa mejor en el contexto de tutoriales donde una relación personal es explícita. Por ejemplo, si tiene un blog o un curso, y está guiando a los usuarios a través de un procedimiento. En New Relic, no solemos tener este contexto, pero podemos tener algunos casos en los que esto encaje.

Si tiene un contexto donde la primera persona es apropiada, evite los casos en los que la primera persona envíe el mensaje de que la empresa está observando en secreto al usuario o sus datos. Por ejemplo, no querría tener un uso en primera persona como este: “Vemos que su agente está desactualizado. ¿Le gustaría actualizarlo?”

## Las secciones de introducción frente a “Por qué es importante” [#why-matters]

Una vez que tenga una variedad de opciones para construir su introducción, tenga cuidado de no diluir su introducción con una sección posterior de “Por qué es importante”.

Para crear una introducción más activa y centrada en el usuario, es posible que desee incluir información que normalmente pondría en una sección del tipo “Por qué es importante”. ¡Debería hacerlo! Definitivamente queremos que los usuarios sepan por qué el tema es importante para ellos lo antes posible.

A continuación se explica por qué usar “Por qué es importante” como sección y encabezado es un problema:

* A menudo esperamos para compartir la información que es más importante para un usuario hasta la sección &quot;Por qué es importante&quot;. Nuestro objetivo debe ser ayudar a los usuarios a aprender rápidamente lo que una característica les ayudará a lograr. Así que siéntase libre de deshacerse de esa sección dedicada si ya les está informando a los usuarios sobre esto en la introducción o en otras secciones del documento.
* El valor debe estar vinculado con el tema de un documento. Debe incluir declaraciones de valor siempre que tengan sentido. Puede tener un valor de alto nivel en la introducción, por ejemplo, y luego declaraciones de valor más específicas cuando analice otro aspecto del tema de la página.
* No use “Por qué es importante” como encabezado, de todos modos. Es otra frase repetitiva que parece documentación genérica. Si dedica espacio a abordar esta pregunta, cree un encabezado que proporcione información sobre el valor, en lugar de usar el encabezado estándar “Por qué es importante”.

## Ejemplos de introducciones [#example-lead-ins]

Eche un vistazo a estas frases introductorias que evitan las frases hechas y van al centro del tema de la página. Estas son reescrituras de contenido existente.

### Ejemplo 1: [pautas de elegibilidad](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/eligibility-guidelines-new-relic-nonprofit-program/) [#eligibility]

```
Non-profits and New Relic

This document provides New Relic's Observability for Good program eligibility guidelines for nonprofit, charitable, and NGO organizations.

Exceptions

Many global nonprofit, charity and NGO organizations are eligible for Observability for Good if the organization has a recognized legal status in their respective country equal to 501(c)(3) status under the United States Internal Revenue Code, with certain exceptions. In addition, all organizations must be verified by TechSoup or the local TechSoup partner.
```

Así es como se podría reescribir esto:

```
If your organization is a global nonprofit, charity, or NGO, it might qualify for Observability for Good, a New Relic program that provides expansive, free access to New Relic. To qualify, your organization must have a recognized legal status in your respective country equal to 501(c)(3) status under the United States Internal Revenue Code. And, it must be verified by TechSoup or the local TechSoup partner.

To get started:

  1. Check that your organization is not in one of the ineligible categories (link). 
  2. Submit a New Relic application (link).
  3. Get qualified with TechSoup (link).
```

Esta revisión tiene estos cambios:

* Define Observability for Good de inmediato. Vaya directamente al propósito de la página, sin tener que decir cuál es el propósito.
* Reemplaza las primeras oraciones pasivas con un punto de vista más activo en segunda persona: “si su organización es una organización sin fines de lucro, benéfica u ONG global” en lugar de “mucha organización global sin fines de lucro, benéfica y ONG”.
* Mantiene el énfasis en “usted”, el lector y los posibles beneficiarios de este programa.
* Elimina las “excepciones” negativas y las reemplaza con detalles sobre cómo calificar y aplicar.

### Ejemplo 2: [Cambia tu contraseña](https://docs.newrelic.com/docs/accounts/accounts/account-maintenance/change-passwords-user-preferences/) [#change-password]

```
This document contains information on New Relic password requirements.

Change your password

New Relic account passwords don't expire. However, users can change their own password and other personal account information anytime.
```

Así es como podría reescribir esto:

```
New Relic account passwords don't expire. However, you can change your own password and other personal account information anytime. You can also request a password reset if you forget your password.
```

Esta revisión tiene estos cambios:

* Elimina la línea &quot;this document contains&quot; y el primer H2.
* Comienza con la información que más le importará a un usuario: las contraseñas no caducan. Puede cambiar su contraseña en cualquier momento que desee.
* Lo convierte en “usted” en lugar de “usuarios”.
* Esta es una página corta y la introducción puede entrar rápidamente en la información esencial. Además, los H2 deben proporcionar la descripción general de la información que se cubrirá.

### Ejemplo 3: [instalar el agente de Java](/docs/apm/agents/java-agent/additional-installation/install-java-agent-using-gradle/) [#install-java-agent]

```
This document explains how to install the Java agent using Gradle. For information on manually installing the Java agent, see "Install the Java agent" and "Java agent configuration: Config file."
```

Así es como podría reescribir esto:

```
Gradle is a highly flexible build automation tool that can help you install the Java agent across many instances quickly and consistently.

If you’d like to manually install the Java agent instead, see Install the Java agent and "Java agent configuration: Config file."
```

Esta revisión tiene estos cambios:

* Define Gradle (le permite automatizar la instalación).
* Luego, cuando se refiere al enfoque manual, está en contraste directo con la herramienta de automatización.
* Si necesita aclarar que solo va a cubrir un subconjunto de información relacionada con algo, por ejemplo, solo una de las muchas formas de automatizar la instalación con Gradle, podría decir lo siguiente: “Aquí, proporcionamos la forma más común de automatizar su instalación con Gradle”. Mucho depende del contexto.

### Ejemplo 4: [atributos de agente Java](/docs/apm/agents/java-agent/attributes/java-agent-attributes/) [#agent-attributes]

```
New Relic attributes are key-value pairs containing information that determines the properties of an event or transaction. These key-value pairs can help you gain greater insight into your application and annotate the data when you query it. You can also automatically forward user information to New Relic.

Both default and custom attributes are visible in APM transaction traces, distributed traces, and error analytics; APM events and Browser events in dashboards. You can customize exactly which attributes will be sent to each of these destinations.

This document describes the Java agent attributes, details how to enable or disable attributes, and describes the rules the agent follows to determine which attributes to include or exclude for a destination.
```

Para mejorar esto, puede mantener los primeros tres párrafos, pero agregar lo siguiente al párrafo final:

```
Before you start creating custom attributes, familiarize yourself with existing Java agent attributes and how to enable or disable them. In addition, learn the rules for which attributes the agent includes or excludes for a destination. 
```
