Este recurso contiene recomendaciones y pautas de la guía de estilo para escribir sobre la API NerdGraph de New Relic.

## Pautas relacionadas con el estilo [#nerdgraph-style]

Algunas pautas relacionadas con el estilo al escribir sobre NerdGraph:

* **NerdGraph.** Debe referirse a este en general como &quot;NerdGraph&quot; o &quot;NerdGraph de New Relic&quot;. En la primera mención, es aceptable denominarlo nuestra &quot;API de NerdGraph&quot;, especialmente en contextos donde puede no ser inmediatamente obvio que estamos hablando de una API.

* **NerdGraph es una sola API.** NerdGraph no es un conjunto de diferentes API. A veces existe la inclinación de referirse a NerdGraph como una colección de API, lo cual es en parte cierto porque NerdGraph reúne muchas de nuestras API bajo el capó, pero desde el punto de vista de los clientes, queremos referirnos a ella como una sola API. Por ejemplo, en lugar de decir algo como &quot;use la API de entidad de NerdGraph&quot;, podríamos decir algo como &quot;use NerdGraph para ver y configurar sus entidades monitoreadas&quot;.

* **GraphQL.** GraphQL es el formato de API de código abierto con el que se creó NerdGraph. Está bien destacar esto ocasionalmente cuando sea apropiado porque GraphQL es muy conocido en el mundo de la tecnología y algunas personas ya están familiarizadas con su funcionamiento.

* **NerdGraph Explorer.** Principalmente nos referimos a esto como &quot;el NerdGraph Explorer&quot; o &quot;nuestro NerdGraph Explorer&quot;, pero si está en un contexto donde puede no ser obvio qué es exactamente NerdGraph, puede referirse al &quot;NerdGraph API Explorer&quot;. Otros consejos:

  * Debido a que hay diferentes URL para las versiones de la UE y JP del explorador de NerdGraph, por lo general debemos enlazar a [la sección de documentación del explorador de NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#explorer) y no a la URL del explorador.
  * Evite usar solo &quot;explorer&quot; porque eso entra en conflicto con otros exploradores (por ejemplo, el explorador de la API REST o el explorador de entidades).
  * Podemos explicar, si creemos que es útil, que el explorador de NerdGraph está creado con GraphiQL, una plataforma de código abierto para crear consultas de GraphQL. Puede ser útil explicar esto porque tanto GraphQL como GraphiQL son conocidos en la industria.

* **Requests.** Hay dos tipos principales de operaciones de GraphQL: consultas y mutaciones ([definidas aquí](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology)). Podemos usar estos términos para referirnos a ejemplos específicos (por ejemplo: &quot;aquí hay una mutación que...&quot;). Para hacer una referencia general a múltiples requests de NerdGraph de diferentes tipos, puede usar &quot;requests&quot;.

* **Campos.** Los campos son los elementos de un tipo de objeto que pueden ser objeto de consulta. Para ver ejemplos del uso de &quot;campo&quot; en contexto, consulte [este tutorial de NerdGraph](/docs/nerdgraph-anomaly-detector-configurations-api-tutorial/#update-configuration). La razón por la que los campos son un concepto importante es que con las API en formato GraphQL, el usuario especifica exactamente los campos que desea recuperar (en contraste con las API REST, por ejemplo, que pueden devolver una respuesta predeterminada con campos que no necesita).

## Consejos para crear documentación de NerdGraph [#creating-nerdgraph-docs]

Está bien agregar secciones relativamente pequeñas de contenido relacionado con NerdGraph a documentos que no están en la categoría de documentos de NerdGraph. Como pauta general, si es más de una página de contenido relacionado con NerdGraph, debe intentar agregarlo a la categoría de documentos de NerdGraph (ya sea en su propio documento o en un documento relacionado, si es posible).

Si está agregando contenido a la categoría de documentos de NerdGraph, considere los siguientes consejos para ayudar a mantener nuestro contenido organizado de manera eficiente y fácil de encontrar:

* **Considere agregar contenido a un tutorial existente.** Al agregar nuevo contenido de NerdGraph, verifique si puede incluir el nuevo contenido en los documentos existentes de NerdGraph. Esto nos ayuda a mantener la lista de tutoriales limpia y evitar que se extienda. Por ejemplo, si desea agregar algo relacionado con la visualización o la configuración de entidades, puede agregarlo al [documento de NerdGraph relacionado con la entidad](/docs/apis/nerdgraph/examples/nerdgraph-entities-api-tutorial).
* **Elija un documento para emular.** Al escribir un nuevo documento de tutorial de NerdGraph, puede usar [este documento de NerdGraph](/docs/apis/nerdgraph/examples/manage-accounts-nerdgraph) como una plantilla aproximada. Siéntase libre de cambiar esta estructura en función de lo que usted o los expertos en la materia consideren necesario para ayudar a los clientes a comprender la funcionalidad de la API, pero esa estructura general debería funcionar para muchos documentos.
* Cuando agregue un nuevo tipo de contenido de NerdGraph, agréguelo al [índice de contenido de NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#tutorials). Ese índice se creó para reflejar que tenemos tutoriales disponibles que no están en la sección principal de la documentación de NerdGraph.

Algunos consejos al escribir contenido de NerdGraph:

* **Requests de ejemplo.** Consejos para crear requests de ejemplo:

  * Use etiquetas `tags for customer-specific values in example queries and mutations. Remember that you don't need to use` en las respuestas de ejemplo o en los mensajes de error.
  * Es una buena práctica explicar el uso general de una solicitud, seguido de una nota de que la solicitud de ejemplo es solo un ejemplo (en lugar de comunicar que es la única forma de lograr algo). Por ejemplo, podría decir: &quot;puede usar NerdGraph para actualizar su [monitor Sintético de prueba de API](/docs/synthetics/synthetic-monitoring/getting-started/types-synthetic-monitors#types-monitors). Este es un ejemplo de creación de un monitor de prueba de API que...&quot;.
  * Para limpiar el formato de un request, vaya al explorador de NerdGraph, ingrese el request y haga clic en **Tools &gt; Prettify**. Tenga en cuenta que el request debe ser uno que funcione, con valores reales.

* **Definiciones de campos.** El explorador de NerdGraph incluye definiciones de campos integradas, pero puede ser bueno explicar cualquiera de los campos más complejos o no obvios en su documento. Para los campos comunes utilizados en todos o en la mayoría de los requests de ejemplo, una forma de abordar esto es con una sección de &quot;Conceptos importantes&quot; cerca de la parte superior del documento, en la que incluya cualquier lectura recomendada o notas sobre campos importantes. Para los campos que solo se utilizan en uno o dos requests, es posible que prefiera explicarlos al presentar el request de ejemplo.

## Documentación del esquema de NerdGraph [#schema-docs]

El explorador de NerdGraph expone las definiciones de esquema de NerdGraph para ayudar a los usuarios a entender cuáles son los distintos campos. El equipo de documentación revisa los documentos de esquema que envían los equipos de ingeniería. Para obtener más información sobre cómo se realiza la revisión de la definición de esquema, consulte el recurso del equipo de documentación &quot;Repositorios de documentación externa&quot;.
