## Sintaxis

```
newrelic.apiStyleGuidelines(data type $parameter_name[, integer $optional_param])
newrelic.apiStyleGuidelines(data type $parameter_name, array $different_param, string $third_param)
```

Describa brevemente la llamada. Idealmente, una línea o menos en la página &quot;Ver todos los métodos&quot;.

## Requisitos

Agente versión 1.2.3.4 o superior.

Requisitos adicionales en su propia línea (no use viñetas).

No use ninguna llamada.

Si no hay requisitos especiales, escriba: `Compatible with all agent versions.`

## Descripción

Describa el comportamiento de la llamada con el mayor detalle posible. No describa lo que hacen los parámetros individuales excepto a grandes rasgos; los detalles de los parámetros y las variantes de llamada van debajo del encabezado `Parameters`. Del mismo modo, no describa los valores de retorno.

Al hacer referencia cruzada a otra llamada API, formatee su nombre con bloques de código e incluya paréntesis `()` de esta manera: `anotherCoolMethod()`.

<Callout variant="tip">
  Puede incluir llamadas, pero use discreción. Estas páginas ya están visualmente sobrecargadas.
</Callout>

## Ejemplos

Esta sección documenta las reglas para los casos atípicos que no se documentan por sí mismos. El resto de los ejemplos están integrados en la propia página. En general, esta página está pensada como referencia de estilo. Para ver ejemplos de cómo escribir buenas páginas de métodos de la API, consulte nuestra documentación de la API existente, como la [API de PHP](/docs/agents/php-agent/php-agent-api).

### Directrices de URL

Para la URL del documento:

* Edite manualmente el slug de la URL para eliminar el nombre del agente.
* Donde la llamada API no incluya ya separadores (como en `newrelic_awesome_call`), separe las partes con guiones `-`.

Por ejemplo:

```
https://docs.newrelic.com/docs/new-relic-only/advanced-style-guide/writing-guidelines/api-style-guidelines
```

### Directrices de título

Para el título del documento:

* Incluya el nombre del método y el nombre del agente entre paréntesis.
* No incluya los prefijos `newrelic.` a menos que sean parte integral del nombre de la llamada (como en el agente PHP).
* No incluya paréntesis `()` en la llamada en sí.

Por ejemplo:

```
apiStyleGuidelines (Example agent API)
```

### Directrices de títulos cortos [#short-title-guideliens]

Para el título breve del documento:

* Incluya solo el nombre del método.
* No incluya los prefijos `newrelic.` a menos que sean parte integral del nombre de la llamada (como en el agente PHP).
* No incluya paréntesis `()`.
* Ajuste si es necesario para que quepa en una sola línea en la barra lateral de la categoría.

Por ejemplo:

```
apiStyleGuidelines
```

### Pautas de sintaxis

<Callout variant="important">
  Los agentes de Python e iOS usan sus propias pautas. Para esas pautas, consulte los métodos existentes en esos idiomas.
</Callout>

* Documente cada variante de una llamada en su propia línea.
* No utilice ningún formato excepto la cursiva para el tipo de datos.
* Encierre los parámetros opcionales (incluido el separador de coma) entre corchetes `[]`.
* Indique la parte de la variable anteponiendo un signo de dólar `$`.
* Si la llamada debe tener el prefijo `newrelic.` o similar, inclúyalo en la sintaxis.
* Opcional: incluya el valor de retorno, si eso parece importante para su agente en particular. Si lo hace, siga las convenciones del lenguaje.
