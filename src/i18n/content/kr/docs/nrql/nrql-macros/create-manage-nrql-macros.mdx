매크로를 생성하기 전에 아래의 [매크로 권한](/docs/nrql/nrql-macros/nrql-macros-overview/#macro-permissions)과 명명 및 표현식 규칙을 검토하십시오. 이러한 규칙을 따르지 않는 매크로는 저장하려고 할 때 유효성 검사에 실패합니다.

## 매크로 규칙 및 제한 사항 [#macro-rules]

<Callout variant="important">
매크로는 조직의 모든 사용자에게 표시됩니다. 매크로를 생성하거나 업데이트할 때 민감한 정보나 계정 관련 정보를 포함하지 마십시오.
</Callout>

<CollapserGroup>
<Collapser id="macro-naming-rules" title="이름 지정 규칙">
매크로 이름은 다음 규칙을 따라야 합니다:

* 조직 내에서 고유해야 합니다
* 다음과 같은 음수가 아닌 정수여야 합니다. `3`
* `.` 문자를 포함해서는 안 됩니다
* 500자 이하여야 합니다.
* `$` 문자로 시작해서는 안 됩니다.
* 생성 시 백틱으로 감싸서는 안 됩니다.
* 매크로 이름에 특수 문자가 포함된 경우 백틱으로 묶어야 합니다. 예: `` $`my#Macro` ``.
</Collapser>

<Collapser id="macro-expression-rules" title="표현식 규칙">
매크로 표현식은 다음 규칙을 따라야 합니다:

* 유효한 NRQL 표현식 또는 표현식 목록이어야 합니다
* 3,000자 이하여야 합니다
* 절이 아닌 표현식이어야 합니다. 예를 들어 `count(*)`은(는) 유효하지만, `SELECT count(*)`은(는) 유효하지 않습니다.
* 단독 쿼리가 아니라 괄호로 묶인 하위 쿼리여야 합니다. 예를 들어 `(FROM Transaction SELECT uniques(userId))`은(는) 유효하지만 `FROM Transaction SELECT uniques(userId)`은(는) 유효하지 않습니다.
* 포함하는 속성 목록이 아닌 특정 속성을 반환해야 합니다. `*`

유효한 표현식 예시:

* `count(*)`
* `(1, 2, 3)`
* `(FROM Transaction SELECT uniques(userId))`
</Collapser>

<Collapser id="macro-limitations" title="제한 사항">
NRQL 매크로에는 다음과 같은 제한 사항이 있습니다:

* **알림**: 매크로는 공지 조건에서 지원되지 않습니다.
* **자동 완성**: 쿼리 빌더는 매크로를 제안하거나 매크로 표현식을 사용하여 제안을 구체화하지 않습니다.
* **템플릿 변수**: 매크로 내에서는 템플릿 변수를 사용할 수 없습니다.
* **중첩된 매크로**: 매크로는 중첩할 수 없습니다. 매크로의 표현식은 다른 매크로에 대한 참조를 포함할 수 없습니다.
* **리전별**: 매크로는 특정 리전에 종속되며 조직의 기본 리전 내에서만 사용할 수 있습니다.
* **시간 절**: `TIMESERIES`, `PREDICT`, `BY`, `USING`, `SINCE`, `UNTIL` 및 `COMPARE WITH`을(를) 포함한 시간 관련 절은 매크로를 지원하지 않습니다.
</Collapser>
</CollapserGroup>

## 매크로 액세스 [#macros-access]

뉴렐릭 플랫폼에서 <DNT>**Administration &gt; NRQL Macros**</DNT>(으)로 이동하십시오. 이 페이지에서는 매크로를 조회, 생성, 편집 및 삭제할 수 있습니다.

## 매크로 생성 [#create-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="create-ui">UI</TabsBarItem> <TabsBarItem id="create-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="create-ui">
<DNT>**NRQL Macros**</DNT> 페이지에서 고유한 이름과 표현식을 제공하여 매크로를 생성하십시오. [명명](#macro-naming-rules) 및 [표현식](#macro-expression-rules) 규칙을 따르십시오. 이름 앞에 `$` 문자를 붙이지 마십시오. 예를 들어 `WHERE` 절 조건을 저장하려면 `WHERE` 키워드 없이 `appName = 'ProductionApp' AND environment = 'prod'`을(를) 입력하십시오.

매크로를 생성하면 <DNT>**NRQL Macros**</DNT> 목록에 나타납니다. 뉴렐릭 전체의 모든 NRQL 쿼리에서 사용할 수 있습니다.
</TabsPageItem>

<TabsPageItem id="create-nerdgraph">
[NerdGraph API](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/)를 사용하여 프로그래밍 방식으로 매크로를 생성, 업데이트 및 쿼리할 수도 있습니다. 매크로를 생성하거나 업데이트하기 전에 [명명 규칙](#macro-naming-rules), [표현식 규칙](#macro-expression-rules) 및 [제한 사항](#macro-limitations)을 검토하십시오.

시작하려면 [NerdGraph API 탐색기](https://one.newrelic.com/nerdgraph-graphiql)로 이동하십시오. NerdGraph API 탐색기를 사용하는 데 도움이 필요하면 [NerdGraph API 탐색기 튜토리얼](/docs/apis/nerdgraph/get-started/nerdgraph-explorer/)을 참조하십시오.

`entityManagementCreateNrqlMacro` 뮤테이션을 사용하십시오:

```graphql
mutation CreateMacro($name: String!, $expression: String!, $orgId: ID!) {
  entityManagementCreateNrqlMacro(
    nrqlMacroEntity: {
      expression: $expression
      name: $name
      scope: { type: ORGANIZATION, id: $orgId }
    }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

예제 변수:

```json
{
  "name": "prod_filter",
  "expression": "(appName = 'ProductionApp' AND environment = 'prod')",
  "orgId": "your-organization-id"
}
```

조직 ID를 찾으려면 [조직 또는 매크로 ID 찾기](#find-ids)를 참조하십시오.
</TabsPageItem>
</TabsPages>
</Tabs>

## 쿼리에서 매크로 사용 [#use-macro]

NRQL 쿼리에서 매크로를 사용하려면 쿼리 빌더에서 `$`을(를) 입력한 다음 매크로 이름을 입력하십시오. 예를 들어 표현식이 `appName = 'ProductionApp' AND environment = 'prod'`인 `prod_filter` (이)라는 매크로가 있다고 가정해 보겠습니다. 다음과 같이 쿼리에서 사용할 수 있습니다.

```sql
SELECT count(*) FROM Transaction WHERE $prod_filter SINCE 1 hour ago
```

쿼리가 실행될 때 뉴렐릭은 매크로를 해당 표현식으로 바꿉니다:

```sql
SELECT count(*) FROM Transaction WHERE appName = 'ProductionApp' AND environment = 'prod' SINCE 1 hour ago
```

<Callout variant="tip">
쿼리 시 특수 문자가 포함된 매크로 이름은 백틱으로 묶으십시오. 예: `` $`my#Macro` ``.
</Callout>

<Callout variant="important">
매크로는 실행 전에 인라인 처리되며, 이는 이항 연산자 우선순위에 영향을 미칩니다. 예를 들어, `1 + 4`로 정의되고 `$five * 3`로 사용되는 `five` 이라는 매크로는 표현식이 `1 + 4 * 3`가 되기 때문에 `15`가 아닌 `13`으로 평가됩니다. 이를 방지하려면 매크로를 정의할 때 `(1 + 4)`과 같이 표현식을 괄호로 묶거나, 매크로를 사용할 때 `($five) * 3`과 같이 매크로를 괄호로 묶으십시오. 두 방법 모두 `15`로 올바르게 평가됩니다.
</Callout>

다음 예는 일반적인 쿼리 문제를 해결하는 매크로를 보여줍니다:

<CollapserGroup>
<Collapser id="macro-example-simplify" title="예시: 쿼리 단순화">
이와 같이 여러 조건이 포함된 쿼리는 읽고 유지 관리하기 어려울 수 있습니다:

```sql
SELECT * FROM Log WHERE entityGuid = '...' AND appId NOT IN (...) AND ...
```

`WHERE` 뒤의 조건을 `macro1`(이)라는 이름의 매크로로 저장하면 쿼리가 다음과 같이 단순화됩니다:

```sql
SELECT * FROM Log WHERE $macro1
```
</Collapser>

<Collapser id="macro-example-single-edit" title="예: 한 곳에서 여러 대시보드 위젯 업데이트">
위젯이 많은 Dashboards는 종종 반복되는 쿼리 로직을 공유합니다. 예를 들어, 대시보드의 대부분의 위젯은 다음을 사용할 수 있습니다:

```sql
SELECT count(*) FROM Transaction WHERE http.statusCode NOT IN (400, 404)
```

`WHERE` 조건을 `macro2`(이)라는 이름의 매크로로 저장하면 각 위젯의 쿼리는 다음과 같습니다:

```sql
SELECT count(*) FROM Transaction WHERE $macro2
```

모든 위젯에서 테스트 앱을 제외하려면 `macro2` 표현식을 `http.statusCode NOT IN (400, 404)`에서 `http.statusCode NOT IN (400, 404) AND appId NOT IN (12345)`로 한 번 업데이트하십시오. `$macro2`을 사용하는 모든 위젯에 변경 사항이 반영되므로 각 위젯을 개별적으로 편집할 필요가 없습니다.
</Collapser>

<Collapser id="macro-example-alias" title="예: 속성 별칭 문제 해결">
서로 다른 에이전트의 데이터가 동일한 개념에 대해 항상 동일한 속성 이름을 사용하는 것은 아닙니다. 예를 들어 호스트 이름은 소스에 따라 `host.name`, `hostName` 또는 `host_name`로 수집될 수 있습니다.

다음 표현식을 사용하여 이름이 `host_alias` 인 매크로를 저장하십시오:

```sql
(host.name OR hostName OR host_name)
```

그런 다음 쿼리에서 이를 참조하십시오:

```sql
FROM Log SELECT $host_alias
```

나중에 `host-name`과(와) 같은 다른 별칭이 나타나면 `host_alias` 매크로를 한 번 업데이트하십시오. 그러면 이를 사용하는 모든 쿼리에 변경 사항이 적용됩니다.
</Collapser>
</CollapserGroup>

## 매크로 관리 [#manage-macros]

### 매크로 편집 [#edit-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="edit-ui">UI</TabsBarItem> <TabsBarItem id="edit-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="edit-ui">
<DNT>**NRQL Macros**</DNT> 페이지에서 매크로를 선택하고 [표현식 규칙](#macro-expression-rules)에 따라 표현식을 업데이트하십시오.
</TabsPageItem>

<TabsPageItem id="edit-nerdgraph">
[NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/)를 사용하여 프로그래밍 방식으로 매크로의 표현식을 업데이트할 수도 있습니다. 업데이트하기 전에 [표현식 규칙](#macro-expression-rules)을 검토하십시오.

`entityManagementUpdateNrqlMacro` 돌연변이를 사용합니다.

```graphql
mutation UpdateMacro($expression: String!, $macroId: ID!) {
  entityManagementUpdateNrqlMacro(
    id: $macroId
    nrqlMacroEntity: { expression: $expression }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

예제 변수:

```json
{
  "expression": "(appName = 'ProductionApp' AND environment = 'prod' AND region = 'us-east-1')",
  "macroId": "your-macro-id"
}
```

매크로의 ID를 찾으려면 [조직 또는 매크로 ID 찾기](#find-ids)를 참조하십시오.
</TabsPageItem>
</TabsPages>
</Tabs>

<Callout variant="important">
매크로를 편집하면 해당 매크로를 사용하는 모든 쿼리가 자동으로 업데이트된 버전을 사용합니다. 기존 쿼리가 손상되지 않도록 변경 사항을 검토하십시오. 캐싱으로 인해 업데이트가 적용되기까지 약간의 지연이 발생할 수 있습니다. 생성 후에는 매크로의 이름을 업데이트할 수 없습니다. 이름을 변경해야 하는 경우 매크로를 삭제하고 새 매크로를 생성하십시오.
</Callout>

## 조직 또는 매크로 ID 찾기 [#find-ids]

<CollapserGroup>
<Collapser id="macro-find-org-id" title="조직 ID 찾기">

query MyOrganizationId {
  actor {
    organization {
      id
    }
  }
}

</Collapser>

<Collapser id="macro-find-macro-id" title="모든 매크로 및 해당 ID 나열">
```graphql
query GetMacros($cursor: String) {
  actor {
    entityManagement {
      entitySearch(query: "type = 'NRQL_MACRO'", cursor: $cursor) {
        entities {
          ... on EntityManagementNrqlMacroEntity {
            id
            name
            expression
          }
        }
        nextCursor
      }
    }
  }
}
```
</Collapser>
