뉴렐릭 사용자로서 동일한 NRQL 쿼리를 반복해서 실행하여 중요한 패턴을 모니터링하고, 특정 조건을 확인하거나, 정기적인 보고서를 생성할 수 있습니다. 예를 들어, 실패한 거래를 매일 확인하거나, 매주 모니터링하거나, 전체에 걸쳐 시간별 성능 지표를 추적해야 합니다. 이러한 수동 프로세스는 시간이 많이 걸리고 적극적으로 모니터링하지 않으면 중요한 인사이트를 놓치기 쉽습니다.

예약된 NRQL 검색은 반복적인 쿼리를 자동화하여 이 문제를 해결합니다. 자동으로 실행되도록 쿼리를 예약하고 이메일로 결과를 받을 수 있으므로, 지속적으로 수동으로 모니터링하지 않고도 중요한 패턴에 대한 정보를 얻을 수 있습니다.

## 당신이 할 수 있는 일 [#features]

예약된 NRQL 검색을 사용하면 다음을 수행할 수 있습니다.

* **반복적인 쿼리 흐름 자동화**: 수동 쿼리를 일정에 따라 실행되는 자동화된 쿼리 흐름으로 변환합니다.
* **Start from anywhere**: Create a scheduled search from Administration or directly from the Logs UI.
* **사전에 정보를 받아보세요**: 쿼리 결과가 담긴 공지 이메일을 받은편지함으로 직접 전달됩니다.
* **Set notification conditions**: Choose to get notified on every run, or only when your results meet a condition you define based on the number of results in your query.
* **Schedule flexibly**: Use custom cron expression schedules to define when queries run.
* **Choose your output format**: Export results as CSV or JSON files attached to email notifications.
* **Collaborate with your team**: Send scheduled search results to multiple email recipients.
* **Manage everything centrally**: View, edit, and manage all your scheduled searches from a single location in the Administration UI, regardless of where you created them.

## 가격 [#pricing]

Scheduled NRQL searches have no separate pricing. You pay only the standard query cost of running the underlying NRQL query, based on your account&apos;s pricing model.

## 전제 조건 [#prerequisites]

예약된 NRQL 검색을 사용하려면 다음이 필요합니다.

* **계정 액세스**: 검색을 예약하려는 계정에 액세스합니다.
* **데이터 접근**: 예약하려는 데이터를 쿼리하기 위한 적절한 권한. 예를 들어, 로그 데이터에 대한 쿼리를 예약하는 경우 해당 로그 데이터에 액세스해야 합니다.

### 권한 [#permissions]

By default, the <DNT>**All product admin**</DNT> and <DNT>**Standard user**</DNT> standard roles already include <DNT>**Read**</DNT> and <DNT>**Modify**</DNT> access to scheduled searches, and only <DNT>**All product admin**</DNT> includes <DNT>**Delete**</DNT> access. These roles also already include the <DNT>**User API Keys (for self)**</DNT> &gt; <DNT>**Modify**</DNT> capability (`account.create.own_api_keys`), which a scheduled search needs to run successfully.

If you want to [create a custom role](/docs/accounts/accounts-billing/new-relic-one-user-management/account-user-mgmt-tutorial/#roles) and assign specific <DNT>**Scheduled Search**</DNT> capabilities to it, use either of the following methods:

* **NerdGraph**: [Create an account-scoped custom role via NerdGraph](/docs/apis/nerdgraph/examples/nerdgraph-manage-groups/#account-scoped-role), and add the permission IDs from the following table to the `permissionIds` array.
* **UI**: [Create a new custom role](/docs/accounts/accounts-billing/new-relic-one-user-management/account-user-mgmt-tutorial/#roles), or edit an existing one, to add the <DNT>**Scheduled Search**</DNT> capability from the <DNT>**Scheduled Search and Reports**</DNT> section.

<Callout variant="important">
  Some capabilities grant broader access than others. For example, <DNT>**Delete**</DNT> also grants read and modify access. If you only want to grant a narrower capability, select that specific capability instead of <DNT>**Delete**</DNT>.
</Callout>

## 새로운 검색 일정을 예약하세요 [#create-schedule]

New Relic guides you through this flow directly in the product. Each step below covers what needs to happen there and anything that isn&apos;t obvious from the screen.

<Steps>
  <Step>
    **Access the scheduled search creation flow**:

    Choose the entry point that fits your workflow. Both lead to the same configuration flow.

    <Tabs>
      <TabsBar>
        <TabsBarItem id="from-admin">From Administration</TabsBarItem> <TabsBarItem id="from-logs-ui">From the Logs UI</TabsBarItem>
      </TabsBar>

      <TabsPages>
        <TabsPageItem id="from-admin">
          <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Administration &gt; Scheduled Searches**</DNT> 으로 이동하여 <DNT>**Schedule a search**</DNT> 클릭합니다.
        </TabsPageItem>

        <TabsPageItem id="from-logs-ui">
          From the [logs UI](/docs/logs/ui-data/use-logs-ui/#workflow-search), use either of these options:

          * At the top-right corner, click the <Icon name="fe-more-horizontal" /> menu and select <DNT>**Schedule a search**</DNT>.
          * Under the query trend chart, click the clock icon.

          If you already composed and ran a query, it carries over into the configuration flow. Otherwise, you can draft your query in the next step.
        </TabsPageItem>
      </TabsPages>
    </Tabs>

    <Callout variant="tip">
      You can create a scheduled search from Administration or the Logs UI, but you can only view, edit, or delete existing scheduled searches from <DNT>**Administration &gt; Scheduled Searches**</DNT>.
    </Callout>
  </Step>

  <Step>
    **쿼리를 구성하세요**:

    Draft and test your NRQL query, then continue.
  </Step>

  <Step>
    **설정 공지**:

    Set up the following:

    * Name the search, then set a destination for the results. You can only send results to email destinations.

      * If the destination exists, select it from the list.
      * If it doesn&apos;t exist, add one or more email recipients and name the destination.

    * Choose a subject, message, and output format for the email.

    * Set the notification condition under <DNT>**Send notification**</DNT>. It defaults to <DNT>**Always**</DNT>. To send only when your results meet a count you define, customize it here.

    <Callout variant="caution">
      Scheduled search results are attached to email as CSV or JSON files and may contain sensitive data. Review your email destinations to confirm only intended recipients are included.
    </Callout>
  </Step>

  <Step>
    **일정을 설정하세요**:

    Choose the following:

    * Choose a frequency: hourly, daily, weekly, or a custom cron expression.
    * Select a time zone for the schedule.

    If you use a cron expression, the following are some common patterns for reference:

    * `0 * * * *` - 매시 정각에
    * `0 9 * * *` - 매일 오전 9시
    * `0 9 * * 1` - 매주 월요일 오전 9시
    * `0 0 1 * *` - 매월 1일 자정
    * `*/15 * * * *` - 15분마다
    * `0 9 * * 1-5` - 매주 평일 오전 9시

    <Callout variant="tip">
      The shortest supported interval is every 10 minutes.
    </Callout>

    If you set a notification condition instead of sending on every run, New Relic checks the condition at the exact scheduled run time. It doesn&apos;t track fluctuations between runs, so if your results drop below the condition&apos;s threshold before the next run, you won&apos;t get a notification for that run.
  </Step>

  <Step>
    **Review, confirm, and schedule the search**:

    Review your configuration, then schedule the search. It appears on the <DNT>**Scheduled searches**</DNT> page.
  </Step>
</Steps>

## 예약된 검색 관리 [#manage]

The <DNT>**Scheduled searches**</DNT> page in the Administration UI lists all your automated searches, including any you created from the Logs UI. From the <Icon name="fe-more-horizontal" /> menu, you can view, edit, or delete a search based on your [permissions](#permissions).
