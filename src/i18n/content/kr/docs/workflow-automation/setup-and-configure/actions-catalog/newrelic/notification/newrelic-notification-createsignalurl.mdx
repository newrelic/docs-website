작업 식별자는 `newrelic.notification.createSignalUrl`입니다.

사용자가 실행 중인 워크플로우에 신호를 보낼 수 있도록 <DNT>Microsoft Teams</DNT>, <DNT>Slack</DNT> 또는 <DNT>email</DNT>을(를) 통해 사용자에게 전송할 URL을 생성합니다. 이 작업은 사람이 URL을 클릭하여 실행을 승인, 거부 또는 다른 방식으로 라우팅할 때까지 워크플로우가 대기 단계에서 일시 중지되는 [human-in-the-loop 패턴](/docs/workflow-automation/workflow-examples/advanced/human-in-the-loop)을 지원합니다.

<Callout variant="important">
  이 작업은 단독으로는 아무런 이점을 제공하지 않습니다. 항상 이 작업을 다음과 함께 사용하십시오:

  * 생성된 URL을 사람에게 전달하는 **공지 작업** (`newrelic.notification.*` 또는 `slack.chat.postMessage`)입니다.
  * 워크플로우 실행이 대기할 하나 이상의 신호를 정의하는 **대기 단계** 입니다.

  입력으로 제공하는 `waitStepName` 은(는) 동일한 워크플로우 정의에 있는 유효한 대기 단계의 이름과 일치해야 하며, 해당 대기 단계에는 하나 이상의 신호가 포함되어야 합니다. 그렇지 않으면 워크플로우 정의를 생성할 때 유효성 검사에 실패합니다.
</Callout>

              ```yaml
              steps:
                - name: createApprovalUrls
                  type: action
                  action: newrelic.notification.createSignalUrl
                  version: 1
                  inputs:
                    waitStepName: waitForApproval
                - name: newrelicNotificationMsTeam
                  type: action
                  action: newrelic.notification.sendMicrosoftTeams
                  version: 1
                  inputs:
                    destinationId: acc24dc2-d4fc-4eba-a7b4-b3ad0170f8aa
                    channel: "dev-channel"
                    teamName: "dev-team"
                    message: "To approve continue at: ${{ .steps.createApprovalUrls.outputs.url }}"
                - name: waitForApproval
                  type: wait
                  seconds: 3900 # 1 hour 5 minutes
                  signals:
                    - name: "approve"
                      next: logApproval
                    - name: "deny"
                      next: logDenial
                  next: handleTimeout
              ```
