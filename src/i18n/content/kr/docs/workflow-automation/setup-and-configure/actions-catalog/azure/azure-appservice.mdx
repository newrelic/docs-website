이 페이지는 워크플로우 자동화 액션 카탈로그에서 사용할 수 있는 Azure App Service 액션에 대한 참조를 제공합니다. 이러한 액션을 사용하면 워크플로우 정의에서 직접 Azure App Service 웹 애플리케이션을 가져오고, 나열하고, 시작, 중지 및 재시작할 수 있으며, 비용 제어를 위한 예약된 종료, 인시던트로 트리거되는 재시작, 배포 단계 전 사전 점검과 같은 운영 워크플로우를 활성화할 수 있습니다.

## 전제 조건

워크플로우 자동화에서 Azure App Service 작업을 사용하기 전에 다음이 준비되어 있는지 확인하십시오:

* 하나 이상의 App Service가 포함된 Azure 구독.
* 필수 권한이 있는 Entra(Azure AD) 앱 등록(서비스 주체).
* 뉴렐릭 Secrets Service에 저장된 앱 등록 자격 증명입니다.

## Entra 인증 설정

Azure App Service 작업은 Entra(Azure AD) 서비스 주체 클라이언트 자격 증명 OAuth2 흐름을 사용하여 인증합니다. 필요한 권한은 작업에 따라 다릅니다:

* **Reader** 역할 — `azure.appService.get` 및 `azure.appService.list`에 필요합니다.
* **Contributor** (또는 최소 권한의 경우 **Website Contributor**) — `azure.appService.start`, `azure.appService.stop`, `azure.appService.restart`에 필요합니다.

<Steps>
<Step>
### Entra 앱 등록 생성

1. Azure 포털에서 **Microsoft Entra ID &gt; App registrations**으로 이동하여 **New registration** \[새 등록]을 클릭하십시오.
2. 등록 이름을 지정하고 **Register**를 클릭하십시오.
3. **애플리케이션(클라이언트) ID** 및 **디렉터리(테넌트) ID**를 기록해 두십시오. — 입력 값으로 필요합니다.
4. **Certificates &amp; secrets** (인증서 및 암호) 아래에서 새 클라이언트 암호를 생성하고 값을 즉시 복사하십시오.

전체 지침은 [인증 토큰을 얻기 위한 앱 등록](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/api/register-app-for-token)을 참조하십시오.
</Step>

<Step>
### 필요한 역할 할당

앱 등록에 타겟 App Service 또는 리소스 그룹으로 범위가 지정된 **Reader** 역할(get/list용) 또는 **Contributor** / **Website Contributor** 역할(start/stop/restart용)을 할당하십시오.

1. Azure 포털에서 타겟 리소스 그룹 또는 App Service로 이동하십시오.
2. **Access control (IAM) &gt; Add role assignment**로 이동합니다.
3. 적절한 역할을 선택하여 앱 등록에 할당하십시오.
</Step>

<Step>
### 크리덴셜을 시크릿으로 저장하십시오.

`clientId`, `clientSecret` 및 `tenantId`를 뉴렐릭 Secrets Service에 저장하고 `${{ :secrets:keyName }}` 구문을 사용하여 워크플로우 YAML에서 참조하십시오:

```yaml
clientId: ${{ :secrets:azure-client-id }}
clientSecret: ${{ :secrets:azure-client-secret }}
tenantId: ${{ :secrets:azure-client-tenant }}
```
</Step>
</Steps>
