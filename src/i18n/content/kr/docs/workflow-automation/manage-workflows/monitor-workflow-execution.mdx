이 문서에서는 워크플로우 실행 또는 일정의 실행을 모니터하는 데 사용할 수 있는 다양한 옵저버빌리티 데이터를 설명합니다.

## 감사

모든 NerdGraph 뮤테이션 호출은 감사되며 고객 계정의 `NrAuditEvent` 에서 데이터를 쿼리할 수 있습니다.

### WorkflowRun

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_run'
SINCE 1 hour ago
```

### WorkflowSchedule

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_schedule'
SINCE 1 hour ago
```

## 이벤트

모든 워크플로우 실행은 워크플로우를 시작하거나 예약하는 데 사용된 고객 계정의 NRDB에 `WorkflowAutomationEvent` 데이터를 내보냅니다.

워크플로우 실행의 이벤트 데이터를 위해 새로운 네임스페이스 `WorkflowAutomation` 이(가) 생성됩니다.

```sql
SELECT *

where definitionName = 'json-parsing' and runId = '31c973d2-c669-4bd7-9b15-7e3a70a4a074'
SINCE 1 month ago
```

## 로그

선택적으로 `logLevel` 상세 수준 옵션을 지정하여 워크플로우를 시작하거나 예약할 수 있습니다. 해당 로그는 워크플로우를 시작하거나 예약하는 데 사용된 워크플로우 계정에 추가됩니다.

로그에는 다음과 같은 속성이 부여됩니다:

* `workflowAutomation.name` WorkflowDefinition 이름입니다
* `workflowAutomation.version` WorkflowDefinition 버전입니다
* `workflowAutomation.runId` 워크플로우 runId입니다
* `entityGuid` WorkflowDefinition ID입니다

일정 발생에서 시작된 경우:

* `workflowAutomation.scheduleId`

Action 단계 유형의 경우, `DEBUG` 을(를) 사용할 때 각 액션 입력은 `workflowAutomation.inputs.<inputName>: <inputValue>` 형식으로 로그 항목에 추가 속성을 추가합니다.

작업 단계 유형의 경우, `TRACE` 을(를) 사용할 때 각 작업 출력은 `workflowAutomation.outputs.<outputName>: <outputValue>` 형식으로 로그 항목에 추가 속성을 추가합니다.

### NRQL 쿼리 예

다음 NRQL 쿼리로 로그를 쿼리할 수 있습니다:

```sql
SELECT message FROM Log WHERE workflowAutomation.runId = '{run_id}' SINCE 3 hours ago
```

<img title="Diagram of log attributes for workflow runs" alt="Diagram of log attributes for workflow runs" src="/images/log_attributes.webp" />

`workflowAutomation.runId` 외에도 로그 데이터 쿼리에 도움이 될 수 있는 다른 몇 가지 로그 속성은 다음과 같습니다.

* `workflowAutomation.name`
* `workflowAutomation.version`

예약된 실행의 경우 로그 항목에 `workflowAutomation.scheduleId` 속성도 포함됩니다.
