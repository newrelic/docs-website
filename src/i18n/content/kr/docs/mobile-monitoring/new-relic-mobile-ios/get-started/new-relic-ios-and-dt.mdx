당사의 iOS 에이전트는 분산 추적을 지원합니다. 이를 통해 모바일 앱 활동이 관련 서비스에 어떻게 연결되는지 확인할 수 있습니다.

## 요구 사항 [#requirements]

분산 추적을 사용하려면 iOS 에이전트 버전 7.3.0 이상이 필요합니다. 최신 에이전트를 사용하는 것이 좋습니다.

## 분산 추적을 설정하는 방법 [#setup]

분산 추적은 기본적으로 활성화되어 있으므로 이를 켜기 위해 별도의 작업을 수행할 필요가 없습니다.

이 기능을 끄려면 모바일 SDK API 가이드의 [분산 추적](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#ios-dt)을 참조하거나 아래의 [분산 추적 비활성화](#disable)를 확인해 주십시오.

분산 추적 헤더는 다른 설정과 관계없이 모든 계측된 요청에 전송됩니다. 하지만 트레이스를 보고된 `MobileRequest` 이벤트와 연결하여 UI에서 앱의 네트워크 활동과 연관되어 표시되게 하려면, [Network Request Events](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#ios-networking)도 활성화해야 합니다. 이 기능은 기본적으로 켜져 있으므로 명시적으로 끈 경우에만 영향을 미칩니다.

## 분산 추적 헤더 [#headers]

iOS 에이전트 버전 7.7.8부터 에이전트는 발신 네트워크 requests에 [W3C Trace Context](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers) 헤더인 `traceparent` 및 `tracestate`만 추가합니다. 더 이상 독점 `newrelic` 헤더를 전송하지 않습니다. 이전 에이전트 버전은 세 가지 헤더를 모두 전송합니다.

W3C Trace Context를 지원하는 뉴렐릭 APM 에이전트는 트레이스를 계속하기 위해 이 헤더를 사용하므로, 앱의 requests가 호출하는 백앤드 서비스에 계속 연결된 상태를 유지합니다. W3C Trace Context는 다음 APM 에이전트 버전 이상에서 지원됩니다:

## 자동으로 분산 추적이 적용되는 requests [#automatic-instrumentation]

에이전트가 `NSURLSession` 및 `NSURLConnection`을(를) 자동으로 계측하므로, 추가 설정 없이 둘 중 하나를 통해 이루어진 requests에 분산 추적 헤더가 추가됩니다.

<Callout variant="important">
앱에서 스위프트의 `async`/`await` `URLSession` API(예: `data(for:)` 또는 `data(from:)`)를 사용하는 경우, 해당 API는 기본 계측에 포함되지 **않습니다**. `NRFeatureFlag_SwiftAsyncURLSessionSupport` (에이전트 버전 7.4.5부터 기본적으로 비활성화됨)를 명시적으로 활성화해야 합니다. 그래야 에이전트가 해당 호출에 분산 추적 헤더를 추가할 수 있습니다:

에이전트는 다음에 분산 추적 헤더를 자동으로 추가하지 않습니다:

* `WKWebView`. `WKWebView`에 로드된 웹 콘텐츠는 앱의 `NSURLSession`/`NSURLConnection` 계측 범위 밖의 WebKit 프로세스 내에서 네트워크 requests를 수행하므로, 해당 requests는 자동으로 트레이스되지 않습니다. (기본적으로 활성화된 에이전트의 별도 `WKWebView` 계측은 네트워크 헤더가 아닌 페이지 로드 타이밍만 다룹니다.)
* `NSURLSession` 또는 `NSURLConnection`을(를) 통해 라우팅되지 않는 서드파티 네트워킹 라이브러리입니다.
* WebSockets.
* gRPC 또는 기타 사용자 지정 전송.

이러한 경우에는 수동 전파를 사용하십시오.

## 수동으로 분산 추적 전파 [#manual]

API를 통해 요청을 하는 경우, 에이전트는 자동으로 계측하지 않습니다. 그래도 분산 추적 헤더를 추가하고 요청을 수동으로 보고할 수 있습니다.

**다른 항목에서 요청을 보고하는 경우**

일부 프레임워크(예: 하이브리드 프레임워크에서 사용하는 네이티브 네트워킹 라이브러리)는 요청을 전송하고 이를 뉴렐릭에 별도로 보고합니다. 이 경우 직접 헤더를 생성하고 첨부하십시오. 요청을 보고하는 항목은 무엇이든 W3C 헤더에서 트레이스 식별자를 복구합니다.

**요청을 보내고 보고하는 경우**

동일한 코드가 요청을 전송하고 이를 뉴렐릭에 보고하는 경우(예: 크로스 플랫폼 에이전트), 대신 `generateDistributedTracingContext`을(를) 사용하십시오. 요청에 설정할 W3C 헤더(`traceparent`, `tracestate`)와 요청을 보고할 때 다시 전달할 트레이스의 식별자(`trace.id`, `id`, `guid`)가 포함된 하나의 딕셔너리를 반환하므로, 보고된 이벤트는 새로운 트레이스가 아닌 해당 트레이스의 속성으로 귀속됩니다.

완료된 요청을 보고할 때 동일한 딕셔너리를 [`noticeNetworkRequestForURL:`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-success/) 또는 [`noticeNetworkFailureForURL:`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-failures/) (iOS 탭 선택)의 `traceHeaders` 파라미터로 전달하십시오. 전체 파라미터 참조는 해당 페이지를 확인해 주십시오.

## 무한 추적 활성화 [#infinite-tracing]

모바일 앱에 [Infinite Tracing](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing) 이라는 꼬리 기반 분산 추적을 사용하는 일부 다운스트림 서비스가 있는 경우 모바일 앱에 대해 이 기능을 활성화해야 합니다.이렇게 하면 루트 범위(시작 모바일 앱)가 Infinite Tracing에서 추적하는 나머지 범위에 포함됩니다.

이를 설정하려면 추적 관찰자를 만들고 범위를 보고해야 하는 모바일 앱(데이터 원본)을 선택하는 [무한 추적 단계](/docs/distributed-tracing/infinite-tracing/set-trace-observer) 를 참조하세요.

## 데이터 찾기 [#find-data]

모바일 스팬은 해당 스팬이 추적의 일부인 [New Relic 분산 추적 UI](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) 에 나타납니다.

다음은 데이터를 찾고 쿼리하기 위한 몇 가지 팁입니다.

* [New Relic 분산 추적 UI](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one) 에서 최종 사용자 시작 추적을 찾을 수 있습니다.
* 분산 추적 UI에서 최종 사용자 스팬은 다음 아이콘으로 표시됩니다.<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}} />아이콘입니다.
* 스팬의 속성을 보려면 [UI에서 스팬을](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details) 선택하세요.
* 스팬은 [스팬 데이터](/attribute-dictionary/?event=Span) 로 보고되며 [New Relic에서 쿼리](/docs/using-new-relic/data/understand-data/query-new-relic-data) 할 수 있습니다.

예를 들어 특정 앱의 모바일 스팬을 찾으려면 다음과 같이 하십시오:

```sql
SELECT count(*) FROM Span WHERE mobileApp.name = 'YOUR_APP_NAME' SINCE 1 day ago
```

모바일 스팬을 백앤드 APM 스팬에 연결하는 트레이스를 찾으려면:

```sql
SELECT * FROM Span WHERE mobileApp.name IS NOT NULL AND appName IS NOT NULL SINCE 1 day ago
```

## 문제점 해결 [#troubleshooting]

예상한 위치에서 모바일 스팬이 표시되지 않는 경우 다음의 가능한 원인을 확인해 주십시오:

* **분산 추적이 비활성화되었습니다.** `NRFeatureFlag_DistributedTracing`을(를) 사용하여 `disableFeatures`을(를) 호출하지 않았는지 확인하십시오. [분산 추적 설정 방법](#setup)을 참조하십시오.
* **request가 자동으로 계측되지 않았습니다.** `NSURLSession` 또는 `NSURLConnection` 이외의 방식을 통해 이루어진 요청(스위프트 `async`/`await` `URLSession` 호출 포함)은 `NRFeatureFlag_SwiftAsyncURLSessionSupport`을(를) 활성화하거나 [수동 전파](#manual)를 해야 합니다. [자동으로 분산 추적이 적용되는 requests](#automatic-instrumentation)를 참조하십시오.
* **백앤드 APM 에이전트가 너무 오래되었습니다.** 수신 서비스의 APM 에이전트가 아직 W3C Trace Context를 지원하지 않는 경우 앱의 트레이스에 연결하는 대신 새로운 트레이스를 시작합니다. [최소 APM 에이전트 버전](#headers)을 확인하십시오.
* **프록시 또는 게이트웨이가 헤더를 제거합니다.** 앱과 백앤드 사이에 있는 모든 요소는 `traceparent` 및 `tracestate`을(를) 수정 없이 통과시켜야 합니다.
* **신뢰할 수 있는 계정 키가 일치하지 않아 `tracestate`이(가) 삭제되었습니다.** 백앤드 서비스가 모바일 앱과 다른 뉴렐릭 계정에 속해 있는 경우, 해당 계정이 동일한 신뢰 관계에 있는지 확인하십시오. 그렇지 않으면 `tracestate` 항목이 무시될 수 있습니다.

더 광범위한 분산 추적 문제에 대해서는 [문제 진단, 해결](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data)을 참조하십시오.
