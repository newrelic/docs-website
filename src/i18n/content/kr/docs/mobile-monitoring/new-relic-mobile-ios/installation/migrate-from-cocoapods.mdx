CocoaPods는 자사의 중앙 레지스트리(트렁크)가 [2026년 12월 2일에 영구적으로 읽기 전용으로 전환된다고](https://blog.cocoapods.org/CocoaPods-Specs-Repo/) 발표했습니다. 해당 날짜 이후부터 CocoaPods는 새로운 파드 버전을 수락하지 않습니다. 이 페이지는 뉴렐릭 iOS 에이전트 및 이를 기반으로 구축된 하이브리드 에이전트에 이것이 무엇을 의미하는지, 그리고 앱을 다른 설치 방법으로 이동하는 방법을 설명합니다.

## 마이그레이션하기 전에 [#before-you-migrate]

마이그레이션하기 전에 다음 답변을 검토해 주십시오:

* <DNT>**What&apos;s changing?**</DNT> 버전 **7.7.10**은 당사가 CocoaPods(`NewRelicAgent` 파드)에 게시하는 마지막 iOS 에이전트입니다. 이후 버전은 [스위프트 패키지 매니저](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation) 및 [XCFramework 다운로드](/docs/mobile-monitoring/new-relic-mobile-ios/installation/xcframework-installation)를 통해서만 사용할 수 있습니다.
* <DNT>**Will my app break?**</DNT> 아닙니다. 이미 게시된 모든 `NewRelicAgent` 버전은 CocoaPods에 유지되므로 `pod install` 및 CI 파이프라인이 계속 작동합니다. 단지 CocoaPods를 통해 최신 에이전트 버전을 받을 수 없을 뿐입니다.
* <DNT>**Why migrate?**</DNT> 새로운 기능, 수정 사항 및 새로운 iOS와 Xcode 버전에 대한 지원을 계속 받으려면 스위프트 패키지 매니저 또는 XCFramework로 전환하십시오.

이 변경 사항은 CocoaPods를 통해 iOS 에이전트를 가져오는 하이브리드 에이전트에도 영향을 미칩니다. 리액트 네이티브, 플러터, Ionic Capacitor, 코도바 또는 Unity를 사용하는 경우 [하이브리드 에이전트를 사용하는 앱 마이그레이션](#hybrid)을 참조하십시오.

## iOS 앱 마이그레이션 [#ios]

다음 설치 방법 중 하나를 선택해 주십시오:

* [스위프트 패키지 매니저](#spm): Xcode에 내장된 Apple의 패키지 매니저입니다. Xcode에서 에이전트를 업데이트합니다.
* [XCFramework](#xcframework): 직접 다운로드하여 프로젝트에 추가하는 프레임워크 번들입니다. 새 버전을 다운로드하여 업데이트합니다.

iOS 에이전트는 다른 패키지에 의존하지 않으므로, 현재 다른 종속성 중 일부가 CocoaPods에 남아 있더라도 스위프트 패키지 매니저로 이동할 수 있습니다. 모든 종속성을 CocoaPods에서 이동할 계획이라면, 먼저 각각의 종속성이 스위프트 패키지 매니저를 지원하는지 확인하십시오. 그렇지 않은 종속성의 경우, XCFramework 방법을 사용하면 패키지 매니저와 독립적으로 에이전트를 추가하고 업데이트할 수 있습니다.

<Callout variant="important">
단 하나의 방법으로만 에이전트를 설치하십시오. 다른 방법으로 에이전트를 추가할 때 `NewRelicAgent` 파드가 여전히 설치되어 있으면, 앱에 두 개의 에이전트 사본이 남게 되어 빌드 오류나 예측할 수 없는 동작이 발생합니다.
</Callout>

### 스위프트 패키지 관리자 [#spm]

<Steps>
<Step>
현재 사용 중인 에이전트 버전을 확인하십시오. `Podfile.lock`의 `NewRelicAgent` 옆에 표시되어 있습니다.
</Step>

<Step>
Xcode를 닫은 다음, `NewRelicAgent` 파드를 제거하십시오:

* `NewRelicAgent`이(가) 유일한 파드인 경우, 프로젝트 디렉터리에서 이 명령을 실행한 다음 CocoaPods가 생성한 `Podfile`, `Podfile.lock` 및 `.xcworkspace` 파일을 삭제하십시오:

  ```shell
  pod deintegrate
  ```

* 여전히 다른 파드를 사용하는 경우, `Podfile`에서 `pod 'NewRelicAgent'` 줄을 삭제한 후 다음을 실행하십시오:

  ```shell
  pod install
  ```

  `Podfile.lock`에 `NewRelicAgent`이(가) 더 이상 나타나지 않는지 확인하십시오.
</Step>

<Step>
Xcode에서 프로젝트를 엽니다. 여전히 다른 파드를 사용하는 경우, `.xcworkspace` 파일을 엽니다. 그렇지 않은 경우, `.xcodeproj` 파일을 엽니다.
</Step>

<Step>
<DNT>**File &gt; Add Package Dependencies...**</DNT>을(를) 선택하고 다음 URL을 입력하십시오:

```
https://github.com/newrelic/newrelic-ios-agent-spm
```

종속성 규칙의 경우, 첫 번째 단계에서 기록한 버전 또는 그 이상의 버전부터 시작하여 <DNT>**Up to Next Major Version**</DNT>을(를) 선택하십시오.
</Step>

<Step>
<DNT>**NewRelic**</DNT> 패키지 제품을 앱 타겟에 추가하고, 앱 확장 프로그램과 같이 파드를 사용한 다른 모든 타겟에도 추가하십시오.
</Step>

<Step>
타겟의 <DNT>**Build Phases**</DNT>에서 dSYM 업로드 빌드 스크립트를 확인하십시오:

* iOS 에이전트 7.4.0 이상용 스크립트(`run-symbol-tool`을(를) 검색함)인 경우 그대로 유지하십시오. 스위프트 패키지에서 도구를 찾습니다.
* `newrelic_postbuild.sh`을(를) 호출하거나 `Pods/` 내부의 경로를 사용하는 경우, [스위프트 패키지 매니저 설치](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation)의 7.4.0 이상 스크립트로 교체하십시오.

스크립트를 마지막 빌드 단계로 유지하고, <DNT>**Based on dependency analysis**</DNT>이(가) 선택 해제되어 있는지 확인하십시오.
</Step>

<Step>
앱을 정리하고 빌드한 다음 실행하십시오. 에이전트를 시작하는 코드와 애플리케이션 토큰은 변경되지 않습니다.
</Step>
</Steps>

나중에 에이전트를 업데이트하려면 [스위프트 패키지 매니저로 업데이트](/docs/mobile-monitoring/new-relic-mobile-ios/installation/upgrade-ios-agent#SPM)를 참조하십시오.

### XCFramework [#xcframework]

<Steps>
<Step>
[스위프트 패키지 매니저 단계](#spm)에 설명된 대로 Xcode를 닫고 `NewRelicAgent` 파드를 제거하십시오.
</Step>

<Step>
[XCFramework 수동 설치](/docs/mobile-monitoring/new-relic-mobile-ios/installation/xcframework-installation)를 따라 에이전트를 다운로드하고 앱 타겟에 추가하십시오. `NewRelic.xcframework`이(가) <DNT>**Embed &amp; Sign**</DNT>(으)로 설정되어 있는지 확인하십시오.
</Step>

<Step>
[스위프트 패키지 매니저 단계](#spm)에 설명된 대로 dSYM 업로드 빌드 스크립트를 확인합니다. 7.4.0 이상 스크립트는 `NewRelic.xcframework` 내에서 `run-symbol-tool`을(를) 찾습니다.
</Step>

<Step>
앱을 정리하고 빌드한 다음 실행하십시오. 에이전트를 시작하는 코드와 애플리케이션 토큰은 변경되지 않습니다.
</Step>
</Steps>

나중에 에이전트를 업데이트하려면 [iOS 에이전트를 수동으로 교체하기](/docs/mobile-monitoring/new-relic-mobile-ios/installation/upgrade-ios-agent#Manual)를 참조하십시오.

### CI/CD 파이프라인을 업데이트하십시오. [#ci]

CocoaPods를 완전히 제거한 경우, `pod install`을(를) 실행하거나 `.xcworkspace` 파일을 빌드하는 모든 파이프라인 단계를 업데이트하십시오. 스위프트 패키지 매니저를 사용하는 경우, 빌드 전 별도의 단계에서 패키지를 해결하는 것을 고려해 보십시오:

```shell
xcodebuild -resolvePackageDependencies -project YourApp.xcodeproj -scheme YourApp
```

### 네이티브 반응 [#react-native]

기본적으로 리액트 네이티브 에이전트는 CocoaPods에서 iOS 에이전트를 가져옵니다. 리액트 네이티브 에이전트 1.9.3 이상에서는 스위프트 패키지 매니저로 전환할 수 있습니다.

#### 표준 리액트 네이티브 앱

전환하기 전에 앱이 다음 요구 사항을 충족하는지 확인하십시오:

* 리액트 네이티브 0.75 이상
* `use_frameworks! :linkage => :dynamic` 사용자의 `Podfile`
* 표준 리액트 네이티브 템플릿과 같이 `react_native_post_install`을(를) 호출하는 `Podfile`의 `post_install` 블록

전환하려면 다음 단계를 따르십시오:

1. 리액트 네이티브 에이전트를 버전 1.9.3 이상으로 업데이트하십시오.

2. `ios/Podfile`의 맨 위에 다음을 추가하십시오:

   ```ruby
   ENV['NEWRELIC_USE_SPM'] = '1'
   use_frameworks! :linkage => :dynamic
   ```

3. `ios` 디렉터리에서 `pod install`을(를) 실행한 다음, `Podfile.lock`에 `NewRelicAgent`이(가) 더 이상 표시되지 않는지 확인합니다.

4. 앱을 빌드하고 실행합니다.

#### Expo 앱

`npx expo prebuild` `ios` 폴더를 다시 생성하므로, `Podfile` 대신 프로젝트 설정에서 이를 설정하십시오. Expo SDK 52 이상이 필요합니다.

전환하려면 다음 단계를 따르십시오:

1. 리액트 네이티브 에이전트를 버전 1.9.3 이상으로 업데이트하십시오.

2. `expo-build-properties` 설치:

   ```shell
   npx expo install expo-build-properties
   ```

3. `app.json` 또는 `app.config.js`에서 동적 프레임워크를 사용하도록 iOS를 설정하십시오:

   ```json
   "plugins": [
     "newrelic-react-native-agent",
     ["expo-build-properties", { "ios": { "useFrameworks": "dynamic" } }]
   ]
   ```

4. 프로젝트의 루트 디렉터리에 있는 `.env` 파일에 `NEWRELIC_USE_SPM=1`을(를) 추가해 주십시오. `npx expo prebuild` 및 `npx expo run:ios`이(가) 이를 로드합니다.

5. `npx expo prebuild --clean`을(를) 실행한 다음, `ios/Podfile.lock`에 `NewRelicAgent`이(가) 더 이상 나타나지 않는지 확인하십시오.

CocoaPods가 실행될 때 `NEWRELIC_USE_SPM`이(가) 설정되지 않은 경우(예를 들어 `pod install` 또는 `npx pod-install`을(를) 직접 실행할 때), 앱은 CocoaPods에서 iOS 에이전트를 가져오는 것으로 돌아갑니다.

### 실룩 거리다 [#flutter]

플러터 에이전트는 CocoaPods와 스위프트 패키지 매니저를 모두 지원하며, 플러터가 어느 것을 사용할지 결정합니다. 플러터 3.44부터 [스위프트 패키지 매니저가 기본적으로 활성화되어 있으므로](https://docs.flutter.dev/packages-and-plugins/swift-package-manager/for-app-developers), 대부분의 앱은 이미 이를 통해 iOS 에이전트를 가져옵니다.

스위프트 패키지 매니저를 비활성화한 경우 다음을 실행하여 다시 켜십시오:

```shell
flutter config --enable-swift-package-manager
```

`enable-swift-package-manager: false`을(를) 추가한 경우 `pubspec.yaml` 에서도 제거합니다.

### Ionic Capacitor [#capacitor]

Capacitor 에이전트는 CocoaPods와 스위프트 패키지 매니저를 모두 지원하며, iOS 프로젝트에서 사용할 패키지 매니저를 결정합니다. Capacitor 8은 스위프트 패키지 매니저를 사용하여 새 iOS 프로젝트를 생성하지만, CocoaPods로 생성된 프로젝트는 마이그레이션할 때까지 계속 CocoaPods를 사용합니다.

* `ios/App` 폴더에 `CapApp-SPM` 패키지가 있는 경우 이미 스위프트 패키지 매니저를 사용하고 있는 것입니다. `npx cap sync`은(는) 에이전트를 최신 상태로 유지합니다.
* `Podfile`이(가) 있는 경우 [Capacitor의 스위프트 패키지 매니저 가이드](https://capacitorjs.com/docs/ios/spm)를 따라 프로젝트를 스위프트 패키지 매니저로 이동하십시오. `npx cap spm-migration-assistant` 명령과 iOS 플랫폼 재생성을 다룹니다.

### 코르도바 [#cordova]

`cordova-ios` 8 이상에서는 코도바 에이전트가 스위프트 패키지 매니저를 통해 iOS 에이전트를 가져옵니다. 이전 `cordova-ios` 버전은 CocoaPods를 사용합니다.

마이그레이션하려면 다음 단계를 따르십시오:

1. 코도바 에이전트를 최신 버전으로 업데이트하십시오.

2. iOS 플랫폼을 업데이트해 주십시오. [cordova-ios 8 릴리스 공지](https://cordova.apache.org/announcements/2025/11/23/cordova-ios-8.0.0.html)를 참조해 주십시오:

   ```shell
   cordova platform remove ios
   cordova platform add ios@8
   ```

   플랫폼을 제거하면 `platforms/ios` 폴더가 삭제되므로 수동으로 변경한 내용이 모두 손실됩니다. 먼저 백업하십시오.

3. `config.xml`이(가) iOS 배포 타겟을 15.0 이상으로 설정했는지 확인해 주십시오:

   ```xml
   <preference name="deployment-target" value="15.0" />
   ```

4. 앱을 빌드하고 실행합니다.

### 단일성 [#unity]

Unity 에이전트는 Unity용 외부 의존성 매니저(EDM4U)를 사용하여 CocoaPods를 통해 iOS 에이전트를 가져옵니다. 스위프트 패키지 매니저를 지원하지 않습니다. 앱은 이미 CocoaPods에 있는 버전으로 계속 빌드되며, 새로운 Unity 에이전트 버전은 iOS 에이전트 **7.7.10**을 유지합니다.

최신 iOS 에이전트 버전을 사용하려면 Unity 에이전트의 [종속성 단계](/docs/mobile-monitoring/new-relic-mobile-unity/monitor-your-unity-application#manage-dependencies)에 설명된 대로 XCFramework를 Xcode 프로젝트에 직접 추가하십시오. 앱에 에이전트 복사본이 하나만 있도록 EDM4U가 `NewRelicAgent` 파드도 설치하지 않는지 확인해 주십시오.

## 문제 해결 [#troubleshooting]

<CollapserGroup>
<Collapser id="no-such-module" title="스위프트 패키 매니저로 마이그레이션한 후 'No such module NewRelic' 오류와 함께 빌드가 실패합니다">
빌드에 실패한 타겟에 <DNT>**NewRelic**</DNT> 패키지 제품이 추가되었는지 확인하십시오. 타겟의 설정에서 <DNT>**Frameworks, Libraries, and Embedded Content**</DNT> 섹션을 확인하십시오. 프로젝트에 여러 타겟이 있는 경우 에이전트를 사용하는 각 타겟에 제품을 추가하십시오.
</Collapser>

<Collapser id="library-not-loaded" title="출시 시 'Library not loaded: @rpath/NewRelic.framework/NewRelic' 메시지와 함께 앱이 충돌합니다.">
에이전트가 앱에 연결되어 있지만 포함되어 있지 않습니다:

* 스위프트 패키지 매니저: <DNT>**NewRelic**</DNT> 패키지 제품을 프레임워크나 익스텐션 타겟뿐만 아니라 앱 타겟 자체에 추가하십시오.
* XCFramework: 앱 타겟의 <DNT>**Frameworks, Libraries, and Embedded Content**</DNT> 섹션에서 `NewRelic.xcframework`을(를) <DNT>**Embed &amp; Sign**</DNT>(으)로 설정합니다.

하이브리드 에이전트를 사용하는 경우, [하이브리드 에이전트를 사용하는 앱 마이그레이션](#hybrid)에서 해당 에이전트에 대한 단계를 참조하십시오.
</Collapser>

<Collapser id="duplicate" title="중복 기호 오류 또는 클래스가 두 번 구현되었다는 경고가 발생합니다">
앱에 에이전트의 복사본이 두 개 있습니다. `Podfile.lock`에 `NewRelicAgent`이(가) 더 이상 나타나지 않는지, 그리고 한 가지 방법으로만 에이전트를 추가했는지 확인하십시오.
</Collapser>

<Collapser id="checksum" title="스위프트 패키지 매니저가 체크섬 또는 다운로드 오류를 보고합니다">
[스위프트 패키지 매니저 문제 진단, 해결 단계](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation#troubleshooting)를 참조하십시오.
</Collapser>
</CollapserGroup>
