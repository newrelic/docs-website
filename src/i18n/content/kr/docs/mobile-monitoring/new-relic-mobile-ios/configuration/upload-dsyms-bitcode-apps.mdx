Xcode는 앱의 dSYM 파일을 dSYM 아카이브 경로 폴더에 저장합니다. 이 폴더는 iOS 에이전트가 크래시 리포트를 심볼화하는 데 사용하는 dSYM 파일을 가져오는 폴더입니다. 뉴렐릭은 [iOS 에이전트 설치 프로세스](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation/#configure-using-swift-package-manager)의 일부로 빌드 후 스크립트를 제공합니다. 이 스크립트는 자동으로 dSYM을 뉴렐릭 맵 파일 형식으로 변환하고 크래시 심볼화에 필요한 파일을 뉴렐릭에 업로드합니다.

## 자동 스크립트 [#Automatic]

iOS 에이전트에는 Xcode의 Run Script \[스크립트 실행] 빌드 단계에서 실행하는 셸 스크립트인 `run-symbol-tool`이(가) 포함되어 있습니다. 각 빌드 후 백그라운드에서 `run-symbol-tool.swift`을(를) 실행하며, 이는 dSYM 파일을 뉴렐릭 맵 파일 형식으로 변환하여 뉴렐릭에 업로드합니다.

Xcode 14에서 Apple은 새로 생성된 프로젝트의 기본 설정을 변경하여 비트코드를 비활성화했습니다. App Store는 이제 비트코드가 꺼져 있는 앱 제출만 수락합니다. [Xcode 14 릴리스 정보](https://developer.apple.com/documentation/xcode-release-notes/xcode-14-release-notes) 를 참조하십시오. 프로젝트에 여전히 비트코드가 활성화되어 있으면 비활성화해야 합니다. 자동 스크립트를 사용하려면 비트코드를 비활성화해야 합니다.

Apple은 Bitcode 지원 앱용 dSYM 파일을 생성합니다. [Apple에서 Bitcode 지원 앱용 dSYM 파일을 다운로드](/docs/mobile-monitoring/new-relic-mobile-ios/install-configure/retrieve-upload-dsyms-bitcode-enabled-apps) 하고 [모바일 모니터링 UI](#mobile-ui) 를 통해 New Relic에 업로드해야 합니다.

[<DNT>**Crashes**</DNT> 페이지](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-apps-crashes-dashboard) 에 읽을 수 없는 기계어 코드가 있으면 dSYM 파일이 올바르게 업로드되지 않은 것일 수 있습니다. 경우에 따라 [dSYM 파일을 수동으로 업로드](#manual-dsym) 해야 할 수도 있습니다.

<Callout variant="important">
iOS 에이전트 버전 7.4.8 파이썬 업로드 스크립트(`generateMap.py`, `generateMapPython2.py` 및 `newrelic_postbuild.sh`)를 제거했습니다. Run Script \[스크립트 실행] 빌드 단계에서 여전히 `newrelic_postbuild.sh`을(를) 호출하는 경우, 아래의 `run-symbol-tool` 스크립트로 교체하십시오.
</Callout>

### Run Script \[스크립트 실행] 빌드 단계를 추가하십시오. [#run-script]

1. Xcode의 navigator \[내비게이터]에서 프로젝트를 선택한 다음, 앱 타겟을 선택하십시오.

2. <DNT>**Build Phases**</DNT> 탭을 선택합니다.

3. <DNT>**+**</DNT>을(를) 클릭하고 <DNT>**New Run Script Phase**</DNT>을(를) 선택합니다.

4. 새로운 단계에 다음 줄을 추가해 주십시오. `APP_TOKEN`을(를) 뉴렐릭의 애플리케이션 토큰으로 교체해 주십시오.

   ```shell
   ARTIFACT_DIR="${BUILD_DIR%Build/*}"
   SCRIPT=`/usr/bin/find "${SRCROOT}" "${ARTIFACT_DIR}" -type f -name run-symbol-tool | head -n 1`
   /bin/sh "${SCRIPT}" "APP_TOKEN"
   ```

스크립트가 dSYM 파일을 읽고 로그를 작성할 수 있도록 Xcode 15.3 이상에서 <DNT>**User Script Sandboxing**</DNT>을(를) <DNT>**No**</DNT> (으)로 설정하십시오. [자동 dSYM 업로드 실패](/docs/mobile-monitoring/new-relic-mobile-ios/troubleshoot/dSYM-upload-tools)를 참조하십시오.

### 앱 버전 [#app-version]

뉴렐릭은 앱 버전에 따라 업로드된 심볼을 빌드와 일치시킵니다. 스크립트는 이 목록에서 비어 있지 않은 첫 번째 값을 사용합니다.

1. `-appVersion` 인수
2. `NEWRELIC_APP_VERSION` 환경 변수
3. `MARKETING_VERSION` 빌드 설정
4. 플레이스홀더 `1.2.3`

스크립트가 플레이스홀더를 사용할 때 `upload_dsym_results.log`에 경고를 로그로 기록합니다.

`agvtool`로 버전이 지정된 앱이나 `GENERATE_INFOPLIST_FILE = YES`를 사용하는 다중 타겟 앱과 같은 일부 프로젝트는 `MARKETING_VERSION`을 설정하지 않습니다. 이러한 프로젝트의 경우 심볼이 빌드와 일치하도록 `-appVersion`을 전달하거나 `NEWRELIC_APP_VERSION`를 설정하십시오.

### 스크립트 작동 방식 [#how-it-works]

실행 시 스크립트는 다음을 수행합니다.

* 업로드는 백그라운드에서 실행되므로 빌드는 업로드가 완료될 때까지 기다리지 않습니다. 스크립트는 [`upload_dsym_results.log`](#auto-upload-fail-troubleshooting)에 결과를 기록합니다.
* 스크립트는 iOS 시뮬레이터 빌드를 건너뜁니다(`EFFECTIVE_PLATFORM_NAME`은(는) `-iphonesimulator`입니다).
* 비트코드가 활성화된 빌드(`ENABLE_BITCODE = YES`)는 업로드하지 않고 빌드 실패 없이 종료됩니다.
* 스크립트는 `DWARF_DSYM_FOLDER_PATH`의 각 dSYM을 맵 파일로 변환하고 맵 파일을 압축한 다음, 압축 파일을 `/map` 엔드포인트에 업로드합니다.
* dSYM을 변환할 수 없는 경우, 스크립트는 해당 dSYM을 압축하여 대신 `/symbol` 엔드포인트에 업로드합니다. 맵 업로드 자체가 실패하면, 스크립트는 HTTP 상태 코드를 로그에 기록하고 dSYM 업로드로 대체하지 않습니다. 이 경우 [dSYM을 수동으로 업로드](#manual-dsym)하십시오.
* iOS 에이전트 버전 7.7.2 이상에서는 압축된 맵 파일이 200MB보다 큰 경우 스크립트가 이를 업로드하지 않습니다. 파일 크기와 앱 버전만 뉴렐릭에 전송합니다. [dSYM을 수동으로 업로드](#manual-dsym)하지 않으면 뉴렐릭은 해당 빌드의 크래시를 심볼리케이트할 수 없습니다.
* 스크립트는 애플리케이션 토큰에서 업로드 리전(US, EU 또는 JP)을 선택합니다. 이는 [수동 업로드 명령](#manual-dsym)에서 사용되는 호스트와 동일합니다.

## 누락된 dSYM 식별 [#IdentifyingMissingdSYMs]

App Store 리뷰 또는 임시 배포를 위해 비트코드(Bitcode)가 활성화된 앱을 Apple에 업로드하는 경우, [모바일 충돌 보고서](/docs/mobile-monitoring/new-relic-mobile/getting-started/ios-agent-crash-reporting)가 제대로 심볼화되도록 하려면 Apple에서 수동으로 dSYM을 다운로드하여 뉴렐릭에 업로드해야 합니다. 이러한 dSYM은 앱을 업로드한 후 몇 분 이내에 Xcode의 archives organizer\[아카이브 오거나이저]를 통해 다운로드할 수 있습니다. 이 경우 [아카이브를 찾고 dSYM을 다운로드](/docs/mobile-monitoring/new-relic-mobile-ios/configuration/retrieve-dsyms-bitcode-apps#Archive)하는 절차를 따르십시오.

앱에 dSYM 파일이 없으면 모바일 모니터링 UI에 세 가지 표시기가 표시됩니다.

* <DNT>**Banner notification**</DNT>: [<DNT>**Crash report**</DNT> 페이지](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-apps-crash-report-dashboard) 에 배너 경고가 나타납니다. 경고 내용은 다음과 같습니다.

```
We were unable to locate your dsym.
```

* <DNT>**Upload prompt**</DNT>: dSYM 파일이 누락된 경우 <DNT>**Crash type summary**</DNT> 페이지에서 자동으로 업로드하게 됩니다.
* <DNT>**Machine code**</DNT>: <DNT>**Crash report**</DNT> 페이지의 충돌 스택 추적은 사람이 읽을 수 있는 오류 메시지가 아닌 기계어 코드를 표시합니다.

## 모바일 모니터링 UI를 통해 dSYM 파일 업로드 [#mobile-ui]

뉴렐릭 UI에서 직접 dSYM 파일을 쉽게 업로드할 수 있습니다. 크기 제한에 대한 자세한 내용은 [제한 사항](#limitations)을 참조하십시오. dSYM 파일을 업로드하려면:

1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Mobile**</DNT> 로 이동합니다. 그런 다음 목록에서 앱을 선택하세요.
2. <DNT>**Crashes**</DNT> 보기.
3. 그룹 충돌에서 <DNT>**Total crashes**</DNT> 중 특정 충돌을 선택하세요.
4. <DNT>**Upload dSYM**</DNT> 클릭합니다. dSYM을 직접 끌어서 놓거나 컴퓨터에서 파일을 선택할 수 있습니다.

## 수동으로 dSYM 파일 업로드 [#manual-dsym]

특정 상황에서는 뉴렐릭의 dSYM 파일 자동 업로드가 실패할 수 있습니다. 예를 들어, 네트워크 장애가 발생하여 업로드가 완료되지 않은 경우 [`upload_dsym_results.log`](#auto-upload-fail-troubleshooting)에 문제 발생 원인이 기록됩니다. 뉴렐릭이 dSYM 업로드를 처리하는 방법에 대한 추가 정보는 [뉴렐릭 온라인 기술 커뮤니티](https://support.newrelic.com/s/hubtopic/aAX8W0000008Yv9/relic-solution-ios-dsym-upload-deepdive)를 참조하십시오.

자동 업로드가 실패할 경우 dSYM 파일을 수동으로 업로드할 수 있습니다. dSYM 파일이 여러 개인 경우 단일 zip 파일에 포함할 수 있습니다. 크기 제한에 대해서는 [제한 사항](#limitations)을 참조해 주십시오. 아래 명령의 `YOUR_NEW_RELIC_APPLICATION_TOKEN` 값은 `+[NewRelic startWithApplicationToken:]` (오브젝티브-C) 또는 `NewRelic.start(withApplicationToken:)` (스위프트)에 사용되는 키와 동일합니다.

아래 명령에서는 전체 경로 또는 `$HOME`을(를) 사용하십시오. 셸은 따옴표 안의 `~`을(를) 확장하지 않습니다.

dSYM 파일을 수동으로 업로드하려면:

<CollapserGroup>
<Collapser id="swift-manual-upload" title="스위프트 스크립트를 통해">
명령줄에서 `run-symbol-tool.swift`을(를) 실행할 수 있습니다. Xcode 아카이브의 `dSYMs` 폴더와 같은 폴더에 있는 dSYM 파일을 변환하고 [자동 스크립트](#how-it-works)와 동일한 방식으로 업로드합니다. 스크립트는 `run-symbol-tool`와(과) 동일한 폴더에 있습니다(예: `NewRelic.xcframework/Resources`).

```shell
DWARF_DSYM_FOLDER_PATH="DSYM_FOLDER_PATH" /usr/bin/xcrun --sdk macosx swift "SCRIPT_PATH/run-symbol-tool.swift" "YOUR_NEW_RELIC_APPLICATION_TOKEN" -appVersion "APP_VERSION"
```

바꾸다:

* `DSYM_FOLDER_PATH` `.dSYM` 파일이 포함된 폴더의 전체 경로(예: `$HOME/Library/Developer/Xcode/Archives/2026-10-22/MyApp.xcarchive/dSYMs`)를 입력합니다.
* `SCRIPT_PATH` `run-symbol-tool.swift`이(가) 포함된 폴더의 전체 경로를 사용합니다.
* `APP_VERSION` 빌드 버전과 함께. `MARKETING_VERSION`은 Xcode 외부에서 설정되지 않으므로 버전을 명시적으로 전달하십시오. 에이전트 버전 7.4.12-7.7.4의 경우, `-appVersion`를 전달하는 대신 명령 앞에 `MARKETING_VERSION="APP_VERSION"`을 설정하십시오.

스크립트는 출력을 터미널에 표시합니다.
</Collapser>
</CollapserGroup>

## 문제점 해결 [#auto-upload-fail-troubleshooting]

`run-symbol-tool` 스크립트는 업로드 성공 여부와 관계없이 모든 빌드에서 프로젝트의 루트 디렉터리에 `upload_dsym_results.log`을(를) 기록합니다. 각 빌드는 이전 로그를 덮어씁니다. 로그에 더 자세한 내용을 기록하려면 [`--debug` 인수](#arguments)를 추가하십시오.

빌드 로그에 `upload_dsym_results.log: Operation not permitted`이(가) 표시되면 [자동 dSYM 업로드 실패](/docs/mobile-monitoring/new-relic-mobile-ios/troubleshoot/dSYM-upload-tools)를 참조하십시오.

### dSYM 누락 [#troubleshooting-missing-dsyms]

dSYM 파일이 없는 경우 Xcode 빌드 설정을 확인하여 파일이 생성되고 있는지 확인해야 할 수 있습니다. 로컬로 빌드된 프레임워크에는 별도의 빌드 설정이 있으며 업데이트해야 할 수도 있습니다.

빌드 설정:

```
Debug Information Format : Dwarf with dSYM File
Deployment Postprocessing: Yes
Strip Linked Product: Yes
Strip Debug Symbols During Copy : Yes
```

### 제한 사항 [#limitations]

다음 크기 제한에 유의해 주십시오:

* [모바일 모니터링 UI](#mobile-ui) 또는 [명령줄](#manual-dsym)을 통한 압축된 dSYM 업로드는 최대 600 MB까지 가능합니다.
* 자동 스크립트는 200MB보다 큰 압축된 맵 파일을 업로드하지 않습니다. [스크립트 작동 방식](#how-it-works)을 참조하십시오.
