이 페이지를 사용하여 리액트 네이티브 소스 맵 업로드 및 `MobileJSError` 심볼화 문제를 해결하십시오. 소스 맵을 업로드하는 방법을 알아보려면 [리액트 네이티브 JavaScript 오류 보고](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting)를 참조하십시오.

## 문제점 해결 [#troubleshooting]

### UI의 소스 맵 오류 [#sourcescontent]

UI에서 다음 오류 중 하나가 표시되는 경우, 소스 맵 파일에 `sourcesContent` 속성이 누락되었거나 업로드 시 제출된 메타데이터(`sourcemapName`, `jsBundleId` 또는 `appVersion`)가 해당 빌드에 대해 앱이 보고하는 값과 일치하지 않는 것입니다:

* `Source map not found.`
* `Source map missing.`
* `Incorrect map detected.`
* `Incorrect and missing maps detected.`

먼저 업로드에 사용된 `sourcemapName`, `jsBundleId` 및 `appVersion`이(가) 앱이 해당 빌드에 대해 보고하는 값과 일치하는지 확인하십시오([내 줄 번호가 일치하지 않는 이유는 무엇입니까?](#faq-line-numbers) 참조). 메타데이터가 일치하는 경우, 뉴렐릭이 스택 추적을 축소 해제할 수 있도록 소스 맵에 `sourcesContent` 속성이 포함되어야 합니다. 이 속성이 포함되도록 소스 맵을 다시 생성한 다음 다시 업로드하십시오. 대부분의 번들러는 `includeSources` (또는 빌드 도구의 동등한 옵션)와 같은 옵션을 활성화할 때 원본 소스 콘텐츠를 포함합니다.

### 리액트 네이티브 앱이 있지만 메뉴 항목이 보이지 않습니다. [#no-menu-item]

리액트 네이티브 앱이 있지만 UI에 리액트 네이티브 메뉴 항목이 표시되지 않는 경우, 업데이트된 에이전트 버전을 사용 중이고 앱이 데이터를 전송하고 있는지 확인하십시오. 앱이 리액트 네이티브 플랫폼으로 태그된 데이터를 전송할 때까지 메뉴 항목이 나타나지 않습니다.

### MobileJSError 및 처리된 예외 이벤트가 모두 표시되지 않습니다. [#mobilejserror-events]

새로운 에이전트 버전에서는 동일한 JavaScript 오류에 대해 `MobileJSError` 이벤트와 처리된 예외 이벤트를 모두 볼 수 없습니다. 대신 JavaScript 오류는 `MobileJSError` 이벤트로 기록됩니다.

뉴렐릭은 현재 리액트 네이티브에 대해서만 `MobileJSError`을(를) 지원합니다. Capacitor와 코도바는 지원되지 않습니다.

## 자주 묻는 질문 [#faq]

<CollapserGroup>
  <Collapser id="faq-zip" title="뉴렐릭은 압축된 파일을 허용합니까?">
    예. gzip 또는 zip(`.zip`)으로 압축된 소스 맵을 업로드할 수 있습니다. 빌드 스크립트는 업로드 전에 대용량 `.map` 파일을 자동으로 압축합니다.
  </Collapser>

  <Collapser id="faq-size" title="최대 업로드 페이로드 크기는 얼마입니까?">
    압축 해제 시 200MB입니다. 뉴렐릭은 심볼리케이션을 위해 압축 해제 시 200MB보다 큰 소스 맵을 저장하지 않습니다. 대신 빌드 텔레메트리를 전송합니다. 자세한 내용은 [파일 크기 제한](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting#file-size-limitations)을 참조하십시오.
  </Collapser>

  <Collapser id="faq-code-snippets" title="스택 추적에 코드 스니펫이 표시되지 않는 이유는 무엇입니까?">
    코드 스니펫은 소스 맵에 `sourcesContent` 속성이 필요합니다. 소스 맵에 원본 소스 콘텐츠가 포함되어 있지 않은 경우에도 뉴렐릭은 행 및 열 매핑을 사용하여 스택 추적의 축소를 해제할 수 있지만 주변 소스 코드는 표시할 수 없습니다. `includeSources`과(와) 같은 옵션(또는 빌드 도구에 해당하는 옵션)을 활성화하여 소스 맵을 다시 생성한 다음 다시 업로드하십시오.
  </Collapser>

  <Collapser id="faq-line-numbers" title="줄 번호가 일치하지 않는 이유는 무엇입니까?">
    업로드된 소스 맵이 오류를 발생시킨 JavaScript 번들과 정확히 일치하지 않으면 줄 번호가 일치하지 않습니다. 업로드에 사용된 `jsBundleId` 및 `appVersion`이(가) 앱에서 해당 빌드에 대해 보고하는 값과 일치하는지 확인하십시오. — 이는 JavaScript 번들이 네이티브 바이너리 버전과 달라지는 CodePush 또는 기타 OTA(Over-The-Air) 업데이트 후에 특히 중요합니다. 또한 소스 맵이 버전 3인지 확인하십시오.
  </Collapser>

  <Collapser id="faq-not-symbolicated" title="내 파일이 심볼릭화되지 않는 이유는 무엇입니까?">
    일반적인 원인은 다음과 같습니다:

    * 소스 맵에 `sourcesContent` 속성이 누락되었습니다([UI의 소스 맵 오류](#sourcescontent) 참조).
    * 업로드와 실행 중인 앱 간에 `jsBundleId` 또는 `appVersion`이(가) 일치하지 않습니다([내 줄 번호가 일치하지 않는 이유는 무엇입니까?](#faq-line-numbers) 참조).
    * 소스 맵이 [200 MB 제한](#faq-size)을 초과하여 뉴렐릭은 빌드 텔레메트리만 전송했습니다.
    * 데이터 동기화가 아직 완료되지 않았습니다. 업로드 후 데이터를 사용할 수 있게 되기까지 몇 분 정도 걸릴 수 있습니다.
    * 소스 맵의 API 키와 애플리케이션 토큰이 서로 다른 뉴렐릭 계정에 속해 있습니다.
  </Collapser>

  <Collapser id="faq-list" title="뉴렐릭에 업로드한 내용을 어떻게 확인할 수 있습니까?">
    NerdGraph 또는 NRQL에서 list 명령을 사용하십시오. [리액트 네이티브 소스 맵 나열 및 삭제](/docs/mobile-monitoring/new-relic-monitoring-react-native/list-delete-react-native-source-maps)를 참조하십시오.
  </Collapser>

  <Collapser id="faq-multi-bundle" title="다중 번들 앱에 대해 여러 소스 맵을 업로드할 수 있습니까?">
    아니요. 뉴렐릭의 리액트 네이티브 심볼리케이션은 Metro의 기본(다중 번들이 아닌) 심볼리케이터와 일치하는 단일 소스 맵 파일만 지원합니다. 앱이 JavaScript를 여러 번들로 분할하고 여러 소스 맵을 생성하는 경우, 뉴렐릭은 해당 설정에 대한 심볼리케이션을 지원하지 않습니다.

    이 문제가 발생하는 경우, 다중 번들 지원을 요청하려면 [뉴렐릭 지원팀에 문의하거나 기능 요청을 제출하십시오](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting#request-support).
  </Collapser>
</CollapserGroup>
