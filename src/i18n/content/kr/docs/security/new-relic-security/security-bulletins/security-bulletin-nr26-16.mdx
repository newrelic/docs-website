<DNT>**Vulnerability Identifier:**</DNT> NR26-16

<DNT>**Priority:**</DNT> 비판적인

## 요약

OpenJDK HotSpot 자바 가상 머신(JVM)의 하드웨어 가속 Base64 디코더에서 심각한 메모리 손상 취약점(CVE-2026-114938)이 공개되었습니다. 영향을 받는 자바 애플리케이션이 특수하게 조작된 Base64 인코딩 입력(예: HTTP Authorization 헤더, JWT, SAML 토큰 또는 파일 업로드)을 처리할 때, 정수 언더플로가 발생하여 범위를 벗어난 힙 쓰기를 트리거할 수 있습니다. 성공적으로 악용할 경우 애플리케이션 충돌(서비스 거부)이 발생하거나, 민감한 힙 메모리가 노출되거나, 인증되지 않은 원격 코드 실행(RCE)이 허용될 수 있습니다.

## 작업 항목

### 조치가 필요하지 않습니다.

뉴렐릭은 뉴렐릭 자바 에이전트와 함께 자바 런타임을 제공하지 않습니다. 신세틱스 공개 위치를 포함하여 뉴렐릭에서 호스팅하는 서비스에 대해서는 고객의 조치가 필요하지 않습니다.

다음의 경우에는 고객의 조치가 필요합니다.

### 신세틱스 프라이빗 로케이션(신세틱스 Job Manager 및 ping 런타임)

신세틱스 작업 관리자(SJM) 및 프라이빗 로케이션용 핑 런타임에는 자바 런타임이 포함되어 있습니다. 패치된 자바 런타임이 포함된 업데이트된 이미지가 2026년 11월 19일에 게시되었습니다.

* 신세틱스 Job Manager를 [release-659](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-659/images/sha256-11fa4a7b78d7a7d708b1f5efec790dc066ab6c02d3b3f02c7a59a8b885913828) 이상으로, ping 런타임을 [1.89.0](https://hub.docker.com/layers/newrelic/synthetics-ping-runtime/1.89.0/images/sha256-33da2eb67b404b09f19e1ea232e80be22d403e97abbeaf2b0f26bc95d2eae646) 이상으로 업그레이드하십시오.
* 설정에서 ping 런타임을 특정 버전으로 고정한 경우, 1.89.0 이상으로 업데이트하십시오. `latest` 태그를 사용하는 경우, 신세틱스 작업 관리자를 다시 시작하여 업데이트된 런타임을 가져오십시오.
* [release-655](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-655/images/sha256-c587a634136aeed4179ebd216d993c9aea4b50a6a88f977fc5099fb164b42c57) 이전 버전의 신세틱스 작업 관리자를 실행하는 경우, 현재 릴리스로의 인플레이스 업그레이드 경로가 없습니다. 최신 버전으로의 마이그레이션을 계획하고 먼저 비운영 환경에서 유효성을 검사하십시오. 설치 지침은 [신세틱스 작업 관리자 설치](/docs/synthetics/synthetic-monitoring/private-locations/install-job-manager)를 참조하십시오.
* 신세틱스 작업 관리자를 즉시 업그레이드할 수 없는 경우, 신세틱스 작업 관리자 컨테이너에 JVM 옵션 `JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"`을(를) 설정하십시오. x86-64 호스트에서만 대신 `-XX:UseAVX=2`을(를) 사용할 수 있습니다. ARM의 JVM은 이 옵션을 인식하지 못하며 시작에 실패합니다. 이 옵션은 신세틱스 작업 관리자가 출시하는 핑 런타임 컨테이너에는 적용되지 않으므로, 완전히 문제를 해결하려면 여전히 핑 런타임 이미지를 업데이트해야 합니다.

### 뉴렐릭 자바 에이전트가 모니터하는 애플리케이션을 포함한 자바 애플리케이션

다음 조건이 모두 참인 경우에만 자바 애플리케이션이 영향을 받습니다:

* 애플리케이션은 버전 17.0.6 이상(단, 2026년 11월 중요 패치 업데이트 이전)의 HotSpot 기반 OpenJDK 배포판에서 실행됩니다. 예로는 오라클 자바 SE, Amazon Corretto, Eclipse Temurin, Azul Zulu, Red Hat OpenJDK, Microsoft Build of OpenJDK가 있습니다.
* 호스트에 AVX-512 VBMI를 지원하는 x86-64 프로세서(Intel Xeon Ice Lake 이상 또는 AMD Zen 4 이상)가 있습니다. AWS Graviton을 포함한 ARM64 프로세서는 영향을 받지 않습니다.
* 애플리케이션이 자바의 Base64 디코더에 도달할 수 있는 신뢰할 수 없는 입력을 처리합니다.

**수정:** 인터넷에 연결된 시스템부터 시작하여 자바 런타임을 공급업체의 2026년 11월 보안 릴리스로 업데이트하십시오. 자세한 내용은 오라클의 [중요 보안 패치 업데이트](https://www.oracle.com/security-alerts/cspunov2026.html) (2026년 11월), OpenJDK [취약점 권고](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) (2026. 11. 17.), 또는 JDK 공급업체의 권고를 참조하십시오.

## 자주 묻는 질문

1. **이것이 뉴렐릭 에이전트에 영향을 미칩니까?**

   뉴렐릭 자바 에이전트는 자바 런타임(JDK/JVM)을 번들로 제공하거나 배포하지 않습니다. 이는 애플리케이션의 환경에서 사용할 수 있는 자바 런타임을 사용하여 자바 애플리케이션을 계측합니다.

2. **뉴렐릭 자바 에이전트를 업데이트해야 합니까?**

   아닙니다. 뉴렐릭 자바 에이전트에는 자바 런타임이 포함되어 있지 않으며, 이 취약점과 관련하여 자바 에이전트 업데이트가 필요하지 않습니다.

3. **어떤 시스템이 영향을 받습니까?**

   AVX-512 VBMI를 지원하는 x86-64 프로세서만 해당합니다. ARM64 프로세서는 영향을 받지 않습니다. OpenJDK 및 오라클이 수정 사항을 게시했습니다.

4. **애플리케이션의 자바 런타임이 영향을 받는지 어떻게 알 수 있습니까?**

   자바 버전과 CPU를 확인하십시오. 뉴렐릭 APM이 모니터하는 애플리케이션의 경우, 서비스의 Environment \[환경] 페이지에 JVM 버전이 표시됩니다. 자세한 내용은 [APM 앱에 대한 환경 데이터 가져오기](/docs/apm/agents/manage-apm-agents/troubleshooting/get-environment-data-about-your-apm-app)를 참조하시고, 반드시 호스트를 선택해 주십시오. 또는 호스트에서 `java -version`을(를) 실행하십시오.

   리눅스에서 다음을 사용하여 CPU를 확인하십시오:

   ```bash
   grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(avx512f|avx512bw|avx512vbmi|bmi2)$'
   ```

   4개의 플래그가 모두 나타나는 경우에만 CPU가 영향을 받습니다.

5. **취약점을 어떻게 수정합니까?**

   인터넷에 연결된 시스템부터 시작하여 자바 런타임을 공급업체의 2026년 11월 보안 릴리스로 업데이트하십시오. 자세한 내용은 오라클의 [중요 보안 패치 업데이트](https://www.oracle.com/security-alerts/cspunov2026.html) (2026년 11월), OpenJDK [취약점 권고](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) (2026. 11. 17.) 또는 JDK 공급업체의 권고를 참조하십시오.

6. **즉시 패치할 수 없는 경우 어떻게 해야 합니까?**

   임시 완화 조치로 `JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"`을(를) 사용하여 JVM을 시작하십시오. x86-64 호스트에서만 대신 `-XX:UseAVX=2`을(를) 사용할 수 있습니다. ARM의 JVM은 이 옵션을 인식하지 못하며 시작에 실패합니다. 두 옵션 모두 임시 조치이며 패치를 대체하지 않습니다.

7. **뉴렐릭에서 악용 증거를 확인했습니까?**

   당사 환경에서 이 취약점이 악용되었다는 지표는 확인되지 않았습니다.

8. **질문이 있는 경우 어떻게 해야 합니까?**

   이 커뮤니케이션과 관련된 지원이 필요한 경우, 인앱 지원을 통해 지원 케이스를 생성하십시오.
