<DNT>**Vulnerability Identifier:**</DNT> NR26-17

<DNT>**Priority:**</DNT> 비판적인

## 요약

2026년 11월 19일, 뉴렐릭의 보안 인시던트 대응 팀은 최근 공개된 루비 취약점인 “Ruby2Shell”(CVE-2026-132825)과 관련하여 당사 서비스 및 엔터프라이즈 인프라에 대한 포괄적인 평가를 시작했습니다. 이는 원격 코드 실행(RCE) 또는 서비스 거부(DoS)를 허용할 수 있는 루비 인터프리터의 문자열 대소문자 변환에서 발생하는 1바이트 힙 기반 버퍼 오버플로입니다.

## 작업 항목

### 루비 에이전트를 사용하는 고객은 조치가 필요하지 않습니다.

뉴렐릭의 배포된 루비 에이전트는 영향을 받지 않습니다. 루비 에이전트를 사용하는 뉴렐릭 고객은 이 취약점에 대해 어떠한 조치도 취하실 필요가 없습니다.

## 자주 묻는 질문

1. **이것이 뉴렐릭 에이전트에 영향을 미칩니까?**

   뉴렐릭 루비 언어 에이전트는 영향을 받지 않습니다. 다른 뉴렐릭 언어 에이전트도 영향을 받지 않습니다. Fluentd 이미지는 뉴렐릭 에이전트에서 사용되지 않습니다.

2. **어떤 시스템이 영향을 받습니까?**

   다음 이미지를 실행하는 모든 컨테이너 런타임(Kubernetes, 도커 등):

   * `newrelic/newrelic-fluentd-docker`
   * `newrelic/fluentd`
   * `newrelic/k8s-golang-apm-linkage-demo`

3. **취약점을 어떻게 수정합니까?**

   `newrelic/newrelic-fluentd-docker` 이미지를 사용하는 경우:

   1. 수정된 이미지를 가져오십시오:

      ```shell
      docker pull newrelic/newrelic-fluentd-docker:1.20.1
      ```

   2. 새 이미지로 컨테이너를 다시 생성하십시오. 이미지를 가져온다고 해서 이미 실행 중인 컨테이너가 업데이트되지는 않습니다. Kubernetes, 도커 또는 다른 컨테이너 런타임에서 이미지 태그를 1.20.1로 변경하고 다시 배포하십시오.

   3. `newrelic/newrelic-fluentd-docker`에서 자체 이미지를 빌드하는 경우 `docker build --pull`을(를) 사용하여 다시 빌드하십시오.

   4. 실행 중인 버전 확인:

      ```shell
      docker exec <container> fluentd --version
      ```

   5. 출력에 `fluentd 1.20.1` 이상이 표시되어야 합니다.

   이미지를 사용하지 않는 경우 뉴렐릭 `newrelic/newrelic-fluentd-docker` [Fluentd 플러그인](/docs/logs/forward-logs/fluentd-plugin-log-forwarding/) 과 함께 [Fluentd 를 사용하는](https://www.fluentd.org/) 것을 고려해 보십시오.

4. **새 이미지를 가져올 때 내 컨테이너가 업데이트됩니까?**

   아니요. 실행 중인 컨테이너는 다시 생성할 때까지 이전 이미지를 유지합니다.

5. **인프라 에이전트의 로그 포워딩이 영향을 받습니까?**

   아니요. 인프라 에이전트 및 Kubernetes 통합의 로그 포워딩은 Fluentd가 아닌 [Fluent Bit](/docs/logs/forward-logs/fluent-bit-plugin-log-forwarding/)를 사용합니다.

6. **질문이 있는 경우 어떻게 해야 합니까?**

   이 커뮤니케이션과 관련된 지원이 필요한 경우, 인앱 지원을 통해 지원 케이스를 생성하십시오.
