<DNT>**Vulnerability Identifier:**</DNT> NR26-14

<DNT>**Priority:**</DNT> 높은

## 요약

2026년 10월 17일-2026년 10월 20일 사이에 연구원들은 eMudhra에서 발급한 8개의 중간 인증 기관(CA) 인증서에 대한 개인 키를 복구할 수 있다고 밝혔습니다(CVE-2026-111943). 해당 키를 가진 사람은 누구든 소프트웨어가 여전히 신뢰하는 경우 진짜로 인식할 인증서를 생성할 수 있습니다. 브라우저와 운영 시스템은 해당 인증서를 차단했지만, 일부 컨테이너 이미지를 포함하여 자체적으로 신뢰할 수 있는 CA 목록을 보유한 소프트웨어는 업데이트해야 합니다.

뉴렐릭은 이러한 CA에서 발급한 인증서를 더 이상 허용하지 않도록 아래의 Kubernetes 구성 요소를 업데이트했습니다. 업데이트된 버전은 자동으로 적용되지 않습니다. 고객은 아래 나열된 버전으로 업그레이드해야 합니다.

## 기술적 취약점 정보

* emSign ECC Root CA - G3에 체인으로 연결되고 교차 서명을 통해 AAA Certificate Services에 연결되는 8개의 중간 CA가 영향을 받습니다.

* 수정된 알파인 기반 이미지는 CA 번들에서 emSign ECC Root CA - G3 및 AAA Certificate Services를 제거한 ca-certificates 20261020-r0이 포함된 알파인 3.24.3을 기반으로 빌드되었습니다.

  * k8s-agents-operator 0.54.0은 두 루트가 모두 제거된 distroless 기반으로 빌드되었습니다.
  * prometheus:v3.15.1(업스트림) 또한 두 루트가 모두 없는 CA 번들을 제공합니다.

* 뉴렐릭 Kubernetes 통합 바이너리는 Go 1.27.3으로 빌드되었으며, 이 버전의 TLS 라이브러리는 루트를 여전히 신뢰할 수 있더라도 영향을 받는 8개의 키가 포함된 인증서 체인을 거부합니다. infrastructure-bundle에 번들로 포함된 일부 온-호스트 통합은 이전 Go 버전을 사용하며, 해당 CA 번들은 여전히 수정된 상태입니다.

* 노출은 퍼블릭 루트 저장소를 사용하는 연결, 즉 에이전트의 뉴렐릭 엔드포인트 및 구성된 프록시에 대한 연결로 제한됩니다. 클러스터(Kubernetes API 서버, kubelet, 컨트롤 플레인) 내부의 연결은 클러스터 자체의 CA를 사용하며 영향을 받지 않습니다.
