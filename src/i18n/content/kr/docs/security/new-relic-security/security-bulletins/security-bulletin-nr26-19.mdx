<DNT>**Vulnerability Identifier:**</DNT> NR26-19

<DNT>**Priority:**</DNT> 비판적인

## 요약

2026년 11월 18일, nginx는 &quot;nginx2root&quot;로 함께 알려진 HTTP/2 모듈의 취약점을 공개했습니다. F5는 CVSS v4.0에 따라 두 가지 주요 문제를 9.2(심각)로 평가합니다.

CVE-2026-123007은 nginx 1.9.5부터 1.31.8까지 영향을 미칩니다. nginx가 특수하게 조작된 HTTP/2 트래픽을 처리할 때 흐름 제어 창이 허용된 한도를 초과하여 힙 버퍼 오버플로가 발생할 수 있습니다. 인증되지 않은 공격자가 nginx 작업자 프로세스를 중단시키거나 메모리를 손상시킬 수 있습니다. ASLR이 비활성화되어 있거나 공격자가 이를 우회할 수 있는 경우 공격자는 코드를 실행할 수도 있습니다.

CVE-2026-123633은 nginx가 HTTP/2 클라이언트 연결을 수락하고 백앤드로 requests를 프록시할 때 nginx 1.19.7부터 1.31.8까지 영향을 미칩니다. 특수하게 조작된 요청은 `worker_connections`이(가) 부족한 작업자 프로세스에서 해제 후 사용을 유발할 수 있습니다. 이는 서비스 거부 또는 ASLR 우회를 통한 코드 실행으로 이어질 수 있습니다.

두 취약점에 대한 수정 사항은 nginx 1.30.7(stable) 및 1.31.9(mainline)와 NGINX Plus PLS.37.0.8.1 및 PLS.37.3.0.1에 포함되어 있습니다. 동일한 릴리스에서 여러 다른 nginx 취약점을 수정하며, 이 중 일부는 HTTP/2와 관련이 없습니다. 이후 릴리스인 nginx 1.30.8 및 1.31.10에서도 CVE-2026-132779를 수정합니다. [공개 익스플로잇](https://github.com/sfewer-r7/CVE-2026-123007?utm_source) 세부 정보를 확인할 수 있습니다. 2026년 11월 24일 현재 CISA의 알려진 악용된 취약점 카탈로그에는 이러한 취약점이 나열되어 있지 않습니다.

**뉴렐릭 nginx 통합(nri-nginx)을 포함한 뉴렐릭 에이전트 및 통합에는 nginx가 포함되어 있지 않으며 영향을 받지 않습니다.** 뉴렐릭은 nginx를 사용하는 인터넷 연결 서비스에서 nginx를 업데이트했습니다. 뉴렐릭은 당사 환경에서 악용 증거를 확인하지 못했습니다.

## 권장 조치

뉴렐릭 서비스나 설치한 뉴렐릭 에이전트 및 통합에 대해서는 아무런 조치도 필요하지 않습니다. 그럼에도 불구하고 뉴렐릭은 자체 환경에서 HTTP/2를 활성화하여 nginx를 실행하는 고객에게 최신 nginx 릴리스(1.30.8 안정 버전 또는 1.31.10 메인라인), NGINX Plus PLS.37.0.8.1 또는 PLS.37.3.0.1 이상, 또는 수정 사항이 포함된 Linux 배포 패키지로 업그레이드할 것을 강력히 권장합니다.

### 권장 사항

* 먼저 HTTP/2가 활성화된 인터넷 연결 서버를 업그레이드하십시오. `listen` 지시어에 `http2`이(가) 포함되거나 `http2 on;`이(가) 설정된 경우 HTTP/2가 활성화됩니다.
* 패치된 바이너리가 실행되도록 업그레이드 후 nginx를 다시 시작하십시오.
* nginx가 포함된 컨테이너 이미지를 다시 빌드하고 다시 배포하십시오. 호스트를 패치해도 컨테이너 내부의 nginx는 업데이트되지 않습니다.
* **Linux 배포 패키지:** 배포판은 종종 업스트림 버전 번호를 변경하지 않고 수정 사항을 추가합니다. Ubuntu는 2026년 11월 19일에 지원되는 모든 릴리스에 대한 수정된 패키지를 게시했습니다. 기타 배포판의 경우 CVE-2026-123007 및 CVE-2026-123633에 대한 공급업체의 권고 사항을 확인하십시오.
* Kubernetes 인그레스 컨트롤러, 게이트웨이 및 어플라이언스와 같이 nginx를 내장한 제품: 수정 사항이 포함된 릴리스에 대해서는 공급업체 또는 프로젝트에 확인하십시오.
* 뉴렐릭이 GitHub에 게시한 예제 또는 데모 애플리케이션 중 하나를 배포했고 퍼블릭 nginx 이미지를 사용하는 경우, 최신 nginx 이미지에서 이를 다시 빌드하십시오.

## 임시 완화 조치

업그레이드만이 동일한 릴리스에서 수정된 다른 취약점과 함께 이러한 취약점을 완전히 수정합니다. 업그레이드할 수 있을 때까지:

* 영향을 받는 리스너에서 HTTP/2를 비활성화하고 nginx를 다시 로드하십시오. 두 취약점 모두 HTTP/2가 필요합니다. 이를 비활성화하려면 `listen` 지시어에서 `http2`을(를) 제거하거나 `http2 off;`을(를) 설정하십시오. 클라이언트는 HTTP/1.1로 폴백합니다.

## 자주 묻는 질문

1. **이것이 뉴렐릭의 에이전트 또는 통합에 영향을 미칩니까?**

   아니요. 뉴렐릭 에이전트 및 통합에는 nginx가 포함되어 있지 않습니다. 뉴렐릭 nginx 통합(nri-nginx)은 실행 중인 nginx 서버에서 메트릭을 수집합니다. 여기에는 nginx가 포함되어 있지 않습니다.

2. **뉴렐릭 nginx 통합을 업데이트해야 합니까?**

   아니요. nginx 자체를 업그레이드하십시오.

3. **일부 뉴렐릭 Helm 차트는 `ingress-nginx/kube-webhook-certgen`(이)라는 이름의 이미지를 참조합니다. 영향을 받습니까?**

   아닙니다. 해당 이미지는 Kubernetes ingress-nginx 프로젝트의 인증서 생성 유틸리티이며 nginx를 포함하지 않습니다.

4. **사용 중인 nginx가 영향을 받는지 어떻게 확인할 수 있습니까?**

   먼저 HTTP/2가 활성화되어 있는지 확인하십시오. `nginx -T | grep http2`을(를) 실행하십시오. 그런 다음 버전을 확인하십시오.

   * nginx.org에서 nginx를 설치했거나 직접 빌드한 경우 `nginx -v`을(를) 실행하십시오. 버전이 1.9.5 이상이고 1.30.7(안정) 또는 1.31.9(메인라인) 이전인 경우 영향을 받습니다.
   * Linux 배포판에서 nginx를 설치한 경우 버전 번호만으로는 보호 여부를 알 수 없습니다. 설치된 패키지 버전(예: `dpkg -l | grep nginx` 또는 `rpm -q nginx`)을 배포판의 권고 사항과 비교하십시오.

5. **시스템이 타겟이 되었는지 어떻게 알 수 있습니까?**

   악의적인 HTTP/2 트래픽은 액세스 로그에서 정상적인 requests로 표시되지 않습니다. 익스플로잇 시도는 일반적으로 nginx 워커 프로세스에 충돌을 일으킵니다. nginx 오류 로그에서 신호 11(세그먼테이션 오류)로 종료되는 워커 프로세스가 있는지 확인하십시오. nginx 로그를 뉴렐릭으로 전달하는 경우, 이 메시지에 대한 [공지를 생성](/docs/tutorial-create-alerts/create-an-alert/) 할 수 있습니다. 또한 셸이나 기타 예상치 못한 하위 프로세스를 시작하는 nginx 워커 프로세스가 있는지도 확인하십시오.

6. **뉴렐릭에서 악용 증거를 확인했습니까?**

   당사 환경에서 이러한 취약점의 악용 징후는 확인되지 않았습니다.

7. **이러한 취약점에 대해 질문이 있습니다. 누구에게 연락해야 합니까?**

   뉴렐릭 서비스와 관련하여 이러한 취약점에 대한 질문이 있는 경우 앱 내 지원을 통해 [지원 케이스를 열거나](/docs/new-relic-solutions/solve-common-issues/find-help-get-support/#file-ticket) 뉴렐릭 계정 담당자에게 문의하십시오.
