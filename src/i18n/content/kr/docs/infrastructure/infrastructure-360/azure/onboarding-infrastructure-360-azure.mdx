## 전제 조건 [#prerequisites]

<DNT>Azure</DNT>에 [<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360)을(를) 활성화하기 전에 다음 사항을 확인하십시오:

* 구독 ID가 있는 <DNT>Azure</DNT> 계정.
* 모니터링 읽기 권한자 역할이 있는 <DNT>Azure</DNT> 앱 등록입니다.
* <DNT>Infrastructure 360</DNT> 프리뷰에 등록된 뉴렐릭 계정.
* 뉴렐릭에서 클라우드 통합을 관리하기 위한 권한입니다.

프리뷰에 등록하려면 <DNT>**one.newrelic.com &gt; Administration &gt; Preview &amp; Trials**</DNT>에 접속하여 <DNT>**Infrastructure 360**</DNT>에 등록해 주십시오.

<DNT>Azure</DNT>에 대해 <DNT>Infrastructure 360</DNT>을(를) 활성화하는 방법에는 세 가지가 있습니다:

## Azure 온보딩 중 활성화 [#onboarding-enable]

<DNT>Azure</DNT>을(를) 뉴렐릭에 처음 연결하는 경우 다음 단계를 따르십시오:

1. <DNT>**Infrastructure &gt; Azure**</DNT> 으로 이동합니다.
2. 계정을 선택하고 <DNT>**Set up integration**</DNT> 클릭합니다.
3. 프롬프트에 따라 <DNT>Azure</DNT> 앱 등록을 생성하십시오. 자세한 설정 지침은 [<DNT>Azure</DNT> 통합 연결](/docs/infrastructure/microsoft-azure-integrations/get-started/activate-azure-integrations)을 확인해 주시기 바랍니다.
4. 통합 설정 중 프롬프트가 표시되면 <DNT>**Infrastructure 360**</DNT> 옵션을 활성화하십시오.
5. 스캔 주기를 구성하십시오. 기본적으로 <DNT>Infrastructure 360</DNT>은(는) 하루에 세 번 스캔합니다. 이를 변경하려면 [스캔 빈도 조정](#adjust-frequency)을 참조하십시오.

## 기존 Azure 통합에 대해 활성화합니다. [#existing-enable]

이미 <DNT>Azure</DNT>을(를) 뉴렐릭과 통합한 경우 다음 단계를 따르십시오:

1. <DNT>**Infrastructure &gt; Azure**</DNT> 으로 이동하여 <DNT>**Manage Infrastructure 360**</DNT> 클릭합니다.
2. 계정 목록에서 <DNT>Azure</DNT> 구독을 찾은 다음 (공급자 계정 수준에서) <DNT>**Install**</DNT>을(를) 클릭하십시오.
3. 위에서 설명한 대로 스캔 주기를 설정하십시오.
4. <DNT>**Save**</DNT>을(를) 클릭하여 <DNT>Azure</DNT> 계정에 대해 <DNT>Infrastructure 360</DNT>을(를) 활성화하십시오.

## 인프라 360 페이지에서 활성화 [#landing-page-enable]

이 페이지에서 <DNT>Infrastructure 360</DNT>을(를) 활성화하려면:

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; Infrastructure 360**</DNT> 으)로 이동합니다.
2. 이 뉴렐릭 계정 하위의 <DNT>Azure</DNT> (및 <DNT>AWS</DNT>) 공급자 계정에 대한 기능을 활성화하십시오.

이 페이지가 비어 있는 경우(아직 어떤 공급자에 대해서도 <DNT>Infrastructure 360</DNT>을(를) 활성화하지 않은 경우), <DNT>**Setup Infrastructure 360**</DNT>을(를) 클릭한 다음 기능을 활성화합니다.

## Terraform을 통한 활성화 [#terraform-enable]

뉴렐릭 UI 대신 <DNT>Terraform</DNT>을(를) 통해 <DNT>Azure</DNT>에 대한 <DNT>Infrastructure 360</DNT>을(를) 활성화할 수도 있습니다. 이는 <DNT>Terraform</DNT>을(를) 사용하여 <DNT>Azure</DNT> 통합에 대한 자동 검색을 활성화하는 단계별 가이드입니다.

### 전제 조건 [#terraform-prerequisites]

시작하기 전에 다음을 확인해 주십시오:

* **<DNT>Terraform</DNT> 설치됨**: 로컬 머신에 <DNT>Terraform</DNT>이(가) 설치되었습니다.
* **뉴렐릭 계정 ID**: 뉴렐릭 계정 ID(`newrelic_account_id`)입니다.
* **뉴렐릭 사용자 API 키**: 뉴렐릭에 인증하기 위한 사용자 키(`newrelic_api_key`)입니다.
* **연결된 프로바이더 계정 ID**: 뉴렐릭에서 인식하는 <DNT>Azure</DNT> 계정의 ID(`provider_account_id`)입니다. 이는 보통 뉴렐릭 UI의 <DNT>**Infrastructure &gt; Azure**</DNT>에서 확인할 수 있습니다.
* **리전**: 뉴렐릭 데이터 리전(US 또는 EU).

<Steps>
<Step>
### 작업 공간 설정 [#setup-workspace]

<DNT>Terraform</DNT> 설정을 위한 로컬 폴더를 구성하십시오:

1. 터미널 또는 명령 프롬프트를 여십시오.

2. 프로젝트용 새 폴더를 생성해 주십시오:

   ```bash
   mkdir terraform-integrate
   cd terraform-integrate
   ```
</Step>

<Step>
### 설정 파일 생성 [#create-config-files]

`terraform-integrate` 폴더 안에 다음 3개의 파일을 생성하십시오. 어떤 텍스트 편집기든 사용할 수 있습니다.

#### providers.tf

이 파일은 <DNT>Terraform</DNT>에 다운로드할 플러그인을 알려줍니다.

```hcl
terraform {
  required_providers {
    newrelic = {
      source = "newrelic/newrelic"
    }
  }
}
```

#### variables.tf

이 파일은 스크립트를 실행하는 데 필요한 입력을 정의합니다.

```hcl
variable "provider_account_id" {
  description = "The Azure Subscription ID Equivalent in Newrelic (Linked Account ID)."
  type        = number
}

variable "new_relic_region" {
  description = "The New Relic region (e.g., 'US', 'EU', or 'JP')."
  type        = string
  default     = "US"
}

variable "newrelic_account_id" {
  description = "The New Relic account ID."
  type        = number
}

variable "newrelic_api_key" {
  description = "The New Relic API key."
  type        = string
}
```

#### main.tf

자동 검색 기능을 활성화하는 핵심 스크립트입니다.

```hcl
provider "newrelic" {
  account_id = var.newrelic_account_id
  region     = var.new_relic_region
  api_key    = var.newrelic_api_key
}

resource "newrelic_cloud_azure_integrations" "auto_discovery_integrations" {
  linked_account_id = var.provider_account_id

  # This block enables auto-discovery for the account
  auto_discovery {}
}
```
</Step>

<Step>
### Terraform 실행 [#run-terraform]

이제 파일이 준비되었으므로, `terraform-integrate` 폴더 내의 터미널에서 다음 명령을 실행하십시오.

1. **초기화**: 필요한 뉴렐릭 공급자 플러그인을 다운로드합니다.

   ```bash
   terraform init
   ```

2. **Plan**: 설정을 확인하고 어떤 일이 발생할지 보여줍니다. <DNT>Terraform</DNT>은(는) 여기에 ID와 키를 입력하도록 프롬프트를 표시합니다.

   ```bash
   terraform plan
   ```

   `newrelic_account_id`, `newrelic_api_key` 및 기타 변수에 대한 프롬프트가 표시되면 값을 입력해 주십시오.

3. **Apply**: 계획을 실행하고 통합을 활성화합니다.

   ```bash
   terraform apply
   ```

   확인 메시지가 표시되면 `yes`을(를) 입력하십시오.
</Step>
</Steps>

자세한 내용은 [뉴렐릭 <DNT>Terraform</DNT> 프로바이더 문서](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#azure)를 참조해 주십시오.

## 인프라 360 사용 [#using-infrastructure-360]

활성화되면 <DNT>Infrastructure 360</DNT>을(를) 통해 인프라, APM 및 데이터베이스를 포함한 모든 <DNT>Azure</DNT> 엔티티 간의 관계를 확인할 수 있습니다.

<Callout title="메모">
<DNT>Infrastructure 360</DNT> 네이티브 뉴렐릭 APM 에이전트(<DNT>Java</DNT>, <DNT>.NET</DNT>, <DNT>Python</DNT>) 및 <DNT>OpenTelemetry</DNT> (<DNT>.NET</DNT>)을(를) 통해 엔티티 관계를 지원합니다.

특히 <DNT>Azure Kubernetes Service</DNT> (<DNT>AKS</DNT>) 클러스터의 경우, 애플리케이션을 해당 <DNT>AKS</DNT> 클러스터에 연결하려면 뉴렐릭 <DNT>Kubernetes</DNT> 에이전트 또는 <DNT>OpenTelemetry</DNT>이(가) 필요합니다. <DNT>Infrastructure 360</DNT>은(는) 자체적으로 해당 연결을 설정하지 않지만, 연결이 존재하면 애플리케이션에서 <DNT>AKS</DNT> 클러스터를 거쳐 종속된 다른 <DNT>Azure</DNT> 인프라로의 관계를 매핑하여 체인을 완성합니다.
</Callout>

### 검색된 엔티티 및 관계 보기 [#view-entities]

검색된 엔티티와 그 관계를 보려면:

1. <DNT>**All entities**</DNT> (으)로 이동하여 `collector.name = auto discovery`을(를) 필터링합니다.

2. <DNT>Azure</DNT> 엔티티를 선택하여 다음 항목 간의 관계를 보여주는 인프라 맵을 확인하십시오:

   * <DNT>Azure</DNT> 엔티티(가상 머신, 데이터베이스, 스토리지 계정).
   * APM 엔티티(애플리케이션, 서비스).
   * 크로스 플랫폼 연결(APM 서비스에 연결된 <DNT>Azure</DNT> 리소스).

### 구독 간 관계 [#cross-subscription]

검색된 리소스가 다른 <DNT>Azure</DNT> 구독의 리소스에 연결되는 경우 <DNT>Infrastructure 360</DNT>은(는) 관계를 자동으로 해결합니다:

* 타겟 구독이 <DNT>Infrastructure 360</DNT>와(과)도 통합된 경우, 맵에 실제 타겟 엔티티와 그 세부 정보가 표시됩니다.
* 타겟 구독을 통합하거나 모니터하지 않은 경우 맵의 해당 위치에 알 수 없거나 계측되지 않은 엔티티가 표시됩니다 ― 연결은 여전히 표시되지만 엔티티 세부 정보는 사용할 수 없습니다.

### 설정 변경 사항을 알림과 연관시키십시오 [#correlate-config-changes]

<DNT>Infrastructure 360</DNT> <DNT>Azure</DNT> 리소스의 설정 변경 사항을 추적하므로 인프라 및 애플리케이션 데이터를 개별적으로 조사하는 대신 최근 변경 사항이 공지 또는 인시던트를 유발했는지 빠르게 파악할 수 있습니다.

1. <DNT>**All capabilities**</DNT> 로 이동하여 <DNT>**Azure Services**</DNT> 선택하세요.
2. 목록에서 임의의 엔티티를 선택하고 <DNT>**Configuration explorer**</DNT>을(를) 클릭하여 현재 설정, 태그 및 속성을 확인하십시오.
3. 설정 변경 타임라인의 타임스탬프를 알림 또는 인시던트와 비교해 주십시오. 공지와 비슷한 시기에 발생한 설정 변경은 근본 원인에 대한 강력한 신호이며, 이를 통해 설정 변경을 알림 및 인시던트와 연관 지을 수 있습니다.

## 인프라 360 설정 관리 [#manage-settings]

### 스캔 주기 조정 [#adjust-frequency]

<DNT>Infrastructure 360</DNT>이(가) <DNT>Azure</DNT> 환경을 스캔하는 빈도를 사용자 지정할 수 있습니다:

1. <DNT>**Infrastructure &gt; Azure**</DNT> 으로 이동하여 <DNT>**Manage Infrastructure 360**</DNT> 클릭합니다.
2. <DNT>Azure</DNT> 계정을 찾아 <DNT>**Edit**</DNT>을(를) 클릭하십시오.
3. 드롭다운 메뉴에서 원하는 스캔 빈도를 선택하십시오.
4. <DNT>**Save**</DNT> 클릭하여 변경 사항을 적용하세요.

<DNT>Azure</DNT> 환경을 자주 변경하는 경우 스캔 빈도를 늘리고, 인프라가 안정적이고 API 호출을 줄이려면 스캔 빈도를 줄이는 것을 고려하십시오.

### 인프라 360 비활성화 [#disable]

<Callout variant="important">
<DNT>Infrastructure 360</DNT>을(를) 비활성화하면 다음에 대한 액세스 권한을 잃게 됩니다:

* 자동으로 검색된 엔티티 및 해당 설정.
* <DNT>Azure</DNT> 리소스와 APM 서비스 간의 관계 매핑.
* 실시간 인프라 토폴로지 업데이트.
</Callout>

나중에 <DNT>Infrastructure 360</DNT>을(를) 다시 활성화하면 다음 예약된 스캔 중에 더 이상 존재하지 않는 엔티티와 관계를 다시 생성합니다.

<DNT>Infrastructure 360</DNT>을(를) 비활성화하려면 다음 단계를 따르십시오:

1. <DNT>**Infrastructure &gt; Azure**</DNT> 으로 이동하여 <DNT>**Manage Infrastructure 360**</DNT> 클릭합니다.
2. <DNT>Infrastructure 360</DNT>을(를) 비활성화할 계정을 찾으십시오.
3. <DNT>**Edit**</DNT>을(를) 클릭하고 스캔 토글을 꺼 주십시오.
4. 변경 사항을 확인하려면 <DNT>**Save**</DNT>을(를) 클릭하십시오.

## 무엇 향후 계획 [#next-steps]
