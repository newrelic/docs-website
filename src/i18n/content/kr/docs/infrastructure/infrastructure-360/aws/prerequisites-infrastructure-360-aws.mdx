<DNT>AWS</DNT>에 [<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360)을(를) 활성화하기 전에 다음 사항을 확인하십시오:

* <DNT>AWS</DNT> 계정에 대해 자동 검색이 활성화되었습니다.
* <DNT>CloudFormation</DNT> 스택이 설정 중에 부여하는 `cloudformation:StartResourceScan` 권한
* <DNT>Infrastructure 360</DNT>이(가) 스캔하는 리전의 리소스(아래의 [스캔 빈도](#scan-frequency) 참조).

## AWS에서 자동 검색이 지원하는 범위 [#coverage]

자동 검색은 연결된 <DNT>AWS</DNT> 계정을 스캔하고 지원되는 모든 리소스에 대해 뉴렐릭 엔티티를 생성한 다음, 해당 리소스가 서로 어떻게 연결되는지 파악하고 이러한 연결을 관계로 기록합니다. 자동 검색에는 에이전트가 필요하지 않습니다. 리소스는 계측되었는지 여부와 관계없이 표시됩니다.

자동 검색은 텔레메트리가 아니라 엔티티와 관계를 생성합니다. 검색된 리소스는 엔티티, 태그, <DNT>AWS</DNT> 설정 및 맵의 위치를 얻지만, 자동 검색은 이에 대한 메트릭이나 이벤트를 전송하지 않습니다. 차트와 알림을 확인하려면 <DNT>AWS</DNT> 메트릭을 연결하거나 에이전트도 설치하십시오.

이미 다른 방법으로 리소스를 모니터하는 경우(예: EC2 인스턴스의 인프라 에이전트 또는 RDS 인스턴스의 CloudWatch Metric Streams), 자동 검색은 중복을 생성하는 대신 해당 기존 엔티티에 추가합니다.

자동 검색은 66개의 <DNT>AWS</DNT> 리소스 유형을 지원하며, 65개의 엔티티 유형에 매핑됩니다.

## 관계 [#relationships]

자동 검색은 엔티티를 생성할 뿐만 아니라 리소스가 연결되는 방식을 파악하고 해당 연결을 관계로 기록합니다. 관계는 맵이 그리는 것이며, 로드 밸런서에서 그 뒤에 있는 데이터베이스까지 느린 요청을 트레이스할 수 있게 해주는 것입니다.

모든 관계는 소스, 관계 유형 및 타겟으로 구성됩니다. 예를 들어, `VPC CONTAINS Subnet` 또는 `S3 bucket TRIGGERS Lambda function`입니다. 순서가 중요합니다. 연결이 어느 방향으로 진행되는지 알려줍니다.

자동 검색은 많은 <DNT>AWS</DNT> 연결에 자연스러운 방향이 없으므로(VPC와 서브넷은 단순히 관련되어 있음) 대부분의 관계를 한 방향으로만 기록합니다. 맵은 자동 검색이 기록한 방식과 관계없이 양쪽 끝에서 연결을 올바르게 그립니다.

자동 검색은 리소스의 설정에서 직접 대부분의 관계를 읽지만, 일부 경우에는 이를 추론합니다. 예를 들어, 타겟 그룹이 명명된 인스턴스가 아닌 IP 주소로 라우팅되는 경우 타겟 IP를 네트워크 라우팅과 일치시켜 로드 밸런서 타겟 그룹을 올바른 호스트에 연결합니다.

## 스캔 빈도 [#scan-frequency]

자동 검색은 계정의 메트릭 폴링 간격을 기반으로 리전을 다시 스캔하며, 기본 빈도는 24시간입니다. 대신 8시간, 12시간 또는 16시간마다 다시 스캔이 실행되도록 구성할 수 있습니다. 최소 간격 길이는 8시간입니다. 간격을 8시간 미만으로 설정하면 자동으로 8시간으로 기본 설정됩니다.
