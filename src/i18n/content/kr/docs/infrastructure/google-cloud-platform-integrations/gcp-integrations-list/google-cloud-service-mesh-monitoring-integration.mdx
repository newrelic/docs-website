[뉴렐릭 통합](/docs/infrastructure/introduction-infra-monitoring) 에는 [Google Cloud Platform(GCP)](https://cloud.google.com/) 과의 [Google Cloud 서비스 메시](https://cloud.google.com/service-mesh/docs) (Istio) 데이터를 뉴렐릭에 보고하는 통합이 포함되어 있습니다. 이 문서에서는 GCP 클라우드 서비스 메시 통합을 활성화하는 방법과 보고되는 데이터에 대해 설명합니다.

## 특징

클라우드 서비스 메시는 Istio를 기반으로 구축된 Google Cloud의 관리형 서비스 메시입니다. 뉴렐릭 클라우드 서비스 메시 통합은 메시된 워크로드에서 내보내는 Istio 서비스 텔레메트리를 수집합니다: 인바운드 및 아웃바운드 요청 수, 요청 및 응답 크기, 서버 및 클라이언트 측 지연시간 분포.

이 통합은 클라우드 서비스 Mesh에 등록된 Cloud Run 워크로드로 범위가 지정됩니다. GKE 사이드카 워크로드(`istio_canonical_service` 모니터 리소스)의 Istio 텔레메트리는 이 통합에서 수집되지 않습니다.

## 통합 활성화 [#activate]

<Callout variant="important">
  이 통합은 GCP 프로젝트를 \[Workload Identity Federation]과 연결할 때만 사용할 수 있습니다.서비스 계정 또는 사용자 계정 연결에는 사용할 수 없습니다.
</Callout>

통합을 활성화하려면 표준 절차에 따라 Workload Identity Federation을 사용하여 [GCP 서비스를 뉴렐릭에 연결](/docs/connect-google-cloud-platform-services-infrastructure) 하십시오.

## 폴링 빈도 [#polling]

뉴렐릭 통합은 통합에 따라 달라지는 폴링 간격에 따라 GCP 서비스를 쿼리합니다. Google Cloud Service Mesh의 폴링 주기는 5분입니다. 해상도는 1분마다 1개의 데이터 포인트입니다.

## 워크로드 아이덴티티 페더레이션 [#wif]

### 데이터 찾기 및 사용 [#find-data-wif]

GCP 클라우드 모니터링에서 사용할 수 있는 모든 클라우드 서비스 메시 메트릭은 `Metric` 이벤트 유형에서 차원 메트릭으로 수집됩니다.

이 통합은 뉴렐릭 엔티티 탐색기에서 엔티티를 생성하지 않습니다. 예를 들어 `Metric` 이벤트 유형에서 직접 메트릭을 쿼리하십시오:

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.istio.io.%' FACET metricName
```

메트릭은 기본 Cloud Run 리비전의 리소스 레이블을 포함하므로, 엔티티 없이도 서비스 이름, 리비전 이름 및 위치별로 패싯할 수 있습니다.
