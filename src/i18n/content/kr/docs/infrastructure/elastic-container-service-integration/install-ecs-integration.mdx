뉴렐릭의 ECS 통합은 Amazon ECS 환경의 성능 데이터를 보고하고 표시합니다.

## 설치 개요 [#overview]

[설치](#install-options)하기 전에 인프라 에이전트(`newrelic-infra`)가 다음 두 가지 시작 유형에 대해 배포되는 방식을 개괄적으로 이해하는 데 도움이 될 수 있습니다.

* <DNT>**EC2 and EXTERNAL (ECS Anywhere) launch type:**</DNT> 데몬 스케줄링 전략은 뉴렐릭 에이전트를 ECS 클러스터에 서비스로 배포합니다. ([AWS 문서에 설명되어 있습니다](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/scheduling_tasks.html)) 그러면 클러스터의 모든 ECS 인스턴트에 에이전트가 설치되어 ECS와 Docker 컨테이너를 모니터링합니다.

* <DNT>**AWS Fargate launch type:**</DNT> 모니터링할 모든 작업에서 에이전트를 사이드카로 배포합니다. 선택 사항: [AWS가 사이드카를 정의하는 방법에 대해 자세히 알아보십시오](https://aws.github.io/copilot-cli/docs/developing/sidecars/).

## CloudFormation을 사용 설치 [#cloud-formation-install]

AWS CloudFormation을 사용해 설치할 수 있도록 뉴렐릭은 EC2, EXTERNAL(ECS Anywhere) 및 AWS Fargate 시작 유형의 AWS 계정에 ECS 통합을 설치하는 몇 가지 CloudFormation 템플릿을 제공합니다.

CloudFormation을 사용하여 설치하려면:

1. ECS 통합 작업을 등록하려면 [이 스택](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/task/master.yaml&stackName=NewRelicECSIntegration)을 배포합니다. 원하는 하나 이상의 지역에 스택이 배포되는지 확인합니다. 이 스택은 다음 리소스를 생성합니다:

   * 뉴렐릭 <InlinePopover type="licenseKey" />을 저장하는 시크릿
   * 라이선스 키에 액세스하기 위한 정책입니다.
   * 라이선스 키에 대한 액세스 권한이 있는 ECS 작업 `ExecutionRole`로 사용할 인스턴스 역할입니다.
   * EC2 및 외부(ECS Anywhere) 시작 유형에 대한 뉴렐릭 인프라 ECS 통합 작업 등록

2. 시작 유형에 대한 추가 지침을 따릅니다.

   <CollapserGroup>
     <Collapser id="ec2-cloudformation" title="EC2 시작 유형">
       모든 EC2 컨테이너 인스턴스에서 작업을 실행하는 서비스를 생성하려면 [이 스택](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/service.yaml&NewRelicInfraTaskVersion=1)을 배포합니다.

       EC2 시작 유형을 선택합니다. 그러면 클러스터에 `newrelic-infra`라는 서비스가 생성됩니다.
     </Collapser>

     <Collapser id="external-cloudformation" title="외부(ECS Anywhere) 시작 유형">
       모든 외부 컨테이너 인스턴스에서 작업을 실행하는 서비스를 생성하려면 [이 스택](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/service.yaml&NewRelicInfraTaskVersion=1)을 배포합니다.

       외부 실행 유형을 선택합니다. 그러면 클러스터에 `newrelic-infra-external`이라는 서비스가 생성됩니다.
     </Collapser>

     <Collapser id="fargate-cloudformation" title="AWS Fargate 시작 유형">
       1. 배포할 사이드카 컨테이너가 있는 작업 정의 예시를 다운로드합니다.

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
          ```

          <Callout variant="tip">
            Graviton의 경우, `"cpuArchitecture": "X86_64"`를 `"cpuArchitecture": "ARM64"`로 바꿉니다.
          </Callout>

       2. 이 작업 정의의 `newrelic-infra` 컨테이너를 모니터링하려는 작업 정의에 사이드카로 추가합니다. 이 예시 작업에서 애플리케이션의 컨테이너는 자리 표시자 `busybox` 컨테이너를 대체합니다.

       ### Fargate용 인프라 에이전트 전달 모드 구성 [#fargate-forward-modes]

       Fargate 환경에서 뉴렐릭 인프라 에이전트를 사이드카로 배포하는 경우 에이전트의 전달 모드를 구성해야 합니다. Fargate는 AWS가 기저 인프라를 관리하는 서버리스 컴퓨트 서비스이므로 에이전트는 호스트 수준 메트릭을 보고하거나 호스트 엔터티를 생성하려고 시도해서는 안 됩니다.

       #### 권장: NRIA\_IS\_FORWARD\_ONLY

       대부분의 Fargate 배포의 경우 `NRIA_IS_FORWARD_ONLY`를 `true`로 설정합니다:

       ```json
       {
         "name": "NRIA_IS_FORWARD_ONLY",
         "value": "true"
       }
       ```

       **Fargate에 이를 권장하는 이유:**

       * **불필요한 호스트 엔터티 생성 방지:** Fargate는 서버리스이고 AWS가 기본 컴퓨트 리소스를 관리하므로 인프라 에이전트는 뉴렐릭에 호스트 엔터티를 생성하지 않습니다.
       * **청구 불일치 방지:** 엔터티 기반으로 측정되는 요금은 모니터링되는 엔터티 수를 기준으로 합니다. 불필요한 호스트 엔터티가 생성되면 예상치 못한 비용이 야기될 수 있습니다.
       * **적절한 APM-컨테이너 연결 활성화:** APM 애플리케이션이 신세틱 호스트 엔터티가 아닌 컨테이너 엔터티에 올바르게 연결됩니다.
       * **통합 데이터에 집중:** 에이전트는 호스트 메트릭을 보고하지 않고 통합 데이터(데이터베이스, 웹 서버, 메시지 대기열 등)를 수집하고 전달합니다.

       #### 대안: NRIA\_IS\_SECURE\_FORWARD\_ONLY

       대체 전달 모드는 `NRIA_IS_SECURE_FORWARD_ONLY`입니다. 뉴렐릭 UI에서 호스트 엔터티에 대한 가시성이 필요한 경우 이를 `true`로 설정합니다.

       ```json
       {
         "name": "NRIA_IS_SECURE_FORWARD_ONLY",
         "value": "true"
       }
       ```

       **전달 모드 간의 차이점:**

       | 기능                     | NRIA\_IS\_FORWARD\_ONLY | NRIA\_IS\_SECURE\_FORWARD\_ONLY |
       | :--------------------- | :---------------------- | :------------------------------ |
       | NR1에 표시되는 호스트 엔터티      | 아니요                     | 예                               |
       | 인프라 UI에 표시되는 호스트 인벤토리  | 아니요                     | 예                               |
       | 통합 인벤토리                | 아니요                     | 예                               |
       | 전달된 통합 이벤트             | 예                       | 예                               |
       | 통합 엔터티(예: Redis 서버)    | 아니요                     | 예                               |
       | 호스트 메트릭(CPU, 메모리, 디스크) | 아니요                     | 아니요                             |
       | 컨테이너 메타데이터 장식됨         | 아니요                     | 예                               |
       | 통합 이벤트의 엔터티 메타데이터      | 아니요                     | 부분적                             |

       **각 모드가 사용되는 경우:**

       * **다음의 경우 `NRIA_IS_FORWARD_ONLY=true`를 사용(권장):**

         * 엔터티 수와 청구서에 미치는 영향을 최소화하려는 경우
         * 컨테이너 및 통합 모니터링만 필요한 경우
         * 뉴렐릭 UI에서 호스트 인벤토리를 볼 필요가 없는 경우

       * **다음의 경우 `NRIA_IS_SECURE_FORWARD_ONLY=true` 사용:**

         * 뉴렐릭 UI에서 호스트 메타데이터와 인벤토리 정보를 확인해야 하는 경우
         * 인프라 UI에 통합 엔터티를 표시하려는 경우
         * 엔티티 수가 문제가 되지 않는 경우

       *필수 Fargate 설정이 포함된 예제 작업 정의:*

       ```json
       {
         "family": "newrelic-infra-fargate",
         "networkMode": "awsvpc",
         "requiresCompatibilities": ["FARGATE"],
         "cpu": "256",
         "memory": "512",
         "containerDefinitions": [
           {
             "name": "newrelic-infra",
             "image": "newrelic/nri-ecs:latest",
             "essential": false,
             "environment": [
               {
                 "name": "NRIA_IS_FORWARD_ONLY",
                 "value": "true"
               },
               {
                 "name": "NRIA_LICENSE_KEY",
                 "value": "your-license-key"
               },
               {
                 "name": "NRIA_PASSTHROUGH_ENVIRONMENT",
                 "value": "ECS_CONTAINER_METADATA_URI,ECS_CONTAINER_METADATA_URI_V4,FARGATE"
               },
               {
                 "name": "FARGATE",
                 "value": "true"
               }
             ]
           },
           {
             "name": "your-application",
             "image": "your-app-image:latest",
             "essential": true
           }
         ]
       }
       ```

       <Callout variant="important">
         `NRIA_IS_FORWARD_ONLY=true` 환경 변수는 모든 Fargate 배포에 **필수**입니다. 이 설정을 생략하면 다음과 같은 결과가 발생할 수 있습니다:

         * 잘못된 호스트 엔터티 생성
         * APM-컨테이너 관계 실패
         * 예상치 못한 엔터티 수로 인한 청구 불일치

         예제 작업 정의를 다운로드하는 경우, 이 환경 변수가 존재하고 true로 설정되어 있는지 확인하십시오.
       </Callout>

       3. 작업 정의를 등록합니다.

          ```sh
          aws ecs register-task-definition --cli-input-json file://newrelic-infra-ecs-fargate-example-latest.json
          ```

       4. 이 작업 정의를 사용하여 서비스를 생성하거나 작업을 실행합니다.
     </Collapser>
   </CollapserGroup>

완료되면 [다음 단계](#next-steps)를 참조하십시오.

## 자동 스크립트로 설치 [#auto-script-install]

한 가지 [설치 옵션](#install-overview)은 설치 스크립트를 사용하는 것입니다. 자동 설치 스크립트를 사용하려면:

1. ECS 통합 설치 프로그램을 다운로드합니다.

   ```sh
   curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-installer.sh
   ```

2. 설치 프로그램에 실행 권한을 추가합니다.

   ```sh
   chmod +x newrelic-infra-ecs-installer.sh
   ```

3. 문서 및 요구 사항을 보려면 `-h`로 실행합니다.

   ```sh
   ./newrelic-infra-ecs-installer.sh -h
   ```

4. AWS 프로파일이 ECS 클러스터가 생성된 동일한 리전을 가리키는지 확인합니다.

   ```sh
   aws configure get region
   [output] us-east-1

   aws ecs list-clusters
   [output] YOUR_CLUSTER_ARNS 	
   [output] arn:aws:ecs:us-east-1:YOUR_AWS_ACCOUNT:cluster/YOUR_CLUSTER
   ```

5. <InlinePopover type="licenseKey" />및 클러스터 이름을 지정하여 설치 프로그램을 실행합니다.

   <CollapserGroup>
     <Collapser id="auto-script-ec2" title="EC2 시작 유형">
       ```sh
       ./newrelic-infra-ecs-installer.sh -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY
       ```
     </Collapser>

     <Collapser id="auto-script-external" title="외부(ECS Anywhere) 시작 유형">
       ```sh
       ./newrelic-infra-ecs-installer.sh -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY -e
       ```
     </Collapser>

     <Collapser id="auto-script-fargate" title="AWS Fargate 시작 유형">
       ```sh
       ./newrelic-infra-ecs-installer.sh -f -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY
       ```
     </Collapser>
   </CollapserGroup>

6. Fargate 시작 유형에 대한 추가 단계(EC2 시작 유형 아님):

   * 배포할 사이드카 컨테이너가 있는 작업 정의 예시를 다운로드합니다.

     ```sh
     curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
     ```

     <Callout variant="tip">
       Graviton의 경우, `"cpuArchitecture": "X86_64"`를 `"cpuArchitecture": "ARM64"`로 바꿉니다.
     </Callout>

     방금 생성한 역할인 `NewRelicECSTaskExecutionRole`을 작업 실행 역할로 사용해야 합니다.

     이 역할에는 모든 시작 유형을 위한 다음 정책이 포함됩니다:

     * `NewRelicSSMLicenseKeyReadAccess` 라이선스 키를 사용해 SSM에 대한 액세스를 활성화할 수 있도록 합니다.
     * `AmazonECSTaskExecutionRolePolicy`

   * 모니터하려는 컨테이너를 사이드카로 추가합니다.

   <Callout variant="important">
     AWS Fargate를 사용할 때 작업 정의 내에서 사이드카 컨테이너의 환경 변수 `NRIA_IS_FORWARD_ONLY`가 `true` 로 설정되어 있어야 합니다. 설정 세부 정보 및 이 설정이 중요한 이유에 대해서는 CloudFormation 아래의 [Fargate 설정 지침](#fargate-isforwardonly)을 참조하십시오.
   </Callout>

완료되면 [다음 단계](#next-steps)를 참조하십시오.

## 수동 설치

다른 [설치 옵션](#install-overview)은 [자동 인스톨러 스크립트](#auto-script-install)에서 수행하는 단계를 수동으로 수행하는 것입니다. `awscli` 툴을 사용하여 이 작업을 수행하는 방법을 설명합니다.

1. AWS 프로파일이 ECS 클러스터가 생성된 동일한 리전을 가리키는지 확인합니다.

   ```sh
   aws configure get region
   [output] us-east-1

   aws ecs list-clusters
   [output] YOUR_CLUSTER_ARNS
   [output] arn:aws:ecs:us-east-1:YOUR_AWS_ACCOUNT:cluster/YOUR_CLUSTER
   ```

2. <InlinePopover type="licenseKey" />를 Systems Manager(SSM) 매개변수로 저장합니다.

   ```sh
   aws ssm put-parameter \
     --name "/newrelic-infra/ecs/license-key" \
     --type SecureString \
     --description 'New Relic license key for ECS monitoring' \
     --value "NEW_RELIC_LICENSE_KEY"
   ```

3. 라이선스 키 파라미터에 액세스하기 위한 IAM 정책을 생성합니다.

   ```sh
   aws iam create-policy \
     --policy-name "NewRelicSSMLicenseKeyReadAccess" \
     --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["ssm:GetParameters"],"Resource":["ARN_OF_LICENSE_KEY_PARAMETER"]}]}' \
     --description "Provides read access to the New Relic SSM license key parameter"
   ```

4. 작업 실행 역할로 사용할 IAM 역할을 생성합니다.

   ```sh
   aws iam create-role \
     --role-name "NewRelicECSTaskExecutionRole" \
     --assume-role-policy-document '{"Version":"2008-10-17","Statement":[{"Sid":"","Effect":"Allow","Principal":{"Service":"ecs-tasks.amazonaws.com"},"Action":"sts:AssumeRole"}]}' \
     --description "ECS task execution role for New Relic infrastructure"
   ```

5. `NewRelicSSMLicenseKeyReadAccess` 및 `AmazonECSTaskExecutionRolePolicy` 정책을 역할에 연결합니다.

   ```sh
   aws iam attach-role-policy \
     --role-name "NewRelicECSTaskExecutionRole" \
     --policy-arn "POLICY_ARN"
   ```

6. 자세한 지침을 보려면 시작 유형을 선택합니다.

   <CollapserGroup>
     <Collapser id="manual-ec2" title="EC2 및 EXTERNAL(ECS Anywhere) 시작 유형">
       EC2 시작 유형에 대한 추가 단계:

       1. 뉴렐릭 ECS 통합 작업 정의 템플릿 파일을 다운로드합니다.

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-ec2-latest.json
          ```

       2. 템플릿 파일의 작업 실행 역할을 새로 생성된 역할로 바꿉니다.

          ```json
          "executionRoleArn": "NewRelicECSTaskExecutionRole",
          ```

       3. `secret`의 `valueFrom` 속성을 Systems Manager 매개변수의 이름으로 바꿉니다.

          ```json
          "secrets": [
            {
              "valueFrom": "/newrelic-infra/ecs/license-key",
              "name": "NRIA_LICENSE_KEY"
            }
          ],
          ```

       4. 작업 정의 파일을 등록합니다.

          ```sh
          aws ecs register-task-definition --cli-input-json file://newrelic-infra-ecs-ec2-latest.json
          ```

       5. 등록된 작업에 대한 [데몬 스케줄링](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) 전략을 사용하여 서비스를 생성합니다.

          EC2 시작 유형의 경우:

          ```sh
          aws ecs create-service --cluster "YOUR_CLUSTER_NAME" --service-name "newrelic-infra" --task-definition "newrelic-infra" --scheduling-strategy DAEMON --launch-type EC2
          ```

          EXTERNAL(ECS Anywhere) 시작 유형:

          ```sh
          aws ecs create-service --cluster "YOUR_CLUSTER_NAME" --service-name "newrelic-infra-external" --task-definition "newrelic-infra" --scheduling-strategy DAEMON --launch-type EXTERNAL
          ```
     </Collapser>

     <Collapser id="manual-fargate" title="AWS Fargate 시작 유형">
       AWS Fargate 시작 유형에 대한 추가 단계:

       1. 배포할 사이드카 컨테이너가 있는 작업 정의 예시를 다운로드합니다.

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
          ```

          <Callout variant="tip">
            Graviton의 경우, `"cpuArchitecture": "X86_64"`를 `"cpuArchitecture": "ARM64"`로 바꿉니다.
          </Callout>

       2. 이 작업 정의의 `newrelic-infra` 컨테이너를 모니터링하려는 작업 정의에 사이드카로 추가합니다. 이 예시 작업에서 애플리케이션의 컨테이너는 자리 표시자 `busybox` 컨테이너를 대체합니다.

       <Callout variant="important">
         수동으로 편집한 작업 정의 사이드카 컨테이너 설정에서는 환경 변수 `NRIA_IS_FORWARD_ONLY`를 `true` 로 구성해야 합니다. 자세한 지침과 전체 JSON 예제는 [CloudFormation Fargate 섹션](#fargate-isforwardonly)을 참조하십시오.
       </Callout>

## 생성된 AWS 리소스 [#aws-resources]

기본/권장 값을 사용하여 ECS 통합을 설치하면 AWS에서 다음을 수행합니다.

* Systems Manager(SSM) 매개변수 `/newrelic-infra/ecs/license-key`를 생성합니다. 이 시스템에는 뉴렐릭 <InlinePopover type="licenseKey" />가 포함되어 있습니다.

* 라이선스 키로 SSM 매개변수에 대한 액세스를 활성화하는 IAM 정책 `NewRelicSSMLicenseKeyReadAccess`를 생성합니다.

* [작업 실행 역할](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_execution_IAM_role.html)로 사용되는 IAM 역할`NewRelicECSTaskExecutionRole`을 생성합니다. 이 역할에는 다음 정책이 포함됩니다.

  * `NewRelicSSMLicenseKeyReadAccess` (설치 프로그램으로 생성)
  * `AmazonECSTaskExecutionRolePolicy`

* EC2 및 외부(ECS Anywhere) 시작 유형에 대한 `newrelic-infra` ECS 작업 정의를 등록합니다.

* EC2 [시작 유형](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/launch_types.html)을 위해 다음을 생성합니다.
  * [데몬 스케줄링](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) 전략 및 EC2 시작 유형을 사용하는 등록된 작업에 대한 서비스 `newrelic-infra`

* EXTERNAL(ECS Anywhere) [시작 유형](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/launch_types.html)에 대해 다음을 생성합니다.
  * [데몬 스케줄링](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) 전략 및 EXTERNAL(ECS Anywhere) 시작 유형을 사용하는 등록된 작업에 대한 서비스 `newrelic-infra-external`
