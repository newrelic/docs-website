AWS RDS PostgreSQL 인스턴스용 NRDOT Collector를 사용하여 PostgreSQL 모니터링을 설정하십시오. RDS 환경에는 확장 및 파라미터 그룹에 대한 특정 고려 사항이 있습니다.

<Steps>
  <Step>
    ## 전제 조건 [#prerequisites]

    설치하기 전에 다음을 갖추고 있는지 확인하십시오:

    * PostgreSQL `14` 이상
    * New Relic [라이센스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) .
    * NRDOT Collector를 설치한 호스트와 RDS PostgreSQL 인스턴스 간의 네트워크 연결.
    * [뉴렐릭 OTLP 엔드포인트 문서](/docs/opentelemetry/best-practices/opentelemetry-otlp/)에 대한 네트워크 연결
    * RDS 마스터 사용자 크리덴셜.
    * 이 통합은 뉴렐릭 퍼블릭 프리뷰 프로그램의 일환으로 제공됩니다. [미리 보기 및 평가판](https://one.newrelic.com/admin-portal/promotion-management/home) 페이지에서 옵트인하려면 조직 관리자에게 문의하세요.

    지원되는 PostgreSQL 버전, 필수 권한 및 권장 서버 파라미터에 대한 자세한 내용은 [호환성 및 필수 조건](/docs/opentelemetry/database/postgresql/compatibility)을 참조하십시오.
  </Step>

  <Step>
    ## NRDOT Collector 설정 [#setup]

    RDS 인스턴스에 연결할 수 있는 시스템에 NRDOT Collector를 설치하십시오.

    <CollapserGroup>
      <Collapser title="AMD64 아키텍처용" id="amd">
        * Debian/Ubuntu 시스템의 경우 다음 명령을 실행하십시오.

          ```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
          ```

        * RHEL/CentOS/OEL 시스템의 경우 다음 명령을 실행하십시오.

          ```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_x86_64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
          ```
      </Collapser>

      <Collapser title="ARM64 아키텍처용" id="arm">

  <Step>
    ## 데이터베이스 사용자 및 권한 설정 [#database-user]

    RDS PostgreSQL 인스턴스에 필요한 권한을 가진 모니터링 사용자를 생성하십시오.

    **모니터링 사용자 및 권한을 생성하려면:**

    1. 마스터 사용자로 RDS 인스턴스에 연결하십시오:

    ```shell
    psql --host=<YOUR_RDS_ENDPOINT> --dbname=postgres --port=5432 --username=<YOUR_MASTER_USERNAME>
    ```

    2. 모니터링 사용자를 생성하십시오:

    ```sql
    CREATE USER <YOUR_DB_USERNAME> WITH LOGIN PASSWORD '<YOUR_DB_PASSWORD>';
    ```

    3. 필요에 따라 모니터링 사용자 역할 멤버십을 부여하십시오:

    * PostgreSQL 15 이상을 사용하는 경우, 권한을 상속하도록 역할을 할당하십시오:

      ```sql
      ALTER ROLE <YOUR_DB_USERNAME> INHERIT;
      ```

      <Callout variant="tip">
        PostgreSQL 14를 사용하는 경우 모니터링 사용자가 기본적으로 권한을 상속하므로 이 단계를 건너뛸 수 있습니다.
      </Callout>

    * 모니터링하려는 모든 데이터베이스에 다음 스키마와 권한을 생성합니다:

      ```sql
      CREATE SCHEMA IF NOT EXISTS otel;
      GRANT USAGE ON SCHEMA otel TO <YOUR_DB_USERNAME>;
      GRANT USAGE ON SCHEMA public TO <YOUR_DB_USERNAME>;
      GRANT SELECT ON ALL TABLES IN SCHEMA public TO <YOUR_DB_USERNAME>;
      GRANT pg_monitor TO <YOUR_DB_USERNAME>;
      CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
      ```

    * (선택 사항) 벡터 메트릭을 수집하려면 각 데이터베이스에 `pgvector` 확장을 생성하십시오:

      ```sql
      CREATE EXTENSION IF NOT EXISTS vector;
      ```

      `l1`, `hamming` 및 `jaccard` 거리 함수에는 `pgvector` 버전 `0.7.0` 이상이 필요합니다.

    * (선택 사항) 연결 및 권한을 확인하려면 다음을 실행하십시오:

      ```shell
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> --command '\conninfo'
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_database LIMIT 1;" && echo "pg_stat_database OK"
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_activity LIMIT 1;" && echo "pg_stat_activity OK"
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_statements LIMIT 1;" && echo "pg_stat_statements OK"
      ```

      각 명령이 오류 없이 완료되면 모니터링 사용자, 호스트 및 포트가 모두 올바른 것입니다.
  </Step>

  <Step>
    ## NRDOT Collector구성 [#configure-collector]

    RDS PostgreSQL 관련 설정으로 NRDOT Collector를 구성하십시오. 모니터링 요구 사항에 따라 설정 유형을 선택하십시오:

    <CollapserGroup>
      <Collapser id="standard" title="표준 설정">
        이 설정은 `nrpostgresql` 수신기만 사용하여 필수적인 PostgreSQL 모니터링에 중점을 둡니다.

        1. 이름이 `postgresql-config.yaml`인 설정 파일을 생성합니다:

        ```bash
          sudo nano /etc/nrdot-collector/postgresql-config.yaml
        ```

        2. 이전 단계에서 생성한 `postgresql-config.yaml` 파일에 다음 설정을 추가하십시오.

        ```yaml
        receivers:
          nrpostgresql:
            endpoint: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
            username: "<YOUR_DB_USERNAME>"
            password: "<YOUR_DB_PASSWORD>"
            databases:
              - <YOUR_DATABASE_NAME>
            # top_query/query_sample scan pg_stat_statements/pg_stat_activity cluster-wide
            # regardless of the databases list above — on RDS/Aurora, exclude reserved
            # databases the monitoring user can never reach.
            exclude_databases:
              - rdsadmin
            collection_interval: 15s
            events:
              db.server.top_query:
                enabled: true
              db.server.query_sample:
                enabled: true
            top_query_collection:
              max_rows_per_query: 1000
              top_n_query: 200
              collection_interval: 60s
              allowed_comment_keys: [nr_service_guid]
            query_sample_collection:
              max_rows_per_query: 1000
              allowed_comment_keys: [nr_service_guid]
            # Metrics needed for the out-of-the-box dashboard but disabled by default —
            # see "Available metrics" below for the full default-on/default-off breakdown.
            metrics:
              postgresql.database.locks:
                enabled: true
              postgresql.deadlocks:
                enabled: true
              postgresql.function.calls:
                enabled: true
              postgresql.query.conflicts:
                enabled: true
              postgresql.sequential_scans:
                enabled: true
              postgresql.temp.io:
                enabled: true
              postgresql.temp_files:
                enabled: true

        processors:
          batch:
          # Static server.address/server.port instead of deriving them from
          # service.instance.id — with receiver.nrpostgresql.useOTelSemconv enabled,
          # service.instance.id becomes a UUID v5 hash, not a "host:port" string, so
          # a Split(...)-based transform breaks. Applies uniformly to both metrics
          # and logs pipelines since neither depends on that internal format.
          resource/postgresql:
            attributes:
              - key: server.address
                value: "<YOUR_DB_HOST>"
                action: upsert
              - key: server.port
                value: <YOUR_DB_PORT>
                action: upsert

        exporters:
          otlp/newrelic:
            endpoint: "<YOUR_NEWRELIC_OTLP_ENDPOINT>"
            headers:
              api-key: "<YOUR_NEWRELIC_LICENSE_KEY>"
            compression: gzip
            retry_on_failure:
              enabled: true
              initial_interval: 5s
              max_interval: 30s
              max_elapsed_time: 300s

        service:
          pipelines:
            metrics:
              receivers: [nrpostgresql]
              processors: [resource/postgresql, batch]
              exporters: [otlp/newrelic]
            logs:
              receivers: [nrpostgresql]
              processors: [resource/postgresql, batch]
              exporters: [otlp/newrelic]
        ```
      </Collapser>

      <Collapser id="full" title="전체 기능 설정">
        이 설정은 PostgreSQL 데이터베이스 모니터링과 함께 호스트 수준 메트릭(CPU, 메모리, 디스크, 네트워크)을 추가합니다.

        1. 이름이 `postgresql-config.yaml`인 설정 파일을 생성합니다:

        ```bash
          sudo nano /etc/nrdot-collector/postgresql-config.yaml
        ```

        2. 이전 단계에서 생성한 `postgresql-config.yaml` 파일에 다음 설정을 추가하십시오.

        <Callout variant="important">
          기존 NRDOT Collector 사용자인 경우 설정을 기존 `config.yaml` 파일과 병합하십시오. 여기에는 현재 설정을 유지하면서 PostgreSQL 데이터베이스 모니터링을 위한 새로운 수신기, 프로세서 및 내보내기 도구를 추가하는 것이 포함됩니다.
        </Callout>

        ```yaml
        extensions:
          health_check:

        receivers:
          otlp:
            protocols:
              grpc:
              http:

          host_metrics:
            collection_interval: 30s
            scrapers:
              cpu:
                metrics:
                  system.cpu.time:
                    enabled: false
                  system.cpu.utilization:
                    enabled: true
              load:
              memory:
                metrics:
                  system.memory.utilization:
                    enabled: true
              paging:
                metrics:
                  system.paging.utilization:
                    enabled: false
                  system.paging.faults:
                    enabled: false
              filesystem:
                metrics:
                  system.filesystem.utilization:
                    enabled: true
              disk:
                metrics:
                  system.disk.merged:
                    enabled: false
                  system.disk.pending_operations:
                    enabled: false
                  system.disk.weighted_io_time:
                    enabled: false
              network:
                metrics:
                  system.network.connections:
                    enabled: false
              # Uncomment to enable process metrics
              # processes:
              # process:
              #  metrics:
              #    process.cpu.utilization:
              #      enabled: true
              #    process.cpu.time:
              #      enabled: false

          nrpostgresql:
            endpoint: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
            username: "<YOUR_DB_USERNAME>"
            password: "<YOUR_DB_PASSWORD>"
            databases:
              - <YOUR_DATABASE_NAME>
            # top_query/query_sample scan pg_stat_statements/pg_stat_activity cluster-wide
            # regardless of the databases list above — on RDS/Aurora, exclude reserved
            # databases the monitoring user can never reach.
            exclude_databases:
              - rdsadmin
            collection_interval: 15s
            events:
              db.server.top_query:
                enabled: true
              db.server.query_sample:
                enabled: true
            query_sample_collection:
              max_rows_per_query: 1000
              allowed_comment_keys: [nr_service_guid]
            top_query_collection:
              max_rows_per_query: 1000
              top_n_query: 200
              collection_interval: 60s
              allowed_comment_keys: [nr_service_guid]
            # Metrics needed for the out-of-the-box dashboard but disabled by default —
            # see "Available metrics" in the docs for the full default-on/default-off breakdown.
            metrics:
              postgresql.database.locks:
                enabled: true
              postgresql.deadlocks:
                enabled: true
              postgresql.function.calls:
                enabled: true
              postgresql.query.conflicts:
                enabled: true
              postgresql.sequential_scans:
                enabled: true
              postgresql.temp.io:
                enabled: true
              postgresql.temp_files:
                enabled: true

        processors:
          metrics_transform:
            transforms:
              - include: system.cpu.utilization
                action: update
                operations:
                  - action: aggregate_labels
                    label_set: [state]
                    aggregation_type: mean
              - include: system.paging.operations
                action: update
                operations:
                  - action: aggregate_labels
                    label_set: [direction]
                    aggregation_type: sum

          filter/exclude_cpu_utilization:
            metrics:
              datapoint:
                - 'metric.name == "system.cpu.utilization" and attributes["state"] == "interrupt"'
                - 'metric.name == "system.cpu.utilization" and attributes["state"] == "nice"'
                - 'metric.name == "system.cpu.utilization" and attributes["state"] == "softirq"'

          filter/exclude_memory_utilization:
            metrics:
              datapoint:
                - 'metric.name == "system.memory.utilization" and attributes["state"] == "slab_unreclaimable"'
                - 'metric.name == "system.memory.utilization" and attributes["state"] == "inactive"'
                - 'metric.name == "system.memory.utilization" and attributes["state"] == "cached"'
                - 'metric.name == "system.memory.utilization" and attributes["state"] == "buffered"'
                - 'metric.name == "system.memory.utilization" and attributes["state"] == "slab_reclaimable"'

          filter/exclude_memory_usage:
            metrics:
              datapoint:
                - 'metric.name == "system.memory.usage" and attributes["state"] == "slab_unreclaimable"'
                - 'metric.name == "system.memory.usage" and attributes["state"] == "inactive"'

          filter/exclude_filesystem_utilization:
            metrics:
              datapoint:
                - 'metric.name == "system.filesystem.utilization" and attributes["type"] == "squashfs"'

          filter/exclude_filesystem_usage:
            metrics:
              datapoint:
                - 'metric.name == "system.filesystem.usage" and attributes["type"] == "squashfs"'
                - 'metric.name == "system.filesystem.usage" and attributes["state"] == "reserved"'

          filter/exclude_filesystem_inodes_usage:
            metrics:
              datapoint:
                - 'metric.name == "system.filesystem.inodes.usage" and attributes["type"] == "squashfs"'
                - 'metric.name == "system.filesystem.inodes.usage" and attributes["state"] == "reserved"'

          filter/exclude_system_disk:
            metrics:
              datapoint:
                - 'metric.name == "system.disk.operations" and IsMatch(attributes["device"], "^loop.*") == true'
                - 'metric.name == "system.disk.merged" and IsMatch(attributes["device"], "^loop.*") == true'
                - 'metric.name == "system.disk.io" and IsMatch(attributes["device"], "^loop.*") == true'
                - 'metric.name == "system.disk.io_time" and IsMatch(attributes["device"], "^loop.*") == true'
                - 'metric.name == "system.disk.operation_time" and IsMatch(attributes["device"], "^loop.*") == true'

          filter/exclude_network:
            metrics:
              datapoint:
                - 'IsMatch(metric.name, "^system.network.*") == true and attributes["device"] == "lo"'

          attributes/exclude_system_paging:
            include:
              match_type: strict
              metric_names:
                - system.paging.operations
            actions:
              - key: type
                action: delete

          cumulative_to_delta:

          transform:
            trace_statements:
              - context: span
                statements:
                  - truncate_all(span.attributes, 4095)
                  - truncate_all(resource.attributes, 4095)
                  
          transform/host:
            metric_statements:
              - context: metric
                statements:
                  - set(metric.description, "")
                  - set(metric.unit, "")

          # Static server.address/server.port instead of deriving them from
          # service.instance.id — with receiver.nrpostgresql.useOTelSemconv enabled,
          # service.instance.id becomes a UUID v5 hash, not a "host:port" string, so
          # a Split(...)-based transform breaks. Applies uniformly to both metrics
          # and logs pipelines since neither depends on that internal format.
          resource/postgresql:
            attributes:
              - key: server.address
                value: "<YOUR_DB_HOST>"
                action: upsert
              - key: server.port
                value: <YOUR_DB_PORT>
                action: upsert

          batch:

          resource_detection:
            detectors: ["system"]
            system:
              hostname_sources: ["os"]
              resource_attributes:
                host.id:
                  enabled: true

          resource_detection/cloud:
            detectors: ["gcp", "ec2", "azure"]
            timeout: 2s
            override: true

          resource_detection/env:
            detectors: ["env"]
            timeout: 2s
            override: true

        exporters:
          otlp/newrelic:
            endpoint: "<YOUR_NEWRELIC_OTLP_ENDPOINT>"
            headers:
              api-key: "<YOUR_NEWRELIC_LICENSE_KEY>"
            compression: gzip
            retry_on_failure:
              enabled: true
              initial_interval: 5s
              max_interval: 30s
              max_elapsed_time: 300s

        service:
          telemetry:
            metrics:
              level: none

          extensions: [health_check]

          pipelines:
            metrics/host:
              receivers: [host_metrics]
              processors:
                - metrics_transform
                - filter/exclude_cpu_utilization
                - filter/exclude_memory_utilization
                - filter/exclude_memory_usage
                - filter/exclude_filesystem_utilization
                - filter/exclude_filesystem_usage
                - filter/exclude_filesystem_inodes_usage
                - filter/exclude_system_disk
                - filter/exclude_network
                - attributes/exclude_system_paging
                - transform/host
                - resource_detection
                - resource_detection/cloud
                - resource_detection/env
                - cumulative_to_delta
                - batch
              exporters: [otlp/newrelic]

            metrics/postgresql:
              receivers: [nrpostgresql]
              processors:
                - resource/postgresql
                - resource_detection
                - resource_detection/cloud
                - resource_detection/env
                - batch
              exporters: [otlp/newrelic]

            logs/postgresql:
              receivers: [nrpostgresql]
              processors:
                - resource/postgresql
                - resource_detection
                - resource_detection/cloud
                - resource_detection/env
                - batch
              exporters: [otlp/newrelic]

            traces:
              receivers: [otlp]
              processors: [transform, resource_detection, resource_detection/cloud, resource_detection/env, batch]
              exporters: [otlp/newrelic]

            metrics:
              receivers: [otlp]
              processors: [resource_detection, resource_detection/cloud, resource_detection/env, batch]
              exporters: [otlp/newrelic]

            logs:
              receivers: [otlp]
              processors: [resource_detection, resource_detection/cloud, resource_detection/env, batch]
              exporters: [otlp/newrelic]
        ```

    ### 구성 매개변수

    다음 표에서는 `nrpostgresql` 수신자에 대한 주요 설정 초기화에 대해 설명합니다.

    | 매개변수                            | 설명                                                                                                                |
    | ------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_RDS_ENDPOINT>`           | RDS 인스턴스 엔드포인트 호스트명을 입력하십시오.                                                                                      |
    | `<YOUR_DB_PORT>`                | PostgreSQL 데이터베이스 포트를 입력하십시오.                                                                                     |
    | `<YOUR_DB_USERNAME>`            | 데이터베이스 사용자 이름을 입력하세요.                                                                                             |
    | `<YOUR_DB_PASSWORD>`            | 데이터베이스 비밀번호를 입력하세요.                                                                                               |
    | `<YOUR_DATABASE_NAME>`          | 모니터링할 데이터베이스의 이름을 입력합니다.                                                                                          |
    | `<YOUR_NEWRELIC_OTLP_ENDPOINT>` | 뉴렐릭 OTLP 엔드포인트를 입력하십시오. 자세한 내용은 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp/)를 참조하십시오. |
    | `<YOUR_NEWRELIC_LICENSE_KEY>`   | 뉴렐릭 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)를 입력하십시오.                               |
    | `collection_interval`           | 메트릭 스크랩 간격을 입력하십시오. 기본값: `15s`.                                                                                   |

    <Callout variant="tip">
      당신은 또한 수:

      * [다중 수신기 구성](/docs/opentelemetry/database/postgresql/multi-receiver): 하나의 수집기에서 여러 PostgreSQL 인스턴스를 모니터합니다.
      * [PostgreSQL 데이터베이스를 APM과 연결](/docs/opentelemetry/database/database-service-identification): 애플리케이션 성능을 데이터베이스 작업과 연관시키기 위함입니다. 이를 통해 특정 데이터베이스 워크로드를 생성하는 애플리케이션을 정확히 확인할 수 있습니다.
      * [EXPLAIN 계획 권한](/docs/opentelemetry/database/postgresql/explain-permissions): 모니터링 사용자에게 쓰기 권한을 부여하지 않고 잠금 또는 쓰기 명령문에 대한 쿼리 계획을 수집합니다.
      * [SQL 쿼리 수신기 설정](/docs/opentelemetry/database/capabilities/sql-query-receiver): PostgreSQL 데이터베이스에서 커스텀 지표를 수집합니다.
      * [시크릿 관리 설정](/docs/opentelemetry/database/database-service-identification/#secret-management): 데이터베이스 자격 증명과 같은 민감한 정보를 안전하게 관리하기 위함입니다. 이는 설정 파일에 민감한 데이터를 하드코딩하는 것을 방지하여 모니터링 설정의 보안을 강화하는 데 도움이 됩니다.
    </Callout>
  </Step>

  <Step>
    ## NRDOT Collector 설정 유효성 검사 [#validate]

    1. 새 `postgresql-config.yaml` 파일을 가리키도록 설정 경로를 업데이트하십시오:

    ```bash
      OTELCOL_OPTIONS="/etc/nrdot-collector/postgresql-config.yaml"
    ```

    2. NRDOT Collector 설정을 검증하여 형식이 올바르고 제대로 작동하는지 확인합니다:

    ```bash
      sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/postgresql-config.yaml
    ```
  </Step>

  <Step>
    ## NRDOT Collector를 다시 시작하십시오 [#restart-collector]

    수집기를 구성한 후 NRDOT Collector 서비스를 다시 시작하여 변경 사항을 적용합니다:

    ```bash
    sudo systemctl restart nrdot-collector
    ```

    수집기가 제대로 실행되고 있는지 확인하려면 서비스 상태를 확인하십시오:

    ```bash
    sudo systemctl status nrdot-collector
    ```

    <Callout variant="tip">
      새 설정이 적용되도록 설정을 변경한 후에는 항상 NRDOT Collector를 다시 시작하십시오.
    </Callout>
  </Step>

  <Step>
    ## 데이터 찾기 및 사용 [#find-use-data]

    쿼리 샘플 및 상위 쿼리는 로그 이벤트(`event.name = 'db.server.query_sample'` / `'db.server.top_query'`, `db.system.name = 'postgresql'`)로 도착합니다. 메트릭은 `postgresql.*` 네임스페이스 아래에 도착합니다.

    뉴렐릭에서 RDS PostgreSQL 데이터베이스 엔티티를 찾으려면 다음을 수행하십시오:

    1. <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT> 으)로 이동합니다.
    2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**PostgreSQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.
    3. 엔티티 목록에서 RDS PostgreSQL 데이터베이스를 선택하십시오.
  </Step>
</Steps>
