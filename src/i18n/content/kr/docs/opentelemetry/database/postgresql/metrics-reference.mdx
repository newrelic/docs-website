<Callout title="시사">
  이 기능은 아직 개발 중이지만 꼭 사용해 보시기 바랍니다!

  이 기능은 현재 [사전 출시 정책](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy/) 에 따라 미리보기의 일부로 제공됩니다.
</Callout>

NRDOT Collector는 광범위한 PostgreSQL 메트릭을 보고합니다. 뉴렐릭은 [기본 메트릭](#default)의 메트릭을 자동으로 수집합니다. 성능 및 상태에 대한 더 깊은 인사이트를 얻으려면 [추가 메트릭](#additional)에 나열된 메트릭을 활성화하십시오.

<Callout variant="tip">
  각 메트릭은 특정 데이터베이스, 테이블, 스키마 또는 인덱스로 범위가 지정됩니다. 이 컨텍스트는 메트릭 속성이 아닌 리소스에 설정됩니다.
</Callout>

    #### 실행 계획 수집(EXPLAIN) 메커니즘

    * **속도 제한:** `top_query_collection.max_explain_each_interval` (기본값 1,000)은 스크랩당 EXPLAIN을 제한합니다.
    * **캐싱:** `query_plan_cache_size` / `query_plan_cache_ttl` (기본값 1,000개 항목/1시간)은 한 번 얻은 계획을 쿼리 ID를 키로 사용하여 캐시합니다.
    * **PostgreSQL 12+ 요구 사항:** 매개변수화된 쿼리 EXPLAIN은 `PREPARE`/`EXPLAIN EXECUTE` 앞에 `plan_cache_mode = force_generic_plan`이(가) 필요합니다 ― PostgreSQL 12+에서만 사용할 수 있습니다. 이전 서버에서는 수신자가 버전을 감지하고 실패할 `SET`을(를) 보내는 대신 해당 쿼리에 대한 EXPLAIN을 건너뜁니다.
    * **권한 경계:** 기본적으로 EXPLAIN은 모니터링 사용자로 직접 실행되며, Postgres는 *계획* 시점에 테이블 권한을 확인합니다. ― 따라서 모니터링 사용자가 절대 가져서는 안 되는 쓰기 액세스 권한이 부여되지 않는 한, 행 잠금 또는 쓰기 명령문은 `permission denied` (으)로 실패합니다. 쓰기 액세스 권한을 부여하지 않고 이 문제를 해결하려면 `explain_function_name` ([EXPLAIN 계획 권한](/docs/opentelemetry/database/postgresql/explain-permissions) 참조)을(를) 사용하십시오.
    * 어떤 이유로든 계획을 얻을 수 없는 경우 해당 행에 대해 `postgresql.query_plan`은(는) 단순히 비어 있으며 ― 오류가 표시되지 않습니다.
