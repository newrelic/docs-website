## 단계별 설정

<Steps>
<Step>
### 설정 파일을 생성하십시오. [#create-config]

다음 설정을 `internal-telemetry-config.yaml`(으)로 저장하여 수집기의 [내부 텔레메트리](https://opentelemetry.io/docs/collector/internal-telemetry/)를 활성화하십시오:

```yaml
##### Example configuration for internal telemetry
# This configuration is intended to be used in conjunction with a configuration of components and pipelines. The
# collector supports config merging on startup.
##### Requirements
# - nrdot-collector (any distro) >= 1.3.0 or collector core version >= v1.35.0 / v0.129.0
##### Configuration via environment variables
# For official documentation, see: https://opentelemetry.io/docs/collector/internal-telemetry/
## Required
# - INTERNAL_TELEMETRY_NEW_RELIC_LICENSE_KEY
## Optional
# - INTERNAL_TELEMETRY_SERVICE_NAME: defaults to 'otel-collector'; determines entity name in New Relic
# - INTERNAL_TELEMETRY_OTLP_ENDPOINT: defaults to 'https://otlp.nr-data.net'; see https://docs.newrelic.com/docs/opentelemetry/best-practices/opentelemetry-otlp/ and https://docs.newrelic.com/docs/opentelemetry/best-practices/opentelemetry-otlp-troubleshooting/
# - INTERNAL_TELEMETRY_METRICS_LEVEL: defaults to 'detailed'; other values are 'normal', 'basic', 'none'
# - INTERNAL_TELEMETRY_LOG_LEVEL: defaults to INFO; other values are DEBUG, WARN, ERROR
# - INTERNAL_TELEMETRY_TRACE_LEVEL: defaults to 'none' (traces disabled); other value is 'basic'
# - INTERNAL_TELEMETRY_TRACE_SAMPLE_RATIO: defaults to 0.01, i.e. 1% sampling; has no effect if TRACE_LEVEL is 'none'
service:
  telemetry:
    metrics:
      level: "${env:INTERNAL_TELEMETRY_METRICS_LEVEL:-detailed}"
      readers:
        - periodic:
            exporter:
              otlp:
                protocol: http/protobuf
                endpoint: "${env:INTERNAL_TELEMETRY_OTLP_ENDPOINT:-https://otlp.nr-data.net}"
                temporality_preference: delta
                headers:
                  - name: api-key
                    value: "${env:INTERNAL_TELEMETRY_NEW_RELIC_LICENSE_KEY}"
    logs:
      level: "${env:INTERNAL_TELEMETRY_LOG_LEVEL:-INFO}"
      # default sampling config for reference to simplify overwrites even if not exposed via env var, e.g. --config=yaml:service::telemetry::logs::sampling::enabled::false
      sampling:
        enabled: true
        # The interval in seconds that the logger applies to each sampling.
        tick: 10s
        # The number of messages logged at the start of each sampling::tick
        initial: 10
        # Sets the sampling policy for subsequent messages after sampling::initial messages are logged. When sampling::thereafter is set to N, every Nth message is logged and all others are dropped. If N is zero, the logger drops all messages after sampling::initial messages are logged.
        thereafter: 100
      processors:
        - batch:
            exporter:
              otlp:
                protocol: http/protobuf
                endpoint: "${env:INTERNAL_TELEMETRY_OTLP_ENDPOINT:-https://otlp.nr-data.net}"
                headers:
                  - name: api-key
                    value: "${env:INTERNAL_TELEMETRY_NEW_RELIC_LICENSE_KEY}"
    traces:
      # traces are disabled by default due to experimental status and lack of default sampling rate that works across use cases
      level: "${env:INTERNAL_TELEMETRY_TRACE_LEVEL:-none}"
      sampler:
        parent_based:
          root:
            trace_id_ratio_based:
              ratio: ${env:INTERNAL_TELEMETRY_TRACE_SAMPLE_RATIO:-0.01}
      processors:
        - batch:
            exporter:
              otlp:
                protocol: http/protobuf
                endpoint: "${env:INTERNAL_TELEMETRY_OTLP_ENDPOINT:-https://otlp.nr-data.net}"
                headers:
                  - name: api-key
                    value: "${env:INTERNAL_TELEMETRY_NEW_RELIC_LICENSE_KEY}"
    resource:
      service.name: "${env:INTERNAL_TELEMETRY_SERVICE_NAME:-otel-collector}"
```
</Step>

<Step>
### 환경 변수 설정 [#set-env-vars]

* <DNT>`INTERNAL_TELEMETRY_NEW_RELIC_LICENSE_KEY`</DNT>: 내부 텔메트리 계정에 대한 Ingest 키가 전송되어야 합니다. 이 키는 수집기가 뉴렐릭에게 일반 데이터를 보낼 때 사용하는 키(예: 아래 예시의 <DNT>`NEW_RELIC_LICENSE_KEY`</DNT> 와 다를 수 있습니다.
* <DNT>`INTERNAL_TELEMETRY_SERVICE_NAME`</DNT>: 기본값은 `otel-collector` 이며, 편집 이름을 뉴렐릭으로 결정합니다.
* <DNT>`INTERNAL_TELEMETRY_OTLP_ENDPOINT`</DNT>: US `https://otlp.nr-data.net`이(가) 기본값입니다, EU에 있는 경우 이를 `https://otlp.eu01.nr-data.net`(으)로 설정하고, JP에 있는 경우 이를 다음으로 설정합니다 `https://otlp.jp.nr-data.net`
</Step>

<Step>
### 병합된 설정으로 수집기 실행 [#run-collector]

구성 요소 및 파이프라인에 대한 일반 설정(다음 예 `--config=/etc/nrdot-collector/config.yaml`) 외에도 두 설정을 병합하는 두 번째 인수 `--config` 를 추가합니다.

```bash
docker run \
  -e INTERNAL_TELEMETRY_NEW_RELIC_LICENSE_KEY='...' \
  -e NEW_RELIC_LICENSE_KEY='...' \
  -e INTERNAL_TELEMETRY_SERVICE_NAME='demo-collector' \
  -v './internal-telemetry-config.yaml:/etc/nrdot-collector/config-internal.yaml' \
  newrelic/nrdot-collector:2.8.1 --config=/etc/nrdot-collector/config.yaml \
  --config='/etc/nrdot-collector/config-internal.yaml'
```

<Callout variant="important">
`service::telemetry` 노드 아래에 기존 설정이 있는 경우 `--config` 인수의 순서가 중요합니다. 수집기는 설정과 구성의 특정 부분(예: 리스트, 리프 노드)는 병합할 수 없으므로 마지막 `--config` 인수로 덮어쓰여집니다.
</Callout>
</Step>

<Step>
### 뉴렐릭이 수집기를 감지할 때까지 기다려 주십시오. [#auto-detection]

다른 것은 설정할 필요가 없습니다. 뉴렐릭은 수집기를 자동으로 감지하고 해당 엔티티에 대한 수집기 환경을 표시합니다.

이면에서 대부분의 수집기 내부 메트릭은 이름이 <DNT>`otelcol`</DNT>(으)로 시작합니다. 엔티티가 이 접두사가 있는 메트릭을 전송하면, 뉴렐릭은 엔티티 태그 <DNT>`otelCollector: opentelemetry`</DNT>을(를) 추가하여 해당 엔티티를 수집기로 표시합니다. 이 작업은 데이터 수집 시 발생하므로, 첫 번째 데이터가 도착한 후 화면이 표시되기까지 몇 분 정도 걸릴 수 있습니다.

감지되면 [UI에서 수집기 보기](/docs/opentelemetry/collector-observability/collector-observability#view-ui)를 참조하여 수집기의 데이터를 탐색해 보십시오.
</Step>

<Step>
### 선택 사항: 설정을 사용자 지정하십시오. [#customize]

기본 설정은 세부 수준 및 샘플링과 같은 공통 옵션을 조정하기 위해 `INTERNAL_TELEMETRY_...` 형태의 추가 환경 변수를 제공합니다. 자세한 내용은 [설정 자체](#create-config)를 참조하십시오.

수집기를 모니터하기 위해 기본 설정을 사용하는 것을 권장합니다. 하지만 세부 수준, 샘플링 속도 또는 데이터 수집 속도를 줄이는 등 예제 설정을 수정할 수 있습니다. 자세한 내용은 [공식 문서](https://opentelemetry.io/docs/collector/internal-telemetry/)를 참조하십시오. 설정을 변경하면 UI의 특정 부분에 데이터가 표시되지 않을 수 있다는 점에 유의하십시오. 또한 [FAQ](/docs/opentelemetry/collector-observability/collector-observability-faq)를 참조하십시오. 수집기의 내부 텔레메트리 설정 옵션은 OTel 커뮤니티가 발전함에 따라 변경됩니다. 필요에 따라 제공된 기본값을 사용하거나 수정할 수 있습니다.
</Step>
</Steps>

## 간접비 고려 사항 [#overhead]

모든 텔레메트리와 마찬가지로 수집기의 내부 텔레메트리는 데이터 수집을 증가시킵니다. 오버헤드는 워크로드와 설정에 따라 다릅니다. 고려해야 할 주요 요소는 다음과 같습니다.

**메트릭은** 처리량과 관계없이 수집기 및 모든 활성 구성 요소에 지속적인 오버헤드를 발생시킵니다. 알림은 일정한 간격(기본값 60초)으로 전송됩니다. 모든 구성 요소는 각각의 [메타데이터.yaml](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/processor/filterprocessor/metadata.yaml#L20) 에 표시된 대로 맞춤 지표를 내보낼 수 있습니다. 이는 간접비용을 증가시킬 수 있습니다.

수집기가 방출하는 철의 양을 줄여야 하는 경우 철 레벨을 <DNT>`normal`</DNT> 으로 설정하는 것이 좋습니다. 예를 들어 예제 구성의 환경 변수 <DNT>`INTERNAL_TELEMETRY_METRICS_LEVEL`</DNT> 통해 UI에서 <DNT>`detailed`</DNT> 메트릭의 하위 집합만 사용되며 일반적으로 성능 또는 네트워크 문제를 미세 조정하기 위한 메트릭이므로 필요에 따라 다시 활성화할 수 있습니다.

**로그** 정상 작동 중에는 로그가 미치는 영향이 거의 없습니다. 오류 로그가 급격히 증가할 때 더 높은 오버헤드가 발생할 수 있지만, 로그는 기본적으로 샘플링되므로 이러한 오버헤드가 감소합니다. 샘플링 알고리즘은 정의된 간격당 일정한 수의 로그를 허용한 다음 정적 비율로 샘플링합니다. [설정](#create-config)에서 <DNT>`service::telemetry::logs::sampling`</DNT>을(를) 참조하십시오.

**트레이스** 기본적으로 비활성화되어 있습니다. 자세한 내용은 [FAQ](/docs/opentelemetry/collector-observability/collector-observability-faq#traces-disabled)를 참조하십시오. 트레이스가 개발되는 동안 이를 실험하려면 <DNT>`INTERNAL_TELEMETRY_TRACE_LEVEL=basic`</DNT>을(를) 설정하고, 수집 볼륨을 모니터링하고 필요에 따라 조정하면서 <DNT>`INTERNAL_TELEMETRY_TRACE_SAMPLE_RATIO=0.001`</DNT> (0.1%)과 같은 낮은 샘플링 속도로 시작하십시오.

### 예: 인프라 관계 채우기(선택 사항)

[요약 페이지](/docs/opentelemetry/collector-observability/collector-observability#summary-page)에서 언급했듯이, APM은 수집기가 실행 중인 인프라에 대한 인프라 메트릭을 표시할 수 있지만, 이는 인프라가 계측되고 [관계](https://docs.newrelic.com/docs/new-relic-solutions/new-relic-one/core-concepts/what-entity-new-relic/#related-entities)가 형성될 수 있는 경우에만 가능합니다. 이 관계는 수집기의 내부 텔레메트리에 있는 추가 속성에 의해 결정됩니다. 이 주제에 대한 자세한 내용은 [OTel 문서](https://docs.newrelic.com/docs/opentelemetry/best-practices/opentelemetry-best-practices-resources/#service-to-infra-otel-collector)를 확인하십시오. 이를 설정하는 단계는 정확한 인프라에 따라 크게 달라집니다. 일반적으로 선택하는 Kubernetes의 경우,[당사의 Kubernetes용 OTel 솔루션](https://docs.newrelic.com/docs/kubernetes-pixie/k8s-otel/intro/) 을 기반으로 컨테이너-서비스 관계를 형성하는 방법을 [보여주는 예제 를 만들었습니다.](https://github.com/newrelic/newrelic-opentelemetry-examples/tree/main/other-examples/collector/internal-telemetry-k8s-container-relationships)
