[Collector 옵저버빌리티 요약 페이지](/docs/opentelemetry/collector-observability/collector-observability#summary-page)는 수집기의 상태를 한눈에 파악할 수 있는 6개의 핵심 성과 지표(KPI) 타일과 함께 열립니다. 타일을 클릭하여 KPI의 예기치 않은 변화를 조사하는 데 도움이 되는 관련 텔레메트리 차트 세트와 기본 차트가 포함된 상세 뷰를 여십시오. 대부분의 경우, 특정 신호 유형을 선택할 때 관련 텔레메트리를 신호 유형이나 구성 요소(익스포터/프로세서/리시버)별로 패싯할 수 있습니다. 이 페이지에서는 각 KPI의 의미와 관련된 각 텔레메트리 차트가 존재하는 이유를 설명합니다.

## 수신된 항목 [#items-received]

수신기를 통해 수집기로 들어오는 텔레메트리의 양입니다. 예기치 않은 변경의 일반적인 원인은 업스트림 클라이언트 문제 — 데이터를 보내는 계측된 애플리케이션이 더 적거나 많음 — 또는 수신기가 가져오도록 구성된 데이터를 스크랩하지 못하는 경우입니다.

관련 텔레메트리:

* <DNT>**Receiver accepted**</DNT>: 총계를 신호 또는 수신기별로 분류하므로 변경이 정확히 어디서 비롯되었는지 알 수 있습니다.
* <DNT>**Receiver refused**</DNT>: 감소의 일부가 업스트림 트래픽의 감소가 아니라 거부된 텔레메트리(또한 [수신기 거부](#receiver-refused) 참조)로 인한 것인지 보여줍니다.
* <DNT>**Memory limiter drop ratio**</DNT>: 수신기가 데이터를 거부하는 것은 궁극적으로 [memorylimiter](https://github.com/open-telemetry/opentelemetry-collector/tree/v0.161.0/processor/memorylimiterprocessor) 차단 때문일 수 있습니다.

## 전송된 항목 [#items-sent]

수집기의 익스포터가 다운스트림 대상으로 성공적으로 전송한 텔레메트리입니다. 예기치 않은 변화의 일반적인 원인은 업스트림 문제(프로세서의 데이터 삭제, 수신기의 데이터 거부 또는 클라이언트가 수집기에 더 적은 데이터를 제공함) 또는 익스포터 오류입니다.

관련 텔레메트리:

* <DNT>**Exporter sent**</DNT>: 전체를 시그널 또는 익스포터별로 세분화하여 변경 사항이 정확히 어디에서 발생했는지 파악할 수 있습니다.
* <DNT>**Exporter failures**</DNT>: 전송되는 항목이 줄어드는 원인으로 익스포터 실패([익스포터 실패율](#export-failure-rate) 참조)를 나타냅니다.
* <DNT>**Exporter queue saturation**</DNT>: 포화 상태의 전송 대기열([대기열 포화](#queue-saturation) 참조)이 항목 전송을 지연시키고 있는지 여부를 보여줍니다.

## 대기열 포화 [#queue-saturation]

각 익스포터의 전송 대기열이 얼마나 차 있는지 나타냅니다, 대기열이 꽉 차면 데이터 손실이 발생합니다. 포화도가 급증하는 일반적인 원인은 대기열을 적체시키는 익스포터 실패나 너무 작은 대기열에 트래픽이 급증하는 경우입니다.

관련 텔레메트리:

* <DNT>**Exporter send failures**</DNT>: 실패한 내보내기는 종종 더 오래 걸립니다. 예를 들어 시간 초과가 발생할 수 있으며, 이는 대기열에 적체를 유발하는 재시도로 이어집니다.
* <DNT>**Exporter queue size vs. capacity**</DNT>: 구성된 용량 대비 원시 대기열 크기를 보여주므로, 포화 상태가 트래픽 급증으로 인한 것인지 아니면 단순히 대기열 크기가 너무 작아서 발생한 것인지 알 수 있습니다.

## 리시버 거부됨 [#receiver-refused]

수신기가 적극적으로 거부하고 있는 업스트림 텔레메트리입니다. 이 값은 일반적으로 0이어야 하며, 지속적인 비율은 로그를 통해 진단해야 하는 이상 징후입니다.

관련 텔레메트리:

* <DNT>**Memory limiter drop ratio**</DNT>: 실제 근본 원인인 [memorylimiter](https://github.com/open-telemetry/opentelemetry-collector/tree/v0.161.0/processor/memorylimiterprocessor) 프로세서가 차단되면 리시버가 텔레메트리 거부를 시작합니다.
* <DNT>**Process memory RSS**</DNT>: 수집기의 메모리 사용량을 표시하여 memorylimiter 메트릭을 맥락화합니다.
* <DNT>**Process runtime heap allocated**</DNT>: Go 힙이 증가하면 비정상적인 가비지 컬렉션이 발생할 수 있으며, 이는 결과적으로 수집기의 처리량을 저하시킬 수 있습니다.

## 내보내기 실패율 [#export-failure-rate]

구성된 경우, 실패하여 재시도되는 익스포터 requests의 백분율입니다. 일반적인 원인은 네트워크 문제 또는 익스포터나 대상의 잘못된 구성입니다.

관련 텔레메트리:

* <DNT>**Exporter failures**</DNT>: 시그널 또는 익스포터별 실패의 절대 수(분자)를 보여주므로, 실패가 정확히 어디에서 발생하는지 확인할 수 있습니다.
* <DNT>**Exporter sent**</DNT>: 실패 및 비율을 전체적인 관점에서 파악할 수 있도록 내보내기의 절대 수(분모)를 표시합니다.

## 큐 드롭 [#queue-drops]

큐가 가득 차서 수집기가 내보내기를 위해 큐에 대기시킬 수 없었던 텔레메트리입니다. 큐에 대기되지 않은 데이터는 삭제됩니다. 즉, 데이터 손실이 확인된 것입니다.

관련 텔레메트리:

* <DNT>**Exporter enqueue failures**</DNT>: 확인된 데이터 손실을 시그널 또는 익스포터별로 분류합니다.
* <DNT>**Exporter queue size vs. capacity**</DNT>: 대기열이 빠르게 채워졌는지(예: 트래픽 급증) 또는 점진적으로 채워졌는지(예: 크기가 작은 수집기, 크기가 작은 대기열 또는 지속적인 실패 누적) 여부를 표시합니다.
* <DNT>**Exporter failures**</DNT>: 내보내기 실패로 인해 종종 대기열이 가득 찰 때까지 항목이 누적되므로, 이것이 근본 원인인지 확인하는 데 도움이 됩니다.
