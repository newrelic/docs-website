이 가이드에서는 매니페스트 설치를 사용하여 Kubernetes에 NRDOT를 배포함으로써 Elasticsearch 파드를 자동으로 검색하고, 클러스터, 노드 및 JVM 메트릭을 수집하며, 이를 뉴렐릭으로 스트리밍하여 클러스터의 상태와 성능을 모니터링하는 방법을 안내합니다.

## 호환성 및 요구 사항 [#requirements]

### 지원

* 쿠버네티스 클러스터에서 파드로 실행되는 Elasticsearch 7.16 이상
* 매니페스트 설치 방법

### 필요한 사항

* 뉴렐릭 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* `kubectl` 쿠버네티스 클러스터에 대한 액세스
* 기본 [Kubernetes OpenTelemetry 매니페스트 설치](/docs/kubernetes-pixie/k8s-otel/install/#manifest-install)가 이미 완료되었습니다
* `monitor` 또는 `manage` 클러스터 권한이 있는 Elasticsearch 사용자([Elasticsearch 보안 권한](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html) 참조)
* 뉴렐릭의 [OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp)에 대한 아웃바운드 HTTPS(포트 443) 연결
* Elasticsearch 사용자 이름 및 비밀번호(클러스터에 인증이 필요한 경우)

<Step>
## 파드 레이블 설정 [#pod-labels]

자동 검색이 작동하려면 각 Elasticsearch 파드에 `app: elasticsearch` 레이블이 있어야 합니다. 이 레이블이 없으면 수집기가 파드를 감지하거나 모니터링하지 않습니다.

StatefulSet을 사용하거나 Elasticsearch 용 배포를 구현하는 경우 파드 템플릿에 레이블을 추가하세요.

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: elasticsearch
spec:
  template:
    metadata:
      labels:
        app: elasticsearch  # Required for auto-discovery
    spec:
      containers:
      - name: elasticsearch
        image: docker.elastic.co/elasticsearch/elasticsearch:8.x.x
```

레이블이 없는 기존 파드의 경우, StatefulSet/배포를 업데이트하고 파드를 다시 시작하십시오:

```bash
kubectl label pods -l <your-existing-selector> app=elasticsearch -n <namespace>
```

레이블이 올바르게 설정되었는지 확인할 수 있습니다.

```bash
kubectl get pods -n <namespace> --show-labels
```
</Step>

## 수집기 이미지 및 설정을 준비하십시오. [#prepare]

수집기 이미지를 업데이트한 다음, 로컬 매니페스트 파일에서 Elasticsearch 모니터링 설정을 정의하십시오. 다음 단계에서 클러스터에 이 변경 사항을 적용합니다.

1. 로컬 `rendered` 디렉터리에 있는 [`deployment.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/deployment.yaml) 및 [`daemonset.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/daemonset.yaml) 두 파일 모두에서 수집기 이미지를 NRDOT로 업데이트해 주십시오:

### 구성 매개변수 [#configuration-parameters]

다음 표는 위의 `deployment-configmap.yaml`에서 사용되는 주요 설정 파라미터를 설명합니다:

| 매개변수                                                                              | 설명                                                                                                                           |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `rule`                                                                            | 자동 검색에 사용되는 파드 일치 규칙입니다. 파드 레이블과 일치하도록 `labels["app"] == "elasticsearch"`을(를) 업데이트하십시오.                                      |
| `endpoint`                                                                        | 검색된 각 파드에서 스크랩된 Elasticsearch 엔드포인트입니다. Elasticsearch가 다른 포트에서 실행되는 경우 포트 `9200`을(를) 업데이트하고, 보안 클러스터의 경우 `https`을(를) 사용하십시오. |
| `collection_interval`                                                             | 메트릭 스크랩 간격입니다. 기본값은 15s입니다.                                                                                                  |
| `elasticsearch-cluster` (`resource/cluster` / `resource/cluster_name_override`에서) | 뉴렐릭에서 이 클러스터를 식별하는 고유한 이름입니다. 계정 전체에서 고유한 이름으로 변경하십시오.                                                                       |
| `NEW_RELIC_MEMORY_LIMIT_MIB`                                                      | 수집기의 `memory_limiter` 프로세서에 대한 메모리 제한(MiB)입니다. 환경에 맞게 설정하십시오.                                                                |
| `NEWRELIC_LICENSE_KEY`                                                            | 귀하의 New Relic [라이센스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) .                                       |
| `NEWRELIC_OTLP_ENDPOINT`                                                          | 계정 리전의 뉴렐릭 OTLP 엔드포인트입니다. [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp)를 참조하십시오.                   |
</Step>

<Step>
## kubectl을 통해 NRDOT 수집기를 설치하고 구성합니다. [#install-manifest]

업데이트된 매니페스트를 적용하여 방금 준비한 이미지와 설정으로 NRDOT 수집기를 클러스터에 배포하십시오.

```bash
kubectl apply -n newrelic -R -f rendered
```
</Step>

<Step>
## NRDOT 수집기 파드를 재시작하십시오 [#restart]

변경 사항을 적용하려면 배포를 재시작하십시오:

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```
</Step>

<Step>
## 설치 확인 [#verify]

설치 후 약 5분 이내에 뉴렐릭에서 이 쿼리를 실행하여 데이터가 수신되는지 확인하십시오(`elasticsearch-cluster`을(를) 클러스터 이름으로 변경하십시오):

```sql
FROM Metric
SELECT *
WHERE metricName LIKE 'elasticsearch.%'
  AND instrumentation.provider = 'opentelemetry'
  AND k8s.cluster.name = 'elasticsearch-cluster'
SINCE 10 minutes ago
```

<Callout variant="tip">
수집기 자체를 확인할 수도 있습니다. 파드는 `Running` 상태(`kubectl get pods -n newrelic --watch`)여야 하고 이름은 `nr-k8s-otel-collector-deployment-<hash>`와(과) 같아야 하며, 파드 로그(`kubectl logs -n newrelic -l app.kubernetes.io/name=nr-k8s-otel-collector -f`)에 연결 오류가 없어야 합니다.
</Callout>

약 5분 이내에 데이터가 표시되지 않으면 [Kubernetes 문제 진단, 해결](/docs/opentelemetry/integrations/elasticsearch/troubleshooting#kubernetes-troubleshooting)을 참조하십시오.
</Step>

<Step>
## 데이터 찾기 및 사용 [#find-and-use]

뉴렐릭이 데이터를 수집하면 뉴렐릭 UI를 통해 Elasticsearch 모니터링에 액세스할 수 있습니다.

뉴렐릭에서 Elasticsearch 대시보드를 찾으려면:

1. <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT> 으)로 이동합니다.
2. <DNT>**All**</DNT> 탭에서 <DNT>**Dashboards**</DNT>을(를) 클릭한 다음, <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT>을(를) 검색하여 대시보드를 확인하십시오.

또는 왼쪽 탐색 메뉴에서:

1. <DNT>**Dashboards**</DNT> 을(를) 클릭합니다.
2. <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> 대시보드를 검색하여 확인하십시오.

NRDOT로 Elasticsearch 모니터링을 설정한 후 다음을 수행할 수 있습니다:

* Elasticsearch 메트릭을 시각화하기 위한 [커스텀 대시보드 생성](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)
* 중요한 클러스터 상태 및 성능 임계값에 대한 [알림 설정](/docs/alerts/create-alert/create-alert-condition/alert-conditions/)
* 뉴렐릭 쿼리 기능을 사용하여 [데이터 탐색](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)
</Step>
</Steps>

<Callout variant="tip">
**APM과 Elasticsearch 연관시키기**: APM 애플리케이션과 Elasticsearch 클러스터를 연결하려면 APM 메트릭에 리소스 속성 `es.cluster.name="your-cluster-name"`을(를) 포함하십시오. 이를 통해 뉴렐릭에서 APM 및 Elasticsearch 데이터를 함께 볼 수 있습니다.
</Callout>
