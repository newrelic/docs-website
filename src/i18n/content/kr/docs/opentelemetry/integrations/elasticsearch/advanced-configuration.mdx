이 페이지에서는 최소 설정 외에 보안 클러스터, 호스트 메트릭, 로그 수집, 사용자 지정 메타데이터 태그 등 Elasticsearch 모니터링을 위한 선택적 설정을 다룹니다.

## 인증 및 SSL이 적용된 보안된 Elasticsearch [#secured]

클러스터에서 요구하는 경우 Elasticsearch 연결에 인증 및 TLS를 추가하십시오.

### 요구 사항 [#secured-requirements]

* `monitor` 또는 `manage` 클러스터 권한과 해당 사용자에 대한 유효한 자격 증명을 가진 Elasticsearch 사용자입니다.

인증 및 SSL이 적용된 보안 Elasticsearch의 경우 수신자 설정을 수정하십시오:

<CollapserGroup>
<Collapser id="secured-nrdot" title="NRDOT">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-otel" title="OTel Collector Contrib">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-k8s-nrdot" title="Kubernetes: NRDOT(매니페스트 또는 Helm)">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>

<Collapser id="secured-k8s-otel" title="Kubernetes: OTel Collector Contrib">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>
</CollapserGroup>

### 구성 매개변수 [#secured-configuration-parameters]

다음 표는 위의 스니펫에서 사용된 주요 설정 파라미터를 설명합니다.

| 매개변수                       | 설명                                                             |
| -------------------------- | -------------------------------------------------------------- |
| `endpoint`                 | Elasticsearch 클러스터의 URL입니다. 보안 클러스터의 경우 `https://`을(를) 사용하십시오. |
| `username`                 | `monitor` 또는 `manage` 클러스터 권한이 있는 Elasticsearch 사용자.           |
| `password`                 | 해당 사용자의 비밀번호입니다.                                               |
| `tls.insecure_skip_verify` | Elasticsearch의 TLS 인증서를 검증할지 여부입니다. 검증을 활성화하려면 `false`로 설정합니다. |
| `collection_interval`      | 메트릭 스크랩 간격입니다. 기본값: `15s`.                                     |
| `rule` (Kubernetes 전용)     | 자동 검색에 사용되는 파드 일치 규칙입니다.                                       |

## 호스트 메트릭 수집 [#host-metrics]

호스트 메트릭을 수집하려면 `hostmetrics` 수신기를 추가하십시오:

<CollapserGroup>
<Collapser id="host-metrics-nrdot" title="NRDOT">
```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization: { enabled: true }
          system.cpu.time: { enabled: true }
      load:
        metrics:
          system.cpu.load_average.1m: { enabled: true }
          system.cpu.load_average.5m: { enabled: true }
          system.cpu.load_average.15m: { enabled: true }
      memory:
        metrics:
          system.memory.usage: { enabled: true }
          system.memory.utilization: { enabled: true }
      disk:
        metrics:
          system.disk.io: { enabled: true }
          system.disk.operations: { enabled: true }
      filesystem:
        metrics:
          system.filesystem.usage: { enabled: true }
          system.filesystem.utilization: { enabled: true }
      network:
        metrics:
          system.network.io: { enabled: true }
          system.network.packets: { enabled: true }
      process:
        metrics:
          process.cpu.utilization:
            enabled: true
```

그리고 서비스 파이프라인에 다음을 추가하세요:

```yaml
service:
  pipelines:
    metrics/host:
      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="host-metrics-otel" title="OTel Collector Contrib">

### 구성 매개변수 [#host-metrics-configuration-parameters]

다음 표는 위의 스니펫에서 사용된 주요 설정 파라미터를 설명합니다.

| 매개변수                  | 설명                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `collection_interval` | 호스트 메트릭 스크랩 간격입니다. 기본값: `60s`.                                                                                                              |
| `scrapers`            | 수집할 호스트 수준 메트릭 범주(`cpu`, `load`, `memory`, `disk`, `filesystem`, `network`, `process`)입니다. `enabled: false`을(를) 설정하여 필요하지 않은 메트릭을 비활성화하십시오. |

## Elasticsearch 로그 수집 [#logs]

### 요구 사항 [#logs-requirements]

* 수집기 서비스를 실행하는 계정에 대한 Elasticsearch 로그 파일 읽기 액세스 권한:

  * Linux 호스트: 다음 항목에 대한 읽기 권한 `/var/log/elasticsearch/`
  * 도커: `/var/lib/docker/containers/`에 대한 읽기 권한(root 또는 도커 그룹 멤버십)

Elasticsearch 로그를 수집하려면 `filelog` 수신기를 추가하십시오.

<CollapserGroup>
<Collapser id="logs-nrdot" title="NRDOT">
수집기 서비스(`nrdot-collector`)를 실행하는 계정이 Elasticsearch 로그 파일에 대한 읽기 권한을 가지고 있는지 확인하십시오.

**Elasticsearch가 Linux 호스트에서 실행되는 경우 다음 설정을 사용하십시오:**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Elasticsearch가 도커에서 실행되는 경우 다음 설정을 사용하십시오:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

그리고 서비스 파이프라인에 다음을 추가하세요:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="logs-otel" title="OTel Collector Contrib">
수집기 서비스(`otelcol-contrib`)를 실행하는 계정이 Elasticsearch 로그 파일에 대한 읽기 권한을 가지고 있는지 확인하십시오.

**Elasticsearch가 Linux 호스트에서 실행되는 경우 다음 설정을 사용하십시오:**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Elasticsearch가 도커에서 실행되는 경우 다음 설정을 사용하십시오:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

그리고 서비스 파이프라인에 다음을 추가하세요:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### 구성 매개변수 [#logs-configuration-parameters]

다음 표는 위의 스니펫에서 사용된 주요 설정 파라미터를 설명합니다.

| 매개변수                | 설명                                                             |
| ------------------- | -------------------------------------------------------------- |
| `include`           | tail할 로그 파일 경로(Linux 호스트) 또는 컨테이너 로그 경로(도커).                   |
| `operators` (도커 전용) | 로그 라인이 올바르게 표시되도록 `attributes.log`에서 `body` (으)로 이동시키는 연산자입니다. |

## 사용자 지정 메타데이터 태그 추가 [#custom-tags]

메트릭에 사용자 지정 메타데이터 태그를 추가하려면 `resource/static_override` 프로세서를 사용하십시오:

<CollapserGroup>
<Collapser id="custom-tags-nrdot" title="NRDOT">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="custom-tags-otel" title="OTel Collector Contrib">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### 구성 매개변수 [#custom-tags-configuration-parameters]

다음 표는 위의 스니펫에서 사용된 주요 설정 파라미터를 설명합니다.

| 매개변수     | 설명                                                          |
| -------- | ----------------------------------------------------------- |
| `key`    | 추가할 속성 이름입니다. 예: `env`.                                     |
| `value`  | 속성 값입니다. 예: `production`.                                   |
| `action` | 적용할 작업입니다. 속성을 추가하거나 이미 존재하는 경우 덮어쓰려면 `upsert` (으)로 설정하십시오. |

## 수집기를 재시작하세요 [#restart]

설정을 업데이트한 후 수집기를 다시 시작하여 변경 사항을 적용하십시오.

<CollapserGroup>
<Collapser id="restart-nrdot" title="NRDOT(셀프 호스팅)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Collapser>

<Collapser id="restart-otel" title="OTel Collector Contrib(셀프 호스팅)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```
</Collapser>

<Collapser id="restart-k8s" title="Kubernetes(NRDOT 또는 OTel Collector Contrib)">
매니페스트 설치의 경우 배포를 다시 시작하십시오:

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```

Helm 설치의 경우, 설치 단계와 동일한 `helm upgrade --install ... -f values.yaml` 명령을 다시 실행하여 업데이트된 설정을 배포하십시오.
</Collapser>
</CollapserGroup>

## 변경 사항 확인 [#verify]

수집기를 다시 시작한 후 변경 사항이 적용되었는지 확인하십시오:

* **보안 클러스터**: 설치 페이지의 데이터 수집 쿼리를 다시 실행하십시오. 수집기 로그에 TLS 또는 인증 오류 없이 메트릭이 수신되고 있다면 보안 연결이 작동하는 것입니다.

* **호스트 메트릭**: 이 쿼리를 실행하십시오:

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'system.%' SINCE 10 minutes ago
  ```

* **Elasticsearch 로그**: 다음 쿼리를 실행하십시오:

  ```sql
  FROM Log SELECT count(*) SINCE 10 minutes ago
  ```

  고유한 로그 속성과 일치하도록 `WHERE` 절을 조정해 주십시오.

* **사용자 지정 태그**: [사용자 지정 메타데이터 태그 추가](#custom-tags)의 예제 태그를 사용하여 다음 쿼리를 실행하십시오:

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'elasticsearch.%' AND env = 'production' SINCE 10 minutes ago
  ```

약 5분 내에 데이터가 표시되지 않으면 [Elasticsearch 문제 진단, 해결](/docs/opentelemetry/integrations/elasticsearch/troubleshooting)을 참조하십시오.
