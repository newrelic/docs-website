이 페이지에서는 Linux 호스트에 NRDOT Collector를 설치하고, 도커 컨테이너 메트릭을 수집하도록 설정하며, 데이터가 뉴렐릭에 도달하는지 확인합니다.

## 호환성 및 요구 사항 [#requirements]

### 지원

* 도커 엔진 API 버전 1.25 이상

### 필요한 사항

* 유효한 뉴렐릭 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* 도커 소켓(일반적으로 `/var/run/docker.sock`)에 대한 접근
* 호스트에서 도커 엔진 소켓 및 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp/#configure-endpoint-port-protocol)로의 네트워크 액세스
* 로그 수집을 위한 `/var/lib/docker/containers/`에 대한 읽기 권한(일반적으로 root 또는 docker 그룹 멤버십)

<Steps>
<Step>
## NRDOT Collector설치하세요 [#install]

<Callout variant="tip">
이미 NRDOT Collector가 설치되어 있는 경우, 이 단계를 건너뛰고 [도커 소켓 권한 설정](#permissions)을 계속 진행해 주십시오.
</Callout>

<CollapserGroup>
<Collapser id="install-deb" title="데비안/우분투">
이 설치를 통해 수집기를 DEB 패키지(Debian의 기본 패키지 형식)로 다운로드하고 설치한 다음, 설정이 완료될 때까지 자동 시작을 비활성화할 수 있습니다:

```bash
# Example version - check releases for latest: https://github.com/newrelic/nrdot-collector-releases/releases
export collector_version="1.10.0"
export collector_arch="amd64"  # or arm64

curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${collector_version}/nrdot-collector_${collector_version}_linux_${collector_arch}.deb" -o collector.deb
sudo dpkg -i collector.deb

# Disable auto-start until configuration is complete
sudo systemctl disable nrdot-collector
sudo systemctl stop nrdot-collector
```
</Collapser>

<Collapser id="install-rpm" title="RHEL/CentOS/Fedora">
이 설치를 통해 수집기를 RPM 패키지(Red Hat의 기본 패키지 형식)로 다운로드하고 설치한 다음, 설정이 완료될 때까지 자동 시작을 비활성화할 수 있습니다:

```bash
# Example version - check releases for latest: https://github.com/newrelic/nrdot-collector-releases/releases
export collector_version="1.10.0"
export collector_arch="x86_64"  # or arm64

curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${collector_version}/nrdot-collector_${collector_version}_linux_${collector_arch}.rpm" -o collector.rpm
sudo rpm -i collector.rpm

# Disable auto-start until configuration is complete
sudo systemctl disable nrdot-collector
sudo systemctl stop nrdot-collector
```
</Collapser>
</CollapserGroup>

**기타 Linux 배포판**: 아카이브 설치 또는 기타 방법은 [NRDOT 설치 가이드를](https://github.com/newrelic/nrdot-collector-releases/blob/main/distributions/README.md#installation) 참조하십시오.
</Step>

<Step>
## 도커 소켓 권한을 설정하십시오. [#permissions]

수집기는 컨테이너 지표를 수집하기 위해 도커 소켓에 액세스해야 합니다. 수집기 사용자에게 도커 그룹에 대한 액세스 권한을 부여합니다.

```bash
# Add nrdot-collector user to docker group
sudo usermod -aG docker nrdot-collector

# Verify the user was added
groups nrdot-collector

# Restart Docker to apply group changes
sudo systemctl restart docker

# Test Docker socket access
sudo -u nrdot-collector docker ps
```

테스트 명령이 성공하고 컨테이너가 표시되면 권한을 올바르게 설정한 것입니다.

컨테이너를 나열하는 대신 `permission denied`을(를) 보고하는 경우 [권한 거부 오류](/docs/opentelemetry/integrations/docker/troubleshooting#permission-errors)를 참조하십시오.
</Step>

<Step>
## 수집기 구성 [#configure]

<Callout variant="important">
**독립형 vs. 결합형 시뮬레이션**: 이 설정은 도커 컨테이너에만 해당됩니다. 호스트 범위(CPU, 메모리, 디스크) 또는 시스템 로그도 필요한 경우 `hostmetrics` 및 `filelog` 수신기가 포함된 NRDOT Collector 의 [기본 설정을](https://github.com/newrelic/nrdot-collector-releases/blob/main/distributions/nrdot-collector/config.yaml) 사용하고 `docker_stats` 수신기를 추가하세요.
</Callout>

다음 내용으로 `/etc/nrdot-collector/docker-stats-config.yaml` 생성하세요:

```yaml

receivers:
  # Docker Stats Receiver - collects container metrics
  docker_stats:
    endpoint: unix:///var/run/docker.sock
    collection_interval: 15s
    timeout: 5s
    api_version: "1.25"
    # Most metrics required for New Relic UI are enabled by default:
    # CPU: container.cpu.usage.total, container.cpu.utilization
    # Memory: container.memory.usage.total, container.memory.percent
    # Network: container.network.io.usage.tx_bytes, container.network.io.usage.rx_bytes
    #          container.network.io.usage.tx_dropped, container.network.io.usage.rx_dropped
    # Storage: container.blockio.io_service_bytes_recursive
    #
    # The following metrics need to be explicitly enabled:
    metrics:
      # Required for New Relic UI
      container.pids.count:
        enabled: true
      # Additional network error metrics
      container.network.io.usage.tx_errors:
        enabled: true
      container.network.io.usage.rx_errors:
        enabled: true

processors:
  # Batch processor optimizes data transmission
  batch:
    timeout: 10s
    send_batch_size: 1024

  # Transform processor - removes descriptions and units
  transform:
    metric_statements:
      - context: metric
        statements:
          - set(description, "")
          - set(unit, "")
exporters:
  otlp_http:
    endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT:-https://otlp.nr-data.net}
    headers:
      api-key: ${env:NEW_RELIC_LICENSE_KEY}
    compression: gzip

service:
  pipelines:
    metrics/docker:
      receivers: [docker_stats]
      processors: [transform, batch]
      exporters: [otlp_http]

```

### 구성 매개변수 [#configuration-parameters]

다음 표는 `docker_stats` 수신자 및 익스포터의 주요 설정 파라미터를 설명합니다:

| 매개변수                          | 설명                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `endpoint` (`docker_stats`)   | 수집기가 연결되는 도커 소켓의 경로를 입력해 주십시오. 기본: `unix:///var/run/docker.sock`                                                   |
| `collection_interval`         | 수집기가 컨테이너 통계를 스크랩하는 빈도를 설정해 주십시오. 기본: `15s`                                                                        |
| `timeout`                     | 수집기가 포기하기 전에 도커 엔진 API의 응답을 기다리는 시간을 설정해 주십시오. 기본: `5s`                                                            |
| `api_version`                 | 호스트가 지원하는 도커 엔진 API 버전을 입력하십시오. 기본: `1.25`                                                                         |
| `NEW_RELIC_LICENSE_KEY`       | 귀하의 블루 클러스터 키를 입력하세요.                                                                                              |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | 해당 리전의 뉴렐릭 OTLP 엔드포인트를 입력해 주십시오. [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp/)를 참조하십시오. |

<Callout variant="tip">
선택적으로 컨테이너에서 로그를 수집할 수도 있습니다. 설정 단계는 [고급 설정](/docs/opentelemetry/integrations/docker/advanced-configuration#logs)을 참조하십시오.
</Callout>

**systemd 서비스를 구성합니다.**

이제 도커 모니터링 설정 및 인증 자격 증명을 사용하도록 NRDOT Collector 서비스를 구성합니다. 이 과정에는 사용자 지정 구성 파일과 환경 변수를 지정하기 위한 systemd 오버라이드를 생성하는 것이 포함됩니다.

1. systemd 오버라이드 디렉터리를 생성합니다.

   ```bash
   sudo mkdir -p /etc/systemd/system/nrdot-collector.service.d
   ```

2. 도커 통계 설정을 사용하도록 재정의 설정을 생성합니다. `YOUR_LICENSE_KEY` 뉴렐릭 클러스터 키로 바꾸고, `YOUR_OTLP_ENDPOINT` 해당 지역에 적합한 엔드포인트로 바꿉니다.

   ```bash
   cat <<EOF | sudo tee /etc/systemd/system/nrdot-collector.service.d/override.conf
   [Service]
   Environment="NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY"
   Environment="OTEL_EXPORTER_OTLP_ENDPOINT=YOUR_OTLP_ENDPOINT"
   ExecStart=
   ExecStart=/usr/bin/nrdot-collector --config=/etc/nrdot-collector/docker-stats-config.yaml
   EOF
   ```

<Callout variant="tip">
빈 `ExecStart=` 줄은 새 명령을 설정하기 전에 기본 명령을 지웁니다. 이를 통해 수집기는 기본 설정 대신 도커 통계 설정만 사용합니다.
</Callout>
</Step>

<Step>
## 수집기를 재시작하세요 [#start]

systemd를 다시 로드하고 수집기를 활성화한 후 다시 시작해 주십시오:

```bash
sudo systemctl daemon-reload
sudo systemctl enable nrdot-collector
sudo systemctl restart nrdot-collector

# Verify the collector is running
sudo systemctl status nrdot-collector
```
</Step>

<Step>
## 설치 확인 [#verify]

설치를 완료한 후 5분 이내에 데이터가 뉴렐릭에 도달하는지 확인해 주십시오.

* <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All Entities**</DNT> (으)로 이동하여 호스트명 또는 컨테이너 이름으로 검색해 주십시오. 사용자의 도커 컨테이너가 엔티티로 표시되어야 합니다.
* 이 NRQL 쿼리를 실행하고 최소 1개의 행이 반환되는지 확인하십시오:
  ```sql
  FROM Metric SELECT count(*) WHERE container.runtime = 'docker' SINCE 10 minutes ago
  ```

5분 이내에 데이터가 표시되지 않으면 [도커 모니터링 문제 진단, 해결](/docs/opentelemetry/integrations/docker/troubleshooting)을 참조하십시오.
</Step>
</Steps>

도커 컨테이너가 데이터를 보고하고 있습니다. 로그도 수집하고 싶으십니까? [고급 설정](/docs/opentelemetry/integrations/docker/advanced-configuration)에서 로그 수집 설정을 다룹니다.
