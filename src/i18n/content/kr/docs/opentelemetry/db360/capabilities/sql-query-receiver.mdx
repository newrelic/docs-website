`sqlqueryreceiver`은(는) 데이터베이스에 대해 커스텀 SQL 쿼리를 실행하고 그 결과를 메트릭으로 뉴렐릭에 수집할 수 있도록 하는 OpenTelemetry Collector 수신자입니다.

내장 `nroracledbreceiver` / `nrsqlserverreceiver` / `nrmysqlreceiver` / `nrpostgresqlreceiver` 메트릭에 포함되지 않은 데이터를 모니터링할 때 이를 사용하십시오. 엔티티 연결 속성이 올바르게 구성된 경우, `sqlqueryreceiver`을(를) 통해 수집된 커스텀 지표는 뉴렐릭에서 내장 수신기 데이터와 동일한 오라클, SQL Server, MySQL 또는 PostgreSQL 엔티티 아래에 표시됩니다.

## 전제 조건 [#prerequisites]

* 데이터소스에 설정된 데이터베이스 사용자는 쿼리하려는 모든 뷰 또는 테이블에 대해 `SELECT` 권한을 가져야 합니다.
* 수집기 바이너리에는 `sqlqueryreceiver` 구성 요소가 포함되어야 합니다.

      ### 명명 규칙

      뉴렐릭의 올바른 엔티티와 연결되려면 메트릭 이름이 `oracledb.`로 시작해야 합니다. 다른 접두사가 있는 메트릭은 수집되지만 데이터베이스 엔티티 아래에 표시되지 않습니다.

      ### 엔티티 합성

      `server.address` 및 `server.port`을(를) 데이터베이스 수신기가 사용하는 것과 동일한 값으로 설정하려면 `resource/add_event_name` 및 `resource/add_host` 프로세서를 추가하십시오. 이것이 없으면 커스텀 지표가 데이터베이스 엔티티에 연결되지 않습니다.

      `processors:` 섹션에 프로세서를 추가하십시오:

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Pipeline 설정

      기존 파이프라인과 함께 구성의 `service.pipelines:` 섹션에 `metrics/custom` 파이프라인을 추가하십시오:

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_event_name, resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        프로세서 목록에서 `batch` 앞에 `resource/add_event_name` 및 `resource/add_host`을(를) 모두 추가하십시오.
      </Callout>

      ### 데이터를 검증하기 위한 NRQL

      수집기를 다시 시작한 후 다음을 실행하여 커스텀 지표가 수신되는지 확인하십시오:

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      ## 문제점 해결 [#troubleshooting]

      | 문제                                        | 원인                                                     | 고치다                                                                   |
      | ----------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------- |
      | `ORA-00942: table or view does not exist` | 데이터베이스 사용자의 SELECT 권한 누락                               | 사용자에게 `SELECT ON <VIEW_NAME>`을(를) 부여하십시오                              |
      | `missing port in address`                 | `#` 사용자 이름/비밀번호가 URL 인코딩되지 않음                          | 데이터 소스 URL에서 `#`를 `%23`로 변경하십시오                                       |
      | 뉴렐릭에 데이터 없음                               | `server.address`/`server.port`이(가) 설정되지 않았거나 일치하지 않습니다 | 올바른 값으로 `resource/add_event_name` 및 `resource/add_host` 프로세서를 추가하십시오. |
      | 데이터베이스 엔티티 아래에 없는 메트릭                     | 메트릭 이름에 필수 접두사 누락                                      | 메트릭 이름이 다음으로 시작하는지 확인하십시오 `oracledb.`                                 |

      위의 방법 중 어느 것으로도 문제가 해결되지 않는 경우, 수집기 자체 로그에 오류가 있는지 확인하십시오:

      ```bash
      sudo journalctl -u nrdot-collector -f
      ```

      ### 엔티티 합성

      `nrpostgresql` `server.address` 및 `server.port`에서 데이터베이스 엔티티를 합성합니다. 데이터베이스 수신기가 사용하는 것과 동일한 `server.address`/`server.port` 값을 부여하도록 `resource/add_host` 프로세서를 추가하십시오. 이것이 없으면 커스텀 지표가 데이터베이스 엔티티에 연결되지 않습니다.

      `processors:` 섹션에 프로세서를 추가하십시오:

      ```yaml
      processors:
        batch:
        resource/add_host:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      <Callout variant="important">
        `nrpostgresql` 파이프라인에 이미 `server.address`/`server.port` (예: `resource/postgresql`)을(를) 설정하는 `resource/*` 프로세서가 있는 경우, 이를 복제하는 대신 아래의 `metrics/custom` 파이프라인에서 동일한 프로세서를 재사용하십시오 — 두 수신자는 동일한 엔티티에 연결하기 위해 동일한 값을 기록해야 합니다.
      </Callout>

      ### Pipeline 설정

      ```yaml
      service:
        pipelines:
          metrics/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          logs/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          metrics/custom:
            receivers: [sql_query/postgres]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        프로세서 목록에서 `batch` 앞에 `resource/add_host`을(를) 추가합니다.
      </Callout>
