Azure Database for MySQL 유연한 서버 인스턴스용 NRDOT Collector를 사용하여 MySQL 모니터링을 설정하십시오. Azure 유연한 서버 환경에는 권한 및 플랫폼 제한 사항에 대한 특정 고려 사항이 있습니다.

<Callout variant="tip" title="가이드 설치">
대신 뉴렐릭 UI를 통해 설치하려면 <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>(으)로 이동하십시오. 이 페이지는 수동 설치만 다룹니다.
</Callout>

<Steps>
<Step>
## 전제 조건 [#prerequisites]

설치하기 전에 다음을 갖추고 있는지 확인하십시오:

* New Relic [라이센스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) .
* NRDOT Collector를 설치하는 호스트와 Azure Database for MySQL 유연한 서버 인스턴스 간의 네트워크 연결입니다.
* [뉴렐릭 OTLP 엔드포인트 문서](/docs/opentelemetry/best-practices/opentelemetry-otlp/)에 대한 네트워크 연결
* Azure Flexible Server 관리자 로그인 자격 증명.

지원되는 MySQL 버전, 필수 권한 및 `performance_schema` 요구 사항은 [호환성 및 전제 조건](/docs/opentelemetry/db360/mysql/compatibility)을 참조하십시오.
</Step>

<Step>
## NRDOT Collector 설정 [#setup]

Azure Database for MySQL 유연한 서버 인스턴스에 연결할 수 있는 시스템에 NRDOT Collector를 설치하십시오:

<CollapserGroup>
<Collapser title="AMD64 아키텍처용" id="amd">
* Debian/Ubuntu 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
  ```

* RHEL/CentOS/OEL 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_x86_64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
  ```
</Collapser>

<Collapser title="ARM64 아키텍처용" id="arm">
* Debian/Ubuntu 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
  ```

* RHEL/CentOS/OEL 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
  ```
</Collapser>
</CollapserGroup>
</Step>

<Step>
## 데이터베이스 사용자 구성 [#user]

Azure Database for MySQL flexible server 인스턴스에 필요한 권한을 가진 모니터링 사용자를 생성하십시오.

1. 모니터링 사용자를 생성하려면 Azure Flexible Server 관리자 로그인으로 인스턴스에 연결하고(`root` 계정은 없습니다) 다음을 실행하십시오:

```sql
CREATE USER '<YOUR_DB_USERNAME>'@'%' IDENTIFIED BY '<YOUR_DB_PASSWORD>';
```

2. 쿼리 샘플 및 상위 쿼리를 수집하려면 모니터링 사용자에게 다음 권한을 부여하십시오:

```sql
GRANT SELECT ON performance_schema.* TO '<YOUR_DB_USERNAME>'@'%';
GRANT SELECT ON *.* TO '<YOUR_DB_USERNAME>'@'%';
GRANT REPLICATION CLIENT ON *.* TO '<YOUR_DB_USERNAME>'@'%';
GRANT PROCESS ON *.* TO '<YOUR_DB_USERNAME>'@'%';
```

<Callout variant="important">
`BACKUP_ADMIN` 부여는 Azure Database for MySQL - Flexible Server에서 지원되지 않습니다. 그 결과 `mysql.innodb.redo_log.checkpoint.age`, `mysql.innodb.redo_log.lsn.checkpoint`, `mysql.innodb.redo_log.lsn.current`은(는) 사용할 수 없습니다.
</Callout>

3. (선택 사항) 뉴렐릭 플랫폼에서 대기 시간 데이터를 보려면 모니터링 사용자에게 다음 권한을 부여하십시오:

```sql
GRANT UPDATE ON performance_schema.setup_consumers TO '<YOUR_DB_USERNAME>'@'%';
```

4. (선택 사항) 연결 및 권한을 확인하려면 다음을 실행하십시오:

```shell
mysql -h <YOUR_DB_HOST> -P <YOUR_DB_PORT> -u <YOUR_DB_USERNAME> -p -e "SELECT 1;"
```

명령이 오류 없이 완료되면 모니터링 사용자, 호스트 및 포트가 모두 올바른 것입니다.
</Step>

## NRDOT Collector구성 [#configure]

MySQL용 Azure 데이터베이스 Flexible Server 관련 설정으로 NRDOT Collector를 구성하십시오.

이 설정은 `nrmysql` 수신기만을 사용한 필수 MySQL 모니터링에 중점을 둡니다.

<Callout variant="tip" title="전체 설정">
이 기준 설정은 필수 메트릭을 캡처합니다. 전체 메트릭 카탈로그를 보려면 [설정 참조](/docs/opentelemetry/db360/mysql/config-reference/#azure-full)를 참조해 주십시오.
</Callout>

1. `mysql-config.yaml`이라는 이름의 설정 파일을 생성합니다:

```bash
  sudo nano /etc/nrdot-collector/mysql-config.yaml
```

### 구성 매개변수

다음 표에서는 `nrmysql` 수신자에 대한 주요 설정 초기화에 대해 설명합니다.

| 매개변수                            | 설명                                                                                                                                                                                |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<YOUR_DB_HOST>`                | Azure Database for MySQL flexible server 엔드포인트입니다. 예를 들어, `myserver.mysql.database.azure.com`                                                                                     |
| `<YOUR_DB_PORT>`                | MySQL 포트 번호를 입력하십시오. 기본값은 `3306` 입니다.                                                                                                                                             |
| `<YOUR_DB_USERNAME>`            | [데이터베이스 사용자 구성](#user)에서 생성한 모니터링 사용자의 사용자 이름을 입력하십시오.                                                                                                                            |
| `<YOUR_DB_PASSWORD>`            | [데이터베이스 사용자 설정](#user)에서 생성한 모니터링 사용자의 비밀번호를 입력합니다.                                                                                                                               |
| `<YOUR_NEWRELIC_OTLP_ENDPOINT>` | 뉴렐릭 OTLP 엔드포인트를 입력하십시오. 자세한 내용은 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp/)를 참조하십시오.                                                                 |
| `<YOUR_NEWRELIC_LICENSE_KEY>`   | 뉴렐릭 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)를 입력하십시오.                                                                                               |
| `transport`                     | 네트워크를 통해 연결하기 위해 기본값은 `tcp`으로 설정됩니다.                                                                                                                                              |
| `collection_interval`           | 메트릭 스크랩 간격을 입력하십시오. 기본값: `15s`.                                                                                                                                                   |
| `explain_mode`                  | 기본값은 `inline`으로 설정되어 있습니다. 모니터링 사용자에게 DML 권한을 부여하지 않고 쓰기 문에 대한 쿼리 계획을 수집하려면 값을 `procedure` (으)로 설정하십시오. [쓰기 문에 대한 쿼리 계획](/docs/opentelemetry/db360/mysql/optional#query)을 참조하십시오. |

<Step>
## NRDOT Collector 설정 유효성 검사 [#validate]

1. 새 `mysql-config.yaml` 파일을 가리키도록 설정 경로를 업데이트하십시오:

   ```bash
     sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/mysql-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
   ```

2. NRDOT Collector 설정을 검증하여 형식이 올바르고 제대로 작동하는지 확인합니다:

   ```bash
     sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mysql-config.yaml
   ```

   <Callout variant="tip">
   당신은 또한 수:

   * [여러 수신자 구성](/docs/opentelemetry/db360/mysql/multi-receiver): 하나의 수집기에서 여러 MySQL 인스턴스를 모니터하려면.
   * [MySQL 데이터베이스를 APM과 연결](/docs/opentelemetry/db360/capabilities/db-apm): 애플리케이션 성능을 데이터베이스 작업과 연관시킵니다. 이를 통해 어떤 애플리케이션이 특정 데이터베이스 워크로드를 생성하는지 정확히 확인할 수 있습니다.
   * [시크릿 관리 설정](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management): 데이터베이스 자격 증명과 같은 민감한 정보를 안전하게 관리할 수 있습니다. 이는 설정 파일에 민감한 데이터를 하드코딩하는 것을 방지하여 모니터링 설정의 보안을 강화하는 데 도움이 됩니다.
   </Callout>
</Step>

<Step>
## NRDOT Collector를 다시 시작하십시오 [#restart]

* 설정을 업데이트한 후 NRDOT Collector 서비스를 다시 시작하십시오:

  ```shell
  sudo systemctl restart nrdot-collector
  ```

  <Callout variant="tip">
  새로운 설정이 적용되도록 설정 변경 후에는 항상 NRDOT Collector 서비스를 다시 시작하십시오.
  </Callout>

* 수집기가 제대로 실행되고 있는지 확인하려면 서비스 상태를 확인하십시오:

  ```shell
  sudo systemctl status nrdot-collector
  ```
</Step>

## 제한 사항 [#limitations]

Azure Database for MySQL - Flexible Server 인스턴스를 모니터링할 때, 수신기의 문제라기보다는 Azure 플랫폼 제한으로 인해 일부 기능이 자체 관리형 MySQL에서와 다르게 작동합니다.

`BACKUP_ADMIN` 부여는 지원되지 않으므로 `mysql.innodb.redo_log.checkpoint.age`, `mysql.innodb.redo_log.lsn.checkpoint` 및 `mysql.innodb.redo_log.lsn.current`이(가) 완전히 차단됩니다.

MySQL X 플러그인은 이 플랫폼에서 지원되지 않으며 고객 활성화 경로도 없다는 점이 [Microsoft의 Azure Database for MySQL 수석 PM에 의해 확인되었습니다](https://stackoverflow.com/questions/74631732/mysql-azure-database-enable-mysqlx-plugin). 그 결과 `mysql.mysqlx_connections` 및 `mysql.mysqlx_worker_threads`은(는) 데이터를 보고하지 않습니다.

읽기 전용 복제본은 스토리지 기반 복제를 사용하므로 실제 복제 상태와 관계없이 `mysql.replica.thread.running`은(는) 항상 실행 중이 아닌 것으로 보고됩니다. `mysql.replica.time_behind_source`은(는) 영향을 받지 않습니다.
