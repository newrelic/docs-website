NRDOT로 MySQL 모니터링을 시작하기 전에 환경이 다음 요구 사항을 충족하는지 확인하십시오.

## 전제 조건 [#prereq]

시작하기 전에 다음 사항이 있는지 확인하세요.

* 유효한 뉴렐릭 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* NRDOT Collector를 설치하는 호스트와 MySQL 데이터베이스 간의 네트워크 연결입니다. MySQL 데이터베이스와 다른 호스트에 NRDOT Collector를 설치하려는 경우 [네트워크 액세스 요구 사항](#network)을 참조하십시오.
* [뉴렐릭 OTLP 엔드포인트 문서](/docs/opentelemetry/best-practices/opentelemetry-otlp/)에 대한 네트워크 연결

## 네트워크 액세스 요구 사항 [#network]

기본적으로 NRDOT는 **TCP**를 통해 연결합니다(수신기 구성의 `transport: tcp`, 기본값). 수집기가 데이터베이스와 동일한 호스트에서 실행되는 경우, 대신 `transport: unix`을(를) 설정하고 `endpoint`을(를) 데이터베이스의 Unix 도메인 소켓(예: `/var/run/mysqld/mysqld.sock`)으로 지정할 수 있으며, 이렇게 하면 아래의 네트워크 검사를 완전히 우회할 수 있습니다. 다른 모든 배포(수집기와 데이터베이스가 다른 호스트, 컨테이너 또는 VPC에 있는 경우)에는 TCP가 필요합니다.

<table>
  <thead>
    <tr>
      <th>
        전개
      </th>

      <th>
        확인해야 할 사항
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        EC2의 자체 관리형 MySQL
      </td>

      <td>
        **보안 그룹**

        : 수집기가 다른 EC2 인스턴스에서 실행되는 경우 수집기의 소스인 자체 보안 그룹 ID(동일한 VPC, 원시 IP보다 권장됨)에서 DB 포트(기본값 

        `3306`

        )에 대한 인바운드 규칙을 추가해야 하며, 동일한 인스턴스에서 사이드카로 실행되는 경우에는 규칙이 필요하지 않습니다. 또한 

        `my.cnf`

        에서 

        `bind-address`

        을(를) 확인하십시오. 많은 배포판 기본값에는 로컬이 아닌 모든 TCP 연결을 거부하는 

        `bind-address = 127.0.0.1`

        이(가) 포함되어 있습니다. 원격 수집기가 도달하려면 먼저 이를 인스턴스의 프라이빗 IP 또는 

        `0.0.0.0`

         (으)로 설정하십시오.
      </td>
    </tr>

    <tr>
      <td>
        MySQL용 Amazon RDS/Aurora
      </td>

      <td>
        **VPC 보안 그룹**

        : 수집기의 보안 그룹 또는 프라이빗 IP에서 RDS 인스턴스의 포트(기본값 

        `3306`

        )에 대한 인바운드 규칙을 추가해야 하며, RDS에는 편집할 수 있는 OS 수준의 

        `my.cnf`

        이(가) 없으므로 이것이 유일한 네트워크 게이트입니다. 

        **권한 부여**

        는 RDS 마스터 사용자가 수행해야 합니다. RDS에는 

        `root`

         계정이 없습니다. 

        **제한된 권한**

        : 

        `SUPER`

         및 

        `FILE`

        은(는) RDS 엔진 버전 및 파라미터 그룹에 따라 제한되거나 사용할 수 없습니다. 

        **TLS**

        : &quot;Require SSL/TLS&quot;가 강제 적용된 RDS 인스턴스는 수집기가 Amazon의 RDS CA를 신뢰해야 합니다. 

        `tls.ca_file`

         (또는 

        `tls.ca_pem`

        )을(를) 

        [Amazon RDS 인증서 번들](https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem)

        로 설정하고 

        `tls.insecure`

        /

        `tls.insecure_skip_verify`

        은(는) 

        `false`

        (으)로 유지하십시오.
      </td>
    </tr>

    <tr>
      <td>
        모든 원격/교차 호스트 배포
      </td>

      <td>
        MySQL은 사용자 이름이 동일하더라도 

        `'<user>'@'localhost'`

         및 

        `'<user>'@'%'`

         (또는 특정 호스트/CIDR)을 

        **다른 계정**

        으로 취급합니다. 모니터링 사용자를 

        `'<user>'@'localhost'`

         (으)로 생성하면 다른 곳에서 실행 중인 수집기에서의 인증이 조용히 실패하며, 잘못된 비밀번호와 구별할 수 없는 액세스 거부 오류가 발생합니다. 

        `'<user>'@'%'`

        을(를) 사용하거나 수집기의 특정 사설 IP/CIDR로 범위를 지정하십시오.
      </td>
    </tr>
  </tbody>
</table>

<Callout variant="important">
  실제 실행 중인 Amazon RDS for MySQL 인스턴스에 대해 확인되었습니다: RDS의 `mysql8.0` 파라미터 그룹 패밀리는 `performance_schema_consumer_*` 파라미터를 전혀 노출하지 않으며, 해당 위치에서는 크기 조정/버퍼 파라미터와 `performance_schema`, `slow_query_log`, `long_query_time`만 설정할 수 있습니다. 이는 `events_waits_current` (`mysql.events_waits_current.timer_wait` 및 일반적인 대기 기반 대시보드에 필요함)를 RDS의 런타임에만 활성화할 수 있으며, 재시작이나 장애 조치 시 유지되지 않음을 의미합니다.
</Callout>

## 다음 단계 [#next]

환경이 이러한 사전 요구 사항을 충족하는지 확인한 후:

1. 설치 방법을 선택하세요:

* [자체 호스팅 설정](/docs/opentelemetry/db360/mysql/hosted)
* [AWS RDS 설정](/docs/opentelemetry/db360/mysql/rds)

2. 수집될 [사용 가능한 메트릭](/docs/opentelemetry/db360/mysql/metrics-reference)을 확인해 주십시오.
3. 쓰기 문 쿼리 계획 및 잠금 대기 시간 추적과 같은 선택적 기능에 대해서는 [상세 인사이트 활성화](/docs/opentelemetry/db360/mysql/optional)를 참조하십시오.
4. 일반적인 문제에 대해서는 [문제 진단, 해결 가이드](/docs/opentelemetry/db360/mysql/troubleshooting)를 확인해 주십시오.
