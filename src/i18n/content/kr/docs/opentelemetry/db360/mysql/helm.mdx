`mysql-otel` Helm 차트를 사용하여 Kubernetes에서 MySQL 모니터링을 설치하고 구성할 수 있습니다. 선택적으로, 차트는 모니터링 사용자를 생성하는 설정 작업을 실행할 수도 있습니다.

<Callout variant="tip" title="가이드 설치">
  대신 뉴렐릭 UI를 통해 설치하려면 <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>(으)로 이동하십시오. 이 페이지는 수동 설치만 다룹니다.
</Callout>

<Callout variant="important">
  차트는 네트워크를 통해 원격으로 MySQL에 도달하는 Kubernetes 배포로 수집기를 배포합니다. 결과적으로 항상 TCP를 통해 연결되며(Unix-socket 모니터링은 지원되지 않음), MySQL 메트릭만 보고합니다(MySQL이 실행되는 머신에 대한 호스트 또는 인프라 메트릭은 없음). `mysql.*`을(를) 사용하여 릴리스당 하나의 MySQL 인스턴스를 모니터하며, 단일 릴리스에서 여러 인스턴스를 모니터하려면 대신 `mysqlMulti.*`을(를) 사용하십시오(아래의 [단일 릴리스에서 여러 인스턴스 모니터](#helm-multi) 참조).
</Callout>

<Steps>
  <Step>
    ## 전제 조건 [#helm-prerequisites]

    * 유효한 뉴렐릭 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key).

    * MySQL 5.7 이상.

    * Helm 3.0 이상 및 쿠버네티스 클러스터에 액세스하도록 구성된 `kubectl`.

    * 쿠버네티스 클러스터에서 MySQL 호스트(또는 RDS 엔드포인트) 및 포트로의 네트워크 연결:

      * 자체 호스팅: MySQL 호스트로 라우팅되는 경로(VPN, 피어링 또는 공유 네트워크), 호스트명인 경우 DNS 확인이 필요하며, MySQL 측 방화벽은 연결의 실제 소스 IP(파드 IP 자체가 아니라 NAT 게이트웨이일 수 있음)를 허용해야 합니다.
      * AWS RDS: VPC 피어링, 트랜짓 게이트웨이 또는 RDS 인스턴스와의 공유 VPC 배치, 그리고 RDS 보안 그룹은 클러스터의 이그레스 소스에서 MySQL 포트(기본값 `3306`)를 허용해야 합니다.

    * 이미 생성한 모니터링 사용자이거나, 차트의 설정 작업에서 사용자를 생성할 수 있도록 하는 MySQL 관리자 자격 증명입니다. 아래의 [모니터링 자격 증명 구성](#helm-credentials)을 참조하십시오.
  </Step>

  <Step>
    ## 네임스페이스를 생성하십시오. [#helm-namespace]

    설치할 네임스페이스를 생성하십시오. `helm install --create-namespace`은(는) 최종 설치 단계에서만 네임스페이스를 생성하므로, 다음 단계에서 시크릿을 생성하기 전에 해당 네임스페이스가 존재해야 합니다:

    ```bash
    kubectl create namespace newrelic
    ```

    <Callout variant="tip">
      아래의 모든 명령어에서 `-n`을(를) 전달할 필요가 없도록 현재 `kubectl` 컨텍스트의 기본 네임스페이스로 설정하십시오:

      ```bash
      kubectl config set-context --current --namespace=newrelic
      ```
    </Callout>
  </Step>

  <Step>
    ## 모니터링 자격 증명 구성 [#helm-credentials]

    차트의 설정 작업이 MySQL 모니터링 사용자를 생성하도록 할지, 그렇지 않다면 자격 증명을 어떻게 제공할지 결정하십시오:

    <CollapserGroup>
      <Collapser id="helm-creds-inline" title="설정 작업 없음: 일반 사용자 이름 및 비밀번호">
        이 방법에는 설정 작업이 없으므로, 여기서는 모니터링 사용자를 생성해 주지 않습니다. 차트를 설치하기 전에 [자체 호스팅](/docs/opentelemetry/db360/mysql/hosted/#user) MySQL 또는 [RDS의 MySQL](/docs/opentelemetry/db360/mysql/rds/#user) **의 데이터베이스 사용자** 구성 단계를 사용하여 직접 생성하거나, 관리 사용자로 동일한 SQL을 실행하십시오:

        ```sql
        CREATE USER IF NOT EXISTS 'newrelic'@'%' IDENTIFIED BY '<password>';
        GRANT SELECT ON performance_schema.* TO 'newrelic'@'%';
        FLUSH PRIVILEGES;
        ```

        다음 단계에서 `values.yaml`에 모니터링 사용자 이름과 비밀번호를 직접 설정합니다.
      </Collapser>

      <Collapser id="helm-creds-secret-nojob" title="설정 작업 없음: 시크릿 기반 자격 증명">
        이 방법에는 설정 작업도 없습니다. 위의 일반 자격 증명 방법과 정확히 동일하게 먼저 모니터링 사용자를 직접 생성하십시오. 유일한 차이점은 자격 증명이 있는 위치입니다: `values.yaml`에 일반 텍스트로 저장하는 대신 Kubernetes 시크릿에 저장하십시오:

        ```bash
        kubectl create secret generic mysql-monitor-creds \
          --from-literal=username=<MONITORING_USERNAME> \
          --from-literal=password='<MONITORING_PASSWORD>' \
          -n newrelic
        ```
      </Collapser>

      <Collapser id="helm-creds-setupjob" title="자동화된 설정 작업">
        이 방법을 사용하면 차트의 설정 작업이 MySQL 관리자 자격 증명을 사용하여 모니터링 사용자를 생성합니다. 모니터링 및 관리자 자격 증명은 모두 Kubernetes 시크릿으로 제공되어야 합니다: 설정 작업은 일반 텍스트 관리자 자격 증명을 절대 허용하지 않으며, 이를 활성화하려면 시크릿 기반 모니터링 자격 증명도 필요합니다.

        1. 모니터링 사용자 이름과 비밀번호로 시크릿을 생성하십시오. 이것은 설정 작업이 생성하고 수집기가 연결하는 자격 증명입니다:

           ```bash
           kubectl create secret generic mysql-monitor-creds \
             --from-literal=username=<MONITORING_USERNAME> \
             --from-literal=password='<MONITORING_PASSWORD>' \
             -n newrelic
           ```

        2. 설정 작업은 Kubernetes 시크릿을 통해서만 관리자 자격 증명을 허용합니다(`values.yaml`에 일반 텍스트 사용자 이름/비밀번호 없음). 이 자격 증명은 `CREATE USER`을(를) 실행하고 광범위한 `performance_schema` 액세스를 부여할 수 있으므로 자체 시크릿으로 생성하십시오. 자체 호스팅 MySQL의 경우 `root` 계정을 사용하거나, AWS RDS의 MySQL의 경우 RDS 마스터 사용자를 사용하십시오:

           ```bash
           kubectl create secret generic mysql-admin-creds \
             --from-literal=username=<ADMIN_USERNAME> \
             --from-literal=password='<ADMIN_PASSWORD>' \
             -n newrelic
           ```
      </Collapser>
    </CollapserGroup>
  </Step>

  <Step>
    ## (선택 사항) 하나의 릴리스에서 여러 인스턴스 모니터 [#helm-multi]

    `mysql.*` 대신, 단일 릴리스의 단일 수집기 파드에서 여러 MySQL 인스턴스(자체 호스팅 또는 RDS)를 모니터하도록 `mysqlMulti.enabled: true`을(를) 설정하십시오. 두 모드는 상호 배타적입니다. 동일한 릴리스에서 `mysql.server` 및 `mysqlMulti.enabled: true`을(를) 설정하지 마십시오.

    다중 인스턴스 모드에는 일반 사용자 이름/비밀번호 경로가 없습니다: 모든 인스턴스에는 모니터링 자격 증명이 있는 자체 Kubernetes 시크릿이 필요합니다. 설정 작업에서 각 모니터링 사용자를 생성하도록 할지 여부도 결정하십시오:

    <CollapserGroup>
      <Collapser id="helm-multi-nojob" title="설정 작업 없음">
        설치하기 전에 각 인스턴스의 모니터링-사용자 시크릿을 직접 생성하십시오(`values.yaml`에서 지정한 `name`과(와) 일치하도록 인스턴스별로 반복):

        ```bash
        kubectl create secret generic db1-monitor-creds \
          --from-literal=username=<MONITORING_USERNAME> \
          --from-literal=password='<MONITORING_PASSWORD>' \
          -n newrelic
        # Repeat for every instance (db2-monitor-creds, ...)
        ```

        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        # EDIT the two example entries below (or add more) to match
        # your real instances - each `name` must be unique within
        # this release and match the Secret you created for it.
        mysqlMulti:
          enabled: true
          topology: <self-hosted|rds>
          databases:
            - name: db1
              server: <YOUR_DB_1_HOST>
              existingSecret: db1-monitor-creds
            - name: db2
              server: <YOUR_DB_2_HOST>
              existingSecret: db2-monitor-creds

        # No admin credential is configured here since the setup
        # job is disabled - create each instance's monitoring user
        # yourself first.
        setupJob:
          enabled: false
        ```
      </Collapser>

      <Collapser id="helm-multi-setupjob" title="자동화된 설정 작업">
        각 인스턴스에는 자체 모니터링 사용자 시크릿과 자체 관리자 자격 증명 시크릿이 모두 필요합니다(인스턴스당 반복):

        ```bash
        kubectl create secret generic db1-monitor-creds \
          --from-literal=username=<MONITORING_USERNAME> \
          --from-literal=password='<MONITORING_PASSWORD>' \
          -n newrelic
        kubectl create secret generic db1-admin-creds \
          --from-literal=username=<ADMIN_USERNAME> \
          --from-literal=password='<ADMIN_PASSWORD>' \
          -n newrelic
        # Repeat for every instance (db2-monitor-creds, db2-admin-creds, ...)
        ```

        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        # EDIT the two example entries below (or add more) to match
        # your real instances - each `name` must be unique within
        # this release and match the Secrets you created for it.
        mysqlMulti:
          enabled: true
          topology: <self-hosted|rds>
          databases:
            - name: db1
              server: <YOUR_DB_1_HOST>
              existingSecret: db1-monitor-creds
              mysqlAdmin:
                existingSecret: db1-admin-creds
            - name: db2

          enabled: true
        ```

  <Step>
    ## Helm 차트를 설치하세요 [#helm-install]

    1. 뉴클릭 Helm 다음을 추가하세요.

       ```bash
       helm repo add newrelic https://helm-charts.newrelic.com
       helm repo update
       ```

    2. `values.yaml` 파일을 사용하여 차트를 설치하십시오:

       ```bash
       helm upgrade --install mysql-otel newrelic/mysql-otel \
         -n newrelic \
         --create-namespace \
         -f values.yaml
       ```
  </Step>

  <Step>
    ## 설치를 확인하십시오 [#helm-verify]

    1. 설정 작업이 완료되었고(활성화된 경우) 수집기 파드가 실행 중인지 확인하십시오:

       ```bash
       kubectl get jobs,pods -n newrelic --watch
       ```

    2. 데이터가 수신되는지 확인하려면 [쿼리 빌더](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/)에서 이 쿼리를 실행하십시오:

       ```sql
       SELECT count(*) FROM Metric
       WHERE metricName LIKE 'mysql.%'
       AND instrumentation.provider = 'opentelemetry'
       SINCE 10 minutes ago
       ```
  </Step>

  <Step>
    ## 데이터 찾기 및 사용 [#find]

    데이터가 수집되면 뉴렐릭 UI를 통해 포괄적인 MySQL 데이터베이스 모니터링에 액세스할 수 있습니다.

    뉴렐릭에서 MySQL 데이터베이스 엔티티를 찾으려면 다음을 수행하십시오:

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT> 으)로 이동합니다.
    2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**MySQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.
    3. 엔티티 목록에서 MySQL 데이터베이스를 선택하십시오.
  </Step>
