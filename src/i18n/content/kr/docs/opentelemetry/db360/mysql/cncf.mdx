MySQL용 OpenTelemetry Collector Contrib를 사용하여 인스턴스를 모니터할 수 있습니다. OpenTelemetry Collector Contrib는 MySQL에서 텔레메트리 데이터를 수집하여 뉴렐릭으로 전송하는 커뮤니티 지원 프로젝트입니다.

기본적으로 OpenTelemetry Collector Contrib는 MySQL에서 제한된 메트릭을 수집합니다. 쿼리 성능, 대기 이벤트, 세션 및 클라이언트 메트릭을 전송하려면 OpenTelemetry Collector Contrib를 구성해야 합니다. 이 가이드에서는 MySQL에서 고급 메트릭을 수집하여 뉴렐릭으로 전송하도록 구성하는 방법을 설명합니다.

<Callout variant="tip" title="메모">
이 페이지에서는 표준 `otelcol-contrib` 바이너리로 제공되는 커뮤니티 `mysqlreceiver`에 대해 설명합니다. 뉴렐릭의 배포판(NRDOT)을 사용하는 경우 대신 [Self-hosted MySQL \[자체 호스팅 MySQL\]](/docs/opentelemetry/db360/mysql/introduction)을 참조하십시오.
</Callout>

<Steps>
<Step>
## 전제 조건 [#prerequisites]

* 시스템에 설치 및 구성된 OpenTelemetry Collector Contrib(`otelcol-contrib`). [OpenTelemetry Collector 릴리스](https://github.com/open-telemetry/opentelemetry-collector-releases/releases) 페이지에서 최신 릴리스를 다운로드할 수 있습니다.
* `performance_schema` 모니터되는 MySQL/MariaDB 인스턴스에서 활성화됩니다(MySQL 5.6.6부터 기본적으로 켜져 있음).
</Step>

<Step>
## UI 메트릭 활성화 [#enable]

`otelcol-contrib` 설정 파일에 메트릭을 추가하고 활성화하여 뉴렐릭 플랫폼 경험을 향상시킬 수 있습니다. 이 섹션에서 제공하는 설정을 사용하면 뉴렐릭 플랫폼의 다음 페이지에 데이터를 채울 수 있습니다:

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="개요 페이지 메트릭 활성화">
<DNT>Overview</DNT> 페이지는 연결, 버퍼 풀 상태, I/O, 잠금, 테이블 크기 및 느린 쿼리 비율과 같은 주요 메트릭을 포함하여 MySQL 인스턴스에 대한 상위 수준 뷰를 표시합니다. `mysql.commands` 및 `mysql.innodb.data_file.io`는 추가적으로 APM 서비스의 트레이스와 해당 MySQL 쿼리 활동 간의 교차 탐색인 APM-DB 연결을 지원합니다.

뉴렐릭 플랫폼의 <DNT>Overview</DNT> 페이지에 데이터를 채우려면 `otelcol-contrib` 설정 파일에 다음 설정을 추가하십시오:

```yaml
receivers:
  mysql:
    metrics:
      mysql.query.count:
        enabled: true
      mysql.query.slow.count:
        enabled: true
      mysql.table.size:
        enabled: true
      mysql.commands:
        enabled: true
      mysql.innodb.data_file.io:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="쿼리 성능, 세션, 대기 및 클라이언트 메트릭 활성화">
<DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT> 및 <DNT>Clients</DNT> 페이지에 데이터를 채우려면:

* Query performance \[쿼리 성능]: 다음 탭에서 MySQL 인스턴스에서 실행 중인 쿼리에 대한 자세한 정보를 표시합니다.

  * Normalized queries \[정규화된 쿼리]: 쿼리당 실행 횟수와 평균 소요 시간을 표시합니다.
  * Query samples \[쿼리 샘플]: 소요 시간, 대기 유형, 데이터베이스, DB 사용자 및 클라이언트 호스트를 포함한 개별 쿼리 실행을 표시합니다.

* Wait events \[대기 이벤트]: 샘플링될 때 대기 중이던 명령문의 대기 유형과 대기 시간을 표시합니다.

* Sessions \[세션]: 세션 수, 세션 상태 및 개별 세션 세부 정보를 포함하여 MySQL 인스턴스에 연결된 세션에 대한 정보를 표시합니다.

* Clients\[클라이언트]: 연결된 DB 사용자 및 클라이언트 호스트 세부 정보를 포함하여 MySQL 인스턴스에 연결된 클라이언트에 대한 정보를 표시합니다.

다음 설정을 `otelcol-contrib` 설정 파일에 추가하십시오:

```yaml
receivers:
  mysql:
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      lookback_time: 60
      max_query_sample_count: 1000
      top_query_count: 250
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 100
```

<Callout variant="important">
`db.server.query_plan` `db.server.top_query` 또는 `db.server.query_sample` 중 하나 이상이 함께 활성화되어야 합니다. 단독으로 활성화하면 설정 유효성 검사 오류가 발생합니다.
</Callout>

<Callout variant="tip" title="메모">
커뮤니티 MySQL 수신기는 저장 프로시저 수집이나 차단된 세션 감지를 지원하지 않습니다. Sessions \[세션] 및 Clients \[클라이언트]에 데이터가 채워지지만, 차단된 세션의 차단자는 표시되지 않습니다.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## OpenTelemetry Collector 다시 시작 [#restart]

설정 변경 사항을 적용하려면 다음 명령을 실행하여 OpenTelemetry Collector를 다시 시작하십시오:

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
