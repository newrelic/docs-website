Linux에서 OpenTelemetry의 뉴렐릭 배포판(NRDOT) 수집기를 사용하여 데이터베이스 메트릭, 쿼리 분석 및 시스템 상태 데이터로 Azure SQL 데이터베이스 성능을 모니터하십시오.

<Callout variant="tip">
Windows에서 수집기를 실행하려면 [Windows의 Azure SQL 데이터베이스](/docs/opentelemetry/db360/mssql/azure-sql-windows)를 참조하십시오.
</Callout>

<Steps>
<Step>
## 전제 조건 [#prerequisites]

* 유효한 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)가 있는 뉴렐릭 계정.

* 해당 리전의 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp)에 대한 네트워크 연결.

* Azure SQL 데이터베이스 요구 사항:

  * Azure SQL 논리 서버 및 데이터베이스.
  * 서버 관리자 로그인 및 비밀번호(또는 `master`에서 로그인을 생성하고 서버 역할을 관리할 수 있는 다른 계정).
  * 서버 방화벽 규칙, 가상 네트워크 규칙 또는 프라이빗 엔드포인트를 통한 수집기 호스트에서 포트 `1433`의 서버로의 네트워크 액세스. 서버가 프라이빗 엔드포인트를 사용하는 경우, 서버 이름은 수집기 호스트의 프라이빗 IP 주소로 확인되어야 합니다.

* Collector 호스트 요구 사항: `sqlcmd` 유틸리티가 설치된 호스트(예: Azure VM).
</Step>

<Step>
## NRDOT Collector설치하세요 [#setup]

Azure SQL 서버에 연결할 수 있는 호스트에 NRDOT Collector를 설치하십시오.

AMD64 기반 Debian/Ubuntu의 경우:

```bash
NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
```

기타 배포판 및 아키텍처의 경우 [Linux RDS 설치 단계](/docs/opentelemetry/db360/mssql/linux-rds#setup) 및 [nrdot-collector-releases](https://github.com/newrelic/nrdot-collector-releases/releases) 페이지를 참조하십시오.
</Step>

<Step>
## 모니터링 사용자 생성 및 권한 부여 [#user]

Azure SQL 데이터베이스는 `GRANT VIEW SERVER STATE` 및 유사한 인스턴스 수준의 권한 부여를 허용하지 않습니다. 대신 `master`의 기본 제공 서버 역할에 로그인을 추가한 다음, 모니터할 각 데이터베이스에 사용자를 생성합니다.

1. `nr-grant-permission-master.sql` (이)라는 이름의 파일을 생성하고 `<YOUR_PASSWORD>`을(를) 원하는 비밀번호로 변경하십시오:

   ```sql
   CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
   GO
   ALTER SERVER ROLE [##MS_ServerStateReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DefinitionReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DatabaseConnector##] ADD MEMBER [newrelic];
   GO
   ```

2. 서버 관리자 권한으로 `master` 데이터베이스에 대해 실행하십시오. `<YOUR-SERVER>`을(를) 서버 이름(예: `myserver.database.windows.net`)(으)로 변경하십시오:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-master.sql
   ```

3. `nr-grant-permission-db.sql` 이라는 파일을 만듭니다.

   ```sql
   CREATE USER [newrelic] FOR LOGIN [newrelic];
   GO
   GRANT VIEW DATABASE STATE TO [newrelic];
   GO
   ```

4. 모니터하려는 **각** 데이터베이스에 대해 실행하십시오. `<YOUR_DATABASE>`을(를) 데이터베이스 이름으로 변경하십시오:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-db.sql
   ```

   다음 표는 각 역할이 필요한 이유를 보여줍니다:

   | 역할 또는 권한                   | 사용                                                                          |
   | -------------------------- | --------------------------------------------------------------------------- |
   | `##MS_ServerStateReader##` | 서버 수준 동적 관리 뷰(예: `sys.dm_exec_query_stats`) 및 `sys.dm_exec_procedure_stats` |
   | `##MS_DefinitionReader##`  | 상위 프로시저 및 인덱스 통계에 대한 객체 및 스키마 이름 확인                                         |
   | `##MS_DatabaseConnector##` | 인덱스 물리적 통계를 수집하기 위해 데이터베이스에 연결                                              |
   | `VIEW DATABASE STATE`      | 다음과 같은 데이터베이스 범위 동적 관리 뷰 `sys.dm_db_resource_stats`                         |

5. (선택 사항) `master` 데이터베이스에서 서버 역할을 확인하십시오:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -Q "SELECT r.name AS [Role], l.name AS [Login] FROM sys.server_role_members rm JOIN sys.server_principals r ON rm.role_principal_id = r.principal_id JOIN sys.sql_logins l ON rm.member_principal_id = l.principal_id WHERE l.name = 'newrelic';"
   ```

   출력에 세 가지 역할이 모두 나열됩니다.

6. (선택 사항) 모니터링 사용자로 연결하여 데이터베이스 권한을 확인하십시오:

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U newrelic -P '<YOUR_PASSWORD>' -C -Q "SELECT TOP 1 * FROM sys.dm_db_resource_stats; SELECT TOP 1 * FROM sys.dm_exec_query_stats;"
   ```

   권한 오류는 권한 부여가 누락되었음을 의미합니다.

<Callout variant="tip">
데이터베이스 자격 증명과 같은 민감한 정보를 안전하게 관리하려면 [시크릿 관리](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management) 도구에 저장하십시오.
</Callout>
</Step>

<Step>
## NRDOT Collector구성 [#configure-collector]

1. 설정 파일을 생성하십시오:

   ```bash
   sudo nano /etc/nrdot-collector/mssql-config.yaml
   ```

2. 다음 설정을 추가합니다. `<YOUR_PASSWORD>`, `<YOUR-SERVER>`, `<YOUR_DATABASE>`, `<YOUR_LICENSE_KEY>` 및 OTLP 엔드포인트를 해당 값으로 변경하십시오:

   ```yaml
   receivers:
     nrsqlserver:
       collection_interval: 15s
       # datasource replaces username, password, server, and port.
       datasource: "sqlserver://newrelic:<YOUR_PASSWORD>@<YOUR-SERVER>:1433?database=<YOUR_DATABASE>"

       metrics:
         sqlserver.database.io:
           enabled: true
         sqlserver.database.latency:
           enabled: true
         sqlserver.database.operations:
           enabled: true
         sqlserver.database.tempdb.space:
           enabled: true
         sqlserver.database.tempdb.version_store.size:
           enabled: true
         sqlserver.deadlock.rate:
           enabled: true
         sqlserver.os.wait.duration:
           enabled: true
         sqlserver.processes.blocked:
           enabled: true
         sqlserver.memory.grants.pending.count:
           enabled: true
         sqlserver.database.file.size:
           enabled: true
         sqlserver.memory.area:
           enabled: true

       events:
         db.server.query_sample:
           enabled: true
         db.server.top_query:
           enabled: true
         db.server.query_plan:
           enabled: true
         db.server.top_procedure:
           enabled: true

       top_query_collection:
         lookback_time: 60s
         max_query_sample_count: 1000
         top_query_count: 250
         collection_interval: 60s
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       query_sample_collection:
         max_rows_per_query: 100
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       top_procedure_collection:
         max_procedure_sample_count: 1000
         top_procedure_count: 250
         collection_interval: 60s

       resource_attributes:
         db.system.version:
           enabled: true
         sqlserver.db.edition:
           enabled: true

   processors:
     memory_limiter:
       check_interval: ${env:NR_MEM_LIMITER_CHECK_INTERVAL:-1s}
       limit_mib:       ${env:NR_MEM_LIMITER_LIMIT_MIB:-200}
       spike_limit_mib: ${env:NR_MEM_LIMITER_SPIKE_MIB:-50}

   exporters:
     otlp:
       endpoint: https://otlp.nr-data.net:4318
       headers:
         api-key: <YOUR_LICENSE_KEY>
       tls:
         insecure: false
       compression: gzip
       sending_queue:
         enabled: true
         sizer: bytes
         queue_size: 100_000_000
         num_consumers: 10
         batch:
           sizer: bytes
           max_size: 1_000_000
           min_size: 0
           flush_timeout: 5s

   service:
     telemetry:
       metrics:
         level: none
     pipelines:
       metrics:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
       logs:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
   ```

<Callout variant="tip">
* `datasource` 값은 연결 URL입니다. 암호에 문자, 숫자 및 `- . _ ~ ! $ * + ,` 이외의 문자가 포함된 경우 이를 URL 인코딩하십시오.
* 수집기는 `database=`에 지정된 단일 데이터베이스에 연결합니다. 동일한 서버에서 여러 데이터베이스를 모니터하려면 [다중 수신자 설정](/docs/opentelemetry/db360/mssql/multi-receiver#multi)에 설명된 대로 각각에 별도의 수신자를 사용하십시오.
* Always-On, 장애 조치 클러스터 및 일부 래치와 tempdb 메트릭은 Azure SQL 데이터베이스에서 사용할 수 없으며 데이터를 반환하지 않습니다.
* `logs` 파이프라인은 수집기 디버그 로그가 아닌 SQL Server 쿼리 텔레메트리(쿼리 텍스트, 실행 계획 및 샘플)를 전달합니다.
</Callout>
</Step>

<Step>
## NRDOT Collector 설정 업데이트 [#update]

1. 서비스 설정 파일을 편집하십시오:

   ```bash
   sudo nano /etc/nrdot-collector/nrdot-collector.conf
   ```

2. 설정 경로를 새 파일로 지정하십시오:

   ```bash
   OTELCOL_CONFIG="/etc/nrdot-collector/mssql-config.yaml"
   ```

3. (선택 사항) 설정을 확인하십시오:

   ```bash
   sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mssql-config.yaml
   ```
</Step>

<Step>
## NRDOT Collector를 다시 시작하십시오 [#restart]

```bash
sudo systemctl restart nrdot-collector
```

권한 또는 연결 오류가 있는지 수집기 로그를 확인하십시오:

```bash
sudo journalctl -u nrdot-collector -n 50 --no-pager
```
</Step>

<Step>
## 데이터 찾기 및 사용 [#find]

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT> 으)로 이동합니다.
2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**MSSQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.
3. 엔티티 목록에서 Azure SQL 데이터베이스를 선택하십시오.
</Step>
</Steps>
