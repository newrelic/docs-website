`newrelic-install` Chef 쿡북을 사용하여 SQL Server 모니터링용 NRDOT Collector를 설치하고 구성할 수 있습니다. `newrelic-install::default` 레시피를 실행하면 쿡북은 수집기를 설치하고, 모니터링 ID를 생성하거나 권한을 부여하며, 수집기를 구성합니다.

<Callout variant="tip" title="가이드 설치">
  대신 뉴렐릭 UI를 통해 설치하려면 <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>(으)로 이동하십시오. 화면의 지시에 따라 통합을 설정하십시오. 이 페이지에서는 수동 설치만 다룹니다.
</Callout>

<Steps>
  <Step>
    ## 전제 조건 [#prerequisites]

    * 유효한 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)가 있는 뉴렐릭 계정.

    * 뉴렐릭 [계정 ID](/docs/accounts/accounts-billing/account-structure/account-id).

    * Microsoft SQL Server 2017 이상.

    * Chef 15 이상이 필요합니다.

    * **자체 호스팅 SQL Server:**

      * **SQL Server 인증:** Windows, Ubuntu 또는 RHEL/CentOS 수집기 호스트, 그리고 `sysadmin` 서버 역할(또는 동급)의 로그인 및 해당 비밀번호.
      * **Windows 인증 또는 gMSA:** 권한을 부여할 Windows 수집기 호스트 및 Windows 도메인 계정(또는 gMSA)입니다.

    * **AWS RDS의 SQL Server:**

      * RDS 마스터 사용자 이름 및 비밀번호와 함께, RDS 엔드포인트(RDS 보안 그룹 내의 SQL Server 포트에서 인바운드 액세스가 허용됨)에 대한 네트워크 연결이 있는 Windows, Ubuntu 또는 RHEL/CentOS 수집기 호스트입니다.
      * **Windows 도메인 인증 또는 gMSA:** AWS Managed Microsoft Active Directory 도메인에 이미 조인된 Windows 수집기 호스트 및 RDS 인스턴스.

    * 타겟 리전에 해당하는 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp)에 대한 네트워크 연결
  </Step>

  <Step>
    ## Chef 쿡북을 다운로드합니다. [#chef-download-cookbook]

    Chef Supermarket에서 `newrelic-install` [Chef 쿡북](https://supermarket.chef.io/cookbooks/newrelic-install)을 chef-repo 디렉터리로 다운로드하십시오:

    ```bash
    knife supermarket install newrelic-install
    ```
  </Step>

  <Step>
    ## 기본 속성을 교체하십시오. [#chef-configure]

    `attributes/default.rb`의 기본 속성을 계정 세부 정보로 변경하십시오:

    <CollapserGroup>
      <Collapser id="chef-host-sql" title="자체 호스팅-SQL Server 인증">
        이 쿡북은 단일 수집기에서 하나 이상의 SQL Server 인스턴스를 모니터합니다. 단일 호스트/포트/자격 증명 세트 대신, 노드에 이미 존재해야 하는 두 개의 파일을 읽습니다. 이는 모니터할 모든 인스턴스를 나열하는 **인스턴스 파일** (YAML)과 일치하도록 인덱싱된 각 인스턴스의 관리자 로그인 및 비밀번호가 포함된 **시크릿 파일** (`KEY=VALUE`)입니다.

        1. 노드에 인스턴스 파일을 생성하십시오. 이 수집기가 모니터할 SQL Server 인스턴스당 하나의 항목을 추가하거나, 단일 인스턴스만 실행 중인 경우 하나의 항목만 추가하십시오:

           ```yaml
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
           ```

        2. 인스턴스 파일의 순서와 일치하도록 인덱싱하여, 각 인스턴스에 대한 관리자 로그인 및 비밀번호가 포함된 시크릿 파일을 노드에 생성하십시오. 관리자 로그인은 `sysadmin` 역할(또는 동등한 역할)의 구성원이어야 합니다:

           ```bash
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
           ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']    = <path to the secrets file (KEY=VALUE per instance) on the node>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

      <Collapser id="chef-host-winauth" title="자체 호스팅-Windows 인증 또는 gMSA">
        이 타겟은 Windows 수집기 호스트에서만 지원됩니다. SQL 로그인 대신 Windows 인증(`integrated security=true`)을 사용하며, **인스턴스 파일** (YAML, 인스턴스당 `host`/`port`, 시크릿 파일 없음: 하나의 Windows ID가 모든 인스턴스를 모니터합니다)을 사용하여 단일 수집기에서 하나 이상의 SQL Server 인스턴스를 모니터합니다.

        단일 인스턴스만 실행하는 경우, 이 파일은 노드에 이미 존재해야 하며 단 하나의 항목만 있어야 합니다. `host` 및 `port`만 필요합니다(`login_name` 제외):

        ```yaml
        instances:
          - host: sql01.contoso.com
            port: 1433
          - host: sql02.contoso.com
            port: 1433
        ```

        명명된 인스턴스의 경우, `host\INSTANCE` 대신 `host` 및 해당 정적 TCP 포트를 사용하십시오.

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-winauth'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']    = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']        = <1 for Windows Domain Auth, 2 for gMSA, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WINAUTH_LOCATION'] = <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']   = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']      = <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']     = <password for that account; required only for Windows Domain Auth on a different host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']     = <gMSA account, DOMAIN\gMSAName$; gMSA only>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

      <Collapser id="chef-rds-sql" title="AWS RDS - SQL Server 인증">
        이 쿡북은 자체 호스팅과 동일한 인스턴스 파일/시크릿 파일 패턴을 사용하여 단일 수집기에서 하나 이상의 RDS SQL Server 엔드포인트를 모니터합니다(두 파일 모두 노드에 이미 존재해야 합니다).

        1. 단일 RDS 인스턴스만 모니터링하는 경우 단 하나의 항목만 포함하여, RDS 엔드포인트를 `host`(으)로 사용하여 노드에 인스턴스 파일을 생성하십시오:

           ```yaml
           instances:
             - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
               port: 1433
               login_name: newrelic
           ```

        2. 인스턴스 파일의 순서와 일치하도록 인덱싱하여, 각 인스턴스의 RDS 마스터 사용자 이름 및 암호를 사용하여 노드에 시크릿 파일을 생성하십시오:

           ```bash
           NR_CLI_MSSQL_ADMIN_USER_1=admin
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=YourMasterPassword1
           ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-rds'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']  = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE'] = <path to the instances YAML file on the node, using RDS endpoints as host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']   = <path to the secrets file (KEY=VALUE per instance) on the node>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

        이 타겟은 Windows 수집기 호스트에서만 지원되며 RDS 인스턴스가 AWS Managed Microsoft AD 도메인에 이미 조인되어 있어야 합니다. **인스턴스 파일** (YAML, 인스턴스당 `host`/`port`, RDS 엔드포인트를 `host`(으)로 사용)을 사용하여 단일 수집기에서 하나 이상의 RDS SQL Server 엔드포인트를 모니터합니다. 위의 자체 호스팅 타겟과 달리 여기에는 &quot;동일 호스트&quot; 옵션이 없습니다: 도메인 계정(또는 gMSA)이 항상 필요합니다.

        이 파일은 각 RDS 엔드포인트를 `host`(으)로 사용하여 노드에 이미 존재해야 하며, 단일 RDS 인스턴스만 모니터링하는 경우에는 항목이 하나만 있어야 합니다:

        ```yaml
        instances:
          - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
          - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
        ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-rds-winauth'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']       = <1 for Windows Domain Auth, 2 for gMSA, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node, using RDS endpoints as host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']     = <Windows domain account, DOMAIN\username; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']    = <password for that account; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']    = <gMSA account, DOMAIN\gMSAName$; gMSA only>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

    ## 데이터 찾기 및 사용 [#find]

    데이터가 수집되면 뉴렐릭 UI를 통해 포괄적인 SQL Server 데이터베이스 모니터링에 액세스할 수 있습니다.

    뉴렐릭에서 SQL Server 데이터베이스를 찾으려면 다음을 수행하세요.

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT> 으)로 이동합니다.

    2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**MSSQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.

    3. 모임 목록에서 SQL Server 데이터베이스를 선택합니다.

       NRDOT로 SQL Server 모니터링을 설정한 후 다음을 수행할 수 있습니다:

       * [사용자 정의 대시보드를 만들어](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) 데이터베이스 지표를 시각화하세요.
       * 중요한 데이터베이스 성능에 대한 [알림 설정](/docs/alerts/create-alert/create-alert-condition/alert-conditions/), 참조 값
       * 뉴렐릭 쿼리 기능을 사용하여 [데이터 탐색](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)
  </Step>
