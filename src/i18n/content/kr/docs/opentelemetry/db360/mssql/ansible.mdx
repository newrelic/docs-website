`newrelic.newrelic_install` Ansible 역할을 사용하여 SQL Server 모니터링을 위한 NRDOT Collector를 설치하고 구성할 수 있습니다. 이 역할은 단일 플레이에서 수집기를 설치하고, 모니터링 ID를 생성하거나 권한을 부여하며, 수집기를 구성합니다.

<Callout variant="tip" title="가이드 설치">
  대신 뉴렐릭 UI를 통해 설치하려면 <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>(으)로 이동하십시오. 화면의 지시에 따라 통합을 설정하십시오. 이 페이지에서는 수동 설치만 다룹니다.
</Callout>

<Steps>
  <Step>
    ## 전제 조건 [#prerequisites]

    * 유효한 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)가 있는 뉴렐릭 계정.

    * 뉴렐릭 [계정 ID](/docs/accounts/accounts-billing/account-structure/account-id).

    * Microsoft SQL Server 2017 이상.

    * Ansible Core 2.13 또는 2.14, 파이썬 3.10, 그리고 `ansible.windows` 및 `ansible.utils` 컬렉션.

    * 자체 호스팅 SQL Server:

      * SQL Server 인증: Linux 또는 Windows 수집기 호스트, 그리고 `sysadmin` 서버 역할(또는 동급)의 로그인 및 해당 비밀번호입니다.
      * Windows 인증 또는 gMSA: Windows 수집기 호스트, 관리자 PowerShell 세션, 그리고 필요한 권한이 있는 Windows 계정 또는 그룹 관리 서비스 계정(`gMSA`).

    * AWS RDS의 SQL Server:

      * 데이터베이스 마스터 사용자 이름 및 비밀번호와 함께 데이터베이스 엔드포인트(보안 그룹 내 SQL Server 포트에서 인바운드 액세스 허용)에 대한 네트워크 연결이 있는 Linux 또는 Windows 수집기 호스트.
      * Windows 도메인 인증 또는 gMSA: Windows 수집기 호스트 및 AWS Managed Microsoft Active Directory 도메인에 가입된 인스턴스입니다.

    * Linux 수집기 호스트: `curl` 유틸리티, `systemd` 및 `sqlcmd` 유틸리티가 설치되어 `PATH`에서 사용 가능(또는 `/opt/mssql-tools18/bin` 또는 `/opt/mssql-tools/bin`에 위치).

    * Windows 수집기 호스트: `sqlcmd.exe` 유틸리티가 설치되어 있고 `PATH`에서 사용할 수 있습니다.

    * 타겟 리전에 해당하는 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp)에 대한 네트워크 연결
  </Step>

  <Step>
    ## 역할 설치 [#ansible-install-role]

```bash
    ansible-galaxy install newrelic.newrelic_install
```

    필요한 컬렉션도 설치되어 있는지 확인하십시오:

```bash
    ansible-galaxy collection install ansible.windows ansible.utils
```
  </Step>

  <Step>
    ## 플레이북을 구성하십시오. [#ansible-configure]

    <CollapserGroup>
      <Collapser id="ansible-host-sql" title="자체 호스팅-SQL Server 인증">
        이 역할은 단일 수집기에서 하나 이상의 SQL Server 인스턴스를 모니터링합니다. 단일 호스트/포트/자격 증명 세트 대신, 타겟 호스트에 이미 존재해야 하는 두 개의 파일, 즉 모니터링할 모든 인스턴스를 나열하는 인스턴스 파일(YAML)과 일치하도록 인덱싱된 각각의 관리자 로그인 및 비밀번호가 포함된 비밀 파일(`KEY=VALUE`)을 읽습니다.

        1. 타겟 호스트에 인스턴스 파일을 생성하십시오. 이 수집기가 모니터할 SQL Server 인스턴스당 하나의 항목을 추가하거나, 단일 인스턴스만 실행 중인 경우 하나의 항목만 추가하십시오:

```yaml
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
```

        2. 인스턴스 파일의 순서와 일치하도록 인덱싱하여, 각 인스턴스에 대한 관리자 로그인 및 비밀번호가 포함된 시크릿 파일을 타겟 호스트에 생성하십시오. 관리자 로그인은 `sysadmin` 역할(또는 동등한 역할)의 구성원이어야 합니다:

```bash
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
```

        그런 다음 이름이 `playbook.yml` 인 파일을 생성하고 다음 콘텐츠를 해당 파일에 복사합니다. `targets`을(를) `mssql-otel` (으)로 설정하고 플레이스홀더 값을 사용자 고유의 값으로 바꿉니다:

```yaml
        - name: Install New Relic NRDOT for SQL Server
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_MSSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

        <Callout variant="tip">
          디버그 로깅을 활성화하려면 플레이북의 `vars` 아래에 `verbosity: "debug"`을(를) 추가하십시오.
        </Callout>

      <Collapser id="ansible-host-winauth" title="자체 호스팅-Windows 인증 또는 gMSA">
        이 타겟은 Windows 수집기 호스트에서만 지원됩니다. SQL 로그인 대신 Windows 인증(`integrated security=true`)을 사용하며, **인스턴스 파일** (YAML, 인스턴스당 `host`/`port`, 시크릿 파일 없음: 하나의 Windows ID가 모든 인스턴스를 모니터합니다)을 사용하여 단일 수집기에서 하나 이상의 SQL Server 인스턴스를 모니터합니다.

        단일 인스턴스만 실행하는 경우 항목이 하나만 있는 인스턴스 파일을 타겟 호스트에 생성하십시오. `host` 및 `port`만 필요합니다(`login_name` 없음):

```yaml
        instances:
          - host: sql01.contoso.com
            port: 1433
          - host: sql02.contoso.com
            port: 1433
```

        명명된 인스턴스의 경우, `host\INSTANCE` 대신 `host` 및 해당 정적 TCP 포트를 사용하십시오.

        그런 다음 이름이 `playbook.yml` 인 파일을 생성하고 다음 콘텐츠를 해당 파일에 복사합니다. `targets`을(를) `mssql-otel-winauth` (으)로 설정하고 플레이스홀더 값을 사용자 고유의 값으로 바꿉니다:

```yaml
        - name: Install New Relic NRDOT for SQL Server (Windows Auth)
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel-winauth
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_AUTH_MODE: <1 for Windows Domain Auth, 2 for gMSA, default 1>
            NR_CLI_MSSQL_WINAUTH_LOCATION: <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_MSSQL_WIN_ACCOUNT: <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
            NR_CLI_MSSQL_WIN_PASSWORD: <password for that account; required only for Windows Domain Auth on a different host>
            NR_CLI_MSSQL_GMSA_ACCOUNT: <gMSA account, DOMAIN\gMSAName$; gMSA only>
```

        <Callout variant="tip">
          디버그 로깅을 활성화하려면 플레이북의 `vars` 아래에 `verbosity: "debug"`을(를) 추가하십시오.
        </Callout>

      <Collapser id="ansible-rds-sql" title="AWS RDS - SQL Server 인증">
        이 역할은 자체 호스팅과 동일한 인스턴스 파일/시크릿 파일 패턴을 사용하여 단일 수집기에서 하나 이상의 RDS SQL Server 엔드포인트를 모니터합니다(두 파일 모두 타겟 호스트에 이미 존재해야 합니다).

        1. 단일 RDS 인스턴스만 모니터링하는 경우 RDS 엔드포인트를 `host`(으)로 사용하여 항목이 하나만 있는 인스턴스 파일을 타겟 호스트에 생성하십시오:

```yaml
           instances:
             - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
               port: 1433
               login_name: newrelic
```

        2. 인스턴스 파일의 순서와 일치하도록 인덱싱된 각 인스턴스의 RDS 마스터 사용자 이름 및 비밀번호를 사용하여 타겟 호스트에 시크릿 파일을 생성합니다:

```bash
           NR_CLI_MSSQL_ADMIN_USER_1=admin
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=YourMasterPassword1
```

        그런 다음 이름이 `playbook.yml` 인 파일을 생성하고 다음 콘텐츠를 해당 파일에 복사합니다. `targets`을(를) `mssql-otel-rds` (으)로 설정하고 플레이스홀더 값을 사용자 고유의 값으로 바꿉니다:

```yaml
        - name: Install New Relic NRDOT for SQL Server on RDS
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel-rds
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
            NR_CLI_MSSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

        <Callout variant="tip">
          디버그 로깅을 활성화하려면 플레이북의 `vars` 아래에 `verbosity: "debug"`을(를) 추가하십시오.
        </Callout>

          이 수집기에서 둘 이상의 RDS SQL Server 엔드포인트를 모니터하려면 인스턴스 파일에 항목을 더 추가하고 시크릿 파일에 일치하는 번호가 지정된 자격 증명을 추가하십시오. 검사에 실패한 인스턴스는 전체 설치를 중단하는 대신 로그에 기록된 이유와 함께 건너뜁니다.
        </Callout>
      </Collapser>

      <Collapser id="ansible-rds-winauth" title="AWS RDS - Windows 도메인 인증 또는 gMSA">
        이 타겟은 Windows 수집기 호스트에서만 지원되며 RDS 인스턴스가 AWS Managed Microsoft AD 도메인에 이미 조인되어 있어야 합니다. **인스턴스 파일** (YAML, 인스턴스당 `host`/`port`, RDS 엔드포인트를 `host`(으)로 사용)을 사용하여 단일 수집기에서 하나 이상의 RDS SQL Server 엔드포인트를 모니터합니다. 위의 자체 호스팅 타겟과 달리 여기에는 &quot;동일 호스트&quot; 옵션이 없습니다: 도메인 계정(또는 gMSA)이 항상 필요합니다.

        각 RDS 엔드포인트를 `host`(으)로 지정하고, 단일 RDS 인스턴스만 모니터링하는 경우 하나의 항목만 사용하여 타겟 호스트에 인스턴스 파일을 생성하십시오:

```yaml
        instances:
          - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
          - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
```

        그런 다음 이름이 `playbook.yml` 인 파일을 생성하고 다음 콘텐츠를 해당 파일에 복사합니다. `targets`을(를) `mssql-otel-rds-winauth` (으)로 설정하고 플레이스홀더 값을 사용자 고유의 값으로 바꿉니다:

```yaml
        - name: Install New Relic NRDOT for SQL Server on RDS (Windows Auth)
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mssql-otel-rds-winauth
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MSSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MSSQL_AUTH_MODE: <1 for Windows Domain Auth, 2 for gMSA, default 1>
            NR_CLI_MSSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
            NR_CLI_MSSQL_WIN_ACCOUNT: <Windows domain account, DOMAIN\username; Windows Domain Auth only>
            NR_CLI_MSSQL_WIN_PASSWORD: <password for that account; Windows Domain Auth only>
            NR_CLI_MSSQL_GMSA_ACCOUNT: <gMSA account, DOMAIN\gMSAName$; gMSA only>
```

        <Callout variant="tip">
          디버그 로깅을 활성화하려면 플레이북의 `vars` 아래에 `verbosity: "debug"`을(를) 추가하십시오.
        </Callout>

    ## 데이터 찾기 및 사용 [#find]

    데이터가 수집되면 뉴렐릭 UI를 통해 포괄적인 SQL Server 데이터베이스 모니터링에 액세스할 수 있습니다.

    뉴렐릭에서 SQL Server 데이터베이스를 찾으려면 다음을 수행하세요.

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT> 으)로 이동합니다.

    2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**MSSQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.

    3. 모임 목록에서 SQL Server 데이터베이스를 선택합니다.

       NRDOT로 SQL Server 모니터링을 설정한 후 다음을 수행할 수 있습니다:

       * [사용자 정의 대시보드를 만들어](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) 데이터베이스 지표를 시각화하세요.
       * 중요한 데이터베이스 성능에 대한 [알림 설정](/docs/alerts/create-alert/create-alert-condition/alert-conditions/), 참조 값
       * 뉴렐릭 쿼리 기능을 사용하여 [데이터 탐색](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)
  </Step>
