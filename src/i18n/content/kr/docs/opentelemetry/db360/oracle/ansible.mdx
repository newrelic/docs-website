`newrelic.newrelic_install` Ansible 역할을 사용하여 오라클 데이터베이스 모니터링을 위한 NRDOT Collector를 설치하고 구성할 수 있습니다. 이 역할은 단일 플레이에서 수집기를 설치하고, 모니터링 데이터베이스 사용자를 생성하며, 수집기를 구성합니다.

<Callout variant="tip" title="가이드 설치">
  대신 뉴렐릭 UI를 통해 설치하려면 <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>(으)로 이동하십시오. 이 페이지는 수동 설치만 다룹니다.
</Callout>

<Steps>
  <Step>
    ## 전제 조건 [#prerequisites]

    * 유효한 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)가 있는 뉴렐릭 계정.
    * 뉴렐릭 [계정 ID](/docs/accounts/accounts-billing/account-structure/account-id).
    * 오라클 데이터베이스 19c 이상입니다.
    * Ansible Core 2.13 또는 2.14, 파이썬 3.10, 그리고 `ansible.windows` 및 `ansible.utils` 컬렉션.
    * 자체 호스팅 오라클의 경우: SSH 사용자가 비밀번호 프롬프트 없이 `sudo su - oracle`을(를) 실행할 수 있는 오라클 데이터베이스 호스트에 대한 SSH 액세스(에이전트 포워딩 포함)가 있는 오라클 Linux 7, 8 또는 9여야 합니다.
    * AWS RDS의 오라클의 경우: Debian/Ubuntu 또는 CentOS/RHEL/OEL을 실행하는 수집기 호스트.
    * 오라클 자율운영 데이터베이스(ADB)의 경우: 데비안/우분투 또는 CentOS/RHEL/OEL을 실행하고 오라클 인스턴트 클라이언트(`sqlplus`)가 설치되어 있으며 `PATH`에 있는 수집기 호스트가 필요하며, 각 인스턴스의 이그레스 IP가 해당 ADB 액세스 제어 목록에 허용되어야 하고, 각 인스턴스의 오라클 월렛이 다운로드되어 타겟 호스트의 자체 디렉터리에 압축 해제되어 있어야 합니다.
  </Step>

  <Step>
    ## 역할 설치 [#install-role]

    ```bash
    ansible-galaxy install newrelic.newrelic_install
    ```
  </Step>

  <Step>
    ## 플레이북을 구성하십시오. [#configure]

    <CollapserGroup>
      <Collapser id="ansible-host" title="자체 호스팅 오라클 데이터베이스">
        이 역할은 단일 수집기에서 하나 이상의 오라클 데이터베이스 인스턴스(각각 SSH를 통해 연결 가능)를 모니터합니다. 단일 호스트/컨테이너/자격 증명 세트 대신, 타겟 호스트에 이미 존재해야 하며 모니터할 모든 인스턴스가 나열된 인스턴스 파일(YAML)을 읽고, 선택적으로 모니터링 사용자 비밀번호를 자동 생성하는 대신 고정하기 위한 보안 비밀 파일을 읽습니다. 정확한 파일 형식은 [CLI 설치](/docs/opentelemetry/db360/oracle/cli/#install)를 참조하십시오.

        `playbook.yml` (이)라는 이름의 파일을 생성하고 다음 내용을 그 안에 복사하십시오. `targets`을(를) `oracle-otel` (으)로 설정하고 플레이스홀더 값을 실제 값으로 바꾸십시오:

        ```yaml
        - name: Install New Relic NRDOT for Oracle Database
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - oracle-otel
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_ORACLE_SECRETS_FILE: <optional path to a secrets file pinning monitoring passwords, on the target host>
            NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
        ```

        <Callout variant="tip">
          디버그 로깅을 활성화하려면 플레이북의 `vars` 아래에 `verbosity: "debug"`을(를) 추가하십시오.
        </Callout>

      <Collapser id="ansible-adb" title="오라클 자율운영 데이터베이스(ADB)">
        이 역할은 RDS와 동일한 인스턴스 파일/시크릿 파일 패턴을 사용하여 단일 수집기에서 하나 이상의 오라클 자율운영 데이터베이스(ADB) 인스턴스를 모니터합니다(두 파일 모두 타겟 호스트에 이미 존재해야 하며, 각 인스턴스에는 해당 호스트에 다운로드하여 압축을 푼 자체 오라클 Wallet도 필요합니다). 정확한 파일 형식은 [CLI 설치](/docs/opentelemetry/db360/oracle/cli/#install)를 참조하십시오. `playbook.yml` (이)라는 이름의 파일을 생성하고 다음 내용을 복사하여 넣으십시오. `targets`을(를) `oracle-otel-adb` (으)로 설정하고 플레이스홀더 값을 자체 값으로 교체하십시오:

        ```yaml
        - name: Install New Relic NRDOT for Oracle Autonomous Database

              - oracle-otel-adb
          environment:

            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_ORACLE_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
        ```

        </Callout>
