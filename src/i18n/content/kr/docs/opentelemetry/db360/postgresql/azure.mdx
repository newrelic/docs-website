Azure Database for PostgreSQL flexible server 인스턴스용 NRDOT Collector를 사용하여 PostgreSQL 모니터링을 설정하십시오. Azure flexible server 환경에는 확장 및 서버 파라미터에 대한 특정 고려 사항이 있습니다.

<Steps>
<Step>
## 전제 조건 [#prerequisites]

설치하기 전에 다음을 갖추고 있는지 확인하십시오:

* PostgreSQL `14` 이상
* New Relic [라이센스 키](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) .
* NRDOT Collector를 설치하는 호스트와 Azure Database for PostgreSQL flexible server 인스턴스 간의 네트워크 연결.
* [뉴렐릭 OTLP 엔드포인트 문서](/docs/opentelemetry/best-practices/opentelemetry-otlp/)에 대한 네트워크 연결
* Azure flexible server 관리자 로그인 자격 증명.

지원되는 PostgreSQL 버전, 필수 권한 및 권장 서버 파라미터에 대한 자세한 내용은 [호환성 및 전제 조건](/docs/opentelemetry/db360/postgresql/compatibility)을 참조하십시오.
</Step>

<Step>
## NRDOT Collector 설정 [#setup]

PostgreSQL용 Azure 데이터베이스 flexible server 인스턴스에 연결할 수 있는 시스템에 NRDOT Collector를 설치하십시오:

<CollapserGroup>
<Collapser title="AMD64 아키텍처용" id="amd">
* Debian/Ubuntu 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
  ```

* RHEL/CentOS/OEL 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_x86_64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
  ```
</Collapser>

<Collapser title="ARM64 아키텍처용" id="arm">
* Debian/Ubuntu 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
  ```

* RHEL/CentOS/OEL 시스템의 경우 다음 명령을 실행하십시오.

  ```bash
  NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_aarch64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
  ```
</Collapser>
</CollapserGroup>
</Step>

<Step>
## 데이터베이스 사용자 및 권한 설정 [#database-user]

Azure Database for PostgreSQL flexible server 인스턴스에 필요한 권한을 가진 모니터링 사용자를 생성하십시오.

**모니터링 사용자 및 권한을 생성하려면:**

1. 관리자 로그인으로 PostgreSQL용 Azure 데이터베이스 flexible server 인스턴스에 연결하십시오:

```shell
psql --host=<YOUR_AZURE_ENDPOINT> --dbname=postgres --port=5432 --username=<YOUR_ADMIN_USERNAME>
```

2. 모니터링 사용자를 생성하십시오:

```sql
CREATE USER <YOUR_DB_USERNAME> WITH LOGIN PASSWORD '<YOUR_DB_PASSWORD>';
```

3. 필요에 따라 모니터링 사용자 역할 멤버십을 부여하십시오:

* PostgreSQL 15 이상을 사용하는 경우, 권한을 상속하도록 역할을 할당하십시오:

  ```sql
  ALTER ROLE <YOUR_DB_USERNAME> INHERIT;
  ```

  <Callout variant="tip">
  PostgreSQL 14를 사용하는 경우 모니터링 사용자가 기본적으로 권한을 상속하므로 이 단계를 건너뛸 수 있습니다.
  </Callout>

* 모니터링하려는 모든 데이터베이스에 다음 스키마와 권한을 생성합니다:

  ```sql
  CREATE SCHEMA IF NOT EXISTS otel;
  GRANT USAGE ON SCHEMA otel TO <YOUR_DB_USERNAME>;
  GRANT USAGE ON SCHEMA public TO <YOUR_DB_USERNAME>;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO <YOUR_DB_USERNAME>;
  GRANT pg_monitor TO <YOUR_DB_USERNAME>;
  CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
  ```

* (선택 사항) 벡터 메트릭을 수집하려면 각 데이터베이스에 `pgvector` 확장을 생성하십시오:

  ```sql
  CREATE EXTENSION IF NOT EXISTS vector;
  ```

  `l1`, `hamming` 및 `jaccard` 거리 함수에는 `pgvector` 버전 `0.7.0` 이상이 필요합니다.

* (선택 사항) 연결 및 권한을 확인하려면 다음을 실행하십시오:

  ```shell
  psql --username=<YOUR_DB_USERNAME> --host=<YOUR_AZURE_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> --command '\conninfo'
  psql --username=<YOUR_DB_USERNAME> --host=<YOUR_AZURE_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
    -c "SELECT * FROM pg_stat_database LIMIT 1;" && echo "pg_stat_database OK"
  psql --username=<YOUR_DB_USERNAME> --host=<YOUR_AZURE_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
    -c "SELECT * FROM pg_stat_activity LIMIT 1;" && echo "pg_stat_activity OK"
  psql --username=<YOUR_DB_USERNAME> --host=<YOUR_AZURE_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
    -c "SELECT * FROM pg_stat_statements LIMIT 1;" && echo "pg_stat_statements OK"
  ```

  각 명령이 오류 없이 완료되면 모니터링 사용자, 호스트 및 포트가 모두 올바른 것입니다.
</Step>

이 설정은 `nrpostgresql` 수신기만 사용하여 필수적인 PostgreSQL 모니터링에 중점을 둡니다.

## NRDOT Collector 설정 유효성 검사 [#validate]

1. 새 `postgresql-config.yaml` 파일을 가리키도록 설정 경로를 업데이트하십시오:

```bash
  sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/postgresql-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
```

2. NRDOT Collector 설정을 검증하여 형식이 올바르고 제대로 작동하는지 확인합니다:

```bash
  sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/postgresql-config.yaml
```
</Step>

<Step>
## NRDOT Collector를 다시 시작하십시오 [#restart-collector]

수집기를 구성한 후 NRDOT Collector 서비스를 다시 시작하여 변경 사항을 적용합니다:

```bash
sudo systemctl restart nrdot-collector
```

수집기가 제대로 실행되고 있는지 확인하려면 서비스 상태를 확인하십시오:

```bash
sudo systemctl status nrdot-collector
```

<Callout variant="tip">
새 설정이 적용되도록 설정을 변경한 후에는 항상 NRDOT Collector를 다시 시작하십시오.
</Callout>
</Step>

## 데이터 찾기 및 사용 [#find-use-data]

쿼리 샘플 및 상위 쿼리는 로그 이벤트(`event.name = 'db.server.query_sample'` / `'db.server.top_query'`, `db.system.name = 'postgresql'`)로 도착합니다. 메트릭은 `postgresql.*` 네임스페이스 아래에 도착합니다.

뉴렐릭에서 PostgreSQL용 Azure 데이터베이스 flexible server 엔티티를 찾으려면 다음을 수행하십시오:

1. <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT> 으)로 이동합니다.
2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**PostgreSQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.
3. 엔티티 목록에서 PostgreSQL용 Azure 데이터베이스 flexible server 인스턴스를 선택하십시오.
</Step>

## Azure Database for PostgreSQL flexible server 동작 [#azure-flexible]

PostgreSQL용 Azure 데이터베이스 flexible server 인스턴스를 모니터할 때, 수신기가 아닌 Azure 플랫폼 아키텍처로 인해 동작이 자체 관리형 PostgreSQL 또는 Amazon RDS와 다릅니다. 모든 표준 PostgreSQL 메트릭은 Azure에서 계속 사용할 수 있습니다.

* Azure는 서버에 `pg_stat_statements` (`postgresql.query.execution.time` 채움) 및 `pgvector` (`postgresql.vector.*` 채움) 확장을 사전 로드하지만, `CREATE EXTENSION`이(가) 성공하려면 먼저 `azure.extensions` 서버 파라미터에 이를 추가해야 합니다. 설정 단계는 [데이터베이스 사용자 및 권한 설정](#database-user)을 참조하십시오.

* 복제 메트릭(`postgresql.replication.data_delay`, `postgresql.wal.lag` 및 `postgresql.wal.delay`)은 명시적 읽기 전용 복제본 또는 Azure의 기본 제공 고가용성(HA) 대기 서버에서 수집되며, `sync_state` (`async` 또는 `sync`)으로 구분됩니다. 또한 `postgresql.wal.delay` 에는 `postgresqlreceiver.preciselagmetrics` 기능 게이트가 필요하지만, 이 페이지의 기준 설정에서는 이를 활성화하지 않습니다.

* `track_functions` 기본값은 `none` 입니다(Azure에 국한되지 않은 표준 PostgreSQL 동작). `postgresql.function.calls`을(를) 활성화하려면 `pl` 또는 `all` (으)로 설정하십시오.
