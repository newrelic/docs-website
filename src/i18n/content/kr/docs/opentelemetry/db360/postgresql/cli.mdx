뉴렐릭 CLI를 사용하여 PostgreSQL 모니터링을 위한 NRDOT Collector를 설치하고 구성할 수 있습니다. CLI는 단일 명령으로 수집기를 설치하고, 모니터링 역할 및 해당 권한을 생성하며, 수집기를 구성합니다.

<Callout variant="tip" title="가이드 설치">
  대신 뉴렐릭 UI를 통해 설치하려면 <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>(으)로 이동하십시오. 이 페이지는 수동 설치만 다룹니다.
</Callout>

<Steps>
  <Step>
    ## 전제 조건 [#prerequisites]

    * 유효한 [라이선스 키](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)가 있는 뉴렐릭 계정.
    * 뉴렐릭 [계정 ID](/docs/accounts/accounts-billing/account-structure/account-id).
    * PostgreSQL 14 이상.
    * Debian/Ubuntu 또는 RHEL/CentOS를 실행하고 `curl` 및 `systemd`이(가) 설치되어 있으며 `psql` 클라이언트를 사용할 수 있는 Linux 수집기 호스트.
    * `pg_stat_statements` `shared_preload_libraries`을(를) 통해 로드해야 합니다. 인스톨러는 이를 확인하며 그렇지 않은 경우 실패합니다. 아래의 [서버 수준 전제 조건](#server-prereqs)을 참조하십시오.
    * 자체 호스팅 PostgreSQL의 경우: PostgreSQL 서버에 대한 관리자 액세스 권한(`postgres` 슈퍼유저 또는 이에 상응하는 권한).
    * AWS RDS/Aurora PostgreSQL의 경우: 수집기 호스트에서 RDS 엔드포인트로의 네트워크 연결(RDS 보안 그룹의 PostgreSQL 포트에 대한 인바운드 액세스) 및 RDS 마스터 사용자 이름과 비밀번호.
    * 해당 리전의 [뉴렐릭 OTLP 엔드포인트](/docs/opentelemetry/best-practices/opentelemetry-otlp)에 대한 네트워크 연결.

    자세한 요구 사항은 [호환성](/docs/opentelemetry/db360/postgresql/compatibility)을 참조하십시오.
  </Step>

    * **자체 호스팅**: `postgresql.conf`에서 이를 설정한 다음 PostgreSQL을 다시 시작하십시오. 일부 배포판에서는 `pg_stat_statements`을(를) 사용하기 위해 `postgresql-contrib` 패키지를 설치해야 합니다.
    * **AWS RDS 또는 Aurora**: 구성 파일이 아닌 DB **파라미터 그룹**에서 이를 설정하십시오. `track_activity_query_size` 및 `pg_stat_statements.max`은(는) 정적 파라미터입니다: `apply_method: pending-reboot`(을)를 사용하여 적용한 다음 인스턴스를 재부팅하십시오. Aurora의 경우, 파라미터 그룹 패밀리 이름은 엔진의 메이저 버전과 정확히 일치해야 합니다(예: `aurora-postgresql16`).
  </Step>

  <Step>
    ## NRDOT Collector를 설치하고 구성하십시오 [#cli-install]

    <CollapserGroup>
      <Collapser id="cli-host" title="자체 호스팅 PostgreSQL">
        이 레시피는 단일 수집기에서 하나 이상의 PostgreSQL 인스턴스를 모니터합니다. 단일 호스트/포트/자격 증명 세트를 요청하는 대신, 사용자가 미리 생성한 두 개의 파일을 읽습니다: 모니터할 모든 인스턴스와 각 인스턴스에서 모니터할 데이터베이스를 나열하는 인스턴스 파일(YAML), 그리고 일치하도록 인덱싱된 각각의 수퍼유저 로그인 및 비밀번호가 포함된 시크릿 파일(`KEY=VALUE`)입니다.

        1. 인스턴스 파일을 생성합니다. 이 수집기가 모니터할 PostgreSQL 인스턴스당 하나의 항목을 추가합니다, 단일 인스턴스만 실행 중인 경우에도 여전히 하나의 항목입니다. 각 인스턴스에는 최소 하나의 데이터베이스가 필요합니다: PostgreSQL에는 모든 데이터베이스 모니터 모드가 없습니다:

           ```bash
           cat > ~/postgresql-instances.yml << 'EOF'
           instances:
             - host: localhost
               port: 5432
               login_name: newrelic
               databases: [app1, app2]
           EOF
           ```

        2. 인스턴스 파일의 순서와 일치하도록 인덱싱하여 각 인스턴스에 대한 슈퍼유저 역할(모든 슈퍼유저 역할이 가능하며, 반드시 `postgres`일 필요는 없습니다) 및 비밀번호로 시크릿 파일을 생성하십시오:

           ```bash
           umask 077
           cat > ~/postgresql-secrets.env << 'EOF'
           NR_CLI_POSTGRES_SUPERUSER_USER_1=postgres
           NR_CLI_POSTGRES_SUPERUSER_PASSWORD_1=YourSuperuserPassword1
           EOF
           chmod 600 ~/postgresql-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-postgresql
        ```

        <Callout variant="important">
          이 인스톨러는 암호를 사용하여 TCP를 통해 PostgreSQL에 연결하므로, 각 인스턴스의 슈퍼유저에게 암호가 설정되어 있어야 하며 `pg_hba.conf`은(는) TCP 연결에 대해 암호 기반 호스트 인증(`md5` 또는 `scram-sha-256`)을 허용해야 합니다. 새로 설치한 경우 기본적으로 `postgres`에 암호가 설정되어 있지 않습니다. 먼저 암호를 설정하십시오:

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```

          RHEL/CentOS에서 기본 `pg_hba.conf`은(는) 비밀번호 기반 호스트 인증을 전혀 허용하지 않는 경우가 많습니다. 설치를 실행하기 전에 이를 확인하고 업데이트한 다음 PostgreSQL을 다시 로드하십시오.
        </Callout>

      <Collapser id="cli-rds" title="AWS RDS/Aurora PostgreSQL">
        이 레시피는 자체 호스팅과 동일한 인스턴스 파일/시크릿 파일 패턴을 사용하여 단일 수집기에서 하나 이상의 RDS PostgreSQL 또는 Aurora 엔드포인트를 모니터합니다.

        1. RDS 또는 Aurora 엔드포인트를 `host`(으)로 사용하여 인스턴스 파일을 생성하되, 단일 인스턴스만 모니터링하는 경우 여전히 항목은 하나뿐입니다. 각 인스턴스에는 하나 이상의 데이터베이스가 필요합니다: PostgreSQL에는 모든 데이터베이스 모니터링 모드가 없습니다:

           ```bash
           cat > ~/postgresql-instances.yml << 'EOF'
           instances:
             - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
               port: 5432
               login_name: newrelic
           ```

           ```bash
           umask 077
           cat > ~/postgresql-secrets.env << 'EOF'
           NR_CLI_POSTGRES_ADMIN_USER_1=postgres
           NR_CLI_POSTGRES_ADMIN_PASSWORD_1=YourMasterPassword1

           chmod 600 ~/postgresql-secrets.env
           ```

  <Step>
    ## 데이터 찾기 및 사용 [#find]

    데이터가 수집되면 뉴렐릭 UI를 통해 포괄적인 PostgreSQL 데이터베이스 모니터링에 액세스할 수 있습니다.

    뉴렐릭에서 PostgreSQL 데이터베이스 엔티티를 찾으려면 다음을 수행하십시오:

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT> 으)로 이동합니다.
    2. **<DNT>Entity type</DNT>** 드롭다운 메뉴에서 <DNT>**PostgreSQL instance**</DNT>을(를) 선택한 다음 <DNT>**Apply**</DNT>을(를) 클릭합니다.
    3. 엔티티 목록에서 PostgreSQL 데이터베이스를 선택하십시오.

    데이터가 수신되는지 확인하려면 [쿼리 빌더](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/)에서 다음 쿼리를 실행하십시오:

    ```sql
    SELECT count(*) FROM Metric
    WHERE metricName LIKE 'postgresql.%'
    AND instrumentation.provider = 'opentelemetry'
    SINCE 10 minutes ago
    ```
