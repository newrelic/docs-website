NRDOT Collector는 다양한 PostgreSQL 메트릭을 보고합니다. 뉴렐릭은 [기본 메트릭 및 이벤트](#default)의 메트릭과 쿼리 수준 이벤트를 자동으로 수집합니다. 성능 및 상태에 대한 더 깊은 인사이트를 얻으려면 [전체 기능 메트릭](#full-feature)에 나열된 메트릭 중 하나를 활성화하십시오.

## 기본 메트릭 및 이벤트 [#default]

<Callout variant="tip">
각 메트릭은 특정 데이터베이스, 테이블, 스키마 또는 인덱스로 범위가 지정됩니다. 이 컨텍스트는 메트릭 속성이 아닌 리소스에 설정됩니다.
</Callout>

### 쿼리 이벤트 [#query-events]

다음 이벤트는 OpenTelemetry 로그 레코드로 수집되며 기본적으로 활성화됩니다. 쿼리 수준의 텔레메트리 데이터를 제공합니다.

<CollapserGroup>
<Collapser id="query-sample" title="쿼리 샘플">
현재 실행 중인 데이터베이스 명령문에 대한 실시간 가시성은 전체 실행 로그가 아니라 스크랩할 때마다 생성되는 특정 시점의 스냅샷입니다. 이 이벤트는 기본적으로 활성화되어 있으며 모니터링 사용자가 `pg_monitor`을(를) 보유해야 합니다.

동작을 조정하려면 `query_sample_collection` 블록을 사용하십시오:

```yaml
query_sample_collection:
  max_rows_per_query: 1000
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="top-query" title="상위 쿼리">
`pg_stat_statements`에서 집계된 정규화된 쿼리별 실행 통계로, 마지막 수집 주기 이후의 **증분(델타) 값**으로 보고됩니다. 이 이벤트는 기본적으로 활성화되며 스캔된 모든 데이터베이스에 `pg_stat_statements` 익스텐션이 필요합니다.

동작을 조정하려면 `top_query_collection` 블록을 사용하십시오:

```yaml
top_query_collection:
  max_rows_per_query: 1000
  top_n_query: 100
  collection_interval: 60s
  allowed_comment_keys: [nr_service_guid]
```

#### 실행 계획 수집(EXPLAIN) 메커니즘

* **속도 제한:** `top_query_collection.max_explain_each_interval` (기본값 1,000)은 스크랩당 EXPLAIN을 제한합니다.
* **캐싱:** `query_plan_cache_size` / `query_plan_cache_ttl` (기본값 1,000개 항목/1시간)은 한 번 얻은 계획을 쿼리 ID를 키로 사용하여 캐시합니다.
* **PostgreSQL 12+ 요구 사항:** 매개변수화된 쿼리 EXPLAIN은 `PREPARE`/`EXPLAIN EXECUTE` 앞에 `plan_cache_mode = force_generic_plan`이(가) 필요하며, 이는 PostgreSQL 12+에서만 사용할 수 있습니다. 구형 서버에서는 수신자가 버전을 감지하고 실패할 `SET`을(를) 보내는 대신 해당 쿼리에 대한 EXPLAIN을 건너뜁니다.
* **권한 경계:** 기본적으로 EXPLAIN은 모니터링 사용자로 직접 실행되며, Postgres는 *계획* 시점에 테이블 권한을 확인하므로, 모니터링 사용자가 절대 가져서는 안 되는 쓰기 권한이 부여되지 않는 한 행 잠금 또는 쓰기 문은 `permission denied` (으)로 실패합니다. 쓰기 권한을 부여하지 않고 이 문제를 해결하려면 `explain_function_name` ([쓰기 문에 대한 쿼리 계획](/docs/opentelemetry/db360/postgresql/optional#query) 참조)을 사용하십시오.
* 어떤 이유로든 계획을 가져올 수 없는 경우, 해당 행의 `postgresql.query_plan`은(는) 단순히 비어 있습니다. 오류가 표시되지 않습니다.
</Collapser>
