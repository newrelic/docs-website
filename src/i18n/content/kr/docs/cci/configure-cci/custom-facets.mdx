커스텀 패싯을 사용하면 정의한 규칙에 따라 cloud 비용을 그룹화하는 가상 차원을 생성할 수 있습니다. 패싯을 생성한 후에는 매번 필터를 다시 적용할 필요 없이 CCI 기능 전반에서 차원으로 사용할 수 있습니다.

사용자 지정 패싯은 <DNT>Cost Overview</DNT>에 표시되는 내장된 <DNT>Custom Dimensions</DNT> (예: 계정 이름, 팀 이름 및 환경)과 동일한 방식으로 작동하지만, cloud 계정의 태그, cloud 차원 및 조건을 결합하여 직접 정의한다는 점이 다릅니다. cloud 태그의 적용 범위에 공백이 있거나 차원 간에 조건을 결합해야 하는 경우 사용자 지정 패싯을 사용하십시오. 예를 들어, 서비스가 그룹에 속하거나, 팀 이름이 패턴과 일치하거나, 환경을 제외하는 경우의 비용을 일치시킬 수 있습니다. 사용자 지정 패싯은 세션당 적용되는 필터가 아니라 데이터 모델의 일부이므로, 이를 사용하여 예산을 편성하고, 공지 조건을 설정하고, 단위 경제성을 계산할 수 있습니다.

각 패싯은 하나 이상의 명명된 값으로 구성됩니다. 각 값에 대해 일련의 조건을 정의합니다. 시스템은 이러한 조건에 대해 각 비용 행을 평가하고 일치하는 행을 해당 값에 할당합니다. 조건과 일치하지 않는 행은 지정한 기본값을 받습니다. 예를 들어, AWS 태그, 계정 이름 및 리전과 일치하는 조건이 있는 `platform-team` 패싯은 일치하는 모든 비용 행을 `platform-team`에 할당합니다.

## 사용 사례

### 멀티 클라우드 비용 그룹화

동일한 워크로드가 AWS, Azure 및 GCP에서 실행되는 경우 세 가지 모두를 단일 패싯으로 결합할 수 있습니다. 각 제공업체의 계정, 서비스 또는 태그와 일치하는 조건을 정의하십시오. 패싯을 사용하면 각 cloud에 대한 필터를 관리하지 않고도 통합 비용을 확인하고 조치를 취할 수 있습니다.

### cloud 제공업체 전반의 트랜잭션당 비용

서비스가 여러 cloud 제공업체에 걸쳐 있는 경우, 각 제공업체의 리소스를 단일 패싯으로 그룹화하십시오. 그런 다음 <DNT>Unit economics</DNT>에서 해당 패싯을 비용 차원으로 사용하여 워크로드를 호스팅하는 cloud 제공업체에 관계없이 트랜잭션당 비용을 계산할 수 있습니다.

### 팀 또는 프로젝트를 위한 차원 예산

팀이나 프로젝트에 속한 태그 또는 계정과 일치하는 패싯을 생성하십시오. 팀별로 cloud 계정이 없어도 팀이 cloud 지출을 추적할 수 있도록 해당 패싯에 대한 예산을 생성하십시오.

## 제한

사용자 지정 패싯에는 다음 제한사항이 적용됩니다.

| 항목    | 세부사항                                                     |
| ----- | -------------------------------------------------------- |
| 최대 패싯 | 제한은 원시 태그, Kubernetes 레이블 및 사용자 지정 패싯을 모두 합쳐 연결당 90개입니다. |

## 커스텀 패싯 생성

UI를 통해 또는 YAML 파일을 업로드하여 패싯을 생성할 수 있습니다.

### UI를 사용하여 생성

사용자 지정 패싯을 생성하려면 다음 단계를 따르십시오.

1. <DNT>[one.newrelic.com](https://one.newrelic.com)</DNT> &gt; <DNT>All Capabilities</DNT> &gt; <DNT>Cloud Cost Intelligence</DNT> &gt; <DNT>Custom Facets</DNT> 으로 이동합니다.

2. <DNT>Create facet</DNT> 을(를) 클릭합니다.

3. 패싯에 대한 <DNT>Name</DNT>, <DNT>Description</DNT> 및 <DNT>Default value</DNT>을(를) 입력하십시오.

4. <DNT>+ Add facet value</DNT> 을(를) 클릭합니다.

5. 하나 이상의 조건을 추가하십시오. 각 조건은 다음을 지정합니다:

   * <DNT>Dimension</DNT> (예: 계정, cloud 공급자 및 AI 모델)
   * <DNT>Operator</DNT> (예를 들어 `in`, `not in`, `equals` 및 `regex`)
   * <DNT>Values</DNT> (하나 이상)

6. 패싯을 저장하십시오.

저장 후, 선택적으로 쿼리 편집기에서 생성된 NRQL을 실행하여 패싯 값이 올바른지 확인할 수 있습니다.

<img title="Cloud cost intelligence add facet" alt="A form for adding a custom facet with condition fields for dimension, operator, and values" src="/images/add-facet.webp" />

패싯은 일반적으로 4-8시간이 걸리는 다음 청구 내보내기 파일 처리 후 <DNT>Cost Overview</DNT> 및 기타 CCI 기능에서 차원으로 나타납니다.

### YAML을 사용하여 가져오기

한 번에 여러 패싯을 정의하거나 다른 시스템에서 규칙을 마이그레이션하려면 YAML 설정 파일을 업로드하십시오. 시작하기 전에 필요한 파일 구조를 보려면 <DNT>Download sample YAML</DNT>을(를) 클릭하고 샘플을 템플릿으로 사용하십시오.

1. <DNT>Custom Facets</DNT> 에서 <DNT>Upload YAML</DNT> 클릭합니다.
2. 설정 파일을 선택하십시오.

시스템이 파일을 검증하고 규칙을 적용합니다.

### 이력 데이터 백필

기본적으로 패싯은 패싯을 생성한 날짜부터 비용 데이터에 적용됩니다. 과거 비용 데이터에 동일한 규칙을 적용하려면 백필을 사용하십시오.

1. 패싯 규칙을 생성하거나 업로드한 후 <DNT>Backfill</DNT> 옵션을 선택하십시오.
2. 포함할 과거 날짜 범위의 시작 날짜를 지정하십시오.

시스템은 해당 기간의 일치하는 비용 행을 재처리하고 패싯 차원을 채웁니다. 백필 처리는 패싯이 활성 상태에 도달한 후 시작되며 일반적으로 8시간 이내에 완료됩니다. 진행 상황을 모니터하려면, <DNT>Custom Facets</DNT> 페이지에서 <DNT>Audit</DNT> 탭으로 이동하십시오.

## CCI 전반에서 패싯 사용

패싯을 생성한 후에는 다음 CCI 기능에서 차원으로 사용할 수 있습니다:

* <DNT>Cost Overview</DNT>: 패싯 차원별로 비용 필터링 및 그룹화
* <DNT>Budgets</DNT>: 패싯 값으로 범위가 지정된 예산 생성
* <DNT>Query your data and Alert conditions</DNT>: 패싯 그룹의 지출에 의해 트리거되는 알림 설정
* <DNT>Unit economics</DNT>: 단위당 비용 계산을 위한 분모 또는 분자 차원으로 패싯을 사용합니다.
* <DNT>Recommendations</DNT>: 패싯 그룹으로 범위가 지정된 최적화 권장 사항 가져오기
