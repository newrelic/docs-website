## 개요

Control은 업데이트를 포함하여 전체 제품 수명 주기를 원활하고 중앙 집중식으로 관리할 수 있는 방법을 제공합니다. 각 호스트 또는 클러스터의 에이전트를 수동으로 업데이트하는 대신 플릿 컨트롤에서 원하는 상태를 정의하면 Agent Control이 나머지를 자동으로 처리합니다.

에이전트 컨트롤은 플릿 컨트롤 배포의 일부로 자체 업그레이드할 수 있으므로 별도의 업그레이드 캠페인 없이 최신 상태를 유지합니다. 플릿 설정에서 버전을 변경하여 관리하는 에이전트를 업데이트합니다.

### 뉴렐릭 컨트롤을 이용한 업데이트 프로세스의 주요 이점

* 중앙 집중식 제어: 단일 위치에서 전체 플릿의 모든 에이전트 버전을 관리하십시오.
* 자동화: 새 버전을 정의하면 배포 및 조정 프로세스가 자동으로 처리됩니다.
* 보호된 설치: 호스트에서 에이전트 컨트롤은 실행 중인 버전을 교체하기 전에 새 버전을 확인합니다. Kubernetes에서는 롤링 업데이트를 통해 새 파드가 정상 상태가 될 때까지 이전 파드를 계속 실행합니다. [에이전트 컨트롤 업그레이드가 실패하는 경우](#upgrade-failure)를 참조하십시오.

<Callout variant="important">
  새 버전이 실행되면 에이전트 컨트롤은 업그레이드를 자동으로 롤백하지 않습니다. 보호되는 항목과 보호되지 않는 항목을 알아보려면 [에이전트 컨트롤 업그레이드 실패 시](#upgrade-failure)를 참조하십시오.
</Callout>

## 관리형 에이전트 업데이트

플릿셀 내의 원격 설정에서 해당 버전을 변경하기만 하면 Agent Control에서 관리하는 모든 에이전트를 업데이트할 수 있습니다. 이러한 선언적 접근 방식은 전체 차량 관리 시스템에서 일관성과 신뢰성을 보장합니다.

* **설정 편집:** 플릿 위험에서 귀하의 차량에 대한 설정으로 이동합니다.
* **버전 업데이트:** 업데이트할 에이전트(예: `infrastructure`)를 찾고 `chart_version` 값을 새 버전 번호로 변경합니다.
* **구현하다, 배포하다 변경 사항:** 저장 및 구현하다, 업데이트된 설정을 배포합니다.

Control은 변경 사항을 자동으로 감지하고 중단 없는 롤링 업데이트를 수행하여 새가 이전를 교체하기 전에 실행 중이고 정상인지 확인합니다.

### 예: 뉴렐릭 인프라 에이전트 업그레이드

이 예시는 인프라 에이전트를 새 버전으로 업그레이드하는 방법을 보여줍니다.

```yaml
# Remote configuration for a single agent
chart_version: "5.0.109"  # Change this value
chart_values:
  newrelic-infrastructure:
    enableProcessMetrics: true
```

## 플릿 컨트롤을 통한 에이전트 컨트롤 업그레이드 방법 [#ac-auto-upgrade]

플릿 컨트롤에서 배포를 푸시하면 플릿 컨트롤은 해당 플릿의 관리되는 엔티티에 사용할 수 있는 최신 버전의 에이전트 컨트롤이 있는지 확인합니다. 있는 경우 업그레이드가 배포에 포함됩니다.

1. 에이전트 컨트롤 팀은 [릴리스 채널](#release-channels)에 새 버전을 릴리스합니다.
2. 플릿 컨트롤에서 배포를 푸시합니다. 에이전트 컨트롤 업그레이드가 여기에 포함됩니다.
3. 에이전트 컨트롤은 자체적으로 업그레이드되며, 관리되는 에이전트는 요청한 설정 변경 사항만 수신합니다.

에이전트 컨트롤은 배포 간이 아니라 배포의 일부로 업그레이드됩니다. 이 프로세스의 배포 측면에 대해서는 플릿 컨트롤 문서의 [자동 에이전트 컨트롤 업그레이드](/docs/new-relic-control/fleet-control/manage-fleets#automatic-agent-control-upgrades)를 참조하십시오.

<Callout variant="important">
  일반 공급 이전의 제한적 또는 공개 프리뷰 기간에 에이전트 컨트롤을 설치한 경우, 해당 버전은 플릿 컨트롤을 통한 업그레이드를 지원하지 않을 수 있습니다. 이 경우 안내 설치를 다시 실행하는 등의 방법으로 에이전트 컨트롤을 최신 버전으로 한 번 수동 업그레이드하십시오. 그 이후에는 플릿 컨트롤이 향후 업그레이드를 배포에 포함할 수 있습니다.
</Callout>

호스트에서 업그레이드하면 에이전트 컨트롤이 다시 시작됩니다. 관리하는 에이전트를 먼저 중지하고 새 버전이 실행된 후 다시 시작하므로 해당 에이전트의 데이터에 짧은 공백이 발생할 수 있습니다. Kubernetes에서 Flux는 롤링 업데이트를 통해 에이전트 컨트롤 파드를 교체하며 관리되는 에이전트는 계속 실행됩니다.

### 릴리스 채널 [#release-channels]

릴리스 채널은 구독하는 에이전트 컨트롤 릴리스의 트랙입니다. 각 채널에는 릴리스가 제공된 기간 및 검증된 정도와 같은 요소를 기반으로 새 버전이 도착하는 시기에 대한 자체 정책이 있습니다.

플릿 컨트롤은 **Rapid**라는 하나의 채널을 제공합니다. 이 채널에는 프로덕션 준비가 완료된 최신 에이전트 컨트롤 릴리스가 포함되어 있습니다. 새 버전은 플릿 컨트롤의 다음 배포와 함께 도착하며, 이는 Kubernetes의 에이전트 컨트롤에 대한 업그레이드 작동 방식이기도 합니다. 다른 채널을 선택하거나 플릿 컨트롤이 업그레이드할 버전을 선택할 수 없습니다.

## 에이전트 제어 업그레이드

모든 플랫폼에서 플릿 컨트롤을 통해 에이전트 컨트롤을 업그레이드하십시오. 업그레이드는 [플릿 컨트롤을 사용한 에이전트 컨트롤 업그레이드 방법](#ac-auto-upgrade)에 설명된 대로 배포의 일부입니다.

### Kubernetes

다음 지침은 쿠버네티스 클러스터에서 실행되는 에이전트 제어에 적용됩니다.

플릿 컨트롤은 [플릿 컨트롤을 사용하여 에이전트 컨트롤을 업그레이드하는 방법](#ac-auto-upgrade)에 설명된 대로 배포에 에이전트 컨트롤 업그레이드를 포함합니다. 최신 버전을 사용할 수 있는 경우, 배포 페이지에 에이전트 컨트롤이 업데이트된다는 알림이 표시됩니다. 설정에서 에이전트 컨트롤 버전을 변경할 필요가 없습니다. 이를 통해 클러스터에서 실행 중인 에이전트 컨트롤을 최신 기능, 수정 사항 및 보안 패치로 최신 상태로 유지합니다.

업그레이드는 클러스터의 에이전트 컨트롤 파드에 대한 롤링 업데이트를 트리거합니다. Kubernetes의 내장된 상태 확인은 중단 없는 업그레이드를 위해 이전 버전이 종료되기 전에 새 버전이 정상인지 확인합니다.

### Linux 및 Windows 호스트

Linux 및 Windows 호스트에서 플릿 컨트롤은 배포에 에이전트 컨트롤 업그레이드도 포함합니다. 플릿 설정에서 에이전트 컨트롤 버전을 변경할 필요가 없습니다.

<Callout variant="caution">
  플릿 컨트롤은 호스트에서 에이전트 컨트롤을 업그레이드하는 방법입니다. 패키지 매니저(`apt-get`, `zypper` 또는 `yum`)를 사용하거나 설치 스크립트를 다시 실행하여 업그레이드하는 것은 권장하지 않습니다.
</Callout>

관리되는 에이전트(인프라 에이전트, NRDOT)는 Kubernetes에서와 동일한 방식으로 업그레이드됩니다. 플릿 설정에서 원하는 에이전트 버전을 업데이트하고 변경 사항을 배포하십시오.

### 에이전트 컨트롤 업그레이드가 실패하는 경우 [#upgrade-failure]

에이전트 컨트롤이 실패한 업그레이드를 관리하는 방법은 플랫폼에 따라 다릅니다:

* **Linux 및 Windows 호스트:** 에이전트 컨트롤은 자체적으로 교체되기 전에 새 버전을 한 번 실행하여 시작하고, 설정을 로드하고, 플릿 컨트롤에 연결할 수 있는지 확인합니다. 해당 확인이 실패하거나 다운로드 또는 서명 확인이 실패하면 현재 버전이 계속 실행되고 배포가 **FAILED**로 표시됩니다. 원하는 다른 버전을 배포하면 즉시 새로운 시도가 시작됩니다. 서명 확인에 실패한 패키지와 같이 원인이 영구적인 경우, 원인을 수정하거나 다른 버전을 배포할 때까지 업그레이드가 계속 실패하고 배포는 **FAILED** 상태로 유지됩니다. 이 확인은 교체 전에 실행되므로, 확인을 통과한 후 나중에 손상되는 버전은 포착할 수 없습니다.
* **Kubernetes:** 롤링 업데이트는 새로운 파드가 준비될 때까지 이전 에이전트 컨트롤 파드를 계속 실행합니다.

새 버전이 실행되면 에이전트 컨트롤은 자체적으로 이전 버전으로 롤백하지 않습니다. 잘못된 버전에서 복구하려면 플릿 컨트롤이 다음 배포에 포함하는 수정된 버전으로 이동하십시오. 실패한 항목을 확인하려면 플릿 컨트롤에서 배포 세부 정보를 확인하십시오. [자동 에이전트 컨트롤 업그레이드](/docs/new-relic-control/fleet-control/manage-fleets#automatic-agent-control-upgrades)도 참조하십시오.

### 에이전트 제어 시작, 중지 및 재시작 [#start-stop-restart]

에이전트 제어는 설치파일을 실행한 후 자동으로 시작됩니다.

#### Linux

리눅스 시스템의 경우, 사용 중인 init 시스템에 맞는 올바른 명령어를 사용해야 합니다. 적절한 것을 선택하세요: `start`, `stop`, `restart`, 또는 `status`.

`systemd` 의 예시는 다음과 같습니다.

```shell
sudo systemctl <start|stop|restart|status> newrelic-agent-control
```

#### 윈도우

관리자 권한으로 PowerShell에서 다음 명령을 실행하세요.

```powershell
Start-Service -Name newrelic-agent-control
Stop-Service -Name newrelic-agent-control
Restart-Service -Name newrelic-agent-control
Get-Service -Name newrelic-agent-control
```
