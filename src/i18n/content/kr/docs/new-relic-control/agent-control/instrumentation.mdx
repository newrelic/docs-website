## 클린 시스템을 계측합니다.

<Callout variant="tip">
  에이전트 컨트롤은 수퍼바이저 서비스이며, 자체적으로 텔레메트리를 수집하거나 전송하지 않습니다. 뉴렐릭에서 데이터를 보려면 에이전트 컨트롤을 설치한 후 플릿 컨트롤을 통해 에이전트(예: 인프라 에이전트 또는 NRDOT)를 배포해야 합니다.
</Callout>

### Kubernetes

1. 플릿 컨트롤에서 **쿠버네티스 클러스터** 유형의 **플릿을 생성하십시오**. 자세한 단계는 [첫 번째 플릿 생성](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet)을 참조하십시오.

2. **에이전트 컨트롤을 설치합니다.** [Kubernetes 설치 가이드](/docs/new-relic-control/agent-control/setup/)를 따라 1단계에서 생성한 플릿을 선택합니다.

3. **플릿 컨트롤에서 각 에이전트에 대한 설정을 생성하십시오.** 에이전트 컨트롤이 플릿 컨트롤에 연결된 후 각 에이전트에 대한 [설정을 생성하십시오](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration). 플릿 컨트롤은 모든 에이전트 설정에 대한 권한이 있는 소스이므로, 로컬 `values.yaml`에 에이전트별 값을 추가하지 마십시오.

사용자 지정 설정으로 인프라 에이전트, Fluent Bit, Prometheus 및 NRDOT를 추가하는 예시이며, 이러한 각 설정은 플릿 컨트롤에서 별도의 원격 설정으로 생성되어야 합니다:

<CollapserGroup>
  <Collapser id="k8s-clean-infra" title="인프라 에이전트">
    사용자 지정 톨러레이션 및 30초 수집 간격으로 뉴렐릭 인프라 에이전트를 활성화합니다.

    ```yaml
    chart_values:
      newrelic-infrastructure:
        kubelet:
          tolerations:
            - operator: "Exists"
              effect: "NoSchedule"
            - operator: "Exists"
              effect: "NoExecute"
        common:
          config:
            interval: 30s
    ```
  </Collapser>

  <Collapser id="k8s-clean-logs" title="Fluent Bit(로그 포워딩)">
    제한된 CPU 리소스로 Fluent Bit 로그 전달자를 배포합니다.

    ```yaml
    chart_values:
      newrelic-logging:
        resources:
          limits:
            cpu: 200m
          requests:
            cpu: 200m
    ```
  </Collapser>

  <Collapser id="k8s-clean-prometheus" title="Prometheus">
    텔레메트리 볼륨을 줄이기 위해 로우 데이터 모드로 Prometheus 에이전트를 배포합니다.

    ```yaml
    chart_values:
      newrelic-prometheus-agent:
        lowDataMode: true
        config:
          kubernetes:
            integrations_filter:
              enabled: false
    ```
  </Collapser>

  <Collapser id="k8s-clean-nrdot" title="NRDOT(OpenTelemetry 수집기)">
    OpenTelemetry 수집기의 뉴렐릭 배포판을 배포합니다. 여기서는 `filelog` 수신기가 비활성화되어 있습니다 ― 로그 수집을 원하면 활성화하십시오.

    ```yaml
    chart_values:
      nr-k8s-otel-collector:
        receivers:
          filelog:
            enabled: false
    ```
  </Collapser>
</CollapserGroup>

4. 방금 생성한 원격 설정을 플릿에 추가하여 **새 배포를 생성하십시오**. 에이전트 컨트롤이 새 설정을 클러스터에 자동으로 적용합니다. [첫 번째 배포 생성 및 실행](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment)의 단계를 따르십시오.

5. **데이터가 흐르고 있는지 확인하십시오.** 뉴렐릭 UI에서 **Infrastructure &gt; Kubernetes**로 이동하십시오. 원격 설정이 적용된 후 1～2분 이내에 클러스터가 나타나야 합니다. 나타나지 않으면 [Agent Control 문제 진단, 해결](/docs/new-relic-control/agent-control/troubleshooting)을 참조하십시오.

### Linux

1. 플릿 컨트롤에서 **Linux Host** 유형의 **플릿을 생성합니다**. 자세한 단계는 [첫 번째 플릿 생성](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet)을 참조하십시오.

2. **에이전트 컨트롤을 설치합니다.** [Linux 설치 가이드](/docs/new-relic-control/agent-control/setup/)를 따르고 1단계에서 생성한 플릿을 선택하십시오.

3. **플릿 컨트롤에서 각 에이전트에 대한 설정을 생성하십시오.** 에이전트 컨트롤이 플릿 컨트롤에 연결된 후, 각 에이전트에 대한 [설정을 생성하십시오](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration).

인프라 에이전트, nri-MySQL, nri-flex, fluentbit 및 nrdot를 추가하는 예시로, 이러한 각 설정은 플릿 컨트롤에서 별도의 원격 설정으로 생성해야 합니다:

<CollapserGroup>
  <Collapser id="linux-clean-infra" title="인프라 에이전트(기준)">
    `config_agent` 최소 필수 설정이 포함되어 있습니다. `license_key`은(는) `nr-env` 값 공급자를 사용하여 `NEW_RELIC_LICENSE_KEY` 환경 변수에서 런타임에 해석되며, `custom_attributes`은(는) 선택 사항이지만 필터링을 위해 권장됩니다. `config_logging`은(는) 시스템 syslog를 뉴렐릭 Logs로 전달합니다.

    ```yaml
    config_agent:
      license_key: '${nr-env:NEW_RELIC_LICENSE_KEY}'
      custom_attributes:
        env: production
    config_logging:
      logging.yml:
        logs:
          - name: syslog
            file: /var/log/syslog
            attributes:
              logtype: linux_syslog
    ```
  </Collapser>

  <Collapser id="linux-clean-mysql" title="nri-mysql(온-호스트 통합)">
    localhost에서 실행 중인 MySQL 인스턴스를 모니터링합니다. 비밀번호는 `nr-env` 값 제공자를 사용하여 `MYSQL_PASSWORD` 환경 변수에서 런타임에 확인됩니다 — 자격 증명을 절대 하드코딩하지 마십시오.

    ```yaml
    config:
      integrations:
        - name: nri-mysql
          env:
            HOSTNAME: localhost
            PORT: 3306
            USERNAME: newrelic
            PASSWORD: ${nr-env:MYSQL_PASSWORD}
            REMOTE_MONITORING: true
          interval: 30s
    ```
  </Collapser>

  <Collapser id="linux-clean-flex" title="셸 명령을 사용하는 nri-flex(온-호스트 통합)">
    `df`을(를) 사용하여 루트 파일 시스템에서 디스크 사용량 통계를 수집합니다. 이 예시는 셸 명령을 실행하고 그 출력을 뉴렐릭 이벤트로 구문 분석하는 방법을 보여줍니다.

    ```yaml
    config:
      integrations:
        - name: nri-flex
          config:
            name: diskUsage
            apis:
              - event_type: DiskUsageSample
                commands:
                  - run: df -kP /
                    split: horizontal
                    split_by: \s+
                    set_header: [filesystem, blocks, used, available, usePercent, mountpoint]
                    row_start: 1
    ```
  </Collapser>

  <Collapser id="linux-clean-nrdot" title="NRDOT(OpenTelemetry 수집기)">
    호스트 메트릭 및 시스템 로그를 수집하고, APM 서비스를 위한 OTLP 수신기를 엽니다. 라이선스 키와 OTLP 엔드포인트는 에이전트 컨트롤에 의해 자동으로 주입됩니다.

    ```yaml
    config:
      # Variables set automatically by Agent Control:
      # - NEW_RELIC_LICENSE_KEY: New Relic ingest license key.
      # - OTEL_EXPORTER_OTLP_ENDPOINT: OTLP endpoint (see: https://docs.newrelic.com/docs/opentelemetry/best-practices/opentelemetry-otlp/).

      extensions:
        health_check:

      receivers:
        otlp:
          protocols:
            grpc:
            http:

        hostmetrics:
          collection_interval: 60s
          scrapers:
            cpu:
              metrics:
                system.cpu.time:
                  enabled: false
                system.cpu.utilization:
                  enabled: true
            load:
            memory:
              metrics:
                system.memory.utilization:
                  enabled: true
            paging:
              metrics:
                system.paging.utilization:
                  enabled: false
                system.paging.faults:
                  enabled: false
            filesystem:
              metrics:
                system.filesystem.utilization:
                  enabled: true
            disk:
              metrics:
                system.disk.merged:
                  enabled: false
                system.disk.pending_operations:
                  enabled: false
                system.disk.weighted_io_time:
                  enabled: false
            network:
              metrics:
                system.network.connections:
                  enabled: false
            # Uncomment to enable process metrics, which can be noisy but valuable.
            # processes:
            # process:
            #  metrics:
            #    process.cpu.utilization:
            #      enabled: true
            #    process.cpu.time:
            #      enabled: false

        filelog:
          include:
            - /var/log/alternatives.log
            - /var/log/cloud-init.log
            - /var/log/auth.log
            - /var/log/dpkg.log
            - /var/log/syslog
            - /var/log/messages
            - /var/log/secure
            - /var/log/yum.log

      processors:
        metricstransform:
          transforms:
            - include: system.cpu.utilization
              action: update
              operations:
                - action: aggregate_labels
                  label_set: [state]
                  aggregation_type: mean
            - include: system.paging.operations
              action: update
              operations:
                - action: aggregate_labels
                  label_set: [direction]
                  aggregation_type: sum
        filter/exclude_cpu_utilization:
          metrics:
            datapoint:
              - 'metric.name == "system.cpu.utilization" and attributes["state"] == "interrupt"'
              - 'metric.name == "system.cpu.utilization" and attributes["state"] == "nice"'
              - 'metric.name == "system.cpu.utilization" and attributes["state"] == "softirq"'
        filter/exclude_memory_utilization:
          metrics:
            datapoint:
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "slab_unreclaimable"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "inactive"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "cached"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "buffered"'
              - 'metric.name == "system.memory.utilization" and attributes["state"] == "slab_reclaimable"'
        filter/exclude_memory_usage:
          metrics:
            datapoint:
              - 'metric.name == "system.memory.usage" and attributes["state"] == "slab_unreclaimable"'
              - 'metric.name == "system.memory.usage" and attributes["state"] == "inactive"'
        filter/exclude_filesystem_utilization:
          metrics:
            datapoint:
              - 'metric.name == "system.filesystem.utilization" and attributes["type"] == "squashfs"'
        filter/exclude_filesystem_usage:
          metrics:
            datapoint:
              - 'metric.name == "system.filesystem.usage" and attributes["type"] == "squashfs"'
              - 'metric.name == "system.filesystem.usage" and attributes["state"] == "reserved"'
        filter/exclude_filesystem_inodes_usage:
          metrics:
            datapoint:
              - 'metric.name == "system.filesystem.inodes.usage" and attributes["type"] == "squashfs"'
              - 'metric.name == "system.filesystem.inodes.usage" and attributes["state"] == "reserved"'
        filter/exclude_system_disk:
          metrics:
            datapoint:
              - 'metric.name == "system.disk.operations" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.merged" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.io" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.io_time" and IsMatch(attributes["device"], "^loop.*") == true'
              - 'metric.name == "system.disk.operation_time" and IsMatch(attributes["device"], "^loop.*") == true'
        filter/exclude_system_paging:
          metrics:
            datapoint:
              - 'metric.name == "system.paging.usage" and attributes["state"] == "cached"'
              - 'metric.name == "system.paging.operations" and attributes["type"] == "cached"'
        filter/exclude_network:
          metrics:
            datapoint:
              - 'IsMatch(metric.name, "^system.network.*") == true and attributes["device"] == "lo"'
        attributes/exclude_system_paging:

                - truncate_all(attributes, 4095)
                - truncate_all(resource.attributes, 4095)
          log_statements:
            - context: log
              statements:
                - truncate_all(attributes, 4095)
                - truncate_all(resource.attributes, 4095)
        memory_limiter:
          check_interval: 1s
          limit_mib: 100
        batch:
        resourcedetection:

            hostname_sources: ["os"]
            resource_attributes:
              host.id:
                enabled: true
        resourcedetection/cloud:
          detectors: ["gcp", "ec2", "azure"]
          timeout: 2s
          ec2:
            resource_attributes:
              host.name:
                enabled: false
        resourcedetection/env:
          detectors: ["env"]
          timeout: 2s
          override: true

      exporters:

              - filter/exclude_filesystem_inodes_usage

              - cumulativetodelta
              - batch

          logs/host:

            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]

            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]

            receivers: [otlp]
            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]
            exporters: [otlphttp]
          logs:
            receivers: [otlp]
            processors: [memory_limiter, transform, resourcedetection, resourcedetection/cloud, resourcedetection/env, batch]
            exporters: [otlphttp]
        extensions: [health_check]
    ```
  </Collapser>
</CollapserGroup>

4. 방금 생성한 원격 설정을 플릿에 추가하여 **새 배포를 생성하십시오**. 에이전트 컨트롤이 새 설정을 호스트에 자동으로 적용하고, 각 에이전트에 대한 OCI 패키지를 다운로드하여 설치합니다. [첫 번째 배포 생성 및 실행](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment)의 단계를 따르십시오.

5. **데이터가 흐르고 있는지 확인합니다.** 뉴렐릭 UI에서 **Infrastructure &gt; Hosts**로 이동하십시오. 1～2분 내에 호스트가 표시됩니다. 표시되지 않는 경우 [Agent Control 문제 진단, 해결](/docs/new-relic-control/agent-control/troubleshooting)을 참조하십시오.

### 윈도우

1. 플릿 컨트롤에서 **Windows 호스트** 유형의 **플릿을 생성하십시오**. 자세한 단계는 [첫 번째 플릿 생성](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet)을 참조하십시오.

2. **에이전트 컨트롤을 설치합니다.** [Windows 설치 가이드](/docs/new-relic-control/agent-control/setup/)를 따르고 1단계에서 생성한 플릿을 선택하십시오.

3. **플릿 컨트롤에서 각 에이전트에 대한 설정을 생성하십시오.** 에이전트 컨트롤이 플릿 컨트롤에 연결된 후, 각 에이전트에 대한 [설정을 생성하십시오](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration).

인프라 에이전트, nri-MySQL, nri-flex, fluentbit 및 nrdot를 추가하는 예시로, 이러한 각 설정은 플릿 컨트롤에서 별도의 원격 설정으로 생성해야 합니다:

<CollapserGroup>
  <Collapser id="win-clean-infra" title="인프라 에이전트(기준)">
    `config_agent` 최소 필수 설정을 포함합니다. `license_key`은(는) `nr-env` 값 제공자를 사용하여 `NEW_RELIC_LICENSE_KEY` 환경 변수에서 런타임에 해석되며, `custom_attributes`은(는) 선택 사항이지만 필터링을 위해 권장됩니다. `config_logging`은(는) Windows 이벤트 로그를 뉴렐릭 Logs에 전달합니다.

    ```yaml

        env: production
    config_logging:
      windows-event-log.yml:
    ```

  <Collapser id="win-clean-flex" title="PowerShell 명령을 사용하는 nri-flex(온-호스트 통합)">
    PowerShell을 통해 `Get-CimInstance`을(를) 사용하여 논리 디스크 성능 메트릭을 수집합니다. 이 예제는 nri-flex가 PowerShell 명령을 실행하고 해당 JSON 출력을 뉴렐릭 이벤트로 구문 분석하는 방법을 보여줍니다. PowerShell v3+가 필요합니다.

    ```yaml
    config:
      integrations:
        - name: nri-flex
          config:
            name: winDiskPerf
            apis:
              - event_type: WinDiskPerfSample
                shell: powershell
                commands:
                  - run: >
    ```

## 이전에 계측된 시스템 마이그레이션

<Callout variant="important">
  Agent Control은 기존 에이전트의 자동 마이그레이션을 지원하지 않습니다. 마이그레이션은 항상 수동 프로세스입니다: 기존 에이전트를 제거하고 Agent Control을 설치한 다음, 설정을 플릿 컨트롤 원격 설정으로 다시 만드십시오.
</Callout>

### 일반 마이그레이션 프로세스

플랫폼에 관계없이 마이그레이션은 다음 네 단계를 따릅니다:

1. **기존 설정을 기록해 두십시오.** 제거하기 전에 모든 에이전트 설정 파일 및 통합 설정의 사본을 저장하십시오. 플릿 컨트롤 원격 설정으로 다시 생성하게 됩니다.
2. **기존 에이전트를 제거합니다.** 에이전트 컨트롤은 동일한 유형의 독립 실행형 에이전트 설치와 공존할 수 없습니다.
3. **에이전트 컨트롤을 설치하고 플릿에 연결하십시오.** 플랫폼별 설치 가이드를 따르고 기존 플릿을 선택하거나 새 플릿을 생성하십시오.
4. **플릿 컨트롤에서 설정을 다시 생성하십시오.** 이전 설정으로 플릿에 대한 원격 설정을 생성하십시오. 에이전트 컨트롤이 이를 자동으로 적용합니다.

<Callout variant="important" title="원격 설정이 항상 승리합니다">
  플릿 컨트롤은 에이전트 설정에 대한 신뢰할 수 있는 소스입니다. 모든 에이전트 설정, 버전, 차트 값 및 리소스 제한은 로컬 설치 파일이 아닌 플릿 컨트롤 원격 설정에 정의되어야 합니다. 두 가지가 모두 존재하는 경우, 원격 설정이 우선하며 모든 로컬 값을 재정의합니다.
</Callout>

<Callout variant="tip" title="모범 사례">
  데이터 연속성을 보장하려면 에이전트 컨트롤 설치 중에 동일한 엔티티 이름(클러스터 이름 또는 호스트명)과 동일한 뉴렐릭 계정을 사용하십시오. 에이전트 컨트롤에서 아직 지원하지 않는 에이전트나 구성 요소는 지원될 때까지 그대로 둘 수 있습니다.
</Callout>

### Kubernetes

쿠버네티스 클러스터가 이미 뉴렐릭으로 계측된 경우, 에이전트가 Agent Control에서 관리되도록 전환할 수 있습니다. 마이그레이션 프로세스는 기존 에이전트 설치를 제거하고 플릿 컨트롤을 통해 중앙에서 설정된 Agent Control 관리 설치로 교체합니다.

에이전트 컨트롤은 `nri-bundle` Helm 차트에서 다음 에이전트를 배포하고 관리할 수 있습니다:

* `newrelic-infrastructure`, `nri-kube-events` 및 `kube-state-metrics`: **인프라 에이전트** 유형으로 관리됨
* `newrelic-prometheus-configurator`: **Prometheus** 에이전트 유형으로 관리됩니다
* `newrelic-logging`: **Fluent Bit** 에이전트 유형으로 관리됩니다
* `nr-k8s-otel-collector`: **OpenTelemetry Collector** 에이전트 유형으로 관리됩니다

1. **기존 설정을 가져오십시오.** Helm을 사용하여 에이전트를 설치한 경우, 클러스터에서 설치 설정을 가져오십시오:

```sh
# Find releases in the namespace
helm list --namespace <namespace-name>

# Get the values for a specific release
helm get values <release-name> --namespace <namespace-name>
```

설치 시 저장한 원본 설정 파일이 있는 경우, 이를 직접 사용하십시오. Kubernetes 매니페스트(kubectl 또는 Kustomize)를 통해 클러스터가 계측된 경우, 각 에이전트에 설정된 옵션을 기록해 두십시오 ― 플릿 컨트롤 원격 설정으로 다시 만들어야 합니다.

2. **이전 에이전트를 제거합니다.** Agent Control을 설치하기 전에 클러스터에서 이전 에이전트를 제거하십시오. Helm 설치의 경우:

```shell
helm uninstall <release-name> -n <namespace>
```

예를 들어, `nri-bundle` 을 제거하려면 다음과 같이 하세요.

```shell
helm uninstall nri-bundle -n newrelic
```

3. **에이전트 컨트롤을 설치합니다.** [에이전트 컨트롤 가이드 설치](/docs/new-relic-control/agent-control/setup/)를 시작하고 생성된 `values.yaml`을(를) 다운로드하십시오. 이 파일에는 에이전트 컨트롤 감독자 설정(자격 증명, 플릿 ID 및 관리할 에이전트 유형)만 포함되어 있습니다 — **여기에 에이전트별 차트 값을 추가하지 마십시오**. 해당 값은 플릿 컨트롤 원격 설정에 속합니다.

```shell
helm upgrade --install agent-control-bootstrap -n newrelic newrelic/agent-control-bootstrap --create-namespace --values my_values.yaml
```

4. **플릿 컨트롤에서 에이전트 설정을 다시 생성하십시오.** 에이전트 컨트롤이 플릿 컨트롤에 연결된 후, 이전 설정을 사용하여 기존의 각 에이전트에 대한 [설정을 생성하십시오](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration).

5. 방금 생성한 원격 설정을 플릿에 추가하여 **새 배포를 생성하십시오**. 에이전트 컨트롤이 새 설정을 클러스터에 자동으로 적용합니다. [첫 번째 배포 생성 및 실행](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment)의 단계를 따르십시오.

6. **데이터가 흐르고 있는지 확인하십시오.** 뉴렐릭 UI에서 **Infrastructure &gt; Kubernetes**로 이동하십시오. 원격 설정이 적용된 후 1～2분 이내에 클러스터가 나타나야 합니다. 나타나지 않으면 [Agent Control 문제 진단, 해결](/docs/new-relic-control/agent-control/troubleshooting)을 참조하십시오.

### 윈도우

<Callout variant="important">
  에이전트 컨트롤은 Windows에서 기존 에이전트의 자동 마이그레이션을 지원하지 않습니다. Windows 호스트에 뉴렐릭 인프라 에이전트가 이미 설치되어 있는 경우, 에이전트 컨트롤을 설치하기 전에 수동으로 제거해야 합니다. APM 에이전트는 Agent Control에서 관리하지 않으므로 설치된 상태로 유지할 수 있습니다.
</Callout>

1. **기존 설정 기록**

제거하기 전에 다음의 사본을 저장하십시오:

* 에이전트 설정: `C:\Program Files\New Relic\newrelic-infra\newrelic-infra.yml`
* 모든 온호스트 통합 설정: `C:\Program Files\New Relic\newrelic-infra\integrations.d\`

4단계에서 이를 플릿 컨트롤 원격 설정으로 다시 생성합니다.

2. **기존 인프라 에이전트 제거**

**Add or Remove Programs** \[프로그램 추가/제거]를 열고 뉴렐릭 인프라 에이전트를 제거하십시오. 또는 PowerShell에서 MSI 제거 프로그램을 사용하십시오:

```powershell
# Replace {PRODUCT_CODE} with the GUID from Add/Remove Programs
msiexec /x {PRODUCT_CODE} /quiet
```

3. **에이전트 컨트롤을 설치하십시오.** [Windows 설치 가이드](/docs/new-relic-control/agent-control/setup/)를 따르십시오. **Host - Windows** 유형의 플릿을 선택하거나 생성하십시오.

4. **플릿 컨트롤에서 에이전트 설정을 다시 생성하십시오.** 에이전트 컨트롤이 플릿 컨트롤에 연결된 후, 이전 설정을 사용하여 기존의 각 에이전트에 대한 [설정을 생성하십시오](/docs/new-relic-control/fleet-control/setup/#step-3-create-an-agent-configuration). 1단계에서 저장한 설정 파일을 참조하십시오.

5. 방금 생성한 원격 설정을 플릿에 추가하여 **새 배포를 생성하십시오**. 에이전트 컨트롤이 새 설정을 호스트에 자동으로 적용하고, 각 에이전트에 대한 OCI 패키지를 다운로드하여 설치합니다. [첫 번째 배포 생성 및 실행](/docs/new-relic-control/fleet-control/setup/#step-4-create-and-run-your-first-deployment)의 단계를 따르십시오.

6. **데이터가 흐르고 있는지 확인합니다.** 뉴렐릭 UI에서 **Infrastructure &gt; Hosts**로 이동하십시오. 1～2분 내에 호스트가 표시됩니다. 표시되지 않는 경우 [Agent Control 문제 진단, 해결](/docs/new-relic-control/agent-control/troubleshooting)을 참조하십시오.

사용자 정의 대시보드 및 알림 에이전트의 데이터 참조는 동일한 계정 및 호스트 이름을 사용하는 한 계속 작동합니다.
