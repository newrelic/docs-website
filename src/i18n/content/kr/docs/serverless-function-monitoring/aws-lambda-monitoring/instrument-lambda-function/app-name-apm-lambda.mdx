`NEW_RELIC_APP_NAME` 은(는) 뉴렐릭에서 함수의 텔레메트리가 어떤 APM 엔티티에 속성으로 할당되는지 제어하는 Lambda 환경 변수입니다. 설정 시, Lambda 함수의 텔레메트리는 기본값인 Lambda 함수 이름 대신 사용자가 선택한 이름의 APM 엔티티 아래에 표시됩니다.

## 작동 원리

`NEW_RELIC_APM_LAMBDA_MODE`이(가) `true`일 때, 뉴렐릭 Lambda 확장은 각 콜드 스타트 시 APM `connect` 호출을 수행합니다. 해당 호출에서 `NEW_RELIC_APP_NAME` (설정되지 않은 경우 `AWS_LAMBDA_FUNCTION_NAME`로 대체)을(를) `app_name` (으)로 사용합니다. APM 수집기는 해당 이름에 대한 엔티티를 확인하거나 생성하고 GUID를 반환합니다. 해당 호출 중에 생성된 모든 텔레메트리는 해당 GUID로 태그 지정되며 뉴렐릭의 명명된 엔티티 아래에 표시됩니다.

## 구성

`NEW_RELIC_APP_NAME`을(를) Lambda 환경 변수로 설정합니다. 코드 변경이 필요하지 않습니다 ― 확장이 콜드 스타트 시 자동으로 처리합니다.

```
NEW_RELIC_APP_NAME = my-entity-name
```

## 지원되는 런타임

`NEW_RELIC_APP_NAME` 은(는) 모든 APM 모드 Lambda 런타임에서 지원됩니다 ― 파이썬, Node.js, 자바, 루비. .NET 및 Go.

## 엔티티 행동

동일한 `NEW_RELIC_APP_NAME` 값과 뉴렐릭 계정을 공유하는 함수는 뉴렐릭 UI에서 단일 APM 엔티티로 그룹화됩니다.

설정한 이름이 기존 APM 엔티티(예: Lambda가 아닌 서비스에서 이미 생성한 엔티티)와 일치하는 경우, Lambda 함수의 텔레메트리가 해당 엔티티에 자동으로 병합됩니다. 별도의 엔티티가 생성되지 않습니다.

<Callout variant="important">
  `NEW_RELIC_APP_NAME` 을(를) 변경하면 새로운 APM 엔티티가 생성됩니다. 이전 이름과 관련된 이력 데이터는 새 엔티티로 마이그레이션되지 않습니다.
</Callout>

## 다중 리전 보고서

서로 다른 AWS 리전에 배포된 여러 Lambda 함수는 동일한 `NEW_RELIC_APP_NAME`을(를) 공유할 수 있습니다. 이 모든 함수는 배포된 리전에 관계없이 단일 APM 엔티티에 보고합니다.

그룹화된 엔티티 내에서 개별 함수 또는 리전별 배포를 구분하려면 NRQL에서 `tags.aws.arn` 속성으로 필터링하거나 엔티티 뷰에서 태그 필터 표시줄을 사용하세요.

## 교차 런타임 보고

동일한 `NEW_RELIC_APP_NAME`을(를) 공유하는 서로 다른 런타임을 사용하는 Lambda 함수(예: 파이썬 함수 및 Node.js 함수)는 별도의 APM 엔티티를 생성합니다 ― 런타임당 하나씩. 그룹화는 런타임 경계를 넘지 않습니다.

## Lambda 및 비-Lambda 서비스 간 동일한 앱 이름

Lambda 함수와 Lambda가 아닌 APM 서비스(예: 기존 웹 애플리케이션 또는 마이크로서비스)가 모두 동일한 `NEW_RELIC_APP_NAME`(으)로 구성된 경우, **동일한** APM 엔티티에 보고합니다.

이는 의도적일 수 있습니다. Lambda와 서버 기반 인프라 모두에서 실행되는 서비스의 통합된 뷰를 원할 경우, 이름을 공유하면 모든 텔레메트리 ― 트랜잭션, 오류, 처리량 ― 가 한 곳에 표시되도록 할 수 있습니다.

하지만 의도치 않게 수행된 경우 혼란을 초래할 수 있습니다. Lambda 함수와 비 Lambda 서비스의 메트릭, 오류율 및 처리량이 결합되어, 문제를 진단하거나 성능을 독립적으로 이해하기가 더 어려워질 수 있습니다.

## 엔티티 수명 주기 및 태그 만료

Lambda 함수가 보고를 중단하더라도 해당 APM 엔티티가 즉시 제거되지는 않습니다. 수신되는 텔레메트리가 없으면 약 1～2일 후에 엔티티 태그(`aws.arn` 포함)가 만료됩니다. 계정의 보존 설정에 따라 엔티티 자체는 더 오래 지속될 수 있습니다.

## 문제 해결

**설정 후에도 함수 이름 아래에 텔레메트리가 계속 표시됩니다 `NEW_RELIC_APP_NAME`**

* 변수가 애플리케이션 코드뿐만 아니라 Lambda 환경 수준에서 설정되었는지 확인하십시오.
* CloudWatch 로그에서 `[NR_EXT]` APM 연결 항목을 확인하십시오 ― `app_name` 필드에 사용자 지정 값이 반영되어야 합니다.
* 계층의 뉴렐릭 Lambda 확장 버전이 이 기능을 지원하는지 확인하십시오.

**동일한 함수에 대해 두 개의 별도 엔티티가 존재합니다**

이는 함수가 이미 보고 중인 상태에서 `NEW_RELIC_APP_NAME`이(가) 추가되거나 변경될 때 예상되는 현상입니다. 이전 엔티티는 이력 데이터를 유지하며, 모든 새로운 텔레메트리는 새 엔티티로 전송됩니다.

**동일한 앱 이름을 가진 두 개의 Lambda 함수는 별도의 엔티티로 표시됩니다**

이는 런타임이 다를 때(예: 파이썬 대 Node.js) 예상되는 동작입니다. 동일한 런타임과 동일한 `NEW_RELIC_APP_NAME`을(를) 공유하는 함수는 하나의 엔티티로 보고됩니다.
