<Callout title="시사">
이 기능은 아직 개발 중이지만 꼭 사용해 보시기 바랍니다!

이 기능은 현재 [출시 전 정책](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy) 에 따라 미리보기 프로그램의 일부로 제공됩니다.
</Callout>

<DNT>New Relic Change Tracking for GitHub Copilot</DNT> 모니터링을 위해 설정한 각 배포 후에 서비스를 모니터링합니다. <DNT>Autopilot</DNT>은(는) 예정된 체크포인트에서 서비스 상태를 확인하고, pull 요청에 댓글을 남기며, 연결한 경우 <DNT>Slack</DNT>에 결과를 보고합니다. 회귀를 감지하면 <DNT>GitHub Copilot</DNT>에게 할당된 <DNT>GitHub</DNT> 이슈도 생성하며, 조직에 <DNT>GitHub Copilot Enterprise</DNT>이(가) 있는 경우 pull 요청으로 수정 사항을 제안할 수 있습니다.

<Callout variant="important">
<DNT>New Relic Change Tracking for GitHub Copilot</DNT> [GitHub에 Autopilot 연결](/docs/agentic-ai/autopilot/connect-to-github)에서 설명하는 읽기 권한 외에도 쓰기 권한이 있는 <DNT>GitHub</DNT> 토큰이 필요합니다. 이미 연결한 토큰에 쓰기 권한을 추가하거나 모든 권한이 있는 새 토큰을 연결하십시오.
</Callout>

모니터링을 위해 설정된 각 배포는 다음 단계를 거칩니다:

1. pull 요청을 병합하면 파이프라인이 이를 배포합니다. 배포 시 릴리스 태그 URL, 병합 커밋 SHA 및 `watchpoint_monitoring` 속성이 포함된 이벤트를 변경 추적에 전송합니다.
2. <DNT>Autopilot</DNT> 이벤트를 검증합니다. 통과하면 <DNT>Autopilot</DNT>이(가) 병합된 pull 요청에 댓글을 남기고, <DNT>Slack</DNT>을(를) 연결한 경우 &quot;모니터링 시작됨&quot; 메시지를 게시합니다.
3. 각 체크포인트에서 <DNT>Autopilot</DNT>은(는) 배포 후 서비스의 메트릭을 배포 전 메트릭과 비교합니다. 세 가지 결과(회귀 없음, 결론 없음 또는 회귀 감지됨) 중 하나를 pull 요청의 댓글로 보고하며, <DNT>Slack</DNT>을(를) 연결한 경우 동일한 스레드의 답글로 보고합니다. 체크포인트는 배포 후 10분, 30분, 1시간, 2시간, 24시간 및 72시간에 실행됩니다.

체크포인트가 회귀를 감지하면 <DNT>Autopilot</DNT>은(는) 세 가지 작업을 수행합니다:

* (<DNT>Slack</DNT>을(를) 연결한 경우) 관련 메트릭 및 발견된 내용의 근거와 함께 <DNT>Slack</DNT> 스레드에 답글을 게시합니다.
* 관련 메트릭, 회귀를 감지한 체크포인트 및 이유와 함께 pull 요청에 댓글을 남깁니다.
* 회귀한 내용, 뒷받침하는 증거, 확인해야 할 위치 및 수락 기준을 설명하는 <DNT>GitHub</DNT> 이슈를 연 다음, 해당 이슈를 <DNT>GitHub Copilot</DNT>에게 할당합니다.

<DNT>Copilot</DNT>이(가) 수정 사항을 제안하는 경우, 병합하기 전에 다른 pull 요청과 마찬가지로 검토하십시오.

## 전제 조건 [#prerequisites]

<DNT>New Relic Change Tracking for GitHub Copilot</DNT>을(를) 설정하기 전에 다음을 확인하십시오:

* <DNT>Autopilot</DNT> 구성을 완료했습니다. [Autopilot 설정](/docs/agentic-ai/autopilot/setup)을 참조하십시오.

* <DNT>**New Relic Organization Manager**</DNT>이며, <DNT>**[one.newrelic.com &gt; Administration](https://one.newrelic.com/admin-portal) &gt; Preview &amp; Trials**</DNT>에서 <DNT>**New Relic Change Tracking for GitHub Copilot**</DNT>에 참여하기로 선택했습니다.

* 모니터할 저장소에 대한 쓰기 권한이 있는 <DNT>GitHub</DNT> 계정 및 토큰이 있습니다.

* [배포 시](/docs/change-tracking/overview) 뮤테이션 과 함께 [`changeTrackingCreateEvent` 변경](/docs/change-tracking/config/nerdgraph) 추적 으로 이벤트를 전송합니다. <DNT>New Relic Change Tracking for GitHub Copilot</DNT>은(는) 구형 엔드포인트를 지원하지 않습니다.

* 각 이벤트에는 다음이 포함됩니다.

  * `changelog` 필드의 릴리스 태그 URL입니다.
  * `commit` 필드의 병합 커밋 SHA입니다.
  * 모니터할 각 배포에 대해 커스텀 속성 `watchpoint_monitoring`이(가) `"true"`(으)로 설정되어 있습니다.

* 서비스는 뉴렐릭에 보고되며 최소 3일의 기록이 있습니다. 데이터가 적을 경우 모든 체크포인트에서 불확실한 결과를 반환합니다.

선택적으로 [Autopilot을 Slack에 연결](/docs/agentic-ai/autopilot/connect-to-slack) 하여 공지를 받을 수 있습니다. <DNT>Copilot</DNT>이(가) 자동으로 문제에 대한 작업을 시작하려면 조직에 <DNT>GitHub Copilot Enterprise</DNT>이(가) 필요합니다.

## GitHub Copilot용 뉴렐릭 변경 추적 설정 [#setup]

<Steps>
<Step>
### GitHub 토큰 생성 [#create-token]

<DNT>GitHub</DNT>에서 개인 액세스 토큰을 생성하십시오. 세분화된 토큰이 권장되지만, 클래식 토큰도 사용할 수 있습니다. 자세한 지침은 <DNT>GitHub</DNT> 문서의 [세분화된 개인 액세스 토큰 생성](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token)을 참조하십시오. 토큰에 다음 항목이 포함되어 있는지 확인하십시오:

* 리소스 소유자로서의 귀하의 <DNT>GitHub</DNT> 조직입니다.
* <DNT>New Relic Change Tracking for GitHub Copilot</DNT>이(가) 모니터할 저장소에 대한 액세스 권한입니다.
* <DNT>**Read and write**</DNT> <DNT>**Pull requests**</DNT>, <DNT>**Issues**</DNT> 및 <DNT>**Contents**</DNT>에 대한 액세스.

이미 <DNT>GitHub</DNT>을(를) <DNT>Autopilot</DNT>에 연결하여 토큰을 가지고 있는 경우, 대신 해당 토큰에 이러한 권한을 추가할 수 있습니다.

조직에서 SAML SSO를 시행하는 경우 SSO에 대한 토큰을 승인해 주십시오. <DNT>GitHub</DNT>은(는) 토큰을 한 번만 표시하므로, 생성 시 복사하여 뉴렐릭에 즉시 붙여넣어 주십시오.
</Step>

<Step>
### GitHub 연결 및 모니터링 활성화 [#enable]

<DNT>Autopilot</DNT> 설정을 열려면 <DNT>**Ask AI**</DNT>을(를) 클릭하고 **...**을(를) 클릭한 다음 <DNT>**Configure**</DNT>을(를) 클릭하십시오.

<img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp" />

<DNT>**External MCP connections**</DNT>에서 토큰 및 조직 이름으로 <DNT>**GitHub**</DNT> (<DNT>**Public GitHub**</DNT> 또는 <DNT>**GitHub Enterprise Cloud**</DNT>)을(를) 연결한 다음 <DNT>**Enable deployment monitoring**</DNT>을(를) 켜십시오. 공지를 받으려면 <DNT>**Post alerts to**</DNT>에서 <DNT>Slack</DNT> 채널도 선택하십시오. 이 옵션은 <DNT>Slack</DNT>을(를) <DNT>Autopilot</DNT>에 연결한 후에만 나타납니다.

변경 사항을 저장하려면 <DNT>**Update agent**</DNT>을(를) 클릭하십시오.
</Step>

<Step>
### 모니터링이 시작되었는지 확인 [#verify]

`watchpoint_monitoring` 속성을 `"true"`(으)로 설정하여 변경 사항을 배포하십시오.

<CollapserGroup>
<Collapser id="example-event" title="배포 이벤트 예시">
```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "MERGE_COMMIT"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```
</Collapser>
</CollapserGroup>

<DNT>Autopilot</DNT>이(가) 배포 이벤트를 검증한 후 다음이 표시됩니다:

* 병합된 pull 요청에 대한 <DNT>Autopilot</DNT>의 댓글입니다.
* <DNT>Slack</DNT>을(를) 연결한 경우, 선택한 채널에 &quot;모니터링 시작됨&quot; 메시지가 표시됩니다. 이후 체크포인트의 결과는 해당 스레드의 답글로 표시됩니다.

어느 것도 표시되지 않으면 배포 이벤트가 [전제 조건](#prerequisites)을 충족하는지 확인해 주십시오.
</Step>
</Steps>
