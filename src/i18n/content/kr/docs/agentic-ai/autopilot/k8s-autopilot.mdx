Autopilot을 벗어나지 않고 Kubernetes 문제를 진단하십시오. Autopilot K8s 에이전트는 [뉴렐릭 Autopilot](/docs/agentic-ai/autopilot/overview/) 내의 특화된 하위 에이전트입니다. 뉴렐릭 Autopilot은 뉴렐릭 자율 운영 내의 AI 기반 운영 인터페이스이자 핵심 기능입니다. 텔레메트리를 분석하고 해결 방법을 권장합니다. Autopilot K8s 에이전트는 [뉴렐릭 Autopilot](/docs/agentic-ai/autopilot/overview/) 내에서 특화된 하위 에이전트로 실행됩니다. 단일 통합 Autopilot과 상호 작용하며, 이는 Kubernetes 관련 쿼리를 Autopilot K8s 에이전트로 자동 라우팅합니다.

수동으로 `kubectl` 명령을 실행하고 여러 대시보드에서 메트릭을 상호 연관시키는 대신, 에이전트가 클러스터 상태를 분석하고, 근본 원인을 식별하며, 실행 가능한 문제 해결 단계를 실시간으로 제공합니다.

* 구형 컴퓨트(CCU) 플랜.

## 주요 이점 [#benefits]

* **일반적인 Kubernetes 장애에 대한 근본 원인 분석**: `CrashLoopBackOff`, `OOMKilled`, 보류 중이거나 예약할 수 없는 파드, `ImagePullBackOff`, 복제본 불일치, 높은 재시작 횟수, 노드 압박, 중단된 롤아웃, DNS, 서비스 및 인그레스 문제, HPA 동작, 스토리지 및 PVC 문제
* **심층 컨텍스트**: 매니페스트, 이벤트, 리소스 메트릭, 로그 및 배포 내역을 함께 분석합니다.
* **클러스터 그 이상**: Kubernetes 문제를 APM 서비스 및 손상된 인스턴스나 비정상적인 로드 밸런서 타겟과 같은 AWS 및 Azure의 클라우드 인프라와 연관시킵니다.
* **수정 지침**: 단순한 탐지가 아닌 구체적인 수정 단계를 제공합니다.
* **Kubernetes 뷰에서 원클릭**: Kubernetes UI 전반의 <DNT>**Investigate**</DNT> 버튼은 현재 보고 있는 내용의 컨텍스트를 바탕으로 조사를 시작합니다.
* **OpenTelemetry와 작동**: [뉴렐릭 Kubernetes 통합](/docs/kubernetes-pixie/kubernetes-integration/get-started/introduction-kubernetes-integration/) 또는 [Kubernetes용 OpenTelemetry](/docs/kubernetes-pixie/k8s-otel/intro/)로 모니터되는 클러스터에서 동일한 진단을 실행합니다.
* **추가 계측이 필요하지 않습니다**: 이미 뉴렐릭으로 전송하는 Kubernetes 데이터와 함께 작동합니다.

## Autopilot K8s 에이전트 작동 방식 [#how]

뉴렐릭 AI 채팅 사이드바의 Autopilot을 통해 액세스하거나 Kubernetes 뷰의 <DNT>**Investigate**</DNT> 버튼에서 액세스할 수 있습니다. 문제를 설명하거나 프롬프트(예: `"Why are pods in namespace X crashing?"`)를 입력하여 에이전트의 자율 조사를 트리거할 수 있습니다. 에이전트는 클러스터 상태를 분석하고, 메트릭을 상호 연관시키며, 매니페스트와 이벤트를 검사하여 근본 원인을 식별합니다. 그런 다음 실행 가능한 문제 해결 단계를 실시간으로 제공합니다.

## 전제 조건 [#prerequisites]

* [Kubernetes 통합](/install/kubernetes/) 또는 [Kubernetes용 OpenTelemetry](/docs/kubernetes-pixie/k8s-otel/intro/)에서 뉴렐릭으로의 Kubernetes 데이터 보고. 옵저버빌리티 설정\[애플리케이션 성능 모니터링(APM), 인프라 모니터링, 클라우드 통합 및 Kubernetes 데이터]이 완전할수록 에이전트의 분석이 더 풍부해집니다.
* 계정에 뉴렐릭 [Autopilot이 활성화 및 설정](/docs/agentic-ai/autopilot/setup) 되어 있어야 합니다.

## Autopilot K8s 에이전트 사용 방법 [#usage]

계정에 Autopilot이 활성화되면 Autopilot K8s 에이전트를 사용하여 Kubernetes 환경을 분석하고 인시던트 조사를 시작할 수 있습니다. 여기에 액세스하는 방법에는 세 가지가 있습니다:

* 뉴렐릭 AI chat sidebar \[채팅 사이드바]에서 **Autopilot에 직접 질문하십시오**.
* Kubernetes 뷰의 **Investigate \[조사] 버튼에서 시작합니다**. [Kubernetes 뷰에서 시작](#investigate)을 참조하십시오.
* **알림에서:** 공지 워크플로우가 Autopilot으로 문제를 전송하고 조사에 Kubernetes 리소스가 포함된 경우, Autopilot은 분석의 일환으로 자동으로 Autopilot K8s 에이전트를 호출합니다. 기존의 [Autopilot 공지 설정](/docs/agentic-ai/autopilot/setup) 외에 추가 설정은 필요하지 않습니다.

### 사용 팁 [#tips]

Autopilot은 쿼리에 포함된 키워드와 컨텍스트를 기반으로 특화된 Kubernetes 진단 엔진으로 프롬프트를 라우팅합니다.

질문이 Autopilot K8s 에이전트에 전달되도록 하려면 다음과 같이 하십시오:

* **프롬프트에 &quot;K8s&quot; 또는 &quot;Kubernetes&quot;를 사용하십시오:** 이 두 단어 중 하나를 포함하는 것은 질문을 Autopilot K8s 에이전트로 라우팅하는 가장 확실한 신호입니다.

* **Kubernetes 용어를 구체적으로 명시하십시오:** `pod`, `node`, `namespace`, `deployment`, `replica`, `container`, `cluster`, `workload`, `CrashLoopBackOff`, `OOMKilled`, `PVC`, `HPA` 등과 같은 Kubernetes 관련 용어를 포함하십시오.

  예를 들어:

  | 덜 효과적입니다.             | 더욱 효과적입니다.                                                          |
  | :-------------------- | :------------------------------------------------------------------ |
  | `Why is my app slow?` | `Why are pods in namespace payments restarting?`                    |
  | `Something is broken` | `Pod checkout-service in cluster prod-east is in CrashLoopBackOff`  |
  | `Fix my deployment`   | `Deployment api-gateway has replica mismatch in namespace frontend` |
  | `Check my cluster`    | `What's the health of my Kubernetes cluster prod-east-1?`           |

* **가능한 경우 컨텍스트를 추가하십시오**

  * 클러스터 이름, 네임스페이스, 파드/배포 이름 또는 노드를 언급하십시오.
  * `"Pending"`, `"Evicted"`, `"ImagePullBackOff"` 등과 같은 정확한 상태 용어를 사용하여 증상을 설명하십시오.
  * 해당하는 경우 명시적인 시간 범위를 정의하십시오. 예: `"since last rollout"`, `"in the last hour"`.

* **자체 증거 붙여넣기:** `kubectl describe` 출력, 로그 또는 오류 메시지를 프롬프트에 붙여넣을 수 있습니다. 에이전트는 뉴렐릭 데이터와 함께 이를 추론합니다.

* **자동 UI 라우팅 활용:** [Investigate \[조사\] 버튼](#investigate)을 포함하여 뉴렐릭의 Kubernetes 페이지에서 Autopilot을 열면, 명시적인 키워드 없이도 쿼리를 Autopilot K8s 에이전트로 자동 라우팅합니다. 에이전트는 활성 UI 뷰에서 직접 상황별 메타데이터를 수신합니다.

  <Callout variant="tip" title="에이전트 라우팅을 확인하십시오.">
  에이전트의 응답에서 **Show reasoning** \[추론 표시]를 확장하여 Autopilot K8s 에이전트가 쿼리를 처리했는지 확인할 수 있습니다. 올바르게 라우팅된 경우, 호출된 Kubernetes 진단 도구(예: 클러스터 분석, 매니페스트 검사 또는 이벤트 상관관계)와 함께 Autopilot K8s 에이전트 어시스턴트에 대한 참조를 확인할 수 있습니다. Kubernetes 관련 추론이 표시되지 않는 경우, 더 명시적인 Kubernetes 키워드를 사용하여 다시 작성해 보십시오.
  </Callout>

## 프라이버시 및 보안 [#privacy]

에이전트는 뉴렐릭 계정에 이미 수집된 텔레메트리 데이터만 분석합니다. 클러스터에 직접 액세스하거나, 명령을 실행하거나, Kubernetes 시크릿을 읽지 않습니다. 해결 단계는 직접 검토하고 실행하는 제안 사항이며, 리소스를 변경하는 제안된 명령에는 먼저 그 영향을 확인할 수 있도록 `--dry-run=client`이(가) 포함되어 있습니다.

모든 상호작용은 기존 뉴렐릭 계정 권한 및 데이터 액세스 제어의 적용을 받습니다.
