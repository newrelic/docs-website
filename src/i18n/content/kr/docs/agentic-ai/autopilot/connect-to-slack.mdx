공지가 트리거되면, 조사하기 위해 팀이 이미 대화 중인 <DNT>Slack</DNT>과(와) 뉴렐릭 UI 사이를 자주 오가게 됩니다. 이러한 컨텍스트 전환은 응답을 지연시킵니다.

팀이 스레드에서 바로 조사하고 <DNT>Slack</DNT> 워크플로우의 Autopilot에서 동일한 출력을 받을 수 있도록 <DNT>Autopilot</DNT> 을(를) <DNT>Slack</DNT> 에 연결하세요. 질문과 함께 뉴렐릭 앱(예: `@New Relic`)을 멘션하면, 사용자의 뉴렐릭 권한을 사용하여 답변합니다.

## 당신이 할 수 있는 일 [#what-you-can-do]

앱을 초대한 모든 채널에서 앱을 멘션합니다(예: `@New Relic`). <DNT>Autopilot</DNT> 은(는) 다음을 수행할 수 있습니다:

* **알림 분류**: 공지가 트리거된 이유, 영향을 받는 항목 및 상관관계가 있는 항목을 알아봅니다.
* **엔티티 상태 확인**: 모니터되는 모든 서비스의 현재 상태를 가져옵니다.
* **변경 사항 분석**: 최근 배포로 인해 회귀가 발생했는지 확인합니다.
* **다중 턴 조사 실행**: 더 깊이 파고들려면 동일한 스레드에서 후속 질문을 하세요.
* **조사 상태, 요약 및 주요 세부 정보 검색**: 심각도, 근본 원인, 해결, 감지 및 할당된 인시던트 커맨더와 같은 세부 정보 외에도 상태 및 요약 정보를 검색합니다.

<DNT>Autopilot</DNT> 동일한 스레드에서 응답하고 뉴렐릭 권한이 허용하는 데이터에만 액세스합니다.

## 전제 조건 [#prerequisites]

시작하기 전에 다음 사항을 확인하십시오:

* **구성된 <DNT>Autopilot</DNT>**: 계정 및 권한이 설정된 활성 에이전트입니다. [Autopilot 설정](/docs/agentic-ai/autopilot/setup)을 참조하세요.
* **<DNT>Slack</DNT> 관리자 액세스**: 뉴렐릭 앱을 승인하기 위한 <DNT>Slack</DNT> 작업 공간의 관리자 권한입니다.
* **<DNT>Workflow</DNT> FCM**: <DNT>Slack</DNT>에서 <DNT>Autopilot</DNT> 을(를) 호출하려면 <DNT>Autopilot</DNT> FCM 외에도 <DNT>Workflow</DNT> FCM을 활성화해야 합니다.
* **사용자 API 키 생성 권한**: <DNT>Slack</DNT>에서 <DNT>Autopilot</DNT> 을(를) 사용하려면, 역할에서 <DNT>Workflow Automation</DNT> 계정에 대한 사용자 API 키를 생성할 수 있도록 허용해야 합니다.

## Slack 연결 설정 [#setup]

<Steps>
  <Step>
    ### Slack 워크스페이스 연결(관리자) [#connect-slack]

    [조직 관리자](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts/#role-scopes) 는 <DNT>Autopilot</DNT> 설정 중에 작업 공간을 연결합니다:

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com)**</DNT> 으)로 이동합니다.

    2. 오른쪽 상단에서 <DNT>**Ask AI**</DNT> 선택한 다음 <DNT>**Configure**</DNT> 탭(톱니바퀴 아이콘)을 선택합니다.

    3. <DNT>**Agents**</DNT> 아래에서 <DNT>Autopilot</DNT>을(를) 선택합니다.

    4. <DNT>**Slack (optional)**</DNT> 섹션에서 <DNT>**Connect**</DNT> 클릭합니다.

    5. <DNT>Slack</DNT> 권한 부여 화면에서:

       1. 연결할 작업 공간을 선택합니다.
       2. 요청된 기본 권한을 검토하고 <DNT>**Allow**</DNT>을(를) 클릭합니다.

    6. 녹색 <DNT>**Connected**</DNT> 배지가 나타나는지 확인하세요.

    7. <DNT>**Update agent**</DNT> 을(를) 클릭합니다.

    <Callout variant="important">
      작업 공간 연결을 통해 사용자는 <DNT>Slack</DNT> ID를 연결하여 <DNT>Autopilot</DNT> 이(가) 작업 공간에서 응답할 수 있도록 합니다. <DNT>Autopilot</DNT> 은(는) 연결된 [Slack 작업 공간](https://slack.com/help/categories/200122103-Workspace-administration) 에서만 응답합니다.
    </Callout>

    <Callout variant="tip">
      작업 공간에서 <DNT>Autopilot</DNT> 의 응답을 중지하려면, 이 페이지에서 언제든지 작업 공간의 연결을 해제할 수 있습니다.
    </Callout>
  </Step>

  <Step>
    ### 채널에 뉴렐릭 앱 초대 [#invite-to-channel]

    모든 작업 공간 멤버는 뉴렐릭 앱을 채널에 초대할 수 있습니다. 채널에서 뉴렐릭 앱을 멘션합니다(예: `@New Relic`). 앱이 아직 없는 경우 <DNT>Slack</DNT> 에서 앱을 추가하라는 메시지를 표시합니다. <DNT>Slack</DNT> 채널의 <DNT>integration</DNT> 탭에서 추가할 수도 있습니다.
  </Step>

  <Step>
    ### ID 연결(처음에만) [#link-identity]

    ID가 연결되기 전에 스레드에서 처음으로 뉴렐릭 앱을 멘션하는 경우, 뉴렐릭 계정을 연결하라는 비공개 메시지가 표시됩니다. <DNT>**Connect**</DNT> 을(를) 클릭하고 뉴렐릭 자격 증명으로 로그인하여 ID를 연결하세요. <DNT>**Connect**</DNT> 및 <DNT>**Authenticate**</DNT> 링크는 10분 후에 만료됩니다. 링크가 만료되면 뉴렐릭 앱을 다시 멘션하세요.

    <Callout variant="important">
      이것은 작업 공간당 한 번만 수행하는 단계입니다. ID를 연결한 후에는 다시 연결할 필요 없이 해당 작업 공간의 모든 채널에서 뉴렐릭 앱을 멘션할 수 있습니다.
    </Callout>
  </Step>
</Steps>

## Slack에서 Autopilot 사용 [#use-in-slack]

설정 후에는 앱을 초대한 모든 채널이나 앱의 홈 탭에서 <DNT>Autopilot</DNT> 을(를) 사용하세요.

### 홈 탭에서 연결 확인 [#home-tab]

홈 탭을 열고 연결 상태를 확인하려면 <DNT>Slack</DNT> 사이드바에서 뉴렐릭 앱을 클릭합니다:

* **연결되지 않음**: 계정을 연결하기 위한 <DNT>**Connect to New Relic**</DNT> 버튼이 있는 시작 화면입니다.
* **연결 만료됨**: 재인증을 위한 <DNT>**Authenticate**</DNT> 버튼이 있는 프롬프트입니다.
* **오류**: 복구 단계가 포함된 &quot;문제가 발생했습니다&quot; 메시지입니다.

연결되면 홈 탭에 현재 연결된 뉴렐릭 조직, <DNT>**Switch orgs**</DNT> 옵션 및 <DNT>**Disconnect**</DNT> 옵션도 표시됩니다.

### 질문하기 [#ask-a-question]

스레드에서 질문과 함께 뉴렐릭 앱(예: `@New Relic`)을 멘션합니다:

```
@New Relic why is checkout-service alerting?
@New Relic what deployed on payment-gateway in the last hour?
@New Relic investigate this alert
```

### 컨텍스트에서 알림 조사 [#investigate-in-context]

뉴렐릭이 채널에 공지를 게시하면 해당 스레드에 답글을 남기세요. <DNT>Autopilot</DNT> 이(가) 공지를 읽고 엔티티와 문제를 식별하므로 이름을 지정할 필요가 없습니다.

### 후속 질문하기 [#follow-up-questions]

동일한 스레드에서 계속합니다. <DNT>Autopilot</DNT> 이(가) 컨텍스트를 유지하기 위해 이전 메시지를 읽습니다:

```
@New Relic what's causing this?
[Autopilot replies with a root cause analysis]
@New Relic what was the deployment before that?
[Autopilot replies with more context]
```

### 뉴렐릭 조직 전환 [#switch-orgs]

여러 뉴렐릭 조직에 액세스할 수 있는 경우, 연결을 끊지 않고 <DNT>Slack</DNT> ID가 사용하는 조직으로 전환하세요:

1. <DNT>Slack</DNT>에서 뉴렐릭 앱의 홈 탭을 여세요.
2. <DNT>**Switch orgs**</DNT> 을(를) 클릭합니다.
3. 뉴렐릭 로그인 페이지에서 원하는 조직의 계정으로 로그인합니다.

인증 후 홈 탭에 새로 연결된 조직이 표시되며, 향후 이 작업 공간에서 멘션하면 이를 쿼리합니다.

<Callout variant="important">
  <DNT>Slack</DNT> ID는 작업 공간당 한 번에 하나의 뉴렐릭 조직에만 연결됩니다. 전환하면 이전 뉴렐릭 조직 매핑이 대체됩니다.
</Callout>

### Autopilot에 대한 액세스 일시 중지 [#pause-access]

전체 작업 공간의 연결을 끊지 않고 <DNT>Autopilot</DNT> 에 대한 자신의 직접적인 대화형 액세스를 중지하려는 경우:

1. <DNT>Slack</DNT> 사이드바에서 뉴렐릭 앱을 클릭하여 홈 탭을 엽니다.
2. <DNT>**Disconnect**</DNT> 을(를) 클릭합니다.

<DNT>Autopilot</DNT> 에 대한 대화형 액세스가 즉시 중지됩니다. 작업 공간에서 <DNT>Autopilot</DNT>의 자동 업데이트를 포함한 공지를 계속 받습니다. 대신 전체 조직의 통합을 제거하려면 [Slack 통합 제거](#remove-integration)를 참조하십시오.

  <Collapser id="how-data-is-used" title="Autopilot이 Slack 데이터를 사용하는 방법">

    <Callout variant="caution">
      <DNT>Autopilot</DNT> 호출된 스레드의 모든 메시지를 읽습니다. 해당 스레드에서 비밀번호, API 키, 토큰, 자격 증명 또는 기타 민감한 정보를 공유하지 마십시오. 자격 증명이 공유된 경우, 해당 정보가 사용되지 않도록 대신 새 스레드에서 뉴렐릭 앱을 멘션하십시오.
    </Callout>

    <DNT>Autopilot</DNT> 다음을 수행합니다:

    * 언급된 스레드의 메시지를 읽습니다.
    * 스레드의 뉴렐릭 공지 URL에서 공지 및 엔티티 세부 정보를 추출합니다.
    * 뉴렐릭 권한을 기반으로 뉴렐릭 인사이트를 사용하여 응답합니다.
    * 모든 채널 멤버가 볼 수 있는 응답을 게시합니다.

    <Callout variant="important">
      응답은 뉴렐릭 액세스 권한이 없는 사람을 포함하여 채널의 모든 사람에게 표시됩니다. <DNT>Autopilot</DNT> 은(는) 사용자의 권한으로 데이터를 쿼리하지만, 그 응답은 채널에 공개됩니다.
    </Callout>

    ### 데이터 격리 [#data-isolation]

    <DNT>Slack</DNT> 의 각 요청은 다음으로 격리됩니다:

    * **요청당 자격 증명**: <DNT>Autopilot</DNT> 을(를) 호출할 때마다 호출하는 사용자의 토큰을 사용합니다.
    * **자격 증명 저장 안 함**: 자격 증명은 요청 헤더를 통해서만 전달됩니다. 저장되거나 유지되지 않습니다.
    * **스레드 특정**: 요청은 Autopilot이 호출된 스레드로 범위가 지정됩니다.
    * **영구적인 <DNT>Slack</DNT> 데이터 없음**: <DNT>Autopilot</DNT> 은(는) 단일 요청에 대해서만 스레드 메시지를 메모리에 임시로 보관합니다.
  </Collapser>

  <Collapser id="nr-connect" title="NR Connect: ID 연결 및 인증">
    <DNT>NR Connect</DNT> <DNT>Slack</DNT> 사용자 ID를 뉴렐릭 계정에 매핑하는 인증 브리지입니다. <DNT>Autopilot</DNT> 이(가) 응답하기 전에 <DNT>NR Connect</DNT> 은(는) <DNT>Slack</DNT> 사용자 ID가 뉴렐릭 계정에 연결되어 있는지(사용자 매핑)와 인증 세션이 활성화되어 있는지(유효한 토큰) 확인합니다.

    ### 유효성 검사 작동 원리 [#how-validation-works]

    뉴렐릭 앱을 멘션할 때마다 시스템은 다음을 확인합니다:

    1. **작업 공간 권한 부여**: 관리자가 이 작업 공간을 뉴렐릭 조직에 연결했는지 여부입니다.
    2. **사용자 매핑**: <DNT>Slack</DNT> 사용자 ID가 뉴렐릭 계정에 연결되어 있는지 여부입니다.
    3. **토큰 유효성 검사**: 인증 세션이 활성 상태이고 만료되지 않았는지 여부입니다.

    모든 검사를 통과하면 <DNT>Autopilot</DNT> 이(가) 요청을 처리하고 스레드에 회신합니다. 매핑 또는 토큰이 실패하면 <DNT>**Connect**</DNT> 버튼이 있는 비공개 메시지가 표시됩니다. 로그인한 다음 뉴렐릭 앱을 다시 멘션합니다. 특정 오류에 대해서는 [Autopilot Slack 연결 문제 해결](/docs/agentic-ai/sre-agent/troubleshoot)을 참조하십시오.

## Slack 통합 제거 [#remove-integration]

<Callout variant="important">
  <DNT>Slack</DNT> 작업 공간에서 뉴렐릭 앱을 제거하면 완전히 삭제됩니다. 조직의 다른 모든 <DNT>Slack</DNT>기반 공지와 함께 <DNT>Autopilot</DNT> 공지를 중지합니다. 대신 자신의 액세스만 일시 중지하려면 [Autopilot에 대한 액세스 일시 중지](#pause-access)를 참조하세요.
</Callout>

<DNT>Slack</DNT> 작업 공간 관리자는 <DNT>Slack</DNT>의 표준 앱 제거 흐름을 사용하여 뉴렐릭 통합을 완전히 제거할 수 있습니다. [앱 제거에 대한 Slack의 문서](https://slack.com/help/articles/360003125231)를 참조하세요.

제거 후 뉴렐릭은 해당 <DNT>Slack</DNT> 대상을 <DNT>**UNINSTALLED**</DNT> (으)로 자동 표시하고 비활성 상태로 설정합니다. 수동으로 삭제할 필요가 없습니다.
