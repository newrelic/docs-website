## 계측 활성화 [#enable]

<DNT>Puma</DNT> 계측을 활성화하려면 `newrelic.yml`에서 `disable_puma_instrumentation` 을(를) `false` (으)로 설정합니다:

```yaml
disable_puma_instrumentation: false
```

에이전트는 <DNT>Puma</DNT> 마스터 프로세스에서 통계를 샘플링하므로, 에이전트가 마스터에 로드된 경우에만 메트릭을 수집합니다:

* **단일 모드** (워커 없음): 메트릭이 항상 수집됩니다.

* **클러스터 모드** (하나 이상의 워커): 애플리케이션이 사전 로드되어 에이전트가 워커가 아닌 마스터에 로드될 때만 메트릭이 수집됩니다. `preload_app!` 을(를) `puma.rb`에 추가합니다:

  ```ruby
  workers 2
  preload_app!
  ```

  <Callout variant="important">
    <DNT>Puma v6.x</DNT> 에서는 `preload_app!` 을(를) 명시적으로 설정해야 합니다. <DNT>Puma v6.x</DNT> 은(는) 구성 블록에서 `preload_app` 기본값을 적용하지 않으므로, `workers` 이(가) 설정되었지만 명시적인 `preload_app!` 이(가) 없는 클러스터링된 앱은 워커에 에이전트를 로드하며 **Puma 메트릭이 수집되지 않습니다**. 이러한 경우 에이전트는 경고를 로그에 기록합니다.
  </Callout>

### 샘플 속도 조정 [#sample-rate]

기본적으로 에이전트는 60초마다 <DNT>Puma</DNT> 통계를 샘플링합니다. `newrelic.yml`의 `puma.sample_rate` 구성으로 이를 변경합니다:

```yaml
puma.sample_rate: 30
```

## 쿼리 예시 [#queries]

`Metric` 유형을 사용하여 [NRQL](/docs/query-your-data/nrql-new-relic-query-language/get-started/introduction-nrql-new-relics-query-language/) 로 이러한 메트릭을 쿼리합니다. `YOUR_APP_NAME` 을 애플리케이션 이름으로 교체합니다.

모든 Puma 메트릭을 한 번에 보려면:

```sql
FROM Metric SELECT average(newrelic.timeslice.value)
WHERE appName = 'YOUR_APP_NAME' AND metricTimesliceName LIKE 'Ruby/Puma/%'
FACET metricTimesliceName TIMESERIES LIMIT MAX SINCE 1 hour ago
```

단일 메트릭을 보려면 이름으로 필터링하세요:

```sql
FROM Metric SELECT average(newrelic.timeslice.value)
WHERE appName = 'YOUR_APP_NAME' AND metricTimesliceName = 'Ruby/Puma/requests_count'
TIMESERIES LIMIT MAX SINCE 1 hour ago
```

## 작동 원리 [#behavior]

활성화되면 에이전트는 이러한 메트릭을 전달하기 위해 Puma 마스터 프로세스에서 보고 스레드를 시작합니다. 이는 Puma 워커의 연결과 함께 마스터에서 추가 에이전트 연결을 실행합니다.

계측은 `NewRelic::Agent.record_metric`을(를) 통해 정수 게이지 및 카운터만 기록합니다. 어떠한 요청, 쿼리 또는 사용자 데이터도 캡처하지 않습니다.
