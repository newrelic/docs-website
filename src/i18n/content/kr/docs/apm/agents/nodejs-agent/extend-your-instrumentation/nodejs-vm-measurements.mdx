뉴렐릭의 Node.js 에이전트는 Node.js 가상 머신(VM)에서 주요 [지표 타임슬라이스 데이터](/docs/data-analysis/metrics/analyze-your-metrics/data-collection-metric-timeslice-event-data)를 수집합니다. 이러한 메트릭은 Node.js VM 동작에 대한 인사이트를 제공하고 애플리케이션의 성능을 향상시키는 데 도움을 줍니다. 또한 에이전트는 CPU 메트릭을 수집하며, 이는 종종 가비지 컬렉션(GC) 메트릭과 함께 분석됩니다.

## 필요한 것 [#requirements]

에이전트 [릴리스 14.11.0](docs/release-notes/agent-release-notes/nodejs-release-notes/node-agent-14-11-0)부터 에이전트에는 에이전트 내부에 직접 JavaScript 네이티브 VM 메트릭 수집 루틴이 포함되어 제공됩니다. 이 릴리스 이전에는 가비지 컬렉션, 메모리 및 CPU와 관련된 Node.js VM 지표 타임슬라이스 데이터를 수집하기 위해 에이전트에 [추가 네이티브 모듈](https://www.npmjs.com/package/@newrelic/native-metrics)이 필요했습니다.

내장된 메트릭 수집 기능을 활용하려면 최신 에이전트 릴리스로 업데이트하는 것을 권장합니다. 이 문서의 나머지 부분에서는 이를 가정하며, 폐기된 네이티브 모듈은 참조하지 않습니다.

## Node.js VM 데이터 보기 [#view-data]

Node.js VM 데이터로 선별된 차트를 보려면 <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; APM &amp; services &gt; (select an app) &gt; Node VMs**</DNT> 으로 이동하세요. 자세한 내용은 [Node.js VM 통계 페이지를](/docs/agents/nodejs-agent/supported-features/node-vms-statistics-page) 참조하세요.

데이터는 [메트릭 및 이벤트](/docs/query-your-data/explore-query-data/data-explorer/introduction-data-explorer) 에서도 사용할 수 있습니다.

## 측정 세부 정보 [#garbage]

<Callout variant="tip">
모든 Node.js 버전에서 모든 데이터를 수집할 수 있는 것은 아닙니다. 일반적으로 최신 LTS 버전의 Node.js를 사용하는 경우 가장 완전한 데이터를 얻을 수 있습니다.
</Callout>

<Collapser id="time-in-garbage-collection" title="가비지 수집 시간">
Node.js 프로세스가 가비지 수집(V8에서 사용하는 모든 유형)에 소비한 시간입니다. 시간은 누적 측정항목( `GC/System/Pauses` )으로 측정되고 가비지 수집 유형별로 버킷( `GC/<type>` 으로 측정됩니다.

가능한 가비지 수집 유형은 다음과 같습니다.

<td>
`Scavenge`
</td>

<td>
가장 일반적인 가비지 수집 방법입니다. Node.js는 일반적으로 VM이 유휴 상태일 때마다 이들 중 하나를 트리거합니다.
</td>
</tr>

<tr>
<td>
`MarkSweepCompact`
</td>

<td>
가장 무거운 유형의 가비지 수집 V8이 수행할 수 있습니다. 이러한 일이 많이 발생하는 경우 프로세스에서 더 적은 수의 개체를 유지하거나 V8의 힙 제한을 늘려야 합니다.
</td>
</tr>

<tr>
<td>
`IncrementalMarking`
</td>

<td>
응용 프로그램이 일시 중지된 시간을 줄이기 위해 응용 프로그램 논리와 컬렉션을 인터리브하는 단계적 가비지 컬렉션입니다. Node.js v6 이상에서만 가능합니다.
</td>
</tr>

<tr>
<td>
`ProcessWeakCallbacks`
</td>

<td>
가비지 수집이 발생한 후 V8은 해제된 개체에 대해 등록된 약한 참조 콜백을 호출합니다. 이 측정은 주어진 가비지 콜렉션에 대한 첫 번째 약한 콜백의 시작부터 마지막 콜백의 끝까지입니다. Node.js v6 이상에서만 가능합니다.
</td>
</tr>
</tbody>
</table>

<Collapser id="memory" title="메모리">
New Relic Node.js 에이전트는 메모리 사용량과 관련된 다음 메트릭을 수집합니다.

<table>

<th>
<DNT>

<tbody>
<tr>
<td>
`Memory/Physical`
</td>

<td>
Node.js 프로세스에서 사용하는 총 실제 메모리(MB)입니다. `process.memoryUsage().rss` Node.js API를 사용하여 기록됩니다.
</td>
</tr>

<tr>
<td>
`Memory/Heap/Max`
</td>

<td>
Javascript 객체를 저장하기 위해 V8에서 할당한 총 힙(MB)입니다. `process.memoryUsage().heapTotal` Node.js API를 사용하여 기록됩니다.
</td>
</tr>

<tr>
<td>
`Memory/Heap/Used`
</td>

<td>
현재 앱에서 사용하는 V8 힙의 양(MB)입니다. `process.memoryUsage().heapUsed` Node.js API를 사용하여 기록됩니다.
</td>
</tr>

<tr>
<td>
`Memory/Heap/Free`
</td>

<td>
할당되었지만 사용되지 않은 V8 메모리의 양(MB)입니다. 파생 측정항목( `heapTotal` - `heapUsed` )입니다.
</td>
</tr>

<tr>
<td>
`Memory/NonHeap/Used`
</td>

<td>
V8 힙 이외의 메모리 양(MB)입니다. 파생 측정항목( `rss` - `heapTotal` )입니다. 이 메트릭은 V8 힙 외부에서 메모리 누수를 찾는 데 유용합니다. 예를 들어 버퍼 또는 스트림이 있습니다.
</td>
</tr>
</tbody>
</table>
</Collapser>
