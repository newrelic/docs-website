일반 설정은 라이선스 키, 애플리케이션 이름, 로깅, 프록시 및 높은 보안 모드를 포함하는 자바 에이전트의 핵심 설정 옵션입니다.

<Callout variant="tip">
전체 설정 인덱스로 돌아가기: [자바 에이전트 설정](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## 구성 파일 구조 [#Structure]

`newrelic.yml` 파일에는 다양한 환경별로 섹션이 마련되어 있습니다.

* 시험
* 개발
* 각색
* 생산(기본값)

뉴렐릭은 이러한 각 환경에 `common` 섹션에 나와 있는 설정을 적용합니다. [`newrelic.environment`](#newrelic-environment) 시스템 속성을 환경 이름으로 설정함으로써 다른 환경을 기본값으로 선택할 수 있습니다.

<Callout variant="tip">
[`newrelic.yml` 템플릿](/docs/java/java-agent-config-file-template) 을 사용할 수 있습니다.
</Callout>

`newrelic.yml` 을 편집하는 경우 [YAML 형식](https://en.wikipedia.org/wiki/YAML) 을 준수하도록 주의하십시오. New Relic의 Java 에이전트와 함께 파일을 사용하기 전에 YAML 유효성 검사기를 사용하여 구문이 정확한지 확인하고 다음 규칙을 따르세요.

## 구성 설정 우선 순위 [#config-options-precedence]

설정 파일의 설정을 재정의하려면 [시스템 속성 재정의](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties)를 사용하십시오. 특정 환경에서는 [환경 변수](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#Environment_Variables)를 사용하여 설정 파일과 시스템 속성을 모두 재정의할 수도 있습니다. 환경 변수는 주로 Heroku를 지원하기 위해 존재합니다. 사용 시 [서버 측 설정](/docs/agents/manage-apm-agents/configuration/server-side-agent-configuration)이 다른 모든 설정을 재정의합니다.

<img title="java-config-order.png" alt="java-config-order.png" src="/images/apm_diagram_Java-config-precedence.webp" />

<figcaption>
Java 에이전트를 사용하면 서버 측 구성이 다른 모든 설정을 재정의합니다. 환경 변수는 Java 시스템 속성을 재정의합니다. 자바 속성은 `newrelic.yml` 파일의 사용자 구성 설정을 재정의합니다. 사용자 설정은 `newrelic.yml` 기본 설정보다 우선합니다.
</figcaption>

## Java 확장 디렉토리 구성 [#extensions-directory]

Java 에이전트는 프로세스 시작 시 구성 파일을 읽습니다. 파일이 있는 디렉토리를 식별하려면 새 디렉토리를 생성하거나 기존 확장 디렉토리를 지정하십시오.

<CollapserGroup>
<Collapser id="create-extensions-directory" title="확장 디렉토리 생성">
확장 디렉토리를 생성하려면:

1. `newrelic.jar` 및 `newrelic.yml` 이 있는 디렉토리로 이동합니다. 이름이 `extensions` 인 디렉토리를 만듭니다.
2. `newrelic.yml` 에서 [`extensions.dir`](#cfg-extensions-dir) 속성이 설정되지 않았는지 확인합니다.
</Collapser>

<Collapser id="specify-extensions-directory" title="기존 확장 디렉토리 지정">
기존 Java 확장 디렉토리를 사용하려면:

1. `newrelic.yml` 파일에서 `common` 섹션을 찾습니다.
2. [`extensions.dir`](#cfg-extensions-dir) 속성을 사용하여 파일 위치를 지정합니다.
</Collapser>
</CollapserGroup>

[`enable_auto_app_naming`](#cfg-enable_auto_app_naming) 이 false인 경우 에이전트는 이 애플리케이션에 모든 데이터를 보고합니다. 그렇지 않으면 에이전트는 이 응용 프로그램에 백그라운드 작업(웹이 아닌 응용 프로그램에 대한 트랜잭션)만 보고합니다.

[둘 이상의 애플리케이션](/docs/java/multiple-application-names)에 데이터를 보고하려면 애플리케이션 이름을 세미콜론으로 구분합니다. 예를 들어, <DNT>**My Application**</DNT>과 <DNT>**My Application 2**</DNT> 에 데이터를 보고하려면 다음을 사용합니다:

```yml
app_name: My Application;My Application 2
```

애플리케이션 이름을 지정하는 더 많은 방법은 [Java 애플리케이션 이름 지정을 참조하세요](/docs/agents/java-agent/configuration/name-your-java-application) .
</Collapser>

동일한 시스템의 동일한 앱에 대한 JVM을 구별하기 위한 번호입니다. New Relic [은 고유성을 위해 호스트/포트를 사용](/docs/agents/java-agent/configuration/hostname-logic-java#unique-identifier) 하므로 각 JVM의 시작 인수에 다음과 같은 스위치를 넣어 JVM을 구별할 수 있습니다.

```ini
-Dnewrelic.config.appserver_port=8081
```

`appserver_port` 을 사용하여 JVM의 이름을 지정하고 다시 시작하면 드롭다운 및 프로파일링 인터페이스에서 개별적으로 볼 수 있어야 합니다.

<Callout variant="important">
이것은 New Relic의 변경 사항일 뿐입니다. 호스트가 어떤 식으로든 통신하는 포트에는 실제로 영향을 미치지 않습니다.
</Callout>

</Callout>

## 환경 변수 [#Environment_Variables]

환경 변수가 가장 높은 우선 순위를 가지며 시스템 속성 및 yml 구성 설정을 재정의합니다.

* 환경 변수를 설정하려면 `export VARNAME=value` 명령을 사용합니다.
* 환경 변수를 영구적으로 설정하려면 내보내기 행을 `~/.bashrc` 또는 `~/.bash_profile` 과 같은 파일에 추가하십시오.

환경 변수를 설정하여 시스템 속성 또는 `newrelic.yml` 의 모든 설정을 재정의할 수 있습니다. 구성 파일의 지정된 설정에 해당하는 환경 변수는 모든 점( `.` ) 및 대시( `-` )가 밑줄( `_` )로 대체된 `NEW_RELIC` 접두사가 붙은 설정 이름입니다. 예를 들어, `log_level` 설정에 대한 환경 변수는 `NEW_RELIC_LOG_LEVEL` 입니다.

섹션에 중첩된 설정의 경우 섹션 이름을 설정 이름 앞에 추가합니다. 예:

```yml
class_transformer:
  com.newrelic.instrumentation.kafka-clients-spans-0.11.0.0:
    enabled: true
```

위의 구성은 다음과 같은 환경 변수로 변환됩니다. `NEW_RELIC_CLASS_TRANSFORMER_COM_NEWRELIC_INSTRUMENTATION_KAFKA_CLIENTS_SPANS_0_11_0_0_ENABLED`

<Callout variant="important">
환경 변수를 통한 에이전트 구성에는 [Java 에이전트 버전 4.10.0 이상](/docs/agents/java-agent/installation/upgrade-java-agent) 이 필요합니다.
</Callout>

## 시스템 속성 [#System_Properties]

시스템 속성을 설정하여 `newrelic.yml` 파일의 모든 설정을 재정의할 수 있습니다. 구성 파일의 지정된 설정에 해당하는 시스템 속성은 `newrelic.config` 접두사가 붙은 설정 이름입니다. 예를 들어, `log_level` 설정의 시스템 속성은 `newrelic.config.log_level` 입니다.

섹션에 중첩된 설정의 경우 섹션 이름을 설정 이름 앞에 추가합니다. 예를 들어 transaction\_tracer 섹션의 `enabled` 설정에 대한 시스템 속성은 `newrelic.config.transaction_tracer.enabled`입니다.

설정을 재정의하는 것 외에도 에이전트는 이러한 시스템 속성을 인식합니다:
