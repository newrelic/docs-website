JFR 설정은 지속적인 JVM 성능 모니터링을 위해 자바 Flight Recorder 기반 실시간 프로파일링을 구성합니다.

<Callout variant="tip">
전체 설정 인덱스로 돌아가기: [자바 에이전트 설정](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## JFR(실시간 프로파일링)

Java 에이전트는 JFR(Java Flight Recorder)을 사용하여 [실시간 프로파일링](/docs/agents/java-agent/features/real-time-profiling-java-using-jfr-metrics/) 을 위해 충실도가 높은 JVM 데이터를 수집합니다.

에이전트 YAML의 `jfr` 섹션에서 실시간 프로파일링을 설정합니다. 이 설정 옵션은 `newrelic.config.jfr.`로 시작하는 [시스템 속성](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties)이나 `NEW_RELIC_JFR_`로 시작하는 [환경 변수](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#Environment_Variables)로 재정의할 수 있습니다.

[JFR을 사용한 실시간 프로파일링](/docs/agents/java-agent/features/real-time-profiling-java-using-jfr-metrics/)을 활성화하려면 `true`로 설정합니다. 이 설정은 동적으로 적용되며 JVM을 다시 시작할 필요가 없습니다.

<Callout variant="important">
JFR을 사용한 실시간 프로파일링은 Java 에이전트 [버전 7.1.0](/docs/release-notes/agent-release-notes/java-release-notes) 에서 기본적으로 켜져 있습니다. 다른 에이전트 버전 7.0.0 이상을 사용 중인 경우 값을 `true` 으로 변경하여 JFR을 켤 수 있습니다.
</Callout>
</Collapser>

에이전트의 메모리 대기열에 저장되는 JFR 이벤트의 최대 수입니다. 이 값을 늘리면 JFR 데이터의 차이를 방지하는 데 도움이 되지만 에이전트의 리소스 소비도 늘어납니다. 대기열이 너무 크면 백앤드 파이프라인 제한을 초과했을 때 데이터가 삭제될 수 있습니다. 자세한 내용은 [이벤트 API 인제스트 한도](/docs/data-apis/ingest-apis/event-api/introduction-event-api/#limits)를 참조하십시오.

<Callout variant="important">
이는 Java 에이전트 [버전 8.17.0 이상](/docs/release-notes/agent-release-notes/java-release-notes)에 적용됩니다.
</Callout>
