## 회로 차단기

이러한 설정은 [Java 회로 차단기](/docs/agents/java-agent/custom-instrumentation/circuit-breaker-java-custom-instrumentation) 의 동작을 사용자 정의합니다. 이러한 설정은 기본적으로 `newrelic.yml` 에 포함되지 않습니다. JVM을 변경한 후에는 JVM을 다시 시작할 필요가 없습니다.

서킷 브레이커를 맞춤화하려면 `common` 섹션 아래에 이를 추가합니다.

```yml
common: &default_settings​
  OTHER_CONFIG_SETTINGS
  circuitbreaker:
    enabled: true
    memory_threshold: 20
    gc_cpu_threshold: 10
```

## 클라우드 설정

에이전트 YAML의 `cloud` 섹션에서 클라우드 관련 옵션을 설정합니다. `newrelic.config.cloud` 접두사가 붙은 [시스템 속성](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#System_Properties)이나 `NEW_RELIC_CLOUD_` 접두사가 붙은 [환경 변수](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Environment_Variables)를 사용해 이 설정을 재정의할 수 있습니다.

설정 예시:

```yml
cloud:
  aws:
    account_id: 123456789012
  metadata_bypass_proxy: false
```

AWS DynamoDB와 Kinesis가 `cloud.resource_id` 속성을 채우기 위해 이 값이 필요한 서비스입니다. AWS Lambda에서는 계정 ID가 함수 이름에 포함되지 않은 경우 이 값이 필요합니다.

다음 호출은 이 설정을 재정의합니다:

```java
NewRelic.getAgent().getCloud().setAccountInfo(CloudAccountInfo.AWS_ACCOUNT_ID, "...");
```

## 맞춤 이벤트 [#Custom_Events]

`custom_insights_events` 섹션에서 커스텀 대시보드 설정을 합니다. `newrelic.config.custom_insights_events` 접두사가 붙은 시스템 속성을 사용하여 이러한 설정을 [재정의](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) 할 수 있습니다.

APM을 사용하면 New Relic 언어 에이전트 API를 통해 [사용자 지정 이벤트 데이터를 기록](/docs/insights/insights-data-sources/custom-data/insert-custom-events-new-relic-apm-agents) [할 수 있습니다](/docs/query-your-data/explore-query-data/explore-data/introduction-querying-new-relic-data) .

<Callout variant="important">
4.1.0 이전 Java 에이전트 버전의 경우 다음 YAML 구성이 인식됩니다.

```yml
custom_insights_events.enabled: true
  custom_insights_events.max_samples_stored: 5000
```

에이전트 버전 4.1.0 이상에서는 YAML 구성이 중첩 섹션 형식을 사용합니다.

```yml
custom_insights_events:
  enabled: false
  max_samples_stored: 5000
```
</Callout>

## 애플리케이션 건너뛰기 [#skip-applications]

에이전트는 명령줄에서 추출된 실행 가능한 jar 파일이나 시작 메인 클래스에 기반해 선택적으로 활성화 또는 비활성화될 수 있습니다. 이 기능은 &quot;JAVA\_TOOL\_OPTIONS&quot; 환경 변수가 존재하고 -javaagent 플래그를 포함하고 있지만 환경의 모든 Java 앱에 계측을 적용하고 싶지 않은 상황(예: 쿠버네티스 컨테이너)에서 유용합니다.

<Callout variant="important">
에이전트 수명 주기의 초반에 건너뛰기 설정을 확인해야 하기 때문에 skip(건너뛰기) 설정은 시스템 속성 또는 환경 변수를 통해서만 지원됩니다.
</Callout>

진단 목적으로 제외 또는 포함 설정 변수가 정의된 경우, 에이전트는 추출된 명령줄과 구문 분석된 건너뛰기 토큰을 stdout으로 출력합니다.

```
New Relic Agent: New Relic Agent: Configured startup Java artifacts [include|skip] string: keytool,Main
New Relic Agent: Retrieved current startup command line / main artifact name: /Users/bob/.sdkman/candidates/java/11.0.17-amzn/bin/keytool
```

포함 또는 건너뛰기 설정 변수에 기반해 에이전트가 비활성화된 경우 다음 내용이 stdout으로 출력됩니다.

```
----------
New Relic Agent is disabled by startup class/jar skip or include configuration.
----------
```

## 임시 Jar 파일 제거 [#temporary-jar-file-removal]

일부 고객 환경에서는 에이전트 임시 JAR 파일이 JVM 종료 시 삭제되도록 표시되어 있음에도 불구하고 제대로 정리되지 않는 문제가 발생합니다. 이는 JVM이 비정상적으로 종료되었기 때문일 가능성이 높습니다. 이 설정은 에이전트가 시작될 때 지정된 값보다 오래된 임시 에이전트 JAR 파일을 삭제하도록 합니다.

<Callout variant="important">
에이전트 수명 주기의 초반에 파일 삭제가 이루어져야 하기 때문에 이 설정은 시스템 속성 또는 환경 변수를 통해서만 지원됩니다.
</Callout>

진단 목적으로 이 기능이 활성화된 경우 콘솔에 다음 내용이 기록됩니다:

```
New Relic Agent: Removing stale temporary agent file jars from [temporaryFolder] older than [X] hour(s)
```

파일이 삭제되면 콘솔에 다음 내용이 기록됩니다:

```
New Relic Agent: Deleted [count] stale temporary jar files freeing up [totalBytes] bytes
```
