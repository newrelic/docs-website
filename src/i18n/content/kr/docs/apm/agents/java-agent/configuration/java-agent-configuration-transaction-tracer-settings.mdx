트랜잭션 트레이서 설정은 에이전트가 느린 트랜잭션, 트랜잭션 이벤트 및 메시지 추적에 대한 상세 정보를 캡처하는 방법을 제어합니다.

<Callout variant="tip">
전체 설정 인덱스로 돌아가기: [자바 에이전트 설정](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## 트랜잭션 추적기

`transaction_tracer` 섹션에서 트랜잭션 트레이서 옵션을 설정합니다. 이러한 옵션은 `newrelic.config.transaction_tracer` 접두어가 붙은 시스템 속성으로 [재정의](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) 할 수 있습니다.

[트랜잭션 추적](/docs/traces/transaction-traces) 은 느린 트랜잭션에 대한 심층 정보를 캡처하고 이를 New Relic 서비스로 보냅니다. 트랜잭션에는 발행된 쿼리 문을 포함하여 트랜잭션의 정확한 호출 순서가 포함됩니다.

<Callout variant="important">
거래 이름 끝에 대괄호 `[suffix]` 를 사용하지 마십시오. New Relic은 자동으로 이름에서 괄호를 제거합니다. 대신 필요한 경우 괄호 `(suffix)` 또는 기타 기호를 사용하십시오.
</Callout>

이 설정을 사용하여 다양한 트랜잭션 추적을 제어합니다. `top_n` 은 추적이 생성될 고유하고 느린 트랜잭션의 수를 나타내는 정수입니다.

* 트랜잭션 추적이 앱에서 가장 느린 실제 트랜잭션을 보다 정확하게 반영하려면 이 값을 **더 낮게** 설정하십시오.

* 더 다양한 트랜잭션 배열을 샘플링하려면 값을 **더 높게** 설정하십시오.

  값이 `0`이면 가장 느린 트랜잭션 **만** 항상 추적됩니다. 항상 가장 느린 하나 또는 두 개의 트랜잭션이 있을 수 있고 동일한 트랜잭션 트레이스를 반복적으로 보는 것은 아마도 많은 가치를 제공하지 못할 것이기 때문에 이는 최적이 아닌 것으로 간주됩니다.

  동일한 트랜잭션이 가장 느린 경우가 많으면 `top_n` 설정을 통해 시간 경과에 따라 Java 에이전트가 가장 느린 `n` 트랜잭션을 샘플링할 수 있습니다. 이를 통해 애플리케이션에 대한 더 많은 다양성과 더 많은 통찰력을 얻을 수 있습니다.
</Collapser>

DataStax 드라이버 2.1.2의 경우 다음 규칙을 허용 목록에 추가합니다.

```yml
transaction_tracer:
  slow_query_whitelist:
    'com.newrelic.instrumentation.cassandra-datastax-2.1.2'
```

DataStax 드라이버 3.0.0의 경우 다음 규칙을 허용 목록에 추가합니다.

```yml
transaction_tracer:
  slow_query_whitelist:
    'com.newrelic.instrumentation.cassandra-datastax-3.0.0'
```

`transaction_events` 섹션에서 트랜잭션 이벤트 옵션을 설정하십시오. 이러한 옵션은 `newrelic.config.transaction_events` 접두어가 붙은 시스템 속성으로 [재정의](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) 할 수 있습니다.

트랜잭션 이벤트 데이터는 UI에 히스토그램과 백분위수를 표시하는 데 사용됩니다.

<Callout variant="important">
이전에는 이 섹션을 `analytics_events`라고 했습니다. 구성 파일이 여전히 `analytics_events`를 사용하는 경우 `transaction_events`를 사용하도록 에이전트를 업데이트하십시오.
</Callout>

<Callout variant="important">
다른 설정과 달리 `custom_request_headers` 는 함께 쌍을 이루어야 하며 `newrelic.yml` 파일에서 설정해야 합니다. Java 가상 머신 인수(시스템 속성) 또는 환경 변수로 덮어쓸 수 없습니다.
</Callout>

쌍을 이룬 키 `header_name` 및 옵션 `header_alias`가 포함된 맵 목록입니다. 하나 이상의 커스텀 HTTP 요청 헤더를 선택하여 트랜잭션 속성으로 추가합니다.

여러 헤더 구성을 나열할 수 있습니다.

```yml
transaction_events:
  custom_request_headers:
    -
      header_name: "X-Custom-Header-1"
    -
      header_name: "X-Custom-Header-2"
      header_alias: "CustomHeader2alias"
```

첫 번째 맵 세트에서 `X-Custom-Header-1` 은 요청 객체의 해당 값에 대한 헤더 이름으로 에이전트에 의해 캡처되고 보고됩니다. `header_name` 은 또한 New Relic에 전송된 속성의 이름입니다.

두 번째 맵 세트에서 요청 헤더는 `X-Custom-Header-2` 이지만 `CustomHeader2alias` 은 New Relic으로 전송된 이름입니다.
</Collapser>

## 거래 세그먼트

`transaction_segments` 섹션에서 트랜잭션 세그먼트 옵션을 설정합니다. 이러한 옵션은 `newrelic.config.transaction_segments` 접두어가 붙은 시스템 속성으로 [재정의](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) 할 수 있습니다.

트랜잭션 세그먼트는 개별 작업(일반적으로 메서드 호출)을 나타내며 [트랜잭션 추적](/docs/traces/transaction-traces) 내에 표시됩니다.

<Callout variant="important">
트랜잭션 세그먼트 속성 필터링을 사용하려면 [Java 에이전트 버전 4.10.0 이상](/docs/agents/java-agent/installation/upgrade-java-agent) 이 필요합니다.
</Callout>
