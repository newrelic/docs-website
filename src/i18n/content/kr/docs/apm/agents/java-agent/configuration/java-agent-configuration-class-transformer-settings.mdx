클래스 트랜스포머 설정은 활성화되는 내장 계측 모듈과 로드 시 에이전트가 클래스를 변환하는 방법을 제어합니다.

<Callout variant="tip">
전체 설정 인덱스로 돌아가기: [자바 에이전트 설정](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## 클래스 트랜스포머 [#Class_Transformer]

`class_transformer` 섹션에서 계측 관련 설정을 할 수 있습니다. `newrelic.config.class_transformer` 접두사가 붙은 [시스템 속성](#System_Properties) 이나 `NEW_RELIC_CLASS_TRANSFORMER_` 접두사가 붙은 [환경 변수](#Environment_Variables)를 사용해 이러한 설정을 재정의할 수 있습니다.

향상된 Spring 트랜잭션 이름 지정이 활성화되면 정의된 경로 및 HTTP 메서드 다음에 Spring 컨트롤러에서 발생하는 모든 트랜잭션의 이름이 지정됩니다. 예: `/customer/v1/edit (POST)`. 여기에는 WebMVC 관련 주석(`@RestController`, `@Controller`, `@RequestMapping` 등)을 사용하여 인터페이스/클래스를 구현하거나 확장하는 컨트롤러가 포함됩니다.

기본적으로 이는 `false`로 설정되며, 컨트롤러 클래스 이름과 메서드를 기반으로 해당 컨트롤러 유형에 대한 트랜잭션 이름이 지정됩니다. 예: `CustomerController/edit` 이는 이전 에이전트 버전에서 가져온 명명 로직입니다. 실제 클래스에 모든 관련 주석이 있는 &quot;표준&quot; 컨트롤러는 여전히 경로 및 HTTP 메서드를 기반으로 이름이 지정됩니다.

이 구성은 자바 에이전트 버전 8.9.0 이상에 존재합니다.
</Collapser>

활성화된 경우, 모든 Spring Controller 트랜잭션은 요청 매핑(예: `/api/v1/customer (POST)`)을 사용하는 대신 컨트롤러 클래스 이름과 메서드 이름(예: `/CustomerController/edit`)을 사용하여 이름이 지정됩니다.

이 설정은 `enhanced_spring_transaction_naming`보다 우선하며 복잡한 URI 패턴에서 트랜잭션 이름 카디널리티 문제를 방지하는 데 도움이 됩니다.

Applies to Spring 4.3.x+ (spring-4.3.0 모듈) 및 Spring 6.x+(spring-6.0.0 모듈)에 적용됩니다.

이 구성은 Java 에이전트 버전 8.25.0 이상에 존재합니다.
</Collapser>

기본적으로 내장된 액추에이터 엔드포인트와 커스텀 액추에이터 엔드포인트( `@endpoint` 주석 및 해당 서브클래스 사용)는 모두 뉴렐릭에서 이름이 `OperationHandler/handle`로 지정됩니다. 이 설정을 활성화하면 실제 베이스 액츄에이터 엔드포인트 URI를 반영해 프로세서 이름이 생성됩니다. 예를 들어, `/actuator/loggers` 또는 `actuator/loggers/com.newrelic`을 호출하면 트랜잭션 이름이 `actuator/loggers (GET)`가 됩니다. 이는 MGI를 방지하기 위함입니다.

Spring Boot v3 이상을 사용할 때 지원됩니다.

이 구성은 자바 에이전트 버전 8.15.0 이상에 존재합니다.
</Collapser>

## 수단

이러한 옵션은 `instrumentation` 스탠자에 설정되며 `newrelic.config.instrumentation` 접두사가 붙은 시스템 속성을 사용하여 재정의할 수 있습니다.

기본적으로 [@TraceLambda](/docs/apm/agents/java-agent/api-guides/java-agent-api-instrument-using-annotation/#tracelambda) 어노테이션은 비활성화되어 있습니다. 람다 메서드 추적을 위한 어노테이션 기능을 사용하려면 다음과 같이 해당 기능을 명시적으로 활성화해야 합니다:

YAML을 통해 이를 구성할 수 있습니다.

```yml
instrumentation:
  trace_lambda:
    enabled: true
```

시스템 속성 `newrelic.config.instrumentation.trace_lambda.enabled=true` 또는 환경 변수 `NEW_RELIC_INSTRUMENTATION_TRACE_LAMBDA_ENABLED` 를 사용할 수도 있습니다.
