분산 추적 설정은 에이전트가 서비스 간에 트레이스 컨텍스트를 전파하는 방법을 제어하고, 스팬 이벤트 수집을 구성하며, Infinite Tracing을 활성화합니다.

<Callout variant="tip">
전체 설정 인덱스로 돌아가기: [자바 에이전트 설정](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## 분산 추적 [#dt-main]

<Callout variant="important">
분산 추적을 활성화하면 [교차 애플리케이션 추적](#Cross_Application_Tracer) 이 비활성화되고 APM 기능에 다른 영향을 미칩니다. 활성화하기 전에 [전환 가이드](/docs/transition-guide-distributed-tracing) 를 읽으십시오.

[Java 에이전트 버전 4.3.0 이상이](/docs/agents/java-agent/installation/upgrade-java-agent) 필요합니다.
</Callout>

[분산 추적](/docs/understand-dependencies/distributed-tracing/get-started/introduction-distributed-tracing)은 분산 시스템을 통해 이동하는 요청의 경로를 볼 수 있도록 해줍니다. 이 기능은 Java 에이전트 버전 7.4.0 이상에서 기본적으로 활성화되어 있습니다.

구성 파일의 `distributed_tracing` 섹션에서 이를 수동으로 재정의할 수 있습니다. 접두사가 붙은 시스템 속성(`newrelic.config.distributed_tracing`) 또는 환경 변수(`NEW_RELIC_DISTRIBUTED_TRACING_ENABLED`)를 사용하여 이를 재정의할 수도 있습니다. 아래 예를 참조하십시오.

분산 추적 설정에 대한 보다 자세한 정보는 [Java 애플리케이션에 대한 분산 추적 사용](/docs/apm/agents/go-agent/instrumentation/distributed-tracing-go-agent)을 참조하십시오.

분산 추적을 비활성화하려면 이 옵션을 `false`로 설정합니다. 예를 들어 구성 파일에서 다음을 사용할 수 있습니다.

```yml
distributed_tracing:
  enabled: false
```

분산 추적을 비활성화하는 다른 옵션은 다음과 같습니다.

[시스템 속성](/docs/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties):

```ini
-Dnewrelic.config.distributed_tracing.enabled=false
```

환경 변수:

```ini
NEW_RELIC_DISTRIBUTED_TRACING_ENABLED=false
```

기본적으로 지원되는 에이전트 버전은 분산 추적을 위해 `newrelic` 헤더와 W3C 추적 컨텍스트 헤더를 모두 사용합니다. `newrelic` 분산 추적 헤더는 W3C 추적 컨텍스트 헤더를 지원하지 않는 이전 에이전트와의 상호 운용성을 허용합니다. W3C 추적 컨텍스트 헤더를 지원하는 에이전트 버전은 분산 추적을 위해 `newrelic` 헤더보다 우선합니다.

`newrelic` 헤더를 사용하지 않으려는 경우 이를 `true` 로 설정하면 에이전트가 `newrelic` 헤더를 제외하고 분산 추적에 W3C Trace Context 헤더만 사용하게 됩니다.

예를 들어 구성 파일에서 `newrelic` 헤더를 제외하려면 다음을 사용합니다.

```yml
distributed_tracing:
  exclude_newrelic_header: true
```

[시스템 속성](/docs/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) 을 사용하여 `newrelic` 헤더를 제외하려면 다음을 사용합니다.

```ini
-Dnewrelic.config.distributed_tracing.exclude_newrelic_header=true
```

`root`, `remote_parent_sampled` 및 `remote_parent_not_sampled` 컨텍스트가 공유하는 전역 적응형 샘플링 타겟을 설정합니다. 이 타겟은 [적응형 샘플러](/docs/apm/distributed-tracing/distributed-trace-sampling#adaptive-sampler)가 캡처하려고 시도하는 분당 트레이스 수를 제어합니다. 컨텍스트는 자체 컨텍스트별 `adaptive.sampling_target`을(를) 사용하여 이 전역 기본값을 재정의할 수 있습니다.

```yaml
distributed_tracing:
  sampler:
    adaptive_sampling_target: 30  # Applied to all contexts without an explicit override
```

자세한 내용은 [샘플링 구성: 적응형 샘플링 타겟](/docs/apm/distributed-tracing/distributed-trace-sampling#adaptive-targets)을 참조하십시오.

[루트 컨텍스트](/docs/apm/distributed-tracing/distributed-trace-sampling#root-context) (현재 서비스에서 시작된 분산 트레이스)에 사용되는 샘플러를 구성합니다. 가능한 값은 다음과 같습니다.

* `adaptive`: 뉴렐릭의 기본 [적응형 샘플러](/docs/apm/distributed-tracing/distributed-trace-sampling#adaptive-sampler)를 사용하십시오.
  * 선택 파라미터: [`sampler.root.adaptive.sampling_target`](#dt-sampler-root-adaptive-sampling_target)
* `trace_id_ratio_based`: [트레이스 ID를 기반으로](/docs/apm/distributed-tracing/distributed-trace-sampling#trace-id-ratio-based-sampler) 고정된 비율의 트레이스를 샘플링하십시오
  * 필수 파라미터: [`sampler.root.trace_id_ratio_based.ratio`](#dt-sampler-root-trace_id_ratio_based-ratio)
* `always_on`: 모든 루트 트레이스를 샘플링합니다.
* `always_off`: 루트 트레이스를 샘플링하지 않습니다.

```yaml
distributed_tracing:
  sampler:
    root: adaptive
```

`root` 컨텍스트에 대해서만 전역 [`adaptive_sampling_target`](#dt-sampler-adaptive_sampling_target)을(를) 재정의하여 적응형 샘플러가 캡처하려고 시도하는 분당 루트 트레이스 수를 설정합니다.

```yaml
distributed_tracing:
  sampler:
    adaptive_sampling_target: 120  # Global default
    root:
      adaptive:
        sampling_target: 5  # Overrides global default to capture 5 traces/min for the root context
```

업스트림의 &quot;샘플링되지 않음&quot; 결정을 재정의하면 일부 서비스만 존재하는 단편화된 트레이스가 생성될 수 있습니다. 업스트림에서 샘플링하지 않은 경우에도 다운스트림 서비스의 활동을 확인해야 하는 특정 요구 사항이 있는 경우에만 이 패턴을 사용하십시오.
</Callout>
</Collapser>
</CollapserGroup>
</Collapser>
</CollapserGroup>

이러한 샘플러의 작동 방식, 적응형 샘플링 타겟 및 샘플링 컨텍스트에 대한 자세한 내용은 [샘플링 설정](/docs/apm/distributed-tracing/distributed-trace-sampling)을 참조하십시오. 실제 설정 시나리오는 [샘플러 설정 예시](/docs/apm/distributed-tracing/sampler-configuration-examples)를 참조하십시오.

## 교차 애플리케이션 추적기 [#Cross_Application_Tracer]

<Callout variant="important">
교차 애플리케이션 추적은 에이전트 버전 7.4.0부터 더 이상 사용되지 않으며 향후 에이전트 버전에서 제거될 예정입니다.

교차 애플리케이션 추적을 사용하는 대신 [분산 추적](#distributed-tracing) 기능을 사용하는 것이 좋습니다. 분산 추적은 애플리케이션 간 추적 기능을 개선한 것으로 대규모 분산 시스템에 권장됩니다.
</Callout>

`cross_application_tracer` 섹션에서 크로스 애플리케이션 추적 옵션을 설정합니다. 이러한 설정은 `newrelic.config.cross_application_tracer` 접두어가 붙은 시스템 속성으로 [재정의](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) 할 수 있습니다.

[애플리케이션 간 추적(Cross application tracing)](/docs/apm/transactions/cross-application-traces/cross-application-tracing)은 Apache HttpClient 라이브러리를 사용해 외부 호출에 요청 및 응답 헤더를 추가합니다. 이는 다른 뉴렐릭 에이전트가 모니터링하는 애플리케이션을 호출할 때 더 나은 성능 데이터를 제공합니다.
