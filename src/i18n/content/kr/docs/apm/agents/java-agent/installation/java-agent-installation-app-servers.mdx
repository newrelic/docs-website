이 페이지에서는 지원되는 모든 앱 서버 또는 JVM 기반 프레임워크에서 뉴렐릭 Java 에이전트를 설치하는 표준 경로를 다룹니다. 다음 단계에 따라 에이전트를 다운로드하고 설정하고 데이터가 뉴렐릭으로 전송되는지 확인할 수 있습니다.

## 호환성 및 요구사항 [#requirements]

### 지원

* Java 8, 11, 17, 21, 24, 25, 26 *(Java 7은 에이전트 v6.5.4 및 이전 버전에서만 지원)*
* JVM 기반 언어: Java, Scala, Kotlin, Clojure
* 앱 서버 및 프레임워크: Tomcat, Spring Boot, JBoss/WildFly, Glassfish, Jetty, WebLogic, WebSphere, Grails, ColdFusion, Solr, Play, Resin, Tanuki Wrapper, Geronimo — 지원되는 버전 범위는 [호환성 및 요구 사항](/docs/apm/agents/java-agent/getting-started/compatibility-requirements-java-agent) 참조
* `-javaagent` 인수를 허용하는 모든 JVM 프로세스

### 지원되지 않음

* 다른 APM 에이전트와 함께 실행 — 동일한 JVM에서 다른 APM 에이전트가 활성화되어 있는 경우 Java 에이전트는 올바른 동작을 보장할 수 없습니다.

### 필요한 사항

* 뉴렐릭 계정<InlinePopover type="licenseKey" />
* SHA-2(256비트) SSL을 지원하는 JVM
* 앱 서버의 시작 스크립트 또는 JVM 설정을 수정할 수 있는 권한
* 에이전트 파일을 보관할 디렉터리를 생성할 수 있는 권한

## 설치 [#install]

<Steps>
  <Step>
    ### Java 에이전트 다운로드 [#install-step-1]

    다음 방법 중 하나를 사용하여 `newrelic-java.zip`을 다운로드합니다.

    <Tabs>
      <TabsBar>
        <TabsBarItem id="curl">curl</TabsBarItem> <TabsBarItem id="powershell">PowerShell</TabsBarItem> <TabsBarItem id="web">Web</TabsBarItem>
      </TabsBar>

      <TabsPages>
        <TabsPageItem id="curl">
          ```bash
          curl -O https://download.newrelic.com/newrelic/java-agent/newrelic-agent/current/newrelic-java.zip
          unzip newrelic-java.zip
          ```
        </TabsPageItem>

        <TabsPageItem id="powershell">
          ```powershell
          Invoke-WebRequest -Uri https://download.newrelic.com/newrelic/java-agent/newrelic-agent/current/newrelic-java.zip -OutFile newrelic-java.zip
          Expand-Archive -Path newrelic-java.zip -DestinationPath .
          ```
        </TabsPageItem>

        <TabsPageItem id="web">
          [Java 에이전트 릴리스 노트](/docs/release-notes/agent-release-notes/java-release-notes/) 페이지에서 `newrelic-java.zip`을 다운로드합니다.
        </TabsPageItem>
      </TabsPages>
    </Tabs>

    압축을 해제하면 `newrelic/` 디렉터리에 다음 단계에서 설정할 에이전트 jar(`newrelic.jar`)와 설정 파일(`newrelic.yml`)이 포함되어 있습니다.
  </Step>

  <Step>
    ### 에이전트 파일 배치 [#install-step-2]

    영구 디렉터리를 생성하고 에이전트 파일을 해당 디렉터리로 이동합니다.

    ```bash
    mkdir -p /opt/newrelic
    mv newrelic/* /opt/newrelic/
    ```

    Linux/macOS에서는 `/opt/newrelic`을(를), Windows에서는 `C:\opt\newrelic`을 권장합니다. `newrelic.jar`가 애플리케이션 클래스 경로 또는 `java.endorsed.dirs`에 나열된 디렉터리에 **없도록** 해야 합니다.
  </Step>

  <Step>
    ### 전달 `-javaagent` [#install-step-3]

    앱 서버의 JVM 시작 설정에 `newrelic.jar`의 전체 경로를 가리키는 `-javaagent` 플래그를 추가합니다. 방법은 서버마다 다릅니다. 환경에 맞는 항목을 확장하시기 바랍니다.

    <CollapserGroup>
      <Collapser id="tomcat" title="Tomcat">
        Tomcat 설정에 맞는 방법을 선택합니다.

        <Tabs>
          <TabsBar>
            <TabsBarItem id="tomcat-setenvsh">setenv.sh (Linux/macOS)</TabsBarItem> <TabsBarItem id="tomcat-setenvbat">setenv.bat (Windows)</TabsBarItem> <TabsBarItem id="tomcat-windows-service">Windows service</TabsBarItem> <TabsBarItem id="tomcat-commons-daemon">Apache Commons Daemon</TabsBarItem>
          </TabsBar>

          <TabsPages>
            <TabsPageItem id="tomcat-setenvsh">
              `CATALINA_BASE/bin/setenv.sh`가 없으면 생성한 후 다음을 추가합니다.

              ```bash
              export CATALINA_OPTS="$CATALINA_OPTS -javaagent:/opt/newrelic/newrelic.jar"
              ```
            </TabsPageItem>

            <TabsPageItem id="tomcat-setenvbat">
              `CATALINA_BASE/bin/setenv.bat`가 없으면 생성한 후 다음을 추가합니다.

              ```batch
              SET "CATALINA_OPTS=%CATALINA_OPTS% -javaagent:C:\opt\newrelic\newrelic.jar"
              ```
            </TabsPageItem>

            <TabsPageItem id="tomcat-windows-service">
              1. **Start &gt; Apache Tomcat X.Y.Z &gt; Configure Tomcat &gt; Java**를 선택합니다.

              2. **Java 옵션** 텍스트 상자에 인수를 입력합니다. 경로 구분 기호로 사선 `/`를 사용합니다. Tomcat 6의 경우 `-javaagent` 인수 뒤에 줄 바꿈을 추가합니다.

                 ```
                 -javaagent:/opt/newrelic/newrelic.jar
                 ```

              3. **Apply**를 선택한 다음 Tomcat을 다시 시작합니다.
            </TabsPageItem>

            <TabsPageItem id="tomcat-commons-daemon">
              Tomcat 6에 번들로 제공되는 Apache Commons Daemon (jsvc) 버전은 `-javaagent` 인수를 지원하지 않습니다. 트렁크 소스의 빌드는 `-X` 접두사를 통해 이를 지원합니다. [Apache 버그 보고서](https://issues.apache.org/jira/browse/DAEMON-84) 및 [Apache Commons 소스 저장소](https://commons.apache.org/svninfo.html)를 참조하십시오.
            </TabsPageItem>
          </TabsPages>
        </Tabs>
      </Collapser>

      <Collapser id="spring-boot" title="Spring Boot">
        명령줄에서 `-jar` 인수 앞에 `-javaagent` 인수를 추가합니다.

        ```bash
        java -javaagent:/opt/newrelic/newrelic.jar -jar /path/to/your-application.jar
        ```
      </Collapser>

      <Collapser id="glassfish" title="Glassfish">
        1. Glassfish 관리 콘솔에서 **Application Server &gt; JVM Settings &gt; JVM Options**를 선택합니다.

        2. **Add JVM Option**을 선택하고 다음을 추가합니다.

           ```
           -javaagent:/opt/newrelic/newrelic.jar
           ```

        3. Glassfish를 저장하고 다시 시작합니다.

        *Glassfish가 시작되지 않으면 `-javaagent` 경로가 잘못되었을 수 있습니다. 또한 `domain.xml`을 직접 수정하여 JVM 인수를 설정할 수도 있습니다.*

        <Callout variant="important">
          Glassfish 2.1의 버그로 인해 부트스트랩 클래스 로더의 클래스는 Java 로깅 API를 사용하지 못합니다. 이는 2.1.1 이상에서 수정되었습니다.
        </Callout>
      </Collapser>

              매니지드 서버 인스턴스의 경우 관리 콘솔을 사용합니다.

              1. **Environments &gt; Servers &gt; (select a server) &gt; Server Start &gt; Arguments**로 이동합니다.

              2. 추가:

                 ```
                 -javaagent:/opt/newrelic/newrelic.jar
                 ```

              3. 서버 인스턴스를 저장하고 다시 시작합니다.

        <Tabs>
          <TabsBar>
            <TabsBarItem id="websphere-admin">WebSphere(관리 콘솔을 통해)</TabsBarItem> <TabsBarItem id="websphere-community">WebSphere Community</TabsBarItem> <TabsBarItem id="websphere-liberty">WebSphere Liberty Profile</TabsBarItem>

            <TabsPageItem id="websphere-admin">
              1. 관리 콘솔에서 **Servers &gt; Application servers &gt; (select a server) &gt; Configuration &gt; Service Infrastructure &gt; Java and Process Management**를 선택합니다.

              2. **Process Definition &gt; Additional Properties**로 이동한 후 **Java Virtual Machine**을 선택합니다.

              3. **Generic JVM arguments** 필드에 다음을 추가합니다.

                 ```
                 -javaagent:/opt/newrelic/newrelic.jar
                 ```

              4. **Apply**를 선택한 다음 **Save**를 선택합니다.

              5. 서버를 다시 시작합니다.

              보다 자세한 내용은 [WebSphere PMI 메트릭 수집](/docs/apm/agents/java-agent/features/jvm-metrics-page#default-pmi)을 참조하십시오.

              ```bash
              export JAVA_OPTS="$JAVA_OPTS -javaagent:/opt/newrelic/newrelic.jar" && startup
              ```
            </TabsPageItem>

            <TabsPageItem id="websphere-liberty">
              1. `${server.config.dir}/jvm.options`를 수정합니다.

              2. 추가:

                 ```
                 -javaagent:/opt/newrelic/newrelic.jar
                 ```

              3. 서버를 다시 시작합니다.
            </TabsPageItem>

        1. ColdFusion 서버를 시작하고 ColdFusion 관리 콘솔을 엽니다.

        4. **JVM Arguments** 필드에 다음을 추가합니다.

           ```
           -javaagent:/opt/newrelic/newrelic.jar
           ```

        5. **Submit Changes**를 선택한 다음 ColdFusion을 다시 시작합니다.

## 설정 [#configure]

`newrelic/newrelic.yml`을 수정하고 다음 두 가지 필수 값을 설정합니다.

```yaml
license_key: 'YOUR_LICENSE_KEY'
app_name: 'My Application'
```

에이전트는 시작 시 `newrelic.jar`과(와) 동일한 디렉터리에서 `newrelic.yml`을(를) 읽습니다. 또한 Java 시스템 속성(예: `-Dnewrelic.config.license_key=YOUR_KEY`) 또는 환경 변수를 사용하여 모든 설정을 재정의할 수 있습니다.

설정 파일을 사용할 때, 애플리케이션 서버 프로세스의 소유자에게만 읽기/쓰기 권한을 제한합니다.

```bash
chmod 600 /opt/newrelic/newrelic.yml
```

사용 가능한 모든 옵션은 [Java 에이전트 설정](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)을 참조하십시오.

## 설치 확인 [#verify]

애플리케이션 서버를 다시 시작합니다. 최소 2개의 요청을 보낸 다음 2-3분 기다리면 [APM &amp; services](https://one.newrelic.com/nr1-core?filters=%28domain%20IN%20%28%27APM%27%2C%20%27EXT%27%29%20AND%20type%20IN%20%28%27APPLICATION%27%2C%20%27SERVICE%27%29%29)에 앱이 표시됩니다.

5분 후에도 데이터가 나타나지 않으면 [데이터가 표시되지 않음(Java)](/docs/apm/agents/java-agent/troubleshooting/no-data-appears-java)을 참조하십시오.
