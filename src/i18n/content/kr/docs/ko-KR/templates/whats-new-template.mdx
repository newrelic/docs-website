뉴렐릭 직원으로서 고객에게 새로운 기능에 대해 공지하고자 하는 경우, `What's new`을(를) 사용하는 것도 한 가지 방법입니다. 이는 주요 기능에 대한 시의적절하고 높은 수준의 공지를 신중하게 선별한 채널입니다.

`What's new` 게시물은 블로그 게시물 및 커뮤니티 포럼에서 릴리스 노트와 기술 제품 심층 분석을 보완합니다. 게시물은 [뉴렐릭 UI](https://onenr.io/0Zyw4MX1MR3) (확성기 아이콘 뒤)와 [문서 사이트](/whats-new/)에 표시됩니다.

게시물이 게시되는 과정은 1-3일이 소요되며 다음과 같습니다:

1. 문서 웹사이트에 `What's new` pull 요청(PR)을 제출합니다.
2. 해당하는 경우 PMM과 상의하여 게시물 콘텐츠를 검토하십시오.
3. 기술 문서 팀에서 최종 검토 및 게시를 담당합니다.

## 시작하기 전에 [#before-you-start]

원활한 프로세스를 보장하기 위한 몇 가지 팁은 다음과 같습니다:

* 이 지침은 [VS Code](https://code.visualstudio.com/)를 참조하지만, 원하는 텍스트 편집기를 사용할 수 있습니다.
* 아직 계정이 없다면 뉴렐릭 이메일 주소가 아닌 이메일 주소를 사용하여 개인 GitHub 계정(Enterprise GitHub용 아님)을 생성하십시오.
* 다음 지침은 GitHub UI에서 직접 이 작업의 대부분을 수행하는 방법을 알려주지만, Git에 익숙한 경우 명령줄, GitHub CLI, GitHub Desktop 또는 관련 도구를 사용하여 컴퓨터에서 변경 사항을 푸시할 수 있습니다.
* 게시물 콘텐츠의 형식을 지정하는 데 도움이 되는 자세한 템플릿이 아래에 포함되어 있습니다. 게시물 작성에 익숙해지면 이전 게시물을 재사용하고 세부 정보만 변경할 수 있습니다.

## 게시물을 위한 파일 준비 [#create-a-file]

`What's new` 게시물은 기능을 설명하는 마크다운 파일(`.md`)과 선택적 이미지 파일로 구성됩니다. 마크다운 파일과 이미지를 준비하는 방법은 다음과 같습니다:

1. VS Code에서 **File &gt; New File**을 클릭하여 새 파일을 만듭니다.

2. 아래의 샘플 템플릿을 복사하여 비어 있는 새 파일에 붙여넣으십시오.

   ```md
   ---
   title: 'Insert a title here'
   summary: 'Insert a brief description of the feature'
   releaseDate: 'yyyy-mm-dd'
   learnMoreLink: 'https://example.com'
   getStartedLink: 'https://example.com'
   ---

   ## Front matter tips (remove this section before publishing)

   The front matter is the group of lines at the top of the post before your content begins. The front matter is sandwiched between lines containing three dashes. Here's what you need to know about each front matter line:

   * `title` (required): The title field is how your readers will browse through `What's new` and find what interests them. Make your titles as short as possible and include the most relevant product and feature names. The more specific you get, the more likely people will be to read the post. As with other pages on the site, use sentence case for titles (Only one capital letter at the beginning of the title).
   * `summary` (required): A brief description of the feature that appears directly under the title in the left sidebar and at the top of the post. Make sure your summary is a single sentence and isn't more than about 10-20 words.
   * `releaseDate` (required): The date a feature is released. `What's new` posts are organized chronologically. This controls where a post will show on the list. If you have two or more posts on the same date, use the time field to control the post order.
   * `learnMoreLink` (optional): Learn more links are used to highlight blog posts or other marketing material that provides more information about the feature. Remove this if you are not using it!
   * `getStartedLink` (optional): This is a link to to documents that explain how to set up the feature. Remove this if you are not using it!
   * `isFeatured`: For tier one launches, you can insert `isFeatured: true` in the front matter to pin your post to the top of the product UI. The technical writers will remove this flag from the previously featured post-unless you need multiple pinned posts. 

   ## Word wrap (remove this section before publishing)

   If you're using VS Code and want to turn on text wrapping to make it easier to edit:

   * Windows: Ctrl + Shift + press the key `p`. Now on the command line, type Toggle Word Wrap and press Enter.
   * Mac: Command + Shift + press the key `p`. Now in the command line, type Toggle Word Wrap and press Enter.

   ## Heading format (remove this section before publishing)

   Headings are not required, but they are helpful if you need to divide the material into at least two sections. We don't recommend headings unless you use them in pairs.

   Headings are preceded by two hash symbols and a space. Use sentence case, which means only one capital letter at the beginning.

   ## Body format (remove this section before publishing)

   The body is all the copy after the front matter. It ranges from 150-400 words and is where you tell the story about your new feature. 

   TIP: If possible, include one or more screenshots or a video.

   The goal of the post is to inform people about the feature. Here are some questions to keep in mind:

   * What is the most important idea to communicate about this feature?
   * What problem does this feature solve?
   * How does it make using New Relic easier?
   * What's delightful about it?
   * Can you add a great, visually appealing screenshot or video?

   Don't include procedural how-to content. Use `getStartedLink` and `learnMoreLink` in the front matter to link to information about how to use the feature.

   ## Links (remove this section before publishing)

   [Lorem ipsum](https://example.com)-You can have spaces between words in square brackets but not in the link inside parentheses.

   WARNING: Remember to use absolute URLs in links (for example, always include the protocol followed by the domain: "https://whatever_domain/path-to-doc")-including references to the New Relic docs site.

   ## Videos (remove this section before publishing)

   Use embed code. The example below is an embedded YouTube video. You would replace the value for src with your link:

   <iframe width="560" height="315" src="https://www.youtube.com/embed/04JP0ky_hjI" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe>

   ## Images (remove this section before publishing)

   Note that you need to use image files you upload to the repository. You can't link to images hosted on other sites.

   Here's the image format:

   ![Insert some alternative text here describing the image](/images/INSERT_IMAGE_FILE_NAME.webp "Repeat the alternative text here as the title of the image")

   Example: !["Screenshot showing automap feature"](/images/automap.webp "Screenshot showing automap feature")

   You can add a caption to images with this HTML tag: <figcaption>Screenshot explaining the image</figcaption>.

   Remember to add your image(s) to `static/images/` folder in the Github pull request. 

   ## Bold format (remove this section before publishing)

   Use double asterisks to bold words for UI labels or simply for emphasis: **bold**

   ## Lists (remove this section before publishing)

   Use this format to create an ordered list (used for sequential steps):
   1. Step one
   2. Step two
   3. Step three

   Use this format to create bullet lists (used for non-sequential information):
   * Important detail
   * Important detail
   * Important detail
   ```

3. 템플릿 예제를 사본으로 교체하십시오. 완료되면 다음과 같은 완성된 게시물처럼 보일 수 있습니다:

   ```md
   ---
   title: 'Control data ingest costs with ingest drill-down'
   summary: 'Analyze the data that you send to New Relic'
   releaseDate: '2021-06-30'
   learnMoreLink: 'https://docs.newrelic.com/docs/telemetry-data-platform/manage-data/manage-data-coming-new-relic/#facet-data-ingest'
   getStartedLink: 'https://one.newrelic.com/-/0gbRKzygzwE'
   ---

   Inspect your data consumption in New Relic to better manage your data ingest and costs. Understand your data usage by each data source, and analyze it using your existing metadata, such as by source, team, and any other data sample attribute.

   To get started, go to the **Data management hub** and select the **Data ingestion chart**. Get detailed insights by data source by clicking on the colored data band at any point in time that you’re interested in. Add "facets" to analyze your data by selected attributes. [**Learn more**](https://docs.newrelic.com/docs/telemetry-data-platform/manage-data/manage-data-coming-new-relic/#facet-data-ingest) and [**get started**](https://one.newrelic.com/-/0gbRKzygzwE).

   ![To find your data ingest usage, click the user menu, click Manage your data, then click Data ingestion.](/images/ingest_drill_down_1_of_2.webp "A screenshot that shows how to find your data ingest consumption.")

   <figcaption>To find your data ingest consumption, click Manage your data, then click Data ingestion.</figcaption>

   ![Choose a specific data source to drill down into what's contributing the most to your data ingest consumption.](/images/ingest_drill_down_2_of_2.webp "A screenshot that shows the data ingest by data source dropdown.")

   <figcaption>Click the chart to see ingestion by data source.</figcaption>
   ```

4. 편리한 폴더에 파일을 저장하고 다음 형식으로 이름을 지정하십시오: `whats-new-MM-DD-descriptive-words.md`(예: `whats-new-5-28-in-context-alerting.md`).

5. Markdown 파일에서 참조하는 이미지를 `static/images/` 폴더에 저장합니다.

   * 이미지 파일을 사용하는 경우 저장소에 업로드한 파일이어야 합니다. 다른 사이트에서 호스팅되는 이미지에 링크할 수 없습니다.
   * 이미지 파일 이름에 공백이 없는지 확인하십시오. 다음과 같이 공백을 대시나 밑줄로 바꿀 수 있습니다: `automap_preview.webp`.
   * Markdown 파일의 이미지에 대한 모든 참조에 다음과 같이 `/images/` 접두사가 붙어 있는지 확인하십시오: `/images/automap_preview.webp`. 이는 결국 GitHub의 `static/images` 폴더에 업로드할 것이기 때문입니다.

## 문서 사이트의 포크 생성 또는 업데이트 [#create-update-fork]

포크는 개인 GitHub 계정에 저장되는 전체 문서 저장소의 복사본입니다. 포크에 변경 사항을 추가한 다음, 포크의 변경 사항을 뉴렐릭 `develop` 브랜치와 병합하도록 요청하는 pull 요청을 생성합니다.

1. [https://github.com/newrelic/docs-website](https://github.com/newrelic/docs-website)로 이동하여, 아직 사이트를 포크하지 않았다면 **Fork**를 클릭하십시오. 문서 사이트를 이미 포크한 경우 2단계로 건너뛰십시오.

   <img title="Screenshot showing fork button" alt="Screenshot showing fork button" src="/images/style-guide_screenshot-crop_whats-new-instructions-fork.webp" />

2. **Fetch upstream**을 클릭한 다음 **Fetch and merge**를 클릭하여 리포지터리를 업데이트합니다.

   <img title="Screenshot showing fetch upstream button" alt="Screenshot showing fetch upstream button" src="/images/style-guide_screenshot-crop_whats-new-instructions-fetch-upstream.webp" />

## 브랜치 생성 [#create-branch]

포크를 생성한 후 게시물을 위한 새 브랜치를 생성하십시오.

1. **develop**을 클릭하십시오.

   <img title="Screenshot showing the box to create a branch" alt="Screenshot showing the box to create a branch" src="/images/style-guide_screenshot-crop_whats-new-instructions-create-a-branch.webp" />

2. **Find or create a branch....** 상자에 새 브랜치 이름인 `whats-new-[number of month]-[day]-[feature name]` (예: `whats-new-10-25-aggregation-methods`)을(를) 입력하고 **Create branch: \[name you created in the box for your branch] from &apos;develop&apos;**을(를) 클릭하십시오.

   <img title="Screenshot showing fetch upstream button" alt="Screenshot showing fetch upstream button" src="/images/style-guide_screenshot-crop_whats-new-instructions-create-a-branch-and-fetch-upstream.webp" />

## Markdown 파일 업로드 [#upload-md]

이 단계에서는 다양한 GitHub 디렉터리를 클릭하여 게시물의 연도와 월에 적합한 디렉터리를 찾습니다.

1. **src** 폴더를 클릭합니다.

   <img title="Screenshot showing the src folder" alt="Screenshot showing the src folder" src="/images/style-guide_screenshot-crop_whats-new-instructions-static-folder.webp" />

2. **content** 폴더를 클릭하십시오.

3. **whats-new** 폴더를 클릭합니다.

4. 현재 연도의 폴더를 클릭한 다음 현재 월의 폴더를 클릭하십시오(예: 1월 = **01**, 2월 = **02** 등).

5. 해당 연도 및 월의 폴더에 도달하면 **Add File**을 클릭한 다음 **Upload files**를 클릭하십시오.

   <img title="Screenshot showing the add file button" alt="Screenshot showing the Add file button" src="/images/style-guide_screenshot-crop_whats-new-instructions-upload-files-content.webp" />

6. Finder(Mac) 또는 탐색기(Windows)에서 “What&apos;s new” 파일을 업로드 상자로 드래그하거나 **choose your files** \[파일 선택]을 클릭하여 파일을 선택하십시오.

7. **Commit changes** 아래에 다음 패턴을 따르는 일반적인 커밋 메시지를 입력합니다: `feat(whats-new): describe your post in a few words`. 이 형식은 기능(feat)에 대한 게시물을 추가하고 있음을 알려줍니다. 몇 가지 예는 다음과 같습니다: `feat(whats-new): add automap post` 또는 `feat(whats-new): apm`.

8. **Commit directly to the \[name of your branch] branch** 옵션을 선택한 다음 **Commit changes** \[변경 사항 커밋]을 클릭하십시오.

   <img title="Screenshot showing the commit changes button" alt="Screenshot showing the commit changes button" src="/images/style-guide_screenshot-crop_whats-new-instructions-commit-changes-content.webp" />

<Callout variant="important">
  화면 상단에 나타나는 배너에서 **Compare and pull request** 버튼을 클릭하지 마십시오. 이 작업은 나중에 수행합니다!
</Callout>

## 이미지 파일을 업로드하십시오 [#add-images]

이미지 파일을 사용하는 경우, 저장소에 업로드한 파일이어야 합니다. 다른 사이트에서 호스팅되는 이미지에 링크할 수 없습니다.

업로드 루틴은 마크다운 파일과 유사합니다:

1. **static** 폴더를 클릭하십시오.

2. **images** 폴더를 클릭하십시오.

3. 이미지 파일을 업로드하려면 **Add file** 및 **Upload files**를 클릭하십시오.

   <img title="Screenshot showing the Upload files button" alt="Screenshot showing the Upload files button" src="/images/style-guide_screenshot-crop_whats-new-instructions-upload-files.webp" />

4. Finder(Mac) 또는 탐색기(Windows)에서 이미지 파일을 해당 공간으로 드래그하거나 **choose your files**를 클릭하고 이미지 파일을 선택합니다.

   <img title="Screenshot showing upload box" alt="Screenshot showing upload box" src="/images/style-guide_screenshot-crop_whats-new-instructions-drag-and-drop-files-and-images.webp" />

5. **Commit changes** 아래에 Markdown 파일에 대해 수행한 것과 유사한 일반적인 커밋 메시지를 입력하십시오(예: `feat(whats-new): add automap images`).

6. **Commit directly to the \[name of your branch] branch** 옵션을 선택한 다음 **Commit changes** \[변경 사항 커밋]을 클릭하십시오.

   <img title="Screenshot showing commit box" alt="Screenshot showing commit box" src="/images/style-guide_screenshot-crop_whats-new-instructions-commit-changes.webp" />

## pull 요청(PR) 생성 [#create-pr]

pull 요청은 변경 사항을 기본 문서 웹사이트에 병합하도록 요청하는 프로세스를 시작하는 방법입니다.

1. 화면 상단에 나타나는 **Compare &amp; pull request**를 클릭하십시오.

   <img title="Screenshot showing the pull request button" alt="Screenshot showing the pull request button" src="/images/style-guide_screenshot-crop_whats-new-instructions-create-pull-request.webp" />

2. 메인 필드에 pull 요청에 대한 간단한 제목을 작성하십시오(예: `"What's new" automap post`).

3. **Write** 탭에서 작성 프롬프트를 게시물에 대한 지침으로 교체하십시오. 포함해야 할 몇 가지 중요한 지침은 다음과 같습니다:

   * 게시할 날짜와 시간대(아침, 정오 또는 저녁)를 지정하십시오.
   * 이 게시물에 제품 마케팅 관리자의 검토가 필요하지 않은 경우 알려주십시오.

4. **Create pull request** \[pull 요청 만들기를] 클릭합니다.

5. 아직 CLA(기여자 라이선스 계약)에 서명하지 않은 경우, pull 요청에 서명을 알리는 프롬프트가 표시됩니다. PR이 수락되도록 하려면 반드시 서명하십시오:

   <img title="Screenshot showing the prompt to sign the CLA agreement" alt="Screenshot showing the prompt to sign the CLA agreement" src="/images/style-guide_screenshot-crop_whats-new-instructions-cla-signature.webp" />

pull 요청을 완료하면 제품 마케팅 관리자 중 한 명이 게시물을 검토하고 우려 사항이 있으면 연락을 드립니다. 승인되면 문서 팀에 전달하여 마무리 작업을 하고 게시합니다. 추가 도움이 필요한 경우 아래의 추가 작업을 참조하거나 문서 담당자에게 문의하십시오.

1. **Code** 탭을 클릭한 다음 **branches**를 클릭하십시오.

   <img title="Screenshot showing the Code tab" alt="Screenshot showing the Code tab" src="/images/style-guide_screenshot-crop_whats-new-instructions-find-a-branch.webp" />

2. 삭제할 브랜치를 찾고, 빨간색 휴지통 아이콘을 클릭하십시오.

   <img title="Screenshot showing the trash can icon" alt="Screenshot showing the trash can icon" src="/images/style-guide_screenshot-crop_whats-new-instructions-delete-branch.webp" />

3. 실수로 브랜치를 삭제한 경우 언제든지 **Restore**를 클릭할 수 있습니다.

## 라이브 게시물 편집 [#edit-live]

때로는 이미 공개된 `What's new` 게시물을 변경해야 할 수도 있습니다:

1. [docs.newrelic.com/whats-new](https://docs.newrelic.com/whats-new/)로 이동하여 게시물을 찾습니다.

2. 문서 하단에서 **Edit page**를 클릭합니다.

3. GitHub에서 연필 아이콘을 클릭하십시오.

4. 텍스트를 편집하거나 파일을 드래그 앤 드롭, 선택 또는 붙여넣기하여 파일을 추가하거나 교체합니다.

5. 페이지 좌측 하단에서 **Propose** changes \[변경 사항 제안]를 클릭합니다.

6. 모든 변경 사항을 검토하고 이상이 없으면 **Create pull request** \[pull 요청 생성]을 클릭하십시오.

7. 두 번째 **Create pull request** \[pull 요청 생성] 버튼이 표시되면 해당 버튼을 클릭하여 pull 요청 제출을 완료하십시오.
