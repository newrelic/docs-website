이는 당사의 분기된 설치 구성 요소를 이루는 구성 요소에 대한 참조입니다.

브랜치 설치를 시작하려면 [브랜치 설치 시작하기](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc)를 참조하십시오.

분기된 설치 문서는 다양한 옵션 간의 관계를 매핑하는 설정 YAML 파일에 의해 제어됩니다. YAML은 콘텐츠 조각(.mdx 파일에 위치한)이 문서를 채우는 시기와 방법을 설명합니다. 사용자가 옵션을 선택함에 따라, YAML은 해당 스니펫을 교체합니다.

## 구성품 [#new-components]

분기된 설치 구성 요소의 실제 작동 모습을 보려면 [분기된 설치 구현](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#uses)을 참조하십시오. 주요 구성 요소는 다음과 같습니다:

* 사용자가 선택한 항목에 따라 표시되는 콘텐츠가 결정되는 옵션 선택 상자(때로는 &quot;타일 드롭다운 메뉴&quot;라고도 함)
* 번호가 매겨진 단계
* 사용자가 값을 입력할 수 있는 내장 구성 파일 옵션
* 설치 피드백 양식(`<InstallFeedback />`)

## 작동 원리 [#how]

설치 문서는 `install` 디렉터리에 있습니다. 문서에서 특정 콘텐츠가 교체되는 방식과 시기를 정의하는 단일 `.yaml` 파일이 있습니다. 특정 콘텐츠 항목은 `.mdx` 파일로 표시됩니다.

## 디렉터리 개요 [#install-directory]

설치 프레임워크 콘텐츠는 `src/install`에 있습니다.

새 설치 문서를 생성하려면 `install`에 디렉터리를 추가하십시오.

디렉터리 구조는 다음과 같아야 합니다:

```
install
|--assets (used for install images)
|--config (used for the install yaml files)
   |--agent-config (used for the agent config yml files)
|--specific-install (used for a specific install doc)
   |--sub-directory1 (used for .mdx files that will be swapped in)
   |--sub-directory2 (used for .mdx files that will be swapped in)
   |--sub-directoryx (you can have as many sub-directories as you need)
```

새 분기 문서를 시작할 때 `install` 디렉터리 아래에 상위 디렉터리를 생성하십시오. 이곳은 분기 문서의 모든 파일이 있는 곳입니다.

## 분기 YAML 파일 [#yaml-overview]

분기 문서 YAML 파일은 매우 다양한 사용자 지정 대화형 콘텐츠를 생성하는 고도로 사용자 지정 가능한 방법입니다. YAML 파일이므로 들여쓰기에 주의를 기울이고 YAML 파일의 모든 부분이 올바른지 확인하는 것이 매우 중요합니다.

YAML 파일에서 MDX 콘텐츠를 교체할 때 특정 MDX 파일은 설치 문서 디렉터리(예: 자바)의 로컬에 있어야 합니다. 재사용을 목적으로 문서 사이트의 어느 곳에서나 콘텐츠에 링크하고 싶을 수 있지만, 이렇게 하면 문서가 손상됩니다.

### YAML 스크립트를 확인하십시오 [#verify-yaml]

YAML 파일이 얼마나 쉽게 손상될 수 있는지를 고려하여, 엔지니어링 팀에서 YAML 파일에서 발생할 수 있는 일반적인 문제를 확인하는 유용한 스크립트를 만들었습니다.

터미널에서 `docs-website` 리포지터리 디렉터리로 이동하여 다음 명령을 실행하십시오:

`yarn verify-install-page YOUR_BRANCHING_DOC_DIRECTORY_NAME`

예를 들어, 자바 분기 문서의 경우 다음을 사용합니다:

`yarn verify-install-page java`

자바 분기 문서가 `src/install/java`에 위치해 있기 때문입니다.

이 스크립트는 YAML 파일에서 다음을 확인합니다:

* `agentName` 값은 `src/install/YOUR_DIRECTORY_NAME`의 폴더 이름과 일치합니다.
* `agentName`, `agentType`, `title` 및 `appInfo` 필드는 비어 있지 않습니다.
* `appInfo` `placeholder` 필드가 비어 있지 않습니다.
* 단계 및 재정의 파일 경로가 유효한 경로이며 실제 파일을 가리킵니다.
* 모든 `overrides` 에는 `selectedOptions` 값이 있습니다.
* 추가 따옴표 또는 잘못된 들여쓰기와 같은 일반적인 YAML 구문 문제입니다.

### YAML 파일 예시 [#sample-yaml]

[YAML 파일 예시](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#yaml-examples)를 참조하십시오.

## YAML 필드 이름 세부 정보 [#yaml-fields]

* agentName: 모든 항목이 있는 디렉터리 이름이며 URL(/install/java)과도 연결됩니다.

* title: 문서의 이름(다른 .mdx 파일과 동일).

* introFilePath: 문서의 소개 콘텐츠가 포함된 파일입니다.

* agentConfigFilePath: (선택 사항, 구성 파일을 사용하는 경우) 에이전트 구성 파일이 있는 위치입니다. 작동하지 않는 경우, 지원되는 파일 형식인지 엔지니어링 팀에 문의하십시오.

* appInfo: 옵션이 정의되는 섹션입니다. 구성 요소:

  * optionType: 옵션 세트에 지정하는 이름입니다. 이 이름은 참조하는 옵션을 지시하기 위해 `steps` 섹션에서 참조되며, 관련 .mdx 파일에서도 참조됩니다.
  * label: 드롭다운 메뉴의 이름으로, 해당 옵션 상자 위에 표시됩니다. 원하지 않는 경우 빈 따옴표를 사용하여 이 항목을 비워둘 수 있습니다.
  * 플레이스홀더: 옵션 상자 위에 넣을 수 있는 추가 텍스트입니다. 원하지 않는 경우 빈 따옴표와 함께 비워 둘 수 있습니다.

* 옵션

  * value: 타일 이름에 대한 변수입니다. 이는 표시할 파일을 제어하는 값을 제공할 때 `steps` 섹션에서 참조됩니다.
  * displayName: 옵션 타일에 표시되는 레이블입니다.
  * logo: 선택 사항입니다. 옵션 타일에 사용되는 이미지의 경로입니다.
  * icon: 선택 사항입니다. 이미지 대신 아이콘을 사용하려면 이를 사용하십시오(icon name=&quot;fe-server”).
  * recommendedGuided: 부울. 이는 `appInfoConfigOption` 구성 요소 유형 .mdx 파일의 콘텐츠가 표시될지 여부를 결정합니다. 이는 주로 안내 설치 콘텐츠에 사용되지만, 해당 파일에 표시되도록 트리거하려는 모든 콘텐츠에 사용할 수 있습니다. [안내 설치 옵션에 대해 자세히 알아보십시오](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#guided-install-decision).

* steps: 표시되는 콘텐츠를 결정하는 섹션입니다. 이들이 나열된 순서가 모든 콘텐츠의 순서를 결정합니다.

  * filePath: .mdx 파일에 대한 경로(또는 트리거 여부에 따른 이론적 경로)입니다.

  * overrides: 세 가지 유형의 재정의가 있습니다.

    * **교체**. 재정의 아래에 나열된 다른 `filePath`이(가) 있는 경우, 이는 다음을 의미합니다: 선택한 옵션에 따라 기본 파일 경로를 이 파일 경로로 교체합니다.
    * **다음인 경우 표시...** 이것은 부울 값을 취하는 `isConditionalStep`을(를) 사용합니다. 이것은 &quot;재정의&quot;가 아니며, 선택한 옵션에 따라 이 파일을 표시한다는 의미입니다. 더 복잡한 AND/OR 논리 사용에 대한 정보는 [예제 .NET yaml](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example)을 참조하십시오.
    * **건너뛰십시오.** 이것은 부울 값을 취하는 `skip`을(를) 사용합니다. 이것은 기본적으로 다음을 의미합니다: 이 파일을 표시하되 이러한 옵션이 선택된 경우 건너뜁니다.

  * selectedOptions: 관련 옵션 선택 항목을 배치하는 섹션입니다. 구성 요소는 다음과 같습니다:

    * optionType: 이는 `appInfo` 섹션에서 사용되는 `optionType`에 연결됩니다.
    * 옵션
      * value: `optionType`에서 사용된 `value`에 연결합니다.

## MDX 파일 분기 [#mdx-overview]

이 설치 프레임워크로 작업할 때 알아두어야 할 특정 MDX 파일이 있습니다. 다양한 MDX 콘텐츠 유형은 `componentType` frontmatter 필드를 통해 지정됩니다.

다양한 .mdx 구성 요소 유형은 다음과 같습니다:

* `intro`

  * YAML에서 `introFilePath`(으)로 참조됩니다.
  * 문서 상단의 소개 콘텐츠입니다.

* `default`

  * 자유 형식 MDX 파일입니다.
  * 대부분의 콘텐츠에 이를 사용하십시오.

* `appInfoConfigOption`
  * 이것은 옵션 콘텐츠를 참조하는 데 사용됩니다.

* `agentConfig`
  * 이는 에이전트의 구성 파일에 사용됩니다.

사용 중인 MDX 파일의 예시를 보려면 [예제 yaml 파일](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example)을 참조하십시오.

### agentConfig MDX 파일 [#sample-agentconfig]

선택 사항인 `agentConfig` MDX 파일은 설치 디렉터리의 적절한 구성 파일을 가리키며 구성 파일에서 편집할 수 있는 줄을 제어합니다.

```md
---
componentType: agentConfig
headingText: Set your app name and license key
descriptionText: Set your app name and license key. Then download your custom config file.
fileName: newrelic.yml
inputOptions:
  - label: 'Name your app'
    name: appName
    codeLine: 21
    defaultValue: 'My app name'
    toolTip: 'New Relic connects metrics to individual applications using your license key and the primary application name.' 
  - label: 'Enter your license key'
    name: licenseKey
    codeLine: 28
    defaultValue: '12345'
---
```

구성 파일을 사용할 때 다음을 권장합니다:

* 기본 `newrelic.yml` 권한을 애플리케이션 서버 프로세스의 소유자만 읽기/쓰기가 가능하도록 변경하십시오.
* `newrelic.yml`이(가) 백업 루틴의 일부인지 확인하십시오.
* 배포하기 전이나 후에 [뉴렐릭 Diagnostics CLI](https://docs.newrelic.com/docs/new-relic-solutions/solve-common-issues/diagnostics-cli-nrdiag/run-diagnostics-cli-nrdiag/)를 사용하여 설정을 검증하십시오.

### MDX 프런트매터 필드 [#mdx-frontmatter]

* `componentType`: (이 네 가지 옵션 중 하나 사용) 누락된 경우 &quot;default&quot; 유형으로 기본 설정됩니다.

  * `default`: 무료 mdx 파일
  * `appInfoConfigOption`: 이것은 드롭다운 메뉴를 위한 것이며, 드롭다운 메뉴를 원할 때마다 사용하십시오.
  * `agentConfig`: 이는 yaml 파일을 위한 것입니다
  * `appInfoConfig`: 이 단계는 콘텐츠를 표시하는 단계입니다(`recommendedGuided` 콘텐츠 포함)

* `descriptionText`: 단계 콘텐츠의 첫 번째 텍스트(두 번째 제목 역할을 하는 더 작은 회색 텍스트)

* `optionType`: 다음에 대해서만 추가됩니다 `appInfoConfigOption`
