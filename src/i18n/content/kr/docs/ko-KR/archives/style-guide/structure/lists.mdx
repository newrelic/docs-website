목록은 정보를 체계화하는 강력한 방법이지만, 항상 쾌적한 읽기 경험을 제공하는 것은 아닙니다. 목록을 작성할 때 다음 사항을 유의하십시오:

* 각 목록 항목의 첫 번째 단어의 첫 글자는 항상 대문자로 쓰십시오.
* 순서가 중요한 단계별 절차에는 정렬된(번호가 매겨진) 목록을 사용하십시오.
* 사용자가 관련 정보를 더 쉽게 훑어볼 수 있도록 순서 없는(글머리 기호) 목록을 사용하십시오.
* 번호가 매겨진 단계나 글머리 기호에 두 개 이상의 옵션이 있는 경우 별도의 줄에 OR를 사용하십시오.
* 정렬된 목록이나 정렬되지 않은 목록에 추가 세부 정보가 필요한 경우 표를 사용하십시오.

<Callout variant="tip">
  문장 부호 지침의 경우 현지화에 대한 고려 사항이 포함된 **[Microsoft 글쓰기 스타일 가이드](https://docs.microsoft.com/en-us/style-guide/scannable-content/lists)**를 따르십시오.
</Callout>

## 인라인 목록 [#inline-lists]

글머리 기호 목록을 사용하는 대신 다음과 같이 인라인 목록을 작성할 수 있습니다: [C SDK](/docs/agents/c-sdk/instrumentation/enable-distributed-tracing-your-c-applications) | [Go](/docs/agents/go-agent/features/distributed-tracing-go#create-manually) | [자바](/docs/agents/java-agent/api-guides/guide-using-java-agent-api#trace-calls).

다음과 같은 경우 인라인 목록을 사용하는 것이 좋습니다:

* 추가 문서에 링크하고 있습니다.
* 고객은 단일 옵션을 선택할 가능성이 높습니다.
* 목록 항목은 짧은 단어나 구(자바 또는 인프라 등)로 표시될 수 있습니다.
* 글머리 기호 목록이 세로 공간을 많이 차지한다고 생각할 수 있습니다. 이러한 상황은 절차에 여러 목록이 포함되어야 하는 경우에 발생할 수 있습니다. 다음은 [이에 대한 한 가지 예](/docs/understand-dependencies/distributed-tracing/enable-configure/enable-distributed-tracing#enable)입니다.
* 선택할 수 있는 잠재적인 옵션이 두세 개뿐이고 글머리 기호 목록이 불필요해 보입니다. 다음은 [예](/install/dotnet#requiremnts)입니다.
