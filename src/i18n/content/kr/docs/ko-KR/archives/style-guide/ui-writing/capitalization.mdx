대문자 표기는 특정 단어의 중요성을 전달하는 데 도움이 되며 의미의 변화를 나타내는 데 사용될 수 있습니다. 이러한 효과를 유지하려면 대문자로 표기하는 대상을 제한해야 합니다.

## 기본 사항

* 2023년 2월부터 세 가지 유형의 UI 콘텐츠에 제목 대소문자를 사용하십시오:

  * 페이지 제목
  * 왼쪽 내비게이션(메인 내비게이션)
  * All Capabilities 페이지 타일의 제목

* 나머지 경우에는 문장 대소문자를 사용하십시오.

* 고유 명사(제품명, 국가, 약어, 사람 이름)의 첫 글자는 문장의 어디에 나타나든 대문자로 표기하십시오.

* [제품 및 기능: 대문자 표시, 상표 및 사용](/docs/style-guide/capitalization/product-capability-feature-usage) 페이지에 설명된 대로 제품명을 대문자로 표기하십시오.

* 문장의 시작 부분에 있지 않는 한 관사(a, an, the)나 전치사(of, on, for, in, to, with 등)는 대문자로 표기하지 마십시오.

| 권장 사항             | 하지 마십시오                   |
| ----------------- | ------------------------- |
| 상위 5개 트랜잭션 트레이스   | 상위 5개 트랜잭션 트레이스           |
| 뉴렐릭은 고유 명사입니다.    | 뉴렐릭은 고유 명사입니다.            |
| 새 대시보드를 사용해 보십시오. | 새로운 Dashboards를 사용해 보십시오. |
| 자유의 여신상           | 자유의 여신상                   |

## 위치별 대문자 표시

| 복사 유형                | 예시                                                    |
| -------------------- | ----------------------------------------------------- |
| 왼쪽 탐색, 페이지 제목, 기능 타일 | 에러스 인박스                                               |
| 소제목, 본문 텍스트 등        | 에러스 인박스(errors inbox)를 사용하여 한 곳에서 모든 오류를 탐색하고 분류하십시오. |
| 버튼, 링크 등             | 에러스 인박스(errors inbox) 탐색                              |

## 제목 대소문자

| 복사 유형           | 예시                                           |
| --------------- | -------------------------------------------- |
| 내비게이션 또는 페이지 제목 | 에러스 인박스(errors inbox), 메트릭 &amp; 이벤트, 서비스 수준 |
| 모든 위치의 고유 명사    | Amazon CloudWatch 로그를 뉴렐릭으로 전송하십시오.          |

## 문장 대소문자

| 복사 유형       | 예시                                    |
| ----------- | ------------------------------------- |
| 데이터 비트      | Kb, Mb, Gb                            |
| 소제목 및 차트 이름 | 가장 느린 5개의 트랜잭션                        |
| 버튼          | 대시보드 만들기                              |
| 설명 및 본문 텍스트 | 새로운 에러스 인박스(errors inbox)를 사용해 보셨습니까? |

## 소문자

| 복사 유형         | 예시             |
| ------------- | -------------- |
| 데이터 1비트       | 1 b            |
| 파일 확장자        | json, gif, pdf |
| 시간 경과에 따른 메트릭 | rpm, ppm       |

## 대문자

| 복사 유형          | 예시                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| 데이터 바이트        | B, KB, MB                                                                                               |
| 999 이상의 축약된 숫자 | 1 k, 1 M, 1 B                                                                                           |
| 약어             | API, CDN, HTTP                                                                                          |
| 시간대            | PDT, CST, BCN                                                                                           |
| 기간             | [AM 또는 PM](https://docs.newrelic.com/docs/style-guide/ui-writing/numbers-dates-and-times#date-and-time) |

## 측정 단위

메모리, 대역폭 및 드라이브 공간 약어에는 대문자 표기에 대한 다양한 규칙이 있습니다.

* 값과 측정 단위 사이에는 항상 공백을 포함하십시오.
* 단일 데이터 비트는 소문자(b)인 반면, 1,204+ 비트는 문장 대소문자(13 Kb)입니다.
* 바이트는 항상 대문자입니다(13 KB, 512 MB).

무게와 거리는 소문자이며 약어 뒤에 마침표가 없습니다(ft, lbs, km).

| 권장 사항   | 하지 마십시오 |
| ------- | ------- |
| 32 Kb/s | 32 kb/s |
| 16s     | 16s     |
| 0.43 MB | 0.43 MB |
| 15ft    | 15ft.   |
