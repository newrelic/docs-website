잘 선택한 스크린샷이나 이미지는 문서의 가독성과 명확성을 크게 향상시킬 수 있습니다. 이미지가 너무 많거나 분석하기 어려운 이미지는 속도를 크게 저하시킬 수 있습니다.

* 문서 팀 소속이 아니면서 문서 사이트에 이미지를 추가하려면 [GitHub 이슈](https://github.com/newrelic/docs-website/issues/new/choose)를 생성하십시오.
* 뉴렐릭 직원인 경우, 문서 Slack 채널의 `@hero`에 문의하십시오.

## 이미지 추가 [#add]

민감한 데이터가 UI 스크린샷에 나타나지 않도록 하고자 합니다. 그렇기 때문에 테스트 계정에 대한 영구 링크를 제공하는 것을 권장합니다. 뉴렐릭 계정에서 스크린샷을 찍지 마십시오.

이미지를 생성할 때 유의해야 할 몇 가지 사항은 다음과 같습니다.

* 이미지가 한눈에 유용한 정보를 제공하는지 확인하십시오.
* [명명 및 가져오기 문 규칙](#naming-and-imports)을 따르십시오.
* 이미지에 유용한 컨텍스트가 포함된 캡션을 포함하십시오.
* 스크린샷 캡션의 경우 경로를 굵게 표시하십시오.
* 비디오 캡션의 경우 대략적인 재생 시간을 포함하십시오.
* 외부 이미지 파일에 링크하지 마십시오. 문서에 사용되는 모든 이미지는 [당사의 GitHub 리포지터리](https://github.com/newrelic/docs-website)에 저장되어야 합니다.
* 기본값은 다크 모드입니다. 해당 분야의 전문가가 라이트 모드의 스크린샷을 제공하는 경우, 다크 모드로 된 새로운 스크린샷을 요청해 주십시오. 다크 모드 이미지를 얻을 수 없는 경우, 스크린샷이 없는 것보다 어떤 스크린샷이라도 있는 것이 낫습니다.

이미지를 추가하거나 편집하려면:

1. `static/images/`의 루트에 이미지를 배치하십시오.

2. 이미지를 추가하거나 편집하려면 다음 절차를 계속 진행하십시오:

    기본 구조는 다음과 같습니다:

    ```md
    ![alt text](/images/IMAGE_NAME.webp "Image title text")
    ```

    2. 새 이미지 파일을 동일한 `static/images` 디렉터리에 배치하십시오.

    * `.md`: 이미지 파일의 이름이 원본 파일과 동일한지 확인하십시오. 현재 `.md`은(는) 번역하지 않습니다.
  </Collapser>
</CollapserGroup>

## 이미지 캡션 작성 [#labeling]

기술 캡션은 독자가 이미지가 중요한 이유를 아는 데 도움이 됩니다. 스크린샷인 경우 설명과 함께 경로를 굵게 표시하는 것이 도움이 됩니다. 예:

```html
<img
  title="Screenshot showing the Overview dashboard"
  alt="Screenshot showing the Overview dashboard"
  src="/images/kubernetes_screenshot-full_cluster-dashboard-detail.webp"
/>

<figcaption>
  Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Kubernetes**</DNT>. Select your cluster and click <DNT>**Overview Dashboard**</DNT> in the left navigation pane. It shows useful overview data about the status and performance of the cluster and its containerized workloads.
</figcaption>
```

이미지 주변의 캡션 및 기타 지원 텍스트에 대한 자세한 도움말은 [이미지 설명 가이드라인](/docs/style-guide/writing-guidelines/screenshots-images#identify-images)을 참조하십시오.

## 인라인 이미지 추가(MDX) [#inline-images-mdx]

인라인 이미지를 사용하려면:

* 파일에서 `img` 태그를 사용하십시오
* `src` 속성에는 이미지 경로가 포함됩니다: `src="/images/IMAGE_NAME.webp"`
* `img`에 `inline` 클래스를 추가하십시오.
* `style` 속성에 선택적 높이/너비를 추가하십시오.

인라인 이미지가 아이콘으로 사용되는 경우 항상 먼저 설명하십시오. 아이콘 이미지를 삽입할 때 텍스트에서 이미지 뒤에 `icon` 단어를 추가하십시오. 예:

```jsx
---
title: Abbreviated example of a file
---

Select your app's settings <img src="/images/example_icon_example-icon.webp" class="inline" style={{height: "30px", width: "30px"}} alt="Multiple app names indicator in New Relic" title="Multiple apps name indicator in New Relic" /> icon.
```

## 이미지 크기 조정

기본적으로 모든 MDX 이미지는 콘텐츠 내에서 세로 이미지가 너무 크게 표시되지 않도록 최대 높이가 550px로 지정됩니다.

550px보다 높아야 하는 이미지가 있는 경우 `img` 속성에서 `unbound` 클래스를 설정할 수 있습니다.

```html
<img
  class="unbound"
  title=""
  alt=""
  src=""
/>
```

**참고:** 일부 이미지는 `img` 속성에 설정된 `width="n%;"`을(를) 사용하고 있습니다. 이렇게 하면 `unbound` 클래스가 자동으로 적용되고 기본 이미지 높이 제한이 제거됩니다. 이는 이미지가 늘어나고 크기가 비례적으로 조정되지 않게 하기 때문입니다.

## 아이콘 [#icons]

문서에 포함할 다양한 아이콘을 선택할 수 있습니다:

* Feather 아이콘(`'fe-` 접두사 사용).
* 뉴렐릭 아이콘(`nr-` 접두사 포함).
* 타사 제품의 로고(`logo-` 접두사 포함).

필요한 아이콘이 이미 있는지 확인하려면 다음으로 이동하십시오:

* [GitHub의 `docs-website` 용 Feather.js](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104): `docs-website` 프로젝트에서 사용할 수 있지만 Gatsby 테마에는 포함되지 않은 Feather 아이콘입니다.
* [GitHub의 `docs-website` 용 Gatsby 테마](https://github.com/newrelic/docs-website/tree/develop/src/%40newrelic/gatsby-theme-newrelic/icons): 이는 개발자 및 문서 사이트 전체에서 사용할 수 있는 Feather, 뉴렐릭 및 제품 로고 아이콘의 하위 집합입니다.

Gatsby 테마 또는 Feather에서 필요한 모든 아이콘을 사용할 수 있습니다. 현재 이러한 위치에는 겹치지 않는 별도의 아이콘 버킷이 있습니다.

### 아이콘을 태그 속성으로 삽입하십시오. [#tag-attributes]

아이콘이 다른 태그 내의 속성으로 나타나는 경우, 이 예와 같이 `icon`을(를) 접두사로 추가하십시오:

```jsx
<LandingPageTileGrid>
  <LandingPageTile
    title="AWS Lambda"
    href="/docs/serverless-function-monitoring/aws-lambda-monitoring/get-started/monitoring-aws-lambda-serverless-monitoring"
    icon="logo-aws"
  >
</LandingPageTile>
```

### 인라인 아이콘 삽입 [#inline-icons]

아이콘이 본문 텍스트 안에 나타나는 경우 `<Icon>` 구성 요소를 사용하십시오. 몇 가지 예는 다음과 같습니다:

* Feather: `<Icon name="fe-database" />`
* 뉴렐릭: `<Icon name="nr-tdp" />`
* 로고: `<Icon name="logo-apple" />`

### 새로운 Feather 아이콘 설치 [#feather-icons]

[GitHub의 `docs-website` 용 Gatsby 테마](https://github.com/newrelic/gatsby-theme-newrelic/tree/develop/packages/gatsby-theme-newrelic#available-icons) 또는 [GitHub의 `docs-website` 용 Feather.js](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104)에 원하는 아이콘이 없으면 Gatsby 테마에 새 아이콘을 추가할 수 있습니다. 개발자에게 원하는 아이콘을 추가해 달라고 요청할 수도 있습니다.

다음은 `database` 아이콘을 추가하는 예입니다:

1. [feathericons.com](https://feathericons.com/)으로 이동하십시오.
2. 아이콘 자체를 클릭하여 `database` 깃털 아이콘을 다운로드하십시오.
3. 다운로드한 후 텍스트 편집기에서 SVG 파일을 엽니다.
4. SVG의 “내부”, 즉 `<svg>` 태그 사이의 모든 내용을 복사하십시오. 예를 들어 SVG가 `<svg><path m="1"></path></svg>`인 경우 `<path m="1"></path>` 부분만 복사하십시오.
5. `src/@newrelic/gatsby-theme-newrelic/icons/feather.js`에서 Feather 아이콘 목록을 여십시오.
6. `database`에 대한 항목을 추가하고 이전 단계의 코드를 여기에 할당하십시오.
7. 아이콘에 여러 경로가 있는 경우 다른 아이콘에서 볼 수 있는 것처럼 그 주위에 `<>` 래퍼를 포함하십시오.
8. `feather.js` 파일을 저장합니다.

`fe-` 접두사가 자동으로 추가됩니다. 해당 아이콘이 추가되면 아이콘 구성 요소와 함께 사용할 수 있습니다, 예를 들어 `<Icon name="fe-database" />`.

## 이미지 리팩터링 PR 충돌 처리

다음은 이미지 리팩터링 후 적용된 기여 변경 사항과 미해결 PR에서 파일 변경 사항을 업데이트하는 방법에 대한 간략한 안내입니다.

`develop`에서 최신 버전을 가져온 다음 변경 사항에서 이미지 관련 파일을 업데이트하십시오:

### 리포지터리에 이미지 추가:

<SideBySide>
  <Side>
    **이전 이미지 규칙:**

    이미지가 있던 곳 `./src/images`

    ```
    ├──src/
    │  └──content/
    │  │  └──docs/
    │  │    └── example-page.mdx
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>

  <Side>
    **새로운 이미지 규칙:**

    이제 이미지는 다음 위치에 있습니다 `./static/images`

    ```
    ├──src/
    │  └──content/
    │     └──docs/
    │        └── example-page.mdx
    ├──static/
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>
</SideBySide>

### MDX 파일에서 이미지 사용

<SideBySide>
  <Side>
    **이전 이미지 규칙:**

    이전에는 이미지 경로를 변수로 가져온 다음 해당 변수를 `<img>` 소스로 사용해야 했습니다.

    ```jsx
    import exampleImage from 'images/example-image.webp'

    <img
      title="Image title."
      alt="Alternate text."
      src={exampleImage}
    />
    ```
  </Side>

  <Side>
    **새로운 이미지 규칙:**

    이제 이미지 소스는 단순히 static 폴더를 기준으로 한 이미지의 경로입니다:

    ```html
    <img
      title="Image title."
      alt="Alternate text."
      src="/images/example-image.webp"
    />
    ```
  </Side>
</SideBySide>

### MD 파일에서 이미지 사용

마크다운에서 이미지를 사용하는 것은 이전과 거의 같습니다. 사용된 경로를 약간 변경했습니다:

<SideBySide>
  <Side>
    **이전 이미지 규칙:**

    `./images`

    ```md
    ![Image title.](./images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>

  <Side>
    **새로운 이미지 규칙:**

    `/images`

    ```md
    ![Image title.](/images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>
</SideBySide>

### 로컬 빌드

`develop`에서 최신 버전으로 브랜치를 업데이트한 후 로컬에서 변경 사항을 실행할 때 발생하는 오류 및 실패한 빌드를 해결하려면 다음 단계를 따르십시오:

1. 위와 같이 이미지 파일 및 코드를 새 규칙으로 업데이트하십시오
2. 올바른 노드 버전을 사용 중인지 확인하려면 `nvm use`을(를) 실행하십시오.
3. 필요한 패키지를 설치하려면 `yarn`을(를) 실행하십시오
4. 이전 빌드에서 캐시된 이미지를 모두 제거하려면 `yarn clean`을(를) 실행하십시오.
5. 실행 `yarn start`
