이 페이지는 다운로드 가능한 소프트웨어의 릴리스 정보를 위한 것입니다. 제품 발표에 대해서는 [새로운 기능 스타일 가이드라인](/docs/style-guide/article-templates/whats-new-style-guidelines/)을 참조하십시오.

## 새 릴리스 정보 [#new-note]

문서 사이트에 릴리스 노트를 추가하려면:

1. 에이전트의 가장 최근 릴리스 정보를 찾아 동일한 폴더에 복사본을 만드십시오.
2. 사본의 이름을 바꿀 때 파일 이름에 `-` 구분 기호를 사용하여 잠재적인 버전 이름 지정 충돌을 방지하십시오. 예를 들어, `agent-123` 대신 버전 1.2.3에는 `agent-1-2-3`를 사용하고 버전 12.3에는 `agent-12-3`을 사용하십시오.
3. `subject`, `releaseDate` 및 `version`을(를) 작성하십시오. 해당하는 경우 `downloadLink` 필드를 포함하십시오. 대소문자의 차이로 인해 왼쪽 탐색 메뉴에서 그룹화 문제가 발생할 수 있으므로 `subject` 필드가 업데이트 중인 시리즈의 다른 릴리스 정보와 일치하는지 확인하십시오.
4. `New features`, `Improvements` 및 `Bug fixes`에 대한 표준 제목을 사용하여, [훌륭한 릴리스 노트를 작성](/docs/style-guide/article-templates/create-release-notes/#guidelines)할 수 있도록 이 섹션에 충분한 요약 정보를 추가하십시오. 더 자세히 알아볼 수 있는 문서나 기타 리소스에 링크하십시오.
5. 변경 사항을 커밋하고 pull 요청을 제출하십시오. 릴리스가 날짜에 민감한 경우 PR에 메모를 남겨 주십시오.

Tech Docs 히어로가 릴리스 노트 콘텐츠를 검토하고 PR을 승인하여 게시합니다. 팀의 다른 팀원에게 PR 검토를 요청할 수도 있습니다.

하루에 몇 번씩 문서 사이트를 빌드하고 릴리스하며, 때로는 빌드를 완료하는 데 몇 시간이 걸릴 수 있습니다. 릴리스가 시간에 민감한 경우, 문서가 라이브로 전환될 수 있도록 충분한 시간을 계획해 주십시오.

## 훌륭한 릴리스 정보의 조건은 무엇입니까? [#guidelines]

훌륭한 릴리스 노트는 사용자가 중요한 업데이트에 빠르게 익숙해지도록 도와주어, 해당 업데이트가 왜 중요한지 알 수 있게 합니다. 또한 훌륭한 릴리스 노트는 지원 및 보안 팀에도 도움이 됩니다.

사용자가 최신 릴리스를 유지하도록 권장함으로써 오래된 버전의 문제를 해결하기 위한 지원 시간을 줄일 수 있습니다. 또한 최신 버전에서 잠재적인 취약점이 해결된 경우 위험을 완화합니다.

훌륭한 릴리스 정보를 작성하려면 가능한 한 구체적으로 작성하십시오. 예:

* 새로운 기능을 간략하게 설명하십시오. 제공하는 가치의 예를 제시하고, 더 자세한 정보로 링크하십시오.
* &quot;다양한 버그 수정&quot;과 같은 모호한 표현을 사용하지 마십시오. 대신 무엇이 개선되었는지 명확하게 명시하여 독자가 겪었던 문제가 해결되었는지 알 수 있도록 하십시오.

## 새 릴리스 정보 카테고리 [#new-category]

이 정보는 주로 기술 문서 팀에서 사용하기 위한 것입니다.

새 릴리스 노트 카테고리를 추가하려면 문서 사이트의 다음 영역을 업데이트하십시오. (`nav/templates` 폴더의 `releaseNote.js` 또는 `releaseNoteLandingPage.js` 파일을 업데이트할 필요는 없습니다.) GitHub 문서 사이트에 pull 요청을 제출하기 전에 로컬 호스트에서 랜딩 페이지와 플레이스홀더 릴리스 노트가 올바르게 빌드되는지 확인하십시오.

### 카테고리 랜딩 페이지

`/src/content/docs/release-notes` 에서 다음을 추가합니다.

* 새 릴리스 노트 카테고리를 위한 폴더입니다. 이 페이지에 나열된 릴리스 노트의 RSS 피드 링크, 페이지 형식 및 날짜 순서는 자동으로 생성됩니다. 예를 들어 [Go 카테고리 랜딩 페이지 형식](/docs/release-notes/agent-release-notes/go-release-notes/)을 참조하십시오.
* `subject`을(를) 포함하는 새 폴더의 `index.mdx` 파일입니다. `subject`은(는) [릴리스 노트 랜딩 페이지](/docs/release-notes/)에 표시될 이름입니다.
* 에이전트 팀이 작성할 수 있도록 이 폴더에 있는 [플레이스홀더 릴리스 노트](/docs/style-guide/article-templates/create-release-notes/#new-note) 입니다. 사용되는 경우, 릴리스 노트의 `downloadLink` 필드는 게시된 릴리스 노트에서 자동으로 형식이 지정됩니다.

새 카테고리가 게시되기 전에 팀의 제품 마케팅 관리(PMM) 담당자에게 다가오는 [새로운 소식 게시물](/docs/style-guide/article-templates/whats-new-style-guidelines/)에 링크를 포함할지 여부를 확인하십시오.

### 랜딩 페이지

`/src/content/docs/release-notes/index.mdx`에서 릴리스 노트 카테고리에 대한 새 타일 섹션을 알파벳순으로 추가하십시오.

예시:

```jsx
<TechTile
  name="Logs"
  icon="logo-newrelic"
  to="/docs/release-notes/logs-release-notes"
/>
```

로고는 `@newrelic/gatsby-theme-newrelic/icons/logo/`에서 가져옵니다. 새 에이전트의 로고가 아직 없는 경우 표준 `logo-newrelic` 아이콘이나 `@newrelic/gatsby-theme-newrelic/icons/feathers.js`의 이미지를 사용하십시오. 다른 옵션이 필요한 경우 팀의 디자이너에게 문의하십시오.

### 다른 카테고리의 링크

에이전트 문서, 일반적으로 `Get started` 카테고리에 새 릴리스 노트 카테고리에 대한 링크를 추가하십시오. 보다 자세한 내용은 [여러 메뉴의 문서](/docs/style-guide/processes-procedures/include-a-doc-in-multiple-menus/)에 대한 문서를 참조하십시오.

선택 사항: 분류에서 `index.mdx` 파일을 업데이트하여 에이전트의 랜딩 페이지 텍스트에 링크를 추가하십시오.
