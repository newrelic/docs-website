미리 보기 문서 사이트는 당사가 고객과 공유하는 예정된 기능에 대한 문서를 호스팅합니다. 공개 문서 사이트와 달리, 미리 보기 문서 사이트는 공개적으로 편집할 수 없으며 검색 엔진 결과에 나타나지 않습니다. 사이트가 색인화되지 않았기 때문에 사용자는 한 미리 보기 문서에서 다른 미리 보기 문서로 이동할 수 없습니다.

미리 보기 문서 사이트는 공개 문서 사이트와 다른 저장소에 있으므로 기여하는 방법이 조금 다릅니다. 이 문서를 다 읽고 나면 미리 보기 사이트용 새 문서를 작성할 수 있습니다.

## 로컬 환경을 설정하십시오. [#do-first]

이전에 컴퓨터에 beta-docs-site 리포지터리를 복제한 경우 3단계로 건너뛰십시오.

1. [`beta-docs-site repo`](https://github.com/newrelic/beta-docs-site)(으)로 이동합니다. 액세스 권한이 없는 경우 #doc-eng-help Slack 채널에 문의하여 도움을 받으십시오.
2. 컴퓨터에 beta-docs-site 리포지터리를 클론하십시오.
3. Github Desktop의 올바른 리포지터리에서 작업하고 있는지 확인하십시오.
4. `main` 브랜치에서 브랜치를 생성하십시오.

## 새 미리보기 문서 생성 [#create-docs]

퍼블릭 및 미리 보기 문서 사이트 간의 차이점에도 불구하고 콘텐츠의 형식과 구문은 대체로 동일합니다. 작업 브랜치로 이동한 후:

1. 텍스트 편집기를 사용하여 새 `.mdx` 파일을 생성하거나 프런트매터 템플릿용 기존 미리보기 문서를 복사하십시오.
2. `/src/content/docs/`에 파일을 저장하십시오.
3. 콘텐츠를 작성할 때, 문서화하고 있는 프리뷰 기능에 대한 가입 및 액세스 요청 정보를 반드시 포함하십시오.
4. 변경 사항을 커밋하고 pull 요청을 생성하십시오.
5. 미리 보기 링크를 검토자와 공유하고 피드백을 반영해 주십시오.
6. 최종 PR을 병합합니다.
7. `https://docs-preview.newrelic.com/docs/` 뒤에 파일 경로 이름을 붙여넣어 공식 링크를 생성하십시오(예: `https://docs-preview.newrelic.com/docs/new-feature-name`)
8. 리뷰어에게 고객과 공유할 공식 링크를 제공해 주십시오.

## 선택적 상용구 텍스트 [#boiler-plate]

미리보기용 문서를 작성할 때 문서 상단에 상용구 텍스트가 포함된 [콜아웃](/docs/style-guide/formatting/callouts/)을 포함할 수 있습니다. 이 텍스트는 독자에게 방향을 제시하여 기능의 가용성 및 관련 연락처 정보에 대한 중요한 정보를 제공하는 데 사용할 수 있습니다.

예를 들어, 미리 보기 문서의 상용구 텍스트는 다음과 같을 수 있습니다:

<Callout variant="caution" title="시사">
  이 기능은 202X년 1월 1일에 출시되었으며 프리뷰 상태입니다. 액세스 권한을 얻으려면 계정 관리자에게 문의하십시오.
</Callout>

정보가 너무 길거나, 페이지의 다른 곳에 포함되어 있거나, 문서와 관련이 없는 경우 상용구 텍스트를 제외할 수 있습니다.

## 내부 기여자를 위한 추가 안내 [#internal-contributors]

미리 보기 문서를 편집하려는 내부 기여자는 beta-docs-site 리포지터리에 대한 액세스 권한이 필요합니다. 액세스 권한이 없는 경우, #doc-eng-help Slack 채널에 기여자로 추가해 달라고 요청하십시오. 액세스 권한을 얻으면 `main` 브랜치에서 자신의 브랜치를 생성하고 그곳에서 편집하십시오.
