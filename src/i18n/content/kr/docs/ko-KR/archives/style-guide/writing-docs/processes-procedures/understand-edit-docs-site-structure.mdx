이 문서에는 다음을 포함하여 문서 사이트의 구조와 관련된 정보 및 절차가 포함되어 있습니다: 탐색 파일, 사이드바, 폴더 또는 파일 구조 등.

일반적인 사용 사례에 대한 간단한 지침은 [절차](#procedures)를 참조하십시오. 하지만 대규모 문서 사이트 프로젝트를 수행하는 경우 사전에 [일반 개념](#understand)을 이해하는 것이 좋습니다.

## 자귀 [#terms]

문서 사이트 구조에 대해 이야기할 때 사람들은 때때로 같은 것에 대해 다른 단어를 사용합니다. 다음은 문서 사이트 구조에 대해 소통하는 데 도움이 되는 용어 목록입니다:

* **문서 파일**: 모든 문서는 .mdx 파일(마크다운 파일이라고도 함)로 표시됩니다.
* **Nav 파일**: Nav 파일은 문서 사이트 왼쪽 사이드바에 노출되는 문서 사이트의 표시 구조를 관리합니다. Nav 파일은 `src/nav` 디렉터리에 있는 yaml 파일입니다.
* **폴더**: 이 문맥에서 &quot;폴더&quot;는 실제 문서 사이트 폴더 구조(`content` 디렉터리의 폴더 및 파일)를 의미합니다. &quot;폴더&quot;라고 지칭하는 것은 실제 폴더 구조와 nav 파일을 사용하여 설정된 표시 구조를 구분하는 데 도움이 될 수 있습니다.
* **사이드바**: 공개 문서에서 사이드바는 왼쪽에 표시되는 부분으로, 해당 문서 범주의 구조를 보여줍니다. 사이드바 구조는 nav 파일에 설정된 구조에 따라 결정됩니다.
* **카테고리** 또는 **하위 카테고리**: 문서 사이트의 특정 영역을 지칭할 때 이 단어들을 거의 혼용하여 사용합니다. 예를 들어, &quot;계정&quot; 카테고리 또는 &quot;데이터 관리&quot; 카테고리라고 지칭할 수 있습니다.
* **자동 인덱스 페이지** (더 이상 사용되지 않음): 이는 사용자가 특정 카테고리의 문서 뷰를 로드할 수 있었던 이전 구현을 나타냅니다(예: 사이드바에서 카테고리 제목을 클릭하여). 더 이상 이 구현을 지원하지 않습니다.

## 문서 사이트 구조의 작동 방식 이해 [#understand]

이 섹션에서는 문서 사이트 구조가 결정되는 방식과 대중에게 표시되는 구조가 실제 폴더 구조와 어떻게 관련되는지에 대한 논리를 설명합니다.

### 표시된 구조는 실제 폴더와 어떤 관련이 있습니까? [#folders-vs-categories]

실제 문서 폴더 구조(`content` 폴더의 폴더 및 mdx 파일)는 사이드바의 문서 사이트 구조와 완전히 분리되어 있습니다. 사이드바에 표시되는 구조는 전적으로 탐색 파일(`src/nav` 폴더의 yaml 형식 파일)에 의해 결정됩니다.

위의 요점을 이해하는 것이 중요합니다. 문서 폴더 구조와 표시되는 문서 사이트 구조가 다른 것은 필수적입니다: 폴더 구조와 폴더 이름 및 문서 파일 이름을 완전히 동일하게 유지할 필요 없이 사이드바에 표시되는 구조를 제어할 방법이 필요하기 때문입니다. 이 두 가지가 분리되어 있기 때문에, 해당 로직이 작동하는 방식에 직관적이지 않은 측면이 있을 수 있습니다.

[일반적인 사용 사례에 대한 절차](#procedures)가 마련되어 있지만, 표시되는 구조가 어떻게 생성되는지에 대한 아래의 세부 사항을 이해하는 것이 많은 도움이 될 것입니다.

### 문서의 URL은 무엇으로 결정됩니까? [#doc-url]

문서 파일(`mdx` 파일)이 `content` 폴더의 어디에 위치하는지와 관련 폴더 및 파일 이름만이 해당 문서의 URL을 결정하는 유일한 요소입니다.

예를 들어 다음 문서 파일 `automated-user-provisioning-single-sign.mdx`을(를) 살펴보십시오:

<img title="Doc file in its folder" alt="Example of a doc file in the folder structure" src="/images/style-guide_screenshot-full_doc-in-folder-structure.webp" />

이 문서의 URL은 전적으로 폴더 위치와 폴더 이름에 기반합니다. 이 경우 URL은 다음과 같습니다:

```
docs.newrelic.com/docs/accounts/accounts/automated-user-management/automated-user-provisioning-single-sign
```

여기에는 다음을 포함하여 중요한 의미가 있습니다:

* 문서를 한 폴더에서 다른 폴더로 이동하면 해당 URL이 변경됩니다. 즉, 문서 파일을 이동할 때 원래 URL의 해당 문서에 대한 리디렉션을 추가해야 합니다.
* mdx 파일 이름이나 폴더 이름을 변경하면 URL이 변경됩니다. 즉, 해당 문서의 원래 URL에 대한 리디렉션을 추가해야 합니다.

### nav 파일은 어떤 역할을 합니까? [#nav-file-contents]

nav 파일은 매우 간단합니다. nav 파일은 사이드바에 표시되는 문서의 구조를 제어합니다. 현재 문서의 각 주요 섹션마다 하나씩 여러 개의 nav 파일이 있습니다. 예를 들어, 조직 및 계정 관련 설정이 포함된 &quot;Accounts&quot;에 대한 nav 파일이 있습니다. 그리고 &quot;인프라 모니터링&quot;에 대한 nav 파일이 있습니다.

nav 파일 형식에 대한 자세한 내용은 [nav 파일 형식](#nav-format)을 참조하십시오.

### 사이드바 표시 방식은 무엇에 의해 결정됩니까? [#doc-sidebar]

위에서 언급했듯이, 사이드바는 문서 사이트 구조(nav 파일에 의해 관리됨)가 노출되는 한 가지 방법일 뿐입니다.

문서가 로드되면 문서 사이트는 모든 탐색 파일에서 해당 URL을 검색합니다. 일치하는 항목을 찾으면 사이드바에 해당 탐색 파일을 표시하고 해당 문서를 강조 표시합니다.

문서의 URL은 두 개 이상의 nav 파일에 존재할 수 있습니다. 현재 문서는 모든 nav 파일에서 한 곳에만 위치할 수 있다는 것이 규칙입니다. 하지만 여전히 여러 nav 파일에 존재하는 일부 문서가 있습니다. 이러한 경우, 사이트는 문서 URL의 최상위 카테고리와 일치하는 nav 파일을 선택하여 적절한 nav 파일을 찾으려고 시도합니다. 예를 들어, 상대 URL이 `/docs/accounts/accounts-billing/account-setup/create-your-new-relic-account` 인 문서가 두 개의 nav 파일에 있는 경우, 문서 사이트 코드는 nav 파일 중 하나에 첫 번째 `path` 필드로 `docs/accounts`이(가) 있는지 검색합니다. 일치하는 항목을 찾으면 해당 nav 파일을 사용합니다.

## Nav 파일 형식 [#nav-format]

아래는 [`agents.yml`](https://github.com/newrelic/docs-website/tree/develop/src/nav/agents.yml) nav 파일의 스니펫입니다. 파일에는 탐색 계층 구조의 수준에 해당하는 들여쓰기가 있다는 점에 유의하십시오. 변경 사항을 적용하거나 새 nav 파일을 생성할 때 기존 간격 형식을 사용하십시오.

```yml
title: Agents
path: /docs/agents
pages:
  - title: Manage APM agents
    pages:
      - title: Agent data
        pages:
          - title: Real time streaming
            path: /docs/agents/manage-apm-agents/agent-data/real-time-streaming
          - title: Custom instrumentation
            path: /docs/agents/manage-apm-agents/agent-data/custom-instrumentation
          - title: Agent attributes
            path: /docs/agents/manage-apm-agents/agent-data/agent-attributes
          - title: Custom events
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-events
          - title: Custom metrics
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-metrics
          - title: Manage errors
            path: /docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected
          - title: Link Kubernetes
            path: /docs/agents/manage-apm-agents/agent-data/link-your-applications-kubernetes
      - title: App naming
        pages:
          - title: Name your application
            path: /docs/agents/manage-apm-agents/app-naming/name-your-application
          - title: Use multiple names for an app
            path: /docs/agents/manage-apm-agents/app-naming/use-multiple-names-app
```

<Callout variant="tip">
  내비게이션 중첩은 현재 최대 6단계 깊이로 제한됩니다. 이것으로 충분하지 않은 경우 엔지니어링 팀에 문의해 주십시오.
</Callout>

### 대규모 문서 사이트 구조 조정 프로젝트의 단계 개요 [#large-project]

일부 소규모 문서 사이트 편집의 경우, 문서 파일이나 폴더를 변경할 필요 없이 단순히 nav 파일을 편집할 수 있습니다. 하지만 대규모 프로젝트의 경우, 문서 파일과 폴더 자체를 편집하고 이동해야 할 수도 있습니다. 아래는 이러한 대규모 프로젝트에 일반적으로 수반되는 작업 단위에 대한 전반적인 개요입니다.

1. 새로운 탐색 파일 구조가 어떤 모습일지 계획하고, 문서 파일을 이동하거나 새 폴더를 만드는 작업을 계획하십시오. 대규모 프로젝트에 수반될 작업 덩어리를 적어 두는 것이 도움이 될 수 있습니다.
2. 영향을 받는 문서 파일을 새 폴더 위치로 이동하고 리디렉션을 추가해야 합니다. 이에 대한 자세한 내용은 [폴더 간 문서 이동](#move-docs-between-folders)을 참조하십시오.
3. 빈 폴더는 모두 삭제하십시오.
4. 파일 구조 자체에 대한 폴더 또는 파일 편집(파일 또는 폴더 이름 바꾸기, 파일 및 폴더 이동 포함, 단 문서 또는 탐색 파일 내의 콘텐츠 또는 프런트 매터 편집은 **제외**)의 경우 `i18n` 디렉터리의 폴더 및 파일에도 동일한 편집을 수행하십시오. 모든 폴더나 파일이 i18n 디렉터리에 있는 것은 아닙니다. mdx 파일이 번역용으로 표시된 경우에만 해당 mdx 파일이나 관련 폴더가 채워집니다.
5. 원하는 새 구조를 반영하고 새 문서 URL을 가리키도록 nav 파일을 편집합니다.

더 구체적이고 세분화된 절차를 보려면 계속 읽어보십시오.

### 문서의 새 카테고리 추가 [#add-category]

기존 nav 파일에 문서의 하위 카테고리를 추가하는 방법과 완전히 새로운 nav 파일을 추가하는 방법의 두 가지 절차를 설명합니다:

#### nav 파일에 새 카테고리 추가 [#add-nav-section]

nav 파일에 새 카테고리를 추가하려면:

1. 기존 탐색 파일에서 `title`(으)로 표시되는 새 카테고리를 추가하십시오.
2. 다른 탐색 파일의 형식과 들여쓰기를 모방하여 해당 섹션에 원하는 문서를 추가하십시오.

작동 방식에 대해 자세히 알아보려면 다음을 참조하십시오:

* [문서의 사이드바가 결정되는 방법](#doc-sidebar)
* [문서 카테고리 보기가 결정되는 방법](#category-view)

#### 새 nav 파일을 추가하십시오 [#add-new-nav]

완전히 새로운 탐색 파일을 추가하는 것은 드물어야 하며 사이트 구조를 대대적으로 개편할 때 가끔씩만 수행해야 합니다. 새 탐색 파일을 추가하려면 문서 사이트 관리자의 승인을 받아야 합니다.

완전히 새로운 탐색 파일을 추가하려면:

1. 기존 파일 nav 파일을 복사하거나 새 nav 파일을 생성하십시오.
2. 표준 탐색 파일 형식 및 들여쓰기를 사용하여 원하는 범주 및 문서로 새 탐색 파일을 사용자 지정하십시오. 구조에 대한 자세한 내용은 [탐색 형식](#nav-format)을 참조하십시오.

### 사이드바/탐색 파일에 문서 추가 [#add-doc-to-nav]

[문서를 생성](/docs/style-guide/writing-guidelines/create-edit-content/#creating-docs)한 후에는 nav 파일에 배치해야 합니다. 문서를 두 개 이상의 nav 파일 위치에 배치하지 마십시오: 다른 범주의 문서에 대한 링크가 필요한 경우, 해당 참조를 관련 문서 섹션 내에 배치해 보십시오.

nav 파일에 문서를 추가하려면:

1. 배치하려는 nav 파일 위치에 `title` (사이드바 및 카테고리 보기에 표시되는 짧은 제목)과 문서의 URL인 `path`을(를) 추가하십시오.
2. 표준 nav 파일 형식 및 들여쓰기를 모방했는지 확인하십시오.

### 문서를 다른 범주로 이동 [#move-docs]

nav 파일과 실제 폴더 구조가 연결되어 있지 않기 때문에 &quot;문서 이동&quot;에는 두 가지 다른 방법이 있습니다:

* 탐색 파일에서 문서 이동: 권장되는 가장 일반적인 절차입니다.
* 폴더 간 문서 이동: 빈도가 낮으며, 주로 문서 구조를 크게 개편하고 폴더 구조가 탐색 파일 구조와 너무 달라지지 않도록 하려는 대규모 프로젝트를 수행할 때 발생합니다.

#### nav 파일을 사용하여 문서를 이동하십시오. [#move-docs-in-nav-file]

사이드바 메뉴에서 표시되는 위치를 변경하려면 탐색 파일에서 문서를 이동하십시오.

nav 파일에서 문서를 한 곳에서 다른 곳으로 이동하려면:

1. 첫 번째 nav 파일에서 해당 문서의 항목을 나타내는 두 행(`title` 및 `path` 줄)을 복사하여 새 nav 파일에서 원하는 위치에 해당 콘텐츠를 붙여넣습니다.
2. 새 nav 파일 섹션에서 서식과 들여쓰기가 표준 nav 파일 구조와 일치하는지 확인하십시오. nav 파일 구조에 대한 자세한 내용은 [Nav 형식](#nav-format)을 참조하십시오.

#### 폴더 간 문서 이동 [#move-docs-between-folders]

폴더 간에 문서를 이동하는 일은 비교적 드물어야 한다는 점에 유의하십시오. 이렇게 하는 주된 이유는 폴더 구조와 탐색 파일 구조가 상당히 달라지는 경우이며, 이는 몇 가지 이유로 좋지 않을 수 있습니다:

* 너무 많은 차이는 사용자 혼란(예: 폴더 기반 URL의 요소가 탐색 파일 기반 위치와 매우 다른 경우)이나 최적이 아닌 검색 엔진 결과를 초래할 수 있습니다.
* 너무 많은 차이는 문서를 찾고 편집하는 것을 더 어렵게 만들 수 있으므로, 최신 상태로 병렬로 유지하는 것이 가치가 있을 수 있습니다.

폴더 간에 문서를 이동하거나 문서의 이름을 변경하면 해당 URL이 변경됩니다(이유에 대한 자세한 내용은 [구조 이해](#understand)를 참조하십시오). 마찬가지로 폴더의 이름을 변경하면 해당 영역에 있는 모든 문서의 URL이 변경됩니다.

폴더 간에 문서를 이동하려면:

1. 이동하려는 문서의 현재 URL을 가져와서 해당 URL을 자체 리디렉션 목록에 추가하십시오. 팁:

   * VSCode에서 이 작업을 수행하는 한 가지 방법은 파일 이름을 마우스 오른쪽 버튼으로 클릭하고 &quot;상대 경로 가져오기&quot;를 클릭하는 것입니다.
   * 많은 파일을 이동하는 경우 전체 문서 디렉터리에 리디렉션을 프로그래밍 방식으로 추가하기 위한 스크립트에 대해 팀에 문의하십시오.
   * 리디렉션 URL에 후행 슬래시가 없는지 확인하십시오.

2. 문서를 새 폴더 위치로 이동하십시오.

3. 해당 mdx 파일이 `i18n` 디렉터리에 있는 경우(번역 대상으로 표시된 경우 여기에 있음), `i18n` 디렉터리에서도 해당 파일을 동일하게 이동하십시오.

4. **새 URL로 nav 파일을 업데이트하십시오**. nav 파일에 리디렉션이 아닌 올바른 문서 URL을 포함하는 것이 중요합니다. 문서의 URL은 두 개 이상의 nav 파일에 있을 수 있으므로 사이트에서 해당 URL을 검색하는 것이 도움이 될 수 있습니다.

### 폴더 이동, 삭제 또는 이름 변경 [#move-delete-folders]

때로는 대규모 구조 조정 프로젝트를 수행할 때 단순히 nav 파일을 편집하는 대신 실제 폴더를 이동하거나 삭제하거나 이름을 바꾸고 싶을 수 있습니다. 이에 대한 지침:

1. 폴더를 이동하거나 이름을 변경하면 해당 폴더에 있는 문서의 모든 URL이 변경되므로, 영향을 받는 문서에 먼저 리디렉션을 추가해야 합니다. 수동으로 이 작업을 수행하거나([여기 1단계에 설명됨](#move-docs-between-folders)) 디렉터리의 모든 문서에 리디렉션을 일괄 추가하기 위해 문서 팀이 보유한 스크립트를 사용할 수 있습니다.
2. 원하는 편집을 수행하십시오. 예를 들어, 폴더를 새 위치로 이동(예: Finder 창에서 끌어서 놓기) 및/또는 폴더의 이름을 변경하십시오.
3. 편집된 폴더가 `i18n` 디렉터리에 있는 경우(해당 폴더의 문서가 번역용으로 표시된 경우 여기에 존재함), `i18n` 디렉터리에서 해당 폴더 및 해당 파일을 동일하게 편집하십시오. 참고: `i18n` 작업은 폴더나 파일의 이동 또는 이름 변경에만 필요하며, 문서나 탐색 파일 콘텐츠의 편집에는 필요하지 **않습니다**.

폴더를 삭제하려면 기본적으로 위와 동일한 단계를 따라야 합니다: 이동하거나 삭제할 mdx 파일에 대한 리디렉션을 추가한 다음, 문서를 이동하거나 삭제하고, 빈 폴더를 삭제합니다.

### 문서의 파일 이름 변경 [#change-doc-file-name]

mdx 파일의 이름을 변경하면 [URL이 변경됩니다](#understand). 실제 파일 이름을 변경하지 않고도 프런트 매터에서 문서의 표시된 제목을 변경할 수 있습니다. 파일 이름을 변경하는 것이 유용할 수 있습니다. 지침:

1. 파일 이름을 변경하려는 문서에 리디렉션을 추가하십시오.
2. 파일 이름을 변경하십시오.
3. 해당 파일이 `i18n` 디렉터리에 있는 경우(해당 문서가 번역 대상으로 표시된 경우 존재함), `i18n` 디렉터리에서 해당 파일의 이름을 동일하게 편집하십시오. 참고: `i18n` 작업은 폴더나 파일의 이동 또는 이름 변경에만 필요하며, 문서나 탐색 파일 콘텐츠의 편집에는 필요하지 **않습니다**.

### 플레이스홀더 문서 생성 [#placeholder-doc]

더 이상 탐색 파일의 여러 위치에 문서를 두지 않으려고 합니다(여전히 이와 같은 문서가 일부 있기는 합니다). 탐색 파일의 여러 위치에서 문서를 참조하도록 하려면, 대신 해당 문서를 참조하는 것이 타당한 문서 내의 위치를 찾으십시오.
