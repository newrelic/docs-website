뉴렐릭 콘텐츠 전반의 일관성을 위해 일반적인 단어 사용 가이드라인은 다음과 같습니다:

* 일반적으로 시카고 매뉴얼 오브 스타일(Chicago Manual of Style)을 기반으로 하는 [Microsoft 스타일 가이드](https://docs.microsoft.com/en-us/style-guide/welcome/)를 따릅니다.
* 영국식 영어 표기법 대신 미국식 영어 표기법을 따릅니다.
* 제품을 참조할 때는 공식 제품 이름을 따릅니다. (예를 들어 Amazon Web Services (AWS)의 경우 [aws.amazon.com/products](https://aws.amazon.com/products/)를 참조하십시오.)
* 뉴렐릭에 특화된 용어의 경우 [제품 용어집](/docs/using-new-relic/welcome-new-relic/getting-started/glossary)을 사용합니다.

<CollapserGroup>
  <Collapser id="account" title="계정">
    뉴렐릭에 가입하시면 뉴렐릭 조직(조직 ID로 표시됨)이 생성됩니다. 해당 조직에는 하나 이상의 계정(각 계정에는 계정 ID가 있음)이 포함될 수 있습니다. `organization`와(과) `account,`의 차이에 대한 보다 자세한 내용은 [조직 및 계정 구조](/docs/accounts/accounts-billing/account-structure/new-relic-account-structure)를 참조하십시오.

    뉴렐릭 외부의 일반적인 사용에서 `account`은(는) 종종 더 넓은 의미로 사용됩니다. 예를 들어, 우리가 `organization,`을(를) 사용하는 것과 같은 방식으로 사용되거나 누군가의 사용자 레코드를 참조하는 데 사용될 수 있습니다. 이러한 용어를 사용할 때는 가능한 한 정확하게 사용하도록 노력해야 합니다. 이는 뉴렐릭 조직이 아닌 뉴렐릭 계정에만 적용되는 측면(예: 계정 수준 데이터 및 쿼리 제한)을 문서화할 때 특히 그렇습니다.

    그렇기는 하지만, 사용이 더 일반적일수록 `account`을(를) `organization`의 동의어로 사용하는 것이 더 용인됩니다. 예를 들어, 뉴렐릭은 때때로 &quot;뉴렐릭 계정에 가입하십시오.&quot;와 같은 문구를 사용합니다. `organization` 대신 `account`을(를) 사용하는 것은 `account`이(가) 일반적으로 사용되는 방식과 일치하며 `account`에 대한 당사의 정의와 관련된 특정 항목을 참조하지 않기 때문에 무방합니다.
  </Collapser>

  <Collapser id="account-id" title="계정 ID">
    [특정 뉴렐릭 계정을 식별하는](/docs/accounts-partnerships/accounts/account-setup/account-id) 고유 번호입니다. `account number`을(를) 사용하지 마십시오.
  </Collapser>

  <Collapser id="agent" title="대리인">
    뉴렐릭 에이전트는 여러 유형의 기술(예: 웹 프레임워크, 운영 시스템 및 데이터베이스 유형)과 통합되고 일반적으로 특정 주기에 따라 뉴렐릭에 데이터를 보고하는 설치 가능한 소프트웨어입니다. 모든 에이전트는 통합이지만, 모든 통합이 에이전트인 것은 아닙니다. 당사의 많은 에이전트는 다중 통합을 지원합니다, 예를 들어 자바 에이전트는 다양한 자바 프레임워크 및 기술에서 데이터를 수집하거나 인프라 에이전트는 온호스트 Cassandra 통합을 활성화합니다.

    뉴렐릭 에이전트로 간주되는 목록은 다음과 같습니다:

    * APM:

      * 에이전트 이동
      * 자바 에이전트
      * .NET 에이전트
      * Node.js 에이전트
      * PHP 에이전트
      * 파이썬 에이전트
      * 루비 에이전트

    * 인프라:

      * 인프라 에이전트
      * Linux 에이전트
      * MacOS 에이전트
      * Unix 에이전트
      * Windows 에이전트

    * 브라우저 에이전트

    * 이동하는:

      * 안드로이드 에이전트
      * iOS 에이전트
      * 하이브리드 에이전트(Capacitor, 플러터 등)

    * 네트워크:

      * ktranslate 에이전트
      * 네트워크 플로우 에이전트

    * SNMP 에이전트

      * Syslog 에이전트

    * Roku

    * Elixir

      통합으로 간주되는 항목의 목록을 보려면 [통합](#integration) 정의를 참조하십시오.
  </Collapser>

  <Collapser id="AIOps" title="AIOps">
    IT 운영을 위한 인공 지능의 약자입니다.
  </Collapser>

  <Collapser id="ampm" title="오전 및 오후">
    * 12시간제를 사용하고 그 뒤에 (소문자) 시간대 am 또는 pm을 사용하십시오.

    * 타임스탬프의 마지막 숫자 뒤에 공백을 두지 마십시오(12:00 am이 아니라 12:00am).

    * 시간이 10 미만인 경우 앞에 0을 포함하지 마십시오.

      ```
      9:30am, 12:30pm, 8:30pm
      ```
  </Collapser>

  <Collapser id="aws" title="Amazon Web Services (AWS) 제품 이름">
    * 일반적으로 대화에서 `AWS`(으)로 지칭됩니다. 첫 번째 인스턴스에서는 `Amazon Web Services`을(를) 참조하고, 그 이후에는 `AWS`을(를) 사용할 수 있습니다.
    * Amazon에는 전체 이름보다 약어로 거의 항상 지칭되는 [Amazon EC2](https://aws.amazon.com/documentation-overview/ec2/) 및 [Amazon S3](https://aws.amazon.com/documentation-overview/s3/)와 같은 여러 제품이 있습니다. Amazon이 약어를 사용하는 경우 첫 번째 인스턴스에서 약어를 사용할 수 있습니다.
    * 일부 Amazon 제품은 `Amazon`을(를) 접두사로 사용하며(`Amazon EC2`와(과) 같이), 다른 제품은 `AWS`을(를) 사용합니다(`AWS Amplify`와(과) 같이). [AWS 문서 사이트](https://aws.amazon.com/documentation)와 일치하게 하십시오.
    * 일부 Amazon 제품 이름은 데이터나 설정 옵션을 지칭하기 위해 더 비공식적인 방식으로 사용될 수도 있습니다. 예를 들어, [AWS Metric Streams](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-Metric-Streams.html)의 경우, AWS는 제품을 참조할 때 해당 이름을 제목 대소문자로 지정하지만, 생성된 데이터를 참조할 때는 비공식적으로 참조합니다(예: `metric stream data` 또는 `metric streams`). 일반적으로 AWS가 수행하는 방식을 따라야 합니다.
  </Collapser>

  <Collapser id="ampersand-details" title="앰퍼샌드(&)">
    회사나 브랜드 이름의 일부가 아닌 한 문장이나 제목에 앰퍼샌드를 사용하지 마십시오. 예외: 공간이 부족한 경우(“and”가 들어가지 않는 경우) 앰퍼샌드를 사용할 수 있습니다.
  </Collapser>

  <Collapser id="app-name" title="앱 이름 대 앱 별칭">
    Collector가 앱을 고유하게 식별하는 데 사용하는 &quot;머신 이름&quot;은 `app name`입니다. 고유 식별자를 변경하지 않고 앱의 표시되는 &quot;이름&quot;을 변경하는 서버 측 설정은 `app alias`입니다.
  </Collapser>

  </Collapser>

  <Collapser id="call-called" title="호출, 호출 중, 호출됨">

  <Collapser id="click" title="딸깍 하는 소리">
    일반적으로 더 모호한 `select` 대신 `click`을(를) 사용하십시오. 예를 들어 UI에서 무언가를 클릭한 다음 목록에서 무언가를 선택할 수 있습니다.

    마우스로만 의미가 있는 작업을 설명할 때 `click`을(를) 사용하도록 각별히 주의하십시오, 예를 들어 `right click` 또는 `click and drag`을(를) 사용하는 경우입니다. 또한 사용자가 선택할 수 없는 객체(`to save your changes, click anywhere outside the dialog box`)를 클릭해야 할 때 `click`을(를) 사용하십시오. [마우스 오버](#mouse-over)도 참조하십시오.
  </Collapser>

  <Collapser id="collector" title="수집기 대 뉴렐릭 연결">
    뉴렐릭 서버와 통신하는 에이전트를 언급할 때는 이를 [뉴렐릭 수집기](/docs/accounts-partnerships/education/getting-started-new-relic/glossary#collector)로 설명하십시오. 내부적으로 `collector`은(는) 아키텍처의 특정 부분만을 가리키지만, 문서에서는 “어떤 제품이든 고객이 데이터를 보고하기 위해 연결해야 하는 모든 엔드포인트”를 의미하는 데 더 폭넓게 사용합니다. “뉴렐릭에 연결”을 피하고 “뉴렐릭 UI에 연결”을 사용하지 마십시오.
  </Collapser>

  <Collapser id="contractions" title="줄임">
    명확성, 간결성, 어조 및 목소리 측면에서 타당한 경우 축약형을 사용하십시오. 글을 더 자연스러운 말처럼 들리게 하고, 전문성과 권위를 희생하지 않으면서 명확성과 접근성을 향상시키는 곳에 사용하십시오.

    어떤 축약형이 허용되는지 또는 허용되지 않는지에 대한 엄격하고 빠른 규칙은 없지만, 복잡하고 드문 것보다는 간단하고 일반적인 것이 더 좋습니다. 예를 들어, `it is` 대신 `it's`을 사용하는 것은 괜찮지만, `mustn't` 또는 `wouldn't've`과 같이 덜 일반적인 구조는 피하는 것이 가장 좋습니다.

    또한:

    * 부정 축약형(`don't`, `can't`, `won't`)을 사용할 때는 무엇을 해야 하고 무엇을 할 수 있는지에 대한 추가 정보를 제공하도록 노력하십시오. (이에 대한 자세한 내용은 [스타일 가이드 소개](/docs/new-relic-only/basic-style-guide/writing-guidelines/introduction-style-guide#tone)를 참조하십시오.)
    * 문서의 일부 위치 ― 예를 들어, 참고 및 경고 ― 에서는 피해야 할 작업이나 차단을 강조하기 위해 축약형보다 `do not`, `cannot` 또는 `will not`를 풀어쓰는 것이 더 좋습니다.
  </Collapser>

  <Collapser id="customer-vs-user" title="고객 대 사용자">
    가능한 경우 2인칭 `you`을(를) 사용하여 독자와의 유대감을 형성하십시오. 기술적인 3인칭 명사가 필요한 경우 다음 지침을 염두에 두십시오:

    * `customer` 및 `user`은(는) 문맥에 따라 둘 다 적절합니다.
    * `customer` 청구, 사람들의 그룹 또는 비즈니스 엔티티에 대해 이야기할 때 더 의미가 있습니다. 예를 들어, 한 고객에게 고객의 계정을 통해 뉴렐릭과 상호 작용하는 한 명 이상의 개별 사용자가 있을 수 있습니다.
    * `user` 개별 사용자에 대한 일반적인 용어로 사용하거나 계정 모델에서 사용자를 객체로 이야기할 때 더 의미가 있습니다. 예를 들어 계정 모델을 논의할 때 시스템에서 단일 개인 ID를 구성하는 요소를 구체적으로 지정하는 것이 중요합니다.
  </Collapser>

    * Dashboards는 [해당 기능 페이지](https://newrelic.com/platform/dashboards)에서 볼 수 있듯이 `New Relic dashboards`(이)라는 뉴렐릭 기능을 의미합니다. 이 문맥에서 `New Relic dashboards`은(는) 핵심 플랫폼 경험(예: APM, 브라우저 모니터링, OpenTelemetry 등의 UI)에 내장되지 않은 맞춤형 뷰를 생성하고 사용하는 기능을 의미합니다. 이러한 커스텀 대시보드는 **Dashboards** UI 페이지에서 찾을 수 있습니다.
    * Dashboards는 큐레이션된 대시보드를 의미할 수도 있습니다. 이러한 대시보드는 고객이 핵심 플랫폼 솔루션(예: APM, 인프라 및 브라우저 모니터링을 위한 UI 경험)을 사용할 때 얻는 기본 뷰입니다.

    일반적인 용어인 &apos;대시보드&apos;를 사용할 때 모호함이 있다고 생각되면 다음 사용법을 권장합니다:

    * 고객 또는 고객의 팀이 만든 너드팩, 퀵스타트 또는 대시보드에 있는 사용자 지정 환경을 참조하려면 `custom dashboards`, `customizable dashboards` 또는 `quickstart dashboards`를 사용하십시오.
    * 더 많은 큐레이션된 뷰를 참조하려면 `curated views`, `curated dashboards`, `New Relic-built dashboards`, `APM dashboards`, `APM views`를 사용하십시오(몇 가지 예를 들자면).

  <Collapser id="metric" title="미터법">
    `metric` 이라는 단어가 업계에서 어떻게 사용되고 뉴렐릭에서 어떻게 사용되는지에 대한 설명은 [데이터 유형](/docs/data-apis/understand-data/new-relic-data-types/#metrics)을 참조하십시오.

    * &quot;메트릭&quot;이라는 단어는 광범위하고 일반적인 개념이며 뉴렐릭에는 [&quot;메트릭&quot;이라고 하는 여러 데이터 유형 및 데이터 보고 방법](/docs/data-apis/understand-data/new-relic-data-types/#metrics-new-relic)이 있습니다.

    * 가장 좋은 메트릭 데이터 형식은 차원 메트릭 데이터, 즉 `Metric` 데이터 유형입니다. 해당 데이터는 메트릭 API를 통해 보고됩니다. 이것은 4가지 핵심 &quot;MELT&quot; 데이터 유형: 메트릭, 이벤트, 로그 및 트레이스에서 &quot;메트릭&quot;에 대해 이야기할 때 주로 언급하는 &quot;메트릭&quot; 데이터입니다.

    * 당사의 원래 메트릭 데이터 형식은 메트릭 타임슬라이스 데이터라고 합니다. 이는 여전히 APM, 브라우저 모니터링 및 모바일 모니터링에서 보고됩니다. 이것은 매우 단순한 형태의 메트릭 데이터였으며 NRDB에 저장되지 않았으므로 NRQL에서 쿼리할 수 없었습니다. 현재 APM 메트릭 타임슬라이스 데이터는 NRDB에 미러링되므로 [NRQL을 통해 쿼리할 수 있습니다](/docs/data-apis/understand-data/metric-data/query-apm-metric-timeslice-data-nrql).

      스타일 관련 권장 사항:

    * **데이터 구조 및 보고 프로세스에 대해 자세히 설명하지 말고 일반적으로 &quot;메트릭&quot;에 대해 이야기하는 편이 낫습니다**. 일반적으로 차원 메트릭(`Metric` 데이터 유형), 지표 타임슬라이스 데이터 또는 인프라 이벤트 속성으로 보고된 메트릭에 대해 이야기할 때 단순히 &quot;메트릭&quot; 또는 &quot;메트릭 데이터&quot;를 사용할 수 있습니다. 문서 및 UI의 대부분의 경우 고객은 데이터 유형이 정확히 무엇인지 알 필요가 없는 것으로 간주됩니다. 하지만 데이터 유형을 아는 것이 도움이 될 것으로 생각되는 경우(예를 들어 해당 데이터를 쿼리하는 방법에 대해 이야기할 때) 데이터 유형에 대해 더 자세히 설명할 수 있습니다.

    * 메트릭 데이터의 유형을 간단하게 명확히 하고 싶을 때, [이 섹션](/docs/data-apis/understand-data/new-relic-data-types/#metrics-new-relic)의 특정 메트릭 데이터 유형 콜랩서에 링크할 수 있습니다. 예를 들어 다음과 같이 작성할 수 있습니다: &quot;이 통합은 [메트릭 데이터](/docs/data-apis/understand-data/new-relic-data-types/#dimensional-metrics)를 보고합니다.&quot;
  </Collapser>

  <Collapser id="version" title="버전 번호 참조">
    여러 버전 번호를 참조할 때는 `or higher` 또는 `or lower`을(를) 사용하십시오. `and higher` (`or`보다 모호함) 또는 `greater` 또는 `later`라는 단어를 사용하지 마십시오. 또한 `version 1.2+` 또는 `<version 1.2`과 같이 문장 부호를 사용하지 마십시오. `1.2.X` 스타일의 참조를 피하고 대신 정확한 버전 번호를 사용하십시오. 예를 들어:

    ```
    Foo requires Ruby agent version 1.2.3 or higher
    ```

    ```
    Bar is compatible with ActiveMerchant version 4.5.6 or lower
    ```

    문맥에 따라 `version` 및 `versions` 모두 작동한다는 것을 알 수 있으며, 확실하지 않은 경우 소리 내어 읽어 보십시오.

    기타 사용 참고 사항:

    * 사용자에게 `up-to-date` 또는 `current` 버전이 아닌 `latest version`을(를) 사용하도록 안내하십시오.
    * 단어 `version`을(를) 축약하려면 숫자 앞에 공백 없이 소문자 `v`을(를) 사용하십시오. 예를 들면 `v2` 또는 `v1.2.3`입니다.
    * &quot;최신 버전으로 업데이트하려면...&quot;과 같이 에이전트 버전에 대해 이야기할 때는 `upgrade`이(가) 아닌 `update`을(를) 사용하십시오.
    * 버전을 더 모호하게 언급할 때는 `in earlier agent versions`을(를) 사용하는 것을 고려하십시오.
  </Collapser>

  <Collapser id="we" title="당사">
    글의 흐름에 맞을 때 `we` 및 `our`을 사용하십시오. 단락에 `New Relic` 언급을 너무 많이 사용하지 않도록 하거나, 뉴렐릭이 아닌 사용자에게 초점이 맞춰지도록 문장을 바꾸십시오. 예를 들어, 다음과 같이 작성하지 마십시오:

    ```
    New Relic recommends setting a startup timeout.
    ```

    대신 다음과 같이 작성하십시오:

    ```
    Recommendation: To help with troubleshooting, include a startup timeout in your configuration.
    ```

    또는

    ```
    We recommend setting a startup timeout.
    ```
