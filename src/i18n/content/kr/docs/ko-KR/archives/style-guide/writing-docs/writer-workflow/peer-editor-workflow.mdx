GitHub에서 동료 작성자를 위해 문서를 검토하고 동료 편집하는 방법을 알아보려면 이 문서를 사용하십시오. 로컬 환경을 설정하는 방법에 대한 정보는 [테크니컬 라이터 워크플로우 문서](/docs/style-guide/writer-workflow/tech-writer-workflow/)를 확인하십시오. GitHub 문제를 해결하려면 [가이드](/docs/style-guide/writing-docs/writer-workflow/github-troubleshooting/)를 참조하십시오.

## 리뷰를 받아야 하는 경우 [#when-to-get-review]

기술 작성자가 문서 사이트에 제출하는 거의 모든 PR은 동료 기술 작성자의 검토를 받아야 합니다. 검토를 수행하는 목적은 다음과 같습니다:

* 부정확한 내용 찾기
* 스타일 가이드 준수
* 글쓰기, 특히 어조와 톤을 개선하십시오.
* 다른 관점을 얻으십시오(예: 알려지지 않은 업무와 관련된 내용 학습).

리뷰는 중요하며, 항상 리뷰를 받는 것을 기본으로 해야 합니다! 이를 염두에 두고, PR의 범위가 작고 위의 고려 사항에서 이점을 얻을 가능성이 낮다고 확신하는 경우 리뷰 없이 PR을 병합할 수 있습니다. PR 리뷰를 받는지 여부와 관계없이, PR이 올바르게 빌드되고 모든 기술적 검사를 통과하도록 하는 것은 작성자의 책임입니다.

검토 없이 병합하기로 결정할 수 있는 항목의 몇 가지 예는 다음과 같습니다:

* 깨진 링크 수정
* 문서의 몇 단어나 몇 줄만 변경
* 단순하고 문제가 없다고 확신하는 단어/구문의 간단한 검색 및 바꾸기
* 특히 시간에 민감한 편집(이 경우 나중에 검토를 받기로 결정할 수 있습니다)
* PR 리뷰에 대한 응답으로 수행한 변경 사항 중 추가 리뷰가 필요하지 않다고 생각되는 변경 사항입니다.

PR에 대한 리뷰를 받아야 할지 조금이라도 의심이 든다면 리뷰를 받으십시오.

## GitHub의 동료 편집 워크플로우 [#peer-edit]

문서를 동료 편집하거나 리뷰어로 PR에 할당된 경우, 작업을 수행할 방법과 위치에 대한 몇 가지 선택 사항이 있습니다. 가장 간소화된 오픈 소스 접근 방식은 파일을 Google Docs에 복사하여 편집하는 대신 GitHub 옵션을 사용하여 편집하는 것입니다.

### 개발 편집 단계 [#edit-pass]

단순한 문구 수정이 아닌 질문이나 제안이 있는 경우 다음 단계를 따르십시오.

1. 리뷰하도록 할당된 PR을 여십시오.

2. 변경된 파일 탭에서 다음 중 하나를 수행할 수 있습니다:

   * 변경 사항 검토를 클릭한 다음 다음 중 하나를 선택하십시오:

     * **의견** ― 후속 조치가 필요하지 않은 의견이 있는 경우 사용하십시오.
     * **Approve** - PR을 승인하기만 하려는 경우에 사용하십시오. Leave a comment 영역에서 변경을 요청할 수 있으며, 작성자가 편집을 수행하고 후속 검토 없이 파일을 병합하도록 하려면 Approve를 선택하십시오.
     * **변경 요청** - 요청한 변경 사항이 포함되었는지 확인하고 싶을 때 사용합니다. 작성자가 업데이트를 수행하면 알림을 받게 됩니다.

   * 또는 문서의 줄이나 섹션에 주석을 작성하기 시작하십시오. 이렇게 하려면 주석 추가 아이콘을 클릭하고 페이지의 해당 특정 줄에 대한 편집 또는 주석을 남기십시오. 이 옵션을 사용하면 단일 주석을 추가하거나 검토를 시작하는 것 중에서 선택할 수 있습니다. 문서 전체에 주석을 작성하려면 주석이 모두 하나의 커밋으로 통합되도록 **Start a review** \[검토 시작]을 선택하십시오.

3. 리뷰를 완료하려면 **Finish your review** \[리뷰 완료]를 클릭하십시오. 이렇게 하면 작성자에게 제안을 했다는 공지가 트리거됩니다.

### 카피 편집 워크플로우 [#edit-copy]

의견이나 제안 대신 파일에 대한 텍스트 편집이 있는 경우, 다양한 방법으로 파일을 변경할 수 있습니다. 두 가지 주요 옵션은 다음과 같습니다:

1. GitHub 브라우저를 사용하여 편집: **Files changed** 탭의 diff 창에서 편집 버튼(점 3개)을 클릭하십시오. 편집을 마치면 파일 하단에 주석을 추가하고 **변경 사항을 직접 커밋**하거나 **브랜치를 생성하고 pull 요청을 시작**하도록 선택하십시오. 작성자가 diff를 검토하고 편집 내용을 수락하거나 수정할 것으로 예상되는 경우 브랜치를 생성하고 pull 요청을 시작하도록 선택하십시오.
2. 로컬에서 편집: 편집하려는 파일이 포함된 브랜치를 체크아웃하십시오. GitHub Desktop에서 Current branch 아래쪽 화살표를 클릭하고 브랜치를 선택하십시오. 그런 다음 로컬 드라이브에서 편집을 수행하고 저장한 후 변경 사항을 브랜치에 커밋하십시오.
   * 이 접근 방식은 열려 있는 pull 요청에 편집 내용을 추가한다는 점에 유의하십시오. 이제 PR의 **Files changed** 탭에서 파일에 추가한 변경 사항을 확인할 수 있습니다.

이것들은 많은 편집 옵션 중 일부에 불과합니다. 다른 도구와 마찬가지로 선호하는 방법을 찾을 수 있을 것입니다.
