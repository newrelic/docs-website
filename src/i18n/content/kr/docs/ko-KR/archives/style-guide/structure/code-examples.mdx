## 인라인 코드 형식 지정 [#inline-code]

인라인 코드(`maxSampleTimes` 또는 `TransactionError` 등)의 서식을 지정하려면 텍스트를 백틱 `` ` `` 문자로 묶으십시오.

## 여러 줄 코드 블록 [#code-block]

하나 이상의 코드 줄 형식을 지정하려면 코드 위와 아래에 3개의 백틱( ` ``` ` )을 삽입하십시오. 이것은 기본적으로 HTML `<pre>` 태그처럼 작동합니다.

코드 스니펫을 3개의 백틱 사이에 넣을 때는 코드 들여쓰기와 구문 강조 표시를 모두 고려해야 합니다.

### 엄격한 들여쓰기 [#strict]

테크니컬 라이터로서 다양한 언어의 코드 스니펫이 제공됩니다. 독자가 코드 스니펫을 더 쉽게 이해할 수 있도록 줄을 들여쓰고 유용한 방식으로 그룹화하십시오.

일부 프로그래밍 및 마크업 언어는 특정 들여쓰기를 요구합니다(예: 파이썬 및 YAML). 제공받은 스니펫이 작동하기 위해 특정 들여쓰기가 필요한지 확실하지 않은 경우 해당 분야의 전문가에게 확인하십시오. 다른 편집 도구에서 전송할 때 스니펫이 뒤섞이는 경우 언제든지 온라인 코드 정리 도구를 통해 스니펫을 실행할 수 있습니다.

다음은 들여쓰기를 변경할 경우 작동하지 않는 파이썬 코드의 예입니다:

```python
import newrelic.agent
newrelic.agent.initialize('newrelic.ini') #This is required!

def greet(name):
    """
    This function says hello to
    the person who is passed in as
    a parameter
    """
    print("Hello, " + name + " and the world!")


def execute_task(application, task_name):
    with newrelic.agent.BackgroundTask(application, name=task_name, group='Task'):
        greet("Robert")

application = newrelic.agent.register_application(timeout=10)
execute_task(application, "bar")
newrelic.agent.shutdown_agent(timeout=10)

```

### 엄격하지 않은 들여쓰기 [#casual]

들여쓰기가 자유로운 자유 형식 언어의 경우 유사한 예제를 찾아 해당 패턴을 따를 것을 권장합니다. 자바와 SQL은 자유 형식 언어의 예입니다.

### NRQL 형식 지정 방법 [#NRQL]

NRQL은 자유 형식의 쿼리 언어이므로 엄격한 들여쓰기 규칙이 없습니다. 읽기 쉽도록 몇 가지 간단한 지침을 따르는 것을 권장합니다. 당사의 제안은 일부 SQL 형식 지정 지침을 대략적으로 기반으로 합니다.

이러한 가이드라인을 스니펫에 적용할지 여부는 재량에 따라 결정할 수 있습니다:

* `FROM`, `SELECT`, `FACET`, `WHERE`, `AND`, `OR`, `AS`, `SINCE`, `ORDER BY`, `TIMESERIES`, `EXTRAPOLATE` 및 `AUTO`과 같은 절 키워드는 대문자로 표기하십시오.

* 쿼리 빌더는 이러한 이름을 자동으로 대문자로 변환하지 않으므로 `min()`, `max()`, `average()`, `percentile()`, `sum()` 및 `stddev()`와 같은 함수를 대문자로 쓰지 마십시오. 키워드가 함수인지 확실하지 않은 경우 [NRQL 참조](/docs/query-your-data/nrql-new-relic-query-language/get-started/nrql-syntax-clauses-functions/#functions)를 확인하십시오.

* `SELECT`(으)로 시작할 때 쿼리가 잘 실행되더라도 첫 번째 줄은 `FROM` 절로 시작해야 합니다.

* 다음 경우를 제외하고 절 키워드를 왼쪽 정렬하십시오:

  * 절 키워드가 선행 키워드와 밀접하게 연결되어 있는 경우(예를 들어 `AGO`이(가) `SINCE`와(과) 밀접하게 연결된 경우) 같은 줄에 위치해야 합니다.
  * 절 키워드에 수식어가 없는 경우(단독으로 사용되는 경우), 이미 키워드가 있는 줄의 끝에 추가할 수 있습니다(예: `TIMESERIES`, `AUTO` 및 `EXTRAPOLATE`).
    ```sql
    FROM Transaction
    SELECT count(*)
    WHERE appName='interestingApplication'
    SINCE 60 minutes AGO EXTRAPOLATE
    ```

* 여러 줄에 걸쳐 있는 괄호 안의 키워드는 두 칸 들여쓰기하십시오. 예를 들어 `WHERE` 키워드는 다음과 같이 두 칸 들여쓰기합니다:
  ```sql
  FROM PageView
  SELECT count(*)
  FACET CASES
  (
    WHERE duration < 1,
    WHERE duration > 1 AND duration < 10,
    WHERE duration > 10
  )
  ```

## 코드 줄 강조 표시 [#highlight-code]

코드 블록에서 전체 코드 줄을 강조 표시하려면 `lineHighlight=`을(를) 사용하여 강조 표시할 특정 줄을 나타낼 수 있습니다. 구문을 기록하는 동일한 위치에서 이 작업을 수행합니다. 다음은 첫 번째 줄과 세 번째 줄부터 다섯 번째 줄까지 강조 표시된 코드 블록의 예입니다:

## 고객별 변수에 대한 플레이스홀더 [#value-placeholders]

때로는 고객이나 상황에 따라 값이 달라지는 변수에 플레이스홀더를 사용하고자 할 때가 있습니다. 예를 들어, 고객이 뉴렐릭 계정 ID를 입력해야 하는 플레이스홀더를 나타내기 위해 `YOUR_ACCOUNT_ID`을(를) 사용해야 할 수 있습니다.

고객별 값 플레이스홀더를 작성하기 위한 몇 가지 요구 사항과 팁은 다음과 같습니다:

* 단어를 구분하려면 모두 대문자와 밑줄 `_`을(를) 사용하십시오([SCREAMING\_SNAKE\_CASE](https://github.com/rubocop-hq/ruby-style-guide#screaming-snake-case)라고도 함).
* SME가 특정 언어나 상황에 다른 요소가 필요한 이유에 대해 설득력 있는 근거를 제시하지 않는 한 `<`, `>` 또는 `$`와 같은 다른 요소를 사용하지 마십시오.
* `YOUR`을(를) 사용하여 독자를 직접 지칭하십시오. 예를 들어 `ACCOUNT_ID`이(가) 아닌 `YOUR_ACCOUNT_ID`을(를) 사용하십시오.
* 구성 요소가 당사의 것인지 타사의 것인지 불분명할 수 있다고 생각되면 플레이스홀더에 `NEW_RELIC`을(를) 추가할 수 있습니다. 예를 들어, AWS를 뉴렐릭에 연결하는 것에 대해 작성할 때 계정이 AWS의 계정이 아니라 당사의 계정임을 다음과 같이 명시할 수 있습니다: `YOUR_NEW_RELIC_ACCOUNT_ID`.
* 변수를 나타내기 위해 다른 문장 부호와 결합하지 마십시오(예: 텍스트를 꺾쇠괄호나 중괄호로 묶는 것).

### 플레이스홀더를 사용하지 않아야 하는 경우 [#placeholders]

플레이스홀더는 주로 코드를 실행할 고객과 같이 수행해야 할 절차가 있는 경우에 사용됩니다. 관련된 절차가 없고 코드 스니펫이 어떤 모습인지 또는 어떤 모습이어야 하는지 보여주기 위해 사용되는 경우에는 플레이스홀더를 사용하지 않아야 합니다. 다음은 플레이스홀더를 사용하지 **않아야** 하는 몇 가지 예입니다:

* 예제 코드 또는 파일: 절차와 직접적인 관련이 없는 예제 구성 파일이나 다른 예제를 보여주는 경우, 플레이스홀더가 아닌 예제 값을 사용하십시오.
* API 호출 응답: 응답이 어떻게 보이는지 보여주기 위한 것이며 절차와 관련이 없는 API 호출의 응답을 포함하는 경우, 플레이스홀더를 사용하지 마십시오.

### API 키

코드 블록이나 구성에서 API 키를 예로 참조해야 하는 경우, 0 대신 별표가 있는 플레이스홀더 텍스트를 사용해야 합니다.

예시:

```
...
-e NEW_RELIC_API_KEY=********************************FFFFNRAL \
...
```

또는

```
...
NEW_RELIC_LICENSE_KEY=****************************************
...
```
