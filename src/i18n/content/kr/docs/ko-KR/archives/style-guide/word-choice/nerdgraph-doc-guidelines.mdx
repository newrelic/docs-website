이 리소스는 뉴렐릭의 NerdGraph API에 대해 작성하기 위한 스타일 가이드 권장 사항 및 지침을 포함합니다.

## 스타일 관련 지침 [#nerdgraph-style]

NerdGraph에 대해 작성할 때의 몇 가지 스타일 관련 지침:

* **NerdGraph.** 일반적으로 &quot;NerdGraph&quot; 또는 &quot;뉴렐릭의 NerdGraph&quot;라고 지칭해야 합니다. 처음 언급할 때는 특히 API에 대해 이야기하고 있다는 것이 즉각적으로 명확하지 않은 문맥에서 당사의 &quot;NerdGraph API&quot;로 표현하는 것이 허용됩니다.

* **NerdGraph는 단일 API입니다.** NerdGraph는 여러 다른 API의 집합이 아닙니다. NerdGraph를 API의 모음이라고 부르는 경향이 가끔 있으며, NerdGraph가 내부적으로 많은 API를 하나로 모으기 때문에 이는 어느 정도 사실이기도 하지만, 고객의 관점에서는 단일 API로 부르고자 합니다. 예를 들어, &quot;NerdGraph의 엔티티 API를 사용하십시오&quot;와 같이 말하는 대신 &quot;NerdGraph를 사용하여 모니터 엔티티를 보고 구성하십시오.&quot;와 같이 말할 수 있습니다.

* **GraphQL.** GraphQL은 NerdGraph가 구축된 오픈 소스 API 형식입니다. GraphQL은 기술 업계에 잘 알려져 있고 일부 사람들은 이미 작동 방식에 익숙하므로 적절한 경우 가끔 이를 강조해도 좋습니다.

* **NerdGraph 탐색기.** 주로 &quot;NerdGraph 탐색기&quot; 또는 &quot;당사의 NerdGraph 탐색기&quot;라고 부르지만, NerdGraph가 정확히 무엇인지 명확하지 않은 문맥에서는 &quot;NerdGraph API 탐색기&quot;라고 부를 수 있습니다. 기타 팁:

  * NerdGraph 탐색기의 EU 및 JP 버전에는 다른 URL이 있으므로 일반적으로 탐색기 URL이 아닌 [NerdGraph 탐색기 문서 섹션](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#explorer)에 링크해야 합니다.
  * 다른 탐색기(예: REST API 탐색기 또는 엔티티 탐색기)와 충돌하므로 &quot;탐색기&quot;만 사용하는 것은 피하십시오.
  * 도움이 된다고 판단되는 경우, NerdGraph 탐색기가 GraphQL 쿼리를 구축하기 위한 오픈 소스 플랫폼인 GraphiQL로 구축되었다고 설명할 수 있습니다. GraphQL과 GraphiQL은 모두 업계에 알려져 있으므로 이를 설명하는 것이 도움이 될 수 있습니다.

* **Requests.** GraphQL 작업에는 쿼리와 뮤테이션이라는 두 가지 주요 유형이 있습니다([여기에서 정의됨](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology)). 이러한 용어를 사용하여 특정 예를 참조할 수 있습니다(예: &quot;다음은 ...하는 뮤테이션입니다.&quot;). 여러 종류의 다양한 NerdGraph requests를 일반적으로 참조하려면 &quot;requests.&quot;를 사용할 수 있습니다.

* **필드.** 필드는 쿼리할 수 있는 객체 유형의 요소입니다. 문맥에서 &quot;필드&quot;가 사용되는 예는 [이 NerdGraph 튜토리얼](/docs/nerdgraph-anomaly-detector-configurations-api-tutorial/#update-configuration)을 참조하십시오. 필드가 중요한 개념인 이유는 GraphQL 형식의 API를 사용하면 사용자가 반환받고자 하는 필드를 정확하게 지정하기 때문입니다(예를 들어 필요하지 않은 필드가 포함된 기본 응답을 반환할 수 있는 REST API와는 대조적입니다).

## NerdGraph 문서 작성 팁 [#creating-nerdgraph-docs]

NerdGraph 문서 범주에 속하지 않는 문서에 비교적 작은 섹션의 NerdGraph 관련 콘텐츠를 추가해도 괜찮습니다. 대략적인 가이드라인으로, NerdGraph 관련 콘텐츠가 한 페이지 이상인 경우 NerdGraph 문서 범주에 추가해야 합니다(가능한 경우 자체 문서 또는 관련 문서에 추가).

NerdGraph 문서 범주에 콘텐츠를 추가하는 경우, 콘텐츠를 효율적으로 구성하고 쉽게 찾을 수 있도록 다음 팁을 고려하십시오:

* **기존 튜토리얼에 콘텐츠를 추가하는 것을 고려하십시오.** 새 NerdGraph 콘텐츠를 추가할 때 기존 NerdGraph 문서에 새 콘텐츠를 포함할 수 있는지 확인하십시오. 이렇게 하면 튜토리얼 목록을 깔끔하게 유지하고 무분별하게 늘어나는 것을 방지할 수 있습니다. 예를 들어, 엔티티 보기 또는 구성과 관련된 내용을 추가하려는 경우 [엔티티 관련 NerdGraph 문서](/docs/apis/nerdgraph/examples/nerdgraph-entities-api-tutorial)에 추가할 수 있습니다.
* **모방할 문서를 선택하십시오.** 새 NerdGraph 튜토리얼 문서를 작성할 때 [이 NerdGraph 문서](/docs/apis/nerdgraph/examples/manage-accounts-nerdgraph)를 대략적인 템플릿으로 사용할 수 있습니다. 고객이 API 기능을 이해하는 데 필요하다고 생각되는 내용에 따라 이 구조를 자유롭게 변경할 수 있지만, 일반적인 구조는 많은 문서에 적용될 수 있습니다.
* 새로운 유형의 NerdGraph 콘텐츠를 추가할 때는 [NerdGraph 콘텐츠 색인](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#tutorials)에 추가하십시오. 해당 색인은 기본 NerdGraph 문서 섹션에 없는 튜토리얼을 사용할 수 있음을 반영하기 위해 생성되었습니다.

NerdGraph 콘텐츠를 작성할 때의 몇 가지 팁:

* **예제 requests.** 예제 requests 생성 팁:

  * 예제 응답 또는 오류 메시지에 `tags for customer-specific values in example queries and mutations. Remember that you don't need to use` 태그를 사용하십시오.
  * 요청의 일반적인 용도를 설명한 다음, 예제 요청이 단지 예제일 뿐이라는 점(무언가를 달성하는 유일한 방법이라고 전달하는 것과 반대)을 참고로 추가하는 것이 좋습니다. 예를 들어 다음과 같이 작성할 수 있습니다. &quot;NerdGraph를 사용하여 [API 테스트 신세틱 모니터](/docs/synthetics/synthetic-monitoring/getting-started/types-synthetic-monitors#types-monitors)를 업데이트할 수 있습니다. 다음은 ...하는 API 테스트 모니터를 생성하는 예제입니다.&quot;
  * requests의 형식을 정리하려면 NerdGraph 탐색기로 이동하여 requests를 입력하고 **Tools &gt; Prettify**를 클릭하십시오. requests는 실제 값이 있는 작동하는 것이어야 합니다.

* **필드 정의.** NerdGraph 탐색기에는 기본 제공 필드 정의가 포함되어 있지만 문서에서 더 복잡하거나 명확하지 않은 필드를 설명하는 것이 좋습니다. 모든 또는 대부분의 예제 requests에 사용되는 공통 필드의 경우, 이를 해결하는 한 가지 방법은 문서 상단 근처에 &quot;중요 개념&quot; 섹션을 만들고 여기에 권장 읽기 자료나 중요 필드에 대한 참고 사항을 포함하는 것입니다. 한두 개의 requests에만 사용되는 필드의 경우 예제 requests를 소개할 때 설명하는 것이 좋습니다.

## NerdGraph 스키마 문서 [#schema-docs]

NerdGraph 탐색기는 사용자가 다양한 필드가 무엇인지 이해할 수 있도록 NerdGraph 스키마 정의를 노출합니다. 문서 팀은 엔지니어링 팀이 제출한 스키마 문서를 검토합니다. 스키마 정의 검토가 이루어지는 방법에 대한 자세한 내용은 문서 팀의 리소스인 &apos;외부 문서 리포지터리&apos;를 참조하십시오.
