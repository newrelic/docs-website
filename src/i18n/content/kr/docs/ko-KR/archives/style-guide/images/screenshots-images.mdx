이미지는 문서의 중요한 부분입니다. 이미지는 절차를 따랐을 때 얻을 수 있는 결과를 사용자에게 보여줍니다. 까다로운 UI 경로를 통해 사용자를 안내하거나, [구성 파일 재정의](/docs/agents/python-agent/installation-configuration/python-agent-configuration#options)와 같은 복잡한 개념을 설명하거나, 때로는 시각적인 흥미를 더하는 데 도움이 될 수 있습니다.

이 문서는 이미지를 생성하고 유지 관리하기 위한 모범 사례를 설명합니다. 사이트에 이미지를 삽입하는 데 도움이 필요하면 [이미지 삽입](/docs/style-guide/processes-procedures/embed-images)을 참조하십시오. 이미지 주석을 추가하려면 [이미지 주석 사용을 위한 모범 사례](/docs/style-guide/images/image-annotations)를 참조하십시오.

## 이미지 설명 지침 [#identify-images]

보충 텍스트는 특히 그 자체로 이해하기 까다로울 수 있는 복잡한 스크린샷 및 기타 이미지에 유용한 컨텍스트와 설명을 제공할 수 있습니다. 접근성을 위해 항상 대체 텍스트를 포함해야 하지만, 다른 유형의 보충 텍스트는 선택 사항입니다.

* 대체 텍스트(필수)
* 제목(필수)
* 캡션
* 주변 텍스트

<Callout variant="important">
  스크린샷 내에 텍스트를 사용하지 마십시오. 대신 [캡션](/docs/style-guide/images/screenshots-images/#captions)을 사용하십시오. [이미지 주석 사용에 대한 모범 사례](/docs/style-guide/images/image-annotations)를 참조하십시오.
</Callout>

### 대체 텍스트(필수) [#alt-text]

시각 장애가 있는 독자가 화면 판독기를 사용하여 이미지에서 유용한 정보를 얻을 수 있도록 이미지 태그에 항상 대체 텍스트를 포함하십시오. 이는 콘텐츠나 명령(예: 버튼)이 포함된 이미지에만 적용됩니다.

<Callout variant="tip">
  대체 텍스트는 인라인 Feather 아이콘에 적용되지 않습니다.
</Callout>

대체 텍스트를 사용하는 경우:

* 간결한 이미지 설명을 사용하십시오.

* 주변 텍스트를 반복하지 마십시오 ― 화면 판독기가 이미 읽었습니다.

* 명확성을 목표로 하십시오. 완전한 문장일 필요는 없습니다.

* 어떤 방식으로든 이미지 유형을 식별하십시오:

  * `alt="Diagram showing the flow of data from client to server."`
  * `alt="Screenshot showing how to select a server."`
  * `alt="Photo of garden hose that serves as a metaphor for electrical amperage."`

### 캡션 [#captions]

캡션은 이미지 아래에 표시되며 독자에게 추가적인 문맥을 제공합니다.

다음 사항에 유의하십시오.

* 캡션은 짧게 유지하고 절차를 삽입하지 마십시오.
* 탐색이 메시지의 핵심 부분인 경우에만 캡션에 [탐색 경로](/docs/style-guide/formatting/ui-paths/)를 삽입하십시오.
* 주변 텍스트와 동일하지 않은 보완 정보를 삽입하십시오.
* 훑어보기 쉬운 캡션을 작성하십시오.
* 독자가 주변 텍스트를 살펴보도록 권장하십시오.
* 다른 곳에서는 제공되지 않는 필수 정보를 캡션에 넣지 마십시오.
* 절차 텍스트가 내용을 명확하게 설명하므로 절차 스크린샷에는 캡션이 필요하지 않습니다.

### 주변 텍스트 [#surrounding-text]

캡션이나 주석을 사용하지 않는 경우, 이미지 앞이나 뒤에 텍스트를 추가하여 유용한 컨텍스트를 제공하십시오.

주변 텍스트를 사용하여 이미지를 설명하는 경우:

* 직관적인 이미지를 사용하십시오.
* 이미지를 더 쉽게 이해할 수 있도록 주변 텍스트를 간결하게 유지하십시오.

## 이미지 파일 삭제 또는 이름 바꾸기 [#delete-rename-image]

당사의 i18n 번역된 .mdx 파일은 해당 영어 .mdx 파일과 일치해야 합니다. 영어로 된 이미지 파일을 삭제하거나 이름을 바꾸면 영어 파일과 번역된 파일 간에 불일치가 발생하여 빌드 오류가 발생할 수 있습니다. 이미지 파일을 삭제하거나 이름을 바꿀 때의 몇 가지 팁은 다음과 같습니다:

* 이미지 교체: 기존 이미지를 교체하는 경우 이미지 파일에 동일한 이름을 지정해야 합니다. 교체할 파일을 삭제하고 새 파일을 추가하십시오. 이렇게 하면 해당 이미지 파일에 대한 참조를 변경할 필요가 없습니다.
* 이미지를 제거하려면: 이미지를 교체하지 않고 단순히 제거하려면 이미지 파일을 삭제하지 마십시오. 대신 해당 이미지 파일에 대한 import 문만 제거하십시오. 문서 팀은 가끔 mdx 파일에서 참조하지 않는 이미지 파일을 제거하는 스크립트를 실행합니다. 즉, 이미지 파일을 삭제할 필요가 없으므로 번역 워크플로우를 통해 자동으로 업데이트되므로 i18n 디렉터리의 mdx 파일을 건드릴 필요가 없습니다.
* 이미지 파일의 이름을 바꾸려면: 먼저, 그렇게 할 필요가 있는지 질문해 보십시오. 이미지 파일 이름은 일반적으로 중요하지 않고 사소합니다. 이미지 파일의 이름을 바꾸기로 결정한 경우, 해당 이미지 파일을 참조하는 모든 mdx 파일(i18n 디렉터리 파일 포함)로 이동하여 해당 파일 이름을 업데이트해야 합니다.
