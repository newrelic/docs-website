뉴렐릭의 일부 팀은 GitHub 저장소에서 문서 콘텐츠를 자동으로 생성합니다. 이러한 자동 생성된 문서가 기본 문서 저장소(`https://github.com/newrelic/docs-website`)에 대한 pull 요청에 나타나면, 작성자는 수동으로 생성된 문서와 다소 다르게 편집해야 합니다.

<Callout variant="tip">
  GitHub에서 작성자를 확인하여 문서가 자동으로 생성되었는지 여부를 확인할 수 있습니다.
</Callout>

## 자동으로 생성된 문서 편집 시의 과제 [#challenges]

자동화된 문서를 편집할 때, 이는 다음 릴리스에 대해 동일한 문서를 생성하는 기본 자동화를 해결하지 않습니다.

두 가지 문제를 해결하는 문서 편집 루틴이 필요합니다:

* 현재 자동으로 생성된 pull 요청이 게시를 위해 수정되었는지 확인합니다.
* 이러한 자동 생성 문서의 기본 소스가 변경되도록 합니다.

## 자동으로 생성된 문서 편집을 위한 모범 사례 [#best-practices]

저장소에서 자동으로 생성된 문서를 검토할 때 다음을 수행하십시오:

1. 변경 사항을 직접 푸시하는 대신 GitHub 제안을 작성하십시오.

2. 변경 사항을 푸시한 팀의 문서 담당자에게 문의하십시오:

   * 이것은 개발자에게 귀하가 만든 제안을 알립니다.
   * 제안을 수락하거나 거부합니다.

3. 제안이 수락되면 해당 변경 사항을 병합하고 현재 릴리스를 게시하십시오.

4. 제안 사항을 기본 소스에도 적용해야 하는 경우, 해당 팀의 저장소에 Github 이슈를 생성하십시오. 해당 GitHub 이슈에서 공개 문서 사이트의 pull 요청에 연결하십시오. 이렇게 하면 향후 자동화된 릴리스를 수정할 수 있도록 개발 팀에 공지합니다. 다음은 후속 GitHub 이슈를 생성할 수 있는 저장소의 몇 가지 예입니다:

   * Node.js(`https://github.com/newrelic/node-newrelic`)
   * 루비(`https://github.com/newrelic/newrelic-ruby-agent`)

<Callout variant="tip">
  Node.js 문서의 경우, 제안한 내용이 자동 문서의 마커 태그(`{/* begin: compat-table */}` 및 `{/* end: compat-table */}`) 사이에 있는 경우에만 해당 GitHub 이슈를 생성하면 됩니다. 해당 섹션 외부의 변경 사항은 자동화의 영향을 받지 않습니다.
</Callout>
