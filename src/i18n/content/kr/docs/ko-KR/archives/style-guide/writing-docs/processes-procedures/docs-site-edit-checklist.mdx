새 문서를 작성할 때 확인해야 할 사항이 많습니다. 이 체크리스트를 사용하여 모든 작업을 완료했는지 확인할 수 있습니다.

## Title \[제목]

다음을 확인하십시오:

* 문서의 제목은 내용을 효과적으로 설명합니다.
* 절차 문서 제목은 능동 동사를 사용합니다, 예를 들어 `Installing`이(가) 아닌 `Install`을(를) 사용합니다.

## 소개 [#intro]

다음을 확인하십시오:

* 소개는 결과로 시작하여 목표에 도달하는 방법에 대한 개요를 제공하므로, 고객은 올바른 문서를 찾았다고 확신할 수 있습니다.
* 문서 내용에 대한 짧고 읽기 쉬운 개요를 제공합니다.

## 제목(H2) [#headings]

다음을 확인하십시오:

* 제목은 간결하지만 독자가 원하는 섹션을 훑어보거나 건너뛸 수 있도록 돕는 정보를 제공합니다.
* 절차적 H2는 `ing` 동사 형태가 아닌 능동태 동사를 사용합니다.

## 텍스트

텍스트가 다음과 같은지 확인하십시오:

* 더 쉬운 번역을 위한 최적화: 관용구, 속어, 특정 문화적 참조 등을 피하십시오.
* 좋은 스토리를 전달합니다: 플랫폼(기타 뉴렐릭 제품, 알림 등)을 홍보합니다. 예제와 사용 사례를 포함하고, 페르소나를 식별하며, 무엇인지 또는 어떻게 사용하는지뿐만 아니라 왜 중요한지 설명합니다.
* [UI 경로의 하이퍼링크](/docs/style-guide/quick-reference/usage-dictionary#ui-path)를 포함합니다.
* 오타가 없습니다.

## 절차

절차는 능동태를 사용하고 단계(&quot;이렇게 하십시오&quot;)에 중점을 둡니다. 단계에 팁이나 추가 세부 정보를 숨기지 마십시오.

* 절차에 전제 조건이나 배경 정보가 포함된 경우, 해당 정보는 순서가 지정된 절차 목록 앞(내부에 숨겨져 있지 않음)에 나타납니다.
* 절차나 단계가 분기되는 경우 옵션을 분할하여 글머리 기호, 축소기 등으로 명확하게 표시되도록 합니다.
* 절차에 하지 말아야 할 사항이 명시되어 있다면, 대신 해야 할 사항도 설명합니다.

**예시: 하지 말아야 할 것과 대신 해야 할 것**

파트너십 소유자 계정에서 자신의 애플리케이션을 모니터하지 마십시오. 대신 파트너십 내에 계정을 생성하고 해당 계정에서 앱을 모니터하십시오.

## 구조

초안 문서가 완전한지 여부를 가장 잘 판단할 수 있는 사람은 원본 테크니컬 라이터 또는 문서 사이트 기여자입니다. 하지만 동료 편집 시 문서나 상호 참조에서 다루지 않아 해결되지 않은 질문이 있다면 메모를 남겨 주십시오.
