UI 페이지와 요소를 찾을 수 있는 위치를 설명하는 것은 까다로울 수 있습니다. 경로 설명을 잘 작성하면 독자가 UI를 더 쉽게 탐색할 수 있습니다. 짧은 UI 경로와 긴 UI 경로를 처리하기 위한 다양한 옵션이 있습니다.

## 좋은 UI 경로를 작성하기 위한 가이드라인

UI 경로에 대한 당사의 목표는 이해하고 따라가기 쉽게 만드는 것이며, 가급적 대화체로 작성하는 것입니다. 절대적인 일관성에 얽매이지는 않지만, UI와 상호 작용하는 사용자에게 불필요한 모호함을 주지 않도록 경로가 일반적인 패턴을 따르기를 바랍니다.

## 다음 UI 경로 지정 예시를 따르십시오. [#examples]

경로의 길이는 접근 방식에 영향을 미쳐야 합니다. 간단한 3단계 탐색은 완전히 대화형일 수 있는 반면, 다단계 절차는 정렬된 목록일 수 있습니다. 그리고 3단계 이상 깊이 묻혀 있는 항목의 경우 `**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > y > z**` 규칙을 사용하는 것을 고려해 보십시오.

다음은 적절한 굵은 글꼴 스타일이 적용된 실제 경로 지정 스타일입니다.

      </td>
    </tr>

    <tr>
      <td>

        3. 세부정보를 보려면 스팬을 선택하십시오.
      </td>
    </tr>

      </td>
    </tr>

        더 긴 경로는 작업으로 끝날 수 있습니다. `>`(으)로 묶인 UI 경로 부분은 굵게 표시하고 마지막 작업은 굵게 표시하지 마십시오. 더 긴 UI 경로에 중첩된 작업에만 괄호를 사용하십시오.

## 최선의 판단을 내리십시오. [#judgment]

UI 경로를 작성할 때 어려움이 있다면 최선의 판단을 내리십시오. UI 경로의 형식을 지정하거나 표현하는 가장 좋은 방법은 경로의 길이와 문맥에 따라 달라질 수 있습니다.
