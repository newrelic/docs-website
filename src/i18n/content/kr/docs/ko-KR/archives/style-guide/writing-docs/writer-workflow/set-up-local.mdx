사이트를 로컬에서 실행하면 대규모 변경 사항을 훨씬 쉽게 테스트하고 미리 볼 수 있습니다. 이 기능을 작동시키려면 몇 가지 작업을 수행해야 합니다. 다행히 이 작업은 한 번만 수행하면 됩니다.

## 터미널 및 명령줄 사용 [#terminal]

macOS에서는 터미널 앱을 사용하여 시스템의 명령줄에 액세스할 수 있습니다. (VS Code를 통해서도 터미널에 액세스할 수 있습니다.) 명령줄은 그래픽 사용자 인터페이스의 대안입니다.

유용할 수 있는 몇 가지 기본 터미널 명령은 다음과 같습니다:

* `pwd` (print working directory): 디렉터리 경로를 보려면 이를 사용하십시오.
* `ls` (list): 현재 디렉터리의 파일을 표시합니다.
* `cd YOUR_DIRECTORY_PATH` (디렉터리 변경): 다른 디렉터리로 이동합니다.
* `cd ..`: 경로에서 한 디렉터리 위로 이동합니다.

## 터미널에서 VS Code를 활성화하십시오. [#code-terminal]

터미널에서 VS Code로 직접 파일을 열 수 있으면 편리합니다. 이 기능은 몇 번만 사용할 수도 있지만, 터미널 자체에서 파일을 편집하는 것보다 훨씬 좋습니다.

1. Visual Studio Code를 엽니다.
2. **Command+Shift+P**를 눌러 명령 팔레트를 연 다음 `install code`을(를) 입력하고 **Shell command: Install &apos;code&apos; command in PATH**를 클릭하십시오.
3. 터미널에서 `code` YOUR\_FILENAME\`을 입력하여 VS Code에서 해당 파일을 엽니다.

## 1. GitHub Desktop을 사용하여 로컬 저장소를 설정하십시오. [#repo-setup]

GitHub Desktop은 브랜치, 커밋 및 PR을 관리하기 위한 그래픽 도구입니다. Git 및 GitHub로 작업하는 가장 간단한 방법일 것입니다.

1. GitHub Desktop을 설치하십시오.
2. GitHub 계정을 통해 GitHub Desktop에 로그인하십시오. Mac의 경우 화면 왼쪽 상단에서 **GitHub Desktop**을 클릭하고 **Preferences**를 선택하십시오. 파란색 **Sign In** 버튼을 선택하고 브라우저 창의 프롬프트를 따르십시오.
3. [문서 사이트 저장소](https://github.com/newrelic/docs-website)로 이동하십시오.
4. 녹색 **Code** 버튼을 클릭하고 **Open with [GitHub Desktop](https://desktop.github.com/)**을 선택하십시오.
5. 원하는 리포지터리 위치를 선택합니다. 이 폴더의 기본 위치는 `~/Documents/github`입니다.
6. 전체 저장소를 로컬 머신에 복제하십시오.

## 2. 전체 디스크 액세스 활성화 [#disk-access]

기본적으로 macOS는 터미널이 `Documents`와(과) 같은 특정 시스템 폴더에 액세스하는 것을 차단하는 것 같습니다. 터미널을 통해 파일 시스템을 더 쉽게 탐색할 수 있도록 이 설정을 변경하십시오.

1. **시스템 환경설정**을 여십시오.
2. **Security &amp; Privacy** \[보안 및 개인정보 보호]를 클릭하십시오.
3. 왼쪽 창에서 **Full Disk Access**를 찾을 때까지 아래로 스크롤한 다음 선택하십시오.
4. 왼쪽 하단 모서리에 있는 자물쇠를 클릭한 다음 컴퓨터에 로그인할 때 사용하는 비밀번호를 입력하십시오.
5. 앱 목록에서 **Terminal** (또는 기본 터미널 애플리케이션) 옆의 확인란을 선택하십시오.
6. 잠그려면 자물쇠를 클릭하십시오.

## 3. Homebrew 설치 [#homebrew]

Homebrew는 다른 애플리케이션을 설치하기 위한 명령줄 도구입니다. 또한 명령줄 소프트웨어를 쉽게 최신 상태로 유지할 수 있는 방법이기도 합니다.

1. 터미널을 여십시오.

2. 이 명령을 복사하여 터미널에 붙여넣습니다:

   ```shell
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

## 4. npm(Node.js 패키지 매니저)을 설치합니다. [#npm]

`nvm` (Node.js 버전 관리자)도 설치할 수 있도록 `npm`을(를) 설치해야 합니다. 터미널에 `brew install npm`을(를) 입력하십시오.

## 5. nvm(Node version manager) 설치 [#nvm]

노드 버전 관리자(`nvm`)는 컴퓨터에 설치된 Node.js의 버전을 관리하는 데 사용하는 것입니다. 터미널에 `npm i -g nvm`을(를) 입력하십시오.

## 6. 셸 프로필에 nvm을 추가하십시오. [#add-nvm]

로컬 빌드에 필요한 명령을 실행하려면 셸 프로필에 `nvm`의 경로를 추가해야 합니다.

macOS에서 셸은 명령줄에 입력하는 내용을 해석합니다. 기본 macOS 셸은 Zsh입니다. 어디서나 이러한 명령을 실행할 수 있도록 컴퓨터에 `nvm`이(가) 있는 디렉터리를 셸에 알려야 합니다.

셸의 구성 파일인 `.zshrc` 파일에 다음 텍스트를 추가하여 이 작업을 수행합니다.

1. 터미널에서 `code ~/.zshrc`을(를) 입력하여 VS Code에서 이 파일을 엽니다.

2. `.zshrc` 파일에 다음 텍스트를 복사하여 붙여넣으십시오:

   ```shell
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
   ```

3. 파일을 저장합니다.

## 7. Node.js 설치 [#node]

`nvm`을(를) 설치한 후에는 올바른 버전의 Node를 설치할 수 있습니다. Node 또는 Node.js는 Gatsby 사이트와 그 종속성을 구동하는 JavaScript 엔진입니다. Node.js 버전 16을 설치하려면 `nvm use 18`을(를) 입력하십시오.

## 8. Yarn 설치 [#yarn]

Yarn은 사이트를 로컬로 빌드하기 위해 **docs-website** 리포지터리의 모든 파일을 컴파일하는 데 사용되는 또 다른 패키지 매니저입니다. npm을 사용하여 Yarn을 설치하십시오. 터미널에 `npm i -g yarn`을(를) 입력하십시오.

## 로컬 사이트 빌드 [#local-site]

터미널에 이 모든 것을 설치하고 나면 컴퓨터에서 로컬로 사이트를 실행할 수 있습니다.

1. 터미널에 `pwd`을(를) 입력하여 **docs-website** 저장소 디렉터리에 있는지 확인하십시오.
2. 모든 Gatsby 종속성이 최신 상태인지 확인하려면 `yarn`을(를) 입력하십시오.
3. `yarn start`을(를) 입력하여 사이트를 로컬로 빌드합니다.
4. 프로세스가 완료되면 웹 브라우저에서 `http://localhost:8000`(으)로 이동하십시오.

`yarn start`을(를) 실행하면 터미널에 여러 줄의 텍스트가 출력됩니다. 로컬 빌드가 실패하는 경우, 터미널 출력은 종종 무엇이 잘못되었는지에 대한 단서를 제공합니다.

기본적으로 사이트는 번역된(jp, kr) 페이지 없이 빌드됩니다. 해당 페이지도 빌드하려면 `yarn start:full`을(를) 실행할 수 있습니다.

## 로컬 사이트의 일부 빌드(더 빠름) [#local-site-speed]

사이트를 더 빠르게 빌드하려면 사이트의 모든 문서 대신 단일 폴더(또는 원하는 만큼의 폴더)를 빌드하도록 선택할 수 있습니다. 예를 들어 계정 문서에서 작업 중이라는 것을 알고 있다면 계정 폴더만 빌드할 수 있으므로 유용할 수 있습니다. 하지만 이는 지정한 폴더 외부의 폴더에 있는 문서를 방문하려고 하면 `404`을(를) 보게 된다는 의미입니다.

하나 이상의 특정 폴더를 빌드하려면 `yarn start` 명령에 다음 변수를 추가하십시오:

`BUILD_FOLDERS=mlops yarn start` 또는 `BUILD_FOLDERS=apm,logs,errors-inbox yarn start`

팁:

* 지정한 폴더는 `/src/content/docs/` 디렉터리의 루트 수준에 있어야 합니다. 여기에는 하위 디렉터리가 포함되지 않습니다. 예를 들어 `browser`은(는) 유효한 폴더이지만, `browser-monitoring`은(는) `browser`의 하위 디렉터리이므로 유효하지 않습니다.
* 폴더 목록에서 쉼표 뒤에 공백이 없는지 확인하십시오. 예를 들어, `BUILD_FOLDERS=apis, infrastructure`이(가) 아닌 `BUILD_FOLDERS=apis,infrastructure`을(를) 입력하십시오.
