GitHub의 버전 제어 기능을 사용하면 문서의 전체 기록을 확인하고, 언제든지 문서에 액세스하며, 수동 백업 없이 삭제된 문서를 찾을 수 있습니다.

## 문서 또는 파일의 편집 기록을 확인합니다. [#doc-history]

파일의 기록을 확인하거나 &quot;diff&quot;하려면 다음 옵션 중 하나를 사용하십시오.

**옵션 1: GitHub 기록 탭**

1. 문서 사이트의 문서로 이동하여 오른쪽 탐색 메뉴에서 **Edit page** \[페이지 편집]을 클릭하십시오.
2. 문서 오른쪽 상단 코너에 있는 **History**를 클릭합니다.

**옵션 2: githistory.xy**

1. GitHub.com의 특정 파일로 이동하십시오:

   ```
   https://github.com/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

2. URL에서 `github.com`을 `github.githistory.xyz`로 바꿉니다:

   ```
   https://github.githistory.xyz/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

3. 해당 특정 파일의 시각적 기록을 보여주는 사이트로 이동합니다. 페이지 상단의 커밋 기록을 클릭하여 변경 사항을 볼 수 있습니다.

**옵션 3: Git blame**

[GitHub의 문서](https://docs.github.com/en/github/managing-files-in-a-repository/managing-files-on-github/tracking-changes-in-a-file)를 따르십시오.

또는 터미널에서 다음 명령을 사용할 수 있습니다:

```bash
git log --follow "**/file_name_here.mdx"
```

해당 파일의 커밋 기록이 출력됩니다. 기본적으로 처음 몇 개의 커밋만 표시됩니다. `Return`을(를) 여러 번 눌러 스크롤할 수 있습니다.

예를 들어 `vmware-vsphere-monitoring-integration.mdx`의 커밋 기록을 찾으려면 다음을 실행하십시오:

```bash
git log --follow "**/vmware-vsphere-monitoring-integration.mdx"
```

## 2021년 10월 이전의 문서 사이트 기록 [#archived-version]

2021년 10월에 대규모 사이트 개편이 있었으며, 이로 인해 문서의 파일 기록 대부분이 손실되었습니다. 재작업 이전 당사 사이트의 아카이브 버전은 [pre-IA-2021](https://github.com/newrelic/docs-website/tree/pre-IA-2021) 브랜치에서 확인할 수 있습니다. 당사 리포지터리의 재작업 이전 버전을 탐색하여 파일 기록 등을 확인할 수 있습니다.

## 삭제된 파일을 찾는 방법 [#deleted-files]

삭제된 파일을 찾는 방법에는 여러 가지가 있습니다. 복잡성에 따라 대략적으로 정렬하면 다음과 같습니다.

<CollapserGroup>
  <Collapser className="freq-link" id="pr" title="삭제 pull 요청 찾기">
    삭제된 파일을 찾는 가장 쉬운 방법은 해당 파일을 삭제한 pull 요청을 찾는 것입니다. 이를 달성하는 방법에는 여러 가지가 있으며, 다음은 몇 가지 아이디어입니다:

    1. GitHub의 검색 기능을 사용하여 관련 키워드를 검색하십시오. 검색 결과를 필터링하여 PR만 포함할 수 있습니다.
    2. 문서가 삭제된 시기를 대략적으로 알고 있다면, pull 요청 탭에서 pull 요청을 찾아볼 수 있습니다. 이 목록에는 수천 개의 PR이 있으므로 시간이 다소 걸릴 수 있습니다.
    3. Jira 지원 티켓으로 인해 많은 문서가 삭제됩니다. Jira에서 해당 지원 티켓을 검색하면 문서가 삭제된 대략적인 시간과 PR 자체에 대한 링크를 찾을 수 있습니다.
    4. \#doc\_talk에 문의하십시오!
  </Collapser>

  <Collapser className="freq-link" id="releases" title="릴리스 PR 검색">
    릴리스 PR을 검색하면 문서가 삭제되기 전에 생성된 브랜치를 찾을 수 있습니다. [GitHub PR 탭](https://github.com/newrelic/docs-we.bsite/pulls?q=is%3Apr+release+is%3Aclosed)에서 릴리스 PR 목록을 찾을 수 있습니다.

    몇 가지 팁:

    * 먼저 한 달 간격으로 검색하십시오. 문서가 포함된 브랜치를 찾으면 범위를 일주일로 좁힌 다음 하루로 좁힐 수 있습니다. 범위를 줄이면 결국 삭제되기 전의 정확한 상태로 삭제된 문서를 찾을 수 있습니다.
    * PR이 시작된 브랜치에 액세스하려면 해당 pull 요청의 페이지로 이동하여 제목과 PR 번호 아래에 있는 브랜치 이름을 클릭하십시오.
  </Collapser>

  <Collapser className="freq-link" id="git-log" title="git 로그 사용">
    삭제된 파일을 찾는 가장 강력하고 확실한 방법은 `git log`을(를) 사용하는 것입니다. 자세한 내용은 [StackOverflow](https://stackoverflow.com/questions/7203515/how-to-find-a-deleted-file-in-the-project-commit-history/7203551#7203551)를 참조하십시오.
  </Collapser>
</CollapserGroup>
