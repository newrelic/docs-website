## 로컬 빌드에서 404 오류가 발생합니다. [#build-fails]

### 문제

localhost:8000을 빌드하려고 할 때 하나 또는 모든 웹페이지에서 404 오류가 발생합니다.

### 솔루션

로컬 빌드에서 무엇이 잘못되었는지 파악하려면 다음 해결책 중 일부를 시도해 보십시오.

<CollapserGroup>
  <Collapser className="freq-link" id="troubleshoot-file" title="문제가 있는 파일 문제 해결">
    어떤 파일에서 오류가 발생하는지 알고 있다면 다음 명령을 실행하여 오류를 식별하십시오:

    ```bash
    yarn verify-mdx path/to/file.mdx
    ```

    이 명령은 오류를 일으키는 특정 문자 및 줄 번호와 같이 일반적인 Gatsby 출력보다 오류에 대한 더 많은 정보를 반환합니다.

    <CollapserGroup>
      <Collapser className="freq-link" id="example" title="예시">
        제 브랜치의 여러 문서에 변경 사항을 적용했다고 가정해 보겠습니다. 사이트를 로컬에서 실행하거나 Netlify 빌드에 액세스하려고 하면 다음 오류가 발생합니다:

        ```
        Unexpected character = (U+003D) before name, expected a character that can start a name, such as a letter, $, or _/usr/src/app/www/src/content/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx: Unexpected character = (U+003D) before name, expected a character that can start a name, such as a letter, $, or _
        ```

        오류는 오류가 있는 문서가 `/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx`에 있음을 알려줍니다. 그 외에 아는 것은 어딘가에서 `=` 문자가 문제를 일으키고 있다는 것뿐입니다. 좋습니다. 하지만 이것은 NRQL 문서이며 수십 개의 `=` 문자가 있습니다.

        따라서 `yarn verify-mdx src/content/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx`을 실행합니다. 다음과 같이 반환됩니다:

        ```json
        reading src/content/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx
        {
          "message": "Unexpected character `=` (U+003D) before name, expected a character that can start a name, such as a letter, `$`, or `_`",
          "name": "284:227",
          "reason": "Unexpected character `=` (U+003D) before name, expected a character that can start a name, such as a letter, `$`, or `_`",
          "line": 284,
          "column": 227,
          "location": {
            "start": {
              "line": 284,
              "column": 227,
              "offset": 19129,
              "index": 1
            },
            "end": {
              "line": null,
              "column": null
            }
          },
          "source": "remark-mdx",
          "ruleId": "unexpected-character",
          "fatal": true
        }
        ```

        이 경우 관련 정보는 다음과 같습니다:

        ```json
        "line": 284,
        "column": 227,
        ```

        그리고

        ```json
        "source": "remark-mdx",
        "ruleId": "unexpected-character",
        "fatal": true
        ```

        이는 284번째 줄, 227번째 열에 예기치 않은 문자가 있음을 알려줍니다. 그런 다음 오류가 발생한 위치를 정확히 파악하여 문서의 해당 섹션으로 이동해 추가로 문제를 해결할 수 있습니다. 이 경우, NRQL 예제를 따옴표로 묶기만 하면 됩니다.
      </Collapser>
    </CollapserGroup>

  <Collapser className="freq-link" id="" title="일반적인 구문 오류를 확인하십시오.">
    변경된 파일에서 다음과 같은 일반적인 마크다운 구문 오류가 있는지 확인하십시오:

    * nav 파일의 일관되지 않은 들여쓰기

    * 잘못된 프런트 매터 구문
      * 프런트매터 필드에 아포스트로피와 콜론이 있는 경우, 문제가 발생하지 않도록 따옴표로 묶으십시오.

    * 누락된 닫힌 괄호 또는 태그

    * 형식이 잘못된 이미지 링크

      * 각 이미지 가져오기 문 사이에 새 줄이 있는지 확인하십시오.
      * 이미지 및 해당 파일 이름 경로의 이름을 바꿀 때 주의하십시오. 불일치로 인해 전체 로컬 빌드가 실패할 수 있습니다.
      * 가져온 이미지 파일을 다룰 때는 특히 주의하십시오.

    * 잘못된 이미지 파일 이름

      * 이미지 파일 이름은 대소문자를 구분합니다. 대소문자를 잘못 사용하면 문서에서 이미지가 누락됩니다.
      * 파일 이름에 인코딩된 값(% 등)이 있는 이미지는 특히 까다로울 수 있으므로 피하십시오.
  </Collapser>

  <Collapser className="freq-link" id="restart-yarn" title="yarn을 중지하고 다시 시작하십시오.">
    yarn을 중지하고 다시 시작하려면:

    1. 터미널에서 `/docs-website` 디렉터리에 있는지 확인하십시오.
    2. (터미널이 활성화된 경우) CONTROL+C를 눌러 yarn 프로세스를 중단하십시오.
    3. 이 명령을 실행하여 localhost:8000에서 실행 중인 모든 서비스를 중지하십시오:
       ```bash
       kill -9 $(lsof -i TCP:8000 | grep LISTEN | awk '{print $2}')
       ```
    4. yarn을 다시 시작하려면 다음 명령을 실행합니다:
       ```bash
       yarn clean && yarn && yarn start 
       ```
  </Collapser>

  <Collapser className="freq-link" id="check-branch" title="문제가 있는 브랜치를 식별하십시오">
    문제를 일으키는 브랜치를 식별하려면:

    1. 터미널에서 `docs-website` 디렉터리에 있는지 확인하십시오.
    2. 필요한 경우 CONTROL+C를 눌러 yarn 프로세스를 중단하십시오.
    3. GitHub Desktop에서 브랜치에 필요한 변경 사항을 커밋한 다음, develop 브랜치로 전환하십시오.
    4. 터미널로 돌아가서 `yarn && yarn start`을(를) 실행하십시오.

    이제 사이트가 develop 브랜치에서 올바르게 빌드된다면, 문제는 브랜치의 변경 사항에 있는 것입니다. Yarn을 다시 중지하고 브랜치로 돌아가서 문제를 해결하십시오.
  </Collapser>

  <Collapser className="freq-link" id="clean-cache" title="로컬 캐시를 정리하십시오.">
    로컬 캐시를 제거하려면 `yarn clean`을(를) 실행하십시오. 이렇게 하면 다음 빌드 속도가 느려지므로 시간이 충분한지 확인하십시오!

    1. 터미널에서 docs-website 디렉터리에 있는지 확인하십시오.
    2. 필요한 경우 CONTROL+C를 눌러 yarn을 중지하십시오.
    3. `yarn clean && yarn && yarn start`을(를) 실행하여 새 빌드를 시작하십시오.
  </Collapser>

  <Collapser className="freq-link" id="remove-cache" title="손상된 캐시 파일 제거">
    .cache 디렉터리가 손상되는 경우가 있을 수 있습니다. 이 디렉터리는 Git에서 무시되므로 브랜치 간에 이동할 때 함께 이동합니다. 현재 위치한 브랜치에 관계없이 로컬 빌드가 실패하는 경우 이것이 문제일 수 있습니다.

    `/docs-website` 디렉터리에서 이 문제를 해결하려면 `rm -rf .cache`을(를) 실행하십시오.
  </Collapser>

  <Collapser className="freq-link" id="start-build" title="처음부터 빌드 시작">
    처음부터 빌드를 시작하면 모든 노드 모듈, 숨겨진 .cache 폴더 및 로컬 캐시가 삭제됩니다. 실행하는 데 10～20분 정도의 긴 시간이 걸립니다.

    1. 터미널에서 docs-website 디렉터리에 있는지 확인하십시오.

    2. 필요한 경우 CONTROL+C를 눌러 yarn을 중지하십시오.

    3. `yarn reboot`을(를) 실행하십시오(또는 Keyboard Maestro 명령 `kknuke`\* 사용).

       \* `kknuke` Keyboard Maestro 명령을 사용하는 경우, 모든 작업이 완료되면 `yarn start`을(를) 실행하여 사이트를 시작하십시오.
  </Collapser>

  <Collapser className="freq-link" id="run-incognito" title="비공개 모드에서 로컬 빌드를 실행하십시오">
    때로는 로컬 사이트가 빌드되지만 사이트 내의 페이지는 빌드되지 않습니다. 이 문제를 해결하려면 비공개 또는 시크릿 세션에서 로컬 빌드를 실행해 보십시오. 브라우저의 캐시를 지워볼 수도 있습니다.
  </Collapser>
</CollapserGroup>

## 필수 빌드 검사 실패 [#check-fail]

### 문제

PR을 생성할 때 `required` 검사 중 하나가 통과하지 못합니다.

<Callout variant="tip" title="메모">
  선택적 검사는 릴리스를 차단하지 않으므로 선택적 검사가 실패하더라도 PR을 병합해도 됩니다. 그러나 검사에 대해 더 조사하고 싶다면 도움말 채널에 메시지를 보내 히어로가 실패 원인을 조사하도록 할 수 있습니다.
</Callout>

### 해결책

검사가 실패하는 경우, 먼저 PR을 닫았다가 다시 열어보십시오.

그런 다음 검사를 다시 실행하십시오:

1. PR로 이동합니다.
2. **Details &gt; Re-run jobs**을 클릭하십시오.

이 방법이 작동하지 않으면 검사를 재설정해야 하며, 이로 인해 캐시가 강제로 다시 빌드됩니다:

1. 로컬 리포지터리에서 `gatsby-config.js` 파일을 찾으십시오(또는 VSCode에서 CMD-P를 사용하여 빠르게 이동하십시오).

2. 코드의 첫 번째 줄과 두 번째 줄을 바꾸십시오(Gatsby Build 검사에서 캐시를 다시 빌드하도록 하는 것 외에는 이 줄의 순서는 중요하지 않습니다):

   ```js
   const fs = require('fs');
   const parse = require('rehype-parse');
   ```

3. 파일을 저장하고 변경 사항을 PR에 커밋하십시오.

4. 빌드 검사를 다시 실행하십시오.

5. 매우 오랫동안 기다리십시오.

## PR 병합 충돌 [#merge-conflict]

### 문제

로컬 브랜치에서 PR을 병합하려고 하면 병합 충돌이 발생합니다.

### 해결책

병합 충돌이 발생하는 경우 Github 데스크톱 또는 브라우저에서 **Resolve conflict**를 클릭하고 충돌을 한 줄씩 검토하십시오. 병합 충돌을 해결한 후 승인자에게 PR을 검토하도록 요청하십시오.

#### 병합 충돌 방지

병합 충돌을 방지하기 위한 몇 가지 권장 사항은 다음과 같습니다:

* develop 또는 main으로 병합하기 전에 **Fetch origin**을 클릭하여 최신 버전의 develop 또는 main을 가져왔는지 확인하십시오.
* 분류 체계 변경 작업을 수행 중인 경우, 병합 충돌을 가능한 한 빨리 해결하십시오. 브랜치가 한동안 남아 있으면 develop에서 꽤 빨리 구식이 될 수 있으며 이로 인해 예기치 않은 문제가 발생할 수 있습니다.
* 새로운 소식 게시물에서 병합 충돌이 발생하는 경우, 사이트가 빌드될 때 자동으로 업데이트되는 `whats-new-ids.json` 파일이 꽤 빨리 구식이 될 수 있기 때문입니다. <Callout variant="caution">`whats-new-ids.json`을(를) 변경하는 PR은 절대 병합하지 마십시오. GitHub Desktop에 `whats-new-ids.json` 파일의 변경 사항이 표시되면 브랜치로 푸시하지 말고 폐기하십시오. 이렇게 하면 다른 사람들이 이 파일과 관련된 병합 충돌을 처리해야 할 가능성이 줄어듭니다.</Callout>

## 포트 8000을 사용할 수 없습니다. [#local-site]

### 문제

`yarn start`을(를) 실행하려고 하면 터미널이 다음과 같이 응답합니다:

```bash
[output] Something is already
[output] running at port 8000. Would you like to run the app at another port instead?
```

### 해결책

localhost:8000에서 실행 중인 모든 서비스를 중지하려면 터미널에서 다음 명령을 실행하십시오:

```bash
kill -9 $(lsof -i TCP:8000 | grep LISTEN | awk '{print $2}')
```

## 리디렉션 링크에서 404 오류 발생 [#redirect-404]

### 문제

로컬 빌드에서 리디렉션 링크를 클릭하면 404 오류가 발생합니다.

### 해결책

리디렉션은 로컬 빌드에서 로드하는 데 오랜 시간이 걸립니다. 리디렉션을 클릭할 때 404가 발생할 때까지 기다린 다음 -1-2분 정도 기다리십시오. 잠시 후 리디렉션될 것입니다. 그렇지 않은 경우, 마크다운 구문을 확인하여 리디렉션을 올바르게 설정했는지 확인하십시오.

Gatsby 빌드에서 리디렉션을 테스트할 수도 있습니다.

## SSH 인증 실패 [#authentication-fail]

### 문제

원격 브랜치에 커밋을 푸시하려고 하면 SSH 인증 오류가 발생합니다.

### 해결책

때로는 Github Desktop에서 로그인/로그아웃하면 인증 문제가 해결될 수 있습니다:

1. 상단 메뉴 표시줄에서 **환경설정**으로 이동하십시오.
2. 로그아웃하고 다시 로그인하십시오.

이 방법이 작동하지 않으면 원격 브랜치에 커밋을 푸시해 보십시오. 여전히 실패하면 터미널을 사용하여 수동으로 PR을 푸시해 보십시오. 예를 들어, PR `second-kafka-pr-for-issue-11231`을(를) 푸시하려면 다음 명령을 실행합니다:

```bash
git push --set-upstream origin second-kafka-pr-for-issue-1123
```

SSH 문제가 있는 경우 터미널에서 인증 오류 메시지를 반환합니다. 이 명령에 대한 응답으로 암호를 요구하는 프롬프트가 표시되면 SSH에 혼선이 생긴 것입니다. 암호를 입력하면 다시 정상적으로 작업을 진행할 수 있습니다. 암호가 기억나지 않는 경우 [이 문서를 확인하십시오](https://docs.github.com/en/github/authenticating-to-github/troubleshooting-ssh/recovering-your-ssh-key-passphrase).
