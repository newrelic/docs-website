이 스타일 가이드 페이지는 문서의 표준 프런트매터를 설명하고, 사이트에서 유지 관리하는 다양한 유형의 콘텐츠에 대해서도 간략하게 설명합니다.

## 문서 프런트매터 및 메타데이터 [#meta-fields]

모든 문서의 상단은 메타데이터 세트로 시작합니다. 이 메타데이터 콘텐츠에 대한 자세한 내용은 계속해서 읽어보십시오:

  <thead>
    <tr>
      <th width={150}>
        **메타 콘텐츠 필드**
      </th>

      <th>
        **설명**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        `title`
      </td>

      <td>
        문서의 기본 제목으로, 문서 상단에 `<h1>` HTML 헤더로 표시되며 브라우저 페이지 제목 및 검색 엔진 메타 필드에 나타납니다.

        가능한 경우 작업 지향적이거나 태스크 지향적인 제목을 제공하십시오, 예를 들어 &quot;AJAX 페이지: 시간이 많이 걸리는 호출 식별.&quot;을 들 수 있습니다. 일반적으로 문장 대소문자를 사용하십시오. 첫 번째 단어만 대문자로 표기하십시오. 특정 제품 이름과 같은 고유 명사이거나 콜론 `:` 뒤에 오는 경우가 아니면 제목의 다른 단어는 대문자로 표기하지 마십시오.

        제목을 선택하는 방법에 대한 아이디어를 찾고 있다면 유사한 문서의 제목을 찾아보십시오.

        사이드바(왼쪽 탐색 창)에 사용되는 제목은 [nav 파일](/docs/style-guide/processes-procedures/update-left-navigation-pane)에서 설정됩니다.
      </td>
    </tr>

    <tr>
      <td>
        `tags`
      </td>

      <td>
        더 이상 사용되지 않습니다. 역사적으로 태그는 검색 엔진과 AI가 올바른 콘텐츠를 찾는 데 도움을 주기 위해 사용되었습니다. 최신 엔진은 태그 없이도 해당 컨텍스트를 추론할 수 있을 만큼 정교하므로 이 태그는 더 이상 필요하지 않습니다.
      </td>
    </tr>

    <tr>
      <td>
        `translate`
      </td>

      <td>
        이 페이지가 어떤 언어로 사람에 의해 번역되었는지 나타냅니다. 이 필드는 기계 번역을 제어하지 않으며, 일반적으로 사이트의 모든 &quot;표준&quot; 문서는 모든 언어로 기계 번역됩니다. 자세한 내용은 [문서 번역](/docs/style-guide/writing-docs/docs-translation/)을 참조하십시오.
      </td>
    </tr>

    <tr>
      <td>
        `metaDescription`
      </td>

      <td>
        문서에 대한 짧은 설명입니다. 검색 엔진은 문서의 내용을 이해하기 위해 이 필드에 의존하며, 종종 검색 결과에 메타 설명을 바로 표시합니다. 160자 미만이어야 합니다. 메타 설명이 검색에 중요한 이유에 대한 자세한 내용은 Google 문서의 [검색 결과의 스니펫 제어](https://developers.google.com/search/docs/appearance/snippet)를 참조하십시오.
      </td>
    </tr>

    <tr>
      <td>
        `redirects`
      </td>

      <td>
        이전 URL에서 이 문서 **로** 리디렉션합니다. 한 줄에 하나의 리디렉션을 입력하십시오. 상대 경로를 사용하고 후행 슬래시 `/`을 포함하지 마십시오.
      </td>
    </tr>

    <tr>
      <td>
        `freshnessValidatedDate`
      </td>

      <td>
        작성자가 이 문서에 중요한 업데이트를 수행하고 정확성을 확인한 마지막 시간입니다.

        기본값은 `never`입니다. 문서에 중요한 업데이트를 수행하는 경우 오늘 날짜를 `YYYY-MM-DD` 형식으로 추가하십시오.
      </td>
    </tr>
  </tbody>
</table>

## 페이지 템플릿

문서 사이트에는 엄격한 페이지 템플릿이 없습니다 ― &quot;코드로서의 문서&quot; 접근 방식을 취하고 있기 때문에 작성자는 다양한 구성 요소를 사용하여 자신이 생각하는 최선의 방식으로 문서를 구성할 수 있습니다. 하지만 표준 `.mdx` 문서와 다르게 작동하는 몇 가지 고유한 유형의 콘텐츠가 있습니다.

<table>
  <thead>
    <tr>
      <th width={150}>
        **콘텐츠 유형**
      </th>

      <th>
        **설명**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        &quot;표준&quot; 문서
      </td>

      <td>
        `/src/content/docs/` 하위 디렉터리에 있는 표준 `.mdx` 파일입니다. 이 콘텐츠 유형은 사이트 콘텐츠의 대부분에 사용됩니다.
      </td>
    </tr>

    <tr>
      <td>
        속성 정의
      </td>

      <td>
        이 형식은 속성 및 이벤트 유형을 정의하기 위한 것입니다. 이러한 정의는 자체 GitHub Enterprise 리포지터리에 있으며, 데이터 사전 서비스를 통해 문서 사이트 및 NerdGraph에 게시됩니다. 자세한 내용은 [속성 정의 콘텐츠 유형 작업](/docs/style-guide/article-templates/attribute-definition-template)을 참조하십시오.
      </td>
    </tr>

    <tr>
      <td>
        분기 설치 문서
      </td>

      <td>
        이 형식은 대화형 설치 문서용입니다. 분기형 설치 문서는 하위 디렉터리에 함께 있는 개별 `.mdx` 파일의 여러 구성 요소로 구성되며, 언제 어떤 부분을 표시할지 정의하는 로직은 별도의 `.yaml` 파일에 정의됩니다. 분기형 설치 콘텐츠는 `/src/install/` 하위 디렉터리에 있습니다.

        자세한 내용은 [분기 설치 구성 요소 시작하기](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc/)를 참조하십시오.
      </td>
    </tr>

    <tr>
      <td>
        릴리즈 정보
      </td>

      <td>
        이 형식에는 고유한 프런트매터 필드가 포함됩니다. 릴리스 노트는 `/src/content/docs/release-notes/`에 있으며, 일반적으로 작성자가 아닌 제품 팀에서 작성합니다.

        사용자는 제품의 작은 변경 사항, 특히 에이전트와 같은 다운로드 가능한 소프트웨어의 변경 사항을 파악하기 위해 릴리스 노트에 의존합니다. 자세한 내용은 [릴리스 정보 작성](/docs/style-guide/article-templates/create-release-notes/)을 참조하십시오.
      </td>
    </tr>

    <tr>
      <td>
        새로운 기능 게시물
      </td>

      <td>
        이 형식에는 고유한 프런트매터 필드가 포함됩니다. 새로운 소식 게시물은 더 큰 규모의 공지를 위해 PMM에서 작성합니다. 대부분의 콘텐츠와 달리 `/docs/` 하위 디렉터리가 아닌 `/src/content/whats-new/`에 있습니다.

        문서 사이트에서 사용할 수 있지만 뉴렐릭 UI에서도 볼 수 있습니다. 자세한 내용은 [새로운 기능 스타일 가이드라인](/docs/style-guide/article-templates/whats-new-style-guidelines/)을 참조하십시오.
      </td>
    </tr>
  </tbody>
</table>
