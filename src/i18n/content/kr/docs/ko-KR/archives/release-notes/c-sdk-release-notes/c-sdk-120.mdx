### 새로운 기능

***컨테이너 배포를 위한 더 많은 유연성***

* 데몬과 계측된 애플리케이션은 더 이상 동일한 호스트에 상주할 필요가 없으며 이제 IPv4 또는 IPv6 TCP 소켓을 통해 통신할 수 있습니다. 계측된 애플리케이션의 경우 `newrelic_init` 함수의 `daemon_socket` 인수를 통해 이를 구성할 수 있습니다. 데몬의 경우 `--address` 명령줄 옵션을 통해 이를 구성할 수 있습니다.
* `SIGTERM` 신호(및/또는 `-f`, `--foreground` 플래그로 시작된 경우 `SIGINT` 신호)를 통해 데몬을 종료할 때, 이제 데몬은 종료하기 전에 버퍼링된 모든 데이터를 뉴렐릭으로 전송합니다.
* 데몬에 새로운 설정 `--watchdog-foreground`이(가) 도입되었습니다. 이 설정은 데몬 워치독 프로세스를 포그라운드에 유지하는 반면, `--foreground` 설정은 데몬 워커 프로세스를 포그라운드에 유지합니다. 새로운 설정을 사용하면 워치독 프로세스가 제공하는 추가적인 안정성을 잃지 않고 데몬을 차단 방식으로 사용할 수 있습니다.
* 이제 C SDK는 사용자가 이미 시작된 트랜잭션의 이름을 변경할 수 있는 `newrelic_set_transaction_name`을(를) 제공합니다.

### 버그 수정

* 이제 데몬은 트랜잭션 데이터의 수집 및 병합과 관련된 중요한 코드 경로를 동기식으로 처리합니다. 이는 경쟁 조건으로 인해 발생하는 충돌을 방지합니다.

### 업그레이드 공지

* 데몬에 `--port`의 별칭 역할을 하는 새로운 설정 `--address`이(가) 도입되었습니다. 고객은 둘 중 하나를 사용하여 데몬의 위치를 지정할 수 있습니다. 두 값이 모두 설정된 경우 `--address`이(가) 우선합니다.

* 데몬을 시작할 때, 이제 백그라운드로 포크하기 전에 수신 대기 포트가 연결을 받을 준비가 될 때까지 최대 3초 동안 기다립니다. 이 작업은 보통 1초보다 (훨씬) 짧은 시간 안에 발생하며, 이 설정을 사용하는 대부분의 사용자는 실제로는 차이를 느끼지 못할 것입니다.

  데몬이 대기할 시간은 `--wait-for-port` 설정에 기간을 지정하여 제어할 수 있습니다. 차단을 방지하기 위해 이 기간을 0으로 설정할 수 있습니다. 옵션을 생략하는 경우 기본값은 `3s`입니다.

  포그라운드 모드(`--foreground` 플래그 사용)에서 시작된 데몬은 영향을 받지 않으며 이전과 동일하게 작동합니다.
