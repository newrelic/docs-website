신세틱 모니터링은 사용자가 선택한 위치 — 뉴렐릭이 전 세계에서 운영하는 공개 위치 또는 자체 네트워크 내부의 [프라이빗 로케이션](/docs/synthetics/synthetic-monitoring/guides/private-location-capabilities/) — 에서 애플리케이션 및 엔드포인트에 대해 자동화되고 예약된 검사를 실행합니다. 각 모니터는 정해진 간격으로 실제 요청이나 사용자 여정을 수행하고 그 결과를 보고하므로, 실패, 속도 저하 및 끊어진 흐름을 최대한 일찍 포착할 수 있습니다.

이러한 검사는 항상 실행되므로 애플리케이션(API 엔드포인트 및 브라우저 여정 모두)에 대한 가용성, 기능 및 성능 기준을 제공합니다. APM 및 브라우저 모니터링은 실제 트래픽이 어떻게 동작했는지 알려주는 반면, 신세틱 모니터는 트래픽이 적은 지역이나 릴리스가 사용자에게 도달하기 전을 포함하여 항상 중요한 기능이 예상대로 작동하는지 여부를 알려줍니다.

## 샘플 사용 사례 [#sample-use-cases]

뉴렐릭 신세틱 모니터링은 가용성을 광범위하게 포괄하는 가벼운 업타임 핑부터 가장 복잡한 흐름을 실행하는 완전히 스크립트화된 API 및 브라우저 여정에 이르기까지 다양한 스펙트럼에 걸쳐 있습니다. 프라이빗 로케이션에서 실행되는 스크립트 모니터에서는 한 걸음 더 나아가, 자체 npm 모듈로 런타임을 확장하여 네트워크에서 도달할 수 있는 거의 모든 것을 확인할 수 있습니다.

### 핑 [#ping]

실행할 수 있는 가장 경제적인 검사는 엔드포인트가 온라인 상태이고 충분히 빠른지 확인하는 예약된 HTTP 요청입니다. 수백 개의 엔드포인트에서 자주 실행할 수 있을 만큼 경제적이므로 광범위한 가용성 및 업타임 보고의 기반이 됩니다. 손상된 기능이 아니라 중단을 감지하므로 앱이 작동한다는 증거보다는 첫 번째 신호로 취급하십시오.

<CollapserGroup>
  <Collapser id="ping-use-cases" title="사용 사례 예시를 확인하십시오.">
    일반적인 확인 사항:

    * **엔드포인트 도달 가능:** 일정에 따라 요청을 보내고 인증이나 스크립트 없이 정상 상태 코드(200 또는 모든 2xx나 3xx)를 반환하는지 확인하십시오.
    * **응답 시간 임계값:** 엔드포인트가 임계값보다 느리게 응답하면 검사에 실패하도록 하여, 지연시간 회귀를 조기에 공지합니다.
    * **본문 문자열 일치:** 응답 본문에 `ok` 또는 `"status":"healthy"`과 같은 예상 문자열이 포함된 경우에만 통과합니다.
  </Collapser>
</CollapserGroup>

시작하려면 모니터를 생성하기 위한 [모니터 추가 및 편집](/docs/synthetics/synthetic-monitoring/using-monitors/add-edit-monitors/)과 보고 내용을 읽기 위한 [핑 모니터 결과 보기](/docs/synthetics/synthetic-monitoring/using-monitors/view-ping-monitor-results/)를 참조하십시오.

### 스크립트 API [#scripted-api]

Node.js를 `$http` API와 함께 사용하여 requests를 체인으로 연결하고, 단계 간에 인증 및 상태를 전달하며, 상태, 페이로드 및 타이밍에 `assertion`을(를) 사용합니다. 서비스 계층에서 실제 비즈니스 트랜잭션을 인코딩하거나, 의존하지만 제어할 수 없는 타사 종속성을 모니터링하는 데 사용하십시오. 프라이빗 로케이션에서는 자체 모듈에 `require()`을(를) 사용하여 비 HTTP 프로토콜에 도달하거나 기존 SDK로 모델, 벡터 스토어 및 cloud API를 호출하십시오.

<CollapserGroup>
  <Collapser id="scripted-api-use-cases" title="사용 사례 예시를 확인하십시오.">
    일반적인 확인 사항:

    * **네트워크 및 프로토콜:** 비 HTTP 연결을 열고 `assert`을(를) 사용하여 성공하는지 확인하십시오. TCP 또는 TLS 포트가 열려 있는지 확인하거나, DNS 레코드를 확인하거나, WebSocket 또는 MQTT 메시지를 교환하거나, LDAP, FTP/SFTP 및 SMTP에 도달하십시오.
    * **인증서 및 보안:** 클라이언트 인증서(상호 TLS)로 API를 호출하고 `assert`을(를) 사용하여 인증을 확인하거나, SAML 메타데이터에 포함된 인증서를 검증하거나, 차단 목록과 대조하여 메일 IP를 확인하십시오.
    * **클라우드 및 SaaS 통합:** AWS, Azure 또는 GCP에 인증하고 `assert`을(를) 사용하여 리소스가 존재하는지 확인할 수 있습니다. 예를 들어, S3 내보내기 객체가 존재하는지 확인하거나 Azure Key Vault 시크릿을 읽을 수 있습니다.
    * **성능 및 SEO:** <DNT>PageSpeed</DNT> API를 통해 <DNT>Lighthouse</DNT> 감사를 실행하여 점수를 기록하거나, 일정에 따라 <DNT>Search Console</DNT> 메트릭을 가져오십시오.
    * **뉴렐릭 데이터(NRDB/NRQL):** 모니터에서 NRQL 쿼리를 실행하고 결과가 임계값을 초과하거나 이전 기간에서 벗어날 때 공지하십시오.
  </Collapser>
</CollapserGroup>

시작하려면 첫 번째 스크립트 작성을 위한 [신세틱 API 테스트 작성](/docs/synthetics/synthetic-monitoring/scripting-monitors/write-synthetic-api-tests/) 및 라이브러리를 사용하여 확장하기 위한 [Node.js 모듈 가져오기](/docs/synthetics/synthetic-monitoring/scripting-monitors/import-nodejs-modules/)를 참조하십시오.

### 간단한 브라우저 [#simple-browser]

실제 Chrome 또는 Firefox 인스턴스에서 페이지를 로드하므로, 검사 시 단순한 상태 코드 대신 JavaScript, 자산, CDN 및 캐시를 실행합니다. 핑(ping)으로는 절대 확인할 수 없는 렌더링 차단 스크립트 오류, 누락된 번들 및 조용히 실패하는 타사 태그를 포착합니다. 코드가 필요하지 않으므로, 여러 페이지에 걸쳐 실제 렌더링 커버리지를 확보하는 가장 빠른 방법입니다.

<CollapserGroup>
  <Collapser id="simple-browser-use-cases" title="사용 사례 예시를 확인하십시오.">
    일반적인 확인 사항:

    * **페이지 가용성:** 글로벌 위치에서 페이지를 열고 예상되는 콘텐츠가 로드되고 렌더링되는지 확인하십시오.
    * **콘텐츠 및 요소 확인:** `assert`을(를) 사용하여 제품 페이지의 &quot;장바구니에 추가&quot; 버튼과 같은 특정 요소나 텍스트가 있는지 확인하십시오.
    * **Core Web Vitals:** 페이지 로드 시간을 측정하고 예산(예: 3초)을 초과하는 경우 검사를 실패로 처리할 수 있습니다.
  </Collapser>
</CollapserGroup>

시작하려면 모니터를 생성하기 위한 [모니터 추가 및 편집](/docs/synthetics/synthetic-monitoring/using-monitors/add-edit-monitors/)과 모바일 및 태블릿 뷰포트를 테스트하기 위한 [디바이스 에뮬레이션](/docs/synthetics/synthetic-monitoring/using-monitors/device-emulation/)을 참조하십시오.

### 스크립트 브라우저 [#scripted-browser]

다단계, 조건부, 인증된 여정을 통해 `$browser` API(셀레니엄 웹드라이버)로 실제 브라우저를 구동합니다. 하나의 검사로 로그인, 검색, 결제 또는 중요한 내부 흐름과 같은 브라우저에서 데이터 계층까지의 전체 경로를 검증합니다. 가장 느리고 리소스를 많이 사용하는 모니터이므로 수익과 신뢰를 수반하는 여정을 위해 남겨 두십시오.

<CollapserGroup>
  <Collapser id="scripted-browser-use-cases" title="사용 사례 예시를 확인하십시오.">
    일반적인 확인 사항:

    * **브라우저 UX 및 콘텐츠:** 페이지를 구동하여 링크를 크롤링하고 끊어진 링크가 있으면 실패 처리하거나, 파일 다운로드 시간을 측정하거나, 다운로드한 PDF 내부의 텍스트를 확인합니다.
    * **cloud 및 SaaS 통합:** 여정 중에 스크린샷을 캡처하여 S3와 같은 cloud 스토리지에 업로드하십시오.
  </Collapser>
</CollapserGroup>

시작하려면 기본 사항에 대한 [스크립트 브라우저 모니터 소개](/docs/synthetics/synthetic-monitoring/scripting-monitors/introduction-scripted-browser-monitors/)와 전체 `$browser` API에 대한 [스크립트 브라우저 참조](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetic-scripted-browser-reference-monitor-versions-chrome-100/)를 확인하십시오.

스크립트 API 및 스크립트 브라우저 모니터는 JavaScript를 실행하므로 자체 npm 모듈에서 `require()`을(를) 사용할 수 있습니다. 위와 동일한 방식으로 프로토콜, cloud-SDK 및 문서 검사를 구동합니다. 프라이빗 로케이션에서는 이러한 모듈이 자체 레지스트리에서 설치되고 네트워크 내부에서 실행됩니다. 모든 키 또는 토큰을 [보안 자격 증명](/docs/synthetics/synthetic-monitoring/using-monitors/store-secure-credentials-scripted-browsers-api-tests/)으로 저장하십시오.

## 사용자 지정 코드 및 확장성 [#programmable-monitoring]

뉴렐릭 스크립트 모니터는 고정 기능 검사기가 아닙니다 ― 프로그램입니다. 코드로 표현할 수 있다면 모니터할 수 있습니다. 이는 사용자 지정 로직을 체인으로 연결하고, 자체 뉴렐릭 데이터를 쿼리하며, 자체 코드 및 모듈로 모니터를 확장할 수 있음을 의미합니다.

### 자체 코드 사용 [#bring-your-own-code]

스크립팅된 모니터를 사용하면 자체 모듈에서 `require()`을(를) 사용할 수 있습니다. [프라이빗 로케이션](/docs/synthetics/synthetic-monitoring/guides/private-location-capabilities/)에서는 `package.json`이(가) 포함된 디렉터리를 마운트하고 작업 관리자가 시작 시 `npm install`을(를) 실행하므로, 모든 npm 패키지 또는 내부 라이브러리가 모니터의 일부가 됩니다 ― 이는 비 HTTP 프로토콜(TCP, WebSocket, MQTT, LDAP, SFTP, SMTP)을 사용하거나, 클라우드 제공업체 SDK를 호출하거나, 독점 형식을 디코딩하기에 충분합니다. 모니터의 범위는 고정된 기능 목록이 아니라 전체 패키지 생태계와 자체 코드입니다 ― 따라서 새로운 요구 사항이 생기면 기능 요청을 제출하는 것이 아니라 종속성을 추가하면 됩니다.

### 네트워크 내부에서 비공개로 실행하십시오 [#run-privately]

스크립트 모니터는 신세틱스 작업 관리자에서 실행되므로 자체 네트워크 내부의 [프라이빗 로케이션](/docs/synthetics/synthetic-monitoring/guides/private-location-capabilities/)에서 실행할 수 있습니다. 즉, 퍼블릭 인터넷에 아무것도 노출하지 않고 자체 레지스트리에서 설치된 자체 모듈을 사용하여 내부 시스템을 실행하는 것을 의미합니다.

### 텔레메트리 이상 징후에 대한 알림을 받으십시오. [#monitor-telemetry]

스크립트 API 모니터는 자체 뉴렐릭 데이터를 쿼리하고 커스텀 스크립트에 정의한 로직을 기반으로 결과에 대해 공지할 수 있으므로, 장기간에 걸쳐 데이터를 쿼리하거나 이전 기간과 결과를 비교하는 등 공지 조건에 맞지 않는 시나리오에 대한 커버리지를 제공합니다:

* **데이터 쿼리:** NRQL [쿼리를 실행하려면](/docs/synthetics/synthetic-monitoring/using-monitors/store-secure-credentials-scripted-browsers-api-tests/) 보안 자격 증명 으로 저장된 API 키를 사용하여 [을(를) 통해 NerdGraph API를 호출하십시오.`$http`](https://docs.newrelic.com/docs/synthetics/synthetic-monitoring/scripting-monitors/write-synthetic-api-tests/#get-nerdgraph-example)
* **편차 공지:** 결과가 임계값을 초과하거나 이전 기간에서 벗어날 때 검사에 실패하도록 `assertion` 또는 유사한 로직을 사용하십시오.
