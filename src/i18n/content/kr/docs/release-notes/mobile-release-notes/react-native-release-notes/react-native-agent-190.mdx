<Callout variant="important" title="오류 보고의 주요 변경 사항">
  버전 1.9.0부터 JavaScript 오류는 새로운 이벤트 유형인 `MobileJSError`을(를) 통해 보고됩니다. 새로운 모바일 오류 프로토콜을 사용하면 리액트 네이티브 JavaScript 오류가 더 이상 `MobileHandledException` 이벤트 유형에 저장되지 않습니다.

  <DNT>**Action required:**</DNT>

  * <DNT>**Alerts:**</DNT> `MobileJSError`을(를) 타겟으로 하도록 NRQL 공지 조건을 업데이트하십시오.
  * <DNT>**Dashboards:**</DNT> JavaScript 계층 오류에 대해 `MobileHandledException`을(를) 쿼리하는 사용자 지정 차트를 업데이트하십시오.
  * <DNT>**Symbolication:**</DNT> 새로운 이벤트 유형에 대한 소스 맵 업로드를 지원하려면 빌드 스크립트를 최신 버전으로 업데이트하십시오. [리액트 네이티브 JavaScript 오류 보고](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting)를 참조하십시오.

  다음과 같이 쿼리를 업데이트하십시오:

  ```sql
  -- Before (1.8.x and lower)
  SELECT count(*) FROM MobileHandledException WHERE platform = 'reactnative'

  -- After (1.9.0 and higher)
  SELECT count(*) FROM MobileJSError
  ```
</Callout>

## 개량

* JavaScript 오류 및 처리되지 않은 프로미스 거부는 이제 `MobileHandledException` 대신 새로운 Mobile Errors Protocol을 통해 일급 `MobileJSError` 이벤트 유형으로 보고됩니다.
* `MobileJSError` 스택 추적(자동, 수동 및 CodePush/OTA)을 심볼릭화하기 위한 소스 맵 업로드 지원이 추가되었습니다. [리액트 네이티브 JavaScript 오류 보고](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting)를 참조하십시오.
* JavaScript 오류 보고를 활성화하거나 비활성화하는 `jsErrorReportingEnabled` 설정 옵션을 추가했습니다(기본적으로 활성화됨).
* `recordError` 이제 선택적 `isFatal` 및 `attributes` 인수를 허용하여 오류를 치명적인 것으로 표시하거나 커스텀 속성을 첨부할 수 있습니다.
* 네이티브 안드로이드 에이전트를 버전 7.8.2로 업데이트했습니다.
* 네이티브 iOS 에이전트를 버전 7.7.6으로 업데이트했습니다.
