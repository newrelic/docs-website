### 개선 및 향상

* 이제 세션 리플레이는 구형 아키텍처를 사용하는 리액트 네이티브 앱에서 텍스트를 캡처합니다. 이전에는 `RCTTextView`이(가) 그린 텍스트가 빈 뷰로 기록되었습니다. 이제 새로운 아키텍처의 `RCTParagraphComponentView` 텍스트와 동일한 방식으로 캡처되고 마스킹됩니다.

### 버그 수정

* 차단된 뷰의 콘텐츠를 업로드하는 세션 리플레이 문제를 수정했습니다. `nr-block` 접근성 식별자로 차단된 뷰는 검은색 상자로 그려졌지만, 해당 텍스트는 여전히 리플레이와 함께 전송되었으며 검은색 이외의 색상으로 상자 위에서 읽을 수 있었습니다. 이미지 마스킹이 꺼져 있을 때 차단된 이미지 뷰도 이미지 데이터를 유지했습니다. 이제 차단된 뷰는 캡처 시점에 텍스트, 이미지 및 하위 뷰가 없는 빈 상자로 기록됩니다. 이제 화면에 표시된 상태에서 차단된 뷰는 다음 전체 스냅샷까지 이전 콘텐츠를 표시하는 대신 리플레이에서 즉시 업데이트됩니다. 이 문제는 7.7.10 및 그 이전 버전에 존재했습니다.
* 앱이 네트워크 requests를 수행하는 동안 세션이 시작된 후 보통 몇 초 이내에 `+[NRMAHTTPUtilities addCrossProcessIdentifier:]`에서 발생하는 드문 크래시(인식할 수 없는 선택자의 경우 `SIGSEGV` 또는 `NSInvalidArgumentException`)를 수정했습니다. 모든 계측된 `NSURLSession` 요청은 잠금 없이 에이전트의 하베스터 설정과 교차 프로세스 ID를 읽었습니다. 동시에 하베스트 스레드는 세션 시작 시 해당 설정을 교체하고 ID를 지웠으므로, 요청이 방금 해제된 객체를 사용할 수 있었습니다. 이제 두 가지 모두 스레드 간에 안전하게 읽히고 교체됩니다. 하베스트 중에 `+[NewRelic shutdown]`이(가) 호출될 때 발생하는 유사한 경합 문제도 수정되었습니다. 이 문제는 7.7.10 및 그 이전 버전에 존재했습니다.
* 에이전트가 구문 분석할 수 없는 `/connect` 응답을 받은 후 네트워크 requests가 기록되지 않는 문제를 수정했습니다. 에이전트는 다음 하베스트까지 빈 설정을 저장했으며, 해당 기간 동안 기록된 모든 requests를 삭제했습니다. 이제 에이전트는 기존 설정을 유지합니다. 이 문제는 7.7.10 및 그 이전 버전에 존재했습니다.
* 앱 업데이트 후 디바이스에 저장된 처리된 예외가 서버 오류 &quot;Failed to resolve data: MobileAppVersion&quot;과 함께 삭제되는 문제를 수정했습니다. 저장된 처리된 예외는 에이전트가 앱의 새 버전에 연결되기 전인 다음 세션 시작 시 업로드되었습니다. 이제 연결이 완료된 후 업로드됩니다. 이 문제는 7.7.10 및 이전 버전에서 발생했습니다.
* 앱 업데이트 전에 기록된 처리된 예외가 새 앱 버전으로 보고되는 문제를 수정했습니다. 이제 저장된 처리된 예외는 기록된 앱 버전으로 업로드됩니다. 이 문제는 7.7.10 및 이전 버전에서 발생했습니다.
* 새로운 이벤트 시스템(`NRFeatureFlag_NewEventSystem`)이 활성화되었을 때 `recordCustomEvent:`이(가) 예약된 이벤트 유형(`Mobile`, `MobileCrash`, `MobileRequest`, `MobileRequestError`, `MobileSession`, `MobileBreadcrumb`)을 허용하는 문제를 수정했습니다. 기본 이벤트 시스템은 이미 이러한 유형을 거부했으므로, 이벤트 전송 여부는 기능 플래그에 따라 달라졌습니다. 이제 두 이벤트 시스템 모두 이를 거부합니다.
* 단일 소스 줄이 1 MB(`0x100000`) 이상의 코드를 포함할 때 dSYM 업로드 도구(`run-symbol-tool`)가 dSYM을 심볼 맵으로 변환하지 못하는 문제를 수정했습니다. 그런 다음 도구는 전체 dSYM을 업로드하는 방식으로 폴백했습니다. 이제 이러한 줄을 심볼 맵으로 변환합니다.
