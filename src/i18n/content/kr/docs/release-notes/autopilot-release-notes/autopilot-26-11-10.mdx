### 새로워진 사항

#### Autopilot으로 Kafka 문제 해결

뉴렐릭 온-호스트 통합, OpenTelemetry, Amazon MSK 및 Confluent Cloud로 모니터되는 Kafka의 경우, 이제 Autopilot은 Kafka 문제를 더 효과적으로 해결하고 이를 완화하기 위한 다음 단계를 권장할 수 있습니다.

* **Cluster health \[Cluster 상태]:** 소비자 지연, 복제본이 부족하거나 오프라인인 파티션, 브로커 및 컨트롤러 상태를 확인합니다.
* **엔티티 관계 매핑:** 생산자, 소비자, 토픽, 브로커, 클러스터 및 호스트 인프라를 연결하여 에코시스템 전반의 관계를 매핑합니다.
* **클라이언트 성능:** 생산자 또는 소비자의 요청을 검토하고 지연시간, I/O 대기, 소비율 및 폴링 타이밍을 가져옵니다.

#### GitHub Copilot용 변경 추적

<Callout title="시사">
이 기능은 아직 개발 단계에 있지만, 시험적으로 사용해 보시길 권합니다. 이 기능은 현재 [출시 전 정책](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy)에 따라 프리뷰 프로그램의 일부로 제공됩니다.
</Callout>

이제 Autopilot은 각 배포 후 서비스를 모니터하고 pull 요청에 결과를 보고할 수 있습니다. 배포 후 6개의 체크포인트(10분, 30분, 1시간, 2시간, 24시간 및 72시간)에서 Autopilot은 배포 후 메트릭을 기준과 비교하고 그 결과를 PR 댓글로 게시합니다. 회귀를 감지하면 Autopilot은 조사 결과를 Slack에 게시하고 GitHub Copilot에 할당된 GitHub 이슈를 엽니다. GitHub Copilot Enterprise를 사용하면 Copilot이 수정 사항을 pull 요청으로 제안할 수 있습니다.

* **PR에 대한 체크포인트 보고서:** 각 체크포인트에서 Autopilot은 회귀 없음, 결론 없음 또는 회귀 감지와 같은 결과를 pull 요청에 댓글로 남기므로 팀은 GitHub를 벗어나지 않고도 신호를 확인할 수 있습니다.
* **Slack 공지:** Slack을 연결한 경우, Autopilot은 배포에 대한 모니터링이 시작될 때 메시지를 게시하고 각 체크포인트의 동일한 스레드에 회신합니다.
* **자동 회귀 이슈:** Autopilot이 회귀를 감지하면 회귀된 내용, 근거 자료, 확인 위치 및 수락 기준이 포함된 GitHub 이슈를 열고 해당 이슈를 GitHub Copilot에 할당합니다.
* **PR 레이블 트리거:** 변경 추적 이벤트에서 `watchpoint_monitoring` 속성을 설정할 필요 없이, 해당 배포에 대한 모니터링을 켜려면 배포하기 전에 pull 요청에 `watchpoint_monitoring` 레이블을 추가하십시오. 파이프라인을 변경할 필요 없이 모니터할 배포를 선택할 수 있습니다.

설정 지침 및 전체 전제 조건에 대해서는 [GitHub Copilot용 뉴렐릭 변경 추적으로 배포 모니터링하기](/docs/agentic-ai/autopilot/change-tracking-for-github-copilot/)를 참조하십시오.

### Kafka 문제 해결, 배포 모니터링 등

#### 새로운 기능

* **Autopilot으로 Kafka 문제 해결:** 이제 Autopilot은 뉴렐릭 온-호스트 통합, OpenTelemetry, Amazon MSK 및 Confluent Cloud로 모니터되는 Kafka의 문제를 더 효과적으로 해결하고 이를 완화하기 위한 다음 단계를 권장할 수 있습니다.
* **GitHub Copilot용 변경 추적(미리 보기):** 이제 Autopilot은 각 배포 후 서비스를 모니터하고 pull 요청에 결과를 보고하는 데 도움을 줄 수 있습니다.
* **사용자별 Autopilot 사용 데이터 보기:** Consumption Management \[소비 관리]를 사용하여 이제 사용자별로 분류된 Autopilot 소비 사용량을 확인할 수 있습니다.
* **인프라에 대한 로그 및 메트릭 검색:** 인프라 조사 중에 Autopilot은 이제 엔티티의 로그를 검토하고 해당 엔티티가 보고하는 메트릭 이름을 조회할 수 있습니다.

#### 개선 및 수정 사항

* **개선된 문제 검색:** 이제 Autopilot은 공지 문제를 더 안정적으로 해결합니다. 접미사 이름 변형이 더 이상 정확한 일치 항목 뒤에 숨겨지지 않으며, 사후 조사를 위해 종료된 문제를 더 안정적으로 해결할 수 있고, 보고 상태가 표시되어 오래된 엔티티가 활성 엔티티보다 우선하지 않습니다.
* **더욱 완전한 빠른 답변:** 목록은 각 항목을 최대 50개까지 표시하며, 답변에는 중요한 엔티티 및 미해결 문제와 같은 개수와 관련된 세부 정보가 포함됩니다.
* **CCU 총계:** 빠른 답변의 CCU 총계에는 더 이상 데이터 볼륨 수치가 포함되지 않습니다.
* **요청하는 시간 범위:** Autopilot은 조사를 위해 시간 범위를 요청할 수 있습니다.
* **Focused checks on ongoing issues \[진행 중인 문제에 대한 집중 확인]:** 문제가 여전히 발생하고 있는지 질문하면 이제 가장 최근 기간을 확인합니다.
* **개선된 인시던트 시작 시간:** 인시던트 조사는 이제 이슈가 열린 시간부터 시작됩니다.
* **더욱 안정적인 질문 라우팅:** Autopilot은 질문의 컨텍스트를 기반으로 경로 처리를 개선했습니다.
* **도구 서비스가 중단되어도 조사는 계속됩니다:** 연결된 도구 서비스를 사용할 수 없는 경우 Autopilot은 나머지 도구를 사용하여 계속 진행합니다.
* **조사가 예산에 도달했을 때 유지되는 조사 결과:** 이제 Autopilot은 조사가 예산 한도에 도달하기 전에 수집한 조사 결과를 요약할 수 있습니다.
* **더욱 탄력적인 조사:** Autopilot은 연결된 도구 서비스 중 하나를 사용할 수 없을 때 조사를 완료할 가능성이 더 높으며, 일시적인 속도 저하에서 더 잘 복구할 수 있습니다.
* **더 상세한 조사 요약:** 다단계 조사의 요약에 전체 분석이 포함될 가능성이 높아졌으며, 더 많은 요약에 차트가 표시됩니다.
* **신세틱스 질문에 대한 더 나은 답변:** 이제 Autopilot은 계정 내 모든 모니터의 목록, 개수 및 상태에 대한 질문에 더 잘 답변할 수 있으며, 질문에 명시한 계정을 더 잘 식별합니다. 이제 실패한 검사에 대한 분석은 실패한 단계에 초점을 맞춥니다.
* **저장된 기본 설정이 현재 질문에 부합합니다:** 이전 대화에서 저장된 기본 설정이 엔티티가 지정되지 않은 경우의 확인 질문 등 현재 질문에 필요한 사항에 과도하게 영향을 미칠 가능성이 낮아집니다.
* **지식 기반 컬렉션의 추가 정보:** 지식 기반 컬렉션을 지정하면 이제 Autopilot에 더 많은 결과가 포함되며, 문서를 검색할 수 없는 경우 이를 알릴 가능성이 더 높아집니다.
* **조사 시의 더 많은 공지 컨텍스트:** Autopilot은 이제 문제를 조사할 때 임계값 및 영향을 받는 엔티티와 같은 더 많은 공지 조건 세부 정보를 활용할 수 있습니다.
* **워크로드 분석:** 이제 Autopilot은 워크로드의 멤버 엔티티를 검토하고 속성별로 엔티티를 계산할 수 있습니다.
* **빠른 답변의 일관된 타임스탬프:** 빠른 답변의 타임스탬프 및 기간이 더욱 일관되게 유지됩니다.
* **미해결 문제에 대한 인시던트 조회:** 유효한 미해결 문제에 대해 Autopilot이 인시던트를 보고하지 않던 문제를 해결했습니다.
* **정확한 단계 상태:** 완료되지 않은 조사 단계가 완료된 것으로 표시되는 문제를 해결했습니다.
* **엔티티 검색 안정성:** 일부 엔티티 검색이 트리거되지 않는 문제를 해결했습니다.
* **알림 페이지의 새로운 대화:** 이제 알림 페이지에서 **New conversation** \[새 대화] 버튼을 통해 새 스레드를 열 수 있습니다.
* **페이지별 예제 프롬프트:** 자체 예제 프롬프트를 제공하는 페이지에서는 이제 Autopilot panel \[Autopilot 패널]에 해당 프롬프트를 표시합니다.
