### 버그 수정

* **ExoPlayer/HLS:** `contentBitrate`은(는) HLS 스트림에 대해 항상 `0`을(를) 보고했습니다. media3는 내부적으로 혼합된 오디오+비디오 HLS 세그먼트 로드를 `TRACK_TYPE_VIDEO` 대신 `TRACK_TYPE_DEFAULT` (으)로 분류합니다(영향을 받지 않은 DASH 및 프로그레시브 스트림과는 다름). 트래커의 비트레이트 캡처 로직은 `TRACK_TYPE_VIDEO`에 대해서만 실행되었으므로, HLS 로드는 해당 필드를 채우지 않았습니다. 이제 `contentBitrate`은(는) HLS 콘텐츠의 실제 스트림 비트레이트를 올바르게 반영합니다.
