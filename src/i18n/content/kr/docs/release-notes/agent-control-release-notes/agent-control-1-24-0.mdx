### 새로운 기능

* `secrets_providers` 구성 키의 이름을 `value_providers`(으)로 변경했으며, 이전 키는 하위 호환성을 위해 유지됩니다.
* OnHost: RedHat 10에 대한 지원을 추가했습니다.
* K8s: Kubernetes ConfigMaps에서 변수를 해석할 새로운 `nr-kubecm` 값 공급자를 추가했습니다.
* `chart_values.global` agentTypes에서 여전히 지원되지만, 더 이상 사용되지 않습니다. 여전히 다음을 통해 전역 설정을 구성할 수 있습니다 `chart_values.[chart-name].global`
* Linux: 패키지 매니저(apt, yum, zypper)를 자동 감지하고 `newrelic-agent-control`을(를) 제거하는 패키지에 번들로 포함된 `uninstall.sh` 스크립트를 추가했습니다.

### 버그 수정

* 온호스트: eBPF 에이전트는 이제 `/etc/newrelic-ebpf-agent` 대신 AC 관리 파일 시스템 디렉터리 아래에 상태 로그를 기록합니다.
* On-host: 오래된 PID 파일이 관련 없는 프로세스에서 재사용된 PID를 유지할 때 발생하는 잘못된 &quot;already running&quot; 시작 오류를 수정했습니다.
* 초기 슈퍼바이저 시작 실패 시를 포함하여 에이전트 유형에 `health:` 블록이 정의되지 않은 하위 에이전트에 대한 `Health` 보고(OpAMP 및 상태 서버)를 억제합니다.
* On-host: 에이전트 유형이 새 버전으로 업그레이드될 때, 이전 버전에서 선언된 오래된 파일 시스템 항목은 이제 전체 에이전트 디렉터리를 지우는 대신 diff를 통해 제거되며, 하위 에이전트의 OpAMP 인스턴스 ID는 버전이 변경되어도 유지됩니다.
* K8s: 하위 에이전트 유형이 새 버전으로 업그레이드될 때, 이제 업그레이드 후에도 OpAMP 인스턴스 ID가 유지되며, 이전에는 에이전트 이름 변경 여부와 관계없이 유형이 변경될 때마다 fleet-data ConfigMap이 삭제되어 다음 시작 시 새로운 인스턴스 ID가 생성되었습니다.
* Linux: `postremove` 스크립트는 이제 모든 제거 시(`apt purge`뿐만 아니라) `newrelic-agent-control` 디렉터리를 올바르게 제거하며, 이전 infra-agent 경로 대신 올바른 경로(`/etc/newrelic-agent-control`, `/var/lib/newrelic-agent-control`, `/var/run/newrelic-infra`)를 타겟으로 합니다.
* 온호스트: 이제 서비스가 5번의 빠른 재시작 후 중지되는 대신 실패 시 무기한으로 재시도(20초 지연)하며, 이는 Linux systemd 유닛과 Windows SCM 실패 조치 모두에 적용됩니다.
