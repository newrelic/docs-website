### 새로운 기능

* 온호스트 및 Kubernetes: 라이브 원격 구성 업데이트를 통해 에이전트의 유형이 변경될 때, 에이전트 컨트롤은 이제 에이전트별 파일 시스템과 공유 파일 시스템을 모두 조정하여, 활성 에이전트의 선언에 더 이상 나타나지 않는 이전 유형에 의해 선언된 경로를 삭제합니다. 다른 활성 에이전트가 여전히 점유하고 있는 공동 소유 공유 경로는 보존됩니다. Kubernetes에서 이전 유형으로 어노테이션이 지정된 k8s 객체는 가비지 컬렉션되는 반면, 새 유형의 리소스는 그대로 유지됩니다.
* 명령줄에서 OCI 레지스트리로 에이전트 패키지 및 에이전트 유형 정의를 푸시하기 위해 `test/crates/oci-test-utils`에 `oci-utils` CLI를 추가합니다(개발/테스트 도구, 게시되지 않음).
* 온호스트 에이전트 유형 파싱은 이제 `reported_version_package`을(를) 검증합니다: 선언된 패키지를 참조해야 하며, 둘 이상의 패키지가 정의된 경우 필수입니다. 잘못된 설정은 기술 오류와 함께 파싱 시 거부됩니다. 이 `reported_version_package`은(는) 어떤 버전이 `agent.version`(으)로 보고될지 결정합니다.
* 온호스트 &quot;에이전트 내&quot; 파일 시스템에 대한 `copy_from_file` 지원을 추가합니다.
* 온호스트 에이전트 유형에서 `shared_filesystem`에 대한 지원을 추가합니다. 단일 소유자 규칙이 포함되어 있습니다: 공유 파일 시스템에서 동일한 경로를 요청하는 두 에이전트는 유효하지 않으며 실패로 보고됩니다.
* 온호스트 자체 업데이트: 자체 업데이트가 진행 중일 때 하위 에이전트 조정을 건너뜁니다. 단일 원격 구성이 에이전트 제어 버전을 높이고 하위 에이전트의 `agent_type`을(를) 변경할 때, 변경된 하위 에이전트는 프로세스가 다시 시작되기 직전에 더 이상 다시 생성되지 않으며, 새로운 구성이 저장되고 다시 시작된 프로세스에 의해 깔끔하게 다시 적용되어 불필요한 하위 에이전트 재시작 및 텔레메트리 공백을 방지합니다.
* 온호스트: Linux 및 Windows 모두에 대한 nri-redis agentType 지원이 추가되었습니다.
* 온호스트 상태 구성: 플랫 `health.http:` / `health.file:` 필드를 명시적인 `checks:` 목록으로 교체했습니다. 각 항목은 `kind:` (`Process`, `Http` 또는 `File`)에 의해 식별됩니다. 이전의 암시적 관리 프로세스 상태 확인은 이제 `kind: Process`(으)로 선언됩니다. 생략되거나 비어 있는 `checks:` 목록은 상태 보고를 완전히 비활성화합니다.
* 이제 온호스트 파일 시스템 항목(`file`/`dir`)은 하위 에이전트 중지, 재시작 및 구성 적용 시에도 항상 유지됩니다. 기존 에이전트 유형 YAML에 있는 잘못된 `persistent:` 키는 거부되지 않고 무시됩니다.

### 버그 수정

* agentType에 `package.version.<id>`(으)로 지정된 각 패키지에 대한 식별 속성을 추가했습니다.
* 이제 RPM 패키지는 이전 제거 시 남겨진 `.rpmsave` 백업에서 `local_config.yaml`을(를) 복원합니다.
