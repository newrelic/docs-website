## v10.9.0

* **기능: 연속 프로파일링(미리 보기)**

  Continuous Profiling은 아직 일반적으로 사용할 수 없는 새로운 기능입니다. 이제 에이전트 측 구성 요소 코드가 에이전트에 존재하지만, 일반 공급 릴리스 전에 실제로 사용하려면 뉴렐릭 영업 담당자에게 문의하여 프리뷰에 미리 참여해야 합니다.

  Continuous Profiling은 실행 중인 애플리케이션의 루비 호출 스택을 반복적으로 샘플링하여 뉴렐릭에 보고하므로, 앱에 코드를 추가하지 않고도 프로덕션 환경에서 어떤 메서드가 가장 많은 CPU 시간을 소비하는지(또는 가장 많은 객체를 할당하는지) 확인할 수 있습니다.

  활성화하려면 애플리케이션의 `Gemfile`에 [`stackprof`](https://rubygems.org/gems/stackprof) 및 [`google-protobuf`](https://rubygems.org/gems/google-protobuf) gem을 추가한 다음 `profiling.enabled`을(를) `true`(으)로 설정하십시오:

  ```yaml
    profiling.enabled: true
  ```

  `profiling.enabled`만 설정된 경우, 에이전트는 프로세스의 수명 동안 10밀리초마다 CPU 시간을 샘플링합니다. 이러한 옵션을 통해 해당 동작을 조정할 수 있습니다:

  | 설정 이름                                  | 기본값     | 행동                                                                                        |
  | -------------------------------------- | ------- | ----------------------------------------------------------------------------------------- |
  | profiling.enabled                      | `false` | `true`인 경우, 에이전트는 지속적인 프로파일링 데이터를 수집하고 보고합니다.                                             |
  | profiling.include                      | `cpu`   | 샘플링할 항목: CPU 시간의 경우 `cpu` 또는 객체 할당의 경우 `object` 입니다.                                      |
  | profiling.sample\_period               | `0.01`  | 스택 샘플 간의 초 단위 시간입니다. `profiling.include`이(가) `cpu`일 때만 사용됩니다. 0.000001～0.999999 사이여야 합니다. |
  | profiling.object\_allocation\_interval | `10000` | 스택 샘플 간의 객체 할당입니다. `profiling.include`이(가) `object`일 때만 사용됩니다. 1,000～999,999 사이여야 합니다.    |
  | profiling.delay                        | `0`     | 프로파일링이 시작되기 전에 대기할 밀리초입니다. `0`은(는) 즉시 시작됩니다.                                              |
  | profiling.duration                     | `0`     | 자동으로 중지되기 전까지 프로파일링할 밀리초 단위 시간입니다. `0`은(는) 프로세스가 종료될 때까지 프로파일링합니다.                        |

  [PR#3617](https://github.com/newrelic/newrelic-ruby-agent/pull/3617)

* **기능: Dalli 5.1.1 지원 추가**

  Dalli 5.1.1은 에이전트에 의해 계측된 일부 메서드에 인수를 추가했으며, 이로 인해 다중 키 작업에서 `ArgumentError`이(가) 발생하거나 요청 옵션이 알림 없이 삭제될 수 있습니다. 이제 에이전트는 이러한 메서드에 대해 가변적인 수의 위치 및 키워드 인수를 수락하고 전달합니다. [PR#3683](https://github.com/newrelic/newrelic-ruby-agent/pull/3683)
