## v10.8.0

* **기능: Google Cloud Run 워커 풀 및 작업에 대한 고유한 호스트명을 보고합니다.**

  [PR#3609](https://github.com/newrelic/newrelic-ruby-agent/pull/3609/)에 추가된 Cloud Run 호스트명 지원은 Cloud Run **Services**에서 설정한 환경 변수인 `K_REVISION`을(를) 통해서만 Cloud Run을 감지했습니다. 이제 에이전트는 [`CLOUD_RUN_REVISION`](https://docs.cloud.google.com/run/docs/container-contract#env-vars) (Worker Pools) 및 `CLOUD_RUN_EXECUTION` (Jobs)도 인식하므로, 이제 `utilization.gcp_cloud_run.use_instance_as_host`은(는) 세 가지 리소스 유형 모두에 적용됩니다. `utilization.gcp_cloud_run.include_revision_in_host`이(가) `true`인 경우, 호스트명은 이러한 변수 중 존재하는 변수를 기반으로 생성됩니다 ― 예를 들어 Job의 경우 `{CLOUD_RUN_EXECUTION}-{instance id}` 입니다. [Issue#3651](https://github.com/newrelic/newrelic-ruby-agent/issues/3651) [PR#3652](https://github.com/newrelic/newrelic-ruby-agent/pull/3652)

* **기능: `browser_monitoring.version` 설정 옵션 추가**

  이제 고객은 새로운 `browser_monitoring.version` 설정 옵션을 설정하여 뉴렐릭이 주입하는 정확한 브라우저 에이전트 로더 버전을 고정할 수 있습니다. 현재 사용 가능하고 지원되는 버전은 [브라우저 에이전트 EOL 정책](https://docs.newrelic.com/docs/browser/browser-monitoring/getting-started/browser-agent-eol-policy/)을 참조하십시오. [PR#3663](https://github.com/newrelic/newrelic-ruby-agent/pull/3663)

* **기능: 백그라운드 작업 라이브러리에 span.kind 추가**

  이제 백그라운드 작업 라이브러리의 `produce` 및 `consume` 작업에 `span.kind` 속성이 추가됩니다. 여기에는 ActiveJob, Sidekiq, Resque 및 DelayedJob이 포함됩니다. [PR#3636](https://github.com/newrelic/newrelic-ruby-agent/pull/3636)

* **버그 수정: prepend 모드에서 DelayedJob 계측이 더 이상 모든 워커에 자체적으로 재설치되지 않습니다.**

  prepend(기본값)를 통해 DelayedJob 계측이 설치된 경우, 동일한 프로세스에서 두 개 이상의 `Delayed::Worker`을(를) 생성하면 에이전트가 &quot;Installing DelayedJob instrumentation&quot;을 로그에 기록하고 추가 작업자마다 플러그인을 다시 초기화했습니다. 이는 무해하지만 노이즈가 많았으며, 이제 기존 체인 계측 동작과 일치하도록 프로세스당 한 번만 수행됩니다. [PR#3654](https://github.com/newrelic/newrelic-ruby-agent/pull/3654)

* **버그 수정: 허용 목록의 설정 값은 더 이상 대소문자를 구분하지 않습니다**

  이전에는 허용 목록에 지정된 설정 옵션에 정확한 대소문자 일치가 필요했으므로, 예상치 못한 대소문자가 포함된 값 — 예를 들어 `slow_sql.record_sql`에 대한 `OBFUSCATED` 또는 `ObFuScAtEd` — 은 조용히 기본값으로 대체되었습니다. 이제 허용 목록을 기준으로 유효성을 검사하는 설정 옵션은 대소문자에 관계없이 값과 일치하므로, 두 값 모두 `obfuscated`과(와) 동일하게 처리됩니다. [이슈#3613](https://github.com/newrelic/newrelic-ruby-agent/issues/3613) [PR#3645](https://github.com/newrelic/newrelic-ruby-agent/pull/3645)

* **버그 수정: Puma가 지연 로드될 때 Puma 계측이 작동합니다.**

  `gem "puma", require: false`의 경우, 에이전트의 의존성 검사가 실행될 때 Puma가 아직 로드되지 않아 Puma 계측 설치에 실패했습니다. 이제 에이전트는 `Puma::RackHandler`을(를) Puma가 존재한다는 증거로 인식하여 이 문제를 해결합니다. [Issue#3641](https://github.com/newrelic/newrelic-ruby-agent/issues/3641) [PR#3650](https://github.com/newrelic/newrelic-ruby-agent/pull/3650)
