## v8.7.0

* **APM logs-in-context 로그 포워딩이 기본적으로 활성화됩니다.**

  이제 자동 애플리케이션 로그 포워딩이 기본적으로 활성화됩니다. 이 버전의 에이전트는 보강된 애플리케이션 로그를 뉴렐릭으로 자동 전송합니다. 이 기능에 대해 자세히 알아보려면 [여기](https://docs.newrelic.com/docs/apm/new-relic-apm/getting-started/get-started-logs-context/)를 참조하시고, 추가 설정 옵션은 [여기](https://docs.newrelic.com/docs/logs/logs-context/configure-logs-context-ruby)에서 확인하실 수 있습니다. 계정별로 로그 수집을 켜거나 끄는 방법을 알아보려면 [여기](https://docs.newrelic.com/docs/logs/logs-context/disable-automatic-logging)를 참조하십시오.

* **향상된 비동기 지원 및 스레드 계측**

  이전에는 에이전트가 이미 실행 중인 트랜잭션 내에서 생성된 스레드 내부의 이벤트와 메트릭을 기록할 수 없었습니다. 이번 릴리스에는 멀티스레드 애플리케이션이 스레드를 자동으로 계측하도록 지원하는 2개의 새로운 설정 옵션이 포함되어 있습니다. 새로운 설정 옵션인 `instrumentation.thread.tracing` (기본적으로 비활성화됨)이 도입되었으며, 이 옵션을 활성화하면 에이전트가 애플리케이션에서 생성한 모든 스레드 내부에 뉴렐릭 트레이싱을 삽입할 수 있습니다. 뉴렐릭에 의해 일부 스레드만 계측되기를 원하는 애플리케이션을 지원하기 위해, 뉴렐릭 계측을 포함하는 스레드를 생성하는 새로운 클래스인 `NewRelic::TracedThread`을(를) 사용할 수 있습니다. 자세한 내용은 [API 문서](https://www.rubydoc.info/gems/newrelic_rpm/NewRelic)를 참조하십시오.

  지원 중단된 버전의 gem의 경우, 멀티버스 제품군에서 해당 버전을 더 이상 테스트하지 않습니다. 하지만 에이전트와는 여전히 호환될 수 있습니다. 이러한 버전의 gem 문제에 대한 버그 리포트는 더 이상 수정하지 않습니다.

* **내부적으로 `Object.const_get`을(를) 활용하며 `Object.const_defined?`**

  문자열에서 클래스 상수를 동적으로 확인하거나 핸들을 얻을 때, 가능한 한 `Object` 클래스의 내장 메서드를 활용하여 더 간단하고 성능이 뛰어난 작업을 수행하십시오. 모든 JRuby 및 CRuby v2.5 이하 버전은 지정된 네임스페이스와 다른 네임스페이스에서 원치 않는 상수를 생성할 수 있으므로 `Object`이(가) 제공할 수 있는 것 이상의 약간의 지원이 필요합니다. 하지만 다른 모든 Ruby의 경우, 그리고 들어오는 문자열 값을 100% 신뢰할 수 있는 컨텍스트의 Ruby의 경우에도 `Object` 클래스의 메서드를 활용하여 이점을 얻으십시오.

* **`rake.tasks` 설정에 대한 문서를 명확히 했습니다**

  기본 `newrelic.yml` 파일의 `rake.tasks` 설명과 [뉴렐릭 루비 에이전트 설정 문서](https://docs.newrelic.com/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration#rake-tasks)가 동작 및 사용법을 명확하게 하기 위해 업데이트되었습니다. 이제 문서의 내용은 다음과 같습니다:

  > 자동으로 계측할 Rake 작업의 어레이를 지정하십시오. 이 설정 옵션은 어레이를 정규식 목록으로 변환합니다. 기본적으로 모든 작업을 허용하려면 `rake.tasks: [.+]`을(를) 사용하십시오. Rake 작업은 이 목록에 추가되지 않는 한 계측되지 않습니다. 자세한 내용은 (뉴렐릭 Rake 계측 문서)\[/docs/apm/agents/ruby-agent/background-jobs/rake-instrumentation]를 확인해 주십시오.

  이러한 변경 사항을 제안해 주신 @robotfelix 님께 감사드립니다.

* **어레이 설정이 어레이로 변환되도록 환경 변수 설정을 활성화합니다.**

  이 변경 이전에는 쉼표로 구분된 목록이 환경 변수로 전달될 때 `newrelic_agent.log`에 오류가 출력되고 문자열이 값으로 설정되었습니다. 이제 어레이가 정확하게 강제 변환됩니다.

* **버그 수정: TransactionEvents가 예상된 비율로 샘플링되도록 허용합니다.**

  TransactionEventAggregator 내의 `transaction_events.max_samples_stored` 용량 값이 예상되는 하베스트 주기 간격과 일치하지 않아 TransactionEvents가 과도하게 샘플링되었습니다. 이 버그 수정은 이름이 변경된 `transaction_events*` 설정 옵션에 대해 간격과 용량이 예상대로 작동하도록 [#952](https://github.com/newrelic/newrelic-ruby-agent/pull/952)에서 이루어진 업데이트를 기반으로 합니다.

* **버그 수정: 트랜잭션 외부에서 생성될 때 오류 이벤트에 속성이 누락되는 문제**

  이전에는 에이전트가 트랜잭션 범위 밖에서 notice\_error를 호출하여 생성된 오류 이벤트에 우선순위를 할당하지 않았습니다. 이로 인해 오류 이벤트 버퍼가 가득 찼을 때 샘플링에 문제가 발생하여 newrelic\_agent.log에 `NoMethodError: undefined method '<' for nil:NilClass`이(가) 기록되었습니다. 이 버그 수정은 에이전트가 이러한 오류 이벤트를 올바르게 샘플링할 수 있도록 오류 이벤트에 항상 우선순위가 할당되도록 보장합니다. 이 문제를 알려주신 @olleolleolle 님께 감사드립니다.
