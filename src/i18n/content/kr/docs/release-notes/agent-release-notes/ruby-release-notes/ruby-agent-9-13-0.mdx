## v9.13.0

버전 9.13.0은 AWS Lambda 함수에 대한 지원을 강화하고, 실험적인 OpenSearch 계측을 추가하며, 프레임워크 감지를 업데이트하고, Bundler 지원 중단 경고를 숨기고, Falcon 디스패처 감지를 수정하고, 레디스 계측 설치와 관련된 버그를 수정하며, JRuby 관련 동시성 문제를 해결합니다.

* **기능: AWS Lambda 함수 계측 강화**

최신 [AWS Lambda용 뉴렐릭 루비 레이어](https://layers.newrelic-external.com/)를 통해 활용할 경우, 이제 에이전트는 향상된 AWS Lambda 함수 계측 지원을 제공합니다.

* AWS Lambda 함수에 대한 에이전트의 계측이 이제 분산 추적을 지원합니다.

* 웹 트리거 호출은 이제 API Gateway 호출이 포함될 때 “web” 기반인 것으로 식별되며, API Gateway 버전 1.0과 2.0을 모두 지원합니다.

* 웹 기반 호출에는 HTTP 메서드, URI 및 상태 코드가 기록됩니다.

* 에이전트는 이제 Lambda 함수 호출을 트리거할 수 있는 12개의 개별 AWS 리소스를 인식하고 보고합니다: ALB, API Gateway V1, API Gateway V2, CloudFront, CloudWatch Scheduler, DynamoStreams, Firehose, Kinesis, S3, SES, SNS 및 SQS.

* 각 리소스에 대해 트리거하는 리소스의 유형과 해당 ARN이 기록되며, 많은 리소스의 경우 리소스별 추가 속성도 기록됩니다. 예를 들어, S3 버킷 활동으로 트리거된 Lambda 함수 호출의 경우 이제 S3 버킷 이름이 기록됩니다. [PR#2811](https://github.com/newrelic/newrelic-ruby-agent/pull/2811)

* **기능: 실험적인 OpenSearch 계측 추가**

  에이전트는 이제 `opensearch-ruby` gem을 자동으로 계측합니다. 이 계측을 완전히 테스트하려면 더 많은 작업이 필요하므로 실험적인 기능으로 표시합니다. OpenSearch 계측은 Elasticsearch와 유사한 텔레메트리를 제공합니다. 문제를 보고해 주신 [@Earlopain](https://github.com/Earlopain) 님과 계측의 초기 초안을 작성해 주신 [@praveen-ks](https://github.com/praveen-ks) 님께 감사드립니다. [Issue#2228](https://github.com/newrelic/newrelic-ruby-agent/issues/2228) [PR#2796](https://github.com/newrelic/newrelic-ruby-agent/pull/2796)

* **기능: Grape 및 Padrino의 프레임워크 감지 정확도 향상**

  이전에 Grape 프레임워크를 사용하는 애플리케이션은 환경 보고서 내에서 프레임워크를 `ruby` (으)로 설정했습니다. 이제 Grape 애플리케이션은 `grape`(으)로 설정됩니다. 마찬가지로 Padrino 프레임워크를 사용하는 애플리케이션은 `sinatra`(으)로 설정되었습니다. 이제 `padrino`(으)로 설정됩니다. 이는 뉴렐릭 보안 에이전트 호환성 검사에 도움이 됩니다. 이 변경 작업을 수행해 주신 [@prateeksen](https://github.com/prateeksen) 님께 감사드립니다. [Issue#2777](https://github.com/newrelic/newrelic-ruby-agent/issues/2777) [PR#2789](https://github.com/newrelic/newrelic-ruby-agent/pull/2789)

* **기능: Bundler `all_specs` 지원 중단 경고 숨김 처리**

  `Bundler.rubygems.all_specs` Bundler 버전 2 이상에서는 `Bundler.rubygems.installed_specs` (으)로 대체되어 더 이상 사용되지 않게 되었으며, 이로 인해 에이전트가 사용 중단 경고를 발생시켰습니다. Bundler 2 이상이 감지될 때 메서드가 업데이트되었으며 이제 경고가 표시되지 않습니다. 이 문제를 보고해 주신 [@jcoyne](https://github.com/jcoyne) 님께 감사드립니다. [Issue#2733](https://github.com/newrelic/newrelic-ruby-agent/issues/2733) [PR#2823](https://github.com/newrelic/newrelic-ruby-agent/pull/2823)

* **버그 수정: Falcon 디스패처 감지 수정**

  이전에는 객체 공간을 사용하여 [Falcon 웹 서버](https://github.com/socketry/falcon)가 사용 중인지 확인하려고 했습니다. 하지만 환경 보고서가 생성된 후에야 Falcon이 객체 공간에 추가되므로, 그 결과 `nil` 디스패처가 반환되는 문제가 있었습니다. 이제 `File.basename`을(를) 사용하여 디스패처를 검색했던 이전 전략으로 되돌아갑니다. 이 문제를 보고하고 원인을 조사해 주신 [@prateeksen](https://github.com/prateeksen) 님께 감사드립니다. [Issue#2778](https://github.com/newrelic/newrelic-ruby-agent/issues/2778) [PR#2795](https://github.com/newrelic/newrelic-ruby-agent/pull/2795)

* **버그 수정: Redis::Cluster::Client가 존재할 때 발생하는 레디스 계측 오류 수정**

  이전의 레디스 계측에는 메서드 외부에서 루비 `return`을(를) 사용함으로 인해 `Redis::Cluster::Client`이(가) 존재할 때 오류를 발생시키는 버그가 있었습니다. 이 버그를 보고해 주셨을 뿐만 아니라 근본적인 원인까지 알려주신 [@jdelStrother](https://github.com/jdelStrother) 님께 진심으로 감사드립니다. [Issue#2814](https://github.com/newrelic/newrelic-ruby-agent/issues/2814) [PR#2816](https://github.com/newrelic/newrelic-ruby-agent/pull/2816)

* **버그 수정: 설정 해시 액세스와 관련된 JRuby 동시성 문제 해결**

  에이전트의 내부 설정 클래스는 가끔 다시 빌드되는 해시를 유지 관리합니다. 다시 빌드하는 동안 이전에 동적으로 결정된 특정 계측 값은 [뉴렐릭 루비 보안 에이전트](https://github.com/newrelic/csec-ruby-agent)를 위해 보존됩니다. 수정되는 동안 해시에 액세스하는 것과 관련된 동시성 문제에 대한 JRuby 고객의 보고가 있은 후, 이전에 해시 재빌드 로직에 두 가지 개별 수정 사항이 적용되었습니다: `Hash#dup` 작업 및 `synchronize do` 블록. 하지만 여전히 오류가 보고되었습니다. 정확히 동일한 버전의 JRuby와 보고된 모든 소프트웨어를 사용했음에도 불구하고 이러한 동시성 오류를 재현할 수 없었습니다. 문제의 해시 액세스 코드가 루비 보안 에이전트(비프로덕션 전용 보안 테스트 환경에서만 작동함)에만 필요하다는 것을 확인한 후, JRuby가 실행 중이지만 보안 에이전트가 실행되지 않을 때 문제가 되는 코드를 단순히 건너뛰는 JRuby 고객을 위한 새로운 수정 사항을 도입했습니다. [PR#2798](https://github.com/newrelic/newrelic-ruby-agent/pull/2798)
