## v10.9.1

* **버그 수정: Action Controller 계측은 컨트롤러 클래스를 식별할 수 없을 때 더 이상 오류를 발생시키지 않습니다.**

  에이전트가 요청의 컨트롤러 클래스를 식별할 수 없는 경우, `TypeError: no implicit conversion of nil into String`을(를) 로그에 기록한 다음 `NoMethodError: undefined method 'finish' for nil`을(를) 기록하고 해당 요청에 대한 데이터를 기록하지 않았습니다. 이제 이러한 트랜잭션의 이름은 `Controller/(unknown)/<action>` (으)로 지정되며 정상적으로 기록됩니다. [PR#3691](https://github.com/newrelic/newrelic-ruby-agent/pull/3691)

* **버그 수정: 대용량 페이로드를 보고할 때 `Parallel` 워커가 멈추는 문제를 방지합니다.**

  `parallel` 계측이 활성화된 경우, `in_processes:`이(가) 있는 `Parallel.each`/`Parallel.map`이(가) 무한정 멈출 수 있었습니다. 각 워커는 에이전트가 이전 형제 프로세스를 위해 등록한 파이프 쓰기 끝을 상속받았기 때문에, 해당 파이프가 파일 끝에 도달할 수 없었고 에이전트의 파이프 리스너 스레드가 그중 하나를 기다리며 차단되었습니다. 데이터가 운영 시스템 파이프 버퍼를 초과하는 모든 워커는 종료 시 차단되었습니다. 이제 에이전트는 포크 직후 상위에서 각 파이프의 쓰기 끝을 닫으며, 다른 파이프에 여전히 대기 중인 데이터가 있는 동안 리스너는 더 이상 단일 파이프에서 차단되지 않습니다. 이 버그를 보고해 주신 [@yayamochi](https://github.com/yayamochi) 님께 감사드립니다. [Issue#3680](https://github.com/newrelic/newrelic-ruby-agent/issues/3680) [PR#3688](https://github.com/newrelic/newrelic-ruby-agent/pull/3688)

* **버그 수정: 신세틱스 모니터의 requests에서 gRPC 호출이 더 이상 실패하지 않습니다.**

  신세틱스 모니터의 요청이 gRPC 호출을 수행할 때 에이전트는 호출의 메타데이터에 `X-NewRelic-Synthetics`을(를) 추가했습니다. gRPC는 소문자 메타데이터 키만 허용하므로 호출 시 `ArgumentError: 'X-NewRelic-Synthetics' is an invalid header key`이(가) 발생했습니다. 이제 에이전트는 신세틱스 헤더를 소문자로 보냅니다. gRPC 서버 트랜잭션은 이제 수신되는 메타데이터에서 신세틱스 헤더도 읽으므로, 신세틱 검사 중에 호출된 gRPC 서비스는 해당 트레이스 및 신세틱스 속성을 기록합니다. [PR#3693](https://github.com/newrelic/newrelic-ruby-agent/pull/3693)
