## Notes

이번 파이썬 에이전트 릴리스에서는 AI 모니터링 서버 측 설정에 대한 지원을 추가하고, [Microsoft 에이전트 프레임워크](https://pypi.org/project/agent-framework/)를 통해 이루어진 Bedrock 호출에 대한 컨텍스트 전파를 추가하며, 원격 MCP 서버를 기반으로 하는 [LangChain](https://pypi.org/project/langchain) 도구의 중복 도구 엔티티를 수정하고, 가비지 컬렉션 데이터 샘플러의 경쟁 조건 위험을 줄이며, [Wagtail](https://pypi.org/project/wagtail) 사용 시 일관되지 않은 트랜잭션 이름을 수정하고, 아웃바운드 [Kombu](https://pypi.org/project/kombu) 분산 추적 헤더에서 바이트 인코딩을 제거합니다.

`easy_install/pip/distribute` 사용하여 에이전트를 설치하세요. [파이썬 패키지 인덱스를](https://pypi.python.org/pypi/newrelic) 통해 `conda` 사용하거나, [Conda-Forge 패키지 인덱스를](https://anaconda.org/conda-forge/newrelic) 통해 을 사용하거나, [뉴렐릭 다운로드 사이트](https://download.newrelic.com/python_agent/release) 에서 직접 다운로드하세요.

## 새로운 기능

* AI 모니터링 서버 측 설정 지원 추가

  * 이제 파이썬 에이전트는 AI 모니터링의 [서버 측 설정](https://docs.newrelic.com/docs/apm/agents/python-agent/configuration/python-agent-configuration/#ai-monitoring) 을 지원합니다. 설정된 경우 서버 측 `ai_monitoring.enabled`, `ai_monitoring.record_content.enabled` 및 `ai_monitoring.streaming.enabled` 값이 로컬 설정보다 우선합니다.

* 에이전트 프레임워크를 통한 Bedrock 호출에 대한 컨텍스트 전파를 추가합니다.

  * [Microsoft 에이전트 프레임워크](https://pypi.org/project/agent-framework/)의 Bedrock 통합으로 생성된 스레드 경계를 넘어 트레이스 컨텍스트를 전파합니다. 이를 통해 에이전트의 기존 [botocore](https://pypi.org/project/botocore) 계측이 에이전트 프레임워크를 통해 이루어진 Bedrock 호출에 대한 LLM 이벤트를 캡처할 수 있습니다. 이는 에이전트 프레임워크 자체에 대한 전체 계측을 추가하지 않습니다.

## 벌레

* Wagtail 사용 시 일관되지 않은 트랜잭션 이름을 수정했습니다.

  * 이전에는 [Wagtail](https://pypi.org/project/wagtail) 을 기반으로 구축된 앱의 트랜잭션 이름이 일관되지 않았으며 다른 페이지 뷰에 대해 동일할 수 있었습니다. 이 문제가 수정되었습니다.

* 원격 MCP 서버를 기반으로 하는 LangChain 도구의 중복 도구 엔티티를 수정합니다.

  * 이전에는 [LangChain](https://pypi.org/project/langchain) 도구가 별도로 계측된 원격 MCP 서버에 의해 지원될 때 UI에 중복된 도구 엔티티가 나타났습니다. 알려진 원격 도구가 감지될 때 LangChain 도구에서 하위 구성 요소 속성을 차단하여 이 문제가 해결되었습니다.

* LangChain 및 LangGraph MCP 도구 호출에 대한 누락된 사용자 입력 필드를 수정합니다.

  * 이전에는 [LangChain](https://pypi.org/project/langchain) 또는 LangGraph가 MCP 서버의 도구를 사용했을 때, 입력 메시지가 스트리밍된 시퀀스의 마지막 메시지가 아닌 경우 AI 모니터링 데이터에서 사용자 입력 필드가 누락될 수 있었습니다. 이 문제가 수정되었으며, 이제 에이전트가 이러한 경우에 입력 메시지를 올바르게 추출합니다.

* 가비지 컬렉션 데이터 샘플러에서 경쟁 조건 위험을 줄입니다.

  * 이전에는 에이전트가 설정에 관계없이 가비지 수집기 객체 수를 샘플링하기 위해 항상 `gc.get_objects()` 을(를) 호출했습니다. 가비지 수집기가 수집한 객체 유형을 추적하지 않는 고객을 위해 불필요한 힙 반복을 방지하도록, `top_object_count_limit` 이(가) `0`보다 높게 설정된 경우에만 `gc.get_objects()` 이(가) 호출되도록 변경되었습니다.

* 아웃바운드 Kombu 분산 추적 헤더에서 바이트 인코딩을 제거합니다

  * 이전에는 [Kombu](https://pypi.org/project/kombu) 계측에 의해 추가된 분산 추적 헤더가 바이트 인코딩되어, 표준 라이브러리 `json` 모듈을 사용하여 페이로드를 직렬화하는 전송(예: SQLAlchemy 기반 전송)이 손상되었습니다. 이러한 전송이 올바르게 작동하도록 바이트 인코딩이 제거되었습니다.

## 지지 성명

최신 에이전트 버전이 출시되면 즉시 업데이트하는 것이 좋습니다. 최신 버전으로 업그레이드할 수 없는 경우, 에이전트를 90일 이내 버전으로 업데이트하세요. 에이전트에게 최신 정보를 제공하는 방법에 대해 [자세히](/docs/new-relic-solutions/new-relic-one/install-configure/update-new-relic-agent/) 알아보세요.

에이전트 릴리스 및 지원 날짜에 대한 정보는 뉴렐릭 끌어 당기는 에이전트 [EOL 정책을](/docs/apm/agents/python-agent/getting-started/python-agent-eol-policy/) 참조하세요.
