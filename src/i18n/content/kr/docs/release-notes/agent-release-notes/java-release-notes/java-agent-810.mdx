## 새로운 기능 및 개선 사항

* Webflux 6 [1181](https://github.com/newrelic/newrelic-java-agent/pull/1181)지원이 추가되었습니다.

* Spring JMS 6 [1088](https://github.com/newrelic/newrelic-java-agent/issues/1088)지원이 추가되었습니다.

* MongoDB 반응형 스트림 지원이 추가되었습니다(버전 [1164).](https://github.com/newrelic/newrelic-java-agent/pull/1164)

* Kafka Streams [1170](https://github.com/newrelic/newrelic-java-agent/pull/1170)지원이 추가되었습니다.

  Kafka Streams 지원은 메트릭과 스팬이라는 두 가지 방식으로 제공됩니다. 메트릭은 기본적으로 활성화되어 있고, 스팬은 기본적으로 비활성화되어 있습니다. 스팬을 활성화하려면 *newrelic.yml* 파일의 common 섹션 아래 설정에 다음 내용을 추가하세요.

```
common:
  class_transformer:
    kafka-streams-spans:
      enabled: true
```

* 오류 지문 - 자체 오류 수신함(errors inbox) 그룹 이름을 제공하세요 [1195](https://github.com/newrelic/newrelic-java-agent/pull/1195)

  에러 발생이 잘못 그룹화되어 있습니까? 콜백 함수를 통해 자체 에러 핑거프린트를 설정하십시오. 사용자 정의 proc를 허용하는 새로운 공개 API 메서드가 추가되었습니다. proc는 감지된 각 에러에 대해 호출되며, 문자열을 반환할 때마다 해당 문자열이 에러의 에러 그룹 이름으로 사용되고 뉴렐릭 에러스 인박스(errors inbox)에서 발생하는 모든 서버 측 그룹화보다 우선 적용됩니다. 이를 통해 사용자는 에러 그룹화에 대해 훨씬 더 많은 제어 권한을 가질 수 있습니다. 자세한 내용은 [API: 에러 그룹화](/docs/apm/agents/java-agent/api-guides/java-agent-api-register-error-group-callback-to-set-fingerprint/) 및 [APM: 에러 그룹 탭](/docs/triage-inbox/apm-tab/) 페이지를 확인하십시오.

* 사용자 추적 - 오류를 사용자 ID [1188](https://github.com/newrelic/newrelic-java-agent/pull/1188)과 연결

  이제 오류 그룹의 영향을 받는 사용자 수를 확인할 수 있습니다. 사용자 ID의 문자열 표현을 허용하고 해당 사용자 ID를 현재 트랜잭션과 연결하는 새로운 공개 API 메서드로 최종 사용자를 식별하십시오. 그러면 트랜잭션과 오류에 새로운 `enduser.id` 에이전트 속성이 연결됩니다. 이를 통해 에이전트 사용자는 더 나은 필터링 및 알림 기능을 지원하기 위해 트랜잭션과 오류를 특정 사용자 ID에 속하는 것으로 태그할 수 있습니다. 자세한 내용은 \[Newrelic.setUserId ]\([https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName(java.lang.String)](https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName\(java.lang.String\)) 문서 및 [에러스 인박스(errors inbox)로 영향을 받는 사용자 추적](/docs/triage-inbox/error-users-impacted/) 페이지를 확인하십시오.

* 소니 외부에서 `token.link()` 호출하면 해당 메소드가 비동기 프로세서 [1140을](https://github.com/newrelic/newrelic-java-agent/pull/1140)시작하게 됩니다.

* Kafka 클라이언트 측정, 로그에는 노드를 나열하는 새로운 지표가 있습니다: `MessageBroker/Kafka/Nodes/&lt;node>` [1130](https://github.com/newrelic/newrelic-java-agent/pull/1130)

## 최신 버전으로 업데이트 [#procedures]

현재 사용 중인 Java 에이전트 버전을 식별하려면 `java -jar newrelic.jar -v` 을 실행합니다. Java 에이전트 버전이 콘솔에 인쇄됩니다.

그런 다음 최신 Java 에이전트 버전으로 업데이트하려면 다음을 수행합니다.

1. **전체** [Java 에이전트 루트 디렉터리](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) 를 다른 위치에 백업합니다. 해당 디렉토리의 이름을 `NewRelic_Agent#.#.#` 으로 바꿉니다. 여기서 `#.#.#` 은 에이전트 버전 번호입니다.
2. [에이전트를 다운로드합니다.](/docs/release-notes/agent-release-notes/java-release-notes)
3. 새 에이전트 다운로드 파일의 압축을 푼 다음 `newrelic-api.jar` 및 `newrelic.jar` 을 원래 [Java 에이전트 루트 디렉토리](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) 에 복사합니다.
4. 이전 `newrelic.yml` 을 zip에서 새로 다운로드한 `newrelic.yml` 과 비교 [하고 필요한 경우 파일을 업데이트합니다](#diff) .
5. Java 디스패처를 다시 시작하십시오.

Java 에이전트 업데이트 후 문제가 발생하면 백업된 New Relic 에이전트 디렉터리에서 복원하십시오.

## 에이전트 구성 차이점 업데이트 [#diff]

에이전트의 새 버전을 출시할 때 `newrelic.yml` 에 새 설정을 추가합니다.`diff` 또는 다른 diffing 유틸리티를 사용하여 변경된 사항을 확인하고 이전 파일에 새 구성 설정을 추가할 수 있습니다.라이센스 키, 앱 이름 또는 기본 설정 변경 사항과 같이 파일에 대해 수행한 사용자 정의를 덮어쓰지 않도록 하십시오.

예를 들어, יאני 버전 7.10.0 및 7.11.0에 대한 기본 `newrelic.yml` 파일을 `diff` 하는 경우 콘솔에 인쇄된 결과는 다음과 같습니다.

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

이 예에서 이러한 줄은 Java의 기본값 `newrelic.yml` 에 추가되었습니다. 7.11.0 이상 버전으로 업그레이드하는 경우 원래 `newrelic.yml` 에 다음 새 줄을 추가해야 합니다.
