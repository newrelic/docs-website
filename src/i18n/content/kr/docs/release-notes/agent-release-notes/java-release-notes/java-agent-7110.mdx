## 새로운 기능 및 개선 사항

* 지원 19 [1022](https://github.com/newrelic/newrelic-java-agent/pull/1022)

* Support Play 2.8.16+ [981](https://github.com/newrelic/newrelic-java-agent/pull/981)

* ojdbc8 v21.1.0.0+ [1042](https://github.com/newrelic/newrelic-java-agent/pull/1042)지원

* Semeru/OpenJ9 JVM [993](https://github.com/newrelic/newrelic-java-agent/pull/993)지원

* java.util.logging(JUL) [1049](https://github.com/newrelic/newrelic-java-agent/pull/1049)에 대한 로그 포워딩 지원

* 로그 컨텍스트 데이터 [866](https://github.com/newrelic/newrelic-java-agent/pull/866)전달 지원

  이제 에이전트는 로그 레코드를 전달할 때 매핑된 진단 컨텍스트(MDC, logback/slf4j) 및 스레드 컨텍스트(log4j2)의 데이터를 속성으로 전달할 수 있습니다. 이 기능이 활성화되면 이러한 속성은 `context.` 접두사와 함께 로그 기록에 추가됩니다. 이 기능을 활성화하는 방법에 대한 자세한 내용은 [context\_data](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#logging-context-data) 설명서를 참조하십시오.

* 맞춤형 대시보드 한도 증가 [1036](https://github.com/newrelic/newrelic-java-agent/pull/1036)

  이 버전은 커스텀 대시보드의 기본 제한을 분당 10,000개 이벤트에서 분당 30,000개 이벤트로 늘립니다. 커스텀 대시보드가 제한되는 시나리오에서, 이 변경 사항을 통해 더 많은 커스텀 대시보드를 뉴렐릭으로 보낼 수 있습니다. 또한 분당 100,000개의 이벤트라는 구성 가능한 새로운 최대 한도가 있습니다. 제한을 변경하려면 [max\_samples\_stored](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Custom_Events) 문서를 참조하십시오. 변경 사항 및 커스텀 대시보드가 삭제되고 있는지 확인하는 방법에 대해 자세히 알아보려면 Explorers Hub [게시물](https://support.newrelic.com/s/hubtopic/aAX8W0000008dby/send-more-custom-events-with-the-latest-apm-agents)을 참조하십시오.

* 코드 레벨 지표는 기본적으로 [1037](https://github.com/newrelic/newrelic-java-agent/pull/1037)입니다.

  에이전트 7.10에 도입된 코드 레벨 지표 기능이 이제 기본적으로 활성화됩니다. 이 기능으로 인해 데이터 사용량이 증가할 것입니다. 금액은 계약에 따라 다릅니다. 앱 레벨 플레이스를 비활성화하려면 [앱 레벨 플레이 설명서](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#code-level-metrics) 의 지침을 참조하세요.

## 최신 버전으로 업데이트 [#procedures]

현재 사용 중인 Java 에이전트 버전을 식별하려면 `java -jar newrelic.jar -v` 을 실행합니다. Java 에이전트 버전이 콘솔에 인쇄됩니다.

그런 다음 최신 Java 에이전트 버전으로 업데이트하려면 다음을 수행합니다.

1. **전체** [Java 에이전트 루트 디렉터리](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) 를 다른 위치에 백업합니다. 해당 디렉토리의 이름을 `NewRelic_Agent#.#.#` 으로 바꿉니다. 여기서 `#.#.#` 은 에이전트 버전 번호입니다.
2. [에이전트를 다운로드합니다.](/docs/release-notes/agent-release-notes/java-release-notes)
3. 새 에이전트 다운로드 파일의 압축을 푼 다음 `newrelic-api.jar` 및 `newrelic.jar` 을 원래 [Java 에이전트 루트 디렉토리](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) 에 복사합니다.
4. 이전 `newrelic.yml` 을 zip에서 새로 다운로드한 `newrelic.yml` 과 비교 [하고 필요한 경우 파일을 업데이트합니다](#diff) .
5. Java 디스패처를 다시 시작하십시오.

Java 에이전트 업데이트 후 문제가 발생하면 백업된 New Relic 에이전트 디렉터리에서 복원하십시오.

## 에이전트 구성 차이점 업데이트 [#diff]

에이전트의 새 버전을 출시할 때 `newrelic.yml` 에 새 설정을 추가합니다.`diff` 또는 다른 diffing 유틸리티를 사용하여 변경된 사항을 확인하고 이전 파일에 새 구성 설정을 추가할 수 있습니다.라이센스 키, 앱 이름 또는 기본 설정 변경 사항과 같이 파일에 대해 수행한 사용자 정의를 덮어쓰지 않도록 하십시오.

예를 들어, יאני 버전 7.10.0 및 7.11.0에 대한 기본 `newrelic.yml` 파일을 `diff` 하는 경우 콘솔에 인쇄된 결과는 다음과 같습니다.

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

이 예에서 이러한 줄은 Java의 기본값 `newrelic.yml` 에 추가되었습니다. 7.11.0 이상 버전으로 업그레이드하는 경우 원래 `newrelic.yml` 에 다음 새 줄을 추가해야 합니다.
