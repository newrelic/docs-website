### 새로운 문서

* Claude Code, Cursor, GitHub Copilot 및 Codex와 같은 AI 코딩 에이전트가 올바른 설치 문서를 찾고, 설치를 확인하며, 라이선스 키를 컨텍스트에서 제외할 수 있도록 복사하여 붙여넣을 수 있는 프롬프트가 포함된 [AI 코딩 에이전트를 사용하여 뉴렐릭 설치](/docs/new-relic-solutions/get-started/install-with-ai) 문서를 추가했습니다.
* 자세한 답변을 개요 및 설정 페이지 대신 한 곳에서 확인할 수 있도록, 지원되는 수집기 버전, 내보내기 형식, 자동 감지, 자동 분류 및 연결된 수집기를 다루는 [Collector 옵저버빌리티 FAQ](/docs/opentelemetry/collector-observability/collector-observability-faq)를 추가했습니다.
* 로깅, 프록시, 상태 서버, 상태 확인, 자체 계측 및 OCI 레지스트리 옵션 등 수정 가능한 에이전트 제어 설정과 그 기본값을 나열한 [에이전트 제어 설정 참조](/docs/new-relic-control/agent-control/configuration-reference)를 추가했습니다.
* Azure에서 MySQL 또는 PostgreSQL을 실행하는 팀이 NRDOT Collector를 사용하여 데이터베이스 옵저버빌리티를 설정할 수 있도록 [Azure 유연한 서버를 사용한 MySQL 모니터링용 NRDOT 설치 및 구성](/docs/opentelemetry/db360/mysql/azure) 및 [Azure 유연한 서버를 사용한 PostgreSQL 모니터링용 NRDOT 설치 및 구성](/docs/opentelemetry/db360/postgresql/azure)을 추가했습니다.
* eMudhra 인증 기관 손상이 로그 통합(Fluent Bit 출력 플러그인, 인프라 에이전트 로그 포워딩 및 Helm 차트)에 미치는 영향을 다룬 [보안 게시판 NR26-13](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-13)을 추가했습니다.
* nri-bundle 및 관련 Helm 차트를 포함하여 Kubernetes 통합에 대한 eMudhra 인증 기관 손상의 영향을 다루는 [보안 게시판 NR26-14](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-14)를 추가했습니다.
* 인프라 에이전트 및 온-호스트 통합에 대한 eMudhra 인증 기관 손상의 영향을 다루는 [보안 게시판 NR26-15](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-15)를 추가했습니다.
* 영향을 받는 뉴렐릭 구성 요소에 대한 조치 항목과 함께 OpenJDK Java4Shell 원격 코드 실행 결함(CVE-2026-114938)에 대한 [보안 게시판 NR26-16](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-16)을 추가했습니다.
* 루비 에이전트를 사용하는 고객은 아무런 조치를 취할 필요가 없다는 점을 명시하며, Ruby2Shell 메모리 손상 취약점(CVE-2026-132825)과 이 취약점이 `newrelic-fluentd-docker`, `newrelic/fluentd` 및 `k8s-golang-apm-linkage-demo` 컨테이너 이미지에 미치는 영향에 대한 [보안 게시판 NR26-17](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-17)을 추가했습니다.

### 주요 변경 사항

* 이제 [Collector 옵저버빌리티](/docs/opentelemetry/collector-observability/collector-observability)를 정식 버전으로 사용할 수 있습니다. 자세한 설명을 위해 새로운 스크린샷과 새로운 [Collector 옵저버빌리티 FAQ](/docs/opentelemetry/collector-observability/collector-observability-faq) 에 대한 링크로 개요 및 설정 [페이지를 업데이트했습니다.](/docs/opentelemetry/collector-observability/collector-observability-setup)
* 어떤 requests가 자동으로 트레이스되는지, 트레이스 상관관계를 위해 무엇을 활성화해야 하는지, 트레이스를 끄는 방법을 설명하도록 [뉴렐릭 iOS 에이전트 및 분산 추적](/docs/mobile-monitoring/new-relic-mobile-ios/get-started/new-relic-ios-and-dt)과 [뉴렐릭 안드로이드 에이전트 및 분산 추적](/docs/mobile-monitoring/new-relic-mobile-android/get-started/new-relic-android-and-dt)을 다시 작성했습니다. 두 페이지 모두에서 오래된 동영상을 제거했습니다.
* 관리자가 각 기본 역할이 부여하는 권한을 확인할 수 있도록 플릿, 시크릿, Lens 커넥터, AI 에이전트, NRQL 매크로, 노트북, 공지 정책 및 대시보드 역할을 포함한 조직, 계정 및 엔티티 범위의 표준 역할 표를 추가하여 [중요한 사용자 및 액세스 관리 개념](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts)을 업데이트했습니다.
* 사용자가 영향을 받는 자바 버전을 실행하는 APM 엔티티를 찾을 수 있도록, PHP 및 Node.js 권고와 함께 Java4Shell 권고(CVE-2026-114938)를 포함하고 새로운 <DNT>Exposure</DNT> 및 <DNT>How to fix</DNT> 요약 카드를 설명하도록 [Exposure check\[노출 확인\]](/docs/vulnerability-management/exposure-check)를 업데이트했습니다.
* 컴파일되지 않는 예제와 iOS, 안드로이드 및 리액트 네이티브에서의 에이전트 동작과 일치하지 않는 태그 규칙을 수정하고, 비밀번호 필드가 마스킹된 상태로 유지된다는 점을 명확히 하기 위해 모바일 세션 리플레이용 [개인정보 보호 설정 구성](/docs/mobile-monitoring/mobile-monitoring-ui/mobile-session-replay/configure-privacy-settings)을 업데이트했습니다.
* 사용자 API 키로 인증하기 위한 요구 사항, 액세스 및 `mcp.json` 설정을 포함하여, Cursor를 지원되는 MCP 클라이언트로 추가하여 [MCP 설정](/docs/agentic-ai/mcp/setup) 및 [MCP 개요](/docs/agentic-ai/mcp/overview)를 업데이트했습니다.
* 팀이 프롬프트를 작성하지 않고도 Slack 공지 스레드에서 조사를 시작할 수 있도록, 공지에 있는 <DNT>**Investigate with AI**</DNT> 버튼에 대한 내용을 추가하여 [Autopilot을 Slack에 연결](/docs/agentic-ai/autopilot/connect-to-slack)을 업데이트했습니다.
* `reportLogs`이(가) 이제 `"false"` 대신 `"auto"`을(를) 기본값으로 사용하고 기본 `fileRegex`이(가) 이제 `".*\\.log$"`임을 반영하도록 [eBPF 로그](/docs/ebpf/logs), [Kubernetes 설치](/docs/ebpf/k8s-installation) 및 [Linux 설치](/docs/ebpf/linux-installation)를 업데이트했습니다.
* 사용자가 비율 기반 샘플링을 구성할 수 있도록 루비 에이전트용 `trace_id_ratio_based` 샘플러 설정으로 [루비 에이전트 분산 추적 설정](/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration-distributed-tracing-settings) 및 [분산 트레이스 샘플링](/docs/apm/distributed-tracing/distributed-trace-sampling)을 업데이트했습니다.
* Google이 해당 메트릭을 정의하지 않거나 알파 또는 사용 중단된 것으로 분류하기 때문에, 뉴렐릭이 수집하지 않는 메트릭을 [Google BigQuery](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-bigquery-monitoring-integration), [Google Cloud Pub/Sub](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-pubsub-monitoring-integration) 및 [Google Cloud Storage](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-storage-monitoring-integration) 통합 페이지에서 제거했습니다.

### 사소한 변경 사항

* 각 지원 케이스 상태의 의미를 설명하는 케이스 상태 정의 테이블을 포함하도록 [도움말 찾기 및 지원 받기](/docs/new-relic-solutions/solve-common-issues/find-help-get-support)를 업데이트했습니다.
* 읽기 전용 `get_retention_policy_and_namespaces`, `get_user_id` 및 `list_support_cases` 도구와 Kafka Autopilot 스킬에 대한 내용을 추가하여 [MCP 도구 참조](/docs/agentic-ai/mcp/tool-reference)를 업데이트했습니다.
* 사용자를 삭제하는 것보다 MCP 서버 권한이 있는 모든 그룹에서 사용자를 제거하는 것이 한 사용자의 액세스 권한을 취소하는 데 영향이 더 적은 방법임을 설명하도록 [MCP 개요](/docs/agentic-ai/mcp/overview)를 업데이트했습니다.
* Agent Control\[에이전트 제어]이 온-호스트 통합에 대해 `unknown` 상태를 보고하는 이유와 `enable_file_logging` 출력 파일이 순환되지 않는다는 점을 설명하도록 [Agent types\[에이전트 유형\]](/docs/new-relic-control/agent-control/agent-types)를 업데이트했습니다.
* 자바 에이전트 v9.4.0 이상을 요구하고 `sql_metadata_comments.enabled` 설정을 표시하도록 [NRDOT를 사용한 데이터베이스 서비스 식별](/docs/opentelemetry/db360/capabilities/db-apm)을 업데이트했습니다.
* [커넥터 설정](/docs/new-relic-lens/set-up-connectors)에 지원되는 MongoDB 및 MongoDB용 Azure Cosmos DB 버전(4.2 이상)을 업데이트했습니다.
* 메트릭당 카디널리티 한도를 계정 한도까지 늘릴 수 있다는 점을 명확히 하도록 [카디널리티 관리](/docs/data-apis/ingest-apis/metric-api/cardinality-management)를 업데이트했습니다.
* KPI 데이터는 KPI를 생성한 시점부터 시작되며 뉴렐릭에서 이를 백필하지 않는다는 점을 명확히 하기 위해 [지능형 워크로드 KPI](/docs/new-relic-solutions/new-relic-one/workloads/intelligent-workload-kpis)를 업데이트했습니다.
* Dataflow 템플릿에 자바 11 이상이 필요하다는 내용을 명시하도록 [Google Cloud Platform에서 로그 전달](/docs/logs/forward-logs/google-cloud-platform-log-forwarding)을 업데이트했습니다.
* 최신 검증된 라이브러리 버전으로 [Node.js 에이전트](/docs/apm/agents/nodejs-agent/getting-started/compatibility-requirements-nodejs-agent) 및 [.NET 에이전트](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) 호환성 및 요구 사항 페이지를 업데이트했습니다.
