### 새로운 문서

* 시큐리티 RX 에이전트를 사용하여 CVE를 분석하고, 완화 계획을 생성하며, 코딩 에이전트가 pull 요청을 열도록 트리거하는 방법에 대한 지침을 제공하기 위해 [시큐리티 RX 에이전트를 사용한 취약점 완화 분류](/docs/vulnerability-management/agent/overview)를 추가했습니다.
* 시큐리티 RX에서 감지한 보안 취약점에 대해 자동으로 Jira 지원 티켓을 생성하고 동기화하기 위한 단계별 지침을 제공하기 위해 [시큐리티 RX Jira 워크플로우](/docs/vulnerability-management/workflows/jira)를 추가했습니다.
* MCP 서버 설정 및 구성 문제를 해결하기 위한 일반적인 문제 진단, 해결 단계 및 솔루션을 제공하기 위해 [뉴렐릭 MCP 문제 진단, 해결](/docs/agentic-ai/mcp/troubleshoot)을 추가했습니다.

### 주요 변경 사항

* 새로운 포괄적인 설정 참조, 새로운 CNCF 수집기 설정 가이드, 그리고 Windows 호스팅, Windows RDS, Linux 호스팅 및 Linux RDS 환경을 위해 전면 개편된 설치 문서를 포함하여 [NRDOT를 사용한 Microsoft SQL Server 모니터링](/docs/opentelemetry/database/mssql/introduction)을 재구성했습니다.
* 설정 파일 위치, OS별 바이너리 경로 및 업데이트 동작을 포함하여 에이전트 제어에서 Fluent Bit 로그 포워딩을 설정하는 문서를 추가하여 [에이전트 유형](/docs/new-relic-control/agent-control/agent-types)을 업데이트했습니다.
* 플릿 컨트롤의 새로운 설정 승인 워크플로우에 대한 포괄적인 문서를 포함하여 [플릿 관리](/docs/new-relic-control/fleet-control/manage-fleets)를 업데이트했습니다. 설정 버전을 배포하기 전에 설정 승인에는 작성자 외에 최소 한 명의 검토자가 필요하며, 이는 2026년 9월 22일부터 시행됩니다.
* `.workflowState`을(를) 통해 워크플로우 단계 전반에 걸쳐 핵심 가치 쌍을 유지하기 위한 새로운 State Step 작업으로 [워크플로우 자동화 정의 스키마](/docs/workflow-automation/workflow-automation-apis/definition-schema)를 업데이트했으며, 새로운 단계 유형 및 `WorkflowAutomationEvent` 데이터를 포함하도록 [워크플로우 제한](/docs/workflow-automation/limitations-and-faq/workflow-limits) 및 [실행 모니터링](/docs/workflow-automation/manage-workflows/monitor-workflow-execution)을 업데이트했습니다.
* vSphere Supervisor 9.0-9.1(vSphere 8.x 및 9.x)에서 실행되는 VKS를 포함하여 [쿠버네티스 통합 호환성 요구 사항](/docs/kubernetes-pixie/kubernetes-integration/get-started/kubernetes-integration-compatibility-requirements)에 VMware vSphere Kubernetes Service(VKS) 3.x 지원을 추가했습니다.
* 검증된 최신 호환 라이브러리 버전을 포함하여 [.NET 에이전트 호환성 요구 사항](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements)을 업데이트했습니다.
* Personalize 뷰 테이블에서 대화형 필(pill)을 통한 태그 기반 열 값 필터링 및 드래그 앤 드롭을 통한 열 재정렬을 문서화하기 위해 [카탈로그](/docs/service-architecture-intelligence/catalogs/catalogs)를 업데이트했습니다.
* AI 생성 인사이트는 조사를 안내하기 위한 제안일 뿐 확인된 근본 원인이 아니며, 조치를 취하기 전에 데이터와 대조하여 확인해야 한다는 주의 사항을 [AI를 활용한 대응 인텔리전스](/docs/alerts/alert-event-management/response-intelligence-ai)에 추가했습니다.
* [뉴렐릭 Browser 브라우저 에이전트 라이선스](/docs/licenses/product-or-service-licenses/new-relic-browser/new-relic-browser-licenses)에 `snapdom` 오픈 소스 라이브러리를 추가했습니다.
* [에러스 인박스(errors inbox) OpenTelemetry 탭](/docs/errors-inbox/otel-tab)을 업데이트하여 스팬 속성 이름을 `otel.status`에서 `otel.status_code` (으)로 수정하고, 지원되는 스팬 종류를 `server` 및 `consumer` 외에 `producer`, `client`, `internal`를 포함하도록 확장했습니다.
* 일본(JP) 데이터 리전이 이제 정식 버전으로 제공됨을 반영하도록 [데이터센터 선택](/docs/accounts/accounts-billing/account-setup/choose-your-data-center)을 업데이트했습니다.

### 사소한 변경 사항

* [뉴렐릭 MCP 설정](/docs/agentic-ai/mcp/setup)을 OAuth 인증을 위해 수정된 Claude Code CLI 명령, 최소 버전 요구 사항(Claude Code v2.1.186+), 및 간소화된 JSON 설정 형식으로 업데이트했습니다.
* 전용 Optional overrides 섹션 아래에 새로운 `otlpEndpoint` 필드를 포함하여 파이프라인별로 기본 뉴렐릭 수집 엔드포인트를 재정의하기 위해 [게이트웨이 YAML 설정 참조](/docs/new-relic-control/pipeline-control/gateway/yaml-overview)에 `nrExporterEndpoints`을(를) 추가했습니다.
* OTLP 및 트레이스 API에 대해 수정된 가장 오래된 스팬 타임스탬프 제한으로 [트레이스 API 문제 진단, 해결](/docs/apm/distributed-tracing/trace-api/troubleshooting-missing-trace-api-data) 및 [누락된 트레이스 데이터](/docs/distributed-tracing/troubleshooting/missing-trace-data)를 업데이트했습니다.
* 카디널리티 예산에 도달했을 때 발생하는 상황, 차트 및 대시보드의 경고 표시기를 통해 영향을 받는 메트릭을 식별하는 방법, 문제를 해결하는 동안 원시 데이터를 쿼리하는 방법을 설명하는 카디널리티 경고 섹션을 [카디널리티 관리](/docs/data-apis/ingest-apis/metric-api/cardinality-management)에 추가했습니다.
* [데이터 파티션](/docs/logs/ui-data/data-partitions)에 세 번째 파티션 옵션으로 Direct to Live Archive 네임스페이스를 추가하고, 이 네임스페이스가 장기 스토리지로 직접 이동하는 규정 준수 및 감사 로그에 대한 표준 보존을 우회한다고 설명하는 지침을 [라이브 아카이브](/docs/logs/get-started/live-archives)에 추가했습니다.
* API 키가 모바일 엔티티 보기 권한이 있는 사용자에게 속해야 한다고 명시하도록 [리액트 네이티브 JavaScript 오류 보고](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting)의 `403 Forbidden` 오류 설명을 수정했습니다.
* 공지 워크플로우와 통합할 때 트리거되는 공지의 문제 ID를 자동으로 전달하기 위해 `{{ issueId }}` 변수를 사용하는 방법에 대한 팁을 포함하여 [Autopilot 및 Slack을 사용한 공지 RCA](/docs/workflow-automation/workflow-examples/integrations/autopilot-slack-rca)를 업데이트했습니다.
* 조직의 마지막 활성 계정은 독립적으로 취소할 수 없으며 조직을 삭제하여 제거해야 한다는 점을 명확히 하는 설명을 추가하고, 명확성을 위해 조직 삭제 단계를 개선하도록 [계정 다운그레이드 또는 취소](/docs/accounts/accounts-billing/account-setup/downgradecancel-account)를 업데이트했습니다.
