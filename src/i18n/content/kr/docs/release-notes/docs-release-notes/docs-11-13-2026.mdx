### 새로운 문서

* CocoaPods를 사용하는 iOS 팀이 계측을 잃거나 처음부터 다시 설정할 필요 없이 스위프트 패키지 매니저로 전환할 수 있도록 [CocoaPods에서 iOS 에이전트 마이그레이션](/docs/mobile-monitoring/new-relic-mobile-ios/installation/migrate-from-cocoapods)을 추가했습니다.
* 이전 OCI 로그 전달자 설정을 실행하는 사용자가 현재 기능 및 보안 수정 사항에 액세스할 수 있는 명확한 업그레이드 경로를 확보할 수 있도록 [OCI 로그 포워딩 통합 업그레이드](/docs/logs/forward-logs/oci-log-forwarder-upgrade)를 추가했습니다.
* 팀이 사용자 지정 설정에 의존하지 않고 전체 데이터베이스 옵저버빌리티를 설정할 수 있도록, Linux 및 Windows 모두에서 Azure Managed 인스턴스와 Azure SQL 데이터베이스를 지원하는 [NRDOT를 사용한 Microsoft SQL Server 모니터링](/docs/opentelemetry/db360/mssql/introduction)을 추가했습니다.

### 주요 변경 사항

* 사용자가 하나의 큰 페이지를 검색하는 대신 필요한 설정으로 직접 이동할 수 있도록 [Node.js 에이전트 설정](/docs/apm/agents/nodejs-agent/installation-configuration/nodejs-agent-configuration)을 일반 설정, 속성, 로깅, 추적, 오류 수집, 브라우저 모니터링 및 AI 모니터링에 대한 주제별 페이지로 재구성했습니다.
* 관리자가 핵심 컴퓨트와 독립적으로 고급 컴퓨트 비용을 제어할 수 있도록, 각 미터에 대한 별도의 적용 정책 및 공지 설정을 통해 핵심 CCU와 함께 고급 CCU 예산을 포함하도록 [컴퓨트 사용자 제한](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/compute-budgets/compute-user-limits)을 업데이트했습니다.
* Valkey 메트릭을 대상으로 하는 대시보드 쿼리 및 공지 조건이 빈 결과 대신 데이터를 반환하도록 수정된 메트릭 이름으로 [Google Memorystore for Valkey](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-memorystore-valkey)를 업데이트했습니다.
* 액세스를 설정할 때 잘못된 구성을 방지하기 위해, 결제 사용자 역할을 계정 범위로 올바르게 식별하고 조직 관리자 기능에 결제를 추가하도록 [중요한 사용자 및 액세스 관리 개념](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts)을 업데이트했습니다.
* 사용자가 Azure App Services에 배포할 때 겪는 시행착오를 줄이기 위해 더 명확한 Azure 호스팅 지침으로 [Microsoft Azure App Services의 Node.js 에이전트](/docs/apm/agents/nodejs-agent/hosting-services/nodejs-agent-microsoft-azure)를 업데이트했습니다.
* 이전에 누락되었던 단계를 다루기 위해 확장된 파이프라인 컨트롤 게이트웨이 설정 지침을 포함하도록 [에이전트 설정 수정](/docs/new-relic-control/pipeline-control/gateway/modify-agent-configuration)을 업데이트했습니다.
* 수신기가 이 메트릭을 수집하지 않고 해당 메트릭의 존재로 인해 사용자가 도착하지 않을 데이터를 기대하게 되므로 수집기 설정에서 `kafka.partition.replicas.total`을(를) 제거하도록 [OpenTelemetry로 Kubernetes에서 자체 관리형 Kafka 모니터](/docs/opentelemetry/integrations/kafka/kubernetes-self-managed)를 업데이트했습니다.
* v14.11.0에서 순수 JS 구현으로 대체된 더 이상 사용되지 않는 `@newrelic/native-metrics` 패키지를 참조하는 콘텐츠를 제거하도록 [Node.js VM 측정](/docs/apm/agents/nodejs-agent/extend-your-instrumentation/nodejs-vm-measurements)을 업데이트했습니다.
* FedRAMP 승인 서비스를 평가하는 고객이 정확한 규정 준수 정보를 얻을 수 있도록 [FedRAMP](/docs/security/security-privacy/compliance/certificates-standards-regulations/fedramp)를 최신 인증 세부 정보로 업데이트했습니다.
* 이제 해당 차트 유형이 지원됨에 따라 사용자가 트리맵이 적절한 시각화인 경우와 다른 차트 유형과 어떻게 다른지 알 수 있도록 [차트 유형](/docs/query-your-data/explore-query-data/use-charts/chart-types)에 트리맵 차트 유형 문서를 추가했습니다.
* 사용자가 에이전트가 검증되었음을 알고 런타임을 자신 있게 업그레이드할 수 있도록 .NET 11 GA 지원을 확인하기 위해 [.NET 에이전트 호환성 및 요구 사항](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements)을 업데이트했습니다.

### 사소한 변경 사항

* API 가이드, 속성, 백그라운드 작업, 설정 및 분산 추적 페이지 전반에 걸쳐 [루비 에이전트 문서](/docs/apm/agents/ruby-agent/getting-started/introduction-new-relic-ruby)를 최신 에이전트 API에 맞게 업데이트하여, 기존 예제를 따르는 사용자가 더 이상 사용되지 않는 메서드나 오래된 옵션 이름을 마주치지 않도록 했습니다.
* 전체 목록을 살펴보지 않고도 특정 사용 사례에 맞는 적절한 도구를 더 쉽게 찾을 수 있도록 관련 태그 아래에 도구를 그룹화하여 [MCP 도구 참조](/docs/agentic-ai/mcp/tool-reference)를 업데이트했습니다.
* 사용자가 워크플로우의 이전 버전을 검토, 비교 및 되돌릴 수 있도록 워크플로우 편집기에 버전 기록 지원 기능을 추가하여 [워크플로우 관리](/docs/workflow-automation/manage-workflows/managing-workflow)를 업데이트했습니다.
* 더 현실적인 워크플로우 설정을 지원할 수 있도록 1,000자에서 3,000자로 증가된 워크플로우 입력 제한을 반영하여 [워크플로우 제한](/docs/workflow-automation/limitations-and-faq/workflow-limits)을 업데이트했습니다.
* 복잡한 공지 조건을 구축하는 사용자가 적용되는 제약 조건을 알 수 있도록 중첩된 집계를 사용하는 NRQL 공지 조건에 대한 패싯 제한을 명확히 하기 위해 [공지 규칙 및 제한](/docs/alerts/admin/rules-limits-alerts/)을 업데이트했습니다.
