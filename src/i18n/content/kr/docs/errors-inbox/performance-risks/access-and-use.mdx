## 성능 위험 수신함에 액세스 [#access]

<DNT>Performance Risks inbox</DNT> 에는 두 가지 방법으로 액세스할 수 있습니다: 단일 엔티티 또는 워크로드로 범위가 지정된 엔티티 수준, 또는 계정의 모든 엔티티를 포함하는 계정 수준입니다.

* [엔티티 수준 액세스](#access-entity)
* [계정 수준 액세스](#access-account)

### 엔티티 수준 액세스 [#access-entity]

엔티티 수준에서 <DNT>Performance Risks inbox</DNT>은(는) 단일 엔티티 또는 워크로드의 텔레메트리 데이터에 대한 성능 문제를 보여줍니다. 다음에 사용할 수 있습니다:

* APM 서비스
* 브라우저 애플리케이션
* 워크로드

**엔티티에 대한 <DNT>Performance Risks inbox</DNT> 에 액세스하려면:**

1. <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities)</DNT>(으)로 이동한 다음 <DNT>**APM &amp; Services**</DNT>, <DNT>**Browser**</DNT> 또는 <DNT>**Workloads**</DNT>을(를) 선택합니다.
2. 필요한 엔티티 또는 워크로드를 선택하십시오.
3. 탐색 창의 <DNT>**Triage**</DNT> 섹션에서 <DNT>**Performance Risks**</DNT>을(를) 클릭하십시오.

### 계정 수준 액세스 [#access-account]

계정 수준에서 <DNT>Performance Risks inbox</DNT>은(는) 두 가지 뷰로 제공됩니다: 계정 전체 대시보드 및 선택한 워크로드 또는 엔티티로 범위가 지정된 성능 위험 그룹 목록입니다.

**계정의 <DNT>Performance Risks inbox</DNT> 에 액세스하려면:**

1. <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox</DNT> 으)로 이동합니다.
2. 엔티티 탐색 창의 <DNT>**Performance Risks**</DNT> 섹션에서 계정 전체 대시보드를 보려면 <DNT>**Performance Overview**</DNT>을(를) 클릭하고([성능 개요 보기](#overview) 참조), 범위가 지정된 목록을 보려면 <DNT>**Risk Groups**</DNT>을(를) 클릭하십시오.
3. <DNT>**Risk Groups**</DNT>에서 범위 선택기를 사용하여 <DNT>**Workload**</DNT> 또는 <DNT>**Entities**</DNT>를 선택한 다음, 검토하려는 특정 [워크로드](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview) 또는 엔티티를 선택하거나 검색 창을 사용하여 이름이나 설명으로 찾으십시오.
4. 선택적으로 <DNT>**Performance risk group metadata state**</DNT> (예: <DNT>Unresolved</DNT>)과(와) 같은 필터를 더 추가하고, <DNT>**Sort by**</DNT>을(를) 사용하여 결과의 순서를 변경하십시오.

## 성능 위험 보기 및 분석 [#view-analyze]

<DNT>Performance Risks inbox</DNT>에 액세스하면 감지된 문제를 두 가지 방법으로 볼 수 있습니다: <DNT>**Triage**</DNT> 보기 및 <DNT>**Group performance risks**</DNT> 보기. 두 뷰 모두 동일한 기본 데이터를 표시하지만 이를 분석하는 다른 방법을 제공합니다.

### 분류 [#triage]

<DNT>**Triage**</DNT> 뷰는 유사한 성능 위험을 자동으로 처리하고 함께 그룹화합니다. 유사한 쿼리는 컴퓨트되고, 저장되며, 단일 성능 위험 그룹으로 병합됩니다. 예를 들어, `IN` 절의 변형과 같이 동일한 패턴을 공유하는 여러 쿼리는 개별 항목으로 나타나는 대신 하나의 항목으로 그룹화됩니다. 이를 통해 각 발생 건을 개별적으로 검토하지 않고도 가장 큰 영향을 미치는 문제를 더 쉽게 식별하고 우선순위를 지정할 수 있습니다.

애플리케이션 전반의 패턴을 식별하기 위해 성능 문제에 대해 미리 그룹화된 요약이 필요한 경우 <DNT>**Triage**</DNT> 뷰를 사용하십시오.

<img title="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." alt="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." src="/images/performancerisks_triage.webp" />

### 그룹 성능 위험 [#group]

<DNT>**Group performance risks**</DNT> 뷰는 사전 컴퓨트된 그룹화 없이 원시 성능 위험 데이터를 표시합니다. 일반적인 쿼리 표현(예: 쉼표 및 물음표 플레이스홀더)이 표시되며, 다음과 같은 다양한 속성을 기반으로 데이터를 필터링하고 그룹화할 수 있습니다:

* 성능 위험의 영향을 받는 사용자
* 호출을 생성하는 서비스
* 쿼리를 트리거하는 API

조사와 관련된 특정 속성을 기반으로 성능 위험을 분석해야 하는 경우 <DNT>**Group performance risks**</DNT> 뷰를 사용하십시오.

<img title="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." alt="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." src="/images/performancerisks_grpperrisk.webp" />

## 권장 사항 가져오기 [#recommendations]

<DNT>**Triage**</DNT> 뷰에서 발생을 수동으로 조사하는 대신 특정 성능 위험에 대한 AI 기반 권장 사항을 생성할 수 있습니다.

**성능 위험에 대한 권장 사항을 확인하려면:**

1. <DNT>**Triage**</DNT> 뷰에서 여러 번 발생한 성능 위험을 여십시오.
2. <DNT>**Generate insights**</DNT> 을(를) 클릭합니다.

<DNT>Performance Risks inbox</DNT> 해당 성능 위험의 발생을 분석하고 근본 원인에 대한 가설과 이를 해결하기 위한 권장 다음 단계를 반환합니다. 정확한 권장 사항은 감지된 성능 위험에 따라 다릅니다.

<img title="Sample performance risk recommendations." alt="Sample performance risk recommendations." src="/images/PRinsights.webp" />

<Callout variant="important">
  뉴렐릭은 모든 계정에 대해 기본적으로 AI 기능을 활성화합니다. 이 옵션이 표시되지 않으면 계정에서 활성화되지 않았을 수 있습니다. 액세스를 요청하려면 조직 관리자에게 문의하십시오.
</Callout>

권장 사항에서 임계값 조정을 제안하는 경우 [임계값 설정](#set-thresholds)을 참조하십시오.

## 임계값 설정 [#set-thresholds]

<DNT>Performance Risks inbox</DNT> 구성 가능한 임계값을 사용하여 성능 이상 징후를 자동으로 감지합니다. 감지 기준이 특정 성능 모니터링 요구 사항 및 우선순위와 일치하도록 계정 및 엔티티 수준 모두에서 ― [워크로드](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview) 포함 ― 이러한 임계값을 업데이트할 수 있습니다. 이러한 임계값은 성능 위험을 구성하는 요소를 결정하고 <DNT>Performance Risks inbox</DNT>이(가) 애플리케이션에서 가장 관련성이 높고 실행 가능한 성능 문제에 대해 알림을 제공하도록 도와줍니다.

계정 또는 엔티티 수준에서 성능 위험 임계값을 설정할 수 있습니다:

* [계정별 임계값](#account-thresholds)
* [엔티티 수준 임계값](#entity-thresholds)

**계정 수준에서 임계값을 설정하려면:**

### 차트에서 임계값 선 보기 [#threshold-guidelines]

성능 위험 차트에는 값이 예상 범위 내에 있는지 해석하는 데 도움이 되는 참조선이 표시됩니다:

* **최소 및 최대 가이드라인**: 해당 차트에 대해 수집된 이력 데이터에서 자동으로 계산되며, 시간에 따른 일반적인 값의 범위를 보여줍니다.
* **현재 임계값**: 계정 수준 또는 엔티티 수준 임계값 설정에 따라 해당 분석기에 대해 현재 활성화된 임계값을 반영합니다. 둘 다 설정된 경우 엔티티 수준 임계값이 우선합니다.

임계값 설정을 열 필요 없이 메트릭이 구성된 임계값에 얼마나 근접했는지 확인하려면 이 선을 사용하십시오.

다음은 샘플 차트입니다. 표시되는 값과 선은 자체 데이터 및 임계값 설정에 따라 다릅니다.

## 뉴렐릭 MCP 서버에서 성능 위험 수신함 도구를 사용하십시오. [#using]

[뉴렐릭 MCP 서버](/docs/agentic-ai/mcp/overview/) 에서 도구()에 [`list_entity_performance_risk_groups`](/docs/agentic-ai/mcp/tool-reference/#performance)액세스할 수도 <DNT>Performance Risks inbox</DNT> 있습니다. 이 도구는 주어진 엔티티에 대해 감지된 모든 성능 위험을 위험 유형, 심각도 및 발생 횟수와 같은 세부 정보와 함께 나열합니다. 이 도구를 사용하여 프로그래밍 방식으로 성능 위험 데이터를 검색할 수 있습니다.
