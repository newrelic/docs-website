CocoaPods a annoncé que son registre central (trunk) [devient définitivement en lecture seule le 2 décembre 2026](https://blog.cocoapods.org/CocoaPods-Specs-Repo/). Après cette date, CocoaPods cesse d’accepter de nouvelles versions de pod. Cette page explique ce que cela signifie pour l’agent iOS New Relic et les agents hybrides construits sur celui-ci, et comment migrer votre application vers une autre méthode d’installation.

## Avant de migrer [#before-you-migrate]

Examinez ces réponses avant de migrer :

* <DNT>**What&apos;s changing?**</DNT> La version **7.7.10** est le dernier agent iOS que nous publions sur CocoaPods (le pod `NewRelicAgent`). Les versions ultérieures sont disponibles uniquement via le [gestionnaire de paquets Swift](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation) et sous forme de [téléchargement XCFramework](/docs/mobile-monitoring/new-relic-mobile-ios/installation/xcframework-installation).
* <DNT>**Will my app break?**</DNT> Non. Chaque version de `NewRelicAgent` déjà publiée reste sur CocoaPods, afin que `pod install` et votre pipeline CI continuent de fonctionner. Vous n’obtenez tout simplement pas les versions plus récentes de l’agent via CocoaPods.
* <DNT>**Why migrate?**</DNT> Pour continuer à recevoir de nouvelles fonctionnalités, des correctifs et la prise en charge des nouvelles versions d’iOS et de Xcode, passez au gestionnaire de paquets Swift ou au XCFramework.

Ce changement affecte également les agents hybrides qui obtiennent l’agent iOS via CocoaPods. Si vous utilisez React Native, Flutter, Ionic Capacitor, Cordova ou Unity, consultez [Migrer les applications qui utilisent un agent hybride](#hybrid).

## Migrez votre application iOS [#ios]

Choisissez l’une de ces méthodes d’installation :

* [Swift Package Manager](#spm): le gestionnaire de paquets d’Apple, intégré à Xcode. Vous mettez à jour l’agent depuis Xcode.
* [XCFramework](#xcframework): un bundle de framework que vous téléchargez et ajoutez vous-même à votre projet. Vous le mettez à jour en téléchargeant une nouvelle version.

L’agent iOS ne dépend d’aucun autre package, vous pouvez donc le déplacer vers le gestionnaire de paquets Swift, même si certaines de vos autres dépendances restent sur CocoaPods pour le moment. Si vous prévoyez de retirer toutes vos dépendances de CocoaPods, vérifiez d’abord que chacune d’entre elles prend en charge le gestionnaire de paquets Swift. Pour une dépendance qui ne le prend pas en charge, la méthode XCFramework vous permet d’ajouter et de mettre à jour l’agent indépendamment de tout gestionnaire de paquets.

<Callout variant="important">
Installez l’agent avec une seule méthode. Si le pod `NewRelicAgent` est toujours installé lorsque vous ajoutez l’agent d’une autre manière, votre application se retrouve avec deux copies de l’agent, ce qui provoque des erreurs de compilation ou un comportement imprévisible.
</Callout>

### Gestionnaire de paquets Swift [#spm]

<Steps>
<Step>
Notez quelle version de l’agent vous utilisez aujourd’hui. Elle est indiquée à côté de `NewRelicAgent` dans votre `Podfile.lock`.
</Step>

<Step>
Fermez Xcode, puis supprimez le pod `NewRelicAgent` :

* Si `NewRelicAgent` est votre seul pod, exécutez cette commande dans le répertoire de votre projet, puis supprimez votre `Podfile`, `Podfile.lock`, et le fichier `.xcworkspace` que CocoaPods a généré :

  ```shell
  pod deintegrate
  ```

* Si vous utilisez encore d’autres pods, supprimez la ligne `pod 'NewRelicAgent'` de votre `Podfile`, puis exécutez :

  ```shell
  pod install
  ```

  Vérifiez que `NewRelicAgent` n’apparaît plus dans votre `Podfile.lock`.
</Step>

<Step>
Ouvrez votre projet dans Xcode. Si vous utilisez encore d’autres pod, ouvrez le fichier `.xcworkspace`. Sinon, ouvrez le fichier `.xcodeproj`.
</Step>

<Step>
Sélectionnez <DNT>**File &gt; Add Package Dependencies...**</DNT> et saisissez cette URL :

```
https://github.com/newrelic/newrelic-ios-agent-spm
```

Pour la règle de dépendance, choisissez <DNT>**Up to Next Major Version**</DNT>, à partir de la version que vous avez notée à la première étape ou d’une version plus récente.
</Step>

<Step>
Ajoutez le produit du package <DNT>**NewRelic**</DNT> à la cible de votre application, et à toute autre cible qui utilisait le pod, telle qu’une extension d’application.
</Step>

<Step>
Vérifiez votre script de build d’upload dSYM dans le <DNT>**Build Phases**</DNT> de votre cible :

* S’il s’agit du script pour l’agent iOS 7.4.0 ou supérieur (il recherche `run-symbol-tool`), conservez-le tel quel. Il trouve l’outil dans le package Swift.
* S’il appelle `newrelic_postbuild.sh`, ou utilise un chemin dans `Pods/`, remplacez-le par le script de la version 7.4.0 ou supérieure issu de l’ [installation du gestionnaire de paquets Swift](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation).

Conservez le script comme dernière phase de compilation, et assurez-vous que <DNT>**Based on dependency analysis**</DNT> est décoché.
</Step>

<Step>
Nettoyez et compilez votre application, puis exécutez-la. Le code qui démarre l’agent et le jeton de votre application ne changent pas.
</Step>
</Steps>

Pour mettre à jour l’agent ultérieurement, consultez [Mettre à jour avec le gestionnaire de paquets Swift](/docs/mobile-monitoring/new-relic-mobile-ios/installation/upgrade-ios-agent#SPM).

### XCFramework [#xcframework]

<Steps>
<Step>
Fermez Xcode et supprimez le pod `NewRelicAgent`, comme décrit dans les [étapes du gestionnaire de paquets Swift](#spm).
</Step>

<Step>
Suivez l’ [installation manuelle de XCFramework](/docs/mobile-monitoring/new-relic-mobile-ios/installation/xcframework-installation) pour télécharger l’agent et l’ajouter à la cible de votre application. Assurez-vous que `NewRelic.xcframework` est défini sur <DNT>**Embed &amp; Sign**</DNT>.
</Step>

<Step>
Vérifiez votre script de build de téléversement de dSYM comme décrit dans les [étapes du gestionnaire de paquets Swift](#spm). Le script de la version 7.4.0 ou supérieure trouve `run-symbol-tool` dans `NewRelic.xcframework`.
</Step>

<Step>
Nettoyez et compilez votre application, puis exécutez-la. Le code qui démarre l’agent et le jeton de votre application ne changent pas.
</Step>
</Steps>

Pour mettre à jour l’agent ultérieurement, consultez [Remplacer manuellement votre agent iOS](/docs/mobile-monitoring/new-relic-mobile-ios/installation/upgrade-ios-agent#Manual).

### Mettez à jour vos pipeline CI/CD [#ci]

Si vous avez complètement supprimé CocoaPods, mettez à jour toutes les étapes du pipeline qui exécutent `pod install` ou compilent le fichier `.xcworkspace`. Si vous utilisez le gestionnaire de paquets Swift, envisagez de résoudre les packages dans une étape séparée avant la compilation :

```shell
xcodebuild -resolvePackageDependencies -project YourApp.xcodeproj -scheme YourApp
```

Si votre application continue d’obtenir l’agent iOS via CocoaPods, vous pouvez toujours mettre à jour votre agent hybride. Les nouvelles versions de l’agent hybride conservent l’agent iOS **7.7.10** pour CocoaPods, et utilisent des versions plus récentes de l’agent iOS uniquement via le gestionnaire de paquets Swift.

### React Native [#react-native]

Par défaut, l’agent React Native récupère l’agent iOS depuis CocoaPods. Vous pouvez passer au gestionnaire de paquets Swift avec l’agent React Native 1.9.3 ou supérieur.

#### Application React Native standard

Avant de changer, assurez-vous que votre application répond à ces exigences :

* React Native 0.75 ou version ultérieure
* `use_frameworks! :linkage => :dynamic` dans votre `Podfile`
* Un bloc `post_install` dans votre `Podfile` qui appelle `react_native_post_install`, comme le fait le modèle React Native standard

Pour changer, suivez ces étapes :

1. Mettez à jour l’agent React Native vers la version 1.9.3 ou supérieure.

2. En haut de votre `ios/Podfile`, ajoutez :

   ```ruby
   ENV['NEWRELIC_USE_SPM'] = '1'
   use_frameworks! :linkage => :dynamic
   ```

3. Exécutez `pod install` dans votre répertoire `ios`, puis vérifiez que `NewRelicAgent` n’apparaît plus dans votre `Podfile.lock`.

4. Créez et exécutez votre application.

#### Application Expo

`npx expo prebuild` régénère votre dossier `ios`, configurez donc cela dans la configuration de votre projet plutôt que dans le `Podfile`. Vous avez besoin d’Expo SDK 52 ou d’une version supérieure.

Pour changer, suivez ces étapes :

1. Mettez à jour l’agent React Native vers la version 1.9.3 ou supérieure.

2. Installez `expo-build-properties`:

   ```shell
   npx expo install expo-build-properties
   ```

3. Dans votre `app.json` ou `app.config.js`, configurez iOS pour utiliser des frameworks dynamiques :

   ```json
   "plugins": [
     "newrelic-react-native-agent",
     ["expo-build-properties", { "ios": { "useFrameworks": "dynamic" } }]
   ]
   ```

4. Ajoutez `NEWRELIC_USE_SPM=1` au fichier `.env` dans le répertoire racine de votre projet. `npx expo prebuild` et `npx expo run:ios` le chargent.

5. Exécutez `npx expo prebuild --clean`, puis vérifiez que `NewRelicAgent` n’apparaît plus dans `ios/Podfile.lock`.

Si `NEWRELIC_USE_SPM` n’est pas défini lors de l’exécution de CocoaPods, par exemple lorsque vous exécutez `pod install` ou `npx pod-install` vous-même, votre application obtient de nouveau l’agent iOS via CocoaPods.

### Flutter [#flutter]

L’agent Flutter prend en charge à la fois CocoaPods et le gestionnaire de paquets Swift, et Flutter décide lequel utiliser. À partir de Flutter 3.44, [le gestionnaire de paquets Swift est activé par défaut](https://docs.flutter.dev/packages-and-plugins/swift-package-manager/for-app-developers), la plupart des applications obtiennent donc déjà l’agent iOS par ce biais.

Si vous avez désactivé le gestionnaire de paquets Swift, réactivez-le en exécutant :

```shell
flutter config --enable-swift-package-manager
```

Supprimez également `enable-swift-package-manager: false` de votre `pubspec.yaml` si vous l’avez ajouté.

### Ionic Capacitor [#capacitor]

L’agent Capacitor prend en charge à la fois CocoaPods et le gestionnaire de paquets Swift, et votre projet iOS décide lequel est utilisé. Capacitor 8 crée de nouveaux projets iOS avec le gestionnaire de paquets Swift, mais un projet créé avec CocoaPods continue de l’utiliser jusqu’à ce que vous le migriez.

* Si votre dossier `ios/App` contient un package `CapApp-SPM`, vous utilisez déjà le gestionnaire de paquets Swift. `npx cap sync` maintient l’agent à jour.
* S’il possède un `Podfile`, migrez votre projet vers le gestionnaire de paquets Swift en suivant le [guide du gestionnaire de paquets Swift de Capacitor](https://capacitorjs.com/docs/ios/spm). Il couvre la commande `npx cap spm-migration-assistant` et la recréation de la plateforme iOS.

### Cordova [#cordova]

Avec `cordova-ios` 8 ou supérieur, l’agent Cordova obtient l’agent iOS via le gestionnaire de paquets Swift. Les versions antérieures de `cordova-ios` utilisent CocoaPods.

Pour migrer, suivez ces étapes :

1. Mettez à jour l’agent Cordova vers la dernière version.

2. Mettez à jour votre plateforme iOS. Consultez l’ [annonce de la sortie de cordova-ios 8](https://cordova.apache.org/announcements/2025/11/23/cordova-ios-8.0.0.html):

   ```shell
   cordova platform remove ios
   cordova platform add ios@8
   ```

   La suppression de la plateforme supprime le dossier `platforms/ios`, vous perdez donc toutes les modifications que vous y avez apportées manuellement. Sauvegardez-les d’abord.

3. Assurez-vous que votre `config.xml` définit la cible de déploiement iOS sur 15.0 ou supérieur :

   ```xml
   <preference name="deployment-target" value="15.0" />
   ```

4. Créez et exécutez votre application.

### Unité [#unity]

L’agent Unity obtient l’agent iOS via CocoaPods, en utilisant le gestionnaire de dépendances externe pour Unity (EDM4U). Il ne prend pas en charge le gestionnaire de paquets Swift. Votre application continue d’être compilée avec les versions déjà sur CocoaPods, et les nouvelles versions de l’agent Unity conservent l’agent iOS **7.7.10**.

Pour utiliser une version plus récente de l’agent iOS, ajoutez vous-même le XCFramework à votre projet Xcode, comme décrit dans les [étapes de dépendance](/docs/mobile-monitoring/new-relic-mobile-unity/monitor-your-unity-application#manage-dependencies) de l’agent Unity. Assurez-vous qu’EDM4U n’installe pas également le pod `NewRelicAgent`, afin que votre application n’ait qu’une seule copie de l’agent.

## Dépannage [#troubleshooting]

<CollapserGroup>
<Collapser id="no-such-module" title="Ma compilation échoue avec « No such module NewRelic » après la migration vers le gestionnaire de paquets Swift">
Assurez-vous que le produit du package <DNT>**NewRelic**</DNT> est ajouté à la cible dont la compilation échoue. Dans les paramètres de votre cible, vérifiez la section <DNT>**Frameworks, Libraries, and Embedded Content**</DNT>. Si votre projet comporte plusieurs cibles, ajoutez le produit à chacune de celles qui utilisent l’agent.
</Collapser>

<Collapser id="library-not-loaded" title="Mon application plante au lancement avec « Library not loaded : @rpath/NewRelic.framework/NewRelic »">
L’agent est lié mais n’est pas intégré à votre application :

* Gestionnaire de paquets Swift : ajoutez le produit de package <DNT>**NewRelic**</DNT> à la cible de votre application elle-même, et non seulement à une cible de framework ou d’extension.
* XCFramework : dans la section <DNT>**Frameworks, Libraries, and Embedded Content**</DNT> de la cible de votre application, définissez `NewRelic.xcframework` sur <DNT>**Embed &amp; Sign**</DNT>.

Si vous utilisez un agent hybride, consultez les étapes pour votre agent dans [Migrer les applications qui utilisent un agent hybride](#hybrid).
</Collapser>

<Collapser id="duplicate" title="J’obtiens des erreurs de symboles dupliqués ou des avertissements concernant des classes implémentées deux fois">
Votre application possède deux copies de l’agent. Vérifiez que `NewRelicAgent` n’apparaît plus dans votre `Podfile.lock`, et que vous avez ajouté l’agent avec une seule méthode.
</Collapser>

<Collapser id="checksum" title="Le gestionnaire de paquets Swift signale une erreur de somme de contrôle ou de téléchargement">
Consultez les [étapes de dépannage du gestionnaire de paquets Swift](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation#troubleshooting).
</Collapser>
</CollapserGroup>
