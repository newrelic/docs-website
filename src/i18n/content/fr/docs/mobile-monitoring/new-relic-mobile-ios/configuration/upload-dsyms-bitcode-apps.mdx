Xcode stocke les fichiers dSYM de votre application dans le dossier du chemin d’archive dSYM. Il s’agit du dossier dans lequel l’agent iOS récupère les fichiers dSYM qu’il utilise pour symboliser vos rapports de plantage. New Relic fournit un script post-build dans le cadre du [processus d’installation de l’agent iOS](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation/#configure-using-swift-package-manager). Ce script convertit automatiquement votre dSYM au format de fichier de mappage de New Relic et téléverse les fichiers nécessaires à la symbolisation des plantages vers New Relic.

## scriptautomatique [#Automatic]

L’agent iOS inclut `run-symbol-tool`, un script shell que vous exécutez à partir d’une phase de build Run Script dans Xcode. Après chaque build, il exécute `run-symbol-tool.swift` en arrière-plan, qui convertit vos fichiers dSYM au format de fichier map de New Relic et les télécharge vers New Relic.

Dans Xcode 14, Apple a modifié le paramètre par défaut des projets nouvellement créés pour désactiver le bitcode. L&apos;App Store accepte désormais uniquement les soumissions d&apos;applications avec le bitcode désactivé. Voir [les notes de sortie de Xcode 14](https://developer.apple.com/documentation/xcode-release-notes/xcode-14-release-notes). Si votre projet a toujours le bitcode activé, vous devez le désactiver. Le script automatique nécessite que le bitcode soit désactivé.

Apple génère des fichiers dSYM pour les applications compatibles Bitcode. Vous devez [télécharger les fichiers dSYM pour les applications compatibles Bitcode depuis Apple](/docs/mobile-monitoring/new-relic-mobile-ios/install-configure/retrieve-upload-dsyms-bitcode-enabled-apps) et les télécharger sur New Relic via l&apos;[interface utilisateur des applications mobilesmonitoring ](#mobile-ui).

Si vous voyez un code machine illisible sur la [page<DNT>**Crashes**</DNT> ](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-apps-crashes-dashboard), il se peut que vos fichiers dSYM ne soient pas téléchargés correctement. Dans certains cas, vous devrez peut-être [télécharger manuellement les fichiers dSYM](#manual-dsym).

<Callout variant="important">
Agent iOS version 7.4.8 a supprimé les scripts de téléversement Python (`generateMap.py`, `generateMapPython2.py`, et `newrelic_postbuild.sh`). Si votre phase de compilation Run script appelle toujours `newrelic_postbuild.sh`, remplacez-la par le script `run-symbol-tool` ci-dessous.
</Callout>

### Ajoutez la phase de construction Run Script [#run-script]

1. Dans Xcode, sélectionnez votre projet dans le navigateur, puis sélectionnez la cible de votre application.

2. Sélectionnez l’onglet <DNT>**Build Phases**</DNT> .

3. Cliquez sur <DNT>**+**</DNT> et choisissez <DNT>**New Run Script Phase**</DNT>.

4. Ajoutez les lignes suivantes à la nouvelle phase. Remplacez `APP_TOKEN` par votre jeton d’application de New Relic.

   ```shell
   ARTIFACT_DIR="${BUILD_DIR%Build/*}"
   SCRIPT=`/usr/bin/find "${SRCROOT}" "${ARTIFACT_DIR}" -type f -name run-symbol-tool | head -n 1`
   /bin/sh "${SCRIPT}" "APP_TOKEN"
   ```

Dans Xcode 15.3 ou supérieur, définissez <DNT>**User Script Sandboxing**</DNT> sur <DNT>**No**</DNT> afin que le script puisse lire vos fichiers dSYM et écrire son log. Consultez [Échecs de téléchargement automatique de dSYM](/docs/mobile-monitoring/new-relic-mobile-ios/troubleshoot/dSYM-upload-tools).

### Version de l&apos;application [#app-version]

New Relic associe les symboles téléversés à vos builds par version de l’application. Le script utilise la première valeur non vide de cette liste :

1. L&apos;argument `-appVersion`
2. La variable d’environnement `NEWRELIC_APP_VERSION`
3. Le paramètre de build `MARKETING_VERSION`
4. L’espace réservé `1.2.3`

Lorsque le script utilise l&apos;espace réservé, il enregistre un avertissement dans `upload_dsym_results.log`.

Certains projets ne définissent pas `MARKETING_VERSION`, comme les applications versionnées avec `agvtool` ou les applications multi-cibles qui utilisent `GENERATE_INFOPLIST_FILE = YES`. Pour ces projets, transmettez `-appVersion` ou définissez `NEWRELIC_APP_VERSION` afin que vos symboles correspondent à vos builds.

### Variables d&apos;environnement [#environment-variables]

Vous n’avez pas besoin de définir ces variables pour un envoi standard. Pour en définir une, ajoutez une ligne `export` au-dessus du script dans la même phase Run script :

```shell
export NEWRELIC_APP_VERSION="1.4.2"
ARTIFACT_DIR="${BUILD_DIR%Build/*}"
SCRIPT=`/usr/bin/find "${SRCROOT}" "${ARTIFACT_DIR}" -type f -name run-symbol-tool | head -n 1`
/bin/sh "${SCRIPT}" "APP_TOKEN"
```

### Comment fonctionne le script [#how-it-works]

Lorsqu’il s’exécute, le script effectue les opérations suivantes :

* Le téléversement s’exécute en arrière-plan, de sorte que votre build n’attend pas qu’il se termine. Le script écrit les résultats dans [`upload_dsym_results.log`](#auto-upload-fail-troubleshooting).
* Le script ignore les compilations du simulateur iOS (`EFFECTIVE_PLATFORM_NAME` est `-iphonesimulator`).
* Les builds avec Bitcode activé (`ENABLE_BITCODE = YES`) se terminent sans envoi et sans faire échouer le build.
* Le script convertit chaque dSYM dans `DWARF_DSYM_FOLDER_PATH` en fichier de mappage, compresse les fichiers de mappage, et téléverse le zip vers le point de terminaison `/map`.
* Si un dSYM ne peut pas être converti, le script compresse ce dSYM et le téléverse plutôt vers le point de terminaison `/symbol`. Si le téléversement de la map lui-même échoue, le script enregistre le code d’état HTTP et ne se rabat pas sur un téléversement de dSYM. Dans ce cas, [téléversez le dSYM manuellement](#manual-dsym).
* Dans la version 7.7.2 et supérieure de l’agent iOS, si un fichier de mappage compressé est supérieur à 200 Mo, le script ne le téléverse pas. Il envoie uniquement la taille du fichier et la version de l’application à New Relic. New Relic ne peut pas symboliquer les plantages de ce build à moins que vous ne [téléversiez son dSYM manuellement](#manual-dsym).
* Le script choisit la région de téléchargement (US, EU, ou JP) à partir de votre jeton d’application. Ce sont les mêmes hôtes utilisés dans les [commandes de téléchargement manuel](#manual-dsym).

## Identifier les dSYM manquants [#IdentifyingMissingdSYMs]

Lorsqu’une application avec Bitcode activé est envoyée à Apple pour évaluation sur l’App Store ou pour une distribution ad hoc, les dSYM doivent être téléchargés manuellement depuis Apple et envoyés à New Relic pour permettre aux [rapports de plantage mobile](/docs/mobile-monitoring/new-relic-mobile/getting-started/ios-agent-crash-reporting) d’être correctement symboliqués. Ces dSYM peuvent être téléchargés via l’organiseur d’archives dans Xcode dans les minutes qui suivent l’envoi de l’application. Dans cette situation, suivez les procédures pour [trouver l’archive et télécharger les dSYM](/docs/mobile-monitoring/new-relic-mobile-ios/configuration/retrieve-dsyms-bitcode-apps#Archive).

Si une application ne dispose pas d&apos;un fichier dSYM, vous verrez trois indicateurs dans l&apos;interface utilisateur des applications mobiles monitoring :

* <DNT>**Banner notification**</DNT>:Une bannière d&apos;avertissement apparaît sur la [page<DNT>**Crash report**</DNT> ](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-apps-crash-report-dashboard). L&apos;avertissement dit :

```
We were unable to locate your dsym.
```

* <DNT>**Upload prompt**</DNT>:À partir de la page <DNT>**Crash type summary**</DNT> , vous serez automatiquement invité à télécharger un fichier dSYM s&apos;il est manquant.
* <DNT>**Machine code**</DNT>:La trace de crash d&apos;appels sur la page <DNT>**Crash report**</DNT> affiche du code machine et non un message d&apos;erreur lisible par l&apos;homme.

## Télécharger des fichiers dSYM via l&apos;interface utilisateur des applications mobiles monitoring [#mobile-ui]

Vous pouvez facilement téléverser vos fichiers dSYM directement depuis l’UI de New Relic. Pour les limites de taille, voir [Limitations](#limitations). Pour téléverser vos fichiers dSYM :

1. Aller à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Mobile**</DNT>. Sélectionnez ensuite votre application dans la liste.
2. Voir <DNT>**Crashes**</DNT>.
3. Sélectionnez un crash spécifique à partir du <DNT>**Total crashes**</DNT> dans les crashes de groupe.
4. Cliquez sur <DNT>**Upload dSYM**</DNT>. Vous pouvez soit glisser-déposer vos dSYM directement, soit sélectionner le fichier depuis votre ordinateur.

## Télécharger manuellement les fichiers dSYM [#manual-dsym]

Dans certaines circonstances, le téléversement automatique des fichiers dSYM par New Relic peut échouer. Par exemple, s’il y a une panne de réseau et que le téléversement n’est pas terminé, [`upload_dsym_results.log`](#auto-upload-fail-troubleshooting) enregistre ce qui s’est mal passé. Pour plus d’informations sur la façon dont New Relic gère les téléversements de dSYM, consultez la [communauté technique en ligne de New Relic](https://support.newrelic.com/s/hubtopic/aAX8W0000008Yv9/relic-solution-ios-dsym-upload-deepdive).

Si le téléchargement automatique échoue, vous pouvez télécharger manuellement votre fichier dSYM. Si vous avez plusieurs fichiers dSYM, ils peuvent être dans un seul fichier zip. Pour les limites de taille, consultez les [Limitations](#limitations). La valeur `YOUR_NEW_RELIC_APPLICATION_TOKEN` dans les commandes ci-dessous est la même clé utilisée pour `+[NewRelic startWithApplicationToken:]` (en Objective-C) ou `NewRelic.start(withApplicationToken:)` (en Swift).

Dans les commandes ci-dessous, utilisez des chemins d’accès complets ou `$HOME`. Le shell ne développe pas `~` entre guillemets.

Pour télécharger manuellement vos fichiers dSYM :

<CollapserGroup>
<Collapser id="swift-manual-upload" title="Via un script Swift">
Vous pouvez exécuter `run-symbol-tool.swift` depuis la ligne de commande. Il convertit les fichiers dSYM d’un dossier, tel que le dossier `dSYMs` d’une archive Xcode, et les téléverse de la même manière que le [script automatique](#how-it-works). Le script se trouve dans le même dossier que `run-symbol-tool` (par exemple, `NewRelic.xcframework/Resources`).

```shell
DWARF_DSYM_FOLDER_PATH="DSYM_FOLDER_PATH" /usr/bin/xcrun --sdk macosx swift "SCRIPT_PATH/run-symbol-tool.swift" "YOUR_NEW_RELIC_APPLICATION_TOKEN" -appVersion "APP_VERSION"
```

Remplacer :

* `DSYM_FOLDER_PATH` avec le chemin complet vers le dossier qui contient vos fichiers `.dSYM` (par exemple, `$HOME/Library/Developer/Xcode/Archives/2026-10-22/MyApp.xcarchive/dSYMs`).
* `SCRIPT_PATH` avec le chemin d’accès complet au dossier qui contient `run-symbol-tool.swift`.
* `APP_VERSION` avec la version du build. `MARKETING_VERSION` n’est pas défini en dehors de Xcode, passez donc la version explicitement. Pour les versions 7.4.12 à 7.7.4 de l’agent, définissez `MARKETING_VERSION="APP_VERSION"` avant la commande au lieu de passer `-appVersion`.

Le script affiche sa sortie dans le terminal.
</Collapser>
</CollapserGroup>

## Dépannage [#auto-upload-fail-troubleshooting]

Le script `run-symbol-tool` écrit `upload_dsym_results.log` dans le répertoire racine de votre projet à chaque build, que le téléchargement réussisse ou échoue. Chaque build écrase le log précédent. Pour écrire plus de détails dans le log, ajoutez l’ [argument `--debug` ](#arguments).

Si votre log de build indique `upload_dsym_results.log: Operation not permitted`, consultez [Échecs de téléversement automatique de dSYM](/docs/mobile-monitoring/new-relic-mobile-ios/troubleshoot/dSYM-upload-tools).

### dSYM manquants [#troubleshooting-missing-dsyms]

Si les fichiers dSYM sont manquants, vous devrez peut-être vérifier les paramètres de construction de Xcode pour vous assurer que le fichier est généré. les frameworks construits localement ont des paramètres de construction distincts et peuvent également nécessiter d&apos;être mis à jour.

Paramètres de construction :

```
Debug Information Format : Dwarf with dSYM File
Deployment Postprocessing: Yes
Strip Linked Product: Yes
Strip Debug Symbols During Copy : Yes
```

### Limites [#limitations]

Tenez compte de ces limites de taille :

* Les téléchargements de dSYM zippés via l’ [interface utilisateur du monitoring des applications mobiles](#mobile-ui) ou la [ligne de commande](#manual-dsym) peuvent atteindre 600 Mo.
* Le script automatique ne télécharge pas les fichiers map zippés de plus de 200 Mo. Consultez [Comment fonctionne le script](#how-it-works).
