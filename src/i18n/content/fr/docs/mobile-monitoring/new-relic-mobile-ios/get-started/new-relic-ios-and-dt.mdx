## Exigences [#requirements]

Pour utiliser le tracing distribué, vous avez besoin de l&apos;agent iOS version 7.3.0 ou supérieure. Nous vous recommandons d&apos;utiliser l&apos;agent le plus récent.

## Comment configurer le tracing distribué [#setup]

Pour les agents mobiles qui prennent en charge cette fonctionnalité, elle est activée par défaut.

Si vous préférez désactiver le tracing distribué, consultez [l&apos;indicateur de fonctionnalité iOS](/docs/mobile-monitoring/new-relic-mobile-ios/api-guides/ios-agent-configuration-feature-flags/#dt).

## En-têtes de tracing distribué [#headers]

À partir de la version 7.7.8 de l’agent iOS, l’agent ajoute uniquement les en-têtes [W3C Trace Context](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers), `traceparent` et `tracestate`, aux requests réseau sortantes. Il n’envoie plus l’en-tête propriétaire `newrelic`. Les versions antérieures de l’agent envoient les trois en-têtes.

Les agents New Relic APM qui prennent en charge W3C Trace Context utilisent ces en-têtes pour continuer la trace, afin que les requests de votre application restent connectées aux services backend qu&apos;elles appellent. W3C Trace Context est pris en charge dans ces versions d&apos;agent APM et supérieures :

<Callout variant="important">
  Si un service, un proxy, ou un gateway entre votre application et votre backend nécessite l&apos;en-tête `newrelic`, mettez-le à jour pour qu&apos;il accepte `traceparent` et `tracestate` à la place. Les agents APM antérieurs aux versions ci-dessus ne reconnaissent que l&apos;en-tête `newrelic`, et démarrent une nouvelle trace au lieu de faire le lien avec la requête de votre application.

## Activer Infinite Tracing [#infinite-tracing]

Si vos applications mobiles disposent de services en aval qui utilisent notre tracing distribué en fin de workflow [Infinite Tracing](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing), vous devez activer cette fonctionnalité pour vos applications mobiles.Cela garantit que votre span racine (l&apos;application mobile d&apos;initiation) est incluse dans le reste des spans suivis par Infinite Tracing.

Pour configurer cela, consultez les [étapes d&apos;Infinite Tracing](/docs/distributed-tracing/infinite-tracing/set-trace-observer) pour créer un observateur de trace et sélectionner les applications mobiles (sources de données) qui doivent signaler les spans.

## Rechercher des données [#find-data]

Les spans mobiles apparaissent dans toute [interface utilisateur de tracing distribué New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) où ces spans font partie d&apos;une trace.

Voici quelques conseils pour rechercher et interroger des données :

* Vous pouvez trouver la trace d&apos;origine finale de l&apos;utilisateur dans n&apos;importe quelle [interface utilisateur de tracing distribué New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one).

* Dans l&apos;interface utilisateur de tracing distribué, les portées finales des utilisateurs sont indiquées par le<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}}>icône.</img>

* Pour voir l&apos;attribut d&apos;une plage, sélectionnez [une plage dans l&apos;interface utilisateur](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details).

* Les spans sont signalées sous forme [de données de span](/attribute-dictionary/?event=Span) et peuvent être [interrogées dans New Relic](/docs/using-new-relic/data/understand-data/query-new-relic-data).

* Conseils de requête :

  * requête par nom en définissant `mobileApp.name` sur le nom de l&apos;application mobile.
  * requête de trace contenant au moins une application mobile avec `mobileApp.name is not null`.
  * requête de trace contenant au moins une application backend avec `appName is not null`.
  * requête de trace contenant à la fois les spans mobiles et backend en combinant les deux conditions précédentes.

## Dépannage [#troubleshooting]

Si vous ne voyez pas les spans finales des utilisateurs ou si vous rencontrez d&apos;autres problèmes de tracing distribué, consultez [dépannage](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data).
