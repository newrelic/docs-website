Parcours des utilisateurs mobiles visualise la façon dont les utilisateurs finaux naviguent dans votre application mobile de manière globale. Il révèle des modèles dans le comportement des utilisateurs — où les utilisateurs vont après avoir ouvert l’application, où ils sont bloqués et quels chemins mènent aux résultats qui vous intéressent.

<img title="Mobile User Journeys Sankey diagram" alt="A Sankey diagram showing user navigation paths through a mobile app, with nodes representing screens and paths sized by user volume" src="/images/mobile_screenshot-full_user-journeys-sankey.png" />

<Callout variant="important">
  <DNT>Mobile User Journeys</DNT> est actuellement disponible dans l’expérience <DNT>**Errors**</DNT> de l’interface utilisateur de monitoring des applications mobiles New Relic. Une vue <DNT>Mobile User Journeys</DNT> autonome (similaire à la fonctionnalité [Browser User Journeys](/docs/browser/browser-monitoring/browser-pro-features/user-journeys/)) est prévue pour une prochaine sortie.
</Callout>

## Comment y accéder [#access]

<DNT>Mobile User Journeys</DNT> est disponible dans les quatre sections sous <DNT>**Triage**</DNT> dans la navigation de gauche : <DNT>**Crashes**</DNT>, <DNT>**Request errors**</DNT>, <DNT>**Handled exceptions**</DNT>, et <DNT>**ANRs**</DNT>. La façon d&apos;y accéder dépend de votre point de départ :

<img title="Mobile Triage navigation showing Crashes, Request errors, Handled exceptions, and ANRs" alt="The New Relic Mobile left navigation with the Triage section expanded, showing Crashes, Request errors, Handled exceptions, and ANRs" src="/images/mobile_screenshot-full_user-journeys-triage-nav.png" />

**Depuis l&apos;onglet Triage :**

1. Accédez à **[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; <DNT>Mobile</DNT>**.
2. Sélectionnez votre application mobile.
3. Dans la navigation de gauche, sous <DNT>**Triage**</DNT>, cliquez sur <DNT>**Crashes**</DNT> ou <DNT>**Request errors**</DNT>.
4. Depuis le <DNT>error groups</DNT>, sélectionnez celui que vous souhaitez examiner pour ouvrir la vue détaillée de l&apos;erreur.
5. Dans la vue détaillée, cliquez sur le lien <DNT>**User Journeys**</DNT> pour voir les chemins de navigation qui ont mené à l&apos;erreur.

**Depuis l&apos;onglet &quot;Group crashes or error&quot; :**

1. Accédez à **[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; <DNT>Mobile</DNT>**.
2. Sélectionnez votre application mobile.
3. Dans la navigation de gauche, sous <DNT>**Triage**</DNT>, cliquez sur <DNT>**Crashes**</DNT> ou <DNT>**Request errors**</DNT>.
4. Cliquez sur l&apos;onglet <DNT>**Group crashes**</DNT> ou <DNT>**Group request errors**</DNT>.
5. Sélectionnez le groupe de plantages ou d&apos;erreurs que vous souhaitez examiner pour ouvrir la vue détaillée du groupe.
6. Sous <DNT>**Triage**</DNT>, cliquez sur le lien <DNT>**User Journeys**</DNT> pour voir les chemins de navigation qui ont mené à l&apos;erreur.

## Comment utiliser les Mobile User Journeys [#how-to-use]

### Diagramme de Sankey [#sankey]

La visualisation <DNT>User Journeys</DNT> utilise un diagramme de Sankey pour montrer le flux des utilisateurs entre les écrans. Chaque nœud représente un écran ou une interaction dans votre application, et la largeur de chaque chemin de connexion reflète le nombre d’utilisateurs qui ont suivi cet itinéraire.

Éléments clés du diagramme :

* **Nœuds**: écrans individuels ou interactions dans l’application.
* **Chemins**: connexions entre les nœuds, dimensionnées proportionnellement au volume d’utilisateurs qui ont suivi ce chemin.
* **Points d&apos;entrée**: les écrans où les sessions utilisateur commencent.
* **Points de sortie**: les écrans où les utilisateurs ont terminé leur session ou déclenché une erreur.

Lorsqu&apos;elle est consultée depuis un groupe d&apos;erreurs, la visualisation s&apos;ancre automatiquement sur les sessions qui ont rencontré cette erreur, afin que vous puissiez suivre la trace des chemins de navigation qui ont précédé le plantage.

### Détails du chemin et de l&apos;événement [#path-details]

Cliquez sur n’importe quel nœud ou chemin dans le diagramme pour explorer les sessions qui ont suivi cet itinéraire exact. Cela ouvre une vue fractionnée avec deux panneaux :

<img title="Mobile User Journeys crash detail view" alt="Split view showing the Profiles panel on the left with attribute distribution and the Sessions table on the right listing affected sessions" src="/images/mobile_screenshot-full_user-journeys-crash-detail.png" />

* <DNT>**Profiles**</DNT>: montre la distribution des valeurs d’attribut (telles que la version de l’application, l’appareil, le système d’exploitation, l’architecture et les détails du plantage) sur les sessions qui ont suivi le chemin sélectionné. Utilisez ceci pour identifier les points communs entre les utilisateurs affectés.
* <DNT>**Sessions that include this event**</DNT>: un tableau répertoriant les sessions individuelles, y compris l&apos;ID utilisateur, la date, le nombre d&apos;occurrences, la version de l&apos;application, l&apos;appareil, la version du système d&apos;exploitation et l&apos;opérateur. Cliquez sur n&apos;importe quelle session pour ouvrir la page <DNT>Event Trail Drilldown</DNT>.

### Exploration du suivi des événements [#event-trail]

Cliquez sur une session dans le tableau des sessions pour ouvrir la page <DNT>**Event Trail Drilldown**</DNT> — une chronologie de chaque événement enregistré dans cette session.

<img title="Mobile User Journeys Event Trail Drilldown" alt="The Event Trail Drilldown showing a chronological list of Interaction and Crash events with expandable attribute details" src="/images/mobile_screenshot-full_user-journeys-event-trail.png" />

Dans le <DNT>Event Trail Drilldown</DNT>, vous pouvez :

* <DNT>**Filter by event type**</DNT>: utilisez les boutons <DNT>**Interaction**</DNT> et <DNT>**Crash**</DNT> pour vous concentrer sur des types d’événements spécifiques.
* <DNT>**Expand event details**</DNT>: cliquez sur n’importe quel événement pour voir sa charge d’attributs complète — y compris les métadonnées de plantage telles que `diskAvailable`, `osBuild`, `processName`, `timeSinceLastInteraction` et `interactionHistory`.

Cette vue vous permet de reconstituer les étapes exactes qu&apos;un utilisateur a suivies avant qu&apos;un plantage ne se produise, jusqu&apos;à l&apos;interaction individuelle avec l&apos;écran.

## Comment personnaliser la visualisation [#customize]

### Filtre de type d’événement [#event-type]

<img title="Mobile User Journeys event type filter" alt="The event type filter dropdown showing options: Crash, Breadcrumb, Interaction, User action, Handled exception, JavaScript error, Request error, Custom, ANR" src="/images/mobile_screenshot-crop_user-journeys-event-type-filter.png" />

Utilisez le filtre <DNT>**Event type**</DNT> pour choisir quels types d&apos;événements apparaissent comme nœuds sur le diagramme. Vous pouvez inclure toute combinaison de :

* Crash
* Breadcrumb
* Interaction
* User action
* Handled exception
* JavaScript error
* Request error
* Coutume
* ANR

### Version de l&apos;application [#app-version]

Utilisez le filtre <DNT>**App version**</DNT> pour vous concentrer sur les parcours d&apos;une sortie spécifique. Cela est utile pour comparer le comportement des utilisateurs avant et après un déploiement afin d&apos;identifier les régressions ou les améliorations.

### Filtrer par attributs utilisateur [#user-attributes]

Utilisez la barre de filtres pour affiner les résultats par attributs supplémentaires tels que le type d’appareil, la version du système d’exploitation, la géographie ou les attributs personnalisés que vous avez instrumentés avec le [SDK mobile](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/mobile-sdk-api-guide/).
