      ## Syntaxe [#syntax]

      ### Objectif-C

      ```objectivec
      recordError:(NSError* _Nonnull)error attributes:(NSDictionary* _Nullable)attributes;
      ```

      ### Swift [#swift]

      ```swift
      NewRelic.recordError(error: $Error, map $eventAttributes);
      ```

      ## Description [#description]

      Vous pouvez utiliser l&apos;appel d&apos;API `recordError` pour l&apos;analyse des crashs. Passez en revue l’événement capturé pour vous aider à comprendre à quelle fréquence votre application génère des erreurs et dans quelles conditions. En plus de tout [attribut personnalisé](/docs/mobile-monitoring/new-relic-mobile/maintenance/add-custom-data-new-relic-mobile) que vous avez ajouté, l&apos;événement aura également [un attribut de session](/docs/insights/insights-data-sources/default-attributes/mobile-default-attributes-insights) associé.

      Cette API prend une instance d&apos;une erreur et un dictionnaire d&apos;attributs facultatif, puis crée un événement `recordHandledException`. Vous pouvez afficher les données d&apos;événement dans l&apos;interface utilisateur <InlinePopover type="mobile" />dans des endroits tels que la [page<DNT>**Handled exceptions**</DNT> ](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/handled-exceptions-analyze-trends-prevent-crashes)et le [parcours<DNT>**Crash events**</DNT> ](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-crash-event-trail). Vous pouvez également interroger ces données avec NRQL et les représenter graphiquement dans les dashboards New Relic.

      ## Exemples [#examples]

      ### Objective-C

      Voici un exemple d&apos;enregistrement d&apos;une erreur simple :

      ```objectivec
      @try {
        @throw [NSException exceptionWithName:@"versionException"
                                       reason:@"App version no longer supported"
                                     userInfo:nil];
      } @catch (NSException* e) {
        [NewRelic recordHandledException:e];
      }
      ```

      Voici un autre exemple d’enregistrement d’une erreur avec un dictionnaire :

      ```objectivec
      [NSJSONSerialization JSONObjectWithData:data options:opt error:error];
      if (error) {
        [NewRelic recordError:error
               withAttributes:@{@"int" : @1, @"Test Group" : @"A | B"}];
      }
      ```

      ### Swift [#swift]

      Voici un exemple d&apos;enregistrement d&apos;une erreur simple :

      ```swift
      do {
          try method()
      } catch {
          NewRelic.recordError(error)
      }
      ```

      Voici un autre exemple d’enregistrement d’une erreur avec un dictionnaire :

      ```swift
      do {
          try method()
      } catch {
          NewRelic.recordError(error, attributes: [ "int" : 1, "Test Group" : "A | B" ])
      }
      ```

    <TabsPageItem id="cordova">
      ## Syntaxe [#syntax]

      ```typescript
      recordError(err: Error) : void;
      ```

      ## Description [#description]

      Enregistre les erreurs JavaScript pour Cordova. Assurez-vous d’ajouter cette méthode au gestionnaire d’erreurs du framework que vous utilisez.

      ## Exemples [#examples]

      ### Angulaire

      Angular 2+ expose une classe ErrorHandler pour gérer les erreurs. Vous pouvez implémenter New Relic en étendant cette classe comme suit :

      ```typescript
      import { ErrorHandler, Injectable } from '@angular/core';
      import { NewRelic } from "@awesome-cordova-plugins/newrelic";

      @Injectable()
      export class GlobalErrorHandler extends ErrorHandler {
        constructor() {
          super();
        }
        handleError(error: any): void {
          NewRelic.recordError(error);
          super.handleError(error);
        }
      }
      ```

      Ensuite, vous devrez informer Angular 2 de ce nouveau gestionnaire d&apos;erreurs en répertoriant les remplacements pour le fournisseur dans app.module.ts :

      ```typescript
      @NgModule({
        declarations: [AppComponent],
        imports: [BrowserModule, IonicModule.forRoot(), AppRoutingModule,HttpClientModule],
        providers: [{ provide: RouteReuseStrategy, useClass: IonicRouteStrategy },{provide: ErrorHandler, useClass: GlobalErrorHandler}],
        bootstrap: [AppComponent],
      })
      ```

      ### React

      React 16+ a ajouté des composants de limite d&apos;erreur qui détectent les erreurs qui remontent à partir des composants enfants. Ils sont très utiles pour suivre les erreurs et signaler les erreurs à New Relic.

      ```typescript
      import React, { Component } from "react";
      import { NewRelic } from "@awesome-cordova-plugins/newrelic";

      export class ErrorBoundary extends Component {
          componentDidCatch(error, errorInfo) {
              if (errorInfo && errorInfo.componentStack) {
                  // Optional line to print out the component stack for debugging.
                  console.log(errorInfo.componentStack);
              }

              NewRelic.recordError(error);
              this.setState({ error });
          }

          render() {
              // Render error messages or other components here.
          }
      }
      ```

      ### Redux

      Vous pouvez créer [Redux Middleware](https://redux.js.org/tutorials/fundamentals/part-4-store#middleware) et l&apos;appliquer à votre boutique. Cela vous permettra de signaler toute erreur à New Relic.

      ```typescript
      import { NewRelic } from "@awesome-cordova-plugins/newrelic";

      const NewRelicLogger = store => next => action => {
          try {
              // You can log every action as a custom event
              NewRelic.recordCustomEvent("eventType", "eventName", action);
              return next(action)
          } catch (err) {

              //
              NewRelic.recordBreadcrumb("NewRelicLogger error", store.getState());

              // Record the JS error to New Relic
              NewRelic.recordError(err);
          }
      }

      export default NewRelicLogger;
      ```

      Assurez-vous que le middleware est appliqué lors de la création de votre boutique :

      ```typescript
      import { createStore, applyMiddleware } from "redux"
      import NewRelicLogger from "./middleware/NewRelicLogger"

      const store = createStore(todoApp, applyMiddleware(NewRelicLogger));
      ```

      ### Vue

      Vue dispose d&apos;un gestionnaire d&apos;erreurs global qui signale les erreurs JavaScript natives et les transmet à l&apos;instance Vue. Ce gestionnaire sera utile pour signaler les erreurs à New Relic.

      ```js
      import { NewRelic } from "@awesome-cordova-plugins/newrelic";

      Vue.config.errorHandler = (err, vm, info) => {
          // Record properties passed to the component if there are any
          if(vm.$options.propsData) {
              NewRelic.recordBreadcrumb("Props passed to component", vm.$options.propsData);
          }

          // Get the lifecycle hook, if present
          let lifecycleHookInfo = 'none';
          if (info){
              lifecycleHookInfo = info;
          }

          // Record a breadcrumb with more details such as component name and lifecycle hook
          NewRelic.recordBreadcrumb("Vue Error", { 'componentName': vm.$options.name, 'lifecycleHook': lifecycleHookInfo })

          // Record the JS error to New Relic
          NewRelic.recordError(error);
      }
      ```

      ## Syntaxe [#react-syntax]

      ```javascript
      recordError(e: string|Error, isFatal?: boolean, attributes?: object): void;
      ```

      ## Exigences [#react-requirements]

      * [Agent New Relic React Native](/docs/mobile-monitoring/new-relic-mobile-react-native/get-started/introduction-new-relic-react-native) installé et configuré.
      * Appelez `NewRelic.setJSAppVersion()` au début de votre application afin que les erreurs JavaScript puissent être capturées.
      * L’enregistrement des erreurs en tant qu’événements `MobileJSError`, l’argument `isFatal`, et l’argument `attributes` nécessitent l’agent React Native version 1.9.0 ou supérieure. Les versions antérieures enregistrent ces erreurs en tant qu’événements `MobileHandledException`.

      ## Description [#react-description]

      Utilisez cet appel pour enregistrer les erreurs JavaScript gérées ou autres erreurs diverses de votre application. Cela est utile lorsque vous avez intercepté et géré une erreur, mais que vous souhaitez tout de même l’identifier sans perturber le fonctionnement de votre application.

      Ces erreurs sont enregistrées en tant qu’ [événements`MobileJSError` ](/attribute-dictionary/?event=MobileJSError). En plus des [attributs personnalisés](/docs/mobile-monitoring/new-relic-mobile/maintenance/add-custom-data-new-relic-mobile) que vous ajoutez, les événements incluent également les [attributs de session](/docs/insights/insights-data-sources/default-attributes/mobile-default-attributes-insights) associés. Vous pouvez afficher ces données dans l’UI <InlinePopover type="mobile" />, les interroger avec NRQL et les représenter graphiquement dans les dashboards New Relic.

      ## Exemples [#react-examples]

      ### Enregistrer une erreur traitée

      Voici un exemple d’enregistrement d’une erreur interceptée sans perturber votre application :

      ```javascript
      try {
        var foo = {};
        foo.bar();
      } catch (e) {
        NewRelic.recordError(e);
      }
      ```

      ### Enregistrer une erreur à partir d’un rejet de promesse

      Les promesses font qu’il est facile d’ignorer les erreurs asynchrones. Cet exemple signale une promesse rejetée à New Relic afin qu’elle ne soit pas ignorée :

      ```javascript
      fetch('https://api.example.com/data')
        .then(response => response.json())
        .catch(error => {
          // Report the unhandled rejection to New Relic
          NewRelic.recordError(error);
        });
      ```

      ### Enregistrer une erreur fatale

      Passez `true` comme deuxième argument pour marquer l’erreur comme fatale :

      ```javascript
      try {
        criticalOperation();
      } catch (e) {
        NewRelic.recordError(e, true);
      }
      ```

      ### Enregistrer une erreur avec des attributs personnalisés

      Passez un objet d’attributs comme troisième argument pour ajouter du contexte à l’erreur :

      ```javascript
      try {
        var foo = {};
        foo.bar();
      } catch (e) {
        NewRelic.recordError(e, false, { screen: 'Checkout', 'Test Group': 'A | B' });
      }
      ```
