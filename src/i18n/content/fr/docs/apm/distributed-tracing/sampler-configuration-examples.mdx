Bien que la configuration d&apos;échantillonnage par défaut fonctionne pour tous les services, elle peut ne pas être optimale. Les agents APM fournissent des options de configuration de l&apos;échantillonnage afin que vous puissiez adapter l&apos;échantillonnage aux besoins de votre service. Cette page présente quelques exemples concrets de différents types de services et explique comment modifier la configuration de l&apos;échantillonnage pour répondre à ces besoins.

Les exemples de configuration sur cette page utilisent le format YAML (agent Java). Pour la syntaxe équivalente dans votre langage et la référence complète des paramètres, consultez la documentation de votre agent :

* [Configuration du tracing distribué de l&apos;agent Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
* [Configuration du tracing distribué de l’agent Node.js](/docs/apm/agents/nodejs-agent/installation-configuration/nodejs-agent-configuration)
* [Configuration du tracing distribué de l’agent Python](/docs/apm/agents/python-agent/configuration/python-agent-configuration)

## Prérequis

Ce guide suppose que vous êtes familiarisé avec les contextes et les types d’échantillonneurs. Consultez la page [Configurer l’échantillonnage](/docs/apm/distributed-tracing/distributed-trace-sampling) pour obtenir une vue d’ensemble complète des concepts d’échantillonneur.

## Exemple 1 : mauvaise répartition des points de terminaison capturés en raison de points de terminaison rarement appelés

L’échantillonneur par défaut, l’échantillonneur adaptatif, échantillonne environ 10 traces par minute pour la plupart des agents de langage APM. Puisque l’échantillonneur adaptatif choisit les traces de manière aléatoire, il est plus susceptible d’échantillonner les points de terminaison fréquemment appelés que les points de terminaison rarement appelés.

### Solution : augmenter la cible d’échantillonnage adaptatif

L&apos;augmentation de `adaptive_sampling_target` permet d&apos;échantillonner plus de traces chaque minute, augmentant la probabilité de capturer des traces pour les points de terminaison peu fréquents.

```yaml
distributed_tracing:
  sampler:
    adaptive_sampling_target: 20  # Increase from default 10 to 20
```

## Exemple 2 : mauvaise répartition des points de terminaison capturés en raison de l&apos;échantillonnage en amont

Avec l’échantillonneur adaptatif par défaut, le service actuel échantillonne également toute trace entrante qu’un service en amont a déjà échantillonnée. Parfois, cela conduit à un trop grand nombre de traces provenant de points de terminaison avec un parent en amont, et à trop peu de traces provenant d’autres points de terminaison.

### Solution : réduisez le taux d’échantillonnage pour les traces échantillonnées par un service en amont

L’échantillonneur basé sur le ratio d’ID de trace peut être utilisé pour échantillonner les traces échantillonnées en amont seulement 10 % du temps. Cela réduit la probabilité de remplir le réservoir de spans avec des traces qui ont été échantillonnées par un service en amont.

```yaml
distributed_tracing:
  sampler:
    remote_parent_sampled:
      trace_id_ratio_based:
        ratio: 0.1
```

## Exemple 3 : modifier la répartition de trace pour tous les contextes

[L’exemple 2](#example-2-poor-distribution-of-endpoints-captured-due-to-upstream-sampling) (trop de traces échantillonnées en amont) est un cas spécifique d’un problème plus général : vous souhaitez plus de contrôle sur la distribution des traces que vous voyez dans tous les contextes de trace.

### Solution : superposer plusieurs échantillonneurs de ratio

Nous pouvons nous appuyer sur l’exemple précédent en superposant plusieurs échantillonneurs de ratio de trace. Le taux d’échantillonnage de chaque contexte de trace est indépendant, de sorte que chaque ratio peut être ajusté pour obtenir la distribution de traces souhaitée.

Dans cet exemple, chaque contexte de trace utilise un échantillonnage basé sur un ratio. Les ratios sont définis pour échantillonner `25%` des `root` traces (au lieu d’un nombre fixe), `50%` des traces échantillonnées par un service en amont (au lieu de toutes), et `5%` des traces non échantillonnées par un service en amont (au lieu d’aucune).

```yaml
distributed_tracing:
  sampler:
    root:
      trace_id_ratio_based:
        ratio: 0.25
    remote_parent_sampled:
      trace_id_ratio_based:
        ratio: 0.5
    remote_parent_not_sampled:
      trace_id_ratio_based:
        ratio: 0.05
```
