Configurez le collecteur d’erreurs de l’agent Ruby pour personnaliser la manière dont les erreurs sont capturées, quelles erreurs ignorer ou traiter comme attendues, et comment les événements d’erreur sont échantillonnés.

## Collectord&apos;erreurs [#error-collector]

Par défaut, l&apos;agent collecte et signale toutes les exceptions non détectées. Ces options de configuration vous permettent de personnaliser la collecte des erreurs.

Pour plus d&apos;informations sur les erreurs ignorées et les erreurs attendues, [consultez cette page sur l&apos;analyse des erreurs dans APM](/docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected/). Pour définir l&apos;erreur attendue via la méthode Ruby `NewRelic::Agent.notice_error`, [consultez l&apos;API de l&apos;agent Ruby](/docs/agents/ruby-agent/api-guides/sending-handled-errors-new-relic/).

## Erreurs configuration de la boîte de réception [#errors-inbox-configuration]

Définir l&apos;une des variables d&apos;environnement suivantes vous aidera à identifier quelles versions de votre logiciel ont produit les erreurs.

* `NEW_RELIC_METADATA_SERVICE_VERSION` crée `tags.service.version` sur les données d&apos;événement contenant la version de votre code qui est déployée, dans de nombreux cas une version sémantique telle que `1.2.3`, mais pas toujours.
* `NEW_RELIC_METADATA_RELEASE_TAG` crée `tags.releaseTag` sur les données d’événement contenant le tag de sortie (tel que `v0.1.209` ou `release-209`).
* `NEW_RELIC_METADATA_COMMIT` crée `tags.commit` sur les données d’événement contenant le SHA de commit. Le SHA complet peut être utilisé ou seulement les sept premiers caractères (par exemple, `734713b`).

[Errors Inbox](/docs/errors-inbox/version-tracking/) suivra automatiquement les versions de votre logiciel qui produisent des erreurs.
