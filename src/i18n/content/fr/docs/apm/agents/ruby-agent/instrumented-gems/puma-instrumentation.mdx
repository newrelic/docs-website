L’agent New Relic <DNT>Ruby</DNT> peut échantillonner les statistiques de serveur à l’échelle du cluster de [Puma](https://github.com/puma/puma) à partir du processus maître <DNT>Puma</DNT> et les signaler comme `Ruby/Puma/*` [métriques de tranche de temps](/docs/data-apis/understand-data/metric-data/query-apm-metric-timeslice-data-nrql/).

Cette instrumentation est **désactivée par défaut**.

## Activer l’instrumentation [#enable]

Pour activer l’instrumentation <DNT>Puma</DNT>, définissez `disable_puma_instrumentation` sur `false` dans votre `newrelic.yml`:

```yaml
disable_puma_instrumentation: false
```

L’agent échantillonne les statistiques du processus maître <DNT>Puma</DNT>, il ne collecte donc les métriques que là où l’agent est chargé dans le maître :

* **Mode unique** (sans workers) : les métriques sont toujours collectées.

* **Mode cluster** (un ou plusieurs workers) : les métriques sont collectées uniquement lorsque votre application est préchargée, de sorte que l&apos;agent soit chargé dans le master plutôt que dans un worker. Ajoutez `preload_app!` à votre `puma.rb`:

  ```ruby
  workers 2
  preload_app!
  ```

  <Callout variant="important">
    Sur <DNT>Puma v6.x</DNT>, vous devez définir `preload_app!` explicitement. <DNT>Puma v6.x</DNT> n’applique pas sa valeur par défaut `preload_app` à partir du bloc de configuration, donc une application en cluster avec `workers` défini mais sans `preload_app!` explicite charge l’agent dans un worker et **aucune métrique Puma n’est collectée**. Lorsque cela se produit, l’agent enregistre un avertissement.
  </Callout>

### Ajuster le taux d’échantillonnage [#sample-rate]

Par défaut, l&apos;agent échantillonne les statistiques <DNT>Puma</DNT> toutes les 60 secondes. Modifiez cela avec la configuration `puma.sample_rate` dans votre `newrelic.yml`:

```yaml
puma.sample_rate: 30
```

## Exemple de requête [#queries]

Effectuez une requête sur ces métriques avec [NRQL](/docs/query-your-data/nrql-new-relic-query-language/get-started/introduction-nrql-new-relics-query-language/) en utilisant le type `Metric`. Remplacez `YOUR_APP_NAME` par le nom de votre application.

Pour afficher toutes les métriques Puma à la fois :

```sql
FROM Metric SELECT average(newrelic.timeslice.value)
WHERE appName = 'YOUR_APP_NAME' AND metricTimesliceName LIKE 'Ruby/Puma/%'
FACET metricTimesliceName TIMESERIES LIMIT MAX SINCE 1 hour ago
```

Pour afficher une seule métrique, filtrez par son nom :

```sql
FROM Metric SELECT average(newrelic.timeslice.value)
WHERE appName = 'YOUR_APP_NAME' AND metricTimesliceName = 'Ruby/Puma/requests_count'
TIMESERIES LIMIT MAX SINCE 1 hour ago
```

## Comment ça marche [#behavior]

Lorsqu’il est activé, l’agent démarre un thread de rapport dans le processus maître Puma pour fournir ces métriques. Cela exécute une connexion d’agent supplémentaire dans le maître, aux côtés des connexions de vos workers Puma.

L’instrumentation enregistre uniquement des jauges et des compteurs entiers via `NewRelic::Agent.record_metric`. Il ne capture aucune donnée de request, de requête ou d’utilisateur.
