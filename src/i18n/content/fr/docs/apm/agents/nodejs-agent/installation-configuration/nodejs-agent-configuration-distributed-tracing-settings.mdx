## Tracing distribué [#dt-main]

[Le tracing distribué](/docs/intro-distributed-tracing) vous permet de voir le chemin emprunté par une requête lorsqu&apos;elle traverse un système distribué. Lors de la configuration via le fichier de configuration, placez l&apos;option suivante dans la section `distributed_tracing` . Il est activé par défaut dans l&apos;agent Node.js 8.3.0 et supérieur.

<Callout variant="important">
L&apos;activation du tracing distribué désactive [le tracing inter-application](#cross-app-tracing) et a des effets sur d&apos;autres fonctionnalités APM . Avant l&apos;activation, lisez le [guide de transition](/docs/transition-guide-distributed-tracing). Nécessite [l&apos;agent Node.js version 4.7.0 ou supérieure](/docs/agents/nodejs-agent/installation-configuration/upgrade-nodejs-agent).
</Callout>

Pour plus d&apos;informations sur la configuration du tracing distribué, consultez [Activer le tracing distribué pour votre application Node.js ](/docs/apm/agents/nodejs-agent/installation-configuration/distributed-tracing-nodejs-agent).

<td>
`NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT`
</td>
</tr>
</tbody>
</table>

Contrôle la façon dont les décisions d&apos;échantillonnage sont prises pour les spans-transactions racines qui n&apos;ont pas de parent distant (ce qui signifie qu&apos;elles n&apos;ont pas d&apos;en-tête de tracing distribué `traceparent` ou `newrelic` entrant). Les valeurs valides sont :

* `adaptive` (par défaut) : utilise l&apos;algorithme d&apos;échantillonnage adaptatif intégré de New Relic.
* `always_on`: échantillonne tous les spans.
* `always_off`: n’échantillonne aucune span.
* `trace_id_ratio_based`: échantillonne un ratio fixe de traces, déterminé de manière déterministe par l’ID de trace.

Par exemple, pour définir cela dans le fichier de configuration, vous utiliseriez :

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    root: 'always_on'
  }
}
```

Lorsqu’il est défini sur `trace_id_ratio_based`, vous devez également fournir un `ratio` (un nombre entre `0` et `1`) :

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    root: {
      trace_id_ratio_based: {
        ratio: 0.5
      }
    }
  }
}
```

Ou via des variables d&apos;environnement :

```ini
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT=trace_id_ratio_based
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT_TRACE_ID_RATIO_BASED_RATIO=0.5
```

Lorsque vous définissez ceci sur `adaptive`, vous pouvez éventuellement remplacer la cible d&apos;échantillonnage (de 1 à 120 transactions/minute) spécifiquement pour cet échantillonneur :

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    root: {
      adaptive: {
        sampling_target: 50
      }
    }
  }
}
```

Ou via des variables d&apos;environnement :

```ini
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT=adaptive
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT_ADAPTIVE_SAMPLING_TARGET=50
```
</Collapser>

Lorsque l&apos;en-tête traceparent a un indicateur échantillonné de `01`, cela contrôle la manière de gérer l&apos;échantillonnage des spans. Les valeurs de chaîne autorisées sont :

* `adaptive` (par défaut) : utilise l&apos;algorithme d&apos;échantillonnage adaptatif intégré de New Relic.
* `always_on`: échantillonne tous les spans.
* `always_off`: n’échantillonne aucune span.
* `trace_id_ratio_based`: échantillonne un ratio fixe de traces, déterminé de manière déterministe par l’ID de trace.

Ce paramètre a priorité sur [`remote_parent_not_sampled`](#dt-sampler-remote-parent-not-sampled) lorsque les deux pourraient s&apos;appliquer.

Par exemple, pour activer cela dans le fichier de configuration, vous utiliseriez :

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    remote_parent_sampled: 'always_on'
  }
}
```

Lorsque vous définissez ceci sur `trace_id_ratio_based`, vous devez fournir une valeur `ratio` de `0`à`1`. Lorsque vous définissez ceci sur `adaptive`, vous pouvez éventuellement remplacer la cible d’échantillonnage spécifiquement pour cet échantillonneur. Pour la syntaxe équivalente, consultez les exemples de forme d’objet et de variable d’environnement sous [`sampler.root`](#dt-sampler-root) et remplacez `root` par `remote_parent_sampled`.
