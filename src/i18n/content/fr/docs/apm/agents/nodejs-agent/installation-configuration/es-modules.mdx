Si vous utilisez ESM pour gérer le code dans vos applications Node.js, vous pouvez désormais monitorer ces applications à l&apos;aide de l&apos;agent Node.js.

<Callout variant="caution">
  La prise en charge de l&apos;instrumentation dans les applications [ESM](https://nodejs.org/api/esm.html) par l&apos;agent APM Node.js est expérimentale. L’agent dépend d’une fonctionnalité Node.js expérimentale pour enregistrer l’instrumentation. Des changements majeurs peuvent se produire jusqu’à ce que l’API Node.js pour les [chargeurs ESM](https://nodejs.org/api/esm.html#loaders) soit stable.
</Callout>

## Présentation [#overview]

Avant la version 12.0.0, Node.js prend officiellement en charge la gestion du code uniquement à l&apos;aide de modules CommonJS. Les modules CommonJS utilisent les instructions `module.exports` et `require()` pour gérer le code comme dans cet exemple :

```js
'use strict'

const bar = require('./bar')

function echoBar() {
  console.log('this is bar:', bar)
}

module.exports = {
  echoBar
}
```

Depuis Node.js v12.0.0, la prise en charge des modules ECMAScript (modules ES/&quot;ESM&quot;) a été ajoutée.

Au lieu de `require()` et `module.exports`, ESM utilise les instructions `import` et `export` comme ceci :

```js
'use strict'

import bar from './bar.js'

export function echoBar() {
  console.log('this is bar:', bar)
}
```

ESM est la norme officielle ECMAScript pour la gestion du code et constitue le moyen standard utilisé par les navigateurs et autres environnements d&apos;exécution JS pour gérer les package. Afin de prendre en charge l&apos;évolution de l&apos;écosystème Node.js, aujourd&apos;hui et à l&apos;avenir, l&apos;agent prend en charge les applications instrumenté écrites à l&apos;aide d&apos;ESM, à partir de la version 9.1.0 de l&apos;agent. L&apos;agent APM Node.js continue également de prendre en charge les applications CommonJS.

<Callout variant="important">
  La version minimale prise en charge de Node.js lors de l&apos;utilisation de l&apos;agent APM Node.js dans les applications ESM est la v16.12.0.
</Callout>

## Configuration de l&apos;agent [#agent-setup]

Pour que l&apos;agent puisse avec succès instrument une application ESM, vous devrez d&apos;abord installer l&apos;agent Node.js, comme décrit dans la [documentation d&apos;installation](/docs/apm/agents/nodejs-agent/installation-configuration/install-nodejs-agent). Une fois votre agent installé, continuez avec la configuration dans les sections ci-dessous.

### Configuration [#configuration]

Si votre application utilise un fichier de configuration pour configurer l&apos;agent, vous devrez mettre à jour l&apos;extension du fichier de configuration pour qu&apos;elle soit `.cjs` au lieu de `.js`.

L&apos;agent est écrit comme un module CommonJS ; il utilise `require()` pour lire le fichier de configuration au démarrage. En modifiant l&apos;extension du fichier, nous étiquetons explicitement le fichier de configuration de l&apos;agent comme un module CommonJS, permettant à l&apos;agent de le charger avec succès.

Si vous ne mettez pas à jour l’extension du fichier, vous pouvez voir l’erreur suivante lors du démarrage de l’agent :

```
New Relic for Node.js is disabled due to an error:
Error [ERR_REQUIRE_ESM]: require() of ESM /path/to/your/application/newrelic.js from /path/to/your/application/node_modules/newrelic/lib/config/index.js not supported.
```

### Ajoutez le chargeur ESM [#add-loader]

Pour que l’agent puisse appliquer correctement l’instrumentation au sein de l’écosystème ESM, vous devez inclure le chargeur ESM de l’agent avec l’agent lors de l’invocation de votre application. Vous pouvez ajouter le chargeur à votre application en utilisant l’ [argument CLI](https://nodejs.org/api/cli.html#--importmodule) de Node.js `--import`.

```sh
node --import newrelic/esm-loader.mjs -r newrelic your-program.js
```

## instrumentation personnalisée [#custom-instrumentation]

L&apos;agent APM Node.js prend en charge l&apos;ajout d&apos;une instrumentation personnalisée à vos applications ESM. Vous pouvez créer une instrumentation dans les applications ESM en utilisant la plupart des [méthodes d&apos;enregistrement d&apos;instrumentation sur l&apos;API](https://newrelic.github.io/node-newrelic/API.html#instrument). En raison de la nature des importations ESM, l&apos;agent ne prend pas en charge `newrelic.instrumentLoadedModule`. Les liaisons ESM ne sont pas assignables, ce qui empêche l&apos;agent de remplacer les membres exportés d&apos;un module par une instrumentation une fois le module chargé.

Pour voir une démonstration de la façon d’utiliser l’API d’instrumentation personnalisée dans une application ESM, consultez notre [exemple](https://github.com/newrelic/newrelic-node-examples/blob/4284ee7eab69708238db0a44f97ff7e839e165cf/esm-app/custom-instrumentation/index.js) sur GitHub.
