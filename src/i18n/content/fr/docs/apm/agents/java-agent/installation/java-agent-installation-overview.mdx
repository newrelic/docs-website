L’agent Java de New Relic instrumente votre application Java automatiquement, vous donnant une visibilité sur les transactions, les erreurs, et les performances de la JVM sans modifier le code de votre application. Une fois installé, vous pouvez voir les temps de réponse, le débit, les taux d’erreur, et la santé de la JVM de votre application dans la plateforme New Relic en quelques minutes. Utilisez l’agent Java pour trouver les goulots d’étranglement de performance, diagnostiquer les erreurs en contexte, et comprendre comment votre application se comporte sous un trafic réel.

## Capacités [#capabilities]

* **Métriques** : temps de réponse, débit, taux d’erreur, score Apdex et métriques de la JVM (tas, ramasse-miettes, nombre de threads) par application et transaction
* **Événements** : événements de transaction, événements d&apos;erreur et événements personnalisés interrogeables via NRQL
* **Logs** : données de log d&apos;application corrélées avec les traces et les erreurs via les [logs en contexte](/docs/logs/logs-context/java-configure-logs-context-all/)
* **Traces** : traces distribuées reliant les requests entre les services, plus les traces de transaction, et les plans d’exécution SQL pour les requêtes lentes
* **Entités** : votre application apparaît en tant qu&apos;entité de service dans New Relic, visible dans APM &amp; services et dans l&apos;explorateur d&apos;entités

## Choisissez votre chemin d&apos;installation [#choose]

* **Serveurs d’applications et JVM autonome** (recommandé) — Le chemin standard pour Tomcat, Spring Boot, JBoss/WildFly, Glassfish, Jetty, WebLogic, WebSphere, et toute JVM qui accepte un argument `-javaagent`
* **Maven** : à utiliser lorsque votre build utilise déjà Maven ; l&apos;agent est téléchargé et décompressé en tant que dépendance de build via `maven-dependency-plugin`
* **Gradle** : à utiliser lorsque votre build utilise déjà Gradle ; les tâches de téléchargement optimisées par `de.undercouch.download` récupèrent et décompressent l&apos;agent automatiquement
* **Azure App Service (Windows)** : utilisez cette option lorsque votre application Java s’exécute sur Azure Windows App Service ; l’extension de site New Relic injecte l’agent sans modifier votre script de démarrage
* **Docker** : à utiliser pour les applications Java conteneurisées ; transmettez `-javaagent` via `JAVA_TOOL_OPTIONS`
* **AWS Elastic Beanstalk** : à utiliser pour les applications Tomcat ou Java SE déployées sur Elastic Beanstalk
* **Google App Engine** : à utiliser pour les applications s&apos;exécutant dans l&apos;environnement flexible GAE via un runtime Docker personnalisé
* **AWS Lambda** : utilise un chemin d’installation différent de celui de l’agent standard ; voir le [monitoring de fonction serverless](/docs/serverless-function-monitoring/aws-lambda-monitoring/enable-lambda-monitoring/enable-serverless-monitoring-aws-lambda-legacy#java)

## Installation guidée [#ui-install]

L&apos;installation guidée est disponible sur <DNT>**[one.newrelic.com](https://one.newrelic.com) → Integrations &amp; Agents → Java**</DNT>. L&apos;interface utilisateur fournit un workflow guidé de bout en bout qui préremplit votre clé de licence et le nom de votre application.

## Installation en un coup d&apos;œil [#at-a-glance]

1. Vérifiez la [compatibilité et les exigences](/docs/apm/agents/java-agent/getting-started/compatibility-requirements-java-agent)
2. Téléchargez et placez les fichiers de l&apos;agent
3. Configurez l&apos;agent avec votre clé de licence et le nom de votre application
4. Vérifier que les données sont transmises à New Relic
