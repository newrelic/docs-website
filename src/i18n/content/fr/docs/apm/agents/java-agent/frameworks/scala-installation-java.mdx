L&apos;agent Java de New Relic est [compatible avec Scala](/docs/agents/java-agent/getting-started/compatibility-requirements-java-agent#other) et prend encharge l&apos;appel d&apos;API New Relic, les annotations et [instrumentation personnalisée .](/docs/java/custom-instrumentation-with-the-java-agent) Toutes les informations ci-dessous complètent [les instructions d&apos;installation de l&apos;agent Java](/docs/java/java-agent-manual-installation) de New Relic.

<Callout variant="tip">
Pour Heroku, voir [agent Java avec Scala sur Heroku](/docs/agents/java-agent/heroku/java-agent-scala-heroku).
</Callout>

## Cadre Scala [#frameworks]

Si votre [framework](/docs/agents/java-agent/getting-started/compatibility-requirements-java-agent#frameworks) n&apos;est pas supporté nativement par New Relic, ou si vous souhaitez mettre en place monitoring supplémentaire, [instrumentation personnalisée](/docs/agents/java-agent/custom-instrumentation/java-custom-instrumentation) est un excellent moyen d&apos;approfondir votre application.

## Instrumenter Scala avec l&apos;Scala API [#using-the-scala-api]

L&apos;API de l&apos;agent New Relic Scala vous permet de contrôler, de personnaliser et d&apos;étendre les fonctionnalités de l&apos;agent Java APM à l&apos;aide de code Scala idiomatique. Il peut être utilisé avec l&apos;et permettre à l&apos;utilisateur [New Relic Java API](/docs/agents/java-agent/api-guides/guide-using-java-agent-api/) de

* Créer des segments pour les fonctions anonymes synchrones et asynchrones
* Créer des segments pour les blocs de code synchrones et asynchrones
* Créer une transaction si aucune n&apos;a déjà été démarrée

<Callout variant="important">
Pour de meilleurs résultats lors de l&apos;utilisation de l&apos;API, assurez-vous que vous disposez de la dernière version agent Java . L&apos;API Scala de New Relic nécessite l&apos;agent Java 7.1.0 ou supérieur.
</Callout>

Vous pouvez appeler l&apos;API lorsque l&apos;agent Java n&apos;est pas en cours d&apos;exécution. Les méthodes API sous-jacentes ne sont que des stubs ; l&apos;implémentation est ajoutée lorsque l&apos;agent Java est en cours d&apos;exécution.

### Segments

Pour créer un segment pour un bloc de code synchrone, utilisez `TraceOps.trace`. Par exemple:

```scala
import com.newrelic.scala.api.TraceOps.trace

trace("statement segment") {
    val i = 1
    val j = 2
    println(i + j)
}
// trace can also be used as an expression
val x: Int = trace("expression segment") {
    val i = 1
    val j = 2
    i + j
}
println(x) // 2
```

`trace` peut également être utilisé en Scala pour les compréhensions

```scala
import scala.concurrent.{ExecutionContext, Future}
import com.newrelic.scala.api.TraceOps.trace

// implicit execution
implicit val ec: ExecutionContext = ???

  val x: Option[Int] = for {
    one <- trace("segment one")(Option(1))
    two <- trace("segment two")(Option(one + 1))
    three <- trace("segment three")(Option(two + 1))
  } yield three

println(x) // Some(3)
```

Si vous souhaitez créer un segment pour un bloc de code asynchrone contenant un Scala Future, utilisez `TraceOps.asyncTrace`. Cela garantira que le timing du segment inclut le temps nécessaire à l&apos;achèvement du futur.

Dans l&apos;exemple ci-dessous, le temps de segment ne sera pas inférieur à 5 secondes en raison du retard créé dans le futur enveloppé.

```scala
import scala.concurrent.{ExecutionContext, Future}
import com.newrelic.scala.api.TraceOps.asyncTrace
// implicit execution
implicit val ec: ExecutionContext = ???

val x: Future[Int] = asyncTrace("segment name")(Future {
  Thread.sleep(5000)
  1
})
x.foreach(println) // prints 1 on completion of Future
```

`asyncTrace` peut également être utilisé en Scala pour les compréhensions

```scala
import scala.concurrent.{ExecutionContext, Future}
import com.newrelic.scala.api.TraceOps.asyncTrace
// implicit execution
implicit val ec: ExecutionContext = ???

 val x: Future[Int] = for {
    one <- asyncTrace("segment one")(Future(1))
    two <- asyncTrace("segment two")(Future(one + 1))
    three <- asyncTrace("segment three")(Future(two + 1))
  } yield three

x.foreach(println) // prints 3 on completion of Future
```

Si vous souhaitez créer un segment pour une fonction anonyme synchrone, utilisez `TraceOps.traceFun`. Par exemple:

```scala
import com.newrelic.scala.api.TraceOps.traceFun

val x: Option[Int] = Option(1)
            .map(traceFun("statement segment")(i => i + 1))
println(x) //Some(2)
```

Si vous souhaitez créer un segment pour une fonction asynchrone qui renvoie un Scala Future, utilisez `TraceOps.asyncTraceFun`. Cela garantira que le timing du segment inclut le temps nécessaire à l&apos;exécution de la fonction.

Dans l&apos;exemple ci-dessous, le temps de segment ne sera pas inférieur à 5 secondes en raison du retard créé dans le futur enveloppé.

```scala
import scala.concurrent.{ExecutionContext, Future}
import com.newrelic.scala.api.TraceOps.asyncTraceFun
// implicit execution
implicit val ec: ExecutionContext = ???

val x: Future[Int] = Future(1)
            .flatMap(asyncTraceFun("statement segment")(i => Future(i + 1)))

x.foreach(println) // prints 2 on completion of Future
```

### Transactions

Les transactions peuvent être créées à l&apos;aide de la méthode `TraceOps.txn` . Par exemple:

```scala
import com.newrelic.scala.api.TraceOps.txn
txn {
    val i = 1
    val j = 2
    println(i + j)
}
```

`txn` peut être utilisé comme une déclaration (comme ci-dessus) ou comme une expression

```scala
import com.newrelic.scala.api.TraceOps.txn
val i: Int = txn(1 + 2) //transaction created
println(i) // 3
```

`txn` peut être utilisé avec l&apos;une des méthodes `TraceOp` pour créer des segments. L&apos;exemple ci-dessous crée une transaction avec 3 segments.

```scala
import scala.concurrent.{ExecutionContext, Future}
import com.newrelic.scala.api.TraceOps.{txn, asyncTrace}
// implicit execution
implicit val ec: ExecutionContext = ???

 val x: Future[Int] = txn(
     for {
        one <- asyncTrace("segment one")(Future(1))
        two <- asyncTrace("segment two")(Future(one + 1))
        three <- asyncTrace("segment three")(Future(two + 1))
    } yield three
 )

x.foreach(println) // prints 3 on completion of Future
```

### Les contrats à terme

New Relic gère les futurs Scala lorsqu&apos;ils sont soumis à l&apos;exécuteur, ce qui peut conduire à un résultat différent de celui attendu. Les exemples de cette section expliquent comment cela fonctionne, afin que vous sachiez à quoi vous attendre.

Cet exemple appelle un bloc de transaction, qui prend un futur comme paramètre et le chaîne à un deuxième futur :

```scala
def chainFutures(f: Future[Unit]) = txn {
     f.flatMap( _ => Future{ Thread.sleep(2000) })
}

val f = Future { Thread.sleep(5000) } // future is submitted here
chainFutures(f)
```

À partir de cet exemple, vous pourriez vous attendre à ce que `chainFutures` produise une transaction d’une durée de 7 secondes. Au lieu de cela, l’UI de New Relic indique que la transaction se termine immédiatement.

Le futur `f` dans l&apos;exemple est soumis par la méthode `Future.apply()` lors de sa construction, avant que la transaction n&apos;existe. Étant donné que `f` est soumis en dehors de la transaction, tous les threadhops effectués pendant son exécution ne sont pas liés entre eux. Le futur en aval, `Future{ Thread.sleep(2000) }`, n&apos;est pas non plus suivi, car il est soumis dans un rappel après que le contexte de transaction a déjà disparu.

Il y a quelques choses que vous pouvez faire pour que votre transaction capture le timing des deux contrats à terme.

* Même si vous ne pouvez pas modifier le moment où `f` est soumis, vous pouvez le chronométrer à l&apos;aide de la méthode `asyncTrace` . Cette fois, `f` s&apos;écoule à partir du moment où la transaction est démarrée (mais ne suivra pas les threadhops effectués par `f`).
* Vous pouvez utiliser un jeton pour lier le rappel à la transaction afin de préserver le contexte de la transaction pendant les threadhops.
* Vous pouvez ajouter un autre `asyncTrace` pour chronométrer le deuxième futur.

Avec cet exemple, l&apos;UI de New Relic montre une transaction d&apos;une durée d&apos;environ 7 secondes, avec deux segments nommés « premier futur » et « deuxième futur » :

```scala
def chainFutures(f: Future[Unit]) = txn {
  val t = NewRelic.getAgent.getTransaction.getToken
  asyncTrace("future one" )(f)                                  //asyncTrace times the first future
    .flatMap(_ => {
      t.linkAndExpire()                                         //token links across potential threadhops
      asyncTrace("future two"){ Future { Thread.sleep(2000) } } //asyncTrace times the second future
    })
}
val f = Future { Thread.sleep(5000) } 
chainFutures(f)
```

Instrumenter Scala pour utiliser la classe API New Relic ou [les annotations](/docs/agents/java-agent/java-agent-api/java-agent-api-instrument-using-annotation).

1. Ajoutez les informations suivantes à votre fichier de configuration Scala :

   <CollapserGroup>
   <Collapser
     id="build-scala"
     title={<><strong>Configurer à l'aide du fichier project/build.scala</strong></>
     }
   >
   Ajoutez la ligne suivante (en remplaçant `X.Y.Z` par la [version de l&apos;agent Java](/docs/agents/java-agent/installation/update-java-agent#procedures) que vous utilisez) à la méthode appDependencies dans le fichier `project/build.scala` de votre application :

   ```scala
   "com.newrelic.agent.java" % "newrelic-api" % "X.Y.Z"
   ```
   </Collapser>

   <Collapser
     id="build.sbt"
     title={<><strong>Configurer à l'aide du fichier project/build.sbt</strong></>
     }
   >
   Ajoutez la ligne suivante (en remplaçant `X.Y.Z` par la [version de l&apos;agent Java](/docs/agents/java-agent/installation/update-java-agent#procedures) que vous utilisez) au fichier `project/build.sbt` de votre application :

   ```scala
   libraryDependencies += "com.newrelic.agent.java" % "newrelic-api" % "X.Y.Z"
   ```
   </Collapser>
   </CollapserGroup>

   ```java
   import com.newrelic.api.agent.NewRelic
   ...
   NewRelic.setTransactionName(null, "/myTransaction");
   ```
