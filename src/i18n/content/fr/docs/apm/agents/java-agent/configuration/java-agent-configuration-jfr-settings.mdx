Les paramètres JFR configurent le profilage en temps réel basé sur Java Flight Recorder pour le monitoring continu des performances de la JVM.

<Callout variant="tip">
  Retour à l’index complet des paramètres : [configuration de l’agent Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file)
</Callout>

## JFR (Profilage en temps réel)

L&apos;agent Java utilise Java Flight Recorder (JFR) pour collecter des données JVM haute fidélité pour [le profilage en temps réel](/docs/agents/java-agent/features/real-time-profiling-java-using-jfr-metrics/).

Configurez le profilage en temps réel dans la section `jfr` du fichier YAML de l’agent. Ces options de configuration peuvent être remplacées par des [propriétés système](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#System_Properties) préfixées par `newrelic.config.jfr.` ou par des [variables d’environnement](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#Environment_Variables) préfixées par `NEW_RELIC_JFR_`.

    Le nombre maximal d’événements JFR stockés dans la file d’attente en mémoire de l’agent. Augmenter cette valeur peut aider à éviter les lacunes dans les données JFR, mais cela augmentera également la consommation de ressources de l’agent. Si la file d’attente est trop grande, des données peuvent être rejetées si les limites du pipeline backend sont dépassées. Pour plus d’informations, reportez-vous aux [limites d’ingestion de l’API d’événements](/docs/data-apis/ingest-apis/event-api/introduction-event-api/#limits).

    <Callout variant="important">
      Ceci s&apos;applique à l&apos;agent Java [version 8.17.0 ou supérieure](/docs/release-notes/agent-release-notes/java-release-notes).
