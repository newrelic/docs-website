Cette page couvre le chemin d’installation standard de l’agent Java New Relic sur tout serveur d’application pris en charge ou framework basé sur la JVM. Suivez ces étapes pour télécharger l’agent, le configurer et vérifier que les données sont acheminées vers New Relic.

## Compatibilité et exigences [#requirements]

### Soutenu

* Java 8, 11, 17, 21, 24, 25, et 26 *(Java 7 pris en charge sur l’agent v6.5.4, et versions antérieures uniquement)*
* Langages basés sur la JVM : Java, Scala, Kotlin, et Clojure
* Serveurs d’applications et frameworks : Tomcat, Spring Boot, JBoss/WildFly, Glassfish, Jetty, WebLogic, WebSphere, Grails, ColdFusion, Solr, Play, Resin, Tanuki Wrapper, et Geronimo ; voir la page [compatibilité et exigences](/docs/apm/agents/java-agent/getting-started/compatibility-requirements-java-agent) pour les plages de versions prises en charge
* Tout processus JVM qui accepte un argument `-javaagent`

### Non pris en charge

* Exécution aux côtés d’autres agents APM : l’agent Java ne peut pas garantir un comportement correct lorsqu’un autre agent APM est actif dans la même JVM

### Vous avez besoin de

* Un compte New Relic et<InlinePopover type="licenseKey" />
* Une JVM avec prise en charge de SSL SHA-2 (256 bits)
* Autorisation de modifier les scripts de démarrage de votre serveur d&apos;applications ou la configuration de la JVM
* Autorisation de créer un répertoire pour contenir les fichiers de l’agent

## Installation [#install]

<Steps>
  <Step>
    ### Téléchargez l’agent Java [#install-step-1]

    Téléchargez `newrelic-java.zip` en utilisant l’une de ces méthodes :

    <Tabs>
      <TabsBar>
        <TabsBarItem id="curl">curl</TabsBarItem> <TabsBarItem id="powershell">PowerShell</TabsBarItem> <TabsBarItem id="web">Web</TabsBarItem>
      </TabsBar>

      <TabsPages>
        <TabsPageItem id="curl">
          ```bash
          curl -O https://download.newrelic.com/newrelic/java-agent/newrelic-agent/current/newrelic-java.zip
          unzip newrelic-java.zip
          ```
        </TabsPageItem>

        <TabsPageItem id="powershell">
          ```powershell
          Invoke-WebRequest -Uri https://download.newrelic.com/newrelic/java-agent/newrelic-agent/current/newrelic-java.zip -OutFile newrelic-java.zip
          Expand-Archive -Path newrelic-java.zip -DestinationPath .
          ```
        </TabsPageItem>

        <TabsPageItem id="web">
          Téléchargez `newrelic-java.zip` depuis la page des [notes de sortie de l’agent Java](/docs/release-notes/agent-release-notes/java-release-notes/).
        </TabsPageItem>
      </TabsPages>
    </Tabs>

    Après la décompression, le répertoire `newrelic/` contient le jar de l’agent (`newrelic.jar`) et le fichier de configuration (`newrelic.yml`) que vous configurerez lors des prochaines étapes.
  </Step>

  <Step>
    ### Placez les fichiers de l’agent [#install-step-2]

    Créez un répertoire permanent et déplacez les fichiers de l&apos;agent dans celui-ci :

    ```bash
    mkdir -p /opt/newrelic
    mv newrelic/* /opt/newrelic/
    ```

    Nous recommandons `/opt/newrelic` sur Linux/macOS ou `C:\opt\newrelic` sur Windows. Assurez-vous que `newrelic.jar` n’est **pas** dans le classpath de votre application ou dans tout répertoire listé dans `java.endorsed.dirs`.
  </Step>

  <Step>
    ### Passez le `-javaagent` [#install-step-3]

    Ajoutez l’indicateur `-javaagent` à la configuration de démarrage de la JVM de votre serveur d’application, en pointant vers le chemin complet de `newrelic.jar`. La méthode diffère selon le serveur : développez celle qui correspond à votre environnement :

    <CollapserGroup>
      <Collapser id="tomcat" title="Tomcat">
        Choisissez la méthode pour votre configuration Tomcat :

        <Tabs>
          <TabsBar>
            <TabsBarItem id="tomcat-setenvsh">setenv.sh (Linux/macOS)</TabsBarItem> <TabsBarItem id="tomcat-setenvbat">setenv.bat (Windows)</TabsBarItem> <TabsBarItem id="tomcat-windows-service">Service Windows</TabsBarItem> <TabsBarItem id="tomcat-commons-daemon">Apache Commons daemon</TabsBarItem>
          </TabsBar>

          <TabsPages>
            <TabsPageItem id="tomcat-setenvsh">
              Créez `CATALINA_BASE/bin/setenv.sh` s’il n’existe pas, puis ajoutez :

              ```bash
              export CATALINA_OPTS="$CATALINA_OPTS -javaagent:/opt/newrelic/newrelic.jar"
              ```
            </TabsPageItem>

            <TabsPageItem id="tomcat-setenvbat">
              Créez `CATALINA_BASE/bin/setenv.bat` s’il n’existe pas, puis ajoutez :

              ```batch
              SET "CATALINA_OPTS=%CATALINA_OPTS% -javaagent:C:\opt\newrelic\newrelic.jar"
              ```
            </TabsPageItem>

            <TabsPageItem id="tomcat-windows-service">
              1. Sélectionnez **Start &gt; Apache Tomcat X.Y.Z &gt; Configure Tomcat &gt; Java**.

              2. Dans la zone de texte **Java Options**, saisissez l’argument. Utilisez des barres obliques `/` comme séparateur de chemin. Pour Tomcat 6, ajoutez un saut de ligne après l’argument `-javaagent`.

                 ```
                 -javaagent:/opt/newrelic/newrelic.jar
                 ```

              3. Sélectionnez **Apply**, puis redémarrez Tomcat.
            </TabsPageItem>

            <TabsPageItem id="tomcat-commons-daemon">
              La version d&apos;Apache Commons daemon (jsvc) incluse avec Tomcat 6 ne prend pas en charge l&apos;argument `-javaagent`. Une construction à partir de la source du trunk le prend en charge via le préfixe `-X`. Consultez le [rapport de bug Apache](https://issues.apache.org/jira/browse/DAEMON-84) et le [référentiel source d&apos;Apache Commons](https://commons.apache.org/svninfo.html).
            </TabsPageItem>
          </TabsPages>
        </Tabs>
      </Collapser>

      <Collapser id="spring-boot" title="Spring Boot">
        Ajoutez l&apos;argument `-javaagent` avant l&apos;argument `-jar` sur la ligne de commande :

        ```bash
        java -javaagent:/opt/newrelic/newrelic.jar -jar /path/to/your-application.jar
        ```
      </Collapser>

      <Collapser id="glassfish" title="Glassfish">
        1. Depuis la console admin Glassfish, sélectionnez **Application Server &gt; JVM Settings &gt; JVM Options**.

        2. Sélectionnez **Add JVM Option** et ajoutez :

           ```
           -javaagent:/opt/newrelic/newrelic.jar
           ```

              ```bash
              exec $JAVA_EXE -javaagent:/opt/newrelic/newrelic.jar -jar lib/resin.jar $@
              ```

## Configure [#configure]

Modifiez `newrelic/newrelic.yml` et définissez ces deux valeurs requises :

```yaml
license_key: 'YOUR_LICENSE_KEY'
app_name: 'My Application'
```

L’agent lit `newrelic.yml` depuis le même répertoire que `newrelic.jar` au démarrage. Vous pouvez également remplacer n’importe quel paramètre à l’aide des propriétés système Java (par exemple `-Dnewrelic.config.license_key=YOUR_KEY`) ou des variables d’environnement.

Lors de l’utilisation du fichier de configuration, restreignez les autorisations de lecture/écriture au seul propriétaire du processus du serveur d’applications :

```bash
chmod 600 /opt/newrelic/newrelic.yml
```

Consultez la [configuration de l’agent Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file) pour toutes les options disponibles.

## Vérifiez votre installation [#verify]

Redémarrez votre serveur d’application. Envoyez au moins deux requests, puis patientez 2 - 3 minutes et votre application apparaît dans [APM &amp; services](https://one.newrelic.com/nr1-core?filters=%28domain%20IN%20%28%27APM%27%2C%20%27EXT%27%29%20AND%20type%20IN%20%28%27APPLICATION%27%2C%20%27SERVICE%27%29%29).

Si aucune donnée n’apparaît après cinq minutes, consultez [Aucune donnée n’apparaît (Java)](/docs/apm/agents/java-agent/troubleshooting/no-data-appears-java).
