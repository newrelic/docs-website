Utilisez la mutation `workflowAutomationStartWorkflowRun` pour lancer l&apos;exécution d&apos;un workflow pour une définition de workflow spécifiée.

<Callout variant="important">
Pour les limites sur les exécutions de workflow simultanées et les étapes par exécution, consultez les [limites du système de workflow](/docs/workflow-automation/limitations-and-faq/workflow-limits).
</Callout>

### option logLevel [#loglevel-option]

L&apos;option `logLevel` contrôle la quantité d&apos;informations que le workflow génère pendant l&apos;exécution.

* `NONE` (par défaut) : ne génère aucune sortie de log.
* `INFO`: fournit des informations au niveau de l&apos;étape.
* `DEBUG`: Ajoute un attribut aux logs de l’étape démarrée avec toutes les entrées de l’étape d’action, en utilisant le format `workflowAutomation.inputs.<inputName>: <inputValue>`.
* `TRACE`: En plus de la sortie `DEBUG`, ajoute un attribut aux logs de l’étape démarrée avec toutes les sorties de l’étape d’action, en utilisant le format `workflowAutomation.outputs.<outputName>: <outputValue>`.

## Demande d&apos;échantillon [#sample-request]

Utilisez le [générateur de requêtes](https://one.newrelic.com/nerdgraph-graphiql?state=b8f3b3a9-8d3e-c03e-5da4-34b98a57ff8f) pour créer et éditer un workflow. Voir [l&apos;explorateur d&apos;API NerdGraph](/docs/apis/nerdgraph/get-started/nerdgraph-explorer).

```graphql
mutation {
  workflowAutomationStartWorkflowRun(
    definition: {name: "json-parsing", version: 1}
    workflowInputs: [
      {key: "checkOperational", value: "false"}
      {key: "checkNonOperational", value: "true"}]
    scope: {id: "12345678"}
    idempotencyKey: "45e65924-5316-479c-a977-f6adfa17e07a"
    options: {logLevel: INFO}
  ) {
    runId
  }
}
```

## Exemple de réponse [#sample-response]

La mutation retourne :

* `runId`: L&apos;identifiant unique de l&apos;exécution du workflow. Utilisez cet ID avec les API `WorkflowRunInfo`, `SignalWorkflowRun` ou `StopWorkflowRun`.
