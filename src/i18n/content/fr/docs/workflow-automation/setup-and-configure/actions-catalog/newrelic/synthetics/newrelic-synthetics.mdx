Cette page fournit une référence pour les actions New Relic Synthetics disponibles dans le catalogue des actions d’automatisation des workflows. Ces actions vous permettent de déclencher des exécutions de tests à la demande pour les moniteurs existants, de gérer les temps d’arrêt des fenêtres de maintenance, et de lire les détails des moniteurs directement depuis une définition de workflow.

## Prérequis

Avant d’utiliser les actions New Relic Synthetics dans l’automatisation de workflow, assurez-vous de disposer de :

* Un compte New Relic avec les autorisations appropriées pour accéder aux moniteurs Synthetics.
* Le GUID de l’entité de chaque moniteur que vous souhaitez cibler. Vous pouvez trouver le GUID d’un moniteur dans New Relic sous **Synthetics &gt; \[nom du moniteur] &gt; Settings**.

## Démarrez un test automatisé [#start-automated-test]

L’identifiant de l’action est `newrelic.synthetics.startAutomatedTest`.

Déclenche une exécution de test automatisé Synthetics à la demande pour un ou plusieurs moniteurs et renvoie un `batchId` pour récupérer les résultats à l’aide de `newrelic.synthetics.getAutomatedTestResult`.

<Callout variant="important">
Seuls les types de moniteurs d&apos;API scriptées, navigateur scripté, étape, et navigateur simple sont pris en charge. Les moniteurs SIMPLE (ping) sont rejetés par l’API avec une erreur de type de moniteur incompatible.
</Callout>

## Créer un temps d’arrêt de moniteur [#create-monitor-downtime]

L’identifiant de l’action est `newrelic.synthetics.createMonitorDowntime`.

Planifie un temps d’arrêt (fenêtre de maintenance) unique du moniteur Synthetics pour un ou plusieurs moniteurs spécifiques. L’API renvoie un libellé de fuseau horaire résolu (tel que `Pacific Standard Time`) plutôt que le nom IANA soumis.

<Callout variant="important">
`monitorGuids` est nullable dans le schéma GraphQL, mais requis en pratique : l’omettre déclenche une erreur de serveur. Il n’existe pas de mode de temps d’arrêt à l’échelle du compte ; les temps d’arrêt ont toujours pour cible des moniteurs spécifiques.
</Callout>

## Modifier un temps d&apos;arrêt du moniteur [#edit-monitor-downtime]

Modifie un temps d’arrêt de moniteur Synthetics existant identifié par son GUID d’entité.

`monitorGuids` est requis à chaque appel de modification. L’API ne conserve pas la liste existante lorsque ce champ est omis ; elle la vide à la place. Transmettez toujours l’ensemble complet souhaité de GUID de moniteur.
