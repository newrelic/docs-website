Cette page fournit une référence pour les actions AWS Lambda disponibles dans le catalogue des actions d’automatisation des workflows. Utilisez ces actions pour gérer et invoquer des fonctions Lambda dans le cadre de vos définitions de workflow.

## Prérequis

Avant d&apos;utiliser les actions AWS Lambda dans l&apos;automatisation des workflows, assurez-vous d&apos;avoir :

* Un compte AWS disposant des autorisations appropriées.
* Informations d’identification AWS configurées (informations d’identification de l’utilisateur IAM, ARN du rôle IAM, ou informations d’identification de session). Au moins une option d’informations d’identification doit être fournie : le rôle IAM est prioritaire sur les clés d’accès statiques.
* Les autorisations IAM nécessaires pour les opérations Lambda spécifiques que vous prévoyez d’utiliser.

Consultez la section [Configurer les identifiants AWS](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials/) pour savoir comment créer des utilisateurs et des rôles IAM, et configurer des identifiants AWS statiques et de session pour l&apos;intégration aux actions AWS de Workflow Automation.

## Répertorier les fonctions Lambda

L’identifiant de l’action est `aws.lambda.listFunctions`.

Renvoie une liste de fonctions Lambda dans une région, avec la configuration spécifique à la version de chacune. AWS renvoie au maximum 50 fonctions par appel ; utilisez `marker` et `maxItems` pour paginer les grands ensembles de résultats.

## Obtenir l’historique d’exécution durable Lambda

L’identifiant de l’action est `aws.lambda.getDurableExecutionHistory`.

Récupère l’historique d’exécution pour une [exécution durable Lambda](https://docs.aws.amazon.com/lambda/latest/dg/durable-functions.html), en affichant toutes les étapes, les rappels et les événements qui se sont produits. Cette action s’applique uniquement aux exécutions durables Lambda : elle ne peut pas récupérer l’historique d’invocation des fonctions Lambda classiques. L’historique est disponible pendant que l’exécution est en cours et pour une période de rétention configurable après son achèvement (1 - 90 jours, 30 jours par défaut).

Pour les exécutions de longue durée avec de nombreuses étapes ou rappels, définissez `includeExecutionData` sur `false` lorsque vous n’avez besoin que des types d’événements et des horodatages plutôt que des charges complètes : cela produit une réponse plus compacte.

## Définir la simultanéité de la fonction Lambda

La réservation de la simultanéité garantit à la fois que la fonction dispose de la capacité pour ce nombre d&apos;exécutions simultanées et l&apos;empêche d&apos;évoluer au-delà de ce niveau. Le paramètre de simultanéité s&apos;applique à toutes les versions publiées et à la version non publiée. Définir `reservedConcurrentExecutions` sur `0` désactive la fonction sans la supprimer.
