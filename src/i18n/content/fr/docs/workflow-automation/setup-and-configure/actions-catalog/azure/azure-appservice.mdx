Cette page fournit une référence pour les actions Azure App Service disponibles dans le catalogue des actions d’automatisation workflow. Ces actions vous permettent d’obtenir, de lister, de démarrer, d’arrêter, et de redémarrer les applications web Azure App Service directement depuis une définition de workflow, permettant des workflow opérationnels tels que les arrêts programmés pour le contrôle des coûts, les redémarrages déclenchés par un incident, et les vérifications préalables avant une étape pour déployer.

## Prérequis

Avant d&apos;utiliser les actions Azure App Service dans l&apos;automatisation de workflow, assurez-vous de disposer de :

* Un abonnement Azure avec un ou plusieurs App Services.
* Une inscription d’application Entra (Azure AD) (principal de service) avec les autorisations requises.
* Les identifiants d’enregistrement de l’application stockés dans le New Relic Secrets Service.

## Configurer l&apos;authentification Entra

Les actions Azure App Service s&apos;authentifient en utilisant un flux OAuth2 d&apos;informations d&apos;identification de client de principal de service Entra (Azure AD). Les autorisations requises dépendent de l&apos;action :

* Rôle **Reader** (Lecteur) : requis pour `azure.appService.get` et `azure.appService.list`.
* **Contributor** (Contributeur) (ou **Website Contributor** (Contributeur de site Web) pour le moindre privilège) — requis pour `azure.appService.start`, `azure.appService.stop`, et `azure.appService.restart`.

<Steps>
<Step>
### Créez une inscription d&apos;application Entra

1. Dans le portail Azure, accédez à **Microsoft Entra ID &gt; App registrations** et cliquez sur **New registration**.
2. Donnez un nom à l’enregistrement et cliquez sur **Register**.
3. Notez l’ **ID d’application (client) (Application (client) ID)** et l’ **ID d’annuaire (tenant) (Directory (tenant) ID)** : vous en aurez besoin comme entrées.
4. Sous **Certificates &amp; secrets**, créez un nouveau secret client et copiez la valeur immédiatement.

Pour des instructions complètes, consultez [Enregistrer une application pour obtenir des jetons d’authentification](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/api/register-app-for-token).
</Step>

<Step>
### Attribuez le rôle requis

Attribuez à l’inscription d’application le rôle **Reader** (pour get/list) ou le rôle **Contributor** / **Website Contributor** (pour start/stop/restart) étendu à l’App Service cible ou au groupe de ressources.

1. Dans le portail Azure, accédez au groupe de ressources cible ou à App Service.
2. Accédez à **Access control (IAM) &gt; Add role assignment**.
3. Sélectionnez le rôle approprié et attribuez-le à l’inscription d’application.
</Step>

<Step>
### Stocker les identifiants en tant que secrets

Stockez `clientId`, `clientSecret`, et `tenantId` dans le New Relic Secrets Service et référencez-les dans votre YAML de workflow en utilisant la syntaxe `${{ :secrets:keyName }}` :

```yaml
clientId: ${{ :secrets:azure-client-id }}
clientSecret: ${{ :secrets:azure-client-secret }}
tenantId: ${{ :secrets:azure-client-tenant }}
```
</Step>
</Steps>
