Cette page fournit une référence pour les actions AWS Auto Scaling disponibles dans le catalogue des actions d’automatisation workflow. Utilisez ces actions pour gérer les groupes Auto Scaling (ASG) : attacher et détacher des instances, ajuster la capacité, exécuter des politiques de mise à l’échelle, gérer les actualisations d’instance, contrôler les processus de mise à l’échelle et interroger l’état des ASG.

## Prérequis

Avant d’utiliser les actions AWS Auto Scaling dans l’automatisation workflow, vous devez :

* Un compte AWS avec des autorisations pour le service Auto Scaling.
* Identifiants AWS configurés en tant qu’ARN de rôle IAM ou identifiants de clé d’accès statique.
* Un secret dans le New Relic Secrets Service pour toutes les informations d’identification statiques. Référencez-le dans le workflow en tant que `${{ :secrets:<keyName> }}`.

Consultez la section [Configurer les identifiants AWS](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials/) pour savoir comment créer des utilisateurs IAM et des rôles IAM, et configurer des identifiants AWS statiques et de session.

## Attacher des instances

L’identifiant de l’action est `aws.autoscaling.attachInstances`.

Attachez une ou plusieurs instances EC2 à un groupe Auto Scaling existant. L’attachement d’instances augmente la capacité souhaitée du nombre attaché. Vous pouvez attacher jusqu’à 20 instances par appel. Les instances doivent être à l’état en cours d’exécution ou arrêté, et l’attachement ne doit pas dépasser la taille maximale du groupe.

## Détacher des instances

L’identifiant de l’action est `aws.autoscaling.detachInstances`.

Détachez une ou plusieurs instances EC2 d&apos;un groupe Auto Scaling. Vous pouvez détacher jusqu&apos;à 20 instances par appel. Les instances doivent être à l&apos;état `InService` ou `Standby`. Si `shouldDecrementDesiredCapacity` est `false`, l&apos;ASG procède au lancement d&apos;instances de remplacement pour maintenir la capacité souhaitée.

## Définir la capacité souhaitée

## Exécuter une politique de mise à l&apos;échelle

L’identifiant de l’action est `aws.autoscaling.executePolicy`.

Exécuter une politique de dimensionnement nommée sur un groupe Auto Scaling. La politique doit déjà exister sur le groupe. Pour les politiques de dimensionnement par étapes, `metricValue` et `breachThreshold` peuvent remplacer le seuil de la politique. Si `honorCooldown` est `true` et que l’ASG est en période de refroidissement, l’appel réussit, mais aucune activité de dimensionnement n’est déclenchée.
