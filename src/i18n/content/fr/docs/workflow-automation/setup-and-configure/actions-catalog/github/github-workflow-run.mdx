Cette page fournit une référence pour les actions d’exécution de workflow GitHub disponibles dans le catalogue d’actions d’automatisation de workflow. Ces actions vous permettent de déclencher, de récupérer, et de lister les exécutions de workflow GitHub Actions directement depuis une définition de workflow, permettant l’orchestration automatisée de CI/CD (intégration et livraison continues), les pipelines de déploiement, et l’automatisation des sorties sans code personnalisé, ni outillage externe.

## Prérequis

Avant d&apos;utiliser les actions d&apos;exécution de workflow GitHub dans l&apos;automatisation workflow, assurez-vous de disposer de :

* Un compte GitHub avec accès au référentiel cible.
* Un jeton d’accès personnel (PAT) GitHub avec les autorisations requises.
* Le PAT stocké dans le service de secrets New Relic.
* Le workflow cible configuré avec un déclencheur `workflow_dispatch` (requis pour `gitHub.workflowRun.trigger`).

## Configurer l’authentification PAT

Les actions d’exécution de workflow GitHub s’authentifient à l’aide d’un jeton d’accès personnel (PAT) transmis en tant qu’identifiant Bearer. Cette action prend en charge deux types de jetons :

* **PAT à granularité fine** : nécessite l&apos;autorisation **Actions : write** pour `gitHub.workflowRun.trigger`; **Actions : read** pour `gitHub.workflowRun.get`, `gitHub.workflowRun.getLatest`, et `gitHub.workflowRun.list`.
* **PAT classique** : nécessite la portée **référentiel (repository)** pour les quatre actions.

<Steps>
<Step>
### Créez un jeton d’accès personnel GitHub

1. Dans GitHub, accédez à **Settings &gt; Developer settings &gt; Personal access tokens**.
2. Choisissez **Fine-grained tokens**, ou **Tokens (classic)**, et cliquez sur **Generate new token**.
3. Définissez les autorisations requises : **Actions : write** (ou **Actions : read** pour les actions en lecture seule) pour les jetons à granularité fine, ou l’étendue **référentiel (repository)** pour les jetons classiques.
4. Copiez le jeton généré : GitHub ne l’affiche qu’une seule fois.
</Step>

<Step>
### Stocker le jeton en tant que secret

Stockez le jeton dans le service New Relic Secrets et référencez-le dans votre YAML de workflow en utilisant la syntaxe `${{ :secrets:keyName }}` :

```yaml
token: ${{ :secrets:github-PAT-token }}
```
</Step>
</Steps>
