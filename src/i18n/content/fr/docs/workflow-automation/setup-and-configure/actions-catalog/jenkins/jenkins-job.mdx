Cette page fournit une référence pour les actions de tâche Jenkins disponibles dans le catalogue des actions d’automatisation de workflow. Utilisez ces actions pour déclencher et gérer les builds Jenkins.

## Prérequis

Avant d&apos;utiliser les actions de job Jenkins dans l&apos;automatisation des workflows, vous avez besoin de :

* Un serveur Jenkins accessible depuis New Relic Workflow Automation via HTTPS. Si votre instance Jenkins est derrière un pare-feu ou dans un réseau privé, autorisez l’accès entrant depuis New Relic Workflow Automation.
* Un jeton d’API Jenkins pour le compte sous lequel le workflow s’exécute. Générez-en un depuis votre profil utilisateur Jenkins : **Configure &gt; API Token &gt; Add new Token**.
* Un secret dans le New Relic Secrets Service contenant la valeur encodée en Base64 de `username:apiToken`. Référencez-le dans le workflow en tant que `${{ :secrets:<keyName> }}`.
* Pour les jobs basés sur des dossiers, le chemin d’accès complet au dossier du job utilisant `/` comme séparateur (par exemple, `deployments/production/my-job`).

## Déclencher un job Jenkins

L’identifiant de l’action est `jenkins.job.trigger`.

Déclenche un build Jenkins avec des paramètres facultatifs. En cas de succès, renvoie un `queueId` que vous pouvez utiliser avec [`jenkins.queue.getItem`](/docs/workflow-automation/setup-and-configure/actions-catalog/jenkins/jenkins-queue#jenkins-queue-getitem) pour suivre la progression du build, et récupérer le numéro de build une fois l’exécution commencée.

## Obtenir le statut d’un build Jenkins

L’identifiant de l’action est `jenkins.job.getStatus`.

Obtient le statut d&apos;un build de job Jenkins. Utilisez cette action pour interroger un build déclenché par `jenkins.job.trigger`.

Pour vérifier un build spécifique plutôt que le dernier, fournissez son `buildNumber`. Obtenez le numéro de build en interrogeant la file d’attente avec [`jenkins.queue.getItem`](/docs/workflow-automation/setup-and-configure/actions-catalog/jenkins/jenkins-queue#jenkins-queue-getitem) après avoir déclenché le build.

                  version: 1
                  inputs:

      L’exemple suivant récupère les logs de build et recherche des erreurs.

      <table>
        <thead>
          <tr>
            <th>
              Exemple de workflow
            </th>
          </tr>

        <tbody>
          <tr>
            <td>
              ```yaml
              name: get-jenkins-build-logs
              description: 'Retrieve Jenkins build logs and check for errors'
              steps:
                - name: get_build_logs
                  type: action
                  action: jenkins.job.getConsoleOutput
                  version: 1
                  inputs:
                    authToken: ${{ :secrets:jenkinsAuthToken }}
                    url: "https://jenkins.example.com"
                    jobName: "deployments/production-deploy"
                    buildNumber: 142
                    selectors:
                      - name: buildLogs
                        expression: ".responseBody"
                      - name: hasErrors
                        expression: ".responseBody | contains(\"ERROR\") or contains(\"FAILED\")"

                - name: check_for_errors
                  type: switch
                  switch:
                    - condition: ${{ .steps.get_build_logs.outputs.hasErrors }}
                      next: handle_error
                  next: end
              ```
            </td>
