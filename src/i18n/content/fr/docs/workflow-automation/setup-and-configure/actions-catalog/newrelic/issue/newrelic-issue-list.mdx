Requête et liste les problèmes New Relic Alert Intelligence pour un compte avec filtrage et pagination facultatifs.

Pour les prérequis, consultez [Actions de New Relic Issue](/docs/workflow-automation/setup-and-configure/actions-catalog/newrelic/issue/newrelic-issue#prerequisites).

## Problèmes de liste

L’identifiant de l’action est `newrelic.issue.list`.

Effectue des requêtes, et liste les problèmes New Relic (problèmes d&apos;IA) pour un compte, renvoyant l&apos;état en temps réel, la chronologie, les entités corrélées, et les détails de l&apos;impact pour les problèmes actifs ou passés. Prend en charge le filtrage par état, priorité, source, entité, condition, politique, état de corrélation et d&apos;acquittement, une fenêtre de temps, et la pagination basée sur un curseur. Basé sur `newrelic.nerdgraph.execute`.

            <td>
              Aucun filtre : lister chaque ticket sur le compte, indépendamment de l’état, de la priorité, ou d’autres filtres. Seul `accountId` est requis :

              ```yaml
              name: newrelic_issue_list_all
              description: list all issues for an account with no filters
              steps:
                - name: newrelic_issue_list
                  type: action
                  action: newrelic.issue.list
                  version: 1
                  inputs:
                    accountId: 123456
                  next: end
              ```

              L’exemple suivant utilise des filtres de base pour lister les problèmes actifs et de haute priorité pour un compte :

              ```yaml
              name: newrelic_issue_list_workflow
              description: list newrelic issues
              steps:
                - name: newrelic_issue_list
                  type: action
                  action: newrelic.issue.list
                  version: 1
                  inputs:
                    accountId: 123456
                    states: ["ACTIVATED", "CREATED"]
                    priority: ["CRITICAL", "HIGH"]
                  next: end
              ```

              L’exemple suivant utilise plusieurs filtres pour les problèmes critiques, non acquittés et non mis en sourdine dans une fenêtre de temps spécifique, avec des sélecteurs aplatissant la réponse pour la pagination :

              ```yaml
              name: newrelic_issue_list_advanced
              description: list unacknowledged critical issues in a time window
              steps:
                - name: newrelic_issue_list
                  type: action
                  action: newrelic.issue.list
                  version: 1
                  inputs:
                    accountId: 123456
                    states: ["ACTIVATED"]
                    priority: ["CRITICAL"]
                    isAcknowledged: false
                    mutingStates: ["NOT_MUTED"]
                    startTime: 1785900000000
                    endTime: 1785998400000
                    selectors:
                      - name: issues
                        expression: ".data.actor.account.aiIssues.issues.issues"
                      - name: nextCursor
                        expression: ".data.actor.account.aiIssues.issues.nextCursor"
                  next: end
              ```

              Pour parcourir les résultats supplémentaires du troisième exemple, prenez la sortie `nextCursor` et passez-la comme entrée `cursor` lors d’un appel de suivi.
