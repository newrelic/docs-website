Cette page fournit une référence pour les actions de ticket GitHub disponibles dans le catalogue des actions d&apos;automatisation workflow. Ces actions vous permettent de créer, mettre à jour, lister, et gérer des tickets dans un référentiel GitHub directement depuis une définition de workflow.

## Prérequis

Avant d’utiliser les actions de ticket GitHub dans l’automatisation workflow, assurez-vous de disposer de :

* Un compte GitHub avec accès au référentiel cible.
* Un jeton d’accès personnel (PAT) GitHub avec les autorisations requises.
* Le PAT stocké dans le service de secrets New Relic.

## Configurer l’authentification PAT

Les actions de ticket GitHub s&apos;authentifient à l&apos;aide d&apos;un jeton d&apos;accès personnel (PAT) transmis en tant qu&apos;identifiant Bearer. Cette action prend en charge deux types de jetons :

* **PAT à granularité fine** — nécessite l’autorisation de référentiel **Issues : Read and write**.
* **Classic PAT** — nécessite la portée **référentiel (repository)**.

<Steps>
  <Step>
    ### Créez un jeton d’accès personnel GitHub

    1. Dans GitHub, accédez à **Settings &gt; Developer settings &gt; Personal access tokens**.
    2. Choisissez **Fine-grained tokens**, ou **Tokens (classic)**, et cliquez sur **Generate new token**.
    3. Définissez les autorisations requises : **Issues : read and write** pour les jetons à granularité fine, ou la portée **référentiel (repository)** pour les jetons classiques.
    4. Copiez le jeton généré : GitHub ne l’affiche qu’une seule fois.
  </Step>

  <Step>
    ### Stocker le jeton en tant que secret

    Stockez le jeton dans le service New Relic Secrets et référencez-le dans votre YAML de workflow en utilisant la syntaxe `${{ :secrets:keyName }}` :

    ```yaml
    token: ${{ :secrets:github-PAT-token }}
    ```
  </Step>
</Steps>
