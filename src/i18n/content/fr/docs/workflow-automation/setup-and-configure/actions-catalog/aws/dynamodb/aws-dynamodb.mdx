Cette page fournit une référence pour les actions AWS DynamoDB disponibles dans le catalogue des actions d’automatisation des workflows. Utilisez ces actions pour lire, écrire, mettre à jour, et supprimer des éléments dans les tables DynamoDB, et pour inspecter ou modifier la configuration des tables directement à partir d’une définition de workflow.

## Prérequis

Pour les prérequis et la configuration des identifiants, consultez [Configurer les identifiants AWS](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials).

Toutes les actions DynamoDB acceptent les mêmes entrées d’authentification. Utilisez `awsRoleArn` (recommandé) ou la paire de clés d’accès.

```yaml
description: Write an order item to DynamoDB
steps:
  - name: putOrderItem
    type: action
    action: aws.dynamodb.putItem
    version: '1'
    inputs:
      awsRoleArn: ${{ :secrets:awsRoleArn }}
      region: us-east-2
      tableName: Orders
      item:
        orderId: { "S": "123" }
        status: { "S": "PLACED" }
    next: end
```

## Analyser une table [#scan]

L’identifiant de l’action est `aws.dynamodb.scan`.

Renvoie des éléments d’une table ou d’un index DynamoDB en parcourant toute la table, avec un filtrage facultatif. Une seule réponse d’analyse est limitée à 100 Ko par Workflow Automation (la propre limite de DynamoDB est de 1 Mo). Utilisez `limit` et `exclusiveStartKey` pour parcourir des tables volumineuses.

<Callout variant="important">
Workflow Automation impose une limite de taille de sortie de 100 Ko par action. `aws.dynamodb.scan` lève une exception de dépassement de limite de taille de sortie lorsque la réponse dépasse cette limite, même si elle peut se situer dans la limite de 1 Mo par réponse propre à DynamoDB. Utilisez `limit` et `exclusiveStartKey` pour paginer les résultats, et rester dans cette limite.
</Callout>
