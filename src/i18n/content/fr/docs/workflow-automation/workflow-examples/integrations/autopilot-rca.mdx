Les modèles de workflow suivants automatisent l’analyse des causes profondes basée sur <DNT>Autopilot</DNT>pour les alertes New Relic :

* **[RCA d’alerte avec Autopilot et Slack](/docs/workflow-automation/workflow-examples/integrations/autopilot-slack-rca)** — Publie les conclusions dans un canal Slack en utilisant le formatage Block Kit
* **[RCA d’alerte avec Autopilot et e-mail](/docs/workflow-automation/workflow-examples/integrations/autopilot-email-rca)** - Envoie les résultats sous forme d’e-mail HTML formaté

Ces modèles acceptent une entrée `issueId` et exécutent <DNT>Autopilot</DNT> avec un prompt RCA. Ils vérifient si <DNT>Autopilot</DNT> a renvoyé une réponse utilisable et acheminent la sortie vers la destination choisie. Ils diffèrent par le type de destination et la façon dont ils formatent la sortie de <DNT>Autopilot&apos;s</DNT>.

## Exigences [#requirements]

Tous les modèles requièrent un ID de problème d’alerte New Relic au format UUID. Chaque modèle requiert également une destination de notification configurée : consultez les pages individuelles des modèles pour connaître les prérequis spécifiques à la destination.

<Callout variant="tip">
  Lorsque vous déclenchez l&apos;un de ces modèles depuis <DNT>**Alert Workflows**</DNT>, utilisez `{{ issueId }}` comme valeur pour l&apos;entrée `issueId`. Cette variable transmet automatiquement l’ID de problème de l’alerte de déclenchement au workflow.
</Callout>

## Notes de configuration [#configuration]

Gardez les éléments suivants à l&apos;esprit lors de la configuration de l&apos;un de ces modèles.

<Callout variant="important">
  Écrivez les valeurs du sélecteur `expression` sur une seule ligne. Le moteur de workflow n’évalue pas les scalaires de bloc YAML multilignes (`|` ou `|-`) comme des expressions de sélecteur : ils ne produisent silencieusement aucune sortie.
</Callout>

<Callout variant="tip">
  <DNT>Autopilot&apos;s</DNT> `finalAnswer` le champ peut renvoyer soit une simple chaîne de caractères, soit un objet encodé en JSON selon le contexte du prompt. Les sélecteurs de chaque modèle gèrent automatiquement les deux formes.
</Callout>
