Le [dashboard de Workflow Automation](https://onenr.io/0gR7XE8LXjo) offre un emplacement centralisé pour visualiser, gérer et monitorer tous les workflows de votre compte. Utilisez le dashboard pour modifier la configuration, suivre l’historique des versions, gérer les calendriers d’exécution et résoudre les problèmes. Pour gérer les workflows, vous avez besoin d’au moins un workflow dans votre compte et des autorisations de modification et de suppression.

<Callout variant="important">
**Désactiver l&apos;automatisation des workflows ?** Si vous prévoyez de désactiver Workflow Automation via Feature Control Management (FCM), assurez-vous que tous les workflows planifiés sont supprimés au préalable. Consultez [Désactiver l&apos;automatisation des workflows](/docs/workflow-automation/troubleshooting#disabling-workflow-automation-fcm) pour les étapes détaillées.
</Callout>

**Vous débutez dans le monde du workflow ?** Commencez par [utiliser un modèle](/docs/workflow-automation/create-a-workflow-automation/use-a-template) ou [créez votre propre workflow](/docs/workflow-automation/create-a-workflow-automation/create-your-own) pour construire votre premier workflow.

## Afficher le workflow [#view-workflows]

Allez à <DNT>**All Capabilities &gt; Workflow Automation**</DNT>. Si votre compte ne contient aucun workflow, le dashboard affiche un état vide avec des options pour créer votre premier workflow.

### Onglets de Dashboard

Une fois que vous avez créé des workflows, le dashboard affiche deux onglets :

<DNT>**Summary tab**</DNT> (par défaut) : affiche les métriques et les visualisations au niveau du compte :

<DNT>**Top metrics**</DNT>:

* <DNT>**Total workflows**</DNT>: nombre de tous les workflows de votre compte
* <DNT>**Total number of steps executed**</DNT>: nombre cumulé d&apos;étapes sur l&apos;ensemble des exécutions de workflow
* <DNT>**Currently running workflows**</DNT>: Nombre d’exécutions actives

<DNT>**Performance charts**</DNT>:

* <DNT>**Total run count of all workflows**</DNT>: graphique linéaire montrant les tendances d&apos;exécution des workflow au fil du temps
* <DNT>**Top 5 most frequently run workflows**</DNT>: graphique à barres affichant les workflows ayant le plus grand nombre d&apos;exécutions
* <DNT>**Ratio of completed to failed workflows**</DNT>: diagramme circulaire affichant les pourcentages et les nombres de succès et d&apos;échecs

<DNT>**Recently failed runs table**</DNT>: affiche les exécutions de workflow en échec avec les colonnes suivantes :

* <DNT>**Workflow**</DNT>: Nom du workflow échoué
* <DNT>**Version**</DNT>: version du workflow qui a échoué
* <DNT>**Failed on**</DNT>: horodatage de l&apos;échec
* <DNT>**Run ID**</DNT>: identifiant unique de l&apos;exécution en échec
* <DNT>**Failed step**</DNT>: Étape où l’échec est survenu
* <DNT>**Error message**</DNT>: Description de l’erreur

Chaque widget de graphique inclut un menu contextuel (trois points) pour afficher la requête, obtenir l&apos;image, ou créer une condition d’alerte.

<img title="Image of the summary tab in the Workflow Automation dashboard showing account-level metrics and visualizations" alt="Image of the summary tab in the Workflow Automation dashboard showing account-level metrics and visualizations" src="/images/workflow-automation-summary-tab.webp" />

<DNT>**Workflows tab**</DNT>:

<DNT>**Search**</DNT>: utilisez la barre <DNT>**Search in all fields**</DNT> pour trouver des workflow à partir de n&apos;importe quelle valeur de colonne.

<DNT>**All workflows table**</DNT> affiche ces colonnes :

* <DNT>**Favorite**</DNT> (icône étoile) : marquer les workflow comme favoris
* <DNT>**Name**</DNT>: identifiant de workflow
* <DNT>**Description**</DNT>: objectif ou fonction du workflow
* <DNT>**Last run on**</DNT>: horodatage de la dernière exécution
* <DNT>**Last run status**</DNT>: résultat de l&apos;exécution (affiché sous forme de badges colorés : vert pour Terminé, rouge pour Échoué)
* <DNT>**Latest version**</DNT>: numéro de version actuel
* <DNT>**Created on**</DNT>: date à laquelle le workflow a été créé
* <DNT>**Actions menu**</DNT> (trois points) : accéder aux opérations de workflow

Les valeurs vides du tableau s&apos;affichent sous la forme `—`

<DNT>**Row actions menu**</DNT> (cliquez sur les trois points à côté du workflow) :

* <DNT>**Run**</DNT>: exécutez le workflow immédiatement
* <DNT>**Schedule**</DNT>: créer une exécution planifiée
* <DNT>**Open in editor**</DNT>: modifier la configuration du workflow
* <DNT>**Duplicate**</DNT>: Créer une copie du workflow
* <DNT>**Delete**</DNT>: supprimez définitivement le workflow

Cliquez sur un nom de workflow pour afficher sa [page Vue d&apos;ensemble de l&apos;entité](/docs/workflow-automation/manage-workflows/workflow-entity-overview) avec des métriques détaillées, l&apos;historique des exécutions, les planifications et les logs.

## Modifier un workflow [#edit-a-workflow]

Mettre à jour le nom, la description ou la configuration du workflow.

1. Localisez le workflow que vous souhaitez modifier

2. Cliquez sur les points de suspension (trois points verticaux) à côté du nom du workflow

3. Select <DNT>**Open in editor**</DNT>

4. Mettez à jour l&apos;un de ces éléments :

   * <DNT>**Name**</DNT> — L&apos;identifiant du workflow
   * <DNT>**Description**</DNT> — Objectif ou fonction du workflow
   * <DNT>**Configuration**</DNT> — Paramètres d’entrée, actions ou logique

5. Cliquez <DNT>**Save**</DNT>

Vous pouvez également accéder à l’éditeur depuis la [page Vue d’ensemble de l’entité](/docs/workflow-automation/manage-workflows/workflow-entity-overview) en cliquant sur le bouton <DNT>**Edit**</DNT>.

## Gérer les versions [#manage-versions]

L&apos;automatisation des workflows crée automatiquement une nouvelle version à chaque mise à jour d&apos;une définition de workflow. Toutes les versions précédentes restent disponibles à titre de référence et peuvent être consultées ou exécutées directement depuis l&apos;éditeur.

### Consultez l’historique des versions dans l’éditeur [#view-version-history]

Vous pouvez parcourir toutes les versions précédentes d&apos;un workflow sans quitter l&apos;éditeur.

1. Ouvrir un workflow dans l’éditeur
2. Cliquez sur le <DNT>**version dropdown**</DNT> dans la barre d&apos;outils de l&apos;éditeur
3. Sélectionnez une version précédente dans la liste

La version sélectionnée s&apos;ouvre dans un <DNT>**read-only preview**</DNT> au sein de l&apos;éditeur. Vous pouvez examiner la configuration et l&apos;exécuter, mais vous ne pouvez pas la modifier directement.

### Créer une nouvelle version à partir d&apos;une version précédente [#edit-as-new-version]

Si vous souhaitez utiliser une version précédente comme base pour une nouvelle modification :

1. Ouvrez le workflow dans l&apos;éditeur et sélectionnez une version précédente dans la liste déroulante des versions
2. Cliquez <DNT>**Edit as new version**</DNT>
3. Effectuez vos modifications
4. Cliquez <DNT>**Save**</DNT>

Le système crée une nouvelle version numérotée comme la version actuelle la plus élevée + 1. Par exemple, si la v5 est la plus récente et que vous modifiez la v2, le résultat est la v6. La version précédente n’est pas écrasée.

Si vous changez d’avis, cliquez sur <DNT>**Cancel**</DNT> pour annuler la modification en cours. Aucune nouvelle version n’est enregistrée, et vous retournez à la liste de workflow.

### Comparer les versions [#compare-versions]

Une vue de comparaison des versions est disponible dans l’éditeur. Utilisez-la pour inspecter les différences entre deux versions d’un workflow avant de décider laquelle exécuter ou utiliser comme base.

### Épinglage de version pour la planification

Lorsque vous planifiez un workflow, vous devez l&apos;associer à une version spécifique. Cette version associée s&apos;exécute même si vous mettez à jour la définition du workflow par la suite.

**Démarrez et planifiez l&apos;épinglage de la version de prise en charge des workflows :**

* Lors de la planification d&apos;un workflow, spécifiez la version à exécuter.
* Lors du lancement manuel d&apos;un workflow, sélectionnez la version à exécuter.
* Lorsque vous mettez à jour un planning, spécifiez la nouvelle version à utiliser

Cela vous permet de :

* Mise à jour du workflow sans incidence sur les calendriers en cours
* Tester manuellement les nouvelles versions avant de mettre à jour les calendriers
* Maintenir la stabilité du flux de production

## Dupliquer un workflow [#duplicate-a-workflow]

Dupliquez le workflow lorsque vous devez adapter un modèle ou workflow existant à un usage différent tout en conservant l&apos;original intact.

1. Localisez le workflow que vous souhaitez dupliquer.
2. Cliquez sur les points de suspension (trois points verticaux).
3. Select <DNT>**Duplicate**</DNT>
4. Le système crée une copie avec **(Copy)** ajouté au nom
5. Renommez et personnalisez le workflow dupliqué selon vos besoins.

**Scénarios de duplication courants :**

* Adapter un modèle workflow à votre cas d&apos;utilisation spécifique
* Création d&apos;un workflow pour une autre équipe ayant des exigences similaires
* Expérimenter des changements significatifs tout en préservant l&apos;original

<Callout variant="important">
**Ne dupliquez pas les workflows pour la gestion de version** - le système le fait automatiquement. Dupliquer des workflows uniquement à des fins de contrôle de version ou de rollback peut vous faire atteindre les limites de workflows. Consultez [Gérer les versions](#manage-versions) pour plus d&apos;informations sur le versionnage automatique.
</Callout>

## Supprimer un workflow [#delete-a-workflow]

Supprimez les workflows dont vous n&apos;avez plus besoin.

1. Localisez le workflow que vous souhaitez supprimer
2. Cliquez sur le menu « Plus d’options » (trois points verticaux).
3. Select <DNT>**Delete**</DNT>
4. Confirmez la suppression dans la boîte de dialogue.

<Callout variant="caution">
La suppression d&apos;un workflow est définitive. Vous ne pouvez pas l&apos;annuler. Nous supprimons toutes les versions et l&apos;historique d&apos;exécution. Si vous pensez avoir besoin du workflow ultérieurement, envisagez de le désactiver au lieu de le supprimer.
</Callout>

**Ce qui est supprimé :**

* Toutes les versions du workflow
* Historique complet des exécutions et des logs
* Toutes les exécutions planifiées associées au workflow

**Avant de supprimer, vérifiez :**

* Aucune automatisation critique ne dépend de ce workflow
* Vous disposez d&apos;une copie de sauvegarde au cas où vous en auriez besoin plus tard.
* Identifier et prendre en compte toutes les exécutions planifiées
