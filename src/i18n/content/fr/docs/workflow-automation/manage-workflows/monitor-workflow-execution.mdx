Cet article décrit comment utiliser les données d&apos;observabilité pour monitorer l&apos;exécution de workflow et l&apos;exécution de planification.

## Audits

Tous les appels de mutation NerdGraph produisent des enregistrements d&apos;audit que vous pouvez requêter dans `NrAuditEvent` dans le compte clients.

### WorkflowRun

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_run'
SINCE 1 hour ago
```

### WorkflowSchedule

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_schedule'
SINCE 1 hour ago
```

## Événements

Toutes les exécutions de workflow émettent des données `WorkflowAutomationEvent` dans NRDB dans le compte clients qui a démarré ou planifié le workflow.

Les exécutions de workflow stockent les données d&apos;événement dans l&apos;espace de nommage `WorkflowAutomation`.

* `ACTION`: exécute une action depuis le catalogue
* `LOOP`: itère sur une collection
* `SWITCH`: évalue les conditions
* `STATE`: stocke les paires de valeur clé dans l&apos;état partagé du workflow

### Exemple de requête

La requête suivante renvoie tous les événements pour une exécution de workflow spécifique :

```sql
SELECT *
FROM WorkflowAutomationEvent
where definitionName = 'json-parsing' and runId = '31c973d2-c669-4bd7-9b15-7e3a70a4a074'
SINCE 1 month ago
```

## Logs

En option, vous pouvez démarrer ou planifier un workflow avec une option de verbosité `logLevel`. Les logs vont vers le compte qui a démarré ou planifié le workflow.

Les logs incluent les attributs suivants :

* `workflowAutomation.name` est le nom de la WorkflowDefinition
* `workflowAutomation.version` est la version de WorkflowDefinition
* `workflowAutomation.runId` est le runId du workflow
* `entityGuid` est l&apos;ID de WorkflowDefinition

Si une occurrence de planification a démarré le workflow, les entrées de log incluent également `workflowAutomation.scheduleId`.

Pour le type d&apos;étape Action, lors de l&apos;utilisation de `DEBUG`, chaque entrée d&apos;action ajoute un attribut supplémentaire à l&apos;entrée de log avec le format `workflowAutomation.inputs.<inputName>: <inputValue>`.

Pour le type d&apos;étape Action, lors de l&apos;utilisation de `TRACE`, chaque sortie d&apos;action ajoute un attribut supplémentaire à l&apos;entrée de log avec le format `workflowAutomation.outputs.<outputName>: <outputValue>`.

### Exemple de requête NRQL

Vous pouvez interroger votre log avec la requête NRQL suivante :

```sql
SELECT message FROM Log WHERE workflowAutomation.runId = '{run_id}' SINCE 3 hours ago
```

<img title="Diagram of log attributes for workflow runs" alt="Diagram of log attributes for workflow runs" src="/images/log_attributes.webp" />

Outre `workflowAutomation.runId`, d&apos;autres attributs de log qui peuvent aider à l&apos;interrogation des données log sont :

* `workflowAutomation.name`
* `workflowAutomation.version`

Pour les exécutions planifiées, les entrées de log incluent également l&apos;attribut `workflowAutomation.scheduleId`.
