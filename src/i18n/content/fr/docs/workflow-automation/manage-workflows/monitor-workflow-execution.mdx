Ce document décrit les différentes données d&apos;observabilité qui peuvent être utilisées pour monitorer les exécutions de workflow ou les planifications.

## Audits

Tous les appels de mutation NerdGraph sont audités et les données peuvent faire l&apos;objet d&apos;une requête dans `NrAuditEvent` dans le compte clients.

### WorkflowRun

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_run'
SINCE 1 hour ago
```

### WorkflowSchedule

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_schedule'
SINCE 1 hour ago
```

## Événements

Toutes les exécutions de workflow émettent des données `WorkflowAutomationEvent` dans NRDB dans le compte client qui a été utilisé pour démarrer, ou planifier, un workflow.

Un nouvel espace de nommage `WorkflowAutomation` est créé pour les données d&apos;événement des exécutions de workflow.

### Exemple de requête

Par exemple:

```sql
SELECT *
FROM WorkflowAutomationEvent
where definitionName = 'json-parsing' and runId = '31c973d2-c669-4bd7-9b15-7e3a70a4a074'
SINCE 1 month ago
```

## Logs

En option, un workflow peut être démarré ou planifié en spécifiant une option de verbosité `logLevel`. Ces logs sont ajoutés au compte de workflow qui a été utilisé pour démarrer, ou planifier, le workflow.

Les logs sont dotés des attributs suivants :

* `workflowAutomation.name` est le nom de la WorkflowDefinition
* `workflowAutomation.version` est la version de WorkflowDefinition
* `workflowAutomation.runId` est le runId du workflow
* `entityGuid` est l&apos;ID de WorkflowDefinition

Si démarré à partir d&apos;une occurrence de planification :

* `workflowAutomation.scheduleId`

Pour le type d&apos;étape Action, lors de l&apos;utilisation de `DEBUG`, chaque entrée d&apos;action ajoute un attribut supplémentaire à l&apos;entrée de log au format `workflowAutomation.inputs.<inputName>: <inputValue>`.

Pour le type d’étape Action, lors de l’utilisation de `TRACE`, chaque sortie d’action ajoute un attribut supplémentaire à l’entrée de log avec le format `workflowAutomation.outputs.<outputName>: <outputValue>`.

### Exemple de requête NRQL

Vous pouvez interroger votre log avec la requête NRQL suivante :

```sql
SELECT message FROM Log WHERE workflowAutomation.runId = '{run_id}' SINCE 3 hours ago
```

<img title="Diagram of log attributes for workflow runs" alt="Diagram of log attributes for workflow runs" src="/images/log_attributes.webp" />

Outre `workflowAutomation.runId`, d&apos;autres attributs de log qui peuvent aider à l&apos;interrogation des données log sont :

* `workflowAutomation.name`
* `workflowAutomation.version`

Pour les exécutions planifiées, les entrées de log auront également l&apos;attribut `workflowAutomation.scheduleId`.
