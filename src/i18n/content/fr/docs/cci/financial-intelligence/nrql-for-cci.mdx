Interrogez vos données d’Intelligence Coûts du cloud (CCI) avec le New Relic Query Language (NRQL) pour analyser vos dépenses cloud et identifier des opportunités d’optimisation des coûts. Pour exécuter l’une des requêtes de cette page, allez dans <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Cloud Cost Intelligence**</DNT> et ouvrez le <DNT>**Query your data**</DNT>.

Les types d’événements avec une prise en charge **complète** de NRQL acceptent toute clause NRQL valide. Les types d’événements avec une prise en charge **limitée** de NRQL acceptent uniquement les clauses répertoriées dans [Clauses NRQL prises en charge](#supported-nrql-clauses):

## CloudSpend [#cloudspend]

`CloudSpend` et `CloudCost` contiennent les mêmes données de facturation de votre fournisseur de cloud, mais diffèrent par leurs capacités NRQL. `CloudSpend` prend en charge l’intégralité du langage NRQL et constitue le choix recommandé pour toutes les nouvelles requêtes. `CloudCost` ne prend en charge qu’un sous-ensemble de clauses NRQL et son abandon est prévu.

`CloudSpend` ingère les lignes de facturation brutes des rapports de coûts et d’utilisation AWS (CUR), des exportations Azure FOCUS, et des exportations GCP BigQuery, mises à jour toutes les heures. Il partage des attributs clés avec `CloudCost`, y compris `line_item_net_unblended_cost`, `line_item_product_code`, et `line_item_usage_account_id`. Pour une référence complète des attributs, consultez le [dictionnaire de données](/attribute-dictionary).

Exemple de requête :

```sql
FROM CloudSpend SELECT * SINCE 24 hours ago
```

Trouvez vos dépenses cloud totales réparties par service au cours du mois dernier :

```sql
FROM CloudSpend SELECT SUM(line_item_net_unblended_cost) FACET line_item_product_code SINCE 1 month ago
```

Découvrez comment les dépenses cloud quotidiennes évoluent au fil du temps :

```sql
FROM CloudSpend SELECT SUM(line_item_net_unblended_cost) TIMESERIES 1 day SINCE 30 days ago
```

## KubernetesSpend [#kubernetesspend]

`KubernetesSpend` stocke les enregistrements d’allocation de coûts individuels pour les workloads Kubernetes. Il combine la télémétrie de New Relic Infrastructure avec les exportations de facturation cloud pour répartir les coûts par cluster, espace de nommage, pod, et conteneur, et prend en charge l’intégralité du langage NRQL.

Étant donné que les coûts des nœuds Kubernetes sont partagés entre les workloads, `KubernetesSpend` les distribue proportionnellement en utilisant `cpu_weightage` et `memory_weightage`. Multipliez `net_unblended_cost` par `(cpu_weightage + memory_weightage)` pour obtenir des totaux de coûts précis par workload. Pour une référence complète des attributs, consultez le [dictionnaire de données](/attribute-dictionary).

Exemple de requête :

```sql
FROM KubernetesSpend SELECT * SINCE 1 week ago
```

## CloudCost [#cloudcost]

<Callout variant="important">
  Nous vous recommandons d’utiliser `CloudSpend` pour toute analyse des coûts et de l’utilisation. Il fournit les mêmes données de facturation que `CloudCost` avec une prise en charge complète de NRQL.
</Callout>

`CloudCost` est un événement de synthèse généré par Intelligence Coûts du cloud à partir des rapports de coûts et d’utilisation (CUR) du fournisseur de cloud. Il fournit des données sur les lignes de facturation, y compris l’utilisation des ressources, les coûts, et les métadonnées de compte sur l’ensemble des comptes AWS et Azure, mises à jour toutes les heures. Comme `CloudCost` est pré-agrégé, il ne prend en charge qu’un sous-ensemble de clauses NRQL. Pour une flexibilité NRQL totale, utilisez `CloudSpend`.

### Attributs clés

Les attributs suivants sont les plus utiles pour créer des requêtes CloudCost :

| Attribut                       | Description                                                                                                          |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `line_item_net_unblended_cost` | Coût après remise pour la ligne de facturation, spécifique au compte individuel.                                     |
| `line_item_product_code`       | Code de service du fournisseur cloud (par exemple, `AmazonEC2` pour AWS ou `Virtual Machine Scale Sets` pour Azure). |
| `line_item_usage_account_id`   | ID de compte AWS à 12 chiffres du compte qui a utilisé cette ligne de facturation.                                   |
| `line_item_usage_account_name` | Nom d’affichage du compte cloud ou de l’abonnement.                                                                  |
| `line_item_unblended_cost`     | Coût aux tarifs à la demande standard avant toute instance réservée, plan d’économies, ou remises sur volume.        |
| `amortised_cost`               | Coût amorti incluant les frais de réservation initiale ou de plan d’épargne répartis sur la période d’utilisation.   |
| `is_k8s`                       | Indicateur précisant si le coût est associé à un workload Kubernetes.                                                |

Exemple de requête :

```sql
FROM CloudCost SELECT * SINCE 24 hours ago
```

## Coût de Kubernetes [#kubernetescost]

`KubernetesCost` est un événement de répartition des coûts généré par Intelligence Coûts du cloud. Il détaille les coûts du cloud par cluster Kubernetes, espace de nommage, pod, et conteneur. Ce type d&apos;événement ne prend en charge qu&apos;un sous-ensemble de clauses NRQL.

### Attributs clés

Les attributs suivants sont les plus utiles pour créer des requêtes KubernetesCost :

| Attribut             | Description                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `total_cost`         | Coût total, calculé comme la somme de `cpu_costs` et `memory_costs`.                                               |
| `cpu_costs`          | Part du coût attribuée à l’utilisation du CPU.                                                                     |
| `memory_costs`       | Partie du coût attribuée à l’utilisation de la mémoire.                                                            |
| `net_unblended_cost` | Coût net après remises, basé sur la part d’utilisation de la ressource dans le coût du nœud EC2 sous-jacent.       |
| `cpu_usage`          | Ratio des cœurs de CPU en cours d’utilisation par rapport aux cœurs de CPU alloués (valeur comprise entre 0 et 1). |
| `memory_usage`       | Ratio de la mémoire utilisée par rapport à la mémoire allouée (valeur comprise entre 0 et 1).                      |
| `cluster_name`       | Nom du cluster hébergeant les nœuds et les pods.                                                                   |
| `namespace_name`     | Espace de nommage Kubernetes, une séparation logique des services et des nœuds de déploiement.                     |
| `pod_name`           | Nom du pod Kubernetes, qui peut héberger un ou plusieurs conteneurs.                                               |
| `container_name`     | Nom du conteneur Docker.                                                                                           |
| `node_name`          | Nœud EC2 sur lequel le pod est déployé.                                                                            |
| `deployment_name`    | Nom du déploiement Kubernetes gérant le pod.                                                                       |

Exemple de requête :

```sql
FROM KubernetesCost SELECT * SINCE 1 week ago
```

Pour des coûts Kubernetes précis, multipliez `cpu_weightage + memory_weightage` dans vos requêtes :

```sql
SELECT SUM(net_unblended_cost * (cpu_weightage + memory_weightage) + network_net_unblended_cost) FROM KubernetesCost SINCE '2026-09-01' UNTIL '2026-09-10'
```

La requête multiplie `net_unblended_cost` par la somme de la pondération du CPU et de la mémoire pour une allocation précise des coûts basée sur l’utilisation des ressources.

<img title="Query Console showing KubernetesCost event attributes" alt="Query Console showing KubernetesCost event attributes" src="/images/kubernetes-cost-cci.webp" />

Identifiez les espaces de nommage Kubernetes les plus coûteux :

```sql
FROM KubernetesCost SELECT SUM(total_cost) FACET namespace_name SINCE 1 week ago LIMIT 10
```

Comparez le coût du CPU au coût de la mémoire par cluster :

```sql
FROM KubernetesCost SELECT SUM(cpu_costs), SUM(memory_costs) FACET cluster_name SINCE 1 week ago
```

Trouvez les conteneurs sous-utilisés où l’utilisation du processeur est faible :

```sql
FROM KubernetesCost SELECT average(cpu_usage) FACET container_name WHERE cpu_usage < 0.2 SINCE 3 days ago
```

## Estimation des coûts du cloud [#cloudcostestimate]

`CloudCostEstimate` est un événement en temps réel généré par Intelligence Coûts du cloud. Il fournit les coûts estimés du cloud au niveau des ressources, y compris les détails de l’instance AWS, et les métadonnées telles que la propriété de l’équipe, l’environnement, et le nom du service. Ce type d’événement ne prend en charge qu’un sous-ensemble de clauses NRQL.

### Attributs clés

Les attributs suivants sont les plus utiles pour créer des requêtes CloudCostEstimate :

| Attribut        | Description                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| `cost`          | Coût estimé dans la devise de votre facture de cloud pour la ressource sur la période d’utilisation.      |
| `owning_team`   | Valeur du tag `owning_team` appliqué à la ressource, s’il est présent.                                    |
| `product_code`  | Code de service du fournisseur de cloud (par exemple, `EC2`).                                             |
| `service_name`  | Le service auquel l’estimation est destinée.                                                              |
| `instance_type` | Type d&apos;instance AWS EC2 (par exemple, `m6g.8xlarge`). S&apos;applique uniquement aux ressources AWS. |
| `aws_region`    | Région AWS où la ressource est déployée (par exemple, `us-east-2`).                                       |
| `department`    | Valeur du tag `department` appliqué à la ressource, s’il est présent.                                     |
| `environment`   | Environnement de déploiement de la ressource, provenant du tag `environment` de la ressource.             |

Exemple de requête :

```sql
FROM CloudCostEstimate SELECT * SINCE 24 hours ago
```

<img title="Query Console showing CloudCostEstimate event attributes" alt="Query Console showing CloudCostEstimate event attributes" src="/images/cloud-cost-estimate.webp" />

Passez en revue les coûts estimés par équipe propriétaire :

```sql
FROM CloudCostEstimate SELECT SUM(cost) FACET owning_team SINCE 24 hours ago
```
