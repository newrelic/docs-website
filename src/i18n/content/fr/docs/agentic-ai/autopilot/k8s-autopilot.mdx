Diagnostiquez les problèmes Kubernetes sans quitter Autopilot. L&apos;agent Autopilot K8s est un sous-agent spécialisé au sein de [New Relic Autopilot](/docs/agentic-ai/autopilot/overview/). New Relic Autopilot est une interface d&apos;opérations alimentée par l&apos;IA, et l&apos;une des capacités de base au sein des opérations autonomes de New Relic. Il analyse la télémétrie, et recommande une remédiation. L&apos;agent Autopilot K8s s&apos;exécute en tant que sous-agent spécialisé au sein de [New Relic Autopilot](/docs/agentic-ai/autopilot/overview/). Vous interagissez avec un seul Autopilot unifié, qui dirige automatiquement les requêtes liées à Kubernetes vers l&apos;agent Autopilot K8s.

Au lieu d&apos;exécuter manuellement les commandes `kubectl` et de corréler les métriques sur plusieurs dashboards, l&apos;agent analyse l&apos;état de votre cluster, identifie les causes profondes, et fournit des étapes de remédiation exploitables en temps réel.

L&apos;agent K8s Autopilot est uniquement accessible via New Relic Autopilot. <DNT>Autopilot</DNT> est disponible pour les organisations disposant d&apos;une édition [Pro ou Enterprise](https://newrelic.com/pricing) avec soit :

* Le module complémentaire [Advanced Compute](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#advance-compute-capacity-unit), ou
* Un plan de calculer legacy (CCU).
</Callout>

## Principaux avantages [#benefits]

* **Analyse de la cause première des pannes Kubernetes courantes**: `CrashLoopBackOff`, `OOMKilled`, pod en attente et non planifiable, `ImagePullBackOff`, incohérences de réplicas, nombre de redémarrages élevé, pression sur les nœuds, déploiements bloqués, problèmes de DNS, de service et d’ingress, comportement HPA, et problèmes de stockage et de PVC
* **Contexte approfondi**: analyse les manifestes, les événements, les métriques de ressources, les logs, et l’historique de déploiement ensemble
* **Au-delà du cluster**: corrèle les problèmes Kubernetes avec vos services APM et avec l&apos;infrastructure cloud sur AWS et Azure, comme une instance dégradée ou une cible d&apos;équilibreur de charge défaillante
* **Conseils de remédiation**: fournit des étapes de correction spécifiques, et pas seulement une détection
* **Un clic depuis les vues Kubernetes**: les boutons <DNT>**Investigate**</DNT> dans l’interface utilisateur Kubernetes lancent une investigation avec le contexte de ce que vous consultez
* **Fonctionne avec OpenTelemetry**: exécute le même diagnostic sur les clusters monitorés avec l’ [intégration Kubernetes de New Relic](/docs/kubernetes-pixie/kubernetes-integration/get-started/introduction-kubernetes-integration/) ou avec [OpenTelemetry pour Kubernetes](/docs/kubernetes-pixie/k8s-otel/intro/)
* **Aucune instrumentation supplémentaire requise**: fonctionne avec les données Kubernetes que vous envoyez déjà à New Relic

## Comment fonctionne l’agent K8s Autopilot [#how]

Vous y accédez via Autopilot dans la barre latérale de chat de New Relic AI, ou depuis un bouton <DNT>**Investigate**</DNT> dans une vue Kubernetes. Vous pouvez décrire un problème ou saisir un prompt (par exemple, `"Why are pods in namespace X crashing?"`) pour déclencher une investigation autonome par l&apos;agent. L&apos;agent analyse l&apos;état de votre cluster, corrèle les métriques, et inspecte les manifestes et les événements pour identifier les causes profondes. Il fournit ensuite des étapes de remédiation exploitables en temps réel.

## Prérequis [#prerequisites]

* Le reporting des données Kubernetes vers New Relic, à partir soit de l’ [intégration Kubernetes](/install/kubernetes/), soit d’ [OpenTelemetry pour Kubernetes](/docs/kubernetes-pixie/k8s-otel/intro/). Plus la configuration de l’observabilité est complète (le monitoring des performances des applications (APM), le monitoring d’infrastructure, l’intégration cloud, et les données Kubernetes), plus l’analyse de l’agent est riche.
* New Relic [Autopilot activé et configuré](/docs/agentic-ai/autopilot/setup) sur votre compte.

## Comment utiliser l’agent K8s Autopilot [#usage]

Une fois qu&apos;Autopilot est activé sur votre compte, vous pouvez commencer à utiliser Autopilot K8s Agent pour analyser votre environnement Kubernetes et investiguer les incidents. Il existe trois façons d&apos;y accéder :

* **Demandez directement à Autopilot** dans la barre latérale de chat de New Relic AI.
* **Commencez à partir d’un bouton Investigate** dans une vue Kubernetes. Voir [Commencer à partir d’une vue Kubernetes](#investigate).
* **À partir des alertes :** lorsqu&apos;un workflow d&apos;alerte envoie un problème à Autopilot et que l&apos;investigation implique des ressources Kubernetes, Autopilot appelle automatiquement Autopilot K8s Agent dans le cadre de son analyse. Aucune configuration supplémentaire n&apos;est nécessaire au-delà de votre [configuration d&apos;alerte Autopilot](/docs/agentic-ai/autopilot/setup) existante.

### Commencer à partir d&apos;une vue Kubernetes [#investigate]

Les pages Kubernetes dans New Relic incluent des boutons qui ouvrent Autopilot avec un prompt prêt à l’emploi. Le prompt inclut déjà le cluster, l’espace de nommage, l’entité, et le statut que vous consultez, vous n’avez donc pas besoin de les saisir.

### Conseils d&apos;utilisation [#tips]

Autopilot dirige les prompts vers le moteur de diagnostic Kubernetes spécialisé en fonction des mots-clés et du contexte intégrés dans votre requête.

Pour vous assurer que votre question parvient à Autopilot K8s Agent :

* **Utilisez « K8s » ou « Kubernetes » dans votre prompt :** inclure l&apos;un de ces mots est le signal le plus fiable pour diriger votre question vers l&apos;agent Autopilot K8s.

* **Soyez précis avec la terminologie Kubernetes :** incluez des termes spécifiques à Kubernetes tels que `pod`, `node`, `namespace`, `deployment`, `replica`, `container`, `cluster`, `workload`, `CrashLoopBackOff`, `OOMKilled`, `PVC`, `HPA`, et d’autres.

  Par exemple:

  | Moins efficace        | Plus efficace                                                       |
  | :-------------------- | :------------------------------------------------------------------ |
  | `Why is my app slow?` | `Why are pods in namespace payments restarting?`                    |
  | `Something is broken` | `Pod checkout-service in cluster prod-east is in CrashLoopBackOff`  |
  | `Fix my deployment`   | `Deployment api-gateway has replica mismatch in namespace frontend` |
  | `Check my cluster`    | `What's the health of my Kubernetes cluster prod-east-1?`           |

* **Ajoutez du contexte si possible**

  * Mentionnez le nom du cluster, l&apos;espace de nommage, le nom du pod/déploiement, ou le nœud.
  * Décrivez les symptômes en utilisant des termes d&apos;état précis, tels que `"Pending"`, `"Evicted"`, `"ImagePullBackOff"`.
  * Définissez des fenêtres de temps explicites lorsque cela est pertinent. Par exemple, `"since last rollout"`, `"in the last hour"`.

* **Collez vos propres preuves :** vous pouvez coller la sortie `kubectl describe`, un log, ou un message d’erreur dans le prompt. L’agent les analyse conjointement avec vos données New Relic.

* **Tirez parti du routage automatique de l’interface utilisateur :** lorsque vous ouvrez Autopilot depuis une page Kubernetes dans New Relic, y compris les [boutons d’investigation](#investigate), il dirige automatiquement les requêtes vers l’agent Autopilot K8s sans nécessiter de mots-clés explicites. L’agent reçoit les métadonnées contextuelles directement depuis la vue active de l’interface utilisateur.

  <Callout variant="tip" title="Vérifier le routage de l'agent">
  Vous pouvez confirmer que votre requête a été traitée par Autopilot K8s Agent en développant **Show reasoning** dans la réponse de l&apos;agent. Si elle est acheminée correctement, vous verrez des références à l&apos;assistant Autopilot K8s Agent aux côtés des outils de diagnostic Kubernetes invoqués (tels que l&apos;analyse de cluster, l&apos;inspection de manifeste, ou la corrélation d&apos;événements). Si vous ne voyez pas de raisonnement spécifique à Kubernetes, essayez de reformuler avec des mots-clés Kubernetes plus explicites.
  </Callout>

## Confidentialité et sécurité [#privacy]

L’agent analyse uniquement les données télémétriques déjà ingérées dans votre compte New Relic. Il n’accède pas directement à votre cluster, n’exécute pas de commandes, ou ne lit pas les secrets Kubernetes. Les étapes de remédiation sont des suggestions que vous passez en revue et exécutez vous-même, et toute commande suggérée qui modifie des ressources inclut `--dry-run=client` afin que vous puissiez d’abord vérifier son effet.

Toutes les interactions sont soumises aux permissions existantes de votre compte New Relic et aux contrôles d’accès aux données.
