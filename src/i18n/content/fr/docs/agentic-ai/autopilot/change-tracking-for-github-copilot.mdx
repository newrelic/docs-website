<Callout title="Aperçu">
Nous travaillons toujours sur cette fonctionnalité, mais nous aimerions que vous l&apos;essayiez !

Cette fonctionnalité est actuellement fournie dans le cadre d&apos;un programme d&apos;aperçu conformément à nos [politiques de pré-sortie](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

<DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitore votre service après chaque déploiement que vous avez configuré pour le monitoring. <DNT>Autopilot</DNT> vérifie l’état de santé du service à des points de contrôle planifiés, commente la demande de tirage, et rapporte les résultats dans <DNT>Slack</DNT> si vous l’avez connecté. S’il détecte une régression, il ouvre également un ticket <DNT>GitHub</DNT> assigné à <DNT>GitHub Copilot</DNT>, qui peut proposer un correctif sous forme de demande de tirage si votre organisation dispose de <DNT>GitHub Copilot Enterprise</DNT>.

<Callout variant="important">
<DNT>New Relic Change Tracking for GitHub Copilot</DNT> nécessite un jeton <DNT>GitHub</DNT> avec accès en écriture en plus de l’accès en lecture que décrit [Connect Autopilot to GitHub](/docs/agentic-ai/autopilot/connect-to-github). Ajoutez les autorisations d’écriture au jeton que vous avez déjà connecté, ou connectez un nouveau jeton qui les possède toutes.
</Callout>

Chaque déploiement configuré pour le monitoring passe par ces étapes :

1. Vous fusionnez la demande de tirage, et votre pipeline la déploie. Le déploiement envoie un événement au suivi des changements qui inclut l’URL du tag de sortie, le SHA du commit de fusion, et l’attribut `watchpoint_monitoring`.
2. <DNT>Autopilot</DNT> valide l’événement. En cas de réussite, <DNT>Autopilot</DNT> commente la demande de tirage fusionnée, et, si vous avez connecté <DNT>Slack</DNT>, publie un message &quot;monitoring démarré&quot;.
3. À chaque point de contrôle, <DNT>Autopilot</DNT> compare les métriques du service après le déploiement avec les métriques avant celui-ci. Il signale l’un des trois résultats (aucune régression, non concluant, ou régression détectée) sous forme de commentaire sur la demande de tirage, et, si vous avez connecté <DNT>Slack</DNT>, comme réponse dans le même fil de discussion. Les points de contrôle sont exécutés 10 min, 30 min, 1 h, 2 h, 24 h, et 72 h après le déploiement.

Lorsqu’un point de contrôle détecte une régression, <DNT>Autopilot</DNT> fait trois choses :

* Publie une réponse dans le fil de discussion <DNT>Slack</DNT> (si vous avez connecté <DNT>Slack</DNT>) avec les métriques pertinentes, et les preuves à l’appui de la découverte.
* Commente la demande de tirage avec les métriques pertinentes, le point de contrôle qui a détecté la régression, et la raison.
* Ouvre un ticket <DNT>GitHub</DNT> qui décrit ce qui a régressé, les preuves à l&apos;appui, où chercher, et les critères d&apos;acceptation, puis assigne le ticket à <DNT>GitHub Copilot</DNT>.

Si <DNT>Copilot</DNT> propose un correctif, examinez-le comme vous le feriez pour n’importe quelle autre demande de tirage avant de la fusionner.

## Prérequis [#prerequisites]

Avant de configurer <DNT>New Relic Change Tracking for GitHub Copilot</DNT>, confirmez ce qui suit :

* Vous avez configuré <DNT>Autopilot</DNT>. Consultez [Configurer Autopilot](/docs/agentic-ai/autopilot/setup).

* Vous êtes un <DNT>**New Relic Organization Manager**</DNT>, et vous avez opté pour <DNT>**New Relic Change Tracking for GitHub Copilot**</DNT> à <DNT>**[one.newrelic.com &gt; Administration](https://one.newrelic.com/admin-portal) &gt; Preview &amp; Trials**</DNT>.

* Vous avez un compte <DNT>GitHub</DNT> et un jeton avec un accès en écriture aux référentiels que vous souhaitez monitorer.

* Vos déploiements envoient des événements au [suivi des changements](/docs/change-tracking/overview) avec la [mutation `changeTrackingCreateEvent` ](/docs/change-tracking/config/nerdgraph). <DNT>New Relic Change Tracking for GitHub Copilot</DNT> ne prend pas en charge le point de terminaison legacy.

* Chaque événement comprend les éléments suivants :

  * L’URL du tag de sortie dans le champ `changelog`.
  * Le SHA du commit de fusion dans le champ `commit`.
  * L’attribut personnalisé `watchpoint_monitoring` défini sur `"true"`, pour chaque déploiement que vous souhaitez monitorer.

* Le service transmet des données à New Relic, et possède au moins 3 jours d&apos;historique. Avec moins de données, chaque point de contrôle renvoie un résultat non concluant.

En option, [connectez Autopilot à Slack](/docs/agentic-ai/autopilot/connect-to-slack) pour recevoir des notifications. Pour que <DNT>Copilot</DNT> commence automatiquement à travailler sur le problème, votre organisation a besoin de <DNT>GitHub Copilot Enterprise</DNT>.

## Configurer le suivi des changements New Relic pour GitHub Copilot [#setup]

<Steps>
<Step>
### Créer un jeton GitHub [#create-token]

Créez un jeton d’accès personnel dans <DNT>GitHub</DNT>. Un jeton à granularité fine est recommandé, mais un jeton classique fonctionne également. Pour obtenir des instructions, consultez [Création d’un jeton d’accès personnel à granularité fine](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token) dans la documentation de <DNT>GitHub</DNT>. Assurez-vous que le jeton possède les éléments suivants :

* Votre organisation <DNT>GitHub</DNT> en tant que propriétaire de sa ressource.
* Accès aux référentiels que vous souhaitez que <DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitore.
* <DNT>**Read and write**</DNT> accès à <DNT>**Pull requests**</DNT>, <DNT>**Issues**</DNT>, et <DNT>**Contents**</DNT>.

Si vous avez déjà connecté <DNT>GitHub</DNT> à <DNT>Autopilot</DNT>, et que vous possédez déjà un jeton, vous pouvez plutôt ajouter ces autorisations à ce jeton.

Si votre organisation applique le SSO SAML, autorisez le jeton pour le SSO. <DNT>GitHub</DNT> n’affiche le jeton qu’une seule fois, donc lors de sa génération, copiez-le, et collez-le immédiatement dans New Relic.
</Step>

<Step>
### Connectez GitHub et activez le monitoring [#enable]

Pour ouvrir la configuration <DNT>Autopilot</DNT>, cliquez sur <DNT>**Ask AI**</DNT>, cliquez sur **...**, puis cliquez sur <DNT>**Configure**</DNT>.

<img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp" />

Dans <DNT>**External MCP connections**</DNT>, connectez <DNT>**GitHub**</DNT> (<DNT>**Public GitHub**</DNT> ou <DNT>**GitHub Enterprise Cloud**</DNT>) avec votre jeton et le nom de votre organisation, puis activez <DNT>**Enable deployment monitoring**</DNT>. Pour recevoir une notification, sélectionnez également un canal <DNT>Slack</DNT> dans <DNT>**Post alerts to**</DNT>. Cette option n&apos;apparaît qu&apos;après que vous avez connecté <DNT>Slack</DNT> à <DNT>Autopilot</DNT>.

Cliquez sur <DNT>**Update agent**</DNT> pour enregistrer vos modifications.
</Step>

<Step>
### Confirmez que le monitoring a démarré [#verify]

Déployez une modification avec l’attribut `watchpoint_monitoring` défini sur `"true"`.

<CollapserGroup>
<Collapser id="example-event" title="Exemple d’événement de déploiement">
```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "MERGE_COMMIT"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```
</Collapser>
</CollapserGroup>

Après que <DNT>Autopilot</DNT> a validé l’événement de déploiement, vous voyez :

* Un commentaire de <DNT>Autopilot</DNT> sur la demande de tirage fusionnée.
* Si vous avez connecté <DNT>Slack</DNT>, un message &quot;monitoring démarré&quot; dans le canal que vous avez sélectionné. Les résultats des points de contrôle ultérieurs apparaissent sous forme de réponses dans ce fil de discussion.

Si aucun des deux n’apparaît, vérifiez que l’événement de déploiement répond aux [prérequis](#prerequisites).
</Step>
</Steps>
