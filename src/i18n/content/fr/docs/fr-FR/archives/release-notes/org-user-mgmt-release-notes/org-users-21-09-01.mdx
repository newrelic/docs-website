Notre API de système de gestion des identités inter-domaines (SCIM) prend désormais en charge la gestion du [type d&apos;utilisateur](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type) des utilisateurs. Cela permet aux clients Enterprise ayant des utilisateurs sur notre nouveau modèle d&apos;utilisateur de gérer le type d&apos;utilisateur via leur fournisseur d&apos;identité (IdP) ou toute intégration personnalisée prenant en charge SCIM. Cela est particulièrement utile pour provisionner des utilisateurs en tant que basiques ou complets (au lieu de toujours provisionner les utilisateurs en tant que complets), ainsi que pour la mise à niveau et la rétrogradation automatiques dans le cadre de la [politique de facturation](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#user-count) de New Relic de deux rétrogradations par utilisateur par période de douze mois glissants.

La sortie inclut [un tutoriel SCIM](/docs/accounts/accounts/automated-user-management/tutorial-manage-users-groups-scim) et la possibilité pour les administrateurs d’ajouter un message personnalisé et/ou une URL à la page de mise à niveau autonome qui communique le processus de demande de mise à niveau spécifique aux clients pour les clients qui gèrent le type d’utilisateur via l’API.

Nous avons des instructions pour activer cela avec notre [intégration Okta](/docs/accounts/accounts/automated-user-management/okta-scimsso-application-configuration/) prédéfinie. Actuellement, nous n’avons pas d’instructions étape par étape pour nos intégrations OneLogin ou Azure AD. Si vous utilisez l’une d’entre elles, vous devrez configurer votre fournisseur d’identité pour envoyer un nouvel attribut, [`nrUserType`](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type).

* Nos [instructions de l’API SCIM concernant le type d’utilisateur](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type).
