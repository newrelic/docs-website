### Nouvelle fonctionnalité

***Plus de flexibilité pour les déploiements de conteneurs***

* Le daemon et l&apos;application instrumentée ne doivent plus nécessairement résider sur le même hôte et peuvent désormais communiquer via un socket TCP IPv4 ou IPv6. Pour l&apos;application instrumentée, cela peut être configuré via l&apos;argument `daemon_socket` de la fonction `newrelic_init`. Pour le daemon, cela peut être configuré via l&apos;option de ligne de commande `--address`.
* Lors de l’arrêt du daemon via le signal `SIGTERM` (et/ou le signal `SIGINT` s’il a été démarré avec l’indicateur `-f`, `--foreground`), le daemon enverra désormais toutes les données mises en mémoire tampon à New Relic avant de se fermer.
* Le daemon a introduit une nouvelle configuration `--watchdog-foreground`. Cela maintient le processus de surveillance du daemon au premier plan, tandis que la configuration `--foreground` maintient le processus de travail du daemon au premier plan. La nouvelle configuration permet d&apos;utiliser le daemon de manière bloquante, sans perdre la stabilité supplémentaire fournie par le processus de surveillance.
* Le SDK C offre désormais `newrelic_set_transaction_name` avec lequel les utilisateurs peuvent modifier le nom d&apos;une transaction déjà démarrée.

### Débogage

* Le daemon gère désormais de manière synchrone les chemins de code critiques liés à la collecte et à la fusion des données de transaction. Cela empêche les plantages causés par les conditions de concurrence.

### Avis de mise à jour

* Le daemon a introduit une nouvelle configuration `--address` qui sert d&apos;alias à `--port`. Les clients peuvent utiliser l&apos;un ou l&apos;autre pour spécifier l&apos;emplacement du daemon. Si les deux valeurs sont définies, `--address` a la priorité.

* Lors du démarrage du daemon, il attendra désormais jusqu&apos;à trois secondes que le port d&apos;écoute soit prêt à recevoir des connexions avant de passer en arrière-plan. Cela se produit généralement en (beaucoup) moins d&apos;une seconde, et la plupart des utilisateurs avec cette configuration ne remarqueront aucune différence dans la pratique.

  Le temps d’attente du daemon peut être contrôlé en définissant le paramètre `--wait-for-port` avec une durée. Cette durée peut être de 0 pour éviter tout blocage. Si l’option est omise, la valeur par défaut est `3s`.

  Les daemons démarrés en mode premier plan (avec le flag `--foreground`) ne sont pas affectés, et se comporteront comme avant.
