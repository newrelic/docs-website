Cette page décrit l’approche de l’équipe de documentation pour documenter les exemples OpenTelemetry.

## Arrière-plan [#background]

Dans la documentation de New Relic pour OpenTelemetry (OTel), nous fournissons des exemples de monitoring de l’IA pour démontrer la configuration la plus courante que nous attendons de l’utilisateur. Historiquement, le site de documentation contenait ces exemples sur le site de documentation. Cependant, en mai 2024, lors d’un effort conjoint avec les Relics travaillant sur OTel, nous avons décidé de migrer ces exemples du site de documentation vers le référentiel (repository) [newrelic-opentelemetry-examples](https://github.com/newrelic/newrelic-opentelemetry-examples/tree/main). Par exemple, voici une PR où nous avons déplacé tous les exemples d’infrastructure : [PR n° 17742](https://github.com/newrelic/docs-website/pull/17742).

## Pourquoi nous soutenons ce changement [#why-we-support-this-change]

Les raisons de cette migration sont :

* Réduisez la redondance à la fois dans le référentiel (repository) et sur le site de documentation : conserver plusieurs copies encourage (et garantit presque) des sources de vérité divergentes et la dégradation des données.
* Facilitez la consommation des exemples : écrire des exemples avec du texte, comme « Mettez le contenu X dans un fichier appelé Y », est une mauvaise expérience pour les développeurs car cela prend du temps et est sujet aux erreurs. Il est bien préférable de cloner un référentiel (repository), de mettre à jour une ou deux variables d’environnement et d’exécuter une commande.
* L’accent est mis sur des exemples de code fonctionnels pour une utilisation en interne et en externe : en interne, les données de ces exemples sont la source de vérité sur laquelle nous construisons des expériences produit. En externe, ces exemples sont la source de vérité sur la façon dont vous faites une chose particulière avec New Relic et OpenTelemetry (éloignez-vous de ce chemin et les résultats peuvent varier).
* Réduisez la charge de maintenance : les équipes OTel et de documentation sont toutes deux petites, avec une grande surface à couvrir.

## Comment nous gérons les requests pour les futurs exemples OTel [#how-we-handle-requests]

À l’avenir, tous les exemples OTel seront créés et maintenus dans le référentiel (repository) [newrelic-opentelemetry-examples](https://github.com/newrelic/newrelic-opentelemetry-examples/tree/main), avec une référence mentionnée sur le site de documentation.

Pour proposer un nouvel exemple (conformément aux [directives de contribution](https://github.com/newrelic/newrelic-opentelemetry-examples/tree/main?tab=readme-ov-file#contribute)), veuillez suivre ces étapes :

1. Ouvrez un ticket pour en discuter : avant de soumettre une demande de tirage, ouvrez un ticket dans le référentiel [newrelic-opentelemetry-examples](https://github.com/newrelic/newrelic-opentelemetry-examples/tree/main). Cela permet à l&apos;équipe OTel d&apos;en discuter et de s&apos;assurer que votre exemple correspond aux domaines d&apos;intervention de l&apos;équipe.

2. Démontrez une valeur mesurable : notre objectif se concentre sur des exemples qui se traduisent directement par le succès de l&apos;utilisateur. Idéalement, ceux-ci mettront en évidence :

   * Dashboards exploitables : l’exemple doit fournir un dashboard prêt à l’emploi pour visualiser vos données.
   * Expériences organisées : en allant au-delà des dashboards, envisagez d’inclure une synthèse d’entité préconfigurée ou d’autres éléments qui améliorent la proposition de valeur.
