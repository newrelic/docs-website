Swiftype est le moteur de recherche basé sur Elastic qui alimente la recherche dans `docs.newrelic.com`.

En tant que rédacteur technique chez New Relic, vous devrez peut-être vous connecter à Swiftype et effectuer diverses tâches pour vous assurer que vos documents sont reconnus lors des recherches internes.

## Informations sur le robot d&apos;exploration Swiftype [#crawler-info]

Le robot d’indexation indique qu’il effectue une exploration toutes les 12 heures. La vitesse à laquelle il explore est relativement lente, ce qui signifie que la prise en compte des modifications de page pourrait prendre plus de temps. Il utilise également une combinaison de `sitemap.xml` et de collecte de liens lors de l’exploration.

Nous pouvons déclencher une exploration manuelle une fois toutes les 12 heures, si nécessaire. Ou, nous pouvons demander à Swiftype d&apos;explorer des pages spécifiques si nécessaire.

Le temps moyen de réindexation des documents est de quatre jours.

## Ajouter manuellement une nouvelle page à l&apos;index Swiftype [#manually-index]

Vous pouvez ajouter manuellement une nouvelle page à l&apos;index Swiftype lorsque l&apos;exploration est trop lente et que vous souhaitez que la page soit disponible immédiatement.

Pour ajouter manuellement une nouvelle page dans Swiftype :

1. Assurez-vous que votre type de document n&apos;est pas dans la liste à ignorer en allant dans **Domains &gt; [https://docs.newrelic.com/](https://docs.newrelic.com/)**.

2. Accédez à **New Relic &gt; Content**.

3. Dans la zone de saisie de texte indiquant **Filter pages**, collez l’URL de la page que vous souhaitez indexer.

4. Si la page n’est pas dans l’index, Swiftype fournira l’option **Add this URL**. Cliquez sur cette option pour ajouter la page à l’index.

5. Insérez l’URL, en vous assurant de faire ce qui suit :

   * Utilisez l&apos;URL complète comme ceci : `https://docs.newrelic.com/docs/path/to/doc/`
   * Assurez-vous que l&apos;URL se termine par une barre oblique

Swiftype devrait l&apos;indexer en une minute environ. Pour vérifier si elle est indexée, actualisez la page et collez l&apos;URL. Notez que parfois l&apos;interface d&apos;administration est mise en cache ou présente des décalages. Vous pouvez demander à un collègue de vérifier, utiliser l&apos;API REST pour vérifier, vider le cache ou recharger la page et vérifier à nouveau.

## Mettre à jour manuellement l’enregistrement Swiftype existant [#manual-index]

De la même manière que pour l’ajout manuel d’une nouvelle page à l’index, vous pouvez mettre à jour un enregistrement existant si l’exploration est trop lente et que vous souhaitez que l’index soit mis à jour immédiatement. Utilisez cette méthode si vous avez modifié l’URL d’une page et que l’ancienne URL est redirigée vers la nouvelle. Pour une discussion approfondie à ce sujet, consultez la section [modification des URL](#url-changes) ci-dessous.

Pour mettre à jour ou réindexer manuellement un enregistrement existant :

1. Accédez à **New Relic &gt; Content**.
2. Collez l&apos;ancienne URL (celle avec laquelle la page a été indexée pour la dernière fois).
3. S’il se trouve dans l’index, vous devriez voir l’entrée correspondante, alors sélectionnez **Détails**.
4. Sur la page des détails de l’enregistrement, sélectionnez **Réindexer**.
5. Ajoutez à nouveau le classement pour ce document en suivant les étapes de la section [Classer les résultats pour un terme de recherche donné](#rank-results).

Swiftype devrait se réindexer en une minute. Notez que cet enregistrement sera supprimé de l’index, ainsi que tous les classements personnalisés que vous avez définis pour lui, et qu’un nouvel enregistrement est créé pour la nouvelle URL vers laquelle le robot d’exploration a été redirigé. Soyez donc prêt à mettre à jour les classements des résultats.

## Supprimer manuellement l&apos;enregistrement swiftype existant [#remove-records]

Vous pouvez souhaiter supprimer manuellement un enregistrement existant de l’index dans ces cas :

* Lorsque vous souhaitez supprimer rapidement un enregistrement pour une page qui a été supprimée sans redirection
* Si vous remarquez qu&apos;il y a plus d&apos;un enregistrement pour une page dont l&apos;URL a changé récemment (un pour l&apos;ancienne URL, un pour la nouvelle qui a été découverte en dehors de la redirection).

Pour supprimer manuellement un enregistrement de l’index :

1. Accédez à **New Relic &gt; Content**.
2. Collez l’URL de l’enregistrement que vous souhaitez supprimer.
3. Sélectionnez **Détails**.
4. Sélectionnez **Supprimer ce document** au bas de la page **Détails**.

## Classer les résultats pour un terme de recherche donné [#rank-results]

Classez les résultats pour des termes de recherche donnés afin de déplacer certaines pages plus haut ou plus bas dans les résultats. Vous pouvez également exclure un enregistrement des résultats pour un terme de recherche donné.

Étant donné que les pages de tous nos sites Web sont gérées par un seul moteur, cela encombre la liste de classement. Il est préférable de rechercher des URL spécifiques au lieu de parcourir les URL des pages pertinentes.

<Callout variant="tip">
  Si une URL change pour un enregistrement donné, le classement des résultats est perdu et doit être ajouté pour le nouvel enregistrement associé à la nouvelle URL.
</Callout>

Pour classer les résultats :

1. Allez dans **New Relic &gt; Result Rankings**.
2. Saisissez le terme de recherche dans la saisie de texte pour lequel vous souhaitez vous classer (la casse n’a pas d’importance).
3. Faites glisser les résultats plus haut ou plus bas. Vous voudrez probablement rechercher l’URL de la page, l’épingler et la déplacer.
4. Supprimez un résultat en sélectionnant le bouton **X** sur le résultat.

Pour plus de détails, consultez la [documentation officielle de Swiftype](https://swiftype.com/documentation/site-search/guides/result-rankings).

## Ajouter un alias [#add-alias]

Lorsque vous définissez un classement des résultats, vous pouvez également ajouter des alias. Un alias est similaire à un [synonyme](#add-synonym), mais n&apos;est applicable qu&apos;à un ensemble de résultats spécifique.

Pour ajouter des alias :

1. Allez dans **New Relic &gt; Result Rankings**.
2. Saisissez le terme de recherche.
3. Ajoutez l’alias dans la saisie de texte.

## Ajouter un synonyme [#add-synonym]

Ajoutez des synonymes lorsque vous souhaitez qu’un terme de recherche affiche les mêmes résultats qu’un autre. Les exemples précédents incluent :

* RBAC = contrôles d’accès basés sur les rôles
* servers = New Relic Infrastructure

Pour ajouter des synonymes, allez dans **New Relic &gt; Synonyms**.

Pour plus d’informations, consultez la [documentation officielle](https://swiftype.com/documentation/site-search/guides/synonyms).

## Bonne pratique : termes de recherche importants [#important-search-terms]

Nous voulons probablement nous assurer que les résultats sont classés et précis pour les termes de recherche qui sont :

* Connu pour être vraiment vague avec des résultats parasites (exemple : navigateur)
* Les termes de recherche les plus populaires sur notre site
* Termes du glossaire

## Meilleure pratique : changements d&apos;URL [#url-changes]

Si l&apos;URL d&apos;une page déjà indexée est modifiée, Swiftype supprimera l&apos;enregistrement associé à l&apos;ancienne URL. Et, s&apos;il existe une redirection vers une nouvelle URL, Swiftype créera un nouvel enregistrement pour la page associée à la nouvelle URL. Lorsque cela se produit, les classements des résultats pour l&apos;ancien enregistrement sont perdus et doivent être rajoutés pour le nouvel enregistrement avec la nouvelle URL.

Le déclenchement d&apos;une nouvelle exploration dans Swiftype finira par résoudre ce problème, mais cela peut prendre beaucoup de temps. Vous pouvez également supprimer des résultats spécifiques pour les anciennes pages, et lui indiquer manuellement d&apos;indexer les nouvelles. Cela *devrait* être synchronisé avec `docs-library-service` lors de sa prochaine mise à jour de son cache pour un terme de recherche donné.
