title: Créez du contenu pour le site de documentation en prévisualisation
translationType: machine

Le site de documentation en préversion héberge la documentation des prochaines fonctionnalités que nous partageons avec les clients. Contrairement au site de documentation public, le site de documentation en préversion n’est pas modifiable publiquement et n’apparaît pas dans les résultats des moteurs de recherche. Les utilisateurs ne peuvent pas naviguer d’un document en préversion à un autre, car le site n’est pas indexé.

Étant donné que le site de prévisualisation de la documentation est situé dans un référentiel différent de celui du site public, la contribution est un peu différente. À la fin de ce document, vous serez prêt à créer un nouveau document pour le site de prévisualisation.

## Configurer votre environnement local [#do-first]

Si vous avez déjà cloné le référentiel (repository) beta-docs-site sur votre ordinateur, passez à l’étape 3.

1. Allez à [`beta-docs-site repo`](https://github.com/newrelic/beta-docs-site). Si vous n&apos;y avez pas accès, contactez le canal Slack #doc-eng-help pour obtenir de l&apos;aide.
2. Clonez le référentiel (repository) beta-docs-site sur votre ordinateur.
3. Assurez-vous de travailler dans le bon référentiel (repository) sur Github Desktop.
4. Créez une branche à partir de la branche `main`.

## Créer un nouveau document d&apos;aperçu [#create-docs]

Malgré les différences entre les sites de documentation publics et en prévisualisation, le formatage et la syntaxe de leur contenu sont en grande partie les mêmes. Une fois que vous êtes dans votre branche de travail :

1. À l’aide de votre éditeur de texte, créez un nouveau fichier `.mdx` ou copiez un document de prévisualisation existant pour le modèle d’en-tête.
2. Enregistrez le fichier dans `/src/content/docs/`.
3. Rédigez votre contenu, en vous assurant d’inclure toute information sur l’inscription et la demande d’accès à la fonctionnalité en aperçu que vous documentez.
4. Validez vos modifications et créez une demande de tirage.
5. Partagez le lien d’aperçu avec les réviseurs et mettez en œuvre leurs commentaires.
6. Fusionnez la PR finale.
7. Créez le lien officiel en collant le nom du chemin d’accès au fichier après `https://docs-preview.newrelic.com/docs/` (par exemple : `https://docs-preview.newrelic.com/docs/new-feature-name`)
8. Fournissez aux réviseurs le lien officiel à partager avec les clients.

## Texte standard facultatif [#boiler-plate]

Lors de la rédaction d’une documentation pour la prévisualisation, vous souhaiterez peut-être inclure un [encadré](/docs/style-guide/formatting/callouts/) avec un texte standard en haut de la documentation. Ce texte peut être utilisé pour orienter votre lecteur, en lui fournissant des informations importantes sur la disponibilité de la fonctionnalité et les coordonnées pertinentes.

Par exemple, le texte standard d&apos;un document d&apos;aperçu pourrait être :

<Callout variant="caution" title="Aperçu">
  Cette fonctionnalité est sortie le 1er janvier 202X et est en version préliminaire. Pour y avoir accès, contactez votre responsable de compte.
</Callout>

Vous pouvez exclure le texte standard si les informations sont trop longues, incluses ailleurs sur la page ou non pertinentes pour le document.

## Directives supplémentaires pour les contributeurs internes [#internal-contributors]

En tant que contributeur interne cherchant à modifier un aperçu de documentation, vous aurez besoin d’accéder au référentiel (repository) beta-docs-site. Si vous n’y avez pas accès, demandez au canal Slack #doc-eng-help de vous ajouter en tant que contributeur. Une fois que vous y avez accès, créez votre propre branche à partir de la branche `main` et apportez-y vos modifications.
