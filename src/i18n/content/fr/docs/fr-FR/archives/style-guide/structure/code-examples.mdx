## Formatage de code en ligne [#inline-code]

Pour formater du code en ligne (comme `maxSampleTimes` ou `TransactionError`), entourez le texte avec des caractères d’accent grave `` ` ``.

## Blocs de code multilignes [#code-block]

Pour formater une ou plusieurs lignes de code, insérez trois backticks ( ` ``` ` ) au-dessus et en dessous de votre code. Cela agit essentiellement comme le tag HTML `<pre>`.

Lorsque vous intercalez vos snippets de code entre trois backticks, vous devez tenir compte à la fois de l’indentation du code et de la coloration syntaxique.

### Indentation stricte [#strict]

En tant que rédacteur technique, on vous fournira des snippets de code dans divers langages. Pour faciliter la compréhension des snippets de code par vos lecteurs, assurez-vous que les lignes sont indentées et regroupées de manière utile.

Certains langages de programmation et de balisage nécessitent une indentation spécifique (par exemple, Python et YAML). Vérifiez auprès de votre expert en la matière si vous n&apos;êtes pas sûr que le snippet qui vous a été fourni nécessite une indentation spécifique pour fonctionner. Vous pouvez toujours passer le snippet dans un embellisseur de code en ligne s&apos;il est brouillé lorsque vous le transférez depuis un autre outil d&apos;édition.

Voici un exemple de code Python qui ne fonctionnera plus si vous modifiez l&apos;indentation :

```python
import newrelic.agent
newrelic.agent.initialize('newrelic.ini') #This is required!

def greet(name):
    """
    This function says hello to
    the person who is passed in as
    a parameter
    """
    print("Hello, " + name + " and the world!")


def execute_task(application, task_name):
    with newrelic.agent.BackgroundTask(application, name=task_name, group='Task'):
        greet("Robert")

application = newrelic.agent.register_application(timeout=10)
execute_task(application, "bar")
newrelic.agent.shutdown_agent(timeout=10)

```

### Indentation non stricte [#casual]

Pour les langages à format libre, qui sont peu stricts sur l’indentation, nous vous recommandons de rechercher des exemples similaires et de suivre ces modèles. Java et SQL sont des exemples de langages à format libre.

### Comment formater NRQL [#NRQL]

NRQL est un langage de requête de forme libre, ce qui signifie qu’il n’a pas de règles d’indentation strictes. Nous vous recommandons de suivre quelques directives simples pour faciliter la lecture. Nos suggestions sont vaguement basées sur certaines directives de formatage SQL.

Vous pouvez utiliser votre propre jugement pour décider si ces directives s&apos;appliquent à votre snippet :

* Mettez en majuscule les mots-clés de clause tels que `FROM`, `SELECT`, `FACET`, `WHERE`, `AND`, `OR`, `AS`, `SINCE`, `ORDER BY`, `TIMESERIES`, `EXTRAPOLATE` et `AUTO`.

* Ne mettez pas de majuscule aux fonctions, telles que `min()`, `max()`, `average()`, `percentile()`, `sum()` et `stddev()`, car le générateur de requêtes ne met pas automatiquement de majuscule à ces noms. Si vous n’êtes pas sûr qu’un mot-clé soit une fonction, consultez la [référence NRQL](/docs/query-your-data/nrql-new-relic-query-language/get-started/nrql-syntax-clauses-functions/#functions).

* La première ligne doit commencer par une clause `FROM`, même si les requêtes s&apos;exécutent correctement lorsque vous commencez par `SELECT`.

* Justifiez à gauche les mots-clés de la clause, sauf dans les cas suivants :

  * Si un mot-clé de clause est étroitement lié à un mot-clé précédent (par exemple, `AGO` est étroitement lié à `SINCE`), il se place sur la même ligne.
  * Si un mot-clé de clause n&apos;a pas de modificateurs (il est autonome), vous pouvez l&apos;ajouter à la fin d&apos;une ligne qui contient déjà des mots-clés (par exemple, `TIMESERIES`, `AUTO` et `EXTRAPOLATE`).
    ```sql
    FROM Transaction
    SELECT count(*)
    WHERE appName='interestingApplication'
    SINCE 60 minutes AGO EXTRAPOLATE
    ```

* Pour les mots-clés à l&apos;intérieur de parenthèses qui s&apos;étendent sur plusieurs lignes, indentez-les de deux espaces. Par exemple, le mot-clé `WHERE` est indenté de deux espaces comme ceci :
  ```sql
  FROM PageView
  SELECT count(*)
  FACET CASES
  (
    WHERE duration < 1,
    WHERE duration > 1 AND duration < 10,
    WHERE duration > 10
  )
  ```

## Mise en évidence de lignes de code [#highlight-code]

Pour mettre en évidence des lignes entières de code dans un bloc de code, vous pouvez utiliser `lineHighlight=` pour indiquer les lignes spécifiques que vous souhaitez mettre en évidence. Vous faites cela au même endroit où vous notez la syntaxe. Voici un exemple de bloc de code avec la première ligne et les lignes trois à cinq mises en évidence :

```js lineHighlight=1,3-5
const coolThing = {
  key: 'HI',
  tada: 'hello'
}
// this is an important object
// other notes...
```

## Espaces réservés pour les variables spécifiques aux clients [#value-placeholders]

Parfois, nous voulons utiliser des espaces réservés pour des variables dont la valeur dépendra des clients ou de la situation. Par exemple, vous pourriez avoir besoin d’utiliser `YOUR_ACCOUNT_ID` pour indiquer un espace réservé où les clients sont censés saisir leur ID de compte New Relic.

Quelques exigences et conseils sur la création d&apos;espaces réservés de valeurs spécifiques aux clients :

* Utilisez des majuscules et des traits de soulignement `_` pour séparer les mots (également connu sous le nom de [SCREAMING\_SNAKE\_CASE](https://github.com/rubocop-hq/ruby-style-guide#screaming-snake-case)).
* N’utilisez pas d’autres éléments, comme `<` ou `>`, ou `$`, à moins que les experts en la matière ne présentent des arguments convaincants expliquant pourquoi d’autres éléments sont nécessaires pour une langue ou une situation spécifique.
* Adressez-vous directement au lecteur en utilisant `YOUR`. Par exemple, utilisez `YOUR_ACCOUNT_ID` et non `ACCOUNT_ID`.
* Si vous pensez qu&apos;il n&apos;est pas clair si un composant est le nôtre ou celui d&apos;un tiers, vous pouvez ajouter `NEW_RELIC` à l&apos;espace réservé. Par exemple, lorsque vous écrivez sur la connexion d&apos;AWS à New Relic, vous voudrez peut-être préciser qu&apos;un compte est le nôtre et non celui d&apos;AWS, comme ceci : `YOUR_NEW_RELIC_ACCOUNT_ID`.
* Ne les combinez pas avec d’autres signes de ponctuation pour indiquer des variables (comme envelopper le texte dans des chevrons ou des accolades).

### Quand ne pas utiliser d&apos;espace réservé [#placeholders]

Les espaces réservés sont principalement utilisés lorsqu&apos;il y a une procédure à effectuer, comme des clients qui vont exécuter du code. S&apos;il n&apos;y a pas de procédure impliquée et qu&apos;un snippet de code est utilisé pour démontrer à quoi ressemble ou devrait ressembler quelque chose, vous ne devez pas utiliser d&apos;espaces réservés. Voici quelques exemples de cas où vous ne devez **pas** utiliser d&apos;espaces réservés :

* Exemple de code ou de fichiers : si vous montrez un exemple de fichier de configuration ou un autre exemple qui n&apos;est pas directement lié à une procédure, utilisez des valeurs d&apos;exemple et non des espaces réservés.
* Réponses d’appel d’API : si vous incluez la réponse d’un appel d’API qui est censée montrer à quoi ressemblera la réponse et n’est pas liée à une procédure, n’utilisez pas d’espaces réservés.

### Clés API

Si une clé API doit être référencée comme exemple dans un bloc de code ou une configuration, nous devrons utiliser un texte d&apos;espace réservé avec des astérisques au lieu de zéros.

Exemple:

```
...
-e NEW_RELIC_API_KEY=********************************FFFFNRAL \
...
```

ou

```
...
NEW_RELIC_LICENSE_KEY=****************************************
...
```
