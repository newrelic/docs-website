Cette page est destinée aux notes de sortie des logiciels téléchargeables. Pour les annonces de produits, consultez les [directives de style des nouveautés](/docs/style-guide/article-templates/whats-new-style-guidelines/).

## Nouvelle note de sortie [#new-note]

Pour ajouter une note de sortie au site de documentation :

1. Trouvez la note de sortie la plus récente pour votre agent et faites-en une copie dans le même dossier.
2. Lorsque vous renommez votre copie, évitez les conflits potentiels de nommage de version en utilisant un séparateur `-` dans le nom de votre fichier. Par exemple, au lieu de `agent-123`, utilisez `agent-1-2-3` pour la version 1.2.3 et `agent-12-3` pour la version 12.3.
3. Renseignez `subject`, `releaseDate` et `version`. Le cas échéant, incluez le champ `downloadLink`. Assurez-vous que le champ `subject` correspond aux autres notes de sortie de la série que vous mettez à jour, car des différences de majuscules peuvent causer des problèmes de regroupement dans la navigation de gauche.
4. En utilisant nos en-têtes standard pour `New features`, `Improvements` et `Bug fixes`, ajoutez suffisamment d&apos;informations de résumé dans ces sections pour [créer une excellente note de sortie](/docs/style-guide/article-templates/create-release-notes/#guidelines). Faites un lien vers la documentation ou d&apos;autres ressources où ils peuvent en apprendre davantage.
5. Validez vos modifications et soumettez une demande de tirage. Si votre sortie est sensible à la date, faites-en la remarque dans votre demande de tirage.

Un héros Tech Docs examinera le contenu de vos notes de sortie et approuvera votre PR pour qu&apos;elle soit publiée. Vous pouvez également demander à d&apos;autres membres de votre équipe d&apos;examiner votre PR.

Nous compilons et publions le site de documentation plusieurs fois par jour, et parfois les compilations peuvent prendre quelques heures. Si votre sortie est sensible au temps, assurez-vous d’avoir prévu suffisamment de temps pour mettre votre documentation en ligne.

## Qu&apos;est-ce qui fait une excellente note de publication ? [#guidelines]

D’excellentes notes de version aident les utilisateurs à se familiariser rapidement avec votre mise à jour importante, afin qu’ils sachent pourquoi elle est importante. D’excellentes notes de version aident également nos équipes d’assistance et de sécurité.

En encourageant les utilisateurs à se tenir à jour avec votre dernière sortie, cela réduit le temps de support pour résoudre les problèmes sur les versions obsolètes. Cela atténue également les risques si d&apos;éventuelles vulnérabilités ont été résolues avec votre dernière version.

Pour rédiger une excellente note de sortie, soyez aussi précis que possible. Par exemple :

* Décrivez brièvement la nouvelle fonctionnalité. Donnez un exemple de la valeur qu’elle apporte, et ajoutez un lien vers des informations plus détaillées.
* N&apos;utilisez pas de formulation vague telle que « divers débogages ». Indiquez plutôt clairement ce qui a été amélioré, afin que les lecteurs sachent si un problème qu&apos;ils ont rencontré a été résolu.

## Nouvelle catégorie de notes de version [#new-category]

Ces informations sont principalement destinées à l&apos;usage de l&apos;équipe Tech Docs.

Pour ajouter une nouvelle catégorie de notes de sortie, mettez à jour les zones suivantes du site de documentation. (Vous n&apos;avez pas besoin de mettre à jour les fichiers `releaseNote.js` ou `releaseNoteLandingPage.js` dans le dossier `nav/templates`.) Avant de soumettre votre demande de tirage sur le site de documentation GitHub, vérifiez que les pages de destination et la note de sortie d&apos;espace réservé se génèrent correctement sur votre localhost.

### Page de destination de la catégorie

Dans `/src/content/docs/release-notes`, ajoutez ce qui suit :

* Un dossier pour votre nouvelle catégorie de notes de sortie. Le lien du flux RSS, le format de la page et l&apos;ordre des dates pour les notes de sortie listées sur cette page sont générés automatiquement. Par exemple, consultez le [format de la page de destination de la catégorie Go](/docs/release-notes/agent-release-notes/go-release-notes/).
* Un fichier `index.mdx` dans votre nouveau dossier contenant le `subject`. Le `subject` est le nom qui apparaîtra sur la [page de destination des notes de sortie](/docs/release-notes/).
* Une [note de sortie d&apos;espace réservé](/docs/style-guide/article-templates/create-release-notes/#new-note) dans ce dossier à remplir par l’équipe de l&apos;agent. S’il est utilisé, le champ `downloadLink` dans la note de sortie sera formaté automatiquement dans la note de sortie publiée.

Avant que la nouvelle catégorie ne soit mise en ligne, vérifiez auprès du représentant de la gestion du marketing produit (PMM) de l’équipe s’il souhaite inclure le lien dans un prochain [article sur les nouveautés](/docs/style-guide/article-templates/whats-new-style-guidelines/).

### Page de destination

Dans `/src/content/docs/release-notes/index.mdx`, ajoutez une nouvelle section de tuiles par ordre alphabétique pour votre catégorie de notes de sortie.

Exemple:

```jsx
<TechTile
  name="Logs"
  icon="logo-newrelic"
  to="/docs/release-notes/logs-release-notes"
/>
```

Les logos proviennent de `@newrelic/gatsby-theme-newrelic/icons/logo/`. Si un logo n’existe pas déjà pour le nouvel agent, utilisez l’icône `logo-newrelic` standard ou une image dans `@newrelic/gatsby-theme-newrelic/icons/feathers.js`. Si vous avez besoin d’autres options, parlez-en au designer de l’équipe.

### Liens d’autres catégories

Ajoutez un lien vers votre nouvelle catégorie de notes de version dans la documentation de l’agent, généralement dans sa catégorie `Get started`. Pour plus d’informations, consultez notre documentation sur [les documents dans plusieurs menus](/docs/style-guide/processes-procedures/include-a-doc-in-multiple-menus/).

Facultatif : Ajoutez un lien dans le texte de la page de destination de l’agent en mettant à jour le fichier `index.mdx` dans sa taxonomie.
