Ceci est une référence pour les composants qui constituent notre composant d’installation ramifiée.

Pour commencer avec l&apos;installation ramifiée, consultez [Commencer avec l&apos;installation ramifiée](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc).

Les documents d’installation ramifiés sont contrôlés par un fichier YAML de configuration qui cartographie les relations entre les différentes options. Le YAML indique quand et comment les éléments de contenu (situés dans les fichiers .mdx ) remplissent le document. À mesure que les utilisateurs sélectionnent des options, le YAML permute ces snippets.

## Composants [#new-components]

Pour voir le composant d&apos;installation ramifiée en action, consultez [nos implémentations d&apos;installation ramifiée](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#uses). Les principaux composants sont :

* Boîtes de sélection d&apos;options (parfois appelées « listes déroulantes de tuiles ») où les choix qu&apos;un utilisateur fait dictent le contenu qui est affiché
* Étapes numérotées
* Option pour un fichier de configuration intégré dans lequel les utilisateurs peuvent saisir des valeurs
* Formulaire de commentaires d’installation (`<InstallFeedback />`)

## Comment ça marche [#how]

Les documents d’installation se trouvent dans le répertoire `install`. Il y a un seul fichier `.yaml` qui définit comment et quand un contenu spécifique est ajouté et retiré du document. Les éléments de contenu spécifiques sont représentés sous forme de fichiers `.mdx`.

## Présentation du répertoire [#install-directory]

Le contenu du framework d&apos;installation se trouve dans `src/install`.

Pour créer un nouveau document d&apos;installation, ajoutez un répertoire à `install`.

La structure de votre répertoire doit ressembler à ceci :

```
install
|--assets (used for install images)
|--config (used for the install yaml files)
   |--agent-config (used for the agent config yml files)
|--specific-install (used for a specific install doc)
   |--sub-directory1 (used for .mdx files that will be swapped in)
   |--sub-directory2 (used for .mdx files that will be swapped in)
   |--sub-directoryx (you can have as many sub-directories as you need)
```

Lorsque vous commencez un nouveau document de ramification, créez un répertoire parent sous le répertoire `install`. C&apos;est ici que se trouvent tous les fichiers de votre document de ramification.

## Le fichier YAML de ramification [#yaml-overview]

Le fichier YAML de documentation de branchement est un moyen hautement personnalisable de générer une grande variété de contenus personnalisés et interactifs. S’agissant d’un fichier YAML, il est extrêmement important de prêter attention aux indentations et de s’assurer que chaque élément du fichier YAML est correct.

Lorsque vous remplacez du contenu MDX dans votre fichier YAML, le fichier MDX spécifique doit être local à votre répertoire de document d’installation (par exemple, Java). Bien qu’il puisse être tentant de créer un lien vers du contenu n’importe où sur le site de documentation à des fins de réutilisation, cela entraînera la rupture de votre document.

### Vérifier le script YAML [#verify-yaml]

Étant donné la facilité avec laquelle il est possible de casser n’importe quel fichier YAML, notre équipe d’ingénieurs a créé un script utile pour vérifier les problèmes courants que vous pourriez rencontrer dans votre fichier YAML.

Dans votre terminal, accédez au répertoire du référentiel (repository) `docs-website` et exécutez cette commande :

`yarn verify-install-page YOUR_BRANCHING_DOC_DIRECTORY_NAME`

Par exemple, pour la documentation de ramification Java, vous utiliseriez :

`yarn verify-install-page java`

car le document de ramification Java se trouve à l’emplacement `src/install/java`.

Ce script vérifie les éléments suivants dans votre fichier YAML :

* La valeur `agentName` correspond au nom du dossier dans `src/install/YOUR_DIRECTORY_NAME`.
* Les champs `agentName`, `agentType`, `title` et `appInfo` ne sont pas vides.
* Le champ `appInfo` `placeholder` n’est pas vide.
* Les chemins d&apos;accès aux fichiers d&apos;étape et de remplacement sont des chemins valides et pointent vers des fichiers réels.
* Tous les `overrides` ont une valeur `selectedOptions`.
* Problèmes généraux de syntaxe YAML, tels qu’un guillemet supplémentaire ou une indentation non valide.

## Détails du nom de champ YAML [#yaml-fields]

* agentName : le nom du répertoire où tout se trouve, également lié à l’URL (/install/java)

* title : le nom du document (identique aux autres .mdx fichiers).

* introFilePath : le fichier contenant le contenu d’introduction du document.

* agentConfigFilePath : (facultatif, si vous utilisez un fichier de configuration) où se trouve le fichier de configuration de l’agent. Si cela ne fonctionne pas, demandez à l’équipe d’ingénierie s’il s’agit d’un type de fichier pris en charge.

* appInfo : la section où vos options sont définies. Composants :

  * optionType : le nom que vous donnez à un ensemble d&apos;options. Ce nom sera référencé dans la section `steps` pour indiquer les options auxquelles vous faites référence, ainsi que dans le .mdx associé fichier.
  * label : nom de la liste déroulante, qui s&apos;affiche au-dessus de cette boîte d&apos;options. Vous pouvez laisser ce champ vide, avec des guillemets vides, si vous ne le souhaitez pas.
  * espace réservé : plus de texte que vous pouvez placer au-dessus de la boîte d&apos;options. Vous pouvez laisser ce champ vide, avec des guillemets vides, si vous ne le souhaitez pas.

* options

  * value : la variable pour le nom de la tuile. Ceci est référencé dans la section `steps` lorsque vous donnez les valeurs qui régissent les fichiers affichés.
  * displayName : l&apos;étiquette affichée de la tuile d&apos;option.
  * logo : facultatif. Un chemin vers une image utilisée pour la tuile d&apos;option.
  * icon : facultatif. Utilisez ceci si vous souhaitez utiliser une icône au lieu d’une image (icon name=&quot;fe-server”)
  * recommendedGuided : booléen. Cela détermine si le contenu du type de composant `appInfoConfigOption` .mdx fichier s&apos;affichera. Ceci est principalement utilisé pour le contenu d&apos;installation guidée, mais peut être utilisé pour tout contenu que vous souhaitez déclencher pour qu&apos;il s&apos;affiche dans ce fichier. [En savoir plus sur les options d&apos;installation guidée](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#guided-install-decision).

* steps : il s’agit de la section qui détermine le contenu qui s’affiche. L’ordre dans lequel ils sont répertoriés détermine l’ordre de tout le contenu.

  * filePath : il s&apos;agit du chemin d&apos;accès au fichier .mdx fichier (ou du chemin théorique selon s&apos;il sera déclenché).

  * overrides : il existe trois types de surcharge :

    * **Remplacer**. S&apos;il y a un autre `filePath` listé sous un remplacement, cela signifie : remplacer le chemin du fichier principal par ce chemin de fichier en fonction des options sélectionnées.
    * **Afficher si...** Cela utilise le `isConditionalStep`, qui prend une valeur booléenne. Ce n&apos;est pas un « override », mais cela signifie : afficher ce fichier en fonction des options sélectionnées. Pour plus d&apos;informations sur l&apos;utilisation d&apos;une logique ET/OU plus complexe, consultez l&apos;[Exemple yaml .NET](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example).
    * **Ignorer.** Ceci utilise `skip`, qui prend un booléen. Cela dit essentiellement : affichez ce fichier mais ignorez-le si ces options sont sélectionnées.

  * selectedOptions : la section où vous placez les sélections d’options pertinentes. Les composants incluent :

    * optionType : cela se connecte au `optionType` utilisé dans la section `appInfo`.
    * options
      * value : se connecte au `value` utilisé dans le `optionType`.

## Création de branches de fichiers MDX [#mdx-overview]

Lorsque vous travaillez avec ce framework d&apos;installation, il y a des fichiers MDX spécifiques à connaître. Les différents types de contenu MDX sont spécifiés via le champ frontmatter `componentType`.

Les différents .mdx types de composants sont :

* `intro`

  * Référencé dans le YAML par `introFilePath`.
  * Ceci est le contenu d&apos;introduction en haut du document.

* `default`

  * Un fichier MDX de forme libre.
  * Utilisez ceci pour la majeure partie de votre contenu.

* `appInfoConfigOption`
  * Ceci est utilisé pour référencer le contenu des options.

* `agentConfig`
  * Ceci est utilisé pour le fichier de configuration d’un agent.

Pour voir des exemples de fichiers MDX en cours d’utilisation, consultez notre [fichier yaml d’exemple](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example).

### Le fichier MDX agentConfig [#sample-agentconfig]

Le fichier MDX `agentConfig` facultatif pointe vers le fichier de configuration approprié dans le répertoire d&apos;installation et contrôle quelles lignes du fichier de configuration sont modifiables.

```md
---
componentType: agentConfig
headingText: Set your app name and license key
descriptionText: Set your app name and license key. Then download your custom config file.
fileName: newrelic.yml
inputOptions:
  - label: 'Name your app'
    name: appName
    codeLine: 21
    defaultValue: 'My app name'
    toolTip: 'New Relic connects metrics to individual applications using your license key and the primary application name.' 
  - label: 'Enter your license key'
    name: licenseKey
    codeLine: 28
    defaultValue: '12345'
---
```

Lors de l&apos;utilisation du fichier de configuration, nous vous recommandons de :

* modifiez les autorisations `newrelic.yml` par défaut en lecture/écriture uniquement pour le propriétaire du processus du serveur d’application.
* assurez-vous que `newrelic.yml` fait partie de votre routine de sauvegarde.
* utilisez la [CLI New Relic Diagnostics](https://docs.newrelic.com/docs/new-relic-solutions/solve-common-issues/diagnostics-cli-nrdiag/run-diagnostics-cli-nrdiag/) pour valider vos paramètres, avant ou après avoir déployé.

### Champs de frontmatter MDX [#mdx-frontmatter]

* `componentType`: (utilisez l&apos;une de ces quatre options) si manquant, la valeur par défaut est le type « default »

  * `default`: fichier mdx gratuit
  * `appInfoConfigOption`: c’est pour les listes déroulantes, utilisez-les chaque fois que vous voulez des listes déroulantes
  * `agentConfig`: ceci est pour le fichier yaml
  * `appInfoConfig`: cette étape est celle où vous affichez le contenu (inclut le contenu `recommendedGuided`)

* `descriptionText`: le premier texte dans le contenu de l&apos;étape (texte gris plus petit qui sert de deuxième en-tête)

* `optionType`: ajouté uniquement pour `appInfoConfigOption`
