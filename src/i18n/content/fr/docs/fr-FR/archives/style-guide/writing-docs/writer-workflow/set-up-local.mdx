Exécuter le site localement rend les tests et la prévisualisation des modifications importantes beaucoup plus faciles. Il y a plusieurs choses que vous devez faire pour que cela fonctionne. Heureusement, vous n&apos;avez besoin de le faire qu&apos;une seule fois.

## Utilisation du terminal et de la ligne de commande [#terminal]

Sur macOS, vous pouvez utiliser l’application Terminal pour accéder à la ligne de commande de votre système. (Vous pouvez également accéder au terminal via VS Code.) La ligne de commande est une alternative à l’interface utilisateur graphique.

Voici quelques commandes de terminal de base qui pourraient être utiles :

* `pwd` (print working directory) : utilisez ceci pour voir le chemin de votre répertoire.
* `ls` (list) : affiche les fichiers de votre répertoire actuel.
* `cd YOUR_DIRECTORY_PATH` (change directory) : déplace vers un autre répertoire.
* `cd ..`: remontez d’un répertoire dans votre chemin.

## Activez VS Code dans votre terminal [#code-terminal]

Il est pratique de pouvoir ouvrir des fichiers depuis votre terminal directement dans VS Code. Vous ne l’utiliserez peut-être que quelques fois, mais c’est beaucoup plus agréable que d’essayer de modifier des fichiers dans le terminal lui-même.

1. Ouvrez Visual Studio Code.
2. Appuyez sur **Command + Shift + P** pour ouvrir la palette de commandes, puis tapez `install code`, et ensuite cliquez sur **Shell command: Install &apos;code&apos; command in PATH**.
3. Dans votre terminal, tapez `code` YOUR\_FILENAME\` pour ouvrir ce fichier dans VS Code.

## 1. Utilisez GitHub Desktop pour configurer votre référentiel local [#repo-setup]

GitHub Desktop est un outil graphique pour gérer vos branches, vos commits et vos PR. C’est probablement la façon la plus simple de travailler avec Git et GitHub.

1. Installez GitHub Desktop.
2. Connectez-vous à GitHub Desktop via votre compte GitHub. Sur Mac, cliquez sur **GitHub Desktop** dans le coin supérieur gauche de votre écran et sélectionnez **Préférences**. Sélectionnez le bouton bleu **Sign In**, et suivez les prompts dans la fenêtre du navigateur.
3. Accédez au [référentiel du site de documentation](https://github.com/newrelic/docs-website).
4. Cliquez sur le bouton vert **Code** et sélectionnez **Open with [GitHub Desktop](https://desktop.github.com/)**.
5. Choisissez l’emplacement où vous souhaitez le référentiel (repository). L’emplacement par défaut de ce dossier est `~/Documents/github`.
6. Clonez l’ensemble du référentiel sur votre machine locale.

## 2. Activez l’accès complet au disque [#disk-access]

Par défaut, il semble que macOS empêche le terminal d’accéder à certains dossiers système, comme `Documents`. Modifiez ce paramètre pour faciliter la navigation dans votre système de fichiers via le terminal.

1. Ouvrez les **Préférences système**.
2. Cliquez sur **Security &amp; Privacy**.
3. Dans le volet de gauche, faites défiler vers le bas jusqu&apos;à ce que vous trouviez **Full Disk Access**, puis sélectionnez-le.
4. Cliquez sur le cadenas dans le coin inférieur gauche, puis entrez le mot de passe que vous utilisez pour vous connecter à votre ordinateur.
5. Dans la liste des applications, cochez la case à côté de **Terminal** (ou de votre application de terminal par défaut).
6. Cliquez sur le cadenas pour le verrouiller.

## 3. Installer Homebrew [#homebrew]

Homebrew est un outil en ligne de commande pour installer d&apos;autres applications. C&apos;est également un moyen facile de garder les logiciels en ligne de commande à jour.

1. Ouvrez votre terminal.

2. Copiez et collez cette commande dans votre terminal :

   ```shell
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

## 4. Installez npm (gestionnaire de paquets Node.js) [#npm]

Vous devez installer `npm` pour pouvoir également installer `nvm` (gestionnaire de versions Node.js). Dans votre terminal, tapez `brew install npm`.

## 5. Installez nvm (Node version manager) [#nvm]

Le gestionnaire de version Node (`nvm`) est ce que vous utilisez pour gérer la version de Node.js installée sur votre ordinateur. Dans votre terminal, tapez `npm i -g nvm`.

## 6. Ajoutez nvm à votre profil shell [#add-nvm]

Afin d’exécuter les commandes dont vous avez besoin pour votre build local, vous devez ajouter le chemin vers `nvm` à votre profil shell.

Sur macOS, votre shell est ce qui interprète ce que vous entrez sur la ligne de commande. Le shell macOS par défaut est Zsh. Vous devez indiquer à votre shell le répertoire où se trouve `nvm` sur votre machine afin de pouvoir exécuter ces commandes de n&apos;importe où.

Vous faites cela en ajoutant le texte suivant à votre fichier `.zshrc`, qui est un fichier de configuration pour votre shell.

1. Dans votre terminal, tapez `code ~/.zshrc` pour ouvrir ce fichier dans VS Code.

2. Dans le fichier `.zshrc`, copiez et collez ce texte :

   ```shell
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
   ```

3. Sauvegarder le fichier.

## 7. Installez Node.js [#node]

Une fois que vous avez installé `nvm`, vous pouvez installer la bonne version de Node. Node, ou Node.js, est le moteur JavaScript qui propulse notre site Gatsby et ses dépendances. Tapez `nvm use 18` pour installer la version 16 de Node.js.

## 8. Installez Yarn [#yarn]

Yarn est un autre gestionnaire de paquets utilisé pour compiler tous les fichiers du référentiel (repository) **docs-website** afin de construire le site localement. Utilisez npm pour installer Yarn. Dans votre terminal, tapez `npm i -g yarn`.

## Construire le site local [#local-site]

Une fois que vous avez installé toutes ces choses dans votre terminal, vous pouvez exécuter le site localement sur votre machine.

1. Dans votre terminal, tapez `pwd` pour vous assurer que vous êtes dans le répertoire du référentiel **docs-website**.
2. Tapez `yarn` pour vous assurer que toutes vos dépendances Gatsby sont à jour.
3. Tapez `yarn start` pour compiler le site localement.
4. Lorsque le processus est terminé, dans votre navigateur web, accédez à `http://localhost:8000`.

Lorsque vous exécutez `yarn start`, votre terminal affiche de nombreuses lignes de texte. Si votre compilation locale échoue, la sortie du terminal fournit souvent un indice sur ce qui s’est mal passé.

Par défaut, le site sera compilé sans aucune page traduite (jp, kr). Si vous souhaitez également compiler ces pages, vous pouvez exécuter `yarn start:full`.

## Construire une partie du site local (plus rapide) [#local-site-speed]

Si vous souhaitez compiler le site encore plus rapidement, vous pouvez choisir de compiler un seul dossier (ou autant que vous le souhaitez) au lieu de chaque document du site. Cela peut être pratique si vous savez que vous travaillez sur un document de compte par exemple, vous pouvez compiler uniquement le dossier du compte. Cependant, cela signifie que si vous essayez de visiter un document dans un dossier en dehors de ce que vous avez spécifié, vous verrez un `404`.

Pour compiler un ou plusieurs dossiers spécifiques, ajoutez cette variable à votre commande `yarn start` :

`BUILD_FOLDERS=mlops yarn start` ou `BUILD_FOLDERS=apm,logs,errors-inbox yarn start`

Conseils:

* Le ou les dossiers que vous spécifiez doivent se trouver au niveau racine du répertoire `/src/content/docs/`. Cela n’inclut aucun sous-répertoire. Par exemple, `browser` est un dossier valide, mais `browser-monitoring` ne l’est pas car il s’agit d’un sous-répertoire de `browser`.
* Assurez-vous qu’il n’y a pas d’espaces après les virgules dans votre liste de dossiers. Par exemple, tapez `BUILD_FOLDERS=apis,infrastructure` et non `BUILD_FOLDERS=apis, infrastructure`.
