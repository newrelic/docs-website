Une capture d’écran ou une image bien choisie peut grandement améliorer la lisibilité et la clarté d’un document. Trop d’images ou une image difficile à analyser peut vraiment ralentir les choses.

* Si vous ne faites pas partie de l&apos;équipe de documentation et que vous souhaitez ajouter une image au site de documentation, créez un [ticket GitHub](https://github.com/newrelic/docs-website/issues/new/choose).
* Si vous êtes un collaborateur de New Relic, contactez le `@hero` dans le canal Slack de la documentation.

## Ajouter une image [#add]

Nous voulons nous assurer que les données sensibles n’apparaissent pas dans les captures d’écran de l’interface utilisateur. C’est pourquoi nous vous recommandons de fournir un permalien vers un compte de test. Ne prenez pas de capture d’écran de votre compte New Relic.

Voici quelques éléments à garder à l’esprit lorsque vous créez une image :

* Assurez-vous que votre image fournit des informations utiles en un coup d’œil.
* Assurez-vous de suivre les [conventions de nommage et d&apos;instructions d&apos;importation](#naming-and-imports).
* Incluez une légende avec un contexte utile pour l&apos;image.
* Pour les légendes de capture d’écran, incluez le chemin en gras.
* Pour les sous-titres de vidéos, incluez la durée approximative.
* Ne créez pas de lien vers un fichier image externe. Toutes les images utilisées dans la documentation doivent être stockées dans [notre référentiel (repository) GitHub](https://github.com/newrelic/docs-website).
* Notre mode par défaut est le mode sombre. Si un expert en la matière vous fournit des captures d&apos;écran en mode clair, veuillez en demander de nouvelles en mode sombre. Si vous ne parvenez pas à obtenir des images en mode sombre, alors n&apos;importe quelle capture d&apos;écran vaut mieux qu&apos;aucune capture d&apos;écran.

Pour ajouter ou modifier une image :

1. Placez votre image à la racine de `static/images/`.

2. Continuez avec les procédures suivantes pour ajouter ou modifier des images :

    Pour mettre à jour une image :

    2. Placez le nouveau fichier image dans le même répertoire `static/images`.
    3. Assurez-vous que la source de l&apos;image est correcte.

## Rédigez des légendes d’images [#labeling]

Les légendes descriptives aident le lecteur à comprendre pourquoi l’image est importante. S’il s’agit d’une capture d’écran, il est utile d’inclure le chemin en gras en plus d’une description. Par exemple :

```html
<img
  title="Screenshot showing the Overview dashboard"
  alt="Screenshot showing the Overview dashboard"
  src="/images/kubernetes_screenshot-full_cluster-dashboard-detail.webp"
/>

<figcaption>
  Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Kubernetes**</DNT>. Select your cluster and click <DNT>**Overview Dashboard**</DNT> in the left navigation pane. It shows useful overview data about the status and performance of the cluster and its containerized workloads.
</figcaption>
```

Pour obtenir plus d’aide sur les légendes et autres textes d’accompagnement des images, consultez les [Directives pour l’explication des images](/docs/style-guide/writing-guidelines/screenshots-images#identify-images).

## Ajouter une image en ligne (MDX) [#inline-images-mdx]

Pour utiliser une image en ligne :

* Utilisez le tag `img` dans le fichier
* L’attribut `src` contient le chemin de l’image : `src="/images/IMAGE_NAME.webp"`
* Ajoutez une classe de `inline` à `img`.
* Ajoutez toute hauteur/largeur facultative dans la propriété `style`.

Si l’image en ligne est utilisée comme icône, décrivez-la toujours en premier. Lorsque vous intégrez l’image de l’icône, faites suivre l’image du mot `icon` dans le texte. Par exemple :

```jsx
---
title: Abbreviated example of a file
---

Select your app's settings <img src="/images/example_icon_example-icon.webp" class="inline" style={{height: "30px", width: "30px"}} alt="Multiple app names indicator in New Relic" title="Multiple apps name indicator in New Relic" /> icon.
```

## Dimensionnement de l&apos;image

Par défaut, toutes les images MDX ont une hauteur maximale de 550 px pour éviter que les images verticales n’apparaissent trop grandes dans le contenu.

Si vous avez une image qui doit être plus haute que 550 px, vous pouvez définir la classe `unbound` dans les attributs `img`.

```html
<img
  class="unbound"
  title=""
  alt=""
  src=""
/>
```

**Remarque :** Certaines images utilisent un ensemble `width="n%;"` dans les attributs `img`. Cela appliquera automatiquement la classe `unbound` et supprimera la restriction de hauteur d’image par défaut car cela provoque l’étirement de l’image et non son redimensionnement proportionnel.

## Icônes [#icons]

Vous pouvez choisir parmi une variété d&apos;icônes à inclure dans vos documents :

* Icônes Feather (préfixées par `'fe-`).
* Icônes New Relic (préfixées par `nr-`).
* Logos pour les produits tiers (préfixés par `logo-`).

Pour voir si nous avons déjà une icône dont vous avez besoin, allez à :

* [Feather.js pour `docs-website` dans GitHub](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104): ce sont les icônes Feather disponibles dans le projet `docs-website` mais qui ne sont pas incluses dans le thème Gatsby.
* [Thème Gatsby pour `docs-website` dans GitHub](https://github.com/newrelic/docs-website/tree/develop/src/%40newrelic/gatsby-theme-newrelic/icons): il s’agit d’un sous-ensemble d’icônes Feather, New Relic et de logos de produits qui sont disponibles sur les sites des développeurs et de documentation.

Vous pouvez utiliser toutes les icônes dont vous avez besoin dans le thème Gatsby ou Feather. Actuellement, ces emplacements disposent de groupes d’icônes distincts et sans chevauchement.

### Insérer des icônes en tant qu&apos;attribut de tag [#tag-attributes]

Si votre icône apparaît comme un attribut à l&apos;intérieur d&apos;un autre tag, préfixez-la avec `icon` comme dans cet exemple :

```jsx
<LandingPageTileGrid>
  <LandingPageTile
    title="AWS Lambda"
    href="/docs/serverless-function-monitoring/aws-lambda-monitoring/get-started/monitoring-aws-lambda-serverless-monitoring"
    icon="logo-aws"
  >
</LandingPageTile>
```

### Insérer des icônes en ligne [#inline-icons]

Si votre icône apparaît dans le texte courant, utilisez le composant `<Icon>`. Voici quelques exemples :

* Feather : `<Icon name="fe-database" />`
* New Relic : `<Icon name="nr-tdp" />`
* Logos : `<Icon name="logo-apple" />`

### Installer de nouvelles icônes Feather [#feather-icons]

Si vous ne voyez pas l’icône que vous souhaitez dans le [thème Gatsby pour `docs-website` dans GitHub](https://github.com/newrelic/gatsby-theme-newrelic/tree/develop/packages/gatsby-theme-newrelic#available-icons) ou dans [Feather.js pour `docs-website` dans GitHub](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104), vous pouvez ajouter une nouvelle icône au thème Gatsby. Vous pouvez également demander aux développeurs d’ajouter l’icône que vous souhaitez.

Voici un exemple d&apos;ajout d&apos;une icône `database` :

1. Accédez à [feathericons.com](https://feathericons.com/).
2. Téléchargez l’icône plume `database` en cliquant sur l’icône elle-même.
3. Une fois téléchargé, ouvrez le fichier SVG dans votre éditeur de texte.
4. Copiez les &quot;entrailles&quot; du SVG, c&apos;est-à-dire tout ce qui se trouve entre les tags `<svg>`. Par exemple, si le SVG est `<svg><path m="1"></path></svg>`, alors copiez uniquement la partie `<path m="1"></path>`.
5. Ouvrez la liste des icônes feather à l&apos;adresse `src/@newrelic/gatsby-theme-newrelic/icons/feather.js`.
6. Ajoutez une entrée pour `database`, et attribuez-lui le code de l’étape précédente.
7. Si l’icône comporte plusieurs chemins, incluez le wrapper `<>` autour d’elle, comme vous le voyez avec d’autres icônes.
8. Enregistrez le fichier `feather.js`.

Le préfixe `fe-` est ajouté automatiquement. Une fois cette icône ajoutée, vous pouvez l’utiliser avec le composant d’icône ; par exemple, `<Icon name="fe-database" />`.

## Gestion des conflits de PR de refactoring d’images

Voici un aperçu rapide des changements de contribution qui sont entrés en vigueur après le refactoring de notre image et comment mettre à jour vos modifications de fichiers dans toutes les PR en attente.

Assurez-vous de récupérer la dernière version depuis `develop`, puis mettez à jour tous les fichiers liés aux images dans vos modifications :

### Ajout d&apos;images au référentiel (repository) :

<SideBySide>
  <Side>
    **Ancienne convention d’image :**

    les images se trouvaient dans `./src/images`

    ```
    ├──src/
    │  └──content/
    │  │  └──docs/
    │  │    └── example-page.mdx
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>

  <Side>
    **Nouvelle convention d&apos;image :**

    les images sont maintenant dans `./static/images`

    ```
    ├──src/
    │  └──content/
    │     └──docs/
    │        └── example-page.mdx
    ├──static/
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>
</SideBySide>

### Utilisation de l&apos;image dans un fichier MDX

<SideBySide>
  <Side>
    **Ancienne convention d’image :**

    Auparavant, nous devions importer nos chemins d&apos;image en tant que variable, puis utiliser cette variable comme source `<img>`.

    ```jsx
    import exampleImage from 'images/example-image.webp'

    <img
      title="Image title."
      alt="Alternate text."
      src={exampleImage}
    />
    ```
  </Side>

  <Side>
    **Nouvelle convention d&apos;image :**

    Maintenant, la source de l’image est simplement le chemin vers l’image par rapport au dossier statique :

    ```html
    <img
      title="Image title."
      alt="Alternate text."
      src="/images/example-image.webp"
    />
    ```
  </Side>
</SideBySide>

### Utilisation de l’image dans un fichier MD

L’utilisation d’images en markdown est presque la même qu’avant. Nous avons juste légèrement modifié le chemin utilisé :

<SideBySide>
  <Side>
    **Ancienne convention d’image :**

    `./images`

    ```md
    ![Image title.](./images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>

  <Side>
    **Nouvelle convention d&apos;image :**

    `/images`

    ```md
    ![Image title.](/images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>
</SideBySide>

### Constructions locales

Suivez ces étapes pour résoudre les erreurs et les échecs de build lors de l’exécution de vos modifications localement après avoir mis à jour votre branche avec la dernière version de `develop`:

1. mettez à jour vos fichiers d&apos;images et votre code selon la nouvelle convention comme indiqué ci-dessus
2. exécutez `nvm use` pour vous assurer que vous êtes sur la bonne version de node
3. exécutez `yarn` pour installer les packages nécessaires
4. exécutez `yarn clean` pour effacer toutes les images en cache des anciennes versions
5. exécuter `yarn start`
