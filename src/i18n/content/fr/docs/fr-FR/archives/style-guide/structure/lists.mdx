Les listes sont un moyen puissant d&apos;organiser l&apos;information, mais elles n&apos;offrent pas toujours une expérience de lecture agréable. Gardez ces points à l&apos;esprit lorsque vous rédigez une liste :

* Mettez toujours en majuscule la première lettre du premier mot de chaque élément de liste.
* Utilisez des listes ordonnées (numérotées) pour les procédures étape par étape, où l&apos;ordre a de l&apos;importance.
* Utilisez des listes non ordonnées (à puces) pour faciliter la lecture rapide des informations connexes par les utilisateurs.
* Utilisez OU sur une ligne séparée lorsqu&apos;il y a plus d&apos;une option pour une étape numérotée ou une puce.
* Utilisez des tableaux lorsque votre liste ordonnée ou non ordonnée bénéficierait de détails supplémentaires.

<Callout variant="tip">
  Pour les directives de ponctuation, suivez le **[Guide de style de rédaction de Microsoft](https://docs.microsoft.com/en-us/style-guide/scannable-content/lists),** qui inclut des considérations pour la localisation.
</Callout>

## Listes en ligne [#inline-lists]

Comme alternative à l&apos;utilisation de listes à puces, vous pouvez créer une liste en ligne, comme ceci : [C SDK](/docs/agents/c-sdk/instrumentation/enable-distributed-tracing-your-c-applications) | [Go](/docs/agents/go-agent/features/distributed-tracing-go#create-manually) | [Java](/docs/agents/java-agent/api-guides/guide-using-java-agent-api#trace-calls).

Vous pourriez vouloir utiliser une liste en ligne lorsque :

* Vous créez un lien vers une documentation supplémentaire.
* Les clients sélectionneront probablement une seule option.
* L’élément de liste peut être affiché avec un mot court ou une phrase (comme Java ou infrastructure).
* Vous pensez qu’une liste à puces prend beaucoup d’espace vertical. Cela peut se produire dans des circonstances où une procédure doit inclure plusieurs listes. Voici [un exemple de cela](/docs/understand-dependencies/distributed-tracing/enable-configure/enable-distributed-tracing#enable).
* Il n&apos;y a que deux ou trois options potentielles parmi lesquelles ils devront choisir et une liste à puces semble inutile. Voici [un exemple](/install/dotnet#requiremnts).
