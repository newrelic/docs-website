Cette page du guide de style décrit le frontmatter standard pour les documents, et souligne également les différents types de contenu que nous maintenons sur le site.

## Frontmatter et métadonnées de la documentation [#meta-fields]

Le haut de chaque document commence par un ensemble de métadonnées. Lisez la suite pour en savoir plus sur le contenu de ces métadonnées :

<table>
  <thead>
    <tr>
      <th width={150}>
        **Champ de contenu méta**
      </th>

      <th>
        **Description**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        `title`
      </td>

      <td>
        Le titre principal du document, qui s’affichera en haut du document sous forme d’en-tête HTML `<h1>`, dans le titre de la page du navigateur et dans les champs méta des moteurs de recherche.

        Dans la mesure du possible, fournissez un titre orienté vers l’action ou la tâche ; par exemple, « Page AJAX : identifier les appels chronophages ». En général, utilisez la casse de phrase. Mettez uniquement le premier mot en majuscule. Ne mettez aucun autre mot du titre en majuscule, à moins qu’il ne s’agisse d’un nom propre, tel qu’un nom de produit spécifique, ou qu’il ne suive un deux-points `:`.

        Si vous cherchez des idées sur la façon de choisir un titre, parcourez les titres de documents similaires.

        Le titre utilisé dans la barre latérale (volet de navigation de gauche) est défini dans [le fichier de navigation](/docs/style-guide/processes-procedures/update-left-navigation-pane).
      </td>
    </tr>

    <tr>
      <td>
        `tags`
      </td>

      <td>
        Obsolète. Historiquement, les tags étaient utilisés pour aider les moteurs de recherche et l’IA à trouver le bon contenu. Les moteurs modernes sont suffisamment sophistiqués pour déduire ce contexte sans tags, ce tag n’est donc plus nécessaire.
      </td>
    </tr>

    <tr>
      <td>
        `translate`
      </td>

      <td>
        Indique les langues dans lesquelles cette page est traduite par des humains. Ce champ ne régit pas la traduction automatique ; en règle générale, tous les documents « standard » du site sont traduits automatiquement dans toutes les langues. Pour en savoir plus, consultez [Traduction de documents](/docs/style-guide/writing-docs/docs-translation/).
      </td>
    </tr>

    <tr>
      <td>
        `metaDescription`
      </td>

      <td>
        Une courte description du document. Les moteurs de recherche s’appuient sur ce champ pour comprendre de quoi traite un document, et ils affichent souvent la méta-description directement dans les résultats de recherche. Doit contenir moins de 160 caractères. Pour en savoir plus sur l’importance des méta-descriptions pour la recherche, consultez [Contrôler vos snippets dans les résultats de recherche](https://developers.google.com/search/docs/appearance/snippet) dans la documentation de Google.
      </td>
    </tr>

    <tr>
      <td>
        `redirects`
      </td>

      <td>
        Redirections **vers** ce document à partir d’anciennes URL. Une redirection par ligne. Utilisez un chemin relatif et n’incluez pas de barre oblique finale `/`.
      </td>
    </tr>

    <tr>
      <td>
        `freshnessValidatedDate`
      </td>

      <td>
        La dernière fois qu&apos;un rédacteur a apporté des mises à jour significatives à cette documentation et vérifié son exactitude.

        La valeur par défaut est `never`. Lorsque vous apportez une mise à jour importante à un document, ajoutez la date d&apos;aujourd&apos;hui dans ce format : `YYYY-MM-DD`.
      </td>
    </tr>
  </tbody>
</table>

## Modèles de pages

Le site de documentation n’a pas de modèles de page stricts — puisque nous avons une approche « docs as code », les rédacteurs peuvent utiliser divers composants pour structurer les documents comme ils le jugent préférable. Cependant, nous avons plusieurs types de contenu uniques qui se comportent différemment de nos documents `.mdx` standards.

<table>
  <thead>
    <tr>
      <th width={150}>
        **Type de contenu**
      </th>

      <th>
        **Description**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        Documentation « Standard »
      </td>

      <td>
        Un fichier `.mdx` standard, se trouvant dans le sous-répertoire `/src/content/docs/`. Ce type de contenu est utilisé pour la majorité du contenu sur le site.
      </td>
    </tr>

    <tr>
      <td>
        Définition de l&apos;attribut
      </td>

      <td>
        Ce format sert à définir les attributs et les types d’événements. Ces définitions se trouvent dans leur propre référentiel (repository) GitHub Enterprise, puis elles sont publiées sur le site de documentation et NerdGraph via le service de dictionnaire de données. Pour en savoir plus, consultez [Travailler avec le type de contenu de définition d’attribut](/docs/style-guide/article-templates/attribute-definition-template).
      </td>
    </tr>

    <tr>
      <td>
        Documentation d’installation ramifiée
      </td>

      <td>
        Ce format est destiné aux documents d’installation interactifs. Les documents d’installation à branches se composent de plusieurs composants dans des fichiers `.mdx` individuels regroupés dans un sous-répertoire, la logique définissant quels éléments afficher et à quel moment étant définie dans un fichier `.yaml` distinct. Le contenu de l’installation à branches se trouve dans le sous-répertoire `/src/install/`.

        Pour en savoir plus, consultez [Commencer avec l&apos;installation ramifiée](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc/).
      </td>
    </tr>

    <tr>
      <td>
        Notes de version
      </td>

      <td>
        Ce format inclut des champs de frontmatter uniques. Les notes de version se trouvent dans `/src/content/docs/release-notes/`, et elles sont généralement rédigées par les équipes produit plutôt que par des rédacteurs.

        Les utilisateurs s’appuient sur les notes de sortie pour se tenir au courant des modifications mineures apportées au produit, en particulier pour les logiciels téléchargeables comme les agents. Pour en savoir plus, consultez [Créer des notes de publication](/docs/style-guide/article-templates/create-release-notes/).
      </td>
    </tr>

    <tr>
      <td>
        Articles sur les nouveautés
      </td>

      <td>
        Ce format inclut des champs de frontmatter uniques. Les articles Nouveautés sont créés par PMM pour les annonces plus importantes. Contrairement à la plupart des contenus, ils se trouvent dans `/src/content/whats-new/` plutôt que dans le sous-répertoire `/docs/`.

        Ils sont disponibles sur le site de documentation, mais ils sont également visibles dans l&apos;UI de New Relic. Pour en savoir plus, consultez les [directives de style des nouveautés](/docs/style-guide/article-templates/whats-new-style-guidelines/).
      </td>
    </tr>
  </tbody>
</table>
