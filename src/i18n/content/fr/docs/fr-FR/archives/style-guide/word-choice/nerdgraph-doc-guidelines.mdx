Cette ressource contient des recommandations et des directives de guide de style pour écrire sur l’API NerdGraph de New Relic.

## Lignes directrices relatives au style [#nerdgraph-style]

Quelques directives liées au style lors de la rédaction sur NerdGraph :

* **NerdGraph.** Vous devez vous y référer en général sous le nom de « NerdGraph » ou « NerdGraph de New Relic ». Lors de la première mention, il est acceptable de le formuler comme notre « API NerdGraph », en particulier dans les contextes où il n&apos;est pas immédiatement évident que nous parlons d&apos;une API.

* **NerdGraph est une API unique.** NerdGraph n&apos;est pas un ensemble d&apos;API différentes. Il y a parfois une tendance à se référer à NerdGraph comme une collection d&apos;API, ce qui est en fait un peu vrai car NerdGraph rassemble beaucoup de nos API sous le capot, mais du point de vue des clients, nous voulons nous y référer comme une API unique. Par exemple, au lieu de dire quelque chose comme « utilisez l&apos;API d&apos;entité de NerdGraph », nous pourrions dire quelque chose comme « utilisez NerdGraph pour afficher et configurer vos entités monitorées ».

* **GraphQL.** GraphQL est le format d’API open source avec lequel NerdGraph a été conçu. Il est acceptable de le souligner occasionnellement lorsque cela est approprié, car GraphQL est bien connu dans le monde de la technologie et certaines personnes sont déjà familières avec son fonctionnement.

* **Explorateur NerdGraph.** Nous l&apos;appelons principalement « l&apos;explorateur NerdGraph » ou « notre explorateur NerdGraph », mais s&apos;il se trouve dans un contexte où ce qu&apos;est exactement NerdGraph n&apos;est pas évident, vous pouvez l&apos;appeler « l&apos;explorateur d&apos;API NerdGraph ». Autres astuces :

  * Parce qu’il existe des URL différentes pour les versions européenne et japonaise de l’explorateur NerdGraph, nous devrions généralement créer un lien vers [la section de documentation de l’explorateur NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#explorer) et non vers l’URL de l’explorateur.
  * Évitez d&apos;utiliser uniquement « explorer » car cela entre en conflit avec d&apos;autres explorateurs (par exemple, l&apos;explorateur d&apos;API REST, ou l&apos;explorateur d&apos;entité).
  * Nous pouvons expliquer, si nous pensons que c&apos;est utile, que l&apos;explorateur NerdGraph est construit avec GraphiQL, une plateforme open source pour créer des requêtes GraphQL. Cela peut être utile à expliquer car GraphQL et GraphiQL sont tous deux connus dans l&apos;industrie.

* **Requests.** Il existe deux principaux types d&apos;opérations GraphQL : les requêtes et les mutations ([définies ici](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology)). Nous pouvons utiliser ces termes pour faire référence à des exemples spécifiques (par exemple : « voici une mutation qui… »). Pour faire une référence générale à plusieurs requests NerdGraph de différents types, vous pouvez utiliser « requests ».

* **Champs.** Les champs sont les éléments d’un type d’objet qui peuvent faire l’objet d’une requête. Pour des exemples d’utilisation de « champ » en contexte, consultez [ce tutoriel NerdGraph](/docs/nerdgraph-anomaly-detector-configurations-api-tutorial/#update-configuration). La raison pour laquelle les champs sont un concept important est qu’avec les API au format GraphQL, les utilisateurs spécifient exactement les champs qu’ils souhaitent récupérer (contrairement aux API REST, par exemple, qui peuvent renvoyer une réponse par défaut avec des champs dont vous n’avez pas besoin).

## Conseils pour créer la documentation NerdGraph [#creating-nerdgraph-docs]

Il est acceptable d&apos;ajouter des sections relativement petites de contenu lié à NerdGraph à des documents qui ne sont pas dans la catégorie de documentation NerdGraph. En règle générale, s&apos;il s&apos;agit de plus d&apos;une page de contenu lié à NerdGraph, vous devez essayer de l&apos;ajouter à la catégorie de documentation NerdGraph (soit dans son propre document, soit dans un document connexe, si possible).

Si vous ajoutez du contenu à la catégorie de documentation NerdGraph, prenez en compte les conseils suivants pour nous aider à conserver notre contenu efficacement organisé et facile à trouver :

* **Envisagez d’ajouter du contenu à un tutoriel existant.** Lorsque vous ajoutez du nouveau contenu NerdGraph, vérifiez si vous pouvez inclure ce nouveau contenu dans les documents NerdGraph existants. Cela nous aide à garder la liste des tutoriels claire et à éviter qu’elle ne s’allonge démesurément. Par exemple, si vous souhaitez ajouter quelque chose lié à la visualisation ou à la configuration des entités, vous pouvez l’ajouter au [document NerdGraph lié à l’entité](/docs/apis/nerdgraph/examples/nerdgraph-entities-api-tutorial).
* **Choisissez un document à imiter.** Lors de la rédaction d’un nouveau document de tutoriel NerdGraph, vous pouvez utiliser [ce document NerdGraph](/docs/apis/nerdgraph/examples/manage-accounts-nerdgraph) comme modèle de base. N’hésitez pas à modifier cette structure en fonction de ce que vous ou les experts en la matière jugez nécessaire pour aider les clients à comprendre la fonctionnalité de l’API, mais cette structure générale devrait convenir à de nombreux documents.
* Lorsque vous ajoutez un nouveau type de contenu NerdGraph, ajoutez-le à l&apos;[index du contenu NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#tutorials). Cet index a été créé pour refléter le fait que nous avons des tutoriels disponibles qui ne se trouvent pas dans la section principale de la documentation NerdGraph.

Quelques conseils lors de la rédaction de contenu NerdGraph :

* **Exemples de requests.** Conseils pour créer des exemples de requests :

  * Utilisez des tags `tags for customer-specific values in example queries and mutations. Remember that you don't need to use` dans les exemples de réponses ou les messages d’erreur.
  * Il est de bonne pratique d&apos;expliquer l&apos;utilisation générale d&apos;une requête, suivie d&apos;une note indiquant que la requête d&apos;exemple n&apos;est qu&apos;un exemple (par opposition à l&apos;idée que c&apos;est la seule façon d&apos;accomplir quelque chose). Ainsi, par exemple, vous pourriez dire : « Vous pouvez utiliser NerdGraph pour mettre à jour votre [monitoring Synthétique de test d&apos;API](/docs/synthetics/synthetic-monitoring/getting-started/types-synthetic-monitors#types-monitors). Voici un exemple de création d&apos;un moniteur de test d&apos;API qui… ».
  * Pour nettoyer le format d&apos;une request, allez dans l&apos;explorateur NerdGraph, saisissez la request et cliquez sur **Tools &gt; Prettify**. Notez que la request doit être fonctionnelle, avec des valeurs réelles.

* **Définitions des champs.** L&apos;explorateur NerdGraph inclut des définitions de champs intégrées, mais il peut être utile d&apos;expliquer les champs plus complexes ou moins évidents dans votre document. Pour les champs courants utilisés dans la totalité ou la plupart des exemples de requests, une façon d&apos;aborder ce point consiste à ajouter une section « Concepts importants » au début du document, dans laquelle vous incluez toute lecture recommandée ou des remarques sur les champs importants. Pour les champs qui ne sont utilisés que dans une ou deux requests, vous préférerez peut-être les expliquer lors de la présentation de l&apos;exemple de request.

## Documentation du schéma NerdGraph [#schema-docs]

L&apos;explorateur NerdGraph expose les définitions de schéma NerdGraph pour aider les utilisateurs à comprendre ce que sont les différents champs. L&apos;équipe de documentation examine les documents de schéma qui sont soumis par les équipes d&apos;ingénierie. Pour en savoir plus sur le déroulement de l&apos;examen des définitions de schéma, consultez la ressource de l&apos;équipe de documentation « Référentiels (repositories) de documentation externe ».
