Les images sont une partie essentielle de notre documentation. Elles montrent aux utilisateurs ce qu&apos;ils obtiendront en suivant une procédure. Ils peuvent aider à orienter les utilisateurs dans un parcours complexe de l&apos;interface utilisateur, illustrer des concepts complexes comme les [surcharges de fichiers de configuration](/docs/agents/python-agent/installation-configuration/python-agent-configuration#options), ou parfois simplement ajouter un intérêt visuel.

Ce document décrit les bonnes pratiques pour créer et maintenir des images. Si vous avez besoin d&apos;aide pour leur incorporation (embedding) sur notre site, consultez [Incorporer des images](/docs/style-guide/processes-procedures/embed-images). Si vous souhaitez ajouter des annotations d&apos;image, consultez [Bonnes pratiques pour l&apos;utilisation des annotations d&apos;image](/docs/style-guide/images/image-annotations).

## Directives pour les types d’images [#types]

Nous avons quatre catégories principales d&apos;images sur notre site.

<CollapserGroup>
  <Collapser id="screenshots" title="Captures d'écran">
    Les captures d’écran sont une ressource clé pour les utilisateurs — dans les enquêtes auprès des utilisateurs, ils nous disent constamment qu’ils aimeraient voir plus de captures d’écran, et de meilleure qualité, dans la documentation.

    Nous utilisons deux types de captures d’écran : les captures d’écran complètes qui montrent l’ensemble de l’interface utilisateur, et les captures d’écran recadrées qui n’en montrent qu’une section. Généralement, nous préférons les captures d’écran complètes car elles aident l’utilisateur à s’orienter dans l’interface utilisateur. Parfois, une capture d’écran recadrée peut être préférable lorsque vous essayez uniquement de montrer une chose très spécifique, et que l’interface utilisateur environnante est une distraction.

    Gardez à l’esprit les directives de sécurité de New Relic et évitez les informations privées de New Relic ou des clients. De plus :

    * Utilisez toujours le mode sombre.
    * Recadrez ou masquez toujours les informations sensibles.
    * Suivez nos [directives d&apos;annotation d&apos;images](/docs/style-guide/images/image-annotations/), et utilisez les annotations avec parcimonie.

## Directives pour expliquer les images [#identify-images]

Le texte d’accompagnement peut fournir un contexte et des explications utiles, en particulier pour les captures d’écran compliquées et d’autres images qui peuvent être difficiles à comprendre par elles-mêmes. Bien que vous deviez toujours inclure un texte alternatif pour l’accessibilité, les autres types de texte d’accompagnement sont facultatifs.

* Texte alternatif (obligatoire)
* Titre (obligatoire)
* Légende
* Texte environnant

<Callout variant="important">
  Évitez l&apos;utilisation de texte dans une capture d&apos;écran, utilisez plutôt des [légendes](/docs/style-guide/images/screenshots-images/#captions). Voir [Bonnes pratiques pour l&apos;utilisation des annotations d&apos;images](/docs/style-guide/images/image-annotations)
</Callout>

### Texte alternatif (requis) [#alt-text]

Incluez toujours un texte alternatif dans vos tags d&apos;image afin que les lecteurs malvoyants puissent utiliser leurs lecteurs d&apos;écran pour obtenir des informations utiles à partir des images. Cela ne s&apos;applique qu&apos;aux images qui contiennent du contenu ou des commandes (par exemple, des boutons).

<Callout variant="tip">
  Le texte alternatif ne s&apos;applique pas aux icônes Feather en ligne.
</Callout>

Lors de l’utilisation du texte alternatif :

* Utilisez des descriptions d&apos;images concises.

* Ne répétez pas le texte environnant — les lecteurs d’écran le lisent déjà.

* Visez la clarté. Des phrases complètes ne sont pas requises.

* Identifiez le type d&apos;image d&apos;une manière ou d&apos;une autre :

  * `alt="Diagram showing the flow of data from client to server."`
  * `alt="Screenshot showing how to select a server."`
  * `alt="Photo of garden hose that serves as a metaphor for electrical amperage."`

### Légende [#captions]

Les légendes apparaissent sous les images et fournissent un contexte supplémentaire aux lecteurs.

Gardez à l’esprit les points suivants :

* Gardez les légendes courtes et n’insérez pas de procédures.
* N’insérez des [chemins de navigation](/docs/style-guide/formatting/ui-paths/) dans les légendes que si la navigation est un élément clé du message.
* Insérez des informations complémentaires qui ne sont pas identiques au texte environnant.
* Faites des légendes faciles à parcourir.
* Encouragez les lecteurs à regarder le texte environnant.
* Ne mettez pas d&apos;informations requises dans les légendes qui ne sont pas disponibles ailleurs.
* Les légendes ne sont pas nécessaires dans les captures d’écran de procédure, car le texte de la procédure devrait clarifier les choses.

### Texte environnant [#surrounding-text]

Si vous n’utilisez pas de légendes ou d’annotations, assurez-vous d’ajouter du texte avant ou après l’image pour donner un contexte utile.

Si vous vous appuyez sur le texte environnant pour expliquer votre image :

* Utilisez des images intuitives.
* Gardez le texte environnant concis afin qu’il soit plus facile de comprendre l’image.

## Supprimer ou renommer un fichier image [#delete-rename-image]

Nos fichiers .mdx traduits en i18n doivent correspondre aux fichiers .mdx anglais correspondants. Lorsque vous supprimez ou renommez des fichiers d’image en anglais, vous risquez de provoquer une erreur de compilation, car il y a désormais une incohérence entre les fichiers anglais et traduits. Voici quelques conseils lors de la suppression ou du renommage d’un fichier d’image :

* Pour remplacer une image : si vous remplacez une image existante, vous devez donner le même nom au fichier image. Supprimez le fichier que vous souhaitez remplacer et ajoutez le nouveau fichier. Cela signifie que vous n’aurez pas besoin de modifier les références à ce fichier image.
* Pour supprimer une image : si vous souhaitez simplement supprimer une image sans la remplacer, ne supprimez pas le fichier image. Au lieu de cela, supprimez simplement l’instruction d’importation pour ce fichier image. L’équipe de documentation exécute occasionnellement un script qui supprime les fichiers images qui ne sont pas référencés par des fichiers mdx. Cela signifie que nous n’avons pas à supprimer de fichiers images et n’avons donc pas besoin de toucher aux fichiers mdx dans le répertoire i18n, car ils seront automatiquement mis à jour avec notre workflow de traduction.
* Pour renommer un fichier image : d&apos;abord, demandez-vous si cela est nécessaire. Le nom du fichier image est généralement sans importance et trivial. Si vous décidez de renommer un fichier image, vous devez aller dans tout fichier mdx qui référence le fichier image (y compris les fichiers du répertoire i18n) et mettre à jour ce nom de fichier.
