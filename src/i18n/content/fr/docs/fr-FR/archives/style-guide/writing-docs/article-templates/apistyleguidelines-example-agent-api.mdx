## Syntaxe

```
newrelic.apiStyleGuidelines(data type $parameter_name[, integer $optional_param])
newrelic.apiStyleGuidelines(data type $parameter_name, array $different_param, string $third_param)
```

Décrivez brièvement l’appel. Idéalement, une ligne ou moins sur la page « View all methods ».

## Exigences

Agent version 1.2.3.4 ou supérieure.

Exigences supplémentaires sur leur propre ligne (n’utilisez pas de puces).

N&apos;utilisez aucun encart.

S&apos;il n&apos;y a pas d&apos;exigences particulières, écrivez : `Compatible with all agent versions.`

## Description

Décrivez le comportement de l&apos;appel avec autant de détails que possible. Ne décrivez pas ce que font les paramètres individuels sauf dans les grandes lignes ; les détails des paramètres et des variantes d&apos;appel appartiennent à la rubrique `Parameters`. De même, ne décrivez pas les valeurs de retour.

Lors d’un renvoi à un autre appel d&apos;API, formatez son nom avec des blocs de code et incluez des parenthèses `()` comme ceci : `anotherCoolMethod()`.

<Callout variant="tip">
  Vous pouvez inclure des encarts, mais faites preuve de discrétion. Ces pages sont déjà visuellement chargées.
</Callout>

## Exemples

Cette section documente les règles pour les cas particuliers qui ne sont pas explicites. Le reste des exemples est intégré dans la page elle-même. En général, cette page est destinée à servir de référence de style. Pour des exemples sur la façon d’écrire de bonnes pages de méthodes d’API, consultez nos documentations d’API existantes, telles que l’ [API PHP](/docs/agents/php-agent/php-agent-api).

### Consignes relatives aux URL

Pour l&apos;URL de la documentation :

* Modifiez manuellement le slug de l&apos;URL pour supprimer le nom de l&apos;agent.
* Lorsque l&apos;appel d&apos;API n&apos;inclut pas déjà de séparateurs (comme dans `newrelic_awesome_call`), séparez les bits avec des tirets `-`.

Par exemple:

```
https://docs.newrelic.com/docs/new-relic-only/advanced-style-guide/writing-guidelines/api-style-guidelines
```

### Consignes relatives aux titres

Pour le titre de la documentation :

* Incluez le nom de la méthode et le nom de l’agent entre parenthèses.
* N&apos;incluez pas les préfixes `newrelic.` à moins qu&apos;ils ne fassent partie intégrante du nom de l&apos;appel (comme dans l&apos;agent PHP).
* N’incluez pas de parenthèses `()` dans l’appel lui-même.

Par exemple:

```
apiStyleGuidelines (Example agent API)
```

### Directives de titre court [#short-title-guideliens]

Pour le titre abrégé de la documentation :

* N&apos;incluez que le nom de la méthode.
* N&apos;incluez pas les préfixes `newrelic.` à moins qu&apos;ils ne fassent partie intégrante du nom de l&apos;appel (comme dans l&apos;agent PHP).
* N&apos;incluez pas les parenthèses `()`.
* Ajustez si nécessaire pour tenir sur une seule ligne dans la barre latérale de la catégorie.

Par exemple:

```
apiStyleGuidelines
```

### Consignes de syntaxe

<Callout variant="important">
  Les agents Python et iOS utilisent leurs propres directives. Pour ces directives, consultez les méthodes existantes dans ces langages.
</Callout>

* Documentez chaque variante d’un appel sur sa propre ligne.
* N&apos;utilisez aucune mise en forme, à l&apos;exception de la mise en italique du type de données.
* Placez les paramètres facultatifs (y compris le séparateur virgule) entre crochets `[]`.
* Indiquez la partie variable en la faisant précéder d’un signe dollar `$`.
* Si l’appel doit être préfixé par `newrelic.` ou similaire, incluez-le dans la syntaxe.
* Facultatif : incluez la valeur de retour, si cela semble important pour votre agent particulier. Si vous le faites, suivez les conventions linguistiques.
