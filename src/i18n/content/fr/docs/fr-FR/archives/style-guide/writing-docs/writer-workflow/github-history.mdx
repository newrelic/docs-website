Les fonctionnalités de contrôle de version de GitHub nous permettent de voir l&apos;historique complet d&apos;un document, d&apos;accéder à un document à tout moment et de trouver les documents supprimés sans sauvegardes manuelles.

## Vérifiez l&apos;historique des modifications d&apos;un document ou d&apos;un fichier [#doc-history]

Utilisez l&apos;une de ces options pour vérifier ou faire un « diff » de l&apos;historique d&apos;un fichier.

**Option 1 : onglet d’historique GitHub**

1. Accédez au document sur le site de documentation et cliquez sur **Edit page** dans la navigation de droite.
2. Cliquez sur **History** dans le coin supérieur droit du document.

**Option 2 : githistory.xy**

1. Accédez à votre fichier spécifique sur GitHub.com :

   ```
   https://github.com/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

2. Dans l&apos;URL, remplacez `github.com` par `github.githistory.xyz`:

   ```
   https://github.githistory.xyz/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

3. Cela vous mènera à un site qui présente l’historique visuel de ce fichier spécifique. Vous pouvez afficher les modifications en cliquant sur l’historique des commits en haut de votre page.

**Option 3 : Git blame**

Suivez la [documentation de GitHub](https://docs.github.com/en/github/managing-files-in-a-repository/managing-files-on-github/tracking-changes-in-a-file).

Alternativement, vous pouvez utiliser la commande suivante dans votre terminal :

```bash
git log --follow "**/file_name_here.mdx"
```

Cela affichera l’historique des commits de ce fichier. Par défaut, cela n’affiche que les premiers commits. Vous pouvez faire défiler en appuyant plusieurs fois sur `Return`.

Par exemple, pour trouver l’historique des commits pour `vmware-vsphere-monitoring-integration.mdx`, exécutez :

```bash
git log --follow "**/vmware-vsphere-monitoring-integration.mdx"
```

## Historique du site de documentation avant octobre 2021 [#archived-version]

Nous avons eu une grande restructuration du site en octobre 2021 qui a perdu la majeure partie de l’historique des fichiers pour notre documentation. Vous pouvez trouver une version archivée de notre site avant la refonte dans la branche [pre-IA-2021](https://github.com/newrelic/docs-website/tree/pre-IA-2021). En naviguant dans la version avant refonte de notre référentiel (repository), vous pouvez trouver l’historique des fichiers et plus encore.

## Comment trouver les fichiers supprimés [#deleted-files]

Il existe plusieurs façons de trouver des fichiers supprimés. Celles-ci sont approximativement classées par complexité :

<CollapserGroup>
  <Collapser className="freq-link" id="pr" title="Trouver la PR de suppression">
    Le moyen le plus simple de trouver un fichier supprimé est de trouver la demande de tirage qui l&apos;a supprimé. Il existe plusieurs façons d&apos;y parvenir ; voici quelques idées :

    1. Utilisez la fonctionnalité de recherche de GitHub pour rechercher des mots-clés pertinents. Vous pouvez filtrer les résultats de recherche pour n’inclure que les PR.
    2. Si vous avez une idée approximative du moment où la documentation a été supprimée, vous pouvez essayer de trouver la demande de tirage dans l’onglet des demandes de tirage. Cette liste contient des milliers de demandes de tirage, cela peut donc prendre un certain temps.
    3. De nombreuses documentations sont supprimées en raison d’un ticket Jira. Recherchez le ticket dans Jira, où vous trouverez l’heure approximative à laquelle la documentation a été supprimée et, espérons-le, un lien vers la demande de tirage elle-même.
    4. Demandez dans #doc\_talk !
  </Collapser>

  <Collapser className="freq-link" id="releases" title="Rechercher dans les PR de sortie">
    En cherchant dans les PR de sortie, vous pouvez éventuellement trouver une branche créée avant que le document ne soit supprimé. Vous pouvez trouver une liste des PR de sortie dans l&apos;[onglet PR de GitHub](https://github.com/newrelic/docs-we.bsite/pulls?q=is%3Apr+release+is%3Aclosed).

    Quelques conseils :

    * Recherchez d&apos;abord par intervalles d&apos;un mois. Une fois que vous avez trouvé une branche qui contient le document, vous pouvez réduire la portée à une semaine, puis à un jour. En réduisant la portée, vous finirez par trouver le document supprimé dans son état exact avant sa suppression.
    * Pour accéder à la branche d&apos;où provient une demande de tirage, allez sur la page de cette demande de tirage et cliquez sur le nom de la branche sous le titre et le numéro de la demande de tirage.
  </Collapser>

  <Collapser className="freq-link" id="git-log" title="Utilisez git log">
    Le moyen le plus puissant et le plus fiable de trouver des fichiers supprimés est d&apos;utiliser `git log`. Voir [StackOverflow](https://stackoverflow.com/questions/7203515/how-to-find-a-deleted-file-in-the-project-commit-history/7203551#7203551) pour plus de détails.
  </Collapser>
</CollapserGroup>
