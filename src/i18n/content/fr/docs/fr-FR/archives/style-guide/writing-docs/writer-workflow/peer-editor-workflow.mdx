Utilisez ce document pour apprendre à réviser et à corriger les documents de vos collègues rédacteurs dans GitHub. Consultez le [document sur le workflow des rédacteurs techniques](/docs/style-guide/writer-workflow/tech-writer-workflow/) pour obtenir des informations sur la configuration de votre environnement local. Pour résoudre les problèmes liés à GitHub, consultez [notre guide](/docs/style-guide/writing-docs/writer-workflow/github-troubleshooting/).

## Quand demander une révision [#when-to-get-review]

Presque toutes les PR sur le site de documentation provenant d&apos;un rédacteur technique devraient faire l&apos;objet d&apos;une révision par un autre rédacteur technique. Nous effectuons des révisions afin de :

* Repérer les inexactitudes
* Respecter notre guide de style
* Améliorer notre rédaction, en particulier la voix et le ton
* Obtenez une perspective différente (par exemple, en apprenant quelque chose de lié au travail qui était inconnu)

Les révisions sont importantes, et la règle par défaut devrait être de toujours obtenir une révision ! Gardant cela à l&apos;esprit, si vous êtes certain que votre PR est de portée limitée et qu&apos;elle ne bénéficiera probablement pas des considérations ci-dessus, vous pouvez fusionner votre PR sans révision. Que vous obteniez ou non une révision de PR, il est de votre responsabilité en tant que rédacteur de vous assurer que votre PR se compile correctement et passe toutes les vérifications techniques.

Voici quelques exemples d’éléments que vous pourriez décider de fusionner sans révision :

* Correction des liens rompus
* Modifications de quelques mots ou lignes d&apos;un document
* Une simple recherche et remplacement d&apos;un mot/d&apos;une expression dont vous êtes sûr qu&apos;il est simple et sans problème
* Une modification particulièrement urgente (dans ce cas, vous pouvez décider d&apos;obtenir une révision plus tard)
* Modifications que vous avez apportées en réponse à une révision de PR et qui, selon vous, ne nécessitent pas de révision supplémentaire.

Si vous avez le moindre doute sur la nécessité d&apos;obtenir une révision de votre PR, demandez-en une.

## Workflow d’édition par les pairs dans GitHub [#peer-edit]

Si vous révisez un document avec un pair ou si vous avez été assigné à une PR en tant que réviseur, vous avez plusieurs choix quant à la manière et à l’endroit où effectuer le travail. L’approche la plus simple et open source consiste à effectuer la modification à l’aide des options de GitHub, plutôt que de copier le fichier dans Google Docs et de le modifier à cet endroit.

### Passe de révision structurelle [#edit-pass]

Pour les cas où vous avez des questions et des suggestions plutôt que de simples modifications de texte, suivez ces étapes.

1. Ouvrez la PR que vous êtes chargé de réviser.

2. Dans l&apos;onglet Files changed, vous pouvez soit :

   * Cliquez sur Review changes, puis sélectionnez l’une des options suivantes :

     * **Commentaire** – utilisez cette option si vous avez un commentaire qui ne nécessite pas de suivi.
     * **Approuver** – utilisez cette option si vous souhaitez simplement approuver la PR. Vous pouvez demander des modifications dans la zone Laisser un commentaire, et sélectionner Approuver si vous souhaitez laisser le rédacteur effectuer les modifications et fusionner le fichier sans examen de suivi de votre part.
     * **Demander des modifications** – à utiliser lorsque vous voulez vous assurer que les modifications que vous demandez sont incluses. Vous serez informé de toutes les mises à jour que le rédacteur effectue.

   * OU, commencez à faire des commentaires sur des lignes ou des sections du document. Pour ce faire, cliquez sur l’icône d’ajout de commentaire, et laissez une modification ou un commentaire pour cette ligne spécifique dans la page. Avec cette option, vous avez le choix entre ajouter un seul commentaire ou commencer une révision. Si vous allez faire des commentaires tout au long d’un document, choisissez **Start a review** afin que les commentaires soient tous regroupés dans un seul commit.

3. Cliquez sur **Finish your review** pour terminer votre révision. Cela déclenche une notification au rédacteur pour l’avertir que vous avez fait des suggestions.

### Workflow de correction [#edit-copy]

Si vous avez des modifications de texte pour un fichier plutôt que des commentaires et des suggestions, vous pouvez apporter les modifications au fichier de différentes manières. Voici deux options principales :

1. Modifiez à l&apos;aide du navigateur GitHub : dans l&apos;onglet **Files changed**, dans la fenêtre de diff, cliquez sur le bouton d&apos;édition (trois points). Lorsque vous avez terminé vos modifications, ajoutez un commentaire au bas du fichier et choisissez de **valider les modifications directement**, ou de **créer une branche et de démarrer une demande de tirage**. Choisissez de créer une branche et de démarrer une demande de tirage si vous attendez d&apos;un rédacteur qu&apos;il examine le diff et accepte ou révise vos modifications.
2. Modifiez localement : extrayez la branche contenant le fichier que vous souhaitez modifier. Dans GitHub Desktop, cliquez sur la flèche vers le bas de la branche actuelle et sélectionnez la branche. Ensuite, effectuez les modifications sur votre lecteur local, enregistrez et validez vos modifications dans la branche.
   * Notez que cette approche ajoute vos modifications à la demande de tirage ouverte. Vous pouvez maintenant voir les modifications que vous avez ajoutées au fichier dans l’onglet **Fichiers modifiés** de la demande de tirage.

Ce ne sont là que quelques-unes des nombreuses options d&apos;édition. Vous trouverez votre méthode préférée, tout comme avec n&apos;importe quel autre outil.
