Cette documentation contient des informations et des procédures relatives à la structure du site de documentation, notamment : les fichiers de navigation, la barre latérale, la structure des dossiers ou des fichiers, et plus encore.

Pour de brèves instructions sur les cas d’utilisation courants, consultez la section [Procédures](#procedures), mais si vous entreprenez des projets de site de documentation plus vastes, il est recommandé de comprendre les [concepts généraux](#understand) au préalable.

## Termes [#terms]

Lorsque l’on parle de la structure du site de documentation, les gens utilisent parfois des mots différents pour désigner les mêmes choses. Vous trouverez ci-dessous une liste de termes qui peuvent nous aider à communiquer sur la structure du site de documentation :

* **Fichiers de documentation**: tous les documents sont représentés par des .mdx fichiers, également connus sous le nom de fichiers markdown.
* **Fichiers de navigation**: les fichiers de navigation régissent la structure affichée du site de documentation, telle qu&apos;elle est exposée dans la barre latérale gauche du site de documentation. Les fichiers de navigation sont des fichiers yaml situés dans le répertoire `src/nav`.
* **Dossier**: dans ce contexte, « dossiers » fait référence à la structure réelle des dossiers du site de documentation (ces dossiers et fichiers dans le répertoire `content`). Faire référence aux « dossiers » peut être un moyen utile de différencier la structure réelle des dossiers de la structure affichée qui est définie à l&apos;aide des fichiers de navigation.
* **Barre latérale**: sur les documents publics, la barre latérale est ce qui est visible sur le côté gauche, montrant la structure de cette catégorie de documents. La structure de la barre latérale est déterminée par la structure définie dans le fichier de navigation.
* **Catégorie** ou **sous-catégorie**: nous utilisons ces mots de manière assez interchangeable pour désigner des zones spécifiques du site de documentation. Par exemple, nous pourrions faire référence à la catégorie « Comptes », ou à la catégorie « Gérer les données ».
* **Pages d’auto-indexation** (obsolète) : cela fait référence à une implémentation précédente où les utilisateurs pouvaient charger des vues des documents dans une catégorie spécifique (par exemple, en cliquant sur un en-tête de catégorie dans la barre latérale). Nous ne prenons plus en charge cette implémentation.

## Comprendre le fonctionnement de la structure du site de documentation [#understand]

Cette section expliquera une partie de la logique derrière la façon dont la structure du site de documentation est déterminée et comment la structure que nous affichons au public est liée à la structure réelle des dossiers.

### Comment la structure affichée est-elle liée aux dossiers réels ? [#folders-vs-categories]

La structure réelle du dossier de documentation (les dossiers et les fichiers mdx dans le dossier `content`) est entièrement distincte de la structure du site de documentation dans la barre latérale. La structure affichée dans la barre latérale est déterminée uniquement par les fichiers de navigation (les fichiers au format yaml dans le dossier `src/nav`).

Il est important de comprendre le point ci-dessus. La divergence entre la structure du dossier de documentation et la structure affichée du site de documentation est nécessaire : nous avons besoin d&apos;un moyen de contrôler la structure affichée dans la barre latérale sans nous obliger à garder la structure des dossiers, les noms de dossiers et les noms de fichiers de documentation complètement équivalents. Parce que ces deux éléments sont distincts, cela peut signifier qu&apos;il peut y avoir des aspects peu intuitifs dans le fonctionnement de cette logique.

Nous avons des [procédures pour les cas d’utilisation courants](#procedures), mais il vous sera très utile de comprendre les spécificités ci-dessous sur la façon dont la structure affichée est générée.

### Qu’est-ce qui détermine l’URL d’un document ? [#doc-url]

L’emplacement d’un fichier de documentation (fichier `mdx`) dans le dossier `content`, ainsi que les noms de dossier et de fichier associés, sont les seuls facteurs qui régissent l’URL de cette documentation.

Par exemple, considérez le fichier de documentation suivant `automated-user-provisioning-single-sign.mdx`:

<img title="Doc file in its folder" alt="Example of a doc file in the folder structure" src="/images/style-guide_screenshot-full_doc-in-folder-structure.webp" />

L&apos;URL de cette documentation est uniquement basée sur l&apos;emplacement de son dossier et le nom des dossiers. Dans ce cas, son URL est :

```
docs.newrelic.com/docs/accounts/accounts/automated-user-management/automated-user-provisioning-single-sign
```

Cela a des implications importantes, notamment :

* Lorsque vous déplacez un document d’un dossier à un autre, son URL change. Cela signifie que lorsque vous déplacez un fichier de document, vous devez ajouter une redirection vers ce document à partir de son URL d’origine.
* Si vous renommez un nom de fichier mdx ou un nom de dossier, cela modifie son URL. Cela signifie que vous devez ajouter une redirection vers ce document de son URL d’origine.

### À quoi sert un fichier nav ? [#nav-file-contents]

Les fichiers de navigation sont assez simples. Un fichier de navigation contrôle la structure affichée des documents que vous voyez dans la barre latérale. Actuellement, il existe plusieurs fichiers de navigation, un pour chaque section principale de la documentation. Par exemple, il existe un fichier de navigation pour &quot;Accounts&quot;, qui contient les paramètres liés à l&apos;organisation et au compte. Et il y a un fichier de navigation pour le &quot;monitoring d&apos;infrastructure.&quot;

Pour en savoir plus sur le format de fichier de navigation, consultez [Format de fichier de navigation](#nav-format)

### Qu’est-ce qui régit l’affichage d’une barre latérale ? [#doc-sidebar]

Comme indiqué ci-dessus, la barre latérale n’est qu’une des façons dont la structure du site de documentation (qui est régie par les fichiers de navigation) est exposée.

Lorsqu’un document est chargé, le site de documentation recherche cette URL dans tous les fichiers de navigation. S’il trouve une correspondance, il affiche ce fichier de navigation dans la barre latérale avec ce document mis en évidence.

L&apos;URL d&apos;un document peut exister dans plus d&apos;un fichier de navigation. Actuellement, la règle veut qu&apos;un document ne puisse se trouver qu&apos;à un seul endroit dans tous les fichiers de navigation. Mais nous avons encore des documents qui existent dans plusieurs fichiers de navigation. Dans ces cas, notre site tente de trouver le fichier de navigation approprié en choisissant le fichier de navigation qui correspond à la catégorie de niveau supérieur dans l&apos;URL du document. Par exemple, si un document avec l&apos;URL relative `/docs/accounts/accounts-billing/account-setup/create-your-new-relic-account` se trouvait dans deux fichiers de navigation, le code du site de documentation chercherait à voir si l&apos;un des fichiers de navigation a `docs/accounts` comme premier champ `path`. S&apos;il trouve une correspondance, il utilise ce fichier de navigation.

## Format de fichier de navigation [#nav-format]

Vous trouverez ci-dessous un snippet du fichier de navigation [`agents.yml`](https://github.com/newrelic/docs-website/tree/develop/src/nav/agents.yml). Veuillez noter que le fichier présente une indentation qui correspond au niveau de la hiérarchie de navigation. Lors de la modification ou de la création d&apos;un nouveau fichier de navigation, assurez-vous d&apos;utiliser le format d&apos;espacement existant.

```yml
title: Agents
path: /docs/agents
pages:
  - title: Manage APM agents
    pages:
      - title: Agent data
        pages:
          - title: Real time streaming
            path: /docs/agents/manage-apm-agents/agent-data/real-time-streaming
          - title: Custom instrumentation
            path: /docs/agents/manage-apm-agents/agent-data/custom-instrumentation
          - title: Agent attributes
            path: /docs/agents/manage-apm-agents/agent-data/agent-attributes
          - title: Custom events
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-events
          - title: Custom metrics
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-metrics
          - title: Manage errors
            path: /docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected
          - title: Link Kubernetes
            path: /docs/agents/manage-apm-agents/agent-data/link-your-applications-kubernetes
      - title: App naming
        pages:
          - title: Name your application
            path: /docs/agents/manage-apm-agents/app-naming/name-your-application
          - title: Use multiple names for an app
            path: /docs/agents/manage-apm-agents/app-naming/use-multiple-names-app
```

<Callout variant="tip">
  L&apos;imbrication de la navigation est actuellement limitée à un maximum de six niveaux de profondeur. Veuillez contacter l&apos;équipe d&apos;ingénierie si cela ne suffit pas.
</Callout>

### Aperçu des étapes d&apos;un grand projet de restructuration de site de documentation [#large-project]

Pour certaines modifications mineures du site de documentation, vous pouvez parfois simplement modifier les fichiers de navigation et ne pas avoir à toucher aux fichiers ou dossiers de documentation. Mais pour les projets plus importants, vous voudrez ou devrez peut-être modifier et déplacer les fichiers et dossiers de documentation eux-mêmes. Vous trouverez ci-dessous un aperçu général des blocs de travail que ces projets plus importants impliquent généralement.

1. Planifiez à quoi ressemblera la nouvelle structure du fichier de navigation et planifiez le travail de déplacement des fichiers de documentation ou de création de nouveaux dossiers. Il peut être utile de noter les différentes tâches qu’un grand projet impliquera.
2. Déplacez les fichiers de documentation concernés vers leurs nouveaux emplacements de dossier, en vous assurant d&apos;ajouter des redirections. Pour en savoir plus à ce sujet, consultez [Déplacer des documents entre les dossiers](#move-docs-between-folders).
3. Supprimez tous les dossiers vides.
4. Pour toute modification de dossier ou de fichier que vous apportez à la structure de fichiers elle-même (y compris le renommage de fichiers ou de dossiers, le déplacement de fichiers et de dossiers, mais **pas** la modification du contenu ou du front matter dans un fichier de documentation ou de navigation), effectuez les mêmes modifications sur les dossiers et les fichiers du répertoire `i18n`. Tous les dossiers ou fichiers ne seront pas présents dans le répertoire i18n : il ne remplit un fichier mdx ou un dossier associé que si ce fichier mdx a été marqué pour la traduction.
5. Modifiez les fichiers de navigation pour refléter la nouvelle structure souhaitée et pointer vers les nouvelles URL de document.

Pour des procédures plus spécifiques et granulaires, continuez à lire.

### Ajouter une nouvelle catégorie de documents [#add-category]

Nous expliquerons deux procédures : l&apos;ajout d&apos;une sous-catégorie de documentation dans un fichier de navigation existant, et l&apos;ajout d&apos;un tout nouveau fichier de navigation :

#### Ajouter une nouvelle catégorie à un fichier de navigation [#add-nav-section]

Pour ajouter une nouvelle catégorie à un fichier de navigation :

1. Dans un fichier de navigation existant, ajoutez une nouvelle catégorie, représentée par son `title`.
2. Ajoutez les documents que vous souhaitez dans cette section, en émulant le format et l&apos;indentation des autres fichiers de navigation.

Pour en savoir plus sur le fonctionnement, voir :

* [Comment la barre latérale d’une documentation est déterminée](#doc-sidebar)
* [Comment une vue de catégorie de document est déterminée](#category-view)

#### Ajoutez un nouveau fichier de navigation [#add-new-nav]

L&apos;ajout d&apos;un tout nouveau fichier de navigation devrait être rare et nous ne le faisons qu&apos;occasionnellement lors de remaniements importants de la structure du site. L&apos;ajout de nouveaux fichiers de navigation doit être approuvé par un responsable du site de documentation.

Pour ajouter un tout nouveau fichier de navigation :

1. Copiez un fichier de navigation existant, ou créez un nouveau fichier de navigation.
2. Personnalisez le nouveau fichier de navigation avec les catégories et les documents que vous souhaitez, en utilisant le formatage et l&apos;indentation standard du fichier de navigation. Pour en savoir plus sur la structure, consultez le [format de navigation](#nav-format).

### Ajouter une documentation à la barre latérale/fichier de navigation [#add-doc-to-nav]

Une fois que vous [créez un document](/docs/style-guide/writing-guidelines/create-edit-content/#creating-docs), vous devez le placer dans un fichier de navigation. Ne placez pas un document dans plus d&apos;un emplacement de fichier de navigation : si vous avez besoin d&apos;un lien vers un document d&apos;une catégorie différente, essayez de placer cette référence dans une section de document pertinente.

Pour ajouter une documentation à un fichier de navigation :

1. Dans l’emplacement du fichier de navigation où vous souhaitez le placer, ajoutez le `title` (son titre court affiché dans la barre latérale et les vues de catégorie) et le `path`, qui est l’URL de la documentation.
2. Assurez-vous que vous avez émulé le formatage et l’indentation standard du fichier de navigation.

### Déplacer les documents vers d’autres catégories [#move-docs]

Étant donné que le fichier de navigation et la structure réelle des dossiers ne sont pas connectés, il existe deux façons différentes de « déplacer des documents » :

* Déplacez un document dans les fichiers de navigation : procédure préférée et la plus courante.
* Déplacer un document entre les dossiers : moins fréquent, principalement lors de la réalisation de projets plus importants où nous voulons faire une refonte significative de la structure de la documentation et voulons nous assurer que la structure des dossiers ne devienne pas trop divergente de la structure du fichier de navigation.

#### Déplacez les documents à l&apos;aide du fichier de navigation [#move-docs-in-nav-file]

Déplacez un document dans le fichier de navigation lorsque vous souhaitez modifier l’endroit où il est visible dans les menus de la barre latérale.

Pour déplacer un document d’un endroit à un autre dans le fichier nav :

1. Dans le premier fichier de navigation, copiez les deux lignes représentant l&apos;entrée de ce document (les lignes `title` et `path`) et collez ce contenu à l&apos;endroit où vous souhaitez qu&apos;il se trouve dans le nouveau fichier de navigation.
2. Dans la nouvelle section du fichier de navigation, assurez-vous que le formatage et l’indentation correspondent à la structure standard du fichier de navigation. Consultez [Format de navigation](#nav-format) pour en savoir plus sur la structure du fichier de navigation.

#### Déplacer une documentation entre des dossiers [#move-docs-between-folders]

Notez que le déplacement de documents entre les dossiers devrait être relativement rare. Les principales raisons de le faire sont lorsque la structure des dossiers et la structure du fichier de navigation deviennent assez divergentes, ce qui peut être mauvais pour quelques raisons :

* Trop de divergence peut créer de la confusion pour l’utilisateur (par exemple, lorsque les éléments de l’URL basée sur les dossiers sont très différents de l’emplacement basé sur le fichier de navigation) ou des résultats de moteur de recherche sous-optimaux.
* Trop de divergence peut rendre plus difficile pour nous de trouver et de modifier les documents, il peut donc être utile de garder les choses assez à jour et parallèles.

Lorsque vous déplacez un document entre des dossiers ou que vous renommez un document, cela modifie son URL (pour en savoir plus sur les raisons, consultez [Comprendre la structure](#understand)). De même, si vous renommez un dossier, cela modifie l’URL de tous les documents de cette zone.

Pour déplacer un document entre des dossiers :

1. Obtenez l&apos;URL actuelle du document que vous souhaitez déplacer et ajoutez cette URL à sa propre liste de redirections. Conseils :

   * Une façon de le faire dans VSCode est de faire un clic droit sur le nom du fichier et de cliquer sur &quot;Obtenir le chemin relatif&quot;.
   * Si vous déplacez de nombreux fichiers, demandez à l&apos;équipe nos scripts pour ajouter par programmation des redirections à un répertoire de documentation entier.
   * Assurez-vous que les URL de redirection n&apos;ont pas de barre oblique finale.

2. Déplacez le document vers son nouvel emplacement de dossier.

3. Si ce fichier mdx est présent dans le répertoire `i18n` (ce qui sera le cas s’il est marqué pour la traduction), effectuez un déplacement équivalent de ce fichier dans le répertoire `i18n`.

4. **Mettre à jour les fichiers de navigation avec la nouvelle URL**. Il est important d&apos;avoir l&apos;URL correcte du document dans le fichier de navigation, et non une redirection. Notez que l&apos;URL d&apos;un document peut se trouver dans plus d&apos;un fichier de navigation, il peut donc être utile de rechercher cette URL sur le site.

### Déplacer, supprimer ou renommer un dossier [#move-delete-folders]

Parfois, lorsque nous effectuons un projet de restructuration plus important, nous pouvons vouloir déplacer, supprimer ou renommer les dossiers réels au lieu de simplement modifier les fichiers de navigation. Instructions pour cela :

1. Étant donné que le déplacement d’un dossier ou la modification de son nom entraîne la modification de toutes les URL des documents de ce dossier, vous devez d’abord ajouter des redirections aux documents concernés. Vous pouvez le faire manuellement ([décrit à l’étape n° 1 ici](#move-docs-between-folders)) ou vous pouvez utiliser un script dont dispose l’équipe de documentation pour ajouter en masse des redirections à tous les documents d’un répertoire.
2. Effectuez la modification souhaitée. Par exemple, déplacez le dossier vers le nouvel emplacement (en le glissant-déposant dans la fenêtre du Finder, par exemple), et/ou renommez le dossier.
3. Si le dossier modifié est présent dans le répertoire `i18n` (ce qui sera le cas si un document de ce dossier a été marqué pour traduction), effectuez une modification équivalente de ce dossier et de ses fichiers dans le répertoire `i18n`. Remarque : le travail `i18n` n&apos;est nécessaire que pour les déplacements ou le renommage de dossiers ou de fichiers, et **non** pour la modification de documents ou du contenu du fichier de navigation.

Pour supprimer des dossiers, vous devrez essentiellement suivre les mêmes étapes que ci-dessus : ajouter des redirections pour les fichiers mdx déplacés ou supprimés, puis déplacer ou supprimer les documents, et enfin supprimer les dossiers vides.

### Modifier le nom de fichier d&apos;un document [#change-doc-file-name]

La modification du nom d&apos;un fichier mdx [entraîne la modification de son URL](#understand). Notez que vous pouvez modifier le titre affiché d&apos;un document dans son front matter sans modifier le nom réel du fichier. La modification du nom de fichier peut être utile. Instructions :

1. Ajoutez une redirection vers le document dont vous modifiez le nom de fichier.
2. Modifiez le nom du fichier.
3. Si ce fichier est présent dans le répertoire `i18n` (ce qui sera le cas si ce document a été marqué pour la traduction), effectuez une modification équivalente du nom de ce fichier dans le répertoire `i18n`. Remarque : le travail `i18n` n&apos;est nécessaire que pour les déplacements ou le renommage de dossiers ou de fichiers, et **non** pour la modification de documents ou du contenu du fichier de navigation.

### Créer des documents d’espace réservé [#placeholder-doc]

Nous ne voulons plus avoir de documents à plusieurs endroits dans les fichiers de navigation (bien que nous ayons encore quelques documents qui sont comme cela). Si vous souhaitez qu&apos;un document soit référencé à plusieurs endroits dans les fichiers de navigation, essayez plutôt de trouver un endroit dans un document où il est logique de référencer ce document.
