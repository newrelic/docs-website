<DNT>**Vulnerability Identifier:**</DNT> NR26-12

<DNT>**Priority:**</DNT> Haut

## Résumé

Entre le 17 octobre et le 20 octobre 2026, des chercheurs ont révélé que les clés privées de huit certificats d&apos;autorité de certification (CA) intermédiaires émis par eMudhra pouvaient être récupérées. Toute personne possédant ces clés pourrait créer des certificats que les logiciels accepteraient comme authentiques s&apos;ils leur font toujours confiance. Bien que les principaux systèmes d&apos;exploitation et navigateurs web aient déjà révoqué la confiance accordée à ces certificats, les applications gérant des magasins de confiance de CA indépendants, y compris certaines images de conteneurs, doivent être mises à jour.

New Relic a reconstruit les images de conteneur qu’il fournit pour les sites privés Synthetics, afin qu’elles n’utilisent plus ces certificats. Les clients qui exécutent des sites privés Synthetics doivent récupérer les nouvelles images, et redémarrer leurs conteneurs, car les images ne sont pas mises à jour automatiquement.

Pour identifier les moniteurs qui s’exécutent encore sur le runtime legacy, exécutez la requête NRQL suivante dans le générateur de requêtes de votre compte :

```sql
SELECT uniques(monitorName) FROM SyntheticCheck WHERE runtimeType = 'NODE_API' AND runtimeTypeVersion = '16.10' SINCE 1 day ago
```

Vous pouvez également identifier les moniteurs affectés dans l&apos;[écran Synthetics EOL](https://onenr.io/0gR77nzxaRo) de l&apos;UI de New Relic. Filtrez par **Monitor Type: Script API** pour afficher tous les moniteurs s&apos;exécutant encore sur Node.js 16.10.

### Avis important : migration Node.js 16.x requise (sites publics et privés) [#node-16-migration]

Les moniteurs d&apos;API scriptés s’exécutant sur Node.js 16.10 atteindront leur [fin de vie](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/) le 18 novembre 2026. Ces moniteurs sont exposés aux vulnérabilités eMudhra, et les moniteurs s’exécutant encore sur ces anciennes versions doivent être migrés vers Node.js 22.23.0. Cela s’applique que vos moniteurs s’exécutent sur un emplacement public ou un site privé.

**Action recommandée :** à partir du 18 novembre 2026, New Relic mettra automatiquement à niveau les moniteurs d’emplacement public s’exécutant encore sur Node.js 16.x vers l’environnement d’exécution actuel. Nous vous recommandons vivement de migrer dès que possible, avant cette date, afin que vous puissiez tester que vos moniteurs continuent de fonctionner comme prévu sur le nouvel environnement d’exécution, et d’abandonner la version vulnérable. Pour obtenir des instructions, consultez [Mettre à niveau les moniteurs d’API scriptés vers Node.js 22](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/).

## Informations sur les vulnérabilités techniques

Aucune CVE n&apos;a été attribuée pour ce problème.

## Questions fréquemment posées

1. **L’infrastructure de l’emplacement public de New Relic a-t-elle été affectée ?**

   New Relic a corrigé l&apos;infrastructure d&apos;emplacement public s&apos;exécutant sur le dernier environnement d&apos;exécution. Cependant, les moniteurs explicitement épinglés à Node.js 16.x continueront à s&apos;exécuter sur cette version jusqu&apos;à ce qu&apos;ils soient mis à jour par le propriétaire du compte.

2. **Des résultats de monitoring ont-ils été falsifiés ?**

   New Relic n’a aucune preuve d’altération de nos images Synthétiques.

3. **Dois-je effectuer une rotation des identifiants stockés dans les identifiants sécurisés de Synthetics ?**

   Aucune action n’est requise à moins que vous n’ayez une raison spécifique de croire que votre réseau et votre infrastructure ont été compromis.

4. **Qui puis-je contacter si j’ai encore des questions ?**

   Ouvrez un ticket auprès de notre équipe de support via la section d’aide de la plateforme New Relic.
