<DNT>**Vulnerability Identifier:**</DNT> NR26-14

<DNT>**Priority:**</DNT> Haut

## Résumé

Entre le 17 octobre et le 20 octobre 2026, des chercheurs ont révélé que les clés privées de huit certificats d’autorité de certification (CA) intermédiaires émis par eMudhra peuvent être récupérées (CVE-2026-111943). Toute personne possédant ces clés peut créer des certificats que les logiciels accepteraient comme authentiques s’ils leur font toujours confiance. Les navigateurs et les systèmes d’exploitation ont bloqué les certificats, mais les logiciels qui intègrent leur propre liste d’autorités de certification de confiance, y compris certaines images de conteneurs, doivent être mis à jour.

New Relic a mis à jour les composants Kubernetes ci-dessous afin qu’ils n’acceptent plus les certificats émis par ces CA. Les versions mises à jour ne sont pas récupérées automatiquement. Les clients doivent effectuer une mise à niveau vers les versions répertoriées ci-dessous.

## Informations sur les vulnérabilités techniques

* Huit autorités de certification intermédiaires qui forment une chaîne vers emSign ECC Root CA - G3 et, par signature croisée, vers AAA Certificate Services, sont concernées.

* Les images basées sur Alpine corrigées sont construites sur Alpine 3.24.3 avec ca-certificates 20261020-r0, ce qui supprime emSign ECC Root CA - G3 et AAA Certificate Services du bundle de CA.

  * k8s-agents-operator 0.54.0 est construit sur une base distroless avec les deux racines supprimées.
  * prometheus:v3.15.1 (en amont) fournit également un bundle CA sans aucune des deux racines.

* Les binaires de l’intégration Kubernetes de New Relic sont compilés avec Go 1.27.3, dont la bibliothèque TLS refuse les chaînes de certificats qui contiennent les huit clés affectées, même si la racine est toujours approuvée. Certaines intégrations sur hôte incluses dans infrastructure-bundle utilisent des versions de Go antérieures ; leur bundle CA est toujours fixe.

* L&apos;exposition est limitée aux connexions qui utilisent le magasin racine public : les connexions des agents aux points de terminaison New Relic et à tout proxy configuré. Les connexions à l&apos;intérieur du cluster (serveur d&apos;API Kubernetes, kubelet, control plane) utilisent la propre CA du cluster et ne sont pas affectées.
