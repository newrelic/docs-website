<DNT>**Vulnerability Identifier:**</DNT> NR26-15

<DNT>**Priority:**</DNT> Haut

## Résumé

Entre le 17 octobre et le 20 octobre 2026, des chercheurs ont révélé que les clés privées de huit certificats d’autorité de certification (CA) intermédiaires émis par eMudhra peuvent être récupérées (CVE-2026-111943). Toute personne possédant ces clés peut créer des certificats que les logiciels accepteraient comme authentiques s’ils leur font toujours confiance. Les navigateurs et les systèmes d’exploitation ont bloqué les certificats, mais les logiciels qui intègrent leur propre liste d’autorités de certification de confiance, y compris certaines images de conteneurs, doivent être mis à jour.

New Relic a mis à jour l&apos;agent d&apos;infrastructure, ses images de conteneur et les intégrations sur hôte ci-dessous afin qu&apos;ils n&apos;acceptent plus les certificats émis par ces CA. Les versions mises à jour ne sont pas récupérées automatiquement. Les clients doivent effectuer une mise à niveau vers les versions répertoriées ci-dessous.

**\* Note de mise à niveau.**

* L&apos;agent d&apos;infrastructure 2.0 est une version majeure. Il active safe\_dir\_check\_enabled par défaut, l&apos;agent ne réutilise donc plus un répertoire de travail qui est un lien symbolique, qui n&apos;appartient pas à l&apos;utilisateur ou au groupe de l&apos;agent, ou qui est accessible en écriture par le groupe ou d&apos;autres. Il recrée le répertoire à la place. Définissez safe\_dir\_check\_enabled sur false pour conserver le comportement précédent. Consultez les notes de sortie avant la mise à niveau. Consultez le lien ci-dessous pour les notes de sortie.
* Sur Windows, la version 2.0 supprime Fluent Bit 1.9 legacy du programme d’installation. Le transfert de logs utilise Fluent Bit 5.1.5.

## Informations sur les vulnérabilités techniques

* Huit autorités de certification intermédiaires qui forment une chaîne vers emSign ECC Root CA - G3 et, par signature croisée, vers AAA Certificate Services, sont concernées.
* L&apos;agent d&apos;infrastructure et les intégrations sur hôte sont compilés avec Go 1.27.3 ou Go 1.26.10. Les deux incluent le correctif Go pour `CVE-2026-111943: crypto/x509` qui refuse les chaînes de certificats qui contiennent les huit intermédiaires concernés, même si la racine est toujours approuvée.
* Les images `newrelic/infrastructure` 2.0.1 et `newrelic/infrastructure-bundle` 3.6.1 sont basées sur Alpine 3.24.3 avec ca-certificates 20261020-r0, qui supprime emSign ECC Root CA - G3 et AAA Certificate Services du bundle CA.
  * Le magasin de confiance Java dans `newrelic/infrastructure-bundle` 3.6.1, utilisé par les intégrations basées sur JMX, ne contient aucune des deux racines.
* Sur les hôtes, l’agent et les intégrations utilisent le magasin de confiance du système d’exploitation. Appliquez également la mise à jour ca-certificates de l’éditeur de votre système d’exploitation.
* nri-jmx, nri-kafka et nri-cassandra collectent les métriques JMX via nr-jmx, qui s’exécute sur votre environnement d’exécution Java et utilise son magasin de confiance, ou le magasin de confiance défini dans la configuration de l’intégration. Appliquez également la mise à jour de votre fournisseur Java.
* L’exposition est limitée aux connexions qui utilisent le magasin racine public : les connexions de l’agent aux points de terminaison New Relic et à tout proxy configuré, ainsi que les connexions TLS de l’intégration aux services qu’elle monitore.

## Questions fréquemment posées

1. **Est-il sûr de supprimer les certificats concernés du bundle d&apos;autorités de certification dans mes images d&apos;agent ?**

   Oui. Les points de terminaison New Relic n&apos;utilisent pas de certificats émis par les autorités de certification concernées, leur suppression n&apos;affecte donc pas la connexion de l&apos;agent à New Relic. Si une intégration se connecte via TLS à l&apos;un de vos services dont la chaîne de certificats remonte à emSign ECC Root CA - G3 ou AAA Certificate Services, cette connexion échoue après la suppression. Vérifiez d&apos;abord ces certificats.

2. **Quelles versions de l&apos;agent peuvent être utilisées en toute sécurité dans mes images ?**

   Agent d&apos;infrastructure 2.0.1 ou version ultérieure, `newrelic/infrastructure-bundle` 3.6.1 ou version ultérieure, et les versions d&apos;intégration sur hôte listées ci-dessus.

3. **Qui puis-je contacter, car j&apos;ai encore quelques questions ?**

   Si une assistance supplémentaire est nécessaire, ouvrez un ticket auprès de notre équipe de support via la section d&apos;aide de la plateforme New Relic.
