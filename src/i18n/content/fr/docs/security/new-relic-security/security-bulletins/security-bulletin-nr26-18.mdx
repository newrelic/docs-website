<DNT>**Vulnerability Identifier:**</DNT> NR26-18

<DNT>**Priority:**</DNT> Critique

## Résumé

Une vulnérabilité critique (score CVSS 4.0 de 9,2) a été divulguée dans l’extension de session de l’environnement d’exécution PHP. Elle affecte les applications qui utilisent le gestionnaire de session de fichiers par défaut de PHP. Le projet PHP a sorti des correctifs le 19 novembre 2026.

Les sorties de correctifs d&apos;octobre 2026 pour CVE-2026-109618 et CVE-2026-109619 ([NR26-10](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-10)) n&apos;incluent pas ce correctif. Les applications qui conservent les sessions dans une base de données ou Redis au lieu du gestionnaire de fichiers natif ne sont pas concernées par ces vulnérabilités.

**Les logiciels et services distribués par New Relic ne sont pas affectés.** New Relic ne fournit pas d’environnement d’exécution PHP dans les logiciels distribués aux clients. L’agent PHP New Relic s’exécute dans le propre environnement PHP des clients, et n’est pas le composant vulnérable. L’agent PHP s’exécute en tant qu’extension dans l’interpréteur PHP existant des clients, ce qui signifie que la remédiation est gérée en mettant à niveau PHP lui-même. New Relic n’a identifié aucune preuve d’exploitation dans son environnement.

## Action recommandée

Aucune action n’est requise concernant vos logiciels et services New Relic. Néanmoins, New Relic encourage vivement les clients qui exécutent des applications PHP, avec ou sans l’instrumentation New Relic, à mettre à niveau vers la sortie corrigée pour leur branche, et à redémarrer tous les workers PHP. Les mêmes sorties corrigent 17 avis de sécurité, une seule mise à niveau les couvre donc tous.

### Recommandations

* **Packages de distribution :**
  * Une distribution peut inclure le correctif sans modifier la chaîne de version de PHP. Consultez l’avis de sécurité de votre fournisseur au lieu de vous fier au numéro de version.
* **Versions en fin de vie (PHP 8.1 et antérieures) :**
  * Ces versions ne figurent pas dans l’enregistrement CVE et ne reçoivent aucun correctif officiel. Considérez les builds non corrigés comme affectés, vérifiez si votre distribution a rétroporté le correctif et planifiez une mise à niveau vers une branche prise en charge.
* **Hébergement géré :**
  * Confirmez auprès de votre fournisseur que chaque environnement, y compris les environnements de développement, de test, et de prévisualisation, exécute une version corrigée.

## Atténuation temporaire

Seule une mise à niveau de vos environnements d’exécution PHP corrige entièrement cette vulnérabilité. Si vous ne pouvez pas mettre à niveau immédiatement, à titre de mesure temporaire, désactivez `session.upload_progress.enabled` administrativement si la fonctionnalité n’est pas nécessaire, et limitez la quantité de données non fiables stockées dans les sessions. La désactivation de la progression du téléchargement supprime ce chemin d’entrée, mais ne corrige pas les applications qui stockent indépendamment des données de session contrôlées par l’attaquant. Un backend de stockage de session qui remplace les enregistrements de manière atomique peut éviter ce défaut d’écriture de fichier. La mise à jour PHP pour l’environnement d’exécution reste le correctif recommandé pour les applications utilisant le gestionnaire de fichiers intégré. Consultez les Documents de support ci-dessous pour plus de détails.

## Questions fréquemment posées

1. **Comment puis-je savoir quelle version de PHP et quels paramètres de session j’utilise ?**

   Exécutez `php -v` sur l’hôte ou dans le conteneur. Vérifiez session.save\_handler et `session.upload_progress.enabled` dans `phpinfo()` ou `php.ini`. Pour la version de PHP que New Relic voit, consultez les détails de l&apos;hôte ou de l&apos;application dans l&apos;UI de New Relic.

2. **L’agent PHP New Relic doit-il être mis à jour ?**

   Non. La vulnérabilité se trouve dans le runtime PHP, et non dans l’agent. Veuillez mettre à jour votre runtime PHP vers les versions corrigées pour remédier à cette vulnérabilité.

3. **Comment puis-je savoir si mes systèmes ont été ciblés ?**

   Aucun indicateur public de compromission n’a été signalé jusqu’à présent. Les clients doivent examiner leurs logs web à partir du 19 novembre 2026 à la recherche de plantages inexpliqués de workers PHP ou d’arrêts pour mémoire insuffisante et de requests POST multipart non authentifiées vers des points de terminaison PHP. Recherchez également des fichiers PHP nouveaux ou modifiés dans les répertoires web.

4. **J&apos;ai des questions ou des préoccupations concernant cette vulnérabilité. Qui dois-je contacter ?**

   Si vous avez des questions sur cette vulnérabilité en lien avec vos services New Relic, veuillez ouvrir un [ticket d&apos;assistance](/docs/new-relic-solutions/solve-common-issues/find-help-get-support/#file-ticket) via l&apos;assistance intégrée à l&apos;application, ou contacter votre représentant de compte New Relic.
