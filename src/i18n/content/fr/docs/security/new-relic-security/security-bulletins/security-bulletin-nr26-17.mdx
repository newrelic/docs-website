<DNT>**Vulnerability Identifier:**</DNT> NR26-17

<DNT>**Priority:**</DNT> Critique

## Résumé

Le 19 novembre 2026, l’équipe de sécurité de réponse aux incidents de New Relic a commencé une évaluation exhaustive de nos services, et de notre infrastructure d’entreprise face à la vulnérabilité Ruby récemment divulguée &quot;Ruby2Shell&quot; (CVE-2026-132825). Il s’agit d’un dépassement de tampon dans le tas d’un octet lors de la conversion de casse des chaînes de caractères de l’interpréteur Ruby qui pourrait permettre l’exécution de code à distance (RCE), ou un déni de service (DoS).

## Éléments d&apos;action

### Aucune action n’est requise pour les clients utilisant des agents Ruby

Les agents Ruby distribués de New Relic ne sont pas impactés. Les clients de New Relic qui utilisent les agents Ruby n’ont besoin d’entreprendre aucune action pour cette vulnérabilité.

## Questions fréquemment posées

1. **Cela affecte-t-il les agents de New Relic ?**

   Les agents de langage Ruby de New Relic ne sont pas affectés. Les autres agents de langage de New Relic ne sont pas non plus affectés. Les images Fluentd ne sont pas utilisées dans les agents New Relic.

2. **Quels systèmes sont concernés ?**

   Tout environnement d&apos;exécution de conteneur (Kubernetes, Docker, et autres) exécutant les images suivantes :

   * `newrelic/newrelic-fluentd-docker`
   * `newrelic/fluentd`
   * `newrelic/k8s-golang-apm-linkage-demo`

3. **Comment puis-je corriger la vulnérabilité ?**

   Si vous utilisez l&apos;image `newrelic/newrelic-fluentd-docker` :

   1. Téléchargez l&apos;image corrigée :

      ```shell
      docker pull newrelic/newrelic-fluentd-docker:1.20.1
      ```

   2. Recréez vos conteneurs avec la nouvelle image. Le téléchargement d&apos;une image ne met pas à jour les conteneurs qui sont déjà en cours d&apos;exécution. Dans Kubernetes, Docker, ou un autre environnement d&apos;exécution de conteneur, remplacez le tag de l&apos;image par 1.20.1, et redéployez.

   3. Si vous créez vos propres images à partir de `newrelic/newrelic-fluentd-docker`, reconstruisez-les avec `docker build --pull`.

   4. Vérifiez la version en cours d’exécution :

      ```shell
      docker exec <container> fluentd --version
      ```

   5. La sortie devrait afficher `fluentd 1.20.1`, ou une version plus récente.

   Si vous n’utilisez pas l’image `newrelic/newrelic-fluentd-docker`, envisagez d’utiliser [Fluentd](https://www.fluentd.org/) avec le [plug-in Fluentd](/docs/logs/forward-logs/fluentd-plugin-log-forwarding/) de New Relic.

4. **Mon conteneur est-il mis à jour lorsque je télécharge une nouvelle image ?**

   Non. Les conteneurs en cours d&apos;exécution conservent l&apos;ancienne image jusqu&apos;à ce que vous les recréiez.

5. **Le transfert de logs de l’agent d’infrastructure est-il affecté ?**

   Non. Le transfert de logs dans l’agent d’infrastructure et l’intégration Kubernetes utilise [Fluent Bit](/docs/logs/forward-logs/fluent-bit-plugin-log-forwarding/), et non Fluentd.

6. **Que faire si j’ai des questions ?**

   Pour tout besoin d’assistance lié à cette communication, ouvrez un ticket d’assistance via l’assistance intégrée à l’application.
