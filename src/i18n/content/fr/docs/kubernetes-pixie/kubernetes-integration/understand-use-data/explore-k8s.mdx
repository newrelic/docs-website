Les environnements Kubernetes modernes ont évolué en **flottes multi-cluster** complexes, mais les outils d’observabilité traditionnels ne fournissent souvent qu’une vue fragmentée et cloisonnée des cluster individuels. Le monitoring Kubernetes dans New Relic s’ouvre sur une vue à l’échelle de la flotte qui transforme cette complexité en clarté.

Cette vue unifiée aide les ingénieurs plateforme et les SRE à :

* **Unifiez l&apos;observabilité de l&apos;ensemble de la flotte** sur un dashboard unique compatible avec le moniteur de cluster des agents New Relic ou OpenTelemetry.
* **Accélérez l&apos;analyse des causes profondes** grâce à un workflow de triage guidé.
* **Réduisez les coûts** en identifiant les ressources gaspillées dans l&apos;ensemble de la flotte.
* **Offrir aux développeurs** une vision centrée sur l&apos;application pour le libre-service.

## Accédez à l’UI [#access]

Il s&apos;agit de l&apos;expérience Kubernetes par défaut dans New Relic. Pour l&apos;ouvrir :

Aller à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Kubernetes**</DNT>

## Principaux composants de l’interface utilisateur [#components]

L’interface utilisateur est structurée pour fournir à la fois une vue d’ensemble de haut niveau et des capacités d’exploration approfondie de l’ensemble de votre parc Kubernetes. Les principaux composants sont les suivants :

* **Filtres d&apos;entités**: Filtrer et trier les problèmes à l&apos;aide **d&apos;étiquettes et de valeurs** au **niveau ducluster ou du nœud**.
  * **FiltreCluster **: Filtre permettant d&apos;isoler l&apos;interface utilisateur à un seul cluster Kubernetes.

* **Tableaux de bord colorés**: Affichez des indicateurs clés de performance pertinents pour mettre en évidence les problèmes les plus importants qui nécessitent une attention particulière pour l’ensemble de la flotte.

  * Cliquez sur une carte de score pour **trier le tableau** dans le contexte de cette métrique, en faisant remonter les clusters et les nœuds présentant les problèmes les plus critiques en haut.
  * Il permet également de visualiser, à l&apos;aide d&apos;un **graphique linéaire,** l&apos;évolution de la métrique sur la période sélectionnée.
  * Sélectionnez <DNT>**`avg`**</DNT>, <DNT>**`p95`**</DNT>, <DNT>**`p99`**</DNT>, ou <DNT>**`max`**</DNT> pour mettre à jour les cartes de score et le graphique en courbes. Le tableau de répartition affiche toujours les valeurs moyennes.

* **Graphique linéaire**: Fournit l’ **évolution de la métrique** sur la période sélectionnée pour l’analyse des tendances.

* **Tableau**: liste toutes les entités du parc et fournit des **données de métriques détaillées** pour chaque cluster sous les cinq [onglets](#tab) principaux.

  * **Priorité à la santé**: Le tableau propose un filtre permettant de n’afficher que les entités « malsaines » afin de concentrer votre attention là où elle est réellement nécessaire.
  * **Recherche**: Une barre de recherche textuelle vous permet de filtrer les lignes du tableau en fonction **du texte libre** saisi.
  * **Code couleur**: comme les cartes de score, les cellules du tableau sont codées par couleur (jaune, rouge) pour attirer rapidement l’attention sur les entités présentant des problèmes qui atteignent un [seuil de gravité](#tab) spécifique.
  * **Sélecteur de colonnes**: l&apos;onglet Workloads propose un ensemble de colonnes par défaut épuré et vous permet d&apos;ajouter ou de supprimer des colonnes. Votre sélection de colonnes persiste entre les sessions.

* **Sélecteur de type de workload**: limitez l’onglet Workloads à un type de workload spécifique, tel que les déploiements, les DaemonSets ou les StatefulSets.

* **Bouton de commentaires**: Permet de partager facilement vos commentaires sur votre expérience avec l’interface utilisateur.

## Visibilité du parc multi-comptes [#multi-account]

Les clusters des comptes New Relic auxquels vous avez accès apparaissent ensemble dans la même vue de flotte, de sorte que le monitoring d’une flotte qui s’étend sur plusieurs comptes ne nécessite pas de changer de contexte de compte.

Pour voir les clusters de plus d’un compte :

1. Dans le sélecteur de compte, sélectionnez <DNT>**All accounts**</DNT>.
2. Utilisez le filtre de compte dans la barre de filtre d’entité pour restreindre la vue aux comptes spécifiques dont vous avez besoin.

## Infobulles d’entité [#popover]

La sélection d&apos;une entité dans le tableau ouvre une fenêtre contextuelle qui vous donne du contexte sur cette entité sans quitter la vue de la flotte :

* **Métriques dorées**, un aperçu des métriques de performance clés de l’entité.
* **Entités associées**, regroupées et triées par type, que vous pouvez ouvrir dans une vue empilée à côté de votre contexte actuel.
* **Liens vers les applications associées**, marqués d’une icône de lien externe lorsqu’ils ouvrent l’expérience APM plutôt qu’une vue empilée.
* **Description de l’objet**, qui ouvre le manifeste pour l’objet Kubernetes sélectionné.
* **Équipe**, si une équipe est définie pour l’entité.
* **Dashboard**, un lien vers le dashboard correspondant de l’entité.

## Mettez en corrélation avec l&apos;APM, les événements, les logs, et les alertes. [#correlate]

La vue de la flotte est conçue pour que vous n’ayez pas à la quitter pour corréler les signaux et réduire le MTTR :

* **Informations détaillées APM**: la vue Workloads présente les données de performances des applications pour les applications s’exécutant dans un workload, afin que vous puissiez passer de la santé de l’infrastructure aux performances des applications en un seul endroit.
* **Alertes**: les alertes ouvertes sont affichées pour les clusters, les nœuds, et les workloads, y compris des indicateurs d’alerte dans l’onglet Workloads, et s’ouvrent dans une vue empilée pour un contexte immédiat. Les alertes ouvertes apparaissent quel que soit l’intervalle de temps que vous avez sélectionné, de sorte qu’une alerte active n’est jamais masquée par un sélecteur d’intervalle de temps étroit.
* **Événements et logs**: les événements et logs Kubernetes pour une entité s’ouvrent dans une vue superposée à côté de votre contexte actuel, afin que vous puissiez corréler les signaux sans perdre votre place dans le flux de triage.
