## v10.9.0

* **Fonctionnalité : profilage continu (aperçu)**

  Le profilage continu est une nouvelle fonctionnalité qui n’est pas encore disponible pour une utilisation générale. Le code du composant côté agent est désormais présent dans l’agent, mais pour l’utiliser réellement avant la sortie de la disponibilité générale, vous devrez contacter votre représentant commercial New Relic pour rejoindre l’aperçu de manière anticipée.

  Le profilage continu échantillonne de manière répétée les call stack Ruby de votre application en cours d’exécution et les signale à New Relic, afin que vous puissiez voir quelles méthodes consomment le plus de temps CPU (ou allouent le plus d’objets) en production, sans ajouter de code à votre application.

  Pour l’activer, ajoutez les gems [`stackprof`](https://rubygems.org/gems/stackprof) et [`google-protobuf`](https://rubygems.org/gems/google-protobuf) au `Gemfile` de votre application, puis définissez `profiling.enabled` sur `true`:

  ```yaml
    profiling.enabled: true
  ```

  Avec seulement `profiling.enabled` défini, l’agent échantillonne le temps CPU toutes les 10 millisecondes pendant toute la durée de vie du processus. Ces options vous permettent d’ajuster ce comportement :

  | Nom de la configuration                | Défaut  | Comportement                                                                                                                                                |
  | -------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | profiling.enabled                      | `false` | Si `true`, l’agent collecte et signale les données de profilage continu.                                                                                    |
  | profiling.include                      | `cpu`   | Ce qu’il faut échantillonner : `cpu` pour le temps CPU, ou `object` pour les allocations d’objets.                                                          |
  | profiling.sample\_period               | `0.01`  | Secondes entre les échantillons de stack. Utilisé uniquement lorsque `profiling.include` est `cpu`. Doit être compris entre 0,000001 et 0,999999.           |
  | profiling.object\_allocation\_interval | `10000` | Allocations d’objets entre les échantillons de stack. Utilisé uniquement lorsque `profiling.include` est `object`. Doit être compris entre 1000 et 999 999. |
  | profiling.delay                        | `0`     | Millisecondes à attendre avant que le profilage ne commence. `0` démarre immédiatement.                                                                     |
  | profiling.duration                     | `0`     | Millisecondes à profiler avant de s’arrêter automatiquement. `0` profile jusqu’à ce que le processus se termine.                                            |

  [PR#3617](https://github.com/newrelic/newrelic-ruby-agent/pull/3617)

* **Fonctionnalité : Ajout de la prise en charge de Dalli 5.1.1**

  Dalli 5.1.1 a ajouté des arguments à certaines des méthodes que l’agent instrumente, ce qui pourrait déclencher une `ArgumentError` sur les opérations à clés multiples ou entraîner l’abandon silencieux des options de requête. Désormais, l’agent accepte et transmet un nombre variable d’arguments positionnels et de mots-clés pour ces méthodes. [PR#3683](https://github.com/newrelic/newrelic-ruby-agent/pull/3683)
