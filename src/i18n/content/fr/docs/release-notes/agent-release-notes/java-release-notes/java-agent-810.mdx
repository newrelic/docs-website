## Nouvelle fonctionnalité et améliorations

* Ajout de la prise en charge de Webflux 6 [1181](https://github.com/newrelic/newrelic-java-agent/pull/1181)

* Ajout de la prise en charge de Spring JMS 6 [1088](https://github.com/newrelic/newrelic-java-agent/issues/1088)

* Ajout de la prise en charge de Mongodb Reactive Streams [1164](https://github.com/newrelic/newrelic-java-agent/pull/1164)

* Ajout de la prise en charge de Kafka Streams [1170](https://github.com/newrelic/newrelic-java-agent/pull/1170)

  La prise en charge de Kafka Streams se décline en deux volets : les métriques et les spans. Les métriques sont activées par défaut, tandis que les spans sont désactivés par défaut. Pour activer les spans, ajoutez ce qui suit à votre configuration *newrelic.yml* dans la section common :

```
common:
  class_transformer:
    kafka-streams-spans:
      enabled: true
```

* Empreinte d&apos;erreur - fournissez vos propres noms de groupes Errors Inbox [1195](https://github.com/newrelic/newrelic-java-agent/pull/1195)

  Vos occurrences d’erreurs sont-elles mal regroupées ? Définissez votre propre empreinte d’erreur via une fonction de rappel. Une nouvelle méthode d’API publique a été ajoutée qui acceptera une procédure définie par l’utilisateur. La proc sera invoquée pour chaque erreur détectée et chaque fois qu’elle renvoie une chaîne, cette chaîne sera utilisée comme nom de groupe d’erreurs pour l’erreur et aura la priorité sur tout regroupement côté serveur effectué avec l’Errors Inbox de New Relic. Cela offre aux utilisateurs un contrôle bien plus grand sur le regroupement de leurs erreurs. Pour plus d’informations, consultez nos pages [API : regroupement d’erreurs](/docs/apm/agents/java-agent/api-guides/java-agent-api-register-error-group-callback-to-set-fingerprint/) et [APM : onglet Groupes d’erreurs](/docs/triage-inbox/apm-tab/).

* Suivi des utilisateurs - associer les erreurs à un identifiant utilisateur [1188](https://github.com/newrelic/newrelic-java-agent/pull/1188)

  Vous pouvez désormais voir le nombre d&apos;utilisateurs impactés par un groupe d&apos;erreurs. Identifiez l’utilisateur final avec une nouvelle méthode d’API publique qui accepte une représentation sous forme de chaîne d’un identifiant utilisateur et associe cet identifiant à la transaction en cours. Les transactions et les erreurs auront alors un nouvel attribut d’agent `enduser.id` associé. Cela permettra aux utilisateurs de l’agent de marquer d’un tag les transactions et les erreurs comme appartenant à des identifiants utilisateur donnés, afin d’améliorer les capacités de filtrage et d’alerte. Pour plus d’informations, consultez la documentation \[Newrelic.setUserId ]\([https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName(java.lang.String)](https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName\(java.lang.String\)) et la page [Suivre les utilisateurs impactés avec Errors Inbox](/docs/triage-inbox/error-users-impacted/).

* L&apos;appel de `token.link()` en dehors d&apos;une transaction instrumentera cette méthode pour démarrer une transaction asynchrone [1140](https://github.com/newrelic/newrelic-java-agent/pull/1140)

* L&apos;instrumentation des clients Kafka comporte de nouvelles métriques pour lister les nœuds : `MessageBroker/Kafka/Nodes/&lt;node>` [1130](https://github.com/newrelic/newrelic-java-agent/pull/1130)

## Mise à jour vers la dernière version [#procedures]

Pour identifier la version de l’agent Java que vous utilisez actuellement, exécutez `java -jar newrelic.jar -v`. Votre version d&apos;agent Java sera imprimée sur votre console.

Ensuite, pour mettre à jour vers la dernière version de l&apos;agent Java :

1. Sauvegardez l’ **intégralité** du [répertoire racine de l’agent Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) vers un autre emplacement. Renommez ce répertoire en `NewRelic_Agent#.#.#`, où `#.#.#` est le numéro de version de l&apos;agent.
2. [Téléchargez l&apos;agent.](/docs/release-notes/agent-release-notes/java-release-notes)
3. Décompressez le nouveau fichier de téléchargement de l&apos;agent, puis copiez `newrelic-api.jar` et `newrelic.jar` dans le [répertoire racine de l&apos;agent Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) d&apos;origine.
4. Comparez votre ancien `newrelic.yml` avec le `newrelic.yml` nouvellement téléchargé à partir du zip et [mettez à jour le fichier si nécessaire](#diff).
5. Redémarrez votre répartiteur Java.

Si vous rencontrez des problèmes après la mise à jour de l&apos;agent Java, effectuez la restauration à partir du répertoire de l&apos;agent New Relic sauvegardé.

## Différences de configuration de l&apos;agent de mise à jour [#diff]

Nous ajoutons de nouveaux paramètres à `newrelic.yml` à mesure que nous sortons de nouvelles versions de l&apos;agent. Vous pouvez utiliser `diff` ou un autre utilitaire de comparaison pour voir ce qui a changé et ajouter les nouveaux paramètres de configuration à votre ancien fichier. Assurez-vous de ne pas écraser les personnalisations que vous avez apportées au fichier, telles que votre clé de licence, le nom de l&apos;application ou les modifications apportées aux paramètres par défaut.

Par exemple, si vous `diff` les fichiers par défaut `newrelic.yml` pour les versions 7.10.0 et 7.11.0 de l&apos;agent Java, les résultats imprimés sur la console seront comme suit :

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

Dans cet exemple, ces lignes ont été ajoutées au `newrelic.yml` par défaut dans la version 7.11.0 de l&apos;agent Java. Si vous passez à la version 7.11.0 ou supérieure, vous devez ajouter ces nouvelles lignes à votre `newrelic.yml` d&apos;origine.
