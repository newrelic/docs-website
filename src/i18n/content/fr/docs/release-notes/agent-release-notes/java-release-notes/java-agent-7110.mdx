## Nouvelle fonctionnalité et améliorations

* Prise en charge de Java 19 [1022](https://github.com/newrelic/newrelic-java-agent/pull/1022)

* Prise en charge de Play 2.8.16+ [981](https://github.com/newrelic/newrelic-java-agent/pull/981)

* Prise en charge de ojdbc8 v21.1.0.0+ [1042](https://github.com/newrelic/newrelic-java-agent/pull/1042)

* Prise en charge des JVM Semeru/OpenJ9 [993](https://github.com/newrelic/newrelic-java-agent/pull/993)

* Prise en charge du transfert de logs pour java.util.logging (JUL) [1049](https://github.com/newrelic/newrelic-java-agent/pull/1049)

* Prise en charge du transfert des données de contexte de log [866](https://github.com/newrelic/newrelic-java-agent/pull/866)

  L&apos;Agent peut désormais transmettre les données du Mapped Diagnostic Context (MDC, logback/slf4j) et du ThreadContext (log4j2) sous forme d&apos;attributs lors du transfert des enregistrements de logs. Lorsque la fonctionnalité est activée, ces attributs seront ajoutés aux enregistrements de log avec un préfixe `context.`. Pour plus de détails sur l&apos;activation de cette fonctionnalité, consultez la documentation relative à [context\_data](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#logging-context-data).

* Augmentation de la limite des événements personnalisés [1036](https://github.com/newrelic/newrelic-java-agent/pull/1036)

  Cette version augmente la limite par défaut des événements personnalisés de 10 000 événements par minute à 30 000 événements par minute. Dans le cas où les événements personnalisés étaient limités, ce changement permettra d’envoyer davantage d’événements personnalisés à New Relic. Il existe également une nouvelle limite maximale configurable de 100 000 événements par minute. Pour modifier les limites, consultez la documentation de [max\_samples\_stored](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Custom_Events). Pour en savoir plus sur ce changement et comment déterminer si des événements personnalisés sont rejetés, consultez notre [publication](https://support.newrelic.com/s/hubtopic/aAX8W0000008dby/send-more-custom-events-with-the-latest-apm-agents) sur l’Explorers Hub.

* Métriques au niveau du code activées par défaut [1037](https://github.com/newrelic/newrelic-java-agent/pull/1037)

  La fonctionnalité de métriques au niveau du code introduite avec l&apos;Agent 7.10 est désormais activée par défaut. Cette fonctionnalité entraînera une augmentation de la consommation de données. La quantité dépend de l&apos;application. Pour désactiver les métriques au niveau du code, consultez les instructions de notre [documentation sur les métriques au niveau du code](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#code-level-metrics).

## Mise à jour vers la dernière version [#procedures]

Pour identifier la version de l’agent Java que vous utilisez actuellement, exécutez `java -jar newrelic.jar -v`. Votre version d&apos;agent Java sera imprimée sur votre console.

Ensuite, pour mettre à jour vers la dernière version de l&apos;agent Java :

1. Sauvegardez l’ **intégralité** du [répertoire racine de l’agent Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) vers un autre emplacement. Renommez ce répertoire en `NewRelic_Agent#.#.#`, où `#.#.#` est le numéro de version de l&apos;agent.
2. [Téléchargez l&apos;agent.](/docs/release-notes/agent-release-notes/java-release-notes)
3. Décompressez le nouveau fichier de téléchargement de l&apos;agent, puis copiez `newrelic-api.jar` et `newrelic.jar` dans le [répertoire racine de l&apos;agent Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) d&apos;origine.
4. Comparez votre ancien `newrelic.yml` avec le `newrelic.yml` nouvellement téléchargé à partir du zip et [mettez à jour le fichier si nécessaire](#diff).
5. Redémarrez votre répartiteur Java.

Si vous rencontrez des problèmes après la mise à jour de l&apos;agent Java, effectuez la restauration à partir du répertoire de l&apos;agent New Relic sauvegardé.

## Différences de configuration de l&apos;agent de mise à jour [#diff]

Nous ajoutons de nouveaux paramètres à `newrelic.yml` à mesure que nous sortons de nouvelles versions de l&apos;agent. Vous pouvez utiliser `diff` ou un autre utilitaire de comparaison pour voir ce qui a changé et ajouter les nouveaux paramètres de configuration à votre ancien fichier. Assurez-vous de ne pas écraser les personnalisations que vous avez apportées au fichier, telles que votre clé de licence, le nom de l&apos;application ou les modifications apportées aux paramètres par défaut.

Par exemple, si vous `diff` les fichiers par défaut `newrelic.yml` pour les versions 7.10.0 et 7.11.0 de l&apos;agent Java, les résultats imprimés sur la console seront comme suit :

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

Dans cet exemple, ces lignes ont été ajoutées au `newrelic.yml` par défaut dans la version 7.11.0 de l&apos;agent Java. Si vous passez à la version 7.11.0 ou supérieure, vous devez ajouter ces nouvelles lignes à votre `newrelic.yml` d&apos;origine.
