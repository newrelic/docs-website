### Améliorations

* Java 10

L&apos;agent Java New Relic est désormais entièrement compatible avec Java 10. Pour en savoir plus sur la sortie du JDK, et l&apos;agent Java, consultez [ce sujet sur l&apos;Explorers Hub](https://support.newrelic.com/s/hubtopic/aAX8W0000008ZWk/jdk-releases-and-the-java-agent).

* Non compatible avec Java 6

Afin de continuer à innover et de fournir efficacement de nouvelles fonctionnalités à nos clients qui utilisent la JVM, cette version de l’agent et les versions futures ne sont pas compatibles avec Java 6. Si vous utilisez Java 6, vous pouvez continuer à utiliser l’agent Java 4.3.0 ou une version antérieure. Pour plus de détails, consultez [ce sujet sur l’Explorers Hub](https://discuss.newrelic.com/t/with-support-for-java-10-new-relic-deprecates-java-6/57738).

* Akka 2.5 et Akka HTTP 10.1

L&apos;agent Java prend désormais en charge Akka 2.5.x et Akka HTTP 10.1.x. Vous verrez vos appels Akka HTTP comme des transactions New Relic, vous verrez les transferts entre les acteurs Akka, et vous comprendrez les appels vers d&apos;autres bases de données et services.

* Solr 7

L’agent Java prend désormais en charge Solr 7.x. La prise en charge de Solr par New Relic signale les appels de base de données aux serveurs Solr et monitore également le serveur Solr lui-même.

Problème connu : la collecte de statistiques JMX pour Solr 7 n&apos;est pas prise en charge à partir de cette sortie.

* Source de données WebLogic

L’agent Java affiche désormais les données de santé de la source de données de WebLogic dans l’onglet Datasource sous la page JVM.

### Corrections

* Correction d’un problème où l’Agent Java 4.3.0 ne rapportait pas de données selon les paramètres régionaux de la JVM. Agent Java 4.3.0 échec de l’envoi des données d’événement si les paramètres régionaux de la JVM sont configurés pour utiliser une virgule comme séparateur décimal. Vous verriez NumberFormatException dans le log de l’agent.
* Correction d’un problème rare où l’agent tente de manière incorrecte de retransformer continuellement les classes lorsqu’une extension avec une date de modification dans le futur est utilisée, entraînant une augmentation significative de la charge CPU.
* Correction d’une ConcurrentModificationException causée par l’instrumentation ning qui se manifeste dans l’instrumentation Mule, provoquant la relance de la requête qu’elle affecte et empêchant l’agent Java de rapporter les données d’en-tête.
* Correction d’un problème où si `enable_auto_app_naming` était défini sur true, et `distributed_tracing.enabled` était défini sur true, il échantillonnait chaque événement de traces distribuées. Désormais, si l’agent a les deux configurations activées, il n’activera pas le tracing distribué.
