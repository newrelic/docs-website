### Nouveaux documents

* Ajout de [Triage de la remédiation des vulnérabilités avec l&apos;agent Security RX](/docs/vulnerability-management/agent/overview) pour fournir des conseils sur l&apos;utilisation de l&apos;agent Security RX afin d&apos;analyser les CVE, de générer des plans de remédiation, et de déclencher des agents de codage pour ouvrir des demandes de tirage.
* Ajout du [workflow Jira Security RX](/docs/vulnerability-management/workflows/jira) pour fournir des instructions étape par étape afin de créer et de synchroniser automatiquement des tickets Jira pour les vulnérabilités de sécurité détectées par Security RX.
* Ajout de [Dépannage de New Relic MCP](/docs/agentic-ai/mcp/troubleshoot) pour fournir des étapes de dépannage courantes et des solutions afin de résoudre les problèmes d’installation et de configuration du serveur MCP.

### Changements majeurs

* Restructuration du [monitoring de Microsoft SQL Server avec NRDOT](/docs/opentelemetry/database/mssql/introduction) avec une nouvelle référence de configuration complète, un nouveau guide de configuration du collecteur CNCF et des documents d&apos;installation remaniés pour les environnements hébergés sur Windows, Windows RDS, hébergés sur Linux et Linux RDS.
* Mise à jour des [types d&apos;agents](/docs/new-relic-control/agent-control/agent-types) avec la documentation pour la configuration du transfert de logs Fluent Bit sous Agent Control, y compris l&apos;emplacement du fichier de configuration, les chemins des binaires par système d&apos;exploitation et le comportement de mise à jour.
* Mise à jour de [Gestion des flottes](/docs/new-relic-control/fleet-control/manage-fleets) avec une documentation complète pour le nouveau workflow d&apos;approbation de configuration dans le contrôle de la flotte. Les approbations de configuration nécessitent au moins un réviseur autre que l&apos;auteur avant qu&apos;une version de configuration puisse être déployée, avec une application à partir du 22 septembre 2026.
* Mise à jour du [schéma de définition de l&apos;automatisation des workflows](/docs/workflow-automation/workflow-automation-apis/definition-schema) avec la nouvelle action State Step pour la persistance des paires valeur clé à travers les étapes de workflow via `.workflowState`, et mise à jour des [limites de workflow](/docs/workflow-automation/limitations-and-faq/workflow-limits) et du [monitoring de l&apos;exécution](/docs/workflow-automation/manage-workflows/monitor-workflow-execution) pour couvrir le nouveau type d&apos;étape et les données `WorkflowAutomationEvent`.
* Ajout de la prise en charge de VMware vSphere Kubernetes Service (VKS) 3.x aux [exigences de compatibilité de l’intégration Kubernetes](/docs/kubernetes-pixie/kubernetes-integration/get-started/kubernetes-integration-compatibility-requirements), couvrant VKS s’exécutant sur vSphere Supervisor 9.0 à 9.1 (vSphere 8.x et 9.x).
* Mise à jour des [exigences de compatibilité de l&apos;agent .NET](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) avec les dernières versions de bibliothèques compatibles vérifiées.
* Mise à jour des [Catalogues](/docs/service-architecture-intelligence/catalogs/catalogs) pour documenter le filtrage des valeurs de colonne basé sur les tags via des pilules interactives, et la réorganisation des colonnes par glisser-déposer dans le tableau de la vue Personnaliser.
* Ajout d&apos;un avertissement à [Response intelligence with AI](/docs/alerts/alert-event-management/response-intelligence-ai) indiquant que les informations détaillées générées par l&apos;IA sont des suggestions pour guider l&apos;investigation, et non des causes profondes confirmées, et qu&apos;elles doivent être vérifiées avec vos données avant d&apos;agir en conséquence.
* Ajout de la bibliothèque open source `snapdom` aux [licences de l&apos;agent New Relic Browser](/docs/licenses/product-or-service-licenses/new-relic-browser/new-relic-browser-licenses).
* Mise à jour de l&apos;[onglet OpenTelemetry d&apos;Errors Inbox](/docs/errors-inbox/otel-tab) pour corriger le nom de l&apos;attribut de span de `otel.status` à `otel.status_code`, et étendre les types de span pris en charge pour inclure `producer`, `client`, et `internal` en plus de `server`, et `consumer`.
* Mise à jour de [Choisir votre data center](/docs/accounts/accounts-billing/account-setup/choose-your-data-center) pour refléter le fait que la région de données Japon (JP) est désormais en disponibilité générale.

### Modifications mineures

* Mise à jour de [Configurer New Relic MCP](/docs/agentic-ai/mcp/setup) avec les commandes CLI Claude Code corrigées pour l’authentification OAuth, une exigence de version minimale (Claude Code v2.1.186+), et un format de configuration JSON simplifié.
* Ajout de `nrExporterEndpoints` à la [référence de configuration YAML de Gateway](/docs/new-relic-control/pipeline-control/gateway/yaml-overview) pour remplacer les points de terminaison d&apos;ingestion New Relic par défaut par pipeline, y compris un nouveau champ `otlpEndpoint`, sous une section dédiée aux remplacements facultatifs.
* Mise à jour du [dépannage de l&apos;API de trace](/docs/apm/distributed-tracing/trace-api/troubleshooting-missing-trace-api-data) et des [données de trace manquantes](/docs/distributed-tracing/troubleshooting/missing-trace-data) avec les limites d&apos;horodatage de span les plus anciennes corrigées pour OTLP et l&apos;API de trace.
* Ajout d&apos;une section sur les avertissements de cardinalité dans [Gérer la cardinalité](/docs/data-apis/ingest-apis/metric-api/cardinality-management) expliquant ce qui se passe lorsqu&apos;un budget de cardinalité est atteint, comment identifier les métriques affectées via des indicateurs d&apos;avertissement dans les graphiques, et les dashboards, et comment effectuer une requête sur les données brutes lors de la remédiation.
* Ajout de l&apos;espace de nommage Direct to Live Archives comme troisième option de partition dans [Partitions de données](/docs/logs/ui-data/data-partitions), et ajout de directives dans [Live Archives](/docs/logs/get-started/live-archives) expliquant que cet espace de nommage contourne la rétention standard pour les logs de conformité, et d&apos;audit qui vont directement dans le stockage à long terme.
* Correction de la description de l&apos;erreur `403 Forbidden` dans le [signalement des erreurs JavaScript React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting) pour indiquer que la clé API doit appartenir à un utilisateur disposant des autorisations d&apos;affichage de l&apos;entité mobile.
* Mise à jour de [Alert RCA with Autopilot and Slack](/docs/workflow-automation/workflow-examples/integrations/autopilot-slack-rca) avec une astuce sur l&apos;utilisation de la variable `{{ issueId }}` pour transmettre automatiquement l&apos;ID de problème de l&apos;alerte de déclenchement lors de l&apos;intégration avec les workflows d&apos;alerte.
* Mise à jour de [Rétrograder ou annuler un compte](/docs/accounts/accounts-billing/account-setup/downgradecancel-account) pour ajouter un encadré précisant que le dernier compte actif d&apos;une organisation ne peut pas être annulé indépendamment et doit être supprimé en supprimant l&apos;organisation, et amélioration des étapes de suppression de l&apos;organisation pour plus de clarté.
