### Nouveaux documents

* Ajout du [monitoring de l’infrastructure cloud Oracle (OCI)](/docs/infrastructure/oci/introduction/) pour fournir un aperçu du monitoring des métriques, et des logs OCI avec New Relic.
* Ajout d&apos;[Infrastructure 360](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360/) pour vous aider à découvrir automatiquement votre infrastructure cloud, cartographier les relations entre les ressources, et suivre les modifications de configuration, couvrant la configuration pour AWS et Azure, les entités et exigences prises en charge, et le dépannage.
* Ajout des [macros NRQL](/docs/nrql/nrql-macros/nrql-macros-overview/) pour vous montrer comment enregistrer une expression NRQL en tant que raccourci nommé et réutilisable et la référencer dans les requêtes avec le symbole `$`.
* Ajout de [Monitorer le déploiement avec le suivi des changements New Relic pour GitHub Copilot](/docs/agentic-ai/autopilot/change-tracking-for-github-copilot/) pour vous montrer comment monitorer chaque déploiement et obtenir des rapports de régression dans Slack et GitHub.
* Ajout de [Symbolicate Flutter Dart errors](/docs/mobile-monitoring/new-relic-mobile-flutter/symbolicate-dart-errors/) et [Symbolicate .NET MAUI C# errors](/docs/mobile-monitoring/new-relic-mobile-maui-dotnet/symbolicate-csharp-errors/) pour expliquer comment générer des fichiers de symboles, symboliquer les traces d’appels, et stocker les symboles pour chaque sortie.
* Ajout de [LaunchDarkly with the Python agent](/docs/apm/agents/python-agent/supported-features/launchdarkly-release-observability/) pour vous montrer comment observer la façon dont les indicateurs de fonctionnalités et les sorties affectent votre application en connectant les données LaunchDarkly à l&apos;agent Python.
* Ajout d’actions au [catalogue d’actions d’automatisation de workflow](/docs/workflow-automation/setup-and-configure/actions-catalog/actions-catalog/) pour [AWS Athena](/docs/workflow-automation/setup-and-configure/actions-catalog/aws/athena/aws-athena/), [AWS DynamoDB](/docs/workflow-automation/setup-and-configure/actions-catalog/aws/dynamodb/aws-dynamodb/), [Azure App Service](/docs/workflow-automation/setup-and-configure/actions-catalog/azure/azure-appservice/), [les exécutions de workflow GitHub](/docs/workflow-automation/setup-and-configure/actions-catalog/github/github-workflow-run/), [les secrets New Relic](/docs/workflow-automation/setup-and-configure/actions-catalog/newrelic/secret/newrelic-secret/), et [New Relic Synthetics](/docs/workflow-automation/setup-and-configure/actions-catalog/newrelic/synthetics/newrelic-synthetics/), et ajout d’une action [Attendre le statut de notification](/docs/workflow-automation/setup-and-configure/actions-catalog/newrelic/notification/newrelic-notification-waitforstatus/).
* Ajout du [bulletin de sécurité NR26-11](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-11/) avec les procédures pour corriger les vulnérabilités critiques de Node.js, y compris l’exécution de code à distance (CVE-2026-111497), affectant les sites publics, et les sites privés du monitoring synthétique.

### Changements majeurs

* Mise à jour de la [référence de l&apos;outil MCP](/docs/agentic-ai/mcp/tool-reference/) avec une section d&apos;analyse des écarts pour l&apos;outil `analyze_github_newrelic_gaps`, qui vérifie si l&apos;instrumentation New Relic est manquante dans votre projet.
* Mise à jour de [Use Autopilot with GitHub](/docs/agentic-ai/autopilot/use-autopilot-with-github/) avec une nouvelle section sur la façon dont Autopilot signale les correctifs à chaud ouverts et les demandes de tirage ouvertes pendant une fenêtre d’incident, et comment il réconcilie les versions de sortie.
* Mise à jour de [Configurer la propriété de l’entité](/docs/service-architecture-intelligence/teams/team-ownership/) pour Service architecture intelligence avec la liste des types d’entités, par domaine et par type, que New Relic attribue automatiquement aux équipes via la propriété basée sur les tags.
* Mise à jour de [Network traffic](/docs/new-relic-solutions/get-started/networks/) avec les domaines de registre Docker Hub qu&apos;Agent Control sur l&apos;hôte utilise pour télécharger les packages d&apos;agent à partir d&apos;un registre OCI, et modification du domaine de collecteur répertorié en `collector.newrelic.com`.
* Mise à jour de l&apos;article [Planifier des recherches NRQL](/docs/nrql/using-nrql/schedule-nrql-searches/) avec les capacités de lecture et de modification des destinations d&apos;intelligence appliquée, dont vous avez besoin pour sélectionner ou créer une destination d&apos;e-mail.
* Mise à jour des pages de référence de l’ [API de Workflow Automation](/docs/workflow-automation/workflow-automation-apis/using-workflow-automation-api/) pour les workflows et les planifications avec des descriptions cohérentes, des tableaux de paramètres et des ancres de section.
* Mise à jour de [Transférer vos logs à l’aide de l’agent d’infrastructure](/docs/logs/forward-logs/forward-your-logs-using-infrastructure-agent/) avec le paramètre `multilineParser`, disponible avec l’agent d’infrastructure v1.53.0 ou supérieure, pour combiner les entrées multilignes telles que les traces d’appels Java en un seul enregistrement de log.
* Mise à jour de la [compatibilité d’agent et des exigences .NET](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements/) pour lister les versions de Windows actuellement prises en charge, y compris Windows Server 2025, et Windows Azure Guest OS Family 5 et versions ultérieures.
* Mise à jour de [Compatibilité et exigences pour l’agent Node.js](/docs/apm/agents/nodejs-agent/getting-started/compatibility-requirements-nodejs-agent/) avec les dernières versions de package tierces prises en charge.

### Modifications mineures

* Mise à jour des recommandations d’alerte de l’ [intégration Azure Monitor](/docs/infrastructure/microsoft-azure-integrations/azure-integrations-list/azure-monitor/) pour utiliser la méthode de streaming du minuteur d’événement au lieu d’un décalage d’évaluation.
* Mise à jour de l&apos;article [Attributs d&apos;événement d&apos;alerte](/docs/alerts/create-alert/condition-details/alert-event-attributes/) pour expliquer que le décalage d&apos;évaluation est obsolète au profit du paramètre Délai/minuteur.
* Mise à jour de la [configuration de l’intégration Kafka](/docs/infrastructure/host-integrations/host-integrations-list/kafka/kafka-config/) pour expliquer que la modification de `CLUSTER_NAME` crée de nouvelles entités de broker et de topic, et que les applications APM restent liées aux anciens topics pendant environ un jour.
* Mise à jour de [Instrumenter votre propre fonction Lambda](/docs/serverless-function-monitoring/aws-lambda-monitoring/instrument-lambda-function/instrument-your-own/) pour ajouter la variable `NEW_RELIC_APP_NAME` requise à la configuration d’exemple.
* Mise à jour des [variables d’environnement de l’extension Lambda](/docs/serverless-function-monitoring/aws-lambda-monitoring/instrument-lambda-function/env-variables-lambda/) avec le paramètre de budget de nouvelle tentative du mode serverless et la variable `NEW_RELIC_EXTENSION_SYNCHRONOUS_FLUSH`.
* Mise à jour des [approches de l’agent Java pour Lambda](/docs/apm/agents/java-agent/getting-started/java-agent-approaches-lambda/) pour lister les variables d’environnement que vous devez définir.
* Mise à jour de [Connecter Autopilot à Slack](/docs/agentic-ai/autopilot/connect-to-slack/) pour expliquer qu’Autopilot accepte des messages allant jusqu’à 1000 caractères.
* Mise à jour des articles [Monitorer votre application Flutter](/docs/mobile-monitoring/new-relic-mobile-flutter/monitor-your-flutter-application/) et [Monitorer votre application .NET MAUI](/docs/mobile-monitoring/new-relic-mobile-maui-dotnet/monitor-your-net-maui-application/) pour expliquer que la symbolication dans le navigateur ne s&apos;applique qu&apos;aux exceptions gérées.
* Mise à jour de l&apos;article [Clés API New Relic](/docs/apis/intro-apis/new-relic-api-keys/) pour renommer « Default account key » en « Original account key ».
* Mise à jour des documentations sur l&apos;[installation de l&apos;observabilité eBPF](/docs/ebpf/linux-installation/) et la [tarification et facturation](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/) pour renommer « eAPM » en « observabilité eBPF ».
* Mise à jour du [signalement des erreurs JavaScript de React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting/) pour vous diriger vers l&apos;assistance New Relic afin de demander une limite de taille de source map plus élevée.
