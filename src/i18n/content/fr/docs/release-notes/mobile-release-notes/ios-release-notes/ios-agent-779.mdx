bugs:
  - 'Fixed a crash (`SIGSEGV` or `SIGBUS` in `SessionAttributeManager::generateJSONObject`) on the harvest thread, which could also corrupt the heap and cause crashes elsewhere. The agent copied its internal session attributes, such as `memUsageMb` and `lastInteraction`, during a harvest without holding the lock that guards them, so it could read them while another thread was updating them. This issue was present in 7.7.8 and earlier.'
  - 'Fixed the main thread blocking, and apps being terminated by the iOS watchdog (`0x8BADF00D`), once the event buffer was full and the app kept making network requests. The agent held a lock while it rewrote its on-disk copy of buffered events, and threads recording events, including the main thread, waited on that lock. Events dropped from a full buffer were also never removed from that copy, so it grew and was rewritten in full for every new event. Writes now happen without holding the lock, are batched, and dropped events are removed. This issue was present in 7.7.8 and earlier.'
  - 'Fixed events occasionally going unreported when they were recorded, for example by a network request finishing, at the same moment the agent collected buffered events for a harvest. The agent cleared the buffer a second time after releasing its lock, which discarded any event added in between before it was sent. This issue was present in 7.7.8 and earlier.'
  - 'Fixed the agent''s own JSON work being recorded as app activity. `NSJSONSerialization` is instrumented for interaction traces, and the agent called it directly for every log message as well as for session attributes and handled exceptions. That added the agent''s internal work to interaction traces and, when the app logged heavily, could overwhelm tracing. The agent now calls the original, uninstrumented implementation. This issue was present in 7.7.8 and earlier.'
  - 'Fixed Session Replay accessibility identifier masking rules set in Application Settings being ignored on iOS. New Relic sends these rules to iOS apps with the identifier `accessibilityIdentifier`, but the agent only recognized `tag`, so every such rule was dropped. Both values are now accepted. A malformed rule is now skipped with a warning instead of discarding every rule or crashing the agent.'
  - 'Fixed possible crashes in Session Replay masking. Masking lists could be updated by a reconnect, or by `addSessionReplayMaskedAccessibilityIdentifier:` and related APIs, while a frame was being captured, without holding the lock that capture uses. Custom masking rules containing values that can''t be saved to `NSUserDefaults`, such as `null`, could also stop the app when the agent saved its configuration. Rules are now cleaned before they are stored, and every update to the masking lists is locked.'
  - 'Fixed `WKWebView` navigations being reported without a URL in apps built with the iOS 27 SDK. With that SDK, `WKWebView.URL` can still be `nil` when a navigation starts. The agent now falls back to the main-frame request URL from `decidePolicyForNavigationAction`.'
  - Fixed possible EXC_BAD_ACCESS crash when using `addHTTPHeaderTrackingFor`.

### Débogage

* Correction d&apos;un plantage (`SIGSEGV` ou `SIGBUS` dans `SessionAttributeManager::generateJSONObject`) sur le thread de collecte, qui pouvait également corrompre le tas, et causer des plantages ailleurs. L&apos;agent copiait ses attributs de session internes, tels que `memUsageMb` et `lastInteraction`, pendant une collecte sans détenir le verrou qui les protège, de sorte qu&apos;il pouvait les lire pendant qu&apos;un autre thread les mettait à jour. Ce problème était présent dans la version 7.7.8 et les versions antérieures.
* Correction du blocage du thread principal, et de la fermeture des applications par le watchdog iOS (`0x8BADF00D`), une fois que le tampon d’événements était plein, et que l’application continuait à effectuer des requests réseau. L’agent maintenait un verrou pendant qu’il réécrivait sa copie sur disque des événements mis en mémoire tampon, et les threads enregistrant les événements, y compris le thread principal, attendaient ce verrou. Les événements rejetés d’un tampon plein n’étaient pas non plus supprimés de cette copie, elle augmentait donc de volume, et était entièrement réécrite pour chaque nouvel événement. Les écritures se produisent désormais sans maintenir le verrou, sont regroupées par lots, et les événements rejetés sont supprimés. Ce problème était présent dans la version 7.7.8, et les versions antérieures.
* Correction d’événements qui n’étaient parfois pas signalés lorsqu’ils étaient enregistrés, par exemple par la fin d’une requête réseau, au même moment où l’agent collectait les événements mis en mémoire tampon pour une récolte. L’agent vidait la mémoire tampon une seconde fois après la sortie de son verrou, ce qui supprimait tout événement ajouté entre-temps avant qu’il ne soit envoyé. Ce problème était présent dans la version 7.7.8 et les précédentes.
* Correction du problème où le propre travail JSON de l’agent était enregistré comme activité de l’application. `NSJSONSerialization` est instrumenté pour les traces d’interaction, et l’agent l’appelait directement pour chaque message de log, ainsi que pour les attributs de session, et les exceptions gérées. Cela ajoutait le travail interne de l’agent aux traces d’interaction, et, lorsque l’application générait beaucoup de logs, pouvait saturer le tracing. L’agent appelle désormais l’implémentation d’origine, non instrumentée. Ce problème était présent dans la version 7.7.8, et les versions antérieures.
* Correction d&apos;un problème où les règles de masquage de l&apos;identifiant d&apos;accessibilité de Session Replay définies dans les paramètres de l&apos;application étaient ignorées sur iOS. New Relic envoie ces règles aux applications iOS avec l&apos;identifiant `accessibilityIdentifier`, mais l&apos;agent ne reconnaissait que `tag`, ce qui entraînait le rejet de toutes ces règles. Les deux valeurs sont désormais acceptées. Une règle mal formée est désormais ignorée avec un avertissement, au lieu de rejeter toutes les règles, ou de faire planter l&apos;agent.
* Correction d&apos;éventuels plantages lors du masquage de Session Replay. Les listes de masquage pouvaient être mises à jour par une reconnexion, ou par `addSessionReplayMaskedAccessibilityIdentifier:` et les API associées, pendant qu’une trame était en cours de capture, sans maintenir le verrou que la capture utilise. Les règles de masquage personnalisées contenant des valeurs qui ne peuvent pas être enregistrées dans `NSUserDefaults`, telles que `null`, pouvaient également arrêter l’application lorsque l’agent enregistrait sa configuration. Les règles sont désormais nettoyées avant d’être stockées, et chaque mise à jour des listes de masquage est verrouillée.
* Correction des navigations `WKWebView` signalées sans URL dans les applications compilées avec le SDK iOS 27. Avec ce SDK, `WKWebView.URL` peut toujours être `nil` lorsqu’une navigation commence. L’agent se rabat désormais sur l’URL de la request du cadre principal à partir de `decidePolicyForNavigationAction`.
* Correction d’un plantage EXC\_BAD\_ACCESS possible lors de l’utilisation de `addHTTPHeaderTrackingFor`.
