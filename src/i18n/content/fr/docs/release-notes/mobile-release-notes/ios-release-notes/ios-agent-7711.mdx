### Améliorations et optimisations

* Session Replay capture désormais le texte dans les applications React Native qui utilisent l&apos;architecture legacy. Le texte dessiné par `RCTTextView` était auparavant enregistré comme une vue vide. Il est désormais capturé et masqué de la même manière que le texte `RCTParagraphComponentView` dans la nouvelle architecture.

### Débogage

* Correction d’un problème avec Session Replay qui envoyait le contenu des vues bloquées. Une vue bloquée avec l’identifiant d’accessibilité `nr-block` était dessinée sous la forme d’une boîte noire, mais son texte était toujours envoyé avec le replay, et était lisible par-dessus la boîte dans n’importe quelle couleur autre que le noir. Une vue d’image bloquée conservait également ses données d’image lorsque le masquage d’image était désactivé. Les vues bloquées sont désormais enregistrées au moment de la capture sous la forme d’une boîte vide, sans texte, sans image, ni sous-vues. Une vue qui se bloque lorsqu’elle est à l’écran se met désormais à jour immédiatement dans le replay, au lieu d’afficher son ancien contenu jusqu’au prochain instantané complet. Ce problème était présent dans la version 7.7.10, et les versions antérieures.
* Correction d’un plantage rare (`SIGSEGV`, ou `NSInvalidArgumentException` pour un sélecteur non reconnu) dans `+[NRMAHTTPUtilities addCrossProcessIdentifier:]`, survenant généralement quelques secondes après le début d’une session pendant que l’application effectuait des requests réseau. Chaque request `NSURLSession` instrumentée lisait la configuration de récolte de l’agent et son ID inter-processus sans verrou. En même temps, le thread de récolte remplaçait cette configuration et effaçait l’ID au début de la session, de sorte qu’une request pouvait utiliser un objet qui venait d’être libéré. Les deux sont désormais lus et remplacés de manière sécurisée entre les threads. Une condition de concurrence similaire lorsque `+[NewRelic shutdown]` était appelé pendant une récolte a également été corrigée. Ce problème était présent dans la version 7.7.10, et les versions antérieures.
* Correction d’un problème où les requests réseau n’étaient pas enregistrées après que l’agent a reçu une réponse `/connect` qu’il ne pouvait pas analyser. L’agent stockait une configuration vide jusqu’à la prochaine récolte, et il abandonnait toutes les requests enregistrées durant cette période. L’agent conserve désormais sa configuration existante. Ce problème était présent dans la version 7.7.10, et les versions antérieures.
* Correction d’un problème où les exceptions gérées enregistrées sur l’appareil étaient perdues après une mise à jour de l’application, avec l’erreur serveur &quot;Failed to resolve data: MobileAppVersion&quot;. Les exceptions gérées sauvegardées étaient envoyées au début de la session suivante, avant que l’agent ne se soit connecté pour la nouvelle version de l’application. Elles sont désormais envoyées une fois la connexion terminée. Ce problème était présent dans la version 7.7.10, et les versions antérieures.
* Correction des exceptions gérées enregistrées avant une mise à jour de l&apos;application qui étaient signalées sous la nouvelle version de l&apos;application. Une exception gérée sauvegardée est désormais envoyée sous la version de l&apos;application dans laquelle elle a été enregistrée. Ce problème était présent dans la version 7.7.10, et les versions antérieures.
* Correction de `recordCustomEvent:` acceptant les types d&apos;événements réservés (`Mobile`, `MobileCrash`, `MobileRequest`, `MobileRequestError`, `MobileSession`, `MobileBreadcrumb`) lorsque le nouveau système d&apos;événements (`NRFeatureFlag_NewEventSystem`) était activé. Le système d&apos;événements par défaut rejetait déjà ces types, l&apos;envoi d&apos;un événement dépendait donc du flag de fonctionnalité. Les deux systèmes d&apos;événements les rejettent désormais.
* Correction de l’outil de téléversement dSYM (`run-symbol-tool`) qui ne parvenait pas à convertir un dSYM en carte de symboles lorsqu’une seule ligne de code source couvrait 1 MB (`0x100000`) ou plus de code. L’outil se rabattait alors sur le téléversement du dSYM complet. Il convertit désormais ces lignes en une carte de symboles.
