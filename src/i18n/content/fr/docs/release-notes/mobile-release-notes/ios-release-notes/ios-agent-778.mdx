### Débogage

* Correction d’un problème où l’appel de `recordError` dans des conditions de faible mémoire pouvait terminer l’application hôte. Les rapports d’erreurs sont désormais rejetés et consignés dans le log, et les frames de l’agent New Relic sont retirées du haut de la stack enregistrée.
* Correction d&apos;un plantage dans `NRMALoggerBridge::log` causé par un argument manquant dans une chaîne de format de log lors de la suppression des attributs de session. Correction de deux autres chaînes de format non valides dans le même composant.
* Correction d’un problème où les horodatages de tracing distribué (`tracestate` et la charge `ti`) étaient envoyés en secondes au lieu de millisecondes lors de l’utilisation du nouveau système d’événements.
* Correction d’un problème où les événements `MobileRequest` réussis perdaient tous les attributs de tracing distribué lorsqu’un SDK multiplateforme passait `traceHeaders`.
* Mise à jour de l&apos;agent natif pour empêcher l&apos;ajout de traces distribuées en double aux requests signalées avec `traceHeaders` par Flutter, React Native, ou d&apos;autres agents hybrides. Cela s&apos;applique à la fois à `MobileRequest` et à `MobileRequestError` dans les deux systèmes d&apos;événements.
* Application des limites minimales et maximales pour les paramètres de configuration `MaxEventPoolSize` et `MaxEventBufferTime` (durée maximale de mise en mémoire tampon plafonnée à 600 secondes).
* Mise à jour de `recordCustomEvent` pour renvoyer un booléen indiquant si l’événement a été ajouté avec succès lors de l’utilisation du nouveau système d’événements, plutôt que de toujours renvoyer `YES`.
* Mise à jour des envois d&apos;erreurs JavaScript React Native pour transmettre la valeur de plateforme `ReactNative` avec la casse correcte, afin de correspondre au comportement de l&apos;agent Android.
