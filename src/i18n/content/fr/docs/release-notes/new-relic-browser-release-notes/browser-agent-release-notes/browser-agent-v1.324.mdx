## v1.324.0

**[Consultez cette sortie sur GitHub →](https://github.com/newrelic/newrelic-browser-agent/releases/tag/v1.324.0)** pour le changelog technique complet et les informations sur la taille du build.

### Caractéristiques

#### Améliorer la correspondance de script dans le manifeste

Les micro frontends enregistrés avec un manifeste ont désormais chaque ressource qu’un outil de correspondance de manifeste fait correspondre comptabilisée dans leurs données MicroFrontEndTiming. Auparavant, chaque ressource de manifeste était consommée par sa première ressource correspondante, de sorte qu’un outil de correspondance large tel qu’une RegExp pour les chunks hachés (par exemple /catalog-chunk-\[a-f0-9]+.js/) ne contribuait qu’à hauteur d’un seul chunk à totalWeight, renderBlocking et à la fenêtre de temps de récupération/exécution. Tous les chunks correspondants, qu’ils soient déjà chargés ou chargés peu après register(), y contribuent désormais. Séparément, lorsque la même URL de script est référencée plus d’une fois (par exemple un tag `<script>` dupliqué, généralement resservi à partir du cache du navigateur), l’agent conserve désormais le temps du premier chargement au lieu de l’écraser, de sorte qu’un doublon mis en cache ne peut plus faire paraître le temps de récupération et d’exécution plus court que le chargement réel.

#### Activer le tracing distribué pour les Micro Frontends enregistrés

Active le tracing distribué (DT) pour les Micro Frontends (MFE) enregistrés : un appel AJAX effectué par un MFE enregistré ancre désormais correctement sa trace au niveau de la propre entité de ce MFE, offrant pour la première fois une visibilité sur les propres appels backend d’un MFE.

### Débogage

#### empêcher les collectes de log incontrôlées dues à une taille d’attribut gonflée

Correction d’un bug où une page qui écrase de manière répétée un attribut personnalisé pouvait amener l’agent à envoyer une requête de log distincte pour chaque message de log, inondant le réseau et épuisant les ressources du navigateur. L’agent suit désormais avec précision la taille de l’attribut personnalisé lorsque les valeurs sont écrasées, limite la fréquence à laquelle chaque fonctionnalité peut effectuer une collecte anticipée, et envoie toujours les lots importants rapidement afin qu’aucun log ne soit perdu ce faisant.

#### fix(jserrors) : réinitialiser la mémoire de hacher de la stack lors de la réinitialisation de la session

voir [https://new-relic.atlassian.net/browse/NR-626097](https://new-relic.atlassian.net/browse/NR-626097) pour plus de détails Renvoyer la trace d’appels complète une fois après une réinitialisation de session, au lieu d’un hacher que le backend pourrait ne plus être en mesure de résoudre en raison des TTL du cache.

#### trouver les temps d&apos;exécution du script de l&apos;entité iframe lors de l&apos;enregistrement

Les entités iframe enregistrées identifient désormais le script qui a appelé register() lors de leur création, et non plus après la réponse de l’agent parent. Auparavant, la recherche s’exécutait après l’aller-retour d’enregistrement, lorsque le script appelant n’était plus sur la stack d’appels, de sorte que l’actif, le type, et les temps de récupération de l’entité pouvaient être manquants, ou attribués au propre script de l’agent.
