## v1.320.0

### Caractéristiques

#### Améliorer la capacité à appliquer des limites raisonnables aux signes vitaux MFE

Correction d&apos;un bug dans le suivi des métriques vitales du micro-frontend (MFE) de l&apos;API Register, où la corrélation temporelle d&apos;un script pouvait être réutilisée après être devenue obsolète, ce qui entraînait un signalement erroné du First Contentful Paint (et d&apos;autres métriques vitales) comme étant jusqu&apos;à plusieurs secondes plus lent qu&apos;il ne l&apos;était réellement pour les MFE qui se remontent sans que leur script sous-jacent ne se recharge (par exemple, dans les applications à page unique).

#### Prise en charge de l&apos;iframe MFE - accès bêta

Ajoute une interface pour capturer les données MFE encapsulées dans une iFrame. Ceci est expérimental, est sujet à modification ou à suppression totale et ne doit pas être utilisé dans un environnement de production jusqu&apos;à ce que le statut GA soit atteint

### Débogage

#### Dédupliquer les événements MFE auto-instrumentés

Corrige le signalement en double des événements auto-instrumentés (requests AJAX, erreurs JS, log de console, activité WebSocket, etc.) lorsqu&apos;un micro-frontend est enregistré plusieurs fois avec l&apos;API `register()`. Auparavant, un seul événement auto-instrumenté provenant d&apos;un script MFE enregistré à plusieurs reprises était signalé une fois par enregistrement — Les événements auto-détectés sont désormais réduits à un seul rapport par occurrence réelle lorsqu&apos;ils se résolvent au même script sous-jacent et au même MFE enregistré `id`. Les appels explicites pilotés par l&apos;API (`.addPageAction()`, `.log()`, `.noticeError()`, etc.) et les événements `MicroFrontEndTiming` restent par enregistrement, comme prévu, et les MFE distincts qui partagent un script (par exemple, deux MFE différents enregistrés à partir du même bloc `<script>` en ligne) continuent d&apos;être signalés indépendamment.
