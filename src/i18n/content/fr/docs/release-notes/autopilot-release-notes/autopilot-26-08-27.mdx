## Nouveautés

### Autopilot : des investigations plus rapides et plus fiables

* **Investigations plus rapides :** Autopilot répartit désormais les étapes en parallèle, ce qui vous permet d’obtenir des délais de traitement plus courts et moins d’expirations de délai, en particulier pour les requests qui se divisent en plusieurs sous-investigations.
* **Routage Fast Path :** vous obtiendrez des réponses instantanées pour les requests simples. Un nouveau moteur fast-path reconnaît les questions simples et ignore les étapes inutiles, ce qui vous permet d’obtenir une réponse plus rapidement.
* **Enregistrer la mémoire dans le fil de discussion :** demandez à Autopilot dans le chat d’enregistrer des informations dans la mémoire et il ajoutera automatiquement ce contexte à la mémoire à long terme.
* **Copie NRQL en un clic :** copiez les requêtes NRQL générées directement dans votre presse-papiers d’un simple clic depuis le panneau de chat.
* **Agrandissement du chat en un clic :** agrandissez instantanément le panneau de chat d’un simple clic pour obtenir un espace de travail plus grand et épuré.
* **Raccourcis de navigation des requêtes :** parcourez et resélectionnez les requêtes passées à l’aide des touches fléchées Haut (↑) et Bas (↓) dans la zone de prompt.
* **Des réponses plus fiables :** nous avons corrigé plusieurs problèmes pour améliorer les investigations et fournir des réponses plus complètes. Vous recevrez désormais un message clair si vous avez atteint votre limite d’utilisation horaire au lieu d’une erreur brute, et nous avons corrigé un problème rare où une investigation pouvait sembler terminée avant qu’elle ne soit réellement achevée.

### Mises à jour des capacités d’intégration MCP GitHub (aperçu public)

<Callout title="Aperçu">
  Nous travaillons toujours sur cette fonctionnalité, mais nous aimerions que vous l&apos;essayiez !

  Cette fonctionnalité est actuellement fournie dans le cadre d&apos;un programme d&apos;aperçu conformément à nos [politiques de pré-sortie](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

**GitHub Enterprise Cloud désormais pris en charge :** l’intégration GitHub MCP fonctionne désormais avec GitHub Enterprise Cloud en plus de GitHub public. Si votre organisation utilise une instance `YOURSUBDOMAIN.ghe.com`, connectez-la à Autopilot en utilisant le même flux PAT. La seule nouvelle étape consiste à saisir l’URL de votre sous-domaine GHE lors de la configuration. Les deux cas d’utilisation d’investigation fonctionnent sur `GHE.com`: l’identification de la cause racine déclenchée par un changement, et la recherche manuelle de PR/commit.

Environnements GitHub pris en charge :

| Type de connexion       | Format d&apos;URL       | Disponibilité             |
| ----------------------- | ----------------------- | ------------------------- |
| GitHub public           | `github.com`            | Aperçu (depuis 2,1)       |
| GitHub Enterprise Cloud | `YOURSUBDOMAIN.ghe.com` | Aperçu - nouveau dans 2,2 |

**Modification de la configuration pour les utilisateurs `GHE.com` :** lors de la connexion de GitHub dans **Configure &gt; Autopilot &gt; External MCP connections**, saisissez `YOURSUBDOMAIN.ghe.com` dans le champ de l’URL GitHub au lieu de `github.com`. Les autorisations PAT sont inchangées : demande de tirage : lecture, contenus : lecture, métadonnées : lecture. Si votre organisation `GHE.com` applique le SSO SAML, autorisez le PAT pour le SSO dans GitHub avant de le saisir dans New Relic - un jeton non autorisé échoue avec `403` lors de la première utilisation.

**Limitez la portée de votre PAT aux référentiels (repository) que vous suivez activement :** Autopilot lit les descriptions de PR et les métadonnées de modification de fichier de chaque référentiel que le jeton autorise.
