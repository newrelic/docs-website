### Nouvelles fonctionnalités

* La clé de configuration `secrets_providers` a été renommée en `value_providers`, l’ancienne clé est conservée pour la rétrocompatibilité.
* OnHost : prise en charge de RedHat 10 ajoutée
* K8s : ajout d’un nouveau fournisseur de valeurs `nr-kubecm` pour résoudre les variables à partir des ConfigMaps Kubernetes.
* `chart_values.global` est toujours pris en charge dans agentTypes, mais obsolète. Vous pouvez toujours configurer les paramètres globaux via `chart_values.[chart-name].global`
* Linux : ajout du script `uninstall.sh` inclus dans le package qui détecte automatiquement le gestionnaire de paquets (apt, yum, zypper) et supprime `newrelic-agent-control`.

### Débogage

* Sur l’hôte : l’agent eBPF écrit désormais son log d’état dans le répertoire du système de fichiers géré par l’AC au lieu de `/etc/newrelic-ebpf-agent`.
* Sur l’hôte : correction de la fausse erreur de démarrage &quot;already running&quot; lorsqu’un fichier PID obsolète contenait un PID réutilisé par un processus non lié.
* Suppression des rapports `Health` (OpAMP et serveur d’état) pour les sous-agents dont le type d’agent ne définit aucun bloc `health:`, y compris lors de l’échec initial du démarrage du superviseur.
* Sur l’hôte : lorsqu’un type d’agent est mis à niveau vers une nouvelle version, les entrées obsolètes du système de fichiers déclarées par l’ancienne version sont désormais supprimées via un diff au lieu d’un effacement complet du répertoire de l’agent ; l’ID d’instance OpAMP du sous-agent est conservé lors des montées de version.
* K8s : lorsqu’un type de sous-agent est mis à niveau vers une nouvelle version, l’ID d’instance OpAMP est désormais conservé lors de la mise à niveau ; auparavant, la ConfigMap fleet-data était supprimée à chaque changement de type, que le nom de l’agent ait changé ou non, ce qui entraînait la génération d’un nouvel ID d’instance au démarrage suivant.
* Linux : le script `postremove` supprime désormais correctement les répertoires `newrelic-agent-control` lors de toute désinstallation (pas seulement sur `apt purge`), et cible les bons chemins (`/etc/newrelic-agent-control`, `/var/lib/newrelic-agent-control`, `/var/run/newrelic-infra`) au lieu de ceux de l’ancien infra-agent.
* Sur l’hôte : le service effectue désormais des tentatives indéfiniment en cas d’échec (délai de 20 s) au lieu de s’arrêter après 5 redémarrages rapides ; cela s’applique à la fois à l’unité systemd Linux et aux actions en cas d’échec SCM de Windows.
