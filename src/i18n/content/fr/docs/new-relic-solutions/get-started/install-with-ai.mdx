Vous pouvez demander à un agent de codage IA, tel que Claude Code, Cursor, GitHub Copilot, ou Codex, d’ajouter New Relic à votre projet. L’agent lit notre documentation d’installation, détermine l’agent New Relic dont votre projet a besoin, et effectue les modifications pour vous.

## Avant de commencer [#before-you-begin]

* **Compte New Relic** - Si vous n’en avez pas, [inscrivez-vous pour créer un compte New Relic](https://newrelic.com/signup).
* **Clé de licence** - Vous aurez besoin de votre <InlinePopover type="licenseKey" />. Pour la trouver, consultez [clé de licence](/docs/apis/intro-apis/new-relic-api-keys#license-key).

<Callout variant="important">
Gardez votre clé de licence hors du contexte de l’agent. Ne la collez pas dans le chat. Définissez-la vous-même comme variable d’environnement `NEW_RELIC_LICENSE_KEY` là où votre application s’exécute.
</Callout>

## Copiez ce prompt [#prompt]

Ouvrez votre agent de codage IA dans le dossier de votre projet, et collez ce prompt :

<Callout variant="tip">
Suivez les instructions sur [https://docs.newrelic.com/docs/new-relic-solutions/get-started/install-with-ai.md](https://docs.newrelic.com/docs/new-relic-solutions/get-started/install-with-ai.md) pour ajouter New Relic à ce projet.
</Callout>

Une fois l’agent exécuté, vérifiez quels fichiers il a modifiés, et assurez-vous que les données parviennent à New Relic.

## Instructions pour les agents d’IA [#agent-instructions]

Si vous êtes un agent IA installant New Relic, suivez ces étapes :

1. **Trouvez la stack :** regardez les fichiers du projet, tels que `package.json`, `pom.xml`, `build.gradle`, `requirements.txt`, `pyproject.toml`, `go.mod`, `*.csproj`, `composer.json`, `Gemfile`, `Dockerfile`, les manifestes Kubernetes, ou les charts Helm. Si la stack n’est pas claire, demandez à l’utilisateur ce qu’il faut monitorer.

2. **Choisissez le guide d’installation :** choisissez le guide correspondant parmi les [guides d’installation](#install-guides) ci-dessous. Pour une URL sous `/docs/`, ajoutez `.md` à la fin pour obtenir une version markdown.

3. **Gardez la clé de licence hors de votre contexte :** la clé est un secret. Vous n’avez jamais besoin de sa valeur.

   * Ne demandez pas la clé à l&apos;utilisateur. S&apos;ils la collent dans le chat, dites-leur de la révoquer et d&apos;en créer une nouvelle.
   * Faites référence à la clé uniquement par le nom `NEW_RELIC_LICENSE_KEY`. Lorsqu&apos;un guide place la clé dans un fichier de configuration, lisez-la plutôt à partir de cette variable d&apos;environnement.
   * N’exécutez pas de commandes, ou ne lisez pas de fichiers qui afficheraient la clé, comme les fichiers `env`, `printenv`, `echo $NEW_RELIC_LICENSE_KEY`, `.env`, ou les magasins de secrets.
   * Exécutez `test -n "$NEW_RELIC_LICENSE_KEY" && echo set || echo missing` pour vérifier que la clé est définie sans l’exposer.

4. **Suivez le guide :**

   * Demandez un nom d’application à l’utilisateur, ou suggérez-en un en fonction du nom du projet.
   * Si le compte de l’utilisateur se trouve dans la [région de data center](/docs/accounts/accounts-billing/account-setup/choose-your-data-center) de l’UE, ou du Japon, utilisez les points de terminaison que le guide indique pour cette région.

5. **Vérifier :** Demandez à l&apos;utilisateur de définir `NEW_RELIC_LICENSE_KEY` et de redémarrer l&apos;application, puis suivez [Vérifier l&apos;installation](#verify). Si aucune donnée n&apos;apparaît, consultez la page de dépannage répertoriée pour cette technologie.

6. **Résumez :** indiquez à l’utilisateur quels fichiers vous avez modifiés et où trouver son application dans New Relic : <DNT>**APM &amp; Services**</DNT> pour les applications, <DNT>**Browser**</DNT> ou <DNT>**Mobile**</DNT> pour les frontends, et <DNT>**Infrastructure**</DNT> pour les hôtes.

## Vérifiez l’installation [#verify]

Vérifiez en deux étapes : d’abord que l’agent est en cours d’exécution, puis que ses données ont atteint New Relic.

### Vérifiez que les données ont atteint New Relic [#check-data]

Exécutez la requête pour la technologie que vous avez installée, en remplaçant chaque espace réservé par la valeur que vous avez configurée. L’apparition des données peut prendre quelques minutes, et certaines requêtes ne renvoient des résultats qu’une fois que l’application a géré du trafic.

<table>
<thead>
<tr>
<th style={{ width: "200px" }}>
**Technologie**
</th>

<th>
**Qequête**
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
Agent APM
</td>

<td>
`SELECT count(*) FROM ApplicationAgentContext WHERE agent.language = 'LANGUAGE' AND appName = 'APP_NAME' SINCE 30 minutes ago`, où `LANGUAGE` est `nodejs`, `java`, `python`, `dotnet`, `go`, `php`, ou `ruby`
</td>
</tr>

<tr>
<td>
Toute application APM, après le trafic
</td>

<td>
`SELECT count(*) FROM Transaction WHERE appName = 'APP_NAME' SINCE 30 minutes ago`
</td>
</tr>

<tr>
<td>
Docker
</td>

<td>
`SELECT count(*) FROM ContainerSample WHERE name = 'CONTAINER_NAME' SINCE 10 minutes ago`
</td>
</tr>

<tr>
<td>
Kubernetes
</td>

<td>
`SELECT count(*) FROM K8sClusterSample WHERE clusterName = 'CLUSTER_NAME' SINCE 10 minutes ago`
</td>
</tr>

<tr>
<td>
Hôtes
</td>

<td>
`SELECT count(*) FROM SystemSample WHERE hostname = 'HOST_NAME' SINCE 10 minutes ago`
</td>
</tr>

<tr>
<td>
Navigateur web, après le chargement d&apos;une page
</td>

<td>
`SELECT count(*) FROM PageView WHERE appName = 'APP_NAME' SINCE 30 minutes ago`
</td>
</tr>

<tr>
<td>
Mobile, après une session
</td>

<td>
`SELECT count(*) FROM MobileSession WHERE appName = 'APP_NAME' SINCE 30 minutes ago`
</td>
</tr>
</tbody>
</table>

Un nombre supérieur à zéro signifie que les données circulent. Il existe deux façons d’exécuter une requête, et aucune ne vous expose un secret :

* **Demandez à l’utilisateur** de la coller dans le [générateur de requêtes](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder) dans New Relic et de vous indiquer le résultat.
* **Utilisez la [CLI New Relic](https://github.com/newrelic/newrelic-cli)** si l’utilisateur l’a installée, et a défini une <InlinePopover type="userKey" />comme variable d’environnement `NEW_RELIC_API_KEY`. Exécutez `newrelic nrql query --accountId ACCOUNT_ID --query 'QUERY'`. La clé API de l’utilisateur est également un secret, traitez-la donc de la même manière que la clé de licence.
