Dans la [version 1211 de l’agent](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes/browser-agent-v1211/) ou supérieure, toutes les requests réseau effectuées par une page sont enregistrées en tant qu’événements `AjaxRequest`. Vous pouvez configurer quelles requests sont enregistrées et quelles données sont capturées :

* **[Liste de refus](#deny-list)**: filtrez les domaines et URL qui sont exclus du suivi AJAX
* **[Capture de charge](#enable-payload-capture)**: enregistrez les données complètes de requête et de réponse pour déboguer les échecs

## Liste de refus [#deny-list]

Par défaut, nous enregistrons les événements `AjaxRequest` pour toutes les requêtes réseau effectuées par votre application.

* Pour arrêter l&apos;enregistrement de tous les événements, ajoutez un caractère générique `*` (astérisque).
  * Exemple: `*`
* Pour arrêter l&apos;enregistrement des événements pour un site complet, ajoutez le nom de domaine.
  * Exemple: `mywebsite.com`
* Pour arrêter l&apos;enregistrement des événements pour une page spécifique, ajoutez le domaine et le chemin d&apos;accès.
  * Exemple: `mywebsite.com/photos`
* À partir de la [version 1.307.0 de l&apos;agent](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes/browser-agent-v1.307.0/), partout où nous trouvons un `*` (astérisque), nous ferons correspondre n&apos;importe quelle longueur de chaîne.
  * Exemple : `mywebsite.com/shop/*` (pour un chemin), `*.mywebsite.com` (pour un sous-domaine), `mywebsite.com/*/shop/*/checkout` (pour les chaînes de milieu d&apos;URL).

Le protocole, le port, la recherche et le hachage d’une URL sont ignorés par la liste de refus.

### Accéder à la liste de refus [#access-deny-list]

Pour mettre à jour la liste de refus des URL que votre application filtrera pour empêcher la création d&apos;événements, accédez à la page des paramètres de l&apos;application :

1. Allez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Settings &gt; Application settings**</DNT>.
2. Sous la section <DNT>**AJAX data capture settings**</DNT>, dans le champ <DNT>**Deny list**</DNT>, ajoutez les filtres que vous souhaitez appliquer à votre application.
3. Sélectionnez <DNT>**Save**</DNT> pour mettre à jour la configuration de l&apos;agent.
4. [Redéployez l&apos;agent du navigateur](/docs/browser/new-relic-browser/installation/upgrade-browser-agent) (en redémarrant l&apos;agent <InlinePopover type="apm" />associé ou en mettant à jour l&apos;installation du navigateur par copier/coller).

### Valider les filtres de la liste de refus [#validation]

Pour valider si les filtres que vous avez ajoutés fonctionnent comme prévu, exécutez une requête NRQL pour `AjaxRequest` événement correspondant à votre filtre.

```sql
FROM AjaxRequest SELECT * WHERE requestUrl LIKE '%example.com%'
```

## Données de capture de charge [#payload-capture]

<Callout variant="important">
  La capture de charge nécessite la version [1.317.0](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes) ou supérieure de l&apos;agent Browser.
</Callout>

Vous pouvez activer la capture de charge pour toutes les requests ou uniquement pour les requests ayant échoué. Lorsqu’il est activé, l’agent Browser capture la charge de la request et de la réponse pour tous les appels AJAX pour tous les domaines autorisés. Cela est utile pour déboguer les échecs qui ne sont pas visibles à partir des métadonnées seules, tels que les erreurs cachées dans les corps de réponse.

Lorsque vous activez la capture de charge AJAX, l’agent Browser ajoute les attributs suivants aux événements `AjaxRequest` :

* `requestBody`: la charge de la requête.
* `requestHeaders`: en-têtes de requête au format JSON.
* `requestQuery`: les paramètres de requête d’URL au format JSON.
* `responseBody`: la charge de la réponse.
* `responseHeaders`: en-têtes de réponse au format JSON.
* `ajaxRequest.id`: identifiant unique pour chaque requête AJAX.

Tous les attributs de données de charge sont tronqués à 4096 octets. Lorsqu’une troncature se produit, les 4 derniers octets sont remplacés par `...` pour indiquer que le contenu a été coupé.

### Activer la capture de charge [#enable-payload-capture]

Vous pouvez activer la capture de charge à l&apos;aide de l&apos;une des méthodes suivantes :

<CollapserGroup>
  <Collapser id="enable-ui" title="Activer via la plateforme New Relic">
    Pour activer la capture de charge :

    1. Allez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Settings &gt; Application settings**</DNT>.

    2. Dans la section <DNT>**AJAX data capture settings**</DNT>, activez la bascule <DNT>**Capture payload for allowed domains**</DNT>, puis sélectionnez le mode de capture :

       * <DNT>**Capture only failure responses**</DNT>: capture les charges uniquement pour les requests avec un code d’état de `0`, un code de `400` ou supérieur, ou une signature d’erreur GraphQL dans le `response body`.
       * <DNT>**Capture all responses**</DNT>: capture les charges pour toutes les requests, y compris celles qui ont réussi. Utilisez ceci pour déboguer les échecs cachés dans les corps de réponse, tels que les erreurs GraphQL renvoyées avec un statut de réussite.

       <Callout variant="important">
         L&apos;activation de la capture de charge pour les requests <DNT>**Capture all responses**</DNT> peut augmenter votre ingestion de données. Utilisez le mode <DNT>**Capture only failure responses**</DNT> à moins que vous n&apos;ayez spécifiquement besoin de capturer les réponses réussies.
       </Callout>

    3. Cliquez sur <DNT>**Save**</DNT> pour appliquer les modifications.
  </Collapser>

  <Collapser id="configure-nerdgraph" title="Configurer via NerdGraph">
    Vous pouvez utiliser l&apos;[API NerdGraph pour interroger et mettre à jour](/docs/apis/nerdgraph/examples/browser-monitoring-config-nerdgraph/#configure-payload-capture) le paramètre de capture de charge.

    Les valeurs suivantes sont disponibles pour le paramètre `capture_payloads` :

    * `"none"`: ne capture aucune donnée de charge. Il s&apos;agit du paramètre par défaut.
    * `"failures"`: capture les charges uniquement pour les requests avec un code d’état de `0`, un code de `400` ou supérieur, ou une signature d’erreur GraphQL dans le `response body`.
    * `"all"`: capture les données de charge pour toutes les requests, quel que soit le code d&apos;état.
  </Collapser>

  <Collapser id="configure-init" title="Configurer via JavaScript">
    Si vous utilisez la méthode d’installation par copier/coller ou NPM, vous pouvez configurer la capture de charge directement dans votre configuration JavaScript.

    #### Installation par copier/coller

    Ajoutez le paramètre `ajax.capture_payloads` à la configuration de votre navigateur avant le chargeur de l&apos;agent :

    ```js
    window.NREUM.init = {
        ...<other init properties>...,
        ajax: {
          deny_list: ["bam.nr-data.net"],
          capture_payloads: 'failures' // or 'none', 'all'
        }
    }
    ```

    #### Installation de NPM

    Ajoutez le paramètre `ajax.capture_payloads` lors de l&apos;initialisation de l&apos;agent de navigateur :

    ```js
    import { BrowserAgent } from '@newrelic/browser-agent/loaders/browser-agent'

    const options = {
      init: {
        ...<other init properties>...,
        ajax: {
          deny_list: ["bam.nr-data.net"],
          capture_payloads: 'failures' // or 'none', 'all'
        }
      },
      info: { ... },
      loader_config: { ... }
    }

    new BrowserAgent(options)
    ```

    #### Modes de capture

    Les valeurs suivantes sont disponibles pour le paramètre `capture_payloads` :

    * `"none"`: ne capture aucune donnée de charge. Il s&apos;agit du paramètre par défaut.
    * `"failures"`: capture les charges uniquement pour les requests avec un code d’état de `0`, un code de `400` ou supérieur, ou une signature d’erreur GraphQL dans le `response body`.
    * `"all"`: capture les données de charge pour toutes les requests, quel que soit le code d&apos;état.
  </Collapser>
</CollapserGroup>

Lorsque vous activez la capture de charge pour la première fois, New Relic ajoute automatiquement des règles d’obfuscation de base de référence pour protéger les données sensibles courantes :

* [**Numéros de carte de crédit**](/docs/browser/new-relic-browser/configuration/obfuscate-browser-agent-data/#ccn): détecte et masque les principaux formats de carte de crédit (Visa, MasterCard, American Express, Discover, etc.)
* [**Numéros de sécurité sociale**](/docs/browser/new-relic-browser/configuration/obfuscate-browser-agent-data/#ssn): détecte et masque les modèles de SSN

Vous pouvez configurer des règles d’obfuscation dans la plateforme New Relic pour masquer les données sensibles avant qu’elles ne soient envoyées à New Relic. Pour plus de détails sur les règles d’obfuscation, consultez [Obfusquer les données de l’agent Browser](/docs/browser/new-relic-browser/configuration/obfuscate-browser-agent-data).

Après avoir activé le paramètre de capture de charge, vous pouvez afficher les données de charge capturées sur les pages suivantes :

* [Détails de la requête AJAX](/docs/browser/browser-monitoring/browser-pro-features/ajax-page-identify-time-consuming-calls)
* [Affichage de la page](/docs/browser/new-relic-browser/browser-pro-features/page-views-examine-page-performance)
* [Session Replay](/docs/browser/browser-monitoring/browser-pro-features/session-replay/get-started)

### Comment la capture de charge interagit avec la liste de refus [#payload-deny-list]

La capture de charge respecte votre liste de refus existante. Pour toute requête AJAX :

* Si l&apos;URL figure sur la liste de refus, l&apos;événement est entièrement ignoré et aucune métadonnée ou charge n&apos;est capturée.
* Si l&apos;URL ne figure pas sur la liste de refus, en fonction de vos paramètres de capture de charge, l&apos;agent capture les charges de requête et de réponse et applique des règles d&apos;obfuscation avant d&apos;envoyer les données à New Relic.
