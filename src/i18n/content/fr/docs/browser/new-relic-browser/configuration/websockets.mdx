## À quoi sert cette fonctionnalité ?

Cela permet le monitoring de l’état et du trafic de vos connexions WebSockets.

Une nouvelle propriété est disponible dans l’objet d’initialisation de l’agent du browser appelée `web_sockets`. Ce paramètre détermine si la fonctionnalité websockets doit être utilisée dans l’agent. Disponible dans l’agent Browser Pro ou Pro + SPA, [version 1.318.0](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes/browser-agent-v1.318.0) ou supérieure.

## Comment l&apos;utiliser ?

Pour utiliser cette fonctionnalité, vous devrez vous rendre sur la page des paramètres de votre application et activer le bouton `"Enable websockets"`. Ce paramètre est désactivé par défaut.

NerdGraph peut être utilisé comme alternative pour activer et désactiver ce paramètre. Pour ce faire, exécutez une requête de mutation sur l&apos;objet graphQL `browserSettings` pour la propriété `browserWebSockets`, en définissant `enabled` sur `true` ou `false`.

Une fois activée, la collecte de données pour les websockets est automatique après avoir redéployé l’agent. Les données des websockets sont collectées sous forme d’événements [WebSocket](https://docs.newrelic.com/attribute-dictionary/?dataSource=Browser+agent&event=WebSocket) comprenant les métriques de connexion, les messages reçus, les données envoyées, et la manière dont la connexion a été fermée. Chaque instance `WebSocket` est suivie indépendamment, et émet un événement par durée de vie de connexion.

## Considérations supplémentaires

* Si les [traces de session](/docs/browser/browser-monitoring/browser-pro-features/session-traces-explore-webpages-life-cycle) sont activées, les événements WebSocket peuvent être liés via la propriété `sessionTraceId` dans le cadre de vos traces de session.
