L’ [API WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API) permet d’ouvrir une session de communication interactive bidirectionnelle entre le navigateur de l’utilisateur et un serveur. Cette session permet d’envoyer et de recevoir des données sans interroger le serveur pour obtenir une réponse. Avec le monitoring de navigateurs New Relic, vous pouvez monitorer et suivre le trafic et l’état de santé de vos sessions websocket.

Les données Websockets de l’API sont enregistrées en tant qu’événements [WebSocket](https://docs.newrelic.com/attribute-dictionary/?dataSource=Browser+agent&event=WebSocket) par l’agent Browser Ces événements incluent des métriques sur la connexion, les messages reçus, les données envoyées, et la façon dont la connexion a été fermée pendant le cycle de vie du websocket.

## Pourquoi utiliser le monitoring des websockets ?

Le suivi automatique des websockets avec New Relic fournit les outils et les informations détaillées pour vous assurer que vos websockets fonctionnent comme prévu. Avec `WebSocket` événements, vous pouvez :

* Monitorez les octets envoyés et reçus de vos connexions réseau
* Examinez si les websockets se ferment correctement ou non et pour quelle raison
* Dépannez les erreurs JavaScript qui se produisent pendant le cycle de vie de vos websockets
* Créez des dashboards personnalisés et des alertes basées sur des websockets

## Prérequis [#prerequisites]

* Un agent Browser **Pro** ou **Pro + SPA**, version 1.318.0 ou supérieure.

<Callout variant="important">
  Le monitoring des websockets n’est pas disponible pour l’agent Browser Lite.
</Callout>

## Activer la collecte automatique [#enable-collection]

Améliorez l&apos;observabilité et les capacités de débogage de votre application en suivant ces instructions de configuration simples.

<Steps>
  <Step>
    Accédez à **[one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Browser**.
  </Step>

  <Step>
    Sélectionnez votre application de navigateur.
  </Step>

  <Step>
    Dans le menu de gauche, cliquez sur **Paramètres de l’application**.
  </Step>

  <Step>
    Assurez-vous que l&apos;agent de navigateur **Pro** ou **Pro + SPA** est sélectionné.
  </Step>

  <Step>
    Activez **Enable websockets**.
  </Step>
</Steps>

## Désactiver la collecte des websockets [#disable-websockets]

Pour désactiver les websockets pour une application de navigateur existante :

<Steps>
  <Step>
    Accédez à **[one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Browser**.
  </Step>

  <Step>
    Sélectionnez votre application de navigateur.
  </Step>

  <Step>
    Dans le menu de gauche, cliquez sur **Paramètres de l’application**.
  </Step>

  <Step>
    Pour désactiver les websockets, désactivez **Enable websockets**.
  </Step>
</Steps>

## Consommation de données

`WebSocket` événement suivent la même tarification de consommation que vos autres octets de navigateur. La quantité d&apos;octets produits dépend du nombre et de l&apos;attribut des données.

Une fois activé, l’agent capturera automatiquement les websockets lorsqu’ils se produisent dans votre application.

## Retrouvez vos données dans New Relic [#find-data]

Les websockets sont stockés en tant que `WebSocket` événement dans New Relic. Consultez le [dictionnaire de données](https://docs.newrelic.com/attribute-dictionary/?dataSource=Browser+agent&event=WebSocket) pour plus d’informations sur les champs disponibles pour une utilisation avec `WebSocket` événement. Pour un dashboard rapide et utile, consultez ce [quickstart](https://newrelic.com/instant-observability/browser-web-sockets). Vous pouvez interroger et visualiser ces données pour obtenir des informations détaillées sur les performances de votre application :

**Mesurez la quantité totale d’instances websocket au fil du temps**

```nrql
FROM WebSocket
SELECT count(*)
TIMESERIES
```

**Afficher les raisons pour lesquelles les websockets se ferment de manière inattendue**

```nrql
FROM WebSocket
SELECT count(*)
FACET closeReason
```

**Suivre les websockets avec des erreurs**

```nrql
FROM WebSocket
SELECT count(*) AS 'Errors'
WHERE hasErrors IS true
TIMESERIES
```

**Afficher la moyenne des octets envoyés et reçus**

```nrql
FROM WebSocket
SELECT average(sendBytes), average(messageBytes)
WHERE messageCount IS NOT null
TIMESERIES 
```

**Monitorer la durée moyenne des websockets**

```nrql
FROM WebSocket
SELECT average(connectedDuration)
FACET cases(
  WHERE closeWasClean IS true AS 'Connected - Clean',
  WHERE closeWasClean IS NOT true AS 'Connected - Dirty'
)
TIMESERIES
```

Utilisez ces requêtes ou créez les vôtres pour créer des dashboards personnalisés, configurer des alertes et monitorer les performances réelles de vos applications Web avec précision.
