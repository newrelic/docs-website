Les widgets personnalisés vous permettent d’étendre le dashboard Media Streaming avec des visualisations de graphiques créées à partir de vos propres requêtes NRQL. Utilisez-les lorsque les métriques de qualité intégrées ne couvrent pas un point de données spécifique que votre équipe doit monitorer.

<Callout variant="important">
  Chaque compte prend en charge une limite souple de **50 widgets personnalisés par contexte de dashboard** : 50 pour <DNT>**Video quality metrics**</DNT> et 50 pour <DNT>**Ad quality metrics**</DNT>, comptés séparément. Si vous atteignez la limite, supprimez un widget personnalisé existant avant d&apos;en ajouter un nouveau. Vos widgets existants continuent de fonctionner normalement.
</Callout>

## Avant de commencer [#prereqs]

Vous avez besoin des éléments suivants avant de créer un widget personnalisé :

* Accès à un compte New Relic avec l’agent <DNT>Streaming Video &amp; Ads</DNT> installé. Consultez [Installer l’agent Streaming vidéo et publicitaire](/docs/streaming-video-&-ads/installation/install-the-streaming-video-&-ads-agent) si vous ne l’avez pas encore configuré.
* Le bouton <DNT>**+ Add Custom Widget**</DNT> visible dans la [section Métriques de qualité](/docs/streaming-video-&-ads/view-data-in-newrelic/streaming-video-&-ads-features). Si ce n’est pas le cas, contactez votre équipe de compte New Relic pour demander l’accès.

## Écrivez votre requête NRQL [#writing-queries]

L’éditeur NRQL prend en charge toute requête NRQL valide. Pour une introduction à la syntaxe NRQL, consultez [Introduction à NRQL](/docs/nrql/get-started/introduction-nrql-how-nrql-works).

### Exigences de la requête [#query-requirements]

Les requêtes de widget personnalisées ont deux exigences supplémentaires au-delà du NRQL standard :

* N’écrivez pas de clause `SINCE` ou `UNTIL` directement dans votre requête. Le sélecteur d’intervalle de temps du dashboard ajoute automatiquement la plage de temps lorsque la requête s’exécute.
* Pour répondre aux sélections de la barre de filtres au niveau du dashboard, incluez un [espace réservé de filtre](#placeholders) dans votre requête.

### Espaces réservés de filtrage [#placeholders]

Le dashboard applique des filtres globaux lorsqu’une requête s’exécute. Si vous écrivez une clause `WHERE` simple directement dans votre requête, le dashboard ne peut pas y injecter les conditions de filtre sélectionnées par l’utilisateur. Les espaces réservés de filtre sont des commentaires NRQL spéciaux qui sont remplacés par les conditions de filtre actives lorsque la requête s’exécute.

| Espace réservé                  | Remplacé par        | Quand l&apos;utiliser                                                                                                                                            |
| ------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/* {whereClause} */`           | `WHERE [filters]`   | La requête n’a pas de clause `WHERE` existante                                                                                                                   |
| `/* {andWhereClause} */`        | `AND [filters]`     | La requête possède déjà une clause `WHERE` — y ajoute des filtres                                                                                                |
| `/* {aggregatorWhereClause} */` | `, WHERE [filters]` | La requête utilise un agrégateur `filter()` sans clause `WHERE` interne existante : le wrapper `filter()` est supprimé lorsqu&apos;aucun filtre n&apos;est actif |

**Exemple — aucune clause WHERE existante :**

```sql
SELECT count(*) FROM VideoAction /* {whereClause} */
```

Avec le filtre `City = Ashburn` appliqué :

```sql
SELECT count(*) FROM VideoAction WHERE city = 'Ashburn' SINCE 30 minutes ago UNTIL now
```

**Exemple — clause WHERE existante :**

```sql
SELECT count(*) FROM VideoAction
WHERE actionName = 'QOE_AGGREGATE' /* {andWhereClause} */
```

Avec le filtre `City = Ashburn` appliqué :

```sql
SELECT count(*) FROM VideoAction
WHERE actionName = 'QOE_AGGREGATE' AND city = 'Ashburn' SINCE 30 minutes ago UNTIL now
```

**Exemple — requête de ratio avec des agrégateurs mixtes :**

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' /* {andWhereClause} */)
     / filter(uniqueCount(viewId) /* {aggregatorWhereClause} */)
  AS 'avgWatchTime'
TIMESERIES
```

Avec le filtre `City = Ashburn` appliqué :

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' AND city = 'Ashburn')
     / filter(uniqueCount(viewId), WHERE city = 'Ashburn')
  AS 'avgWatchTime'
TIMESERIES SINCE 30 minutes ago UNTIL now
```

Sans aucun filtre actif :

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT')
     / uniqueCount(viewId)
  AS 'avgWatchTime'
TIMESERIES SINCE 30 minutes ago UNTIL now
```

<Callout variant="tip">
  Les espaces réservés sont des commentaires NRQL valides : cliquer sur <DNT>**Run Query**</DNT> fonctionne même lorsqu’aucun filtre n’est actif dans le dashboard.
</Callout>

### Mots-clés et caractères bloqués [#blocked]

Pour éviter toute modification accidentelle des données, l’éditeur NRQL rejette les requêtes qui contiennent :

* Les mots-clés `DROP`, `DELETE`, `INSERT`, `UPDATE`, `CREATE`, ou `ALTER`
* Les points-virgules (`;`), qui permettraient une chaîne de requêtes

Les requêtes contenant l’un de ces éléments échouent à la validation et ne peuvent pas être enregistrées, ou prévisualisées.

### Exemples de requêtes [#sample-queries]

Les exemples suivants montrent des modèles de requête courants pour le monitoring vidéo et publicitaire. Chacun utilise l’espace réservé de filtre approprié pour sa structure de requête.

**Série chronologique de base — nombre total de lancements de vidéos :**

```sql
SELECT count(*) AS 'Video Starts'
FROM VideoAction
WHERE actionName = 'CONTENT_START' /* {andWhereClause} */
TIMESERIES
```

**Nombre de spectateurs uniques avec intégration de filtre :**

```sql
SELECT uniqueCount(viewId) AS 'Unique Viewers'
FROM VideoAction /* {whereClause} */
TIMESERIES
```

**Taux d’erreur sur l’ensemble des types d’événements :**

```sql
SELECT count(*) AS 'Error Count'
FROM VideoErrorAction, VideoAction
WHERE actionName = 'CONTENT_ERROR' /* {andWhereClause} */
TIMESERIES
```

**Temps de visionnage moyen (ratio avec des agrégateurs imbriqués) :**

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' /* {andWhereClause} */)
     / filter(uniqueCount(viewId) /* {aggregatorWhereClause} */)
  AS 'avgWatchTime'
TIMESERIES
```

### Limites [#known-limitations]

Certains modèles de requête NRQL ont une prise en charge limitée ou non testée lorsque les filtres globaux sont actifs. Consultez [Limitations pour le Streaming vidéo et publicitaire](/docs/streaming-video-&-ads/limitations#nrql-patterns) pour obtenir la liste complète.

## Créer un widget personnalisé [#create]

Pour créer un widget personnalisé :

1. Allez dans <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Streaming Video &amp; Ads**</DNT>, puis sélectionnez <DNT>**Video Overview**</DNT> ou <DNT>**Ads Overview**</DNT>.
2. Faites défiler vers le bas jusqu&apos;à la section <DNT>**Video Quality Metrics**</DNT> ou <DNT>**Ad Quality Metrics**</DNT>.
3. Cliquez sur <DNT>**+ Add Custom Widget**</DNT> dans l’en-tête de la section.
4. Saisissez un titre unique pour le widget.
5. Écrivez votre requête NRQL dans l’éditeur NRQL. Consultez [Écrivez votre requête NRQL](#writing-queries) ci-dessus pour obtenir des conseils sur la syntaxe, les espaces réservés de filtre et des exemples.
6. Cliquez sur <DNT>Run Query</DNT> pour prévisualiser les résultats par rapport aux données en direct. Cela n’enregistre pas le widget. Utilisez l’aperçu pour confirmer que le graphique affiche les données que vous attendez, vérifier que les espaces réservés de filtre se résolvent correctement lorsqu’un filtre est actif, et détecter toute erreur de syntaxe ou de logique avant d’enregistrer.
7. Lorsque l’aperçu se charge, le sélecteur de type de graphique apparaît. La valeur par défaut est <DNT>Line</DNT> : sélectionnez un type différent si nécessaire. Certains types de graphiques peuvent apparaître grisés s’ils ne sont pas recommandés pour les résultats de votre requête, mais vous pouvez toujours sélectionner l’un d’entre eux : **Billboard**, **Line**, **Area**, **Bar**, **Table**, ou **Pie**.
8. Cliquez sur <DNT>**Save**</DNT>. New Relic ajoute le widget à la section <DNT>**Custom Metrics**</DNT> de la liste déroulante du sélecteur de métrique et l’affiche en haut de la grille des métriques de qualité. Les widgets persistent d’une session à l’autre.

<Callout variant="tip">
  La disponibilité des widgets dépend de la vue dans laquelle vous les créez :

  * **Vue de toutes les plateformes** (Aperçu vidéo ou Aperçu des annonces) : les widgets sont visibles par tous les utilisateurs du compte.
  * **Vue d’une application unique** (page d’une application spécifique) : les widgets sont spécifiques à cette application.

  Le type de graphique ne dépend pas de la vue : le type de graphique que vous définissez s’applique à tous les utilisateurs, quelle que soit la vue qu’ils utilisent.
</Callout>

## Modifier un widget personnalisé [#edit]

Pour modifier un widget personnalisé :

1. Dans la section <DNT>**Quality Metrics**</DNT>, localisez le widget personnalisé que vous souhaitez modifier.
2. Cliquez sur l’icône en forme de crayon <Icon name="fe-edit-2" /> sur la carte du widget. L’éditeur s’ouvre avec votre titre et votre requête existants préremplis.
3. Apportez vos modifications, cliquez sur <DNT>**Run Query**</DNT> pour vérifier, puis cliquez sur <DNT>**Save**</DNT>.

Lors de l’enregistrement :

* Votre date de création d’origine et l’identité du widget sont préservées.
* le widget se réaffiche immédiatement avec la requête mise à jour.
* Si vous avez modifié le titre, il se met à jour dans la liste déroulante du sélecteur de métrique.

## Supprimer un widget personnalisé [#delete]

Pour supprimer un widget personnalisé :

1. Dans la section <DNT>**Quality Metrics**</DNT>, cliquez sur l’icône <Icon name="fe-more-horizontal" /> sur la carte du widget.
2. Sélectionnez <DNT>**Delete**</DNT>.
3. Confirmez dans le prompt : *« Êtes-vous sûr de vouloir supprimer “\[Widget Title]” ? Cette action ne peut pas être annulée. »*

Une fois supprimé :

* New Relic supprime définitivement le widget.
* Le dashboard supprime immédiatement la carte du widget.
* La liste déroulante du sélecteur de métrique supprime l’entrée du titre.
* Si le widget a été sélectionné, le dashboard le désélectionne automatiquement.

<Callout variant="caution">
  La suppression est définitive. Copiez votre requête NRQL avant de supprimer un widget si vous risquez d’en avoir besoin plus tard.
</Callout>

## Dépannage [#troubleshoot]

Trouvez votre symptôme ci-dessous. Les problèmes sont classés du plus au moins courant.

### Le widget ne se met pas à jour lorsque j’applique un filtre de dashboard [#widget-not-responding-to-filters]

Il manque un espace réservé de filtre à votre requête. Sans `/* {whereClause} */`, `/* {andWhereClause} */` ou `/* {aggregatorWhereClause} */`, le widget exécute toujours la requête telle qu’elle est écrite et ignore les sélections de la barre de filtres du dashboard. Consultez [Espaces réservés de filtre](#placeholders) pour choisir celui qui convient à la structure de votre requête.

### Les filtres s’appliquent mais la requête renvoie une erreur ou aucune donnée [#wrong-placeholder]

Vous avez peut-être utilisé le mauvais type d&apos;espace réservé. Vérifier :

* Si votre requête n&apos;a pas de clause `WHERE`, utilisez `/* {whereClause} */`.
* Si votre requête possède déjà une clause `WHERE` au niveau de la requête, utilisez `/* {andWhereClause} */`.
* Si l’espace réservé se trouve dans un agrégateur `filter()` sans `WHERE` interne existant, utilisez `/* {aggregatorWhereClause} */`.

Le mauvais espace réservé produit un NRQL non valide lors de l&apos;exécution de la requête, ce qui entraîne son échec.

### Ma requête échoue à la validation ou ne s’enregistre pas [#query-blocked]

Vérifiez si votre requête contient un [mot-clé ou caractère bloqué](#blocked), tel que `DROP`, `DELETE`, ou un point-virgule. Vérifiez également que la requête répond à ces exigences :

* La requête contient à la fois les clauses `SELECT` et `FROM`.
* Il n&apos;y a aucune erreur de syntaxe signalée par la validation en ligne de l&apos;éditeur.

### Le widget ne s’enregistre pas : le titre existe déjà [#duplicate-title]

Si un widget avec le même titre existe déjà dans le même contexte de dashboard (métriques de qualité vidéo ou publicitaire), l’enregistrement échoue avec une notification toast :

* **Titre :** échec de l’enregistrement du widget
* **Description :** un widget avec ce nom existe déjà

La correspondance des titres est insensible à la casse : `My Widget` et `MY WIDGET` sont traités comme le même titre. Choisissez un titre distinct ou renommez d&apos;abord le widget existant.

### Le widget s&apos;enregistre mais disparaît après une actualisation de la page [#widget-not-saving]

Cela peut indiquer un échec d’enregistrement. Vérifiez si une notification toast est apparue au moment de l’enregistrement : elle indiquera si l’enregistrement a échoué en raison d’une erreur réseau. Réessayez d’enregistrer, ou contactez votre équipe de compte New Relic si le problème persiste.

### Je ne peux pas ajouter de nouveau widget [#limit-reached]

Vous avez atteint la limite souple de 50 widgets pour ce contexte de dashboard (métriques de qualité vidéo ou publicitaire). Supprimez au moins un widget personnalisé existant, puis essayez d’en ajouter un nouveau.

### Le bouton + Ajouter un widget personnalisé n’est pas visible [#button-not-visible]

New Relic contrôle l’accès à cette fonctionnalité. Contactez votre équipe de compte New Relic pour demander l’accès.
