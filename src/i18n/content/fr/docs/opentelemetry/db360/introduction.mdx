Database 360 (DB360) vous donne une vue unifiée sur vos applications, bases de données et infrastructure afin que vous puissiez trouver plus rapidement la cause première des goulots d’étranglement de base de données. Au lieu de jongler entre des outils d’application, de base de données et d’infrastructure distincts pour comprendre pourquoi une requête est lente, DB360 modélise chaque base de données comme une entité de premier ordre et la connecte directement à vos services APM et métriques d’hôte.

DB360 est conçu sur une base axée sur OpenTelemetry. Vous collectez la télémétrie à l’aide du Collector New Relic Distribution of OpenTelemetry (NRDOT) ou d’une distribution CNCF OpenTelemetry Collector Contrib.

## Ce que vous obtenez [#capabilities]

* **Plans d’exécution de requête**: visualisez le chemin d’exécution exact qu’emprunte une requête, y compris les événements d’attente et les verrous, afin que vous puissiez repérer les index manquants et autres inefficacités.
* **États d’attente et suivi des verrous**: identifiez les sessions de longue durée, les requêtes bloquantes, et les workloads gourmands en ressources avant qu’ils n’affectent d’autres workloads sur la même base de données.
* **Corrélation APM-base de données**: liez les traces d’application directement aux requêtes de base de données, aux sessions et aux événements d’attente qu’elles génèrent. Pour plus d’informations, consultez [la corrélation APM-base de données](/docs/opentelemetry/db360/capabilities/db-apm).
* **Contexte d’infrastructure**: affichez les métriques de base de données côte à côte avec les métriques de CPU, de mémoire, et d’I/O au niveau de l’hôte.
* **Visibilité du nœud, et de la base de données logique**: monitorez à la fois le serveur de base de données (nœud), et les bases de données logiques individuelles qui s’y exécutent, afin que vous puissiez dimensionner correctement la capacité, et repérer les instances inactives, ou sous-utilisées.

## À savoir avant de commencer [#considerations]

* **Corrélation APM**: la liaison des entités de base de données aux traces APM fonctionne actuellement avec l’agent Java et l’agent .NET.

* **Couverture des fournisseurs de cloud**:

  * **AWS**: RDS, Aurora, et les bases de données auto-hébergées sur EC2 sont prises en charge sur les quatre moteurs de base de données.
  * **Oracle Cloud Infrastructure (OCI)**: la base de données Oracle est prise en charge via Autonomous Database.

* **Volume de métriques**: les bases de données auto-hébergées exposent généralement plus de métriques que leurs équivalents gérés dans le cloud, car les fournisseurs de cloud restreignent l’accès à certains composants internes de la base de données.

* **Contrôles d’ingestion**: vous pouvez activer ou désactiver des catégories de métriques dans votre fichier de configuration NRDOT pour gérer le volume de données que vous collectez.
