Obtenez des informations détaillées sur les performances de votre base de données Oracle avec notre solution de monitoring basée sur OpenTelemetry. Suivez les métriques de la base de données, analysez les performances des requêtes, monitorez l’utilisation des ressources, et corrélez les performances de la base de données avec vos applications.

Cette approche basée sur NRDOT complète notre On-Host Integration (OHI) existante en s&apos;appuyant sur les standards OpenTelemetry pour le monitoring des bases de données, facilitant ainsi l&apos;intégration avec votre pile d&apos;observabilité existante.

Contrairement aux intégrations sur hôte, NRDOT fonctionne indépendamment de l’agent d’infrastructure. Il ne nécessite pas l’agent d’infrastructure pour collecter la télémétrie de la base de données. NRDOT inclut également des capacités natives de monitoring d’hôte, vous pouvez donc choisir de :

* Utilisez l&apos;agent d&apos;infrastructure pour le monitoring de l&apos;hôte en parallèle de NRDOT pour le monitoring de la base de données, ou
* Utilisez NRDOT pour monitorer à la fois la base de données et l&apos;hôte.

## Capacités [#capabilities]

* **Standards OpenTelemetry**: s’intègre parfaitement aux outils d’observabilité existants
* **Métriques exhaustives**: informations détaillées approfondies sur les performances de la base de données, les événements d&apos;attente, et l&apos;utilisation des ressources
* **Informations détaillées au niveau des requêtes**: identifiez et analysez les requêtes lentes et l’activité des sessions
* **Déploiement flexible**: fonctionne avec les environnements CDB/PDB sur hôte et Amazon RDS
* **Corrélation APM**: connectez les performances de la base de données aux traces de l’application

## Choisissez votre chemin d&apos;installation [#choose]

Vous pouvez installer le NRDOT Collector pour le monitoring d’Oracle Database des manières suivantes :

* Environnements auto-hébergés : installation manuelle sur votre propre infrastructure

  * [Base de données conteneur sur l’hôte (CDB)](/docs/opentelemetry/db360/oracle/host-cdb): monitorer une base de données conteneur entière, y compris toutes les bases de données enfichables sous-jacentes.
  * [Base de données enfichable (PDB) sur l’hôte](/docs/opentelemetry/db360/oracle/host-pdb): monitorer une base de données enfichable individuelle.

* Environnements AWS RDS : monitoring de la base de données Oracle gérée dans le cloud
  * [Monitoring RDS](/docs/opentelemetry/db360/oracle/rds): monitorer une instance de base de données Oracle s’exécutant dans Amazon RDS.

* Environnements Oracle Cloud : monitoring de base de données Oracle entièrement géré
  * [Monitoring d’Autonomous Database (ADB)](/docs/opentelemetry/db360/oracle/adb): monitorez une instance Oracle Autonomous Database.

* [New Relic CLI](/docs/opentelemetry/db360/oracle/cli): installer et configurer le collecteur avec une seule commande

* [Ansible](/docs/opentelemetry/db360/oracle/ansible): installez et configurez le collecteur à grande échelle à l’aide du rôle Ansible `newrelic.newrelic_install`

* [Chef](/docs/opentelemetry/db360/oracle/chef): installez et configurez le collecteur à grande échelle à l&apos;aide du cookbook Chef `newrelic-install`

* [Chart Helm](/docs/opentelemetry/db360/oracle/helm): installez et configurez le monitoring de la base de données Oracle sur Kubernetes à l’aide du chart Helm `oracle-otel`

* [Docker](/docs/opentelemetry/db360/oracle/docker): exécutez le collecteur en tant que conteneur frère d&apos;une instance de base de données Oracle déjà en cours d&apos;exécution dans Docker

## Installation guidée [#ui-install]

L&apos;installation guidée est disponible sur <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>. L&apos;UI fournit un workflow guidé de bout en bout.

## Installation en un coup d&apos;œil [#at-a-glance]

1. Vérifiez la compatibilité et rassemblez les prérequis.
2. Installez le Collector NRDOT.
3. Configurer l&apos;utilisateur de monitoring.
4. Configurer le Collector NRDOT.
5. Redémarrez le Collector NRDOT.
6. Vérifiez que les données circulent vers New Relic.
