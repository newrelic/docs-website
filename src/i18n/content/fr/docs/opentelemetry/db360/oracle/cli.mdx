Vous pouvez installer et configurer le NRDOT Collector pour le monitoring d&apos;Oracle Database à l&apos;aide de la CLI New Relic. La CLI installe le collecteur, crée l&apos;utilisateur de la base de données de monitoring, et configure le collecteur en une seule commande.

<Callout variant="tip" title="Installation guidée">
Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)** </DNT>. Cette page traite uniquement de l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.
* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.
* Oracle Database 19c ou version ultérieure.
* Pour Oracle auto-hébergé : Oracle Linux 7, 8 ou 9, avec `curl` et `systemd` installés, et un accès SSH (avec transfert d’agent) à l’hôte de la base de données Oracle où l’utilisateur SSH peut exécuter `sudo su - oracle` sans prompt de mot de passe.
* Pour Oracle sur AWS RDS : un hôte collecteur exécutant Debian/Ubuntu ou CentOS/RHEL/OEL, avec `curl` et `systemd` installés, et une connectivité réseau de l’hôte collecteur au point de terminaison Oracle RDS.
* Pour Oracle Autonomous Database (ADB) : un hôte collecteur exécutant Debian/Ubuntu ou CentOS/RHEL/OEL, avec `curl`, `systemd`, et Oracle Instant Client (`sqlplus`) installés et sur `PATH`; l’adresse IP de sortie de chaque instance autorisée dans sa liste de contrôle d’accès ADB ; et l’Oracle Wallet de chaque instance téléchargé et décompressé dans son propre répertoire sur l’hôte collecteur.
</Step>

<Step>
## Installer et configurer le NRDOT Collector [#install]

<CollapserGroup>
<Collapser id="cli-host" title="Base de données Oracle auto-hébergée">
Cette recette monitore une ou plusieurs instances de base de données Oracle (chacune accessible via SSH) depuis un seul collecteur. Au lieu de demander un seul ensemble hôte/conteneur/identifiants, elle lit un fichier d’instances (YAML) listant chaque instance à monitorer, et éventuellement un fichier de secrets pour fixer des mots de passe spécifiques d’utilisateur de monitoring au lieu de les générer automatiquement.

Avant d’exécuter cette commande, préparez :

* Accès SSH (avec transfert d&apos;agent) à chaque hôte de base de données Oracle listé, où chaque `ssh_user` peut exécuter `sudo su - oracle` sans prompt de mot de passe
* Type de conteneur par instance (CDB pour tous les PDB, ou un seul nom de PDB)
* Nom de service CDB ou PDB par instance
* Que vous souhaitiez des métriques Basic ou Advanced

1. Créer le fichier d’instance. Ajouter une entrée par instance de base de données Oracle que vous souhaitez que ce collecteur monitore ; juste une entrée si vous effectuez uniquement le monitoring d’une seule instance :

   ```bash
   cat > ~/oracle-instances.yml << 'EOF'
   instances:
     - host: dbhost1.example.com
       port: 1521
       ssh_user: opc
       container_type: 1
       pdb_name:
       service: ORCLCDB
       login_name: newrelic
   EOF
   ```

   `container_type` est `1` pour CDB (monitore tous les PDB, crée un utilisateur `c##<login_name>` commun) ou `2` pour un seul PDB (`pdb_name` requis uniquement dans ce cas). Saisissez `login_name` sans le préfixe `c##` : la recette l’ajoute pour vous en mode CDB.

2. (Facultatif) Créez un fichier de secrets pour définir un mot de passe fixe pour l’utilisateur de monitoring par instance au lieu de laisser la recette en générer un automatiquement. Oracle auto-hébergé ne nécessite pas d’identifiants d’administrateur ici. L’utilisateur de monitoring est créé via SSH et un accès SYSDBA authentifié par le système d’exploitation :

   ```bash
   umask 077
   cat > ~/oracle-secrets.env << 'EOF'
   NR_CLI_ORACLE_LOGIN_PASSWORD_1=SomeFixedPassword1
   EOF
   chmod 600 ~/oracle-secrets.env
   ```

   Laissez le chemin du fichier de secrets vide (ou pointez-le vers un fichier qui n’existe pas) pour générer automatiquement un mot de passe aléatoire pour chaque instance à la place.

Exécutez ceci depuis un hôte avec un accès SSH (avec transfert d’agent) vers chaque hôte de base de données Oracle répertorié dans votre fichier d’instance :

```bash
curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle
```

La CLI affiche un prompt de manière interactive pour les variables suivantes. Vous pouvez également les définir à l’avance comme variables d’environnement pour une exécution non interactive.

<Collapser id="cli-rds" title="Oracle Database sur AWS RDS">
Cette recette monitore un ou plusieurs points de terminaison Oracle RDS depuis un seul collecteur, en utilisant un fichier d’instance et un fichier de secrets.

Avant d’exécuter cette commande, préparez :

* Point de terminaison RDS Oracle, port d&apos;écoute, et nom du service de base de données pour chaque instance
* Nom d’utilisateur et mot de passe maître RDS pour chaque instance
* Que vous souhaitiez des métriques Basic ou Advanced

1. Créez le fichier d&apos;instance (une entrée par point de terminaison RDS Oracle que vous souhaitez que ce collecteur monitore, toujours une seule entrée si vous ne monitorez qu&apos;une seule instance) :

   ```bash
   cat > ~/oracle-instances.yml << 'EOF'
   instances:
     - host: rds-orders.abcdef123.us-east-1.rds.amazonaws.com
       port: 1521
       service: ORDERSDB
       login_name: newrelic
   EOF
   ```

2. Créez le fichier de secrets avec le nom d’utilisateur et le mot de passe maître RDS pour chaque instance, indexé pour correspondre à l’ordre du fichier d’instance. Vous pouvez également définir un mot de passe fixe pour l’utilisateur de monitoring par instance. Omettez-le pour en générer un automatiquement :

   ```bash
   umask 077
   cat > ~/oracle-secrets.env << 'EOF'
   NR_CLI_ORACLE_ADMIN_USER_1=admin
   NR_CLI_ORACLE_ADMIN_PASSWORD_1=YourMasterPassword1
   EOF
   chmod 600 ~/oracle-secrets.env
   ```

```bash
curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle-rds
```

<Collapser id="cli-adb" title="Oracle Autonomous Database (ADB)">
Cette recette monitore une ou plusieurs instances de base de données Oracle Autonomous (ADB) depuis un seul collecteur, en utilisant un fichier d’instances ainsi qu’un fichier de secrets. Chaque instance se connecte via TLS mutuel (par défaut dans ADB) en utilisant son propre portefeuille téléchargé. Ne partagez pas un même répertoire de portefeuille entre les instances.

Avant d’exécuter cette commande, préparez :

* Pour chaque instance : sa chaîne de connexion (`host`, `port`, `service`, depuis **Database connection &gt; Connection strings** de la console ADB)
* Pour chaque instance : son Oracle Wallet téléchargé (**Database connection &gt; Download wallet** de la console ADB), décompressé dans son propre répertoire sur l’hôte du collecteur
* Nom d’utilisateur et mot de passe de l’administrateur ADB (`ADMIN`) pour chaque instance

1. Créez le fichier d&apos;instance. Ajoutez une entrée par instance ADB que vous souhaitez que ce collecteur monitore ; juste une entrée si vous ne monitorez qu&apos;une seule instance :

   ```bash
   cat > ~/adb-instances.yml << 'EOF'
   instances:
     - host: adb1.adb.us-ashburn-1.oraclecloud.com
       port: 1522
       service: myadb1_high
       login_name: newrelic
       wallet_dir: /home/opc/wallet1
   EOF
   ```

   `wallet_dir` est le répertoire où le portefeuille de cette instance a été décompressé (doit contenir `cwallet.sso` et `sqlnet.ora`) ; une instance avec un répertoire de portefeuille manquant ou non valide est ignorée plutôt que de faire échouer l’ensemble de l’installation.

2. Créez le fichier de secrets avec le nom d’utilisateur et le mot de passe administrateur ADB pour chaque instance, indexés pour correspondre à l’ordre du fichier d’instance. Vous pouvez également définir un mot de passe fixe pour l’utilisateur de monitoring par instance. Omettez-le pour en générer un automatiquement :

   ```bash
   umask 077
   cat > ~/adb-secrets.env << 'EOF'
   NR_CLI_ORACLE_ADMIN_USER_1=ADMIN
   NR_CLI_ORACLE_ADMIN_PASSWORD_1=YourAdminPassword1
   EOF
   chmod 600 ~/adb-secrets.env
   ```

Exécutez ceci depuis un hôte qui a `sqlplus` (Oracle Instant Client) sur `PATH` et une connectivité réseau (mTLS) vers chaque instance ADB répertoriée :

```bash
curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle-adb
```

La CLI affiche un prompt de manière interactive pour les variables suivantes. Vous pouvez également les définir à l’avance comme variables d’environnement pour une exécution non interactive.
