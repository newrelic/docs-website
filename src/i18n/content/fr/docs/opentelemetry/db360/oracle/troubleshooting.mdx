Résolvez les problèmes courants que vous pouvez rencontrer lors du monitoring de votre base de données Oracle avec le Collector NRDOT.

## Problèmes courants [#common-issues]

<CollapserGroup>
  <Collapser id="test-connection" title="Tester la connectivité réseau">
    Exécutez la commande suivante pour vérifier que le port de la base de données Oracle est accessible depuis cet hôte.

    ```bash
    (timeout 3 bash -c '</dev/tcp/<YOUR_ENDPOINT>/<YOUR_PORT>' && echo "PORT OPEN - Network connection successful!") || echo "CONNECTION FAILED - Port closed or firewall blocking"
    ```

    **Résultat attendu :** `PORT OPEN - Network connection successful!`
  </Collapser>

  <Collapser id="otlp-endpoint-connection" title="Tester la connectivité du point de terminaison OTLP">
    Exécutez la commande suivante pour vérifier que votre hôte peut atteindre le point de terminaison OTLP New Relic sélectionné.

    ```bash
    ENDPOINT="<YOUR_OTLP_ENDPOINT>"
    HOST=$(echo "$ENDPOINT" | sed 's|https://||' | cut -d: -f1)
    PORT=$(echo "$ENDPOINT" | awk -F: '{print $NF}')
    (timeout 2 bash -c "</dev/tcp/$HOST/$PORT" && echo "SUCCESS") || echo "FAILED"
    ```

    **Résultat attendu :** `SUCCESS`
  </Collapser>
</CollapserGroup>

## Les données n&apos;apparaissent pas dans New Relic [#data-not-flowing]

* Pour vérifier les problèmes liés à la limitation de débit, exécutez :

  ```sql
  SELECT * FROM NrIntegrationError
  ```

* Si les données ne circulent toujours pas, vérifiez si des règles de suppression sont définies sur vos événements de métrique et de log. Consultez [Supprimer les données de log avec des règles de filtre de suppression](/docs/logs/ui-data/drop-data-drop-filter-rules/) et [Contrôle du Pipeline](/docs/new-relic-control/pipeline-control/overview/).

* Vérifiez les logs du NRDOT Collector :

  ```bash
  journalctl -u nrdot-collector -f
  ```
