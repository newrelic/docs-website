Obtenez des informations détaillées et complètes sur les performances de votre Oracle Database avec le monitoring de base de données, l’analyse des requêtes, et les métriques de santé du système à l’aide du New Relic Distribution of OpenTelemetry (NRDOT) Collector, s’exécutant en tant que conteneur frère d’une instance Oracle Database qui s’exécute déjà dans Docker.

<Callout variant="tip" title="Installation guidée">
  Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>. Cette page couvre uniquement le chemin d’installation Docker.
</Callout>

<Callout variant="tip">
  Vous cherchez plutôt à automatiser cela à grande échelle ? Consultez [l&apos;installation d&apos;Ansible](/docs/opentelemetry/db360/oracle/ansible), [l&apos;installation de Chef](/docs/opentelemetry/db360/oracle/chef), ou [l&apos;installation du chart Helm](/docs/opentelemetry/db360/oracle/helm) pour Kubernetes.
</Callout>

## Prérequis [#prerequisites]

Avant de commencer, assurez-vous d’avoir les éléments suivants :

* Docker installé sur l’hôte.
* Un conteneur de base de données Oracle déjà en cours d’exécution (base de données Oracle `19c` ou version ultérieure), avec `sqlplus` disponible à l’intérieur.
* Le mot de passe `sys` pour ce conteneur.
* Une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic valide.
* Connectivité réseau depuis le conteneur du collecteur vers [le point de terminaison OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp).

<Steps>
  <Step>
    ## Configurer l’utilisateur de la base de données et accorder des privilèges [#database-user]

    Créez un utilisateur de monitoring, et accordez-lui les vues nécessaires pour la collecte de métriques, de requêtes, et d&apos;événements en exécutant du SQL sur votre conteneur Oracle avec `docker exec`. Choisissez l&apos;onglet qui correspond à votre déploiement, soit une base de données conteneur (CDB) multilocataire, soit une base de données enfichable (PDB) unique :

    <CollapserGroup>
      <Collapser id="docker-cdb" title="Base de données conteneur (CDB)">
        Cela crée un utilisateur commun (requis pour utiliser le préfixe `C##`) et lui accorde une visibilité sur chaque PDB sous la CDB. Remplacez `<YOUR_ORACLE_CONTAINER_NAME>`, `<YOUR_SYS_PASSWORD>`, `<YOUR_DB_USERNAME>` et `<YOUR_DB_PASSWORD>` par vos propres valeurs :

        ```bash
        docker exec -i <YOUR_ORACLE_CONTAINER_NAME> sqlplus sys/'<YOUR_SYS_PASSWORD>' as sysdba << 'EOF'
        ALTER SESSION SET CONTAINER = CDB$ROOT;

        -- Create the common user and set container-data visibility
        CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>" CONTAINER=ALL;
        GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;

        -- Grant system and dynamic performance views
        GRANT SELECT ON V_$INSTANCE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$DATABASE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CONTAINERS                 TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$DATAFILE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SYSSTAT                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CON_SYSSTAT                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SYSMETRIC                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CON_SYSMETRIC              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SESSION                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$RESOURCE_LIMIT             TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$OSSTAT                     TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SGAINFO                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ROWCACHE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$PARAMETER                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_TABLESPACES               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_FREE_SPACE                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_RECYCLEBIN                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SQL                        TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$LOCK                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SESSION_EVENT              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$PDBS                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_SERVICES                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ASM_DISKGROUP_STAT          TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ASM_DISK_STAT               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

        EXIT;
        EOF
        ```

        <Callout variant="tip">
          Le préfixe `C##` est requis par Oracle pour les utilisateurs communs. Les deux derniers privilèges (`V_$ASM_DISKGROUP_STAT` et `V_$ASM_DISK_STAT`) sont uniquement requis si vous souhaitez collecter les [métriques de disque et de groupe de disques ASM](/docs/opentelemetry/db360/oracle/metrics-reference/#asm). Ignorez-les si vous n’utilisez pas ASM.
        </Callout>
      </Collapser>

        ```bash
        -- Create the local user in the PDB
        CREATE USER <YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>";
        GRANT CREATE SESSION TO <YOUR_DB_USERNAME>;

        -- Grant system and dynamic performance views
        GRANT SELECT ON V_$INSTANCE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$DATABASE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$CONTAINERS                 TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$DATAFILE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SYSSTAT                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SYSMETRIC                  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SESSION                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$RESOURCE_LIMIT             TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$OSSTAT                     TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SGAINFO                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$ROWCACHE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$PARAMETER                  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_TABLESPACE_USAGE_METRICS  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_TABLESPACES               TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_DATA_FILES                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_FREE_SPACE                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_RECYCLEBIN                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SQL                        TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$LOCK                       TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SESSION_EVENT              TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_PROCEDURES                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_OBJECTS                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$PDBS                       TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$PROCESS                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$TRANSACTION                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$CON_SYSSTAT                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$CON_SYSMETRIC               TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$ASM_DISKGROUP_STAT          TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$ASM_DISK_STAT               TO <YOUR_DB_USERNAME>;

        EXIT;
        EOF
        ```

        <Callout variant="tip">
          Les droits `V_$ASM_DISKGROUP_STAT` et `V_$ASM_DISK_STAT` ne sont requis que si vous souhaitez collecter les [métriques de disque et de groupe de disques ASM](/docs/opentelemetry/db360/oracle/metrics-reference/#asm).
        </Callout>

        <Callout variant="tip">
          Si vous devez monitorer toute la base de données conteneur plutôt qu&apos;une base de données enfichable individuelle, utilisez plutôt l&apos;onglet CDB.
        </Callout>

  <Step>
    ## S’assurer de la connectivité réseau de Docker [#network]

    Créez un réseau partagé défini par l’utilisateur (si vous n’en avez pas déjà un) et connectez-y votre conteneur Oracle, afin que le conteneur du collecteur puisse le résoudre par son nom :

    ```bash
    docker network create <YOUR_DOCKER_NETWORK> 2>/dev/null || true
    docker network connect <YOUR_DOCKER_NETWORK> <YOUR_ORACLE_CONTAINER_NAME> 2>/dev/null || true
    ```

    <Callout variant="tip">
      Les deux commandes peuvent être réexécutées en toute sécurité : `|| true` ignore les erreurs « already exists » ou « already connected » d’une exécution précédente.
    </Callout>
  </Step>

    ### Paramètres de configuration [#configuration-parameters]

    | paramètres                                            | Description                                                                                                                                                                                          |
    | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_ORACLE_CONTAINER_NAME>`                        | Le nom (ou le nom d’hôte résolvable par le DNS Docker) de votre conteneur de base de données Oracle en cours d’exécution.                                                                            |
    | `<YOUR_DB_USERNAME>`                                  | L’utilisateur de monitoring que vous avez créé dans [Configurer l’utilisateur de base de données et accorder des privilèges](#database-user) (le préfixe `C##` est ajouté automatiquement pour CDB). |
    | `<YOUR_DB_PASSWORD>`                                  | Le mot de passe de l’utilisateur de monitoring que vous avez créé dans [Configurer l’utilisateur de la base de données et accorder des privilèges](#database-user).                                  |
    | `<YOUR_CDB_SERVICE_NAME>` / `<YOUR_PDB_SERVICE_NAME>` | Le nom du service Oracle pour votre CDB ou PDB.                                                                                                                                                      |
    | `<YOUR_NEWRELIC_OTLP_ENDPOINT>`                       | Votre point de terminaison OTLP New Relic. Pour plus d’informations, consultez les [points de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/).                   |
    | `<YOUR_NEWRELIC_LICENSE_KEY>`                         | Votre [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic.                                                                                                      |
  </Step>

  <Step>
    ## Démarrer le conteneur NRDOT Collector [#start]

    Exécutez le collecteur sur le même réseau Docker que votre conteneur Oracle :

    ```bash
    docker run -d \
      --name nrdot-collector \
      --network <YOUR_DOCKER_NETWORK> \
      --platform linux/amd64 \
      -v "$PWD/oracle-config.yaml:/etc/nrdot-collector/oracle-config.yaml" \
      newrelic/nrdot-collector:latest \
      --config /etc/nrdot-collector/oracle-config.yaml
    ```

    <Callout variant="tip">
      `--platform linux/amd64` évite les incompatibilités d’architecture sur Apple Silicon et d’autres hôtes ARM64 où l’image Oracle elle-même n’est généralement fournie que pour AMD64. Supprimez-le si votre hôte et vos images sont déjà natifs AMD64.
    </Callout>

    Confirmez que le conteneur du collecteur est en cours d&apos;exécution :

    ```bash
    docker ps --filter name=nrdot-collector
    ```

    S’il n’est pas en cours d’exécution, vérifiez ses logs pour y trouver des erreurs. Les causes les plus courantes sont des problèmes d’indentation YAML dans `oracle-config.yaml` ou un conteneur Oracle inaccessible :

    ```bash
    docker logs nrdot-collector
    ```

    <Callout variant="tip">
      Après avoir modifié `oracle-config.yaml`, redémarrez le conteneur pour appliquer vos modifications :

      ```bash
      docker restart nrdot-collector
      ```
    </Callout>
  </Step>

  <Step>
    ## Trouvez et utilisez vos données [#find-use-data]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données Oracle via l&apos;UI de New Relic.

    Pour trouver votre entité de base de données Oracle dans New Relic :

    1. Allez à <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.
    2. Définissez les critères de recherche comme <DNT>`instrumentation.provider = opentelemetry`</DNT>.
    3. Sélectionnez votre base de données Oracle dans la liste des entités.
  </Step>
</Steps>
