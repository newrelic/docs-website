Vous pouvez installer et configurer le Collector NRDOT pour le monitoring de la base de données Oracle en utilisant le rôle Ansible `newrelic.newrelic_install`. Le rôle installe le collecteur, crée l&apos;utilisateur de base de données de monitoring, et configure le collecteur en une seule exécution.

<Callout variant="tip" title="Installation guidée">
Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>. Cette page traite uniquement de l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.
* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.
* Oracle Database 19c ou version ultérieure.
* Ansible Core 2.13 ou 2.14, Python 3.10, et les collections `ansible.windows` et `ansible.utils`.
* Pour Oracle auto-hébergé : Oracle Linux 7, 8, ou 9, avec un accès SSH (avec transfert d’agent) à l’hôte Oracle Database où l’utilisateur SSH peut exécuter `sudo su - oracle` sans prompt de mot de passe.
* Pour Oracle sur AWS RDS : un hôte collecteur exécutant Debian/Ubuntu ou CentOS/RHEL/OEL.
* Pour Oracle Autonomous Database (ADB) : un hôte collecteur exécutant Debian/Ubuntu ou CentOS/RHEL/OEL, avec Oracle Instant Client (`sqlplus`) installé et sur `PATH`; l’adresse IP de sortie de chaque instance autorisée dans sa liste de contrôle d’accès ADB ; et l’Oracle Wallet de chaque instance téléchargé et décompressé dans son propre répertoire sur l’hôte cible.
</Step>

<Step>
## Installez le rôle [#install-role]

```bash
ansible-galaxy install newrelic.newrelic_install
```
</Step>

<Step>
## Configurez le playbook [#configure]

<CollapserGroup>
<Collapser id="ansible-host" title="Base de données Oracle auto-hébergée">
Ce rôle monitore une ou plusieurs instances Oracle Database (chacune accessible via SSH) à partir d’un seul collecteur. Au lieu d’un seul ensemble hôte/conteneur/identifiant, il lit un fichier d’instances (YAML) qui doit déjà exister sur l’hôte cible, répertoriant chaque instance à monitorer, et facultativement un fichier de secrets pour épingler les mots de passe de l’utilisateur de monitoring au lieu de les générer automatiquement. Consultez l’ [installation de la CLI](/docs/opentelemetry/db360/oracle/cli/#install) pour les formats de fichiers exacts.

Créez un fichier nommé `playbook.yml` et copiez-y le contenu suivant. Définissez `targets` sur `oracle-otel` et remplacez les valeurs des espaces réservés par les vôtres :

```yaml
- name: Install New Relic NRDOT for Oracle Database
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - oracle-otel
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
    NR_CLI_ORACLE_SECRETS_FILE: <optional path to a secrets file pinning monitoring passwords, on the target host>
    NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
```

<Callout variant="tip">
Pour activer le logging de débogage, ajoutez `verbosity: "debug"` sous `vars` dans le playbook.
</Callout>

<Collapser id="ansible-rds" title="Oracle Database sur AWS RDS">
Ce rôle monitore un ou plusieurs points de terminaison RDS Oracle depuis un seul collecteur, en utilisant le même modèle de fichier d’instances / fichier de secrets qu’en auto-hébergé (les deux fichiers doivent déjà exister sur l’hôte cible). Créez un fichier nommé `playbook.yml` et copiez-y le contenu suivant. Définissez `targets` sur `oracle-otel-rds` et remplacez les valeurs d’espace réservé par les vôtres :

```yaml
- name: Install New Relic NRDOT for Oracle Database on RDS
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - oracle-otel-rds
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
    NR_CLI_ORACLE_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
    NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
```

<Callout variant="tip">
Pour activer le logging de débogage, ajoutez `verbosity: "debug"` sous `vars` dans le playbook.
</Callout>

<Collapser id="ansible-adb" title="Oracle Autonomous Database (ADB)">
Ce rôle monitore une ou plusieurs instances Oracle Autonomous Database (ADB) à partir d’un seul collecteur, en utilisant le même modèle de fichier d’instances / fichier de secrets que RDS (les deux fichiers doivent déjà exister sur l’hôte cible, et chaque instance a également besoin de son propre Oracle Wallet téléchargé et décompressé sur cet hôte). Consultez l&apos;[installation de la CLI](/docs/opentelemetry/db360/oracle/cli/#install) pour les formats de fichiers exacts. Créez un fichier nommé `playbook.yml` et copiez-y le contenu suivant. Définissez `targets` sur `oracle-otel-adb` et remplacez les valeurs des espaces réservés par les vôtres :

```yaml
- name: Install New Relic NRDOT for Oracle Autonomous Database
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - oracle-otel-adb
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
    NR_CLI_ORACLE_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

<Callout variant="tip">
Pour activer le logging de débogage, ajoutez `verbosity: "debug"` sous `vars` dans le playbook.
</Callout>
