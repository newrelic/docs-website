Configurez le monitoring de Microsoft SQL Server à l’aide du NRDOT Collector sur des environnements Windows pour monitorer les instances AWS RDS for SQL Server, en utilisant l’authentification de domaine Windows. Pour monitorer dans un environnement auto-hébergé, reportez-vous à l’ [instrumentation auto-hébergée Windows](/docs/opentelemetry/db360/mssql/windows-hosted-domain).

<Callout variant="tip" title="Installation guidée">
  Pour installer ceci via l’UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Suivez les instructions à l’écran pour configurer l’intégration. Cette page couvre uniquement l’installation manuelle.
</Callout>

Cette page traite de l’authentification de domaine Windows. Si votre environnement utilise une méthode d’authentification différente, consultez [Authentification SQL Server](/docs/opentelemetry/db360/mssql/windows-rds-sql) ou [gMSA](/docs/opentelemetry/db360/mssql/windows-rds-gmsa).

<Steps>
  <Step>
    ## Prérequis [#prerequisites-domain]

    Avant de monitorer votre Microsoft SQL Server avec NRDOT à l’aide de l’authentification de domaine Windows, assurez-vous que votre environnement répond à ces exigences :

    * Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) valide.

    * Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

    * Prérequis SQL Server :

      * SQL Server 2017 ou version ultérieure sur Amazon RDS.
      * Identifiants de l&apos;utilisateur principal RDS ou identifiants pour une connexion SQL Server avec le rôle `rds_superuser`.
      * Groupe de sécurité RDS configuré pour autoriser les connexions sur le port `1433` ou un port personnalisé.
      * SQL Server Management Studio (SSMS) ou l&apos;utilitaire `sqlcmd`.
      * Instance RDS associée au service AWS Active Directory.

    * Exigences d&apos;authentification de domaine Windows :

      * Un environnement de domaine Windows avec Active Directory.
      * Une instance EC2 Windows jointe à un domaine.
      * RDS SQL Server configuré pour accepter l&apos;authentification Windows.
      * Un compte utilisateur de domaine à utiliser par le Collector NRDOT.

    * L&apos;URL de votre point de terminaison RDS SQL Server, qui se trouve dans votre console AWS RDS sous Connectivité &amp; sécurité. Pour plus d&apos;informations, consultez la [documentation AWS RDS](https://docs.aws.amazon.com/AmazonRDS/latest/gettingstartedguide/connecting-console.html).
  </Step>

  <Step>
    ## Installer le collecteur NRDOT [#setup-domain]

    Installez le Collector NRDOT sur une instance EC2 Windows jointe au domaine ou une machine Windows locale qui fait partie du même domaine et peut se connecter à votre instance RDS SQL Server.

    <Callout variant="important">
      Pour le monitoring RDS, installez le Collector NRDOT sur une instance EC2 dans le même VPC que votre instance RDS pour une connectivité réseau optimale et une latence plus faible.
    </Callout>

    1. Téléchargez et installez le NRDOT Collector à l&apos;aide de PowerShell :

    ```powershell
    [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
    $NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
    $WebClient = New-Object System.Net.WebClient
    $WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
    $WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
    Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
    Get-Service nrdot-collector -ErrorAction SilentlyContinue
    ```
  </Step>

  <Step>
    ## Créer une connexion de domaine Windows [#create-domain]

    Connectez-vous à votre instance RDS SQL Server à l&apos;aide de SQL Server Management Studio (SSMS) ou de `sqlcmd` avec des privilèges administratifs.

    Dans votre SQL Server Management Studio (SSMS), exécutez le script suivant pour créer une connexion pour votre compte gMSA et accorder les autorisations nécessaires. Remplacez toutes les occurrences de `<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>` par votre véritable nom de domaine et de compte.

    ```sql
    USE [master];
    GO

    CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FROM WINDOWS;
    GO

    GRANT VIEW ANY DATABASE   TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
    GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
    GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
    GO

    -- Grant access to all databases (required for query monitoring and tempdb metrics)
    DECLARE @name SYSNAME;
    DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
      SELECT [name] FROM [master].[sys].[databases]
      WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
        AND [state] = 0;
    OPEN db_cursor;
    FETCH NEXT FROM db_cursor INTO @name;
    WHILE @@FETCH_STATUS = 0
    BEGIN
      BEGIN TRY
        EXEC('USE [' + @name + '];
        IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>'')
        BEGIN
          CREATE USER [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        END;
        GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];');
      END TRY
      BEGIN CATCH
        PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
      END CATCH
      FETCH NEXT FROM db_cursor INTO @name;
    END
    CLOSE db_cursor;
    DEALLOCATE db_cursor;
    GO
    ```

    <Callout variant="tip">
      Pour gérer en toute sécurité les informations sensibles, telles que les identifiants de base de données, stockez-les dans des outils de [gestion des secrets](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
    </Callout>
  </Step>

  <Step>
    ## Exécuter en tant qu&apos;utilisateur de domaine [#run-domain]

    1. Configurez le service NRDOT Collector pour qu’il s’exécute en tant qu’utilisateur de votre domaine à l’aide de PowerShell. Remplacez `YOUR_DOMAIN\YOUR_USER_ACCOUNT` par votre domaine et votre nom de compte :

       ```powershell
       # Configure service to use domain account
       # The space after obj= and password= is required syntax for sc.exe
       sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

       # Restart the service
       Restart-Service nrdot-collector
       ```

    2. Validez l’identité du service :

       ```powershell
       Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
       # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
       ```
  </Step>

  <Step>
    ## Configurer le collecteur NRDOT [#configure-domain]

    1. Créez un fichier de configuration nommé `mssql-config.yaml` dans PowerShell en tant qu&apos;administrateur :

       ```powershell
       New-Item -Path "C:\Program Files\nrdot-collector\mssql-config.yaml" -ItemType File
       ```

    2. Ajoutez la configuration suivante au fichier `mssql-config.yaml` créé à l’étape précédente :

    <Callout variant="important">
      L’authentification de domaine Windows utilise la sécurité intégrée, qui utilise la même approche de configuration que l’authentification gMSA. Mettez à jour la valeur du serveur `datasource` avec votre point de terminaison RDS. Le service NRDOT s’authentifiera en utilisant le compte de domaine que vous avez configuré dans [Créer une connexion de domaine Windows](#create-domain).
    </Callout>

    <Callout variant="tip">
      Le pipeline `logs` ne transporte ni les logs de débogage du collecteur, ni les logs internes de l’agent. Il transmet la télémétrie des requêtes SQL Server, y compris le texte des requêtes, les plans d’exécution, et les données d’exemple. Le Récepteur `nrsqlserver` capture cette télémétrie via les événements `db.server.query_sample`, `db.server.top_query`, `db.server.query_plan`, et `db.server.top_procedure` émis sous forme d’enregistrements de log OpenTelemetry.

      L’événement `db.server.top_procedure` nécessite SQL Server 2017 CU3 ou une version ultérieure, qui a introduit la prise en charge de `sys.dm_exec_procedure_stats.total_spills`. Sur les versions antérieures, cet événement n’émet pas de données et log une erreur. Les autres événements ne sont pas affectés. L’accès à `sys.dm_exec_procedure_stats` nécessite `VIEW SERVER STATE` (ou `VIEW SERVER PERFORMANCE STATE`, selon la version de SQL Server). De plus, `VIEW ANY DEFINITION` est requis pour que `OBJECT_NAME` et `OBJECT_SCHEMA_NAME` se résolvent correctement sur toutes les bases de données utilisateur, et `CONNECT SQL` est nécessaire pour configurer les sessions initiales. Le compte que vous avez configuré dans [Créer une connexion de domaine Windows](#create-domain) possède déjà les 3 permissions.

  <Step>
    ## Mettre à jour le registre des services Windows [#update-registry-domain]

    1. Mettez à jour le registre des services Windows pour utiliser le nouveau fichier `mssql-config.yaml` à l&apos;aide de l&apos;une des méthodes suivantes :

       * **Pour PowerShell :** Exécutez la commande suivante en tant qu&apos;administrateur :

         ```powershell
         Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
         ```

       * **Pour l’invite de commande :** si PowerShell n’est pas disponible, utilisez plutôt l’invite de commande et exécutez la commande suivante en tant qu’administrateur :

       ```bash
       sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
       ```

    2. Validez la configuration du Collector NRDOT pour vous assurer qu&apos;elle est correctement formatée et qu&apos;elle fonctionnera correctement :

       ```bash
       & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
       ```

    <Callout variant="tip">
      Pour corréler les performances de votre application avec les opérations de base de données, vous pouvez configurer l’identification du service de bases de données. Pour plus d’informations, reportez-vous au [guide de configuration de l’identification du service de bases de données](/docs/opentelemetry/db360/capabilities/db-apm).
    </Callout>
  </Step>

  <Step>
    ## Redémarrer NRDOT Collector [#restart-domain]

    Après avoir mis à jour votre configuration, redémarrez le service NRDOT Collector :

    ```bash
    net stop nrdot-collector
    net start nrdot-collector
    ```

    Vérifiez que le service s’exécute sous le compte de domaine en consultant les services Windows (`services.msc`). La colonne `Log On As` doit afficher votre compte de domaine. Par exemple, `CORP\SQLMonitor`.
  </Step>

  <Step>
    ## Trouvez et utilisez vos données [#find-domain]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données SQL Server via l&apos;UI de New Relic.

    Pour trouver votre entité de base de données SQL Server dans New Relic :

    1. Allez à <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.

    2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.

    3. Sélectionnez votre base de données SQL Server dans la liste des entités.

       Après avoir configuré le monitoring SQL Server avec NRDOT, vous pouvez :

       * [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser les métriques de votre base de données
       * [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de performances des bases de données
       * [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
  </Step>
</Steps>
