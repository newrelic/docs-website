Configurez le monitoring de Microsoft SQL Server à l’aide du NRDOT Collector sur les environnements auto-hébergés Windows, y compris les serveurs physiques, les machines virtuelles, et les installations Windows autonomes, en utilisant l’authentification de domaine Windows. Pour monitorer dans un environnement Windows RDS, reportez-vous à l’ [instrumentation Windows RDS](/docs/opentelemetry/db360/mssql/windows-rds-domain).

<Callout variant="tip" title="Installation guidée">
  Pour installer ceci via l’UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Suivez les instructions à l’écran pour configurer l’intégration. Cette page couvre uniquement l’installation manuelle.
</Callout>

Cette page traite de l’authentification de domaine Windows. Si votre environnement utilise une méthode d’authentification différente, consultez [Authentification SQL Server](/docs/opentelemetry/db360/mssql/windows-hosted-sql) ou [gMSA](/docs/opentelemetry/db360/mssql/windows-hosted-gmsa).

<Steps>
  <Step>
    ## Prérequis [#prerequisites-domain]

    Avant de monitorer votre Microsoft SQL Server avec NRDOT à l’aide de l’authentification Windows, assurez-vous que votre environnement répond à ces exigences :

    * Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) valide.

    * Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

    * Prérequis SQL Server :

      * SQL Server 2017 ou version ultérieure.
      * Accès administrateur à SQL Server (rôle `sysadmin` ou équivalent).
      * Connectivité réseau entre le collecteur et SQL Server sur le port `1433` ou un port personnalisé.
      * SQL Server Management Studio (SSMS) ou l&apos;utilitaire `sqlcmd`.

    * Un environnement de domaine Windows avec Active Directory.

    * SQL Server configuré pour accepter l’authentification Windows.

    * Un compte d&apos;utilisateur de domaine avec les permissions SQL Server appropriées.
  </Step>

  <Step>
    ## Installer le collecteur NRDOT [#setup-domain]

    Téléchargez et installez le NRDOT Collector à l&apos;aide de PowerShell :

```powershell
    [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
    $NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
    $WebClient = New-Object System.Net.WebClient
    $WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
    $WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
    Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
    Get-Service nrdot-collector -ErrorAction SilentlyContinue
```
  </Step>

  <Step>
    ## Créer un utilisateur de monitoring [#user-domain]

    Assurez-vous que votre SQL Server est configuré pour l&apos;authentification Windows et vérifiez la connectivité.

    <CollapserGroup>
      <Collapser id="same-host" title="Collector sur le même hôte Windows">
        1. Récupérez votre nom d’utilisateur Windows :

```sql
           SELECT SYSTEM_USER;
```

        2. Exécutez la commande suivante pour vérifier que les autorisations nécessaires sont accordées à votre utilisateur Windows. Remplacez toutes les occurrences de `<ACCOUNT_USERNAME>` par le nom d’utilisateur récupéré à l’étape 1 :

```sql
           DECLARE @TargetUser SYSNAME = '<ACCOUNT_USERNAME>'; -- <-- Set your Windows user here

           -- 1. Create the checklist of required permissions from your script
           DECLARE @Checklist TABLE (Scope NVARCHAR(50), [Database] SYSNAME, [Permission] NVARCHAR(128));

           INSERT INTO @Checklist VALUES
           ('Server', 'ALL', 'VIEW SERVER STATE'),
           ('Server', 'ALL', 'VIEW ANY DEFINITION'),
           ('Server', 'ALL', 'VIEW ANY DATABASE');

           INSERT INTO @Checklist
           SELECT 'Database Role', [name], 'db_datareader' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0
           UNION ALL
           SELECT 'Database Explicit', [name], 'VIEW DATABASE STATE' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0
           UNION ALL
           SELECT 'Database Explicit', [name], 'VIEW DEFINITION' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0;

           -- 2. Gather existing explicit permissions
           WITH ExplicitPerms AS (
               SELECT 'Server' AS Scope, CAST('ALL' AS NVARCHAR(128)) COLLATE DATABASE_DEFAULT AS [Database], p.permission_name COLLATE DATABASE_DEFAULT AS [Permission]
               FROM sys.server_permissions p JOIN sys.server_principals l ON p.grantee_principal_id = l.principal_id WHERE l.name = @TargetUser
               UNION ALL
               SELECT 'Database Role', d.name COLLATE DATABASE_DEFAULT, r.name COLLATE DATABASE_DEFAULT
               FROM sys.databases d CROSS APPLY (SELECT dp_role.name FROM sys.database_role_members drm JOIN sys.database_principals dp_role ON drm.role_principal_id = dp_role.principal_id JOIN sys.database_principals dp_user ON drm.member_principal_id = dp_user.principal_id JOIN sys.server_principals sp ON dp_user.sid = sp.sid WHERE sp.name = @TargetUser) r WHERE d.state = 0
               UNION ALL
               SELECT 'Database Explicit', d.name COLLATE DATABASE_DEFAULT, p.permission_name COLLATE DATABASE_DEFAULT
               FROM sys.databases d CROSS APPLY (SELECT db_p.permission_name FROM sys.database_permissions db_p JOIN sys.database_principals dp_user ON db_p.grantee_principal_id = dp_user.principal_id JOIN sys.server_principals sp ON dp_user.sid = sp.sid WHERE sp.name = @TargetUser) p WHERE d.state = 0
           )
           -- 3. Output the exact verification matrix
           SELECT
               chk.Scope,
               chk.[Database],
               chk.[Permission] AS [Required Permission],
               CASE
                   WHEN exp.[Permission] IS NOT NULL THEN 'GRANTED'
                   WHEN IS_SRVROLEMEMBER('sysadmin', @TargetUser) = 1 THEN 'PASSED (via SysAdmin Role)'
                   ELSE 'MISSING'
               END AS [Verification Status]
           FROM @Checklist chk
           LEFT JOIN ExplicitPerms exp ON chk.Scope = exp.Scope AND chk.[Database] = exp.[Database] AND chk.[Permission] = exp.[Permission]
           ORDER BY chk.Scope, chk.[Database], chk.[Permission];
```

        3. (Facultatif) Si vous n’avez pas les autorisations nécessaires, depuis votre SSMS ou l’utilitaire `sqlcmd`, exécutez la commande suivante pour accorder les autorisations requises à votre compte Windows. Remplacez toutes les occurrences de `<ACCOUNT_USERNAME>` par votre nom d’utilisateur Windows récupéré à l’étape 1 :

```sql
           USE [master];
           GO

           -- 1. Grant Instance-level permissions to your Windows Account
           GRANT VIEW SERVER STATE TO [<ACCOUNT_USERNAME>];
           GRANT VIEW ANY DEFINITION TO [<ACCOUNT_USERNAME>];
           GRANT VIEW ANY DATABASE TO [<ACCOUNT_USERNAME>];
           GO

           -- 2. Loop through all user databases and grant read/visibility permissions
           DECLARE @name SYSNAME;
           DECLARE @sql NVARCHAR(MAX);

           DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
           SELECT [name]
           FROM [master].[sys].[databases]
           WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
             AND [state] = 0; -- Only online databases

           OPEN db_cursor;
           FETCH NEXT FROM db_cursor INTO @name;

           WHILE @@FETCH_STATUS = 0
           BEGIN
               BEGIN TRY
                   PRINT 'Granting permissions on database: ' + @name;

                   -- Create the database user mapping if it doesn't exist, then grant roles
                   SET @sql = '
                       USE [' + @name + '];
                       IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<ACCOUNT_USERNAME>'')
                       BEGIN
                           CREATE USER [<ACCOUNT_USERNAME>] FOR LOGIN [<ACCOUNT_USERNAME>];
                       END;
                       GRANT VIEW DATABASE STATE TO [<ACCOUNT_USERNAME>];
                       GRANT VIEW DEFINITION TO [<ACCOUNT_USERNAME>];
                       ALTER ROLE db_datareader ADD MEMBER [<ACCOUNT_USERNAME>];';

                   EXEC sp_executesql @sql;
                   PRINT 'Success: ' + @name;
               END TRY
               BEGIN CATCH
                   PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
               END CATCH

               FETCH NEXT FROM db_cursor INTO @name;
           END

           CLOSE db_cursor;
           DEALLOCATE db_cursor;
           GO
```
      </Collapser>

      <Collapser id="different-host" title="Collector sur un hôte Windows différent">
        1. Dans votre SQL Server Management Studio (SSMS), exécutez le script suivant pour créer une connexion pour votre compte gMSA et accorder les autorisations nécessaires. Remplacez toutes les occurrences de `<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>` par votre véritable nom de domaine et de compte.

```sql
        USE [master];
        GO

        CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FROM WINDOWS;
        GO

        GRANT VIEW ANY DATABASE   TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GO

        -- Grant access to all databases
        DECLARE @name SYSNAME;
        DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
          SELECT [name] FROM [master].[sys].[databases]
          WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
            AND [state] = 0;
        OPEN db_cursor;
        FETCH NEXT FROM db_cursor INTO @name;
        WHILE @@FETCH_STATUS = 0
        BEGIN
          BEGIN TRY
            EXEC('USE [' + @name + '];
            IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>'')
            BEGIN
              CREATE USER [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
            END;
            GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];');
          END TRY
          BEGIN CATCH
            PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
          END CATCH
          FETCH NEXT FROM db_cursor INTO @name;
        END
        CLOSE db_cursor;
        DEALLOCATE db_cursor;
        GO
```

        2. Configurez le service NRDOT Collector pour qu’il s’exécute en tant qu’utilisateur de votre domaine à l’aide de PowerShell. Remplacez `YOUR_DOMAIN\YOUR_USER_ACCOUNT` par votre domaine et votre nom de compte :

```powershell
           # Configure service to use domain account
           # The space after obj= and password= is required syntax for sc.exe
           sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

           # Restart the service
           Restart-Service nrdot-collector
```

        3. Validez l’identité du service :

```powershell
           Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
           # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
```
      </Collapser>
    </CollapserGroup>

    <Callout variant="tip">
      Pour gérer en toute sécurité les informations sensibles, telles que les identifiants de base de données, stockez-les dans des outils de [gestion des secrets](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
    </Callout>
  </Step>

    <Callout variant="tip">
      Le pipeline `logs` ne transporte ni les logs de débogage du collecteur, ni les logs internes de l’agent. Il transmet la télémétrie des requêtes SQL Server, y compris le texte des requêtes, les plans d’exécution, et les données d’exemple. Le Récepteur `nrsqlserver` capture cette télémétrie via les événements `db.server.query_sample`, `db.server.top_query`, `db.server.query_plan`, et `db.server.top_procedure` émis sous forme d’enregistrements de log OpenTelemetry.

      L’événement `db.server.top_procedure` nécessite SQL Server 2017 CU3 ou une version ultérieure, qui a introduit la prise en charge de `sys.dm_exec_procedure_stats.total_spills`. Sur les versions antérieures, cet événement n’émet pas de données et log une erreur. Les autres événements ne sont pas affectés. L’accès à `sys.dm_exec_procedure_stats` nécessite `VIEW SERVER STATE` (ou `VIEW SERVER PERFORMANCE STATE`, selon la version de SQL Server). De plus, `VIEW ANY DEFINITION` est requis pour que `OBJECT_NAME` et `OBJECT_SCHEMA_NAME` se résolvent correctement sur toutes les bases de données utilisateur, et `CONNECT SQL` est nécessaire pour configurer les sessions initiales. Le compte que vous avez configuré dans [Créer un utilisateur de monitoring](#user-domain) possède déjà les 3 permissions.
    </Callout>

  <Step>
    ## Mettre à jour le registre des services Windows [#update-registry-domain]

    1. Mettez à jour le registre des services Windows pour utiliser le nouveau fichier `mssql-config.yaml` à l&apos;aide de l&apos;une des méthodes suivantes :

       * **Pour PowerShell :** Exécutez la commande suivante en tant qu&apos;administrateur :

```powershell
         Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
```

       * **Pour l’invite de commande :** si PowerShell n’est pas disponible, utilisez plutôt l’invite de commande et exécutez la commande suivante en tant qu’administrateur :

```bash
       sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
```

    2. Validez la configuration du Collector NRDOT pour vous assurer qu&apos;elle est correctement formatée et qu&apos;elle fonctionnera correctement :

```bash
       & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
```

       <Callout variant="tip">
         Pour corréler les performances de votre application avec les opérations de base de données, vous pouvez configurer l’identification du service de bases de données. Pour plus d’informations, reportez-vous à [configurer l’identification du service de bases de données](/docs/opentelemetry/db360/capabilities/db-apm/).
       </Callout>
  </Step>

  <Step>
    ## Redémarrer NRDOT Collector [#restart-domain]

    Après avoir mis à jour votre configuration, redémarrez le service NRDOT Collector :

```bash
    net stop nrdot-collector
    net start nrdot-collector
```

    <Callout variant="tip">
      Redémarrez toujours le service NRDOT Collector après avoir modifié la configuration pour vous assurer que les nouveaux paramètres soient pris en compte.
    </Callout>
  </Step>

  <Step>
    ## Trouvez et utilisez vos données [#find-domain]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données SQL Server via l’UI de New Relic.

    Pour trouver votre entité de base de données SQL Server dans New Relic :

    1. Allez à <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.

    2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.

    3. Sélectionnez votre base de données SQL Server dans la liste des entités.

       Après avoir configuré le monitoring SQL Server avec NRDOT, vous pouvez :

       * [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser les métriques de votre base de données
       * [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de performances des bases de données
       * [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
  </Step>
</Steps>
