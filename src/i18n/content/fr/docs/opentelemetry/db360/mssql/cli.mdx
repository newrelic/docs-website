Vous pouvez installer et configurer le NRDOT Collector pour le monitoring de SQL Server à l&apos;aide de la CLI New Relic. La CLI installe le collecteur, crée ou autorise l&apos;identité de monitoring, et configure le collecteur en une seule commande.

<Callout variant="tip" title="Installation guidée">
Pour installer ceci via l’UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Suivez les instructions à l’écran pour configurer l’intégration. Cette page couvre uniquement l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.

* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.

* Microsoft SQL Server 2017 ou version ultérieure.

* **SQL Server auto-hébergé :**

  * **Authentification SQL Server :** un hôte collecteur Linux ou Windows, et un identifiant dans le rôle de serveur `sysadmin` (ou équivalent) avec son mot de passe.
  * **Authentification Windows ou gMSA :** un hôte collecteur Windows, une session PowerShell administrateur, et un compte Windows ou gMSA avec les autorisations requises.

* **SQL Server sur AWS RDS :**

  * Un hôte collecteur Linux, ou Windows avec une connectivité réseau au point de terminaison RDS (accès entrant accordé sur le port SQL Server au sein du groupe de sécurité RDS), ainsi que le nom d’utilisateur, et le mot de passe principaux RDS.
  * **Authentification de domaine Windows, ou gMSA :** un hôte de collecteur Windows, et une instance RDS déjà joints à un domaine AWS Managed Microsoft Active Directory.

* **Hôte collecteur Linux :** l’utilitaire `curl`, `systemd`, et l’utilitaire `sqlcmd` installés, et disponibles sur `PATH` (ou situés sous `/opt/mssql-tools18/bin`, ou `/opt/mssql-tools/bin`).

* **Hôte collecteur Windows :** l’utilitaire `sqlcmd.exe` installé et disponible sur `PATH`.

* Connectivité réseau vers le [point de terminaison OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondant à la région cible.
</Step>

<Step>
## Installer et configurer le NRDOT Collector [#cli-install]

<CollapserGroup>
<Collapser id="cli-host-sql" title="Auto-hébergé - Authentification SQL Server">
Cette recette monitore une ou plusieurs instances SQL Server à partir d’un seul collecteur. Au lieu de demander un seul ensemble hôte/port/identifiants, elle lit deux fichiers que vous créez à l’avance : un **fichier d’instances** (YAML) listant chaque instance à monitorer, et un **fichier de secrets** (`KEY=VALUE`) avec un identifiant et un mot de passe administrateur pour chacune, indexés pour correspondre.

1. Créer le fichier d’instance. Ajoutez une entrée par instance SQL Server que vous souhaitez que ce collecteur monitore, ou juste une entrée si vous n’exécutez qu’une seule instance :

   ```bash
   cat > ~/mssql-instances.yml << 'EOF'
   instances:
     - host: localhost
       port: 1433
       login_name: newrelic
   EOF
   ```

2. Créez le fichier de secrets avec un identifiant et un mot de passe d’administrateur pour chaque instance, indexé pour correspondre à l’ordre du fichier d’instance. L’identifiant d’administrateur doit être membre du rôle `sysadmin` (ou équivalent) :

   ```bash
   umask 077
   cat > ~/mssql-secrets.env << 'EOF'
   NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
   NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
   EOF
   chmod 600 ~/mssql-secrets.env
   ```

**Linux:**

```bash
curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-mssql
```

**Windows** (exécutez dans une session PowerShell administrateur) :

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql
```

<Collapser id="cli-host-winauth" title="Auto-hébergé - Authentification Windows ou gMSA">
Cette méthode est uniquement prise en charge sur un hôte collecteur Windows. Elle utilise l’authentification Windows (`integrated security=true`) au lieu des connexions SQL, et monitore une ou plusieurs instances SQL Server à partir d’un seul collecteur. Le collecteur est un service Windows avec un seul compte de connexion, et se connecte à **chaque** instance avec ce compte, de sorte qu’une installation multi-instance utilise toujours un seul mode d’authentification et une seule identité Windows, accordée sur chaque instance que vous listez.

1. Créez le fichier d’instance. Ajoutez une entrée par instance SQL Server que vous souhaitez que ce collecteur monitore, ou juste une entrée si vous n’exécutez qu’une seule instance. Seuls `host` et `port` sont nécessaires (pas de `login_name`, pas de fichier de secrets) :

   ```yaml
   instances:
     - host: sql01.contoso.com
       port: 1433
     - host: sql02.contoso.com
       port: 1433
   ```

   Enregistrez ceci n’importe où sur l’hôte du collecteur, par exemple `C:\mssql-instances.yml`. Pour une instance nommée, utilisez `host` plus son port TCP statique plutôt que `host\INSTANCE`.

Avant d’exécuter cette commande, préparez :

* Le fichier d&apos;instance de l&apos;étape 1
* Que vous utilisiez un compte Windows ou un compte gMSA
* Pour l’authentification Windows : si le collecteur s’exécute sur le même hôte que SQL Server, ou sur un hôte différent
* Le compte Windows (ou compte gMSA) auquel accorder des autorisations (non requis si le collecteur s&apos;exécute sur le même hôte que SQL Server)
* Que vous souhaitiez des métriques Basic ou Advanced

Exécutez ceci dans une session PowerShell administrateur :

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql-winauth
```

<Callout variant="tip">
Pour monitorer plus d’une instance SQL Server à partir de ce collecteur, ajoutez des entrées supplémentaires au fichier d’instances. Un hôte ou un port non valide, un `host:port` en double, ou une instance qui échoue à sa vérification de version ou à la configuration des autorisations est ignorée avec une raison dans le log plutôt que d’annuler toute l’installation. Le flux sur le même hôte (`NR_CLI_MSSQL_WINAUTH_LOCATION` `1`) ne fonctionne que pour les instances sur cette machine. Répertoriez les instances sur d’autres hôtes en utilisant le flux sur un hôte différent, ou gMSA.
</Callout>

<Collapser id="cli-rds-sql" title="AWS RDS - Authentification SQL Server">
Cette recette monitore un ou plusieurs points de terminaison RDS SQL Server à partir d’un seul collecteur, en utilisant le même modèle de fichier d’instances / fichier de secrets que pour l’auto-hébergé.

1. Créez le fichier d’instance, en utilisant le point de terminaison RDS comme `host`, avec une seule entrée, si vous effectuez uniquement le monitoring d’une seule instance RDS :

   ```bash
   cat > ~/mssql-instances.yml << 'EOF'
   instances:
     - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
       port: 1433
       login_name: newrelic
   EOF
   ```

2. Créez le fichier de secrets avec le nom d’utilisateur et le mot de passe maître RDS pour chaque instance, indexé pour correspondre à l’ordre du fichier des instances :

   ```bash
   umask 077
   cat > ~/mssql-secrets.env << 'EOF'
   NR_CLI_MSSQL_ADMIN_USER_1=admin
   NR_CLI_MSSQL_ADMIN_PASSWORD_1=YourMasterPassword1
   EOF
   chmod 600 ~/mssql-secrets.env
   ```


<Collapser id="cli-rds-winauth" title="AWS RDS - Authentification de domaine Windows ou gMSA">
Cette méthode est uniquement prise en charge sur un hôte collecteur Windows, et nécessite que vos instances RDS soient déjà jointes à un domaine AWS Managed Microsoft AD. Elle monitore un ou plusieurs points de terminaison RDS SQL Server à partir d’un seul collecteur. Le collecteur est un service Windows avec un seul compte de connexion, et se connecte à **chaque** point de terminaison avec ce compte, de sorte qu’une installation multi-instance utilise toujours un seul mode d’authentification et une seule identité Windows, accordée sur chaque point de terminaison que vous listez. Contrairement à la méthode auto-hébergée ci-dessus, il n’y a pas d’option &quot;même hôte&quot; ici : un compte de domaine (ou gMSA) est toujours requis.

1. Créez le fichier d’instances, en utilisant chaque point de terminaison RDS comme `host`, avec juste une entrée si vous ne faites le monitoring que d’une seule instance RDS :

   ```yaml
   instances:
     - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
       port: 1433
     - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
       port: 1433
   ```

   Enregistrez ceci n’importe où sur l’hôte du collecteur, par exemple `C:\mssql-instances.yml`.

Avant d’exécuter cette commande, préparez :

* Le fichier d&apos;instance de l&apos;étape 1
* Si vous utilisez un compte de domaine Windows ou un compte gMSA
* Le compte de domaine (ou le compte gMSA) auquel accorder des autorisations
* Que vous souhaitiez des métriques Basic ou Advanced

Exécutez ceci dans une session PowerShell administrateur :

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql-rds-winauth
```

## Trouvez et utilisez vos données [#find]

Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données SQL Server via l&apos;UI de New Relic.

Pour trouver votre entité de base de données SQL Server dans New Relic :

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.

3. Sélectionnez votre base de données SQL Server dans la liste des entités.

   Après avoir configuré le monitoring SQL Server avec NRDOT, vous pouvez :

   * [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser les métriques de votre base de données
   * [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de performances des bases de données
   * [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
</Step>
