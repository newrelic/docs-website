Vous pouvez installer, et configurer le Collector NRDOT pour le monitoring de SQL Server à l&apos;aide du livre de recettes Chef `newrelic-install`. Le livre de recettes installe le collecteur, crée, ou autorise l&apos;identité de monitoring, et configure le collecteur lorsque vous exécutez la recette `newrelic-install::default`.

<Callout variant="tip" title="Installation guidée">
Pour installer ceci via l’UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Suivez les instructions à l’écran pour configurer l’intégration. Cette page couvre uniquement l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.

* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.

* Microsoft SQL Server 2017 ou version ultérieure.

* Chef 15 ou version ultérieure.

* **SQL Server auto-hébergé :**

  * **Authentification SQL Server :** un hôte de collecteur Windows, Ubuntu ou RHEL/CentOS, et un identifiant de connexion dans le rôle de serveur `sysadmin` (ou équivalent) avec son mot de passe.
  * **Authentification Windows ou gMSA :** un hôte collecteur Windows et le compte de domaine Windows (ou gMSA) auquel accorder des autorisations.

* **SQL Server sur AWS RDS :**

  * Un hôte collecteur Windows, Ubuntu, ou RHEL/CentOS avec une connectivité réseau au point de terminaison RDS (accès entrant accordé sur le port SQL Server au sein du groupe de sécurité RDS), ainsi que le nom d’utilisateur et le mot de passe maître RDS.
  * **Authentification de domaine Windows, ou gMSA :** un hôte de collecteur Windows, et une instance RDS déjà joints à un domaine AWS Managed Microsoft Active Directory.

* Connectivité réseau vers le [point de terminaison OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondant à la région cible.
</Step>

<Step>
## Télécharger le cookbook Chef [#chef-download-cookbook]

Téléchargez le `newrelic-install` [livre de recettes Chef](https://supermarket.chef.io/cookbooks/newrelic-install) depuis le Chef Supermarket dans votre répertoire chef-repo :

```bash
knife supermarket install newrelic-install
```
</Step>

<Step>
## Remplacez les attributs par défaut [#chef-configure]

Remplacez les attributs par défaut dans `attributes/default.rb` par les détails de votre compte :

<CollapserGroup>
<Collapser id="chef-host-sql" title="Auto-hébergé - Authentification SQL Server">
Ce cookbook monitore une ou plusieurs instances SQL Server à partir d’un seul collecteur. Au lieu d’un seul ensemble hôte/port/identifiants, il lit deux fichiers qui doivent déjà exister sur le nœud : un **fichier d’instances** (YAML) listant chaque instance à monitorer, et un **fichier de secrets** (`KEY=VALUE`) avec un identifiant de connexion et un mot de passe administrateur pour chacune, indexés pour correspondre.

1. Créez le fichier d’instance sur le nœud. Ajoutez une entrée par instance SQL Server que vous souhaitez que ce collecteur monitore, ou juste une entrée si vous n’exécutez qu’une seule instance :

   ```yaml
   instances:
     - host: localhost
       port: 1433
       login_name: newrelic
   ```

2. Créez le fichier de secrets sur le nœud avec un identifiant, et un mot de passe d&apos;administrateur pour chaque instance, indexé pour correspondre à l&apos;ordre du fichier d&apos;instance. L&apos;identifiant d&apos;administrateur doit être membre du rôle `sysadmin` (, ou équivalent) :

   ```bash
   NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
   NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
   ```

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mssql'
]
default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node>
default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']    = <path to the secrets file (KEY=VALUE per instance) on the node>
# See all available targets at: https://github.com/newrelic/chef-install
```

<Collapser id="chef-host-winauth" title="Auto-hébergé - Authentification Windows ou gMSA">
Cette cible est uniquement prise en charge sur un hôte collecteur Windows. Elle utilise l’authentification Windows (`integrated security=true`) au lieu des identifiants SQL, et monitore une ou plusieurs instances SQL Server à partir d’un seul collecteur à l’aide d’un **fichier d’instances** (YAML, `host`/`port` par instance, aucun fichier de secrets : une identité Windows monitore chaque instance).

Ce fichier doit déjà exister sur le nœud, avec une seule entrée si vous n’exécutez qu’une seule instance. Seuls `host` et `port` sont nécessaires (pas de `login_name`) :

```yaml
instances:
  - host: sql01.contoso.com
    port: 1433
  - host: sql02.contoso.com
    port: 1433
```

Pour une instance nommée, utilisez `host` plus son port TCP statique plutôt que `host\INSTANCE`.

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mssql-winauth'
]
default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']    = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']        = <1 for Windows Domain Auth, 2 for gMSA, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_WINAUTH_LOCATION'] = <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']   = <path to the instances YAML file on the node>
default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']      = <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']     = <password for that account; required only for Windows Domain Auth on a different host>
default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']     = <gMSA account, DOMAIN\gMSAName$; gMSA only>
# See all available targets at: https://github.com/newrelic/chef-install
```

<Collapser id="chef-rds-sql" title="AWS RDS - Authentification SQL Server">
Ce cookbook monitore un ou plusieurs points de terminaison RDS SQL Server à partir d’un seul collecteur, en utilisant le même modèle de fichier d’instance / fichier de secrets que la version auto-hébergée (les deux fichiers doivent déjà exister sur le nœud).

1. Créez le fichier des instances sur le nœud, en utilisant le point de terminaison RDS comme `host`, avec une seule entrée si vous ne monitorez qu’une seule instance RDS :

   ```yaml
   instances:
     - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
       port: 1433
       login_name: newrelic
   ```

2. Créez le fichier de secrets sur le nœud avec le nom d’utilisateur et le mot de passe maître RDS pour chaque instance, indexé pour correspondre à l’ordre du fichier d’instance :

   ```bash
   NR_CLI_MSSQL_ADMIN_USER_1=admin
   NR_CLI_MSSQL_ADMIN_PASSWORD_1=YourMasterPassword1
   ```

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mssql-rds'
]
default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']  = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE'] = <path to the instances YAML file on the node, using RDS endpoints as host>
default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']   = <path to the secrets file (KEY=VALUE per instance) on the node>
# See all available targets at: https://github.com/newrelic/chef-install
```

<Collapser id="chef-rds-winauth" title="AWS RDS - Authentification de domaine Windows ou gMSA">
Cette cible est uniquement prise en charge sur un hôte collecteur Windows, et nécessite que vos instances RDS soient déjà jointes à un domaine AWS Managed Microsoft AD. Elle monitore un ou plusieurs points de terminaison RDS SQL Server à partir d’un seul collecteur à l’aide d’un **fichier d’instance** (YAML, `host`/`port` par instance, en utilisant les points de terminaison RDS comme `host`). Contrairement à la cible auto-hébergée ci-dessus, il n’y a pas d’option &quot;même hôte&quot; ici : un compte de domaine (ou gMSA) est toujours requis.

Ce fichier doit déjà exister sur le nœud, en utilisant chaque point de terminaison RDS comme `host`, avec une seule entrée si vous ne monitorez qu’une seule instance RDS :

```yaml
instances:
  - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
    port: 1433
  - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
    port: 1433
```

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mssql-rds-winauth'

default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node, using RDS endpoints as host>
default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']     = <Windows domain account, DOMAIN\username; Windows Domain Auth only>
default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']    = <password for that account; Windows Domain Auth only>
default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']    = <gMSA account, DOMAIN\gMSAName$; gMSA only>
```

## Trouvez et utilisez vos données [#find]

Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données SQL Server via l&apos;UI de New Relic.

Pour trouver votre entité de base de données SQL Server dans New Relic :

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.

3. Sélectionnez votre base de données SQL Server dans la liste des entités.

   Après avoir configuré le monitoring SQL Server avec NRDOT, vous pouvez :

   * [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser les métriques de votre base de données
   * [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de performances des bases de données
   * [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
</Step>
