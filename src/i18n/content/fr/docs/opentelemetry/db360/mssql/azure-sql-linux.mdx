Monitorez les performances de votre base de données Azure SQL avec les métriques de base de données, l&apos;analyse des requêtes, et les données de santé du système en utilisant le collecteur New Relic Distribution of OpenTelemetry (NRDOT) sur Linux.

<Callout variant="tip">
Pour exécuter le collecteur sur Windows, consultez [Base de données Azure SQL sur Windows](/docs/opentelemetry/db360/mssql/azure-sql-windows).
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) valide.

* Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

* Exigences d&apos;Azure SQL Database :

  * Un serveur logique Azure SQL et une base de données.
  * L&apos;identifiant et le mot de passe de l&apos;administrateur du serveur (ou d&apos;un autre compte pouvant créer des identifiants et gérer les rôles de serveur dans `master`).
  * Accès réseau depuis l&apos;hôte du collecteur vers le serveur sur le port `1433`, à travers une règle de pare-feu du serveur, une règle de réseau virtuel, ou un point de terminaison privé. Si le serveur utilise un point de terminaison privé, le nom du serveur doit se résoudre en l&apos;adresse IP privée depuis l&apos;hôte du collecteur.

* Prérequis de l&apos;hôte du Collector : un hôte (par exemple, une machine virtuelle Azure) avec l&apos;utilitaire `sqlcmd` installé.
</Step>

<Step>
## Installer le collecteur NRDOT [#setup]

Installez le NRDOT Collector sur un hôte pouvant atteindre votre serveur Azure SQL.

Pour Debian/Ubuntu sur AMD64 :

```bash
NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
```

Pour les autres distributions et architectures, consultez l’ [étape d’installation de Linux RDS](/docs/opentelemetry/db360/mssql/linux-rds#setup) et la page [nrdot-collector-releases](https://github.com/newrelic/nrdot-collector-releases/releases).
</Step>

<Step>
## Créer un utilisateur de monitoring et accorder des permissions [#user]

La base de données SQL Azure n’autorise pas `GRANT VIEW SERVER STATE`, et les autorisations similaires au niveau de l’instance. Au lieu de cela, vous ajoutez la connexion aux rôles de serveur intégrés dans `master`, puis vous créez un utilisateur dans chaque base de données que vous souhaitez monitorer.

1. Créez un fichier nommé `nr-grant-permission-master.sql` et remplacez `<YOUR_PASSWORD>` par le mot de passe souhaité :

   ```sql
   CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
   GO
   ALTER SERVER ROLE [##MS_ServerStateReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DefinitionReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DatabaseConnector##] ADD MEMBER [newrelic];
   GO
   ```

2. Exécutez-le sur la base de données `master` en tant qu&apos;administrateur du serveur. Remplacez `<YOUR-SERVER>` par le nom de votre serveur (par exemple, `myserver.database.windows.net`) :

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-master.sql
   ```

3. Créez un fichier nommé `nr-grant-permission-db.sql`:

   ```sql
   CREATE USER [newrelic] FOR LOGIN [newrelic];
   GO
   GRANT VIEW DATABASE STATE TO [newrelic];
   GO
   ```

4. Exécutez-le sur **chaque** base de données que vous souhaitez monitorer. Remplacez `<YOUR_DATABASE>` par le nom de la base de données :

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-db.sql
   ```

   Le tableau suivant montre pourquoi chaque rôle est nécessaire :

   | Rôle ou permission         | Utilisé pour                                                                                                          |
   | -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
   | `##MS_ServerStateReader##` | Vues de gestion dynamique au niveau du serveur, telles que `sys.dm_exec_query_stats` et `sys.dm_exec_procedure_stats` |
   | `##MS_DefinitionReader##`  | Résolution des noms d’objets et de schémas pour les principales procédures et statistiques d’index                    |
   | `##MS_DatabaseConnector##` | Connexion aux bases de données pour collecter les statistiques physiques des index                                    |
   | `VIEW DATABASE STATE`      | Vues de gestion dynamique à l’échelle de la base de données, telles que `sys.dm_db_resource_stats`                    |

5. (Facultatif) Vérifiez les rôles de serveur à partir de la base de données `master` :

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -Q "SELECT r.name AS [Role], l.name AS [Login] FROM sys.server_role_members rm JOIN sys.server_principals r ON rm.role_principal_id = r.principal_id JOIN sys.sql_logins l ON rm.member_principal_id = l.principal_id WHERE l.name = 'newrelic';"
   ```

   La sortie répertorie les trois rôles.

6. (Facultatif) Vérifiez les autorisations de la base de données en vous connectant en tant qu’utilisateur de monitoring :

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U newrelic -P '<YOUR_PASSWORD>' -C -Q "SELECT TOP 1 * FROM sys.dm_db_resource_stats; SELECT TOP 1 * FROM sys.dm_exec_query_stats;"
   ```

   Une erreur d’autorisation signifie qu’une autorisation est manquante.

<Callout variant="tip">
Pour gérer en toute sécurité les informations sensibles, telles que les identifiants de base de données, stockez-les dans des outils de [gestion des secrets](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
</Callout>
</Step>

<Step>
## Configurer le collecteur NRDOT [#configure-collector]

1. Créez le fichier de configuration :

   ```bash
   sudo nano /etc/nrdot-collector/mssql-config.yaml
   ```

2. Ajoutez la configuration suivante. Remplacez `<YOUR_PASSWORD>`, `<YOUR-SERVER>`, `<YOUR_DATABASE>`, `<YOUR_LICENSE_KEY>`, et le point de terminaison OTLP par vos valeurs :

   ```yaml
   receivers:
     nrsqlserver:
       collection_interval: 15s
       # datasource replaces username, password, server, and port.
       datasource: "sqlserver://newrelic:<YOUR_PASSWORD>@<YOUR-SERVER>:1433?database=<YOUR_DATABASE>"

       metrics:
         sqlserver.database.io:
           enabled: true
         sqlserver.database.latency:
           enabled: true
         sqlserver.database.operations:
           enabled: true
         sqlserver.database.tempdb.space:
           enabled: true
         sqlserver.database.tempdb.version_store.size:
           enabled: true
         sqlserver.deadlock.rate:
           enabled: true
         sqlserver.os.wait.duration:
           enabled: true
         sqlserver.processes.blocked:
           enabled: true
         sqlserver.memory.grants.pending.count:
           enabled: true
         sqlserver.database.file.size:
           enabled: true
         sqlserver.memory.area:
           enabled: true

       events:
         db.server.query_sample:
           enabled: true
         db.server.top_query:
           enabled: true
         db.server.query_plan:
           enabled: true
         db.server.top_procedure:
           enabled: true

       top_query_collection:
         lookback_time: 60s
         max_query_sample_count: 1000
         top_query_count: 250
         collection_interval: 60s
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       query_sample_collection:
         max_rows_per_query: 100
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       top_procedure_collection:
         max_procedure_sample_count: 1000
         top_procedure_count: 250
         collection_interval: 60s

       resource_attributes:
         db.system.version:
           enabled: true
         sqlserver.db.edition:
           enabled: true

   processors:
     memory_limiter:
       check_interval: ${env:NR_MEM_LIMITER_CHECK_INTERVAL:-1s}
       limit_mib:       ${env:NR_MEM_LIMITER_LIMIT_MIB:-200}
       spike_limit_mib: ${env:NR_MEM_LIMITER_SPIKE_MIB:-50}

   exporters:
     otlp:
       endpoint: https://otlp.nr-data.net:4318
       headers:
         api-key: <YOUR_LICENSE_KEY>
       tls:
         insecure: false
       compression: gzip
       sending_queue:
         enabled: true
         sizer: bytes
         queue_size: 100_000_000
         num_consumers: 10
         batch:
           sizer: bytes
           max_size: 1_000_000
           min_size: 0
           flush_timeout: 5s

   service:
     telemetry:
       metrics:
         level: none
     pipelines:
       metrics:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
       logs:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
   ```

<Callout variant="tip">
* La valeur `datasource` est une URL de connexion. Si votre mot de passe contient des caractères autres que des lettres, des chiffres, et `- . _ ~ ! $ * + ,`, encodez-les en URL.
* Le collecteur se connecte à la seule base de données nommée dans `database=`. Pour monitorer plusieurs bases de données sur le même serveur, utilisez un Récepteur distinct pour chacune, comme décrit dans la [Configuration multi-Récepteur](/docs/opentelemetry/db360/mssql/multi-receiver#multi).
* Les métriques Always-On, de cluster de basculement, et certaines métriques de verrou, et de tempdb ne sont pas disponibles sur la base de données SQL Azure, et ne renvoient aucune donnée.
* Le pipeline `logs` transporte la télémétrie des requêtes SQL Server (texte de la requête, plans d’exécution, et échantillons), et non les logs de débogage du collecteur.
</Callout>
</Step>

<Step>
## Mettre à jour la configuration du Collector NRDOT [#update]

1. Modifiez le fichier de configuration du service :

   ```bash
   sudo nano /etc/nrdot-collector/nrdot-collector.conf
   ```

2. Pointez le chemin de configuration vers votre nouveau fichier :

   ```bash
   OTELCOL_CONFIG="/etc/nrdot-collector/mssql-config.yaml"
   ```

3. (Facultatif) Validez la configuration :

   ```bash
   sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mssql-config.yaml
   ```
</Step>

<Step>
## Redémarrer NRDOT Collector [#restart]

```bash
sudo systemctl restart nrdot-collector
```

Vérifiez le log du collecteur pour détecter des erreurs de permission ou de connexion :

```bash
sudo journalctl -u nrdot-collector -n 50 --no-pager
```
</Step>

<Step>
## Trouvez et utilisez vos données [#find]

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.
3. Sélectionnez votre base de données Azure SQL dans la liste des entités.
</Step>
