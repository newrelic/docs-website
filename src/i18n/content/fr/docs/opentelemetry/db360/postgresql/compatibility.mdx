Avant de commencer à monitorer votre PostgreSQL avec NRDOT, assurez-vous que votre environnement répond à ces exigences.

## Prérequis [#prereq]

Avant de commencer, assurez-vous d’avoir les éléments suivants :

* PostgreSQL 14 ou version ultérieure
* Une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)New Relic valide
* Connectivité réseau entre le Collector NRDOT et votre base de données
* Les modules supplémentaires fournis par PostgreSQL doivent être installés. Pour la plupart des installations, cela est inclus par défaut, mais les installations moins conventionnelles pourraient nécessiter une installation supplémentaire de votre version du [package postgresql-contrib](https://www.postgresql.org/docs/current/contrib.html)

## Paramètres de serveur recommandés [#params]

Configurez les [paramètres](https://www.postgresql.org/docs/current/config-setting.html) suivants, puis redémarrez le serveur pour que les paramètres prennent effet. Pour plus d&apos;informations sur ces paramètres, consultez la [documentation Postgres](https://www.postgresql.org/docs/current/pgstatstatements.html).

<Callout variant="important">
Sur RDS/Aurora, `track_activity_query_size` et `pg_stat_statements.max` sont des paramètres statiques. Même en les appliquant via un groupe de paramètres lors de la création de l’instance, AWS exige `apply_method: pending-reboot` pour ces derniers (l’application immédiate échoue avec `InvalidParameterCombination`). Un redémarrage est requis pour que ces deux éléments prennent effet dans tous les cas.
</Callout>

<Callout variant="important">
Sur Aurora, le nom de la famille de groupes de paramètres de base de données encode la version majeure (par exemple, `aurora-postgresql14`, `aurora-postgresql16`) et doit correspondre exactement à la version du moteur du cluster ou de l’instance. AWS rejette la création d’instance avec `InvalidParameterCombination` s’ils ne correspondent pas. Il n’existe aucune famille unique qui fonctionne pour toutes les versions.
</Callout>
