Vous pouvez utiliser le OpenTelemetry Collector Contrib pour PostgreSQL pour monitorer votre instance. Le OpenTelemetry Collector Contrib est un projet soutenu par la communauté qui collecte des données télémétriques à partir de PostgreSQL, et les envoie à New Relic.

Par défaut, OpenTelemetry Collector Contrib collecte des métriques limitées à partir de PostgreSQL. Pour envoyer des métriques de performances des requêtes, d&apos;événements d&apos;attente, de session, et de client, vous devrez configurer OpenTelemetry Collector Contrib. Ce guide vous montre comment le configurer pour collecter des métriques avancées à partir de PostgreSQL, et les envoyer à New Relic.

<Callout variant="tip" title="Note">
Cette page couvre le Récepteur `postgresql` communautaire fourni dans le binaire `otelcol-contrib` standard. Si vous utilisez la distribution de New Relic (NRDOT), consultez plutôt [Introduction au monitoring de PostgreSQL](/docs/opentelemetry/db360/postgresql/introduction).
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* OpenTelemetry Collector Contrib (`otelcol-contrib`) installé et configuré sur votre système. Vous pouvez télécharger la dernière sortie depuis la page des [sorties de l’OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).

* `pg_stat_statements` activé via `shared_preload_libraries` sur l&apos;instance PostgreSQL monitorée. Cela est requis pour les données de performances des requêtes, d&apos;événements d&apos;attente, de session, et de client. Voir les [Paramètres de serveur recommandés](/docs/opentelemetry/db360/postgresql/compatibility#params).

* Le collecteur a démarré en mode convention sémantique en utilisant la porte de fonctionnalité `receiver.postgresql.useOTelSemconv`.

  Si vous exécutez `otelcol-contrib` en tant que package RPM/Debian (service systemd), le fichier de service importe les variables d’environnement via `EnvironmentFile=/etc/otelcol-contrib/otelcol-contrib.conf`. Dans ce fichier, ajoutez le flag à `OTELCOL_OPTIONS`:

  ```bash
  OTELCOL_OPTIONS="--config=/etc/otelcol-contrib/config.yaml --feature-gates=receiver.postgresql.useOTelSemconv"
  ```

  Après avoir enregistré le fichier, redémarrez le service pour appliquer la porte :

  ```bash
  sudo systemctl restart otelcol-contrib
  ```
</Step>

<Step>
## Activer les métriques UI [#enable]

Vous pouvez enrichir votre expérience de la plateforme New Relic en ajoutant, et en activant des métriques dans votre fichier de configuration `otelcol-contrib`. En utilisant la configuration fournie dans cette section, vous pouvez alimenter les données pour les pages suivantes dans la plateforme New Relic :

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Activer les métriques de la page Overview">
La page <DNT>Overview</DNT> affiche une vue d’ensemble de votre instance PostgreSQL, y compris des métriques clés telles que les verrous de base de données, les interblocages, les appels de fonction, les conflits de requêtes, les parcours séquentiels, et l’utilisation des fichiers temporaires et des E/S.

Pour renseigner les données de la page <DNT>Overview</DNT> dans la plateforme New Relic, ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib` :

```yaml
receivers:
  postgresql:
    metrics:
      postgresql.database.locks:
        enabled: true
      postgresql.deadlocks:
        enabled: true
      postgresql.function.calls:
        enabled: true
      postgresql.query.conflicts:
        enabled: true
      postgresql.sequential_scans:
        enabled: true
      postgresql.temp.io:
        enabled: true
      postgresql.temp_files:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="Activer les métriques de performance de requête, de session, d'attente et de client">
Pour alimenter en données les pages <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT>, et <DNT>Clients</DNT> :

* Performances des requêtes : affiche des informations détaillées sur les requêtes en cours d&apos;exécution sur votre instance PostgreSQL dans les onglets suivants :

  * Requêtes normalisées : affiche les graphiques d’exécution et de temps CPU moyen.
  * Échantillons de requêtes : affiche les exécutions individuelles de requêtes, y compris l&apos;heure de début, la durée, le type d&apos;attente, le temps d&apos;attente, la base de données, l&apos;utilisateur de base de données, et l&apos;hôte client.

* Événements d&apos;attente : affiche des informations sur les événements d&apos;attente survenant sur votre instance PostgreSQL. La vue des échantillons de requêtes affiche les requêtes actuellement en attente, ainsi que leur type d&apos;attente et leur temps d&apos;attente.

* Sessions : visualise les tendances pour les connexions à la base de données actives par rapport aux inactives, la durée moyenne des sessions, les sessions bloquées, et l’utilisation par application et processus, pour suivre les pics de charge, et les goulots d’étranglement de connexion.

* Clients : affiche des informations sur les clients connectés à votre instance PostgreSQL, y compris les sessions actives, les sessions bloquées, les utilisateurs de base de données connectés, et les détails de l’hôte client.

Ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib` :

```yaml
receivers:
  postgresql:
    events:
      db.server.top_query:
        enabled: true
      db.server.query_sample:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      max_rows_per_query: 1000
      top_n_query: 200
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 1000
```

<Callout variant="important">
`db.server.query_plan` nécessite qu’au moins `db.server.top_query` ou `db.server.query_sample` soit également activé. L’activer seul constitue une erreur de validation de configuration.
</Callout>

<Callout variant="tip" title="Note">
`postgresql.session.duration` n&apos;est pas disponible dans le Récepteur communautaire `postgresql`, donc la table Sessions ne s&apos;affiche pas sur la page Sessions.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

## Redémarrez le Collector OpenTelemetry [#restart]

Redémarrez l&apos;OpenTelemetry Collector pour appliquer les modifications de configuration :

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
