Vous pouvez installer et configurer le NRDOT Collector pour le monitoring de PostgreSQL à l&apos;aide du cookbook Chef `newrelic-install`. Le cookbook installe le collecteur, crée le rôle de monitoring et ses droits, et configure le collecteur lorsque vous exécutez la recette `newrelic-install::default`.

<Callout variant="tip" title="Installation guidée">
  Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>. Cette page traite uniquement de l’installation manuelle.
</Callout>

<Steps>
  <Step>
    ## Prérequis [#prerequisites]

    * Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.
    * Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.
    * PostgreSQL 14 ou version ultérieure.
    * Chef 15 ou version ultérieure.
    * Un hôte collecteur Linux exécutant Debian/Ubuntu ou RHEL/CentOS.
    * `pg_stat_statements` doit être chargé via `shared_preload_libraries`, ce qui nécessite un redémarrage de la base de données. Mettez en place les [prérequis au niveau du serveur](/docs/opentelemetry/db360/postgresql/cli/#server-prereqs) avant d’exécuter la recette.
    * Pour PostgreSQL auto-hébergé : un accès administratif à votre serveur PostgreSQL (le superutilisateur `postgres` ou équivalent), avec un mot de passe défini et `pg_hba.conf` permettant l’authentification de l’hôte par mot de passe.
    * Pour PostgreSQL ou Aurora sur AWS RDS : connectivité réseau depuis l&apos;hôte du collecteur vers le point de terminaison RDS, et le nom d&apos;utilisateur principal et le mot de passe RDS.
    * Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

    Pour connaître les prérequis détaillés, consultez la page [Compatibilité](/docs/opentelemetry/db360/postgresql/compatibility).
  </Step>

  <Step>
    ## Télécharger le cookbook Chef [#chef-download-cookbook]

    Téléchargez le `newrelic-install` [livre de recettes Chef](https://supermarket.chef.io/cookbooks/newrelic-install) depuis le Chef Supermarket dans votre répertoire chef-repo :

    ```bash
    knife supermarket install newrelic-install
    ```
  </Step>

  <Step>
    ## Remplacez les attributs par défaut [#chef-configure]

    Remplacez les attributs par défaut dans `attributes/default.rb` par les détails de votre compte :

    <CollapserGroup>
      <Collapser id="chef-host" title="PostgreSQL auto-hébergé">
        Ce cookbook monitore une ou plusieurs instances PostgreSQL à partir d’un seul collecteur. Au lieu d’un seul ensemble hôte/port/identifiants, il lit deux fichiers qui doivent déjà exister sur le nœud : un fichier d’instances (YAML) listant chaque instance à monitorer et les bases de données à monitorer sur chacune, et un fichier de secrets (`KEY=VALUE`) avec un identifiant et un mot de passe de superutilisateur pour chacune, indexés pour correspondre. Consultez la page [CLI install](/docs/opentelemetry/db360/postgresql/cli/#cli-install) pour connaître les formats de fichiers exacts.

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-postgresql'
        ]
        default['newrelic_install']['env']['NR_CLI_POSTGRES_CONFIG_PRESET']         = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_INSTANCES_FILE']        = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_SECRETS_FILE']          = <path to the secrets file (KEY=VALUE per instance) on the node>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_ENABLE_EXPLAIN_HELPER'] = <y or N, default N; PREVIEW feature, see table below>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

        <Callout variant="important">
          Le cookbook se connecte à PostgreSQL via TCP à l’aide d’un mot de passe, le superutilisateur de chaque instance doit donc avoir un mot de passe défini et `pg_hba.conf` doit autoriser l’authentification de l’hôte par mot de passe (`md5` ou `scram-sha-256`) pour les connexions TCP :

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```
        </Callout>

      <Collapser id="chef-rds" title="PostgreSQL ou Aurora sur AWS RDS">

  <Step>
    ## Téléversez le cookbook Chef [#chef-upload-cookbook]

    Téléversez le cookbook Chef `newrelic-install` sur votre serveur Chef :

    ```bash
    knife cookbook upload newrelic-install
    ```
  </Step>

  <Step>
    ## Mettez à jour la liste d’exécution [#chef-run-list]

    Ajoutez la recette `newrelic-install` à la run list d&apos;un nœud :

    ```json
    "run_list": [
      "recipe[newrelic-install]"
    ]
    ```
  </Step>

  <Step>
    ## Trouvez et utilisez vos données [#find]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données PostgreSQL via l&apos;UI de New Relic.

    Pour trouver votre entité de base de données PostgreSQL dans New Relic :

    1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**PostgreSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.
    3. Sélectionnez votre base de données PostgreSQL dans la liste des entités.
  </Step>
