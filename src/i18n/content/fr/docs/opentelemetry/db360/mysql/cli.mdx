Vous pouvez installer et configurer le NRDOT Collector pour le monitoring MySQL à l&apos;aide de la CLI New Relic. La CLI installe le collecteur, crée l&apos;utilisateur de monitoring, et configure le collecteur en une seule commande.

<Callout variant="tip" title="Installation guidée">
Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>. Cette page traite uniquement de l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.
* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.
* MySQL 5.7 ou version ultérieure.
* Un hôte collecteur Linux exécutant Debian/Ubuntu ou RHEL/CentOS, avec `curl` et `systemd` installés, et le client `mysql` disponible.
* Pour MySQL auto-hébergé : accès administrateur à votre serveur MySQL (le compte `root` ou équivalent).
* Pour AWS RDS/Aurora MySQL : connectivité réseau depuis l’hôte du collecteur vers le point de terminaison RDS (accès entrant sur le port MySQL dans le groupe de sécurité RDS), et le nom d’utilisateur et le mot de passe maître RDS.
* Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

Pour connaître les exigences détaillées, reportez-vous à [Compatibilité et prérequis](/docs/opentelemetry/db360/mysql/compatibility).
</Step>

<Step>
## Installer et configurer le NRDOT Collector [#cli-install]

<CollapserGroup>
<Collapser id="cli-host" title="MySQL auto-hébergé">
Cette recette monitore une ou plusieurs instances MySQL à partir d’un seul collecteur. Au lieu de demander un seul ensemble hôte/port/identifiants, elle lit deux fichiers que vous créez à l’avance : un fichier d’instances (YAML) listant chaque instance à monitorer, et un fichier de secrets (`KEY=VALUE`) avec un identifiant et un mot de passe administrateur pour chacune, indexés pour correspondre.

1. Créez le fichier d’instance. Ajoutez une entrée par instance MySQL que vous souhaitez que ce collecteur monitore ; juste une entrée si vous n’exécutez qu’une seule instance :

   ```bash
   cat > ~/mysql-instances.yml << 'EOF'
   instances:
     - host: localhost
       port: 3306
       login_name: newrelic
   EOF
   ```

2. Créez le fichier de secrets avec un identifiant admin (n&apos;importe quel utilisateur admin complet fonctionne ; il n&apos;est pas nécessaire que ce soit `root`) et un mot de passe pour chaque instance, indexés pour correspondre à l&apos;ordre du fichier d&apos;instance :

   ```bash
   umask 077
   cat > ~/mysql-secrets.env << 'EOF'
   NR_CLI_MYSQL_ADMIN_USER_1=root
   NR_CLI_MYSQL_ADMIN_PASSWORD_1=YourRootPassword1
   EOF
   chmod 600 ~/mysql-secrets.env
   ```

```bash
curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-mysql
```

<Callout variant="important">
Ce programme d’installation se connecte à MySQL via TCP à l’aide d’un mot de passe, donc le compte administrateur dans votre fichier de secrets doit utiliser une authentification par mot de passe. Sur certaines installations Debian/Ubuntu, `root`@`localhost` utilise par défaut le plug-in `auth_socket` (sans mot de passe, socket local uniquement), ce qui ne fonctionnera pas ici. Modifiez-le d’abord en exécutant ceci localement en tant que root :

```bash
mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '<password>';"
```

Si cela échoue avec `Access denied`, le package `mysql-server` crée également un compte `debian-sys-maint` avec des identifiants d’administrateur connus dans `/etc/mysql/debian.cnf`. Utilisez-le plutôt :

```bash
mysql --defaults-file=/etc/mysql/debian.cnf -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '<password>';"
```
</Callout>

<Collapser id="cli-rds" title="AWS RDS/Aurora MySQL">
Cette recette monitore un ou plusieurs points de terminaison RDS MySQL ou Aurora à partir d’un seul collecteur, en utilisant le même modèle de fichier d’instances / fichier de secrets que la version auto-hébergée.

1. Créez le fichier d’instances, en utilisant le point de terminaison RDS comme `host`; juste une entrée si vous effectuez uniquement le monitoring d’une seule instance RDS :

   ```bash
   cat > ~/mysql-instances.yml << 'EOF'
   instances:
     - host: mydb1.abcdefg12345.us-east-1.rds.amazonaws.com
       port: 3306
       login_name: newrelic
   EOF
   ```

2. Créez le fichier de secrets avec le nom d’utilisateur et le mot de passe maître RDS pour chaque instance, indexé pour correspondre à l’ordre du fichier des instances :

   ```bash
   umask 077
   cat > ~/mysql-secrets.env << 'EOF'
   NR_CLI_MYSQL_ADMIN_USER_1=admin
   NR_CLI_MYSQL_ADMIN_PASSWORD_1=YourMasterPassword1
   EOF
   chmod 600 ~/mysql-secrets.env
   ```

```bash
curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-mysql-rds
```

## Trouvez et utilisez vos données [#find]

Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données MySQL via l&apos;UI de New Relic.

Pour trouver votre entité de base de données MySQL dans New Relic :

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MySQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.
3. Sélectionnez votre base de données MySQL dans la liste des entités.

Pour confirmer que les données arrivent, exécutez cette requête dans le [générateur de requêtes](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/):

```sql
SELECT count(*) FROM Metric
WHERE metricName LIKE 'mysql.%'
AND instrumentation.provider = 'opentelemetry'
SINCE 10 minutes ago
```
