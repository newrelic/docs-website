Vous pouvez utiliser l’OpenTelemetry Collector Contrib pour MySQL afin de monitorer votre instance. L’OpenTelemetry Collector Contrib est un projet soutenu par la communauté qui collecte des données télémétriques à partir de MySQL et les envoie à New Relic.

Par défaut, l’OpenTelemetry Collector Contrib collecte des métriques limitées à partir de MySQL. Pour envoyer les métriques de performances des requêtes, d’événements d’attente, de session, et de client, vous devrez configurer l’OpenTelemetry Collector Contrib. Ce guide vous montre comment le configurer pour collecter des métriques avancées à partir de MySQL, et les envoyer à New Relic.

<Callout variant="tip" title="Note">
Cette page couvre le `mysqlreceiver` de la communauté inclus dans le binaire `otelcol-contrib` standard. Si vous utilisez la distribution de New Relic (NRDOT), consultez plutôt [MySQL auto-hébergé](/docs/opentelemetry/db360/mysql/introduction).
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* OpenTelemetry Collector Contrib (`otelcol-contrib`) installé et configuré sur votre système. Vous pouvez télécharger la dernière sortie depuis la page des [sorties de l’OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).
* `performance_schema` activé sur l’instance MySQL/MariaDB monitorée (activé par défaut depuis MySQL 5.6.6).
</Step>

<Step>
## Activer les métriques UI [#enable]

Vous pouvez enrichir votre expérience de la plateforme New Relic en ajoutant, et en activant des métriques dans votre fichier de configuration `otelcol-contrib`. En utilisant la configuration fournie dans cette section, vous pouvez alimenter les données pour les pages suivantes dans la plateforme New Relic :

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Activer les métriques de la page Overview">
La page <DNT>Overview</DNT> affiche une vue d’ensemble de votre instance MySQL, y compris des métriques clés telles que les connexions, l’état du pool tampon, les I/O, les verrouillages, la taille des tables et le taux de requêtes lentes. `mysql.commands` et `mysql.innodb.data_file.io` alimentent en outre la liaison APM-DB, la navigation croisée entre la trace d’un service APM et son activité de requête MySQL.

Pour renseigner les données de la page <DNT>Overview</DNT> dans la plateforme New Relic, ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib` :

```yaml
receivers:
  mysql:
    metrics:
      mysql.query.count:
        enabled: true
      mysql.query.slow.count:
        enabled: true
      mysql.table.size:
        enabled: true
      mysql.commands:
        enabled: true
      mysql.innodb.data_file.io:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="Activer les métriques de performance de requête, de session, d'attente et de client">
Pour alimenter en données les pages <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT>, et <DNT>Clients</DNT> :

* Performances des requêtes : affiche des informations détaillées sur les requêtes en cours d’exécution sur votre instance MySQL dans les onglets suivants :

  * Requêtes normalisées : affiche le nombre d’exécutions et la durée moyenne par requête.
  * Échantillons de requêtes : affiche les exécutions individuelles de requêtes, y compris la durée, le type d&apos;attente, la base de données, l&apos;utilisateur de base de données, et l&apos;hôte client.

* Événements d’attente : affiche le type d’attente, et le temps d’attente pour les instructions qui étaient en attente lors de l’échantillonnage.

* Sessions : affiche des informations sur les sessions connectées à votre instance MySQL, y compris le nombre de sessions, le statut des sessions, et les détails de chaque session.

* Clients : affiche des informations sur les clients connectés à votre instance MySQL, y compris les utilisateurs de base de données connectés et les détails de l’hôte client.

Ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib` :

```yaml
receivers:
  mysql:
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      lookback_time: 60
      max_query_sample_count: 1000
      top_query_count: 250
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 100
```

<Callout variant="important">
`db.server.query_plan` nécessite qu’au moins `db.server.top_query` ou `db.server.query_sample` soit également activé. L’activer seul constitue une erreur de validation de configuration.
</Callout>

<Callout variant="tip" title="Note">
Le Récepteur MySQL de la communauté ne prend pas en charge la collecte de procédures stockées ou la détection de sessions bloquées. Les sessions et les clients se remplissent, mais le bloqueur d’une session bloquée n’est pas affiché.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## Redémarrez le Collector OpenTelemetry [#restart]

Redémarrez le Collector OpenTelemetry pour appliquer les modifications de configuration en exécutant la commande suivante :

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
