Vous pouvez installer et configurer le Collector NRDOT pour le monitoring MySQL en utilisant le rôle Ansible `newrelic.newrelic_install`. Le rôle installe le collecteur, crée l’utilisateur de monitoring, et configure le collecteur en une seule exécution.

<Callout variant="tip" title="Installation guidée">
Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>. Cette page traite uniquement de l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.
* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.
* MySQL 5.7 ou version ultérieure.
* Ansible Core 2.13 ou 2.14, Python 3.10, et les collections `ansible.windows` et `ansible.utils`.
* Un hôte collecteur Linux exécutant Debian/Ubuntu ou RHEL/CentOS.
* Pour MySQL auto-hébergé : accès administratif à votre serveur MySQL (le compte `root` ou équivalent), en utilisant l’authentification par mot de passe.
* Pour MySQL ou Aurora sur AWS RDS : connectivité réseau de l’hôte du collecteur au point de terminaison RDS, et le nom d’utilisateur et le mot de passe maître RDS.
* Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

Pour connaître les exigences détaillées, reportez-vous à [Compatibilité et prérequis](/docs/opentelemetry/db360/mysql/compatibility).
</Step>

<Step>
## Installez le rôle [#ansible-install-role]

```bash
ansible-galaxy install newrelic.newrelic_install
```

Assurez-vous que les collections requises sont également installées :

```bash
ansible-galaxy collection install ansible.windows ansible.utils
```
</Step>

<Step>
## Configurez le playbook [#ansible-configure]

<CollapserGroup>
<Collapser id="ansible-host" title="MySQL auto-hébergé">
Ce rôle monitore une ou plusieurs instances MySQL à partir d&apos;un seul collecteur. Au lieu d&apos;un seul ensemble hôte/port/identifiants, il lit deux fichiers qui doivent déjà exister sur l&apos;hôte cible : un fichier d&apos;instances (YAML) listant chaque instance à monitorer, et un fichier de secrets (`KEY=VALUE`) avec un identifiant et un mot de passe administrateur pour chacune, indexé pour correspondre. Consultez la page [CLI install](/docs/opentelemetry/db360/mysql/cli/#cli-install) pour connaître les formats de fichiers exacts.

Créez un fichier nommé `playbook.yml` et copiez-y le contenu suivant. Définissez `targets` sur `mysql-otel` et remplacez les valeurs des espaces réservés par les vôtres :

```yaml
- name: Install New Relic NRDOT for MySQL
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - mysql-otel
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_MYSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
    NR_CLI_MYSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
    NR_CLI_MYSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

<Callout variant="important">
Le rôle se connecte à MySQL via TCP à l’aide d’un mot de passe, le compte administrateur dans votre fichier de secrets doit donc utiliser une authentification par mot de passe. Sur certaines installations Debian/Ubuntu, `root`@`localhost` utilise par défaut le plug-in `auth_socket` (sans mot de passe, socket local uniquement), ce qui ne fonctionnera pas ici. Changez-le avant d’exécuter le playbook :

```bash
mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '<password>';"
```
</Callout>

<Callout variant="tip">
Pour activer le logging de débogage, ajoutez `verbosity: "debug"` sous `vars` dans le playbook.
</Callout>

<Collapser id="ansible-rds" title="MySQL ou Aurora sur AWS RDS">
Ce rôle monitore un ou plusieurs points de terminaison RDS MySQL ou Aurora à partir d’un seul collecteur, en utilisant le même modèle de fichier d’instances / fichier de secrets que pour l’auto-hébergé (les deux fichiers doivent déjà exister sur l’hôte cible). Créez un fichier nommé `playbook.yml` et copiez-y le contenu suivant. Définissez `targets` sur `mysql-otel-rds` et remplacez les valeurs d’espace réservé par les vôtres :

```yaml
- name: Install New Relic NRDOT for MySQL on RDS
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - mysql-otel-rds
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_MYSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
    NR_CLI_MYSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
    NR_CLI_MYSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
```

<Callout variant="tip">
Pour activer le logging de débogage, ajoutez `verbosity: "debug"` sous `vars` dans le playbook.
</Callout>

ansible-playbook -i <inventory_file> <playbook_file>.yml

<Step>
## Trouvez et utilisez vos données [#find]

Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données MySQL via l&apos;UI de New Relic.

Pour trouver votre entité de base de données MySQL dans New Relic :

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MySQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.
3. Sélectionnez votre base de données MySQL dans la liste des entités.
</Step>
