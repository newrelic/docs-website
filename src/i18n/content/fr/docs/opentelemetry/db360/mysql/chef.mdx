Vous pouvez installer et configurer le Collector NRDOT pour le monitoring MySQL à l’aide du livre de recettes Chef `newrelic-install`. Le livre de recettes installe le collecteur, crée l’utilisateur de monitoring, et configure le collecteur lorsque vous exécutez la recette `newrelic-install::default`.

<Callout variant="tip" title="Installation guidée">
Pour installer plutôt via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>. Cette page traite uniquement de l’installation manuelle.
</Callout>

<Steps>
<Step>
## Prérequis [#prerequisites]

* Un compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) valide.
* Un [ID de compte](/docs/accounts/accounts-billing/account-structure/account-id) New Relic.
* MySQL 5.7 ou version ultérieure.
* Chef 15 ou version ultérieure.
* Un hôte collecteur Linux exécutant Debian/Ubuntu ou RHEL/CentOS.
* Pour MySQL auto-hébergé : accès administratif à votre serveur MySQL (le compte `root` ou équivalent), en utilisant l’authentification par mot de passe.
* Pour MySQL ou Aurora sur AWS RDS : connectivité réseau de l’hôte du collecteur au point de terminaison RDS, et le nom d’utilisateur et le mot de passe maître RDS.
* Connectivité réseau vers le [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) pour votre région.

Pour connaître les exigences détaillées, reportez-vous à [Compatibilité et prérequis](/docs/opentelemetry/db360/mysql/compatibility).
</Step>

<Step>
## Télécharger le cookbook Chef [#chef-download-cookbook]

Téléchargez le `newrelic-install` [livre de recettes Chef](https://supermarket.chef.io/cookbooks/newrelic-install) depuis le Chef Supermarket dans votre répertoire chef-repo :

```bash
knife supermarket install newrelic-install
```
</Step>

<Step>
## Remplacez les attributs par défaut [#chef-configure]

Remplacez les attributs par défaut dans `attributes/default.rb` par les détails de votre compte :

<CollapserGroup>
<Collapser id="chef-host" title="MySQL auto-hébergé">
Ce livre de recettes monitore une ou plusieurs instances MySQL à partir d’un seul collecteur. Au lieu d’un seul ensemble hôte/port/identifiant, il lit deux fichiers qui doivent déjà exister sur le nœud : un fichier d’instances (YAML) listant chaque instance à monitorer, et un fichier de secrets (`KEY=VALUE`) avec un identifiant et un mot de passe administrateur pour chacune, indexés pour correspondre. Consultez la page [CLI install](/docs/opentelemetry/db360/mysql/cli/#cli-install) pour connaître les formats de fichiers exacts.

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mysql'
]
default['newrelic_install']['env']['NR_CLI_MYSQL_CONFIG_PRESET']  = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MYSQL_INSTANCES_FILE'] = <path to the instances YAML file on the node>
default['newrelic_install']['env']['NR_CLI_MYSQL_SECRETS_FILE']   = <path to the secrets file (KEY=VALUE per instance) on the node>
# See all available targets at: https://github.com/newrelic/chef-install
```

<Callout variant="important">
Le livre de recettes se connecte à MySQL via TCP à l’aide d’un mot de passe, le compte administrateur dans votre fichier de secrets doit donc utiliser une authentification par mot de passe. Sur certaines installations Debian/Ubuntu, `root`@`localhost` utilise par défaut le plug-in `auth_socket` (sans mot de passe, socket local uniquement), ce qui ne fonctionnera pas ici. Modifiez-le avant d’exécuter la recette :

```bash
mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '<password>';"
```
</Callout>

<Collapser id="chef-rds" title="MySQL ou Aurora sur AWS RDS">
Ce cookbook monitore un ou plusieurs points de terminaison RDS MySQL ou Aurora à partir d’un seul collecteur, en utilisant le même modèle de fichier d’instances / fichier de secrets que pour l’auto-hébergement (les deux fichiers doivent déjà exister sur le nœud).

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mysql-rds'
]
default['newrelic_install']['env']['NR_CLI_MYSQL_CONFIG_PRESET']  = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MYSQL_INSTANCES_FILE'] = <path to the instances YAML file on the node, using RDS endpoints as host>
default['newrelic_install']['env']['NR_CLI_MYSQL_SECRETS_FILE']   = <path to the secrets file (KEY=VALUE per instance) on the node>
# See all available targets at: https://github.com/newrelic/chef-install
```

```json
"run_list": [
  "recipe[newrelic-install]"
]
```
</Step>

<Step>
## Trouvez et utilisez vos données [#find]

Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données MySQL via l&apos;UI de New Relic.

Pour trouver votre entité de base de données MySQL dans New Relic :

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MySQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.
3. Sélectionnez votre base de données MySQL dans la liste des entités.
</Step>
