Le `sqlqueryreceiver` est un Récepteur OpenTelemetry Collector qui vous permet d’exécuter n’importe quelle requête SQL personnalisée sur votre base de données, et d’ingérer les résultats sous forme de métriques dans New Relic.

Utilisez ceci lorsque vous souhaitez monitorer des données non couvertes par les métriques `nroracledbreceiver` / `nrsqlserverreceiver` / `nrmysqlreceiver` / `nrpostgresqlreceiver` intégrées. Les métriques personnalisées collectées via `sqlqueryreceiver` apparaissent sous la même entité Oracle, SQL Server, MySQL, ou PostgreSQL dans New Relic que les données intégrées du Récepteur, à condition que les attributs de liaison d’entité soient configurés correctement.

## Prérequis [#prerequisites]

* L’utilisateur de base de données configuré dans la source de données doit avoir le privilège `SELECT` sur toute vue ou table que vous avez l’intention d’interroger.
* Le binaire du collecteur doit inclure le composant `sqlqueryreceiver`.

      Ajoutez le bloc `sqlqueryreceiver` dans la section `receivers:` de votre `oracle-config.yaml` existant, à côté du bloc `nroracledb` existant :

      ```yaml
      receivers:
        nroracledb:

        ...

        sqlquery/oracle:
          driver: oracle

          # Approach 1: Use the `host`, `port`, `database`, `username`, and `password` fields to connect to your database. The receiver will construct the datasource URL for you.
          # host: <YOUR_DB_HOST>
          # port: <YOUR_DB_PORT>
          # database: <YOUR_DATABASE_NAME>
          # username: <YOUR_DB_USERNAME>
          # password: <YOUR_DB_PASSWORD>


          # Approach 2: Use the `datasource` field to provide a full connection string. 
          datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"
      ```

      ### Convention de nommage

      Les noms de métriques doivent commencer par `oracledb.` pour être associés à l’entité correcte dans New Relic. Les métriques avec un préfixe différent seront ingérées mais n’apparaîtront pas sous l’entité de base de données.

      ### Synthèse d’entité

      Ajoutez les Processeurs `resource/add_event_name` et `resource/add_host` pour définir `server.address` et `server.port` sur les mêmes valeurs que celles utilisées par le Récepteur de base de données. Sans cela, les métriques personnalisées ne seront pas liées à l&apos;entité de base de données.

      Ajoutez les processeurs dans la section `processors:` :

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Configuration du Pipeline

      Ajoutez un pipeline `metrics/custom` dans la section `service.pipelines:` de la configuration, à côté des pipelines existants :

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_event_name, resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        Ajoutez `resource/add_event_name` et `resource/add_host` avant `batch` dans la liste des Processeurs.
      </Callout>

      ### NRQL pour valider les données

      Après avoir redémarré le collecteur, exécutez ce qui suit pour confirmer que les métriques personnalisées arrivent :

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      ## Dépannage [#troubleshooting]

      | Problème                                                   | Cause                                                           | Réparer                                                                                             |
      | ---------------------------------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
      | `ORA-00942: table or view does not exist`                  | Privilège SELECT manquant pour l’utilisateur de base de données | Accordez `SELECT ON <VIEW_NAME>` à l’utilisateur                                                    |
      | `missing port in address`                                  | `#` dans le nom d’utilisateur / mot de passe non encodé en URL  | Remplacez `#` par `%23` dans l’URL de la source de données                                          |
      | Aucune donnée dans New Relic                               | `server.address`/`server.port` non défini ou non concordant     | Ajoutez les processeurs `resource/add_event_name` et `resource/add_host` avec les valeurs correctes |
      | Métriques ne figurant pas sous l’entité de base de données | Préfixe requis manquant dans le nom de métrique                 | Assurez-vous que les noms des métriques commencent par `oracledb.`                                  |

      Si aucune des solutions ci-dessus ne résout le problème, vérifiez les propres logs du collecteur pour y trouver des erreurs :

      ```bash
      sudo journalctl -u nrdot-collector -f
      ```

      ### Convention de nommage

      Les noms de métriques doivent commencer par `postgresql.` pour être associés à l’entité correcte dans New Relic. Les métriques avec un préfixe différent seront ingérées mais n’apparaîtront pas sous l’entité de base de données.

      ### Synthèse d’entité

      `nrpostgresql` synthétise son entité de base de données à partir de `server.address` et `server.port`. Ajoutez un Processeur `resource/add_host` pour appliquer les mêmes valeurs `server.address`/`server.port` utilisées par le Récepteur de base de données. Sans cela, les métriques personnalisées ne seront pas liées à l’entité de base de données.

      Ajoutez le Processeur dans la section `processors:` :

      ```yaml
      processors:
        batch:
        resource/add_host:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      <Callout variant="important">
        Si votre pipeline `nrpostgresql` possède déjà un processeur `resource/*` définissant `server.address`/`server.port` (par exemple `resource/postgresql`), réutilisez ce même processeur dans le pipeline `metrics/custom` ci-dessous au lieu de le dupliquer : les deux récepteurs doivent appliquer des valeurs identiques pour être rattachés à la même entité.
      </Callout>

      ### Configuration du Pipeline

      Ajoutez un pipeline `metrics/custom` dans la section `service.pipelines:` de la configuration, à côté des pipelines existants :

      ```yaml
      service:
        pipelines:
          metrics/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          logs/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          metrics/custom:
            receivers: [sql_query/postgres]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        Ajoutez `resource/add_host` avant `batch` dans la liste des processeurs.
      </Callout>
