Obtenez des informations détaillées complètes sur les performances de votre base de données conteneur (CDB) Oracle avec le monitoring de base de données, l’analyse des requêtes, et les métriques de santé du système à l’aide du collecteur New Relic Distribution of OpenTelemetry (NRDOT). Toutes les bases de données enfichables (PDB) sous la CDB configurée sont monitorées.

<Callout variant="tip" title="Installation guidée">
  Pour installer plutôt via l&apos;UI de New Relic, accédez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; Oracle (OpenTelemetry)** </DNT>. Cette page couvre uniquement l&apos;installation via la CLI.
</Callout>

## Prérequis [#prerequisites]

Avant de commencer, assurez-vous d’avoir les éléments suivants :

* [Clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)New Relic valide
* Architecture prise en charge : Linux avec AMD64 et ARM64
* Connectivité réseau vers le [point de terminaison OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp)
* Oracle Database `19c` ou version ultérieure

    Sélectionnez la méthode de distribution de l&apos;installation appropriée pour votre environnement Linux :

    <CollapserGroup>

  <Step>
    ## Configurer l&apos;utilisateur de la base de données [#database-user]

    Créez un utilisateur de monitoring avec les privilèges nécessaires pour votre base de données Oracle multitenant. Cela nécessite de créer un utilisateur commun avec le préfixe `C##`.

    1. Pour définir votre contexte de conteneur actif actuel sur `CDB$ROOT`, exécutez l’instruction suivante en tant qu’utilisateur `SYS` :

       ```sql
       ALTER SESSION SET CONTAINER = CDB$ROOT;
       ```

    2. Pour les bases de données multi-locataires :

       1. Connectez-vous à la base de données racine en tant qu&apos;administrateur.

       2. Pour créer un nouvel utilisateur, exécutez l&apos;instruction `CREATE USER` suivante :

          ```sql
          CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<USER_PASSWORD>" CONTAINER=ALL;
          GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
          ```

          <Callout variant="tip">
            L’utilisateur nouvellement créé sera un utilisateur commun avec le préfixe `C##`. Le préfixe `C##` est requis pour les utilisateurs communs par Oracle.
          </Callout>

    3. Pour permettre à l’utilisateur de monitoring de voir les lignes de chaque PDB dans les vues de données de conteneur, exécutez l’instruction suivante en tant que `SYSDBA` sur la racine CDB. Ceci est requis pour les métriques et événements par PDB.

       ```sql
       ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;
       ```

       <Callout variant="tip">
         Assurez-vous que votre `USER_PASSWORD` respecte les exigences d&apos;Oracle en matière de [mot de passe du nouvel utilisateur](https://docs.oracle.com/en/database/oracle/oracle-database/12.2/dbseg/keeping-your-oracle-database-secure.html#GUID-451679EB-8676-47E6-82A6-DF025FD65156).
       </Callout>
  </Step>

  <Step>
    ## Accorder des privilèges de monitoring pour une base de données multitenant [#grant-privileges]

    Exécutez les `GRANT` instructions suivantes en tant que `SYSDBA` sur la racine CDB. Celles-ci couvrent la détection d’instance, la collecte de métriques, le monitoring par PDB, et la collecte d’événements. Vous pouvez les exécuter ensemble sous forme de script unique, ou exécuter chaque instruction individuellement.

    ```sql
    GRANT SELECT ON V_$INSTANCE   TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$DATABASE   TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$CONTAINERS TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$DATAFILE   TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SYSSTAT                    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$CON_SYSSTAT                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SYSMETRIC                  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$CON_SYSMETRIC              TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SESSION                    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$RESOURCE_LIMIT             TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$OSSTAT                     TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SGAINFO                    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ROWCACHE                   TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$PARAMETER                  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_TABLESPACES               TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_DATA_FILES                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_FREE_SPACE                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_RECYCLEBIN                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SQL            TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL       TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$LOCK           TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SESSION_EVENT  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_PROCEDURES    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_OBJECTS       TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$PDBS           TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_SERVICES      TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ASM_DISKGROUP_STAT TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ASM_DISK_STAT      TO c##<USER_NAME> CONTAINER=ALL;
    ```

    <Callout variant="tip">
      Les autorisations `V_$ASM_DISKGROUP_STAT` et `V_$ASM_DISK_STAT` ne sont requises que si vous souhaitez collecter [les métriques de groupe de disques et de disque ASM](/docs/opentelemetry/database/oracle/metrics-reference/#asm).
    </Callout>
  </Step>

    </table>

    <Callout variant="tip">
      Pour plus de détails sur la configuration du point de terminaison OTLP New Relic et les bonnes pratiques OpenTelemetry, consultez la [documentation OpenTelemetry OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp/).
    </Callout>
  </Step>

  <Step>
    ## Mettre à jour la configuration du Collector NRDOT [#update]

    Mettez à jour la configuration du Collector NRDOT pour utiliser votre fichier `oracle-config.yaml` :

    ```bash
    sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/oracle-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
    ```

    <Callout variant="tip">
      Vous pouvez également :

      * [Configurer plusieurs récepteurs](/docs/opentelemetry/database/oracle/multi-receiver): pour monitorer plusieurs instances de base de données Oracle à partir d’un seul collecteur.
      * [Configurer le Récepteur de requêtes SQL](/docs/opentelemetry/database/capabilities/sql-query-receiver/): pour collecter des métriques personnalisées à partir de votre base de données Oracle.
      * [Lier votre base de données Oracle à l&apos;APM](/docs/opentelemetry/database/capabilities/db-apm): pour corréler les performances de vos applications avec les opérations de base de données. Cela vous permet de voir exactement quelles applications génèrent des workloads de base de données spécifiques.
      * [Configurer la gestion des secrets](/docs/opentelemetry/database/capabilities/db-apm/#secret-management): pour gérer en toute sécurité des informations sensibles, telles que les identifiants de base de données. Cela permet de renforcer la sécurité de votre configuration de monitoring en évitant de coder en dur des données sensibles dans les fichiers de configuration.
    </Callout>
  </Step>

  <Step>
    ## Redémarrer NRDOT Collector [#restart-collector]

    Après avoir mis à jour votre configuration, redémarrez le Collector NRDOT :

    ```bash
    sudo systemctl restart nrdot-collector.service
    sudo systemctl status nrdot-collector.service
    ```

    <Callout variant="tip">
      Redémarrez toujours le Collector NRDOT après avoir modifié la configuration pour que les nouveaux paramètres soient pris en compte.
    </Callout>
  </Step>

  <Step>
    ## Trouvez et utilisez vos données [#find-use-data]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données Oracle via l&apos;interface utilisateur de New Relic.

    Pour trouver votre entité de base de données Oracle dans New Relic :

    1. Allez à <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.
    2. Définissez les critères de recherche comme <DNT>`instrumentation.provider = opentelemetry`</DNT>.
    3. Sélectionnez votre base de données Oracle dans la liste des entités.
  </Step>
</Steps>
