Vous pouvez utiliser la contribution OpenTelemetry Collector pour la base de données Oracle afin de monitorer votre instance. La contribution OpenTelemetry Collector est un projet soutenu par la communauté qui offre un moyen de collecter des données télémétriques à partir de la base de données Oracle, et de les envoyer à New Relic.

Par défaut, la contribution OpenTelemetry Collector collecte les métriques de la base de données Oracle et les envoie à New Relic. Cependant, il s’agit de métriques limitées. Pour envoyer les métriques de performance des requêtes, les métriques de temps d’attente, les métriques de session, les métriques de stockage ASM, et d’autres métriques avancées, vous devrez configurer la contribution OpenTelemetry Collector. Ce guide fournit des instructions pour configurer la contribution OpenTelemetry Collector afin de collecter des métriques avancées de la base de données Oracle et de les envoyer à New Relic.

<Steps>
  <Step>
    ## Prérequis [#prerequisites]

    * OpenTelemetry Collector Contrib (`otelcol-contrib`) installé &amp; configuré sur votre système. Vous pouvez télécharger la dernière sortie depuis la page des [sorties de l&apos;OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).
  </Step>

  <Step>
    ## Activer les métriques UI [#enable]

    Vous pouvez enrichir votre expérience de la plateforme New Relic en ajoutant et en activant les différentes métriques dans votre fichier de configuration `otelcol-contrib`. En utilisant la configuration fournie dans cette section, vous pouvez alimenter les données des pages suivantes de la plateforme New Relic :

    * <DNT>Overview</DNT>
    * <DNT>Query performance</DNT>
    * <DNT>Wait events</DNT>
    * <DNT>Sessions</DNT>

    <CollapserGroup>
      <Collapser id="overview" title="Activer les métriques de la page Overview">
        La page <DNT>Overview</DNT> affiche une vue d’ensemble de votre instance de base de données Oracle, y compris des métriques clés telles que l’utilisation du CPU, le temps d’attente, les I/O, la mémoire, et l’utilisation des sessions.

        Pour renseigner les données de la page <DNT>Overview</DNT> dans la plateforme New Relic, ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib` :

        ```yaml
        receivers:
          oracledb:
            # Metrics required by the "Oracle Database Monitoring (OTel)" dashboard
            metrics:
              oracledb.buffer_cache.utilization:
                enabled: true
              oracledb.consistent_gets:
                enabled: true
              oracledb.cpu_time:
                enabled: true
              oracledb.database.cpu.utilization:
                enabled: true
              oracledb.database.wait.utilization:
                enabled: true
              oracledb.db_block_gets:
                enabled: true
              oracledb.enqueue_deadlocks:
                enabled: true
              oracledb.execution.utilization:
                enabled: true
              oracledb.executions:
                enabled: true
              oracledb.hard_parses:
                enabled: true
              oracledb.host.cpu.utilization:
                enabled: true
              oracledb.library_cache.utilization:
                enabled: true
              oracledb.logical_reads:
                enabled: true
              oracledb.logons:
                enabled: true
              oracledb.parse.rate:
                enabled: true
              oracledb.parse_calls:
                enabled: true
              oracledb.pga_memory:
                enabled: true
              oracledb.physical_io.requests:
                enabled: true
              oracledb.physical_reads:
                enabled: true
              oracledb.physical_writes:
                enabled: true
              oracledb.processes.usage:
                enabled: true
              oracledb.sessions.usage:
                enabled: true
              oracledb.sga.usage:
                enabled: true
              oracledb.shared_pool.utilization:
                enabled: true
              oracledb.sql_service.response.duration:
                enabled: true
              oracledb.sqlnet.io.transferred:
                enabled: true
              oracledb.tablespace_size.usage:
                enabled: true
              oracledb.transactions.usage:
                enabled: true
              oracledb.user_commits:
                enabled: true
              oracledb.user_rollbacks:
                enabled: true
        ```
      </Collapser>

      <Collapser id="query-performance" title="Activez les métriques de performance des requêtes, de session, et d'attente">
        Pour alimenter les données des pages <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, et <DNT>Sessions</DNT>, ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib` :

        ```yaml
        receivers:
          oracledb:
            events:
              db.server.query_sample:
                enabled: true
              db.server.top_query:
                enabled: true
              db.server.session.wait_sample:
                enabled: true

            top_query_collection:
              max_query_sample_count: 1000
              top_query_count: 200
              collection_interval: 60s
              allowed_comment_keys:
                - nr_service_guid

            query_sample_collection:
              max_rows_per_query: 100
              allowed_comment_keys:
                - nr_service_guid

            session_wait_event_collection:
              max_rows_per_query: 100
        ```
      </Collapser>

      <Collapser id="asm" title="Activer les métriques de groupe de disques et de disque ASM">
        Le Récepteur de base de données Oracle prend en charge le monitoring des instances ASM (Automatic Storage Management). Le Récepteur collecte des métriques critiques de santé du stockage, y compris la capacité du groupe de disques, l’espace libre utilisable, les disques hors ligne, et les erreurs de lecture/écriture des disques physiques.

        Exécutez ce qui suit en tant qu&apos;utilisateur Oracle privilégié pour accorder l&apos;accès :

        ```sql
        GRANT SELECT ON V_$ASM_DISKGROUP_STAT TO <username>;
        GRANT SELECT ON V_$ASM_DISK_STAT TO <username>;
        ```

        Ajoutez la configuration suivante à votre fichier de configuration `otelcol-contrib`. Les 5 métriques sont **désactivées par défaut** (opt-in) :

        ```yaml
        receivers:
          oracledb:
            datasource: "oracle://otel:password@localhost:51521/XE"
            metrics:
              oracledb.asm.disk_group.free:
                enabled: true
              oracledb.asm.disk_group.capacity:
                enabled: true
              oracledb.asm.disk_group.usable_free:
                enabled: true
              oracledb.asm.disk_group.offline_disks:
                enabled: true
              oracledb.asm.disk.errors:
                enabled: true
        ```

        Pour une description de ces métriques, consultez la [référence des métriques](/docs/opentelemetry/database/oracle/metrics-reference/#asm).
      </Collapser>
    </CollapserGroup>
  </Step>

  <Step>
    ## Redémarrez le Collector OpenTelemetry [#restart]

    Redémarrez l&apos;OpenTelemetry Collector pour appliquer les modifications de configuration :

    ```bash
    sudo systemctl restart otelcol-contrib
    ```
  </Step>
</Steps>
