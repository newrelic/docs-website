Vous pouvez configurer le NRDOT Collector pour monitorer plusieurs instances PostgreSQL à partir d&apos;un seul collecteur. Cela est utile si vous avez plusieurs bases de données PostgreSQL exécutées sur différents hôtes ou ports et que vous souhaitez collecter des métriques de toutes ces bases à l&apos;aide d&apos;une seule instance NRDOT Collector.

<Steps>
  <Step>
    ## Prérequis [#prerequisites]

    * NRDOT est installé et configuré pour vos instances PostgreSQL :
      * [PostgreSQL auto-hébergé](/docs/opentelemetry/database/postgresql/hosted)
  </Step>

  <Step>
    ## Ajouter une configuration multi-récepteur [#multi]

    L’exemple suivant montre comment configurer le NRDOT Collector pour monitorer deux instances PostgreSQL à l’aide d’une configuration multi-Récepteur. Vous pouvez ajouter d’autres Récepteurs selon vos besoins pour des instances PostgreSQL supplémentaires.

    ```yaml
    receivers:
      nrpostgresql/db1: &nrpostgresql-common
        endpoint: "<YOUR_DB1_HOST>:<YOUR_DB1_PORT>"
        username: "<YOUR_DB_USERNAME>"
        password: "<YOUR_DB_PASSWORD>"
        databases:
          - <YOUR_DB1_DATABASE_NAME>
        collection_interval: 10s
      nrpostgresql/db2:
        <<: *nrpostgresql-common
        endpoint: "<YOUR_DB2_HOST>:<YOUR_DB2_PORT>"
        databases:
          - <YOUR_DB2_DATABASE_NAME>

    service:
      pipelines:
        metrics:
          receivers: [nrpostgresql/db1, nrpostgresql/db2]
          exporters: [otlp/newrelic]
    ```
  </Step>

  <Step>
    ## Redémarrer NRDOT Collector [#restart]

    Le redémarrage est requis, et non facultatif — le collecteur charge sa configuration une fois au démarrage et ne se recharge pas à chaud. Toute modification de la configuration n’a aucun effet tant que vous ne redémarrez pas le processus.

    ```bash
    sudo systemctl restart nrdot-collector
    ```
  </Step>
</Steps>
