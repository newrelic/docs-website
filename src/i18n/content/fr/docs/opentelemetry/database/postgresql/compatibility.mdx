Avant de commencer à monitorer votre PostgreSQL avec NRDOT, assurez-vous que votre environnement répond à ces exigences.

## Prérequis

Avant de commencer, assurez-vous d’avoir les éléments suivants :

* PostgreSQL `14` et versions ultérieures
* [Clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)New Relic valide
* Connectivité réseau entre le Collector NRDOT et votre base de données
* Modules supplémentaires fournis par Postgres installés. Pour la plupart des installations, cela est inclus par défaut, mais les installations moins conventionnelles peuvent nécessiter une installation supplémentaire de votre version du [package postgresql-contrib](https://www.postgresql.org/docs/current/contrib.html)
* Cette intégration est disponible dans le cadre du programme d&apos;aperçu public de New Relic. Vérifiez auprès du responsable de votre organisation pour vous inscrire à partir de la page [Previews &amp; Trials](https://one.newrelic.com/admin-portal/promotion-management/home)

## Paramètres de serveur recommandés [#params]

Configurez les [paramètres](https://www.postgresql.org/docs/current/config-setting.html) suivants, puis redémarrez le serveur pour que les paramètres prennent effet. Pour plus d&apos;informations sur ces paramètres, consultez la [documentation Postgres](https://www.postgresql.org/docs/current/pgstatstatements.html).

<Callout variant="important">
  Sur RDS/Aurora, `track_activity_query_size` et `pg_stat_statements.max` sont des paramètres statiques — même lors de leur application via un groupe de paramètres à la création de l&apos;instance, AWS exige `apply_method: pending-reboot` pour ces derniers (l&apos;application immédiate échoue avec `InvalidParameterCombination`). Un redémarrage est nécessaire pour que ces deux paramètres prennent effet dans tous les cas.
</Callout>

<Callout variant="important">
  Sur Aurora, le nom de la famille de groupes de paramètres de base de données encode la version majeure (par exemple, `aurora-postgresql14`, `aurora-postgresql16`) et doit correspondre exactement à la version du moteur du cluster ou de l&apos;instance — AWS rejette la création de l&apos;instance avec `InvalidParameterCombination` s&apos;ils ne correspondent pas. Il n&apos;y a pas de famille unique qui fonctionne pour toutes les versions.
</Callout>

1. Choisissez votre méthode d&apos;installation :

* [Configuration auto-hébergée](/docs/opentelemetry/database/postgresql/hosted)
* [Configuration d’AWS RDS](/docs/opentelemetry/database/postgresql/rds)

2. Consultez les [métriques disponibles](/docs/opentelemetry/database/postgresql/metrics-reference) qui seront collectées
3. Consultez notre [guide de dépannage](/docs/opentelemetry/database/postgresql/troubleshooting) pour les problèmes courants
