Obtenez des informations détaillées complètes sur les performances de votre AWS RDS SQL Server grâce au monitoring de base de données, à l&apos;analyse des requêtes et aux métriques de santé du système à l&apos;aide du collecteur New Relic Distribution of OpenTelemetry (NRDOT).

Pour installer ceci via l&apos;UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Suivez les instructions à l&apos;écran pour configurer l&apos;intégration. Cette page couvre uniquement le chemin d&apos;installation de la CLI.

<Callout variant="tip">
  Si vous utilisez SQL Server dans un environnement auto-hébergé Linux, consultez l’ [instrumentation Linux pour RDS](/docs/opentelemetry/database/mssql/linux-hosted).
</Callout>

    * Exigences système Linux :

      * `sqlcmd` utilitaire installé sur votre système Linux
      * Connectivité réseau vers le [point de terminaison OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp)

  <Step>
    ## Installer le collecteur NRDOT [#setup]

    Téléchargez et installez le package NRDOT pour votre distribution Linux. Remplacez `<NRDOT_VERSION>` par le dernier tag de sortie de la page [nrdot-collector-releases](https://github.com/newrelic/nrdot-collector-releases/releases).

    <Callout variant="important">
      Installez le Collector NRDOT sur une instance EC2 ou une machine locale disposant d’une connectivité réseau à votre instance RDS SQL Server. Assurez-vous que votre groupe de sécurité autorise les connexions entrantes sur le port 1433 (ou un port personnalisé).
    </Callout>

  <Step>
    ## Créer un utilisateur de monitoring [#user]

    Exécutez ce script en tant qu’utilisateur root pour créer l’utilisateur de monitoring `newrelic` et accorder les autorisations nécessaires pour collecter les métriques RDS SQL Server.

    1. Créez un fichier nommé `nr-grant-permission-rds.sql`.

    2. Collez le script SQL suivant pour créer l’utilisateur de monitoring `newrelic` et remplacez `<YOUR_PASSWORD>` par le mot de passe souhaité :

       ```sql
       USE [master];
       GO
       CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
       GO
       -- Instance-level permissions
       GRANT VIEW SERVER STATE TO [newrelic];
       GRANT VIEW ANY DEFINITION TO [newrelic];
       GRANT VIEW ANY DATABASE TO [newrelic];
       GO
       -- Grant read access privileges to all user databases
       DECLARE @name SYSNAME;
       DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
       SELECT [name]
       FROM [master].[sys].[databases]
       WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
       AND [state] = 0; -- Only online databases
       OPEN db_cursor;
       FETCH NEXT FROM db_cursor INTO @name;
       WHILE @@FETCH_STATUS = 0
       BEGIN
         BEGIN TRY
           EXEC('USE [' + @name + '];
             IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
             BEGIN
               CREATE USER [newrelic] FOR LOGIN [newrelic];
             END;
             GRANT VIEW DATABASE STATE TO [newrelic];');
         END TRY
         BEGIN CATCH
           PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
         END CATCH
         FETCH NEXT FROM db_cursor INTO @name;
       END
       CLOSE db_cursor;
       DEALLOCATE db_cursor;
       GO
       ```

    3. Exécutez le script à l&apos;aide de `sqlcmd`. Remplacez `<YOUR-RDS-ENDPOINT>` par votre point de terminaison RDS et `<YOUR_MASTER_PASSWORD>` par votre mot de passe maître :

    ```bash
    sqlcmd -S <YOUR-RDS-ENDPOINT> -U <YOUR_MASTER_USER> -P '<YOUR_MASTER_PASSWORD>' -C -i nr-grant-permission-rds.sql
    ```

    3. *(Facultatif)* Vérifiez que l&apos;utilisateur a été créé avec succès avec les autorisations appropriées :

    ```bash
    sqlcmd -S <YOUR-RDS-ENDPOINT> -U <YOUR_MASTER_USER> -P '<YOUR_MASTER_PASSWORD>' -C -Q "SELECT sp.name AS [User], p.permission_name AS [Permission_Granted] FROM sys.server_permissions p JOIN sys.server_principals sp ON p.grantee_principal_id = sp.principal_id WHERE sp.name = 'newrelic';"
    ```

    <Callout variant="tip">
      * Utilisez votre nom d’utilisateur et votre mot de passe principal RDS pour exécuter ces commandes. Le script exclut automatiquement la base de données `rdsadmin` qui est réservée par AWS.
      * Pour gérer en toute sécurité les informations sensibles, telles que les identifiants de base de données, stockez-les dans des outils de [gestion des secrets](/docs/opentelemetry/database/capabilities/db-apm/#secret-management).
    </Callout>
  </Step>

  <Step>
    ## Mettre à jour la configuration du Collector NRDOT [#update]

    Après avoir configuré votre fichier YAML avec les entrées interactives ci-dessus, terminez la configuration du Collector NRDOT :

    1. Modifiez le fichier de configuration du service à l’aide de la commande suivante :

       ```bash
       sudo nano /etc/nrdot-collector/nrdot-collector.conf
       ```

    2. Mettez à jour le chemin de configuration pour pointer vers votre nouveau fichier `mssql-config.yaml` :

       ```bash
       OTELCOL_CONFIG="/etc/nrdot-collector/mssql-config.yaml"
       ```

    3. (Facultatif) Validez la configuration du Collector NRDOT :

       ```bash
       sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mssql-config.yaml
       ```

       <Callout variant="tip">
         Pour corréler les performances de votre application avec les opérations de base de données, vous pouvez configurer l&apos;identification du service de bases de données. Pour plus d’informations, reportez-vous au [guide de configuration de l’identification du service de bases de données](/docs/opentelemetry/database/capabilities/db-apm).
       </Callout>
  </Step>

  <Step>
    ## Redémarrer NRDOT Collector [#restart]

    Après avoir mis à jour votre configuration, redémarrez le service NRDOT Collector :

    ```bash
    sudo systemctl restart nrdot-collector
    ```

    <Callout variant="tip">
      Redémarrez toujours le service NRDOT Collector après avoir modifié la configuration pour vous assurer que les nouveaux paramètres soient pris en compte.
    </Callout>
  </Step>

  <Step>
    ## Trouvez et utilisez vos données [#find]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données SQL Server via l’UI de New Relic.

    Pour trouver votre entité de base de données SQL Server dans New Relic :

    1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.

    3. Sélectionnez votre base de données SQL Server dans la liste des entités.

       Après avoir configuré le monitoring SQL Server avec NRDOT, vous pouvez :

       * [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser les métriques de votre base de données
       * [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de performances des bases de données
       * [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
  </Step>
