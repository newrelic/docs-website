  Nous travaillons toujours sur cette fonctionnalité, mais nous aimerions que vous l&apos;essayiez !

  Cette fonctionnalité est actuellement fournie dans le cadre d&apos;un aperçu conformément à nos [politiques de pré-sortie](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy/).
</Callout>

Obtenez des informations détaillées sur les performances de votre SQL Server avec notre solution de monitoring basée sur OpenTelemetry. Suivez les métriques de base de données, analysez les requêtes lentes, monitorez l’utilisation des ressources, et corrélez les performances de la base de données avec vos applications.

Cette approche basée sur NRDOT complète notre On-Host Integration (OHI) existante en s&apos;appuyant sur les standards OpenTelemetry pour le monitoring des bases de données, facilitant ainsi l&apos;intégration avec votre pile d&apos;observabilité existante.

Fonctionnalités clés :

* **Standards OpenTelemetry**: s’intègre parfaitement aux outils d’observabilité existants
* **Métriques complètes**: plus de 50 indicateurs de performance de la base de données
* **Informations détaillées au niveau des requêtes**: identifiez et optimisez les requêtes lentes
* **Déploiement flexible**: fonctionne avec les environnements auto-hébergés et cloud
* **Corrélation APM**: connectez les performances de la base de données aux traces de l’application

## Choisissez votre méthode d&apos;installation [#install]

Vous pouvez installer le NRDOT Collector pour le monitoring de SQL Server des manières suivantes :

* Environnements auto-hébergés : installation manuelle sur votre propre infrastructure

  * [Windows auto-hébergé](/docs/opentelemetry/database/mssql/windows-hosted)
  * [Linux auto-hébergé](/docs/opentelemetry/database/mssql/linux-hosted)

* Environnements AWS RDS : monitoring SQL Server géré dans le cloud :

  * [Monitoring de Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
  * [Monitoring RDS Linux](/docs/opentelemetry/database/mssql/linux-rds)

## Installation guidée [#ui-install]

Pour installer ceci via l&apos;UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Suivez les instructions à l&apos;écran pour configurer l&apos;intégration.

## Installation en un coup d&apos;œil [#at-a-glance]

<Steps>
  <Step>
    ### Prérequis [#prerequisites]

    * Compte New Relic avec une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)valide

    * Connectivité réseau entre l’hôte où vous installez le Collector NRDOT et votre Microsoft SQL Server.

    * Connectivité réseau vers la [documentation sur les points de terminaison OTLP de New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/)

    * Prérequis SQL Server, vous aurez besoin de :

      * SQL Server 2017 ou version ultérieure
      * Accès administrateur à SQL Server (rôle `sysadmin` ou équivalent)
      * Connectivité réseau entre le collecteur et SQL Server sur le port `1433` ou un port personnalisé

    * Cette intégration est disponible dans le cadre du programme de préversion publique de New Relic. Vérifiez auprès de votre responsable d’organisation pour vous inscrire depuis la page [Préversions et essais](https://one.newrelic.com/admin-portal/promotion-management/home).

    Pour les prérequis détaillés pris en charge, consultez la section dédiée aux prérequis du document d’installation.
  </Step>

  <Step>
    ### Installer le collecteur NRDOT [#install]

    Choisissez votre parcours d’installation en fonction de votre infrastructure :

    * **Installation guidée**: pour installer via l’UI de New Relic, accédez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Suivez les instructions à l’écran pour configurer l’intégration. Cette page couvre uniquement le chemin d’installation de la CLI.

    * **Environnements auto-hébergés**: installation manuelle sur votre propre infrastructure

      * [Windows auto-hébergé](/docs/opentelemetry/database/mssql/windows-hosted)
      * [Linux auto-hébergé](/docs/opentelemetry/database/mssql/linux-hosted)

    * **Environnements AWS RDS**: monitoring de SQL Server géré dans le cloud

      * [Monitoring de Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
      * [Monitoring RDS Linux](/docs/opentelemetry/database/mssql/linux-rds)
  </Step>

  <Step>
    ### Configurer les utilisateurs de monitoring [#user]

    Créez un utilisateur Microsoft SQL Server dédié avec les autorisations nécessaires pour permettre au Collector NRDOT de collecter des métriques, et de faire une requête sur les données de performances. L’utilisateur doit avoir un accès en lecture seule aux éléments requis.
  </Step>

  <Step>
    ### Configurer le collecteur NRDOT [#configure]

    Configurez le Collector NRDOT pour qu’il se connecte à votre instance Microsoft SQL Server. Cela implique de spécifier les détails de connexion, la méthode d’authentification et toute option de configuration supplémentaire requise pour votre environnement.
  </Step>

  <Step>
    ### Redémarrer NRDOT Collector [#restart]

    Après avoir configuré le NRDOT Collector, redémarrez le service pour appliquer les modifications, et commencer à collecter des données à partir de votre instance Microsoft SQL Server.
  </Step>

  <Step>
    ### Trouvez et utilisez vos données [#find]

    Une fois vos données collectées, vous pouvez accéder à un monitoring complet de la base de données SQL Server via l&apos;UI de New Relic.

    Pour trouver votre entité de base de données SQL Server dans New Relic :

    1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. Dans la liste déroulante **<DNT>Entity type</DNT>**, sélectionnez <DNT>**MSSQL instance**</DNT>, puis cliquez sur <DNT>**Apply**</DNT>.
    3. Sélectionnez votre base de données SQL Server dans la liste des entités pour afficher son dashboard, ses métriques et les données de performance de requête.
  </Step>
</Steps>
