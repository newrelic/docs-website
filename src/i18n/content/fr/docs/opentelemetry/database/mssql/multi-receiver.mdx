Vous pouvez configurer le Collector NRDOT pour monitorer plusieurs instances MSSQL à partir d’un seul collecteur. Cela est utile si vous avez plusieurs MSSQL en cours d’exécution sur différents hôtes et que vous souhaitez collecter des métriques de chacun d’eux à l’aide d’une seule instance de Collector NRDOT.

<Steps>
  <Step>
    ## Prérequis [#prerequisites]

    * NRDOT est installé et configuré pour vos instances MSSQL :

      * [Linux RDS](/docs/opentelemetry/database/mssql/linux-rds)
      * [Hébergé Linux](/docs/opentelemetry/database/mssql/linux-hosted)
      * [Hébergé sur Windows](/docs/opentelemetry/database/mssql/windows-hosted)
      * [Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
  </Step>

  <Step>
    ## Ajouter une configuration multi-récepteur [#multi]

    Les exemples suivants montrent comment configurer le Collector NRDOT pour monitorer plusieurs instances MSSQL en utilisant une configuration multi-Récepteur. Sélectionnez le type de déploiement qui correspond à votre environnement. Vous pouvez ajouter d’autres Récepteurs selon les besoins pour des instances supplémentaires.

    ```yaml
    receivers:
      nrsqlserver/1: &nrsqlserver-common
        username: "<YOUR_DB_USERNAME>"
        password: "<YOUR_DB_PASSWORD>"
        server: "<YOUR_SERVER_1>"
        port: <YOUR_PORT_1>
        collection_interval: 30s
        # Add any additional configuration here (metrics, events, query collection, etc.)
        # All settings are automatically inherited by additional receiver instances.
      nrsqlserver/2:
        <<: *nrsqlserver-common
        username: "<YOUR_DB2_USERNAME>"
        password: "<YOUR_DB2_PASSWORD>"
        server: "<YOUR_SERVER_2>"
        port: <YOUR_PORT_2>
      # Add more instances as needed:
      # nrsqlserver/3:
      #   <<: *nrsqlserver-common
      #   username: "<YOUR_DB3_USERNAME>"
      #   password: "<YOUR_DB3_PASSWORD>"
      #   server: "<YOUR_SERVER_3>"
      #   port: <YOUR_PORT_3>

    service:
      pipelines:
        metrics:
          receivers: [nrsqlserver/1, nrsqlserver/2]  # Add nrsqlserver/3, nrsqlserver/4, ... as needed
          processors: [<YOUR_PROCESSORS>]
          exporters: [otlp]
        logs:
          receivers: [nrsqlserver/1, nrsqlserver/2]  # Add nrsqlserver/3, nrsqlserver/4, ... as needed
          processors: [<YOUR_PROCESSORS>]
          exporters: [otlp]
    ```

    La clé de fusion `<<: *nrsqlserver-common` hérite de tous les paramètres de `nrsqlserver/1`. Tout champ que vous définissez explicitement après celle-ci, tel que `username`, `password`, `server`, et `port`, remplace la valeur héritée pour cette instance de Récepteur spécifique.

    <Callout variant="important">
      Chaque fois que vous ajoutez une nouvelle instance de Récepteur (par exemple, `nrsqlserver/3`), ajoutez-la également à la liste `receivers` dans les deux pipelines `metrics` et `logs` sous `service.pipelines`. Un Récepteur défini dans le bloc `receivers` mais absent de `service.pipelines` ne collectera aucune donnée.
    </Callout>
  </Step>

  <Step>
    ## Redémarrer NRDOT Collector [#restart]

    Le redémarrage est requis, et non facultatif — le collecteur charge sa configuration une fois au démarrage et ne se recharge pas à chaud. Toute modification de la configuration n’a aucun effet tant que vous ne redémarrez pas le processus.

    ```bash
    sudo systemctl restart nrdot-collector
    ```
  </Step>
</Steps>
