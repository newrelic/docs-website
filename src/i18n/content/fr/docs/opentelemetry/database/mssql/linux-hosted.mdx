Configurez le monitoring de Microsoft SQL Server à l&apos;aide du collecteur NRDOT sur les environnements auto-hébergés Linux, y compris les serveurs physiques, les machines virtuelles et les déploiements Linux conteneurisés.

<Steps>
  <Step>
    ### Prérequis [#prerequisites]

    Assurez-vous que votre environnement répond à nos [exigences de compatibilité et prérequis](/docs/opentelemetry/database/mssql/compatibility).
  </Step>

  <Step>
    ## Configurer le Collector NRDOT [#setup]

    Installer le Collector NRDOT sur votre distribution Linux :

    <Callout variant="important">
      Il est recommandé d&apos;installer le Collector NRDOT sur le même hôte que votre instance SQL Server afin de visualiser les métriques d&apos;infrastructure pour le monitoring des performances des requêtes.
    </Callout>

    1. **Debian/Ubuntu**

    **Pour l&apos;architecture AMD64 (x86\_64) :**

    ```bash
    NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
    ```

    **Pour l&apos;architecture ARM64 :**

    ```bash
    NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
    ```

    2. **RHEL/CentOS**

    **Pour l&apos;architecture AMD64 (x86\_64) :**

    ```bash
    NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_x86_64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
    ```

    **Pour l&apos;architecture ARM64 :**

    ```bash
    NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
    ```

  <Step>
    ## Configurer l&apos;utilisateur de la base de données [#user]

    Exécutez le script suivant en tant que `root user/sysadmin` pour créer l&apos;utilisateur de monitoring `newrelic` et accorder des droits de lecture globaux.

    1. Pour créer un utilisateur de monitoring `newrelic` sous Linux, créez un fichier nommé `nr-grant-permission.sql` sur votre instance Linux avec le contenu suivant :

       ```sql
       USE [master];
       GO
       CREATE LOGIN [newrelic] WITH PASSWORD = '<PASSWORD>';
       GO
       -- Instance-level permissions
       GRANT VIEW SERVER STATE TO [newrelic];
       GRANT VIEW ANY DEFINITION TO [newrelic];
       GRANT VIEW ANY DATABASE TO [newrelic];
       GO
       -- Grant read access privileges to all user databases
       DECLARE @name SYSNAME;
       DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
       SELECT [name]
       FROM [master].[sys].[databases]
       WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
       AND [state] = 0; -- Only online databases
       OPEN db_cursor;
       FETCH NEXT FROM db_cursor INTO @name;
       WHILE @@FETCH_STATUS = 0
       BEGIN
         BEGIN TRY
           EXEC('USE [' + @name + '];
             IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
             BEGIN
               CREATE USER [newrelic] FOR LOGIN [newrelic];
             END;
             GRANT VIEW DATABASE STATE TO [newrelic];');
         END TRY
         BEGIN CATCH
           PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
         END CATCH
         FETCH NEXT FROM db_cursor INTO @name;
       END
       CLOSE db_cursor;
       DEALLOCATE db_cursor;
       GO
       ```

    2. Pour exécuter le script, exécutez la commande suivante. Remplacez `<Your_SA_Password>` par votre mot de passe administrateur SQL Server :

       ```bash
       sqlcmd -S localhost -U sa -P '<Your_SA_Password>' -C -i nr-grant-permission.sql
       ```

    3. *(Facultatif)* Pour vérifier que l&apos;utilisateur a été créé avec succès et dispose des autorisations appropriées, exécutez la commande suivante. Remplacez `<Your_SA_Password>` par votre mot de passe administrateur SQL Server :

       ```bash
       sqlcmd -S localhost -U sa -P '<Your_SA_Password>' -C -Q "SELECT sp.name AS [User], p.permission_name AS [Permission_Granted] FROM sys.server_permissions p JOIN sys.server_principals sp ON p.grantee_principal_id = sp.principal_id WHERE sp.name = 'newrelic';"
       ```

       **Résultat attendu :**

       ```
       User Permission_Granted
       -------------------------------------------------------------------------------------
       <your_username> CONNECT SQL
       <your_username> VIEW ANY DEFINITION
       <your_username> VIEW ANY DATABASE
       <your_username> VIEW SERVER STATE
       ```

    Cette sortie confirme que votre utilisateur a été créé avec succès avec les permissions requises au niveau du serveur.
  </Step>

    ### Paramètres de configuration

    Le tableau suivant décrit les principaux paramètres de configuration du récepteur nrsqlserver :

    | paramètres             | Description                                                                                                                                                                                             |
    | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_USERNAME>`      | Saisissez votre nom d&apos;utilisateur de base de données pour l&apos;authentification                                                                                                                  |
    | `<YOUR_PASSWORD>`      | Saisissez le mot de passe de votre base de données pour l&apos;authentification                                                                                                                         |
    | `<YOUR_SERVER>`        | Saisissez le nom d&apos;hôte ou l&apos;adresse IP de SQL Server                                                                                                                                         |
    | `<YOUR_PORT_NUMBER>`   | Saisissez votre numéro de port SQL Server. La valeur par défaut est 1433.                                                                                                                               |
    | `<YOUR_OTLP_ENDPOINT>` | Saisissez le point de terminaison OTLP New Relic. Pour plus d&apos;informations, consultez la [documentation sur les endpoints OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/). |
    | `<YOUR_LICENSE_KEY>`   | Entrez votre clé de licence New Relic.                                                                                                                                                                  |
    | `collection_interval`  | Intervalle en secondes pour collecter les métriques de base de données. Par défaut : 15s                                                                                                                |

    <Callout variant="tip">
      **Remarque :** Si vous activez toutes les métriques disponibles, augmentez la valeur `limit_mib` (par ex., 1000) pour éviter que le limiteur de mémoire ne supprime des données.
    </Callout>

    3. **Mettez à jour le fichier de configuration du collecteur**

       Exécutez la commande suivante pour modifier la configuration du service :

       ```bash
       sudo nano /etc/nrdot-collector/nrdot-collector.conf
       ```

       Mettez à jour le chemin de configuration pour qu&apos;il pointe vers votre nouveau fichier mssql-config.yaml :

       ```bash
       OTELCOL_CONFIG="/etc/nrdot-collector/mssql-config.yaml"
       ```

    4. **Valider la configuration du Collector NRDOT**

       Validez la configuration du Collector NRDOT pour vous assurer qu&apos;elle est correctement formatée et qu&apos;elle fonctionnera correctement :

       ```bash
       sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mssql-config.yaml
       ```
  </Step>

    ## Redémarrer le collecteur NRDOT [#restart]

    Après avoir mis à jour votre configuration, redémarrez le service NRDOT Collector :

    ```bash
    sudo systemctl restart nrdot-collector
    ```

    <Callout variant="tip">
      Redémarrez toujours le service de collecte NRDOT après avoir modifié la configuration pour vous assurer que les nouveaux paramètres soient pris en compte.
    </Callout>
  </Step>
</Steps>
