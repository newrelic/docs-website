New Relic permet désormais à votre équipe de monitorer les performances de votre base de données Oracle à l’aide de la distribution New Relic d’OpenTelemetry (NRDOT) et des fonctionnalités de monitoring de bases de données de New Relic. Cette intégration fournit des informations détaillées complètes sur les métriques de base de données, les performances des requêtes et la santé du système à l’aide du collecteur NRDOT.

Cette approche basée sur NRDOT complète notre On-Host Integration (OHI) existante en s&apos;appuyant sur les standards OpenTelemetry pour le monitoring des bases de données, facilitant ainsi l&apos;intégration avec votre pile d&apos;observabilité existante.

## Prérequis [#prerequisites]

Avant de commencer, assurez-vous d’avoir les éléments suivants :

* [Clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)New Relic valide
* Architecture prise en charge : Linux avec AMD64 et ARM64
* Connectivité réseau vers le point de terminaison OTLP de New Relic
* Oracle Database 19c ou version ultérieure
* Cette intégration est disponible dans le cadre du programme de préversion publique de New Relic. Vérifiez auprès de votre responsable d’organisation pour vous inscrire depuis la page [Préversions et essais](https://one.newrelic.com/admin-portal/promotion-management/home).

## Configurer le NRDOT Collector pour le monitoring d&apos;Oracle Database [#install-collector]

Vous pouvez configurer le monitoring d&apos;Oracle Database à l&apos;aide du collecteur NRDOT dans des environnements sur l&apos;hôte (multitenant) ou RDS. Vous pouvez configurer le NRDOT Collector en utilisant les méthodes suivantes :

* [Installation guidée](/docs/opentelemetry/database/otel-oracledb/#guided): la méthode d’installation guidée fournit des instructions étape par étape sur la plateforme New Relic pour vous aider à installer et configurer le Collector NRDOT pour le monitoring de la base de données Oracle.

* **Installation manuelle**: la méthode d’installation manuelle vous permet de configurer le NRDOT Collector vous-même en suivant les instructions de cette documentation. Vous pouvez configurer manuellement dans les environnements suivants :

  * [Environnement sur l’hôte (multitenant)](/docs/opentelemetry/database/otel-oracledb/#host): installez le Collector NRDOT sur le même hôte que votre instance de base de données Oracle pour collecter les données télémétriques de l’infrastructure et de la base de données.
  * [Environnement RDS](/docs/opentelemetry/database/otel-oracledb/#rds): installez le Collector NRDOT dans un environnement RDS pour monitorer vos instances de base de données Oracle exécutées dans Amazon RDS.

<Callout variant="tip">
  Le NRDOT Collector collecte les données télémétriques liées à la fois à l&apos;infrastructure et à la base de données, afin que vous puissiez disposer d&apos;une solution d&apos;observabilité unifiée pour votre environnement Oracle Database dans New Relic.
</Callout>

              <Step>
                ### Configurer l&apos;utilisateur de la base de données [#mdatabase-user]

                Créez un utilisateur de monitoring avec les privilèges nécessaires pour votre base de données Oracle multitenant. Cela nécessite de créer un utilisateur commun avec le préfixe `C##`.

                1. Avant de créer l’utilisateur de base de données, ou d’exécuter des octrois d’affectation, vous devez exécuter l’instruction suivante en tant qu’utilisateur `SYS` pour définir votre contexte de conteneur actif actuel sur `CDB$ROOT`:

                   ```sql
                   ALTER SESSION SET CONTAINER = CDB$ROOT;
                   ```

                2. Pour une base de données multitenant, connectez-vous à la base de données racine en tant qu’administrateur. Utilisez CREATE USER pour ajouter un nouvel utilisateur à la base de données. Le nom d’utilisateur spécifié sera un « utilisateur commun » et doit être préfixé par `c##` comme recommandé par Oracle.

                   ```sql
                   CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<USER_PASSWORD>" CONTAINER=ALL;
                   GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
                   ```

                3. Exécutez l’instruction suivante en tant que SYSDBA sur la racine CDB. Cela permet à l’utilisateur de monitoring de voir les lignes de chaque PDB dans les vues de données de conteneur, ce qui est requis pour les métriques et événements par PDB.

                   ```sql
                   ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;
                   ```

                   <Callout variant="tip">
                     Assurez-vous que votre `USER_PASSWORD` respecte les exigences d&apos;Oracle en matière de [mot de passe du nouvel utilisateur](https://docs.oracle.com/en/database/oracle/oracle-database/12.2/dbseg/keeping-your-oracle-database-secure.html#GUID-451679EB-8676-47E6-82A6-DF025FD65156).
                   </Callout>
              </Step>

## Commandes prises en charge par le collecteur NRDOT [#commands]

Cette section fournit une liste de commandes courantes pour gérer le service NRDOT Collector sur votre système.

<CollapserGroup>
  <Collapser title="Commandes du collecteur NRDOT" id="command">
    * Pour valider le statut de l&apos;installation :

      * Pour les distributions basées sur Debian/Ubuntu :

        ```bash
        dpkg -l | grep nrdot-collector
        ```

      * Pour les distributions basées sur RHEL/CentOS :

        ```bash
        rpm -q nrdot-collector || ls /etc/nrdot-collector
        ```

    * Pour redémarrer NRDOT Collector :

    ```bash
    sudo systemctl restart nrdot-collector.service
    ```

    * Pour vérifier l&apos;état du NRDOT Collector :

    ```bash
    sudo systemctl status nrdot-collector.service
    ```

    * Pour afficher les logs du NRDOT Collector :

    ```bash
    sudo journalctl -u nrdot-collector -n 50 --no-pager
    ```

    * Pour supprimer le service NRDOT Collector :

      * Pour les distributions basées sur Debian/Ubuntu :

        ```bash
        sudo apt purge nrdot-collector
        ```

      * Pour les distributions basées sur RHEL/CentOS :

        ```bash
        sudo yum erase nrdot-collector
        ```

    * Pour nettoyer les fichiers de configuration :

    ```bash
    # Clean up configuration and reload systemd
    sudo rm -rf /etc/nrdot-collector/
    sudo systemctl daemon-reload
    ```

## Dépannage [#troubleshoot]

Si vous rencontrez des problèmes lors de l&apos;installation, utilisez ce guide de dépannage pour diagnostiquer et résoudre les problèmes courants.

<CollapserGroup>
  <Collapser id="test-connection" title="Tester la connectivité réseau">
    Exécutez la commande suivante pour vérifier que le port de la base de données Oracle est accessible depuis cet hôte.

    ```bash
    (timeout 3 bash -c '</dev/tcp/<YOUR_ENDPOINT>/<YOUR_PORT>' && echo "PORT OPEN - Network connection successful!") || echo "CONNECTION FAILED - Port closed or firewall blocking"
    ```

    **Résultat attendu :** `PORT OPEN - Network connection successful!`
  </Collapser>

  <Collapser id="otlp-endpoint-connection" title="Tester la connectivité du point de terminaison OTLP">
    Exécutez la commande suivante pour vérifier que votre hôte peut atteindre le point de terminaison OTLP New Relic sélectionné.

    ```bash
    ENDPOINT="<YOUR_OTLP_ENDPOINT>"
    HOST=$(echo "$ENDPOINT" | sed 's|https://||' | cut -d: -f1)
    PORT=$(echo "$ENDPOINT" | awk -F: '{print $NF}')
    (timeout 2 bash -c "</dev/tcp/$HOST/$PORT" && echo "✅ SUCCESS") || echo "❌ FAILED"
    ```

    **Résultat attendu :** `✅ SUCCESS`
  </Collapser>
</CollapserGroup>
