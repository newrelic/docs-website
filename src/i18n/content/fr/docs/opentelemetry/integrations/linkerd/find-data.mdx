Après avoir configuré le Collector OpenTelemetry pour Linkerd, la télémétrie de votre maillage est transmise à New Relic sous forme d’événements `Metric`, `Span` et `Log` associés à votre entité Linkerd.

## Trouvez votre entité Linkerd [#find-entity]

1. Accédez à [one.newrelic.com](https://one.newrelic.com) et sélectionnez **Entity Explorer**.
2. Recherchez le nom de votre cluster.
3. Sélectionnez votre entité Linkerd pour ouvrir le dashboard intégré.

Le dashboard intégré couvre le taux de requêtes, la latence p50/p95/p99, le taux de réussite, les connexions TCP, le statut des certificats mTLS, l’état de santé du control plane et l’inventaire des pods maillés.

### Dashboard Linkerd [#dashboard]

Le dashboard d&apos;entité Linkerd fournit un aperçu de la télémétrie de votre service mesh. Il inclut :

| Section               | Panneaux                                                                    |
| --------------------- | --------------------------------------------------------------------------- |
| Métriques principales | Connexions TCP, Requêtes desservies par les proxys                          |
| Traffic               | Taux entrant, Taux sortant                                                  |
| Santé                 | Taux de réussite, taux d’erreur, codes de statut HTTP                       |
| latence               | Latence des requêtes p50/p95/p99, Latence sortante p99                      |
| Sécurité              | Expiration du certificat mTLS, Taux d’actualisation du certificat           |
| Control plane         | Politique d’autorisation, Profondeur de file d’attente, Taux de requêtes CP |
| Topologie             | Utilisation de la mémoire du proxy, opérations par service                  |
| Inventaire            | Pods maillés                                                                |

## Exemple de requête NRQL [#queries]

Remplacez `<YOUR_CLUSTER>` par le nom réel de votre cluster dans chaque requête.

<table>
  <thead>
    <tr>
      <th>
        But
      </th>

      <th>
        Requête NRQL
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        Taux de requêtes par service
      </td>

      <td>
        ```sql
        SELECT rate(sum(request_total), 1 minute) AS 'Req/min' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NULL FACET k8s.deployment.name SINCE 30 minutes ago TIMESERIES
        ```
      </td>
    </tr>

    <tr>
      <td>
        Latence p99 par service
      </td>

      <td>
        ```sql
        SELECT histogram(response_latency_ms, width: 50, slide_by: 10) FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NULL FACET k8s.deployment.name SINCE 30 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Taux de réussite HTTP
      </td>

      <td>
        ```sql
        SELECT sum(response_total) AS 'Total responses', filter(sum(response_total), WHERE classification = 'success') / sum(response_total) * 100 AS 'Success %' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET k8s.deployment.name SINCE 30 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Expiration du certificat mTLS
      </td>

      <td>
        ```sql
        SELECT latest(identity_cert_expiration_timestamp_seconds) AS 'Cert expires (epoch)' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET k8s.deployment.name SINCE 10 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Profondeur de la file d’attente du control plane
      </td>

      <td>
        ```sql
        SELECT latest(control_plane_queue_length) AS 'Queue depth' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NOT NULL FACET linkerd_control_plane_component SINCE 10 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Connexions TCP ouvertes
      </td>

      <td>
        ```sql
        SELECT rate(sum(tcp_open_connections), 1 second) AS 'TCP connections' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET k8s.deployment.name SINCE 30 minutes ago TIMESERIES
        ```
      </td>
    </tr>

    <tr>
      <td>
        Traces distribuées par service (chemin APM uniquement)
      </td>

      <td>
        ```sql
        SELECT count(*) FROM Span WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET service.name SINCE 30 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Vérifiez que les spans du proxy sont collectées avec les attributs Linkerd
      </td>

      <td>
        ```sql
        SELECT count(*) FROM Span WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NOT NULL FACET service.name SINCE 10 minutes ago
        ```
      </td>
    </tr>
  </tbody>
</table>

Si la requête « Vérifiez les spans du proxy » renvoie 0, le Processeur `transform/linkerd_component_inject` n’est pas en cours d’exécution ou `linkerd_control_plane_ns` est manquant dans les spans. Consultez [Dépanner le monitoring Linkerd](/docs/opentelemetry/integrations/linkerd/troubleshooting) pour les étapes de remédiation.
