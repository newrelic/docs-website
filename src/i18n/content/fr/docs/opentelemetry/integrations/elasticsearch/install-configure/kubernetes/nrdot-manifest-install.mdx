Ce guide explique comment déployer NRDOT sur Kubernetes à l’aide d’une installation via manifeste pour découvrir automatiquement vos pods Elasticsearch, collecter les métriques de cluster, de nœud, et de JVM, et les transmettre à New Relic afin de monitorer la santé et les performances de votre cluster.

## Compatibilité et exigences [#requirements]

### Soutenu

* Elasticsearch 7.16 ou version ultérieure, s&apos;exécutant en tant que pods dans un cluster Kubernetes
* Méthode d’installation via manifeste

### Vous avez besoin de

* Une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic
* `kubectl` accès à votre cluster Kubernetes
* L’installation de base du [manifeste Kubernetes OpenTelemetry](/docs/kubernetes-pixie/k8s-otel/install/#manifest-install) est déjà terminée
* Un utilisateur Elasticsearch avec le privilège de cluster `monitor` ou `manage` (voir les [privilèges de sécurité Elasticsearch](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html))
* Connectivité HTTPS sortante (port 443) vers le [point de terminaison OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) de New Relic
* Un nom d&apos;utilisateur et un mot de passe Elasticsearch (si votre cluster nécessite une authentification)

<Steps>
<Step>
## Configurer les étiquettes de pod [#pod-labels]

Chaque pod Elasticsearch doit avoir l&apos;étiquette `app: elasticsearch` pour que la découverte automatique fonctionne. Sans ce label, le collecteur ne détectera ni ne monitorera vos pods.

Si vous utilisez un StatefulSet ou un Deployment pour Elasticsearch, ajoutez l&apos;étiquette dans le modèle de pod :

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: elasticsearch
spec:
  template:
    metadata:
      labels:
        app: elasticsearch  # Required for auto-discovery
    spec:
      containers:
      - name: elasticsearch
        image: docker.elastic.co/elasticsearch/elasticsearch:8.x.x
```

Pour les pods existants sans le label, mettez à jour votre StatefulSet/déploiement et redémarrez les pods :

```bash
kubectl label pods -l <your-existing-selector> app=elasticsearch -n <namespace>
```

Vous pouvez vérifier que les étiquettes sont correctement définies :

```bash
kubectl get pods -n <namespace> --show-labels
```
</Step>

## Préparez l&apos;image du collecteur et les paramètres [#prepare]

Mettez à jour l&apos;image du collecteur, puis définissez sa configuration de monitoring Elasticsearch dans vos fichiers manifestes locaux. Vous appliquez ces modifications à votre cluster à l&apos;étape suivante.

1. Mettez à jour l&apos;image du collecteur vers NRDOT dans les fichiers [`deployment.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/deployment.yaml) et [`daemonset.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/daemonset.yaml) de votre répertoire local `rendered` :

   ```yaml
   image: newrelic/nrdot-collector:latest
   ```

2. Mettez à jour [`deployment-configmap.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/deployment-configmap.yaml) pour le monitoring d&apos;Elasticsearch : définissez `rule` pour qu&apos;il corresponde au label de votre pod, et définissez le nom du cluster dans `resource/cluster` et `resource/cluster_name_override`.    Vous pouvez éventuellement sécuriser ce cluster avec une authentification et SSL. Consultez [Configuration avancée](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration#secured).

### Paramètres de configuration [#configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration utilisés dans le `deployment-configmap.yaml` ci-dessus :

| paramètres                                                                           | Description                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rule`                                                                               | La règle de correspondance de pod utilisée pour la découverte automatique. Mettez à jour `labels["app"] == "elasticsearch"` pour correspondre aux labels de votre pod.                                   |
| `endpoint`                                                                           | Le point de terminaison Elasticsearch scrapé sur chaque pod découvert. Mettez à jour le port `9200` si Elasticsearch s&apos;exécute sur un port différent, et utilisez `https` pour un cluster sécurisé. |
| `collection_interval`                                                                | L&apos;intervalle entre les collectes de métriques. La valeur par défaut est 15 s.                                                                                                                       |
| `elasticsearch-cluster` (dans `resource/cluster` / `resource/cluster_name_override`) | Un nom unique identifiant ce cluster dans New Relic. Remplacez par un nom unique pour l’ensemble de votre compte.                                                                                        |
| `NEW_RELIC_MEMORY_LIMIT_MIB`                                                         | La limite de mémoire, en MiB, pour le Processeur `memory_limiter` du collecteur. Configurez cette valeur en fonction de votre environnement.                                                             |
| `NEWRELIC_LICENSE_KEY`                                                               | Votre [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic.                                                                                                          |
| `NEWRELIC_OTLP_ENDPOINT`                                                             | Le point de terminaison OTLP New Relic pour la région de votre compte. Consultez [les points de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp).                      |
</Step>

<Step>
## Installer et configurer le collecteur NRDOT via kubectl [#install-manifest]

Appliquez les manifestes mis à jour pour déployer le collecteur NRDOT sur votre cluster avec l&apos;image et les paramètres que vous venez de préparer.

```bash
kubectl apply -n newrelic -R -f rendered
```
</Step>

<Step>
## Redémarrez les pods du collecteur NRDOT [#restart]

Redémarrez le déploiement pour appliquer vos modifications :

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```
</Step>

<Step>
## Vérifiez votre installation [#verify]

Dans les -5 minutes suivant l&apos;installation, exécutez cette requête dans New Relic pour confirmer que les données arrivent (remplacez `elasticsearch-cluster` par le nom de votre cluster) :

```sql
FROM Metric
SELECT *
WHERE metricName LIKE 'elasticsearch.%'
  AND instrumentation.provider = 'opentelemetry'
  AND k8s.cluster.name = 'elasticsearch-cluster'
SINCE 10 minutes ago
```

<Callout variant="tip">
Vous pouvez également vérifier le collecteur lui-même : le pod doit être dans un état `Running` (`kubectl get pods -n newrelic --watch`), avec un nom comme `nr-k8s-otel-collector-deployment-<hash>`, sans erreur de connexion dans les logs du pod (`kubectl logs -n newrelic -l app.kubernetes.io/name=nr-k8s-otel-collector -f`).
</Callout>

Si vous ne voyez pas de données dans les -5 minutes, consultez le [dépannage Kubernetes](/docs/opentelemetry/integrations/elasticsearch/troubleshooting#kubernetes-troubleshooting).
</Step>

<Step>
## Trouvez et utilisez vos données [#find-and-use]

Une fois que New Relic collecte vos données, vous pouvez accéder au monitoring Elasticsearch via l&apos;UI de New Relic.

Pour trouver votre dashboard Elasticsearch dans New Relic :

1. Allez à <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT>.
2. Sous l&apos;onglet <DNT>**All**</DNT>, cliquez sur <DNT>**Dashboards**</DNT>, puis recherchez <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> pour afficher le dashboard.

Ou, depuis la navigation de gauche :

1. Cliquez sur <DNT>**Dashboards**</DNT>.
2. Recherchez le dashboard <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> pour l&apos;afficher.

Après avoir configuré le monitoring d’Elasticsearch avec NRDOT :

* [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser vos métriques Elasticsearch
* [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de santé et de performances du cluster
* [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
</Step>
</Steps>

<Callout variant="tip">
**Corréler APM avec Elasticsearch**: pour connecter votre application APM et votre cluster Elasticsearch, incluez l’attribut de ressource `es.cluster.name="your-cluster-name"` dans vos métriques APM. Cela vous permet de visualiser les données APM et Elasticsearch ensemble dans New Relic.
</Callout>
