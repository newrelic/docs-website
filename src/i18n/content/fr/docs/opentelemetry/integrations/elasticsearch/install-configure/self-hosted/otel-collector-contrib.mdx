Utilisez ce guide pour installer et configurer OpenTelemetry Collector Contrib afin de monitorer un cluster Elasticsearch auto-hébergé sur un serveur Linux ou une machine virtuelle. Une fois que vous l’avez configuré, le collecteur exporte les métriques de votre cluster Elasticsearch vers New Relic. Pour les métriques d’hôte, les logs, et les tags personnalisés, consultez la section [Configuration avancée](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration).

## Compatibilité et exigences [#requirements]

### Soutenu

* Elasticsearch 7.16 ou version ultérieure

### Vous avez besoin de

* Une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic
* Privilèges root ou sudo sur l&apos;hôte
* Privilèges d’administration de cluster Elasticsearch avec le privilège de cluster `monitor` ou `manage` (voir les [privilèges de sécurité Elasticsearch](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html))
* Connectivité HTTPS sortante (port 443) vers le [point de terminaison OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) de New Relic
* Un nom d&apos;utilisateur et un mot de passe Elasticsearch (si votre cluster nécessite une authentification)

<Steps>
<Step>
## Installer Collecteur Otel Contrib [#install]

Installez [OpenTelemetry Collector Contrib](https://github.com/open-telemetry/opentelemetry-collector-contrib/releases/latest) et exécutez-le en tant que service systemd. Les packages `.deb`/`.rpm` officiels créent l’unité de service pour vous.
</Step>

<Step>

### Paramètres de configuration [#configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration utilisés dans la configuration ci-dessus :

| paramètres                                                           | Description                                                                                                                                                                     |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`                                                           | L’URL de votre cluster Elasticsearch.                                                                                                                                           |
| `collection_interval`                                                | L&apos;intervalle entre les collectes de métriques. La valeur par défaut est 15 s.                                                                                              |
| `elasticsearch.cluster.name` (dans `resource/cluster_name_override`) | Un nom unique identifiant ce cluster dans New Relic, en remplaçant `<YOUR_ELASTICSEARCH_CLUSTER_NAME>` par un nom unique sur l’ensemble de votre compte.                        |
| `NEW_RELIC_MEMORY_LIMIT_MIB`                                         | La limite de mémoire, en MiB, pour le Processeur `memory_limiter` du collecteur, définie pour s&apos;adapter à votre environnement.                                             |
| `NEWRELIC_LICENSE_KEY`                                               | Votre [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic.                                                                                 |
| `NEWRELIC_OTLP_ENDPOINT`                                             | Le point de terminaison OTLP New Relic pour la région de votre compte, selon les [points de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp). |

3. Enregistrez le fichier de configuration.

Vous pouvez facultativement ajouter l&apos;authentification de cluster sécurisé, les métriques d&apos;hôte, la collecte de log, ou les tags de métadonnées personnalisés. Consultez [Configuration avancée](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration).
</Step>

<Step>
## Définissez les variables d&apos;environnement [#env-vars]

Définissez les identifiants et les détails de connexion dont le collecteur a besoin pour envoyer des données à New Relic.

```bash
sudo mkdir -p /etc/systemd/system/otelcol-contrib.service.d
cat <<EOF | sudo tee /etc/systemd/system/otelcol-contrib.service.d/environment.conf
[Service]
Environment="NEWRELIC_OTLP_ENDPOINT=<YOUR_NEWRELIC_OTLP_ENDPOINT>"
Environment="NEWRELIC_LICENSE_KEY=<YOUR_NEWRELIC_LICENSE_KEY>"
Environment="NEW_RELIC_MEMORY_LIMIT_MIB=100"
EOF
```
</Step>

<Step>
## Redémarrez le Collecteur Otel Contrib [#restart]

Redémarrez le collecteur pour appliquer vos modifications :

```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```
</Step>

<Step>
## Vérifier la collecte de données [#verify]

Dans les -5 minutes suivant le redémarrage du collecteur, exécutez cette requête dans New Relic pour confirmer que les données circulent (remplacez `<YOUR_ELASTICSEARCH_CLUSTER_NAME>` par le nom de votre cluster) :

```sql
FROM Metric SELECT count(*)
WHERE metricName LIKE 'elasticsearch.%'
AND elasticsearch.cluster.name = '<YOUR_ELASTICSEARCH_CLUSTER_NAME>'
SINCE 10 minutes ago
```

<Callout variant="tip">
Vous pouvez également vérifier le collecteur lui-même : `otelcol-contrib.service` devrait signaler `active (running)` (`sudo systemctl status otelcol-contrib.service`), sans erreur de connexion dans les logs (`sudo journalctl -u otelcol-contrib.service -f`).
</Callout>

Si vous ne voyez pas de données d&apos;ici -5 minutes, consultez le [dépannage d&apos;Elasticsearch](/docs/opentelemetry/integrations/elasticsearch/troubleshooting).
</Step>

<Step>
## Trouvez et utilisez vos données [#find-and-use]

Une fois que New Relic collecte vos données, vous pouvez accéder au monitoring Elasticsearch via l&apos;UI de New Relic.

Pour trouver votre dashboard Elasticsearch dans New Relic :

1. Allez à <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT>.
2. Sous l&apos;onglet <DNT>**All**</DNT>, cliquez sur <DNT>**Dashboards**</DNT>, puis recherchez <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> pour afficher le dashboard.

Ou, depuis la navigation de gauche :

1. Cliquez sur <DNT>**Dashboards**</DNT>.
2. Recherchez le dashboard <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> pour l&apos;afficher.

Après avoir configuré le monitoring d&apos;Elasticsearch avec le Collecteur Otel Contrib, vous pouvez :

* [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser vos métriques Elasticsearch
* [Configurer des alertes](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) pour les seuils critiques de santé et de performances du cluster
* [Explorez vos données](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) à l’aide des fonctionnalités de requête de New Relic
</Step>
</Steps>

<Callout variant="tip">
**Corréler APM avec Elasticsearch**: pour connecter votre application APM et votre cluster Elasticsearch, incluez l’attribut de ressource `es.cluster.name="your-cluster-name"` dans vos métriques APM. Cela vous permet de visualiser les données APM et Elasticsearch ensemble dans New Relic.
</Callout>
