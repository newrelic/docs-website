Cette page couvre la configuration facultative pour le monitoring d’Elasticsearch au-delà de la configuration minimale : les cluster sécurisés, les métriques de l’hôte, la collecte de log et les tag de métadonnées personnalisés.

## Elasticsearch sécurisé avec authentification et SSL [#secured]

Ajoutez l&apos;authentification et TLS à votre connexion Elasticsearch lorsque votre cluster les requiert.

### Exigences [#secured-requirements]

* Un utilisateur Elasticsearch avec le privilège de cluster `monitor` ou `manage`, et des identifiants valides pour cet utilisateur.

Pour un Elasticsearch sécurisé avec authentification et SSL, modifiez la configuration du récepteur :

<CollapserGroup>
<Collapser id="secured-nrdot" title="NRDOT">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-otel" title="Collecteur OTel Contrib">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-k8s-nrdot" title="Kubernetes : NRDOT (manifeste ou Helm)">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>

<Collapser id="secured-k8s-otel" title="Kubernetes : Collecteur OTel Contrib">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>
</CollapserGroup>

### Paramètres de configuration [#secured-configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration utilisés dans les snippets ci-dessus :

| paramètres                     | Description                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `endpoint`                     | L’URL de votre cluster Elasticsearch. Utilisez `https://` pour un cluster sécurisé.                             |
| `username`                     | Un utilisateur Elasticsearch avec le privilège de cluster `monitor` ou `manage`.                                |
| `password`                     | Le mot de passe de cet utilisateur.                                                                             |
| `tls.insecure_skip_verify`     | Indique s’il faut vérifier le certificat TLS d’Elasticsearch. Définir sur `false` pour activer la vérification. |
| `collection_interval`          | L&apos;intervalle entre les collectes de métriques. Par défaut : `15s`.                                         |
| `rule` (Kubernetes uniquement) | La règle de correspondance de pod utilisée pour la découverte automatique.                                      |

## Collecter les métriques de l’hôte [#host-metrics]

Pour collecter les métriques de l&apos;hôte, ajoutez le Récepteur `hostmetrics` :

<CollapserGroup>
<Collapser id="host-metrics-nrdot" title="NRDOT">
```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization: { enabled: true }
          system.cpu.time: { enabled: true }
      load:
        metrics:
          system.cpu.load_average.1m: { enabled: true }
          system.cpu.load_average.5m: { enabled: true }
          system.cpu.load_average.15m: { enabled: true }
      memory:
        metrics:
          system.memory.usage: { enabled: true }
          system.memory.utilization: { enabled: true }
      disk:
        metrics:
          system.disk.io: { enabled: true }
          system.disk.operations: { enabled: true }
      filesystem:
        metrics:
          system.filesystem.usage: { enabled: true }
          system.filesystem.utilization: { enabled: true }
      network:
        metrics:
          system.network.io: { enabled: true }
          system.network.packets: { enabled: true }
      process:
        metrics:
          process.cpu.utilization:
            enabled: true
```

Et ajoutez aux pipelines de service :

```yaml
service:
  pipelines:
    metrics/host:
      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="host-metrics-otel" title="Collecteur OTel Contrib">

### Paramètres de configuration [#host-metrics-configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration utilisés dans les snippets ci-dessus :

| paramètres            | Description                                                                                                                                                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `collection_interval` | L&apos;intervalle entre les collectes de métriques d&apos;hôte. Par défaut : `60s`.                                                                                                                                                 |
| `scrapers`            | Les catégories de métriques au niveau de l&apos;hôte à collecter (`cpu`, `load`, `memory`, `disk`, `filesystem`, `network`, `process`). Désactivez toute métrique dont vous n&apos;avez pas besoin en définissant `enabled: false`. |

## Collecter les log Elasticsearch [#logs]

### Exigences [#logs-requirements]

* Accès en lecture à vos fichiers de log Elasticsearch, pour le compte qui exécute le service du collecteur :

  * Hôte Linux : autorisation de lecture sur `/var/log/elasticsearch/`
  * Docker : autorisation de lecture sur `/var/lib/docker/containers/` (root, ou appartenance au groupe Docker)

Pour collecter les logs Elasticsearch, ajoutez le Récepteur `filelog`.

<CollapserGroup>
<Collapser id="logs-nrdot" title="NRDOT">
Assurez-vous que le compte exécutant le service du collecteur (`nrdot-collector`) dispose d&apos;un accès en lecture à vos fichiers de log Elasticsearch.

**Si Elasticsearch s’exécute sur un hôte Linux, utilisez cette configuration :**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Si Elasticsearch s’exécute dans Docker, utilisez cette configuration :**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

Et ajoutez aux pipelines de service :

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="logs-otel" title="Collecteur OTel Contrib">
Assurez-vous que le compte exécutant le service du collecteur (`otelcol-contrib`) dispose d&apos;un accès en lecture à vos fichiers de log Elasticsearch.

**Si Elasticsearch s’exécute sur un hôte Linux, utilisez cette configuration :**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Si Elasticsearch s’exécute dans Docker, utilisez cette configuration :**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

Et ajoutez aux pipelines de service :

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### Paramètres de configuration [#logs-configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration utilisés dans les snippets ci-dessus :

| paramètres                      | Description                                                                                                                 |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `include`                       | Chemins des fichiers de log à lire en continu (hôte Linux) ou chemins des log de conteneur (Docker).                        |
| `operators` (Docker uniquement) | L&apos;opérateur qui déplace la ligne de log de `attributes.log` vers `body` afin qu&apos;elle s&apos;affiche correctement. |

## Ajouter des tag de métadonnées personnalisés [#custom-tags]

Pour ajouter des tag de métadonnées personnalisés à vos métriques, utilisez le Processeur `resource/static_override` :

<CollapserGroup>
<Collapser id="custom-tags-nrdot" title="NRDOT">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="custom-tags-otel" title="Collecteur OTel Contrib">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### Paramètres de configuration [#custom-tags-configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration utilisés dans les snippets ci-dessus :

| paramètres | Description                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| `key`      | Le nom de l’attribut à ajouter, par ex. `env`.                                                                           |
| `value`    | La valeur de l&apos;attribut, par ex. `production`.                                                                      |
| `action`   | L&apos;action à appliquer. Définissez sur `upsert` pour ajouter l&apos;attribut ou l&apos;écraser s&apos;il existe déjà. |

## Redémarrez le collecteur [#restart]

Après avoir mis à jour votre configuration, redémarrez le collecteur pour appliquer les modifications.

<CollapserGroup>
<Collapser id="restart-nrdot" title="NRDOT (auto-hébergé)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Collapser>

<Collapser id="restart-otel" title="OTel Collector Contrib (auto-hébergé)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```
</Collapser>

<Collapser id="restart-k8s" title="Kubernetes (NRDOT ou Collecteur Otel Contrib)">
Pour une installation par manifeste, redémarrez le déploiement :

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```

Pour une installation Helm, réexécutez la même commande `helm upgrade --install ... -f values.yaml` de votre étape d&apos;installation pour déployer la configuration mise à jour.
</Collapser>
</CollapserGroup>

## Vérifiez vos modifications [#verify]

Après avoir redémarré le collecteur, confirmez que votre modification a pris effet :

* **Cluster sécurisé**: relancez la requête de collecte de données de votre page d&apos;installation. Si les métriques circulent sans erreur TLS ou d&apos;authentification dans les log du collecteur, la connexion sécurisée fonctionne.

* **Métriques de l&apos;hôte**: exécutez cette requête :

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'system.%' SINCE 10 minutes ago
  ```

* **Logs Elasticsearch**: exécutez cette requête :

  ```sql
  FROM Log SELECT count(*) SINCE 10 minutes ago
  ```

  Ajustez la clause `WHERE` pour correspondre à vos propres attributs de log.

* **Tag personnalisés**: exécutez cette requête, en utilisant le tag d&apos;exemple de [Ajouter des tag de métadonnées personnalisés](#custom-tags):

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'elasticsearch.%' AND env = 'production' SINCE 10 minutes ago
  ```

Si vous ne voyez pas de données d&apos;ici -5 minutes, consultez le [dépannage d&apos;Elasticsearch](/docs/opentelemetry/integrations/elasticsearch/troubleshooting).
