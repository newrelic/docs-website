L’intégration Elasticsearch de New Relic utilise l’OpenTelemetry Collector pour monitorer vos clusters Elasticsearch via un pipeline unique, et sans fournisseur associé, afin que vous n’ayez pas à maintenir des agents, ou des exportateurs distincts pour les métriques, et les log. Une fois connecté, vous pouvez déterminer si un cluster est sain, détecter les problèmes avant qu’ils ne provoquent une panne, et corréler ce que vous voyez dans Elasticsearch avec le reste de votre stack dans New Relic.

## Capacités [#capabilities]

* **Métriques**: santé du cluster, distribution des fragments, performances des nœuds, et de la JVM, et utilisation des ressources de l’hôte (processeur, mémoire, disque, réseau)
* **Log**: log du serveur Elasticsearch, corrélés avec le même cluster, et les mêmes métadonnées de nœud que vos métriques
* **Tracing distribué**: corrélez vos applications APM avec le cluster Elasticsearch qu’elles appellent, en utilisant les traces OpenTelemetry natives d’Elasticsearch. Consultez [Corréler l’APM avec Elasticsearch en utilisant le tracing distribué](/docs/opentelemetry/integrations/elasticsearch/distributed-tracing).

## Choisissez votre chemin d&apos;installation [#choose]

**Auto-hébergé**: pour Elasticsearch s’exécutant directement sur des serveurs, ou des machines virtuelles.

* **NRDOT** (recommandé) : la distribution New Relic de l&apos;OpenTelemetry Collector ; la voie la plus directe si vous n&apos;avez aucun collecteur existant.
* **OTel Collector Contrib**: la distribution communautaire de l’OpenTelemetry Collector ; choisissez-la si votre environnement se standardise déjà sur celle-ci.
* **Récepteur Prometheus**: choisissez ceci uniquement si vous exécutez déjà un [exportateur Elasticsearch Prometheus](https://github.com/prometheus-community/elasticsearch_exporter), et souhaitez le réutiliser plutôt que de connecter directement un collecteur à Elasticsearch.

**Kubernetes**: pour Elasticsearch s&apos;exécutant dans un cluster Kubernetes, avec la découverte automatique des pods.

* **NRDOT** (recommandé) : la distribution par New Relic de l’OpenTelemetry Collector ; le chemin le plus direct si vous n’avez aucun collecteur existant. Choisissez [l’installation via manifeste](/docs/opentelemetry/integrations/elasticsearch/install-configure/kubernetes/nrdot-manifest-install) si vous avez déjà terminé l’installation de base du manifeste OpenTelemetry Kubernetes, ou [l’installation Helm](/docs/opentelemetry/integrations/elasticsearch/install-configure/kubernetes/nrdot-helm-install) pour un déploiement plus simple en une seule commande.
* **OTel Collector Contrib**: la distribution communautaire de l’OpenTelemetry Collector ; choisissez-la si votre environnement se standardise déjà sur celle-ci.
* **Récepteur Prometheus**: même condition que ci-dessus : uniquement si vous exécutez déjà l&apos;exportateur dans le cluster.

## Installation guidée [#ui-install]

Pour installer ceci via l&apos;UI de New Relic à la place, accédez à <DNT>**[one.newrelic.com](https://onenr.io/0qwyANKOOwn) &gt; Integrations &amp; Agents &gt; Elasticsearch (OpenTelemetry Collector)**</DNT>. Suivez les instructions à l&apos;écran pour configurer l&apos;intégration.

## Installation en un coup d&apos;œil [#at-a-glance]

1. Vérifier la compatibilité et rassembler les prérequis
2. Configurez le collecteur
3. Appliquer la configuration minimale
4. Redémarrez le collecteur
5. Vérifier que les données sont transmises à New Relic
