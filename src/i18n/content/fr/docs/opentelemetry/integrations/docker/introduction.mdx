L’intégration Docker OpenTelemetry monitore la santé et les performances de vos applications conteneurisées en collectant des métriques en temps réel directement depuis le Docker Engine. Vous obtenez une visibilité sur l’utilisation du CPU, la mémoire, les I/O réseau, et les I/O disque pour chaque conteneur en cours d’exécution, afin de pouvoir détecter les goulots d’étranglement des ressources et les défaillances des conteneurs avant qu’ils n’affectent vos services.

## Capacités [#capabilities]

Cette intégration fournit :

* **Métriques**: usage et utilisation du processeur, utilisation de la mémoire et pourcentage, I/O réseau (octets et paquets envoyés et reçus, rejets, et erreurs), I/O bloc, et nombre de processus (PID)
* **Entités**: les conteneurs Docker apparaissent comme des entités monitorées dans New Relic, liées à leur hôte
* **Logs**: collectez les logs de vos conteneurs. Pour les étapes de configuration, consultez [Configuration avancée](/docs/opentelemetry/integrations/docker/advanced-configuration#logs).

## Choisissez votre chemin d&apos;installation [#choose]

* **[NRDOT Collector](/docs/opentelemetry/integrations/docker/install-nrdot) (recommandé)**: la distribution OpenTelemetry de New Relic, préconfigurée pour envoyer des données à New Relic. Utilisez ceci si vous n’exécutez pas déjà un autre OpenTelemetry Collector.
* **[OpenTelemetry Collector Contrib](/docs/opentelemetry/integrations/docker/install-otelcol-contrib)**: le collecteur communautaire en amont. Utilisez ceci si vous exécutez déjà OpenTelemetry Collector Contrib pour d&apos;autres workloads et souhaitez ajouter le monitoring de Docker à la même instance.

## Installation en un coup d&apos;œil [#at-a-glance]

La page d&apos;installation vous guide dans les étapes suivantes :

1. Vérifier la compatibilité et rassembler les prérequis
2. Installez le collecteur de votre choix
3. Configurer les permissions du socket Docker
4. Configurer le collecteur
5. Redémarrez le collecteur
6. Vérifier que les données sont transmises à New Relic
