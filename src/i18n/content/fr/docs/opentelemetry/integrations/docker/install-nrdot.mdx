Cette page installe le Collector NRDOT sur un hôte Linux, le configure pour collecter les métriques de conteneurs Docker, et vérifie que les données parviennent à New Relic.

## Compatibilité et exigences [#requirements]

### Soutenu

* API Docker Engine version 1.25 ou ultérieure

### Vous avez besoin de

* Une [clé de licence](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)New Relic valide
* Accès au socket Docker (généralement `/var/run/docker.sock`)
* Accès réseau de l’hôte au socket Docker Engine et à un [point de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/#configure-endpoint-port-protocol)
* Droits de lecture sur `/var/lib/docker/containers/` pour la collecte de logs (généralement l&apos;appartenance au groupe root ou Docker)

<Steps>
<Step>
## Installer le collecteur NRDOT [#install]

<Callout variant="tip">
Si NRDOT Collector est déjà installé, ignorez cette étape et passez à [Configurer les permissions du socket Docker](#permissions).
</Callout>

<CollapserGroup>
<Collapser id="install-deb" title="Debian/Ubuntu">
Cette installation vous permet de télécharger et d’installer le collecteur en tant que package DEB (le format de package natif de Debian), puis de désactiver le démarrage automatique jusqu’à ce que la configuration soit terminée :

```bash
# Example version - check releases for latest: https://github.com/newrelic/nrdot-collector-releases/releases
export collector_version="1.10.0"
export collector_arch="amd64"  # or arm64

curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${collector_version}/nrdot-collector_${collector_version}_linux_${collector_arch}.deb" -o collector.deb
sudo dpkg -i collector.deb

# Disable auto-start until configuration is complete
sudo systemctl disable nrdot-collector
sudo systemctl stop nrdot-collector
```
</Collapser>

<Collapser id="install-rpm" title="RHEL/CentOS/Fedora">
Cette installation vous permet de télécharger et d’installer le collecteur en tant que package RPM (le format de package natif de Red Hat), puis de désactiver le démarrage automatique jusqu’à ce que la configuration soit terminée :

```bash
# Example version - check releases for latest: https://github.com/newrelic/nrdot-collector-releases/releases
export collector_version="1.10.0"
export collector_arch="x86_64"  # or arm64

curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${collector_version}/nrdot-collector_${collector_version}_linux_${collector_arch}.rpm" -o collector.rpm

# Disable auto-start until configuration is complete
sudo systemctl disable nrdot-collector
sudo systemctl stop nrdot-collector
```
</Collapser>
</CollapserGroup>

**Autres distributions Linux**: Pour les installations par archive ou d&apos;autres méthodes, consultez le [guide d&apos;installation NRDOT](https://github.com/newrelic/nrdot-collector-releases/blob/main/distributions/README.md#installation).
</Step>

<Step>
## Configurer les permissions du socket Docker [#permissions]

Le collecteur a besoin d&apos;accéder au socket Docker pour collecter les métriques des conteneurs. Accordez à l&apos;utilisateur du collecteur l&apos;accès au groupe Docker.

```bash
# Add nrdot-collector user to docker group
sudo usermod -aG docker nrdot-collector

# Verify the user was added
groups nrdot-collector

# Restart Docker to apply group changes
sudo systemctl restart docker

# Test Docker socket access
sudo -u nrdot-collector docker ps
```

Si la commande de test réussit et affiche vos conteneurs, vous avez configuré les permissions correctement.

Si cela indique `permission denied` au lieu de lister les conteneurs, consultez [Erreurs d’accès refusé](/docs/opentelemetry/integrations/docker/troubleshooting#permission-errors).
</Step>

<Step>
## Configurer le collecteur [#configure]

<Callout variant="important">
**Monitoring autonome vs combiné**: cette configuration monitore uniquement les conteneurs Docker. Si vous avez également besoin de métriques d&apos;hôte (CPU, mémoire, disque) ou de logs système, utilisez la [configuration par défaut](https://github.com/newrelic/nrdot-collector-releases/blob/main/distributions/nrdot-collector/config.yaml) du NRDOT Collector qui inclut les récepteurs `hostmetrics` et `filelog`, et ajoutez-y le récepteur `docker_stats`.
</Callout>

Créez `/etc/nrdot-collector/docker-stats-config.yaml` avec le contenu suivant :

```yaml

receivers:
  # Docker Stats Receiver - collects container metrics
  docker_stats:
    endpoint: unix:///var/run/docker.sock
    collection_interval: 15s
    timeout: 5s
    api_version: "1.25"
    # Most metrics required for New Relic UI are enabled by default:
    # CPU: container.cpu.usage.total, container.cpu.utilization
    # Memory: container.memory.usage.total, container.memory.percent
    # Network: container.network.io.usage.tx_bytes, container.network.io.usage.rx_bytes
    #          container.network.io.usage.tx_dropped, container.network.io.usage.rx_dropped
    # Storage: container.blockio.io_service_bytes_recursive
    #
    # The following metrics need to be explicitly enabled:
    metrics:
      # Required for New Relic UI
      container.pids.count:
        enabled: true
      # Additional network error metrics
      container.network.io.usage.tx_errors:
        enabled: true
      container.network.io.usage.rx_errors:
        enabled: true

processors:
  # Batch processor optimizes data transmission
  batch:
    timeout: 10s
    send_batch_size: 1024

  # Transform processor - removes descriptions and units
  transform:
    metric_statements:
      - context: metric
        statements:
          - set(description, "")
          - set(unit, "")
exporters:
  otlp_http:
    endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT:-https://otlp.nr-data.net}
    headers:
      api-key: ${env:NEW_RELIC_LICENSE_KEY}
    compression: gzip

service:
  pipelines:
    metrics/docker:
      receivers: [docker_stats]
      processors: [transform, batch]
      exporters: [otlp_http]

```

### Paramètres de configuration [#configuration-parameters]

Le tableau suivant décrit les principaux paramètres de configuration du récepteur et de l’exportateur `docker_stats` :

| paramètres                    | Description                                                                                                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint` (`docker_stats`)   | Saisissez le chemin d’accès au socket Docker auquel le collecteur se connecte. Par défaut : `unix:///var/run/docker.sock`                                                         |
| `collection_interval`         | Définissez la fréquence à laquelle le collecteur récupère les statistiques des conteneurs. Par défaut : `15s`                                                                     |
| `timeout`                     | Définissez la durée pendant laquelle le collecteur attend que l’API Docker Engine réponde avant d’abandonner. Par défaut : `5s`                                                   |
| `api_version`                 | Saisissez la version de l’API Docker Engine que votre hôte prend en charge. Par défaut : `1.25`                                                                                   |
| `NEW_RELIC_LICENSE_KEY`       | Entrez votre clé de licence New Relic.                                                                                                                                            |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Saisissez le point de terminaison OTLP New Relic pour votre région. Consultez les [points de terminaison OTLP New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/). |

<Callout variant="tip">
En option, vous pouvez également collecter les logs de vos conteneurs. Pour les étapes de configuration, consultez [Configuration avancée](/docs/opentelemetry/integrations/docker/advanced-configuration#logs).
</Callout>

**Configurer le service systemd :**

Vous allez maintenant configurer le service NRDOT Collector pour utiliser votre configuration de supervision Docker et vos identifiants d&apos;authentification. Cela implique de créer une surcharge systemd pour spécifier le fichier de configuration personnalisé et les variables d&apos;environnement.

1. Créer un répertoire de remplacement systemd :

   ```bash
   sudo mkdir -p /etc/systemd/system/nrdot-collector.service.d
   ```

2. Créez une configuration de surcharge pour utiliser la configuration des statistiques Docker. Remplacez `YOUR_LICENSE_KEY` par votre clé de licence New Relic et `YOUR_OTLP_ENDPOINT` par le point de terminaison approprié pour votre région :

   ```bash
   cat <<EOF | sudo tee /etc/systemd/system/nrdot-collector.service.d/override.conf
   [Service]
   Environment="NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY"
   Environment="OTEL_EXPORTER_OTLP_ENDPOINT=YOUR_OTLP_ENDPOINT"
   ExecStart=
   ExecStart=/usr/bin/nrdot-collector --config=/etc/nrdot-collector/docker-stats-config.yaml
   EOF
   ```

<Callout variant="tip">
La ligne `ExecStart=` vide efface la commande par défaut avant de définir la nouvelle. Cela garantit que le collecteur utilise uniquement la configuration des statistiques Docker au lieu de la configuration par défaut.
</Callout>
</Step>

<Step>
## Redémarrez le collecteur [#start]

Rechargez systemd, activez et redémarrez le collecteur :

```bash
sudo systemctl daemon-reload
sudo systemctl enable nrdot-collector
sudo systemctl restart nrdot-collector

# Verify the collector is running
sudo systemctl status nrdot-collector
```
</Step>

<Step>
## Vérifiez votre installation [#verify]

Dans les 5 minutes suivant la fin de l’installation, confirmez que les données parviennent à New Relic.

* Accédez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All Entities**</DNT> et recherchez par nom d’hôte ou nom de conteneur. Vos conteneurs Docker devraient apparaître en tant qu&apos;entités.
* Exécutez cette requête NRQL et confirmez qu’elle renvoie au moins 1 ligne :
  ```sql
  FROM Metric SELECT count(*) WHERE container.runtime = 'docker' SINCE 10 minutes ago
  ```

Si vous ne voyez pas de données dans les 5 minutes, consultez [Dépannage du monitoring Docker](/docs/opentelemetry/integrations/docker/troubleshooting).
</Step>
</Steps>
