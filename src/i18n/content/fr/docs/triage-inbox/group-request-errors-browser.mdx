Les appels AJAX, et fetch échoués, comme une intégration tierce défectueuse, ou une API backend renvoyant une erreur 500, provoquent souvent des pages défectueuses, et une expérience utilisateur déroutante. La page <DNT>**Request errors**</DNT> regroupe ces requests échouées, afin que vous puissiez trouver les appels d’API derrière les pages défectueuses, voir à quelle fréquence ils échouent, et savoir par où commencer le débogage.

Les erreurs de requête sont basées sur les événements [`AjaxRequest`](/attribute-dictionary/?event=AjaxRequest) que votre agent Browser collecte déjà, il n’y a donc rien à installer, ni à activer pour commencer à les utiliser.

## Afficher la page des erreurs de demande [#request-errors-page]

Pour afficher la page des erreurs de demande, accédez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Request errors**</DNT>.

## workflowrecommandé [#suggested-workflow]

Nous recommandons l&apos;approche suivante pour analyser les erreurs de requête, afin que vous puissiez comprendre l&apos;erreur, identifier les facteurs contributifs, et commencer le débogage :

1. **Consultez les tendances globales**: commencez par les graphiques <DNT>**Error count**</DNT> et <DNT>**Errors by page**</DNT> pour voir en un coup d’œil s’il y a des pics, des baisses, ou des schémas inattendus.
2. **Grouper et filtrer**: utilisez les options <DNT>**Group by**</DNT> et de filtrage pour vous concentrer sur des domaines de requête, des chemins de requête, des codes de réponse, ou des plages de codes spécifiques.
3. **Explorer une seule erreur**: sélectionnez une ligne dans le tableau des erreurs de requête pour afficher les détails complets de la requête, y compris l’URL de la requête, le code de réponse, le corps de la réponse, et plus encore.
4. **Examiner les Session Replay et le suivi des événements**: à partir d’une erreur spécifique, examinez le [suivi des événements](#event-trail) et, si disponible, le [Session Replay](#session-replay) enregistré lors de cette occurrence.
5. **Interrogez et partagez les données**: sur n’importe quel graphique, sélectionnez le menu <DNT>**…**</DNT> puis <DNT>**View query**</DNT> pour explorer les données `AjaxRequest` sous-jacentes dans le générateur de requêtes, ou ajoutez-les à un dashboard.
6. **Changer la fenêtre horaire**: Sélectionnez une nouvelle période horaire dans la liste déroulante du sélecteur d&apos;intervalle de temps.

## Demander les détails de l&apos;erreur [#error-details]

Sélectionnez une ligne dans le tableau des erreurs de demande pour ouvrir les détails de la demande sous forme de panneau empilé, affichant les informations complètes de la demande, les attributs de la demande, et le corps de la réponse pour cette erreur.

### Profils [#error-profiles]

À partir du tableau des erreurs de requests, sélectionnez <DNT>**View profiles**</DNT> pour voir quels attributs distinguent le plus ce groupe d&apos;erreurs de requests de votre autre trafic. Utilisez les profils pour repérer rapidement ce que les requests concernées ont en commun.

### suivi des événements [#event-trail]

Lorsque vous sélectionnez une erreur spécifique, le suivi des événements montre les interactions du navigateur, et les appels AJAX qui y ont conduit. Cela vous aide à comprendre ce que l’utilisateur faisait lorsque la requête a échoué, et si d’autres appels à peu près au même moment ont également été affectés.

### Session Replay [#session-replay]

Lorsqu’un Session Replay a été enregistré pour l’occurrence que vous consultez, vous pouvez l’ouvrir depuis les détails de l’erreur pour voir exactement ce que l’utilisateur a vécu lorsque la requête a échoué.

## Interroger et visualiser des données d’erreur de requête [#insights]

New Relic enregistre les données d’erreur de requête sous forme d’événements `AjaxRequest`. Interrogez le type d’événement `AjaxRequest` dans le [générateur de requêtes](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder) pour exécuter des requêtes NRQL et créer des dashboards à partir de vos données d’erreur de requête.
