<Callout title="Aperçu">
Nous travaillons encore sur cette fonctionnalité, mais nous serions ravis que vous l&apos;essayiez ! Cette fonctionnalité est actuellement proposée dans le cadre d&apos;un programme d&apos;aperçu conformément à nos [politiques de pré-sortie](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

Vous pouvez utiliser les mutations [NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/) pour gérer les [règles de normalisation des métriques](/docs/new-relic-solutions/new-relic-one/ui-data/metric-normalization-rules) dans New Relic. En exploitant ces mutations, vous pouvez créer, modifier, activer, et désactiver ces règles directement depuis votre compte New Relic. Cela offre une approche simplifiée et programmatique pour résoudre les [problèmes de regroupement de métriques (MGIs).](/docs/new-relic-solutions/solve-common-issues/troubleshooting/metric-grouping-issues)

Les règles de normalisation des métriques sont utilisées pour :

* Grouper ou filtrer les [données d’intervalle de temps métrique](/docs/data-apis/understand-data/new-relic-data-types/#timeslice-data).
* Gérez les métriques à forte cardinalité en les renommant, en les supprimant, ou en les transformant avant qu’elles ne soient ingérées dans New Relic.
* Évitez les [MGI](/docs/new-relic-solutions/solve-common-issues/troubleshooting/metric-grouping-issues) pour vous assurer que vos métriques sont bien organisées et pertinentes.
* Réduisez le nombre de noms de métriques uniques envoyés à New Relic.

## Prérequis [#prerequisites]

* Un [compte New Relic](https://newrelic.com/signup), et avec ce compte, vous pouvez accéder à votre clé d’utilisateur API que vous devez inclure avec les [requêtes et mutations](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph).

* Le type d&apos;utilisateur et les rôles attribués peuvent affecter vos autorisations NerdGraph. Pour plus de détails, voir [Facteurs affectant l’accès](/docs/accounts/accounts-billing/account-structure/factors-affecting-access-features-data#user-permissions).

<Callout variant="tip">
Vous pouvez également créer une règle de normalisation des métriques à l’aide de la plateforme New Relic. Pour plus d’informations, reportez-vous à [Règles de normalisation des métriques](/docs/new-relic-solutions/new-relic-one/ui-data/metric-normalization-rules).
</Callout>

## Récupérer les règles de normalisation des métriques [#nerdgraph-query]

Utilisez la requête `metricNormalizationRules` pour récupérer toutes les règles de normalisation de métriques associées à votre compte. Cette requête fournit un aperçu complet des règles existantes, y compris leur statut et leur configuration.

### Exemple de requête

```graphql

    {
        actor {
            user {
            name
            }
            account(id: xxxxxx) {
            metricNormalization {
                metricNormalizationRules(enabled: true) {
                action
                applicationGuid
                applicationName
                createdAt
                enabled
                evalOrder
                id
                matchExpression
                notes
                replacement
                terminateChain
                }
            }
            }
        }
    }

```

## Mutations [#nerdgraph-mutations]

Gérez vos règles de normalisation des métriques avec les [mutations NerdGraph](https://docs.newrelic.com/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology) suivantes :

<CollapserGroup>
<Collapser id="create-metric-normalization-rule" title="Créer une règle de normalisation de métrique">
Utilisez la mutation `metricNormalizationCreateRule` pour créer une nouvelle règle de normalisation des métriques dans New Relic.

<table>
<thead>
<tr>
<th>
Nom de l&apos;attribut
</th>

<th>
Type de données

</th>

</thead>

<tr>
<td>
accountId
</td>

<td>
Chaîne
</td>

<td>
(Requis) L’ID de compte associé à la règle.
</td>
</tr>

<tr>
<td>
action
</td>

<td>
Chaîne
</td>

<td>
(Requis) Sélectionnez l&apos;une des actions suivantes :

* `REPLACE`: remplacer les métriques qui correspondent à `matchExpression` par la valeur définie dans le champ `replacement`.
* `IGNORE`: bloquez l&apos;envoi vers New Relic de toutes les métriques qui correspondent à `matchExpression`.
* `DENY_NEW_METRICS`: empêchez la création de nouveaux noms de métriques qui correspondent à `matchExpression`, tout en permettant aux noms de métriques existants de continuer à être rapportés.
</td>
</tr>

<tr>
<td>
applicationGuid
</td>

<td>
Chaîne
</td>

<td>
(Facultatif) Le GUID unique pour l’application dans New Relic. Si laissé vide, cela devient une règle à l’échelle du compte.
</td>
</tr>

<tr>
<td>
enabled
</td>

<td>
Booléen
</td>

<td>
(Requis) Pour activer la règle, définissez sur `true`.
</td>
</tr>

<tr>
<td>
evalOrder
</td>

<td>
Entier
</td>

<td>
(Requis) Spécifiez l&apos;ordre dans lequel la règle est appliquée par rapport aux autres règles. Plus le nombre est bas, plus la priorité évaluée est élevée. La valeur recommandée est `2000`.
</td>
</tr>

<tr>
<td>
matchExpression
</td>

<td>
Chaîne
</td>

<td>
(Requis) Accepte un motif d’ [expression régulière](https://regexone.com/) correspondant aux métriques à normaliser. Ce champ doit commencer par un `^`, et se terminer par un `$`. Il définit un motif pour identifier les métriques qui doivent être affectées par la règle de normalisation. Par exemple : `^WebTransaction/Uri/RESTfulExample/users/username/[a-zA-Z0-9]+$` Le motif `^[a-zA-Z0-9]+$` correspond à toute chaîne composée de caractères minuscules `(a-z)`, de caractères majuscules `(A-Z)`, et de chiffres `(0-9)`.
</td>
</tr>

<tr>
<td>
notes
</td>

<td>
Chaîne
</td>

<td>
Notes ou commentaires supplémentaires concernant la règle de normalisation.
</td>
</tr>

<tr>
<td>
remplacement
</td>

<td>
Chaîne
</td>

<td>
Ce champ est uniquement requis lorsque l’option `REPLACE` est sélectionnée dans la liste déroulante `action`. Il remplace tout nom de métrique qui correspond à `matchExpression`. Par exemple : `WebTransaction/Uri/RESTfulExample/users/username/{username}$`
</td>
</tr>

<tr>
<td>
terminateChain
</td>

<td>
Booléen
</td>

<td>
(Requis) Si défini sur `true`, aucune autre règle ne s&apos;appliquera aux métriques correspondantes.
</td>
</tr>
</tbody>
</table>

### Exemple de requête

```graphql

    mutation {
        metricNormalizationCreateRule(
            accountId: xxxxxx
            rule: {action: REPLACE, applicationGuid: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx", enabled: false, evalOrder: 2000, matchExpression: "^WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/[a-f0-9]+$", notes: "rules to replace", replacement: "WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/{guid}", terminateChain: true}
        ) {
            errors {
                message
                type
            }
            rule {
                action
                applicationGuid
                applicationName
                createdAt
                enabled
                evalOrder
                id
                matchExpression
                notes
                replacement
                terminateChain
            }
        }
    }

```

```graphql
                    "evalOrder": 2000,
                    "id": 29205,
                    "matchExpression": "^WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/[a-f0-9]+$",
                    "notes": "rules to replace",
                    "replacement": "WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/{guid}",
                    "terminateChain": true
                }
            }
        }
    }

```
