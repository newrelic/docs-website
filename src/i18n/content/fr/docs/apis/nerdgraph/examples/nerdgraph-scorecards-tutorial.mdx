New Relic vous permet d&apos;utiliser les mutations GraphQL [des cartes de score](/docs/service-architecture-intelligence/scorecards/getting-started) NerdGraph pour gérer les cartes de score et les règles. Ces mutations vous permettent de créer, mettre à jour, supprimer et récupérer des dashboards et leurs règles associées dans votre workflow et votre intégration existants.

Ce tutoriel fournit des exemples d&apos;utilisation de NerdGraph pour gérer les Scorecards et les règles. Vous pouvez utiliser ces exemples pour automatiser les tâches de gestion des cartes de score, telles que la création de cartes de score, l&apos;ajout de règles et la mise à jour des détails des cartes de score. Si vous devez configurer des autorisations personnalisées pour gérer les tableaux de bord (Scorecards), consultez [Créer des rôles personnalisés pour les tableaux de bord (Scorecards)](/docs/apis/nerdgraph/examples/nerdgraph-scorecards-custom-tutorial).

## Mutations [#mutations]

New Relic fournit diverses mutations NerdGraph pour créer et gérer des dashboards et des règles associées.

Vous pouvez également organiser les règles d&apos;une Scorecard en [niveaux de maturité](/docs/service-architecture-intelligence/scorecards/service-maturity) et attribuer un poids à chaque règle. Dans l&apos;API, les niveaux de maturité sont appelés <DNT>**progress levels**</DNT>:

* Une Scorecard définit ses niveaux de maturité avec le champ `progressLevels`. La création de niveaux personnalisés (non par défaut) est uniquement disponible via l&apos;API, voir [Créer ou mettre à jour les niveaux de maturité](#maturity-levels).
* Une règle est assignée à un niveau avec le champ `progressLevel`, qui prend le `id` de l&apos;un des niveaux de progression du Scorecard.
* Le poids d&apos;une règle dans le score moyen pondéré de la Scorecard est défini avec le champ `impactWeight`. Pour savoir comment fonctionne la pondération, voir [score pondéré](/docs/service-architecture-intelligence/scorecards/service-maturity#weighted-scoring).

  <Collapser id="maturity-levels" title="Créer ou mettre à jour les niveaux de maturité">
    Les niveaux de maturité sont définis par le `progressLevels` d&apos;une Scorecard. Définissez-les lorsque vous [créez une Scorecard](#create-scorecard), ou mettez-les à jour ultérieurement à l&apos;aide de la mutation `entityManagementUpdateScorecard`.

    L&apos;API est le seul moyen de créer des niveaux personnalisés (comme l&apos;ajout d&apos;un 4e niveau ou le renommage de ceux par défaut) car l&apos;interface utilisateur ne prend en charge que les 3 par défaut.

    **Pour ajouter un nouveau niveau de maturité à une scorecard existante :**

    1. Exécutez la [requête de lecture de Scorecard](#fetch-scorecards) pour obtenir vos niveaux actuels.
    2. Appelez la mutation `entityManagementUpdateScorecard` avec l&apos;éventail `progressLevels` *complet*. Assurez-vous d&apos;inclure les niveaux existants que vous souhaitez conserver, ainsi que le nouveau.

    <Callout variant="important">
      La mutation de mise à jour remplace l’ensemble des niveaux de la carte de score. Tout niveau que vous excluez de l’éventail est définitivement supprimé.
    </Callout>

    Gardez à l’esprit :

    * **Limites :** un scorecard peut avoir de 1 à 5 niveaux.
    * **Hiérarchie :** l&apos;ordre de l&apos;éventail définit leur hiérarchie, de la maturité la plus faible à la plus élevée.

    Chaque élément de l&apos;éventail `progressLevels` accepte les champs suivants.

    ```graphql
      $progressLevel: ID
      $impactWeight: Int
      $runInterval: Int

        scorecardRuleEntity: {
          name: $name
          description: $description
          enabled: true
          progressLevel: $progressLevel
          impactWeight: $impactWeight
          runInterval: $runInterval
          nrqlEngine: {
            accounts: $accounts
            joinAccounts: $joinAccounts
            query: $query
          }
          scope: { id: $organizationId, type: ORGANIZATION }
        }
      ) {
        entity {
          id # RULE Id
        }
      }
    }
    ```

    ```json
    // PARAMETERS

      "accounts": [1, 2, 3],
    ```
