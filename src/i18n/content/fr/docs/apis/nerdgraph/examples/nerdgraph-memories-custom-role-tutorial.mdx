<DNT>Autopilot</DNT> La mémoire permet à <DNT>Autopilot</DNT> de conserver le contexte d&apos;une conversation à l&apos;autre et de contrôler qui peut lire, créer, mettre à jour ou supprimer ce contexte stocké.

## Accès par défaut à la mémoire [#default-access]

New Relic fournit un accès par défaut à la mémoire via ces rôles standards :

### Accès au niveau du compte

      </td>

    </tr>

    <tr>
      <td>

      </td>

      <td>

      </td>

      </td>
    </tr>

Vous pourriez avoir besoin d&apos;un rôle personnalisé si les permissions par défaut ne répondent pas aux besoins de votre organisation.

## Prérequis [#prerequisites]

Avant de commencer, assurez-vous d’avoir :

* [Exigences générales de NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#authentication)
* Rôle de gestionnaire d&apos;organisation, pour créer des rôles personnalisés

<Callout variant="tip">
  Vous pouvez également [créer un rôle personnalisé pour la mémoire via l&apos;UI](/docs/accounts/accounts-billing/new-relic-one-user-management/account-user-mgmt-tutorial/#roles). Pour les permissions à sélectionner et la portée à utiliser, consultez [Capacités de la mémoire](#capabilities).
</Callout>

## Créer un rôle personnalisé via l&apos;API NerdGraph [#create-role]

Chacun des appels d’API suivants gère une partie de la création et de l’attribution d’un rôle personnalisé pour la mémoire. Développez chacun d’eux pour voir ses paramètres d’entrée ainsi qu’un exemple de requête et de réponse.

<CollapserGroup>
  <Collapser id="find-permission-ids" title="Rechercher les identifiants d'autorisation requis pour la mémoire">
    Utilisez la requête `customerAdministration` pour récupérer une liste de capacités, leurs ID d’autorisation et les informations associées. Filtrez par fonctionnalité pour obtenir les autorisations de mémoire.

    **Paramètres d&apos;entrée**

    <table>
      <thead>
        <tr>
          <th>
            paramètres
          </th>

          <th>
            Type de données
          </th>

          <th>
            Description
          </th>
        </tr>
      </thead>

      <tbody>
        <tr>
          <td>
            `eq`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            Définissez la valeur sur 

            `Memory`

             (au niveau du compte) ou 

            `Memory For Organization`

             (au niveau de l&apos;organisation) pour récupérer les autorisations correspondantes.
          </td>
        </tr>
      </tbody>
    </table>

    **Exemple de requête — au niveau du compte**

    ```graphql
    {
      customerAdministration {
        permissions(filter: { feature: { eq: "Memory" } }) {
          items {
            feature
            category
            id
            product
          }
        }
      }
    }
    ```

    **Exemple de réponse**

    ```json
    {
      "data": {
        "customerAdministration": {
          "permissions": {
            "items": [
              {
                "category": "READ",
                "feature": "Memory",
                "id": "xxxxx",
                "product": "New Relic AI"
              },
              {
                "category": "MODIFY",
                "feature": "Memory",
                "id": "xxxxxx",
                "product": "New Relic AI"
              },
              {
                "category": "DELETE",
                "feature": "Memory",
                "id": "xxxxxx",
                "product": "New Relic AI"
              }
            ]
          }
        }
      }
    }
    ```

    Exécutez la même requête avec `feature: { eq: "Memory For Organization" }` pour récupérer les identifiants d&apos;autorisation au niveau de l&apos;organisation (READ, MODIFY, DELETE pour la mémoire pour l&apos;organisation).

    À partir de la réponse, copiez les ID de permission où `feature` est `Memory` ou `Memory For Organization`, correspondant au niveau d’accès que vous souhaitez accorder. Vous aurez besoin de ces ID pour créer le rôle personnalisé.
  </Collapser>

  <Collapser id="retrieve-organization-id" title="Récupérez votre identifiant d'organisation">
    Récupérez l’ID de votre organisation, que vous utiliserez dans les mutations ultérieures. Pour un rôle au niveau du compte, récupérez également l’ID du compte.

    **Demande d&apos;échantillon**

    ```graphql
    {
      actor {
        organization {
          id
        }
        accounts {
          id
          name
        }
      }
    }
    ```

    **Exemple de réponse**

    ```json
    {
      "data": {
        "actor": {
          "organization": {
            "id": "YOUR_ORGANIZATION_ID"
          },
          "accounts": [
            {
              "id": "YOUR_ACCOUNT_ID",
              "name": "Your Account Name"
            }
          ]
        }
      }
    }
    ```

    Copiez le ou les ID dont vous avez besoin à partir de la réponse. Vous les utiliserez pour créer le rôle personnalisé.
  </Collapser>

  <Collapser id="create-custom-role" title="Créer le rôle personnalisé">
    Utilisez la mutation `customRoleCreate` pour créer votre rôle personnalisé pour la gestion de la mémoire.

    **Paramètres d&apos;entrée**

    <table>
      <thead>
        <tr>
          <th>
            paramètres
          </th>

          <th>
            Type de données
          </th>

          <th>
            Description
          </th>
        </tr>
      </thead>

      <tbody>
        <tr>
          <td>
            `id`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            L&apos;ID de l&apos;organisation (au niveau de l&apos;organisation) ou l&apos;ID du compte (au niveau du compte) de l&apos;appel précédent.
          </td>
        </tr>

        <tr>
          <td>
            `type`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            Définissez sur 

            `organization`

             pour un rôle au niveau de l’organisation, ou sur 

            `account`

             pour un rôle au niveau du compte.
          </td>
        </tr>

        <tr>
          <td>
            `name`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            Le nom d&apos;affichage du rôle personnalisé.
          </td>
        </tr>

        <tr>
          <td>
            `permissionIds`

             (Requis)
          </td>

          <td>
            Éventail d&apos;entiers
          </td>

          <td>
            Les ID d’autorisation de mémoire identifiés ci-dessus.
          </td>
        </tr>

        <tr>
          <td>
            `scope`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            Définissez sur 

            `organization`

             ou 

            `account`

            , correspondant à 

            `type`

            .
          </td>
        </tr>
      </tbody>
    </table>

    **Exemple de requête — rôle au niveau du compte**

    ```graphql
    mutation {
      customRoleCreate(
        container: { id: "YOUR_ACCOUNT_ID", type: "account" }
        name: "Memory manager"
        permissionIds: [xxxxx, xxxxx]
        scope: "account"
      ) {
        id
      }
    }
    ```

    **Exemple de requête — rôle au niveau de l&apos;organisation**

    ```graphql
    mutation {
      customRoleCreate(
        container: { id: "YOUR_ORGANIZATION_ID", type: "organization" }
        name: "Memory manager (org-wide)"
        permissionIds: [xxxxx, xxxxx]
        scope: "organization"
      ) {
        id
      }
    }
    ```

    **Exemple de réponse**

    ```json
    {
      "data": {
        "customRoleCreate": {
          "id": 9999999
        }
      }
    }
    ```

    Enregistrez l&apos;identifiant de rôle renvoyé — vous en aurez besoin pour attribuer ce rôle à un groupe d&apos;utilisateurs.
  </Collapser>

  <Collapser id="add-role-to-group" title="Ajouter le rôle personnalisé à un groupe d'utilisateurs">
    Après avoir créé le rôle personnalisé, attribuez-le à un groupe d&apos;utilisateurs.

    **Récupérer les ID de groupe**

    Utilisez la requête `customerAdministration` pour obtenir une liste des groupes d&apos;utilisateurs disponibles.

    **Paramètres d&apos;entrée**

    <table>
      <thead>
        <tr>
          <th>
            paramètres
          </th>

          <th>
            Type de données
          </th>

          <th>
            Description
          </th>
        </tr>
      </thead>

      <tbody>
        <tr>
          <td>
            `id`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            Votre identifiant d&apos;organisation.
          </td>
        </tr>
      </tbody>
    </table>

    **Demande d&apos;échantillon**

    ```graphql
    {
      customerAdministration {
        groups(filter: { organizationId: { eq: "YOUR_ORGANIZATION_ID" } }) {
          nextCursor
          items {
            id
            name
            users {
              items {
                id
                email
              }
            }
          }
        }
      }
    }
    ```

    À partir de la réponse, copiez l’ID de groupe pour le groupe auquel vous souhaitez attribuer le rôle de mémoire.

    **Attribuer le rôle au groupe**

    Utilisez la mutation `authorizationManagementGrantAccess` pour attribuer le rôle personnalisé à un groupe d’utilisateurs.

    **Paramètres d&apos;entrée**

    <table>
      <thead>
        <tr>
          <th>
            paramètres
          </th>

          <th>
            Type de données
          </th>

          <th>
            Description
          </th>
        </tr>
      </thead>

      <tbody>
        <tr>
          <td>
            `roleId`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            L’ID du rôle personnalisé de l’appel précédent.
          </td>
        </tr>

        <tr>
          <td>
            `groupId`

             (Requis)
          </td>

          <td>
            Chaîne
          </td>

          <td>
            L&apos;ID du groupe récupéré ci-dessus.
          </td>
        </tr>
      </tbody>
    </table>

    **Exemple de requête — rôle au niveau du compte**

    ```graphql
    mutation {
      authorizationManagementGrantAccess(
        grantAccessOptions: {
          accountAccessGrants: { accountId: "YOUR_ACCOUNT_ID", roleId: "YOUR_ROLE_ID" }
        }
        groupId: "YOUR_GROUP_ID"
      ) {
        roles {
          id
          name
          accountId
          roleId
          groupId
          displayName
        }
      }
    }
    ```

    **Exemple de requête — rôle au niveau de l&apos;organisation**

    ```graphql
    mutation {
      authorizationManagementGrantAccess(
        grantAccessOptions: {
          organizationAccessGrants: { roleId: "YOUR_ROLE_ID" }
        }
        groupId: "YOUR_GROUP_ID"
      ) {
        roles {
          id
          name
          organizationId
          roleId
          groupId
          displayName
        }
      }
    }
    ```

    **Exemple de réponse**

    ```json
    {
      "data": {
        "authorizationManagementGrantAccess": {
          "roles": [
            {
              "displayName": "Memory manager",
              "groupId": null,
              "id": "99999999",
              "name": "memory_manager",
              "organizationId": "YOUR_ORGANIZATION_ID",
              "roleId": 99999
            }
          ]
        }
      }
    }
    ```
  </Collapser>
</CollapserGroup>
