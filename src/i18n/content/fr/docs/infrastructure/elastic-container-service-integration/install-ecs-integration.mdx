L&apos;intégration ECS de New Relic génère des rapports et affiche les données de performances de votre environnement Amazon ECS.

## Présentation de l&apos;installation [#overview]

Avant d&apos;[installer](#install-options), il peut vous être utile de comprendre à un niveau élevé comment notre agent infrastructure (`newrelic-infra`) est déployé pour ces deux types de lancement :

* <DNT>**EC2 and EXTERNAL (ECS Anywhere) launch type:**</DNT> La stratégie de planification de daemon déploie notre agent sur un cluster ECS en tant que service ([expliqué ici dans la documentation AWS](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/scheduling_tasks.html)). Cela installe l&apos;agent dans toutes les instances EC2 du cluster, puis monitore ECS et les conteneurs Docker.

* <DNT>**AWS Fargate launch type:**</DNT> Dans chaque tâche à monitorer, vous déployez notre agent en tant que side-car. Vous pouvez facultativement [en apprendre davantage sur la façon dont AWS définit un side-car](https://aws.github.io/copilot-cli/docs/developing/sidecars/).

## Options d&apos;installation [#install-options]

## Installer à l&apos;aide de CloudFormation [#cloud-formation-install]

Pour vous aider à installer à l&apos;aide d&apos;AWS CloudFormation, nous fournissons des modèles CloudFormation qui installent l&apos;intégration ECS sur votre compte AWS pour les types de lancement EC2, EXTERNAL (ECS Anywhere) et AWS Fargate.

Pour installer à l&apos;aide de CloudFormation :

1. Pour enregistrer la tâche d&apos;intégration ECS, déployez [cette stack](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/task/master.yaml&stackName=NewRelicECSIntegration). Assurez-vous de déployer la stack dans une ou plusieurs des régions souhaitées. Cette stack crée les ressources suivantes :

   * Un secret qui stocke New Relic <InlinePopover type="licenseKey" />.
   * Une politique pour accéder à la clé de licence.
   * Un rôle d’instance à utiliser comme tâche ECS `ExecutionRole`, avec accès à la clé de licence.
   * Un enregistrement de la tâche d’intégration ECS de New Relic Infrastructure, pour le type de lancement EC2 et Externe (ECS Anywhere).

2. Suivez les instructions supplémentaires correspondant à votre type de lancement :

   <CollapserGroup>
     <Collapser id="ec2-cloudformation" title="Type de lancement EC2">
       Pour créer un service qui exécute la tâche sur chaque instance de conteneur EC2, déployez [cette stack](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/service.yaml&NewRelicInfraTaskVersion=1).

       Sélectionnez le type de lancement EC2. Ensuite, un service nommé `newrelic-infra` sera créé dans le cluster.
     </Collapser>

     <Collapser id="external-cloudformation" title="Type de lancement externe (ECS Anywhere)">
       Pour créer un service qui exécute la tâche sur chaque instance de conteneur externe, déployez [cette stack](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/service.yaml&NewRelicInfraTaskVersion=1).

       Sélectionnez le type de lancement EXTERNE. Ensuite, un service nommé `newrelic-infra-external` sera créé dans le cluster.
     </Collapser>

     <Collapser id="fargate-cloudformation" title="Type de lancement d'AWS Fargate">
       1. Téléchargez l&apos;exemple de définition de tâche avec le conteneur sidecar à déployer :

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
          ```

          <Callout variant="tip">
            Pour Graviton, remplacez `"cpuArchitecture": "X86_64"` par `"cpuArchitecture": "ARM64"`.
          </Callout>

       2. Ajoutez le conteneur `newrelic-infra` dans cette définition de tâche en tant que side-car aux définitions de tâches que vous souhaitez monitorer. Dans cet exemple de tâche, le conteneur de votre application remplace le conteneur espace réservé `busybox` .

       ### Configurer les modes de transfert de l&apos;agent d&apos;infrastructure pour Fargate [#fargate-forward-modes]

       Lorsque vous déployez l&apos;agent New Relic Infrastructure en tant que sidecar dans des environnements Fargate, vous devez configurer le mode de transfert de l&apos;agent. Fargate est un service de calcul sans serveur où AWS gère l&apos;infrastructure sous-jacente, l&apos;agent ne doit donc pas rapporter de métriques au niveau de l&apos;hôte ni tenter de créer des entités hôte.

       #### Recommandé : NRIA\_IS\_FORWARD\_ONLY

       Pour la plupart des déploiements Fargate, définissez `NRIA_IS_FORWARD_ONLY` sur `true`:

       ```json
       {
         "name": "NRIA_IS_FORWARD_ONLY",
         "value": "true"
       }
       ```

       **Pourquoi cela est recommandé pour Fargate :**

       * **Empêche la création inutile d&apos;entité hôte :** l&apos;agent d&apos;infrastructure ne créera pas d&apos;entité hôte dans New Relic, car Fargate est sans serveur et AWS gère les ressources de calcul sous-jacentes.
       * **Évite les écarts de facturation :** les frais de comptage basés sur les entités sont basés sur le nombre d&apos;entités monitorées. La création incorrecte d&apos;entité hôte entraîne une facturation inattendue.
       * **Permet une liaison APM-conteneur appropriée :** les applications APM sont correctement liées aux entités conteneur plutôt qu&apos;aux entités Hôte Synthétiques.
       * **Se concentre sur les données d&apos;intégration :** l&apos;agent collecte et transfère les données d&apos;intégration (bases de données, serveurs web, files d&apos;attente des messages, etc.) sans rapporter de métriques d&apos;hôte.

       #### Alternative : NRIA\_IS\_SECURE\_FORWARD\_ONLY

       Un mode de transfert alternatif est `NRIA_IS_SECURE_FORWARD_ONLY`. Définissez ceci sur `true` si vous avez besoin d&apos;une visibilité de l&apos;entité hôte dans l&apos;UI de New Relic :

       ```json
       {
         "name": "NRIA_IS_SECURE_FORWARD_ONLY",
         "value": "true"
       }
       ```

       **Différences entre les modes de transfert :**

       | Capacité                                                            | NRIA\_IS\_FORWARD\_ONLY | NRIA\_IS\_SECURE\_FORWARD\_ONLY |
       | :------------------------------------------------------------------ | :---------------------- | :------------------------------ |
       | Entité hôte visible dans NR1                                        | Non                     | Oui                             |
       | Inventaire d&apos;hôte visible dans l&apos;UI d&apos;infrastructure | Non                     | Oui                             |
       | Inventaire d&apos;intégration                                       | Non                     | Oui                             |
       | Événements d&apos;intégration transférés                            | Oui                     | Oui                             |
       | Entités d&apos;intégration (par exemple, serveur Redis)             | Non                     | Oui                             |
       | Métriques d&apos;hôte (CPU, mémoire, disque)                        | Non                     | Non                             |
       | Métadonnées de conteneur décorées                                   | Non                     | Oui                             |
       | Métadonnées d&apos;entité sur les événements d&apos;intégration     | Non                     | Partiel                         |

       **Quand utiliser chaque mode :**

       * **Utilisez `NRIA_IS_FORWARD_ONLY=true` (recommandé) si :**

         * Vous souhaitez minimiser le nombre d&apos;entités et l&apos;impact sur la facturation
         * Vous n&apos;avez besoin que du monitoring de conteneur et d&apos;intégration
         * Vous n&apos;avez pas besoin de voir l&apos;inventaire d&apos;hôte dans l&apos;UI de New Relic

       * **Utilisez `NRIA_IS_SECURE_FORWARD_ONLY=true` si :**

         * Vous avez besoin de voir les métadonnées d&apos;hôte et les informations d&apos;inventaire dans l&apos;UI de New Relic
         * Vous souhaitez que les entités d&apos;intégration apparaissent dans l&apos;UI d&apos;infrastructure
         * Le nombre d&apos;entités n&apos;est pas une préoccupation

       *Exemple de définition de tâche avec la configuration Fargate requise :*

       ```json
       {
         "family": "newrelic-infra-fargate",
         "networkMode": "awsvpc",
         "requiresCompatibilities": ["FARGATE"],
         "cpu": "256",
         "memory": "512",
         "containerDefinitions": [
           {
             "name": "newrelic-infra",
             "image": "newrelic/nri-ecs:latest",
             "essential": false,
             "environment": [
               {
                 "name": "NRIA_IS_FORWARD_ONLY",
                 "value": "true"
               },
               {
                 "name": "NRIA_LICENSE_KEY",
                 "value": "your-license-key"
               },
               {
                 "name": "NRIA_PASSTHROUGH_ENVIRONMENT",
                 "value": "ECS_CONTAINER_METADATA_URI,ECS_CONTAINER_METADATA_URI_V4,FARGATE"
               },
               {
                 "name": "FARGATE",
                 "value": "true"
               }
             ]
           },
           {
             "name": "your-application",
             "image": "your-app-image:latest",
             "essential": true
           }
         ]
       }
       ```

       <Callout variant="important">
         La variable d&apos;environnement `NRIA_IS_FORWARD_ONLY=true` est **requise** pour tous les déploiements Fargate. L&apos;omission de ce paramètre peut entraîner :

         * Création incorrecte d’entité d’hôte
         * Échecs de la relation APM-conteneur
         * Écarts de facturation dus à un nombre inattendu d’entités

         Si vous téléchargez l’exemple de définition de tâche, vérifiez que cette variable d’environnement est présente et définie sur true.
       </Callout>

       3. Enregistrez la définition de tâche :

          ```sh
          aws ecs register-task-definition --cli-input-json file://newrelic-infra-ecs-fargate-example-latest.json
          ```

       4. Créez un service ou exécutez une tâche à l&apos;aide de cette définition de tâche.
     </Collapser>
   </CollapserGroup>

Lorsque vous avez terminé, consultez [Étapes suivantes](#next-steps).

## Installer avec un script automatique [#auto-script-install]

Une [option d&apos;installation](#install-overview) consiste à utiliser notre script d&apos;installation. Pour utiliser le script d’installation automatique :

1. Téléchargez le programme d&apos;installation d&apos;intégration ECS :

   ```sh
   curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-installer.sh
   ```

2. Ajoutez des autorisations d’exécution au programme d’installation :

   ```sh
   chmod +x newrelic-infra-ecs-installer.sh
   ```

3. Exécutez-le avec `-h` pour voir la documentation et les exigences :

   ```sh
   ./newrelic-infra-ecs-installer.sh -h
   ```

4. Vérifiez que votre profil AWS pointe vers la même région où votre cluster ECS a été créé :

   ```sh
   aws configure get region
   [output] us-east-1

   aws ecs list-clusters
   [output] YOUR_CLUSTER_ARNS 	
   [output] arn:aws:ecs:us-east-1:YOUR_AWS_ACCOUNT:cluster/YOUR_CLUSTER
   ```

5. Exécutez le programme d’installation en spécifiant votre <InlinePopover type="licenseKey" />et le nom du cluster.

   <CollapserGroup>
     <Collapser id="auto-script-ec2" title="Type de lancement EC2">
       ```sh
       ./newrelic-infra-ecs-installer.sh -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY
       ```
     </Collapser>

     <Collapser id="auto-script-external" title="Type de lancement externe (ECS Anywhere)">
       ```sh
       ./newrelic-infra-ecs-installer.sh -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY -e
       ```
     </Collapser>

     <Collapser id="auto-script-fargate" title="Type de lancement d'AWS Fargate">
       ```sh
       ./newrelic-infra-ecs-installer.sh -f -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY
       ```
     </Collapser>
   </CollapserGroup>

6. Étapes supplémentaires pour le type de lancement Fargate (pas le type de lancement EC2) :

   * Téléchargez l&apos;exemple de définition de tâche avec le conteneur sidecar à déployer :

     ```sh
     curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
     ```

     <Callout variant="tip">
       Pour Graviton, remplacez `"cpuArchitecture": "X86_64"` par `"cpuArchitecture": "ARM64"`.
     </Callout>

     Notez que vous devez utiliser le rôle que vous venez de créer, `NewRelicECSTaskExecutionRole`, comme rôle d&apos;exécution de tâche.

     Ce rôle inclut les politiques suivantes pour tous les types de lancement :

     * `NewRelicSSMLicenseKeyReadAccess` qui permet d&apos;accéder au paramètre SSM avec la clé de licence.
     * `AmazonECSTaskExecutionRolePolicy`

   * Ajoutez le conteneur que vous souhaitez monitorer en tant que side-car.

   <Callout variant="important">
     Lorsque vous utilisez AWS Fargate, vous devez également vous assurer que le conteneur sidecar a la variable d&apos;environnement `NRIA_IS_FORWARD_ONLY` définie sur `true` dans votre définition de tâche. Reportez-vous aux [instructions de configuration Fargate](#fargate-isforwardonly) sous CloudFormation pour obtenir des détails sur la configuration et comprendre pourquoi ce paramètre est critique.
   </Callout>

Lorsque vous avez terminé, consultez [Étapes suivantes](#next-steps).

## Installation manuelle

Une [option d&apos;installation](#install-overview) consiste à effectuer manuellement les étapes réalisées par le [script du programme d&apos;installation automatique](#auto-script-install). Nous allons décrire comment cela est fait à l&apos;aide de l&apos;outil `awscli` :

1. Vérifiez que votre profil AWS pointe vers la même région où votre cluster ECS a été créé :

   ```sh
   aws configure get region
   [output] us-east-1

   aws ecs list-clusters
   [output] YOUR_CLUSTER_ARNS
   [output] arn:aws:ecs:us-east-1:YOUR_AWS_ACCOUNT:cluster/YOUR_CLUSTER
   ```

2. Enregistrez votre <InlinePopover type="licenseKey" />en tant que paramètre du gestionnaire de système (SSM) :

   ```sh
   aws ssm put-parameter \
     --name "/newrelic-infra/ecs/license-key" \
     --type SecureString \
     --description 'New Relic license key for ECS monitoring' \
     --value "NEW_RELIC_LICENSE_KEY"
   ```

3. Créez une politique IAM pour accéder au paramètre de clé de licence :

   ```sh
   aws iam create-policy \
     --policy-name "NewRelicSSMLicenseKeyReadAccess" \
     --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["ssm:GetParameters"],"Resource":["ARN_OF_LICENSE_KEY_PARAMETER"]}]}' \
     --description "Provides read access to the New Relic SSM license key parameter"
   ```

4. Créez un rôle IAM à utiliser comme rôle d’exécution de tâche :

   ```sh
   aws iam create-role \
     --role-name "NewRelicECSTaskExecutionRole" \
     --assume-role-policy-document '{"Version":"2008-10-17","Statement":[{"Sid":"","Effect":"Allow","Principal":{"Service":"ecs-tasks.amazonaws.com"},"Action":"sts:AssumeRole"}]}' \
     --description "ECS task execution role for New Relic infrastructure"
   ```

5. Attachez les politiques `NewRelicSSMLicenseKeyReadAccess` et `AmazonECSTaskExecutionRolePolicy` au rôle :

   ```sh
   aws iam attach-role-policy \
     --role-name "NewRelicECSTaskExecutionRole" \
     --policy-arn "POLICY_ARN"
   ```

6. Choisissez votre type de lancement pour plus d&apos;instructions :

   <CollapserGroup>
     <Collapser id="manual-ec2" title="Type de lancement EC2 et External (ECS Anywhere)">
       Étapes supplémentaires pour le type de lancement EC2 :

       1. Téléchargez le fichier de modèle de définition de tâche d&apos;intégration New Relic ECS :

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-ec2-latest.json
          ```

       2. Remplacez le rôle d’exécution de la tâche dans le fichier modèle par le rôle nouvellement créé :

          ```json
          "executionRoleArn": "NewRelicECSTaskExecutionRole",
          ```

       3. Remplacez l&apos;attribut `valueFrom` du `secret` par le nom du paramètre système Manager :

          ```json
          "secrets": [
            {
              "valueFrom": "/newrelic-infra/ecs/license-key",
              "name": "NRIA_LICENSE_KEY"
            }
          ],
          ```

       4. Enregistrer le fichier de définition de tâche :

          ```sh
          aws ecs register-task-definition --cli-input-json file://newrelic-infra-ecs-ec2-latest.json
          ```

       5. Créez un service avec la stratégie [de planification du daemon](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) pour la tâche enregistrée :

          Pour le type de lancement EC2 :

          ```sh
          aws ecs create-service --cluster "YOUR_CLUSTER_NAME" --service-name "newrelic-infra" --task-definition "newrelic-infra" --scheduling-strategy DAEMON --launch-type EC2
          ```

          Pour le type de lancement EXTERNE (ECS Anywhere) :

          ```sh
          aws ecs create-service --cluster "YOUR_CLUSTER_NAME" --service-name "newrelic-infra-external" --task-definition "newrelic-infra" --scheduling-strategy DAEMON --launch-type EXTERNAL
          ```
     </Collapser>

     <Collapser id="manual-fargate" title="Type de lancement d'AWS Fargate">
       Étapes supplémentaires pour le type de lancement AWS Fargate :

       1. Téléchargez l&apos;exemple de définition de tâche avec le conteneur sidecar à déployer :

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
          ```

          <Callout variant="tip">
            Pour Graviton, remplacez `"cpuArchitecture": "X86_64"` par `"cpuArchitecture": "ARM64"`.
          </Callout>

       2. Ajoutez le conteneur `newrelic-infra` dans cette définition de tâche en tant que side-car aux définitions de tâches que vous souhaitez monitorer. Dans cet exemple de tâche, le conteneur de votre application remplace le conteneur espace réservé `busybox` .

       <Callout variant="important">
         Assurez-vous de configurer la variable d’environnement `NRIA_IS_FORWARD_ONLY` sur `true` dans les paramètres du conteneur side-car de votre définition de tâche modifiée manuellement. Consultez la [section CloudFormation Fargate](#fargate-isforwardonly) pour obtenir des instructions détaillées et un exemple JSON complet.
       </Callout>
     </Collapser>
   </CollapserGroup>

Lorsque vous avez terminé, consultez [Étapes suivantes](#next-steps).

## Prochaines étapes après l&apos;installation [#next-steps]

Après avoir installé cette intégration :

* Attendez quelques minutes, puis [recherchez vos données dans l&apos;UI](/docs/ecs-integration-understand-use-data).
* Installez notre [intégration cloud ECS](/docs/integrations/amazon-integrations/aws-integrations-list/aws-ecsecr-monitoring-integration) recommandée, qui vous permet d&apos;obtenir d&apos;autres données ECS, y compris des informations sur les clusters et les services.
* Voir [la condition d&apos;alerte recommandée](/docs/ecs-integration-recommended-alert-conditions).
* Comprendre les [ressources AWS](#aws-resources) créées par ce processus.

## Ressources AWS créées [#aws-resources]

Lorsque vous installez l’intégration ECS à l’aide des valeurs par défaut/recommandées, elle effectue les opérations suivantes dans AWS :

* Crée le paramètre `/newrelic-infra/ecs/license-key` du système Manager (SSM). Ce paramètre système contient New Relic <InlinePopover type="licenseKey" />.

* Crée la politique IAM `NewRelicSSMLicenseKeyReadAccess`, qui permet l&apos;accès au paramètre SSM avec la clé de licence.

* Crée le rôle IAM `NewRelicECSTaskExecutionRole` utilisé comme [rôle d’exécution de tâche](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_execution_IAM_role.html). Ce rôle inclut les politiques suivantes :

  * `NewRelicSSMLicenseKeyReadAccess` (créé par le programme d&apos;installation).
  * `AmazonECSTaskExecutionRolePolicy`

* Enregistre la définition de tâche ECS `newrelic-infra` pour les types de lancement EC2 et externe (ECS Anywhere).

* Crée les éléments suivants pour le [type de lancement](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/launch_types.html) EC2 :
  * Le service `newrelic-infra` pour la tâche enregistrée, à l’aide d’une stratégie [de planification de daemon](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) et d’un type de lancement EC2.

* Crée les éléments suivants pour le [type de lancement](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/launch_types.html) EXTERNE (ECS Anywhere) :
  * Le service `newrelic-infra-external` pour la tâche enregistrée, à l&apos;aide d&apos;une stratégie [de planification de daemon](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) et d&apos;un type de lancement EXTERNAL (ECS Anywhere).
