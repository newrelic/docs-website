## Prérequis [#prerequisites]

Avant d’activer [<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360) pour <DNT>Azure</DNT>, assurez-vous d’avoir :

* Un compte <DNT>Azure</DNT> avec un ID d’abonnement.
* Une inscription d’application <DNT>Azure</DNT> avec le rôle Lecteur de monitoring.
* Un compte New Relic inscrit à la préversion <DNT>Infrastructure 360</DNT>.
* Autorisations pour gérer l’intégration cloud dans New Relic.

Pour vous inscrire à la version préliminaire, accédez à <DNT>**one.newrelic.com &gt; Administration &gt; Preview &amp; Trials**</DNT>, et inscrivez-vous à <DNT>**Infrastructure 360**</DNT>.

Il existe trois façons d’activer <DNT>Infrastructure 360</DNT> pour <DNT>Azure</DNT>:

## Activer lors de l’intégration Azure [#onboarding-enable]

Si vous connectez <DNT>Azure</DNT> à New Relic pour la première fois, suivez ces étapes :

1. Accédez à <DNT>**Infrastructure &gt; Azure**</DNT>.
2. Sélectionnez un compte et cliquez sur <DNT>**Set up integration**</DNT>.
3. Suivez les prompts pour créer l’enregistrement de votre application <DNT>Azure</DNT>. Pour des instructions de configuration détaillées, consultez [Connecter les intégrations <DNT>Azure</DNT> ](/docs/infrastructure/microsoft-azure-integrations/get-started/activate-azure-integrations).
4. Lors de la configuration de l’intégration, activez l’option <DNT>**Infrastructure 360**</DNT> lors du prompt.
5. Configurez la fréquence d&apos;analyse. Par défaut, <DNT>Infrastructure 360</DNT> effectue une analyse trois fois par jour. Pour modifier cela, consultez [Ajuster la fréquence d&apos;analyse](#adjust-frequency).

## Activer pour une intégration Azure existante [#existing-enable]

Si vous avez déjà intégré <DNT>Azure</DNT> à New Relic, suivez ces étapes :

1. Allez à <DNT>**Infrastructure &gt; Azure**</DNT> et cliquez sur <DNT>**Manage Infrastructure 360**</DNT>.
2. Dans la liste des comptes, trouvez votre abonnement <DNT>Azure</DNT>, et cliquez sur <DNT>**Install**</DNT> (au niveau du compte fournisseur).
3. Configurez la fréquence d’analyse comme décrit ci-dessus.
4. Cliquez sur <DNT>**Save**</DNT> pour activer <DNT>Infrastructure 360</DNT> pour votre compte <DNT>Azure</DNT>.

## Activer depuis la page infrastructure 360 [#landing-page-enable]

Pour activer <DNT>Infrastructure 360</DNT> depuis cette page :

1. Allez à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; Infrastructure 360**</DNT>.
2. Activez la fonctionnalité pour vos comptes fournisseurs <DNT>Azure</DNT> (et <DNT>AWS</DNT>) sous ce compte New Relic.

Si cette page est vide (vous n’avez encore activé <DNT>Infrastructure 360</DNT> pour aucun fournisseur), cliquez sur <DNT>**Setup Infrastructure 360**</DNT>, puis activez la fonctionnalité.

## Activer via Terraform [#terraform-enable]

Vous pouvez également activer <DNT>Infrastructure 360</DNT> pour <DNT>Azure</DNT> via <DNT>Terraform</DNT> au lieu de l’UI de New Relic. Il s’agit d’un guide étape par étape pour activer la découverte automatique pour les intégrations <DNT>Azure</DNT> à l’aide de <DNT>Terraform</DNT>.

### Prérequis [#terraform-prerequisites]

Avant de commencer, assurez-vous d’avoir les éléments suivants :

* **<DNT>Terraform</DNT> installé**: <DNT>Terraform</DNT> installé sur votre machine locale.
* **ID de compte New Relic**: votre ID de compte New Relic (`newrelic_account_id`).
* **Clé API utilisateur New Relic**: une clé utilisateur pour vous authentifier auprès de New Relic (`newrelic_api_key`).
* **ID du compte fournisseur lié**: l&apos;ID du compte <DNT>Azure</DNT> tel que reconnu par New Relic (`provider_account_id`). Cela se trouve souvent dans l&apos;UI de New Relic sous <DNT>**Infrastructure &gt; Azure**</DNT>.
* **Région**: votre région de données New Relic (États-Unis ou UE).

<Steps>
<Step>
### Configurez votre espace de travail [#setup-workspace]

Configurez un dossier local pour votre configuration <DNT>Terraform</DNT> :

1. Ouvrez votre terminal ou votre invite de commande.

2. Créez un nouveau dossier pour votre projet :

   ```bash
   mkdir terraform-integrate
   cd terraform-integrate
   ```
</Step>

<Step>
### Créer des fichiers de configuration [#create-config-files]

Créez les trois fichiers suivants dans votre dossier `terraform-integrate`. Vous pouvez utiliser n&apos;importe quel éditeur de texte.

#### providers.tf

Ce fichier indique à <DNT>Terraform</DNT> quels plug-ins télécharger.

```hcl
terraform {
  required_providers {
    newrelic = {
      source = "newrelic/newrelic"
    }
  }
}
```

#### variables.tf

Ce fichier définit les entrées requises pour exécuter le script.

```hcl
variable "provider_account_id" {
  description = "The Azure Subscription ID Equivalent in Newrelic (Linked Account ID)."
  type        = number
}

variable "new_relic_region" {
  description = "The New Relic region (e.g., 'US', 'EU', or 'JP')."
  type        = string
  default     = "US"
}

variable "newrelic_account_id" {
  description = "The New Relic account ID."
  type        = number
}

variable "newrelic_api_key" {
  description = "The New Relic API key."
  type        = string
}
```

#### main.tf

Il s’agit du script principal qui active la fonctionnalité de découverte automatique.

```hcl
provider "newrelic" {
  account_id = var.newrelic_account_id
  region     = var.new_relic_region
  api_key    = var.newrelic_api_key
}

resource "newrelic_cloud_azure_integrations" "auto_discovery_integrations" {
  linked_account_id = var.provider_account_id

  # This block enables auto-discovery for the account
  auto_discovery {}
}
```
</Step>

<Step>
### Exécuter Terraform [#run-terraform]

Maintenant que vos fichiers sont prêts, exécutez ces commandes dans votre terminal à partir du dossier `terraform-integrate`.

1. **Initialize**: télécharge les plug-ins nécessaires du fournisseur New Relic.

   ```bash
   terraform init
   ```

2. **Plan**: vérifie la configuration, et vous montre ce qui va se passer. <DNT>Terraform</DNT> affiche un prompt pour vous inviter à saisir vos identifiants, et clés ici.

   ```bash
   terraform plan
   ```

   Saisissez les valeurs lors du prompt pour `newrelic_account_id`, `newrelic_api_key`, et les autres variables.

3. **Appliquer**: exécute le plan et active l’intégration.

   ```bash
   terraform apply
   ```

   Tapez `yes` lorsqu’on vous demande de confirmer.
</Step>
</Steps>

Pour plus d&apos;informations, consultez la [documentation du fournisseur New Relic <DNT>Terraform</DNT> ](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#azure).

## Utiliser infrastructure 360 [#using-infrastructure-360]

Une fois activé, <DNT>Infrastructure 360</DNT> vous permet de vérifier les relations entre toutes vos entités <DNT>Azure</DNT>, y compris l’infrastructure, l’APM, et les bases de données.

<Callout title="Note">
<DNT>Infrastructure 360</DNT> prend en charge les relations d’entité via les agents New Relic APM natifs (<DNT>Java</DNT>, <DNT>.NET</DNT>, <DNT>Python</DNT>), et <DNT>OpenTelemetry</DNT> (<DNT>.NET</DNT>).

Pour les clusters <DNT>Azure Kubernetes Service</DNT> (<DNT>AKS</DNT>) spécifiquement, la connexion de votre application à son cluster <DNT>AKS</DNT> nécessite l’agent New Relic <DNT>Kubernetes</DNT>, ou <DNT>OpenTelemetry</DNT>. <DNT>Infrastructure 360</DNT> n’établit pas cette connexion de lui-même, mais une fois qu’elle existe, il complète la chaîne par la modélisation de la relation depuis votre application à travers le cluster <DNT>AKS</DNT> vers l’autre infrastructure <DNT>Azure</DNT> dont elle dépend.
</Callout>

### Afficher les entités et les relations découvertes [#view-entities]

Pour afficher les entités découvertes et leurs relations :

1. Allez dans <DNT>**All entities**</DNT>, et filtrez pour `collector.name = auto discovery`.

2. Sélectionnez n’importe quelle entité <DNT>Azure</DNT> pour voir sa carte d’infrastructure, qui montre les relations entre :

   * <DNT>Azure</DNT> entités (machines virtuelles, bases de données, comptes de stockage).
   * Entité APM (applications, services).
   * Connexions inter-plateformes (ressources <DNT>Azure</DNT> connectées aux services APM).

### Relations inter-abonnements [#cross-subscription]

Si une ressource découverte se connecte à une ressource dans un abonnement <DNT>Azure</DNT> différent, <DNT>Infrastructure 360</DNT> résout la relation automatiquement :

* Si l’abonnement cible est également intégré à <DNT>Infrastructure 360</DNT>, la carte affiche l’entité cible réelle, et ses détails.
* Si vous n’avez pas intégré, ou monitoré l’abonnement cible, la carte montre une entité inconnue, ou non instrumentée à sa place ; la connexion est toujours visible, mais les détails de l’entité ne sont pas disponibles.

### Corréler les modifications de configuration avec les alertes [#correlate-config-changes]

<DNT>Infrastructure 360</DNT> suit les modifications de configuration sur vos ressources <DNT>Azure</DNT> afin que vous puissiez rapidement déterminer si une modification récente a causé une alerte ou un incident, au lieu d’enquêter séparément sur les données d’infrastructure et d’application.

1. Allez à <DNT>**All capabilities**</DNT> et sélectionnez <DNT>**Azure Services**</DNT>.
2. Sélectionnez une entité dans la liste, et cliquez sur <DNT>**Configuration explorer**</DNT> pour voir ses paramètres, tags, et propriétés actuels.
3. Comparez les horodatages dans la chronologie des modifications de configuration avec vos alertes, ou incidents. Une modification de configuration à peu près au même moment qu’une alerte est un signal fort de cause première, vous permettant de corréler les modifications de configuration avec vos alertes, et incidents.

## Gérer les paramètres d&apos;infrastructure 360 [#manage-settings]

### Ajustez la fréquence d’analyse [#adjust-frequency]

Vous pouvez personnaliser la fréquence à laquelle <DNT>Infrastructure 360</DNT> analyse votre environnement <DNT>Azure</DNT> :

1. Allez à <DNT>**Infrastructure &gt; Azure**</DNT> et cliquez sur <DNT>**Manage Infrastructure 360**</DNT>.
2. Trouvez votre compte <DNT>Azure</DNT> et cliquez sur <DNT>**Edit**</DNT>.
3. Sélectionnez votre fréquence d&apos;analyse préférée dans la liste déroulante.
4. Cliquez sur <DNT>**Save**</DNT> pour appliquer les modifications.

Envisagez d’augmenter la fréquence d’analyse si vous apportez des modifications fréquentes à votre environnement <DNT>Azure</DNT>, ou de la diminuer si votre infrastructure est stable, et que vous souhaitez réduire les appels d’API.

### Désactiver Infrastructure 360 [#disable]

<Callout variant="important">
Lorsque vous désactivez <DNT>Infrastructure 360</DNT>, vous perdez l’accès à :

* Entités découvertes automatiquement, et leurs configurations.
* Modélisation des relations entre les ressources <DNT>Azure</DNT> et les services APM.
* Mises à jour de la topologie de l’infrastructure en temps réel.
</Callout>

Si vous réactivez <DNT>Infrastructure 360</DNT> plus tard, il recrée toutes les entités et relations qui n’existent plus, lors de sa prochaine analyse programmée.

Pour désactiver <DNT>Infrastructure 360</DNT>, suivez ces étapes :

1. Allez à <DNT>**Infrastructure &gt; Azure**</DNT> et cliquez sur <DNT>**Manage Infrastructure 360**</DNT>.
2. Trouvez le compte où vous souhaitez désactiver <DNT>Infrastructure 360</DNT>.
3. Cliquez sur <DNT>**Edit**</DNT> et désactivez le commutateur d’analyse.
4. Cliquez sur <DNT>**Save**</DNT> pour confirmer la modification.
