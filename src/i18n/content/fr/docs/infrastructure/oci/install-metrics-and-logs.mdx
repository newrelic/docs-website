Utilisez ce guide pour envoyer à la fois les métriques et les logs OCI à New Relic. Choisir les deux permet d&apos;envoyer les métriques et les logs ensemble, afin que vous puissiez les corréler pour les mêmes ressources OCI. Pour n&apos;envoyer qu&apos;un seul type de données, consultez [Monitorer les métriques OCI](/docs/infrastructure/oci/install-metrics) ou [Transférer les logs OCI](/docs/logs/forward-logs/oci-log-forwarding).

## Compatibilité et exigences [#requirements]

Avant de commencer, assurez-vous d&apos;avoir :

* Un compte New Relic avec des permissions de monitoring d’infrastructure dans une région prise en charge (US, EU, ou JP)
* Une [clé de licence d’ingestion](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) New Relic valide et une [clé utilisateur](/docs/apis/intro-apis/new-relic-api-keys/#user-api-key)
* Une location OCI avec un domaine de gestion des identités et des accès (IAM), et un accès administratif temporaire à ce domaine et au compartiment racine, suffisant pour terminer la configuration de la fédération d’identités de workload (WIF), le mécanisme que New Relic utilise pour s’authentifier sans stocker d’identifiants à long terme. Vous pouvez révoquer cet accès une fois la configuration terminée.
* L&apos;OCID de votre location OCI et votre région principale (par exemple, `us-ashburn-1`)
* Une clé de signature d’API OCI (uniquement si vous déployez avec Terraform)

## Installation guidée [#ui-install]

L&apos;installation guidée est disponible sur <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; Oracle Cloud Infrastructure**</DNT>. L’interface utilisateur vous guide pour connecter votre compte OCI, puis pour instrumenter les espaces de nommage de métrique et les groupes de log que vous souhaitez monitorer.

<Steps>
<Step>
### Choisissez les deux types de données

Suivez ces étapes :

1. Sélectionnez à la fois <DNT>**Metrics**</DNT> (pour les statistiques de performances et d’utilisation) et <DNT>**Logs**</DNT> (pour les enregistrements détaillés d’événement et d’audit).
2. Cliquez sur <DNT>**Continue**</DNT>.
</Step>

<Step>
### Choisissez votre méthode d’intégration et configurez l’intégration

Sélectionnez votre méthode d’intégration préférée pour ingérer les données OCI dans New Relic en fonction de vos besoins organisationnels :

<CollapserGroup>
<Collapser id="orm" title="Monitorer OCI avec Oracle Resource Manager">
Exécute les stacks Oracle Resource Manager pour provisionner ce dont l’intégration a besoin, au lieu de créer vous-même chaque élément à la main dans la console OCI. Suivez les instructions à l’écran pour établir la connexion.
</Collapser>

<Collapser id="manual" title="Intégrer manuellement votre compte OCI">
Dans la console OCI, créez les politiques et les connecteurs de service requis. L’installation guidée vous accompagne à travers ces étapes dans l’ordre : créer un compartiment, créer un groupe dynamique, configurer un secret de coffre de clés, créer une politique, configurer un réseau, configurer la fonction de métriques, configurer la fonction de log, configurer le connecteur de métriques, configurer un connecteur de log d’audit (facultatif), configurer le connecteur de log, configurer WIF et créer la connexion.

Vous aurez besoin des informations suivantes pour terminer le processus :

* Nommez le compartiment dédié `newrelic_compartment_DO_NOT_REMOVE`. Créez-le dans votre région d’origine OCI.

* Lors de la création du groupe dynamique dans le compartiment racine sous le domaine par défaut, ajoutez les règles `resource.type = 'serviceconnector'` et `resource.type = 'fnfunc'`.

* Créez un coffre de clés pour stocker en toute sécurité votre clé de licence New Relic et votre clé utilisateur pour l’authentification.<br />

  1. **Créez un coffre de clés**. Dans la console OCI, localisez et accédez aux **services Key Management and Vault** et créez un coffre dans le compartiment que vous avez créé précédemment, en le nommant (par exemple, `newrelic-vault`) et en choisissant un coffre standard ou privé virtuel en fonction de vos exigences de sécurité.<br />
  2. **Créez une clé de chiffrement principale**. Dans le coffre-fort, créez une clé principale nommée (par exemple) `newrelic-encryption-key`, en utilisant l’algorithme `AES` et une longueur de clé de `256`bits.<br />
  3. **Créez des secrets pour vos clés API**. Créez un secret pour votre clé de licence d’ingestion New Relic, nommé (par exemple) `newrelic-ingest-key`, en sélectionnant la clé principale que vous venez de créer, et en collant votre clé de licence d’ingestion comme contenu du secret (texte brut). Répétez l’opération pour créer un second secret pour votre clé utilisateur New Relic, nommé (par exemple) `newrelic-user-key`, en collant votre clé utilisateur comme contenu du secret (texte brut).

* Créez une application serverless et déployez la fonction New Relic qui traite et transfère vos métriques OCI.<br />

  1. **Créez une application sans serveur**

     * Accédez au service <DNT>**Functions**</DNT> sous <DNT>**Developer Services**</DNT> dans la console OCI.

     * Créer une nouvelle application avec cette configuration :

       * **Nom**: un nom descriptif (par exemple, `NewRelicMetricsApp`)
       * **Compartiment**: votre compartiment New Relic désigné
       * **VCN**: le VCN créé pour l’intégration New Relic
       * **Subnet**: le sous-réseau privé, pour une connectivité sécurisée
       * **Forme**: `GENERIC_X86`, pour la forme de l’application

  2. **Configurer les variables d’environnement**

     * Dans les paramètres de l’application, ajoutez ces variables de configuration :

       * `FORWARD_TO_NR`: définissez sur `True` pour activer le transfert de données vers New Relic
       * `LOGGING_ENABLED`: définissez sur `False` pour désactiver le logging détaillé (facultatif)
       * `NR_METRIC_ENDPOINT`: le point de terminaison New Relic, en utilisant `newrelic-metric-api` pour les comptes US, `newrelic-eu-metric-api` pour les comptes EU, ou `newrelic-jp-metric-api` pour les comptes JP
       * `VAULT_REGION`: la région où vous avez créé votre coffre de clés
       * `SECRET_OCID`: l&apos;OCID de votre secret d&apos;ingestion New Relic du coffre de clés
       * `TENANCY_OCID`: l’OCID de votre location OCI

     * Enregistrez les variables de configuration.

  3. **Créez et déployez la fonction**

     * Dans l’application, créez une nouvelle fonction avec ces spécifications :

       * **Function name**: un nom descriptif (par exemple, `newrelic-metrics-function`)
       * **Source de l’image**: l’image Docker New Relic, que vous copiez dans un référentiel privé de votre registre de conteneurs
       * **Memory allocation**: une mémoire appropriée (par exemple, 256 Mo)

     * Pour l’image Docker, récupérez l’image New Relic depuis Docker Hub (`docker.io/newrelic/beyond-oci-metric-function:latest`, plateforme `linux/amd64`). Ensuite, authentifiez-vous auprès du point de terminaison régional de votre registre de conteneurs (`{region}.ocir.io`) à l’aide d’un jeton d’authentification.

     * Ajoutez un tag à l&apos;image et poussez-la vers un référentiel privé dans votre espace de nommage dans la même région que la fonction, et référencez-la dans la configuration de votre fonction.

     * Terminez le processus de création et de déploiement de la fonction.

     * Pour mettre à niveau ultérieurement, poussez à nouveau la nouvelle image, et mettez à jour la fonction pour l’utiliser.

* Créez une application sans serveur et déployez la fonction New Relic qui traite et transfère votre log OCI.<br />

  1. **Créez une application sans serveur pour le logging**

     * Accédez au service <DNT>**Functions**</DNT> sous <DNT>**Developer Services**</DNT> dans la console OCI.

     * Créer une nouvelle application avec cette configuration :

       * **Nom**: un nom descriptif (par exemple, `newrelic-logging-function-app`)
       * **Compartiment**: votre compartiment New Relic désigné
       * **VCN**: le VCN créé pour l’intégration New Relic
       * **Subnet**: le sous-réseau privé, pour une connectivité sécurisée
       * **Forme**: `GENERIC_X86`, pour la forme de l’application

     * Enregistrez la configuration de l’application.

  2. **Configurez les variables d&apos;environnement pour le logging**

     * Dans les paramètres de l’application, accédez à la section de configuration et ajoutez ces variables :

       * `VAULT_REGION`: la région où vous avez créé votre coffre de clés
       * `DEBUG_ENABLED`: `false` pour un usage en production (ou `true` pour le débogage)
       * `NEW_RELIC_REGION`: votre région New Relic (`US`, `EU`, ou `JP`)
       * `SECRET_OCID`: l’OCID du secret de votre clé de licence New Relic provenant du coffre-fort de clés
       * `CLIENT_TTL`: `30` secondes, pour l’intervalle d’actualisation de la clé de licence

     * Facultativement, pour activer les [métriques d’auto-observabilité sur le redirecteur de logs](/docs/logs/forward-logs/oci-log-forwarder-observability), ajoutez également

       * `FORWARDER_METRICS_TIER`: contrôle quelles métriques d’auto-observabilité le forwarder émet. La valeur par défaut est `basic`. Consultez les [niveaux de métriques](/docs/logs/forward-logs/oci-log-forwarder-observability/#metric-tiers) pour savoir ce que chaque paramètre collecte.
       * `TENANCY_NAME`: identifie votre location OCI par son nom d’affichage, en ajoutant un tag aux métriques du forwarder afin que vous puissiez différencier les locations si vous en monitorez plusieurs.
       * `COMPARTMENT_NAME`: identifie, par son nom d’affichage, le compartiment où vous avez déployé la fonction de log, en ajoutant un tag aux métriques pour des répartitions par compartiment. Si vous avez déployé dans le compartiment racine de la location, utilisez la même valeur que `TENANCY_NAME`.

     * Une fois que vous avez activé les métriques du redirecteur, [importez le dashboard d’observabilité](/docs/logs/forward-logs/oci-log-forwarder-observability/#observability-dashboard) pour les visualiser.

     * Enregistrez les variables de configuration.

  3. **Déployer la fonction de logging**

     * Créez une nouvelle fonction dans l’application avec ces spécifications :

       * **Function name**: un nom descriptif (par exemple, `newrelic-logging-function`)
       * **Source de l’image**: l’image Docker de logging de New Relic, que vous copiez dans un référentiel privé de votre registre de conteneurs
       * **Memory allocation**: au moins 128 Mo
       * **Délai d’expiration**: 300 secondes, pour un temps de traitement adéquat

     * Pour l’image Docker, récupérez l’image de logging de New Relic depuis Docker Hub (`docker.io/newrelic/oci-log-forwarder:latest`, plateforme `linux/amd64`). Ensuite, authentifiez-vous auprès de votre point de terminaison régional de registre de conteneur (`{region}.ocir.io`) à l’aide d’un jeton d’authentification.

     * Ajoutez un tag à l&apos;image et poussez-la vers un référentiel privé dans votre espace de nommage dans la même région que la fonction, et référencez-la dans la configuration de votre fonction.

     * Terminez le processus de création et de déploiement de la fonction.

     * Pour mettre à niveau ultérieurement, poussez à nouveau la nouvelle image, et mettez à jour la fonction pour l’utiliser.

  4. **(Facultatif) Activez le logging de la fonction**

     * Accédez aux paramètres de monitoring de votre application de fonction.
     * Activez les logs d’invocation de fonction en sélectionnant ou en créant un groupe de logs approprié, en configurant les politiques de rétention et d’accès des logs, et en activant la collecte de logs pour la fonction.
     * Pour plus d’informations, consultez la documentation Oracle sur [l’exportation de fichiers de log de fonction](https://docs.oracle.com/en-us/iaas/Content/Functions/Tasks/functionsexportingfunctionlogfiles.htm).
</Collapser>

<Collapser id="terraform" title="Automatiser avec Terraform">
Puisque vous avez sélectionné les logs, Terraform est la méthode de configuration recommandée.<br /> Pour les étapes d&apos;intégration détaillées, consultez le [guide d&apos;intégration cloud OCI](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#oci).<br />
</Collapser>
</CollapserGroup>
</Step>

<Step>
### Instrumentez vos espaces de nommage de métriques et vos groupes de log

Une fois la connexion créée, la page OCI dans New Relic affiche des vues distinctes pour les métriques et les logs, chacune avec son propre contrôle **Add instrumentation** :

1. Cliquez sur **Add instrumentation**, filtré par défaut sur l’onglet **Not instrumented**.
2. Développez un compartiment pour voir ses espaces de nommage de métriques (ou groupes de log) individuels, et sélectionnez ceux que vous souhaitez monitorer. Pour les log, vous pouvez également activer **Enable audit logs** pour inclure les log d’audit OCI.
3. Confirmez votre sélection. New Relic affiche un résumé du nombre de compartiments, et d’espaces de nommage (ou groupes de logs) que vous êtes sur le point d’instrumenter. Puis cliquez sur **Deploy to OCI**.
4. Une fois le déploiement terminé dans OCI, le compartiment se déplace vers l’onglet **Instrumented**, et ses données apparaissent à <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; OCI**</DNT>.
5. Passez à la vue **Logs** et répétez-y les étapes 1 à 4.

Les données peuvent mettre jusqu’à 30 minutes à apparaître. Si vous ne les voyez pas après cela, vérifiez l’état du déploiement dans la console OCI.

Pour instrument des espaces de nommage ou des groupes de log supplémentaires ultérieurement, retournez sur la page OCI dans New Relic et répétez ces étapes.
</Step>

<Step>
### Trouvez et utilisez vos données

Une fois que vos données commencent à apparaître dans <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; OCI**</DNT>, confirmez que l’intégration fonctionne et utilisez-la :

1. Vérifiez que votre compte OCI apparaît dans la liste des intégrations.

2. Confirmez que vous recevez des données (métriques et logs). Pour confirmer les logs, vérifiez l&apos;un de ces emplacements :

   * L’ [interface utilisateur des logs](https://one.newrelic.com/launcher/logger.log-launcher): allez dans <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Logs**</DNT>, et confirmez que vos logs OCI apparaissent.

   * Les [outils de requête NRQL](/docs/chart-builder/use-chart-builder/choose-data/use-advanced-nrql-mode-specify-data): exécutez une requête NRQL comme ceci :

     ```sql
     SELECT * FROM Log
     ```

3. [Créez des conditions d’alerte](/docs/alerts/create-alert/create-alert-condition/alert-conditions) pour les métriques OCI clés afin d’obtenir des notifications proactives sur les problèmes de performances.

4. [Créez des dashboards personnalisés](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) pour visualiser les données de votre infrastructure OCI et monitorer les tendances de performances.

Si vous ne voyez pas de données après 30 minutes, consultez [dépannage](/docs/infrastructure/oci/troubleshoot).
</Step>
</Steps>
