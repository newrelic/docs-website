Si vous rencontrez des problèmes avec l’intégration OCI, commencez ici.

## Résoudre les problèmes liés aux logs [#logs]

Si vos log OCI n’apparaissent pas, s’arrêtent de manière inattendue, s’affichent en double, ou affichent les noms de ressources de manière incorrecte, commencez par la vérification de l’état ci-dessous, puis trouvez votre problème spécifique dans les sections qui suivent.

### Bilan de santé [#logs-health-check]

Ces deux vérifications vous indiquent si le problème se situe en amont dans OCI (rien à vérifier dans New Relic pour le moment), ou si les logs ont réellement atteint New Relic :

1. **Vérifiez votre connecteur dans OCI.** Dans la console OCI, accédez à <DNT>**Connector Hub**</DNT>, et ouvrez le compartiment où vous avez déployé votre intégration New Relic. Recherchez un connecteur nommé `newrelic-logs-<region>-audit` (par exemple, `newrelic-logs-us-ashburn-1-audit`), et confirmez que son statut est <DNT>**Active**</DNT>. Si vous voyez un statut d’erreur, ouvrez le connecteur pour obtenir les détails de l’erreur.

2. **Vérifiez que les logs arrivent dans New Relic.** Exécutez cette requête dans [Interrogez vos données](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder):

   ```sql
   SELECT count(*) FROM Log WHERE oracle.loggroupid = '_Audit' SINCE 30 minutes ago
   ```

   Un nombre supérieur à zéro signifie que les log d’audit sont transmis. Si vous effectuez le dépannage d’un autre type de log, vérifiez plutôt que vous voyez des résultats récents pour la fenêtre de temps correspondante.

Si les deux contrôles semblent sains, votre problème correspond probablement à l&apos;un des scénarios spécifiques ci-dessous, plutôt qu&apos;à une panne totale.

<Collapser id="duplicate-logs" title="Entrées de log en double">
Plus d’un connecteur envoie le même événement de log à New Relic. Cela signifie généralement que plus d’un connecteur dans OCI couvre les mêmes log : le plus souvent, quelqu’un a ajouté un connecteur &quot;tous les compartiments&quot; plus large sans supprimer un ancien connecteur qui ne couvrait qu’un seul compartiment.

Dans <DNT>**Connector Hub**</DNT>, listez tous les connecteurs liés à votre intégration New Relic, et vérifiez ce que chacun couvre. Supprimez tous ceux qui se chevauchent, en ne conservant que le seul connecteur qui couvre le périmètre que vous souhaitez réellement.
</Collapser>

<Collapser id="resource-names" title="Les noms de ressources s’affichent sous forme de chaînes d’ID">
Pour certains types de ressources OCI, New Relic recherche automatiquement un nom lisible par l’homme (comme un nom de VCN ou de pare-feu) peu de temps après l’arrivée du premier log, plutôt que d’afficher l’identifiant brut de la ressource. Cette recherche peut prendre quelques minutes la première fois que New Relic voit une ressource donnée.

Si les noms ne se résolvent jamais, demandez à votre administrateur de location OCI de confirmer que le groupe dynamique possède les `inspect` politiques répertoriées sous [Autorisations manquantes](#logs-permissions) : une pour chacune des ressources DNS, GoldenGate, pare-feu réseau, règle d’événement, et instance d’intégration. Si les autorisations semblent correctes, et que les noms ne se résolvent toujours pas après une attente raisonnable, contactez le support avec un exemple de la ressource affectée, et l’horodatage du log.
</Collapser>

## Obtenir plus d&apos;aide [#get-help]

Si vous avez effectué les vérifications ci-dessus, et que le problème n’est pas résolu, veuillez contacter le support New Relic avec :

* La méthode de configuration que vous avez utilisée (assistant guidé, configuration manuelle, ou Terraform)
* La région OCI, et, le cas échéant, le(s) compartiment(s) affecté(s)
* La plage de temps approximative à laquelle le problème a commencé
* Lesquelles des vérifications ci-dessus vous avez déjà essayées
