[Les intégrations New Relic](/docs/infrastructure/introduction-infra-monitoring) avec [Google Cloud Platform (GCP)](https://cloud.google.com/) incluent une intégration qui signale les données de [Google Cloud Service Mesh](https://cloud.google.com/service-mesh/docs) (Istio) à New Relic. Ce document explique comment activer l’intégration GCP Cloud Service Mesh, et décrit les données qu’elle signale.

## Caractéristiques

Cloud Service Mesh est le maillage de services géré de Google Cloud, basé sur Istio. L’intégration New Relic Cloud Service Mesh collecte la télémétrie du service Istio émise par vos workloads maillés : le nombre de requêtes entrantes et sortantes, la taille des requêtes et des réponses, et les distributions de latence côté serveur et client.

Cette intégration est limitée aux workloads Cloud Run inscrits dans Cloud Service Mesh. La télémétrie Istio provenant des workloads sidecar GKE (la ressource monitorée `istio_canonical_service`) n’est pas collectée par cette intégration.

## Activer l&apos;intégration [#activate]

<Callout variant="important">
  Cette intégration est disponible uniquement lorsque vous connectez votre projet GCP avec Workload Identity Federation. Elle n’est pas disponible pour les connexions de compte de service ou de compte utilisateur.
</Callout>

Pour activer l’intégration, suivez les procédures standard pour [connecter votre service GCP à New Relic](/docs/connect-google-cloud-platform-services-infrastructure) avec Workload Identity Federation.

## Fréquence des sondages [#polling]

L’intégration New Relic interroge vos services GCP selon un intervalle d’interrogation qui varie selon l’intégration. La fréquence d’interrogation pour Google Cloud Service Mesh est de 5 minutes. La résolution est de 1 point de données chaque minute.

## Fédération d&apos;identité de workload (Workload Identity Federation) [#wif]

### Rechercher et utiliser des données [#find-data-wif]

Toutes les métriques Cloud Service Mesh disponibles dans le monitoring cloud GCP sont collectées en tant que métriques dimensionnelles dans le type d’événement `Metric`.

Cette intégration ne crée pas d’entités dans l’explorateur d’entités de New Relic. Interrogez ses métriques directement sur le type d’événement `Metric`, par exemple :

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.istio.io.%' FACET metricName
```

Les métriques portent les étiquettes de ressource de la révision Cloud Run sous-jacente, vous pouvez donc créer des facettes par nom de service, nom de révision, et emplacement sans entité.

Les métriques de distribution ci-dessus (`request_bytes`, `response_bytes`, `response_latencies`, `roundtrip_latencies`) sont également disponibles en tant que métriques de percentile `.p50`, `.p95`, et `.p99`. Par exemple, `gcp.istio.io.service.server.response_latencies.p99`.

Pour en savoir plus sur la télémétrie du service Istio, consultez la [documentation sur l’observabilité de Google Cloud Service Mesh](https://cloud.google.com/service-mesh/docs/observability).
