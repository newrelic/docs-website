<DNT>**Workload Identity Federation (WIF)**</DNT> permet à New Relic d&apos;accéder à vos métriques GCP à l&apos;aide de jetons de courte durée au lieu de clés de longue durée. Vous créez et contrôlez le compte de service dans votre propre projet GCP, de sorte que New Relic ne stocke jamais d&apos;identifiants statiques.

Ce guide couvre la configuration manuelle via l&apos;[UI de New Relic](https://onenr.io/0VRVAVapXwa). Si vous préférez l&apos;infrastructure as code, consultez [Automatiser avec Terraform](/docs/infrastructure/google-cloud-platform-integrations/get-started/install-and-configure/connect-gcp-workload-identity-federation-terraform).

<Callout variant="tip">
  Vous avez déjà des projets connectés avec un compte de service ? Ajoutez de nouveaux projets avec WIF en parallèle — les deux méthodes fonctionnent sous le même compte New Relic. Suivez simplement ce guide pour ajouter une connexion basée sur WIF.
</Callout>

## Intégrer manuellement GCP [#manual-setup]

<Steps>
  <Step>
    ### Démarrer l&apos;intégration dans New Relic [#step-1]

    1. Accédez à <DNT>**Infrastructure &gt; Google Cloud Platform**</DNT> dans New Relic.
    2. Sélectionnez <DNT>**Add a GCP account**</DNT> (ou le bouton d&apos;action principal s&apos;il s&apos;agit de votre première intégration).
    3. Sélectionnez le compte New Relic que vous souhaitez utiliser.
    4. Sous <DNT>**Select instrumentation method**</DNT>, choisissez <DNT>**Workload Identity Federation**</DNT>.
    5. Sous <DNT>**Choose setup method**</DNT>, sélectionnez <DNT>**Manually integrate your GCP project or folder**</DNT>.

    {/* Image needed: the instrumentation method selection screen showing WIF highlighted as recommended */}
  </Step>

  <Step>
    ### Activez les API GCP requises [#step-2]

    1. Activez ces cinq API dans votre projet GCP. Elles permettent à New Relic de s&apos;authentifier et de collecter des données :

       * [API IAM](https://console.cloud.google.com/apis/library/iam.googleapis.com?pli=1): gérer l&apos;accès au compte de service
       * [API Security Token Service](https://console.cloud.google.com/apis/library/sts.googleapis.com): échanger des jetons lors de l’authentification WIF
       * [Service Account Credentials API](https://console.cloud.google.com/apis/library/iamcredentials.googleapis.com): générer des jetons d&apos;accès de courte durée
       * [API de monitoring Stackdriver](https://console.cloud.google.com/apis/library/monitoring.googleapis.com): lire les métriques du monitoring cloud GCP
       * [API Asset](https://console.cloud.google.com/apis/library/cloudasset.googleapis.com): découvrir les ressources et les métadonnées
       * [API Cloud Resource Manager](https://console.cloud.google.com/apis/library/cloudresourcemanager.googleapis.com): obtenir `displayName` du dossier

    2. Cochez la case une fois que les cinq sont activés, puis sélectionnez <DNT>**Continue**</DNT>.

    {/* Image needed: prerequisites screen showing the five API links and confirmation checkbox */}
  </Step>

  <Step>
    ### Créer ou sélectionner un compte de service [#step-3]

    Dans votre projet GCP, créez un compte de service dont New Relic pourra emprunter l&apos;identité :

    1. Dans la console GCP, accédez à <DNT>**[IAM &amp; Admin](https://console.cloud.google.com/projectselector2/iam-admin) &gt; Service Accounts**</DNT>.

    2. Créez un nouveau compte de service, ou utilisez-en un existant.

    3. Attribuez les rôles suivants au compte de service :

       * <DNT>**Viewer**</DNT>
       * <DNT>**Service Usage Consumer**</DNT>
       * <DNT>**Cloud Asset Viewer**</DNT>
       * <DNT>**Folder Viewer**</DNT> (requis uniquement pour les intégrations configurées au niveau du dossier)

    4. Sélectionnez <DNT>**Save**</DNT>.

    <Callout variant="important">
      Pour monitorer chaque projet d&apos;un dossier via une seule connexion, accordez ces rôles sur le dossier au lieu d&apos;un seul projet. Consultez [Intégrer au niveau du dossier](#folder-level).
    </Callout>

    {/* Image needed: enabling service account screen with instructions */}
  </Step>

  <Step>
    ### Créer un pool d&apos;identités de workload [#step-4]

    Un pool d’identités de workload est un conteneur pour les identités externes (telles que New Relic) auxquelles vous faites confiance.

    1. Dans la console GCP, accédez à <DNT>**[IAM &amp; Admin &gt; Workload Identity Federation](https://console.cloud.google.com/getting-started)**</DNT>.
    2. Sélectionnez <DNT>**Get Started**</DNT> (ou <DNT>**Create Pool**</DNT>).
    3. Saisissez un nom et une description pour le pool, puis activez le pool.
    4. Sélectionnez <DNT>**Continue**</DNT>.
  </Step>

  <Step>
    ### Ajouter un fournisseur OIDC au pool [#step-5]

    Cela indique à GCP de faire confiance aux jetons signés par New Relic.

    1. Sous <DNT>**Select a provider**</DNT>, choisissez <DNT>**OpenID Connect (OIDC)**</DNT>.

    2. Copiez ces valeurs depuis l&apos;UI de New Relic dans la console GCP :

       * <DNT>**Provider pool name**</DNT>: affiché dans l&apos;écran de configuration de New Relic.
       * <DNT>**Issuer URL**</DNT>: affiché dans l&apos;écran de configuration de New Relic (par exemple, `https://oidc.newrelic.com/r/gcp-cmp`).

    3. Sous <DNT>**Allowed audiences**</DNT>, sélectionnez-le et laissez l&apos;audience par défaut non sélectionnée.

    4. Copiez le <DNT>**Audience URL**</DNT> depuis l&apos;UI de New Relic.

    5. Sélectionnez <DNT>**Continue**</DNT>.

    {/* Image needed: create an identity pool screen showing provider name, issuer URL, and audience fields pre-filled from New Relic */}
  </Step>

  <Step>
    ### Configurer les attributs du fournisseur [#step-6]

    Les modélisations d’attributs indiquent à GCP comment lire les jetons de New Relic. Ajoutez ces deux modélisations :

    | Attribut Google           | Attribut OIDC             |
    | ------------------------- | ------------------------- |
    | `google.subject`          | `assertion.sub`           |
    | `attribute.nr_account_id` | `assertion.nr_account_id` |

    L&apos;UI de New Relic affiche l&apos;ID de votre compte prérempli. Copiez-le dans le champ de condition dans GCP.

    <Callout variant="important">
      La condition d’attribut garantit que seul votre compte New Relic peut utiliser ce pool. Sans elle, n’importe quel compte New Relic pourrait potentiellement accéder à votre projet GCP.
    </Callout>

    {/* Image needed: configure provider attributes screen showing the two mappings and the attribute condition */}
  </Step>

  <Step>
    ### Accorder l&apos;accès au pool [#step-7]

    Connectez le pool d&apos;identités à votre compte de service afin que New Relic puisse emprunter son identité :

    1. Dans les détails du pool, sélectionnez <DNT>**Grant Access**</DNT>.
    2. Activer <DNT>**Grant access using service account impersonation**</DNT>.
    3. Sélectionnez le compte de service que vous avez créé à l&apos;étape [Créer ou sélectionner un compte de service](#step-3).
    4. Sous <DNT>**Add principals**</DNT>, sélectionnez <DNT>**Principal with access**</DNT>.
    5. Ajoutez l&apos;attribut d&apos;identité `nr_account_id` avec la valeur de votre [ID de compte](/docs/accounts-partnerships/accounts/account-setup/account-id) New Relic.
    6. Sélectionnez <DNT>**Save**</DNT>.

    {/* Image needed: GCP access pool details screen showing service account impersonation and identity attributes */}
  </Step>

  <Step>
    ### Télécharger et téléverser le fichier de configuration [#step-8]

    Cette étape relie votre configuration GCP à New Relic :

    1. Dans la console GCP, dans la section <DNT>**Connected Service Accounts**</DNT> du pool, sélectionnez le compte de service.

    2. Définissez ces paramètres :

       * <DNT>**Service Provider**</DNT>: sélectionnez le fournisseur que vous venez de créer.
       * <DNT>**OIDC ID Token Path**</DNT>: sélectionnez `/`
       * <DNT>**Format Type**</DNT>: JSON

    3. Sélectionnez <DNT>**Download Config**</DNT> pour obtenir un fichier JSON.

    4. Retournez à l&apos;écran de configuration de New Relic et téléversez ce fichier JSON.

    New Relic valide la configuration avec une authentification de test. Si cela réussit, vous verrez un message <DNT>**Connection succeeded**</DNT>.

    <Callout variant="important">
      Ne fermez pas l&apos;onglet du navigateur avant de sélectionner <DNT>**Continue**</DNT> après le téléversement. Si vous le faites, vous perdez votre progression.
    </Callout>

    {/* Image needed: application configuration screen showing the file upload area and the success toast */}
  </Step>

  <Step>
    ### Sélectionner des projets et des services [#step-9]

    Une fois la connexion vérifiée :

    1. New Relic répertorie les projets GCP auxquels votre compte de service peut accéder.
    2. Développez un projet pour voir les services disponibles.
    3. Sélectionnez les services que vous souhaitez monitorer.
    4. Sélectionnez <DNT>**Instrument**</DNT> pour commencer à collecter des données.

    Les services se divisent en deux catégories :

    * <DNT>**Full entity support**</DNT> — métriques, entité dans l&apos;explorateur d&apos;entités et dashboard.
    * <DNT>**Metrics only**</DNT> — New Relic collecte des métriques, mais ne crée pas d&apos;entité.

    {/* Image needed: project and service selection screen showing an expanded project with Full entity support / Metrics only tabs */}
  </Step>
</Steps>

## Intégrer au niveau du dossier [#folder-level]

Avec la fédération d&apos;identités de workload, vous pouvez intégrer un seul projet ou un dossier entier de projets. Dans GCP, lorsque vous accordez des rôles IAM au niveau du dossier, chaque projet de ce dossier en hérite. Ainsi, si vous accordez les rôles du compte de service sur un dossier au lieu d&apos;un seul projet, New Relic peut monitorer tous les projets de ce dossier via une seule connexion.

Pour ce faire, dans [Créer ou sélectionner un compte de service](#step-3), accordez au compte de service les rôles <DNT>**Viewer**</DNT>, <DNT>**Service Usage Consumer**</DNT>, <DNT>**Cloud Asset Viewer**</DNT> et <DNT>**Folder Viewer**</DNT> sur le dossier plutôt que sur un seul projet. Lorsque vous atteignez [Sélectionner des projets et des services](#step-9), New Relic répertorie chaque projet de ce dossier afin que vous puissiez choisir ceux à monitorer.

## Afficher vos données GCP [#explore]

Une fois la configuration terminée, New Relic commence à monitorer vos données GCP à des [intervalles d’interrogation](/docs/infrastructure/google-cloud-platform-integrations/get-started/view-your-data/polling-intervals-gcp-integrations) réguliers, et vos données apparaissent dans l’UI de New Relic après quelques minutes. Pour savoir comment les afficher, les requêter et les explorer — y compris les dashboards, les alertes et les entités —, consultez [Afficher et requêter vos données GCP](/docs/infrastructure/google-cloud-platform-integrations/get-started/view-your-data/view-and-query-your-gcp-data).

## Lier plusieurs projets Google [#link-multiple]

Une seule configuration WIF accorde l&apos;accès aux projets GCP pour lesquels votre compte de service a des autorisations. Lors de la configuration, New Relic répertorie tous les projets accessibles afin que vous puissiez sélectionner ceux à monitorer.

Pour monitorer des projets GCP supplémentaires ultérieurement :

* Si les nouveaux projets se trouvent dans la même organisation GCP et que votre compte de service y a déjà accès, accédez à <DNT>**Infrastructure &gt; GCP &gt; Manage services**</DNT> et ajoutez-les.
* Si les nouveaux projets nécessitent un compte de service ou un pool d’identités différent, répétez la configuration pour créer une nouvelle connexion WIF.

## Gérer les services [#manage]

Après la configuration, vous pouvez modifier les services qui sont monitorés pour chaque projet :

1. Allez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Infrastructure &gt; GCP**</DNT>.
2. Sélectionnez <DNT>**Manage services**</DNT> à côté de votre compte.
3. Activez ou désactivez les services par projet.
4. Enregistrez vos modifications.

## Désactiver ou dissocier vos intégrations GCP [#unlink]

Vous pouvez désactiver des services individuels ou déconnecter complètement votre projet GCP de New Relic.

### Désactiver un ou plusieurs services GCP [#disable-services]

1. Allez à <DNT>**Infrastructure &gt; GCP &gt; Manage services**</DNT>.
2. Décochez la case de chaque service que vous souhaitez désactiver.
3. Enregistrez vos modifications.

### Déconnecter entièrement le compte GCP [#disconnect-account]

1. Allez à <DNT>**Infrastructure &gt; GCP &gt; Manage services**</DNT>.
2. Sélectionnez <DNT>**Unlink this account**</DNT>.
3. Enregistrez vos modifications.

Après la dissociation dans New Relic, effectuez un nettoyage côté GCP :

1. Ouvrez la console GCP et accédez à <DNT>**IAM &amp; Admin &gt; Workload Identity Federation**</DNT>.
2. Supprimez le pool d&apos;identités que vous avez créé pour New Relic, ou retirez le fournisseur OIDC de celui-ci.
3. En option, supprimez le compte de service s’il a été créé uniquement pour New Relic.
