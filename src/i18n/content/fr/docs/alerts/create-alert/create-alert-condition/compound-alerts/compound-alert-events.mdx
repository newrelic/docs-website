Lorsque l’expression de déclenchement d’une condition d’alerte composée est évaluée comme vraie, New Relic ouvre un événement d’alerte composée. L’événement inclut un lien vers l’URL de votre runbook. Pour afficher les dépassements de seuil spécifiques pour chaque condition de composant, cliquez sur les événements d’alerte individuels.

## Événements d’alerte et corrélation des problèmes [#alert-events-correlation]

Les conditions d’alerte composites créent plusieurs événements d&apos;alerte associés :

* <DNT>**Multiple alert events**</DNT>: une condition d’alerte composée crée son propre événement d’alerte composée. Par défaut, chaque condition de composant crée également ses propres événements d’alerte lorsqu’elle dépasse ses seuils. Pour réduire le bruit, vous pouvez mettre ces événements en sourdine à partir de la configuration de la condition d’alerte. Si vous désactivez les événements d’alerte d’une condition de composant, les tags de cette condition n’apparaîtront pas dans l’événement d’alerte composée.
* <DNT>**Issue correlation**</DNT>: Pour vous assurer que tous les événements d&apos;alerte associés (à la fois composites et composants) sont regroupés dans le même problème, configurez vos conditions de composant pour utiliser la même règle d’alerte que votre condition d’alerte composite. Cela permet à la corrélation des problèmes de New Relic de les regrouper.
* <DNT>**Related events**</DNT>: à partir d’un événement d’alerte composée, vous pouvez naviguer vers les événements d’alerte de composant individuels pour voir les dépassements de seuil et les métriques pour chaque condition.

## Titres et descriptions personnalisés [#custom-title-description]

Si vous définissez un [modèle de titre ou de description](/docs/alerts/create-alert/create-alert-condition/compound-alerts/create-compound-alert#title-description-templates) sur une condition d’alerte composite, cette personnalisation est reportée sur le problème qu’elle génère :

* <DNT>**Issue title**</DNT>: le titre du problème affiche le texte rendu à partir du modèle de titre de la condition composite, au lieu de l’en-tête par défaut généré par le système.
* <DNT>**Issue description**</DNT>: le texte rendu à partir du modèle de description de la condition composée apparaît directement sous la section des événements d’alerte pour la condition composée.

Pour que la page du problème reste ciblée, les descriptions des conditions de composants individuels (enfants) n’y sont pas affichées ; seule la description de la condition composée est affichée.

## Entités impactées [#impacted-entities]

Lorsque vos conditions de composant partagent des facettes correspondantes (par exemple, le même service ou hôte), New Relic affiche les entités correspondantes dans la section [Entités impactées](/docs/alerts/alert-event-management/Issues-and-alert-event-management-and-response/#impacted-entities-and-issue-map) au bas de la page du problème. Si les facettes partagées correspondent à plusieurs entités, elles apparaissent toutes, et pas seulement une.

Survolez ou cliquez sur n’importe quelle carte d’entité pour afficher les métriques clés de santé et de performances pour cette entité, telles que le temps de réponse, le débit, et le taux d’erreur.
