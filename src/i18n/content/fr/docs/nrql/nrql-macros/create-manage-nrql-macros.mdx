Avant de créer une macro, passez en revue les [autorisations de macro](/docs/nrql/nrql-macros/nrql-macros-overview/#macro-permissions), et les règles de nommage, et d’expression ci-dessous. Une macro qui ne respecte pas ces règles échoue à la validation lorsque vous essayez de l’enregistrer.

## Règles et limites des macros [#macro-rules]

<Callout variant="important">
Les macros sont visibles par tous les utilisateurs de votre organisation. N’incluez pas d’informations sensibles ou spécifiques à un compte lorsque vous créez ou mettez à jour une macro.
</Callout>

<CollapserGroup>
<Collapser id="macro-naming-rules" title="Règles de nommage">
Les noms de macros doivent respecter ces règles :

* Doit être unique au sein de l’organisation
* Must be a non-negative integer, such as `3`
* Ne doit pas contenir le caractère `.`
* Doit comporter 500 caractères ou moins
* Ne doit pas commencer par le caractère `$`
* Ne doit pas être entouré de backticks lors de la création.
* Si le nom d’une macro contient des caractères spéciaux, il doit être entouré d’accents graves. Par exemple `` $`my#Macro` ``.
</Collapser>

<Collapser id="macro-expression-rules" title="Règles d’expression">
Les expressions de macros doivent respecter ces règles :

* Doit être une expression NRQL valide ou une liste d’expressions
* Doit contenir 3000 caractères ou moins
* Doit être une expression, et non une clause. Par exemple, `count(*)` est valide, mais `SELECT count(*)` ne l’est pas.
* Doit être une sous-requête entourée de parenthèses, et non une requête autonome. Par exemple, `(FROM Transaction SELECT uniques(userId))` est valide, mais `FROM Transaction SELECT uniques(userId)` ne l’est pas.
* Doit retourner des attributs spécifiques, et non une liste d’attributs contenant `*`

Exemples d’expressions valides :

* `count(*)`
* `(1, 2, 3)`
* `(FROM Transaction SELECT uniques(userId))`
</Collapser>

<Collapser id="macro-limitations" title="Limites">
Les macros NRQL présentent les limites suivantes :

* **Alertes**: les macros ne sont pas prises en charge dans les conditions d’alerte.
* **Saisie automatique**: le générateur de requêtes ne suggère pas de macros ou n’utilise pas d’expressions de macro pour affiner les suggestions.
* **Variables de modèle**: vous ne pouvez pas utiliser de variables de modèle dans les macros.
* **Macros imbriquées**: les macros ne peuvent pas être imbriquées. L’expression d’une macro ne peut pas contenir de référence à une autre macro.
* **Spécifique à une région**: les macros sont spécifiques à une région et ne peuvent être utilisées que dans la région principale de votre organisation.
* **Clauses de temps**: les clauses liées au temps, y compris `TIMESERIES`, `PREDICT`, `BY`, `USING`, `SINCE`, `UNTIL`, et `COMPARE WITH`, ne prennent pas en charge les macros.
</Collapser>
</CollapserGroup>

## Accéder aux macros [#macros-access]

Dans la plateforme New Relic, accédez à <DNT>**Administration &gt; NRQL Macros**</DNT>. Depuis cette page, vous pouvez afficher, créer, modifier et supprimer des macros.

## Créer une macro [#create-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="create-ui">UI</TabsBarItem> <TabsBarItem id="create-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="create-ui">
Depuis la page <DNT>**NRQL Macros**</DNT>, créez une macro en fournissant un nom unique et une expression. Suivez les règles de [nommage](#macro-naming-rules) et d’ [expression](#macro-expression-rules). Ne préfixez pas le nom avec le caractère `$`. Par exemple, pour enregistrer une condition de clause `WHERE`, saisissez `appName = 'ProductionApp' AND environment = 'prod'` sans le mot-clé `WHERE`.

Une fois que vous avez créé une macro, elle apparaît dans la liste <DNT>**NRQL Macros**</DNT>. Vous pouvez l’utiliser dans n’importe quelle requête NRQL dans tout New Relic.
</TabsPageItem>

<TabsPageItem id="create-nerdgraph">
Vous pouvez également créer, mettre à jour, et effectuer des requêtes sur des macros par programmation à l’aide de l’ [API NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/). Avant de créer, ou de mettre à jour des macros, passez en revue les [règles de nommage](#macro-naming-rules), les [règles d’expression](#macro-expression-rules), et les [limitations](#macro-limitations).

Pour commencer, accédez à l’ [explorateur d’API NerdGraph](https://one.newrelic.com/nerdgraph-graphiql). Si vous avez besoin d’aide pour utiliser l’explorateur d’API NerdGraph, consultez le [tutoriel de l’explorateur d’API NerdGraph](/docs/apis/nerdgraph/get-started/nerdgraph-explorer/).

Utilisez la mutation `entityManagementCreateNrqlMacro` :

```graphql
mutation CreateMacro($name: String!, $expression: String!, $orgId: ID!) {
  entityManagementCreateNrqlMacro(
    nrqlMacroEntity: {
      expression: $expression
      name: $name
      scope: { type: ORGANIZATION, id: $orgId }
    }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

Variables d’exemple :

```json
{
  "name": "prod_filter",
  "expression": "(appName = 'ProductionApp' AND environment = 'prod')",
  "orgId": "your-organization-id"
}
```

Pour trouver l’ID de votre organisation, consultez [Trouver l’ID de votre organisation ou de votre macro](#find-ids).
</TabsPageItem>
</TabsPages>
</Tabs>

## Utiliser une macro dans une requête [#use-macro]

Pour utiliser une macro dans vos requêtes NRQL, tapez `$` suivi du nom de la macro dans le générateur de requêtes. Par exemple, supposons que vous ayez une macro nommée `prod_filter` avec l’expression `appName = 'ProductionApp' AND environment = 'prod'`. Vous pouvez l’utiliser dans une requête comme celle-ci :

```sql
SELECT count(*) FROM Transaction WHERE $prod_filter SINCE 1 hour ago
```

Lorsque la requête s’exécute, New Relic remplace la macro par son expression :

```sql
SELECT count(*) FROM Transaction WHERE appName = 'ProductionApp' AND environment = 'prod' SINCE 1 hour ago
```

<Callout variant="tip">
Entourez les noms de macros contenant des caractères spéciaux avec des backticks au moment de la requête. Par exemple : `` $`my#Macro` ``.
</Callout>

<Callout variant="important">
Les macros sont intégrées en ligne avant l’exécution, ce qui affecte la priorité des opérateurs binaires. Par exemple, une macro nommée `five` définie comme `1 + 4`, et utilisée comme `$five * 3` est évaluée à `13`, et non à `15`, car l’expression devient `1 + 4 * 3`. Pour éviter cela, entourez l’expression de parenthèses lorsque vous définissez la macro, comme dans `(1 + 4)`, ou entourez la macro de parenthèses lorsque vous l’utilisez, comme dans `($five) * 3`. L’une ou l’autre approche est correctement évaluée à `15`.
</Callout>

Les exemples suivants montrent des macros résolvant des problèmes de requête courants :

<CollapserGroup>
<Collapser id="macro-example-simplify" title="Exemple : simplifier une requête">
Une requête avec plusieurs conditions, comme celle-ci, peut être difficile à lire et à maintenir :

```sql
SELECT * FROM Log WHERE entityGuid = '...' AND appId NOT IN (...) AND ...
```

Enregistrez les conditions après `WHERE` en tant que macro nommée `macro1`, et la requête se simplifie en :

```sql
SELECT * FROM Log WHERE $macro1
```
</Collapser>

<Collapser id="macro-example-single-edit" title="Exemple : mettre à jour plusieurs widgets de dashboard depuis un seul emplacement">
Les dashboards avec de nombreux widgets partagent souvent une logique de requête répétée. Par exemple, la plupart des widgets d’un dashboard peuvent utiliser :

```sql
SELECT count(*) FROM Transaction WHERE http.statusCode NOT IN (400, 404)
```

Si vous enregistrez la condition `WHERE` en tant que macro nommée `macro2`, la requête de chaque widget ressemble à :

```sql
SELECT count(*) FROM Transaction WHERE $macro2
```

Pour exclure une application de test de chaque widget, mettez à jour l’expression `macro2` une fois, de `http.statusCode NOT IN (400, 404)` à `http.statusCode NOT IN (400, 404) AND appId NOT IN (12345)`. Chaque widget qui utilise `$macro2` reflète la modification, et vous n’avez pas à modifier chaque widget individuellement.
</Collapser>

<Collapser id="macro-example-alias" title="Exemple : résoudre le problème d’alias d’attribut">
Les données provenant de différents agents n’utilisent pas toujours le même nom d’attribut pour le même concept. Un nom d’hôte, par exemple, peut être ingéré comme `host.name`, `hostName`, ou `host_name` selon la source.

Enregistrez une macro nommée `host_alias` avec l’expression :

```sql
(host.name OR hostName OR host_name)
```

Ensuite, référencez-la dans vos requêtes :

```sql
FROM Log SELECT $host_alias
```

Si un autre alias, tel que `host-name`, apparaît plus tard, mettez à jour la macro `host_alias` une fois et chaque requête qui l’utilise prendra en compte la modification.
</Collapser>
</CollapserGroup>

## Gérer les macros [#manage-macros]

### Modifier une macro [#edit-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="edit-ui">UI</TabsBarItem> <TabsBarItem id="edit-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="edit-ui">
Depuis la page <DNT>**NRQL Macros**</DNT>, sélectionnez la macro et mettez à jour son expression, en suivant les [règles d’expression](#macro-expression-rules).
</TabsPageItem>

<TabsPageItem id="edit-nerdgraph">
Vous pouvez également mettre à jour l’expression d’une macro par programmation à l’aide de [NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/). Consultez les [règles d’expression](#macro-expression-rules) avant de la mettre à jour.

Utilisez la mutation `entityManagementUpdateNrqlMacro` .

```graphql
mutation UpdateMacro($expression: String!, $macroId: ID!) {
  entityManagementUpdateNrqlMacro(
    id: $macroId
    nrqlMacroEntity: { expression: $expression }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

Variables d’exemple :

```json
{
  "expression": "(appName = 'ProductionApp' AND environment = 'prod' AND region = 'us-east-1')",
  "macroId": "your-macro-id"
}
```

Pour trouver l’ID d’une macro, consultez [Trouver l’ID de votre organisation ou de votre macro](#find-ids).
</TabsPageItem>
</TabsPages>
</Tabs>

<Callout variant="important">
Lorsque vous modifiez une macro, toutes les requêtes utilisant cette macro utilisent automatiquement la version mise à jour. Passez en revue vos modifications pour vous assurer qu’elles ne cassent pas les requêtes existantes. En raison de la mise en cache, il peut y avoir un léger délai avant que la mise à jour ne prenne effet. Vous ne pouvez pas mettre à jour le nom d’une macro après sa création. Si vous devez modifier le nom, supprimez la macro et créez-en une nouvelle.
</Callout>

## Trouver l’ID de votre organisation ou de votre macro [#find-ids]

<CollapserGroup>
<Collapser id="macro-find-org-id" title="Trouver l'ID de votre organisation">
```graphql
query MyOrganizationId {
  actor {
    organization {
      id
    }
  }
}
```
</Collapser>

<Collapser id="macro-find-macro-id" title="Lister toutes les macros et leurs ID">
```graphql
query GetMacros($cursor: String) {
  actor {
    entityManagement {
      entitySearch(query: "type = 'NRQL_MACRO'", cursor: $cursor) {
        entities {
          ... on EntityManagementNrqlMacroEntity {
            id
            name
            expression
          }
        }
        nextCursor
      }
    }
  }
}
```
</Collapser>
</CollapserGroup>
