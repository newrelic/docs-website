Avec les variables de notebook, vous pouvez configurer des paramètres dynamiques qui se répercutent sur plusieurs requêtes à travers les blocs de requête. Contrairement aux [variables de modèle de dashboard](/docs/query-your-data/explore-query-data/dashboards/dashboard-template-variables), qui filtrent une vue statique, les variables de notebook agissent comme des paramètres injectés qui pilotent la logique sous-jacente de l&apos;ensemble de votre document.

Accédez à **[one.newrelic.com](https://one.newrelic.com) &gt; <DNT>All capabilities</DNT> &gt; <DNT>Notebooks</DNT>**.

## Pourquoi utiliser des variables dans les notebooks ? [#why-use-variables]

Les variables de notebook vous permettent de créer des expériences interactives telles que :

* **Runbooks paramétrés** où un ingénieur saisit un `hostName` ou `transactionId` spécifique pour générer instantanément un rapport de santé du système cible.
* **Modèles de post-mortem** qui peuvent être mis à jour avec des horodatages, des régions ou des noms d’application spécifiques pour analyser un incident.
* **Seuils interactifs** où les utilisateurs peuvent ajuster des variables comme `errorThreshold` ou `latencyTarget` pour voir comment différents paramètres affectent les données visualisées.

Les principaux avantages sont les suivants :

* **Création de runbooks exécutables**: les variables transforment vos notebooks de pages statiques en outils interactifs. Vous pouvez créer des workflows adaptables pour les investigations d’événements d’alerte, l’analyse des performances et la collaboration en équipe.
* **Standardiser le partage des connaissances**: en tant que document enregistré, vous pouvez partager des workflows analytiques avec des collègues. Les utilisateurs n&apos;ont pas besoin de réécrire des requêtes <DNT>NRQL</DNT> complexes — ils changent simplement pour une nouvelle valeur de variable à partir de vos variables prédéfinies et exécutent le workflow.

## Définir une variable de notebook [#define-variable]

Définissez une variable que vous injecterez dans vos blocs de requête <DNT>NRQL</DNT> pour paramétrer votre récupération de données et vos visualisations.

Pour définir une variable :

1. À partir d&apos;un notebook ouvert, localisez la barre de variables en haut de l&apos;interface.
2. Cliquez sur <DNT>**+ Add variable**</DNT>.
3. Configurez votre type de variable (par exemple, saisie de texte, liste déroulante ou numérique) et fournissez une valeur par défaut.

### Règles de nommage des variables [#naming-rules]

Lors de la dénomination de votre variable, gardez à l’esprit ce qui suit :

* Le nom est la chaîne exacte que vous utiliserez dans vos blocs de notebook, entourée de `{{...}}`. Par exemple, si vous nommez la variable `targetApp`, vous la référencez dans vos blocs de requête en tant que `{{targetApp}}`.
* Les noms de variables sont sensibles à la casse et doivent être uniques au sein d&apos;un notebook.
* Choisissez des noms descriptifs qui rendent votre runbook explicite pour les autres utilisateurs (par exemple, `failingHost` plutôt que `var1`).

## Utiliser une variable dans un bloc de requête [#use-variable]

Une fois définie, référencez votre variable n’importe où dans une requête <DNT>NRQL</DNT> en utilisant la syntaxe `{{variableName}}` :

```sql
SELECT average(cpuPercent) FROM SystemSample WHERE hostname = {{failingHost}} TIMESERIES
```

```sql
SELECT latest(cpuPercent) FROM ProcessSample WHERE hostname = {{failingHost}} FACET processDisplayName
```

Lorsque vous exécutez la requête, la valeur de la variable que vous avez définie dans la barre des variables est substituée dans la requête au moment de l’exécution. La modification de la valeur de la variable et la réexécution de la requête mettent instantanément à jour tous les blocs qui font référence à cette variable.

## Automatiser la réponse aux incidents avec des runbooks [#runbook-use-case]

L&apos;application la plus puissante pour les variables de notebook est la création de runbooks exécutables pour la réponse aux incidents. En combinant les variables de notebook avec les [workflows<DNT>New Relic</DNT> ](/docs/alerts/get-notified/incident-workflows), vous pouvez automatiser le transfert entre le déclenchement d&apos;une alerte et le début de l&apos;investigation.
