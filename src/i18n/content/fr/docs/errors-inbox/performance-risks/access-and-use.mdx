Vous pouvez accéder à <DNT>Performance Risks inbox</DNT> et l’utiliser pour identifier et résoudre de manière proactive les problèmes de performances des applications avant qu’ils n’affectent vos utilisateurs finaux. Ce guide vous explique comment accéder à <DNT>Performance Risks inbox</DNT>, afficher la vue d’ensemble à l’échelle du compte, analyser et obtenir des recommandations pour des risques spécifiques, mettre à jour les seuils de détection, et utiliser l’outil dans le serveur MCP New Relic. Pour plus d’informations sur ce qu’est <DNT>Performance Risks inbox</DNT> et ses principaux avantages, consultez l’ [introduction à <DNT>Performance Risks inbox</DNT>](/docs/errors-inbox/performance-risks/introduction).

## Accéder à la boîte de réception des risques de performance [#access]

Vous pouvez accéder à <DNT>Performance Risks inbox</DNT> de deux manières : au niveau de l’entité, limité à une seule entité ou un seul workload, ou au niveau du compte, couvrant chaque entité de votre compte.

* [Accès au niveau de l’entité](#access-entity)
* [Accès au niveau du compte](#access-account)

### Accès au niveau de l’entité [#access-entity]

Au niveau de l’entité, <DNT>Performance Risks inbox</DNT> montre des problèmes de performances pour les données télémétriques d’une seule entité ou d’un seul workload. Ceci est disponible pour :

* Services APM
* Applications Browser
* Workloads

**Pour accéder à <DNT>Performance Risks inbox</DNT> pour une entité :**

1. Allez dans <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities)</DNT>, puis sélectionnez <DNT>**APM &amp; Services**</DNT>, <DNT>**Browser**</DNT>, ou <DNT>**Workloads**</DNT>.
2. Sélectionnez l’entité ou le workload requis.
3. Dans le volet de navigation, sous la section <DNT>**Triage**</DNT>, cliquez sur <DNT>**Performance Risks**</DNT>.

### Accès au niveau du compte [#access-account]

Au niveau du compte, <DNT>Performance Risks inbox</DNT> est disponible dans deux vues : un dashboard à l’échelle du compte, et une liste de groupes de risques de performance limités à un workload ou à une entité que vous choisissez.

**Pour accéder à <DNT>Performance Risks inbox</DNT> pour un compte :**

1. Allez à <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox</DNT>.
2. Dans le volet de navigation de l’entité, sous la section <DNT>**Performance Risks**</DNT>, cliquez sur <DNT>**Performance Overview**</DNT> pour le dashboard à l’échelle du compte (voir [Afficher la vue d’ensemble des performances](#overview)), ou sur <DNT>**Risk Groups**</DNT> pour une liste ciblée.
3. Dans <DNT>**Risk Groups**</DNT>, utilisez le sélecteur de portée pour choisir <DNT>**Workload**</DNT> ou <DNT>**Entities**</DNT>, puis sélectionnez le [workload](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview) ou l’entité spécifique que vous souhaitez examiner, ou utilisez le champ de recherche pour le trouver par nom ou description.
4. En option, ajoutez d’autres filtres, tels que par <DNT>**Performance risk group metadata state**</DNT> (par exemple, <DNT>Unresolved</DNT>), et utilisez <DNT>**Sort by**</DNT> pour modifier l’ordre des résultats.

Il affiche chaque risque de performance détecté sur l’ensemble de vos entités, afin que vous n’ayez pas à vérifier chaque entité individuellement pour trouver où se trouvent les problèmes.

## Visualiser et analyser les risques de performance [#view-analyze]

Une fois que vous accédez à <DNT>Performance Risks inbox</DNT>, vous pouvez afficher les problèmes détectés de deux manières : la vue <DNT>**Triage**</DNT> et la vue <DNT>**Group performance risks**</DNT>. Les deux vues affichent les mêmes données sous-jacentes mais offrent différentes manières de les analyser.

### Triage [#triage]

La vue <DNT>**Triage**</DNT> traite et regroupe automatiquement les risques de performance similaires. Les requêtes similaires sont calculées, stockées et fusionnées en un seul groupe de risques de performance. Par exemple, plusieurs requêtes qui partagent le même modèle — comme des variations d&apos;une clause `IN` — sont regroupées en une seule entrée plutôt que d&apos;apparaître comme des éléments distincts. Cela permet d&apos;identifier et de prioriser plus facilement les problèmes les plus impactants sans examiner chaque occurrence individuellement.

Utilisez la vue <DNT>**Triage**</DNT> lorsque vous souhaitez un résumé pré-groupé des problèmes de performances pour identifier des modèles dans votre application.

<img title="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." alt="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." src="/images/performancerisks_triage.webp" />

### Risques de performance du groupe [#group]

La vue <DNT>**Group performance risks**</DNT> affiche les données brutes de risque de performance sans regroupements pré-calculés. Les représentations normales de requête (telles que les espaces réservés de virgule et de point d’interrogation) sont affichées, et vous pouvez filtrer et regrouper les données en fonction de différents attributs, tels que :

* L&apos;utilisateur affecté par le risque de performance
* Le service générant les appels
* L&apos;API déclenchant les requêtes

Utilisez la vue <DNT>**Group performance risks**</DNT> lorsque vous devez analyser les risques de performance en fonction d&apos;attributs spécifiques qui sont pertinents pour votre investigation.

<img title="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." alt="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." src="/images/performancerisks_grpperrisk.webp" />

## Obtenir des recommandations [#recommendations]

Depuis la vue <DNT>**Triage**</DNT>, vous pouvez générer des recommandations basées sur l’IA pour un risque de performance spécifique au lieu d’examiner ses occurrences manuellement.

**Pour obtenir des recommandations pour un risque de performance :**

1. Depuis la vue <DNT>**Triage**</DNT>, ouvrez un risque de performance qui présente plusieurs occurrences.
2. Cliquez sur <DNT>**Generate insights**</DNT>.

<DNT>Performance Risks inbox</DNT> analyse les occurrences de ce risque de performance et renvoie une hypothèse sur la cause fondamentale, ainsi que les prochaines étapes recommandées pour le résoudre. Les recommandations exactes varient en fonction du risque de performance détecté.

<img title="Sample performance risk recommendations." alt="Sample performance risk recommendations." src="/images/PRinsights.webp" />

<Callout variant="important">
  New Relic active les fonctionnalités d’IA par défaut pour tous les comptes. Si vous ne voyez pas cette option, il se peut qu’elle ne soit pas activée sur votre compte. Contactez l’administrateur de votre organisation pour demander l’accès.
</Callout>

Si une recommandation suggère d’ajuster un seuil, consultez [Définir les seuils](#set-thresholds).

## Définir les seuils [#set-thresholds]

<DNT>Performance Risks inbox</DNT> utilise des seuils configurables pour détecter automatiquement les anomalies de performances. Vous pouvez mettre à jour ces seuils aux niveaux du compte et de l’entité, y compris pour les [workloads](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview), afin de vous assurer que les critères de détection correspondent à vos besoins et priorités spécifiques en matière de monitoring des performances. Ces seuils déterminent ce qui constitue un risque de performances et contribuent à garantir que <DNT>Performance Risks inbox</DNT> vous alerte sur les problèmes de performances les plus pertinents et exploitables dans vos applications.

Vous pouvez définir les seuils de risques de performance au niveau d&apos;un compte ou d&apos;une entité :

* [Seuils au niveau du compte](#account-thresholds)
* [Seuils au niveau de l’entité](#entity-thresholds)

### Définir les seuils au niveau du compte [#account-thresholds]

La définition de seuils au niveau du compte vous permet d&apos;établir des critères de détection des risques de performance par défaut qui s&apos;appliquent à toutes les entités du compte. Cela est utile pour maintenir des normes de monitoring cohérentes et s&apos;assurer que toutes les applications sont évaluées par rapport aux mêmes évaluations de performance.

**Pour définir les seuils au niveau du compte :**

<CollapserGroup>
  <Collapser id="new-account-thresholds" title="Nouveaux seuils au niveau du compte">
    1. Allez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox &gt; Performance Thresholds**.</DNT>.
    2. Dans l&apos;onglet **Accounts**, cliquez sur <DNT>**+ New**</DNT>.
    3. Dans la liste déroulante <DNT>**Account**</DNT>, sélectionnez le compte pour lequel vous souhaitez créer un nouveau seuil.
    4. Définissez les limites requises pour chaque analyseur.
    5. Cliquez sur <DNT>**Submit**</DNT> pour enregistrer.
  </Collapser>

  <Collapser id="edit-account-thresholds" title="Modifier les seuils existants au niveau du compte">
    1. Allez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox &gt; Performance Thresholds**.</DNT>.
    2. Dans l’onglet **Accounts**, cliquez sur le bouton <DNT>**Edit**</DNT> à côté du compte que vous souhaitez mettre à jour.
    3. Définissez les limites requises pour chaque analyseur.
    4. Cliquez sur <DNT>**Submit**</DNT> pour enregistrer.

    <Callout variant="tip">
      Lorsque vous modifiez les seuils, New Relic affiche votre nom d’utilisateur pour suivre qui a effectué les modifications.
    </Callout>
  </Collapser>
</CollapserGroup>

### Définir les seuils au niveau de l’entité [#entity-thresholds]

Définir des seuils au niveau de l&apos;entité vous permet de personnaliser les critères de détection des risques de performance pour des applications ou des services spécifiques qui peuvent présenter des caractéristiques ou des exigences de performance uniques. Cela est particulièrement utile pour adapter le monitoring à différents types d&apos;applications, d&apos;environnements ou de priorités métier.

**Pour définir les seuils au niveau d&apos;une entité :**

Vous pouvez définir les seuils pour une entité spécifique de l&apos;une des manières suivantes :

<CollapserGroup>
  <Collapser id="entity-triage" title="À partir de la page Risques de performance">
    1. Allez à <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; APM &amp; Services**.</DNT>.
    2. Sélectionnez l&apos;entité requise.
    3. Dans le volet de navigation de l&apos;entité, cliquez sur <DNT>**Performance Risks**</DNT> dans la section <DNT>**Triage**</DNT>.
    4. Cliquez sur <DNT>**Adjust performance thresholds**</DNT> dans le coin supérieur droit.
    5. Définissez les limites requises pour chaque analyseur.
    6. Cliquez sur <DNT>**Submit**</DNT> pour enregistrer.

    <Callout variant="tip">
      Lorsque vous modifiez les seuils, New Relic affiche votre nom d’utilisateur pour suivre qui a effectué les modifications.
    </Callout>
  </Collapser>

  <Collapser id="entity-page" title="Depuis la page Seuils de performance">

    3. Dans la liste déroulante <DNT>**Account**</DNT>, sélectionnez le compte de votre entité.
    4. Dans la liste déroulante <DNT>**Entity**</DNT>, sélectionnez l&apos;entité que vous souhaitez mettre à jour.
    5. Définissez les limites requises pour chaque analyseur.
    6. Cliquez sur <DNT>**Submit**</DNT> pour enregistrer.

    <Callout variant="tip">

### Afficher les lignes de seuil sur les graphiques [#threshold-guidelines]

Les graphiques de risque de performance affichent des lignes de référence pour vous aider à interpréter si une valeur se situe dans une plage attendue :

* **Lignes directrices minimales et maximales**: calculées automatiquement à partir des données historiques collectées pour ce graphique, montrant la plage typique de valeurs au fil du temps.
* **Seuil actuel**: reflète le seuil qui est actuellement actif pour cet analyseur, en fonction de vos paramètres de seuil au niveau du compte ou de l’entité. Si les deux sont définis, le seuil au niveau de l’entité prévaut.

Utilisez ces lignes pour voir à quel point une métrique est proche de son seuil configuré, sans avoir besoin d’ouvrir les paramètres de seuil.

Voici un exemple de graphique. Les valeurs et les lignes que vous voyez dépendent de vos propres données et paramètres de seuil.

## Utilisez l&apos;outil de boîte de réception Performance Risks dans le serveur MCP New Relic. [#using]

Vous pouvez également accéder à l’outil <DNT>Performance Risks inbox</DNT> ([`list_entity_performance_risk_groups`](/docs/agentic-ai/mcp/tool-reference/#performance)) dans le [serveur MCP New Relic](/docs/agentic-ai/mcp/overview/). Cet outil répertorie tous les risques de performance détectés pour une entité donnée, ainsi que leurs détails tels que le type de risque, la gravité, et le nombre d’occurrences. Vous pouvez utiliser cet outil pour récupérer par programmation les données de risque de performance.
