## Présentation

Agent Control simplifie la gestion de vos agents d&apos;instrumentation. Ce guide vous guidera dans le processus d&apos;installation et de désinstallation d&apos;Agent Control sur vos clusters Kubernetes, hôtes Linux ou hôtes Windows à l&apos;aide de différentes méthodes.

## Installer Agent Control

<Callout title="conseil">
  Pour automatiser la configuration du contrôle des agents sur une infrastructure à grande échelle, consultez [Configurer le contrôle des agents avec Terraform](/docs/infrastructure-as-code/terraform/agent-control).
</Callout>

### Installation guidée

1. Connectez-vous à New Relic.
2. Assurez-vous que le bon compte est sélectionné.
3. Dans Intégration et agents, cliquez sur **Installer Agent Control** ou recherchez **Agent Control**.

<img title="Agent Control guided install" alt="Screenshot of the guided install tasks for Agent Control" src="/images/agent-control-guided-install.webp" />

4. Suivez les étapes pour terminer le processus d&apos;installation et de configuration.

<Callout variant="important" title="Important">
  Pour installer Agent Control, il est obligatoire d&apos;avoir une flotte. Si vous n&apos;avez pas encore créé de flotte pour cette entité gérée, vous pouvez [créer une flotte](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet) durant l&apos;installation dans l&apos;installation guidée ou terminer le processus de création de flotte dans le [**Fleet Control**](/docs/new-relic-control/fleet-control/setup/#step-1-create-your-first-fleet), puis revenir à cette étape de l&apos;installation guidée.

  **Exigence de type de flotte :** les flottes sont séparées par type. Vous devez sélectionner le bon type pour vos hôtes (Windows ou Linux) ou k8s. L&apos;utilisation d&apos;une flotte d&apos;un type différent entraînera des problèmes d&apos;installation ou de fonctionnement.

  Les modèles et configurations dans différents environnements peuvent nécessiter des ajustements pour la compatibilité.
</Callout>

5. Téléchargez la configuration générée sur votre ordinateur et exécutez la commande fournie dans votre terminal pour installer Agent Control. Après l&apos;installation, cliquez sur **Continue**.
6. Testez la connexion pour confirmer que l&apos;installation a réussi. Cette étape peut prendre 5 à 10 minutes.
7. Maintenant qu&apos;Agent Control est installé et en cours d&apos;exécution, vous êtes prêt à [configurer et gérer vos agents](/docs/new-relic-control/agent-control/configuration) ou à déployer des modifications sur vos agents [à l&apos;aide du contrôle de la flotte](/docs/new-relic-control/fleet-control/overview).

#### À quoi s&apos;attendre après l&apos;installation

Après avoir exécuté le script d&apos;installation, Agent Control configure uniquement le service de supervision. Aucun agent d&apos;instrumentation n&apos;est déployé automatiquement.

**Immédiat (0-2 minutes) :**

* **0-30 secondes :** Le service Agent Control s&apos;enregistre et démarre
* **30-60 secondes :** Première connexion à Fleet Control établie
* **1 à 2 minutes :** la synchronisation de la configuration se termine et l&apos;hôte/cluster apparaît dans le contrôle de la flotte

<Callout variant="important">
  **Pas de télémétrie par défaut :** Agent Control est un service de supervision qui gère les agents. Il ne collecte ni n&apos;envoie de données de télémétrie lui-même. Pour consulter les métriques d&apos;infrastructure, les logs ou toute autre télémétrie dans New Relic, vous devez déployer et configurer des agents (tels que l&apos;agent Infrastructure) via Fleet Control après l&apos;installation.
</Callout>

**Prochaines étapes requises :** Une fois Agent Control installé et connecté à Fleet Control, vous devez déployer manuellement des agents pour commencer à collecter la télémétrie :

1. Connectez-vous à New Relic et accédez à **Fleet Control**
2. Sélectionnez votre flotte et localisez votre hôte/cluster dans la table **Entities**
3. Déployez des agents (agent Infrastructure, NRDOT, etc.) sur votre hôte/cluster à l’aide de Fleet Control
4. Attendez 5 à 10 minutes que les agents déployés démarrent et envoient la télémétrie à New Relic

<Callout variant="important" title="Migration">
  **Agents existants :** Si l&apos;agent New Relic Infrastructure est déjà installé sur votre hôte, vous devez le désinstaller avant d&apos;installer Agent Control. Après avoir installé Agent Control, vous pouvez gérer l&apos;Agent d&apos;infrastructure en [migrant votre configuration locale vers le contrôle de la flotte](/docs/new-relic-control/agent-control/instrumentation/). Les agents APM (qui ne sont pas actuellement gérés par Agent Control) peuvent rester installés et continueront de fonctionner indépendamment.
</Callout>

### Remarque sur l&apos;authentification

New Relic Control nécessite l&apos;utilisation d&apos;identités système, qui sont des identités non humaines utilisées pour authentifier et établir la confiance entre les services et les applications.

Lors du processus d&apos;installation guidée d&apos;Agent Control, la première identité système est créée à l&apos;aide des identifiants client, qui sont inclus dans les valeurs du chart Helm ou la commande de l&apos;hôte. **Les identifiants de cette identité système expirent après 12 heures.** Lorsqu&apos;ils expirent, le déploiement du chart Helm Agent Control ou la commande de l&apos;hôte ne parviendra pas à s&apos;authentifier auprès du service de contrôle de la flotte, entraînant l&apos;erreur suivante :

```
Error getting system identity auth token. The API endpoint returned 400: Expired client secret.
```

Dans ce cas, le chart Helm ou la commande d’hôte doit être mis à jour avec de nouveaux identifiants d’identité système.

<Callout variant="tip">
  Si vous relancez cette installation selon une planification ou depuis un pipeline, consultez [Automatiser l’installation d’Agent Control à grande échelle](/docs/new-relic-control/agent-control/automated-installation) pour savoir comment éviter de réémettre cet identifiant manuellement toutes les 12 heures.
</Callout>

Exemple de chart Helm :

```yaml
global:
  cluster: "cluster-name"
  licenseKey: "*************************"
agentControlDeployment:
  chartValues:
    systemIdentity:
      organizationId: "00000000-0000-0000-0000-000000000000"
      parentIdentity:
        clientId: "CLIENT_ID"
        clientSecret: "CLIENT_SECRET"
    config:
      fleet_control:
        fleet_id: "SAMPLE_FLEET_ID"
      agents:
        ...
```

### Configuration Kubernetes avancée

Par défaut, le chart Helm Agent Control utilise une instance intégrée de Flux CD pour gérer le cycle de vie de vos agents dans Kubernetes. Selon les exigences de votre écosystème, vous pouvez configurer Agent Control pour exploiter une installation Flux v2 personnalisée existante ou contourner entièrement les composants d&apos;infrastructure de livraison continue.

#### Prise en charge des installations Flux existantes

Par défaut, le chart Helm Agent Control utilise une instance intégrée de [Flux CD](https://fluxcd.io/) pour gérer le cycle de vie de vos agents dans Kubernetes. Cependant, si votre organisation utilise déjà **Flux v2** pour GitOps, vous pouvez configurer Agent Control pour tirer parti de votre installation existante.

Cette approche découple Agent Control du moteur de livraison continue intégré, vous permettant de maintenir une instance Flux unique pour vos opérations de cluster tout en bénéficiant des capacités de gestion d&apos;Agent Control.

**Exigences et compatibilité** Pour utiliser une installation externe de Flux avec Agent Control, votre environnement doit répondre aux exigences suivantes. Les configurations qui s&apos;écartent de ces spécifications ne sont pas validées.

* **Version Flux :** Flux v2 ou supérieur.

* **Composants requis :** Votre installation Flux doit inclure :

  * **Contrôleur Helm :** Avec la CRD HelmRelease (helm.toolkit.fluxcd.io/v2).
  * **Contrôleur de source :** Avec la CRD HelmRepository (source.toolkit.fluxcd.io/v1).

* **Portée de l&apos;espace de noms :** Votre instance Flux doit être configurée pour surveiller l&apos;espace de noms dans lequel Agent Control sera installé (ou configurée pour surveiller tous les espaces de noms).

**Configuration** Pour activer ce mode, vous devez désactiver explicitement les composants Flux inclus dans la configuration du chart Helm Agent Control.

Dans votre fichier `values.yaml`, définissez `agentControlCd.enabled` sur `false`:

```yaml
global:
  cluster: "<YOUR_CLUSTER_NAME>"
  licenseKey: "<YOUR_LICENSE_KEY>"

# Disable the embedded Flux instance
agentControlCd:
  enabled: false

agentControlDeployment:
  chartValues:
    # ... other configurations ...
```

**Permissions pour Flux externe** Lorsque vous utilisez votre propre installation Flux, le compte de service Flux de votre cluster est responsable de l’application des configurations générées par Agent Control. Par conséquent, votre instance Flux existante nécessite des autorisations spécifiques pour déployer des ressources New Relic. Nous recommandons vivement l&apos;une des approches ci-dessous :

* **Administrateur de cluster (recommandé) :** La configuration la plus simple consiste à s&apos;assurer que votre instance Flux s&apos;exécute avec les privilèges `cluster-admin`. Il s&apos;agit de la configuration standard pour le chart communautaire Flux et elle garantit qu&apos;il peut gérer toutes les ressources nécessaires (Deployments, DaemonSets, Services, etc.) requises par les agents New Relic.
* **Configuration du moindre privilège :** Si vos politiques de sécurité restreignent l&apos;utilisation de `cluster-admin`, vous devez créer un `ClusterRole` spécifique garantissant que votre compte de service Flux dispose des autorisations requises par le Source Controller, le Helm Controller, l&apos;Agent Control et chaque agent spécifique que vous prévoyez d&apos;installer.

<Callout variant="important">
  Remarque : les autorisations de l&apos;Agent peuvent changer à mesure que de nouvelles fonctionnalités ou agents sont ajoutés. Vous êtes responsable de la maintenance de ces permissions dans votre rôle personnalisé.
</Callout>

Voici un exemple `ClusterRole` illustrant les permissions minimales requises pour que les composants Agent Control et Flux interagissent :

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: external-flux-agent-control-role
rules:
  # Permissions required by Flux to operate Agent Control components
  - apiGroups: ["apiextensions.k8s.io"]

    resources: ["leases"]
    verbs: ["get", "create", "update"]
  - apiGroups: ["rbac.authorization.k8s.io"]
    resources: ["clusterroles", "rolebindings"]
    verbs: ["get", "create", "delete"]
  - apiGroups: [""]
    resources: ["configmaps"]
    verbs: ["watch"]
  - apiGroups: [""]
    resources: ["events"]
    verbs: ["create", "patch"]
  - apiGroups: [""]
    resources: ["namespaces"]
    verbs: ["create"]
  - apiGroups: [""]
    resources: ["serviceaccounts"]
    verbs: ["get", "create", "delete"]
  - apiGroups: [""]
    resources: ["services"]
    verbs: ["get", "create"]
  - apiGroups: ["apps"]
    resources: ["deployments"]
    verbs: ["create"]
  - apiGroups: ["autoscaling"]
    resources: ["horizontalpodautoscalers"]
    verbs: ["get", "create"]
  - apiGroups: ["batch"]
    resources: ["jobs"]
    verbs: ["get", "list", "watch", "create", "delete"]

  # Permissions required by Agent Control logic
  - apiGroups: ["helm.toolkit.fluxcd.io", "newrelic.com", "source.toolkit.fluxcd.io"]
    resources: ["*"]
    verbs: ["*"]
  - apiGroups: [""]
    resources: ["secrets"]
    verbs: ["*"]
  - apiGroups: [""]
    resources: ["configmaps"]
    verbs: ["get", "list", "create", "patch", "update", "delete", "deletecollection"]

```

**Limites du support** Lors de l’utilisation d’une installation Flux externe, le support New Relic se limite au logiciel Agent Control (la génération de manifestes de configuration valides). Dans ce mode, vous devez prendre en compte un schéma de responsabilité partagée comme suit :

* **Responsabilité de New Relic :** Nous nous assurons qu&apos;Agent Control interagit correctement avec le backend New Relic et génère des définitions `HelmRelease` et `HelmRepository` valides.
* **Responsabilité du client :** Vous êtes responsable de l&apos;état de santé, de la maintenance des versions, de la mise en réseau et du dépannage de votre propre installation Flux. Les problèmes découlant spécifiquement de la configuration ou de la défaillance des contrôleurs Flux externes ne sont pas couverts par le support d&apos;Agent Control.

#### Installer Agent Control sans Flux [#install-without-flux]

Vous pouvez installer Agent Control sans Flux lorsque son rôle se limite à distribuer la configuration aux agents gérés et non à les installer ou à les mettre à niveau. Dans ce mode, Agent Control ne peut pas gérer le cycle de vie des agents — il n&apos;installe ni ne met à niveau les agents et pousse uniquement la configuration via le contrôle de la flotte. Vous êtes vous-même responsable de l&apos;installation et de la mise à niveau d&apos;Agent Control et de tous les agents gérés. Le principal cas d’utilisation est le [gateway Contrôle de pipeline](/docs/new-relic-control/pipeline-control/gateway/install-gateway-without-flux): Agent Control fournit les modifications de configuration du gateway Contrôle de pipeline.

Pour installer Agent Control sans Flux, définissez `agentControlCd.enabled` sur `false` dans vos valeurs Helm. Agent Control ne créera ni ne monitorera aucun objet Flux.

```yaml
global:
  cluster: "<YOUR_CLUSTER_NAME>"
  licenseKey: "<YOUR_LICENSE_KEY>"

agentControlCd:
  enabled: false

agentControlDeployment:
  chartValues:
    # ... other configurations ...
```

<Callout variant="important">
  Sans Flux, Agent Control ne peut pas installer ou mettre à niveau l&apos;agent de gateway Contrôle de pipeline — vous êtes responsable de son installation et de sa mise à niveau (par exemple, avec `helm upgrade`). Le chart Agent Control lui-même ne peut pas non plus être mis à niveau à distance dans cette configuration. Pour mettre à niveau Agent Control, exécutez `helm upgrade` avec le même fichier de valeurs. Pour qu’Agent Control installe et mette à niveau l’agent de gateway pour vous, laissez Flux activé — soit avec l’installation intégrée, soit avec [votre propre installation de Flux](#support-for-existing-flux-installations).
</Callout>

Lorsque vous installez le gateway Contrôle de pipeline via l&apos;installation guidée de New Relic, le fichier de valeurs généré définit déjà `agentControlCd.enabled: false`. Vous n&apos;avez pas besoin de le modifier manuellement.

<Callout title="Contrôle d'accès" variant="important">
  **Aucune autorisation de cluster supplémentaire requise :** puisque Flux est désactivé dans ce mode, vous n’avez pas besoin de créer les autorisations `ClusterRole` étendues à l’échelle du cluster requises pour les configurations Flux personnalisées. Agent Control reste totalement confiné, ne nécessitant que des autorisations de base pour lire `Secrets` et `ConfigMaps` dans son propre espace de nommage `newrelic-agent-control`.
</Callout>

## Vérifier l&apos;installation

### Kubernetes

1. Exécutez les commandes suivantes pour vérifier le statut de vos pods : Agent Control installe des sous-agents dans un espace de nommage différent pour des raisons de sécurité. Pour vérifier que tout fonctionne, vérifiez que les pods Agent Control s’exécutent dans l’espace de nommage `newrelic-agent-control` et que les pods de sous-agent s’exécutent dans un espace de nommage différent, tel que `newrelic`.

```shell
  kubectl get pods -n newrelic-agent-control    # Check Agent Control pods
  kubectl get pods -n newrelic                  # Check subagent pods
```

2. connectez-vous à New Relic et accédez au **Fleet Control**.
3. Accédez à la page Flottes et sélectionnez la flotte que vous avez choisie lors de l&apos;installation.
4. Dans la table **Entities** , confirmez que votre cluster Kubernetes apparaît dans la liste.
5. Vérifiez que l’état de l’instrumentation de votre cluster est **sain**.

### Linux

* Vérifiez l&apos;état du service `newrelic-agent-control` :

  ```bash
  sudo systemctl status newrelic-agent-control
  ```

  Si le service apparaît à l&apos;état `Failed` ou `Stopped`, cela signifie que l&apos;agent a été installé mais qu&apos;un problème empêche son fonctionnement normal. Vérifiez les logs des services de l&apos;Agent avec `journalctl` (ou tout autre outil Linux similaire) :

  ```bash
  journalctl -u newrelic-agent-control
  ```

  Si aucune information n&apos;est disponible, consultez la procédure pour [exécuter l&apos;agent en mode débogage](/docs/new-relic-control/agent-control/troubleshooting/#debug) afin d&apos;accéder aux logs détaillés et de mieux comprendre pourquoi le service ne peut pas être démarré.

* Si le service n&apos;est pas installé, essayez d&apos;ajouter `--debug` à la fin de la commande d&apos;installation CLI de l&apos;installation guidée et relancez-la. Cela active le logs détaillé pour le script d&apos;installation et peut fournir un contexte supplémentaire expliquant l&apos;erreur.

* Facultativement, répondez `yes` lorsqu&apos;il vous est demandé d&apos;envoyer des logs à New Relic pour aider au dépannage de l&apos;installation. Une fois soumis, les logs sont accessibles avec la requête NRQL suivante :

  ```sql
    SELECT * FROM Log WHERE hostname = `your-host-name`
  ```

### Windows

1. Vérifiez l&apos;état du service `newrelic-agent-control` :

   Ouvrez PowerShell avec les privilèges d&apos;administrateur et exécutez :

   ```powershell
   Get-Service -Name newrelic-agent-control | Format-List Status, StartType
   ```

   Sortie attendue lorsque l&apos;état est sain :

   ```
   Status    : Running
   StartType : Automatic
   ```

2. Vérifier l&apos;endpoint de santé de l&apos;Agent Control :

   ```powershell
   Invoke-WebRequest -Uri "http://localhost:51200/status" -UseBasicParsing
   ```

   Un Agent Control sain doit renvoyer une réponse JSON avec `"healthy": true`.

3. connectez-vous à New Relic et accédez au **Fleet Control**.

4. Accédez à la page Flottes et sélectionnez la flotte que vous avez choisie lors de l&apos;installation.

5. Dans le tableau **Entities**, confirmez que votre hôte Windows apparaît dans la liste.

6. Vérifiez que le statut de l&apos;instrumentation de votre hôte est **sain**.

Si le service Agent Control ne se connecte pas à Fleet Control dans les 2 à 3 minutes, consultez [Dépannage des hôtes Windows](/docs/new-relic-control/agent-control/troubleshooting/#windows-hosts-troubleshooting).

<Callout variant="caution" title="Antivirus et logiciels de sécurité">
  Windows Defender ou un logiciel antivirus tiers peut bloquer l&apos;exécution d&apos;Agent Control en tant que service. Avant l&apos;installation, ajoutez ces répertoires aux exclusions de votre antivirus :

  * `C:\Program Files\New Relic\newrelic-agent-control\`
  * `C:\ProgramData\New Relic\newrelic-agent-control\`

  Si Agent Control ne démarre pas après l&apos;installation et s&apos;exécute correctement depuis la ligne de commande, cela indique une interférence de l&apos;antivirus. Collaborez avec votre équipe de sécurité pour configurer les exceptions appropriées pour les exécutables New Relic.
</Callout>

## Désinstaller Agent Control [#uninstall]

### Kubernetes

Pour désinstaller Agent Control de votre cluster Kubernetes, exécutez les commandes suivantes :

<Steps>
  <Step>
    #### Afficher la sortie installée [#list-releases]

    Exécutez la commande suivante pour répertorier toutes les sorties installées et identifier celle destinée au contrôle de l&apos;agent :

    ```shell
    helm list --all-namespaces
    ```
  </Step>

  <Step>
    #### Désinstaller Agent Control [#uninstall-agent-control]

    * Remplacez `<RELEASE>` et `<NAMESPACE>` par les valeurs appropriées pour votre installation et votre environnement :

      ```shell
        helm uninstall <RELEASE> -n <NAMESPACE>
      ```

    * Par exemple:

      ```shell
        helm uninstall agent-control-bootstrap -n newrelic-agent-control
      ```
  </Step>
</Steps>

### Hôtes Linux

<Callout variant="important">
  Le processus de désinstallation laisse généralement des fichiers de configuration et d&apos;autres fichiers divers. Il n&apos;est pas nécessaire d&apos;arrêter le service au préalable. Le processus de désinstallation peut prendre plusieurs minutes. Exemple d&apos;actifs susceptibles de ne pas être supprimés lors de la désinstallation :

  * Fichiers de configuration locaux ou distants : vérifiez et supprimez les dossiers `/etc/newrelic-agent-control` et `/var/lib/newrelic-agent-control`.
  * New Relic CLI : vérifier et supprimer le binaire `/usr/bin/newrelic-cli`.
</Callout>

Pour désinstaller Agent Control de votre hôte Linux :

1. Exécutez le script de désinstallation :

   ```shell
   sudo sh /usr/lib/newrelic-agent-control/uninstall.sh
   ```

   Ce script va :

   * Arrêtez le service `newrelic-agent-control`
   * Détecter le gestionnaire de paquets
   * Exécutez la purge du gestionnaire de paquets afin que tous les fichiers d&apos;Agent Control soient supprimés du système

### Hôtes Windows

<Callout variant="important">
  Le processus de désinstallation supprime le service Agent Control et l&apos;exécutable. Des fichiers de configuration et d&apos;autres fichiers divers peuvent subsister. Exemple d&apos;actifs susceptibles de ne pas être supprimés dans le cadre de la désinstallation :

  * Fichiers de configuration : vérifiez et supprimez les dossiers `C:\Program Files\New Relic\newrelic-agent-control` et `C:\ProgramData\New Relic\newrelic-agent-control` si nécessaire.
</Callout>

Pour désinstaller Agent Control de votre hôte Windows :

1. Ouvrez PowerShell avec les privilèges d&apos;administrateur.

2. Exécutez le script de désinstallation :

   ```powershell
   PowerShell.exe -ExecutionPolicy Bypass -File "C:\Program Files\New Relic\newrelic-agent-control\uninstall.ps1"
   ```

   Ce script va :

   * Arrêtez le service `newrelic-agent-control`
   * Supprimer l&apos;enregistrement du service
   * Supprimez les répertoires et fichiers Agent Control
