Infinite Tracing est une solution cloud entièrement gérée qui peut analyser 100 % de vos données trace et choisir les données les plus exploitables, vous permettant d&apos;enquêter et de résoudre les problèmes rapidement.

Ce document s’applique uniquement à la fonctionnalité Infinite Tracing. Si vous recherchez notre solution de tracing distribué standard, consultez le [guide de configuration du tracing distribué standard](/docs/distributed-tracing/enable-configure/quick-start).

## Qu&apos;est-ce que l&apos;Infinite Tracing ? [#understand-infinite-tracing]

Infinite Tracing vous permet d&apos;envoyer toutes vos données de trace à notre service cloud et de vous fier à Infinite Tracing pour prendre des décisions d&apos;échantillonnage. Vous pouvez configurer Infinite Tracing de différentes manières pour garantir qu&apos;il conserve les données de trace que vous devez voir.

Infinite Tracing exige que vous envoyiez votre télémétrie à un [observateur de trace](/docs/distributed-tracing/infinite-tracing/set-trace-observer), un point de terminaison d’ingestion régional dédié qui met en mémoire tampon vos spans dans le cloud. L’observateur de trace est le point d’entrée pour toutes les données d’Infinite Tracing, et il accepte la télémétrie provenant des sources suivantes :

* <InlinePopover type="apm" />agents de New Relic, via gRPC
* Les collecteurs et SDK [OpenTelemetry](/docs/opentelemetry/get-started/opentelemetry-get-started-intro), via [OTLP sur gRPC ou HTTP](/docs/distributed-tracing/infinite-tracing/set-trace-observer#apm-and-third-party)
* D&apos;autres outils, tels que Zipkin, via l&apos;[API trace](/docs/distributed-tracing/trace-api/introduction-trace-api)

Contrairement au tracing distribué standard, Infinite Tracing peut traiter plus de données trace. Il utilise [l&apos;échantillonnage en fin de workflow](/docs/understand-dependencies/distributed-tracing/get-started/how-new-relic-distributed-tracing-works#tail-based) (échantillonnage après la collecte des données), au lieu de l&apos;échantillonnage en début de workflow utilisé par le tracing standard. Parce qu&apos;Infinite Tracing prend la décision d&apos;échantillonnage après l&apos;arrivée de tous les spans dans une trace, il peut conserver les trace dont vous avez besoin pour le dépannage, telles que les trace avec des erreurs ou les trace inhabituellement lentes, au lieu de décider au début d&apos;une requête, avant de savoir si elle va échouer ou être lente. Infinite Tracing conserve également un échantillon aléatoire de toutes les trace, 1 % par défaut, afin que vous puissiez voir comment vos services se comportent en fonctionnement normal, et pas seulement en cas de problème. Vous pouvez ajuster cette valeur avec le [filtre de trace aléatoire](/docs/distributed-tracing/infinite-tracing/infinite-tracing-configure-random-trace-filter), et affiner les règles d&apos;erreur avec le [filtre de trace d&apos;attribut de span](/docs/distributed-tracing/infinite-tracing/infinite-tracing-configure-span-attribute-trace-filter).

Ressources pour en savoir plus sur Infinite Tracing :

* [Détails techniques de l&apos;échantillonnage et de l&apos;architecture d&apos;Infinite Tracing](/docs/understand-dependencies/distributed-tracing/get-started/how-new-relic-distributed-tracing-works#sampling)

## Exigences [#requirements]

Les exigences diffèrent selon votre [modèle de tarification](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-pricing-models):

* Modèle de tarification basé sur l&apos;utilisation : nécessite Pro ou édition Enterprise.
* Modèle de tarification d&apos;origine : nécessite l&apos;aide de New Relic pour l&apos;activer pour votre organisation. Pour toute question, contactez votre représentant de compte New Relic.

La possibilité de configurer cette fonctionnalité est régie par [les autorisations d’Infinite Tracing](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions#infinite-tracing).

## Activer Infinite Tracing [#enable-infinite-tracing]

Lorsque vous activez Infinite Tracing, vous devez idéalement l&apos;activer pour tous les services associés. Si certains services d&apos;une trace utilisent Infinite Tracing et d&apos;autres utilisent nos solutions de tracing standard, chaque service prend sa propre décision d&apos;échantillonnage : le tracing standard échantillonne au début d&apos;une requête, tandis qu&apos;Infinite Tracing attend la trace complète. Par conséquent, des spans provenant des services de tracing standard peuvent manquer, ce qui entraîne des trace fragmentées, des spans orphelins et des métriques de trace inexactes. Pour plus de détails, consultez les [conflits de configuration de trace](/docs/understand-dependencies/distributed-tracing/troubleshooting/infinite-tracing-trace-configuration-conflicts).

Pour commencer, suivez le [guide de configuration de l&apos;observateur de trace](/docs/distributed-tracing/infinite-tracing/set-trace-observer).

## Configurer le Infinite Tracing [#configure]

Après avoir activé Infinite Tracing, vous pouvez [configurer le filtrage de l’observateur de trace](/docs/distributed-tracing/infinite-tracing/set-trace-observer#follow-up-config) pour vous assurer qu’il conserve les données exactes dont vous avez besoin.
