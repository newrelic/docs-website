Compute User Limits \[計算ユーザー制限]を使用すると、組織内の個々のユーザーに対して日次または月次の予算を設定し、計算の消費量に基づいてNew Relicリソースへのアクセスを管理できます。各予算は、コア計算（コアCCU）および高度な計算（高度なCCU）を個別のメーターとして追跡します。ユーザーがメーターの割り当てられた予算に達した場合、予算期間が終了するか、予算を増やすまで、関連するリソースへのアクセスをブロックできます。

また、すべてのユーザーに適用されるグローバルなユーザー予算により、大規模な予算管理が簡素化されるため、ユーザーごとに個別に予算を構成する必要はありません。特定のニーズを持つユーザーに対して、カスタムのオーバーライド予算を作成できます。

計算ユーザー制限を使用して、次のことを行います：

* ユーザーごとの消費量を制限して計算コストを管理する
* ユーザーレベルの計算消費量をモニターする
* 組織全体のユーザーの計算使用パターンの可視性を維持します。
* 大規模な組織全体でユーザーの計算予算を管理します。

## 主な機能

2つの予算タイプを利用できます：

* **Global user budget \[グローバルユーザー予算]**：組織内のすべてのユーザーに適用されるデフォルトの予算を設定します。
* **カスタム上書き予算**: グローバル予算よりも高いまたは低い制限を必要とする個々のユーザーに特定の予算を割り当てます。

両方の予算タイプについて、メーターごとに以下を設定します：

* **Core CCU limit**\[コアCCU制限]：組織レベルの計算予算のパーセンテージとして設定すると、対応するCCU値が自動的に計算されます。このメーターの制限タイプとして、**Block CCU usage**\[CCU使用をブロック]または**Do not block CCU usage**\[CCU使用をブロックしない]を選択してください。
* **Advanced CCU limit \[Advanced CCUの制限]**：組織レベルの計算予算のパーセンテージとして設定し、同等のCCU値が自動的に計算されます。このメーターの制限タイプとして、**Block CCU usage** \[CCU使用量のブロック]または**Do not block CCU usage** \[CCU使用量をブロックしない]を選択します。

予算の追跡は、グローバル予算またはカスタムのオーバーライド予算を設定した場合にのみ適用されます。

グローバル予算を設定した場合、すべてのユーザーは自動的にその予算を受け取ります。グローバル予算なしでカスタム上書き予算のみを作成した場合、カスタム予算のないユーザーは無制限にアクセスできます。

New Relic Autopilotによる使用量を管理する必要がある場合は、代わりに[Autopilot compute limits \[Autopilotの計算制限\]](/docs/agentic-ai/autopilot/autopilot-compute-limits/)機能を使用してください。

## ユーザー制限の仕組み

ユーザー制限は、各ユーザーの計算消費量を、コア計算（コアCCU）と高度な計算（高度なCCU）という2つの独立したメーターで追跡します。ユーザーに予算を割り当てると、その計算アクティビティは適切なメーターにカウントされます。各メーターには、独自の予算値と制限タイプがあります。

たとえば、ユーザーに10,000のコアCCU予算と5,000の高度なCCU予算がある場合、クエリの実行やダッシュボードの更新などの標準的な計算アクティビティはコアCCUの制限にカウントされ、Ask AI、Live Archives、MCPなどの高度な計算アクティビティは高度なCCUの制限にカウントされます。

ユーザーがメーターに割り当てられた予算に達すると、そのメーターに設定された制限タイプが有効になります。

### コアおよび高度な計算メーター

コア計算（コアCCU）は、ダッシュボード、クエリビルダー、およびAPIコールを対象としています。高度な計算（高度なCCU）は、Live ArchivesやAIを活用した機能などの機能を対象としています。

ユーザーのコアCCU予算を使い果たし、制限タイプが**Block CCU usage**\[CCU使用をブロック]に設定されている場合、以下へのアクセスが失われます：

* [ダッシュボード](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards)
* [クエリビルダー](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder)
* APIコール

ユーザーの高度なCCU予算が消費され、制限タイプが**Block CCU usage** \[CCU使用をブロック]に設定されている場合、以下のアクセス権が失われます：

* [Ask AI](/docs/agentic-ai/new-relic-ai)（V1およびV2）
* [Live Archives](/docs/logs/get-started/live-archives)（クエリビルダーのQuery Live Archives \[Live Archivesをクエリ]ボタンおよびUse live archives \[ライブアーカイブを使用]トグル）
* [MCP](/docs/agentic-ai/mcp/overview)
* [Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui)（Explain Error \[エラーの解説] および Generate Insights \[Insightsの生成]）

以下の高度なCCUを消費する製品は、この計算ユーザー制限機能ではサポートされていないため、ユーザーの高度なCCU予算が100％に達した場合でも引き続きアクセスできます：

* Pipeline Control
* 無制限のカーディナリティ
* Transaction 360
* Security RX
* New Relic AIナレッジ
* Autopilot

<Callout variant="tip">
より多くの製品が一般提供されるにつれて、適用対象となる高度なCCU製品のリストは増える可能性があります。サポートされている高度なCCU製品の最新情報については、こちらを再度ご確認ください。
</Callout>

### 予算の頻度

予算を作成するときは、毎日リセットするか毎月リセットするかを選択します。適切な選択は、ユーザーの作業パターンと、コストをどれだけ厳密に管理する必要があるかによって異なります。

以下の表は、毎月の予算と毎日の予算を比較したものです：

| 行動         | 月次           | 毎日           |
| ---------- | ------------ | ------------ |
| **リセット**   | 各暦月の開始時（UTC） | 各暦日の開始時（UTC） |
| **ブロック解除** | 翌暦月の開始時（UTC） | 次の暦日の開始（UTC） |

以下のいずれかに該当する場合は、月次予算を選択してください：

* ユーザーの日々の使用量は変動しますが、請求期間全体で平均化されます — たとえば、スプリントの終わりに集中的なクエリを実行するものの、それ以外の使用量は少ない開発者などです。
* 予算期間を請求サイクルに合わせたい場合
* 1か月につき1回のみリセットしたい場合

次のいずれかに該当する場合は、日次予算を選択してください：

* 暴走したクエリやスクリプトが1日に消費できる量を制限したい場合
* ユーザーの日々の使用量が一定しており、1日あたりの固定制限を設定したい場合です。
* より短いリカバリ期間が必要な場合：毎日の予算でブロックされたユーザーは、月末まで待つのではなく、翌日にアクセス権を回復します。

<Callout variant="tip">
1日の上限を設定すると、合計使用量が月間予算内に収まるはずだった場合でも、使用量が多い日にユーザーがブロックされる可能性があります。1日の制限を広く適用する前に、ユーザーの一般的な使用パターンを確認してください。
</Callout>

### 予算通知

通知は、各計算メーターに対して独立してトリガーされます。アプリ内通知は4つの閾値すべてでトリガーされます；メール通知は75％と100％でのみトリガーされます。

| 閾値       | Urgency \[緊急度] | アプリ内通知 | メール |
| -------- | -------------- | ------ | --- |
| **50％**  | 情報             | ✓✓     | —   |
| **75％**  | 警告             | ✓✓     | ✓✓  |
| **95%**  | 致命的            | ✓✓     | —   |
| **100%** | 致命的            | ✓✓     | ✓✓  |

たとえば、100,000コアCCUの予算と200,000アドバンストCCUの予算を持つユーザーは、50,000；75,000；95,000；および100,000コアCCUでコアCCUの通知を受け取り、100,000；150,000；190,000；および200,000アドバンストCCUで別のアドバンストCCUの通知を受け取ります。各メーターの75％および100％の閾値で、メール通知が送信されます。

### 予算の適用

組織マネージャーとして、各計算メーターの制限タイプを独立して設定します。つまり、たとえば、ユーザーのコア計算に**Block CCU usage** \[CCU使用量のブロック]を適用し、アドバンスト計算に**Do not block CCU usage** \[CCU使用量をブロックしない]を設定したり、両方に同じ制限タイプを適用したりできます。

**コア計算については、以下のいずれかを選択してください：**

* **Block CCU usage** \[CCU使用をブロック]：ユーザーが予算を使い切った場合、ユーザーに通知し、クエリビルダー、Dashboards、およびAPIコールへのアクセス（クエリの実行、ダッシュボードの更新、APIコールの実行）をブロックします。
* **Do not block CCU usage** \[CCU使用をブロックしない]：ユーザーが予算を消費したときに通知しますが、CCUを消費する製品へのアクセスはブロックしません。このオプションはプラットフォームへの完全なアクセスを維持しますが、超過を防ぐことはできません。

**高度な計算については、以下のいずれかを選択してください：**

* **Block CCU usage** \[CCU使用量のブロック]：ユーザーが予算を使い切った場合、ユーザーに通知し、[Ask AI](/docs/agentic-ai/new-relic-ai)、[Live Archives](/docs/logs/get-started/live-archives)、[MCP](/docs/agentic-ai/mcp/overview)、[Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui)などへのアクセスをブロックします。
* **Do not block CCU usage** \[CCU使用をブロックしない]：ユーザーが予算を使い切った場合、ユーザーに通知しますが、CCUを消費するアクションへのアクセスはブロックしません。このオプションはプラットフォームへの完全なアクセスを維持しますが、超過を防ぐことはできません。

ブロックされると、ユーザーには、その期間の予算を使い切ったこと、および質問がある場合は組織の管理者に連絡できることを示す画面が表示されます。

<Callout variant="tip">
予算制限を初めて導入する場合は、両方のメーターで**Do not block CCU usage**\[CCU使用をブロックしない]から始めてください。これにより、ブロックを有効にする前に実際の使用パターンを観察でき、予期しないアクセス中断が発生する可能性を減らすことができます。
</Callout>

<Callout variant="important">
月間予算の場合、ブロックは暦月の終わり（UTC）まで有効です。日次予算の場合、ブロックは暦日の終わり（UTC）まで有効です。どちらの場合も、ユーザーの予算を増やすことで、より早くアクセスを復元できます。消費データは数時間（通常は2～4時間）以内に更新されるため、ブロックは正確に100％で発生するわけではありません。ブロックが有効になる前に、ユーザーが予算を超過する可能性があります。
</Callout>

## あなたが始める前に

予算を作成するときは、4つの設定を構成します。開始前にこれらを確認することで、セットアップウィザードで適切な選択を行うことができます。

| 設定                   | オプション                                                                              | 考慮すべき事項                                                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **予算タイプ**            | グローバルまたはカスタムのオーバーライド                                                               | ベースラインとしてグローバル予算から開始してください。異なる制限が必要なユーザーには、カスタムオーバーライドを追加してください。                                                                                     |
| **頻度**               | 月単位または日単位                                                                          | それらの選択に関するガイダンスについては、[予算の頻度](#budget-frequency)をご覧ください。                                                                                              |
| **コアCCU割り当て**        | 組織の予算の割合；Block CCU usage \[CCU使用量のブロック]またはDo not block CCU usage \[CCU使用量をブロックしない] | パーセンテージを入力してください；ウィザードが同等のCCU値を計算します。このメーターについては、制限タイプも選択してください：ブロックを有効にする前に実際の使用パターンを観察するために、**Do not block CCU usage** \[CCU使用をブロックしない] から始めてください。 |
| **Advanced CCU割り当て** | 組織の予算の割合；Block CCU usage \[CCU使用量のブロック]またはDo not block CCU usage \[CCU使用量をブロックしない] | パーセンテージを入力してください；ウィザードが同等のCCU値を計算します。このメーターについては、制限タイプも選択してください：ブロックを有効にする前に実際の使用パターンを観察するために、**Do not block CCU usage** \[CCU使用をブロックしない] から始めてください。 |

## グローバルユーザー予算を設定する

組織が複数のNew Relic組織にまたがっている場合は、それぞれに個別にサインインして、そのユーザーのユーザー制限を作成および管理してください。

<Steps>
<Step>
### 計算リソース予算にアクセスします

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; [user menu](/docs/accounts/accounts-billing/general-account-settings/intro-account-settings)**</DNT>に移動します。
2. <DNT>**Administration &gt; Compute Budgets**</DNT>を選択します。
</Step>

<Step>
### グローバル予算ウィザードを開きます

<DNT>**Global user budget**</DNT>カードで、<DNT>**Manage budget**</DNT>をクリックします。<DNT>**Manage global budget**</DNT>ウィザードが開きます。
</Step>

<Step>
### 予算の頻度を設定します。

<DNT>**Set the frequency**</DNT>で、予算がリセットされる頻度を選択します：

* <DNT>**Monthly**</DNT>：暦月全体の使用量を追跡し、各月の初め（UTC）にリセットします。
* <DNT>**Daily**</DNT>：各暦日の使用量を追跡し、各日の開始時（UTC）にリセットします。

<DNT>**Next**</DNT>をクリックします。
</Step>

<Step>
### Define core CCU budget \[コアCCU予算の定義]

1. <DNT>**Budget allocation**</DNT>で、各ユーザーに割り当てる組織のコアCCU予算の割合を入力してください。入力すると、ウィザードに同等の高度なCCU値が表示されます。たとえば、組織に800,000コアCCUがあり、5％に設定した場合、各ユーザーは40,000コアCCUを受け取ります。ユーザーの予算は、組織の合計予算を超えることができます。

2. 「<DNT>**Limit type**</DNT>」で、ユーザーのコアCCU予算が100％に達したときの処理を選択してください：

   * <DNT>**Block CCU usage**</DNT>：ユーザーに通知し、CCUを消費するアクション（クエリの実行、ダッシュボードの更新、APIコールの実行）へのアクセスをブロックします。
   * <DNT>**Do not block CCU usage**</DNT>：ユーザーに通知しますが、プラットフォームへの完全なアクセスは維持します。これにより超過を防ぐことはできません。

<DNT>**Next**</DNT>をクリックします。
</Step>

<Step>
### 高度なCCU予算を定義する

1. 「<DNT>**Budget allocation**</DNT>」で、各ユーザーに割り当てる組織の高度なCCU予算のパーセンテージを入力してください。入力すると、ウィザードに対応するCCU値が表示されます。ユーザーの予算は、組織全体の予算を超えることができます。

2. <DNT>**Limit type**</DNT>で、ユーザーが高度なCCU予算の100％に達したときの動作を選択してください：

   * <DNT>**Block CCU usage**</DNT>：ユーザーに通知し、[Ask AI](/docs/agentic-ai/new-relic-ai)、[Live Archives](/docs/logs/get-started/live-archives)、[MCP](/docs/agentic-ai/mcp/overview)、および[Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui)へのアクセスをブロックします。
   * <DNT>**Do not block CCU usage**</DNT>：ユーザーに通知しますが、プラットフォームへの完全なアクセスは維持します。これにより超過を防ぐことはできません。

<DNT>**Next**</DNT>をクリックします。
</Step>

<Step>
### 通知の確認

このページでは、各計算メーターについてユーザーが受け取る通知の閾値を確認します。設定は必要ありません。<DNT>**Finish**</DNT>をクリックして、グローバルユーザー予算を作成します。
</Step>
</Steps>

## カスタムのオーバーライド予算を設定

グローバル予算とは異なる上限を必要とするユーザーのために、カスタムの上書き予算を作成します。チームをオンボーディングする場合、または各ユーザーを個別に構成せずにグループに一律の上限を適用する場合は、このアプローチを使用してください。

<Steps>
<Step>
### ユーザー予算を作成する

<DNT>**User Limits**</DNT>ページから<DNT>**Create a user budget**</DNT>をクリックします。<DNT>**Create custom user budget**</DNT>ウィザードが開きます。
</Step>

<Step>
### 頻度を設定してユーザーを選択する

1. <DNT>**Set the frequency**</DNT>で、予算がリセットされる頻度を選択します：

   * <DNT>**Monthly**</DNT>：暦月全体の使用量を追跡し、各月の初め（UTC）にリセットします。
   * <DNT>**Daily**</DNT>：各暦日の使用量を追跡し、各日の開始時（UTC）にリセットします。

2. <DNT>**Select users**</DNT>で、ドロップダウンから1人以上のユーザーを選択して、このカスタム上書き予算を割り当てます。複数のユーザーを選択した場合、同じ予算が各ユーザーに個別に適用されます — 単一の予算を共有することはありません。

<DNT>**Next**</DNT>をクリックします。
</Step>

<Step>
### Define core CCU budget \[コアCCU予算の定義]

1. <DNT>**Budget allocation**</DNT>で、このユーザーに割り当てる組織のコアCCU予算の割合を入力します。入力すると、ウィザードに相当するCCU値が表示されます。ユーザー予算は、組織の合計予算を超えることができます。

2. <DNT>**Limit type**</DNT>で、ユーザーがコアCCU予算の100％に達したときの動作を選択してください。これはグローバル予算の設定と異なる場合があります。

   * <DNT>**Block CCU usage**</DNT>：ユーザーに通知し、CCUを消費するアクション（クエリの実行、ダッシュボードの更新、APIコールの実行）へのアクセスをブロックします。
   * <DNT>**Do not block CCU usage**</DNT>：ユーザーに通知しますが、プラットフォームへの完全なアクセスは維持します。これにより超過を防ぐことはできません。

<DNT>**Next**</DNT>をクリックします。
</Step>

<Step>
### 高度なCCU予算を定義する

1. <DNT>**Budget allocation**</DNT>で、このユーザーに割り当てる組織の高度なCCU予算の割合を入力します。入力すると、ウィザードに相当するCCU値が表示されます。ユーザーの予算は、組織の総予算を超える場合があります。

2. 「<DNT>**Limit type**</DNT>」で、ユーザーの高度なCCU予算が100％に達したときの処理を選択してください。これは、グローバルの予算設定とは異なる場合があります。

   * <DNT>**Block CCU usage**</DNT>：ユーザーに通知し、[Ask AI](/docs/agentic-ai/new-relic-ai)、[Live Archives](/docs/logs/get-started/live-archives)、[MCP](/docs/agentic-ai/mcp/overview)、および[Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui)へのアクセスをブロックします。
   * <DNT>**Do not block CCU usage**</DNT>：ユーザーに通知しますが、プラットフォームへの完全なアクセスは維持します。これにより超過を防ぐことはできません。

<DNT>**Next**</DNT>をクリックします。
</Step>

<Step>
### 通知の確認

各計算メーターについて、このユーザーに適用される通知閾値を確認してください。カスタム・オーバーライド予算を作成するには、<DNT>**Finish**</DNT>をクリックしてください。
</Step>
</Steps>

作成後、カスタム上書き予算は個別の項目としてユーザー予算テーブルに表示されます。これらを個別に更新するか、<DNT>**Group by**</DNT>ドロップダウンを使用して、同じ割り当て、制限タイプ、および頻度を共有するユーザーを表示および管理できます。

## ユーザー制限の管理

### 予算の消費状況を表示

組織マネージャーには、<DNT>**Compute Budgets**</DNT>ページの上部に<DNT>**Global user budget**</DNT>カードが表示されます。カードには、設定されたコアCCUとAdvanced CCUの量、ユーザーごとに割り当てられたパーセンテージ、および各メーターの制限タイプが表示されます。

カードの下にある<DNT>**User budgets**</DNT>テーブルには、次の列を持つカスタム上書き予算が表示されます：

| カラム                           | 説明                                                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| **ユーザー**                      | ユーザーのメールアドレス                                                                                            |
| **頻度**                        | 予算が毎日リセットされるか、毎月リセットされるか                                                                                |
| **コア使用量**                     | 割り当てに対する現在のコアCCU消費量の割合、またはBlock CCU usage \[CCU使用量をブロック]が有効になっていてユーザーが予算を超過している場合は**Blocked \[ブロック済み]** |
| **Core allocation \[コア割り当て]** | コアCCU予算額および設定された制限タイプ（Block \[ブロック] または Do not block \[ブロックしない]）                                        |
| **高度な使用法**                    | 割り当てに対する割合としての現在の高度なCCU消費量、または閾値に近づいている場合は**Close to limit \[制限間近]**                                    |
| **高度な割り当て**                   | 高度なCCU予算額と設定された制限タイプ（Block \[ブロック] または Do not block \[ブロックしない]）                                         |

<DNT>**Group by &gt; Allocation, limit, and frequency**</DNT>を使用して、同じ予算設定を共有するユーザーをクラスタ化します。各グループヘッダーには、設定の概要が表示されます（例：`Core CCU 45,000 CCU · Block | Advanced CCU 100,000 CCU · Do not block | Monthly`）。

**組織マネージャー**は以下のことができます：

* テーブル内のすべてのカスタム上書き予算を詳細とともに表示します

* 各予算の横にある3点メニュー（**⋯**）にアクセスします。メニューには以下のオプションが含まれます：

  * <DNT>**View**</DNT>：詳細な予算情報、消費量、および傾向を表示する
  * <DNT>**Edit**</DNT>：予算設定を変更する
  * <DNT>**Delete**</DNT>: 予算を削除します

**読み取り専用ユーザー**は以下のことができます：

* カスタムオーバーライド予算かグローバル予算かにかかわらず、自身の予算をテーブルの行項目として確認できます。
* 3点メニューから<DNT>**View**</DNT>オプションのみにアクセスできます。

読み取り専用ユーザーは、他のユーザーの予算を表示したり、<DNT>**Edit**</DNT>や<DNT>**Delete**</DNT>を使用したりすることはできません。

### 予算詳細ビュー [#budget-details]

予算（すべてのユーザーが自身の予算に対して利用可能）を表示すると、以下を確認できます：

* 現在のコアCCUおよび高度なCCUの消費量
* 各予算の使用率
* 期間中の消費傾向
* 各メーターの100％でのブロックステータス
* 通知ステータス

### 予算を調整 [#adjust-budgets]

組織のマネージャーは、いつでも予算を変更できます：

* <DNT>**Edit existing budgets**</DNT>：単一ユーザーの予算額、頻度、または制限タイプを更新するか、グループビューを使用してグループ内のすべてのユーザーの予算を一度に更新します
* <DNT>**Increase a user&apos;s budget**</DNT>：ブロックされたユーザーのアクセスを復元するか、追加のキャパシティを提供する
* <DNT>**Decrease budgets**</DNT>：現在および将来の予算期間の予算額を調整します
* <DNT>**Delete budgets**</DNT>：グローバル予算とカスタムオーバーライド予算の両方を削除します。カスタムオーバーライド予算を削除すると、ユーザーは自動的にグローバルユーザー予算（設定されている場合）にフォールバックします。

予算への変更は、約15分以内に有効になります。

<Callout variant="important">
カスタム予算を削除しても、予算トラッキングは削除されません。予算トラッキングは、グローバル予算の下で継続されます（設定している場合）。
</Callout>

### ブロックされたユーザーの処理

予算の消費によりユーザーがブロックされた場合、以下の操作を行うことができます：

* その期間の予算を使い切ったというメッセージが表示されます
* 予算の詳細を表示して、消費量を確認してください。
* 予算の増額をリクエストするために連絡する

ブロックされたユーザーのアクセスを復元するには、以下のいずれかのオプションを選択してください。

* 予算を増やします。「[予算の調整](#adjust-budgets)」を参照してください。
* 次の予算期間の開始時に予算がリセットされるまでお待ちください。[予算の頻度](#budget-frequency)をご覧ください。

<Callout variant="tip">
ユーザーが制限の引き上げについて誰に連絡すべきかを把握できるように、組織の管理者の内部リストを公開し、サービスインシデント中に少なくとも1人が引き上げを迅速に承認できるようにしてください。
</Callout>

## 一般的なシナリオ

**予算はいつリセットされますか？**予算の設定時に選択した頻度によって異なります：

* **毎月**：予算は各暦月の初め（UTC）にリセットされます。
* **日次**：予算は各暦日の開始時（UTC）にリセットされます。

**ユーザーがコアCCU予算の100％に達した場合、進行中のクエリはどうなりますか？**実行中のクエリは完了します。ブロックは、ブロックの適用後に新しいクエリ、ダッシュボードの読み込み、およびAPIコールが開始されるのを防ぐだけです。消費データレポートの遅延に関する上記の注意事項を参照してください。

**ユーザーが高度なCCU予算の100％に達するとどうなりますか？**高度なCCU制限タイプが**Block CCU usage** \[CCU使用をブロック] に設定されている場合、ユーザーは[Ask AI](/docs/agentic-ai/new-relic-ai)、[Live Archives](/docs/logs/get-started/live-archives)、[MCP](/docs/agentic-ai/mcp/overview)、および[Errors Inbox](/docs/apm/errors-inbox/errors-inbox-ui)へのアクセスを失います。制限タイプが**Do not block CCU usage** \[CCU使用をブロックしない] の場合、ユーザーは引き続きフルアクセスを利用できますが、通知を受け取ります。

**カスタムオーバーライド予算を削除すると、ユーザーはどうなりますか？**グローバルユーザー予算を設定している場合、ユーザーには自動的にグローバルユーザー予算が適用されます。グローバル予算が存在しない場合、ユーザーは無制限にアクセスできます。

**予算が割り当てられていないユーザーはどうなりますか？**予算が割り当てられていないユーザーは、ダッシュボード、クエリビルダー、APIコール、およびAI機能に無制限にアクセスできます。

**予算の変更はどのくらいで反映されますか？**予算の変更は約15分以内に反映されます。
