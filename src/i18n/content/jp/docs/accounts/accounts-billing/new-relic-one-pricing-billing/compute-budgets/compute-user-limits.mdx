計算ユーザー制限を使用すると、組織内の個々のユーザーに対して日次または月次の予算を設定し、計算の消費量に基づいてNew Relicリソースへのアクセスを管理できます。ユーザーが割り当てられた予算に達した場合、予算期間が終了するか予算を増やすまで、ダッシュボード、クエリビルダー、およびAPIコールへのアクセスをブロックできます。

また、すべてのユーザーに適用されるグローバルなユーザー予算により、大規模な予算管理が簡素化されるため、ユーザーごとに個別に予算を構成する必要はありません。特定のニーズを持つユーザーに対して、カスタムのオーバーライド予算を作成できます。

計算ユーザー制限を使用して、次のことを行います：

* ユーザーごとの消費量を制限して計算コストを管理する
* ユーザーレベルの計算消費量をモニターする
* 組織全体の使用パターンの可視性を維持する
* 大規模な組織全体で予算を管理する

## 主な機能

2つの予算タイプを利用できます：

* **グローバルユーザー予算**: 組織内のすべてのユーザーに適用されるデフォルトの予算を設定します。以下のいずれかの方法で設定します：

  * **組織予算の割合**: 組織レベルの計算予算（最小コミットメントに基づく）の割合を各ユーザーに割り当てます。
  * **実際の計算値**: 各ユーザーの計算容量ユニット（CCU）の正確な数を指定します

* **カスタム上書き予算**: グローバル予算よりも高いまたは低い制限を必要とする個々のユーザーに特定の予算を割り当てます。

予算の追跡は、グローバル予算またはカスタムのオーバーライド予算を設定した場合にのみ適用されます。

グローバル予算を設定した場合、すべてのユーザーは自動的にその予算を受け取ります。グローバル予算なしでカスタム上書き予算のみを作成した場合、カスタム予算のないユーザーは無制限にアクセスできます。

## ユーザー制限の仕組み

ユーザー制限は、各ユーザーの計算消費量を追跡します。ユーザーに予算を割り当てると、そのユーザーのすべての計算アクティビティがその予算にカウントされます。ユーザーがCCUとCoreCCUの両方を持っている場合、CCUのみが予算制限にカウントされます。

たとえば、ユーザーに1,000 CCUの予算がある場合、そのユーザーIDまたはAPIキーに属性づけられたすべての計算消費量がその制限にカウントされます。

ユーザーが割り当てられた予算に達すると、設定されたブロックまたは監視ルールが有効になります。

### 予算の頻度

予算を作成するときは、毎日リセットするか毎月リセットするかを選択します。適切な選択は、ユーザーの作業パターンと、コストをどれだけ厳密に管理する必要があるかによって異なります。

以下の表は、毎月の予算と毎日の予算を比較したものです：

| 行動         | 月次           | 毎日           |
| ---------- | ------------ | ------------ |
| **リセット**   | 各暦月の開始時（UTC） | 各暦日の開始時（UTC） |
| **ブロック解除** | 翌暦月の開始時（UTC） | 次の暦日の開始（UTC） |

以下のいずれかに該当する場合は、月次予算を選択してください：

* ユーザーの日々の使用量は変動しますが、請求期間全体で平均化されます — たとえば、スプリントの終わりに集中的なクエリを実行するものの、それ以外の使用量は少ない開発者などです。
* 予算期間を請求サイクルに合わせたい場合
* 1か月につき1回のみリセットしたい場合

次のいずれかに該当する場合は、日次予算を選択してください：

* 暴走したクエリやスクリプトが1日に消費できる量を制限したい場合
* ユーザーの日々の使用量が一定しており、1日あたりの固定制限を設定したい場合です。
* より短いリカバリ期間が必要な場合：毎日の予算でブロックされたユーザーは、月末まで待つのではなく、翌日にアクセス権を回復します。

<Callout variant="tip">
  1日の上限を設定すると、合計使用量が月間予算内に収まるはずだった場合でも、使用量が多い日にユーザーがブロックされる可能性があります。1日の制限を広く適用する前に、ユーザーの一般的な使用パターンを確認してください。
</Callout>

### 予算通知

以下の閾値でアプリ内バナー通知を受け取ります：

* **予算の50％を消費**: 黄色の情報バナー
* **予算の75％を消費**: 黄色の警告バナー
* **予算の95％を消費**: 赤色のクリティカルバナー
* **予算の100％を消費**: ユーザーが予算を超過していることを示す情報バナー

また、予算の75％および100％が消費された時点でメール通知を受け取ります。

これらの通知により、消費状況を把握できます。

### 予算の適用

組織の管理者として、ユーザーが割り当てられた予算の100％に達したときに何が起こるかを選択できます：

* **ユーザーをブロックする**: ブロックすると、ユーザーは以下にアクセスできなくなります：

  * ダッシュボードへのアクセス
  * クエリビルダーへのアクセス
  * ユーザーIDまたはAPIキーを介したAPIアクセス

  ブロックされると、ユーザーには、その期間の予算を使い切ったこと、および質問がある場合は組織の管理者に連絡できることを示す画面が表示されます。

* **モニターのみ**：アクセスをブロックせずに、予算の消費についてユーザーに通知するのみです。

<Callout variant="tip">
  初めて予算制限を導入する場合は、モニターのみで開始してください。これにより、ブロックを有効にする前に実際の使用パターンを観察できるため、予期しないアクセスの中断が発生する可能性を減らすことができます。
</Callout>

<Callout variant="important">
  毎月の予算の場合、ブロックは暦月の終わり（UTC）まで有効です。毎日の予算の場合、ブロックは暦日の終わり（UTC）まで有効です。どちらの場合も、ユーザーの予算を増やすことで、より早くアクセスを復元できます。消費データは数時間（通常は2～4時間）以内に更新されるため、ブロックは正確に100％の時点では発生しません。ブロックが有効になる前に、ユーザーが予算をわずかに超える場合があります。
</Callout>

## あなたが始める前に

予算を作成するときは、4つの設定を構成します。開始前にこれらを確認することで、セットアップウィザードで適切な選択を行うことができます。

| 設定         | オプション                | 考慮すべき事項                                                                  |
| ---------- | -------------------- | ------------------------------------------------------------------------ |
| **予算タイプ**  | グローバルまたはカスタムのオーバーライド | ベースラインとしてグローバル予算から開始してください。異なる制限が必要なユーザーには、カスタムオーバーライドを追加してください。         |
| **割り当て方法** | 組織の予算の割合または実際のCCU値   | 組織のコミットメントに合わせて制限をスケーリングする場合は、パーセンテージを使用してください。固定のCCU制限には、実際の値を使用してください。 |
| **頻度**     | 月単位または日単位            | それらの選択に関するガイダンスについては、[予算の頻度](#budget-frequency)をご覧ください。                  |
| **強制適用**   | ブロックまたはモニターのみ        | ブロックを有効にする前に、実際の使用パターンを観察するために、まずはモニターのみで開始してください。                       |

## グローバルユーザー予算を設定する

組織が複数のNew Relic組織にまたがっている場合は、それぞれに個別にサインインして、そのユーザーのユーザー制限を作成および管理してください。

<Steps>
  <Step>
    ### 計算リソース予算にアクセスします

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; [user menu](/docs/accounts/accounts-billing/general-account-settings/intro-account-settings)**</DNT>に移動します。
    2. <DNT>**Administration &gt; Compute Budgets**</DNT>を選択します。
  </Step>

  <Step>
    ### グローバル予算を追加する

    <DNT>**Create a global user budget**</DNT>をクリックして、サインインしている組織のすべてのユーザーに適用される予算を作成します。
  </Step>

  <Step>
    ### 予算を設定する

    1. 予算の割り当て方法を選択します：

       * **Percentage of organization budget** \[組織予算の割合]: 組織レベルの計算予算（最小コミットメントに基づく）の割合を各ユーザーに割り当てます。たとえば、組織に800,000コアCCUがあり、ユーザーごとに1％を設定した場合、各ユーザーは8,000コアCCUを受け取ります。すべてのユーザーの合計割合が100％に等しい必要はありません。合計を100％未満（一部の予算を未割り当てのままにする）または100％を超えるように設定できます。合計を100％を超えて設定することは許容されます。
       * **Actual value** \[実際の値]: 各ユーザーのCCUの正確な数を指定します。

    2. 予算額を入力してください。

    3. <DNT>**Set the frequency**</DNT>で、予算がリセットされる頻度を選択します：

       * **月次**: 暦月全体の使用量を追跡し、各月の初め（UTC）にリセットします。
       * **毎日**：各暦日の使用量を追跡し、各日の開始時（UTC）にリセットします。

    4. <DNT>**Next**</DNT>をクリックします。
  </Step>

  <Step>
    ### グローバル予算の通知を確認

    このページでは、ユーザーが受け取る通知の閾値を確認します。設定は必要ありません。<DNT>**Next**</DNT>をクリックして続行します。
  </Step>

  <Step>
    ### グローバル予算のブロックを設定する

    1. ユーザーがCCU予算を超えた場合の使用量の制限方法を選択します。制限は予算がなくなったときに開始され、予算期間（日または月）の終わりまで、または変更するまで続きます。以下のいずれかを選択してください：

       * **これ以上のCCU使用をブロックする**: ユーザーが予算上限に達すると、ダッシュボード、クエリビルダー、またはAPIコールにアクセスできなくなります。ユーザーが予算を使い果たすと、クエリの実行やダッシュボードの更新など、CCUを消費するアクションにブロックが適用されます。
       * **使用を制限しない**: ユーザーは通知を受け取りますが、すべての機能へのフルアクセスを維持します。これにより超過を防ぐことはできません。

       制限が有効になると通知を受け取ります。

    2. グローバルユーザー予算を作成するには、<DNT>**Finish**</DNT>をクリックします。
  </Step>
</Steps>

## カスタムのオーバーライド予算を設定

グローバル予算とは異なる上限を必要とするユーザーのために、カスタムの上書き予算を作成します。チームをオンボーディングする場合、または各ユーザーを個別に構成せずにグループに一律の上限を適用する場合は、このアプローチを使用してください。

<Steps>
  <Step>
    ### ユーザー予算を追加

    <DNT>**User Limits**</DNT>ページから<DNT>**+ Create a user budget**</DNT>をクリックします。
  </Step>

  <Step>
    ### ユーザーの選択

    ドロップダウンメニューから、カスタム上書き予算を割り当てるユーザーを1人以上選択します。複数のユーザーを選択した場合、同じ予算額が各ユーザーに個別に適用されます。たとえば、40,000 CCUを設定して5人のユーザーを選択した場合、各ユーザーには共有部分ではなく40,000 CCUが割り当てられます。
  </Step>

  <Step>
    ### カスタム予算を設定します

    1. 特定のパーセンテージまたは実際の値を設定します。

    2. <DNT>**Set the frequency**</DNT>で、予算がリセットされる頻度を選択します：

       * **月次**: 暦月全体の使用量を追跡し、各月の初め（UTC）にリセットします。
       * **毎日**：各暦日の使用量を追跡し、各日の開始時（UTC）にリセットします。

    3. <DNT>**Next**</DNT>をクリックします。
  </Step>

  <Step>
    ### カスタム予算通知の確認

    このユーザーに適用される通知の閾値を確認します。<DNT>**Next**</DNT>をクリックして続行します。
  </Step>

  <Step>
    ### カスタム予算ブロックの設定

    1. この特定のユーザーのブロック設定を選択します。これはグローバル予算設定とは異なる場合があります。

    2. <DNT>**Finish**</DNT>をクリックして、カスタムのオーバーライド予算を作成します。
  </Step>
</Steps>

作成後、カスタム上書き予算は予算テーブルに個別の行項目として表示されます。これらを個別に更新することも、グループビューを使用してグループ内のすべてのユーザーを一度に更新することもできます。

## ユーザー制限の管理

### 予算の消費状況を表示

組織の管理者には、メインの<DNT>**User Limits**</DNT>ページの上部にグローバル予算がカードとして表示されます。カスタムオーバーライド予算は、下部の予算テーブルに表示されます。

**組織マネージャー**は以下のことができます：

* グローバル予算カードとテーブル内のすべてのカスタム上書き予算を詳細とともに表示する

* 各予算の横にある3点メニュー（**⋯**）にアクセスします。メニューには以下のオプションが含まれます：

  * <DNT>**View**</DNT>：詳細な予算情報、消費量、および傾向を表示する
  * <DNT>**Edit**</DNT>：予算設定を変更する
  * <DNT>**Delete**</DNT>: 予算を削除します

**読み取り専用ユーザー**は以下のことができます：

* カスタムオーバーライド予算かグローバル予算かにかかわらず、自身の予算をテーブルの行項目として確認できます。
* 3点メニューから<DNT>**View**</DNT>オプションのみにアクセスできます。

読み取り専用ユーザーは、他のユーザーの予算を表示したり、<DNT>**Edit**</DNT>や<DNT>**Delete**</DNT>を使用したりすることはできません。

### 予算詳細ビュー [#budget-details]

予算（すべてのユーザーが自身の予算に対して利用可能）を表示すると、以下を確認できます：

* 現在の予算消費量
* 予算使用率
* 期間中の消費傾向
* 100％でのブロックステータス
* 通知ステータス

### 予算を調整 [#adjust-budgets]

組織のマネージャーは、いつでも予算を変更できます：

* <DNT>**Edit existing budgets**</DNT>：単一のユーザーの予算額、頻度、またはブロック設定を更新するか、グループビューを使用してグループ内のすべてのユーザーの予算を一度に更新します。
* <DNT>**Increase a user&apos;s budget**</DNT>：ブロックされたユーザーのアクセスを復元するか、追加のキャパシティを提供する
* <DNT>**Decrease budgets**</DNT>：現在および将来の予算期間の予算額を調整します
* <DNT>**Delete budgets**</DNT>：グローバル予算とカスタムオーバーライド予算の両方を削除します。カスタムオーバーライド予算を削除すると、ユーザーは自動的にグローバルユーザー予算（設定されている場合）にフォールバックします。

予算への変更は、約15分以内に有効になります。

<Callout variant="important">
  カスタム予算を削除しても、予算トラッキングは削除されません。予算トラッキングは、グローバル予算の下で継続されます（設定している場合）。
</Callout>

### ブロックされたユーザーの処理

予算の消費によりユーザーがブロックされた場合、以下の操作を行うことができます：

* その期間の予算を使い切ったというメッセージが表示されます
* 予算の詳細を表示して、消費量を確認してください。
* 予算の増額をリクエストするために連絡する

ブロックされたユーザーのアクセスを復元するには、以下のいずれかのオプションを選択してください。

* 予算を増やします。「[予算の調整](#adjust-budgets)」を参照してください。
* 次の予算期間の開始時に予算がリセットされるまでお待ちください。[予算の頻度](#budget-frequency)をご覧ください。

<Callout variant="tip">
  ユーザーが制限の引き上げについて誰に連絡すべきかを把握できるように、組織の管理者の内部リストを公開し、サービスインシデント中に少なくとも1人が引き上げを迅速に承認できるようにしてください。
</Callout>

## 一般的なシナリオ

**予算はいつリセットされますか？**予算の設定時に選択した頻度によって異なります：

* **毎月**：予算は各暦月の初め（UTC）にリセットされます。
* **日次**：予算は各暦日の開始時（UTC）にリセットされます。

**ユーザーが予算の100％に達した場合、進行中のクエリはどうなりますか？**実行中のクエリは完了します。ブロックは、新しいクエリ、ダッシュボードの読み込み、およびAPIコールの開始のみを防止します。

**カスタムオーバーライド予算を削除すると、ユーザーはどうなりますか？**グローバルユーザー予算を設定している場合、ユーザーには自動的にグローバルユーザー予算が適用されます。グローバル予算が存在しない場合、ユーザーは無制限にアクセスできます。

**予算が割り当てられていないユーザーはどうなりますか？**予算が割り当てられていないユーザーは、ダッシュボード、クエリビルダー、APIコールに無制限にアクセスできます。

**予算の変更はどのくらいで反映されますか？**予算の変更は約15分以内に反映されます。
