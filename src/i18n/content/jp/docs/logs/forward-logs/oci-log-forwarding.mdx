OCIサービスおよび監査ログをNew Relicに送信するには、このガイドを使用してください。メトリクスも送信するには、[OCIメトリクスとログのモニター](/docs/infrastructure/oci/install-metrics-and-logs)をご覧ください。メトリクスのみを送信するには、[OCIメトリクスのモニター](/docs/infrastructure/oci/install-metrics)をご覧ください。

## 互換性と要件 [#requirements]

始める前に、以下があることを確認してください：

* サポートされているリージョン（US、EU、またはJP）でinfrastructureモニタリング権限を持つNew Relicアカウント
* 有効なNew Relicの[Ingestライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)および[ユーザーキー](/docs/apis/intro-apis/new-relic-api-keys/#user-api-key)
* Identity and Access Management（IAM）ドメインを持つOCIテナンシ、およびそのドメインとルートコンパートメントへの一時的な管理アクセス（New Relicが長期的な認証情報を保存せずに認証するために使用するメカニズムである、ワークロード・アイデンティティ・フェデレーション（WIF）のセットアップを完了するのに十分なアクセス権）。セットアップが完了したら、このアクセス権を取り消すことができます。
* OCIテナンシOCIDとホームリージョン（例：`us-ashburn-1`）
* OCI API署名キー（Terraformでデプロイする場合のみ）

## ガイド付きインストレーション [#ui-install]

ガイド付きインストレーションは<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; Oracle Cloud Infrastructure**</DNT>でご利用いただけます。UIでは、OCIアカウントを接続し、次にモニターするロググループをインストゥルメントされた状態にする手順を案内します。

<Steps>
<Step>
### ログデータタイプを選択します

以下の手順に従ってください。

1. <DNT>**Logs**</DNT> を選択してください（詳細なイベントおよび監査レコード用）。
2. <DNT>**Continue**</DNT>をクリックします。
</Step>

<Step>
### インテグレーション方法を選択し、インテグレーションを設定してください。

組織のニーズに合わせて、OCIログをNew Relicに取り込むためのご希望のインテグレーション方法を選択してください：

<CollapserGroup>
<Collapser id="orm" title="Oracle Resource Managerを使用してOCIをモニターします。">
OCIコンソールで各要素を手作業で作成する代わりに、Oracle Resource Managerスタックを実行して、インテグレーションに必要なものをプロビジョニングします。画面上の指示に従って、接続を確立します。
</Collapser>

<Collapser id="manual" title="OCIアカウントを手動で統合する">
OCIコンソールで、必要なポリシーとサービス・コネクタを作成します。ガイド付きインストレーションでは、次の手順を順番に案内します：コンパートメントの作成、動的グループの作成、キー・ボールト・シークレットの設定、ポリシーの作成、ネットワークの設定、ログ機能の設定、監査ログ・コネクタの設定(オプション)、ログ・コネクタの設定、WIFの設定、および接続の作成。

プロセスを完了するには、次の情報が必要です：

* 専用コンパートメントの名前を`newrelic_compartment_DO_NOT_REMOVE`にしてください。OCIホーム・リージョンに作成してください。

* デフォルト・ドメイン下のルート・コンパートメントに動的グループを作成する際に、ルール`resource.type = 'serviceconnector'`および`resource.type = 'fnfunc'`を追加します。

* 認証用のNew Relicライセンスキーとユーザーキーを安全に保存するためのキー・ボールトを作成します。<br />

  1. **キー・ボールトを作成してください**。OCIコンソールで、**Key Management and Vault services**を見つけてアクセスし、以前に作成したコンパートメントにボールトを作成します。名前（たとえば`newrelic-vault`）を付け、セキュリティ要件に基づいて標準または仮想プライベート・ボールトを選択してください。<br />
  2. **マスター暗号化キーを作成します**。ボールトで、`AES`アルゴリズムと`256`ビットのキー長を使用して、（たとえば）`newrelic-encryption-key`という名前のマスターキーを作成します。<br />
  3. **APIキーのシークレットを作成してください**。先ほど作成したマスターキーを選択し、シークレットのコンテンツ（プレーンテキスト）としてIngestライセンスキーを貼り付けて、New RelicのIngestライセンスキー用のシークレット（たとえば`newrelic-ingest-key`という名前）を作成してください。同じ手順を繰り返して、シークレットのコンテンツ（プレーンテキスト）としてユーザーキーを貼り付け、New Relicのユーザーキー用の2つ目のシークレット（たとえば`newrelic-user-key`という名前）を作成してください。

* サーバーレスアプリケーションを作成し、OCIログを処理して転送するNew Relic関数をデプロイしてください。<br />

  1. **ロギング用のサーバーレスアプリケーションを作成します**

     * OCIコンソールの<DNT>**Developer Services**</DNT>にある<DNT>**Functions**</DNT>サービスにアクセスします。

     * この設定で新しいアプリケーションを作成します：

       * **名前**：分かりやすい名前（たとえば、`newrelic-logging-function-app`）
       * **コンパートメント**：指定したNew Relicコンパートメント
       * **VCN**：New Relicインテグレーション用に作成されたVCN
       * **サブネット**: 安全な接続のためのプライベートサブネット
       * **シェイプ**：アプリケーションシェイプ用の`GENERIC_X86`

     * アプリケーションの設定を保存します。

  2. **ログ用の環境変数を設定する**

     * アプリケーションの設定で、設定セクションに移動し、これらの変数を追加してください：

       * `VAULT_REGION`：キーボールトを作成した地域
       * `DEBUG_ENABLED`：本番環境用には`false`（またはデバッグ用には`true`）
       * `NEW_RELIC_REGION`：New Relicのリージョン（`US`、`EU`、または`JP`）
       * `SECRET_OCID`：キーボールトのNew RelicライセンスキーシークレットのOCID
       * `CLIENT_TTL`：`30`秒、ライセンスキーの更新間隔

     * オプションで、[ログフォワーダーのセルフオブザーバビリティメトリクス](/docs/logs/forward-logs/oci-log-forwarder-observability)を有効にするには、次も追加します

       * `FORWARDER_METRICS_TIER`：フォワーダーが出力する自己オブザーバビリティメトリクスを制御します。デフォルトは`basic`です。各設定で収集される内容については、[メトリクスティア](/docs/logs/forward-logs/oci-log-forwarder-observability/#metric-tiers)を参照してください。
       * `TENANCY_NAME`：表示名でOCIテナンシを識別し、フォワーダーのメトリクスにタグを付けることで、複数のテナンシをモニターする場合にそれらを区別できるようにします。
       * `COMPARTMENT_NAME`：ログ関数をデプロイしたコンパートメントを表示名で識別し、コンパートメントごとの内訳を示すためにメトリクスにタグを付けます。テナンシのルートコンパートメントにデプロイした場合は、`TENANCY_NAME`と同じ値を使用します。

     * フォワーダーのメトリクスを有効にしたら、[オブザーバビリティダッシュボードをインポート](/docs/logs/forward-logs/oci-log-forwarder-observability/#observability-dashboard)して視覚化してください。

     * 設定変数を保存してください。

  3. **ロギング関数をデプロイします**

     * 以下の仕様で、アプリケーション内に新しい関数を作成します：

       * **関数名**：分かりやすい名前（例：`newrelic-logging-function`）
       * **イメージソース**：コンテナレジストリ内のプライベートリポジトリにコピーするNew RelicログDockerイメージ
       * **メモリ割り当て**：128 MB以上
       * **タイムアウト**：300秒（適切な処理時間を確保するため）

     * Dockerイメージの場合は、Docker HubからNew Relicログフォワーダーイメージの特定のバージョンをプルし（:latestではなく — 現在のバージョンについてはDocker Hubのタグページを確認してください）、同じバージョンタグで独自のコンテナレジストリにプッシュします。

     * イメージにタグを付けて、関数と同じリージョンにあるネームスペース内のプライベートリポジトリにプッシュし、関数の設定で参照します。

     * 関数の作成とデプロイメントのプロセスを完了します。

     * 後でアップグレードするには、新しいイメージを再度プッシュし、それを使用するように関数を更新します。完全な手順については、『[OCIログ転送インテグレーションのアップグレード](/docs/logs/forward-logs/oci-log-forwarder-upgrade)』をご覧ください。

  4. **（オプション）関数のログ記録を有効にする**

     * 関数アプリケーションの監視設定にアクセスしてください。
     * 適切なロググループを選択または作成し、ログの保持ポリシーとアクセスポリシーを設定して、関数のログ収集をアクティブ化することで、関数の呼び出しログを有効にします。
     * 詳細については、[関数のログファイルのエクスポート](https://docs.oracle.com/en-us/iaas/Content/Functions/Tasks/functionsexportingfunctionlogfiles.htm)に関するOracleのドキュメントを参照してください。
</Collapser>

<Collapser id="terraform" title="Terraformで自動化する">
Terraformは、ログに推奨されるセットアップ方法です。<br />インテグレーションの詳細な手順については、[『OCIクラウドインテグレーションガイド』](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#oci)を参照してください。<br />
</Collapser>
</CollapserGroup>
</Step>

<Step>
### ロググループを計装してください

接続を作成すると、New RelicのOCIページに、**Add instrumentation** \[計装の追加]コントロールを含むログビューが表示されます：

1. **Add instrumentation** \[計装を追加]をクリックしてください。デフォルトでは、**Not instrumented** \[インストゥルメントされていない]タブにフィルタリングされています。
2. コンパートメントを展開して個々のロググループを表示し、モニターする対象を選択してください。また、**Enable audit logs** \[監査ログを有効にする]をオンにして、OCI監査ログを含めることもできます。
3. 選択内容を確認してください。New Relicには、これから計装するコンパートメントとロググループの数の概要が表示されます。次に、**Deploy to OCI** \[OCIにデプロイ]をクリックしてください。
4. OCIでのデプロイメントが完了すると、コンパートメントは**Instrumented** \[インストゥルメントされた]タブに移動し、そのデータは<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; OCI**</DNT>に表示されます。

データが表示されるまで最大30分かかる場合があります。その後も表示されない場合は、OCIコンソールでデプロイメントのステータスを確認してください。

後で追加のロググループを計装するには、New RelicのOCIページに戻り、これらの手順を繰り返してください。
</Step>

<Step>
### データを探す、使う

<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; OCI**</DNT>にデータが表示され始めたら、インテグレーションが機能していることを確認し、活用してください：

1. OCIアカウントがインテグレーションリストに表示されることを確認してください。

2. 以下のいずれかの場所で、ログを受信していることを確認してください：

   * [ログUI](https://one.newrelic.com/launcher/logger.log-launcher)：<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Logs**</DNT>に移動し、OCIログが表示されることを確認します。

   * [NRQLクエリツール](/docs/chart-builder/use-chart-builder/choose-data/use-advanced-nrql-mode-specify-data)：次のようにNRQLクエリを実行します：

     ```sql
     SELECT * FROM Log
     ```

3. ログの問題に関するプロアクティブな通知を受け取るには、[アラート条件を作成](/docs/alerts/create-alert/create-alert-condition/alert-conditions)してください。

4. OCIログデータを可視化し、トレンドをモニターするには、[カスタムダッシュボードを構築](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)してください。

30分経過してもデータが表示されない場合は、[トラブルシューティング](/docs/infrastructure/oci/troubleshoot)をご覧ください。
</Step>
</Steps>
