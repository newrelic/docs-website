<DNT>**Vulnerability Identifier:**</DNT> NR26-16

<DNT>**Priority:**</DNT> 致命的

## 概要

OpenJDK HotSpot Java仮想マシン（JVM）のハードウェア・アクセラレーションによるBase64デコーダーにおいて、深刻なメモリ破損の脆弱性（CVE-2026-114938）が公開されました。影響を受けるJavaアプリケーションが特別に細工されたBase64エンコードの入力（HTTP Authorizationヘッダー、JWT、SAMLトークン、またはファイルのアップロードなど）を処理すると、整数アンダーフローにより境界外ヒープ書き込みがトリガーされる可能性があります。悪用に成功すると、アプリケーションのクラッシュ（サービス拒否）を引き起こしたり、機密性の高いヒープメモリを公開したり、認証されていないリモートコード実行（RCE）を許可したりする可能性があります。

## アクションアイテム

### 対応は不要です。

New Relicは、New Relic JavaエージェントにJavaランタイムを同梱していません。外形監視のパブリックロケーションを含む、New Relicがホストするサービスについては、顧客によるアクションは必要ありません。

以下の場合、顧客による対応が必要です。

### 外形監視プライベートロケーション（Synthetics Job Managerおよびpingランタイム）

プライベートロケーションの外形監視ジョブマネージャー（SJM）およびpingランタイムには、Javaランタイムが含まれています。パッチが適用されたJavaランタイムを含む更新されたイメージは、2026年11月19日に公開されました。

* 外形監視ジョブマネージャーを[release-659](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-659/images/sha256-11fa4a7b78d7a7d708b1f5efec790dc066ab6c02d3b3f02c7a59a8b885913828)以降に、pingランタイムを[1.89.0](https://hub.docker.com/layers/newrelic/synthetics-ping-runtime/1.89.0/images/sha256-33da2eb67b404b09f19e1ea232e80be22d403e97abbeaf2b0f26bc95d2eae646)以降にアップグレードしてください。
* 設定でpingランタイムを特定のバージョンに固定している場合は、1.89.0以降にアップデートしてください。`latest`タグを使用している場合は、Synthetics Job Managerを再起動して、更新されたランタイムをプルしてください。
* [release-655](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-655/images/sha256-c587a634136aeed4179ebd216d993c9aea4b50a6a88f977fc5099fb164b42c57)より古いバージョンのSynthetics Job Managerを実行している場合、現在のリリースへのインプレース・アップグレード・パスはありません。最新バージョンへの移行を計画し、まずは本番環境以外の環境で検証してください。インストレーション手順については、[「Synthetics Job Managerのインストール」](/docs/synthetics/synthetic-monitoring/private-locations/install-job-manager)を参照してください。
* Synthetics Job Managerをすぐにアップグレードできない場合は、Synthetics Job ManagerコンテナにJVMオプション`JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"`を設定してください。x86-64ホストでのみ、代わりに`-XX:UseAVX=2`を使用できます。ARM上のJVMはこのオプションを認識せず、起動に失敗します。このオプションは、Synthetics Job Managerがリリースするpingランタイムコンテナには適用されないため、完全に修復するにはpingランタイムイメージをアップデートする必要があります。

### New Relic Javaエージェントによってモニターされるものを含む、お客様のJavaアプリケーション

Javaアプリケーションは、以下のすべてに該当する場合にのみ影響を受けます：

* アプリケーションは、バージョン17.0.6以降（ただし、2026年11月のクリティカルパッチアップデートより前）のHotSpotベースのOpenJDKディストリビューションで実行されます。例として、Oracle Java SE、Amazon Corretto、Eclipse Temurin、Azul Zulu、Red Hat OpenJDK、Microsoft Build of OpenJDKなどが挙げられます。
* ホストにAVX-512 VBMIをサポートするx86-64プロセッサ（Intel Xeon Ice Lake以降、またはAMD Zen 4以降）が搭載されている。AWS Gravitonを含むARM64プロセッサは影響を受けません。
* アプリケーションが、JavaのBase64デコーダーに到達する可能性のある信頼できない入力を処理する。

**修正：**インターネットに接続されているシステムから順に、Javaランタイムをベンダーの2026年11月のセキュリティリリースにアップデートしてください。詳細については、Oracleの[クリティカル・セキュリティ・パッチ・アップデート](https://www.oracle.com/security-alerts/cspunov2026.html)（2026年11月）、OpenJDKの[脆弱性アドバイザリ](https://openjdk.org/groups/vulnerability/advisories/2026-11-17)（2026/11/17）、またはJDKベンダーのアドバイザリを参照してください。

## よくあるご質問

1. **これはNew Relicのエージェントに影響しますか？**

   New Relic Javaエージェントは、Javaランタイム（JDK/JVM）をバンドルまたは配布していません。アプリケーションの環境で利用可能なJavaランタイムを使用して、Javaアプリケーションをインストゥルメントします。

2. **New RelicのJavaエージェントをアップデートする必要がありますか？**

   いいえ。New RelicのJavaエージェントにはJavaランタイムは含まれておらず、この脆弱性に対するJavaエージェントのアップデートは必要ありません。

3. **どのシステムが影響を受けますか？**

   AVX-512 VBMIをサポートするx86-64プロセッサのみです。ARM64プロセッサは影響を受けません。OpenJDKおよびOracleは修正を公開しています。

4. **アプリケーションのJavaランタイムが影響を受けるかどうかは、どうすればわかりますか？**

   JavaのバージョンとCPUを確認してください。New Relic APMによってモニターされるアプリケーションの場合、JVMバージョンはサービスのEnvironment \[環境] ページに表示されます。詳細については、[「APMアプリに関する環境データの取得」](/docs/apm/agents/manage-apm-agents/troubleshooting/get-environment-data-about-your-apm-app)をご覧ください。また、必ずホストを選択してください。または、ホスト上で`java -version`を実行してください。

   Linuxでは、次を使用してCPUを確認します：

   ```bash
   grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(avx512f|avx512bw|avx512vbmi|bmi2)$'
   ```

   4つのフラグすべてが表示される場合のみ、CPUは影響を受けます。

5. **脆弱性を修正するにはどうすればよいですか？**

   インターネットに接続されているシステムから順に、Javaランタイムをベンダーの2026年11月のセキュリティリリースにアップデートしてください。詳細については、Oracleの[Critical Security Patch Update](https://www.oracle.com/security-alerts/cspunov2026.html)（2026年11月）、OpenJDKの[脆弱性アドバイザリ](https://openjdk.org/groups/vulnerability/advisories/2026-11-17)（2026/11/17）、またはJDKベンダーのアドバイザリを参照してください。

6. **すぐにパッチを適用できない場合はどうすればよいですか？**

   一時的な緩和策として、`JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"`を使用してJVMを起動します。x86-64ホストの場合にのみ、代わりに`-XX:UseAVX=2`を使用できます。ARM上のJVMはこのオプションを認識せず、起動に失敗します。どちらのオプションも一時的なものであり、パッチ適用の代わりにはなりません。

7. **New Relicは悪用の形跡を確認していますか？**

   当社の環境では、この脆弱性の悪用の痕跡は確認されていません。

8. **質問がある場合はどうすればよいですか？**

   この連絡に関するサポートが必要な場合は、アプリ内サポートからサポートケースをオープンしてください。
