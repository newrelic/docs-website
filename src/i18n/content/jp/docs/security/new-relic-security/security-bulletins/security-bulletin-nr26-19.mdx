<DNT>**Vulnerability Identifier:**</DNT> NR26-19

<DNT>**Priority:**</DNT> 致命的

## 概要

2026年11月18日、nginxは、まとめて「nginx2root」として知られるHTTP/2モジュールの脆弱性を公開しました。F5は、CVSS v4.0において2つの主な問題を9.2（Critical）と評価しています。

CVE-2026-123007は、nginx 1.9.5～1.31.8に影響を与えます。nginxが特別に細工されたHTTP/2トラフィックを処理する際、フロー制御ウィンドウが許容上限を超える可能性があり、ヒープバッファオーバーフローを引き起こす恐れがあります。認証されていない攻撃者が、nginxワーカープロセスをクラッシュさせたり、そのメモリを破損させたりする可能性があります。ASLRが無効になっている場合、または攻撃者がASLRを回避できる場合、攻撃者はコードを実行することも可能になります。

CVE-2026-123633は、nginxがHTTP/2クライアント接続を受け入れ、バックエンドにrequestsをプロキシする場合、nginx 1.19.7～1.31.8に影響を与えます。特別に細工されたリクエストは、`worker_connections`が不足しているワーカープロセスでuse-after-freeを引き起こす可能性があります。これは、サービス拒否、またはASLRの回避によるコード実行につながる可能性があります。

両方の脆弱性の修正は、nginx 1.30.7（stable）および1.31.9（mainline）、ならびにNGINX Plus PLS.37.0.8.1およびPLS.37.3.0.1に含まれています。同じリリースで、他のいくつかのnginxの脆弱性も修正されています。その一部はHTTP/2に関連していません。以降のリリースであるnginx 1.30.8および1.31.10でも、CVE-2026-132779が修正されています。[公開されているエクスプロイト](https://github.com/sfewer-r7/CVE-2026-123007?utm_source)の詳細を確認できます。2026年11月24日現在、CISAのKnown Exploited Vulnerabilitiesカタログにこれらの脆弱性はリストされていません。

**New Relic nginxインテグレーション（nri-nginx）を含むNew Relicエージェントとインテグレーションには、nginxが含まれていないため影響を受けません。**New Relicは、nginxを使用するインターネット向けサービスにおいて、nginxをアップデートしました。New Relicは、自社の環境において悪用の証拠を確認していません。

## 推奨されるアクション

ご利用のNew Relicサービス、またはインストール済みのNew Relicエージェントおよびインテグレーションについて、必要な対応はありません。それでも、New Relicは、独自の環境でHTTP/2を有効にしてnginxを実行している顧客に対し、最新のnginxリリース（1.30.8 stableまたは1.31.10 mainline）、NGINX Plus PLS.37.0.8.1またはPLS.37.3.0.1以降、あるいは修正を含むLinuxディストリビューションパッケージにアップグレードすることを強くお勧めします。

### 推奨事項

* まず、HTTP/2が有効になっているインターネット向けサーバーをアップグレードしてください。`listen`ディレクティブに`http2`が含まれている場合、または`http2 on;`が設定されている場合、HTTP/2は有効になります。
* アップグレード後にnginxを再起動して、パッチが適用されたバイナリを実行してください。
* nginxを含むコンテナイメージを再ビルドして再デプロイしてください。ホストにパッチを適用しても、コンテナ内のnginxは更新されません。
* **Linuxディストリビューションパッケージ：**ディストリビューションは多くの場合、アップストリームのバージョン番号を変更せずに修正を追加します。Ubuntuは、2026年11月19日に、サポートされているすべてのリリース向けに修正済みパッケージを公開しました。その他のディストリビューションについては、CVE-2026-123007およびCVE-2026-123633に関するベンダーのアドバイザリを確認してください。
* Kubernetes Ingressコントローラー、ゲートウェイ、アプライアンスなど、nginxを組み込んでいる製品：修正を含むリリースについて、ベンダーまたはプロジェクトにご確認ください。
* New RelicがGitHubで公開しているサンプルまたはデモアプリケーションのいずれかをデプロイし、それがパブリックnginxイメージを使用している場合は、最新のnginxイメージから再ビルドしてください。

## 一時的な緩和策

これらの脆弱性、および同じリリースで修正されたその他の脆弱性を完全に修正できるのは、アップグレードのみです。アップグレードするまでの間：

* 影響を受けるリスナーでHTTP/2を無効にし、nginxをリロードしてください。どちらの脆弱性もHTTP/2を必要とします。無効にするには、`listen`ディレクティブから`http2`を削除するか、`http2 off;`を設定してください。クライアントはHTTP/1.1にフォールバックします。

## よくあるご質問

1. **これはNew Relicのエージェントやインテグレーションに影響しますか？**

   いいえ。New Relicエージェントとインテグレーションにはnginxは含まれていません。New Relic nginxインテグレーション（nri-nginx）は、実行中のnginxサーバーからメトリクスを収集します。これにはnginxは含まれていません。

2. **New Relic nginxインテグレーションをアップデートする必要がありますか？**

   いいえ。nginx自体をアップグレードしてください。

3. **一部のNew Relic Helmチャートは、`ingress-nginx/kube-webhook-certgen`という名前のイメージを参照しています。影響を受けますか？**

   いいえ。そのイメージはKubernetes ingress-nginxプロジェクトの証明書生成ユーティリティであり、nginxは含まれていません。

4. **使用しているnginxが影響を受けるかどうかを確認するにはどうすればよいですか？**

   まず、HTTP/2が有効になっているかどうかを確認します：`nginx -T | grep http2`を実行してください。次に、バージョンを確認します：

   * nginx.orgからnginxをインストールしたか、ご自身でビルドした場合は、`nginx -v`を実行してください。バージョンが1.9.5以降で、1.30.7（stable）または1.31.9（mainline）より前の場合、影響を受けます。
   * Linuxディストリビューションからnginxをインストールした場合、バージョン番号だけでは保護されているかどうかはわかりません。インストールされているパッケージバージョン（たとえば`dpkg -l | grep nginx`や`rpm -q nginx`）と、ディストリビューションのアドバイザリを比較してください。

5. **自分のシステムがターゲットにされたかどうかは、どのようにして確認できますか？**

   悪意のあるHTTP/2トラフィックは、アクセスログに通常のrequestsとして表示されません。エクスプロイトの試みは、通常、nginxワーカープロセスをクラッシュさせます。シグナル11（セグメンテーション違反）で終了するワーカープロセスがないか、nginxエラーログを監視してください。nginxのログをNew Relicに転送している場合は、このメッセージに対して[集計を作成](/docs/tutorial-create-alerts/create-an-alert/)できます。また、シェルやその他の予期しない子プロセスを開始するnginxワーカープロセスがないかどうかも確認してください。

6. **New Relicは悪用の形跡を確認していますか？**

   当社の環境では、これらの脆弱性が悪用された兆候は確認されていません。

7. **これらの脆弱性について質問があります。誰に連絡すべきですか？**

   ご利用のNew Relicサービスに関連するこれらの脆弱性についてご質問がある場合は、アプリ内サポートから[サポートケースを作成](/docs/new-relic-solutions/solve-common-issues/find-help-get-support/#file-ticket)するか、New Relicアカウント担当者にお問い合わせください。
