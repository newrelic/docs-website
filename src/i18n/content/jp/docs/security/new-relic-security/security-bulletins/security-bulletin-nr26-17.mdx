<DNT>**Vulnerability Identifier:**</DNT> NR26-17

<DNT>**Priority:**</DNT> 致命的

## 概要

2026年11月19日、New Relicのセキュリティインシデント対応チームは、最近公開されたRubyの脆弱性「Ruby2Shell」（CVE-2026-132825）に対して、当社のサービスとエンタープライズインフラストラクチャの包括的な評価を開始しました。これは、Rubyインタプリタの文字列の大文字小文字変換における1バイトのヒープベースのバッファオーバーフローであり、リモートコード実行（RCE）またはサービス拒否（DoS）を可能にする可能性があります。

## アクションアイテム

### Rubyエージェントを使用している顧客によるアクションは不要です。

New Relicの分散Rubyエージェントは影響を受けません。Rubyエージェントを使用しているNew Relicの顧客は、この脆弱性に対してアクションを実行する必要はありません。

## よくあるご質問

1. **これはNew Relicのエージェントに影響しますか？**

   New Relic Ruby言語エージェントは影響を受けません。その他のNew Relic言語エージェントも影響を受けません。Fluentdイメージは、New Relicエージェントでは使用されていません。

2. **どのシステムが影響を受けますか？**

   次のイメージを実行しているコンテナランタイム（Kubernetes、Dockerなど）：

   * `newrelic/newrelic-fluentd-docker`
   * `newrelic/fluentd`
   * `newrelic/k8s-golang-apm-linkage-demo`

3. **脆弱性を修正するにはどうすればよいですか？**

   `newrelic/newrelic-fluentd-docker`イメージを使用する場合：

   1. 修正済みのイメージをプルしてください：

      ```shell
      docker pull newrelic/newrelic-fluentd-docker:1.20.1
      ```

   2. 新しいイメージでコンテナを再作成してください。イメージをプルしても、すでに実行中のコンテナは更新されません。Kubernetes、Docker、またはその他のコンテナランタイムで、イメージタグを1.20.1に変更して再デプロイしてください。

   3. `newrelic/newrelic-fluentd-docker`から独自のイメージをビルドする場合は、`docker build --pull`で再ビルドしてください。

   4. 実行中のバージョンを確認してください：

      ```shell
      docker exec <container> fluentd --version
      ```

   5. 出力には`fluentd 1.20.1`以降が表示されます。

   イメージを使用していない場合は、New `newrelic/newrelic-fluentd-docker`Relic[ Fluentdプラグイン](https://www.fluentd.org/)[ と共に Fluentd](/docs/logs/forward-logs/fluentd-plugin-log-forwarding/) を使用することを検討してください。

4. **新しいイメージをプルすると、コンテナは更新されますか？**

   いいえ。実行中のコンテナは、再作成するまで古いイメージを保持します。

5. **infrastructureエージェントのログ転送は影響を受けますか？**

   いいえ。infrastructureエージェントおよびKubernetesインテグレーションのログ転送では、Fluentdではなく[Fluent Bit](/docs/logs/forward-logs/fluent-bit-plugin-log-forwarding/)を使用します。

6. **質問がある場合はどうすればよいですか？**

   この連絡に関するサポートが必要な場合は、アプリ内サポートからサポートケースをオープンしてください。
