<DNT>**Vulnerability Identifier:**</DNT> NR26-12

<DNT>**Priority:**</DNT> 高

## 概要

2026年10月17日～2026年10月20日の間に、研究者は、eMudhraによって発行された8つの中間認証局（CA）証明書の秘密鍵が復元される可能性があることを公表しました。これらの鍵を持つ者は誰でも、ソフトウェアがまだ信頼している場合、ソフトウェアが本物として受け入れる証明書を作成できる可能性があります。主要なOSやWebブラウザはすでにこれらの証明書の信頼を取り消していますが、一部のコンテナイメージを含む、独自のCAトラストストアを管理するアプリケーションは更新する必要があります。

New Relicは、外形監視プライベートロケーション用に提供しているコンテナイメージを再構築し、これらの証明書を使用しないようにしました。イメージは自動的に更新されないため、外形監視プライベートロケーションを実行している顧客は、新しいイメージをプルしてコンテナを再起動する必要があります。

レガシーランタイムでまだ実行されているモニターを特定するには、アカウントのquery builder \[クエリビルダー]で次のNRQLクエリを実行します。

```sql
SELECT uniques(monitorName) FROM SyntheticCheck WHERE runtimeType = 'NODE_API' AND runtimeTypeVersion = '16.10' SINCE 1 day ago
```

New Relic UIの[Synthetics EOL screen \[外形監視のEOL画面\]](https://onenr.io/0gR77nzxaRo)で、影響を受けるモニターを特定することもできます。**Monitor Type: Script API** \[モニタータイプ：スクリプトAPI]でフィルタリングして、Node.js 16.10でまだ実行されているすべてのモニターを表示します。

### プライベートロケーション

**対応必須：**プライベートロケーションを実行しているすべての顧客は、ランタイムのバージョンに関係なく、手動で最新のイメージをプルして再デプロイする必要があります。

### 重要なお知らせ：Node.js 16.xの移行が必要です（パブリックおよびプライベートロケーション） [#node-16-migration]

Node.js 16.10で実行されているScripted APIモニターは、2026年11月18日に[サポート終了](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/)を迎えます。これらのモニターはeMudhraの脆弱性にさらされており、これらの古いバージョンでまだ実行されているモニターはNode.js 22.23.0に移行する必要があります。これは、モニターがパブリックロケーションとプライベートロケーションのどちらで実行されているかに関係なく適用されます。

**推奨される対応：**2026年11月18日より、New RelicはNode.js 16.xでまだ実行されているパブリックロケーションのモニターを現在のランタイムに自動的にアップグレードします。モニターが新しいランタイムで意図したとおりに動作し続けることをテストし、脆弱性のあるバージョンから移行できるように、その日付より前に、できるだけ早く移行することを強くお勧めします。手順については、「[Scripted APIモニターをNode.js 22にアップグレードする](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/)」を参照してください。

## 技術的な脆弱性情報

この問題にCVEは割り当てられていません。

## よくあるご質問

1. **New Relicのパブリックロケーションのインフラストラクチャは影響を受けましたか？**

   New Relicは、最新のランタイムで実行されているパブリックロケーションのインフラストラクチャにパッチを適用しました。ただし、Node.js 16.xに明示的に固定されているモニターは、アカウント所有者によって更新されるまで、引き続きそのバージョンで実行されます。

2. **モニター結果は改ざんされていましたか？**

   New Relicには、当社の外形監視イメージが改ざんされた証拠はありません。

3. **Synthetics secure credentials \[外形監視のセキュアな認証情報] に保存されている認証情報をローテーションする必要がありますか？**

   ネットワークやインフラストラクチャが侵害されたと考える特別な理由がない限り、対応は必要ありません。

4. **さらに質問がある場合は、どこに問い合わせればよいですか？**

   New Relicプラットフォームのヘルプセクションから、サポートチームにケースをオープンしてください。
