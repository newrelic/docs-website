<DNT>**Vulnerability Identifier:**</DNT> NR26-14

<DNT>**Priority:**</DNT> 高

## 概要

2026年10月17日～2026年10月20日の間に、研究者はeMudhraによって発行された8つの中間認証局（CA）証明書の秘密鍵が復元可能であることを公表しました（CVE-2026-111943）。これらの鍵を持つ者は誰でも、ソフトウェアがまだそれらを信頼している場合、本物として受け入れられる証明書を作成できます。ブラウザおよびOSはこれらの証明書をブロックしていますが、一部のコンテナイメージなど、独自の信頼されたCAリストを保持するソフトウェアは更新する必要があります。

New Relicは、これらのCAによって発行された証明書を受け付けないように、以下のKubernetesコンポーネントを更新しました。更新されたバージョンは自動的には反映されません。顧客は、以下に記載されているバージョンにアップグレードする必要があります。

**\*アップグレードに関する注意事項。**`newrelic-infrastructure` 4.xはメジャーバージョンです。唯一の破壊的変更は、Windowsノードに影響します。アップグレードする前に、[リソース](#resources)セクションのチャートのリリースノートを参照してください。

## 技術的な脆弱性情報

* emSign ECC Root CA - G3にチェーンされ、クロス署名を通じてAAA Certificate Servicesにチェーンされている8つの中間CAが影響を受けます。

* 修正済みのAlpineベースのイメージは、ca-certificates 20261020-r0を含むAlpine 3.24.3で構築されており、CAバンドルからemSign ECC Root CA - G3およびAAA Certificate Servicesが削除されています。

  * k8s-agents-operator 0.54.0は、両方のルートが削除されたdistrolessベースで構築されています。
  * prometheus:v3.15.1（アップストリーム）も、どちらのルートも含まないCAバンドルを同梱しています。

* New Relic KubernetesインテグレーションのバイナリはGo 1.27.3で構築されており、そのTLSライブラリは、ルートが引き続き信頼されている場合でも、影響を受ける8つのキーを含む証明書チェーンを拒否します。インフラストラクチャ・バンドル（infrastructure-bundle）に含まれる一部のオンホストインテグレーションは以前のGoバージョンを使用していますが、それらのCAバンドルも修正済みです。

* 影響は、パブリックルートストアを使用する接続（エージェントのNew Relicエンドポイントや設定された任意のプロキシへの接続）に限定されます。クラスタ内の接続（Kubernetes APIサーバー、kubelet、コントロールプレーン）は、クラスタ独自のCAを使用するため、影響を受けません。
