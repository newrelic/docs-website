<DNT>**Priority:**</DNT> 致命的

## 概要

PHPランタイムのセッション拡張機能において、重大な脆弱性（CVSS 4.0スコア9.2）が公開されました。PHPのデフォルトのファイルセッションハンドラーを使用するアプリケーションに影響します。PHPプロジェクトは、2026年11月19日に修正版をリリースしました。

CVE-2026-109618およびCVE-2026-109619（[NR26-10](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-10)）の2026年10月の修正リリースには、この修正は含まれていません。ネイティブのファイルハンドラーの代わりにデータベースまたはRedisにセッションを保持するアプリケーションは、この脆弱性の対象外です。

**New Relicが配布するソフトウェアおよびサービスは影響を受けません。**New Relicは、顧客に配布するソフトウェアにPHPランタイムを同梱していません。New RelicのPHPエージェントは顧客自身のPHP環境内で実行されるため、脆弱性のあるコンポーネントではありません。PHPエージェントは顧客の既存のPHPインタープリター内で拡張機能として実行されるため、修復はPHP自体をアップグレードすることで行われます。New Relicは、自社の環境で悪用された証拠を確認していません。

## 推奨されるアクション

ご利用のNew Relicソフトウェアおよびサービスに関して、必要なアクションはありません。それでも、New Relicは、New Relicの計装の有無にかかわらず、PHPアプリケーションを実行している顧客に対し、該当するブランチの修正済みリリースにアップグレードし、すべてのPHPワーカーを再起動することを強くお勧めします。同じリリースで17件のアドバイザリが修正されるため、1回のアップグレードですべてに対応できます。

### 推奨事項

* **ディストリビューション・パッケージ：**
  * ディストリビューションによっては、PHPのバージョン文字列を変更せずに修正が含まれている場合があります。バージョン番号に依存するのではなく、ベンダーのセキュリティアドバイザリを確認してください。
* **サポート終了バージョン（PHP 8.1以前）：**
  * これらのバージョンはCVEレコードに記載されておらず、公式の修正は提供されません。パッチが適用されていないビルドは影響を受けるものとして扱い、ディストリビューションが修正をバックポートしているかどうかを確認し、サポートされているブランチへのアップグレードを計画してください。
* **マネージドホスティング：**
  * 開発、テスト、プレビューを含むすべての環境で修正済みのバージョンが実行されていることをプロバイダーに確認してください。

## 一時的な緩和策

PHPランタイムのアップグレードのみが、この脆弱性を完全に修正します。すぐにアップグレードできない場合は、一時的な対策として、機能が不要であれば管理上`session.upload_progress.enabled`を無効にし、セッションに保存される信頼できないデータの量を制限してください。アップロードの進行状況を無効にすると、その入力パスは削除されますが、攻撃者が制御するセッションデータを独自に保存するアプリケーションは修正されません。レコードをアトミックに置換するセッションストレージのバックエンドは、このファイル書き込みの欠陥を回避できます。組み込みのファイルハンドラーを使用するアプリケーションの場合、ランタイムのPHPアップデートが引き続き推奨される修正です。詳細については、以下の「Supporting Documents」を参照してください。

## よくあるご質問

1. **使用しているPHPバージョンとセッション設定を確認するにはどうすればよいですか？**

   ホストまたはコンテナで`php -v`を実行します。session.save\_handlerを確認しますおよび`phpinfo()`または`php.ini`の`session.upload_progress.enabled`。New Relicが認識するPHPバージョンについては、New Relic UIのホストまたはアプリケーションの詳細を確認してください。

2. **New Relic PHPエージェントをアップデートする必要がありますか？**

   いいえ。脆弱性はエージェントではなく、PHPランタイムに存在します。この脆弱性を修正するには、PHPランタイムを修正済みのバージョンにアップデートしてください。

3. **自分のシステムがターゲットにされたかどうかは、どのようにして確認できますか？**

   これまでのところ、公的な侵害の痕跡は報告されていません。顧客は、2026年11月19日以降のWebログを確認し、原因不明のPHPワーカーのクラッシュやメモリ不足による強制終了、およびPHPエンドポイントに対する認証されていないマルチパートPOST requestsがないか確認する必要があります。また、Webディレクトリ内に新規または変更されたPHPファイルがないかどうかも確認してください。

4. **この脆弱性について質問や懸念があります。誰に連絡すべきですか？**

   New Relicサービスに関連するこの脆弱性についてご質問がある場合は、In-app support \[アプリ内サポート]から[サポートケース](/docs/new-relic-solutions/solve-common-issues/find-help-get-support/#file-ticket)を起票するか、New Relicのアカウント担当者にお問い合わせください。
