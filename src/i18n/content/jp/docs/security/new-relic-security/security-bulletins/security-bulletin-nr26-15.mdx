<DNT>**Vulnerability Identifier:**</DNT> NR26-15

<DNT>**Priority:**</DNT> 高

## 概要

2026年10月17日～2026年10月20日の間に、研究者はeMudhraによって発行された8つの中間認証局（CA）証明書の秘密鍵が復元可能であることを公表しました（CVE-2026-111943）。これらの鍵を持つ者は誰でも、ソフトウェアがまだそれらを信頼している場合、本物として受け入れられる証明書を作成できます。ブラウザおよびOSはこれらの証明書をブロックしていますが、一部のコンテナイメージなど、独自の信頼されたCAリストを保持するソフトウェアは更新する必要があります。

New Relicは、以下のinfrastructureエージェント、そのコンテナイメージ、およびオンホストインテグレーションを更新し、これらのCAによって発行された証明書を受け入れないようにしました。更新されたバージョンは自動的には反映されません。顧客は、以下に記載されているバージョンにアップグレードする必要があります。

**\*アップグレードに関する注意事項。**

* infrastructureエージェント 2.0はメジャーバージョンです。デフォルトでsafe\_dir\_check\_enabledがオンになるため、エージェントは、シンボリックリンクである、エージェントのユーザーやグループが所有していない、またはグループや他のユーザーが書き込み可能な作業ディレクトリを再利用しなくなります。代わりにディレクトリを再作成します。以前の動作を維持するには、safe\_dir\_check\_enabledをfalseに設定してください。アップグレードする前にリリースノートをご覧ください。リリースノートについては、以下のリンクをご覧ください。
* Windowsでは、2.0でインストーラからレガシーFluent Bit 1.9が削除されます。ログ転送ではFluent Bit 5.1.5を使用します。

## 技術的な脆弱性情報

* emSign ECC Root CA - G3にチェーンされ、クロス署名を通じてAAA Certificate Servicesにチェーンされている8つの中間CAが影響を受けます。
* infrastructureエージェントおよびオンホストインテグレーションは、Go 1.27.3またはGo 1.26.10でビルドされています。どちらにも`CVE-2026-111943: crypto/x509`に対するGoの修正が含まれており、ルートが引き続き信頼されている場合でも、影響を受ける8つの中間証明書が含まれる証明書チェーンを拒否します。
* `newrelic/infrastructure` 2.0.1および`newrelic/infrastructure-bundle` 3.6.1のイメージは、CAバンドルからemSign ECC Root CA - G3およびAAA Certificate Servicesを削除するca-certificates 20261020-r0を含むAlpine 3.24.3で構築されています。
  * `newrelic/infrastructure-bundle` 3.6.1のJavaトラストストアは、JMXベースのインテグレーションで使用されますが、どちらのルートも含まれていません。
* ホストでは、エージェントとインテグレーションはOSのトラストストアを使用します。OSベンダーのca-certificatesアップデートも適用してください。
* nri-jmx、nri-kafka、およびnri-cassandraは、Javaランタイム上で実行され、そのトラストストアまたはインテグレーション設定で設定されたトラストストアを使用するnr-jmxを通じて、JMXメトリクスを収集します。Javaベンダーのアップデートも適用してください。
* 影響範囲はパブリックルートストアを使用する接続に限定されます。これには、New Relicエンドポイントおよび設定されたプロキシへのエージェントの接続、ならびにインテグレーションがモニターするサービスへのTLS接続が含まれます。

## よくあるご質問

1. **エージェントイメージのCAバンドルから、影響を受ける証明書を削除しても安全ですか？**

   はい。New Relicのエンドポイントは影響を受けるCAによって発行された証明書を使用しないため、これらを削除してもエージェントのNew Relicへの接続には影響しません。インテグレーションがTLS経由で、証明書がemSign ECC Root CA - G3またはAAA Certificate Servicesにチェーンされているサービスのいずれかに接続する場合、削除後にその接続は失敗します。まず、それらの証明書を確認してください。

2. **イメージで安全に使用できるエージェントのバージョンはどれですか？**

   infrastructureエージェント2.0.1以降、`newrelic/infrastructure-bundle` 3.6.1以降、および上記に記載されているオンホストインテグレーションのバージョン。

3. **まだいくつか質問があるのですが、誰に連絡すればよいですか？**

   追加のサポートが必要な場合は、 New Relicプラットフォームのヘルプ セクションからサポート チームにケースをオープンしてください。
