<DNT>**Vulnerability Identifier:**</DNT> NR26-11

<DNT>**Priority:**</DNT> 高

## 概要

このお知らせは、パブリックロケーションおよびプライベートロケーションを使用しているNew Relicの外形監視の顧客に対して、顧客のアクションが必要になる可能性がある、Node.jsのバージョン（22.x、24.x、26.x）における重大なセキュリティの脆弱性についてお知らせするために発行しています。

**修正済みバージョン：** Node.jsの修正済みバージョンは22.23.4、24.22.1、および26.12.1です。

**サポート終了（EOL）バージョン：** Node.js 16.xを含む、Node.js 20以前のバージョンはサポートが終了しており、Node.jsプロジェクトからパッチは提供されません。Node.jsのEOLバージョンに対する唯一の対応策は、サポートされているリリースへの移行です。

## 必要なアクション

これらの脆弱性は、パブリックロケーションとプライベートロケーションの両方を使用している外形監視の顧客に影響します。それぞれに対する顧客の対応は以下のとおりです。

### パブリックロケーション

顧客のアクションは、モニターが最新のランタイムを使用しているかどうかによって異なります。

**対応不要：**パブリックロケーションにデプロイされた、最新のサポート対象ランタイムを使用しているモニターについては、対応は不要です。

### プライベートロケーション

**必要なアクション：**プライベートロケーションの場合、これらのCVEを修正するには、最新のランタイムイメージをプルする必要があります。`latest`タグを使用していない場合、プライベートロケーションにデプロイされたモニターに対する対応が必要です。

New Relic Syntheticsジョブマネージャー（SJM）自体は、脆弱性の原因ではありません。ただし、`node-api-runtime`および`node-browser-runtime`のコンテナイメージにはNode.jsがバンドルされており、直接的な影響を受けます。

プライベートロケーションを実行している場合は、次の手順を実行してください。

1. 影響を受けるランタイムイメージの最新バージョンをプルしてください：

   ```shell
   # Node API runtime
   docker pull newrelic/synthetics-node-api-runtime:latest

   # Node browser runtime
   docker pull newrelic/synthetics-node-browser-runtime:latest
   ```

2. 修正を適用するには、更新されたイメージをプルした後、コンテナを再起動してください。

詳細については、[ランタイム移行ガイド](/docs/synthetics/synthetic-monitoring/private-locations/runtime-transition-guide/)をご覧ください。

### 重要なお知らせ：Node.js 16.xのスクリプト化されたAPIモニター

Node.js 16.xで実行するように構成されたスクリプト化されたAPIモニターがある場合は、次の点にご注意ください：

* Node.js 16.xはすでに[サポート終了](https://nodejs.org/en/about/previous-releases)となっているため、Node.jsプロジェクトからこれらのCVEに対するセキュリティパッチは提供されません。
* スクリプトの互換性を保証できないため、New RelicはNode.js 16.xのモニターをNode 22.xに自動的に強制アップグレードしていません。一部のモニタースクリプトは、Node 22.xで正しく実行するためにコードの変更が必要になる場合があります。

2026年11月18日まで待つことなく、できるだけ早くNode 16.xモニターを確認し、Node 22.23.4へ移行することを強くお勧めします。移行手順の詳細については、[Scripted APIモニターをNode.js 22にアップグレードする](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/)を参照してください。

## よくあるご質問

1. **外形監視ジョブマネージャー（SJM）を更新する必要がありますか？**

   いいえ。これらの脆弱性は、SJM自体ではなく、ランタイム・コンテナ・イメージにバンドルされているNode.jsランタイムに存在します。ランタイム・コンテナ・イメージのみを更新する必要があります。

2. **ランタイムイメージを更新すると、実行中のモニターに影響しますか？**

   ランタイムイメージの更新後も、モニターは引き続き正常に実行されます。Node 22.xで実行されているモニターの動作に変更はありません。

3. **CVE-2026-111497はリモートで悪用される可能性はありますか？**

   はい。これはリモートコード実行の脆弱性です。これは、攻撃者が制御するサーバーからNode.jsプロセスがBrotli圧縮されたHTTPレスポンスを受信した際にトリガーされる可能性があります。ローカルアクセスは不要です。

4. **Node 16.xのモニターを実行しています。リスクはありますか？**

   はい。Node 16.xはサポートが終了しており、パッチは適用されません。Node 22.23.4に移行するまで、モニターは脆弱なままです。ランタイムアップグレードツールを使用して、ご自身で実行できます。詳細については、[モニターのランタイムの管理](/docs/synthetics/synthetic-monitoring/using-monitors/manage-monitor-runtimes/)を参照してください。

5. **Node 16.xモニターが自動的にアップグレードされなかったのはなぜですか？**

   Node 22.xにはNode 16.xからの破壊的変更が含まれており、これについてはNew Relicから事前にお知らせしています。現在もNode 16.xを使用しているスクリプト化されたAPIモニターは、エラーなしで自動的にアップグレードできなかったものです。そのため、New Relicは意図しないモニターの破損を防ぐため、これを顧客主導のアップグレードとしました。事前にお知らせしたEOLのタイムラインに従い、2026年11月18日にNode 16.xモニターを強制的にアップグレードします。

6. **プライベートロケーションのランタイムを更新した後、何かを再起動する必要がありますか？**

   コンテナの再起動のみが必要です。ホストの再起動は必要ありません。

7. **さらに質問がある場合は、どこに問い合わせればよいですか？**

   New Relicプラットフォームのヘルプセクションから、サポートチームにケースをオープンしてください。
