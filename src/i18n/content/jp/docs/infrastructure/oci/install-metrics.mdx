OCIメトリクスをNew Relicに送信するには、このガイドを使用してください。メトリクスは、OCIリソースの健全性、キャパシティ、およびパフォーマンスを追跡します。ログも送信する場合は、[OCIメトリクスとログのモニター](/docs/infrastructure/oci/install-metrics-and-logs)をご覧ください。ログのみを送信する場合は、[OCIログの転送](/docs/logs/forward-logs/oci-log-forwarding)をご覧ください。

## 互換性と要件 [#requirements]

始める前に、以下があることを確認してください：

* サポートされているリージョン（US、EU、またはJP）でinfrastructureモニタリング権限を持つNew Relicアカウント
* 有効なNew Relicの[Ingestライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)および[ユーザーキー](/docs/apis/intro-apis/new-relic-api-keys/#user-api-key)
* Identity and Access Management（IAM）ドメインを持つOCIテナンシ、およびそのドメインとルートコンパートメントへの一時的な管理アクセス（New Relicが長期的な認証情報を保存せずに認証するために使用するメカニズムである、ワークロード・アイデンティティ・フェデレーション（WIF）のセットアップを完了するのに十分なアクセス権）。セットアップが完了したら、このアクセス権を取り消すことができます。
* OCIテナンシOCIDとホームリージョン（例：`us-ashburn-1`）
* OCI API署名キー（Terraformでデプロイする場合のみ）

## ガイド付きインストレーション [#ui-install]

ガイド付きインストレーションは<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; Oracle Cloud Infrastructure**</DNT>でご利用いただけます。UIでは、OCIアカウントを接続し、次にモニターするメトリクスネームスペースをインストゥルメントする手順を案内します。

<Steps>
<Step>
### メトリクスデータ型を選択してください

以下の手順に従ってください。

1. <DNT>**Metrics**</DNT> を選択してください（パフォーマンスと使用状況の統計情報用）。
2. <DNT>**Continue**</DNT>をクリックします。
</Step>

<Step>
### インテグレーション方法を選択し、インテグレーションを設定してください。

組織のニーズに基づいて、OCIメトリクスをNew Relicに取り込むための希望するインテグレーション方法を選択してください：

<CollapserGroup>
<Collapser id="orm" title="Oracle Resource Managerを使用してOCIをモニターします。">
OCIコンソールで各要素を手作業で作成する代わりに、Oracle Resource Managerスタックを実行して、インテグレーションに必要なものをプロビジョニングします。画面上の指示に従って、接続を確立します。
</Collapser>

<Collapser id="manual" title="OCIアカウントを手動で統合する">
OCIコンソールで、必要なポリシーとサービス・コネクタを作成します。ガイド付きインストレーションでは、次の手順を順番に案内します：コンパートメントの作成、動的グループの作成、キー・ボールト・シークレットの設定、ポリシーの作成、ネットワークの設定、メトリクス関数の設定、メトリクス・コネクタの設定、WIFの設定、接続の作成。

プロセスを完了するには、次の情報が必要です：

* 専用コンパートメントの名前を`newrelic_compartment_DO_NOT_REMOVE`にしてください。OCIホーム・リージョンに作成してください。

* デフォルト・ドメイン下のルート・コンパートメントに動的グループを作成する際に、ルール`resource.type = 'serviceconnector'`および`resource.type = 'fnfunc'`を追加します。

* 認証用のNew Relicライセンスキーとユーザーキーを安全に保存するためのキー・ボールトを作成します。<br />

  1. **キー・ボールトを作成してください**。OCIコンソールで、**Key Management and Vault services**を見つけてアクセスし、以前に作成したコンパートメントにボールトを作成します。名前（たとえば`newrelic-vault`）を付け、セキュリティ要件に基づいて標準または仮想プライベート・ボールトを選択してください。<br />
  2. **マスター暗号化キーを作成します**。ボールトで、`AES`アルゴリズムと`256`ビットのキー長を使用して、（たとえば）`newrelic-encryption-key`という名前のマスターキーを作成します。<br />
  3. **APIキーのシークレットを作成してください**。先ほど作成したマスターキーを選択し、シークレットのコンテンツ（プレーンテキスト）としてIngestライセンスキーを貼り付けて、New RelicのIngestライセンスキー用のシークレット（たとえば`newrelic-ingest-key`という名前）を作成してください。同じ手順を繰り返して、シークレットのコンテンツ（プレーンテキスト）としてユーザーキーを貼り付け、New Relicのユーザーキー用の2つ目のシークレット（たとえば`newrelic-user-key`という名前）を作成してください。

* サーバーレスアプリケーションを作成し、OCIメトリクスを処理して転送するNew Relic関数をデプロイしてください。<br />

  1. **サーバーレスアプリケーションを作成します。**

     * OCIコンソールの<DNT>**Developer Services**</DNT>にある<DNT>**Functions**</DNT>サービスにアクセスします。

     * この設定で新しいアプリケーションを作成します：

       * **名前**：分かりやすい名前（たとえば、`NewRelicMetricsApp`）
       * **コンパートメント**：指定したNew Relicコンパートメント
       * **VCN**：New Relicインテグレーション用に作成されたVCN
       * **サブネット**: 安全な接続のためのプライベートサブネット
       * **シェイプ**：アプリケーションシェイプ用の`GENERIC_X86`

  2. **環境変数を設定する**

     * アプリケーションの設定内で、以下の設定変数を追加します：

       * `FORWARD_TO_NR`: New Relicへのデータ転送を有効にするには、`True`に設定してください
       * `LOGGING_ENABLED`: 詳細ロギングを無効にするには`False`に設定します（オプション）
       * `NR_METRIC_ENDPOINT`：New Relicエンドポイント。米国アカウントには`newrelic-metric-api`、EUアカウントには`newrelic-eu-metric-api`、JPアカウントには`newrelic-jp-metric-api`を使用します。
       * `VAULT_REGION`：キーボールトを作成した地域
       * `SECRET_OCID`：キーボールトのNew Relic取り込みシークレットのOCID
       * `TENANCY_OCID`：OCIテナンシのOCID

     * 設定変数を保存してください。

  3. **ファンクションを作成してデプロイします。**

     * アプリケーション内で、次の仕様で新しい関数を作成します：

       * **関数名**：分かりやすい名前（例：`newrelic-metrics-function`）
       * **イメージソース**: ご利用のコンテナレジストリのプライベートリポジトリにコピーするNew Relic Dockerイメージ
       * **メモリ割り当て**: 適切なメモリ（たとえば256 MB）

     * Dockerイメージの場合は、Docker HubからNew Relicイメージをプルします（`docker.io/newrelic/beyond-oci-metric-function:latest`、プラットフォーム`linux/amd64`）。次に、認証トークンを使用して、リージョンのコンテナレジストリエンドポイント（`{region}.ocir.io`）で認証します。

     * イメージにタグを付けて、関数と同じリージョンにあるネームスペース内のプライベートリポジトリにプッシュし、関数の設定で参照します。

     * 関数の作成とデプロイメントのプロセスを完了します。

     * 後でアップグレードするには、新しいイメージを再度プッシュし、それを使用するように関数を更新します。
</Collapser>

<Collapser id="terraform" title="Terraformで自動化する">
詳細なインテグレーション手順については、『[OCIクラウドインテグレーションガイド](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#oci)』を参照してください。<br />
</Collapser>
</CollapserGroup>
</Step>

<Step>
### メトリクスネームスペースの計装

接続を作成すると、New RelicのOCIページに、**Add instrumentation** \[計装の追加]コントロールを含むメトリクスビューが表示されます：

1. **Add instrumentation** \[計装を追加]をクリックしてください。デフォルトでは、**Not instrumented** \[インストゥルメントされていない]タブにフィルタリングされています。
2. コンパートメントを展開して個々のメトリクスネームスペースを表示し、モニターするものを選択してください。
3. 選択内容を確認してください。New Relicは、計装しようとしているコンパートメントとネームスペースの数の概要を表示します。次に、**Deploy to OCI** \[OCIにデプロイ]をクリックしてください。
4. OCIでのデプロイメントが完了すると、コンパートメントは**Instrumented** \[インストゥルメントされた]タブに移動し、そのデータは<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; OCI**</DNT>に表示されます。

データが表示されるまで最大30分かかる場合があります。その後も表示されない場合は、OCIコンソールでデプロイメントのステータスを確認してください。

後で追加のネームスペースを計装するには、New RelicのOCIページに戻り、これらの手順を繰り返してください。
</Step>

<Step>
### データを探す、使う

<DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; OCI**</DNT>にデータが表示され始めたら、インテグレーションが機能していることを確認し、活用してください：

1. OCIアカウントがインテグレーションリストに表示されることを確認してください。
2. メトリクスを受信していることを確認してください。
3. パフォーマンスの問題に関するプロアクティブな通知を受け取るには、主要なOCIメトリクスの[アラート条件を作成](/docs/alerts/create-alert/create-alert-condition/alert-conditions)してください。
4. [カスタムダッシュボードを作成](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)して、OCIインフラストラクチャのデータを可視化し、パフォーマンスの傾向をモニターします。

30分経過してもデータが表示されない場合は、[トラブルシューティング](/docs/infrastructure/oci/troubleshoot)をご覧ください。
</Step>
</Steps>
