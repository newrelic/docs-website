OCIインテグレーションで問題が発生している場合は、ここから開始してください。

## トラブルシューティングログ [#logs]

OCIログが表示されない、予期せず停止する、重複して表示される、またはリソース名が正しく表示されない場合は、以下のヘルスチェックから開始し、続くセクションで特定の問題を確認してください。

### 健康診断 [#logs-health-check]

これらの2つのチェックにより、問題がOCIのアップストリームにある（New Relicで確認すべきことはまだない）か、ログが実際にNew Relicに到達しているかがわかります：

1. **OCIのコネクタを確認してください。**OCIコンソールで<DNT>**Connector Hub**</DNT>に移動し、New Relicインテグレーションをデプロイしたコンパートメントを開きます。`newrelic-logs-<region>-audit`という名前のコネクタ（たとえば、`newrelic-logs-us-ashburn-1-audit`）を探し、そのステータスが<DNT>**Active**</DNT>であることを確認します。エラーステータスが表示されている場合は、コネクタを開いてエラーの詳細を確認してください。

2. **ログがNew Relicに届いていることを確認してください。**[データのクエリ](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder)でこのクエリを実行します：

   ```sql
   SELECT count(*) FROM Log WHERE oracle.loggroupid = '_Audit' SINCE 30 minutes ago
   ```

   カウントがゼロより大きい場合は、監査ログが送信されていることを意味します。別のログタイプのトラブルシューティングを行っている場合は、代わりに該当する時間枠の最近の結果が表示されることを確認してください。

両方のチェックが正常である場合、問題は完全な停止ではなく、以下の特定のシナリオのいずれかである可能性があります。

<Collapser id="duplicate-logs" title="重複するログエントリ">
複数のコネクタが同じログイベントをNew Relicに送信しています。これは通常、OCI内の複数のコネクタが同じログをカバーしていることを意味します — 多くの場合、単一のコンパートメントのみをカバーしていた古いコネクタを削除せずに、より広範な「すべてのコンパートメント」コネクタが追加されたことが原因です。

<DNT>**Connector Hub**</DNT>で、New Relicインテグレーションに関連するすべてのコネクタをリストし、それぞれがカバーする範囲を確認してください。重複するものを削除し、実際に必要な範囲をカバーするコネクタを1つだけ残してください。
</Collapser>

名前が解決されない場合は、OCIテナンシのアドミニストレーターに、動的グループに[不足している権限](#logs-permissions)にリストされている`inspect`個のポリシーがあることを確認するよう依頼してください — DNS、GoldenGate、ネットワーク・ファイアウォール、イベント・ルール、およびインテグレーション・インスタンスのリソースごとに1つずつです。権限が正しく設定されているように見え、適度な時間待っても名前が解決されない場合は、影響を受けるリソースの例とログのタイムスタンプを添えてサポートにお問い合わせください。

## その他のヘルプ [#get-help]

上記のチェックを行っても問題が解決しない場合は、以下の情報を添えてNew Relicサポートにお問い合わせください：

* 使用したセットアップ方法（ガイド付きウィザード、手動セットアップ、またはTerraform）
* OCIリージョン、および該当する場合は影響を受けるコンパートメント
* 問題が発生し始めたおおよその時間帯
* 上記のチェックのうち、すでにお試しいただいたもの
