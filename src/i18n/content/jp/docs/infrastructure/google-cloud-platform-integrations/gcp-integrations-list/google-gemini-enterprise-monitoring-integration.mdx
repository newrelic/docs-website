[<DNT>Google Cloud Platform</DNT>（<DNT>GCP</DNT> ）](https://cloud.google.com/)[ との New](/docs/infrastructure/introduction-infra-monitoring) Relicインテグレーション[<DNT>Gemini Enterprise</DNT>](https://cloud.google.com/gemini-enterprise) には、 のデータをNew Relicに報告するものが含まれます。本ドキュメントでは、<DNT>GCP Gemini Enterprise</DNT>インテグレーションを有効にする方法と、報告されるデータについて解説します。

## 特徴

<DNT>Gemini Enterprise</DNT> <DNT>Discovery Engine</DNT>上に構築された、エンタープライズ検索およびAIエージェントアプリケーションを構築および実行するための<DNT>Google Cloud</DNT>のプラットフォームです。New Relicの<DNT>Gemini Enterprise</DNT>インテグレーションは、アプリ（エンジン）、エージェント、それらのエージェントが呼び出すツール、およびデータコネクタのリクエスト、レイテンシ、セッションメトリクスを、ロケーションごとおよびユーザーごとのリソース数とクォータ消費量とともに収集します。

## 統合をアクティブ化する [#activate]

<Callout variant="important">
このインテグレーションは、<DNT>GCP</DNT> プロジェクトを <DNT>**Workload Identity Federation**</DNT> に接続する場合にのみ利用可能です。サービスアカウントまたはユーザーアカウントの接続では利用できません。
</Callout>

インテグレーションを有効にするには、標準手順に従い、<DNT>**Workload Identity Federation**</DNT>を使用して[<DNT>GCP</DNT>サービスをNew Relicに接続します](/docs/connect-google-cloud-platform-services-infrastructure)。

## ポーリング頻度 [#polling]

New Relicインテグレーションは、インテグレーションによって異なるポーリング間隔に従って、<DNT>GCP</DNT>サービスをクエリします。<DNT>Gemini Enterprise</DNT>のポーリング頻度は5分です。解像度は1分あたり1データポイントです。

## ワークロード Identity Federation [#wif]

### データを見つけて使用する [#find-data-wif]

インテグレーションを有効にすると、<DNT>Gemini Enterprise</DNT>リソースがNew Relicのentity explorer \[エンティティエクスプローラー]にエンティティとして表示されます。ダッシュボードを表示してサービスを管理するには、<DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Infrastructure &gt; GCP</DNT>に移動します。

New Relicは、<DNT>GCP Cloud Monitoring</DNT>で利用可能な<DNT>Gemini Enterprise</DNT>メトリクスを、`Metric`イベントタイプのディメンショナルメトリクスとして収集します。例：

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.discoveryengine.%' FACET metricName
```

#### ロケーションメトリクス

ロケーションメトリクスは、プロジェクトのロケーションごとの集計です。これらには、エンジン、データストア、ドキュメント、ユーザーイベントの数などのリソース数や、検索リクエスト量が含まれます。また、これらには、エージェント、画像および動画の生成、ウェブグラウンディング、検索requestsなどの領域を対象とする、140を超える<DNT>Gemini Enterprise</DNT>の割り当ての使用量、制限、および制限超過数も含まれます。

ほとんどのロケーションメトリクスはクォータメトリクスです。各クォータは最大3つのメトリクスとして報告され、`usage`、`limit`、または`exceeded`というサフィックスを追加して名前が付けられます（例：`gcp.discoveryengine.quota.search_requests_regional.usage`）。クォータ・メトリクスは、`metric.limit_name`および`metric.regional_location`ラベルを保持します。

ロケーションは、`gcp.discoveryengine.engines_regional`などの非クォータメトリクスも定義します。<DNT>Google Cloud</DNT>はすべてのプロジェクトでこれらのデータを報告するわけではなく、報告されない場合、それらはNew Relicに表示されません。同じカウントは、たとえば`gcp.discoveryengine.quota.engines_regional.usage`などのクォータメトリクスとしても報告されます。

Locationメトリクスの完全なリストについては、[Googleのクラウドモニタリングメトリクスリファレンス](https://docs.cloud.google.com/monitoring/api/metrics_gcp_d_h#gcp-discoveryengine)の`discoveryengine`セクションを参照してください。New Relicは、そこに記載されているGAおよびベータ版のメトリクスを収集します。
