[New Relicインテグレーション](/docs/infrastructure/introduction-infra-monitoring)には、[Google Cloud Platform（GCP）](https://cloud.google.com/)との[Google Cloud Service Mesh](https://cloud.google.com/service-mesh/docs)（Istio）のデータをNew Relicに報告するものがあります。本ドキュメントでは、GCP Cloud Service Meshインテグレーションを有効にする方法と、報告されるデータについて解説します。

## 特徴

クラウドサービス Meshは、Istio上に構築されたGoogle Cloudのマネージドサービスメッシュです。New Relicのクラウドサービス Meshインテグレーションは、メッシュ化されたワークロードによって発行されるIstioサービスのテレメトリーを収集します：インバウンドおよびアウトバウンドのリクエスト数、リクエストとレスポンスのサイズ、サーバーおよびクライアント側のレイテンシ分布。

このインテグレーションは、クラウドサービスメッシュに登録されているCloud Runワークロードを対象としています。GKEサイドカーワークロード（`istio_canonical_service`モニターリソース）からのIstioテレメトリーは、このインテグレーションでは収集されません。

## 統合をアクティブ化する [#activate]

<Callout variant="important">
  この統合は、GCP プロジェクトを \[Workload Identity Federation] に接続する場合にのみ利用可能です。サービスアカウントまたはユーザーアカウントの接続では利用できません。
</Callout>

インテグレーションを有効にするには、標準手順に従い、Workload Identity Federationを使用して[GCPサービスをNew Relicに接続します](/docs/connect-google-cloud-platform-services-infrastructure)。

## ポーリング頻度 [#polling]

New Relicインテグレーションは、インテグレーションによって異なるポーリング間隔に従って、GCPサービスをクエリします。Google Cloud Service Meshのポーリング頻度は5分です。解像度は1分あたり1データポイントです。

## ワークロード Identity Federation [#wif]

### データを見つけて使用する [#find-data-wif]

GCPクラウドモニタリングで利用可能なすべてのクラウドサービスMeshメトリクスは、`Metric`イベントタイプのディメンショナルメトリクスとして収集されます。

このインテグレーションは、New Relicエンティティエクスプローラーにエンティティを作成しません。たとえば、`Metric`イベントタイプで直接そのメトリクスをクエリします：

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.istio.io.%' FACET metricName
```

メトリクスは基盤となるCloud Runリビジョンのリソースラベルを保持するため、エンティティなしでサービス名、リビジョン名、ロケーションごとにファセット化できます。

上記の分布メトリクス（`request_bytes`、`response_bytes`、`response_latencies`、`roundtrip_latencies`）は、`.p50`、`.p95`、および`.p99`パーセンタイルメトリクスとしても利用できます。例：`gcp.istio.io.service.server.response_latencies.p99`。

Istioサービスのテレメトリーの詳細については、[GoogleのCloud Service Meshオブザーバビリティドキュメント](https://cloud.google.com/service-mesh/docs/observability)を参照してください。
