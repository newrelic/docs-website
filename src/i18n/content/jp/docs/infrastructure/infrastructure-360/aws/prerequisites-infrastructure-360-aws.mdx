## AWSでの自動検出の対象 [#coverage]

Auto-discoveryは、接続されている<DNT>AWS</DNT>アカウントをスキャンしてサポートされているすべてのリソースに対してNew Relicエンティティを作成し、これらのリソースが互いにどのように接続されているかを割り出して、それらの接続を関係として記録します。Auto-discoveryはエージェントを必要としません。リソースは、インストゥルメントされているかどうかにかかわらず表示されます。

自動検出はテレメトリーではなく、エンティティとリレーションシップを作成します。検出されたリソースには、エンティティ、タグ、<DNT>AWS</DNT>の設定、およびマップ上の場所が割り当てられますが、自動検出ではそのメトリクスやイベントは送信されません。チャートとアラートを取得するには、<DNT>AWS</DNT>のメトリクスを接続するか、エージェントもインストールしてください。

すでに別の方法（たとえば、EC2インスタンス上のinfrastructureエージェントや、RDSインスタンス上のCloudWatch Metric Streamsなど）でリソースをモニターしている場合、自動検出は重複を作成するのではなく、その既存のエンティティに追加します。

Auto-discoveryは66の<DNT>AWS</DNT>リソースタイプをサポートしており、65のエンティティタイプにマッピングします。

## 関係 [#relationships]

自動検出は、エンティティを作成するだけでなく、リソースがどのように接続されているかを把握し、それらの接続を関係として記録します。関係はマップに描画されるものであり、ロードバランサーからその背後にあるデータベースに至るまでの遅延したrequestをトレースできるようにするものです。

すべてのリレーションシップは、ソース、リレーションシップ・タイプ、およびターゲットで構成されます。たとえば、`VPC CONTAINS Subnet`または`S3 bucket TRIGGERS Lambda function`です。順序は重要です：接続の方向を示します。

多くの<DNT>AWS</DNT>接続には自然な方向性がないため（VPCとサブネットは単に関連付けられているだけです）、自動検出はほとんどのリレーションシップを一方向でのみ記録します。自動検出での記録方法に関係なく、マップはどちらの端からでも接続を正しく描画します。

オートディスカバリーは、ほとんどのリレーションシップをリソースの設定から直接読み取りますが、場合によっては推測します。たとえば、ターゲットグループが名前付きインスタンスではなくIPアドレスにルーティングする場合、ターゲットIPをネットワークルーティングと照合することで、ロードバランサーのターゲットグループを適切なホストに接続します。

## スキャン頻度 [#scan-frequency]

自動検出は、アカウントのメトリクスのポーリング間隔に基づいてリージョンを再スキャンします。デフォルトの頻度は24時間です。代わりに、8時間、12時間、または16時間ごとに再スキャンを実行するように設定できます。最小間隔は8時間です。8時間未満の間隔を設定した場合、自動的にデフォルトの8時間になります。
