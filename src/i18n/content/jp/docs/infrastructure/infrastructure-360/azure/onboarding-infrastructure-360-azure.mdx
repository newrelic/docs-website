## 前提条件 [#prerequisites]

<DNT>Azure</DNT>の[<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360)を有効にする前に、以下が用意されていることを確認してください：

* サブスクリプションIDを持つ<DNT>Azure</DNT>アカウント。
* 監視リーダーロールを持つ<DNT>Azure</DNT>アプリ登録。
* <DNT>Infrastructure 360</DNT>プレビューに登録されているNew Relicアカウント。
* New Relicでクラウドインテグレーションを管理するための権限。

プレビューに登録するには、<DNT>**one.newrelic.com &gt; Administration &gt; Preview &amp; Trials**</DNT>に移動して<DNT>**Infrastructure 360**</DNT>に登録してください。

<DNT>Azure</DNT>で<DNT>Infrastructure 360</DNT>を有効にする方法は3つあります：

## Azureのオンボーディング中に有効にします。 [#onboarding-enable]

初めて<DNT>Azure</DNT>をNew Relicに接続する場合は、次の手順に従ってください：

1. <DNT>**Infrastructure &gt; Azure**</DNT>に移動します。
2. アカウントを選択し、 <DNT>**Set up integration**</DNT>をクリックします。
3. プロンプトに従って、<DNT>Azure</DNT>アプリ登録を作成します。セットアップの詳細な手順については、「[<DNT>Azure</DNT>インテグレーションの接続](/docs/infrastructure/microsoft-azure-integrations/get-started/activate-azure-integrations)」を参照してください。
4. インテグレーションのセットアップ中に、プロンプトが表示されたら<DNT>**Infrastructure 360**</DNT>オプションを有効にします。
5. スキャン頻度を設定してください。デフォルトでは、<DNT>Infrastructure 360</DNT>は1日に3回スキャンします。これを変更するには、[スキャン頻度の調整](#adjust-frequency)をご覧ください。

## 既存のAzureインテグレーションで有効にする [#existing-enable]

すでに<DNT>Azure</DNT>をNew Relicと統合している場合は、次の手順に従ってください。

1. <DNT>**Infrastructure &gt; Azure**</DNT>に移動し、 <DNT>**Manage Infrastructure 360**</DNT>をクリックします。
2. アカウントリストから<DNT>Azure</DNT>サブスクリプションを見つけ、（プロバイダーアカウントレベルで）「<DNT>**Install**</DNT>」をクリックします。
3. 上記の説明に従って、スキャン頻度を設定してください。
4. <DNT>Azure</DNT>アカウントで<DNT>Infrastructure 360</DNT>を有効にするには、<DNT>**Save**</DNT>をクリックしてください。

## インフラストラクチャ360ページから有効にしてください [#landing-page-enable]

このページから<DNT>Infrastructure 360</DNT>を有効にするには：

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; Infrastructure 360**</DNT>に移動します。
2. このNew Relicアカウント配下の<DNT>Azure</DNT>（および<DNT>AWS</DNT>）プロバイダーアカウントの機能を有効にしてください。

このページが空白の場合（まだどのプロバイダーに対しても<DNT>Infrastructure 360</DNT>を有効にしていない場合）、<DNT>**Setup Infrastructure 360**</DNT>をクリックして機能を有効にしてください。

## Terraform経由で有効にする [#terraform-enable]

New Relic UIの代わりに、<DNT>Terraform</DNT>を通じて<DNT>Azure</DNT>の<DNT>Infrastructure 360</DNT>を有効にすることもできます。これは、<DNT>Terraform</DNT>を使用して<DNT>Azure</DNT>インテグレーションの自動検出を有効にするための段階的な手順です。

### 前提条件 [#terraform-prerequisites]

開始する前に、以下のものが用意されていることを確認してください。

* **<DNT>Terraform</DNT>のインストール**：ローカルマシンに<DNT>Terraform</DNT>がインストールされていること。
* **New RelicアカウントID**：お客様のNew RelicアカウントID（`newrelic_account_id`）。
* **New RelicユーザーAPIキー**：New Relic（`newrelic_api_key`）で認証するためのユーザーキーです。
* **リンクされたプロバイダーアカウントID**：New Relicによって認識される<DNT>Azure</DNT>アカウントのID（`provider_account_id`）。これは通常、New Relic UIの<DNT>**Infrastructure &gt; Azure**</DNT>にあります。
* **リージョン**: New Relicのデータリージョン（USまたはEU）。

<Steps>
<Step>
### ワークスペースの設定 [#setup-workspace]

<DNT>Terraform</DNT>の設定用にローカル・フォルダーをセットアップします：

1. ターミナルまたはコマンドプロンプトを開いてください。

2. プロジェクト用の新しいフォルダーを作成します：

   ```bash
   mkdir terraform-integrate
   cd terraform-integrate
   ```
</Step>

<Step>
### 設定ファイルを作成します。 [#create-config-files]

`terraform-integrate` フォルダー内に以下の3つのファイルを作成してください。任意のテキストエディターを使用できます。

#### providers.tf

このファイルは、どのプラグインをダウンロードするかを<DNT>Terraform</DNT>に指示します。

```hcl
terraform {
  required_providers {
    newrelic = {
      source = "newrelic/newrelic"
    }
  }
}
```

#### variables.tf

このファイルでは、スクリプトの実行に必要な入力を定義します。

```hcl
variable "provider_account_id" {
  description = "The Azure Subscription ID Equivalent in Newrelic (Linked Account ID)."
  type        = number
}

variable "new_relic_region" {
  description = "The New Relic region (e.g., 'US', 'EU', or 'JP')."
  type        = string
  default     = "US"
}

variable "newrelic_account_id" {
  description = "The New Relic account ID."
  type        = number
}

variable "newrelic_api_key" {
  description = "The New Relic API key."
  type        = string
}
```

#### main.tf

これは、自動検出機能を有効にするコア・スクリプトです。

```hcl
provider "newrelic" {
  account_id = var.newrelic_account_id
  region     = var.new_relic_region
  api_key    = var.newrelic_api_key
}

resource "newrelic_cloud_azure_integrations" "auto_discovery_integrations" {
  linked_account_id = var.provider_account_id

  # This block enables auto-discovery for the account
  auto_discovery {}
}
```
</Step>

<Step>
### Terraformを実行する [#run-terraform]

ファイルの準備が整いましたので、`terraform-integrate` フォルダー内からターミナルでこれらのコマンドを実行してください。

1. **初期化**：必要なNew Relicプロバイダー・プラグインをダウンロードします。

   ```bash
   terraform init
   ```

2. **Plan**: 設定を確認し、どのような変更が行われるかを表示します。<DNT>Terraform</DNT>は、ここでIDとキーを入力するようにプロンプトを表示します。

   ```bash
   terraform plan
   ```

   `newrelic_account_id`、`newrelic_api_key`、およびその他の変数のプロンプトが表示されたら、値を入力してください。

3. **Apply**: プランを実行し、インテグレーションを有効にします。

   ```bash
   terraform apply
   ```

   確認を求められたら、`yes`と入力してください。
</Step>
</Steps>

詳細については、[New Relic <DNT>Terraform</DNT> プロバイダードキュメンテーション](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#azure)を参照してください。

## インフラストラクチャ360を使用する [#using-infrastructure-360]

有効にすると、<DNT>Infrastructure 360</DNT>を使用して、インフラストラクチャ、APM、データベースを含むすべての<DNT>Azure</DNT>エンティティ間の関係を確認できます。

<Callout title="注記">
<DNT>Infrastructure 360</DNT> ネイティブのNew Relic APMエージェント（<DNT>Java</DNT>、<DNT>.NET</DNT>、<DNT>Python</DNT>）および<DNT>OpenTelemetry</DNT>（<DNT>.NET</DNT>）を介したエンティティの関係をサポートします。

特に<DNT>Azure Kubernetes Service</DNT>（<DNT>AKS</DNT>）クラスタの場合、アプリケーションをその<DNT>AKS</DNT>クラスタに接続するには、New Relic <DNT>Kubernetes</DNT>エージェントまたは<DNT>OpenTelemetry</DNT>が必要です。<DNT>Infrastructure 360</DNT>は単独でその接続を確立することはありませんが、一度接続が確立されると、アプリケーションから<DNT>AKS</DNT>クラスタを経由して、依存する他の<DNT>Azure</DNT>インフラストラクチャへの関係をマッピングすることで、チェーンを完成させます。
</Callout>

### 発見されたエンティティと関係を表示する [#view-entities]

検出されたエンティティとその関係を表示するには：

1. <DNT>**All entities**</DNT>に移動し、`collector.name = auto discovery`でフィルタリングします。

2. 任意の<DNT>Azure</DNT>エンティティを選択すると、以下の間の関係を示すインフラストラクチャマップが表示されます：

   * <DNT>Azure</DNT> エンティティ（仮想マシン、データベース、ストレージアカウント）。
   * APMエンティティ（アプリケーション、サービス）。
   * クロスプラットフォーム接続（APMサービスに接続された<DNT>Azure</DNT>リソース）。

### クロスサブスクリプション関係 [#cross-subscription]

検出されたリソースが別の<DNT>Azure</DNT>サブスクリプションのリソースに接続している場合、<DNT>Infrastructure 360</DNT>は自動的に関係を解決します：

* ターゲットサブスクリプションが<DNT>Infrastructure 360</DNT>とも統合されている場合、マップには実際のターゲットエンティティとその詳細が表示されます。
* ターゲット・サブスクリプションを統合またはモニターしていない場合、マップにはその代わりに不明なエンティティまたはインストゥルメントされていないエンティティが表示されます — 接続は引き続き表示されますが、エンティティの詳細は利用できません。

### 設定の変更をアラートと関連付けます [#correlate-config-changes]

<DNT>Infrastructure 360</DNT> <DNT>Azure</DNT>リソースの設定の変更を追跡するため、インフラストラクチャとアプリケーションのデータを個別に調査する代わりに、最近の変更が集計やインシデントの原因であるかどうかをすばやく判断できます。

1. <DNT>**All capabilities**</DNT>に移動して<DNT>**Azure Services**</DNT>を選択します。
2. リストから任意のエンティティを選択し、<DNT>**Configuration explorer**</DNT>をクリックして、現在の設定、タグ、およびプロパティを確認してください。
3. 設定変更タイムラインのタイムスタンプを、アラートまたはインシデントと比較してください。集計とほぼ同時期の設定変更は根本原因の強力なシグナルであり、設定変更をアラートおよびインシデントと関連付けることができます。

## インフラストラクチャ 360 の設定を管理する [#manage-settings]

### スキャン頻度の調整 [#adjust-frequency]

<DNT>Infrastructure 360</DNT>が<DNT>Azure</DNT>環境をスキャンする頻度をカスタマイズできます：

1. <DNT>**Infrastructure &gt; Azure**</DNT>に移動し、 <DNT>**Manage Infrastructure 360**</DNT>をクリックします。
2. <DNT>Azure</DNT>アカウントを見つけて、<DNT>**Edit**</DNT>をクリックします。
3. ドロップダウンメニューから希望するスキャン頻度を選択してください。
4. 変更を適用するには<DNT>**Save**</DNT>をクリックします。

<DNT>Azure</DNT>環境を頻繁に変更する場合はスキャン頻度を上げることを検討し、インフラストラクチャが安定しておりAPIコールを減らしたい場合はスキャン頻度を下げることを検討してください。

### インフラストラクチャ360を無効にする [#disable]

<Callout variant="important">
<DNT>Infrastructure 360</DNT>を無効にすると、以下にアクセスできなくなります：

* 自動的に検出されたエンティティとその設定。
* <DNT>Azure</DNT>リソースとAPMサービス間のリレーションシップマッピング。
* リアルタイムのインフラストラクチャトポロジの更新。
</Callout>

後で<DNT>Infrastructure 360</DNT>を再度有効にすると、次回のスケジュールされたスキャン時に、存在しなくなったエンティティと関係が再作成されます。

<DNT>Infrastructure 360</DNT>を無効にするには、以下の手順に従います：

1. <DNT>**Infrastructure &gt; Azure**</DNT>に移動し、 <DNT>**Manage Infrastructure 360**</DNT>をクリックします。
2. <DNT>Infrastructure 360</DNT> を無効にするアカウントを見つけてください。
3. <DNT>**Edit**</DNT>をクリックして、スキャンのトグルをオフにします。
4. <DNT>**Save**</DNT>をクリックして変更を確認します。
