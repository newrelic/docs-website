### 新機能

***コンテナデプロイメントの柔軟性の向上***

* デーモンとインストゥルメントされたアプリケーションは、同じホスト上に配置する必要がなくなり、IPv4またはIPv6 TCPソケットを介して通信できるようになりました。インストゥルメントされたアプリケーションの場合、これは`newrelic_init`関数の`daemon_socket`引数を介して設定できます。デーモンの場合、これは`--address`コマンドラインオプションを介して設定できます。
* `SIGTERM`シグナル（および/または`-f`、`--foreground`フラグで開始された場合は`SIGINT`シグナル）を介してデーモンを終了する場合、デーモンは終了する前にバッファリングされたすべてのデータをNew Relicに送信するようになりました。
* デーモンに新しい設定`--watchdog-foreground`が導入されました。これにより、デーモンのウォッチドッグプロセスがフォアグラウンドに維持されますが、`--foreground`の設定ではデーモンのワーカープロセスがフォアグラウンドに維持されます。新しい設定により、ウォッチドッグプロセスによって提供される追加の安定性を失うことなく、デーモンをブロッキング方式で使用できるようになります。
* C SDKは`newrelic_set_transaction_name`を提供するようになり、ユーザーはすでに開始されたトランザクションの名前を変更できるようになりました。

### バグ修正

* デーモンは、トランザクションデータの収集とマージに関連する重要なコードパスを同期的に処理するようになりました。これにより、競合状態によるクラッシュを防ぎます。

### アップグレードに関する注意事項

* デーモンに、`--port`のエイリアスとして機能する新しい設定`--address`が導入されました。顧客は、どちらかを使用してデーモンの場所を指定できます。両方の値が設定された場合、`--address`が優先されます。

* デーモンの起動時、バックグラウンドにフォークする前に、リスニングポートが接続を受信する準備ができるまで最大3秒間待機するようになりました。これは通常1秒未満（はるかに短い時間）で発生するため、この設定を使用するほとんどのユーザーは実際には違いに気付きません。

  デーモンが待機する時間は、`--wait-for-port`設定に期間を設定することで制御できます。ブロックを防ぐために、この期間を0にすることもできます。オプションを省略した場合、デフォルト値は`3s`です。

  フォアグラウンドモード（`--foreground`フラグ付き）で起動されたデーモンは影響を受けず、以前と同様に動作します。
