当社のSystem for Cross-domain Identity Management（SCIM）APIは、ユーザーの[ユーザータイプ](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type)の管理をサポートするようになりました。これにより、当社の新しいユーザーモデルのユーザーを持つEnterpriseの顧客は、アイデンティティプロバイダー（IdP）またはSCIMをサポートする任意のカスタムインテグレーションを介してユーザータイプを管理できるようになります。これは、（常にユーザーをフルとしてプロビジョニングするのではなく）ユーザーをベーシックまたはフルのいずれかとしてプロビジョニングする場合や、直近12か月間にユーザーあたり2回のダウングレードというNew Relicの[請求ポリシー](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#user-count)の範囲内で自動的にアップグレードおよびダウングレードする場合に特に役立ちます。

このリリースには、[SCIMチュートリアル](/docs/accounts/accounts/automated-user-management/tutorial-manage-users-groups-scim)と、APIを通じてユーザータイプを管理する顧客向けに、顧客固有のアップグレードリクエストプロセスを伝えるカスタムメッセージやURLをセルフアップグレードページに管理者が追加できる機能が含まれています。

事前構築済みの[Oktaインテグレーション](/docs/accounts/accounts/automated-user-management/okta-scimsso-application-configuration/)を使用してこれを有効にする手順を用意しています。現在、OneLoginまたはAzure ADインテグレーションの段階的な手順は用意していません。これらを使用している場合は、新しい属性[`nrUserType`](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type)を送信するようにIDプロバイダーを設定する必要があります。

詳細については、以下を参照してください。

* ユーザータイプに関する[SCIM APIの手順](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type)。
