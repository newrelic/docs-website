サイトをローカルで実行すると、大規模な変更のテストとプレビューがはるかに簡単になります。これを機能させるために行う必要があることがいくつかあります。幸いなことに、これを行う必要があるのは1回だけです。

## ターミナルとコマンドラインの使用 [#terminal]

macOSでは、ターミナルアプリを使用してシステムのコマンドラインにアクセスできます。（VS Code経由でターミナルにアクセスすることもできます）。コマンドラインは、グラフィカルユーザーインタフェースの代替手段です。

役立つ可能性のある基本的なターミナルコマンドをいくつか紹介します：

* `pwd` （print working directory）：ディレクトリパスを確認するために使用します。
* `ls` （list）：現在のディレクトリ内のファイルを表示します。
* `cd YOUR_DIRECTORY_PATH` （change directory）：別のディレクトリに移動します。
* `cd ..`: パス内の1つ上のディレクトリに移動します。

## ターミナルでVS Codeを有効にする [#code-terminal]

ターミナルから直接VS Codeでファイルを開くことができると便利です。数回しか使用しないかもしれませんが、ターミナル自体でファイルを編集しようとするよりもはるかに優れています。

1. Visual Studio Codeを開きます。
2. **Command + Shift + P**を押してコマンドパレットを開き、`install code`と入力して、**Shell command: Install &apos;code&apos; command in PATH**をクリックします。
3. ターミナルで「`code` YOUR\_FILENAME\`」と入力して、そのファイルをVS Codeで開きます。

## 1. GitHub Desktopを使用してローカルリポジトリをセットアップする [#repo-setup]

GitHub Desktopは、ブランチ、コミット、およびPRを管理するためのグラフィカルツールです。おそらく、GitおよびGitHubを操作する最も簡単な方法です。

1. GitHub Desktopをインストールします。
2. GitHubアカウントを使用してGitHub Desktopにサインインします。Macの場合は、画面の左上隅にある**GitHub Desktop**をクリックし、**Preferences**を選択します。青い**Sign In**ボタンを選択し、ブラウザウィンドウのプロンプトに従います。
3. [Docs Siteリポジトリ](https://github.com/newrelic/docs-website)に移動します。
4. 緑色の**Code**ボタンをクリックし、**Open with [GitHub Desktop](https://desktop.github.com/)**を選択します。
5. リポジトリを配置する場所を選択します。このフォルダーのデフォルトの場所は`~/Documents/github`です。
6. リポジトリ全体をローカルマシンにクローンしてください。

## 2. フルディスクアクセスを有効にする [#disk-access]

デフォルトでは、macOSはターミナルが`Documents`などの特定のシステムフォルダーにアクセスするのを防いでいるようです。ターミナル経由でファイルシステムをナビゲートしやすくするために、この設定を変更してください。

1. **システム環境設定**を開きます。
2. **Security &amp; Privacy** \[セキュリティとプライバシー]をクリックします。
3. 左側のペインで**フルディスクアクセス**が見つかるまで下にスクロールし、それを選択します。
4. 左下のロックをクリックし、コンピューターへのログインに使用するパスワードを入力してください。
5. アプリのリストで、**Terminal**（またはデフォルトのターミナルアプリケーション）の横にあるチェックボックスをオンにしてください。
6. ロックをクリックしてロックします。

## 3. Homebrewのインストール [#homebrew]

Homebrewは、他のアプリケーションをインストールするためのコマンドラインツールです。また、コマンドラインソフトウェアを最新の状態に保つための簡単な方法でもあります。

1. ターミナルを開きます。

2. このコマンドをターミナルにコピーして貼り付けます：

   ```shell
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

## 4. npm（Node.jsパッケージマネージャ）をインストールします [#npm]

`nvm`（Node.jsバージョンマネージャー）もインストールできるように、`npm`をインストールする必要があります。ターミナルで、`brew install npm`と入力します。

## 5. nvm（Node version manager）をインストールします。 [#nvm]

Node version manager（`nvm`）は、コンピューターにインストールされているNode.jsのバージョンを管理するために使用するものです。ターミナルで、`npm i -g nvm`と入力します。

## 6. シェルプロファイルにnvmを追加します [#add-nvm]

ローカルビルドに必要なコマンドを実行するには、シェルプロファイルに`nvm`へのパスを追加する必要があります。

macOSでは、シェルはコマンドラインに入力した内容を解釈するものです。デフォルトのmacOSシェルはZshです。どこからでもこれらのコマンドを実行できるように、マシン上の`nvm`があるディレクトリをシェルに伝える必要があります。

これを行うには、シェルの設定ファイルである`.zshrc`ファイルに次のテキストを追加します。

1. ターミナルで「`code ~/.zshrc`」と入力し、VS Codeでこのファイルを開きます。

2. `.zshrc`ファイルで、次のテキストをコピーして貼り付けます：

   ```shell
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
   ```

3. ファイルを保存します。

## 7. Node.jsをインストールする [#node]

`nvm`をインストールすると、正しいバージョンのNodeをインストールできます。Node、またはNode.jsは、Gatsbyサイトとその依存関係を動かすJavaScriptエンジンです。`nvm use 18`と入力して、Node.jsバージョン16をインストールします。

## 8. Yarnのインストール [#yarn]

Yarnは、**docs-website**リポジトリ内のすべてのファイルをコンパイルしてサイトをローカルでビルドするために使用される、もう1つのパッケージマネージャです。npmを使用してYarnをインストールします。ターミナルで「`npm i -g yarn`」と入力します。

## ローカルサイトのビルド [#local-site]

ターミナルでこれらをすべてインストールすると、ローカルのマシンでサイトを実行できるようになります。

1. ターミナルで「`pwd`」と入力し、**docs-website**リポジトリのディレクトリにいることを確認します。
2. 「`yarn`」と入力して、Gatsbyのすべての依存関係が最新であることを確認します。
3. 「`yarn start`」と入力して、サイトをローカルでビルドします。
4. プロセスが完了したら、Webブラウザで`http://localhost:8000`に移動します。

`yarn start`を実行すると、ターミナルに多くのテキスト行が出力されます。ローカルビルドが失敗した場合、ターミナルの出力が問題の原因の手がかりとなることがよくあります。

デフォルトでは、サイトは翻訳された（jp、kr）ページなしでビルドされます。これらのページもビルドしたい場合は、`yarn start:full`を実行できます。

## ローカルサイトの一部をビルドする（高速） [#local-site-speed]

サイトをさらにすばやくビルドしたい場合は、サイト上のすべてのドキュメントではなく、単一のフォルダー（または任意の数のフォルダー）をビルドすることを選択できます。これは、たとえばアカウントのドキュメントで作業していることがわかっている場合に便利で、アカウントフォルダーのみをビルドできます。ただし、これは、指定した以外のフォルダーにあるドキュメントにアクセスしようとすると、`404`が表示されることを意味します。

1つ以上の特定のフォルダーをビルドするには、この変数を`yarn start`コマンドに追加します：

`BUILD_FOLDERS=mlops yarn start` または `BUILD_FOLDERS=apm,logs,errors-inbox yarn start`

ヒント

* 指定するフォルダは、`/src/content/docs/`ディレクトリのルートレベルにある必要があります。これにはサブディレクトリは含まれません。たとえば、`browser`は有効なフォルダですが、`browser-monitoring`は`browser`のサブディレクトリであるため有効ではありません。
* フォルダーリスト内のカンマの後にスペースがないことを確認してください。たとえば、`BUILD_FOLDERS=apis, infrastructure`ではなく`BUILD_FOLDERS=apis,infrastructure`と入力してください。
