## インラインコードの書式設定 [#inline-code]

インラインコード（`maxSampleTimes`や`TransactionError`など）をフォーマットするには、テキストをバッククォート`` ` ``文字で囲みます。

## 複数行のコードブロック [#code-block]

1行以上のコードを書式設定するには、コードの上下に3つのバッククォート（` ``` `）を挿入します。これは基本的に、HTMLの`<pre>`タグのように機能します。

コードスニペットを3つのバッククォートで挟む場合は、コードのインデントと構文のハイライトの両方を考慮する必要があります。

### 厳密なインデント [#strict]

テクニカルライターとして、さまざまな言語のコードスニペットが提供されます。読者がコードスニペットを理解しやすくなるように、行が適切にインデントされ、グループ化されていることを確認してください。

一部のプログラミング言語やマークアップ言語では、特定のインデントが必要です（たとえば、PythonやYAMLなど）。提供されたスニペットが機能するために特定のインデントが必要かどうか不明な場合は、対象分野の専門家にご確認ください。別の編集ツールから転送する際にスニペットが乱れた場合は、いつでもオンラインのコード整形ツールでスニペットを整形できます。

インデントを変更するとエラーになるPythonコードの例を以下に示します：

```python
import newrelic.agent
newrelic.agent.initialize('newrelic.ini') #This is required!

def greet(name):
    """
    This function says hello to
    the person who is passed in as
    a parameter
    """
    print("Hello, " + name + " and the world!")


def execute_task(application, task_name):
    with newrelic.agent.BackgroundTask(application, name=task_name, group='Task'):
        greet("Robert")

application = newrelic.agent.register_application(timeout=10)
execute_task(application, "bar")
newrelic.agent.shutdown_agent(timeout=10)

```

### 厳密ではないインデント [#casual]

インデントが厳密ではないフリーフォーム言語の場合は、類似の例を探し、そのパターンに従うことをお勧めします。JavaとSQLは、フリーフォーム言語の例です。

### NRQLをフォーマットする方法 [#NRQL]

NRQLはフリーフォームのクエリ言語であるため、厳密なインデント規則はありません。読みやすくするために、いくつかの簡単なガイドラインに従うことをお勧めします。私たちの提案は、いくつかのSQLフォーマットのガイドラインに大まかに基づいています。

これらのガイドラインがスニペットに適用されるかどうかは、ご自身の判断で決定できます：

* `FROM`、`SELECT`、`FACET`、`WHERE`、`AND`、`OR`、`AS`、`SINCE`、`ORDER BY`、`TIMESERIES`、`EXTRAPOLATE`、`AUTO`などの句のキーワードは大文字にしてください。

* クエリビルダーはこれらの名前を自動的に大文字にしないため、`min()`、`max()`、`average()`、`percentile()`、`sum()`、`stddev()`などの関数を大文字にしないでください。キーワードが関数かどうかわからない場合は、[NRQLリファレンス](/docs/query-your-data/nrql-new-relic-query-language/get-started/nrql-syntax-clauses-functions/#functions)を参照してください。

* `SELECT`で開始してもクエリは正常に実行されますが、最初の行は`FROM`句で開始する必要があります。

* 以下の場合を除き、句のキーワードは左揃えにしてください：

  * 句のキーワードが前のキーワードと密接に結びついている場合（たとえば、`AGO`が`SINCE`と密接に結びついている場合）、同じ行に配置します。
  * 句のキーワードに修飾語がない（単独である）場合は、すでにキーワードがある行の末尾に追加できます（たとえば、`TIMESERIES`、`AUTO`、`EXTRAPOLATE`）。
    ```sql
    FROM Transaction
    SELECT count(*)
    WHERE appName='interestingApplication'
    SINCE 60 minutes AGO EXTRAPOLATE
    ```

* 複数行にまたがる括弧内のキーワードについては、2スペース分インデントします。たとえば、`WHERE`キーワードは次のように2スペース分インデントされます：
  ```sql
  FROM PageView
  SELECT count(*)
  FACET CASES
  (
    WHERE duration < 1,
    WHERE duration > 1 AND duration < 10,
    WHERE duration > 10
  )
  ```

## コード行の強調表示 [#highlight-code]

コードブロック内のコード行全体をハイライトするには、`lineHighlight=`を使用してハイライトする特定の行を指定できます。これは、構文を記述するのと同じ場所で行います。1番目と、3番目から5番目の行がハイライトされたコードブロックの例を次に示します：

```js lineHighlight=1,3-5
const coolThing = {
  key: 'HI',
  tada: 'hello'
}
// this is an important object
// other notes...
```

## 顧客固有の変数のプレースホルダー [#value-placeholders]

顧客や状況によって値が異なる変数のプレースホルダーを使用したい場合があります。たとえば、顧客がNew RelicアカウントIDを入力するためのプレースホルダーを示すために`YOUR_ACCOUNT_ID`を使用する必要がある場合があります。

顧客固有の値のプレースホルダーを作成する際の要件とヒント：

* 単語を区切るには、すべて大文字とアンダースコア`_`を使用します（[SCREAMING\_SNAKE\_CASE](https://github.com/rubocop-hq/ruby-style-guide#screaming-snake-case)とも呼ばれます）。
* SMEが特定の言語や状況において他の要素が必要であるという説得力のある理由を示さない限り、`<`、`>`、または`$`などの他の要素は使用しないでください。
* `YOUR`を使用して、読者に直接語りかけます。たとえば、 `ACCOUNT_ID` ではなく`YOUR_ACCOUNT_ID`を使用します。
* コンポーネントが自社のものかサードパーティのものか不明確になる可能性があると思われる場合は、プレースホルダーに`NEW_RELIC`を追加できます。たとえば、AWSをNew Relicに接続することについて記述する場合、アカウントがAWSのものではなく当社のものであることを次のように明記したい場合があります：`YOUR_NEW_RELIC_ACCOUNT_ID`。
* 変数を示すために、他の句読点と組み合わせないでください（テキストを山括弧や波括弧で囲むなど）。

### プレースホルダーを使用しない場合 [#placeholders]

プレースホルダーは主に、コードを実行する顧客のように、実行すべき手順がある場合に使用されます。手順が含まれておらず、コードスニペットが、何かがどのように見えるか、またはどのように見えるべきかを示すために使用されている場合は、プレースホルダーを使用しないでください。以下に、プレースホルダーを使用すべき**ではない**場合の例をいくつか示します：

* サンプルコードまたはファイル：設定ファイルの例など、手順に直接関係しない例を示す場合は、プレースホルダーではなくサンプルの値を使用してください。
* APIコールのレスポンス: レスポンスがどのようになるかを示すことを目的としており、手順に関連しないAPIコールのレスポンスを含める場合は、プレースホルダーを使用しないでください。

### API キー

コードブロックや設定で例としてAPIキーを参照する必要がある場合は、ゼロの代わりにアスタリスクを使用したプレースホルダーテキストを使用する必要があります。

例：

```
...
-e NEW_RELIC_API_KEY=********************************FFFFNRAL \
...
```

または

```
...
NEW_RELIC_LICENSE_KEY=****************************************
...
```
