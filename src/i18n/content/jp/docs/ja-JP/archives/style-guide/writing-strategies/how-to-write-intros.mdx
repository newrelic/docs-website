導入部分はディナーパーティーの前菜によく似ています — メインコースの舞台を整える役割を果たします。導入部分に少し手間をかければ、読者はメインコースへの準備が整います。

はじめにを作成する際は、通常、次の3つの要素を含めます：

* トピックを定義する情報
* ユーザーの関心を引くアイデア
* 読者にドキュメントの内容を伝えるティーザー

最初の2つの要素は単純に思えますが、読者に何を期待できるかを伝えるとなると、しばしば反復的でぎこちない表現に頼りがちです。この扱い方にはいくつかの疑問が生じます：誰が話しているのでしょうか？権威があるのでしょうか？協力的でしょうか？これは、ユーザーが学習し、問題を解決するのを支援するための最良の方法でしょうか？

導入部分に関する一般的なヒントをいくつか見ていきますが、ドキュメントから何が期待できるかを読者に伝える方法に焦点を当てます。背景の議論をスキップしたい場合は、定型文を避けてページの主題の核心に迫る導入部分を示す[導入例](#example-lead-ins)にジャンプできます。

## よりアクティブな導入部を作成するためのヒント [#tips]

当社のサイトには、見出しの後に`This document is about`導入文が続くページが多数あります。この文は多くの場合、見出しを言い換えたものです。さらに読み進めると、通常はより適切な導入となる段落があります。`this document is about`の使用を避け、ユーザーが探している情報に直接入ることをお勧めします。

このドキュメント全体を通して、この種の構文のさまざまな代替案を見ていきます。これらの代替案を検討する前に、より強力な導入部を書くための以下の方法を検討してください：

* すぐにユーザーに焦点を当てます。ドキュメントの内容について話し始めるのではなく、ユーザーが知りたいことや行いたいことについて話します（[5つの質問](/docs/style-guide/writing-strategies/five-questions-help-write-docs)を考慮してください）。
* どのような情報が不足しているか、または暗示されているかを自問してください：用語や概念を定義する必要があるかもしれません。たとえば、Gradleの使用に焦点を当てたドキュメントページがありますが、Gradleとは何かについては説明されていません。または、Observability for Goodページでは、最初にOfGについて言及していますが、それが何であるかは説明していません。
* ページの本当の要点を把握し、それを必ず導入部分に含めるようにしてください。その情報は通常、「このページはこれについてです」という平坦な導入文の直後に含まれています。ただし、強調されている部分を見つけるには、ページをよく見る必要がある場合があります。

読者にリーチする新しい方法を見つけるには、導入部分のいくつかのアプローチを検討してください。

## いくつか異なるアプローチを検討してください。 [#what-about]

ドキュメントの内容は何ですか？この質問への回答方法は、読者と、読者を引き付ける機会に影響を与えます。すべてのドキュメントで同じ構文を使用すると、予測しやすくなるかもしれませんが、ユーザーがそれらの文を見なくなるほど繰り返しになる可能性もあります。

決まり文句は、良い詳細情報の妨げになる傾向があり、ページタイトルですでに提供されている情報を繰り返す傾向があります。多くの場合、関連する情報を導入部分に移動することで、ページの内容をより具体的かつ興味深く読者に伝えることができます。

問題を要約し、読者の注意を引く導入部のサンプルは次のとおりです：

```
Clogged drains account for 60 percent of calls to professional plumbers. You may be able to solve this problem yourself and avoid the expense.
```

このドキュメントの残りの部分が何についてであるかを読者に伝えるために、この段落にどのような3番目の文を追加できますか？以下のセクションには、3番目で最後となる構成を説明する文のさまざまなオプションを含む表があります。

### アプローチ3：一人称を使用する [#first-person]

手順書で一人称の`we`を使用する場合、`we`は読者とともに書き手である自分自身を指します。両者が一緒に手順を進めていることになります。

<Callout variant="tip">
  これは、`we`がNew Relicを指すことができるより一般的な使用法とは異なる、`we`の使用法です。ライターと読者を一緒に指さない場合は、New Relicの代わりに`we`を使用できます。たとえば、「NerdGraphは、New Relicデータにクエリを実行して、特定の設定を実行するための**推奨**APIです（機能の詳細を確認する）。」
</Callout>

一人称は、個人的な関係が明確なチュートリアルのコンテキストで使用するのがおそらく最適です。たとえば、ブログやコースがあり、ユーザーに手順を説明している場合です。New Relicでは、このようなコンテキストになることはあまりありませんが、これが当てはまるケースもいくつかあります。

一人称が適切なコンテキストがある場合、会社がユーザーやそのデータを密かに監視しているというメッセージを一人称が送るようなケースは避けてください。たとえば、次のような一人称の使用は避けるべきです：「エージェントが古くなっているようです。更新しますか？」

## 導入セクションと「Why it matters」セクションの比較 [#why-matters]

導入部分を構成するためのさまざまなオプションを用意したら、その後の「なぜ重要なのか」セクションで導入部分を薄めないように注意してください。

よりアクティブユーザー中心の導入部を作成するには、通常「なぜ重要なのか」というタイプのセクションに配置する情報を含めることをお勧めします。そうすべきです！ユーザーには、その主題が自分にとってなぜ重要なのかをできるだけ早く知ってもらいたいと強く考えています。

「Why it matters」をセクションおよび見出しとして使用することが問題である理由は次のとおりです：

* 多くの場合、ユーザーにとって最も重要な情報を共有するのは、「Why it matters」セクションまで待つことになります。私たちの目標は、機能によって何が達成できるかをユーザーがすぐに学べるように支援することです。したがって、導入部やドキュメントの他のセクションでこのことについてすでにユーザーに伝えている場合は、その専用セクションを自由に削除してください。
* 価値は、ドキュメントの主題と結び付けられるべきです。意味のあるところには、価値に関する記述を含める必要があります。たとえば、導入部で高レベルの価値を示し、ページの主題の別の側面について議論する際に、より具体的な価値のステートメントを示すことができます。
* いずれにせよ、見出しとして「Why it matters」を使用しないでください。テンプレート通りのドキュメントのように見える、繰り返し使われるもう1つのフレーズです。この質問に対処するためのスペースを設ける場合は、ありきたりの「Why it matters」という見出しを使用するのではなく、価値に関する情報を提供する見出しを作成してください。

## リードインの例 [#example-lead-ins]

ありきたりのフレーズを避け、ページの主題の核心に迫るこれらの導入部分をご覧ください。これらは既存のコンテンツを書き直したものです。

### 例1：[適格性ガイドライン](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/eligibility-guidelines-new-relic-nonprofit-program/) [#eligibility]

```
Non-profits and New Relic

This document provides New Relic's Observability for Good program eligibility guidelines for nonprofit, charitable, and NGO organizations.

Exceptions

Many global nonprofit, charity and NGO organizations are eligible for Observability for Good if the organization has a recognized legal status in their respective country equal to 501(c)(3) status under the United States Internal Revenue Code, with certain exceptions. In addition, all organizations must be verified by TechSoup or the local TechSoup partner.
```

これを次のように書き直すことができます：

```
If your organization is a global nonprofit, charity, or NGO, it might qualify for Observability for Good, a New Relic program that provides expansive, free access to New Relic. To qualify, your organization must have a recognized legal status in your respective country equal to 501(c)(3) status under the United States Internal Revenue Code. And, it must be verified by TechSoup or the local TechSoup partner.

To get started:

  1. Check that your organization is not in one of the ineligible categories (link). 
  2. Submit a New Relic application (link).
  3. Get qualified with TechSoup (link).
```

このリビジョンには以下の変更が含まれています：

* すぐにObservability for Goodを定義します。目的が何であるかを述べることなく、ページの目的に直接入ります。
* 受動的な最初の数文を、より能動的な二人称の視点に置き換えます。「多くのグローバルな非営利団体、慈善団体、NGO組織」の代わりに、「お客様の組織がグローバルな非営利団体、慈善団体、またはNGOである場合」とします。
* 読者であり、このプログラムの潜在的な受益者である「you」に重点を置いています。
* 否定的な「例外」という表現を削除し、資格要件と申請方法に関する具体的な情報に置き換えます。

### 例2: [パスワードを変更する](https://docs.newrelic.com/docs/accounts/accounts/account-maintenance/change-passwords-user-preferences/) [#change-password]

```
This document contains information on New Relic password requirements.

Change your password

New Relic account passwords don't expire. However, users can change their own password and other personal account information anytime.
```

これを書き換える方法は次のとおりです：

```
New Relic account passwords don't expire. However, you can change your own password and other personal account information anytime. You can also request a password reset if you forget your password.
```

このリビジョンには以下の変更が含まれています：

* 「this document contains」の行と最初のH2を削除します。
* ユーザーにとって最も重要な情報から始まります：パスワードの有効期限はありません。パスワードはいつでも変更できます。
* 「ユーザー」ではなく「you」にします。
* これは短いページであり、導入部分ですぐに重要な情報に入ることができます。さらに、H2はカバーされる情報の概要を提供する必要があります。

### 例3：[Javaエージェントのインストール](/docs/apm/agents/java-agent/additional-installation/install-java-agent-using-gradle/) [#install-java-agent]

```
This document explains how to install the Java agent using Gradle. For information on manually installing the Java agent, see "Install the Java agent" and "Java agent configuration: Config file."
```

これを書き換える方法は次のとおりです：

```
Gradle is a highly flexible build automation tool that can help you install the Java agent across many instances quickly and consistently.

If you’d like to manually install the Java agent instead, see Install the Java agent and "Java agent configuration: Config file."
```

このリビジョンには以下の変更が含まれています：

* Gradleを定義します（インストールの自動化を可能にします）。
* その後、手動のアプローチに言及する場合、それは自動化ツールとは対照的になります。
* ある事柄に関連する情報のサブセットのみを扱うことを明確にする必要がある場合、たとえば、Gradleを使用したインストールの自動化の多くの方法のうちの1つだけを扱う場合、次のように言うことができます：「ここでは、Gradleを使用してインストールを自動化する最も一般的な方法を提供します。」多くはコンテキストに依存します。

### 例4：[Javaエージェントの属性](/docs/apm/agents/java-agent/attributes/java-agent-attributes/) [#agent-attributes]

```
New Relic attributes are key-value pairs containing information that determines the properties of an event or transaction. These key-value pairs can help you gain greater insight into your application and annotate the data when you query it. You can also automatically forward user information to New Relic.

Both default and custom attributes are visible in APM transaction traces, distributed traces, and error analytics; APM events and Browser events in dashboards. You can customize exactly which attributes will be sent to each of these destinations.

This document describes the Java agent attributes, details how to enable or disable attributes, and describes the rules the agent follows to determine which attributes to include or exclude for a destination.
```

これを改善するには、最初の3つの段落はそのままにして、最後の段落に次を追加します：

```
Before you start creating custom attributes, familiarize yourself with existing Java agent attributes and how to enable or disable them. In addition, learn the rules for which attributes the agent includes or excludes for a destination. 
```
