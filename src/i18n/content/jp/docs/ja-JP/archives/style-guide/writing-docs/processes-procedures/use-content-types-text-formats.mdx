このスタイルガイドのページでは、ドキュメントの標準的なフロントマターについて説明し、サイトで維持しているさまざまな種類のコンテンツの概要も説明します。

## ドキュメントのフロントマターとメタデータ [#meta-fields]

すべてのドキュメントの先頭は、一連のメタデータで始まります。このメタデータコンテンツの詳細については、以下をお読みください：

<table>
  <thead>
    <tr>
      <th width={150}>
        **メタコンテンツフィールド**
      </th>

      <th>
        **説明**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        `title`
      </td>

      <td>
        ドキュメントのプライマリタイトルです。ドキュメントの上部に`<h1>`HTMLヘッダーとして、ブラウザのページタイトルに、および検索エンジンのメタフィールドに表示されます。

        可能な限り、アクション指向またはタスク指向のタイトルを提供してください；たとえば、「AJAXページ：時間のかかる呼び出しを特定する」などです。一般的に、センテンスケースを使用します。最初の単語のみを大文字にします。特定の製品名などの固有名詞である場合、またはコロン`:`の後に続く場合を除き、タイトルの他の単語を大文字にしないでください。

        タイトルの選び方についてアイデアを探している場合は、類似するドキュメントのタイトルを参照してください。

        サイドバー(左側のナビゲーションペイン)で使用されるタイトルは、[ナビゲーションファイル](/docs/style-guide/processes-procedures/update-left-navigation-pane)で設定されます。
      </td>
    </tr>

    <tr>
      <td>
        `tags`
      </td>

      <td>
        非推奨。歴史的に、タグは検索エンジンやAIが適切なコンテンツを見つけるのを助けるために使用されていました。最新のエンジンはタグなしでそのコンテキストを推測できるほど洗練されているため、このタグはもはや必要ありません。
      </td>
    </tr>

    <tr>
      <td>
        `translate`
      </td>

      <td>
        このページがどの言語に人力翻訳されているかを示します。このフィールドは機械翻訳を管理するものではありません；一般的に言って、サイト上のすべての「標準」ドキュメントはすべての言語に機械翻訳されます。詳細については、[文書の翻訳](/docs/style-guide/writing-docs/docs-translation/)をご覧ください。
      </td>
    </tr>

    <tr>
      <td>
        `metaDescription`
      </td>

      <td>
        ドキュメントの簡単な説明です。検索エンジンは、ドキュメントの内容を理解するためにこのフィールドを利用しており、検索結果にメタディスクリプションを直接表示することがよくあります。160文字未満にしてください。メタディスクリプションが検索において重要である理由の詳細については、Googleのドキュメントの「[検索結果のスニペットを管理する](https://developers.google.com/search/docs/appearance/snippet)」をご覧ください。
      </td>
    </tr>

    <tr>
      <td>
        `redirects`
      </td>

      <td>
        古いURLからこのドキュメント**へ**リダイレクトします。1行につき1つのリダイレクトです。相対パスを使用し、末尾のスラッシュ`/`を含めないでください。
      </td>
    </tr>

    <tr>
      <td>
        `freshnessValidatedDate`
      </td>

      <td>
        ライターがこのドキュメントに重要な更新を行い、その正確性を検証した最後の日時。

        デフォルトは`never`です。ドキュメントに大幅な更新を加える場合は、今日の日付を次の形式で追加してください：`YYYY-MM-DD`。
      </td>
    </tr>
  </tbody>
</table>

## ページテンプレート

ドキュメントサイトには厳密なページテンプレートはありません—「docs as code」アプローチを採用しているため、ライターはさまざまなコンポーネントを使用して、最適だと考える方法でドキュメントを構成できます。ただし、標準の`.mdx`ドキュメントとは異なる動作をする、いくつかの固有のコンテンツタイプがあります。

<table>
  <thead>
    <tr>
      <th width={150}>
        **コンテンツタイプ**
      </th>

      <th>
        **説明**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        &quot;Standard&quot;ドキュメント
      </td>

      <td>
        `/src/content/docs/`サブディレクトリにある標準の`.mdx`ファイル。このコンテンツタイプは、サイト上の大部分のコンテンツに使用されます。
      </td>
    </tr>

    <tr>
      <td>
        属性の定義
      </td>

      <td>
        この形式は、属性とイベントタイプを定義するためのものです。これらの定義は独自のGitHub Enterpriseリポジトリにあり、データディクショナリサービスを介してドキュメントサイトとNerdGraphに公開されます。詳細については、[属性定義コンテンツタイプの操作](/docs/style-guide/article-templates/attribute-definition-template)を参照してください。
      </td>
    </tr>

    <tr>
      <td>
        分岐インストールドキュメント
      </td>

      <td>
        この形式は、インタラクティブなインストレーションドキュメント用です。分岐するインストールドキュメントは、サブディレクトリに共存する個別の`.mdx`ファイル内の複数のコンポーネントで構成され、どの部分をいつ表示するかを定義するロジックは別の`.yaml`ファイルで定義されます。分岐するインストールコンテンツは、`/src/install/`サブディレクトリにあります。

        詳細については、[分岐インストールコンポーネントの開始](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc/)を参照してください。
      </td>
    </tr>

    <tr>
      <td>
        リリースノート
      </td>

      <td>
        このフォーマットには、独自のフロントマターフィールドが含まれています。リリースノートは`/src/content/docs/release-notes/`にあり、通常はライターではなく製品チームによって作成されます。

        ユーザーは、特にエージェントのようなダウンロード可能なソフトウェアにおいて、製品の小さな変更を把握するためにリリースノートを頼りにしています。詳細については、[リリースノートの作成](/docs/style-guide/article-templates/create-release-notes/)を参照してください。
      </td>
    </tr>

    <tr>
      <td>
        新機能の投稿
      </td>

      <td>
        このフォーマットには、独自のフロントマターフィールドが含まれています。What&apos;s Newの投稿は、より大きな発表のためにPMMによって作成されます。ほとんどのコンテンツとは異なり、これらは`/docs/`サブディレクトリではなく`/src/content/whats-new/`に配置されます。

        これらはドキュメントサイトで利用できますが、New Relic UIでも表示されます。詳細については、[What&apos;s Newスタイルガイドライン](/docs/style-guide/article-templates/whats-new-style-guidelines/)をご覧ください。
      </td>
    </tr>
  </tbody>
</table>
