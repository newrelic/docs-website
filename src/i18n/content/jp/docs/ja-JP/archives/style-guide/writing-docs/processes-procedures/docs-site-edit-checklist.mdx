新しいドキュメントを作成する際には、把握しておくべきことがたくさんあります。このチェックリストを使用して、すべて完了していることを確認できます。

## タイトル

以下を確認します：

* ドキュメントのタイトルは、その内容を効果的に説明しています。
* 手順書のタイトルには能動動詞を使用します；たとえば、`Installing`ではなく`Install`です。

## 概要 [#intro]

以下を確認します：

* 導入部では結果を先に示し、そこに到達する方法の概要を説明するため、顧客は適切なドキュメントを見つけたと確信できます。
* ドキュメントの内容に関する短く読みやすい概要を提供します。

## 見出し（H2） [#headings]

以下を確認します：

* 見出し名は簡潔でありながら、読者が目的のセクションを拾い読みしたり、スキップしたりするのに役立つ情報を提供します。
* 手順を示すH2では、`ing`の動詞形ではなく、能動態の動詞を使用します。

## テキスト

テキストが以下のようになっていることを確認します：

* 翻訳を容易にするための最適化：慣用句、スラング、特定の文化への言及などは避けてください。
* 優れたストーリーを伝えます：プラットフォーム（他のNew Relic製品、アラートなど）をプロモートします。例やユースケースを含め、ペルソナを特定し、それが何であるか、またはどのように使用するかだけでなく、なぜそれが重要であるかを説明します。
* [UIパスのハイパーリンク](/docs/style-guide/quick-reference/usage-dictionary#ui-path)が含まれます。
* タイプミスはありません。

## 手順

手順では能動態を使用し、ステップ（「これを行う」）に焦点を当てます。ヒントや追加の詳細をステップの中に埋め込まないでください。

* 手順に前提条件や背景情報が含まれる場合、その情報は手順の順序付きリストの中（埋もれた状態）ではなく、前に記載されます。
* 手順やステップが分岐する場合は、箇条書きや折りたたみ要素などとして明確に表示されるようにオプションを分割します。
* 手順にやってはいけないことが記載されている場合は、代わりにやるべきことも記載されています。

**例：やってはいけないことと、その代わりにやるべきこと**

パートナーシップ所有者のアカウントから自身のアプリケーションをモニターしないでください。代わりに、パートナーシップ内にアカウントを作成し、そのアカウントからアプリをモニターします。

## 構造

元のテクニカルライターまたはドキュメントサイトの貢献者が、下書きのドキュメントが完全であるかどうかを判断するのに最適な人物です。ただし、ピアエディットでは、ドキュメントやその相互参照で対処されていない未解決の質問がある場合は、メモを残してください。
