このページは、ダウンロード可能なソフトウェアのリリースノート用です。製品の発表については、[What&apos;s new style guidelines](/docs/style-guide/article-templates/whats-new-style-guidelines/)をご覧ください。

## 新しいリリースノート [#new-note]

ドキュメントサイトにリリースノートを追加するには：

1. エージェントの最新のリリースノートを見つけて、同じフォルダーにコピーを作成します。
2. コピーの名前を変更する際は、ファイル名に`-`セパレータを使用して、バージョンの名前付けの競合を回避してください。例：`agent-123`の代わりに、バージョン1.2.3には`agent-1-2-3`を使用し、バージョン12.3には`agent-12-3`を使用します。
3. `subject`、`releaseDate`、`version`を入力してください。該当する場合は、`downloadLink`フィールドを含めてください。大文字と小文字の違いにより左側のナビゲーションのグループ化で問題が発生する可能性があるため、`subject`フィールドが更新中のシリーズの他のリリースノートと一致していることを確認してください。
4. `New features`、`Improvements`、および`Bug fixes`の標準見出しを使用して、これらのセクションに十分な概要情報を追加し、[優れたリリースノートを作成](/docs/style-guide/article-templates/create-release-notes/#guidelines)してください。詳細を学習できるドキュメントやその他のリソースにリンクしてください。
5. 変更をコミットし、プルリクエストを送信します。リリースが日付に依存する場合は、PRにメモを残してください。

Tech Docsのヒーローがリリースノートのコンテンツをレビューし、PRを承認して公開します。チームの他のメンバーにPRのレビューをリクエストすることもできます。

ドキュメントサイトのビルドとリリースは1日に数回行われますが、ビルドの完了に数時間かかる場合があります。リリースに時間的な制約がある場合は、ドキュメントを公開するための十分な時間を確保してください。

## 優れたリリースノートとはどのようなものですか？ [#guidelines]

優れたリリースノートは、ユーザーが重要なアップデートにすぐに慣れ、その重要性を理解するのに役立ちます。優れたリリースノートは、サポートチームやセキュリティチームにも役立ちます。

ユーザーに最新リリースを維持するよう促すことで、古いバージョンの問題を解決するためのサポート時間が短縮されます。また、最新バージョンで潜在的な脆弱性が解決されている場合、リスクを軽減します。

優れたリリースノートを作成するには、できるだけ具体的に記述してください。例を以下に示します。

* 新しい機能について簡単に説明します。それが提供する価値の例を示し、より詳細な情報へのリンクを提供します。
* 「さまざまなバグ修正」などの曖昧な表現は使用しないでください。代わりに、何が改善されたかを明確に記載し、読者が経験した問題が解決されたかどうかを把握できるようにしてください。

## 新しいリリースノートカテゴリ [#new-category]

この情報は、主にTech Docsチームが使用するためのものです。

新しいリリースノートのカテゴリを追加するには、ドキュメントサイトの次の領域を更新します。（`nav/templates`フォルダー内の`releaseNote.js`または`releaseNoteLandingPage.js`ファイルを更新する必要はありません。）GitHubのドキュメントサイトにプルリクエストを送信する前に、ランディングページとプレースホルダーのリリースノートがローカルホストで正しくビルドされることを確認してください。

### カテゴリーのランディングページ

`/src/content/docs/release-notes`に、次を追加します。

* 新しいリリースノートカテゴリ用のフォルダー。このページにリストされているリリースノートのRSSフィードリンク、ページ形式、および日付順は自動的に生成されます。たとえば、[Goカテゴリのランディングページ形式](/docs/release-notes/agent-release-notes/go-release-notes/)をご覧ください。
* `subject`を含む新しいフォルダー内の`index.mdx`ファイル。`subject`は、[リリースノートのランディングページ](/docs/release-notes/)に表示される名前です。
* エージェントチームが記入するための、このフォルダー内の[プレースホルダーリリースノート](/docs/style-guide/article-templates/create-release-notes/#new-note)。使用する場合、リリースノートの`downloadLink`フィールドは、公開されるリリースノートで自動的にフォーマットされます。

新しいカテゴリが公開される前に、チームのプロダクトマーケティングマネジメント（PMM）担当者に、今後の[What&apos;s new post](/docs/style-guide/article-templates/whats-new-style-guidelines/)にリンクを含めるかどうかを確認してください。

### ランディングページ

`/src/content/docs/release-notes/index.mdx`で、リリースノートカテゴリの新しいタイルセクションをアルファベット順に追加します。

例：

```jsx
<TechTile
  name="Logs"
  icon="logo-newrelic"
  to="/docs/release-notes/logs-release-notes"
/>
```

ロゴは`@newrelic/gatsby-theme-newrelic/icons/logo/`から取得されます。新しいエージェントのロゴがまだ存在しない場合は、標準の`logo-newrelic`アイコンまたは`@newrelic/gatsby-theme-newrelic/icons/feathers.js`の画像を使用してください。他のオプションが必要な場合は、チームのデザイナーに相談してください。

### 他のカテゴリからのリンク

エージェントのドキュメント（通常はその`Get started`カテゴリ）に、新しいリリースノートのカテゴリへのリンクを追加します。詳細については、[複数のメニューのドキュメント](/docs/style-guide/processes-procedures/include-a-doc-in-multiple-menus/)に関するドキュメントを参照してください。

オプション：タクソノミーの`index.mdx`ファイルを更新して、エージェントのランディングページのテキストにリンクを追加します。
