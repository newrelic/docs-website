---
title: プレビュードキュメントサイトのコンテンツの作成
translationType: machine
---

プレビュー版ドキュメントサイトは、顧客と共有する今後の機能に関するドキュメントをホストします。公開ドキュメントサイトとは異なり、プレビュー版ドキュメントサイトは一般に編集可能ではなく、検索エンジンの結果にも表示されません。サイトがインデックス化されていないため、ユーザーはあるプレビュードキュメントから別のプレビュードキュメントに移動することはできません。

プレビュードキュメントサイトは公開ドキュメントサイトとは異なるリポジトリにあるため、コントリビュートの方法が少し異なります。このドキュメントを最後まで読むと、プレビューサイト用の新しいドキュメントを作成できるようになります。

## ローカル環境のセットアップ [#do-first]

以前にコンピューターにbeta-docs-siteリポジトリをクローンしたことがある場合は、ステップ3に進んでください。

1. [`beta-docs-site repo`](https://github.com/newrelic/beta-docs-site)に移動します。アクセスできない場合は、#doc-eng-helpのSlackチャンネルにお問い合わせください。
2. コンピューターにbeta-docs-siteリポジトリをクローンしてください。
3. Github Desktopで正しいリポジトリで作業していることを確認してください。
4. `main`ブランチからブランチを作成します。

## 新しいプレビュードキュメントの作成 [#create-docs]

公開ドキュメントサイトとプレビュー版ドキュメントサイトの違いにもかかわらず、コンテンツの書式と構文はほぼ同じです。作業ブランチに入ったら：

1. テキストエディターを使用して、新しい`.mdx`ファイルを作成するか、フロントマターテンプレート用の既存のプレビュードキュメントをコピーします。
2. `/src/content/docs/`にファイルを保存します。
3. ドキュメント化しているプレビュー機能へのサインアップやアクセス要求に関する情報を含めるようにして、コンテンツを記述します。
4. 変更をコミットし、プルリクエストを作成します。
5. プレビューリンクをレビュー担当者と共有し、フィードバックを反映してください。
6. 最終的なPRをマージします。
7. `https://docs-preview.newrelic.com/docs/`の後にファイルパス名を貼り付けて、公式リンクを作成します（例：`https://docs-preview.newrelic.com/docs/new-feature-name`）
8. レビュアーに、顧客と共有するための公式リンクを提供してください。

## オプションの定型文 [#boiler-plate]

プレビュー用のドキュメントを作成するときは、ドキュメントの上部に定型文を含む[コールアウト](/docs/style-guide/formatting/callouts/)を含めることができます。このテキストは、読者をガイドし、機能の可用性と関連する連絡先情報に関する重要な情報を提供するために使用できます。

たとえば、プレビュードキュメントの定型文は次のようになります：

<Callout variant="caution" title="プレビュー">
  この機能は202X年1月1日にリリースされ、プレビュー版として提供されています。アクセスするには、アカウントマネージャーにお問い合わせください。
</Callout>

情報が長すぎる場合、ページの他の場所に含まれている場合、またはドキュメントに関連しない場合は、定型文を除外することをお勧めします。

## 内部コントリビューター向けの追加ガイダンス [#internal-contributors]

プレビュードキュメントを編集しようとする内部コントリビューターは、beta-docs-siteリポジトリへのアクセス権が必要です。アクセス権がない場合は、Slackの#doc-eng-helpチャンネルに、コントリビューターとして追加するよう依頼してください。アクセス権を取得したら、`main`ブランチから独自のブランチを作成し、そこで編集を行ってください。
