はじめに: このセクションでは、エージェントとAPIの概要を説明します。ユーザーがAPIを必要とする場合や、APIを使用する代わりの方法（たとえば、XMLファイルによる計装など）について説明します。フレームワークに“out of the box”のサポートがある場合、APIは不要であることが多い点に言及します。オンサイトかオフサイトかを問わず、APIリファレンスのルートにリンクします。最新のエージェントバージョンを使用する必要があることをユーザーに警告します。

## コードの欠落しているセクションをトランザクションで計測する [#creating-transactions]

アプリを計装するために、New Relicはコード内の各パスを独自のトランザクションに分離します。New Relicは、これらのトランザクションの親メソッドの時間を計測（または「計装」）してアプリの総合的なパフォーマンスを測定し、追加の詳細情報を得るために長期間実行されているトランザクションからトランザクショントレースを収集します。トランザクションの詳細については、[トランザクション](/docs/accounts-partnerships/education/getting-started-new-relic/glossary#transaction)および[トランザクショントレース](/docs/apm/transactions/transaction-traces/introduction-transaction-traces)を参照してください。

New Relicがコードの特定の部分をまったくインストルメントしていない場合は、次のメソッドを使用します。

## セグメントを使用した時間固有の方法 [#segments]

New Relic UIにトランザクションがすでに表示されているが、そのトランザクション中に呼び出された特定のメソッドに関するデータが十分ではない場合は、これらの各メソッドをより詳細に時間計測するセグメントを作成できます。たとえば、複雑なロジックの特に重要なメソッドの時間を計測する必要があることがあります。

## トランザクションのメタデータを強化する [#metadata]

## エラーを収集または無視する [#errors]

通常、エージェントはエラーを自動的に検出します。ただし、エージェントを使用してエラーに手動でマーク付けできます。エラーを[無視または想定済み](/docs/apm/applications-menu/error-analytics/ignoring-errors-new-relic-apm)としてマークすることもできます。
