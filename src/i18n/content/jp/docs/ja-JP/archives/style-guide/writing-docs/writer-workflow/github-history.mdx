GitHubのバージョン管理機能により、ドキュメントの完全な履歴の表示、任意の時点でのドキュメントへのアクセス、手動バックアップなしでの削除されたドキュメントの検索が可能になります。

## ドキュメントまたはファイルの編集履歴を確認します。 [#doc-history]

ファイルの履歴を確認または&quot;diff&quot;するには、これらのオプションのいずれかを使用します。

**オプション1：GitHubの履歴タブ**

1. ドキュメントサイトでドキュメントに移動し、右側のナビゲーションで**Edit page**をクリックします。
2. ドキュメントの右上隅にある**History**をクリックします。

**オプション2：githistory.xy**

1. GitHub.comの特定のファイルに移動します：

   ```
   https://github.com/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

2. URLでは、`github.com`を`github.githistory.xyz`に置き換えます：

   ```
   https://github.githistory.xyz/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

3. その特定のファイルの視覚的な履歴を表示するサイトに移動します。ページ上部のコミット履歴をクリックして、変更を表示できます。

**オプション3：Git blame**

[GitHubのドキュメント](https://docs.github.com/en/github/managing-files-in-a-repository/managing-files-on-github/tracking-changes-in-a-file)に従ってください。

または、ターミナルで以下のコマンドを使用できます：

```bash
git log --follow "**/file_name_here.mdx"
```

これにより、そのファイルのコミット履歴が出力されます。デフォルトでは、最初の数回のコミットのみが表示されます。`Return`を複数回押すことでスクロールできます。

たとえば、`vmware-vsphere-monitoring-integration.mdx`のコミット履歴を検索するには、次を実行します：

```bash
git log --follow "**/vmware-vsphere-monitoring-integration.mdx"
```

## 2021年10月以前のドキュメントサイトの履歴 [#archived-version]

2021年10月に大規模なサイトの再構築が行われ、ドキュメントのファイル履歴の大部分が失われました。再構築前のサイトのアーカイブバージョンは、[pre-IA-2021](https://github.com/newrelic/docs-website/tree/pre-IA-2021)ブランチにあります。再構築前のバージョンのリポジトリを移動することで、ファイル履歴などを見つけることができます。

## 削除されたファイルの検索方法 [#deleted-files]

削除されたファイルを検索する方法は複数あります。これらは、複雑さの順に大まかに並べられています：

<CollapserGroup>
  <Collapser className="freq-link" id="pr" title="削除PRの検索">
    削除されたファイルを見つける最も簡単な方法は、それを削除したプルリクエストを見つけることです。これを実現するには複数の方法があります；以下にいくつかのアイデアを示します：

    1. GitHubの検索機能を使用して、関連するキーワードを検索してください。検索結果をフィルタリングして、PRのみを含めることができます。
    2. ドキュメントが削除された時期の概略がわかっている場合は、プルリクエストタブでプルリクエストを検索してみてください。このリストには何千ものプルリクエストがあるため、時間がかかる場合があります。
    3. 多くのドキュメントはJiraチケットが原因で削除されます。Jiraでチケットを検索すると、ドキュメントが削除されたおおよその時間と、うまくいけばPR自体へのリンクが見つかります。
    4. \#doc\_talkで質問してください！
  </Collapser>

  <Collapser className="freq-link" id="releases" title="リリースPRを検索">
    リリースPRを検索することで、ドキュメントが削除される前に作成されたブランチを最終的に見つけることができます。リリースPRのリストは、[GitHubのPRタブ](https://github.com/newrelic/docs-we.bsite/pulls?q=is%3Apr+release+is%3Aclosed)にあります。

    いくつかのヒント：

    * まず、1か月の間隔で検索します。ドキュメントを含むブランチを見つけたら、範囲を1週間、次に1日に絞り込むことができます。範囲を狭めることで、最終的に、削除される前の正確な状態の削除されたドキュメントを見つけることができます。
    * PRの元のブランチにアクセスするには、そのプルリクエストのページに移動し、タイトルとPR番号の下にあるブランチ名をクリックします。
  </Collapser>

  <Collapser className="freq-link" id="git-log" title="git logの使用">
    削除されたファイルを見つけるための最も強力で信頼性の高い方法は、`git log`を使用することです。詳細については、[StackOverflow](https://stackoverflow.com/questions/7203515/how-to-find-a-deleted-file-in-the-project-commit-history/7203551#7203551)を参照してください。
  </Collapser>
</CollapserGroup>
