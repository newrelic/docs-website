これは、分岐インストールコンポーネントを構成するコンポーネントのリファレンスです。

分岐インストールの開始については、[分岐インストールの開始](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc)をご覧ください。

分岐インストールのドキュメントは、さまざまなオプション間の関係をマッピングする設定YAMLファイルによって制御されます。YAMLは、コンテンツの一部（.mdxファイルに配置されている）がいつ、どのようにドキュメントに配置されるかの概要を示します。ユーザーがオプションを選択すると、YAMLはそれらのスニペットを入れ替えます。

## コンポーネント [#new-components]

分岐インストールコンポーネントの動作を確認するには、[分岐インストールの実装](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#uses)をご覧ください。主な構成要素は次のとおりです：

* ユーザーの選択によって表示されるコンテンツが決まるオプション選択ボックス（「タイル ドロップダウン」と呼ばれることもあります）
* 番号付きの手順
* ユーザーが値を入力できる組み込み設定ファイルのオプション
* インストレーションのフィードバックフォーム（`<InstallFeedback />`）

## 使い方 [#how]

インストールドキュメントは`install`ディレクトリにあります。特定のコンテンツをドキュメントにスワップインおよびスワップアウトする方法とタイミングを定義する単一の`.yaml`ファイルがあります。コンテンツの特定の部分は`.mdx`ファイルとして表されます。

## ディレクトリの概要 [#install-directory]

インストールフレームワークのコンテンツは`src/install`にあります。

新しいインストールドキュメントを作成するには、`install`にディレクトリを追加します。

ディレクトリ構造は次のようになっている必要があります：

```
install
|--assets (used for install images)
|--config (used for the install yaml files)
   |--agent-config (used for the agent config yml files)
|--specific-install (used for a specific install doc)
   |--sub-directory1 (used for .mdx files that will be swapped in)
   |--sub-directory2 (used for .mdx files that will be swapped in)
   |--sub-directoryx (you can have as many sub-directories as you need)
```

新しいブランチドキュメントを開始するときは、`install`ディレクトリの下に親ディレクトリを作成します。ここに、ブランチドキュメントのすべてのファイルが配置されます。

## 分岐YAMLファイル [#yaml-overview]

分岐ドキュメントのYAMLファイルは、さまざまなカスタムのインタラクティブなコンテンツを生成するための高度にカスタマイズ可能な方法です。YAMLファイルであるため、インデントに注意を払い、YAMLファイルのすべての部分が正しいことを確認することが非常に重要です。

YAMLファイルでMDXコンテンツを入れ替える場合、特定のMDXファイルはインストールドキュメントディレクトリ（Javaなど）に対してローカルである必要があります。再利用の目的でドキュメントサイト上の任意の場所にあるコンテンツにリンクしたくなるかもしれませんが、これを行うとドキュメントが破損する原因になります。

### YAMLスクリプトの検証 [#verify-yaml]

YAMLファイルは非常に壊れやすいため、エンジニアリングチームは、YAMLファイルで発生する可能性のある一般的な問題をチェックするための便利なスクリプトを作成しました。

ターミナルで`docs-website`リポジトリディレクトリに移動し、次のコマンドを実行します：

`yarn verify-install-page YOUR_BRANCHING_DOC_DIRECTORY_NAME`

たとえば、Javaのブランチに関するドキュメントの場合は、次を使用します：

`yarn verify-install-page java`

Javaの分岐ドキュメントは`src/install/java`にあるためです。

このスクリプトは、YAMLファイル内の次の項目を確認します：

* `agentName`の値は、`src/install/YOUR_DIRECTORY_NAME`のフォルダー名と一致します。
* `agentName`、`agentType`、`title`、および`appInfo`フィールドは空白ではありません。
* `appInfo``placeholder`フィールドは空白ではありません。
* ステップとオーバーライドのファイルパスは有効なパスであり、実際のファイルを指しています。
* すべての`overrides`には`selectedOptions`の値があります。
* 余分な引用符や無効なインデントなど、一般的なYAML構文の問題。

## YAMLフィールド名の詳細 [#yaml-fields]

* agentName: すべてが配置されているディレクトリ名であり、URL（/install/java）にも関連付けられています

* title: ドキュメントの名前（他の.mdxと同じファイル）。

* introFilePath: ドキュメントの紹介コンテンツを含むファイル。

* agentConfigFilePath: （オプション、構成ファイルを使用する場合）エージェント構成ファイルが存在する場所。機能しない場合は、サポートされているファイルタイプかどうかをエンジニアに確認してください。

* appInfo: オプションが定義されているセクション。コンポーネント：

  * optionType: オプションのセットに付ける名前。この名前は、参照しているオプションを指示するために`steps`セクションで参照されるほか、関連する.mdxファイルでも参照されます。
  * label: オプションボックスの上に表示される、ドロップダウンの名前。不要な場合は、空の引用符を使用して空白のままにすることができます。
  * プレースホルダー: オプションボックスの上に配置できる追加のテキスト。不要な場合は、空の引用符を使用して空白のままにすることができます。

* オプション

  * value：タイルの名前の変数。これは、表示されるファイルを制御する値を指定するときに、`steps`セクションで参照されます。
  * displayName：オプションタイルの表示ラベル。
  * logo: オプション。オプションタイルに使用される画像へのパス。
  * icon: オプションです。画像の代わりにアイコンを使用する場合にこれを使用します（icon name=&quot;fe-server”）。
  * recommendedGuided：ブール値。これにより、`appInfoConfigOption`コンポーネントタイプの.mdxファイル内のコンテンツを表示するかどうかが決定されます。これは主にガイド付きインストールコンテンツに使用されますが、そのファイルで表示をトリガーしたい任意のコンテンツに使用できます。[ガイド付きインストールオプションの詳細をご覧ください](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#guided-install-decision)。

* steps: これは表示されるコンテンツを決定するセクションです。これらがリストされている順序によって、すべてのコンテンツの順序が決定されます。

  * filePath: これは.mdxファイル（または、トリガーされるかどうかに応じた理論上のパス）へのパスです。

  * overrides：オーバーライドには3つのタイプがあります。

    * **置換**。オーバーライドの下に別の`filePath`がリストされている場合、それは次のことを意味します：選択されたオプションに応じて、メインのファイルパスをこのファイルパスに置換すること。
    * **次の場合に表示...**これは`isConditionalStep`を使用し、ブール値を取ります。これは&quot;override&quot;ではなく、選択したオプションに応じてこのファイルを表示することを意味します。より複雑なAND/ORロジックの使用に関する情報については、[Example .NET yaml](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example)をご覧ください。
    * **スキップします。**これは`skip`を使用し、ブール値を受け取ります。これは基本的に次のことを意味します：このファイルを表示しますが、これらのオプションが選択されている場合はスキップします。

  * selectedOptions：関連するオプションの選択を配置するセクションです。コンポーネントとしては、次のものがあります：

    * optionType: これは`appInfo`セクションで使用される`optionType`に接続します。
    * オプション
      * value: `optionType`で使用される`value`に接続します。

## MDXファイルのブランチ作成 [#mdx-overview]

このインストールフレームワークを使用する際には、注意すべき特定のMDXファイルがあります。さまざまなMDXコンテンツタイプは、`componentType`frontmatterフィールドで指定されます。

さまざまな.mdxコンポーネントのタイプは、以下のとおりです。

* `intro`

  * YAMLでは`introFilePath`によって参照されます。
  * これはドキュメントの先頭にある導入コンテンツです。

* `default`

  * フリーフォームのMDXファイル。
  * ほとんどのコンテンツには、これを使用してください。

* `appInfoConfigOption`
  * これは、オプションのコンテンツを参照するために使用されます。

* `agentConfig`
  * これは、エージェントの設定ファイルに使用されます。

使用中のMDXファイルの例については、[Example yaml file](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example)をご覧ください。

### agentConfig MDXファイル [#sample-agentconfig]

オプションの`agentConfig`MDXファイルは、インストールディレクトリ内の適切な設定ファイルを指し、設定ファイルのどの行を編集可能にするかを制御します。

```md
---
componentType: agentConfig
headingText: Set your app name and license key
descriptionText: Set your app name and license key. Then download your custom config file.
fileName: newrelic.yml
inputOptions:
  - label: 'Name your app'
    name: appName
    codeLine: 21
    defaultValue: 'My app name'
    toolTip: 'New Relic connects metrics to individual applications using your license key and the primary application name.' 
  - label: 'Enter your license key'
    name: licenseKey
    codeLine: 28
    defaultValue: '12345'
---
```

設定ファイルを使用する際は、以下のことを推奨します。

* `newrelic.yml`のパーミッションをデフォルトの値から、アプリケーションサーバープロセスのオーナーのみ読み取り/書き込み可能な値に変更してください。
* `newrelic.yml`がバックアップルーチンの一部となっていることを確認してください。
* デプロイの前後に[New Relic Diagnostics CLI](https://docs.newrelic.com/docs/new-relic-solutions/solve-common-issues/diagnostics-cli-nrdiag/run-diagnostics-cli-nrdiag/)を使用して設定を検証します。

### MDXフロントマターフィールド [#mdx-frontmatter]

* `componentType`：（これら4つのオプションのいずれかを使用します）省略した場合、デフォルトで&quot;default&quot;タイプになります。

  * `default`：フリーMDXファイル
  * `appInfoConfigOption`：これはドロップダウン用です。ドロップダウンが必要な場合はいつでも使用してください
  * `agentConfig`: これはyamlファイル用です
  * `appInfoConfig`：このステップは、コンテンツを表示するステップです（`recommendedGuided`のコンテンツを含みます）。

* `descriptionText`: ステップコンテンツの最初のテキスト（2番目の見出しとして機能する小さな灰色のテキスト）

* `optionType`: 追加されるのは次の場合のみです `appInfoConfigOption`
