適切に選択されたスクリーンショットや画像は、ドキュメントの読みやすさと分かりやすさを大幅に向上させます。しかし、画像が多すぎたり、理解しにくい画像が含まれていたりすると、かえって読者の理解を妨げる原因になります。

* ドキュメントチームのメンバーではなく、ドキュメントサイトに画像を追加したい場合は、[GitHub issue](https://github.com/newrelic/docs-website/issues/new/choose)を作成してください。
* New Relicの社員である場合は、ドキュメントのSlackチャンネルで`@hero`に連絡してください。

## 画像を追加 [#add]

機密データがUIのスクリーンショットに表示されないようにする必要があります。そのため、テストアカウントへのパーマリンクを提供することをお勧めします。ご自身のNew Relicアカウントからスクリーンショットを撮らないでください。

イメージを作成する際に留意すべき点は次のとおりです：

* 画像が一目で有用な情報を提供していることを確認してください。
* [命名規則とインポートステートメントの規則](#naming-and-imports)に従っていることを確認してください。
* 画像には役立つコンテキストを含むキャプションを含めてください。
* スクリーンショットのキャプションには、パスを太字で含めてください。
* ビデオのキャプションには、おおよその再生時間を含めてください。
* 外部の画像ファイルにリンクしないでください。ドキュメントで使用されるすべての画像は、[当社のGitHubリポジトリ](https://github.com/newrelic/docs-website)に保存する必要があります。
* デフォルトはダークモードです。サブジェクトマターエキスパートからライトモードのスクリーンショットが提供された場合は、ダークモードの新しいスクリーンショットをリクエストしてください。ダークモードの画像を取得できない場合は、スクリーンショットがないよりも、どのようなスクリーンショットでもあった方が良いです。

画像を追加または編集するには：

1. 画像を`static/images/`のルートに配置してください。

2. 次の手順を続行して、画像を追加または編集します：

## 画像のキャプションを記述する [#labeling]

分かりやすいキャプションは、読者が画像が重要である理由を知るのに役立ちます。スクリーンショットの場合は、説明に加えてパスを太字で含めると役立ちます。例を以下に示します。

```html
<img
  title="Screenshot showing the Overview dashboard"
  alt="Screenshot showing the Overview dashboard"
  src="/images/kubernetes_screenshot-full_cluster-dashboard-detail.webp"
/>

<figcaption>
  Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Kubernetes**</DNT>. Select your cluster and click <DNT>**Overview Dashboard**</DNT> in the left navigation pane. It shows useful overview data about the status and performance of the cluster and its containerized workloads.
</figcaption>
```

画像の周囲のキャプションやその他のサポートテキストの詳細については、[画像を説明するためのガイドライン](/docs/style-guide/writing-guidelines/screenshots-images#identify-images)を参照してください。

## インライン画像（MDX）を追加する [#inline-images-mdx]

インライン画像を使用するには：

* ファイル内で`img`タグを使用してください
* `src`属性には画像パスが含まれます： `src="/images/IMAGE_NAME.webp"`
* `img`に`inline`のクラスを追加します。
* 任意の高さ/幅を`style`プロパティに追加します。

インライン画像がアイコンとして使用されている場合は、常に最初に説明してください。アイコン画像を埋め込む場合は、テキスト内で画像の後に`icon`という単語を続けてください。例を以下に示します。

```jsx
---
title: Abbreviated example of a file
---

Select your app's settings <img src="/images/example_icon_example-icon.webp" class="inline" style={{height: "30px", width: "30px"}} alt="Multiple app names indicator in New Relic" title="Multiple apps name indicator in New Relic" /> icon.
```

## 画像のサイズ設定

縦長の画像がコンテンツ内で大きくなりすぎるのを防ぐため、デフォルトで、すべてのMDX画像には550pxの最大高さが設定されています。

550pxより高くする必要がある画像がある場合は、`img`属性で`unbound`クラスを設定できます。

```html
<img
  class="unbound"
  title=""
  alt=""
  src=""
/>
```

**注：**一部の画像は、`img`属性で設定された`width="n%;"`を使用しています。これにより、自動的に`unbound`クラスが適用され、デフォルトの画像の高さ制限が削除されます。これは、画像の高さ制限によって画像が引き伸ばされ、比例してサイズ変更されなくなるためです。

## アイコン [#icons]

ドキュメントに含めるさまざまなアイコンから選択できます：

* Featherアイコン（`'fe-`で始まるプリフィックス付き）。
* New Relicアイコン（プレフィックスは`nr-`）。
* サードパーティ製品のロゴ（`logo-`がプレフィックスとして付きます）。

必要なアイコンがすでにあるかどうかを確認するには、次をご覧ください：

* [GitHubの`docs-website`用Feather.js](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104)：これらは`docs-website`プロジェクトで利用可能なFeatherアイコンですが、Gatsbyテーマには含まれていません。
* [GitHubの`docs-website`用Gatsbyテーマ](https://github.com/newrelic/docs-website/tree/develop/src/%40newrelic/gatsby-theme-newrelic/icons)：これは、開発者サイトおよびドキュメントサイト全体で利用できるFeather、New Relic、および製品ロゴアイコンのサブセットです。

GatsbyテーマまたはFeatherで必要なアイコンを使用できます。現在、これらの場所には、重複しない別々のアイコンのバケットがあります。

### アイコンをタグの属性として挿入する [#tag-attributes]

アイコンが別のタグ内の属性として表示される場合は、この例のように`icon`をプレフィックスとして付けます：

```jsx
<LandingPageTileGrid>
  <LandingPageTile
    title="AWS Lambda"
    href="/docs/serverless-function-monitoring/aws-lambda-monitoring/get-started/monitoring-aws-lambda-serverless-monitoring"
    icon="logo-aws"
  >
</LandingPageTile>
```

### インラインアイコンを挿入します。 [#inline-icons]

アイコンが本文内に表示される場合は、`<Icon>`コンポーネントを使用してください。以下にいくつか例を示します。

* Feather： `<Icon name="fe-database" />`
* New Relic: `<Icon name="nr-tdp" />`
* ロゴ： `<Icon name="logo-apple" />`

### 新しいFeatherアイコンをインストールする [#feather-icons]

[GitHubの`docs-website`用Gatsbyテーマ](https://github.com/newrelic/gatsby-theme-newrelic/tree/develop/packages/gatsby-theme-newrelic#available-icons)または[GitHubの`docs-website`用Feather.js](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104)のいずれにも目的のアイコンがない場合は、Gatsbyテーマに新しいアイコンを追加できます。開発者に目的のアイコンを追加するように依頼することもできます。

`database`アイコンを追加する例を以下に示します：

1. [feathericons.com](https://feathericons.com/)に移動します。
2. アイコン自体をクリックして、`database` featherアイコンをダウンロードします。
3. ダウンロードしたら、テキストエディタでSVGファイルを開きます。
4. SVGの&quot;中身&quot;、つまり`<svg>`タグの間にあるすべてのものをコピーします。たとえば、SVGが`<svg><path m="1"></path></svg>`の場合、`<path m="1"></path>`の部分のみをコピーします。
5. `src/@newrelic/gatsby-theme-newrelic/icons/feather.js`でFeatherアイコンのリストを開きます。
6. `database`のエントリを追加し、前の手順のコードをそれに割り当てます。
7. アイコンに複数のパスがある場合は、他のアイコンと同様に、その周りに`<>`ラッパーを含めてください。
8. `feather.js`ファイルを保存します。

`fe-`プレフィックスは、自動的に追加されます。そのアイコンが追加されると、アイコンコンポーネントで使用できるようになります；たとえば、`<Icon name="fe-database" />`。

## 画像リファクタリングPRの競合の処理

画像のリファクタリング後に有効になったコントリビューションの変更点と、未解決のPRでファイルの変更を更新する方法について簡単に説明します。

必ず`develop`から最新のものをプルし、変更に含まれる画像関連ファイルを更新してください：

### リポジトリへの画像の追加：

<SideBySide>
  <Side>
    **以前の画像の規則：**

    画像は以前以下にありました `./src/images`

    ```
    ├──src/
    │  └──content/
    │  │  └──docs/
    │  │    └── example-page.mdx
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>

  <Side>
    **新しい画像規則：**

    画像は現在次の場所にあります `./static/images`

    ```
    ├──src/
    │  └──content/
    │     └──docs/
    │        └── example-page.mdx
    ├──static/
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>
</SideBySide>

### MDXファイルでの画像の使用

<SideBySide>
  <Side>
    **以前の画像の規則：**

    以前は、画像パスを変数としてインポートし、その変数を`<img>`ソースとして使用する必要がありました。

    ```jsx
    import exampleImage from 'images/example-image.webp'

    <img
      title="Image title."
      alt="Alternate text."
      src={exampleImage}
    />
    ```
  </Side>

  <Side>
    **新しい画像規則：**

    これで、画像ソースは静的フォルダーからの相対的な画像へのパスになります：

    ```html
    <img
      title="Image title."
      alt="Alternate text."
      src="/images/example-image.webp"
    />
    ```
  </Side>
</SideBySide>

### MDファイルでの画像の使用

Markdownでの画像の使用は、以前とほぼ同じです。使用するパスを少し変更しました：

<SideBySide>
  <Side>
    **以前の画像の規則：**

    `./images`

    ```md
    ![Image title.](./images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>

  <Side>
    **新しい画像規則：**

    `/images`

    ```md
    ![Image title.](/images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>
</SideBySide>

### ローカルビルド

`develop`から最新の状態でブランチを更新した後、ローカルで変更を実行したときに発生するエラーや失敗したビルドを解決するには、次の手順に従ってください：

1. 上記のように、画像ファイルとコードを新しい規則に更新します
2. 正しいNodeバージョンを使用していることを確認するには、`nvm use`を実行します
3. 必要なパッケージをインストールするには、`yarn`を実行します。
4. `yarn clean`を実行して、古いビルドからキャッシュされた画像を消去します
5. 実行 `yarn start`
