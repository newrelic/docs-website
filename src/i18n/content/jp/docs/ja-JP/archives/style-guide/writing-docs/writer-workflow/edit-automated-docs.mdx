---
title: 自動生成されたドキュメントを編集する方法
translationType: machine
---

New Relicの一部のチームは、GitHubリポジトリからドキュメントコンテンツを自動的に生成します。これらの自動生成されたドキュメントがメインのドキュメントリポジトリ（`https://github.com/newrelic/docs-website`）のプルリクエストに表示される場合、ライターは手動で生成されたドキュメントとは少し異なる方法でこれらを編集する必要があります。

<Callout variant="tip">
  GitHubの作成者を見ることで、ドキュメントが自動生成されたものかどうかを判断できます。
</Callout>

## 自動生成されたドキュメントの編集における課題 [#challenges]

自動化されたドキュメントを編集しても、次のリリースで同じドキュメントを生成する基盤となる自動化には対処できません。

2つの問題を解決する、ドキュメント編集のルーチンが必要です：

* 現在の自動生成されたプルリクエストが、公開に向けて確実に修正されるようにします。
* これらの自動生成されたドキュメントの基となるソースが確実に変更されるようにします。

## 自動生成されたドキュメントを編集するためのベストプラクティス [#best-practices]

リポジトリから自動生成されたドキュメントをレビューする場合は、次の手順を実行してください：

1. 変更を直接プッシュするのではなく、GitHubの提案機能を使用してください。

2. 変更をプッシュしたチームのドキュメントヒーローにお問い合わせください：

   * これにより、作成した提案について開発者にアラートが送信されます。
   * 開発者は提案を承認または拒否します。

3. 提案が受け入れられた場合は、それらの変更をマージして現在のリリースを公開してください。

4. 提案を基となるソースにも適用する必要がある場合は、該当するチームのリポジトリにGithub Issueを作成してください。そのGitHub Issueで、公開ドキュメントサイトのプルリクエストへのリンクを追加してください。これにより、将来の自動リリースを修正するよう開発チームに集計されます。フォローアップのGitHub Issueを作成できるリポジトリの例をいくつか示します：

   * Node.js（`https://github.com/newrelic/node-newrelic`）
   * Ruby（`https://github.com/newrelic/newrelic-ruby-agent`）

<Callout variant="tip">
  Node.jsのドキュメントの場合、行った提案が自動ドキュメントのマーカータグ（`{/* begin: compat-table */}`と`{/* end: compat-table */}`）の間にある場合にのみ、対応するGitHubのIssueを作成する必要があります。これらのセクション外の変更は、自動化の影響を受けません。
</Callout>
