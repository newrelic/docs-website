GitHubで他のライターのドキュメントをレビューおよびピアエディットする方法については、このドキュメントをご覧ください。ローカル環境のセットアップ方法に関する情報については、[テクニカルライターのワークフローのドキュメント](/docs/style-guide/writer-workflow/tech-writer-workflow/)をご確認ください。GitHubの問題をトラブルシューティングするには、[ガイド](/docs/style-guide/writing-docs/writer-workflow/github-troubleshooting/)をご覧ください。

## レビューを受けるタイミング [#when-to-get-review]

テクニカルライターからドキュメントサイトへのほぼすべてのPRは、同僚のテクニカルライターからレビューを受ける必要があります。レビューを行う目的は次のとおりです：

* 不正確な箇所を見つける
* スタイルガイドに準拠します。
* 文章、特にボイスとトーンを改善します。
* 異なる視点を得ます（たとえば、これまで知らなかった仕事に関連することについて学ぶなど）。

レビューは重要であり、デフォルトでは常にレビューを受ける必要があります！それを念頭に置いて、PRの範囲が狭く、上記の考慮事項から恩恵を受ける可能性が低いと確信している場合は、レビューなしでPRをマージできます。PRのレビューを受けるかどうかに関係なく、PRが正しくビルドされ、すべての技術的チェックに合格することを確認するのは、ライターとしての責任です。

レビューなしでマージすることを決定する可能性のある例をいくつか示します：

* リンク切れの修正
* ドキュメントの数語または数行のみの変更
* シンプルで問題がないと確信できる単語/フレーズの単純な検索と置換
* 特に時間的制約のある編集（その場合、後でレビューを受けることを決定できます）
* 追加のレビューは必要ないと思われる、PRレビューに応じて行った変更。

PRのレビューを受けるべきか少しでも迷った場合は、レビューを受けてください。

## GitHubでのピア編集ワークフロー [#peer-edit]

ドキュメントをピア編集している場合、またはレビュアーとしてPRに割り当てられている場合、作業を行う方法と場所にはいくつかの選択肢があります。最も合理的でオープンソースなアプローチは、ファイルをGoogleドキュメントにコピーしてそこで編集するのではなく、GitHubのオプションを使用して編集を行うことです。

### 構成編集パス [#edit-pass]

単純なコピー編集ではなく、質問や提案がある場合は、以下の手順に従ってください。

1. レビューに割り当てられているPRを開きます。

2. \[Files changed] タブでは、次のいずれかを行うことができます：

   * \[Review changes] をクリックし、次のいずれかを選択します：

     * **Comment** - フォローアップを必要としないコメントがある場合に使用します。
     * **Approve** — PRを承認するだけの場合に使用します。\[Leave a comment]エリアで変更をリクエストし、ライターに編集を行わせて、フォローアップのレビューなしでファイルをマージさせたい場合は、\[Approve]を選択できます。
     * **変更をリクエスト** — リクエストした変更が確実に含まれるようにしたい場合に使用します。ライターが行った更新が通知されます。

   * または、ドキュメントの行またはセクションにコメントを追加し始めます。これを行うには、コメント追加アイコンをクリックし、ページ内のその特定の行に対して編集またはコメントを残します。このオプションを使用すると、単一のコメントを追加するか、レビューを開始するかを選択できます。ドキュメント全体にコメントを追加する場合は、コメントがすべて1つのコミットにまとめられるように、**Start a review**を選択します。

3. **Finish your review** \[レビューを完了]をクリックして、レビューを完了します。これにより、提案が行われたことを知らせる通知がライターに送信されます。

### コピー編集ワークフロー [#edit-copy]

コメントや提案ではなく、ファイルのコピー編集がある場合は、さまざまな方法でファイルに変更を加えることができます。主な2つのオプションは次のとおりです：

1. GitHubブラウザを使用して編集する：**Files changed**タブのdiffウィンドウで、編集ボタン（3つのドット）をクリックします。編集が完了したら、ファイルの下部にコメントを追加し、**commit the changes directly**を選択するか、**create a branch and start a pull request**を選択します。ライターがdiffをレビューし、編集を受け入れるか修正することを期待する場合は、ブランチを作成してプルリクエストを開始することを選択します。
2. ローカルで編集: 編集したいファイルが含まれているブランチをチェックアウトします。GitHub Desktopで、現在のブランチの下矢印をクリックしてブランチを選択します。次に、ローカルドライブで編集を行い、保存して、変更をブランチにコミットします。
   * このアプローチでは、開いているプルリクエストに編集が追加されることに注意してください。これで、PRの**Files changed**タブでファイルに追加した変更を確認できます。

これらは、多数ある編集オプションのほんの一部にすぎません。他のツールと同様に、好みの方法が見つかるでしょう。
