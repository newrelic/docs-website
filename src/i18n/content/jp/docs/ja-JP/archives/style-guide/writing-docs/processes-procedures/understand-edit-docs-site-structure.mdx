このドキュメントには、ナビゲーションファイル、サイドバー、フォルダーまたはファイル構造など、ドキュメントサイトの構造に関する情報と手順が含まれています。

一般的なユースケースの簡単な手順については、[手順](#procedures)をご覧ください。ただし、大規模なドキュメントサイトのプロジェクトを行う場合は、事前に[一般的な概念](#understand)を理解しておくことをお勧めします。

## 条件 [#terms]

ドキュメントサイトの構造について話す際、同じものに対して異なる言葉が使用されることがあります。ドキュメントサイトの構造についてコミュニケーションをとる際に役立つ用語のリストを以下に示します：

* **ドキュメントファイル**: すべてのドキュメントは.mdxファイル（マークダウンファイルとも呼ばれます）で表されます。
* **Navファイル**: Navファイルは、ドキュメントサイトの左側のサイドバーに表示される、ドキュメントサイトの表示構造を管理するものです。Navファイルは、`src/nav`ディレクトリにあるyamlファイルです。
* **フォルダー**: このコンテキストでは、「フォルダー」は実際のドキュメントサイトのフォルダー構造（`content`ディレクトリ内のフォルダーとファイル）を指します。「フォルダー」を参照することは、実際のフォルダー構造と、ナビゲーションファイルを使用して設定される表示構造を区別するのに役立つ場合があります。
* **サイドバー**：公開されているドキュメントでは、サイドバーは左側に表示されるもので、そのドキュメントのカテゴリの構造を示しています。サイドバーの構造は、navファイルで設定された構造によって決定されます。
* **カテゴリ**または**サブカテゴリ**: ドキュメントサイトの特定の領域を指すために、これらの言葉をほぼ同義で使用します。たとえば、&quot;Accounts&quot;カテゴリや&quot;Manage data&quot;カテゴリと呼ぶことがあります。
* **自動インデックスページ**(非推奨)：これは、ユーザーが特定のカテゴリのドキュメントのビューを読み込むことができる(たとえば、サイドバーのカテゴリ見出しをクリックするなど)以前の実装を指します。この実装は現在サポートされていません。

## ドキュメントサイトの構造の仕組みを理解する [#understand]

このセクションでは、ドキュメントサイトの構造がどのように決定されるか、また、一般に公開する構造が実際のフォルダ構造とどのように関連しているかについてのロジックをいくつか説明します。

### 表示される構造は実際のフォルダーとどのように関連していますか？ [#folders-vs-categories]

実際のドキュメントのフォルダー構造（`content`フォルダー内のフォルダーとmdxファイル）は、サイドバーのドキュメントサイトの構造とは完全に独立しています。サイドバーに表示される構造は、ナビゲーションファイル（`src/nav`フォルダー内のyaml形式のファイル）によってのみ決定されます。

上記の点を理解することが重要です。docsフォルダ構造と表示されるdocsサイト構造の相違は必要です：フォルダ構造、フォルダ名、およびドキュメントファイル名を完全に同一に保つことなく、サイドバーに表示される構造を制御する方法が必要です。これら2つは別々であるため、そのロジックの機能方法に直感的ではない側面がある可能性があります。

[一般的なユースケースの手順](#procedures)は用意していますが、表示される構造がどのように生成されるかについて、以下の詳細を理解しておくと非常に役立ちます。

### ドキュメントのURLは何によって決まりますか？ [#doc-url]

ドキュメントファイル（`mdx`ファイル）が`content`フォルダー内のどこにあるか、および関連するフォルダー名とファイル名が、そのドキュメントのURLを決定する唯一の要因です。

たとえば、次のドキュメントファイル`automated-user-provisioning-single-sign.mdx`を考えてみましょう：

<img title="Doc file in its folder" alt="Example of a doc file in the folder structure" src="/images/style-guide_screenshot-full_doc-in-folder-structure.webp" />

このドキュメントのURLは、そのフォルダーの場所とフォルダー名のみに基づいています。この場合、そのURLは次のようになります：

```
docs.newrelic.com/docs/accounts/accounts/automated-user-management/automated-user-provisioning-single-sign
```

これには、次のような重要な意味があります。

* ドキュメントをあるフォルダーから別のフォルダーに移動すると、そのURLが変更されます。つまり、ドキュメントファイルを移動する場合は、元のURLのそのドキュメントへのリダイレクトを追加する必要があります。
* mdxファイル名またはフォルダー名を変更すると、そのURLも変更されます。つまり、元のURLのドキュメントへのリダイレクトを追加する必要があります。

### navファイルは何をしますか？ [#nav-file-contents]

navファイルは非常にシンプルです。navファイルは、サイドバーに表示されるドキュメントの表示構造を制御します。現在、ドキュメントの主要なセクションごとに1つずつ、複数のナビゲーションファイルがあります。たとえば、「Accounts」のナビゲーションファイルがあり、これには組織およびアカウント関連の設定が含まれています。また、「infrastructureモニタリング」のナビゲーションファイルもあります。

navファイルの形式の詳細については、[Nav file format](#nav-format)をご覧ください。

### サイドバーの表示方法はどのように決まりますか？ [#doc-sidebar]

上記のように、サイドバーはドキュメントサイトの構造（ナビゲーションファイルによって管理されます）を公開する1つの方法にすぎません。

ドキュメントが読み込まれると、ドキュメントサイトはすべてのナビゲーションファイルにわたってそのURLを検索します。一致するものが見つかった場合、そのドキュメントをハイライトして、サイドバーにそのナビゲーションファイルを表示します。

ドキュメントのURLは、複数のnavファイルに存在する場合があります。現在、ドキュメントはすべてのnavファイル全体で1か所にしか配置できないというルールがあります。しかし、複数のnavファイルに存在するドキュメントがまだいくつかあります。そのような場合、当社のサイトは、ドキュメントのURLのトップレベルカテゴリに一致するnavファイルを選択することで、適切なnavファイルを見つけようとします。たとえば、相対URLが`/docs/accounts/accounts-billing/account-setup/create-your-new-relic-account`のドキュメントが2つのnavファイルにある場合、ドキュメントサイトのコードは、いずれかのnavファイルの最初の`path`フィールドに`docs/accounts`があるかどうかを検索します。一致するものが見つかった場合は、そのnavファイルを使用します。

## Navファイルの形式 [#nav-format]

以下は、[`agents.yml`](https://github.com/newrelic/docs-website/tree/develop/src/nav/agents.yml)navファイルのスニペットです。ファイルには、ナビゲーション階層のレベルに対応するインデントがあることに注意してください。変更を加えたり、新しいnavファイルを作成したりする場合は、必ず既存のスペース形式を使用してください。

```yml
title: Agents
path: /docs/agents
pages:
  - title: Manage APM agents
    pages:
      - title: Agent data
        pages:
          - title: Real time streaming
            path: /docs/agents/manage-apm-agents/agent-data/real-time-streaming
          - title: Custom instrumentation
            path: /docs/agents/manage-apm-agents/agent-data/custom-instrumentation
          - title: Agent attributes
            path: /docs/agents/manage-apm-agents/agent-data/agent-attributes
          - title: Custom events
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-events
          - title: Custom metrics
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-metrics
          - title: Manage errors
            path: /docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected
          - title: Link Kubernetes
            path: /docs/agents/manage-apm-agents/agent-data/link-your-applications-kubernetes
      - title: App naming
        pages:
          - title: Name your application
            path: /docs/agents/manage-apm-agents/app-naming/name-your-application
          - title: Use multiple names for an app
            path: /docs/agents/manage-apm-agents/app-naming/use-multiple-names-app
```

<Callout variant="tip">
  ナビゲーションのネストは現在、最大6レベルの深さに制限されています。それで不十分な場合は、エンジニアリングチームにお問い合わせください。
</Callout>

### 大規模なドキュメントサイト再構築プロジェクトの手順の概要 [#large-project]

ドキュメントサイトの小規模な編集の場合、ドキュメントのファイルやフォルダーに触れることなく、ナビゲーションファイルを編集するだけで済むことがあります。ただし、大規模なプロジェクトの場合は、ドキュメントのファイルやフォルダー自体を編集および移動する必要がある場合があります。以下は、このような大規模なプロジェクトに通常伴う作業の概要です。

1. 新しいナビゲーションファイル構造がどのようになるかを計画し、ドキュメントファイルの移動や新しいフォルダーの作成作業を計画します。大規模なプロジェクトに伴う作業の塊を書き出すと役立ちます。
2. 影響を受けるドキュメントファイルを新しいフォルダーの場所に移動し、必ずリダイレクトを追加してください。詳細については、[フォルダー間でドキュメントを移動する](#move-docs-between-folders)をご覧ください。
3. 空のフォルダーをすべて削除します。
4. ファイル構造自体に対して行うフォルダまたはファイルの編集（ファイルまたはフォルダの名前変更、ファイルとフォルダの移動を含みますが、ドキュメントまたはnavファイル内のコンテンツやフロントマターの編集は含み**ません**）については、`i18n`ディレクトリ内のフォルダとファイルにも同じ編集を行ってください。すべてのフォルダーまたはファイルがi18nディレクトリに存在するわけではありません：mdxファイルが翻訳対象としてマークされている場合にのみ、そのmdxファイルまたは関連フォルダーが配置されます。
5. 新しい目的の構造を反映し、新しいドキュメントのURLを指すようにnavファイルを編集します。

より具体的で詳細な手順については、引き続きお読みください。

### ドキュメントの新しいカテゴリを追加します。 [#add-category]

既存のnavファイルにドキュメントのサブカテゴリを追加する手順と、まったく新しいnavファイルを追加する手順の2つを説明します：

#### navファイルに新しいカテゴリを追加する [#add-nav-section]

navファイルに新しいカテゴリを追加するには：

1. 既存のnavファイルに、`title`で表される新しいカテゴリを追加します。
2. 他のnavファイルの形式とインデントを模倣して、そのセクションに必要なドキュメントを追加してください。

この仕組みの詳細については、以下をご覧ください：

* [ドキュメントのサイドバーが決定される仕組み](#doc-sidebar)
* [ドキュメントカテゴリビューの決定方法](#category-view)

#### 新しいnavファイルを追加します。 [#add-new-nav]

まったく新しいナビゲーションファイルを追加することはまれであり、サイト構造の大規模な見直しの際にのみ時折行うことです。新しいナビゲーションファイルを追加する場合は、ドキュメントサイトマネージャーの承認を得る必要があります。

まったく新しいnavファイルを追加するには：

1. 既存のファイルnavファイルをコピーするか、新しいnavファイルを作成します。
2. 標準のナビゲーションファイルのフォーマットとインデントを使用して、必要なカテゴリとドキュメントで新しいナビゲーションファイルをカスタマイズします。構造の詳細については、[nav format](#nav-format)を参照してください。

### サイドバー/ナビゲーションファイルにドキュメントを追加する [#add-doc-to-nav]

[ドキュメントを作成](/docs/style-guide/writing-guidelines/create-edit-content/#creating-docs)したら、それをnavファイルに配置する必要があります。ドキュメントを複数のnavファイルの場所に配置しないでください：別のカテゴリからドキュメントへのリンクが必要な場合は、関連するドキュメントセクション内にその参照を配置してみてください。

navファイルにドキュメントを追加するには：

1. 配置するnavファイルの場所に、`title`（サイドバーとカテゴリビューに表示される短いタイトル）と、ドキュメントのURLである`path`を追加します。
2. 標準のnavファイルのフォーマットとインデントをエミュレートしていることを確認してください。

### ドキュメントを他のカテゴリに移動します。 [#move-docs]

ナビゲーションファイルと実際のフォルダー構造は接続されていないため、&quot;ドキュメントを移動する&quot;には2つの異なる方法があります：

* ナビゲーションファイル内のドキュメントの移動：推奨される最も一般的な手順。
* フォルダー間でドキュメントを移動する：これは頻度が低く、主にドキュメント構造の大幅な見直しを行う大規模なプロジェクトを実施する際、フォルダー構造がnavファイル構造から乖離しすぎないようにしたい場合に行います。

#### navファイルを使用してドキュメントを移動する [#move-docs-in-nav-file]

サイドバーメニューでの表示場所を変更したい場合は、navファイル内のドキュメントを移動します。

navファイル内でドキュメントをある場所から別の場所に移動するには：

1. 最初のナビゲーションファイルで、そのドキュメントのエントリを表す2つの行（`title`行と`path`行）をコピーし、新しいナビゲーションファイルの配置したい場所にそのコンテンツを貼り付けます。
2. 新しいnavファイルのセクションでは、フォーマットとインデントが標準のnavファイルの構造と一致していることを確認してください。navファイルの構造の詳細については、[Navフォーマット](#nav-format)をご覧ください。

#### フォルダー間でドキュメントを移動する [#move-docs-between-folders]

フォルダー間でドキュメントを移動することは、比較的まれであることにご注意ください。これを行う主な理由は、フォルダー構造とnavファイル構造がかなり乖離してきている場合であり、これはいくつかの理由で好ましくありません：

* 分岐が多すぎると、ユーザーの混乱（たとえば、フォルダーベースのURLの要素がnavファイルベースの場所と大きく異なる場合など）や、検索エンジンの結果が最適ではなくなる可能性があります。
* 分岐が多すぎると、ドキュメントの検索や編集が困難になる可能性があるため、かなり最新の状態で並行して維持することには価値があります。

フォルダー間でドキュメントを移動したり、ドキュメントの名前を変更したりすると、そのURLが変更されます（その理由の詳細については、[構造を理解する](#understand)を参照してください）。同様に、フォルダーの名前を変更すると、その領域にあるすべてのドキュメントのURLが変更されます。

フォルダー間でドキュメントを移動するには：

1. 移動するドキュメントの現在のURLを取得し、そのURLを独自のリダイレクトリストに追加します。ヒント：

   * VSCodeでこれを行う1つの方法は、ファイル名を右クリックして「Get relative path」をクリックすることです。
   * 多くのファイルを移動する場合は、ドキュメントディレクトリ全体にリダイレクトをプログラムで追加するためのスクリプトについてチームに問い合わせてください。
   * リダイレクトURLの末尾にスラッシュがないことを確認してください。

2. ドキュメントを新しいフォルダーの場所に移動してください。

3. そのmdxファイルが`i18n`ディレクトリに存在する場合（翻訳のマークが付けられている場合は存在します）、`i18n`ディレクトリ内のそのファイルも同様に移動します。

4. **新しいURLでnavファイルを更新します**。リダイレクトではなく、正しいドキュメントのURLをnavファイルに記述することが重要です。ドキュメントのURLは複数のnavファイルに含まれている場合があるため、サイトでそのURLを検索すると役立つことに注意してください。

### フォルダーの移動、削除、または名前の変更 [#move-delete-folders]

大規模な再構築プロジェクトを行う場合、単にnavファイルを編集するのではなく、実際のフォルダーを移動、削除、または名前変更したいことがあります。これに関する解説：

1. フォルダを移動したり名前を変更したりすると、そのフォルダ内のドキュメントのすべてのURLが変更されるため、まず影響を受けるドキュメントにリダイレクトを追加する必要があります。これは手動で行うか（[こちらのステップ1で説明](#move-docs-between-folders)）、ドキュメントチームが用意している、ディレクトリ内のすべてのドキュメントにリダイレクトを一括追加するためのスクリプトを使用できます。
2. 目的の編集を行います。たとえば、フォルダーを新しい場所に移動したり（Finderウィンドウでのドラッグアンドドロップなど）、フォルダーの名前を変更したりします。
3. 編集されたフォルダーが`i18n`ディレクトリに存在する場合（そのフォルダー内のドキュメントに翻訳のマークが付けられている場合は存在します）、`i18n`ディレクトリ内のそのフォルダーとそのファイルに同等の編集を行います。注意：`i18n`の作業は、フォルダーやファイルの移動または名前変更にのみ必要であり、ドキュメントやナビゲーションファイルの内容の編集には必要**ありません**。

フォルダーを削除する場合は、基本的に上記と同じ手順に従います：移動または削除するmdxファイルのリダイレクトを追加し、ドキュメントを移動または削除してから、空のフォルダーを削除します。

### ドキュメントのファイル名を変更 [#change-doc-file-name]

mdxファイルの名前を変更すると、[URLが変更されます](#understand)。実際のファイル名を変更せずに、フロントマターでドキュメントの表示タイトルを変更できることに注意してください。ファイル名の変更が役立つ場合があります。解説：

1. ファイル名を変更するドキュメントへのリダイレクトを追加してください。
2. ファイル名を変更してください。
3. そのファイルが`i18n`ディレクトリに存在する場合（そのドキュメントが翻訳対象としてマークされている場合は存在します）、`i18n`ディレクトリ内のそのファイル名に対して同等の編集を行います。注意：`i18n`の作業は、フォルダーやファイルの移動または名前変更にのみ必要であり、ドキュメントやナビゲーションファイルの内容の編集には必要**ありません**。

### プレースホルダードキュメントを作成する [#placeholder-doc]

ナビゲーションファイルの複数の場所にドキュメントを配置することはもう望んでいません（ただし、このようなドキュメントはまだいくつかあります）。ナビゲーションファイルの複数の場所でドキュメントを参照したい場合は、代わりに、そのドキュメントを参照することが理にかなっている場所をドキュメント内で見つけるようにしてください。
