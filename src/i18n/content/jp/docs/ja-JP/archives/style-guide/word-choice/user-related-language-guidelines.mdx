このドキュメントでは、ユーザーロール/権限関連のドキュメントで必須のスタイルと推奨される言い回しについて説明します。

## ユーザーモデルに関する注意事項

このスタイルガイドは主に、初代のユーザーモデルではなく、当社の新しいユーザーモデルのユーザーに関する記述に適用されます。両方のユーザーモデルで特定の用語（**Admin**など）が共通していても、これはまったく異なる構造、推奨される言い回し、スタイルを持つ、まったく異なるユーザーモデルです。ユーザーモデルの違いを理解するには、[ユーザーモデルの概要](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models)をご覧ください。

元のユーザーモデルは非推奨になる傾向にあるため、そのユーザーモデルについて深く考えたり、それらのドキュメントを頻繁に更新したりする必要はありません。

## ユーザーの権限/ロールのドキュメント化に関するガイドライン [#user-language-philosophy]

New RelicユーザーがNew Relic機能にアクセスする能力に影響を与える主な要因は2つあります：

* ユーザータイプ：ユーザータイプに関する情報は、ほぼ完全に[ユーザータイプドキュメント](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type)に限定しています。

* ロールとケイパビリティ：これに関する情報は、ほぼ完全に専用のユーザー管理ドキュメントに限定しています：

  * [元のユーザーモデルのドキュメント](/docs/accounts/original-accounts-billing/original-users-roles/users-roles-original-user-model)
  * [新しいユーザーモデルのドキュメント](/docs/accounts/accounts-billing/new-relic-one-user-management/introduction-managing-users)

言い換えると、以下の例外を除き、**製品機能関連のドキュメントにユーザータイプやロール/機能に関する情報は記載しません**：

* ユーザータイプについて：ほとんどの製品機能において、ユーザータイプが原因で何かが制限されている場合、ユーザーにはそれが明らかです（たとえば、ユーザータイプに関するUIメッセージが表示されます）。ユーザータイプが原因で何かが制限されていることが明らかでない場合は、機能ドキュメントの要件セクションにその旨を記載できます。たとえば、NerdGraphのユーザーにとって、特定のrequestsを送信できない理由がすぐにはわからない場合があります。このような状況では、メインのNerdGraphドキュメントにユーザータイプを記載します。
* ロールと権限について：機能ドキュメントの要件セクションにユーザータイプまたはロール/権限を含める特定の理由がある場合は、それを含めることができます。たとえば：機能へのアクセスを制御する[権限](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions)が、権限の名前（[サービスレベル管理権限](/docs/service-level-management/faqs-slm#permissions)など）から明らかでない場合は、それをドキュメント化する必要があります。
* 組織およびユーザー管理の権限については、必要なロールを文書化しています。これは、これらの数がそれほど多くないためであり、また、これらを管理する権限がロールと権限のUIに表示されず、顧客にとって分かりにくいためです。

## 元のユーザーモデルと新しいユーザーモデルの両方を文書化する際の考慮事項 [#user-model-requirements]

新しいユーザーモデルのロールまたは権限に関する要件を含める必要がある場合は、元のユーザーモデルに関する詳細も含める必要があるでしょう（その機能がその対象者で利用可能であると想定して）。その方法の例は次のとおりです：

```md
Permissions requirements differ depending on your user model:

* For users on the [original user model](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models): the [**Data retention manager** role](/docs/accounts/original-accounts-billing/original-users-roles/users-roles-original-user-model/#roles).
* For users on [our newer user model](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models): the [**Billing** administration setting](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts#admin-settings).
```
