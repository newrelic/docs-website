Swiftypeは、`docs.newrelic.com`の検索を強化するElasticベースの検索エンジンです。

New Relicのテクニカルライターとして、内部検索でドキュメントが確実に認識されるように、Swiftypeにログインしてさまざまなタスクを実行する必要がある場合があります。

## Swiftypeクローラー情報 [#crawler-info]

クローラーは12時間ごとにクロールすると表示しています。クロールする速度は比較的遅いため、ページの変更を検出するまでにそれ以上の時間がかかる可能性があります。また、クロール時には`sitemap.xml`とリンク収集の組み合わせも使用します。

必要に応じて、12時間に1回手動クロールをトリガーできます。または、必要に応じてSwiftypeに特定のページをクロールさせることもできます。

ドキュメントの平均再インデックス時間は4日です。

## Swiftypeインデックスに新しいページを手動で追加します。 [#manually-index]

クロールが遅すぎて、ページをすぐに利用できるようにしたい場合は、Swiftypeインデックスに新しいページを手動で追加することをお勧めします。

Swiftypeで新しいページを手動で追加するには：

1. **Domains &gt; [https://docs.newrelic.com/](https://docs.newrelic.com/)**に移動して、ドキュメントタイプが無視リストに含まれていないことを確認してください。

2. **New Relic &gt; Content**に移動します。

3. **Filter pages**と表示されているテキスト入力ボックスに、インデックスを作成するページのURLを貼り付けます。

4. ページがインデックスにない場合、Swiftypeは**Add this URL** \[このURLを追加]オプションを提供します。そのオプションをクリックして、ページをインデックスに追加します。

5. URLを挿入し、必ず以下の操作を行ってください：

   * 次のようにURL全体を使用します： `https://docs.newrelic.com/docs/path/to/doc/`
   * URLの末尾にスラッシュがあることを確認してください

Swiftypeは1分ほどでインデックスを作成するはずです。インデックスが作成されているか確認するには、ページを更新してURLを貼り付けます。管理者UIがキャッシュされたり、遅延したりする場合があることに注意してください。同僚に確認を依頼するか、REST APIを使用して確認するか、キャッシュをクリアするか、ページを再読み込みしてもう一度確認することができます。

## 既存のSwiftypeレコードを手動で更新する [#manual-index]

インデックスに新しいページを手動で追加するのと同様に、クロールが遅すぎてインデックスをすぐに更新したい場合は、既存のレコードを更新できます。ページのURLを変更し、古いURLが新しいURLにリダイレクトされる場合は、このメソッドを使用します。これに関する詳細な議論については、以下の[URLの変更](#url-changes)セクションを参照してください。

既存のレコードを手動で更新または再インデックスするには：

1. **New Relic &gt; Content**に移動します。
2. 古いURL（ページが最後にインデックスされたURL）を貼り付けます。
3. インデックスに見つかった場合は、そのエントリが表示されるはずですので、**Details**を選択してください。
4. レコードの詳細ページで、**Reindex**を選択します。
5. [特定の検索語の検索結果をランク付けする](#rank-results)の手順に従って、このドキュメントのランキングを再度追加します。

Swiftypeは1分以内に再インデックス化されるはずです。そのレコードは、設定したカスタムランキングとともにインデックスから削除され、クローラーがリダイレクトされた新しいURLに対して新しいレコードが作成されることに注意してください。そのため、結果のランキングを更新する準備をしてください。

## 既存のSwiftypeレコードを手動で削除してください [#remove-records]

次のような場合は、インデックスから既存のレコードを手動で削除することをお勧めします：

* リダイレクトなしで削除されたページのレコードをすばやく削除したい場合
* 最近URLが変更されたページのレコードが複数あることに気付いた場合（1つは古いURL用、もう1つはリダイレクトの外部で検出された新しいURL用）。

インデックスからレコードを手動で削除するには：

1. **New Relic &gt; Content**に移動します。
2. 削除するレコードのURLを貼り付けます。
3. **詳細**を選択します。
4. **詳細**ページの下部にある**このドキュメントを削除**を選択します。

## 指定された検索用語の検索結果をランク付けします [#rank-results]

指定した検索語句の検索結果をランク付けして、特定のページを結果の上位または下位に移動します。指定した検索語句の結果からレコードを除外することもできます。

すべてのWebサイトのページは1つのエンジンで処理されるため、ランキングリストが煩雑になります。関連するページのURLを参照するのではなく、特定のURLを検索することをお勧めします。

<Callout variant="tip">
  特定のレコードのURLが変更された場合、結果のランキングは失われ、新しいURLに関連付けられた新しいレコードに対して追加する必要があります。
</Callout>

結果をランク付けするには：

1. **New Relic &gt; Result Rankings**に移動します。
2. ランク付けしたい検索語をテキスト入力に入力してください（大文字と小文字は区別されません）。
3. 結果を上または下にドラッグします。ページのURLを検索し、ピン留めして、移動させたいと思うでしょう。
4. 結果の**X**ボタンを選択して、結果を削除してください。

詳細については、[公式のSwiftypeドキュメント](https://swiftype.com/documentation/site-search/guides/result-rankings)を参照してください。

## エイリアスを追加します。 [#add-alias]

結果のランキングを設定する際、エイリアスを追加することもできます。エイリアスは[シノニム](#add-synonym)に似ていますが、特定の結果セットにのみ適用されます。

エイリアスを追加するには：

1. **New Relic &gt; Result Rankings**に移動します。
2. 検索語を入力してください。
3. テキスト入力にエイリアスを追加してください。

## 同義語を追加 [#add-synonym]

ある検索語で別の検索語と同じ結果を表示させたい場合は、シノニムを追加します。以前の例：

* RBAC=ロールベースのアクセス制御
* servers=New Relic Infrastructure

同義語を追加するには、**New Relic &gt; Synonyms**に移動します。

詳細については、[公式ドキュメント](https://swiftype.com/documentation/site-search/guides/synonyms)を参照してください。

## ベストプラクティス：重要な検索用語 [#important-search-terms]

おそらく、次のような検索語に対して結果がランク付けされ、正確であることを確認する必要があります：

* ノイズの多い結果を伴う非常に曖昧なものとして知られています（例：ブラウザ）
* サイトで最も人気のある検索用語
* 用語集の用語

## ベストプラクティス：URLの変更 [#url-changes]

すでにインデックスに登録されているページのURLが変更された場合、Swiftypeは古いURLに関連付けられたそのレコードを削除します。また、新しいURLへのリダイレクトが存在する場合、Swiftypeは新しいURLに関連付けられたページの新しいレコードを作成します。その場合、古いレコードの結果ランキングは失われ、新しいURLを持つ新しいレコードに再度追加する必要があります。

Swiftypeで再クロールをトリガーすると最終的にこれは修正されますが、長い時間がかかる場合があります。または、古いページの特定の結果を削除し、新しいページをインデックス化するように手動で指示することもできます。これは、次に特定の検索語のキャッシュを更新する際に`docs-library-service`に同期される*はず*です。
