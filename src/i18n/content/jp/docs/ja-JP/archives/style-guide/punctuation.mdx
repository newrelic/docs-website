文章において、句読点は話し言葉を模倣するために使用され、言語の意味を伝える上で重要な役割を果たします。たとえば、誤って配置された感嘆符は、メッセージのトーンや意図を劇的に変える可能性があります。

## アンパサンド（&amp;）

**UIのみ**。スペースが限られている場合は、ナビゲーション項目にアンパサンドを使用します。たとえば、メインナビゲーションの`AI & Alerts`などです。会社名やブランド名の一部である場合にのみ、文や見出しで使用してください。

## アポストロフィ

* 頭字語を複数形にするためにアポストロフィを使用しないでください。
* 年を省略するためにアポストロフィを使用しないでください。年は常に4桁で記述してください。
* 短縮形を作成する場合はアポストロフィを使用します。

| 実行           | してはいけないこと       |
| ------------ | --------------- |
| SRE          | SRE             |
| 2017年、1990年代 | \\&apos;17、90年代 |
| できません        | cant、cannot     |

## コロン

* コロンは、次に続く内容が前の単語、フレーズ、または文に直接関連していることを示します。
* 文の断片の後にコロンを使用しないでください。

コロンを使用するための一般的なガイドライン：

##

* 本文：コロンの後の最初の単語が完全な文の始まりである場合は、その単語を大文字にします。それ以外の場合、本文のコロンの後の最初の単語は大文字にしません。
* 見出しの場合：コロンの後の最初の単語は、品詞に関係なく大文字にします。ただし、単語が小文字で始まる製品名である場合、または開発者向け資料で小文字で始まるコンピューターリテラルである場合は除きます。
* リードイン付きの箇条書きリストの項目の場合：導入の単語やフレーズ（通常は太字）がある場合は、完全な文でなくても、それに続くテキストの最初の単語を大文字にします。

## セミコロン

これらは通常、長くて複雑な文をサポートします。エムダッシュ（`—`）を使用するか、文を簡潔にするか、単に新しい文を開始することを検討してください。

## カンマ

文中で3つ以上の項目をリストする場合は、最後の項目と「and」という単語の間にカンマを含めてください。これはオックスフォード・カンマとも呼ばれ、一部のライターの間では議論の的となっていますが、実用的なメリットの方が大きいです。

「今一番好きな3つのものは何ですか？」という質問に対する以下の回答を検討してください。

1. 私は兄弟、ボブ・ロス、そしてFun Dipが大好きです。
2. 私は兄弟であるBob RossとFun Dipを愛しています。

最初の文は、話し手が3つの別々のものを愛していると述べていますが、2番目の文は、話し手の兄弟の名前がボブ・ロスとファン・ディップであると述べています。

## ダッシュとハイフン

* 範囲や数値の期間には、両側にスペースを入れずにenダッシュ（`–`）を使用します。
* 日付の期間には、enダッシュの周囲にスペースを使用します。
* 複合語はハイフンでつなぎます；たとえば、usage-based pricingやshort-term data storageなどです。名詞の前に来て修飾する複合語では、「ly」で終わる副詞をハイフンでつながないでください；たとえば、highly customized softwareなどです。

| 実行                    | してはいけないこと             |
| --------------------- | --------------------- |
| 2～30                  | 2～30                  |
| 2019年7月12日～2019年7月19日 | 2019年7月12日～2019年7月19日 |

## 省略記号

重要ではない情報を省略できる場所（表のセルなど）でスペースの制約がある場合は、元のテキストをできるだけ多く表示し、切り詰めたテキストの末尾に省略記号を追加します。顧客が全文を簡単に、わかりやすく取得できる方法があることを確認してください。多くの場合、ホバー時のツールチップに全文を表示します。

## 感嘆符

感嘆符は文章に個性を加えることができますが、使用は控えめにし、テキストに追加する際は顧客の不安レベルを考慮してください。私たちは顧客を応援したいのであり、怒鳴りつけたいわけではありません。

* 成功画面やメッセージには感嘆符の使用を検討してください。
* ユーザーがトラブルシューティングを行っている可能性がある状況では、感嘆符の使用を避けてください。
* エラーメッセージでは絶対に感嘆符を使用しないでください。

迷った場合は、感嘆符を使用しないでください。

| 実行                    | してはいけないこと      |
| --------------------- | -------------- |
| 初めての集計の作成、おめでとうございます！ | おっと！問題が発生しました。 |

## ピリオド

* 完全な文の末尾には句点を使用してください。
* ヘッダーまたはサブヘッダーに句点を使用しないでください。（.comサイトのブランドガイドラインに従う場合を除きます。）
* テキストが完全な文にならない限り、リストの各行の末尾に句点を使用しないでください。
* リスト（箇条書き、番号付きなど）を記述する場合は、リスト内のすべての項目をフラグメントにするか、完全な文にします。混在させないでください。

## 疑問符

* 平叙文ではなく、完全な疑問文には疑問符を使用してください。
* データや説明がない場合のプレースホルダーとして疑問符を使用しないでください。

## 引用符

* 平叙文が引用テキストで終わる場合は、句点を閉じ引用符の内側に配置します。
* 引用符の中に引用符がある場合は、外側のテキストに二重引用符を使用し、内側の引用符に一重引用符を使用します。

### 例

* アルベルト・アインシュタインはかつて、「シンプルに説明できないのであれば、それを十分に理解していないということだ」と言いました。
* Lew Cirneは次のように述べています。「Hello, Relics！アルベルト・アインシュタインがかつて「シンプルに説明できないのであれば、それを十分に理解していないということだ」と言ったことを思い出してください。頼りにしています。」

## スラッシュ

スラッシュ(`/`)は、文字、単語、または数値を区切ります。最も一般的には、「〜につき」を意味するために使用します。スラッシュの前後にスペースは入れません。例を以下に示します。

* 0.30ドル/GB
* 100 GB無料/月
* 100万/月

LinuxやmacOSなどの\*nixシステムでは、ファイルパス内のディレクトリを区切るためにスラッシュも使用されます。Windowsシステムの場合、代わりにバックスラッシュ（`\`）が使用されます。説明しているOSに正しい文字を使用するように注意してください。例を以下に示します。

* `/Users/LewCirne/Desktop`
* `C:\Users\LewCirne\Desktop`
