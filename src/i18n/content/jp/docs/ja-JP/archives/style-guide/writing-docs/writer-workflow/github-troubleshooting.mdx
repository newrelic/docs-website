[GitHubでのドキュメントの作業](/docs/style-guide/writer-workflow/tech-writer-workflow/)で問題が発生していますか？次の一般的な問題を確認してください。

## ローカルビルドで404エラーが発生する [#build-fails]

### 問題

localhost:8000をビルドしようとすると、1つまたはすべてのWebページで404エラーが発生します。

### ソリューション

ローカルビルドで何が問題だったのかを把握するために、これらの解決策のいくつかを試してください。

<CollapserGroup>
  <Collapser className="freq-link" id="troubleshoot-file" title="問題のあるファイルをトラブルシューティングします。">
    エラーの原因となっているファイルがわかっている場合は、次のコマンドを実行してエラーを特定します：

    ```bash
    yarn verify-mdx path/to/file.mdx
    ```

    このコマンドは、エラーの原因となっている特定の文字や行番号など、通常のGatsbyの出力よりもエラーに関する詳細な情報を返します。

    <CollapserGroup>
      <Collapser className="freq-link" id="example" title="例">
        ブランチ内の複数のドキュメントに変更を加えたと仮定します。サイトをローカルで実行するか、Netlifyビルドにアクセスしようとすると、次のエラーが発生します：

        ```
        Unexpected character = (U+003D) before name, expected a character that can start a name, such as a letter, $, or _/usr/src/app/www/src/content/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx: Unexpected character = (U+003D) before name, expected a character that can start a name, such as a letter, $, or _
        ```

        エラーは、エラーのあるドキュメントが`/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx`にあることを示しています。それ以外に分かっているのは、どこかで`=`文字が問題を引き起こしているということだけです。素晴らしいですが、これはNRQLドキュメントであり、数十個の`=`文字があります。

        したがって、`yarn verify-mdx src/content/docs/new-relic-solutions/observability-maturity/uptime-performance-reliability/aqm-implementation-guide.mdx`を実行します。これは以下を返します：

        ```json

          "name": "284:227",
          "reason": "Unexpected character `=` (U+003D) before name, expected a character that can start a name, such as a letter, `$`, or `_`",
          "line": 284,
          "column": 227,
          "location": {
            "start": {
              "line": 284,
              "column": 227,
              "offset": 19129,
              "index": 1
            },
            "end": {
              "line": null,
              "column": null
            }
          },
          "source": "remark-mdx",
          "ruleId": "unexpected-character",
          "fatal": true
        }
        ```

        この場合、関連する情報は次のとおりです：

        ```json
        "line": 284,
        "column": 227,
        ```

        および

        ```json
        "source": "remark-mdx",
        "ruleId": "unexpected-character",
        "fatal": true
        ```

        これにより、284行目の227列目に予期しない文字があることがわかります。エラーの発生箇所が正確にわかるため、ドキュメントのそのセクションに移動してさらにトラブルシューティングを行うことができます。この場合、おそらくNRQLの例を引用符で囲むだけで済みます。
      </Collapser>

  <Collapser className="freq-link" id="" title="一般的な構文エラーを確認します。">
    変更されたファイルに、次のような一般的なMarkdown構文エラーがないか確認します：

    * ナビゲーションファイルのインデントの不一致

    * 誤ったフロントマターの構文
      * フロントマターのフィールドにアポストロフィやコロンがある場合は、問題を回避するためにそれらを引用符で囲みます。

    * 閉じ括弧またはタグの欠落

    * 形式が正しくない画像リンク

      * 各画像インポートステートメントの間に改行があることを確認してください。
      * 画像とそのファイル名パスの名前を変更する際は注意してください。不一致があると、ローカルビルド全体が失敗する可能性があります。
      * インポートされる画像ファイルを扱う場合は特に注意してください。

    * 不正な画像ファイル名

      * 画像ファイル名には、大文字と小文字の区別があります。大文字と小文字を間違えると、ドキュメント内の画像が欠落する原因になります。
      * ファイル名にエンコードされた値（％など）が含まれる画像は特に扱いにくい場合があるため、避けるようにしてください。
  </Collapser>

  <Collapser className="freq-link" id="restart-yarn" title="yarnを停止して再起動します">
    yarnを停止して再起動するには：

    1. ターミナルで、`/docs-website`ディレクトリにいることを確認します。
    2. yarnプロセスを中断するには、CONTROL+Cを押します（ターミナルがアクティブな場合）。
    3. localhost:8000で実行されているすべてのサービスを停止するには、次のコマンドを実行します：
       ```bash
       kill -9 $(lsof -i TCP:8000 | grep LISTEN | awk '{print $2}')
       ```
    4. 以下のコマンドを実行してyarnを再起動します：
       ```bash
       yarn clean && yarn && yarn start 
       ```
  </Collapser>

  <Collapser className="freq-link" id="check-branch" title="問題のあるブランチを特定します">
    どのブランチが問題を引き起こしているかを特定するには：

    1. ターミナルで、`docs-website`ディレクトリにいることを確認します。
    2. 必要に応じて、CONTROL+Cを押してyarnプロセスを中断します。
    3. GitHub Desktopで、ブランチに必要な変更をコミットし、developブランチに切り替えます。
    4. ターミナルに戻り、`yarn && yarn start`を実行します。

    developブランチからサイトが正しくビルドされるようになった場合、問題はブランチの変更にあります。Yarnを再度停止し、ブランチに戻ってトラブルシューティングを行ってください。
  </Collapser>

  <Collapser className="freq-link" id="clean-cache" title="ローカルキャッシュをクリアしてください。">
    ローカルキャッシュを削除するには、`yarn clean`を実行します。これにより次のビルドが遅くなるため、時間に余裕があることを確認してください！

    1. ターミナルで、docs-websiteディレクトリにいることを確認します。
    2. 必要に応じて、CONTROL+Cを押してyarnを停止します。
    3. `yarn clean && yarn && yarn start`を実行して、新しいビルドを開始してください。
  </Collapser>

  <Collapser className="freq-link" id="remove-cache" title="破損したキャッシュファイルを削除してください">
    場合によっては、.cacheディレクトリが破損している場合があります。このディレクトリはGitによって無視されるため、ブランチからブランチへと移動してもそのまま残ります。どのブランチにいるかに関係なくローカルビルドが失敗する場合は、これが問題である可能性があります。

    これを`/docs-website`ディレクトリから解決するには、`rm -rf .cache`を実行します。
  </Collapser>

  <Collapser className="freq-link" id="start-build" title="ゼロからビルドを開始します。">
    ビルドを最初から開始すると、すべてのnodeモジュール、非表示の.cacheフォルダー、およびローカルキャッシュが削除されます。これには実行に長い時間がかかり、約10～20分かかります。

    1. ターミナルで、docs-websiteディレクトリにいることを確認します。

    2. 必要に応じて、CONTROL+Cを押してyarnを停止します。

    3. `yarn reboot`を実行します（またはKeyboard Maestroコマンド`kknuke`\*を使用します）。

       \*`kknuke` Keyboard Maestroコマンドを使用する場合、すべてが完了したら、`yarn start`を実行してサイトを起動します。
  </Collapser>

  <Collapser className="freq-link" id="run-incognito" title="プライベートモードでローカルビルドを実行します">
    ローカルサイトはビルドされても、サイト内のページがビルドされないことがあります。この問題を解決するには、プライベートセッションまたはシークレットセッションでローカルビルドを実行してみてください。ブラウザのキャッシュをクリアすることも試してみてください。
  </Collapser>
</CollapserGroup>

## 必須のビルドチェックが失敗する [#check-fail]

### 問題

PRを作成すると、`required`チェックの1つがパスしません。

<Callout variant="tip" title="注記">
  オプションのチェックはリリースをブロックしないため、オプションのチェックが失敗した場合でもPRをマージして問題ありません。ただし、チェックをさらに調査したい場合は、ヘルプチャンネルにメッセージを送信して、ヒーローが失敗を調査できるようにすることができます。
</Callout>

### 解決

チェックが失敗した場合は、まずPRを閉じてから再度開いてみてください。

次に、チェックを再実行します：

1. PRに移動します。
2. **Details &gt; Re-run jobs**をクリックします。

これが機能しない場合は、チェックをリセットする必要があります。これにより、キャッシュの再ビルドが強制されます：

1. ローカルリポジトリで、ファイル`gatsby-config.js`を見つけます（またはVSCodeでCMD-Pを使用してすばやくジャンプします）。

2. コードの1行目と2行目を入れ替えます（Gatsby Buildチェックでキャッシュを再構築させるためだけであり、これらの行の順序は関係ありません）：

   ```js
   const fs = require('fs');
   const parse = require('rehype-parse');
   ```

3. ファイルを保存し、変更をPRにコミットしてください。

4. ビルドチェックを再実行します。

5. 非常に長い時間お待ちください。

## PRマージの競合 [#merge-conflict]

### 問題

ローカルブランチからPRをマージしようとすると、マージコンフリクトが発生します。

### 解決

マージ競合が発生した場合は、Githubデスクトップまたはブラウザで**Resolve conflict**をクリックし、競合を1行ずつ確認してください。マージ競合を修正した後は、必ず承認者にPRをレビューしてもらってください。

#### マージの競合の回避

マージ競合を回避するための推奨事項は次のとおりです：

* developまたはmainにマージする前に、**Fetch origin**をクリックして、developまたはmainの最新バージョンを確実にプルしてください。
* タクソノミーの変更に取り組んでいる場合は、マージコンフリクトをできるだけ早く修正してください。ブランチがしばらく放置されると、developからすぐに古くなり、予期しない問題が発生する可能性があります。
* 新着記事からマージの競合が発生した場合、それは`whats-new-ids.json`ファイル（サイトのビルド時に自動的に更新される）がすぐに古くなる可能性があるためです。<Callout variant="caution">`whats-new-ids.json`を変更するPRは絶対にマージしないでください。GitHub Desktopに`whats-new-ids.json`ファイルの変更が表示された場合は、ブランチにプッシュするのではなく、必ず破棄してください。これにより、他の人がこのファイルに関連するマージの競合に対処しなければならない可能性が低くなります。</Callout>

## ポート8000は利用できません [#local-site]

### 問題

`yarn start`を実行しようとすると、ターミナルは次のように応答します：

```bash
[output] Something is already
[output] running at port 8000. Would you like to run the app at another port instead?
```

### 解決

localhost:8000で実行されているすべてのサービスを停止するには、ターミナルで次のコマンドを実行します：

```bash
kill -9 $(lsof -i TCP:8000 | grep LISTEN | awk '{print $2}')
```

## リダイレクトリンクが404エラーをスローする [#redirect-404]

### 問題

ローカルビルドでリダイレクトリンクをクリックすると、404エラーが発生します。

### 解決

ローカルビルドでは、リダイレクトの読み込みに長い時間がかかります。リダイレクトをクリックしたら、404がスローされるまで待ち、その後約1～2分待ちます。しばらくするとリダイレクトされるはずです。リダイレクトされない場合は、マークダウン構文を確認して、リダイレクトが正しく設定されていることを確認してください。

Gatsbyビルドでリダイレクトをテストすることもできます。

## SSH認証の失敗 [#authentication-fail]

### 問題

リモートブランチにコミットをプッシュしようとすると、SSH認証エラーが発生します。

### 解決

GitHub Desktopのサインイン/サインアウトを行うと、認証の問題が解決する場合があります：

1. 上部のメニューバーで、**Preferences**に移動します。
2. サインアウトして、もう一度サインインします。

これが機能しない場合は、リモートブランチにコミットをプッシュしてみてください。それでも失敗する場合は、ターミナルを使用して手動でPRをプッシュしてみてください。たとえば、PR`second-kafka-pr-for-issue-11231`をプッシュするには、次のコマンドを実行します：

```bash
git push --set-upstream origin second-kafka-pr-for-issue-1123
```

SSHの問題がある場合、ターミナルは認証エラーメッセージを返します。このコマンドへの応答でパスフレーズのプロンプトが表示される場合、SSHが何らかの理由で混乱しています。パスフレーズを入力することで、通常の状態に戻るはずです。パスフレーズを思い出せない場合は、[この記事を確認してください](https://docs.github.com/en/github/authenticating-to-github/troubleshooting-ssh/recovering-your-ssh-key-passphrase)。
