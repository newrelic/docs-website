### 改善と強化

* セッションリプレイは、レガシーアーキテクチャーを使用するReact Nativeアプリでテキストをキャプチャするようになりました。`RCTTextView`によって描画されたテキストは、以前は空のビューとして記録されていました。現在は、新しいアーキテクチャーの`RCTParagraphComponentView`テキストと同じ方法でキャプチャおよびマスクされるようになりました。

### バグ修正

* セッションリプレイがブロックされたビューのコンテンツをアップロードする問題を修正しました。`nr-block`アクセシビリティ識別子でブロックされたビューは黒いボックスとして描画されていましたが、そのテキストは引き続きリプレイとともに送信され、黒以外の色であればボックスの上で読み取れる状態になっていました。ブロックされた画像ビューは、画像マスキングがオフの場合でも画像データを保持していました。ブロックされたビューは、キャプチャ時にテキスト、画像、サブビューのない空のボックスとして記録されるようになりました。画面上でブロックされたビューは、次の完全なスナップショットまで古いコンテンツを表示するのではなく、リプレイですぐに更新されるようになりました。この問題は7.7.10以前のバージョンに存在していました。
* アプリがネットワークrequestsを行っている間、通常はセッション開始から数秒以内に`+[NRMAHTTPUtilities addCrossProcessIdentifier:]`で発生するまれなクラッシュ（`SIGSEGV`、または認識されないセレクターの場合は`NSInvalidArgumentException`）を修正しました。インストゥルメントされたすべての`NSURLSession`リクエストは、ロックなしでエージェントのハーベスター設定とそのクロスプロセスIDを読み取っていました。同時に、ハーベストスレッドはその設定を置き換え、セッションの開始時にIDをクリアしていたため、リクエストが解放されたばかりのオブジェクトを使用する可能性がありました。現在は、どちらもスレッド間で安全に読み取りおよび置き換えが行われます。ハーベスト中に`+[NewRelic shutdown]`が呼び出された際の同様の競合も修正されました。この問題は7.7.10以前のバージョンに存在していました。
* エージェントが解析できない`/connect`レスポンスを受信した後に、ネットワークrequestsが記録されなくなる問題を修正しました。エージェントは次のハーベストまで空の設定を保存し、その期間に記録されたすべてのrequestsを破棄していました。エージェントは既存の設定を保持するようになりました。この問題は7.7.10以前のバージョンに存在していました。
* アプリのアップデート後に、デバイスに保存された処理済み例外がサーバーエラー「Failed to resolve data: MobileAppVersion」とともに破棄される問題を修正しました。保存された処理済み例外は、エージェントがアプリの新しいバージョンに接続する前、次のセッションの開始時にアップロードされていました。接続が完了した後にアップロードされるようになりました。この問題は、7.7.10以前のバージョンに存在していました。
* アプリのアップデート前に記録された処理済み例外が、新しいアプリバージョンで報告される問題を修正しました。保存された処理済み例外は、記録されたアプリバージョンでアップロードされるようになりました。この問題は、7.7.10以前のバージョンに存在していました。
* 新しいイベントシステム（`NRFeatureFlag_NewEventSystem`）が有効になっている場合に、`recordCustomEvent:`が予約済みイベントタイプ（`Mobile`、`MobileCrash`、`MobileRequest`、`MobileRequestError`、`MobileSession`、`MobileBreadcrumb`）を受け入れる問題を修正しました。デフォルトのイベントシステムはすでにこれらのタイプを拒否していたため、イベントが送信されるかどうかは機能フラグに依存していました。現在、両方のイベントシステムがそれらを拒否します。
* 単一のソース行が1 MB（`0x100000`）以上のコードをカバーしている場合、dSYMアップロード・ツール（`run-symbol-tool`）がdSYMをシンボル・マップに変換できない問題を修正しました。その際、ツールは完全なdSYMのアップロードにフォールバックしていました。現在は、これらの行をシンボル・マップに変換します。
