### 改良点

* Java 10

New RelicのJavaエージェントは、Java 10と完全に互換性を持つようになりました。JDKリリースとJavaエージェントの詳細については、[Explorers Hubのこちらのトピック](https://support.newrelic.com/s/hubtopic/aAX8W0000008ZWk/jdk-releases-and-the-java-agent)をご覧ください。

* Java 6とは互換性がありません。

JVMを利用している顧客に対し、イノベーションを継続し、新しい機能を効率的に提供するために、今回および今後のエージェントのバージョンはJava 6と互換性がありません。Java 6を実行している場合は、引き続きJavaエージェント4.3.0以前を使用できます。詳細については、[Explorers Hubのこのトピック](https://discuss.newrelic.com/t/with-support-for-java-10-new-relic-deprecates-java-6/57738)をご覧ください。

* Akka 2.5およびAkka HTTP 10.1

Javaエージェントは、Akka 2.5.xおよびAkka HTTP 10.1.xをサポートするようになりました。Akka HTTP呼び出しをNew Relicトランザクションとして表示し、Akkaアクター間のハンドオフを確認し、他のデータベースやサービスへの呼び出しを理解できるようになります。

* Solr 7

JavaエージェントはSolr 7.xをサポートするようになりました。New RelicのSolrサポートは、Solrサーバーへのデータベース呼び出しをレポートするだけでなく、Solrサーバー自体もモニターします。

既知の問題：Solr 7のJMX統計収集は、このリリースではサポートされていません。

* WebLogicデータソース

Javaエージェントは、「JVM」ページの「Datasource」タブにWebLogicのデータソースに関するヘルスデータを表示するようになりました。

### 修正

* JVMのロケール設定によっては、Javaエージェント4.3.0がデータを報告しない問題を修正しました。Javaエージェント4.3.0JVMのロケールが小数点の記号としてカンマを使用するように設定されている場合、イベントデータの送信に失敗しました。エージェントログにNumberFormatExceptionが表示されます。
* 将来の変更日を持つ拡張機能が使用された場合に、エージェントがクラスの再変換を継続的に誤って試行し、CPU負荷が大幅に増加するまれな問題を修正しました。
* 影響を受けるリクエストが再試行され、Javaエージェントがヘッダーデータを報告しなくなる原因となる、Mule計装で発生するning計装によるConcurrentModificationExceptionを修正しました。
* `enable_auto_app_naming`がtrueに設定され、`distributed_tracing.enabled`がtrueに設定されている場合に、すべてのディストリビューティッド（分散）トレーシングイベントをサンプリングする問題を修正しました。現在、エージェントで両方の設定が有効になっている場合、ディストリビューティッド（分散）トレーシングはオンになりません。
