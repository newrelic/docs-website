## 新機能と改善点

* Webflux 6 [1181](https://github.com/newrelic/newrelic-java-agent/pull/1181)のサポートを追加しました

* Spring JMS 6 [1088](https://github.com/newrelic/newrelic-java-agent/issues/1088)のサポートを追加しました

* Mongodb Reactive Streams [1164](https://github.com/newrelic/newrelic-java-agent/pull/1164)のサポートを追加しました

* Kafka Streams [1170](https://github.com/newrelic/newrelic-java-agent/pull/1170)のサポートを追加しました

  Kafka ストリームのサポートには、メトリクスとスパンの 2 つの種類があります。 メトリクスはデフォルトで有効になっていますが、スパンはデフォルトで無効になっています。 スパンズを有効にするには、 *newrelic.yml*設定の common セクションに以下を追加します。

```
common:
  class_transformer:
    kafka-streams-spans:
      enabled: true
```

* エラーフィンガープリント - 独自のエラー受信トレイグループ名を入力してください[1195](https://github.com/newrelic/newrelic-java-agent/pull/1195)

  エラー発生が適切にグループ化されていませんか？コールバック関数を使用して、独自のエラーフィンガープリントを設定します。ユーザー定義のprocを受け入れる新しいパブリックAPIメソッドが追加されました。procは検出されたエラーごとに呼び出され、文字列を返す場合は常に、その文字列がエラーのエラーグループ名として使用され、New RelicのErrors Inboxで行われるサーバー側のグループ化よりも優先されます。これにより、ユーザーはエラーのグループ化をより詳細に制御できるようになります。詳細については、「[API：エラーのグループ化](/docs/apm/agents/java-agent/api-guides/java-agent-api-register-error-group-callback-to-set-fingerprint/)」および「[APM：エラーのグループ化タブ](/docs/triage-inbox/apm-tab/)」のページをご覧ください。

* ユーザー追跡 - エラーをユーザー ID [1188](https://github.com/newrelic/newrelic-java-agent/pull/1188)に関連付けます

  エラーグループの影響を受けるユーザーの数を確認できるようになりました。ユーザーIDの文字列表現を受け入れ、そのユーザーIDを現在のトランザクションに関連付ける新しいパブリックAPIメソッドを使用して、エンドユーザーを識別します。トランザクションとエラーには、新しい`enduser.id`エージェント属性が関連付けられます。これにより、エージェントユーザーは、より優れたフィルタリング機能とアラート機能をサポートするために、トランザクションとエラーを特定のユーザーIDに属するものとしてタグ付けできるようになります。詳細については、\[Newrelic.setUserId ]\([https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName(java.lang.String)](https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName\(java.lang.String\))のドキュメントと、[Errors Inboxで影響を受けるユーザーを追跡する](/docs/triage-inbox/error-users-impacted/)ページを確認してください。

* 現場の外で`token.link()`呼び出すと、そのメソッドが非同期を開始するために計装されます[1140](https://github.com/newrelic/newrelic-java-agent/pull/1140)

* Kafka クライアントの計装には、ノードをリストするための新しいメトリクスがあります: `MessageBroker/Kafka/Nodes/&lt;node>` [1130](https://github.com/newrelic/newrelic-java-agent/pull/1130)

## 最新バージョンへのアップデート [#procedures]

現在使用中のJavaエージェントのバージョンを特定するには、`java -jar newrelic.jar -v`を実行します。Javaエージェントのバージョンがコンソールに出力されます。

次に、最新バージョンのJavaエージェントにアップデートするには、以下の手順に従います。

1. **すべて**の[Javaエージェントのルートディレクトリ](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent)を別の場所にバックアップします。そのディレクトリの名前を`NewRelic_Agent#.#.#`に変更します。ここで、`#.#.#`はエージェントのバージョン番号です。
2. [エージェントをダウンロードします。](/docs/release-notes/agent-release-notes/java-release-notes)
3. 新しいエージェントのダウンロードファイルを解凍し、`newrelic-api.jar`と`newrelic.jar`を元の[Javaエージェントのルートディレクトリ](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent)にコピーします。
4. 古い`newrelic.yml`とzipからダウンロードした新しい`newrelic.yml`を比較し、[必要に応じてファイルを更新します](#diff)。
5. Javaディスパッチャを再起動します。

Javaエージェントのアップデート後に問題が発生する場合は、バックアップしたNew Relicエージェントディレクトリから復元します。

## エージェント設定の差分のアップデート [#diff]

エージェントの新しいバージョンをリリースする際に、`newrelic.yml`に新しい設定を追加します。`diff`または別の差分ユーティリティを使用して変更内容を確認してから、新しい設定を古いファイルに追加できます。ライセンスキー、アプリ名、デフォルト設定の変更など、ファイルに対して行ったカスタマイズを上書きしないようにしてください。

たとえば、 Javaバージョン 7.10.0 および 7.11.0 のデフォルトの`newrelic.yml`ファイルを`diff`すると、コンソールに表示される結果は次のようになります。

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

この例では、これらの行はJavaエージェント バージョン 7.11.0 のデフォルトの`newrelic.yml`に追加されました。 7.11.0 以降に移行する場合は、これらの新しい行を元の`newrelic.yml`に追加する必要があります。
