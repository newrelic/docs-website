## v10.9.1

* **バグ修正：Action Controllerの計装は、コントローラークラスを識別できない場合にエラーにならなくなりました。**

  エージェントがリクエストのコントローラークラスを識別できなかった場合、`TypeError: no implicit conversion of nil into String`、次に`NoMethodError: undefined method 'finish' for nil`をログに記録し、そのリクエストのデータを記録しませんでした。これらのトランザクションは`Controller/(unknown)/<action>`という名前になり、正常に記録されるようになりました。[PR#3691](https://github.com/newrelic/newrelic-ruby-agent/pull/3691)

* **バグ修正：大きなペイロードを報告する際に`Parallel`ワーカーがハングするのを防止しました。**

  `parallel`の計装が有効になっている場合、`in_processes:`を使用する`Parallel.each`/`Parallel.map`が永久にハングする可能性がありました。各ワーカーは、エージェントが先に作成された兄弟プロセスのために登録したパイプの書き込み側を継承したため、それらのパイプはend-of-fileに到達できず、エージェントのパイプリスナースレッドはそれらのいずれかを待機してブロックされました。データがOSのパイプバッファを超えたワーカーは、終了時にブロックされていました。現在、エージェントはフォーク直後に親プロセスの各パイプの書き込み側を閉じるようになり、他のパイプにデータが待機している間にリスナーが単一のパイプでブロックされることはなくなりました。このバグを報告していただいた[@yayamochi](https://github.com/yayamochi)に感謝いたします。[Issue#3680](https://github.com/newrelic/newrelic-ruby-agent/issues/3680) [PR#3688](https://github.com/newrelic/newrelic-ruby-agent/pull/3688)

* **バグ修正：外形監視モニターからのrequestsでgRPC呼び出しが失敗しなくなりました。**

  外形監視モニターからのリクエストがgRPC呼び出しを行った場合、エージェントは呼び出しのメタデータに`X-NewRelic-Synthetics`を追加していました。gRPCは小文字のメタデータキーのみを許可するため、呼び出しで`ArgumentError: 'X-NewRelic-Synthetics' is an invalid header key`が発生しました。エージェントは、外形監視ヘッダーを小文字で送信するようになりました。また、gRPCサーバートランザクションは受信したメタデータから外形監視ヘッダーを読み取るようになったため、syntheticチェック中に呼び出されたgRPCサービスは、そのトレースと外形監視属性を記録します。[PR#3693](https://github.com/newrelic/newrelic-ruby-agent/pull/3693)
