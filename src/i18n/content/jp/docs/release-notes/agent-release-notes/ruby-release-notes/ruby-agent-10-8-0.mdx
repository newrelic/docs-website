## v10.8.0

* **機能：Google Cloud Runのワーカープールとジョブの一意のホスト名を報告します**

  [PR#3609](https://github.com/newrelic/newrelic-ruby-agent/pull/3609/)で追加されたCloud Runのホスト名サポートは、Cloud Run **Services**によって設定される環境変数である`K_REVISION`を通じてのみCloud Runを検出していました。エージェントは[`CLOUD_RUN_REVISION`](https://docs.cloud.google.com/run/docs/container-contract#env-vars)（ワーカープール）と`CLOUD_RUN_EXECUTION`（ジョブ）も認識するようになったため、`utilization.gcp_cloud_run.use_instance_as_host`はこれら3つのリソースタイプすべてに適用されるようになりました。`utilization.gcp_cloud_run.include_revision_in_host`が`true`の場合、ホスト名はこれらの変数のうち存在する方から構築されます — たとえば、ジョブの場合は`{CLOUD_RUN_EXECUTION}-{instance id}`です。[Issue#3651](https://github.com/newrelic/newrelic-ruby-agent/issues/3651) [PR#3652](https://github.com/newrelic/newrelic-ruby-agent/pull/3652)

* **機能：`browser_monitoring.version`設定オプションを追加**

  顧客は、新しい`browser_monitoring.version`設定オプションを設定することで、New Relicが挿入する正確なBrowserエージェントローダーのバージョンを固定できるようになりました。現在利用可能でサポートされているバージョンについては、[BrowserエージェントのEOLポリシー](https://docs.newrelic.com/docs/browser/browser-monitoring/getting-started/browser-agent-eol-policy/)をご覧ください。[PR#3663](https://github.com/newrelic/newrelic-ruby-agent/pull/3663)

* **機能：バックグラウンドジョブライブラリにspan.kindを追加**

  これで、バックグラウンドジョブライブラリの`produce`および`consume`の操作に`span.kind`属性が追加されます。これには、ActiveJob、Sidekiq、Resque、およびDelayedJobが含まれます。[PR#3636](https://github.com/newrelic/newrelic-ruby-agent/pull/3636)

* **バグ修正：prependモードで、DelayedJobの計装がすべてのワーカーで再インストールされなくなりました**

  DelayedJobの計装がprepend（デフォルト）を介してインストールされている場合、同じプロセス内で複数の`Delayed::Worker`を作成すると、エージェントは「Installing DelayedJob instrumentation」をログに記録し、追加のワーカーごとにプラグインを再度初期化していました。これは無害ですがノイズが多いものでした；現在は、既存のチェーン計装の動作に合わせて、プロセスごとに1回だけ実行されるようになりました。[PR#3654](https://github.com/newrelic/newrelic-ruby-agent/pull/3654)

* **バグ修正：許可リストに登録された設定値は大文字と小文字を区別しなくなりました。**

  以前は、許可リストに登録された設定オプションでは大文字と小文字の完全な一致が必要だったため、予期しない大文字と小文字の組み合わせの値 — たとえば`slow_sql.record_sql`に対する`OBFUSCATED`や`ObFuScAtEd`など — は、暗黙のうちにデフォルトにフォールバックしていました。許可リストに対して検証される設定オプションは、大文字と小文字を問わず値に一致するようになったため、どちらも`obfuscated`と同じように扱われます。[Issue#3613](https://github.com/newrelic/newrelic-ruby-agent/issues/3613) [PR#3645](https://github.com/newrelic/newrelic-ruby-agent/pull/3645)

* **バグ修正：Pumaが遅延読み込みされた場合にPumaの計装が機能するようになりました**

  `gem "puma", require: false`では、エージェントの依存関係チェックが実行されたときにPumaがまだロードされていなかったため、Pumaの計装のインストールに失敗していました。エージェントは`Puma::RackHandler`をPumaが存在する証拠として認識するようになり、この問題が修正されました。[Issue#3641](https://github.com/newrelic/newrelic-ruby-agent/issues/3641) [PR#3650](https://github.com/newrelic/newrelic-ruby-agent/pull/3650)
