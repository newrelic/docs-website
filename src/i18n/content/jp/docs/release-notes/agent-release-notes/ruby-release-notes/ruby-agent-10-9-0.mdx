## v10.9.0

* **機能：Continuous Profiling（プレビュー）**

  Continuous Profilingは、まだ一般提供されていない新しい機能です。エージェント側のコンポーネントコードは現在エージェントに存在しますが、一般提供リリースに先立って実際に使用するには、New Relicの営業担当者に連絡してプレビューに早期参加する必要があります。

  Continuous Profilingは、実行中のアプリケーションのRubyのコールスタックを繰り返しサンプリングしてNew Relicに報告するため、アプリケーションにコードを追加することなく、本番環境でどのメソッドが最もCPU時間を消費しているか（または最も多くのオブジェクトを割り当てているか）を確認できます。

  これを有効にするには、[`stackprof`](https://rubygems.org/gems/stackprof)および[`google-protobuf`](https://rubygems.org/gems/google-protobuf)のgemをアプリケーションの`Gemfile`に追加し、`profiling.enabled`を`true`に設定します：

  ```yaml
    profiling.enabled: true
  ```

  `profiling.enabled`のみを設定した場合、エージェントはプロセスの存続期間中、10ミリ秒ごとにCPU時間をサンプリングします。以下のオプションでその動作を調整できます：

  | 設定名                                    | デフォルト   | 行動                                                                                        |
  | -------------------------------------- | ------- | ----------------------------------------------------------------------------------------- |
  | profiling.enabled                      | `false` | `true`の場合、エージェントは継続的なプロファイリングデータを収集し、レポートします。                                             |
  | profiling.include                      | `cpu`   | サンプリング対象：CPU時間の場合は`cpu`、オブジェクト割り当ての場合は`object`。                                           |
  | profiling.sample\_period               | `0.01`  | スタックサンプル間の秒数。`profiling.include`が`cpu`の場合にのみ使用されます。0.000001から0.999999の間である必要があります。        |
  | profiling.object\_allocation\_interval | `10000` | スタックサンプル間のオブジェクト割り当て。`profiling.include`が`object`の場合にのみ使用されます。1,000から999,999の間である必要があります。 |
  | profiling.delay                        | `0`     | プロファイリングが開始される前に待機するミリ秒数です。`0` の場合はすぐに開始されます。                                             |
  | profiling.duration                     | `0`     | 自動的に停止する前にプロファイリングを行うミリ秒数です。`0` の場合は、プロセスが終了するまでプロファイリングを行います。                            |

  [PR#3617](https://github.com/newrelic/newrelic-ruby-agent/pull/3617)

* **機能：Dalli 5.1.1のサポートの追加**

  Dalli 5.1.1では、エージェントによってインストゥルメントされた一部のメソッドに引数が追加されました。これにより、マルチキー操作で`ArgumentError`が発生したり、リクエストオプションが暗黙のうちに破棄されたりする可能性がありました。現在、エージェントはこれらのメソッドに対して可変数の位置引数とキーワード引数を受け入れ、転送します。[PR#3683](https://github.com/newrelic/newrelic-ruby-agent/pull/3683)
