## v9.1.0

エージェントのバージョン9.1.0は、2つの新しい[Errors Inbox](https://docs.newrelic.com/docs/triage-inbox/errors-inbox/)機能（エラーのフィンガープリントとユーザー追跡）をサポートし、Amazon Timestreamデータストアを識別し、Sidekiq使用時にエージェントログからディストリビューティッド（分散）トレーシングの警告を削除し、バグを修正し、最近リリースされたJRuby 9.4.2.0でテストされています。

* **機能：エラーのフィンガープリント — 独自のErrors Inboxグループ名を提供する**

  エラー発生が適切にグループ化されていませんか？コールバック関数を使用して、独自のエラーフィンガープリントを設定します。ユーザー定義のprocを受け入れる新しい`set_error_group_callback`パブリックAPIメソッドが追加されました。procは検出されたエラーごとに呼び出され、文字列を返す場合は常に、その文字列がエラーのグループ名として使用され、New RelicのErrors Inboxで行われるサーバー側のグループ化よりも優先されます。これにより、ユーザーはエラーのグループ化をより詳細に制御できるようになります。

  顧客が定義したprocは、正確に1つの入力引数（ハッシュ）を受け取ることが想定されます。ハッシュには以下が含まれます。

  | 鍵                    | 価値                                                    |
  | -------------------- | ----------------------------------------------------- |
  | `:error`             | Rubyエラークラスのインスタンス。`#class`、`#message`を提供 `#backtrace` |
  | `:customAttributes`  | 現在のトランザクションの顧客定義のカスタムアトリビュート                          |
  | `:'request.uri'`     | 利用可能な場合、現在のリクエストURI                                   |
  | `:'http.statusCode'` | 利用可能な場合、HTTPステータスコード（200、404など）                       |
  | `:'http.method'`     | 利用可能な場合、HTTPメソッド（GET、PUTなど）                           |
  | `:'error.expected'`  | 予期されていたエラー（true）かどうか（false）                           |
  | `:'options'`         | オプションのハッシュが渡されました `NewRelic::Agent.notice_error`      |

  コールバックは、New Relicエージェントの初期化ごとに1回設定するだけで済みます。

  使用例：

  ```
  proc = proc { |hash| "Access" if hash[:'http.statusCode'] == 401 }
  NewRelic::Agent.set_error_group_callback(proc)
  ```

* **機能：ユーザー追跡 - エラーをユーザーIDに関連付ける**

  エラーグループの影響を受けるユーザーの数を確認できるようになりました。ユーザーIDの文字列表現を受け入れ、そのユーザーIDを現在のトランザクションに関連付ける新しい`set_user_id`パブリックAPIメソッドを使用してエンドユーザーを識別します。トランザクションとエラーには、新しい`enduser.id`エージェント属性が関連付けられます。これにより、エージェントユーザーは、より優れたフィルタリング機能とアラート機能をサポートして、トランザクションとエラーを特定のユーザーIDに属するものとしてタグ付けできるようになります。

* **amazon\_timestream ARアダプターが使用されている場合にAmazon Timestreamを識別**

  エージェントが[activerecord-amazon-timestream-adapter](https://rubygems.org/gems/activerecord-amazon-timestream-adapter) gemの使用を検知すると、データストアを&quot;Timestream&quot;として識別するようになりました。この機能強化に貢献していただいた[@wagner](https://github.com/wagner)に感謝いたします！[PR#1872](https://github.com/newrelic/newrelic-ruby-agent/pull/1872)

* **バグ修正：Sidekiqにヘッダーが存在しない場合、エージェントログからディストリビューティッド（分散）トレーシング関連の警告を削除**

  以前は、エージェントがSidekiqジョブから空のディストリビューティッド（分散）トレーシングヘッダーを受け入れようとするたびに、`newrelic_agent.log`に警告をログに記録していたため、過剰な数の警告が発生する可能性がありました。現在、Sidekiqを使用する場合、エージェントはこれらの警告を生成しなくなりました。[PR#1834](https://github.com/newrelic/newrelic-ruby-agent/pull/1834)

* **バグ修正：リクエストヘッダーを人間が読める形式のオブジェクトではなく、デバッグレベルのログに記録するようにしました。**

  以前は、`NewRelic::Agent::Transaction::DistributedTracers#log_request_headers`が呼び出されたときに、エージェントが引数として`NewRelic::Agent::HTTPClients::AbstractRequest`クラスの子クラスを受け取ることがありました。これにより、リクエストヘッダーを出力するデバッグレベルのログメッセージに、人間が読める形式のオブジェクト（例：`#<NewRelic::Agent::HTTPClients::HTTPClientRequest:0x00007fd0dda983e0>`）がリクエストヘッダーの代わりに表示されていました。これで、リクエストヘッダーのハッシュは常にログに記録されるようになります。[PR#1839](https://github.com/newrelic/newrelic-ruby-agent/pull/1839)

* **バグ修正：Action Controller計装でログに記録される未定義メソッド `controller_path` を修正しました**

  以前は、コントローラークラスが`controller_path`に応答しない場合、Action Controllerの計装でメトリクス名を決定しようとする際に、エージェントがエラーをログに記録することがありました。この問題は解決され、クラスが応答しない限り、エージェントはこのメソッドを呼び出さなくなりました。この問題についてお知らせいただいた[@gsar](https://github.com/gsar)に感謝します。[PR#1844](https://github.com/newrelic/newrelic-ruby-agent/pull/1844)

* **バグ修正：非同期トランザクション中のTransaction#finish例外を修正し、関連する警告のログレベルを下げました。**

  以前は、トランザクションの完了時に親のないセグメントが未完了の場合、エージェントは致命的ではないエラーを発生させていました。このエラーは、`warn`レベルのログメッセージを構築しているときに発生しました。Threadの計装がデフォルトでオンになったため、このログメッセージはより頻繁に出力されるようになり、懸念は少なくなりました。トランザクション内にThread、Fiber、またはconcurrent-rubyセグメントが見られる場合、メッセージは`debug`レベルに引き下げられます。issueを作成していただいた[@NielsKSchjoedt](https://github.com/NielsKSchjoedt)と、ソリューションをテストしていただいた[@boomer196](https://github.com/boomer196)に感謝いたします。[PR#1876](https://github.com/newrelic/newrelic-ruby-agent/pull/1876)

* **CI：JRuby 9.4.2.0をターゲットに設定しました**

  現在、エージェントはJRuby 9.4.2.0に対して積極的にテストされています。注：このリリースには、JRuby向けのCI関連以外の変更は含まれていません。古いエージェントバージョンは引き続き新しいJRubyで動作し、最新のエージェントバージョンは引き続き古いJRubyで動作することが想定されています。
