## v8.7.0

* **APM logs-in-contextのログ転送がデフォルトで有効に**

  自動アプリケーションログ転送がデフォルトで有効になりました。このバージョンのエージェントは、エンリッチされたアプリケーションログをNew Relicに自動的に送信します。この機能の詳細については[こちら](https://docs.newrelic.com/docs/apm/new-relic-apm/getting-started/get-started-logs-context/)をご覧ください。また、追加の設定オプションについては[こちら](https://docs.newrelic.com/docs/logs/logs-context/configure-logs-context-ruby)をご覧ください。アカウントごとにログの取り込みをオン/オフに切り替える方法については、[こちら](https://docs.newrelic.com/docs/logs/logs-context/disable-automatic-logging)をご覧ください。

* **非同期サポートおよびスレッドの計装の改善**

  以前は、エージェントはすでに実行中のトランザクションの内部で作成されたスレッド内で、イベントとメトリクスを記録できませんでした。このリリースには、マルチスレッドアプリケーションによるスレッドの自動計装をサポートする2つの新しい設定オプションが含まれています。新しい設定オプションである`instrumentation.thread.tracing`（デフォルトでは無効）が導入されました。これを有効にすると、エージェントはアプリケーションによって作成されたすべてのスレッド内にNew Relicトレースを挿入できるようになります。一部のスレッドのみをNew Relicによってインストゥルメントされた状態にしたいアプリケーションをサポートするために、New Relicの計装を含むスレッドを作成する新しいクラス`NewRelic::TracedThread`を利用できます。詳細については、[APIドキュメント](https://www.rubydoc.info/gems/newrelic_rpm/NewRelic)をご覧ください。

* **内部的に`Object.const_get`を利用し、 `Object.const_defined?`**

  文字列からクラス定数を動的にチェックしたり、そのハンドルを取得したりする際は、可能な限り`Object`クラスの組み込みメソッドを活用して、よりシンプルでパフォーマンスの高い操作を実現してください。すべてのJRubyおよびv2.5以下のCRubyでは、指定されたものとは異なるネームスペースから意図しない定数が生成される可能性があるため、`Object`が提供できる以上のサポートが少し必要になります。しかし、その他のすべてのRuby、そして入力される文字列値を100％信頼できるコンテキストにおけるRubyの場合であっても、`Object`クラスのメソッドを活用してそのメリットを享受してください。

* **`rake.tasks`の設定に関するドキュメントを明確化**

  デフォルトの`newrelic.yml`ファイル内の`rake.tasks`の説明、および[New Relic Rubyエージェント設定ドキュメント](https://docs.newrelic.com/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration#rake-tasks)が更新され、その動作と使用方法が明確になりました。現在、ドキュメントには次のように記載されています：

  > 自動的に計装するRakeタスクの配列を指定します。この設定オプションは、配列を正規表現リストに変換します。デフォルトで全てのタスクを許可したい場合は、`rake.tasks: [.+]`を使用してください。このリストに追加されない限り、Rakeタスクはインストゥルメントされません。詳細については、(New RelicのRake計装に関するドキュメント)\[/docs/apm/agents/ruby-agent/background-jobs/rake-instrumentation]を参照してください。

  これらの変更を提案していただいた@robotfelixに感謝いたします。

* **配列の設定を配列に変換する環境変数の設定を有効にします。**

  この変更以前は、カンマ区切りのリストが環境変数として渡された場合、`newrelic_agent.log`にエラーが出力され、値として文字列が設定されていました。現在は、配列が正確に型変換されます。

* **バグ修正：TransactionEventsが期待されるレートでサンプリングされるようにしました**

  TransactionEventAggregator内の`transaction_events.max_samples_stored`のキャパシティ値が、想定される収集サイクルの間隔と一致しなかったため、TransactionEventsが過剰にサンプリングされていました。このバグ修正は、名前が変更された`transaction_events*`の設定に対して間隔とキャパシティが想定通りに機能するように、[#952](https://github.com/newrelic/newrelic-ruby-agent/pull/952)で行われた更新に基づいています。

* **バグ修正：トランザクションの外部で作成された場合にエラーイベントの属性が欠落する問題**

  以前は、トランザクションのスコープ外でnotice\_errorを呼び出すことによって作成されたエラーイベントに対し、エージェントは優先度を割り当てていませんでした。これにより、エラーイベントのバッファが満杯になったときにサンプリングの問題が発生し、newrelic\_agent.logに`NoMethodError: undefined method '<' for nil:NilClass`が出力されていました。このバグ修正により、エラーイベントには常に優先度が割り当てられるようになり、エージェントがこれらのエラーイベントを正しくサンプリングできるようになります。この問題を知らせていただいた@olleolleolleに感謝いたします。

## サポートステートメント

New Relicでは、エージェントを定期的に、少なくとも3か月ごとにアップグレードすることを推奨します。このリリース以降、サポートされる最も古いバージョンは[5.7.0.350](https://docs.newrelic.com/docs/release-notes/agent-release-notes/ruby-release-notes/ruby-agent-570350)です。
