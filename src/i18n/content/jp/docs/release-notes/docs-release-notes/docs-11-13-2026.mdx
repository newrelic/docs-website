### 新しいドキュメント

* CocoaPodsを使用しているiOSチームが、計装を失ったりゼロから再設定したりすることなくSwiftパッケージマネージャに移行できるように、[CocoaPodsからのiOSエージェントの移行](/docs/mobile-monitoring/new-relic-mobile-ios/installation/migrate-from-cocoapods)を追加しました。
* 古いOCIログフォワーダー設定を実行しているユーザーが、現在の機能やセキュリティ修正にアクセスするための明確なアップグレードパスを利用できるように、[『OCIログ転送インテグレーションのアップグレード』](/docs/logs/forward-logs/oci-log-forwarder-upgrade)を追加しました。
* チームがカスタム設定に依存することなく完全なデータベースのオブザーバビリティを設定できるように、LinuxおよびWindows上のAzure Managed インスタンスとAzure SQL データベースをカバーする[NRDOTを使用したMicrosoft SQL Serverの監視](/docs/opentelemetry/db360/mssql/introduction)を追加しました。

### 主な変更点

* ユーザーが1つの大きなページを検索するのではなく、必要な設定に直接移動できるように、[『Node.jsエージェントの設定』](/docs/apm/agents/nodejs-agent/installation-configuration/nodejs-agent-configuration)を、一般設定、属性、ロギング、トレース、エラー収集、ブラウザ監視、およびAIモニタリングのトピック別のページに再構築しました。
* 管理者がコア計算とは独立して高度な計算コストを制御できるように、各メーターに個別の適用ポリシーと通知設定を設け、コアCCUに加えて高度なCCUの予算を対象とするように、[Compute User Limits \[計算ユーザー制限\]](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/compute-budgets/compute-user-limits)を更新しました。
* Valkeyのメトリクスを対象とするダッシュボードのクエリとアラート条件が、空の結果ではなくデータを返すように、修正されたメトリクス名で[『Google Memorystore for Valkey』](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-memorystore-valkey)を更新しました。
* アクセス権を設定する際の設定ミスを防ぐため、Billing \[請求] ユーザーロールがアカウントスコープであることを正しく識別し、Organization \[組織] マネージャーの機能にBilling \[請求] を追加するように、[ユーザーとアクセス管理の重要な概念](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts)を更新しました。
* Azure App Servicesにデプロイする際にユーザーが直面する試行錯誤を減らすため、より明確なAzureホスティングのガイダンスを追加して、[Microsoft Azure App Services上のNode.jsエージェント](/docs/apm/agents/nodejs-agent/hosting-services/nodejs-agent-microsoft-azure)を更新しました。
* 以前は欠落していた手順をカバーするために、拡張されたPipeline Control Gatewayの設定ガイダンスを使用して、[エージェント設定の変更](/docs/new-relic-control/pipeline-control/gateway/modify-agent-configuration)を更新しました。
* このメトリクスはレシーバーによって収集されず、その存在によりユーザーが届かないデータを期待する原因となっていたため、コレクターの設定から`kafka.partition.replicas.total`を削除するように[『OpenTelemetryを使用してKubernetes上のセルフマネージドKafkaをモニターする』](/docs/opentelemetry/integrations/kafka/kubernetes-self-managed)を更新しました。
* v14.11.0でpure-JS実装に置き換えられた非推奨の`@newrelic/native-metrics`パッケージを参照するコンテンツを削除するために、[Node.js VMの測定](/docs/apm/agents/nodejs-agent/extend-your-instrumentation/nodejs-vm-measurements)を更新しました。
* FedRAMP認定サービスを評価している顧客が正確なコンプライアンス情報を得られるように、最新の認証の詳細で[FedRAMP](/docs/security/security-privacy/compliance/certificates-standards-regulations/fedramp)を更新しました。
* チャートタイプがサポートされるようになったため、ツリーマップがいつ適切な視覚化であるか、また他のチャートタイプとどのように異なるかをユーザーが理解できるように、[Chart types \[チャートタイプ\]](/docs/query-your-data/explore-query-data/use-charts/chart-types)にツリーマップのチャートタイプのドキュメントを追加しました。
* ユーザーがエージェントが検証済みであることを把握し、安心してランタイムをアップグレードできるように、.NET 11 GAのサポートを確認するために[.NETエージェントの互換性と要件](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements)を更新しました。

### マイナーチェンジ

* 既存の例に従っているユーザーが非推奨のメソッドや古いオプション名に遭遇しないように、現在のエージェントAPIに合わせるため、APIガイド、属性、バックグラウンドジョブ、設定、およびディストリビューティッド（分散）トレーシングのページ全体で[Rubyエージェントのドキュメント](/docs/apm/agents/ruby-agent/getting-started/introduction-new-relic-ruby)を更新しました。
* 関連するタグの下にツールをグループ化するように[『MCPツールリファレンス』](/docs/agentic-ai/mcp/tool-reference)を更新し、リスト全体をスキャンしなくても、特定のユースケースに適したツールを見つけやすくしました。
* ユーザーがワークフローの以前のバージョンをレビュー、比較、および元に戻すことができるように、ワークフローエディターでのバージョン履歴のサポートを追加して[『ワークフローの管理』](/docs/workflow-automation/manage-workflows/managing-workflow)を更新しました。
* より現実的なワークフローの設定に対応するため、ワークフローの入力制限が1,000文字から3,000文字に増加したことを反映するように、[ワークフローの制限](/docs/workflow-automation/limitations-and-faq/workflow-limits)を更新しました。
* 複雑なアラート条件を構築するユーザーが適用される制約を把握できるように、ネストされた集計を使用するNRQLアラート条件のファセット制限を明確にするため、[アラートルールと制限](/docs/alerts/admin/rules-limits-alerts/)を更新しました。

### 新機能

* [Compute User Limits \[計算ユーザー制限\] が高度な計算を対象とするようになりました](/whats-new/2026/11/whats-new-11-03-compute-user-limits-accu)：ユーザーごとに独立したコアCCUと高度なCCUの予算を設定し、各メーターの制限を個別に適用します。
* [GitHub CopilotのChange Tracking (変更追跡機能)](/whats-new/2026/11/whats-new-11-09-change-tracking-github-copilot)：デプロイメントをプルリクエストにリンクし、リグレッションが発生した際に自動化されたGitHub Copilotの修正ワークフローをトリガーします。
* [Gap Analysis MCPツールを使用して不足しているNew Relicの計装を検出する](/whats-new/2026/11/whats-new-11-09-gap-analysis-mcp-tool)：ローカルのリポジトリファイルをスキャンして、APMエージェント、Browserエージェント、設定ファイル、およびCI/CDのChange Tracking (変更追跡機能) のワークフローにおけるギャップを特定します。
