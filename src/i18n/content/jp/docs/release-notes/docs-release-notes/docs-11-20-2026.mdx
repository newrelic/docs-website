### 新しいドキュメント

* Claude Code、Cursor、GitHub Copilot、CodexなどのAIコーディングエージェントが適切なインストール手順を見つけ、インストールを検証し、コンテキストにライセンスキーを含めないようにするための、コピーアンドペースト可能なプロンプトを含む[AIコーディングエージェントを使用したNew Relicのインストール](/docs/new-relic-solutions/get-started/install-with-ai)を追加しました。
* 詳細な回答が概要ページやセットアップページではなく1か所にまとまるように、サポートされているコレクターのバージョン、エクスポート形式、自動検出、自動分類、およびアタッチされたコレクターを網羅した[CollectorオブザーバビリティFAQ](/docs/opentelemetry/collector-observability/collector-observability-faq)を追加しました。
* ロギング、プロキシ、ステータスサーバー、ヘルスチェック、自己計装、OCIレジストリオプションなど、変更可能なAgent Control設定とそのデフォルト値をリストした[Agent Control設定リファレンス](/docs/new-relic-control/agent-control/configuration-reference)を追加しました。
* AzureでMySQLまたはPostgreSQLを実行しているチームがNRDOT Collectorを使用してデータベースのオブザーバビリティをセットアップできるように、[Azureフレキシブルサーバーを使用したMySQL監視のためのNRDOTのインストールと構成](/docs/opentelemetry/db360/mysql/azure)および[Azureフレキシブルサーバーを使用したPostgreSQL監視のためのNRDOTのインストールと構成](/docs/opentelemetry/db360/postgresql/azure)を追加しました。
* eMudhra認証局の侵害がログインテグレーション（Fluent Bit出力プラグイン、infrastructureエージェントのログ転送、Helmチャート）に与える影響について記載した[セキュリティ情報 NR26-13](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-13)を追加しました。
* eMudhra認証局の侵害がnri-bundleおよび関連するHelmチャートを含むKubernetesインテグレーションに与える影響に関する、[セキュリティ情報NR26-14](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-14)を追加しました。
* eMudhra認証局の侵害がinfrastructureエージェントおよびオンホストインテグレーションに与える影響に関する、[セキュリティ情報NR26-15](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-15)を追加しました。
* OpenJDK Java4Shellリモートコード実行の脆弱性（CVE-2026-114938）に関する[Security bulletin NR26-16](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-16)を追加し、影響を受けるNew Relicコンポーネントの対応事項を記載しました。
* Ruby2Shellのメモリ破損の脆弱性（CVE-2026-132825）およびそれが`newrelic-fluentd-docker`、`newrelic/fluentd`、`k8s-golang-apm-linkage-demo`のコンテナイメージに与える影響に関する[セキュリティ情報 NR26-17](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-17)を追加し、Rubyエージェントを使用している顧客は対応不要であることを記載しました。

### 主な変更点

* [Collectorのオブザーバビリティ](/docs/opentelemetry/collector-observability/collector-observability)が一般提供されました。概要および[セットアップ](/docs/opentelemetry/collector-observability/collector-observability-setup)ページを更新し、新しいスクリーンショットと、詳細な説明が記載された新しい[CollectorのオブザーバビリティFAQ](/docs/opentelemetry/collector-observability/collector-observability-faq)へのリンクを追加しました。
* どのrequestsが自動的にトレースされるか、トレースの相関付けを有効にするために必要なこと、およびトレーシングをオフにする方法を説明するために、[New Relic iOSエージェントとディストリビューティッド（分散）トレーシング](/docs/mobile-monitoring/new-relic-mobile-ios/get-started/new-relic-ios-and-dt)および[New Relic Androidエージェントとディストリビューティッド（分散）トレーシング](/docs/mobile-monitoring/new-relic-mobile-android/get-started/new-relic-android-and-dt)を書き直しました。両方のページから古い動画を削除しました。
* 管理者が各デフォルトロールで付与される権限を確認できるように、フリート、シークレット、Lensコネクタ、AIエージェント、NRQLマクロ、ノートブック、アラートポリシー、ダッシュボードのロールを含む、組織、アカウント、エンティティスコープの標準ロールの表を追加して、[ユーザーおよびアクセス管理の重要な概念](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts)を更新しました。
* PHPおよびNode.jsのアドバイザリに加えてJava4Shellのアドバイザリ（CVE-2026-114938）を網羅し、新しい<DNT>Exposure</DNT>および<DNT>How to fix</DNT>のサマリーカードについて説明するように、[Exposure check \[露出チェック\]](/docs/vulnerability-management/exposure-check)を更新しました。これにより、ユーザーは影響を受けるJavaバージョンを実行しているAPMエンティティを見つけることができます。
* コンパイルできなかった例や、iOS、Android、およびReact Nativeでのエージェントの動作と一致しなかったタグルールを修正し、パスワードフィールドがマスクされたままになることを明確にするために、モバイルセッションリプレイの[プライバシー設定の構成](/docs/mobile-monitoring/mobile-monitoring-ui/mobile-session-replay/configure-privacy-settings)を更新しました。
* サポート対象のMCPクライアントとしてCursorを追加し、ユーザーAPIキーを使用した認証の要件、アクセス、および`mcp.json`設定を含めるように、[MCPセットアップ](/docs/agentic-ai/mcp/setup)と[MCPの概要](/docs/agentic-ai/mcp/overview)を更新しました。
* チームがプロンプトを記述することなく、Slackの集計スレッドから調査を開始できるように、集計通知の<DNT>**Investigate with AI**</DNT> button \[ボタン]を使用して[AutopilotをSlackに接続する](/docs/agentic-ai/autopilot/connect-to-slack)を更新しました。
* `reportLogs`のデフォルトが`"false"`ではなく`"auto"`になったこと、およびデフォルトの`fileRegex`が`".*\\.log$"`になったことを反映するように、[eBPFログ](/docs/ebpf/logs)、[Kubernetesインストレーション](/docs/ebpf/k8s-installation)、および[Linuxインストレーション](/docs/ebpf/linux-installation)を更新しました。
* ユーザーが比率ベースのサンプリングを構成できるように、Rubyエージェントの`trace_id_ratio_based`サンプラー設定を使用して、[Rubyエージェントのディストリビューティッド（分散）トレーシング設定](/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration-distributed-tracing-settings)および[ディストリビューティッド（分散）トレースサンプリング](/docs/apm/distributed-tracing/distributed-trace-sampling)を更新しました。
* Googleが定義していないか、アルファ版または非推奨としてリストしているため、New Relicが収集しないメトリクスを[Google BigQuery](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-bigquery-monitoring-integration)、[Google Cloud Pub/Sub](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-pubsub-monitoring-integration)、および[Google Cloud Storage](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-storage-monitoring-integration)のインテグレーションページから削除しました。

### マイナーチェンジ

* 各サポートケースのステータスの意味を説明するケースステータス定義表を追加して、[ヘルプとサポートの検索](/docs/new-relic-solutions/solve-common-issues/find-help-get-support)を更新しました。
* [MCPツールリファレンス](/docs/agentic-ai/mcp/tool-reference)を更新し、読み取り専用の`get_retention_policy_and_namespaces`、`get_user_id`、`list_support_cases`ツールとKafka Autopilotスキルを追加しました。
* ユーザーを削除するよりも、MCPサーバー権限を持つすべてのグループからユーザーを削除する方が、1人のユーザーのアクセス権を取り消す方法として影響が少ないことを説明するように、[MCPの概要](/docs/agentic-ai/mcp/overview)を更新しました。
* Agent Controlがオンホストインテグレーションに対して`unknown`のヘルスステータスを報告する理由と、`enable_file_logging`の出力ファイルがローテーションされないことを説明するように、[Agent types \[エージェントタイプ\]](/docs/new-relic-control/agent-control/agent-types)を更新しました。
* Javaエージェント v9.4.0以降を必須とし、`sql_metadata_comments.enabled`設定を表示するように、[NRDOTを使用したデータベースサービスの識別](/docs/opentelemetry/db360/capabilities/db-apm)を更新しました。
* サポートされているMongoDBおよびAzure Cosmos DB for MongoDBのバージョン（4.2以降）を記載して、[コネクタのセットアップ](/docs/new-relic-lens/set-up-connectors)を更新しました。
* メトリクスごとのカーディナリティ制限をアカウントの制限まで引き上げることができることを明確にするために、[カーディナリティ管理](/docs/data-apis/ingest-apis/metric-api/cardinality-management)を更新しました。
* KPIデータはKPIを作成した時点から開始され、New Relicはバックフィルを行わないことを明確にするために、[インテリジェントワークロードKPI](/docs/new-relic-solutions/new-relic-one/workloads/intelligent-workload-kpis)を更新しました。
* DataflowテンプレートにはJava 11以降が必要であることを明記して、[Google Cloud Platformからのログの転送](/docs/logs/forward-logs/google-cloud-platform-log-forwarding)を更新しました。
* [Node.jsエージェント](/docs/apm/agents/nodejs-agent/getting-started/compatibility-requirements-nodejs-agent)および[.NETエージェント](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements)の互換性と要件に関するページを、最新の検証済みライブラリバージョンで更新しました。
