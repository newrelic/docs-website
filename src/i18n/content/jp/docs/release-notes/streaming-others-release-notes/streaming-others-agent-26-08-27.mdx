### 追加した

* `VideoAction`/`VideoAdAction`イベントに`contentIsLive`属性を追加し、設定時にVideoノードの`content.live`フィールドを反映するようにしました — これにより、Rokuは標準のクロスエージェントのビデオデータモデルに準拠します。

### 修理済み

* ビデオの一時停止中にリバッファリングが完了した場合、再生が再開されるまで`CONTENT_BUFFER_END`が遅延する問題を修正しました。ユーザーが再生を再開したかどうかに関係なく、バッファリングが実際に回復するとすぐにイベントが発生するようになりました — これにより、バッファリング中の一時停止シナリオにおいて過剰に報告されていたバッファリング時間と合計リバッファリング時間が修正されます。
* ハートビートを含むすべての`VideoAction`/`VideoAdAction`イベントに`errorCode`/`errorMessage`/`backtrace`が付与される問題を修正しました — RokuのVideoノードはエラーがない場合でも（`invalid`ではなく）`errorCode: 0`を報告するため、エラーではないすべてのイベントでエラー形式の属性が漏洩していました（NR-606648）。これらは実際のエラーイベントにのみ表示されるようになりました。
* 4.2.0での導入以来、MediaTailor SSAIデバッグロギング（`nrActivateLogging`）がサイレントに抑制されていた問題を修正しました — `callFunc`を介して`nrCheckLoggingState()`に渡された余分な引数により、ロギングゲートを評価する代わりに呼び出しがno-opになり、ロギング状態に関係なくMediaTailorのデバッグ出力が生成されることはありませんでした。
