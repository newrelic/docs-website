### 新機能

* `secrets_providers`設定キーの名前を`value_providers`に変更しました。古いキーは下位互換性のために保持されます。
* OnHost：RedHat 10のサポートを追加しました。
* K8s：Kubernetes ConfigMapから変数を解決するための新しい`nr-kubecm`値プロバイダーを追加しました。
* `chart_values.global` agentTypesでは引き続きサポートされていますが、非推奨です。引き続き、以下からグローバルを設定できます `chart_values.[chart-name].global`
* Linux：パッケージマネージャ（apt、yum、zypper）を自動検出して`newrelic-agent-control`を削除する、パッケージに同梱された`uninstall.sh`スクリプトを追加しました。

### バグ修正

* オンホスト：eBPFエージェントは、ステータスログを`/etc/newrelic-ebpf-agent`の代わりにAC管理のファイルシステムディレクトリ配下に書き込むようになりました。
* On-host：無関係なプロセスによって再利用されたPIDを古いPIDファイルが保持していた場合に発生する、誤った&quot;already running&quot;起動エラーを修正しました。
* 初期スーパーバイザーの起動失敗時を含め、エージェントタイプに`health:`ブロックが定義されていないサブエージェントの`Health`レポート（OpAMPおよびステータスサーバー）を抑制しました。
* On-host：エージェントタイプが新しいバージョンにアップグレードされる際、古いバージョンで宣言された古いファイルシステムエントリは、エージェントディレクトリ全体を消去するのではなく、差分によって削除されるようになりました；サブエージェントのOpAMPインスタンスIDは、バージョンの更新後も保持されます。
* K8s：サブエージェントタイプが新しいバージョンにアップグレードされる際、OpAMPインスタンスIDはアップグレード後も保持されるようになりました；以前は、エージェント名が変更されたかどうかに関係なく、タイプが変更されるたびにfleet-data ConfigMapが削除されていたため、次回の起動時に新しいインスタンスIDが生成されていました。
* Linux：`postremove`スクリプトは、（`apt purge`だけでなく）すべてのアンインストール時に`newrelic-agent-control`ディレクトリを正しく削除するようになり、古いinfra-エージェントのパスではなく、適切なパス（`/etc/newrelic-agent-control`、`/var/lib/newrelic-agent-control`、`/var/run/newrelic-infra`）をターゲットにするようになりました。
* On-host：サービスは、5回の短時間での再起動後に停止するのではなく、失敗時に無期限に再試行するようになりました（20秒の遅延）；これは、LinuxのsystemdユニットとWindowsのSCM失敗時のアクションの両方に適用されます。
