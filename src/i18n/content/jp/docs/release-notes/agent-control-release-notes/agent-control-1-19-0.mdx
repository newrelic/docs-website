### 新機能

* オンホストおよびKubernetes：ライブ・リモート設定の更新によってエージェントのタイプが引き上げられた場合、Agent Controlはエージェントごとのファイルシステムと共有ファイルシステムの両方を調整し、アクティブなエージェントの宣言に表示されなくなった、古いタイプによって宣言されたパスを削除するようになりました。ほかのアクティブなエージェントによって引き続き要求されている共同所有の共有パスは保持されます。Kubernetesでは、古いタイプでアノテーションされたk8sオブジェクトはガベージ・コレクションされますが、新しいタイプのリソースはそのまま残されます。
* コマンドラインからOCIレジストリにエージェント・パッケージおよびエージェント・タイプ定義をプッシュするために、`oci-utils` CLIを`test/crates/oci-test-utils`に追加します（開発/テスト・ツール；未公開）。
* オンホストのエージェント・タイプの解析で`reported_version_package`が検証されるようになりました：宣言されたパッケージを参照する必要があり、複数のパッケージが定義されている場合は必須です。無効な設定は、解析時に分かりやすいエラーとともに拒否されます。この`reported_version_package`は、どのバージョンが`agent.version`として報告されるかを決定します。
* オンホストの&quot;in-agent&quot;ファイルシステムに対する`copy_from_file`のサポートを追加します。
* オンホストのエージェント・タイプにおける`shared_filesystem`のサポートを追加します。これには単一所有者のルールが含まれます：共有ファイルシステム内の同じパスを要求する2つのエージェントは無効であり、Failedとして報告されます。
* オンホストの自己更新：自己更新の進行中は、サブエージェントの調整をスキップします。単一のリモート設定がAgent Controlのバージョンを上げ、かつサブエージェントの`agent_type`を変更する場合、変更されたサブエージェントは、プロセスの再起動直前に再作成されることはなくなりました；新しい設定は保存され、再起動したプロセスによってクリーンに再適用されるため、冗長なサブエージェントの再起動とテレメトリーのギャップを回避できます。
* オンホスト：LinuxとWindowsの両方でnri-redisのagentTypeのサポートを追加しました。
* オンホストのヘルス設定：フラットな`health.http:`/`health.file:`フィールドを明示的な`checks:`リストに置き換えました。各エントリは`kind:`（`Process`、`Http`、または`File`）によって区別されます。以前は暗黙的だった監視対象プロセスのヘルスチェックは、`kind: Process`として宣言されるようになりました。省略された、または空の`checks:`リストは、ヘルスレポートを完全に無効にします。
* オンホストのファイルシステムエントリ（`file`/`dir`）は、サブエージェントの停止、再起動、および設定の適用後も常に維持されるようになりました。既存のエージェントタイプのYAMLにある余分な`persistent:`キーは、拒否されるのではなく無視されます。

### バグ修正

* agentTypeで`package.version.<id>`として指定された各パッケージに識別属性を追加しました。
* RPMパッケージは、以前のアンインストールによって残された`.rpmsave`バックアップから`local_config.yaml`を復元するようになりました。
