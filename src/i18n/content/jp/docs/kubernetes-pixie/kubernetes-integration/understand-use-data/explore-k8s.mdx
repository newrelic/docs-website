現代のKubernetes環境は複雑な**マルチクラスタフリート**へと進化していますが、従来のオブザーバビリティツールでは、個々のクラスタの断片的でサイロ化されたビューしか提供されないことがよくあります。New RelicのKubernetes監視は、その複雑さを明確にするフリート全体のビューから始まります。

この統合ビューは、プラットフォームエンジニアやSREが以下のことを行うのに役立ちます：

* New RelicエージェントまたはOpenTelemetryによる**クラスタモニターと互換性のある単一ダッシュボード上でフリート全体の監視を統合します**。
* ガイド付きトリアージ ワークフローを使用して**根本原因分析を加速します**。
* 艦隊全体で無駄なリソースを特定することで**コストを削減します**。
* セルフサービスのためのアプリケーション中心のビューで**開発者を支援します**。

## UIへのアクセス [#access]

これは、New RelicにおけるデフォルトのKubernetesエクスペリエンスです。これを開くには：

に行く <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Kubernetes**</DNT>

## UIの主なコンポーネント [#components]

UIは、Kubernetesフリート全体の概要と詳細な分析機能の両方を提供するように構成されています。主なコンポーネントとしては、次のものがあります：

* **エンティティ フィルター**:**クラスターまたはノード レベル**で**タグと値**を使用して問題をフィルター処理およびトリアージします。
  * **Clusterフィルター**: UIを単一またはより小さいKubernetesクラスターのセットに分離するフィルター。

* **色分けされたスコアカード**: 関連する高レベルのメトリックを表示して、艦隊全体で注意が必要な最も重要な問題を浮き彫りにします。

  * スコアカードをクリックすると、そのメトリクスのコンテキストで**テーブルを並べ替え**、最も重大な問題があるクラスタとノードを一番上に表示します。
  * また、選択した時間範囲にわたるメトリクスの進化を**折れ線グラフ**で視覚化することもできます。
  * スコアカードと折れ線グラフを更新するには、<DNT>**`avg`**</DNT>、<DNT>**`p95`**</DNT>、<DNT>**`p99`**</DNT>、または<DNT>**`max`**</DNT>を選択します。breakdown table \[内訳テーブル] は、常に平均値を表示します。

* **折れ線グラフ**: 傾向分析のために選択した時間枠にわたる**メトリクスの推移**を提供します。

* **Table** \[テーブル] ：フリート内のすべてのエンティティを一覧表示し、5つのメイン[ タブ](#tab) の下に各クラスタの** 詳細なメトリクスデータ** を提供します。

  * **健康の焦点**: テーブルには、本当に必要な場所に注意を集中できるように、「不健康な」エンティティのみをリストするフィルターが用意されています。
  * **検索**: テキスト検索バーを使用すると、入力した**フリーテキスト**に基づいてテーブル行をフィルタリングできます。
  * **色分け**：scorecards \[スコアカード] と同様に、テーブルセルは色分け（黄色、赤）されており、特定の[重大度の閾値](#tab)を満たす問題のあるエンティティにすばやく注意を向けます。
  * **Column chooser \[列の選択]**：Workloads \[ワークロード] タブには、無駄のないデフォルトの列セットが用意されており、列を追加または削除できます。列の選択はセッション間で保持されます。

* **Workload type selector \[ワークロードタイプセレクタ]**：Workloads \[ワークロード]タブを、Deployments \[デプロイメント]、DaemonSets、またはStatefulSetsなどの特定のワークロードタイプに絞り込みます。

* **フィードバック ボタン**: UI の使用経験に関するフィードバックを簡単に共有できます。

## マルチアカウントフリートの可視性 [#multi-account]

アクセス権のあるNew Relicアカウントのクラスタは、同じフリートビューにまとめて表示されるため、複数のアカウントにまたがるフリートを監視する際にアカウントコンテキストを切り替える必要はありません。

複数のアカウントのクラスタを表示するには：

1. account picker \[アカウントピッカー]で、<DNT>**All accounts**</DNT>を選択してください。
2. entity filter bar \[エンティティフィルターバー] の account filter \[アカウントフィルター] を使用して、必要な特定のアカウントにビューを絞り込んでください。

## エンティティポップオーバー [#popover]

テーブル内のエンティティを選択するとポップオーバーが開き、fleet view \[フリートビュー] から移動することなく、そのエンティティのコンテキストを確認できます：

* **ゴールデンメトリクス**、エンティティの主要なパフォーマンスメトリクスのスナップショット。
* **関連エンティティ**、タイプ別にグループ化およびソートされており、現在のコンテキストと並べて stacked view \[スタックビュー] で開くことができます。
* **関連アプリケーションへのリンク**、stacked view \[スタックビュー] ではなくAPMエクスペリエンスを開くものには、外部リンクアイコンが付いています。
* **Object description \[オブジェクトの説明]**。選択したKubernetesオブジェクトのマニフェストを開きます。
* **Team** \[チーム]（エンティティに設定されている場合）
* **Dashboard \[ダッシュボード]**：エンティティの対応するダッシュボードへのリンクです。

## APM、イベント、ログ、およびアラートとの相関付け [#correlate]

フリートビューは、シグナルを関連付けてMTTRを短縮するために、ビューから離れる必要がないように設計されています：

* **APM insights \[APMインサイト]**：Workloads \[ワークロード]ビューには、ワークロードで実行されているアプリケーションのアプリケーションパフォーマンスデータが表示されるため、インフラストラクチャの健全性とアプリケーションパフォーマンスを1か所で切り替えることができます。
* **Alerts \[アラート]**：オープンなアラートは、Workloads \[ワークロード] タブの集計インジケーターを含め、クラスタ、ノード、およびワークロードに対して表示され、即座にコンテキストを把握できるように stacked view \[スタックビュー] で開きます。オープンなアラートは選択した時間範囲に関係なく表示されるため、狭いタイムピッカーによってアクティブな集計が隠れることはありません。
* **Events and logs \[イベントとログ]**：エンティティのKubernetesイベントとログが現在のコンテキストの横にスタックビューで開くため、トリアージフローの場所を見失うことなくシグナルを関連付けることができます。

<Collapser id="workloads" title="ワークロードタブ">
**Workloads** \[ワークロード]タブは、アプリケーションの不安定性やQoSの低下を診断するために**、レディネス、再起動、レプリカの欠落などのメトリクス**に焦点を当てた、デプロイメント、デーモンセット、ステートフルセットのアプリケーション中心のビューを提供します。
