指定されたワークフロー定義のワークフローの実行を開始するには、`workflowAutomationStartWorkflowRun`ミューテーションを使用します。

<Callout variant="important">
ワークフローの同時実行数および1回の実行あたりのステップ数の制限については、[「ワークフローシステムの制限」](/docs/workflow-automation/limitations-and-faq/workflow-limits)を参照してください。
</Callout>

### logLevelオプション [#loglevel-option]

`logLevel`オプションは、実行中にワークフローが生成する情報の量を制御します。

* `NONE` （デフォルト）：ログ出力を生成しません。
* `INFO`：ステップレベルの情報を出力します。
* `DEBUG`：`workflowAutomation.inputs.<inputName>: <inputValue>`の形式を使用して、すべてのアクションステップの入力を含む属性をステップ開始ログに追加します。
* `TRACE`：`DEBUG`の出力に加えて、すべてのアクションステップの出力を含む属性を、`workflowAutomation.outputs.<outputName>: <outputValue>`の形式を使用してステップ開始ログに追加します。

## サンプルリクエスト [#sample-request]

ワークフローの作成・編集には、書き込み[ビルダー](https://one.newrelic.com/nerdgraph-graphiql?state=b8f3b3a9-8d3e-c03e-5da4-34b98a57ff8f)を使用します。 [NerdGraph API エクスプローラー](/docs/apis/nerdgraph/get-started/nerdgraph-explorer)を参照してください。

```graphql
mutation {
  workflowAutomationStartWorkflowRun(
    definition: {name: "json-parsing", version: 1}
    workflowInputs: [
      {key: "checkOperational", value: "false"}
      {key: "checkNonOperational", value: "true"}]
    scope: {id: "12345678"}
    idempotencyKey: "45e65924-5316-479c-a977-f6adfa17e07a"
    options: {logLevel: INFO}
  ) {
    runId
  }
}
```

## サンプル回答 [#sample-response]

突然変異により以下が返されます:

* `runId`: ワークフロー実行の一意の識別子。この ID は`WorkflowRunInfo` 、 `SignalWorkflowRun` 、または`StopWorkflowRun` API で使用します。
