このページでは、ワークフロー自動化アクションカタログで利用できるAzure App Serviceアクションのリファレンスを提供します。これらのアクションを使用すると、Azure App Service Webアプリケーションの取得、一覧表示、開始、停止、および再起動をワークフロー定義から直接実行できます。これにより、コスト管理のためのスケジュールされたシャットダウン、インシデントをトリガーとする再起動、デプロイステップ前の事前チェックなどの運用ワークフローが可能になります。

## 前提条件

ワークフローの自動化でAzure App Serviceアクションを使用する前に、以下が準備されていることを確認してください：

* 1つ以上のApp Serviceを含むAzureサブスクリプション。
* 必要な権限を持つEntra（Azure AD）アプリの登録（サービス・プリンシパル）。
* New Relic Secrets Serviceに保存されているアプリ登録の資格情報。

## Entra認証を設定する

Azure App Serviceのアクションは、Entra（Azure AD）サービスプリンシパル・クライアント資格情報OAuth2フローを使用して認証します。必要な権限はアクションによって異なります：

* **Reader** (閲覧者)ロール — `azure.appService.get`および`azure.appService.list`に必要です。
* **Contributor** (コントリビューター)（または最小特権の**Website Contributor** (Webサイト・コントリビューター)） — `azure.appService.start`、`azure.appService.stop`、および`azure.appService.restart`に必要です。

<Steps>
<Step>
### Entraアプリの登録を作成します。

1. Azureポータルで、**Microsoft Entra ID &gt; App registrations**に移動し、**New registration** \[新規登録]をクリックします。
2. 登録に名前を付け、**Register** (登録)をクリックしてください。
3. **アプリケーション（クライアント）ID**および**ディレクトリ（テナント）ID**を控えておいてください — これらは入力として必要になります。
4. **Certificates &amp; secrets**から、新しいクライアントシークレットを作成し、すぐにその値をコピーします。

詳細な手順については、[「認証トークンを取得するためのアプリの登録」](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/api/register-app-for-token)をご覧ください。
</Step>

<Step>
### 必要なロールを割り当ててください

ターゲットのApp Serviceまたはリソースグループをスコープとして、アプリの登録に**Reader** (閲覧者)ロール（get/list用）または**Contributor** (共同作成者)/**Website Contributor** (Webサイト共同作成者)ロール（start/stop/restart用）を割り当てます。

1. Azureポータルで、ターゲットのリソースグループまたはApp Serviceに移動します。
2. **Access control (IAM) &gt; Add role assignment**に移動します。
3. 適切なロールを選択し、アプリの登録に割り当ててください。
</Step>

<Step>
### 認証情報をシークレットとして保存

`clientId`、`clientSecret`、および`tenantId`をNew Relic Secrets Serviceに保存し、`${{ :secrets:keyName }}`構文を使用してワークフローYAMLでそれらを参照します：

```yaml
clientId: ${{ :secrets:azure-client-id }}
clientSecret: ${{ :secrets:azure-client-secret }}
tenantId: ${{ :secrets:azure-client-tenant }}
```
</Step>
</Steps>
