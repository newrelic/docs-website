このページでは、ワークフロー自動化アクションカタログで利用可能なAWS Lambdaアクションのリファレンスを提供します。これらのアクションを使用して、ワークフロー定義の一部としてLambda関数を管理および呼び出します。

## 前提条件

ワークフロー自動化で AWS Lambda アクションを使用する前に、次の点を確認してください。

* 適切な権限を持つ AWS アカウント。
* 設定されたAWS認証情報（IAMユーザー認証情報、IAMロールARN、またはセッション認証情報）。少なくとも1つの認証情報オプションを指定する必要があります — IAMロールは静的アクセスキーよりも優先されます。
* 使用する予定の特定のLambdaオペレーションに必要なIAM権限。

IAM ユーザーおよび IAM ロールを作成する方法、およびワークフロー オートメーションAWSアクションと統合するための静的 AWS 認証情報とセッションAWS認証情報を設定する方法については[、 AWS認証情報のセットアップ」を](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials/)参照してください。

## Lambdaの永続的な実行履歴を取得

アクション識別子は`aws.lambda.getDurableExecutionHistory`です。

[Lambda durable execution](https://docs.aws.amazon.com/lambda/latest/dg/durable-functions.html)の実行履歴を取得し、発生したすべてのステップ、コールバック、およびイベントを表示します。このアクションはLambda durable executionにのみ適用されます — 通常のLambda関数の呼び出し履歴を取得することはできません。履歴は、実行中、および完了後の設定可能な保持期間（1～90日、デフォルトは30日）にわたって利用できます。
