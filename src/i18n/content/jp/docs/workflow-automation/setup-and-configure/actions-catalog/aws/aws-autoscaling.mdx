このページでは、ワークフロー自動化アクションカタログで利用可能なAWS Auto Scalingアクションのリファレンスを提供します。これらのアクションを使用して、Auto Scalingグループ（ASG）を管理します — インスタンスのアタッチとデタッチ、キャパシティの調整、スケーリングポリシーの実行、インスタンス更新の管理、スケーリングプロセスの制御、およびASG状態のクエリ。

## 前提条件

ワークフローの自動化でAWS Auto Scalingアクションを使用する前に、以下が必要です：

* Auto Scalingサービスの権限を持つAWSアカウント。
* IAMロールARNまたは静的アクセスキー認証情報として設定されたAWS認証情報。
* 任意の静的認証情報用のNew Relic Secrets Serviceのシークレットです。ワークフロー内で`${{ :secrets:<keyName> }}`として参照してください。

IAMユーザーとIAMロールを作成し、静的およびセッションAWS認証情報を設定する方法については、「[AWS認証情報の設定](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials/)」を参照してください。

## インスタンスのアタッチ

アクション識別子は`aws.autoscaling.attachInstances`です。

1つ以上のEC2インスタンスを既存のAuto Scalingグループにアタッチします。インスタンスをアタッチすると、アタッチした数だけ希望するキャパシティが増加します。1回の呼び出しにつき最大20個のインスタンスをアタッチできます。インスタンスは実行中または停止状態である必要があり、アタッチによってグループの最大サイズを超えてはなりません。

## インスタンスの更新を開始します

## インスタンスの更新のキャンセル

アクション識別子は`aws.autoscaling.cancelInstanceRefresh`です。

進行中のインスタンスの更新をキャンセルします。キャンセルできるのは進行中の更新のみです — 更新がアクティブでないときにこれを呼び出すと、`ActiveInstanceRefreshNotFound`で失敗します。すでに置換されたインスタンスは元に戻りません；置換されたインスタンスを元に戻すには、`aws.autoscaling.rollbackInstanceRefresh`を使用します。

進行中のインスタンスの更新をロールバックし、置き換えられたインスタンスを以前のリリーステンプレートまたは設定に戻します。ロールバックをサポートするには、グループでチェックポイントが有効になっている必要があります。ロールバックの対象となる更新がない場合、呼び出しは`ActiveInstanceRefreshNotFound`で失敗します。

## スケーリングプロセスを一時停止

アクション識別子は`aws.autoscaling.suspendProcesses`です。

Auto Scalingグループの1つ以上のスケーリングプロセスを一時停止します。不要なスケーリングアクティビティを防ぐため、デプロイメントやメンテナンスウィンドウ中に使用してください。`scalingProcesses`を省略すると、すべてのプロセスが一時停止されます。一時停止されたプロセスは、`aws.autoscaling.resumeProcesses`で明示的に再開されるまで一時停止されたままになります。

## スケーリングプロセスを再開する
