このページでは、ワークフロー自動化アクションカタログで利用可能なGitHub issueアクションのリファレンスを提供します。これらのアクションを使用すると、ワークフロー定義から直接、GitHubリポジトリ内のissueを作成、更新、一覧表示、および管理できます。

## 前提条件

ワークフロー自動化でGitHub issueアクションを使用する前に、以下を確認してください：

* ターゲットリポジトリへのアクセス権を持つGitHubアカウント。
* 必要な権限を持つGitHubパーソナルアクセストークン（PAT）。
* New Relic Secrets Serviceに保存されているPAT。

## PAT認証を設定する

GitHub issueアクションは、Bearer資格情報として渡されるパーソナルアクセストークン（PAT）を使用して認証します。このアクションは2つのトークンタイプをサポートしています：

* **Fine-grained PAT** — **Issues: Read and write**リポジトリ権限が必要です。
* **Classic PAT** — **リポジトリ**スコープが必要です。

<Steps>
  <Step>
    ### GitHub パーソナルアクセストークンを作成する

    1. GitHubで、**Settings &gt; Developer settings &gt; Personal access tokens**に移動します。
    2. **Fine-grained tokens** \[Fine-grained トークン]または**Tokens (classic)** \[トークン（クラシック）]を選択し、**Generate new token** \[新しいトークンを生成]をクリックします。
    3. 必要な権限を設定します：細かい粒度のトークンの場合は**Issues: Read and write**、クラシックトークンの場合は**リポジトリ**スコープ。
    4. 生成されたトークンをコピーしてください — GitHubでは1回のみ表示されます。
  </Step>

  <Step>
    ### トークンをシークレットとして保存します

    トークンをNew Relic Secrets Serviceに保存し、`${{ :secrets:keyName }}` 構文を使用してワークフローYAMLで参照してください：

    ```yaml
    token: ${{ :secrets:github-PAT-token }}
    ```
  </Step>
</Steps>
