このページでは、ワークフロー自動化アクションカタログで利用可能なGitHubワークフロー実行アクションのリファレンスを提供します。これらのアクションを使用すると、ワークフロー定義から直接GitHub Actionsワークフロー実行をトリガー、取得、および一覧表示でき、カスタムコードや外部ツールを使用せずに、自動化されたCI/CDオーケストレーション、デプロイメントパイプライン、およびリリース自動化を実現できます。

## 前提条件

ワークフロー自動化でGitHubワークフロー実行アクションを使用する前に、以下が用意されていることを確認してください：

* ターゲットリポジトリへのアクセス権を持つGitHubアカウント。
* 必要な権限を持つGitHubパーソナルアクセストークン（PAT）。
* New Relic Secrets Serviceに保存されているPAT。
* `workflow_dispatch`トリガーが設定されたターゲットワークフロー（`gitHub.workflowRun.trigger`に必要）。

## PAT認証を設定する

GitHubワークフロー実行アクションは、Bearer資格情報として渡されるパーソナルアクセストークン（PAT）を使用して認証します。このアクションは、2つのトークンタイプをサポートしています：

* **Fine-grained PAT** — `gitHub.workflowRun.trigger`には**Actions: write**権限、`gitHub.workflowRun.get`、`gitHub.workflowRun.getLatest`、および`gitHub.workflowRun.list`には**Actions: read**権限が必要です。
* **Classic PAT** — 4つのアクションすべてで**リポジトリ**スコープが必要です。

<Steps>
<Step>
### GitHub パーソナルアクセストークンを作成する

1. GitHubで、**Settings &gt; Developer settings &gt; Personal access tokens**に移動します。
2. **Fine-grained tokens** \[Fine-grained トークン]または**Tokens (classic)** \[トークン（クラシック）]を選択し、**Generate new token** \[新しいトークンを生成]をクリックします。
3. 必要な権限を設定してください。きめ細かいトークンの場合は**Actions: write**（読み取り専用アクションの場合は**Actions: read**）、クラシックトークンの場合は**リポジトリ**スコープを設定します。
4. 生成されたトークンをコピーしてください — GitHubでは1回のみ表示されます。
</Step>

<Step>
### トークンをシークレットとして保存します

トークンをNew Relic Secrets Serviceに保存し、`${{ :secrets:keyName }}` 構文を使用してワークフローYAMLで参照してください：

```yaml
token: ${{ :secrets:github-PAT-token }}
```
</Step>
</Steps>
