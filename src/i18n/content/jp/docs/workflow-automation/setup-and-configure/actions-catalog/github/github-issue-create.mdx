認証のセットアップについては、[GitHub Issueアクション](/docs/workflow-automation/setup-and-configure/actions-catalog/github/github-issue)を参照してください。

    <TabsPageItem id="github-issue-create-inputs">
      このアクションでは、以下の入力を使用できます。

      <table>
        <thead>
          <tr>
            <th>
              入力
            </th>

            <th>
              タイプ
            </th>

            <th>
              説明
            </th>

            <th>
              例
            </th>
          </tr>
        </thead>

        <tbody>
          <tr>
            <td>
              **token**
            </td>

            <td>
              弦
            </td>

            <td>
              **必須。**

              シークレットとして保存されたGitHubパーソナルアクセストークン（fine-grainedまたはclassic）。Fine-grained PATには、Issues：読み取りと書き込み権限が必要です。Classic PATには、リポジトリスコープが必要です。
            </td>

            <td>
              `"${{ :secrets:github-PAT-token }}"`
            </td>
          </tr>

          <tr>
            <td>
              **owner**
            </td>

            <td>
              弦
            </td>

            <td>
              **必須。**

              リポジトリのアカウント所有者（ユーザーまたは組織のログイン）。大文字と小文字は区別されません。
            </td>

            <td>
              `"octocat"`
            </td>
          </tr>

          <tr>
            <td>
              **repo**
            </td>

            <td>
              弦
            </td>

            <td>
              **必須。**

              .gitを含まないリポジトリ名サフィックス。大文字と小文字は区別されません。
            </td>

            <td>
              `"Hello-World"`
            </td>
          </tr>

          <tr>
            <td>
              **title**
            </td>

            <td>
              弦
            </td>

            <td>
              **必須。**

              イシューのタイトル。
            </td>

            <td>
              `"Production issue detected"`
            </td>
          </tr>

          <tr>
            <td>
              **body**
            </td>

            <td>
              弦
            </td>

            <td>
              **オプション。**

              GitHub-flavored Markdown形式のIssue本文。空の場合はリクエストから省略されます。
            </td>

            <td>
              `"Steps to reproduce: ..."`
            </td>
          </tr>

          <tr>
            <td>
              **assignees**
            </td>

            <td>
              リスト
            </td>

            <td>
              **オプション。**

              割り当てるGitHubユーザー名。トークンにプッシュアクセス権が必要です。GitHub APIは、プッシュアクセス権を持たないユーザーを警告なしに除外します。
            </td>

            <td>
              `["octocat"]`
            </td>
          </tr>

          <tr>
            <td>
              **labels**
            </td>

            <td>
              リスト
            </td>

            <td>
              **オプション。**

              付与するラベル。トークンにプッシュアクセス権が必要です。権限がある場合、APIは不明なラベルを自動的に作成します。それ以外の場合、APIはそれらを拒否します。
            </td>

            <td>
              `["incident", "p1"]`
            </td>
          </tr>

          <tr>
            <td>
              **milestone**
            </td>

            <td>
              Int
            </td>

            <td>
              **オプション。**

              マイルストーン番号（タイトルではなく整数ID）。トークンにプッシュアクセスが必要です。マイルストーンはすでにリポジトリに存在している必要があります。
            </td>

            <td>
              `3`
            </td>
          </tr>

          <tr>
            <td>
              **type**
            </td>

            <td>
              弦
            </td>

            <td>
              **オプション。**

              このイシューに関連付けるイシュータイプの名前（例：バグ、タスク、機能）。プッシュアクセスが必要です。イシュータイプは、使用する前にリポジトリまたは組織レベルで設定する必要があります。
            </td>

            <td>
              `"Bug"`
            </td>
          </tr>

          <tr>
            <td>
              **issueFieldValues**
            </td>

            <td>
              リスト
            </td>

            <td>
              **オプション。**

              GitHub Projects v2カスタムフィールドのIssueフィールド値。各オブジェクトには、

              `field_id`

              （整数）および

              `value`

              （文字列、数値、または複数選択フィールド用の配列）を含める必要があります。GitHub Projects v2カスタムフィールドが有効になっている組織所有のリポジトリでのみ利用可能です。
            </td>

            <td>
              `[{"field_id": 1, "value": "high"}]`
            </td>
          </tr>

          <tr>
            <td>
              **selectors**
            </td>

            <td>
              リスト
            </td>

            <td>
              **オプション。**

              レスポンスから値を抽出するためのJQセレクター。
            </td>

            <td>
              `[{"name": "issueNumber", "expression": ".number"}]`
            </td>
          </tr>
        </tbody>
      </table>

      <table>
        <thead>
          <tr>
            <th>
              ワークフローの例
            </th>
          </tr>
        </thead>

        <tbody>
          <tr>
            <td>
              ```yaml
              name: github_create_issue_workflow
              description: Create a GitHub issue
              steps:
                - name: create_issue
                  type: action
                  action: gitHub.issue.create
                  version: 1
                  inputs:
                    token: ${{ :secrets:github-PAT-token }}
                    owner: your_user_name
                    repo: test-workflow
                    title: Production issue detected
                    body: An issue has been detected and needs investigation.
                    assignees:
                      - your_user_name
                    labels:
                      - incident
                    milestone: 3
                  next: end
              ```
            </td>
          </tr>
