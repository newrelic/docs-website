CocoaPodsは、その中央レジストリ（trunk）が[2026年12月2日に恒久的に読み取り専用になる](https://blog.cocoapods.org/CocoaPods-Specs-Repo/)と発表しました。その日以降、CocoaPodsは新しいポッドのバージョンの受け入れを停止します。このページでは、それがNew Relic iOSエージェントおよびその上に構築されたハイブリッドエージェントにとって何を意味するのか、またアプリを別のインストレーション方法に移行する方法について説明します。

## 移行する前に [#before-you-migrate]

移行する前に、これらの回答を確認してください：

* <DNT>**What&apos;s changing?**</DNT> バージョン**7.7.10**は、CocoaPods（`NewRelicAgent`ポッド）に公開する最後のiOSエージェントです。以降のバージョンは、[Swiftパッケージマネージャ](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation)および[XCFrameworkのダウンロード](/docs/mobile-monitoring/new-relic-mobile-ios/installation/xcframework-installation)を通じてのみ利用可能です。
* <DNT>**Will my app break?**</DNT> いいえ。すでに公開されているすべての`NewRelicAgent`バージョンはCocoaPodsに残るため、`pod install`とCIパイプラインは引き続き機能します。CocoaPods経由で新しいエージェントバージョンを取得できなくなるだけです。
* <DNT>**Why migrate?**</DNT> 新しい機能、修正、および新しいiOSとXcodeバージョンのサポートを引き続き受け取るには、SwiftパッケージマネージャまたはXCFrameworkに移行してください。

この変更は、CocoaPodsを通じてiOSエージェントを取得するハイブリッドエージェントにも影響します。React Native、Flutter、Ionic Capacitor、Cordova、またはUnityを使用している場合は、[ハイブリッドエージェントを使用するアプリの移行](#hybrid)をご覧ください。

## iOSアプリの移行 [#ios]

以下のインストレーション方法から1つを選択してください：

* [Swift パッケージマネージャ](#spm)：Xcodeに組み込まれているAppleのパッケージマネージャです。Xcodeからエージェントを更新します。
* [XCFramework](#xcframework)：ご自身でダウンロードしてプロジェクトに追加するフレームワークバンドルです。新しいバージョンをダウンロードすることで更新します。

iOSエージェントは他のパッケージに依存しないため、他の依存関係の一部が当面CocoaPodsに残る場合でも、Swiftパッケージマネージャに移行できます。すべての依存関係をCocoaPodsから移行する予定の場合は、まずそれぞれがSwiftパッケージマネージャをサポートしていることを確認してください。サポートしていない依存関係については、XCFrameworkメソッドを使用すると、パッケージマネージャとは独立してエージェントを追加および更新できます。

<Callout variant="important">
エージェントのインストールには、1つの方法のみを使用してください。別の方法でエージェントを追加したときに`NewRelicAgent`ポッドがまだインストールされている場合、アプリにエージェントのコピーが2つ存在することになり、ビルドエラーや予期しない動作の原因となります。
</Callout>

### Swift パッケージ マネージャー [#spm]

<Steps>
<Step>
現在使用しているエージェントのバージョンを確認してください。これは、`Podfile.lock`の`NewRelicAgent`の横に記載されています。
</Step>

<Step>
Xcodeを閉じてから、`NewRelicAgent`ポッドを削除します：

* `NewRelicAgent` が唯一のポッドである場合は、プロジェクトのディレクトリでこのコマンドを実行してから、`Podfile`、`Podfile.lock`、および CocoaPods が生成した `.xcworkspace` ファイルを削除します：

  ```shell
  pod deintegrate
  ```

* 他のポッドを引き続き使用する場合は、`Podfile` から `pod 'NewRelicAgent'` の行を削除し、次を実行します：

  ```shell
  pod install
  ```

  `Podfile.lock`に`NewRelicAgent`が表示されなくなったことを確認してください。
</Step>

<Step>
Xcodeでプロジェクトを開いてください。引き続き他のポッドを使用する場合は、`.xcworkspace`ファイルを開いてください。それ以外の場合は、`.xcodeproj`ファイルを開いてください。
</Step>

<Step>
<DNT>**File &gt; Add Package Dependencies...**</DNT>を選択し、このURLを入力します：

```
https://github.com/newrelic/newrelic-ios-agent-spm
```

依存関係のルールについては、最初のステップでメモしたバージョン、またはそれ以降のバージョンから<DNT>**Up to Next Major Version**</DNT>を選択してください。
</Step>

<Step>
アプリのターゲット、およびアプリ拡張機能など、ポッドを使用したその他のターゲットに、<DNT>**NewRelic**</DNT>パッケージ製品を追加してください。
</Step>

<Step>
ターゲットの<DNT>**Build Phases**</DNT>でdSYMアップロードビルドスクリプトを確認してください：

* iOSエージェント7.4.0以降のスクリプトの場合（`run-symbol-tool`を検索します）、そのままにします。Swiftパッケージ内のツールを検出します。
* `newrelic_postbuild.sh`を呼び出している場合、または`Pods/`内のパスを使用している場合は、[Swiftパッケージマネージャのインストレーション](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation)の7.4.0以降のスクリプトに置き換えてください。

スクリプトを最後のビルドフェーズとして維持し、<DNT>**Based on dependency analysis**</DNT>のチェックが外れていることを確認してください。
</Step>

<Step>
アプリをクリーンにして構築してから、実行します。エージェントを開始するコードとアプリケーションのトークンは変更されません。
</Step>
</Steps>

後でエージェントを更新するには、[Swiftパッケージマネージャを使用した更新](/docs/mobile-monitoring/new-relic-mobile-ios/installation/upgrade-ios-agent#SPM)をご覧ください。

### XCFramework [#xcframework]

<Steps>
<Step>
Xcodeを閉じて、[Swiftパッケージマネージャの手順](#spm)に記載されているとおりに、`NewRelicAgent`ポッドを削除してください。
</Step>

<Step>
[XCFramework手動インストレーション](/docs/mobile-monitoring/new-relic-mobile-ios/installation/xcframework-installation)に従ってエージェントをダウンロードし、アプリのターゲットに追加してください。`NewRelic.xcframework`が<DNT>**Embed &amp; Sign**</DNT>に設定されていることを確認してください。
</Step>

<Step>
[Swiftパッケージマネージャの手順](#spm)で説明されているように、dSYMアップロードビルドスクリプトを確認してください。7.4.0以上のスクリプトは、`NewRelic.xcframework`内の`run-symbol-tool`を見つけます。
</Step>

<Step>
アプリをクリーンにして構築してから、実行します。エージェントを開始するコードとアプリケーションのトークンは変更されません。
</Step>
</Steps>

後でエージェントを更新するには、[「iOSエージェントを手動で置き換える」](/docs/mobile-monitoring/new-relic-mobile-ios/installation/upgrade-ios-agent#Manual)を参照してください。

### CI/CDパイプラインを更新してください [#ci]

CocoaPodsを完全に削除した場合は、`pod install`を実行する、または`.xcworkspace`ファイルをビルドするパイプライン・ステップを更新してください。Swiftパッケージマネージャを使用する場合は、ビルド前の別のステップでパッケージを解決することを検討してください：

```shell
xcodebuild -resolvePackageDependencies -project YourApp.xcodeproj -scheme YourApp
```

### リアクトネイティブ [#react-native]

デフォルトでは、React NativeエージェントはCocoaPodsからiOSエージェントを取得します。React Nativeエージェント1.9.3以降では、Swiftパッケージマネージャに切り替えることができます。

#### 標準のReact Nativeアプリ

切り替える前に、アプリがこれらの要件を満たしていることを確認します：

* React Native 0.75以上
* `use_frameworks! :linkage => :dynamic` ご使用の `Podfile`
* 標準のReact Nativeテンプレートと同様に、`react_native_post_install`を呼び出す`Podfile`内の`post_install`ブロック

切り替えるには、以下の手順に従います：

1. React Nativeエージェントをバージョン1.9.3以降に更新してください。

2. `ios/Podfile`の先頭に、次を追加します：

   ```ruby
   ENV['NEWRELIC_USE_SPM'] = '1'
   use_frameworks! :linkage => :dynamic
   ```

3. `ios`ディレクトリで`pod install`を実行し、`Podfile.lock`に`NewRelicAgent`が表示されなくなったことを確認してください。

4. アプリを構築して実行します。

#### Expoアプリ

`npx expo prebuild` `ios`フォルダを再生成するため、`Podfile`内ではなくプロジェクト設定でこれを設定してください。Expo SDK 52以降が必要です。

切り替えるには、以下の手順に従います：

1. React Nativeエージェントをバージョン1.9.3以降に更新してください。

2. `expo-build-properties`をインストールします：

   ```shell
   npx expo install expo-build-properties
   ```

3. `app.json`または`app.config.js`で、動的フレームワークを使用するようにiOSを設定してください：

   ```json
   "plugins": [
     "newrelic-react-native-agent",
     ["expo-build-properties", { "ios": { "useFrameworks": "dynamic" } }]
   ]
   ```

4. プロジェクトのルートディレクトリにある`.env`ファイルに`NEWRELIC_USE_SPM=1`を追加してください。`npx expo prebuild`と`npx expo run:ios`がそれをロードします。

5. `npx expo prebuild --clean`を実行し、`ios/Podfile.lock`に`NewRelicAgent`が表示されなくなったことを確認してください。

CocoaPodsの実行時に`NEWRELIC_USE_SPM`が設定されていない場合（たとえば、ご自身で`pod install`や`npx pod-install`を実行した場合など）、アプリはCocoaPodsからiOSエージェントを取得する状態に戻ります。

### フラッター [#flutter]

FlutterエージェントはCocoaPodsとSwiftパッケージマネージャの両方をサポートしており、どちらを使用するかはFlutterが決定します。Flutter 3.44から、[Swiftパッケージマネージャはデフォルトでオンになっている](https://docs.flutter.dev/packages-and-plugins/swift-package-manager/for-app-developers)ため、ほとんどのアプリはすでにこれを通じてiOSエージェントを取得しています。

Swiftパッケージマネージャをオフにした場合は、次を実行して再度オンにしてください：

```shell
flutter config --enable-swift-package-manager
```

また、`enable-swift-package-manager: false`を追加した場合は、`pubspec.yaml`から削除してください。

### Ionic Capacitor [#capacitor]

CapacitorエージェントはCocoaPodsとSwiftパッケージマネージャの両方をサポートしており、どちらを使用するかはiOSプロジェクトによって決まります。Capacitor 8では、Swiftパッケージマネージャを使用して新しいiOSプロジェクトを作成しますが、CocoaPodsで作成されたプロジェクトは、移行するまで引き続きCocoaPodsを使用します。

* `ios/App`フォルダに`CapApp-SPM`パッケージがある場合、すでにSwiftパッケージマネージャを使用しています。`npx cap sync`はエージェントを最新状態で維持します。
* `Podfile`がある場合は、[CapacitorのSwiftパッケージマネージャガイド](https://capacitorjs.com/docs/ios/spm)に従って、プロジェクトをSwiftパッケージマネージャに移行してください。これでは、`npx cap spm-migration-assistant`コマンドとiOSプラットフォームの再作成について説明しています。

### コルドバ [#cordova]

`cordova-ios` 8以降では、CordovaエージェントはSwiftパッケージマネージャを介してiOSエージェントを取得します。以前の`cordova-ios`バージョンでは、CocoaPodsを使用します。

移行するには、以下の手順に従ってください：

1. Cordovaエージェントを最新バージョンに更新してください。

2. iOSプラットフォームを更新してください。[cordova-ios 8のリリース発表](https://cordova.apache.org/announcements/2025/11/23/cordova-ios-8.0.0.html)をご覧ください：

   ```shell
   cordova platform remove ios
   cordova platform add ios@8
   ```

   プラットフォームを削除すると`platforms/ios`フォルダが削除されるため、手動で行った変更はすべて失われます。事前にバックアップしてください。

3. `config.xml`がiOSのデプロイメントターゲットを15.0以降に設定していることを確認してください：

   ```xml
   <preference name="deployment-target" value="15.0" />
   ```

4. アプリを構築して実行します。

### Unity [#unity]

Unityエージェントは、External Dependency Manager for Unity（EDM4U）を使用して、CocoaPods経由でiOSエージェントを取得します。Swiftパッケージマネージャはサポートしていません。アプリはCocoaPodsにすでに存在するバージョンでビルドされ続け、新しいUnityエージェントのバージョンはiOSエージェント**7.7.10**を維持します。

新しいiOSエージェントバージョンを使用するには、Unityエージェントの[依存関係の手順](/docs/mobile-monitoring/new-relic-mobile-unity/monitor-your-unity-application#manage-dependencies)で説明されているように、ご自身でXCFrameworkをXcodeプロジェクトに追加してください。アプリ内のエージェントのコピーが1つだけになるように、EDM4Uが`NewRelicAgent`ポッドもインストールしないことを確認してください。

## トラブルシューティング [#troubleshooting]

<CollapserGroup>
<Collapser id="no-such-module" title="Swiftパッケージマネージャへの移行後、ビルドが「No such module NewRelic」で失敗する">
ビルドに失敗するターゲットに<DNT>**NewRelic**</DNT>パッケージプロダクトが追加されていることを確認してください。ターゲットの設定で、<DNT>**Frameworks, Libraries, and Embedded Content**</DNT>セクションを確認してください。プロジェクトに複数のターゲットがある場合は、エージェントを使用する各ターゲットにプロダクトを追加してください。
</Collapser>

<Collapser id="library-not-loaded" title="リリース時にアプリが「Library not loaded: @rpath/NewRelic.framework/NewRelic」でクラッシュする">
エージェントはリンクされていますが、アプリには組み込まれていません：

* Swiftパッケージマネージャ：<DNT>**NewRelic**</DNT>パッケージプロダクトを、フレームワークや拡張機能のターゲットだけでなく、アプリのターゲット自体にも追加してください。
* XCFramework：アプリターゲットの<DNT>**Frameworks, Libraries, and Embedded Content**</DNT>セクションで、`NewRelic.xcframework`を<DNT>**Embed &amp; Sign**</DNT>に設定してください。

ハイブリッドエージェントを使用している場合は、[「ハイブリッドエージェントを使用するアプリを移行する」](#hybrid)にあるエージェントの手順を参照してください。
</Collapser>

<Collapser id="duplicate" title="重複シンボルのエラー、またはクラスが2回実装されているという警告が表示されます。">
アプリにはエージェントのコピーが2つあります。`NewRelicAgent`が`Podfile.lock`に表示されなくなったこと、およびエージェントを1つのメソッドでのみ追加したことを確認してください。
</Collapser>

<Collapser id="checksum" title="Swiftパッケージマネージャがチェックサムまたはダウンロード・エラーを報告する">
[Swiftパッケージマネージャのトラブルシューティング手順](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation#troubleshooting)を参照してください。
</Collapser>
</CollapserGroup>
