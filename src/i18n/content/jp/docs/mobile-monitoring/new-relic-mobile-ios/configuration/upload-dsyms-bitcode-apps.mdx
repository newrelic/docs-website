Xcodeは、アプリのdSYMファイルをdSYMアーカイブパスフォルダーに保存します。これは、iOSエージェントがクラッシュ・レポートをシンボル化するために使用するdSYMファイルを取得するフォルダーです。New Relicは、[iOSエージェントのインストールプロセス](/docs/mobile-monitoring/new-relic-mobile-ios/installation/spm-installation/#configure-using-swift-package-manager)の一部として、ビルド後スクリプトを提供しています。このスクリプトは、dSYMをNew Relicのマップファイル形式に自動的に変換し、クラッシュのシンボル化に必要なファイルをNew Relicにアップロードします。

## 自動スクリプト [#Automatic]

iOSエージェントには、XcodeのRun Script \[スクリプトの実行] ビルドフェーズから実行するシェルスクリプトである`run-symbol-tool`が含まれています。各ビルドの後、バックグラウンドで`run-symbol-tool.swift`を実行します。これにより、dSYMファイルがNew Relicマップファイル形式に変換され、New Relicにアップロードされます。

Xcode 14 では、Apple は新しく作成されたプロジェクトのデフォルト設定を変更してビットコードを無効にしました。App Store は、ビットコードがオフになっているアプリの提出のみを受け入れるようになりました。[Xcode 14 のリリース ノート](https://developer.apple.com/documentation/xcode-release-notes/xcode-14-release-notes)を参照してください。プロジェクトでビットコードが有効になっている場合は、無効にする必要があります。自動スクリプトでは、ビットコードを無効にする必要があります。

Apple は、ビットコード対応アプリ用に dSYM ファイルを生成します。[ビットコード対応アプリの dSYM ファイルを Apple からダウンロードし](/docs/mobile-monitoring/new-relic-mobile-ios/install-configure/retrieve-upload-dsyms-bitcode-enabled-apps)、[モバイル監視 UI](#mobile-ui)を介して New Relic にアップロードする必要があります。

[<DNT>**Crashes**</DNT>ページ](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-apps-crashes-dashboard)に判読できないマシンコードが表示される場合、dSYM ファイルが正しくアップロードされていない可能性があります。 場合によっては、 [dSYM ファイルを手動でアップロードする](#manual-dsym)必要があります。

<Callout variant="important">
iOSエージェントのバージョン7.4.8Pythonのアップロード・スクリプト（`generateMap.py`、`generateMapPython2.py`、および`newrelic_postbuild.sh`）を削除しました。Run Script \[スクリプトの実行] ビルド・フェーズでまだ`newrelic_postbuild.sh`を呼び出している場合は、以下の`run-symbol-tool`スクリプトに置き換えてください。
</Callout>

### Run Script \[スクリプトの実行] ビルドフェーズを追加します [#run-script]

1. Xcodeで、navigator \[ナビゲーター] からプロジェクトを選択し、次にアプリのターゲットを選択します。

2. <DNT>**Build Phases**</DNT>タブを選択します。

3. <DNT>**+**</DNT>をクリックし、<DNT>**New Run Script Phase**</DNT>を選択します。

4. 新しいフェーズに次の行を追加します。`APP_TOKEN`をNew Relicのアプリケーション・トークンに置き換えます。

   ```shell
   ARTIFACT_DIR="${BUILD_DIR%Build/*}"
   SCRIPT=`/usr/bin/find "${SRCROOT}" "${ARTIFACT_DIR}" -type f -name run-symbol-tool | head -n 1`
   /bin/sh "${SCRIPT}" "APP_TOKEN"
   ```

Xcode 15.3以降では、スクリプトがdSYMファイルを読み取り、ログを書き込めるように、<DNT>**User Script Sandboxing**</DNT>を<DNT>**No**</DNT>に設定します。[「dSYMの自動アップロードの失敗」](/docs/mobile-monitoring/new-relic-mobile-ios/troubleshoot/dSYM-upload-tools)をご覧ください。

### アプリバージョン [#app-version]

New Relicは、アップロードされたシンボルとビルドをアプリのバージョンによって照合します。スクリプトは、このリストから最初の空ではない値を使用します：

1. `-appVersion`引数
2. 環境変数`NEWRELIC_APP_VERSION`
3. `MARKETING_VERSION`ビルド設定
4. プレースホルダー `1.2.3`

スクリプトがプレースホルダーを使用する場合、`upload_dsym_results.log`に警告をログに記録します。

`agvtool`でバージョン管理されているアプリや、`GENERATE_INFOPLIST_FILE = YES`を使用するマルチターゲットアプリなど、一部のプロジェクトでは`MARKETING_VERSION`が設定されません。これらのプロジェクトでは、シンボルがビルドと一致するように、`-appVersion`を渡すか`NEWRELIC_APP_VERSION`を設定します。

### 環境変数 [#environment-variables]

標準のアップロードでは、これらの変数を設定する必要はありません。設定するには、同じRun Script \[スクリプトの実行] フェーズ内のスクリプトの上に`export`行を追加します：

```shell
export NEWRELIC_APP_VERSION="1.4.2"
ARTIFACT_DIR="${BUILD_DIR%Build/*}"
SCRIPT=`/usr/bin/find "${SRCROOT}" "${ARTIFACT_DIR}" -type f -name run-symbol-tool | head -n 1`
/bin/sh "${SCRIPT}" "APP_TOKEN"
```

### スクリプトの仕組み [#how-it-works]

実行時に、スクリプトは次の処理を行います：

* アップロードはバックグラウンドで実行されるため、ビルドは完了を待ちません。スクリプトは結果を[`upload_dsym_results.log`](#auto-upload-fail-troubleshooting)に書き込みます。
* スクリプトはiOSシミュレーターのビルドをスキップします（`EFFECTIVE_PLATFORM_NAME`は`-iphonesimulator`です）。
* Bitcodeが有効なビルド（`ENABLE_BITCODE = YES`）は、アップロードを行わず、ビルドを失敗させることなく終了します。
* スクリプトは`DWARF_DSYM_FOLDER_PATH`内の各dSYMをマップファイルに変換し、マップファイルをzip圧縮して、zipを`/map`エンドポイントにアップロードします。
* dSYMを変換できない場合、スクリプトはそのdSYMをzip圧縮し、代わりに`/symbol`エンドポイントにアップロードします。マップのアップロード自体が失敗した場合、スクリプトはHTTPステータス・コードをログに記録し、dSYMのアップロードへのフォールバックは行いません。その場合は、[dSYMを手動でアップロード](#manual-dsym)してください。
* iOSエージェントのバージョン7.7.2以降では、zip圧縮されたマップファイルが200 MBより大きい場合、スクリプトはそれをアップロードしません。ファイルサイズとアプリのバージョンのみをNew Relicに送信します。[dSYMを手動でアップロード](#manual-dsym)しない限り、New Relicはそのビルドからのクラッシュをシンボリケートできません。
* スクリプトは、アプリケーション・トークンからアップロードのリージョン（US、EU、またはJP）を選択します。これらは、[手動アップロードコマンド](#manual-dsym)で使用されるホストと同じです。

## 欠落しているdSYMを特定する [#IdentifyingMissingdSYMs]

Bitcodeが有効なアプリがApp Storeの審査やアドホック配信のためにAppleにアップロードされた場合、[モバイルクラッシュレポート](/docs/mobile-monitoring/new-relic-mobile/getting-started/ios-agent-crash-reporting)を適切にシンボル化できるように、dSYMをAppleから手動でダウンロードし、New Relicにアップロードする必要があります。アプリのアップロードから数分以内に、XcodeのArchives \[アーカイブ] オーガナイザーを通じてこれらのdSYMをダウンロードできます。このような場合は、[アーカイブを見つけてdSYMをダウンロードする](/docs/mobile-monitoring/new-relic-mobile-ios/configuration/retrieve-dsyms-bitcode-apps#Archive)手順に従ってください。

アプリにdSYMファイルがない場合は、モバイルモニタリングUIに次の3つのインジケーターが表示されます。

* <DNT>**Banner notification**</DNT>: [<DNT>**Crash report**</DNT>ページ](/docs/mobile-monitoring/mobile-monitoring-ui/crashes/mobile-apps-crash-report-dashboard)にバナー警告が表示されます。 警告には次のように書かれています。

```
We were unable to locate your dsym.
```

* <DNT>**Upload prompt**</DNT>: <DNT>**Crash type summary**</DNT>ページでは、dSYM ファイルが見つからない場合、自動的にアップロードするように求められます。
* <DNT>**Machine code**</DNT>: <DNT>**Crash report**</DNT>ページのクラッシュ スタック トレースには、人間が判読できるエラー メッセージではなく、マシン コードが表示されます。

## モバイルモニタリングUIを介してdSYMファイルをアップロードする [#mobile-ui]

New Relic UIから直接dSYMファイルを簡単にアップロードできます。サイズ制限については、[制限事項](#limitations)をご覧ください。dSYMファイルをアップロードするには：

1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Mobile**</DNT>に移動します。 次に、リストからアプリを選択します。
2. <DNT>**Crashes**</DNT>表示します。
3. グループクラッシュの<DNT>**Total crashes**</DNT>から特定のクラッシュを選択します。
4. <DNT>**Upload dSYM**</DNT>クリックします。 dSYM を直接ドラッグ アンド ドロップするか、コンピューターからファイルを選択することができます。

## dSYMファイルを手動でアップロードする [#manual-dsym]

状況によっては、New RelicによるdSYMファイルの自動アップロードが失敗する場合があります。たとえば、ネットワーク障害が発生してアップロードが完了しない場合、[`upload_dsym_results.log`](#auto-upload-fail-troubleshooting)に何が問題だったかが記録されます。New RelicがdSYMアップロードを処理する方法の追加情報については、[「New Relic&apos;s Online Technical Community」](https://support.newrelic.com/s/hubtopic/aAX8W0000008Yv9/relic-solution-ios-dsym-upload-deepdive)を参照してください。

自動アップロードが失敗した場合は、dSYMファイルを手動でアップロードできます。複数のdSYMファイルがある場合は、1つのzipファイルにまとめることができます。サイズ制限については、[「制限事項」](#limitations)を参照してください。以下のコマンドの`YOUR_NEW_RELIC_APPLICATION_TOKEN`の値は、`+[NewRelic startWithApplicationToken:]`（Objective-Cの場合）または`NewRelic.start(withApplicationToken:)`（Swiftの場合）に使用されるキーと同じです。

以下のコマンドでは、フルパスまたは`$HOME`を使用してください。シェルは、引用符内の`~`を展開しません。

dSYMファイルを手動でアップロードするには：

<CollapserGroup>
<Collapser id="swift-manual-upload" title="Swiftスクリプト経由">
コマンドラインから`run-symbol-tool.swift`を実行できます。これは、Xcodeアーカイブの`dSYMs`フォルダーなどのフォルダー内のdSYMファイルを変換し、[自動スクリプト](#how-it-works)と同じ方法でアップロードします。スクリプトは`run-symbol-tool`と同じフォルダーにあります（たとえば、`NewRelic.xcframework/Resources`）。

```shell
DWARF_DSYM_FOLDER_PATH="DSYM_FOLDER_PATH" /usr/bin/xcrun --sdk macosx swift "SCRIPT_PATH/run-symbol-tool.swift" "YOUR_NEW_RELIC_APPLICATION_TOKEN" -appVersion "APP_VERSION"
```

交換する：

* `DSYM_FOLDER_PATH` `.dSYM`ファイルを含むフォルダーへのフルパス（たとえば、`$HOME/Library/Developer/Xcode/Archives/2026-10-22/MyApp.xcarchive/dSYMs`）を指定します。
* `SCRIPT_PATH` `run-symbol-tool.swift`が含まれるフォルダーへのフルパス。
* `APP_VERSION` ビルドのバージョン。`MARKETING_VERSION`はXcodeの外部では設定されないため、バージョンを明示的に渡してください。エージェントのバージョンが7.4.12～7.7.4の場合、`-appVersion`を渡す代わりに、コマンドの前に`MARKETING_VERSION="APP_VERSION"`を設定してください。

スクリプトは、その出力をターミナルに表示します。
</Collapser>
</CollapserGroup>

## トラブルシューティング [#auto-upload-fail-troubleshooting]

`run-symbol-tool`スクリプトは、アップロードの成功または失敗にかかわらず、ビルドごとにプロジェクトのルートディレクトリに`upload_dsym_results.log`を書き込みます。ビルドごとに前のログが上書きされます。ログにより詳細な情報を書き込むには、[`--debug`引数](#arguments)を追加します。

ビルドのログに`upload_dsym_results.log: Operation not permitted`と表示される場合は、[「Automatic dSYM upload failures」](/docs/mobile-monitoring/new-relic-mobile-ios/troubleshoot/dSYM-upload-tools)を参照してください。

### 欠落しているdSYM [#troubleshooting-missing-dsyms]

dSYMファイルが見つからない場合は、Xcodeビルド設定をチェックして、ファイルが生成されていることを確認する必要があります。ローカルでビルドされるフレームワークには個別のビルド設定があり、同様に更新する必要がある場合があります。

ビルド設定：

```
Debug Information Format : Dwarf with dSYM File
Deployment Postprocessing: Yes
Strip Linked Product: Yes
Strip Debug Symbols During Copy : Yes
```

### 制限 [#limitations]

以下のサイズ制限にご注意ください：

* [モバイル監視UI](#mobile-ui)または[コマンドライン](#manual-dsym)を介したzip圧縮されたdSYMのアップロードは、最大600 MBまで可能です。
* 自動スクリプトは、200 MBより大きいzip圧縮されたマップファイルをアップロードしません。[「スクリプトの仕組み」](#how-it-works)を参照してください。
