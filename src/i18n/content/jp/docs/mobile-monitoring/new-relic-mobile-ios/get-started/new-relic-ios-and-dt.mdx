当社のiOSエージェントは、ディストリビューティッド（分散）トレーシングをサポートしています。これにより、モバイルアプリのアクティビティが関連サービスにどのように接続されているかを確認できます。

## 要件 [#requirements]

分散トレースを使用するには、iOS エージェント バージョン 7.3.0 以降が必要です。最新のエージェントを使用することをお勧めします。

## 分散型トレーシングの設定方法 [#setup]

ディストリビューティッド（分散）トレーシングはデフォルトで有効になっています — 有効にするために何もする必要はありません。

無効にする場合は、モバイルSDKのAPIガイドの[ディストリビューティッド（分散）トレーシング](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#ios-dt)、または以下の[ディストリビューティッド（分散）トレーシングを無効にする](#disable)をご覧ください。

他の設定に関係なく、ディストリビューティッド（分散）トレーシングヘッダーはインストゥルメントされたすべてのリクエストで送信されます。ただし、トレースをレポートされた`MobileRequest`イベントにリンクする（そしてUIでアプリのネットワークアクティビティと関連付けて表示する）には、[Network Request Events](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#ios-networking)も有効にする必要があります。これはデフォルトで有効になっているため、明示的に無効にした場合にのみ関係します。

## ディストリビューティッド（分散）トレーシングヘッダー [#headers]

iOSエージェントバージョン7.7.8以降、エージェントは送信ネットワークrequestsに[W3Cトレースコンテキスト](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers)ヘッダーである`traceparent`と`tracestate`のみを追加します。独自の`newrelic`ヘッダーは送信されなくなりました。以前のバージョンのエージェントでは、3つのヘッダーすべてを送信します。

## どのrequestsが自動的にディストリビューティッド（分散）トレーシングされますか [#automatic-instrumentation]

エージェントは自動的に`NSURLSession`と`NSURLConnection`を計装するため、設定不要で、どちらかを通じて行われたrequestsにディストリビューティッド（分散）トレーシングのヘッダーが追加されます。

<Callout variant="important">
アプリがSwiftの`async`/`await` `URLSession` API（たとえば、`data(for:)`や`data(from:)`）を使用している場合、これらはデフォルトの計装の対象には**なりません**。`NRFeatureFlag_SwiftAsyncURLSessionSupport`を明示的に有効にする必要があります（エージェントバージョン7.4.5の時点ではデフォルトで無効）。これにより、エージェントはこれらの呼び出しにディストリビューティッド（分散）トレーシングヘッダーを追加できるようになります：

エージェントは、以下の対象にはディストリビューティッド（分散）トレーシングヘッダーを自動的に追加しません：

* `WKWebView`. `WKWebView`にロードされたWebコンテンツは、アプリの`NSURLSession`/`NSURLConnection`計装の外部であるWebKitプロセス内からネットワークrequestsを行うため、それらのrequestsは自動的にトレースされません。（デフォルトで有効になっているエージェントの個別の`WKWebView`計装は、ページ読み込みのタイミングのみを対象とし、ネットワークヘッダーは対象としません）。
* `NSURLSession`または`NSURLConnection`を経由してルーティングしないサードパーティのネットワークライブラリ。
* WebSockets。
* gRPCやその他のカスタムトランスポート。

これらのいずれかについては、手動プロパゲーションを使用してください。

## ディストリビューティッド（分散）トレーシングを手動で伝播します [#manual]

APIを通じてリクエストを行う場合、エージェントは自動的に計装しません。その場合でも、手動でディストリビューティッド（分散）トレーシングのヘッダーを追加し、リクエストを報告することができます。

**他の何かがリクエストを報告する場合**

一部のフレームワーク（たとえば、ハイブリッドフレームワークで使用されるネイティブのネットワーキングライブラリ）はリクエストを送信し、New Relicに個別にレポートします。この場合、ヘッダーを生成し、ご自身でアタッチしてください。リクエストをレポートするものは何であれ、W3CヘッダーからトレースIDを復元します。

**リクエストの送信と報告の両方を行う場合**

同じコードがリクエストを送信し、それをNew Relicに報告する場合（たとえば、クロスプラットフォーム・エージェントなど）、代わりに`generateDistributedTracingContext`を使用してください。リクエストに設定するW3Cヘッダー（`traceparent`、`tracestate`）と、リクエストを報告する際に引き渡すトレースのID（`trace.id`、`id`、`guid`）を含む1つのディクショナリが返されるため、報告されたイベントは新しいトレースではなく、そのトレースに属性付けられます。

完了したリクエストをレポートするときに、その同じディクショナリを[`noticeNetworkRequestForURL:`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-success/)または[`noticeNetworkFailureForURL:`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-failures/)の`traceHeaders`パラメーターとして渡してください（iOSタブを選択してください）。完全なパラメーターのリファレンスについては、それらのページを参照してください。

## インフィニット トレースの有効化 [#infinite-tracing]

モバイルアプリに、[無限トレース](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing)と呼ばれるテールベースの分散トレースを使用するダウンストリームサービスがある場合は、モバイルアプリでこの機能を有効にする必要があります。これにより、ルートスパン（開始モバイルアプリ）が、InfiniteTracingによって追跡される残りのスパンに含まれるようになります。

この設定を行うには、 [Infinite Tracingの手順](/docs/distributed-tracing/infinite-tracing/set-trace-observer) を参照して、トレースオブザーバーを作成し、スパンをレポートするモバイルアプリ（データソース）を選択します。

## データを探す [#find-data]

モバイルスパンは、そのスパンがトレースの一部である [New Relic distributed tracing UI](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) に表示されます。

ここでは、データを検索したり、問い合わせたりするためのヒントをご紹介します。

* エンドユーザーが作成したトレースは[、NewRelicの分散トレースUI](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one)で見つけることができます。
* ディストリビューティッド（分散）トレーシングUIでは、エンドユーザースパンは<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}}>で示されます。</img>アイコン。
* スパンの属性を見るには、UI で [a span を選択します。](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details)
* [](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details)
  [スパンは ](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details)[スパンデータ](/attribute-dictionary/?event=Span) として報告され、 [New Relic](/docs/using-new-relic/data/understand-data/query-new-relic-data) で照会することができます。

たとえば、特定のアプリのモバイルスパンを検索するには：

```sql
SELECT count(*) FROM Span WHERE mobileApp.name = 'YOUR_APP_NAME' SINCE 1 day ago
```

モバイルスパンをバックエンドのAPMスパンに接続するトレースを検索するには：

```sql
SELECT * FROM Span WHERE mobileApp.name IS NOT NULL AND appName IS NOT NULL SINCE 1 day ago
```

## トラブルシューティング [#troubleshooting]

想定される場所にモバイルスパンが表示されない場合は、以下の考えられる原因を確認してください：

* **ディストリビューティッド（分散）トレーシングが無効になっています。**`NRFeatureFlag_DistributedTracing`を使用して`disableFeatures`を呼び出していないことを確認してください。[ディストリビューティッド（分散）トレーシングの設定方法](#setup)をご覧ください。
* **リクエストは自動的にインストゥルメントされません。**`NSURLSession`または`NSURLConnection`以外を介して行われたRequests — Swiftの`async`/`await` `URLSession`呼び出しを含む — には、`NRFeatureFlag_SwiftAsyncURLSessionSupport`を有効にするか、[手動プロパゲーション](#manual)が必要です。[どのrequestsが自動的にディストリビューティッド（分散）トレーシングの対象になるか](#automatic-instrumentation)をご覧ください。
* **バックエンドのAPMエージェントが古すぎます。**受信側サービスのAPMエージェントがW3Cトレースコンテキストをまだサポートしていない場合、アプリのトレースにリンクする代わりに新しいトレースを開始します。[APMエージェントの最小バージョン](#headers)を確認してください。
* **プロキシまたはゲートウェイがヘッダーを削除しています。**アプリとバックエンドの間にあるものはすべて、`traceparent`および`tracestate`を変更せずに通過させる必要があります。
* **信頼できるアカウントキーが一致しないため、`tracestate`は破棄されます。**バックエンドサービスがモバイルアプリとは異なるNew Relicアカウントに属している場合は、そのアカウントが同じ信頼関係にあることを確認してください。そうでない場合、`tracestate`エントリは無視される可能性があります。

より広範なディストリビューティッド（分散）トレーシングの問題については、[トラブルシューティング](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data)をご覧ください。
