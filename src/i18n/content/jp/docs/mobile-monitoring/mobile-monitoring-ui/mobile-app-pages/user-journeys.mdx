モバイルユーザージャーニーは、エンドユーザーがモバイルアプリをどのようにナビゲートするかを全体的に視覚化します。ユーザーの行動パターン — アプリを開いた後にユーザーがどこへ行くか、どこで行き詰まるか、どのパスが関心のある結果につながるか — を明らかにします。

<img title="Mobile User Journeys Sankey diagram" alt="A Sankey diagram showing user navigation paths through a mobile app, with nodes representing screens and paths sized by user volume" src="/images/mobile_screenshot-full_user-journeys-sankey.png" />

<Callout variant="important">
  <DNT>Mobile User Journeys</DNT> 現在、New Relicモバイル監視UIの<DNT>**Errors**</DNT>エクスペリエンス内で利用可能です。スタンドアロンの<DNT>Mobile User Journeys</DNT>ビュー（[Browser User Journeys \[Browserユーザージャーニー\]](/docs/browser/browser-monitoring/browser-pro-features/user-journeys/)機能に類似）は、将来のリリースで予定されています。
</Callout>

## アクセス方法 [#access]

<DNT>Mobile User Journeys</DNT> 左側のナビゲーションの<DNT>**Triage**</DNT>の下にある4つのセクション（<DNT>**Crashes**</DNT>、<DNT>**Request errors**</DNT>、<DNT>**Handled exceptions**</DNT>、<DNT>**ANRs**</DNT>）すべてで利用可能です。どこからアクセスするかによって、到達する方法は異なります：

<img title="Mobile Triage navigation showing Crashes, Request errors, Handled exceptions, and ANRs" alt="The New Relic Mobile left navigation with the Triage section expanded, showing Crashes, Request errors, Handled exceptions, and ANRs" src="/images/mobile_screenshot-full_user-journeys-triage-nav.png" />

**Triageタブから：**

1. **[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; <DNT>Mobile</DNT>**に移動します。
2. モバイルアプリケーションを選択します。
3. 左側のナビゲーションで、<DNT>**Triage**</DNT>の下にある<DNT>**Crashes**</DNT>または<DNT>**Request errors**</DNT>をクリックします。
4. <DNT>error groups</DNT>から、調査したいものを選択してエラー詳細ビューを開きます。
5. 詳細ビューで、<DNT>**User Journeys**</DNT>リンクをクリックして、エラーにつながったナビゲーションパスを表示します。

**「Group crashes or error」タブから：**

1. **[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; <DNT>Mobile</DNT>**に移動します。
2. モバイルアプリケーションを選択します。
3. 左側のナビゲーションで、<DNT>**Triage**</DNT>の下にある<DNT>**Crashes**</DNT>または<DNT>**Request errors**</DNT>をクリックします。
4. <DNT>**Group crashes**</DNT>または<DNT>**Group request errors**</DNT>タブをクリックします。
5. 調査するクラッシュまたはエラーグループを選択して、グループの詳細ビューを開きます。
6. <DNT>**Triage**</DNT>の下にある<DNT>**User Journeys**</DNT>リンクをクリックして、エラーに至ったナビゲーションパスを確認します。

## Mobile User Journeysの使用方法 [#how-to-use]

### サンキーダイアグラム [#sankey]

<DNT>User Journeys</DNT>の視覚化では、サンキーダイアグラムを使用して画面間のユーザーのフローを示します。各ノードはアプリ内の画面またはインタラクションを表し、各接続パスの幅はそのルートをたどったユーザーの数を反映しています。

ダイアグラムの主な要素：

* **Nodes**: アプリ内の個々の画面またはインタラクション。
* **パス**: ノード間の接続であり、そのパスをたどったユーザーの数に比例したサイズになります。
* **エントリポイント**: ユーザーセッションが開始される画面です。
* **離脱ポイント**: ユーザーがセッションを終了した、またはエラーをトリガーした画面。

エラーグループ内から表示すると、ビジュアライゼーションはそのエラーが発生したセッションに自動的に固定されるため、クラッシュの前に発生したナビゲーションパスをトレースできます。

### パスとイベントの詳細 [#path-details]

ダイアグラム内の任意のノードまたはパスをクリックすると、その正確なルートをたどったセッションにドリルダウンします。これにより、2つのパネルを持つ分割ビューが開きます：

<img title="Mobile User Journeys crash detail view" alt="Split view showing the Profiles panel on the left with attribute distribution and the Sessions table on the right listing affected sessions" src="/images/mobile_screenshot-full_user-journeys-crash-detail.png" />

* <DNT>**Profiles**</DNT>: 選択したパスをたどったセッション全体での属性値（アプリのバージョン、デバイス、OS、アーキテクチャー、クラッシュの詳細など）の分布を示します。これを使用して、影響を受けたユーザー間の共通点を特定します。
* <DNT>**Sessions that include this event**</DNT>: ユーザーID、日付、発生回数、アプリのバージョン、デバイス、OSバージョン、キャリアなど、個々のセッションをリストするテーブル。任意のセッションをクリックして、<DNT>Event Trail Drilldown</DNT>ページを開きます。

### イベントトレイルのドリルダウン [#event-trail]

セッションテーブル内のセッションをクリックして<DNT>**Event Trail Drilldown**</DNT>ページを開きます — そのセッションで記録されたすべてのイベントの時系列のタイムラインです。

<img title="Mobile User Journeys Event Trail Drilldown" alt="The Event Trail Drilldown showing a chronological list of Interaction and Crash events with expandable attribute details" src="/images/mobile_screenshot-full_user-journeys-event-trail.png" />

<DNT>Event Trail Drilldown</DNT>では、次のことができます：

* <DNT>**Filter by event type**</DNT>: <DNT>**Interaction**</DNT>ボタンと<DNT>**Crash**</DNT>ボタンを使用して、特定のイベントタイプに焦点を当てます。
* <DNT>**Expand event details**</DNT>: 任意のイベントをクリックすると、完全な属性ペイロードが表示されます — これには、`diskAvailable`、`osBuild`、`processName`、`timeSinceLastInteraction`、`interactionHistory`などのクラッシュメタデータが含まれます。

このビューを使用すると、クラッシュが発生する前にユーザーが実行した正確な手順を、個々の画面インタラクションに至るまで再構築できます。

## 視覚化のカスタマイズ方法 [#customize]

### イベントタイプフィルター [#event-type]

<img title="Mobile User Journeys event type filter" alt="The event type filter dropdown showing options: Crash, Breadcrumb, Interaction, User action, Handled exception, JavaScript error, Request error, Custom, ANR" src="/images/mobile_screenshot-crop_user-journeys-event-type-filter.png" />

<DNT>**Event type**</DNT>フィルターを使用して、ダイアグラム上のノードとして表示するイベントタイプを選択します。以下の任意の組み合わせを含めることができます：

* Crash \[クラッシュ]
* ブレッドクラム
* Interaction \[インタラクション]
* User action \[ユーザーアクション]
* Handled exception \[ハンドルされた例外]
* JavaScript error \[JavaScriptエラー]
* Request error \[リクエストエラー]
* カスタム
* ANR

### アプリバージョン [#app-version]

<DNT>**App version**</DNT>フィルターを使用して、特定のリリースからのジャーニーに焦点を当てます。これは、デプロイメントの前後のユーザーの行動を比較して、リグレッションや改善を特定するのに役立ちます。

### ユーザー属性でフィルタリング [#user-attributes]

フィルターバーを使用して、デバイスタイプ、OSバージョン、地域などの追加の属性、または[Mobile SDK](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/mobile-sdk-api-guide/)でインストゥルメントされたカスタムアトリビュートによって結果を絞り込みます。
