New Relic Android <InlinePopover type="mobile" />エージェントは、ディストリビューティッド（分散）トレーシングをサポートしています。これにより、モバイルアプリのアクティビティが関連サービスにどのように接続しているかを確認できます。

## 要件 [#requirements]

分散型トレーシングを使用するには、最低でもAndroidエージェントのバージョン6.0.0が必要となります。

## 分散型トレーシングの設定方法 [#setup]

ディストリビューティッド（分散）トレーシングはデフォルトで有効になっています。有効にするために何も行う必要はありません。ディストリビューティッド（分散）トレーシングのヘッダーは、他の設定に関係なく、自動でインストゥルメントされたすべてのリクエストで送信されます。

オフにしたい場合は、以下の[ディストリビューティッド（分散）トレーシングの無効化](#disable)をご覧ください。

New Relic内でアプリのネットワークアクティビティに関連付けられたトレース（報告された`MobileRequest`または`MobileRequestError`イベント）を確認するには、[AnalyticsEvents](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#android-analytics-settings)を有効にする必要があります — これはデフォルトでオンになっており、アプリの分析イベントを送信するための前提条件であり、ディストリビューティッド（分散）トレーシングに特有のものではありません。

## ディストリビューティッド（分散）トレーシングヘッダー [#headers]

Androidエージェントのバージョン7.8.3以降、エージェントは送信されるネットワークrequestsに[W3Cトレースコンテキスト](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers)ヘッダーである`traceparent`と`tracestate`のみを追加します。独自の`newrelic`ヘッダーは送信されなくなりました。以前のバージョンのエージェントでは、3つのヘッダーすべてを送信します。

## どのrequestsが自動的にディストリビューティッド（分散）トレーシングされますか [#automatic-instrumentation]

AndroidエージェントのGradleプラグインは、ビルド時にアプリのバイトコードを計装するため、以下を通じて行われるrequestsにディストリビューティッド（分散）トレーシングのヘッダーが自動的に追加されます：

* `OkHttp` （バージョン2と3）
* Apache `HttpClient`
* `HttpURLConnection`
* Retrofit

この計装はこれらのライブラリの呼び出し箇所を直接ウィーブするため、呼び出し元に関係なく基盤となる呼び出し箇所がウィーブされることから、それらをラップするコード — Kotlinコルーチンやsuspend関数など — も対象になります。

エージェントは、以下の対象にはディストリビューティッド（分散）トレーシングヘッダーを自動的に追加しません：

* Volley。エージェントではVolleyがまったくサポートされていないため、Volleyのrequestsをトレースしたい場合は、[手動での伝播](#manual)が必要です。
* `WebView`。エージェントの`WebView`の計装は、ネットワークリクエストのヘッダーではなく、ページのロード時間を対象としているため、`WebView`にロードされたWebコンテンツから行われたrequestsは自動的にトレースされません。
* 上記のライブラリを経由してルーティングされない、その他のサードパーティ製ネットワーキングライブラリまたはカスタムトランスポート。

これらのいずれかについては、手動プロパゲーションを使用してください。

## ディストリビューティッド（分散）トレーシングの無効化 [#disable]

```java
NewRelic.disableFeature(FeatureFlag.DistributedTracing)
```

## インフィニット トレースの有効化 [#infinite-tracing]

モバイルアプリに、[無限トレース](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing)と呼ばれるテールベースの分散トレースを使用するダウンストリームサービスがある場合は、モバイルアプリでこの機能を有効にする必要があります。これにより、ルートスパン（開始モバイルアプリ）が、InfiniteTracingによって追跡される残りのスパンに含まれるようになります。

この設定を行うには、 [Infinite Tracingの手順](/docs/distributed-tracing/infinite-tracing/set-trace-observer) を参照して、トレースオブザーバーを作成し、スパンをレポートするモバイルアプリ（データソース）を選択します。

## データを探す [#find-data]

モバイルスパンは、そのスパンがトレースの一部である [New Relic distributed tracing UI](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) に表示されます。

ここでは、データを検索したり、問い合わせたりするためのヒントをご紹介します。

* エンドユーザーが作成したトレースは[、NewRelicの分散トレースUI](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one)で見つけることができます。

* ディストリビューティッド（分散）トレーシングのUIでは、エンドユーザースパンは<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}}>で示されます。</img>アイコン。

* スパンの属性を見るには、UI で [a span を選択します。](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details)

* [](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details)
  [スパンは ](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details)[スパンデータ](/attribute-dictionary/?event=Span) として報告され、 [New Relic](/docs/using-new-relic/data/understand-data/query-new-relic-data) で照会することができます。

* クエリのヒント

  * `mobileApp.name`をモバイルアプリ名に設定して、名前でクエリします。
  * `mobileApp.name is not null`を含む少なくとも1つのモバイルアプリスパンを含むトレースをクエリします。
  * `appName is not null`を使用して少なくとも 1 つのバックエンド アプリを含むトレースをクエリします。
  * 前の 2 つの条件を組み合わせて、モバイル スパンとバックエンド スパンの両方を含むトレースを照会します。

たとえば、特定のアプリのモバイルスパンを検索するには：

```sql
SELECT count(*) FROM Span WHERE mobileApp.name = 'YOUR_APP_NAME' SINCE 1 day ago
```

モバイルスパンをバックエンドのAPMスパンに接続するトレースを検索するには：

```sql
SELECT * FROM Span WHERE mobileApp.name IS NOT NULL AND appName IS NOT NULL SINCE 1 day ago
```

## トラブルシューティング [#troubleshooting]

想定される場所にモバイルスパンが表示されない場合は、以下の考えられる原因を確認してください：

* **ディストリビューティッド（分散）トレーシングが無効になっています。**`FeatureFlag.DistributedTracing`を使用して`disableFeature`を呼び出していないことを確認してください。[ディストリビューティッド（分散）トレーシングの設定方法](#setup)をご覧ください。
* **AnalyticsEventsは無効になっています。**ヘッダーは引き続き送信されますが、関連する`MobileRequest`/`MobileRequestError`イベントは送信されません。[ディストリビューティッド（分散）トレーシングの設定方法](#setup)をご覧ください。
* **リクエストは自動的にインストゥルメントされていません。**Volley、`WebView`、または`OkHttp`、Apache `HttpClient`、`HttpURLConnection`、Retrofit以外のライブラリを介して行われたrequestsには、[手動での伝播](#manual)が必要です。[どのrequestsにディストリビューティッド（分散）トレーシングが自動的に適用されるか](#automatic-instrumentation)をご覧ください。
* **バックエンドのAPMエージェントが古すぎます。**受信側サービスのAPMエージェントがW3Cトレースコンテキストをまだサポートしていない場合、アプリのトレースにリンクする代わりに新しいトレースを開始します。[APMエージェントの最小バージョン](#headers)を確認してください。
* **プロキシまたはゲートウェイがヘッダーを削除しています。**アプリとバックエンドの間にあるものはすべて、`traceparent`および`tracestate`を変更せずに通過させる必要があります。
* **信頼できるアカウントキーが一致しないため、`tracestate`は破棄されます。**バックエンドサービスがモバイルアプリとは異なるNew Relicアカウントに属している場合は、そのアカウントが同じ信頼関係にあることを確認してください。そうでない場合、`tracestate`エントリは無視される可能性があります。

より広範なディストリビューティッド（分散）トレーシングの問題については、[トラブルシューティング](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data)をご覧ください。
