Rubyエージェントのエラーコレクターを設定して、エラーのキャプチャ方法、無視または想定内として処理するエラー、およびエラーイベントのサンプリング方法をカスタマイズします。

## エラーコレクター [#error-collector]

エージェントは、デフォルトでは、すべてのアンキャッチャー例外を収集して報告します。これらの設定オプションにより、エラー収集をカスタマイズすることができます。

無視されたエラーと予想されるエラーの[詳細については、APM のエラー分析に関するこのページを参照してください](/docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected/)。`NewRelic::Agent.notice_error` Ruby メソッドを介して予想されるエラーを設定[するには、Ruby エージェント API を参照してください](/docs/agents/ruby-agent/api-guides/sending-handled-errors-new-relic/)。

## 受信トレイ構成のエラー [#errors-inbox-configuration]

次の環境変数のいずれかを設定すると、ソフトウェアのどのバージョンでエラーが発生したかを特定するのに役立ちます。

* `NEW_RELIC_METADATA_SERVICE_VERSION` デプロイされているコードのバージョンを含む`tags.service.version`をイベントデータに作成します。このバージョンは多くの場合、`1.2.3`などのセマンティックバージョンですが、そうでない場合もあります。
* `NEW_RELIC_METADATA_RELEASE_TAG` リリースタグ（`v0.1.209`または`release-209`など）を含む`tags.releaseTag`をイベントデータに作成します。
* `NEW_RELIC_METADATA_COMMIT` コミットSHAを含む`tags.commit`をイベントデータに作成します。SHA全体を使用することも、先頭7文字（例：`734713b`）のみを使用することもできます。

[Errors Inbox](/docs/errors-inbox/version-tracking/)は、ソフトウェアのどのバージョンでエラーが発生しているかを自動追跡します。
