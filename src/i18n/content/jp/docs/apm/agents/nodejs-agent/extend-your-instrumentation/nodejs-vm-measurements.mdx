New RelicのNode.jsエージェントは、Node.js仮想マシン（VM）から主要な[メトリックタイムスライスデータ](/docs/data-analysis/metrics/analyze-your-metrics/data-collection-metric-timeslice-event-data)を収集します。これらのメトリクスは、Node.js VMの動作に関するインサイトを提供し、アプリケーションのパフォーマンスを向上させるのに役立ちます。エージェントはCPUメトリクスも収集します。これらは多くの場合、ガベージコレクション（GC）メトリクスと一緒に分析されます。

## 何が必要 [#requirements]

エージェントの[リリース14.11.0](docs/release-notes/agent-release-notes/nodejs-release-notes/node-agent-14-11-0)以降、エージェントにはJavaScriptネイティブのVMメトリクス収集ルーチンが直接組み込まれています。このリリース以前は、ガベージコレクション、メモリ、CPUに関連するNode.js VMのメトリクス時間区切りデータを収集するために、エージェントには[追加のネイティブモジュール](https://www.npmjs.com/package/@newrelic/native-metrics)が必要でした。

組み込みのメトリクス収集機能を利用するために、最新のエージェントリリースにアップデートすることをお勧めします。このドキュメントの残りの部分ではそのように想定しており、廃止されたネイティブモジュールについては言及しません。

## Node.jsのVMデータを見る [#view-data]

Node.js VM データを含む厳選されたチャートを表示するには、 <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; APM &amp; services &gt; (select an app) &gt; Node VMs**</DNT>に移動してください。 詳細については、 [Node.js VM の統計ページ](/docs/agents/nodejs-agent/supported-features/node-vms-statistics-page)を参照してください。

データは[メトリクスとイベント](/docs/query-your-data/explore-query-data/data-explorer/introduction-data-explorer)でも利用できます。

## 測定内容 [#garbage]

<Callout variant="tip">
Node.js のすべてのバージョンですべてのデータを収集できるわけではありません。一般に、Node.js の最新の LTS バージョンを使用している場合、最も完全なデータを取得できます。
</Callout>

<Collapser id="time-in-garbage-collection" title="ガベージコレクションの時間">
Node.js プロセスがガベージ コレクション (V8 で使用されるすべてのタイプ) に費やした時間。時間は、 `GC/System/Pauses`として累積メトリックとして測定され、 `GC/<type>`としてガベージ コレクション タイプごとにバケット化されます。

ガベージコレクションの種類には次のようなものがあります。

<table>
<thead>
<tr>
<th style={{ width: "250px" }}>
<DNT>
**GC type**
</DNT>
</th>

<th>
<DNT>
**Description**
</DNT>
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
`Scavenge`
</td>

<td>
最も一般的なガベージコレクションの方法です。Node.jsは通常、VMがアイドル状態になるたびに、これらのうちの1つを起動します。
</td>
</tr>

<tr>
<td>
`MarkSweepCompact`
</td>

<td>
V8が行うガベージコレクションの中で最も重いタイプです。このような現象が多く見られる場合は、プロセス内のオブジェクトの数を減らすか、V8のヒープ制限を増やす必要があります。
</td>
</tr>

<tr>
<td>
`IncrementalMarking`
</td>

<td>
段階的なガベージコレクションで、コレクションとアプリケーションロジックを連動させ、アプリケーションの一時停止時間を短縮します。Node.js v6以上でのみ使用可能。
</td>
</tr>

<tr>
<td>
`ProcessWeakCallbacks`
</td>

<td>
ガベージコレクションが行われた後、V8は、解放されたオブジェクトのために登録された弱参照コールバックを呼び出します。この測定は、あるガベージコレクションにおいて、最初の弱いコールバックの開始から最後のコールバックの終了までです。Node.js v6以上でのみ使用可能です。
</td>
</tr>
</tbody>
</table>

`Memory/Physical`
</td>

<td>
Node.js プロセスによって使用される物理メモリの合計 (MB 単位)。`process.memoryUsage().rss` Node.js API を使用して記録されます。
</td>
</tr>

<tr>
<td>
`Memory/Heap/Max`
</td>

<td>

</td>
</tr>

<tr>
<td>
`Memory/Heap/Used`
</td>

<td>
アプリによって現在使用されている V8 ヒープの量 (MB 単位)。`process.memoryUsage().heapUsed` Node.js API を使用して記録されます。
</td>
</tr>

<tr>
<td>
`Memory/Heap/Free`
</td>

<td>
割り当てられているが使用されていないV8メモリーの量（MB単位）。これは派生メトリックです（ `heapTotal` - `heapUsed` ）。
</td>
</tr>

<tr>
<td>
`Memory/NonHeap/Used`
</td>

<td>
V8ヒープ以外のメモリの量（MB単位）。これは派生メトリックです（ `rss` - `heapTotal` ）。このメトリックは、V8ヒープ外のメモリリークを見つけるのに役立ちます。たとえば、バッファまたはストリームを使用します。
</td>
</tr>
