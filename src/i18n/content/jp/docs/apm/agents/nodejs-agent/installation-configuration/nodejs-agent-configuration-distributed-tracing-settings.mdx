## クロスアプリケーショントレース（廃止） [#cross-app-tracing]

[クロスアプリケーショントレーシング](/docs/apm/transactions/cross-application-traces/introduction-cross-application-traces)を制御するNode.jsエージェントの変数は、通常はご利用のアプリケーションの`newrelic.js`設定ファイルの`cross_application_tracer`セクションに表示されます。

<Callout variant="important">
クロスアプリケーション トレーシングは[ディストリビューティッド（分散）](/docs/enable-distributed-tracing)トレーシングに代わって非推奨となり、将来のエージェント バージョンでは削除される予定です。
</Callout>

</Callout>

## ディストリビューティッド（分散）トレーシング [#dt-main]

[ディストリビューティッド（分散）トレーシング](/docs/intro-distributed-tracing)では、リクエストが経由する分散システムのパスを見ることができます。設定ファイルを介して設定する場合は、以下のオプションを`distributed_tracing`セクションに配置してください。Node.jsエージェント8.3.0以降では、デフォルトでオンになっています。

<Callout variant="important">
ディストリビューティッド（分散）トレーシングを有効にすると、[クロスアプリケーショントレーシング](#cross-app-tracing)が無効になり、他のAPM機能に影響します。有効にする前に、[移行ガイド](/docs/transition-guide-distributed-tracing)を読んでください。[Node.jsエージェントのバージョン4.7.0以降が必要です](/docs/agents/nodejs-agent/installation-configuration/upgrade-nodejs-agent)。
</Callout>

ディストリビューティッド（分散）トレーシングの設定の詳細については、[Node.jsアプリケーションのディストリビューティッド（分散）トレーシングを有効にする](/docs/apm/agents/nodejs-agent/installation-configuration/distributed-tracing-nodejs-agent)を参照してください。

ルートスパンのサンプリングの判断方法を制御します。ルートスパンとは、リモートの親を持たないトランザクションのスパン（受信した`traceparent`または`newrelic`のディストリビューティッド（分散）トレーシングヘッダーがないもの）のことです。有効な値は、次のとおりです。

* `adaptive` （デフォルト）：標準で備わっているNew Relicの適応型サンプリングアルゴリズムを使用します。
* `always_on`：すべてのスパンをサンプリングします。
* `always_off`：スパンをサンプリングしません。
* `trace_id_ratio_based`：トレースの一定割合をサンプリングします。対象はトレースIDに基づいて決定論的に選定されます。

たとえば、設定ファイルを使って設定する場合は次のように記述します。

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    root: 'always_on'
  }
}
```

`trace_id_ratio_based`に設定する場合は、`ratio`（`0`から`1`までの数値）も指定する必要があります。

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    root: {
      trace_id_ratio_based: {
        ratio: 0.5
      }
    }
  }
}
```

または、環境変数を使って設定します。

```ini
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT=trace_id_ratio_based
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT_TRACE_ID_RATIO_BASED_RATIO=0.5
```

`adaptive`に設定すると、このサンプラーのみを対象に、サンプリングターゲット（1分あたり1～120トランザクション）を任意に上書きできます。

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    root: {
      adaptive: {
        sampling_target: 50
      }
    }
  }
}
```

または、環境変数を使って設定します。

```ini
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT=adaptive
NEW_RELIC_DISTRIBUTED_TRACING_SAMPLER_ROOT_ADAPTIVE_SAMPLING_TARGET=50
```
</Collapser>

traceparentヘッダーに`01`のsampledフラグがある場合、これはスパンのサンプリングを処理する方法を制御します。設定可能な文字列値は次のとおりです。

* `adaptive` （デフォルト）：標準で備わっているNew Relicの適応型サンプリングアルゴリズムを使用します。
* `always_on`：すべてのスパンをサンプリングします。
* `always_off`：スパンをサンプリングしません。
* `trace_id_ratio_based`：トレースの一定割合をサンプリングします。対象はトレースIDに基づいて決定論的に選定されます。

両方が適用可能な場合、この設定が[`remote_parent_not_sampled`](#dt-sampler-remote-parent-not-sampled)よりも優先されます。

たとえば、設定ファイルでこれを有効にするには、次のものを使用します：

```js
distributed_tracing: {
  enabled: true,
  sampler: {
    remote_parent_sampled: 'always_on'
  }
}
```

`trace_id_ratio_based`に設定する場合は、`ratio`の値を`0`～`1`の範囲で指定する必要があります。`adaptive`に設定すると、このサンプラーのみを対象に、サンプリングターゲットを任意に上書きできます。また、[`sampler.root`](#dt-sampler-root)のオブジェクト形式と環境変数の例に従って、`root`を`remote_parent_sampled`に置き換えることでもこの設定が可能です。
</Collapser>
