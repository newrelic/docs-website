## OpenTelemetry [#opentelemetry]

Javaエージェントバージョン`9.1.0`以降、OpenTelemetry Tracing、メトリクス、およびログAPIの互換性が追加されました。New Relicの強力な可視性とOpenTelemetryシグナルを組み合わせることで「両方の長所」を兼ね備えたエクスペリエンスを実現できます。

この機能を使用すると、 OpenTelemetry Tracing、メトリクス、ログAPIをNew Relic JavaエージェントAPIと組み合わせることでアプリケーションを直接カスタム計装できるようになり、また、Javaエージェントとこれらすべてを組み合わせて使い慣れたAPMエクスペリエンスを実現できるようになります。さらに、 OpenTelemetryネイティブまたは独立のライブラリ計装を提供する一部のライブラリを使用して、アプリケーションの可視性を向上させることができます。

次の設定オプションを使用して、どのOpenTelemetryシグナルをキャプチャしてNew Relic APMエクスペリエンスに組み込むかを決定します。

```yml
  opentelemetry:
    enabled: false
    logs:
      enabled: true
    metrics:
      enabled: true
      include: "MeterName1,MeterName2"
      exclude: "MeterName3,MeterName4"
    traces:
      enabled: true
      include: "TracerName1,TracerName2"
      exclude: "TracerName3,TracerName4"
```

各OpenTelemetryシグナルを有効にするには「true」に設定し、すべての OpenTelemetryシグナルを無効にするには「false」に設定します。デフォルトは「false」です。

システムプロパティを介して設定できます。

```ini
-Dnewrelic.config.opentelemetry.enabled=false
```

以下の環境変数を使って設定できます：

```ini
NEW_RELIC_OPENTELEMETRY_ENABLED
```

シグナルを含めるOpenTelemetryメーターのコンマ区切りの文字列（例：「MeterName1, MeterName2」）。デフォルトでは、すべてのメーターが含まれます。これにより、エージェント内のデフォルトのメーター除外設定が上書きされ、再度有効になります。

デフォルトは空の文字列です。

システムプロパティを介して設定できます。

```ini
-Dnewrelic.config.opentelemetry.metrics.include=MeterName1,MeterName2
```

以下の環境変数を使って設定できます：

```ini
NEW_RELIC_OPENTELEMETRY_METRICS_INCLUDE
```
