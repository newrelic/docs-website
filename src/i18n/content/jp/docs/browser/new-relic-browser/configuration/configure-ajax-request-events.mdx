[エージェント バージョン 1211](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes/browser-agent-v1211/)以降では、ページによって行われたすべてのネットワークrequestsは`AjaxRequest`イベントとして記録されます。どのrequestsを記録し、どのデータをキャプチャするかを構成できます：

* **[拒否リスト](#deny-list)**：AJAXトラッキングから除外するドメインとURLをフィルタリングします。
* **[ペイロードのキャプチャ](#enable-payload-capture)**: 障害のデバッグのために、完全なリクエストとレスポンスのデータを記録します。

## 拒否リスト [#deny-list]

デフォルトでは、アプリケーションによって行われたすべてのネットワークrequestsの`AjaxRequest`イベントが記録されます。

* すべてのイベントの記録を停止するには、単数の`*` (アスタリスク) ワイルドカード文字を追加します。
  * 例： `*`
* サイト全体のイベントの記録を停止するには、ドメイン名を追加します。
  * 例： `mywebsite.com`
* 特定のページのイベントの記録を停止するには、ドメインとパスを追加します。
  * 例： `mywebsite.com/photos`
* [エージェントバージョン1.307.0](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes/browser-agent-v1.307.0/)以降、`*` (アスタリスク) が見つかる場所であればどこでも、任意の長さの文字列と一致します。
  * 例: `mywebsite.com/shop/*` (パスの場合)、 `*.mywebsite.com` (サブドメインの場合)、 `mywebsite.com/*/shop/*/checkout` (URL の途中の文字列の場合)。

URLのプロトコル、ポート、検索、およびハッシュは、拒否リストによって無視されます。

### 拒否リストへのアクセス [#access-deny-list]

アプリケーションがイベント作成時にフィルタリングするURLの拒否リストを更新するには、アプリの設定ページに移動します。

1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Settings &gt; Application settings**</DNT>に移動します。
2. 「<DNT>**AJAX data capture settings**</DNT>」セクションの「<DNT>**Deny list**</DNT>」フィールドに、アプリに適用するフィルターを追加してください。
3. エージェント設定を更新するには、 <DNT>**Save**</DNT>選択します。
4. [Browser エージェントを再デプロイします](/docs/browser/new-relic-browser/installation/upgrade-browser-agent)(関連付けられている <InlinePopover type="apm" />エージェントを再起動するか、コピー/貼り付けのbrowserインストレーションを更新します)。

### 拒否リストフィルターを検証します [#validation]

追加したフィルターが期待どおりに機能するかどうかを検証するには、フィルターに一致する`AjaxRequest`イベントに対して NRQL クエリを実行します。

```sql
FROM AjaxRequest SELECT * WHERE requestUrl LIKE '%example.com%'
```

## ペイロードキャプチャデータ [#payload-capture]

<Callout variant="important">
  ペイロードのキャプチャには、[Browserエージェントのバージョン1.317.0以降](/docs/release-notes/new-relic-browser-release-notes/browser-agent-release-notes)が必要です。
</Callout>

すべてのrequestsまたは失敗したrequestsに対してのみ、ペイロードキャプチャを有効にすることができます。有効にすると、Browserエージェントは、許可されたすべてのドメインのすべてのAJAX呼び出しに対するリクエストとレスポンスのペイロードをキャプチャします。これは、レスポンス本文に隠されているエラーなど、メタデータだけでは確認できない障害をデバッグするのに役立ちます。

AJAXペイロードキャプチャを有効にすると、Browserエージェントは`AjaxRequest`イベントに次の属性を追加します：

* `requestBody`：リクエストのペイロード。
* `requestHeaders`：JSON形式のリクエストヘッダー。
* `requestQuery`：JSON形式のURLクエリパラメーター。
* `responseBody`：レスポンスペイロード。
* `responseHeaders`：JSON形式のレスポンスヘッダー。
* `ajaxRequest.id`：各AJAXリクエストの一意の識別子。

すべてのペイロードデータ属性は4,096バイトで切り捨てられます。切り捨てが発生した場合、コンテンツが切り取られたことを示すために、最後の4バイトが`...`に置き換えられます。

### ペイロードキャプチャの有効化 [#enable-payload-capture]

次のいずれかの方法を使用して、ペイロードキャプチャを有効にすることができます：

<CollapserGroup>
  <Collapser id="enable-ui" title="New Relicプラットフォーム経由で有効にする">
    ペイロードキャプチャを有効にするには：

    1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Settings &gt; Application settings**</DNT>に移動します。

    2. <DNT>**AJAX data capture settings**</DNT>セクションで、<DNT>**Capture payload for allowed domains**</DNT>トグルを有効にし、キャプチャモードを選択します：

       * <DNT>**Capture only failure responses**</DNT>：ステータスコードが`0`、コードが`400`以上、または`response body`にGraphQLエラーシグネチャがあるrequestsのペイロードのみをキャプチャします。
       * <DNT>**Capture all responses**</DNT>：成功したものを含む、すべてのrequestsのペイロードをキャプチャします。これを使用して、成功ステータスで返されたGraphQLエラーなど、レスポンス本文に隠された障害をデバッグします。

       <Callout variant="important">
         <DNT>**Capture all responses**</DNT> requestsのペイロードキャプチャを有効にすると、データの取り込みが増加する可能性があります。成功したレスポンスをキャプチャする必要が特にない限り、<DNT>**Capture only failure responses**</DNT>モードを使用してください。
       </Callout>

    3. 変更を適用するには<DNT>**Save**</DNT>をクリックします。
  </Collapser>

  <Collapser id="configure-nerdgraph" title="NerdGraph経由で設定する">
    [NerdGraph APIを使用して、ペイロードキャプチャ設定をクエリおよび更新](/docs/apis/nerdgraph/examples/browser-monitoring-config-nerdgraph/#configure-payload-capture)できます。

    `capture_payloads`設定では、以下の値が利用可能です：

    * `"none"`：ペイロードデータをキャプチャしません。これがデフォルト設定です。
    * `"failures"`：ステータスコードが`0`、コードが`400`以上、または`response body`にGraphQLエラーシグネチャがあるrequestsのペイロードのみをキャプチャします。
    * `"all"`：ステータスコードに関係なく、すべてのrequestsのペイロードデータをキャプチャします。
  </Collapser>

  <Collapser id="configure-init" title="JavaScript経由で設定する">
    コピー/ペーストまたはNPMインストレーション方法を使用している場合、JavaScript設定で直接ペイロードキャプチャを設定できます。

    #### コピー＆ペーストでインストール

    エージェントローダーの前に、ブラウザの設定に`ajax.capture_payloads`設定を追加します：

    ```js
    window.NREUM.init = {
        ...<other init properties>...,
        ajax: {
          deny_list: ["bam.nr-data.net"],
          capture_payloads: 'failures' // or 'none', 'all'
        }
    }
    ```

    #### NPMのインストール

    Browserエージェントを初期化する際に、`ajax.capture_payloads`設定を追加します：

    ```js
    import { BrowserAgent } from '@newrelic/browser-agent/loaders/browser-agent'

    const options = {
      init: {
        ...<other init properties>...,
        ajax: {
          deny_list: ["bam.nr-data.net"],
          capture_payloads: 'failures' // or 'none', 'all'
        }
      },
      info: { ... },
      loader_config: { ... }
    }

    new BrowserAgent(options)
    ```

    #### キャプチャモード

    `capture_payloads`設定では、以下の値が利用可能です：

    * `"none"`：ペイロードデータをキャプチャしません。これがデフォルト設定です。
    * `"failures"`：ステータスコードが`0`、コードが`400`以上、または`response body`にGraphQLエラーシグネチャがあるrequestsのペイロードのみをキャプチャします。
    * `"all"`：ステータスコードに関係なく、すべてのrequestsのペイロードデータをキャプチャします。
  </Collapser>
</CollapserGroup>

ペイロードキャプチャを初めて有効にすると、New Relicは一般的な機密データを保護するためにベースラインの難読化ルールを自動的に追加します：

* [**クレジットカード番号**](/docs/browser/new-relic-browser/configuration/obfuscate-browser-agent-data/#ccn)：主要なクレジットカードの形式（Visa、MasterCard、American Express、Discoverなど）を検出し、マスクします。
* [**社会保障番号**](/docs/browser/new-relic-browser/configuration/obfuscate-browser-agent-data/#ssn)：SSNパターンを検出してマスクします

New Relicプラットフォームで難読化ルールを設定して、機密データがNew Relicに送信される前にマスクすることができます。難読化ルールの詳細については、[Browserエージェントデータの難読化](/docs/browser/new-relic-browser/configuration/obfuscate-browser-agent-data)を参照してください。

ペイロードキャプチャ設定を有効にした後、次のページでキャプチャされたペイロードデータを表示できます：

* [AJAXリクエストの詳細](/docs/browser/browser-monitoring/browser-pro-features/ajax-page-identify-time-consuming-calls)
* [ページビュー](/docs/browser/new-relic-browser/browser-pro-features/page-views-examine-page-performance)
* [セッションのリプレイ](/docs/browser/browser-monitoring/browser-pro-features/session-replay/get-started)

### ペイロードのキャプチャと拒否リストの相互作用 [#payload-deny-list]

ペイロードのキャプチャは、既存の拒否リストを尊重します。任意のAJAXリクエストの場合：

* URLが拒否リストにある場合、イベントは完全に破棄され、メタデータやペイロードはキャプチャされません。
* URLが拒否リストにない場合、ペイロードのキャプチャ設定に基づいて、エージェントはリクエストとレスポンスのペイロードをキャプチャし、データをNew Relicに送信する前に難読化ルールを適用します。
