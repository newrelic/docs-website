外形監視は、選択したロケーション — New Relicが世界中で運用しているパブリックロケーション、または独自のネットワーク内の[プライベートロケーション](/docs/synthetics/synthetic-monitoring/guides/private-location-capabilities/) — から、アプリケーションとエンドポイントに対して自動化されたスケジュールされたチェックを実行します。各モニターは、一定の間隔で実際のリクエストまたはユーザージャーニーを実行し、その結果を報告するため、障害、速度低下、およびフローの破損をできるだけ早く発見できます。

これらのチェックは常に実行されているため、アプリケーション（APIエンドポイントとブラウザジャーニーの両方）の可用性、機能性、およびパフォーマンスのベースラインを提供します。APMとブラウザ監視は実際のトラフィックがどのように動作したかを示しますが、Syntheticモニターは、トラフィックの少ない地域やリリースがユーザーに届く前を含め、重要な機能が常に期待どおりに動作するかどうかを示します。

## サンプルの使用事例 [#sample-use-cases]

New Relicの外形監視は、可用性を広くカバーする軽量な稼働時間のpingから、最も複雑なフローを実行する完全にスクリプト化されたAPIおよびブラウザのジャーニーまで、幅広い範囲に及びます。プライベートロケーションから実行されるスクリプト化されたモニターでは、さらに一歩進んで、独自のnpmモジュールでランタイムを拡張し、ネットワークから到達可能なほぼすべてのものをチェックできます。

### Ping [#ping]

実行できる最も経済的なチェックは、エンドポイントがオンラインであり、十分に高速であることを確認するスケジュールされたHTTPリクエストです。何百ものエンドポイント全体で頻繁に実行できるほど経済的であるため、幅広い可用性と稼働時間のレポートの基盤となります。機能の破損ではなく停止を検出するため、アプリが機能していることの証明としてではなく、最初のシグナルとして扱ってください。

<CollapserGroup>
  <Collapser id="ping-use-cases" title="使用例をご覧ください">
    一般的なチェック：

    * **エンドポイント到達可能：**スケジュールに従ってリクエストを送信し、認証やスクリプトなしで、正常なステータスコード（200、または任意の2xxや3xx）が返されることを確認してください。
    * **レスポンスタイムの閾値：**エンドポイントの応答が閾値より遅い場合にチェックを失敗させることで、レイテンシの低下を早期に集計します。
    * **本文の文字列一致：** レスポンス本文に`ok`や`"status":"healthy"`などの予期される文字列が含まれている場合にのみパスします。
  </Collapser>
</CollapserGroup>

開始するには、モニターの作成については[モニターの追加と編集](/docs/synthetics/synthetic-monitoring/using-monitors/add-edit-monitors/)を、レポート内容の確認については[Pingモニター結果の表示](/docs/synthetics/synthetic-monitoring/using-monitors/view-ping-monitor-results/)をご覧ください。

### Scripted API [#scripted-api]

Node.jsと`$http` APIを使用してrequestsをチェーンし、ステップ間で認証と状態を伝達し、ステータス、ペイロード、タイミングに`assertion`を使用します。これを使用して、サービスレイヤーで実際のビジネストランザクションをエンコードするか、依存しているが制御していないサードパーティの依存関係を監視します。プライベートロケーションでは、独自のモジュールに`require()`を使用して、非HTTPプロトコルに到達するか、既存のSDKを使用してモデル、ベクターストア、およびcloud APIを呼び出します。

<CollapserGroup>
  <Collapser id="scripted-api-use-cases" title="使用例をご覧ください">
    一般的なチェック：

    * **ネットワークとプロトコル：**非HTTP接続を開き、`assert`を使用して接続が成功することを確認します。TCPまたはTLSポートが開いていることの確認、DNSレコードの解決、WebSocketまたはMQTTメッセージの交換、またはLDAP、FTP/SFTP、およびSMTPへの到達を行います。
    * **証明書とセキュリティ：**クライアント証明書（相互TLS）を使用してAPIを呼び出し、`assert`を使用して認証されることを確認したり、SAMLメタデータに埋め込まれた証明書を検証したり、メールIPをブロックリストと照合したりします。
    * **クラウドおよびSaaSインテグレーション：**AWS、Azure、またはGCPで認証し、`assert`を使用してリソースが存在することを確認します。たとえば、S3エクスポートオブジェクトが存在することを確認したり、Azure Key Vaultのシークレットを読み取ったりします。
    * **パフォーマンスとSEO：** <DNT>PageSpeed</DNT> APIを介して<DNT>Lighthouse</DNT>監査を実行してスコアを記録するか、スケジュールに従って<DNT>Search Console</DNT>メトリクスを取得します。
    * **New Relicデータ（NRDB/NRQL）：**モニターからNRQLクエリを実行し、結果が閾値を超えるか、前の期間から逸脱した場合に集計します。
  </Collapser>
</CollapserGroup>

始めるには、最初のスクリプトの作成については[合成APIテストの作成](/docs/synthetics/synthetic-monitoring/scripting-monitors/write-synthetic-api-tests/)を、ライブラリを使用して拡張することについては[Node.jsモジュールのインポート](/docs/synthetics/synthetic-monitoring/scripting-monitors/import-nodejs-modules/)をご覧ください。

### シンプルブラウザ [#simple-browser]

実際のChromeまたはFirefoxインスタンスでページを読み込むため、単なるステータスコードだけでなく、JavaScript、アセット、CDN、キャッシュを実行してチェックを行います。pingでは決して検出できない、レンダリングをブロックするスクリプトエラー、バンドルの欠落、エラーを出さずに失敗するサードパーティのタグを捕捉します。コードは不要なため、多数のページにわたって実際のレンダリングカバレッジを最も迅速に取得できる方法です。

<CollapserGroup>
  <Collapser id="simple-browser-use-cases" title="使用例をご覧ください">
    一般的なチェック：

    * **ページの可用性：**グローバルロケーションからページを開き、期待されるコンテンツが読み込まれ、レンダリングされることを確認してください。
    * **コンテンツと要素のチェック：**製品ページの「カートに追加」ボタンなど、特定の要素またはテキストが存在することを確認するには、`assert`を使用します。
    * **Core Web Vitals：**ページロードタイムを測定し、予算（たとえば3秒）を超えた場合にチェックを失敗させます。
  </Collapser>
</CollapserGroup>

始めるには、モニターの作成については[モニターの追加と編集](/docs/synthetics/synthetic-monitoring/using-monitors/add-edit-monitors/)を、モバイルおよびタブレットのビューポートのテストについては[デバイスエミュレーション](/docs/synthetics/synthetic-monitoring/using-monitors/device-emulation/)をご覧ください。

### スクリプト化ブラウザ [#scripted-browser]

複数ステップの、条件付きの、認証されたジャーニーを通じて、`$browser` API（Seleniumウェブドライバ）を使用して実際のブラウザを駆動します。1つのチェックで、サインイン、検索、チェックアウト、または重要な内部フローなど、ブラウザからデータ層までのパス全体を検証します。これは最も遅く、最もリソースを消費するモニターであるため、収益と信頼をもたらすジャーニーに限定して使用してください。

<CollapserGroup>
  <Collapser id="scripted-browser-use-cases" title="使用例をご覧ください">
    一般的なチェック：

    * **BrowserのUXとコンテンツ：**ページを操作してリンクをクロールし、リンク切れがある場合は失敗させるか、ファイルのダウンロード時間を計測するか、ダウンロードしたPDF内のテキストを検証します。
    * **CloudとSaaSのインテグレーション：**ジャーニー中にスクリーンショットをキャプチャし、S3などのcloudストレージにアップロードします。
  </Collapser>
</CollapserGroup>

始めるには、基本事項について[スクリプト化ブラウザモニターの概要](/docs/synthetics/synthetic-monitoring/scripting-monitors/introduction-scripted-browser-monitors/)を、完全な`$browser` APIについて[スクリプト化ブラウザリファレンス](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetic-scripted-browser-reference-monitor-versions-chrome-100/)をご覧ください。

スクリプト化APIおよびスクリプト化ブラウザモニターはJavaScriptを実行するため、独自のnpmモジュールで`require()`を使用できます。上記のプロトコル、クラウドSDK、およびドキュメントのチェックも同じ方法で実行します。プライベートロケーションでは、これらのモジュールは独自のレジストリからインストールされ、ネットワーク内で実行されます。キーやトークンは、[セキュアな認証情報](/docs/synthetics/synthetic-monitoring/using-monitors/store-secure-credentials-scripted-browsers-api-tests/)として保存してください。

## カスタムコードと拡張性 [#programmable-monitoring]

New Relicのスクリプト化されたモニターは固定機能のチェッカーではありません — プログラムです。コードで表現できるものであれば、監視できます。つまり、カスタムロジックをチェーンし、独自のNew Relicデータをクエリし、独自のコードとモジュールでモニターを拡張できるということです。

### 独自のコードの持ち込み [#bring-your-own-code]

スクリプト化されたモニターを使用すると、独自のモジュールで`require()`を使用できます。[プライベートロケーション](/docs/synthetics/synthetic-monitoring/guides/private-location-capabilities/)では、`package.json`を含むディレクトリをマウントし、ジョブマネージャーが起動時に`npm install`を実行するため、任意のnpmパッケージや内部ライブラリがモニターの一部になります — これは、非HTTPプロトコル（TCP、WebSocket、MQTT、LDAP、SFTP、SMTP）との通信、クラウドプロバイダーのSDKの呼び出し、または独自のフォーマットのデコードを行うのに十分です。モニターの適用範囲は、固定された機能リストではなく、パッケージエコシステム全体と独自のコードです — そのため、新しいニーズが生じた場合は、機能リクエストを提出するのではなく、依存関係を追加することになります。

### ネットワーク内でプライベートに実行します [#run-privately]

スクリプト化モニターは外形監視ジョブマネージャーで実行されるため、独自のネットワーク内の[プライベートロケーション](/docs/synthetics/synthetic-monitoring/guides/private-location-capabilities/)から実行できます。つまり、パブリックインターネットに何も公開することなく、独自のレジストリからインストールされた独自のモジュールを使用して内部システムをテストできるということです。

### テレメトリーの異常に関するアラートを受け取る [#monitor-telemetry]

スクリプト化されたAPIモニターは、独自のNew Relicデータをクエリし、カスタムスクリプトで定義したロジックに基づいて結果を集計できます。これにより、長期間にわたるデータのクエリや、以前の期間との結果の比較など、アラート条件に適合しないシナリオをカバーできます：

* **データのクエリ：**[ セキュアな認証情報](/docs/synthetics/synthetic-monitoring/using-monitors/store-secure-credentials-scripted-browsers-api-tests/) として保存されたAPIキーを使用して、[ でNerdGraph APIを呼び出し`$http`](https://docs.newrelic.com/docs/synthetics/synthetic-monitoring/scripting-monitors/write-synthetic-api-tests/#get-nerdgraph-example) 、NRQLクエリを実行します。
* **偏差の集計：** 結果が閾値を超えるか、前の期間から逸脱した場合にチェックを失敗させるには、`assertion`または同様のロジックを使用します。
