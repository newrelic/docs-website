`newrelic-install` Chefクックブックを使用して、SQL Serverの監視用にNRDOT Collectorをインストールして構成できます。`newrelic-install::default`レシピを実行すると、クックブックはコレクターをインストールし、監視IDを作成または承認し、コレクターを構成します。

<Callout variant="tip" title="ガイド付きインストレーション">
代わりにNew Relic UIからこれをインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>に移動してください。画面上の指示に従って、インテグレーションをセットアップします。このページでは、手動インストレーションについてのみ説明します。
</Callout>

<Steps>
<Step>
## 前提条件 [#prerequisites]

* 有効な[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)を持つNew Relicアカウント。

* New Relic [アカウントID](/docs/accounts/accounts-billing/account-structure/account-id)。

* Microsoft SQL Server 2017以降。

* Chef 15以降が必要です。

* **セルフホスト型SQL Server：**

  * **SQL Server認証：**Windows、Ubuntu、またはRHEL/CentOSのコレクター・ホスト、および`sysadmin`サーバー・ロール（または同等）のログインとそのパスワード。
  * **Windows認証またはgMSA：**Windowsのコレクター・ホスト、および権限を付与するWindowsドメイン・アカウント（またはgMSA）。

* **AWS RDS上のSQL Server：**

  * RDSエンドポイントへのネットワーク接続（RDSセキュリティ・グループ内のSQL Serverポートで許可されたインバウンド・アクセス）を持つWindows、Ubuntu、またはRHEL/CentOSのコレクター・ホスト、およびRDSマスター・ユーザー名とパスワード。
  * **Windowsドメイン認証またはgMSA：**AWS Managed Microsoft Active Directoryドメインにすでに参加しているWindowsコレクターホストおよびRDSインスタンス。

* ターゲットリージョンに対応する[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのネットワーク接続。
</Step>

<Step>
## Chefクックブックをダウンロードします。 [#chef-download-cookbook]

Chef Supermarketから`newrelic-install` [Chefクックブック](https://supermarket.chef.io/cookbooks/newrelic-install)をchef-repoディレクトリにダウンロードします：

```bash
knife supermarket install newrelic-install
```
</Step>

<Step>
## デフォルトの属性を置き換えます [#chef-configure]

`attributes/default.rb`のデフォルトの属性をアカウントの詳細に置き換えてください：

<CollapserGroup>
<Collapser id="chef-host-sql" title="セルフホスト型 - SQL Server認証">
このクックブックは、単一のコレクターから1つ以上のSQL Serverインスタンスをモニターします。単一のホスト/ポート/資格情報のセットの代わりに、ノード上にすでに存在している必要がある2つのファイルを読み取ります：モニターする各インスタンスをリストした**インスタンスファイル**（YAML）と、一致するようにインデックス付けされた、それぞれの管理者ログインとパスワードを含む**シークレットファイル**（`KEY=VALUE`）です。

1. ノード上にインスタンス・ファイルを作成してください。このコレクターでモニターするSQL Serverインスタンスごとに1つのエントリを追加してください。単一のインスタンスのみを実行している場合は、1つのエントリのみを追加してください：

   ```yaml
   instances:
     - host: localhost
       port: 1433
       login_name: newrelic
   ```

2. インスタンスファイルの順序と一致するようにインデックス付けされた、各インスタンスの管理者ログインとパスワードを含むシークレットファイルをノード上に作成してください。管理者ログインは、`sysadmin`ロール（または同等のもの）のメンバーである必要があります：

   ```bash
   NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
   NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
   ```

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mssql'
]
default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node>
default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']    = <path to the secrets file (KEY=VALUE per instance) on the node>
# See all available targets at: https://github.com/newrelic/chef-install
```

<Collapser id="chef-host-winauth" title="セルフホスト型 — Windows認証またはgMSA">
このターゲットは、Windowsコレクターホストでのみサポートされています。SQLログインの代わりにWindows認証（`integrated security=true`）を使用し、**インスタンスファイル**（YAML、インスタンスごとに`host`/`port`、シークレットファイルなし：1つのWindows IDがすべてのインスタンスをモニターします）を使用して、単一のコレクターから1つ以上のSQL Serverインスタンスをモニターします。

このファイルはノード上にすでに存在している必要があり、単一のインスタンスのみを実行している場合はエントリは1つだけです。`host`と`port`のみが必要です（`login_name`は不要です）：

```yaml
instances:
  - host: sql01.contoso.com
    port: 1433
  - host: sql02.contoso.com
    port: 1433
```

名前付きインスタンスの場合は、`host\INSTANCE`ではなく、`host`とその静的TCPポートを使用してください。

```ruby
default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
default['newrelic_install']['targets'] = [
  'nrdot-collector-mssql-winauth'
]
default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']    = <1 Basic, 2 Advanced, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']        = <1 for Windows Domain Auth, 2 for gMSA, default 1>
default['newrelic_install']['env']['NR_CLI_MSSQL_WINAUTH_LOCATION'] = <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']   = <path to the instances YAML file on the node>
default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']      = <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']     = <password for that account; required only for Windows Domain Auth on a different host>
default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']     = <gMSA account, DOMAIN\gMSAName$; gMSA only>
# See all available targets at: https://github.com/newrelic/chef-install
```

## データを探す、使う [#find]

データの収集が開始されると、New Relic UIを通じて包括的なSQL Serverデータベース監視にアクセスできます。

New Relic で SQL Server データベース エンティティを見つけるには:

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>に移動します。

2. **<DNT>Entity type</DNT>**ドロップダウンから<DNT>**MSSQL instance**</DNT>を選択し、<DNT>**Apply**</DNT>をクリックします。

3. エンティティのリストから SQL Server データベースを選択します。

   NRDOTを使用してSQL Serverの監視をセットアップした後、次のことができます：

   * データベースのメトリクスを視覚化する[カスタムダッシュボードを作成する](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)
   * クリティカルデータベースパフォーマンス閾値の[アラートを設定する](/docs/alerts/create-alert/create-alert-condition/alert-conditions/)
   * New Relicのクエリ機能を使用して、[データを探索](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)します
</Step>
</Steps>
