Windowsドメイン認証を使用して、物理サーバー、仮想マシン、およびスタンドアロンのWindowsインストレーションを含むWindowsセルフホスト環境で、NRDOT Collectorを使用してMicrosoft SQL Serverの監視をセットアップしてください。Windows RDS環境でモニターするには、[Windows RDS計装](/docs/opentelemetry/db360/mssql/windows-rds-domain)を参照してください。

<Callout variant="tip" title="ガイド付きインストレーション">
  代わりにNew Relic UIからこれをインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>に移動してください。画面上の指示に従って、インテグレーションをセットアップします。このページでは、手動インストレーションについてのみ説明します。
</Callout>

このページでは、Windowsドメイン認証について説明します。お使いの環境で別の認証方法を使用している場合は、[SQL Server認証](/docs/opentelemetry/db360/mssql/windows-hosted-sql)または[gMSA](/docs/opentelemetry/db360/mssql/windows-hosted-gmsa)をご覧ください。

<Steps>
  <Step>
    ## 前提条件 [#prerequisites-domain]

    Windows認証を使用してNRDOTでMicrosoft SQL Serverを監視する前に、環境が以下の要件を満たしていることを確認してください：

    * 有効な[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)を持つNew Relicアカウント。

    * ご利用のリージョンの[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのネットワーク接続。

    * SQL Serverの要件：

      * SQL Server 2017以降。
      * SQL Serverへの管理アクセス（`sysadmin`ロールまたは同等のロール）。
      * ポート`1433`またはカスタムポートでのコレクターとSQL Server間のネットワーク接続。
      * SQL Server Management Studio（SSMS）または `sqlcmd` ユーティリティ。

    * Active Directory を備えた Windows ドメイン環境。

    * SQL Server は Windows 認証を受け付けるように設定されています。

    * 適切な SQL Server の権限を持つドメインユーザーアカウント。
  </Step>

  <Step>
    ## NRDOT Collectorをインストールする [#setup-domain]

    PowerShellを使用してNRDOT Collectorをダウンロードし、インストールします：

```powershell
    [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
    $NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
    $WebClient = New-Object System.Net.WebClient
    $WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
    $WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
    Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
    Get-Service nrdot-collector -ErrorAction SilentlyContinue
```
  </Step>

  <Step>
    ## 監視ユーザーを作成する [#user-domain]

    SQL ServerがWindows認証用に設定されていることを確認し、接続を検証します。

    <CollapserGroup>
      <Collapser id="same-host" title="同じWindowsホスト上のCollector">
        1. Windowsユーザー名を取得します：

```sql
           SELECT SYSTEM_USER;
```

        2. 次のコマンドを実行して、Windowsユーザーに必要な権限が付与されていることを確認します。すべての`<ACCOUNT_USERNAME>`を、ステップ1で取得したユーザー名に置き換えます：

```sql
           DECLARE @TargetUser SYSNAME = '<ACCOUNT_USERNAME>'; -- <-- Set your Windows user here

           -- 1. Create the checklist of required permissions from your script
           DECLARE @Checklist TABLE (Scope NVARCHAR(50), [Database] SYSNAME, [Permission] NVARCHAR(128));

           INSERT INTO @Checklist VALUES
           ('Server', 'ALL', 'VIEW SERVER STATE'),
           ('Server', 'ALL', 'VIEW ANY DEFINITION'),
           ('Server', 'ALL', 'VIEW ANY DATABASE');

           INSERT INTO @Checklist
           SELECT 'Database Role', [name], 'db_datareader' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0
           UNION ALL
           SELECT 'Database Explicit', [name], 'VIEW DATABASE STATE' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0
           UNION ALL
           SELECT 'Database Explicit', [name], 'VIEW DEFINITION' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0;

           -- 2. Gather existing explicit permissions
           WITH ExplicitPerms AS (
               SELECT 'Server' AS Scope, CAST('ALL' AS NVARCHAR(128)) COLLATE DATABASE_DEFAULT AS [Database], p.permission_name COLLATE DATABASE_DEFAULT AS [Permission]
               FROM sys.server_permissions p JOIN sys.server_principals l ON p.grantee_principal_id = l.principal_id WHERE l.name = @TargetUser
               UNION ALL
               SELECT 'Database Role', d.name COLLATE DATABASE_DEFAULT, r.name COLLATE DATABASE_DEFAULT
               FROM sys.databases d CROSS APPLY (SELECT dp_role.name FROM sys.database_role_members drm JOIN sys.database_principals dp_role ON drm.role_principal_id = dp_role.principal_id JOIN sys.database_principals dp_user ON drm.member_principal_id = dp_user.principal_id JOIN sys.server_principals sp ON dp_user.sid = sp.sid WHERE sp.name = @TargetUser) r WHERE d.state = 0
               UNION ALL
               SELECT 'Database Explicit', d.name COLLATE DATABASE_DEFAULT, p.permission_name COLLATE DATABASE_DEFAULT
               FROM sys.databases d CROSS APPLY (SELECT db_p.permission_name FROM sys.database_permissions db_p JOIN sys.database_principals dp_user ON db_p.grantee_principal_id = dp_user.principal_id JOIN sys.server_principals sp ON dp_user.sid = sp.sid WHERE sp.name = @TargetUser) p WHERE d.state = 0
           )
           -- 3. Output the exact verification matrix
           SELECT
               chk.Scope,
               chk.[Database],
               chk.[Permission] AS [Required Permission],
               CASE
                   WHEN exp.[Permission] IS NOT NULL THEN 'GRANTED'
                   WHEN IS_SRVROLEMEMBER('sysadmin', @TargetUser) = 1 THEN 'PASSED (via SysAdmin Role)'
                   ELSE 'MISSING'
               END AS [Verification Status]
           FROM @Checklist chk
           LEFT JOIN ExplicitPerms exp ON chk.Scope = exp.Scope AND chk.[Database] = exp.[Database] AND chk.[Permission] = exp.[Permission]
           ORDER BY chk.Scope, chk.[Database], chk.[Permission];
```

        3. （オプション）必要な権限がない場合は、SSMSまたは`sqlcmd`ユーティリティから次のコマンドを実行して、Windowsアカウントに必要な権限を付与します。すべての`<ACCOUNT_USERNAME>`を、ステップ1で取得したWindowsユーザー名に置き換えます：

```sql
           USE [master];
           GO

           -- 1. Grant Instance-level permissions to your Windows Account
           GRANT VIEW SERVER STATE TO [<ACCOUNT_USERNAME>];
           GRANT VIEW ANY DEFINITION TO [<ACCOUNT_USERNAME>];
           GRANT VIEW ANY DATABASE TO [<ACCOUNT_USERNAME>];
           GO

           -- 2. Loop through all user databases and grant read/visibility permissions
           DECLARE @name SYSNAME;
           DECLARE @sql NVARCHAR(MAX);

           DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
           SELECT [name]
           FROM [master].[sys].[databases]
           WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
             AND [state] = 0; -- Only online databases

           OPEN db_cursor;
           FETCH NEXT FROM db_cursor INTO @name;

           WHILE @@FETCH_STATUS = 0
           BEGIN
               BEGIN TRY
                   PRINT 'Granting permissions on database: ' + @name;

                   -- Create the database user mapping if it doesn't exist, then grant roles
                   SET @sql = '
                       USE [' + @name + '];
                       IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<ACCOUNT_USERNAME>'')
                       BEGIN
                           CREATE USER [<ACCOUNT_USERNAME>] FOR LOGIN [<ACCOUNT_USERNAME>];
                       END;
                       GRANT VIEW DATABASE STATE TO [<ACCOUNT_USERNAME>];
                       GRANT VIEW DEFINITION TO [<ACCOUNT_USERNAME>];
                       ALTER ROLE db_datareader ADD MEMBER [<ACCOUNT_USERNAME>];';

                   EXEC sp_executesql @sql;
                   PRINT 'Success: ' + @name;
               END TRY
               BEGIN CATCH
                   PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
               END CATCH

               FETCH NEXT FROM db_cursor INTO @name;
           END

           CLOSE db_cursor;
           DEALLOCATE db_cursor;
           GO
```
      </Collapser>

      <Collapser id="different-host" title="別のWindowsホスト上のCollector">
        1. SQL Server Management Studio（SSMS）で次のスクリプトを実行し、gMSAアカウントのログインを作成して、必要な権限を付与します。`<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>`のすべての出現箇所を、実際のドメインとアカウント名に置き換えます。

```sql
        USE [master];
        GO

        CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FROM WINDOWS;
        GO

        GRANT VIEW ANY DATABASE   TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GO

        -- Grant access to all databases
        DECLARE @name SYSNAME;
        DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
          SELECT [name] FROM [master].[sys].[databases]
          WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
            AND [state] = 0;
        OPEN db_cursor;
        FETCH NEXT FROM db_cursor INTO @name;
        WHILE @@FETCH_STATUS = 0
        BEGIN
          BEGIN TRY
            EXEC('USE [' + @name + '];
            IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>'')
            BEGIN
              CREATE USER [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
            END;
            GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];');
          END TRY
          BEGIN CATCH
            PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
          END CATCH
          FETCH NEXT FROM db_cursor INTO @name;
        END
        CLOSE db_cursor;
        DEALLOCATE db_cursor;
        GO
```

        2. PowerShellを使用して、ドメインユーザーとして実行するようにNRDOT Collectorサービスを設定します。`YOUR_DOMAIN\YOUR_USER_ACCOUNT`をドメインとアカウント名に置き換えます：

```powershell
           # Configure service to use domain account
           # The space after obj= and password= is required syntax for sc.exe
           sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

           # Restart the service
           Restart-Service nrdot-collector
```

        3. サービスIDを検証します：

```powershell
           Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
           # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
```
      </Collapser>
    </CollapserGroup>

    <Callout variant="tip">
      データベースの認証情報などの機密情報を安全に管理するには、[シークレット管理](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management)ツールに保存してください。
    </Callout>
  </Step>

    ## NRDOT Collectorを構成する [#configure-domain]

    1. アドミニストレーターとしてPowerShellで`mssql-config.yaml`という名前の設定ファイルを作成します：

```powershell
    New-Item -Path "C:\Program Files\nrdot-collector\mssql-config.yaml" -ItemType File
```

    2. 前の手順で作成した`mssql-config.yaml`ファイルに以下の設定を追加します：

    <Callout variant="tip">
      `logs`パイプラインは、コレクターのデバッグログや内部エージェントのログを転送しません。クエリテキスト、実行プラン、およびサンプルデータを含む、SQL Serverのクエリテレメトリーを送信します。`nrsqlserver`レシーバーは、OpenTelemetryのログレコードとして出力される`db.server.query_sample`、`db.server.top_query`、`db.server.query_plan`、および`db.server.top_procedure`イベントを通じて、このテレメトリーをキャプチャします。

      `db.server.top_procedure` イベントには、`sys.dm_exec_procedure_stats.total_spills` のサポートが導入された SQL Server 2017 CU3 以降が必要です。以前のバージョンでは、このイベントはデータを出力せず、エラーをログに記録します。他のイベントは影響を受けません。`sys.dm_exec_procedure_stats` にアクセスするには、`VIEW SERVER STATE`（または SQL Server のバージョンによっては `VIEW SERVER PERFORMANCE STATE`）が必要です。さらに、すべてのユーザーデータベースで `OBJECT_NAME` と `OBJECT_SCHEMA_NAME` を正しく解決するには `VIEW ANY DEFINITION` が必要であり、初期セッションを設定するには `CONNECT SQL` が必要です。「[監視ユーザーの作成](#user-domain)」で構成したアカウントには、すでに3つの権限すべてが付与されています。

  <Step>
    ## Windowsサービスレジストリの更新 [#update-registry-domain]

    1. 次のいずれかの方法を使用して、新しい`mssql-config.yaml`ファイルを使用するようにWindowsサービスレジストリを更新します：

       * **PowerShellの場合：**アドミニストレーターとして次のコマンドを実行します：

```powershell
         Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
```

       * **コマンドプロンプトの場合：**PowerShellが利用できない場合は、代わりにコマンドプロンプトを使用し、アドミニストレーターとして次のコマンドを実行します：

```bash
       sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
```

    2. NRDOT Collectorの設定を検証して、正しくフォーマットされ、適切に機能することを確認します：

```bash
       & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
```

       <Callout variant="tip">
         アプリケーションパフォーマンスをデータベース操作と関連付けるには、データベースサービス識別を設定できます。詳細については、[データベースサービス識別の設定](/docs/opentelemetry/db360/capabilities/db-apm/)を参照してください。
       </Callout>
  </Step>

  <Step>
    ## NRDOT Collectorを再起動します [#restart-domain]

    設定を更新した後、NRDOT Collectorサービスを再起動します：

```bash
    net stop nrdot-collector
    net start nrdot-collector
```

    <Callout variant="tip">
      新しい設定を確実に適用するために、設定を変更した後は常にNRDOT Collectorサービスを再起動してください。
    </Callout>
  </Step>

  <Step>
    ## データを探す、使う [#find-domain]

    データの収集が開始されると、New Relic UIを通じて包括的なSQL Serverデータベース監視にアクセスできます。

    New Relic で SQL Server データベース エンティティを見つけるには:

    1. <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>に移動します。

    2. **<DNT>Entity type</DNT>**ドロップダウンから<DNT>**MSSQL instance**</DNT>を選択し、<DNT>**Apply**</DNT>をクリックします。

    3. エンティティのリストから SQL Server データベースを選択します。

       NRDOTを使用してSQL Serverの監視をセットアップした後、次のことができます：

       * データベースのメトリクスを視覚化する[カスタムダッシュボードを作成する](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)
       * クリティカルデータベースパフォーマンス閾値の[アラートを設定する](/docs/alerts/create-alert/create-alert-condition/alert-conditions/)
       * New Relicのクエリ機能を使用して、[データを探索](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)します
  </Step>
</Steps>
