Microsoft SQL Server用のOpenTelemetry Collectorを使用して、インスタンスをモニターできます。OpenTelemetry Collectorは、Microsoft SQL Serverからテレメトリーデータを収集してNew Relicに送信する、コミュニティがサポートするプロジェクトです。

デフォルトでは、OpenTelemetry CollectorはMicrosoft SQL Serverから限られたメトリクスを収集します。クエリのパフォーマンス、待機時間、セッション、およびその他の高度なメトリクスを送信するには、OpenTelemetry Collectorを設定する必要があります。このガイドでは、Microsoft SQL Serverから高度なメトリクスを収集し、New Relicに送信するように設定する方法を説明します。

<Steps>
  <Step>
    ## 前提条件 [#prerequisites]

    * システムにOpenTelemetry Collector Contrib（`otelcol-contrib`）がインストールされ、設定されています。最新のリリースは、[OpenTelemetry Collectorのリリース](https://github.com/open-telemetry/opentelemetry-collector-releases/releases)ページからダウンロードできます。
  </Step>

  <Step>
    ## UIメトリクスを有効化 [#enable]

    `otelcol-contrib`設定ファイルにメトリクスを追加して有効にすることで、New Relicプラットフォームのエクスペリエンスを向上させることができます。このセクションで提供されている設定を使用すると、New Relicプラットフォームの以下のページにデータを入力できます。

    * <DNT>Overview</DNT>
    * <DNT>Query performance</DNT>
    * <DNT>Wait events</DNT>
    * <DNT>Sessions</DNT>
    * <DNT>Clients</DNT>
    * <DNT>Stored procedures</DNT>

    <CollapserGroup>
      <Collapser id="overview" title="Overviewページメトリクスを有効化">
        <DNT>Overview</DNT>ページには、データベース数、I/O、レイテンシ、操作、tempdbスペース、デッドロック率などの主要なメトリクスを含む、Microsoft SQL Serverインスタンスの概要が表示されます。

        New Relicプラットフォームの<DNT>Overview</DNT>ページにデータを入力するには、`otelcol-contrib`設定ファイルに以下の設定を追加します：

        ```yaml
        receivers:
            sqlserver:

                # Enable comprehensive database metrics
              metrics:
                sqlserver.database.count:
                  enabled: true
                sqlserver.database.io:
                  enabled: true
                sqlserver.database.latency:
                  enabled: true
                sqlserver.database.operations:
                  enabled: true
                sqlserver.database.tempdb.space:
                  enabled: true
                sqlserver.database.tempdb.version_store.size:
                  enabled: true
                sqlserver.deadlock.rate:
                  enabled: true
                sqlserver.os.wait.duration:
                  enabled: true
                sqlserver.processes.blocked:
                  enabled: true
                sqlserver.memory.grants.pending.count:
                  enabled: true
                sqlserver.memory.area:
                  enabled: true
        ```
      </Collapser>

      <Collapser id="query-performance" title="クエリパフォーマンス、セッション、待機、クライアント、およびストアドプロシージャのメトリクスを有効にします。">
        New Relicプラットフォームの以下のページにデータを入力できます：

        * <DNT>Query performance</DNT>：Microsoft SQL Serverインスタンスで実行されているクエリに関する詳細情報を、以下のタブに表示します：

          * <DNT>Normalized queries</DNT>：実行時間と平均CPU時間のグラフを表示します。
          * <DNT>Query samples</DNT>：開始時間、期間、待機タイプ、待機時間、データベース、DBユーザー、クライアントホストを含む個々のクエリ実行を表示します。
          * <DNT>Stored procedures</DNT>: 上位のストアドプロシージャのパフォーマンスメトリクスを表示します。

        * <DNT>Wait events</DNT>：Microsoft SQL Serverインスタンスで発生している待機イベントに関する情報を表示します。「Query samples」ビューには、現在待機中のクエリが、その待機タイプおよび待機時間とともに表示されます。

        * <DNT>Sessions</DNT>：セッション数、セッション状態、平均アクティブセッション期間、ブロックされたセッション、個々のセッションの詳細など、Microsoft SQL Serverインスタンスに接続されているセッションに関する情報を表示します。

        * <DNT>Clients</DNT>：アクティブなセッション、ブロックされたセッション、接続されているDBユーザー、クライアントホストの詳細など、Microsoft SQL Serverインスタンスに接続されているクライアントに関する情報を表示します。

        * <DNT>Stored procedures</DNT>: 上位のストアドプロシージャのパフォーマンスメトリクスを表示します。

        これらのページにデータを入力するには、`otelcol-contrib`設定ファイルに次の設定を追加します。

        ```yaml
        receivers:
            sqlserver:

                events:
                    db.server.query_sample:
                        enabled: true
                    db.server.top_query:
                        enabled: true
                    db.server.query_plan:
                        enabled: true
                    db.server.top_procedure:
                        enabled: true

                # Top query collection configuration
                top_query_collection:
                    lookback_time: 60s
                    max_query_sample_count: 1000
                    top_query_count: 250
                    collection_interval: 60s

                # Query sample collection configuration
                query_sample_collection:
                    max_rows_per_query: 100

                # Top stored procedure collection configuration
                top_procedure_collection:
                    max_procedure_sample_count: 1000
                    top_procedure_count: 250
                    collection_interval: 60s
        ```
      </Collapser>

      <Collapser id="waits" title="「Wait event」タブですべての待機を有効化">
        「All waits」ビューには、待機カテゴリおよび個々の待機タイプ別に分類されたインスタンスレベルの待機時間が表示されます。

        New Relicプラットフォームの<DNT>Wait event</DNT>タブで<DNT>All waits</DNT>を有効にするには、`otelcol-contrib`設定ファイルに次の設定を追加します。

        ```yaml
        receivers:
            sqlserver:

                metrics:
                    sqlserver.os.wait.duration:
                        enabled: true
        ```
      </Collapser>
    </CollapserGroup>
  </Step>

  <Step>
    ## OpenTelemetry Collectorを再起動する

    設定の変更を適用するには、次のコマンドを実行してOpenTelemetry Collectorを再起動してください：

    ```powershell
    Restart-Service -Name "otelcol-contrib"
    ```
  </Step>
</Steps>
