Windows上のNew Relic Distribution of OpenTelemetry（NRDOT）コレクターを利用し、データベースのメトリクス、クエリ分析、およびシステムヘルスデータを用いて、Azure SQL データベースのパフォーマンスをモニターします。

<Callout variant="tip">
Linuxでコレクターを実行するには、[Linux上のAzure SQL データベース](/docs/opentelemetry/db360/mssql/azure-sql-linux)を参照してください。
</Callout>

<Steps>
<Step>
## 前提条件 [#prerequisites]

* 有効な[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)を持つNew Relicアカウント。

* ご利用のリージョンの[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのネットワーク接続。

* Azure SQL Databaseの要件：

  * Azure SQL論理サーバーおよびデータベース。
  * サーバー管理者のログインとパスワード（または、`master`でログインを作成してサーバーロールを管理できる別のアカウント）。
  * サーバーのファイアウォールルール、仮想ネットワークルール、またはプライベートエンドポイントを介した、コレクターホストからポート`1433`のサーバーへのネットワークアクセス。サーバーがプライベートエンドポイントを使用する場合、サーバー名はコレクターホストからプライベートIPアドレスに解決される必要があります。

* Collectorホストの要件：PowerShell、アドミニストレーターアクセス、および`sqlcmd`またはSQL Server Management Studio（SSMS）を備えたホスト（たとえば、Azure VM）。
</Step>

<Step>
## NRDOT Collectorをインストールする [#setup]

Azure SQLサーバーに到達できるホストにNRDOT Collectorをインストールします。

PowerShellをアドミニストレーターとして実行します：

```powershell
[Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
$NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
$WebClient = New-Object System.Net.WebClient
$WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
$WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
Get-Service nrdot-collector -ErrorAction SilentlyContinue
```
</Step>

<Step>
## 監視ユーザーの作成と権限の付与 [#user]

Azure SQL データベースでは、`GRANT VIEW SERVER STATE` および同様のインスタンスレベルの権限付与は許可されていません。代わりに、`master`の組み込みサーバーロールにログインを追加してから、モニターする各データベースにユーザーを作成します。

1. `nr-grant-permission-master.sql` という名前のファイルを作成し、`<YOUR_PASSWORD>` を任意のパスワードに置き換えてください：

   ```sql
   CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
   GO
   ALTER SERVER ROLE [##MS_ServerStateReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DefinitionReader##] ADD MEMBER [newrelic];
   ALTER SERVER ROLE [##MS_DatabaseConnector##] ADD MEMBER [newrelic];
   GO
   ```

2. サーバー管理者として、`master` データベースに対して実行してください。`<YOUR-SERVER>` をサーバー名（たとえば、`myserver.database.windows.net`）に置き換えてください：

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-master.sql
   ```

3. `nr-grant-permission-db.sql`という名前のファイルを作成します。

   ```sql
   CREATE USER [newrelic] FOR LOGIN [newrelic];
   GO
   GRANT VIEW DATABASE STATE TO [newrelic];
   GO
   ```

4. モニターする**各**データベースに対して実行します。`<YOUR_DATABASE>`をデータベース名に置き換えます：

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission-db.sql
   ```

   以下の表は、各ロールが必要な理由を示しています：

   | ロールまたは権限                   | のために使用される                                                                      |
   | -------------------------- | ------------------------------------------------------------------------------ |
   | `##MS_ServerStateReader##` | サーバーレベルの動的管理ビュー、たとえば `sys.dm_exec_query_stats` や `sys.dm_exec_procedure_stats` |
   | `##MS_DefinitionReader##`  | 上位のプロシージャとインデックス統計のオブジェクト名およびスキーマ名の解決                                          |
   | `##MS_DatabaseConnector##` | インデックスの物理統計を収集するためのデータベースへの接続                                                  |
   | `VIEW DATABASE STATE`      | 次のようなデータベーススコープの動的管理ビュー `sys.dm_db_resource_stats`                             |

5. （オプション）`master` データベースからサーバーロールを確認してください：

   ```bash
   sqlcmd -S <YOUR-SERVER> -d master -U <YOUR_ADMIN_USER> -P '<YOUR_ADMIN_PASSWORD>' -C -Q "SELECT r.name AS [Role], l.name AS [Login] FROM sys.server_role_members rm JOIN sys.server_principals r ON rm.role_principal_id = r.principal_id JOIN sys.sql_logins l ON rm.member_principal_id = l.principal_id WHERE l.name = 'newrelic';"
   ```

   出力には3つのロールすべてが表示されます。

6. （オプション）監視ユーザーとして接続し、データベースの権限を確認します：

   ```bash
   sqlcmd -S <YOUR-SERVER> -d <YOUR_DATABASE> -U newrelic -P '<YOUR_PASSWORD>' -C -Q "SELECT TOP 1 * FROM sys.dm_db_resource_stats; SELECT TOP 1 * FROM sys.dm_exec_query_stats;"
   ```

   権限エラーは、権限付与が不足していることを意味します。

<Callout variant="tip">
データベースの認証情報などの機密情報を安全に管理するには、[シークレット管理](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management)ツールに保存してください。
</Callout>
</Step>

<Step>
## NRDOT Collectorを構成する [#configure-collector]

1. Administrator \[アドミニストレーター]としてPowerShellで設定ファイルを作成します：

   ```powershell
   New-Item -Path "C:\Program Files\nrdot-collector\mssql-config.yaml" -ItemType File
   ```

2. 以下の設定を追加します。`<YOUR_PASSWORD>`、`<YOUR-SERVER>`、`<YOUR_DATABASE>`、`<YOUR_LICENSE_KEY>`、およびOTLPエンドポイントを、ご自身の値に置き換えてください：

   ```yaml
   receivers:
     nrsqlserver:
       collection_interval: 15s
       # datasource replaces username, password, server, and port.
       datasource: "sqlserver://newrelic:<YOUR_PASSWORD>@<YOUR-SERVER>:1433?database=<YOUR_DATABASE>"

       metrics:
         sqlserver.database.io:
           enabled: true
         sqlserver.database.latency:
           enabled: true
         sqlserver.database.operations:
           enabled: true
         sqlserver.database.tempdb.space:
           enabled: true
         sqlserver.database.tempdb.version_store.size:
           enabled: true
         sqlserver.deadlock.rate:
           enabled: true
         sqlserver.os.wait.duration:
           enabled: true
         sqlserver.processes.blocked:
           enabled: true
         sqlserver.memory.grants.pending.count:
           enabled: true
         sqlserver.database.file.size:
           enabled: true
         sqlserver.memory.area:
           enabled: true

       events:
         db.server.query_sample:
           enabled: true
         db.server.top_query:
           enabled: true
         db.server.query_plan:
           enabled: true
         db.server.top_procedure:
           enabled: true

       top_query_collection:
         lookback_time: 60s
         max_query_sample_count: 1000
         top_query_count: 250
         collection_interval: 60s
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       query_sample_collection:
         max_rows_per_query: 100
         collect_full_query_text: true
         allowed_comment_keys:
           - nr_service_guid

       top_procedure_collection:
         max_procedure_sample_count: 1000
         top_procedure_count: 250
         collection_interval: 60s

       resource_attributes:
         db.system.version:
           enabled: true
         sqlserver.db.edition:
           enabled: true

   processors:
     memory_limiter:
       check_interval: ${env:NR_MEM_LIMITER_CHECK_INTERVAL:-1s}
       limit_mib:       ${env:NR_MEM_LIMITER_LIMIT_MIB:-200}
       spike_limit_mib: ${env:NR_MEM_LIMITER_SPIKE_MIB:-50}

   exporters:
     otlp:
       endpoint: https://otlp.nr-data.net:4318
       headers:
         api-key: <YOUR_LICENSE_KEY>
       tls:
         insecure: false
       compression: gzip
       sending_queue:
         enabled: true
         sizer: bytes
         queue_size: 100_000_000
         num_consumers: 10
         batch:
           sizer: bytes
           max_size: 1_000_000
           min_size: 0
           flush_timeout: 5s

   service:
     telemetry:
       metrics:
         level: none
     pipelines:
       metrics:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
       logs:
         receivers: [nrsqlserver]
         processors: [memory_limiter]
         exporters: [otlp]
   ```

<Callout variant="tip">
* `datasource`の値は接続URLです。パスワードに英字、数字、および`- . _ ~ ! $ * + ,`以外の文字が含まれている場合は、それらをURLエンコードしてください。
* コレクターは、`database=`で指定された単一のデータベースに接続します。同じサーバー上の複数のデータベースをモニターするには、「[マルチレシーバーの設定](/docs/opentelemetry/db360/mssql/multi-receiver#multi)」で説明されているように、それぞれに個別のレシーバーを使用します。
* Always-On、フェールオーバー・クラスタ、および一部のラッチとtempdbのメトリクスは、Azure SQL データベースでは利用できず、データは返されません。
* `logs`パイプラインは、コレクターのデバッグログではなく、SQL Serverのクエリテレメトリー（クエリテキスト、実行プラン、およびサンプル）を伝送します。
</Callout>
</Step>

<Step>
## NRDOT Collectorの設定を更新 [#update]

1. Windows サービスの参照先を新しい設定ファイルに設定してください。アドミニストレーターとしてPowerShellで実行してください：

   ```powershell
   Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
   ```

2. （オプション）設定を検証します：

   ```powershell
   & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
   ```
</Step>

<Step>
## NRDOT Collectorを再起動します [#restart]

```powershell
net stop nrdot-collector
net start nrdot-collector
```

権限または接続エラーがないか、Windows アプリケーション・イベント・ログを確認してください：

```powershell
Get-EventLog -LogName Application -Source nrdot-collector -Newest 20
```
</Step>

<Step>
## データを探す、使う [#find]

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>に移動します。
2. **<DNT>Entity type</DNT>**ドロップダウンから<DNT>**MSSQL instance**</DNT>を選択し、<DNT>**Apply**</DNT>をクリックします。
3. エンティティのリストからAzure SQL データベースを選択してください。
</Step>
</Steps>
