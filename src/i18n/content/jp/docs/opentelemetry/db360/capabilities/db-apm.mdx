SQLクエリのコメント機能により、アプリケーションとデータベースのパフォーマンスをシームレスに関連付けることができます。このメカニズムにより、New Relic Distribution of OpenTelemetry（NRDOT）データベースレシーバーは、特定のデータベース負荷、スロークエリ、またはブロッキングイベントの原因となっているサービスを正確に特定できるようになります。

<Callout variant="important">
New Relicは、アプリケーションのデータベース接続アドレスとポートを、データベース監視エージェントの接続アドレスとポートと照合することで、New Relic アプリケーションパフォーマンス監視（New Relic APM）とデータベースエンティティをリンクします。両側がまったく同じアドレスとポートを報告する場合、このリンクは確実に機能します。ただし、アプリケーションがロードバランサーやプロキシを経由してトラフィックをルーティングする場合、または2つのコンポーネントが異なるアドレス形式（IPアドレスとドメイン名など）を使用する場合、自動リンクが失敗する可能性があります。
</Callout>

## 前提条件 [#prerequisites]

* Javaエージェント：バージョン`9.4.0`以降。
* .NETエージェント：バージョン`10.54.0`以降。

## APM-DBの関連付けを有効にする [#enable-correlation]

New Relicがアプリケーションサービスとデータベースのアクティビティを関連付けられるように、APMエージェントでSQLクエリのコメント機能を有効にしてください。

### Javaエージェントの場合 [#enable-correlation-java]

この相関関係を有効にするには、Javaエージェント設定ファイル（`newrelic.yml`）の`transaction_tracer`セクションに`sql_metadata_comments`プロパティを追加します。詳細については、[Javaエージェント設定ドキュメント](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/)を参照してください。

```yaml
transaction_tracer:
  sql_metadata_comments:
    enabled: true
```

### .NETエージェントの場合 [#enable-correlation-dotnet]

この相関関係を有効にするには、.NETエージェント設定ファイル (`newrelic.config`) の`transactionTracer`セクションに`sqlMetadataComments`プロパティを追加します。詳細については、[.NETエージェント設定ドキュメント](/docs/apm/agents/net-agent/configuration/net-agent-configuration/)を参照してください。

<CollapserGroup>
<Collapser id="option1" title="オプション1：環境変数経由（スクリプト）">
実行可能ファイルをリリースするためにスタートアップスクリプトまたはラッパースクリプトを使用している場合は、`NEW_RELIC_TRANSACTION_TRACER_SQL_METADATA_COMMENTS_ENABLED`変数を`1`に設定してください。

```powershell
# Add this environment variable alongside your other CoreCLR / New Relic variables
$env:NEW_RELIC_TRANSACTION_TRACER_SQL_METADATA_COMMENTS_ENABLED = "1"
```
</Collapser>

<Collapser id="option2" title="オプション2：newrelic.config経由">
または、`newrelic.config`ファイルの`<transactionTracer>`ブロック内で直接これを有効にすることもできます：

```xml
<transactionTracer enabled="true" sqlMetadataCommentsEnabled="true" />
```
</Collapser>
</CollapserGroup>

## 使い方 [#how-it-works]

アプリケーションがデータベースに文章を送信すると、 APMエージェントはAPM GUID をコメントとして SQL テキストの先頭に自動的に追加します。 この一般的な業界慣行は、SQL ステートメントの実行ロジックには影響しません。

1. **コメントの先頭に付加**: APMエージェントは、発信SQLの先頭にコメント文字列を付加します(例: `/* nr_service_guid="MTE2MDAzMTl8QVBNfEFQUExJ" */ SELECT * FROM orders...`)。
2. **実行**: データベースは通常どおりクエリを実行します。コメントはデータベースの内部パフォーマンス スキーマ (`sys.dm_exec_requests`や`v$session`など) に保存されます。
3. **抽出**: データベース レシーバーはこれらのクエリ (アクティブ、低速、またはブロッキング) を取得します。
4. **強化**: 受信者はコメントを解析し、 `nr_service_guid`を抽出し、それをディメンションとしてデータベース メトリクスに添付します。

## サービスタグ付けのメリット [#benefits]

サービス メタデータを先頭に追加すると、データベース エコシステムの高精度な可視性が得られます。

* **サービスレベルの帰属**: データベースのCPUやメモリの急増の原因となっているマイクロサービスを即座に確認
* **詳細なスロークエリ分析**：`client_name` でスロークエリログをフィルタリングして、データベースのボトルネックが特定のアプリケーションバージョンに限定されているかどうかを把握します。
* **ブロッキングとデッドロックの解決**: ブロッキングクエリの「所有者」を迅速に特定し、チーム間のトラブルシューティングを迅速化します。
