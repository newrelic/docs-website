`sqlqueryreceiver`は、データベースに対して任意のカスタムSQLクエリを実行し、その結果をメトリクスとしてNew Relicに取り込むことができるOpenTelemetry Collectorレシーバーです。

組み込みの`nroracledbreceiver`/`nrsqlserverreceiver`/`nrmysqlreceiver`/`nrpostgresqlreceiver`メトリクスでカバーされていないデータをモニターする場合は、これを使用してください。エンティティリンク属性が正しく設定されている場合、`sqlqueryreceiver`経由で収集されたカスタムメトリックは、組み込みのレシーバーデータと同じNew Relic内のOracle、SQL Server、MySQL、またはPostgreSQLエンティティの下に表示されます。

## 前提条件 [#prerequisites]

* データソースで構成されたデータベースユーザーは、クエリを実行する予定のすべてのビューまたはテーブルに対する`SELECT`権限を持っている必要があります。
* コレクターのバイナリには、`sqlqueryreceiver`コンポーネントが含まれている必要があります。

      ### 命名規則

      New Relicで正しいエンティティに関連付けるには、メトリクス名が`oracledb.`で始まる必要があります。異なるプレフィックスを持つメトリクスは取り込まれますが、データベースエンティティの下には表示されません。

      ### エンティティ合成

      `resource/add_event_name`および`resource/add_host`プロセッサーを追加して、`server.address`と`server.port`をデータベースレシーバーで使用されるのと同じ値に設定します。これを行わないと、カスタムメトリックはデータベースエンティティにリンクされません。

      `processors:` セクションにプロセッサーを追加してください：

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Pipeline設定

      設定の`service.pipelines:`セクションに、既存のパイプラインと並んで`metrics/custom`パイプラインを追加します：

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_event_name, resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        プロセッサーリストの`batch`の前に、`resource/add_event_name`と`resource/add_host`の両方を追加します。
      </Callout>

      ### データを検証するためのNRQL

      コレクターを再起動した後、以下を実行してカスタムメトリックが到着していることを確認します：

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      ## トラブルシューティング [#troubleshooting]

      | 問題                                        | 原因                                              | 修理                                                                      |
      | ----------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------- |
      | `ORA-00942: table or view does not exist` | データベースユーザーにSELECT権限がありません                       | ユーザーに`SELECT ON <VIEW_NAME>`を付与します。                                     |
      | `missing port in address`                 | `#` URLエンコードされていないユーザー名/パスワード内                  | データソースURLで`#`を`%23`に置き換えてください。                                          |
      | New Relicにデータがありません                       | `server.address`/`server.port`が設定されていないか、一致しません | 正しい値で `resource/add_event_name` および `resource/add_host` プロセッサーを追加してください |
      | データベースエンティティの下にないメトリクス                    | メトリクス名に必須のプレフィックスがありません。                        | メトリクス名が次で始まるようにしてください `oracledb.`                                       |

      上記のいずれの方法でも問題が解決しない場合は、エラーがないかコレクター自体のログを確認してください：

      ```bash
      sudo journalctl -u nrdot-collector -f
      ```

      ### 命名規則

      New Relicで正しいエンティティに関連付けるには、メトリクス名が`sqlserver.`で始まる必要があります。異なるプレフィックスを持つメトリクスは取り込まれますが、データベースエンティティの下には表示されません。

      ### エンティティ合成

      `server.address` と `server.port` をデータベースレシーバーで使用されるのと同じ値に設定するには、`resource/add_host` プロセッサーを追加します。これを行わないと、カスタムメトリックはデータベースエンティティにリンクされません。

      プロセッサを`processors:`セクションに追加してください：

      ```yaml
      processors:
        resource/add_host:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Pipeline設定

      設定の`service.pipelines:`セクションに、既存のパイプラインと並んで`metrics/custom`パイプラインを追加します：

      ```yaml
      service:
        pipelines:
          metrics/custom:
            receivers: [sqlquery]
            processors: [resource/add_host, batch]
            exporters: [otlp]
      ```

      <Callout variant="important">
        プロセッサーリストの`batch`の前に`resource/add_host`を追加します。
      </Callout>

      ### 命名規則

      New Relicで正しいエンティティに関連付けるには、メトリクス名が`mysql.`で始まる必要があります。異なるプレフィックスを持つメトリクスは取り込まれますが、データベースエンティティの下には表示されません。

      ### Pipeline設定

      設定の`service.pipelines:`セクションに、既存のパイプラインと並べて`metrics/custom`パイプラインを追加します：

      ```yaml
      service:
        pipelines:
          metrics/mysql:
            receivers: [nrmysql]
            processors: [batch]
            exporters: [otlp/newrelic]
          metrics/custom:
            receivers: [sql_query/mysql]
            processors: [batch]
            exporters: [otlp/newrelic]
      ```

      ### データを検証するためのNRQL

      コレクターを再起動した後、以下を実行してカスタムメトリックが到着していることを確認します：

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'mysql.%'
      SINCE 1 hour ago
      ```

      New Relicで正しいエンティティに関連付けるには、メトリクス名が`postgresql.`で始まる必要があります。異なるプレフィックスを持つメトリクスは取り込まれますが、データベースエンティティの下には表示されません。

      ### エンティティ合成

      `nrpostgresql` `server.address`と`server.port`からデータベースエンティティを合成します。データベースレシーバーで使用されるのと同じ`server.address`/`server.port`の値を付与するために、`resource/add_host`プロセッサを追加してください。これを行わないと、カスタムメトリックはデータベースエンティティにリンクされません。

      プロセッサを`processors:`セクションに追加してください：

      ```yaml
      processors:
        batch:
        resource/add_host:
          attributes:
            - key: server.address
              value: "<YOUR_DB_HOST>"
              action: upsert
            - key: server.port
              value: "<YOUR_DB_PORT>"
              action: upsert
      ```

      <Callout variant="important">
        `nrpostgresql`パイプラインに`server.address`/`server.port`を設定する`resource/*`プロセッサ（たとえば`resource/postgresql`）がすでにある場合は、複製するのではなく、以下の`metrics/custom`パイプラインで同じプロセッサを再利用してください — 同じエンティティにアタッチするには、両方のレシーバーが同一の値をスタンプする必要があります。
      </Callout>

      ### Pipeline設定

      設定の`service.pipelines:`セクションに、既存のパイプラインと並んで`metrics/custom`パイプラインを追加します：

      ```yaml
      service:
        pipelines:
          metrics/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          logs/postgresql:
            receivers: [nrpostgresql]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
          metrics/custom:
            receivers: [sql_query/postgres]
            processors: [resource/add_host, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        プロセッサーリストの`batch`の前に`resource/add_host`を追加します。
      </Callout>
