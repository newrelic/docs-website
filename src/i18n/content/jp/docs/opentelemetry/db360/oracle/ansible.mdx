`newrelic.newrelic_install` Ansibleロールを使用して、Oracleデータベース監視用のNRDOT Collectorをインストールして構成できます。このロールは、単一のプレイでコレクターをインストールし、監視データベースユーザーを作成し、コレクターを構成します。

<Callout variant="tip" title="ガイド付きインストレーション">
代わりにNew Relic UIからインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>に移動してください。このページでは、手動インストレーションについてのみ説明します。
</Callout>

<Steps>
<Step>
## 前提条件 [#prerequisites]

* 有効な[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)を持つNew Relicアカウント。
* New Relic [アカウントID](/docs/accounts/accounts-billing/account-structure/account-id)。
* Oracleデータベース19c以降。
* Ansible Core 2.13または2.14、Python 3.10、および`ansible.windows`と`ansible.utils`のコレクション。
* セルフホスト型Oracleの場合：SSHユーザーがパスワードプロンプトなしで`sudo su - oracle`を実行できるOracleデータベースホストへのSSHアクセス（エージェント転送付き）を備えたOracle Linux 7、8、または9。
* AWS RDS上のOracleの場合：Debian/UbuntuまたはCentOS/RHEL/OELを実行しているコレクター・ホスト。
* Oracle Autonomousデータベース（ADB）の場合：Debian/UbuntuまたはCentOS/RHEL/OELを実行し、Oracle Instant Client（`sqlplus`）がインストールされて`PATH`上にあるコレクター・ホスト；各インスタンスのエグレスIPがADBアクセス制御リストで許可されていること；および各インスタンスのOracle Walletがダウンロードされ、ターゲット・ホスト上の独自のディレクトリに解凍されていること。
</Step>

<Step>
## 役割をインストールします [#install-role]

```bash
ansible-galaxy install newrelic.newrelic_install
```
</Step>

<Step>
## プレイブックを設定してください [#configure]

<CollapserGroup>
<Collapser id="ansible-host" title="セルフホスト型Oracleデータベース">
このロールは、単一のコレクターから1つ以上のOracleデータベースインスタンス（それぞれSSH経由で到達可能）をモニターします。単一のホスト/コンテナ/資格情報セットの代わりに、ターゲットホストにすでに存在している必要があるインスタンスファイル（YAML）（モニターするすべてのインスタンスをリストしたもの）と、オプションで監視ユーザーのパスワードを自動生成する代わりに固定するためのシークレットファイルを読み取ります。正確なファイル形式については、[CLIインストール](/docs/opentelemetry/db360/oracle/cli/#install)を参照してください。

`playbook.yml`という名前のファイルを作成し、以下の内容をコピーします。`targets`を`oracle-otel`に設定し、プレースホルダーの値を独自の値に置き換えます：

```yaml
- name: Install New Relic NRDOT for Oracle Database
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - oracle-otel
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
    NR_CLI_ORACLE_SECRETS_FILE: <optional path to a secrets file pinning monitoring passwords, on the target host>
    NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
```

<Callout variant="tip">
デバッグロギングを有効にするには、プレイブックの`vars`の下に`verbosity: "debug"`を追加します。
</Callout>

<Collapser id="ansible-rds" title="AWS RDS上のOracleデータベース">
このロールは、セルフホスト型と同じインスタンスファイル/シークレットファイルパターンを使用して、単一のコレクターから1つ以上のRDS Oracleエンドポイントをモニターします（両方のファイルがターゲットホストにすでに存在している必要があります）。`playbook.yml`という名前のファイルを作成し、次のコンテンツをコピーします。`targets`を`oracle-otel-rds`に設定し、プレースホルダーの値を独自の値に置き換えます：

```yaml
- name: Install New Relic NRDOT for Oracle Database on RDS
  hosts: all
  roles:
    - role: newrelic.newrelic_install
  vars:
    targets:
      - oracle-otel-rds
  environment:
    NEW_RELIC_API_KEY: <API key>
    NEW_RELIC_ACCOUNT_ID: <Account ID>
    NEW_RELIC_REGION: <Region>
    NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
    NR_CLI_ORACLE_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
    NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
```

<Callout variant="tip">
デバッグロギングを有効にするには、プレイブックの`vars`の下に`verbosity: "debug"`を追加します。
</Callout>

```yaml
- name: Install New Relic NRDOT for Oracle Autonomous Database

      - oracle-otel-adb

    NEW_RELIC_ACCOUNT_ID: <Account ID>
```

<Callout variant="tip">
