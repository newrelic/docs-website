Dockerで既に実行されているOracleデータベースのインスタンスの兄弟コンテナとして実行されるNew Relic Distribution of OpenTelemetry（NRDOT）Collectorを使用し、データベース監視、クエリ分析、およびシステムヘルスメトリクスを通じて、Oracleデータベースのパフォーマンスに関する包括的なインサイトを取得します。

<Callout variant="tip" title="ガイド付きインストレーション">
  代わりにNew Relic UIからインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>にアクセスしてください。このページでは、Dockerのインストールパスについてのみ説明します。
</Callout>

<Callout variant="tip">
  代わりにこれを大規模に自動化することをお考えですか？Kubernetesの場合は、[Ansibleのインストール](/docs/opentelemetry/db360/oracle/ansible)、[Chefのインストール](/docs/opentelemetry/db360/oracle/chef)、または[Helmチャートのインストール](/docs/opentelemetry/db360/oracle/helm)を参照してください。
</Callout>

## 前提条件 [#prerequisites]

始める前に、次のものがあることを確認してください。

* ホストにインストールされているDocker。
* 内部で`sqlplus`が利用可能な、すでに実行中のOracleデータベースコンテナ（Oracleデータベース`19c`以降）
* そのコンテナの`sys`パスワード。
* 有効なNew Relicの[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)。
* コレクターコンテナから[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのネットワーク接続。

<Steps>
  <Step>
    ## データベースユーザーを設定し、権限を付与します。 [#database-user]

    `docker exec` を使用して Oracle コンテナに対して SQL を実行し、監視ユーザーを作成して、メトリクス、クエリ、およびイベント収集に必要なビューを付与します。マルチテナントのコンテナデータベース（CDB）または単一のプラガブルデータベース（PDB）のいずれかから、デプロイメントに一致するタブを選択します：

    <CollapserGroup>
      <Collapser id="docker-cdb" title="コンテナ・データベース（CDB）">
        これにより、共通ユーザー（`C##`プレフィックスを使用する必要があります）が作成され、CDB配下のすべてのPDBに対する可視性が付与されます。`<YOUR_ORACLE_CONTAINER_NAME>`、`<YOUR_SYS_PASSWORD>`、`<YOUR_DB_USERNAME>`、および`<YOUR_DB_PASSWORD>`をご自身の値に置き換えます：

        ```bash
        docker exec -i <YOUR_ORACLE_CONTAINER_NAME> sqlplus sys/'<YOUR_SYS_PASSWORD>' as sysdba << 'EOF'
        ALTER SESSION SET CONTAINER = CDB$ROOT;

        -- Create the common user and set container-data visibility
        CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>" CONTAINER=ALL;
        GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;

        -- Grant system and dynamic performance views
        GRANT SELECT ON V_$INSTANCE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$DATABASE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CONTAINERS                 TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$DATAFILE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SYSSTAT                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CON_SYSSTAT                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SYSMETRIC                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CON_SYSMETRIC              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SESSION                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$RESOURCE_LIMIT             TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$OSSTAT                     TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SGAINFO                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ROWCACHE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$PARAMETER                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_TABLESPACES               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_FREE_SPACE                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_RECYCLEBIN                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SQL                        TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$LOCK                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SESSION_EVENT              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$PDBS                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_SERVICES                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ASM_DISKGROUP_STAT          TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ASM_DISK_STAT               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

        EXIT;
        EOF
        ```

        <Callout variant="tip">
          共通ユーザーの場合、Oracleでは`C##`プレフィックスが必須です。最後の2つの権限（`V_$ASM_DISKGROUP_STAT`および`V_$ASM_DISK_STAT`）は、[ASMディスクグループおよびディスクのメトリクス](/docs/opentelemetry/db360/oracle/metrics-reference/#asm)を収集する場合にのみ必要です。ASMを使用しない場合は、これらをスキップしてください。
        </Callout>
      </Collapser>

      <Collapser id="docker-pdb" title="プラガブル・データベース（PDB）">
        これにより、単一のターゲットPDB内にローカルユーザーが作成されます。`<YOUR_ORACLE_CONTAINER_NAME>`、`<YOUR_SYS_PASSWORD>`、`<YOUR_PDB_SERVICE_NAME>`、`<YOUR_DB_USERNAME>`、`<YOUR_DB_PASSWORD>`をご自身の値に置き換えてください：

        ```bash
        docker exec -i <YOUR_ORACLE_CONTAINER_NAME> sqlplus sys/'<YOUR_SYS_PASSWORD>'@//localhost:1521/<YOUR_PDB_SERVICE_NAME> as sysdba << 'EOF'
        ALTER SESSION SET CONTAINER = <YOUR_PDB_SERVICE_NAME>;

        -- Create the local user in the PDB
        CREATE USER <YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>";
        GRANT CREATE SESSION TO <YOUR_DB_USERNAME>;

        -- Grant system and dynamic performance views
        GRANT SELECT ON V_$INSTANCE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$DATABASE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$CONTAINERS                 TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$DATAFILE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SYSSTAT                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SYSMETRIC                  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SESSION                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$RESOURCE_LIMIT             TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$OSSTAT                     TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SGAINFO                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$ROWCACHE                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$PARAMETER                  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_TABLESPACE_USAGE_METRICS  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_TABLESPACES               TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_DATA_FILES                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_FREE_SPACE                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_RECYCLEBIN                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SQL                        TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$LOCK                       TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SESSION_EVENT              TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_PROCEDURES                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_OBJECTS                   TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$PDBS                       TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$PROCESS                    TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$TRANSACTION                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$CON_SYSSTAT                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$CON_SYSMETRIC               TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$ASM_DISKGROUP_STAT          TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$ASM_DISK_STAT               TO <YOUR_DB_USERNAME>;

        EXIT;
        EOF
        ```

        <Callout variant="tip">
          [ASMディスクグループおよびディスクのメトリクス](/docs/opentelemetry/db360/oracle/metrics-reference/#asm)を収集する場合にのみ、`V_$ASM_DISKGROUP_STAT`および`V_$ASM_DISK_STAT`の権限が必要です。
        </Callout>

        <Callout variant="tip">
          個別のプラガブルデータベースではなく、コンテナデータベース全体をモニターする必要がある場合は、代わりにCDBタブを使用してください。
        </Callout>
      </Collapser>
    </CollapserGroup>
  </Step>

  <Step>
    ## Dockerネットワークの接続を確認してください。 [#network]

    共有のユーザー定義ネットワークを作成し（まだない場合）、Oracle コンテナをそれに接続して、コレクターコンテナが名前で解決できるようにします：

    ```bash
    docker network create <YOUR_DOCKER_NETWORK> 2>/dev/null || true
    docker network connect <YOUR_DOCKER_NETWORK> <YOUR_ORACLE_CONTAINER_NAME> 2>/dev/null || true
    ```

    <Callout variant="tip">
      どちらのコマンドも安全に再実行できます：`|| true` は、前回の実行による &quot;already exists&quot; または &quot;already connected&quot; エラーを無視します。
    </Callout>
  </Step>

        ```bash
              max_elapsed_time: 300s
            sending_queue:
              enabled: true
              sizer: bytes
              queue_size: 100_000_000
              num_consumers: 10
              batch:
                sizer: bytes
                max_size: 1_000_000
                min_size: 0
                flush_timeout: 5s

        service:
          pipelines:
            metrics/oracledb:
              receivers: [nroracledb]
              exporters: [otlp/newrelic]
            logs/oracledb:
              receivers: [nroracledb]
              exporters: [otlp/newrelic]
        EOF
        ```
      </Collapser>
    </CollapserGroup>

    ### 設定パラメーター [#configuration-parameters]

    | パラメータ                                                 | 説明                                                                                                                      |
    | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_ORACLE_CONTAINER_NAME>`                        | 実行中のOracleデータベース・コンテナの名前（またはDockerでDNS解決可能なホスト名）です。                                                                     |
    | `<YOUR_DB_USERNAME>`                                  | [データベースユーザーの構成と権限の付与](#database-user)で作成した監視ユーザー（CDBの場合は`C##`プレフィックスが自動的に追加されます）。                                       |
    | `<YOUR_DB_PASSWORD>`                                  | 「[データベースユーザーの構成と権限の付与](#database-user)」で作成した監視ユーザーのパスワード。                                                               |
    | `<YOUR_CDB_SERVICE_NAME>` / `<YOUR_PDB_SERVICE_NAME>` | CDBまたはPDBのOracleサービス名です。                                                                                                |
    | `<YOUR_NEWRELIC_OTLP_ENDPOINT>`                       | New Relic OTLPエンドポイント。詳細については、[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp/)を参照してください。 |
    | `<YOUR_NEWRELIC_LICENSE_KEY>`                         | あなたのNew Relic [ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) 。                                 |
  </Step>

  <Step>
    ## NRDOT Collectorコンテナを起動してください。 [#start]

    Oracleコンテナと同じDockerネットワーク上でコレクターを実行します：

    ```bash
    docker run -d \
      --name nrdot-collector \
      --network <YOUR_DOCKER_NETWORK> \
      --platform linux/amd64 \
      -v "$PWD/oracle-config.yaml:/etc/nrdot-collector/oracle-config.yaml" \
      newrelic/nrdot-collector:latest \
      --config /etc/nrdot-collector/oracle-config.yaml
    ```

    <Callout variant="tip">
      `--platform linux/amd64` Oracleイメージ自体が通常AMD64向けにのみ提供されているApple Siliconやその他のARM64ホストでのアーキテクチャーの不一致を回避します。ホストとイメージがすでにAMD64ネイティブである場合は、これを削除してください。
    </Callout>

    コレクターコンテナが実行されていることを確認します：

    ```bash
    docker ps --filter name=nrdot-collector
    ```

    実行されていない場合は、ログでエラーを確認してください。最も一般的な原因は、`oracle-config.yaml`のYAMLインデントの問題、または到達不可能なOracleコンテナです：

    ```bash
    docker logs nrdot-collector
    ```

    <Callout variant="tip">
      `oracle-config.yaml`を変更した後、コンテナを再起動して変更を適用してください：

      ```bash
      docker restart nrdot-collector
      ```
    </Callout>
  </Step>

  <Step>
    ## データを探す、使う [#find-use-data]

    データの収集が開始されると、New Relic UIから包括的なOracleデータベース監視にアクセスできます。

    New RelicでOracleデータベースエンティティを見つけるには：

    1. <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>に移動します。
    2. 検索条件を<DNT>`instrumentation.provider = opentelemetry`</DNT>に設定します。
    3. エンティティのリストからOracleデータベースを選択します。
  </Step>
</Steps>
