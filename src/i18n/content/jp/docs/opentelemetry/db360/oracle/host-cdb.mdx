New Relic Distribution of OpenTelemetry（NRDOT）コレクターを使用し、データベース監視、クエリ分析、およびシステムヘルスメトリクスによって、Oracleコンテナ・データベース（CDB）のパフォーマンスに関する包括的なインサイトを取得します。構成されたCDB配下のすべてのプラガブル・データベース（PDB）がモニターされます。

<Callout variant="tip" title="ガイド付きインストレーション">
  代わりにNew Relic UIからインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>に移動してください。このページでは、手動インストレーションについてのみ説明します。
</Callout>

## 前提条件 [#prerequisites]

始める前に、次のものがあることを確認してください。

* 有効な[New Relicライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* サポートされているアーキテクチャー: AMD64 および ARM64 を搭載した Linux
* [New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのネットワーク接続
* Oracleデータベース `19c` 以降

  <Step>
    ## データベースユーザーを構成する [#database-user]

    マルチテナントOracleデータベースに必要な権限を持つ監視ユーザーを作成します。これには、`C##`プレフィックスを持つ共通ユーザーを作成する必要があります。

    1. 現在のアクティブなコンテナ・コンテキストを`CDB$ROOT`に設定するには、`SYS`ユーザーとして次の文を実行します：

       ```sql
       ALTER SESSION SET CONTAINER = CDB$ROOT;
       ```

    2. マルチテナントデータベースの場合：

       1. ルートデータベースにアドミニストレーターとしてログインします。

       2. 新しいユーザーを作成するには、次の`CREATE USER`ステートメントを実行します：

          ```sql
          CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>" CONTAINER=ALL;
          GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
          ```

          <Callout variant="tip">
            新しく作成されたユーザーは、`C##`プレフィックスを持つ共通ユーザーになります。Oracleでは、共通ユーザーには`C##`プレフィックスが必須です。
          </Callout>

    3. 監視ユーザーがコンテナ・データ・ビュー内のすべてのPDBの行を表示できるようにするには、CDBルートで`SYSDBA`として次の文を実行します。これは、PDBごとのメトリクスとイベントに必要です。

       ```sql
       ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;
       ```

       <Callout variant="tip">
         `USER_PASSWORD`がOracleの[新しいユーザーパスワード](https://docs.oracle.com/en/database/oracle/oracle-database/12.2/dbseg/keeping-your-oracle-database-secure.html#GUID-451679EB-8676-47E6-82A6-DF025FD65156)の要件を満たしていることを確認します。
       </Callout>
  </Step>

    ```sql
    GRANT SELECT ON V_$SESSION                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

    GRANT SELECT ON V_$OSSTAT                     TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SGAINFO                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ROWCACHE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON V_$PARAMETER                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_TABLESPACES               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

    GRANT SELECT ON DBA_RECYCLEBIN                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

    GRANT SELECT ON DBA_OBJECTS       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON V_$PDBS           TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_SERVICES      TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_DATA_FILES    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_PROCEDURES    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_OBJECTS       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ASM_DISKGROUP_STAT TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ASM_DISK_STAT      TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
    ```

    <Callout variant="tip">
      [ASMディスクグループおよびディスクのメトリクス](/docs/opentelemetry/db360/oracle/metrics-reference/#asm)を収集する場合にのみ、`V_$ASM_DISKGROUP_STAT`および`V_$ASM_DISK_STAT`の権限が必要です。
    </Callout>

  <Step>
    ## NRDOT Collectorの設定を更新 [#update]

    `oracle-config.yaml`ファイルを使用するようにNRDOT Collectorの設定を更新してください：

    ```bash
    sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/oracle-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
    ```

    <Callout variant="tip">
      もできます。

      * [複数のレシーバーを構成する](/docs/opentelemetry/db360/oracle/multi-receiver)：1つのコレクターから複数のOracle データベースインスタンスをモニターします。
      * [SQLクエリレシーバーの構成](/docs/opentelemetry/db360/capabilities/sql-query-receiver/)：Oracleデータベースからカスタムメトリックを収集します。
      * [OracleデータベースをAPMとリンクする](/docs/opentelemetry/db360/capabilities/db-apm)：アプリケーションパフォーマンスをデータベース操作と関連付けます。これにより、どのアプリケーションが特定のデータベースワークロードを生成しているかを正確に確認できます。
      * [シークレット管理のセットアップ](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management)：データベースの認証情報などの機密情報を安全に管理します。これにより、設定ファイルへの機密データのハードコーディングを回避し、監視セットアップのセキュリティを強化できます。
    </Callout>
  </Step>

  <Step>
    ## NRDOT Collectorを再起動します [#restart-collector]

    設定を更新した後、NRDOT Collectorを再起動します：

    ```bash
    sudo systemctl restart nrdot-collector.service
    sudo systemctl status nrdot-collector.service
    ```

    <Callout variant="tip">
      新しい設定を有効にするために、設定を変更した後は常にNRDOT Collectorを再起動してください。
    </Callout>
  </Step>

  <Step>
    ## データを探す、使う [#find-use-data]

    データの収集が開始されると、New Relic UIから包括的なOracleデータベース監視にアクセスできます。

    New RelicでOracleデータベースエンティティを見つけるには：

    1. <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>に移動します。
    2. 検索条件を<DNT>`instrumentation.provider = opentelemetry`</DNT>に設定します。
    3. エンティティのリストからOracleデータベースを選択します。
  </Step>
</Steps>
