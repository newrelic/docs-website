`oracle-otel` Helmチャートを使用して、Kubernetes上でOracle データベースの監視をインストールおよび構成できます。オプションとして、チャートは監視データベースユーザーを作成するセットアップジョブを実行することもできます。

<Callout variant="tip" title="ガイド付きインストレーション">
  代わりにNew Relic UIからインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>に移動してください。このページでは、手動インストレーションについてのみ説明します。
</Callout>

<Steps>
  <Step>
    ## 前提条件 [#prerequisites]

    * 有効なNew Relicの[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)。
    * Helm 3.0以降、およびKubernetesクラスタにアクセスするように設定された`kubectl`。
    * KubernetesクラスタからOracleデータベースのホストおよびリスナーポートへのネットワーク接続。
    * すでに作成済みの監視データベースユーザー、またはチャートのセットアップジョブがユーザーを作成できるようにするためのOracleデータベース管理者資格情報（RDSマスターユーザー、`SYS`、または`ADMIN`）のいずれかです。以下の[監視資格情報の設定](#credentials)を参照してください。
  </Step>

  <Step>
    ## ネームスペースを作成 [#namespace]

    インストール先のネームスペースを作成します。`helm install --create-namespace`は最後のインストール手順でのみネームスペースを作成するため、次の手順でシークレットを作成する前に、ネームスペースが存在している必要があります：

    ```bash
    kubectl create namespace newrelic
    ```

    <Callout variant="tip">
      以下のすべてのコマンドで`-n`を渡す必要がないように、現在の`kubectl`コンテキストのデフォルトのネームスペースとして設定します：

      ```bash
      kubectl config set-context --current --namespace=newrelic
      ```
    </Callout>
  </Step>

  <Step>
    ## 監視資格情報の設定 [#credentials]

    チャートのセットアップジョブでOracleデータベースの監視ユーザーを作成するかどうか、および作成しない場合はその認証情報をどのように提供するかを決定してください：

    <CollapserGroup>
      <Collapser id="helm-creds-inline" title="セットアップジョブなし：プレーンなユーザー名とパスワード">
        この方法ではセットアップジョブがないため、ここで監視ユーザーが自動的に作成されることはありません。チャートをインストールする前に、ご自身で作成してください：環境に応じて、[ オンホストCDB](/docs/opentelemetry/db360/oracle/host-cdb) または[ オンホストPDB](/docs/opentelemetry/db360/oracle/host-pdb) **の データベースユーザーの設定** **および 監視権限の付与 の手順に従ってください。**

        次のステップで、監視用のユーザー名とパスワードを直接`values.yaml`に設定します。
      </Collapser>

      <Collapser id="helm-creds-secret-nojob" title="セットアップジョブなし：シークレットベースの認証情報">
        この方法でも、セットアップジョブはありません。上記のプレーンテキストの資格情報を使用する方法とまったく同じように、まずご自身で監視ユーザーを作成してください。唯一の違いは、資格情報の保存場所です：`values.yaml`にプレーンテキストで保存する代わりに、Kubernetesシークレットに保存します：

        ```bash
        kubectl create secret generic oracle-monitor-creds \
          --from-literal=username=<MONITORING_USERNAME> \
          --from-literal=password='<MONITORING_PASSWORD>' \
          -n newrelic
        ```
      </Collapser>

      <Collapser id="helm-creds-setupjob" title="自動セットアップジョブ">
        この方法では、チャートのセットアップジョブがデータベース管理者の認証情報を使用して監視ユーザーを作成します。監視および管理者の認証情報はどちらもKubernetesシークレットとして提供する必要があります：セットアップジョブはプレーンテキストの管理者認証情報を受け入れることはなく、これを有効にするにはシークレットベースの監視認証情報も必要になります。

        1. 監視のユーザー名とパスワードを使用してシークレットを作成します。これは、セットアップジョブが作成し、コレクターが接続に使用するIDです：

           ```bash
           kubectl create secret generic oracle-monitor-creds \
             --from-literal=username=<MONITORING_USERNAME> \
             --from-literal=password='<MONITORING_PASSWORD>' \
             -n newrelic
           ```

        2. セットアップジョブは、Kubernetesシークレット経由でのみ管理者資格情報を受け入れます（`values.yaml`にプレーンテキストのユーザー名/パスワードを含めることはできません）。この認証情報はユーザーを作成し、データベースへの幅広いアクセス権を付与できるため、独自のシークレットとして作成してください：

           ```bash
           kubectl create secret generic oracle-admin-creds \
             --from-literal=username=<ADMIN_USERNAME> \
             --from-literal=password='<ADMIN_PASSWORD>' \
             -n newrelic
           ```
      </Collapser>
    </CollapserGroup>
  </Step>

    <CollapserGroup>
      <Collapser id="helm-values-inline" title="セットアップジョブなし：プレーンなユーザー名とパスワード">
        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        oracle:
          topology: <cdb|pdb|rds|adb>
          endpoint: <YOUR_DB_HOST>:<YOUR_DB_PORT>
          service: <YOUR_SERVICE_NAME>
          username: <YOUR_MONITORING_USERNAME>
          password: <YOUR_MONITORING_PASSWORD>

        # No setup job runs, so create the monitoring user yourself
        # before installing the chart.
        setupJob:
          enabled: false
        ```
      </Collapser>

      <Collapser id="helm-values-secret-nojob" title="セットアップジョブなし：シークレットベースの認証情報">
        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        oracle:
          topology: <cdb|pdb|rds|adb>
          endpoint: <YOUR_DB_HOST>:<YOUR_DB_PORT>
          service: <YOUR_SERVICE_NAME>
          existingSecret: oracle-monitor-creds

        # No setup job runs, so the monitoring user referenced by
        # this secret must already exist - create it yourself
        # before installing the chart.
        setupJob:
          enabled: false
        ```
      </Collapser>

      <Collapser id="helm-values-setupjob" title="自動セットアップジョブ">
        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        oracle:
          topology: <cdb|pdb|rds|adb>
          endpoint: <YOUR_DB_HOST>:<YOUR_DB_PORT>
          service: <YOUR_SERVICE_NAME>
          existingSecret: oracle-monitor-creds

        setupJob:
          enabled: true
          image:
            # -- Oracle Instant Client + sqlplus image. No default: pulling from container-registry.oracle.com requires accepting Oracle's license terms first. See README.
            repository: ""
            tag: ""
            pullPolicy: IfNotPresent
          oracleAdmin:
            existingSecret: oracle-admin-creds
        ```
      </Collapser>

  <Step>
    ## (オプション) 1つのリリースから複数のインスタンスをモニターする [#multi]

    1つのリリースで単一のコレクターポッドから複数のOracleデータベースインスタンスをモニターするには、`oracle.*`の代わりに`oracleMulti.enabled: true`を設定します。2つのモードは相互に排他的です：同じリリースで`oracle.endpoint`と`oracleMulti.enabled: true`を設定しないでください。リリース内のすべてのインスタンスは同じ`oracleMulti.topology`（`cdb`、`pdb`、`rds`、または`adb`）を共有する必要があります：トポロジの混在、たとえばRDSインスタンスとセルフホスト型CDBなどは、1つのリリースではサポートされていません；代わりにトポロジごとに個別のリリースを使用してください。

    マルチインスタンスモードには、プレーンなユーザー名/パスワードのパスはありません：各インスタンスには、監視資格情報を含む独自のKubernetesシークレットが必要です。セットアップジョブで各監視ユーザーも作成するかどうかを決定します：

    <CollapserGroup>
      <Collapser id="helm-multi-nojob" title="セットアップジョブなし">
        インストールする前に、各インスタンスの監視ユーザーのシークレットを自分で作成してください（`values.yaml`で指定した`name`と一致するように、インスタンスごとに繰り返します）：

        ```bash
        kubectl create secret generic db1-monitor-creds \
          --from-literal=username=<MONITORING_USERNAME> \
          --from-literal=password='<MONITORING_PASSWORD>' \
          -n newrelic
        # Repeat for every instance (db2-monitor-creds, ...)
        ```

        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        # EDIT the two example entries below (or add more) to match
        # your real instances - each `name` must be unique within
        # this release and match the Secret you created for it.
        oracleMulti:
          enabled: true
          topology: <cdb|pdb|rds|adb>
          collectionInterval: 15s
          databases:
            - name: db1
              endpoint: <YOUR_DB_1_HOST>:<YOUR_DB_1_PORT>
              service: <YOUR_DB_1_SERVICE_NAME>
              existingSecret: db1-monitor-creds
            - name: db2
              endpoint: <YOUR_DB_2_HOST>:<YOUR_DB_2_PORT>
              service: <YOUR_DB_2_SERVICE_NAME>
              existingSecret: db2-monitor-creds

        # No admin credential is configured here since the setup
        # job is disabled - create each instance's monitoring user
        # yourself first.
        setupJob:
          enabled: false
        ```
      </Collapser>

      <Collapser id="helm-multi-setupjob" title="自動セットアップジョブ">
        各インスタンスには、独自の監視ユーザーシークレットと独自の管理者資格情報シークレットの両方が必要です（インスタンスごとに繰り返します）：

        ```bash
        kubectl create secret generic db1-monitor-creds \
          --from-literal=username=<MONITORING_USERNAME> \
          --from-literal=password='<MONITORING_PASSWORD>' \
          -n newrelic
        kubectl create secret generic db1-admin-creds \
          --from-literal=username=<ADMIN_USERNAME> \
          --from-literal=password='<ADMIN_PASSWORD>' \
          -n newrelic
        # Repeat for every instance (db2-monitor-creds, db2-admin-creds, ...)
        ```

        ```yaml
        licenseKey: <YOUR_LICENSE_KEY>
        otlpEndpoint: otlp.nr-data.net:4317

        # EDIT the two example entries below (or add more) to match
        # your real instances - each `name` must be unique within
        # this release and match the Secrets you created for it.
        oracleMulti:
          enabled: true
          topology: <cdb|pdb|rds|adb>
          collectionInterval: 15s
          databases:
            - name: db1
              endpoint: <YOUR_DB_1_HOST>:<YOUR_DB_1_PORT>
              service: <YOUR_DB_1_SERVICE_NAME>
              existingSecret: db1-monitor-creds
              oracleAdmin:
                existingSecret: db1-admin-creds
            - name: db2
              endpoint: <YOUR_DB_2_HOST>:<YOUR_DB_2_PORT>
              service: <YOUR_DB_2_SERVICE_NAME>
              existingSecret: db2-monitor-creds
              oracleAdmin:
                existingSecret: db2-admin-creds

        setupJob:
          enabled: true
          image:
            repository: ""
            tag: ""
        ```
      </Collapser>
    </CollapserGroup>

    <Callout variant="tip">
      他のNRDOT Helmチャートとは異なり、Oracleではインスタンスごとに`collectionInterval`をオーバーライドできます。その他のすべてのスクレイプ設定は、引き続きすべてのインスタンスに同じように適用されます。その他に異なる必要があるものについては、`additionalReceiverConfig`を使用してください。セットアップジョブは、リリースごとに1回ではなく、インスタンス（`<release>-setup-<name>`）ごとに1回実行されます。

  <Step>
    ## Helmチャートをインストールする [#install]

    1. New Relic Helm リポジトリを追加します。

       ```bash
       helm repo add newrelic https://helm-charts.newrelic.com
       helm repo update
       ```

    2. `values.yaml`ファイルを使用してチャートをインストールします：

       ```bash
       helm upgrade --install oracle-otel newrelic/oracle-otel \
         -n newrelic \
         --create-namespace \
         -f values.yaml
       ```
  </Step>

  <Step>
    ## インストレーションを確認する [#verify]

    1. セットアップジョブが完了し、コレクターポッドが実行されていることを確認してください：

       ```bash
       kubectl get jobs,pods -n newrelic --watch
       ```

    2. データが到着していることを確認するには、[クエリビルダー](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/)でこのクエリを実行してください：

       ```sql
       SELECT count(*) FROM Metric
       WHERE metricName LIKE 'oracledb.%'
       AND instrumentation.provider = 'opentelemetry'
       SINCE 10 minutes ago
       ```
  </Step>
</Steps>
