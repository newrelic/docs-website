AWS RDS PostgreSQLインスタンス用のNRDOT Collectorを使用して、PostgreSQL監視をセットアップします。RDS環境には、拡張機能とパラメーターグループに関する特定の考慮事項があります。

<Callout variant="tip" title="ガイド付きインストレーション">
  代わりにNew Relic UIからインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>に移動してください。このページでは、手動インストレーションについてのみ説明します。
</Callout>

<Steps>
  <Step>
    ## 前提条件 [#prerequisites]

    インストールする前に、以下のものがあることを確認してください：

    * PostgreSQL `14`以降
    * NewRelic[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)。
    * NRDOT CollectorをインストールするホストとRDS PostgreSQLインスタンス間のネットワーク接続。
    * [New Relic OTLPエンドポイントのドキュメント](/docs/opentelemetry/best-practices/opentelemetry-otlp/)へのネットワーク接続
    * RDSマスターユーザーの認証情報。

    サポートされているPostgreSQLのバージョン、必要な権限、および推奨されるサーバーパラメーターについては、[互換性と前提条件](/docs/opentelemetry/db360/postgresql/compatibility)をご覧ください。
  </Step>

  <Step>
    ## NRDOT Collectorのセットアップ [#setup]

    RDSインスタンスに接続できるシステムにNRDOT Collectorをインストールします：

    <CollapserGroup>
      <Collapser title="AMD64向けアーキテクチャー" id="amd">
        * Debian/Ubuntuシステムの場合は、以下を実行してください。

```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
```

        * RHEL/CentOS/OELシステムの場合は、以下を実行してください。

```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_x86_64.rpm" --output nrdot-collector.rpm && sudo rpm -ivh nrdot-collector.rpm
```

  <Step>
    ## データベースユーザーと権限を設定する [#database-user]

    RDS PostgreSQLインスタンスに必要な権限を持つ監視ユーザーを作成します。

    **監視ユーザーと権限を作成するには：**

    1. マスターユーザーとしてRDSインスタンスに接続します：

```shell
    psql --host=<YOUR_RDS_ENDPOINT> --dbname=postgres --port=5432 --username=<YOUR_MASTER_USERNAME>
```

    2. 監視ユーザーを作成する：

```sql
    CREATE USER <YOUR_DB_USERNAME> WITH LOGIN PASSWORD '<YOUR_DB_PASSWORD>';
```

    3. 必要に応じて、監視ユーザーロールのメンバーシップを付与する：

    * PostgreSQL 15以降を使用している場合は、権限を継承するようにロールを割り当てます：

```sql
      ALTER ROLE <YOUR_DB_USERNAME> INHERIT;
```

      <Callout variant="tip">
        PostgreSQL 14を使用している場合、監視ユーザーはデフォルトで権限を継承するため、この手順をスキップできます。
      </Callout>

    * 監視するすべてのデータベースに次のスキーマと権限を作成します：

```sql
      CREATE SCHEMA IF NOT EXISTS otel;
      GRANT USAGE ON SCHEMA otel TO <YOUR_DB_USERNAME>;
      GRANT USAGE ON SCHEMA public TO <YOUR_DB_USERNAME>;
      GRANT SELECT ON ALL TABLES IN SCHEMA public TO <YOUR_DB_USERNAME>;
      GRANT pg_monitor TO <YOUR_DB_USERNAME>;
      CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

    * （オプション）ベクトルメトリクスを収集するには、各データベースで`pgvector`拡張機能を作成します：

```sql
      CREATE EXTENSION IF NOT EXISTS vector;
```

      `l1`、`hamming`、および`jaccard`の距離関数には、`pgvector`バージョン`0.7.0`以降が必要です。

    * （オプション）接続と権限を確認するには、次を実行します：

```shell
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> --command '\conninfo'
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_database LIMIT 1;" && echo "pg_stat_database OK"
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_activity LIMIT 1;" && echo "pg_stat_activity OK"
      psql --username=<YOUR_DB_USERNAME> --host=<YOUR_RDS_ENDPOINT> --port=5432 --dbname=<YOUR_DATABASE_NAME> \
        -c "SELECT * FROM pg_stat_statements LIMIT 1;" && echo "pg_stat_statements OK"
```

      各コマンドがエラーなしで完了した場合、監視ユーザー、ホスト、およびポートはすべて正しいです。
  </Step>

    ## NRDOT Collectorを構成する [#configure-collector]

    RDS PostgreSQL固有の設定でNRDOT Collectorを設定してください。

    この設定は、`nrpostgresql`レシーバーのみを使用した基本的なPostgreSQL監視に焦点を当てています。

    <Callout variant="tip" title="完全な設定">
      このベースライン設定は、必須のメトリクスを取得します。完全なメトリクスカタログを確認するには、[設定リファレンス](/docs/opentelemetry/db360/postgresql/config-reference/#rds-full)を参照してください。
    </Callout>

```bash
      sudo nano /etc/nrdot-collector/postgresql-config.yaml
```

    ### 設定パラメーター

    次の表は、 `nrpostgresql`受信機のキー設定を説明しています。

    | パラメータ                           | 説明                                                                                                                              |
    | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_RDS_ENDPOINT>`           | RDSインスタンスのエンドポイントのホスト名を入力します。                                                                                                   |
    | `<YOUR_DB_PORT>`                | PostgreSQLデータベースのポートを入力します。                                                                                                     |
    | `<YOUR_DB_USERNAME>`            | データベースのユーザー名を入力してください。                                                                                                          |
    | `<YOUR_DB_PASSWORD>`            | データベースのパスワードを入力してください。                                                                                                          |
    | `<YOUR_DATABASE_NAME>`          | 監視するデータベースの名前を入力します。                                                                                                            |
    | `databases`                     | 統計を収集するデータベースのリストです。デフォルト：`[]`（すべての非テンプレートデータベース）。メトリクスにのみ適用されます。クエリサンプルとトップクエリはこのリストを無視し、`exclude_databases`によってのみフィルタリングされます。 |
    | `exclude_databases`             | 統計、クエリサンプル、トップクエリから除外されるデータベース。デフォルト：`[]`。監視ユーザーがアクセスできないマネージドサービスの内部データベース（`rdsadmin`など）には、これを使用してください。                        |
    | `<YOUR_NEWRELIC_OTLP_ENDPOINT>` | New Relic OTLPエンドポイントを入力します。詳細については、[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp/)を参照してください。   |
    | `<YOUR_NEWRELIC_LICENSE_KEY>`   | New Relicの[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)を入力してください。                                     |
    | `collection_interval`           | メトリクススクレイプの間隔を入力します。デフォルト：`15s`。                                                                                                |

    <Callout variant="tip">
      もできます。

      [複数のレシーバーの構成](/docs/opentelemetry/db360/postgresql/multi-receiver)：1つのコレクターから複数のPostgreSQLインスタンスをモニターします。
      [PostgreSQLデータベースをAPMとリンクする](/docs/opentelemetry/db360/capabilities/db-apm)：アプリケーションパフォーマンスをデータベース操作と関連付けるため。これにより、どのアプリケーションが特定のデータベースワークロードを生成しているかを正確に確認できます。
      [書き込みステートメントのクエリプラン](/docs/opentelemetry/db360/postgresql/optional#query)：監視ユーザーに書き込みアクセス権を付与せずに、ロックまたは書き込みステートメントのクエリプランを収集します。
      [シークレット管理のセットアップ](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management)：データベースの認証情報などの機密情報を安全に管理します。これにより、設定ファイルへの機密データのハードコーディングを回避し、監視セットアップのセキュリティを強化できます。
    </Callout>
  </Step>

  <Step>
    ## NRDOT Collectorの設定の検証 [#validate]

    1. 新しい`postgresql-config.yaml`ファイルを指すように設定パスを更新します：

```bash
      sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/postgresql-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
```

    2. NRDOT Collectorの設定を検証して、正しくフォーマットされ、適切に機能することを確認します：

```bash
      sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/postgresql-config.yaml
```
  </Step>

  <Step>
    ## NRDOT Collectorを再起動します [#restart-collector]

    コレクターを設定した後、NRDOT Collectorサービスを再起動して変更を適用します：

```bash
    sudo systemctl restart nrdot-collector
```

    コレクターが正常に実行されていることを確認するには、サービスステータスを確認します：

```bash
    sudo systemctl status nrdot-collector
```

    <Callout variant="tip">
      新しい設定を確実に適用するために、設定を変更した後は常にNRDOT Collectorを再起動してください。
    </Callout>
  </Step>

  <Step>
    ## データを探す、使う [#find-use-data]

    クエリのサンプルと上位のクエリは、ログイベント（`event.name = 'db.server.query_sample'`/`'db.server.top_query'`、`db.system.name = 'postgresql'`）として到着します。メトリクスは`postgresql.*`ネームスペースの下に到着します。

    New RelicでRDS PostgreSQLデータベースエンティティを見つけるには：

    1. <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>に移動します。
    2. **<DNT>Entity type</DNT>**ドロップダウンから<DNT>**PostgreSQL instance**</DNT>を選択し、<DNT>**Apply**</DNT>をクリックします。
    3. エンティティのリストからRDS PostgreSQLデータベースを選択します。
  </Step>
</Steps>
