NRDOT Collectorは、幅広いPostgreSQLメトリクスを報告します。New Relicは、[デフォルトのメトリクスとイベント](#default)にあるメトリクスとクエリレベルのイベントを自動的に収集します。パフォーマンスと正常性に関するより深いインサイトを得るには、[フル機能のメトリクス](#full-feature)にリストされている任意のメトリクスを有効にしてください。

## デフォルトのメトリクスとイベント [#default]

<Callout variant="tip">
各メトリクスは、特定のデータベース、テーブル、スキーマ、またはインデックスにスコープされます。このコンテキストは、メトリクス属性としてではなく、リソースに設定されます。
</Callout>

#### 実行プラン収集（EXPLAIN）のメカニズム

* **レート制限：**`top_query_collection.max_explain_each_interval`（デフォルトは1000）は、スクレイプごとのEXPLAINを制限します。
* **キャッシュ:** `query_plan_cache_size`/`query_plan_cache_ttl`（デフォルト1000エントリ/1時間）は、一度取得したプランをクエリIDをキーとしてキャッシュします。
* **PostgreSQL 12+の要件：**パラメータ化されたクエリのEXPLAINには`PREPARE`/`EXPLAIN EXECUTE`の前に`plan_cache_mode = force_generic_plan`が必要ですが、これはPostgreSQL 12+でのみ利用可能です。古いサーバーでは、レシーバーがバージョンを検出し、失敗する`SET`を送信するのではなく、そのクエリのEXPLAINをスキップします。
* **権限の境界：**デフォルトでは、EXPLAINは直接監視ユーザーとして実行され、Postgresは*プラン*時にテーブル権限をチェックするため、監視ユーザーが持つべきではない書き込みアクセス権が付与されていない限り、行ロックや書き込みステートメントは`permission denied`で失敗します。書き込みアクセス権を付与せずにこれを回避するには、`explain_function_name`を使用してください（[書き込みステートメントのクエリプラン](/docs/opentelemetry/db360/postgresql/optional#query)を参照）。
* 何らかの理由でプランを取得できない場合、その行の`postgresql.query_plan`は単に空になります。エラーは表示されません。
</Collapser>
