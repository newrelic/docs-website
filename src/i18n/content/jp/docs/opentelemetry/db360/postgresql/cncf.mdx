PostgreSQL用のOpenTelemetry Collector Contribを使用して、インスタンスをモニターできます。OpenTelemetry Collector Contribは、PostgreSQLからテレメトリーデータを収集してNew Relicに送信する、コミュニティサポートのプロジェクトです。

デフォルトでは、OpenTelemetry Collector ContribはPostgreSQLから限られたメトリクスを収集します。クエリのパフォーマンス、待機イベント、セッション、およびクライアントのメトリクスを送信するには、OpenTelemetry Collector Contribを設定する必要があります。このガイドでは、PostgreSQLから高度なメトリクスを収集し、New Relicに送信するように設定する方法を説明します。

<Callout variant="tip" title="注記">
このページでは、標準の`otelcol-contrib`バイナリに同梱されているコミュニティの`postgresql`レシーバーについて説明します。New Relicのディストリビューション（NRDOT）を使用している場合は、代わりに[「PostgreSQL監視の概要」](/docs/opentelemetry/db360/postgresql/introduction)を参照してください。
</Callout>

<Steps>
<Step>
## 前提条件 [#prerequisites]

* システムにOpenTelemetry Collector Contrib（`otelcol-contrib`）がインストールされ、設定されています。最新のリリースは、[OpenTelemetry Collectorのリリース](https://github.com/open-telemetry/opentelemetry-collector-releases/releases)ページからダウンロードできます。

* `pg_stat_statements` モニターされるPostgreSQLインスタンスで`shared_preload_libraries`を介して有効化されます。これは、クエリパフォーマンス、待機イベント、セッション、およびクライアントデータに必要です。[推奨サーバーパラメーター](/docs/opentelemetry/db360/postgresql/compatibility#params)を参照してください。

* コレクターは、`receiver.postgresql.useOTelSemconv`機能ゲートを使用してセマンティック規約モードで開始されました。

  `otelcol-contrib`をRPM/Debianパッケージ（systemdサービス）として実行している場合、サービスファイルは`EnvironmentFile=/etc/otelcol-contrib/otelcol-contrib.conf`を介して環境変数をインポートします。そのファイルで、フラグを`OTELCOL_OPTIONS`に追加します：

  ```bash
  OTELCOL_OPTIONS="--config=/etc/otelcol-contrib/config.yaml --feature-gates=receiver.postgresql.useOTelSemconv"
  ```

  ファイルを保存した後、サービスを再起動してゲートを適用してください：

  ```bash
  sudo systemctl restart otelcol-contrib
  ```
</Step>

<Step>
## UIメトリクスを有効化 [#enable]

`otelcol-contrib`設定ファイルにメトリクスを追加して有効にすることで、New Relicプラットフォームのエクスペリエンスを向上させることができます。このセクションで提供されている設定を使用すると、New Relicプラットフォームの以下のページにデータを入力できます。

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Overviewページメトリクスを有効化">
<DNT>Overview</DNT>ページは、データベースロック、デッドロック、関数呼び出し、クエリの競合、シーケンシャルスキャン、一時ファイル/IOの使用量などの主要なメトリクスを含む、PostgreSQLインスタンスの概要を表示します。

New Relicプラットフォームの<DNT>Overview</DNT>ページにデータを入力するには、`otelcol-contrib`設定ファイルに以下の設定を追加します：

```yaml
receivers:
  postgresql:
    metrics:
      postgresql.database.locks:
        enabled: true
      postgresql.deadlocks:
        enabled: true
      postgresql.function.calls:
        enabled: true
      postgresql.query.conflicts:
        enabled: true
      postgresql.sequential_scans:
        enabled: true
      postgresql.temp.io:
        enabled: true
      postgresql.temp_files:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="クエリのパフォーマンス、セッション、待機、およびクライアントメトリクスを有効化">
<DNT>Query performance</DNT>、<DNT>Wait events</DNT>、<DNT>Sessions</DNT>、および<DNT>Clients</DNT>ページにデータを入力するには：

* Query performance \[クエリパフォーマンス]：PostgreSQLインスタンスで実行されているクエリに関する詳細情報を、以下のタブに表示します：

  * Normalized queries \[正規化されたクエリ]：実行および平均CPU時間のグラフを表示します。
  * Query samples \[クエリサンプル]：開始時間、所要時間、待機タイプ、待機時間、データベース、DBユーザー、およびクライアントホストを含む、個々のクエリの実行を表示します。

* Wait events \[待機イベント]：PostgreSQLインスタンスで発生している待機イベントに関する情報を表示します。query samples \[クエリサンプル] ビューでは、現在待機中のクエリが、その待機タイプおよび待機時間とともに表示されます。

* Sessions \[セッション]：負荷のスパイクと接続のボトルネックを追跡するために、アクティブおよびアイドル状態のデータベース接続、平均セッション期間、ブロックされたセッション、およびアプリケーションとプロセスごとの使用状況の傾向を視覚化します。

* Clients \[クライアント]：アクティブなセッション、ブロックされたセッション、接続されているDBユーザー、およびクライアントホストの詳細など、PostgreSQLインスタンスに接続されているクライアントに関する情報を表示します。

以下の設定を`otelcol-contrib`設定ファイルに追加します。

```yaml
receivers:
  postgresql:
    events:
      db.server.top_query:
        enabled: true
      db.server.query_sample:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      max_rows_per_query: 1000
      top_n_query: 200
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 1000
```

<Callout variant="important">
`db.server.query_plan` `db.server.top_query`または`db.server.query_sample`の少なくとも1つも有効にする必要があります。単独で有効にすると、設定検証エラーになります。
</Callout>

<Callout variant="tip" title="注記">
`postgresql.session.duration` コミュニティの`postgresql`レシーバーでは使用できないため、Sessions \[セッション] ページにSessions \[セッション] テーブルは表示されません。
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## OpenTelemetry Collectorを再起動する [#restart]

設定の変更を適用するには、OpenTelemetry Collectorを再起動します：

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
