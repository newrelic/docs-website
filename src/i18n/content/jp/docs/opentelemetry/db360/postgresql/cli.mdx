New Relic CLIを使用して、PostgreSQL監視用のNRDOT Collectorをインストールおよび設定できます。CLIは1つのコマンドで、コレクターをインストールし、監視ロールとその権限を作成し、コレクターを設定します。

<Callout variant="tip" title="ガイド付きインストレーション">
  代わりにNew Relic UIからインストールするには、<DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>に移動してください。このページでは、手動インストレーションについてのみ説明します。
</Callout>

<Steps>
  <Step>
    ## 前提条件 [#prerequisites]

    * 有効な[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys)を持つNew Relicアカウント。
    * New Relic [アカウントID](/docs/accounts/accounts-billing/account-structure/account-id)。
    * PostgreSQL 14以降。
    * `curl`と`systemd`がインストールされ、`psql`クライアントが利用可能な、Debian/UbuntuまたはRHEL/CentOSを実行しているLinuxコレクターホスト。
    * `pg_stat_statements` `shared_preload_libraries`経由でロードする必要があります。インストーラはこれを確認し、そうでない場合は失敗します。以下の[サーバーレベルの前提条件](#server-prereqs)を参照してください。
    * セルフホスト型PostgreSQLの場合：PostgreSQLサーバーへの管理アクセス（`postgres`スーパーユーザーまたは同等のユーザー）。
    * AWS RDS/Aurora PostgreSQLの場合：コレクターホストからRDSエンドポイントへのネットワーク接続（RDSセキュリティグループのPostgreSQLポートでのインバウンドアクセス）、およびRDSマスターのユーザー名とパスワード。
    * ご利用のリージョンの[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのネットワーク接続。

    詳細な要件については、[互換性](/docs/opentelemetry/db360/postgresql/compatibility)をご覧ください。
  </Step>

  <Step>

    * **セルフホスト型**：これらを`postgresql.conf`に設定し、PostgreSQLを再起動します。一部のディストリビューションでは、`pg_stat_statements`を利用可能にするために`postgresql-contrib`パッケージをインストールする必要があります。
    * **AWS RDSまたはAurora**：これらは設定ファイルではなく、DBの**パラメーターグループ**で設定します。`track_activity_query_size` と `pg_stat_statements.max` は静的パラメーターです：`apply_method: pending-reboot` で適用してから、インスタンスを再起動してください。Aurora の場合、パラメーターグループのファミリー名はエンジンのメジャーバージョンと完全に一致する必要があります。たとえば `aurora-postgresql16` です。

  <Step>
    ## NRDOT Collectorのインストールと設定 [#cli-install]

    <CollapserGroup>
      <Collapser id="cli-host" title="セルフホスト型PostgreSQL">
        このレシピは、単一のコレクターから1つ以上のPostgreSQLインスタンスをモニターします。単一のホスト/ポート/資格情報セットの入力を求める代わりに、事前に作成した2つのファイルを読み込みます：モニターするすべてのインスタンスとそれぞれでモニターするデータベースをリストしたインスタンスファイル（YAML）、および一致するようにインデックス付けされた、それぞれに対するスーパーユーザーのログインとパスワードを含むシークレットファイル（`KEY=VALUE`）です。

        1. インスタンスファイルを作成します。このコレクターでモニターするPostgreSQLインスタンスごとに1つのエントリを追加します；単一のインスタンスのみを実行している場合でも、エントリは1つだけです。各インスタンスには少なくとも1つのデータベースが必要です：PostgreSQLにはすべてのデータベースをモニターするモードはありません：

           ```bash
           cat > ~/postgresql-instances.yml << 'EOF'
           instances:
             - host: localhost
               port: 5432
               login_name: newrelic
               databases: [app1, app2]
           EOF
           ```

        2. インスタンスファイルの順序と一致するようにインデックス付けされた、各インスタンスのスーパーユーザーロール（任意のスーパーユーザーロールで機能します；`postgres`である必要はありません）とパスワードを含むシークレットファイルを作成してください：

           ```bash
           umask 077
           cat > ~/postgresql-secrets.env << 'EOF'
           NR_CLI_POSTGRES_SUPERUSER_USER_1=postgres
           NR_CLI_POSTGRES_SUPERUSER_PASSWORD_1=YourSuperuserPassword1
           EOF
           chmod 600 ~/postgresql-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-postgresql
        ```

        <Callout variant="important">
          このインストーラはパスワードを使用してTCP経由でPostgreSQLに接続するため、各インスタンスのスーパーユーザーにはパスワードが設定されている必要があり、`pg_hba.conf`はTCP接続に対してパスワードベースのホスト認証（`md5`または`scram-sha-256`）を許可する必要があります。新規インストールの場合、デフォルトでは`postgres`にパスワードが設定されていません。まずパスワードを設定してください：

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```

          RHEL/CentOSでは、デフォルトの`pg_hba.conf`はパスワードベースのホスト認証をまったく許可しないことがよくあります。これを確認して更新し、インストールを実行する前にPostgreSQLをリロードしてください。
        </Callout>

        <Callout variant="tip">
          このコレクターから複数のPostgreSQLインスタンスをモニターするには、instancesファイルにさらにエントリーを追加し、secretsファイルに対応する番号付きの認証情報（`_2`、`_3`、...）を追加してください。チェックに失敗した（またはリストされているデータベースがない）インスタンスは、インストール全体を中止するのではなく、理由をログに記録してスキップされます；インストールが完全に失敗するのは、チェックを通過したインスタンスが1つもない場合のみです。

           ```bash

               login_name: newrelic
           ```

           ```bash
           umask 077

           NR_CLI_POSTGRES_ADMIN_USER_1=postgres

           EOF
           chmod 600 ~/postgresql-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-postgresql-rds
        ```

  <Step>
    ## データを探す、使う [#find]

    データの収集が開始されると、New Relic UIから包括的なPostgreSQLデータベース監視にアクセスできます。

    New RelicでPostgreSQLデータベースエンティティを見つけるには：

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>に移動します。
    2. **<DNT>Entity type</DNT>**ドロップダウンから<DNT>**PostgreSQL instance**</DNT>を選択し、<DNT>**Apply**</DNT>をクリックします。
    3. エンティティのリストからPostgreSQLデータベースを選択します。

    データが到着していることを確認するには、[クエリビルダー](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/)で次のクエリを実行します：

    ```sql
    SELECT count(*) FROM Metric
    WHERE metricName LIKE 'postgresql.%'
    AND instrumentation.provider = 'opentelemetry'
    SINCE 10 minutes ago
    ```
