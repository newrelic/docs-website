NRDOT Collectorが収集する包括的なメトリクスを使用して、MySQLデータベースのパフォーマンスをモニターしてください。デフォルトでは、New Relicは[デフォルトのメトリクスとイベント](#default)セクションで参照されているメトリクスとクエリレベルのイベントを収集します。[フル機能のメトリクス](#full-feature)セクションに記載されている目的のメトリクスを有効にすることで、監視を強化できます。

### イベント検索 [#query-events]

次のイベントはOpenTelemetryログレコードとして収集され、デフォルトで有効になっています。これらはクエリレベルの可視性を提供します。

<CollapserGroup>
<Collapser id="query-sample" title="クエリのサンプル">
現在実行中のデータベースステートメントのリアルタイムの可視性：完全な実行ログではなく、スクレイプごとに取得されるポイントインタイムのスナップショットです。このイベントはデフォルトで有効化されています。

その動作を調整するには、`query_sample_collection`ブロックを使用します：

```yaml
query_sample_collection:
  max_rows_per_query: 100
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="top-query" title="上位のクエリ">
最も実行時間を消費しているクエリ。MySQL独自の`performance_schema.events_statements_summary_by_digest`によってサーバー側で集約されます：サンプル数ではなく、ダイジェストごとの真の実行カウンターです。このイベントはデフォルトで有効化されています。

その動作を調整するには、`top_query_collection`ブロックを使用します：

```yaml
top_query_collection:
  lookback_time: 60
  max_query_sample_count: 5000
  top_query_count: 200
  collection_interval: 60s
  query_plan_cache_size: 1000
  query_plan_cache_ttl: 1h
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="query-plan" title="クエリプラン">
