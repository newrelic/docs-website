NRDOTでMySQLの監視を開始する前に、環境がこれらの要件を満たしていることを確認してください。

## 前提条件 [#prereq]

始める前に、次のものがあることを確認してください。

* 有効な[New Relicライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* NRDOT CollectorをインストールするホストとMySQLデータベース間のネットワーク接続。NRDOT CollectorをMySQLデータベースとは異なるホストにインストールする予定の場合は、[ネットワークアクセス要件](#network)を参照してください。
* [New Relic OTLPエンドポイントのドキュメント](/docs/opentelemetry/best-practices/opentelemetry-otlp/)へのネットワーク接続

## ネットワークアクセス要件 [#network]

デフォルトでは、NRDOTは**TCP**経由で接続します（レシーバー設定の`transport: tcp`、デフォルト）。コレクターがデータベースと同じホストで実行されている場合は、代わりに`transport: unix`を設定し、`endpoint`をデータベースのUnixドメインソケット（たとえば`/var/run/mysqld/mysqld.sock`）に指定することで、以下のネットワークチェックを完全に回避できます。その他のデプロイメント（コレクターとデータベースが異なるホスト、コンテナ、またはVPCにある場合）では、TCPが必要です。

  <thead>
    <tr>
      <th>
        デプロイメント
      </th>

      <th>
        チェックポイント
      </th>
    </tr>

  <tbody>
    <tr>
      <td>
        EC2上の自己管理型MySQL
      </td>

      <td>
        **セキュリティグループ**

        ：コレクターが別のEC2インスタンスで実行されている場合は、コレクターのソース（コレクター自身のセキュリティグループID。同一VPCの場合、生のIPよりも推奨）からDBポート（デフォルトは

        `3306`

        ）にインバウンドルールを追加します。同じインスタンスでサイドカーとして実行されている場合は、ルールは必要ありません。

        `my.cnf`

        の

        `bind-address`

        も確認してください：多くのディストリビューションのデフォルトでは

        `bind-address = 127.0.0.1`

        が同梱されており、ローカル以外のTCP接続をすべて拒否します。リモートコレクターがアクセスできるようにする前に、インスタンスのプライベートIPまたは

        `0.0.0.0`

        に設定してください。
      </td>
    </tr>

    <tr>
      <td>
        Amazon RDS/Aurora for MySQL
      </td>

      <td>
        **VPCセキュリティグループ**

        ：コレクターのセキュリティグループまたはプライベートIPから、RDSインスタンスのポート（デフォルトは

        `3306`

        ）にインバウンドルールを追加します；RDSには編集可能なOSレベルの

        `my.cnf`

        がないため、これが唯一のネットワークゲートとなります。

        **権限付与**

        は、RDSマスターユーザーから行う必要があります。RDSには

        `root`

        アカウントがありません。

        **制限された権限**

        ：RDSエンジンのバージョンとパラメーターグループによっては、

        `SUPER`

        および

        `FILE`

        が制限されるか、利用できない場合があります。

        **TLS**

        ：「Require SSL/TLS」が強制されているRDSインスタンスでは、コレクターがAmazonのRDS CAを信頼する必要があります。

        `tls.ca_file`

        （または

        `tls.ca_pem`

        ）を

        [Amazon RDS証明書バンドル](https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem)

        に設定し、

        `tls.insecure`

        /

        `tls.insecure_skip_verify`

        は

        `false`

        のままにします。
      </td>
    </tr>

    <tr>
      <td>
        リモート/クロスホストのデプロイメント
      </td>

      <td>
        MySQLは、ユーザー名が同じであっても、

        `'<user>'@'localhost'`

        と

        `'<user>'@'%'`

        （または特定のホスト/CIDR）を

        **異なるアカウント**

        として扱います。監視ユーザーを

        `'<user>'@'localhost'`

        として作成すると、他の場所で実行されているコレクターからの認証に暗黙的に失敗し、誤ったパスワードと区別できないアクセス拒否エラーが発生します。

        `'<user>'@'%'`

        を使用するか、コレクターの特定のプライベートIP/CIDRにスコープを限定してください。
      </td>
    </tr>
  </tbody>
</table>

<Callout variant="important">
  稼働中のAmazon RDS for MySQLインスタンスで検証済み：RDSの`mysql8.0`パラメーターグループファミリーは、`performance_schema_consumer_*`パラメーターをまったく公開していません；そこで設定できるのは、サイジング/バッファーパラメーターと、`performance_schema`、`slow_query_log`、および`long_query_time`のみです。これは、`events_waits_current`（`mysql.events_waits_current.timer_wait`、および一般的な待機ベースのダッシュボードに必要）がRDS上の実行時にのみオンにでき、再起動やフェイルオーバー後には維持されないことを意味します。
</Callout>

## 推奨されるサーバーサイドコンフィグレーション [#server]

レシーバーが利用可能なすべてのメトリクスとクエリプランを収集できるように、これらのMySQLサーバーのパラメーターを構成します。次の表に、パラメーターとその推奨値を示します：

## 次のステップ [#next]

環境がこれらの前提条件を満たしていることを確認したら：

1. インストール方法を選択してください:

* [セルフホストのセットアップ](/docs/opentelemetry/db360/mysql/hosted)
* [AWS RDSのセットアップ](/docs/opentelemetry/db360/mysql/rds)

2. 収集される[利用可能なメトリクス](/docs/opentelemetry/db360/mysql/metrics-reference)を確認してください
3. 書き込みステートメントのクエリ実行計画やロック待機時間の追跡などのオプション機能については、[詳細なインサイトの有効化](/docs/opentelemetry/db360/mysql/optional)をご覧ください。
4. 一般的な問題については、[トラブルシューティングガイド](/docs/opentelemetry/db360/mysql/troubleshooting)をご覧ください
