NRDOT Collectorを使用してPostgreSQLを監視する際に発生する可能性のある一般的な問題をトラブルシューティングします。

## 接続をテストする

### PostgreSQLへのネットワーク接続をテストします。

```bash
psql --host=<YOUR_DB_HOST> --port=<YOUR_DB_PORT> --username=<YOUR_DB_USERNAME> --dbname=<YOUR_DATABASE_NAME> --command 'SELECT 1;'
```

接続と結果が成功すると、コレクター自体のトラブルシューティングを行う前に、監視ユーザー、ホスト、およびポートに到達可能であることが確認されます。

### OTLPエンドポイントの接続テスト

NRDOT CollectorがNew RelicのOTLPエンドポイントに到達できることを確認します：

```bash
curl -v <YOUR_NEWRELIC_OTLP_ENDPOINT>
```

## よくある症状

| 症状                                                                                | 考えられる原因                                                                                                                                  |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `db.server.query_sample`/`db.server.top_query`イベントはありません                          | レシーバーの設定で`events`ブロックが有効になっていません（デフォルトでは両方ともオフです）                                                                                        |
| `db.server.top_query` 完全に欠落しているイベント                                               | `pg_stat_statements` そのデータベースに拡張機能が作成されていません                                                                                             |
| `db.server.query_sample` ブロッキング・セッションの詳細の欠落                                       | 監視ユーザーに不足している `pg_monitor`                                                                                                               |
| 長いクエリが切り捨てられる `db.server.query_sample`                                            | デフォルトの`track_activity_query_size`（1024バイト） — これを増やします。[互換性と前提条件](/docs/opentelemetry/database/postgresql/compatibility#params)を参照してください。 |
| `postgresql.function.calls` 常に空、またはダッシュボードの&quot;Function Calls/min&quot;ウィジェットが空 | `track_functions` 内で`pl`または`all`に設定されていない `postgresql.conf`                                                                              |
| メトリクスが流れているにもかかわらず、いくつかのダッシュボードウィジェットが空です                                         | これらのメトリクスはデフォルトで無効になっています — [メトリクスリファレンス](/docs/opentelemetry/database/postgresql/metrics-reference#dashboard)を参照してください                  |
| `db.query.comment_tags.nr_service_guid` 常に空                                       | `allowed_comment_keys: [nr_service_guid]` `query_sample_collection`/`top_query_collection`に設定されていません — デフォルトでは空です                        |
| 一部のテーブルでテーブル/インデックス/関数のメトリクスが欠落している                                               | 監視ユーザーには、それらのテーブル/スキーマの`SELECT`が不足しています — `pg_monitor`はオブジェクトレベルではなく、統計の可視性を付与します `SELECT`                                               |
| `postgresql.wal.lag` /`.wal.age`が欠落している                                           | 少なくとも1つのレプリカが接続された状態でWALが有効になっている必要があります — スタンドアロン/ソースのみのインスタンスではゼロにならず、暗黙的に省略されます。                                                      |
| PostgreSQLエンティティが表示されない、またはEntity Explorerでアプリ→PostgreSQLの関係が解決されません              | `server.address`リソースに/`server.port`が存在しません；デフォルトの（レガシー）リソースモデルでは、レシーバー単独でこれらを出力しません。                                                     |
