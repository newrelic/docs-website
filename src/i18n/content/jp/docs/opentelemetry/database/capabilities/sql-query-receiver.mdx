`sqlqueryreceiver`は、データベースに対して任意のカスタムSQLクエリを実行し、その結果をメトリクスとしてNew Relicに取り込むことができるOpenTelemetry Collectorレシーバーです。

組み込みの`nroracledbreceiver`/`nrsqlserverreceiver`メトリクスでカバーされていないデータをモニターしたい場合にこれを使用します。`host.name`が正しく構成されている場合、`sqlqueryreceiver`経由で収集されたカスタムメトリックは、組み込みのレシーバーデータと同じOracleまたはSQL Serverエンティティの下にNew Relicで表示されます。

## 前提条件 [#prerequisites]

* データソースで構成されたデータベースユーザーは、クエリを実行する予定のすべてのビューまたはテーブルに対する`SELECT`権限を持っている必要があります。
* コレクターのバイナリには、`sqlqueryreceiver`コンポーネントが含まれている必要があります。

        sqlquery/oracle:
          driver: oracle

          # Approach 1: Use the `endpoint`, `username`, `password`, and `service` fields to connect to your database. The receiver will construct the datasource URL for you.
          # host: <YOUR_DB_HOST>
          # port: <YOUR_DB_PORT>
          # database: <YOUR_DATABASE_NAME>
          # username: <YOUR_DB_USERNAME>
          # password: <YOUR_DB_PASSWORD>


          # Approach 2: Use the `datasource` field to provide a full connection string. 
          datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"

      ### 命名規則

      New Relicで正しいエンティティに関連付けるには、メトリクス名が`oracledb.`で始まる必要があります。異なるプレフィックスを持つメトリクスは取り込まれますが、データベースエンティティの下には表示されません。

      ### エンティティ合成

      `resource/add_host`プロセッサーを追加して、`host.name`をデータベースレシーバーで使用される値と同じ値に設定してください。これを行わないと、カスタムメトリックはデータベースエンティティにリンクされません。

      プロセッサを`processors:`セクションに追加してください：

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: host.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: host.name
              value: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Pipeline設定

      設定の`service.pipelines:`セクションに、既存のパイプラインと並んで`metrics/custom`パイプラインを追加します：

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [resource/add_event_name, batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [resource/add_event_name, batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_host, resource/add_event_name, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        プロセッサーリストの`batch`の前に`resource/add_host`を追加します。
      </Callout>

      ### データを検証するためのNRQL

      コレクターを再起動した後、以下を実行してカスタムメトリックが到着していることを確認します：

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      | 問題                                        | 原因                             | 修理                                                                             |
      | ----------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------ |
      | `ORA-00942: table or view does not exist` | データベースユーザーにSELECT権限がありません      | ユーザーに`SELECT ON <VIEW_NAME>`を付与します。                                            |
