このページでは、最小限のセットアップを超える、Dockerコンテナ監視のオプション設定について説明します。現在、これはログ収集です。

## 要件 [#requirements]

OpenTelemetryの[receiver creator](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/receivercreator)と[Docker observer](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/extension/observer/dockerobserver)拡張機能を使用して、Dockerコンテナのログを収集できます。以下の要件を満たしていることを確認してください：

* コレクタープロセス（root、またはdockerグループのメンバーシップ）の`/var/lib/docker/containers/`に対する読み取り権限
* receiver creatorがコンテナログを検出してスクレイピングできるように、コンテナポートが公開されていること

## ログ収集を構成する [#logs]

<CollapserGroup>
<Collapser id="logs-nrdot" title="NRDOT Collector">
既存の`docker-stats-config.yaml`にログ収集設定を追加してください。

```yaml
extensions:
  # Docker observer - discovers running containers
  docker_observer:
    endpoint: unix:///var/run/docker.sock
    use_hostname_if_present: true

receivers:
  # Your existing dockerstats receiver...

  # Receiver creator - dynamically creates filelog receivers for discovered containers
  receiver_creator:
    watch_observers: [docker_observer]
    receivers:
      filelog:
        rule: type == "container"
        config:
          include:
            - /var/lib/docker/containers/`container_id`/`container_id`-json.log
          poll_interval: 200ms
          start_at: end
          include_file_name: false
          include_file_path: false
          operators:
            - id: container-parser
              type: container
              format: docker
              add_metadata_from_filepath: false

processors:
  # Your existing processors...

  # Add entity type attribute for logs (required for New Relic entity correlation)
  attributes/logs:
    actions:
      - key: nr.entity_type
        value: CONTAINER
        action: upsert

service:
  extensions: [docker_observer]
  pipelines:
  # Your existing metrics pipeline...

    logs:
      receivers: [receiver_creator]
      processors: [attributes/logs, batch]
      exporters: [otlp_http]
```
</Collapser>

### 設定パラメーター [#logs-configuration-parameters]

以下の表は、ログ収集の主要な設定パラメーターについて説明しています：

| パラメータ                            | 説明                                                                         |
| -------------------------------- | -------------------------------------------------------------------------- |
| `endpoint` ( `docker_observer` ) | observerが接続するDockerソケットへのパスを入力してください。デフォルト： `unix:///var/run/docker.sock`  |
| `use_hostname_if_present`        | 利用可能な場合にコンテナのホスト名を使用するかどうかを設定します。デフォルト： `true`                             |
| `poll_interval`                  | レシーバーがログファイルの新しい行をチェックする頻度を設定します。デフォルト： `200ms`                            |
| `start_at`                       | receiverが各ログファイルの読み取りを開始する位置を設定します。既存のログ行をスキップして新しい行のみを収集するには、`end`を使用します。 |

## コレクターを再起動します [#start]

設定を更新した後、変更を適用するためにコレクターを再起動してください。

<CollapserGroup>
<Collapser id="restart-nrdot" title="NRDOT Collector">
systemdをリロードし、コレクターを有効にして再起動します：

```bash
sudo systemctl daemon-reload
sudo systemctl enable nrdot-collector
sudo systemctl restart nrdot-collector

# Verify the collector is running
sudo systemctl status nrdot-collector
```
</Collapser>

<Collapser id="restart-otelcol-contrib" title="OpenTelemetry Collector貢献">
systemd をリロードし、コレクターを再起動します。

```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib

# Verify the collector is running
sudo systemctl status otelcol-contrib
```
</Collapser>
</CollapserGroup>

## ログの検証 [#verify-logs]

**Docker logs**：次のクエリを実行します：

```sql
FROM Log SELECT count(*) SINCE 10 minutes ago
```

独自のログ属性に合わせて`WHERE`句を調整してください。
