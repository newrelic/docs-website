Linkerdのメトリクス、トレース、またはログがNew Relicに表示されない場合は、発生している事象に一致する問題に対処してください。

<CollapserGroup>
  <Collapser id="no-entity" title="Linkerdエンティティが表示されない">
    LinkerdプロキシのメトリクスがNew Relicに到達していることを確認します：

    ```sql
    SELECT count(*) FROM Metric
    WHERE linkerd_control_plane_ns IS NOT NULL
      AND k8s.cluster.name = '<YOUR_CLUSTER>'
    SINCE 5 minutes ago
    ```

    これが0を返す場合は、コレクターのポッドが実行されていること、およびコレクター設定のPrometheusスクレイプジョブが正しいネームスペースをターゲットにしていることを確認してください。
  </Collapser>

  <Collapser id="no-deployment-entities" title="ワークロードエンティティがありません">
    ワークロードエンティティにはkube-state-metricsが必要です。データを送信していることを確認します：

    ```sql
    SELECT uniques(k8s.deployment.name)
    FROM Metric
    WHERE metricName LIKE 'kube_deployment%'
      AND k8s.cluster.name = '<YOUR_CLUSTER>'
    SINCE 10 minutes ago
    ```

    空の場合は、kube-state-metricsが実行されていること、およびコレクター設定のスクレイプターゲットが正しいネームスペースとサービス名を指していることを確認してください。
  </Collapser>

  <Collapser id="no-metrics" title="New Relicにメトリクスがまったくない">
    ```bash
    kubectl get pods -n newrelic
    kubectl logs -n newrelic deployment/my-opentelemetry-collector | grep -E "error|warn|Failed" | tail -20
    ```
  </Collapser>

  <Collapser id="no-traces" title="スパン/トレースがない">
    ```bash
    # Verify Java agent loaded (for APM-instrumented app pods)
    kubectl logs -n <YOUR_NAMESPACE> deployment/<YOUR_APP> | grep "javaagent"

    # Verify Linkerd proxy routing for OTLP gRPC (must show appProtocol: grpc)
    kubectl get svc -n newrelic my-opentelemetry-collector -o jsonpath='{.spec.ports}'
    ```

    コレクターのServiceポート4317には`appProtocol: grpc`が必要です。これがないと、LinkerdはgRPCをHTTP/1.1としてルーティングします。修正：

    ```bash
    kubectl patch svc -n newrelic my-opentelemetry-collector --type='json' \
      -p='[{"op":"add","path":"/spec/ports/1/appProtocol","value":"grpc"}]'
    ```
  </Collapser>

  <Collapser id="no-cp-ns-on-spans" title="スパンに linkerd_control_plane_ns がありません">
    `k8sattributes/traces`プロセッサは、ポッドの関連付けに`k8s.pod.ip`を使用します。アプリのポッドにdownward API環境変数が設定されていることを確認します：

    ```bash
    kubectl exec -n <YOUR_NAMESPACE> deployment/<YOUR_APP> -- env | grep MY_POD_IP
    ```

    `MY_POD_IP`が欠落している場合は、`status.podIP`を指す`fieldRef`環境変数としてポッド仕様に追加してください。
  </Collapser>

  <Collapser id="no-logs" title="New Relicにログがありません">
    `filelog`レシーバーは、`varlogpods`のhostPathマウントの下にあるログファイルを読み取り、`linkerd-proxy`コンテナ（OTel Collector Contrib）またはすべてのコンテナ（NRDOT）に絞り込みます。マウントが存在し、読み取り可能であることを確認します：

    ```bash
    # OTel Collector Contrib (separate DaemonSet release for logs)
    kubectl exec -n newrelic daemonset/my-opentelemetry-collector-logs -- ls /var/log/pods 2>/dev/null | head -5

    # NRDOT (built-in, same DaemonSet as metrics/traces)
    kubectl exec -n newrelic daemonset/nr-k8s-otel-collector-daemonset -- ls /var/log/pods 2>/dev/null | head -5
    ```

    マウントが読み取り可能であるにもかかわらず、New Relic（OTel Collector Contrib）に`linkerd-proxy`ログレコードが表示されない場合は、`filter/onlyproxy`の`k8s.container.name != "linkerd-proxy"`条件がポッドと一致しているか確認してください。`filelog`レシーバーの`container`オペレーターの`add_metadata_from_filepath: true`は、ログファイルパスから`k8s.container.name`に値を設定するものです。
  </Collapser>
</CollapserGroup>
