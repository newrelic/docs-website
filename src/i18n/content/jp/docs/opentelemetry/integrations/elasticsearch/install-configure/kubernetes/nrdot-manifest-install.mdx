このガイドでは、マニフェストインストールを使用してKubernetes上にNRDOTをデプロイし、Elasticsearchのポッドを自動的に検出し、クラスタ、ノード、およびJVMのメトリクスを収集してNew Relicにストリーミングすることで、クラスタの健全性とパフォーマンスをモニターする方法を説明します。

## 互換性と要件 [#requirements]

### サポート対象

* Kubernetesクラスタでポッドとして実行されているElasticsearch 7.16以降
* マニフェストのインストール方法

### 必要なこと

* New Relicの[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* `kubectl` Kubernetesクラスタへのアクセス
* ベースとなる[Kubernetes OpenTelemetryマニフェストのインストレーション](/docs/kubernetes-pixie/k8s-otel/install/#manifest-install)はすでに完了しています。
* `monitor`または`manage`のクラスタ権限を持つElasticsearchユーザー（[Elasticsearchのセキュリティ権限](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html)を参照）
* New Relicの[OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのアウトバウンドHTTPS（ポート443）接続
* Elasticsearchのユーザー名とパスワード（クラスタで認証が必要な場合）

<Steps>
<Step>
## ポッドラベルの設定 [#pod-labels]

自動検出が機能するためには、各Elasticsearchポッドにラベル `app: elasticsearch` が付与されている必要があります。このラベルがないと、コレクターはポッドを検出またはモニターしません。

Elasticsearchに StatefulSet またはデプロイメントを使用している場合は、ポッド テンプレートにラベルを追加します。

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: elasticsearch
spec:
  template:
    metadata:
      labels:
        app: elasticsearch  # Required for auto-discovery
    spec:
      containers:
      - name: elasticsearch
        image: docker.elastic.co/elasticsearch/elasticsearch:8.x.x
```

ラベルのない既存のポッドについては、StatefulSet/デプロイメントを更新し、ポッドを再起動してください：

```bash
kubectl label pods -l <your-existing-selector> app=elasticsearch -n <namespace>
```

ラベルが正しく設定されているかどうかを確認できます。

```bash
kubectl get pods -n <namespace> --show-labels
```
</Step>

## コレクターのイメージと設定を準備します。 [#prepare]

コレクターのイメージを更新し、ローカルのマニフェストファイルでElasticsearchの監視設定を定義してください。次のステップで、これらの変更をクラスタに適用します。

1. ローカルの `rendered` ディレクトリにある [`deployment.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/deployment.yaml) と [`daemonset.yaml`](https://github.com/newrelic/helm-charts/blob/master/charts/nr-k8s-otel-collector/examples/k8s/rendered/daemonset.yaml) の両方で、コレクターのイメージを NRDOT に更新してください：

### 設定パラメーター [#configuration-parameters]

以下の表は、上記の`deployment-configmap.yaml`で使用される主な設定パラメーターについて説明しています：

| パラメータ                                                                          | 説明                                                                                                                           |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `rule`                                                                         | 自動検出に使用されるポッドマッチングルール。ポッドラベルと一致するように`labels["app"] == "elasticsearch"`を更新します。                                                |
| `endpoint`                                                                     | 検出された各ポッドでスクレイプされるElasticsearchエンドポイント。Elasticsearchが別のポートで実行されている場合はポート`9200`を更新し、セキュアなクラスタには`https`を使用してください。              |
| `collection_interval`                                                          | メトリクスのスクレイプ間隔です。デフォルトは15秒です。                                                                                                 |
| `elasticsearch-cluster` （`resource/cluster`/`resource/cluster_name_override`内） | New Relicでこのクラスタを識別する一意の名前です。アカウント全体で一意の名前に置き換えてください。                                                                        |
| `NEW_RELIC_MEMORY_LIMIT_MIB`                                                   | コレクターの`memory_limiter`プロセッサのメモリ制限（MiB単位）。環境に合わせて設定してください。                                                                    |
| `NEWRELIC_LICENSE_KEY`                                                         | あなたのNew Relic [ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) 。                                      |
| `NEWRELIC_OTLP_ENDPOINT`                                                       | アカウントのリージョンのNew Relic OTLPエンドポイントです。[New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)を参照してください。 |
</Step>

<Step>
## kubectlを使用してNRDOTコレクターをインストールおよび設定します。 [#install-manifest]

先ほど準備したイメージと設定を使用して、更新したマニフェストを適用し、クラスタにNRDOTコレクターをデプロイしてください。

```bash
kubectl apply -n newrelic -R -f rendered
```
</Step>

<Step>
## NRDOTコレクターのポッドを再起動してください。 [#restart]

変更を適用するためにデプロイメントを再起動します：

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```
</Step>

<Step>
## インストールの確認 [#verify]

インストールから約5分以内に、New Relicでこのクエリを実行して、データが送信されていることを確認します（`elasticsearch-cluster`をご自身のクラスタ名に置き換えてください）：

```sql
FROM Metric
SELECT *
WHERE metricName LIKE 'elasticsearch.%'
  AND instrumentation.provider = 'opentelemetry'
  AND k8s.cluster.name = 'elasticsearch-cluster'
SINCE 10 minutes ago
```

<Callout variant="tip">
コレクター自体を確認することもできます：ポッドは`Running`状態（`kubectl get pods -n newrelic --watch`）で、名前が`nr-k8s-otel-collector-deployment-<hash>`のようになっており、ポッドログ（`kubectl logs -n newrelic -l app.kubernetes.io/name=nr-k8s-otel-collector -f`）に接続エラーがないはずです。
</Callout>

約5分経過してもデータが表示されない場合は、[Kubernetesのトラブルシューティング](/docs/opentelemetry/integrations/elasticsearch/troubleshooting#kubernetes-troubleshooting)をご覧ください。
</Step>

<Step>
## データを探す、使う [#find-and-use]

New Relicがデータを収集すると、New Relic UIを通じてElasticsearchの監視にアクセスできるようになります。

New RelicでElasticsearchダッシュボードを見つけるには：

1. <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT>に移動します。
2. <DNT>**All**</DNT>タブで<DNT>**Dashboards**</DNT>をクリックし、<DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT>を検索してダッシュボードを表示します。

または、左側のナビゲーションから：

1. <DNT>**Dashboards**</DNT>をクリックします。
2. <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT>ダッシュボードを検索して表示します。

NRDOTを使用してElasticsearchの監視をセットアップすると、次のことができるようになります：

* Elasticsearchのメトリクスを可視化するための[カスタムダッシュボードを作成](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)します
* クリティカルなクラスタのヘルスおよびパフォーマンスの閾値に対する[アラートを設定](/docs/alerts/create-alert/create-alert-condition/alert-conditions/)します
* New Relicのクエリ機能を使用して、[データを探索](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)します
</Step>
</Steps>

<Callout variant="tip">
**APMとElasticsearchの関連付け**：APMアプリケーションとElasticsearchクラスタを接続するには、APMメトリクスにリソース属性`es.cluster.name="your-cluster-name"`を含めてください。これにより、New RelicでAPMとElasticsearchのデータを一緒に表示できるようになります。
</Callout>
