このページでは、最小限のセットアップに加えて、Elasticsearch監視のオプション設定について説明します：保護されたクラスタ、ホストメトリクス、ログ収集、およびカスタムメタデータタグ。

## 認証とSSLで保護されたElasticsearch [#secured]

クラスタで必要な場合は、Elasticsearch接続に認証とTLSを追加してください。

### 要件 [#secured-requirements]

* `monitor`または`manage`のクラスタ権限を持つElasticsearchユーザー、およびそのユーザーの有効な認証情報。

認証とSSLで保護されたElasticsearchの場合は、レシーバーの設定を変更してください：

<CollapserGroup>
<Collapser id="secured-nrdot" title="NRDOT">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-otel" title="OTel Collector Contrib">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-k8s-nrdot" title="Kubernetes：NRDOT（マニフェストまたはHelm）">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>

<Collapser id="secured-k8s-otel" title="Kubernetes：OTel Collector Contrib">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>
</CollapserGroup>

### 設定パラメーター [#secured-configuration-parameters]

次の表は、上記のスニペットで使用されている主要な設定パラメーターについて説明しています。

| パラメータ                      | 説明                                                      |
| -------------------------- | ------------------------------------------------------- |
| `endpoint`                 | ElasticsearchクラスタのURL。セキュアなクラスタには`https://`を使用してください。   |
| `username`                 | `monitor`または`manage`のクラスタ権限を持つElasticsearchユーザー。        |
| `password`                 | そのユーザーのパスワード。                                           |
| `tls.insecure_skip_verify` | ElasticsearchのTLS証明書を検証するかどうか。`false`に設定すると、検証が有効になります。 |
| `collection_interval`      | メトリクスのスクレイプ間隔です。デフォルト：`15s`。                            |
| `rule` （Kubernetesのみ）      | 自動検出に使用されるポッドマッチングルール。                                  |

## ホストメトリクスの収集 [#host-metrics]

ホストメトリクスを収集するには、`hostmetrics`レシーバーを追加します：

<CollapserGroup>
<Collapser id="host-metrics-nrdot" title="NRDOT">
```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization: { enabled: true }
          system.cpu.time: { enabled: true }
      load:
        metrics:
          system.cpu.load_average.1m: { enabled: true }
          system.cpu.load_average.5m: { enabled: true }
          system.cpu.load_average.15m: { enabled: true }
      memory:
        metrics:
          system.memory.usage: { enabled: true }
          system.memory.utilization: { enabled: true }
      disk:
        metrics:
          system.disk.io: { enabled: true }
          system.disk.operations: { enabled: true }
      filesystem:
        metrics:
          system.filesystem.usage: { enabled: true }
          system.filesystem.utilization: { enabled: true }
      network:
        metrics:
          system.network.io: { enabled: true }
          system.network.packets: { enabled: true }
      process:
        metrics:
          process.cpu.utilization:
            enabled: true
```

さらに、サービスパイプラインに以下を追加します。

```yaml
service:
  pipelines:
    metrics/host:
      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="host-metrics-otel" title="OTel Collector Contrib">

### 設定パラメーター [#host-metrics-configuration-parameters]

次の表は、上記のスニペットで使用されている主要な設定パラメーターについて説明しています。

| パラメータ                 | 説明                                                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `collection_interval` | ホストメトリクスのスクレイプ間隔。デフォルト：`60s`。                                                                                              |
| `scrapers`            | 収集するホストレベルのメトリクスカテゴリ（`cpu`、`load`、`memory`、`disk`、`filesystem`、`network`、`process`）。`enabled: false`を設定して、不要なメトリクスを無効にします。 |

## Elasticsearchログの収集 [#logs]

### 要件 [#logs-requirements]

* コレクターサービスを実行するアカウントに対する、Elasticsearchログファイルへの読み取りアクセス権：

  * Linuxホスト：〜の読み取り権限 `/var/log/elasticsearch/`
  * Docker：`/var/lib/docker/containers/` に対する読み取り権限（root、または Docker グループのメンバーシップ）

Elasticsearchのログを収集するには、`filelog`レシーバーを追加してください。

<CollapserGroup>
<Collapser id="logs-nrdot" title="NRDOT">
コレクターサービス（`nrdot-collector`）を実行しているアカウントが、Elasticsearchのログファイルに対する読み取りアクセス権を持っていることを確認してください。

**ElasticsearchがLinuxホストで実行されている場合は、この設定を使用してください：**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**ElasticsearchがDockerで実行されている場合は、この設定を使用してください：**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

さらに、サービスパイプラインに以下を追加します。

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="logs-otel" title="OTel Collector Contrib">
コレクターサービス（`otelcol-contrib`）を実行しているアカウントが、Elasticsearchのログファイルに対する読み取りアクセス権を持っていることを確認してください。

**ElasticsearchがLinuxホストで実行されている場合は、この設定を使用してください：**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**ElasticsearchがDockerで実行されている場合は、この設定を使用してください：**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

さらに、サービスパイプラインに以下を追加します。

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### 設定パラメーター [#logs-configuration-parameters]

次の表は、上記のスニペットで使用されている主要な設定パラメーターについて説明しています。

| パラメータ                   | 説明                                                    |
| ----------------------- | ----------------------------------------------------- |
| `include`               | tailするログファイルのパス（Linuxホスト）、またはコンテナのログパス（Docker）。       |
| `operators` （Docker のみ） | 正しく表示されるようにログ行を`attributes.log`から`body`に移動するオペレーターです。 |

## カスタムメタデータタグの追加 [#custom-tags]

メトリクスにカスタムメタデータタグを追加するには、`resource/static_override`プロセッサーを使用します：

<CollapserGroup>
<Collapser id="custom-tags-nrdot" title="NRDOT">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="custom-tags-otel" title="OTel Collector Contrib">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### 設定パラメーター [#custom-tags-configuration-parameters]

次の表は、上記のスニペットで使用されている主要な設定パラメーターについて説明しています。

| パラメータ    | 説明                                                      |
| -------- | ------------------------------------------------------- |
| `key`    | 追加する属性名、たとえば`env`など。                                    |
| `value`  | 属性値、たとえば`production`など。                                 |
| `action` | 適用するアクション。属性を追加するか、すでに存在する場合は上書きするには、`upsert`に設定してください。 |

## コレクターを再起動します [#restart]

設定を更新した後、変更を適用するためにコレクターを再起動してください。

<CollapserGroup>
<Collapser id="restart-nrdot" title="NRDOT（セルフホスト）">
```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Collapser>

<Collapser id="restart-otel" title="OTel Collector Contrib（セルフホスト）">
```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```
</Collapser>

<Collapser id="restart-k8s" title="Kubernetes（NRDOT または OTel Collector Contrib）">
マニフェストインストールの場合は、デプロイメントを再起動してください：

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```

Helmインストールの場合は、インストール手順と同じ`helm upgrade --install ... -f values.yaml`コマンドを再実行して、更新された設定をロールアウトします。
</Collapser>
</CollapserGroup>

## 変更内容の確認 [#verify]

コレクターを再起動した後、変更が反映されたことを確認してください：

* **セキュアなクラスタ**：インストールページのデータ収集クエリを再実行してください。コレクターのログにTLSエラーや認証エラーがなく、メトリクスが送信されている場合、セキュアな接続は正常に機能しています。

* **ホストメトリクス**：このクエリを実行してください：

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'system.%' SINCE 10 minutes ago
  ```

* **Elasticsearchログ**: このクエリを実行します：

  ```sql
  FROM Log SELECT count(*) SINCE 10 minutes ago
  ```

  独自のログ属性に合わせて`WHERE`句を調整してください。

* **カスタムタグ**：[「カスタムメタデータタグの追加」](#custom-tags)のサンプルタグを使用して、このクエリを実行します：

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'elasticsearch.%' AND env = 'production' SINCE 10 minutes ago
  ```

約5分以内にデータが表示されない場合は、[Elasticsearchのトラブルシューティング](/docs/opentelemetry/integrations/elasticsearch/troubleshooting)をご覧ください。
