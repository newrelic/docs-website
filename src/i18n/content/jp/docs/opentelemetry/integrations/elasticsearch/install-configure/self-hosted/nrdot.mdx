LinuxサーバーまたはVM上のセルフホスト型Elasticsearchクラスタをモニターするには、このガイドを使用してNRDOTをインストールおよび設定してください。設定が完了すると、コレクターはElasticsearchクラスタのメトリクスをNew Relicにエクスポートします。ホストのメトリクス、ログ、およびカスタムタグについては、[高度な設定](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration)をご覧ください。

## 互換性と要件 [#requirements]

### サポート対象

* Elasticsearch 7.16以降

### 必要なこと

* New Relicの[ライセンスキー](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)
* ホスト上のrootまたはsudo権限
* `monitor`または`manage`のクラスタ権限を持つElasticsearchクラスタの管理者権限（[Elasticsearchのセキュリティ権限](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html)を参照）
* New Relicの[OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)へのアウトバウンドHTTPS（ポート443）接続
* Elasticsearchのユーザー名とパスワード（クラスタで認証が必要な場合）

<Steps>
<Step>
## NRDOTコレクターをインストールします [#install]

NRDOTコレクターをインストールし、systemdサービスとして実行してください。[NRDOTのインストール](/docs/opentelemetry/nrdot/nrdot-collector/)をご覧ください。
</Step>

<Step>
## NRDOT コレクターを構成する [#configure]

1. コレクターのデフォルト設定をバックアップしてから、編集用に開いてください：

   ```bash
   sudo cp /etc/nrdot-collector/config.yaml /etc/nrdot-collector/config.yaml.backup
   sudo nano /etc/nrdot-collector/config.yaml
   ```

### 設定パラメーター [#configuration-parameters]

以下の表は、上記の設定で使用される主要な設定パラメーターについて説明しています：

| パラメータ                        | 説明                                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`                   | ElasticsearchクラスタのURL。                                                                                                    |
| `collection_interval`        | メトリクスのスクレイプ間隔です。デフォルトは15秒です。                                                                                              |
| `elasticsearch.cluster.name` | New Relic内でこのクラスタを識別する一意の名前。                                                                                              |
| `NEW_RELIC_MEMORY_LIMIT_MIB` | ご利用の環境に合わせて設定する、コレクターの`memory_limiter`プロセッサのメモリ制限（MiB単位）です。                                                               |
| `NEWRELIC_LICENSE_KEY`       | New Relicライセンスキー。                                                                                                         |
| `NEWRELIC_OTLP_ENDPOINT`     | [New Relic OTLPエンドポイント](/docs/opentelemetry/best-practices/opentelemetry-otlp)に基づく、アカウントのリージョンに対応するNew Relic OTLPエンドポイント。 |

3. 設定ファイルを保存します。

オプションで、保護されたクラスタの認証、ホストのメトリクス、ログ収集、またはカスタムメタデータタグを追加できます。[高度な設定](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration)をご覧ください。
</Step>

<Step>
## 環境変数を設定します。 [#env-vars]

コレクターがNew Relicにデータを送信するために必要な認証情報と接続の詳細を設定します。

```bash
sudo mkdir -p /etc/systemd/system/nrdot-collector.service.d
cat <<EOF | sudo tee /etc/systemd/system/nrdot-collector.service.d/environment.conf
[Service]
Environment="NEWRELIC_OTLP_ENDPOINT=<YOUR_NEWRELIC_OTLP_ENDPOINT>"
Environment="NEWRELIC_LICENSE_KEY=<YOUR_NEWRELIC_LICENSE_KEY>"
Environment="NEW_RELIC_MEMORY_LIMIT_MIB=100"
EOF
```
</Step>

<Step>
## NRDOTコレクターを再起動してください [#restart]

変更を適用するには、コレクターを再起動してください：

```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Step>

<Step>
## データ収集を確認する [#verify]

コレクターを再起動してから約5分以内に、New Relicでこのクエリを実行して、データが到着していることを確認してください（`<YOUR_ELASTICSEARCH_CLUSTER_NAME>`をクラスタ名に置き換えます）：

```sql
FROM Metric SELECT count(*)
WHERE metricName LIKE 'elasticsearch.%'
AND elasticsearch.cluster.name = '<YOUR_ELASTICSEARCH_CLUSTER_NAME>'
SINCE 10 minutes ago
```

<Callout variant="tip">
コレクター自体を確認することもできます：`nrdot-collector.service`は`active (running)`（`sudo systemctl status nrdot-collector.service`）を報告し、ログ（`sudo journalctl -u nrdot-collector.service -f`）に接続エラーがないはずです。
</Callout>

約5分以内にデータが表示されない場合は、[Elasticsearchのトラブルシューティング](/docs/opentelemetry/integrations/elasticsearch/troubleshooting)をご覧ください。
</Step>

<Step>
## データを探す、使う [#find-and-use]

New Relicがデータを収集すると、New Relic UIを通じてElasticsearchの監視にアクセスできるようになります。

New RelicでElasticsearchダッシュボードを見つけるには：

1. <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT>に移動します。
2. <DNT>**All**</DNT>タブで<DNT>**Dashboards**</DNT>をクリックし、<DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT>を検索してダッシュボードを表示します。

または、左側のナビゲーションから：

1. <DNT>**Dashboards**</DNT>をクリックします。
2. <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT>ダッシュボードを検索して表示します。

NRDOTを使用してElasticsearchの監視をセットアップすると、次のことができるようになります：

* Elasticsearchのメトリクスを可視化するための[カスタムダッシュボードを作成](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/)します
* クリティカルなクラスタのヘルスおよびパフォーマンスの閾値に対する[アラートを設定](/docs/alerts/create-alert/create-alert-condition/alert-conditions/)します
* New Relicのクエリ機能を使用して、[データを探索](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/)します
</Step>
</Steps>

<Callout variant="tip">
**APMとElasticsearchの関連付け**：APMアプリケーションとElasticsearchクラスタを接続するには、APMメトリクスにリソース属性`es.cluster.name="your-cluster-name"`を含めてください。これにより、New RelicでAPMとElasticsearchのデータを一緒に表示できるようになります。
</Callout>
