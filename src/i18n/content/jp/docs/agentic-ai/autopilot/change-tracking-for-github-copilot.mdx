<Callout title="プレビュー">
この機能はまだ開発中ですが、ぜひお試しください。

この機能は現在、弊社の[プレリリース ポリシー](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy)に従ってプレビュー プログラムの一部として提供されています。
</Callout>

<DNT>New Relic Change Tracking for GitHub Copilot</DNT> 監視のために設定した各デプロイメントの後に、サービスをモニターします。<DNT>Autopilot</DNT> はスケジュールされたチェックポイントでサービスの健全性を確認し、プルリクエストにコメントし、接続されている場合は <DNT>Slack</DNT> に結果を報告します。リグレッションを検出した場合、<DNT>GitHub Copilot</DNT> に割り当てられた <DNT>GitHub</DNT> のIssueも開きます。組織に <DNT>GitHub Copilot Enterprise</DNT> がある場合、プルリクエストとして修正を提案できます。

<Callout variant="important">
<DNT>New Relic Change Tracking for GitHub Copilot</DNT> [「AutopilotをGitHubに接続する」](/docs/agentic-ai/autopilot/connect-to-github)で説明されている読み取りアクセスに加えて、書き込みアクセス権を持つ<DNT>GitHub</DNT>トークンが必要です。すでに接続されているトークンに書き込み権限を追加するか、すべての権限を持つ新しいトークンを接続してください。
</Callout>

監視用に設定された各デプロイメントは、以下の段階を経ます：

1. プルリクエストをマージすると、パイプラインがそれをデプロイします。デプロイメントは、リリースタグURL、マージコミットSHA、および`watchpoint_monitoring`属性を含むイベントをChange Tracking (変更追跡機能)に送信します。
2. <DNT>Autopilot</DNT> イベントを検証します。パスした場合、<DNT>Autopilot</DNT> はマージされたプルリクエストにコメントし、<DNT>Slack</DNT> を接続している場合は「監視開始」メッセージを投稿します。
3. 各チェックポイントで、<DNT>Autopilot</DNT>はデプロイメント後のサービスのメトリクスをデプロイメント前のメトリクスと比較します。3つの結果（リグレッションなし、判定不能、またはリグレッション検出）のいずれかをプルリクエストへのコメントとして報告し、<DNT>Slack</DNT>を接続している場合は同じスレッドへの返信として報告します。チェックポイントは、デプロイメントの10分後、30分後、1時間後、2時間後、24時間後、および72時間後に実行されます。

チェックポイントがリグレッションを検出すると、<DNT>Autopilot</DNT>は次の3つの処理を行います：

* （<DNT>Slack</DNT>を接続している場合）関連するメトリクスと検出結果の根拠とともに、<DNT>Slack</DNT> スレッドに返信を投稿します。
* 関連するメトリクス、リグレッションを検出したチェックポイント、およびその理由をプルリクエストにコメントします。
* 何がリグレッションしたか、裏付けとなる証拠、確認すべき場所、および受け入れ基準を説明する<DNT>GitHub</DNT>のIssueをオープンし、そのIssueを<DNT>GitHub Copilot</DNT>に割り当てます。

<DNT>Copilot</DNT>が修正を提案した場合は、マージする前に、他のプルリクエストと同様にレビューしてください。

## 前提条件 [#prerequisites]

<DNT>New Relic Change Tracking for GitHub Copilot</DNT> をセットアップする前に、次の点を確認してください：

* <DNT>Autopilot</DNT>を設定しました。「[Autopilotのセットアップ](/docs/agentic-ai/autopilot/setup)」を参照してください。

* <DNT>**New Relic Organization Manager**</DNT>であり、<DNT>**[one.newrelic.com &gt; Administration](https://one.newrelic.com/admin-portal) &gt; Preview &amp; Trials**</DNT>で<DNT>**New Relic Change Tracking for GitHub Copilot**</DNT>にオプトインしています。

* モニターするリポジトリへの書き込みアクセス権を持つ <DNT>GitHub</DNT> アカウントとトークンを持っています。

* デプロイメントは、[ ミューテーション を使用して、 Change Tracking](/docs/change-tracking/overview) [`changeTrackingCreateEvent`](/docs/change-tracking/config/nerdgraph)(変更追跡機能) にイベントを送信します。<DNT>New Relic Change Tracking for GitHub Copilot</DNT>はレガシーエンドポイントをサポートしていません。

* 各イベントには以下が含まれます：

  * `changelog`フィールドのリリースタグURL。
  * `commit` フィールドのマージコミットSHA。
  * モニターする各デプロイメントに対して、カスタムアトリビュート`watchpoint_monitoring`を`"true"`に設定します。

* サービスはNew Relicにレポートしており、少なくとも3日間の履歴があります。データが少ない場合、すべてのチェックポイントが不確定な結果を返します。

通知を受け取るには、任意で[AutopilotをSlackに接続](/docs/agentic-ai/autopilot/connect-to-slack)してください。<DNT>Copilot</DNT>が問題への対応を自動的に開始するには、組織に<DNT>GitHub Copilot Enterprise</DNT>が必要です。

## GitHub Copilot用のNew Relic Change Tracking (変更追跡機能)を設定します。 [#setup]

<Steps>
<Step>
### GitHubトークンを作成します。 [#create-token]

<DNT>GitHub</DNT>で個人アクセストークンを作成します。きめ細かいトークンが推奨されますが、クラシックトークンも使用できます。手順については、<DNT>GitHub</DNT>ドキュメントの[「きめ細かい個人アクセストークンの作成」](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token)を参照してください。トークンに以下が含まれていることを確認してください：

* リソース所有者としてのお客様の<DNT>GitHub</DNT>組織。
* <DNT>New Relic Change Tracking for GitHub Copilot</DNT>にモニターさせたいリポジトリへのアクセス。
* <DNT>**Read and write**</DNT> <DNT>**Pull requests**</DNT>、<DNT>**Issues**</DNT>、および<DNT>**Contents**</DNT>へのアクセス。

すでに<DNT>GitHub</DNT>を<DNT>Autopilot</DNT>に接続しており、トークンをすでにお持ちの場合は、代わりにそのトークンにこれらの権限を追加できます。

組織でSAML SSOを必須としている場合は、SSO用にトークンを認可してください。<DNT>GitHub</DNT>ではトークンは1回しか表示されないため、生成したらすぐにコピーしてNew Relicに貼り付けてください。
</Step>

<Step>
### GitHubを接続して監視を有効にする [#enable]

<DNT>Autopilot</DNT>の設定を開くには、<DNT>**Ask AI**</DNT>をクリックし、**...**をクリックして、次に<DNT>**Configure**</DNT>をクリックします。

<img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp" />

<DNT>**External MCP connections**</DNT>で、トークンと組織名を使用して<DNT>**GitHub**</DNT>（<DNT>**Public GitHub**</DNT>または<DNT>**GitHub Enterprise Cloud**</DNT>）を接続し、<DNT>**Enable deployment monitoring**</DNT>をオンにします。通知を受信するには、<DNT>**Post alerts to**</DNT>で<DNT>Slack</DNT>チャネルも選択してください。このオプションは、<DNT>Slack</DNT>を<DNT>Autopilot</DNT>に接続した後にのみ表示されます。

<DNT>**Update agent**</DNT>をクリックして変更内容を保存します。
</Step>

<Step>
### 監視が開始されたことを確認する [#verify]

`watchpoint_monitoring`属性を`"true"`に設定して変更をデプロイします。

<CollapserGroup>
<Collapser id="example-event" title="デプロイメントイベントの例">
```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "MERGE_COMMIT"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```
</Collapser>
</CollapserGroup>

<DNT>Autopilot</DNT>がデプロイメント・イベントを検証すると、次のように表示されます：

* マージされたプルリクエストに対する<DNT>Autopilot</DNT>からのコメント。
* <DNT>Slack</DNT>を接続した場合、選択したチャンネルに&quot;監視開始&quot;メッセージが表示されます。以降のチェックポイントの結果は、そのスレッドの返信として表示されます。

どちらも表示されない場合は、デプロイメントイベントが[前提条件](#prerequisites)を満たしていることを確認してください。
</Step>
</Steps>
