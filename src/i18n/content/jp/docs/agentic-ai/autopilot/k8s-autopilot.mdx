Autopilotから移動することなく、Kubernetesの問題を診断できます。Autopilot K8sエージェントは、[New Relic Autopilot](/docs/agentic-ai/autopilot/overview/)内の特化したサブエージェントです。New Relic Autopilotは、AIを活用したオペレーションインターフェースであり、New Relicの自律型オペレーションのコア機能です。テレメトリーを分析し、修復を推奨します。Autopilot K8sエージェントは、[New Relic Autopilot](/docs/agentic-ai/autopilot/overview/)内で特化したサブエージェントとして実行されます。ユーザーは単一の統合されたAutopilotを操作し、Kubernetes関連のクエリは自動的にAutopilot K8sエージェントにルーティングされます。

手動で`kubectl`コマンドを実行し、複数のダッシュボード間でメトリクスを関連付ける代わりに、エージェントがクラスタの状態を分析し、根本原因を特定して、実行可能な修復手順をリアルタイムで提供します。

* [高度な計算](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#advance-compute-capacity-unit)アドオン、または
* レガシー計算（CCU）プラン。

## 主なメリット [#benefits]

* **一般的なKubernetes障害の根本原因分析**：`CrashLoopBackOff`、`OOMKilled`、保留中およびスケジュール不可能なポッド、`ImagePullBackOff`、レプリカの不一致、再起動回数の多さ、ノードプレッシャー、スタックしたロールアウト、DNS、サービスおよびIngressの問題、HPAの動作、ストレージおよびPVCの問題
* **深いコンテキスト**：マニフェスト、イベント、リソースメトリクス、ログ、およびデプロイメント履歴をまとめて分析します。
* **クラスタを超えて**：Kubernetesの問題を、APMサービスや、AWSおよびAzure上のクラウドインフラストラクチャ（障害が発生したインスタンスや異常なロードバランサーのターゲットなど）と関連付けます。
* **修復ガイダンス**：検出だけでなく、具体的な修正手順を提供します。
* **Kubernetesビューからワンクリック**：Kubernetes UI全体の<DNT>**Investigate**</DNT>ボタンにより、表示しているコンテキストで調査を開始します。
* **OpenTelemetryとの連携**: [New Relic Kubernetesインテグレーション](/docs/kubernetes-pixie/kubernetes-integration/get-started/introduction-kubernetes-integration/)または[OpenTelemetry for Kubernetes](/docs/kubernetes-pixie/k8s-otel/intro/)でモニターされているクラスタで同じ診断を実行します。
* **追加の計装は不要**：すでにNew Relicに送信しているKubernetesデータで機能します。

## Autopilot K8sエージェントの仕組み [#how]

New Relic AIチャットサイドバーのAutopilot \[オートパイロット]、またはKubernetesビューの<DNT>**Investigate**</DNT>ボタンからアクセスします。問題を説明するか、プロンプト（たとえば、`"Why are pods in namespace X crashing?"`）を入力して、エージェントによる自律的な調査をトリガーできます。エージェントはクラスタの状態を分析し、メトリクスを関連付け、マニフェストとイベントを検査して根本原因を特定します。その後、実行可能な修復手順をリアルタイムで提供します。

## 前提条件 [#prerequisites]

* [Kubernetesインテグレーション](/install/kubernetes/)または[Kubernetes向けOpenTelemetry](/docs/kubernetes-pixie/k8s-otel/intro/)のいずれかからの、New RelicへのKubernetesデータレポート。アプリケーションパフォーマンス監視（APM）、infrastructureモニタリング、クラウドインテグレーション、Kubernetesデータなどのオブザーバビリティの設定が完全であるほど、エージェントの分析が充実します。
* アカウントでNew Relic [Autopilotが有効化され、セットアップされている](/docs/agentic-ai/autopilot/setup)こと。

## Autopilot K8sエージェントの使用方法 [#usage]

アカウントでAutopilotが有効になると、Autopilot K8sエージェントを使用してKubernetes環境を分析し、インシデントの調査を開始できます。これにアクセスするには3つの方法があります：

* New Relic AIのチャットサイドバーで**Autopilotに直接質問してください**。
* Kubernetesビューの**Investigate \[調査] ボタンから開始します**。[Kubernetesビューからの開始](#investigate)をご覧ください。
* **アラートから：**集計ワークフローが問題をAutopilotに送信し、調査にKubernetesリソースが含まれる場合、Autopilotはその分析の一部として自動的にAutopilot K8sエージェントを呼び出します。既存の[Autopilot集計設定](/docs/agentic-ai/autopilot/setup)以外に、追加の設定は必要ありません。

### Kubernetesビューから開始します [#investigate]

New RelicのKubernetesページには、あらかじめ用意されたプロンプトでAutopilotを開くボタンがあります。プロンプトには、表示しているクラスタ、ネームスペース、エンティティ、ステータスがすでに含まれているため、これらを入力する必要はありません。

| 対象箇所                                                | ボタン                                                                                               | Autopilotに要求する内容                                  |
| :-------------------------------------------------- | :------------------------------------------------------------------------------------------------ | :------------------------------------------------ |
| K8sランディングページ                                        | <DNT>**Investigate**</DNT> エンティティ名またはメトリクス値にカーソルを合わせたときに表示されるホバーレイヤー内                             | 異常なエンティティや異常なメトリクスを診断するか、正常なエンティティに問題がないことを確認します。 |
| Kubernetes navigator \[Kubernetesナビゲーター]            | **クラスタを調査します。**                                                                                   | 重大なアラートや障害が発生しているエンティティから順に、表示されているエンティティを分析します。  |
| Kubernetes navigator \[Kubernetesナビゲーター]            | <DNT>**Investigate**</DNT> クリティカルなエンティティの六角形にカーソルを合わせたときのツールチップ内、またはテーブルの行にカーソルを合わせたときのアクションアイコン内 | そのエンティティの稼働ステータスを診断します。                           |
| Kubernetesイベント                                      | <DNT>**Investigate**</DNT> 警告イベントの理由にカーソルを合わせると表示されるポップオーバー内。ポップオーバーには、イベントの説明とボタンが表示されます         | 警告イベントの根本原因を見つけます                                 |

| K8s entity dashboards \[K8sエンティティダッシュボード]           | <DNT>**Explain this chart**</DNT> または、チャートメニューの<DNT>**Find anomalies**</DNT>                      | チャートがエンティティについて示している内容を説明するか、その中の異常を見つけます。        |

### 使用上のヒント [#tips]

Autopilotは、クエリに埋め込まれたキーワードとコンテキストに基づいて、プロンプトを専用のKubernetes診断エンジンにルーティングします。

質問が確実にAutopilot K8sエージェントに届くようにするには：

* **プロンプトで「K8s」または「Kubernetes」を使用する：**これらの単語のいずれかを含めることは、質問をAutopilot K8sエージェントにルーティングするための最も確実なシグナルです。

* **Kubernetesの用語を具体的に指定する：**`pod`、`node`、`namespace`、`deployment`、`replica`、`container`、`cluster`、`workload`、`CrashLoopBackOff`、`OOMKilled`、`PVC`、`HPA`などのKubernetes固有の用語を含めてください。

  例えば：

  | 効果が低い                 | より効果的                                                               |
  | :-------------------- | :------------------------------------------------------------------ |
  | `Why is my app slow?` | `Why are pods in namespace payments restarting?`                    |
  | `Something is broken` | `Pod checkout-service in cluster prod-east is in CrashLoopBackOff`  |
  | `Fix my deployment`   | `Deployment api-gateway has replica mismatch in namespace frontend` |
  | `Check my cluster`    | `What's the health of my Kubernetes cluster prod-east-1?`           |

* **可能な場合はコンテキストを追加してください。**

  * クラスタ名、ネームスペース、ポッド/デプロイメント名、またはノードを記載してください。
  * `"Pending"`、`"Evicted"`、`"ImagePullBackOff"`などの正確なステータス用語を使用して、症状を説明してください。
  * 関連する場合は、明示的な時間枠を定義してください。たとえば、`"since last rollout"`、`"in the last hour"`です。

* **Paste your own evidence \[独自のエビデンスを貼り付ける]:** `kubectl describe`の出力、ログ、またはエラーメッセージをプロンプトに貼り付けることができます。エージェントは、お客様のNew Relicデータとともにそれらを推論します。

* **自動UIルーティングの活用：**New RelicのKubernetesページ（[Investigate \[調査\] ボタン](#investigate)を含む）からAutopilotを開くと、明示的なキーワードを必要とせずに、クエリが自動的にAutopilot K8sエージェントにルーティングされます。エージェントは、アクティブなUIビューから直接コンテキストメタデータを受け取ります。

  <Callout variant="tip" title="エージェントのルーティングを検証します。">
  エージェントの応答で**Show reasoning** \[推論を表示]を展開することで、クエリがAutopilot K8sエージェントによって処理されたことを確認できます。正しくルーティングされた場合、呼び出されたKubernetes診断ツール（クラスタ分析、マニフェスト検査、イベント相関など）と一緒に、Autopilot K8sエージェントアシスタントへの参照が表示されます。Kubernetes固有の推論が表示されない場合は、より明確なKubernetesキーワードを使用して言い換えてみてください。
  </Callout>

## プライバシーとセキュリティ [#privacy]

エージェントは、New Relicアカウントにすでに取り込まれているテレメトリーデータのみを分析します。クラスタに直接アクセスしたり、コマンドを実行したり、Kubernetesのシークレットを読み取ったりすることはありません。修復手順はユーザー自身が確認して実行するための提案であり、リソースを変更する提案されたコマンドには、最初にその効果を確認できるように`--dry-run=client`が含まれています。

すべてのインタラクションは、既存のNew Relicアカウントの権限およびデータアクセス制御の対象となります。
