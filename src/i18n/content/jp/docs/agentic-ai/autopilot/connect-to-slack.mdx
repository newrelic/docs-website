集計がトリガーされると、調査のために、チームがすでに会話している<DNT>Slack</DNT>とNew Relic UIの間を行き来することがよくあります。そのコンテキストの切り替えにより、対応が遅くなります。

チームがスレッド内で直接調査し、<DNT>Slack</DNT>ワークフローでAutopilotから同じ出力を受け取ることができるように、<DNT>Autopilot</DNT>を<DNT>Slack</DNT>に接続します。質問とともにNew Relicアプリ（たとえば`@New Relic`）をメンションすると、New Relicの権限を使用して返信します。

## 行えること [#what-you-can-do]

アプリを招待した任意のチャネルで、アプリをメンションします（たとえば`@New Relic`）。<DNT>Autopilot</DNT>は以下のことが可能です。

* **アラートのトリアージ**: 集計がトリガーされた理由、影響を受けるもの、および相関するものを確認します。
* **エンティティの健全性の確認**: モニター対象サービスの現在のステータスを取得します。
* **変更の分析**: 最近のデプロイメントがリグレッションを引き起こしたかどうかを確認します。
* **マルチターンの調査を実行**: 同じスレッドでフォローアップの質問をして、さらに深く掘り下げます。
* **調査のステータス、概要、および主要な詳細の取得**: 重大度、根本原因、解決策、検出、割り当てられたインシデントコマンダーなどの詳細に加えて、ステータスと概要情報を取得します。

<DNT>Autopilot</DNT> 同じスレッドで返信し、New Relicの権限で許可されているデータにのみアクセスします。

## 前提条件 [#prerequisites]

始める前に、以下があることを確認してください：

* **設定済みの<DNT>Autopilot</DNT>**：アカウントと権限が設定されたアクティブなエージェント。[Autopilotの設定](/docs/agentic-ai/autopilot/setup)を参照してください。
* **<DNT>Slack</DNT>の管理者アクセス**: New Relicアプリを承認するための<DNT>Slack</DNT>ワークスペースの管理者権限。
* **<DNT>Workflow</DNT> FCM**: <DNT>Slack</DNT>から<DNT>Autopilot</DNT>を呼び出すには、<DNT>Autopilot</DNT> FCMに加えて<DNT>Workflow</DNT> FCMを有効にする必要があります。
* **Permission to create a user API key**: To use <DNT>Autopilot</DNT> in <DNT>Slack</DNT>, your role must allow creating user API keys for your <DNT>Workflow Automation</DNT> accounts.

## Slack接続を設定する [#setup]

<Steps>
  <Step>
    ### Slackワークスペースの接続（管理者） [#connect-slack]

    [組織管理者](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts/#role-scopes)は、<DNT>Autopilot</DNT>の設定中にワークスペースを接続します：

    1. <DNT>**[one.newrelic.com](https://one.newrelic.com)**</DNT>に移動します。

    2. 右上で<DNT>**Ask AI**</DNT>を選択し、次に<DNT>**Configure**</DNT>タブ（歯車アイコン）を選択します。

    3. <DNT>**Agents**</DNT>の下で、<DNT>Autopilot</DNT>を選択します。

    4. <DNT>**Slack (optional)**</DNT>セクションで、 <DNT>**Connect**</DNT>をクリックします。

    5. <DNT>Slack</DNT>の承認画面で:

       1. 接続するワークスペースを選択します。
       2. 要求されたデフォルトの権限を確認し、<DNT>**Allow**</DNT>をクリックします。

    6. 緑色の<DNT>**Connected**</DNT>バッジが表示されることを確認します。

    7. <DNT>**Update agent**</DNT>をクリックします。

    <Callout variant="important">
      ワークスペース接続により、ユーザーは<DNT>Slack</DNT> IDをリンクして、<DNT>Autopilot</DNT>がワークスペースで応答できるようになります。<DNT>Autopilot</DNT>は、接続されている[Slackワークスペース](https://slack.com/help/categories/200122103-Workspace-administration)でのみ応答します。
    </Callout>

    <Callout variant="tip">
      ワークスペースで<DNT>Autopilot</DNT>が応答しないようにするには、このページからいつでもワークスペースを切断できます。
    </Callout>
  </Step>

  <Step>
    ### New Relicアプリをチャンネルに招待する [#invite-to-channel]

    ワークスペースのメンバーは誰でも、New Relicアプリをチャネルに招待できます。チャネル内で、New Relicアプリをメンションします（たとえば、`@New Relic`）。アプリがまだ存在しない場合、<DNT>Slack</DNT>は追加するようにプロンプトを表示します。<DNT>Slack</DNT>チャネルの<DNT>integration</DNT>タブから追加することもできます。
  </Step>

  <Step>
    ### IDをリンクする（初回のみ） [#link-identity]

    IDがリンクされる前に、スレッドで初めてNew Relicアプリをメンションした場合、New Relicアカウントの接続を促すプライベートメッセージが表示されます。<DNT>**Connect**</DNT>をクリックし、New Relicの認証情報でログインしてIDをリンクします。<DNT>**Connect**</DNT>および<DNT>**Authenticate**</DNT>のリンクは10分後に期限切れになります。リンクが期限切れになった場合は、再度New Relicアプリをメンションしてください。

    <Callout variant="important">
      これはワークスペースごとに1回限りの手順です。IDをリンクした後は、再度接続しなくても、そのワークスペースの任意のチャンネルでNew Relicアプリをメンションできます。
    </Callout>
  </Step>
</Steps>

## SlackでAutopilotを使用する [#use-in-slack]

設定後、アプリを招待した任意のチャネル、またはアプリのホームタブから<DNT>Autopilot</DNT>を使用します。

### ホームタブから接続を確認します。 [#home-tab]

\[Home]タブを開いて接続ステータスを確認するには、<DNT>Slack</DNT>のサイドバーでNew Relicアプリをクリックします：

* **未接続**：アカウントをリンクするための<DNT>**Connect to New Relic**</DNT>ボタンがあるウェルカムスクリーン。
* **接続の有効期限切れ**: 再認証するための<DNT>**Authenticate**</DNT>ボタンを含むプロンプト。
* **エラー**: 回復手順が記載された「Something went wrong」メッセージ。

接続すると、ホームタブには現在リンクされているNew Relic組織、<DNT>**Switch orgs**</DNT>オプション、および<DNT>**Disconnect**</DNT>オプションも表示されます。

### 質問する [#ask-a-question]

任意のスレッドで、質問とともにNew Relicアプリ（たとえば`@New Relic`）をメンションします：

```
@New Relic why is checkout-service alerting?
@New Relic what deployed on payment-gateway in the last hour?
@New Relic investigate this alert
```

### コンテキスト内でアラートを調査する [#investigate-in-context]

New Relicがチャネルに集計通知を投稿した場合は、そのスレッドで返信してください。<DNT>Autopilot</DNT>は通知を読み取ってエンティティと問題を特定するため、それらの名前を指定する必要はありません。

### フォローアップの質問をする [#follow-up-questions]

同じスレッドで続行します。<DNT>Autopilot</DNT>はコンテキストを維持するために以前のメッセージを読み取ります：

```
@New Relic what's causing this?
[Autopilot replies with a root cause analysis]
@New Relic what was the deployment before that?
[Autopilot replies with more context]
```

### New Relic組織を切り替える [#switch-orgs]

複数のNew Relic組織にアクセスできる場合は、切断せずに<DNT>Slack</DNT> IDが使用する組織に切り替えてください：

1. <DNT>Slack</DNT>でNew Relicアプリの「ホーム」タブを開きます。
2. <DNT>**Switch orgs**</DNT>をクリックします。
3. New Relicのログインページで、目的の組織のアカウントを使用してサインインします。

認証後、ホームタブには新しくリンクされた組織が表示され、このワークスペースでの今後のメンションはそれをクエリします。

<Callout variant="important">
  <DNT>Slack</DNT>のIDは、ワークスペースごとに一度に1つのNew Relic組織にのみリンクします。切り替えると、以前のNew Relic組織のマッピングが置き換えられます。
</Callout>

### Autopilotへのアクセスを一時停止する [#pause-access]

ワークスペース全体を切断せずに、<DNT>Autopilot</DNT>への自身の直接的かつインタラクティブなアクセスを停止する場合：

1. <DNT>Slack</DNT>のサイドバーで、New Relicアプリをクリックして「ホーム」タブを開きます。
2. <DNT>**Disconnect**</DNT>をクリックします。

<DNT>Autopilot</DNT>へのインタラクティブなアクセスは直ちに停止されます。<DNT>Autopilot</DNT>からの自動更新を含め、ワークスペースでの通知は引き続き受信します。代わりに組織全体のインテグレーションを削除する場合は、[Slackインテグレーションの削除](#remove-integration)を参照してください。

<CollapserGroup>
  <Collapser id="how-data-is-used" title="AutopilotによるSlackデータの使用方法">
    New Relicアプリをメンションすると、スレッドのコンテキストを理解するために、メンションされたスレッドの履歴が最大48時間分読み取られます。

    <Callout variant="caution">
      <DNT>Autopilot</DNT> 呼び出されたスレッド内のすべてのメッセージを読み取ります。これらのスレッドでパスワード、APIキー、トークン、認証情報、またはその他の機密情報を共有しないでください。認証情報が共有された場合は、その情報が使用されないように、代わりに新しいスレッドでNew Relicアプリにメンションしてください。
    </Callout>

    <DNT>Autopilot</DNT> 次のことを行います：

    * メンションされたスレッド内のメッセージを読み取ります。
    * スレッド内のNew Relic通知URLから集計とエンティティの詳細を抽出します。
    * New Relicの権限に基づき、New Relicのインサイトを使用して応答します。
    * すべてのチャンネルメンバーに表示される応答を投稿します。

    <Callout variant="important">
      応答は、New Relicへのアクセス権を持たないユーザーを含め、チャネル内の全員に表示されます。<DNT>Autopilot</DNT>はあなたの権限でデータをクエリしますが、その返信はチャネルに公開されます。
    </Callout>

    ### データ分離 [#data-isolation]

    <DNT>Slack</DNT>からの各リクエストは、以下に分離されます：

    * **リクエストごとの認証情報**：<DNT>Autopilot</DNT>を呼び出すたびに、呼び出し元のユーザーのトークンが使用されます。
    * **資格情報の保存なし**：資格情報はリクエストヘッダーのみを通過します。保存または永続化されることはありません。
    * **スレッド固有**：リクエストは、Autopilotが呼び出されたスレッドにスコープされます。
    * **永続的な<DNT>Slack</DNT>データなし**: <DNT>Autopilot</DNT>は、単一のリクエストに対してのみ、スレッドメッセージを一時的にメモリに保持します。
  </Collapser>

  <Collapser id="nr-connect" title="NR Connect: IDのリンクと認証">
    <DNT>NR Connect</DNT> は、<DNT>Slack</DNT>ユーザーIDをNew Relicアカウントにマッピングする認証ブリッジです。<DNT>Autopilot</DNT>が応答する前に、<DNT>NR Connect</DNT>は<DNT>Slack</DNT>ユーザーIDがNew Relicアカウントにリンクされていること（ユーザーマッピング）、および認証セッションがアクティブであること（有効なトークン）を検証します。

    ### 検証の仕組み [#how-validation-works]

    New Relicアプリをメンションするたびに、システムは以下を確認します：

    1. **ワークスペースの承認**：管理者がこのワークスペースをNew Relic組織に接続しているかどうか。
    2. **ユーザーマッピング**: <DNT>Slack</DNT>のユーザーIDがNew Relicアカウントにリンクされているかどうか。
    3. **トークン検証**: 認証セッションがアクティブで有効期限が切れていないかどうか。

    すべてのチェックに合格すると、<DNT>Autopilot</DNT>はリクエストを処理し、スレッドで返信します。マッピングまたはトークンが失敗した場合、<DNT>**Connect**</DNT>ボタンを含むプライベートメッセージが表示されます。サインインしてから、New Relicアプリを再度メンションします。特定のエラーについては、[Autopilot Slack接続の問題のトラブルシューティング](/docs/agentic-ai/sre-agent/troubleshoot)を参照してください。

    ### リクエスト元による認証チェック [#slack-vs-ui]

    <DNT>Slack</DNT>からのリクエストはNew Relic UIの外部から発生するため、システムはIDマッピングとトークンの両方を検証します。New Relic UI内からは、システムはアクティブなWebセッションを信頼し、マッピングのみを確認します。

  <Collapser id="limitations" title="現在の制限">
    * **テキスト応答のみ**：チャート、画像、およびインタラクティブなボタンは利用できないか、サポートされていません。
    * **スレッドをスコープとするコンテキスト**：<DNT>Autopilot</DNT>はメンションされたスレッドのみを読み取り、<DNT>Slack</DNT>チャネル全体は読み取りません。
    * **アクションの実行なし**: <DNT>Autopilot</DNT>は調査して推奨事項を提示しますが、ロールバックや再起動などの修復アクションは実行しません。
    * **外部インシデントデータなし**：<DNT>Autopilot</DNT>は、<DNT>ServiceNow</DNT>、<DNT>PagerDuty</DNT>、またはその他の外部インシデントデータにアクセスしません。
    * **<DNT>Slack</DNT>のみ**: <DNT>Microsoft Teams</DNT>はまだサポートされていません。
  </Collapser>
</CollapserGroup>

## Slackインテグレーションを削除する [#remove-integration]

<Callout variant="important">
  <DNT>Slack</DNT>ワークスペースからNew Relicアプリをアンインストールすると、完全に削除されます。組織の他のすべての<DNT>Slack</DNT>ベースの集計通知とともに、<DNT>Autopilot</DNT>通知を停止します。代わりに自分自身のアクセスのみを一時停止したい場合は、「[Autopilotへのアクセスを一時停止する](#pause-access)」を参照してください。
</Callout>

<DNT>Slack</DNT>ワークスペースのアドミニストレーターは、<DNT>Slack</DNT>の標準のアプリ削除フローを使用して、New Relicインテグレーションを完全に削除できます。[アプリの削除に関するSlackのドキュメント](https://slack.com/help/articles/360003125231)を参照してください。

アンインストール後、New Relicは対応する<DNT>Slack</DNT>の宛先を自動的に<DNT>**UNINSTALLED**</DNT>としてマークし、非アクティブに設定します。手動で削除する必要はありません。
