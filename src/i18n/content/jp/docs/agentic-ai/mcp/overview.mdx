Ground Truthは、New Relicの運用インテリジェンスレイヤーです。Model Context Protocol（MCP）ツールは、オブザーバビリティデータを整理することで、AIエージェントが技術スタックを理解しやすくします。

MCPは、AIモデルやエージェントが特定のシステムや環境に関する関連情報（コンテキスト）を取得するための標準的な方法です。コンテキストがあることで、AIが現状を理解し、タスクを正確に実行し、有用な応答を提供しやすくなります。MCPサーバーを使用すると、サポートされているAIエージェントが、自然言語を使ってNew Relicのデータを照会・調査したり、そのデータに対して操作を実行したりするためのツールを呼び出せるようになります。その結果、インシデント対応とパフォーマンス分析の迅速化が期待できます。

## 期待できるメリット

MCPサーバーを使用することで、エンジニアや運用チームは次のような実用的なメリットが得られます。

* **直接インテグレーション：**サポート対象の開発環境からNew RelicのMCPツールに直接アクセスできます。これにより、複数のAIツールを切り替える必要がなくなります。
* **トラブルシューティングの迅速化：**MCPを使用することで、オブザーバビリティデータをもとに問題を迅速に発見・修正し、エラーログを分析し、AIから得られる洞察を活用して可能性の高い原因を特定できます。
* **運用クエリ：**AIエージェントに依頼して、アラートの状態確認、アラートレポートの作成、デプロイメントがシステムに与える影響の分析を実行できます。
* **シンプルなデータクエリ：**New Relicクエリ言語（NRQL）に詳しくなくても、平易な英語で質問を作成すると、サーバーがそれをNRQLに変換して結果を取得できます。

## サポート対象のAI開発ツール [#supported-tools]

New Relic MCPは、以下のAI開発環境（サポート対象のMCPクライアント）と連携できます。

* **Claude Code：**Claude向けのコマンドラインインターフェース
* **Antigravity CLI：**Antigravity向けのコマンドラインインターフェース
* **Kiro CLI：**Kiro向けのコマンドラインインターフェース
* **Claude Desktop：**インタラクティブなAI開発のためのデスクトップアプリケーション
* **VS Code：**MCPに対応している統合開発環境

各環境にはそれぞれ独自の強みがあり、どれが適しているかはワークフローの内容によって異なります。MCPクライアントごとの設定手順については、[セットアップガイド](/docs/agentic-ai/mcp/setup)をご覧ください。

## 前提条件 [#prerequisites]

New Relic MCPを使用するには、以下が必要です。

* New Relicアカウント（すべてのアカウントでMCPを利用できます：データまたはCCUユーザーは全員コアツールを利用でき、aCCUユーザーは高度なツールを含むすべてのツールを利用できます）
* `Node.js` のインストール（一部の認証方法で必要）
* 前述したサポート対象のMCPクライアントのいずれかのインストール

### 組織アクセス [#org-access]

接続する前に、New Relicの管理を担当するアドミニストレーターが以下の操作を行う必要があります。

**グループメンバーシップとロール**

デフォルトの組織ロール（`Organization Read Only`、`Organization Manager`、`Organization Product Admin`）またはMCPサーバーの読み取り権限がある組織スコープのカスタムロールが割り当てられたグループのメンバーである必要があります。グループに必要な権限がない場合は、`Organization Manager`または`Authentication Domain Manager`ロールを持つアドミニストレーターに連絡し、グループへの権限付与を依頼してください。

**機能コントロールマネージャー**

組織のアドミニストレーターは、[機能コントロールマネージャー](/docs/accounts/accounts-billing/new-relic-one-user-management/feature-control-manager/)を使用して、MCPアクセスを有効にする必要があります。以下のトグル設定でMCPアクセスを制御できます。**New Relic MCP Server**と**Local Clients**は、デフォルトで有効になっています。その他のサブトグルはすべてデフォルトで無効になっていますが、必要に応じてNew Relicのアドミニストレーターが有効にできます。

* **New Relic MCP Server**：MCPのセットアップに必要です。MCPアクセスを機能させるために有効にする必要があるメイントグルです。
* **Local Clients**：ローカルクライアント接続（Claude Code、Claude Desktop、VS Code、Kiro）に必要です。
* **APIキー**：APIキー接続に必要です（自動スクリプトを含む）。
* **プレビューツール**：MCPプレビュー（非GA）ツールへのアクセスに必要です。
* **Atlassian**：Atlassianインテグレーションに必要です
* **AWS**：AWSインテグレーションに必要です。

### 認証オプション [#auth-options]

* **OAuth（推奨）**：New Relicには事前設定済みのOAuthエンドポイントが用意されています。

  * クライアントID： `pUWGgnjsQ0bydqCbavTPpw==`
  * 認証URL： `https://oauth2.service.newrelic.com/oauth2/auth`
  * トークンURL： `https://oauth2.service.newrelic.com/oauth2/token`
  * スコープ： `["observability:read", "offline", "offline_access"]`

* **ユーザーAPIキー**：**一部のMCPツールはOAuth経由でのみアクセスできる**ことに注意してください。

  1. New Relicにログインしてください
  2. **ユーザーメニュー -&gt; API keys**を選択します。
  3. 新しいユーザーキーを作成するか、既存のユーザーキーをコピーします。
  4. キーの形式：`NRAK-XXXXXXXXXXXXXXXXXXXXX`。

<Callout variant="important">
  一部のツールはOAuth経由でのみ利用可能で、APIキーでは利用できません。例えば、AIを活用した分析ツール（`natural_language_to_nrql_query`、`generate_alert_insights_report`、`generate_user_impact_report`、`analyze_deployment_impact`）やプレビューツール（`search_traces`、`analyze_trace_anomaly`、`analyze_service_dependencies`）が該当します。詳細については、[ツールリファレンス](/docs/agentic-ai/mcp/tool-reference)を参照してください。
</Callout>

## 次のステップ [#next-steps]

サポート対象のMCPクライアントをNew Relicのオブザーバビリティデータに接続する準備はよろしいですか？

1. [サポート対象の環境](#supported-tools)から、使用するサポート対象MCPクライアントを選択します。
2. 設定手順については、[セットアップガイド](/docs/agentic-ai/mcp/setup)をご覧ください。
3. 利用可能なツールについては、[ツールリファレンス](/docs/agentic-ai/mcp/tool-reference)をご覧ください。
4. 自然言語を使ってNew Relicのデータを照会できます。
5. [一般的な問題のトラブルシューティングを行います](/docs/agentic-ai/mcp/troubleshoot)。
