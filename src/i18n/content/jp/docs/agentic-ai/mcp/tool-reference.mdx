New RelicのMCPサーバーは、AIエージェントがオブザーバビリティデータにアクセス・分析できるようにする特殊なツールを提供します。このリファレンスガイドでは、利用可能なすべてのツールをカテゴリ別に整理しています。

## MCPツールの使い方 [#how-to-use]

MCPツールは、AI開発環境において自然言語によるクエリを通じて呼び出されます。ユーザーが正確なツール名やパラメーターを覚える必要はありません。New Relicのデータについて知りたいことを具体的に説明してください。

**クエリ例：**

* 「私のアカウントにはどのようなエンティティが含まれていますか？」
* 「私のウェブアプリケーションに関する最新のアラートを表示してください」
* 「過去1時間で最も多かったエラーは何ですか？」
* 「NRQLを実行してパフォーマンスを分析してください」

開発ツールのAIエージェントは自動的に適切なMCPツールを選択し、適切な形式で結果を出力します。

## ツールの絞り込み `include-tags` [#filter-tools]

一部のツールは、複数の関連タグが付けられているため、複数のカテゴリに表示されます（例えば、`analyze_deployment_impact`は`incident-response`と`advanced-analysis`の両方に関連しています）。

requestsに「`include-tags`」`HTTP`ヘッダーを送信することで、サポート対象のMCPクライアントが受け取るツールを動的に絞り込めます。これにより、必要なツール群だけを指定して、AIモデルが扱うツールの数を減らすことができ、問い合わせに使用するAIモデルの種類を問わず、処理効率や精度の向上が期待できます。

フィルタリングに使用できるタグは、このリファレンスのカテゴリヘッダー（`discovery`、`data-access`、`alerting`、`incident-response`、`performance-analytics`、`advanced-analysis`）に直接対応しています。

### 実装例 [#example]

```json
"servers": {
    "new-relic-mcp-server": {
        "url": "https://mcp.newrelic.com/mcp/",
        "type": "http",
        "headers": {
            "include-tags": "discovery,alerting"
        }
    }
}
```

この例では、AIエージェントには、discovery（例：`get_entity`）とalerting（例：`list_alert_policies`）に分類されたツールのみが表示され、モデルが現在のタスクに最も関連性の高い機能のみに焦点を当てるようにします。

<Callout variant="important">
  **セキュリティとアクセス：**AIエージェントがここに掲載されているツール（例：`get_entity`、`analyze_deployment_impact`、`execute_nrql_query`）を呼び出す際に実行できる操作は、セットアップ時に設定したNew RelicユーザーのOAuthプロファイル（Antigravity CLIの場合はAPIキー）に付与された権限によって厳密に制御されます。このツールは、New Relicのロールベースアクセス制御（RBAC）によって、該当するユーザーアカウントにアクセス権が付与されているデータ、エンティティ、アカウントにのみアクセスできます。OAuthプロファイルまたはAPIキーに特定の操作（例：アラートの表示やNRQLの実行）を行う権限がない場合、ツールの呼び出しは権限エラーで失敗します。
</Callout>

<Callout variant="important">
  一部のツールはOAuth認証が必須で、APIキーでは利用できません。詳細については、[OAuth専用ツール](#oauth-only-tools)セクションをご覧ください。
</Callout>

<Callout variant="tip">
  **レート制限：**MCPサーバーでは、ユーザー1人あたり1時間に最大2,000回のツール呼び出しが可能です。この上限は状況によって異なる場合があります。ユースケースのために上限の引き上げが必要な場合は、[New Relicサポート](https://support.newrelic.com/s/)にお問い合わせください。
</Callout>

<Callout variant="tip">
  **請求：**ほとんどのMCPツールの使用量は、[Core Compute Unit（CCU）](/docs/licenses/license-information/product-definitions/new-relic-one-pricing-definitions/#compute-capacity-unit)単位で測定され、既存のCore Computeの割り当て分に計上されます。4つのAIを活用した分析ツール（`natural_language_to_nrql_query`、`generate_alert_insights_report`、`generate_user_impact_report`、`analyze_deployment_impact`）の使用量は、[高度計算容量ユニット（aCCU）](/docs/licenses/license-information/product-definitions/new-relic-one-pricing-definitions/#compute-capacity-unit)単位で測定され、Advanced Computeアドオンが必要です。
</Callout>

## エンティティおよびアカウント管理（タグ：discovery） [#entity-account]

* `convert_time_period_to_epoch_ms`：時間範囲（例：「過去30分」）をエポックミリ秒に変換します。
* `get_dashboard`：特定のダッシュボードに関する詳細情報を取得します。
* `get_entity`：New RelicエンティティをGUIDで取得するか、名前パターンで検索します。
* `list_related_entities`：指定されたエンティティ`GUID`から1ホップ離れた（関連する）エンティティをリストします。
* `list_available_new_relic_accounts`：ユーザーが利用できるすべてのアカウント`IDs`をリストします。
* `list_dashboards`：New Relicアカウントのすべてのダッシュボードをリストします。
* `search_entity_with_tag`：特定のタグキーと値を使用してエンティティを検索します。
* `list_metric_names`：エンティティまたはアカウントで報告されている利用可能なすべてのメトリクス名（ディメンショナルメトリクスと従来のタイムスライスメトリクス）を検出します。

## データアクセス（タグ：data-access） [#data-access]

* `execute_nrql_query`：NRDBに対してNRQLクエリを実行します。
* `natural_language_to_nrql_query`：自然言語リクエストをNRQLクエリに変換し、実行して結果を返すことにより、書き込みを実行します。

## アラートと監視（タグ：alerting） [#alerts]

* `list_alert_conditions`：特定のアラートポリシーについてアラート条件の詳細をリストします。
* `search_incident`：柔軟なフィルタリング機能を使用して、すべてのアラート（開始イベントと終了イベントの両方）を一覧表示します。
* `list_alert_policies`：指定されたアカウントのアラートポリシーを一覧表示します。必要に応じて、ポリシー名でフィルタリングできます。
* `list_recent_issues`：指定されたアカウントについて、New Relicにおけるすべての未解決の問題を一覧表示します。
* `list_synthetic_monitors`：すべての合成モニター（サービスの可用性とパフォーマンスをチェックする自動テスト）をリストします。
* `list_synthetic_monitor_results`：指定した期間内におけるモニターのSyntheticチェックの実行結果（所要時間、エラー、実行ロケーション）を1件ずつ返します。
* `get_synthetic_check_statistics`：モニターやロケーションをまたがって、syntheticチェックの成功率、失敗数、処理時間のパーセンタイルを集計します。

## アラートへの対応（タグ：incident-response） [#alertevents]

* `analyze_deployment_impact`：特定のエンティティにおけるデプロイメントのパフォーマンスへの影響を分析します。
* `generate_alert_insights_report`：特定の問題に関するアラートインテリジェンス分析レポートを生成します。
* `generate_user_impact_report`：特定の問題に関するエンドユーザーへの影響分析レポートを生成します。
* `list_entity_error_groups`：時間枠内でErrors Inboxから特定のエンティティのエラーグループを取得します。
* `list_change_events`：エンティティ`GUID`で識別されるアプリケーションについて、New Relicからの変更イベントの履歴を一覧表示します。
* `get_error_statistics`：`TransactionError`イベントからの合計エラー数、初回と最後の検出日時、時系列での変化（オプション）を算出します。また、エラークラス、メッセージ、アプリ、`HTTP`ステータスなどに基づいて、柔軟にフィルタリングやファセット化を行うことができます。
* `search_errors`：メッセージ、クラス、`HTTP`ステータス、トレース`ID`などのフィルター条件に一致する未加工のエラーイベントを返します。

## パフォーマンス分析（タグ：Performance-analytics） [#performance]

* `analyze_entity_logs`：アプリケーションログを分析して、エラーパターン、異常な動作、および繰り返し発生する問題を特定します。
* `analyze_golden_metrics`：ゴールデンメトリクス（主要な健全性指標：スループット、レスポンスタイム、エラー率、飽和度）を分析します。
* `analyze_kafka_metrics`：Kafkaメトリクス（コンシューマーラグ、プロデューサースループット、メッセージのレイテンシ、パーティションのバランスなど）を分析します。
* `analyze_threads`：特定のエンティティのスレッドメトリクスデータ（スレッドの状態、CPU使用率、メモリ消費量など）を分析します。
* `analyze_transactions`：特定のエンティティについて、指定した期間内のトランザクションを分析し、処理に時間がかかるトランザクションやエラーが発生しやすいトランザクションを特定します。分析には、P95およびP99のレイテンシーメトリクス（それぞれ、応答時間が長い上位5％および1％のrequestsを区切る閾値）も含まれます。
* `list_garbage_collection_metrics`：指定されたアカウントとエンティティについて、ガベージコレクションとメモリメトリクスを一覧表示します。
* `list_recent_logs`：指定されたアカウントとエンティティ`GUID`について、New Relicからの最近のログを一覧表示します。
* `list_entity_performance_risk_groups`：Performance Risks Inboxから、指定期間内における特定のエンティティのパフォーマンスリスクグループを取得します。
* `get_metric_statistics`：指定したディメンショナルメトリクスまたはタイムスライスメトリクスの集計値（平均、合計、パーセンタイル、レート）を取得します。
* `get_log_statistics`：ログの集計件数、レベル別・属性別の内訳、指定期間内の推移を返します。
* `get_distributed_trace_details`：特定のエンティティ、またはトレース内の個々のスパンについて、すべてのスパン属性、異常情報、スパンリンクを返します。

## 高度な分析（タグ：advanced-analysis） [#advanced-analysis]

* `analyze_deployment_impact`：特定のエンティティにおけるデプロイメントのパフォーマンスへの影響を分析します。
* `generate_alert_insights_report`：特定の問題に関するアラートインテリジェンス分析レポートを生成します。
* `generate_user_impact_report`：特定の問題に関するエンドユーザーへの影響分析レポートを生成します。
* `natural_language_to_nrql_query`：自然言語によるリクエストをNRQLクエリに変換し、実行して結果を返します。

## スキル [#skills]

スキルは、複数のMCPツールを組み合わせたプリセットのワークフローです。オブザーバビリティに関する一般的なシナリオの調査・解決に役立ちます。スキルは[New Relic skills hubリポジトリ](https://github.com/newrelic/nr-skills-hub)で公開されています。

ユーザーはこれらのスキルをダウンロードし、個々のAIエージェントに合わせて設定できます。

利用可能なスキル：

| スキル                     | 説明                                  |
| ----------------------- | ----------------------------------- |
| Discover trace ID       | 特定のリクエストまたはインシデントに関連するトレースIDを特定します。 |
| apm-error-investigation | APMエラーグループの調査を案内します。                |
| NL2NRQL                 | 自然言語の質問を実行可能なNRQLクエリに変換します。         |

## OAuth専用ツール [#oauth-only-tools]

以下のツールはOAuth認証が必須で、APIキーでは利用できません。

**AIを活用した分析ツール：**これらのツールの使用量は、[高度計算容量ユニット（aCCU）](/docs/licenses/license-information/product-definitions/new-relic-one-pricing-definitions/#compute-capacity-unit)単位で測定されます。

* `natural_language_to_nrql_query`
* `generate_alert_insights_report`
* `generate_user_impact_report`
* `analyze_deployment_impact`

**プレビューツール：**[プレビューツール](#preview-tools)を参照してください。これらのツールもOAuthが必須です。

## プレビューツール [#preview-tools]

以下のツールは、GA時点ではプレビュー機能として利用できます。これらは読み取り専用で、評価目的で提供されています。料金はGA後に決定されます。

* `search_traces`：特定のエンティティについて、指定した期間内のトレースを検索し、処理時間、エラー数、またはバックエンド時間を基準にランク付けします。
* `analyze_trace_anomaly`：特定のエンティティのトレースを分析し、トレースの遅延、失敗、大量発生の原因となっているトランザクションまたはエラークラスを特定します。
* `analyze_service_dependencies`: 特定のエンティティのサービス依存関係を分析し、上流と下流の接続関係をマッピングして、異常がある接続にフラグを付けます。
