[NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/)のミューテーションを使用して、New Relicの[メトリクス正規化ルール](/docs/new-relic-solutions/new-relic-one/ui-data/metric-normalization-rules)を管理できます。これらのミューテーションを活用することで、New Relicアカウントから直接、これらのルールを作成、編集、有効化、および無効化できます。これにより、[メトリクスグループ化の問題（MGI）](/docs/new-relic-solutions/solve-common-issues/troubleshooting/metric-grouping-issues)を解決するための合理的かつプログラムによるアプローチが提供されます。

メトリクス正規化ルールは、次の目的で使用されます：

* [メトリックタイムスライスデータ](/docs/data-apis/understand-data/new-relic-data-types/#timeslice-data)をグループ化または除外します。
* New Relicに取り込まれる前に、名前の変更、破棄、または変換を行って、高いカーディナリティのメトリクスを管理します。
* メトリクスを適切に整理して意味のある状態に保つために、[MGI](/docs/new-relic-solutions/solve-common-issues/troubleshooting/metric-grouping-issues)を防止します。
* New Relicに報告される一意のメトリクス名の数を減らします。

## 前提条件 [#prerequisites]

* [New Relicアカウント](https://newrelic.com/signup)。そのアカウントでは、[クエリやミューテーション](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph)に含める必要があるAPIユーザーキーにアクセスできます。

* ユーザータイプと割り当てられたロールは、NerdGraphの権限に影響を与える可能性があります。詳細については、[アクセスに影響する要因](/docs/accounts/accounts-billing/account-structure/factors-affecting-access-features-data#user-permissions)を参照してください。

<Callout variant="tip">
New Relicプラットフォームを使用して、メトリクス正規化ルールを作成することもできます。詳細については、[「メトリクス正規化ルール」](/docs/new-relic-solutions/new-relic-one/ui-data/metric-normalization-rules)を参照してください。
</Callout>

## メトリクス正規化ルールを取得する [#nerdgraph-query]

アカウントに関連付けられているすべてのメトリクス正規化ルールを取得するには、`metricNormalizationRules`クエリを使用してください。このクエリは、ステータスや設定を含む、既存のルールの包括的な概要を提供します。

### サンプルクエリ

```graphql

    {
        actor {
            user {
            name
            }
            account(id: xxxxxx) {
            metricNormalization {
                metricNormalizationRules(enabled: true) {
                action
                applicationGuid
                applicationName
                createdAt
                enabled
                evalOrder
                id
                matchExpression
                notes
                replacement
                terminateChain
                }
            }
            }
        }
    }

```

## 変異 [#nerdgraph-mutations]

以下の[NerdGraphミューテーション](https://docs.newrelic.com/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology)を使用して、メトリクス正規化ルールを管理します：

<CollapserGroup>
<Collapser id="create-metric-normalization-rule" title="メトリクス正規化ルールを作成する">
`metricNormalizationCreateRule`ミューテーションを使用して、New Relicで新しいメトリクス正規化ルールを作成します。

### 入力

<table>
<thead>
<tr>
<th>
属性名
</th>

<th>
データ型
</th>

<th>
説明
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
アカウントID
</td>

<td>
弦
</td>

<td>
（必須）ルールに関連付けられたアカウントID。
</td>
</tr>

<tr>
<td>
アクション
</td>

<td>
弦
</td>

<td>
（必須）以下のアクションのいずれかを選択してください。

* `REPLACE`：`matchExpression`に一致するメトリクスを、`replacement`フィールドで定義された値に置き換えます。
* `IGNORE`：`matchExpression`に一致するメトリクスがNew Relicに報告されるのをブロックします。
* `DENY_NEW_METRICS`：`matchExpression`に一致する新しいメトリクス名の作成を防ぎつつ、既存のメトリクス名は引き続き報告できるようにします。
</td>
</tr>

<tr>
<td>
applicationGuid
</td>

<td>
弦
</td>

<td>
（任意）New Relicにおけるアプリケーションの一意のGUID。空白のままにした場合、これはアカウント全体のルールになります。
</td>
</tr>

<tr>
<td>
有効
</td>

<td>
ブール値
</td>

<td>
（必須）ルールを有効にするには、`true`に設定します。
</td>
</tr>

<tr>
<td>
evalOrder
</td>

<td>
整数
</td>

<td>
（必須）他のルールに対して、ルールが適用される順序を指定します。数値が小さいほど、評価の優先度が高くなります。推奨値は`2000`です。
</td>
</tr>

<tr>
<td>
matchExpression
</td>

<td>
弦
</td>

<td>
（必須）正規化対象のメトリクスに一致する[正規表現](https://regexone.com/)パターンを受け入れます。このフィールドは`^`で始まり、`$`で終わる必要があります。正規化ルールの影響を受けるメトリクスを特定するためのパターンを定義します。例：`^WebTransaction/Uri/RESTfulExample/users/username/[a-zA-Z0-9]+$` パターン`^[a-zA-Z0-9]+$`は、小文字`(a-z)`、大文字`(A-Z)`、および数字`(0-9)`で構成される任意の文字列に一致します。
</td>
</tr>

<tr>
<td>
メモ
</td>

<td>
弦
</td>

<td>
正規化ルールに関する追加のメモまたはコメント。
</td>
</tr>

<tr>
<td>
置換
</td>

<td>
弦
</td>

<td>
このフィールドは、`action`ドロップダウンリストから`REPLACE`オプションが選択されている場合にのみ必須です。`matchExpression`に一致するすべてのメトリクス名を置き換えます。例を以下に示します。 `WebTransaction/Uri/RESTfulExample/users/username/{username}$`
</td>
</tr>

<tr>
<td>
terminateChain
</td>

<td>
ブール値
</td>

<td>
（必須）`true`に設定されている場合、一致したメトリクスにはこれ以上のルールは適用されません。
</td>
</tr>
</tbody>
</table>

### サンプルクエリ

```graphql

    mutation {
        metricNormalizationCreateRule(
            accountId: xxxxxx
            rule: {action: REPLACE, applicationGuid: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx", enabled: false, evalOrder: 2000, matchExpression: "^WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/[a-f0-9]+$", notes: "rules to replace", replacement: "WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/{guid}", terminateChain: true}
        ) {
            errors {
                message
                type
            }
            rule {
                action
                applicationGuid
                applicationName
                createdAt
                enabled
                evalOrder
                id
                matchExpression
                notes
                replacement
                terminateChain
            }
        }
    }

```

                    "id": 29205,

                    "replacement": "WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/{guid}",
