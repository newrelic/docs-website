カスタムウィジェットを使用すると、独自のNRQLクエリから作成したチャートの視覚化によって、Media Streamingダッシュボードを拡張できます。組み込みの品質メトリクスが、チームでモニターする必要がある特定のデータポイントをカバーしていない場合に、これらを使用します。

<Callout variant="important">
  各アカウントは、**ダッシュボードコンテキストごとに50個のカスタムウィジェット**というソフトリミットをサポートしています — <DNT>**Video quality metrics**</DNT>用に50個、<DNT>**Ad quality metrics**</DNT>用に50個で、個別にカウントされます。制限に達した場合は、新しいカスタムウィジェットを追加する前に、既存のカスタムウィジェットを削除してください。既存のウィジェットは引き続き正常に機能します。
</Callout>

## あなたが始める前に [#prereqs]

カスタムウィジェットを作成する前に、以下が必要です：

* <DNT>Streaming Video &amp; Ads</DNT>エージェントがインストールされたNew Relicアカウントへのアクセス。まだ設定していない場合は、[Streaming Video &amp; Adsエージェントのインストール](/docs/streaming-video-&-ads/installation/install-the-streaming-video-&-ads-agent)をご覧ください。
* [品質メトリクスセクション](/docs/streaming-video-&-ads/view-data-in-newrelic/streaming-video-&-ads-features)に表示される<DNT>**+ Add Custom Widget**</DNT>ボタン。そうでない場合は、New Relicアカウントチームに連絡してアクセスをリクエストしてください。

## NRQLクエリを記述する [#writing-queries]

NRQLエディターは、有効なNRQLクエリをすべてサポートしています。NRQL構文の概要については、[『NRQLの概要』](/docs/nrql/get-started/introduction-nrql-how-nrql-works)をご覧ください。

### クエリの要件 [#query-requirements]

カスタムウィジェットのクエリには、標準のNRQLに加えて2つの追加要件があります：

* クエリに直接`SINCE`または`UNTIL`句を記述しないでください。クエリの実行時に、ダッシュボードのタイムピッカーが自動的に時間範囲を追加します。
* ダッシュボードレベルのフィルターバーの選択に応答するには、クエリに[フィルタープレースホルダー](#placeholders)を含めます。

### フィルタープレースホルダー [#placeholders]

クエリの実行時に、ダッシュボードはグローバルフィルターを適用します。クエリに直接プレーンな`WHERE`句を記述した場合、ダッシュボードはユーザーが選択したフィルター条件をそこに挿入できません。フィルターのプレースホルダーは、クエリの実行時にアクティブなフィルター条件に置き換えられる特別なNRQLコメントです。

| プレースホルダー                        | 次で置き換え              | 用途                                                                                |
| ------------------------------- | ------------------- | --------------------------------------------------------------------------------- |
| `/* {whereClause} */`           | `WHERE [filters]`   | クエリに既存の`WHERE`句がありません。                                                            |
| `/* {andWhereClause} */`        | `AND [filters]`     | クエリにはすでに`WHERE`句が含まれています — フィルターを追加します                                            |
| `/* {aggregatorWhereClause} */` | `, WHERE [filters]` | クエリは既存の内部`WHERE`句を持たない`filter()`集計を使用します — フィルターがアクティブでない場合、`filter()`ラッパーは削除されます |

**例 — 既存のWHERE句がない場合：**

```sql
SELECT count(*) FROM VideoAction /* {whereClause} */
```

フィルター`City = Ashburn`を適用した場合：

```sql
SELECT count(*) FROM VideoAction WHERE city = 'Ashburn' SINCE 30 minutes ago UNTIL now
```

**例 — 既存のWHERE句：**

```sql
SELECT count(*) FROM VideoAction
WHERE actionName = 'QOE_AGGREGATE' /* {andWhereClause} */
```

フィルター`City = Ashburn`を適用した場合：

```sql
SELECT count(*) FROM VideoAction
WHERE actionName = 'QOE_AGGREGATE' AND city = 'Ashburn' SINCE 30 minutes ago UNTIL now
```

**例 — 混在する集計を使用した比率クエリ：**

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' /* {andWhereClause} */)
     / filter(uniqueCount(viewId) /* {aggregatorWhereClause} */)
  AS 'avgWatchTime'
TIMESERIES
```

フィルター`City = Ashburn`を適用した場合：

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' AND city = 'Ashburn')
     / filter(uniqueCount(viewId), WHERE city = 'Ashburn')
  AS 'avgWatchTime'
TIMESERIES SINCE 30 minutes ago UNTIL now
```

アクティブなフィルターがない場合：

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT')
     / uniqueCount(viewId)
  AS 'avgWatchTime'
TIMESERIES SINCE 30 minutes ago UNTIL now
```

<Callout variant="tip">
  プレースホルダーは有効なNRQLコメントです — ダッシュボードでフィルターがアクティブになっていない場合でも、<DNT>**Run Query**</DNT>をクリックすると機能します。
</Callout>

### ブロックされたキーワードと文字 [#blocked]

偶発的なデータ変更を防ぐため、NRQLエディターは以下を含むクエリを拒否します：

* キーワード`DROP`、`DELETE`、`INSERT`、`UPDATE`、`CREATE`、または `ALTER`
* クエリのチェーンを可能にするセミコロン（`;`）

これらのいずれかを含むクエリは検証に失敗し、保存やプレビューができません。

### クエリの例 [#sample-queries]

以下の例は、動画および広告監視の一般的なクエリパターンを示しています。それぞれが、そのクエリ構造に適切なフィルタープレースホルダーを使用します。

**基本的な時系列 — ビデオの合計開始数：**

```sql
SELECT count(*) AS 'Video Starts'
FROM VideoAction
WHERE actionName = 'CONTENT_START' /* {andWhereClause} */
TIMESERIES
```

**フィルターインテグレーションを使用したユニーク視聴者数：**

```sql
SELECT uniqueCount(viewId) AS 'Unique Viewers'
FROM VideoAction /* {whereClause} */
TIMESERIES
```

**イベントタイプ全体のエラー率：**

```sql
SELECT count(*) AS 'Error Count'
FROM VideoErrorAction, VideoAction
WHERE actionName = 'CONTENT_ERROR' /* {andWhereClause} */
TIMESERIES
```

**平均視聴時間（ネストされた集計との比率）：**

```sql
FROM VideoAction
SELECT filter(sum(elapsedTime), WHERE actionName = 'CONTENT_HEARTBEAT' /* {andWhereClause} */)
     / filter(uniqueCount(viewId) /* {aggregatorWhereClause} */)
  AS 'avgWatchTime'
TIMESERIES
```

### 制限 [#known-limitations]

グローバルフィルターが有効な場合、一部のNRQLクエリパターンはサポートが限定的であるか、未テストです。完全なリストについては、[Streaming Video &amp; Adsの制限事項](/docs/streaming-video-&-ads/limitations#nrql-patterns)をご覧ください。

## カスタムウィジェットを作成する [#create]

カスタムウィジェットを作成するには：

1. <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Streaming Video &amp; Ads**</DNT>に移動し、<DNT>**Video Overview**</DNT>または<DNT>**Ads Overview**</DNT>を選択します。
2. <DNT>**Video Quality Metrics**</DNT>または<DNT>**Ad Quality Metrics**</DNT>セクションまでスクロールダウンします。
3. セクションヘッダーの<DNT>**+ Add Custom Widget**</DNT>をクリックしてください。
4. ウィジェットの一意のタイトルを入力してください。
5. NRQLエディタでNRQLクエリを記述してください。構文、フィルターのプレースホルダー、例については、上の[NRQLクエリの記述](#writing-queries)をご覧ください。
6. ライブデータに対する結果をプレビューするには、<DNT>Run Query</DNT>をクリックします。この操作ではウィジェットは保存されません。プレビューを使用して、チャートが期待どおりのデータをレンダリングすることを確認し、フィルターがアクティブなときにフィルターのプレースホルダーが正しく解決されることを検証し、保存する前に構文エラーや論理エラーを検出してください。
7. プレビューが読み込まれると、チャートタイプのピッカーが表示されます。デフォルトは<DNT>Line</DNT>です — 必要に応じて別のタイプを選択してください。クエリ結果に推奨されないチャートタイプはグレーアウトして表示される場合がありますが、それでも次のいずれかを選択できます：**Billboard**、**Line**、**Area**、**Bar**、**Table**、または**Pie**。
8. <DNT>**Save**</DNT>をクリックします。New Relicは、メトリクスセレクターのドロップダウンの<DNT>**Custom Metrics**</DNT>セクションにウィジェットを追加し、品質メトリクスグリッドの上部にレンダリングします。ウィジェットはセッション間で保持されます。

<Callout variant="tip">
  ウィジェットの利用可否は、作成するビューによって異なります：

  * **全プラットフォームビュー**（Video OverviewまたはAds Overview）：ウィジェットはアカウントのすべてのユーザーに表示されます。
  * **単一アプリケーションビュー**（特定のアプリケーションのページ）：ウィジェットはそのアプリケーションに固有のものです。

  チャートタイプはビューに依存しません — 設定したチャートタイプは、使用するビューに関係なくすべての閲覧者に適用されます。
</Callout>

## カスタムウィジェットを編集する [#edit]

カスタムウィジェットを編集するには：

1. <DNT>**Quality Metrics**</DNT>セクションで、変更するカスタムウィジェットを見つけます。
2. ウィジェットカードの鉛筆<Icon name="fe-edit-2" />アイコンをクリックします。既存のタイトルとクエリが事前に入力された状態でエディタが開きます。
3. 変更を行い、<DNT>**Run Query**</DNT>をクリックして確認し、<DNT>**Save**</DNT>をクリックします。

保存時：

* 元の作成日とウィジェットの識別情報は保持されます。
* ウィジェットは更新されたクエリで直ちに再レンダリングされます。
* タイトルを変更すると、メトリクスセレクタのドロップダウンで更新されます。

## カスタムウィジェットを削除する [#delete]

カスタムウィジェットを削除するには：

1. <DNT>**Quality Metrics**</DNT>セクションで、ウィジェットカードの<Icon name="fe-more-horizontal" />アイコンをクリックします。
2. <DNT>**Delete**</DNT>を選択します。
3. プロンプトで確認します：*「『\[Widget Title]』を削除してもよろしいですか？この操作は元に戻せません。」*

削除された場合：

* New Relicはウィジェットを完全に削除します。
* ダッシュボードからウィジェットカードが直ちに削除されます。
* メトリクスセレクターのドロップダウンからタイトルのエントリが削除されます。
* ウィジェットが選択されていた場合、ダッシュボードは自動的にその選択を解除します。

<Callout variant="caution">
  削除は元に戻せません。後で必要になる可能性がある場合は、ウィジェットを削除する前にNRQLクエリをコピーしてください。
</Callout>

## トラブルシューティング [#troubleshoot]

以下の症状から該当するものを探してください。問題は、最も一般的なものから順に並んでいます。

### ダッシュボードフィルターを適用してもウィジェットが更新されない [#widget-not-responding-to-filters]

クエリにフィルタープレースホルダーがありません。`/* {whereClause} */`、`/* {andWhereClause} */`、または`/* {aggregatorWhereClause} */`がない場合、ウィジェットは常に記述されたとおりにクエリを実行し、ダッシュボードのフィルターバーの選択を無視します。クエリ構造に適切なものを選択するには、[フィルタープレースホルダー](#placeholders)を参照してください。

### フィルターは適用されるが、クエリがエラーを返すかデータを返さない [#wrong-placeholder]

間違ったプレースホルダーのタイプを使用した可能性があります。確認事項：

* クエリに`WHERE`句がない場合は、`/* {whereClause} */`を使用します。
* クエリレベルですでにクエリに`WHERE`句が含まれている場合は、`/* {andWhereClause} */`を使用してください。
* プレースホルダーが既存の内部 `WHERE` のない `filter()` 集計内にある場合は、`/* {aggregatorWhereClause} */` を使用してください。

誤ったプレースホルダーを使用すると、クエリの実行時に無効なNRQLが生成され、失敗の原因となります。

### クエリが検証に失敗するか、保存されない [#query-blocked]

クエリに、`DROP`、`DELETE`、またはセミコロンなどの[ブロックされたキーワードまたは文字](#blocked)が含まれていないか確認してください。また、クエリが以下の要件を満たしているか確認してください：

* クエリには`SELECT`句と`FROM`句の両方が含まれています。
* エディターのインライン検証で構文エラーが指摘されていないこと。

### ウィジェットを保存できません — タイトルがすでに存在します [#duplicate-title]

同じダッシュボードコンテキスト（ビデオまたは広告品質メトリクス）に同じタイトルのウィジェットがすでに存在する場合、保存に失敗し、トースト通知が表示されます：

* **タイトル:** ウィジェットの保存に失敗しました
* **説明:** この名前のウィジェットはすでに存在します

タイトルの照合では大文字と小文字は区別されません — `My Widget`と`MY WIDGET`は同じタイトルとして扱われます。別のタイトルを選択するか、先に既存のウィジェットの名前を変更してください。

### ウィジェットは保存されるが、ページを更新すると消える [#widget-not-saving]

これは保存の失敗を示している可能性があります。保存時に表示されたトースト通知を確認してください — ネットワークエラーが原因で保存に失敗したかどうかが示されます。保存を再試行してください。問題が解決しない場合は、New Relicアカウントチームにお問い合わせください。

### 新しいウィジェットを追加できません [#limit-reached]

このダッシュボードコンテキスト（動画または広告品質メトリクス）の50ウィジェットのソフトリミットに達しました。既存のカスタムウィジェットを少なくとも1つ削除してから、新しいウィジェットを追加してみてください。

### 「+ カスタムウィジェットを追加」ボタンが表示されません [#button-not-visible]

New Relicがこの機能へのアクセスを制御します。アクセスをリクエストするには、New Relicアカウントチームにお問い合わせください。
