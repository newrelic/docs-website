<DNT>Performance Risks inbox</DNT>にアクセスして使用することで、アプリケーションパフォーマンスの問題がエンドユーザーに影響を与える前に、プロアクティブに特定して解決できます。このガイドでは、<DNT>Performance Risks inbox</DNT>へのアクセス方法、アカウント全体の概要の表示、特定のリスクの分析と推奨事項の取得、検出閾値の更新、およびNew Relic MCPサーバー内でのツールの使用方法について説明します。<DNT>Performance Risks inbox</DNT>の概要とその主な利点の詳細については、[<DNT>Performance Risks inbox</DNT>の概要](/docs/errors-inbox/performance-risks/introduction)を参照してください。

## パフォーマンス リスク インボックスにアクセスする [#access]

<DNT>Performance Risks inbox</DNT>には2つの方法でアクセスできます：単一のエンティティまたはワークロードをスコープとするエンティティレベル、またはアカウント内のすべてのエンティティを対象とするアカウントレベルです。

* [エンティティレベルでのアクセス](#access-entity)
* [アカウントレベルでのアクセス](#access-account)

### エンティティレベルでのアクセス [#access-entity]

エンティティレベルでは、<DNT>Performance Risks inbox</DNT>は単一のエンティティまたはワークロードのテレメトリーデータのパフォーマンスの問題を表示します。これは以下で利用可能です：

* APMサービス
* ブラウザ アプリケーション
* ワークロード

**エンティティの<DNT>Performance Risks inbox</DNT>にアクセスするには：**

1. <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities)</DNT>に移動してから、<DNT>**APM &amp; Services**</DNT>、<DNT>**Browser**</DNT>、または<DNT>**Workloads**</DNT>を選択します。
2. 必要なエンティティまたはワークロードを選択します。
3. ナビゲーションペインの<DNT>**Triage**</DNT>セクションで、<DNT>**Performance Risks**</DNT>をクリックします。

### アカウントレベルでのアクセス [#access-account]

アカウントレベルでは、<DNT>Performance Risks inbox</DNT>は2つのビューで利用できます：アカウント全体のダッシュボード、および選択したワークロードまたはエンティティをスコープとするパフォーマンスリスクグループのリストです。

**アカウントの<DNT>Performance Risks inbox</DNT>にアクセスするには：**

1. <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox</DNT>に移動します。
2. エンティティナビゲーションペインの<DNT>**Performance Risks**</DNT>セクションで、アカウント全体のダッシュボードの場合は<DNT>**Performance Overview**</DNT>をクリックし（[パフォーマンスの概要の表示](#overview)を参照）、スコープされたリストの場合は<DNT>**Risk Groups**</DNT>をクリックします。
3. <DNT>**Risk Groups**</DNT>で、スコープセレクターを使用して<DNT>**Workload**</DNT>または<DNT>**Entities**</DNT>を選択し、確認する特定の[ワークロード](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview)またはエンティティを選択するか、検索ボックスを使用して名前または説明で検索します。
4. オプションで、<DNT>**Performance risk group metadata state**</DNT>(たとえば<DNT>Unresolved</DNT>)によるフィルターなどをさらに追加し、<DNT>**Sort by**</DNT>を使用して結果の順序を変更します。

## パフォーマンスリスクの表示と分析 [#view-analyze]

<DNT>Performance Risks inbox</DNT>にアクセスすると、検出された問題を2つの方法で表示できます：<DNT>**Triage**</DNT>ビューと<DNT>**Group performance risks**</DNT>ビューです。どちらのビューも同じ基になるデータを表示しますが、異なる分析方法を提供します。

### トリアージ [#triage]

<DNT>**Triage**</DNT>ビューは、類似したパフォーマンスリスクを自動的に処理してグループ化します。類似のクエリは計算、保存され、単一のパフォーマンスリスクグループにマージされます。たとえば、`IN`句のバリエーションなど、同じパターンを共有する複数のクエリは、個別の項目として表示されるのではなく、1つのエントリにグループ化されます。これにより、個々の発生を個別に確認することなく、最も影響の大きい問題を特定して優先順位を付けることが容易になります。

アプリケーション全体のパターンを特定するために、パフォーマンスの問題の事前グループ化された概要が必要な場合は、<DNT>**Triage**</DNT>ビューを使用します。

<img title="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." alt="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." src="/images/performancerisks_triage.webp" />

### グループのパフォーマンスリスク [#group]

<DNT>**Group performance risks**</DNT>ビューには、事前に計算されたグループ化なしで、生のパフォーマンスリスクデータが表示されます。通常のクエリ表現（カンマや疑問符のプレースホルダーなど）が表示され、次のようなさまざまな属性に基づいてデータをフィルタリングおよびグループ化できます：

* パフォーマンスリスクの影響を受けるユーザー
* コールを生成するサービス
* クエリをトリガーするAPI

調査に関連する特定の属性に基づいてパフォーマンスリスクを分析する必要がある場合は、<DNT>**Group performance risks**</DNT>ビューを使用してください。

<img title="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." alt="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." src="/images/performancerisks_grpperrisk.webp" />

## 推奨事項の取得 [#recommendations]

<DNT>**Triage**</DNT>ビューから、その発生を手動で調査する代わりに、特定のパフォーマンスリスクに対するAIを活用した推奨事項を生成できます。

**パフォーマンスリスクに関する推奨事項を取得するには：**

1. <DNT>**Triage**</DNT>ビューから、複数回発生しているパフォーマンスリスクを開きます。
2. <DNT>**Generate insights**</DNT>をクリックします。

<DNT>Performance Risks inbox</DNT> そのパフォーマンスリスクの発生を分析し、根本原因に関する仮説と、それを解決するために推奨される次のステップを返します。正確な推奨事項は、検出されたパフォーマンスリスクによって異なります。

<img title="Sample performance risk recommendations." alt="Sample performance risk recommendations." src="/images/PRinsights.webp" />

<Callout variant="important">
  New Relicは、すべてのアカウントでデフォルトでAI機能を有効にします。このオプションが表示されない場合、アカウントで有効になっていない可能性があります。アクセスをリクエストするには、組織の管理者に連絡してください。
</Callout>

推奨事項で閾値の調整が提案されている場合は、[閾値の設定](#set-thresholds)をご覧ください。

## 閾値の設定 [#set-thresholds]

<DNT>Performance Risks inbox</DNT> 設定可能な閾値を使用して、パフォーマンスの異常を自動的に検出します。アカウントレベルとエンティティレベルの両方で — [ワークロード](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview)を含め — これらの閾値を更新して、検出基準が特定のパフォーマンス監視のニーズと優先順位に確実に一致するようにすることができます。これらの閾値は、何がパフォーマンスリスクを構成するかを決定し、<DNT>Performance Risks inbox</DNT>がアプリケーション内の最も関連性が高く対処可能なパフォーマンスの問題について確実にアラートを出すのに役立ちます。

アカウントまたはエンティティレベルでパフォーマンスリスクの閾値を設定できます：

* [アカウントレベルの閾値](#account-thresholds)
* [エンティティレベルの閾値](#entity-thresholds)

### アカウントレベルの閾値を設定します。 [#account-thresholds]

アカウントレベルで閾値を設定すると、アカウント内のすべてのエンティティに適用されるデフォルトのパフォーマンスリスク検出基準を確立できます。これは、一貫した監視基準を維持し、すべてのアプリケーションが同じパフォーマンスベンチマークに基づいて評価されるようにするために役立ちます。

**アカウントレベルで閾値を設定するには：**

<CollapserGroup>
  <Collapser id="new-account-thresholds" title="新しいアカウントレベルの閾値">
    1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox &gt; Performance Thresholds**.</DNT>に移動します。
    2. **Accounts** \[アカウント] タブで、<DNT>**+ New**</DNT>をクリックします。
    3. <DNT>**Account**</DNT>ドロップダウンから、新しい閾値を作成するアカウントを選択します。
    4. 各アナライザーに必要な制限を設定します。
    5. <DNT>**Submit**</DNT>をクリックして保存します。
  </Collapser>

  <Collapser id="edit-account-thresholds" title="既存のアカウントレベルの閾値を編集">
    1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox &gt; Performance Thresholds**.</DNT>に移動します。
    2. **Accounts** \[アカウント]タブで、更新するアカウントの横にある<DNT>**Edit**</DNT>ボタンをクリックします。
    3. 各アナライザーに必要な制限を設定します。
    4. <DNT>**Submit**</DNT>をクリックして保存します。

    <Callout variant="tip">
      閾値を変更すると、New Relicは誰が変更を行ったかを追跡するためにユーザー名を表示します。
    </Callout>
  </Collapser>
</CollapserGroup>

**エンティティレベルで閾値を設定するには：**

特定のエンティティの閾値は、次のいずれかの方法で設定できます：

### チャートに閾値線を表示する [#threshold-guidelines]

パフォーマンスリスクチャートには、値が予想される範囲内にあるかどうかを解釈するのに役立つ参照線が表示されます：

* **最小および最大のガイドライン**：そのチャートのために収集された履歴データから自動的に計算され、時間の経過に伴う値の一般的な範囲を示します。
* **現在の閾値**：アカウントレベルまたはエンティティレベルの閾値設定に基づいて、そのアナライザーで現在アクティブな閾値を反映します。両方が設定されている場合、エンティティレベルの閾値が優先されます。

閾値設定を開く必要なく、これらの線を使用して、メトリクスが設定された閾値にどれくらい近いかを確認します。

## New Relic MCPサーバーのパフォーマンスリスクインボックスツールを使用してください。 [#using]

[New Relic](/docs/agentic-ai/mcp/overview/) MCPサーバー<DNT>Performance Risks inbox</DNT> で[`list_entity_performance_risk_groups`](/docs/agentic-ai/mcp/tool-reference/#performance) ツール（ ）にアクセスすることもできます。このツールは、特定のエンティティについて検出されたすべてのパフォーマンスリスクを、リスクタイプ、重大度、発生回数などの詳細とともに一覧表示します。このツールを使用して、パフォーマンスリスクデータをプログラムで取得できます。
