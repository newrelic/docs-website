ノートブック変数を使用すると、クエリブロック全体で複数のクエリにカスケードする動的パラメーターを設定できます。静的なビューをフィルタリングする[ダッシュボードテンプレート変数](/docs/query-your-data/explore-query-data/dashboards/dashboard-template-variables)とは異なり、ノートブック変数は、ドキュメント全体の基盤となるロジックを駆動する挿入されたパラメーターとして機能します。

**[one.newrelic.com](https://one.newrelic.com) &gt; <DNT>All capabilities</DNT> &gt; <DNT>Notebooks</DNT>**に移動します。

## ノートブックで変数を使用する理由 [#why-use-variables]

ノートブックの変数を使用すると、次のようなインタラクティブなエクスペリエンスを構築できます：

* エンジニアが特定の`hostName`または`transactionId`を入力して、ターゲットのシステムヘルスレポートを即座に生成する**パラメータ化されたランブック**。
* インシデントを分析するために特定のタイムスタンプ、リージョン、またはアプリケーション名で更新できる**ポストモーテムテンプレート**。
* ユーザーが`errorThreshold`や`latencyTarget`などの変数を微調整して、さまざまなパラメーターが視覚化されたデータにどのように影響するかを確認できる**インタラクティブな閾値**。

主な利点は次のとおりです。

* **実行可能なランブックの作成**: 変数を使用すると、ノートブックは静的なページからインタラクティブなツールに変わります。集計イベントの調査、パフォーマンス分析、およびチームのコラボレーションのための、適応性の高いワークフローを構築できます。
* **ナレッジ共有の標準化**: 保存されたドキュメントとして、分析ワークフローを同僚と共有できます。ユーザーは複雑な<DNT>NRQL</DNT>クエリを書き直す必要はありません — 事前定義された変数から新しい変数値に変更して、ワークフローを実行するだけです。

## ノートブック変数を定義する [#define-variable]

データ取得と視覚化をパラメーター化するために、<DNT>NRQL</DNT>クエリブロックに挿入する変数を定義します。

変数を定義するには:

1. 開いているノートブックで、インターフェイスの上部にある変数バーを見つけます。
2. <DNT>**+ Add variable**</DNT>をクリックします。
3. 変数のタイプ（テキスト入力、ドロップダウン、数値など）を設定し、デフォルト値を指定します。

### 変数の命名規則 [#naming-rules]

変数の名前を付けるときは、次の点に注意してください：

* 名前は、ノートブックブロックで使用する、`{{...}}`で囲まれた正確な文字列です。たとえば、変数の名前を`targetApp`にした場合、クエリブロックでは`{{targetApp}}`として参照します。
* 変数名は大文字と小文字が区別され、ノートブック内で一意である必要があります。
* 他のユーザーにとってランブックが一目でわかるように、分かりやすい名前を選択してください（たとえば、`var1`ではなく`failingHost`）。

## クエリブロックで変数を使用する [#use-variable]

定義したら、`{{variableName}}`構文を使用して、<DNT>NRQL</DNT>クエリ内の任意の場所で変数を参照します：

```sql
SELECT average(cpuPercent) FROM SystemSample WHERE hostname = {{failingHost}} TIMESERIES
```

```sql
SELECT latest(cpuPercent) FROM ProcessSample WHERE hostname = {{failingHost}} FACET processDisplayName
```

クエリを実行すると、変数バーで設定した変数値が実行時にクエリに代入されます。変数の値を変更してクエリを再実行すると、その変数を参照するすべてのブロックが即座に更新されます。

## ランブックでインシデント対応を自動化する [#runbook-use-case]

ノートブック変数の最も強力なアプリケーションは、インシデント対応のための実行可能なランブックを作成することです。ノートブック変数を[<DNT>New Relic</DNT>ワークフロー](/docs/alerts/get-notified/incident-workflows)と組み合わせることで、集計のトリガーから調査開始までの引き継ぎを自動化できます。
