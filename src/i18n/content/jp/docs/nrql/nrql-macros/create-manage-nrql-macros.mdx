マクロを作成する前に、[マクロの権限](/docs/nrql/nrql-macros/nrql-macros-overview/#macro-permissions)と以下の命名規則および式規則を確認してください。これらの規則に従わないマクロは、保存しようとしたときに検証に失敗します。

## マクロのルールと制限事項 [#macro-rules]

<Callout variant="important">
マクロは、組織内のすべてのユーザーに表示されます。マクロを作成または更新する際は、機密情報やアカウント固有の情報を含めないでください。
</Callout>

<CollapserGroup>
<Collapser id="macro-naming-rules" title="命名規則">
マクロ名は以下のルールに従う必要があります：

* 組織内で一意である必要があります。
* 次のような、負でない整数である必要があります `3`
* `.`文字を含めることはできません。
* 500文字以下である必要があります。
* `$`文字で開始することはできません。
* 作成時にバッククォートで囲んではなりません。
* マクロ名に特殊文字が含まれる場合は、バッククォートで囲む必要があります。例：`` $`my#Macro` ``。
</Collapser>

<Collapser id="macro-expression-rules" title="式のルール">
マクロ式は次のルールに従う必要があります：

* 有効なNRQL式、または式のリストである必要があります。
* 3,000文字以下である必要があります。
* 句ではなく、式である必要があります。たとえば、`count(*)`は有効ですが、`SELECT count(*)`は有効ではありません。
* 単独のクエリではなく、括弧で囲まれたサブクエリである必要があります。たとえば、`(FROM Transaction SELECT uniques(userId))`は有効ですが、`FROM Transaction SELECT uniques(userId)`は有効ではありません。
* 含む属性リストではなく、特定の属性を返す必要があります。 `*`

有効な式の例：

* `count(*)`
* `(1, 2, 3)`
* `(FROM Transaction SELECT uniques(userId))`
</Collapser>

<Collapser id="macro-limitations" title="制限">
NRQLマクロには次の制限があります：

* **アラート**：マクロはアラート条件ではサポートされていません。
* **オートコンプリート**：クエリビルダーはマクロを提案したり、マクロ式を使用して提案を絞り込んだりしません。
* **テンプレート変数**：マクロ内でテンプレート変数を使用することはできません。
* **ネストされたマクロ**：マクロはネストできません。マクロの式に別のマクロへの参照を含めることはできません。
* **リージョン固有**：マクロはリージョン固有であり、組織のプライマリリージョン内でのみ使用できます。
* **時間句**：`TIMESERIES`、`PREDICT`、`BY`、`USING`、`SINCE`、`UNTIL`、および`COMPARE WITH`を含む時間に関連する句は、マクロをサポートしていません。
</Collapser>
</CollapserGroup>

## アクセスマクロ [#macros-access]

New Relicプラットフォームで、<DNT>**Administration &gt; NRQL Macros**</DNT>に移動します。このページから、マクロを表示、作成、編集、削除できます。

## マクロの作成 [#create-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="create-ui">UI</TabsBarItem> <TabsBarItem id="create-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="create-ui">
<DNT>**NRQL Macros**</DNT>ページから、一意の名前と式を指定してマクロを作成します。[命名](#macro-naming-rules)規則と[式](#macro-expression-rules)の規則に従ってください。名前の先頭に`$`文字を付けないでください。たとえば、`WHERE`句の条件を保存するには、`WHERE`キーワードを付けずに`appName = 'ProductionApp' AND environment = 'prod'`を入力します。

マクロを作成すると、<DNT>**NRQL Macros**</DNT>リストに表示されます。New Relic全体の任意のNRQLクエリで使用できます。
</TabsPageItem>

<TabsPageItem id="create-nerdgraph">
[NerdGraph API](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/)を使用して、プログラムでマクロを作成、更新、クエリすることもできます。マクロを作成または更新する前に、[命名規則](#macro-naming-rules)、[式規則](#macro-expression-rules)、および[制限事項](#macro-limitations)を確認してください。

始めるには、[NerdGraph APIエクスプローラー](https://one.newrelic.com/nerdgraph-graphiql)にアクセスしてください。NerdGraph APIエクスプローラーの使用についてサポートが必要な場合は、[NerdGraph APIエクスプローラーのチュートリアル](/docs/apis/nerdgraph/get-started/nerdgraph-explorer/)を参照してください。

`entityManagementCreateNrqlMacro`ミューテーションを使用します：

```graphql
mutation CreateMacro($name: String!, $expression: String!, $orgId: ID!) {
  entityManagementCreateNrqlMacro(
    nrqlMacroEntity: {
      expression: $expression
      name: $name
      scope: { type: ORGANIZATION, id: $orgId }
    }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

変数の例：

```json
{
  "name": "prod_filter",
  "expression": "(appName = 'ProductionApp' AND environment = 'prod')",
  "orgId": "your-organization-id"
}
```

組織IDを確認するには、[組織またはマクロIDの確認](#find-ids)を参照してください。
</TabsPageItem>
</TabsPages>
</Tabs>

## クエリでマクロを使用する [#use-macro]

NRQLクエリでマクロを使用するには、クエリビルダーで`$`に続けてマクロ名を入力します。たとえば、式が`appName = 'ProductionApp' AND environment = 'prod'`の`prod_filter`という名前のマクロがあるとします。次のようなクエリで使用できます：

```sql
SELECT count(*) FROM Transaction WHERE $prod_filter SINCE 1 hour ago
```

クエリが実行されると、New Relicはマクロをその式に置き換えます：

```sql
SELECT count(*) FROM Transaction WHERE appName = 'ProductionApp' AND environment = 'prod' SINCE 1 hour ago
```

<Callout variant="tip">
クエリ実行時に、特殊文字を含むマクロ名をバッククォートで囲んでください。例：`` $`my#Macro` ``。
</Callout>

<Callout variant="important">
マクロは実行前にインライン展開されるため、二項演算子の優先順位に影響を与えます。たとえば、`1 + 4` として定義され、`$five * 3` として使用される `five` という名前のマクロは、式が `1 + 4 * 3` になるため、`15` ではなく `13` と評価されます。これを回避するには、`(1 + 4)` のようにマクロを定義する際に式を括弧で囲むか、`($five) * 3` のようにマクロを使用する際にマクロを括弧で囲みます。どちらの方法でも、正しく `15` と評価されます。
</Callout>

次の例は、一般的なクエリの問題を解決するマクロを示しています：

<CollapserGroup>
<Collapser id="macro-example-simplify" title="例：クエリを簡素化する">
このような複数の条件を含むクエリは、読み取りや保守が困難になる場合があります：

```sql
SELECT * FROM Log WHERE entityGuid = '...' AND appId NOT IN (...) AND ...
```

`WHERE` の後の条件を `macro1` という名前のマクロとして保存すると、クエリは次のように簡略化されます：

```sql
SELECT * FROM Log WHERE $macro1
```
</Collapser>

<Collapser id="macro-example-single-edit" title="例：1か所から複数のダッシュボードウィジェットを更新する">
多くのウィジェットを持つDashboardsでは、繰り返されるクエリロジックを共有することがよくあります。たとえば、ダッシュボード内のほとんどのウィジェットで次を使用する場合があります：

```sql
SELECT count(*) FROM Transaction WHERE http.statusCode NOT IN (400, 404)
```

`WHERE`条件を`macro2`という名前のマクロとして保存すると、各ウィジェットのクエリは次のようになります：

```sql
SELECT count(*) FROM Transaction WHERE $macro2
```

すべてのウィジェットからテストアプリを除外するには、`macro2`の式を`http.statusCode NOT IN (400, 404)`から`http.statusCode NOT IN (400, 404) AND appId NOT IN (12345)`に1回更新してください。`$macro2`を使用するすべてのウィジェットに変更が反映されるため、各ウィジェットを個別に編集する必要はありません。
</Collapser>

<Collapser id="macro-example-alias" title="例：属性エイリアスの問題を解決する">
異なるエージェントからのデータが、同じ概念に対して常に同じ属性名を使用するとは限りません。たとえば、ホスト名はソースに応じて`host.name`、`hostName`、または`host_name`として取り込まれる場合があります。

次の式を使用して、`host_alias` という名前のマクロを保存します：

```sql
(host.name OR hostName OR host_name)
```

次に、クエリでそれを参照します：

```sql
FROM Log SELECT $host_alias
```

後で`host-name`などの別のエイリアスが追加された場合は、`host_alias`マクロを1回更新するだけで、それを使用するすべてのクエリに変更が反映されます。
</Collapser>
</CollapserGroup>

## マクロを管理する [#manage-macros]

### マクロを編集する [#edit-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="edit-ui">UI</TabsBarItem> <TabsBarItem id="edit-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="edit-ui">
<DNT>**NRQL Macros**</DNT>ページからマクロを選択し、[式のルール](#macro-expression-rules)に従って式を更新します。
</TabsPageItem>

<TabsPageItem id="edit-nerdgraph">
[NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/)を使用して、プログラムでマクロの式を更新することもできます。更新する前に、[式のルール](#macro-expression-rules)を確認してください。

`entityManagementUpdateNrqlMacro`ミューテーションを使用します。

```graphql
mutation UpdateMacro($expression: String!, $macroId: ID!) {
  entityManagementUpdateNrqlMacro(
    id: $macroId
    nrqlMacroEntity: { expression: $expression }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

変数の例：

```json
{
  "expression": "(appName = 'ProductionApp' AND environment = 'prod' AND region = 'us-east-1')",
  "macroId": "your-macro-id"
}
```

マクロのIDを確認するには、[組織またはマクロのIDを確認する](#find-ids)を参照してください。
</TabsPageItem>
</TabsPages>
</Tabs>

<Callout variant="important">
マクロを編集すると、そのマクロを使用しているすべてのクエリに更新されたバージョンが自動的に適用されます。既存のクエリに問題が発生しないよう、変更内容を確認してください。キャッシュにより、更新が反映されるまでに少し時間がかかる場合があります。作成後にマクロ名を更新することはできません。名前を変更する必要がある場合は、マクロを削除して新しいマクロを作成してください。
</Callout>

## 組織またはマクロIDの検索 [#find-ids]

<CollapserGroup>
<Collapser id="macro-find-org-id" title="組織IDを確認する">
```graphql
query MyOrganizationId {
  actor {
    organization {
      id
    }
  }
}
```
</Collapser>

<Collapser id="macro-find-macro-id" title="すべてのマクロとそのIDを一覧表示する">
```graphql
query GetMacros($cursor: String) {
  actor {
    entityManagement {
      entitySearch(query: "type = 'NRQL_MACRO'", cursor: $cursor) {
        entities {
          ... on EntityManagementNrqlMacroEntity {
            id
            name
            expression
          }
        }
        nextCursor
      }
    }
  }
}
```
</Collapser>
</CollapserGroup>
