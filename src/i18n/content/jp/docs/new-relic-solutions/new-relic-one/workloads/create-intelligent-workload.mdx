  この機能はまだ開発中ですが、ぜひお試しください。

  この機能は現在、弊社の[プレリリース ポリシー](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy)に従ってプレビュー プログラムの一部として提供されています。

従来の監視では、エンジニアリングチームに分離されたサービスレベル指標の追跡を強いることが多く、重要なユーザージャーニーが低下したときに、断片化された&quot;スイベルチェア&quot;デバッグエクスペリエンスを生み出します。インテリジェントワークロードは、Transaction 360の事後対応的なトラブルシューティングを、プロアクティブで自己更新型の監視ハブへと進化させます。ディストリビューティッド（分散）トレーシングを活用してアーキテクチャ全体を単一のビジネストランザクションに自動的にマッピングすることで、システムの変更に合わせてフルスタックの依存関係を継続的に追跡し、技術的なパフォーマンスをリアルタイムのビジネス成果(KPIs)と一致させます。

## 前提条件

Intelligent ワークロードを作成する前に、APMサービス全体で[ディストリビューティッド（分散）トレーシングを有効に](/docs/distributed-tracing/enable-configure/quick-start)してください。

## インテリジェントワークロードを作成する方法 [#create]

インテリジェントワークロードは3つの方法で作成でき、それぞれ数分で設定できます：

<CollapserGroup>
  <Collapser id="create-from-recommendations" title="推奨されるワークロードから作成する">
    New Relicは自動的にアプリケーションのトランザクションを分析し、作成すべき価値の高いインテリジェントワークロードを推奨します。これは、インテリジェントワークロードを使い始める最も早い方法です。インテリジェントワークロードを1つずつ作成することも、一括作成機能を使用して複数のワークロードを作成することもできます。

    ### おすすめを見る

    ワークロードページに移動したとき、New Relicが推奨するワークロードを見つけた場合は、上部にバナーが表示されます：

    <img title="Workloads page with Review recommendations banner" alt="Screenshot of the Workloads page showing the Review recommendations banner and button" src="/images/intelligent-workload-review-recs.webp" />

    おすすめモーダルを開くには、 <DNT>**Review recommendations**</DNT>をクリックします。

    ### 推奨事項を確認して作成する

    **Recommended Intelligent Workloads** \[推奨されるインテリジェント ワークロード]モーダルには、監視によってメリットが得られるトランザクションが表示されます。

    1. **カテゴリ別にフィルタリング**: タブを使用して切り替えます:

       * **Key Transactions** \[キースイッチ]: 高トラフィックまたはビジネスクリティカルなトランザクション
       * **Impacted Transactions** \[影響を受けたトランザクション]: パフォーマンスの問題またはエラーが発生したトランザクション

    2. **おすすめを並べ替える**: ドロップダウンを使用して並べ替えます。

       * 最も高いエラー率
       * 平均応答時間が最も長い
       * 最も時間がかかる

    3. **トランザクションの詳細を確認する**

    4. **ワークロードの作成**: 推奨事項の横にある<DNT>**Create**</DNT>をクリックします

    推奨事項から作成する場合、New Relic によってエンティティとトランザクションの選択が自動的に事前入力され、**Add details** \[詳細の追加]手順に直接移動して次の操作を実行できます。

    * ワークロードに名前を付ける
    * 説明を追加する（オプション）
    * 焦点となるサービスとトランザクションを確認する
    * セットアップを完了する

    <Callout variant="tip">
      推奨事項から作成する方法は、インテリジェント ワークロードを初めて使用するときや、専用の監視によって最もメリットが得られるトランザクションをすばやく特定したいときに最適です。
    </Callout>

    ### 推奨事項から一括作成 [#bulk-create]

    複数のインテリジェントワークロードを一度に作成する場合は、推奨事項モーダルから一括作成オプションを使用してください。New Relicは自動的に候補となるトランザクションを提示し、次の方法でキュレーションできるようにします：

    * **最も時間がかかる**：合計処理時間が最も長いトランザクション
    * **最も遅い平均応答時間**：平均レイテンシが最も悪いトランザクション
    * **最も高いエラー率**：最も頻繁に失敗するトランザクション

    <img title="Recommended Intelligent Workloads modal" alt="Screenshot of the Recommended Intelligent Workloads modal showing transaction recommendations with checkboxes" src="/images/intelligent-workload-bulk-create.webp" />
  </Collapser>

  <Collapser id="create-workloads-page" title="ワークロードページから作成">
    標準のセットアップウィザードを使用してワークロードを構築したい特定のアカウント、サービス、およびトランザクションがすでにわかっている場合に最適です。

    1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Workloads**</DNT>に移動します。
    2. <DNT>**Create a workload**</DNT>をクリックします。
    3. <DNT>**Intelligent Workload**</DNT>タイプを選択してください。
    4. ウィザードを開始するには、 <DNT>**Setup**</DNT>をクリックします。

    <img title="Select Intelligent Workload type" alt="Screenshot showing workload type selection with Standard and Intelligent options" src="/images/create_intelligent_workload.webp" />

    ### ステップ1: エンティティを選択する [#select-entity]

    重要なトランザクションが含まれるサービスまたはエンティティを選択します。

    1. 名前でエンティティを検索または参照します。
    2. 必要に応じて、エンティティ タイプ (APM サービス、ブラウザー アプリなど) でフィルターします。
    3. キートランザクションを処理するエンティティを選択します。
    4. <DNT>**Next**</DNT>をクリックします。

    <Callout variant="tip">
      トランザクション フローの中心となるエンティティを選択します。たとえば、チェックアウト プロセスを監視する場合は、周辺ログ サービスではなくチェックアウト サービスを選択します。
    </Callout>

    ### ステップ 2: あなたの場面を選択してください [#pick-transaction]

    監視したい特定の場面を選択してください:

    1. 選択したエンティティのトランザクションのリストを参照します。
    2. 検索を使用して、特定のトランザクション名を見つけます。
    3. ビジネスワークフローを表すトランザクションを選択します。
    4. <DNT>**Next**</DNT>をクリックします。

    ワークロードは、ディストリビューティッド（分散）トレーシングに基づいて、この行為に参加するすべてのエンティティを追跡します。

    <Callout variant="important">
      プラットフォームの制限により、インフラストラクチャエンティティは現在ヘルストラッキングから除外されています。APMサービス、ブラウザアプリ、およびその他のインストゥルメントされたエンティティのみが、ワークロードのヘルス計算に含まれます。
    </Callout>

    ### ステップ3: 詳細を追加する [#add-details]

    ワークロードに関する情報を提供します。

    1. **Name** \[名前]: 分かりやすい名前を入力します (例: 「Checkout」、「ユーザー認証フロー」)
    2. **Description** \[説明]\(オプション): このワークロード モニターの内容とそれがなぜ重要なのかについてのコンテキストを追加します。
    3. **Account** \[アカウント]: ワークロードを作成するアカウントを選択します。デフォルトでは、現在アクティブなアカウントが事前に選択されています。別のアカウントでワークロードを作成する場合は、ドロップダウンを使用して変更します。
    4. <DNT>**Next**</DNT>をクリックします。

    ### ステップ4：プレビューと最終決定 [#preview-finalize]

    ワークロードの設定を確認します。

    1. **Focal entity**が正しいことを確認します。
    2. **Focal transaction** \[フォーカストランザクション]が意図したワークフローと一致していることを確認します。
    3. ワークロードの**Name** \[名前]と**Description** \[説明]を確認します。
    4. <DNT>**Create Workload**</DNT>をクリックします。

    インテリジェントワークロードは、トランザクションに参加しているエンティティの追跡を直ちに開始します。
  </Collapser>

  <Collapser id="create-from-t360" title="Transaction 360から作成">
    インシデントを積極的に調査しており、現在のトランザクションビューを永続的でプロアクティブなワークロードとしてシームレスに保存したい場合に最適です。

    <img title="Save as Intelligent Workload from Transaction 360" alt="Screenshot of Transaction 360 showing golden metrics and the Save as workload button highlighted in the top right" src="/images/intelligent-workload-save-as-workload.webp" />

    1. <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; APM &amp; Services**</DNT>に移動します。
    2. 重要なトランザクションフローの一部であるサービスを選択します。
    3. 監視したい特定の場面に移動し、 <DNT>**Transaction 360**</DNT>をクリックします。
    4. <DNT>**Save as Intelligent Workload**</DNT>をクリックします。
    5. ワークロードのわかりやすい名前を入力します。
    6. <DNT>**Save**</DNT>をクリックします。

    <Callout variant="tip">
      個々のAPIコールではなく、完全なビジネス ワークフローを表す名前 (「チェックアウト」、「ユーザー認証」など) を選択してください。
    </Callout>
  </Collapser>
</CollapserGroup>

## インテリジェントワークロードのスコープを設定する [#exclude-filters]

デフォルトでは、インテリジェントワークロードは、中心となるトランザクションのディストリビューティッド（分散）トレーシングに参加するすべての上流および下流サービスを動的に含みます。トランザクションが、所有していないマイクロサービス、サードパーティAPI、またはワークロード全体の健全性に影響を与えたくない複雑なファンアウトパイプラインのブランチを呼び出す場合は、除外フィルタリングを使用してそれらの依存関係パスを取り除いてください。

**一般的なスコープ設定のユースケース：**

* **所有していない依存関係の削除**：チームが直接管理していない、アップストリームのAPIゲートウェイやセカンダリのダウンストリームサービス（外部の支払いゲートウェイやクーポンのマイクロサービスなど）を除外します。
* **パイプラインブランチの分離**：複雑なファンインおよびファンアウトアーキテクチャー（Kafkaメッセージパイプラインなど）では、並列の消費者キューや無関係なトピックを削減して、チームが所有する正確な実行ブランチを分離します。

**除外フィルターの仕組み：**

ワークロードグラフに除外フィルターを追加する際は、3つのパラメーターを設定します：

* **ターゲットエンティティ**：フィルターを適用する、依存関係マップ上の特定のサービスノードです。
* **方向**：選択したエンティティに入ってくる依存関係（**Upstream** \[アップストリーム]）と、そこから出ていく依存関係（**Downstream** \[ダウンストリーム]）のどちらをプルーニングするかを指定します。
* **ターゲットエンティティの可視性**：ターゲットエンティティ自体をすべての接続とともに除外する（ワークロードグラフから完全に削除する）か、ターゲットエンティティを表示したまま、さらに上流または下流の依存関係のみを除外するかどうか

除外フィルターは動的であるため、将来のトレースで除外されたブランチ上に現れる新しいマイクロサービスや接続は、ワークロードを手動で更新することなく自動的に除外されます。

## 次のステップ [#next-steps]

インテリジェントワークロードが作成されたら、コアビューとツールを探索して、重要なカスタマージャーニーの監視に慣れてください：

* **[統合されたエクスペリエンスによる調査](/docs/new-relic-solutions/new-relic-one/workloads/intelligent-workload-integrated-experiences)**：Errors Inbox、[パフォーマンスリスクインボックス](/docs/errors-inbox/performance-risks/introduction)、Transaction 360、依存関係マップなどのスコープされたサブビューを詳しく調べます — これらはワークロードコンテキストに直接組み込まれています。
* **[カスタムKPIの管理](/docs/new-relic-solutions/new-relic-one/workloads/intelligent-workload-kpis):** 技術的なパフォーマンス指標とともに、カスタムビジネスメトリクス（チェックアウト成功率など）を定義して追跡します。
