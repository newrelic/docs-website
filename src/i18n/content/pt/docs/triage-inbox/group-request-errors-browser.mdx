Chamadas AJAX e fetch malsucedidas, como uma integração de terceiros quebrada ou uma API de backend retornando um erro 500, frequentemente causam páginas quebradas e uma experiência do usuário confusa. A página <DNT>**Request errors**</DNT> agrupa esses requests com falha para que você possa encontrar as chamadas de API por trás de páginas com erro, ver com que frequência elas estão falhando e saber por onde começar a depuração.

O recurso de erros de solicitação baseia-se nos eventos [`AjaxRequest`](/attribute-dictionary/?event=AjaxRequest) que o seu agente do browser já coleta, portanto, não há nada para instalar ou ativar para começar a usá-lo.

## Ver a página de erros de solicitação [#request-errors-page]

Para visualizar a página de erros de solicitação, acesse <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Browser &gt; (select an app) &gt; Request errors**</DNT>.

## Fluxo de trabalho recomendado [#suggested-workflow]

Recomendamos a seguinte abordagem para investigar erros de requisição, para que você possa entender o erro, identificar os fatores contribuintes e iniciar a depuração:

1. **Veja as tendências gerais**: comece com os gráficos <DNT>**Error count**</DNT> e <DNT>**Errors by page**</DNT> para ver rapidamente se há picos, quedas ou padrões inesperados.
2. **Agrupe e filtre**: use as opções <DNT>**Group by**</DNT> e de filtro para se concentrar em domínios de solicitação, caminhos de solicitação, códigos de resposta ou intervalos de código específicos.
3. **Aprofunde-se em um único erro**: selecione uma linha na tabela de erros de requisição para visualizar os detalhes completos da requisição, incluindo o URL da requisição, o código de resposta, o corpo da resposta e muito mais.
4. **Revise o Session Replay e a trilha de evento**: a partir de um erro específico, revise a [trilha de evento](#event-trail) e, quando disponível, o [Session Replay](#session-replay) gravado durante essa ocorrência.
5. **Consulte e compartilhe os dados**: em qualquer gráfico, selecione o menu <DNT>**…**</DNT> e, em seguida, <DNT>**View query**</DNT> para explorar os dados `AjaxRequest` subjacentes no criador de consulta ou adicioná-los a um dashboard.
6. **Alterar a janela de tempo**: Selecione um novo período de tempo no dropdown seletor de horas.

## Solicitar detalhes do erro [#error-details]

Selecione uma linha na tabela de erros de solicitação para abrir os detalhes da solicitação como um painel empilhado, mostrando as informações completas da solicitação, os atributos da solicitação e o corpo da resposta para esse erro.

### Perfis [#error-profiles]

Na tabela de erros de request, selecione <DNT>**View profiles**</DNT> para ver quais atributos mais distinguem esse grupo de erros de request do seu outro tráfego. Use perfis para identificar rapidamente o que os requests afetados têm em comum.

### Trilha do evento [#event-trail]

Quando você seleciona um erro específico, a trilha de evento mostra as interações do navegador e as chamadas AJAX que levaram a ele. Isso ajuda você a entender o que o usuário estava fazendo quando o request falhou e se outras chamadas no mesmo período também foram afetadas.

### Session Replay [#session-replay]

Se um Session Replay foi gravado para a ocorrência que você está visualizando, você pode abri-lo a partir dos detalhes do erro para ver exatamente o que o usuário vivenciou quando a solicitação falhou.

## Consultar e visualizar dados de erro de solicitação [#insights]

O New Relic salva os dados de erro de solicitação como eventos `AjaxRequest`. Consulte o tipo de evento `AjaxRequest` no [criador de consulta](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder) para executar consultas NRQL e criar dashboard a partir dos seus dados de erro de solicitação.
