With Compute User Limits, you can set daily or monthly budgets for individual users in your organization and manage their access to New Relic resources based on compute consumption. When a user reaches their allocated budget, you can block their access to dashboards, query builder, and API calls until the end of the budget period or until you increase their budget.

Também simplifica o gerenciamento de orçamento em escala com um orçamento global de usuário que se aplica a todos os usuários, para que não seja necessário configurar um orçamento para cada usuário individualmente. Para usuários com necessidades específicas, é possível criar orçamentos de substituição personalizados.

Use Compute User Limits to do the following:

* Controlar custos de computação limitando o consumo por usuário
* Monitorar o consumo de computação no nível do usuário
* Manter a visibilidade dos padrões de uso em toda a organização
* Gerenciar orçamentos em uma grande organização

## Principais capacidades

Dois tipos de orçamento estão disponíveis:

* **Orçamento global de usuário**: definir um orçamento padrão que se aplica a todos os usuários na organização. Configurar como um dos seguintes:

  * **Porcentagem do orçamento da organização**: alocar uma porcentagem do orçamento compute no nível da organização (com base nos compromissos mínimos) para cada usuário
  * **Valor real de computação**: especificar um número exato de unidades de capacidade de computação (CCUs) para cada usuário

* **Orçamentos de substituição personalizados**: atribuir orçamentos específicos a usuários individuais que precisam de limites maiores ou menores que o orçamento global.

O rastreamento de orçamento se aplica apenas quando se configura um orçamento global ou orçamentos de substituição personalizados.

Se um orçamento global foi configurado, todos os usuários recebem automaticamente esse orçamento. Se apenas orçamentos de substituição personalizados foram criados sem um orçamento global, os usuários sem orçamentos personalizados têm acesso irrestrito.

## Como funcionam os limites de usuário

Os limites de usuário rastreiam o consumo de computação de cada usuário. Ao atribuir um orçamento a um usuário, toda a sua atividade de computação conta para esse orçamento. Quando um usuário tem CCU e CoreCCU, apenas o CCU conta para os limites do orçamento.

For example, if a user has a 1,000 CCU budget, all compute consumption attributed to their user ID or API key counts toward that limit.

Quando um usuário atinge seu orçamento alocado, as regras configuradas de bloqueio ou monitoramento entram em vigor.

### Budget frequency

When you create a budget, you choose whether it resets daily or monthly. The right choice depends on your users&apos; work patterns and how tightly you need to control costs.

The following table compares monthly and daily budgets:

| Comportamento        | Mensal                             | Diário                           |
| -------------------- | ---------------------------------- | -------------------------------- |
| **Reinicializações** | Start of each calendar month (UTC) | Start of each calendar day (UTC) |
| **Block lifts**      | Start of next calendar month (UTC) | Start of next calendar day (UTC) |

Choose a monthly budget if any of the following apply:

* Your users have variable day-to-day usage that averages out over a billing period — for example, developers who run intensive queries at the end of a sprint but have light usage otherwise
* You want the budget period to align with your billing cycle
* You want only one reset per month

Choose a daily budget if any of the following apply:

* You want to limit how much a runaway query or script can consume in a single day
* Your users have consistent day-to-day usage and you want a fixed daily limit
* You want a shorter recovery window: A user blocked under a daily budget regains access the next day, rather than waiting until the end of the month

<Callout variant="tip">
  Daily caps can block users on high-usage days even when their total usage would have stayed within a monthly budget. Review your users&apos; typical usage patterns before applying daily limits broadly.
</Callout>

### Notificações de orçamento

Recebe-se notificação de banner no aplicativo em cada limite a seguir:

* **50% do orçamento consumido**: banner informativo amarelo
* **75% do orçamento consumido**: banner de aviso amarelo
* **95% do orçamento consumido**: Banner crítico vermelho
* **100% do orçamento consumido**: banner informativo indicando que o usuário está acima do orçamento

You also receive email notifications at 75% and 100% of budget consumed.

These notifications keep you informed of your consumption status.

### Aplicação de orçamento

Como gerente da organização, é possível escolher o que acontece quando um usuário atinge 100% de seu orçamento alocado:

* **Bloquear o usuário**: o bloqueio impede que o usuário acesse o seguinte:

  * Acesso ao dashboard
  * Acesso ao criador de consulta
  * Acesso à API por meio da ID de usuário ou chave de API

  When blocked, users see a screen that says they&apos;ve used their budget for the period and that they can contact an organization manager with any questions.

* **Monitor only**: Only notify the user about their budget consumption without blocking access.

<Callout variant="tip">
  If you&apos;re rolling out budget limits for the first time, start with monitor only. This lets you observe actual usage patterns before enabling blocking, reducing the chance of unexpected access disruptions.
</Callout>

<Callout variant="important">
  For monthly budgets, blocks remain in effect until the end of the calendar month (UTC). For daily budgets, blocks remain in effect until the end of the calendar day (UTC). In both cases, you can restore access sooner by increasing the user&apos;s budget. Consumption data updates within a few hours (typically 2 to 4 hours), so blocking doesn&apos;t happen exactly at 100%. Users might exceed their budget slightly before the block takes effect.
</Callout>

## Antes de você começar

When you create any budget, you configure four settings. Reviewing these before you start helps you make the right choices in the setup wizard.

| Contexto              | Opções                                                | What to consider                                                                                                                 |
| --------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Budget type**       | Global or custom override                             | Start with a global budget as your baseline. Add custom overrides for users who need different limits.                           |
| **Allocation method** | Percentage of organization budget or actual CCU value | Use percentage if you want limits to scale with your organization&apos;s commitments. Use an actual value for a fixed CCU limit. |
| **Frequência**        | Monthly or daily                                      | See [Budget frequency](#budget-frequency) for guidance on choosing between them.                                                 |
| **Enforcement**       | Block or monitor only                                 | Start with monitor only to observe actual usage patterns before enabling blocking.                                               |

## Configurar um orçamento global de usuário

Se a organização abranger mais de uma organização do New Relic, é necessário fazer login em cada uma separadamente para criar e gerenciar limites de usuário para cada usuário.

<Steps>
  <Step>
    ### Acessar Orçamentos Compute

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; [user menu](/docs/accounts/accounts-billing/general-account-settings/intro-account-settings)**</DNT>.
    2. Selecione <DNT>**Administration &gt; Compute Budgets**</DNT>.
  </Step>

  <Step>
    ### Adicionar um orçamento global

    Basta clicar em <DNT>**Create a global user budget**</DNT> para criar um orçamento que se aplique a todo usuário na organização na qual se fez login.
  </Step>

  <Step>
    ### Configurar o orçamento

    1. Escolher como alocar orçamentos:

       * **Porcentagem do orçamento da organização**: alocar uma porcentagem do orçamento de computação no nível da organização (com base em seus compromissos mínimos) para cada usuário. Por exemplo, se a organização tiver 800.000 Core CCUs e for definido 1% por usuário, cada usuário receberá 8.000 Core CCUs. A porcentagem total de todo usuário não precisa ser igual a 100%. É possível definir o total abaixo de 100% (deixando parte do orçamento não alocada) ou acima de 100%. Definir o agregado acima de 100% é aceitável.
       * **Valor real**: especifique um número exato de CCUs para cada usuário.

    2. Enter the budget amount.

    3. Under <DNT>**Set the frequency**</DNT>, select how often the budget resets:

       * **Monthly**: Tracks usage across the calendar month and resets at the start of each month (UTC).
       * **Daily**: Tracks usage across each calendar day and resets at the start of each day (UTC).

    4. Clique em <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Revisar notificações de orçamento global

    Esta página confirma os limites de notificação que os usuários recebem. Nenhuma configuração é necessária. Clique em <DNT>**Next**</DNT> para continuar.
  </Step>

  <Step>
    ### Configurar o bloqueio de orçamento global

    1. Choose how to limit usage when users exceed their CCU budget. Limits start when the budget runs out and last through the end of the budget period (day or month) or until you change them. Select one of the following:

       * **Bloquear uso adicional de CCU**: os usuários não podem acessar dashboards, o criador de consulta ou chamadas de API quando atingem o limite de orçamento. Quando um usuário esgota o orçamento, o bloqueio se aplica a ações que consomem CCU, como executar consultas ou atualizar dashboards.
       * **Não limitar o uso**: os usuários recebem notificações, mas mantêm acesso total a todos os recursos. Isso não evita excedentes.

       You receive a notification when limits take effect.

    2. Clique em <DNT>**Finish**</DNT> para criar o orçamento global de usuário.
  </Step>
</Steps>

## Configurar orçamentos de substituição personalizados

Crie orçamentos de substituição personalizados para usuários que precisam de limites diferentes do orçamento global. Use essa abordagem ao integrar uma equipe ou aplicar um limite uniforme a um grupo sem configurar cada usuário individualmente.

<Steps>
  <Step>
    ### Adicionar um orçamento de usuário

    Na página <DNT>**User Limits**</DNT> , clique em <DNT>**+ Create a user budget**</DNT>.
  </Step>

  <Step>
    ### Selecionar usuários

    No menu dropdown, selecione um ou mais usuários para atribuir um orçamento de substituição personalizado. Ao selecionar vários usuários, o mesmo valor de orçamento se aplica a cada usuário individualmente. Por exemplo, ao definir 40.000 CCUs e selecionar cinco usuários, cada usuário recebe 40.000 CCUs, não uma parte compartilhada.
  </Step>

  <Step>
    ### Configurar o orçamento personalizado

    1. Definir uma porcentagem específica ou valor real.

    2. Under <DNT>**Set the frequency**</DNT>, select how often the budget resets:

       * **Monthly**: Tracks usage across the calendar month and resets at the start of each month (UTC).
       * **Daily**: Tracks usage across each calendar day and resets at the start of each day (UTC).

    3. Clique em <DNT>**Next**</DNT>.
  </Step>

  <Step>
    ### Revisar notificações de orçamento personalizado

    Revise os limites de notificação que se aplicam a este usuário. Clique em <DNT>**Next**</DNT> para continuar.
  </Step>

  <Step>
    ### Configurar o bloqueio de orçamento personalizado

    1. Escolha a preferência de bloqueio para este usuário específico, que pode diferir das configurações de orçamento global.

    2. Clique em <DNT>**Finish**</DNT> para criar o orçamento de substituição personalizado.
  </Step>
</Steps>

Após criá-los, os orçamentos de substituição personalizados aparecem na tabela de orçamentos como itens de linha separados. É possível atualizá-los individualmente ou usar a visualização de grupo para atualizar todos os usuários do grupo de uma só vez.

## Gerenciar limites de usuário

### Visualizar o consumo do orçamento

Organization managers see the global budget as a card at the top of the main <DNT>**User Limits**</DNT> page. Custom override budgets appear in a budget table below.

**Organization managers** can do the following:

* É possível visualizar o cartão de orçamento global e todos os orçamentos de substituição personalizados na tabela com todos os detalhes

* Access a three-dot menu (**⋯**) next to each budget. The menu includes the following options:

  * <DNT>**View**</DNT>: Ver informações detalhadas do orçamento, consumo e tendências
  * <DNT>**Edit**</DNT>: Modificar as configurações do orçamento
  * <DNT>**Delete**</DNT>: Remover o orçamento

**Read-only users** can do the following:

* See their own budget as a line item in the table, whether it&apos;s a custom override or global budget
* Access only the <DNT>**View**</DNT> option from the three-dot menu

Read-only users can&apos;t see other users&apos; budgets or use <DNT>**Edit**</DNT> or <DNT>**Delete**</DNT>.

### Visualização de detalhes do orçamento [#budget-details]

Ao visualizar um orçamento (disponível para todos os usuários para o próprio orçamento), é possível ver:

* Consumo atual do orçamento
* Porcentagem do orçamento usado
* Consumption trends for the period
* Status de bloqueio em 100%
* Status da notificação

### Ajustar orçamentos [#adjust-budgets]

Como gerente da organização, é possível modificar os orçamentos a qualquer momento:

* <DNT>**Edit existing budgets**</DNT>: Update budget amounts, frequency, or blocking preferences for a single user, or use the group view to update the budget for all users in a group at once
* <DNT>**Increase a user&apos;s budget**</DNT>: Restaurar o acesso para usuários bloqueados ou fornecer capacidade adicional
* <DNT>**Decrease budgets**</DNT>: Adjust budget amounts for the current and future budget periods
* <DNT>**Delete budgets**</DNT>: Delete both global and custom override budgets. When you delete a custom override budget, the user automatically falls back to the global user budget (if you&apos;ve configured one).

As alterações nos orçamentos entram em vigor em aproximadamente 15 minutos.

<Callout variant="important">
  Deleting a custom budget doesn&apos;t remove budget tracking. Budget tracking continues under the global budget (if you&apos;ve configured one).
</Callout>

### Lidar com usuários bloqueados

When a user is blocked due to budget consumption, they can do the following:

* See a message that says they&apos;ve used their budget for the period
* View their budget details to check consumption
* Entrar em contato para solicitar um aumento de orçamento

To restore a blocked user&apos;s access, choose one of the following options:

* Increase their budget. See [Adjust budgets](#adjust-budgets).
* Wait until the budget resets at the start of the next budget period. See [Budget frequency](#budget-frequency).

<Callout variant="tip">
  É recomendado publicar uma lista interna de gerentes da organização para que os usuários saibam quem contatar para aumentos de limite e garantir que pelo menos um esteja disponível para aprovar os aumentos rapidamente durante um incidente de serviço.
</Callout>

## Cenários comuns

**When do budgets reset?** It depends on the frequency you selected when setting up the budget:

* **Monthly**: Budgets reset at the start of each calendar month (UTC).
* **Daily**: Budgets reset at the start of each calendar day (UTC).

**O que acontece com as consultas em andamento quando um usuário atinge 100% de seu orçamento?** As consultas em execução são concluídas. O bloqueio apenas impede que novas consultas, carregamentos de dashboard e chamadas de API sejam iniciados.

**What happens to a user when I delete their custom override budget?** The user automatically falls back to the global user budget if you&apos;ve configured one. If no global budget exists, the user has unrestricted access.

**What happens to users who don&apos;t have a budget assigned?** Users without a budget assigned have unrestricted access to dashboards, query builder, and API calls.

**How quickly do budget changes take effect?** Budget changes take effect within approximately 15 minutes.
