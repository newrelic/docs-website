Ainda estamos trabalhando nesse recurso, mas adoraríamos que você experimentasse!

Atualmente, esse recurso é fornecido como parte de um programa de visualização de acordo com nossas [políticas de pré-lançamento](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

<DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitora o seu serviço após cada implantação que você configura para monitoramento. <DNT>Autopilot</DNT> verifica a integridade do serviço em pontos de verificação programados, comenta no pull request e relata os resultados em <DNT>Slack</DNT> se você o tiver conectado. Se detectar uma regressão, ele também abre uma issue no <DNT>GitHub</DNT> atribuída a <DNT>GitHub Copilot</DNT>, que pode propor uma correção como um pull request se a sua organização tiver <DNT>GitHub Copilot Enterprise</DNT>.

<Callout variant="important">
<DNT>New Relic Change Tracking for GitHub Copilot</DNT> requer um token <DNT>GitHub</DNT> com acesso de gravação, além do acesso de leitura que [Conectar o Autopilot ao GitHub](/docs/agentic-ai/autopilot/connect-to-github) descreve. Adicione as permissões de gravação ao token que você já conectou ou conecte um novo token que tenha todas elas.
</Callout>

Cada implantação configurada para monitoramento passa por estas etapas:

1. Você mescla o pull request e seu pipeline o implanta. A implantação envia um evento ao Monitoramento de Alterações que inclui o URL da tag de lançamento, o SHA do commit de merge e o atributo `watchpoint_monitoring`.
2. <DNT>Autopilot</DNT> valida o evento. Se for aprovado, <DNT>Autopilot</DNT> comenta no pull request mesclado e, se você conectou <DNT>Slack</DNT>, publica uma mensagem de &quot;monitoramento iniciado&quot;.
3. Em cada ponto de verificação, <DNT>Autopilot</DNT> compara as métricas do serviço após a implantação com as métricas antes dela. Ele relata um de três resultados (sem regressão, inconclusivo ou regressão detectada) como um comentário no pull request e, se você conectou <DNT>Slack</DNT>, como uma resposta na mesma thread. Os pontos de verificação são executados 10 minutos, 30 minutos, 1 hora, 2 horas, 24 horas e 72 horas após a implantação.

Quando um checkpoint detecta uma regressão, <DNT>Autopilot</DNT> faz três coisas:

* Publica uma resposta na thread <DNT>Slack</DNT> (se você conectou <DNT>Slack</DNT>) com as métricas relevantes e a evidência por trás da descoberta.
* Comenta no pull request com as métricas relevantes, o checkpoint que detectou a regressão e o motivo.
* Abre uma issue no <DNT>GitHub</DNT> que descreve o que regrediu, as evidências de suporte, onde procurar e os critérios de aceitação e, em seguida, atribui a issue a <DNT>GitHub Copilot</DNT>.

Se <DNT>Copilot</DNT> propuser uma correção, revise-a como você faria com qualquer outro pull request antes de mesclá-lo.

## Pré-requisitos [#prerequisites]

Antes de configurar <DNT>New Relic Change Tracking for GitHub Copilot</DNT>, confirme o seguinte:

* Você configurou <DNT>Autopilot</DNT>. Consulte [Configurar o Autopilot](/docs/agentic-ai/autopilot/setup).

* Você é um <DNT>**New Relic Organization Manager**</DNT> e optou por <DNT>**New Relic Change Tracking for GitHub Copilot**</DNT> em <DNT>**[one.newrelic.com &gt; Administration](https://one.newrelic.com/admin-portal) &gt; Preview &amp; Trials**</DNT>.

* Você tem uma conta <DNT>GitHub</DNT> e um token com acesso de gravação aos repositórios que você deseja monitorar.

* Suas implantações enviam eventos para o [Monitoramento de Alterações](/docs/change-tracking/overview) com a [mutação `changeTrackingCreateEvent` ](/docs/change-tracking/config/nerdgraph). <DNT>New Relic Change Tracking for GitHub Copilot</DNT> não oferece suporte ao endpoint legado.

* Cada evento inclui o seguinte:

  * A URL da tag de release no campo `changelog`.
  * O SHA do commit de mesclagem no campo `commit`.
  * O atributo personalizado `watchpoint_monitoring` definido como `"true"`, para cada implantação que você deseja monitorar.

* O serviço reporta ao New Relic e tem pelo menos 3 dias de histórico. Com menos dados, cada checkpoint retorna um resultado inconclusivo.

Opcionalmente, [conecte o Autopilot ao Slack](/docs/agentic-ai/autopilot/connect-to-slack) para receber notificações. Para que <DNT>Copilot</DNT> comece a trabalhar no problema automaticamente, sua organização precisa de <DNT>GitHub Copilot Enterprise</DNT>.

## Configurar o Monitoramento de Alterações do New Relic para o GitHub Copilot [#setup]

<Steps>
<Step>
### Criar um token do GitHub [#create-token]

Crie um token de acesso pessoal em <DNT>GitHub</DNT>. Um token de granulação fina é recomendado, mas um token clássico também funciona. Para obter instruções, consulte [Creating a fine-grained personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token) na documentação do <DNT>GitHub</DNT>. Certifique-se de que o token tenha o seguinte:

* Sua organização <DNT>GitHub</DNT> como proprietária do recurso.
* Acesso aos repositórios que você deseja que o <DNT>New Relic Change Tracking for GitHub Copilot</DNT> monitore.
* <DNT>**Read and write**</DNT> acesso a <DNT>**Pull requests**</DNT>, <DNT>**Issues**</DNT> e <DNT>**Contents**</DNT>.

Se você já conectou <DNT>GitHub</DNT> a <DNT>Autopilot</DNT> e já possui um token, pode adicionar essas permissões a esse token.

Se a sua organização exige o SSO SAML, autorize o token para o SSO. <DNT>GitHub</DNT> exibe o token apenas uma vez, portanto, ao gerá-lo, copie-o e cole-o no New Relic imediatamente.
</Step>

<Step>
### Conecte o GitHub e habilite o monitoramento [#enable]

Para abrir a configuração de <DNT>Autopilot</DNT>, clique em <DNT>**Ask AI**</DNT>, clique em **...** e, em seguida, clique em <DNT>**Configure**</DNT>.

<img title="Configure option in the New Relic AI panel" alt="A screenshot of the New Relic AI panel open on the right side of the page, with the three-dot menu expanded and the Configure option highlighted" src="/images/autopilot_screenshot-full_ai-panel-configure-menu.webp" />

Em <DNT>**External MCP connections**</DNT>, conecte <DNT>**GitHub**</DNT> (<DNT>**Public GitHub**</DNT> ou <DNT>**GitHub Enterprise Cloud**</DNT>) com seu token e nome da organização e, em seguida, ative <DNT>**Enable deployment monitoring**</DNT>. Para receber notificações, selecione também um canal <DNT>Slack</DNT> em <DNT>**Post alerts to**</DNT>. Esta opção aparece apenas depois que você conectar <DNT>Slack</DNT> a <DNT>Autopilot</DNT>.

Clique em <DNT>**Update agent**</DNT> para salvar suas alterações.
</Step>

<Step>
### Confirme que o monitoramento foi iniciado [#verify]

Implantar uma alteração com o atributo `watchpoint_monitoring` definido como `"true"`.

<CollapserGroup>
<Collapser id="example-event" title="Exemplo de evento de implantação">
```graphql
mutation {
  changeTrackingCreateEvent(
    changeTrackingEvent: {
      categoryAndTypeData: {
        kind: { category: "deployment", type: "basic" }
        categoryFields: {
          deployment: {
            version: "RELEASE_VERSION"
            commit: "MERGE_COMMIT"
            changelog: "RELEASE_TAG_URL"
          }
        }
      }
      customAttributes: { watchpoint_monitoring: "true" }
      entitySearch: { query: "id = 'ENTITY_GUID'" }
    }
  ) {
    changeTrackingEvent {
      changeTrackingId
    }
    messages
  }
}
```
</Collapser>
</CollapserGroup>

Após <DNT>Autopilot</DNT> validar o evento de implantação, você verá:

* Um comentário de <DNT>Autopilot</DNT> no pull request mesclado.
* Se você conectou <DNT>Slack</DNT>, uma mensagem de &quot;monitoramento iniciado&quot; no canal que você selecionou. Os resultados de checkpoints posteriores aparecem como respostas nesse tópico.

Se nenhum aparecer, verifique se o evento de implantação atende aos [pré-requisitos](#prerequisites).
</Step>
</Steps>
