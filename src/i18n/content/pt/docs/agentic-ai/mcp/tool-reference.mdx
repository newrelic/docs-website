O servidor MCP da New Relic fornece ferramentas especializadas que permitem que o agente de IA acesse e analise seus dados de observabilidade. Este guia de referência organiza todas as ferramentas disponíveis por categoria.

## Como usar as ferramentas MCP [#how-to-use]

As ferramentas MCP são invocadas por meio de consulta em linguagem natural no seu ambiente de desenvolvimento de IA. Você não precisa memorizar os nomes exatos das ferramentas ou os parâmetros. Basta descrever o que você deseja saber sobre seus dados do New Relic.

**Exemplo de consulta:**

* &quot;Quais entidades estão na minha conta?&quot;
* &quot;Mostrar alertas recentes para meu aplicativo web&quot;
* &quot;Quais foram os principais erros da última hora?&quot;
* &quot;Execute uma consulta NRQL para analisar o desempenho&quot;

O agente de IA na sua ferramenta de desenvolvimento selecionará automaticamente as ferramentas MCP apropriadas e formatará os resultados para você.

## Ferramentas de filtro com `include-tags` [#filter-tools]

Algumas ferramentas aparecem em várias categorias (por exemplo, `analyze_deployment_impact` é relevante tanto para `incident-response` quanto para `advanced-analysis`) porque são tags com várias tags relevantes.

Você pode filtrar dinamicamente as ferramentas que seu cliente MCP suportado recebe enviando o cabeçalho `include-tags` `HTTP` com suas requests. Isso permite que você solicite apenas subconjuntos específicos de ferramentas, o que é útil para reduzir o corpus de ferramentas e ajudar a melhorar a eficiência e a precisão de qualquer modelo de IA que esteja sendo usado para a consulta.

As tags disponíveis que você pode usar para filtragem correspondem diretamente aos cabeçalhos de categoria nesta referência: `discovery`, `data-access`, `alerting`, `incident-response`, `performance-analytics`, `advanced-analysis`, `gap-analysis`, bem como `monitoring-analysis`.

### Exemplo de implementação [#example]

```json
"servers": {
    "new-relic-mcp-server": {
        "url": "https://mcp.newrelic.com/mcp/",
        "type": "http",
        "headers": {
            "include-tags": "discovery,alerting"
        }
    }
}
```

Neste exemplo, o agente de IA só receberá ferramentas categorizadas como descoberta (por exemplo, `get_entity`) e alerta (por exemplo, `list_alert_policies`), garantindo que o modelo se concentre apenas nas funções mais relevantes para a sua tarefa atual.

<Callout variant="important">
**Segurança e acesso:** quando seu agente de IA invoca qualquer ferramenta listada aqui (por exemplo, `get_entity`, `analyze_deployment_impact`, `execute_nrql_query`), a ação que ele executa é estritamente governada pelas permissões concedidas ao perfil OAuth do usuário do New Relic (chave de API para a CLI do Antigravity) que foi configurado durante a instalação. A ferramenta só pode acessar os dados, entidades e contas aos quais sua conta de usuário correspondente recebeu acesso por meio do Controle de Acesso Baseado em Função (RBAC) do New Relic. Se o seu perfil OAuth ou chave de API não tiver permissões para uma ação específica (por exemplo, visualizar alertas ou executar NRQL), a chamada da ferramenta falhará com um erro de permissão.
</Callout>

<Callout variant="important">
Algumas ferramentas exigem autenticação OAuth e não estão disponíveis com uma chave de API. Consulte a seção [Ferramentas apenas com OAuth](#oauth-only-tools) para obter detalhes.
</Callout>

<Callout variant="tip">
**Limites de taxa:** o servidor MCP permite até 2.000 chamadas de ferramenta por hora por usuário. Esses limites podem variar. Se o seu caso de uso exigir um limite maior, entre em contato com o [suporte da New Relic](https://support.newrelic.com/s/).
</Callout>

<Callout variant="tip">
**Faturamento:** a maioria das ferramentas MCP é contabilizada como [unidades de computação Core (CCUs)](/docs/licenses/license-information/product-definitions/new-relic-one-pricing-definitions/#compute-capacity-unit) na sua alocação de computação Core existente. Quatro ferramentas de análise com tecnologia de IA (`natural_language_to_nrql_query`, `generate_alert_insights_report`, `generate_user_impact_report`, `analyze_deployment_impact`) são contabilizadas como [unidades de capacidade de computação Advanced (aCCUs)](/docs/licenses/license-information/product-definitions/new-relic-one-pricing-definitions/#compute-capacity-unit) e exigem o complemento de computação Advanced.
</Callout>

## entidade e gestão de contas (tag: descoberta) [#entity-account]

* `convert_time_period_to_epoch_ms`Converter um período de tempo (por exemplo, &quot;últimos 30 minutos&quot;) em milissegundos da época.
* `get_dashboard`Obter detalhes sobre um dashboard específico.
* `get_entity`Recuperar entidade New Relic por GUID ou pesquisar por padrão de nome.
* `list_related_entities`: Lista de entidades a 1 salto de distância (relacionadas) de uma determinada entidade `GUID`.
* `list_available_new_relic_accounts`: Listar todas as contas `IDs` disponíveis para o usuário.
* `list_dashboards`Listar todos os painéis de controle de uma conta New Relic.
* `search_entity_with_tag`: Pesquise por entidade usando uma chave e um valor tag específicos.
* `list_metric_names`: descubra todos os nomes de métricas disponíveis (dimensionais e de timeslice legado) reportados por uma entidade ou conta.
* `analyze_kafka_related_entities`: mapeie uma entidade do Kafka (um serviço produtor ou consumidor, tópico, broker, cluster ou host) para seu cluster, brokers, tópicos, serviços produtores e consumidores e hosts de broker.

## Acesso a dados (tag: acesso-a-dados) [#data-access]

* `execute_nrql_query`Executar uma consulta NRQL no NRDB.
* `natural_language_to_nrql_query`Executa uma consulta convertendo uma solicitação em linguagem natural em uma consulta NRQL, executando-a e retornando os resultados.

## Alertas e monitoramento (tag: alertas) [#alerts]

* `list_alert_conditions`: Lista detalhes da condição do alerta para uma política de alertas específica.
* `search_incident`: Listar todos os eventos de alerta (eventos de abertura e fechamento) com filtragem flexível.
* `list_alert_policies`Listar as políticas de alertas para a conta especificada, com opção de filtrar por nome da política.
* `list_recent_issues`Lista todos os problemas em aberto no New Relic para a conta especificada.
* `list_synthetic_monitors`Liste todos os monitores Sintético (testes automatizados que verificam a disponibilidade e o desempenho dos seus serviços).
* `list_synthetic_monitor_results`: retorna linhas individuais de execução de verificações sintéticas (tempos, erros, locais) para um monitor em uma janela de tempo.
* `get_synthetic_check_statistics`: agregar taxas de sucesso de verificações sintéticas, contagens de falhas e percentis de duração em monitores ou locais.

## Resposta a eventos de alerta (tag: incident-response) [#alertevents]

* `analyze_deployment_impact`: Analisar o impacto no desempenho de uma implantação em uma entidade específica.
* `generate_alert_insights_report`Gere um relatório de análise de inteligência de alertas para um problema específico.
* `generate_user_impact_report`Gere um relatório de análise de impacto para o usuário final referente a um problema específico.
* `list_entity_error_groups`: Obter grupos de erros para uma entidade específica na Errors Inbox dentro de um período de tempo.
* `list_change_events`: Liste um histórico de eventos de mudança do New Relic para o aplicativo identificado por sua entidade `GUID`.
* `get_error_statistics`: computar contagens agregadas de erros, timestamps da primeira/última ocorrência e tendências opcionais de séries temporais a partir de eventos `TransactionError`, com filtragem e facetamento flexíveis por classe de erro, mensagem, aplicativo, status de `HTTP` e muito mais.
* `search_errors`: retornar eventos de erro brutos correspondentes a filtros como mensagem, classe, status `HTTP` ou trace `ID`.

## análise de desempenho (tag: análise de desempenho) [#performance]

* `analyze_entity_logs`Analisar o log do aplicativo para identificar padrões de erro, comportamentos anômalos e problemas recorrentes.
* `analyze_golden_metrics`: Analisar métricas clássicas (indicadores-chave de saúde: taxas de transferência, tempo de resposta, taxas de erros e saturação).
* `analyze_threads`Analisar dados métricos de threads para uma determinada entidade, incluindo estado da thread, uso da CPU e consumo de memória.
* `analyze_transactions`: analise as transações de uma entidade específica dentro de uma janela de tempo, identificando transações lentas e propensas a erros, incluindo métricas de latência P95 e P99 (os limites de tempo de resposta para os 5% e 1% de requests mais lentos).
* `list_garbage_collection_metrics`: Listar coleta de lixo e memória métrica para uma determinada conta e entidade.
* `list_recent_logs`: Listar logs recentes do New Relic para a conta e entidade especificadas `GUID`.
* `list_entity_performance_risk_groups`: buscar grupos de riscos de desempenho para uma entidade específica da Caixa de entrada de riscos de desempenho dentro de uma janela de tempo.
* `get_metric_statistics`: Buscar valores de métrica agregada (média, soma, percentis, taxa) para uma determinada métrica dimensional ou de fatia de tempo.
* `get_log_statistics`: retorna contagens agregadas de logs, detalhamentos por nível e atributo e tendências ao longo de uma janela de tempo.
* `get_distributed_trace_details`: retorna atributos completos de span, anomalias e links de span para uma entidade específica ou span individual dentro de um trace.
* `analyze_kafka_health`: avalie a integridade de um cluster, broker, tópico ou aplicativo consumidor do Kafka verificando o atraso do consumidor, as partições sub-replicadas e offline e o estado do broker e do controlador. Funciona com a integração no host da New Relic, OpenTelemetry, Amazon MSK e Confluent Cloud, e relata quais sinais não puderam ser medidos.
* `analyze_kafka_client_metrics`: analise as métricas do cliente Kafka de um aplicativo produtor ou consumidor, como latência de solicitação e busca, tempo de espera de I/O, taxa de registros consumidos e tempo de poll.

## Análise avançada (tag: análise-avançada) [#advanced-analysis]

* `analyze_deployment_impact`: Analisar o impacto no desempenho de uma implantação em uma entidade específica.
* `generate_alert_insights_report`Gere um relatório de análise de inteligência de alertas para um problema específico.
* `generate_user_impact_report`Gere um relatório de análise de impacto para o usuário final referente a um problema específico.

## Análise de lacunas (tags: gap-analysis e monitoring-analysis) [#gap-analysis]

`analyze_github_newrelic_gaps`: verifique os arquivos do seu projeto em busca de instrumentação do New Relic ausente. Ele gera relatórios sobre quatro áreas: o arquivo de configuração do New Relic, o agente APM, o agente do browser e o Monitoramento de Alterações. Para usá-lo, instale o New Relic GitHub App e ative a análise de lacunas durante a configuração. Para obter detalhes, consulte [Encontrar lacunas de instrumentação](#instrumentation-gaps).

### Encontre lacunas de instrumentação [#instrumentation-gaps]

`analyze_github_newrelic_gaps` lê arquivos do seu projeto e relata onde o monitoramento do New Relic pode estar ausente. Seu cliente MCP lê os arquivos e os envia para a ferramenta quando você pergunta sobre lacunas de monitoramento.

A ferramenta fornece relatórios sobre quatro áreas:

* **Arquivo de configuração do New Relic:** se existe um arquivo de configuração que inclui um [nome da entidade](/docs/new-relic-solutions/new-relic-one/core-concepts/what-entity-new-relic/#reserved-attributes) na raiz do projeto. O nome da entidade no arquivo de configuração deve corresponder exatamente ao nome da entidade no New Relic que reporta dados para esse repositório.
* **Agente APM:** se o serviço reporta dados ao New Relic APM.
* **Agente do browser:** se o trecho do agente do browser está no seu HTML ou em seus templates.
* **Monitoramento de Alterações:** se a [GitHub Action de Monitoramento de Alterações](https://github.com/newrelic/deployment-marker-action) está nos seus fluxos de trabalho de CI/CD.

#### Pré-requisitos [#gap-prerequisites]

Antes de invocar a ferramenta, você precisa:

* O New Relic GitHub App, instalado a partir do [GitHub Marketplace](https://github.com/marketplace/new-relic-observability), com a análise de lacunas ativada durante a configuração
* Um [servidor MCP da New Relic](/docs/agentic-ai/mcp/setup) configurado que usa autenticação OAuth, porque a ferramenta não está disponível com uma chave de API
* Um arquivo de configuração do New Relic na raiz do projeto que inclui o nome da sua entidade

Em alguns casos, a ferramenta verifica a inscrição usando a chave de API do New Relic que você configurou. Se essas credenciais tiverem as permissões para visualizar o repositório de destino, a ferramenta conduzirá a análise. Essa verificação de permissão é executada em alguns casos antes que a ferramenta processe qualquer arquivo.

#### Executar a ferramenta [#gap-run]

Pergunte ao seu cliente MCP sobre lacunas de monitoramento, por exemplo:

* “Falta alguma instrumentação da New Relic neste projeto?”
* &quot;Audite esta base de código em busca de lacunas de observabilidade e sugira o que configurar.&quot;

O seu cliente lê os arquivos `.github/workflows/*.yml`, `package.json`, `pyproject.toml` e os arquivos de configuração do New Relic, e os envia com o nome do repositório. Os arquivos devem totalizar 5 MB ou menos. A ferramenta os lê na memória e retorna a resposta ao seu cliente MCP. O New Relic não armazena nem registra as respostas da ferramenta.

#### Revise os resultados [#gap-results]

A resposta inclui:

* **Lacunas:** para cada lacuna, o tipo (`apm`, `browser`, `change_tracking` ou `nr_config`), o estado e o motivo.
* **Resumo:** o número de lacunas no estado `Not Implemented` ou `Implemented & Broken`.
* **Recomendações:** comandos `gh issue create` sugeridos e uma dica para atribuir problemas ao GitHub Copilot.
* **Metadados:** o nome do repositório, o GUID da entidade vinculada, a linguagem, a versão do agente e o tempo de análise.

Para agir sobre os resultados, execute os comandos sugeridos para criar uma issue no GitHub por lacuna. Se o GitHub Copilot Enterprise estiver habilitado, você pode atribuir cada issue ao Copilot para gerar um PR de correção. Revise o PR antes de fazer o merge e, em seguida, execute a ferramenta novamente para confirmar que a lacuna de monitoramento está fechada.

#### Limitações [#gap-limitations]

A ferramenta tem estas limitações:

* Oferece suporte apenas a repositórios com um único serviço, não a monorepos com vários serviços.
* Ao usar o Autopilot, há suporte apenas para repositórios no GitHub.com.
* Detecta APM apenas para Python, não para .NET, Node.js, PHP, Ruby, Java ou Go.
* Verifica apenas a GitHub Action do Monitoramento de Alterações. Se você enviar marcadores de implantação de outra forma, o Monitoramento de Alterações será exibido como não detectado. Adicione o rótulo `dismissed` ao problema resultante para evitar que ele apareça novamente.
* Não analisa Terraform, Helm, manifestos do Kubernetes ou SDKs móveis.
* Os resultados variam de acordo com o modelo de IA e os harnesses. Modelos e harnesses mais capazes tendem a encontrar mais lacunas e fazer recomendações melhores.
* O nome da entidade no arquivo de configuração deve corresponder à entidade no New Relic para o serviço (seja navegador ou aplicativo) que ela representa.

## Habilidades [#skills]

Skills são fluxos de trabalho pré-criados que combinam várias ferramentas MCP para ajudar a investigar e resolver cenários comuns de observabilidade. As skills estão hospedadas no [repositório do hub de skills da New Relic](https://github.com/newrelic/nr-skills-hub).

Os clientes podem baixar essas habilidades e configurá-las de acordo com seu agente de IA específico.

Habilidades disponíveis:

| Habilidade              | Descrição                                                                       |
| ----------------------- | ------------------------------------------------------------------------------- |
| Descobrir ID do trace   | Localiza um ID de trace relevante para uma determinada solicitação ou incidente |
| apm-error-investigation | Orienta a investigação de grupos de erros do APM                                |
| NL2NRQL                 | Converte perguntas em linguagem natural em consultas NRQL executáveis           |

## Ferramentas somente OAuth [#oauth-only-tools]

As ferramentas a seguir exigem autenticação OAuth e não estão disponíveis ao usar uma chave de API.

**Ferramentas de análise com tecnologia de IA:** essas ferramentas são medidas como [Unidades Avançadas de Capacidade de Computação (aCCUs)](/docs/licenses/license-information/product-definitions/new-relic-one-pricing-definitions/#compute-capacity-unit).

* `natural_language_to_nrql_query`
* `generate_alert_insights_report`
* `generate_user_impact_report`
* `analyze_deployment_impact`

**Ferramenta de análise de lacunas:** `analyze_github_newrelic_gaps`. Para obter detalhes, consulte [Encontrar lacunas de instrumentação](#instrumentation-gaps).

**Ferramentas de pré-visualização:** veja [Ferramentas de pré-visualização](#preview-tools). Estes também exigem OAuth.

## Ferramentas de pré-visualização [#preview-tools]

As seguintes ferramentas estão disponíveis no GA como recursos de pré-visualização. Elas são somente leitura e fornecidas para avaliação. Os preços serão determinados após o GA.

* `search_traces`: pesquisar os traces de uma entidade específica dentro de uma janela de tempo, classificados por duração, contagem de erros ou tempo de backend.
* `analyze_trace_anomaly`: analise os traces de uma entidade específica para identificar a transação ou classe de erro responsável por traces lentos, com falha ou de alto volume.
* `analyze_service_dependencies`: analisa as dependências de serviço de uma entidade específica, mapeando as conexões upstream e downstream e sinalizando quais não estão íntegras.
