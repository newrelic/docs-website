Antes de criar uma macro, verifique as [permissões de macro](/docs/nrql/nrql-macros/nrql-macros-overview/#macro-permissions) e as regras de nomenclatura e expressão abaixo. Uma macro que não segue essas regras falha na validação quando você tenta salvá-la.

## Regras e limitações de macros [#macro-rules]

<Callout variant="important">
As macros são visíveis para todos os usuários na sua organização. Não devem ser incluídas informações confidenciais ou específicas da conta ao criar ou atualizar uma macro.
</Callout>

<CollapserGroup>
<Collapser id="macro-naming-rules" title="Regras de nomenclatura">
Os nomes de macros devem seguir estas regras:

* Deve ser único na organização
* Não deve ser um número inteiro não negativo, como `3`
* Não deve conter o caractere `.`
* Deve ter 500 caracteres ou menos
* Não deve começar com o caractere `$`
* Não deve ser delimitada por crases no momento da criação.
* Se o nome de uma macro contiver caracteres especiais, ele deve ser colocado entre crases. Por exemplo `` $`my#Macro` ``.
</Collapser>

<Collapser id="macro-expression-rules" title="Regras de expressão">
As expressões de macro devem seguir estas regras:

* Deve ser uma expressão NRQL válida ou uma lista de expressões
* Deve ter 3.000 caracteres ou menos
* Deve ser uma expressão, não uma cláusula. Por exemplo, `count(*)` é válido, mas `SELECT count(*)` não é válido.
* Deve ser uma subconsulta entre parênteses, não uma consulta independente. Por exemplo, `(FROM Transaction SELECT uniques(userId))` é válido, mas `FROM Transaction SELECT uniques(userId)` não é válido.
* Deve retornar atributos específicos, não uma lista de atributos contendo `*`

Exemplos de expressões válidas:

* `count(*)`
* `(1, 2, 3)`
* `(FROM Transaction SELECT uniques(userId))`
</Collapser>

<Collapser id="macro-limitations" title="Limitações">
As macros NRQL têm as seguintes limitações:

* **Alertas**: as macros não são suportadas em condições do alerta.
* **Autocompletar**: o criador de consulta não sugere macros nem usa expressões de macro para refinar as sugestões.
* **Variáveis de template**: você não pode usar variáveis de template dentro de macros.
* **Macros aninhadas**: as macros não podem ser aninhadas. A expressão de uma macro não pode conter uma referência a outra macro.
* **Específico da região**: as macros são específicas da região e só podem ser usadas na região principal da sua organização.
* **Cláusulas de tempo**: cláusulas relacionadas a tempo, incluindo `TIMESERIES`, `PREDICT`, `BY`, `USING`, `SINCE`, `UNTIL` e `COMPARE WITH`, não suportam macros.
</Collapser>
</CollapserGroup>

## Macros de acesso [#macros-access]

Na plataforma New Relic, vá para <DNT>**Administration &gt; NRQL Macros**</DNT>. A partir desta página, você pode visualizar, criar, editar e excluir macros.

## Criar uma macro [#create-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="create-ui">Interface</TabsBarItem> <TabsBarItem id="create-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="create-ui">
A partir da página <DNT>**NRQL Macros**</DNT>, crie uma macro fornecendo um nome exclusivo e uma expressão. Siga as regras de [nomenclatura](#macro-naming-rules) e de [expressão](#macro-expression-rules). Não adicione o caractere `$` como prefixo do nome. Por exemplo, para salvar uma condição de cláusula `WHERE`, insira `appName = 'ProductionApp' AND environment = 'prod'` sem a palavra-chave `WHERE`.

Depois de criar uma macro, ela aparece na lista <DNT>**NRQL Macros**</DNT>. Você pode usá-la em qualquer consulta NRQL em todo o New Relic.
</TabsPageItem>

<TabsPageItem id="create-nerdgraph">
Você também pode criar, atualizar e consultar macros de forma programática usando a [API NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/). Antes de criar ou atualizar macros, revise as [regras de nomenclatura](#macro-naming-rules), as [regras de expressão](#macro-expression-rules) e as [limitações](#macro-limitations).

Para começar, acesse o [NerdGraph API explorer](https://one.newrelic.com/nerdgraph-graphiql). Se você precisar de ajuda para usar o NerdGraph API explorer, consulte o [tutorial do NerdGraph API explorer](/docs/apis/nerdgraph/get-started/nerdgraph-explorer/).

Use a mutação `entityManagementCreateNrqlMacro`:

```graphql
mutation CreateMacro($name: String!, $expression: String!, $orgId: ID!) {
  entityManagementCreateNrqlMacro(
    nrqlMacroEntity: {
      expression: $expression
      name: $name
      scope: { type: ORGANIZATION, id: $orgId }
    }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

Variáveis de exemplo:

```json
{
  "name": "prod_filter",
  "expression": "(appName = 'ProductionApp' AND environment = 'prod')",
  "orgId": "your-organization-id"
}
```

Para encontrar o ID da sua organização, consulte [Encontrar o ID da sua organização ou macro](#find-ids).
</TabsPageItem>
</TabsPages>
</Tabs>

## Usar uma macro em uma consulta [#use-macro]

Para usar uma macro em suas consultas NRQL, digite `$` seguido pelo nome da macro no criador de consulta. Por exemplo, suponha que você tenha uma macro chamada `prod_filter` com a expressão `appName = 'ProductionApp' AND environment = 'prod'`. Você pode usá-la em uma consulta como esta:

```sql
SELECT count(*) FROM Transaction WHERE $prod_filter SINCE 1 hour ago
```

Quando a consulta é executada, a New Relic substitui a macro por sua expressão:

```sql
SELECT count(*) FROM Transaction WHERE appName = 'ProductionApp' AND environment = 'prod' SINCE 1 hour ago
```

<Callout variant="tip">
Coloque os nomes de macros que contêm caracteres especiais entre crases no momento da consulta. Por exemplo: `` $`my#Macro` ``.
</Callout>

<Callout variant="important">
As macros são embutidas antes da execução, o que afeta a precedência de operadores binários. Por exemplo, uma macro chamada `five` definida como `1 + 4` e usada como `$five * 3` é avaliada como `13`, não `15`, porque a expressão se torna `1 + 4 * 3`. Para evitar isso, coloque a expressão entre parênteses ao definir a macro, como em `(1 + 4)`, ou coloque a macro entre parênteses ao usá-la, como em `($five) * 3`. Qualquer uma das abordagens é avaliada corretamente como `15`.
</Callout>

Os exemplos a seguir mostram macros resolvendo problemas comuns de consulta:

<CollapserGroup>
<Collapser id="macro-example-simplify" title="Exemplo: simplificar uma consulta">
Uma consulta com várias condições, como esta, pode ser difícil de ler e manter:

```sql
SELECT * FROM Log WHERE entityGuid = '...' AND appId NOT IN (...) AND ...
```

Salve as condições após `WHERE` como uma macro chamada `macro1`, e a consulta se simplifica para:

```sql
SELECT * FROM Log WHERE $macro1
```
</Collapser>

<Collapser id="macro-example-single-edit" title="Exemplo: atualizar vários widget de dashboard de um único lugar">
Dashboards com muitos widgets frequentemente compartilham lógica de consulta repetida. Por exemplo, a maioria dos widgets em um dashboard pode usar:

```sql
SELECT count(*) FROM Transaction WHERE http.statusCode NOT IN (400, 404)
```

Se você salvar a condição `WHERE` como uma macro chamada `macro2`, a consulta de cada widget ficará assim:

```sql
SELECT count(*) FROM Transaction WHERE $macro2
```

Para excluir um aplicativo de teste de cada widget, atualize a expressão `macro2` uma vez, de `http.statusCode NOT IN (400, 404)` para `http.statusCode NOT IN (400, 404) AND appId NOT IN (12345)`. Cada widget que usa `$macro2` reflete a alteração, e você não precisa editar cada widget individualmente.
</Collapser>

<Collapser id="macro-example-alias" title="Exemplo: resolva o problema de alias de atributo">
Os dados de diferentes agentes nem sempre usam o mesmo nome de atributo para o mesmo conceito. Um nome de host, por exemplo, pode ser ingerido como `host.name`, `hostName` ou `host_name`, dependendo da origem.

Salve uma macro chamada `host_alias` com a expressão:

```sql
(host.name OR hostName OR host_name)
```

Em seguida, referencie-a em suas consultas:

```sql
FROM Log SELECT $host_alias
```

Se outro alias, como `host-name`, surgir mais tarde, atualize a macro `host_alias` uma vez e cada consulta que a utilizar adotará a alteração.
</Collapser>
</CollapserGroup>

## Gerenciar macros [#manage-macros]

### Editar uma macro [#edit-macro]

<Tabs>
<TabsBar>
<TabsBarItem id="edit-ui">Interface</TabsBarItem> <TabsBarItem id="edit-nerdgraph">NerdGraph</TabsBarItem>
</TabsBar>

<TabsPages>
<TabsPageItem id="edit-ui">
Na página <DNT>**NRQL Macros**</DNT>, selecione a macro e atualize sua expressão, seguindo as [regras de expressão](#macro-expression-rules).
</TabsPageItem>

<TabsPageItem id="edit-nerdgraph">
Você também pode atualizar a expressão de uma macro de forma programática usando o [NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/). Revise as [regras de expressão](#macro-expression-rules) antes de atualizá-la.

Use a mutação `entityManagementUpdateNrqlMacro` .

```graphql
mutation UpdateMacro($expression: String!, $macroId: ID!) {
  entityManagementUpdateNrqlMacro(
    id: $macroId
    nrqlMacroEntity: { expression: $expression }
  ) {
    entity {
      id
      name
      expression
    }
  }
}
```

Variáveis de exemplo:

```json
{
  "expression": "(appName = 'ProductionApp' AND environment = 'prod' AND region = 'us-east-1')",
  "macroId": "your-macro-id"
}
```

Para encontrar o ID de uma macro, consulte [Encontrar o ID da sua organização ou macro](#find-ids).
</TabsPageItem>
</TabsPages>
</Tabs>

<Callout variant="important">
Quando você edita uma macro, todas as consultas que usam essa macro utilizam automaticamente a versão atualizada. Revise suas alterações para garantir que elas não quebrem as consultas existentes. Devido ao cache, pode haver um pequeno atraso antes que a atualização entre em vigor. Não é possível atualizar o nome de uma macro após a criação. Se você precisar alterar o nome, exclua a macro e crie uma nova.
</Callout>

## Encontre o ID da sua organização ou macro [#find-ids]

<CollapserGroup>
<Collapser id="macro-find-org-id" title="Encontrar o ID da sua organização">
```graphql
query MyOrganizationId {
  actor {
    organization {
      id
    }
  }
}
```
</Collapser>

<Collapser id="macro-find-macro-id" title="Listar todas as macros e seus IDs">
```graphql
query GetMacros($cursor: String) {
  actor {
    entityManagement {
      entitySearch(query: "type = 'NRQL_MACRO'", cursor: $cursor) {
        entities {
          ... on EntityManagementNrqlMacroEntity {
            id
            name
            expression
          }
        }
        nextCursor
      }
    }
  }
}
```
</Collapser>
</CollapserGroup>
