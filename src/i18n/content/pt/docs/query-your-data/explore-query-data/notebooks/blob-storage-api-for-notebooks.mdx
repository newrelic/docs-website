A API <DNT>Notebooks</DNT> do New Relic permite criar, ler, atualizar e excluir cadernos programaticamente, incluindo o conteúdo completo do bloco (consultas <DNT>NRQL</DNT>, texto). Os cadernos são armazenados como blobs versionados, o que significa que cada salvamento produz uma nova revisão imutável que você pode recuperar mais tarde.

Use esta API para:

* Automatize a criação de notebooks a partir de modelos de incidentes, runbooks ou pipeline de CI/CD
* Sincronizar o conteúdo do notebook a partir do controle de versão ou de ferramentas de autoria externas
* Crie integrações que preencham notebooks de forma programática durante as investigações

<Callout variant="important">
  **<DNT>Notebooks</DNT> usar múltiplas APIs**

  A superfície da API <DNT>Notebooks</DNT> é dividida entre dois sistemas:

  * **<DNT>Blob Storage API</DNT>** lida com o conteúdo do notebook (blocos, histórico de versões)
  * **<DNT>NerdGraph</DNT>** lida com operações no nível da entidade (listar, renomear, tags, metadados da organização)

  Essa separação é intencional. O <DNT>Blob Storage API</DNT> é otimizado para transferência de conteúdo de arquivo e controle de versão; o <DNT>NerdGraph</DNT> é otimizado para consultas e mutações de entidade estruturadas.
</Callout>

## Pré-requisitos [#prerequisites]

* Uma [conta<DNT>New Relic</DNT> ](https://newrelic.com/signup)com uma chave de API de usuário
* Seu ID da organização do <DNT>New Relic</DNT>
* Devidas [permissões](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions/) para gerenciar notebooks

## Autenticação [#authentication]

Todas as requisições de API <DNT>Notebooks</DNT> exigem autenticação usando uma chave de API de usuário <DNT>New Relic</DNT>.

**Gere uma chave de API:**

1. Acesse [one.newrelic.com](https://one.newrelic.com)
2. Clique em seu nome no canto superior direito
3. Selecione <DNT>**API Keys**</DNT>
4. Crie uma chave <DNT>**User**</DNT> (não uma chave de Browser ou chave de licença)

**Incluir nos cabeçalhos da requisição:**

```shell
Api-Key: NRAK-YOUR-USER-API-KEY
```

<Callout variant="tip">
  O <DNT>Blob Storage API</DNT> também suporta contexto de login, portanto, ao chamar a API de uma interface autenticada como um usuário <DNT>New Relic</DNT>, o cabeçalho `Api-Key` não é necessário.
</Callout>

## Endpoint base [#base-endpoint]

```plaintext
https://blob-api.service.newrelic.com/v1/e
```

Para contas da região da UE, use:

```plaintext
https://blob-api.service.eu.newrelic.com/v1/e
```

  <Collapser id="retrieve-versions" title="Recuperar versões anteriores">
    <DNT>Notebook</DNT> as versões são retidas por **1 dia**. Para recuperar uma revisão anterior, primeiro liste as versões recentes via <DNT>NRQL</DNT>, depois busque o blob específico.

    ### Passo 1 — Listar as últimas 5 versões [#retrieve-list-versions]

    Execute esta consulta <DNT>NRQL</DNT> no criador de consulta para reunir os IDs de blob e timestamps das últimas 5 alterações:

    ```sql
    FROM Entity
    SELECT uniques(tuple(updatedAt, content.id))
    WHERE id = '<entity guid>'
    SINCE 1 day ago
    LIMIT 5
    ```

    ### Etapa 2 — Recuperar uma versão específica [#retrieve-specific-version]

    Use o `content.id` do resultado de <DNT>NRQL</DNT> para buscar o conteúdo dessa versão:

    ```bash
    curl -X GET \
      https://blob-api.service.newrelic.com/v1/blobs/<content.id> \
      -H 'Api-Key: NRAK-YOUR-API-KEY'
    ```
  </Collapser>

## Operações de entidade (NerdGraph) [#entity-operations]

Operações no nível da entidade, como listagem, renomeação e tag, usam <DNT>NerdGraph</DNT> em vez do <DNT>Blob Storage API</DNT>.

### Listar todos os notebooks [#list-notebooks]

```graphql
query listAllNotebooks {
  actor {
    entityManagement {
      entitySearch(query: "type='NOTEBOOK'") {
        entities {
          id
          name
        }
      }
    }
  }
}
```

<Callout variant="tip">
  A criação da entidade é totalmente transacional, portanto, um notebook fica imediatamente disponível por meio da API. No entanto, se você listar notebooks por meio da consulta `actor.entitySearch` legada, pode haver um pequeno atraso de propagação entre a criação e o notebook aparecer nos resultados da lista.
</Callout>

### Renomear um notebook [#rename-notebook]

```graphql
mutation changeNotebookName {
  entityManagementUpdateNotebook(
    id: "<entity guid>"
    notebookEntity: { name: "<new name>" }
  ) {
    entity {
      name
    }
  }
}
```

### Atualizar tags do caderno [#update-tags]

<Callout variant="important">
  As atualizações de tag são uma operação de **substituição**. Você deve incluir o conjunto completo de tag, mesmo as que não estão mudando — qualquer tag omitida da mutação será removida.
</Callout>

```graphql
mutation updateNotebookTags {
  entityManagementUpdateNotebook(
    id: "<entity guid>"
    notebookEntity: {
      tags: [
        { key: "<key>", values: "<value>" }
        { key: "<key>", values: "<value>" }
      ]
    }
  ) {
    entity {
      name
      tags {
        key
        values
      }
    }
  }
}
```

query getOrgId {

## Práticas medidas [#best-practices]

* **Armazene os GUIDs de entidade:** Salve o `entityGuid` retornado das operações de criação. Você precisará disso para ler, atualizar e excluir cadernos.
* **Valide o JSON antes do upload:** certifique-se de que a carga do seu caderno seja um JSON válido e esteja em conformidade com o esquema `version` antes de enviar.
* **Use nomes descritivos:** os nomes dos notebooks devem ser exclusivos dentro de uma organização, portanto, escolha nomes que indiquem claramente o propósito (por exemplo, `prod-checkout-investigation` em vez de `notebook-1`).
* **Incluir todas as tags na atualização:** as atualizações de tag substituem todo o conjunto de tags. Sempre leia as tags existentes antes de modificar.
* **Recupere rapidamente:** o histórico de versões é retido por apenas 1 dia. Se você precisar de histórico de longo prazo, arquive o conteúdo do caderno em seu próprio armazenamento a cada atualização.
* **Proteja sua chave de API:** Nunca exponha sua chave de API de Usuário em código do lado do cliente ou repositórios públicos.
* **Verifique os códigos de status HTTP:** A API retorna 2xx para operações bem-sucedidas, 404 para não encontrado e outros códigos de status para erros.
