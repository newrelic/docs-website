## Resumo

Em 19 de novembro de 2026, a Equipe de Resposta a Incidentes de Segurança da New Relic iniciou uma avaliação abrangente de nossos serviços e infraestrutura corporativa contra a recém-divulgada vulnerabilidade do Ruby &quot;Ruby2Shell&quot; (CVE-2026-132825). Trata-se de um buffer overflow baseado em heap de um byte na conversão de maiúsculas e minúsculas de strings do interpretador Ruby, que poderia permitir a execução remota de código (RCE) ou a negação de serviço (DoS).

## Itens de ação

### Nenhuma ação necessária para clientes que usam agentes Ruby

Os agentes Ruby distribuídos da New Relic não são afetados. Os clientes da New Relic que usam os agentes Ruby não precisam realizar nenhuma ação para esta vulnerabilidade.

## Perguntas frequentes

1. **Isso afeta os agentes da New Relic?**

   Os agentes de idiomas da New Relic para Ruby não são afetados. Outros agentes de idiomas da New Relic também não são afetados. As imagens do Fluentd não são usadas nos agentes da New Relic.

2. **Quais sistemas são afetados?**

   Qualquer tempo de execução de contêiner (Kubernetes, Docker, entre outros) executando as seguintes imagens:

   * `newrelic/newrelic-fluentd-docker`
   * `newrelic/fluentd`
   * `newrelic/k8s-golang-apm-linkage-demo`

3. **Como faço para corrigir as vulnerabilidades?**

   Se você utiliza a imagem `newrelic/newrelic-fluentd-docker`:

   1. Faça o pull da imagem corrigida:

      ```shell
      docker pull newrelic/newrelic-fluentd-docker:1.20.1
      ```

   2. Recrie seus contêineres com a nova imagem. Baixar uma imagem não atualiza os contêineres que já estão em execução. No Kubernetes, Docker ou outro tempo de execução de contêiner, altere a tag da imagem para 1.20.1 e reimplante.

   3. Se você cria suas próprias imagens a partir de `newrelic/newrelic-fluentd-docker`, recrie-as com `docker build --pull`.

   4. Verifique a versão em execução:

      ```shell
      docker exec <container> fluentd --version
      ```

   5. A saída deve mostrar `fluentd 1.20.1` ou mais recente.

   Se você não estiver usando a imagem `newrelic/newrelic-fluentd-docker`, considere usar o [Fluentd](https://www.fluentd.org/) com o [plug-in do Fluentd](/docs/logs/forward-logs/fluentd-plugin-log-forwarding/) da New Relic.

4. **Meu contêiner é atualizado quando baixo uma nova imagem?**

   Não. Os contêineres em execução mantêm a imagem antiga até que você os recrie.

5. **O encaminhamento de logs do agente de infraestrutura é afetado?**

   Não. O encaminhamento de logs no agente de infraestrutura e na integração do Kubernetes usa o [Fluent Bit](/docs/logs/forward-logs/fluent-bit-plugin-log-forwarding/), não o Fluentd.

6. **E se eu tiver dúvidas?**

   Para qualquer necessidade de suporte relacionada a este comunicado, abra um caso de suporte por meio do suporte no aplicativo.
