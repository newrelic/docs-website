<DNT>**Vulnerability Identifier:**</DNT> NR26-16

<DNT>**Priority:**</DNT> Crítico

## Resumo

Uma vulnerabilidade crítica de corrupção de memória (CVE-2026-114938) foi divulgada no decodificador Base64 acelerado por hardware da máquina virtual Java (JVM) OpenJDK HotSpot. Quando um aplicativo Java afetado processa uma entrada codificada em Base64 especialmente criada (como cabeçalhos HTTP Authorization, JWTs, tokens SAML ou uploads de arquivos), um underflow de número inteiro pode desencadear uma gravação de heap fora dos limites. A exploração bem-sucedida pode causar travamentos do aplicativo (Negação de Serviço), expor a memória heap sensível ou permitir a Execução Remota de Código (RCE) não autenticada.

## Itens de ação

### Nenhuma ação necessária

A New Relic não fornece um tempo de execução Java com o agente Java da New Relic. Nenhuma ação dos clientes é necessária para os serviços hospedados pela New Relic, incluindo as localizações públicas do Sintéticos.

A ação dos clientes é necessária nos seguintes casos.

### Localização privada do Sintéticos (Sintéticos Job Manager e runtime de ping)

O Gerenciador de Jobs do Sintéticos (SJM) e o runtime de ping para localização privada incluem um ambiente de execução Java. Imagens atualizadas contendo um ambiente de execução Java corrigido foram publicadas em 19 de novembro de 2026.

* Atualize o Job Manager do Sintéticos para a [release-659](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-659/images/sha256-11fa4a7b78d7a7d708b1f5efec790dc066ab6c02d3b3f02c7a59a8b885913828) ou posterior e o runtime de ping para o [1.89.0](https://hub.docker.com/layers/newrelic/synthetics-ping-runtime/1.89.0/images/sha256-33da2eb67b404b09f19e1ea232e80be22d403e97abbeaf2b0f26bc95d2eae646) ou posterior.
* Se a sua configuração fixar o runtime de ping em uma versão específica, atualize-o para a 1.89.0 ou posterior. Se ele usar a tag `latest`, reinicie o Gerenciador de Jobs do Sintéticos para obter o runtime atualizado.
* Se você executar qualquer versão do Gerenciador de Jobs do Sintéticos anterior à [release-655](https://hub.docker.com/layers/newrelic/synthetics-job-manager/release-655/images/sha256-c587a634136aeed4179ebd216d993c9aea4b50a6a88f977fc5099fb164b42c57), não haverá um caminho de atualização in-loco para a versão atual. Planeje uma migração para a versão mais recente e valide-a em um ambiente não produção primeiro. Para obter instruções de instalação, consulte [Instalar o Gerenciador de Jobs do Sintéticos](/docs/synthetics/synthetic-monitoring/private-locations/install-job-manager).
* Se você não puder atualizar o Gerenciador de Jobs do Sintéticos imediatamente, defina a opção da JVM `JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"` no contêiner do Gerenciador de Jobs do Sintéticos. Apenas em hosts x86-64, você pode usar `-XX:UseAVX=2` em vez disso. As JVMs em ARM não reconhecem essa opção e falharão ao iniciar. Essa opção não se aplica ao contêiner de runtime de ping cujo lançamento é realizado pelo Sintéticos Job Manager, de modo que você ainda precisa atualizar a imagem do runtime de ping para remediar de forma completa.

### Seus aplicativos Java, incluindo aqueles monitorados pelo agente Java da New Relic

Seus aplicativos Java são afetados apenas quando todas as seguintes condições são verdadeiras:

* O aplicativo é executado em uma distribuição OpenJDK baseada em HotSpot, versão 17.0.6 ou posterior (mas anterior à atualização de patch crítica de novembro de 2026). Os exemplos incluem Oracle Java SE, Amazon Corretto, Eclipse Temurin, Azul Zulu, Red Hat OpenJDK e Microsoft Build of OpenJDK.
* O host tem um processador x86-64 com suporte a AVX-512 VBMI (Intel Xeon Ice Lake ou mais recente, ou AMD Zen 4 ou mais recente). Processadores ARM64, incluindo o AWS Graviton, não são afetados.
* O aplicativo processa entradas não confiáveis que podem chegar ao decodificador Base64 do Java.

**Correção:** atualize seu ambiente de execução Java para a versão de segurança de novembro de 2026 do seu fornecedor, começando pelos sistemas expostos à internet. Para obter detalhes, consulte a [Atualização crítica de patch de segurança](https://www.oracle.com/security-alerts/cspunov2026.html) da Oracle (novembro de 2026), o [Aviso de vulnerabilidades](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) do OpenJDK (17/11/2026) ou o aviso do seu fornecedor de JDK.

## Perguntas frequentes

1. **Isso afeta os agentes da New Relic?**

   O agente Java New Relic não agrupa nem distribui um runtime Java (JDK/JVM). O aplicativo Java é instrumentado por ele usando o runtime Java disponível no ambiente do aplicativo.

2. **Preciso atualizar o agente Java New Relic?**

   Não. O agente Java da New Relic não inclui um runtime do Java, e nenhuma atualização do agente Java é necessária para esta vulnerabilidade.

3. **Quais sistemas são afetados?**

   Apenas processadores x86-64 que oferecem suporte a AVX-512 VBMI. Os processadores ARM64 não são afetados. O OpenJDK e a Oracle publicaram correções.

4. **Como sei se os runtimes do Java dos meus aplicativos são afetados?**

   Verifique a versão do Java e a CPU. Para aplicativos monitorados pelo New Relic APM, a versão da JVM é mostrada na página de Ambiente do serviço. Consulte [Obter dados de ambiente sobre seu aplicativo APM](/docs/apm/agents/manage-apm-agents/troubleshooting/get-environment-data-about-your-apm-app) para obter mais detalhes e certifique-se de selecionar seus hosts. Como alternativa, em um host, execute `java -version`.

   No Linux, verifique a CPU com:

   ```bash
   grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(avx512f|avx512bw|avx512vbmi|bmi2)$'
   ```

   A CPU é afetada apenas se todas as quatro flags aparecerem.

5. **Como faço para corrigir as vulnerabilidades?**

   Atualize seu ambiente de execução Java para a versão de segurança de novembro de 2026 do seu fornecedor, começando pelos sistemas expostos à internet. Para obter detalhes, consulte a [Atualização crítica de patch de segurança](https://www.oracle.com/security-alerts/cspunov2026.html) da Oracle (novembro de 2026), o [Aviso de vulnerabilidades](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) do OpenJDK (17/11/2026) ou o aviso do seu fornecedor de JDK.

6. **O que posso fazer se não puder aplicar o patch imediatamente?**

   Inicie a JVM com `JAVA_TOOL_OPTIONS="-XX:-UseBASE64Intrinsics"` como uma mitigação temporária. Apenas em hosts x86-64, você pode usar `-XX:UseAVX=2` em vez disso. As JVMs em ARM não reconhecem essa opção e falharão ao iniciar. Ambas as opções são temporárias e não substituem a aplicação de patches.

7. **A New Relic identificou evidências de exploração?**

   Não identificamos indicadores de exploração dessas vulnerabilidades em nosso ambiente.

8. **E se eu tiver dúvidas?**

   Para qualquer necessidade de suporte relacionada a este comunicado, abra um caso de suporte por meio do suporte no aplicativo.
