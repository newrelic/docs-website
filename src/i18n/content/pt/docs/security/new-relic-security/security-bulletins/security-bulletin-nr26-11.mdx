<DNT>**Vulnerability Identifier:**</DNT> NR26-11

<DNT>**Priority:**</DNT> Alto

## Resumo

We are issuing this bulletin to inform you of critical security vulnerabilities in [Node.js](https://nodejs.org/) versions (22.x, 24.x, 26.x) that may require customer action for New Relic Synthetic monitoring customers using Public and Private locations.

**Versões corrigidas:** as versões corrigidas do Node.js são 22.23.4, 24.22.1 e 26.12.1.

**Versões em fim de vida útil (EOL):** Node.js 20 e anteriores, incluindo o Node.js 16.x, atingiram o fim da vida útil e não receberão patches do projeto Node.js. A única solução para versões EOL do Node.js é a migração para uma versão suportada.

## Ação requerida

Essas vulnerabilidades afetam os clientes de monitoramento sintético que usam tanto localizações públicas quanto privadas. A ação dos clientes para cada uma é a seguinte.

### Localização pública

A ação dos clientes depende de os seus monitores estarem no runtime mais recente.

1. **Nenhuma ação necessária:** nenhuma ação é necessária para monitores implantados em localizações públicas que estão no runtime compatível mais recente.

### localização privada

**Ação necessária:** para localizações privadas, é necessário baixar as imagens de tempo de execução mais recentes para corrigir essas CVEs. É necessária uma ação para monitores implantados em localizações privadas se você não usar a tag `latest`.

The `node-api-runtime` and `node-browser-runtime` container images bundle Node.js and are directly impacted by this vulnerability. Although security scanners may detect the CVE within the Synthetics Job Manager (SJM) and ping-runtime images, these runtimes are not exploitable. To eliminate the same, these CVE&apos;s will be addressed in the next releases of SJM v642 and ping-runtime 1.87.0.

Se você estiver executando localizações privadas, siga as seguintes etapas:

1. Baixe as versões mais recentes das imagens de runtime afetadas:

   ```shell
   # Node API runtime
   docker pull newrelic/synthetics-node-api-runtime:latest

   # Node browser runtime
   docker pull newrelic/synthetics-node-browser-runtime:latest
   ```

2. É necessário reiniciar seus contêineres após baixar as imagens atualizadas para aplicar a correção.

Para obter mais informações, consulte o [guia de transição de runtime](/docs/synthetics/synthetic-monitoring/private-locations/runtime-transition-guide/).

### Aviso importante: monitores de API com script do Node.js 16.x

Se você tiver monitores de API com script configurados para execução no Node.js 16.x, esteja ciente de que:

* Node.js 16.x will not receive a security patch for these CVEs from the Node.js project, because it has already reached [end-of-life](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/).
* A New Relic não forçou a atualização automática dos monitores do Node.js 16.x para o Node 22.x, porque a compatibilidade do script não pode ser garantida. Alguns scripts de monitor podem exigir alterações de código para serem executados corretamente no Node 22.x.

Recomendamos fortemente que você revise e migre seus monitores do Node 16.x para o Node 22.23.4 o mais rápido possível, e não espere até 18 de novembro de 2026. Para obter instruções detalhadas de migração, consulte [Atualizar monitores de API com script para o Node.js 22](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/).

## Perguntas frequentes

1. **Do I need to update the Synthetics job manager (SJM) &amp; ping-runtime?**

   No immediate update is required for remediation. While vulnerability scanners may flag the CVE in SJM and ping-runtime, these components are not susceptible to exploitation. However, upcoming releases (SJM v642 and ping-runtime 1.87.0) will address this CVE. Updating to these releases is recommended if you wish to maintain zero-finding compliance reports.

2. **A atualização das imagens de tempo de execução afetará meus monitores em execução?**

   Os monitores continuam a ser executados normalmente após a atualização da imagem de runtime. Não há alteração de comportamento para os monitores em execução no Node 22.x.

3. **A CVE-2026-111497 pode ser explorada remotamente?**

   Sim. Esta é uma vulnerabilidade de execução remota de código. Ela pode ser acionada quando um processo Node.js recebe uma resposta HTTP compactada com Brotli de um servidor controlado por um invasor. Não é necessário acesso local.

4. **Estou executando monitores do Node 16.x. Estou em risco?**

   Sim. O Node 16.x chegou ao fim da vida útil e não receberá patches. Seus monitores permanecem vulneráveis até que você os migre para o Node 22.23.4. Você mesmo pode fazer isso usando a ferramenta de atualização de runtime. Para obter mais informações, consulte [Gerenciar runtimes de monitor](/docs/synthetics/synthetic-monitoring/using-monitors/manage-monitor-runtimes/).

5. **Por que meu monitor do Node 16.x não foi atualizado automaticamente?**

   Node 22.x includes breaking changes from Node 16.x, which New Relic [communicated earlier](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/). Scripted API monitors still on Node 16.x are those that couldn&apos;t be automatically upgraded without failing. New Relic therefore made this a customer-initiated upgrade to avoid unintended monitor breakage. We&apos;ll follow the EOL timelines [communicated earlier](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/) and will force-upgrade Node 16.x monitors on November 18, 2026.

6. **Preciso reinicializar ou reiniciar algo após atualizar os tempos de execução da localização privada?**

   É necessária apenas a reinicialização do contêiner. Não é necessário reiniciar o host.

7. **Com quem posso entrar em contato se ainda tiver dúvidas?**

   Abra um caso com nossa equipe de Suporte através da seção de ajuda na plataforma New Relic.
