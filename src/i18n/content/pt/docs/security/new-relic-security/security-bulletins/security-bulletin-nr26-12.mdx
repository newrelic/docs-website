<DNT>**Vulnerability Identifier:**</DNT> NR26-12

<DNT>**Priority:**</DNT> Alto

## Resumo

Entre 17 de outubro e 20 de outubro de 2026, pesquisadores revelaram que as chaves privadas de oito certificados intermediários de autoridade de certificação (CA) emitidos pela eMudhra poderiam ser recuperadas. Qualquer pessoa com essas chaves poderia criar certificados que o software aceitaria como genuínos se ainda confiar neles. Embora os principais sistemas operacionais e navegadores da web já tenham revogado a confiança nesses certificados, os aplicativos que gerenciam repositórios de confiança de CA independentes, incluindo algumas imagens de contêiner, precisam ser atualizados.

A New Relic reconstruiu as imagens de contêiner que fornece para as localizações privadas do Sintéticos para que elas não utilizem mais esses certificados. Os clientes que executam as localizações privadas do Sintéticos precisam baixar as novas imagens e reiniciar seus contêineres, pois as imagens não são atualizadas automaticamente.

Para identificar os monitores ainda em execução no tempo de execução legado, execute a seguinte consulta NRQL no criador de consulta da sua conta:

```sql
SELECT uniques(monitorName) FROM SyntheticCheck WHERE runtimeType = 'NODE_API' AND runtimeTypeVersion = '16.10' SINCE 1 day ago
```

Você também pode identificar os monitores afetados na [tela de EOL do Sintéticos](https://onenr.io/0gR77nzxaRo) na interface do New Relic. Filtre por **Monitor Type: Script API** para ver todos os monitores ainda em execução no Node.js 16.10.

### Aviso importante: migração para o Node.js 16.x obrigatória (localizações públicas e localização privada) [#node-16-migration]

Os monitores de API com script em execução no Node.js 16.10 chegarão ao [fim da vida útil](/eol/2026/05/eol-05-18-26-node-16-chrome-134-runtimes/) em 18 de novembro de 2026. Esses monitores estão expostos às vulnerabilidades do eMudhra, e os monitores que ainda estão em execução nessas versões mais antigas devem ser migrados para o Node.js 22.23.0. Isso se aplica independentemente de seus monitores serem executados em localizações públicas ou localização privada.

**Ação recomendada:** a partir de 18 de novembro de 2026, a New Relic atualizará automaticamente os monitores de localização pública que ainda estão em execução no Node.js 16.x para o tempo de execução atual. Recomendamos fortemente que você migre o mais rápido possível, antes dessa data, para que você possa testar se os seus monitores continuam a operar conforme o esperado no novo tempo de execução e deixe de usar a versão vulnerável. Para obter instruções, consulte [Atualizar monitores de API com script para o Node.js 22](/docs/synthetics/synthetic-monitoring/scripting-monitors/synthetics-scripted-api-monitors-to-node-22/).

## Informações sobre vulnerabilidades técnicas

Nenhum CVE foi atribuído a este problema.

## Perguntas frequentes

1. **A infraestrutura de localização pública da New Relic foi afetada?**

   A New Relic corrigiu a infraestrutura de localização pública em execução no runtime mais recente. No entanto, os monitores fixados explicitamente no Node.js 16.x continuarão sendo executados nessa versão até que sejam atualizados pelo proprietário da conta.

2. **Algum resultado do monitor foi adulterado?**

   A New Relic não tem evidências de adulteração em nossas imagens Sintéticas.

3. **Preciso rotacionar as credenciais armazenadas nas credenciais seguras do Sintéticos?**

   Nenhuma ação é necessária, a menos que você tenha um motivo específico para acreditar que a sua rede e a infraestrutura foram comprometidas.

4. **Com quem posso entrar em contato se ainda tiver dúvidas?**

   Abra um caso com nossa equipe de Suporte através da seção de ajuda na plataforma New Relic.
