<DNT>**Vulnerability Identifier:**</DNT> NR26-14

<DNT>**Priority:**</DNT> Alto

## Resumo

Entre 17 e 20 de outubro de 2026, pesquisadores revelaram que as chaves privadas de oito certificados de autoridade de certificação (CA) intermediária emitidos pela eMudhra podem ser recuperadas (CVE-2026-111943). Qualquer pessoa com essas chaves pode criar certificados que o software aceitaria como genuínos se ainda confiar neles. Navegadores e sistemas operacionais bloquearam os certificados, mas o software que carrega sua própria lista de CAs confiáveis, incluindo algumas imagens de contêiner, precisa ser atualizado.

A New Relic atualizou os componentes do Kubernetes abaixo para que não aceitem mais certificados emitidos por essas CAs. As versões atualizadas não são obtidas automaticamente. Os clientes precisam atualizar para as versões listadas abaixo.

**Nota para todos os componentes:** Se os seus valores do Helm fixarem tags de imagem (por exemplo, `images.integration.tag`), remova a fixação ou atualize-a para a versão corrigida. Caso contrário, a atualização manterá a imagem antiga.

**\*Nota de atualização.** `newrelic-infrastructure` 4.x é uma versão principal. A única alteração incompatível afeta os nós do Windows. Consulte as notas de lançamento do chart na seção [Recursos](#resources) antes de atualizar.

## Informações sobre vulnerabilidades técnicas

* Oito CAs intermediárias que formam uma cadeia com a emSign ECC Root CA - G3 e, por meio de assinatura cruzada, com a AAA Certificate Services, foram afetadas.

* As imagens corrigidas baseadas no Alpine são compiladas no Alpine 3.24.3 com ca-certificates 20261020-r0, o que remove o emSign ECC Root CA - G3 e o AAA Certificate Services do pacote CA.

  * O k8s-agents-operator 0.54.0 é compilado em uma base distroless com ambas as raízes removidas.
  * prometheus:v3.15.1 (upstream) também inclui um pacote CA sem nenhuma das raízes.

* Os binários da integração do Kubernetes do New Relic são compilados com o Go 1.27.3, cuja biblioteca TLS recusa cadeias de certificados que contêm as oito chaves afetadas, mesmo se a raiz ainda for confiável. Algumas integrações no host agrupadas no infrastructure-bundle usam versões anteriores do Go; seu pacote CA ainda está fixo.

* A exposição é limitada a conexões que usam o armazenamento raiz público: as conexões dos agentes aos endpoints da New Relic e a qualquer proxy configurado. As conexões dentro do cluster (servidor de API do Kubernetes, kubelet, control plane) usam a CA do próprio cluster e não são afetadas.
