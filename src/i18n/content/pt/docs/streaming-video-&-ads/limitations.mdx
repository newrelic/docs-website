Esta página consolida limitações conhecidas, comportamentos não suportados e restrições em todo o conjunto de recursos do Streaming Video &amp; Ads. Para obter o contexto completo sobre cada limitação, siga os links no final de cada seção.

## Widgets personalizados [#custom-widgets]

### Limite de widget [#widget-limit]

Cada conta suporta um limite flexível de **50 widgets personalizados por contexto de dashboard** — 50 para <DNT>**Video quality metrics**</DNT> e 50 para <DNT>**Ad quality metrics**</DNT>, contados separadamente. Se atingir o limite, exclua um widget personalizado existente antes de adicionar um novo. Seus widgets existentes continuam funcionando normalmente.

### Padrões de consulta NRQL [#nrql-patterns]

A integração do filtro do dashboard funciona bem para padrões de consulta comuns. Os seguintes padrões NRQL têm suporte limitado ou não testado e podem produzir resultados inesperados quando os filtros globais estão ativos:

* **Condições OR em `WHERE`** — Consultas com a lógica `OR` na cláusula `WHERE` podem produzir resultados incorretos quando filtros globais são aplicados, devido à precedência de operadores.
* **`COMPARE WITH`** — Consultas de comparação de tempo podem não funcionar corretamente com a integração do seletor de hora do dashboard.
* **Subconsultas** — Padrões `FROM (SELECT …)` aninhados podem não se comportar como o esperado quando filtros globais são aplicados.
* **Agregadores aninhados complexos** — Construções avançadas de `filter()` além dos exemplos documentados podem não lidar corretamente com o estado sem filtro.
* **Cláusula`PREDICT` **— as consultas da cláusula `PREDICT` podem não funcionar corretamente com a integração do seletor de hora do dashboard.

Caso encontre um padrão de consulta que não funcione como o esperado, entre em contato com a equipe da sua conta da New Relic com os detalhes da consulta.

Para obter o contexto completo, consulte [Criar widgets personalizados para dashboards de streaming](/docs/streaming-video-&-ads/custom-widget-support).

## Ofuscação [#obfuscation]

### Padrões de regex do Roku [#roku-regex]

O Roku usa `roRegex` para correspondência de padrão. O Roku não oferece suporte a asserções complexas de lookahead/lookbehind. Os padrões que são válidos em regex de JavaScript ou Java podem precisar ser simplificados para o Roku.

Para obter o contexto completo, consulte [Ofuscar dados do agente de mídia de streaming](/docs/streaming-video-&-ads/obfuscation) e [Regras de ofuscação do Roku](/docs/streaming-video-&-ads/installation/roku/obfuscation-rules).
