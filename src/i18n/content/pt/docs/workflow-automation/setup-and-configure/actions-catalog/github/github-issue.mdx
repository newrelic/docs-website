Esta página fornece uma referência para as ações de issue do GitHub disponíveis no catálogo de ações de automação de fluxo de trabalho. Estas ações permitem criar, atualizar, listar e gerenciar issues em um repositório do GitHub diretamente de uma definição de fluxo de trabalho.

## Pré-requisitos

Antes de usar as ações de issue do GitHub na automação do fluxo de trabalho, é necessário ter:

* Uma conta do GitHub com acesso ao repositório de destino.
* Um token de acesso pessoal (PAT) do GitHub com as permissões necessárias.
* O PAT armazenado no serviço de segredos da New Relic.

## Configurar a autenticação PAT

As ações de issue do GitHub são autenticadas usando um token de acesso pessoal (PAT) passado como uma credencial Bearer. Esta ação suporta dois tipos de token:

* **Fine-grained PAT** — requer a permissão de repositório **Issues: Read and write**.
* **Classic PAT** — requer o escopo de **repositório**.

<Steps>
  <Step>
    ### Crie um token de acesso pessoal do GitHub

    1. No GitHub, acesse **Settings &gt; Developer settings &gt; Personal access tokens**.
    2. É necessário escolher **Fine-grained tokens** ou **Token (classic)** e clicar em **Generate new token**.
    3. Defina as permissões necessárias: **Issues: Read and write** para tokens granulares, ou escopo de **repositório** para tokens clássicos.
    4. Copie o token gerado — o GitHub o exibe apenas uma vez.
  </Step>

  <Step>
    ### Armazenar o token como um segredo

    Armazenar o token no New Relic Secrets Service e referenciá-lo no YAML do fluxo de trabalho usando a sintaxe `${{ :secrets:keyName }}`:

    ```yaml
    token: ${{ :secrets:github-PAT-token }}
    ```
  </Step>
</Steps>
