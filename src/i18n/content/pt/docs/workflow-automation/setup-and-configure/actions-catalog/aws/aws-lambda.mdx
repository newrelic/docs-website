Esta página fornece uma referência para as ações do AWS Lambda disponíveis no catálogo de ações de automação de fluxo de trabalho. Use estas ações para gerenciar e invocar funções do Lambda como parte das definições do seu fluxo de trabalho.

## Pré-requisitos

Antes de usar ações AWS Lambda na automação de fluxo de trabalho, certifique-se de ter:

* Uma conta da AWS com as permissões apropriadas.
* Credenciais da AWS configuradas (credenciais de usuário do IAM, ARN da função do IAM ou credenciais de sessão). Pelo menos uma opção de credencial deve ser fornecida — a função do IAM tem precedência sobre as chaves de acesso estáticas.
* As permissões do IAM necessárias para as operações específicas do Lambda que você planeja usar.

Consulte [Configurar credenciais da AWS](/docs/workflow-automation/setup-and-configure/set-up-aws-credentials/) para obter informações sobre como criar usuários e funções do IAM, e configurar credenciais da AWS estáticas e de sessão para integração com ações da AWS de automação de fluxo de trabalho.

## Obter histórico de execução durável do Lambda

O identificador da ação é `aws.lambda.getDurableExecutionHistory`.

Recupera o histórico de execução de uma [execução durável do Lambda](https://docs.aws.amazon.com/lambda/latest/dg/durable-functions.html), mostrando todos os passos, retornos de chamada e eventos que ocorreram. Esta ação se aplica apenas a execuções duráveis do Lambda — ela não pode recuperar o histórico de invocação para funções regulares do Lambda. O histórico está disponível enquanto a execução está em andamento e por um período de retenção configurável após a sua conclusão (1–90 dias, padrão de 30 dias).

Para execuções de longa duração com muitas etapas ou retornos de chamada, defina `includeExecutionData` como `false` quando precisar apenas de tipos de evento e timestamps em vez de cargas completas — isso produz uma resposta mais compacta.

## Definir a simultaneidade da função do Lambda

A configuração de simultaneidade se aplica a todas as versões publicadas e à versão não publicada. Definir `reservedConcurrentExecutions` como `0` desativa a função sem excluí-la.
