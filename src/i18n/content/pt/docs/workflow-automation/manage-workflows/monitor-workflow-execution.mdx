Este artigo descreve como usar dados de observabilidade para monitorar a execução do fluxo de trabalho e a execução do agendamento.

## Auditorias

Todas as chamadas de mutação do NerdGraph produzem registros de auditoria que podem ser consultados em `NrAuditEvent` na conta de clientes.

### WorkflowRun

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_run'
SINCE 1 hour ago
```

### WorkflowSchedule

```sql
SELECT actionIdentifier, actorId, actorType, description
FROM NrAuditEvent 
WHERE targetType = 'workflow_schedule'
SINCE 1 hour ago
```

## Evento

Todas as execuções de fluxo de trabalho emitem dados `WorkflowAutomationEvent` no NRDB na conta de clientes que iniciou ou agendou o fluxo de trabalho.

As execuções de fluxo de trabalho armazenam dados de evento no namespace `WorkflowAutomation`.

O atributo `stepType` tem os seguintes valores:

* `ACTION`: executa uma ação do catálogo
* `LOOP`: itera sobre uma coleção
* `SWITCH`: avalia condições
* `STATE`: armazena pares de valor principal no estado compartilhado do fluxo de trabalho

### Exemplo de consulta

A consulta a seguir retorna todos os eventos para uma execução de fluxo de trabalho específica:

```sql
SELECT *
FROM WorkflowAutomationEvent
where definitionName = 'json-parsing' and runId = '31c973d2-c669-4bd7-9b15-7e3a70a4a074'
SINCE 1 month ago
```

## Registro

Opcionalmente, é possível iniciar ou agendar um fluxo de trabalho com uma opção de verbosidade `logLevel`. Os logs vão para a conta que iniciou ou agendou o fluxo de trabalho.

Os registros incluem os seguintes atributos:

* `workflowAutomation.name` é o nome do WorkflowDefinition
* `workflowAutomation.version` é a versão do WorkflowDefinition
* `workflowAutomation.runId` é o runId do fluxo de trabalho
* `entityGuid` é o ID do WorkflowDefinition

Se uma ocorrência de agendamento iniciou o fluxo de trabalho, as entradas de registro também incluem `workflowAutomation.scheduleId`.

Para o tipo de etapa Action, ao usar `DEBUG`, cada entrada de ação adiciona um atributo adicional à entrada de registro com o formato `workflowAutomation.inputs.<inputName>: <inputValue>`.

Para o tipo de etapa Action, ao usar `TRACE`, cada saída de ação adiciona um atributo adicional à entrada de registro com o formato `workflowAutomation.outputs.<outputName>: <outputValue>`.

### Exemplo de consulta NRQL

Você pode consultar seu log com a seguinte consulta NRQL:

```sql
SELECT message FROM Log WHERE workflowAutomation.runId = '{run_id}' SINCE 3 hours ago
```

<img title="Diagram of log attributes for workflow runs" alt="Diagram of log attributes for workflow runs" src="/images/log_attributes.webp" />

Além de `workflowAutomation.runId`, alguns outros atributos de log que podem ajudar na consulta de dados de log são:

* `workflowAutomation.name`
* `workflowAutomation.version`

Para execuções agendadas, as entradas de registro também incluem o atributo `workflowAutomation.scheduleId`.
