Os seguintes modelos de fluxo de trabalho automatizam a análise de causa raiz baseada em <DNT>Autopilot</DNT>para alertas do New Relic:

* **[RCA de alerta com Autopilot e Slack](/docs/workflow-automation/workflow-examples/integrations/autopilot-slack-rca)** — Publica as descobertas em um canal do Slack usando a formatação do Block Kit
* **[RCA de alerta com Autopilot e e-mail](/docs/workflow-automation/workflow-examples/integrations/autopilot-email-rca)** — Envia as descobertas como um e-mail em HTML formatado

Esses modelos aceitam uma entrada `issueId` e executam <DNT>Autopilot</DNT> com um prompt de RCA. Eles verificam se <DNT>Autopilot</DNT> retornou uma resposta utilizável e encaminham a saída para o destino escolhido. Eles diferem no tipo de destino e em como formatam a saída de <DNT>Autopilot&apos;s</DNT>.

## Requisitos [#requirements]

Todos os modelos exigem um ID de problema de alerta do New Relic no formato UUID. Cada modelo também exige um destino de notificação configurado — consulte as páginas individuais do modelo para obter os pré-requisitos específicos do destino.

<Callout variant="tip">
  Ao acionar qualquer um desses modelos a partir de <DNT>**Alert Workflows**</DNT>, use `{{ issueId }}` como o valor para a entrada `issueId`. Esta variável passa automaticamente o ID do problema do alerta acionador para o fluxo de trabalho.
</Callout>

## Notas de configuração [#configuration]

Tenha o seguinte em mente ao configurar qualquer um destes modelos.

<Callout variant="important">
  Escreva os valores do seletor `expression` em uma única linha. O mecanismo de fluxo de trabalho não avalia escalares de bloco YAML de várias linhas (`|` ou `|-`) como expressões de seletor — eles silenciosamente não produzem saída.
</Callout>

<Callout variant="tip">
  <DNT>Autopilot&apos;s</DNT> `finalAnswer` o campo pode retornar como uma string simples ou como um objeto codificado em JSON, dependendo do contexto do prompt. Os seletores de cada modelo lidam com ambos os formatos automaticamente.
</Callout>
