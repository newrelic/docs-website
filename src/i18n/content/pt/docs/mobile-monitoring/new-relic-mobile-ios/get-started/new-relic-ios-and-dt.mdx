Nosso agente iOS suporta distributed tracing. Isso permite que você veja como a atividade do seu aplicativo móvel se conecta aos serviços relacionados.

## Requisitos [#requirements]

Para usar distributed tracing, você precisa do agente iOS versão 7.3.0 ou superior. Recomendamos que você use o agente mais recente.

## Como configurar distributed tracing [#setup]

O distributed tracing está ativado por padrão — você não precisa fazer nada para ativá-lo.

Se você preferir desativá-lo, consulte [distributed tracing](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#ios-dt) no guia da API do SDK mobile, ou [Desativar o distributed tracing](#disable) abaixo.

Os cabeçalhos de distributed tracing são enviados em cada solicitação instrumentada, independentemente de outras configurações. No entanto, para que o trace seja vinculado a um evento `MobileRequest` relatado (e, assim, apareça correlacionado com a atividade de rede do seu aplicativo na interface), você também precisa ter os [Eventos de solicitação de rede](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#ios-networking) ativados. Isso está ativado por padrão, portanto, só importa se você o tiver desativado explicitamente.

## Cabeçalhos de distributed tracing [#headers]

A partir da versão 7.7.8 do agente iOS, o agente adiciona apenas os cabeçalhos do [W3C Trace Context](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers), `traceparent` e `tracestate`, aos requests de rede de saída. Ele não envia mais o cabeçalho proprietário `newrelic`. As versões anteriores do agente enviam todos os três cabeçalhos.

Os agentes New Relic APM que suportam o W3C Trace Context usam esses cabeçalhos para continuar o trace, para que os requests do seu aplicativo permaneçam conectados aos serviços de backend que eles chamam. O W3C Trace Context é suportado nestas versões do agente APM e superiores:

## Quais requests recebem distributed tracing automaticamente [#automatic-instrumentation]

O agente instrumenta automaticamente `NSURLSession` e `NSURLConnection`, portanto, cabeçalhos de distributed tracing são adicionados aos requests feitos por qualquer um deles sem necessidade de configuração.

<Callout variant="important">
Se o seu aplicativo usa as APIs `URLSession` `async`/`await` do Swift (por exemplo, `data(for:)` ou `data(from:)`), elas **não** são cobertas pela instrumentação padrão. Você deve ativar explicitamente `NRFeatureFlag_SwiftAsyncURLSessionSupport` (desativado por padrão a partir da versão 7.4.5 do agente) para que o agente adicione cabeçalhos de distributed tracing a essas chamadas:

O agente não adiciona automaticamente os cabeçalhos de distributed tracing a:

* `WKWebView`. O conteúdo da web carregado em um `WKWebView` faz seus requests de rede de dentro do processo WebKit, fora da instrumentação `NSURLSession`/`NSURLConnection` do aplicativo, portanto, esses requests não recebem o trace automaticamente. (A instrumentação `WKWebView` separada do agente, ativada por padrão, cobre apenas o tempo de carregamento da página, não os cabeçalhos de rede.)
* Bibliotecas de rede de terceiros que não passam por `NSURLSession` ou `NSURLConnection`.
* WebSockets.
* gRPC ou outros transportes personalizados.

Para qualquer um desses, use a propagação manual.

## Propagar manualmente o distributed tracing [#manual]

Se você fizer um request por meio de uma API, o agente não realiza a auto-instrumentação. Você ainda pode adicionar cabeçalhos de distributed tracing e relatar o request manualmente.

**Se algo mais relatar o request**

Alguns frameworks (por exemplo, uma biblioteca de rede nativa usada por um framework híbrido) enviam a solicitação e a relatam ao New Relic separadamente. Neste caso, gere os cabeçalhos e anexe-os você mesmo. O que quer que relate a solicitação recuperará a identidade do trace a partir dos cabeçalhos W3C.

**Se você enviar e reportar o request**

Se o mesmo código enviar o request e relatá-lo para a New Relic (por exemplo, um agente multiplataforma), use `generateDistributedTracingContext` em vez disso. Ele retorna um dicionário com os cabeçalhos W3C para definir no request (`traceparent`, `tracestate`) mais a identidade do trace (`trace.id`, `id`, `guid`) para devolver quando você relatar o request, para que o evento relatado tenha esse trace como atributo, em vez de um novo.

Passe esse mesmo dicionário como o parâmetro `traceHeaders` de [`noticeNetworkRequestForURL:`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-success/) ou [`noticeNetworkFailureForURL:`](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/network-request-failures/) (selecione a guia iOS) ao relatar a solicitação concluída — consulte essas páginas para obter a referência completa do parâmetro.

## Habilitar rastreamento infinito [#infinite-tracing]

Se seus aplicativos móveis tiverem alguns serviços downstream que usam nosso tail-based distributed tracing chamado [Infinite Tracing](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing), você deverá ativar esse recurso para seus aplicativos móveis. Isso garante que seu intervalo raiz (o aplicativo móvel inicial) seja incluído no restante dos intervalos rastreados pelo Infinite Tracing.

Para configurar isso, consulte as [etapas do Rastreamento Infinito](/docs/distributed-tracing/infinite-tracing/set-trace-observer) para criar um observador de rastreamento e selecionar quais aplicativos móveis (fontes de dados) devem relatar períodos.

## Encontre dados [#find-data]

Os spans móveis aparecem em qualquer [interface distributed tracing do New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) onde esses spans fazem parte de um trace.

Aqui estão algumas dicas para encontrar e consultar dados:

* Você pode encontrar rastreamento originado pelo usuário final em qualquer [interface distributed tracing do New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one).
* Na interface de distributed tracing, os spans do usuário final são indicados com o<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}} />ícone.
* Para ver o atributo de um span, selecione [um span na interface](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details).
* Os spans são relatados como [dados de span](/attribute-dictionary/?event=Span) e podem ser [consultados no New Relic](/docs/using-new-relic/data/understand-data/query-new-relic-data).

Por exemplo, para encontrar spans de dispositivos móveis para um aplicativo específico:

```sql
SELECT count(*) FROM Span WHERE mobileApp.name = 'YOUR_APP_NAME' SINCE 1 day ago
```

Para encontrar traces que conectam um span de dispositivo móvel a um span de APM do backend:

```sql
SELECT * FROM Span WHERE mobileApp.name IS NOT NULL AND appName IS NOT NULL SINCE 1 day ago
```

## Resolução de problemas [#troubleshooting]

Se você não visualizar os spans mobile onde os espera, verifique estas possíveis causas:

* **O distributed tracing está desativado.** Confirme se você não chamou `disableFeatures` com `NRFeatureFlag_DistributedTracing`. Consulte [Como configurar o distributed tracing](#setup).
* **O request não é autoinstrumentado.** Requests feitos por meio de qualquer outra opção além de `NSURLSession` ou `NSURLConnection` — incluindo chamadas Swift `async`/`await` `URLSession` — precisam do `NRFeatureFlag_SwiftAsyncURLSessionSupport` ativado ou da [propagação manual](#manual). Consulte [Quais requests recebem o distributed tracing automaticamente](#automatic-instrumentation).
* **O agente APM do backend é muito antigo.** Se o agente APM do serviço receptor ainda não oferecer suporte ao W3C Trace Context, ele iniciará um novo trace em vez de vincular ao do seu aplicativo. Verifique as [versões mínimas do agente APM](#headers).
* **Um proxy ou gateway remove os cabeçalhos.** Qualquer componente entre o seu aplicativo e o backend precisa repassar `traceparent` e `tracestate` sem modificações.
* **`tracestate` é descartado porque a chave da conta confiável não corresponde.** Se um serviço de backend pertencer a uma conta da New Relic diferente da conta do seu aplicativo mobile, confirme se a conta está na mesma relação de confiança, ou a entrada `tracestate` poderá ser ignorada.

Para problemas mais amplos de distributed tracing, consulte a [resolução de problemas](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data).
