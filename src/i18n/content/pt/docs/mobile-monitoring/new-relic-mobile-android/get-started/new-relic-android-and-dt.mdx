O agente <InlinePopover type="mobile" />Android New Relic oferece suporte distributed tracing. Isso permite que você veja como a atividade do seu aplicativo móvel se conecta aos serviços relacionados.

## Requisitos [#requirements]

Para usar distributed tracing, você precisa de pelo menos a versão 6.0.0 do agente Android. Recomendamos que você use o agente mais recente.

## Como configurar distributed tracing [#setup]

O distributed tracing está ativado por padrão — você não precisa fazer nada para ativá-lo. Os cabeçalhos de distributed tracing são enviados em todos os requests autoinstrumentados, independentemente de outras configurações.

Se você preferir desativá-lo, consulte [Desativar o distributed tracing](#disable) abaixo.

Para ver o trace correlacionado com a atividade de rede do seu aplicativo no New Relic (o evento `MobileRequest` ou `MobileRequestError` relatado), você precisa ter o [AnalyticsEvents](/docs/mobile-monitoring/new-relic-mobile/mobile-sdk/configure-settings/#android-analytics-settings) ativado — isso está ativado por padrão e é um pré-requisito para enviar qualquer um dos eventos de análise do seu aplicativo, não algo específico do distributed tracing.

## Cabeçalhos de distributed tracing [#headers]

A partir da versão 7.8.3 do agente Android, o agente adiciona apenas os cabeçalhos do [W3C Trace Context](/docs/distributed-tracing/concepts/how-new-relic-distributed-tracing-works/#headers), `traceparent` e `tracestate`, aos requests de rede de saída. Ele não envia mais o cabeçalho proprietário `newrelic`. As versões anteriores do agente enviam todos os três cabeçalhos.

Os agentes New Relic APM que suportam o W3C Trace Context usam esses cabeçalhos para continuar o trace, para que os requests do seu aplicativo permaneçam conectados aos serviços de backend que eles chamam. O W3C Trace Context é suportado nestas versões do agente APM e superiores:

## Quais requests recebem distributed tracing automaticamente [#automatic-instrumentation]

O plug-in Gradle do agente Android instrumenta o bytecode do seu aplicativo no momento da compilação, portanto, os cabeçalhos de distributed tracing são adicionados automaticamente aos requests feitos por meio de:

* `OkHttp` (versões 2 e 3)
* Apache `HttpClient`
* `HttpURLConnection`
* Retrofit

Como essa instrumentação entrelaça os locais de chamada dessas bibliotecas diretamente, o código que as envolve — incluindo corrotinas do Kotlin e funções de suspensão — também deve ser coberto, já que os locais de chamada subjacentes são entrelaçados independentemente do que os chama.

O agente não adiciona automaticamente os cabeçalhos de distributed tracing a:

* Volley. Não há nenhum suporte ao Volley no agente, portanto, os requests do Volley precisam de [propagação manual](#manual) se você desejar realizar o trace deles.
* `WebView`. A instrumentação `WebView` do agente abrange o tempo de carregamento da página, não os cabeçalhos de request de rede, portanto, os requests feitos a partir de conteúdo da web carregado em um `WebView` não recebem trace automaticamente.
* Qualquer outra biblioteca de rede de terceiros ou transporte personalizado que não seja roteado por meio das bibliotecas listadas acima.

Para qualquer um desses, use a propagação manual.

## Desativar o distributed tracing [#disable]

```java
NewRelic.disableFeature(FeatureFlag.DistributedTracing)
```

## Habilitar rastreamento infinito [#infinite-tracing]

Se seus aplicativos móveis tiverem alguns serviços downstream que usam nosso tail-based distributed tracing chamado [Infinite Tracing](/docs/distributed-tracing/infinite-tracing/introduction-infinite-tracing), você deverá ativar esse recurso para seus aplicativos móveis. Isso garante que seu intervalo raiz (o aplicativo móvel inicial) seja incluído no restante dos intervalos rastreados pelo Infinite Tracing.

Para configurar isso, consulte as [etapas do Rastreamento Infinito](/docs/distributed-tracing/infinite-tracing/set-trace-observer) para criar um observador de rastreamento e selecionar quais aplicativos móveis (fontes de dados) devem relatar períodos.

## Encontre dados [#find-data]

Os spans móveis aparecem em qualquer [interface distributed tracing do New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one/) onde esses spans fazem parte de um trace.

Aqui estão algumas dicas para encontrar e consultar dados:

* Você pode encontrar rastreamento originado pelo usuário final em qualquer [interface distributed tracing do New Relic](/docs/understand-dependencies/distributed-tracing/ui-data/additional-distributed-tracing-features-new-relic-one).

* Na interface distributed tracing, os intervalos do usuário final são indicados com o<img title="New Relic distributed tracing mobile span icon" alt="New Relic distributed tracing mobile span icon" src="/images/mobile_icon_icon.webp" style={{height: "30px", width: "30px"}} />ícone.

* Para ver o atributo de um span, selecione [um span na interface](/docs/apm/distributed-tracing/ui-data/understand-use-distributed-tracing-data#span-details).

* Os spans são relatados como [dados de span](/attribute-dictionary/?event=Span) e podem ser [consultados no New Relic](/docs/using-new-relic/data/understand-data/query-new-relic-data).

* Dicas de consulta:

  * Consulta por nome, definindo `mobileApp.name` como o nome do aplicativo móvel.
  * Consulta para rastreamento contendo pelo menos um intervalo de aplicativo móvel com `mobileApp.name is not null`.
  * Consulta para rastreamento contendo pelo menos um aplicativo backend com `appName is not null`.
  * Consulta para rastreamento contendo períodos móveis e backend , combinando as duas condições anteriores.

Por exemplo, para encontrar spans de dispositivos móveis para um aplicativo específico:

```sql
SELECT count(*) FROM Span WHERE mobileApp.name = 'YOUR_APP_NAME' SINCE 1 day ago
```

Para encontrar traces que conectam um span de dispositivo móvel a um span de APM do backend:

```sql
SELECT * FROM Span WHERE mobileApp.name IS NOT NULL AND appName IS NOT NULL SINCE 1 day ago
```

## Resolução de problemas [#troubleshooting]

Se você não visualizar os spans mobile onde os espera, verifique estas possíveis causas:

* **O distributed tracing está desativado.** Confirme se você não chamou `disableFeature` com `FeatureFlag.DistributedTracing`. Consulte [Como configurar o distributed tracing](#setup).
* **O AnalyticsEvents está desativado.** Os cabeçalhos ainda são enviados, mas o evento `MobileRequest`/`MobileRequestError` relacionado não será enviado. Consulte [Como configurar o distributed tracing](#setup).
* **O request não é autoinstrumentado.** Requests feitos por meio do Volley, um `WebView`, ou qualquer biblioteca diferente de `OkHttp`, Apache `HttpClient`, `HttpURLConnection` ou Retrofit precisam de [propagação manual](#manual). Consulte [Quais requests recebem distributed tracing automaticamente](#automatic-instrumentation).
* **O agente APM do backend é muito antigo.** Se o agente APM do serviço receptor ainda não oferecer suporte ao W3C Trace Context, ele iniciará um novo trace em vez de vincular ao do seu aplicativo. Verifique as [versões mínimas do agente APM](#headers).
* **Um proxy ou gateway remove os cabeçalhos.** Qualquer componente entre o seu aplicativo e o backend precisa repassar `traceparent` e `tracestate` sem modificações.
* **`tracestate` é descartado porque a chave da conta confiável não corresponde.** Se um serviço de backend pertencer a uma conta da New Relic diferente da conta do seu aplicativo mobile, confirme se a conta está na mesma relação de confiança, ou a entrada `tracestate` poderá ser ignorada.

Para problemas mais amplos de distributed tracing, consulte a [resolução de problemas](/docs/apm/distributed-tracing/troubleshooting/troubleshooting-missing-trace-data).
