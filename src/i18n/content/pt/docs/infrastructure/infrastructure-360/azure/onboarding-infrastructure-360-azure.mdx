## Pré-requisitos [#prerequisites]

Antes de habilitar [<DNT>Infrastructure 360</DNT>](/docs/infrastructure/infrastructure-360/introduction-infrastructure-360) para <DNT>Azure</DNT>, certifique-se de ter:

* Uma conta <DNT>Azure</DNT> com um ID de assinatura.
* Um registro de aplicativo <DNT>Azure</DNT> com a função de Leitor de Monitoramento.
* Uma conta New Relic inscrita no preview do <DNT>Infrastructure 360</DNT>.
* Permissões para gerenciar integrações na nuvem no New Relic.

Para se inscrever no preview, acesse <DNT>**one.newrelic.com &gt; Administration &gt; Preview &amp; Trials**</DNT> e inscreva-se em <DNT>**Infrastructure 360**</DNT>.

Existem três maneiras de habilitar <DNT>Infrastructure 360</DNT> para <DNT>Azure</DNT>:

## Habilitar durante o onboarding do Azure [#onboarding-enable]

Se você estiver conectando <DNT>Azure</DNT> ao New Relic pela primeira vez, siga estas etapas:

1. Navegue até <DNT>**Infrastructure &gt; Azure**</DNT>.
2. Selecione uma conta e clique em <DNT>**Set up integration**</DNT>.
3. Siga os prompts para criar o registro do seu aplicativo <DNT>Azure</DNT>. Para obter instruções detalhadas de configuração, consulte [Conectar integrações <DNT>Azure</DNT> ](/docs/infrastructure/microsoft-azure-integrations/get-started/activate-azure-integrations).
4. Durante a configuração da integração, habilite a opção <DNT>**Infrastructure 360**</DNT> no prompt.
5. Configure a frequência de verificação. Por padrão, o <DNT>Infrastructure 360</DNT> faz verificações três vezes por dia. Para alterar isso, consulte [Ajustar a frequência de verificação](#adjust-frequency).

## Habilitar para uma integração do Azure existente [#existing-enable]

Se você já possui <DNT>Azure</DNT> integrado ao New Relic, siga estas etapas:

1. Vá para <DNT>**Infrastructure &gt; Azure**</DNT> e clique em <DNT>**Manage Infrastructure 360**</DNT>.
2. Na lista de contas, encontre sua assinatura <DNT>Azure</DNT> e clique em <DNT>**Install**</DNT> (no nível da conta do provedor).
3. A frequência de varredura deve ser configurada conforme descrito acima.
4. Clique em <DNT>**Save**</DNT> para habilitar <DNT>Infrastructure 360</DNT> para sua conta <DNT>Azure</DNT>.

## Habilitar a partir da página Infraestrutura 360 [#landing-page-enable]

Para habilitar <DNT>Infrastructure 360</DNT> a partir desta página:

1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Infrastructure &gt; Infrastructure 360**</DNT>.
2. Ative a funcionalidade para suas contas de provedor <DNT>Azure</DNT> (e <DNT>AWS</DNT>) nesta conta da New Relic.

Se esta página estiver em branco (você ainda não habilitou <DNT>Infrastructure 360</DNT> para nenhum provedor), clique em <DNT>**Setup Infrastructure 360**</DNT> e, em seguida, habilite a funcionalidade.

## Habilitar via Terraform [#terraform-enable]

Você também pode habilitar <DNT>Infrastructure 360</DNT> para <DNT>Azure</DNT> por meio de <DNT>Terraform</DNT> em vez da interface do New Relic. Este é um guia passo a passo para habilitar a descoberta automática para integrações <DNT>Azure</DNT> usando <DNT>Terraform</DNT>.

### Pré-requisitos [#terraform-prerequisites]

Antes de começar, certifique-se de ter o seguinte:

* **<DNT>Terraform</DNT> instalado**: <DNT>Terraform</DNT> instalado na sua máquina local.
* **ID da conta do New Relic**: o ID da sua conta do New Relic (`newrelic_account_id`).
* **Chave de API de usuário do New Relic**: uma chave de usuário para autenticação no New Relic (`newrelic_api_key`).
* **ID da conta de provedor vinculada**: o ID da conta <DNT>Azure</DNT> conforme reconhecido pela New Relic (`provider_account_id`). Isso geralmente é encontrado na interface da New Relic em <DNT>**Infrastructure &gt; Azure**</DNT>.
* **Região**: sua região de dados do New Relic (EUA ou UE).

<Steps>
<Step>
### Configure seu espaço de trabalho [#setup-workspace]

Crie uma pasta local para a sua configuração do <DNT>Terraform</DNT>:

1. Abra o seu terminal ou prompt de comando.

2. Crie uma nova pasta para o seu projeto:

   ```bash
   mkdir terraform-integrate
   cd terraform-integrate
   ```
</Step>

<Step>
### Crie arquivos de configuração [#create-config-files]

Crie os três arquivos a seguir dentro da sua pasta `terraform-integrate`. Você pode usar qualquer editor de texto.

#### providers.tf

Este arquivo informa ao <DNT>Terraform</DNT> quais plug-ins baixar.

```hcl
terraform {
  required_providers {
    newrelic = {
      source = "newrelic/newrelic"
    }
  }
}
```

#### variables.tf

Este arquivo define as entradas necessárias para executar o script.

```hcl
variable "provider_account_id" {
  description = "The Azure Subscription ID Equivalent in Newrelic (Linked Account ID)."
  type        = number
}

variable "new_relic_region" {
  description = "The New Relic region (e.g., 'US', 'EU', or 'JP')."
  type        = string
  default     = "US"
}

variable "newrelic_account_id" {
  description = "The New Relic account ID."
  type        = number
}

variable "newrelic_api_key" {
  description = "The New Relic API key."
  type        = string
}
```

#### main.tf

Este é o script principal que habilita o recurso de autodescoberta.

```hcl
provider "newrelic" {
  account_id = var.newrelic_account_id
  region     = var.new_relic_region
  api_key    = var.newrelic_api_key
}

resource "newrelic_cloud_azure_integrations" "auto_discovery_integrations" {
  linked_account_id = var.provider_account_id

  # This block enables auto-discovery for the account
  auto_discovery {}
}
```
</Step>

<Step>
### Execute o Terraform [#run-terraform]

Agora que seus arquivos estão prontos, execute estes comandos no seu terminal a partir da pasta `terraform-integrate`.

1. **Inicializar**: baixa os plug-ins necessários do provedor do New Relic.

   ```bash
   terraform init
   ```

2. **Plan**: verifica a configuração e mostra o que acontecerá. <DNT>Terraform</DNT> exibe um prompt para você inserir seus IDs e chaves aqui.

   ```bash
   terraform plan
   ```

   Insira os valores quando receber um prompt para `newrelic_account_id`, `newrelic_api_key` e as outras variáveis.

3. **Apply**: executa o plano e habilita a integração.

   ```bash
   terraform apply
   ```

   Digite `yes` quando solicitado a confirmar.
</Step>
</Steps>

Para mais informações, consulte a [documentação do provedor <DNT>Terraform</DNT> da New Relic](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/guides/cloud_integrations_guide#azure).

## Use a infraestrutura 360 [#using-infrastructure-360]

Uma vez ativado, o <DNT>Infrastructure 360</DNT> permite que você verifique os relacionamentos entre todas as suas entidades <DNT>Azure</DNT>, incluindo infraestrutura, APM e bancos de dados.

<Callout title="Observação">
<DNT>Infrastructure 360</DNT> oferece suporte a relacionamentos de entidade por meio de agentes nativos do New Relic APM (<DNT>Java</DNT>, <DNT>.NET</DNT>, <DNT>Python</DNT>) e <DNT>OpenTelemetry</DNT> (<DNT>.NET</DNT>).

Para clusters <DNT>Azure Kubernetes Service</DNT> (<DNT>AKS</DNT>) especificamente, conectar o seu aplicativo ao seu cluster <DNT>AKS</DNT> exige o agente <DNT>Kubernetes</DNT> do New Relic ou <DNT>OpenTelemetry</DNT>. <DNT>Infrastructure 360</DNT> não estabelece essa conexão por conta própria, mas, assim que ela existe, completa a cadeia por meio do mapeamento da relação do seu aplicativo através do cluster <DNT>AKS</DNT> para a outra infraestrutura <DNT>Azure</DNT> da qual ele depende.
</Callout>

### Visualizar entidades e relacionamentos descobertos [#view-entities]

Para visualizar as entidades descobertas e seus relacionamentos:

1. Acesse <DNT>**All entities**</DNT> e filtre por `collector.name = auto discovery`.

2. Selecione qualquer entidade <DNT>Azure</DNT> para ver seu mapa de infraestrutura, que mostra os relacionamentos entre:

   * <DNT>Azure</DNT> entidades (máquinas virtuais, bancos de dados, contas de armazenamento).
   * Entidades do APM (aplicativos, serviços).
   * Conexões entre plataformas (recursos <DNT>Azure</DNT> conectados a serviços de APM).

### Relacionamentos entre assinaturas [#cross-subscription]

Se um recurso descoberto se conectar a um recurso em uma assinatura <DNT>Azure</DNT> diferente, <DNT>Infrastructure 360</DNT> resolve o relacionamento automaticamente:

* Se a assinatura de destino também estiver integrada com <DNT>Infrastructure 360</DNT>, o mapa mostrará a entidade de destino real e seus detalhes.
* Se você não integrou ou monitorou a assinatura de destino, o mapa mostra uma entidade desconhecida ou não instrumentada em seu lugar — a conexão ainda é visível, mas os detalhes da entidade não estão disponíveis.

### Correlacionar alterações de configuração com alertas [#correlate-config-changes]

<DNT>Infrastructure 360</DNT> rastreia as alterações de configuração nos seus recursos do <DNT>Azure</DNT> para que você possa identificar rapidamente se uma alteração recente causou um alerta ou incidente, em vez de investigar os dados de infraestrutura e do aplicativo separadamente.

1. Vá para <DNT>**All capabilities**</DNT> e selecione <DNT>**Azure Services**</DNT>.
2. Selecione qualquer entidade da lista e clique em <DNT>**Configuration explorer**</DNT> para ver suas configurações, tags e propriedades atuais.
3. Compare o timestamp na linha do tempo de alterações de configuração com seus alertas ou incidentes. Uma alteração de configuração quase ao mesmo tempo que um alerta é um forte sinal de causa raiz, permitindo que você correlacione as alterações de configuração com seus alertas e incidentes.

## Gerenciar configurações da infraestrutura 360 [#manage-settings]

### Ajustar frequência de verificação [#adjust-frequency]

Você pode personalizar a frequência com que o <DNT>Infrastructure 360</DNT> verifica seu ambiente <DNT>Azure</DNT>:

1. Vá para <DNT>**Infrastructure &gt; Azure**</DNT> e clique em <DNT>**Manage Infrastructure 360**</DNT>.
2. Encontre sua conta <DNT>Azure</DNT> e clique em <DNT>**Edit**</DNT>.
3. Selecione a frequência de verificação de sua preferência no menu dropdown.
4. Clique em <DNT>**Save**</DNT> para aplicar as alterações.

Considere aumentar a frequência de varredura se você fizer alterações frequentes no seu ambiente <DNT>Azure</DNT>, ou diminuí-la se a sua infraestrutura for estável e você quiser reduzir as chamadas de API.

### Desativar infraestrutura 360 [#disable]

<Callout variant="important">
Quando você desativa <DNT>Infrastructure 360</DNT>, você perde acesso a:

* Entidades descobertas automaticamente e suas configurações.
* Mapeamento de relacionamento entre recursos <DNT>Azure</DNT> e serviços de APM.
* Atualizações de topologia de infraestrutura em tempo real.
</Callout>

Se você reativar <DNT>Infrastructure 360</DNT> posteriormente, ele recria quaisquer entidades e relacionamentos que não existem mais, durante sua próxima verificação agendada.

Para desabilitar <DNT>Infrastructure 360</DNT>, siga estas etapas:

1. Vá para <DNT>**Infrastructure &gt; Azure**</DNT> e clique em <DNT>**Manage Infrastructure 360**</DNT>.
2. Encontre a conta onde você deseja desativar o <DNT>Infrastructure 360</DNT>.
3. Clique em <DNT>**Edit**</DNT> e desative o botão de alternância de verificação.
4. Clique em <DNT>**Save**</DNT> para confirmar a alteração.
