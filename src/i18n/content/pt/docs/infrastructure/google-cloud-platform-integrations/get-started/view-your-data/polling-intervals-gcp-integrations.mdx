A integração do GCP do New Relic consulta os serviços do GCP de acordo com um intervalo de sondagem, que varia dependendo [da integração](#manage-polling). O New Relic aplica o intervalo de sondagem a cada entidade do GCP.

## Intervalos de sondagem por método de conexão [#polling]

O New Relic consulta a API de monitoramento de nuvem do GCP regularmente para coletar as métricas. A frequência com que isso ocorre depende do método de conexão.

  Os intervalos de sondagem de 1 minuto para integrações do WIF estão em versão prévia limitada e disponíveis apenas para serviços selecionados. Serviços aos quais o WIF oferece suporte atualmente: Managed Service for Apache Kafka, Cloud Dataflow, Cloud Dataproc, Cloud Spanner, Google Kubernetes Engine (GKE), BigQuery, AlloyDB for PostgreSQL, Cloud Load Balancing e Cloud Pub/Sub. Para solicitar acesso, entre em contato com o [suporte da New Relic](https://support.newrelic.com/).
</Callout>

## Quando os dados aparecem [#when-data-appears]

Após conectar um projeto do GCP pela primeira vez, espera-se que os dados comecem a aparecer dentro de 2–5 minutos. As entidades podem levar alguns minutos a mais para aparecer.

Para a coleta contínua, a atualização dos dados depende de dois fatores:

* **Disponibilidade da métrica do GCP**: o monitoramento de nuvem do GCP disponibiliza algumas métricas apenas após um atraso de até alguns minutos após a amostragem. Essa latência se aplica independentemente do intervalo de sondagem — se configurar uma sondagem de 1 minuto, os dados para essas métricas ainda poderão aparecer 2–3 minutos após a amostragem.
* **Coleta e processamento do New Relic**: após a consulta do New Relic ao GCP no intervalo de sondagem configurado, os dados normalmente levam de 1–2 minutos adicionais para aparecer no New Relic.
