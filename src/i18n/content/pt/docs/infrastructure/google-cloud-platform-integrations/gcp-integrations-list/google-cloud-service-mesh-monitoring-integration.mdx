[A integração da New Relic](/docs/infrastructure/introduction-infra-monitoring) com o [Google Cloud Platform (GCP)](https://cloud.google.com/) inclui uma integração para reportar dados [Google Cloud Service Mesh](https://cloud.google.com/service-mesh/docs) (Istio) para New Relic. Este documento explica como ativar a integração do GCP Cloud Service Mesh e descreve os dados reportados.

## Recurso

O Cloud Service Mesh (malha de serviços na nuvem) é a malha de serviços gerenciada do Google Cloud, desenvolvida no Istio. A integração do Cloud Service Mesh (malha de serviços na nuvem) do New Relic coleta a telemetria do serviço Istio emitida pelo seu workload em malha: contagens de requests de entrada e saída, tamanhos de requests e respostas e distribuições de latência do lado do servidor e do cliente.

Esta integração tem como escopo os workloads do Cloud Run inscritos no Cloud Service Mesh. A telemetria do Istio dos workloads de sidecar do GKE (o recurso monitorado `istio_canonical_service`) não é coletada por esta integração.

## Ativar integração [#activate]

<Callout variant="important">
  Esta integração está disponível apenas ao conectar o projeto do GCP com o Workload Identity Federation. Não está disponível para conexões de conta de serviço ou de conta de usuário.
</Callout>

Para habilitar a integração, siga os procedimentos padrão para [conectar seu serviço GCP ao New Relic](/docs/connect-google-cloud-platform-services-infrastructure) com a Workload Identity Federation.

## Frequência de votação [#polling]

As integrações do New Relic consultam os serviços do GCP de acordo com um intervalo de sondagem que varia por integração. A frequência de sondagem para a malha de serviços na nuvem do Google Cloud é de 5 minutos. A resolução é 1 ponto de dados a cada minuto.

## Workload Identity Federation [#wif]

### Encontre e use dados [#find-data-wif]

Todas as métricas do Cloud Service Mesh disponíveis no monitoramento de nuvem do GCP são coletadas como métricas dimensionais no tipo de evento `Metric`.

Esta integração não cria entidades no explorador de entidades do New Relic. Realize a consulta das respectivas métricas diretamente no tipo de evento `Metric`, por exemplo:

```sql
FROM Metric SELECT count(*) WHERE metricName LIKE 'gcp.istio.io.%' FACET metricName
```

As métricas carregam os rótulos de recursos da revisão subjacente do Cloud Run, para que seja possível facetar por nome do serviço, nome da revisão e local sem uma entidade.

As métricas de distribuição acima (`request_bytes`, `response_bytes`, `response_latencies`, `roundtrip_latencies`) também estão disponíveis como métricas de percentil `.p50`, `.p95` e `.p99`. Por exemplo, `gcp.istio.io.service.server.response_latencies.p99`.

Para mais informações sobre a telemetria do serviço Istio, consulte a [documentação de observabilidade do Google Cloud Service Mesh](https://cloud.google.com/service-mesh/docs/observability).
