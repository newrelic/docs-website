A integração do ECS da New Relic relata e exibe dados de desempenho do seu ambiente Amazon ECS.

## Visão geral da instalação [#overview]

Antes de [instalar](#install-options), pode ser útil entender em alto nível como nosso agente de infraestrutura (`newrelic-infra`) é implantado para estes dois tipos de lançamento:

* <DNT>**EC2 and EXTERNAL (ECS Anywhere) launch type:**</DNT> A estratégia de agendamento de daemon implanta nosso agente em um cluster ECS como um serviço ([explicado aqui na documentação da AWS](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/scheduling_tasks.html)). Isso instala o agente em todas as instâncias do EC2 do cluster e monitora o ECS e o contêiner Docker.

* <DNT>**AWS Fargate launch type:**</DNT> Em cada tarefa a ser monitorada, nosso agente é implantado como um sidecar. Opcionalmente, é possível [saber mais sobre como a AWS define um sidecar](https://aws.github.io/copilot-cli/docs/developing/sidecars/).

## Opções de instalação [#install-options]

Escolha a instalação desejada:

* [Instalar usando AWS CloudFormation](#cloud-formation-install)
* [Instalar usando script automático](#auto-script-install)
* [Instale manualmente](#manual-install)

## Instalar usando CloudFormation [#cloud-formation-install]

Para ajudar na instalação usando o AWS CloudFormation, são fornecidos alguns modelos do CloudFormation que instalam a integração do ECS na conta da AWS para os tipos de lançamento EC2, EXTERNO (ECS Anywhere) e AWS Fargate.

Para instalar usando CloudFormation:

1. Para registrar a tarefa de integração do ECS, é necessário implantar [esta stack](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/task/master.yaml&stackName=NewRelicECSIntegration). Deve-se garantir a implantação da stack em uma ou mais das regiões desejadas. Esta stack cria os seguintes recursos:

   * Um segredo que armazena a New Relic <InlinePopover type="licenseKey" />.
   * Uma política para acessar a chave de licença.
   * Uma função de instância a ser usada como uma tarefa ECS `ExecutionRole`, com acesso à chave de licença.
   * Um registro da tarefa de integração do ECS da New Relic Infrastructure, para o tipo de lançamento EC2 e Externo (ECS Anywhere).

2. Siga as instruções adicionais para o seu tipo de lançamento:

   <CollapserGroup>
     <Collapser id="ec2-cloudformation" title="Tipo de lançamento EC2">
       Para criar um serviço que execute a tarefa em cada instância do contêiner EC2, implante [esta stack](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/service.yaml&NewRelicInfraTaskVersion=1).

       Selecione o tipo de lançamento do EC2. Em seguida, um serviço denominado `newrelic-infra` será criado no cluster.
     </Collapser>

     <Collapser id="external-cloudformation" title="Tipo de lançamento externo (ECS Anywhere)">
       Para criar um serviço que execute a tarefa em cada instância do contêiner externo, implante [esta stack](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://nr-downloads-main.s3.amazonaws.com/infrastructure_agent/integrations/ecs/cloudformation/service.yaml&NewRelicInfraTaskVersion=1).

       Selecione o tipo de lançamento EXTERNO. Em seguida, um serviço denominado `newrelic-infra-external` será criado no cluster.
     </Collapser>

     <Collapser id="fargate-cloudformation" title="Tipo de lançamento AWS Fargate">
       1. Baixe o exemplo de definição de tarefa com o contêiner sidecar a ser implantado:

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
          ```

          <Callout variant="tip">
            Para Graviton, substitua `"cpuArchitecture": "X86_64"` por `"cpuArchitecture": "ARM64"`.
          </Callout>

       2. Adicione o contêiner `newrelic-infra` nesta definição de tarefa como um arquivo secundário às definições de tarefa que você deseja monitor. Nesta tarefa de exemplo, o contêiner do seu aplicativo substitui o espaço reservado `busybox` contêiner.

       ### Configurar os modos de encaminhamento do agente de infraestrutura para o Fargate [#fargate-forward-modes]

       Ao implantar o agente de infraestrutura da New Relic como um sidecar em ambientes Fargate, deve-se configurar o modo de encaminhamento do agente. Fargate é um serviço para computar sem servidor onde a AWS gerencia a infraestrutura subjacente, portanto, o agente não deve relatar métricas no nível do host ou tentar criar entidades de host.

       #### Recomendado: NRIA\_IS\_FORWARD\_ONLY

       Para a maioria das implantações do Fargate, definir `NRIA_IS_FORWARD_ONLY` como `true`:

       ```json
       {
         "name": "NRIA_IS_FORWARD_ONLY",
         "value": "true"
       }
       ```

       **Por que isso é recomendado para o Fargate:**

       * **Evita a criação desnecessária de entidade de host:** o agente de infraestrutura não criará uma entidade de host no New Relic, uma vez que o Fargate é serverless e a AWS gerencia os recursos de computar subjacentes.
       * **Evita discrepâncias de faturamento:** as cobranças de medição baseadas em entidade são baseadas no número de entidades monitoradas. A criação incorreta de entidade de host causa faturamento inesperado.
       * **Permite a vinculação adequada de APM a contêiner:** os aplicativos do APM são vinculados corretamente a entidades de contêiner em vez de entidades de host Sintético.
       * **Foca em dados de integração:** o agente coleta e encaminha dados de integração (bancos de dados, servidores web, filas de mensagens, etc.) sem relatar métricas de host.

       #### Alternativa: NRIA\_IS\_SECURE\_FORWARD\_ONLY

       Um modo de encaminhamento alternativo é `NRIA_IS_SECURE_FORWARD_ONLY`. Isso deve ser definido como `true` se houver necessidade de visibilidade da entidade do host na interface da New Relic:

       ```json
       {
         "name": "NRIA_IS_SECURE_FORWARD_ONLY",
         "value": "true"
       }
       ```

       **Diferenças entre os modos de encaminhamento:**

       | Capacidade                                                 | NRIA\_IS\_FORWARD\_ONLY | NRIA\_IS\_SECURE\_FORWARD\_ONLY |
       | :--------------------------------------------------------- | :---------------------- | :------------------------------ |
       | Entidade de host visível no NR1                            | Não                     | Sim                             |
       | Inventário de hosts visível na interface de infraestrutura | Não                     | Sim                             |
       | Inventário de integração                                   | Não                     | Sim                             |
       | Eventos de integração encaminhados                         | Sim                     | Sim                             |
       | Entidades de integração (por exemplo, servidor Redis)      | Não                     | Sim                             |
       | Métricas do host (CPU, memória, disco)                     | Não                     | Não                             |
       | Metadados do contêiner decorados                           | Não                     | Sim                             |
       | Metadados de entidade em eventos de integração             | Não                     | Parcial                         |

       **Quando usar cada modo:**

       * **Use `NRIA_IS_FORWARD_ONLY=true` (recomendado) se:**

         * Deseja-se minimizar a contagem de entidades e o impacto no faturamento
         * É necessário apenas o monitoramento de contêiner e integração
         * Não é necessário visualizar o inventário de hosts na interface do New Relic

       * **Use `NRIA_IS_SECURE_FORWARD_ONLY=true` se:**

         * É necessário ver os metadados do host e as informações de inventário na interface do New Relic
         * Deseja-se que as entidades de integração apareçam na interface de infraestrutura
         * A contagem de entidade não é uma preocupação

       *Exemplo de definição de tarefa com a configuração necessária do Fargate:*

       ```json
       {
         "family": "newrelic-infra-fargate",
         "networkMode": "awsvpc",
         "requiresCompatibilities": ["FARGATE"],
         "cpu": "256",
         "memory": "512",
         "containerDefinitions": [
           {
             "name": "newrelic-infra",
             "image": "newrelic/nri-ecs:latest",
             "essential": false,
             "environment": [
               {
                 "name": "NRIA_IS_FORWARD_ONLY",
                 "value": "true"
               },
               {
                 "name": "NRIA_LICENSE_KEY",
                 "value": "your-license-key"
               },
               {
                 "name": "NRIA_PASSTHROUGH_ENVIRONMENT",
                 "value": "ECS_CONTAINER_METADATA_URI,ECS_CONTAINER_METADATA_URI_V4,FARGATE"
               },
               {
                 "name": "FARGATE",
                 "value": "true"
               }
             ]
           },
           {
             "name": "your-application",
             "image": "your-app-image:latest",
             "essential": true
           }
         ]
       }
       ```

       <Callout variant="important">
         A variável de ambiente `NRIA_IS_FORWARD_ONLY=true` é **obrigatória** para todas as implantações do Fargate. Omitir essa configuração pode resultar em:

         * Criação incorreta de entidade de host
         * Falhas de relacionamento de APM para contêiner
         * Discrepâncias de faturamento devido a contagens inesperadas de entidade

         Se o exemplo de definição de tarefa for baixado, é necessário verificar se esta variável de ambiente está presente e definida como verdadeira.
       </Callout>

       3. Registre a definição de tarefa:

          ```sh
          aws ecs register-task-definition --cli-input-json file://newrelic-infra-ecs-fargate-example-latest.json
          ```

       4. Criar um serviço ou executar uma tarefa usando esta definição de tarefa.
     </Collapser>
   </CollapserGroup>

Quando terminar, consulte [Próximas etapas](#next-steps).

## Instalar com script automático [#auto-script-install]

Uma [opção de instalação](#install-overview) é usar nosso script de instalação. Para usar o script de instalação automática:

1. Baixe o instalador de integração do ECS:

   ```sh
   curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-installer.sh
   ```

2. Adicione permissões de execução ao instalador:

   ```sh
   chmod +x newrelic-infra-ecs-installer.sh
   ```

3. Execute-o com `-h` para ver a documentação e os requisitos:

   ```sh
   ./newrelic-infra-ecs-installer.sh -h
   ```

4. Verifique se o seu perfil da AWS aponta para a mesma região onde o cluster do ECS foi criado:

   ```sh
   aws configure get region
   [output] us-east-1

   aws ecs list-clusters
   [output] YOUR_CLUSTER_ARNS 	
   [output] arn:aws:ecs:us-east-1:YOUR_AWS_ACCOUNT:cluster/YOUR_CLUSTER
   ```

5. Execute o instalador, especificando seu <InlinePopover type="licenseKey" />e o nome do cluster.

   <CollapserGroup>
     <Collapser id="auto-script-ec2" title="Tipo de lançamento EC2">
       ```sh
       ./newrelic-infra-ecs-installer.sh -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY
       ```
     </Collapser>

     <Collapser id="auto-script-external" title="Tipo de lançamento externo (ECS Anywhere)">
       ```sh
       ./newrelic-infra-ecs-installer.sh -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY -e
       ```
     </Collapser>

     <Collapser id="auto-script-fargate" title="Tipo de lançamento AWS Fargate">
       ```sh
       ./newrelic-infra-ecs-installer.sh -f -c YOUR_CLUSTER_NAME -l YOUR_LICENSE_KEY
       ```
     </Collapser>
   </CollapserGroup>

6. Etapas adicionais para o tipo de lançamento Fargate (não para o tipo de lançamento EC2):

   * Baixe o exemplo de definição de tarefa com o contêiner sidecar a ser implantado:

     ```sh
     curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
     ```

     <Callout variant="tip">
       Para Graviton, substitua `"cpuArchitecture": "X86_64"` por `"cpuArchitecture": "ARM64"`.
     </Callout>

     Deve-se notar que é necessário usar a função recém-criada, `NewRelicECSTaskExecutionRole`, como a função de execução da tarefa.

     Esta função inclui as seguintes políticas para todos os tipos de lançamento:

     * `NewRelicSSMLicenseKeyReadAccess` que permite o acesso ao parâmetro SSM com a chave de licença.
     * `AmazonECSTaskExecutionRolePolicy`

   * Adicionar o contêiner que se deseja monitorar como um sidecar.

   <Callout variant="important">
     Ao usar o AWS Fargate, também é necessário garantir que o contêiner sidecar tenha a variável de ambiente `NRIA_IS_FORWARD_ONLY` definida como `true` dentro da definição de tarefa. Consultar as [instruções de configuração do Fargate](#fargate-isforwardonly) em CloudFormation para obter detalhes de configuração e o motivo pelo qual esta configuração é crítica.
   </Callout>

Quando terminar, consulte [Próximas etapas](#next-steps).

## Instalação manual

Uma [opção de instalação](#install-overview) é executar manualmente as etapas que são feitas pelo [script instalador automático](#auto-script-install). Será descrito como isso é feito usando a ferramenta `awscli`:

1. Verifique se o seu perfil da AWS aponta para a mesma região onde o cluster do ECS foi criado:

   ```sh
   aws configure get region
   [output] us-east-1

   aws ecs list-clusters
   [output] YOUR_CLUSTER_ARNS
   [output] arn:aws:ecs:us-east-1:YOUR_AWS_ACCOUNT:cluster/YOUR_CLUSTER
   ```

2. Salve seu <InlinePopover type="licenseKey" />como um parâmetro do Systems Manager (SSM):

   ```sh
   aws ssm put-parameter \
     --name "/newrelic-infra/ecs/license-key" \
     --type SecureString \
     --description 'New Relic license key for ECS monitoring' \
     --value "NEW_RELIC_LICENSE_KEY"
   ```

3. Crie uma política IAM para acessar o parâmetro da chave de licença:

   ```sh
   aws iam create-policy \
     --policy-name "NewRelicSSMLicenseKeyReadAccess" \
     --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["ssm:GetParameters"],"Resource":["ARN_OF_LICENSE_KEY_PARAMETER"]}]}' \
     --description "Provides read access to the New Relic SSM license key parameter"
   ```

4. Crie uma função do IAM para ser usada como função de execução de tarefas:

   ```sh
   aws iam create-role \
     --role-name "NewRelicECSTaskExecutionRole" \
     --assume-role-policy-document '{"Version":"2008-10-17","Statement":[{"Sid":"","Effect":"Allow","Principal":{"Service":"ecs-tasks.amazonaws.com"},"Action":"sts:AssumeRole"}]}' \
     --description "ECS task execution role for New Relic infrastructure"
   ```

5. Anexe as políticas `NewRelicSSMLicenseKeyReadAccess` e `AmazonECSTaskExecutionRolePolicy` à função:

   ```sh
   aws iam attach-role-policy \
     --role-name "NewRelicECSTaskExecutionRole" \
     --policy-arn "POLICY_ARN"
   ```

6. Escolha seu tipo de lançamento para obter mais instruções:

   <CollapserGroup>
     <Collapser id="manual-ec2" title="Tipo de lançamento EC2 e Externo (ECS Anywhere)">
       Etapas adicionais para o tipo de lançamento EC2:

       1. Baixe o arquivo de modelo de definição de tarefa de integração do New Relic ECS:

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-ec2-latest.json
          ```

       2. Substitua a função de execução da tarefa no arquivo de modelo pela função recém-criada:

          ```json
          "executionRoleArn": "NewRelicECSTaskExecutionRole",
          ```

       3. Substitua o atributo `valueFrom` de `secret` pelo nome do parâmetro do Systems Manager:

          ```json
          "secrets": [
            {
              "valueFrom": "/newrelic-infra/ecs/license-key",
              "name": "NRIA_LICENSE_KEY"
            }
          ],
          ```

       4. Registre o arquivo de definição de tarefa:

          ```sh
          aws ecs register-task-definition --cli-input-json file://newrelic-infra-ecs-ec2-latest.json
          ```

       5. Crie um serviço com a estratégia [de agendamento do daemon](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) para a tarefa registrada:

          Para tipo de lançamento EC2:

          ```sh
          aws ecs create-service --cluster "YOUR_CLUSTER_NAME" --service-name "newrelic-infra" --task-definition "newrelic-infra" --scheduling-strategy DAEMON --launch-type EC2
          ```

          Para tipo de lançamento EXTERNO (ECS Anywhere):

          ```sh
          aws ecs create-service --cluster "YOUR_CLUSTER_NAME" --service-name "newrelic-infra-external" --task-definition "newrelic-infra" --scheduling-strategy DAEMON --launch-type EXTERNAL
          ```
     </Collapser>

     <Collapser id="manual-fargate" title="Tipo de lançamento AWS Fargate">
       Etapas adicionais para o tipo de lançamento AWS Fargate:

       1. Baixe o exemplo de definição de tarefa com o contêiner sidecar a ser implantado:

          ```sh
          curl -O https://download.newrelic.com/infrastructure_agent/integrations/ecs/newrelic-infra-ecs-fargate-example-latest.json
          ```

          <Callout variant="tip">
            Para Graviton, substitua `"cpuArchitecture": "X86_64"` por `"cpuArchitecture": "ARM64"`.
          </Callout>

       2. Adicione o contêiner `newrelic-infra` nesta definição de tarefa como um arquivo secundário às definições de tarefa que você deseja monitor. Nesta tarefa de exemplo, o contêiner do seu aplicativo substitui o espaço reservado `busybox` contêiner.

       <Callout variant="important">
         É necessário garantir a configuração da variável de ambiente `NRIA_IS_FORWARD_ONLY` para `true` nas configurações do contêiner sidecar da definição de tarefa editada manualmente. Consultar a [seção CloudFormation Fargate](#fargate-isforwardonly) para obter instruções detalhadas e um exemplo JSON completo.
       </Callout>
     </Collapser>
   </CollapserGroup>

Quando terminar, consulte [Próximas etapas](#next-steps).

## Próximas etapas após a instalação [#next-steps]

* Instale nossa [integração na nuvem do ECS](/docs/integrations/amazon-integrations/aws-integrations-list/aws-ecsecr-monitoring-integration) recomendada, que fornece outros dados do ECS, incluindo informações sobre cluster e serviços.

## Recursos AWS criados [#aws-resources]

Quando você instala a integração do ECS usando valores padrão/recomendados, ela faz o seguinte na AWS:

* Cria o parâmetro `/newrelic-infra/ecs/license-key` do Systems Manager (SSM). Este parâmetro do sistema contém a New Relic <InlinePopover type="licenseKey" />.

* Cria a política IAM `NewRelicSSMLicenseKeyReadAccess`, que permite acesso ao parâmetro SSM com a chave de licença.

* Cria a função do IAM `NewRelicECSTaskExecutionRole` usada como a [função de execução da tarefa](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_execution_IAM_role.html). Esta função inclui as seguintes políticas:

  * `NewRelicSSMLicenseKeyReadAccess` (criado pelo instalador).
  * `AmazonECSTaskExecutionRolePolicy`

* Registra a definição de tarefa `newrelic-infra` do ECS para os tipos de lançamento EC2 e externo (ECS Anywhere).

* Cria o seguinte para o [tipo de lançamento](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/launch_types.html) do EC2:
  * O serviço `newrelic-infra` para a tarefa registrada, usando uma estratégia [de agendamento daemon](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) e tipo de lançamento EC2.

* Cria o seguinte para o [tipo de lançamento](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/launch_types.html) EXTERNAL (ECS Anywhere):
  * O serviço `newrelic-infra-external` para a tarefa registrada, usando uma estratégia [de agendamento daemon](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_services.html) e tipo de lançamento EXTERNO (ECS Anywhere).
