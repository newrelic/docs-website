Para uma integração perfeita da conta da AWS com a New Relic, a [integração via CloudFormation e CloudWatch Metric Streams](/docs/infrastructure/amazon-integrations/aws-integration-for-metrics/via-cloudformation) é a abordagem recomendada. Caso não seja possível usar os modelos do CloudFormation e não se deseje usar o Terraform, este procedimento deve ser seguido para integrar manualmente a partir do console da AWS.

<Callout variant="tip">
  * Se gerenciar várias contas AWS, [conecte cada conta a uma única conta New Relic](/docs/infrastructure/amazon-integrations/manage-aws-data/aws-multi-account).
  * Caso sejam gerenciadas várias regiões nessas contas, um [Kinesis Data Firehose](#create-firehose) separado deve ser criado para cada região.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    Antes de começar a integrar sua conta da AWS com o New Relic, certifique-se de atender aos seguintes pré-requisitos:

    * **Uma [chave de licença do New Relic Ingest e uma chave de usuário](https://one.newrelic.com/api-keys)**: você precisará dessas chaves para conectar seus serviços da AWS à sua conta do New Relic.
    * **[Permissões](https://docs.aws.amazon.com/ARG/latest/userguide/gettingstarted-prereqs-permissions.html)** para implantar novos recursos AWS e **[funções do IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)**: Será necessária esta permissão para a conta AWS.
    * **[Permissões](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions/#infrastructure)** para integração na nuvem: você precisará dessas permissões para sua conta New Relic.
  </Step>

  <Step>
    ## Criar um fluxo de entrega do Kinesis Data Firehose [#create-firehose]

    No console da AWS, os seguintes parâmetros de destino devem ser definidos para o fluxo de entrega:

    * Fonte: <DNT>Direct PUT</DNT> ou outras fontes

    * Destino: New Relic

    * Transformação de dados: <DNT>Disabled</DNT>

    * Conversão de formato de registro: <DNT>Disabled</DNT>

    * Certifique-se de que as seguintes configurações estejam definidas:

      * Configuração do New Relic (configurações de destino):

        * URL do endpoint HTTP:

          * Datacenter dos EUA: `https://aws-api.newrelic.com/cloudwatch-metrics/v1`
          * Datacenter da UE: `https://aws-api.eu01.nr-data.net/cloudwatch-metrics/v1`
          * Datacenter do JP: `https://aws-api.jp.nr-data.net/cloudwatch-metrics/v1`

        * Chave de API: Digite sua<InlinePopover type="licenseKey" />

        * Codificação de conteúdo: `GZIP`

        * Duração da nova tentativa: `60`

        * Condições de buffer do New Relic:

          * Tamanho do buffer: `1 MB`
          * Intervalo de buffer: `60 (seconds)`

      * Modo de backup do S3: <DNT>Failed data only</DNT>

      * Bucket de backup do S3: selecione um bucket ou crie um novo para armazenar métricas que falharam ao serem enviadas.

      * Configurações avançadas:
        * Acesso ao serviço: forneça permissões para a função do IAM:
          * <DNT>Create or update IAM role</DNT>
  </Step>

  <Step>
    ## Criar um CloudWatch Metric Streams [#create-metric-stream]

    1. No console da AWS, deve-se acessar <DNT>**CloudWatch service**</DNT>, selecionar <DNT>**Streams**</DNT> no menu <DNT>**Metrics**</DNT> e clicar em <DNT>**Create metric stream**</DNT>.
    2. Para controlar quais serviços da AWS enviam métricas para a New Relic, devem ser configurados filtros de inclusão e exclusão.
    3. Na lista de fluxos de entrega do Firehose, selecione o fluxo criado e, em seguida, insira um nome significativo para o fluxo de métricas, por exemplo, `newrelic-metric-stream`.
    4. No campo de formato de saída, selecione `Open Telemetry 0.7` ou `Open Telemetry 1.0`. JSON não é suportado.
  </Step>

  <Step>
    ## Conecte a conta da AWS à New Relic [#connect-aws-account]

    1. Na New Relic, vá para [<DNT>**Infrastructure &gt; AWS**</DNT>](https://one.newrelic.com/infra/infrastructure/cloud-aws).

    2. Selecione a conta correta.

    3. Clique em <DNT>**Set up integration**</DNT>.

    4. Em cada tela, preencha os campos que se aplicam a você. Para esta integração, escolha as seguintes opções:

       * <DNT>**Choose Data type(s)**</DNT>: <DNT>Metrics</DNT>
       * <DNT>**Choose a setup method**</DNT>: <DNT>Manually integrate your AWS account</DNT>

    5. Na tela <DNT>**Select services**</DNT>, alterne <DNT>**Show resources not supported by CloudWatch Metric Streams**</DNT> se necessário, selecione os serviços que deseja monitorar e continue.

    6. Na tela <DNT>**Choose data integration type**</DNT>, escolha entre as seguintes opções:

       * **Monitoramento AWS em tempo real (Recomendado)**: Esta opção é para serviços que suportam CloudWatch Metric Streams.
       * **API Polling**: esta opção é para serviços não suportados pelo CloudWatch Metric Streams.

    7. Da página <DNT>**Create role**</DNT> para a página <DNT>**Configure budgets policy**</DNT>, siga as instruções na tela e conclua as etapas no console da AWS.
  </Step>

  <Step>
    ## Valide seus dados [#validate]

    Para confirmar que você está recebendo dados do Metric Streams:

    1. No New Relic, acesse <DNT>**[one.newrelic.com &gt; All capabilities &gt; Infrastructure &gt; AWS](https://one.newrelic.com/infra/infrastructure/cloud-aws)**</DNT>, pesquise a conta AWS conectada e procure por contas **Stream**.
    2. No dashboard de status da conta, confirme se New Relic está recebendo dados métricos, incluindo erros e o número de namespace e métrica ingeridos.
    3. Para explorar métricas específicas, escreva consultas para os conjuntos de métricas que você deseja analisar.

    Pode levar alguns minutos para que New Relic detecte novos recursos e os sintetize como entidade.

    <Callout variant="tip">
      As métricas AWS do CloudWatch para serviços globais, como AWS Billing, estão disponíveis somente na região <DNT>**us-east-1**</DNT>. Certifique-se de que haja um CloudWatch Metric Streams ativo configurado nessa região.
    </Callout>
  </Step>
</Steps>
