Um fluxo é a unidade que você cria no Pathpoint: uma jornada de negócios, dividida em estágios, níveis, etapas e nos sinais que relatam sua integridade. Esta página aborda como criar um fluxo na interface, gerenciá-lo depois de criado e planejar seu design.

## Criar um fluxo [#build-a-flow]

### Crie um fluxo [#create-a-flow]

Para criar um novo fluxo, clique em <DNT>**+ Add a flow**</DNT> no canto superior direito da página <DNT>**Flows**</DNT>. Na caixa de diálogo <DNT>**Create a flow**</DNT>, escolha <DNT>**Blank flow**</DNT> para criar um novo fluxo do zero ou <DNT>**Import a flow**</DNT> para criar um a partir de uma configuração JSON existente.

#### Fluxo em branco [#blank-flow]

A caixa de diálogo <DNT>**Pathpoint flow**</DNT> cria o fluxo na conta selecionada no momento. Preencha os seguintes campos:

* <DNT>**Flow name**</DNT> (obrigatório): o nome exibido no fluxo e na página <DNT>**Flows**</DNT>.
* <DNT>**Category**</DNT> (opcional): uma categoria de negócios para ajudar a organizar seus fluxos, como E-commerce ou Onboarding.
* <DNT>**Description**</DNT> (opcional): uma breve descrição do fluxo, como &quot;Fluxo de compra para aplicativo móvel.&quot;
* <DNT>**Refresh data every**</DNT>: com que frequência o fluxo atualiza seus dados de integridade. Escolha 1, 5, 10, 15 ou 30 minutos. O padrão é 1 minuto.

Clique em <DNT>**Save**</DNT> para criar o fluxo. Isso o abre em modo de rascunho, onde você construirá a estrutura da sua jornada.

#### Importe um fluxo [#create-from-json]

Se você já tiver uma configuração de fluxo como JSON, poderá criar um fluxo a partir dela em vez de criar um manualmente. Isso é útil para mover um fluxo entre contas, restaurar um do controle de versão ou começar a partir de uma configuração que um colega exportou.

Arraste um arquivo JSON para o campo de entrada, clique em <DNT>**Upload JSON**</DNT>, ou cole o JSON diretamente, e edite-o no local se precisar.

Em <DNT>**Select what to import**</DNT>, escolha o quanto da configuração deseja transferir:

* <DNT>**Structure only**</DNT>: importa os estágios, níveis e etapas, sem sinais ou KPIs. Use isso para reutilizar a forma de um fluxo sem herdar seus sinais.
* <DNT>**Everything**</DNT>: importa a estrutura junto com seus sinais e KPIs.

Clique em <DNT>**Save**</DNT> para criar o fluxo.

<Callout title="Observação">
  Se a configuração incluir sinais aos quais você não tem acesso, esses sinais serão adicionados ao fluxo, mas ficarão ocultos para você, e um indicador <DNT>**Missing signals**</DNT> aparecerá na parte superior dos estágios afetados. Um usuário com acesso a esses sinais os vê e pode editar como o fluxo os utiliza.
</Callout>

Para obter o JSON de um fluxo que você já criou, abra-o e selecione <DNT>**View as code**</DNT> no menu <DNT>**...**</DNT>. Consulte [Visualizar como código](/docs/pathpoint/flow-view#view-as-code).

### Adicione e configure estágios [#add-and-configure-stages]

O modo de rascunho é aberto com um estágio, nível e etapa já estruturados. Clique no nome do estágio para renomeá-lo.

Para adicionar um novo estágio, clique no ícone <DNT>**+**</DNT> no cabeçalho de um estágio e selecione <DNT>**Add a stage**</DNT>.

Para adicionar um KPI diretamente a um estágio, clique no ícone <DNT>**+**</DNT> e selecione <DNT>**Add a KPI**</DNT>. Veja [KPIs](/docs/pathpoint/kpis) para mais detalhes.

Para configurar um estágio, clique no ícone de engrenagem no cabeçalho do estágio e selecione <DNT>**Adjust settings**</DNT>. As configurações do estágio incluem:

* <DNT>**Stage link**</DNT> (opcional): adicione um URL para fornecer contexto adicional para o estágio, como um dashboard ou documento.

* <DNT>**Stage shape**</DNT>: defina a forma visual do estágio para refletir seu papel na jornada: Nenhum, Início, Conectar ou Parar.

* <DNT>**Health setup**</DNT>: escolha como a saúde do estágio é determinada:

  * <DNT>**Rollup of all levels**</DNT>: O status do estágio reflete o status mais grave em todos os seus níveis. Use isso quando quiser que o estágio reaja assim que qualquer nível apresentar problemas.
  * <DNT>**Alert policy and conditions**</DNT>: configure políticas de alertas e condições personalizadas para determinar o status de saúde do estágio. Este método permite definir condições específicas que acionam alterações no status de saúde do estágio com base nos estados de alerta. Use isso quando desejar que o estágio se torne crítico com base em um KPI do estágio que viola um limite.

Para excluir um estágio, clique no ícone de engrenagem e selecione <DNT>**Delete**</DNT>.

### Adicione e configure níveis e etapas [#add-and-configure-levels-and-steps]

Para adicionar um nível, clique em <DNT>**+ Add a level**</DNT> na parte inferior de um estágio. Os níveis são numerados automaticamente com base em sua posição no estágio.

Para adicionar uma etapa a um nível, clique no ícone <DNT>**+**</DNT> dentro do nível. Para renomear uma etapa, clique no nome da etapa e digite diretamente.

Para configurar uma etapa, clique no menu <DNT>**...**</DNT> na etapa e selecione <DNT>**Settings**</DNT>. As configurações da etapa incluem:

* <DNT>**Step link**</DNT> (opcional): adicione um URL para fornecer contexto adicional para a etapa, como um dashboard ou documento.

* <DNT>**Status configuration**</DNT>: escolha como a saúde da etapa é determinada:

  * <DNT>**Exclude step from level status**</DNT>: Quando marcada, a etapa ainda exibe sua própria integridade, mas não contribui para agregar a integridade do nível.
  * <DNT>**Rollup the worst status**</DNT>: a integridade da etapa reflete o status mais grave de qualquer sinal. Opcionalmente, ative <DNT>**Apply only when**</DNT> para definir um limite antes que a alteração de status entre em vigor.
  * <DNT>**Rollup the best status**</DNT>: A saúde da etapa reflete o melhor status de qualquer sinal.
  * <DNT>**Included signals**</DNT>: selecione quais sinais são incluídos na determinação do status da etapa. O padrão são todos os sinais. Sinais definidos via consultas não são incluídos se consultas estiverem presentes.

Para adicionar sinais a uma etapa, clique em <DNT>**+ Add signals**</DNT> dentro da etapa. Isso abre a sobreposição <DNT>**Select signals**</DNT>, onde você pode navegar e selecionar os sinais que determinam a integridade da etapa.

#### Selecione os sinais manualmente [#select-signals-manually]

Use a guia <DNT>**Entities**</DNT> ou <DNT>**Alerts**</DNT> dependendo do tipo de sinal que está procurando e, em seguida, navegue ou pesquise os sinais por nome. Marque a caixa ao lado de um sinal para adicioná-lo à etapa. Para remover um sinal, desmarque-o na tabela ou clique no <DNT>**x**</DNT> ao lado dele na lista <DNT>**Selected signals**</DNT>.

#### Use filtros dinâmicos [#use-dynamic-filters]

Em vez de selecionar sinais um por um, você pode usar filtros para definir dinamicamente um conjunto de sinais como destino. Filtros dinâmicos determinam os sinais no escopo cada vez que o fluxo é carregado. Isso é útil quando seu conjunto de sinais pode mudar ao longo do tempo.

Para usar um filtro dinâmico, aplique os critérios de filtro desejados e clique em <DNT>**Add this filter**</DNT>. A definição do filtro é adicionada à lista <DNT>**Selected signals**</DNT> junto com quaisquer sinais que correspondam a ela no momento.

Para remover um filtro dinâmico, clique no <DNT>**x**</DNT> ao lado da definição do filtro na lista <DNT>**Selected signals**</DNT>.

<Callout variant="important">
  Filtros dinâmicos não podem ser editados após a criação. Para alterar um filtro, remova-o e recrie-o.

  Filtros dinâmicos também não podem ter como destino as condições do alerta (`domain = 'AIOPS' AND type = 'CONDITION'`). Para incluir uma condição do alerta em uma etapa, em vez disso, [selecione-a manualmente](#select-signals-manually).
</Callout>

Para excluir uma etapa, clique no menu <DNT>**...**</DNT> e selecione <DNT>**Delete**</DNT>. Para excluir um nível, clique no ícone <DNT>**x**</DNT> ao lado do nível.

### Salvar e editar um fluxo [#save-and-edit-a-flow]

Quando terminar de criar, clique em <DNT>**Save**</DNT> no canto superior direito para salvar suas alterações e sair do modo de rascunho. Para, em vez disso, abandonar suas alterações, clique em <DNT>**Discard changes**</DNT>.

Para voltar a um fluxo salvo, clique em <DNT>**Edit**</DNT> no canto superior direito da visualização do fluxo. Suas alterações permanecem em rascunho até que você as salve.

No modo de rascunho, você pode atualizar os estágios, níveis, etapas e sinais do fluxo usando as mesmas ações descritas em [Adicionar e configurar estágios](#add-and-configure-stages) e [Adicionar e configurar níveis e etapas](#add-and-configure-levels-and-steps) acima.

Para gerenciar o ruído ao editar um fluxo grande, use o botão de alternância <DNT>**Collapse all**</DNT> no canto superior direito para ocultar todos os sinais e mostrar apenas a estrutura do fluxo. Isso facilita o foco em estágios, níveis e etapas sem a distração de sinais individuais.

Quando estiver pronto, clique em <DNT>**Save**</DNT> no canto superior direito para salvar suas alterações e retornar à visualização do Flow.

### Resolver conflitos de edição [#resolve-editing-conflicts]

Mais de uma pessoa pode editar um fluxo ao mesmo tempo. Se outra pessoa salvar enquanto você ainda estiver editando, uma caixa de diálogo <DNT>**You&apos;re editing an older version**</DNT> aparecerá quando você tentar salvar. Informa o nome da pessoa que salvou e oferece duas opções:

<img title="You're editing an older version" alt="A screenshot showing the You're editing an older version dialog with Preview changes and Cancel options." src="/images/pathpoint-editing-conflict.webp" />

* <DNT>**Preview changes**</DNT>: mostra a versão deles para que você possa decidir como prosseguir.
* <DNT>**Cancel**</DNT>: retorna você ao modo de rascunho com suas alterações intactas.

Na visualização, um banner oferece três maneiras de prosseguir:

<img title="Previewing the latest version" alt="A screenshot showing the You're previewing the latest version banner with Exit preview, Overwrite changes, and Accept changes and refresh options." src="/images/pathpoint-preview-conflict.webp" />

* <DNT>**Exit preview**</DNT>: retorna você ao modo de rascunho com suas alterações intactas.
* <DNT>**Overwrite changes**</DNT>: salva a sua versão, substituindo a deles.
* <DNT>**Accept changes and refresh**</DNT>: Descarta suas alterações e carrega a versão deles.

<Callout variant="tip">
  A API aplica a mesma verificação por meio do campo `version` do fluxo. Consulte [Atualizar um fluxo](/docs/apis/nerdgraph/examples/nerdgraph-pathpoint-flows/#update-flow).
</Callout>

## Crie e gerencie fluxos de forma programática [#programmatically]

Além de criar fluxos na interface, você pode criá-los e gerenciá-los como código:

* <DNT>**NerdGraph**</DNT>: criar, ler, atualizar, duplicar e excluir fluxos por meio da API. Consulte [Tutorial do NerdGraph: Criar e gerenciar fluxos do Pathpoint](/docs/apis/nerdgraph/examples/nerdgraph-pathpoint-flows).
* <DNT>**Terraform**</DNT>: gerencie fluxos como infraestrutura como código, para que sua configuração do Pathpoint resida no controle de versão junto com o restante da sua configuração. Consulte o recurso [`newrelic_pathpoint_flow`](https://registry.terraform.io/providers/newrelic/newrelic/latest/docs/resources/pathpoint_flow).

Para obter o código de um fluxo que você já criou, abra-o e selecione <DNT>**View as code**</DNT> no menu <DNT>**...**</DNT>. Isso fornece a configuração do Terraform para o fluxo, junto com as mutações e a consulta do NerdGraph que o criam, atualizam e leem. Consulte [Visualizar como código](/docs/pathpoint/flow-view#view-as-code).

## Duplicar um fluxo [#duplicate-a-flow]

Para duplicar um fluxo, clique no menu <DNT>**...**</DNT> em qualquer linha da página <DNT>**Flows**</DNT> e selecione <DNT>**Duplicate**</DNT>.

Isso abre a caixa de diálogo <DNT>**Duplicate a flow**</DNT>. Você pode atualizar o seguinte antes de salvar:

* <DNT>**Flow name**</DNT> (obrigatório): o padrão é o nome original com “Copy” anexado.
* <DNT>**Select an account**</DNT>: A conta na qual a duplicata será criada. O padrão é a conta atual, portanto, use isso para copiar um fluxo para uma conta diferente.
* <DNT>**Category**</DNT>: Herdado do fluxo original.
* <DNT>**Description**</DNT>: Herdado do fluxo original.
* <DNT>**Refresh data every**</DNT>: Herdado do fluxo original.

Escolha o que duplicar:

* <DNT>**Add Structure (stages, levels, steps)**</DNT>: copia apenas os estágios, níveis e etapas, sem sinais ou KPIs.
* <DNT>**Everything (structure, signals, flow KPIs)**</DNT>: copia a estrutura junto com seus sinais e KPIs.

<Callout variant="important">
  Os KPIs não são copiados se um fluxo for duplicado para uma conta diferente.
</Callout>

Clique em <DNT>**Save**</DNT> para criar a duplicata.

## Gerenciar um fluxo [#manage-a-flow]

Na aba <DNT>**General settings**</DNT>, você pode atualizar as propriedades principais de um fluxo, manter sua equipe conectada a ele e excluí-lo.

### Atualizar configurações do fluxo [#update-flow-settings]

Clique em <DNT>**Edit**</DNT> para atualizar as seguintes propriedades:

* <DNT>**Flow name**</DNT>: O nome exibido no fluxo e na página <DNT>**Flows**</DNT>.
* <DNT>**Category**</DNT>: a categoria de negócios associada ao fluxo.
* <DNT>**Description**</DNT>: Uma breve descrição do fluxo.
* <DNT>**Refresh data every**</DNT>: com que frequência o fluxo atualiza seus dados de integridade.

Esta guia também mostra quem criou o fluxo e quando, e quem o editou por último.

### Contatos [#contacts]

Adicione e-mails ou canais do Slack para manter sua equipe conectada a este fluxo. Clique em <DNT>**Add contact**</DNT> para adicionar um contato.

### Ligações [#links]

Adicione runbooks, repositórios e outros documentos relevantes para fornecer contexto adicional para o fluxo. Clique em <DNT>**Add links**</DNT> para adicionar um link.

### Excluir um fluxo [#delete-a-flow]

Para excluir um fluxo, clique em <DNT>**Delete flow**</DNT> no canto inferior direito de Configurações gerais. Você também pode clicar no menu <DNT>**...**</DNT> em qualquer linha da página <DNT>**Flows**</DNT> e selecionar <DNT>**Delete flow**</DNT>.

<Callout variant="caution">
  A exclusão de um fluxo é permanente e não pode ser desfeita.
</Callout>

## Planejar um fluxo [#plan-a-flow]

Antes de criar um fluxo, é útil planejar seu design, analisar alguns exemplos e pensar sobre quais sinais usar.

<CollapserGroup>
  <Collapser id="design-a-flow" title="Projetar um fluxo">
    Um fluxo modela uma jornada de negócios, e seus estágios representam as fases de nível superior que compõem essa jornada. Antes de criar qualquer coisa, defina qual é o seu processo da empresa e como você o descreveria em sequência. Muitas vezes, ajuda observar como outras organizações de um setor semelhante modelam os seus:

    * Hotel ou hospitalidade
    * Linha de cruzeiro ou companhia aérea
    * Compartilhamento de carona
    * Bens embalados para consumidores
    * Mercado on-line
    * Varejo geral
    * Restaurante de serviço rápido
    * Mineração, construção, petróleo, gás
    * Mídia de streaming digital
    * Mídia de notícias on-line
    * Banco de varejo ou comercial
    * Seguro
    * Gestão de talentos

Os nomes dos estágios geralmente não são técnicos: eles podem ser específicos do setor, mas devem ser compreendidos por qualquer executivo de nível C ou VP na organização.

    Concentre-se primeiro nos estágios pelos quais um usuário ou processo passa.     Concentre-se primeiro em estágios e etapas, depois encontre sinais para eles. Trabalhar de cima para baixo permite pensar em termos do que é importante para o processo da empresa antes de procurar por telemetria de baixo nível, e ajuda a priorizar quais sinais capturar. O Pathpoint permite selecionar qualquer entidade ou condição do alerta como um sinal, o que pode tornar a escolha desafiadora. Recomendamos trabalhar nesta ordem:

    1. Transações de frontend críticas para a jornada ou SLIs que impactam diretamente a receita ou a experiência dos clientes.
    2. Transações de back-end ou SLIs críticos para a jornada que impactam diretamente a receita ou a experiência dos clientes.
    3. Serviços de terceiros essenciais para a jornada, frequentemente obtidos por meio de Sintéticos.
    4. A integridade geral dos serviços mais importantes em cada etapa.
    5. Suporte a infraestrutura e plataformas relevantes para cada etapa, como balanceadores de carga, serviços de contêiner, bancos de dados gerenciados ou sistemas de mensagens.

    Para uma etapa de login, por exemplo, você pode considerar:

    1. A taxa de erros de JavaScript para a ação da página de login.
    2. A latência geral para a ação da página de login.
    3. SLIs relacionados a transações de back-end para autenticação.
    4. Transações de back-end ou serviços relacionados à pesquisa de usuário.
    5. A saúde dos bancos de dados usados para armazenar informações do usuário.
    6. A integridade de um balanceador de carga posicionado à frente do serviço de autenticação.
    7. A saúde de um cache Redis que contém informações de estado do usuário.

    O objetivo é fornecer sinais que sejam razoavelmente independentes uns dos outros, para que, quando ocorrer um evento de alerta, seja possível deduzir o provável problema a partir do que ficar vermelho.

## Permissões de acesso [#access-permissions]

O que você pode fazer no Pathpoint depende de três coisas: seu tipo de usuário, as permissões que sua função lhe concede e as contas às quais você tem acesso.

### Controle de acesso baseado em função [#role-based-access-control]

O Pathpoint tem sua própria capacidade na lista de permissões, em <DNT>**New Relic One**</DNT>. Ele tem escopo de conta, portanto, o acesso do usuário ao Pathpoint se aplica às contas que sua função abrange.

<Callout variant="important">
  Apenas [usuários completos da plataforma](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type) recebem todas as permissões do Pathpoint abaixo. Usuários básicos e core não as recebem, portanto, seu acesso permanece limitado independentemente da função atribuída a eles.
</Callout>
