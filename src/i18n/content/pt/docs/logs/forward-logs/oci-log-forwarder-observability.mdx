Quando você [integra sua conta do OCI](/docs/infrastructure/oci/introduction/#ui-install) para enviar logs para o New Relic, o OCI é sua fonte de dados e o New Relic é o destino. Entre eles, uma função do New Relic (o encaminhador de logs) extrai logs do OCI e os entrega ao New Relic. Se essa função encontrar problemas, por exemplo, um segredo que não consegue ler, um lote que não consegue decodificar ou uma entrega que não consegue concluir, seus logs do OCI param de fluir, mas nada no OCI ou no New Relic informa o motivo.

Para detectar esse tipo de falha antes que custe dados de log a você, o encaminhador de logs pode emitir métricas sobre sua própria integridade. Este documento aborda:

1. [Habilite as métricas de auto-observabilidade](#enable-metrics) na função do encaminhador de logs, para que ela comece a relatar sinais como contagens de invocação, erros de entrega e atraso no pipeline, o tipo de detalhe que informa onde ocorreu uma falha no pipeline.
2. [Importe um dashboard pré-criado](#observability-dashboard) que transforma esses sinais em gráficos, para que você possa identificar uma anomalia rapidamente em vez de examinar dados brutos de métrica.

## Pré-requisitos [#prerequisites]

Antes de começar, certifique-se de ter:

* A função de encaminhador de logs do OCI que você já implantou com o Resource Manager, o Terraform ou a [configuração manual](/docs/infrastructure/oci/introduction/#ui-install)
* O ID da sua conta New Relic, para usar quando você importar o dashboard

## Habilite métricas de auto-observabilidade [#enable-metrics]

Nas [variáveis de configuração](/docs/infrastructure/oci/introduction/#ui-install) da função de logs, o mesmo local onde você define `VAULT_REGION`, `SECRET_OCID` e as outras variáveis de logging, adicione:

* **`FORWARDER_METRICS_TIER`**: Controla quais métricas de auto-observabilidade o encaminhador emite. Consulte os [níveis de métricas](#metric-tiers) para saber o que cada configuração coleta.

Se você configurar a integração com o Resource Manager ou o Terraform, `FORWARDER_METRICS_TIER` é a única variável que você precisa adicionar — `TENANCY_NAME` e `COMPARTMENT_NAME` são resolvidas automaticamente.

Se você configurar a integração manualmente, adicione também:

* **`TENANCY_NAME`**: identifica sua tenancy do OCI pelo nome de exibição, adicionando tags às métricas do encaminhador para que você possa distinguir as tenancies se monitorar mais de uma.
* **`COMPARTMENT_NAME`**: Identifica, pelo nome de exibição, o compartimento onde você implantou a função de logs, adicionando tags às métricas para detalhamentos por compartimento. Se você implantou no compartimento raiz da tenancy, use o mesmo valor que `TENANCY_NAME`.

<Callout variant="important">
O New Relic cobra essas métricas de auto-observabilidade na ingestão, da mesma forma que quaisquer outros dados de métrica.
</Callout>

### Níveis de métrica [#metric-tiers]

`FORWARDER_METRICS_TIER` permite que você equilibre a visibilidade em relação ao custo. Ele aceita um dos seguintes valores:

* **`none`**: Desativa totalmente as métricas de auto-observabilidade.
* **`basic`** (padrão): coleta métricas principais de integridade: contagens de invocação, registros recebidos, entregues e descartados, duração da entrega e atraso no pipeline.
* **`advanced`**: coleta tudo em `basic`, além de métricas de ajuste mais profundas: volumes de bytes, contagens de erros de decodificação e serialização, comportamento de envio em lote, classes de erros de entrega, duração da execução da função, falhas de busca de segredos e taxa de ocorrência no cache do cliente.

## Importe o dashboard de observabilidade [#observability-dashboard]

<Callout variant="important">
Defina `FORWARDER_METRICS_TIER` como `basic` ou `advanced` antes de importar o dashboard. Se você o definir como `none`, o dashboard não terá nenhum dado para mostrar.
</Callout>

Para importar o dashboard:

1. Abra o arquivo [`oci-log-forwarder-metrics-dashboard-template.json`](https://github.com/newrelic/oci-log-integration/blob/develop/docs/oci-log-forwarder-metrics-dashboard-template.json) no repositório `oci-log-integration` do GitHub e copie seu conteúdo.
2. No JSON copiado, localize e substitua todas as ocorrências de `YOUR_ACCOUNT_ID` pelo ID da sua conta da New Relic.
3. Vá para <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Dashboards**</DNT>.
4. No canto superior direito, clique em <DNT>**Import dashboard**</DNT>.
5. Cole o JSON editado.
6. Escolha a conta e as configurações de permissão para o dashboard e, em seguida, clique em <DNT>**Save**</DNT>.

O dashboard é preenchido após a função de logs processar pelo menos uma invocação com métricas ativadas.

## Solucione problemas com o dashboard [#troubleshoot]

Se os logs do OCI pararem de chegar ao New Relic, verifique este dashboard primeiro. Um pico nas falhas de obtenção de segredos ou erros de entrega aponta para um problema no pipeline do encaminhador, como o hub de conectores de serviço, grupos de logs ou função, em vez de no próprio OCI ou New Relic. Depois que você corrigir o problema subjacente, por exemplo, uma política ou permissão do cofre de chaves, os logs são retomados sem reimplantar nada.

Se você não estiver vendo nenhum dado de log e ainda não tiver confirmado que a integração base está funcionando, em vez disso, comece com nossos [procedimentos padrão de resolução de problemas de log](/docs/logs/log-management/troubleshooting/no-log-data-appears-ui/).
