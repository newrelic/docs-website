Obtenha uma correlação perfeita entre o desempenho dos seus aplicativos e do banco de dados com comentários em consultas SQL. Este mecanismo permite que o receiver de banco de dados da Distribuição da New Relic para OpenTelemetry (NRDOT) identifique exatamente qual serviço é responsável por cargas específicas do banco de dados, consultas lentas ou eventos de bloqueio.

<Callout variant="important">
O New Relic vincula o monitoramento do desempenho de aplicativos (APM) do New Relic (New Relic APM) e as entidades de banco de dados comparando o endereço e a porta de conexão do banco de dados do seu aplicativo com o endereço e a porta de conexão do agente de monitoramento de banco de dados. Essa vinculação funciona de forma confiável quando ambos os lados relatam exatamente o mesmo endereço e porta. No entanto, a vinculação automática pode falhar se o seu aplicativo rotear o tráfego por meio de um balanceador de carga ou proxy, ou se os dois componentes usarem formatos de endereço diferentes (como um endereço IP em vez de um nome de domínio).
</Callout>

## Pré-requisitos [#prerequisites]

* Agente Java: versão `9.4.0` ou posterior.
* Agente .NET: versão `10.54.0` ou posterior.

## Habilitar correlação APM-DB [#enable-correlation]

Habilite os comentários de consulta SQL no seu agente APM para que o New Relic possa correlacionar serviços do aplicativo com a atividade do banco de dados.

### Para o agente Java [#enable-correlation-java]

Para habilitar essa correlação, adicione a propriedade `sql_metadata_comments` à seção `transaction_tracer` do seu arquivo de configuração do agente Java (`newrelic.yml`). Para mais informações, consulte a [documentação de configuração do agente Java](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/).

```yaml
transaction_tracer:
  sql_metadata_comments:
    enabled: true
```

### Para o agente .NET [#enable-correlation-dotnet]

Para habilitar essa correlação, adicione a propriedade `sqlMetadataComments` à seção `transactionTracer` do seu arquivo de configuração do agente .NET (`newrelic.config`). Para mais informações, consulte a [documentação de configuração do agente .NET](/docs/apm/agents/net-agent/configuration/net-agent-configuration/).

<CollapserGroup>
<Collapser id="option1" title="Opção 1: via variáveis de ambiente (script)">
Se você estiver usando um script de inicialização ou wrapper para lançar seu executável, defina a variável `NEW_RELIC_TRANSACTION_TRACER_SQL_METADATA_COMMENTS_ENABLED` como `1`.

```powershell
# Add this environment variable alongside your other CoreCLR / New Relic variables
$env:NEW_RELIC_TRANSACTION_TRACER_SQL_METADATA_COMMENTS_ENABLED = "1"
```
</Collapser>

<Collapser id="option2" title="Opção 2: via newrelic.config">
Como alternativa, você pode habilitar isso diretamente no bloco `<transactionTracer>` do seu arquivo `newrelic.config`:

```xml
<transactionTracer enabled="true" sqlMetadataCommentsEnabled="true" />
```
</Collapser>
</CollapserGroup>

## Como funciona [#how-it-works]

Quando sua aplicação envia uma consulta ao banco de dados, o agente APM insere automaticamente um GUID de entidade APM no início do texto SQL como um comentário. Essa prática comum na indústria não afeta a lógica de execução das suas instruções SQL.

1. **Prefixação de comentários**: O agente APM prefixa uma string de comentário ao SQL de saída (por exemplo, `/* nr_service_guid="MTE2MDAzMTl8QVBNfEFQUExJ" */ SELECT * FROM orders...`).
2. **Execução**: O banco de dados executa a consulta normalmente. O comentário é armazenado nos esquemas de desempenho internos do banco de dados (como `sys.dm_exec_requests` ou `v$session`).
3. **Extração**: O receptor do banco de dados busca essas consultas (ativas, lentas ou bloqueantes).
4. **Enriquecimento**: O receptor analisa o comentário, extrai o `nr_service_guid` e o anexa como uma dimensão às suas métricas de banco de dados.

## Benefícios da etiquetagem de serviços [#benefits]

Adicionar metadados de serviço no início oferece visibilidade de alta fidelidade do seu ecossistema de banco de dados:

* **Atribuição em nível de serviço**: Veja instantaneamente qual microsserviço é responsável por um pico na CPU ou memória do banco de dados
* **Análise refinada de consultas lentas**: filtre os logs de consultas lentas por `client_name` para entender se um gargalo no banco de dados está isolado em uma versão específica do aplicativo
* **Resolução de bloqueios e deadlocks**: Identifique rapidamente o &quot;proprietário&quot; de uma consulta bloqueadora para agilizar a solução de problemas entre equipes
