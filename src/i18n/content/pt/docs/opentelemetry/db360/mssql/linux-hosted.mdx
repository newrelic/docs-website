Obtenha insights abrangentes sobre o desempenho do seu SQL Server com o monitoramento de banco de dados, análise de consulta e métricas de integridade do sistema usando o coletor New Relic Distribution of OpenTelemetry (NRDOT).

<Callout variant="tip" title="Instalação guiada">
  Para instalar isso pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga as instruções na tela para configurar a integração. Esta página aborda apenas a instalação manual.
</Callout>

<Callout variant="tip">
  Se você estiver usando o SQL Server em um ambiente Linux RDS, consulte a [Instrumentação Linux para RDS](/docs/opentelemetry/db360/mssql/linux-rds).
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) válida.

    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para sua região.

    * Requisitos do SQL Server:

      * SQL Server 2017 ou posterior.
      * Acesso administrativo ao SQL Server (função `sysadmin` ou equivalente).
      * Conectividade de rede entre o coletor e o SQL Server na porta `1433` ou em uma porta personalizada.
      * O utilitário `sqlcmd` instalado no seu sistema Linux.
  </Step>

  <Step>
    ## Instalar o NRDOT Collector [#setup]

    Baixe e instale o pacote NRDOT para sua distribuição Linux. Substitua `<NRDOT_VERSION>` pela tag de versão mais recente da página [nrdot-collector-releases](https://github.com/newrelic/nrdot-collector-releases/releases).

    <Callout variant="tip">
      Recomendamos instalar o NRDOT Collector no mesmo host que a instância do SQL Server para visualizar métricas de nível de infraestrutura para monitoramento de desempenho de consultas.
    </Callout>

    <CollapserGroup>
      <Collapser id="deb" title="Para Debian/Ubuntu">
        * Para a arquitetura AMD64:

          ```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_amd64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
          ```

        * Para a arquitetura ARM64:

          ```bash
          NRDOT_VERSION=$(curl -s https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest | grep '"tag_name":' | awk -F'"' '{print $4}') && curl -L "https://github.com/newrelic/nrdot-collector-releases/releases/download/${NRDOT_VERSION}/nrdot-collector_${NRDOT_VERSION}_linux_arm64.deb" --output nrdot-collector.deb && sudo dpkg -i nrdot-collector.deb
          ```
      </Collapser>

      <Collapser id="rpm" title="Para RHEL/CentOS">

  <Step>
    ## Criar usuário de monitoramento [#user]

    Execute este script como usuário root para criar o usuário de monitoramento `newrelic` e conceder as permissões necessárias para coletar métricas do SQL Server.

    1. Crie um arquivo de configuração chamado `nr-grant-permission.sql`.

    2. Cole o seguinte script SQL para criar o usuário de monitoramento `newrelic` e substitua `<YOUR_PASSWORD>` pela senha desejada:

       ```sql
       USE [master];
       GO
       CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
       GO
       -- Instance-level permissions
       GRANT VIEW SERVER STATE TO [newrelic];
       GRANT VIEW ANY DEFINITION TO [newrelic];
       GRANT VIEW ANY DATABASE TO [newrelic];
       GO
       -- Grant read access privileges to all user databases
       DECLARE @name SYSNAME;
       DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
       SELECT [name]
       FROM [master].[sys].[databases]
       WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
       AND [state] = 0; -- Only online databases
       OPEN db_cursor;
       FETCH NEXT FROM db_cursor INTO @name;
       WHILE @@FETCH_STATUS = 0
       BEGIN
         BEGIN TRY
           EXEC('USE [' + @name + '];
             IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
             BEGIN
               CREATE USER [newrelic] FOR LOGIN [newrelic];
             END;
             GRANT VIEW DATABASE STATE TO [newrelic];');
         END TRY
         BEGIN CATCH
           PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
         END CATCH
         FETCH NEXT FROM db_cursor INTO @name;
       END
       CLOSE db_cursor;
       DEALLOCATE db_cursor;
       GO
       ```

    3. Execute o script usando `sqlcmd` com qualquer login que tenha permissão para criar logins e conceder permissões no nível do servidor (por exemplo, o login `sa` ou outra conta com a função `sysadmin`). Substitua `<YOUR_ADMIN_USERNAME>` e `<YOUR_ADMIN_PASSWORD>` pelas credenciais desse login:

       ```bash
       sqlcmd -S <YOUR_DB_ENDPOINT> -U <YOUR_ADMIN_USERNAME> -P '<YOUR_ADMIN_PASSWORD>' -C -i nr-grant-permission.sql
       ```

    4. (Opcional) Verifique se o usuário foi criado com sucesso e possui as permissões corretas:

       ```bash
       sqlcmd -S <YOUR_DB_ENDPOINT> -U <YOUR_ADMIN_USERNAME> -P '<YOUR_ADMIN_PASSWORD>' -C -Q "SELECT sp.name AS [User], p.permission_name AS [Permission_Granted] FROM sys.server_permissions p JOIN sys.server_principals sp ON p.grantee_principal_id = sp.principal_id WHERE sp.name = 'newrelic';"
       ```

       **Saída esperada:**

       ```bash
       [output] User Permission_Granted
       [output] -------------------------------------------------------------------------------------
       [output] newrelic CONNECT SQL
       [output] newrelic VIEW ANY DEFINITION
       [output] newrelic VIEW ANY DATABASE
       [output] newrelic VIEW SERVER STATE
       ```

       Esta saída confirma que seu usuário foi criado com sucesso com as permissões necessárias em nível de servidor.

       <Callout variant="tip">
         Para gerenciar informações confidenciais com segurança, como credenciais de banco de dados, armazene-as em ferramentas de [gerenciamento de segredos](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
       </Callout>
  </Step>

    <Callout variant="tip">
      O pipeline `logs` não transporta logs de depuração do coletor ou logs internos do agente. Ele transmite a telemetria de consulta do SQL Server, incluindo texto da consulta, planos de execução e dados de amostra. O receptor `nrsqlserver` captura essa telemetria por meio dos eventos `db.server.query_sample`, `db.server.top_query`, `db.server.query_plan` e `db.server.top_procedure` emitidos como registros de log do OpenTelemetry.

      O evento `db.server.top_procedure` requer o SQL Server 2017 CU3 ou posterior, que introduziu suporte para `sys.dm_exec_procedure_stats.total_spills`. Em versões anteriores, esse evento não emite dados e registra um erro. Outros eventos não são afetados. O acesso a `sys.dm_exec_procedure_stats` requer `VIEW SERVER STATE` (ou `VIEW SERVER PERFORMANCE STATE`, dependendo da versão do SQL Server). Além disso, `VIEW ANY DEFINITION` é necessário para que `OBJECT_NAME` e `OBJECT_SCHEMA_NAME` sejam resolvidos corretamente em todos os bancos de dados de usuário, e `CONNECT SQL` é necessário para configurar as sessões iniciais. O usuário de monitoramento criado em [Criar usuário de monitoramento](#user) inclui todas as 3 permissões.

  <Step>
    ## Atualize a configuração do NRDOT Collector [#update]

    Após configurar seu arquivo YAML com as entradas interativas acima, conclua a configuração do NRDOT Collector:

    1. Edite o arquivo de configuração do serviço:

       ```bash
       sudo nano /etc/nrdot-collector/nrdot-collector.conf
       ```

    2. Atualize o caminho da configuração para apontar para o novo arquivo `mssql-config.yaml`:

       ```bash
       OTELCOL_CONFIG="/etc/nrdot-collector/mssql-config.yaml"
       ```

    3. (Opcional) Valide a configuração do Collector NRDOT:

       ```bash
       sudo /usr/bin/nrdot-collector validate --config=/etc/nrdot-collector/mssql-config.yaml
       ```

       <Callout variant="tip">
         Para correlacionar o desempenho do seu aplicativo com as operações de banco de dados, você pode configurar a identificação de serviço de banco de dados. Para mais informações, consulte o [guia de configuração da identificação de serviço de banco de dados](/docs/opentelemetry/db360/capabilities/db-apm).
       </Callout>
  </Step>

  <Step>
    ## Reiniciar o NRDOT Collector [#restart]

    Após atualizar sua configuração, reinicie o serviço NRDOT Collector:

    ```bash
    sudo systemctl restart nrdot-collector
    ```

    <Callout variant="tip">
      Sempre reinicie o serviço do NRDOT Collector após fazer alterações na configuração para garantir que as novas configurações entrem em vigor.
    </Callout>
  </Step>

  <Step>
    ## Encontre e use seus dados [#find]

    Assim que os dados estiverem sendo coletados, será possível acessar o monitoramento abrangente do banco de dados SQL Server por meio da interface do New Relic.

    Para encontrar sua entidade de banco de dados SQL Server no New Relic:

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**MSSQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.

    3. Selecione seu banco de dados SQL Server na lista de entidades.

       Após configurar o monitoramento do SQL Server com o NRDOT, você pode:

       * [Crie dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar suas métricas de banco de dados
       * [Configure alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para limites críticos de desempenho do banco de dados
       * [Explore seus dados](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) usando os recursos de consulta do New Relic
  </Step>
