Configure o monitoramento do Microsoft SQL Server usando o NRDOT Collector em ambientes auto-hospedados do Windows, incluindo servidores físicos, máquinas virtuais e instalações autônomas do Windows, usando a autenticação de domínio do Windows. Para monitorar em um ambiente Windows RDS, consulte a [instrumentação do Windows RDS](/docs/opentelemetry/db360/mssql/windows-rds-domain).

<Callout variant="tip" title="Instalação guiada">
  Para instalar isso pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga as instruções na tela para configurar a integração. Esta página aborda apenas a instalação manual.
</Callout>

Esta página aborda a autenticação de domínio do Windows. Se o seu ambiente usa um método de autenticação diferente, consulte [Autenticação do SQL Server](/docs/opentelemetry/db360/mssql/windows-hosted-sql) ou [gMSA](/docs/opentelemetry/db360/mssql/windows-hosted-gmsa).

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites-domain]

    Antes de monitorar seu Microsoft SQL Server com NRDOT usando a Autenticação do Windows, certifique-se de que seu ambiente atenda a estes requisitos:

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) válida.

    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para sua região.

    * Requisitos do SQL Server:

      * SQL Server 2017 ou posterior.
      * Acesso administrativo ao SQL Server (função `sysadmin` ou equivalente).
      * Conectividade de rede entre o coletor e o SQL Server na porta `1433` ou em uma porta personalizada.
      * SQL Server Management Studio (SSMS) ou o utilitário `sqlcmd`.

    * Um ambiente de domínio Windows com Active Directory.

    * SQL Server configurado para aceitar a Autenticação do Windows.

    * Uma conta de usuário de domínio com as permissões apropriadas do SQL Server.
  </Step>

  <Step>
    ## Instalar o NRDOT Collector [#setup-domain]

    Baixe e instale o NRDOT Collector usando o PowerShell:

    ```powershell
    [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'
    $NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name
    $WebClient = New-Object System.Net.WebClient
    $WebClient.Headers.Add("User-Agent", "Mozilla/5.0")
    $WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi")
    Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait
    Get-Service nrdot-collector -ErrorAction SilentlyContinue
    ```
  </Step>

  <Step>
    ## Criar usuário de monitoramento [#user-domain]

    Certifique-se de que seu SQL Server esteja configurado para Autenticação do Windows e verifique a conectividade.

    <CollapserGroup>
      <Collapser id="same-host" title="Collector no mesmo host do Windows">
        1. Recupere o seu nome de usuário do Windows:

           ```sql
           SELECT SYSTEM_USER;
           ```

        2. Execute o seguinte comando para verificar se as permissões necessárias foram concedidas ao seu usuário do Windows. Substitua todas as ocorrências de `<ACCOUNT_USERNAME>` pelo nome de usuário recuperado da etapa 1:

           ```sql
           DECLARE @TargetUser SYSNAME = '<ACCOUNT_USERNAME>'; -- <-- Set your Windows user here

           -- 1. Create the checklist of required permissions from your script
           DECLARE @Checklist TABLE (Scope NVARCHAR(50), [Database] SYSNAME, [Permission] NVARCHAR(128));

           INSERT INTO @Checklist VALUES
           ('Server', 'ALL', 'VIEW SERVER STATE'),
           ('Server', 'ALL', 'VIEW ANY DEFINITION'),
           ('Server', 'ALL', 'VIEW ANY DATABASE');

           INSERT INTO @Checklist
           SELECT 'Database Role', [name], 'db_datareader' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0
           UNION ALL
           SELECT 'Database Explicit', [name], 'VIEW DATABASE STATE' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0
           UNION ALL
           SELECT 'Database Explicit', [name], 'VIEW DEFINITION' FROM sys.databases WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution') AND [state] = 0;

           -- 2. Gather existing explicit permissions
           WITH ExplicitPerms AS (
               SELECT 'Server' AS Scope, CAST('ALL' AS NVARCHAR(128)) COLLATE DATABASE_DEFAULT AS [Database], p.permission_name COLLATE DATABASE_DEFAULT AS [Permission]
               FROM sys.server_permissions p JOIN sys.server_principals l ON p.grantee_principal_id = l.principal_id WHERE l.name = @TargetUser
               UNION ALL
               SELECT 'Database Role', d.name COLLATE DATABASE_DEFAULT, r.name COLLATE DATABASE_DEFAULT
               FROM sys.databases d CROSS APPLY (SELECT dp_role.name FROM sys.database_role_members drm JOIN sys.database_principals dp_role ON drm.role_principal_id = dp_role.principal_id JOIN sys.database_principals dp_user ON drm.member_principal_id = dp_user.principal_id JOIN sys.server_principals sp ON dp_user.sid = sp.sid WHERE sp.name = @TargetUser) r WHERE d.state = 0
               UNION ALL
               SELECT 'Database Explicit', d.name COLLATE DATABASE_DEFAULT, p.permission_name COLLATE DATABASE_DEFAULT
               FROM sys.databases d CROSS APPLY (SELECT db_p.permission_name FROM sys.database_permissions db_p JOIN sys.database_principals dp_user ON db_p.grantee_principal_id = dp_user.principal_id JOIN sys.server_principals sp ON dp_user.sid = sp.sid WHERE sp.name = @TargetUser) p WHERE d.state = 0
           )
           -- 3. Output the exact verification matrix
           SELECT
               chk.Scope,
               chk.[Database],
               chk.[Permission] AS [Required Permission],
               CASE
                   WHEN exp.[Permission] IS NOT NULL THEN 'GRANTED'
                   WHEN IS_SRVROLEMEMBER('sysadmin', @TargetUser) = 1 THEN 'PASSED (via SysAdmin Role)'
                   ELSE 'MISSING'
               END AS [Verification Status]
           FROM @Checklist chk
           LEFT JOIN ExplicitPerms exp ON chk.Scope = exp.Scope AND chk.[Database] = exp.[Database] AND chk.[Permission] = exp.[Permission]
           ORDER BY chk.Scope, chk.[Database], chk.[Permission];
           ```

        3. (Opcional) Se você não tiver as permissões necessárias, no seu SSMS ou utilitário `sqlcmd`, execute o seguinte comando para conceder as permissões necessárias à sua conta do Windows. Substitua todas as ocorrências de `<ACCOUNT_USERNAME>` pelo seu nome de usuário do Windows recuperado na etapa 1:

           ```sql
           USE [master];
           GO

           -- 1. Grant Instance-level permissions to your Windows Account
           GRANT VIEW SERVER STATE TO [<ACCOUNT_USERNAME>];
           GRANT VIEW ANY DEFINITION TO [<ACCOUNT_USERNAME>];
           GRANT VIEW ANY DATABASE TO [<ACCOUNT_USERNAME>];
           GO

           -- 2. Loop through all user databases and grant read/visibility permissions
           DECLARE @name SYSNAME;
           DECLARE @sql NVARCHAR(MAX);

           DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
           SELECT [name]
           FROM [master].[sys].[databases]
           WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
             AND [state] = 0; -- Only online databases

           OPEN db_cursor;
           FETCH NEXT FROM db_cursor INTO @name;

           WHILE @@FETCH_STATUS = 0
           BEGIN
               BEGIN TRY
                   PRINT 'Granting permissions on database: ' + @name;

                   -- Create the database user mapping if it doesn't exist, then grant roles
                   SET @sql = '
                       USE [' + @name + '];
                       IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<ACCOUNT_USERNAME>'')
                       BEGIN
                           CREATE USER [<ACCOUNT_USERNAME>] FOR LOGIN [<ACCOUNT_USERNAME>];
                       END;
                       GRANT VIEW DATABASE STATE TO [<ACCOUNT_USERNAME>];
                       GRANT VIEW DEFINITION TO [<ACCOUNT_USERNAME>];
                       ALTER ROLE db_datareader ADD MEMBER [<ACCOUNT_USERNAME>];';

                   EXEC sp_executesql @sql;
                   PRINT 'Success: ' + @name;
               END TRY
               BEGIN CATCH
                   PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
               END CATCH

               FETCH NEXT FROM db_cursor INTO @name;
           END

           CLOSE db_cursor;
           DEALLOCATE db_cursor;
           GO
           ```
      </Collapser>

      <Collapser id="different-host" title="Collector em um host diferente do Windows">
        1. No seu SQL Server Management Studio (SSMS), execute o seguinte script para criar um login para a sua conta gMSA e conceder as permissões necessárias. Substitua todas as ocorrências de `<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>` pelo seu domínio e nome de conta reais.

        ```sql
        USE [master];
        GO

        CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FROM WINDOWS;
        GO

        GRANT VIEW ANY DATABASE   TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
        GO

        -- Grant access to all databases
        DECLARE @name SYSNAME;
        DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
          SELECT [name] FROM [master].[sys].[databases]
          WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
            AND [state] = 0;
        OPEN db_cursor;
        FETCH NEXT FROM db_cursor INTO @name;
        WHILE @@FETCH_STATUS = 0
        BEGIN
          BEGIN TRY
            EXEC('USE [' + @name + '];
            IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>'')
            BEGIN
              CREATE USER [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];
            END;
            GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_DOMAIN_USER>];');
          END TRY
          BEGIN CATCH
            PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
          END CATCH
          FETCH NEXT FROM db_cursor INTO @name;
        END
        CLOSE db_cursor;
        DEALLOCATE db_cursor;
        GO
        ```

        2. Configure o serviço NRDOT Collector para ser executado como seu usuário de domínio usando o PowerShell. Substitua `YOUR_DOMAIN\YOUR_USER_ACCOUNT` pelo seu domínio e nome de conta:

           ```powershell
           # Configure service to use domain account
           # The space after obj= and password= is required syntax for sc.exe
           sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

           # Restart the service
           Restart-Service nrdot-collector
           ```

        3. Valide a identidade do serviço:

           ```powershell
           Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
           # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
           ```
      </Collapser>
    </CollapserGroup>

    <Callout variant="tip">
      Para gerenciar informações confidenciais com segurança, como credenciais de banco de dados, armazene-as em ferramentas de [gerenciamento de segredos](/docs/opentelemetry/db360/capabilities/db-apm/#secret-management).
    </Callout>
  </Step>

    <Callout variant="tip">
      O pipeline `logs` não transporta logs de depuração do coletor ou logs internos do agente. Ele transmite a telemetria de consulta do SQL Server, incluindo texto da consulta, planos de execução e dados de amostra. O receptor `nrsqlserver` captura essa telemetria por meio dos eventos `db.server.query_sample`, `db.server.top_query`, `db.server.query_plan` e `db.server.top_procedure` emitidos como registros de log do OpenTelemetry.

      O evento `db.server.top_procedure` requer o SQL Server 2017 CU3 ou posterior, que introduziu suporte para `sys.dm_exec_procedure_stats.total_spills`. Em versões anteriores, esse evento não emite dados e registra um erro. Outros eventos permanecem inalterados. O acesso a `sys.dm_exec_procedure_stats` requer `VIEW SERVER STATE` (ou `VIEW SERVER PERFORMANCE STATE`, dependendo da versão do SQL Server). Além disso, `VIEW ANY DEFINITION` é necessário para que `OBJECT_NAME` e `OBJECT_SCHEMA_NAME` sejam resolvidos corretamente em todos os bancos de dados de usuário, e `CONNECT SQL` é necessário para configurar as sessões iniciais. A conta configurada em [Criar usuário de monitoramento](#user-domain) já possui todas as 3 permissões.
    </Callout>

  <Step>
    ## Atualizar Registro de Serviço do Windows [#update-registry-domain]

    1. Atualize o Registro de Serviço do Windows para usar o novo arquivo `mssql-config.yaml` usando um dos seguintes métodos:

       * **Para PowerShell:** execute o seguinte comando como administrador:

         ```powershell
         Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
         ```

       * **Para prompt de comando:** se o PowerShell não estiver disponível, use o prompt de comando e execute o seguinte comando como administrador:

       ```bash
       sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
       ```

    2. Valide a configuração do Collector NRDOT para garantir que esteja formatada corretamente e funcione adequadamente:

       ```bash
       & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
       ```

       <Callout variant="tip">
         Para correlacionar o desempenho do seu aplicativo com as operações de banco de dados, você pode configurar a identificação de serviço de banco de dados. Para mais informações, consulte [configurar a identificação de serviço de banco de dados](/docs/opentelemetry/db360/capabilities/db-apm/).
       </Callout>
  </Step>

  <Step>
    ## Reiniciar o NRDOT Collector [#restart-domain]

    Após atualizar sua configuração, reinicie o serviço NRDOT Collector:

    ```bash
    net stop nrdot-collector
    net start nrdot-collector
    ```

    <Callout variant="tip">
      Sempre reinicie o serviço do NRDOT Collector após fazer alterações na configuração para garantir que as novas configurações entrem em vigor.
    </Callout>
  </Step>

  <Step>
    ## Encontre e use seus dados [#find-domain]

    Assim que seus dados estiverem sendo coletados, você poderá acessar o monitoramento abrangente do banco de dados SQL Server por meio da interface do New Relic.

    Para encontrar sua entidade de banco de dados SQL Server no New Relic:

    1. Vá para <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.

    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**MSSQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.

    3. Selecione seu banco de dados SQL Server na lista de entidades.

       Após configurar o monitoramento do SQL Server com o NRDOT, você pode:

       * [Crie dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar suas métricas de banco de dados
       * [Configure alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para limites críticos de desempenho do banco de dados
       * [Explore seus dados](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) usando os recursos de consulta do New Relic
  </Step>
</Steps>
