Você pode instalar e configurar o NRDOT Collector para o monitoramento do SQL Server usando o cookbook do Chef `newrelic-install`. O cookbook instala o coletor, cria ou autoriza a identidade de monitoramento e configura o coletor quando você executa a receita `newrelic-install::default`.

<Callout variant="tip" title="Instalação guiada">
  Para instalar isso pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga as instruções na tela para configurar a integração. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.

    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.

    * Microsoft SQL Server 2017 ou posterior.

    * Chef 15 ou posterior.

    * **SQL Server auto-hospedado:**

      * **Autenticação do SQL Server:** um host de coletor Windows, Ubuntu ou RHEL/CentOS e um login na função de servidor `sysadmin` (ou equivalente) com sua senha.
      * **Autenticação do Windows ou gMSA:** um host de coletor do Windows e a conta de domínio do Windows (ou gMSA) para a qual conceder permissões.

    * **SQL Server no AWS RDS:**

      * Um host do coletor Windows, Ubuntu ou RHEL/CentOS com conectividade de rede para o endpoint do RDS (acesso de entrada concedido na porta do SQL Server dentro do grupo de segurança do RDS), junto com o nome de usuário mestre e a senha do RDS.
      * **Autenticação de domínio do Windows ou gMSA:** um host coletor do Windows e uma instância do RDS já ingressados em um domínio do AWS Managed Microsoft Active Directory.

    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondente à região de destino.
  </Step>

  <Step>
    ## Baixar o cookbook do Chef [#chef-download-cookbook]

    Faça o download do `newrelic-install` [cookbook do Chef](https://supermarket.chef.io/cookbooks/newrelic-install) do Chef Supermarket para o seu diretório de repositório (chef-repo):

    ```bash
    knife supermarket install newrelic-install
    ```
  </Step>

  <Step>
    ## Substituir os atributos padrão [#chef-configure]

    Substitua os atributos padrão em `attributes/default.rb` pelos detalhes da sua conta:

    <CollapserGroup>
      <Collapser id="chef-host-sql" title="Auto-hospedado - autenticação do SQL Server">
        Este cookbook monitora uma ou mais instâncias do SQL Server a partir de um único coletor. Em vez de um único conjunto de host/porta/credencial, ele lê dois arquivos que já devem existir no nó: um **arquivo de instâncias** (YAML) listando cada instância a ser monitorada, e um **arquivo de segredos** (`KEY=VALUE`) com um login de administrador e senha para cada uma, indexado para corresponder.

        1. Crie o arquivo de instância no nó. Adicione uma entrada por instância do SQL Server que este coletor deve monitorar, ou apenas uma entrada se estiver executando uma única instância:

           ```yaml
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
           ```

        2. Crie o arquivo de segredos no nó com um login de administrador e senha para cada instância, indexado para corresponder à ordem do arquivo de instâncias. O login de administrador deve ser um membro da função `sysadmin` (ou equivalente):

           ```bash
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
           ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_MSSQL_SECRETS_FILE']    = <path to the secrets file (KEY=VALUE per instance) on the node>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

      <Collapser id="chef-host-winauth" title="Auto-hospedado - Autenticação do Windows ou gMSA">
        Este destino é suportado apenas em um host de coletor Windows. Ele usa a autenticação do Windows (`integrated security=true`) em vez de logins do SQL e monitora uma ou mais instâncias do SQL Server a partir de um único coletor usando um **arquivo de instâncias** (YAML, `host`/`port` por instância, sem arquivo de segredos: uma identidade do Windows monitora cada instância).

        Este arquivo já deve existir no nó, com apenas uma entrada se estiver executando uma única instância. Apenas `host` e `port` são necessários (sem `login_name`):

        ```yaml
        instances:
          - host: sql01.contoso.com
            port: 1433
          - host: sql02.contoso.com
            port: 1433
        ```

        Para uma instância nomeada, use `host` mais sua porta TCP estática em vez de `host\INSTANCE`.

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-winauth'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']    = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']        = <1 for Windows Domain Auth, 2 for gMSA, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WINAUTH_LOCATION'] = <1 for same host as SQL Server, 2 for a different host, default 1; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']   = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']      = <Windows domain account, DOMAIN\username; required only for Windows Domain Auth on a different host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']     = <password for that account; required only for Windows Domain Auth on a different host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']     = <gMSA account, DOMAIN\gMSAName$; gMSA only>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>

      <Collapser id="chef-rds-winauth" title="AWS RDS - autenticação de domínio do Windows ou gMSA">
        Este destino é compatível apenas com um host de coletor Windows e exige que suas instâncias do RDS já estejam ingressadas em um domínio do AWS Managed Microsoft AD. Ele monitora um ou mais endpoints do RDS SQL Server a partir de um único coletor usando um **arquivo de instâncias** (YAML, `host`/`port` por instância, usando endpoints do RDS como `host`). Ao contrário do destino auto-hospedado acima, não há opção de &quot;mesmo host&quot; aqui: uma conta de domínio (ou gMSA) é sempre necessária.

        Este arquivo já deve existir no nó, usando cada endpoint do RDS como `host`, com apenas uma entrada se o monitoramento for de apenas uma única instância do RDS:

        ```yaml
        instances:
          - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
          - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
            port: 1433
        ```

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-mssql-rds-winauth'
        ]
        default['newrelic_install']['env']['NR_CLI_MSSQL_CONFIG_PRESET']   = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_AUTH_MODE']       = <1 for Windows Domain Auth, 2 for gMSA, default 1>
        default['newrelic_install']['env']['NR_CLI_MSSQL_INSTANCES_FILE']  = <path to the instances YAML file on the node, using RDS endpoints as host>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_ACCOUNT']     = <Windows domain account, DOMAIN\username; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_WIN_PASSWORD']    = <password for that account; Windows Domain Auth only>
        default['newrelic_install']['env']['NR_CLI_MSSQL_GMSA_ACCOUNT']    = <gMSA account, DOMAIN\gMSAName$; gMSA only>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

  <Step>
    ## Encontre e use seus dados [#find]

    Assim que os dados estiverem sendo coletados, será possível acessar o monitoramento abrangente do banco de dados SQL Server por meio da interface do New Relic.

    Para encontrar sua entidade de banco de dados SQL Server no New Relic:

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**MSSQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.

    3. Selecione seu banco de dados SQL Server na lista de entidades.

       Após configurar o monitoramento do SQL Server com o NRDOT, você pode:

       * [Crie dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar suas métricas de banco de dados
       * [Configure alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para limites críticos de desempenho do banco de dados
       * [Explore seus dados](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) usando os recursos de consulta do New Relic
  </Step>
