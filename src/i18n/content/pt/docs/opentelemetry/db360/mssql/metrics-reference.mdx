Monitore o desempenho do seu banco de dados SQL Server com métricas abrangentes coletadas pelo NRDOT Collector. Por padrão, o New Relic coleta as métricas e os eventos no nível da consulta referenciados na seção [Métricas e eventos padrão](#default). Você pode aprimorar seu monitoramento ativando as métricas desejadas listadas na seção [Métricas de recursos completos](#full-feature).

## Métricas e eventos padrão [#default]

As seguintes métricas estão habilitadas por padrão. Elas são coletadas em qualquer plataforma quando o receptor é configurado com uma conexão direta com o SQL Server.

### Evento de log [#log-events]

Os seguintes eventos são coletados como registros de log do OpenTelemetry e estão habilitados por padrão, exceto `db.server.procedure_definition`, que é opcional. Eles fornecem visibilidade no nível da consulta: amostras de consultas ativas, principais consultas, planos de execução, principais procedimentos armazenados e definições de procedimentos armazenados.

<Collapser id="db-server-top-query" title="Principais consultas">
Coleção de métricas de evento para as N principais consultas, filtradas com base no maior tempo decorrido consumido no intervalo de coleta. Este evento está habilitado por padrão.

Use o bloco `top_query_collection` para ajustar seu comportamento:

```yaml
top_query_collection:
  lookback_time: 60s
  max_query_sample_count: 1000
  top_query_count: 250
  collection_interval: 60s
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="db-server-top-procedure" title="Principais procedimentos">
Métricas de desempenho agregadas para os principais procedimentos armazenados por tempo decorrido, computadas como deltas ao longo do intervalo de coleta. Correlaciona-se com `db.server.top_query` e `db.server.query_sample` via `sqlserver.procedure_id`. Este evento está habilitado por padrão.

<Callout variant="tip">
Requer o SQL Server 2017 CU3 ou posterior, que introduziu suporte para `sys.dm_exec_procedure_stats.total_spills`. Em versões anteriores, esse evento não emite dados e registra um erro. Outros eventos permanecem inalterados.
</Callout>

Use o bloco `top_procedure_collection` para ajustar seu comportamento:

```yaml
top_procedure_collection:
  max_procedure_sample_count: 1000
  top_procedure_count: 250
  collection_interval: 60s
```

## Limitações do Amazon RDS [#rds-limitations]

Ao realizar o monitoramento de uma instância do Amazon RDS for SQL Server, certas métricas podem reportar `0` ou não ser coletadas devido a restrições do serviço RDS e limitações da edição do SQL Server.

<Callout variant="important">
As seguintes limitações se aplicam especificamente a instâncias do SQL Server em execução no Amazon RDS. As implantações auto-hospedadas do SQL Server não são afetadas por essas restrições.
</Callout>

<CollapserGroup>

`sqlserver.database.execution.errors`
</td>

<td>
