É possível instalar e configurar o NRDOT Collector para o monitoramento do SQL Server usando a CLI da New Relic. A CLI instala o coletor, cria ou autoriza a identidade de monitoramento e configura o coletor em um único comando.

<Callout variant="tip" title="Instalação guiada">
  Para instalar isso pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Microsoft SQL Server (Database 360)](https://onenr.io/00jlEJX6EQW)** </DNT>. Siga as instruções na tela para configurar a integração. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.

    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.

    * Microsoft SQL Server 2017 ou posterior.

    * **SQL Server auto-hospedado:**

      * **Autenticação do SQL Server:** um host de coletor Linux ou Windows e um login na função de servidor `sysadmin` (ou equivalente) com sua senha.
      * **Autenticação do Windows ou gMSA:** um host de coletor do Windows, uma sessão do PowerShell de administrador e uma conta do Windows ou gMSA com as permissões necessárias.

    * **SQL Server no AWS RDS:**

      * Um host de coletor Linux ou Windows com conectividade de rede para o endpoint do RDS (acesso de entrada concedido na porta do SQL Server dentro do grupo de segurança do RDS), juntamente com o nome de usuário mestre e a senha do RDS.
      * **Autenticação de domínio do Windows ou gMSA:** um host coletor do Windows e uma instância do RDS já ingressados em um domínio do AWS Managed Microsoft Active Directory.

    * **Host do coletor Linux:** O utilitário `curl`, `systemd` e o utilitário `sqlcmd` instalados e disponíveis em `PATH` (ou localizados em `/opt/mssql-tools18/bin` ou `/opt/mssql-tools/bin`).

    * **Host do coletor Windows:** o utilitário `sqlcmd.exe` instalado e disponível em `PATH`.

    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) correspondente à região de destino.
  </Step>

  <Step>
    ## Instale e configure o NRDOT Collector [#cli-install]

    <CollapserGroup>
      <Collapser id="cli-host-sql" title="Auto-hospedado - autenticação do SQL Server">
        Esta receita monitora uma ou mais instâncias do SQL Server a partir de um único coletor. Em vez de solicitar um único conjunto de host/porta/credencial, ele lê dois arquivos criados antecipadamente: um **arquivo de instâncias** (YAML) que lista cada instância a ser monitorada e um **arquivo de segredos** (`KEY=VALUE`) com um login e senha de administrador para cada uma, indexados para corresponder.

        1. Crie o arquivo de instâncias. Adicione uma entrada por instância do SQL Server que este coletor deve monitorar, ou apenas uma entrada se estiver executando apenas uma única instância:

           ```bash
           cat > ~/mssql-instances.yml << 'EOF'
           instances:
             - host: localhost
               port: 1433
               login_name: newrelic
           EOF
           ```

        2. Crie o arquivo de segredos com um login e senha de administrador para cada instância, indexado para corresponder à ordem do arquivo de instância. O login de administrador deve ser membro da função `sysadmin` (ou equivalente):

           ```bash
           umask 077
           cat > ~/mssql-secrets.env << 'EOF'
           NR_CLI_MSSQL_ADMIN_USER_1=<YOUR_ADMIN_USERNAME>
           NR_CLI_MSSQL_ADMIN_PASSWORD_1=<YOUR_ADMIN_PASSWORD>
           EOF
           chmod 600 ~/mssql-secrets.env
           ```

        **Linux:**

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-mssql
        ```

        **Windows** (executar em uma sessão do PowerShell de administrador):

        ```powershell
        [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql
        ```

      <Collapser id="cli-host-winauth" title="Auto-hospedado - Autenticação do Windows ou gMSA">
        Este método é suportado apenas em um host de coletor Windows. Ele usa a autenticação do Windows (`integrated security=true`) em vez de logins do SQL, e monitora uma ou mais instâncias do SQL Server a partir de um único coletor. O coletor é um serviço do Windows com uma conta de logon, e se conecta a **cada** instância como essa conta, portanto, uma instalação de múltiplas instâncias sempre usa um modo de autenticação e uma identidade do Windows, concedida em cada instância listada.

        1. Crie o arquivo de instâncias. Adicione uma entrada por instância do SQL Server a ser monitorada por este coletor, ou apenas uma entrada se estiver executando uma única instância. Apenas `host` e `port` são necessários (sem `login_name`, sem arquivo de segredos):

           ```yaml
           instances:
             - host: sql01.contoso.com
               port: 1433
             - host: sql02.contoso.com
               port: 1433
           ```

           Salve isto em qualquer lugar no host do coletor, por exemplo, `C:\mssql-instances.yml`. Para uma instância nomeada, use `host` mais sua porta TCP estática em vez de `host\INSTANCE`.

        Antes de executar este comando, tenha em mãos:

        * O arquivo de instâncias da etapa 1
        * Seja usando uma conta do Windows ou uma conta gMSA
        * Para Autenticação do Windows: se o coletor é executado no mesmo host que o SQL Server ou em um host diferente
        * A conta do Windows (ou conta gMSA) à qual conceder permissões (não é necessário se o coletor for executado no mesmo host que o SQL Server)
        * Se deseja métricas Básicas ou Avançadas

        Execute isto em uma sessão do PowerShell de administrador:

        ```powershell
        [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $WebClient = New-Object System.Net.WebClient; $WebClient.DownloadFile("https://download.newrelic.com/install/newrelic-cli/scripts/install.ps1", "$env:TEMP\install.ps1"); & PowerShell.exe -ExecutionPolicy Bypass -File $env:TEMP\install.ps1; $env:NEW_RELIC_API_KEY='INSERT_YOUR_API_KEY'; $env:NEW_RELIC_ACCOUNT_ID='INSERT_YOUR_ACCOUNT_ID'; $env:NEW_RELIC_REGION='INSERT_YOUR_REGION'; & 'C:\Program Files\New Relic\New Relic CLI\newrelic.exe' install -n nrdot-collector-mssql-winauth
        ```

      <Collapser id="cli-rds-winauth" title="AWS RDS - autenticação de domínio do Windows ou gMSA">
        Este método é compatível apenas com um host de coletor Windows e exige que suas instâncias do RDS já estejam ingressadas em um domínio do AWS Managed Microsoft AD. Ele monitora um ou mais endpoints do RDS SQL Server a partir de um único coletor. O coletor é um serviço do Windows com uma conta de logon e se conecta a **cada** endpoint com essa conta; portanto, uma instalação de múltiplas instâncias sempre usa um modo de autenticação e uma identidade do Windows, concedida em cada endpoint que você listar. Ao contrário do método auto-hospedado acima, não há opção de &quot;mesmo host&quot; aqui: uma conta de domínio (ou gMSA) é sempre necessária.

        1. Crie o arquivo de instância, usando cada endpoint do RDS como `host`, com apenas uma entrada se estiver realizando o monitoramento de apenas uma única instância do RDS:

           ```yaml
           instances:
             - host: mydb1.xxxxxxxxxx.us-east-1.rds.amazonaws.com
               port: 1433
             - host: mydb2.xxxxxxxxxx.us-east-1.rds.amazonaws.com
               port: 1433
           ```

           Salvar em qualquer lugar no host do coletor, por exemplo, `C:\mssql-instances.yml`.

        Antes de executar este comando, tenha em mãos:

        * O arquivo de instâncias da etapa 1
        * Seja usando uma conta de domínio do Windows ou uma conta gMSA
        * A conta de domínio (ou conta gMSA) à qual conceder permissões
        * Se deseja métricas Básicas ou Avançadas

        Execute isto em uma sessão do PowerShell de administrador:


  <Step>
    ## Encontre e use seus dados [#find]

    Assim que os dados estiverem sendo coletados, será possível acessar o monitoramento abrangente do banco de dados SQL Server por meio da interface do New Relic.

    Para encontrar sua entidade de banco de dados SQL Server no New Relic:

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.

    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**MSSQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.

    3. Selecione seu banco de dados SQL Server na lista de entidades.

       Após configurar o monitoramento do SQL Server com o NRDOT, você pode:

       * [Crie dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar suas métricas de banco de dados
       * [Configure alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para limites críticos de desempenho do banco de dados
       * [Explore seus dados](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) usando os recursos de consulta do New Relic
  </Step>
