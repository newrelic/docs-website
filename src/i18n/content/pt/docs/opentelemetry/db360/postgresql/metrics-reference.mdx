O NRDOT Collector relata uma ampla variedade de métricas do PostgreSQL. O New Relic coleta as métricas em [Métricas padrão](#default) automaticamente. Para obter insights mais profundos sobre o desempenho e a integridade, ative qualquer uma das métricas listadas em [Métricas adicionais](#additional).

<Callout variant="tip">
  Cada métrica tem o escopo de um banco de dados, tabela, esquema ou índice específico. Esse contexto é definido no recurso, não como um atributo de métrica.
</Callout>

    #### Mecânica de coleta do plano de execução (EXPLAIN)

    * **Limitação de taxa:** `top_query_collection.max_explain_each_interval` (padrão 1.000) limita os EXPLAINs por coleta.
    * **Cache:** `query_plan_cache_size` / `query_plan_cache_ttl` (padrão de 1.000 entradas / 1h) armazenam em cache um plano assim que obtido, com chave por ID da consulta.
    * **Requisito do PostgreSQL 12+:** o EXPLAIN de consulta parametrizada precisa de `plan_cache_mode = force_generic_plan` antes de `PREPARE`/`EXPLAIN EXECUTE`, disponível apenas no PostgreSQL 12+. Em servidores mais antigos, o receiver detecta a versão e ignora o EXPLAIN para essa consulta em vez de enviar um `SET` que falharia.
    * **Limite de privilégio:** por padrão, o EXPLAIN é executado diretamente como o usuário de monitoramento, e o Postgres verifica os privilégios de tabela no momento do *plano*, portanto, as instruções de bloqueio de linha ou de gravação falham com `permission denied` a menos que seja concedido acesso de gravação, o que o usuário de monitoramento nunca deve ter. Use `explain_function_name` (consulte [Planos de consulta para instruções de gravação](/docs/opentelemetry/db360/postgresql/optional#query)) para contornar isso sem conceder acesso de gravação.
    * Se um plano não puder ser obtido por qualquer motivo, `postgresql.query_plan` fica simplesmente vazio para essa linha. Nenhum erro é exibido.
