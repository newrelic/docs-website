Você pode instalar e configurar o NRDOT Collector para o monitoramento do PostgreSQL usando o cookbook `newrelic-install` do Chef. O cookbook instala o coletor, cria a função de monitoramento e suas permissões, e configura o coletor quando você executa a receita `newrelic-install::default`.

<Callout variant="tip" title="Instalação guiada">
  Para instalar pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.
    * PostgreSQL 14 ou posterior.
    * Chef 15 ou posterior.
    * Um host coletor Linux executando Debian/Ubuntu ou RHEL/CentOS.
    * `pg_stat_statements` deve ser carregado via `shared_preload_libraries`, o que requer a reinicialização do banco de dados. Atenda aos [pré-requisitos no nível do servidor](/docs/opentelemetry/db360/postgresql/cli/#server-prereqs) antes de executar a receita.
    * Para PostgreSQL auto-hospedado: acesso administrativo ao seu servidor PostgreSQL (o superusuário `postgres` ou equivalente), com uma senha definida e `pg_hba.conf` permitindo autenticação de host baseada em senha.
    * Para PostgreSQL ou Aurora no AWS RDS: conectividade de rede do host do coletor para o endpoint do RDS, e o nome de usuário e senha mestre do RDS.
    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para sua região.

    Para requisitos detalhados, consulte [Compatibilidade](/docs/opentelemetry/db360/postgresql/compatibility).
  </Step>

  <Step>
    ## Baixar o cookbook do Chef [#chef-download-cookbook]

    Faça o download do `newrelic-install` [cookbook do Chef](https://supermarket.chef.io/cookbooks/newrelic-install) do Chef Supermarket para o seu diretório de repositório (chef-repo):

    ```bash
    knife supermarket install newrelic-install
    ```
  </Step>

  <Step>
    ## Substituir os atributos padrão [#chef-configure]

    Substitua os atributos padrão em `attributes/default.rb` pelos detalhes da sua conta:

    <CollapserGroup>
      <Collapser id="chef-host" title="PostgreSQL auto-hospedado">
        Este cookbook monitora uma ou mais instâncias do PostgreSQL a partir de um único coletor. Em vez de um único conjunto de host/porta/credencial, ele lê dois arquivos que já devem existir no nó: um arquivo de instâncias (YAML) listando cada instância a ser monitorada e os bancos de dados a serem monitorados em cada uma, e um arquivo de segredos (`KEY=VALUE`) com um login e senha de superusuário para cada uma, indexados para corresponder. Consulte a página de [instalação da CLI](/docs/opentelemetry/db360/postgresql/cli/#cli-install) para obter os formatos exatos dos arquivos.

        ```ruby
        default['newrelic_install']['NEW_RELIC_API_KEY']    = <API key>
        default['newrelic_install']['NEW_RELIC_ACCOUNT_ID'] = <Account ID>
        default['newrelic_install']['NEW_RELIC_REGION']     = <Region>
        default['newrelic_install']['targets'] = [
          'nrdot-collector-postgresql'
        ]
        default['newrelic_install']['env']['NR_CLI_POSTGRES_CONFIG_PRESET']         = <1 Basic, 2 Advanced, default 1>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_INSTANCES_FILE']        = <path to the instances YAML file on the node>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_SECRETS_FILE']          = <path to the secrets file (KEY=VALUE per instance) on the node>
        default['newrelic_install']['env']['NR_CLI_POSTGRES_ENABLE_EXPLAIN_HELPER'] = <y or N, default N; PREVIEW feature, see table below>
        # See all available targets at: https://github.com/newrelic/chef-install
        ```

        <Callout variant="important">
          O cookbook se conecta ao PostgreSQL via TCP usando uma senha, portanto, o superusuário de cada instância deve ter uma senha definida e `pg_hba.conf` deve permitir a autenticação de host baseada em senha (`md5` ou `scram-sha-256`) para conexões TCP:

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```
        </Callout>

      <Collapser id="chef-rds" title="PostgreSQL ou Aurora no AWS RDS">

  <Step>
    ## Faça o upload do cookbook do Chef [#chef-upload-cookbook]

    Faça o upload do cookbook `newrelic-install` do Chef para o seu servidor Chef:

    ```bash
    knife cookbook upload newrelic-install
    ```
  </Step>

  <Step>
    ## Atualizar a run list [#chef-run-list]

    Adicione a receita `newrelic-install` à run list de um nó:

    ```json
    "run_list": [
      "recipe[newrelic-install]"
    ]
    ```
  </Step>

  <Step>
    ## Encontre e use seus dados [#find]

    Assim que seus dados estiverem sendo coletados, você poderá acessar o monitoramento abrangente do banco de dados PostgreSQL por meio da interface do New Relic.

    Para encontrar a entidade de banco de dados PostgreSQL no New Relic:

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**PostgreSQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.
    3. Selecione seu banco de dados PostgreSQL na lista de entidades.
  </Step>
