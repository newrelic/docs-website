Você pode instalar e configurar o NRDOT Collector para monitoramento do PostgreSQL usando a CLI da New Relic. A CLI instala o coletor, cria a função de monitoramento e suas permissões e configura o coletor em um único comando.

<Callout variant="tip" title="Instalação guiada">
  Para instalar pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; PostgreSQL (Database 360)](https://onenr.io/00jlEJKbdQW)**</DNT>. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.
    * PostgreSQL 14 ou posterior.
    * Um host coletor Linux executando Debian/Ubuntu ou RHEL/CentOS, com `curl` e `systemd` instalados e o cliente `psql` disponível.
    * `pg_stat_statements` deve ser carregado via `shared_preload_libraries`. O instalador verifica isso e falha se não estiver. Consulte os [Pré-requisitos no nível do servidor](#server-prereqs) abaixo.
    * Para PostgreSQL auto-hospedado: acesso administrativo ao seu servidor PostgreSQL (o superusuário `postgres` ou equivalente).
    * Para AWS RDS/Aurora PostgreSQL: conectividade de rede do host do coletor para o endpoint do RDS (acesso de entrada na porta do PostgreSQL no grupo de segurança do RDS) e o nome de usuário e a senha mestre do RDS.
    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para sua região.

    Para requisitos detalhados, consulte [Compatibilidade](/docs/opentelemetry/db360/postgresql/compatibility).
  </Step>

    * **Auto-hospedado**: defina-os em `postgresql.conf` e, em seguida, reinicie o PostgreSQL. Algumas distribuições precisam do pacote `postgresql-contrib` instalado para que `pg_stat_statements` esteja disponível.
    * **AWS RDS ou Aurora**: defina-os no **grupo de parâmetros** do banco de dados, não em um arquivo de configuração. `track_activity_query_size` e `pg_stat_statements.max` são parâmetros estáticos: aplique-os com `apply_method: pending-reboot` e, em seguida, reinicie a instância. Para o Aurora, o nome da família do grupo de parâmetros deve corresponder exatamente à versão principal do seu mecanismo, por exemplo, `aurora-postgresql16`.
  </Step>

  <Step>
    ## Instale e configure o NRDOT Collector [#cli-install]

    <CollapserGroup>
      <Collapser id="cli-host" title="PostgreSQL auto-hospedado">
        Esta receita monitora uma ou mais instâncias do PostgreSQL a partir de um único coletor. Em vez de solicitar um único conjunto de host/porta/credencial, lê dois arquivos que você cria com antecedência: um arquivo de instâncias (YAML) listando cada instância a ser monitorada e os bancos de dados a serem monitorados em cada uma, e um arquivo de segredos (`KEY=VALUE`) com um login e senha de superusuário para cada uma, indexados para corresponder.

        1. Crie o arquivo de instâncias. Adicione uma entrada por instância do PostgreSQL que você deseja que este coletor monitore; ainda assim, apenas uma entrada se você estiver executando apenas uma única instância. Cada instância requer pelo menos um banco de dados: o PostgreSQL não possui um modo de monitorar todos os bancos de dados:

           ```bash
           cat > ~/postgresql-instances.yml << 'EOF'
           instances:
             - host: localhost
               port: 5432
               login_name: newrelic
               databases: [app1, app2]
           EOF
           ```

        2. Crie o arquivo de segredos com uma função de superusuário (qualquer função de superusuário funciona; não precisa ser `postgres`) e senha para cada instância, indexado para corresponder à ordem do arquivo de instâncias:

           ```bash
           umask 077
           cat > ~/postgresql-secrets.env << 'EOF'
           NR_CLI_POSTGRES_SUPERUSER_USER_1=postgres
           NR_CLI_POSTGRES_SUPERUSER_PASSWORD_1=YourSuperuserPassword1
           EOF
           chmod 600 ~/postgresql-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-postgresql
        ```

        <Callout variant="important">
          Este instalador se conecta ao PostgreSQL via TCP usando uma senha, portanto, o superusuário de cada instância deve ter uma senha definida e `pg_hba.conf` deve permitir a autenticação de host baseada em senha (`md5` ou `scram-sha-256`) para conexões TCP. Uma nova instalação não tem senha definida em `postgres` por padrão. Defina uma primeiro:

          ```bash
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '<password>';"
          ```

          No RHEL/CentOS, o `pg_hba.conf` padrão frequentemente não permite qualquer autenticação de host baseada em senha. Verifique e atualize-o e, em seguida, recarregue o PostgreSQL antes de executar a instalação.
        </Callout>

           cat > ~/postgresql-secrets.env << 'EOF'
           NR_CLI_POSTGRES_ADMIN_USER_1=postgres
           NR_CLI_POSTGRES_ADMIN_PASSWORD_1=YourMasterPassword1

  <Step>
    ## Encontre e use seus dados [#find]

    Assim que seus dados estiverem sendo coletados, você poderá acessar o monitoramento abrangente do banco de dados PostgreSQL por meio da interface do New Relic.

    Para encontrar a entidade de banco de dados PostgreSQL no New Relic:

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**PostgreSQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.
    3. Selecione seu banco de dados PostgreSQL na lista de entidades.

    Para confirmar que os dados estão chegando, execute esta consulta no [criador de consulta](/docs/query-your-data/explore-query-data/query-builder/introduction-query-builder/):

    ```sql
    SELECT count(*) FROM Metric
    WHERE metricName LIKE 'postgresql.%'
    AND instrumentation.provider = 'opentelemetry'
    SINCE 10 minutes ago
    ```
