Você pode usar o OpenTelemetry Collector Contrib para PostgreSQL para monitorar sua instância. O OpenTelemetry Collector Contrib é um projeto apoiado pela comunidade que coleta dados de telemetria do PostgreSQL e os envia para o New Relic.

Por padrão, o OpenTelemetry Collector Contrib coleta métricas limitadas do PostgreSQL. Para enviar métricas de desempenho de consulta, evento de espera, sessão e cliente, você precisará configurar o OpenTelemetry Collector Contrib. Este guia mostra como configurá-lo para coletar métricas avançadas do PostgreSQL e enviá-las para o New Relic.

<Callout variant="tip" title="Observação">
Esta página aborda o receiver da comunidade `postgresql` incluído no binário padrão do `otelcol-contrib`. Se você estiver usando a distribuição do New Relic (NRDOT), consulte [Introdução ao monitoramento do PostgreSQL](/docs/opentelemetry/db360/postgresql/introduction) em vez disso.
</Callout>

<Steps>
<Step>
## Pré-requisitos [#prerequisites]

* OpenTelemetry Collector Contrib (`otelcol-contrib`) instalado e configurado no seu sistema. Você pode fazer o download do release mais recente na página de [releases do OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).

* `pg_stat_statements` habilitado via `shared_preload_libraries` na instância monitorada do PostgreSQL. Isso é necessário para dados de desempenho de consulta, evento de espera, sessão e cliente. Consulte [Parâmetros de servidor recomendados](/docs/opentelemetry/db360/postgresql/compatibility#params).

* O coletor iniciou no modo de convenção semântica usando o gate de recurso `receiver.postgresql.useOTelSemconv`.

  Se você estiver executando o `otelcol-contrib` como um pacote RPM/Debian (serviço systemd), o arquivo de serviço importa variáveis de ambiente via `EnvironmentFile=/etc/otelcol-contrib/otelcol-contrib.conf`. Nesse arquivo, acrescente o sinalizador a `OTELCOL_OPTIONS`:

  ```bash
  OTELCOL_OPTIONS="--config=/etc/otelcol-contrib/config.yaml --feature-gates=receiver.postgresql.useOTelSemconv"
  ```

  Após salvar o arquivo, reinicie o serviço para aplicar o gate:

  ```bash
  sudo systemctl restart otelcol-contrib
  ```
</Step>

<Step>
## Habilite as métricas da interface [#enable]

Você pode enriquecer sua experiência na plataforma New Relic adicionando e habilitando métricas em seu arquivo de configuração `otelcol-contrib`. Usando a configuração fornecida nesta seção, você pode preencher dados para as seguintes páginas na plataforma New Relic:

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Ativar métricas da página Overview">
A página <DNT>Overview</DNT> exibe uma visão de alto nível da sua instância do PostgreSQL, incluindo métricas principais, como bloqueios de banco de dados, deadlocks, chamadas de função, conflitos de consulta, varreduras sequenciais e uso de arquivos temporários/E/S.

Para preencher os dados da página <DNT>Overview</DNT> na plataforma New Relic, adicione a seguinte configuração ao arquivo de configuração `otelcol-contrib`:

```yaml
receivers:
  postgresql:
    metrics:
      postgresql.database.locks:
        enabled: true
      postgresql.deadlocks:
        enabled: true
      postgresql.function.calls:
        enabled: true
      postgresql.query.conflicts:
        enabled: true
      postgresql.sequential_scans:
        enabled: true
      postgresql.temp.io:
        enabled: true
      postgresql.temp_files:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="Ativar Métricas de Desempenho de Consulta, Sessão, Espera e Cliente">
Para preencher os dados das páginas <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT> e <DNT>Clients</DNT>:

* Desempenho de consulta: exibe informações detalhadas sobre as consultas em execução na sua instância do PostgreSQL nas seguintes abas:

  * Consultas normalizadas: exibe gráficos de execução e tempo médio de CPU.
  * Amostras de consulta: exibe execuções individuais de consulta, incluindo hora de início, duração, tipo de espera, tempo de espera, banco de dados, usuário do BD e host do cliente.

* Eventos de espera: exibe informações sobre os eventos de espera que ocorrem na sua instância do PostgreSQL. A visualização de amostras de consulta mostra as consultas que estão aguardando no momento, juntamente com seu tipo de espera e tempo de espera.

* Sessões: visualiza tendências para conexões de banco de dados ativas vs. ociosas, duração média da sessão, sessões bloqueadas e uso por aplicativo e processo, para rastrear picos de carga e gargalos de conexão.

* Clientes: exibe informações sobre os clientes conectados à sua instância do PostgreSQL, incluindo sessões ativas, sessões bloqueadas, usuários de banco de dados conectados e detalhes do host do cliente.

Adicione a seguinte configuração ao seu arquivo de configuração `otelcol-contrib`:

```yaml
receivers:
  postgresql:
    events:
      db.server.top_query:
        enabled: true
      db.server.query_sample:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      max_rows_per_query: 1000
      top_n_query: 200
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 1000
```

<Callout variant="important">
`db.server.query_plan` requer que pelo menos `db.server.top_query` ou `db.server.query_sample` também seja habilitado. Habilitá-lo sozinho é um erro de validação de configuração.
</Callout>

<Callout variant="tip" title="Observação">
`postgresql.session.duration` não está disponível no receiver `postgresql` da comunidade, portanto, a tabela Sessions não é renderizada na página Sessions.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## Reinicie o OpenTelemetry Collector [#restart]

Reinicie o OpenTelemetry Collector para aplicar as alterações de configuração:

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
