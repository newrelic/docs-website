Monitore o desempenho do seu banco de dados MySQL com métricas abrangentes coletadas pelo NRDOT Collector. Por padrão, o New Relic coleta as métricas e os eventos no nível da consulta referenciados na seção [Métricas e eventos padrão](#default). Você pode aprimorar seu monitoramento habilitando as métricas desejadas listadas na seção [Métricas de recursos completos](#full-feature).

### Consulta evento [#query-events]

Os eventos a seguir são coletados como registros de log do OpenTelemetry e são habilitados por padrão. Eles fornecem visibilidade no nível da consulta.

<CollapserGroup>
<Collapser id="query-sample" title="Amostras de consulta">
Visibilidade em tempo real das instruções do banco de dados atualmente em execução: um snapshot de um momento específico obtido a cada scrape, não um log de execução completo. Este evento está habilitado por padrão.

Use o bloco `query_sample_collection` para ajustar seu comportamento:

```yaml
query_sample_collection:
  max_rows_per_query: 100
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="top-query" title="Principais consultas">
As consultas que consomem mais tempo de execução, agregadas no lado do servidor pelo próprio `performance_schema.events_statements_summary_by_digest` do MySQL: um verdadeiro contador de execução por digest, não uma contagem de amostra. Este evento está habilitado por padrão.

Use o bloco `top_query_collection` para ajustar seu comportamento:

```yaml
top_query_collection:
  lookback_time: 60
  max_query_sample_count: 5000
  top_query_count: 200
  collection_interval: 60s
  query_plan_cache_size: 1000
  query_plan_cache_ttl: 1h
  allowed_comment_keys: [nr_service_guid]
```

<Collapser id="query-plan" title="Planos de consulta">
Plano de execução para uma instrução, reportado como seu próprio evento para que o plano possa ser filtrado, roteado ou descartado independentemente das próprias estatísticas de `top_query`/`query_sample`. Requer que pelo menos um entre `db.server.top_query` ou `db.server.query_sample` também esteja habilitado. Uma vez habilitado, `mysql.query_plan` não é mais incluído nos registros `db.server.top_query`/`db.server.query_sample`. Consulte [Coleta do plano de execução](#explain) para ver a mecânica de `EXPLAIN`. Este evento está habilitado por padrão.

<Collapser id="explain" title="Coleta do plano de execução">
`EXPLAIN` precisa de uma instrução SQL literal: o texto de resumo normalizado usa espaços reservados (`SELECT ? FROM t WHERE id = ?`) que o MySQL não pode executar.

<table>
<thead>
<tr>
<th>
Versão do MySQL
</th>

<th>
Disponibilidade do plano
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
`8.0.3`+
</td>

<td>
Disponível: `query_sample_text` na tabela de resumo do digest contém uma instrução real para `EXPLAIN`
</td>
</tr>

<tr>
<td>
`5.x`, `8.0.0`–`8.0.2`
</td>

<td>
Não disponível: nenhum `query_sample_text` para explicar
</td>
</tr>
</tbody>
</table>

Se uma instrução capturada for truncada (terminar em `...`), `EXPLAIN` é ignorado em todas as versões. Consulte [Parâmetros de servidor recomendados](/docs/opentelemetry/db360/mysql/compatibility#params).

<table>
<thead>
<tr>
<th>
`explain_mode`
</th>

<th>
Comportamento
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
`inline` (padrão)
</td>

<td>
Executa `EXPLAIN FORMAT=json <statement>` diretamente; suficiente para workload exclusivo de `SELECT`
</td>
</tr>

<tr>
<td>
`procedure`
</td>

<td>
Encaminha por meio de um procedimento `SQL SECURITY DEFINER` (`<schema>.explain_statement`) para que as instruções de gravação (`UPDATE`/`DELETE`/`INSERT`/`REPLACE`) possam ser explicadas sem conceder DML ao usuário de monitoramento. Recorre a `inline` se o procedimento estiver ausente. Requer a etapa de configuração única por esquema. Consulte [Planos de consulta para instruções de gravação](/docs/opentelemetry/db360/mysql/optional#query).
</td>
</tr>
</tbody>
</table>

<Callout variant="important">
`mysql.query_plan` é a saída bruta de `EXPLAIN FORMAT=json`, envolvida em uma matriz JSON de um elemento antes do armazenamento em cache, para que a ingestão de logs do New Relic não a achate automaticamente e a destrua. Analise o índice `[0]` para recuperar o objeto do plano.
</Callout>

A configuração com todos os recursos coleta cada métrica padrão, além das seguintes métricas adicionais. Essas métricas são organizadas por funcionalidade e a maioria exige uma conexão direta com o MySQL. Você pode definir qualquer uma dessas métricas como `true` na seção `metrics` da sua configuração para habilitá-las.
