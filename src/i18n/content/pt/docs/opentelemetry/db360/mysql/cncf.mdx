Você pode usar o OpenTelemetry Collector Contrib para MySQL para monitorar sua instância. O OpenTelemetry Collector Contrib é um projeto mantido pela comunidade que coleta dados de telemetria do MySQL e os envia para o New Relic.

Por padrão, o OpenTelemetry Collector Contrib coleta métricas limitadas do MySQL. Para enviar métricas de desempenho de consulta, evento de espera, sessão e cliente, você precisará configurar o OpenTelemetry Collector Contrib. Este guia mostra como configurá-lo para coletar métricas avançadas do MySQL e enviá-las para o New Relic.

<Callout variant="tip" title="Observação">
Esta página aborda o `mysqlreceiver` da comunidade fornecido no binário `otelcol-contrib` padrão. Se você estiver usando a distribuição do New Relic (NRDOT), consulte [MySQL auto-hospedado](/docs/opentelemetry/db360/mysql/introduction) em vez disso.
</Callout>

<Steps>
<Step>
## Pré-requisitos [#prerequisites]

* OpenTelemetry Collector Contrib (`otelcol-contrib`) instalado e configurado no seu sistema. Você pode fazer o download do release mais recente na página de [releases do OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector-releases/releases).
* `performance_schema` habilitado na instância monitorada do MySQL/MariaDB (ativado por padrão desde o MySQL 5.6.6).
</Step>

<Step>
## Habilite as métricas da interface [#enable]

Você pode enriquecer sua experiência na plataforma New Relic adicionando e habilitando métricas em seu arquivo de configuração `otelcol-contrib`. Usando a configuração fornecida nesta seção, você pode preencher dados para as seguintes páginas na plataforma New Relic:

* <DNT>Overview</DNT>
* <DNT>Query performance</DNT>
* <DNT>Wait events</DNT>
* <DNT>Sessions</DNT>
* <DNT>Clients</DNT>

<CollapserGroup>
<Collapser id="overview" title="Ativar métricas da página Overview">
A página <DNT>Overview</DNT> exibe uma visão de alto nível da sua instância do MySQL, incluindo métricas principais, como conexões, integridade do pool de buffers, I/O, bloqueio, tamanho da tabela e taxa de consulta lenta. `mysql.commands` e `mysql.innodb.data_file.io` também alimentam a vinculação APM-DB, a navegação cruzada entre o trace de um serviço APM e sua atividade de consulta do MySQL.

Para preencher os dados da página <DNT>Overview</DNT> na plataforma New Relic, adicione a seguinte configuração ao arquivo de configuração `otelcol-contrib`:

```yaml
receivers:
  mysql:
    metrics:
      mysql.query.count:
        enabled: true
      mysql.query.slow.count:
        enabled: true
      mysql.table.size:
        enabled: true
      mysql.commands:
        enabled: true
      mysql.innodb.data_file.io:
        enabled: true
```
</Collapser>

<Collapser id="query-performance" title="Ativar Métricas de Desempenho de Consulta, Sessão, Espera e Cliente">
Para preencher os dados das páginas <DNT>Query performance</DNT>, <DNT>Wait events</DNT>, <DNT>Sessions</DNT> e <DNT>Clients</DNT>:

* Desempenho de consulta: exibe informações detalhadas sobre as consultas em execução na sua instância do MySQL nas seguintes guias:

  * Consultas normalizadas: exibe a contagem de execuções e a duração média por consulta.
  * Amostras de consulta: exibe execuções de consultas individuais, incluindo duração, tipo de espera, banco de dados, usuário do BD e host do cliente.

* Eventos de espera: exibe o tipo de espera e o tempo de espera das instruções que estavam aguardando quando amostradas.

* Sessões: exibe informações sobre as sessões conectadas à sua instância do MySQL, incluindo contagens de sessão, status da sessão e detalhes de sessões individuais.

* Clientes: exibe informações sobre os clientes conectados à sua instância do MySQL, incluindo usuários de banco de dados conectados e detalhes do host do cliente.

Adicione a seguinte configuração ao seu arquivo de configuração `otelcol-contrib`:

```yaml
receivers:
  mysql:
    events:
      db.server.query_sample:
        enabled: true
      db.server.top_query:
        enabled: true
      db.server.query_plan:
        enabled: true
    top_query_collection:
      lookback_time: 60
      max_query_sample_count: 1000
      top_query_count: 250
      collection_interval: 60s
    query_sample_collection:
      max_rows_per_query: 100
```

<Callout variant="important">
`db.server.query_plan` requer que pelo menos `db.server.top_query` ou `db.server.query_sample` também seja habilitado. Habilitá-lo sozinho é um erro de validação de configuração.
</Callout>

<Callout variant="tip" title="Observação">
O receiver do MySQL da comunidade não oferece suporte à coleta de procedimentos armazenados ou à detecção de sessões bloqueadas. Sessões e clientes são preenchidos, mas o bloqueador de uma sessão bloqueada não é mostrado.
</Callout>
</Collapser>
</CollapserGroup>
</Step>

<Step>
## Reinicie o OpenTelemetry Collector [#restart]

Reinicie o OpenTelemetry Collector para aplicar as alterações de configuração executando o seguinte comando:

```bash
sudo systemctl restart otelcol-contrib
```
</Step>
