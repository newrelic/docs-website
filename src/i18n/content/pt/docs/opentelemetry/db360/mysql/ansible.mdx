Você pode instalar e configurar o NRDOT Collector para monitoramento do MySQL usando a role `newrelic.newrelic_install` do Ansible. A role instala o coletor, cria o usuário de monitoramento e configura o coletor em uma única play.

<Callout variant="tip" title="Instalação guiada">
  Para instalar pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; MySQL (Database 360)](https://onenr.io/0oQDYBNG1wy)** </DNT>. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.
    * MySQL 5.7 ou superior.
    * Ansible Core 2.13 ou 2.14, Python 3.10 e as coleções `ansible.windows` e `ansible.utils`.
    * Um host coletor Linux executando Debian/Ubuntu ou RHEL/CentOS.
    * Para MySQL auto-hospedado: acesso administrativo ao seu servidor MySQL (a conta `root` ou equivalente), usando autenticação baseada em senha.
    * Para MySQL ou Aurora no AWS RDS: conectividade de rede do host do coletor para o endpoint do RDS, e o nome de usuário e senha mestre do RDS.
    * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp) para sua região.

    Para requisitos detalhados, consulte [Compatibilidade e pré-requisitos](/docs/opentelemetry/db360/mysql/compatibility).
  </Step>

  <Step>
    ## Instale a função [#ansible-install-role]

    ```bash
    ansible-galaxy install newrelic.newrelic_install
    ```

    Certifique-se de que as coleções necessárias também estejam instaladas:

    ```bash
    ansible-galaxy collection install ansible.windows ansible.utils
    ```
  </Step>

  <Step>
    ## Configure o playbook [#ansible-configure]

    <CollapserGroup>
      <Collapser id="ansible-host" title="MySQL auto-hospedado">
        Esta role monitora uma ou mais instâncias do MySQL a partir de um único coletor. Em vez de um único conjunto de host/porta/credencial, ele lê dois arquivos que já devem existir no host de destino: um arquivo de instância (YAML) listando cada instância a ser monitorada e um arquivo de segredos (`KEY=VALUE`) com um login e senha de administrador para cada uma, indexados para corresponder. Consulte a página de [instalação da CLI](/docs/opentelemetry/db360/mysql/cli/#cli-install) para ver os formatos exatos dos arquivos.

        Crie um arquivo chamado `playbook.yml` e copie o seguinte conteúdo para ele. Defina `targets` como `mysql-otel` e substitua os valores de espaço reservado pelos seus:

        ```yaml
        - name: Install New Relic NRDOT for MySQL
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mysql-otel
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MYSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MYSQL_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_MYSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
        ```

        <Callout variant="important">
          A função se conecta ao MySQL via TCP usando uma senha, portanto, a conta de administrador no seu arquivo de segredos deve usar autenticação baseada em senha. Em algumas instalações do Debian/Ubuntu, `root`@`localhost` usa por padrão o plug-in `auth_socket` (sem senha, apenas soquete local), o que não funcionará aqui. Altere-o antes de executar o playbook:

          ```bash
          mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '<password>';"
          ```
        </Callout>

        <Callout variant="tip">
          Para habilitar o logging de depuração, adicione `verbosity: "debug"` em `vars` no playbook.
        </Callout>

      <Collapser id="ansible-rds" title="MySQL ou Aurora no AWS RDS">
        Esta função monitora um ou mais endpoints do RDS MySQL ou Aurora a partir de um único coletor, usando o mesmo padrão de arquivo de instâncias/arquivo de segredos que o auto-hospedado (ambos os arquivos já devem existir no host de destino). Crie um arquivo chamado `playbook.yml` e copie o seguinte conteúdo para ele. Defina `targets` como `mysql-otel-rds` e substitua os valores de espaço reservado pelos seus:

        ```yaml
        - name: Install New Relic NRDOT for MySQL on RDS
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - mysql-otel-rds
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_MYSQL_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
            NR_CLI_MYSQL_INSTANCES_FILE: <path to the instances YAML file on the target host, using RDS endpoints as host>
            NR_CLI_MYSQL_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
        ```

        <Callout variant="tip">
          Para habilitar o logging de depuração, adicione `verbosity: "debug"` em `vars` no playbook.
        </Callout>

  <Step>
    ## Execute o playbook [#ansible-run]

    ```bash
    ansible-playbook -i <inventory_file> <playbook_file>.yml
    ```
  </Step>

  <Step>
    ## Encontre e use seus dados [#find]

    Assim que seus dados estiverem sendo coletados, você poderá acessar o monitoramento abrangente do banco de dados MySQL por meio da interface do New Relic.

    Para encontrar a entidade de banco de dados MySQL no New Relic:

    1. Vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; All capabilities &gt; Databases**</DNT>.
    2. Na dropdown **<DNT>Entity type</DNT>**, selecione <DNT>**MySQL instance**</DNT> e clique em <DNT>**Apply**</DNT>.
    3. Selecione seu banco de dados MySQL na lista de entidades.
  </Step>
