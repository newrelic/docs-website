É possível instalar e configurar o NRDOT Collector para o monitoramento do Oracle Database usando a função `newrelic.newrelic_install` do Ansible. A função instala o coletor, cria o usuário do banco de dados de monitoramento e configura o coletor em um único play.

<Callout variant="tip" title="Instalação guiada">
  Para instalar pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.
    * Oracle Database 19c ou posterior.
    * Ansible Core 2.13 ou 2.14, Python 3.10 e as coleções `ansible.windows` e `ansible.utils`.
    * Para Oracle auto-hospedado: Oracle Linux 7, 8 ou 9, com acesso SSH (com encaminhamento de agente) ao host do Oracle Database onde o usuário SSH pode executar `sudo su - oracle` sem um prompt de senha.
    * Para Oracle no AWS RDS: um host do coletor executando Debian/Ubuntu ou CentOS/RHEL/OEL.
    * Para Oracle Autonomous Database (ADB): um host do coletor executando Debian/Ubuntu ou CentOS/RHEL/OEL, com o Oracle Instant Client (`sqlplus`) instalado e em `PATH`; o IP de saída de cada instância permitido em sua lista de controle de acesso do ADB; e a Oracle Wallet de cada instância baixada e descompactada em seu próprio diretório no host de destino.
  </Step>

  <Step>
    ## Instale a função [#install-role]

    ```bash
    ansible-galaxy install newrelic.newrelic_install
    ```
  </Step>

  <Step>
    ## Configure o playbook [#configure]

    <CollapserGroup>
      <Collapser id="ansible-host" title="Oracle Database auto-hospedado">
        Esta função monitora uma ou mais instâncias do Oracle Database (cada uma acessível via SSH) a partir de um único coletor. Em vez de um único conjunto de host/contêiner/credencial, ele lê um arquivo de instâncias (YAML) que já deve existir no host de destino, listando cada instância a ser monitorada, e, opcionalmente, um arquivo de segredos para fixar as senhas do usuário de monitoramento em vez de gerá-las automaticamente. Consulte a [instalação da CLI](/docs/opentelemetry/db360/oracle/cli/#install) para obter os formatos exatos dos arquivos.

        Crie um arquivo chamado `playbook.yml` e copie o seguinte conteúdo para ele. Defina `targets` como `oracle-otel` e substitua os valores de espaço reservado pelos seus:

        ```yaml
        - name: Install New Relic NRDOT for Oracle Database
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - oracle-otel
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_ORACLE_SECRETS_FILE: <optional path to a secrets file pinning monitoring passwords, on the target host>
            NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
        ```

        <Callout variant="tip">
          Para habilitar o logging de depuração, adicione `verbosity: "debug"` em `vars` no playbook.
        </Callout>

      <Collapser id="ansible-rds" title="Oracle Database no AWS RDS">
        Esta função monitora um ou mais endpoints do RDS Oracle a partir de um único coletor, usando o mesmo padrão de arquivo de instâncias/arquivo de segredos que o auto-hospedado (ambos os arquivos já devem existir no host de destino). Crie um arquivo chamado `playbook.yml` e copie o seguinte conteúdo para ele. Defina `targets` como `oracle-otel-rds` e substitua os valores de espaço reservado pelos seus:

        ```yaml
        - name: Install New Relic NRDOT for Oracle Database on RDS
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - oracle-otel-rds
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_ORACLE_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
            NR_CLI_ORACLE_CONFIG_PRESET: <1 Basic, 2 Advanced, default 1>
        ```

        <Callout variant="tip">
          Para habilitar o logging de depuração, adicione `verbosity: "debug"` em `vars` no playbook.

      <Collapser id="ansible-adb" title="Banco de dados autônomo Oracle (ADB)">
        Esta função monitora uma ou mais instâncias do Oracle Autonomous Database (ADB) a partir de um único coletor, usando o mesmo padrão de arquivo de instâncias/arquivo de segredos do RDS (ambos os arquivos já devem existir no host de destino, e cada instância também precisa de sua própria Oracle Wallet baixada e descompactada nesse host). Consulte a [instalação da CLI](/docs/opentelemetry/db360/oracle/cli/#install) para obter os formatos exatos dos arquivos. Crie um arquivo chamado `playbook.yml` e copie o seguinte conteúdo para ele. Defina `targets` como `oracle-otel-adb` e substitua os valores de espaço reservado pelos seus:

        ```yaml
        - name: Install New Relic NRDOT for Oracle Autonomous Database
          hosts: all
          roles:
            - role: newrelic.newrelic_install
          vars:
            targets:
              - oracle-otel-adb
          environment:
            NEW_RELIC_API_KEY: <API key>
            NEW_RELIC_ACCOUNT_ID: <Account ID>
            NEW_RELIC_REGION: <Region>
            NR_CLI_ORACLE_INSTANCES_FILE: <path to the instances YAML file on the target host>
            NR_CLI_ORACLE_SECRETS_FILE: <path to the secrets file (KEY=VALUE per instance) on the target host>
        ```

        <Callout variant="tip">
          Para habilitar o logging de depuração, adicione `verbosity: "debug"` em `vars` no playbook.
