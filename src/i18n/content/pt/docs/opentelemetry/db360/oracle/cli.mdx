Você pode instalar e configurar o NRDOT Collector para o monitoramento do banco de dados Oracle usando a CLI do New Relic. A CLI instala o coletor, cria o usuário do banco de dados de monitoramento e configura o coletor em um único comando.

<Callout variant="tip" title="Instalação guiada">
  Para instalar pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)** </DNT>. Esta página aborda apenas a instalação manual.
</Callout>

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * Uma conta New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#overview-keys) válida.
    * Um [ID de conta](/docs/accounts/accounts-billing/account-structure/account-id) da New Relic.
    * Oracle Database 19c ou posterior.
    * Para Oracle auto-hospedado: Oracle Linux 7, 8 ou 9, com `curl` e `systemd` instalados, e acesso SSH (com encaminhamento de agente) ao host do banco de dados Oracle onde o usuário SSH pode executar `sudo su - oracle` sem um prompt de senha.
    * Para Oracle na AWS RDS: um host do coletor executando Debian/Ubuntu ou CentOS/RHEL/OEL, com `curl` e `systemd` instalados, e conectividade de rede do host do coletor para o endpoint do RDS Oracle.
    * Para Oracle Autonomous Database (ADB): um host do coletor executando Debian/Ubuntu ou CentOS/RHEL/OEL, com `curl`, `systemd` e Oracle Instant Client (`sqlplus`) instalados e em `PATH`; o IP de saída de cada instância permitido em sua lista de controle de acesso do ADB; e a Oracle Wallet de cada instância baixada e descompactada em seu próprio diretório no host do coletor.
  </Step>

  <Step>
    ## Instale e configure o NRDOT Collector [#install]

    <CollapserGroup>
      <Collapser id="cli-host" title="Oracle Database auto-hospedado">
        Esta receita monitora uma ou mais instâncias de banco de dados Oracle (cada uma acessível via SSH) a partir de um único coletor. Em vez de solicitar um único conjunto de host/contêiner/credencial, ela lê um arquivo de instâncias (YAML) que lista cada instância a ser monitorada e, opcionalmente, um arquivo de segredos para fixar senhas específicas de usuário de monitoramento em vez de gerá-las automaticamente.

        Antes de executar este comando, tenha em mãos:

        * Acesso SSH (com encaminhamento de agente) a cada host do banco de dados Oracle listado, onde cada `ssh_user` pode executar `sudo su - oracle` sem um prompt de senha
        * Tipo de contêiner por instância (CDB para todos os PDBs ou um único nome de PDB)
        * Nome do serviço CDB ou PDB por instância
        * Se deseja métricas Básicas ou Avançadas

        1. Crie o arquivo de instâncias. Adicione uma entrada por instância do banco de dados Oracle que você deseja que este coletor monitore; apenas uma entrada se você estiver monitorando apenas uma única instância:

           ```bash
           cat > ~/oracle-instances.yml << 'EOF'
           instances:
             - host: dbhost1.example.com
               port: 1521
               ssh_user: opc
               container_type: 1
               pdb_name:
               service: ORCLCDB
               login_name: newrelic
           EOF
           ```

           `container_type` é `1` para CDB (monitora todos os PDBs, cria um usuário `c##<login_name>` comum) ou `2` para um único PDB (`pdb_name` necessário apenas nesse caso). Insira `login_name` sem o prefixo `c##`: a receita o adiciona para você no modo CDB.

        2. (Opcional) Crie um arquivo de segredos para definir uma senha fixa de usuário de monitoramento por instância em vez de permitir que a receita gere uma automaticamente. O Oracle auto-hospedado não precisa de credenciais de administrador aqui. O usuário de monitoramento é criado via SSH e acesso SYSDBA autenticado pelo sistema operacional:

           ```bash
           umask 077
           cat > ~/oracle-secrets.env << 'EOF'
           NR_CLI_ORACLE_LOGIN_PASSWORD_1=SomeFixedPassword1
           EOF
           chmod 600 ~/oracle-secrets.env
           ```

           Deixe o caminho do arquivo de segredos em branco (ou aponte-o para um arquivo que não existe) para gerar automaticamente uma senha aleatória para cada instância.

        Execute isso a partir de um host com acesso SSH (com encaminhamento de agente) para cada host do banco de dados Oracle listado em seu arquivo de instância:

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle
        ```

      <Collapser id="cli-rds" title="Oracle Database no AWS RDS">
        Esta receita monitora um ou mais endpoints do RDS Oracle a partir de um único coletor, usando um arquivo de instâncias e um arquivo de segredos.

        Antes de executar este comando, tenha em mãos:

        * Endpoint do RDS Oracle, porta do listener e nome do serviço de banco de dados para cada instância
        * Nome de usuário e senha mestre do RDS para cada instância
        * Se deseja métricas Básicas ou Avançadas

        1. Criar o arquivo de instâncias (uma entrada por endpoint do RDS Oracle a ser monitorado por este coletor; ainda assim, apenas uma entrada caso seja monitorada apenas uma única instância):

           ```bash
           cat > ~/oracle-instances.yml << 'EOF'
           instances:
             - host: rds-orders.abcdef123.us-east-1.rds.amazonaws.com
               port: 1521
               service: ORDERSDB
               login_name: newrelic
           EOF
           ```

        2. Crie o arquivo de segredos com o nome de usuário e a senha mestre do RDS para cada instância, indexado para corresponder à ordem do arquivo de instâncias. Você também pode, opcionalmente, definir uma senha fixa de usuário de monitoramento por instância. Omita para gerar uma automaticamente:

           ```bash
           umask 077
           cat > ~/oracle-secrets.env << 'EOF'
           NR_CLI_ORACLE_ADMIN_USER_1=admin
           NR_CLI_ORACLE_ADMIN_PASSWORD_1=YourMasterPassword1
           EOF
           chmod 600 ~/oracle-secrets.env
           ```

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle-rds
        ```

      <Collapser id="cli-adb" title="Banco de dados autônomo Oracle (ADB)">
        Esta receita monitora uma ou mais instâncias do Oracle Autonomous Database (ADB) a partir de um único coletor, usando um arquivo de instâncias e um arquivo de segredos. Cada instância se conecta por meio de TLS mútuo (padrão do ADB) usando sua própria carteira baixada. Não compartilhar um diretório de carteira entre instâncias.

        Antes de executar este comando, tenha em mãos:

        * Para cada instância: sua string de conexão (`host`, `port`, `service`, em **Database connection &gt; Connection strings** do console do ADB)
        * Para cada instância: sua Oracle Wallet baixada (**Database connection &gt; Download wallet** do console do ADB), descompactada em seu próprio diretório no host do coletor
        * Nome de usuário e senha do administrador do ADB (`ADMIN`) para cada instância

        1. Crie o arquivo de instâncias. Adicione uma entrada por instância do ADB que você deseja que este coletor monitore; apenas uma entrada se você estiver monitorando apenas uma única instância:

           ```bash
           cat > ~/adb-instances.yml << 'EOF'
           instances:
             - host: adb1.adb.us-ashburn-1.oraclecloud.com
               port: 1522
               service: myadb1_high
               login_name: newrelic
               wallet_dir: /home/opc/wallet1
           EOF
           ```

           `wallet_dir` é o diretório onde a carteira dessa instância foi descompactada (deve conter `cwallet.sso` e `sqlnet.ora`); uma instância com um diretório de carteira ausente ou inválido é ignorada em vez de falhar toda a instalação.

        2. Crie o arquivo de segredos com o nome de usuário e a senha do administrador do ADB para cada instância, indexado para corresponder à ordem do arquivo de instâncias. Opcionalmente, você também pode definir uma senha fixa de usuário de monitoramento por instância. Omita para gerar uma automaticamente:

           ```bash
           umask 077
           cat > ~/adb-secrets.env << 'EOF'
           NR_CLI_ORACLE_ADMIN_USER_1=ADMIN
           NR_CLI_ORACLE_ADMIN_PASSWORD_1=YourAdminPassword1
           EOF
           chmod 600 ~/adb-secrets.env
           ```

        Executar a partir de um host que tenha o `sqlplus` (Oracle Instant Client) no `PATH` e conectividade de rede (mTLS) com cada instância do ADB listada:

        ```bash
        curl -Ls https://download.newrelic.com/install/newrelic-cli/scripts/install.sh | bash && sudo NEW_RELIC_API_KEY=INSERT_YOUR_API_KEY NEW_RELIC_ACCOUNT_ID=INSERT_YOUR_ACCOUNT_ID NEW_RELIC_REGION=INSERT_YOUR_REGION /usr/local/bin/newrelic install -n nrdot-collector-oracle-adb
        ```
