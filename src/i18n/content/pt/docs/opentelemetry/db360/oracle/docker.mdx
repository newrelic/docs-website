Obtenha insights abrangentes sobre o desempenho do seu banco de dados Oracle com monitoramento de banco de dados, análise de consulta e métricas de integridade do sistema usando o New Relic Distribution of OpenTelemetry (NRDOT) Collector, executado como um contêiner irmão de uma instância de banco de dados Oracle que já está em execução no Docker.

<Callout variant="tip" title="Instalação guiada">
  Para instalar pela interface da New Relic, acesse <DNT>**[one.newrelic.com &gt; Integrations &amp; Agents &gt; Oracle (Database 360)](https://onenr.io/0kjnebKW7Ro)**</DNT>. Esta página aborda apenas o caminho de instalação do Docker.
</Callout>

<Callout variant="tip">
  Prefere automatizar isso em escala? Consulte a [instalação do Ansible](/docs/opentelemetry/db360/oracle/ansible), a [instalação do Chef](/docs/opentelemetry/db360/oracle/chef) ou a [instalação do chart do Helm](/docs/opentelemetry/db360/oracle/helm) para Kubernetes.
</Callout>

## Pré-requisitos [#prerequisites]

Antes de começar, certifique-se de ter o seguinte:

* Docker instalado no host.
* Um contêiner de banco de dados Oracle já em execução (banco de dados Oracle `19c` ou posterior), com `sqlplus` disponível dentro dele.
* A senha `sys` para esse contêiner.
* Uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) do New Relic válida.
* Conectividade de rede do contêiner do coletor para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp).

<Steps>
  <Step>
    ## Configurar usuário do banco de dados e conceder privilégios [#database-user]

    Crie um usuário de monitoramento e conceda a ele as visualizações necessárias para a coleta de métricas, consultas e eventos executando SQL em seu contêiner Oracle com `docker exec`. Escolha a guia que corresponde à sua implantação, seja um banco de dados de contêiner (CDB) multilocatário ou um único banco de dados conectável (PDB):

    <CollapserGroup>
      <Collapser id="docker-cdb" title="Banco de dados de contêiner (CDB)">
        Isso cria um usuário comum (obrigatório usar o prefixo `C##`) e concede a ele visibilidade em todos os PDBs sob o CDB. Substitua `<YOUR_ORACLE_CONTAINER_NAME>`, `<YOUR_SYS_PASSWORD>`, `<YOUR_DB_USERNAME>` e `<YOUR_DB_PASSWORD>` pelos seus próprios valores:

        ```bash
        docker exec -i <YOUR_ORACLE_CONTAINER_NAME> sqlplus sys/'<YOUR_SYS_PASSWORD>' as sysdba << 'EOF'
        ALTER SESSION SET CONTAINER = CDB$ROOT;

        -- Create the common user and set container-data visibility
        CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<YOUR_DB_PASSWORD>" CONTAINER=ALL;
        GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;

        -- Grant system and dynamic performance views
        GRANT SELECT ON V_$INSTANCE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$DATABASE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CONTAINERS                 TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$DATAFILE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SYSSTAT                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CON_SYSSTAT                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SYSMETRIC                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$CON_SYSMETRIC              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SESSION                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$RESOURCE_LIMIT             TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$OSSTAT                     TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SGAINFO                    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ROWCACHE                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$PARAMETER                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_TABLESPACES               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_FREE_SPACE                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_RECYCLEBIN                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SQL                        TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL    TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$LOCK                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$SESSION_EVENT              TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON DBA_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$PDBS                       TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_SERVICES                  TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_DATA_FILES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_PROCEDURES                TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON CDB_OBJECTS                   TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ASM_DISKGROUP_STAT          TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
        GRANT SELECT ON V_$ASM_DISK_STAT               TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;

        EXIT;
        EOF
        ```

        <Callout variant="tip">
          O prefixo `C##` é exigido pela Oracle para usuários comuns. As duas últimas permissões (`V_$ASM_DISKGROUP_STAT` e `V_$ASM_DISK_STAT`) são exigidas apenas se desejar coletar [métricas de disco e grupo de discos do ASM](/docs/opentelemetry/db360/oracle/metrics-reference/#asm). Ignore-as se não utilizar o ASM.
        </Callout>
      </Collapser>

        GRANT SELECT ON V_$ROWCACHE                   TO <YOUR_DB_USERNAME>;

        GRANT SELECT ON DBA_TABLESPACE_USAGE_METRICS  TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_TABLESPACES               TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_DATA_FILES                TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_FREE_SPACE                TO <YOUR_DB_USERNAME>;

        GRANT SELECT ON V_$LOCK                       TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON V_$SESSION_EVENT              TO <YOUR_DB_USERNAME>;
        GRANT SELECT ON DBA_PROCEDURES                TO <YOUR_DB_USERNAME>;

        GRANT SELECT ON V_$PDBS                       TO <YOUR_DB_USERNAME>;

  <Step>
    ## Garantir a conectividade de rede do Docker [#network]

    Crie uma rede compartilhada definida pelo usuário (se você ainda não tiver uma) e conecte seu contêiner Oracle a ela, para que o contêiner do coletor possa resolvê-la pelo nome:

    ```bash
    docker network create <YOUR_DOCKER_NETWORK> 2>/dev/null || true
    docker network connect <YOUR_DOCKER_NETWORK> <YOUR_ORACLE_CONTAINER_NAME> 2>/dev/null || true
    ```

    <Callout variant="tip">
      Ambos os comandos podem ser executados novamente com segurança: `|| true` ignora os erros &quot;already exists&quot; ou &quot;already connected&quot; de uma execução anterior.
    </Callout>
  </Step>

    ### Parâmetro de configuração [#configuration-parameters]

    | Parâmetro                                             | Descrição                                                                                                                                                                             |
    | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `<YOUR_ORACLE_CONTAINER_NAME>`                        | O nome (ou nome do host resolvível por DNS do Docker) do seu contêiner do banco de dados Oracle em execução.                                                                          |
    | `<YOUR_DB_USERNAME>`                                  | O usuário de monitoramento que você criou em [Configurar o usuário do banco de dados e conceder privilégios](#database-user) (o prefixo `C##` é adicionado automaticamente para CDB). |
    | `<YOUR_DB_PASSWORD>`                                  | A senha do usuário de monitoramento que você criou em [Configurar usuário do banco de dados e conceder privilégios](#database-user).                                                  |
    | `<YOUR_CDB_SERVICE_NAME>` / `<YOUR_PDB_SERVICE_NAME>` | O nome do serviço Oracle para seu CDB ou PDB.                                                                                                                                         |
    | `<YOUR_NEWRELIC_OTLP_ENDPOINT>`                       | Seu endpoint OTLP da New Relic. Para mais informações, consulte os [endpoints OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp/).                             |
    | `<YOUR_NEWRELIC_LICENSE_KEY>`                         | Sua [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) da New Relic.                                                                                    |
  </Step>

  <Step>
    ## Inicie o contêiner do Collector NRDOT [#start]

    Execute o coletor na mesma rede Docker que o seu contêiner do Oracle:

    ```bash
    docker run -d \
      --name nrdot-collector \
      --network <YOUR_DOCKER_NETWORK> \
      --platform linux/amd64 \
      -v "$PWD/oracle-config.yaml:/etc/nrdot-collector/oracle-config.yaml" \
      newrelic/nrdot-collector:latest \
      --config /etc/nrdot-collector/oracle-config.yaml
    ```

    <Callout variant="tip">
      `--platform linux/amd64` evita incompatibilidades de arquitetura no Apple Silicon e em outros hosts ARM64 onde a própria imagem da Oracle normalmente é fornecida apenas para AMD64. Remova-o se o seu host e as imagens já forem nativos de AMD64.
    </Callout>

    Confirme se o contêiner do coletor está em execução:

    ```bash
    docker ps --filter name=nrdot-collector
    ```

    Se não estiver em execução, verifique os logs em busca de erros. As causas mais comuns são problemas de indentação YAML em `oracle-config.yaml` ou um contêiner do Oracle inacessível:

    ```bash
    docker logs nrdot-collector
    ```

    <Callout variant="tip">
      Após alterar `oracle-config.yaml`, reinicie o contêiner para aplicar suas alterações:

      ```bash
      docker restart nrdot-collector
      ```
    </Callout>
  </Step>

  <Step>
    ## Encontre e use seus dados [#find-use-data]

    Assim que seus dados estiverem sendo coletados, você poderá acessar o monitoramento abrangente do banco de dados Oracle por meio da interface do New Relic.

    Para encontrar sua entidade de banco de dados Oracle no New Relic:

    1. Vá para <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.
    2. Defina os critérios de pesquisa como <DNT>`instrumentation.provider = opentelemetry`</DNT>.
    3. Selecione seu banco de dados Oracle na lista de entidades.
  </Step>
</Steps>
