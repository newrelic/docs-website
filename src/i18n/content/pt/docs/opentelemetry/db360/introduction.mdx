Banco de dados 360 (DB360) oferece uma visão unificada de seus aplicativos, bancos de dados e infraestrutura para que você possa encontrar a causa raiz dos gargalos de banco de dados mais rapidamente. Em vez de alternar entre ferramentas separadas de aplicativo, banco de dados e infraestrutura para descobrir por que uma consulta está lenta, o DB360 modela cada banco de dados como uma entidade de primeira classe e o conecta diretamente aos seus serviços de APM e métricas de host.

O DB360 é construído sobre uma base que prioriza o OpenTelemetry. Você coleta telemetria usando o Collector da New Relic Distribution of OpenTelemetry (NRDOT) ou uma distribuição CNCF OpenTelemetry Collector Contrib.

## O que você ganha [#capabilities]

* **Planos de execução de consulta**: veja o caminho exato de execução que uma consulta percorre, incluindo eventos de espera e bloqueios, para que você possa identificar índices ausentes e outras ineficiências.
* **Estados de espera e rastreamento de bloqueios**: identifique sessões de longa duração, consultas bloqueadoras e workloads que consomem muitos recursos antes que afetem outros workloads no mesmo banco de dados.
* **Correlação entre APM e banco de dados**: vincule os traces do aplicativo diretamente às consultas ao banco de dados, sessões e eventos de espera que eles geram. Para obter mais informações, consulte [Correlação entre APM e banco de dados](/docs/opentelemetry/db360/capabilities/db-apm).
* **Contexto de infraestrutura**: visualize as métricas do banco de dados lado a lado com as métricas de CPU, memória e I/O no nível do host.
* **Visibilidade de nó e banco de dados lógico**: monitore tanto o servidor de banco de dados (nó) quanto os bancos de dados lógicos individuais em execução nele, para que você possa dimensionar a capacidade corretamente e identificar instâncias ociosas ou subutilizadas.

## O que saber antes de começar [#considerations]

* **Correlação de APM**: a vinculação de entidades de banco de dados a traces de APM funciona atualmente com o agente Java e o agente .NET.

* **Cobertura do provedor de nuvem**:

  * **AWS**: RDS, Aurora e auto-hospedados no EC2 são suportados em todos os quatro mecanismos de banco de dados.
  * **Infraestrutura de nuvem Oracle (OCI)**: o banco de dados Oracle é compatível por meio do Autonomous Database.

* **Volume de métricas**: bancos de dados auto-hospedados geralmente expõem mais métricas do que seus equivalentes gerenciados na cloud, já que os provedores de cloud restringem o acesso a alguns componentes internos do banco de dados.

* **Controles de ingestão**: você pode ativar ou desativar categorias de métricas no seu arquivo de configuração do NRDOT para gerenciar o volume de dados que você coleta.
