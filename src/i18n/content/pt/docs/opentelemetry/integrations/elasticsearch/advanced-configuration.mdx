Esta página aborda a configuração opcional para o monitoramento do Elasticsearch além da configuração mínima: clusters seguros, métricas de host, coleta de logs e tags de metadados personalizadas.

## Elasticsearch seguro com autenticação e SSL [#secured]

Adicione autenticação e TLS à sua conexão do Elasticsearch quando seu cluster exigir.

### Requisitos [#secured-requirements]

* Um usuário do Elasticsearch com o privilégio de cluster `monitor` ou `manage` e credenciais válidas para esse usuário.

Para Elasticsearch seguro com autenticação e SSL, modifique a configuração do receiver:

<CollapserGroup>
<Collapser id="secured-nrdot" title="NRDOT">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-otel" title="OTel Collector Contrib">
```yaml
receivers:
  elasticsearch:
    endpoint: "https://<YOUR_ELASTICSEARCH_HOST>:9200"
    username: "<YOUR_ELASTICSEARCH_USERNAME>"
    password: "<YOUR_ELASTICSEARCH_PASSWORD>"
    tls:
      insecure_skip_verify: false
    collection_interval: 15s
```
</Collapser>

<Collapser id="secured-k8s-nrdot" title="Kubernetes: NRDOT (manifesto ou Helm)">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>

<Collapser id="secured-k8s-otel" title="Kubernetes: OTel Collector Contrib">
```yaml
receivers:
  receiver_creator/elasticsearch:
    watch_observers: [k8s_observer]
    receivers:
      elasticsearch:
        rule: type == "pod" && labels["app"] == "elasticsearch"
        config:
          endpoint: 'https://`endpoint`:9200'
          username: "<YOUR_ELASTICSEARCH_USERNAME>"
          password: "<YOUR_ELASTICSEARCH_PASSWORD>"
          tls:
            insecure_skip_verify: false
```
</Collapser>
</CollapserGroup>

### Parâmetro de configuração [#secured-configuration-parameters]

A tabela a seguir descreve os principais parâmetros de configuração usados nos trechos acima:

| Parâmetro                  | Descrição                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `endpoint`                 | A URL do seu cluster Elasticsearch. Use `https://` para um cluster seguro.                                   |
| `username`                 | Um usuário do Elasticsearch com o privilégio de cluster `monitor` ou `manage`.                               |
| `password`                 | A senha desse usuário.                                                                                       |
| `tls.insecure_skip_verify` | Se o certificado TLS do Elasticsearch deve ser verificado. Defina como `false` para habilitar a verificação. |
| `collection_interval`      | O intervalo entre as coletas de métrica. Padrão: `15s`.                                                      |
| `rule` (Apenas Kubernetes) | A regra de correspondência de pod usada para descoberta automática.                                          |

## Coletar métricas do host [#host-metrics]

Para coletar métricas do host, adicione o receptor `hostmetrics`:

<CollapserGroup>
<Collapser id="host-metrics-nrdot" title="NRDOT">
```yaml
receivers:
  hostmetrics:
    collection_interval: 60s
    scrapers:
      cpu:
        metrics:
          system.cpu.utilization: { enabled: true }
          system.cpu.time: { enabled: true }
      load:
        metrics:
          system.cpu.load_average.1m: { enabled: true }
          system.cpu.load_average.5m: { enabled: true }
          system.cpu.load_average.15m: { enabled: true }
      memory:
        metrics:
          system.memory.usage: { enabled: true }
          system.memory.utilization: { enabled: true }
      disk:
        metrics:
          system.disk.io: { enabled: true }
          system.disk.operations: { enabled: true }
      filesystem:
        metrics:
          system.filesystem.usage: { enabled: true }
          system.filesystem.utilization: { enabled: true }
      network:
        metrics:
          system.network.io: { enabled: true }
          system.network.packets: { enabled: true }
      process:
        metrics:
          process.cpu.utilization:
            enabled: true
```

E adicione aos pipelines de serviço:

```yaml
service:
  pipelines:
    metrics/host:
      receivers: [hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="host-metrics-otel" title="OTel Collector Contrib">

### Parâmetro de configuração [#host-metrics-configuration-parameters]

A tabela a seguir descreve os principais parâmetros de configuração usados nos trechos acima:

| Parâmetro             | Descrição                                                                                                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `collection_interval` | O intervalo entre as coletas de métricas do host. Padrão: `60s`.                                                                                                                                                 |
| `scrapers`            | As categorias de métrica no nível do host a serem coletadas (`cpu`, `load`, `memory`, `disk`, `filesystem`, `network`, `process`). Desative qualquer métrica de que você não precise definindo `enabled: false`. |

## Coletar logs do Elasticsearch [#logs]

### Requisitos [#logs-requirements]

* Acesso de leitura aos seus arquivos de log do Elasticsearch, para qualquer conta que execute o serviço do coletor:

  * Host Linux: permissão de leitura em `/var/log/elasticsearch/`
  * Docker: permissão de leitura em `/var/lib/docker/containers/` (root ou associação ao grupo Docker)

Para coletar logs do Elasticsearch, adicione o receiver `filelog`.

<CollapserGroup>
<Collapser id="logs-nrdot" title="NRDOT">
Certifique-se de que a conta que executa o serviço do coletor (`nrdot-collector`) tenha acesso de leitura aos seus arquivos de log do Elasticsearch.

**Se o Elasticsearch for executado em um host Linux, use esta configuração:**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Se o Elasticsearch for executado no Docker, use esta configuração:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

E adicione aos pipelines de serviço:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="logs-otel" title="OTel Collector Contrib">
Certifique-se de que a conta que executa o serviço do coletor (`otelcol-contrib`) tenha acesso de leitura aos seus arquivos de log do Elasticsearch.

**Se o Elasticsearch for executado em um host Linux, use esta configuração:**

```yaml
receivers:
  filelog:
    include:
      - /var/log/elasticsearch/elasticsearch.log
      - /var/log/elasticsearch/*.log
```

**Se o Elasticsearch for executado no Docker, use esta configuração:**

```yaml
receivers:
  filelog:
    include:
      - /var/lib/docker/containers/*/*.log
    operators:
      - type: move
        from: attributes.log
        to: body
```

E adicione aos pipelines de serviço:

```yaml
service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource/cluster_name_override]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### Parâmetro de configuração [#logs-configuration-parameters]

A tabela a seguir descreve os principais parâmetros de configuração usados nos trechos acima:

| Parâmetro                   | Descrição                                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------------------------ |
| `include`                   | Caminhos do arquivo de log para tail (host Linux) ou caminhos de log do contêiner (Docker).            |
| `operators` (Apenas Docker) | O operador que move a linha de log de `attributes.log` para `body` para que seja exibida corretamente. |

## Adicionar tags de metadados personalizadas [#custom-tags]

Para adicionar tags de metadados personalizadas às suas métricas, use o processador `resource/static_override`:

<CollapserGroup>
<Collapser id="custom-tags-nrdot" title="NRDOT">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>

<Collapser id="custom-tags-otel" title="OTel Collector Contrib">
```yaml
processors:
  resource/static_override:
    attributes:
      - key: env
        value: "production"
        action: upsert
service:
  pipelines:
    metrics/elasticsearch:
      receivers: [elasticsearch]
      processors: [memory_limiter, resourcedetection, resource/cluster_name_override, resource/static_override, attributes/cardinality_reduction, cumulativetodelta, transform/metadata_nullify, batch]
      exporters: [otlphttp]
```
</Collapser>
</CollapserGroup>

### Parâmetro de configuração [#custom-tags-configuration-parameters]

A tabela a seguir descreve os principais parâmetros de configuração usados nos trechos acima:

| Parâmetro | Descrição                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------- |
| `key`     | O nome do atributo a ser adicionado, por exemplo, `env`.                                                 |
| `value`   | O valor do atributo, por exemplo, `production`.                                                          |
| `action`  | A ação a ser aplicada. Defina como `upsert` para adicionar o atributo ou substituí-lo se ele já existir. |

## Reinicie o coletor [#restart]

Após atualizar sua configuração, reinicie o coletor para aplicar as alterações.

<CollapserGroup>
<Collapser id="restart-nrdot" title="NRDOT (auto-hospedado)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Collapser>

<Collapser id="restart-otel" title="OTel Collector Contrib (auto-hospedado)">
```bash
sudo systemctl daemon-reload
sudo systemctl restart otelcol-contrib.service
```
</Collapser>

<Collapser id="restart-k8s" title="Kubernetes (NRDOT ou OTel Collector Contrib)">
Para uma instalação de manifesto, reinicie a implantação:

```bash
kubectl rollout restart deployment nr-k8s-otel-collector-deployment -n newrelic
```

Para uma instalação do Helm, execute novamente o mesmo comando `helm upgrade --install ... -f values.yaml` da sua etapa de instalação para implementar a configuração atualizada.
</Collapser>
</CollapserGroup>

## Verifique suas alterações [#verify]

Após reiniciar o coletor, confirme se a alteração entrou em vigor:

* **Cluster protegido**: execute novamente a consulta de coleta de dados da sua página de instalação. Se as métricas estiverem fluindo sem erros de TLS ou de autenticação nos logs do coletor, a conexão protegida está funcionando.

* **Métricas de host**: Execute esta consulta:

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'system.%' SINCE 10 minutes ago
  ```

* **Logs do Elasticsearch**: execute esta consulta:

  ```sql
  FROM Log SELECT count(*) SINCE 10 minutes ago
  ```

  Ajuste a cláusula `WHERE` para corresponder aos seus próprios atributos de log.

* **Tags personalizadas**: execute esta consulta, usando a tag de exemplo de [Adicionar tags de metadados personalizadas](#custom-tags):

  ```sql
  FROM Metric SELECT count(*) WHERE metricName LIKE 'elasticsearch.%' AND env = 'production' SINCE 10 minutes ago
  ```

Se você não visualizar dados em cerca de 5 minutos, consulte a [resolução de problemas do Elasticsearch](/docs/opentelemetry/integrations/elasticsearch/troubleshooting).
