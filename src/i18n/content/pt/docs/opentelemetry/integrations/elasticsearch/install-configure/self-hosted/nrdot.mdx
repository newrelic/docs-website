Use este guia para instalar e configurar o NRDOT para monitorar um cluster Elasticsearch auto-hospedado em um servidor Linux ou VM. Uma vez configurado, o coletor exporta as métricas do seu cluster Elasticsearch para o New Relic. Para métricas de host, logs e tags personalizadas, consulte [Configuração avançada](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration).

## Compatibilidade e requisitos [#requirements]

### Suportado

* Elasticsearch 7.16 ou posterior

### Você precisa

* Uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key) da New Relic
* Privilégios de root ou sudo no host
* Privilégios de administrador de cluster do Elasticsearch com privilégio de cluster `monitor` ou `manage` (consulte os [Privilégios de segurança do Elasticsearch](https://www.elastic.co/guide/en/elasticsearch/reference/current/security-privileges.html))
* Conectividade HTTPS de saída (porta 443) para o [endpoint OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) da New Relic
* Um nome de usuário e uma senha do Elasticsearch (se o seu cluster exigir autenticação)

<Steps>
<Step>
## Instalar o coletor NRDOT [#install]

Instale o coletor NRDOT e execute-o como um serviço systemd. Consulte [Instalar o NRDOT](/docs/opentelemetry/nrdot/nrdot-collector/).
</Step>

<Step>
## Configure o coletor NRDOT [#configure]

Atualize a configuração padrão do coletor para habilitar o monitoramento do Elasticsearch.

1. Faça backup da configuração padrão do coletor e, em seguida, abra-o para edição:

   ```bash
   sudo cp /etc/nrdot-collector/config.yaml /etc/nrdot-collector/config.yaml.backup
   sudo nano /etc/nrdot-collector/config.yaml
   ```

### Parâmetro de configuração [#configuration-parameters]

A tabela a seguir descreve os principais parâmetros de configuração usados na configuração acima:

| Parâmetro                    | Descrição                                                                                                                                                  |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endpoint`                   | A URL do seu cluster Elasticsearch.                                                                                                                        |
| `collection_interval`        | O intervalo entre as coletas de métrica. O padrão é 15s.                                                                                                   |
| `elasticsearch.cluster.name` | Um nome exclusivo que identifica este cluster no New Relic.                                                                                                |
| `NEW_RELIC_MEMORY_LIMIT_MIB` | O limite de memória, em MiB, para o processador `memory_limiter` do coletor, definido para se adequar ao seu ambiente.                                     |
| `NEWRELIC_LICENSE_KEY`       | Sua chave de licença New Relic.                                                                                                                            |
| `NEWRELIC_OTLP_ENDPOINT`     | O endpoint OTLP da New Relic para a região da sua conta, conforme os [endpoints OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp). |

3. Salve o arquivo de configuração.

Você pode, opcionalmente, adicionar autenticação de cluster seguro, métricas de host, coleta de logs ou tags de metadados personalizadas. Consulte a [Configuração avançada](/docs/opentelemetry/integrations/elasticsearch/advanced-configuration).
</Step>

<Step>
## Defina as variáveis de ambiente [#env-vars]

Defina as credenciais e os detalhes de conexão que o coletor precisa para enviar dados para o New Relic.

```bash
sudo mkdir -p /etc/systemd/system/nrdot-collector.service.d
cat <<EOF | sudo tee /etc/systemd/system/nrdot-collector.service.d/environment.conf
[Service]
Environment="NEWRELIC_OTLP_ENDPOINT=<YOUR_NEWRELIC_OTLP_ENDPOINT>"
Environment="NEWRELIC_LICENSE_KEY=<YOUR_NEWRELIC_LICENSE_KEY>"
Environment="NEW_RELIC_MEMORY_LIMIT_MIB=100"
EOF
```
</Step>

<Step>
## Reinicie o coletor NRDOT [#restart]

Reinicie o coletor para aplicar suas alterações:

```bash
sudo systemctl daemon-reload
sudo systemctl restart nrdot-collector.service
```
</Step>

<Step>
## Verificar coleta de dados [#verify]

Em até -5 minutos após reiniciar o coletor, execute esta consulta no New Relic para confirmar que os dados estão fluindo (substitua `<YOUR_ELASTICSEARCH_CLUSTER_NAME>` pelo nome do seu cluster):

```sql
FROM Metric SELECT count(*)
WHERE metricName LIKE 'elasticsearch.%'
AND elasticsearch.cluster.name = '<YOUR_ELASTICSEARCH_CLUSTER_NAME>'
SINCE 10 minutes ago
```

<Callout variant="tip">
Você também pode verificar o próprio coletor: `nrdot-collector.service` deve relatar `active (running)` (`sudo systemctl status nrdot-collector.service`), sem erros de conexão nos logs (`sudo journalctl -u nrdot-collector.service -f`).
</Callout>

Se você não visualizar dados em cerca de 5 minutos, consulte a [resolução de problemas do Elasticsearch](/docs/opentelemetry/integrations/elasticsearch/troubleshooting).
</Step>

<Step>
## Encontre e use seus dados [#find-and-use]

Assim que o New Relic coletar seus dados, você poderá acessar o monitoramento do Elasticsearch pela interface do New Relic.

Para encontrar seu dashboard do Elasticsearch no New Relic:

1. Vá para <DNT>**one.newrelic.com &gt; Integrations &amp; Agents**</DNT>.
2. Na aba <DNT>**All**</DNT>, clique em <DNT>**Dashboards**</DNT> e, em seguida, pesquise por <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> para visualizar o dashboard.

Ou, na navegação à esquerda:

1. Clique em <DNT>**Dashboards**</DNT>.
2. Pesquise o dashboard <DNT>**Elasticsearch (OpenTelemetry Collector)**</DNT> para visualizá-lo.

Após configurar o monitoramento do Elasticsearch com o NRDOT, você pode:

* [Crie dashboards personalizados](/docs/query-your-data/explore-query-data/dashboards/introduction-dashboards/) para visualizar suas métricas do Elasticsearch
* [Configure alertas](/docs/alerts/create-alert/create-alert-condition/alert-conditions/) para limites críticos de integridade e desempenho do cluster
* [Explore seus dados](/docs/query-your-data/explore-query-data/browse-data/introduction-data-explorer/) usando os recursos de consulta do New Relic
</Step>
</Steps>

<Callout variant="tip">
**Correlacione APM com Elasticsearch**: Para conectar seu aplicativo APM e o cluster Elasticsearch, inclua o atributo de recurso `es.cluster.name="your-cluster-name"` em suas métricas APM. Isso permite que você visualize dados do APM e do Elasticsearch juntos no New Relic.
</Callout>
