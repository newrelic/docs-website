Após configurar o OpenTelemetry Collector para o Linkerd, a telemetria da sua malha flui para o New Relic como eventos `Metric`, `Span` e `Log` no escopo da sua entidade do Linkerd.

## Encontre sua entidade do Linkerd [#find-entity]

1. Acesse [one.newrelic.com](https://one.newrelic.com) e selecione **Entity Explorer**.
2. Pesquise o nome do seu cluster.
3. Selecione sua entidade do Linkerd para abrir o dashboard integrado.

O dashboard integrado abrange a taxa de solicitações, latência p50/p95/p99, taxa de sucesso, conexões TCP, status do certificado mTLS, integridade do plano de controle e inventário de pods em malha.

### Linkerd dashboard [#dashboard]

O dashboard da entidade do Linkerd fornece uma visão geral da telemetria da sua malha de serviço. Isso inclui:

| Seção             | Painéis                                                                  |
| ----------------- | ------------------------------------------------------------------------ |
| Principais        | Conexões TCP, solicitações atendidas por proxies                         |
| Traffic           | Taxa de entrada, taxa de saída                                           |
| Saúde             | Taxa de sucesso, taxa de erros, códigos de status HTTP                   |
| lenta             | Latência de solicitação p50/p95/p99, latência de saída p99               |
| Segurança         | Expiração do certificado mTLS, taxa de atualização do certificado        |
| Plano de controle | Política de autorização, profundidade da fila, taxa de solicitação do CP |
| Topologia         | Uso de memória do proxy, operações por serviço                           |
| Inventário        | Pods na malha                                                            |

## Exemplo de consulta NRQL [#queries]

Substitua `<YOUR_CLUSTER>` pelo nome real do seu cluster em cada consulta.

<table>
  <thead>
    <tr>
      <th>
        Propósito
      </th>

      <th>
        Consulta NRQL
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        Taxa de solicitação por serviço
      </td>

      <td>
        ```sql
        SELECT rate(sum(request_total), 1 minute) AS 'Req/min' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NULL FACET k8s.deployment.name SINCE 30 minutes ago TIMESERIES
        ```
      </td>
    </tr>

    <tr>
      <td>
        Latência p99 por serviço
      </td>

      <td>
        ```sql
        SELECT histogram(response_latency_ms, width: 50, slide_by: 10) FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NULL FACET k8s.deployment.name SINCE 30 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Taxa de sucesso HTTP
      </td>

      <td>
        ```sql
        SELECT sum(response_total) AS 'Total responses', filter(sum(response_total), WHERE classification = 'success') / sum(response_total) * 100 AS 'Success %' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET k8s.deployment.name SINCE 30 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Expiração do certificado mTLS
      </td>

      <td>
        ```sql
        SELECT latest(identity_cert_expiration_timestamp_seconds) AS 'Cert expires (epoch)' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET k8s.deployment.name SINCE 10 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Profundidade da fila do plano de controle
      </td>

      <td>
        ```sql
        SELECT latest(control_plane_queue_length) AS 'Queue depth' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NOT NULL FACET linkerd_control_plane_component SINCE 10 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Conexões TCP abertas
      </td>

      <td>
        ```sql
        SELECT rate(sum(tcp_open_connections), 1 second) AS 'TCP connections' FROM Metric WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET k8s.deployment.name SINCE 30 minutes ago TIMESERIES
        ```
      </td>
    </tr>

    <tr>
      <td>
        Distributed traces por serviço (apenas caminho do APM)
      </td>

      <td>
        ```sql
        SELECT count(*) FROM Span WHERE k8s.cluster.name = '<YOUR_CLUSTER>' FACET service.name SINCE 30 minutes ago
        ```
      </td>
    </tr>

    <tr>
      <td>
        Verifique se os spans de proxy estão sendo coletados com atributos do Linkerd
      </td>

      <td>
        ```sql
        SELECT count(*) FROM Span WHERE k8s.cluster.name = '<YOUR_CLUSTER>' AND linkerd_control_plane_component IS NOT NULL FACET service.name SINCE 10 minutes ago
        ```
      </td>
    </tr>
  </tbody>
</table>

Se a consulta “Verify proxy spans” retornar 0, o processador `transform/linkerd_component_inject` não está em execução ou `linkerd_control_plane_ns` está ausente dos spans. Consulte [Solucionar problemas de monitoramento do Linkerd](/docs/opentelemetry/integrations/linkerd/troubleshooting) para obter as etapas de correção.
