Monitore seus balanceadores de carga HAProxy auto-hospedados com o OpenTelemetry para enviar métricas de desempenho e dados de telemetria para o New Relic.

Você pode escolher entre três opções de coletor:

* **NRDOT:** Distribuição New Relic do OpenTelemetry (recomendado — automatizado via instalação guiada)
* **OTel Collector Contrib:** Collector OpenTelemetry padrão com o [haproxyreceiver](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/haproxyreceiver)
* **Prometheus Receiver:** para ambientes que já usam o endpoint do Prometheus integrado do HAProxy (HAProxy 2.0+)

<Callout variant="tip">
  Se você estiver usando `nri-haproxy` atualmente e quiser mudar para o OpenTelemetry, desative a integração legada e siga as etapas de configuração abaixo. A abordagem baseada em OTel fornece métricas dimensionais com metadados mais ricos (`haproxy.proxy_name`, `haproxy.service_name` por frontend/backend/servidor).
</Callout>

## Antes de você começar [#prerequisites]

Certifique-se de ter:

* [Chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)da New Relic válida

* HAProxy versão 2.0 ou posterior com o [endpoint de estatísticas](https://www.haproxy.com/blog/exploring-the-haproxy-stats-page) habilitado (qualquer versão que suporte estatísticas; o caminho do Prometheus requer 2.0+)

* Um dos seguintes coletores instalado em um host Linux:

  * [coletor NRDOT](https://github.com/newrelic/nrdot-collector-releases/blob/main/distributions/README.md#deb-installation), ou
  * [OpenTelemetry Collector Contrib](https://github.com/open-telemetry/opentelemetry-collector-contrib/releases/latest)

* Acesso à rede do host Linux para:

  * Endpoint de estatísticas do HAProxy (geralmente `http://localhost:8404/stats`)
  * [Endpoint OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp/#configure-endpoint-port-protocol)da New Relic

        <Collapser id="nrdot-step1" title="Passo 1: habilitar o endpoint de estatísticas do HAProxy">
          Se você ainda não ativou o endpoint de estatísticas do HAProxy, adicione o seguinte ao seu `haproxy.cfg`:

          ```text
          frontend stats
              bind *:8404
              stats enable
              stats uri /stats
              stats refresh 10s
          ```

          Recarregue o HAProxy para aplicar a configuração:

          ```bash
          sudo systemctl reload haproxy
          ```

          Verifique se o endpoint de estatísticas está acessível:

          ```bash
          curl -s http://localhost:8404/stats
          ```

          Você deve ver a saída em HTML com as estatísticas do HAProxy.

        <Collapser id="nrdot-step2" title="Etapa 2: configurar o coletor NRDOT">
          Configure o coletor NRDOT para coletar métricas do seu endpoint stats do HAProxy e enviá-las para o New Relic.

          <Callout variant="important">
            **Escolha sua abordagem de monitoramento**:

            * Monitoramento exclusivo do HAProxy (este guia): monitora apenas o desempenho e as métricas do seu balanceador de carga HAProxy
            * Monitoramento completo do servidor: monitora o HAProxy e todo o seu servidor (uso da CPU, memória, espaço em disco, logs do sistema)

            Se você quiser monitorar todo o seu servidor, não apenas o HAProxy, use a [configuração padrão](https://github.com/newrelic/nrdot-collector-releases/blob/main/distributions/nrdot-collector/config.yaml) do coletor NRDOT em vez disso e adicione a configuração do receiver do HAProxy a ela.
          </Callout>

          Crie o arquivo de configuração `/etc/nrdot-collector/haproxy-config.yaml`:

          ```yaml
          receivers:
            haproxy:
              endpoint: http://localhost:8404/stats
              collection_interval: 15s

          processors:
            resourcedetection:
              detectors: [system]
              system:
                resource_attributes:
                  host.name:
                    enabled: true
                  host.id:
                    enabled: true

            batch:

          exporters:
            otlphttp:
              endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
              headers:
                api-key: ${env:NEW_RELIC_LICENSE_KEY}

          service:
            pipelines:
              metrics:
                receivers: [haproxy]
                processors: [resourcedetection, batch]
                exporters: [otlphttp]
          ```

          Esta configuração coleta todas as 17 métricas padrão em um intervalo de 15 segundos. O haproxyreceiver anexa automaticamente os atributos `haproxy.proxy_name`, `haproxy.service_name` e `haproxy.addr` a cada métrica.

          Para habilitar métricas adicionais para uma visibilidade mais profunda (27 no total: 17 padrão + 10 opcionais), adicione métricas opcionais:

          ```yaml
          receivers:
            haproxy:
              endpoint: http://localhost:8404/stats
              collection_interval: 15s
              metrics:
                haproxy.connections.average_time:
                  enabled: true
                haproxy.requests.average_time:
                  enabled: true
                haproxy.responses.average_time:
                  enabled: true
                haproxy.active:
                  enabled: true
                haproxy.backup:
                  enabled: true
                haproxy.downtime:
                  enabled: true
                haproxy.failed_checks:
                  enabled: true
                haproxy.weight:
                  enabled: true
                haproxy.sessions.total:
                  enabled: true
                haproxy.connections.total:
                  enabled: true
          ```

          <Callout variant="tip">
            A configuração otimizada abaixo reduz a ingestão de dados em aproximadamente 85% em comparação com o modo abrangente. Todos os dashboards e métricas clássicas permanecem totalmente funcionais.
          </Callout>

          Para reduzir o volume de ingestão de dados, use um intervalo de 60 segundos e adicione processadores de otimização:

          ```yaml
          receivers:
            haproxy:
              endpoint: http://localhost:8404/stats
              collection_interval: 60s

          processors:
            resourcedetection:
              detectors: [system]
              system:
                resource_attributes:
                  host.name:
                    enabled: true
                  host.id:
                    enabled: true

            transform/metadata_nullify:
              metric_statements:
                - context: metric
                  statements:
                    - set(description, "") where description != ""
                    - set(unit, "") where unit != ""

            resource/remove_attributes:
              attributes:
                - key: os.description
                  action: delete
                - key: telemetry.sdk.version
                  action: delete
                - key: telemetry.sdk.language
                  action: delete
                - key: telemetry.sdk.name
                  action: delete
                - key: host.arch
                  action: delete

            batch:
              send_batch_size: 2048
              timeout: 30s

          exporters:
            otlphttp:
              endpoint: ${env:OTEL_EXPORTER_OTLP_ENDPOINT}
              headers:
                api-key: ${env:NEW_RELIC_LICENSE_KEY}

          service:
            pipelines:
              metrics:
                receivers: [haproxy]
                processors: [resourcedetection, transform/metadata_nullify, resource/remove_attributes, batch]
                exporters: [otlphttp]
          ```

          Atualize a configuração do coletor NRDOT para usar seu arquivo de configuração HAProxy e defina o endpoint OTLP.

          Para obter informações sobre o seu endpoint OTLP, consulte o [endpoint New Relic OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp).

          <Callout variant="important">
            Sua chave de licença já está configurada em `/etc/nrdot-collector/nrdot-collector.conf` durante a instalação. Você só precisa atualizar o caminho do arquivo de configuração e o endpoint OTLP.
          </Callout>

          Atualize o arquivo de configuração do coletor:

          ```bash
          export collector_distro="nrdot-collector"
          export otlp_endpoint="<YOUR_NEWRELIC_OTLP_ENDPOINT>"  # Replace with your region's endpoint

          # Update the config file path to point to haproxy-config.yaml
          sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/haproxy-config.yaml"|' /etc/${collector_distro}/${collector_distro}.conf

          # Add the OTLP endpoint
          echo "OTEL_EXPORTER_OTLP_ENDPOINT=${otlp_endpoint}" | sudo tee -a /etc/${collector_distro}/${collector_distro}.conf > /dev/null
          ```
        </Collapser>

      Use esta abordagem se você já tiver o [endpoint Prometheus](https://www.haproxy.com/blog/haproxy-exposes-a-prometheus-metrics-endpoint) integrado do HAProxy habilitado em seu ambiente, ou se estiver migrando de uma stack de monitoramento baseada no Prometheus.

      <Callout variant="tip">
        **Recomendado:** se você ainda não tem o endpoint do HAProxy Prometheus habilitado, use as guias **coletor NRDOT** ou **OpenTelemetry Collector Contrib** em vez disso. Eles se conectam diretamente ao endpoint de estatísticas do HAProxy sem precisar do módulo exportador do Prometheus.
      </Callout>

      <CollapserGroup>
        <Collapser id="prom-step1" title="Passo 1: Habilite o endpoint do Prometheus do HAProxy">
          Adicione o exportador do Prometheus ao seu frontend de estatísticas em `haproxy.cfg`:

          ```text
          frontend stats
              bind *:8404
              http-request use-service prometheus-exporter if { path /metrics }
              stats enable
              stats uri /stats
              stats refresh 10s
          ```

          A linha principal é `http-request use-service prometheus-exporter if { path /metrics }` — isso intercepta requests para `/metrics` e fornece métricas formatadas para Prometheus por meio do módulo `promex` integrado do HAProxy.

          <Callout variant="tip">
            Se você estiver executando o HAProxy 2.0–2.3, também será necessário adicionar `option http-use-htx` ao frontend. Essa opção se tornou o padrão no HAProxy 2.4+ e não é mais necessária.
          </Callout>

          Recarregue o HAProxy:

          ```bash
          sudo systemctl reload haproxy
          ```

          Verifique o endpoint do Prometheus:

          ```bash
          curl -s http://localhost:8404/metrics | head -20
          ```

          Você deve ver métricas formatadas para Prometheus, como `haproxy_frontend_current_sessions` e `haproxy_backend_http_responses_total`. O HAProxy expõe aproximadamente 204 métricas por meio deste endpoint.

          <Callout variant="important">
            O endpoint do Prometheus requer o HAProxy 2.0 ou posterior. Se você estiver executando uma versão mais antiga, use a guia **OTel Collector Contrib** com o haproxyreceiver, que usa o endpoint de estatísticas CSV e funciona com todas as versões do HAProxy.
          </Callout>
        </Collapser>

        <Collapser id="prom-step3" title="Etapa 3: configurar o coletor">
          Esta configuração coleta o endpoint do Prometheus do HAProxy, filtra para métricas relevantes, transforma os rótulos para corresponder ao esquema de atributo haproxyreceiver (`haproxy.proxy_name`, `haproxy.service_name`) e renomeia as métricas para a convenção de nomenclatura `haproxy.*` do OTel.

          Esta configuração funciona tanto com o NRDOT quanto com o OTel Collector Contrib. Coloque-o no local de configuração apropriado:

          * **NRDOT:** `/etc/nrdot-collector/config.yaml`
          * **OTel Collector Contrib:** `/etc/otelcol-contrib/config.yaml`

          <Callout variant="important">
            Antes de editar: faça backup da sua configuração existente:

            ```bash
            # NRDOT
            sudo cp /etc/nrdot-collector/config.yaml /etc/nrdot-collector/config.yaml.backup
            # OTel Collector Contrib
            sudo cp /etc/otelcol-contrib/config.yaml /etc/otelcol-contrib/config.yaml.backup
            ```
          </Callout>

          Substitua o conteúdo do seu arquivo de configuração do coletor por:

          ```yaml
          receivers:
            prometheus/haproxy_transform:
              config:
                scrape_configs:
                  - job_name: haproxy_transform
                    scrape_interval: 30s
                    static_configs:
                      - targets: ["localhost:8404"]
                    metrics_path: /metrics

          processors:
            # Filter to keep only the metrics we need to transform
            filter/haproxy:
              metrics:
                include:
                  match_type: regexp
                  metric_names:
                    - "haproxy_frontend_bytes_in_total"
                    - "haproxy_frontend_bytes_out_total"
                    - "haproxy_frontend_requests_denied_total"
                    - "haproxy_frontend_request_errors_total"
                    - "haproxy_frontend_responses_denied_total"
                    - "haproxy_frontend_http_requests_total"
                    - "haproxy_frontend_connections_rate_max"
                    - "haproxy_frontend_http_requests_rate_max"
                    - "haproxy_frontend_current_sessions"
                    - "haproxy_frontend_max_session_rate"
                    - "haproxy_backend_bytes_in_total"
                    - "haproxy_backend_bytes_out_total"
                    - "haproxy_backend_connection_errors_total"
                    - "haproxy_backend_retry_warnings_total"
                    - "haproxy_backend_requests_denied_total"
                    - "haproxy_backend_responses_denied_total"
                    - "haproxy_backend_redispatch_warnings_total"
          ```

## Visualize seus dados no New Relic [#find-data]

Assim que os dados estiverem fluindo, encontre suas métricas do HAProxy na New Relic:

1. Vá para <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; All entities**</DNT>.

## Resolução de problemas [#troubleshooting]

Se você encontrar problemas durante a configuração, use este guia de solução de problemas para diagnosticar e resolver problemas comuns.

<CollapserGroup>
  <Collapser id="troubleshoot-stats-endpoint" title="Endpoint de estatísticas do HAProxy não está respondendo">
    Verifique se o frontend de estatísticas está configurado em `haproxy.cfg`:

    ```bash
    sudo haproxy -c -f /etc/haproxy/haproxy.cfg
    grep -A 4 "frontend stats" /etc/haproxy/haproxy.cfg
    ```

    Soluções:

    * Certifique-se de que a porta `bind` (padrão 8404) não seja usada por outro processo: `sudo ss -tlnp | grep 8404`
    * Verifique se o HAProxy está em execução: `sudo systemctl status haproxy`
    * Recarregue a configuração após as alterações: `sudo systemctl reload haproxy`
  </Collapser>

  <Collapser id="troubleshoot-collector-start" title="O serviço do Collector não será iniciado">
    Verifique os logs do coletor em busca de erros de configuração:

    ```bash
    sudo journalctl -u otelcol-contrib -n 100 --no-pager
    # or for NRDOT:
    sudo journalctl -u nrdot-collector -n 100 --no-pager
    ```

    Causas comuns:

    * Sintaxe YAML inválida no arquivo de configuração
    * Variáveis de ambiente ausentes (`NEW_RELIC_LICENSE_KEY`, `OTEL_EXPORTER_OTLP_ENDPOINT`)
    * Conflitos de porta na porta de telemetria do coletor
  </Collapser>

  <Collapser id="troubleshoot-no-data" title="Nenhum dado aparece no New Relic">
    * Aguarde de 2 a 3 minutos para a ingestão inicial de dados
    * Verifique se o coletor está em execução: `sudo systemctl status otelcol-contrib`
    * Verifique se o endpoint de estatísticas está acessível a partir do host do coletor: `curl -s http://localhost:8404/stats`
    * Verifique se sua chave de licença está correta e se o endpoint OTLP está configurado corretamente. Para mais informações, consulte o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp).
    * Consulte quaisquer métricas do HAProxy:
      ```sql
      FROM Metric SELECT count(*) WHERE metricName LIKE 'haproxy.%' SINCE 30 minutes ago
      ```
  </Collapser>

  <Collapser id="troubleshoot-auth-errors" title="Erros de autenticação">
    Se você vir `401 Unauthorized` ou `403 Forbidden` nos logs do coletor:

    * Verifique sua chave de licença: certifique-se de que é uma chave de **ingestão** (INGEST - LICENSE), não uma chave de usuário
    * Verifique se o endpoint está configurado corretamente. Para mais informações, consulte o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp).
    * Certifique-se de que a variável de ambiente esteja definida corretamente: `echo $NEW_RELIC_LICENSE_KEY`
  </Collapser>

  <Collapser id="troubleshoot-prom-endpoint" title="Endpoint do Prometheus não disponível">
    O exportador do Prometheus integrado do HAProxy (`promex`) requer a versão 2.0 ou posterior.

    Verifique a versão do seu HAProxy:

    ```bash
    haproxy -v
    ```

    Se estiver executando uma versão anterior à 2.0, use a guia **OTel Collector Contrib** com o haproxyreceiver em vez disso, que usa o endpoint de estatísticas CSV e funciona com todas as versões do HAProxy que suportam estatísticas.

    Se você estiver executando o HAProxy 2.0–2.3, verifique se `option http-use-htx` está presente na configuração do frontend de estatísticas. Esta opção se tornou o padrão no HAProxy 2.4+ e não é necessária para versões mais recentes.
  </Collapser>
</CollapserGroup>
