A New Relic agora capacita sua equipe a monitorar o desempenho do banco de dados Oracle usando a New Relic Distribution of OpenTelemetry (NRDOT) com os recursos de monitoramento de banco de dados da New Relic. Esta integração fornece insights abrangentes sobre métricas de banco de dados, desempenho de consultas e saúde do sistema usando o coletor NRDOT.

Essa abordagem baseada em NRDOT complementa nossa Integração On-Host (OHI) existente, utilizando padrões OpenTelemetry para monitoramento de banco de dados, facilitando a integração com sua stack de observabilidade existente.

## Pré-requisitos [#prerequisites]

Antes de começar, certifique-se de ter o seguinte:

* [Chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)da New Relic válida
* Arquitetura suportada: Linux com AMD64 e ARM64
* Conectividade de rede para o endpoint OTLP da New Relic
* Oracle Database 19c ou posterior
* Esta integração está disponível como parte do programa de pré-visualização pública da New Relic. Verifique com seu gerente da organização para fazer a adesão na página [Previews &amp; Trials](https://one.newrelic.com/admin-portal/promotion-management/home).

## Configure o NRDOT Collector para o monitoramento do Oracle Database [#install-collector]

Você pode configurar o monitoramento do Oracle Database usando o NRDOT Collector em ambientes on-host (multitenant) ou RDS. Você pode configurar o NRDOT Collector usando os seguintes métodos:

* [Instalação guiada](/docs/opentelemetry/database/otel-oracledb/#guided): o método de instalação guiada fornece instruções passo a passo na plataforma New Relic para ajudar você a instalar e configurar o NRDOT Collector para o monitoramento do banco de dados Oracle.

* **Instalação manual**: o método de instalação manual permite que você configure o NRDOT Collector por conta própria seguindo as instruções nesta documentação. Você pode configurar manualmente nos seguintes ambientes:

  * [Ambiente on-host (multilocatário)](/docs/opentelemetry/database/otel-oracledb/#host): instale o NRDOT Collector no mesmo host que a sua instância do banco de dados Oracle para coletar dados de telemetria de infraestrutura e do banco de dados.
  * [Ambiente RDS](/docs/opentelemetry/database/otel-oracledb/#rds): instale o NRDOT Collector em um ambiente RDS para monitorar suas instâncias de banco de dados Oracle em execução no Amazon RDS.

<Callout variant="tip">
  O NRDOT Collector coleta dados de telemetria relacionados tanto à infraestrutura quanto ao banco de dados, para que você tenha uma solução de observabilidade unificada para o seu ambiente Oracle Database no New Relic.
</Callout>

              <Step>
                ### Configurar usuário do banco de dados [#mdatabase-user]

                Crie um usuário de monitoramento com os privilégios necessários para o seu banco de dados Oracle multitenant. Isso requer a criação de um usuário comum com o prefixo `C##`.

                1. Antes de criar o usuário do banco de dados ou executar quaisquer concessões de atribuição, você deve executar a seguinte instrução como um usuário `SYS` para definir seu contexto de contêiner ativo atual para `CDB$ROOT`:

                   ```sql
                   ALTER SESSION SET CONTAINER = CDB$ROOT;
                   ```

                2. Para bancos de dados multilocatários, login no banco de dados raiz como administrador. Use CREATE USER para adicionar um novo usuário ao banco de dados. O nome de usuário especificado será um &apos;usuário comum&apos; e precisa ser prefixado com `c##` conforme recomendado pela Oracle.

                   ```sql
                   CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<USER_PASSWORD>" CONTAINER=ALL;
                   GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
                   ```

                3. Execute a seguinte instrução como SYSDBA na raiz do CDB. Isso permite que o usuário de monitoramento veja as linhas de cada PDB nas visualizações de dados do contêiner, o que é necessário para métricas e eventos por PDB.

                   ```sql
                   ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;
                   ```

                   <Callout variant="tip">
                     Certifique-se de que sua `USER_PASSWORD` atenda aos requisitos de [senha de novo usuário](https://docs.oracle.com/en/database/oracle/oracle-database/12.2/dbseg/keeping-your-oracle-database-secure.html#GUID-451679EB-8676-47E6-82A6-DF025FD65156) da Oracle.
                   </Callout>
              </Step>

## Comandos suportados pelo coletor NRDOT [#commands]

Esta seção fornece uma lista de comandos comuns para gerenciar o serviço NRDOT Collector no seu sistema.

<CollapserGroup>
  <Collapser title="Comandos do Coletor NRDOT" id="command">
    * Para validar o status da instalação:

      * Para distribuições baseadas em Debian/Ubuntu:

        ```bash
        dpkg -l | grep nrdot-collector
        ```

      * Para distribuições baseadas em RHEL/CentOS:

        ```bash
        rpm -q nrdot-collector || ls /etc/nrdot-collector
        ```

    * Para reiniciar o NRDOT Collector:

    ```bash
    sudo systemctl restart nrdot-collector.service
    ```

    * Para verificar o status do NRDOT Collector:

    ```bash
    sudo systemctl status nrdot-collector.service
    ```

    * Para visualizar os logs do NRDOT Collector:

    ```bash
    sudo journalctl -u nrdot-collector -n 50 --no-pager
    ```

    * Para excluir o serviço NRDOT Collector:

      * Para distribuições baseadas em Debian/Ubuntu:

        ```bash
        sudo apt purge nrdot-collector
        ```

      * Para distribuições baseadas em RHEL/CentOS:

        ```bash
        sudo yum erase nrdot-collector
        ```

    * Para limpar arquivos de configuração:

    ```bash
    # Clean up configuration and reload systemd
    sudo rm -rf /etc/nrdot-collector/
    sudo systemctl daemon-reload
    ```

## Resolução de problemas [#troubleshoot]

Se você encontrar problemas durante a configuração, use este guia de solução de problemas para diagnosticar e resolver problemas comuns.

<CollapserGroup>
  <Collapser id="test-connection" title="Testar a conectividade de rede">
    Execute o seguinte comando para verificar se a porta do banco de dados Oracle está acessível a partir deste host.

    ```bash
    (timeout 3 bash -c '</dev/tcp/<YOUR_ENDPOINT>/<YOUR_PORT>' && echo "PORT OPEN - Network connection successful!") || echo "CONNECTION FAILED - Port closed or firewall blocking"
    ```

    **Resultado esperado:** `PORT OPEN - Network connection successful!`
  </Collapser>

  <Collapser id="otlp-endpoint-connection" title="Teste a conectividade do endpoint OTLP">
    Execute o seguinte comando para verificar se o seu host pode alcançar o endpoint OTLP do New Relic selecionado.

    ```bash
    ENDPOINT="<YOUR_OTLP_ENDPOINT>"
    HOST=$(echo "$ENDPOINT" | sed 's|https://||' | cut -d: -f1)
    PORT=$(echo "$ENDPOINT" | awk -F: '{print $NF}')
    (timeout 2 bash -c "</dev/tcp/$HOST/$PORT" && echo "✅ SUCCESS") || echo "❌ FAILED"
    ```

    **Resultado esperado:** `✅ SUCCESS`
  </Collapser>
</CollapserGroup>
