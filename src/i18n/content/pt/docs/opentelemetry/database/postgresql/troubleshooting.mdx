Solucionar problemas comuns que podem ser encontrados durante o monitoramento do PostgreSQL com o NRDOT Collector.

## Testar conectividade

### Testar a conectividade de rede com o PostgreSQL

```bash
psql --host=<YOUR_DB_HOST> --port=<YOUR_DB_PORT> --username=<YOUR_DB_USERNAME> --dbname=<YOUR_DATABASE_NAME> --command 'SELECT 1;'
```

Uma conexão e um resultado bem-sucedidos confirmam que o usuário de monitoramento, o host e a porta estão acessíveis antes da resolução de problemas do próprio coletor.

### Teste a conectividade do endpoint OTLP

Verificar se o NRDOT Collector pode alcançar o endpoint OTLP da New Relic:

```bash
curl -v <YOUR_NEWRELIC_OTLP_ENDPOINT>
```

## Sintomas comuns

| Sintoma                                                                                                 | Causa provável                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nenhum evento `db.server.query_sample` / `db.server.top_query`                                          | O bloco `events` não está habilitado na configuração do receptor (ambos estão desativados por padrão)                                                                  |
| `db.server.top_query` eventos totalmente ausentes                                                       | `pg_stat_statements` extensão não criada nesse banco de dados                                                                                                          |
| `db.server.query_sample` detalhe de sessão de bloqueio ausente                                          | O usuário de monitoramento não possui `pg_monitor`                                                                                                                     |
| Consultas longas truncadas em `db.server.query_sample`                                                  | Padrão `track_activity_query_size` (1024 bytes) — aumentar, consultar [Compatibilidade e pré-requisitos](/docs/opentelemetry/database/postgresql/compatibility#params) |
| `postgresql.function.calls` sempre vazio, ou o widget &quot;Function Calls/min&quot; do dashboard vazio | `track_functions` não definido como `pl` ou `all` em `postgresql.conf`                                                                                                 |
| Vários widgets do dashboard vazios apesar do fluxo de métricas                                          | Essas métricas estão desativadas por padrão — consulte a [Referência de métrica](/docs/opentelemetry/database/postgresql/metrics-reference#dashboard)                  |
| `db.query.comment_tags.nr_service_guid` sempre vazio                                                    | `allowed_comment_keys: [nr_service_guid]` não definido em `query_sample_collection` / `top_query_collection` — vazio por padrão                                        |
| Métricas de tabela/índice/função ausentes para algumas tabelas                                          | O usuário de monitoramento não possui `SELECT` nessas tabelas/esquemas — `pg_monitor` concede visibilidade de estatísticas, não em nível de objeto `SELECT`            |
| `postgresql.wal.lag` / `.wal.age` ausente                                                               | Requer WAL habilitado com pelo menos uma réplica conectada — omitido silenciosamente em instâncias autônomas/apenas de origem, não zerado                              |
| A entidade PostgreSQL não aparece, ou o relacionamento app→PostgreSQL não se resolve no Entity Explorer | `server.address`/`server.port` não está presente no recurso; o receptor sozinho não os emite no modelo de recurso padrão (legado)                                      |
