Você pode configurar o NRDOT Collector para monitorar múltiplas instâncias do MSSQL a partir de um coletor. Isso é útil se você tiver múltiplos MSSQLs em execução em hosts diferentes e quiser coletar métricas de todos eles usando uma única instância do NRDOT Collector.

<Steps>
  <Step>
    ## Pré-requisitos [#prerequisites]

    * O NRDOT está instalado e configurado para suas instâncias do MSSQL:

      * [Linux RDS](/docs/opentelemetry/database/mssql/linux-rds)
      * [Linux hospedado](/docs/opentelemetry/database/mssql/linux-hosted)
      * [Windows hospedado](/docs/opentelemetry/database/mssql/windows-hosted)
      * [Windows RDS](/docs/opentelemetry/database/mssql/windows-rds)
  </Step>

  <Step>
    ## Adicionar configuração de multirreceptor [#multi]

    Os exemplos a seguir mostram como configurar o NRDOT Collector para monitorar múltiplas instâncias do MSSQL usando uma configuração de múltiplos receptores. Selecione o tipo de implantação que corresponde ao seu ambiente. Você pode adicionar mais receptores conforme necessário para instâncias adicionais.

    ```yaml
    receivers:
      nrsqlserver/1: &nrsqlserver-common
        username: "<YOUR_DB_USERNAME>"
        password: "<YOUR_DB_PASSWORD>"
        server: "<YOUR_SERVER_1>"
        port: <YOUR_PORT_1>
        collection_interval: 30s
        # Add any additional configuration here (metrics, events, query collection, etc.)
        # All settings are automatically inherited by additional receiver instances.
      nrsqlserver/2:
        <<: *nrsqlserver-common
        username: "<YOUR_DB2_USERNAME>"
        password: "<YOUR_DB2_PASSWORD>"
        server: "<YOUR_SERVER_2>"
        port: <YOUR_PORT_2>
      # Add more instances as needed:
      # nrsqlserver/3:
      #   <<: *nrsqlserver-common
      #   username: "<YOUR_DB3_USERNAME>"
      #   password: "<YOUR_DB3_PASSWORD>"
      #   server: "<YOUR_SERVER_3>"
      #   port: <YOUR_PORT_3>

    service:
      pipelines:
        metrics:
          receivers: [nrsqlserver/1, nrsqlserver/2]  # Add nrsqlserver/3, nrsqlserver/4, ... as needed
          processors: [<YOUR_PROCESSORS>]
          exporters: [otlp]
        logs:
          receivers: [nrsqlserver/1, nrsqlserver/2]  # Add nrsqlserver/3, nrsqlserver/4, ... as needed
          processors: [<YOUR_PROCESSORS>]
          exporters: [otlp]
    ```

    A chave de mesclagem `<<: *nrsqlserver-common` herda todas as configurações de `nrsqlserver/1`. Qualquer campo que você definir explicitamente após ela, como `username`, `password`, `server` e `port`, substitui o valor herdado para essa instância de receptor específica.

    <Callout variant="important">
      Cada vez que você adicionar uma nova instância de receptor (por exemplo, `nrsqlserver/3`), adicione-a também à lista `receivers` em ambos os pipelines `metrics` e `logs` em `service.pipelines`. Um receptor definido no bloco `receivers`, mas ausente em `service.pipelines`, não coletará nenhum dado.
    </Callout>
  </Step>

  <Step>
    ## Reiniciar o NRDOT Collector [#restart]

    A reinicialização é obrigatória, não opcional — o coletor carrega a configuração uma vez na inicialização e não recarrega a quente. Qualquer alteração de configuração não tem efeito até que o processo seja reiniciado.

    ```bash
    sudo systemctl restart nrdot-collector
    ```
  </Step>
</Steps>
