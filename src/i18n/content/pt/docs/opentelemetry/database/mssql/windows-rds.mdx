Configure o monitoramento do Microsoft SQL Server usando o NRDOT Collector em ambientes Windows para monitorar instâncias do AWS RDS for SQL Server. Para monitorar em um ambiente auto-hospedado, consulte a [instrumentação auto-hospedada do Windows](/docs/opentelemetry/database/mssql/windows-hosted).

Para instalar isso por meio da interface da New Relic, vá para <DNT>**[one.newrelic.com](https://one.newrelic.com) &gt; Integrations &amp; Agents &gt; MSSQL (OpenTelemetry)** </DNT>. Siga as instruções na tela para configurar a integração. Esta página abrange apenas o caminho de instalação da CLI.

Com base na sua configuração de segurança do RDS SQL Server, escolha os métodos de autenticação para conectar o NRDOT Collector à sua instância do RDS:

          ## Pré-requisitos [#prerequisites]

          Antes de monitorar seu Microsoft SQL Server com o NRDOT, certifique-se de que seu ambiente atenda a estes requisitos:

          * Conta do New Relic com uma [chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)válida

          * [Endpoint OTLP](/docs/opentelemetry/best-practices/opentelemetry-otlp) da New Relic para sua região

          * Requisitos do AWS RDS SQL Server:

            * Autenticação do SQL Server habilitada na instância do RDS
            * Credenciais de usuário mestre do RDS ou credenciais para um login do SQL Server com a função `rds_superuser`
            * Grupo de segurança do RDS configurado para permitir conexões na porta `1433` ou em uma porta personalizada
            * SQL Server Management Studio (SSMS) ou utilitário `sqlcmd`

          * Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp)

          * A URL do endpoint do seu RDS SQL Server, que pode ser encontrada no seu AWS RDS Console em Connectivity &amp; security. Para obter mais informações, consulte a [documentação do AWS RDS](https://docs.aws.amazon.com/AmazonRDS/latest/gettingstartedguide/connecting-console.html).
        </Step>

        <Step>
          ## Instalar o NRDOT Collector [#install-sql]

          Instale o NRDOT Collector em uma instância do Windows no EC2 ou em uma máquina local do Windows que possa se conectar à sua instância do RDS SQL Server.

          <Callout variant="important">
            Para o monitoramento do RDS, instale o NRDOT Collector em uma instância de EC2 na mesma VPC que a sua instância do RDS para obter conectividade de rede ideal e menor latência.
          </Callout>

          Baixe e instale o NRDOT Collector usando o PowerShell:

          ```bash
          [Net.ServicePointManager]::SecurityProtocol = 'tls12, tls'; $NRDOT_VERSION = (Invoke-RestMethod -Uri "https://api.github.com/repos/newrelic/nrdot-collector-releases/releases/latest").tag_name; $WebClient = New-Object System.Net.WebClient; $WebClient.Headers.Add("User-Agent", "Mozilla/5.0"); $WebClient.DownloadFile("https://github.com/newrelic/nrdot-collector-releases/releases/download/$NRDOT_VERSION/nrdot-collector_${NRDOT_VERSION}_windows_x64.msi", "$env:TEMP\nrdot-collector.msi"); Start-Process msiexec.exe -ArgumentList "/i `"$env:TEMP\nrdot-collector.msi`" /qn /norestart /L*V `"$env:TEMP\nrdot_install.log`"" -Wait; Get-Service nrdot-collector -ErrorAction SilentlyContinue
          ```
        </Step>

        <Step>
          ## Criar usuário de monitoramento [#user-sql]

          Execute este script como um usuário administrador para criar o usuário de monitoramento `newrelic` e conceder as permissões necessárias para coletar métricas do SQL Server.

          <Callout variant="tip">
            Execute este script usando o nome de usuário mestre do RDS ou um usuário com a função `rds_superuser`. O script exclui automaticamente o banco de dados `rdsadmin`, que é reservado pela AWS.
          </Callout>

          Em seu SQL Server Management Studio (SSMS), execute o seguinte script para criar o usuário de monitoramento `newrelic`. Substitua `<YOUR_PASSWORD>` pela senha desejada:

          ```sql
          USE [master];
          GO
          CREATE LOGIN [newrelic] WITH PASSWORD = '<YOUR_PASSWORD>';
          GO

          GRANT VIEW SERVER STATE TO [newrelic];
          GRANT VIEW ANY DEFINITION TO [newrelic];
          GRANT VIEW ANY DATABASE TO [newrelic];
          GO

          DECLARE @name SYSNAME;
          DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
          SELECT [name]
          FROM [master].[sys].[databases]
          WHERE [name] NOT IN ('master', 'msdb', 'model', 'rdsadmin', 'distribution')
          AND [state] = 0;
          OPEN db_cursor;
          FETCH NEXT FROM db_cursor INTO @name;
          WHILE @@FETCH_STATUS = 0
          BEGIN
            BEGIN TRY
              EXEC('USE [' + @name + '];
              IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''newrelic'')
              BEGIN
                CREATE USER [newrelic] FOR LOGIN [newrelic];
              END;
              GRANT VIEW DATABASE STATE TO [newrelic];');
            END TRY
            BEGIN CATCH
              PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
            END CATCH
            FETCH NEXT FROM db_cursor INTO @name;
          END
          CLOSE db_cursor;
          DEALLOCATE db_cursor;
          GO
          ```

          <Callout variant="tip">
            Para gerenciar informações confidenciais com segurança, como credenciais de banco de dados, armazene-as em ferramentas de [gerenciamento de segredos](/docs/opentelemetry/database/capabilities/db-apm/#secret-management).
          </Callout>
        </Step>

          ## Atualizar registro de serviço do Windows [#registry-sql]

          1. Atualize o Registro de Serviço do Windows para usar o novo arquivo `mssql-config.yaml` usando um dos seguintes métodos:

             * **Para PowerShell:** execute o seguinte comando como administrador:

               ```bash
               Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\nrdot-collector" -Name "ImagePath" -Value '"C:\Program Files\nrdot-collector\nrdot-collector.exe" --config "C:\Program Files\nrdot-collector\mssql-config.yaml"'
               ```

             * **Para prompt de comando:** se o PowerShell não estiver disponível, use o prompt de comando e execute o seguinte comando como administrador:

             ```bash
             sc config "nrdot-collector" binPath= "\"C:\Program Files\nrdot-collector\nrdot-collector.exe\" --config \"C:\Program Files\nrdot-collector\mssql-config.yaml\""
             ```

          2. Valide a configuração do Collector NRDOT para garantir que esteja formatada corretamente e funcione de maneira adequada.

          ```bash
          & "C:\Program Files\nrdot-collector\nrdot-collector.exe" validate --config="C:\Program Files\nrdot-collector\mssql-config.yaml"
          ```

          <Callout variant="tip">
            Para correlacionar o desempenho do aplicativo com as operações de banco de dados, é possível configurar a identificação de serviço de banco de dados. Para mais informações, consulte [configurar a identificação de serviço de banco de dados](/docs/opentelemetry/database/capabilities/db-apm/).
          </Callout>

          ## Executar como usuário de domínio [#run-domain]

          1. Configure o serviço NRDOT Collector para ser executado como seu usuário de domínio usando o PowerShell. Substitua `YOUR_DOMAIN\YOUR_USER_ACCOUNT` pelo seu domínio e nome de conta:

             ```bash
             # Configure service to use domain account
             # The space after obj= and password= is required syntax for sc.exe
             sc.exe config "nrdot-collector" obj= "YOUR_DOMAIN\YOUR_USER_ACCOUNT" password= "<YOUR_PASSWORD>"

             # Restart the service
             Restart-Service nrdot-collector
             ```

          2. Valide a identidade do serviço:

             ```bash
             Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, State, StartName
             # Expected: StartName = YOUR_DOMAIN\YOUR_USER_ACCOUNT
             ```

        <Step>
          ## Criar usuário de monitoramento [#create-user]

          Conecte-se à sua instância do RDS SQL Server usando o SQL Server Management Studio (SSMS) ou `sqlcmd` com privilégios administrativos.

          No seu SQL Server Management Studio (SSMS), execute o seguinte script para criar um login para a sua conta gMSA e conceder as permissões necessárias. Substitua todas as ocorrências de `<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>` pelo seu domínio e nome de conta reais.

          ```sql
          USE [master];
          GO

          CREATE LOGIN [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$] FROM WINDOWS;
          GO

          GRANT VIEW ANY DATABASE TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
          GRANT VIEW SERVER STATE TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
          GRANT VIEW ANY DEFINITION TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
          GO
          -- Grant access to all databases 
          DECLARE @name SYSNAME;
          DECLARE db_cursor CURSOR READ_ONLY FORWARD_ONLY FOR
            SELECT [name] FROM [master].[sys].[databases]
            WHERE [name] NOT IN ('master','msdb','model','rdsadmin','distribution')
            AND [state] = 0;
          OPEN db_cursor;
          FETCH NEXT FROM db_cursor INTO @name;
          WHILE @@FETCH_STATUS = 0
          BEGIN
            BEGIN TRY
              EXEC('USE [' + @name + '];
              IF NOT EXISTS (SELECT 1 FROM sys.database_principals WHERE name = ''<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$'')
              BEGIN
                CREATE USER [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$] FOR LOGIN [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];
              END;
              GRANT VIEW DATABASE STATE TO [<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$];');
            END TRY
            BEGIN CATCH
              PRINT 'Error on ' + @name + ': ' + ERROR_MESSAGE();
            END CATCH
            FETCH NEXT FROM db_cursor INTO @name;
          END
          CLOSE db_cursor;
          DEALLOCATE db_cursor;
          GO
          ```

          <Callout variant="tip">
            Para gerenciar informações confidenciais com segurança, como credenciais de banco de dados, armazene-as em ferramentas de [gerenciamento de segredos](/docs/opentelemetry/database/capabilities/db-apm/#secret-management).
          </Callout>
        </Step>

          Configure o serviço do NRDOT Collector para ser executado como sua conta gMSA usando o PowerShell. Substitua `<YOUR_DOMAIN>\<YOUR_GMSA_USERNAME>$` pelo seu domínio e nome da conta gMSA. Você deve incluir o `$` no final, pois é necessário para contas gMSA:

          ```bash
          Get-WmiObject Win32_Service -Filter "Name='nrdot-collector'" | Select Name, StartName

          Start-Service nrdot-collector
          ```
