O `sqlqueryreceiver` é um receptor do OpenTelemetry Collector que permite executar qualquer consulta SQL personalizada em seu banco de dados e ingerir os resultados como métricas no New Relic.

Use isso quando quiser monitorar dados não cobertos pelas métricas integradas do `nroracledbreceiver` / `nrsqlserverreceiver`. As métricas personalizadas coletadas via `sqlqueryreceiver` aparecem sob a mesma entidade do Oracle ou SQL Server no New Relic que os dados do receptor integrado, desde que `host.name` esteja configurado corretamente.

## Pré-requisitos [#prerequisites]

* O usuário do banco de dados configurado na fonte de dados deve ter o privilégio `SELECT` em qualquer visualização ou tabela que você pretenda consultar.
* O binário do coletor deve incluir o componente `sqlqueryreceiver`.

      Adicione o bloco `sqlqueryreceiver` dentro da seção `receivers:` do seu `oracle-config.yaml` existente, ao lado do bloco `nroracledb` existente:

      ```yaml
      receivers:
        nroracledb:

        ...

        sqlquery/oracle:
          driver: oracle

          # Approach 1: Use the `endpoint`, `username`, `password`, and `service` fields to connect to your database. The receiver will construct the datasource URL for you.
          # host: <YOUR_DB_HOST>
          # port: <YOUR_DB_PORT>
          # database: <YOUR_DATABASE_NAME>
          # username: <YOUR_DB_USERNAME>
          # password: <YOUR_DB_PASSWORD>


          # Approach 2: Use the `datasource` field to provide a full connection string. 
          datasource: "oracle://<YOUR_DB_USERNAME>:<YOUR_DB_PASSWORD>@<YOUR_DB_HOST>:<YOUR_DB_PORT>/<YOUR_SERVICE_NAME>"

          collection_interval: 60s
          queries:
            - sql: "<YOUR_CUSTOM_SQL>"
              metrics:
                - metric_name: oracledb.<YOUR_METRIC_NAME>
                  value_column: <RESULT_COLUMN>
                  attribute_columns: [<DIMENSION_COLUMN_1>, <DIMENSION_COLUMN_2>]
                  value_type: double
      ```

      ### Convenção de nomenclatura

      Os nomes das métricas devem começar com `oracledb.` para serem associados à entidade correta no New Relic. Métricas com um prefixo diferente serão ingeridas, mas não aparecerão sob a entidade do banco de dados.

      ### Síntese de entidade

      Adicione um processador `resource/add_host` para definir `host.name` com o mesmo valor usado pelo receptor do banco de dados. Sem isso, as métricas personalizadas não serão vinculadas à entidade do banco de dados.

      Adicione o processador na seção `processors:`:

      ```yaml
      processors:
        batch:
        resource/add_event_name:
          attributes:
            - key: host.address
              value: "<YOUR_DB_HOST>"
              action: upsert
        resource/add_host:
          attributes:
            - key: host.name
              value: "<YOUR_DB_HOST>:<YOUR_DB_PORT>"
              action: upsert
      ```

      ### Configuração de Pipeline

      Adicione um pipeline `metrics/custom` na seção `service.pipelines:` da configuração, junto aos pipelines existentes:

      ```yaml
      service:
        pipelines:
          metrics/oracledb:
            receivers: [nroracledb]
            processors: [resource/add_event_name, batch]
            exporters: [otlp/newrelic]
          logs/oracledb:
            receivers: [nroracledb]
            processors: [resource/add_event_name, batch]
            exporters: [otlp/newrelic]

          metrics/custom:
            receivers: [sqlquery/oracle]
            processors: [resource/add_host, resource/add_event_name, batch]
            exporters: [otlp/newrelic]
      ```

      <Callout variant="important">
        Adicione `resource/add_host` antes de `batch` na lista de processadores.
      </Callout>

      ### NRQL para validar dados

      Após reiniciar o coletor, execute o seguinte para confirmar se a métrica personalizada está chegando:

      ```sql
      SELECT uniques(metricName) FROM Metric
      WHERE otel.library.name LIKE '%sqlqueryreceiver%'
      AND metricName LIKE 'oracledb.%'
      SINCE 1 hour ago
      ```

      ## Resolução de problemas [#troubleshooting]

      | Problema                                     | Causa                                               | Consertar                                                                                                                          |
      | -------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
      | `ORA-00942: table or view does not exist`    | Usuário do banco de dados sem privilégio SELECT     | Conceda `SELECT ON <VIEW_NAME>` ao usuário                                                                                         |
      | `missing port in address`                    | `#` em nome de usuário/senha não codificados em URL | Substitua `#` por `%23` na URL da fonte de dados                                                                                   |
      | Nenhum dado no New Relic                     | `host.name` não definido ou incompatível            | Adicione o processador `resource/add_host` com o valor correto do host                                                             |
      | Métrica não sob a entidade de banco de dados | Nome da métrica sem o prefixo obrigatório           | Certifique-se de que os nomes das métricas comecem com `oracledb.` para o banco de dados Oracle ou `sqlserver.` para o SQL Server. |
