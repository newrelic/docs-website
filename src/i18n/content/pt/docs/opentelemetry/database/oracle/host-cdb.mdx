## Pré-requisitos [#prerequisites]

Antes de começar, certifique-se de ter o seguinte:

* [Chave de licença](/docs/apis/intro-apis/new-relic-api-keys/#ingest-license-key)da New Relic válida
* Arquitetura suportada: Linux com AMD64 e ARM64
* Conectividade de rede para o [endpoint OTLP da New Relic](/docs/opentelemetry/best-practices/opentelemetry-otlp)
* Oracle Database `19c` ou posterior

  <Step>
    ## Configurar usuário do banco de dados [#database-user]

    Crie um usuário de monitoramento com os privilégios necessários para o seu banco de dados Oracle multitenant. Isso requer a criação de um usuário comum com o prefixo `C##`.

    1. Para definir seu contexto de contêiner ativo atual como `CDB$ROOT`, execute a seguinte instrução como um usuário `SYS`:

       ```sql
       ALTER SESSION SET CONTAINER = CDB$ROOT;
       ```

    2. Para bancos de dados multitenant:

       1. Faça login no banco de dados raiz como administrador.

       2. Para criar um novo usuário, execute a seguinte instrução `CREATE USER`:

          ```sql
          CREATE USER c##<YOUR_DB_USERNAME> IDENTIFIED BY "<USER_PASSWORD>" CONTAINER=ALL;
          GRANT CREATE SESSION TO c##<YOUR_DB_USERNAME> CONTAINER=ALL;
          ```

          <Callout variant="tip">
            O usuário recém-criado será um usuário comum com o prefixo `C##`. O prefixo `C##` é exigido pela Oracle para usuários comuns.
          </Callout>

    3. Para permitir que o usuário de monitoramento veja as linhas de cada PDB nas views de dados do contêiner, execute a seguinte instrução como `SYSDBA` na raiz do CDB. Isso é necessário para métricas e eventos por PDB.

       ```sql
       ALTER USER c##<YOUR_DB_USERNAME> SET CONTAINER_DATA=ALL CONTAINER=CURRENT;
       ```

       <Callout variant="tip">
         Certifique-se de que sua `USER_PASSWORD` atenda aos requisitos de [senha de novo usuário](https://docs.oracle.com/en/database/oracle/oracle-database/12.2/dbseg/keeping-your-oracle-database-secure.html#GUID-451679EB-8676-47E6-82A6-DF025FD65156) da Oracle.
       </Callout>
  </Step>

    ```sql

    GRANT SELECT ON V_$DATAFILE   TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SYSSTAT                    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$CON_SYSSTAT                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SYSMETRIC                  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$CON_SYSMETRIC              TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SESSION                    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$RESOURCE_LIMIT             TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$OSSTAT                     TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SGAINFO                    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ROWCACHE                   TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$PARAMETER                  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_TABLESPACE_USAGE_METRICS  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_TABLESPACES               TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_DATA_FILES                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_FREE_SPACE                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_RECYCLEBIN                TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SQL            TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SQL_PLAN_STATISTICS_ALL       TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$LOCK           TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$SESSION_EVENT  TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_PROCEDURES    TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON DBA_OBJECTS       TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$PDBS           TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON CDB_SERVICES      TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ASM_DISKGROUP_STAT TO c##<USER_NAME> CONTAINER=ALL;
    GRANT SELECT ON V_$ASM_DISK_STAT      TO c##<USER_NAME> CONTAINER=ALL;
    ```

    <Callout variant="tip">
      As permissões `V_$ASM_DISKGROUP_STAT` e `V_$ASM_DISK_STAT` são necessárias apenas se você desejar coletar [métricas de diskgroup e disco do ASM](/docs/opentelemetry/database/oracle/metrics-reference/#asm).
    </Callout>

    Atualize a configuração do NRDOT Collector para usar seu arquivo `oracle-config.yaml`:

    ```bash
    sudo sed -i 's|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/config.yaml"|OTELCOL_OPTIONS="--config=/etc/nrdot-collector/oracle-config.yaml"|' /etc/nrdot-collector/nrdot-collector.conf
    ```

    <Callout variant="tip">
      Você também pode:

      * [Configure múltiplos receptores](/docs/opentelemetry/database/oracle/multi-receiver): para monitorar várias instâncias do banco de dados Oracle a partir de um coletor.
      * [Configure o SQL Query Receiver](/docs/opentelemetry/database/capabilities/sql-query-receiver/): para coletar métricas personalizadas do seu Oracle Database.
      * [Vincule seu banco de dados Oracle ao APM](/docs/opentelemetry/database/capabilities/db-apm): para correlacionar o desempenho do seu aplicativo com as operações do banco de dados. Isso permite visualizar exatamente quais aplicativos estão gerando workloads específicas de banco de dados.
      * [Configurar o gerenciamento de segredos](/docs/opentelemetry/database/capabilities/db-apm/#secret-management): para gerenciar com segurança informações confidenciais, como credenciais de banco de dados. Isso ajuda a aprimorar a segurança do ambiente de monitoramento ao evitar a inserção direta de dados sensíveis nos arquivos de configuração.
    </Callout>
  </Step>

  <Step>
    ## Reiniciar o NRDOT Collector [#restart-collector]

    Após atualizar a configuração, reinicie o NRDOT Collector:

    ```bash
    sudo systemctl restart nrdot-collector.service
    sudo systemctl status nrdot-collector.service
    ```

    <Callout variant="tip">
      Sempre reinicie o NRDOT Collector após fazer alterações de configuração para que as novas configurações entrem em vigor.
    </Callout>
  </Step>

  <Step>
    ## Encontre e use seus dados [#find-use-data]

    Assim que seus dados estiverem sendo coletados, você poderá acessar o monitoramento abrangente do banco de dados Oracle por meio da interface do New Relic.

    Para encontrar sua entidade de banco de dados Oracle no New Relic:

    1. Vá para <DNT>**[https://one.newrelic.com](https://one.newrelic.com) &gt; All Capabilities &gt; Databases**</DNT>.
    2. Defina os critérios de pesquisa como <DNT>`instrumentation.provider = opentelemetry`</DNT>.
    3. Selecione seu banco de dados Oracle na lista de entidades.
  </Step>
</Steps>
