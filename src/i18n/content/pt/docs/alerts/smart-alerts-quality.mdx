Embora os [alertas inteligentes](/docs/alerts/smart-alerts) se concentrem em fechar lacunas de cobertura, o <DNT>**Alerts Overview**</DNT> oferece uma verificação de integridade para todo o seu ecossistema de alertas — incluindo condições criadas manualmente, por meio da API ou do Terraform, ou por alertas inteligentes.

## Reduzir o ruído [#reduce-noise]

O excesso de alertas atrasa a resposta a incidentes. Uma condição é considerada ruidosa quando gera três ou mais problemas por hora durante pelo menos três horas em um período de 24 horas. Essa definição é um ponto de partida, não uma recomendação — o que é considerado ruidoso depende de suas prioridades, portanto, revise essas condições e defina limites que atendam às suas necessidades.

Para reduzir o ruído:

1. Na página <DNT>**Alerts Overview**</DNT>, na seção <DNT>**Noise overview**</DNT>, clique em <DNT>**Manage**</DNT> abaixo das condições ruidosas.

2. Para uma condição que não é útil, desative-a com seu botão de alternância. Para manter uma condição, mas torná-la menos ruidosa, clique em <DNT>**Edit**</DNT>.

3. Ajuste o limite com base no tipo de condição:

   * Para uma condição do alerta inteligente <DNT>static</DNT>, insira um valor de limite e ajuste-o até que os eventos de alerta estimados por semana para esse valor correspondam a quantos alertas você deseja. Ou ative <DNT>**Minimize noise**</DNT> para definir o valor automaticamente.
   * Para uma condição do alerta inteligente <DNT>anomaly</DNT>, arraste o controle deslizante de mais ruidoso para menos ruidoso.
   * Para outros tipos tradicionais de condição do alerta, defina os valores de limite que você achar apropriados. Não tem estimativas ou sugestões automáticas. Consulte [Definir limite para condições do alerta](/docs/alerts/create-alert/set-thresholds/set-thresholds-alert-condition).

4. Use o gráfico <DNT>**Compare threshold to past signals**</DNT> para verificar o limite em relação aos sinais passados.

5. Quando estiver satisfeito com o limite, salve a condição.

Além de ajustar o limite, você pode reduzir o ruído editando outras configurações de condição, como a consulta, o método de agregação ou a duração da janela.

## Gerenciar Condições sem Sinais [#no-signals]

Uma condição pode não produzir nenhum sinal porque o serviço que ela monitora foi renomeado, rearquitetado ou removido. Algumas condições, como taxa de erros ou taxa de falhas, não produzem sinal por padrão, portanto, revise cada uma antes de agir.

Para limpar condições sem sinais:

1. Na página <DNT>**Alerts Overview**</DNT>, na seção <DNT>**Noise overview**</DNT>, clique em <DNT>**Manage**</DNT> sob as condições que não produzem sinal.
2. Aprofunde-se em uma condição que não recebeu dados de sinal nos últimos 30 dias para descobrir o motivo.
3. Desative ou exclua a condição se não precisar mais dela. Para torná-la produtiva novamente, clique em <DNT>**Edit**</DNT> para abrir sua página de configuração.
4. Ajuste a consulta, o limite ou outras configurações como faria ao criar uma condição. Para obter ajuda, consulte [Editar uma condição do alerta](/docs/alerts/create-alert/create-alert-condition/alert-conditions/#edit-existing-alert-condition).
