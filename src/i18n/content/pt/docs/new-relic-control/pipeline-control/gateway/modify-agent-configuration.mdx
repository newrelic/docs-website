Para que o gateway processe os dados de telemetria dos seus agentes, reconfigure-os para rotear os dados para o seu cluster de gateway em vez de diretamente para a New Relic. A forma de fazer isso depende do tipo de agente: os agentes New Relic APM usam `NEW_RELIC_HOST`, as fontes OpenTelemetry usam as configurações de exportador OTLP e os encaminhadores de logs usam sua própria configuração de plug-in de saída. As seções abaixo abordam cada tipo de agente. Todos os exemplos usam o endpoint do gateway local do cluster. Substitua-o pelo seu endpoint real se os agentes forem executados fora do cluster.

## Agente New Relic APM

`NEW_RELIC_HOST` é exclusivo do APM e não tem efeito nas fontes do OpenTelemetry, no agente de infraestrutura ou nos encaminhadores de logs. O endpoint do gateway deve ser acessível por HTTPS, para que os agentes APM se conectem através do proxy reverso no cluster (NGINX ou Kong) ou do ALB fora do cluster, não diretamente ao pod do gateway.

O exemplo a seguir mostra um arquivo de configuração do agente Node.js:

```js
'use strict'
/**
 * New Relic agent configuration.
 *
 * See lib/config/default.js in the agent distribution for a more complete
 * description of configuration variables and their potential values.
 */
exports.config = {
  /**
   * Array of application names.
   */
  app_name: ['My Application'],
  /**
   * Your New Relic Host endpoint.
  */
  NEW_RELIC_HOST: 'GATEWAY_DNS_ENDPOINT_HERE',
  /**
   * Your New Relic license key.
   */
  license_key: 'license key here',
  logging: {
    /**
     * Level at which to log. 'trace' is most useful to New Relic when diagnosing
     * issues with the agent, 'info' and higher will impose the least overhead on
     * production applications.
     */
    level: 'info'
  },
  /**
   * When true, all request headers except for those listed in attributes.exclude
   * will be captured for all traces, unless otherwise specified in a destination's
   * attributes include/exclude lists.
   */
  allow_all_headers: true,
  attributes: {
    /**
     * Prefix of attributes to exclude from all destinations. Allows * as wildcard
     * at end.
     *
     * NOTE: If excluding headers, they must be in camelCase form to be filtered.
     *
     * @name NEW_RELIC_ATTRIBUTES_EXCLUDE
     */
    exclude: [
      'request.headers.cookie',
      'request.headers.authorization',
      'request.headers.proxyAuthorization',
      'request.headers.setCookie*',
      'request.headers.x*',
      'response.headers.cookie',
      'response.headers.authorization',
      'response.headers.proxyAuthorization',
      'response.headers.setCookie*',
      'response.headers.x*'
    ]
  }
}
```

## Coletor OpenTelemetry

**Versão mínima:** opentelemetry-collector-contrib v0.104.0

Use o exportador `otlphttp` apontado para a porta HTTP OTLP do gateway. Implante esta configuração como um ConfigMap do Kubernetes:

```yaml
exporters:
  otlphttp:
    endpoint: http://pipeline-control-gateway.newrelic.svc.cluster.local:4318
    tls:
      insecure: true

service:
  pipelines:
    traces:
      exporters: [otlphttp]
    metrics:
      exporters: [otlphttp]
    logs:
      exporters: [otlphttp]
```

<Callout variant="important">
  Use o exportador `otlphttp`, não `otlp`. O chart do Helm renomeia `otlp` para `otlp_grpc` internamente, o que é inválido para esta versão do coletor.
</Callout>

## agente de anexação automática do eBPF

Configure o agente de anexação automática do APM eBPF para enviar telemetria via OTLP gRPC definindo `customOtlpEndpoint` em seu arquivo de valores:

```yaml
customOtlpEndpoint: "pipeline-control-gateway.newrelic.svc.cluster.local:4317"
customOtlpEndpointTlsEnabled: false
reportLogs: "true"
```

Isso roteia tanto as métricas quanto os logs pelo receptor OTLP gRPC do gateway na porta 4317. O TLS está desativado porque a conexão permanece dentro do cluster.

## Agente de infraestrutura

**Versão mínima:** v1.62.0

O agente de infraestrutura tem dois caminhos de configuração separados, dependendo do que você deseja rotear pelo gateway:

* **Toda a telemetria (métricas, eventos, inventário e logs):** use `collector_url` e `metric_url` em seus valores do Helm. Isso roteia tudo o que o agente coleta pelo gateway.
* **Apenas logs:** use `logging_endpoint` em `newrelic-infra.yml`. Isso roteia apenas o encaminhamento de logs pelo gateway, enquanto outra telemetria continua indo diretamente para o New Relic.

### Roteie toda a telemetria através do gateway

Defina `collector_url` e `metric_url` em seus valores Helm:

```yaml
newrelic-infrastructure:
  common:
    agentConfig:
      collector_url: "http://pipeline-control-gateway.newrelic.svc.cluster.local"
      metric_url: "http://pipeline-control-gateway.newrelic.svc.cluster.local"
```

### Roteie apenas os logs através do gateway

Defina `logging_endpoint` em `/etc/newrelic-infra.yml` e ative o encaminhamento de logs:

```yaml
license_key: YOUR_LICENSE_KEY
logging_endpoint: http://pipeline-control-gateway.newrelic.svc.cluster.local/log/v1
log:
  forward: true
```

Use `http://` para o endpoint local do cluster. Use `https://` apenas ao rotear através de um proxy reverso no cluster (NGINX ou Kong) com o cert-manager implantado.

Em seguida, defina quais arquivos de log encaminhar em `/etc/newrelic-infra/logging.d/logging.yml`:

```yaml
logs:
  - name: my-app-logs
    file: /var/log/my-app.log
```

Reinicie o agente de infraestrutura para aplicar as alterações.
