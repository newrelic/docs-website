Os ambientes modernos Kubernetes evoluíram para **frotas complexas com múltiploscluster **, mas as ferramentas tradicionais de observabilidade geralmente fornecem apenas uma visão fragmentada e isolada de cada cluster individual. Essa interface entrecluster Kubernetes fornece um centro de comando unificado que transforma essa complexidade de múltiploscluster em clareza para toda a frota.

Essa visão unificada ajuda a plataforma de engenharia e os engenheiros de confiabilidade de sites (SREs) a:

* **Unifique a observabilidade de toda a frota** em um único dashboard compatível com clusters monitorados pelo agente New Relic ou OpenTelemetry.
* **Acelere a análise da causa raiz** com um fluxo de trabalho de triagem guiado.
* **Reduza custos** identificando recursos desperdiçados em toda a frota.
* **Capacitar os desenvolvedores** com uma visão centrada em aplicativos para o autoatendimento.

## Acesse a nova interface do usuário. [#access]

Você pode acessar a nova interface entrecluster Kubernetes a partir da opção Kubernetes na navegação à esquerda da plataforma New Relic.

Para acessar a interface entrecluster Kubernetes :

1. Vá para <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Kubernetes**</DNT>
2. Clique no botão **Try it out** no canto superior direito da página.

## Scorecards e tabela [#scorecards]

Os scorecards resumem cada métrica em toda a sua frota, e a tabela de detalhamento categoriza os valores por cluster, nó ou workload. Tanto os scorecards quanto as linhas da tabela mudam para laranja (aviso) ou vermelho (crítico) quando um valor atinge um [limite de gravidade](#tab). Proporções como `2/436` mudam de cor com base em sua porcentagem.

* Selecione **`avg`**, **`p95`**, **`p99`** ou **`max`** para atualizar os scorecards e o gráfico de linhas. A tabela de detalhamento sempre exibe valores médios.
* Desative **Include healthy entities** para filtrar a lista para entidades com um limite de status laranja ou vermelho ativo.
* As entidades que pararam de relatar permanecem na lista, exibindo dados históricos para o intervalo de tempo selecionado.

## Capacidade de detalhamento para triagem [#drill-down]

Você pode acelerar a análise de causa raiz com a interface entre clusters usando um fluxo de trabalho de triagem guiada que vai de métricas de toda a frota até entidades individuais:

* **Do scorecard à classificação de entidades:** selecione um scorecard para classificar a tabela por essa métrica em ordem decrescente de gravidade e plotar as 10 principais entidades no gráfico de linha
* **Da métrica de tabela para o navegador do Kubernetes:** passe o ponteiro do mouse sobre um valor de métrica para exibir a linha de tendência da entidade e, em seguida, selecione <DNT>**View in navigator**</DNT> para abrir o [navegador do Kubernetes](/docs/kubernetes-pixie/kubernetes-integration/understand-use-data/kubernetes-cluster-explorer/#navigator-preview).
* **Da entidade aos detalhes:** passe o mouse sobre o nome de uma entidade para ver suas métricas clássicas e entidades relacionadas, ou clique nele para abrir sua página de visão geral.

## Métrica específica da guia [#tab]
