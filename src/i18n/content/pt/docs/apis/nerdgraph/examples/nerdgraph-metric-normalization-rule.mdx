Você pode usar as mutações do [NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/) para gerenciar as [regras de normalização de métricas](/docs/new-relic-solutions/new-relic-one/ui-data/metric-normalization-rules) no New Relic. Aproveitando essas mutações, você pode criar, editar, ativar e desativar essas regras diretamente da sua conta do New Relic. Isso fornece uma abordagem simplificada e programática para resolver [problemas de agrupamento de métricas (MGIs).](/docs/new-relic-solutions/solve-common-issues/troubleshooting/metric-grouping-issues)

As regras de normalização de métrica são usadas para:

* Agrupe ou filtre [dados da métrica de fração de tempo](/docs/data-apis/understand-data/new-relic-data-types/#timeslice-data).
* Gerencie métricas de cardinalidade alta renomeando-as, descartando-as ou transformando-as antes que sejam ingeridas no New Relic.
* Evite [MGIs](/docs/new-relic-solutions/solve-common-issues/troubleshooting/metric-grouping-issues) para garantir que suas métricas sejam bem organizadas e significativas.
* Reduza o número de nomes de métricas únicos reportados ao New Relic.

## Pré-requisitos [#prerequisites]

* Uma [conta do New Relic](https://newrelic.com/signup) e, com essa conta, você pode acessar sua chave de usuário da API que precisa incluir nas [consultas e mutações](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph).

* O tipo de usuário e as funções atribuídas podem afetar suas permissões do NerdGraph. Para obter mais detalhes, consulte [Fatores que afetam o acesso](/docs/accounts/accounts-billing/account-structure/factors-affecting-access-features-data#user-permissions).

<Callout variant="tip">
Você também pode criar uma regra de normalização de métrica usando a plataforma New Relic. Para mais informações, consulte [Regras de normalização de métricas](/docs/new-relic-solutions/new-relic-one/ui-data/metric-normalization-rules).
</Callout>

## Recuperar as regras de normalização de métricas [#nerdgraph-query]

Use a consulta `metricNormalizationRules` para recuperar todas as regras de normalização de métrica associadas à sua conta. Esta consulta fornece uma visão geral abrangente das regras existentes, incluindo seu status e configuração.

### Exemplo de consulta

```graphql

    {
        actor {
            user {
            name
            }
            account(id: xxxxxx) {
            metricNormalization {
                metricNormalizationRules(enabled: true) {
                action
                applicationGuid
                applicationName
                createdAt
                enabled
                evalOrder
                id
                matchExpression
                notes
                replacement
                terminateChain
                }
            }
            }
        }
    }

```

## Mutações [#nerdgraph-mutations]

Gerencie suas regras de normalização de métricas com as seguintes [mutações do NerdGraph](https://docs.newrelic.com/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology):

<CollapserGroup>
<Collapser id="create-metric-normalization-rule" title="Criar uma regra de normalização de métricas">
Use a mutação `metricNormalizationCreateRule` para criar uma nova regra de normalização de métrica no New Relic.

### Parâmetro de entrada

<table>
<thead>
<tr>
<th>
Nome do atributo
</th>

<th>
Tipo de dados
</th>

<th>
Descrição
</th>
</tr>
</thead>

<tbody>
<tr>
<td>
ID da conta
</td>

<td>
Corda
</td>

<td>
(Obrigatório) O ID da conta associado à regra.
</td>
</tr>

<tr>
<td>
Ação
</td>

<td>
Corda
</td>

<td>
(Obrigatório) Selecione uma das seguintes ações:

* `REPLACE`: Substitua as métricas que correspondem ao `matchExpression` pelo valor definido no campo `replacement`.
* `IGNORE`: bloqueie o envio para o New Relic de qualquer métrica correspondente a `matchExpression`.
* `DENY_NEW_METRICS`: impeça a criação de novos nomes de métricas que correspondam a `matchExpression`, enquanto permite que nomes de métricas existentes continuem reportando.
</td>
</tr>

<tr>
<td>
applicationGuid
</td>

<td>
Corda
</td>

<td>
(Opcional) O GUID exclusivo do aplicativo no New Relic. Se deixado em branco, isso se torna uma regra para toda a conta.
</td>
</tr>

<tr>
<td>
habilitado
</td>

<td>
Boleano
</td>

<td>
(Obrigatório) Para habilitar a regra, defina como `true`.
</td>
</tr>

<tr>
<td>
evalOrder
</td>

<td>
Inteiro
</td>

<td>
(Obrigatório) Especifique a ordem em que a regra é aplicada em relação a outras regras. Quanto menor o número, maior a prioridade avaliada. O valor recomendado é `2000`.
</td>
</tr>

<tr>
<td>
matchExpression
</td>

<td>
Corda
</td>

<td>
(Obrigatório) Aceita um padrão de [expressão regular](https://regexone.com/) que corresponda às métricas a serem normalizadas. Este campo deve começar com um `^` e terminar com um `$`. Define um padrão para identificar quais métricas devem ser afetadas pela regra de normalização. Por exemplo: `^WebTransaction/Uri/RESTfulExample/users/username/[a-zA-Z0-9]+$` O padrão `^[a-zA-Z0-9]+$` corresponde a qualquer string composta por caracteres minúsculos `(a-z)`, caracteres maiúsculos `(A-Z)` e números `(0-9)`.
</td>
</tr>

<tr>
<td>
notas
</td>

<td>
Corda
</td>

<td>
Notas ou comentários adicionais sobre a regra de normalização.
</td>
</tr>

<tr>
<td>
substituição
</td>

<td>
Corda
</td>

<td>
Este campo é obrigatório apenas quando a opção `REPLACE` é selecionada na lista suspensa `action`. Ele substitui qualquer nome de métrica que corresponda a `matchExpression`. Por exemplo: `WebTransaction/Uri/RESTfulExample/users/username/{username}$`
</td>
</tr>

<tr>
<td>
terminateChain
</td>

<td>
Boleano
</td>

<td>
(Obrigatório) Se definido como `true`, nenhuma regra adicional será aplicada à métrica correspondente.
</td>
</tr>
</tbody>
</table>

### Exemplo de consulta

```graphql

    mutation {
        metricNormalizationCreateRule(
            accountId: xxxxxx
            rule: {action: REPLACE, applicationGuid: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx", enabled: false, evalOrder: 2000, matchExpression: "^WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/[a-f0-9]+$", notes: "rules to replace", replacement: "WebTransaction/Uri/MGIGenerator_war_exploded/api/MGI/pattern/{guid}", terminateChain: true}
        ) {
            errors {
                message
                type
            }
            rule {
                action
                applicationGuid
                applicationName
                createdAt
                enabled
                evalOrder
                id
                matchExpression
                notes
                replacement
                terminateChain
            }
        }
    }

```
