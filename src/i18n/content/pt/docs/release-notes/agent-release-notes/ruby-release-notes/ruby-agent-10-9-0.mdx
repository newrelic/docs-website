## v10.9.0

* **Recurso: Continuous Profiling (preview)**

  O Continuous Profiling é um novo recurso que ainda não está disponível para uso geral. O código do componente do lado do agente agora está presente no agente, mas para realmente usá-lo antes do lançamento da Disponibilidade Geral, você precisará entrar em contato com seu representante de vendas da New Relic para participar da prévia antecipadamente.

  O Continuous Profiling coleta amostras repetidamente da stack de chamadas do Ruby do seu aplicativo em execução e as reporta ao New Relic, para que você possa ver quais métodos estão consumindo mais tempo de CPU (ou alocando mais objetos) em produção, sem adicionar código ao seu aplicativo.

  Para ativá-lo, adicione as gems [`stackprof`](https://rubygems.org/gems/stackprof) e [`google-protobuf`](https://rubygems.org/gems/google-protobuf) ao `Gemfile` do seu aplicativo e, em seguida, defina `profiling.enabled` como `true`:

  ```yaml
    profiling.enabled: true
  ```

  Com apenas `profiling.enabled` definido, o agente coleta amostras do tempo de CPU a cada 10 milissegundos durante a vida útil do processo. Essas opções permitem ajustar esse comportamento:

  | Nome da configuração                   | Padrão  | Comportamento                                                                                                                        |
  | -------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------ |
  | profiling.enabled                      | `false` | Se `true`, o agente coleta e reporta dados de profiling contínuo.                                                                    |
  | profiling.include                      | `cpu`   | O que amostrar: `cpu` para tempo de CPU, ou `object` para alocações de objetos.                                                      |
  | profiling.sample\_period               | `0.01`  | Segundos entre amostras de stack. Usado somente quando `profiling.include` é `cpu`. Deve estar entre 0,000001 e 0,999999.            |
  | profiling.object\_allocation\_interval | `10000` | Alocações de objetos entre amostras de stack. Usado somente quando `profiling.include` é `object`. Deve estar entre 1.000 e 999.999. |
  | profiling.delay                        | `0`     | Milissegundos para aguardar antes do início do profiling. `0` inicia imediatamente.                                                  |
  | profiling.duration                     | `0`     | Milissegundos para fazer o profiling antes de parar automaticamente. `0` faz o profiling até que o processo seja encerrado.          |

  [PR#3617](https://github.com/newrelic/newrelic-ruby-agent/pull/3617)

* **Recurso: adicionar suporte ao Dalli 5.1.1**

  O Dalli 5.1.1 adicionou argumentos a alguns dos métodos instrumentados pelo agente, o que poderia gerar um `ArgumentError` em operações de várias chaves ou fazer com que as opções de solicitação fossem descartadas silenciosamente. Agora, o agente aceita e encaminha um número variável de argumentos posicionais e de palavras-chave para esses métodos. [PR#3683](https://github.com/newrelic/newrelic-ruby-agent/pull/3683)
