## v8.7.0

* **Encaminhamento de logs do logs-in-context do APM ativado por padrão**

  O encaminhamento automático de logs de aplicativo agora está habilitado por padrão. Esta versão do agente enviará automaticamente logs de aplicativo enriquecidos para o New Relic. Para saber mais sobre este recurso, consulte [aqui](https://docs.newrelic.com/docs/apm/new-relic-apm/getting-started/get-started-logs-context/), e opções adicionais de configuração estão disponíveis [aqui](https://docs.newrelic.com/docs/logs/logs-context/configure-logs-context-ruby). Para saber como ativar ou desativar a ingestão de logs por conta, consulte [aqui](https://docs.newrelic.com/docs/logs/logs-context/disable-automatic-logging).

* **Suporte assíncrono aprimorado e instrumentação de Thread**

  Anteriormente, o agente não era capaz de registrar eventos e métricas dentro de Threads criadas dentro de uma transação já em execução. Esta versão inclui 2 novas opções de configuração para oferecer suporte a aplicativos multithread para instrumentar threads automaticamente. Uma nova opção de configuração,`instrumentation.thread.tracing` (desativada por padrão), foi introduzida e, quando ativada, permitirá que o agente insira o rastreamento do New Relic dentro de todas as Threads criadas por um aplicativo. Para oferecer suporte a aplicativos que desejam apenas que algumas threads sejam instrumentadas pelo New Relic, uma nova classe está disponível, `NewRelic::TracedThread`, que criará uma thread que inclui a instrumentação do New Relic, consulte a nossa [documentação da API](https://www.rubydoc.info/gems/newrelic_rpm/NewRelic) para obter mais detalhes.

  Para as gems com versões descontinuadas, não testaremos mais essas versões em nossa suíte multiverse. Elas podem, no entanto, ainda ser compatíveis com o agente. Não corrigiremos mais os relatórios de bugs para problemas com essas versões da gem.

* **Utilizar internamente `Object.const_get` e `Object.const_defined?`**

  Ao verificar dinamicamente ou obter uma referência para uma constante de classe a partir de uma string, aproveite os métodos integrados da classe `Object` sempre que possível para desfrutar de operações mais simples e com melhor desempenho. Todos os JRubies e CRubies v2.5 e anteriores precisam de um pouco de assistência além do que `Object` pode fornecer, visto que esses Rubies podem gerar uma constante indesejada de um namespace diferente daquele que foi especificado. Mas para todos os outros Rubies e até mesmo para aqueles Rubies em contextos onde podemos confiar 100% no valor da string recebida, aproveite os métodos da classe `Object` e colha os benefícios.

* **Esclarecer a documentação para a configuração de `rake.tasks`**

  A descrição de `rake.tasks` no arquivo `newrelic.yml` padrão e a [documentação de configuração do agente Ruby da New Relic](https://docs.newrelic.com/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration#rake-tasks) foram atualizadas para esclarecer seu comportamento e uso. A documentação agora diz:

  > Especifique uma matriz de tarefas Rake para instrumentar automaticamente. Esta opção de configuração converte a matriz em uma lista RegEx. Se você desejar permitir todas as tarefas por padrão, use `rake.tasks: [.+]`. As tarefas Rake não serão instrumentadas, a menos que sejam adicionadas a esta lista. Para mais informações, visite a (documentação de instrumentação Rake do New Relic)\[/docs/apm/agents/ruby-agent/background-jobs/rake-instrumentation].

  Agradecemos a @robotfelix por sugerir estas alterações.

* **Habilitar a configuração de Variáveis de Ambiente para converter configurações de matriz em matrizes**

  Antes dessa alteração, quando listas separadas por vírgulas eram passadas como variáveis de ambiente, um erro era emitido para o `newrelic_agent.log` e uma String era definida como o valor. Agora, as matrizes serão convertidas com precisão.

* **Correção de bug: permitir que TransactionEvents sejam amostrados na taxa esperada**

  O valor de capacidade `transaction_events.max_samples_stored` dentro do TransactionEventAggregator não correspondia ao intervalo esperado do seu ciclo de coleta, fazendo com que os TransactionEvents fossem superamostrados. Esta correção de bug se baseia nas atualizações feitas em [#952](https://github.com/newrelic/newrelic-ruby-agent/pull/952) para que o intervalo e a capacidade se comportem conforme o esperado para as opções de configuração `transaction_events*` renomeadas.

* **Correção de bug: eventos de erro sem atributos quando criados fora de uma transação**

  Anteriormente, o agente não atribuía uma prioridade aos eventos de erro que eram criados ao chamar notice\_error fora do escopo de uma transação. Isso causou problemas com a amostragem quando o buffer de eventos de erro estava cheio, resultando em um `NoMethodError: undefined method '<' for nil:NilClass` no newrelic\_agent.log. Esta correção de bug garante que uma prioridade seja sempre atribuída a eventos de erro, para que o agente seja capaz de realizar amostras desses eventos de erro corretamente. Agradecemos a @olleolleolle por trazer este problema à nossa atenção.

## Declaração de apoio

A New Relic recomenda que você atualize o agente regularmente e, no mínimo, a cada 3 meses. A partir desta versão, a versão mais antiga suportada é a [5.7.0.350](https://docs.newrelic.com/docs/release-notes/agent-release-notes/ruby-release-notes/ruby-agent-570350).
