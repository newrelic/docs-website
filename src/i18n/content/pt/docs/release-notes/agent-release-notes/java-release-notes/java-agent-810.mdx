## Novos recursos e melhorias

* Adicionado suporte ao Webflux 6 [1181](https://github.com/newrelic/newrelic-java-agent/pull/1181)

* Adicionado suporte ao Spring JMS 6 [1088](https://github.com/newrelic/newrelic-java-agent/issues/1088)

* Adicionado suporte para Mongodb Reactive Streams [1164](https://github.com/newrelic/newrelic-java-agent/pull/1164)

* Adicionado suporte ao Kafka Streams [1170](https://github.com/newrelic/newrelic-java-agent/pull/1170)

  O suporte ao Kafka Streams vem em dois formatos: métricas e spans. As métricas são habilitadas por padrão, enquanto os spans são desabilitados por padrão. Para habilitar spans, adicione o seguinte à sua configuração do *newrelic.yml* na seção common:

```
common:
  class_transformer:
    kafka-streams-spans:
      enabled: true
```

* Impressão digital de erro - forneça seus próprios nomes de grupo do Errors inbox [1195](https://github.com/newrelic/newrelic-java-agent/pull/1195)

  Suas ocorrências de erro estão mal agrupadas? Defina seu próprio fingerprint de erro via uma função de retorno de chamada. Foi adicionado um novo método de API pública que aceitará um proc definido pelo usuário. O proc será invocado para cada erro notado e, sempre que retornar uma string, essa string será usada como o nome do grupo de erros para o erro e terá precedência sobre qualquer agrupamento no lado do servidor que ocorra com o Errors Inbox do New Relic. Isso oferece aos usuários um controle muito maior sobre o agrupamento de seus erros. Para mais informações, consulte nossas páginas [API: Agrupamento de erros](/docs/apm/agents/java-agent/api-guides/java-agent-api-register-error-group-callback-to-set-fingerprint/) e [APM: aba Agrupar erros](/docs/triage-inbox/apm-tab/).

* Rastreamento de usuário - associar erros a um ID de usuário [1188](https://github.com/newrelic/newrelic-java-agent/pull/1188)

  Agora você pode ver o número de usuários impactados por um grupo de erros. Identifique o usuário final com um novo método de API pública que aceitará uma representação de string de um ID de usuário e associará esse ID de usuário à transação atual. Transações e erros terão então um novo atributo de agente `enduser.id` associado a eles. Isso permitirá que os usuários do agente adicionem tags a transações e erros como pertencentes a determinados IDs de usuário, para dar suporte a recursos aprimorados de filtragem e alerta. Para mais informações, consulte a documentação \[Newrelic.setUserId ]\([https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName(java.lang.String)](https://newrelic.github.io/java-agent-api/javadoc/com/newrelic/api/agent/NewRelic.html#setUserName\(java.lang.String\)) e a página [Rastrear usuários impactados com o Errors Inbox](/docs/triage-inbox/error-users-impacted/).

* Invocar `token.link()` fora de uma transação instrumentará esse método para iniciar uma transação assíncrona [1140](https://github.com/newrelic/newrelic-java-agent/pull/1140)

* A instrumentação de clientes Kafka possui novas métricas para listar os nós: `MessageBroker/Kafka/Nodes/&lt;node>` [1130](https://github.com/newrelic/newrelic-java-agent/pull/1130)

## Atualizar para a versão mais recente [#procedures]

Para identificar qual versão do agente Java você está usando atualmente, execute `java -jar newrelic.jar -v`. A versão do seu agente Java será impressa em seu console.

Em seguida, para atualizar para a versão mais recente do agente Java:

1. Faça backup **de todo** o [diretório raiz do agente Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) em outro local. Renomeie esse diretório para `NewRelic_Agent#.#.#`, onde `#.#.#` é o número da versão do agente.
2. [Baixe o agente.](/docs/release-notes/agent-release-notes/java-release-notes)
3. Descompacte o novo arquivo de download do agente e copie `newrelic-api.jar` e `newrelic.jar` no [diretório raiz original do agente Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent).
4. Compare seu `newrelic.yml` antigo com o `newrelic.yml` recém-baixado do zip e [atualize o arquivo, se necessário](#diff).
5. Reinicie seu despachante Java.

Se você tiver problemas após a atualização do agente Java, restaure a partir do diretório do agente New Relic do qual foi feito backup.

## Atualizar diferenças de configuração do agente [#diff]

Adicionamos novas configurações a `newrelic.yml` à medida que lançamos novas versões do agente. Você pode usar `diff` ou outro utilitário de comparação para ver o que mudou e adicionar as novas configurações ao seu arquivo antigo. Certifique-se de não substituir nenhuma personalização feita no arquivo, como chave de licença, nome do aplicativo ou alterações nas configurações padrão.

Por exemplo, se você `diff` os arquivos `newrelic.yml` padrão para as versões 7.10.0 e 7.11.0 do agente Java, os resultados impressos no console serão como:

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

Neste exemplo, essas linhas foram adicionadas ao `newrelic.yml` padrão na versão 7.11.0 do agente Java. Se você estiver migrando para a 7.11.0 ou superior, você deve adicionar estas novas linhas ao seu `newrelic.yml` original.
