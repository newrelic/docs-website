## Novos recursos e melhorias

* Suporte ao Java 19 [1022](https://github.com/newrelic/newrelic-java-agent/pull/1022)

* Suporte ao Play 2.8.16+ [981](https://github.com/newrelic/newrelic-java-agent/pull/981)

* Suporte ao ojdbc8 v21.1.0.0+ [1042](https://github.com/newrelic/newrelic-java-agent/pull/1042)

* Suporte a JVMs Semeru/OpenJ9 [993](https://github.com/newrelic/newrelic-java-agent/pull/993)

* Suporte ao encaminhamento de logs para java.util.logging (JUL) [1049](https://github.com/newrelic/newrelic-java-agent/pull/1049)

* Suporte ao encaminhamento de dados de contexto de log [866](https://github.com/newrelic/newrelic-java-agent/pull/866)

  O agente agora pode encaminhar dados no Mapped Diagnostic Context (MDC, logback/slf4j) e ThreadContext (log4j2) como atributos ao encaminhar registros de log. Quando o recurso estiver habilitado, esses atributos serão adicionados aos registros de log com um prefixo `context.`. Para obter detalhes sobre como habilitar este recurso, consulte a documentação do [context\_data](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#logging-context-data).

* Aumento do limite de eventos personalizados [1036](https://github.com/newrelic/newrelic-java-agent/pull/1036)

  Esta versão aumenta o limite padrão de eventos personalizados de 10.000 eventos por minuto para 30.000 eventos por minuto. No cenário em que os eventos personalizados estavam sendo limitados, essa alteração permitirá que mais eventos personalizados sejam enviados para a New Relic. Há também um novo limite máximo configurável de 100.000 eventos por minuto. Para alterar os limites, consulte a documentação para [max\_samples\_stored](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file/#Custom_Events). Para saber mais sobre a mudança e como determinar se eventos personalizados estão sendo descartados, consulte nossa [postagem](https://support.newrelic.com/s/hubtopic/aAX8W0000008dby/send-more-custom-events-with-the-latest-apm-agents) no Explorers Hub.

* Métricas em nível de código ativadas por padrão [1037](https://github.com/newrelic/newrelic-java-agent/pull/1037)

  A funcionalidade de métricas de nível de código introduzida com o agente 7.10 agora está habilitada por padrão. Este recurso causará um aumento no consumo de dados. A quantidade depende da aplicação. Para desativar as métricas de nível de código, consulte as instruções em nossa [documentação de métricas de nível de código](/docs/apm/agents/java-agent/configuration/java-agent-configuration-config-file#code-level-metrics).

Os seguintes módulos de instrumentação estão sendo descontinuados para remoção:

* cassandra-datastax-2.1.2
* httpclient-3.0
* jdbc-embedded-derby-10.10.1.1
* jetty-7
* jetty-7.6
* jetty-9
* jetty-9.0.4
* jetty-9.1
* mongodb-2.12
* mongodb-2.14
* mongodb-3.0
* okhttp-3.0.0
* okhttp-3.4.0
* okhttp-3.5.0

Os atributos de transação/span `httpResponseCode`, `response.status` e `response.statusMessage` estão descontinuados e serão removidos em uma versão futura. Estes foram substituídos por `http.statusCode` e `http.statusText`.

## Declaração de apoio

A New Relic recomenda que você atualize o agente regularmente para garantir que obtenha os recursos e benefícios de desempenho mais recentes. Além disso, versões mais antigas não serão mais suportadas quando atingirem o [fim da vida útil](/docs/using-new-relic/cross-product-functions/install-configure/notification-changes-new-relic-saas-features-distributed-software/).

## Atualizar para a versão mais recente [#procedures]

Para identificar qual versão do agente Java você está usando atualmente, execute `java -jar newrelic.jar -v`. A versão do seu agente Java será impressa em seu console.

Em seguida, para atualizar para a versão mais recente do agente Java:

1. Faça backup **de todo** o [diretório raiz do agente Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent) em outro local. Renomeie esse diretório para `NewRelic_Agent#.#.#`, onde `#.#.#` é o número da versão do agente.
2. [Baixe o agente.](/docs/release-notes/agent-release-notes/java-release-notes)
3. Descompacte o novo arquivo de download do agente e copie `newrelic-api.jar` e `newrelic.jar` no [diretório raiz original do agente Java](/docs/agents/manage-apm-agents/troubleshooting/find-agent-root-directory#java-agent).
4. Compare seu `newrelic.yml` antigo com o `newrelic.yml` recém-baixado do zip e [atualize o arquivo, se necessário](#diff).
5. Reinicie seu despachante Java.

Se você tiver problemas após a atualização do agente Java, restaure a partir do diretório do agente New Relic do qual foi feito backup.

## Atualizar diferenças de configuração do agente [#diff]

Adicionamos novas configurações a `newrelic.yml` à medida que lançamos novas versões do agente. Você pode usar `diff` ou outro utilitário de comparação para ver o que mudou e adicionar as novas configurações ao seu arquivo antigo. Certifique-se de não substituir nenhuma personalização feita no arquivo, como chave de licença, nome do aplicativo ou alterações nas configurações padrão.

Por exemplo, se você `diff` os arquivos `newrelic.yml` padrão para as versões 7.10.0 e 7.11.0 do agente Java, os resultados impressos no console serão como:

```yaml
➜ diff newrelic_7.10.0.yml newrelic_7.11.0.yml
...
107a108,119
>       # Whether the log events should include context from loggers with support for that.
>       context_data:
>
>         # When true, application logs will contain context data.
>         enabled: false
>
>         # A comma separated list of attribute keys whose values should be sent to New Relic.
>         #include:
>
>         # A comma separated list of attribute keys whose values should not be sent to New Relic.
>         #exclude:
>
125a138
>
128c141
<     enabled: false
---
>     enabled: true
...
```

Neste exemplo, essas linhas foram adicionadas ao `newrelic.yml` padrão na versão 7.11.0 do agente Java. Se você estiver migrando para a 7.11.0 ou superior, você deve adicionar estas novas linhas ao seu `newrelic.yml` original.
