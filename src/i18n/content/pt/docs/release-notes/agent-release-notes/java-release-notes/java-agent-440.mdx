### Melhorias

* Java 10

O agente Java da New Relic agora é totalmente compatível com o Java 10. Para mais informações sobre a versão do JDK e o agente Java, consulte [este tópico no Explorers Hub](https://support.newrelic.com/s/hubtopic/aAX8W0000008ZWk/jdk-releases-and-the-java-agent).

* Não compatível com Java 6

Para continuar a inovar e fornecer novos recursos de forma eficiente aos nossos clientes que executam na JVM, esta e as futuras versões do agente não são compatíveis com o Java 6. Caso esteja executando o Java 6, é possível continuar usando o agente Java 4.3.0 ou inferior. Para obter detalhes, consulte [este tópico no Explorers Hub](https://discuss.newrelic.com/t/with-support-for-java-10-new-relic-deprecates-java-6/57738).

* Akka 2.5 e Akka HTTP 10.1

O agente Java agora suporta Akka 2.5.x e Akka HTTP 10.1.x. Será possível ver as chamadas Akka HTTP como transações do New Relic, ver as transferências entre os atores Akka e entender as chamadas para outros banco de dados e serviços.

* Solr 7

O agente Java agora oferece suporte ao Solr 7.x. O suporte ao Solr da New Relic relata chamadas de banco de dados para servidores Solr, bem como monitora o próprio servidor Solr.

Problema conhecido: a coleta de estatísticas JMX para o Solr 7 não é suportada a partir desta versão.

* Fonte de dados do WebLogic

O agente Java agora exibe dados de integridade sobre a fonte de dados do WebLogic na guia Datasource, na página da JVM.

### Correções

* Corrigido um problema em que o agente Java 4.3.0 não relatava dados dependendo da configuração de localidade da JVM. Agente Java 4.3.0 falhou ao enviar dados de evento se a localidade da JVM estiver configurada para usar uma vírgula como decimal. Seria possível ver NumberFormatException no log do agente.
* Corrigido um problema raro em que o agente tentará incorretamente retransformar classes continuamente quando uma extensão com uma data de modificação no futuro for usada, causando um aumento significativo na carga da CPU.
* Corrigida uma ConcurrentModificationException causada pela instrumentação ning que se manifesta na instrumentação Mule, o que faz com que a solicitação afetada seja repetida e o agente Java não relate os dados de cabeçalho.
* Corrigido um problema em que, se `enable_auto_app_naming` fosse definido como true e `distributed_tracing.enabled` fosse definido como true, ele faria a amostragem de cada evento de distributed trace. Agora, se o agente tiver ambas as configurações habilitadas, ele não ativará o distributed tracing.
