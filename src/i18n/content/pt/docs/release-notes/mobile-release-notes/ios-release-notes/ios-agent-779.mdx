bugs:
  - 'Fixed a crash (`SIGSEGV` or `SIGBUS` in `SessionAttributeManager::generateJSONObject`) on the harvest thread, which could also corrupt the heap and cause crashes elsewhere. The agent copied its internal session attributes, such as `memUsageMb` and `lastInteraction`, during a harvest without holding the lock that guards them, so it could read them while another thread was updating them. This issue was present in 7.7.8 and earlier.'
  - 'Fixed the main thread blocking, and apps being terminated by the iOS watchdog (`0x8BADF00D`), once the event buffer was full and the app kept making network requests. The agent held a lock while it rewrote its on-disk copy of buffered events, and threads recording events, including the main thread, waited on that lock. Events dropped from a full buffer were also never removed from that copy, so it grew and was rewritten in full for every new event. Writes now happen without holding the lock, are batched, and dropped events are removed. This issue was present in 7.7.8 and earlier.'
  - 'Fixed events occasionally going unreported when they were recorded, for example by a network request finishing, at the same moment the agent collected buffered events for a harvest. The agent cleared the buffer a second time after releasing its lock, which discarded any event added in between before it was sent. This issue was present in 7.7.8 and earlier.'
  - 'Fixed the agent''s own JSON work being recorded as app activity. `NSJSONSerialization` is instrumented for interaction traces, and the agent called it directly for every log message as well as for session attributes and handled exceptions. That added the agent''s internal work to interaction traces and, when the app logged heavily, could overwhelm tracing. The agent now calls the original, uninstrumented implementation. This issue was present in 7.7.8 and earlier.'
  - 'Fixed Session Replay accessibility identifier masking rules set in Application Settings being ignored on iOS. New Relic sends these rules to iOS apps with the identifier `accessibilityIdentifier`, but the agent only recognized `tag`, so every such rule was dropped. Both values are now accepted. A malformed rule is now skipped with a warning instead of discarding every rule or crashing the agent.'
  - 'Fixed possible crashes in Session Replay masking. Masking lists could be updated by a reconnect, or by `addSessionReplayMaskedAccessibilityIdentifier:` and related APIs, while a frame was being captured, without holding the lock that capture uses. Custom masking rules containing values that can''t be saved to `NSUserDefaults`, such as `null`, could also stop the app when the agent saved its configuration. Rules are now cleaned before they are stored, and every update to the masking lists is locked.'
  - 'Fixed `WKWebView` navigations being reported without a URL in apps built with the iOS 27 SDK. With that SDK, `WKWebView.URL` can still be `nil` when a navigation starts. The agent now falls back to the main-frame request URL from `decidePolicyForNavigationAction`.'
  - Fixed possible EXC_BAD_ACCESS crash when using `addHTTPHeaderTrackingFor`.

### Correções de bugs

* Corrigida uma falha (`SIGSEGV` ou `SIGBUS` em `SessionAttributeManager::generateJSONObject`) na thread de harvest, que também poderia corromper o heap e causar falhas em outros lugares. O agente copiava seus atributos de sessão internos, como `memUsageMb` e `lastInteraction`, durante um harvest sem manter o bloqueio que os protege, de modo que poderia lê-los enquanto outra thread os atualizava. Esse problema estava presente na versão 7.7.8 e anteriores.
* Corrigido o bloqueio da thread principal e o encerramento de aplicativos pelo watchdog do iOS (`0x8BADF00D`), quando o buffer de eventos estava cheio e o aplicativo continuava fazendo requests de rede. O agente mantinha um bloqueio enquanto reescrevia sua cópia em disco dos eventos em buffer, e as threads que registravam eventos, incluindo a thread principal, aguardavam esse bloqueio. Eventos descartados de um buffer cheio também nunca eram removidos dessa cópia, então ela crescia e era totalmente reescrita para cada novo evento. As gravações agora ocorrem sem manter o bloqueio, são feitas em lote, e os eventos descartados são removidos. Esse problema estava presente na versão 7.7.8 e anteriores.
* Corrigidos eventos que ocasionalmente não eram relatados quando eram registrados, por exemplo, pela conclusão de um request de rede, no mesmo momento em que o agente coletava eventos em buffer para um harvest. O agente limpava o buffer uma segunda vez após liberar seu bloqueio, o que descartava qualquer evento adicionado nesse intervalo antes de ser enviado. Esse problema estava presente na versão 7.7.8 e anteriores.
* Corrigido o próprio trabalho JSON do agente sendo registrado como atividade do aplicativo. `NSJSONSerialization` é instrumentado para trace da interação, e o agente o chamava diretamente para cada mensagem do log, bem como para atributos de sessão e exceções tratadas. Isso adicionava o trabalho interno do agente aos traces da interação e, quando o aplicativo registrava muitos logs, podia sobrecarregar o tracing. O agente agora chama a implementação original, não instrumentada. Esse problema estava presente na versão 7.7.8 e anteriores.
* Corrigidas as regras de mascaramento do identificador de acessibilidade do Session Replay definidas nas configurações do aplicativo sendo ignoradas no iOS. A New Relic envia essas regras para aplicativos iOS com o identificador `accessibilityIdentifier`, mas o agente reconhecia apenas `tag`, então todas essas regras eram descartadas. Ambos os valores agora são aceitos. Uma regra malformada agora é ignorada com um aviso em vez de descartar todas as regras ou causar falha no agente.
* Corrigidas possíveis falhas no mascaramento do Session Replay. As listas de mascaramento podiam ser atualizadas por uma reconexão, ou por `addSessionReplayMaskedAccessibilityIdentifier:` e APIs relacionadas, enquanto um quadro estava sendo capturado, sem manter o bloqueio que a captura usa. Regras de mascaramento personalizadas contendo valores que não podem ser salvos em `NSUserDefaults`, como `null`, também podiam interromper o aplicativo quando o agente salvava sua configuração. As regras agora são limpas antes de serem armazenadas, e todas as atualizações nas listas de mascaramento são bloqueadas.
* Corrigidas as navegações `WKWebView` sendo relatadas sem um URL em aplicativos criados com o SDK do iOS 27. Com esse SDK, `WKWebView.URL` ainda pode ser `nil` quando uma navegação é iniciada. O agente agora recorre ao URL do request do main-frame de `decidePolicyForNavigationAction`.
* Corrigida possível falha EXC\_BAD\_ACCESS ao usar `addHTTPHeaderTrackingFor`.
