### Novidades

#### Solucionar problemas do Kafka com o Autopilot

O Autopilot agora pode solucionar melhor os problemas do Kafka e recomendar os próximos passos para mitigá-los, para o Kafka monitorado com a integração no host do New Relic, o OpenTelemetry, o Amazon MSK e o Confluent Cloud.

* **Integridade do cluster:** verifica o lag do consumidor, as partições sub-replicadas e offline, e o estado do broker e do controlador.
* **Mapeamento de relacionamento de entidades:** mapeia relacionamentos em todo o ecossistema, conectando produtores, consumidores, tópicos, brokers, clusters e infraestrutura de host.
* **Desempenho do cliente:** analisa a solicitação de um produtor ou consumidor e obtém latência, espera de I/O, taxa de consumo e tempo de sondagem.

#### Monitoramento de Alterações para o GitHub Copilot

<Callout title="visualização">
Ainda estamos trabalhando neste recurso, mas adoraríamos que você o experimentasse! Este recurso está sendo fornecido atualmente como parte de um programa de pré-visualização, de acordo com nossas [políticas de pré-lançamento](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

O Autopilot agora pode ajudar a monitorar o seu serviço após cada implantação e relatar os resultados no seu pull request. Em seis pontos de verificação após uma implantação (10 minutos, 30 minutos, 1 hora, 2 horas, 24 horas e 72 horas), o Autopilot compara as métricas pós-implantação com um baseline e publica o resultado como um comentário no PR. Quando detecta uma regressão, o Autopilot publica suas descobertas no Slack e abre uma issue no GitHub atribuída ao GitHub Copilot. Com o GitHub Copilot Enterprise, o Copilot pode propor uma correção como um pull request.

* **Relatórios de checkpoint no seu PR:** em cada checkpoint, o Autopilot comenta no pull request com o resultado — nenhuma regressão, inconclusivo ou regressão detectada — para que sua equipe veja o sinal sem sair do GitHub.
* **Notificações do Slack:** se você conectou o Slack, o Autopilot publica uma mensagem quando o monitoramento é iniciado para uma implantação e responde na mesma thread em cada ponto de verificação.
* **Issues automáticas de regressão:** quando o Autopilot detecta uma regressão, ele abre uma issue no GitHub com o que regrediu, as evidências de suporte, onde procurar e os critérios de aceitação, e atribui a issue ao GitHub Copilot.
* **Gatilho de rótulo de PR:** adicione o rótulo `watchpoint_monitoring` a um pull request antes de implantar para ativar o monitoramento para essa implantação, sem a necessidade de definir o atributo `watchpoint_monitoring` no seu evento de Monitoramento de Alterações. Você escolhe quais implantações monitorar, sem a necessidade de alterações no pipeline.

Para obter instruções de configuração e os pré-requisitos completos, consulte [Monitorar a implantação com o New Relic Monitoramento de Alterações para GitHub Copilot](/docs/agentic-ai/autopilot/change-tracking-for-github-copilot/).

### Resolução de problemas do Kafka, monitoramento de implantação e muito mais

#### Novo recurso

* **Solucione problemas do Kafka com o Autopilot:** o Autopilot agora pode solucionar melhor os problemas do Kafka e recomendar as próximas etapas para mitigá-los, para o Kafka monitorado com a integração no host do New Relic, OpenTelemetry, Amazon MSK e Confluent Cloud.
* **Monitoramento de Alterações para o GitHub Copilot (Preview):** o Autopilot agora pode ajudar a monitorar o seu serviço após cada implantação e relatar os resultados no seu pull request.
* **Visualize os dados de uso do Autopilot por usuário:** usando o Gerenciamento de consumo, agora você pode ver o uso de consumo do Autopilot detalhado por usuário.
* **Descoberta de logs e métricas para infraestrutura:** durante investigações de infraestrutura, o Autopilot agora pode analisar os logs de uma entidade e consultar os nomes de métricas que ela reporta.

#### Melhorias e correções

* **Pesquisa de problemas aprimorada:** o Autopilot agora resolve problemas de alerta de forma mais confiável — variantes de nome com sufixo não ficam mais ocultas atrás de correspondências exatas, problemas fechados podem ser resolvidos com mais confiabilidade para investigação retrospectiva e o status de relatório é exibido para que entidades desatualizadas não prevaleçam sobre as ativas.
* **Respostas rápidas mais completas:** as listas mostram cada item, até 50, e as respostas incluem detalhes por trás das contagens, como entidades críticas e issues abertas.
* **Totais de CCU:** os totais de CCU em respostas rápidas não incluem mais valores de volume de dados.
* **Intervalos de tempo que você solicita:** o Autopilot pode solicitar a você um intervalo de tempo para investigação.
* **Verificações focadas em problemas em andamento:** perguntar se um problema ainda está ocorrendo agora verifica o período mais recente.
* **Tempos de início de incidentes aprimorados:** as investigações de incidentes agora começam a partir do momento em que o problema foi aberto.
* **Roteamento de perguntas mais confiável:** o Autopilot aprimorou o tratamento de caminhos com base no contexto da sua pergunta.
* **As investigações continuam quando um serviço de ferramenta está inativo:** o Autopilot continua com as ferramentas restantes quando um serviço de ferramenta conectado está indisponível.
* **Descobertas mantidas quando uma investigação atinge seu orçamento:** o Autopilot agora pode resumir as descobertas que reuniu antes que uma investigação atingisse seu limite de orçamento.
* **Investigações mais resilientes:** o Autopilot tem maior probabilidade de concluir uma investigação quando um de seus serviços de ferramentas conectados está indisponível, e é mais capaz de se recuperar de lentidões temporárias.
* **Resumos de investigação mais completos:** os resumos de investigações em várias etapas têm maior probabilidade de incluir a análise completa, e gráficos aparecem em mais deles.
* **Melhores respostas para perguntas sobre Sintéticos:** o Autopilot agora pode responder melhor a perguntas sobre as listas, contagens e o status de todos os monitores em uma conta, e identifica melhor uma conta que você indicar em sua pergunta. A análise de uma verificação com falha agora se concentra na etapa que falhou.
* **As preferências salvas se adequam à pergunta atual:** as preferências salvas de conversas anteriores têm menos probabilidade de influenciar excessivamente o que a sua pergunta atual exige, como uma pergunta de esclarecimento quando nenhuma entidade é nomeada.
* **Mais das suas coleções da base de conhecimento:** quando você especifica uma coleção da base de conhecimento, o Autopilot agora inclui mais de seus resultados e tem maior probabilidade de informar se não conseguir recuperar um documento.
* **Mais contexto de alerta em investigações:** o Autopilot agora pode utilizar mais detalhes da condição do alerta, como o limite e a entidade afetada, ao investigar um problema.
* **Análise de workload:** o Autopilot agora pode revisar as entidades membro de um workload e contar entidades por atributo.
* **Timestamps consistentes em respostas rápidas:** os timestamps e as durações nas respostas rápidas são mais consistentes.
* **Pesquisas de incidentes para issues abertas:** resolvido um problema que fazia com que o Autopilot não relatasse incidentes para uma issue aberta e válida.
* **Status preciso das etapas:** foi resolvido um problema que fazia com que uma etapa de investigação inacabada fosse exibida como concluída.
* **Confiabilidade da pesquisa de entidades:** foi resolvido um problema que fazia com que algumas pesquisas de entidades não fossem acionadas.
* **Novas conversas a partir da página de alertas:** o botão **New conversation** agora abre um novo tópico a partir da página de alertas.
* **Exemplos de prompt específicos da página:** as páginas que fornecem seus próprios exemplos de prompt agora os exibem no painel do Autopilot.
