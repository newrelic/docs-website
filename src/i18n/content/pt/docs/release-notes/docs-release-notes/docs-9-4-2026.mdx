### Novos documentos

* Adicionada a [Triagem de correção de vulnerabilidades com o agente Security RX](/docs/vulnerability-management/agent/overview) para fornecer orientação sobre o uso do agente Security RX para analisar CVEs, gerar planos de correção e acionar agentes de codificação para abrir pull requests.
* Adicionado o [fluxo de trabalho do Jira do Security RX](/docs/vulnerability-management/workflows/jira) para fornecer instruções passo a passo para criar e sincronizar automaticamente tickets do Jira para vulnerabilidades de segurança detectadas pelo Security RX.
* Adicionado [Solucionar problemas do New Relic MCP](/docs/agentic-ai/mcp/troubleshoot) para fornecer etapas comuns de resolução de problemas e soluções para resolver problemas de instalação e configuração do servidor MCP.

### Grandes mudanças

* Reestruturado o [Monitoramento do Microsoft SQL Server com NRDOT](/docs/opentelemetry/database/mssql/introduction) com uma nova referência abrangente de configuração, um novo guia de configuração do coletor CNCF e documentos de instalação reformulados para ambientes hospedados no Windows, Windows RDS, hospedados no Linux e Linux RDS.
* Atualizado [Tipos de agente](/docs/new-relic-control/agent-control/agent-types) com documentação para configurar o encaminhamento de logs do Fluent Bit no Agent Control, incluindo o posicionamento do arquivo de configuração, caminhos de binários por sistema operacional e comportamento de atualização.
* Atualizado [Gerenciar frotas](/docs/new-relic-control/fleet-control/manage-fleets) com documentação abrangente para o novo fluxo de trabalho de aprovação de configuração no Controle de Agentes. As aprovações de configuração exigem pelo menos um revisor além do autor antes que uma versão de configuração possa ser implantada, com aplicação a partir de 22 de setembro de 2026.
* Atualizado o [esquema de definição de automação de fluxo de trabalho](/docs/workflow-automation/workflow-automation-apis/definition-schema) com a nova ação State Step para persistir pares de valor principal nas etapas do fluxo de trabalho via `.workflowState`, e atualizados os [limites do fluxo de trabalho](/docs/workflow-automation/limitations-and-faq/workflow-limits) e o [monitoramento de execução](/docs/workflow-automation/manage-workflows/monitor-workflow-execution) para cobrir o novo tipo de etapa e os dados de `WorkflowAutomationEvent`.
* Adicionado suporte ao VMware vSphere Kubernetes Service (VKS) 3.x aos [requisitos de compatibilidade da integração do Kubernetes](/docs/kubernetes-pixie/kubernetes-integration/get-started/kubernetes-integration-compatibility-requirements), cobrindo o VKS em execução no vSphere Supervisor 9.0 a 9.1 (vSphere 8.x e 9.x).
* Atualizados os [requisitos de compatibilidade do agente .NET](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) com as versões de biblioteca compatíveis verificadas mais recentes.
* Atualizado [Catálogos](/docs/service-architecture-intelligence/catalogs/catalogs) para documentar a filtragem de valor de coluna baseada em tag por meio de pílulas interativas e reordenação de colunas por arrastar e soltar na tabela de visualização Personalizar.
* Adicionado um aviso à [Inteligência de resposta com IA](/docs/alerts/alert-event-management/response-intelligence-ai) afirmando que os insights gerados por IA são sugestões para orientar a investigação, não causas raízes confirmadas, e devem ser verificados em relação aos seus dados antes de agir sobre eles.
* Adicionada a biblioteca de código aberto `snapdom` às [licenças do Agente do Browser do New Relic](/docs/licenses/product-or-service-licenses/new-relic-browser/new-relic-browser-licenses).
* Atualizada a [aba OpenTelemetry do Errors Inbox](/docs/errors-inbox/otel-tab) para corrigir o nome do atributo de span de `otel.status` para `otel.status_code` e expandir os tipos de span suportados para incluir `producer`, `client` e `internal`, além de `server` e `consumer`.
* Atualizado [Escolha seu data center](/docs/accounts/accounts-billing/account-setup/choose-your-data-center) para refletir que a região de dados do Japão (JP) agora está disponível de forma geral.

### Pequenas mudanças

* Atualizado [Configurar o New Relic MCP](/docs/agentic-ai/mcp/setup) com comandos corrigidos da CLI do Claude Code para autenticação OAuth, um requisito de versão mínima (Claude Code v2.1.186+), e um formato de configuração JSON simplificado.
* Adicionado `nrExporterEndpoints` à [Referência de configuração YAML do Gateway](/docs/new-relic-control/pipeline-control/gateway/yaml-overview) para substituir os endpoints de ingestão padrão da New Relic por pipeline, incluindo um novo campo `otlpEndpoint`, em uma seção dedicada de substituições opcionais.
* Atualizada a [resolução de problemas da API de trace](/docs/apm/distributed-tracing/trace-api/troubleshooting-missing-trace-api-data) e [dados de trace ausentes](/docs/distributed-tracing/troubleshooting/missing-trace-data) com os limites de timestamp de span mais antigos corrigidos para OTLP e API de trace.
* Adicionada uma seção de avisos de cardinalidade a [Gerenciar cardinalidade](/docs/data-apis/ingest-apis/metric-api/cardinality-management) explicando o que acontece quando um orçamento de cardinalidade é atingido, como identificar métricas afetadas por meio de indicadores de aviso em gráficos e dashboards, e como consultar dados brutos durante a correção.
* Adicionado o namespace Direct to Live Archives como uma terceira opção de partição para [Partições de dados](/docs/logs/ui-data/data-partitions) e adicionada orientação para [Live Archives](/docs/logs/get-started/live-archives) explicando que esse namespace ignora a retenção padrão para logs de conformidade e auditoria que vão diretamente para o armazenamento de longo prazo.
* Corrigida a descrição do erro `403 Forbidden` em [Relatório de erros de JavaScript do React Native](/docs/mobile-monitoring/new-relic-monitoring-react-native/react-native-agent-js-error-reporting) para afirmar que a chave de API deve pertencer a um usuário com permissões de visualização de entidade móvel.
* Atualizado [RCA de alerta com Autopilot e Slack](/docs/workflow-automation/workflow-examples/integrations/autopilot-slack-rca) com uma dica sobre o uso da variável `{{ issueId }}` para passar automaticamente o ID do problema do alerta acionador ao integrar com fluxos de trabalho de alerta.
* Atualizado [Fazer downgrade ou cancelar conta](/docs/accounts/accounts-billing/account-setup/downgradecancel-account) para adicionar um destaque esclarecendo que a última conta ativa em uma organização não pode ser cancelada de forma independente e deve ser removida excluindo a organização, e melhorou as etapas de exclusão da organização para maior clareza.
