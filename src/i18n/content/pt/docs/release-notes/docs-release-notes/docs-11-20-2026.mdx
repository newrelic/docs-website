### Novos documentos

* Adicionado [Instalar o New Relic com um agente de programação de IA](/docs/new-relic-solutions/get-started/install-with-ai) com um prompt de copiar e colar para que agentes de programação de IA, como Claude Code, Cursor, GitHub Copilot e Codex, possam encontrar a documentação de instalação correta, verificar a instalação e manter sua chave de licença fora do contexto deles.
* Adicionadas as [Perguntas frequentes sobre a observabilidade do Collector](/docs/opentelemetry/collector-observability/collector-observability-faq), abrangendo versões compatíveis do coletor, formatos de exportação, detecção automática, classificação automática e coletores anexados, para que as respostas detalhadas fiquem em um só lugar em vez de nas páginas de visão geral e configuração.
* Adicionada a [referência de configurações do Controle de agentes](/docs/new-relic-control/agent-control/configuration-reference), que lista as configurações do Controle de agentes que você pode modificar, como opções de logging, proxy, servidor de status, verificações de integridade, autoinstrumentação e registro OCI, com seus valores padrão.
* Adicionados [Instalar e configurar o NRDOT para monitoramento do MySQL com o servidor flexível do Azure](/docs/opentelemetry/db360/mysql/azure) e [Instalar e configurar o NRDOT para monitoramento do PostgreSQL com o servidor flexível do Azure](/docs/opentelemetry/db360/postgresql/azure) para que as equipes que executam o MySQL ou o PostgreSQL no Azure possam configurar a observabilidade de banco de dados com o NRDOT Collector.
* Adicionado o [Boletim de segurança NR26-13](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-13) com o impacto do comprometimento da autoridade de certificação eMudhra nas integrações de logs (plug-in de saída do Fluent Bit, encaminhamento de logs do agente de infraestrutura e chart do Helm).
* Adicionado o [Boletim de segurança NR26-14](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-14) com o impacto do comprometimento da autoridade de certificação eMudhra na integração do Kubernetes, incluindo o nri-bundle e os charts do Helm relacionados.
* Adicionado o [Boletim de segurança NR26-15](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-15) com o impacto do comprometimento da autoridade de certificação eMudhra no agente de infraestrutura e nas integrações no host.
* Adicionado o [Boletim de segurança NR26-16](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-16) para a falha de execução remota de código OpenJDK Java4Shell (CVE-2026-114938), com itens de ação para os componentes afetados da New Relic.
* Adicionado o [Boletim de segurança NR26-17](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-17) para a vulnerabilidade de corrupção de memória Ruby2Shell (CVE-2026-132825) e seu impacto nas imagens de contêiner `newrelic-fluentd-docker`, `newrelic/fluentd` e `k8s-golang-apm-linkage-demo`, observando que nenhuma ação é necessária para clientes que usam agentes Ruby.

### Grandes mudanças

* A [Observabilidade do Collector](/docs/opentelemetry/collector-observability/collector-observability) agora está disponível para o público geral. Atualizadas as páginas de visão geral e [configuração](/docs/opentelemetry/collector-observability/collector-observability-setup) com novas capturas de tela e um link para as novas [Perguntas frequentes sobre a observabilidade do Collector](/docs/opentelemetry/collector-observability/collector-observability-faq) para explicações detalhadas.
* Reescritos o [Agente iOS da New Relic e distributed tracing](/docs/mobile-monitoring/new-relic-mobile-ios/get-started/new-relic-ios-and-dt) e o [Agente Android da New Relic e distributed tracing](/docs/mobile-monitoring/new-relic-mobile-android/get-started/new-relic-android-and-dt) para explicar quais requests recebem trace automaticamente, o que você precisa habilitar para a correlação de trace e como desativar o trace. Removido o vídeo desatualizado de ambas as páginas.
* Atualizado o [Conceitos importantes de gerenciamento de usuários e acesso](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts) com tabelas de funções padrão para os escopos de organização, conta e entidade, incluindo funções de frota, segredo, conector do Lens, agente de IA, macro do NRQL, notebook, política de alertas e dashboard, para que os administradores possam ver o que cada função padrão concede.
* Atualizada a [Verificação de exposição](/docs/vulnerability-management/exposure-check) para cobrir o aviso do Java4Shell (CVE-2026-114938) junto com os avisos do PHP e Node.js, e para descrever os novos cartões de resumo <DNT>Exposure</DNT> e <DNT>How to fix</DNT>, para que os usuários possam encontrar quais entidades do APM executam uma versão afetada do Java.
* Atualizado o [Configurar definições de privacidade](/docs/mobile-monitoring/mobile-monitoring-ui/mobile-session-replay/configure-privacy-settings) para o Session Replay mobile para corrigir exemplos que não compilavam e regras de tag que não correspondiam ao comportamento do agente no iOS, Android e React Native, e para esclarecer que os campos de senha permanecem mascarados.
* Atualizado [Configuração do MCP](/docs/agentic-ai/mcp/setup) e [Visão geral do MCP](/docs/agentic-ai/mcp/overview) com o Cursor como um cliente MCP compatível, incluindo os requisitos, o acesso e a configuração `mcp.json` para autenticação com uma chave de API de usuário.
* Atualizado [Conectar o Autopilot ao Slack](/docs/agentic-ai/autopilot/connect-to-slack) com o botão <DNT>**Investigate with AI**</DNT> nas notificações de alerta, para que as equipes possam iniciar uma investigação a partir de uma thread de alerta do Slack sem escrever um prompt.
* Atualizados os [Logs do eBPF](/docs/ebpf/logs), a [Instalação do Kubernetes](/docs/ebpf/k8s-installation) e a [Instalação do Linux](/docs/ebpf/linux-installation) para refletir que `reportLogs` agora tem como padrão `"auto"` em vez de `"false"` e que o `fileRegex` padrão agora é `".*\\.log$"`.
* Atualizadas as [Configurações de distributed tracing do agente Ruby](/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration-distributed-tracing-settings) e a [Amostragem de distributed trace](/docs/apm/distributed-tracing/distributed-trace-sampling) com as configurações do amostrador `trace_id_ratio_based` para o agente Ruby, para que os usuários possam configurar a amostragem baseada em proporção.
* Removidas as métricas que a New Relic não coleta das páginas de integração do [Google BigQuery](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-bigquery-monitoring-integration), do [Google Cloud Pub/Sub](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-pubsub-monitoring-integration) e do [Google Cloud Storage](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-cloud-storage-monitoring-integration) porque o Google não as define ou as lista como alfa ou descontinuadas.

### Pequenas mudanças

* Atualizado o [Encontre ajuda e obtenha suporte](/docs/new-relic-solutions/solve-common-issues/find-help-get-support) com uma tabela de definição de status de caso para explicar o que significa cada status de caso de suporte.
* Atualizada a [referência de ferramentas MCP](/docs/agentic-ai/mcp/tool-reference) com as ferramentas `get_retention_policy_and_namespaces`, `get_user_id` e `list_support_cases` somente leitura e a habilidade Kafka Autopilot.
* Atualizada a [Visão geral do MCP](/docs/agentic-ai/mcp/overview) para explicar que remover um usuário de todos os grupos com permissões de servidor MCP é uma maneira de menor impacto para revogar o acesso de um usuário do que excluir o usuário.
* Atualizado o [Tipos de agentes](/docs/new-relic-control/agent-control/agent-types) para explicar por que o Controle de agentes relata um estado de integridade `unknown` para integrações no host e que os arquivos de saída `enable_file_logging` não são rotacionados.
* Atualizada a [Identificação do serviço de banco de dados com o NRDOT](/docs/opentelemetry/db360/capabilities/db-apm) para exigir o agente Java v9.4.0 ou superior e para mostrar a configuração `sql_metadata_comments.enabled`.
* Atualizado [Configurar conectores](/docs/new-relic-lens/set-up-connectors) com as versões compatíveis do MongoDB e do Azure Cosmos DB for MongoDB (4.2 ou mais recente).
* Atualizado [Gerenciamento de cardinalidade](/docs/data-apis/ingest-apis/metric-api/cardinality-management) para esclarecer que você pode aumentar o limite de cardinalidade por métrica até o limite da sua conta.
* Atualizado [KPIs inteligentes de workload](/docs/new-relic-solutions/new-relic-one/workloads/intelligent-workload-kpis) para esclarecer que os dados de KPI começam a partir do momento em que você cria o KPI e que o New Relic não os preenche retroativamente.
* Atualizado [Encaminhar logs do Google Cloud Platform](/docs/logs/forward-logs/google-cloud-platform-log-forwarding) para informar que o modelo do Dataflow requer o Java 11 ou posterior.
* Atualizadas as páginas de compatibilidade e requisitos do [agente Node.js](/docs/apm/agents/nodejs-agent/getting-started/compatibility-requirements-nodejs-agent) e do [agente .NET](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements) com as versões de biblioteca mais recentes verificadas.

### Notas de versão

* Fique por dentro dos nossos últimos lançamentos:

  * [Agente Python v14.3.0](/docs/release-notes/agent-release-notes/python-release-notes/python-agent-14-03-00):

    * Habilitado o AI Monitoring por padrão. A instrumentação de LLM agora envia `Llm*` eventos, spans e métricas sem o conteúdo da mensagem, a menos que você opte por desativar essa opção.
    * Descontinuada a configuração `ai_monitoring.enabled` em favor de `ai_monitoring.basic_telemetry.enabled`.
    * Corrigida uma falha na instrumentação `StructuredTool` do LangChain quando nenhuma configuração é passada.

  * [Agente Node.js v14.13.0](/docs/release-notes/agent-release-notes/nodejs-release-notes/node-agent-14-13-0):

    * Adicionado `event.name` aos logs quando `eventName` existe em um registro de log do OpenTelemetry.
    * Corrigidos o protocolo e a porta dos requests de saída `http` e `https`.
    * Corrigida a captura de cabeçalhos de resposta para `writeHead`.
    * Retornou a promise do manipulador do aplicativo a partir do wrapper `eachMessage` do kafkajs.

  * [Agente .NET v10.58.0](/docs/release-notes/agent-release-notes/net-release-notes/net-agent-10-58-0):

    * Habilitada a telemetria básica de IA por padrão.
    * Aplicada a ofuscação de SQL compatível com a especificação ao MySQL, Oracle, SQL Server, Postgres e outros armazenamentos de dados.
    * Capturados cabeçalhos de request em transações de gatilho HTTP do Azure Function.
    * Corrigida a captura do plano de explicação para MySQL e SQL Server.

  * [Agente PHP v12.13.0.43](/docs/release-notes/agent-release-notes/php-release-notes/php-agent-12-13-0-43):

    * Adicionada instrumentação para `mysqli_execute_query` e `mysqli::execute_query`.
    * Suporte verificado para Ubuntu 26.04 e Alpine 3.24.
    * Adicionados dados de lançamento para hashes de tarball, digests de imagem e impressões digitais de chave de assinatura.
    * Atualizado o Go para 1.27.4 e `golang.org/x/net` para 0.62.0 no daemon.

  * [Agente de infraestrutura v2.1.1](/docs/release-notes/infrastructure-release-notes/infrastructure-agent-release-notes/new-relic-infrastructure-agent-211):

    * Adicionado suporte para SUSE 16.

    * Atualizado o Go para 1.27.4 e atualizadas as integrações no host incorporadas.
