### Novos documentos

* Adicionada a [Browser: aba de agrupamento de erros de requests](/docs/triage-inbox/group-request-errors-browser/) para mostrar a você como agrupar, ordenar e filtrar requests AJAX e fetch com falha.
* Adicionada a [Verificação de exposição (pré-visualização do Security RX)](/docs/vulnerability-management/exposure-check/) para listar a entidade APM que executa uma versão do PHP ou Node.js afetada por um aviso de segurança recente.
* Adicionamos [Identidades do sistema](/docs/accounts/accounts-billing/new-relic-one-user-management/system-identities/) para explicar como provisionar identidades não humanas que se autenticam no New Relic com suas próprias credenciais.
* Adicionada a [integração de monitoramento do Google Gemini Enterprise](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-gemini-enterprise-monitoring-integration/), que abrange como ativar a integração e as métricas de solicitação, latência, sessão e cota que ela coleta para aplicativos, agentes, ferramentas e conectores de dados.
* Foram adicionadas [ações de configuração do New Relic Logs](/docs/workflow-automation/setup-and-configure/actions-catalog/newrelic/log-configurations/newrelic-log-configurations/) ao catálogo de ações de automação de fluxo de trabalho para consultar e atualizar regras de análise de log, partição e ofuscação.
* Adicionado o [Boletim de segurança NR26-12](/docs/security/new-relic-security/security-bulletins/security-bulletin-nr26-12/) com as etapas para baixar as imagens atualizadas do contêiner de localização privada do Sintéticos após o comprometimento da autoridade de certificação eMudhra.

### Grandes mudanças

* Atualizado o artigo [Faça a triagem da sua frota do Kubernetes](/docs/kubernetes-pixie/kubernetes-integration/understand-use-data/explore-k8s/), anteriormente a página entre clusters, com a visualização de triagem de toda a frota que classifica os problemas em seus clusters.
* Atualizamos a [instalação do agente Ruby](/docs/apm/agents/ruby-agent/installation/install-new-relic-ruby-agent/) para simplificar a instalação em três etapas e dividimos as configurações da [configuração do agente Ruby](/docs/apm/agents/ruby-agent/configuration/ruby-agent-configuration-overview/) em páginas de tópicos para que você possa encontrar as opções por categoria.
* Removemos a documentação do CodeStream após o fim de sua vida útil em 5 de novembro de 2026, reescrevemos as páginas de métricas de nível do código do agente para remover as referências ao CodeStream e adicionamos redirecionamentos para que os links existentes continuem funcionando.
* Atualizado o [New Relic Ground Truth](/docs/agentic-ai/mcp/overview/) com uma seção sobre como proteger o acesso ao MCP, incluindo a revogação de tokens OAuth e a auditoria da atividade de login com `NrAuditEvent`.
* Atualizamos [Gerenciamento de acesso para gerenciar a cardinalidade](/docs/data-apis/ingest-apis/metric-api/cardinality-access-management/) com as permissões necessárias para alterar os orçamentos de cardinalidade por meio do NerdGraph ou do Terraform.
* Atualizamos as [Permissões e funções](/docs/cci/configure-cci/cci-permissions/) da Inteligência de Custos na Nuvem com pré-requisitos de acesso e uma tabela de referência de permissões.
* Atualizado o [Upload de arquivos dSYM](/docs/mobile-monitoring/new-relic-mobile-ios/configuration/upload-dsyms-bitcode-apps/) com a fase de compilação `run-symbol-tool` Run script, que substitui o script de upload do Python removido no agente iOS v7.4.8.
* Atualizamos as [ações do AWS Lambda](/docs/workflow-automation/setup-and-configure/actions-catalog/aws/lambda/aws-lambda/) no catálogo de ações de automação de fluxo de trabalho com valores de exemplo concretos para campos de saída, incluindo exemplos de mensagens de erro e objetos de resposta da API.
* Foi atualizada a página [Gerenciar runtimes de monitor](/docs/synthetics/synthetic-monitoring/using-monitors/manage-monitor-runtimes/) com o runtime do Node.js 22.23.4 e seus módulos de terceiros compatíveis.

### Pequenas mudanças

* Atualizamos [Browser: aba de erros de JavaScript](/docs/triage-inbox/browser-tab/) para renomear **Erros (Errors Inbox)** para **Erros de JavaScript**.
* Atualizado [Instalar o agente Android](/docs/mobile-monitoring/new-relic-mobile-android/install-configure/install-android-agent-gradle/) para recomendar a inicialização do agente no método `onCreate()` da sua classe `Application`.
* Foram atualizadas as [ferramentas do New Relic AI](/docs/agentic-ai/tools/) e as páginas da interface de monitoramento de Mobile com links para as habilidades do Autopilot disponíveis para cada área de produto.
* Atualizadas as [Regras e limites de alertas](/docs/alerts/admin/rules-limits-alerts/) para esclarecer como as condições ativadas e desativadas contam para os limites.
* Atualizados [Introdução aos alertas compostos](/docs/alerts/create-alert/create-alert-condition/compound-alerts/compound-alerts/) e [Regras de silenciamento](/docs/alerts/get-notified/muting-rules-suppress-notifications/) para explicar que as regras de silenciamento agora se aplicam aos alertas compostos.
* Atualizado [Enviar dados do New Relic via AWS PrivateLink](/docs/data-apis/custom-data/aws-privatelink/) para esclarecer que você deve selecionar **PrivateLink Ready partner services** ao criar o endpoint da VPC.
* Adicionada a configuração `safe_dir_check_enabled` às [configurações do agente de infraestrutura](/docs/infrastructure/infrastructure-agent/configuration/infrastructure-agent-configuration-settings/). O padrão dessa configuração é `true` no agente de infraestrutura v2.0.1 — uma alteração incompatível se você dependia do padrão anterior.
* Atualizamos [Otimizar seus dados de ingestão](/docs/tutorial-optimize-telemetry/data-optimize-techniques/) e [Otimizar sua ingestão de dados](/docs/new-relic-solutions/observability-maturity/operational-efficiency/data-governance-optimize-ingest-guide/) para esclarecer como `enable_process_metrics` e `metrics_process_sample_rate: -1` interrompem a amostragem de processos.
* Atualizado [Encaminhar seus logs usando o agente de infraestrutura](/docs/logs/forward-logs/forward-your-logs-using-infrastructure-agent/) para listar o Debian 12 e 13 e o Windows Server 2025, e remover o Debian 11.
* Atualizados [Errors Inbox no APM](/docs/apm/errors-inbox/errors-inbox-ui/) e [Serviços externos do Errors Inbox](/docs/triage-inbox/error-external-services/) para explicar que um grupo de erros não resolvido envia uma nova notificação no Slack se o erro ocorrer novamente após 14 dias.
* A [integração do Azure Monitor](/docs/infrastructure/microsoft-azure-integrations/azure-integrations-list/azure-monitor/) foi atualizada para explicar que os tipos de métricas dimensionais dependem dos dados que o Azure retorna, como `summary`, `gauge` ou `count`.
* Atualizado o artigo [Comece a usar a observabilidade do coletor](/docs/opentelemetry/collector-observability/collector-observability-setup/) para definir `INTERNAL_TELEMETRY_TRACE_LEVEL=basic` quando você experimentar o trace do coletor.
* Atualizado o artigo [Identificação do serviço de banco de dados com NRDOT](/docs/opentelemetry/db360/capabilities/db-apm/) para exigir o agente .NET v10.54.0 ou superior.
* Atualizado [Configurar conectores](/docs/new-relic-lens/set-up-connectors/) para refletir que os nomes dos conectores agora usam um prefixo de sublinhado (`nrlens_`) em vez de um hífen (`nrlens-`).
* Atualizamos o [Plano de uso](/docs/licenses/license-information/usage-plans/new-relic-usage-plan/) com uma seção do Advantage Plan e sua tabela de conversão de pagamento conforme o uso (PAYG).
* O documento [Relatar vulnerabilidades de segurança](/docs/security/security-privacy/information-security/report-security-vulnerabilities/) foi atualizado com uma seção sobre relatórios de vulnerabilidades e impacto de CVE.
* Atualizamos [Encaminhar logs do Google Cloud Platform](/docs/logs/forward-logs/google-cloud-platform-log-forwarding/) para usar `PubSubToNewRelic` como o nome correto do modelo do Dataflow.
* Atualizadas as páginas de compatibilidade e requisitos do [agente Node.js](/docs/apm/agents/nodejs-agent/getting-started/compatibility-requirements-nodejs-agent/) e do [agente .NET](/docs/apm/agents/net-agent/getting-started/net-agent-compatibility-requirements/) com as versões de biblioteca verificadas mais recentes.
* Atualizados [Compatibilidade e requisitos para AI Monitoring](/docs/ai-monitoring/compatibility-requirements-ai-monitoring/) e [Pacotes Python instrumentados](/docs/apm/agents/python-agent/getting-started/instrumented-python-packages/) com o framework de agente da Microsoft e o CrewAI.
* Atualizamos a [integração de monitoramento do Google VertexAI](/docs/infrastructure/google-cloud-platform-integrations/gcp-integrations-list/google-vertexai-monitoring-integration/) para listar o Publisher Model como uma entidade do Vertex AI.
