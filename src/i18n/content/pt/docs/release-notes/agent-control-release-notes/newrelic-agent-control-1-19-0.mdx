### Novo recurso

* No host e no Kubernetes: quando o tipo de um agente é atualizado por meio de uma atualização de configuração remota ao vivo, o Agent Control agora reconcilia os sistemas de arquivos compartilhados e por agente, excluindo os caminhos declarados pelo tipo antigo que não aparecem mais nas declarações de nenhum agente ativo. Caminhos compartilhados em copropriedade ainda reivindicados por outro agente ativo são preservados. No Kubernetes, os objetos k8s anotados com o tipo antigo são coletados pelo garbage collector, enquanto os recursos do novo tipo são deixados intactos.
* Adiciona a CLI `oci-utils` ao `test/crates/oci-test-utils` para enviar pacotes de agente e definições de tipo de agente para registros OCI a partir da linha de comando (ferramentas de desenvolvimento/teste; não publicadas).
* A análise de tipo de agente no host agora valida `reported_version_package`: deve referenciar um pacote declarado e é obrigatório quando mais de um pacote é definido. Configurações inválidas são rejeitadas no momento da análise com um erro descritivo. Este `reported_version_package` determina qual versão é relatada como `agent.version`.
* Adiciona suporte a `copy_from_file` para o sistema de arquivos on-host &quot;no agente&quot;.
* Adiciona suporte a `shared_filesystem` em tipos de agente on-host. Inclui uma regra de proprietário único: dois agentes que reivindicam o mesmo caminho no sistema de arquivos compartilhado são inválidos e relatados como Failed.
* Atualização automática on-host: ignora a reconciliação do subagente quando uma atualização automática está em andamento. Quando uma única configuração remota incrementa a versão do Controle do Agente e altera o `agent_type` de um subagente, o subagente alterado não é mais recriado momentos antes de o processo reiniciar; a nova configuração é armazenada e reaplicada de forma limpa pelo processo reiniciado, evitando uma reinicialização redundante do subagente e uma lacuna de telemetria.
* On-host: adicionado suporte para o agentType nri-redis para Linux e Windows.
* Configuração de integridade no host: substituídos os campos `health.http:` / `health.file:` planos por uma lista `checks:` explícita. Cada entrada é discriminada por `kind:` (`Process`, `Http` ou `File`). A verificação de integridade do processo supervisionado, anteriormente implícita, agora é declarada como `kind: Process`. Uma lista `checks:` omitida ou vazia desativa totalmente os relatórios de integridade.
* As entradas de sistema de arquivos no host (`file`/`dir`) agora sempre sobrevivem à parada, reinicialização e aplicação de configuração do subagente. Uma chave `persistent:` avulsa no YAML de tipo de agente existente é ignorada em vez de rejeitada.

### Correções de bugs

* Adicionados atributos de identificação para cada pacote especificado no agentType como `package.version.<id>`.
* Os pacotes RPM agora restauram `local_config.yaml` do backup `.rpmsave` deixado por uma desinstalação anterior.
