É possível acessar e usar <DNT>Performance Risks inbox</DNT> para identificar e resolver proativamente problemas de desempenho do aplicativo antes que eles afetem o usuário final. Este guia mostra como acessar <DNT>Performance Risks inbox</DNT>, visualizar a visão geral de toda a conta, analisar e obter recomendações para riscos específicos, atualizar os limites de detecção e usar a ferramenta no servidor MCP da New Relic. Para obter mais informações sobre o que é <DNT>Performance Risks inbox</DNT> e seus principais benefícios, consulte a [introdução ao <DNT>Performance Risks inbox</DNT>](/docs/errors-inbox/performance-risks/introduction).

## Acesse a caixa de entrada de Riscos de desempenho [#access]

É possível acessar <DNT>Performance Risks inbox</DNT> de duas maneiras: no nível da entidade, com escopo para uma única entidade ou workload, ou no nível da conta, abrangendo todas as entidades da conta.

* [Acesso em nível de entidade](#access-entity)
* [Acesso no nível da conta](#access-account)

### Acesso em nível de entidade [#access-entity]

No nível da entidade, <DNT>Performance Risks inbox</DNT> mostra problemas de desempenho para os dados de telemetria de uma única entidade ou workload. Isso está disponível para:

* Serviços APM
* Aplicativo Browser
* Carga de trabalho

**Para acessar <DNT>Performance Risks inbox</DNT> para uma entidade:**

1. Vá para <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities)</DNT>, depois selecione <DNT>**APM &amp; Services**</DNT>, <DNT>**Browser**</DNT> ou <DNT>**Workloads**</DNT>.
2. Selecione a entidade ou o workload necessário.
3. No painel de navegação, na seção <DNT>**Triage**</DNT>, clique em <DNT>**Performance Risks**</DNT>.

### Acesso no nível da conta [#access-account]

No nível da conta, <DNT>Performance Risks inbox</DNT> está disponível em duas visualizações: um dashboard para toda a conta e uma lista de grupos de risco de desempenho com escopo para um workload ou entidade que for escolhido.

**Para acessar <DNT>Performance Risks inbox</DNT> de uma conta:**

1. Vá para <DNT>[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox</DNT>.
2. No painel de navegação da entidade, na seção <DNT>**Performance Risks**</DNT>, clique em <DNT>**Performance Overview**</DNT> para o dashboard de toda a conta (consulte [Visualizar a visão geral de desempenho](#overview)) ou em <DNT>**Risk Groups**</DNT> para uma lista com escopo.
3. Em <DNT>**Risk Groups**</DNT>, use o seletor de escopo para escolher <DNT>**Workload**</DNT> ou <DNT>**Entities**</DNT>, depois selecione o [workload](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview) ou a entidade específica que deseja revisar, ou use a caixa de pesquisa para buscar por nome ou descrição.
4. Opcionalmente, adicione mais filtros, como por <DNT>**Performance risk group metadata state**</DNT> (por exemplo, <DNT>Unresolved</DNT>), e use <DNT>**Sort by**</DNT> para alterar a ordem dos resultados.

## Visualizar e analisar riscos de desempenho [#view-analyze]

Ao acessar <DNT>Performance Risks inbox</DNT>, você pode visualizar os problemas detectados de duas maneiras: a visualização <DNT>**Triage**</DNT> e a visualização <DNT>**Group performance risks**</DNT>. Ambas as visualizações exibem os mesmos dados subjacentes, mas oferecem maneiras diferentes de analisá-los.

### Triagem [#triage]

A visualização <DNT>**Triage**</DNT> processa e agrupa riscos de desempenho semelhantes automaticamente. Consultas semelhantes são computadas, armazenadas e mescladas em um único grupo de risco de desempenho. Por exemplo, várias consultas que compartilham o mesmo padrão — como variações de uma cláusula `IN` — são agrupadas em uma entrada em vez de aparecerem como itens separados. Isso facilita identificar e priorizar os problemas mais impactantes sem analisar cada ocorrência individualmente.

Utilize a visualização <DNT>**Triage**</DNT> quando desejar um resumo pré-agrupado de problemas de desempenho para identificar padrões em todo o seu aplicativo.

<img title="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." alt="Screenshot of the Triage view in Performance Risks inbox showing pre-grouped performance issues." src="/images/performancerisks_triage.webp" />

### Riscos de desempenho do grupo [#group]

A visualização <DNT>**Group performance risks**</DNT> exibe os dados brutos de risco de desempenho sem agrupamentos pré-computados. As representações normais de consulta (como espaços reservados de vírgula e ponto de interrogação) são mostradas, e é possível filtrar e agrupar os dados com base em diferentes atributos, como:

* O usuário afetado pelo risco de desempenho
* O serviço que gera as chamadas
* A API que aciona as consultas

Use a visualização <DNT>**Group performance risks**</DNT> quando precisar analisar riscos de desempenho com base em atributos específicos que são relevantes para sua investigação.

<img title="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." alt="Screenshot of the Group performance risks view in Performance Risks inbox showing raw performance risk data." src="/images/performancerisks_grpperrisk.webp" />

## Obter recomendações [#recommendations]

A partir da visualização <DNT>**Triage**</DNT>, é possível gerar recomendações baseadas em IA para um risco de desempenho específico em vez de investigar as suas ocorrências manualmente.

**Para obter recomendações para um risco de desempenho:**

1. A partir da visualização <DNT>**Triage**</DNT>, abra um risco de desempenho que tenha várias ocorrências.
2. Clique em <DNT>**Generate insights**</DNT>.

<DNT>Performance Risks inbox</DNT> analisa as ocorrências desse risco de desempenho e retorna uma hipótese sobre a causa raiz, juntamente com as próximas etapas recomendadas para resolvê-lo. As recomendações exatas variam dependendo do risco de desempenho detectado.

<img title="Sample performance risk recommendations." alt="Sample performance risk recommendations." src="/images/PRinsights.webp" />

<Callout variant="important">
  O New Relic habilita recursos de IA por padrão para todas as contas. Caso esta opção não seja exibida, é possível que ela não esteja habilitada na sua conta. Entre em contato com o administrador da organização para solicitar acesso.
</Callout>

Se uma recomendação sugerir o ajuste de um limite, consulte [Definir os Limites](#set-thresholds).

## Defina os limites [#set-thresholds]

<DNT>Performance Risks inbox</DNT> usa limites configuráveis para detectar automaticamente anomalias de desempenho. É possível atualizar esses limites tanto no nível da conta quanto da entidade — incluindo para [workloads](/docs/new-relic-solutions/new-relic-one/workloads/workloads-overview) — para garantir que os critérios de detecção estejam alinhados com as necessidades e prioridades específicas de monitoramento de desempenho. Esses limites determinam o que constitui um risco de desempenho e ajudam a garantir que <DNT>Performance Risks inbox</DNT> alerte sobre os problemas de desempenho mais relevantes e acionáveis nos aplicativos.

Você pode definir os limites de Riscos de desempenho em nível de conta ou entidade:

* [Limites no nível da conta](#account-thresholds)
* [Limites de nível de entidade](#entity-thresholds)

### Definir os limites no nível da conta [#account-thresholds]

Definir limites no nível da conta permite estabelecer critérios padrão de detecção de risco de desempenho que se aplicam a todas as entidades da conta. Isso é útil para manter padrões consistentes de monitoramento e garantir que todos os aplicativos sejam avaliados com base nos mesmos benchmarks de desempenho.

**Para definir os limites no nível da conta:**

<CollapserGroup>
  <Collapser id="new-account-thresholds" title="Novos limites no nível da conta">
    1. Vá para <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox &gt; Performance Thresholds**.</DNT>.
    2. Na guia **Accounts**, clique em <DNT>**+ New**</DNT>.
    3. No dropdown <DNT>**Account**</DNT>, selecione a conta para a qual você deseja criar um novo limite.
    4. Defina os limites necessários para cada analisador.
    5. Clique em <DNT>**Submit**</DNT> para salvar.
  </Collapser>

  <Collapser id="edit-account-thresholds" title="Editar limites existentes no nível da conta">
    1. Vá para <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Errors Inbox &gt; Performance Thresholds**.</DNT>.
    2. Na guia **Accounts**, clique no botão <DNT>**Edit**</DNT> ao lado da conta que você deseja atualizar.
    3. Defina os limites necessários para cada analisador.
    4. Clique em <DNT>**Submit**</DNT> para salvar.

    <Callout variant="tip">
      Ao modificar os limites, o New Relic exibe o nome de usuário para rastrear quem fez as alterações.
    </Callout>
  </Collapser>
</CollapserGroup>

### Defina os limites no nível da entidade [#entity-thresholds]

Definir limites no nível da entidade permite personalizar os critérios de detecção de risco de desempenho para aplicativos ou serviços específicos que possam ter características ou requisitos de desempenho exclusivos. Isso é particularmente útil para adaptar o monitoramento a diferentes tipos de aplicativos, ambientes ou prioridades de negócios.

**Para definir os limites no nível da entidade:**

Você pode definir os limites para uma entidade específica de uma das seguintes maneiras:

<CollapserGroup>
  <Collapser id="entity-triage" title="Da página Riscos de Desempenho">
    1. Vá para <DNT>**[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; APM &amp; Services**.</DNT>.
    2. Selecione a entidade necessária.
    3. No painel de navegação da entidade, clique em <DNT>**Performance Risks**</DNT> na seção <DNT>**Triage**</DNT>.
    4. Clique em <DNT>**Adjust performance thresholds**</DNT> no canto superior direito.
    5. Defina os limites necessários para cada analisador.
    6. Clique em <DNT>**Submit**</DNT> para salvar.

    <Callout variant="tip">
      Ao modificar os limites, o New Relic exibe o nome de usuário para rastrear quem fez as alterações.
    </Callout>
  </Collapser>

  <Collapser id="entity-page" title="Da página Limites de Desempenho">

    2. Na guia <DNT>**Entities**</DNT>:
    3. Na dropdown <DNT>**Account**</DNT>, selecione a conta da sua entidade.
    4. Na dropdown <DNT>**Entity**</DNT>, selecione a entidade que você deseja atualizar.
    5. Defina os limites necessários para cada analisador.
    6. Clique em <DNT>**Submit**</DNT> para salvar.

    <Callout variant="tip">
      Ao modificar os limites, o New Relic exibe o nome de usuário para rastrear quem fez as alterações.

  </Collapser>
</CollapserGroup>

### Visualizar linhas de limite nos gráficos [#threshold-guidelines]

Os gráficos de risco de desempenho exibem linhas de referência para ajudar a interpretar se um valor está dentro de um intervalo esperado:

* **Diretrizes mínimas e máximas**: calculadas automaticamente a partir dos dados históricos coletados para esse gráfico, mostrando o intervalo típico de valores ao longo do tempo.
* **Limite atual**: reflete o limite que está ativo no momento para esse analisador, com base nas configurações de limite no nível da conta ou no nível da entidade. Se ambos estiverem definidos, o limite no nível da entidade terá precedência.

Estas linhas podem ser utilizadas para verificar o quão próxima uma métrica está do seu limite configurado, sem precisar abrir as configurações de limite.

## Use a ferramenta de caixa de entrada de riscos de desempenho no servidor MCP do New Relic. [#using]

Também é possível acessar a ferramenta <DNT>Performance Risks inbox</DNT> ([`list_entity_performance_risk_groups`](/docs/agentic-ai/mcp/tool-reference/#performance)) no [servidor MCP da New Relic](/docs/agentic-ai/mcp/overview/). Esta ferramenta lista todos os riscos de desempenho detectados para uma determinada entidade, juntamente com seus detalhes, como tipo de risco, gravidade e contagem de ocorrências. É possível usar esta ferramenta para recuperar dados de risco de desempenho de forma programática.
