### Novo recurso

***Mais flexibilidade para implantação de contêiner***

* O daemon e o aplicativo instrumentado não precisam mais residir no mesmo host e agora podem se comunicar por meio de um soquete TCP IPv4 ou IPv6. Para o aplicativo instrumentado, isso pode ser configurado por meio do argumento `daemon_socket` da função `newrelic_init`. Para o daemon, isso pode ser configurado por meio da opção de linha de comando `--address`.
* Ao encerrar o daemon por meio do sinal `SIGTERM` (e/ou do sinal `SIGINT` se iniciado com o sinalizador `-f`, `--foreground`), o daemon agora enviará todos os dados em buffer para a New Relic antes de sair.
* O daemon introduziu uma nova configuração `--watchdog-foreground`. Isso mantém o processo watchdog do daemon em primeiro plano, enquanto a configuração `--foreground` mantém o processo worker do daemon em primeiro plano. A nova configuração possibilita o uso do daemon de forma bloqueadora, sem perder a estabilidade adicional fornecida pelo processo watchdog.
* O C SDK agora oferece `newrelic_set_transaction_name` com o qual os usuários podem alterar o nome de uma transação já iniciada.

### Correções de bugs

* O daemon agora lida de forma síncrona com caminhos de código críticos relacionados à coleta e à mesclagem de dados de transação. Isso evita falhas causadas por condições de corrida.

### Avisos de Atualização

* O daemon introduziu uma nova configuração `--address` que serve como um alias para `--port`. Os clientes podem usar qualquer um deles para especificar a localização do daemon. Se ambos os valores estiverem definidos, `--address` terá precedência.

* Ao iniciar o daemon, ele agora aguardará até três segundos para que a porta de escuta esteja pronta para receber conexões antes de bifurcar para o segundo plano. Isso geralmente ocorre em (muito) menos de um segundo, e a maioria dos usuários com esta configuração não notará diferença na prática.

  O tempo que o daemon aguardará pode ser controlado definindo a configuração `--wait-for-port` com uma duração. Essa duração pode ser 0 para evitar qualquer bloqueio. Se a opção for omitida, o valor padrão será `3s`.

  Os daemons iniciados no modo de primeiro plano (com a flag `--foreground`) não são afetados e se comportarão como antes.
