A API do nosso System for Cross-domain Identity Management (SCIM) agora oferece suporte ao gerenciamento do [tipo de usuário](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type) dos usuários. Isso permite que os clientes Enterprise com usuários em nosso modelo de usuário mais recente gerenciem o tipo de usuário por meio de seu provedor de identidade (IdP) ou de qualquer integração personalizada que ofereça suporte ao SCIM. Isso é particularmente útil para provisionar usuários como básicos ou completos (em vez de sempre provisionar usuários como completos), além de realizar upgrades e downgrades automaticamente dentro da [política de faturamento](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/new-relic-one-pricing-billing/#user-count) da New Relic de dois downgrades por usuário a cada doze meses consecutivos.

O lançamento inclui [um tutorial do SCIM](/docs/accounts/accounts/automated-user-management/tutorial-manage-users-groups-scim) e a capacidade de os administradores adicionarem uma mensagem personalizada e/ou URL à página de autoatualização que comunica o processo de solicitação de atualização específico dos clientes para clientes que gerenciam o tipo de usuário por meio da API.

Temos instruções para habilitar isso com a nossa [integração Okta](/docs/accounts/accounts/automated-user-management/okta-scimsso-application-configuration/) pré-criada. Atualmente, não temos instruções passo a passo para as nossas integrações do OneLogin ou do Azure AD. Caso utilize um desses, será necessário configurar o seu provedor de identidade para enviar um novo atributo, [`nrUserType`](/docs/accounts/accounts/automated-user-management/scim-support-automated-user-management/#user-type).
