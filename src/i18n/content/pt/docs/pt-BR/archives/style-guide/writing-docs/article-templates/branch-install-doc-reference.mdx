Esta é uma referência para os componentes que formam o nosso componente de instalação ramificada.

Para começar com a instalação ramificada, consulte [Começar com a instalação ramificada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc).

Os documentos de instalação ramificada são controlados por um arquivo YAML de configuração que mapeia as relações entre as diferentes opções. O YAML descreve quando e como as partes do conteúdo (localizadas em .mdx arquivos) preenchem o documento. À medida que o usuário faz seleções de opções, o YAML alterna esses trechos.

## Componentes [#new-components]

Para ver o componente de instalação ramificada em ação, consulte [nossas implementações de instalação ramificada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#uses). Os principais componentes são:

* Caixas de seleção de opções (às vezes chamadas de &quot;tile dropdown&quot;) onde as escolhas que um usuário faz determinam qual conteúdo é exibido
* Etapas numeradas
* Opção de arquivo de configuração incorporado no qual os usuários podem inserir valores
* Formulário de feedback de instalação (`<InstallFeedback />`)

## Como funciona [#how]

Os documentos de instalação residem no diretório `install`. Há um único arquivo `.yaml` que define como e quando um conteúdo específico é inserido e retirado do documento. As partes específicas de conteúdo são representadas como arquivos `.mdx`.

## Visão geral do diretório [#install-directory]

O conteúdo do framework de instalação fica em `src/install`.

Para criar um novo documento de instalação, adicione um diretório a `install`.

A estrutura de diretórios precisa ser assim:

```
install
|--assets (used for install images)
|--config (used for the install yaml files)
   |--agent-config (used for the agent config yml files)
|--specific-install (used for a specific install doc)
   |--sub-directory1 (used for .mdx files that will be swapped in)
   |--sub-directory2 (used for .mdx files that will be swapped in)
   |--sub-directoryx (you can have as many sub-directories as you need)
```

Ao iniciar um novo documento de ramificação, é necessário criar um diretório pai no diretório `install`. É neste local que ficam todos os arquivos do documento de ramificação.

## O arquivo YAML de ramificação [#yaml-overview]

O arquivo YAML de documento de ramificação é uma maneira altamente personalizável de gerar uma ampla variedade de conteúdo interativo e personalizado. Por ser um arquivo YAML, é extremamente importante prestar atenção aos recuos e garantir que cada parte do arquivo YAML esteja correta.

Quando o senhor trocar o conteúdo MDX no seu arquivo YAML, o arquivo MDX específico precisará ser local para o seu diretório de documentos de instalação (por exemplo, Java). Embora possa ser tentador vincular a conteúdo em qualquer lugar no site de documentação para fins de reutilização, isso fará com que o seu documento quebre.

### Verificar script YAML [#verify-yaml]

Dado o quão fácil é quebrar qualquer arquivo YAML, a prestativa equipe de engenharia criou um script útil para verificar problemas comuns que podem ser vistos no arquivo YAML.

No seu terminal, vá para o diretório do repositório `docs-website` e execute este comando:

`yarn verify-install-page YOUR_BRANCHING_DOC_DIRECTORY_NAME`

Por exemplo, para o documento de ramificação do Java, deve-se usar:

`yarn verify-install-page java`

porque o documento de ramificação do Java está localizado em `src/install/java`.

Este script verifica o seguinte no arquivo YAML:

* O valor `agentName` corresponde ao nome da pasta em `src/install/YOUR_DIRECTORY_NAME`.
* Os campos `agentName`, `agentType`, `title` e `appInfo` não estão em branco.
* O campo `appInfo` `placeholder` não está em branco.
* Os caminhos de arquivo de etapa e substituições são caminhos válidos e apontam para arquivos reais.
* Todos os `overrides` têm um valor `selectedOptions`.
* Problemas gerais de sintaxe YAML, como aspas extras ou um recuo inválido.

## Detalhes do nome do campo YAML [#yaml-fields]

* agentName: o nome do diretório onde tudo reside, também vinculado ao URL (/install/java)

* title: o nome do documento (o mesmo que outros .mdx arquivos).

* introFilePath: o arquivo que contém o conteúdo de introdução do documento.

* agentConfigFilePath: (opcional, se usar um arquivo de configuração) onde o arquivo de configuração do agente reside. Se não funcionar, pergunte à engenharia se é um tipo de arquivo compatível.

* appInfo: a seção onde as opções são definidas. Componentes:

  * optionType: o nome dado a um conjunto de opções. Esse nome será referenciado na seção `steps` para ditar quais opções estão sendo referenciadas, e também no .mdx associado arquivo.
  * rótulo: nome para o dropdown, que é exibido acima dessa caixa de opção. É possível deixar em branco, com aspas vazias, caso não seja desejado.
  * Espaço reservado: mais texto que pode ser colocado acima da caixa de opções. É possível deixar em branco, com aspas vazias, caso não seja desejado.

* opções

  * value: a variável para o nome do bloco. Isso é referenciado na seção `steps` ao fornecer os valores que controlam quais arquivos são exibidos.
  * displayName: o rótulo exibido do bloco de opções.
  * logo: opcional. Um caminho para uma imagem usada para o bloco de opções.
  * icon: opcional. Deve-se utilizar isto se desejar usar um ícone em vez de uma imagem (icon name=&quot;fe-server&quot;)
  * recommendedGuided: booleano. Isso determina se o conteúdo no arquivo .mdx do tipo de componente `appInfoConfigOption` será exibido. Isso é usado principalmente para o conteúdo de instalação guiada, mas pode ser usado para qualquer conteúdo que se deseja acionar para exibição nesse arquivo. Leia mais sobre [as opções de instalação guiada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#guided-install-decision).

* steps: esta é a seção que determina qual conteúdo é exibido. A ordem em que estão listados determina a ordem de todo o conteúdo.

  * filePath: este é o caminho para o .mdx arquivo (ou caminho teórico, dependendo se será acionado).

  * overrides: existem três tipos de substituição:

    * **Substituir**. Se houver outro `filePath` listado em uma substituição, isso significa: substituir o caminho do arquivo principal por este caminho de arquivo, dependendo das opções selecionadas.
    * **Exibir se...** Isso usa o `isConditionalStep`, que aceita um valor booleano. Isso não é uma &quot;substituição&quot;, mas significa: exibir este arquivo dependendo das opções selecionadas. Para obter informações sobre o uso de uma lógica AND/OR mais complexa, consulte o [Exemplo de yaml do .NET](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example).
    * **Skip.** Isso utiliza `skip`, que recebe um valor booleano. Basicamente, isso indica: exiba este arquivo, mas pule-o se estas opções estiverem selecionadas.

  * selectedOptions: a seção onde são colocadas as seleções de opções relevantes. Os componentes incluem:

    * optionType: isto se conecta ao `optionType` usado na seção `appInfo`.
    * opções
      * valor: conecta-se ao `value` usado em `optionType`.

## Ramificação de arquivos MDX [#mdx-overview]

Ao trabalhar com este framework de instalação, há arquivos MDX específicos dos quais se deve estar ciente. Os diferentes tipos de conteúdo MDX são especificados por meio do campo de frontmatter `componentType`.

Os diferentes .mdx tipos de componentes são:

* `intro`

  * Referenciado no YAML por `introFilePath`.
  * Este é o conteúdo de introdução na parte superior do documento.

* `default`

  * Um arquivo MDX de formato livre.
  * Isto deve ser utilizado para a maior parte do conteúdo.

* `appInfoConfigOption`
  * Isso é utilizado para referenciar o conteúdo da opção.

* `agentConfig`
  * Isto é usado para o arquivo de configuração de um agente.

Para ver exemplos de arquivos MDX em uso, consulte nosso [Exemplo de arquivo yaml](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc#complex-yaml-example).

### O arquivo MDX agentConfig [#sample-agentconfig]

O arquivo MDX `agentConfig` opcional aponta para o arquivo de configuração apropriado no diretório de instalação e controla quais linhas no arquivo de configuração são editáveis.

```md
---
componentType: agentConfig
headingText: Set your app name and license key
descriptionText: Set your app name and license key. Then download your custom config file.
fileName: newrelic.yml
inputOptions:
  - label: 'Name your app'
    name: appName
    codeLine: 21
    defaultValue: 'My app name'
    toolTip: 'New Relic connects metrics to individual applications using your license key and the primary application name.' 
  - label: 'Enter your license key'
    name: licenseKey
    codeLine: 28
    defaultValue: '12345'
---
```

Ao usar o arquivo de configuração, recomenda-se:

* alterar as permissões padrão de `newrelic.yml` para leitura/gravação apenas para o proprietário do processo do servidor do aplicativo.
* certifique-se de que `newrelic.yml` faça parte da rotina de backup.
* utilizar a [New Relic Diagnostics CLI](https://docs.newrelic.com/docs/new-relic-solutions/solve-common-issues/diagnostics-cli-nrdiag/run-diagnostics-cli-nrdiag/) para validar as configurações, seja antes ou depois de implantar.

### Campos de frontmatter MDX [#mdx-frontmatter]

* `componentType`: (utilize uma destas quatro opções) se ausente, o padrão é o tipo &quot;default&quot;

  * `default`: arquivo mdx gratuito
  * `appInfoConfigOption`: isso é para dropdown, deve-se usar sempre que desejar dropdown
  * `agentConfig`: isso é para o arquivo yaml
  * `appInfoConfig`: esta é a etapa em que o conteúdo é exibido (inclui o conteúdo de `recommendedGuided`)

* `descriptionText`: o primeiro texto no conteúdo da etapa (texto cinza menor que atua como um segundo cabeçalho)

* `optionType`: adicionado apenas para `appInfoConfigOption`
