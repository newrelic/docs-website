Esta página do guia de estilo descreve o frontmatter padrão para documentos e também descreve os vários tipos de conteúdo que mantemos no site.

## Frontmatter e metadados da documentação [#meta-fields]

A parte superior de cada documentação começa com um conjunto de metadados. A seguir, há mais informações sobre este conteúdo de metadados:

<table>
  <thead>
    <tr>
      <th width={150}>
        **Campo de conteúdo meta**
      </th>

      <th>
        **Descrição**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        `title`
      </td>

      <td>
        O título principal do documento, que aparecerá na parte superior do documento como um cabeçalho HTML `<h1>`, no título da página do navegador e nos campos meta do mecanismo de pesquisa.

        Sempre que possível, forneça um título orientado à ação ou à tarefa; por exemplo, &quot;Página AJAX: identificar chamadas demoradas.&quot; Em geral, use o estilo de frase. Coloque em maiúscula apenas a primeira palavra. Não coloque em maiúscula nenhuma outra palavra no título, a menos que seja um substantivo próprio, como um nome de produto específico, ou que siga dois-pontos `:`.

        Para obter ideias sobre como escolher um título, consultar os títulos de documentações semelhantes.

        O título utilizado na barra lateral (painel de navegação esquerdo) é definido no [arquivo de navegação](/docs/style-guide/processes-procedures/update-left-navigation-pane).
      </td>
    </tr>

    <tr>
      <td>
        `tags`
      </td>

      <td>
        Descontinuado. Historicamente, as tags eram usadas para ajudar os mecanismos de pesquisa e a IA a encontrar o conteúdo certo. Os mecanismos modernos são sofisticados o suficiente para inferir esse contexto sem tags, portanto, essa tag não é mais necessária.
      </td>
    </tr>

    <tr>
      <td>
        `translate`
      </td>

      <td>
        Indica para quais idiomas esta página é traduzida por humanos. Este campo não controla a tradução automática; de modo geral, todas as documentações &quot;padrão&quot; no site são traduzidas automaticamente para todos os idiomas. Para mais informações, consulte [Tradução de documentação](/docs/style-guide/writing-docs/docs-translation/).
      </td>
    </tr>

    <tr>
      <td>
        `metaDescription`
      </td>

      <td>
        Uma breve descrição do documento. Os mecanismos de pesquisa dependem deste campo para entender sobre o que é um documento, e frequentemente exibirão a meta descrição diretamente nos resultados da pesquisa. Deve ter menos de 160 caracteres. Para obter mais informações sobre por que as meta descrições são importantes para a pesquisa, consulte [Controlar Seus Trechos nos Resultados da Pesquisa](https://developers.google.com/search/docs/appearance/snippet) na documentação do Google.
      </td>
    </tr>

    <tr>
      <td>
        `redirects`
      </td>

      <td>
        Redireciona **para** este documento a partir de URLs antigas. Um redirecionamento por linha. Deve-se usar um caminho relativo e não incluir uma barra final `/`.
      </td>
    </tr>

    <tr>
      <td>
        `freshnessValidatedDate`
      </td>

      <td>
        A última vez que um redator fez atualizações significativas neste documento e verificou sua precisão.

        O padrão é `never`. Ao fazer uma atualização significativa em um documento, adicione a data de hoje neste formato: `YYYY-MM-DD`.
      </td>
    </tr>
  </tbody>
</table>

## Modelos de página

O site de documentação não possui modelos de página rigorosos — como há uma abordagem de &quot;docs as code&quot;, os redatores podem usar uma variedade de componentes para estruturar a documentação da maneira que considerarem melhor. No entanto, existem vários tipos exclusivos de conteúdo que se comportam de maneira diferente da documentação padrão de `.mdx`.

<table>
  <thead>
    <tr>
      <th width={150}>
        **Tipo de conteúdo**
      </th>

      <th>
        **Descrição**
      </th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>
        Documentos &quot;padrão&quot;
      </td>

      <td>
        Um arquivo `.mdx` padrão, localizado no subdiretório `/src/content/docs/`. Esse tipo de conteúdo é usado para a maioria do conteúdo do site.
      </td>
    </tr>

    <tr>
      <td>
        Definição de atributo
      </td>

      <td>
        Este formato é para definir atributos e tipos de evento. Essas definições residem em seu próprio repositório do GitHub Enterprise, depois são publicadas no site de documentação e no NerdGraph por meio do serviço de dicionário de dados. Para saber mais, consulte [Trabalhar com o Tipo de Conteúdo de Definição de Atributo](/docs/style-guide/article-templates/attribute-definition-template).
      </td>
    </tr>

    <tr>
      <td>
        Documentação de instalação ramificada
      </td>

      <td>
        Este formato é para documentação de instalação interativa. A documentação de instalação ramificada consiste em vários componentes em arquivos `.mdx` individuais que residem juntos em um subdiretório, com a lógica que define quais partes mostrar e quando, definida em um arquivo `.yaml` separado. O conteúdo de instalação ramificada reside no subdiretório `/src/install/`.

        Para saber mais, consulte [Começar a usar o componente de instalação ramificada](/docs/style-guide/writing-docs/article-templates/intro-branch-install-doc/).
      </td>
    </tr>

    <tr>
      <td>
        Notas de versão
      </td>

      <td>
        Este formato inclui campos exclusivos de frontmatter. As notas de versão ficam em `/src/content/docs/release-notes/` e geralmente são criadas pelas equipes de produto, e não por redatores.

        Os usuários dependem das notas de versão para acompanhar as alterações menores no produto, especialmente para softwares para download, como os agentes. Para obter mais informações, consulte [Criar notas de versão](/docs/style-guide/article-templates/create-release-notes/).
      </td>
    </tr>

    <tr>
      <td>
        Publicações de novidades
      </td>

      <td>
        Este formato inclui campos exclusivos de frontmatter. As publicações do What&apos;s New são criadas pelo PMM para anúncios maiores. Ao contrário da maioria do conteúdo, eles residem em `/src/content/whats-new/` em vez de no subdiretório `/docs/`.

        Eles estão disponíveis no site de documentação, mas também são visíveis na interface da New Relic. Para obter mais informações, consulte as [diretrizes de estilo do What&apos;s New](/docs/style-guide/article-templates/whats-new-style-guidelines/).
      </td>
    </tr>
  </tbody>
</table>
