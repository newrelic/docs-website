Este documento deve ser utilizado para aprender a revisar e editar documentos para os colegas redatores no GitHub. Recomenda-se consultar o [documento de fluxo de trabalho do Tech Writer](/docs/style-guide/writer-workflow/tech-writer-workflow/) para obter informações sobre como configurar o ambiente local. Para solucionar problemas do GitHub, recomenda-se consultar [o nosso guia](/docs/style-guide/writing-docs/writer-workflow/github-troubleshooting/).

## Quando obter uma revisão [#when-to-get-review]

Quase todos os PRs para o site de documentação de um redator técnico devem receber uma revisão de um colega redator técnico. Realizamos revisões para:

* Identifique imprecisões
* Cumprir nosso guia de estilo
* Melhore nossa escrita, particularmente a voz e o tom
* Obter uma perspectiva diferente (por exemplo, aprender sobre algo relacionado ao trabalho que era desconhecido)

As revisões são importantes, e o padrão deve ser sempre obter uma revisão! Com isso em mente, caso haja certeza de que o pull request tem um escopo pequeno e dificilmente se beneficiará das considerações acima, é possível fazer o merge do pull request sem revisão. Independentemente de obter uma revisão do pull request, é responsabilidade do redator garantir que o pull request seja compilado corretamente e passe em todas as verificações técnicas.

Alguns exemplos de itens que podem ser mesclados sem revisão:

* Correção de links quebrados
* Alterações em apenas algumas palavras ou linhas de um documento
* Uma simples busca e substituição de uma palavra/frase que se tenha certeza de que é simples e não problemática
* Uma edição particularmente urgente (nesse caso, é possível decidir obter uma revisão mais tarde)
* Alterações feitas em resposta a uma revisão de PR que não necessitam de uma revisão adicional.

Em caso de dúvida sobre a necessidade de obter uma revisão do PR, deve-se solicitar uma.

## Fluxo de trabalho de edição por pares no GitHub [#peer-edit]

Ao editar um documento com um colega ou ser designado para um PR como revisor, há algumas opções de como e onde realizar o trabalho. A abordagem mais simplificada e de código aberto é fazer a edição usando as opções do GitHub, em vez de copiar o arquivo para o Google Docs e editá-lo lá.

### Revisão de desenvolvimento [#edit-pass]

Para casos em que houver dúvidas e sugestões em vez de edições diretas de texto, siga estas etapas.

1. É necessário abrir o PR atribuído para revisão.

2. Na guia Arquivos alterados, é possível:

   * Clicar em Revisar alterações e, em seguida, selecionar uma das seguintes opções:

     * **Comment** - utilize caso haja um comentário que não exija acompanhamento.
     * **Aprovar** - deve ser utilizado caso se deseje apenas aprovar o PR. É possível solicitar alterações na área Deixar um comentário e selecionar Aprovar caso se deseje permitir que o redator faça as edições e mescle o arquivo sem uma revisão de acompanhamento posterior.
     * **Request changes** - use para os momentos em que for necessário garantir que as alterações solicitadas sejam incluídas. Uma notificação será enviada com quaisquer atualizações que o redator fizer.

   * OU, é possível começar a fazer comentários em linhas ou seções do documento. Para fazer isso, deve-se clicar no ícone de adicionar comentário, e deixar uma edição ou comentário para essa linha específica na página. Com essa opção, é possível escolher entre adicionar um único comentário ou iniciar uma revisão. Se houver a intenção de fazer comentários ao longo de um documento, deve-se escolher **Start a review** para que todos os comentários sejam agrupados em um único commit.

3. Clique em **Finish your review** para concluir a revisão. Isso aciona uma notificação para o redator, alertando-o de que foram feitas sugestões.

### Fluxo de trabalho de edição de texto [#edit-copy]

Se houver edições de texto para um arquivo em vez de comentários e sugestões, as alterações no arquivo poderão ser feitas de maneiras diferentes. Aqui estão duas opções principais:

1. Edite usando o navegador do GitHub: na guia **Files changed**, na janela de diff, clique no botão de edição (três pontos). Ao terminar as edições, adicione um comentário na parte inferior do arquivo e escolha **fazer o commit das alterações diretamente** ou **criar um branch e iniciar um pull request**. Escolha criar um branch e iniciar um pull request se esperar que um redator revise o diff e aceite ou revise as edições.
2. Editar localmente: faça o checkout da branch que contém o arquivo a ser editado. No GitHub Desktop, clique na seta para baixo de Current branch e selecione a branch. Em seguida, faça as edições na unidade local, salve e faça o commit das alterações na branch.
   * Note que esta abordagem adiciona as edições ao pull request aberto. Agora é possível ver as alterações adicionadas ao arquivo na aba **Arquivos alterados** no PR.

Estas são apenas algumas das muitas opções de edição. É possível encontrar a maneira preferida, assim como com qualquer outra ferramenta.
