Uma captura de tela ou imagem bem escolhida pode melhorar muito a legibilidade e a clareza de um documento. Muitas imagens ou uma imagem difícil de analisar podem realmente atrasar o processo.

* Para adicionar uma imagem ao site de documentação sem fazer parte da equipe de documentação, é necessário criar uma [issue no GitHub](https://github.com/newrelic/docs-website/issues/new/choose).
* Caso seja um funcionário da New Relic, entre em contato com `@hero` no canal de documentação do Slack.

## Adicione uma imagem [#add]

Queremos garantir que dados confidenciais não apareçam em capturas de tela da interface. Por isso, recomendamos fornecer um link permanente para uma conta de teste. Não fazer uma captura de tela da conta do New Relic.

Aqui estão algumas coisas a serem lembradas ao criar uma imagem:

* Certifique-se de que a imagem forneça informações úteis rapidamente.
* Certifique-se de seguir as [convenções de nomenclatura e de declaração de importação](#naming-and-imports).
* Inclua uma legenda com contexto útil para a imagem.
* Para legendas de capturas de tela, inclua o caminho em negrito.
* Para legendas de vídeo, inclua o tempo de execução aproximado.
* Não vincule a um arquivo de imagem externo. Todas as imagens usadas na documentação devem ser armazenadas em [nosso repositório do GitHub](https://github.com/newrelic/docs-website).
* O nosso padrão é o modo escuro. Se um especialista no assunto fornecer capturas de tela no modo claro, por gentileza, solicitar novas no modo escuro. Se não for possível obter imagens no modo escuro, então qualquer captura de tela é melhor do que nenhuma captura de tela.

Para adicionar ou editar uma imagem:

1. Coloque a imagem na raiz de `static/images/`.

2. Deve-se continuar com os seguintes procedimentos para adicionar ou editar imagens:

## Escreva legendas de imagens [#labeling]

Legendas descritivas ajudam o leitor a saber por que a imagem é importante. Se for uma captura de tela, é útil incluir o caminho em negrito, além de uma descrição. Por exemplo:

```html
<img
  title="Screenshot showing the Overview dashboard"
  alt="Screenshot showing the Overview dashboard"
  src="/images/kubernetes_screenshot-full_cluster-dashboard-detail.webp"
/>

<figcaption>
  Go to <DNT>**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > Kubernetes**</DNT>. Select your cluster and click <DNT>**Overview Dashboard**</DNT> in the left navigation pane. It shows useful overview data about the status and performance of the cluster and its containerized workloads.
</figcaption>
```

Para obter mais ajuda com legendas e outros textos de apoio em torno de imagens, recomenda-se consultar [Diretrizes para Explicar Imagens](/docs/style-guide/writing-guidelines/screenshots-images#identify-images).

## Adicionar uma imagem inline (MDX) [#inline-images-mdx]

Para usar uma imagem embutida:

* Use a tag `img` no arquivo
* O atributo `src` contém o caminho da imagem: `src="/images/IMAGE_NAME.webp"`
* Deve-se adicionar uma classe de `inline` a `img`.
* Adicione qualquer altura/largura opcional na propriedade `style`.

Se a imagem embutida estiver sendo usada como um ícone, ela deve ser sempre descrita primeiro. Ao incorporar a imagem do ícone, a imagem deve ser seguida pela palavra `icon` no texto. Por exemplo:

```jsx
---
title: Abbreviated example of a file
---

Select your app's settings <img src="/images/example_icon_example-icon.webp" class="inline" style={{height: "30px", width: "30px"}} alt="Multiple app names indicator in New Relic" title="Multiple apps name indicator in New Relic" /> icon.
```

## Dimensionamento de imagem

Por padrão, todas as imagens MDX recebem uma altura máxima de 550px para evitar que imagens verticais pareçam muito grandes dentro do conteúdo.

Se houver uma imagem que precise ter mais de 550px de altura, é possível definir a classe `unbound` nos atributos `img`.

```html
<img
  class="unbound"
  title=""
  alt=""
  src=""
/>
```

**Nota:** algumas imagens estão usando um `width="n%;"` definido nos atributos `img`. Isso aplicará automaticamente a classe `unbound` e removerá a restrição de altura padrão da imagem, pois isso faz com que a imagem se estique e não seja redimensionada proporcionalmente.

## Ícones [#icons]

É possível escolher entre uma variedade de ícones para incluir nos documentos:

* Ícones Feather (com o prefixo `'fe-`).
* Ícones da New Relic (com o prefixo `nr-`).
* Logotipos de produtos de terceiros (com o prefixo `logo-`).

Para verificar se já existe o ícone necessário, acesse:

* [Feather.js para `docs-website` no GitHub](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104): estes são os ícones do Feather disponíveis no projeto `docs-website`, mas que não estão incluídos no tema Gatsby.
* [Tema Gatsby para `docs-website` no GitHub](https://github.com/newrelic/docs-website/tree/develop/src/%40newrelic/gatsby-theme-newrelic/icons): este é um subconjunto de ícones do Feather, da New Relic e de logotipos de produtos que estão disponíveis nos sites de desenvolvedores e de documentação.

É possível usar quaisquer ícones necessários no tema Gatsby ou Feather. Atualmente, essas localizações possuem grupos de ícones separados e que não se sobrepõem.

### Insira ícones como atributos de tag [#tag-attributes]

Se o ícone aparecer como um atributo dentro de outra tag, o prefixo `icon` deve ser adicionado, como neste exemplo:

```jsx
<LandingPageTileGrid>
  <LandingPageTile
    title="AWS Lambda"
    href="/docs/serverless-function-monitoring/aws-lambda-monitoring/get-started/monitoring-aws-lambda-serverless-monitoring"
    icon="logo-aws"
  >
</LandingPageTile>
```

### Inserir ícones inline [#inline-icons]

Se o ícone aparecer dentro de um texto corrido, use o componente `<Icon>`. Aqui estão alguns exemplos:

* Feather: `<Icon name="fe-database" />`
* New Relic: `<Icon name="nr-tdp" />`
* Logotipos: `<Icon name="logo-apple" />`

### Instalar novos ícones Feather [#feather-icons]

Se o ícone desejado não estiver no [tema Gatsby para `docs-website` no GitHub](https://github.com/newrelic/gatsby-theme-newrelic/tree/develop/packages/gatsby-theme-newrelic#available-icons) nem no [Feather.js para `docs-website` no GitHub](https://github.com/newrelic/docs-website/blob/develop/src/@newrelic/gatsby-theme-newrelic/icons/feather.js#L100-L104), é possível adicionar um novo ícone ao tema Gatsby. Também é possível solicitar aos desenvolvedores que adicionem o ícone desejado.

Aqui está um exemplo de como adicionar um ícone `database`:

1. Acesse [feathericons.com](https://feathericons.com/).
2. Faça o download do ícone feather `database` clicando no próprio ícone.
3. Após o download, abra o arquivo SVG no editor de texto.
4. Copie o &quot;interior&quot; do SVG, que é tudo o que está entre as tags `<svg>`. Por exemplo, se o SVG for `<svg><path m="1"></path></svg>`, copie apenas a parte `<path m="1"></path>`.
5. Abra a lista de ícones feather em `src/@newrelic/gatsby-theme-newrelic/icons/feather.js`.
6. Adicionar uma entrada para `database` e atribuir a ela o código da etapa anterior.
7. Se o ícone tiver vários caminhos, inclua o wrapper `<>` ao redor dele, como é visto em outros ícones.
8. Salve o arquivo `feather.js`.

O prefixo `fe-` é adicionado automaticamente. Uma vez que esse ícone seja adicionado, é possível usá-lo com o componente de ícone; por exemplo, `<Icon name="fe-database" />`.

## Lidando com conflitos de PR de refatoração de imagens

Aqui está uma visão rápida das alterações de contribuição que entraram em vigor após a nossa refatoração de imagens e como atualizar as alterações de arquivo em quaisquer PRs pendentes.

Deve-se obter a versão mais recente de `develop` e, em seguida, atualizar quaisquer arquivos relacionados a imagens nas alterações:

### Adicionando imagens ao repositório:

<SideBySide>
  <Side>
    **Convenção de imagem antiga:**

    as imagens costumavam estar em `./src/images`

    ```
    ├──src/
    │  └──content/
    │  │  └──docs/
    │  │    └── example-page.mdx
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>

  <Side>
    **Nova convenção de imagem:**

    as imagens agora estão em `./static/images`

    ```
    ├──src/
    │  └──content/
    │     └──docs/
    │        └── example-page.mdx
    ├──static/
    │  └──images/
    │     └── example-image.webp
    ```
  </Side>
</SideBySide>

### Usando a imagem em um arquivo MDX

<SideBySide>
  <Side>
    **Convenção de imagem antiga:**

    Anteriormente, tínhamos que importar nossos caminhos de imagem como uma variável e, em seguida, usar essa variável como a fonte `<img>`.

    ```jsx
    import exampleImage from 'images/example-image.webp'

    <img
      title="Image title."
      alt="Alternate text."
      src={exampleImage}
    />
    ```
  </Side>

  <Side>
    **Nova convenção de imagem:**

    Agora a fonte da imagem é simplesmente o caminho para a imagem em relação à pasta estática:

    ```html
    <img
      title="Image title."
      alt="Alternate text."
      src="/images/example-image.webp"
    />
    ```
  </Side>
</SideBySide>

### Usar a imagem em um arquivo MD

O uso de imagens em markdown é quase o mesmo de antes. O caminho utilizado foi ligeiramente alterado:

<SideBySide>
  <Side>
    **Convenção de imagem antiga:**

    `./images`

    ```md
    ![Image title.](./images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>

  <Side>
    **Nova convenção de imagem:**

    `/images`

    ```md
    ![Image title.](/images/kinesis_data_firehose.webp "Alternate text.")
    ```
  </Side>
</SideBySide>

### Compilações locais

Siga estas etapas para resolver erros e falhas de compilação ao executar as alterações localmente após atualizar a branch com a versão mais recente de `develop`:

1. atualize os arquivos de imagem e o código para a nova convenção, conforme mostrado acima
2. execute `nvm use` para certificar-se de estar na versão correta do Node
3. execute `yarn` para instalar os pacotes necessários
4. execute `yarn clean` para apagar quaisquer imagens em cache de compilações antigas
5. executar `yarn start`
