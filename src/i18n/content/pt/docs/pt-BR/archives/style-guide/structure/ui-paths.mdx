Explicar onde encontrar páginas e elementos da interface pode ser complicado. Quando bem feitas, as descrições de caminho podem facilitar a navegação em nossa interface para os leitores. Há diferentes opções para lidar com caminhos de interface menores e caminhos de interface maiores.

## Diretrizes para Escrever Bons Caminhos de Interface

O objetivo para os caminhos da interface é torná-los fáceis de entender e seguir, preferencialmente escritos de forma conversacional. Embora não haja preocupação com a consistência absoluta, deseja-se que os caminhos sigam padrões gerais para não introduzir ambiguidade desnecessária para o usuário que interage com a interface.

        Inicie a maioria dos caminhos da interface com `go to **[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities)**`.
      </td>

      <td>
        Quase qualquer caminho dentro da nossa interface principal deve começar com esta frase padrão. Recomenda-se evitar outras palavras introdutórias como `from` ou `login to`. E vale lembrar que os caminhos da interface estão sempre em **negrito**. Recomenda-se evitar a exibição de links que pulam vários nós de navegação na interface. Por exemplo, em vez disto:

        *[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; trace*

        Escreva isto:

        *[one.newrelic.com &gt; All capabilities](https://one.newrelic.com/all-capabilities) &gt; Traces*.
      </td>

      <td>
        Deve-se utilizar um formato conciso e coloquial.
      </td>

      <td>
        Um bom caminho de interface é curto, coloquial e inequívoco. Frequentemente, utiliza-se `>` entre os nós em um caminho para ajudar a manter a brevidade, mas quando a interface é confusa, também é possível usar palavras posicionais como `left navigation` ou `upper-right`.
      </td>
    </tr>

    <tr>
      <td>
        Evite redundância
      </td>

      <td>
        Se houver um documento ou uma seção de documento existente que explique como chegar a um elemento de interface, seção ou página específica, adicione um link para ele.

        Aqui está um exemplo que contém um link para um documento existente:

        No [menu do usuário](/docs/accounts/accounts-billing/general-account-settings/intro-account-settings), selecione **Configurações da conta** e, em seguida, selecione **Gerenciamento de plano**.

        Aqui está um que direciona para uma seção anterior:

        ...

        1. No [painel de detalhes](http://details-pane-empty-link) de um span \[link to doc section above], selecione **Atributos**.
        2. Deve-se procurar atributos relacionados à entidade, como *entityId* e *entity.name*.
      </td>
    </tr>

    <tr>
      <td>
        Orientar o leitor
      </td>

      <td>
        Se algo for difícil de localizar, é possível usar termos como `top of the screen` ou `left navigation`. Por exemplo:

        Na navegação superior, clique em **APM** e, em seguida, escolha o aplicativo.
      </td>
    </tr>

    <tr>
      <td>
        Use verbos naturais
      </td>

      <td>
        Use verbos naturais e acionáveis. Pense no usuário e na lógica da ação e, em seguida, leia as etapas em voz alta antes de decidir.

        * Exemplos: `click`, `select`, `choose`.
      </td>
    </tr>

    <tr>
      <td>
        Usar capturas de tela
      </td>

      <td>
        As capturas de tela podem ajudar a situar o leitor. Por exemplo, se a interface contiver um dashboard com várias opções, uma captura de tela pode orientar o leitor com um conjunto comum de procedimentos. Escreva o caminho de interface associado à captura de tela em um `<figcaption>`.
      </td>
    </tr>

    <tr>
      <td>
        Excluir instruções de login
      </td>

      <td>
        Presuma que nossos leitores estejam conectados. Em outras palavras, não inclua `log in to New Relic`.
      </td>
    </tr>

</table>

## Siga estes exemplos de caminhos de interface [#examples]

O comprimento do caminho deve influenciar a abordagem. Uma navegação simples de três etapas pode ser totalmente conversacional, enquanto um procedimento de várias etapas pode ser uma lista ordenada. E para algo oculto a mais de três passos de profundidade, considere usar a convenção `**[one.newrelic.com > All capabilities](https://one.newrelic.com/all-capabilities) > y > z**`.

Aqui estão alguns estilos de caminho na prática, completos com o estilo em negrito apropriado.

## Utilize o bom senso [#judgment]

Em caso de dúvida ao escrever um caminho de interface, deve-se usar o bom senso. A melhor maneira de formatar ou redigir um caminho de interface pode depender do comprimento e do contexto do caminho.
