Este documento explica os estilos obrigatórios e as frases recomendadas para a documentação relacionada a permissões e perfil do usuário.

## Nota sobre modelos de usuário

Este guia de estilo aplica-se principalmente à redação sobre usuários em nosso modelo de usuário mais recente, não em nosso modelo de usuário original. Embora ambos os modelos de usuário compartilhem certos termos (como **Admin**), este é um modelo de usuário totalmente diferente, com uma estrutura, fraseados recomendados e estilo totalmente diferentes. Para entender as diferenças do modelo de usuário, consulte a [Visão geral dos modelos de usuário](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models).

O modelo de usuário original será cada vez mais descontinuado, portanto, não deve ser necessário pensar muito sobre esse modelo de usuário ou atualizar esses documentos com muita frequência.

## Diretrizes para documentar permissões/funções de usuário [#user-language-philosophy]

Há dois fatores principais que afetam a capacidade de um usuário da New Relic acessar um recurso da New Relic:

* Tipo de usuário: restringimos quase inteiramente as informações sobre o tipo de usuário ao [documento de tipo de usuário](/docs/accounts/accounts-billing/new-relic-one-user-management/user-type).

* Funções e capacidades: restringimos quase inteiramente as informações sobre isso aos documentos dedicados de gerenciamento de usuários:

  * [Documentação original do modelo de usuário](/docs/accounts/original-accounts-billing/original-users-roles/users-roles-original-user-model)
  * [Documentação mais recente do modelo de usuário](/docs/accounts/accounts-billing/new-relic-one-user-management/introduction-managing-users)

Em outras palavras, **não são colocadas informações sobre o tipo de usuário e funções/capacidades na documentação relacionada aos recursos do produto**, com as seguintes exceções:

* Para o tipo de usuário: para a maioria dos recursos do produto, é óbvio para um usuário se algo está fora dos limites devido ao tipo de usuário (por exemplo, ao ver uma mensagem na interface sobre o tipo de usuário). Se não for óbvio que algo está fora dos limites devido ao tipo de usuário, é possível documentar isso na seção de requisitos da documentação do recurso. Por exemplo, não será imediatamente óbvio para um usuário do NerdGraph por que não é possível fazer determinados requests, portanto, essa é uma situação em que o tipo de usuário seria documentado na documentação principal do NerdGraph.
* Para funções e permissões: se houver um motivo específico para incluir o tipo de usuário ou funções/permissões na seção de requisitos de um documento de recurso, é possível incluí-lo. Por exemplo: se uma [permissão](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions) que controla o acesso a um recurso não for óbvia pelo nome das permissões (como [permissões de gerenciamento a nível de serviço](/docs/service-level-management/faqs-slm#permissions)), devemos documentá-la.
* Para permissões de gerenciamento de organização e usuário, documentamos as funções necessárias. Isso ocorre porque não há muitos deles e, também, porque as permissões que os regem não estão expostas na interface de funções e permissões e, portanto, são menos óbvias para os clientes.

## Considerações para documentar tanto o modelo de usuário original quanto o novo [#user-model-requirements]

Se for necessário incluir requisitos sobre funções ou permissões de modelos de usuário mais recentes, provavelmente também será necessário incluir detalhes sobre o modelo de usuário original (presumindo que esse recurso esteja disponível para esse público). Aqui está um exemplo de como fazer isso:

```md
Permissions requirements differ depending on your user model:

* For users on the [original user model](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models): the [**Data retention manager** role](/docs/accounts/original-accounts-billing/original-users-roles/users-roles-original-user-model/#roles).
* For users on [our newer user model](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-user-models): the [**Billing** administration setting](/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts#admin-settings).
```
