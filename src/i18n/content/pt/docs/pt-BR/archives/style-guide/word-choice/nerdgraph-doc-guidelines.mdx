Este recurso contém recomendações e diretrizes do guia de estilo para escrever sobre a API NerdGraph da New Relic.

## Diretrizes relacionadas a estilo [#nerdgraph-style]

Algumas diretrizes relacionadas a estilo ao escrever sobre o NerdGraph:

* **NerdGraph.** Deve-se referir a ele em geral como &quot;NerdGraph&quot; ou &quot;NerdGraph da New Relic&quot;. Na primeira menção, é aceitável formulá-lo como nossa &quot;API NerdGraph&quot;, especialmente em contextos onde pode não ser imediatamente óbvio que estamos falando sobre uma API.

* **O NerdGraph é uma única API.** O NerdGraph não é um conjunto de APIs diferentes. Às vezes, há uma inclinação para se referir ao NerdGraph como uma coleção de APIs, o que na verdade é um tanto verdadeiro porque o NerdGraph reúne muitas de nossas APIs nos bastidores, mas do ponto de vista dos clientes, queremos nos referir a ele como uma única API. Por exemplo, em vez de dizer algo como &quot;use a API de entidade do NerdGraph&quot;, poderíamos dizer algo como &quot;use o NerdGraph para visualizar e configurar as entidades monitoradas&quot;.

* **GraphQL.** O GraphQL é o formato de API de código aberto com o qual o NerdGraph foi desenvolvido. É aceitável destacar isso ocasionalmente, quando apropriado, porque o GraphQL é bem conhecido no mundo da tecnologia e algumas pessoas já estão familiarizadas com o seu funcionamento.

* **NerdGraph explorer.** Principalmente, referimo-nos a isso como &quot;o NerdGraph explorer&quot; ou &quot;nosso NerdGraph explorer&quot;, mas se estiver em um contexto em que pode não ser óbvio o que exatamente é o NerdGraph, é possível referir-se ao &quot;explorador de API NerdGraph.&quot; Outras dicas:

  * Como existem URLs diferentes para as versões da UE e do JP do explorador do NerdGraph, geralmente deve-se vincular à [seção de documentos do explorador do NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#explorer) e não à URL do explorador.
  * Recomenda-se evitar o uso de apenas &quot;explorer&quot; porque isso entra em conflito com outros explorers (por exemplo, o explorer da API REST ou o explorer de entidade).
  * Podemos explicar, se acharmos útil, que o explorador NerdGraph é construído com GraphiQL, uma plataforma de código aberto para a criação de consultas GraphQL. Isso pode ser útil de explicar porque tanto o GraphQL quanto o GraphiQL são conhecidos no setor.

* **Requests.** Existem dois tipos principais de operações do GraphQL: consultas e mutações ([definidas aqui](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#terminology)). É possível usar esses termos para se referir a exemplos específicos (por exemplo: &quot;aqui está uma mutação que...&quot;). Para fazer uma referência geral a vários requests do NerdGraph de tipos diferentes, é possível usar &quot;requests&quot;.

* **Campos.** Os campos são os elementos em um tipo de objeto que podem ser consultados. Para obter exemplos de &quot;campo&quot; sendo utilizado no contexto, consulte [este tutorial do NerdGraph](/docs/nerdgraph-anomaly-detector-configurations-api-tutorial/#update-configuration). O motivo pelo qual os campos são um conceito importante é que, com as APIs no formato GraphQL, os usuários especificam exatamente os campos que desejam receber (em contraste com as APIs REST, por exemplo, que podem retornar uma resposta padrão com campos que não são necessários).

## Dicas para criar a documentação do NerdGraph [#creating-nerdgraph-docs]

É aceitável adicionar seções relativamente pequenas de conteúdo relacionado ao NerdGraph a documentos que não estão na categoria de documentos do NerdGraph. Como uma diretriz geral, se houver mais de uma página de conteúdo relacionado ao NerdGraph, deve-se tentar adicioná-lo à categoria de documentos do NerdGraph (seja em seu próprio documento ou em um documento relacionado, se possível).

Ao adicionar conteúdo à categoria de documentos do NerdGraph, considere as seguintes dicas para ajudar a manter nosso conteúdo organizado de forma eficiente e fácil de encontrar:

* **Considere adicionar conteúdo a um tutorial existente.** Ao adicionar novo conteúdo do NerdGraph, verifique se é possível incluir o novo conteúdo em documentações existentes do NerdGraph. Isso nos ajuda a manter a lista de tutoriais limpa e evita que ela se torne muito extensa. Por exemplo, caso deseje adicionar algo relacionado à visualização ou configuração de entidades, é possível adicionar isso à [documentação do NerdGraph relacionada à entidade](/docs/apis/nerdgraph/examples/nerdgraph-entities-api-tutorial).
* **Escolher um documento para emular.** Ao escrever um novo documento de tutorial do NerdGraph, é possível usar [este documento do NerdGraph](/docs/apis/nerdgraph/examples/manage-accounts-nerdgraph) como um modelo básico. É possível alterar esta estrutura com base no que os especialistas no assunto ou os redatores considerarem necessário para ajudar os clientes a entender a funcionalidade da API, mas essa estrutura geral deve funcionar para muitos documentos.
* Ao adicionar um novo tipo de conteúdo do NerdGraph, adicione-o ao [índice de conteúdo do NerdGraph](/docs/apis/nerdgraph/get-started/introduction-new-relic-nerdgraph/#tutorials). Esse índice foi criado para refletir que há tutoriais disponíveis que não estão na seção principal de documentação do NerdGraph.

Algumas dicas ao escrever o conteúdo do NerdGraph:

* **Exemplos de requests.** Dicas para criar exemplos de requests:

  * Deve-se usar a tag `tags for customer-specific values in example queries and mutations. Remember that you don't need to use` em respostas de exemplo ou mensagem de erro.
  * É uma boa prática explicar o uso geral de um request, seguido por uma nota de que o request de exemplo é apenas um exemplo (em oposição a comunicar que é a única maneira de realizar algo). Assim, por exemplo, pode-se dizer: &quot;É possível usar o NerdGraph para atualizar o [monitor Sintético de teste de API](/docs/synthetics/synthetic-monitoring/getting-started/types-synthetic-monitors#types-monitors). Aqui está um exemplo de criação de um monitor de teste de API que...&quot;.
  * Para limpar o formato de uma solicitação, acessar o explorador do NerdGraph, inserir a solicitação e clicar em **Tools &gt; Prettify**. Observar que a solicitação deve ser funcional, com valores reais.

* **Definições de campo.** O explorador do NerdGraph inclui definições de campo integradas, mas pode ser bom explicar qualquer um dos campos mais complexos ou não óbvios no documento. Para campos comuns usados em todos ou na maioria dos requests de exemplo, uma maneira de lidar com isso é com uma seção de &quot;Conceitos importantes&quot; perto do topo do documento, na qual se inclui qualquer leitura recomendada ou notas sobre campos importantes. Para campos que são usados apenas em um ou dois requests, pode ser preferível explicá-los ao introduzir o request de exemplo.

## Documentação do esquema do NerdGraph [#schema-docs]

O explorador do NerdGraph expõe as definições de esquema do NerdGraph para ajudar os usuários a entender quais são os vários campos. A equipe de documentação revisa os documentos de esquema que são enviados pelas equipes de engenharia. Para obter mais informações sobre como ocorre a revisão da definição de esquema, recomenda-se consultar o recurso da equipe de documentação &apos;Repositórios de Documentação Externa&apos;.
