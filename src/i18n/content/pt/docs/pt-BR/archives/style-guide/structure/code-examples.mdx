## Formatação de código em linha [#inline-code]

Para formatar código em linha (como `maxSampleTimes` ou `TransactionError`), envolver o texto com caracteres de crase `` ` ``.

## Blocos de código de várias linhas [#code-block]

Para formatar uma ou mais linhas de código, inserir três crases ( ` ``` ` ) acima e abaixo do código. Isso atua essencialmente como a tag HTML `<pre>`.

Ao intercalar os trechos de código entre três crases, é necessário considerar tanto o recuo do código quanto o destaque de sintaxe.

### Recuo estrito [#strict]

Como redator técnico, serão fornecidos trechos de código de uma variedade de linguagens. Para facilitar a compreensão dos trechos de código pelos leitores, certificar-se de que as linhas estejam recuadas e agrupadas de forma útil.

Algumas linguagens de programação e marcação exigem indentação específica (por exemplo, Python e YAML). Verifique com o especialista no assunto em caso de dúvida se o trecho fornecido precisa ter indentação específica para funcionar. Sempre é possível passar o trecho por um formatador de código online caso ele fique desordenado ao ser transferido de outra ferramenta de edição.

Abaixo está um exemplo de código Python que será interrompido se a indentação for alterada:

```python
import newrelic.agent
newrelic.agent.initialize('newrelic.ini') #This is required!

def greet(name):
    """
    This function says hello to
    the person who is passed in as
    a parameter
    """
    print("Hello, " + name + " and the world!")


def execute_task(application, task_name):
    with newrelic.agent.BackgroundTask(application, name=task_name, group='Task'):
        greet("Robert")

application = newrelic.agent.register_application(timeout=10)
execute_task(application, "bar")
newrelic.agent.shutdown_agent(timeout=10)

```

### Recuo não estrito [#casual]

Para linguagens de formato livre, que são casuais quanto à indentação, recomenda-se procurar exemplos semelhantes e seguir esses padrões. Java e SQL são exemplos de linguagens de formato livre.

### Como formatar NRQL [#NRQL]

A NRQL é uma linguagem de consulta de forma livre, o que significa que não possui regras estritas de recuo. Recomendamos que sejam seguidas algumas diretrizes simples para facilitar a leitura. Nossas sugestões baseiam-se vagamente em algumas diretrizes de formatação de SQL.

Fica a critério decidir se estas diretrizes se aplicam ao trecho:

* Coloque em maiúsculas as palavras-chave da cláusula, como `FROM`, `SELECT`, `FACET`, `WHERE`, `AND`, `OR`, `AS`, `SINCE`, `ORDER BY`, `TIMESERIES`, `EXTRAPOLATE` e `AUTO`.

* Não colocar funções em maiúsculas, como `min()`, `max()`, `average()`, `percentile()`, `sum()` e `stddev()`, uma vez que o criador de consulta não coloca automaticamente esses nomes em maiúsculas. Se não houver certeza se uma palavra-chave é uma função, consultar a [referência do NRQL](/docs/query-your-data/nrql-new-relic-query-language/get-started/nrql-syntax-clauses-functions/#functions).

* A primeira linha deve começar com uma cláusula `FROM`, embora as consultas sejam executadas perfeitamente quando se começa com `SELECT`.

* Alinhar à esquerda as palavras-chave da cláusula, exceto nos seguintes casos:

  * Se uma palavra-chave de cláusula estiver intimamente ligada a uma palavra-chave anterior (por exemplo, `AGO` está intimamente ligada a `SINCE`), ela pertence à mesma linha.
  * Se uma palavra-chave de cláusula não tiver nenhum modificador (ela fica sozinha), é possível anexá-la ao final de uma linha que já tenha palavras-chave (por exemplo, `TIMESERIES`, `AUTO` e `EXTRAPOLATE`).
    ```sql
    FROM Transaction
    SELECT count(*)
    WHERE appName='interestingApplication'
    SINCE 60 minutes AGO EXTRAPOLATE
    ```

* Para palavras-chave dentro de parênteses que abrangem várias linhas, recuá-las dois espaços. Por exemplo, a palavra-chave `WHERE` é recuada dois espaços da seguinte forma:
  ```sql
  FROM PageView
  SELECT count(*)
  FACET CASES
  (
    WHERE duration < 1,
    WHERE duration > 1 AND duration < 10,
    WHERE duration > 10
  )
  ```

## Destacar linhas de código [#highlight-code]

Para destacar linhas inteiras de código em um bloco de código, é possível usar `lineHighlight=` para indicar as linhas específicas que se deseja destacar. Isso é feito no mesmo local onde se anota a sintaxe. Aqui está um exemplo de um bloco de código com a primeira e da terceira à quinta linhas destacadas:

```js lineHighlight=1,3-5
const coolThing = {
  key: 'HI',
  tada: 'hello'
}
// this is an important object
// other notes...
```

## Espaços reservados para variáveis específicas de clientes [#value-placeholders]

Às vezes, é necessário utilizar espaços reservados para variáveis cujo valor dependerá dos clientes ou da situação. Por exemplo, pode ser necessário utilizar `YOUR_ACCOUNT_ID` para indicar um espaço reservado onde os clientes devem inserir o ID da conta da New Relic.

Alguns requisitos e dicas sobre a criação de espaços reservados de valor específicos para clientes:

* Usar letras maiúsculas e sublinhados `_` para separar palavras (também conhecido como [SCREAMING\_SNAKE\_CASE](https://github.com/rubocop-hq/ruby-style-guide#screaming-snake-case)).
* Não use outros elementos, como `<` ou `>`, ou `$`, a menos que os SMEs apresentem um motivo convincente pelo qual outros elementos são necessários para um idioma ou situação específica.
* Dirigir-se ao leitor diretamente usando `YOUR`. Por exemplo, usar `YOUR_ACCOUNT_ID` e não `ACCOUNT_ID`.
* Se houver dúvidas se um componente é nosso ou de terceiros, é possível adicionar `NEW_RELIC` ao espaço reservado. Por exemplo, ao escrever sobre a conexão da AWS com a New Relic, pode ser necessário especificar que uma conta é nossa e não da AWS, da seguinte forma: `YOUR_NEW_RELIC_ACCOUNT_ID`.
* Evite combiná-los com outras pontuações para indicar variáveis (como envolver o texto em sinais de menor e maior ou chaves).

### Quando não usar espaços reservados [#placeholders]

Os espaços reservados são utilizados principalmente quando há um procedimento a ser realizado, como clientes que executarão algum código. Se não houver um procedimento envolvido e um trecho de código estiver sendo utilizado para demonstrar como algo é ou deveria ser, não se deve utilizar espaços reservados. Aqui estão alguns exemplos de onde **não** se deve utilizar espaços reservados:

* Código ou arquivos de exemplo: ao mostrar um arquivo de configuração de exemplo ou outro exemplo que não esteja diretamente relacionado ao procedimento, devem ser usados valores de exemplo e não espaços reservados.
* Respostas de chamada de API: se estiver incluindo a resposta de uma chamada de API que se destina a mostrar como será a resposta e não estiver relacionada a procedimentos, não utilizar espaços reservados.

### Chaves de API

Se uma chave de API precisar ser referenciada como exemplo em um bloco de código ou configuração, será necessário usar um texto de espaço reservado com asteriscos em vez de zeros.

Exemplo:

```
...
-e NEW_RELIC_API_KEY=********************************FFFFNRAL \
...
```

ou

```
...
NEW_RELIC_LICENSE_KEY=****************************************
...
```
