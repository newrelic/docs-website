As chamadas direcionam a atenção para informações de especial importância ou para informações que não se integram perfeitamente ao texto principal. É importante considerar o leitor. Se o documento possuir muitas chamadas, isso poderá confundir o leitor sobre o que é mais importante e distraí-lo do foco principal.

Use os callouts com prudência. **Recomendação:** faça uma leitura dinâmica do documento completo. Se houver muitos callouts, decida quais podem ser removidos.

## Tipos de Callouts [#classes]

Há vários tipos de destaque, e cada um é controlado pelo `variant` incluído na tag `<Callout>`.

Este é um exemplo do formato para um destaque de dica:

```jsx
<Callout variant="tip">
  Your tip text goes here.

  It can have multiple paragraphs.
</Callout>
```

Aqui estão exemplos das nossas variantes de callout:

<CollapserGroup>
  <Collapser id="tr-caution" title="Cuidado">
    **Cautions** alertam que isso pode causar uma falha ou resultar em perda de dados além da tarefa em andamento. Os avisos de cuidado usam `<Callout variant="caution">`. Em um semáforo, um **Caution** seria vermelho.

    <Callout variant="caution">
      Recomenda-se evitar a desativação da nomenclatura automática de transações, pois provavelmente ocorrerão problemas de agrupamento de métricas. Em vez disso, utilize chamadas de API para nomear as transações.
    </Callout>
  </Collapser>

  <Collapser id="tr-important" title="Importante">
    As notas **Importante** pedem atenção para o fato de que isso pode prejudicar a tarefa em andamento ou custar tempo se o texto for ignorado. As notas importantes usam `<Callout variant="important">`. Em um semáforo, uma nota **Importante** seria amarela.

    <Callout variant="important">
      Os eventos personalizados enviados por meio da API do agente não são compatíveis com o modo de alta segurança.
    </Callout>
  </Collapser>

  <Collapser id="tr-tip" title="Dica">
    As **Dicas** sugerem que é bom saber disso, como um atalho, práticas recomendadas ou lembrete, mas não é necessário para concluir a tarefa em questão. As Dicas usam `<Callout variant="tip">`. Em um semáforo, uma **Dica** seria um sinal verde.
  </Collapser>

  <Collapser id="tr-permissions" title="Permissões relacionadas ao usuário">
    Para obter o texto recomendado, recomenda-se consultar [Linguagem e Estilos Relacionados ao Usuário](/docs/new-relic-only/basic-style-guide/style-guide-quick-reference/user-related-language-styles-recommended-phrasings).
  </Collapser>

  <Collapser id="tr-custom-callout" title="Balões personalizados">
    Destaques personalizados estão disponíveis para casos especiais, como documentação de pré-visualização. Veja o que pode ser controlado com destaques personalizados:

    * **Texto do título:** é possível alterar o rótulo do destaque inserindo o atributo `title` da seguinte forma: `title="YOUR CUSTOM TITLE"`. Ao publicar, este campo é convertido automaticamente para letras maiúsculas.

    * **Color:** A cor é limitada à cor do `variant` incluído, ou se um `variant` não for incluído, obtém-se a cor de borda padrão (azul-acinzentado).

      Veja como o código fica:

      ```jsx
      <Callout variant="caution" title="YOUR CUSTOM TITLE">
        Your callout message goes here!
      </Callout>
      ```
  </Collapser>
</CollapserGroup>

## Evitar a fadiga de avisos [#fatigue]

A fadiga de avisos é o que acontece quando há muitos avisos em um documento. Um único aviso é uma ótima maneira de chamar a atenção para informações importantes, mas quanto mais avisos houver, maior será a probabilidade de o leitor não ler os avisos.

Tenha estes pontos em mente ao trabalhar com destaques:

* **Ao adicionar um destaque, remover um destaque.** Sempre que possível, não aumentar o número de destaques.
* **Não utilizar textos explicativos empilhados.** Textos explicativos empilhados são dois ou mais textos explicativos que se seguem diretamente um após o outro. Além de não os utilizar, caso sejam encontrados em um documento, recomenda-se reservar alguns minutos para separar esses textos explicativos.
* **Remover destaques desatualizados.** Ao navegar pelo site de documentação, se for encontrado um destaque desatualizado, por qualquer motivo, recomenda-se dedicar alguns minutos para excluí-lo do documento.
* **Recomenda-se moderação no uso de avisos importantes e de alerta.** Se usarmos avisos importantes e de alerta com muita frequência, eles perderão sua eficácia.

### Exemplo de textos explicativos empilhados [#stacked]

Apresentamos um exemplo dos textos de destaque empilhados que gostaríamos de evitar.

<Callout variant="tip">
  Quanto mais balões houver, mais difícil será identificar as informações importantes.
</Callout>

<Callout variant="important">
  Nem tudo é importante o suficiente para ser colocado em um destaque.
</Callout>

<Callout variant="caution">
  Deve-se pensar cuidadosamente antes de adicionar outro destaque na página.
</Callout>
