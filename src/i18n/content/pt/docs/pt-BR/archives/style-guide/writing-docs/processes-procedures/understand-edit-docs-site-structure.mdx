Este documento contém informações e procedimentos referentes à estrutura do site de documentação, incluindo: os arquivos de navegação, a barra lateral, a estrutura de pastas ou arquivos e muito mais.

Para obter instruções breves sobre casos de uso comuns, consulte [Procedimentos](#procedures), mas se estiver realizando projetos maiores no site de documentação, recomenda-se compreender os [conceitos gerais](#understand) de antemão.

## Termos [#terms]

Ao falar sobre a estrutura do site de documentação, às vezes as pessoas usam palavras diferentes para as mesmas coisas. Abaixo está uma lista de termos que podem ajudar na comunicação sobre a estrutura do site de documentação:

* **Arquivos de documentação**: todos os documentos são representados por .mdx arquivos, também conhecidos como arquivos markdown.
* **Arquivos nav**: os arquivos nav são o que governa a estrutura exibida do site de documentação, conforme exposto na barra lateral esquerda do site de documentação. Os arquivos nav são arquivos yaml localizados no diretório `src/nav`.
* **Pasta**: neste contexto, &quot;pastas&quot; refere-se à estrutura real de pastas do site de documentação (aquelas pastas e arquivos no diretório `content`). Referir-se a &quot;pastas&quot; pode ser uma maneira útil de diferenciar entre a estrutura real de pastas e a estrutura exibida que é definida usando os arquivos de navegação.
* **Barra lateral**: em documentos voltados para o público, a barra lateral é o que fica visível no lado esquerdo, mostrando a estrutura dessa categoria de documentos. A estrutura da barra lateral é determinada pela estrutura definida no arquivo de navegação.
* **Categoria** ou **subcategoria**: usamos essas palavras de forma bastante intercambiável para nos referirmos a áreas específicas do site de documentação. Por exemplo, podemos nos referir à categoria &quot;Contas&quot; ou à categoria &quot;Gerenciar dados&quot;.
* **Páginas de autoindexação** (obsoleto): isso se refere a uma implementação anterior em que os usuários podiam carregar visualizações da documentação em uma categoria específica (por exemplo, ao clicar em um título de categoria na barra lateral). Essa implementação não é mais suportada.

## Entenda como funciona a estrutura do site de documentação [#understand]

Esta seção explicará parte da lógica por trás de como a estrutura do site de documentação é determinada e como a estrutura exibida ao público se relaciona com a estrutura real de pastas.

### Como a estrutura exibida está relacionada às pastas reais? [#folders-vs-categories]

A estrutura real da pasta de documentação (as pastas e os arquivos mdx na pasta `content`) é totalmente separada da estrutura do site de documentação na barra lateral. A estrutura exibida na barra lateral é determinada exclusivamente pelos arquivos de navegação (os arquivos no formato yaml na pasta `src/nav`).

É importante entender o ponto acima. A divergência entre a estrutura de pastas de documentos e a estrutura do site de documentos exibida é necessária: é preciso uma maneira de controlar a estrutura exibida na barra lateral sem exigir que a estrutura de pastas, os nomes das pastas e os nomes dos arquivos de documentos sejam mantidos completamente equivalentes. Como essas duas coisas são separadas, isso pode significar que pode haver alguns aspectos não intuitivos de como essa lógica funciona.

Temos [procedimentos para casos de uso comuns](#procedures), mas será de grande ajuda entender as especificidades abaixo sobre como a estrutura exibida é gerada.

### O que determina o URL de um documento? [#doc-url]

Onde um arquivo de documento (arquivo `mdx`) está localizado na pasta `content`, e os nomes de pasta e arquivo associados, são os únicos fatores que governam o URL desse documento.

Por exemplo, deve-se considerar o seguinte arquivo de documento `automated-user-provisioning-single-sign.mdx`:

<img title="Doc file in its folder" alt="Example of a doc file in the folder structure" src="/images/style-guide_screenshot-full_doc-in-folder-structure.webp" />

O URL deste documento baseia-se exclusivamente na localização da pasta e nos nomes das pastas. Neste caso, o URL é:

```
docs.newrelic.com/docs/accounts/accounts/automated-user-management/automated-user-provisioning-single-sign
```

Isso tem implicações importantes, incluindo:

* Quando um documento é movido de uma pasta para outra, seu URL é alterado. Isso significa que, ao mover um arquivo de documento, deve-se adicionar um redirecionamento para esse documento a partir de seu URL original.
* Se o nome de um arquivo mdx ou de uma pasta for renomeado, seu URL será alterado. Isso significa que deve-se adicionar um redirecionamento para esse documento a partir de seu URL original.

### O que um arquivo nav faz? [#nav-file-contents]

Os arquivos de navegação são bastante simples. Um arquivo de navegação controla a estrutura exibida dos documentos que são vistos na barra lateral. Atualmente, existem vários arquivos de navegação, um para cada seção principal de documentos. Por exemplo, há um arquivo de navegação para &quot;Contas&quot;, que contém configurações relacionadas à organização e à conta. E há um arquivo de navegação para &quot;Monitoramento de infraestrutura&quot;.

Para obter mais informações sobre o formato do arquivo de navegação, consulte [Formato do arquivo de navegação](#nav-format)

### O que determina como uma barra lateral é exibida? [#doc-sidebar]

Conforme indicado acima, a barra lateral é apenas uma maneira pela qual a estrutura do site de documentos (que é governada pelos arquivos de navegação) é exposta.

Quando um documento é carregado, o site de documentos pesquisa esse URL em todos os arquivos de navegação. Se encontrar uma correspondência, ele exibirá esse arquivo de navegação na barra lateral com esse documento destacado.

A URL de um documento pode existir em mais de um arquivo de navegação. Atualmente, é uma regra que um documento só pode estar localizado em apenas um lugar em todos os arquivos de navegação. Mas ainda temos alguns documentos que existem em vários arquivos de navegação. Para esses casos, nosso site tenta encontrar o arquivo de navegação apropriado escolhendo o arquivo de navegação que corresponde à categoria de nível superior na URL do documento. Por exemplo, se um documento com a URL relativa `/docs/accounts/accounts-billing/account-setup/create-your-new-relic-account` estivesse em dois arquivos de navegação, o código do site de documentação pesquisaria para ver se um dos arquivos de navegação tem `docs/accounts` como seu primeiro campo `path`. Se encontrar uma correspondência, ele usará esse arquivo de navegação.

## Formato do arquivo de navegação [#nav-format]

Abaixo está um trecho do arquivo de navegação [`agents.yml`](https://github.com/newrelic/docs-website/tree/develop/src/nav/agents.yml). Observe que o arquivo possui um recuo que corresponde ao nível da hierarquia de navegação. Ao fazer alterações ou criar um novo arquivo de navegação, certifique-se de usar o formato de espaçamento existente.

```yml
title: Agents
path: /docs/agents
pages:
  - title: Manage APM agents
    pages:
      - title: Agent data
        pages:
          - title: Real time streaming
            path: /docs/agents/manage-apm-agents/agent-data/real-time-streaming
          - title: Custom instrumentation
            path: /docs/agents/manage-apm-agents/agent-data/custom-instrumentation
          - title: Agent attributes
            path: /docs/agents/manage-apm-agents/agent-data/agent-attributes
          - title: Custom events
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-events
          - title: Custom metrics
            path: /docs/agents/manage-apm-agents/agent-data/collect-custom-metrics
          - title: Manage errors
            path: /docs/agents/manage-apm-agents/agent-data/manage-errors-apm-collect-ignore-or-mark-expected
          - title: Link Kubernetes
            path: /docs/agents/manage-apm-agents/agent-data/link-your-applications-kubernetes
      - title: App naming
        pages:
          - title: Name your application
            path: /docs/agents/manage-apm-agents/app-naming/name-your-application
          - title: Use multiple names for an app
            path: /docs/agents/manage-apm-agents/app-naming/use-multiple-names-app
```

<Callout variant="tip">
  Atualmente, o aninhamento de navegação é limitado a um máximo de seis níveis de profundidade. Por gentileza, entre em contato com a equipe de engenharia se isso não for suficiente.
</Callout>

### Visão geral das etapas para um grande projeto de reestruturação de site de documentação [#large-project]

Para algumas edições menores no site de documentação, às vezes é possível simplesmente editar os arquivos de navegação e não ter que tocar nos arquivos ou pastas de documentos. Mas para projetos maiores, pode ser desejável ou necessário editar e mover os próprios arquivos e pastas de documentos. Abaixo está uma visão geral ampla das partes de trabalho que tais projetos maiores geralmente envolvem.

1. É necessário planejar como será a nova estrutura de arquivos de navegação e planejar o trabalho de mover arquivos de documentos ou criar novas pastas. Pode ser útil anotar as partes do trabalho que um grande projeto envolverá.
2. Os arquivos de documento afetados devem ser movidos para seus novos locais de pasta, certificando-se de adicionar redirecionamentos. Para obter mais informações sobre isso, consulte [Mover documentos entre pastas](#move-docs-between-folders).
3. Exclua qualquer pasta vazia.
4. Para quaisquer edições de pasta ou arquivo feitas na própria estrutura de arquivos (incluindo renomeação de arquivo ou pasta, movimentação de arquivos e pastas, mas **não** incluindo edição de conteúdo ou front matter dentro de um documento ou arquivo de navegação), fazer as mesmas edições nas pastas e arquivos no diretório `i18n`. Nem todas as pastas ou arquivos estarão presentes no diretório i18n: ele apenas preenche um arquivo mdx ou uma pasta associada se esse arquivo mdx tiver sido marcado para tradução.
5. Edite os arquivos de navegação para refletir a nova estrutura desejada e apontar para os novos URLs do documento.

Para procedimentos mais específicos e granulares, continue lendo.

### Adicionar uma nova categoria de documentos [#add-category]

Explicaremos dois procedimentos: adicionar uma subcategoria de documentos em um arquivo de navegação existente e adicionar um arquivo de navegação totalmente novo:

#### Adicionar uma nova categoria a um arquivo de navegação [#add-nav-section]

Para adicionar uma nova categoria a um arquivo nav:

1. Em um arquivo de navegação existente, deve-se adicionar uma nova categoria, representada por seu `title`.
2. Adicionar os documentos desejados nessa seção, emulando o formato e a indentação de outros arquivos de navegação.

Para saber mais sobre como isso funciona, consulte:

* [Como a barra lateral de um documento é determinada](#doc-sidebar)
* [Como a visualização de categoria de documento é determinada](#category-view)

#### Adicionar um novo arquivo de navegação [#add-new-nav]

Adicionar um arquivo de navegação totalmente novo deve ser raro e algo que fazemos apenas ocasionalmente durante grandes revisões da estrutura do site. A adição de novos arquivos de navegação deve obter a aprovação de um gerente do site de documentos.

Para adicionar um arquivo de navegação totalmente novo:

1. Deve-se copiar um arquivo de navegação existente ou criar um novo arquivo de navegação.
2. O novo arquivo de navegação deve ser personalizado com as categorias e os documentos desejados, utilizando a formatação e o recuo padrão do arquivo de navegação. Para obter mais informações sobre a estrutura, consulte [formato de navegação](#nav-format).

### Adicionar um documento à barra lateral/arquivo de navegação [#add-doc-to-nav]

Após [criar um documento](/docs/style-guide/writing-guidelines/create-edit-content/#creating-docs), é necessário colocá-lo em um arquivo de navegação. Não coloque um documento em mais de um local de arquivo de navegação: se for necessário um link para um documento de uma categoria diferente, tente colocar essa referência dentro de uma seção de documento relevante.

Para adicionar um documento a um arquivo de navegação:

1. No local do arquivo de navegação onde se deseja localizá-lo, adicionar o `title` (seu título curto exibido na barra lateral e nas visualizações de categoria) e o `path`, que é o URL do documento.
2. Garantir que a formatação e a indentação padrão do arquivo nav tenham sido emuladas.

### Mover documentos para outras categorias [#move-docs]

Como o arquivo de navegação e a estrutura de pastas real não estão conectados, existem duas maneiras diferentes de &quot;mover documentos&quot;:

* Mover um documento nos arquivos de navegação: procedimento preferencial e mais comum.
* Mover um documento entre pastas: menos frequente, principalmente ao realizar projetos maiores em que se deseja fazer uma revisão significativa da estrutura de documentação e garantir que a estrutura de pastas não se torne muito divergente da estrutura do arquivo de navegação.

#### Mover documentos usando o arquivo de navegação [#move-docs-in-nav-file]

Mova um documento no arquivo nav quando desejar alterar onde ele é visível nos menus da barra lateral.

Para mover um documento de um lugar para outro no arquivo de navegação:

1. No primeiro arquivo de navegação, copie as duas linhas que representam a entrada desse documento (as linhas `title` e `path`) e cole esse conteúdo no local onde deseja que ele fique no novo arquivo de navegação.
2. Na nova seção do arquivo de navegação, é necessário certificar-se de que a formatação e o recuo correspondam à estrutura padrão do arquivo de navegação. Consulte o [Formato de Navegação](#nav-format) para obter mais informações sobre a estrutura do arquivo de navegação.

#### Mover um documento entre pastas [#move-docs-between-folders]

Observe que a movimentação de documentos entre as pastas deve ser relativamente rara. Os principais motivos para fazer isso são quando a estrutura de pastas e a estrutura do arquivo de navegação estão se tornando muito divergentes, o que pode ser ruim por alguns motivos:

* Muita divergência pode criar confusão para o usuário (por exemplo, quando os elementos do URL baseado em pastas são muito diferentes da localização baseada no arquivo nav) ou resultados de mecanismos de busca abaixo do ideal.
* Muita divergência pode dificultar a localização e a edição de documentos, portanto, pode haver valor em manter as coisas razoavelmente atualizadas e paralelas.

Quando um documento é movido entre pastas ou renomeado, seu URL é alterado (para obter mais informações sobre o motivo, consulte [Entender a estrutura](#understand)). Da mesma forma, se uma pasta for renomeada, o URL de todos os documentos nessa área será alterado.

Para mover um documento entre pastas:

1. Deve-se obter o URL atual do documento que se deseja mover e adicionar esse URL à sua própria lista de redirecionamentos. Dicas:

   * Uma maneira de fazer isso no VSCode é clicar com o botão direito do mouse no nome do arquivo e clicar em &quot;Get relative path&quot;.
   * Caso muitos arquivos estejam sendo movidos, a equipe deve ser consultada sobre nosso script para adicionar redirecionamentos de forma programática a um diretório inteiro de documentos.
   * Certifique-se de que as URLs de redirecionamento não tenham uma barra no final.

2. Mova o documento para o seu novo local de pasta.

3. Se esse arquivo mdx estiver presente no diretório `i18n` (o que ocorrerá se estiver marcado para tradução), deve-se fazer uma movimentação equivalente desse arquivo no diretório `i18n`.

4. **Atualizar os arquivos de navegação com o novo URL**. Ter o URL correto do documento no arquivo de navegação, e não um redirecionamento, é importante. É importante notar que o URL de um documento pode estar em mais de um arquivo de navegação, portanto, pesquisar esse URL no site pode ajudar.

### Mover, excluir ou renomear uma pasta [#move-delete-folders]

Às vezes, ao realizar um projeto de reestruturação maior, pode ser necessário mover, excluir ou renomear as pastas reais em vez de simplesmente editar os arquivos de navegação. Instruções para isso:

1. Como mover uma pasta ou alterar o seu nome resulta na alteração de todos os URLs das documentações nessa pasta, deve-se primeiro adicionar redirecionamentos às documentações afetadas. É possível fazer isso manualmente ([descrito na etapa n.º 1 aqui](#move-docs-between-folders)) ou usar um script que a equipe de documentação possui para adicionar redirecionamentos em massa a todas as documentações em um diretório.
2. A edição desejada deve ser realizada. Por exemplo, a pasta pode ser movida para o novo local (arrastando e soltando na janela do Finder, por exemplo) e/ou renomeada.
3. Se a pasta editada estiver presente no diretório `i18n` (o que ocorrerá se um documento nessa pasta tiver sido marcado para tradução), deve-se fazer uma edição equivalente dessa pasta e de seus arquivos no diretório `i18n`. Nota: o trabalho `i18n` é necessário apenas para movimentações ou renomeação de pastas ou arquivos, **não** para edição de documentos ou conteúdo de arquivos de navegação.

Para excluir pastas, deve-se seguir essencialmente as mesmas etapas acima: adicionar redirecionamentos para os arquivos mdx sendo movidos ou excluídos, em seguida, mover ou excluir os documentos e, em seguida, excluir as pastas vazias.

### Alterar o nome do arquivo de um documento [#change-doc-file-name]

Alterar o nome de um arquivo mdx [resulta na alteração da respectiva URL](#understand). Note que é possível alterar o título exibido de uma documentação no respectivo front matter sem alterar o nome real do arquivo. Alterar o nome do arquivo pode ser útil. Instruções:

1. Adicione um redirecionamento ao documento cujo nome de arquivo está sendo alterado.
2. Altere o nome do arquivo.
3. Se esse arquivo estiver presente no diretório `i18n` (o que ocorrerá se esse documento tiver sido marcado para tradução), deve-se fazer uma edição equivalente do nome desse arquivo no diretório `i18n`. Nota: o trabalho `i18n` é necessário apenas para movimentações ou renomeação de pastas ou arquivos, **não** para edição de documentos ou conteúdo de arquivos de navegação.

### Criar documentos de espaço reservado [#placeholder-doc]

Não é mais desejável ter documentos em vários lugares nos arquivos nav (embora ainda existam alguns documentos que sejam assim). Caso se deseje que um documento seja referenciado em mais de um local nos arquivos nav, em vez disso, deve-se tentar encontrar um lugar dentro de um documento onde faça sentido referenciar esse documento.
