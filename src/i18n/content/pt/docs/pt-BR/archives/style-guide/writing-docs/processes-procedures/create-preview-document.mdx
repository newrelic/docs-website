title: Criar conteúdo para o site de documentação de visualização
translationType: machine
---

O site de documentação de pré-visualização hospeda documentos para os próximos recursos que compartilhamos com os clientes. Ao contrário do site de documentação pública, o site de documentação de pré-visualização não é editável publicamente e não aparece nos resultados dos mecanismos de pesquisa. Os usuários não podem navegar de um documento de pré-visualização para outro, porque o site não está indexado.

Como o site de visualização da documentação está localizado em um repositório diferente do site público de documentação, a contribuição é um pouco diferente. Ao final deste documento, será possível criar um novo documento para o site de visualização.

## Configurar seu ambiente local [#do-first]

Caso o repositório beta-docs-site já tenha sido clonado no computador, é possível pular para a etapa 3.

1. Vá para o [`beta-docs-site repo`](https://github.com/newrelic/beta-docs-site). Caso não haja acesso, entre em contato com o canal #doc-eng-help do Slack para obter ajuda.
2. Clonar o repositório beta-docs-site no computador.
3. Certificar-se de estar trabalhando no repositório correto no GitHub Desktop.
4. Crie uma branch a partir da branch `main`.

## Criar um novo documento de pré-visualização [#create-docs]

Apesar das diferenças entre os sites de documentação públicos e de visualização, a formatação e a sintaxe de seu conteúdo são basicamente as mesmas. Uma vez na ramificação de trabalho:

1. Usando o editor de texto, crie um novo arquivo `.mdx` ou copie um documento de visualização existente para o modelo de frontmatter.
2. Salve o arquivo em `/src/content/docs/`.
3. O conteúdo deve ser redigido, garantindo a inclusão de qualquer informação sobre a inscrição e a solicitação de acesso ao recurso de pré-visualização que está sendo documentado.
4. É necessário fazer o commit das alterações e criar um pull request.
5. Compartilhar o link de pré-visualização com os revisores e implementar qualquer feedback.
6. Mesclar o PR final.
7. Crie o link oficial colando o nome do caminho do arquivo após `https://docs-preview.newrelic.com/docs/` (por exemplo: `https://docs-preview.newrelic.com/docs/new-feature-name`)
8. Fornecer aos revisores o link oficial para compartilhar com os clientes.

## Texto padrão opcional [#boiler-plate]

Ao escrever um documento para visualização, pode ser útil incluir uma [chamada](/docs/style-guide/formatting/callouts/) com texto padrão na parte superior do documento. Esse texto pode ser usado para orientar o leitor, fornecendo-lhe informações importantes sobre a disponibilidade do recurso e informações de contato relevantes.

Por exemplo, o texto padrão para uma documentação de pré-visualização pode ser:

<Callout variant="caution" title="Visualização">
  Este recurso foi lançado em 1 de janeiro de 202X e está em versão de pré-visualização. Para obter acesso, é necessário entrar em contato com o gerente de contas.
</Callout>

Pode ser desejável excluir o texto clichê se a informação for muito longa, estiver incluída em outro lugar na página ou for irrelevante para o documento.

## Diretrizes adicionais para colaboradores internos [#internal-contributors]

Como colaborador interno que deseja editar um documento de pré-visualização, será necessário ter acesso ao repositório beta-docs-site. Caso não possua acesso, solicite no canal #doc-eng-help do Slack a inclusão como colaborador. Após obter acesso, será necessário criar uma ramificação própria a partir da ramificação `main` e realizar as edições nela.
