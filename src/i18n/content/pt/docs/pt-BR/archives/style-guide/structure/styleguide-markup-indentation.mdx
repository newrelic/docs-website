Ao escrever em Markdown, o recuo pode tornar a fonte do documento mais legível. O recuo também pode afetar a legibilidade do arquivo quando ele é renderizado em HTML. Este documento aborda como lidar com listas pai (primeiro nível), filhas (segundo nível) e netas (terceiro nível). Também demonstraremos como inserir espaços para incorporar blocos de código, imagens e listas aninhadas dentro de um conjunto de procedimentos.

## Recuo de lista [#lists]

As listas são uma ótima maneira de explicar procedimentos (etapas numeradas) ou simplesmente detalhar itens (listas com marcadores). Embora as listas de nível único sejam bastante simples, ao começar a aninhá-las, é possível encontrar problemas de recuo. Observe estes tópicos de lista nesta seção:

* [Listas de primeiro nível (pais)](#first-level)
* [Recuo para listas filhas](#second-and-third)

### Listas de primeiro nível (pais) [#first-level]

Para listas de primeiro nível introduzidas por uma frase introdutória alinhada à esquerda, seguimos este padrão Markdown: alinhar à esquerda todos os itens da lista de primeiro nível. Ao publicar o documento, a biblioteca Markdown recuará os itens da lista de primeiro nível:

```md
Here is a basic list written as left-justified but indented at the time of publication:
* Item 1
* Item 2
```

### Recuo para listas filhas [#second-and-third]

Para listas filhas ou netas, insira quatro espaços (ou duas tabulações de dois espaços) antes do marcador ou número. Embora seja possível usar três espaços para recuar listas filhas, recomendamos o método de quatro espaços ou duas tabulações, pois eles renderizam as listas de forma mais consistente e são mais fáceis de digitar.

Nas seções a seguir, serão apresentados exemplos de como recuar várias listas secundárias.

<Callout variant="important">
  Não se deve utilizar recuo de dois espaços para nenhum nível de itens de lista. Embora funcionem em alguns contextos, eles não são previsíveis. Consulte nossos [Exemplos de Dois Espaços](#two-space).
</Callout>

#### Recuo de quatro espaços para listas filhas (recomendado) [#four-space]

Recomendamos o seguinte espaçamento no Markdown porque ele usa múltiplos de dois espaços:

```md
1. Item 1
2. Item 2
    * Item 2a
    * Item 2b
```

#### Problemas com recuo de dois espaços para listas [#two-space]

Embora existam alguns casos em que o recuo de dois espaços funciona, como no recuo de imagens ou para listas de marcadores principais e secundárias, os resultados para listas numeradas e outros casos podem ser imprevisíveis. Aqui estão alguns exemplos de recuo de dois espaços de uma lista secundária. Note que a biblioteca Markdown não recua nenhuma dessas listas secundárias.

Uma lista de marcadores secundária:

```md
1. Item 1
2. Item 2
  * Item 2a
  * Item 2b
```

Observe que os marcadores filhos são renderizados, mas não são recuados:

Uma lista numerada filha:

```md
1. Item 1
2. Item 2
  1. Item 2a
  2. Item 2b
```

Observe que o conversor de Markdown não consegue identificar que a lista recuada é um elemento secundário:

#### Marcadores aninhados em listas numeradas [#bullets-nested-in-numbers]

Ao aninhar listas com marcadores em listas numeradas, recue cada lista secundária em quatro espaços. Observe este exemplo de Markdown onde um marcador secundário na etapa n.º 4 é recuado apenas dois espaços:

```md
The process consists of four activities:
1. Review AQM dashboard and KPI trends: Here you and the stakeholders will look at the AQM KPIs and identify their week over week trends. The team should identify areas where KPIs are not improving and develop strategies to drive improvement.
2. Identify achievements, challenges, and opportunities: Here you and the stakeholders will map the current state of alert quality to business impact, identifying areas where improvement has resulted in better business outcomes and areas where problems are impacting business outcomes.
3. Incident policy review: Using the AQM dashboard, you and the stakeholders will identify the noisiest incident policies. Once identified, those policies should be evaluated as detailed in step 4 below.
4. Alert policy recommendations: In this step, you and the stakeholders will review the noisiest policies using the following criteria:
  * Do the alerts have any business impact?
  * Are the policies properly configured?
    * Are they telling us something about the resource that needs to be fixed?
    * Are the policies necessary? Do they have business impact?
    * Are the thresholds set properly?
5. Technical recommendations: Here, you and the stakeholders will review any technical recommendations, including:
    * Are there application / system problems for engineering to review?
    * Are there poorly constructed policies that need to be fixed?
    * Are there instrumentation gaps?
```

Este Markdown com recuo de dois espaços é renderizado assim:

## Indentação de procedimentos consecutivos [#consecutive]

Os procedimentos consecutivos se comportam como o esperado no Markdown, desde que estejam alinhados à esquerda. No entanto, ao recuar procedimentos consecutivos, como dentro de um recolhedor, o Markdown às vezes faz uma formatação incomum. O exemplo a seguir mostra como configurar duas listas consecutivas alinhadas à esquerda no Markdown (fora de um recolhedor):

```md
To add or delete tags via the UI:

    1. Select a monitored entity, like a monitored app or host.
    2. Near the entity's name at the top of the page, select the **See metadata and manage tags** menu.
    3. In the menu that pops up, add or delete a tag.
    4. For APM agents, restart your service.

You can also add or delete tags associated with a NRQL alert condition. To add or delete condition tags via the UI:

    1. Navigate to a condition.
    2. Near the condition's name at the top of the form, click **Manage tags**.
    3. In the menu that pops up, add or delete a tag.
```

No entanto, dentro de um expansor onde o conteúdo já está sendo recuado, o Markdown pode se confundir sobre como formatar os recuos:

* O Markdown não recua as frases introdutórias para o segundo procedimento.
* O Markdown inicia a numeração do segundo procedimento com base no último número do primeiro procedimento.

Este é um exemplo de como o Markdown para os mesmos procedimentos consecutivos é recuado dentro de um elemento expansível.

```md
<CollapserGroup>
  <Collapser
    id="incorrect-formatting"
    title="Two consecutive lists with incorrect formatting"
  >
    When you add tags via the UI or API, this occurs at the entity level. This means that, for example, if you have multiple APM agents monitoring a single entity and apply a tag via the UI, that tag is available for all data coming from that entity.

    To add or delete tags via the UI:

      1. Select a monitored entity, like a monitored app or host.
      2. Near the entity's name at the top of the page, select the **See metadata and manage tags** menu.
      3. In the menu that pops up, add or delete a tag.
      4. For APM agents, restart your service.

    You can also add or delete tags associated with a NRQL alert condition. To add or delete condition tags via the UI:

      1. Navigate to a condition.
      2. Near the condition's name at the top of the form, click **Manage tags**.
      3. In the menu that pops up, add or delete a tag.

    To manage tags via API: see our [NerdGraph tagging docs](/docs/apis/nerdgraph/examples/nerdgraph-tagging-api-tutorial). For a guide to using our CLI to automate tagging, see [our developer site](https://developer.newrelic.com/automate-workflows/5-mins-tag-resources/).
  </Collapser>
</CollapserGroup>
```

Quando o Markdown é renderizado, a introdução do segundo procedimento não é recuada (vide &quot;You can also add...&quot;) e deve-se observar como a numeração do segundo procedimento começa em 5:

## Recuo de imagem [#images]

As imagens abaixo dos itens de lista devem ter o mesmo recuo que seus elementos pai. Isso mostra ao leitor que a imagem está diretamente vinculada a esse item de lista. Aqui está um exemplo em que a primeira imagem não usa o mesmo recuo que o item de lista pai. A segunda imagem está recuada corretamente:

```md
1. First, New Relic gathers all relevant incidents. This includes incidents where [decision-logic steps 1 and 2](#build-decision) are true, and that are also within the defined time window in advanced settings.

2. Next, we attempt to associate each incident to a vertex in your [topology graph](#create-topology-graph) using a vertex's defining attributes and the available attributes on the incident.
```
