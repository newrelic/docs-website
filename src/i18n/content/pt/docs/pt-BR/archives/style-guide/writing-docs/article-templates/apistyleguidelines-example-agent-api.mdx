## Sintaxe

```
newrelic.apiStyleGuidelines(data type $parameter_name[, integer $optional_param])
newrelic.apiStyleGuidelines(data type $parameter_name, array $different_param, string $third_param)
```

Descrever brevemente a chamada. Idealmente, uma linha ou menos na página &quot;View all methods&quot;.

## Requisitos

Agente versão 1.2.3.4 ou superior.

Requisitos adicionais em sua própria linha (não utilize marcadores).

Não utilizar nenhum destaque.

Se não houver requisitos especiais, escreva: `Compatible with all agent versions.`

## Descrição

O comportamento da chamada deve ser descrito com o máximo de detalhes possível. O que os parâmetros individuais fazem não deve ser descrito, exceto em linhas gerais; os detalhes dos parâmetros e as variantes de chamada pertencem ao título `Parameters`. Da mesma forma, os valores de retorno não devem ser descritos.

Ao fazer referência cruzada a outra chamada de API, formatar o seu nome com blocos de código e incluir parênteses `()` da seguinte forma: `anotherCoolMethod()`.

<Callout variant="tip">
  É possível incluir destaques, mas deve-se ter discrição. Essas páginas já estão visualmente carregadas.
</Callout>

## Exemplos

Esta seção documenta regras para casos atípicos que não são autodocumentados. O restante dos exemplos está incorporado na própria página. Em geral, esta página destina-se a referência de estilo. Para obter exemplos de como escrever boas páginas de métodos de API, confira nossa documentação de API existente, como a [API do PHP](/docs/agents/php-agent/php-agent-api).

### Diretrizes de URL

Para o URL do documento:

* O slug do URL deve ser editado manualmente para remover o nome do agente.
* Onde a chamada de API ainda não incluir separadores (como em `newrelic_awesome_call`), as partes devem ser separadas com hifens `-`.

Por exemplo:

```
https://docs.newrelic.com/docs/new-relic-only/advanced-style-guide/writing-guidelines/api-style-guidelines
```

### Diretrizes de Título

Para o título do documento:

* Deve-se incluir o nome do método e o nome do agente entre parênteses.
* Não inclua prefixos `newrelic.`, a menos que sejam essenciais para o nome da chamada (como no agente PHP).
* Não incluir parênteses `()` na própria chamada.

Por exemplo:

```
apiStyleGuidelines (Example agent API)
```

### Diretrizes de títulos curtos [#short-title-guideliens]

Para o título curto do documento:

* Incluir apenas o nome do método.
* Não inclua prefixos `newrelic.`, a menos que sejam essenciais para o nome da chamada (como no agente PHP).
* Não incluir parênteses `()`.
* Ajuste, se necessário, para caber em uma única linha na barra lateral da categoria.

Por exemplo:

```
apiStyleGuidelines
```

### Diretrizes de Sintaxe

<Callout variant="important">
  Os agentes Python e iOS usam suas próprias diretrizes. Para obter essas diretrizes, consulte os métodos existentes nessas linguagens.
</Callout>

* Cada variante de uma chamada deve ser documentada em sua própria linha.
* Não use nenhuma formatação, exceto colocar o tipo de dados em itálico.
* Envolva os parâmetros opcionais (incluindo o separador de vírgula) entre colchetes `[]`.
* A parte variável deve ser indicada precedendo-a com um cifrão `$`.
* Se a chamada precisar ser prefixada com `newrelic.` ou similar, isso deve ser incluído na sintaxe.
* Opcional: o valor de retorno deve ser incluído, se isso parecer importante para o agente específico. Caso isso seja feito, as convenções do idioma devem ser seguidas.
