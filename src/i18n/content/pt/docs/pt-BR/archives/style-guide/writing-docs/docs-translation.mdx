A documentação da New Relic existe nestes sites:

* [**docs.newrelic.com**](https://docs.newrelic.com): Inglês
* [**docs.newrelic.com/jp/**](https://docs.newrelic.com/jp/): Japonês
* [**docs.newrelic.com/kr/**](https://docs.newrelic.com/kr/): Coreano
* [**docs.newrelic.com/es/**](https://docs.newrelic.com/es/): Espanhol
* [**docs.newrelic.com/pt/**](https://docs.newrelic.com/pt/): Português
* [**docs.newrelic.com/fr/**](https://docs.newrelic.com/fr/): Francês

É possível alternar entre idiomas com um botão na barra de menu superior.

## Visualizar status da tradução [#translation-status]

O frontmatter de cada documento inclui seu status de tradução humana.

Se não houver um elemento `translate:` no frontmatter, o documento não será traduzido por humanos para nenhum idioma. Ele ainda será traduzido automaticamente para todos os nossos idiomas de tradução automática.

Se o elemento `translate:` tiver uma abreviação de idioma, como `jp`, o documento foi traduzido, será traduzido ou está sob consideração para tradução. Por exemplo:

```md
---
title: 'NRQL reference'
translate:
  - jp
  - kr
  - es
  - pt
  - fr
metaDescription: "A detailed reference list of clauses and functions in NRQL, the New Relic query language."
redirects:
  - /docs/insights/using-nrql
```

## Atualizar documento traduzido [#update-translation]

O site executa uma tarefa automática uma vez por dia para traduzir automaticamente as alterações na documentação para os idiomas de destino.

## Mostrar status de SEO para documentos traduzidos [#translation-seo]

O frontend do site usa as informações de [status de tradução](#translation-status) do documento para exibir o elemento `hreflang` de SEO para uma página. Isso informa aos mecanismos de pesquisa que a página também tem uma versão disponível no idioma específico.

```html
<link rel="alternate" href="https://docs.newrelic.com/jp/" hreflang="ja" />
```

## Excluir e mover documentos [#delete]

Ao fazer alterações em nossos documentos em inglês, é possível que ocorra um erro de tradução não pareada no GitHub. Aqui estão os cenários em que seriam feitas alterações em nossa pasta i18n:

* Ao excluir um arquivo mdx, o arquivo mdx correspondente nas pastas `/kr/` e `/jp/` deve ser excluído. O arquivo yaml **não** deve ser atualizado.
* Ao mover um arquivo mdx da pasta X para a pasta Y, é necessário mover esse mesmo arquivo mdx para a pasta Y em `/kr/` e `/jp/`. O arquivo yaml **não** deve ser atualizado.
* Ao mover um arquivo mdx para uma nova pasta, é necessário criar essa nova pasta em `/kr/` e `/jp/` e, em seguida, mover o arquivo mdx para ela. O arquivo yaml **não** deve ser atualizado.

Em vez de excluir ou mover arquivos manualmente, devem ser executadas estas sequências de comandos:

* Para mover/renomear arquivos traduzidos:

  ```bash
  yarn i18n-utility list-renames
  yarn i18n-utility make-renames
  ```

* Para excluir arquivos traduzidos:

  ```bash
  yarn i18n-utility list-orphans
  yarn i18n-utility delete-orphans
  ```
