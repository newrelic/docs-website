Os recursos de controle de versão do GitHub nos permitem ver o histórico completo de um documento, acessar um documento em qualquer momento e encontrar documentos excluídos sem backups manuais.

## Verifique o histórico de edição de um documento ou arquivo [#doc-history]

É possível usar qualquer uma destas opções para verificar ou fazer o &quot;diff&quot; do histórico de um arquivo.

**Opção 1: guia de histórico do GitHub**

1. Navegue até o documento no site de documentação e clique em **Edit page** na navegação à direita.
2. Clique em **History** no canto superior direito do documento.

**Opção 2: githistory.xy**

1. Navegar até o arquivo específico no GitHub.com:

   ```
   https://github.com/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

2. Na URL, substituir `github.com` por `github.githistory.xyz`:

   ```
   https://github.githistory.xyz/newrelic/docs-website/blob/develop/src/content/docs/browser/new-relic-browser/browser-agent-spa-api/add-page-action.mdx
   ```

3. Isso levará a um site que apresenta o histórico visual desse arquivo específico. É possível visualizar as alterações clicando no histórico de commits na parte superior da página.

**Opção 3: Git blame**

Siga a [documentação do GitHub](https://docs.github.com/en/github/managing-files-in-a-repository/managing-files-on-github/tracking-changes-in-a-file).

Como alternativa, é possível usar o seguinte comando no seu terminal:

```bash
git log --follow "**/file_name_here.mdx"
```

Isso gerará o histórico de commits desse arquivo. Por padrão, são mostrados apenas os primeiros commits. É possível rolar pressionando `Return` várias vezes.

Por exemplo, para encontrar o histórico de commits para `vmware-vsphere-monitoring-integration.mdx`, deve-se executar:

```bash
git log --follow "**/vmware-vsphere-monitoring-integration.mdx"
```

## Histórico do site de documentação antes de outubro de 2021 [#archived-version]

Houve uma grande reestruturação do site em outubro de 2021, na qual se perdeu a maior parte do histórico de arquivos da nossa documentação. É possível encontrar uma versão arquivada do nosso site antes da reformulação na ramificação [pre-IA-2021](https://github.com/newrelic/docs-website/tree/pre-IA-2021). Ao navegar na versão anterior à reformulação do nosso repositório, é possível encontrar o histórico de arquivos e muito mais.

## Como encontrar arquivos excluídos [#deleted-files]

Existem várias maneiras de encontrar arquivos excluídos. Estas estão ordenadas aproximadamente por complexidade:

<CollapserGroup>
  <Collapser className="freq-link" id="pr" title="Como encontrar o PR de exclusão">
    A maneira mais fácil de encontrar um arquivo excluído é encontrar o pull request que o excluiu. Existem várias maneiras de realizar isso; aqui estão algumas ideias:

    1. Utilize o recurso de pesquisa do GitHub para buscar palavras-chave relevantes. É possível filtrar os resultados da pesquisa para incluir apenas PRs.
    2. Caso se tenha uma ideia aproximada de quando o documento foi excluído, é possível tentar encontrar o pull request na guia de pull request. Esta lista tem milhares de PRs, portanto, isso pode levar algum tempo.
    3. Muitos documentos são excluídos devido a um ticket do Jira. Deve-se pesquisar o ticket no Jira, onde será possível encontrar o horário aproximado em que o documento foi excluído e, com sorte, um link para o próprio PR.
    4. Pergunte no #doc\_talk!
  </Collapser>

  <Collapser className="freq-link" id="releases" title="Pesquisar em PRs de lançamento">
    Ao pesquisar nos PRs de lançamento, é possível encontrar uma ramificação criada antes que o documento fosse excluído. É possível encontrar uma lista de PRs de lançamento na [guia de PR do GitHub](https://github.com/newrelic/docs-we.bsite/pulls?q=is%3Apr+release+is%3Aclosed).

    Algumas dicas:

    * Pesquise primeiro por intervalos de um mês. Assim que encontrar uma ramificação que contenha a documentação, é possível reduzir o escopo para uma semana e, em seguida, para um dia. Ao diminuir o escopo, a documentação excluída será eventualmente encontrada em seu estado exato antes da exclusão.
    * Para acessar a branch de origem de um PR, acesse a página desse pull request e clique no nome da branch abaixo do título e do número do PR.
  </Collapser>

  <Collapser className="freq-link" id="git-log" title="Usar o git log">
    A maneira mais poderosa e confiável de encontrar arquivos excluídos é utilizar `git log`. Consulte o [StackOverflow](https://stackoverflow.com/questions/7203515/how-to-find-a-deleted-file-in-the-project-commit-history/7203551#7203551) para mais detalhes.
  </Collapser>
</CollapserGroup>
