O Swiftype é o mecanismo de busca baseado em elastic que alimenta a busca no `docs.newrelic.com`.

Como redator técnico na New Relic, pode ser necessário fazer login no Swiftype e realizar diversas tarefas para garantir que os documentos sejam reconhecidos durante as pesquisas internas.

## Informações do crawler do Swiftype [#crawler-info]

O rastreador informa que rastreia a cada 12 horas. A taxa de rastreamento é relativamente lenta, o que significa que pode levar mais tempo do que isso para detectar alterações na página. Ele também usa alguma combinação de `sitemap.xml` e coleta de links ao rastrear.

É possível acionar um rastreamento manual uma vez a cada 12 horas, se necessário. Ou, é possível fazer com que o Swiftype rastreie páginas específicas quando necessário.

O tempo médio de reindexação de documentos é de quatro dias.

## Adicionar manualmente uma nova página ao índice do Swiftype [#manually-index]

Pode ser necessário adicionar manualmente uma nova página ao índice do Swiftype quando o rastreamento for muito lento e se desejar que a página esteja disponível imediatamente.

Para adicionar manualmente uma nova página no Swiftype:

1. Certifique-se de que o tipo de documento não esteja na lista de ignorados acessando **Domains &gt; [https://docs.newrelic.com/](https://docs.newrelic.com/)**.

2. Vá para **New Relic &gt; Content**.

3. Na caixa de entrada de texto que diz **Filter pages**, cole o URL da página a ser indexada.

4. Se a página não estiver no índice, o Swiftype fornecerá a opção **Add this URL**. Clique nessa opção para adicionar a página ao índice.

5. Inserir o URL, certificando-se de fazer o seguinte:

   * Use o URL completo da seguinte forma: `https://docs.newrelic.com/docs/path/to/doc/`
   * Certifique-se de que o URL tenha uma barra final

O Swiftype deve indexá-lo em cerca de um minuto. Para verificar se está indexado, recomenda-se atualizar a página e colar o URL. É importante notar que, às vezes, a interface de administração é armazenada em cache ou apresenta atrasos. É possível pedir a um colega para verificar, usar a API REST para verificar, limpar o cache ou recarregar a página e verificar novamente.

## Atualizar manualmente o registro existente do Swiftype [#manual-index]

De forma semelhante à adição manual de uma nova página ao índice, é possível atualizar um registro existente se o rastreamento for muito lento e for desejado que o índice seja atualizado imediatamente. Utilize este método se o URL de uma página tiver sido alterado e o URL antigo for redirecionado para o novo. Para uma discussão mais aprofundada sobre isso, consulte a seção [alteração de URLs](#url-changes) abaixo.

Para atualizar ou reindexar manualmente um registro existente:

1. Vá para **New Relic &gt; Content**.
2. Cole o URL antigo (aquele com o qual a página foi indexada pela última vez).
3. Se for encontrado no índice, a entrada correspondente deverá ser exibida; portanto, selecione **Details**.
4. Na página de detalhes do registro, selecionar **Reindex**.
5. A classificação para este documento deve ser readicionada seguindo as etapas em [Classificar resultados para um determinado termo de pesquisa](#rank-results).

O Swiftype deve reindexar em um minuto. Observe que esse registro será removido do índice, junto com quaisquer classificações personalizadas definidas para ele, e um novo registro é criado para o novo URL para o qual o rastreador foi redirecionado. Portanto, prepare-se para atualizar as classificações de resultados.

## Remover Manualmente o Registro Existente do Swiftype [#remove-records]

Pode ser necessário remover manualmente um registro existente do índice nestes casos:

* Quando for necessário remover rapidamente um registro de uma página que foi excluída sem redirecionamentos
* Caso se note que há mais de um registro para uma página que mudou de URL recentemente (um para o URL antigo, um para o novo que foi descoberto fora do redirecionamento).

Para remover manualmente um registro do índice:

1. Vá para **New Relic &gt; Content**.
2. Colar o URL do registro que se deseja remover.
3. Selecione **Detalhes**.
4. Selecione **Excluir este Documento** na parte inferior da página **Detalhes**.

## Classificar resultados para um determinado termo de pesquisa [#rank-results]

Classificar os resultados para determinados termos de pesquisa para mover certas páginas para cima ou para baixo nos resultados. Também é possível excluir um registro dos resultados para um determinado termo de pesquisa.

Como as páginas de todos os nossos sites são processadas por um único mecanismo, isso desorganiza a lista de classificação. É preferível pesquisar URLs específicos em vez de navegar pelos URLs das páginas relevantes.

<Callout variant="tip">
  Se um URL mudar para um determinado registro, a classificação do resultado será perdida e precisará ser adicionada para o novo registro associado ao novo URL.
</Callout>

Para classificar os resultados:

1. Acesse **New Relic &gt; Result Rankings**.
2. Deve-se inserir o termo de pesquisa na entrada de texto para o qual se deseja obter classificação (o uso de maiúsculas ou minúsculas não importa).
3. Arraste os resultados para cima ou para baixo. Provavelmente será necessário pesquisar o URL da página, fixá-lo e movê-lo.
4. É possível remover um resultado selecionando o botão **X** no resultado.

Para obter mais detalhes, consulte a [documentação oficial do Swiftype](https://swiftype.com/documentation/site-search/guides/result-rankings).

## Adicionar alias [#add-alias]

Ao definir uma classificação de resultados, também é possível adicionar aliases. Um alias é semelhante a um [sinônimo](#add-synonym), mas é aplicável apenas a um conjunto de resultados específico.

Para adicionar aliases:

1. Acesse **New Relic &gt; Result Rankings**.
2. Insira o termo de pesquisa.
3. Adicionar o alias na entrada de texto.

## Adicionar sinônimo [#add-synonym]

Adicionar sinônimos quando se deseja que um termo de pesquisa mostre os mesmos resultados que outro. Exemplos anteriores incluem:

* RBAC = controles de acesso baseados em funções
* servers = New Relic Infrastructure

Para adicionar sinônimos, acesse **New Relic &gt; Synonyms**.

Para obter mais informações, consulte a [documentação oficial](https://swiftype.com/documentation/site-search/guides/synonyms).

## Prática recomendada: termos de pesquisa importantes [#important-search-terms]

Provavelmente, deseja-se garantir que os resultados sejam classificados e precisos para os termos de pesquisa que são:

* Conhecido por ser muito vago com resultados ruidosos (exemplo: navegador)
* Os termos de pesquisa mais populares em nosso site
* Termos do glossário

## Prática recomendada: alterações de URL [#url-changes]

Se uma página que já está indexada tiver a URL alterada, o Swiftype removerá o registro associado à URL antiga. E, se houver um redirecionamento para uma nova URL, o Swiftype criará um novo registro para a página que está associada à nova URL. Quando isso acontece, as classificações de resultados para o registro antigo são perdidas e devem ser adicionadas novamente para o novo registro com a nova URL.

Acionar um novo rastreamento no Swiftype acabará corrigindo isso, mas pode levar muito tempo. Como alternativa, é possível excluir resultados específicos de páginas antigas e instruí-lo manualmente a indexar novas. Isso *deve* ser sincronizado com `docs-library-service` na próxima vez que for atualizar seu cache para um determinado termo de pesquisa.
