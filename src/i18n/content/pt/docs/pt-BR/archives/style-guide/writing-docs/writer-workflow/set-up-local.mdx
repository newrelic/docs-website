Executar o site localmente torna o teste e a visualização de grandes alterações muito mais fáceis. Há várias coisas que precisam ser feitas para que isso funcione. Felizmente, é necessário fazer isso apenas uma vez.

## Usar o terminal e a linha de comando [#terminal]

No macOS, é possível usar o aplicativo Terminal para acessar a linha de comando do sistema. (Também é possível acessar o terminal pelo VS Code.) A linha de comando é uma alternativa à interface gráfica do usuário.

Aqui estão alguns comandos básicos de terminal que podem ser úteis:

* `pwd` (print working directory): use isto para ver o caminho do diretório.
* `ls` (list): Mostra os arquivos no diretório atual.
* `cd YOUR_DIRECTORY_PATH` (change directory): move para outro diretório.
* `cd ..`: mover um diretório para cima no caminho.

## Habilite o VS Code no seu terminal [#code-terminal]

É prático poder abrir arquivos do terminal diretamente no VS Code. Isso pode ser usado apenas algumas vezes, mas é muito melhor do que tentar editar arquivos no próprio terminal.

1. Abra o Visual Studio Code.
2. Pressione **Command + Shift + P** para abrir a paleta de comandos, digite `install code` e, em seguida, clique em **Shell command: Install &apos;code&apos; command in PATH**.
3. No terminal, digite `code` YOUR\_FILENAME\` para abrir esse arquivo no VS Code.

## 1. Utilizar o GitHub Desktop para configurar o repositório local [#repo-setup]

O GitHub Desktop é uma ferramenta gráfica para gerenciar os branches, commits e PRs. É provavelmente a maneira mais direta de trabalhar com o Git e o GitHub.

1. Instalar o GitHub Desktop.
2. Faça login no GitHub Desktop por meio da conta do GitHub. Em Macs, clique em **GitHub Desktop** no canto superior esquerdo da tela e selecione **Preferences**. Selecione o botão azul **Sign In** e siga os prompts na janela do navegador.
3. Navegar até o [repositório do Docs Site](https://github.com/newrelic/docs-website).
4. Clique no botão verde **Code** e selecione **Open with [GitHub Desktop](https://desktop.github.com/)**.
5. Escolher o local desejado para o repositório. O local padrão para esta pasta é `~/Documents/github`.
6. Clone o repositório inteiro para sua máquina local.

## 2. Habilitar acesso total ao disco [#disk-access]

Por padrão, parece que o macOS impede o acesso do terminal a certas pastas do sistema, como `Documents`. Alterar esta configuração para facilitar a navegação no sistema de arquivos via terminal.

1. Abrir **Preferências do Sistema**.
2. Clique em **Security &amp; Privacy**.
3. No painel esquerdo, role para baixo até encontrar **Full Disk Access** e, em seguida, selecione-o.
4. Clique no cadeado no canto inferior esquerdo e, em seguida, insira a senha que utiliza para fazer login no seu computador.
5. Na lista de aplicativos, marque a caixa ao lado de **Terminal** (ou qualquer que seja o aplicativo de terminal padrão).
6. Clique no cadeado para bloqueá-lo.

## 3. Instalar o Homebrew [#homebrew]

O Homebrew é uma ferramenta de linha de comando para instalar outros aplicativos. Também é uma maneira fácil de manter o software de linha de comando atualizado.

1. Abra seu terminal.

2. Copie e cole este comando no seu terminal:

   ```shell
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

## 4. Instalar o npm (gerenciador de pacote do Node.js) [#npm]

É necessário instalar `npm` para que também seja possível instalar `nvm` (gerenciador de versão do Node.js). No terminal, digite `brew install npm`.

## 5. Instalar o nvm (gerenciador de versão do Node) [#nvm]

O gerenciador de versões do Node (`nvm`) é o que se utiliza para gerenciar a versão do Node.js instalada no computador. No terminal, deve-se digitar `npm i -g nvm`.

## 6. Adicionar o nvm ao perfil do shell [#add-nvm]

Para executar os comandos necessários para a compilação local, é necessário adicionar o caminho para `nvm` ao perfil do shell.

No macOS, o shell é o que interpreta o que é inserido na linha de comando. O shell padrão do macOS é o Zsh. É necessário informar ao shell o diretório onde `nvm` está na máquina para que seja possível executar esses comandos de qualquer lugar.

Isso é feito adicionando o seguinte texto ao arquivo `.zshrc`, que é um arquivo de configuração para o shell.

1. No terminal, deve-se digitar `code ~/.zshrc` para abrir este arquivo no VS Code.

2. No arquivo `.zshrc`, copie e cole este texto:

   ```shell
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
   ```

3. Salve o arquivo.

## 7. Instalar o Node.js [#node]

Após instalar o `nvm`, é possível instalar a versão correta do Node. O Node, ou Node.js, é o mecanismo JavaScript que alimenta nosso site Gatsby e suas dependências. Digite `nvm use 18` para instalar o Node.js versão 16.

## 8. Instalar o Yarn [#yarn]

O Yarn é outro gerenciador de pacote usado para compilar todos os arquivos no repositório **docs-website** para criar o site localmente. Utilize o npm para instalar o Yarn. No terminal, digite `npm i -g yarn`.

## Compilar o site local [#local-site]

Depois de instalar todos esses itens no terminal, é possível executar o site localmente na máquina.

1. Em seu terminal, digite `pwd` para certificar-se de que está no diretório do repositório **docs-website**.
2. Digite `yarn` para garantir que todas as dependências do Gatsby estejam atualizadas.
3. Digitar `yarn start` para compilar o site localmente.
4. Quando o processo terminar, no navegador da web, acesse `http://localhost:8000`.

Ao executar `yarn start`, o terminal exibe muitas linhas de texto. Se a compilação local falhar, a saída do terminal geralmente fornece uma pista sobre o que deu errado.

Por padrão, o site será compilado sem nenhuma página traduzida (jp, kr). Caso deseje compilar essas páginas também, é possível executar `yarn start:full`.

## Compilar parte do site local (mais rápido) [#local-site-speed]

Caso deseje compilar o site ainda mais rapidamente, é possível optar por compilar uma única pasta (ou quantas desejar) em vez de todos os documentos do site. Isso pode ser útil se souber que está trabalhando em um documento de conta, por exemplo, é possível compilar apenas a pasta da conta. No entanto, isso significa que, ao tentar visitar um documento em uma pasta fora do que foi especificado, será exibido um `404`.

Para compilar uma ou mais pastas específicas, adicione esta variável ao comando `yarn start`:

`BUILD_FOLDERS=mlops yarn start` ou `BUILD_FOLDERS=apm,logs,errors-inbox yarn start`

Pontas:

* A(s) pasta(s) especificada(s) deve(m) estar no nível raiz do diretório `/src/content/docs/`. Isso não inclui nenhum subdiretório. Por exemplo, `browser` é uma pasta válida, mas `browser-monitoring` não é porque é um subdiretório de `browser`.
* Certifique-se de que não haja espaços após as vírgulas na lista de pastas. Por exemplo, digite `BUILD_FOLDERS=apis,infrastructure`, não `BUILD_FOLDERS=apis, infrastructure`.
