As introduções são muito parecidas com os aperitivos de um jantar — elas preparam o cenário para o prato principal. Ao dedicar um esforço extra à introdução, os leitores estarão prontos para o prato principal.

Ao compor introduções, normalmente incluem-se estes três ingredientes:

* Informações que definem o tópico
* Ideias que capturam o interesse do usuário
* Teasers que informam ao leitor o que esperar do documento

Os dois primeiros ingredientes parecem diretos, mas quando se trata de dizer aos leitores o que podem esperar, frequentemente dependemos de frases repetitivas e engessadas. A maneira como lidamos com isso levanta algumas questões: quem está falando? É autoritativo? É colaborativo? Esta é a melhor maneira de ajudar os usuários a aprender e a resolver seus problemas?

Veremos algumas dicas gerais sobre introduções, mas o foco será em como informar aos leitores o que esperar do documento. Se preferir pular a discussão de contexto, é possível ir direto para os [Exemplos de introduções](#example-lead-ins), que mostram introduções que evitam frases feitas e vão direto ao ponto do assunto da página.

## Dicas para introduções mais ativas [#tips]

Temos várias páginas em nosso site que têm um cabeçalho seguido por uma frase introdutória `This document is about`. Esta frase frequentemente reafirma o cabeçalho. Ao ler mais adiante, geralmente há um parágrafo que fornece uma introdução melhor. Recomendamos evitar o uso do `this document is about` e ir direto à informação que o usuário procura.

Várias alternativas a esse tipo de construção serão analisadas ao longo do documento. Antes de explorar essas alternativas, recomenda-se considerar estas maneiras de escrever introduções mais fortes:

* Deve-se focar no usuário imediatamente. Em vez de começar falando sobre o assunto do documento, deve-se abordar o que o usuário pode querer saber ou fazer (considere as [Cinco perguntas](/docs/style-guide/writing-strategies/five-questions-help-write-docs)).
* Deve-se questionar quais informações estão faltando ou implícitas: talvez seja necessário definir um termo ou um conceito. Por exemplo, temos uma página de documentação que se concentra no uso do Gradle, mas nunca informa o que é o Gradle. Ou, na página do Observability for Good, começamos fazendo referência ao OfG, mas não informamos o que ele é.
* É necessário descobrir qual é o verdadeiro objetivo da página e garantir a sua inclusão na introdução. Essa informação geralmente está contida logo após a frase introdutória simples &quot;Esta página é sobre isto&quot;. Porém, pode ser necessário analisar a página com atenção para encontrar a ênfase.

Para encontrar novas maneiras de alcançar o leitor, deve-se explorar algumas abordagens alternativas para as introduções.

## Considere algumas abordagens diferentes [#what-about]

Sobre o que trata o documento? A maneira como se responde a essa pergunta afeta os leitores e a chance de engajá-los. Se a mesma construção for usada em todos os documentos, eles podem ser previsíveis, mas também podem ser repetitivos a ponto de o usuário deixar de ver essas frases.

A frase feita tende a ser uma barreira para bons detalhes, e tende a repetir as informações já fornecidas no título da página. Muitas vezes, ao mover informações pertinentes para a introdução, é possível informar ao leitor, de forma mais específica e interessante, sobre o que a página trata.

A seguir, apresenta-se um exemplo de introdução que resume um problema e chama a atenção dos leitores:

```
Clogged drains account for 60 percent of calls to professional plumbers. You may be able to solve this problem yourself and avoid the expense.
```

Que tipo de terceira frase poderia ser adicionada a este parágrafo para informar aos leitores sobre o que trata o restante deste documento? As seções abaixo contêm tabelas com várias opções para a terceira e última frase de conexão.

### Abordagem 3: usar a primeira pessoa [#first-person]

Ao usar a primeira pessoa `we` em um documento procedural, o `we` refere-se ao redator junto com o leitor. Ambos estão seguindo as etapas juntos.

<Callout variant="tip">
  Esse é um uso diferente de `we` em relação ao uso mais geral, em que `we` pode se referir ao New Relic. É possível usar `we` como um substituto para New Relic quando não se referir ao escritor e ao leitor em conjunto. Por exemplo, &quot;NerdGraph é a API que **nós** recomendamos para consultar dados do New Relic e para realizar algumas configurações específicas (saiba mais sobre os recursos)&quot;.
</Callout>

A primeira pessoa é provavelmente melhor utilizada no contexto de tutoriais onde uma relação pessoal é explícita. Por exemplo, se houver um blog ou um curso, e o usuário for guiado por um procedimento. Na New Relic, não costumamos ter esse contexto, mas podemos ter alguns casos em que isso se encaixa.

Se houver um contexto em que a primeira pessoa seja apropriada, evite casos em que a primeira pessoa envie a mensagem de que a empresa está observando secretamente o usuário ou seus dados. Por exemplo, não seria desejável ter um uso em primeira pessoa como este: &quot;Vemos que o seu agente está desatualizado. Gostaria de atualizá-lo?&quot;

## As seções de introdução versus &quot;Por Que É Importante&quot; [#why-matters]

Assim que houver uma gama de opções para construir a introdução, deve-se ter cuidado para não diluir a introdução com uma seção subsequente de “Por que isso importa”.

Para criar uma introdução mais centrada em usuários ativos, pode ser útil incluir informações que normalmente seriam colocadas em uma seção do tipo “Por que isso é importante”. Isso é recomendado! É de extrema importância que os usuários saibam por que o assunto é importante para eles o mais rápido possível.

Eis por que usar &quot;Por que é importante&quot; como uma seção e um cabeçalho é um problema:

* Muitas vezes, espera-se para compartilhar as informações mais importantes para um usuário até a seção &quot;Por que isso é importante&quot;. O objetivo deve ser ajudar os usuários a aprender rapidamente o que um recurso os ajudará a realizar. Portanto, é possível remover essa seção dedicada se os usuários já estiverem sendo informados sobre isso na introdução ou em outras seções do documento.
* O valor deve ser associado ao assunto de um documento. Declarações de valor devem ser incluídas sempre que fizerem sentido. Pode haver um valor de alto nível na introdução, por exemplo, e, em seguida, declarações de valor mais específicas quando se discute outro aspecto do assunto da página.
* Não utilize &quot;Por que isso é importante&quot; como cabeçalho, independentemente da situação. É mais uma frase repetitiva que parece uma documentação genérica. Caso seja dedicado espaço para abordar essa questão, crie um cabeçalho que forneça informações sobre o valor, em vez de utilizar o cabeçalho padrão &quot;Por que isso é importante&quot;.

## Exemplos de introduções [#example-lead-ins]

Analisar estas introduções que evitam frases feitas e vão direto ao cerne do assunto da página. Estas são reescritas de conteúdo existente.

### Exemplo 1: [diretrizes de elegibilidade](/docs/accounts/accounts-billing/new-relic-one-pricing-billing/eligibility-guidelines-new-relic-nonprofit-program/) [#eligibility]

```
Non-profits and New Relic

This document provides New Relic's Observability for Good program eligibility guidelines for nonprofit, charitable, and NGO organizations.

Exceptions

Many global nonprofit, charity and NGO organizations are eligible for Observability for Good if the organization has a recognized legal status in their respective country equal to 501(c)(3) status under the United States Internal Revenue Code, with certain exceptions. In addition, all organizations must be verified by TechSoup or the local TechSoup partner.
```

Veja como isso pode ser reescrito:

```
If your organization is a global nonprofit, charity, or NGO, it might qualify for Observability for Good, a New Relic program that provides expansive, free access to New Relic. To qualify, your organization must have a recognized legal status in your respective country equal to 501(c)(3) status under the United States Internal Revenue Code. And, it must be verified by TechSoup or the local TechSoup partner.

To get started:

  1. Check that your organization is not in one of the ineligible categories (link). 
  2. Submit a New Relic application (link).
  3. Get qualified with TechSoup (link).
```

Esta revisão apresenta estas alterações:

* Define Observability for Good imediatamente. Vá direto ao propósito da página, sem ter que dizer qual é o propósito.
* Substitui as primeiras frases passivas por um ponto de vista mais ativo, de segunda pessoa: &quot;Se a sua organização é uma organização sem fins lucrativos, instituição de caridade ou ONG global&quot; em vez de &quot;Muitas organizações sem fins lucrativos, instituições de caridade e ONGs globais...&quot;
* Mantém a ênfase no leitor e nos potenciais beneficiários deste programa.
* Remove as &quot;exceções&quot; negativas e as substitui por detalhes sobre como se qualificar e se inscrever.

### Exemplo 2: [Alterar a senha](https://docs.newrelic.com/docs/accounts/accounts/account-maintenance/change-passwords-user-preferences/) [#change-password]

```
This document contains information on New Relic password requirements.

Change your password

New Relic account passwords don't expire. However, users can change their own password and other personal account information anytime.
```

Aqui está como se pode reescrever isso:

```
New Relic account passwords don't expire. However, you can change your own password and other personal account information anytime. You can also request a password reset if you forget your password.
```

Esta revisão apresenta estas alterações:

* Remove a linha &quot;este documento contém&quot; e o primeiro H2.
* Começa com a informação que mais importará para um usuário: as senhas não expiram. É possível alterar a senha a qualquer momento.
* Altera para “o senhor” em vez de “usuários”.
* Esta é uma página curta e a introdução pode entrar rapidamente nas informações essenciais. Além disso, os H2s devem fornecer a visão geral das informações que serão abordadas.

### Exemplo 3: [instalar o agente Java](/docs/apm/agents/java-agent/additional-installation/install-java-agent-using-gradle/) [#install-java-agent]

```
This document explains how to install the Java agent using Gradle. For information on manually installing the Java agent, see "Install the Java agent" and "Java agent configuration: Config file."
```

Aqui está como se pode reescrever isso:

```
Gradle is a highly flexible build automation tool that can help you install the Java agent across many instances quickly and consistently.

If you’d like to manually install the Java agent instead, see Install the Java agent and "Java agent configuration: Config file."
```

Esta revisão apresenta estas alterações:

* Define o Gradle (permite automatizar a instalação).
* Então, ao se referir à abordagem manual, ela está em contraste direto com a ferramenta de automação.
* Se for necessário esclarecer que será abordado apenas um subconjunto de informações relacionadas a algo, por exemplo, apenas uma de muitas maneiras de automatizar a instalação com o Gradle, é possível dizer que: “Aqui, fornecemos a maneira mais comum de automatizar a sua instalação com o Gradle.” Muito depende do contexto.

### Exemplo 4: [atributos do agente Java](/docs/apm/agents/java-agent/attributes/java-agent-attributes/) [#agent-attributes]

```
New Relic attributes are key-value pairs containing information that determines the properties of an event or transaction. These key-value pairs can help you gain greater insight into your application and annotate the data when you query it. You can also automatically forward user information to New Relic.

Both default and custom attributes are visible in APM transaction traces, distributed traces, and error analytics; APM events and Browser events in dashboards. You can customize exactly which attributes will be sent to each of these destinations.

This document describes the Java agent attributes, details how to enable or disable attributes, and describes the rules the agent follows to determine which attributes to include or exclude for a destination.
```

Para melhorar isso, pode-se manter os três primeiros parágrafos, mas adicionar o seguinte ao parágrafo final:

```
Before you start creating custom attributes, familiarize yourself with existing Java agent attributes and how to enable or disable them. In addition, learn the rules for which attributes the agent includes or excludes for a destination. 
```
