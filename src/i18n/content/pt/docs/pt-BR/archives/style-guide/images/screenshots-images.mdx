As imagens são uma parte fundamental de nossa documentação. Elas mostram ao usuário o que ele obterá ao seguir um procedimento. Elas podem ajudar a orientar o usuário por um caminho de interface complicado, ilustrar conceitos complexos como [substituições de arquivo de configuração](/docs/agents/python-agent/installation-configuration/python-agent-configuration#options), ou às vezes apenas adicionar interesse visual.

Este documento descreve as práticas recomendadas para criar e manter imagens. Para obter ajuda sobre como incorporá-las em nosso site, consulte [Incorporar Imagens](/docs/style-guide/processes-procedures/embed-images). Para adicionar anotações de imagem, consulte [Práticas Recomendadas para o Uso de Anotações de Imagem](/docs/style-guide/images/image-annotations).

## Diretrizes para tipos de imagens [#types]

Existem quatro categorias principais de imagens em nosso site.

<CollapserGroup>
  <Collapser id="screenshots" title="Capturas de tela">
    As capturas de tela são um recurso fundamental para o usuário — em pesquisas com o usuário, ele consistentemente nos diz que gostaria de ver mais capturas de tela, e de maior qualidade, na documentação.

    Utilizam-se dois tipos de capturas de tela: capturas de tela completas que mostram toda a interface, e capturas de tela recortadas que mostram apenas uma seção. Geralmente, preferem-se capturas de tela completas porque ajudam o usuário a se orientar dentro da interface. Às vezes, uma captura de tela recortada pode ser melhor quando se tenta mostrar apenas algo muito específico, e os elementos da interface ao redor são uma distração.

    Tenha em mente as diretrizes de segurança da New Relic e evite informações privadas da New Relic ou de clientes. Além disso:

    * Sempre utilizar o modo escuro.
    * Sempre corte ou mascare informações confidenciais.
    * Deve-se seguir as nossas [diretrizes de anotação de imagem](/docs/style-guide/images/image-annotations/) e usar as anotações com moderação.
    * Considere adicionar uma legenda. Veja as nossas [dicas](/docs/style-guide/images/screenshots-images/#captions) abaixo.
    * É necessário cortar elementos que não são da interface, como o ponteiro do mouse ou as abas do navegador.
    * Caso seja necessário desfocar parte da captura de tela, recomenda-se o uso do desfoque gaussiano.

## Diretrizes para explicar imagens [#identify-images]

O texto de apoio pode fornecer contexto e explicação úteis, especialmente para capturas de tela complicadas e outras imagens que podem ser difíceis de entender por si só. Embora o texto alternativo deva ser sempre incluído para acessibilidade, os outros tipos de texto de apoio são opcionais.

* Texto alternativo (obrigatório)
* Título (obrigatório)
* Legenda
* Texto adjacente

<Callout variant="important">
  Evite o uso de texto dentro de uma captura de tela, use [legendas](/docs/style-guide/images/screenshots-images/#captions) em vez disso. Veja as [Práticas recomendadas para uso de anotações de imagem](/docs/style-guide/images/image-annotations)
</Callout>

### Texto alternativo (obrigatório) [#alt-text]

Sempre inclua texto alternativo nas tags de imagem para que os leitores com deficiência visual possam usar seus leitores de tela para obter informações úteis das imagens. Isso se aplica apenas a imagens que contêm conteúdo ou comandos (por exemplo, botões).

<Callout variant="tip">
  O texto alternativo não se aplica a ícones Feather embutidos.
</Callout>

Ao usar texto alternativo:

* Utilize descrições de imagem concisas.

* Não repita o texto ao redor — os leitores de tela já leem isso.

* AI Monitoring para clareza. Frases completas não são obrigatórias.

* Identifique o tipo de imagem de alguma forma:

  * `alt="Diagram showing the flow of data from client to server."`
  * `alt="Screenshot showing how to select a server."`
  * `alt="Photo of garden hose that serves as a metaphor for electrical amperage."`

### Legenda [#captions]

As legendas aparecem abaixo das imagens e fornecem contexto de apoio aos leitores.

Tenha o seguinte em mente:

* Manter as legendas curtas e não inserir procedimentos.
* Deve-se inserir [caminhos de navegação](/docs/style-guide/formatting/ui-paths/) em legendas apenas se a navegação for uma parte fundamental da mensagem.
* Insira informações complementares que não sejam idênticas ao texto circundante.
* Criar legendas que sejam fáceis de ler rapidamente.
* Incentive os leitores a observar o texto ao redor.
* Não colocar em legendas informações obrigatórias que não estejam disponíveis em outro lugar.
* As legendas não são necessárias nas capturas de tela de procedimentos, pois o texto do procedimento deve ser claro.

### Texto adjacente [#surrounding-text]

Se não estiver usando legendas ou anotações, certifique-se de adicionar texto antes ou depois da imagem para fornecer um contexto útil.

Se o texto ao redor for utilizado para explicar a imagem:

* Recomenda-se o uso de imagens intuitivas.
* Mantenha o texto ao redor conciso para que seja mais fácil entender a imagem.

## Excluir ou renomear um arquivo de imagem [#delete-rename-image]

Os nossos arquivos .mdx traduzidos de i18n precisam corresponder aos arquivos .mdx em inglês correspondentes. Ao excluir ou renomear arquivos de imagem em inglês, pode ocorrer um erro de compilação, pois passa a haver uma incompatibilidade entre os arquivos em inglês e os traduzidos. A seguir, apresentam-se algumas dicas para excluir ou renomear um arquivo de imagem:

* Para substituir uma imagem: se uma imagem existente estiver sendo substituída, o arquivo de imagem deve receber o mesmo nome. Excluir o arquivo a ser substituído e adicionar o novo arquivo. Fazer isso significa que não será necessário alterar nenhuma referência a esse arquivo de imagem.
* Para remover uma imagem: caso deseje simplesmente remover uma imagem sem substituí-la, o arquivo de imagem não deve ser excluído. Em vez disso, basta remover a instrução de importação desse arquivo de imagem. A equipe de documentação ocasionalmente executa um script que remove arquivos de imagem que não são referenciados por arquivos mdx. Isso significa que não é necessário excluir arquivos de imagem e, portanto, não há necessidade de alterar os arquivos mdx no diretório i18n, pois eles serão atualizados automaticamente com o nosso fluxo de trabalho de tradução.
* Para renomear um arquivo de imagem: primeiro, deve-se questionar se isso é necessário. O nome do arquivo de imagem é geralmente sem importância e trivial. Se for decidido renomear um arquivo de imagem, deve-se acessar qualquer arquivo mdx que faça referência ao arquivo de imagem (incluindo os arquivos do diretório i18n) e atualizar esse nome de arquivo.
