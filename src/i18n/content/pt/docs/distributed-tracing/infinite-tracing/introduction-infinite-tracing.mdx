O Infinite Tracing é uma solução totalmente gerenciada baseada em nuvem que pode analisar 100% dos seus dados trace e escolher os dados mais acionáveis, permitindo investigar e resolver problemas rapidamente.

Este documento se aplica apenas ao recurso Infinite Tracing. Se você estiver procurando por nossa solução de distributed tracing padrão, consulte o [guia de configuração de distributed tracing padrão](/docs/distributed-tracing/enable-configure/quick-start).

## O que é rastreamento infinito? [#understand-infinite-tracing]

O Infinite Tracing permite que você envie todos os seus dados trace para nosso serviço baseado em nuvem e conte com o Infinite Tracing para tomar decisões de amostragem. Você pode configurar o Rastreamento Infinito de várias maneiras para garantir que ele mantenha os dados trace que você precisa ver.

O Infinite Tracing exige que você envie sua telemetria para um [observador de trace](/docs/distributed-tracing/infinite-tracing/set-trace-observer), um endpoint de ingestão regional dedicado que armazena seus spans em buffer na cloud. O observador de trace é o ponto de entrada para todos os dados do Infinite Tracing e aceita telemetria das seguintes fontes:

* <InlinePopover type="apm" />agentes do New Relic, via gRPC
* Coletores e SDKs do [OpenTelemetry](/docs/opentelemetry/get-started/opentelemetry-get-started-intro), via [OTLP sobre gRPC ou HTTP](/docs/distributed-tracing/infinite-tracing/set-trace-observer#apm-and-third-party)
* Outras ferramentas, como o Zipkin, via [API de trace](/docs/distributed-tracing/trace-api/introduction-trace-api)

Ao contrário do distributed tracing padrão, o Infinite Tracing pode processar mais dados de trace. Ele usa [amostragem tail-based](/docs/understand-dependencies/distributed-tracing/get-started/how-new-relic-distributed-tracing-works#tail-based) (amostragem após a coleta dos dados), em vez da Amostragem head-based que o rastreamento padrão usa. Como o Infinite Tracing toma a decisão de amostragem depois que todos os spans em um trace chegam, ele pode manter os trace de que você precisa para a resolução de problemas — como trace com erros ou trace excepcionalmente lentos — em vez de decidir no início de uma solicitação, antes de você saber se ela falhará ou será lenta. O Infinite Tracing também mantém uma amostra aleatória de todos os trace, 1% por padrão, para que você possa ver como seus serviços se comportam durante a operação normal, não apenas quando algo dá errado. Você pode ajustar esse valor com o [filtro de trace aleatório](/docs/distributed-tracing/infinite-tracing/infinite-tracing-configure-random-trace-filter) e refinar as regras de erro com o [filtro de trace de atributo de span](/docs/distributed-tracing/infinite-tracing/infinite-tracing-configure-span-attribute-trace-filter).

Recursos para aprender mais sobre o Infinite Tracing:

* [Detalhes técnicos da amostragem e arquitetura do Infinite Tracing](/docs/understand-dependencies/distributed-tracing/get-started/how-new-relic-distributed-tracing-works#sampling)

## Requisitos [#requirements]

Os requisitos diferem dependendo do seu [modelo de preços](/docs/accounts/original-accounts-billing/original-product-based-pricing/overview-pricing-models):

* Modelo de precificação baseado no uso: requer Pro ou edição Enterprise.
* Modelo de preços original: requer a ajuda da New Relic para ativá-lo em sua organização. Em caso de dúvidas, entre em contato com seu representante de conta da New Relic.

A capacidade de configurar este recurso é regida pelas [permissões do Infinite Tracing](/docs/accounts/accounts-billing/new-relic-one-user-management/user-permissions#infinite-tracing).

## Habilitar rastreamento infinito [#enable-infinite-tracing]

Ao habilitar o Infinite Tracing, você deve, idealmente, habilitá-lo para todos os serviços associados. Se alguns serviços em um trace usarem o Infinite Tracing e outros usarem nossas soluções de rastreamento padrão, cada serviço tomará sua própria decisão de amostragem: o rastreamento padrão faz a amostragem no início de uma solicitação, enquanto o Infinite Tracing aguarda o trace completo. Como resultado, spans de serviços de rastreamento padrão podem estar ausentes, o que causa trace fragmentados, spans órfãos e métricas de trace imprecisas. Para obter detalhes, consulte [conflitos de configuração de trace](/docs/understand-dependencies/distributed-tracing/troubleshooting/infinite-tracing-trace-configuration-conflicts).

Para começar, siga o [guia de configuração do observador de trace](/docs/distributed-tracing/infinite-tracing/set-trace-observer).

## Configurar rastreamento infinito [#configure]

Após habilitar o Infinite Tracing, você pode [configurar a filtragem do observador de trace](/docs/distributed-tracing/infinite-tracing/set-trace-observer#follow-up-config) para garantir que ele retenha os dados exatos de que você precisa.
